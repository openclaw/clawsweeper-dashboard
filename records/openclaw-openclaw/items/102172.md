## Label Justifications

- `P1`: The report describes a real claude-cli channel workflow where background tool work is killed at turn end without a model-visible failure signal.
- `impact:data-loss`: Killing CLI-owned background tool work can discard in-progress task output or partial work without a durable failure signal.
- `impact:message-loss`: The killed Workflow/tool child can leave the model without a terminal tool result or task notification.
- `impact:session-state`: The parent session can continue as if background work exists while the underlying CLI process tree has already been reaped.
- `maturity:stable`: The affected gateway runtime lifecycle/process-supervision surface maps to gateway-runtime, which is scored M4 Stable in qa/maturity-scores.yaml.

## Summary

Keep open: current main and v2026.6.11 still have the standard CLI message cleanup path that closes the Claude live session, cancels the managed run, and escalates to process-tree SIGTERM/SIGKILL; the related open issues are sibling lifecycle gaps, not superseding fixes.

## What This Changes

The issue requests a claude-cli lifecycle opt-out or telemetry so turn-end cleanup does not silently SIGKILL in-flight CLI-owned background grandchildren such as Workflow runtimes.

## Best Possible Solution

Define an owner-approved claude-cli lifecycle contract that either boundedly drains or detaches in-flight CLI-owned background work with typed failure/telemetry, or explicitly denies unsupported post-turn work while preserving safe process-tree cleanup.

- **Telemetry first:** Keep cleanup unconditional for now, but snapshot, log, and surface killed grandchildren so the silent failure class is observable before changing process lifetime.
- **Declare unsupported post-turn work:** Document or enforce that Claude CLI Workflow/background grandchildren cannot survive OpenClaw turn cleanup and route users to ACP, exec/process, or detached task surfaces.
