## Label Justifications

- `P1`: The report describes a real claude-cli channel workflow where background tool work is killed at turn end without a model-visible failure signal.
- `impact:data-loss`: Killing CLI-owned background tool work can discard in-progress task output or partial workspace state without a durable failure signal.
- `impact:message-loss`: The killed Workflow/tool child can leave the model without a terminal tool result or task notification.
- `impact:session-state`: The parent session can continue as if background work exists while the underlying CLI process tree has already been reaped.
- `maturity:stable`: The process-supervision side of the issue maps to the M4 Stable gateway-runtime lifecycle and supervision surface.

## Summary

Keep open: current main and the latest release still use the reported claude-cli turn-end cleanup path, and the open sibling issues cover related symptoms rather than replacing this lifecycle-policy decision.

## What This Changes

The issue asks OpenClaw to avoid or visibly report claude-cli turn-end cleanup that kills in-flight CLI-owned tool grandchildren such as Workflow or background-like Bash work.

## Best Possible Solution

Define a maintainer-approved claude-cli lifecycle contract that keeps process-tree cleanup safe while preventing turns from being treated as cleanly finished when owned tool grandchildren are still running, or at least surfaces a typed failure/telemetry signal.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should claude-cli live-session cleanup remain unconditional at turn end, or should OpenClaw add a bounded drain or telemetry/failure-signal contract for in-flight CLI-owned background grandchildren?

Rationale: The current and shipped source confirm the reported cleanup-to-process-tree-kill behavior, but changing it affects orphan prevention, process lifetime, model-visible terminal state, and likely config/default surfaces.

Likely owner: obviyus

Owner reason: obviyus has the strongest recent history on the Claude live-session lifecycle code where this policy decision would likely land.

Owner confidence: high

Options:

- **Bounded drain plus signal (recommended):** Add a narrow owner-approved contract for detecting in-flight CLI-owned background children, deferring cleanup only within a bounded ceiling, and surfacing forced cleanup to the parent/session.
- **Telemetry first:** Keep unconditional cleanup for now, but snapshot, log, or surface killed descendants so the silent failure class becomes observable before changing lifecycle behavior.
- **Keep cleanup as contract:** Document that Claude CLI Workflow/Bash grandchildren are not supported across turn boundaries and route users to OpenClaw exec/process or detached task surfaces instead.

## Reproduction Assessment

Yes at source level: current main and v2026.6.11 still follow cleanupCliLiveSessionOnRunEnd to closeClaudeLiveSessionForContext to managed-run cancellation and process-tree signaling. I did not run a live Claude Workflow reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the lifecycle contract: a raw config opt-out is plausible but risky, while a bounded drain plus typed failure or telemetry signal better preserves cleanup safety.
