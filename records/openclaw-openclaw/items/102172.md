## Label Justifications

- `P1`: The report describes a real claude-cli channel workflow where background tool work is killed at turn end without a model-visible failure signal.
- `impact:data-loss`: Killing CLI-owned background tool work can discard in-progress task output or partial workspace state without a durable failure signal.
- `impact:message-loss`: The killed Workflow/tool child can leave the model without a terminal tool result or task notification after the user was told work started.
- `impact:session-state`: The parent session can continue as if background work exists while the underlying CLI process tree has already been reaped.
- `maturity:stable`: The affected gateway runtime lifecycle/process-supervision surface maps to gateway-runtime, which is M4 Stable in qa/maturity-scores.yaml.

## Summary

Keep open: current main and v2026.6.11 still have the reported claude-cli cleanup-to-managed-cancel-to-process-tree SIGTERM/SIGKILL path, and the overlapping open issues do not fully replace this sharper no-opt-out/Workflow lifecycle decision.

## What This Changes

The issue asks OpenClaw to avoid silently killing claude-cli-owned background tool grandchildren at turn end, or at least surface telemetry and parent-visible failure when cleanup kills them.

## Best Possible Solution

Define an owner-approved claude-cli lifecycle contract that either denies unsupported post-turn work or boundedly drains/detaches active CLI-owned background work with parent-visible failure telemetry while preserving safe process-tree cleanup.

- **Declare post-turn native work unsupported:** Document or enforce that Claude CLI Workflow/background grandchildren cannot survive OpenClaw turn cleanup and route users to ACP, exec/process, or detached task surfaces.
