## Label Justifications

- `P1`: The report describes a real claude-cli channel workflow where background tool work is killed at turn end without a model-visible failure signal.
- `impact:data-loss`: Killing CLI-owned background tool work can discard partial task output or in-progress work without a durable failure signal.
- `impact:message-loss`: The killed Workflow or tool child can leave the model without a terminal tool result or task notification.
- `impact:session-state`: The parent session can continue as if background work exists while the underlying CLI process tree has already been reaped.
- `maturity:stable`: The affected gateway runtime/process lifecycle surface maps to gateway-runtime, which is scored M4 Stable in qa/maturity-scores.yaml.

## Summary

Keep open: current main and v2026.6.11 still perform the reported claude-cli turn-end cleanup-to-cancel-to-process-tree-signal path, and the related open issues are sibling symptoms rather than a merged or canonical fix.

## What This Changes

The issue requests a claude-cli lifecycle opt-out or telemetry so in-flight Workflow or other CLI-owned tool grandchildren are not silently killed at turn end.

## Best Possible Solution

Define a maintainer-approved claude-cli lifecycle contract that preserves process-tree cleanup safety while preventing owned background tool work from being treated as silently successful, ideally through bounded drain plus typed failure or telemetry.

Options:

- **Adopt bounded drain plus telemetry (recommended):** Add a narrow owner-approved contract for detecting in-flight CLI-owned background children, deferring cleanup only within a bounded ceiling, and surfacing forced cleanup to the parent session.
- **Telemetry first:** Keep unconditional cleanup for now, but snapshot, log, or surface killed grandchildren so the silent failure class becomes observable before changing lifecycle behavior.
- **Keep cleanup as the contract:** Document that Claude CLI Workflow or Bash grandchildren are not supported across turn boundaries and route users to OpenClaw exec/process or durable task surfaces instead.
