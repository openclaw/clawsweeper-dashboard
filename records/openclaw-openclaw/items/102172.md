## Label Justifications

- `P1`: The issue describes a real claude-cli channel workflow where background tool work is killed at turn end without a model-visible failure signal.
- `impact:data-loss`: Killing CLI-owned background tool work can discard in-progress task output or partial work without a durable failure signal.
- `impact:message-loss`: The killed Workflow/tool child can leave the model without a terminal tool result or task notification.
- `impact:session-state`: The parent session can continue as if background work exists while the underlying CLI process tree has already been reaped.

## Summary

Keep open: current main and v2026.6.11 still have the reported claude-cli turn-end cleanup path that closes the live Claude session, cancels the managed run, and signals the child process tree. The related open issues are useful sibling evidence, but none supersedes this narrower lifecycle/opt-out decision.

## What This Changes

The issue requests a claude-cli lifecycle change so turn-end cleanup does not silently SIGKILL CLI-owned Workflow or background grandchildren without a bounded drain, telemetry, or parent-visible failure signal.

## Best Possible Solution

Define a maintainer-approved claude-cli lifecycle contract that preserves safe process cleanup while surfacing or deferring in-flight CLI-owned tool grandchildren through bounded drain and typed telemetry/failure signals.
