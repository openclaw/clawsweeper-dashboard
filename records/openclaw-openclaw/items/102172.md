## Label Justifications

- `P1`: The report describes a real claude-cli channel workflow where background tool work is killed at turn end without a model-visible failure signal.
- `impact:data-loss`: Killing CLI-owned background tool work can discard in-progress task output or partial work without a durable failure signal.
- `impact:message-loss`: The killed Workflow/tool child can leave the model without a terminal tool result or task notification.
- `impact:session-state`: The parent session can continue as if background work exists while the underlying CLI process tree has already been reaped.
- `maturity:stable`: The affected gateway runtime lifecycle surface maps to the gateway-runtime M4 Stable scorecard entry, even though the narrower Agent Runtime and Anthropic provider rows are M3 Beta.

## Summary

Keep open: current main and v2026.6.11 still follow the reported claude-cli cleanup-to-process-tree-cancel path, and related open items cover overlapping lifecycle symptoms rather than superseding this narrower turn-end cleanup decision.

## What This Changes

The issue reports that claude-cli turn-end cleanup kills CLI-owned Workflow/background grandchildren without an opt-out or parent-visible failure signal.

## Best Possible Solution

Define a maintainer-approved claude-cli lifecycle contract that keeps process-tree cleanup safe while surfacing or preventing silent loss of in-flight CLI-owned background grandchildren.
