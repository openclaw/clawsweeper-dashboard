## Label Justifications

- `P1`: The report describes a real claude-cli channel workflow where background tool work is killed at turn end without a model-visible failure signal.
- `impact:data-loss`: Killing CLI-owned background tool work can discard in-progress task output or partial workspace state without a durable failure signal.
- `impact:message-loss`: The killed Workflow/tool child can leave the model without a terminal tool result or task notification.
- `impact:session-state`: The parent session can continue as if background work exists while the underlying CLI process tree has already been reaped.
- `maturity:stable`: The affected gateway runtime lifecycle/process-supervision surface maps to the M4 Stable Gateway runtime scorecard entry.

## Summary

Keep open: current main and the latest release still have the cleanup-to-cancel-to-process-tree SIGTERM/SIGKILL path, there is no bounded opt-out or telemetry contract for CLI-owned background grandchildren, and the linked sibling issues do not supersede this sharper claude-cli lifecycle decision.

## What This Changes

The issue requests a safe claude-cli turn-end lifecycle for Workflow/background child work, either by boundedly deferring cleanup when CLI-owned background grandchildren are alive or by surfacing those killed grandchildren as first-class telemetry.

## Best Possible Solution

Define an owner-approved claude-cli lifecycle contract that boundedly drains or detaches in-flight CLI-owned background work with typed failure/telemetry, or explicitly rejects unsupported post-turn work while preserving safe process-tree cleanup.

- **Adopt bounded drain plus telemetry (recommended):** Detect in-flight CLI-owned background children, defer cleanup only within a bounded ceiling, and surface forced cleanup as parent-visible failure or telemetry.

- **Declare post-turn work unsupported:** Document or enforce that Claude CLI Workflow/background grandchildren cannot survive OpenClaw turn cleanup and route users to ACP, exec/process, or detached task surfaces.
