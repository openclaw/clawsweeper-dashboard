## Label Justifications

- `P1`: The report describes a real claude-cli channel workflow where background tool work is killed at turn end without a model-visible failure signal.
- `impact:data-loss`: Killing CLI-owned background tool work can discard in-progress task output or partial work without a durable failure signal.
- `impact:message-loss`: The killed Workflow/tool child can leave the model without a terminal tool result or task notification.
- `impact:session-state`: The parent session can continue as if background work exists while the underlying CLI process tree has already been reaped.

## Summary

Keep open: current main and v2026.6.11 still have the reported claude-cli run-end cleanup path, and the related open issues cover adjacent symptoms rather than superseding this lifecycle/no-opt-out decision.

## What This Changes

The issue requests a claude-cli lifecycle opt-out or telemetry so turn-end cleanup does not silently SIGKILL in-flight Workflow or other CLI-owned background child work.

## Best Possible Solution

Define an owner-approved claude-cli lifecycle contract that either boundedly drains or detaches in-flight CLI-owned background work with typed failure/telemetry, or explicitly denies unsupported post-turn work while preserving safe process-tree cleanup.

- **Declare post-turn Workflow unsupported:** Document or enforce that Claude CLI Workflow/background grandchildren cannot survive OpenClaw turn cleanup and route users to ACP, exec/process, or detached task surfaces.
