## Summary

Keep open: current main still lacks native mobile code syntax highlighting, and the iOS table/header subset is only partially covered by a separate open issue rather than implemented here.

## What This Changes

Request richer native mobile chat Markdown rendering: syntax-highlight fenced code on iOS/shared and Android, and render or gracefully degrade GFM tables in the iOS/shared chat UI.

## Best Possible Solution

Define one native mobile Markdown rendering plan for code-heavy chat: share behavior expectations across iOS/shared and Android, keep streaming performance, update license notices for any dependency, and link the iOS table/header subset to https://github.com/openclaw/openclaw/issues/98290 rather than duplicating that work.

No high-confidence live reproduction was run in this read-only review. Source inspection does show the current iOS/shared and Android renderer paths lack syntax highlighting, and Android already has table rendering while iOS/shared still routes through AttributedString(markdown:).

## Solution Assessment

Unclear as an implementation plan because the issue intentionally leaves dependency choice and iOS table fallback design open. The best path is a maintainer-approved native rendering approach with focused Swift/Kotlin coverage and visual mobile proof.
