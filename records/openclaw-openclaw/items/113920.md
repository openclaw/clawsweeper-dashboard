## Summary

Keep this PR open for a maintainer product decision. The earlier public-plugin-API blocker is resolved: exact-profile reads now remain core-internal, and the PR supplies redacted real-run evidence; the remaining question is whether usage commands should query every eligible profile by default.

## What This Changes

This PR reads usage for each eligible configured authentication profile and shows the resulting quota windows in `openclaw status --usage`, `openclaw models status`, and gateway auth-status responses.

## System Context

The provider-usage subsystem resolves configured authentication profiles and fetches normalized quota snapshots from provider hooks. Those snapshots feed CLI status output and the Gateway's auth-status response, which clients use to display account health and plan usage.

## Best Possible Solution

If maintainers want complete multi-account visibility by default, land the core-internal, bounded, no-refresh profile-read design and retain the provider-level summary only as a compatibility fallback; otherwise require an explicit opt-in surface before broadening these commands.
