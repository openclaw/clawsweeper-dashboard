## Summary

Keep open: current main still supports Telegram inline buttons only when they arrive as structured message-tool, presentation, interactive, or Telegram channel data, and it does not parse Gemini-style raw `[[...]]` button JSON from final reply text. The linked closing PR is the active candidate fix, but it remains open, conflicting, and still needs maintainer direction plus live proof.

## What This Changes

The issue asks OpenClaw to prevent Gemini Telegram replies from showing inline-button JSON as raw text and instead render those controls as interactive buttons.

## Best Possible Solution

Keep this as the canonical report until the linked PR or a maintainer-approved replacement lands with a narrow accepted fallback or typed-routing fix plus live Gemini/Telegram proof.
