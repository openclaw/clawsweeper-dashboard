## Summary

Keep open. Current main has durable outbound outcomes and caller-facing delivery statuses, but still lacks the requested shared agent-visible cross-channel delivery-failure notification contract.

## What This Changes

Request a shared notification/status contract so agents know when outbound channel message delivery fails.

## Best Possible Solution

Define one typed shared delivery-failure contract over existing durable outbound outcomes, then expose it consistently through the chosen agent/tool surface with cross-channel tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw expose outbound delivery failures to agents as a shared system event, structured message-tool/agent delivery status, or both?

Rationale: This changes model-visible context, channel/plugin SDK expectations, and recovery semantics, so the permanent contract needs maintainer intent before implementation.

Likely owner: steipete

Owner reason: The strongest history trail for outbound delivery and agent/message-tool boundaries points to steipete.

Owner confidence: high

Options:

- **Shared typed delivery contract (recommended):** Define one status/failure contract over existing durable outbound outcomes and decide exactly where agents observe it.
- **Tool/status only:** Limit the feature to structured tool or agent result status and avoid injecting new system events into session context.
- **Keep narrower mechanisms:** Leave current CLI, cron, restart-recovery, and channel-specific behavior as the supported path and close this direction separately if maintainers do not want model-visible delivery failures.

## Solution Assessment
