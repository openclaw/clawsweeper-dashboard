## Summary

Keep open. Current main has caller-facing delivery status, durable outbound outcomes, and narrower cron/session recovery work, but it still lacks the requested shared cross-channel mechanism that makes failed final delivery visible to the agent as context or a tool-result contract.

## What This Changes

Request a cross-channel delivery-failure notification mechanism so agents can detect, retry, or recover when channel sends fail.

## Best Possible Solution

Define one maintainer-approved delivery outcome contract at the agent/channel boundary, then wire final-reply and direct-delivery failures through that contract with sanitized errors and focused cross-channel tests.
