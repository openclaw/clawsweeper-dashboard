## Summary

Keep open. Current main has narrower delivery-status and recovery mechanisms, but it still does not provide the shared agent-visible cross-channel delivery-failure notification or tool-status contract requested here; this remains a product/API decision rather than a cleanup close.

## What This Changes

Request a shared delivery-failure notification mechanism so agents can know when channel sends fail and recover or inform users.

## Best Possible Solution

Define a maintainer-approved shared delivery outcome contract at the agent/channel boundary, then implement channel adapters so failed final replies become agent-visible without duplicating channel-specific policy.

## Reproduction Assessment

Yes at source level for the missing shared contract: current main exposes narrower delivery statuses and logs, but no generic mechanism injects failed channel delivery into agent context. I did not run a live channel failure scenario in this read-only review.

## Solution Assessment

Unclear as proposed: system-message injection is plausible, but the best fix needs maintainer agreement on the shared channel/agent API contract and how retries, transcript state, and memory updates should behave across transports.
