## Summary

Keep open. Current main and v2026.6.11 have useful delivery-status primitives for CLI/Gateway callers, durable outbound failure outcomes, pending-final recovery, and plugin observation hooks, but they still do not define the requested shared agent-visible delivery-failure notification or cross-channel message-tool failure-status contract.

## What This Changes

The issue requests a cross-channel way for agents to learn when outbound message delivery fails, either through injected session context or structured delivery status returned to the message tool.

## Best Possible Solution

Define one typed shared delivery-failure contract over the existing durable outbound outcomes, then expose it through the selected agent/tool surface with cross-channel tests instead of adding per-channel ad hoc failure injection.

- **Keep narrower status paths:** Leave current CLI, cron, restart recovery, diagnostics, and channel-specific handling as the supported behavior and close the broader request as not planned.
