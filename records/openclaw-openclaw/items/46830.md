## Summary

Keep open. Current main has per-surface delivery diagnostics and related narrow work in flight, but the central request for a shared agent-visible delivery-failure contract across channels is not implemented and still needs maintainer product/API direction.

## What This Changes

The issue asks OpenClaw to notify agents when outbound channel message delivery fails so the agent can recover instead of assuming the user received the message.

## Best Possible Solution

Define a single maintainer-approved delivery-status contract at the channel/agent boundary, then implement one narrow path that records failed sends, exposes the failure to the agent or caller, and aligns cron/CLI/channel behavior without per-plugin ad hoc injections.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Not a live high-confidence reproduction for this broad feature request; source and related reports show delivery failures can be logged or tracked in narrower paths, but the cross-channel agent-visible failure contract is still absent.

## Solution Assessment

Is this the best way to solve the issue? Unclear: system-message injection and tool-response status are plausible, but maintainers should choose the shared channel/agent contract before implementation to avoid divergent plugin behavior.
