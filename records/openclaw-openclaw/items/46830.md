## Summary

Keep open. Current main and v2026.6.11 expose narrower delivery-status, durable outbound outcome, pending-final recovery, and some narrow failure-notification primitives, but they still do not define the shared agent-visible delivery-failure event or message-tool failure-status contract requested here.

## What This Changes

The issue requests a cross-channel agent-visible notification or status contract when outbound channel message delivery fails.

## Best Possible Solution

Define one typed shared delivery-failure contract over the existing durable outbound outcomes and deliveryStatus, then expose it through the chosen agent/tool surface with cross-channel tests.

Question: Should OpenClaw expose outbound delivery failures to agents as a shared system event, structured message-tool/agent delivery status, or both?

Rationale: The choice changes model-visible context, channel ownership, plugin SDK expectations, and recovery semantics, so source inspection can show the gap but cannot safely choose the permanent contract.

Likely owner: steipete

Owner confidence: high

Options:

- **Shared typed delivery contract (recommended):** Define a single delivery-failure/status contract on top of durable outbound outcomes and decide where agents may observe it.
- **Tool/status only:** Limit the change to structured agent/tool result status and avoid injecting new system events into session context.
- **Keep narrower status paths:** Leave current CLI, cron, restart recovery, sessions_send, and channel-specific handling as the supported behavior and close the feature as not planned.
