## Summary

This is a credible ACPX runtime regression, but the forwarding logic is owned by the separately maintained official `openclaw/acpx` package rather than this OpenClaw checkout. The issue should be filed upstream with the supplied reproduction; no OpenClaw core change is needed to route or implement the fix.

## What This Changes

Prevent the official ACPX runtime from forwarding OpenClaw-specific session configuration keys such as `thinking` and `effort` to ACP backends that do not support them.

## System Context

OpenClaw's ACP control plane dispatches agent-session controls to the official `@openclaw/acpx` runtime plugin. ACPX then translates those controls into ACP adapter calls for Codex, Claude, OpenCode, and other backends, where unsupported configuration keys can fail a turn.

## Architecture Diagram

flowchart LR
  A[Main session settings] --> B[OpenClaw ACP controls]
  B --> C[Official ACPX plugin]
  C --> D[Backend capability handling]
  D --> E[ACP adapter request]
  E --> F[Sub-agent turn result]

## Best Possible Solution

File the narrowly scoped regression in the ACPX repository, add a backend-capability-aware filter with regression coverage for a non-Codex adapter, and release the corrected official package for OpenClaw users.
