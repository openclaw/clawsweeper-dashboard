The issue requests `$VAR` and `${VAR}` expansion when OpenClaw loads project and global `.env` files while preserving existing process-env precedence.

## Best Possible Solution

Define one maintainer-approved dotenv expansion policy for workspace, global/state-dir, legacy gateway, config-substitution, and service-env paths, then implement it with focused precedence and security tests or document literal dotenv values as intentional.
