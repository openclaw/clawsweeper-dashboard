## Summary

Keep open: current main and the latest release still load project/global dotenv values literally, while the merged state-dir service-env work only skips/removes unresolved whole-value references instead of expanding them. The remaining request is real, but it needs maintainer product/security direction because expansion changes credential propagation and workspace/global dotenv trust boundaries.

## What This Changes

The issue asks OpenClaw to expand `$VAR` and `${VAR}` references when loading project or global `.env` files while preserving shell environment precedence.

## Best Possible Solution

Define one maintainer-approved dotenv expansion policy for trusted global/state-dir, workspace, legacy gateway, config-substitution, and service-env paths; then implement it with focused precedence/security tests, preferably using a small maintained expansion dependency or explicitly documented no-expansion behavior.
