## Summary

Keep open: current main and v2026.6.11 still load dotenv values literally, while the overlapping merged state-dir work only skips unresolved service-env references. The remaining work needs maintainer security/product direction because expansion changes credential propagation across workspace, global, and service-env trust boundaries.

## What This Changes

The issue requests expansion of `${VAR}` and `$VAR` references when OpenClaw loads project or global `.env` files while preserving shell environment precedence.

## Best Possible Solution

Define one maintainer-approved dotenv expansion policy across workspace, global/state-dir, legacy gateway, config-substitution, and service-env paths, then implement it with focused precedence/security tests or document literal dotenv values as intentional.
