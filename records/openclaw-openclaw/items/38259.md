## Summary

Keep open: current main and v2026.6.11 still load dotenv values literally, while the merged state-dir work only skips unresolved service-env references instead of implementing general expansion. The remaining behavior needs maintainer product/security direction because expansion changes credential propagation and workspace/global dotenv trust boundaries.

## What This Changes

The issue asks for loaded project and global dotenv files to expand `$VAR` and `${VAR}` references while preserving shell environment precedence.

## Best Possible Solution

Define one maintainer-approved dotenv expansion policy for trusted global/state-dir, workspace, legacy gateway, config-substitution, and service-env paths, then implement it with precedence and security tests or document literal dotenv values as intentional.
