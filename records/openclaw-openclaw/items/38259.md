## Summary

Keep open: current main and the latest release still load general workspace/global dotenv values literally, while the merged state-dir work only skips unresolved service-env references instead of implementing expansion. The remaining request is real, but it needs maintainer product/security direction because expansion changes credential propagation and workspace/global dotenv trust boundaries.

## What This Changes

The issue requests `$VAR` and `${VAR}` expansion when OpenClaw loads project or global `.env` files while preserving shell environment precedence.

## Best Possible Solution

Define one maintainer-approved dotenv expansion policy for trusted global/state-dir, workspace, legacy gateway, config-substitution, and service-env paths, then implement it with focused precedence and security tests or document literal dotenv values as intentional.
