## Summary

Keep open: current main and v2026.6.11 still load workspace and global dotenv values literally, while the merged state-dir work only skips unresolved whole-value refs instead of implementing the requested expansion behavior.

## What This Changes

Request to expand `${VAR}` and `$VAR` references in loaded workspace/global `.env` files while preserving process-env precedence.

## Best Possible Solution

Define one explicit dotenv expansion policy for trusted global, untrusted workspace, legacy gateway, config, and service-env paths, then implement it with tests for precedence, blocked keys, provider credentials, unresolved refs, and upgrade behavior.

## Reproduction Assessment

Yes. Source inspection is high-confidence: OpenClaw parses dotenv files with `dotenv.parse` and assigns parsed values directly into `process.env`, matching the reported literal `${VAR}` behavior.

## Solution Assessment

Unclear. Expansion is plausible, but the best fix needs maintainer policy for workspace trust boundaries, provider credential aliases, missing variables, and durable service-env handling before implementation.
