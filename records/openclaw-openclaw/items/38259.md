## Summary

Keep open: current main and the latest release still load dotenv values literally, and the merged state-dir service-env work only skips whole-value unresolved references rather than implementing general expansion. The remaining decision is security-sensitive because expansion changes which credentials can propagate across workspace, global, runtime, and service-env boundaries.

## What This Changes

The issue requests `$VAR` and `${VAR}` expansion for OpenClaw-loaded `.env` files while preserving process environment precedence.

## Best Possible Solution

Define one maintainer-approved dotenv expansion policy across workspace, global/state-dir, legacy gateway, config substitution, and service-env paths, then implement it with focused precedence and security tests or document literal dotenv values as intentional.
