## Summary

Keep open: current main and v2026.6.11 still load general workspace/global dotenv values literally, while the merged related state-dir work only skips unresolved service-env references instead of implementing expansion. The remaining work is real, but it needs maintainer security/product direction because expansion changes credential propagation and workspace/global dotenv trust boundaries.

## What This Changes

The issue requests dotenv-style expansion of `$VAR` and `${VAR}` references in OpenClaw-loaded `.env` files while preserving shell environment precedence.

## Best Possible Solution

Define one maintainer-approved dotenv expansion policy for trusted global/state-dir, workspace, legacy gateway, config-substitution, and service-env paths, then implement it with focused precedence/security tests or document literal dotenv values as intentional.
