## Summary

Keep open: current main and v2026.6.11 still load dotenv values literally, while the merged state-dir work only skips unresolved service-env references. The remaining decision is real but security-sensitive because expansion changes credential propagation and workspace/global dotenv trust boundaries.

## What This Changes

The issue requests expansion of `$VAR` and `${VAR}` references when OpenClaw loads project and global `.env` files.

## Best Possible Solution

Define one maintainer-approved dotenv expansion policy for trusted global/state-dir, workspace, legacy gateway, config-substitution, and service-env paths, then implement it with focused precedence/security tests or document literal dotenv values as intentional.
