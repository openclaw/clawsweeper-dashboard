## Summary

Keep open: current main and v2026.6.11 still load dotenv values literally, while the merged state-dir work only skips unresolved service-env references instead of implementing general expansion. The remaining request is real, but it needs maintainer product/security direction because expansion changes credential propagation and workspace/global dotenv trust boundaries.

## What This Changes

Request support for expanding `$VAR` and `${VAR}` references while loading project/global `.env` files without overriding existing shell environment values.

## Best Possible Solution

Define one maintainer-approved dotenv expansion policy for trusted global/state-dir, workspace, legacy gateway, config-substitution, and service-env paths, then implement it with focused precedence and security tests or document literal dotenv values as intentional.
