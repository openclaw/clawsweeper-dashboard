## Summary

Keep open: current main and v2026.6.11 still load dotenv values literally, and the merged state-dir work only skips unresolved service-env references instead of implementing general expansion. The remaining decision is security/product policy for which dotenv sources may expand references and how missing references should behave.

## What This Changes

The issue requests expanding `$VAR` and `${VAR}` references when OpenClaw loads project and global `.env` files while preserving shell environment precedence.

## Best Possible Solution

Define one maintainer-approved dotenv expansion contract across trusted/global, workspace, legacy gateway, config-substitution, and service-env paths, then implement it with focused precedence/security tests or document literal `.env` values as intentional.
