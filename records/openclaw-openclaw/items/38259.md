## Summary

Keep open: current `main` and the latest release still load `.env` references literally, while the merged state-dir work only skips unresolved whole-value references instead of implementing general expansion. The remaining decision is security-sensitive because expansion changes credential propagation across workspace, global, config, and service-env boundaries.

## What This Changes

The issue requests `$VAR` and `${VAR}` expansion for OpenClaw-loaded project and global `.env` files while preserving existing shell environment precedence.

## Best Possible Solution

Define a maintainer-approved dotenv expansion policy across trusted and untrusted sources, then either implement trusted-source expansion with precedence/security tests or document `.env` values as literal and point users to config substitution, shell import, or SecretRefs.
