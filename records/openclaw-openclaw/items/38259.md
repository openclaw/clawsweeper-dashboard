## Summary

Keep open: current `main` and v2026.6.11 still load dotenv values literally, and the merged state-dir work only skips unresolved service-env references instead of implementing general `.env` expansion.

## What This Changes

The issue requests expansion of `$VAR` and `${VAR}` references loaded from OpenClaw-managed `.env` files while preserving shell environment precedence.

## Best Possible Solution

Define one maintainer-approved dotenv expansion contract across trusted/global, workspace, legacy gateway, config-substitution, and service-env paths, then implement it with focused precedence/security tests or document literal `.env` values as intentional.
