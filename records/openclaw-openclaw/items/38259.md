## Summary

Keep open: current main and the latest release still load dotenv values literally, and the related merged service-env work only skips unresolved whole-value references rather than implementing general `.env` reference expansion.

## What This Changes

The issue requests `${VAR}` and `$VAR` expansion when OpenClaw loads project or global `.env` files so provider-key aliases do not remain literal.

## Best Possible Solution

Define one maintainer-approved dotenv expansion policy across workspace, global/state-dir, legacy gateway env, config substitution, and service-env paths, then either implement it with focused precedence/security tests or document dotenv values as intentionally literal.
