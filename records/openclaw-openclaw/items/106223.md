## Summary

The latest head still has two merge-blocking correctness gaps: query-routed gateways can share dismissal state, and a failed cron job can recover while unseen then fail again without resurfacing. The browser proof is strong, but the gateway-scope repair is mechanical while failed-cron re-arm semantics need an explicit maintainer choice.

## What This Changes

Adds browser-local dismissal controls for sidebar cron and model-auth attention chips, with gateway-scoped localStorage persistence, signature-based resurfacing, cross-tab synchronization, tests, and styling.

## Best Possible Solution

Use a query-preserving gateway identity for storage and adopt a documented, tested failed-cron re-arm policy—preferably a bounded snooze expiry unless maintainers explicitly want every failed run to create a new incident—then prove query-route isolation and offline recover/refail behavior in the browser harness.

Options:

- **Bound the snooze (recommended):** Expire failed-cron dismissals after a defined interval so accepted incidents stay quiet temporarily but later unseen failures eventually resurface.
- **Key every failed run:** Include a stable run or incident identity so each later failed execution resurfaces, accepting that persistently failing recurring jobs may nag again every schedule tick.
- **Require observed recovery:** Keep job-id-only signatures and explicitly accept that recoveries not observed by an open tab cannot re-arm later failures.
