## Summary

Keep open. Current evidence still shows the requested clipboard mode is missing, no merged related work owns it, and maintainers must choose the interaction and plain-text conversion semantics before implementation.

## What This Changes

Add a Control UI option to copy assistant responses as plain text instead of only Markdown.

## Best Possible Solution

Add a compact per-message Markdown/plain-text copy menu, derive semantic plain text through the existing parsed Markdown pipeline or a dedicated tested renderer, and avoid adding a global preference or config surface unless later demand establishes it.

Options:

- **Add Per-Message Menu (recommended):** Expose Markdown and plain-text choices beside each assistant message and define a focused semantic conversion contract with browser clipboard tests.
- **Keep Markdown Only:** Retain the current single copy action to avoid another control and conversion contract in the chat bubble.
- **Add Persisted Preference:** Store a default copy format in UI settings, accepting the extra settings and upgrade surface instead of prompting per copy.

Yes at source level: the current assistant-message action passes Markdown directly to the clipboard, and no plain-text choice is wired into that path. A live browser run was not performed during this read-only review.

## Solution Assessment

Unclear until maintainers choose the interaction and conversion contract; a compact per-message menu is narrower and safer than adding a persisted preference or public config option.
