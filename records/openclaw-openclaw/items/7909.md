## Summary

Keep open. Current main still exposes only the Markdown clipboard action, and the latest related work does not implement a Markdown/plain-text choice; maintainers still need to choose the interaction and conversion semantics.

## What This Changes

Add a Control UI option to copy assistant message content as plain text instead of Markdown.

## Best Possible Solution

Add a compact per-message copy menu that preserves the existing Markdown action and offers plain text through one canonical, tested conversion helper, without adding a persisted preference unless maintainers explicitly request it.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Control UI add a per-message Markdown/plain-text copy menu, and what plain-text representation should it guarantee for structured Markdown?

Rationale: The capability is still missing, but choosing between a local menu and persisted preference—and defining how structured content is flattened—is a user-facing product contract rather than a mechanical bug fix.

Likely owner: steipete

Owner reason: The behavior originates in their Control UI copy implementation and they remain the strongest history-backed routing candidate for the UX decision.

Owner confidence: high

Options:

- **Add a local copy menu (recommended):** Keep Markdown as the existing action and add plain text in a compact per-message menu with documented conversion rules.
- **Add a persisted preference:** Let users choose a default format, accepting additional settings and upgrade surface for a small clipboard feature.
- **Retain Markdown only:** Decline the additional interaction and keep the current single-purpose copy control.

## Reproduction Assessment

Not applicable as a failing bug, but yes at source level: current main has a single Markdown-labeled action that copies its input unchanged and no plain-text path.

## Solution Assessment

Yes, a small per-message format menu is the narrowest maintainable direction; a new persisted preference is unnecessary unless maintainers explicitly want a global default.
