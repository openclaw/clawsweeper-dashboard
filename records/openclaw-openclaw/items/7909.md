## Summary

Keep open: current main and v2026.6.11 still expose only a Control UI assistant-message action labeled “Copy as markdown”; there is no Markdown/plain-text selector, persisted copy-format preference, or focused test proving plain-text clipboard output.

## What This Changes

The issue requests a Control UI option to copy assistant message content as plain text instead of only Markdown.

## Best Possible Solution

Add a compact Control UI copy-format menu that keeps current Markdown copy intact, adds plain-text output with explicit conversion semantics, and proves both clipboard paths with focused UI tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Control UI assistant-message copy expose a per-click Markdown/plain-text menu, add a persisted default copy-format preference, or decline this extra copy format for now?

Rationale: The missing behavior is clear, but the permanent UX shape and Markdown-to-plain-text semantics are product choices rather than a strict bug repair.

Likely owner: steipete

Owner reason: steipete introduced the current copy-as-markdown action and has the strongest history signal for this Control UI product decision.

Owner confidence: high

Options:

- **Add per-click copy-format menu (recommended):** Keep the existing Markdown copy behavior and add a small menu with Markdown and plain-text choices without introducing persisted settings.
- **Add persisted copy-format preference:** Let users choose a default copy format, accepting the extra preference, i18n, and settings-state surface.
- **Decline for now:** Leave the current Markdown-only copy action and close the request if maintainers do not want extra Control UI copy-format surface.

## Solution Assessment

Unclear. A per-click menu looks like the narrowest maintainable direction because it avoids new persisted settings, but maintainers still need to choose the UX and plain-text conversion contract.
