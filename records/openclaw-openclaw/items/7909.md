## Summary

Keep open: current main still exposes only the Markdown clipboard action, while the requested plain-text mode remains a distinct, vision-aligned Control UI ergonomics feature whose interaction and conversion contract need maintainer approval.

## What This Changes

Add a Control UI option to copy assistant messages as plain text instead of only Markdown.

## Best Possible Solution

Preserve one-click Markdown copying and add a compact per-message format menu with a clearly specified plain-text conversion contract and focused clipboard/UI coverage, without adding persisted configuration unless maintainers explicitly want it.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should the Control UI offer a per-click Markdown/plain-text copy menu, add a persisted default format, or remain Markdown-only, and what content semantics must the plain-text conversion preserve?

Rationale: The missing capability is source-confirmed, but the interaction model and treatment of code blocks, links, lists, tables, and embedded content are product choices rather than a mechanical bug fix.

Likely owner: steipete

Owner reason: This handle introduced the current copy behavior, maintains the adjacent Control UI path, and is the strongest available product-direction owner in repository history.

Owner confidence: high

Options:

- **Add per-click format menu (recommended):** Keep Markdown as the immediate default and expose plain text through a compact adjacent menu with documented conversion semantics.
- **Add persisted copy preference:** Let users choose a default format, accepting additional preference storage, settings UI, and upgrade behavior for a small clipboard action.
- **Keep Markdown-only copying:** Decline the additional UI and conversion complexity and leave users to paste through an external Markdown-to-text workflow.

## Reproduction Assessment

Yes at source level: current main has a single action labeled “Copy as markdown” that copies the Markdown string unchanged, with no plain-text selector. This is a missing feature rather than a failing existing contract, so no runtime bug reproduction is required.

## Solution Assessment

Yes, with refinement: a focused per-click format menu is the narrowest maintainable solution because it avoids a new persisted preference while preserving the existing one-click Markdown behavior. The conversion contract must be specified before implementation.
