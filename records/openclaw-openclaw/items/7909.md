## Summary

Keep open. The plain-text clipboard option remains a valid low-priority Control UI ergonomics request, and the discussion and related items do not identify a merged implementation; maintainers still need to choose the copy interaction and conversion semantics.

## What This Changes

Add a plain-text alternative to the Control UI assistant-message Markdown copy action.

## Best Possible Solution

Use a compact per-message copy menu with Markdown and Plain text actions, implement one deterministic Markdown-to-text conversion policy, and add focused clipboard tests for prose, links, lists, and fenced code without adding a global config option.

Options:

- **Add Compact Copy Menu (recommended):** Keep Markdown as the primary format and offer Plain text beside it with documented conversion behavior and focused tests.
- **Add Browser Preference:** Store a browser-local default copy format while retaining a menu for occasional overrides, at the cost of additional preference UX.
- **Keep Markdown Only:** Decline the extra format surface and retain the current predictable source-preserving copy behavior.

## Reproduction Assessment

Yes at source level: the reviewed copy path writes the assistant Markdown string directly and exposes no plain-text action. A live browser run was not performed for this read-only review.

## Solution Assessment

The requested outcome is useful, but the proposed dropdown versus preference choice is not settled. A compact per-message menu is the narrowest maintainable option and avoids creating another global setting.
