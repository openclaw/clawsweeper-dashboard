## Summary

The PR cannot merge as written because it changes the shared hook contract while only the embedded runner applies returned mutations; supported CLI/Codex harness paths still dispatch both hooks as best-effort observations and discard block, rewrite, and redaction results. The prior maintainer close deliberately left the API direction open and required defined compatibility/mutation semantics plus exact-head end-to-end plugin proof, which this branch still lacks.

## What This Changes

This PR converts `llm_input` and `llm_output` from fire-and-forget observation hooks into sequential modifying hooks that can block or rewrite model input and replace assistant output in embedded agent runs.

## Best Possible Solution

Preserve one consistent contract: preferably add explicitly privileged interception hooks across every supported runner while retaining the existing observation hooks, then document permissions, mutation/validation, timeout/failure semantics, and prove block, rewrite, redaction, and void compatibility on the exact head.
