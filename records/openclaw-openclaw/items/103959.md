## Summary

This PR remains necessary as a feature proposal, but it is not merge-ready: exact-head inspection shows that CLI-backed runners discard the new modifying results, the embedded runner evaluates token pressure against prompt text captured before plugin rewriting, and the changed shipped plugin contract lacks public guidance. A maintainer must also confirm whether these existing observational hooks should become a uniform cross-runner interception API.

## What This Changes

The PR changes `llm_input` and `llm_output` from observational hooks into sequential plugin modifiers that can block or rewrite model input and replace assistant output.

## Best Possible Solution

Define a documented, capability-aware interception contract first; then consume supported results at every advertised runner boundary, recompute all guards from the final effective prompt, and prove the behavior with a real exact-head plugin and agent run.
