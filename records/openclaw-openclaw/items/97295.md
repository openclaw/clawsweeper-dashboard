## Summary

Keep open for Feishu-owner review. The patch appears functionally correct and live-proven, but current main still lacks invalid-token recovery, a competing implementation remains open, and this branch uses process-wide cache invalidation whose multi-account scope needs explicit owner acceptance.

Likely related people: @m1heng is the strongest Feishu routing candidate; @vincentkoc and @whiteyzy have recent history in the affected client and sending paths.

## What This Changes

Adds one-shot Feishu recovery for invalid tenant-access-token responses by clearing SDK and CardKit token caches, recreating clients, retrying message sends, and adding regression coverage.

## Best Possible Solution

Land one plugin-local implementation that retries exactly once using a freshly resolved client, preserves the original Feishu error after a persistent failure, and scopes cache invalidation to the affected account unless the Feishu owner explicitly accepts process-wide eviction.
