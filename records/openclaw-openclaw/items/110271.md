## Summary

Keep open. The PR’s fast schema gates and off-hot-path verification address a real downgrade and repeated-scan problem, but the documented process-local-only fallback after a quarantine write failure can let a database that full verification already rejected reopen after restart through only the narrower `schema_meta` check. It also still lacks inspectable after-fix behavior proof.

Likely related people: `steipete` (high confidence) for the current and recent SQLite safety work; `vincentkoc` (high confidence) for the earlier merged integrity-gate work.

## What This Changes

The branch replaces synchronous full SQLite checks on ordinary opens with schema-first gates and targeted checks, adds gateway/update downgrade preflight plus delayed background full verification and quarantine, and documents database compatibility.

## Best Possible Solution

Preserve fail-closed protection across restart when verification persistence fails—either retain full open validation for that path or introduce an approved durable quarantine design—then provide redacted live proof of updater refusal-before-stop, gateway startup refusal, and repaired-database recovery.
