## Summary

Keep open: this is still the active implementation candidate for generated session titles, but the current head has a blocking source-level bug where automatically derived origin labels can suppress title generation for the direct/WebChat-style sessions this feature is meant to improve. The branch is also currently dirty/unmergeable and still needs maintainer acceptance of the default-off config, persisted metadata, auth routing, and transcript privacy boundary before merge.

## What This Changes

The PR adds a default-off `sessionTitle` config group, generates and persists `autoTitle` session metadata after successful replies, and projects that title through CLI, gateway session rows/events, and Control UI session list/search.

## Best Possible Solution

Keep the default-off stored `autoTitle` design only after origin labels no longer suppress generation for direct/WebChat-style sessions, the dirty branch is resolved, and maintainers approve the privacy, auth-routing, and config shape.

## Reproduction Assessment

Yes, at source level for the blocking PR bug. Current code can derive and persist `origin.label` from direct-message sender context, while the PR returns early when that field exists, so an origin-labeled session will not generate an `autoTitle`.

## Solution Assessment

No, not yet. Persisting one default-off generated title is a plausible architecture, but treating automatic origin labels as manual titles is too broad; the safer fix is to narrow the skip check and keep manual title precedence explicit.
