## Summary

Keep open: current main and v2026.6.11 still keep the fixed 5 MiB media-store and sandbox-staging cap, and the open related PRs only address narrower outbound Telegram/document slices rather than the broader configurable store/staging limit.

## What This Changes

The issue asks OpenClaw to make the hardcoded 5 MiB media-store and sandbox-staging cap configurable so larger PDFs, presentations, images, and generated attachments can reach sandboxed agents or outbound delivery.

## Best Possible Solution

Define one bounded, documented media-store and sandbox-staging limit contract, keep secure defaults, enforce hard maximums, and thread that resolved value through store, staging, gateway preflight, and reply-media callers.
