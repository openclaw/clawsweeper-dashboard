## Summary

Keep open: current main and latest release v2026.6.11 still keep the 5 MiB media-store/sandbox staging cap, and the open linked PR only addresses a narrow outbound reply-media slice with negative Mantis proof.

## What This Changes

The issue requests making the hardcoded media store and sandbox staging byte cap configurable or otherwise consistent with configured media limits so larger files are not rejected before sandbox or channel handling.

## Best Possible Solution

Define a bounded, documented media-store and sandbox-staging limit contract, keep secure defaults, thread the resolved cap through store, sandbox staging, gateway preflight, and reply-media callers, and keep this issue open until the full boundary is resolved.

## Reproduction Assessment

## Solution Assessment

Unclear as a final design. Making the cap configurable is plausible, but the best fix needs maintainer-approved scope, precedence with existing mediaMaxMb settings, secure defaults, and hard upper bounds; the linked PR is too narrow.
