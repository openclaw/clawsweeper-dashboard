## Summary

Keep open: current main and v2026.6.11 still keep the generic media-store, sandbox-staging, and unconfigured reply-media fallback on the 5 MiB `MEDIA_MAX_BYTES` cap, while the open Telegram PR only covers one outbound document slice.

## What This Changes

The issue asks for the hardcoded 5 MiB media store/sandbox staging limit to become configurable so larger files can be staged and delivered.

## Best Possible Solution

Define one maintainer-approved media staging cap contract for store, sandbox, and reply-media paths, with bounded defaults, explicit operator configuration if accepted, and regression coverage for both over-cap rejection and configured larger document cases.
