## Summary

Keep open: current main and the latest release still keep the 5 MiB media-store/sandbox staging cap, and the open related PR only addresses one Telegram outbound reply-media slice rather than the broader configurable store/staging limit.

## What This Changes

Make the hardcoded 5 MiB media-store and sandbox-staging cap configurable or otherwise aligned with media limits so larger files can be staged and delivered safely.

## Best Possible Solution

Define one bounded, documented media-store and sandbox-staging limit contract, keep secure defaults, thread it through store, staging, gateway preflight, and reply-media callers, and keep the Telegram outbound slice aligned with that contract.

## Reproduction Assessment

## Solution Assessment

Unclear as a final design. Making the cap configurable is plausible, but the best fix needs maintainer-approved precedence with existing mediaMaxMb settings, secure defaults, hard upper bounds, and upgrade behavior.
