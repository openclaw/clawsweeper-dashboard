## Summary

Keep this PR open. The change is a focused parity fix for an established approval-race behavior, but the available evidence is limited to unit tests and CI; it still needs redacted after-fix proof from real WhatsApp and Signal conversations before merge.

## What This Changes

Adds WhatsApp and Signal messages that tell an operator the canonical approval outcome when their reaction loses a concurrent approval race.

## System Context

WhatsApp and Signal inbound monitors receive operator reactions and ask the gateway to resolve the referenced approval. When another operator has already won the race, this change carries the gateway’s terminal result back to the channel monitor so it can notify the losing operator in the same conversation.

## Architecture Diagram

flowchart LR

  B --> C[Approval reaction resolver]
  C --> D[Gateway approval resolution]
  D --> E{Already resolved?}
  E -->|No| F[Apply operator decision]
  E -->|Yes| G[Send canonical outcome feedback]

## Best Possible Solution

Keep approval resolution channel-local, retain the narrow callback boundary, and add redacted live evidence showing the losing reaction produces exactly one canonical-outcome notice in both WhatsApp and Signal.
