## Summary

The PR fixes the payload-growth direction and resolves both prior review findings, but the 256 KiB limit is placed in a shared local-avatar opener. That helper also feeds the authenticated Control UI avatar route, so merging would make previously valid 256 KiB–2 MiB configured avatars fail outside `agents.list`; the branch also provides harness-only rather than real-setup proof.

## What This Changes

The branch adds a 256 KiB inline avatar limit, applies it to shared local-avatar open/read helpers, deduplicates oversized warnings, and adds unit plus gateway-harness tests.

## Best Possible Solution

Keep shared local-avatar acceptance and route delivery at 2 MiB, enforce the smaller limit only while producing inline `avatarUrl` data, and prove both bounded payloads and preserved dedicated delivery.
