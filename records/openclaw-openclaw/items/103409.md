## Summary

The latest head fixes the prior owner-boundary defect by preserving the shared 2 MiB opener and dedicated-route reader, but it still does not guarantee the new 256 KiB agent-list bound: the descriptor is checked with `fstat` and then read with the 2 MiB helper. The PR also lacks after-fix proof from an installed gateway and real client or dedicated avatar route.

## What This Changes

The PR adds a separate 256 KiB cap for local avatar data URLs projected through `agents.list` and `chat.startup`, deduplicates oversized-avatar warnings, and adds focused unit and gateway-harness tests.

## Best Possible Solution

Use the already-pinned descriptor for a projection-specific bounded read at 256 KiB, retain the shared 2 MiB opener and reader for accepted storage and authenticated delivery, and land only after maintainers accept the missing-avatar fallback and live proof demonstrates both paths.
