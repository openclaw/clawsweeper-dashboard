## Summary

The prior blocker remains on the latest head: oversized configured image data URLs are rejected for `identity.avatarUrl` but still copied unchanged into `identity.avatar`, so the full `agents.list` response is not bounded for a supported avatar source. The local-file cap is directionally sound, but merge also needs an explicit decision on omission versus thumbnail/reference behavior and after-fix proof from the affected gateway/client setup.

## What This Changes

The PR adds a 256 KiB limit for local-file and configured data-URL `avatarUrl` projection, while retaining the existing 2 MiB avatar acceptance and dedicated-delivery limits.

## Best Possible Solution

Bound every serialized avatar field for local files and configured data URLs, add a complete-projection regression case, and implement the maintainer-approved oversized-avatar outcome—prefer a small thumbnail or lazy dedicated-avatar reference if silent omission is not an accepted contract.
