## Summary

Keep open: the current head still permits configured data-URL avatars to bypass the new projection budget and appear in both response fields, so the reported multi-megabyte response remains possible. The omission behavior also needs owner confirmation and real affected-client proof before merge.

## What This Changes

The PR adds a separate 256 KiB cap for local-file avatar projection while preserving the existing 2 MiB avatar acceptance and dedicated-delivery limit.

## Best Possible Solution

Enforce one encoded inline-response budget across both identity.avatar and identity.avatarUrl for local files and configured data URLs, retain the 2 MiB storage and dedicated-delivery contract, and verify the chosen fallback plus response timing on the affected client.
