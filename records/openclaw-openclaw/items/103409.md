## Summary

This PR remains necessary and fixes the reported local-file case without changing avatar storage or dedicated delivery, but it does not fully bound gateway payloads because accepted inline image data URLs bypass the new cap; the external PR also lacks after-fix proof from a real configured gateway/client setup.

## What This Changes

The PR adds a separate 256 KB cap for local avatars in gateway agent projections, preserves the existing 2 MB acceptance and dedicated-delivery limit, and adds focused unit and gateway-harness tests.

## Best Possible Solution

Enforce one projection-only byte budget for every inline value returned by `resolveAgentAvatarUrlFromSource`—including configured image data URLs—while retaining the 2 MB storage/upload and dedicated-delivery contract, then demonstrate bounded RPC payloads and preserved dedicated delivery on a real configured gateway.
