## Summary

Current main does not reproduce the claimed leak: `deleteSession` intentionally hides the session while the process remains live, and the canonical terminal path clears active membership after process and sandbox cleanup settle. The proposed change would regress suspend safety and allow identifier reuse while termination is still in progress.

## What This Changes

Investigate whether deleting a bash process session leaves its background-session identifier retained in the active registry.

## Best Possible Solution

Keep session visibility separate from process liveness: hide deleted sessions immediately, reserve their identifiers while termination is active, and clear activity only through the idempotent terminal path after backend cleanup settles.

## Maintainer Decision

Required: false

## Reproduction Assessment

No. Current main explicitly tests that a deleted background session remains active until its process reaches the terminal path, where the identifier is removed.

## Solution Assessment

No. Adding `activeBackgroundExecSessionIds.delete(id)` to `deleteSession` would release lifecycle admission and permit identifier reuse before the underlying process and sandbox cleanup have actually settled.
