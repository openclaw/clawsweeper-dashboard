## Summary

Keep this PR open: it is a focused LINE-channel mitigation with sufficient live proof, but it still needs maintainer acceptance of the intentional busy-and-skip delivery semantics and a small pre-merge fix so skipped media messages are not downloaded and retained before the guard fires.

## What This Changes

The PR adds a process-local LINE per-user in-flight guard, wires it into `createLineBot`, sends a busy reply for rapid same-user events, skips senderless events, and expands LINE handler tests.

## Best Possible Solution

Land a LINE plugin-local guard only if maintainers accept busy-skip semantics, and move guard acquisition ahead of media download/context finalization so skipped messages are not partly processed or retained.
