## Summary

This PR remains useful because current main lacks equivalent relay fan-out telemetry, but it is not merge-ready: the unregister path emits the only aggregate before asynchronous invocations necessarily record their duration, and the PR still lacks exact-head real behavior proof.

## What This Changes

The PR adds per-registration native hook relay request and invocation counters, unregister-time duration summaries, no-local-work counts, and warnings for invocations lasting at least 250 ms.

## Best Possible Solution

Give each registration explicit active-invocation and teardown/finalized state, emit exactly one aggregate only after teardown starts and the last invocation records its duration, and cover normal unregister, replacement, expiration, exact counters, slowCount, and duplicate-summary prevention before collecting exact-head live logs.

## Reproduction Assessment

Yes, from source. Start an invocation whose local hook work remains pending, then unregister or replace the registration; the summary logs before the invocation's `finally` block records its completed duration.

## Solution Assessment

No. Aggregate metrics are a reasonable diagnostic direction, but immediate unregister-time emission is not the safest lifecycle boundary for asynchronous Codex hooks; deferred one-shot finalization is narrower and reliable.
