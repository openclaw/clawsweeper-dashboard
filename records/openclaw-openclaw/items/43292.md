## What This Changes

The issue reports a false unscheduled-reminder note when isolated-session cron coverage is missed and the same-turn cron-add counter is lost during compaction.

## Best Possible Solution

Land or replace the linked reminder-guard fix so main suppresses the guard for same-agent isolated cron jobs and preserves same-turn cron-add counts across compaction retry.

## Reproduction Assessment

Yes. Current main resets `state.successfulCronAdds` during compaction retry and only matches existing crons by `sessionKey`, so an enabled isolated cron without a session key cannot suppress the note after the counter is lost.

## Solution Assessment

Yes on direction. The narrow maintainable fix belongs in the core reply guard and compaction state path, while maintainers should resolve the existing linked fix candidate rather than queueing a duplicate repair.
