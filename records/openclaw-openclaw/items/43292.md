## What This Changes

The issue asks OpenClaw to stop appending the unscheduled-reminder note when an isolated-session cron was created or when a same-turn cron add survived compaction.

## Best Possible Solution

Land, adopt, or replace a focused fix that preserves same-turn cron-add evidence through compaction and treats enabled same-agent isolated crons as reminder coverage.

## Reproduction Assessment

Yes, at source level: current main resets state.successfulCronAdds during compaction retry and only matches existing crons by sessionKey, so an enabled isolated cron without a sessionKey cannot suppress the note after the counter is lost.

## Solution Assessment

Yes on direction: the narrow maintainable fix belongs in the core reply guard and compaction state path, not in channel-specific filtering or a broad reminder-policy rewrite.
