## Summary

Keep open: current main still cannot expose the original queued run ID set on merged followup/collect execution events, and the remaining work is a public Gateway event-contract choice rather than a stale report.

## What This Changes

Request to add Gateway event lineage so merged queued messages can be correlated from the executed agent run back to the original `chat.send` run IDs.

## Best Possible Solution

Define an additive Gateway lineage field for merged queued work, propagate ordered source run IDs through collect/followup execution, and preserve existing singular `runId` behavior.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What public Gateway event contract should represent source-run lineage when multiple `chat.send` requests merge into one executed agent run?

Rationale: The source path is clear, but automation should not choose stable protocol field names, ordering semantics, duplicate handling, or whether `runId` remains the execution identity.

Likely owner: steipete

Owner reason: steipete has the strongest recent history and timeline signal for Gateway event and queue semantics.

Owner confidence: high

Options:

- **Add lineage array (recommended):** Keep `runId` as the executed run ID and add an ordered `sourceRunIds`/`originalRunIds` style field to public agent/chat events for merged work.
- **Reuse one source ID:** Use the first or last queued source ID as the public merged run ID, which helps simple clients but loses full lineage.
- **Keep current contract:** Leave clients to correlate through accepted responses, history, and session state, accepting that live merged events have no source-run lineage.

## Reproduction Assessment

Yes. Source inspection shows collect/followup can aggregate multiple queued sources while current agent/chat event schemas and projections expose only one public `runId`.

## Solution Assessment

Unclear until maintainers choose the API shape. An additive lineage array appears safest because it preserves existing `runId` semantics while giving clients exact correlation data.
