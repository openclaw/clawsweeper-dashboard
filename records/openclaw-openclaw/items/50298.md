## Summary

Keep open: current main and the latest release still expose only singular run identifiers on public Gateway agent/chat events, while the internal steering queue retains the original queued run IDs only for lease/ack handling. The request is source-reproducible and valid, but the public API shape needs maintainer product direction before implementation.

## What This Changes

Request an event-contract change so merged queued message execution can report the original chat.send run ID set back to Gateway/WebSocket clients.

## Best Possible Solution

Define an additive original/source run ID lineage field for Gateway agent/chat events, propagate steering lease runIds into emitted events, and cover the public schema plus merged-queue projection behavior without overloading runId.

## Reproduction Assessment

Yes. Source inspection on current main shows queued steering preserves original runIds internally, while public Gateway agent/chat schemas and event projection expose only singular run identifiers.

## Solution Assessment

Unclear until maintainers choose the public API shape. An additive lineage field appears safer than selecting the first or last queued runId, because it preserves correlation without changing runId semantics.
