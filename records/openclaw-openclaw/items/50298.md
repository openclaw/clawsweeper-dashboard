## Summary

Keep open: current main still exposes only singular run identifiers on public Gateway agent/chat events, while collect-mode aggregation can complete multiple queued source identities without projecting those originals back to clients.

## What This Changes

Request an additive Gateway WebSocket event lineage field so merged or collect-mode agent runs can be correlated to the original queued `chat.send` run IDs.

## Best Possible Solution

Add a documented, additive lineage/correlation field on Gateway agent/chat events and cover collect-mode source IDs with focused protocol and Gateway projection tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Gateway agent/chat events grow an additive lineage field for collect/merged turns, and what exact name and semantics should that field use?

Rationale: Current source tracks queued identities internally but exposes only singular public run IDs on an M4 stable Gateway contract, so automation should not choose the API semantics unilaterally.

Likely owner: steipete

Owner reason: The decision is about the stable Gateway event contract and recent history routes the relevant protocol/projection surface most strongly here.

Owner confidence: medium

Options:

- **Add additive lineage array (recommended):** Preserve the executed `runId` and add a named array such as `sourceRunIds` or `originalRunIds` for merged queued sources.
- **Reuse one source ID:** Make merged execution appear under the first or last queued source ID, simplifying some clients while hiding multi-source lineage and changing run identity semantics.
- **Keep current contract:** Document that clients must correlate through accepted/final events and history, accepting that live aggregate agent events do not expose every queued source.

## Reproduction Assessment

Yes at source level: collect-mode source identities are retained for internal lifecycle/cancellation paths, while public Gateway schemas and projections expose only singular run identifiers.

## Solution Assessment

Unclear until maintainers choose the API shape; an additive lineage field appears safer than reusing a first or last source run ID because it preserves all merged sources without changing existing run identity.
