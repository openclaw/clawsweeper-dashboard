## Summary

Keep open: current main and the latest release still expose only singular run identity on Gateway agent/chat events, while collect-mode queue draining can merge multiple queued turns into one executed run. The remaining work is real, but it needs maintainer API direction before an automated fix should choose the public lineage contract.

## What This Changes

The issue requests that merged queued message processing expose the original chat.send run IDs on the resulting agent/Gateway events so clients can correlate replies to original messages.

## Best Possible Solution

Define an additive Gateway event lineage contract for merged queued work, propagate the queued source run IDs into public agent/chat events, and preserve existing singular runId behavior for non-merged runs.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What public Gateway event contract should represent source-run lineage when multiple chat.send requests merge into one executed agent run?

Rationale: Current code can identify queued turns and collect-mode groups, but the fix requires a stable API choice about field naming, ordering, duplicate handling, and whether public runId should remain the execution ID or become one of the source IDs.

Likely owner: steipete

Owner reason: steipete has the strongest combined history signal for collect-mode queue semantics and Gateway event/run lifecycle behavior, and the issue timeline routed this decision to them.

Owner confidence: high

Options:

- **Add an ordered lineage array (recommended):** Keep runId as the executed run ID and add an ordered originalRunIds/sourceRunIds-style field to public agent/chat events for merged work.
- **Reuse one source run ID:** Make merged execution use the first or last queued run ID as the public runId, which helps simple clients but loses full lineage.
- **Keep current contract:** Leave clients to correlate through accepted responses, session state, and history, accepting that merged live events do not expose all source run IDs.

## Reproduction Assessment

Yes by source inspection, but not by a live run in this read-only pass. Collect-mode can aggregate multiple queued turns, while the current Gateway agent/chat schemas and projections expose only singular run identity with no original queued run ID set.

## Solution Assessment

Unclear until maintainers choose the API shape. An additive lineage field appears safest because it preserves existing runId semantics while giving clients exact correlation data.
