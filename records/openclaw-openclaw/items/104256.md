Question: Should existing unannotated `openclaw/plugin-sdk/reply-runtime` pre-delivery callbacks receive a 15-second per-stage deadline by default?

Rationale: The deadline prevents a severe serialized-lane deadlock, but it intentionally changes the timing and failure semantics of a shipped public plugin callback contract, which requires lifecycle-owner approval.

Likely owner: steipete

Owner confidence: high

Options:

- **Adopt bounded default (recommended):** Apply a 15-second deadline to each stage and require legitimately slower callback owners to declare a larger positive finite budget.
- **Preserve unbounded default:** Keep existing callbacks unbounded unless they opt in, accepting that an unannotated callback can still indefinitely block its serialized delivery lane.

## Reproduction Assessment

Yes, from the instrumented linked issue and the current source chain: a never-settling `beforeDeliver` keeps `sendChain` and `waitForIdle()` pending. This review did not reproduce the original intermittent failure on live WhatsApp.

## Solution Assessment

Yes. Per-stage deadlines with explicit owner budgets and distinct delivery outcomes are narrower and safer than a shared aggregate deadline or treating timeout as intentional cancellation; only the public default requires owner confirmation.
