## Summary

This PR addresses a real unbounded-read risk, but the current patch also changes valid under-cap ignore-file behavior: more than 20,000 patterns or a pattern over 16 KiB excludes the whole subtree. That compatibility policy needs an explicit core-owner decision, and the posted real-behavior transcript predates the current head.

## What This Changes

The PR replaces unbounded ignore-file reads with a 4 MiB bounded reader and adds terminal subtree exclusion for oversized or pattern-complex `.gitignore`, `.ignore`, and `.fdignore` files.

## Best Possible Solution

Keep the bounded byte read, but preserve normal `ignore` semantics for valid under-cap content; reserve terminal subtree exclusion for genuinely unreadable or oversized files unless a core owner explicitly adopts and documents separate complexity limits.
