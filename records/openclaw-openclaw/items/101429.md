## Label Justifications

- `P2`: The memory hardening is valuable, but the current patch has a bounded, repairable regression affecting workspaces with unusually large ignore policies.
- `merge-risk: 🚨 compatibility`: Existing oversized ignore policies that previously excluded paths are silently discarded after merge.
- `merge-risk: 🚨 security-boundary`: Discarding an ignore policy can cause workspace scanners to ingest files and directories users intentionally excluded.
- `merge-risk: 🚨 availability`: Scanning dependency or build trees exposed by a discarded policy can cause excessive work or memory consumption.

## Summary

The latest head still leaves the repeatedly reported blocker unresolved: an oversized ignore policy causes scanning to continue without any of that file’s exclusions, so the proposed memory guard fails open.

## What This Changes

This PR replaces unbounded reads of `.gitignore`, `.ignore`, and `.fdignore` with a 4 MiB bounded regular-file read, preserves symlink-chain behavior, and adds focused tests.

## Best Possible Solution

Keep the bounded read and symlink preservation, but return a structured ignore-policy failure and make every workspace-scan caller fail closed by skipping the affected subtree, with caller-level coverage proving excluded content is never discovered.

## Solution Assessment

No. Bounding the read is appropriate, but silently dropping the complete policy is not the safest solution; scan callers should receive the failure and skip the affected subtree.
