## Summary

This PR addresses a real unbounded-read risk, but the current branch also turns syntactically valid under-cap ignore files into terminal subtree exclusions when internal pattern-complexity limits are crossed. That is an upgrade-visible compatibility policy, not a mechanical safety fix, and the standalone proof in the PR body predates the current head. A core owner should decide that policy before merge.

## What This Changes

The PR replaces unbounded ignore-file reads with bounded reads and adds terminal fail-closed exclusion for oversized or pattern-complex `.gitignore`, `.ignore`, and `.fdignore` files, plus focused tests.

## Best Possible Solution

Retain bounded physical reads, but require an explicit owner-approved compatibility contract for valid under-cap pattern complexity; then rerun and post redacted scanner proof from the exact merge head covering ordinary, oversized, complex-valid, negated, symlinked, and case-insensitive paths.
