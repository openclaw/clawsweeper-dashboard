## Summary

Keep open: the underlying unbounded ignore-file read is source-reproducible, but the proposed implementation also drops existing symlinked ignore-file behavior and lacks real behavior proof from a workspace scan.

## What This Changes

The PR replaces unbounded `.gitignore`/`.ignore`/`.fdignore` reads in `addIgnoreRules` with a 4 MiB capped reader and adds focused tests for normal and oversized ignore files.

## Best Possible Solution

Enforce a byte cap in the shared ignore-file read path while preserving current ignore-file semantics for symlinked files that resolve to readable regular files, use the local infra surface instead of the broad SDK barrel where possible, and add real workspace-scan proof.

- **[P2] Preserve symlinked ignore files:** `src/shared/ignore-rules.ts:26-29`
  - body: This switches ignore-file loading from Node's `readFileSync`, which follows a symlinked `.gitignore`, to `readRegularFileSync`, whose published `@openclaw/fs-safe@0.4.1` implementation rejects symlinks before reading.
