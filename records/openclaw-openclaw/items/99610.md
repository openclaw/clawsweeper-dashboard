## Summary

Keep open: this is a focused attempt at the linked gateway watch crash-loop, but it is not merge-ready because it only checks the currently existing `dist/entry.js`, not whether the replacement build for the new tree is ready, and the new deferred-restart test can leak a real polling timer.

## What This Changes

The PR adds a `dist/entry.js` readiness guard and polling-based deferred restart path to `scripts/watch-node.mjs`, plus new watch-node tests.

## Best Possible Solution

Make gateway watch restarts transactional: prepare and validate replacement build output for the new checkout state before signaling the healthy child, then prove it with focused regression tests and real source-checkout watch output.

## Reproduction Assessment

No live systemd reproduction was run in this read-only review. Source inspection shows current `main` can stop the watched child before `run-node` rebuilds and launches a valid replacement, which is enough to review this PR but not enough to call real behavior proof sufficient.

## Solution Assessment

No: this is a plausible mitigation for one missing-entry timing window, but it is not the best fix for the linked issue because it does not validate the replacement build for the new checkout before killing the healthy gateway.
