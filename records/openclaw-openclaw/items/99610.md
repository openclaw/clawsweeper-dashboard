## Summary

Keep open: this is a plausible candidate for the linked gateway crash-loop, but it is not merge-ready because the guard only checks that the current entrypoint exists before killing the healthy child, while `run-node` can still rebuild and clean `dist/` for the new checkout state after that kill.

## What This Changes

The PR adds a `dist/entry.js` existence check, deferred polling restart path, and watch-node tests for missing-entry rebuild windows.

## Best Possible Solution

Make gateway watch restarts transactional: prepare or validate replacement build output for the new checkout before signaling the healthy child, settle timer tests, and prove the race with real source-checkout watch output.

## Reproduction Assessment

No live systemd reproduction was run in this read-only review. Source inspection shows the current watch/rebuild ordering can stop the running child before the replacement runner rebuilds and launches a valid entrypoint.

## Solution Assessment

No: this is a plausible mitigation for one missing-entry timing window, but it is not the best fix for the linked issue because it does not validate the replacement build for the new checkout before killing the healthy gateway.
