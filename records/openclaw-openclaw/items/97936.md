## Summary

Keep open. The PR targets a real credential-scrub bug, but the current head still has the two prior blockers: independent key/value scrub sets can over-delete credentials, and file/exec migrations can now skip `.env` cleanup that current main performs.

## What This Changes

The PR changes `secrets apply` to collect migrated env ref IDs for `.env` scrubbing and adds regression tests for same-value provider credential migrations.

## Best Possible Solution

Carry owned `.env` scrub data as env-key-to-migrated-value sets, preferably from explicit target or registry ownership, while preserving file/exec cleanup and blocking unrelated same-value deletion.

## Reproduction Assessment

Yes, source-reproducible. I did not run a write-path reproduction in this read-only review, but current main still has the global value/key scrub and PR head still preserves source-level failure modes for mixed ownership and file/exec cleanup.

## Solution Assessment

No. The PR is a useful partial direction, but the best fix must bind each scrub key to its own migrated values and preserve file/exec cleanup coverage, ideally using explicit target-registry ownership metadata.
