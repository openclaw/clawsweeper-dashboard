## Summary

This remains a focused Codex runtime regression: ordinary turns persist split per-run usage but do not propagate the absolute cumulative thread total required to keep session context usage fresh. The report matches OpenClaw’s freshness semantics and Codex’s separate cumulative token-usage notification contract, and no merged fix or linked implementation PR is established.

## What This Changes

Ensure ordinary Codex app-server turns persist a fresh cumulative session token total so `/status` does not revert to unknown after each non-compaction turn.

## Best Possible Solution

Project the latest absolute Codex `thread/tokenUsage/updated` snapshot into the completed run’s aggregate usage at the Codex plugin boundary, then let the existing generic session persistence mark that total fresh without changing provider-neutral fallback semantics.
