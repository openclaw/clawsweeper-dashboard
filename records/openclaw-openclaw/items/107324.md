## Summary

Keep this issue open. Current OpenClaw behavior deliberately reports context usage as unknown when it lacks a trustworthy active-window snapshot, while Codex app-server currently exposes lifetime totals and last-response usage but no active-window value. No OpenClaw fix landed, and the three linked downstream proposals were closed after direct contract review; the remaining work starts at the Codex producer/protocol boundary. citeturn100344search0turn877450search0turn877450search1

## What This Changes

Restore trustworthy Codex current-context usage after ordinary turns so `/status` no longer alternates between unknown and numeric values around compaction.

## Best Possible Solution

Add an explicit active-window token value to the Codex producer and app-server protocol, then map it in OpenClaw’s Codex plugin to `contextUsage` while preserving `tokenUsage.last` for per-response accounting and retaining unknown status for older producers.

## Solution Assessment

Yes. A producer-defined active-window value followed by a narrow OpenClaw mapping is safer and more maintainable than inferring context from lifetime totals, per-response usage, or cache-accounting buckets.
