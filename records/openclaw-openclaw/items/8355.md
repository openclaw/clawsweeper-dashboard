## Summary

Keep open. Current main has reduced one adjacent source of voice latency by delivering a completed reply block before post-turn compaction, and it now provides generic streaming speech synthesis for providers such as ElevenLabs. However, the classic voice-call path still hands one completed text block to playback, calls buffered telephony synthesis returning a complete audio buffer, and only then emits Twilio frames; Telnyx is not wired to that playback path. No other open item now owns the remaining provider-generic sentence-to-audio streaming work.

## What This Changes

Add a provider-generic sentence-level LLM-to-TTS-to-audio streaming pipeline for classic voice calls to reduce time to first audio.

## Best Possible Solution

Add an additive public telephony streaming synthesis result that yields format- and sample-rate-tagged audio chunks, feed it from reliable completed reply boundaries, and let the existing per-call queue own ordered playback and aborts; ship buffered synthesis only as a documented fallback before the first audio chunk is delivered.

- Twilio currently owns outbound telephony TTS playback while Telnyx primarily exposes call-control and media-stream setup, so the initial cross-transport support boundary needs an explicit product decision.
