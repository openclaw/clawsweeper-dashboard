## Summary

Current main includes narrower early-response and playback-hardening improvements, but it still does not provide the requested provider-generic sentence-level classic voice pipeline. Realtime voice uses a separate full-duplex architecture, and every direct implementation attempt closed unmerged, so this remains the canonical feature pending product direction.

## What This Changes

Add a provider-generic voice-call pipeline that begins TTS and carrier playback from sentence-level LLM output instead of waiting for complete text and audio.

## Best Possible Solution

Define an additive plugin-owned streaming speech capability, then implement one provider/carrier reference path with ordered segmentation, backpressure, barge-in propagation, partial-playback recovery, latency telemetry, and complete-result fallback.
