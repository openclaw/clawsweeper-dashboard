## Summary

Keep open. Current main and the latest release still buffer the classic voice-call STT to embedded-agent to telephony-TTS path; realtime voice and the open compaction-wait PR are adjacent latency work, not the requested provider-generic sentence-level telephony streaming pipeline.

## What This Changes

Issue requests a provider-generic sentence-level streaming pipeline from LLM output through TTS audio for voice-call latency reduction.

## Best Possible Solution

Implement an additive provider-generic telephony audio streaming contract plus voice-call sentence pipeline that preserves buffered fallback, barge-in cancellation, ordering, and realtime voice as a separate bypass mode.

## Maintainer Decision

Question: Should OpenClaw add a provider-generic telephony streaming contract for the classic voice-call STT to LLM to TTS path, and what fallback/provider semantics should that contract require?

Rationale: The missing behavior is clear, but the permanent API shape affects bundled and external speech providers, Twilio/Telnyx playback adapters, fallback behavior, and user-visible latency expectations.

Likely owner: steipete

Owner confidence: high

Options:

- **Design additive provider-generic streaming (recommended):** Add a telephony audio stream capability to the speech/plugin SDK, wire sentence-level text delivery through voice-call, and keep buffered synthesis as the fallback for unsupported providers.
- **Use realtime voice as the low-latency path:** Document realtime voice as the supported low-latency solution and leave the classic STT to LLM to TTS path buffered.
- **Accept a provider-specific experiment:** Allow a narrower Twilio/OpenAI or ElevenLabs-first implementation, with follow-up API work needed before Telnyx and other providers can share it.

## Reproduction Assessment

Yes, at source level. Current main still awaits a complete embedded-agent response and complete telephony TTS buffer before Twilio chunking begins; no live carrier call was run in this read-only review.

## Solution Assessment

Unclear until maintainers choose the API direction. The requested direction addresses the remaining gap, but the safest implementation is a provider-generic telephony streaming contract rather than treating realtime voice or the compaction-wait PR as sufficient.
