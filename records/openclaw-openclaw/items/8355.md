## Label Justifications

- `P2`: The issue is a normal-priority voice-call latency improvement with limited channel blast radius, not a crash, data loss, or fully blocked setup path.

## Summary

Keep open. Current main and the latest release still batch the classic voice-call STT to embedded-agent to telephony-TTS path; newer generic speech streaming, realtime voice, and the open compaction-wait PR are adjacent work rather than the requested provider-generic sentence-level telephony streaming pipeline.

## What This Changes

Requested provider-generic sentence-level LLM to TTS to audio streaming for classic voice-call pipelines.

## Best Possible Solution

Implement an additive provider-generic telephony streaming contract and voice-call sentence pipeline that preserves the buffered fallback, barge-in cancellation, ordering, and realtime voice as a separate bypass mode, with Twilio/Telnyx and provider-specific proof.

## Reproduction Assessment

Yes. Source inspection on current main shows the classic path awaits one completed embedded-agent response, then one completed telephony TTS Buffer, before Twilio chunks audio; no live call was run in this read-only review.

## Solution Assessment

Unclear as an implementation, but the requested direction addresses the right remaining gap. Maintainers still need to choose the provider-generic telephony streaming API and fallback semantics before this becomes a safe implementation target.
