## Summary

Keep this issue open: current work reduces classic voice-call latency, but the provider-generic sentence-level LLM-to-TTS pipeline remains a distinct product and API decision. Likely related people: steipete (high confidence), joshavant (medium confidence), and xialonglee (medium confidence).

## What This Changes

The issue requests a provider-generic classic voice-call pipeline that begins TTS/playback from sentence-level LLM output instead of waiting for a completed response and audio buffer.

## Best Possible Solution

Sponsor an additive, plugin-owned streaming speech contract for the classic voice-call path, then implement one bounded carrier/provider slice with ordered playback, cancellation, fallback, and live latency proof before broadening support.
