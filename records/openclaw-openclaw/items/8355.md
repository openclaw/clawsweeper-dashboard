## Summary

Keep open. Current main and the latest release still batch the classic voice-call STT to embedded-agent to telephony-TTS path; realtime voice and the open compaction-wait PR are adjacent work, not the requested provider-generic sentence-level telephony streaming pipeline.

## What This Changes

The issue requests a provider-generic sentence-level streaming pipeline for classic voice-call responses so LLM text can flow into TTS and audio playback before the full response and full audio buffer are complete.

## Best Possible Solution

Implement an additive provider-generic telephony streaming contract and voice-call sentence pipeline that preserves buffered fallback, barge-in cancellation, ordering, and realtime voice as a separate bypass mode.

## Reproduction Assessment

Yes. Source inspection on current main and the latest release shows the classic path still awaits a completed embedded-agent response and a completed telephony TTS buffer before Twilio audio chunking begins; no live call was run in this read-only review.

## Solution Assessment

Unclear as an implementation, but the requested direction addresses the right remaining gap. Maintainers still need to choose the provider-generic telephony streaming API and fallback semantics before this becomes a safe implementation target.
