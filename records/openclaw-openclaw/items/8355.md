## Summary

Current main has useful early-response and provider-audio streaming improvements, but it still does not provide the requested provider-generic sentence-level LLM-to-TTS pipeline for classic voice calls. Realtime voice is a separate full-duplex path, the direct implementation PRs closed unmerged, and this issue remains the canonical product/API design item.

## What This Changes

Add provider-generic sentence-level LLM-to-TTS-to-audio streaming for classic voice calls while preserving ordered playback, barge-in, and safe fallback behavior.

## Best Possible Solution

Define an additive plugin speech-stream contract with explicit text-segment, audio-chunk, abort, ordering, and partial-delivery outcomes; implement one live-proven provider/carrier slice first while retaining the buffered path, then extend other carriers through their own adapters.

No, replacing the completed-response interfaces outright would be too disruptive. The safer solution is an additive provider-generic stream contract with explicit buffered fallback and tested partial-playback semantics.
