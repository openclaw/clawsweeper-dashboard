## Summary

Current main improves one adjacent delay by handing off a completed reply block before post-turn compaction, but the classic voice-call path still does not pipeline incremental LLM sentences through streaming telephony synthesis and ordered carrier playback. Realtime voice remains a separate full-duplex architecture, all direct implementation PRs are closed unmerged, and this issue remains the canonical provider-generic request. Likely related people: steipete (high confidence), xialonglee (high), joshavant (medium), and dguido (medium).

## What This Changes

Add a provider-generic sentence-level LLM-to-TTS audio pipeline to reduce time-to-first-audio on classic voice calls.

## Best Possible Solution

Reuse the existing generic speech streaming capability where its output format is suitable, add only the missing additive telephony stream metadata/contract, and connect reliable completed-sentence boundaries to ordered Twilio and Telnyx playback with abort, barge-in, resource cleanup, and buffered fallback semantics proven by live calls.

## Reproduction Assessment

Yes, from current source with high confidence: classic generation flushes one completed reply block, telephony synthesis returns one completed buffer, and Twilio begins 20 ms frame delivery only after that buffer resolves. This review did not perform a new live carrier timing run.

## Solution Assessment

No—the proposed direct replacement of `generateVoiceResponse()` with an iterator and a parallel streaming stack is broader than necessary. The best fix is additive wiring around existing block callbacks and generic speech streaming, with only the missing telephony stream contract introduced.
