## Summary

Keep open. Current main still batches the classic voice-call STT to embedded-agent to telephony TTS path before Twilio sends audio chunks, and the adjacent realtime/early-reply work does not implement the requested provider-generic sentence-level telephony streaming pipeline.

## What This Changes

The issue requests a provider-generic sentence-level streaming pipeline that sends LLM partial output through TTS and into voice-call audio playback before the full text and full audio buffer are complete.

## Best Possible Solution

Keep this as the canonical provider-generic classic voice-call latency feature and solve it with an additive streaming speech/telephony contract, sentence-level embedded-agent partial reply handling, Twilio/Telnyx playback adapters, and fallback/barge-in tests.

Yes, source inspection gives a high-confidence reproduction of the current shape: the classic path completes embedded-agent text and full telephony TTS before Twilio audio chunks are sent. I did not run a live Twilio or Telnyx call in this read-only review.

## Solution Assessment

Yes for triage: keeping this open is the best current outcome because realtime voice and early-block-reply delivery are adjacent paths, not the provider-generic sentence-level telephony stream requested here. The implementation path still needs maintainer-approved API and playback semantics.
