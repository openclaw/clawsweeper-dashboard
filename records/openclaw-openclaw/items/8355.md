## Summary

Keep open. Current main and the latest release still batch the classic voice-call STT to agent to telephony-TTS path; realtime voice and the open compaction-wait PR are adjacent latency work, not the requested provider-generic sentence-level telephony streaming pipeline.

## What This Changes

Request a provider-generic classic voice-call pipeline that streams LLM sentence chunks through TTS audio to Twilio/Telnyx instead of waiting for full text and full audio buffers.

## Best Possible Solution

Add an explicit provider-generic telephony streaming contract and voice-call sentence pipeline that preserves buffered fallback, barge-in cancellation, ordering, and realtime voice as a separate bypass mode.

Options:

- **Accept a provider-specific experiment:** Allow a narrower Twilio/OpenAI or ElevenLabs-first implementation, with follow-up API work needed before Telnyx and other providers can share it.
