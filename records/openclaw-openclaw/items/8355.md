## Summary

Keep open. Current main and the latest release still batch the classic voice-call STT to embedded-agent to telephony-TTS path; realtime voice, Discord/ElevenLabs streaming TTS, and the open compaction-wait PR are adjacent latency work, not the requested provider-generic sentence-level telephony pipeline.

## What This Changes

Request a provider-generic sentence-level streaming pipeline that starts voice-call TTS/audio playback before the full response text and full telephony audio buffer are complete.

## Best Possible Solution

Implement an additive provider-generic telephony streaming contract plus voice-call sentence pipeline that preserves buffered fallback, barge-in cancellation, playback ordering, and separate realtime-voice bypass behavior.
