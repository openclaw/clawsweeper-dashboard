## Summary

Keep open: the merged Feishu drive list pagination fix covers one half of the report, but current main still leaves `info` as a single-page lookup that can falsely return `File not found` for files beyond the first listed page.

## What This Changes

The issue requests Feishu drive cursor support for `list` and paginated lookup for `info` so files beyond the first Lark drive page remain accessible.

## Best Possible Solution

Keep this issue open until the remaining `info` action has a concrete folder-aware pagination contract, preserves the merged list continuation behavior, and proves files past page one no longer produce false `File not found` results.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: `info` calls `drive.file.list` once, then throws if the target token is not on that first page. I did not run a live Feishu tenant test in this read-only review.

## Solution Assessment

Yes, the best fix is plugin-local: add the folder-aware `info` contract and drain Lark cursor pages for that concrete folder, while avoiding automatic root draining because Feishu bot credentials normally have no browsable root.
