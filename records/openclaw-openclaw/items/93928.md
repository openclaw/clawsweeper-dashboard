## Summary

Keep open: current main fixed the Feishu Drive `list` cursor half through https://github.com/openclaw/openclaw/pull/101572, but `info` still dispatches without a folder token and searches only one `drive.file.list` page before throwing `File not found`.

## What This Changes

Request to make Feishu Drive folder listing pagination usable and make `info` find files beyond the first API page instead of falsely reporting that they are missing.

## Best Possible Solution

Keep the list pagination behavior from https://github.com/openclaw/openclaw/pull/101572, then land a Feishu-plugin-local `info` fix that uses an explicit concrete folder scope, follows SDK cursors until the file is found or pages are exhausted, and updates the skill plus focused regression proof.

## Solution Assessment

Yes, the narrow solution belongs inside the Feishu plugin, but not by unbounded root draining. The best fix is a folder-aware `info` contract with cursor pagination, regression coverage, and real or accepted gateway proof.
