## Summary

Keep open: current main fixed the Feishu Drive `list` continuation path through https://github.com/openclaw/openclaw/pull/101572, but the separate `info` lookup still searches only one `drive.file.list` page and maintainer discussion explicitly keeps the folder-aware `info` contract unresolved.

## What This Changes

The issue asks for Feishu Drive `list` and `info` actions to handle Lark cursor pagination so files beyond the first API page remain reachable.

## Best Possible Solution

Keep the merged list continuation behavior, then define and implement a Feishu-plugin-local `info` lookup that accepts an explicit concrete folder scope, follows SDK cursors until found or exhausted, and updates the skill plus focused proof.

Options:

- **Add folder-scoped info lookup (recommended):** Add an optional concrete `folder_token` to `info`, paginate only within that folder, and document that root lookup remains limited for bot credentials.
- **Keep info root-limited:** Leave `info` as a root/first-page helper and document that users must use paginated `list` to browse shared folders before requesting metadata.
- **Reject cross-page info lookup:** Treat the merged list continuation as sufficient and close the remaining `info` request as unsupported product behavior.

## Reproduction Assessment

Yes, source-reproducible: current `info` dispatch calls a helper that makes one `drive.file.list` request and throws when the target is not on that page. The issue body also includes mocked runtime proof for the same failure, but this read-only review did not run a live Feishu tenant test.

## Solution Assessment

Unclear until maintainer intent is set: the narrow fix belongs inside the Feishu plugin, but the best permanent shape is folder-scoped pagination rather than unbounded root draining.
