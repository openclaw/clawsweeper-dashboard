## Summary

Keep open: https://github.com/openclaw/openclaw/pull/101572 fixed the `list` continuation half on current main, but `feishu_drive` `info` still performs a single `drive.file.list` call and can still report `File not found` before following later pages.

## What This Changes

The issue requests Feishu Drive pagination support for `list` and `info`, so callers can continue folder listings and `info` does not miss files beyond the first API page.

## Best Possible Solution

Add a plugin-local, folder-scoped `info` lookup contract that paginates safely inside a supplied shared folder, with focused tests, docs, and proof; avoid automatic root draining unless maintainers explicitly approve it.

Options:

- **Add folder-scoped info pagination (recommended):** Expose a narrow `folder_token` contract for `info`, paginate only that concrete folder, and document that root lookup is not automatically drained for bot credentials.
- **Keep info root-only:** Document `list` pagination as the supported way to locate files in shared folders and close or narrow the remaining `info` request.
- **Design a separate lookup tool:** Defer implementation until maintainers choose a different file lookup surface that can handle folder scope, permissions, and proof requirements.

## Reproduction Assessment

Yes. Current main still shows a source-level repro for the `info` half: `getFileInfo` reads one list page and throws before following `has_more` / `next_page_token`.

## Solution Assessment

Unclear without maintainer direction. The merged `list` fix is the right shape for folder continuation, but the remaining `info` behavior should be resolved as a folder-scoped contract or explicitly documented as unsupported.
