Keep this issue open: current main still uses the custom non-Desktop WhatsApp socket identity implicated by the reporter, and the central group-delivery failure remains present after the earlier reconnect-churn repair and latest release. The reporter’s real deployment provides strong before/after evidence that a Desktop identity plus re-pairing restores durable group delivery.

## What This Changes

Fix WhatsApp linked-device group inbound delivery that stops after pairing while direct-message delivery remains functional.

## Best Possible Solution

Use the upstream Desktop browser identity as the canonical pairing mode, detect credentials registered with the legacy identity, and provide an explicit doctor or setup recovery that guides affected operators through re-pairing instead of adding a permanent identity option.

- **Opt-in transition:** Preserve the current default and add a Desktop identity option that operators enable before manually re-pairing.
