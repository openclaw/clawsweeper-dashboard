## Summary

Keep this issue open. Current main still creates WhatsApp sockets with the non-Desktop `openclaw/cli` browser identity, while the reporter has a repeatable live failure and restored sustained group delivery only after changing that identity and re-pairing; no merged fix or viable canonical replacement exists.

## What This Changes

Fix WhatsApp linked-device sessions that receive direct messages but silently stop receiving group messages after pairing.

## Best Possible Solution

Keep the fix in the WhatsApp plugin: adopt a Baileys Desktop companion identity for supported pairings without adding a general config knob, provide an explicit in-product diagnostic and re-pair recovery path for legacy sessions, retain `syncFullHistory: false` unless live evidence requires otherwise, and verify fresh pairing plus restart/reconnect group delivery.
