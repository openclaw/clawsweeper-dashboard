## Summary

Keep this issue open: current main still creates WhatsApp sockets with the non-Desktop `openclaw/cli` identity implicated by the reporter, while the supplied real-deployment workaround restores group delivery after switching to a Desktop identity and re-pairing. The defect remains necessary to resolve, but the upgrade and re-pairing behavior needs maintainer direction before implementation.

## What This Changes

Fix WhatsApp linked-device sessions that receive direct messages but silently stop receiving group messages after pairing or reconnecting.

## Best Possible Solution

Validate a Desktop browser identity against the pinned Baileys version, make it the canonical pairing identity if confirmed, preserve that identity across reconnects, and provide an in-product doctor/status warning with a guided re-pair path for incompatible existing credentials; add live proof that group messages continue after reconnect and avoid a new config option unless a single safe default is impossible.
