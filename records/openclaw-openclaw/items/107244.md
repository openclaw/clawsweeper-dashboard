## Summary

This is a current, well-diagnosed WhatsApp inbound bug: group messages stop reaching `messages.upsert` while DMs continue, and current `main` still uses the non-Desktop browser identity and disables full-history synchronization that the reporter isolated through a successful local Desktop-identity workaround. Earlier reports show the same symptom, but none provides a current merged fix or viable canonical implementation, so this issue should remain open for an upgrade-safe maintainer decision.

## What This Changes

Fix WhatsApp linked-device sessions so inbound group messages continue working after pairing and reconnects, with useful diagnostics when group delivery is unavailable.

## Best Possible Solution

After verifying the Baileys contract directly, use its supported Desktop identity for new WhatsApp pairings, keep full-history synchronization disabled unless separately proven safe, add Doctor/status guidance for affected existing sessions that must re-pair, and validate DMs plus group ingestion across fresh pairing and reconnects; avoid a new config knob unless multiple identities are intentionally supported.
