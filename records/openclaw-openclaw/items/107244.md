## Label Justifications

- `P1`: A documented WhatsApp group workflow silently loses all inbound messages for affected linked-device sessions while reporting the provider as healthy.
- `impact:message-loss`: Group messages are delivered by WhatsApp but never reach OpenClaw's inbound processing or agent routing.

## Summary

Keep this issue open: current main still uses the non-Desktop WhatsApp socket identity implicated by the reporter, while a real deployment consistently restored group delivery only after switching to a Desktop identity and re-pairing; the remaining blocker is choosing an upgrade-safe pairing migration policy.

## What This Changes

Restore reliable WhatsApp linked-device group ingestion after pairing and reconnects without affecting working direct messages.

## Best Possible Solution

Use a Desktop-compatible identity for new WhatsApp pairings, add an explicit doctor/setup path that detects or explains incompatible existing pairings and guides re-pairing, and cover fresh-pair plus upgrade/reconnect behavior without adding a permanent config knob unless maintainers deliberately want one.
