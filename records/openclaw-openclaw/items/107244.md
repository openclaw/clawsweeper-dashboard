## Label Justifications

- `P1`: A currently supported WhatsApp group workflow silently loses all inbound messages while the provider reports healthy.
- `impact:message-loss`: Group messages never enter OpenClaw inbound handling and therefore cannot be routed or answered.
- `impact:session-state`: The failure changes with pairing identity and reconnect state, and the working transition requires replacing linked-device credentials.

## Summary

Keep this issue open: current main still creates WhatsApp sockets with the custom non-Desktop identity implicated by the reporter, so the central group-delivery failure is not implemented away. The reporter supplied strong real-deployment evidence that switching to a Desktop identity and re-pairing restores group delivery across reconnects and restarts.

## What This Changes

Fix WhatsApp linked-device group messages silently failing to reach inbound handling while direct messages continue to work.

## Best Possible Solution

Adopt an upstream-supported Desktop identity for new WhatsApp pairings, add an explicit status/doctor warning and guided re-pair path for incompatible existing credentials, keep unnecessary history sync disabled, and prove group delivery through pairing, reconnect, and gateway restart; track directory population separately if it still fails.
