## Summary

This remains a current, well-diagnosed WhatsApp inbound bug. The reporter reproduced it on release 2026.7.1, demonstrated that direct messages continue while group messages disappear before OpenClaw inbound handling, and restored reliable delivery only by re-pairing with a Desktop browser identity; current-main evidence from the previous review still shows the non-Desktop identity, with no merged fix or safe canonical replacement.

## What This Changes

Fix WhatsApp linked-device group messages disappearing after pairing while direct messages continue to work.

## Best Possible Solution

Use one supported Desktop linked-device identity in the WhatsApp plugin, preserve `syncFullHistory: false` unless upstream proof supports changing it, and add a guided Doctor/setup recovery that detects incompatible existing credentials and tells affected users to re-pair without requiring manual file edits.

- **Keep current identity:** Retain current behavior while seeking a different upstream fix that does not alter the registered linked-device identity.

## Solution Assessment

The demonstrated Desktop-identity change is the strongest available fix direction, but exposing a generic browser-identity option is not the best solution. A single supported default with an explicit re-pair migration and focused lifecycle tests is narrower and safer.
