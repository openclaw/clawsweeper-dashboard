## What This Changes

Fix WhatsApp linked-device sessions that receive direct messages but silently stop receiving group messages after pairing or reconnect.

## Best Possible Solution

Make the official WhatsApp plugin use a proven group-capable linked-device identity for new pairings, detect incompatible existing pairings, and provide a clear doctor/setup recovery that guides users through required re-pairing; validate fresh pairing, restart, reconnect, direct messages, and sustained group delivery with live Baileys proof.

Question: Should the official WhatsApp plugin change its default linked-device browser identity and require a guided re-pair for affected existing sessions, or preserve the current default and expose an opt-in identity mode?

Rationale: The live workaround is convincing, but changing identity is an upgrade-sensitive product decision because existing credentials can enter a 428 loop and the repository discourages adding configuration when a reliable default and doctor recovery can solve the problem.

Likely owner: steipete

Owner confidence: medium

Options:

- **Change default with guided re-pair (recommended):** Adopt the proven Desktop identity for new sessions and add detection plus doctor/setup guidance for existing credentials that must be re-paired.
- **Add an opt-in identity setting:** Preserve current behavior by default and expose a plugin setting for users willing to re-pair, at the cost of another compatibility-sensitive config surface.
- **Hold for upstream proof:** Keep the issue open without changing defaults until direct Baileys testing isolates whether identity, history sync, or both are required.

## Reproduction Assessment

Yes. The reporter reproduced the failure repeatedly on 2026.7.1, isolated it from policy and routing, and demonstrated an after-fix live path using a Desktop identity plus re-pairing that survived gateway restarts.

## Solution Assessment

No, making the browser identity configurable is not the best default solution unless compatibility evidence requires it. The narrower product outcome is a reliable plugin-owned default with explicit detection and guided recovery for sessions that must be re-paired.
