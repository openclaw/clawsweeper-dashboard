## Summary

Keep open: current main and the latest release still lack a typed Gemini safety-settings config surface, the direct Google GenerateContent payload still omits `safetySettings`, and the prior implementation PR is closed unmerged, leaving this issue as the canonical tracker.

## What This Changes

Request to configure Gemini safety thresholds per provider or model and pass them to Google Gemini API requests.

## Best Possible Solution

Add a narrow, documented Google Gemini provider configuration contract with strict category/threshold validation, schema/help/docs/test coverage, Google-only request injection, and explicit precedence for per-request payload values after maintainer approval.

Options:

- **Approve a narrow Google setting (recommended):** Add a strict Google-scoped `models.providers.*.safetySettings` or equivalent contract with documented categories, thresholds, request precedence, and tests.
- **Keep upstream defaults:** Decline the config surface for now and keep Gemini safety behavior on provider defaults to avoid adding a safety-affecting knob.
- **Design a broader provider-settings seam:** Pause implementation until maintainers define a general provider-specific request-settings API that can cover Google and future provider-owned controls.

Yes, at source level: current main has no accepted `safetySettings` provider config key and the direct Google GenerateContent builder does not emit that request field. I did not run a live Gemini request because the missing behavior is already visible in the config schema and request builder.

## Solution Assessment

Unclear as proposed: provider/model config is plausible, but maintainers still need to decide the schema, category set, threshold policy, Google-only scope, and safety posture before implementation.
