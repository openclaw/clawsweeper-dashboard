## Summary

Current main still lacks configurable Gemini safety thresholds, and the earlier implementation PR closed unmerged. The request remains useful, but its public configuration shape and policy require maintainer approval.

## What This Changes

Allow operators to configure Gemini harm-category thresholds and include them in supported Google model requests.

## Best Possible Solution

Add an explicit, operator-controlled Google-plugin contract with no default behavior change, strict category and threshold validation, documented precedence, supported-transport scoping, focused config/request tests, and redacted live Gemini proof.

Question: Should OpenClaw expose operator-configurable Gemini safety thresholds, and which permanent configuration owner and transport scope should it use?

Rationale: This adds public configuration that can deliberately relax an upstream safety control, while provider-level, per-model, Vertex, custom-endpoint, and precedence choices have materially different compatibility consequences.

Likely owner: steipete

Owner confidence: medium

Options:

- **Provider-owned model parameters (recommended):** Use a Google-plugin-owned, validated per-model parameters contract and inject it only for explicitly supported Google transports.
- **Provider-level inheritance:** Add a typed models.providers entry and define inheritance, custom-provider matching, request precedence, and upgrade behavior.
- **Keep Google defaults:** Decline built-in configuration and leave altered safety policy to an external provider plugin or proxy.

## Reproduction Assessment

Yes at source level. Current main has no typed safety-settings field, the strict provider schema has no dedicated key, and the Google request builder does not emit safetySettings.

## Solution Assessment

Unclear. The requested provider-level pseudo-key demonstrates the need, but the narrowest maintainable solution should use Google-plugin ownership and requires a maintainer decision on policy, scope, and precedence first.
