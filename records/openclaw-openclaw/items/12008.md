## Summary

Current main still lacks Gemini safety-setting parsing and request injection, and the prior implementation PR closed unmerged. The issue remains useful because maintainers must choose the safety policy, configuration ownership, precedence, and endpoint scope before implementation.

## What This Changes

Add an opt-in way to configure Gemini harm-category thresholds and pass them to Google model requests.

## Best Possible Solution

Implement an opt-in, Google-plugin-owned safety-settings contract using the existing provider/model parameter seams where possible, with strict Google enum validation, unchanged safe defaults, explicit request values taking precedence, endpoint scoping, user-facing safety documentation, and focused config plus outbound-payload tests.
