## Summary

Keep open: current main still lacks a typed Gemini safety-settings config contract and the direct Google GenerateContent payload still does not emit `safetySettings`; the prior implementation PR is closed unmerged and is context, not a viable landing path.

## What This Changes

Request to configure Gemini safety thresholds per provider or model and pass them through to Google Gemini requests.

## Best Possible Solution

Define a narrow Google-owned `safetySettings` contract, validate it in config/schema/help/docs, inject it only on the direct Google GenerateContent request path without overriding explicit request payload values, and require focused tests plus redacted live Gemini proof.

## Reproduction Assessment

Yes at source level: current main has no accepted `safetySettings` config key and the Google GenerateContent builder does not emit that request field. I did not run a live Gemini request in this read-only review.

## Solution Assessment

Unclear as proposed: provider/model config is plausible, but maintainers still need to choose the public schema, category set, threshold policy, Google-only scope, precedence, and safety posture before implementation.
