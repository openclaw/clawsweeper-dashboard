## Summary

Keep open: current main and v2026.6.11 still lack a validated Gemini safety-settings config surface and the direct Google GenerateContent request path still omits `safetySettings`; the prior implementation PR is closed unmerged, so this remains the canonical tracker.

## What This Changes

Request to let users configure Gemini safety thresholds per provider or model and pass them through to Gemini API requests.

## Best Possible Solution

Define a narrow Google-owned `models.providers.<id>.safetySettings` contract with strict category/threshold validation, generated schema/help/docs, direct Gemini request injection that preserves explicit request-level payload values, focused tests, and redacted live Gemini proof.

## Reproduction Assessment

Yes at source level, though not as a broken-behavior repro: current main has no accepted `safetySettings` config key and the direct Google GenerateContent builder does not emit that request field.

## Solution Assessment

Unclear as proposed: provider/model config is plausible, but maintainers still need to decide the public schema, category set, threshold policy, Google-only scope, and safety posture before implementation.
