## Summary

Keep open: current main and v2026.6.11 still lack a first-class Gemini `safetySettings` config contract and direct Google GenerateContent request injection, while the prior implementation PR is closed unmerged and no longer a viable landing path.

## What This Changes

The issue requests configurable Gemini safety settings at provider and/or model level so OpenClaw can pass those thresholds to Gemini requests.

## Best Possible Solution

Define a narrow Google-owned `safetySettings` contract with schema/help/docs coverage, inject it only on the direct Google GenerateContent path without overriding explicit request payload values, and require focused config/runtime tests plus redacted live Gemini proof.

## Reproduction Assessment

Not applicable as a broken-behavior reproduction, but yes at source level: current main has no accepted `safetySettings` config key and the Google GenerateContent builder does not emit that request field.

## Solution Assessment

Unclear as proposed: provider/model config is plausible, but maintainers still need to choose the public schema, supported categories, Google-only scope, precedence rules, and safety posture before implementation.
