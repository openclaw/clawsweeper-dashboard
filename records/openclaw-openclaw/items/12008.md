## Summary

Keep open. Current main still has no typed Gemini safety-settings field on a model provider and the Google request type does not include `safetySettings`; the prior implementation PR was closed unmerged, so no viable fix currently owns the work. This needs a maintainer decision on the supported configuration contract and safety-policy boundary before a new implementation is started.

## What This Changes

Add a validated, documented way for Gemini users to configure supported safety thresholds that OpenClaw sends with Google Generative AI requests.

## System Context

OpenClaw's model-provider configuration selects an API adapter and supplies runtime parameters to provider plugins. The bundled Google plugin converts agent messages into Gemini `streamGenerateContent` payloads, which then determine Google’s safety-filter behavior.

## Architecture Diagram

flowchart LR
  A[Operator configuration] --> B[Model provider schema]
  B --> C[Provider and model selection]
  C --> D[Google plugin transport]
  D --> E[Gemini request payload]
  E --> F[Google safety filtering]
  F --> G[Agent response stream]

## Best Possible Solution

Define a Google-plugin-owned, schema-validated safety-settings contract limited to documented Google Generative AI categories and thresholds, inject it only on the compatible request path while preserving explicit request-level values, and cover validation, fresh configuration, and payload precedence with focused tests and user documentation.
