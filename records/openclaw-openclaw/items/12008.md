## What This Changes

Add a schema-validated provider or model configuration for supported Gemini safety thresholds and pass it to Google Generative AI requests.

## System Context

OpenClaw resolves a configured model provider, validates its provider settings, and builds an outbound request through the matching provider adapter. Gemini safety settings would enter through the model-provider configuration and affect only the Google Generative AI request payload sent to Gemini.

## Architecture Diagram

flowchart LR
  A[Operator configuration] --> B[Provider configuration validation]
  B --> C[Resolved model provider]
  C --> D[Google Generative AI adapter]
  D --> E[Gemini request payload]
  E --> F[Gemini safety filtering]

## Best Possible Solution

Adopt a provider-owned, documented Google Generative AI safety-settings contract only if maintainers want to support operator-controlled thresholds; validate Google-supported values, inject them only on that adapter, preserve explicit per-request settings, and cover accepted/rejected configuration plus outbound-payload behavior.
