## Summary

Keep open: current main still lacks a typed Gemini safety-settings config surface and the Google GenerateContent request builder still emits payloads without `safetySettings`; the previous implementation PR is closed unmerged, so no viable open fix path currently owns the work.

## What This Changes

The issue requests optional Gemini safety settings in provider or model configuration and mapping those thresholds into Google Gemini requests.

## Best Possible Solution

Keep this as the canonical tracker and have maintainers sponsor a focused Google-provider implementation with schema/help/docs coverage, strict category/threshold validation, direct Gemini request injection, precedence tests, and live or redacted payload proof.

## Reproduction Assessment

Yes by source inspection: the strict provider schema has no `safetySettings` key and the Google GenerateContent payload type/builder omits it. A live Gemini request was not run in this read-only review.

## Solution Assessment

Unclear until maintainers choose the config contract. The current best direction is a narrow Google-owned provider field with validation, docs, tests, and request injection that preserves explicit per-request payload precedence.
