## Summary

Keep open: current main and v2026.6.11 still lack a first-class Gemini `safetySettings` config contract or Google GenerateContent request injection, and the prior implementation PR is closed unmerged rather than a viable fix path.

## What This Changes

Request to add provider/model-level Gemini safety settings configuration and map it into Google Gemini requests.

## Best Possible Solution

Define a narrow Google-owned `safetySettings` config contract, validate and document it with generated config/help coverage, inject it only on the direct Google GenerateContent path without overriding explicit request payload values, and require focused tests plus redacted live Gemini proof.

## Reproduction Assessment

Yes, at source level: current main has no accepted `safetySettings` config key and the Google GenerateContent builder does not emit that request field. I did not run a live Gemini request in this read-only review.

## Solution Assessment

Unclear as proposed: provider/model config is plausible, but maintainers still need to choose the public schema, category set, threshold policy, Google-only scope, precedence, and safety posture before implementation.
