## Summary

Keep open: current main and the latest release still lack the requested natural-language inbound reply-in-thread suffix directive, and the only direct implementation attempt is closed unmerged. This remains a product-direction question around trigger vocabulary, default behavior, and reply-mode override semantics.

## What This Changes

Request to add an inbound message suffix directive such as `reply in thread` or `rit` that strips the suffix before the agent sees it and forces the reply to target the inbound message thread.

## Best Possible Solution

Define a maintainer-approved per-message reply override contract, then implement one narrow shared inbound directive or plugin/API seam with regression coverage for prompt stripping and supported threaded channels.
