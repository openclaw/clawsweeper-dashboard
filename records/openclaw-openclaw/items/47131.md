## Summary

Keep open: current main and the latest release still lack the requested inbound natural-language reply-in-thread suffix directive, the direct implementation PR is closed unmerged, and the remaining choice is cross-channel product behavior rather than a narrow bug fix.

## What This Changes

The issue requests a built-in inbound message directive that strips suffixes such as `reply in thread` or `rit` and forces the assistant response to reply to the triggering message thread.

## Best Possible Solution

Define a maintainer-approved per-message reply override contract, then implement a narrow shared inbound directive or plugin/API seam with prompt stripping, reply-mode precedence, docs, and regression coverage.
