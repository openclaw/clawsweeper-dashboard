## Summary

Keep open: current main still lacks a built-in inbound natural-language reply-in-thread suffix, and the remaining choice is product behavior for cross-channel trigger words and reply-routing precedence.

## What This Changes

The issue requests inbound preprocessing that detects suffixes like `reply in thread` or `rit`, strips them before the agent sees the message, and forces the outbound reply to target the inbound message thread.

## Best Possible Solution

Define a narrow reply-in-thread directive contract first, then implement it with safe trigger words, cross-channel precedence, docs, and regression plus channel proof.
