## Summary

Keep open: current main and v2026.6.11 still lack the requested natural-language inbound reply-in-thread suffix directive. The only direct implementation attempt is closed unmerged, and the remaining blocker is maintainer product direction around trigger vocabulary, defaults, and reply-mode override behavior.

## What This Changes

Add a built-in inbound directive so suffixes like `reply in thread` or `rit` are stripped before the model sees the message and force the outbound reply to thread to the inbound message.

## Best Possible Solution

Define a maintainer-approved per-message reply override contract, then implement one narrow shared inbound directive or plugin/API seam with regression coverage for prompt stripping and supported threaded channels.
