## Summary

Keep open: current main still supports outbound reply tags and replyToMode controls, but it does not implement inbound `reply in thread`/`rit` phrase preprocessing. The remaining blocker is product direction for trigger phrases and cross-channel reply precedence, not missing implementation effort alone.

## What This Changes

Request adds a built-in inbound directive that detects and strips trailing phrases such as `reply in thread` or `rit` and forces the outbound response to reply to the triggering message.

## Best Possible Solution

Define a narrow inbound directive contract first: supported phrases, BodyForAgent stripping, replyToMode precedence, per-channel differences, and whether any config surface is allowed.
