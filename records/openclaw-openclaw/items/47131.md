## Summary

Keep open: current main and the latest release still do not implement a natural-language inbound reply-in-thread suffix such as `rit`, and the direct implementation attempt is closed unmerged; this needs product direction before core owns global trigger vocabulary and reply override semantics.

## What This Changes

The issue requests a built-in inbound directive that strips suffixes such as `reply in thread` or `rit` from user messages and forces the next response to reply to the triggering message.

## Best Possible Solution

Define one maintainer-approved per-message reply override contract, then implement either a narrow shared inbound directive or a typed command/action seam with regression coverage for prompt stripping and supported threaded channels.
