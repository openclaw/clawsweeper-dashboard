## Summary

Keep open: current main and v2026.6.11 still support explicit outbound reply tags and configured reply modes, but not the requested natural-language inbound suffix directive; the remaining blocker is maintainer product direction for global trigger vocabulary and cross-channel reply-routing semantics.

## What This Changes

Request to add a built-in inbound directive that strips suffixes such as `reply in thread` or `rit` from user messages and forces the response to reply to the inbound message/thread.

## Best Possible Solution

Define a maintainer-approved per-message reply override contract, then implement a narrow shared inbound directive or plugin/API seam with prompt stripping, reply-mode semantics, docs, and regression coverage.
