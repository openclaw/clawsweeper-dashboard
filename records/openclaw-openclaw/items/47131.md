Keep open: current main and the latest release still do not implement a built-in natural-language inbound reply-in-thread suffix directive, and the remaining question is product direction rather than missing proof of an existing bug.

## What This Changes

Request to add a built-in inbound suffix directive that strips phrases like `reply in thread` or `rit` and forces the response to reply to the current inbound message.

## Best Possible Solution

Define a maintainer-approved per-message reply override contract, then implement a narrow shared inbound directive or plugin/API seam with prompt-stripping, reply-mode semantics, docs, and regression coverage.
