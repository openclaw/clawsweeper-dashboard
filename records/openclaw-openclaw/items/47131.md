## Summary

Keep open: current main and the latest release still do not implement the requested inbound `reply in thread` or `rit` suffix, the direct implementation PR is closed unmerged, and the remaining question is a cross-channel product decision about global trigger syntax and reply override semantics.

## What This Changes

The issue requests a built-in inbound natural-language directive that strips trailing phrases such as `reply in thread`, `rit`, `thread`, or `in thread` from user messages and forces the next response to reply to the triggering message.

## Best Possible Solution

Define one maintainer-approved per-message reply override contract, then implement either a narrow shared inbound directive or a typed command/action seam with regression coverage for prompt stripping and supported threaded channels.
