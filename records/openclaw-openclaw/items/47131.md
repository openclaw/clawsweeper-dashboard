## Summary

Keep open: current main and the latest release still lack the requested natural-language inbound reply-in-thread suffix directive, and the direct implementation attempt is closed unmerged. The remaining question is product direction around trigger vocabulary, default behavior, and how a forced inbound reply override should interact with existing reply modes.

## What This Changes

Request to add a built-in inbound message suffix directive such as `reply in thread` or `rit` that strips the suffix from the agent prompt and forces the response to reply to the inbound message.

## Best Possible Solution

Define a maintainer-approved per-message reply override contract, then implement one narrow shared inbound directive or explicit plugin/core seam with regression coverage for prompt stripping and supported threaded channels.
