## Summary

This PR targets a plausible recovery gap, but the linked incident never establishes that the phantom reply operation was terminal, and the new phase-only force-clear can reclaim intentionally retained terminal work before its settle window. The supplied proof exercises phase lookup and mocked recovery rather than the changed recovery branch with a real reply-operation lifecycle.

## What This Changes

The PR makes stuck-session recovery abort and drain reply operations whose registry phase is completed, failed, or aborted, with parameterized recovery tests for those phases.

## Best Possible Solution

Define phantom reply work from authoritative registry ownership, active-handle presence, progress evidence, and operation age; reclaim only after the relevant settle interval, then prove both the real orphan recovery and preservation of legitimate terminal delivery.
