## Summary

This is a valid candidate fix for a P1 stuck-session bug, but the unchanged head still measures the terminal settle guard from session age rather than the terminal transition, so a long-running operation can be reclaimed immediately after entering a terminal phase; the supplied recovery output also remains test-harness evidence rather than a non-test Gateway recovery.

## What This Changes

The PR changes stuck-session recovery to reclaim terminal-phase and no-progress reply operations and adds runtime and integration regression coverage.

## Best Possible Solution

Record or expose the reply operation’s terminal-transition timestamp, apply the settle timeout to that clock, preserve the existing stale-progress fallback for genuinely inactive running operations, and prove recovery plus queued delivery in a redacted non-test Gateway run.
