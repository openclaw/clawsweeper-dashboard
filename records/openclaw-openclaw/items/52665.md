Request adding APT retry handling and `--fix-missing` to the sandbox-common Docker image package install path to reduce transient-network build failures.

Land or replace the linked PR with retry-only `Acquire::Retries` handling that keeps package installation fail-closed, unless maintainers explicitly accept `--fix-missing` with package-presence verification.

Question: Should the sandbox Dockerfile fix be retry-only, or should OpenClaw intentionally accept `--fix-missing` partial-install semantics for these images?

Rationale: `Acquire::Retries` directly addresses transient APT fetch failures, while `--fix-missing` can allow requested sandbox packages to be held back after retrieval or integrity failures; that changes the build contract and needs maintainer intent.

- **Accept partial-install behavior:** Keep `--fix-missing` only if maintainers intentionally want builds to proceed after missing packages and require package-presence verification or documentation for that contract.
- **Replace the linked branch:** If the linked PR is not revised with proof, keep this issue open and use a narrower retry-only replacement as the landing path.

Yes for the source gap: current main and v2026.6.11 both lack APT retry handling in the sandbox Dockerfiles. No for a live intermittent-network reproduction; this read-only review did not run a flaky Docker build scenario.

## Solution Assessment

No as written. Retry options are the narrow maintainable fix for transient APT fetch failures, but `--fix-missing` should be removed or explicitly accepted with verification because it can hold back required packages.
