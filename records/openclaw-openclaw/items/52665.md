## Summary

Keep open: current main and the latest release still lack sandbox APT retry handling, and the open linked PR remains the active implementation candidate rather than a merged fix.

## What This Changes

The issue requests adding APT retry and `--fix-missing` behavior to the sandbox common Docker build to reduce transient network build failures.

## Best Possible Solution

Land a retry-only or explicitly maintainer-approved Dockerfile change through the linked PR or a replacement, preserving fail-closed package installation and adding inspectable build plus package-presence proof.

## Reproduction Assessment

Yes for the source gap: current main and `v2026.6.11` both lack APT retry handling in the sandbox Dockerfiles. No for the live flaky-network failure, because this read-only review did not run a failing Docker build under network fault conditions.

## Solution Assessment

No as requested: `Acquire::Retries` is the narrow maintainable part, but `--fix-missing` changes package-install failure semantics unless maintainers intentionally accept that contract. A retry-only change with build and package-presence proof is the safer default path.
