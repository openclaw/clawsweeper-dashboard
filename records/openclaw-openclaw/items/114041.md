## Summary

This PR addresses a real Google Gemini TTS corruption path with the repository’s shared base64 validator rather than a parallel parser. The updated body supplies a provider-boundary before/after transcript showing the real synthesis path retries once and then rejects malformed audio, so the prior proof gap appears resolved; no discrete patch defect was found in the submitted two-file change.

## What This Changes

The PR makes the bundled Google Gemini text-to-speech provider reject malformed base64 audio instead of turning it into a structurally valid but corrupted WAV file, and adds regression coverage for the retry-and-fail behavior.

## System Context

The Google extension receives Gemini `generateContent` responses and extracts PCM audio before OpenClaw returns a WAV file or transcodes a voice note. This change sits at the network-response decoding boundary, preventing corrupted provider payloads from reaching the audio-output path.
