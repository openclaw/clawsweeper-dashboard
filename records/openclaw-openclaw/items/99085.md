## Summary

Close as ClawHub/plugin-routed work: the request is an optional full-page extraction mode, while current core `web_fetch` is intentionally bounded and existing plugin/tool seams can host a custom extractor without adding core surface. The overlapping `web_fetch` body-extraction bug is already tracked separately by the canonical issue and open fix PR.

## What This Changes

The issue requests a full-page `extract_content` mode that avoids truncating long articles and includes image captions.

## Best Possible Solution

Keep core `web_fetch` bounded, route richer full-page/caption extraction to a ClawHub plugin or existing Firecrawl/Tavily-style plugin tools, and let the separate body-extraction bug finish through https://github.com/openclaw/openclaw/issues/82685 and https://github.com/openclaw/openclaw/pull/89028.

## Reproduction Assessment

Not as a bug: the issue provides no URL, article, or expected/actual caption example to reproduce. Source inspection confirms current `web_fetch` is deliberately bounded by `maxChars`, so the requested no-truncation/full-caption behavior is a new feature direction.

## Solution Assessment

No for OpenClaw core: VISION.md and AGENTS.md route optional extraction capabilities to plugins when current seams suffice. A ClawHub plugin or existing Firecrawl/Tavily-style plugin tool is the narrower maintainable path unless a concrete missing plugin API is identified.
