## Summary

This PR should stay open for repair: its main behavior is well-proven, but current main intentionally permits a valid effective reasoning level to be absent from the selectable picker options, and the proposed Android fallback silently replaces that level before the next send.

## What This Changes

The PR makes Android chat consume Gateway-provided thinking options and effective state, updates them after model changes, renders a dynamic inline selector, and adds focused controller and UI tests.

## Best Possible Solution

Keep the Gateway-reported effective level as Android's active and send state even when it is not selectable, restrict only user-initiated changes to advertised options, and retain the older-Gateway fallback.
