## What This Changes

The issue reports that rebrand-style text replacement rewrites legacy product names inside path/tool-bearing text, causing file operations to target a current-name directory instead of the intended legacy workspace.

## Best Possible Solution

Review the linked candidate as context, then land a maintainer-sponsored target-repo fix that preserves cosmetic/non-functional replacements while preventing path or tool-bearing text from silently changing filesystem targets, with regression coverage, docs/API notes, and dual-directory proof.

Rationale: The same API currently serves cosmetic rebrand shims, privacy/entity restoration, CLI prompt shaping, and provider structured tool-call argument restoration, so an automated repair cannot safely choose the contract boundary without maintainer intent.

Options:

- **Define path-safe transform scopes (recommended):** Keep text transforms for prompt/display/entity restoration, but add an explicit path/tool-bearing safety rule plus tests and documentation for when replacements do not run.

- **Replace with explicit plugin hooks:** Deprecate broad text transforms for executable payloads and move tool/persistence rewriting into narrower hooks, accepting a larger Plugin SDK design pass.
