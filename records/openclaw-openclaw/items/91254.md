## What This Changes

The issue asks OpenClaw to stop blind rebrand/plugin text substitutions from rewriting filesystem-path tool-call arguments and masking the misrouting in output.

## Best Possible Solution

Land a maintainer-sponsored fix that preserves cosmetic text transforms while exempting path/tool-bearing arguments by default or making argument rewriting explicit, with docs, regression coverage, and live dual-directory proof.

Question: Should plugin text transforms be allowed to rewrite structured tool-call argument strings, or should path/tool-bearing arguments be exempt by default with any rewrite opt-in?

Rationale: This choice defines public plugin/backend text-transform semantics and trades off privacy/terminology transform coverage against silent filesystem misrouting and user data loss.

Likely owner: steipete

Owner reason: `steipete` introduced the text-transform surface and is the strongest current history signal for choosing the durable plugin/runtime boundary.

Owner confidence: high

Options:

- **Exempt path/tool-bearing arguments by default (recommended):** Keep cosmetic prompt/output transforms but skip filesystem-looking tool argument strings unless a narrower, explicit API opts into argument rewriting.
- **Keep current argument transform semantics:** Preserve broad plugin transform power and require plugins or `before_tool_call` hooks to avoid unsafe path rewrites themselves.
- **Design a new transform scope contract:** Add explicit transform scopes for prompt, display, structured arguments, and persistence before changing runtime behavior.

Source-reproducible, but not live end-to-end. Current main's helper will rewrite a path string such as `~/openclaw/data` under a matching replacement, and current stream wrappers apply output transforms to structured tool-call arguments; the exact macOS/Signal dual-directory report still needs live proof.

## Solution Assessment

Unclear pending maintainer direction. A path-aware or no-tool-argument rewrite guard is safer than the current blind helper, but maintainers need to choose how it interacts with plugin text-transform contracts and `before_tool_call` hooks.
