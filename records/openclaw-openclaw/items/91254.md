## Summary

Keep open: current main still uses blind text replacements and applies output transforms to structured tool-call arguments before execution, with no path-aware or opt-out fix. ## What This Changes

The issue requests preventing plugin/rebrand text transforms from silently rewriting filesystem path strings in tool-call arguments and related I/O.

## Best Possible Solution

Define and land a maintainer-approved transform boundary that preserves cosmetic display/prompt transforms while preventing executable path and tool arguments from silent brand rewrites, with regression coverage and dual-directory real behavior proof.

Options:

- **Define path/tool-safe transform boundary (recommended):** Keep cosmetic prompt/display replacements but skip or explicitly gate replacements for executable filesystem paths and tool arguments, then document and test that boundary.
- **Preserve broad transform semantics:** Treat all string-bearing tool arguments as valid transform targets and close this as accepted risk after documenting the operator hazard.
- **Require explicit plugin-owned policy:** Move executable argument rewriting behind an explicit plugin hook or opt-in mode so each plugin owns whether its transforms may mutate tool inputs.
