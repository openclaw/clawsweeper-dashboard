## Summary

Keep open: current main still uses blind text replacement and now explicitly applies output transforms to structured tool-call arguments, so the path-misrouting concern remains source-reproducible and needs a maintainer decision on the plugin text-transform boundary.

## What This Changes

The issue asks OpenClaw to stop rebrand text transforms from silently rewriting filesystem paths in tool-call arguments, or to make that transform path-aware with diagnostics/recovery.

## Best Possible Solution

Land a maintainer-sponsored fix that preserves intended text-transform use cases while preventing filesystem-path tool arguments from being blindly rewritten, with regression tests and live dual-directory proof.
