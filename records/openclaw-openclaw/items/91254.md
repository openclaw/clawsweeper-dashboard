## Summary

Keep open: current main still uses blind text replacement for configured transforms, and current main now explicitly applies output transforms to structured tool-call argument values without a path-aware guard. ## What This Changes

The issue requests preventing rebrand/plugin text substitutions from blindly rewriting filesystem path and tool-call argument strings, which can send file operations to a renamed sibling directory.

## Best Possible Solution

Land a maintainer-sponsored path/tool-argument-safe text-transform policy that preserves intended masking/cosmetic transforms while preventing filesystem path strings from being silently rewritten, with regression coverage and dual-directory proof.

Options:

- **Path-aware transform boundary (recommended):** Keep tool-call argument transforms enabled, but skip or constrain replacements in filesystem-path contexts with tests and clear docs for plugin authors.
- **Owner-declared transform scopes:** Require plugin/backend transforms to declare whether they apply to conversational text, tool arguments, or persistence surfaces, avoiding heuristic path detection at the cost of a larger API change.
- **Disable argument transforms by default:** Stop applying text transforms to tool-call arguments unless explicitly opted in, reducing path risk but potentially regressing current masking/privacy plugin behavior fixed by the recent merged change.
