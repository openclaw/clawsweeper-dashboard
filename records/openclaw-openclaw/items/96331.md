## Summary

Keep this open: the issue is a concrete WebChat session-continuity bug, current main does not provide high-confidence proof that the page-load/restart case is fixed, and the linked open pull request is the active candidate implementation rather than a reason to close the issue first.

## What This Changes

WebChat should preserve the model-visible session context on `chat.send` after restart or page reload when `chat.history` displays the same prior session history.

## Best Possible Solution

Repair, approve, or replace the linked candidate PR with a narrow session-resume implementation that lets the first verified restored WebChat send keep context while preserving configured idle/daily rollover for ordinary sends.

Rationale: The report is a real session-continuity bug, but current main and tests deliberately keep ordinary `sessionId` sends subject to freshness rollover, so the permanent WebChat session policy needs maintainer intent before the issue can close.

Options:

- **One-shot resume exception (recommended):** Keep configured rollover behavior for ordinary sends and allow only the first verified post-reconnect or page-load continuation to reuse the displayed session.
- **Visible session overrides rollover:** Treat any displayed WebChat session as authoritative and accept that WebChat can continue sessions past configured idle/daily freshness boundaries.
- **Explicit stale-session UX:** Do not auto-continue stale visible sessions; add UI disclosure or a restore action when history is visible but rollover would create a new session.

Yes at source level, but not with a live provider run in this review. Current main records the `chat.history` session id and sends it back, while `initSessionState` only lets a private one-shot resume marker bypass freshness rollover.

## Solution Assessment

Not yet. The reported behavior should be fixed, but the best implementation should preserve configured idle/daily rollover while allowing the intended first restored WebChat send to keep model-visible context.
