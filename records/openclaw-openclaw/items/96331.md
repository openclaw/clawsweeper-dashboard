## Summary

Keep open. Current main still has a source-visible split where WebChat history can load a stored session while `chat.send` does not pass the backing session id into session freshness handling; the open closing PR at https://github.com/openclaw/openclaw/pull/96391 owns the active fix path.

## What This Changes

Ensure WebChat `chat.send` preserves the same persisted session context that `chat.history` displays after a gateway, browser, or machine restart.

## Best Possible Solution

Review, update, and land the linked Gateway/session PR so WebChat can continue the displayed stored session after restart while preserving `/new`, `/reset`, idle reset, and daily reset semantics; then close this issue after the merge.
