## Summary

Keep open: the current head does not yet satisfy the central preinstalled-skill use case because its name-only snapshot omits the sandbox-readable location that agents need to load each `SKILL.md`; the permanent product boundary and convincing live proof also remain unresolved.

## What This Changes

Adds an opt-in Docker sandbox setting that skips skill synchronization, emits a name-only skill snapshot, guards command-prompt inspection, and updates configuration metadata, tests, generated baselines, and sandbox documentation.

## Best Possible Solution

Make skill materialization an explicit sandbox/backend-owned capability that returns a verified sandbox-readable skill inventory, then build the ordinary prompt snapshot with real descriptions, versions, and locations while preserving synchronization as the default.
