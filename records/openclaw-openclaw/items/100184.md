## What This Changes

The PR adds an optional `skipSkillsSync` sandbox config boolean, resolves it into sandbox runtime config, guards both sandbox skill sync call sites, and adds mocked tests for read-only and writable workspaces.

## Best Possible Solution

Land this only after sandbox owners approve the config or backend-capability shape, the implementation preserves prompt/read-tool skill availability when copying is skipped, and public config docs plus real sandbox proof are included.

## Reproduction Assessment

Yes for the review concern: source inspection shows the new guard skips the helper that computes sandbox skill eligibility, while CLI and embedded runs use that eligibility for skill prompt/read behavior. The original overhead claim remains a feature request and was not measured here.

## Solution Assessment

No; the PR is a plausible opt-out, but it is not yet the best solution because it couples copy suppression to loss of eligibility/prompt inputs. A safer fix would separate eligibility computation from file copying or make the backend preinstalled-skill contract explicit.
