## Summary

Keep this PR open as the candidate for the linked feature request, but do not merge the current head: its name-only catalog advertises preinstalled skills without telling the agent where to read their instructions, the command inspection path suppresses them entirely, and the public config boundary still needs sandbox-owner approval.

## What This Changes

Adds an opt-in Docker sandbox configuration setting that skips skill synchronization, constructs a name-only skill snapshot, guards command-prompt inspection, and updates config metadata, tests, generated baselines, and sandbox documentation.

## Best Possible Solution

Model externally provisioned skills as a sandbox-backend capability that supplies canonical container-readable SKILL.md locations; add a public config knob only if maintainers intentionally accept that contract, and prove a real agent can use the skills across fresh and repeated setup.
