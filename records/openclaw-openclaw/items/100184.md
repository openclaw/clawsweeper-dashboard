## Summary

This PR remains useful but is not merge-ready: the latest head addresses the earlier missing-location finding, yet the option still crosses the Docker/backend ownership boundary and assumes a fixed preinstalled-skill path without making that path part of the operator contract. The linked feature request remains open for product direction.

## What This Changes

Adds `agents.*.sandbox.docker.skipSkillsSync`, skips sandbox skill materialization when enabled, generates prompt entries for presumed preinstalled skills, and updates config metadata, tests, and sandbox documentation.

## Best Possible Solution

Have the selected sandbox backend explicitly report whether it provides skills and the sandbox-readable skill root, then let core skip materialization and build prompt locations from that prepared fact; add a public boolean only if maintainers deliberately prefer that broader contract, and prove fresh plus reused sandbox behavior.
