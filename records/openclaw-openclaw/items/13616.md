## Summary

Keep open: current main and v2026.6.11 still expose local backup archive create/verify only, while the requested native restore/import/list/cloud/encryption/scheduled workflow and component-aware cron/session restore semantics remain unresolved.

## What This Changes

The issue requests first-party backup/restore commands for OpenClaw config, cron jobs, workspace files, sessions, cloud storage, encryption, scheduling, and disaster recovery.

## Best Possible Solution

Keep this as the native backup lifecycle umbrella until maintainers define and land a security-reviewed first-party restore/import contract, with optional cloud and scheduled integrations routed through plugin or ClawHub surfaces unless core APIs are missing.

Owner confidence: medium

Options:

- **Scope Native Restore First (recommended):** Define a minimal core restore/import lifecycle for OpenClaw-owned archives with safe extraction, dry-run validation, conflict and rollback rules, and explicit cron/session component semantics, while leaving cloud and scheduled sync to plugins unless a missing API is identified.
- **Move Most Scope To ClawHub:** Close or narrow the core issue if maintainers decide community plugin and skill backup flows are sufficient and only docs or plugin APIs should remain in OpenClaw core.
- **Design A Full Core Backup Platform:** Accept a broader core design that includes cloud targets, encryption, scheduling, retention, and restore, with a larger security and compatibility review before implementation.
