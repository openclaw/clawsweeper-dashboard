## Summary

Keep open: current main and v2026.6.11 still provide first-party local backup archive creation and verification only. Native restore/import/export/list/cloud/encryption/scheduled backup plus component-aware cron and session-history restore remain unresolved, while community tools and open docs work cover only parts of the request.

## What This Changes

Requests built-in backup, export, import, restore, listing, cloud storage, encryption, scheduling, and selective config/cron/session/workspace backup support.

## Best Possible Solution

Keep this as the native backup lifecycle umbrella, build on the existing create/verify archive format, and split implementation into maintainer-approved restore/import safety, component modeling, transcript/cron snapshot policy, and plugin-bound cloud/encryption decisions.

Options:

- **Core Local Restore First (recommended):** Define and implement local manifest-driven restore/import with dry-run, conflict handling, rollback, and explicit secret/session policy, leaving cloud scheduling to plugins until the core contract is stable.
- **Full Native Backup Platform:** Treat cloud storage, encryption, scheduling, retention, and component merge semantics as first-party OpenClaw CLI scope, accepting a broader security and maintenance surface.
- **Plugin-Led Cloud Backup:** Keep first-party core to archive create/verify and extension APIs, while routing cloud backup/restore UX through vetted ClawHub plugins unless a missing core API is identified.
