- `P2`: The request covers important production recovery and migration work, but it is broad feature design rather than an urgent broken core-runtime regression.

## Summary

Keep open: current main and the latest release still provide local backup creation and verification, while native restore/import/list/cloud/encryption/scheduled backup and component-aware cron/session recovery remain unresolved and security-sensitive.

## What This Changes

Request a built-in backup/restore lifecycle for OpenClaw config and state, cron jobs, session history, cloud storage, encryption, scheduling, and disaster recovery.

## Best Possible Solution

Keep this as the native umbrella for a maintainer-sponsored backup lifecycle built on the existing create/verify archive path, with scoped follow-ups for safe restore, transcript policy, cron semantics, cloud/encryption boundaries, and docs that point to community tools as optional workarounds.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature request. Source and docs give a high-confidence feature-gap check because current main and v2026.6.11 expose backup create/verify only.

## Solution Assessment

Unclear until maintainers define the restore safety model. A first-party core restore lifecycle is plausible for local state, but cloud/scheduled backup, retention, and encryption need explicit core-versus-plugin boundaries.
