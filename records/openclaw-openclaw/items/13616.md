## Summary

Keep open: current main and v2026.6.11 provide a hardened first-party local archive create/verify workflow, but the central native restore/import lifecycle remains absent. The remaining work requires an explicit product and security decision because restoration can destructively replace configuration, credentials, cron state, sessions, workspaces, and SQLite-backed state; community backup plugins are useful alternatives but do not settle the intended first-party recovery contract.

## What This Changes

Requests a first-party backup and restore lifecycle for configuration, cron jobs, workspaces, sessions, encryption, scheduling, and cloud storage.

## Best Possible Solution

Define a first-party local restore contract over the existing verified archive format with versioned manifests, staged extraction, dry-run validation, pre-restore snapshots, atomic commit or rollback, explicit secret and permission policy, and component-aware cron/session handling; keep cloud storage, recurring schedules, retention, and provider-specific encryption in plugins unless a concrete core extension gap is found.

## Risks / Open Questions

- A native restore command could overwrite or mis-associate configuration, credentials, cron jobs, sessions, workspaces, plugin data, and SQLite state unless staging, conflict, rollback, ownership, and version-compatibility rules are explicit.
- Archive extraction introduces hostile-input concerns including traversal, links, permissions, ownership, oversized payloads, incompatible manifests, and restoration of secret-bearing state.
- The umbrella mixes a core local recovery contract with optional scheduling, retention, encryption-key management, and cloud-provider integrations that existing plugins can own, so implementing the whole proposal in core would conflict with the lean-core boundary.
- Related open work such as https://github.com/openclaw/openclaw/issues/63392 and https://github.com/openclaw/openclaw/pull/86971 may diverge unless maintainers define one canonical restore format and lifecycle first.
