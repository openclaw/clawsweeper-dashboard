## Summary

Current main still has a real interrupted-turn classification defect: when a native command has no terminal result, the synthesized invariant error can override abort semantics and make the run fail, although ordinary failed Codex turns already preserve their real error. Keep this issue open as the focused tracker for interrupted and aborted projector behavior; the unexpected TUI client-shutdown trigger remains separately tracked.

## What This Changes

Preserve the correct Codex interrupted or aborted outcome and usable assistant output when a turn ends with an unfinished native command, while retaining fail-closed tool-result proof.

## Best Possible Solution

Keep synthetic failed `tool.result` records for transcript integrity, but do not promote `missing_tool_result` to the run's prompt error when the authoritative outcome is interrupted or externally aborted; retain it as structured tool-failure detail, preserve any completed assistant text, and leave TUI shutdown policy to the related lifecycle issue.
