## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Filter voice-state packets per bot account:** `extensions/discord/src/voice/manager.ts:576`
  - body: This adds per-account @discordjs/voice groups, but the adapter path is still guild-only: `VoicePlugin.adapters` stores one adapter per guild and `dispatchVoiceGatewayEvent` forwards every guild VOICE_STATE_UPDATE to it. With two bot accounts in one guild, the later adapter can receive the other bot's voice-state packet; @discordjs/voice stores that packet and uses its session/user fields for networking, so the join can stick before Ready or bind the wrong session. Scope the adapter by account/bot user and ignore voice-state packets whose `user_id` is not the owning bot before calling `onVoiceStateUpdate`.
  - confidence: 0.93
- **[P2] Await or cancel lifecycle auto-join:** `extensions/discord/src/monitor/provider.lifecycle.ts:524`
  - body: The lifecycle path still starts `autoJoin()` fire-and-forget, then can immediately enter `finally` and call `voiceManager.destroy()` without waiting for the join task. Because `joinUnlocked` can create the voice connection before it notices `this.destroyed`, shutdown can leave a real voice join in progress until Ready or timeout. Await the task, gate it on the abort signal, or cancel it before destroying the manager.
  - confidence: 0.88
