## Summary

Keep open: the underlying Discord voice bug is still real and the account-group fix is useful, but this head starts already-ready autoJoin before lifecycle cleanup owns the voice manager, which can leave voice sessions alive after a later startup failure.

## What This Changes

The PR scopes Discord voice lookup/join/cleanup through account-derived @discordjs/voice groups and adds an already-connected gateway autoJoin path, with focused tests and a changelog entry.

## Best Possible Solution

Keep the account-scoped group isolation, but make already-ready autoJoin lifecycle-owned or explicitly destroy and clear the voice manager on pre-lifecycle failure, then add current-head real/log proof for multi-account voice behavior.
