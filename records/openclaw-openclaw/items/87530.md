- `P1`: The PR targets a broken Discord voice account/autojoin workflow that can affect real multi-account users and startup reliability.

## Summary

Keep open: the account-scoped voice group change matches the `@discordjs/voice` contract, but the latest head still starts READY catch-up autoJoin before lifecycle cleanup owns the voice manager, and current-head real behavior proof is still mock/test-only.

## What This Changes

The PR scopes Discord voice connections by account-specific `@discordjs/voice` groups, adds an already-ready gateway autoJoin catch-up, updates Discord voice/provider tests, and adds a changelog entry.

## Best Possible Solution

Keep the account-scoped voice group change, but move already-ready autoJoin into lifecycle-owned startup or explicitly destroy and clear the voice manager on pre-lifecycle failures, then add regression coverage and current-head real Discord proof.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path for the reported bug: current main and v2026.6.11 call `@discordjs/voice` without a group while the dependency defaults to the process-global `default` group, and current provider startup only calls autoJoin through later READY/RESUMED listeners. I did not run a live Discord two-account setup in this read-only review.

## Solution Assessment

No: the account-grouping half is the right narrow fix, but the current READY catch-up is not the best cleanup boundary because it runs before lifecycle owns voice-manager teardown. The safer fix is to start catch-up inside lifecycle-owned startup or add explicit pre-lifecycle voice-manager cleanup.
