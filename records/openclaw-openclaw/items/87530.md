Full review comments:

- **[P1] Filter voice-state packets to the owning bot:** `extensions/discord/src/voice/manager.ts:576`
  - body: This adds an account-specific @discordjs/voice group, but the custom adapter still forwards every guild `VOICE_STATE_UPDATE` to the connection. @discordjs/voice stores whichever packet it receives as the connection state and uses that packet's `user_id/session_id` for networking, so another bot in the same guild can satisfy this connection with the wrong state; carry the bot user id into the adapter and only call `onVoiceStateUpdate` for that account.
  - confidence: 0.9
- **[P2] Wait for lifecycle auto-join before cleanup:** `extensions/discord/src/monitor/provider.lifecycle.ts:523-524`
  - body: The new already-ready path starts `autoJoin()` fire-and-forget, then `finally` can destroy the manager immediately on gateway wait failure. `destroy()` does not wait for active join tasks, and `joinUnlocked` can still create a voice connection after an awaited fetch, so shutdown can leave a connection attempt alive until the connect timeout; await or cancel this task before cleanup destroys the manager.
  - confidence: 0.82
