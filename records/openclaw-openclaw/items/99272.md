## Summary

Keep open: current `main` still has the source-level Codex watchdog gaps described here, and the protected `maintainer` label means this should not be closed by conservative cleanup. The native-tool attempt-idle abort path is source-reproducible, while the broader open-request and wall-clock-ceiling behavior needs maintainer policy alignment with adjacent timeout trackers.

## What This Changes

The issue asks to make Codex app-server turn watchdogs share consistent defer guards for active work, add an absolute per-turn ceiling, avoid counting unknown notifications as progress, and make blocker lifecycle tracking robust to out-of-order events.

## Best Possible Solution

Keep this as a maintainer-owned Codex watchdog bug: fix blocker-aware attempt-idle behavior and out-of-order blocker tracking, then align the wall-clock/open-request policy with the existing timeout trackers before changing broader liveness semantics.

## Reproduction Assessment

Yes, at source level: an active native tool can be tracked as a completion blocker while `fireAttemptIdleTimeout` still aborts without checking blocker state, and the blocker tracker lacks completed-id memory for out-of-order lifecycle events. I did not run a live Codex turn in this read-only pass.

## Solution Assessment

Partly. Adding blocker-aware attempt-idle deferral and completed-id tracking is the narrow maintainable fix, but applying the same rule to all in-flight requests and adding an absolute wall-clock ceiling requires maintainer policy alignment with existing timeout behavior.
