## What This Changes

The issue requests consistent Codex app-server watchdog deferral, an absolute turn ceiling, narrower notification progress accounting, and completed-id memory for completion blockers.

## Best Possible Solution

Keep this as a maintainer-owned Codex watchdog bug: fix blocker-aware attempt-idle behavior and out-of-order blocker tracking, then decide the wall-clock and active-request policy consistently with existing timeout trackers.

## Reproduction Assessment

Yes, at source level: current main still allows an active native tool to be tracked as a completion blocker while `fireAttemptIdleTimeout` can abort without checking blocker state, and the blocker tracker lacks completed-id memory for out-of-order lifecycle events. I did not run a live Codex turn in this read-only pass.

## Solution Assessment

Partly. Adding blocker-aware attempt-idle deferral and completed-id tracking is the narrow maintainable fix, but extending the same rule to all in-flight requests and adding an absolute wall-clock ceiling requires maintainer policy alignment.
