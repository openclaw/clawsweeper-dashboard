## Summary

Keep open. Current main and the latest release still hardcode the lane wait diagnostic default and do not expose `diagnostics.laneWaitWarnMs`; the open linked implementation PR is the active fix candidate but has not merged.

## What This Changes

The issue requests a configurable lane wait diagnostic warning threshold so long-running cron or lane work can avoid repeated non-actionable `lane wait exceeded` log warnings.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/86676 with a narrow `diagnostics.laneWaitWarnMs` implementation that preserves the current 2,000 ms default, respects explicit per-entry overrides, updates schema/types/help/docs/generated config surfaces, and proves runtime config reload behavior.

## Reproduction Assessment

Yes. Source inspection shows the queue default is still `opts?.warnAfterMs ?? 2_000`, while the current diagnostics schema, typed config, labels/help, and docs have no lane wait threshold field.

## Solution Assessment

Yes, the narrow `diagnostics.laneWaitWarnMs` direction is the best fit if maintainers accept the new config surface. Per-lane timeouts, adaptive thresholds, and session concurrency changes are broader product work and should remain separate.
