## Summary

Keep open. Current main and v2026.6.11 still keep the lane wait diagnostic threshold as an unconfigurable queue-entry default, while the linked implementation PR remains open and unmerged.

## What This Changes

The issue requests a configurable lane wait diagnostic warning threshold, likely as `diagnostics.laneWaitWarnMs`, to reduce non-actionable gateway log noise for long-running cron work.

## Best Possible Solution

Ship a narrow, documented `diagnostics.laneWaitWarnMs` positive millisecond setting that preserves the current 2,000 ms default and explicit per-call overrides, with broader lane concurrency and auto-yield work kept separate.
