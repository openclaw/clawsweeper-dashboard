## Summary

Keep open. Current main and the latest release still keep the lane wait diagnostic threshold as an unconfigurable queue-entry default, and the open linked implementation PR has not merged.

## What This Changes

Add a configurable lane wait diagnostic warning threshold so long-running cron lanes do not flood gateway logs.

## Best Possible Solution

Ship a narrow, documented `diagnostics.laneWaitWarnMs` positive millisecond setting that preserves the current 2,000 ms default and explicit per-entry overrides, with broader lane concurrency and auto-yield work kept separate.
