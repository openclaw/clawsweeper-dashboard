## Summary

Keep open. Current main and the latest release still hard-code the queue-entry lane wait warning default and do not expose `diagnostics.laneWaitWarnMs`; the open closing PR is the active implementation path, but it remains unmerged and conflicting.

## What This Changes

The issue requests a configurable lane wait diagnostic warning threshold so long-running cron or lane workloads do not flood gateway logs with hardcoded two-second warnings.

## Best Possible Solution

Resolve https://github.com/openclaw/openclaw/pull/86676 or land a narrow replacement so `diagnostics.laneWaitWarnMs` is documented, schema-backed, type/help/reference aligned, default-preserving, and covered by command-queue/config reload tests before closing this issue.

## Reproduction Assessment

Yes. Source inspection shows current `main` still defaults queue-entry warning thresholds to 2,000 ms when no explicit override is supplied, and the diagnostics schema/docs have no `laneWaitWarnMs` field.

## Solution Assessment

Yes in direction, but it is not complete yet. A narrow `diagnostics.laneWaitWarnMs` setting with the current default preserved is the maintainable core fix, while the open PR or a replacement must still align the public config contract, reload behavior, docs, and tests.
