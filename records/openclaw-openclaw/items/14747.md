## Summary

Keep open. Current `main` and the latest release still keep lane wait diagnostics on the hardcoded queue-entry default, while https://github.com/openclaw/openclaw/pull/86676 is the open implementation candidate and has not merged.

## What This Changes

Add a configurable diagnostics lane-wait warning threshold so long-running queued work can avoid repeated non-actionable log warnings.

## Best Possible Solution

Ship a narrow, documented `diagnostics.laneWaitWarnMs` positive-ms setting that preserves the 2,000 ms default and explicit per-entry overrides, then keep broader lane concurrency and auto-yield work separate.
