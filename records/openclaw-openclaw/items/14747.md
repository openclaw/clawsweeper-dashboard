## Summary

Keep open. Current main and the latest release still lack a configurable lane-wait warning threshold, while the focused linked implementation PR remains open, unmerged, and conflict-marked; this issue remains the canonical tracker pending product approval and repair or replacement of that PR.

## What This Changes

Request a configurable threshold for lane-wait diagnostic warnings instead of the fixed queue default.

## Best Possible Solution

Expose one positive-millisecond `diagnostics.laneWaitWarnMs` field that preserves the 2,000 ms default and explicit per-entry overrides, uses the current runtime configuration for future enqueues, and keeps schema, types, help, docs, and focused default/reload tests aligned.
