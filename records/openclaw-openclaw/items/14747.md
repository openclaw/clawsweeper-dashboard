## What This Changes

Request to make the lane wait diagnostic warning threshold configurable instead of hardcoded at 2,000 ms.

## Best Possible Solution

Land a focused fix through https://github.com/openclaw/openclaw/pull/86676 or a narrow replacement that preserves the 2,000 ms default, respects explicit per-call overrides, and aligns schema, types, help/reference docs, reload semantics, and tests.

## Reproduction Assessment

Yes. Source inspection is enough to reproduce the missing capability: current main defaults lane wait warnings to `2_000` when callers omit `warnAfterMs`, and the diagnostics schema/types/docs have no `laneWaitWarnMs` field.

## Solution Assessment

Yes in direction, but not complete yet. A documented global `diagnostics.laneWaitWarnMs` setting is narrower than per-lane or dynamic timeout work; the linked PR still needs its config contract and reload semantics resolved before this issue closes.
