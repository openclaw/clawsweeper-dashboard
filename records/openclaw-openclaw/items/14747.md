## Summary

Keep open. Current `main` and the latest release still lack the requested configurable lane wait diagnostic threshold, while https://github.com/openclaw/openclaw/pull/86676 is the open implementation candidate that explicitly closes this issue but has not merged.

## What This Changes

The issue requests a configurable `diagnostics.laneWaitWarnMs` threshold so legitimate long lane waits do not flood diagnostics with the hardcoded short warning.

## Best Possible Solution

Ship one narrow implementation path that adds optional `diagnostics.laneWaitWarnMs`, preserves the 2,000 ms default and explicit per-entry overrides, aligns schema/types/help/docs/tests, and keeps broader lane concurrency or auto-yield work separate.
