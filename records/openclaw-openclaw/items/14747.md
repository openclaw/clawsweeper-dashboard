## Summary

Keep open. Current main and the latest release still hardcode the lane wait diagnostic default and do not expose `diagnostics.laneWaitWarnMs`; https://github.com/openclaw/openclaw/pull/86676 is the open implementation candidate but has not merged and is currently conflicting.

## What This Changes

Requests a configurable lane wait diagnostic warning threshold so long-running cron or lane work does not flood gateway diagnostics with non-actionable warnings.

## Best Possible Solution

Land or replace the linked implementation with a narrow `diagnostics.laneWaitWarnMs` positive-ms setting that preserves the 2,000 ms default and explicit per-entry overrides, aligns schema/types/help/docs, and keeps broader lane concurrency work separate.

## Reproduction Assessment

Yes. Source inspection shows the queue default is still `opts?.warnAfterMs ?? 2_000`, while current schema, typed config, reload planning, and docs do not expose a lane wait threshold setting.

## Solution Assessment

Yes, the narrow `diagnostics.laneWaitWarnMs` direction is the best fit for this issue. Per-lane thresholds, adaptive timeouts, and session concurrency changes are broader product work and should stay separate.
