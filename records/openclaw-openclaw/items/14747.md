## Summary

Keep open. Current main and v2026.6.11 still keep the lane wait diagnostic threshold as an unconfigurable queue-entry default, and the open linked implementation PR has not merged.

## What This Changes

Request to make the command-lane wait diagnostic warning threshold configurable for long-running cron or other queued work.

## Best Possible Solution

Ship a narrow documented `diagnostics.laneWaitWarnMs` setting that preserves the current 2,000 ms default and explicit per-entry overrides, with broader lane concurrency and auto-yield work left to the separate scheduler discussion.
