## Summary

Keep open. Current main and v2026.6.11 still lack the requested configurable lane wait warning threshold, and the active implementation candidate at https://github.com/openclaw/openclaw/pull/86676 is open, unmerged, and conflicting.

## What This Changes

Request a configurable `diagnostics.laneWaitWarnMs` threshold so long-running cron or lane work can reduce non-actionable `lane wait exceeded` diagnostics without disabling diagnostics.

## Best Possible Solution

Ship a narrow, documented `diagnostics.laneWaitWarnMs` positive millisecond setting that preserves the 2,000 ms default and explicit `warnAfterMs` overrides, aligns schema/types/help/docs/reload behavior, and keeps broader lane concurrency work separate.
