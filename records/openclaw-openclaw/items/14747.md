## Summary

Keep open. Current main and the latest release still hardcode the lane wait warning default and do not expose `diagnostics.laneWaitWarnMs`; the open linked implementation PR is the active fix candidate but is still unmerged and conflicting.

## What This Changes

Request to make the lane wait diagnostic warning threshold configurable so long-running cron lanes can avoid repetitive non-actionable warnings.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/86676 with a narrow `diagnostics.laneWaitWarnMs` positive-ms setting that preserves the 2,000 ms default and explicit per-call overrides while aligning schema, types, help/reference docs, and reload behavior.

## Reproduction Assessment

Yes. Source inspection shows the queue default is still `opts?.warnAfterMs ?? 2_000`, while current schema, typed config, and docs have no lane wait threshold field.

## Solution Assessment

Yes, the narrow `diagnostics.laneWaitWarnMs` direction is the best fit for this issue. Per-lane/adaptive thresholds and session concurrency changes are broader product work and should remain separate.
