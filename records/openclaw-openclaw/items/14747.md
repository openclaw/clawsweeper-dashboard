## Summary

Keep open. Current main and the latest release still use an unconfigurable 2,000 ms default for lane wait warnings, and the linked implementation PR is open, conflicting, and waiting on follow-up rather than merged.

## What This Changes

Request a configurable lane wait diagnostic warning threshold so long-running cron or queued work can reduce non-actionable `lane wait exceeded` log noise without disabling diagnostics.

## Best Possible Solution

Land or replace the focused linked PR with a documented `diagnostics.laneWaitWarnMs` positive millisecond setting that preserves the 2,000 ms default and explicit per-entry overrides while aligning schema, types, help/reference docs, generated docs, tests, and reload semantics.
