## What This Changes

Request to add a configurable lane wait diagnostic warning threshold so long-running cron or contended lanes do not flood logs with hardcoded two-second warnings.

## Best Possible Solution

Resolve https://github.com/openclaw/openclaw/pull/86676 or a narrow replacement that preserves the two-second default and explicit `warnAfterMs` overrides while aligning schema, typed config, docs, and reload behavior.

## Reproduction Assessment

Yes. Source inspection on current main shows queue entries without an explicit override still use the hardcoded `2_000` ms threshold, and the diagnostics schema/docs have no `laneWaitWarnMs` field.

## Solution Assessment

Yes in direction, but not complete here. A narrow `diagnostics.laneWaitWarnMs` setting with the current default preserved is the maintainable core path, while final acceptance belongs with the linked PR's config-surface review.
