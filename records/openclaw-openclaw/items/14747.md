## Summary

Keep open. Current main and the latest release still hardcode the lane wait diagnostic threshold, while https://github.com/openclaw/openclaw/pull/86676 is an open, conflicting implementation candidate that explicitly closes this issue but has not merged.

## What This Changes

Request a configurable lane wait diagnostic threshold so legitimate long-running cron or queued work can avoid noisy `lane wait exceeded` warnings without disabling diagnostics.

## Best Possible Solution

Ship a narrow, documented `diagnostics.laneWaitWarnMs` positive millisecond setting that preserves the 2,000 ms default and explicit `warnAfterMs` overrides, with schema/types/help/docs/reload semantics aligned and broader lane concurrency work kept separate.
