## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Enforce auth before exposing task execution:** `extensions/a2a/index.ts:100-103`
  - body: This route is registered with `auth: "plugin"`, which means the plugin must verify the caller itself; the handler never checks the documented `auth.mode` or any token before creating sessions and sending messages. Enabling the plugin would expose task execution to any caller that can reach the Gateway route.
  - confidence: 0.91
- **[P2] Use the supported sessions.send parameters:** `extensions/a2a/index.ts:214-220`
  - body: `sessions.send` accepts `key` and rejects extra fields, but this call sends `sessionKey` and `deliver`. The async send will fail validation while the JSON-RPC response already reports a working task, so the advertised task execution endpoint does not actually deliver the message.
  - confidence: 0.93
- **[P2] Read plugin config from api.pluginConfig:** `extensions/a2a/index.ts:61-74`
  - body: `api.config` is the full OpenClaw config snapshot, not `plugins.entries.a2a.config`; as written, `gatewayUrl`, `agents.expose`, and `auth.mode` from the documented plugin config are ignored. The manifest also omits `gatewayUrl`, so the docs' strict-config example would be rejected before runtime.
  - confidence: 0.88
