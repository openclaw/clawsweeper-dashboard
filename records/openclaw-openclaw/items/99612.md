## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P1] Keep A2A disabled unless explicitly enabled:** `extensions/a2a/index.ts:139`
  - body: The manifest and docs describe `enabled` as defaulting to false, but this code treats missing config as enabled. If this is bundled, the Gateway can mount the A2A routes without an explicit operator opt-in.
  - confidence: 0.9
- **[P1] Enforce auth before accepting A2A tasks:** `extensions/a2a/index.ts:177-189`
  - body: This route declares `auth: "plugin"`, which bypasses normal Gateway auth, but the handler never validates the configured `gateway_token` or `none` mode before creating sessions and sending messages. Enabling the plugin would let any reachable caller start agent work.
  - confidence: 0.92
- **[P1] Do not proxy arbitrary targets with caller tokens:** `extensions/a2a/index.ts:288-290`
  - body: `params.target` and `params.auth` are accepted from the JSON-RPC request and passed to `fetch` as a bearer token without an allowlist or trust boundary. A reachable caller can make the Gateway issue outbound requests and forward credentials to attacker-chosen URLs.
  - confidence: 0.86

## Security Review

Status: needs_attention

Summary: The diff introduces externally reachable protocol surfaces with incomplete auth, default-off mismatch, arbitrary outbound forwarding, and dependency-guarded package metadata.

Concerns:

- **[high] A2A routes enable by default when config is absent:** `extensions/a2a/index.ts:139`
  - body: The runtime treats missing `config.enabled` as enabled even though the manifest default is false, so bundling the plugin can unexpectedly expose its HTTP routes.
