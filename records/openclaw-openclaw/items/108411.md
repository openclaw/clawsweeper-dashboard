## Label Justifications

- `P1`: Ack-first webhook failures can be acknowledged before core owns the event, causing real inbound messages to disappear without platform redelivery.
- `impact:message-loss`: The requested contract directly addresses silently lost inbound events after an early successful webhook response.

## Summary

Keep this issue open: current main has the receive-context, adoption, and durable-journal pieces, but still lacks the composed per-event outcome needed to distinguish retryable rejection from safe no-dispatch completion; the open LINE PR depends on this decision rather than superseding it.

## What This Changes

Requests a typed Plugin SDK per-event inbound acceptance outcome so ack-first webhook channels can distinguish adopted, retryable rejection, and legitimate no-dispatch completion.

## Best Possible Solution

Extend the existing channel-inbound receive lifecycle with one closed per-event result, settle it exactly once across every admission, failure, and no-dispatch path, and let the LINE PR aggregate that result while retaining its current default until the durable-spool direction is decided.
