## Summary

Keep this PR open for maintainer review: it is a focused candidate for the hidden-tool diagnostic bug, but it only adds a planner callback and crash guards while the linked issue asks for an observable registration/startup diagnostic path for plugin authors.

## What This Changes

The PR adds an optional `onHiddenDiagnostic` callback to `BuildToolPlanOptions`, invokes it for hidden tool diagnostics, guards non-array `allOf`/`anyOf`, and adds focused planner and availability tests.

## Best Possible Solution

Land one canonical fix that keeps the evaluator pure and surfaces malformed availability diagnostics once at the plugin registration or resolver boundary; keep the planner callback only if maintainers want that public API.

## Reproduction Assessment

Yes. Source inspection shows empty availability groups produce `unsupported-signal` diagnostics, current `buildToolPlan` only records them in `hidden`, and current plugin descriptor capture does not preserve `availability` for registration-time visibility.

## Solution Assessment

No. The callback is a plausible helper, but without a production caller or registration sink it is not the complete fix for the linked runtime diagnostic issue.
