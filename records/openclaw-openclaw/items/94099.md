## What This Changes

This PR adds an optional `onHiddenDiagnostic` callback to `BuildToolPlanOptions`, invokes it for hidden planner diagnostics, guards non-array `allOf`/`anyOf`, and adds focused tool tests.

## Best Possible Solution

Land one canonical fix that keeps the evaluator pure and surfaces malformed availability diagnostics once at plugin descriptor registration or resolver time; keep the planner callback only if maintainers want that public API.

## Reproduction Assessment

Yes. Source inspection shows empty availability groups return `unsupported-signal`, `buildToolPlan` only records those diagnostics in `hidden`, and plugin descriptor capture does not preserve tool-authored `availability` on current main.

## Solution Assessment

No. The callback is a plausible helper, but the best fix must also wire the observable diagnostic into the plugin registration or resolver boundary before this PR closes the linked issue.
