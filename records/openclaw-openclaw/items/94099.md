## Summary

Keep this PR open, but not merge-ready: it is a useful narrow helper, yet it does not surface the linked diagnostic through the production plugin registration/startup path and it adds a public planner callback that needs maintainer boundary approval.

## What This Changes

This PR adds an optional `onHiddenDiagnostic` callback to `BuildToolPlanOptions`, invokes it for hidden availability diagnostics, guards non-array `allOf`/`anyOf`, and adds focused tests.

## Best Possible Solution

Land one canonical warn-only implementation that keeps the evaluator pure and surfaces malformed availability diagnostics once at the plugin descriptor registration or resolver boundary; keep the planner callback only if maintainers accept that public API.

## Reproduction Assessment

Yes. Source inspection shows empty groups return unsupported-signal diagnostics, buildToolPlan only stores them in hidden on current main, and plugin descriptor capture drops plugin-authored availability before any registration-time warning can occur.

## Solution Assessment

No. The callback is a plausible helper, but without a production caller or registration sink it is not the complete fix for the linked diagnostic issue and the public API boundary still needs maintainer direction.
