## Summary

Current main contradicts the reported hijacking mechanism: sequence numbers order server events and detect gaps, RPC requests use separate random UUID correlation IDs, and method dispatch is reached only after gateway authentication and device authorization. Because this issue carries protected security labels, keep it open for explicit security-owner disposition rather than auto-closing; the previous Codex review reached the same conclusion and no new technical evidence was added.

## What This Changes

Investigate whether predictable gateway event sequence numbers permit session hijacking or WebSocket message injection, and replace them with cryptographic identifiers and payload validation if necessary.

## Best Possible Solution

Have the gateway security owner confirm the threat model and close the report unless a PoC demonstrates bypass of the connect handshake, authentication, device authorization, or scoped dispatch; do not randomize event sequence numbers or add per-payload cryptography without evidence that those changes address a real boundary failure.
