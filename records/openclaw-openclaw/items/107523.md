## Summary

Current main does not support the reported attack mechanism: event sequence numbers are socket-local ordering metadata, request identifiers and connection challenges are random UUIDs, and gateway requests are processed only after authentication and device authorization. Keep this issue open because its protected security labels require explicit gateway security-owner confirmation.

## What This Changes

Investigate whether predictable gateway event sequence numbers permit WebSocket session hijacking or message injection, and harden the protocol if confirmed.

## Best Possible Solution

Retain random UUID request and challenge identifiers plus authenticated request dispatch, while asking the reporter to provide a private concrete proof if they have an injection path independent of event sequence ordering.
