## Summary

Current main does not support the reported attack mechanism: gateway event sequence values are socket-local ordering metadata, RPC request IDs and connection challenges are cryptographically random UUIDs, and request dispatch occurs only after authentication and device authorization. The protected security labels require explicit gateway security-owner confirmation before closure.

## What This Changes

Review whether predictable gateway event sequence numbers permit WebSocket session hijacking or message injection.

## Best Possible Solution

Keep event sequence numbers as per-connection ordering metadata, retain random UUID request IDs and nonce-bound connect authentication, and ask the reporter to submit any concrete boundary-bypass proof through a private GitHub Security Advisory.
