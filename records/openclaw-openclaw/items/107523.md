## Summary

Current main does not support the reported attack mechanism: `seq` is optional server-event ordering metadata used only for gap detection, while request correlation uses random UUIDs and gateway RPC dispatch requires an authenticated, authorized connection. The protected security labels still require explicit gateway security-owner disposition before closure.

## What This Changes

Investigate whether predictable gateway event sequence numbers allow WebSocket session hijacking or unauthorized message injection.

## Best Possible Solution

Keep the current authenticated WebSocket and method-scope model, add no randomization or per-frame cryptography unless a concrete bypass is demonstrated, and close after a gateway security owner confirms that `seq` never influences authority or request routing.
