## Summary

Current main does not support the reported hijacking mechanism: event sequence numbers are ordering metadata, RPC correlation uses cryptographically random UUIDs, and non-connect requests reach method dispatch only after gateway authentication and device authorization. The protected security label requires explicit security-owner disposition before closure.

## What This Changes

Investigate and remediate the claim that predictable gateway event sequence numbers permit WebSocket session hijacking or message injection.

## Best Possible Solution

Keep sequence numbers as per-connection ordering metadata and UUIDs as RPC correlation IDs; a gateway security owner should close the report as non-exploitable unless the reporter privately supplies a concrete authentication-bypass packet trace or reproducible proof.
