## Summary

The gateway security model and current source do not support the reported mechanism: `seq` is event-ordering metadata used for gap detection, while the first accepted client frame must be `connect` and gateway authentication, device pairing, nonce-bound signatures, scopes, and socket-local request dispatch control access. Because this issue carries protected security labels, keep it open for an explicit gateway security-owner boundary check rather than automated cleanup.

## What This Changes

Investigate whether predictable gateway event sequence numbers permit WebSocket session hijacking or message injection, and replace them with cryptographic identifiers and payload validation if so.

## Best Possible Solution

Run a focused raw-WebSocket boundary test against current main using unauthenticated and separately authenticated sockets with guessed `seq` values; if all frames remain socket-bound and auth-gated, close the report, and if a bypass appears, fix that authorization path rather than randomizing ordering metadata.
