## Summary

Current main does not support the reported attack mechanism: `seq` is socket-local server-event ordering metadata, not a session secret or client request identifier, and non-connect requests reach dispatch only after connection authentication and device authorization. The protected security labels still require an explicit gateway security-owner decision before closure.

## What This Changes

Assess and prevent alleged gateway session hijacking or WebSocket message injection through predictable sequence identifiers.

## Best Possible Solution

Keep sequence values as deterministic per-connection event-ordering metadata; close the report unless a proof of concept demonstrates that an unauthenticated or unauthorized connection can cross the authenticated dispatcher boundary.
