## Summary

Current main does not support the reported attack mechanism: gateway event `seq` values are ordering metadata, RPC request IDs are cryptographically random UUIDs, and every usable socket must pass connect authentication and device authorization before socket-local request dispatch. The protected security labels nevertheless require an explicit gateway security-owner boundary check before cleanup.

## What This Changes

Investigate whether predictable gateway event sequence numbers permit WebSocket session hijacking or message injection.

## Best Possible Solution

Have a gateway security owner run a focused unauthenticated and authenticated cross-socket injection check; if prediction of `seq` grants no authority, close the report, but if a bypass exists, repair the authentication or socket-dispatch boundary rather than randomizing event-order metadata.
