## Summary

Keep this PR open: the prior lifecycle blocker remains because timeout handling still rejects before confirming the ngrok child and its piped streams have closed, and the added tests do not provide real-process proof.

## What This Changes

The PR unreferences the ngrok startup timeout, marks the child closed when startup times out, and adds mocked timeout-path regression tests.

## Best Possible Solution

Use one lifecycle-owned ngrok termination helper for startup timeout and normal stop: request SIGTERM, wait a bounded interval for `close`, escalate to SIGKILL when needed, await final child/stdio closure, and only then mark ownership closed or reject; retain timer unref only as a supplementary optimization and prove both timeout and parent-exit behavior with a real OS child.
