## Summary

Keep this PR open for revision. The prior lifecycle blocker remains on the unchanged reviewed head: unrefing the watchdog only removes the timer reference, while the ngrok child and its piped streams can still hold the process open; marking `closed` and rejecting immediately after SIGTERM releases ownership without observing that the child exited. The submitted proof remains mock-only and does not demonstrate real child-process cleanup.

## What This Changes

The PR unreferences the ngrok startup timer, marks the tunnel closed before sending SIGTERM on startup timeout, and adds mocked timeout-path regression tests.

## Best Possible Solution

Use one bounded ngrok termination helper for startup timeout and normal stop: send SIGTERM, await `close`, escalate to SIGKILL after a short grace period, await final closure, and only then reject or release ownership.

## Reproduction Assessment

Yes from source inspection: the timeout branch rejects immediately after sending SIGTERM, while Node child-process ownership remains active until the process and piped streams close. A live current-main reproduction was not run in this review.

## Solution Assessment

No. Unrefing the watchdog does not address the referenced child process, and setting `closed` before observing exit makes the ownership state inaccurate; bounded termination and reaping is the narrow maintainable fix.
