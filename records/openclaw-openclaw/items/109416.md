## Summary

The previous lifecycle blocker remains: the watchdog is unreferenced, but the timeout path still treats sending SIGTERM as if the ngrok child had closed, so a resistant child and its stdio can continue keeping the host alive. The updated proof is explicitly mock-only.

## What This Changes

The PR unreferences the ngrok startup watchdog, marks the tunnel closed before sending SIGTERM on timeout, and adds mocked timeout-path tests.

## Best Possible Solution

Keep the watchdog unreferenced, but terminate ngrok through one bounded helper that sends SIGTERM, waits for `close`, escalates to SIGKILL if needed, and marks ownership closed only after the child is actually reaped.

## Reproduction Assessment

Yes. The related real-process report uses a child that ignores SIGTERM and observes it still alive after the current timeout path rejects; Node's documented kill and close semantics match that result.

## Solution Assessment

No. Unreferencing the timer is useful, but marking `closed` before the process closes does not solve process ownership; bounded termination and reaping is the narrow maintainable fix.
