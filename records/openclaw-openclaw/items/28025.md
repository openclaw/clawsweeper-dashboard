## Summary

Keep open: current main still has only static Slack reply-placement controls, including per-channel `replyToMode`, and no tool-use-sensitive policy. The remaining work is a product/config decision about visible Slack reply placement, not an already-implemented bug fix.

## What This Changes

The issue requests a default-off Slack option that replies in a thread after agent tool use while leaving purely conversational responses at top level.

## Best Possible Solution

Define a maintainer-approved Slack-owned reply-placement policy, preferably by extending the existing `replyToMode` machinery with docs and regression coverage instead of adding a parallel routing path.
