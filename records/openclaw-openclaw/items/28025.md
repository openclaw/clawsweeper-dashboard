## Summary

Keep open: current main has static Slack reply placement controls, including the merged per-channel override, but it still lacks the requested default-off policy that routes automatic replies into a Slack thread only when the agent used tools. This remains a product/config decision rather than a strict bug fix.

## What This Changes

The issue requests a new Slack configuration option that automatically threads tool-using agent replies while leaving purely conversational replies at the top level.

## Best Possible Solution

Maintainers should first define the Slack-owned config shape and precedence, then implement the default-off policy across schema, routing, docs, tests, and live Slack proof.
