## Summary

Keep open: current main and the latest release still provide static Slack reply-threading controls only, while this request asks for tool-use-sensitive reply placement. The related Slack threading PR and issues overlap on channel clutter and reply policy, but none is merged or canonical for this exact behavior.

## What This Changes

Request to add optional Slack behavior that threads agent replies only after tool use while leaving tool-less conversational responses top-level.

## Best Possible Solution

Define a maintainer-approved Slack reply-policy contract, then update the Slack plugin config schema, docs, routing/streaming behavior, message-tool consistency, and focused Slack tests together.

## Reproduction Assessment

Yes, from source for the missing capability: current main resolves Slack reply placement from static replyToMode settings and exposes no tool-use-sensitive option. I did not run live Slack proof because this is a feature request, not a broken existing contract.

## Solution Assessment

Unclear for the proposed boolean until maintainers choose the public Slack reply-policy contract. A default-off option is plausible, but the best fix must specify precedence with existing modes, DMs, tool delivery, streaming, and explicit top-level opt-outs.
