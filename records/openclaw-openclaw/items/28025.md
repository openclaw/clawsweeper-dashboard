## Summary

Keep open: current main and the latest release still expose static Slack reply-threading controls only, while this request is specifically for tool-use-sensitive placement. The closest linked PR, https://github.com/openclaw/openclaw/pull/82253, is open, conflicting, and only covers per-channel static `replyToMode`, so it is not a canonical replacement.

## What This Changes

Request a default-off Slack config option that threads agent replies only when the session used tools while leaving purely conversational replies top-level.

## Best Possible Solution

Define one maintainer-approved Slack reply-policy contract for tool-sensitive threading, then update schema, docs, routing/streaming behavior, and focused Slack regression tests together.

## Reproduction Assessment

Yes, from source: current main resolves Slack reply placement from static `replyToMode` and thread context, and the strict config/docs expose no tool-use-sensitive mode. I did not run live Slack proof because this is a feature request, not a broken existing contract.

## Solution Assessment

Unclear for the exact proposed shape: a default-off boolean is plausible, but maintainers need to choose its precedence with existing Slack reply modes, DMs, existing threads, explicit top-level opt-outs, and streaming/status timing.
