## Summary

Keep open: current main and the latest release still expose static Slack reply-threading controls only, while this request is specifically for tool-use-sensitive placement. The related Slack threading items overlap on channel clutter and reply mode design, but none is a merged or safe canonical replacement for this exact behavior.

## What This Changes

Add an opt-in Slack config that routes agent replies into a thread after tool use while leaving tool-free conversational responses top-level.

## Best Possible Solution

Define one maintainer-approved Slack reply-policy contract for tool-sensitive threading, then update schema, docs, routing/streaming behavior, and focused Slack regression tests together.

## Reproduction Assessment

Yes from source: current main resolves static Slack `replyToMode` before reply dispatch and documents no tool-use-sensitive mode. I did not run live Slack proof because this is a feature request, not a current behavior bug.

## Solution Assessment

Unclear for the proposed shape: the default-off boolean is plausible, but the best implementation needs maintainer-approved precedence with existing Slack reply modes, DMs, channels, existing thread sessions, explicit top-level opt-outs, and streaming/status timing.
