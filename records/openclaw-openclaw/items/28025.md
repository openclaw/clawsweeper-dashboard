## Summary

Current main still lacks tool-use-sensitive Slack reply placement: Slack has static `replyToMode` controls, and tool lifecycle callbacks only affect progress/status output. The request remains useful, but it needs maintainer product direction for the public config shape and precedence with existing threading modes before implementation.

## What This Changes

Request to add a Slack config option that routes tool-using agent responses into threads while leaving purely conversational responses top-level.

## Best Possible Solution

Define one maintainer-approved Slack reply-policy contract for tool-sensitive threading, then update the plugin schema, docs, routing/streaming behavior, and focused Slack regression tests together.

## Reproduction Assessment

Yes, at source level for feature absence: current Slack reply routing is static reply-mode based and tool lifecycle callbacks do not change thread placement. This is a feature gap, not a broken existing behavior contract.

## Solution Assessment

Unclear as proposed. The default-off boolean is plausible, but the best fix needs a maintainer-approved precedence contract with existing Slack reply modes, streaming/status timing, DMs, channels, and current thread sessions.
