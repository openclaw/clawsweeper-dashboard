## Summary

Keep open: current main still supports only static Slack reply placement, while this issue requests a new tool-use-sensitive Slack reply policy that needs maintainer product direction before implementation.

## What This Changes

Add a default-off Slack option that routes agent replies into a thread when a run used tools, while leaving purely conversational replies top-level.

## Best Possible Solution

Define one Slack-owned reply-placement contract first, then add the default-off schema, routing, docs, and focused tests if maintainers approve it.
