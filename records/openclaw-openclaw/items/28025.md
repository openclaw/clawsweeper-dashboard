## Summary

Keep open: current main still has only static Slack reply placement (`replyToMode` at account, chat-type, and per-channel levels), while this issue asks for a new tool-use-sensitive policy that needs maintainer product direction.

## What This Changes

Request to add a default-off Slack config that threads agent replies only when the turn invoked tools and leaves conversational replies top-level.

## Best Possible Solution

Define one Slack-owned reply-placement contract first, then implement the default-off schema, routing, docs, and tests without changing existing installs.
