## Summary

Keep open: current main still has static Slack reply-placement controls, including the recently merged per-channel `replyToMode`, but no tool-use-sensitive reply policy. The remaining decision is product/config direction rather than a stale or already-implemented bug fix.

## What This Changes

The issue requests a default-off Slack option that routes agent replies into a thread only when the session used tools, while leaving purely conversational replies at top level.

## Best Possible Solution

Define a maintainer-approved Slack-owned reply-placement policy, preferably by extending the existing `replyToMode` machinery with docs and regression coverage instead of adding a parallel routing path.
