## Summary

Keep open: current main still has static Slack reply-placement controls and per-channel overrides, but no tool-use-sensitive policy that threads tool-heavy responses while leaving conversational replies at the channel root. The remaining work is product-sensitive because it adds a new Slack config/default surface and must define precedence with existing reply modes, explicit thread context, DMs, streaming, and message-tool behavior.

## What This Changes

The issue requests a default-off Slack option that routes agent replies into a thread when the session used tools while keeping purely conversational responses top-level.

## Best Possible Solution

Define one maintainer-approved Slack reply-placement contract, then implement schema, docs, routing, and focused tests with a default-off config and explicit precedence.
