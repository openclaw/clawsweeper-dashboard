## Summary

Keep open: current main still exposes static Slack reply modes and has no tool-use-sensitive reply-placement policy. The merged per-channel reply-mode work at https://github.com/openclaw/openclaw/pull/82253 is useful partial overlap, but this request still needs maintainer product direction before implementation.

## What This Changes

The issue requests a Slack configuration option that threads agent replies only when the session used tools, while leaving purely conversational replies at the top level.

## Best Possible Solution

Define one maintainer-approved Slack reply-policy contract, then update the Slack plugin schema, docs, routing/streaming behavior, and focused regression tests together without changing existing defaults.
