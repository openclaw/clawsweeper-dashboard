## Summary

Keep open: current main and the latest release still expose static Slack reply-threading controls only, while this request is specifically for tool-use-sensitive reply placement. The related Slack threading items overlap on channel clutter and reply mode design, but none is a merged canonical replacement for this exact behavior.

## What This Changes

The issue requests a default-off Slack configuration policy that posts tool-using agent replies in a thread while keeping purely conversational replies at top level.

## Best Possible Solution

Define one maintainer-approved Slack reply-policy contract for tool-sensitive threading, then update schema, docs, routing/streaming behavior, and focused Slack regression tests together.

## Reproduction Assessment

Yes, at source level: current main resolves static Slack replyToMode before reply dispatch and documents no tool-use-sensitive mode. I did not run live Slack proof because this is a feature request, not a current behavior bug.

## Solution Assessment

Unclear for the proposed shape: a default-off boolean is plausible, but the best solution needs maintainer-approved precedence with existing Slack reply modes, DMs, channels, existing thread sessions, explicit top-level opt-outs, and streaming/status timing.
