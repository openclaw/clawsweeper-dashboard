## Summary

Keep open: current main and v2026.6.11 still expose static Slack reply-threading controls only, while this issue asks for tool-use-sensitive reply placement. Related Slack threading items overlap on channel clutter and reply-mode design, but none is a merged or viable canonical replacement for this exact policy.

## What This Changes

The issue requests a Slack config option that routes tool-using agent responses into a thread while leaving purely conversational responses at top level.

## Best Possible Solution

Define one maintainer-approved Slack reply-policy contract for tool-sensitive threading, then update schema, docs, routing/streaming behavior, and focused Slack regression tests together.

## Reproduction Assessment

Yes, from source: current main and v2026.6.11 resolve static Slack `replyToMode` and document no tool-use-sensitive mode. I did not run live Slack proof because the gap is a missing feature/config policy, not a runtime regression.

Unclear for the proposed shape: a default-off boolean is plausible, but maintainers need to approve precedence with existing Slack reply modes, DMs, existing threads, explicit top-level opt-outs, and streaming/status timing.
