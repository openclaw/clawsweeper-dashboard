## Summary

Keep open: current main still supports only static Slack reply-placement controls; the requested tool-use-sensitive thread policy is not implemented and needs maintainer product/config direction.

## What This Changes

The issue requests a default-off Slack config option that threads agent replies after tool use while leaving purely conversational replies at top level.

## Best Possible Solution

Define a maintainer-approved Slack-owned reply-placement policy, preferably within the existing `replyToMode` model, with docs and regression coverage for DMs, channels, streaming/status behavior, and per-channel precedence.
