## Summary

Keep open: current main still lacks a tool-use-sensitive Slack reply-placement policy. The merged per-channel `replyToMode` work is useful partial overlap, but it remains static config and does not implement the requested default-off tool-use heuristic.

## What This Changes

Request to add a default-off Slack config option that threads agent replies only when the turn used tools, while leaving purely conversational replies top-level.

## Best Possible Solution

Define one maintainer-approved Slack reply-placement contract, then update Slack schema, routing, docs, and focused tests with default false so existing installs keep current behavior.
