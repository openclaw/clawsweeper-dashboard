## Summary

Keep open: current main and the latest release still use static Slack reply-thread controls, and the overlapping Slack reply-mode items do not implement tool-use-sensitive placement. The remaining work is a public Slack config/reply-policy decision rather than a strict bug fix.

## What This Changes

The issue requests an opt-in Slack reply-routing mode that starts a thread for agent responses after tool use while leaving purely conversational responses at top level.

## Best Possible Solution

Define one maintainer-approved Slack reply-policy contract for tool-sensitive threading, then update schema, docs, routing/streaming behavior, and focused Slack regression tests together.

## Reproduction Assessment

Yes, at source level: current Slack reply routing is static `replyToMode`/thread-context based, and the tool callbacks appear after the reply plan is already built. This proves feature absence, not a broken existing behavior contract.

## Solution Assessment

No, not as an automatic fix lane. The proposed default-off boolean is plausible, but the best fix needs maintainer-approved precedence with existing Slack reply modes, DMs, channels, explicit top-level opt-outs, streaming/status timing, and existing thread sessions.
