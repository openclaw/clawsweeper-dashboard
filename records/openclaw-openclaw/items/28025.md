## Summary

Keep open: current main and v2026.6.11 still expose static Slack reply-threading controls only, while the requested behavior is tool-use-sensitive reply placement. The related Slack threading items overlap on channel clutter and reply-mode design, but none is a merged or safe canonical replacement for this exact behavior.

## What This Changes

Add a default-off Slack config policy that threads agent replies only when the session used tools and leaves purely conversational replies at top level.

## Best Possible Solution

Define a maintainer-approved Slack reply-policy contract, then update the Slack plugin schema, docs, routing/streaming behavior, and focused regression tests together while preserving existing defaults.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 expose only static Slack reply controls and have no replyOnToolUse or equivalent routing branch. This is feature absence rather than a failing bug repro, so no live Slack failure was run.

## Solution Assessment

Unclear: a default-off boolean is plausible, but the best fix needs maintainer-approved precedence across existing Slack reply modes, DMs, existing threads, explicit top-level opt-outs, and streaming/status timing.
