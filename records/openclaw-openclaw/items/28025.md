## Summary

Keep open: current main still has static Slack reply-placement controls, but no tool-use-sensitive policy. The merged per-channel `replyToMode` work is useful partial overlap, not an implementation of the requested default-off tool-use heuristic.

## What This Changes

Request adds a default-off Slack config option that routes agent replies into a Slack thread only when the turn used tools, while leaving conversational replies at top level.

## Best Possible Solution

Define a maintainer-approved Slack reply-placement policy in the Slack plugin, preferably by extending the existing `replyToMode` machinery and docs/tests rather than adding a parallel routing path.
