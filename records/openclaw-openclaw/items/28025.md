## Summary

Keep open: current main and v2026.6.11 still expose static Slack reply-threading controls only, while this request specifically asks for tool-use-sensitive placement. The overlapping Slack threading PR and related issues do not implement or safely replace this exact behavior.

## What This Changes

Add a Slack option that threads agent replies only when the run used tools while keeping purely conversational replies top-level.

## Best Possible Solution

Define one maintainer-approved Slack reply-policy contract for tool-sensitive threading, then update schema, docs, routing/streaming behavior, and focused Slack regression tests together.

## Reproduction Assessment

Yes, at source level for feature absence: current main and v2026.6.11 expose static Slack reply threading controls only. I did not run live Slack proof because this is a requested new mode rather than a current behavior bug.

## Solution Assessment

Unclear for the proposed config shape: the default-off boolean is plausible, but maintainers need to choose precedence with existing Slack reply modes, DMs, channels, existing thread sessions, explicit top-level opt-outs, and streaming/status timing.
