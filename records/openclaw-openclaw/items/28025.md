## Summary

Keep open: current main and v2026.6.11 still expose static Slack threading controls only, while this request is specifically for tool-use-sensitive reply placement. The related Slack threading PR and issues overlap on channel clutter and reply-mode design, but none is a merged canonical replacement for this exact behavior.

## What This Changes

The issue requests a Slack config option that threads agent replies only after tool-using turns while leaving purely conversational replies top-level.

## Best Possible Solution

Define one maintainer-approved Slack reply-policy contract for tool-sensitive threading, then update the Slack schema, generated metadata, docs, routing/streaming behavior, and focused regression proof together.

## Reproduction Assessment

Yes, from source for feature absence: current main resolves Slack reply placement from static replyToMode settings and documents no tool-use-sensitive mode. I did not run live Slack proof because this is a requested feature, not a broken existing behavior contract.

## Solution Assessment

Unclear for the proposed boolean: the default-off shape is plausible, but the best solution needs maintainer-approved precedence with existing Slack reply modes, DMs, current threads, explicit top-level opt-outs, and streaming/status timing.
