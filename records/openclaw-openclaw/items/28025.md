## Summary

Keep open. Current main and the latest release still only expose static Slack reply-threading controls, and the related open work covers per-channel or always-thread policies rather than tool-use-sensitive placement.

## What This Changes

The issue requests an optional Slack reply-routing policy that sends tool-using agent responses into a thread while leaving purely conversational replies at top level.

## Best Possible Solution

Adopt one maintainer-approved Slack reply-policy contract, then update schema, docs, routing, streaming/status behavior, and focused Slack regression tests together.

## Reproduction Assessment

Yes, at source level. Current Slack schema and delivery code are static reply-mode based and do not contain a tool-use-sensitive reply-routing branch.

## Solution Assessment

Unclear as proposed. The default-off boolean is plausible, but the best solution needs maintainer-approved precedence with existing Slack reply modes, streaming/status timing, DMs, and explicit top-level opt-outs.
