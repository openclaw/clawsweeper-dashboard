## Summary

Current main and the latest release still expose static Slack reply-threading controls only, so the requested tool-use-sensitive reply policy remains missing. Keep this open for maintainer product direction because it adds public Slack config/reply-policy behavior; the related open per-channel reply-mode PR and all-replies-in-thread issue overlap but do not replace this narrower tool-use signal request.

## What This Changes

The issue requests an opt-in Slack policy that threads agent replies only after tool use while leaving purely conversational replies at the top level.

## Best Possible Solution

Define one maintainer-approved Slack reply-policy contract for tool-sensitive threading, then update schema, docs, routing/streaming behavior, and focused Slack regression tests together.

## Reproduction Assessment

Yes. Source inspection shows current Slack reply placement is driven by static `replyToMode` values and lacks a tool-use-sensitive branch or config field.

## Solution Assessment

No, not as an automatic fix lane. The proposed default-off boolean is plausible, but the best solution needs maintainer-approved precedence with existing Slack reply modes, streaming/status timing, DMs, and explicit top-level opt-outs.
