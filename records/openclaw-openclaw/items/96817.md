## What This Changes

Add a Skill Workshop action that removes an applied proposal’s persisted artifacts and associated installed workspace skill.

## Best Possible Solution

Implement a kind-aware reversible cleanup lifecycle that uninstalls create outputs, restores or archives update outputs, retains proposal and rollback provenance, and refuses destructive removal when live content has drifted.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should applied create and update proposals receive different reversible cleanup behavior, or should OpenClaw expose a privileged permanent purge?

Rationale: Create proposals install new content, while update proposals replace pre-existing content and record rollback state; one unconditional directory-delete rule cannot safely serve both.

Likely owner: shakkernerd

Owner reason: The strongest history signal covers the proposal store, persisted lifecycle, apply behavior, and its safety invariants.

Owner confidence: high

Options:

- **Kind-aware reversible cleanup (recommended):** Uninstall create outputs and restore or archive update outputs while retaining provenance, checking content drift, and supporting recovery.
- **Privileged permanent purge:** Expose a separately named destructive purge with explicit approval, backup, and warnings for modified or pre-existing content.
- **Metadata-only cleanup:** Archive or hide applied proposal records while leaving live skills and rollback state untouched.
