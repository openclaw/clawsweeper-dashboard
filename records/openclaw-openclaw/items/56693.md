## Summary

Keep open: current main classifies `deactivated_workspace` as an auth/failover condition, but it still persists and reuses a token-derived ChatGPT account id without validating, selecting, or recovering an active workspace for multi-workspace OAuth users.

## What This Changes

The issue requests OpenAI Codex OAuth behavior that avoids binding to a deactivated ChatGPT workspace when the same account has an active workspace available.

## Best Possible Solution

Add an OpenAI-plugin-owned workspace validation and recovery policy that uses current Codex/OpenAI auth contracts to select and persist a usable ChatGPT account id, with focused regression tests and live multi-workspace proof.

## Reproduction Assessment

No high-confidence live reproduction was run in this read-only review. The issue is source-reproducible: current main stores one token-derived account id and reuses it in provider discovery/usage paths, while multiple users reported the same `deactivated_workspace` failure after OAuth succeeded.

## Solution Assessment

No, the current merged classifier mitigation is not the best complete solution. It is a useful narrow mitigation, but the durable fix needs an explicit OpenAI/Codex auth policy for active workspace validation, retry, persistence, and user remediation.
