## Summary

Keep open: current main contains the `deactivated_workspace` failover classifier mitigation, but the central multi-workspace OAuth problem remains because OpenClaw still persists one token-derived ChatGPT account id and reuses it without active-workspace validation or recovery.

## What This Changes

The issue requests that OpenAI/Codex OAuth avoid binding to a deactivated ChatGPT workspace when an account also has an active workspace.

## Best Possible Solution

Add an OpenAI-plugin-owned workspace validation and recovery policy that selects or recovers a usable ChatGPT accountId, persists it deliberately, and has focused tests plus live multi-workspace proof.

## Reproduction Assessment

Yes for source reproduction: current main stores one token-derived ChatGPT account id and reuses it in provider usage and Codex app-server paths, while multiple users reported the matching deactivated-workspace failure after OAuth succeeded.

## Solution Assessment

No, the current classifier mitigation is useful but not the full best fix; the maintainable fix needs an explicit OpenAI/Codex workspace validation and recovery policy rather than only mapping the error after it happens.
