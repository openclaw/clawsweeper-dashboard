## Summary

Keep open: current main contains a narrow failover classifier mitigation for deactivated_workspace, but the underlying OpenAI/Codex workspace selection and recovery problem remains unresolved because OAuth still persists a single token-derived accountId and Codex bridge refresh paths ignore the upstream previousAccountId hint.

## What This Changes

The issue requests recovery when Codex/OpenAI OAuth succeeds but the stored ChatGPT workspace/accountId later returns deactivated_workspace despite another active workspace being available.

## Best Possible Solution

Add OpenAI-plugin-owned active workspace validation and recovery policy that honors Codex previous_account_id, persists a known-good accountId only under clear rules, and surfaces guided remediation when safe recovery cannot be proven.
