## Summary

Keep open: current main only classifies `deactivated_workspace` for failover; it still persists and reuses one token-derived ChatGPT account id without active-workspace validation or recovery.

## What This Changes

Request OpenAI/Codex OAuth to avoid binding to a deactivated ChatGPT workspace when the user also has active workspaces.

## Best Possible Solution

Add an OpenAI-plugin-owned workspace validation and recovery policy that validates, selects, and persists a usable ChatGPT accountId, with usage and Codex app-server paths aligned.

## Reproduction Assessment

Yes for source reproduction: current main persists and reuses one token-derived accountId, while multiple users reported the same deactivated-workspace failure after OAuth succeeded.

## Solution Assessment

No current implementation is not a complete fix; PR #55893 is a useful classifier mitigation, but active workspace validation and recovery remain unresolved.
