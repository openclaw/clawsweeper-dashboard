## Summary

Keep open: current main and the latest release still extract and reuse one token-derived ChatGPT accountId without proving an active-workspace validation or recovery path; the merged `deactivated_workspace` PR is a useful classifier mitigation but explicitly does not solve workspace selection.

## What This Changes

OpenAI Codex OAuth should avoid binding to, or recover from, a deactivated ChatGPT workspace when a user account also has an active workspace.

## Best Possible Solution

Add an OpenAI-plugin-owned workspace validation and recovery policy that uses current Codex/OpenAI auth contracts to select and persist a usable ChatGPT accountId, with focused tests plus live multi-workspace proof.

## Reproduction Assessment

Yes for source reproduction: current main stores one token-derived accountId and reuses it in provider discovery, usage, and Codex app-server paths while users reported `deactivated_workspace` after OAuth succeeded. I did not reproduce against a live multi-workspace account in this read-only review.

## Solution Assessment

No; the current classifier mitigation is useful but not the complete fix because it only normalizes `deactivated_workspace` as a permanent auth/failover condition instead of validating, selecting, or recovering an active workspace.
