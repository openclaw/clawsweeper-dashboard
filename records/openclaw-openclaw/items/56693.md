## Summary

Keep open: current main only classifies `deactivated_workspace` for failover, while the OpenAI/Codex OAuth and app-server paths still reuse one token-derived account id without active-workspace validation or recovery.

## What This Changes

OpenAI/ChatGPT OAuth should avoid binding to or recover from a deactivated ChatGPT workspace when an active workspace exists.

## Best Possible Solution

Define an OpenAI-plugin-owned active workspace validation and recovery policy, with an in-product recovery path and live multi-workspace proof before changing persisted accountId behavior.

Yes for source-level reproduction: the issue has matching user reports, and current main stores and reuses one token-derived account id without active-workspace validation.

## Solution Assessment

No; the classifier mitigation is useful but incomplete because the real fix needs explicit workspace selection and recovery semantics in the OpenAI/Codex auth owner boundary.
