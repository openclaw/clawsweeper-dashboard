## Summary

Keep open: current main and the latest related merged PR only classify `deactivated_workspace` as a permanent auth/failover condition; OpenClaw still stores one token-derived ChatGPT account id and reuses it without active-workspace validation, selection, or recovery for multi-workspace OAuth users.

## What This Changes

Issue #56693 requests that OpenAI/Codex OAuth avoid or recover from binding a multi-workspace account to a deactivated ChatGPT workspace.

## Best Possible Solution

Keep this as the canonical OpenAI/Codex active-workspace recovery issue and implement owner-approved OpenAI-plugin auth recovery with an in-product setup/doctor remediation path plus focused source and live multi-workspace proof.

## Reproduction Assessment
