## Summary

Keep open: current main only classifies `deactivated_workspace` as a permanent auth/failover condition; it still lacks active workspace validation, selection, or recovery for multi-workspace ChatGPT OAuth accounts.

## What This Changes

Issue #56693 requests that OpenAI/Codex OAuth avoid or recover from binding to a deactivated ChatGPT workspace when an account has multiple workspaces.

## Best Possible Solution

Have maintainers choose a plugin-owned OpenAI/Codex workspace recovery path that validates or reselects a usable active `chatgpt_account_id` without adding broad runtime fallback shims.

## Reproduction Assessment

Yes at source level: OAuth extracts and stores a JWT-derived account id, runtime paths reuse it, and no active workspace probe or retry is present; no live multi-workspace account was exercised in this review.

## Solution Assessment

Unclear: PR #55893 is a useful classifier mitigation, but the full fix needs a maintainer choice between post-login validation, runtime retry, user remediation, or Codex workspace-hint support.
