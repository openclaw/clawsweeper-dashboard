## Summary

Keep open: current main and v2026.6.11 still route hook-agent requests through isolated cron-style runs, so stable hook session keys cannot preserve transcript state; the open linked implementation PR remains the active fix path.

## What This Changes

The issue requests persistent multi-turn webhook hook sessions when callers provide a stable session key.

## Best Possible Solution

Review and either land or reject https://github.com/openclaw/openclaw/pull/75918 as the canonical fix, preserving isolated defaults while adding a documented persistent hook-session opt-in with schema, docs, tests, and trust-boundary proof.
