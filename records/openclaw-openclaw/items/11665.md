## Summary

Keep open: current main and v2026.6.11 still route hook-agent requests through the isolated cron runner, so a stable hook sessionKey cannot preserve multi-turn transcript state. The open linked implementation PR https://github.com/openclaw/openclaw/pull/75918 has closing syntax and should own the active review path before this issue is closed.

## What This Changes

Allow trusted webhook hook-agent runs with a stable sessionKey to reuse persistent session state for multi-turn hook conversations.

## Best Possible Solution

Land a maintainer-approved explicit sessionMode persistent opt-in for direct hook payloads, mappings, and transform results, with isolated as the default and focused docs/tests for security and upgrade behavior.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should trusted hook-agent callers get persistent session reuse only through an explicit sessionMode opt-in, or should OpenClaw keep hook-agent runs isolated and update docs instead?

Rationale: The remaining change affects external hook ingress and session identity, so automation should not choose between compatibility, security, and product semantics without maintainer intent.

Likely owner: steipete

Owner reason: Peter owns the latest maintainer cleanup direction and current-line history for the central hook/session code paths.

Owner confidence: medium

Options:

- **Explicit persistent opt-in (recommended):** Add sessionMode: "isolated" | "persistent" across direct hooks, mappings, and transforms, keep isolated as default, and require existing hook token/sessionKey prefix gates for persistent reuse.
- **Docs-only isolation:** Keep hook-agent sessions always isolated and update user-facing docs to remove the multi-turn sessionKey expectation for hooks.
- **Automatic stable-key reuse:** Reuse existing sessions automatically for stable hook sessionKey values, accepting broader compatibility and security-boundary risk.

## Reproduction Assessment

Yes. Source inspection is enough to reproduce the gap: repeat accepted hook-agent calls with the same sessionKey and current main still sends them through sessionTarget "isolated", which forces a new session id.

## Solution Assessment

Yes, the explicit persistent-mode direction is the best maintainable shape found so far because it preserves default isolation while giving trusted hooks a deliberate multi-turn path; automatic reuse would be riskier.
