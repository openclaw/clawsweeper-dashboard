## Summary

Keep open: current main and v2026.6.11 still route hook-agent requests through isolated cron execution that forces fresh session ids, while the open closing PR is the active implementation candidate and has not merged.

## What This Changes

Requests persistent multi-turn webhook hook sessions so stable hook `sessionKey` values can reuse existing session context instead of creating a new isolated transcript on every invocation.

## Best Possible Solution

Review and either land or reject https://github.com/openclaw/openclaw/pull/75918 as the canonical fix path, keeping isolated as the default and adding a documented explicit persistent hook-session opt-in across direct payloads, mappings, and transforms.

## Reproduction Assessment

Yes, at source level. Current main creates isolated hook-agent jobs, passes `forceNew=true`, and only reuses stored session ids when `forceNew` is false.

## Solution Assessment

Unclear until maintainers finish the linked PR review. The explicit `sessionMode: "isolated" | "persistent"` opt-in is the best visible direction because it preserves safe default isolation while enabling trusted hook continuity.
