## Label Justifications

- `P2`: The issue affects real webhook integrations and conversation continuity, but it is a bounded feature/security decision already paired with open implementation work rather than an emergency outage.
- `impact:session-state`: Stable hook `sessionKey` values currently do not preserve the conversation/session state the reporter needs for multi-turn webhook interactions.
- `impact:data-loss`: The reported behavior creates new session ids and orphaned transcript files, making prior conversation context unavailable to subsequent hook turns.
- `impact:security`: The requested persistent mode would let trusted external hooks re-enter existing sessions, so session-key routing, prefix gates, and hook-token trust boundaries are central to the issue.

## Summary

Keep open: current main and the latest release still force `/hooks/agent` work through isolated cron sessions, so a stable hook `sessionKey` cannot preserve multi-turn transcript state. The open linked implementation PR https://github.com/openclaw/openclaw/pull/75918 uses closing syntax for this issue and should remain the active review path rather than starting duplicate work.

## What This Changes

The issue requests persistent multi-turn webhook hook sessions when callers provide a stable session key.

## Best Possible Solution

Review the linked `sessionMode: "isolated" | "persistent"` implementation as the canonical path, preserving isolated defaults while allowing trusted hook integrations to opt into persistent session reuse with documented security gates.

## Solution Assessment

The explicit `sessionMode` approach in the linked PR looks like the best maintainable direction because it preserves secure isolated defaults while making trusted persistent hook sessions opt-in. Automatic reuse based only on a stable `sessionKey` would be riskier because current docs treat session keys as routing selectors rather than authorization tokens.
