## Label Justifications

- `P2`: This is a normal-priority user-facing hook/session improvement with concrete source proof and production-impact reports, but it is not an emergency outage.
- `impact:session-state`: Stable hook sessionKey values currently do not preserve the intended multi-turn session context across hook-agent invocations.
- `impact:data-loss`: The report describes conversation history becoming unavailable for follow-up webhook turns and orphaned transcript files accumulating.
- `impact:security`: The requested persistent mode changes how authenticated external hook callers can target long-lived session context and needs an explicit trust boundary.
- `maturity:stable`: The issue affects the Gateway hook HTTP API surface, and gateway-runtime is scored M4 Stable with HTTP APIs marked Stable in qa/maturity-scores.yaml.

## Summary

Keep open: current main and the latest release still route hook-agent requests through isolated cron runs that force a fresh session, and the canonical closing PR is still open rather than merged.

## What This Changes

The issue asks for webhook hook-agent invocations with a stable sessionKey to opt into reusing an existing session for multi-turn behavior.

## Best Possible Solution

Review and either land or reject https://github.com/openclaw/openclaw/pull/75918 as the canonical fix path, preserving isolated default behavior while adding an explicit documented persistent hook-session opt-in.

## Reproduction Assessment

Yes, at source level. Current main builds hook-agent requests as isolated cron jobs, passes forceNew=true for isolated jobs, and only reuses an existing sessionId when forceNew is false.

## Solution Assessment

Unclear until maintainers finish reviewing the open closing PR. The explicit sessionMode direction is the best visible shape because it preserves safe isolated defaults while giving trusted hooks a narrow opt-in path.
