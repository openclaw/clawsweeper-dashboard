## Label Justifications

- `P2`: The report describes a bounded but meaningful webhook-session continuity problem, with a viable open implementation path rather than an emergency runtime failure.
- `impact:session-state`: Repeated hook calls with the same stable key can start new session identities instead of continuing the intended conversation context.
- `impact:data-loss`: The report describes abandoned transcript files and practical loss of prior conversational context on each webhook turn.
- `impact:security`: Any persistent mode changes the boundary by which authenticated external hook traffic can select retained session context.

## Summary

Keep open. This issue is paired with the still-open implementation candidate at https://github.com/openclaw/openclaw/pull/75918, so it should not close before that work is reviewed and either merged or rejected. The remaining choice is product and security policy: preserve isolated hooks by default while defining the narrow, authorized conditions under which a hook may deliberately resume stored session state.

## What This Changes

Add an explicit persistent-session mode for hook-agent requests, mappings, and transform results so stable authorized `sessionKey` values can reuse conversation context.

## Best Possible Solution

Land one narrowly scoped, current-main implementation that keeps hook runs isolated by default and permits stored-session reuse only through an explicit persistent mode guarded by the existing hook authentication and session-key policy.
