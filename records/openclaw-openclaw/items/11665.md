- `P2`: This is a normal-priority hook/session continuity improvement with concrete source proof and limited but real production impact.
- `impact:session-state`: Stable hook `sessionKey` values currently do not preserve the intended multi-turn session context across webhook invocations.
- `impact:data-loss`: The report describes conversation history becoming unusable for follow-up turns and orphaned transcript files accumulating under repeated stable hook keys.
- `impact:security`: The requested persistent hook mode changes how external authenticated hook callers can target session context and needs an explicit trust boundary.
- `maturity:stable`: The affected hook ingress path is part of the M4 Stable Gateway runtime HTTP APIs surface in the maturity taxonomy.

## Summary

Keep open: current main still forces direct and mapped hook-agent requests through isolated cron runs, so a stable hook `sessionKey` cannot preserve multi-turn session history; the open linked PR is the current candidate fix but has not merged.

## What This Changes

The issue requests multi-turn webhook hook sessions by reusing an existing session when callers provide a stable hook `sessionKey`.

## Best Possible Solution

Review and either land or reject https://github.com/openclaw/openclaw/pull/75918 as the canonical fix path, preserving isolated default behavior while adding a documented persistent hook-session opt-in.

## Reproduction Assessment

Yes. Source inspection on current main shows `/hooks/agent` creates an isolated cron job, the runner passes `forceNew=true`, and `resolveCronSession` only reuses an existing `sessionId` when `forceNew` is false.

## Solution Assessment

Unclear until maintainers finish reviewing the open fix PR. The explicit `sessionMode: "isolated" | "persistent"` direction is the best visible shape because it preserves the safe default while giving trusted hooks a narrow opt-in path.
