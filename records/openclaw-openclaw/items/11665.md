## What This Changes

Add an explicit webhook hook session mode that can reuse a stable session key for multi-turn conversations while retaining isolated runs as the default.

## System Context

Gateway webhook hooks accept direct payloads or mapped transform results, then dispatch an agent turn through the cron-style isolated runner. The runner resolves a stored session identity and produces the agent conversation state, delivery result, and session metadata.

## Architecture Diagram

flowchart LR
  A[Webhook request] --> B[Hook payload or mapping]
  B --> C[Hook authorization and session-key checks]
  C --> D[Hook agent dispatch]
  D --> E[Isolated or persistent session decision]
  E --> F[Session store and agent turn]
  F --> G[Delivery and updated session state]

## Best Possible Solution

Land a narrowly scoped, explicit `sessionMode: "persistent"` opt-in only if maintainers approve its authorization boundary; keep omitted mode isolated and cover both modes with focused hook, mapping, and session-isolation tests.
