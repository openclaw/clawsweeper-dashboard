## Label Justifications

- `P2`: This is a concrete user-facing hook/session continuity problem with bounded gateway, config, and cron surfaces, but no core outage or first-run release blocker evidence.
- `impact:session-state`: Stable hook sessionKey values currently do not preserve the active transcript/session identity across webhook turns.
- `impact:data-loss`: Reporters describe prior webhook conversation context becoming unreachable for later turns and orphaned transcript files accumulating.
- `impact:security`: Allowing external hook callers to re-enter existing sessions changes routing and trust boundaries and must preserve explicit security gates.
- `maturity:stable`: The affected hook HTTP ingress path maps to gateway-runtime HTTP APIs, and qa/maturity-scores.yaml marks gateway-runtime M4 Stable.

## Summary

Keep open: current main still routes direct and mapped hook-agent requests through isolated cron sessions, so stable hook sessionKey values cannot preserve transcript continuity; the open linked implementation PR is the active candidate and needs maintainer product/security review before this issue closes.

## What This Changes

The issue requests multi-turn webhook hook sessions by reusing an existing session when callers provide a stable sessionKey, preferably through an explicit persistent session mode.

## Best Possible Solution

Review and either land or reject https://github.com/openclaw/openclaw/pull/75918; the desired end state is an explicit sessionMode option with isolated defaults, documented trust guidance, schema/docs coverage, and regression tests for direct payloads, mappings, transforms, and session reuse.
