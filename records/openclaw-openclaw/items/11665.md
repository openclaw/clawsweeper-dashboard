## What This Changes

The issue requests persistent multi-turn webhook hook sessions when a stable hook `sessionKey` is supplied.

## Best Possible Solution

Yes. Source inspection shows `/hooks/agent` builds an isolated cron job, the runner passes `forceNew=true`, and the resolver only reuses sessions when `forceNew` is false.

## Solution Assessment

Yes on direction, not yet as completed work. An explicit persistent `sessionMode` opt-in is safer than automatic reuse, but this issue should stay open until the linked PR merges or is replaced.
