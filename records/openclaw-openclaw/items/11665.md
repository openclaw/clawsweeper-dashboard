## Summary

Keep open: current main still defines hook-agent requests as isolated and lacks a persistent-session option, while the open linked PR remains the active implementation candidate. The issue should close only after that PR lands or maintainers reject the persistent-session direction.

## What This Changes

Add an explicit persistent hook-session mode so repeated webhook calls with a stable session key can retain multi-turn conversation history.

## Best Possible Solution

Review and land the linked explicit persistent-mode PR only if it preserves isolated behavior by default, enforces existing hook authentication and session-key scoping, and proves both persistent reuse and unchanged isolated-session behavior.
