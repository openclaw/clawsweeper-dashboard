## Label Justifications

- `P2`: This is a concrete user-facing hook/session continuity problem with bounded config and gateway surfaces, but no emergency outage evidence.
- `impact:session-state`: Stable hook `sessionKey` values currently do not preserve the active transcript/session identity across webhook turns.
- `impact:data-loss`: Reporters describe prior webhook context becoming unreachable for later turns and orphaned session transcripts accumulating.
- `impact:security`: Allowing external hook callers to re-enter existing sessions changes routing and trust boundaries and must preserve explicit security gates.
- `maturity:stable`: The affected HTTP hook ingress path is under `gateway-runtime` HTTP APIs, and the maturity scorecard marks `gateway-runtime` M4 Stable.

## Summary

Keep open: current main and the latest release still force hook-agent dispatch through isolated cron sessions, so a stable hook `sessionKey` cannot preserve multi-turn transcript state. The open linked implementation PR is the active review path and should be landed or rejected before this issue closes.

## What This Changes

The issue requests multi-turn webhook hook sessions by reusing an existing session when callers provide a stable `sessionKey`.

## Best Possible Solution

Review and either land or reject https://github.com/openclaw/openclaw/pull/75918; the maintainable end state is an explicit `sessionMode: "isolated" | "persistent"` hook option with isolated defaults, documented security guidance, and regression coverage across direct payloads, mappings, transforms, schema/docs, and session reuse.
