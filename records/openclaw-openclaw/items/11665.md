## Summary

Keep open: current main still forces hook-agent requests through isolated cron sessions, so stable hook session keys cannot preserve multi-turn transcript state; the linked open PR is the current candidate fix and has not merged.

## What This Changes

Requests explicit multi-turn support for hook/webhook agent calls so a stable `sessionKey` can reuse an existing session instead of creating a fresh transcript each turn.

## Best Possible Solution

Review and either land or reject https://github.com/openclaw/openclaw/pull/75918 as the canonical fix path, preserving isolated default behavior while adding a documented persistent hook-session opt-in with schema, docs, tests, and trust-boundary proof.

## Reproduction Assessment

Yes, by source inspection: current main routes hook-agent requests through isolated cron jobs, which pass `forceNew=true` and bypass sessionId reuse even with a stable session key.

## Solution Assessment

Unclear until the linked fix PR finishes review; the explicit `sessionMode` opt-in appears safer than automatic reuse because it preserves isolated defaults and makes the trust boundary visible.
