- `P2`: This is a normal-priority hook/session improvement with concrete production workaround reports and source proof, but no emergency outage evidence.
- `impact:session-state`: Stable hook sessionKey values currently cannot preserve the intended multi-turn session context across webhook invocations.

- `impact:security`: The requested persistent hook mode changes how externally triggered hook calls can target durable session context and needs an explicit trust boundary.
- `maturity:stable`: The affected hook ingress path belongs to the Gateway runtime HTTP APIs surface, which qa/maturity-scores.yaml scores as M4 Stable.

## Summary

Keep open: current main still forces hook-agent runs through isolated cron execution, so a stable hook sessionKey cannot reuse the existing session transcript, and the open closing PR has not merged.

## What This Changes

The issue asks for webhook hook-agent calls with a stable sessionKey to support multi-turn context by reusing an existing session through an explicit persistent mode or equivalent opt-in.

## Best Possible Solution

Review and either land or reject https://github.com/openclaw/openclaw/pull/75918 as the canonical fix, preserving isolated default behavior while adding a documented persistent hook-session opt-in.

## Reproduction Assessment

Yes. Source inspection on current main shows /hooks/agent creates an isolated cron job, the runner passes forceNew=true, and resolveCronSession only reuses an existing sessionId when forceNew is false.

## Solution Assessment

Unclear until maintainers finish reviewing the open fix PR. The explicit sessionMode direction is the best visible shape because it preserves isolated safe defaults while giving trusted hooks a narrow opt-in path.
