- `P2`: This is a normal-priority user-facing hook/session improvement with concrete source proof and production workaround reports, but no emergency outage evidence.

## Summary

Keep open: current main still routes hook-agent requests through isolated cron runs, so a stable hook sessionKey cannot reuse the existing fresh session id, and the issue is already paired with an open closing PR that has not merged.

## What This Changes

The issue requests persistent multi-turn webhook hook sessions when callers provide a stable sessionKey.

## Best Possible Solution

Review and either land or reject https://github.com/openclaw/openclaw/pull/75918 as the canonical fix, preserving isolated default behavior while adding an explicit documented persistent hook-session opt-in.

## Reproduction Assessment

Yes. Source inspection on current main shows /hooks/agent creates an isolated cron job, the runner passes forceNew=true, and resolveCronSession only reuses an existing sessionId when forceNew is false.

## Solution Assessment

Unclear until maintainers finish reviewing the open fix PR. The explicit sessionMode direction is the best visible shape because it preserves isolated safe defaults while giving trusted hooks a narrow opt-in path.
