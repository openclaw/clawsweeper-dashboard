- `P2`: This is a normal-priority user-facing hook/session improvement with concrete source proof, production reports, and a bounded blast radius.
- `impact:session-state`: Stable hook `sessionKey` values currently cannot preserve the intended multi-turn session context across webhook invocations.

- `impact:security`: The requested persistent hook mode changes how external authenticated hook callers can target session context and needs an explicit trust boundary.
- `maturity:stable`: The issue affects Gateway runtime HTTP hook ingress, which maps to the M4 Stable `gateway-runtime` HTTP APIs surface.

## Summary

Keep open: current main still routes hook-agent requests through isolated cron runs that force a fresh session id, and the live closing candidate at https://github.com/openclaw/openclaw/pull/75918 has not merged yet.

## What This Changes

The issue requests multi-turn webhook hook support so stable hook `sessionKey` values can explicitly reuse an existing session instead of creating a fresh isolated transcript on every invocation.

## Best Possible Solution

Review and either land or reject https://github.com/openclaw/openclaw/pull/75918 as the canonical fix path, preserving isolated default behavior while adding a documented persistent hook-session opt-in.

## Reproduction Assessment

Yes. Source inspection on current main shows `/hooks/agent` creates an isolated cron job, the runner passes `forceNew=true`, and `resolveCronSession` only reuses an existing `sessionId` when `forceNew` is false.

## Solution Assessment

Unclear until maintainers finish reviewing the open fix PR. The explicit `sessionMode: "isolated" | "persistent"` direction is the best visible shape because it preserves the safe default while giving trusted hooks a narrow opt-in path.
