## Label Justifications

- `P2`: The issue breaks multi-turn webhook continuity for real integrations but has a costly external-history workaround and does not disable the core runtime.
- `impact:session-state`: Repeated webhook turns use new session identities and therefore lose the intended conversation state.
- `impact:data-loss`: The stable key is remapped to the newest session while earlier transcripts become orphaned from the integration’s logical conversation.
- `impact:security`: Persistent reuse would grant external hook callers access to an existing transcript, requiring explicit authentication and session-key scoping.
- `maturity:stable`: The issue affects the M4 Stable Gateway runtime feature, specifically its HTTP API and security-control surfaces.

## Summary

Current main still treats every hook-agent turn as an isolated run, so a stable accepted session key cannot preserve transcript continuity. Keep this issue open because the linked implementation PR remains open, while the persistent-session access boundary and its now-broad branch scope require maintainer review before landing.

## What This Changes

Allow trusted webhook-agent calls with a stable session key to opt into transcript reuse across turns while preserving isolated behavior by default.

## Best Possible Solution

Approve an explicit `isolated | persistent` hook-session contract, then land a focused implementation across direct payloads, mappings, transforms, schema, replay scope, and dispatch, with isolated remaining the default and persistent reuse gated by hook authentication plus bounded session-key policy.

Options:

- **Allow explicit persistent mode (recommended):** Permit opt-in reuse behind existing hook authentication and narrowly bounded session-key prefixes, while preserving isolated behavior by default.
- **Keep all hooks isolated:** Reject transcript reuse and update the public webhook contract to state that stable session keys do not preserve conversation history.

## Solution Assessment

Yes for the design direction: explicit opt-in persistence is safer and more maintainable than automatic reuse because it preserves current isolation and makes transcript access deliberate. The current linked branch should be narrowed or cleanly refreshed before landing because it now includes unrelated changes.
