## Label Justifications

- `P2`: The issue has source-confirmed production impact for webhook multi-turn sessions, but it is a bounded hook/session improvement rather than an emergency outage.
- `impact:session-state`: Stable hook session keys currently cannot preserve the intended conversation context across webhook invocations.
- `impact:data-loss`: Prior transcript state becomes unavailable to later webhook turns and repeated stable keys can leave orphaned session files.
- `impact:security`: The requested persistent mode changes how authenticated external hooks may target longer-lived agent context and needs explicit trust boundaries.
- `maturity:stable`: The affected `/hooks/agent` ingress path maps to Gateway runtime HTTP APIs, and Gateway runtime is scored M4 Stable.

## Summary

Keep open: current main and v2026.6.11 still route hook-agent requests through isolated cron-style sessions, so a stable hook `sessionKey` cannot preserve multi-turn transcript state; the open linked PR is the active candidate fix and should own review.

## What This Changes

The issue requests multi-turn webhook hook support so a stable hook `sessionKey` can reuse an existing session instead of creating a fresh isolated transcript every invocation.

## Best Possible Solution

Review and either land or reject https://github.com/openclaw/openclaw/pull/75918 as the canonical fix, preserving isolated defaults while adding a documented persistent hook-session opt-in with schema, docs, tests, and trust-boundary proof.
