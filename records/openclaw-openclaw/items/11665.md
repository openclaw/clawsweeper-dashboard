## Summary

Keep open: current main still routes hook-agent requests through isolated cron runs, so stable hook session keys cannot preserve multi-turn transcript state; the linked open PR is the candidate fix and has not merged.

## What This Changes

The issue requests persistent multi-turn webhook hook sessions so a stable hook session key can reuse conversation state instead of creating a fresh isolated session on every invocation.

## Best Possible Solution

Review and either land or reject https://github.com/openclaw/openclaw/pull/75918 as the canonical fix path, preserving isolated default behavior while adding a documented persistent hook-session opt-in.

## Reproduction Assessment

Yes by source inspection: current main routes hook-agent requests through isolated cron jobs, which pass forceNew=true and bypass sessionId reuse even with a stable session key.

## Solution Assessment

Unclear until the linked fix PR finishes maintainer review; the explicit sessionMode opt-in appears safer than automatic reuse because it preserves isolated defaults and makes the trust boundary visible.
