## Summary

Keep open: current main still routes hook-agent requests through isolated cron runs that force a fresh session id, and the linked open fix candidate has not merged yet.

## What This Changes

Request an explicit persistent webhook hook session mode so stable hook session keys can reuse transcript state instead of always starting isolated runs.

## Best Possible Solution

Review and either land or reject https://github.com/openclaw/openclaw/pull/75918 as the canonical fix path, preserving isolated defaults while adding a documented persistent hook-session opt-in with auth and prefix controls.

## Reproduction Assessment

Yes. Source inspection on current main shows direct and mapped hook-agent requests still create isolated cron-style runs, and the isolated runner passes forceNew=true so a stable hook session key cannot reuse the stored session id.

## Solution Assessment

Unclear until the linked PR finishes maintainer review. The explicit sessionMode opt-in appears safer than automatic reuse because it preserves the isolated default and makes the trusted-hook boundary visible.
