## Label Justifications

- `P2`: The issue has source-confirmed production impact for webhook multi-turn sessions, but it is a bounded hook/session improvement rather than an emergency outage.
- `impact:session-state`: Stable hook session keys currently cannot preserve the intended conversation context across webhook invocations.
- `impact:data-loss`: The reported behavior makes prior transcript state unavailable to later turns and leaves orphaned session files for repeated stable hook keys.
- `impact:security`: The requested persistent mode changes how externally triggered hooks may target longer-lived agent context and needs explicit trust boundaries.
- `maturity:stable`: The affected POST /hooks/agent path belongs to Gateway runtime, which is scored M4 Stable in qa/maturity-scores.yaml.

## Summary

Keep open: current main and latest release still route hook-agent requests through isolated cron-style sessions, so stable hook session keys cannot preserve multi-turn transcript state; the open linked implementation PR should remain the active fix path.

## What This Changes

Request persistent multi-turn webhook hook sessions when callers provide a stable sessionKey, preferably through an explicit sessionMode option.

## Best Possible Solution

Review and either land or reject https://github.com/openclaw/openclaw/pull/75918 as the canonical fix, preserving isolated defaults while adding a documented persistent hook-session opt-in with schema, docs, tests, and trust-boundary proof.
