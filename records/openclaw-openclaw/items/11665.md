## Label Justifications

- `P2`: This is a normal-priority user-facing hook/session improvement with source proof and production workaround reports, but no emergency outage evidence.
- `impact:session-state`: Stable hook sessionKey values currently do not preserve the intended multi-turn session context across webhook invocations.
- `impact:data-loss`: The report describes conversation history becoming unusable for follow-up turns and orphaned transcript files accumulating under repeated stable hook keys.
- `impact:security`: The requested persistent hook mode changes how external authenticated hook callers can target durable session context and needs an explicit trust boundary.
- `maturity:stable`: The affected hook ingress path is part of the M4 Stable gateway-runtime HTTP API surface in the maturity scorecard.

## Summary

Keep open: current main still routes direct and mapped hook-agent requests through isolated cron runs, so a stable hook sessionKey cannot reuse the existing session id, and the issue is paired with an open closing PR that has not merged.

## What This Changes

The issue requests opt-in persistent multi-turn webhook hook sessions when callers provide a stable sessionKey.

## Best Possible Solution

Review and either land or reject https://github.com/openclaw/openclaw/pull/75918 as the canonical fix, preserving isolated default behavior while adding an explicit documented persistent hook-session opt-in.

## Reproduction Assessment

Yes. Source inspection on current main shows /hooks/agent creates an isolated cron job, the runner passes forceNew=true, and resolveCronSession only reuses an existing sessionId when forceNew is false.

## Solution Assessment

Yes on direction, pending maintainer approval: the explicit sessionMode shape is the best visible solution because it preserves isolated safe defaults while giving trusted hooks a narrow opt-in path.
