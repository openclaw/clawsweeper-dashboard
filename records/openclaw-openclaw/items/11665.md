## Label Justifications

- `P2`: This is a concrete user-facing session continuity problem with a bounded hook/config surface, but it is not an emergency or live core-runtime outage.
- `impact:session-state`: Stable hook `sessionKey` values do not preserve the active transcript/session identity, causing agent context drift across webhook turns.
- `impact:data-loss`: The reporter and later commenters describe prior webhook transcript context becoming unreachable for the next turn and orphaned session files accumulating.
- `impact:security`: Allowing external hook callers to re-enter existing sessions changes routing and trust boundaries, so the implementation must preserve explicit security gates.
- `maturity:stable`: The affected hook ingress path is part of `gateway-runtime` Gateway HTTP APIs, and the scorecard marks `gateway-runtime` M4 Stable.

## Summary

Keep open: current main and v2026.6.11 still route direct and mapped hook-agent requests through isolated cron-style sessions, so a stable hook `sessionKey` cannot preserve multi-turn transcript state. The open linked implementation PR https://github.com/openclaw/openclaw/pull/75918 has closing syntax and should own the active review path before this issue is closed.

## What This Changes

Allow webhook hook-agent requests with a stable `sessionKey` to opt into reusing the existing session for multi-turn context instead of always creating a new isolated run.

## Best Possible Solution

Review, narrow, and either land or reject https://github.com/openclaw/openclaw/pull/75918; the maintainable end state is an explicit `sessionMode: "isolated" | "persistent"` hook option with `isolated` as the default, documented security guidance, and regression tests for direct payloads, mappings, transforms, schema/docs, and session reuse.
