## Summary

Keep open: current main and the latest release still route hook-agent requests through isolated cron runs, so stable hook session keys cannot preserve multi-turn transcript state; the open closing PR is the candidate fix and has not merged.

## What This Changes

The issue requests persistent multi-turn webhook hook sessions when callers provide a consistent sessionKey, preferably through an explicit compatibility-safe hook session mode.

## Best Possible Solution

Review and either land or reject https://github.com/openclaw/openclaw/pull/75918 as the canonical fix path, preserving isolated defaults while adding a documented persistent hook-session opt-in with existing auth and session-key prefix controls.

## Reproduction Assessment

Yes. Source inspection shows current main routes hook-agent requests through isolated cron jobs, which pass forceNew=true and bypass sessionId reuse even when a stable hook session key is supplied.

## Solution Assessment

Unclear until the linked fix PR finishes maintainer review. The explicit sessionMode opt-in appears safer than automatic reuse because it preserves isolated defaults and makes the trusted-hook boundary visible.
