## Label Justifications

- `P2`: The issue breaks multi-turn webhook context for real integrations but has a costly external-history workaround rather than blocking the core runtime.
- `impact:session-state`: Stable hook keys do not currently preserve the intended transcript and conversation state across invocations.
- `impact:data-loss`: Each isolated invocation replaces the active session mapping, leaving prior transcript state unavailable to subsequent turns and producing orphaned transcript files.
- `impact:security`: Persistent hook reuse would let authenticated external callers target durable session context, making agent and session-key authorization central to the design.

## Summary

Current main still forces direct and mapped hook-agent requests into fresh isolated sessions, so stable hook session keys cannot preserve transcript continuity. The open linked PR remains the active implementation candidate, but maintainers must approve its durable-session security boundary and review its broader adjacent changes before this issue can close.

## What This Changes

Add an explicit persistent mode so trusted webhook hook-agent calls with stable session keys can reuse conversation state.

## Best Possible Solution

Land a focused `sessionMode: "isolated" | "persistent"` hook surface with isolated as the default, an explicit stable session key for persistent mode, existing effective-agent and prefix authorization, and fresh-install, upgrade, isolation, and live reuse proof.

Owner confidence: high

Options:

- **Approve explicit persistent mode (recommended):** Keep isolated as the default and allow persistent reuse only through an explicit mode with effective-agent, request-session-key, and prefix policy enforcement.
- **Keep hooks isolated:** Reject durable transcript re-entry and update the public contract to state that hook-agent runs do not retain prior transcript context.

## Reproduction Assessment

Yes at source level: current main hard-codes hook-agent jobs as isolated, converts that into `forceNew: true`, and exposes no hook persistence mode. Multiple users also report the same observable loss of context across webhook calls.

## Solution Assessment

Yes, an explicit isolated-versus-persistent mode is the narrowest safe direction. Automatic reuse from any consistent key would silently change existing isolation and broaden the security boundary.
