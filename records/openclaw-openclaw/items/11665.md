## Summary

Keep open: current main still forces hook-agent requests through isolated cron runs, so a stable hook session key cannot preserve multi-turn transcript state. The open closing PR is the candidate fix and has not merged.

## What This Changes

The issue requests stable webhook hook session keys to preserve multi-turn conversation state, preferably through an explicit persistent session mode.

## Best Possible Solution

Review and land or reject https://github.com/openclaw/openclaw/pull/75918 as the canonical fix, preserving isolated default behavior while adding documented persistent hook-session opt-in with prefix/auth controls.

## Reproduction Assessment

Yes. Source inspection shows hook-agent requests are dispatched as isolated cron jobs, which pass forceNew=true and bypass existing sessionId reuse even with a stable session key.

## Solution Assessment

Yes on direction, not yet on completion. An explicit sessionMode opt-in is safer than automatic reuse because it preserves isolated defaults and makes the hook trust boundary visible.
