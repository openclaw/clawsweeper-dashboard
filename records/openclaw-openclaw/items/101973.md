Full review comments:

- **[P2] Key and prune workspace refs by workspace root:** `src/claws/workspace.ts:55`
  - body: `--workspace` makes the same Claw applicable to multiple workspace roots, and each ref stores `workspaceRoot`, but the table identity and UPSERT use only `(claw_id, entry_id)` while stale pruning also filters only by `claw_id`. Applying the same Claw in a second workspace will overwrite or delete the first workspace's provenance, so include `workspace_root` or an explicit workspace install id in both the primary key/conflict target and stale-delete predicate.
  - confidence: 0.91
- **[P2] Move workspace refs into the state schema:** `src/claws/workspace.ts:40`
  - body: This creates a durable shared-state table from the Claws feature module, but the shared state DB owns schema creation, migrations, and generated DB types. Add `claw_workspace_file_refs` to the canonical state schema/generated contract instead of creating it ad hoc here, otherwise doctor/migration/typed state code will not reliably see the persisted Claw workspace state.
  - confidence: 0.86
