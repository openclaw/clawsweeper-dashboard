## Summary

Keep open. Current main and latest release still refresh bootstrap files from disk for session-keyed runs and replace the session cache when file content changes, so the reported session-freeze/cacheWrite concern is not implemented or superseded.

## What This Changes

The issue asks OpenClaw to address Anthropic cacheWrite cost from mid-session edits to bootstrap-injected workspace files by adding a true session-freeze mode, dynamic-file cache-boundary config, or corrected docs.

## Best Possible Solution

Maintainers should choose one documented prompt-cache contract, then implement it with schema/docs/tests and live cache-read/write proof while keeping file-tool reads live.
