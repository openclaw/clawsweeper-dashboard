## Summary

Keep open. Current `main` and the latest stable release still refresh changed bootstrap files into the prompt and have no session-freeze or configurable dynamic-file surface, so the central cacheWrite concern remains real but needs maintainer product direction before implementation.

## What This Changes

The issue asks OpenClaw to stop mid-session writes to bootstrap-injected files from invalidating provider prompt-cache prefixes, or to document/configure dynamic bootstrap files so operators can avoid cacheWrite spikes.

## Best Possible Solution

Keep this open until maintainers choose one documented bootstrap cache contract, then implement it with focused source tests, config/docs updates if a new surface is accepted, and live or redacted usage proof for the Anthropic cacheWrite case.

Options:

- **Prioritize configurable dynamic files (recommended):** Add a narrow `bootstrapDynamicFiles`-style surface, aligned with the open dynamic-file tracker, so volatile files can move below the cache boundary while normal live bootstrap visibility remains available.
- **Add opt-in session freeze:** Add a `bootstrapFreezeMode: "session"`-style mode with unchanged live defaults and tests proving file-tool reads remain live while system-prompt bootstrap content stays frozen for the session.
- **Document live refresh only:** Keep the current content-equality refresh behavior and update prompt-caching/model-selection docs to warn that volatile bootstrap files above the boundary can drive cacheWrite spikes.
