## Summary

Keep open. The patch is a focused Matrix bug fix with no blocking findings: current main still classifies Matrix outbound media through a raw, case-sensitive MIME prefix helper, and this PR normalizes only the msgtype decision while preserving upload and `info.mimetype` passthrough. The standard fetched-HTTP media path already normalizes headers before Matrix sees them, so the strongest proof is the classifier boundary rather than a full live homeserver send.

## What This Changes

The PR lowercases Matrix outbound media content types before msgtype classification and adds tests for mixed-case image, audio, and video MIME strings.

## Best Possible Solution

Keep the normalization in the Matrix-local msgtype decision point, preserve the original mimetype for upload/event metadata, and avoid widening the plugin runtime media contract for this narrow fix.

## Reproduction Assessment

Yes from source for the classifier boundary: on current main, `resolveMatrixMsgType("Image/PNG")` reaches the raw `mediaKindFromMime` prefix checks and would fall through to file. I did not reproduce a full live Matrix homeserver send, and the standard remote loader path normalizes fetched HTTP headers before this point.

## Solution Assessment

Yes. This is the best narrow fix because it normalizes at the Matrix msgtype decision point without changing upload/mimetype passthrough or expanding the injected plugin runtime media API.
