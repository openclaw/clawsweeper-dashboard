## Summary

Keep open. Current main and the latest release still only partially satisfy this through the default-off admin HTTP RPC plugin: `status` and `agents.list` can be called when enabled, but the requested HTTP session list/detail/get query surface is not exposed.

## What This Changes

The issue requests lightweight bearer-authenticated HTTP endpoints for common Gateway session and agent queries to avoid CLI cold-start and WebSocket client overhead.

## Best Possible Solution

Define one approved authenticated HTTP query surface that reuses existing Gateway `status`, `agents.list`, and `sessions.*` handlers, documents the security contract, and avoids duplicating session business logic.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 expose the underlying `sessions.*` and `agents.list` Gateway RPC methods, but neither the core HTTP route table nor the admin HTTP RPC allowlist exposes the requested read-only session list/detail methods over HTTP.

## Solution Assessment

Unclear until maintainers confirm the API/security contract. The narrow maintainable shape is either an intentional admin HTTP RPC allowlist expansion for read-only session methods or a thin dedicated REST adapter over existing handlers.
