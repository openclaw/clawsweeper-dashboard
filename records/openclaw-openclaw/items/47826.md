## Summary

Keep open. Current main and v2026.6.11 still only partially cover the request through the default-off admin HTTP RPC plugin: `status` and `agents.list` are available when enabled, but the requested HTTP session list/detail/get surface is not exposed.

## What This Changes

Request to add lightweight bearer-authenticated HTTP endpoints for Gateway status, agents, session listing, and session detail so web apps can avoid CLI cold-start or WebSocket handshakes.

## Best Possible Solution

Define one approved authenticated HTTP query surface that reuses existing Gateway session and agent handlers; expanding the default-off admin HTTP RPC allowlist is the leanest path unless maintainers want a public GET-style REST contract.

- **Keep current surfaces:** Document WebSocket RPC and the current admin HTTP RPC methods as the supported integration paths and leave session query HTTP access absent.
