## Summary

Keep open. Current main only partially addresses the request through the default-off admin HTTP RPC plugin: `health`, `status`, and `agents.list` are available when enabled, but session list/detail queries are still not exposed over HTTP.

## What This Changes

The issue requests lightweight HTTP endpoints for common read-only Gateway queries so integrations can avoid slow CLI startup and WebSocket client setup.

## Best Possible Solution

Approve one authenticated HTTP query surface, preferably by extending the default-off admin HTTP RPC plugin with session read methods, reusing existing Gateway handlers and documenting the security contract.
