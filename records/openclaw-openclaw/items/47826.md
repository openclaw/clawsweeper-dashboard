## Summary

Keep open. Current main and v2026.6.11 only partially satisfy the request through the default-off admin HTTP RPC plugin: `health`, `status`, and `agents.list` are available over HTTP, but the requested session list/detail queries are still not exposed.

## What This Changes

The issue requests lightweight authenticated HTTP endpoints for common gateway read queries so integrations can avoid slow CLI cold starts or WebSocket handshakes.

## Best Possible Solution

If maintainers approve the boundary, extend the existing default-off admin HTTP RPC surface with explicit read-only session query methods plus focused auth/allowlist/docs tests; otherwise keep this linked to the broader session API discussion.
