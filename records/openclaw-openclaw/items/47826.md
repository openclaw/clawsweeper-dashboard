## Summary

Keep open. Current main and v2026.6.11 partially address the request with the default-off admin HTTP RPC plugin, but the shipped/current allowlist exposes `health`, `status`, and `agents.list` without exposing the requested session list/detail queries.

## What This Changes

Expose lightweight authenticated HTTP access for common gateway read queries, especially session and agent data, so integrations do not have to use the slow CLI or WebSocket control plane.

## Best Possible Solution

If maintainers accept the direction, extend the existing default-off admin HTTP RPC surface with explicit read-only session methods, docs, focused tests, and security wording; otherwise make https://github.com/openclaw/openclaw/issues/20934 the canonical broader session-control API discussion.
