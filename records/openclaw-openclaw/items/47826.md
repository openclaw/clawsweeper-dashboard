## Summary

Keep open. Current main and v2026.6.11 partially address the request through the default-off admin HTTP RPC plugin, but the shipped/current allowlist still exposes `health`, `status`, and `agents.list` without the requested session list/detail queries.

## What This Changes

The issue requests lightweight authenticated HTTP access to gateway health/status, agent list, session list, and session detail data without CLI startup or a WebSocket client.

## Best Possible Solution

Have maintainers decide whether read-only session queries belong in the existing default-off admin HTTP RPC plugin; if approved, add only the approved session query methods with docs and focused route/auth/allowlist tests.
