## Summary

Keep open. Current `main` and the latest release only partially cover this request through the default-off admin HTTP RPC plugin: `health`, `status`, and `agents.list` are available when the plugin is enabled, but session list/detail access is still not exposed through the requested lightweight HTTP query surface.

## What This Changes

Request to add lightweight authenticated HTTP endpoints for common Gateway read queries, especially session list/detail plus agent/status data, to avoid slow CLI cold starts and WebSocket client complexity.

## Best Possible Solution

Approve one authenticated HTTP query surface that reuses existing Gateway `sessions.*` and `agents.list` handlers, documents the security contract, and avoids duplicating session business logic.

- **Add Dedicated REST Endpoints:** Create authenticated GET routes for sessions and agents if maintainers want REST semantics instead of JSON-RPC over HTTP.
- **Defer HTTP Session Exposure:** Keep session list/detail access on WebSocket and CLI until maintainers are ready to own a broader HTTP control-plane contract.
