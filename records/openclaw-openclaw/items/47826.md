## Summary

Keep open. Current main and v2026.6.11 only partially cover the request through the default-off admin HTTP RPC plugin: `status` and `agents.list` are callable when enabled, but the requested HTTP session list/detail/get surface is still not exposed.

## What This Changes

The issue requests lightweight bearer-authenticated HTTP REST endpoints on the gateway for common read-only session and agent queries so integrations can avoid slow CLI startup and WebSocket control-plane setup.

## Best Possible Solution

Define one approved authenticated HTTP query surface that reuses existing Gateway `status`, `agents.list`, and `sessions.*` handlers, documents the security contract, and avoids duplicating session business logic.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 expose `status` and `agents.list` through the optional admin HTTP RPC surface, but not `sessions.list`, `sessions.describe`, or `sessions.get` over HTTP.

## Solution Assessment

Unclear until maintainers confirm the API and security contract. The narrow maintainable shape is either an intentional admin HTTP RPC allowlist expansion for read-only session methods or a thin dedicated REST adapter over existing handlers.
