## Summary

Keep open. Current main and v2026.6.11 partially cover this through the default-off admin HTTP RPC plugin, but session list/detail queries are still not exposed over HTTP and the remaining session-data surface needs maintainer product/security approval.

## What This Changes

The issue requests lightweight authenticated HTTP REST access to common Gateway queries such as sessions, agents, session detail, and health/status without CLI cold-start or WebSocket client setup.

## Best Possible Solution

Approve one authenticated HTTP query surface, preferably by extending the default-off admin HTTP RPC plugin with read-only session query methods plus docs/tests, while reusing existing session handlers and avoiding duplicated session business logic.

Rationale: The source gap is clear, but exposing session data over HTTP changes a security-sensitive operator API boundary and creates a public integration contract that automation should not choose alone.

Owner confidence: high

Options:

- **Extend admin HTTP RPC allowlist (recommended):** Add read-only session query methods to the default-off admin HTTP RPC plugin with explicit docs, auth/scope tests, and no duplicated session-store logic.
- **Add dedicated REST endpoints:** Create thin authenticated GET routes for session and agent queries if maintainers want REST semantics instead of JSON-RPC for web integrations.
- **Defer HTTP session exposure:** Keep session list/detail access on WebSocket and CLI until maintainers are ready to own a broader HTTP control-plane contract.

## Reproduction Assessment

Yes for the API gap. Source inspection shows current main and v2026.6.11 expose only partial HTTP access through health/status/agents paths, while session list/detail methods exist only as Gateway RPC handlers and are not HTTP-exposed.

## Solution Assessment

Unclear until maintainers choose the API and security shape. The narrow maintainable answer is to reuse the existing admin HTTP RPC plugin or add a thin REST adapter over existing handlers, not to duplicate session query logic.
