## Summary

Keep open: the scoped Control UI truncation remains useful, but the patch introduces a non-direct fallback labeling bug and the supplied screenshots do not show the real current-head Sessions table/details path with a long direct-chat key.

## What This Changes

This PR adds a Sessions-view helper to shorten long direct-chat session identifiers in table/detail cells, preserve fallback-row raw hover text, and cover the behavior with Vitest tests.

## Best Possible Solution

Keep the scoped direct-ID formatter, fix non-direct fallback labels to reuse the canonical fallback exactly, add exact cron/subagent regression tests, and require current-head Control UI proof before merge.

## Reproduction Assessment

Yes, at source level: current main renders fallback Sessions rows/details from `row.key` while the parser preserves full direct identifiers, so long direct-chat keys remain unshortened. I did not run a browser reproduction in this read-only review.

## Solution Assessment

No, not as currently written: the scoped truncation approach is acceptable, but the implementation also changes non-direct fallback rows and can duplicate typed prefixes. The safer fix is to keep the parser canonical and return `fallbackName` directly for non-direct keys, with exact tests.
