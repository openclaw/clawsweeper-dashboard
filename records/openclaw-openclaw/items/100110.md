## What This Changes

This PR changes Linux `ss` listener parsing to compare parsed endpoint ports exactly and adds two Unix `inspectPortUsage` regression tests for prefix-conflicting listener ports.

## Best Possible Solution

Land one focused exact-port parser fix with regression coverage after redacted real Linux `ss` or gateway diagnostic proof is added, then close the linked issue and the other candidate PR as superseded.

## Reproduction Assessment

Yes for source-level reproduction: current main's substring matcher can select `127.0.0.1:18789` while inspecting port `1878`, and the PR's parsed-port check avoids that false positive. I did not run Vitest because this review was read-only.

## Solution Assessment

Yes. Reusing the existing `parseTcpEndpoint` helper for exact port equality is the narrowest maintainable fix and matches the sibling netstat parser; fixed-column `ss` parsing would be more invasive for this bug.
