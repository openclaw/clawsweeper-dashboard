## Summary

This is a necessary, narrowly scoped bug fix: the shared resolver currently accepts whitespace-only credentials, while the patch consistently rejects blanks across provider selection, AWS/Vertex auth markers, and Azure Responses. No actionable correctness or security finding remains; keep the PR open for normal exact-head CI and merge review.

## What This Changes

The PR makes environment credential discovery ignore whitespace-only values, trims selected credentials, and routes Azure Responses through the shared resolved key.

## Best Possible Solution

Land one canonical non-blank credential predicate in the shared AI resolver, keep provider factories from independently rereading raw environment values, and retain focused fallback and no-egress regression coverage.

## Reproduction Assessment

Yes. The production helper deterministically selected a whitespace-only Anthropic OAuth token over a valid API key, and the Azure path produced the wrong downstream authentication error before the patch.

## Solution Assessment

Yes. Centralizing trimmed non-blank resolution is the narrowest maintainable fix because it aligns discovery, fallback ordering, auth-status reporting, and request-time client construction without adding configuration or provider-specific fallback logic.
