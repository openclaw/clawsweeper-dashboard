## Summary

Keep this PR open: it targets a real P1 idle-timeout failure reported in https://github.com/openclaw/openclaw/issues/113323, but the new notification runs only when OpenClaw emits a stream event. The reported configuration suppresses reasoning output, so reasoning-only provider chunks still produce no pushed event and can remain idle to the watchdog.

## What This Changes

The PR adds an idle-watchdog activity notification to OpenAI completions stream-event delivery so streamed reasoning activity can keep an agent run alive.

## System Context

The OpenAI completions transport turns provider chunks into OpenClaw assistant stream events, while the agent runtime’s idle watchdog listens for request activity through the abort signal. Provider reasoning chunks may be intentionally hidden from the assistant stream, but they still need to count as model progress before the watchdog decides to abort the run.

## Best Possible Solution
