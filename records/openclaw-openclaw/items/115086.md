## Summary

The patch appears to correctly distinguish caller-requested AbortSignal cancellation from timeout and output-limit termination, and it addresses the earlier already-aborted-signal finding. It should remain open for an owner to explicitly accept the documented plugin-facing semantic change: existing extensions that inspect a resolved `{ killed: true }` result after cancellation will instead receive a rejection.

## What This Changes

This PR makes agent-session command execution reject on caller AbortSignal cancellation, avoids spawning for an already-aborted signal, documents the public extension contract, and retains resolved killed results for timeout and output-limit termination.

## System Context

Agent-session tools launch local command processes for agent and extension work. The public extension API passes execution options into this command runner, which now maps caller cancellation to rejection while preserving structured results for internal process-kill safeguards.
