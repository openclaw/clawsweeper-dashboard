## Summary

Keep open: current main still routes Telegram Markdown through the shared markdown-it parser without a CJK-friendly delimiter rule, and no merged or open canonical fix owns this exact CJK emphasis failure.

## What This Changes

The issue reports Telegram Markdown leaving CJK bold labels such as `**社区显示：**Fable` as literal asterisks because CommonMark emphasis flanking rejects punctuation-inside/no-space-after CJK spans.

## Best Possible Solution

Fix the shared Markdown IR parser to support CJK-friendly emphasis delimiters, then prove Telegram legacy, rich, and chunked output render the reported CJK label pattern without a Telegram-only string hack.
