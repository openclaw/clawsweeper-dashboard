## Label Justifications

- `P2`: The issue describes a normal-priority core behavior and discoverability gap affecting multi-surface session context without evidence of data loss, security bypass, or an unusable runtime.
- `impact:session-state`: The reported failure is that the model does not discover readable same-agent session context and therefore behaves as though its session state is unavailable.
- `impact:ux-friction`: Users can work around the behavior by explicitly directing a session search, but the current prompt/tool wording makes that necessary in a documented default workflow.

## Summary

This issue remains necessary: the documented watched-session capability exists, but current model-facing system-prompt summaries still describe session tools only as generic “other sessions/subagents,” so they do not advertise the same-agent watched-group read path. The issue also has a `maintainer` label and asks for durable/prompt-visible context, which needs an explicit product and privacy decision before implementation.

## What This Changes

Make a main agent aware of readable watched same-agent group/topic sessions through accurate session-tool guidance, a recall cue, and potentially durable activity context.

## System Context

OpenClaw routes direct messages into a main session and lets that session read selected same-agent group activity under the default session scope. The system prompt and session tools shape whether the model discovers that context before responding to the user.

## Architecture Diagram

  B --> C[Session visibility rules]
  C --> D[Session list, search, and history tools]

  D --> F
  F --> G[Context-aware DM reply]

## Best Possible Solution

Land a focused first tranche that corrects model-facing session-tool language and adds a bounded recall instruction for readable watched sessions, with prompt tests; decide separately whether named dynamic watch context is worth its privacy and cache-cost tradeoff, reusing `stateVersion`/`changesSince` rather than adding a parallel delta model.
