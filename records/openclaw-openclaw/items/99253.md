## Summary

This should stay open: current main and the latest release keep tool execution structurally tied to real tool-call blocks, but I did not find a dedicated guard, warning, or display escape for assistant-generated text that looks like a fresh user transcript turn. The report is safety-sensitive and plausible from the supplied forensic logs, but the exact model-side incident is private and stochastic, so the next step is maintainer product/security review rather than an automatic repair PR.

## What This Changes

The issue requests a safety boundary so assistant-authored transcript-shaped text cannot be confused with or treated as a real user turn for tool authority, routing, session state, or display.

## Best Possible Solution

Define a maintainer-approved assistant-output role-boundary guard that keeps suspicious transcript-looking assistant content inert, visibly escapes or warns in UI and trajectory evidence, and explicitly decides whether same-turn tool execution should fail closed.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? No for the exact stochastic Anthropic generation, but source inspection gives a medium-confidence reproduction of the missing guard: assistant text shaped like a transcript role header is not covered by the existing tool-text diagnostic, visible-text sanitizer, or chat projection guard paths.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainers choose the product/security policy; the structural tool-call boundary is already mostly in the right layer, but warning, escaping, and any fail-closed behavior need an explicit decision.
