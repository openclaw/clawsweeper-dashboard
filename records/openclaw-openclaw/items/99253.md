This issue should stay open: current main appears to keep assistant text structurally inert for tool execution, but source inspection did not find a dedicated guard, warning, or display escape for assistant-generated text that looks like a fresh user turn. The report is safety-sensitive and plausible from the supplied logs, but the exact model-side incident is stochastic and private, so the next step is maintainer product/security review rather than automatic repair.

## What This Changes

The issue requests boundary hardening for assistant output that fabricates transcript-shaped user turns, including UI/trajectory warnings and runtime assurance that assistant-authored text cannot become user authority.

## Best Possible Solution

Define a narrow assistant-output role-boundary guard that keeps suspicious text inert, escapes or warns on transcript-role-looking assistant content in UI and trajectory evidence, and makes an explicit maintainer decision on whether same-turn tool execution should fail closed.
