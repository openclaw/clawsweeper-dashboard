## Summary

Keep open: current main has useful structural safeguards around real tool execution and inbound timestamp metadata, but the central safety request remains unresolved because there is no dedicated guard, warning, or display escape for assistant-generated text that looks like a fresh timestamped user turn. The report is plausible and security-sensitive, but the exact incident is stochastic/private, so this needs maintainer product/security review rather than closure or an automatic fix PR.

## What This Changes

The issue asks OpenClaw to prevent assistant-authored transcript-shaped user turns from being confused with real user input, session state, routing authority, or tool authorization.

## Best Possible Solution

Maintain an explicit assistant-output role-boundary policy: keep fake transcript headers inert, visibly escape or warn on suspicious assistant text in UI/trajectory surfaces, and decide separately whether same-turn tool execution should fail closed.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? No for the exact stochastic provider completion; source inspection gives a medium-confidence reproduction of the missing guard because assistant-visible sanitizing and tool-text diagnostics do not cover transcript-role headers.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainers choose the policy; the best shape is likely a narrow outbound assistant role-header guard plus UI/trajectory warning, while preserving the existing structured tool-call dispatch boundary.
