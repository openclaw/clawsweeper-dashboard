## Summary

Keep this PR open for repair and maintainer sponsorship. The proposed default sandbox-create command includes `--pull missing` (and exposes a GPU option) that are not documented by Docker’s current `sbx create shell` contract, so first-time sandbox creation is likely to fail; it also still lacks live `sbx` evidence and needs the required dependency/security authorization.

## What This Changes

This PR adds an `sbx` plugin that registers Docker Sandboxes as an agent-tool sandbox backend, with backend configuration, documentation, package/catalog metadata, unit tests, and an opt-in end-to-end smoke test.

## System Context

OpenClaw routes agent tool calls through a configured sandbox backend. This plugin registers Docker’s `sbx` command-line runtime so sandbox creation, command execution, and filesystem operations can run in Docker Sandboxes while the agent workspace remains bind-mounted from the host.
