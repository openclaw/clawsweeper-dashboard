- `maturity:stable`: The issue affects the Android app surface, which the maturity scorecard lists as M4 Stable with a distribution category.

## Summary

Keep open: current main supports Google Play distribution and local signed third-party APK archiving, but the latest GitHub release still does not publish an official standalone Android APK, and the only recent workflow candidate was closed unmerged with signing, security, automation, and proof concerns.

## What This Changes

The issue requests official prebuilt Android APK downloads, preferably built and uploaded by release automation.

## Best Possible Solution

Publish maintainer-approved signed standalone APKs through the existing Android release/signing lane to GitHub Releases or F-Droid, or explicitly document Google Play as the only official Android channel and provide a non-technical alternative for no-GMS users.

## Reproduction Assessment

Yes. The issue is reproducible from source and release inspection: current docs point to Google Play/source build paths, current tooling only archives a third-party APK locally, and v2026.6.11 release assets do not include an Android APK.

## Solution Assessment

No complete fix is on main yet. The best implementation should reuse the existing Android release signing/archive lane and publish only maintainer-approved signed artifacts, rather than adding a parallel ad hoc signing workflow.
