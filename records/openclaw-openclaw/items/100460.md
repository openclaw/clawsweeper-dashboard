## Summary

Keep open. Current main still has a narrow fallback-classification gap: Ollama throws the exact stream-end error, but the assistant/result fallback path does not classify that status-less provider error as fallback-worthy, so a configured fallback chain can still dead-end.

## What This Changes

The issue asks OpenClaw to treat Ollama `stream ended without a final response` failures as eligible for configured model fallback instead of surfacing a terminal unclassified failure.

## Best Possible Solution

Add a narrow replay-safe classification for this Ollama incomplete-stream failure at the provider/runtime fallback boundary, with regression coverage proving the embedded-run/model fallback path advances to the configured fallback without broadening arbitrary app-level error payloads.
