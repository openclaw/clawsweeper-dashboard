## Summary

Keep open. Current main still emits the exact Ollama incomplete-stream error and the embedded-result fallback classifier does not treat this unclassified non-GPT provider error payload as fallback-worthy, so a configured fallback chain can still dead-end.

## What This Changes

The issue asks OpenClaw to treat Ollama incomplete-stream failures as fallback-eligible so configured model fallbacks can answer instead of surfacing a terminal channel error.

## Best Possible Solution

Add a narrow Ollama incomplete-stream classification at the provider/runtime fallback boundary with regression tests proving embedded error payloads advance to configured fallbacks, without adding a new config knob or broadening generic application errors.
