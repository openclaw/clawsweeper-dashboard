## Summary

Keep open. Current main still has the reported fallback gap: Ollama can throw the exact incomplete-stream error, but the embedded-result/provider classifier does not map that status-less error to a failover reason, so a configured fallback chain can still end in a terminal `LLM request failed` result; no linked PR or canonical issue now supersedes this focused report.

## What This Changes

The issue requests that Ollama incomplete-stream errors be classified as failover-eligible so configured model fallbacks are attempted instead of ending with `LLM request failed`.

## Best Possible Solution

Classify the exact Ollama incomplete-stream failure as replay-safe at the provider/runtime fallback boundary and advance to the configured fallback only when no user-visible output or side effects were committed.
