## Summary

Keep open. Current main and the latest release still lack the requested ACP `affinityKey` or `mode="persistent"` `sessions_spawn` contract, and the existing ACP session path remains thread-bound; related cron and hub-delegated work overlaps the area but does not implement cron/hook/orchestrator affinity reuse.

## What This Changes

The issue requests a first-class ACP `sessions_spawn` persistence path for cron or orchestrator sessions using `mode="persistent"` and `affinityKey` rather than channel thread binding.

## Best Possible Solution

Define an explicit cron/hook/orchestrator ACP affinity contract scoped by requester identity, backend, cwd, and affinity key, then update schema, runtime, docs, and regression tests while keeping thread-bound `mode="session"` intact.

## Reproduction Assessment

Yes, source-level. Current main still has no `affinityKey` schema or runtime path, accepts only `run` and `session`, generates random ACP child session keys, and rejects ACP `mode="session"` without `thread=true`.

## Solution Assessment

Unclear. The downstream `mode="persistent"` plus `affinityKey` shape is plausible, but maintainers still need to choose ownership, lifecycle, cleanup, and security scope before implementation.
