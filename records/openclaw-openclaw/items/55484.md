## Summary

Keep open. Current main and v2026.6.11 still lack an official ACP `sessions_spawn` `mode="persistent"` or `affinityKey` contract, still create fresh random ACP session keys, and still reject ACP `mode="session"` without `thread=true`; related decoupling, cron, and hub-delegation items are partial or adjacent rather than a merged fix for cron/hook affinity.

## What This Changes

The issue requests non-thread persistent ACP session affinity for cron and orchestrator sessions, including a stable affinity key rather than channel-thread binding.

## Best Possible Solution

Define a first-class core ACP affinity contract for cron/hook/orchestrator spawns, with owner-scoped deterministic keys, explicit lifecycle/cleanup rules, security review, docs, and regression coverage; keep broad thread decoupling and scheduled ACP cron API work tracked separately.

## Reproduction Assessment

Yes, source-level. Current main still rejects ACP `mode="session"` without `thread=true`, creates random ACP session keys, and exposes no `mode="persistent"` or `affinityKey` `sessions_spawn` parameter.

## Solution Assessment

Unclear. The downstream `mode="persistent"` plus `affinityKey` shape is plausible, but the best fix needs maintainer agreement on owner scoping, lifecycle, security, and delivery semantics rather than a direct guard removal.
