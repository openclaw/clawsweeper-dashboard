## Summary

Keep open. Current main and v2026.6.11 still lack the requested ACP `affinityKey`/`mode="persistent"` sessions_spawn contract, and related cron or hub-delegation work does not implement the cron/hook/orchestrator affinity boundary described here.

## What This Changes

The issue requests a non-thread ACP persistent-session affinity contract for cron, hook, and orchestrator sessions.

## Best Possible Solution

Add an explicit ACP affinity-backed persistent path scoped by requester owner, backend, cwd, and affinity key, while keeping generic `mode="session"` thread-bound unless maintainers approve a broader contract.

## Reproduction Assessment

Yes. Source inspection is enough to reproduce the current gap: `sessions_spawn(runtime="acp", mode="session")` without `thread=true` reaches the `thread_required` guard, and the schema has no `affinityKey` or `persistent` mode.

## Solution Assessment

Unclear until maintainer review. The separate persistent affinity path described by the reporter looks safer than relaxing `mode="session"` globally, but it still needs an explicit product and security decision.
