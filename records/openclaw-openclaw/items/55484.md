## Summary

Keep open. Current main and the latest release still lack ACP `affinityKey` or `mode="persistent"` support in `sessions_spawn`, still expose ACP spawns as `run`/`session`, and still reject ACP `mode="session"` without `thread=true`; the remaining work needs maintainer product/security review rather than cleanup closure.

## What This Changes

The issue requests an ACP persistent session-affinity contract for cron and orchestrator sessions that does not depend on channel thread binding.

## Best Possible Solution

Define a first-class cron/hook/orchestrator ACP affinity contract scoped by requester identity, backend, cwd, and affinity key, then update schema, runtime, docs, and regression tests while preserving the thread-bound `mode="session"` contract.

## Reproduction Assessment

Yes, source-level: current main has no `affinityKey` schema or runtime path, accepts only ACP `run`/`session`, and rejects ACP `mode="session"` without `thread=true`. I did not execute a live ACP cron/hook flow because the missing contract is directly visible in source and docs.

## Solution Assessment

Unclear: the downstream `mode="persistent"` plus `affinityKey` shape is plausible, but maintainers still need to choose ownership, lifecycle, security scope, and relation to cron ACP or hub-delegated work before implementation.
