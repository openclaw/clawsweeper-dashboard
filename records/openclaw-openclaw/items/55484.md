## Summary

Keep open. Current main still lacks an ACP `mode="persistent"` or `affinityKey` `sessions_spawn` contract, still rejects non-thread `mode="session"`, and still creates random ACP child session keys; related cron and hub-delegated work does not implement the requested cron/hook affinity behavior.

## What This Changes

Request adds non-thread persistent ACP session affinity for cron, hook, or orchestrator callers while keeping existing thread-bound ACP sessions intact.

## Best Possible Solution

Define a maintainer-approved ACP persistent-affinity contract scoped by requester identity, backend, cwd, and affinity key, then update the tool schema, ACP spawn runtime, lifecycle cleanup, docs, and focused tests while leaving thread-bound `mode="session"` intact.

## Reproduction Assessment

Yes. Source inspection shows current main has no `affinityKey` schema or runtime path, accepts only `run` and `session`, rejects non-thread ACP sessions, and generates random ACP session keys.

## Solution Assessment

Unclear. The downstream `mode="persistent"` plus `affinityKey` shape is plausible, but ownership, lifecycle, cleanup, and security scoping need maintainer approval before implementation.
