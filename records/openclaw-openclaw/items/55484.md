## Summary

Keep open. Current main and the latest release still expose ACP `sessions_spawn` as `run`/`session`, still reject unthreaded ACP `mode="session"`, and do not provide the requested `mode="persistent"` plus `affinityKey` contract; related cron, thread-decoupling, and hub-delegation items do not close this narrower cron/hook affinity gap.

## What This Changes

Add a non-thread ACP persistent-affinity `sessions_spawn` contract for cron/hook/orchestrator sessions using `mode="persistent"` and `affinityKey` instead of thread-bound `mode="session"`.

## Best Possible Solution

Define a maintainer-approved ACP affinity contract that keeps `mode="session"` thread-bound, adds a separate non-thread persistent path scoped by requester owner, backend, cwd, and `affinityKey`, and lands focused source, docs, and security tests together.

## Reproduction Assessment

Yes. Source inspection on current main is enough to reproduce the missing contract: ACP `sessions_spawn` accepts only `run`/`session`, has no `affinityKey`, and rejects non-thread `mode="session"`.

## Solution Assessment

Unclear until maintainers choose the product boundary. A separate `mode="persistent"` plus `affinityKey` path looks safer than relaxing thread-bound `mode="session"`, but the owner/security scope needs explicit approval.
