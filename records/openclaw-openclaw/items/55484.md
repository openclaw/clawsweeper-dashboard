## Summary

Keep open. Current main and v2026.6.11 still lack an ACP `affinityKey` or `mode="persistent"` `sessions_spawn` contract, still generate random ACP child session keys, and still require `thread=true` for persistent ACP `mode="session"`.

## What This Changes

Request first-class non-thread persistent ACP affinity for cron, hook, and orchestrator `sessions_spawn` callers.

## Best Possible Solution

Define an explicit cron/hook/orchestrator ACP affinity contract scoped by requester identity, backend, cwd, and affinity key, then update schema, runtime, docs, and regression tests while preserving thread-bound `mode="session"`.

Yes, source-level: current main accepts only `run`/`session` for ACP `sessions_spawn`, has no `affinityKey` field, and rejects `mode="session"` without `thread=true`. I did not run a live cron/hook flow because the missing contract is visible in source and docs.

## Solution Assessment

Unclear. The downstream `mode="persistent"` plus `affinityKey` shape is plausible, but maintainers still need to choose the ownership, lifecycle, cleanup, and security scope before implementation.
