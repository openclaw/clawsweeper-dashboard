## Summary

Keep open. Current main and v2026.6.11 still lack the requested ACP `affinityKey` or non-thread `mode="persistent"` `sessions_spawn` contract, and the remaining work needs maintainer product/security direction rather than stale cleanup.

## What This Changes

The issue requests non-thread persistent ACP session affinity for cron, hook, and orchestrator callers, scoped by requester/workspace/backend identity instead of channel thread binding.

## Best Possible Solution

Define a narrow maintainer-approved ACP affinity contract for cron/hook/orchestrator callers with owner-scoped reuse and cleanup rules, rather than globally relaxing thread-bound `mode="session"`.

Yes. Source inspection shows current main still rejects ACP `mode="session"` without `thread=true`, and the tool schema has no `affinityKey` or `mode="persistent"` path for `sessions_spawn`.

## Solution Assessment

Unclear until maintainers choose the product contract. A narrow cron/hook affinity mode looks safer than globally decoupling `mode="session"` from thread binding, but owner/security semantics must be decided first.
