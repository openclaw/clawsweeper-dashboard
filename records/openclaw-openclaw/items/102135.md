## Label Justifications

- `P2`: This is a bounded ACP/media dispatch bug that can fail image turns for text-only ACP-backed models without making the whole runtime unusable.
- `impact:message-loss`: The affected image turn can fail before the ACP model processes the user message because unsupported raw image attachments are still sent.
- `impact:auth-provider`: The failure depends on model capability routing between a text-only primary ACP model and a configured image-understanding model.

## Summary

Keep open: current main and the latest release still run ACP media understanding and then forward the same raw current image attachment into the ACP turn; the linked open PR is the candidate fix and should be reviewed rather than closing this issue early.

## What This Changes

The issue reports that ACP dispatch sends both media-understanding text and raw image attachments to text-only ACP models after image understanding succeeds.

## Best Possible Solution

Mirror the non-ACP current-turn image filtering in ACP dispatch: drop only raw current image attachments whose attachmentIndex already has an image.description, while preserving inline, extracted, recent-history, and undescribed images.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level: current ACP dispatch applies media understanding, then resolves and forwards the same current image attachment to runTurn. I did not run a live channel/acpx repro in this read-only cleanup pass.

## Solution Assessment

Yes, the narrow maintainable fix is ACP parity with the existing current-turn image filter. A blanket clear of all attachments after ctx.MediaUnderstanding would be too broad because it could drop inline images, PDF page images, recent-history context, or undescribed images.
