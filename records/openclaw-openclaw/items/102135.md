- `impact:message-loss`: The affected image turn can fail before the ACP model processes the user message because unsupported raw image attachments are still sent.
- `impact:auth-provider`: The failure depends on model capability routing between a text-only primary ACP model and a configured image-understanding model.
- `maturity:stable`: The affected ACP dispatch path is part of gateway runtime, which the maturity shortlist reports as M4 Stable.

## Summary

Keep open: current main and v2026.6.11 still run ACP media understanding and then forward raw current image attachments into `acpManager.runTurn()`, so the reported text-only ACP failure remains source-reproducible.

## What This Changes

The issue reports that ACP dispatch keeps forwarding raw image attachments to a text-only session model even after media understanding has converted the images into text.

## Best Possible Solution

Mirror the current-turn image filtering used by the non-ACP path: drop only raw current image attachments whose `attachmentIndex` has a successful `image.description`, while preserving inline images, extracted PDF page images, recent-history images, and undescribed current images.
