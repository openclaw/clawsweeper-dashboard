## Label Justifications

- `P2`: This is a bounded ACP/media dispatch bug that can break image turns for text-only ACP-backed models without making the whole runtime unusable.
- `impact:message-loss`: The affected image turn can fail before the ACP backend processes the user message because unsupported raw image attachments are still sent.
- `impact:auth-provider`: The failure depends on model capability routing between a text-only primary ACP model and a configured image-understanding model.
- `maturity:stable`: The affected gateway/ACP dispatch path maps to Gateway runtime, which is scored M4 Stable in qa/maturity-scores.yaml.

## Summary

Keep open: current main and v2026.6.11 still apply ACP media understanding and then forward resolved raw image attachments into ACP turns, and the linked closing PR remains open rather than merged.

## What This Changes

The issue asks ACP dispatch to stop passing raw current-turn image attachments to text-only ACP models after media understanding has already converted those images into text.

## Best Possible Solution

Keep this issue open until https://github.com/openclaw/openclaw/pull/102145 lands or is replaced by an equivalent narrow ACP fix that drops only described current image attachments while preserving undescribed, inline, extracted, and recent-history images.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Current main source shows ACP dispatch applying media understanding, resolving the same current image attachments, and forwarding those attachments into runTurn without checking image.description attachment indexes.

## Solution Assessment

Yes. The maintainable fix is to mirror the sibling current-turn image filter and drop only raw current images whose attachment indexes were successfully described, not to clear all attachments whenever media understanding exists.
