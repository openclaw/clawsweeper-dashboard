## Label Justifications

- `P2`: This is a bounded ACP/media bug that can fail image turns for text-only ACP-backed models without making the whole runtime unusable.
- `impact:message-loss`: The affected user image turn can fail before the ACP model processes the message because unsupported raw image attachments are still sent.
- `impact:auth-provider`: The failure depends on model capability routing between a text-only primary ACP model and a configured image-understanding model.
- `maturity:stable`: The issue names Discord as an affected channel and the maturity shortlist marks Discord Media and Rich Content as M4 Stable.

## Summary

Keep open: current main and the latest release still run ACP media understanding and then forward the same raw current image attachment into `acpManager.runTurn()`, so the reported text-only ACP failure remains source-reproducible.

## What This Changes

The issue requests that ACP dispatch stop forwarding raw image attachments after media understanding has already converted those images into text for a text-only ACP-backed model.

## Best Possible Solution

Mirror current-turn image filtering in ACP dispatch: drop only raw current image attachments whose `attachmentIndex` has a successful `image.description`, while preserving inline images, extracted PDF page images, recent-history context, and undescribed current images.

Yes, at source level: current ACP dispatch runs media understanding, then resolves and forwards the same raw current image attachment to `runTurn`. I did not run a live channel/acpx repro in this read-only cleanup pass.

## Solution Assessment

Yes, the best fix is a narrow ACP parity change with `resolveCurrentTurnImages`: filter described current-image indexes instead of clearing all attachments or changing public API/config behavior.
