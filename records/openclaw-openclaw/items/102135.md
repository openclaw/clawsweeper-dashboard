- `impact:message-loss`: The affected image turn can fail before the ACP model processes the user message because unsupported raw image attachments are still sent.
- `impact:auth-provider`: The failure depends on model capability routing between a text-only primary ACP model and a configured image-understanding model.
- `maturity:stable`: The issue affects Gateway runtime ACP/external runtime dispatch, which the maturity scorecard lists as M4 Stable.

## Summary

Keep open: current main and the latest release still forward raw ACP image attachments after media understanding, and https://github.com/openclaw/openclaw/pull/102145 is an open candidate fix that specifically closes this issue.

## What This Changes

This issue reports ACP dispatch sending raw image attachments to text-only ACP runtimes even after media understanding has converted those images into text descriptions.

## Best Possible Solution

Review https://github.com/openclaw/openclaw/pull/102145 and land a precise described-image filter that drops only current image attachments already represented by image.description outputs.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level: current main applies media understanding, then resolves and forwards the same current image attachment into ACP runTurn without checking image.description attachment indexes. I did not run a live channel/acpx repro in this read-only pass.

## Solution Assessment

Yes, the best fix is a narrow ACP parity change that mirrors the existing current-turn image filter. A blanket ctx.MediaUnderstanding attachment clear would be too broad because it could drop inline, extracted, recent-history, or undescribed images.
