- `P2`: This is a bounded ACP/media dispatch bug that can fail image turns for text-only ACP-backed models without making the whole runtime unusable.
- `impact:message-loss`: The affected image turn can fail before the ACP model processes the user message because unsupported raw image attachments are still sent.
- `impact:auth-provider`: The failure depends on model capability routing between a text-only primary ACP model and a configured image-understanding model.

## Summary

Keep open: current main still has the source-reproducible ACP dispatch bug, and the open closing PR is the candidate fix but has not merged.

## What This Changes

The issue asks ACP dispatch to stop forwarding raw current-turn image attachments after media understanding has already converted those images into text.

## Best Possible Solution

Land a narrow ACP dispatch parity fix, likely via https://github.com/openclaw/openclaw/pull/102145 after proof and review, that filters raw current-turn image attachments by successful image.description indexes before runTurn.

## Maintainer Decision

## Reproduction Assessment

Yes, at source level: current ACP dispatch applies media understanding, then resolves and forwards the same current image attachment to runTurn. I did not run a live channel/acpx repro in this read-only cleanup pass.

## Solution Assessment

Yes, the best fix is the narrow parity change already used by the non-ACP current-turn image path. A blanket ctx.MediaUnderstanding attachment clear would be too broad because it could drop other image sources that still need forwarding.
