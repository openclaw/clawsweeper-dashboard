## Label Justifications

- `P2`: This is a bounded ACP/media dispatch bug that can fail image turns for text-only ACP-backed models without making the whole runtime unusable.
- `impact:message-loss`: The affected image turn can fail before the ACP model processes the user message because unsupported raw image attachments are still sent.
- `impact:auth-provider`: The failure depends on model capability routing between a text-only primary ACP model and a configured image-understanding model.
- `maturity:stable`: The affected ACP reply dispatch path sits in the gateway runtime surface, which the scorecard lists as M4 Stable.

## Summary

Keep open: current main and the latest release still apply ACP media understanding and then forward raw current image attachments into `acpManager.runTurn()`, and the linked open fix PR is the right place to resolve the implementation before this issue closes.

## What This Changes

Reports that ACP dispatch sends raw image attachments to text-only ACP models even after media understanding has already added image descriptions.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/102145 or an equivalent narrow ACP parity fix that drops only described current image attachment indexes while preserving inline, extracted, recent-history, and undescribed images.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, source-level: current ACP dispatch applies media understanding, resolves the same current image attachment as base64, and passes attachments to `runTurn()` without checking described-image indexes. I did not run a live ACP backend or channel reproduction.

## Solution Assessment

Partly: the requested behavior is the right fix, but the literal proposed clear-all-attachments check is too broad. The best fix is the index-based filter used by the non-ACP sibling path so only already-described current images are dropped.
