## Label Justifications

- `P2`: This is a bounded ACP/media dispatch bug that can fail image turns for text-only ACP-backed models without making the whole runtime unusable.
- `impact:message-loss`: The affected image turn can fail before the ACP model processes the user message because unsupported raw image attachments are still sent.
- `impact:auth-provider`: The failure depends on model capability routing between a text-only primary ACP model and the configured image-understanding model.
- `maturity:stable`: The affected ACP dispatch runs in gateway-side runtime dispatch, and the scorecard lists Gateway runtime as M4 Stable.

## Summary

Keep open: current main and the latest release still forward ACP image attachments after media understanding, and the linked open PR is the current fix candidate rather than a reason to close this issue early.

## What This Changes

ACP dispatch should stop passing raw current-turn image attachments to ACP runtimes after media understanding has already converted those images into text for a text-only session model.

## Best Possible Solution

Land or close the linked open PR after review; the fix should mirror the non-ACP path by dropping only described current image attachments while preserving inline images, extracted/PDF images, recent-history images, and undescribed current images.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level: current ACP dispatch applies media understanding, resolves the same current image into a base64 ACP attachment, and forwards it to runTurn. I did not run a live channel/acpx repro in this read-only cleanup pass.

## Solution Assessment

Yes, the best fix is a narrow ACP parity change with existing current-turn image filtering semantics. A blanket clear when ctx.MediaUnderstanding has content would be too broad because it could drop inline, extracted, recent-history, or undescribed images.
