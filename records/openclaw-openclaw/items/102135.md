## Label Justifications

- `P2`: This is a bounded ACP/media bug affecting text-only model turns with image attachments, without making the whole runtime unusable.
- `impact:message-loss`: The raw image attachment can make the ACP model call fail after the user sent a valid channel message, suppressing the expected agent response.
- `impact:auth-provider`: The failure depends on model capability routing between a text-only primary model and the configured image-understanding model.

## Summary

Keep open: current main and v2026.6.11 still run ACP media understanding and then forward raw ACP image attachments, while a sibling non-ACP path already filters described current images. This is a narrow ACP dispatch bug, not a duplicate of the broader agent-RPC opt-in or durable media-memory requests.

## What This Changes

ACP dispatch should stop forwarding raw current-turn image attachments once media understanding has successfully converted those images into text for the turn.

## Best Possible Solution

Filter ACP raw media attachments by media-understanding image.description attachment indexes so described current images are represented only as text, while native attachments remain for undescribed current images, inline images, recent-history images, and extracted PDF page images.

Yes. The narrow maintainable fix is to reuse the existing described-image-index invariant in the ACP attachment merge path, rather than adding a new config option or changing the broader agent RPC behavior.
