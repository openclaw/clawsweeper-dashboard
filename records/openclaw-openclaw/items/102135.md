## Label Justifications

- `P2`: This is a bounded ACP/media dispatch bug that can fail image turns for text-only ACP-backed models without making the core runtime unusable.
- `impact:message-loss`: The affected image turn can fail before the ACP model processes the user message because unsupported raw image attachments are still sent.
- `impact:auth-provider`: The failure depends on model capability routing between a text-only primary ACP model and a configured image-understanding model.

## Summary

Keep open: current main and the latest stable release still apply ACP media understanding and then forward the raw current image attachment into ACP `runTurn`; an open linked PR now owns the candidate fix, so this issue should stay open until that PR lands or is closed.

## What This Changes

The issue asks ACP dispatch to stop forwarding raw current-turn image attachments once media understanding has already converted those images into text for a text-only ACP model.

## Best Possible Solution

Keep this issue open until https://github.com/openclaw/openclaw/pull/102145 either lands or is closed; the desired fix is a narrow ACP filter that drops only described current-image attachments by attachment index while preserving undescribed, inline, extracted, and recent-history images.

Yes, at source level: current ACP dispatch applies media understanding, then resolves and forwards the same current image attachment into `runTurn`. I did not run a live channel/acpx repro in this read-only cleanup pass.

## Solution Assessment

Yes, if implemented as the linked narrow index-based filter; a blanket clear whenever `ctx.MediaUnderstanding` is non-empty would be too broad because it could drop undescribed or non-current image payloads.
