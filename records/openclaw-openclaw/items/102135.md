## Summary

Keep open: current main and v2026.6.11 still forward current raw image attachments after media understanding, and https://github.com/openclaw/openclaw/pull/102145 is the open closing PR that should be reviewed rather than creating another fix path.

## What This Changes

The issue reports ACP dispatch sending raw current-turn image attachments to text-only ACP models even after media understanding has already injected image descriptions.

## Best Possible Solution

Review and land or close https://github.com/openclaw/openclaw/pull/102145; the fix should filter only raw current image attachments whose indexes already have image.description outputs while preserving undescribed, inline, extracted, and recent-history images.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level: current main applies media understanding, then resolves and forwards the same current image attachment into ACP runTurn without checking image.description attachment indexes. I did not run a live channel/acpx repro in this read-only pass.

## Solution Assessment

Yes, the best path is a narrow ACP parity fix matching the existing non-ACP described-image filter. Blanket-clearing attachments after any media understanding would be too broad because it could drop undescribed, inline, extracted, or recent-history images.
