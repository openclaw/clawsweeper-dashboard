## What This Changes

The PR changes Slack interactive reply parsing and tests so `H:MM`/`HH:MM` labels and dash-separated time ranges keep their label colons while colon-containing callback values and button style suffixes continue to parse.

## Best Possible Solution

Land one canonical Slack parser fix; this PR is the strongest current candidate if maintainers prefer preserving colon-containing callback values while fixing common clock-label cases.

## Reproduction Assessment

Yes from source. Current main's `parseChoice` uses the first colon as the delimiter, so a directive like `Fr 10.07. 9:00:slot_fr_0900` is parsed as label `Fr 10.07. 9` and value `00:slot_fr_0900`.

## Solution Assessment

Yes, with maintainer acceptance of the compatibility tradeoff. The H:MM heuristic is a narrower fix than the last-colon alternatives because it preserves existing callback values such as `ticket:123` and `/approve plugin:approval-123 deny`, but maintainers still need to choose the canonical semantics.
