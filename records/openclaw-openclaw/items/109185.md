## Summary

The source scenario is plausible, but the PR replaces an unbounded proxy-local body lifetime with an unconditional one-hour cutoff that can preempt longer configured agent/runtime budgets. The contributor also supplied only mocked fake-timer proof, so this is not ready to merge.

## What This Changes

The PR adds a post-header wall-clock deadline for proxied SSE response bodies and a fake-timer regression test for continuously dripping streams.

## Best Possible Solution

Keep chunk-idle protection, preserve the configured outer agent/provider deadline as the total lifetime owner, and add a loopback `/api/stream` proof that a dripping body is canceled by that existing signal; add a separate proxy lifetime only if maintainers explicitly choose and document that contract.
