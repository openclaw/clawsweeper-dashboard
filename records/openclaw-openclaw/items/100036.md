## Summary

Keep open: current main and v2026.6.11 still route Codex compaction through native app-server state with no OpenClaw-visible summary payload, and the related reports do not exactly own the topic-diversity failure after a topic switch.

## What This Changes

The issue reports that Codex native compaction can lose earlier topic context in long multi-topic sessions, causing short later messages to be interpreted under the most recent topic.

## Best Possible Solution

Design an owner-approved Codex continuity path that preserves bounded cross-topic anchors after native compaction, preferably by consuming an upstream summary if available or adding a capped OpenClaw topic/ambiguity projection without replaying an unbounded mirrored transcript.

## Reproduction Assessment

Yes for the source-level boundary, but not for the live model behavior: current source and tests show Codex compaction delegates to native app-server state without an OpenClaw-visible summary payload. I did not run a long Telegram/Codex session to reproduce the exact topic-switch misinterpretation.

## Solution Assessment

Unclear: the issue identifies plausible mitigations, but choosing between upstream summary exposure, a bounded topic index, context-engine projection changes, or raw-tail guarantees needs maintainer design. A blind one-file repair is not the best path yet.
