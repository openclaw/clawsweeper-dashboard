- `impact:ux-friction`: Users can work around the failure only by starting a new session or restating full context after compaction, which adds avoidable support and usage friction.

## Summary

Keep open: current main and v2026.6.11 still delegate Codex compaction to the native app-server without an OpenClaw-visible summary payload, and no exact duplicate owns the reported topic-diversity failure.

## What This Changes

Request that Codex-runtime sessions preserve enough cross-topic context after native compaction to avoid misinterpreting ambiguous later topic switches.

## Best Possible Solution

Design an owner-approved Codex continuity path that preserves bounded cross-topic anchors after native compaction, ideally by consuming an upstream summary if exposed or injecting a tested topic/ambiguity index without replacing Codex's native thread ownership.

## Reproduction Assessment

Source-reproducible, but not live-reproduced: current source and tests show Codex sessions delegate compaction to native app-server state and OpenClaw records no native summary payload. I did not run a long Telegram/Codex session to observe the model misinterpretation directly.

## Solution Assessment

Unclear: the report identifies plausible mitigations, but choosing between upstream summary exposure, a bounded topic index, context-engine projection changes, or raw-tail guarantees needs owner design. A blind one-file repair is not the best path yet.
