## Summary

Keep open: current main and the shipped v2026.6.11 behavior still route Codex-runtime compaction through the native app-server without an OpenClaw-visible structured summary, and the related issues overlap but do not fully own the topic-diversity failure after a later topic switch.

## What This Changes

The issue reports that Codex-runtime native compaction drops older topic context, causing ambiguous follow-up messages after a topic switch to be interpreted in the most recent topic instead of preserving or recovering topic diversity.

## Best Possible Solution

Design an owner-approved Codex continuity path that preserves bounded cross-topic anchors after native compaction, preferably by consuming an upstream summary if available or adding a capped OpenClaw topic/ambiguity projection without replaying an unbounded mirrored transcript.

## Reproduction Assessment

No for the exact user-visible topic-switch failure: this review did not run a long Telegram/Codex session. Yes for the source-level boundary: current code and shipped tests show Codex compaction delegates to app-server state without an OpenClaw-visible structured summary payload.

## Solution Assessment

Unclear: the issue lists plausible mitigations, but choosing between upstream summary exposure, bounded topic indexing, context-engine projection changes, or raw-tail guarantees needs maintainer design. A blind one-file repair would not be the best fix yet.
