## Summary

This remains a meaningful but broad product and architecture request: current memory search supports ordinary provider/model reindexing, while the public embedding-provider contract still exposes flat query and batch inputs that do not fully express provider-managed document-group contextualization. The issue should stay open for a maintainer decision on a generic plugin/runtime contract rather than immediately adding Voyage-specific core behavior. ([github.com](https://github.com/openclaw/openclaw/raw/refs/heads/main/src/plugins/types.ts))

## What This Changes

Requests first-class contextual embedding semantics for native memory indexing, querying, index identity, migration, diagnostics, result provenance, privacy, and rollback.

## Best Possible Solution

Define a provider-neutral contextual embedding capability and memory index-generation contract first, then implement Voyage contextual embeddings in its provider plugin with atomic reindex/cutover, bounded diagnostics, and rollback coverage.
