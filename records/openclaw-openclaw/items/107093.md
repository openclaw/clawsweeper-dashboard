## Summary

This should remain open as a meaningful product and architecture request. Current main supports asymmetric query/document labels and atomic provider/model reindexing, but the embedding contract still cannot represent document-group contextualization required by providers such as Voyage contextual embeddings; the permanent plugin, storage, migration, and diagnostics boundary needs maintainer direction first.

## What This Changes

Requests first-class contextual embedding semantics for native memory indexing, querying, migration, diagnostics, provenance, and rollback.

## Best Possible Solution

Add a provider-neutral contextual embedding capability at the memory-plugin boundary: grouped document chunks and contextual queries, an explicit provider-owned index fingerprint covering mode and boundary strategy, atomic side-by-side SQLite cutover with verified rollback, bounded status metadata, and a Voyage implementation owned by its provider plugin rather than a Voyage-specific core branch.
