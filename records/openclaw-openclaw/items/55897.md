## Summary

Keep open: current main and v2026.6.11 still intentionally use oldest-first round-robin auth-profile ordering rather than MRU/last-success stickiness, while the 402 classifier/failover path exists but the reported intermediate chat rendering still needs live multi-key proof before changing auth-routing semantics.

## What This Changes

Request to add MRU/last-success auth profile stickiness for multiple same-provider API keys and suppress intermediate 402 failover errors unless every profile fails.

## Best Possible Solution

Define an additive, compatibility-safe auth-profile routing policy that preserves current defaults unless maintainers approve MRU/failover-only behavior, then back it with focused resolver/failover tests, docs, and live multi-key 402 proof.

## Reproduction Assessment

Partly yes: current source and tests prove the ordering half because `lastGood` is ignored and same-type profiles sort by oldest `lastUsed`. No live multi-key 402 run was performed, so the intermediate chat-rendering claim is not high-confidence reproduced.

## Solution Assessment

No for a simple default flip: current docs and tests intentionally preserve round-robin behavior, so the safer path is a maintainer-approved additive policy or mode plus live proof for the 402 UX path.
