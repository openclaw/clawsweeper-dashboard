## Summary

Keep open: current main and v2026.6.11 still intentionally use oldest-first round-robin auth-profile ordering rather than MRU/last-success stickiness, while the claimed user-visible intermediate 402 rendering still needs live multi-key proof before changing auth-routing semantics.

## What This Changes

Requests MRU-sticky API-key auth-profile ordering after session reset and silent intermediate 402 failover when rotating across multiple keys.

## Best Possible Solution

Define a compatibility-safe auth-profile routing policy that preserves current round-robin defaults unless maintainers explicitly approve MRU or failover-only stickiness, then back it with focused resolver/failover tests, docs, and live multi-key 402 proof.

## Reproduction Assessment

Partly yes: current source and tests reproduce the ordering half by intentionally ignoring lastGood and sorting same-type profiles by oldest lastUsed. No live multi-key 402 run was performed, so the user-visible intermediate-error claim is not high-confidence reproduced.

## Solution Assessment

No for a simple default flip: current docs and tests intentionally preserve round-robin behavior, so the safer path is a maintainer-approved additive policy or mode plus live proof for the 402 UX path.
