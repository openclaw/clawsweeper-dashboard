## Label Justifications

- `P1`: A routine plugin update or repair command can currently disable every active npm-backed plugin on npm 12 hosts, breaking real provider workflows.
- `impact:data-loss`: The reported failure removes active plugin configuration and allowlist state, requiring manual reconstruction.
- `impact:auth-provider`: Disabling provider plugins such as Codex removes configured OAuth and model-provider runtime paths.

## Summary

Keep open: npm 12 deliberately changed `npm view --json` to always return an array, matching the reported parser failure, and the observed update-repair path destructively disables working provider plugins after that metadata-only failure. ([newreleases.io](https://newreleases.io/project/npm/npm/release/12.0.0?utm_source=openai))

## What This Changes

Accept npm 12 metadata output and keep healthy installed plugins enabled when update metadata resolution fails.

## Best Possible Solution

Normalize both legacy object output and npm 12 arrays, require one unambiguous valid metadata record for supported exact/tag specs, and make pre-install metadata failures skip the update without changing `plugins.entries`, `plugins.allow`, or the running installation.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at the source and dependency-contract level: npm 12 always returns an array for `npm view --json`, while the reported current parser requires a single object. A live current-main CLI run was not performed.

## Solution Assessment

Yes, with one refinement: accept the npm 12 array contract without inventing highest-version selection for ambiguous arrays, and separately make metadata preflight failure non-destructive across every caller.
