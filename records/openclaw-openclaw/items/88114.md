## Summary

Keep open: this targets a real Windows update race, but the branch is not merge-ready because it changes generic Scheduled Task stop/restart semantics, can override durable operator state, and still lacks after-fix native Windows proof.

## What This Changes

The branch adds `schtasks /Change /DISABLE` after Windows Scheduled Task stop and `schtasks /Change /ENABLE` before Scheduled Task restart in `src/daemon/schtasks.ts`.

## Best Possible Solution

Land or replace with an update-scoped suspend/resume guard that disables only enabled Windows Scheduled Task autostart during mutable package replacement and restores only tasks this invocation disabled.

## Reproduction Assessment

Yes, source-reproducible. Current main stops the managed service before mutable update work and the Windows Scheduled Task stop implementation uses `/End` without disabling repeated triggers; I did not run a native Windows update in this read-only review.

## Solution Assessment

No. This branch is a plausible mitigation, but it is broader than the bug because it changes generic stop/restart behavior instead of owning temporary suspension inside the update lifecycle.
