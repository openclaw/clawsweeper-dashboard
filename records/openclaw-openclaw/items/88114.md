## Summary

Keep this PR open, but it is not merge-ready: the Windows update race is source-reproducible, while this patch changes generic Scheduled Task stop/restart semantics and lacks after-fix real Windows proof.

## What This Changes

The PR adds `schtasks /Change /DISABLE` to Windows Scheduled Task stop and `/ENABLE` to restart in `src/daemon/schtasks.ts`.

## Best Possible Solution

Land or replace an update-scoped suspend/resume guard that disables only enabled Windows Scheduled Task autostart during package replacement and restores only tasks that invocation suspended.

## Reproduction Assessment

Yes, source-reproducible. Current main stops the managed service before package replacement, and the Windows Scheduled Task stop implementation uses `/End` without update-scoped trigger suspension; I did not run a native Windows update in this read-only review.

## Solution Assessment

No. This is a plausible mitigation, but it is broader than the bug because it changes generic stop/restart behavior instead of owning temporary suspension inside the update lifecycle.

Full review comments:

- **[P1] Keep persistent disable out of generic stop:** `src/daemon/schtasks.ts:1335`
  - body: The new `/DISABLE` call is inside `stopScheduledTask()`, and the Windows service registry routes ordinary gateway stops to this function. That turns a normal stop into persisted autostart suppression, so the suspend should live in the update lifecycle instead.
  - confidence: 0.91
- **[P1] Restore only tasks this flow disabled:** `src/daemon/schtasks.ts:1360`
  - body: The new `/ENABLE` in `restartScheduledTask()` runs for normal restarts too, even when this flow did not disable the task. That can re-enable an operator-disabled task; track update-scoped suspension state and restore only tasks this invocation disabled.
  - confidence: 0.87
