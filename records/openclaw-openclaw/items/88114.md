## Summary

Keep open: current main and the latest release still have the `/End`-only Windows Scheduled Task stop behavior, but this branch is not merge-ready because it changes generic stop/restart semantics, lacks real Windows proof, and the stronger companion fix is still open, draft, and conflicting rather than a safe superseding landing path.

## What This Changes

The PR adds `/DISABLE` after stopping the Windows Scheduled Task and `/ENABLE` before restarting it.

## Best Possible Solution

Land or replace an update-scoped suspend/resume guard that disables only enabled Windows Scheduled Task autostart during mutable package replacement and restores only tasks this invocation disabled.

Yes. Source inspection shows current main and v2026.6.11 stop the Windows Scheduled Task with `/End` only, and the update lifecycle calls that stop path before mutable package work; I did not run a native Windows update in this read-only review.

## Solution Assessment

No. This is a plausible mitigation but not the best fix because it changes generic stop/restart behavior instead of owning temporary suspension inside the update lifecycle.
