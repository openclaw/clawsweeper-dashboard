## What This Changes

The branch adds unconditional Windows Scheduled Task `/DISABLE` after stop and `/ENABLE` before restart in `src/daemon/schtasks.ts`.

## Best Possible Solution

Land or replace an update-scoped suspend/resume guard that disables only enabled Windows Scheduled Task autostart during mutable package replacement and restores only tasks this invocation disabled.

## Reproduction Assessment

Yes. Current main stops the managed Windows service before package replacement and `stopScheduledTask()` uses `/End` without disabling legacy repeated triggers, which source-reproduces the reported update race even though I did not run a native Windows update here.

## Solution Assessment

No. This is a plausible mitigation, but it is broader than the bug because it changes generic stop/restart behavior instead of owning temporary suspension inside the update lifecycle.
