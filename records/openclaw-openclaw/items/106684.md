## Summary

Current `main` and the latest release use a transactional SQLite-backed auth-profile store, so the reported validation-then-reread of a token JSON file is not present in the runtime credential-discovery path. The report also does not identify an untrusted writer crossing OpenClaw’s documented security boundary.

## What This Changes

Investigate and eliminate a possible time-of-check/time-of-use race while loading agent authentication token files.

## Best Possible Solution

Keep the transactional SQLite auth-profile path; reopen or file a new security report only with a current call path showing separate validation and use, plus evidence that an untrusted OpenClaw-controlled process can perform the intervening replacement.
