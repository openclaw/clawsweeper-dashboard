## Summary

This is a credible fix for a real redaction-eviction failure, with concrete before/after runtime evidence. It should stay open for the requested security-owner decision because the PR establishes a new long-lived credential-retention policy: which values qualify, how the separate 512-entry budget is governed, and whether stale rotated values may remain masked until eviction.

## What This Changes

The PR adds a bounded durable exact-secret-redaction tier and registers boot-time audit keys plus SecretRef-resolved runtime values in it so transient credential churn cannot evict their masking.

## System Context

OpenClaw registers resolved credentials with an in-process exact-value redaction registry before diagnostic, proxy-capture, and support text is emitted. This PR changes how boot-time credentials and short-lived runtime credentials compete for that bounded registry, affecting both masked output and the auth sentinel check that asks whether a value is currently registered.

## Best Possible Solution

Have the security owner select the durable capacity and permitted caller set, then merge this bounded-tier implementation only if that policy is accepted; otherwise revise this branch toward the selected lifecycle-scoped retirement design while preserving the demonstrated no-under-redaction invariant.
