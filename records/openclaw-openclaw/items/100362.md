## Summary

Keep open: this is a plausible candidate for the canonical large ownerAllowFrom slowdown, but the patch is not merge-ready because it still rebuilds the large active owner list and Set on every authorization call, and the only after-fix proof is unit-test output.

## What This Changes

The PR modifies src/auto-reply/command-auth.ts to index commands.ownerAllowFrom entries by channel and use Set-backed owner membership checks.

## Best Possible Solution

Compile or cache normalized owner authorization state per stable config array, provider, plugin, and account so both the owner list and membership Set are reused across authorization calls, then prove the large-list path with focused regression coverage and real runtime or benchmark output.

Yes at source level: current main walks and linearly checks large owner allowlists during resolveCommandAuthorization, and the linked issue provides a concrete 9,282-entry configuration. I did not run a live 9,000-entry Gateway benchmark in this read-only review.

## Solution Assessment

No: this PR is only a partial optimization because it partitions channel-prefixed entries but still rebuilds the large active owner list and Set per authorization call. The maintainable fix should cache or compile the normalized authorization state itself.
