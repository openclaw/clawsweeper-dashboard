## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.87

Full review comments:

- **[P1] Skip disabled MCP servers in secret collection:** `src/secrets/runtime-config-collectors-core.ts:220-221`
  - body: `collectMcpAssignments` scans every `mcp.servers` entry and `resolveMcpSecretSurfaceActivity` treats a command-bearing server as active without checking `enabled === false`. Current launch setup filters disabled MCP servers out before runtime, so a disabled server with an unresolved SecretRef can still block startup/reload or materialize credentials even though it will not launch.
  - confidence: 0.9
- **[P1] Preserve literal MCP env and header strings:** `src/config/zod-schema.ts:369`
  - body: By adding `SecretInputSchema` to fields that already accepted literal strings and then collecting them with `collectSecretInputAssignment`, existing values like `$FOO` or `${FOO}` are reinterpreted as env SecretRefs on upgrade. If the env var is missing the runtime can fail resolution; if present, the child receives a different value than the saved literal, so the new support needs an object-only or otherwise compatibility-preserving path unless maintainers explicitly approve this break.
  - confidence: 0.86
- **[P1] Share the MCP stdio env drop predicate:** `src/secrets/runtime-config-collectors-core.ts:225-226`
  - body: The collector only blocks `isDangerousHostEnvVarName(envKey)`, but current main's launch path drops a broader MCP-specific set via `toMcpEnvRecord` and `isDangerousMcpStdioEnvVarName`. After rebase, refs for keys launch will drop can still be resolved or block startup even though the child process will never receive them, so the collector needs to reuse the same predicate as launch.
  - confidence: 0.88
