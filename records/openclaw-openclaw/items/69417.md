## Summary

Keep this PR open, but it still has merge-blocking compatibility and security issues. The PR widens core MCP server `env` and `headers` config values to SecretInput/SecretRef, wires those targets into runtime resolution, audit/configure, docs, and tests.

## Best Possible Solution

Land this only after MCP SecretRef collection mirrors the actual enabled launch surface, shares the stdio env drop policy, and has an explicit maintainer-approved compatibility rule for existing literal MCP strings.

## Solution Assessment

No, the current PR is a plausible implementation but not the best merge shape yet. The maintainable fix is to make MCP SecretRef resolution follow the same enabled/transport/env-drop contract as launch and to settle the literal-string compatibility rule before landing.

Overall correctness: patch is incorrect

Full review comments:

- **[P1] Skip disabled MCP servers in secret collection:** `src/secrets/runtime-config-collectors-core.ts:68-71`
  - body: `loadMergedBundleMcpConfig` removes configured MCP servers with `enabled === false` before launch, but this new activity check calls the launch resolver first and marks any command-bearing server active. A disabled server with an unresolved SecretRef would now block startup/reload, and a resolvable one can materialize credentials for a server OpenClaw will not launch.
  - confidence: 0.9
- **[P1] Preserve literal MCP env and header strings:** `src/secrets/runtime-config-collectors-core.ts:231`
  - body: `collectSecretInputAssignment` uses `coerceSecretRef`, which treats exact `$NAME` and `${NAME}` strings as env SecretRefs. These MCP env/header fields are existing literal string surfaces, so existing configs can start failing resolution or have literal values replaced with host env values on upgrade.
  - confidence: 0.88
- **[P1] Share the MCP stdio env drop predicate:** `src/secrets/runtime-config-collectors-core.ts:225`
  - body: `envKeyBlocked` only calls `isDangerousHostEnvVarName`, but the launch path drops the broader MCP stdio policy through `toMcpEnvRecord` and `isDangerousMcpStdioEnvVarName`. SecretRefs for launch-dropped inherited keys such as `ANSIBLE_CONFIG` can still resolve or block startup here.
  - confidence: 0.87
