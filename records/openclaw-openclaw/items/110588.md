## Summary

The OAuth handler currently writes an empty MiniMax Portal model list even though the plugin’s canonical catalog contains the M3 context metadata, so the proposed persistence change is directionally correct and the submitted redacted live output is relevant. However, it only repairs configurations created by a future OAuth login; existing OAuth configurations retain the empty list after upgrade, so this is not yet the complete upgrade-safe fix.

## What This Changes

The PR replaces the empty `minimax-portal` OAuth `models` config patch with the bundled Portal catalog and updates the OAuth-patch assertion.

## Best Possible Solution

Persist the canonical Portal catalog for future OAuth logins and add a narrow MiniMax-owned Doctor/config migration that fills only legacy empty `minimax-portal.models` entries while preserving user-customized model lists.
