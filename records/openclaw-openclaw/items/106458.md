## Summary

Keep it open for an explicit API decision and live proof rather than treating the implementation tests as sufficient merge evidence.

## What This Changes

The PR adds a typed `inbound_debounce` plugin hook, extends the shared inbound debouncer for asynchronous per-message decisions, and integrates the policy with WhatsApp rich-message batching.

## Best Possible Solution

Adopt the generic hook only after maintainers approve its stable cross-channel semantics, require an example plugin plus redacted live WhatsApp proof for debounce, bypass, timeout, control-command, and rich-batch cases, and document whether conversation-level configuration remains an alternative or is superseded.
