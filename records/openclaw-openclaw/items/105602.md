## Summary

Current main still enters fallback plugin-manifest discovery for both warm-turn MCP fingerprint validation and LSP bundle loading even though the embedded attempt already owns a compatible metadata snapshot. The bug remains necessary and narrowly actionable, but the active assignment and protected `maintainer` label require explicit maintainer handling rather than automated repair.

## What This Changes

Reuse the Gateway-owned plugin metadata snapshot for bundled MCP and LSP configuration checks during warm agent turns.

## Best Possible Solution

Thread the attempt-scoped manifest registry through MCP fingerprint/runtime creation and LSP bundle loading, without adding another cache, and add focused coverage proving repeated warm calls do not invoke fallback registry discovery while still detecting real config changes.
