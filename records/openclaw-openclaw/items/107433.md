## Summary

Keep open: current main supports only built-in volatile exclusions and still lacks an operator-declared, manifest-verified omission contract; this is a legitimate security-sensitive feature requiring explicit maintainer direction.

## What This Changes

Add fail-closed, manifest-backed intentional omission contracts for protected or reconstructable paths handled by `openclaw backup create` and `openclaw backup verify`.

## Best Possible Solution

Add one explicit versioned omission-plan input that resolves to concrete anchored manifest entries, records classifications and recovery instructions, rejects traversal and unsafe wildcard expansion, and keeps every undeclared read or planning failure fail-closed.

- **Retain strict inclusion:** Keep the present behavior and require protected datasets to be relocated, made readable, or backed up by a separate producer.
