## Summary

Keep open. Current main intentionally fails closed except for built-in volatile filtering and does not provide an operator-declared, manifest-verified omission contract; the request is valid but needs maintainer agreement on its security and backup-completeness semantics before implementation.

## What This Changes

Add an explicit, traversal-safe backup omission contract whose classified omissions are recorded in the archive manifest and validated during backup creation and verification.

## Best Possible Solution

Adopt a maintainer-approved, versioned backup-plan format that initially permits exact anchored paths only, records each resolved omission and recovery contract in the manifest, keeps undeclared unreadable paths fatal, and clearly separates creation-time source-plan checks from offline archive verification.

Options:

- **Versioned exact-path plan (recommended):** Add an explicit plan input with traversal-safe exact paths, required classifications and recovery guidance, resolved creation-time observations, and no wildcard support initially.
- **Built-in datasets only:** Allow omissions only for narrowly defined OpenClaw-owned reconstructable datasets, avoiding an operator-configurable general exclusion surface.
- **Retain strict failure:** Decline omission support and preserve the current requirement that operators relocate data, adjust the selected backup scope, or use an external producer.
