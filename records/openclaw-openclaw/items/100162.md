## Summary

Keep this open: current main still has a source-reproducible completed-empty cron finalization path, and the direct fix is the open closing PR https://github.com/openclaw/openclaw/pull/100229 rather than landed code. The parser-side PR https://github.com/openclaw/openclaw/pull/90450 is useful complementary work for the streamed-then-empty subset, but it intentionally does not handle genuinely empty completions.

## What This Changes

The issue requests that delivery-requested embedded cron runs with genuinely empty final assistant payloads fail or surface an observable delivery signal instead of completing silently.

## Best Possible Solution

Land a narrow cron/runner finalization fix that treats unintentionally empty, delivery-requested completions as an error or retry signal while preserving explicit silent-empty replies and verified message-tool deliveries.

## Reproduction Assessment

Yes, source-reproducible. A mocked completed run with `payloads: []`, no error metadata, and delivery requested flows through `resolveCronPayloadOutcome` to empty delivery payloads, then `dispatchCronDelivery` treats that as silent delivery success instead of an observable failure.

## Solution Assessment

Yes in direction. The best fix belongs in cron/runner finalization for genuinely empty completions; the parser-side PR is complementary for recoverable streamed text, while watchdogs or new configuration would be broader than the bug requires.
