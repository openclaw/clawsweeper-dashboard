## Summary

The report identifies a concrete authorization mismatch: pairing approval treats `fs.listDir` as a write-scoped command even though invocation is admin-only. The directly linked fix remains open and unmerged, so this issue should remain open until that PR lands or is replaced.

## What This Changes

Require `operator.admin` when approving a paired node that advertises `fs.listDir`, matching the command’s invoke-time authorization.

## Best Possible Solution

Land the narrow core repair that classifies `fs.listDir` as admin-level during pairing approval, with resolver coverage and an end-to-end `node.pair.approve` regression proving a write-scoped operator is rejected.
