## Summary

Keep open: current main has targeted cron/tool-error hardening, but it still lacks a complete fail-closed or ledger-backed finalization policy for output unsupported by failed or missing tool work.

## What This Changes

The issue asks unattended cron and tool-backed agent output to fail cleanly instead of delivering fabricated or unsupported final messages after failed or missing tool work.

## Best Possible Solution

Define a maintainer-approved core finalization policy for unattended and tool-backed turns that uses structured run/tool state to suppress, replace, or clearly mark unsupported output.

## Reproduction Assessment

Yes at source level, but not from a live run: current main tests and helpers explicitly allow preferred final assistant text to recover a plain tool warning, and cron delivery proceeds for non-fatal outcomes.

## Solution Assessment

No complete solution exists on current main; marker filters are too narrow, and the better fix needs a structured finalization policy covering failed tools, missing required tool attempts, and unsupported success claims.
