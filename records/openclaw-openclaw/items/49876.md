## Summary

Keep open: current main still has targeted cron/tool-error hardening rather than the requested broad fail-closed finalization contract, so unsupported final assistant text can still be treated as cron output when no narrow fatal signal is present.

## What This Changes

The issue asks OpenClaw to fail closed or suppress unsupported cron output when required tool execution fails, is missing, or cannot verify completion.

## Best Possible Solution

Define a core cron/unattended finalization policy that derives deliverability from structured run and tool state, preserves explicitly verified recovery, and turns unsupported success-looking assistant text into suppression or a clear failure state before delivery.

## Reproduction Assessment

Yes at source level: current source and tests still allow final assistant visible text to become cron output after some warning/error paths when no narrow fatal signal is present. I did not run a live model reproduction in this read-only review.

## Solution Assessment

No complete fix is present; targeted denial and warning handling help adjacent cases, but the best solution is a structured finalization contract tied to real tool/run state rather than marker-word filtering or one-off fatal-denial handling.
