## Summary

Keep open: current main has targeted cron/tool-error hardening, but still allows final assistant text to become cron output in paths where failed or missing tool work is not proven by structured run state, so the core fail-closed behavior remains unresolved.

## What This Changes

The issue requests that cron/unattended sessions stop delivering success-looking hallucinated output when required tool calls fail or are not actually executed.

## Best Possible Solution

Define a core cron/unattended finalization policy that derives deliverable output from structured run and tool state, and replaces unsupported success-looking assistant text with a clear failure or verification-needed result.

## Reproduction Assessment

Yes at source level: current main still has cron paths where final assistant visible text can be delivered without a broad failed-or-missing-tool finalization gate; no live run was executed in this read-only review.

## Solution Assessment

No complete solution is present; existing error markers and hooks help adjacent cases, but the best fix is a maintainer-approved structured finalization policy rather than trusting final assistant text.
