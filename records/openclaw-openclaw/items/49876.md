## Label Justifications

- `P1`: The issue affects real agent/channel workflows where users can receive apparently successful cron or chat output that is not backed by the required tool action.
- `impact:session-state`: The reported failure is a mismatch between the agent turn ledger, final assistant state, and delivered transcript state.
- `impact:security`: Unsupported success claims after failed or missing tools can misrepresent external writes, approvals, or operator-controlled actions.

## Summary

Keep open: current main has partial cron/tool-failure hardening, but it still allows final assistant text to recover or replace warning payloads after non-fatal tool errors, so the reported fail-cleanly behavior is not implemented.

## What This Changes

Issue requests structural handling for cron/chat agent turns that report successful output after failed or missing tool calls, especially on Telegram delivery paths.

## Best Possible Solution

Define a maintainer-approved tool-failure finalization policy for cron and chat delivery, then implement it with explicit tests for missing tool calls, failed mutating tools, warning-only recovery, and Telegram-facing delivery.

## Reproduction Assessment

Yes from source at medium confidence: current cron payload and failure-signal paths show non-fatal tool warnings can still be followed by deliverable final assistant text, though no live Telegram repro was run in this read-only review.

## Solution Assessment

No current implementation is sufficient: the existing hardening only covers narrow fatal exec-like errors and leaves the broader claim-versus-tool-ledger policy unresolved.
