## Summary

Issue #49876 should stay open: current main has several targeted cron/tool-error hardening paths, but it still allows final assistant text to be delivered without a general ledger-backed guarantee that claimed side effects or required tool calls actually happened.

## What This Changes

The issue asks OpenClaw to prevent unattended cron/chat agent runs from delivering hallucinated or unsupported success output when tool calls fail, are missing, or only appear in model text.

## Best Possible Solution

Define a maintainer-approved core finalization policy for unattended/tool-backed runs that uses structured tool/run state to suppress, replace, or clearly mark unsupported output, with explicit default and compatibility behavior.

## Reproduction Assessment

Yes at source level: current main still has a path where final assistant text is delivered without general tool-ledger verification, though this read-only review did not run a live cron reproduction.

## Solution Assessment

The issue is directionally correct, but marker filtering or a narrow fail-closed rule is not the best standalone fix; the durable fix should be a structured finalization policy based on tool/run state.
