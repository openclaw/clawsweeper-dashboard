## Summary

Keep open: current main has partial cron/tool-error hardening, but it still permits some failed-tool warning paths to be recovered or replaced by final assistant text before scheduled delivery, so the central trust-boundary problem remains.

## What This Changes

The issue asks cron isolated sessions to fail cleanly or suppress delivery after failed or unverifiable tool work instead of delivering hallucinated output.

## Best Possible Solution

Define a core cron/unattended finalization contract that derives deliverability from structured run and tool state, preserves explicitly verified recovery, and suppresses or cleanly errors unsupported success-looking assistant text.
