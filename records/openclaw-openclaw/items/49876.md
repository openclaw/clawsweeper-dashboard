## Summary

Keep open: current main has partial cron hardening, but it still allows final visible assistant text to recover some tool-warning/error payloads, so the requested fail-closed or ledger-backed finalization policy is not implemented.

## What This Changes

The issue requests fail-closed handling so cron or unattended agent sessions do not deliver fabricated final output after tool failures or incomplete work.

## Best Possible Solution

Add a maintainer-approved finalization policy that distinguishes recoverable diagnostics from unsupported success claims and blocks unattended delivery when required tool work failed or was never attempted.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What should OpenClaw treat as a fatal finalization failure for unattended cron/session delivery when the turn contains failed, missing, or unattempted tool work but also has final assistant text?

Rationale: Current code intentionally allows some recovery after tool warnings, while the issue asks for stronger fail-closed behavior that could suppress legitimate recovered output and has security implications.

Likely owner: steipete

Owner reason: The current cron finalization behavior in blame is from steipete's recent PR, making him the best available routing owner for the policy question.

Owner confidence: high

Options:

- **Ledger-backed fail-closed policy (recommended):** Require final delivery for unattended runs to be backed by successful required tool calls or explicit typed success evidence, suppressing unsupported success claims after failed or missing tool work.
- **Keep current recovery semantics:** Continue treating final assistant text as proof of recovery unless an explicit fatal signal or structured error is present, leaving this issue open only for narrower incidents.
- **Cron-only text-marker filter:** Add a narrow cron output filter for self-referential phrases such as mock data or placeholders, accepting that plain unsupported success claims remain possible.

Yes from source inspection: current cron helper tests show final assistant text can supersede tool-warning payloads, though I did not run a live cron reproduction.

## Solution Assessment

No as a text-marker-only fix: the thread has examples without marker phrases, so the maintainable fix should use finalization/tool-ledger evidence and a maintainer-defined fatality policy.
