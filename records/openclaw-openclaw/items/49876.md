## Summary

Keep open: current main has targeted cron/tool-error hardening, but it still permits success-looking final assistant text to recover or accompany tool-warning paths, so the reported fail-closed cron finalization problem is not fully solved.

## What This Changes

The issue asks isolated cron sessions to fail cleanly or suppress delivery instead of sending fabricated, placeholder, or unsupported final output after tool failures or unverifiable task completion.

## Best Possible Solution

Define a maintainer-approved unattended-run finalization contract where known fatal tool or run failures override success-looking assistant text, diagnostics remain visible, and optional broad claim verification lives in plugin/ClawHub hooks unless a core API gap is identified.

## Reproduction Assessment

## Solution Assessment

Unclear pending maintainer product and security direction; targeted fatal-error suppression exists, but broad phrase filtering is not the best core answer after #68051 was closed toward ClawHub and the remaining invariant is a typed unattended-run finalization contract.
