## Summary

Keep open: current main has targeted cron/tool-error hardening, but still allows final assistant text to recover or replace warning/error payloads unless a narrow fatal signal is present, so the central unattended-delivery trust problem remains.

## What This Changes

The issue requests fail-closed cron or unattended delivery when tool calls fail, required data is missing, or the final output is not backed by real tool/run state.

## Best Possible Solution

Define a core cron/unattended finalization contract that derives deliverability from structured run and tool state, preserves explicitly verified recovery, and suppresses or cleanly errors unsupported success-looking assistant text before delivery.
