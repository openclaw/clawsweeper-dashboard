## Label Justifications

- `P1`: The issue describes real unattended cron outputs claiming unsupported work, which is an urgent trust and delivery-boundary failure for agent workflows.
- `impact:session-state`: The core problem is drift between cron run state/tool results and the final output delivered to the user.
- `impact:security`: Fabricated cron output after failed tools can mislead users about external data access or operational changes in unattended runs.

## Summary

Keep open: current main and the latest release still allow final assistant text to recover non-fatal cron tool warnings, so the cron fail-closed trust boundary remains unresolved while broad arbitrary claim verification is already scoped outside core.

## What This Changes

The issue requests a cron/unattended delivery policy that suppresses or cleanly errors when isolated cron runs cannot verify tool/data completion instead of sending fabricated final text.

## Best Possible Solution

Define a narrow core invariant for cron/unattended runs: failed or missing tool evidence must not be converted into successful scheduled output, while broad arbitrary claim verification remains plugin/ClawHub scope.

- **Add Opt-In Strict Mode:** Preserve the current default but add an explicit strict cron finalization mode with focused tests and upgrade documentation.
