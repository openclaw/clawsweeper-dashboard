## Summary

Keep open: current main has targeted cron/tool-error hardening, but it still permits some failed-tool warning paths to be treated as recovered when final assistant text exists, so the requested ledger-backed fail-closed finalization policy is not implemented.

## What This Changes

The issue requests that cron and related agent sessions fail cleanly, stay silent, or suppress unsupported output when tools fail or required work cannot be verified.

## Best Possible Solution

Maintainers should define a core finalization policy for unattended and tool-backed turns that uses structured run/tool state to suppress, replace, or clearly mark unsupported output, with compatibility-safe warn/strict behavior and focused cron plus interactive coverage.

## Reproduction Assessment

Yes from source inspection: a cron run with a non-fatal tool warning plus final assistant text follows a recovery path; live production repro remains report-backed and was not re-run in this read-only review.

## Solution Assessment

No complete solution exists on current main; the issue's marker-filter idea is too narrow by itself, and the better fix is a structured finalization or ledger-backed policy that covers failed tools, missing tool attempts, and unsupported success claims.
