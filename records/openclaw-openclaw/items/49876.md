## Summary

Issue #49876 should stay open because current main has targeted cron/tool-error hardening, but it still lacks the broader fail-closed or ledger-backed finalization policy needed to prevent unsupported final assistant output after failed, unavailable, or missing tool work.

## What This Changes

The issue asks OpenClaw to prevent isolated cron and related agent runs from delivering fabricated success or operational output when required tool calls fail, are unavailable, or never run.

## Best Possible Solution

Define a maintainer-approved core finalization policy that derives delivery from structured run and tool-call state, blocking or clearly replacing unsupported success claims instead of trusting final assistant text alone.

## Reproduction Assessment

Yes at source level: current main still has paths where selected failed-tool warnings can be treated as recovered by final assistant text and then delivered, though this read-only review did not run a live cron or Telegram reproduction.

## Solution Assessment

No current solution is complete: marker filtering and narrow fatal error signals help adjacent cases, but the best fix is a structured finalization or ledger-backed policy covering failed tools, missing required attempts, and unsupported success claims.
