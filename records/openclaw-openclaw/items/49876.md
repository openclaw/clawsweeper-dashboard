## Summary

Keep open: current main has warning diagnostics, plugin hooks, and failed-tool metadata, but it still lacks a general cron/final-output policy that suppresses or cleanly fails delivery when tool work failed or was never attempted. Related open issues overlap the run-loop and response-gate design, but none fully supersedes this concrete unsupported-output-after-tool-failure report.

## What This Changes

Cron and unattended agent sessions should fail closed or stay silent instead of delivering fabricated or unsupported final output after failed or missing tool work.

## Best Possible Solution

Define a maintainer-approved core finalization policy that uses structured tool outcomes to suppress, retry, or clearly fail unsafe final output, while leaving optional linguistic claim-verification heuristics to plugin or ClawHub packaging unless core hooks are insufficient.

## Reproduction Assessment

Yes, at source level. Current main still has ordinary assistant-text finalization paths without a general failed-tool or ledger-backed fail-closed gate; the specific production incidents were not replayed in this read-only review.

## Solution Assessment

Unclear pending maintainer direction. The right layer is core finalization/tool-result policy, but the default behavior must be chosen carefully because blanket fail-closed delivery could break existing cron and local-model workflows.
