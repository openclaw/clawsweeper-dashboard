## Summary

Keep open: current main has targeted cron/tool-error hardening, but it still permits final assistant text to recover or replace warning/error payloads unless a narrow fatal signal is present, so the unattended-delivery trust problem remains.

## What This Changes

The issue asks OpenClaw to stop cron or unattended sessions from delivering fabricated, placeholder, or unsupported output after tool failures or unverifiable task completion.

## Best Possible Solution

Define a core cron/unattended finalization contract that derives deliverability from structured run and tool state, preserves explicitly verified recovery, and suppresses or cleanly errors unsupported success-looking final text before delivery.
