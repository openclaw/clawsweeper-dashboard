## Summary

Keep open: current main still has targeted cron/tool-error hardening, but not a general fail-closed or ledger-backed finalization policy for fabricated final output after failed or missing tool work.

## What This Changes

The issue requests fail-closed cron/session delivery so fabricated or unsupported agent output is suppressed when tool calls fail or the task cannot be verified.

## Best Possible Solution

Define a maintainer-approved finalization policy for unattended and tool-backed turns that uses structured run/tool state to suppress, replace, or clearly mark unsupported output without relying only on model self-suppression or marker text.

## Reproduction Assessment

Yes, at source level: current main still allows selected tool-warning/error states to be recovered by final assistant text and delivered, while failure signals are limited to narrow structured cron denials. I did not live-run the original Gemini cron incidents in this read-only review.

## Solution Assessment

No complete solution exists on current main. The issue's marker-filter proposal is too narrow by itself; the maintainable direction is a structured finalization or ledger-backed policy covering failed tools, missing tool attempts, and unsupported success claims.
