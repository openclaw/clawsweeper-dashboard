## Label Justifications

- `P1`: The issue describes real unattended cron outputs claiming unsupported work, which is an urgent trust and delivery-boundary regression for agent workflows.
- `impact:session-state`: The problem is about agent run state and final output drifting from the actual tool-call/tool-result ledger.
- `impact:security`: Fabricated cron output after failed tools can mislead users about external data access or operational changes in unattended runs.

## Summary

Keep open: current main and the latest release still allow non-fatal failed tool work to be followed by final assistant text that can become cron output, so the core unattended-delivery trust boundary remains unresolved.

## What This Changes

The issue asks OpenClaw cron/isolated sessions to fail cleanly or stay silent instead of delivering fabricated or unsupported output after tool failures, missing data, or incomplete work.

## Best Possible Solution

Define a narrow core invariant for cron/unattended runs: unrecovered failed or missing tool evidence must suppress normal scheduled delivery or produce a clean failure, while broad arbitrary claim verification stays in plugin/ClawHub scope.
