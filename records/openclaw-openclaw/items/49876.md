## Summary

Keep open: current main has targeted cron/tool-error warning hardening, but it still does not implement the reported fail-closed delivery boundary for unattended output after failed, missing, or unverifiable tool work.

## What This Changes

Issue #49876 requests fail-closed handling for cron or agent output that fabricates success or operational data after tool failures or absent tool execution.

## Best Possible Solution

Define a core unattended-run finalization contract that derives deliverability from structured run/tool state, preserves explicitly verified recovery, and suppresses or cleanly errors unsupported success-looking final text before normal delivery.

- **Keep broad claim checks plugin-first:** Limit core to structured fatal tool/error states and leave natural-language success-claim verification to ClawHub plugins.
