## Label Justifications

- `P1`: The issue describes real unattended cron outputs claiming unsupported work, which is an urgent trust and delivery-boundary regression for agent workflows.
- `impact:session-state`: The problem is about agent run state and final output drifting from the actual tool-call/tool-result ledger.
- `impact:security`: Fabricated cron output after failed tools can mislead users about external data access or operational changes in unattended runs.

## Summary

Keep open: current main still lets non-fatal failed or missing tool work be followed by final assistant text that can become cron delivery output, so the unattended trust boundary reported in #49876 remains unresolved even though broad arbitrary claim verification has been routed outside core.

## What This Changes

The issue asks OpenClaw to fail cleanly or stay silent for cron/unattended runs when tool calls fail or do not actually support the final output.

## Best Possible Solution

Define a narrow core invariant for cron/unattended runs: failed or missing tool evidence must not be converted into successful scheduled output, while broad arbitrary claim verification remains a plugin/ClawHub concern.

Options:

- **Fail closed for cron only (recommended):** Make cron/unattended delivery suppress or mark final assistant text as failed when required tool evidence is missing or failed, without adding broad claim verification to core.
- **Keep current behavior:** Leave final assistant text as a recovery path after non-fatal tool warnings and rely on plugins or operator policy for broader trust checks.
- **Add opt-in strict mode:** Preserve the current default but add an explicit strict cron finalization mode with tests and upgrade documentation.
