## Summary

Current main and the latest release already route custom model catalog thinking metadata into Gateway session rows and session patch validation, so the reported v2026.6.10 mismatch between CLI `--thinking` and session-level `/think` is fixed.

## What This Changes

The issue asks for custom `openai-completions` models that advertise reasoning support to expose the same session-level thinking choices in TUI/WebUI that request-level CLI thinking accepts.

## Best Possible Solution

Keep the released catalog-backed session thinking implementation and ask affected users on v2026.6.10 to upgrade to v2026.6.11 or newer.
