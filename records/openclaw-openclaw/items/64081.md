## Summary

Keep open: current main and the latest release still do not provide a config-level default task notify policy, and the existing per-task CLI override does not solve the pre-create defaulting race described in the report.

## What This Changes

Request a config-level default task notification policy so ACP and subagent task completion messages can default to `silent`, `done_only`, or `state_changes` without per-task CLI changes.

## Best Possible Solution

Add a maintainer-approved, backward-compatible task notify default resolver that preserves current behavior when unset, lets explicit task and flow policies win, keeps cron/CLI/media silent defaults intact, and updates schema, docs, and tests together.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add a public task notify default config surface, and should that surface be global or per-runtime/channel-scoped?

Rationale: The source gap is clear, but adding config/default behavior is a public product contract with channel-delivery and upgrade implications that automation should not choose alone.

Likely owner: Vincent Koc

Owner reason: Vincent Koc is the strongest recent history match for the task registry, ACP/subagent creation paths, config defaults, and release-tagged behavior involved in this decision.

Owner confidence: high

Options:

- **Add per-runtime defaults (recommended):** Introduce an `agents.defaults.tasks` policy map, preserve current behavior when unset, and apply it before ACP, subagent, and Task Flow records are created.
- **Add one global default:** Expose a single default notify policy for all task-like records while explicitly exempting cron, CLI, and media tasks that already have silent contracts.
- **Keep CLI-only overrides:** Leave the current per-task `openclaw tasks notify` override as the supported path and close or redirect broader default-policy requests.

## Reproduction Assessment

Yes. Source inspection on current main shows deliverable tasks without explicit `notifyPolicy` resolve to `done_only`, and the ACP/subagent callers omit `notifyPolicy`; a live Telegram repro was not needed to prove that defaulting path.

## Solution Assessment

Unclear. A config-level default is a plausible maintainable fix, but maintainers still need to choose the public shape and semantics before implementation.
