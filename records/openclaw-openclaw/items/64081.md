## Summary

Keep open: current main and the latest release still lack a schema-backed config default for task notification policy, while ACP, subagent, ACP control-plane, and Task Flow creation paths still rely on hardcoded defaults when callers omit `notifyPolicy`. This is a valid feature/config request, but it needs maintainer product direction before implementation.

## What This Changes

Request to add a config-level default task notify policy so users can suppress or change raw background task completion notifications without racing per-task CLI updates.

## Best Possible Solution

Add a maintainer-approved, backward-compatible task notify default resolver that preserves current behavior when unset, lets explicit task/flow policies win, keeps cron/CLI/media silent defaults intact, and updates schema, types, docs, and focused tests together.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What public config shape should OpenClaw support for default task notify policy across ACP, subagent, Task Flow, cron, CLI, and media task runtimes?

Rationale: The requested fix adds a user-visible config/default surface and can change channel message volume, so automation should not choose global versus per-runtime semantics without maintainer intent.

Likely owner: steipete

Owner reason: Peter has the broadest recent history across the config, docs, ACP, and task surfaces that would need to move together.

Owner confidence: high

Options:

- **Per-runtime task defaults (recommended):** Add a narrow `agents.defaults.tasks.notifyPolicy` map keyed by runtime, preserve unset current behavior, and keep explicit task or flow policies authoritative.
- **Single global task default:** Add one default notify policy for all deliverable task records, accepting a simpler config shape with higher risk of surprising ACP/subagent versus cron/CLI/media behavior differences.
- **No config surface:** Keep the per-task CLI override and solve only narrower channel/runtime issues such as Discord visibility or Telegram ACP coalescing.

## Reproduction Assessment

Yes. Source inspection shows deliverable tasks without an explicit `notifyPolicy` still resolve to `done_only`, and the main ACP, subagent, ACP control-plane, and Task Flow paths omit any config-backed default.

## Solution Assessment

Unclear. A config-level default is plausible, but the best solution depends on maintainer choice of global versus per-runtime semantics and must preserve explicit policies plus existing silent cron/CLI/media defaults.
