## Summary

Keep open: current main and the latest release still lack a config-level default task notify policy, while ACP, subagent, and Task Flow creation paths continue to use hardcoded defaults unless a caller supplies `notifyPolicy`. This is valid, but it adds a compatibility-sensitive config/default surface and needs maintainer product direction before implementation.

## What This Changes

The issue requests a configurable default notify policy for background tasks so ACP/subagent completion notifications can default to `silent`, `done_only`, or `state_changes` without a racy per-task CLI update.

## Best Possible Solution

Add one additive, backward-compatible task notify default resolver after maintainer approval, preserving current behavior when unset, letting explicit task policies win, and updating schema, docs, and focused tests together.

- **Keep per-task controls only:** Decline a config default and keep `openclaw tasks notify` plus targeted owner-specific fixes for Discord, Codex, ACP flood, and announce suppression issues.

## Solution Assessment

Unclear until maintainers choose the public API shape. A config-level resolver is plausible, but the safest implementation must be additive, preserve current defaults when unset, and avoid competing with related announce/routing/channel policies.
