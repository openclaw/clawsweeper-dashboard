## Summary

Keep open: current main and the latest release still hardcode `done_only` for deliverable ACP, subagent, and Task Flow records unless the caller passes `notifyPolicy`; adding a config-level default remains valid but needs a maintainer product/config decision.

## What This Changes

Request a user-configurable default task notification policy so background ACP/subagent completions can default to `silent`, `done_only`, or `state_changes` instead of only being changed per task.

## Best Possible Solution

Add a backward-compatible task notification default resolver that preserves current behavior when unset, lets explicit per-task and per-flow policies win, keeps cron/CLI/media silent defaults intact, and updates schema, docs, and tests together.
