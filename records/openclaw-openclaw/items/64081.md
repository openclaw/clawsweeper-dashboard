## Summary

Keep open: current main and v2026.6.11 still lack a config-level default task notify policy, while deliverable task records and Task Flow records still fall back to hardcoded `done_only` when no caller supplies `notifyPolicy`. Current main has narrowed ordinary subagent terminal auto-delivery, but ACP spawn and flow defaults still leave the broader config/default policy decision unresolved.

## What This Changes

Request a config-level default task notification policy for ACP, subagent, and related task records so users can suppress or tune raw background task notifications without racing per-task CLI updates.

## Best Possible Solution

Choose one backward-compatible task notify default resolver that preserves unset behavior, lets explicit per-task and flow policies win, keeps cron/CLI/media quiet defaults intact, and updates schema, help, docs, and focused tests together.
