## Summary

Keep open: current main and v2026.6.11 still hard-code `done_only` for deliverable ACP, subagent, and Task Flow records without a schema-backed config default, and the related open items cover narrower runtime or channel symptoms rather than replacing this broader config decision.

## What This Changes

The issue requests a config-level default background-task notification policy so users can choose `silent`, `done_only`, or `state_changes` without racing per-task overrides.

## Best Possible Solution

Define a maintainer-approved, backward-compatible task notify default resolver, likely under `agents.defaults.tasks`, that preserves current behavior when unset, lets explicit task/flow policies win, and keeps existing silent cron, CLI, and media paths intact.
