## Summary

Keep open: current main and the latest release still have hardcoded task notify defaults and no schema-backed config-level default notify policy. The related open issues are narrower channel/runtime visibility problems, while the closed cron-subagent issue points back to this issue as the broader config-shape decision.

## What This Changes

Request to add a config-level default notify policy for background tasks so users can silence or adjust ACP/subagent completion notifications without racing per-task overrides.

## Best Possible Solution

Add a maintainer-approved, backward-compatible core config surface that preserves current behavior when unset, lets explicit task and flow policies win, keeps cron/CLI/media silent defaults intact, and updates schema, docs, and tests together.
