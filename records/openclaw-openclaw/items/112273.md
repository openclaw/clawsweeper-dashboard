## Summary

Keep open. The performance direction is useful and the reported production backport is meaningful, but the new process-local TTL cache can return stale session entries after another OpenClaw process changes the same SQLite store; that is a session-state correctness regression until the cache has a cross-process coherence strategy.

## What This Changes

This PR caches SQLite session-entry lists, adds a lightweight list view that omits two large report fields, supports pagination, and invalidates the cache after local session-entry writes.

## System Context

The gateway loads session-entry metadata to serve `sessions.list` and build combined session views for the Control UI and agent runtime. SQLite rows feed the accessor layer, which returns entries to gateway consumers and is updated by session lifecycle writes.

## Architecture Diagram

flowchart LR

  B --> C{TTL cache hit?}

  E --> D
  D --> F[Gateway session list and combined view]

## Best Possible Solution

Use a cache design with an explicit cross-process freshness mechanism or an owner-approved bounded-staleness contract, then add focused coverage for an external SQLite mutation and a subsequent `sessions.list` read.
