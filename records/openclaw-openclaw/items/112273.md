## Summary

Keep open. The latest head resolves the earlier cross-process freshness blocker with file-stat and SQLite `data_version` validation, but its light list still appears to read and parse the full `entry_json` blobs before removing the two oversized fields. That leaves the cold-cache and post-write path proportional to the reported ~99 MB store, so the central gateway-stall problem remains only partially addressed.

## What This Changes

This PR adds a coherent process-local cache for SQLite session-entry lists, a lightweight list mode, pagination, local write invalidation, and regression/benchmark coverage for gateways with many sessions.

## System Context

The gateway reads session-entry metadata from each agent’s SQLite database to serve `sessions.list` and construct combined session views used by the Control UI and runtime. The accessor turns stored JSON rows into session entries, then supplies either full or lightweight results to gateway consumers.

## Best Possible Solution

Project `systemPromptReport` and `skillsSnapshot` out in the SQLite list query before JSON parsing, retain the repaired freshness guard for cache hits, and prove cold, warm, and post-write gateway list behavior against a representative large database.
