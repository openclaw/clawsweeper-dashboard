- `merge-risk: 🚨 availability`: Serializing all page reads can materially stall explicit exhaustive searches on large vaults.

## Summary

The patch’s deadline propagation and supplement-only fallback policy address the linked bug, but the shared page reader now serializes all file reads, including explicit exhaustive `wiki_search`, creating a likely large-vault performance regression. The PR should remain open for a bounded abort-aware scheduling repair and representative runtime proof.

## What This Changes

The PR propagates the memory tool deadline through the corpus-supplement API, disables exhaustive fallback for memory-wiki supplements, and changes wiki page reads to stop starting file I/O after cancellation.

## Best Possible Solution

Preserve the generic deadline signal and supplement-only non-exhaustive policy, but load pages with bounded abort-aware concurrency that stops scheduling new work after cancellation without slowing explicit exhaustive `wiki_search`; then prove both paths on a representative vault.
