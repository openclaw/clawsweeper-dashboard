## Summary

Keep this issue open. The reported gateway-host execution conflicts with the documented fail-closed Codex behavior for active OpenClaw sandboxes, and the report is distinct from the PathUri defect because that path requires `sandboxExecServer: true`; however, the creation-time divergence has not yet been isolated on current main. ([docs.openclaw.ai](https://docs.openclaw.ai/plugins/codex-harness-reference?utm_source=openai))

## What This Changes

Investigate why newly created Codex agents with sandbox mode enabled route native execution to the gateway host while older agents with equivalent effective sandbox configuration execute inside the sandbox.

## Best Possible Solution

Make every active-sandbox Codex turn fail closed when native sandbox execution is unavailable, route ordinary shell work through `sandbox_exec` or `sandbox_process`, and add regression coverage comparing fresh and previously persisted agent/session state across an upgrade.

No, not yet on current main. The report provides a concrete A/B procedure and strong outward signals, but the review could not run the two-agent scenario or inspect a diagnostic bundle that identifies the selected Codex tool surface and persisted thread state.

## Solution Assessment

Yes at the contract level: native host execution must remain disabled whenever an OpenClaw sandbox is active and the sandbox exec-server is off. The exact repair location remains unclear until the fresh-agent and persisted-agent runtime projections are compared.
