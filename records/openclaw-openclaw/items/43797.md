## Summary

Keep this open: current main and v2026.6.11 still remove expired sandbox runtimes and registry entries without deleting the non-shared sandbox workspace directory, and the linked fix PR is still open and conflicting.

## What This Changes

The issue requests that sandbox prune delete expired non-shared sandbox workspace directories in addition to removing Docker runtimes and registry entries.

## Best Possible Solution

Land a current-main fix, or adopt and rebase the linked fix PR, that removes only unreferenced non-shared sandbox workspaces after successful runtime removal and adds focused prune/recreate coverage.

## Reproduction Assessment

Yes, from source inspection: expired sandbox entries reach backend runtime removal and registry deletion, but the non-shared workspace directory is not removed. I did not run a live Docker prune in this read-only review.

## Solution Assessment

Yes for the central bug: workspace deletion after successful runtime prune is the narrow maintainable fix, provided it preserves shared-scope and still-referenced agent-scope safety. The broader lifecycle feature should stay separate from this prune cleanup.
