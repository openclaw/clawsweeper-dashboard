## Summary

Keep this open: current main and the latest release still remove the expired sandbox runtime and registry entry without deleting the local non-shared sandbox workspace, so the reported disk leak and stale workspace state remain possible.

## What This Changes

The issue asks for sandbox pruning to remove both expired runtime containers and their corresponding local sandbox workspace directories.

## Best Possible Solution

Land a narrow sandbox cleanup fix that removes the non-shared workspace derived from the existing scope helpers after successful runtime cleanup, with regression coverage for session, agent, and shared scope behavior.

## Reproduction Assessment

Yes, source-level: current main's prune path removes the runtime and registry entry while Docker removeRuntime only runs docker rm -f. I did not run a live Docker prune in this read-only review.

## Solution Assessment

Yes, the narrow maintainable fix is to extend the existing sandbox prune cleanup path using resolveSandboxScopeKey and resolveSandboxWorkspaceDir rather than adding a new config option or broad lifecycle feature for this specific bug.
