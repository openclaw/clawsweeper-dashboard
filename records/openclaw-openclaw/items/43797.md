## Summary

Keep open: current main and v2026.6.11 still omit workspace deletion from ordinary sandbox prune. The open fork PR targets this bug but is conflicting and unmerged, and the same-repository attempts were closed unmerged, so there is no landed fix to close against.

## What This Changes

Sandbox prune is reported to remove runtime containers and registry entries without deleting per-scope sandbox workspace directories, leaving stale state and disk use behind.

## Best Possible Solution

Land, adopt, or replace the linked fix with a current-main patch that removes only safe non-shared sandbox workspaces after confirmed runtime removal and adds focused prune regression coverage.

## Reproduction Assessment

Yes. Source inspection shows an expired sandbox registry entry reaches backend runtime removal and registry deletion, but ordinary sandbox prune never removes the separate workspace directory; I did not run a live Docker prune in this read-only review.

## Solution Assessment

No. Current main is not the fix, and a simple recursive delete alone is not sufficient because prior PR reviews showed browser, shared-scope, and active-workspace safety issues.
