## Summary

Keep this open: current main still prunes sandbox runtimes and registry rows without deleting the ordinary non-shared sandbox workspace directory, and the active linked fix candidate is open but conflicting rather than landed.

## What This Changes

The issue reports that sandbox pruning removes Docker containers and registry entries but leaves sandbox workspace directories behind, causing disk and stale workspace-state leaks.

## Best Possible Solution

Land, adopt, or replace the active prune fix with a current-main patch that removes only safe non-shared sandbox workspaces after successful runtime and registry cleanup, with regression coverage for shared, agent, browser, and failed-runtime paths.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: an expired registry entry reaches backend runtime removal and registry deletion, but ordinary sandbox workspace directories are not removed on current main.

## Solution Assessment

Yes for the narrow direction: the maintainable fix is workspace cleanup in the sandbox prune path with scope and runtime-safety guards. The broader ephemeral lifecycle issue should remain separate product work.
