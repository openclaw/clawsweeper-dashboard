## Summary

Keep this open: current main and the latest release still prune sandbox runtimes and registry entries without removing the non-shared local sandbox workspace, and the open closing PR is still conflicting rather than merged.

## What This Changes

The issue asks sandbox prune to delete expired non-shared workspace directories in addition to removing the sandbox runtime and registry entry.

## Best Possible Solution

Review and land a current-main fix, likely by rebasing/adopting https://github.com/BingqingLyu/openclaw/pull/510 or replacing it with an equivalent patch that removes only non-shared sandbox workspaces after successful prune and adds regression coverage.

## Reproduction Assessment

Yes. Source inspection on current main shows an expired sandbox entry removes the backend runtime and registry entry, but the non-shared sandbox workspace directory is never removed; I did not run a live Docker prune in this read-only review.

## Solution Assessment

Yes for the narrow fix direction. The maintainable solution is to delete the non-shared workspace only after successful runtime/registry cleanup with shared-scope safety and tests, not to add a new config option for the central bug.
