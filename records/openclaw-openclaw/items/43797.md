## Summary

Keep open: current main and v2026.6.11 still prune sandbox runtimes and registry entries without deleting the non-shared workspace directory, and the open linked fork PR remains unmerged/conflicting while broader lifecycle work is only partial overlap.

## What This Changes

The issue requests that sandbox prune also remove expired sandbox workspace directories instead of only removing Docker containers and registry entries.

## Best Possible Solution

Land, adopt, or replace the linked fix with a current-main patch that deletes only safe non-shared sandbox workspaces after successful runtime prune, with regression coverage for shared and active-scope safety.

## Reproduction Assessment

Yes. Source inspection shows an expired sandbox registry entry reaches backend runtime removal and registry deletion, but ordinary sandbox prune has no workspace-directory cleanup path; I did not run a live Docker prune in this read-only review.

## Solution Assessment

Yes, the narrow prune-path cleanup is the best fix shape, as long as it deletes only safe non-shared workspaces after successful runtime removal and keeps broader managed lifecycle work separate unless that PR lands the same behavior.
