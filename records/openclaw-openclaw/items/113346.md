## Summary

This issue remains necessary: current main has transcript-hygiene repairs and some loop/compaction safeguards, but the reviewed material does not establish a general guard that collapses repetitive valid transcript content before a session read or compaction summary reintroduces it. The report overlaps the transcript/replay umbrella but describes a distinct transmission mechanism that needs scoped design and a current-main reproduction.

## What This Changes

Add protection against repetitive tool-call and assistant-content patterns being preserved in session history, then amplified when transcripts are read or compacted into later agent contexts.

## System Context

OpenClaw’s embedded agent runtime persists conversation and tool events, rebuilds them into later model context, and compacts older history into summaries. Session-search or other transcript-reading paths can therefore turn stored content into new model input, while loop detection and compaction determine whether a runaway turn is stopped or carried forward.

## Architecture Diagram

flowchart LR
  A[Agent tool calls and replies] --> B[Durable session transcript]
  B --> C[Transcript search or session read]
  B --> D[Compaction summary]
  C --> E[New agent model context]
  D --> E
  E --> F[Tool loop detection]
  F --> G[Next tool call or recovery]

## Best Possible Solution

Define a single bounded repeated-pattern policy at the model-context boundary, preserve the durable transcript for diagnostics, and prove it prevents self- and cross-session reinjection without suppressing legitimate repeated work.
