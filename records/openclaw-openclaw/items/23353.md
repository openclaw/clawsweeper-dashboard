## Summary

Keep open: current main still lacks the broad Anthropic native server-tools implementation, including Anthropic server-tool injection, web_fetch/code_execution/PTC support, allowed_callers, and Anthropic server result preservation.

## What This Changes

The issue requests opt-in Anthropic server-side web_search, web_fetch, and code_execution/PTC support as provider-native alternatives to OpenClaw client-side tools.

## Best Possible Solution

Keep this as the broad Anthropic server-tools tracker and design a maintainer-approved Anthropic plugin/transport implementation with explicit opt-in, provider/model gating, safe transcript replay, and security-reviewed defaults.

## Reproduction Assessment

Yes. Source inspection reproduces the missing capability: current Anthropic transport only projects client tool definitions, current config lacks typed Anthropic server-tool support, and the Anthropic plugin manifest does not declare web search/fetch/tool contracts.

## Solution Assessment

Unclear as a final product design. The requested direction is valid, but the best solution should be a maintainer-approved Anthropic plugin/transport design rather than a one-off config switch, because code_execution/PTC and server result replay need explicit safety and compatibility choices.
