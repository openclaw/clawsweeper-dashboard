## Summary

Current main still lacks the requested Anthropic-native server-side tool support: the Anthropic transport only projects OpenClaw client tools, the stream parser does not handle server-tool blocks/results, and the Anthropic plugin has no web-search/web-fetch/code-execution contract surface. The issue should stay open for maintainer-directed provider/security design rather than be closed as implemented or routed to a small autonomous fix.

## What This Changes

Request Anthropic-native server-side tools such as web_search, web_fetch, code_execution/PTC, related config, and transcript/session handling.

## Best Possible Solution

Keep the issue open for a maintainer-approved Anthropic plugin/transport design with explicit opt-in config, provider/model/auth gating, raw server-block preservation and replay semantics, docs, and focused tests across fresh and upgrade behavior.

## Reproduction Assessment

Yes by source inspection: current main has no Anthropic-native server-tool config, payload injection, plugin contract, or stream parser support, although this is a feature gap rather than a failing bug repro.

## Solution Assessment

No current solution is sufficient: existing client web tools and the narrower web_search/advisor efforts do not cover web_fetch, code_execution/PTC, allowed_callers, and raw server-block replay semantics for Anthropic Messages.
