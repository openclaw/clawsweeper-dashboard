## Label Justifications

- `P2`: This is a useful Anthropic provider capability with clear source gaps, but existing client-side web tools still work and it is not a release-blocking regression.
- `impact:session-state`: Server-tool result handling affects transcript replay, encrypted provider result continuity, and context/session state.

- `impact:auth-provider`: The feature is Anthropic-provider-specific and depends on Anthropic request payloads, credentials, and model routing.

## Summary

Current main still does not implement the broad Anthropic server-side tools request: native Anthropic web search remains a narrower open tracker, and web_fetch, code_execution/PTC, allowed_callers, and server-tool result preservation still need maintainer design for provider-hosted execution and replay policy.

## What This Changes

Request Anthropic-native server-side support for web_search, web_fetch, and code_execution/PTC as an opt-in alternative to OpenClaw client-side web and tool execution.

## Best Possible Solution

Keep this as the broad Anthropic server-side tools tracker and design an Anthropic plugin/transport implementation for native web_search, web_fetch, code_execution/PTC, allowed_callers, server-result display/replay policy, docs, tests, and security defaults.
