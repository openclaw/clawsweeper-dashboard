## Summary

Keep this open: current main has adjacent Claude CLI and generic server-tool transcript handling, but the broad direct Anthropic Messages request still lacks provider-gated server-tool injection, config/API shape, web_fetch and code_execution/PTC support, allowed_callers handling, and raw server result preservation.

## What This Changes

The issue requests opt-in support for Anthropic server-side web_search, web_fetch, and code_execution/PTC tools as alternatives to OpenClaw client-side web tools.

## Best Possible Solution

Design this in the Anthropic plugin/transport boundary as an opt-in, provider-gated capability with explicit security defaults, raw server-block preservation/replay, docs, and focused tests; keep https://github.com/openclaw/openclaw/issues/49949 as the narrower native web_search tracker.

## Reproduction Assessment

Yes for the source-level gap: current main can be checked by inspecting config, Anthropic payload construction, plugin manifest contracts, and direct stream parsing. This is a feature request rather than a failing runtime repro.

## Solution Assessment

No implementation is ready to close this yet. The best path is a bounded Anthropic plugin/transport design, not a narrow web_search-only patch or a generic core shim.
