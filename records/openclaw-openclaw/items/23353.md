## Summary

Current main still lacks broad Anthropic native server-side tool support; related web-search and advisor items are narrower, open, or closed unmerged, and none cover the full web_fetch, code_execution/PTC, allowed_callers, transport preservation/replay/rendering, docs, tests, and security-default surface requested here.

## What This Changes

The issue asks to opt into Anthropic native server-side web_search, web_fetch, and code_execution/PTC instead of only client-side OpenClaw tools.

## Best Possible Solution

Keep this as the broad Anthropic server-tools tracker and require an Anthropic-owned plugin/transport design with explicit opt-in, generic server block preservation/rendering/replay, safe allowed_callers/container handling, docs, focused tests, live proof, and security review.

## Reproduction Assessment

Yes. Current-main source inspection shows the direct Anthropic transport cannot inject or parse the requested server-side tools; no live Anthropic call was needed because this is a missing feature surface rather than a runtime-only bug.

## Solution Assessment

The requested direction is reasonable, but the best fix is a provider-owned transport/plugin design with security and upgrade decisions, not a small config flag or isolated parser change.
