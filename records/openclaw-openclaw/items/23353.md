## Summary

Current main still does not implement the broad Anthropic native server-side tools request: Anthropic request construction still converts OpenClaw tools into client-side Anthropic tool definitions, the current config/schema has no Anthropic server-tools or PTC shape, and the Anthropic transport stream parser still lacks the requested server-tool/result block preservation. Related items are narrower or adjacent, so this issue remains useful as the broad tracker.

## What This Changes

Request support for opt-in Anthropic server-side tools including native web search, web fetch, code execution/PTC, response block handling, and provider-scoped configuration.

## Best Possible Solution

Keep this as the broad Anthropic native server-tools tracker and design the implementation in the Anthropic provider/plugin boundary, with web_search-only, advisor, or compaction items linked as narrower follow-ups rather than replacements.

## Reproduction Assessment

Yes for the missing capability: source inspection on current main shows no Anthropic serverTools/PTC config, no native server-tool injection in Anthropic request construction, and no parser handling for the requested server-tool result blocks. This is a feature gap rather than a broken existing behavior contract.

## Solution Assessment

Unclear until maintainers choose the product and security contract; provider-owned Anthropic native-tool support is the right boundary, but code_execution/PTC, allowed_callers, encrypted replay, billing, and fallback policy need explicit design first.
