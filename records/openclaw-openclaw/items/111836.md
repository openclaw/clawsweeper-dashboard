## Summary

The PR follows the right ownership boundary by reusing the shared provider JSON reader, but current `main` shows that reader still uses the default non-fatal `TextDecoder`; malformed UTF-8 can therefore still be replaced with U+FFFD and parsed. The central fix is incomplete and needs a small shared-reader repair before merge.

## What This Changes

The PR replaces Exa’s local successful-response decoding with the shared provider JSON reader and updates Exa tests to use plugin-owned API-key configuration.

## Best Possible Solution

Make the canonical provider JSON reader use fatal UTF-8 decoding, add direct shared-reader coverage for malformed bytes, then retain the Exa delegation and rebase its regression test on that verified contract.
