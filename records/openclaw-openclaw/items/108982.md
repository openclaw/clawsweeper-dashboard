## Summary

The bug is valid and the patch is directionally right, but it should stay open because the OpenRouter path reuses a timeout budget resolved before the header fetch and the external PR still has only mock-based behavior proof.

## What This Changes

The PR adds idle body-read timeouts and provider-specific stalled-download errors across generated media download paths, plus an OpenAI regression test and deadline-aware HTTP mocks.

## Best Possible Solution

Keep one shared absolute operation deadline through header fetch and body read, resolve the remaining budget immediately before each body wait, and prove the behavior with a real local HTTP server that sends headers then stalls.

No in its current form: adding body-idle bounds is the right fix shape, but OpenRouter refreshes an already-consumed numeric budget and the shared mock does not model elapsed remaining time. A lazy deadline resolver plus real stalled-server proof is narrower and contract-correct.
