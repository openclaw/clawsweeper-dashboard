## What This Changes

The PR changes Control UI session hydration so repeated metadata-only Gateway snapshots on an existing connection do not issue another `sessions.list` request, and adds a regression test for that startup path.

## System Context

The Control UI session capability receives Gateway connection snapshots plus session events, then subscribes and fetches the session list used by the session UI. Connection transitions should hydrate that list, while other snapshot changes may still need a refresh when they represent a meaningful session-state change.

## Best Possible Solution

Classify snapshot changes by the session-list fields they affect: suppress only metadata-only same-connection updates, retain the authoritative refresh path for snapshots that can change displayed session state, and prove both paths with focused tests plus a redacted trace of the real triggering snapshot.
