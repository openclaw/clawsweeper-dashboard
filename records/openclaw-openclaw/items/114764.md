## What This Changes

The PR stops Control UI session hydration from issuing another `sessions.list` request for same-connection Gateway metadata snapshots and adds regression coverage for metadata updates and reconnect hydration.

## System Context

The Control UI subscribes to Gateway connection snapshots and session events, then hydrates its session list through `sessions.list`. Gateway metadata such as recovery scope and Canvas details can update the same snapshot stream, so the session capability must distinguish connection transitions from non-session metadata changes.

## Architecture Diagram

  D -->|Yes| E[Hydrate session list]
  D -->|No, metadata only| F[Keep current list]
  E --> G[sessions.list request]
  C --> H[Refresh or reconcile sessions]

## Best Possible Solution

Keep connection transitions as the single snapshot hydration owner, retain event-driven reconciliation, and add a redacted final-head browser/Gateway trace that proves metadata-only suppression alongside a session-relevant refresh or reconnect outcome.
