## Summary

Keep this PR open: current main still has the snapshot-triggered refresh path, while this narrow change removes the redundant same-connection startup request and retains connection-transition and event-driven refresh ownership. The PR body supplies credible live Gateway/browser evidence and focused regression coverage; it needs ordinary merge-result/CI confirmation rather than a repair rewrite.

## What This Changes

The PR stops Control UI session hydration from scheduling a second `sessions.list` request when Gateway metadata publishes additional snapshots for the already-connected client.

## System Context

The Control UI’s session capability listens to Gateway connection snapshots and session events, then fetches `sessions.list` to hydrate the sidebar. Gateway metadata updates can reuse the same client connection, so the capability must distinguish a real connection transition from an informational snapshot update before issuing work.
