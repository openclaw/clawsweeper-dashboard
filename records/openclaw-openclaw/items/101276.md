## Summary

This PR remains necessary and has strong live proof, but it is not merge-ready because delegated macOS companion execution does not carry denylist state into its final current-policy check. A matching STOP rule added after node-side evaluation can therefore be missed before companion launch; after that repair, maintainers still need to approve the new persistent security-policy surfaces.

## What This Changes

Adds a deny-over-allow exec approval denylist across config, persisted approval policy, gateway/node execution paths, protocol schemas, documentation, and focused tests.

## Best Possible Solution

Extend the canonical delayed-authorization contract so the macOS companion re-screens newly current denylist rules immediately before launch, then obtain security-owner approval for the two persistent policy surfaces and the intentional full/off behavior change.
