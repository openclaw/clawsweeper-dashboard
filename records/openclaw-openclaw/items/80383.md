## Best Possible Solution

Land a rebased version that keeps cancellation owned by SessionActorQueue, preserves the public Plugin SDK KeyedAsyncQueue API and current manager error normalization, and guards diagnostics by queued-item identity.

## Reproduction Assessment

## Solution Assessment

Yes after a narrow repair. Queue-level cancellation is the right owner boundary because pending accounting lives in SessionActorQueue; manager-only abort handling cannot clean up a queued item stuck behind a non-settling predecessor.
