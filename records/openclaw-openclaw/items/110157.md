## Summary

Keep open: current main deliberately injects Bedrock `guardrailConfig` for configured requests but does not emit selective `guardContent` blocks, so the requested guardrail scope remains unavailable. The report is a concrete provider feature with security-sensitive compatibility choices, not a duplicate of the related error-reporting issue.

## What This Changes

Add selective Amazon Bedrock guardrail input tagging so configured guardrails can evaluate untrusted input without evaluating OpenClaw’s trusted system prompt.

## Best Possible Solution

Keep the current all-request mode as the compatibility default unless an owner explicitly approves a change; add a provider-owned selective mode only after defining which system, user, external-context, tool-result, and attachment spans are trusted, then prove the resulting Bedrock payload and a real guarded invocation.
