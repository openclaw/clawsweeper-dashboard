## Summary

Keep open: current main and v2026.6.11 still emit the hardcoded main-agent identity opener before SOUL.md Project Context, and the remaining work is already represented by an open but unmerged implementation candidate that needs maintainer API acceptance.

## What This Changes

The issue requests a narrow configurable replacement or suppression path for the hardcoded main-agent identity preamble so SOUL.md-defined agent identities do not have to fight the first system-prompt line.

## Best Possible Solution

Settle the prompt-identity contract, then land a refreshed narrow opt-in implementation with unchanged defaults, config docs/schema metadata, focused prompt tests, and no revival of whole-prompt override behavior.
