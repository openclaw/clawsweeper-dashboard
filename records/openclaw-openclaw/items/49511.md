Full review comments:

- **[P1] Port Mermaid rendering to markdown-it:** `ui/src/ui/markdown.ts:263-264`
  - body: Current main no longer uses the `marked` `htmlEscapeRenderer.code` path this branch modifies; fenced blocks are handled by `md.renderer.rules.fence` and `renderCodeBlock`. Rebase/port the Mermaid branch onto that current markdown-it path so the feature preserves the active sanitizer, task-list, code-copy, streaming, and cache behavior.
  - confidence: 0.92
- **[P2] Schedule rendering wherever Mermaid blocks are emitted:** `ui/src/ui/app-lifecycle.ts:124`
  - body: The PR rewrites every `toSanitizedMarkdownHtml()` Mermaid fence into an empty render placeholder, but only the chat lifecycle calls `scheduleMermaidRender()`. Shared markdown consumers such as the sidebar and preview panes can therefore show blank Mermaid blocks; either scope the rewrite to scheduled surfaces or schedule rendering in every consumer that can emit the placeholder.
  - confidence: 0.88
- **[P2] Allow transient Mermaid failures to retry:** `ui/src/ui/mermaid.ts:149-151`
  - body: `renderMermaidBlocks()` only selects `.mermaid-block:not([data-mermaid-status])`, and the error paths permanently set `data-mermaid-status="error"`. A transient lazy-import failure or early malformed/streamed diagram leaves the same DOM node stuck on the fallback until a full DOM rebuild, so later chat updates cannot recover the now-valid diagram.
  - confidence: 0.86
- **[P1] Remove the workspace-wide lodash-es override:** `package.json:1253`
  - body: This root override forces every workspace package and transitive dependency to resolve `lodash-es` to 4.18.1 even though the feature is scoped to Control UI Mermaid rendering. Keep any required dependency constraint local to the UI path or get explicit maintainer approval for the workspace-wide compatibility and supply-chain impact.
  - confidence: 0.9
