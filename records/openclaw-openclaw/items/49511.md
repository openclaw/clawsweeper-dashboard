  - body: Current main replaced this marked.js renderer with the MarkdownIt-based `ui/src/components/markdown.ts` path, and this file no longer exists there. Please rebase and implement Mermaid handling in the current fence renderer instead of reviving the old path, or the branch cannot land cleanly and risks bypassing the ReDoS hardening from the renderer migration.
  - confidence: 0.94
- **[P2] Scope Mermaid placeholders to views that schedule rendering:** `ui/src/ui/markdown.ts:263-264`
  - body: `toSanitizedMarkdownHtml()` is shared by sidebar and file-preview Markdown views, but this PR only calls `scheduleMermaidRender()` from the chat lifecycle. A Mermaid fence in those shared views becomes an empty `.mermaid-block__render` with the source hidden in `<details>`, so either scope the rewrite to chat or schedule rendering for every consumer.
  - confidence: 0.9
- **[P2] Call Mermaid bindFunctions after SVG insertion:** `ui/src/ui/mermaid.ts:186-188`
  - body: Mermaid 11.13.0 documents `render()` as returning `{ svg, bindFunctions }` and expects callers to run `bindFunctions?.(element)` after inserting the SVG. This code drops that callback, so diagrams with Mermaid-provided click handlers or tooltips render as static SVGs with interactions silently broken.
  - confidence: 0.88
- **[P1] Remove the workspace-wide lodash-es override:** `package.json:1253`
  - body: A UI-only Mermaid feature should not pin `lodash-es` for the whole workspace without explicit maintainer approval. This override can change package resolution for unrelated packages and turns the lockfile into a broader supply-chain/compatibility change than the feature requires.
  - confidence: 0.91
- **[P2] Allow failed Mermaid blocks to rerender after streaming completes:** `ui/src/ui/mermaid.ts:149-150`
  - body: Late discovery on the unchanged reviewed head: `renderMermaidBlocks()` only selects blocks without `data-mermaid-status`, but streamed or malformed first passes set `error` and are then skipped forever. A Mermaid fence that becomes valid later in the stream can stay stuck on fallback text until the DOM is rebuilt.
  - late: true
  - confidence: 0.82
