## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Port Mermaid handling to the current markdown-it renderer:** `ui/src/ui/markdown.ts:2`
  - body: Current main no longer uses `marked` for this path; it uses markdown-it with custom fence, sanitizer, streaming, task-list, and code-block contracts. This branch still imports `marked`, so resolving the dirty branch by keeping this file would regress the active renderer instead of extending it.
  - confidence: 0.94
- **[P1] Remove the workspace-wide lodash-es override:** `package.json:1253`
  - body: This UI feature should not pin `lodash-es` through the root pnpm override without explicit maintainer approval. Root overrides affect dependency resolution across the workspace and are a supply-chain/compatibility surface, while the Mermaid integration is UI-local.
  - confidence: 0.9
- **[P2] Keep Mermaid blocks renderable outside chat lifecycle:** `ui/src/ui/markdown.ts:263-264`
  - body: `toSanitizedMarkdownHtml()` is shared by sidebars, skill cards, cron details, and side-result views, but this patch rewrites every Mermaid fence into a `.mermaid-block` while only scheduling rendering from the chat lifecycle. Those other consumers can show an empty render slot with the source hidden behind `<details>` instead of a diagram or normal code fence.
  - confidence: 0.88
- **[P2] Call Mermaid bindFunctions after inserting SVG:** `ui/src/ui/mermaid.ts:186-187`
  - body: Mermaid's render API returns `bindFunctions` for diagrams with interactions, and upstream documents calling it after inserting the SVG. This code discards that return value, so Mermaid diagrams with click handlers or tooltips render as static/broken output.
  - confidence: 0.86
- **[P2] Let transient Mermaid failures retry:** `ui/src/ui/mermaid.ts:149-150`
  - body: The render pass only selects blocks without `data-mermaid-status`, but render and load failures mark blocks as `error`. A streamed or temporarily invalid Mermaid block can therefore stay permanently failed after the message finishes or the chunk load recovers.
  - confidence: 0.84
