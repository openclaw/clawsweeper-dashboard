## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Port Mermaid support to the current markdown-it renderer:** `ui/src/ui/markdown.ts:2`
  - body: This branch still imports `marked` and adds the Mermaid branch to the old `htmlEscapeRenderer.code` path, but current main has moved chat markdown to `markdown-it` with `md.renderer.rules.fence` and `renderCodeBlock`. The PR is already conflicting, and resolving it by carrying this file shape forward would drop current sanitizer, task-list, highlighting, streaming, and code-copy behavior.
  - confidence: 0.94
- **[P2] Scope Mermaid placeholders to surfaces that render them:** `ui/src/ui/markdown.ts:263-264`
  - body: The Mermaid branch rewrites every shared `toSanitizedMarkdownHtml()` Mermaid fence into a `.mermaid-block` with an empty render target, but only the chat lifecycle schedules `scheduleMermaidRender()`. Markdown sidebar, file previews, skills, cron, and other shared markdown consumers can therefore show a blank block with the source hidden instead of either rendering it or leaving a normal code fence.
  - confidence: 0.88
- **[P2] Call Mermaid bindFunctions after inserting SVG:** `ui/src/ui/mermaid.ts:185-187`
  - body: Mermaid 11.13.0 documents that `render()` can return `bindFunctions` and its example runs those after assigning the SVG into the DOM. This wrapper types the return as `{ svg }` only and never invokes `bindFunctions`, so diagrams that rely on Mermaid click bindings or tooltips will render as static SVGs with their interactions silently broken.
  - confidence: 0.86
- **[P2] Let failed Mermaid blocks retry on later passes:** `ui/src/ui/mermaid.ts:149-150`
  - body: `renderMermaidBlocks()` only selects `.mermaid-block:not([data-mermaid-status])`, but both module-load and render failures set `data-mermaid-status="error"`. A transient chunk load, network failure, or first-pass parse failure therefore permanently excludes the same block from later render attempts until the DOM is rebuilt.
  - confidence: 0.84
- **[P2] Remove or scope the workspace lodash-es override:** `package.json:1253`
  - body: The feature adds Mermaid under the Control UI package, but the root pnpm override pins `lodash-es` for the entire workspace. That changes dependency resolution outside this UI feature and should be removed unless maintainers explicitly want a repo-wide dependency override with matching proof.
  - confidence: 0.82
