Full review comments:

- **[P1] Port Mermaid rendering to markdown-it:** `ui/src/ui/markdown.ts:263-264`
  - body: Current main no longer uses this marked Renderer path; it renders fenced code through `md.renderer.rules.fence` and `renderCodeBlock`. Adding Mermaid only here would either conflict during rebase or replace recent markdown-it behavior such as highlighting, block-art copy encoding, i18n labels, and streaming safeguards.
  - confidence: 0.93
- **[P1] Remove the workspace-wide lodash override:** `package.json:1253`
  - body: This PR adds a root `pnpm.overrides` entry for `lodash-es` even though Mermaid already declares its own compatible range. A workspace override is a supply-chain and compatibility surface for every importer, so it needs to be removed or explicitly justified before this UI feature lands.
  - confidence: 0.86
- **[P2] Call Mermaid bindFunctions after SVG insertion:** `ui/src/ui/mermaid.ts:186-187`
  - body: Mermaid's render contract can return `bindFunctions` and its own example calls it after setting `innerHTML`. This code only reads `svg`, so Mermaid diagrams with tooltips or click bindings render as static output with interactions silently missing.
  - confidence: 0.89
- **[P2] Scope Mermaid placeholders to rendered views:** `ui/src/ui/markdown.ts:263-264`
  - body: `toSanitizedMarkdownHtml()` is shared by chat, sidebars, cron details, and other UI surfaces, but this branch schedules Mermaid rendering only from chat lifecycle updates. Non-chat markdown consumers would get an empty `.mermaid-block__render` with the source collapsed instead of a rendered diagram or a normal code fence.
  - confidence: 0.84
