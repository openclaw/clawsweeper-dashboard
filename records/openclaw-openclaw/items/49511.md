Overall confidence: 0.84

Full review comments:

- **[P1] Port Mermaid rendering to the markdown-it fence path:** `ui/src/ui/markdown.ts:263-264`
  - body: Current main renders code fences through the markdown-it `md.renderer.rules.fence` path, but this branch adds Mermaid handling to the old marked `htmlEscapeRenderer.code` implementation. Rebase and move this branch into the current `renderCodeBlock`/fence renderer so the feature applies to main instead of a retired renderer.
  - confidence: 0.9
- **[P1] Remove the workspace-wide lodash-es override:** `package.json:1253`
  - body: This feature only needs Mermaid in the Control UI, but the PR adds a root pnpm override for `lodash-es`, changing transitive resolution across the workspace. Remove the override or get explicit maintainer approval plus lockfile proof for why a workspace-wide pin is required.
  - confidence: 0.86
- **[P2] Call Mermaid bindFunctions after inserting SVG:** `ui/src/ui/mermaid.ts:186-187`
  - body: Mermaid 11.13.0 documents that `render()` returns `bindFunctions` and shows callers invoking it after setting `innerHTML`. This code drops that return value, so diagrams that rely on Mermaid tooltips or click bindings will render without their expected interactions.
  - confidence: 0.82
- **[P2] Allow transient Mermaid failures to retry:** `ui/src/ui/mermaid.ts:150`
  - body: The renderer only selects blocks without `data-mermaid-status`, but module-load and render failures mark the current block as `error`. A temporary chunk/load or first-pass render failure therefore skips that same diagram on later scheduler runs even though the loader promise is reset.
  - confidence: 0.78
- **[P2] Show a fallback for empty Mermaid definitions:** `ui/src/ui/mermaid.ts:178-180`
  - body: When a Mermaid fence has no definition, this branch marks the block as `error` and continues without calling `setMermaidRenderError`. Users get a blank render area with the source collapsed instead of an actionable fallback message.
  - confidence: 0.76
