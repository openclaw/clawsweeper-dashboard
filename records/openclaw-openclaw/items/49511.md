Full review comments:

- **[P1] Port Mermaid rendering to markdown-it:** `ui/src/ui/markdown.ts:263-264`
  - body: The PR head adds Mermaid handling to the old `marked` renderer, but current main renders code fences through `markdown-it` and `renderCodeBlock`. As written, the branch cannot merge cleanly or preserve current markdown behavior without being ported to the current renderer path.
  - confidence: 0.93
- **[P1] Remove the workspace-wide lodash override:** `package.json:1253`
  - body: This UI feature adds `lodash-es` to root pnpm overrides, which can change dependency resolution for the whole workspace. Keep the dependency impact scoped to Control UI or provide explicit maintainer-approved package rationale before merge.
  - confidence: 0.88
- **[P2] Run Mermaid bindFunctions after insertion:** `ui/src/ui/mermaid.ts:186-187`
  - body: Mermaid's render result includes optional `bindFunctions` that upstream expects callers to invoke after inserting the SVG. The PR types render as `{ svg }` only and ignores that callback, so diagrams that rely on Mermaid event bindings will render without their intended interactions.
  - confidence: 0.86
- **[P2] Only rewrite Mermaid fences where rendering is scheduled:** `ui/src/ui/markdown.ts:263-264`
  - body: `toSanitizedMarkdownHtml()` is shared by chat and non-chat markdown views, but this PR turns every Mermaid fence into an empty render placeholder while only scheduling Mermaid rendering from the chat lifecycle. Shared markdown panes would show blank blocks with source hidden instead of rendered diagrams or normal code fences.
  - confidence: 0.83
- **[P2] Allow failed Mermaid blocks to retry:** `ui/src/ui/mermaid.ts:149-150`
  - body: The renderer selects only blocks without `data-mermaid-status` and marks module-load or render failures as `error`. A transient chunk failure or incomplete streamed diagram is then permanently skipped until the DOM is rebuilt, even though the loader resets the import promise for future attempts.
  - confidence: 0.82
