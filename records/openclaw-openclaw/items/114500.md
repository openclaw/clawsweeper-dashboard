## Summary

Keep this PR open. It correctly targets the newline-leading `NO_REPLY` leak, but the same shared trailing-token regex now treats punctuation as a control-token boundary and removes literal user-visible text such as `question?NO_REPLY`; that broadening contradicts current behavior and the PR’s stated preservation goal. The prior P1 finding remains on the unchanged head.

## What This Changes

The PR changes shared auto-reply token parsing so newline-delimited leading `NO_REPLY` tokens and repeated trailing whitespace-delimited tokens are removed before ordinary and restart-recovered replies are delivered.

## System Context

Auto-reply normalizes model output before OpenClaw sends a reply to a channel. The shared silent-token helpers feed both ordinary reply delivery and pending-final delivery that resumes after a gateway restart.

## Best Possible Solution

Retain the newline-leading and repeated whitespace-delimited fixes, but restore the existing whitespace-only trailing boundary and add regression cases proving punctuation-attached literals remain visible.
