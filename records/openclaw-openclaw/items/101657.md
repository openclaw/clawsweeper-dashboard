## Summary

Keep open: current main and the latest release still make quarantined Skill Workshop proposals terminal for apply, revise, and reject, while any recovery path changes the security meaning of quarantine and needs maintainer direction.

## What This Changes

The issue requests a CLI/Gateway/UI path to recover or dismiss Skill Workshop proposals after they enter `quarantined` status.

## Best Possible Solution

Add one audited quarantine recovery contract, likely reject/dismiss quarantined proposals and allow revise-to-pending only after a fresh clean scan, then update service, CLI, Gateway, UI, docs, and tests together.

Unclear until maintainers choose the lifecycle contract. The safest implementation should preserve quarantine safety with explicit audit and rescan semantics rather than treating quarantined proposals as ordinary pending proposals.
