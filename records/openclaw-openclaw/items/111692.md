## Summary

The PR addresses a real ClickClack availability failure with a channel-local timeout boundary and includes credible live loopback proof; it remains necessary because current main's REST client has the existing websocket handshake timeout but no corresponding REST deadline. No discrete patch defect was established, though the new fixed deadlines intentionally change failure behavior for unusually slow self-hosted endpoints and uploads.

## What This Changes

The branch adds 30-second ClickClack REST deadlines, a 120-second upload deadline, and regression tests for stalled response headers and response-body reads.

## Best Possible Solution

Retain the channel-local deadline design, using the existing 30-second WebSocket handshake floor as the control-plane precedent, and land after confirming that the 120-second upload budget is acceptable for supported ClickClack deployments.
