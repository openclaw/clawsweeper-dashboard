## Summary

Keep open: current main and v2026.6.11 still intentionally try configured fallback speech providers after the selected TTS provider is skipped or fails, while the exact claim that successful ElevenLabs audio is discarded still lacks live proof.

## What This Changes

The issue asks OpenClaw TTS to play configured ElevenLabs audio instead of unexpectedly playing an OpenAI fallback voice after a provider-selection or fallback mismatch.

## Best Possible Solution

Decide and document the TTS fallback policy; if stickiness is desired, add an explicit strict provider mode with focused speech-core tests and keep the existing fallback default unless maintainers approve a breaking change.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should auto TTS keep using other configured speech providers as fallbacks when the selected provider is skipped or fails, or should OpenClaw expose provider stickiness for configured providers?

Rationale: Current docs and code make fallback deliberate, but this report shows the behavior can surprise users and has billing/voice-identity implications that automation should not decide as a default policy change.

Likely owner: steipete

Owner reason: Current blame and older TTS provider/config history make this the strongest available routing signal for a cross-cutting fallback-policy decision.

Owner confidence: high

Options:

- **Add opt-in provider stickiness (recommended):** Keep fallback as the compatibility default, but expose a documented strict mode that fails visibly instead of playing another provider when the selected provider cannot be used.
- **Keep fallback-only behavior:** Treat the remaining behavior as expected and improve docs/status messaging enough that users understand why OpenAI may play.
- **Fail closed by default:** Make configured TTS providers sticky by default and require upgrade communication because existing fallback setups may stop producing audio.

## Reproduction Assessment

No high-confidence live reproduction exists for the exact claim that successful ElevenLabs audio is discarded and OpenAI is played. Source inspection does reproduce the remaining fallback behavior: a selected provider skip or failure can synthesize with a later configured provider and report fallbackFrom.

## Solution Assessment

Unclear: forcing provider stickiness globally is not automatically the best fix because current docs describe fallback as intentional. The safer maintainable path is a maintainer-approved policy, likely an explicit strict mode plus diagnostics rather than an unconditional default break.
