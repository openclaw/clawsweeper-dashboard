## Summary

Keep open: current main and the latest release still intentionally allow TTS to fall through from a configured primary provider to another provider when the primary is skipped or fails; related merged PRs fixed diagnostics and ElevenLabs registration but explicitly left provider stickiness/fallback policy unresolved.

## What This Changes

The issue requests that TTS keep using the configured ElevenLabs provider instead of producing OpenAI audio after an ElevenLabs attempt appears to succeed.

## Best Possible Solution

Make an explicit TTS fallback-versus-stickiness product decision, then update speech-core behavior, status output, docs, and regression tests as one coherent policy change.

- **Keep fallback default, add explicit strict mode (recommended):** Preserve the documented fallback chain for upgrades while adding an explicit provider-stickiness or fail-closed mode only if maintainers accept the new config surface.

- **Close as expected fallback behavior:** Keep diagnostics and docs as the product answer, and close this issue unless new live proof shows a successful ElevenLabs audio result is discarded.
