## What This Changes

The issue asks OpenClaw TTS to play ElevenLabs audio when `messages.tts.provider` is `elevenlabs` instead of falling through to OpenAI after the ElevenLabs path is selected.

## Best Possible Solution

Make an explicit TTS fallback-versus-stickiness decision, then update speech-core behavior, `/tts status`, docs, and regression tests together.

- **Preserve fallback by default with explicit strict behavior (recommended):** Keep the documented fallback chain for existing users and add or define a narrow opt-in sticky/fail-closed policy only if maintainers want that behavior.

- **Keep diagnostics-only behavior:** Leave current fallback behavior as-is and close the remaining provider-stickiness expectation as not planned after documenting the rationale.
