## Summary

Keep open: current main and v2026.6.11 have fixed ElevenLabs registration and fallback diagnostics, but they still intentionally allow a configured TTS provider to fall through to another provider when the primary fails or is skipped.

## What This Changes

The issue requests that configured ElevenLabs TTS audio be played instead of silently ending up with OpenAI voice output.

## Best Possible Solution

Keep the shipped registration and diagnostics fixes, then make an explicit maintainer decision on strict provider stickiness versus documented automatic fallback before changing runtime behavior.

- **Keep diagnostics only:** Treat the current `/tts status` attempt chain and fallback visibility as the intended resolution and close the remaining stickiness request as not planned.

## Solution Assessment

Unclear until maintainers decide fallback policy; the merged registration and diagnostics fixes are useful partial fixes, but strict provider stickiness would change documented and tested behavior.
