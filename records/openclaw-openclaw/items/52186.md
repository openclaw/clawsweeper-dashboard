Rationale: Current source and docs treat TTS fallbacks as automatic, while the remaining request would change user-visible provider-routing semantics and possibly add config surface.

Likely owner: steipete

Owner reason: The current TTS/provider routing code and broad provider-qualified alias refactor point to steipete as the best available owner for the product-direction choice.

Owner confidence: medium

Options:

- **Preserve automatic fallback by default (recommended):** Keep the current default behavior, require live proof for any successful-audio-discard bug, and improve only diagnostics or targeted provider failures as needed.
- **Add opt-in strict TTS mode:** Expose a narrow, documented fail-closed provider setting so users can choose no fallback without breaking existing fallback users by default.
- **Make provider stickiness unconditional:** Change configured-provider failure to stop rather than fallback, accepting an upgrade-sensitive behavior break for users who currently depend on fallback speech.
