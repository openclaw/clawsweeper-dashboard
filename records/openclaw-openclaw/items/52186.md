## Summary

Keep open: current main has improved ElevenLabs registration and fallback diagnostics, but the central request remains unresolved because auto TTS still uses the general provider fallback chain and can play a later provider when the configured provider fails or is skipped. The remaining work is a maintainer product choice about provider stickiness versus fallback compatibility, not a safe autonomous close.

## What This Changes

The issue requests that ElevenLabs-configured TTS play the ElevenLabs-generated voice instead of falling back to an OpenAI voice after provider selection or playback failure.

## Best Possible Solution

Add a maintainer-approved strict or sticky-provider mode with upgrade-safe defaults, diagnostics, docs, and tests that prove both legacy fallback behavior and opt-in fail-closed behavior.
