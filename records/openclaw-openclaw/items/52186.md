## Summary

Keep open: current main and the latest release still allow configured TTS providers to fall back to another configured provider, while the exact successful-ElevenLabs-then-OpenAI playback claim still lacks live proof and the remaining fix is a provider-stickiness policy decision.

## What This Changes

The issue asks for ElevenLabs-configured TTS to play ElevenLabs audio instead of falling through to OpenAI after ElevenLabs is selected or used.

## Best Possible Solution

Decide and document the TTS fallback policy; if provider stickiness is desired, add an explicit strict or disable-fallback path with speech-core tests, status diagnostics, and docs while preserving the current default unless maintainers approve a breaking change.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Auto-TTS keep using other configured speech providers as fallbacks when the selected provider is skipped or fails, or should OpenClaw expose or enable provider stickiness for configured providers?

Rationale: Current docs and tests make fallback deliberate, but this report shows the fallback can surprise users and obscure provider billing/voice expectations; automation should not choose that product policy.

Likely owner: steipete

Owner reason: steipete has the strongest current-main ownership signal on the central speech-core fallback loop, and the remaining question is cross-cutting fallback policy.

Owner confidence: medium

Options:

- **Add opt-in provider stickiness (recommended):** Keep fallback as the compatibility default, but expose a documented strict mode that fails visibly instead of playing another provider when the selected provider cannot be used.
- **Keep fallback-only behavior:** Treat the remaining behavior as expected after diagnostics and docs clearly explain why OpenAI may play.
- **Fail closed by default:** Make configured providers sticky by default and require upgrade communication because existing fallback setups may stop producing audio.

## Reproduction Assessment

No high-confidence live reproduction of the exact successful-ElevenLabs-then-OpenAI playback path is available. Source inspection does show the remaining fallback path: if the selected provider is skipped or fails, OpenClaw can synthesize with another configured provider and record fallbackFrom.

## Solution Assessment

Unclear: forcing provider stickiness is not automatically the best fix because current docs describe fallback as intentional. The safer path is a maintainer-approved fallback policy, likely preserving fallback by default and adding an explicit strict mode if needed.
