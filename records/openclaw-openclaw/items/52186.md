## What This Changes

## Best Possible Solution

Make an explicit maintainer decision on TTS provider stickiness versus fallback, then align speech-core behavior, `/tts status`, docs, and regression tests together.

## Reproduction Assessment

No, not for the reporter's exact Ubuntu/ElevenLabs setup. Source inspection does show the remaining fallback path: automatic TTS can fall through from a configured primary provider to another configured provider when the primary attempt fails or is skipped.

## Solution Assessment

Unclear until maintainers decide the policy. The existing diagnostics and registration fixes are useful partial fixes, but the remaining change should either preserve documented fallback behavior or introduce an explicit sticky/fail-closed TTS mode with matching docs and tests.
