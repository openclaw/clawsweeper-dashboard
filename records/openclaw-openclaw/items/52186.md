## What This Changes

The issue asks for configured ElevenLabs TTS audio to be played instead of falling back to OpenAI after ElevenLabs is selected or attempted.

## Best Possible Solution

Make an explicit TTS provider stickiness versus fallback policy decision, then align speech-core behavior, status output, docs, and regression coverage with live ElevenLabs proof.

Options:

- **Add opt-in sticky mode (recommended):** Preserve the documented fallback default, but add a named strict/sticky TTS policy for users who want wrong-voice fallback to fail visibly instead of switching providers.
- **Change default to fail closed:** Make configured TTS providers sticky by default, accepting upgrade risk for users who currently depend on automatic fallback when their primary provider fails.
- **Keep fallback as designed:** Treat diagnostics and registration fixes as sufficient and close the remaining behavior as expected documented fallback semantics.

## Solution Assessment

Unclear until maintainers decide the policy. The existing diagnostics and registration fixes are useful partial fixes, but the remaining solution should explicitly choose sticky provider behavior or preserve documented fallback with an opt-in strict mode.
