## Summary

Keep this PR open. It addresses a real silent-success failure mode in the OpenAI Responses stream path, and the supplied loopback and live-provider evidence supports the proposed terminal-event invariant; it is neither obsolete nor superseded. The branch is behind current `main`, and the fail-closed behavior should be validated on the exact merge result before landing because OpenAI-compatible endpoints that omit semantic terminal events will now surface an error.

## What This Changes

The PR makes OpenAI Responses streaming reject EOF or `[DONE]` without a completed or incomplete response event, while preserving explicit failures, unresolved-tool errors, and caller cancellation.

## System Context

OpenAI and Azure Responses models feed SSE events into OpenClaw's shared AI transport, which turns them into assistant output, usage, and tool-call events for agent runs. This change decides whether a completed iterator represents a valid model result or an incomplete upstream stream before that output can be treated as successful.
