## Summary

Keep open: current main still forces iOS manual Tailscale CGNAT and .ts.net hosts onto the TLS/fingerprint path, while the issue’s latest real-device repro says that path still fails before the gateway sees a connection. The merged route-list work helps advertised Tailscale Serve candidates, but it does not resolve the direct CGNAT secure-transport policy or the native iOS TLS failure mode.

## What This Changes

The issue reports that the iOS app cannot connect to an OpenClaw Gateway over Tailscale CGNAT or Tailscale Serve because the native client requires secure WebSockets but the TLS/WebSocket path never completes.

## Best Possible Solution

Keep the secure-by-default mobile gateway policy, then make the iOS Tailscale path explicit and testable: either support Tailscale Serve/MagicDNS with clear diagnostics and fingerprint trust, or deliberately approve a narrow direct-tailnet exception with documented security limits and real iOS proof.
