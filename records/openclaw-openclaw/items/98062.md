## Summary

Keep open: current main only partially improved mobile route fallback, while the native iOS path still forces secure transports for Tailnet CGNAT and `.ts.net` hosts. The reporter's July 7 repro plus current source show the direct Tailnet/no-native-TLS case remains unresolved and needs a security/product decision rather than cleanup closure.

## What This Changes

The issue reports that the iOS app cannot connect to an OpenClaw Gateway over Tailscale CGNAT or Tailscale Serve because the required `wss://` path fails before the Gateway sees a WebSocket upgrade.

## Best Possible Solution

Keep the mobile secure-transport default, then make iOS remote pairing guide users toward Tailscale Serve or MagicDNS `wss://`, detect direct CGNAT/no-TLS gateways with an actionable diagnostic, and only add a direct-tailnet exception if maintainers explicitly approve that security boundary.
