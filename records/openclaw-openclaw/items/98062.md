## Summary

Keep open: current main still forces iOS manual Tailscale CGNAT and `.ts.net` hosts onto TLS/WSS, while the reporter supplied a July 7 live repro showing that a plain tailnet-bound Gateway still fails before any Gateway-side connection is logged. The merged route-list work helps LAN setup codes find a Tailscale Serve fallback, but it does not settle the direct CGNAT/native TLS trust policy or prove this iOS path works end to end.

## What This Changes

The issue asks OpenClaw to make the iOS app connect reliably to a Gateway over Tailscale CGNAT or Tailscale Serve using the supported secure WebSocket path.

## Best Possible Solution

Define and prove a supported iOS remote Gateway pairing path, preferably Tailscale Serve or another `wss://` endpoint with actionable reachability/TLS diagnostics, while preserving the plaintext fail-closed policy for Tailscale CGNAT and `.ts.net` unless maintainers explicitly approve a narrower trust rule.
