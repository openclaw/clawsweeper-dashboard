## Summary

Keep this PR open: it forwards the configured policy only for the speech submission, while the provider-controlled generated-audio URL is still fetched through the unguarded Vydra download helper. That leaves the requested transport-policy behavior incomplete and preserves an SSRF-sensitive result-download path; the prior P1 finding remains unresolved at the current head.

## Best Possible Solution

Make Vydra generated-media retrieval use the shared guarded transport path with the resolved private-network and dispatcher policy, while keeping authorization and custom request headers off provider-returned asset URLs; add focused speech and shared image/video regression coverage.
