## Summary

Keep open: the underlying request-policy gap is credible, but this branch covers only the synthesis POST, leaves generated-audio retrieval outside explicit proxy/TLS policy, and still lacks after-fix real transport proof.

## What This Changes

The PR passes sanitized `models.providers.vydra.request` configuration into the HTTP resolver used for the initial Vydra speech-synthesis request.

## Best Possible Solution

Resolve the Vydra request policy once, apply API headers/auth only to the Vydra API origin, carry the non-secret dispatcher and SSRF transport policy into generated-audio retrieval, and cover both stages with a controlled transport regression plus redacted runtime proof.
