## Summary

This PR remains necessary: current `main` accepts agent descriptions but does not expose them through the authorized `agents_list` discovery result. The implementation is narrow and has credible live Gateway proof, but making operator-authored description text model-visible is an intentional security/product boundary that needs maintainer acceptance before merge. Likely related people: `giodl73-repo` is the strongest adjacent configuration-history lead, with low-confidence routing support from `gavinbmoore`.

## What This Changes

The PR adds trimmed nonblank configured agent descriptions to the authorized `agents_list` tool result, updates its schema and documentation, and refreshes focused tests and Codex prompt snapshots.

## System Context

`agents_list` is the agent-facing discovery tool used before a session spawns an allowed sub-agent. It reads the canonical agent configuration, filters it through the requester’s sub-agent authorization, and returns portable metadata to the calling model.
