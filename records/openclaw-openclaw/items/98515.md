## Summary

Keep open: current main has mature cron, task ledger, heartbeat, commitments, and Task Flow surfaces, but it does not have a first-class durable routines registry. The `maintainer` label also makes this a protected product/design item, and the linked scheduling issues are partial overlaps rather than a canonical replacement.

## What This Changes

Request a durable routines registry for named scheduled team operations that stores routine intent and delegates the first schedule-backed trigger to existing Gateway cron jobs.

## Best Possible Solution

Keep this as the canonical maintainer-owned routine-registry design item; if approved, define one SQLite-backed routine model that compiles schedule triggers to cron and reuses the existing task ledger without duplicating scheduling or execution.

## Reproduction Assessment

Not applicable: this is a feature request for a new durable routine object, not a report of broken current behavior. Source inspection confirms current main has cron jobs and task records but no routine registry to reproduce against.

## Solution Assessment

Unclear until maintainers pick the product boundary. A schedule-backed routine registry is plausible, but the best implementation must reuse cron, SQLite state, and the task ledger while deciding whether future triggers belong in core, plugin API, or a separate security/provenance RFC.
