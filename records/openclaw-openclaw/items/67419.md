## Summary

Keep open: the issue still raises a real product-policy question beyond the merged opt-in continuation behavior. Current evidence narrows the native Codex portion—unchanged instructions are not replayed as model-visible history—but does not settle non-Codex, gateway-restart, changed-bootstrap, memory fallback, or default-policy behavior. Likely related people: `vincentkoc` (high confidence) introduced the continuation-skip contract; `xDarkicex` (high confidence) extended the same setting with the `never` mode.

## What This Changes

Request a lower-overhead bootstrap-context policy by making safe continuation injection the default, reducing initial memory payloads, and allowing cache-boundary control for changing workspace files.

## System Context

OpenClaw assembles workspace bootstrap files into agent context before a runtime turn. The selected injection policy decides whether that bootstrap payload is rebuilt for a continuation, affecting prompt-cache stability, context usage, and the instructions available after compaction or recovery.

## Architecture Diagram

## Best Possible Solution

Define and benchmark a single cross-runtime bootstrap lifecycle contract—fresh turn, safe continuation, post-compaction, changed files, and gateway restart—then retain an explicit opt-in mode or deliberately migrate the default only with upgrade-safe proof and user-facing guidance.
