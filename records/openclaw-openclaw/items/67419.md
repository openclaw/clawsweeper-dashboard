## Summary

Keep open. Current main still documents the implicit `always` behavior for workspace bootstrap injection, while the existing `continuation-skip` path remains opt-in; changing that default, changing MEMORY.md loading, and adding cache-boundary configuration are separate compatibility and product choices. The linked umbrella is useful shared analysis, but it explicitly treats bootstrap reinjection as its own track rather than a strict duplicate.

## What This Changes

Reduce repeated workspace-bootstrap context and related token/cache overhead by changing continuation behavior, memory loading, and bootstrap-file cache treatment.

## System Context

Agent runs assemble workspace bootstrap files such as AGENTS.md and MEMORY.md into the model context before a turn. The context-injection policy decides whether stable bootstrap material is included again on later turns, affecting transcript size, prompt-cache stability, and what context remains available after restart or compaction.

## Architecture Diagram

flowchart LR

  C[Session transcript and turn state] --> D[Continuation safety check]
  B --> D

  D -->|skip safe continuation| F[Existing transcript context]
  E --> G[Agent response and session updates]
  F --> G

## Best Possible Solution

Decide the continuation default independently, then implement a narrow completion rule that excludes heartbeat/lightweight/background turns and prove fresh-session, continuation, restart, and post-compaction behavior; keep configurable cache ordering in the dedicated open issue and treat MEMORY.md lazy loading as a separate product proposal.
