## Summary

The reported bug is valid, but this patch should not merge as written: it creates a second click/open state machine around a tooltip component that already supports combined click, hover, and focus triggers. The contributor also provides only mock-backed test evidence, without the promised visible after-fix proof.

## What This Changes

The PR replaces nine native-title Usage Overview hints with focusable Web Awesome tooltip buttons, adds manual click-state synchronization and styling, and expands unit and mocked-browser E2E coverage.

## Best Possible Solution

Use the tooltip's native trigger contract—prefer `trigger="hover focus click"` without parallel dataset or show/hide state—then retain focused regression coverage and attach redacted browser proof showing click, keyboard, Escape, reopening, and touch-sized rendering.
