Keep open: current main and the latest release still route Control UI `/model status` and `/model list` through the model mutation path, while docs and the shared directive handler define them as informational modes. ## What This Changes

The issue requests that Control UI treat `/model status` and `/model list` as `/model` subcommands instead of sending `status` or `list` to `sessions.patch` as model names.

## Best Possible Solution

Land one refreshed Control UI executor fix that routes `/model list` and `/model status` to the documented informational flows, preserves normal `/model <provider/model>` selection, and adds focused regression coverage.
