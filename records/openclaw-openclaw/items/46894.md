## Summary

Keep open: current main and the latest release still route non-empty `/model` arguments through `sessions.patch`, while the docs define `/model list` and `/model status` as informational commands. A linked open fork PR targets the same bug, but it is conflicting and not maintainer-editable, so the issue should remain open until that PR is refreshed/adopted or replaced.

## What This Changes

Handle WebUI `/model status` and `/model list` as informational slash-command subcommands instead of model ids that trigger `sessions.patch`.

## Best Possible Solution

Update the current `ui/src/pages/chat/chat-command-executor.ts` path so `status`, `list`, and likely `info` reuse the existing no-arg model-info path, while preserving `/model <provider/model>` and adding focused regression tests.
