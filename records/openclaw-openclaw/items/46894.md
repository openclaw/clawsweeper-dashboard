## What This Changes

The issue reports that the Control UI slash-command executor sends `/model status` and `/model list` as model-change requests instead of treating them as informational `/model` subcommands.

## Best Possible Solution

Land or replace one canonical Control UI fix that recognizes documented `/model list` and `/model status` before model mutation, preserves normal model selection, and adds focused executor regression coverage.

## Reproduction Assessment

Yes. Source inspection shows `/model status` and `/model list` parse into non-empty args, then current Control UI `executeModel` sends those args as `model` in `sessions.patch`, matching the reporter's logs.

## Solution Assessment

Yes, the best fix is a narrow Control UI command-routing repair before the model patch branch, but it should align with the documented shared `list` and `status` behaviors rather than only suppressing `sessions.patch`.
