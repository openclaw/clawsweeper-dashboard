## Summary

Keep open: current main and v2026.6.11 still route non-empty Control UI `/model` arguments through the model mutation path, while docs and the shared directive handler define `list` and `status` as informational modes. ## What This Changes

The issue asks for the Control UI `/model status` and `/model list` slash-command arguments to show model information instead of being submitted as model IDs.

## Best Possible Solution

Land a refreshed narrow Control UI executor fix that treats `status` and `list` as model-info modes, proves those subcommands never call `sessions.patch`, and preserves `/model <provider/model>` mutation behavior.
