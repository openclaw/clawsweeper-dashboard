## Label Justifications

- `P2`: This is a normal-priority Control UI model-command regression with a clear source path and limited blast radius.
- `impact:auth-provider`: The failure path misroutes model/status commands into provider-qualified model selection and surfaces provider allowlist errors.
- `impact:ux-friction`: Users trying documented `/model status` or `/model list` in the WebUI get avoidable errors and must use another path to inspect models.

## Summary

This issue is still necessary: current main and the latest release still send non-empty Control UI `/model` arguments such as `status` and `list` into `sessions.patch`, while docs and the shared directive path define them as informational/list commands.

## What This Changes

The issue requests that Control UI treat `/model status` and `/model list` as slash-command subcommands instead of literal model names.

## Best Possible Solution

Land one current-main Control UI fix that routes `/model list` and `/model status` before model mutation, aligns with the shared directive semantics, preserves normal `/model <provider/model>` selection, and adds focused executor tests.

Yes, source inspection gives a high-confidence reproduction path: `/model status` and `/model list` arrive as non-empty args, and current Control UI sends those args to `sessions.patch`. I did not run a live browser session, so this is source-reproducible rather than tool-reproduced.

## Solution Assessment

Yes, a narrow Control UI executor fix is the right direction, but it should mirror the documented shared `/model list` and `/model status` semantics instead of collapsing both into the bare `/model` summary.
