## Summary

Keep open: current main still sends every non-empty WebUI `/model` argument to the session model patch path, so `/model status` and `/model list` remain source-reproducible failures. The linked fork PR is an implementation candidate, but it is open, conflicting, and targets the old UI path.

## What This Changes

The issue requests that WebUI treat `/model status` and `/model list` as informational slash-command subcommands instead of model ids.

## Best Possible Solution

Refresh the fix against `ui/src/pages/chat/chat-command-executor.ts`, route only known informational subcommands such as `status`, `list`, and `info` through the existing model-info branch, and add regression tests proving those values do not call `sessions.patch` while real model values still do.
