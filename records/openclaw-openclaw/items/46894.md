## Summary

Keep open: current main and the latest release still send non-empty WebUI `/model` arguments through the session model patch path, so `/model status` and `/model list` remain source-reproducible. ## What This Changes

The issue reports that WebUI `/model status` and `/model list` are treated as model names instead of informational slash-command subcommands.

## Best Possible Solution

Land one current-main Control UI fix that routes `/model list` and `/model status` through documented informational behavior before model mutation, preserves normal `/model <provider/model>` selection, avoids reserving real model ids unnecessarily, and adds focused no-`sessions.patch` regression coverage.
