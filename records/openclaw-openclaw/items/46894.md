## Summary

Keep open: current main still treats Control UI `/model status` and `/model list` as non-empty model-setting arguments, and the latest release tag has the same behavior. The linked fix PR remains open but conflicting, so this issue is still the canonical tracker rather than closeable cleanup.

## What This Changes

Control UI `/model status` and `/model list` should show model information instead of sending `status` or `list` to `sessions.patch` as model ids.

## Best Possible Solution

Land a refreshed narrow Control UI executor fix that treats `list` and `status` as informational model modes, proves neither calls `sessions.patch`, and preserves `/model <provider/model>` mutation behavior.
