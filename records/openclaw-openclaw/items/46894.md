## Summary

Keep open: current main and the latest release still send non-empty WebUI `/model` arguments to `sessions.patch`, so `/model status` and `/model list` can still be misread as model IDs. Same-repo fix attempts are closed unmerged, and the only open closing reference is a conflicting cross-repo PR, so this needs maintainer dedupe rather than cleanup closure.

## What This Changes

The issue asks for WebUI `/model status` and `/model list` to be handled as informational slash-command subcommands instead of being sent as model IDs to `sessions.patch`.

## Best Possible Solution

Land one canonical Control UI fix that handles `/model list` and `/model status` before model mutation, preserves legitimate model IDs, aligns with the shared `/models` and status behavior, and adds focused WebUI executor regression tests plus redacted UI proof.
