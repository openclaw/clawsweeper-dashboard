## Summary

Keep open: current main and the latest release still route non-empty WebUI `/model` arguments into the session model patch path, so `/model status` and `/model list` remain source-reproducible against the documented command contract. ## What This Changes

The issue reports that WebUI `/model status` and `/model list` are treated as model ids instead of informational `/model` subcommands.

## Best Possible Solution

Implement the fix in the current `ui/src/pages/chat/chat-command-executor.ts` path so `/model list`, `/model status`, and probably `/model info` use the informational model path without calling `sessions.patch`, while preserving real `/model <provider/model>` setting behavior with regression tests.
