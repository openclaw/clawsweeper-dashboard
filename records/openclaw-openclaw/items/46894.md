## Summary

Keep open: current main still routes any non-empty WebUI `/model` argument through `sessions.patch`, while current docs say `/model list` and `/model status` are informational. The same-repo fix PRs are closed unmerged, and the remaining open fork PR is conflicting and outside the target repository.

## What This Changes

The issue asks for WebUI `/model status` and `/model list` to use the informational model-command path instead of being treated as model IDs.

## Best Possible Solution

Apply the same invariant to the current WebUI executor: treat documented informational `/model` subcommands as info requests, keep real model switching unchanged, and add focused regression coverage that `status` and `list` never call `sessions.patch`.
