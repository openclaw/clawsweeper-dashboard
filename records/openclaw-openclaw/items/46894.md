## Summary

Keep open: current main still sends non-empty WebUI `/model` arguments through `sessions.patch`, so `/model status` and `/model list` can still be treated as model ids despite the documented command semantics. The same-repo attempted fixes are closed unmerged, and the remaining open fork PR is conflicting and not a proven canonical fix.

## What This Changes

The issue reports that WebUI `/model status` and `/model list` should be local informational slash-command subcommands, not model names passed to `sessions.patch`.

## Best Possible Solution

Land one current-main Control UI fix that handles `/model list` and `/model status` before model mutation, preserves valid model ids, aligns with the shared directive semantics, and adds focused executor coverage plus redacted UI proof.
