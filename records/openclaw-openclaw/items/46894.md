## Summary

Keep open: current main still sends every non-empty WebUI `/model` argument through the session model patch path, so `/model status` and `/model list` remain source-reproducible despite the shared Gateway directive path already handling those subcommands.

## What This Changes

The issue asks for the WebUI `/model status` and `/model list` inputs to behave as informational slash-command subcommands instead of being treated as model IDs.

## Best Possible Solution

Refresh or replace the linked fix so the current WebUI executor handles documented `/model list` and `/model status` modes before model mutation, preserves real model selection, and adds focused regression coverage.

Yes from source inspection: `/model status` is parsed as a non-empty `args` value and current `executeModel` sends all non-empty values to `sessions.patch`. I did not run a live browser repro in this read-only pass.

## Solution Assessment

Yes, the narrow maintainable fix is to route only documented informational subcommands before the model patch path while preserving `/model <provider/model>`. Current main does not implement that WebUI local behavior yet.
