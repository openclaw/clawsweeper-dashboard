## Summary

Keep open: current main still routes WebUI `/model status` and `/model list` through the local model-setting path, so the reported `sessions.patch` failure is still source-reproducible. A sibling auto-reply/channel path handles these words correctly now, but the Control UI local executor has not adopted that behavior.

## What This Changes

The issue asks Control UI chat to treat `/model status` and `/model list` as informational model commands instead of model IDs passed to `sessions.patch`.

## Best Possible Solution

Update the Control UI local `executeModel` path so `status`, `list`, and likely `info` reuse the model-info/list response without calling `sessions.patch`, while keeping `/model <provider/model>` unchanged and covered by regression tests.
