## Summary

Keep open: current main still routes non-empty `/model` arguments through `sessions.patch`, while current docs reserve `/model list` and `/model status` for informational behavior. An open fork PR references this issue, but it is not merged and is currently conflicting, so the issue remains necessary.

## What This Changes

The issue asks for WebUI `/model status` and `/model list` to be handled as slash-command subcommands instead of session model names.

## Best Possible Solution

Update `ui/src/pages/chat/chat-command-executor.ts` so `/model list`, `/model status`, and likely `/model info` use the informational path without calling `sessions.patch`, add focused regression tests, and then rebase/adopt or close the open fork PR.
