## Summary

Keep open: current main and the latest release still route non-empty WebUI `/model` arguments into the session model patch path, so the reported `/model status` and `/model list` failure remains source-reproducible. A linked external fix PR exists, but it is conflicting and targets the older UI path, so the issue should remain open until a refreshed fix lands or that candidate is resolved.

## What This Changes

WebUI `/model status` and `/model list` should show model information instead of treating `status` or `list` as model IDs.

## Best Possible Solution

Refresh the fix against `ui/src/pages/chat/chat-command-executor.ts`, route only known informational subcommands such as `status`, `list`, and `info` through the existing model-info branch, and add regression coverage proving those values do not call `sessions.patch` while real model values still do.
