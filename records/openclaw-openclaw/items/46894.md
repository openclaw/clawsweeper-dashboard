## Summary

Keep open: current main still routes `/model status` and `/model list` through the non-empty `/model` model-setting branch, and the only linked closing PR is still open and conflicting, so no close reason is satisfied.

## What This Changes

The issue asks for WebUI `/model status` and `/model list` to be handled as informational slash-command subcommands instead of model names passed to `sessions.patch`.

## Best Possible Solution

Refresh or replace the linked fix so current `ui/src/pages/chat/chat-command-executor.ts` treats `status`, `list`, and `info` as informational `/model` modes and adds regression tests proving no `sessions.patch` call occurs.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source inspection: the WebUI registers `/model` as a local command, dispatches it to `executeModel`, and the current non-empty args branch calls `sessions.patch` with `model: "status"` or `model: "list"`. I did not run a live WebUI scenario in this read-only review.

## Solution Assessment

Yes, the best fix is the narrow executor change: route `status`, `list`, and `info` through the existing model-info path while leaving `/model <provider/model>` unchanged. The open candidate has the right shape but needs refresh to the current file layout.
