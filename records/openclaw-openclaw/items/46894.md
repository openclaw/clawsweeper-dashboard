## Summary

Keep open: current main and the latest release still route non-empty Control UI `/model` arguments through session model mutation, while docs and the shared directive handler define `list` and `status` as informational model commands. Open linked PRs remain unmerged, so this issue is still the canonical tracker.

## What This Changes

The issue asks for WebUI `/model status` and `/model list` to be treated as informational slash-command modes instead of model-set values.

## Best Possible Solution

Refresh, review, or replace the linked Control UI executor fix so `status` and `list` route to model information before mutation, with regression coverage that they never call `sessions.patch` while `/model <provider/model>` still works.
