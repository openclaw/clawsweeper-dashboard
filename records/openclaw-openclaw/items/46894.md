## Label Justifications

- `P2`: This is a normal-priority Control UI regression with a clear source path and limited blast radius around model slash-command handling.
- `impact:auth-provider`: The bug misroutes model/provider command input into session model selection and surfaces provider/model allowlist errors.
- `impact:ux-friction`: Users can still work around the issue, but documented `/model status` and `/model list` commands fail in the WebUI and create avoidable confusion.

## Summary

Keep open: current main still routes any non-empty Control UI `/model` argument through `sessions.patch`, while current docs say `/model list` and `/model status` are informational model views. An open linked fork PR proposes the narrow fix, so this issue should remain open until a target fix lands or maintainers deliberately replace that candidate.

## What This Changes

The issue requests treating Control UI `/model status` and `/model list` as informational slash-command modes instead of model IDs passed to `sessions.patch`.

## Best Possible Solution

Land a narrow Control UI fix that routes `/model status`, `/model list`, and likely `/model info` through the same informational path as bare `/model`, with regression tests proving `sessions.patch` is not called.

Yes, from source inspection: current main treats `status` or `list` as a non-empty model argument and calls `sessions.patch`. I did not run the WebUI, so this is source-reproducible rather than live-reproduced.

## Solution Assessment

Yes, the narrow maintainable fix is to recognize documented informational `/model` subcommands before the patch path and add regression coverage. A broader model-routing refactor is unnecessary for this specific failure.
