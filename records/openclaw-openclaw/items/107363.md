## Label Justifications

- `P1`: A valid concurrency race silently removes LINE group context during an active channel workflow and can affect busy groups repeatedly.
- `impact:message-loss`: Ambient LINE messages recorded during a mention turn are silently removed before they can reach the next agent turn.
- `impact:session-state`: Whole-key cleanup makes the group-history window diverge from the messages that were actually consumed by the completed turn.

## Summary

Current main still has the reported race: LINE snapshots pending group history, awaits the agent turn, then clears the whole group key while separate webhook dispatches may record new entries. The linked fix PR is open and explicitly closes this issue, so the issue should remain open until that PR is reviewed and merged. Likely related people: kirisame-wang introduced the LINE pending-history flow, Takhoffman merged that feature, and RealKai42 introduced its mention-gating foundation.

## What This Changes

Preserve LINE ambient group-history messages recorded concurrently while a mention-triggered agent turn is running.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/107367 if its consumed-entry cleanup preserves failure semantics and its deterministic concurrent-dispatch test passes; then let the merged PR close this issue.

## Reproduction Assessment

Yes at source level: start a mention turn, record an unmentioned message into the same group history while processMessage is pending, then complete the turn and observe the whole-key clear remove both old and new entries. I did not execute the focused test against the read-only checkout.

## Solution Assessment

Yes in principle: deleting only entries included in the pre-turn snapshot is narrower than serializing all LINE webhook handling and preserves concurrent arrivals. The linked PR should prove stable entry identity and unchanged failed-turn retention before merge.
