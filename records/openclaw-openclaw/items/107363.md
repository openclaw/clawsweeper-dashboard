## Label Justifications

- `P1`: A reproducible race silently drops LINE group context during an active channel workflow, affecting real mention-gated conversations.
- `impact:message-loss`: Ambient LINE messages recorded during an agent turn can be silently deleted before they reach the next turn's context.
- `impact:session-state`: The race corrupts the in-memory group-history window by removing entries that the completed turn never consumed.

## Summary

Current main still has the reported race: a LINE mention turn reads pending group history, awaits agent processing, and then clears the whole history key, so a separate webhook dispatch can record an ambient message that the later clear silently removes. The linked pull request remains open and explicitly closes this issue, so the issue should stay open until that candidate is reviewed and merged.

**Likely related people**
- kirisame-wang — high confidence; introduced the merged LINE pending-history flow.
- Takhoffman — medium confidence; merged the feature that established the affected cleanup path.
- RealKai42 — medium confidence; contributed the earlier mention-gating foundation used by that flow.

## What This Changes

Prevent LINE mention turns from deleting ambient group-history messages that are recorded concurrently while the agent is processing.

## Best Possible Solution

Land a focused consumed-entry cleanup that assigns stable identities before the turn, removes only the snapshotted entries after a successful turn, preserves concurrently recorded entries and failed-turn retry semantics, and includes deterministic concurrency regression coverage.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes—there is a high-confidence source-level reproduction: pause a mention turn inside message processing, dispatch an unmentioned group message, then complete the turn and observe whole-key cleanup remove the newly recorded entry. The linked PR describes a deterministic gated-promise regression test for this sequence, although this review did not independently execute it.

## Solution Assessment

Yes—the narrowest maintainable fix is to snapshot the identities of entries supplied to the turn and remove only those after success, rather than serializing all webhook processing or changing mention policy. This preserves concurrent arrivals and the existing failed-turn retry behavior.
