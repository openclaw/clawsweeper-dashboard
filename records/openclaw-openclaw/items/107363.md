## Label Justifications

- `P1`: A normal, supported LINE group workflow can silently lose ambient messages whenever they arrive during an active mention turn.
- `impact:message-loss`: A concurrently recorded group message is silently deleted before it can reach the next mention turn.
- `impact:session-state`: The pending group-history context window drifts from the messages actually received because cleanup removes entries the completed turn never consumed.

## Summary

Current main still has the reported LINE history race, and the same-author pull request that specifically addresses it remains open, so this issue should stay open until that candidate or an equivalent fix merges.

## What This Changes

Prevent a LINE mention turn from deleting ambient group-history messages recorded concurrently while the agent is processing.

## Best Possible Solution

Use LINE-owned snapshot identities to remove only history entries consumed by the completed mention turn, retain later concurrent entries, and land focused concurrency coverage plus redacted live LINE proof.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: park a LINE mention turn inside message processing, record an unmentioned message through a concurrent dispatch, then complete the turn and inspect the history window. A live LINE run was not performed during this read-only review.

## Solution Assessment

Yes in direction: clearing only the snapshotted entries is narrower and safer than a whole-key delete because it preserves existing retry semantics while removing only context the turn consumed.
