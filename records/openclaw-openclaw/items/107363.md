## Label Justifications

- `impact:message-loss`: The whole-key cleanup removes a concurrently received group message before it can reach a later agent turn.
- `impact:session-state`: The race corrupts the buffered ambient-history state associated with the LINE group conversation.

## Summary

Current main still has the reported race: LINE webhook events can overlap while mention-turn cleanup deletes the entire buffered history key. The directly linked fix remains open, so this issue is still necessary until that PR or an equivalent repair merges.

## What This Changes

Preserve LINE group-history messages recorded concurrently while a mention-triggered agent turn is running.

## Best Possible Solution

Use consumed-entry cleanup: snapshot stable entry identities before awaiting the agent, remove only those entries after a successful turn, retain concurrently appended entries, and cover the exact interleaving with focused LINE regression tests.

## Reproduction Assessment

Yes at source level: pause a mention turn inside processing, record an unmentioned group message through a concurrent webhook dispatch, then finish the turn and observe the whole-key cleanup remove both old and newly recorded entries. This review did not execute that scenario against a live LINE account.

## Solution Assessment

Yes in principle: removing only entries captured by the pre-turn snapshot directly restores the required concurrency invariant without adding configuration or changing failure semantics. The linked PR should still receive normal patch review and real-behavior proof before merge.
