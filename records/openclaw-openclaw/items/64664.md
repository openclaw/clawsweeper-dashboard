## Summary

Keep open: current main and the latest release still create fresh process-local exec/plugin approval managers, so a gateway restart drops pending approval IDs; the Telegram retry-loop symptom is fixed, but the remaining restart-stale approval UX and security boundary need maintainer direction.

## What This Changes

The issue reports that gateway restarts discard in-flight approval IDs, leaving stale Telegram approval buttons or `/approve` retries to return confusing approval-not-found errors instead of a clear recovery path or durable approval state.

## Best Possible Solution

Make restart-stale approvals fail closed as an explicit expired/restart state across `/approve`, Telegram callbacks, and approval clients unless maintainers deliberately approve a durable SQLite design with replay guards.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should restart-stale exec/plugin approvals be deliberately invalidated with clear recovery UX, or should pending approvals be persisted and restored across gateway restarts?

Rationale: The implementation choice changes the privileged approval trust boundary: fail-closed UX is simpler and safer, while persistence needs a durable state and replay model for approvals that authorize command execution.

Likely owner: steipete

Owner reason: The current central gateway approval and callback paths are most recently tied to this author in current-main history.

Owner confidence: medium

Options:

- **Invalidate on restart (recommended):** Treat gateway restart as approval expiry and make all user-facing approval paths tell the operator to re-request the action.
- **Persist with replay guards:** Store pending approvals in SQLite with expiry, requester/approver binding, replay limits, and restart cleanup tests before restoring them after restart.
- **Split UX and persistence:** Land the explicit stale/restart copy first and track durable approval persistence as a separate security design item.

## Reproduction Assessment

Yes at source level. A fresh gateway process constructs empty in-memory approval managers, so an old approval ID can no longer resolve; I did not run a live Telegram restart in this read-only review.

## Solution Assessment

Unclear until maintainers choose the security boundary. A narrow fail-closed UX fix is the safest current shape, while restart persistence is a broader durable-state design with replay implications.
