## Summary

Keep open: this is a small useful diagnostics fix, but the current patch still accepts partially malformed `lsof` PID records because it keeps `Number.parseInt`, and the PR body only shows mocked Vitest proof.

## What This Changes

The PR makes Unix `lsof` listener parsing skip address rows when the current process record has no positive PID and updates a port-inspection test.

## Best Possible Solution

Tighten lsof PID parsing with the existing strict positive-integer helper, keep listener dedupe coverage, and add redacted real diagnostics proof before merge.

## Reproduction Assessment

Yes, from source inspection: current `main` can turn a malformed `p` record followed by an `nTCP ... (LISTEN)` row into a listener entry without a valid PID. I did not run tests because this review is read-only.

## Solution Assessment

No. The PR is a plausible local fix, but the best fix should parse the full `p` token strictly instead of accepting `Number.parseInt` prefixes, and it should preserve the existing dedupe behavior test.
