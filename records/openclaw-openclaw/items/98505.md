## Summary

Keep open. Current main still truncates malformed lsof PID tokens, while this active PR hardens the three relevant lsof PID surfaces with focused coverage and a maintainer-approved fail-closed behavior.

## What This Changes

The PR hardens Unix lsof PID parsing across port diagnostics, gateway --force cleanup, and stale gateway restart cleanup so malformed PID tokens are rejected or fail closed instead of being truncated into valid PIDs.

## Best Possible Solution

Keep strict positive-integer parsing as the canonical lsof PID boundary, preserve unknown-PID diagnostics, and use the maintainer-approved fail-closed cleanup behavior when ownership cannot be trusted.

## Reproduction Assessment

Yes. Source inspection shows current main uses Number.parseInt on lsof p-fields in the affected paths, which reproduces p111abc-to-111 truncation without needing a live corrupted lsof binary.

## Solution Assessment

Yes. Using the existing strict positive-integer helper at each lsof PID boundary is the narrowest maintainable fix; skipping all malformed listener evidence or preserving parseInt truncation would either hide occupancy or keep fabricating PIDs.
