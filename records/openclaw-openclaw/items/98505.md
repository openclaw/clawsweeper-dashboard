## Summary

Keep this PR open, but not merge-ready yet: it fixes the diagnostics parser, while the sibling force-free `lsof` parser still accepts digit-prefixed malformed PID tokens such as `p111abc` as PID 111.

## What This Changes

The branch hardens `src/infra/ports-inspect.ts` lsof PID parsing with `parseStrictPositiveInteger` and adds listener diagnostics regression tests.

## Best Possible Solution

Use strict whole-token positive PID parsing for both diagnostics and force-free lsof p-field parsers, with focused regression coverage for both paths.

## Reproduction Assessment

Yes. Source inspection shows current main truncates digit-prefixed malformed lsof PID tokens with `Number.parseInt` in both the diagnostics parser and the sibling force-free parser.

## Solution Assessment

No. The diagnostics change is the right local shape, but the best fix should apply the same strict whole-token PID validation to the force-free parser too.
