## Summary

Keep open: the diagnostics parser fix is directionally correct and has useful proof, but the same malformed `lsof` PID invariant remains unpatched in the sibling force-free parser, so this is not yet the best complete fix.

## What This Changes

The PR changes Unix `lsof` listener diagnostics to accept only strict positive PID fields before attaching address rows and adds malformed PID regression tests.

## Best Possible Solution

Use the shared strict PID parser for all `lsof` `p` field parsing in this port surface and keep the new diagnostics regression coverage.

## Reproduction Assessment

Yes, by source inspection. Current main's diagnostics parser truncates `p111abc` with `Number.parseInt` before attaching the following `nTCP` row, and the sibling force-free parser has the same trailing-garbage weakness.

## Solution Assessment

No. The diagnostics change is the right local shape, but the best fix should apply the same whole-token PID validation to the sibling `lsof` force-free parser or explicitly document why that parser has a different contract.
