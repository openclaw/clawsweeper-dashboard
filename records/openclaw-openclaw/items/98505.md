## What This Changes

The PR makes Unix lsof listener parsing accept only strict positive PID tokens before attaching address rows and adds malformed-token regression tests.

## Best Possible Solution

Land the narrow parser and regression-test change after ordinary maintainer review and required current-head checks.

## Reproduction Assessment

Yes. Current main's lsof field parser can be source-reproduced with a p111abc line followed by an nTCP listener row, because Number.parseInt truncates the PID token before the row is attached.

## Solution Assessment

Yes. Reusing parseStrictPositiveInteger at the lsof parser boundary is the narrowest maintainable fix and avoids adding a new parsing contract.
