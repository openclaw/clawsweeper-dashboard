The PR changes Unix lsof listener diagnostics to parse p-record PIDs with strict positive-integer parsing, skip address rows without a valid PID context, and adds focused diagnostics regression tests.

## Best Possible Solution

Use strict whole-token positive PID parsing for both diagnostics and force-free lsof p-field parsers, with regression coverage for both paths.

## Reproduction Assessment

Yes. Source inspection shows Number.parseInt truncates digit-prefixed malformed lsof p-records in current main, and the PR adds a diagnostics regression for that exact p111abc case.

## Solution Assessment

No. The diagnostics change is the right local shape, but the best fix should apply the same strict whole-token PID validation to the force-free parser too.
