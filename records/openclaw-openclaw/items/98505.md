## Summary

Keep this PR open: current main still accepts malformed numeric-prefix lsof PID records in the diagnostics parser, while the updated branch now applies the existing strict positive-integer parser and restores/extends focused coverage.

## What This Changes

The PR changes Unix port diagnostics to ignore lsof listener address rows unless the current process record has a strictly valid positive PID, and adds regression tests for missing and garbage-suffixed PID tokens.

## Best Possible Solution

Land the narrow parser/test fix after normal maintainer review and required checks, keeping the shared strict integer parser as the canonical PID token contract.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: feed an lsof record such as p111abc followed by an nTCP listener row through current main's parser and it can attach that row to PID 111.

## Solution Assessment

Yes. Reusing parseStrictPositiveInteger at the existing lsof parser boundary is the narrowest maintainable fix; adding a new local regex/parser would duplicate an existing contract.
