## Summary

Keep open: the PR targets the right lsof listener parser, but the current patch still accepts partially malformed PID tokens through `Number.parseInt`, and the posted proof shows normal `lsof` output rather than the after-fix malformed-row behavior.

## What This Changes

The PR changes Unix port diagnostics to skip listener address rows unless the current lsof process record has a positive PID and updates the port-inspection test.

## Best Possible Solution

Use the existing strict positive-integer parser for lsof p records, keep valid listener and dedupe behavior covered, and add redacted terminal or log proof that the diagnostics path ignores malformed rows.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path by feeding an lsof record such as `p111abc` followed by an `nTCP ... (LISTEN)` row through the parser; I did not execute tests in this read-only review.

## Solution Assessment

No. The patch is aimed at the right parser, but the best fix should parse the full PID token strictly and preserve the existing lsof dedupe coverage before merge.
