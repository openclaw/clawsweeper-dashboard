## Summary

Keep this issue open, but narrow its premise: Node’s documented thread-0 behavior contradicts the claimed `TypeError` crash, while the current retry branch does synchronously block the event loop during SQLite journal-mode contention. A current-main contention harness is needed before choosing a safe repair.

## What This Changes

Investigate and eliminate harmful main-thread blocking during SQLite WAL journal-mode lock retries.

## Best Possible Solution

Add a deterministic current-main contention test that records both thrown errors and event-loop timer progress, then move retry waiting off the Gateway thread if the measured stall affects active runtime; do not replace it with a busy loop.
