## Summary

Keep this issue open for clarification rather than queueing a fix. The retry branch does synchronously block the Node.js event loop, but the reported `TypeError` crash premise conflicts with Node’s documented support for `Atomics.wait()` on thread 0, and the issue provides no current-main lock-contention trace or failing reproduction. ([nodejs.org](https://nodejs.org/download/release/v22.18.0/docs/api/cli.html?utm_source=openai))

## What This Changes

Investigate and replace the synchronous SQLite WAL lock-retry sleep that can temporarily block the gateway thread during journal-mode initialization.

## Best Possible Solution

Add a deterministic two-connection contention regression that proves the current retry outcome and measures event-loop progress; if the bounded stall reaches a live gateway path, move journal initialization before request serving or introduce a properly asynchronous opener rather than adding a spin loop.
