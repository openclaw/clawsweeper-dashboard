## Summary

This PR remains necessary because current `main` still routes asynchronously finalized Slack file uploads as edit/system events, but the unchanged proposed head does not fix the full delivery path: its promoted event retains the original message timestamp and is rejected by existing in-memory or persistent delivery dedupe after the initial event dispatches. The router-level tests do not exercise that downstream collision, and the production-use statement lacks inspectable redacted real-behavior evidence. Likely related people: @steipete (high confidence, current message-router and dedupe provenance), @Takhoffman and @littleben (medium confidence, prior Slack app-mention dedupe fixes), and @scoootscooob (medium confidence, Slack routing/debounce history).

## What This Changes

The PR conditionally promotes user-authored Slack file-share `message_changed` payloads into normal inbound processing and adds four event-router regression tests.

## Best Possible Solution

Represent a qualifying file finalization with a stable content-version identity distinct from the initial incomplete delivery but stable across Slack retries, then prove initial delivery, finalization, replay suppression, ordinary-edit suppression, and attachment extraction through the real handler and a redacted live Slack run.
