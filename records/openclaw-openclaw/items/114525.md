## Summary

Keep this PR open, but it is not ready to merge: the latest revision still applies a context-free escape decoder to every string-valued tool argument for selected models, while the reported regression is specifically a write-tool content case. The branch also still lacks redacted real Volcengine/DeepSeek after-fix evidence showing the provider payload and corrected tool output.

## What This Changes

The PR adds a DeepSeek-only Volcengine compatibility mode that decodes repeated literal newline, tab, carriage-return, and backslash escapes in streamed tool-call argument objects before OpenClaw tools receive them.

## System Context

Volcengine model compatibility metadata feeds the embedded agent runner, which wraps a provider response stream before tool calls are dispatched. This PR inserts a decoder into that shared stream path, so it can affect arguments for every tool invoked by the selected DeepSeek models.

## Best Possible Solution

Decode only a demonstrated Volcengine transport encoding at the parser/transport boundary, preserving canonical tool arguments by default; if the evidence proves the issue is limited to a particular tool field, constrain the repair to that exact operation and add regression coverage for literal escape text in other tool arguments.
