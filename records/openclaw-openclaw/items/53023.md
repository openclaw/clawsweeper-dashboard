Keep open. Current main and v2026.6.11 still serialize each session lane at one active task, do not expose session-concurrency or auto-yield config, and only the narrower lane-wait warning threshold is covered by an open conflicting PR.

Request configurable per-session lane concurrency, automatic yielding after long tool execution, and a configurable lane-wait warning threshold.

## Best Possible Solution

Keep this as the umbrella design tracker: land or replace the diagnostics-threshold slice separately, then require a maintainer-approved session scheduler contract before adding public concurrency or auto-yield config.
