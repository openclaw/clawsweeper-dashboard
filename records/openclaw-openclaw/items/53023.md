## Summary

Keep open. Current main and latest release v2026.6.11 still serialize each session lane at one active run, do not expose session-concurrency or auto-yield config, and the only active implementation candidate covers the narrower lane-wait diagnostic threshold slice.

## What This Changes

The issue requests configurable per-session lane concurrency, automatic yielding during long tool execution, and a configurable lane-wait warning threshold.

## Best Possible Solution

Keep this as the umbrella design tracker, land or replace the narrow diagnostics-threshold PR separately, and require a maintainer-approved session scheduler contract before implementing session concurrency or auto-yield.

## Reproduction Assessment

Yes, at source level: current main still initializes lane state with one active task and embedded runs still route through a session lane before global execution. The exact reported wait durations remain workload-dependent and were not live-reproduced in this read-only review.

## Solution Assessment

Unclear. The requested knobs are plausible, but the best solution needs maintainer decisions on session ordering, cancellation, transcript safety, and public config shape before code should be written.
