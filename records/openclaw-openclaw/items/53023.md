## Summary

Keep open. Current main and v2026.6.11 still serialize each session lane at one active run, expose only global/subagent concurrency defaults, keep yielding as an explicit `sessions_yield` action, and leave the warning-threshold slice to a separate open PR.

## What This Changes

Request configurable per-session lane concurrency, automatic yield after long tool execution, and a configurable lane-wait warning threshold for interactive agent responsiveness.

## Best Possible Solution

Keep this as the umbrella design tracker, land or replace the narrow diagnostics-threshold PR separately, and require a maintainer-approved session scheduler contract before implementing session concurrency or auto-yield.
