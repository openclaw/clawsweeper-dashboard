Keep open. Current main and v2026.6.11 still serialize session lanes at one active run, expose no session-concurrency or auto-yield config, and only the narrower lane-wait diagnostic threshold is covered by an open unmerged PR.

## What This Changes

The issue requests configurable per-session lane concurrency, automatic yielding during long tool execution, and a configurable lane-wait warning threshold for interactive agent responsiveness.

## Best Possible Solution

Keep this open as the umbrella design tracker: land or replace the narrow diagnostics-threshold PR separately, then require a maintainer-approved session scheduler contract before implementing session concurrency or auto-yield.
