## Summary

Keep open. Current main and the latest release still keep each session lane serialized by default and do not expose the requested session-concurrency or auto-yield config; current steer/interrupt paths are useful partial mitigations, and the lane-wait threshold slice is separately covered by an open unmerged PR.

## What This Changes

Requested configurable per-session lane concurrency, automatic yielding during long tool execution, and a configurable lane-wait warning threshold for interactive agent sessions.

## Best Possible Solution

Keep this as the umbrella design tracker: review or replace the narrow diagnostics-threshold PR separately, and require a maintainer-approved session scheduler contract before implementing session concurrency or auto-yield.

Yes, at source level. Current main still creates session lanes with one active task, routes embedded runs through those lanes, exposes only global/subagent concurrency in config, and implements yield through explicit sessions_yield rather than an automatic policy.

Unclear. The requested knobs are plausible, but the best solution needs maintainer decisions on session ordering, cancellation, transcript safety, and public config shape before code should be written.
