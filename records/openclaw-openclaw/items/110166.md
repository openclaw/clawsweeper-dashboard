## Summary

Keep this PR open for a narrow correctness repair: it invokes the existing verdict loader after route data is applied, but that loader still returns when the page has a usable client while `connected` is temporarily false—the reported route-data state—after which the route-data short-circuit leaves the verdict map unhydrated. The supplied live Gateway and Chromium transcript is credible after-fix behavior proof for the covered connected path, but it does not cover that remaining state transition.

## What This Changes

The PR exports and invokes the existing ClawHub-verdict loader after Skills route data is applied, renders missing verdicts as Refreshing while loading, and adds a browser regression test.

## Best Possible Solution

Make the route-data path hydrate verdicts when the client can actually request them, or retry exactly once on the usable-client transition, and add regression coverage for a route report applied while `connected` is transiently false.
