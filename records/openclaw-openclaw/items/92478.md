## Summary

Keep open: current main still lets Browser/Control UI Talk start through client-owned realtime creation and proceed to the OpenAI WebRTC offer path before any UI-level configured/availability gate; adjacent OAuth-only 500 work was closed, but this issue's visible-button and preflight contract remains unresolved.

## What This Changes

The issue requests that the Control UI Talk button avoid starting OpenAI Realtime WebRTC when Realtime is not configured and instead stay disabled, show an actionable message, or respect local Talk/TTS configuration.

## Best Possible Solution

Expose a Gateway-owned realtime Talk availability/preflight contract and have Control UI disable or explain Talk before microphone/WebRTC when no realtime provider/transport is actually usable, while leaving native/local STT-TTS Talk paths intact.
