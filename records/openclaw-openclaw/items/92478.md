## Summary

Keep open: current main still exposes the Control UI Talk button and enters the client-owned realtime path before the browser posts SDP to OpenAI; related auth fixes and diagnostics cover narrower credential failures but do not settle the product contract for when browser Talk should be enabled.

## What This Changes

The issue asks Control UI Talk to avoid starting OpenAI Realtime WebRTC when the user intends a local/non-Realtime Talk setup, and to show a clear readiness or configuration message instead.

## Best Possible Solution

Make Gateway-owned realtime readiness the single source for the Control UI Talk button and startup error after maintainers choose whether implicit OpenAI/Codex auth should enable browser Talk.
