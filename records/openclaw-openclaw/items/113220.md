## Summary

The reported “model is not allowed” failure is no longer caused by `agents.defaults.models` on current main: that map now holds aliases and per-model settings, while the optional `agents.defaults.modelPolicy.allow` owns override restrictions. This issue remains open only as a broader, compatibility-sensitive product request to remove active metadata/configuration behavior, which needs an explicit maintainer direction rather than a cleanup patch.

## What This Changes

Remove `agents.defaults.models` so model access follows provider availability or a more dynamic policy instead of a manually maintained model map.

## System Context

OpenClaw combines provider catalogs, agent-level model metadata, and an optional override policy to populate model pickers and validate session or CLI model changes. Provider availability feeds the catalog, aliases and per-model settings refine agent behavior, and `modelPolicy.allow` can restrict which overrides proceed.

## Architecture Diagram

flowchart LR
  A[Provider catalogs and auth] --> B[Gateway model catalog]
  C[Agent model aliases and settings] --> D[Model selection]
  E[Optional override allow policy] --> D
  B --> F[Pickers and model commands]
  D --> F
  D --> G[Session or CLI model override]

## Best Possible Solution

Keep `agents.defaults.models` as metadata for aliases and per-model settings, keep dynamic provider access available through an omitted or wildcard-based `modelPolicy.allow`, and only pursue any further schema reduction with a maintainer-approved migration design.
