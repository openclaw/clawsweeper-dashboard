## Label Justifications

- `P1`: Ordinary delegated agent turns can leave real channel users without any acknowledgment for several minutes.
- `impact:message-loss`: The model-provided `sessions_yield` acknowledgment is discarded before outbound channel delivery.
- `impact:ux-friction`: Users can eventually receive the subagent result, but the unexplained silence prompts uncertainty and support-style follow-up messages.

## Summary

Keep open: current main records that `sessions_yield` occurred but does not carry its message into the outbound reply payload, so an otherwise empty spawn-and-yield turn can still end silently. The report identifies a bounded cross-harness message-delivery bug rather than the later completion-delivery races tracked by related issues.

## What This Changes

Deliver the user-facing `sessions_yield` acknowledgment when a yielded turn has produced no other visible reply.

## Best Possible Solution

Carry an optional yield message as a prepared attempt-result fact through both harnesses, then let the canonical reply pipeline emit it once only when the source turn has no other visible delivery; avoid a session-key registry, cache, environment switch, or parallel dispatcher.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: invoke `sessions_yield` with a message on a turn that produces no other visible payload, and both harness results retain only the yield boolean before the reply runner's empty-payload exit. A fresh live current-main channel transcript would strengthen validation but is not needed to establish the code path.

## Solution Assessment

The suggested delivery boundary is directionally correct, but a session-key registry and opt-out environment variable are not the best implementation. Passing the message through the existing attempt result into the canonical reply builder is narrower, lifecycle-owned, and less prone to stale or duplicate delivery.
