## Summary

Keep open: the report is fresh and plausible, but current main only shows fallback execution and progress-forwarding plumbing, not proof that cross-provider fallback attempts preserve every user-visible progress signal during long tasks.

## What This Changes

Fallback long-running turns can complete work through a secondary model while intermediate progress updates to the source channel may be missing or unreliable.

## Best Possible Solution

Define the shared fallback progress contract, then add focused fallback-run coverage and live proof for tool, item, commentary, heartbeat, and subagent progress across provider fallback attempts or document any intentional provider limitation.
