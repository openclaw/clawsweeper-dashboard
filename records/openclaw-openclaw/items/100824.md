## Summary

Keep open: current main and v2026.6.11 have model-fallback lifecycle notices and broad progress-forwarding plumbing, but there is no current-main or live proof that cross-provider fallback attempts preserve the same channel-visible intermediate progress as primary attempts during long tasks.

## What This Changes

Ensure long-running fallback model attempts report intermediate progress to the user/source channel as reliably as primary model attempts.

## Best Possible Solution

Define fallback-attempt progress parity in the shared agent/channel progress path and prove primary failure to fallback success emits execution, tool, item, commentary, heartbeat, and subagent progress.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw guarantee channel-visible intermediate progress parity across model fallback candidates, including cross-provider fallbacks with different streaming/tool behavior?

Rationale: The source has several fallback and progress surfaces, and fixing this safely requires deciding whether degraded provider progress is allowed or whether core must normalize parity before adding a repair.

Likely owner: Peter Steinberger

Owner reason: He introduced the model fallback mechanism and is the strongest history signal for setting the fallback behavior contract.

Owner confidence: medium

Options:

- **Guarantee Parity In Core (recommended):** Treat fallback attempts as the same user-visible progress contract as primary attempts and fix the shared progress plumbing plus regression proof.
- **Document Provider Gaps:** Only guarantee available diagnostic or typing progress when a fallback provider lacks streaming/tool-progress capability, and document the degraded mode.
- **Fold Into Durable Status Work:** Track this under a broader channel status/progress contract so fallback visibility is handled with the same semantics as other long-running task status work.
