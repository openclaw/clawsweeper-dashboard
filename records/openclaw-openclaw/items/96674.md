## What This Changes

The PR changes `canRunPlaywrightChromium()` to probe Chromium with `--headless=new --version`, a 5-second `spawnSync` timeout, and `ETIMEDOUT` fallback.

## Best Possible Solution

Use one bounded headless Chromium capability probe across the e2e helper, preflight script, and UI Vitest config, with adjacent tests and contributor-supplied Windows proof before merge.

## Reproduction Assessment

Source-reproducible: the current `pnpm test:ui:e2e` path runs `scripts/ensure-playwright-chromium.mjs` before Vitest, and that script still uses the unbounded `['--version']` probe. I did not live-reproduce Chrome for Testing 148 on Windows, so the platform-specific hang itself is not locally reproduced.

## Solution Assessment

No. Updating the helper is a plausible partial mitigation, but the best fix must also update the sibling preflight and UI Vitest probes plus their tests so the documented command cannot hang first or outside the helper.
