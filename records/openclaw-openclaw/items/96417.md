## Summary

Keep open for maintainer review: current main and the latest release still allow non-finite response `maxBytes` values to bypass the intended cap, and this PR's shared guard plus regression coverage is the right narrow repair. The remaining issue is compatibility acceptance because the helper is exported through plugin SDK paths and now fails closed for invalid caller input.

## What This Changes

Adds finite, non-negative `maxBytes` validation to the shared response prefix reader and regression tests for invalid response-body and snippet limits.

## Best Possible Solution

Merge the shared-prefix validation once maintainers accept the SDK-visible fail-closed invalid-limit contract; if `Infinity` must remain supported, design an explicit unbounded mode instead.

## Reproduction Assessment

Yes, by source inspection: current main only compares response byte counts with `maxBytes`, so `NaN` and `Infinity` bypass the intended cap. The PR body also includes after-fix live output for the invalid-limit cases.

## Solution Assessment

Yes, with compatibility acceptance: validating once in the shared prefix reader is the narrowest maintainable fix because it covers both response APIs and matches the sibling byte-stream helper contract.
