## Summary

Keep this PR open for maintainer review: source and tests support the fix, current main and the latest release still lack the guard, but the SDK-visible fail-closed invalid-limit behavior is compatibility-sensitive.

## What This Changes

Adds finite, non-negative `maxBytes` validation to shared HTTP response prefix reads and regression tests for response-buffer and text-snippet helpers.

## Best Possible Solution

Merge the shared-prefix validation once maintainers accept the SDK-visible fail-closed invalid-limit contract; if `Infinity` must remain supported, design an explicit unbounded mode instead.

## Reproduction Assessment

Yes by source inspection. Current main compares response byte totals to `maxBytes` without validating `maxBytes`, so `NaN` and `Infinity` bypass the intended cap; the PR body also provides after-fix live output.

## Solution Assessment

Yes, with maintainer compatibility acceptance. Validating once in `readResponsePrefix` covers both response APIs and matches the sibling byte-stream helper instead of duplicating checks at callers.
