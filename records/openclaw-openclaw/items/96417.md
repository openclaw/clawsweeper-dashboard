## Summary

Keep open for maintainer review: the patch is still necessary on current main and appears correct, but it changes SDK-visible invalid-limit behavior from unbounded/overflow-style reads to immediate fail-closed `RangeError`s.

## What This Changes

Adds finite non-negative `maxBytes` validation to the shared response prefix reader and regression coverage for response body and text-snippet reads.

## Best Possible Solution

Merge the shared-prefix guard once maintainers accept the SDK-visible fail-closed invalid-limit contract; if `Infinity` is a supported sentinel, design an explicit unbounded mode instead.

## Reproduction Assessment

Yes, by source inspection. Current main only compares response byte counts with `maxBytes`, so `NaN` and `Infinity` bypass the intended cap; the PR body also includes after-fix live output for invalid-limit cases.

## Solution Assessment

Yes, with compatibility acceptance. Validating once in the shared prefix reader is the narrowest maintainable fix because it covers both response APIs and matches the sibling byte-stream helper contract.
