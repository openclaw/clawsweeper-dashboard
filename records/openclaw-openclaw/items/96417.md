## Summary

## What This Changes

Adds finite non-negative `maxBytes` validation to the shared response prefix reader and regression tests for invalid response-body and snippet limits.

## Best Possible Solution

Merge the shared-prefix validation once maintainers accept finite non-negative response byte caps as the SDK contract; if `Infinity` must be supported, add an explicit unbounded mode instead.

## Reproduction Assessment

Yes. Current main only compares response byte counts with `maxBytes`, so `NaN` and `Infinity` bypass the cap by source inspection; the PR body includes after-fix live output for those invalid-limit cases.

## Solution Assessment

Yes, with compatibility acceptance. Validating once in the shared prefix reader is the narrowest maintainable fix because it covers both response APIs and matches the sibling byte-stream helper contract.
