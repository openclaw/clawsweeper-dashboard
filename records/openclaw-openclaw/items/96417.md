## What This Changes

Adds a finite, non-negative `maxBytes` guard in the shared HTTP response prefix reader and regression tests for invalid response buffer and text-snippet limits.

## Best Possible Solution

Merge the shared-prefix validation once maintainers accept the SDK-visible fail-closed invalid-limit contract; if `Infinity` must remain supported, define an explicit unbounded mode instead.

## Reproduction Assessment

Yes, by source inspection rather than a locally executed repro. Current main compares response byte counts directly with `maxBytes`, so `NaN` and `Infinity` bypass the intended cap; the PR body includes after-fix live output for the invalid-limit cases.

## Solution Assessment

Yes, with compatibility acceptance. Validating once in `readResponsePrefix` covers both response APIs and matches sibling byte-stream/SSE guard contracts; per-caller validation would duplicate the same policy.
