## Summary

Keep open: this focused bugfix is still useful on current main and has no blocking code findings, but the SDK-visible fail-closed invalid-limit behavior needs maintainer acceptance before merge.

## What This Changes

Adds a finite, non-negative `maxBytes` guard to the shared response prefix reader and regression tests for invalid response-body and snippet limits.

## Best Possible Solution

Merge the shared-prefix guard and regression tests once maintainers accept the SDK-visible fail-closed invalid-limit contract; if unlimited reads are supported, add an explicit unbounded API instead of treating `Infinity` as a sentinel.

## Reproduction Assessment

Yes by source inspection. Current main compares body sizes against `maxBytes` without first validating it, so `NaN` and `Infinity` bypass the intended cap; the PR body also includes after-fix live output for invalid-limit cases.

## Solution Assessment

Yes, with compatibility acceptance. Validating once in the shared prefix reader is the narrowest maintainable fix because it covers both response APIs and matches the sibling byte-stream helper contract.
