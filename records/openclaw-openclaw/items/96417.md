## Summary

Keep open for maintainer review: the patch appears correct and still necessary because current main and the latest release lack response maxBytes validation, but it intentionally changes SDK-visible invalid-limit behavior to fail closed.

## What This Changes

The PR adds finite, non-negative maxBytes validation to the shared response prefix reader and regression tests for readResponseWithLimit and readResponseTextSnippet.

## Best Possible Solution

Merge the shared-prefix validation once maintainers accept invalid response byte limits as unsupported sentinels; if Infinity must be supported, design an explicit unbounded mode instead.

## Reproduction Assessment

Yes by source inspection. Current main only compares response byte counts with maxBytes, so NaN bypasses the intended cap and Infinity allows an unbounded read; the PR body also includes after-fix live output for invalid-limit cases.

## Solution Assessment

Yes, with compatibility acceptance. Validating once in the shared prefix reader is the narrowest maintainable fix because it covers both response APIs and matches the sibling byte-stream helper contract.
