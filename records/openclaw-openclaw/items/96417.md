## Summary

Keep open. Current `main` and the latest release still lack response `maxBytes` validation, while this PR adds a focused guard with regression coverage and sufficient live text proof; the remaining blocker is maintainer acceptance of the SDK-visible fail-closed behavior.

## What This Changes

The branch adds a finite, non-negative `maxBytes` guard to the shared response prefix reader and tests invalid response-body and snippet limits.

## Best Possible Solution

Merge the shared-prefix validation once maintainers accept the SDK-visible fail-closed invalid-limit contract; if `Infinity` is a supported sentinel, design an explicit unbounded mode instead.

## Reproduction Assessment

Yes by source inspection. Current `main` compares response byte totals to `maxBytes` without validating non-finite values, so `NaN` and `Infinity` can bypass the intended cap.

## Solution Assessment

Yes, with compatibility acceptance. Validating once in `readResponsePrefix` is the narrowest maintainable fix because it covers both response APIs and matches the sibling byte-stream helper contract.
