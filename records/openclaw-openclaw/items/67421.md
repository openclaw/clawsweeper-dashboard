- **[P1] Preserve global SSRF policy when merging overrides:** `src/infra/net/ssrf.ts:80-83`
  - body: `mergeSsrFPolicies` currently returns a shallow spread, so an agent policy can replace or clear global `allowedHostnames` / `hostnameAllowlist` entries instead of preserving the documented baseline. That can silently widen or otherwise change the SSRF boundary for that agent; merge with explicit OR/union/normalization or a maintainer-approved ceiling model.
  - confidence: 0.92
- **[P1] Authorize agent-scoped SSRF widening before selecting it:** `src/agents/openclaw-tools.ts:142-143`
  - body: The new tool construction resolves agent tools from the session-derived agent id and feeds that into `web_fetch` policy selection. Since session keys are routing selectors rather than an auth boundary, a caller that can target an agent session can select that agent's private-network policy unless this path checks requester authorization or keeps agent overrides tighten-only.
  - confidence: 0.86
- **[P2] Report only actual agent SSRF widening in audit:** `src/security/audit.ts:1154-1160`
  - body: The audit warning fires whenever the merged effective policy allows private-network access, even if the global baseline already allows it and the agent only set an unrelated narrow exception. Compare agent policy against the global baseline before labeling the agent as widening access, otherwise the audit output becomes noisy and misleading.
  - confidence: 0.81
