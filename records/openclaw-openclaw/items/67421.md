## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Preserve global SSRF restrictions when merging agent policy:** `src/infra/net/ssrf.ts:80-83`
  - body: The agent policy is spread over the global policy, so an agent config with its own `hostnameAllowlist` or `allowedHostnames` replaces the global list. A per-agent exception can therefore clear a global hostname restriction or silently drop globally allowed private hosts, breaking the intended baseline/override contract; merge list fields with explicit security semantics and ignore undefined override fields.
  - confidence: 0.9
- **[P1] Authorize agent-scoped SSRF policy selection:** `src/agents/openclaw-tools.ts:142-144`
  - body: This resolves `activeAgentTools` from `sessionAgentId`, and current agent resolution can come from an `agent:<id>:` session key. Once SSRF policy widening is per-agent, callers that can choose or influence a session key can select a more permissive agent's web_fetch policy unless that agent id is authorized for the requester.
  - confidence: 0.82
- **[P3] Canonicalize SSRF policy before cache key serialization:** `src/infra/net/ssrf.ts:86-93`
  - body: `serializeSsrFPolicy` serializes hostname arrays in input order, while enforcement normalizes them as sets. Semantically identical policies such as `["a", "b"]` and `["b", "a"]` will create different cache keys and fragment web_fetch cache behavior.
  - confidence: 0.78
