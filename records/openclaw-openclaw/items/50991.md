## Summary

Keep open: current main and latest release still limit the bundled session-memory archive hook to `/new` and `/reset`; compaction has separate lifecycle hooks, but none currently write the requested session-memory archive. The KeepMyClaw discussion is complementary backup context, not an OpenClaw implementation.

## What This Changes

The issue requests firing the session-memory hook when `/compact` runs so valuable context can be archived before compaction.

## Best Possible Solution

Define the compaction-time memory archive semantics on the compaction lifecycle surface, then update the bundled hook, docs, and regression tests without duplicating memoryFlush or post-index-sync behavior.

## Reproduction Assessment

Yes, at source level: the session-memory hook is registered and gated only for new/reset command events, while compaction emits separate session compact lifecycle events. I did not run live compaction because the current-source path is explicit and this is a feature request, not a broken documented contract.

## Solution Assessment

No as proposed: the preservation gap is real, but `command:compact` is not the current lifecycle surface. The safer path is a maintainer-approved `session:compact:before` session-memory contract rather than a new command event alias.
