## Summary

Keep open: current main and the latest release still limit the bundled session-memory archive hook to `/new` and `/reset`. The preservation gap is real, but the literal `command:compact` proposal is not the current compaction lifecycle surface; maintainers should choose the compact-time archival contract before implementation.

## What This Changes

Requested behavior is to trigger bundled session-memory archival when `/compact` or compaction runs so pre-compaction context is preserved.

## Best Possible Solution

Define the compact-time archival contract, then wire session-memory through the existing `session:compact:before` lifecycle event with the workspace/session-file context it needs, plus docs and regression coverage, if maintainers approve the retention behavior.

## Reproduction Assessment

Yes, at source level: session-memory metadata and handler logic only register and accept `/new` and `/reset`, while compaction currently emits `session:compact:before/after`. I did not run a live compaction because this review is read-only and the source path is direct.

## Solution Assessment

No for the literal proposed `command:compact` shape: the preservation gap is real, but the current lifecycle surface is `session:compact:before`. The safer fix is a maintainer-approved compact lifecycle contract for session-memory rather than only adding a command event alias.
