## Summary

Keep open: current main and the latest release still limit bundled session-memory archiving to `/new` and `/reset`, while `/compact` goes through the separate compaction lifecycle and no `command:compact` event exists. The gap is real, but the permanent fix needs maintainer direction because current main already has `session:compact:before` and automatic memoryFlush behavior.

## What This Changes

Request adding a compaction-time trigger so the bundled session-memory hook archives conversation context before `/compact` or compaction compresses it.

## Best Possible Solution

Define one compaction-memory contract, preferably on `session:compact:before` if archives should cover both manual and automatic compaction, then update session-memory, docs, and focused tests without duplicating memoryFlush.

## Reproduction Assessment

Yes. Source inspection shows session-memory subscribes to and handles only command `new`/`reset`, while `/compact` calls the compaction runtime and current hook keys expose `session:compact:before/after`, not `command:compact`.

## Solution Assessment

Unclear as proposed. Adding literal `command:compact` would only cover manual compact and create a second compaction trigger surface; `session:compact:before` is the more natural existing lifecycle seam if maintainers want all compactions archived.
