## Summary

Keep open: current `main` and `v2026.6.11` still limit the bundled session-memory archive hook to `/new` and `/reset`; compaction has separate lifecycle hooks, but none currently write the requested session-memory archive. The KeepMyClaw discussion is useful backup context, but it is complementary and not an OpenClaw implementation.

## What This Changes

The issue requests triggering the bundled session-memory archive hook when `/compact` or compaction runs so pre-compaction context is preserved.

## Best Possible Solution

Define the compaction-time memory archive semantics on the compaction lifecycle surface, then update the bundled hook, public docs, and regression tests without duplicating memoryFlush or post-index-sync behavior.

## Reproduction Assessment

Yes, at source level: the session-memory hook is registered and gated only for new/reset command events, while compaction emits separate session compact lifecycle events. I did not run live compaction because the current-source path is explicit and this is a feature request, not a broken documented contract.

## Solution Assessment

No as proposed: the preservation gap is real, but `command:compact` is not the current lifecycle surface. The safer path is a maintainer-approved `session:compact:before` session-memory contract rather than a new command event alias.
