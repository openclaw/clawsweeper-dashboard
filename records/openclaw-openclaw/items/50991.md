## Summary

Keep open: current main and the latest release still limit the bundled session-memory archive hook to `/new` and `/reset`; compaction has `session:compact:before/after` lifecycle hooks and memoryFlush paths, but nothing currently writes the requested session-memory archive at compact time. The linked KeepMyClaw discussion is useful complementary backup context, and the open continuity-helper PR explicitly excludes hooks and compaction behavior.

## What This Changes

The issue requests firing the bundled session-memory archival behavior when a session is compacted so conversation context is saved before compression.

## Best Possible Solution

Define the compact-time archival contract, then wire session-memory through `session:compact:before` with the needed context, docs, regression tests, and explicit retention/dedupe behavior.

## Reproduction Assessment

Yes, at source level: current metadata and handler logic register and accept only `/new` and `/reset`, while compaction emits `session:compact:before/after`. I did not run live compaction because this review is read-only.

## Solution Assessment

Unclear as proposed: the preservation gap is real, but `command:compact` is not the current lifecycle surface. The safer path is a maintainer-approved `session:compact:before` session-memory contract rather than a new command alias.
