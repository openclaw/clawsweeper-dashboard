## Summary

Keep open. Current main and v2026.6.11 still create one QMD `xdg-cache/qmd/index.sqlite` per agent and pass that per-agent cache root to QMD; related work adds adjacent per-agent OpenClaw SQLite scaffolding or optimizes session export, but does not settle QMD cache layout, compaction, eviction, or live multi-agent disk-I/O behavior.

## What This Changes

The issue requests reducing QMD per-agent SQLite cache write amplification in multi-agent deployments, potentially through a shared cache layout, WAL/compaction tuning, reduced-write mode, or cache limits.

## Best Possible Solution

Have memory/QMD owners choose one canonical cache-layout or maintenance policy, then validate it with live multi-agent measurements of DB size, WAL sidecars, disk writes, and gateway recovery behavior.
