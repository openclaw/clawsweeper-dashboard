## Summary

Keep open. Current main and v2026.6.11 still isolate QMD under a per-agent `XDG_CACHE_HOME` and `qmd/index.sqlite`; merged related work serializes same-store writers or adds adjacent per-agent cache infrastructure, but it does not solve the reported multi-agent disk-I/O amplification.

## What This Changes

Request to reduce QMD per-agent SQLite cache write amplification in multi-agent deployments, with possible shared cache, checkpointing, reduced-write mode, or eviction policy.

## Best Possible Solution

Choose a maintainer-owned QMD storage or maintenance policy that reduces multi-agent write amplification by default, avoid new config unless measurement proves it necessary, and validate it with a live multi-agent workload.
