## Summary

Keep open. Current main still gives each agent its own QMD `xdg-cache/qmd/index.sqlite`, and the merged/open related work only covers adjacent per-agent OpenClaw SQLite infrastructure or QMD export fast paths rather than the multi-agent QMD cache layout, compaction, eviction, or write-amplification problem.

## What This Changes

Request to reduce extreme disk writes from per-agent QMD SQLite caches in high-concurrency agent deployments.

## Best Possible Solution

Have the memory/QMD owner choose one canonical cache layout or maintenance policy, then validate it with a live multi-agent workload measuring QMD DB size, WAL sidecars, disk writes, and gateway recovery.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes for the core layout claim from source: current main still gives each agent its own QMD `xdg-cache/qmd/index.sqlite`; no for the exact 19-agent macOS disk-write magnitude because this read-only review did not run that live workload.

## Solution Assessment

Is this the best way to solve the issue? Unclear: the suggested fixes are plausible, but maintainers need to choose between automatic QMD maintenance, shared/source-keyed storage, eviction, or explicit reduced-write behavior before code is queued.
