## Summary

Keep open. Current main and the latest release still give each agent its own QMD `xdg-cache/qmd/index.sqlite` and do not schedule QMD cleanup, checkpoint, compaction, or eviction; the related merged PR is only adjacent storage scaffolding, and the open export-cache PR does not settle the reported multi-agent QMD store multiplication.

## What This Changes

The issue asks OpenClaw to reduce QMD per-agent SQLite cache write amplification, unbounded cache growth, and resulting multi-agent disk-I/O pressure.

## Best Possible Solution

Have the memory/QMD owner choose a canonical storage or maintenance policy, prefer upstream QMD cleanup/vacuum hooks if they are sufficient, and validate the chosen path with a live multi-agent workload measuring DB size, WAL sidecars, bytes written, and gateway liveness.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes for the source-level layout claim: current main and the latest release still create one QMD `index.sqlite` under each agent-local `XDG_CACHE_HOME`; no for the exact 19-agent macOS disk-write magnitude because this read-only review did not run that live workload.

## Solution Assessment

Is this the best way to solve the issue? Unclear: the issue lists plausible solution families, but the best maintainable fix should be chosen by the memory/QMD owner after comparing upstream cleanup hooks, shared storage, eviction, and reduced-write behavior with live measurements.
