## Summary

Keep open. Current main and v2026.6.11 still give each QMD manager an agent-local `xdg-cache/qmd/index.sqlite`, and the related merged/storage work plus open export-cache PR do not yet solve the multi-agent QMD store multiplication, compaction, eviction, or live disk-write problem.

## What This Changes

The issue asks OpenClaw to reduce extreme disk I/O from per-agent QMD SQLite caches in multi-agent deployments, likely through shared storage, maintenance, reduced-write mode, or cache limits.

## Best Possible Solution

Have the memory/QMD owner choose a canonical cache-layout or maintenance policy, then validate it with a live multi-agent workload measuring DB size, WAL sidecars, disk writes, and gateway recovery.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes for the core layout claim from source: current main and v2026.6.11 still give each agent its own QMD `xdg-cache/qmd/index.sqlite`; no for the exact 19-agent macOS write volume and forced logout because that workload was not run.

## Solution Assessment

Is this the best way to solve the issue? Unclear: the suggested fixes are plausible, but OpenClaw needs a maintainer-owned choice between shared storage, automatic QMD maintenance, eviction, or reduced-write behavior before a narrow fix is safe.
