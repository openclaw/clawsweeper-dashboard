## Summary

Keep this PR open: the new curl bounds and `--show-error` improve diagnostics, but the nested `bash -lc` pipeline still lacks `pipefail`, so a failed curl can be treated as successful before the later `droid --version` error obscures the setup failure. The prior P2 finding remains unresolved, and the PR still needs redacted real live-harness proof.

## What This Changes

The PR adds `--show-error`, a 10-second connect timeout, and a 120-second maximum duration to the Droid CLI curl installer in the live ACP bind Docker harness, and updates its exact-string contract test.

## Best Possible Solution

Run the installer pipeline in a child shell with `pipefail` enabled, keep the 10-second/120-second bounds and `--show-error`, extend the contract assertion to lock that full failure-propagating shape, then attach redacted live ACP bind Docker evidence for either a successful Droid install or a controlled bounded failure.
