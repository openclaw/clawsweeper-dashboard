## Summary

The timeout addition is directionally sound, but the proposed pipeline still suppresses curl’s timeout diagnostic and may not propagate curl’s nonzero status, so it does not reliably deliver the stated actionable failure before merge.

## What This Changes

The PR adds 10-second connect and 120-second total curl timeouts to the Droid CLI install step in the live ACP bind Docker harness and updates its exact-string contract test.

## Best Possible Solution

Use curl’s error-visible mode and `pipefail` at the existing setup-command boundary, lock that complete failure contract in the targeted assertion, and attach redacted live ACP bind Docker output showing the Droid path succeeds or reports a bounded curl failure clearly.

## Reproduction Assessment

Yes, from source: a TCP-connected but stalled download reaches curl’s new `--max-time 120` path; the current shell pipeline lacks `pipefail` and uses silent mode, so the expected diagnostic/failure result is not reliably preserved.

## Solution Assessment

No. Native curl deadlines are the narrowest mechanism, but this implementation also needs `-S` and `pipefail` so the timeout is visible and authoritative instead of being masked by the pipeline’s final command.
