## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.87

Full review comments:

- **[P1] Preserve beta headers when adding fallbacks:** `src/llm/providers/anthropic.ts:1177-1179`
  - body: This branch sets `fallbacks` whenever the model/auth/endpoint gate passes, but the client headers are merged with `model.headers` and `options.headers` afterward, so an existing `anthropic-beta` header can replace the required `server-side-fallback-2026-06-01` value. OpenClaw already supports caller-supplied Anthropic beta headers, and Anthropic rejects `fallbacks` without the fallback beta, so a user with a custom beta header would now get a 400 instead of their existing Fable request. Please append/preserve the required beta in the final header, or only emit `fallbacks` when that final header contains it; the transport path at `src/agents/anthropic-transport-stream.ts:985` needs the same treatment.
  - confidence: 0.88
- **[P1] Replay the Anthropic fallback boundary:** `src/shared/anthropic-server-fallback.ts:81-83`
  - body: Anthropic's server-side fallback docs say the `fallback` content block must be kept exactly where it appeared on the next turn, but this helper splices the stored assistant content down to text survivors and never records a replayable fallback block. Because OpenClaw later replays assistant text/thinking/tool blocks into Anthropic requests, any fallback-served conversation can lose the required handoff boundary, especially when the fallback model returns post-boundary thinking. Please preserve/replay a provider fallback block or otherwise prove the next-turn payload remains valid for fallback-served Fable responses.
  - confidence: 0.83
