## Summary

Keep open. The report gives a specific current-stable Telegram Desktop regression path, and current Telegram documentation describes selected quote text as inbound context rather than an object string. The earlier prompt-assembly incident at https://github.com/openclaw/openclaw/issues/77582 overlaps, but it was a quote-omission bug and does not prove that the current `[object Object]` coercion is fixed.

## What This Changes

Fix Telegram selected-text Quote and Reply so the model receives the selected quote text instead of the literal string `[object Object]`.

## System Context

Telegram receives Bot API message updates, normalizes reply and selected-quote metadata, then assembles that context into the agent's current prompt. This issue affects the handoff from Telegram-native quote data to the text supplied to the model.
