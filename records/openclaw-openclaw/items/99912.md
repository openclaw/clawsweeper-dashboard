## Summary

This remains a valid open bug: current main still lets global-scope heartbeat context reach reply resolution without the configured secondary `AgentId`, and https://github.com/openclaw/openclaw/pull/102307 is the active fix candidate rather than merged implementation evidence.

## What This Changes

The issue reports secondary-agent heartbeats running in the default agent/session instead of the configured agent's own heartbeat context, especially with global session scope.

## Best Possible Solution

Review and land or revise https://github.com/openclaw/openclaw/pull/102307 so global-scope heartbeat context carries the configured agent identity while preserving literal global session-key semantics.

## Reproduction Assessment

Yes, at source level: current main constructs global-scope heartbeat context with `SessionKey: "global"` and no `AgentId`, and reply resolution falls back to the default agent when no agent id can be parsed. I did not run the reporter's full WSL2/Docker live scenario in this read-only review.

## Solution Assessment

Yes, the linked PR's direction appears to be the narrowest maintainable fix because it uses the existing `MsgContext.AgentId` fallback instead of changing global session-key semantics. The issue should stay open until that PR lands or maintainers choose another equivalent fix.
