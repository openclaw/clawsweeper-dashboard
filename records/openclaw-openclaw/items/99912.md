## Summary

Keep open: current main still constructs heartbeat reply context with `SessionKey: "global"` and no `AgentId`, so secondary-agent heartbeats under global session scope can resolve as the default agent; https://github.com/openclaw/openclaw/pull/102307 is the current narrow fix candidate.

## What This Changes

The issue reports that a configured secondary agent's heartbeat can execute in the default agent's session and read the default agent's `HEARTBEAT.md` instead of its own.

## Best Possible Solution

Review and land or revise https://github.com/openclaw/openclaw/pull/102307 with live WSL2/Docker proof and regression coverage so global-scope heartbeat context carries the configured agent identity without changing global-session semantics.
