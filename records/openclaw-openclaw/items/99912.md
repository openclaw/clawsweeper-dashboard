## Summary

Keep open: the follow-up reproduction narrows the bug to global-scoped heartbeat routing, and current main still has a source-level path where a secondary agent heartbeat enters the reply pipeline with `SessionKey: "global"` but no `AgentId`, so the reply layer falls back to the default agent.

## What This Changes

The issue reports per-agent heartbeat runs in a multi-agent setup routing into the default agent session/workspace, especially with `session.scope: "global"` and `dmScope: "per-channel-peer"`.

## Best Possible Solution

Thread the resolved heartbeat `agentId` into the reply context for heartbeat/cron-event turns whose session key does not encode an agent, then add a focused regression for secondary-agent heartbeat under `session.scope: "global"`.
