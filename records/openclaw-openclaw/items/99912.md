## Summary

Keep open: current main still contains the global-scope heartbeat identity gap, and the open fix candidate at https://github.com/openclaw/openclaw/pull/102307 is linked with closing syntax and owns the remaining work.

## What This Changes

The issue reports that a configured secondary agent heartbeat can execute in the default agent's session/workspace instead of the configured agent's own session under global session scope.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/102307 so global-scope secondary-agent heartbeats preserve selected agent identity, workspace, session store, runtime lane, and event queue ownership while keeping the persisted global key contract.

## Solution Assessment

Yes, the best fix direction is to carry the selected agent identity separately from the persisted global key and scope runtime/event ownership appropriately. The open linked PR is the right implementation candidate to review rather than queueing another fix branch.
