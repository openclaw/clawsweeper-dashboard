## What This Changes

The issue reports that a configured secondary agent's heartbeat can run in the default/global session instead of that agent's own session, workspace, and `HEARTBEAT.md`.

## Best Possible Solution

Preserve the configured heartbeat agent identity through global-scope session/store and isolated-session resolution, backed by a live WSL2 or Docker repro plus regression coverage for `session.scope: "global"` and `dmScope: "per-channel-peer"`.
