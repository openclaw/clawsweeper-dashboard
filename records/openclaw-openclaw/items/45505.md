## Summary

Keep open: current main has the narrow late-success compactionCount reconciliation, but it still lacks a single authoritative reconciliation boundary for other compaction-derived session state. This remains a maintainer-owned session-state design decision rather than cleanup that can safely close.

## What This Changes

The issue requests a generalized compaction-completion reconciliation model so post-timeout successful compactions converge session counters, token/status snapshots, and downstream recovery state.

## Best Possible Solution

Define one authoritative core compaction-completion reconciliation boundary that owns monotonic compaction-derived session fields, then land narrower status, activity, and recovery follow-ups against that contract.
