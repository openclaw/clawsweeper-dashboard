## Summary

Keep open: current main and the latest release still implement only the narrow late-success `compactionCount` repair; `/status` token snapshots, memory-flush freshness, and auth override boundaries remain separate session-state consumers, so the broader state-convergence design is still unresolved.

## What This Changes

The issue asks to promote late compaction success into a general authoritative reconciliation boundary for compaction-derived session state instead of only patching session-store counters.

## Best Possible Solution

Define one compaction-completion reconciliation boundary for monotonic compaction-derived durable state, then deliberately move only the fields that are semantically tied to compaction success into that path with late-signal and duplicate-signal tests.
