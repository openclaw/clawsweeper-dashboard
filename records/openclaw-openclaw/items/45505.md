## Summary

Keep open: current main and the latest checked release have the count-only late-success repair, but source inspection still shows no general authoritative reconciliation boundary for other compaction-derived session state. The remaining work is a maintainer-owned session-state design decision, not a safe cleanup close.

## What This Changes

Request to promote late compaction completion into a general reconciliation path for session counters, token/status snapshots, lifecycle events, and timeout-late-success repair.

## Best Possible Solution

Define one authoritative core compaction-completion reconciliation boundary that owns monotonic compaction-derived session fields, then land narrower status, activity, and recovery follow-ups against that contract.
