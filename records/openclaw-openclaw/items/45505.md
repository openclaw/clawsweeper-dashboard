## Summary

Keep open: current main and v2026.6.11 still implement a narrow compaction-count reconciler, while the requested authoritative reconciliation boundary for compaction-derived session state remains a product/design decision.

## What This Changes

Request to generalize late compaction-success reconciliation beyond `compactionCount` so session-store, token/status, and related session state converge after timeout-late success.

## Best Possible Solution

Define one authoritative compaction-completion reconciliation boundary, then deliberately enroll only compaction-derived session fields with monotonic/idempotent updates and focused regression coverage.

## Reproduction Assessment

Partly: source inspection reproduces the architectural gap because current main has a count-only late reconciler plus separate finalizer, status, memory-flush, and auth-profile paths. I did not establish a single failing live current-main runtime path in this read-only review.

## Solution Assessment

Unclear as an implementation, but the direction is plausible. Maintainers should choose the authoritative compaction-completion boundary and enrolled fields before code changes broaden the current counter helper.
