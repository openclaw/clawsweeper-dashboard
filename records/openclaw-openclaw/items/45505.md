## Summary

Keep open: current main has the narrow late-success `compactionCount` reconciliation, but it does not yet provide one authoritative compaction-completion boundary across status/token snapshots, context-engine-owned compaction, and downstream session-state consumers.

## What This Changes

The issue requests a generalized reconciliation path for compaction completion so session counters, token/status snapshots, and downstream session state converge after timeout-late success.

## Best Possible Solution

Define one owner boundary for compaction-completion state convergence, then route monotonic session-count, token/status, and plugin/context-engine notification updates through that boundary.
