## Summary

Keep open for maintainer review: the source path and live proof support the Feishu bug fix, but merging it changes credential precedence for multi-account Feishu tool calls and promotes two routing helpers through the public plugin SDK.

## What This Changes

The PR threads `ctx.sessionKey` into Feishu resource tool account resolution, checks runtime and configured Feishu bindings before `channels.feishu.defaultAccount`, exports routing helpers through the plugin SDK, and updates focused tests/baselines.

## Best Possible Solution

Merge the binding-first Feishu resource-tool fix only after maintainers explicitly accept the credential precedence and public SDK export shape, then let the linked issue close when this PR lands.

## Reproduction Assessment

Yes. Current main has a source-level reproduction path: a Feishu resource tool call with no valid `ctx.agentAccountId` can return global `channels.feishu.defaultAccount` before any runtime or configured binding lookup.

## Solution Assessment

Yes, with maintainer acceptance. Reusing existing session-binding and configured-routing helpers inside the shared Feishu resolver is the narrow maintainable fix; the open decision is whether maintainers accept the public SDK exports and precedence change.
