## Summary

Keep open: the PR is a focused fix for the Feishu non-inbound account-routing bug, but it is not merge-ready because Bitable still calls the resolver without a required tool family, so the new capability-before-default fallback does not apply to one of the named resource-tool surfaces.

## What This Changes

The branch changes Feishu resource tool account selection to pass `ctx.sessionKey`, prefer runtime/configured Feishu bindings, move tool-family fallback before `defaultAccount`, and add focused routing tests plus generated baseline/lint updates.

## Best Possible Solution

Make Bitable use the same required-tool routing as sibling resource tools, then land only after maintainer acceptance of bound-account precedence and fail-closed ambiguity behavior.

## Reproduction Assessment

Yes, at source level: current main can return `channels.feishu.defaultAccount` before any binding-aware or required-tool family selection when `ctx.agentAccountId` is absent. The PR discussion also includes redacted live Feishu before/after proof for the bound-account path.

## Solution Assessment

No, not yet: the Feishu-local resolver shape is appropriate, but Bitable still omits `requiredTool` and therefore does not participate in the new capability-before-default fallback. After that narrow fix, the remaining question is maintainer acceptance of the compatibility and credential-boundary tradeoff.
