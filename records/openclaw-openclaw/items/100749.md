## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Clear the SDK tenant-token cache before retrying:** `extensions/feishu/src/client.ts:203-205`
  - body: `refreshFeishuClient()` only deletes OpenClaw's wrapper `clientCache` entry before constructing another SDK `Client`. The SDK uses `params.cache || internalCache`, and its `TokenManager` stores `CTenantAccessToken` in that shared cache by `appId`, so the retried request can reuse the same stale tenant token and fail again. Clear or own the SDK token cache before retrying.
  - confidence: 0.92
- **[P2] Keep token refresh outside the rate-limit attempt budget:** `extensions/feishu/src/comment-shared.ts:211`
  - body: The invalid-token branch calls `continue` inside the same `attempt <= FEISHU_SEND_MAX_RETRIES` loop used for rate limits. If a request sees rate-limit responses first and then an invalid-token response on the final attempt, this refreshes the client but exits the loop without making the refreshed request, so the promised one-shot recovery is skipped.
  - confidence: 0.84
