Full review comments:

- **[P1] Refresh the SDK token cache before retrying:** `extensions/feishu/src/client.ts:203-205`
  - body: This refresh only deletes OpenClaw's `clientCache` and creates another `Lark.Client`. In `@larksuiteoapi/node-sdk@1.68.0`, the constructor defaults to the package-level `internalCache`, and `TokenManager` stores `CTenantAccessToken` there by appId, so the new client can still send the same invalid bearer token after 99991663/99991664. Own or replace the SDK cache before retrying, as the canonical PR does.
  - confidence: 0.93
- **[P2] Keep token refresh outside the rate-limit budget:** `extensions/feishu/src/comment-shared.ts:208-211`
  - body: The invalid-token branches `continue` without preserving a retry slot. If two rate-limit retries are spent before the token-invalid response, the refresh path exits the loop and falls through to the synthetic error instead of trying the fresh token once. Make the token-invalid retry independent of `FEISHU_SEND_MAX_RETRIES` or throw the original token error.
  - confidence: 0.84
