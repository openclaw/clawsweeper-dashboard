## Summary

Keep open. The self-authored Feishu receive-event loop is fixed on current main and in v2026.6.11, but the broader slow-run incident remains unresolved because Feishu still queues the full handler path and the timeout cap explicitly does not abort the original agent task.

## What This Changes

The issue requests fixes for a Feishu slow-LLM failure mode involving same-chat queue blocking, missing abort/backpressure behavior, self-authored receive echoes, and session write-lock observability loss.

## Best Possible Solution

Keep the shipped self-open-id filter, then consolidate or land a maintainer-approved Feishu/session-state repair that lets active follow-ups reach shared queue policy, fences or aborts timed-out runs, preserves control and /btw ordering, and proves the result with a live Feishu slow-run scenario.
