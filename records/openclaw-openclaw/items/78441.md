## Summary

Keep this PR open for human maintainer review. It adds a public, persisted tool-restriction contract across Gateway and subagent sessions, and the latest branch state needs a review refresh: the documentation still says CLI-backed native runs reject `toolsAllow`, while the latest commit says the PR instead forwards it to the CLI harness. The supplied Gateway-backed proof is strong for the embedded child-run path, but it does not settle the permanent API and enforcement contract.

## What This Changes

This PR adds an optional `toolsAllow` array to `sessions_spawn` and Gateway agent runs, persists it for spawned child sessions, forwards it into child execution, and documents the allowlist behavior.

## System Context

A parent agent invokes `sessions_spawn` through the Gateway to create a child session. The proposed allowlist is normalized, saved with that child session, then passed to the embedded or CLI-backed runtime so the child receives a restricted tool surface on its first and later turns.

## Best Possible Solution

Adopt one documented contract for CLI-backed child runs—either reject `toolsAllow` before dispatch or forward it only to harnesses that fail closed—then rebase, update the docs and focused tests, and obtain maintainer approval for the public Gateway/session API.
