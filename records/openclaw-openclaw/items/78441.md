## Summary

This PR remains necessary: current `main` forwards runtime tool allowlists to CLI harnesses but does not expose `toolsAllow` from `sessions_spawn`. The earlier documentation blocker remains on the latest head: it says CLI-backed native runs reject the field, while the branch now forwards it to the CLI harness for enforcement or fail-closed handling.

## What This Changes

Adds an optional `toolsAllow` array for native `sessions_spawn` child runs, carrying the allowlist through Gateway, persisted child-session state, and embedded or CLI execution paths.

## System Context

A parent agent invokes `sessions_spawn` through the Gateway to create a child session. The child session’s runtime tool policy is then carried into the selected execution harness so the child receives only the allowed tools or the harness rejects unsupported enforcement.

## Architecture Diagram

flowchart LR

  B --> C[Tool allowlist validation]
  C --> D[Gateway agent run]
  D --> E[Child session state]
  E --> F[Selected execution harness]
  F --> G[Restricted child tool set]

## Best Possible Solution

Keep one documented contract: native embedded children enforce the allowlist, while CLI-backed children receive it only where the selected harness can enforce it and otherwise fail closed; update the docs and add current-head proof for that boundary before merge.
