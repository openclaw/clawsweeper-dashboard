## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P2] Reuse profiled gateway path resolution before probing:** `scripts/postinstall-bundled-plugins.mjs:1155`
  - body: This lookup falls back to `$HOME/.openclaw` and the unprofiled service/env metadata when `OPENCLAW_STATE_DIR` is absent. Current gateway services derive their state directory and systemd service name from `OPENCLAW_PROFILE` (`.openclaw-<profile>`, `openclaw-gateway-<profile>.service`), so a profiled gateway installed on a custom port can be missed and the postinstall will probe config/defaults instead of the running service port. Please reuse/extract the existing daemon path/service-name contracts or mirror their profile semantics and cover that path with tests.
  - confidence: 0.89
- **[P2] Parse authored config with the existing JSON5 contract:** `scripts/postinstall-bundled-plugins.mjs:1113-1115`
  - body: The fallback config reader uses `JSON.parse`, but `openclaw.json` is documented and loaded by the main config path as JSON5, so comments or trailing commas make this skip a valid `gateway.port` and probe the default or wrong port. Use the existing config reader/parser or a JSON5-compatible script helper for this fallback.
  - confidence: 0.86
- **[P2] Honor the existing postinstall disable path:** `scripts/postinstall-bundled-plugins.mjs:1401`
  - body: `OPENCLAW_DISABLE_BUNDLED_PLUGIN_POSTINSTALL` still returns from the old bundled-plugin work, but this PR runs the new gateway warning afterward unless the new warning-specific env var is also set. Environments that already use the existing disable flag during install can now still get a loopback probe and warning, contrary to the PR's compatibility claim; gate the new postinstall work on the existing disable contract or document the intentional split.
  - confidence: 0.78
