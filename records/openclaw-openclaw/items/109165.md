## Label Justifications

- `P1`: The proposed behavior affects inbound LINE media handling and can change whether user attachments complete or are degraded.
- `merge-risk: 🚨 compatibility`: The new fixed transfer deadline changes established behavior for existing slow but progressing LINE media downloads.
- `merge-risk: 🚨 message-delivery`: A body timeout can feed the current LINE error path, where transient media failures may be presented as unavailable rather than retried.

## Summary

Keep this PR open for LINE-path owner review: the bounded-body approach is well-scoped and has convincing loopback proof, but intentionally failing an otherwise live inbound-media transfer at 120 seconds is a delivery-policy choice rather than a mechanical merge decision.

## What This Changes

The branch keeps LINE’s existing 15-second 202/readiness timeout and adds a separate 120-second wall-clock deadline that destroys a successful response body stream if it continues beyond that budget.

## Best Possible Solution

Have the LINE-path owner explicitly accept or adjust the 120-second fail-closed body policy, then land it with the existing separate readiness/body contracts and ensure transient timeout handling is addressed by the durable-ingress follow-up.
