## Summary

This PR remains useful, but the current head does not reliably deliver the signed-APK case it claims to support: file-path-aware MIME detection reclassifies a JAR sniff as APK, while the host-read gate still evaluates the buffer-only JAR result and rejects it. The separate decision to add installable APK files to the host-local send boundary also needs explicit owner acceptance.

Likely related people: @steipete is the strongest routing candidate for the host-read security boundary; @vincentkoc and @Unayung have relevant adjacent media-path history.

## What This Changes

The PR adds APK MIME recognition, permits host-local APK attachments, adds focused media and outbound tests, and documents the new attachment type.

## Best Possible Solution

Create one canonical buffer-verifiable APK classification using Android package evidence such as classes*.dex and AndroidManifest.xml, carry that result through MIME detection and host-read authorization, add signed-APK and renamed-JAR load/action regressions, and land only after the media/security owner accepts verified APKs in the host-read boundary.
