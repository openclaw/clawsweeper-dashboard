## Summary

Keep open. Current main still sends the private `qa` command through the global pre-action bootstrap: `qa` has no command-catalog exception, so the default policy does not bypass the config guard before QA creates its temporary gateway state. The issue is newly filed and carries the protected `maintainer` label, so it needs explicit maintainer handling rather than automatic cleanup.

## What This Changes

The issue requests that private `openclaw qa` commands avoid operator config, migration, and plugin preflight until their isolated QA runtime owns setup.

## Best Possible Solution

Add an explicit `qa` startup policy that bypasses global operator config readiness and plugin preloading, then cover the launcher path with a regression test proving no operator-state bootstrap occurs before the disposable QA gateway starts.
