## Summary

This PR addresses a reproduced P1 message-delivery regression with strong Telegram evidence, but the new Codex-specific finalizer does not yet demonstrate an enforced absence of Codex native tools. That leaves the central safety claim—never repeat or extend completed work—unproven on a path that starts a fresh Codex turn from settled tool output.

## What This Changes

The branch adds one bounded settled-tool finalization path in the shared embedded runner, plus a Codex app-server implementation that projects the completed transcript into a fresh private turn and QA coverage for a Telegram recovery scenario.

## Best Possible Solution

Keep one shared, bounded recovery path, but make Codex finalization use a supported app-server mechanism that denies every native, managed, and external tool capability, prove an attempted tool call is unavailable, and decide whether scheduled runs with delivery targets should receive the same recovery.
