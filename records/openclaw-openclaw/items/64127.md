Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P2] Persist quota_exhausted in auth-profile state normalization:** `src/agents/auth-profiles/types.ts:81`
  - body: The PR writes quota_exhausted as an AuthProfileFailureReason, but the persisted-state normalizer only accepts the old AUTH_FAILURE_REASONS set. After reload, disabledReason and failureCounts for quota exhaustion are dropped while disabledUntil remains, so the circuit-breaker state loses its reason and follow-on fallback/status decisions cannot see the new class.
  - confidence: 0.9
- **[P2] Map quota_exhausted in OpenAI-compatible errors:** `src/agents/embedded-agent-helpers/types.ts:8`
  - body: Adding this FailoverReason lets FailoverError carry quota_exhausted, but resolveOpenAiCompatError only maps known reasons. Without a matching ERROR_TYPE_BY_REASON entry, OpenAI-compatible chat/responses handlers fall back to generic 500/internal errors instead of a 429 quota/rate-limit style envelope.
  - confidence: 0.88
- **[P2] Allow quota_exhausted in embedded result classification:** `src/agents/embedded-agent-helpers/types.ts:8`
  - body: Embedded terminal error payloads go through an explicit allowlist in classifyProviderErrorPayloadReason. Once the shared classifier can return quota_exhausted, those error-only payloads are dropped as null, so the circuit breaker can be bypassed for embedded-run terminal provider errors.
  - confidence: 0.84
- **[P2] Add quota_exhausted to cron reason schemas:** `src/agents/embedded-agent-helpers/types.ts:8`
  - body: Cron state and run logs carry FailoverReason values as lastErrorReason/errorReason, but the public CronFailoverReasonSchema and run-log reason set do not include quota_exhausted. A quota-exhausted cron failure can therefore be written by TypeScript state but rejected or normalized away by the protocol/run-log path.
  - confidence: 0.82
