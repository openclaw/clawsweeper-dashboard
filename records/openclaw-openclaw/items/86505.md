## Summary

Close as implemented: current main and the latest shipped release use a read-only `/tools/invoke` to `sessions_list` to `sessions.list` path, so missing transcript files are not used to spawn or persist replacement transient sessions during polling.

## What This Changes

The issue reports repeated transient session-store entries when an integration polls `sessions_list` through `/tools/invoke` after the target transcript JSONL file is deleted.

## Best Possible Solution

Keep the shipped read-only `/tools/invoke` to `sessions_list` to `sessions.list` behavior, and leave missing transcript cleanup to doctor/session cleanup instead of creating sessions during polling.
