## Summary

Close: current main and the v2026.6.11 release already route the reported `/tools/invoke` `sessions_list` polling path through lightweight read-only session listing, so missing transcript files no longer force the transcript-usage fallback that could persist new session metadata.

## What This Changes

The issue reports that Gateway polling of `/tools/invoke` for `sessions_list` can create persistent transient sessions when the target session transcript file is missing.

## Best Possible Solution

Keep the shipped lightweight/read-only session-list implementation; any remaining non-default transcript-hydration leak should be reported as a narrower new issue with fresh current-version proof.
