## Summary

Keep open: current main has strong source evidence that the normal `/tools/invoke` `sessions_list` path is lightweight and should not hydrate deleted transcript files, but there is still no direct current-main regression proof for the reported repeated-polling leak after a transcript is manually removed.

## What This Changes

The issue reports that polling `/tools/invoke` for `sessions_list` against a session whose transcript file was deleted can create and persist a new transient session on every poll.

## Best Possible Solution

Add focused regression coverage for repeated `/tools/invoke` `sessions_list` polling after a transcript file is removed, then either keep the existing read-only path if it passes or repair the canonical listing path without adding runtime fallback session creation.
