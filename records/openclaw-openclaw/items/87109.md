## What This Changes

Investigate macOS Gateway memory growth that degrades the event loop and leaves cron work without a visible failure outcome.

## System Context

The Gateway hosts agent turns, scheduled cron sessions, provider calls, and memory indexing in one long-lived Node process. Memory pressure or event-loop stalls can prevent cron work and its in-process alert path from completing, affecting scheduled outputs and session recovery.

## Best Possible Solution

Run an instrumented long-duration macOS Gateway scenario on current main, attribute retained heap/RSS and event-loop delay to concrete owners, then make interrupted cron runs persist an explicit terminal failure or recovery-visible state rather than disappearing silently.
