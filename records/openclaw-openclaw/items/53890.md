## Summary

Keep open: current main supports explicit Telegram topic targets and same-source auto-threading, but it still lacks the requested config-level per-agent outbound topic default; this remains a Telegram delivery precedence and config-contract product decision.

## What This Changes

Requests a Telegram config option that lets an agent default proactive outbound sends to a configured topic/thread without passing `threadId` on every call.

## Best Possible Solution

Define a Telegram-owned precedence contract, likely explicit `threadId` first, active source topic when available, then an opt-in per-agent topic default, and ship it with schema/docs/tests plus live Telegram proof.
