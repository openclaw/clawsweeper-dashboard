## Summary

Keep open: current main and the latest release still lack the requested Telegram per-agent outbound topic default, and the issue has credible live evidence that threadless proactive sends can become hard to find in forum topics. The remaining work is a product/config precedence decision, not conservative cleanup closure.

## What This Changes

Request a Telegram config-level default outbound topic/thread binding per agent so proactive sends can target forum topics without each call passing `threadId`.

## Best Possible Solution

Define a Telegram-owned outbound topic-default contract only after maintainers choose precedence, then land schema, docs, and regression coverage for proactive `message.send` from forum-topic sessions.

## Reproduction Assessment

Yes for source-level reproduction: current main's strict Telegram topic config schema and types have no outbound/default thread field, and the outbound message-action path only uses explicit `threadId` or active-context auto-threading. I did not run a live current-main Telegram repro of the nested proactive send.

## Solution Assessment

Unclear as the final product shape. The requested `outbound: true` flag is plausible, but maintainers need to choose whether config defaulting, stronger active-context inheritance, or fail/warn behavior is the durable solution.
