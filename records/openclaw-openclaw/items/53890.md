## What This Changes

The issue requests a Telegram config-level default outbound topic/thread binding per agent so proactive sends do not need per-call threadId values.

## Best Possible Solution

Define a Telegram-owned outbound topic-default contract only after maintainers choose the precedence model, then cover proactive message.send with docs, focused tests, and live Telegram proof.

## Reproduction Assessment

Yes for the missing config surface: current main's strict Telegram topic schema and type have no outbound/default field. The user-visible no-thread-send symptom has credible prior live evidence, but I did not live-reproduce it on current main.

## Solution Assessment

Unclear as the final product shape. The requested outbound flag is plausible, but maintainers should decide whether config defaulting, stronger active-context inheritance, or fail/warn behavior is the durable solution.
