## Summary

Keep open: current main still has explicit Telegram topic targets and active-context auto-threading, but it does not implement the requested config-level per-agent default outbound topic binding.

## What This Changes

The issue requests a Telegram per-agent default outbound topic/thread binding so proactive sends can target a forum topic without each call passing a threadId.

## Best Possible Solution

Define a Telegram-owned outbound topic-default contract after maintainers choose precedence, then land schema/types/docs and regression coverage for proactive `message.send` from forum-topic sessions.

## Reproduction Assessment

Yes for source-level reproduction of the missing config surface: current main has no topic-level outbound/default binding in the strict Telegram schema or topic config type. The live no-thread-send symptom has credible v2026.5.18 evidence, but it was not rerun against current main in this read-only review.

## Solution Assessment

Unclear as a final product shape: the requested `outbound: true` flag is plausible, but maintainers should choose between config defaulting, stronger active-context inheritance, or fail/warn behavior before implementation.
