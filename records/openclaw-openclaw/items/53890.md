## Summary

Keep open: current main and the latest release still lack the requested Telegram per-agent outbound topic default, while existing explicit topic targets and same-context auto-threading only cover adjacent paths. The issue should stay with maintainer review because the fix adds a new Telegram config/default precedence contract.

## What This Changes

Request a Telegram config-level default outbound topic/thread binding per agent so proactive sends target the agent's forum topic without passing `threadId` on each call.

## Best Possible Solution

Choose a Telegram-owned precedence contract for outbound topic defaults, then add schema, types, docs, and tests so explicit `threadId` or topic targets and current-context inheritance outrank any new per-agent default.

## Reproduction Assessment

Yes for source-level reproduction of the missing config surface: the strict Telegram topic schema/types contain no outbound/default binding and outbound resolution only uses explicit `threadId` plus current-context auto-threading. The live no-thread message-loss path is credible on v2026.5.18, but I did not live-reproduce it on current main.

## Solution Assessment

Unclear until maintainers pick the product shape. A topic `outbound` flag is plausible, but current-context inheritance or a fail/warn path may be safer; the durable fix needs one Telegram-owned precedence contract.
