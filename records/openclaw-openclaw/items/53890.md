## Summary

Keep open: current main and v2026.6.11 still lack the requested Telegram config-level per-agent outbound topic default. Existing explicit `:topic:` targets, per-call `threadId`, active-context auto-threading, and adjacent thread-binding PRs cover useful pieces, but they do not settle the new config/default and delivery-precedence contract.

## What This Changes

Request a Telegram config-level per-agent outbound topic/thread default so proactive agent sends can land in a configured forum topic without passing `threadId` per call.

## Best Possible Solution

Define a Telegram-owned outbound-topic default contract with explicit precedence and opt-outs, then document and test proactive `message.send` behavior from forum-topic sessions with live Telegram proof.

## Solution Assessment

Unclear until maintainers choose the product shape. The requested `outbound` flag is plausible, but stronger active-context inheritance or fail/warn behavior would create different precedence and upgrade contracts.
