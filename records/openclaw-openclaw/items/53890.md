## Summary

Keep open: current main still lacks a Telegram config-level outbound topic/thread binding, and the remaining work is a product/config precedence decision rather than conservative cleanup.

## What This Changes

Request adds a Telegram per-topic/per-agent default so proactive outbound sends can target a configured forum topic without passing `threadId` on every call.

## Best Possible Solution

Maintainers should choose a Telegram-owned outbound topic precedence contract, then implement it in the Telegram plugin schema, routing code, docs, and regression coverage so proactive sends either use the intended topic or warn/fail instead of succeeding on the wrong surface.

## Reproduction Assessment

Yes for source-level reproduction of the missing config surface: current main’s strict Telegram topic schema and type lack any outbound/default binding. The live no-thread delivery symptom is supported by v2026.5.18 issue evidence, but it was not rerun live on current main.

## Solution Assessment

Unclear as the final product shape: the requested `outbound: true` flag is plausible, but maintainers need to decide whether config defaulting, stronger active-context inheritance, warning/fail behavior, or a combination is the durable fix.
