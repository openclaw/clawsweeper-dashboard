## Label Justifications

- `P2`: The issue affects a real Telegram multi-topic workflow with an available per-call `threadId` workaround, so it is normal-priority product work rather than an urgent core outage.
- `impact:message-loss`: A successful no-thread proactive Telegram send can be effectively lost from the user's active forum topic even though Telegram accepts the message.

## Summary

Keep open: current main still lacks a Telegram config-level outbound topic binding, and the source-backed gap matches the live report that proactive forum-topic sends can succeed without being topic-bound.

## What This Changes

The issue asks for a per-agent/per-topic Telegram outbound default so proactive sends can target configured forum topics without passing `threadId` on every call.

## Best Possible Solution

Define a Telegram-owned outbound topic default contract with explicit `threadId` and explicit topic targets taking precedence, then update schema, docs, topic tests, and live Telegram proof around proactive `message.send`.

## Reproduction Assessment

Yes for the missing config surface from source inspection: the strict topic schema, Telegram topic type, docs, and outbound threading path have no per-agent outbound default. A fresh live current-main Telegram reproduction was not run in this read-only review.

## Solution Assessment

Unclear: the requested `outbound: true` flag is plausible, but maintainers should choose the product contract versus active-topic inheritance or warning/failing no-thread sends for Telegram forum groups.
