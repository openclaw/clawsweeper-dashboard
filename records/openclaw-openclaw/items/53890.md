## Summary

Keep open: current main still lacks the requested Telegram config-level per-agent outbound topic binding. Existing explicit topic targets and current-context auto-threading cover adjacent delivery paths, but the requested config/default and precedence contract remains unimplemented and needs maintainer product review.

## What This Changes

Request a Telegram per-topic/per-agent outbound default so proactive sends can target a configured forum topic without passing threadId on each call.

## Best Possible Solution

Define a Telegram-owned outbound topic-default contract after maintainers choose the precedence model, then add schema/types/docs and regression coverage for proactive message.send from forum-topic sessions.

## Reproduction Assessment

Yes for source-level reproduction of the missing config surface: current main has no topic-level outbound/default binding in the Telegram types or strict schema. The live no-thread-send symptom has credible v2026.5.18 evidence, but I did not run a current-main Telegram live repro.

## Solution Assessment

Unclear as a final product shape. The requested outbound flag is plausible, but maintainers should choose whether config defaulting, stronger active-context inheritance, or fail/warn behavior is the durable solution.
