## Summary

Keep open: current main still lacks the requested Telegram config-level per-agent outbound topic binding, while existing explicit topic targets and active-context auto-threading only cover adjacent paths.

## What This Changes

Request to add a Telegram per-topic/per-agent outbound default so proactive sends can target the configured forum topic without each call passing threadId.

## Best Possible Solution

Define a Telegram-owned outbound topic-default contract after maintainer precedence review, then implement it in the plugin config/schema, message-tool outbound resolution, docs, and focused regression coverage for proactive forum-topic sends.

## Reproduction Assessment

Yes for source-level reproduction of the missing config surface: current main has no Telegram topic-level outbound/default binding in the strict schema, types, adapter, or message-tool threading resolver. The live message-loss symptom has credible v2026.5.18 evidence in the discussion, but this review did not run a fresh Telegram live repro.

## Solution Assessment

Unclear as the final product shape. The requested outbound flag is plausible, but maintainers should first choose whether the durable fix is config defaulting, stronger active-context inheritance, or fail/warn behavior for forum-group sends with no resolved thread.
