## Summary

Keep open: current main and the latest release still lack a Telegram config-level per-agent outbound topic default, even though explicit `:topic:` targets and active-context auto-threading cover adjacent send paths.

## What This Changes

Request adds a Telegram config-level per-topic outbound default so proactive agent sends can target each agent's forum topic without per-call `threadId`.

## Best Possible Solution

Have maintainers choose the Telegram-owned precedence contract, likely explicit `threadId` or explicit topic target first, active source context next, then any optional per-agent topic default, with schema/docs/tests and live Telegram proof.

## Reproduction Assessment

Yes, at source level: the strict Telegram topic schema has no `outbound` field, and message-action threading only uses explicit params or active same-chat context. I did not run a live Telegram reproduction in this read-only review.

## Solution Assessment

Unclear: the requested `outbound: true` flag is plausible, but maintainers should first decide whether config defaults, stronger current-context inheritance, or a warning/fail path is the best long-term contract.
