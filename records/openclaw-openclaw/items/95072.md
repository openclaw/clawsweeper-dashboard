## Summary

Keep open: current main and the latest release still have the env-marker-only Windows Scheduled Task detection path, and the linked open pull request is the active candidate fix for this exact issue.

## What This Changes

The issue asks for Windows `/restart` to perform a real gateway process restart when a Scheduled Task exists but service-marker environment variables are missing.

## Best Possible Solution

Resolve the linked PR or a narrow replacement so Windows restart detection can hand off to the correct Scheduled Task without reviving unsafe unmanaged detached respawn.

- **Keep Env-Marker-Only Detection:** Reject the requested behavior and document that manually-started Windows gateways without service markers intentionally stay in-process unless relaunched via the Scheduled Task.
- **Split Broader Windows Restart Recovery:** Keep this issue scoped to env-missing Scheduled Task detection and track schtasks failure diagnostics or half-state recovery in the broader Windows restart issues.

## Reproduction Assessment

Yes from source: on win32 with no Scheduled Task env markers, current main returns no supervisor and disables fresh-PID restart, which drives the run loop into the in-process fallback. I did not run a live Windows Scheduled Task scenario in this read-only review.

## Solution Assessment

Unclear until the linked PR is reviewed: direct `schtasks` probing is a safer direction than detached respawn, but it must align with the actual task-name contract and include Windows behavior proof.
