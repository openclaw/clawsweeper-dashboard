## What This Changes

The issue requests that Windows `/restart` perform a real gateway process restart when Scheduled Task supervision exists but the running gateway lacks supervisor environment markers.

## Best Possible Solution

Review and land or close https://github.com/openclaw/openclaw/pull/95095 after it probes the exact Windows task-name contract, keeps unsafe detached respawn out of ordinary restart, and includes redacted Windows `/restart` then `/status` proof.

Yes, source-reproducible: on win32 with no supervisor markers, current main returns no supervisor, disables fresh-PID respawn, and the run loop resumes via in-process restart. I did not run a live Windows Scheduled Task scenario in this read-only review.

## Solution Assessment

Unclear until the linked PR is resolved: direct `schtasks` probing is safer than detached respawn, but it must match the actual default/profile/custom task-name handoff contract and include real Windows proof.
