## Label Justifications

- `P1`: The PR addresses a regression that can terminate active Docker sandbox commands and browser operations during upgrade rollout.
- `merge-risk: 🚨 availability`: Queued Docker exec acquisition is not abortable, so merging can leave cancelled tool calls blocked behind unrelated sandbox activity.

## Summary

This PR remains necessary because current main still uses timestamp-based rollout eviction, and the branch provides strong real Docker proof for the lifecycle-coordinator approach. It is not merge-ready because cancelled sandbox exec calls can remain queued during rollout; the protected maintainer label and sandbox CODEOWNERS routing also require explicit owner handling.

## What This Changes

Adds per-container lifecycle coordination so automatic Docker sandbox and browser rollouts drain active work, retries authenticated browser requests across refresh, and hardens process finalization failures.

## Best Possible Solution

Preserve the lifecycle coordinator and marked browser retry, but pass the exec tool AbortSignal through backend spec construction into activity acquisition and add deterministic queued-cancellation coverage before landing.
