## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Enforce byte or token-shape auth bounds:** `packages/gateway-protocol/src/schema/frames.ts:75-76`
  - body: `Type.String({ maxLength })` is not a byte cap here: TypeBox 1.3.3 counts grapheme clusters, while `safeEqualSecret` pads and compares UTF-8 buffers by byte length. A payload made from one base character plus many combining marks can stay under the 256/4096 grapheme limit while still consuming most of the pre-auth frame budget and reaching the byte-scaling comparison path, so the stated DoS bound is not enforced. Please cap UTF-8 bytes before secret comparison or restrict these fields to ASCII/token shapes where the schema length matches the work being bounded.
  - confidence: 0.91
- **[P2] Cover the newly capped runtime-token fields:** `packages/gateway-protocol/src/connect-auth-bounds.test.ts:29-34`
  - body: The schema now caps `approvalRuntimeToken` and `agentRuntimeIdentityToken`, but the new test only exercises `token`, `bootstrapToken`, `deviceToken`, and `password`. Those runtime-token fields feed separate local approval and agent-identity paths with different token formats and compatibility behavior, so this patch needs at-cap and over-cap coverage for them, or the schema change should be narrowed to the fields actually covered.
  - confidence: 0.86
