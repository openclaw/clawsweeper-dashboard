Full review comments:

- **[P1] Enforce auth caps in bytes or token shape:** `packages/gateway-protocol/src/schema/primitives.ts:32-43`
  - body: The new primitives rely on TypeBox `maxLength`, but typebox@1.3.3 checks grapheme clusters while `safeEqualSecret` allocates and scans UTF-8 bytes. A long combining/ZWJ sequence can stay under the schema cap while still approaching the 64KB pre-auth frame budget, so the claimed byte/work bound is not enforced; validate `Buffer.byteLength` or restrict these auth values to an ASCII token shape before the comparison path.
  - confidence: 0.91
- **[P2] Cover runtime-token fields before capping them:** `packages/gateway-protocol/src/schema/frames.ts:78-79`
  - body: The schema now caps `approvalRuntimeToken` and `agentRuntimeIdentityToken`, but the new tests and live proof only exercise token/password/bootstrap/device fields, and the primitive comment describes only token/password shared secrets. Because invalid agent-runtime identity connect params fail closed and approval-runtime params trigger compatibility retry behavior, either remove these two fields from the PR or add explicit rationale and at/over-cap coverage for them.
  - confidence: 0.86
