## Summary

Keep open: the security-hardening direction is valid, but this PR can fail closed for valid agent runtime identity connects because the new 2048-character runtime-token cap is not tied to the sessionKey embedded in the minted token.

## What This Changes

Adds bounded connect-frame auth schema primitives for shared secrets, bootstrap/device tokens, and runtime tokens, plus validator tests for cap and Unicode edge cases.

## Best Possible Solution

Keep schema-boundary auth bounds, but size every cap from the actual producing contract, add a regression for minted agent runtime tokens with long valid session keys, and land only after gateway/security owners accept the shared-secret compatibility boundary.
