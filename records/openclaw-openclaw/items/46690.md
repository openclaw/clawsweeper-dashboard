## Summary

Keep this open: current main and the latest release still inventory only configured skill roots, so standalone off-root `SKILL.md` directories remain invisible unless the user installs or configures that root.

## What This Changes

The issue requests guardrails or diagnostics for skill directories with `SKILL.md` files created outside OpenClaw's canonical workspace skill roots.

## Best Possible Solution

Add a bounded explicit orphan-skill diagnostic to `openclaw skills check` or Doctor that honors configured roots and trusted symlink targets; avoid startup or broad home-directory scans unless maintainers explicitly approve that UX.
