## Summary

Keep open: current main mitigates the Skill Workshop creation path, but loader, status, Doctor, and workspace-audit code still inspect configured skill roots only, so arbitrary off-root SKILL.md orphan detection remains missing and needs a product decision on scan scope and warning surface.

## What This Changes

The issue requests a guard or diagnostic for SKILL.md directories created outside configured OpenClaw skill roots so users can find orphaned skills.

## Best Possible Solution

Add a bounded explicit `openclaw skills check` or Doctor orphan diagnostic that excludes configured and trusted roots and gives move, install, or configure remediation; avoid startup-wide filesystem scans unless maintainers intentionally accept that tradeoff.
