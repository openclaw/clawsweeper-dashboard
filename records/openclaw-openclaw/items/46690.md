## Summary

Keep open: current main still routes skill discovery, `openclaw skills check`, Doctor readiness, and workspace audit through configured/workspace roots, so arbitrary off-root `SKILL.md` orphan detection remains missing. Safe creation/install paths now reduce the risk, but the remaining diagnostic needs maintainer product direction on scan scope and warning surface.

## What This Changes

The issue requests guardrails or diagnostics for skill directories created outside OpenClaw's canonical workspace skills path.

## Best Possible Solution

Add a bounded explicit `openclaw skills check` or Doctor orphan diagnostic that excludes all configured/trusted roots and gives clear move, install, or configure remediation; avoid startup or home-wide scans unless maintainers intentionally accept that tradeoff.
