Keep open: current main and the latest release still inspect only configured skill roots, so off-root `SKILL.md` directories remain invisible. Related PRs cover adjacent skill defaults, symlinks, or nesting, but none implements orphan-skill diagnostics.

## What This Changes

Requests a guard or diagnostic for skill directories with `SKILL.md` outside canonical/configured skill roots so users are warned about orphaned, unloaded skills.

## Best Possible Solution

Add a bounded explicit orphan-skill diagnostic to `openclaw skills check` or Doctor that excludes configured roots and trusted targets; avoid startup or broad home scans unless maintainers approve that UX.
