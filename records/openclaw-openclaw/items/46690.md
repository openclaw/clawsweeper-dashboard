## Summary

Keep open: current main and v2026.6.11 still only discover and report configured skill roots, so arbitrary off-root `SKILL.md` directories remain invisible. Core skill creation paths are now safer, but the remaining orphan-diagnostic behavior still needs maintainer direction because broad filesystem scanning has privacy, performance, false-positive, and startup-noise tradeoffs.

## What This Changes

The issue requests guards or diagnostics for skill-like directories created outside OpenClaw's canonical workspace skill roots so users do not end up with orphaned, undiscovered skills.

## Best Possible Solution

Add a bounded explicit orphan-skill diagnostic to `openclaw skills check` or Doctor with clear remediation, and avoid startup scanning unless maintainers intentionally accept that UX tradeoff.
