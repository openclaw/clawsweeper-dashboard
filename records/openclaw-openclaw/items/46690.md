## Summary

Keep open: current main still limits skill loading, skills status, Doctor readiness, and workspace audit checks to configured skill roots. Skill Workshop now prevents generated skills from being written directly off-root, but arbitrary orphan `SKILL.md` directories outside configured roots are still not detected, so this needs a maintainer product decision before implementation.

## What This Changes

The issue requests guardrails that detect or prevent skill directories created outside canonical workspace skill paths.

## Best Possible Solution

Add a bounded explicit orphan diagnostic to `openclaw skills check` or Doctor that excludes configured/trusted roots and gives move, install, or configure remediation; avoid startup or home-wide scans unless maintainers intentionally accept that tradeoff.
