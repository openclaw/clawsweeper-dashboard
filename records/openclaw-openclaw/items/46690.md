## Summary

Keep this open: current main and the latest release still only load and diagnose skills through configured skill roots, so off-root skill-like directories remain invisible unless the user explicitly installs or configures that root. The source gap is real, but the permanent fix needs maintainer direction because broad filesystem scanning affects privacy, performance, false positives, and startup noise.

## What This Changes

The issue asks OpenClaw to warn or diagnose when `SKILL.md` directories are created outside canonical skill roots.

## Best Possible Solution

Add a bounded explicit orphan-skill diagnostic to skills check or Doctor that reports likely skill directories outside configured roots with clear remediation; avoid startup or broad scans unless maintainers explicitly approve that UX.
