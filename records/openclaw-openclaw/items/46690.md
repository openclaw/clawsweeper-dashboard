## Summary

Keep this open: current main and the latest release still only discover and diagnose skills through configured skill roots, so an arbitrary off-root `SKILL.md` directory remains invisible unless the user installs it, configures it as an extra root, or moves it under a supported path.

## What This Changes

The issue requests guardrails or diagnostics that warn when valid `SKILL.md` directories exist outside OpenClaw's configured skill roots.

## Best Possible Solution

Add a bounded explicit orphan-skill diagnostic to `openclaw skills check` or Doctor that honors configured and trusted roots; avoid startup or broad home-directory scanning unless maintainers explicitly choose that UX.
