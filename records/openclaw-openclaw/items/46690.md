## Summary

Keep this open: current main and the latest release still load and diagnose skills only through configured skill roots, so standalone off-root `SKILL.md` directories remain invisible unless the user installs or configures that root.

## What This Changes

Request an OpenClaw guard or diagnostic that warns about skill-like directories created outside canonical skill roots.

## Best Possible Solution

Add a bounded explicit orphan-skill diagnostic to `openclaw skills check` or Doctor that honors configured roots and trusted symlink targets; avoid startup or broad home-directory scans unless maintainers explicitly approve that UX.
