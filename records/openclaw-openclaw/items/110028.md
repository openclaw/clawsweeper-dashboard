## Summary

The prior P1 blocker remains: the production checkout configuration selects the explicit-auth fetch path, which is still unbounded, so this PR does not yet prevent the reported release-check hang.

## What This Changes

This PR adds 120-second GNU `timeout` wrappers with a 10-second termination grace to the direct `git fetch` branches in two release-check workflow helpers.

## Best Possible Solution

Apply the deadline to both authentication branches in both helpers, add regression coverage that forces the `persist-credentials: false` explicit-auth path, and provide redacted terminal proof showing TERM and exit 124 for that production configuration.

## Reproduction Assessment

Yes, from source with high confidence: run either helper after a checkout configured with `persist-credentials: false` and stall the explicit-auth `git fetch`; that command has no process deadline. A live reproduction was not independently executed during this read-only review.

## Solution Assessment

No. The narrow maintainable fix is to enforce one timeout invariant across both authentication branches, rather than wrapping only the branch that the production checkout normally bypasses.
