## Summary

This PR addresses a real Slack message-loss bug, but the shared Bolt App still authenticates event-scoped clients with the group creator’s token, so sibling-account replies and reads can use the wrong workspace credential. Likely related people: steipete (high confidence) and pgondhi987 (medium confidence).

## What This Changes

The PR shares one Slack Socket Mode connection across accounts using the same app token, demultiplexes inbound events by workspace, and introduces per-account Web API clients.

## Best Possible Solution

Use one Socket Mode receiver per app token with a Bolt authorize callback that selects botToken, botId, and botUserId by teamId or enterpriseId, then prove sibling replies, creator-token failure isolation, Enterprise Grid handling, and independent account shutdown in a real two-workspace setup.

## Reproduction Assessment

Yes from source and Slack's Socket Mode contract: two account-specific connections using one app token can receive each other's workspace events, which the existing team mismatch filter then drops. I did not independently execute the live two-workspace setup.

## Solution Assessment

No. Sharing one connection is the right topology, but Bolt's supported team-aware authorize contract is safer and more complete than retaining a creator-token App and manually replacing clients across scattered call sites.
