## Summary

Keep open: the raw response-size cap is useful, but the patch is not merge-ready because gzip token responses are still decoded with unbounded `gunzipSync`, so a small compressed body can inflate past the intended cap. The contributor proof is also test/mock-only, and the PR body cites a test file that is not part of the branch.

## What This Changes

The PR replaces the Google Vertex ADC OAuth token response `arrayBuffer()` read with `readResponseWithLimit` capped at 16 MiB.

## Best Possible Solution

Cap the decoded gzip output as well as the raw response bytes, then add committed ADC regression coverage for both normal token responses and raw/compressed overflow paths before merge.

## Reproduction Assessment

Yes for the source-level issue: current main uses an unbounded ADC token `arrayBuffer()` read, and the PR still leaves unbounded gzip decompression. I did not run repo tests because this review was required to keep the checkout read-only.

## Solution Assessment

No. The shared raw-body limit is the right helper for uncompressed token responses, but the best fix must also bound gzip-decoded output and commit focused regression coverage.
