## What This Changes

This PR changes Google Vertex ADC OAuth token response parsing to use the shared byte-limited response reader, exports the parser for direct tests, and adds boundary tests for raw and gzip token bodies.

## Best Possible Solution

Merge only after the ADC decoder bounds zlib output during decompression and the PR body includes redacted terminal or live proof of the token-refresh path.

## Reproduction Assessment

Yes for the source-level safety gap: current main uses an unbounded raw token response read, and the PR head still calls gunzipSync without maxOutputLength before checking decoded length. I did not run repo tests because this review was required to keep the checkout read-only.

## Solution Assessment

No. The raw read cap is the right helper, but the best fix must also bound gzip output during decompression with zlib maxOutputLength and keep the regression coverage tied to that pre-allocation guard.
