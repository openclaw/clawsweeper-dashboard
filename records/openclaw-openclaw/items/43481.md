## Summary

Keep open: current main still has no provider media trust policy, and the central security/product choice is still unresolved while the linked implementation candidate remains open and unmerged.

## What This Changes

Request provider-level trust configuration so cross-provider model fallback can withhold user images and attachments unless the fallback provider is trusted for media.

## Best Possible Solution

Land a maintainer-approved media trust policy for fallback retries, with explicit docs, compatibility-safe defaults or migration behavior, and coverage for explicit images plus prompt/attachment-derived images.

Options:

- **Add explicit media trust policy (recommended):** Preserve existing behavior by default if desired, but add config/docs/runtime checks so users can restrict images and attachments on cross-provider fallback.

- **Fail closed for cross-provider media:** Strip media on cross-provider fallback by default and require an explicit opt-in for users who want fallback vision behavior.
