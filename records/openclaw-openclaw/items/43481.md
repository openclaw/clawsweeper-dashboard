## Summary

Keep open: current main still lacks a provider media trust policy for fallback retries, and the linked implementation candidate is open rather than merged, so the security/product decision remains unresolved.

## What This Changes

Request a provider media trust policy so cross-provider fallback retries can distinguish text fallback consent from image or attachment media transfer consent.

## Best Possible Solution

Land a maintainer-approved provider media trust policy covering explicit images, prompt-detected image refs, and attachment-derived media across embedded and CLI fallback, with compatible defaults, docs, and focused upgrade tests.

Options:

- **Add explicit media trust policy (recommended):** Add config, docs, and runtime checks that preserve existing behavior by default while letting users restrict images and attachments on cross-provider fallback.

- **Fail closed for cross-provider media:** Strip cross-provider media by default and require users to opt back into media forwarding when they want fallback vision behavior.
