## Summary

Keep open: current main still lacks a provider media trust-policy surface, and the fallback paths still need a maintainer security/product decision before this can be considered fixed. The linked open PR is an implementation candidate, not a merged fix.

## What This Changes

The issue asks OpenClaw to keep user images and attachments inside provider trust boundaries during cross-provider model fallback retries.

## Best Possible Solution

Keep this as the canonical security/product tracker, decide the provider media trust model, then land or replace the linked PR with coverage for explicit images, prompt-detected images, CLI and embedded retries, same-provider retries, and cross-provider retries.

Options:

- **Add explicit media trust policy (recommended):** Preserve compatibility by default unless maintainers choose a migration, and add tested config/docs so operators can restrict images and attachments crossing provider boundaries.
- **Fail closed on cross-provider media:** Strip explicit and prompt-detected media by default on cross-provider fallback, accepting a compatibility change with upgrade proof and clear docs.
- **Reject a core policy knob:** Document that users needing media isolation should avoid cross-provider fallbacks or run separate agents/gateways, leaving the runtime behavior unchanged.
