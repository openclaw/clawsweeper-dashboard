## Summary

Keep open: current main and the latest release still lack a provider media-trust policy, while the linked implementation candidate remains open and conflicting, so the security/product question is not resolved.

## What This Changes

The issue requests provider media trust controls so cross-provider model fallback does not forward images or attachments to a provider trusted only for text fallback.

## Best Possible Solution

Land a maintainer-approved provider media trust policy that covers explicit images, prompt-detected images, and attachment-derived media on fallback retries, with compatible defaults, docs, and focused upgrade/security tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should configured cross-provider model fallback be treated as consent to transfer user media, or should OpenClaw add a separate provider media trust policy for fallback retries?

Rationale: The source shows a real sensitive-data boundary gap, but the permanent default affects compatibility, fallback usefulness, and disclosure expectations, so automation should not choose the policy alone.

Likely owner: vincentkoc

Owner reason: Recent model-fallback history and current blame make vincentkoc the closest available routing owner for the policy decision.

Owner confidence: medium

Options:

- **Add explicit media trust policy (recommended):** Add config, docs, and runtime checks that preserve existing behavior by default while letting users restrict images and attachments on cross-provider fallback.
- **Document fallback as full consent:** Keep current forwarding semantics and document that configured cross-provider fallbacks may receive prompt text, images, and attachment-derived media.
- **Fail closed for cross-provider media:** Strip cross-provider media by default and require users to opt back into media forwarding when they want fallback vision behavior.
