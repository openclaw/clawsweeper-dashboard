## Label Justifications

- `P1`: The issue concerns sensitive user media crossing provider trust boundaries during real fallback workflows, but it is not an immediate crash loop or confirmed emergency security bypass.
- `impact:security`: User-supplied images or attachment-derived media can be sent to a fallback provider without a separate media trust decision.
- `impact:auth-provider`: The affected behavior is provider/model fallback routing and provider selection during agent retry.

## Summary

Keep open: current main still has no provider media trust-policy surface, and the active fallback paths can still forward or reload user images for fallback attempts without distinguishing text fallback trust from media trust.

## What This Changes

The issue requests a provider-level trust policy so cross-provider model fallback can avoid sending user images or attachments to fallback providers unless that data class is trusted.

## Best Possible Solution

Land a maintainer-approved provider media trust policy that covers explicit images, prompt-detected images, and attachment-derived images across fallback retries, with compatibility-preserving defaults or a documented opt-in/opt-out path and focused upgrade tests.

- **Fail closed for cross-provider media:** Strip cross-provider media by default and require users to opt back into forwarding when they want fallback vision behavior.
