## Summary

Keep open: current main still has no provider media trust policy, source and test evidence shows images can still travel through fallback paths, and the linked implementation candidate remains open and conflicting rather than merged.

## What This Changes

The issue requests provider-level fallback trust controls so text fallback can remain enabled without automatically forwarding user images or attachments across provider boundaries.

## Best Possible Solution

Keep this issue as the canonical tracker until maintainers land a tested provider media trust policy or explicitly decide that configured cross-provider fallback is consent for media transfer.

## Reproduction Assessment

Yes, source-level. Current main can forward explicit images through CLI fallback retries and can load prompt-referenced images in embedded attempts without a provider media trust gate.

## Solution Assessment

Unclear. A provider/data-class trust policy is a plausible durable fix, but the default, upgrade behavior, and whether to strip, prompt, or configure per provider need maintainer security/product review.
