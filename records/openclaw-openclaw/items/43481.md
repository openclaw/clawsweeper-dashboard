## Summary

Keep open: current main still lacks a provider media trust policy for cross-provider fallback, and the linked implementation candidate remains open and unmerged, so the security/product decision is unresolved.

## What This Changes

Request provider-level trust controls so images and attachments are not forwarded to cross-provider fallback models without an explicit media trust decision.

## Best Possible Solution

Land or sponsor a maintainer-approved provider media trust policy covering explicit images, prompt-detected images, and attachment-derived media across agent fallback, with compatibility-preserving defaults, docs, and tests.

Options:

- **Add explicit media trust policy (recommended):** Add config, docs, and runtime checks that preserve existing behavior by default while letting users restrict images and attachments on cross-provider fallback.
- **Document fallback as full consent:** Keep current forwarding semantics and document that configured cross-provider fallbacks may receive prompt text, images, and attachment-derived media.
- **Fail closed for cross-provider media:** Strip cross-provider media by default and require users to opt back into media forwarding when they want fallback vision behavior.
