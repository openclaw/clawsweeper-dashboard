## Label Justifications

- `P1`: The issue concerns sensitive user media crossing provider trust boundaries during real fallback workflows, but it is not a confirmed emergency bypass or crash-loop.
- `impact:security`: User-supplied images or attachment-derived media can reach a fallback provider without a separate media trust decision.
- `impact:auth-provider`: The affected behavior is provider/model fallback routing and provider selection during agent retry.

## Summary

Keep open: current main still lacks a provider media trust policy, and the fallback paths can still forward or reload image data without separating text-fallback trust from media-transfer trust.

## What This Changes

Request provider-level media trust controls so cross-provider model fallback can distinguish text fallback consent from image and attachment consent.

## Best Possible Solution

Land a maintainer-approved provider media trust policy covering explicit images, prompt-detected images, and attachment-derived media on fallback retries, with compatible defaults, docs, and focused upgrade tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should configured cross-provider model fallback be treated as consent to transfer user media, or should OpenClaw add a separate provider media trust policy for fallback retries?

Rationale: The source shows a real sensitive-data boundary gap, but the permanent default affects compatibility, fallback usefulness, and disclosure expectations, so automation cannot safely choose the security policy.

Likely owner: vincentkoc

Owner reason: He most recently changed the current fallback image replay path on main and is closest to the implementation surface that needs the policy.

Owner confidence: high

Options:

- **Add explicit media trust policy (recommended):** Add config, docs, and runtime checks that preserve existing behavior by default while letting users restrict images and attachments on cross-provider fallback.
- **Document fallback as full consent:** Keep current forwarding semantics and document that configured cross-provider fallbacks may receive prompt text, images, and attachment-derived media.
- **Fail closed for cross-provider media:** Strip cross-provider media by default and require users to opt back into media forwarding when they want fallback vision behavior.

Yes, source-level. Current main has no provider media trust config and still has fallback paths that forward or reload images without checking fallback-target media trust.

## Solution Assessment

Unclear until maintainer security/product review. A trust-policy surface fits the problem, but the default and upgrade behavior need maintainer intent before implementation is settled.
