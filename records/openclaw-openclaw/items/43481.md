## Label Justifications

## Summary

Keep open: current main still has no provider media trust-policy surface, CLI fallback still forwards current-turn images, prompt image loading remains provider-policy agnostic, and the linked fixing PR is open/conflicting rather than merged.

## What This Changes

The issue requests provider-level trust controls so cross-provider model fallback can distinguish text fallback trust from image or attachment transfer trust.

## Best Possible Solution

Keep this issue as the canonical tracker until maintainers choose and land a tested provider media trust policy, or explicitly document that configured cross-provider fallbacks are consent for media transfer.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should configured cross-provider model fallback imply consent to transfer images and attachments, or should OpenClaw add a separate media trust policy for fallback retries?

Rationale: Current code proves the media can cross provider boundaries, but the durable default affects privacy, compatibility, and fallback usefulness, so automation should not choose the trust boundary alone.

Likely owner: vincentkoc

Owner reason: Recent merged work on the active fallback media path makes this the best available owner for the immediate decision routing.

Owner confidence: medium

Options:

- **Add explicit media trust policy (recommended):** Add config/docs/runtime behavior that preserves compatibility unless maintainers choose otherwise while letting users restrict images and attachments on cross-provider fallback.
- **Document full fallback consent:** Keep forwarding semantics and clearly document that configured cross-provider fallbacks may receive prompt text plus media.
- **Fail closed for cross-provider media:** Strip fallback media by default across provider boundaries and require an explicit opt-in for fallback vision behavior.

## Solution Assessment
