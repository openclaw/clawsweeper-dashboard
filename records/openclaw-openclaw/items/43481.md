## Summary

Keep open: current main and the latest release still lack a provider media trust-policy surface, current main intentionally replays CLI fallback images, and the linked implementation candidate remains open and conflicting.

## What This Changes

The issue asks for provider-level trust controls so cross-provider fallback can avoid forwarding images or attachments to providers trusted only for text fallback.

## Best Possible Solution

Keep this issue open as the canonical tracker until maintainers either land an explicit provider media trust policy with docs/tests/upgrade behavior or document that configured fallback is consent for media transfer.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw add an explicit provider media trust policy for cross-provider fallback, or treat configured fallback providers as trusted for all current-turn media?

Rationale: The source path is clear, but the correct default changes the security boundary and upgrade expectations for existing fallback users.

Likely owner: vincentkoc

Owner reason: They recently changed the affected CLI fallback image path and are best positioned among the observed history owners to judge the runtime compatibility tradeoff.

Owner confidence: medium

Options:

- **Add explicit media trust policy (recommended):** Add a documented config surface and runtime checks so users can opt out of cross-provider image/attachment transfer while preserving existing behavior by default unless maintainers choose otherwise.
- **Document fallback as media consent:** Keep runtime behavior and document that adding a provider to fallback means that provider may receive the current turn's media payloads.
- **Strip media on cross-provider fallback:** Fail closed by default for cross-provider media, accepting a compatibility break only with maintainer security approval and upgrade proof.

## Reproduction Assessment

Yes, source-reproducible. Current main has no fallback media trust config shape, and the CLI fallback path forwards current-turn images into fallback attempts; I did not run a live cross-provider media test.

## Solution Assessment

Unclear until maintainer security/product review. A trust-policy surface fits the problem, but the default and upgrade behavior need an explicit maintainer decision before implementation is settled.
