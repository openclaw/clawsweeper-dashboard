## Summary

Keep open: current main still lacks a provider media trust-policy surface, source paths still forward or load current-turn images during fallback without a provider trust decision, and the open linked PR has not landed.

## What This Changes

Request provider-level media trust controls so cross-provider fallback can distinguish text fallback trust from image or attachment disclosure.

## Best Possible Solution

Land a maintainer-approved, upgrade-safe media trust policy covering explicit images, prompt-loaded images, attachments, config, docs, and fallback defaults, or explicitly document configured fallback as media-transfer consent.

Likely owner: vincentkoc

Owner confidence: medium

Options:

- **Add explicit media trust policy (recommended):** Preserve current behavior by default if maintainers choose compatibility, but add config, docs, and runtime checks so users can restrict images and attachments on cross-provider fallback.
- **Document fallback as full consent:** Keep forwarding semantics and make the docs state that configured cross-provider fallbacks may receive prompt text, images, and attachments.
- **Fail closed for cross-provider media:** Strip cross-provider media by default and require explicit opt-in when users want vision-capable fallback behavior across providers.

Yes, source-level. Current main has fallback image forwarding and prompt-image loading paths but no provider media trust-policy schema or runtime decision; I did not run a live cross-provider media fallback scenario.

## Solution Assessment

Unclear until maintainer security/product review. A trust-policy surface fits the problem, but the default and upgrade behavior need a maintainer decision before implementation is settled.
