## Label Justifications

- `P2`: This fixes a bounded Gmail integration reliability bug that can launch redundant external renewal commands but does not make the core runtime unusable.

## Summary

Current main still allows overlapping Gmail renewal commands when a renewal exceeds its interval, while this focused PR applies the single-flight invariant to both affected watcher lifecycles with regression and real-process proof. No blocking correctness or security findings were identified.

## What This Changes

The PR adds per-lifecycle single-flight guards for periodic Gmail watch renewals, aborts managed renewals during watcher replacement or shutdown, and adds regression tests for both Gmail watcher entry points.

## Best Possible Solution

Keep single-flight state scoped to each watcher lifecycle, cancel and settle the managed renewal before replacing its process, and retain focused tests proving skipped ticks and clean replacement behavior.

## Reproduction Assessment

Yes. Configure a renewal interval shorter than the existing 120-second command timeout, stall the first periodic command across a second tick, and current main admits another renewal; the PR reports this exact real-process scenario.

## Solution Assessment

Yes. Per-lifecycle promise guards are the narrowest maintainable fix because the gateway-managed watcher and foreground CLI service have independent shutdown ownership; a shared global mutex would incorrectly couple separate service instances.
