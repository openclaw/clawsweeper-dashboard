## Label Justifications

- `P2`: The issue affects multi-model fallback quality and operator reliability, but it is a bounded feature/design request rather than an urgent regression or outage.
- `impact:session-state`: The central problem is fallback attempts reusing the primary agent's workspace, context, session, and skills state instead of fallback-specific context.
- `impact:auth-provider`: The behavior is triggered by provider/model fallback routing and any fix would change fallback candidate scoping and auth/session interaction.

## Summary

Keep open: current main and the latest release still implement fallback as provider/model retry, not as a switch to a different agent, workspace, agentDir, session/context profile, or skills snapshot. The issue remains valid but needs maintainer product direction before implementation because the API shape affects config, session state, auth routing, and workspace ownership.

## What This Changes

Request to let fallback attempts use a different agent/workspace or model-specific context profile instead of reusing the primary agent context.

## Best Possible Solution

Keep this as the canonical core design thread, choose a first-class fallback context contract, then implement schema, docs, runner/session plumbing, and regression coverage around that contract.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw fallback attempts switch to another configured agent/workspace, apply a model-specific context profile, or remain model-only with narrower fallback notice/re-injection improvements?

Rationale: The missing behavior is real, but the permanent public API affects config schema, session identity, agentDir/workspace ownership, auth routing, skills snapshots, and upgrade behavior, so automation should not choose the product shape.

Likely owner: steipete

Owner reason: steipete already posted the design-oriented keep-open review and the reachable history points to adjacent fallback/config ownership.

Owner confidence: high

Options:

- **Choose fallback context profiles (recommended):** Define a first-class model or fallback context profile that can control bootstrap budgets/files, skills visibility, and context without changing agent identity by default.
- **Add explicit fallback agent/workspace:** Allow fallback attempts to select another configured agent or workspace, but require explicit session, auth, state, and migration semantics before implementation.
- **Defer to narrower fixes:** Leave model fallback selection unchanged for now and solve notification, re-injection, model-key, or auth-propagation subproblems in their own threads.

Yes, at source level: current main still exposes only primary/fallback model refs and runs fallback candidates without an alternate agent/workspace/context slot. I did not run a live provider outage because the missing schema and runtime carrier are directly visible in source.
