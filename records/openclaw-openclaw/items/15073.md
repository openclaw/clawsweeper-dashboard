- `P2`: The issue affects multi-model fallback quality and operator reliability, but it is a bounded feature/design request rather than an urgent regression or outage.
- `impact:session-state`: The central problem is fallback attempts reusing the primary agent's workspace, context, session, and skills state instead of fallback-specific context.

## Summary

Keep open: current main and v2026.6.11 still implement fallback as provider/model retry, not as a switch to a different agent, workspace, agentDir, session/context profile, or skills snapshot. The issue remains valid but needs maintainer product direction before implementation because the API shape affects config, session state, auth routing, and workspace ownership.

## What This Changes

The issue requests a fallback mode where model fallback can also switch to a different agent/workspace/context profile instead of reusing the primary agent context.

## Best Possible Solution

Keep this as the canonical core design thread, choose a first-class fallback context contract, then implement schema, docs, runner/session plumbing, and regression coverage around that contract.

- **Defer to narrower fixes:** Leave model fallback selection unchanged for now and solve notification, re-injection, model-key, or auth-propagation subproblems in their own threads.
