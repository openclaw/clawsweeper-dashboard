## Summary

Keep open: current main and the latest release still model fallback as provider/model retry inside the original run context, while the requested fallback agent/workspace/context-profile contract remains unimplemented and needs maintainer product direction.

## What This Changes

Request an option for model fallback to switch to an alternate agent, workspace, or context profile instead of reusing the primary agent's full context.

## Best Possible Solution

Define one maintainer-approved fallback context contract, then update config types, strict schemas, docs, fallback candidate metadata, reply-runner/session plumbing, and regression tests together.

## Reproduction Assessment

Yes, at source level. Current schemas and fallback runner code show fallback attempts vary provider/model only while preserving the original run's agentDir, workspaceDir, sessionFile, config, and skills snapshot.

## Solution Assessment

No implementation is under review yet. The issue is valid, but maintainers should choose fallbackAgent/fallbackWorkspace semantics or a narrower model-context-profile contract before any repair PR picks public config and session semantics.
