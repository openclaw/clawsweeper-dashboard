- `P2`: This affects multi-model fallback quality and operator reliability, but it is a feature/design request rather than an urgent regression or outage.
- `impact:session-state`: The central issue is fallback attempts reusing the primary agent's workspace, context, session, and skills state instead of fallback-specific context.

## Summary

Keep open: current main and the latest release still model fallback as provider/model candidate retry, with no fallback-agent, fallback-workspace, or model-context-profile contract, so the requested behavior remains real and needs product direction.

## What This Changes

The issue requests per-agent or model-specific fallback context/workspace behavior so fallback models can use a smaller or different workspace/context profile.

## Best Possible Solution

Keep this as the canonical core design thread, choose the fallback context contract first, then implement schema, docs, runner/session plumbing, and regression coverage around that contract.

Options:

- **Choose a fallback context profile contract (recommended):** Define a first-class model or fallback context profile that controls bootstrap budget/files, skills visibility, and session-safe context without changing agent identity by default.
- **Add fallback agent or workspace switching:** Allow a fallback attempt to select another configured agent or workspace, but require explicit session/auth/state semantics and migration proof before implementation.
- **Defer to narrower fallback issues:** Keep fallback model selection unchanged for now and solve only notification, re-injection, or model-key subproblems in their own threads.
