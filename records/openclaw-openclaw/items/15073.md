## Summary

Keep open: current main still treats fallback as provider/model retry inside the original agent run context, and the requested fallback agent/workspace/context-profile behavior remains an unresolved public config and session-identity design decision.

## What This Changes

The issue requests a way for model fallback to use a different agent, workspace, or model-specific context profile instead of reusing the original agent context.

## Best Possible Solution

Define one maintainer-approved fallback context contract, then update config types, strict schemas, schema help/docs, fallback candidate metadata, reply-runner/session plumbing, and regression tests together.

## Reproduction Assessment

Yes, at source level. Current-main schemas and fallback runner code show fallback attempts vary provider/model only while preserving the original run's agent/session/workspace context.

## Solution Assessment

No implementation is under review yet. The issue is valid, but maintainers should choose fallbackAgent/fallbackWorkspace semantics or a narrower model-context-profile contract before any repair PR picks public config and session semantics.
