## Label Justifications

- `P2`: Fallback quality and graceful degradation are affected, but the remaining work is a bounded design improvement rather than an urgent runtime outage.
- `impact:session-state`: The request would intentionally change workspace/context and possibly agent/session identity during fallback retries.

## Summary

Keep open: current main still treats fallback as provider/model retry inside the original agent run context, and the requested fallback agent/workspace/context-profile contract remains an unresolved public config and session-identity design decision.

## What This Changes

The issue requests per-agent fallback context or workspace selection so smaller fallback models do not inherit the primary agent's full workspace prompt, skills, and session context.

## Best Possible Solution

Define one maintainer-approved fallback context contract, then update config types, strict schemas, docs, fallback candidate metadata, reply-runner/session plumbing, and regression tests together.

## Reproduction Assessment

Yes, at source level. Current-main schemas and fallback runner code show fallback attempts vary provider/model only while preserving the original run's agentDir, workspaceDir, sessionFile, config, and skills snapshot.

## Solution Assessment

No implementation is under review yet. The issue is valid, but maintainers should choose fallbackAgent/fallbackWorkspace semantics or a narrower model-context-profile contract before any repair PR picks public config and session semantics.
