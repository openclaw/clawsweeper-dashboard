## Summary

Keep open: current main still models fallback as provider/model retry inside the original agent run context, while the requested fallback agent/workspace/context-profile contract remains a public config and session-identity product decision.

## What This Changes

The issue requests a way for model fallback to switch to a different agent, workspace, or model-specific context profile so smaller fallback models do not receive the primary agent's full workspace context.

## Best Possible Solution

Define one maintainer-approved fallback context contract, then update config types, strict schemas, docs, fallback candidate metadata, reply-runner/session plumbing, and regression tests together.

## Reproduction Assessment

Yes, at source level. Current-main schemas and fallback runner code show fallback attempts vary provider/model only while preserving the resolved run's agentDir, workspaceDir, session state, and skills/context setup.

## Solution Assessment

No implementation is under review yet. The issue is valid, but maintainers should choose fallbackAgent/fallbackWorkspace semantics or a narrower model-context-profile contract before any repair PR picks public config and session behavior.
