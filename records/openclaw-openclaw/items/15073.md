## Label Justifications

- `P2`: The issue affects multi-model fallback quality and operator reliability, but it is a bounded feature/design request rather than an urgent regression or outage.
- `impact:session-state`: The central problem is fallback attempts reusing the primary agent's workspace, context, session, and skills state instead of fallback-specific context.
- `impact:auth-provider`: The behavior is triggered by provider/model fallback routing and any fix would change fallback candidate scoping.

## Summary

Keep open: current main and the latest release still model fallback as provider/model candidate retry, with no fallback-agent, fallback-workspace, or model-context-profile contract, so the requested behavior remains real and needs product direction.

## What This Changes

The issue requests per-agent or per-workspace context selection when a model fallback is used instead of reusing the primary agent's context.

## Best Possible Solution

Keep this issue as the canonical core design thread, choose the fallback context contract first, then implement schema, docs, runner/session plumbing, and regression coverage around that contract.

## Maintainer Decision

Kind: product_direction

Question: Should OpenClaw model fallback switch to another agent/workspace, apply a model-specific context profile, or stay model-only with a narrower fallback notice/re-injection mechanism?

Rationale: The missing behavior is real, but the permanent public API affects config schema, session identity, agentDir/workspace ownership, auth routing, skills snapshots, and upgrade behavior, so automation should not choose the product shape.

Likely owner: steipete

Owner reason: steipete already posted the design-oriented keep-open review and history points to adjacent fallback/config ownership.

Owner confidence: high

Options:

- **Choose a fallback context profile contract (recommended):** Define a first-class model or fallback context profile that can control bootstrap budget/files, skills visibility, and session-safe context without changing agent identity by default.
- **Add fallback agent or workspace switching:** Allow a fallback attempt to select another configured agent or workspace, but require explicit session/auth/state semantics and migration proof before implementation.
- **Defer to narrower related issues:** Keep fallback model selection unchanged for now and solve only notification, re-injection, or model-key subproblems in their own threads.
