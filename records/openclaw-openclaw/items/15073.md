## Summary

Keep open: current main still implements fallback as provider/model candidate retry, and the requested per-agent workspace/context fallback remains a compatibility-sensitive product design change rather than cleanup-closeable stale work.

## What This Changes

The issue requests a way for a model fallback attempt to switch to a different agent, workspace, or model-specific context profile instead of reusing the primary agent context.

## Best Possible Solution

Keep this open for a maintainer-selected fallback context contract, then implement the chosen agent-switch, workspace override, or model-context-profile semantics through config schemas, docs, fallback candidate metadata, runner/session plumbing, and regression tests.

## Reproduction Assessment

Yes, at source level: current main exposes only primary/fallback model refs and executes fallback candidates with the same agent/session/workspace run context. I did not run a live provider outage because the missing config/runtime surface is directly visible in source.

## Solution Assessment

Unclear. The reported gap is real, but the best long-term fix depends on a maintainer choice between fallbackAgent, fallbackWorkspace, and a narrower model-context-profile or budget mechanism.
