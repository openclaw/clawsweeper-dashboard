## Label Justifications

- `P2`: This is a valid multi-model fallback improvement with limited blast radius, but it requires product/API design rather than urgent regression repair.
- `impact:session-state`: The request changes how fallback attempts relate to agent identity, workspace context, session files, and skills snapshots.
- `impact:auth-provider`: Fallback behavior is tied to provider/model routing and per-agent auth/profile state during failover.

## Summary

Keep open: current main still treats fallback as provider/model retry inside the original agent run context, while the requested fallback agent/workspace/context-profile behavior remains a core config and session-identity product decision.

## What This Changes

Request an option for model fallback to switch to a different agent, workspace, or model-specific context profile so smaller fallback models do not receive the primary agent's full context.

## Best Possible Solution

Choose one first-class core design for fallbackAgent, fallbackWorkspace, or model-specific context profiles, then update config types, schemas, docs, fallback candidate metadata, reply-runner/session plumbing, and regression coverage together.

## Reproduction Assessment

Yes, at source level. Current-main schemas and fallback runner code show fallback attempts vary provider/model only while preserving the original run's agentDir, workspaceDir, sessionFile, config, and skills snapshot.

## Solution Assessment

Unclear until maintainers choose the API shape. The requested behavior is useful, but implementing one proposed config key now would prematurely decide between agent switching, workspace override, and model context-profile semantics.
