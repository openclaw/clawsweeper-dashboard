## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Preserve existing audio and video modalities:** `src/commands/model-metadata.ts:149`
  - body: `ModelDefinitionConfig.input` supports `audio` and `video`, and existing configured models can use those modalities. This prompt only offers `text` and `image`, then saves `result.input` from that selection, so reconfiguring metadata for an existing custom audio/video-capable model silently removes capabilities the prompt cannot show. Preserve unknown existing modalities or expose the full supported set before writing the model entry.
  - confidence: 0.89
- **[P2] Make Auto clear or relabel the API override:** `src/commands/model-metadata.ts:131-133`
  - body: Selecting `Auto (inherit from provider)` leaves `result.api` unset, and the later merge spreads `...entry.model` first, so an existing model-level `api` override remains in config. That contradicts the label and keeps the model from inheriting the provider adapter. Either clear `model.api` when Auto is selected or relabel the choice so users know it keeps the current override.
  - confidence: 0.86
- **[P2] Preserve tiered pricing when editing cost:** `src/commands/model-metadata.ts:210-215`
  - body: When a model already has `cost.tieredPricing`, the cost prompt defaults on and pressing Enter creates a replacement flat `cost` object with only input/output/cache fields. The merge then drops `tieredPricing`, even though current cost accounting uses it when present, so editing metadata can silently change usage-cost calculations. Preserve the existing tiered pricing unless the wizard explicitly edits it.
  - confidence: 0.88
