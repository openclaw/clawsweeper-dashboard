## Summary

Keep open: this PR adds useful custom-provider metadata setup UX that is not already on current main, but the branch is not merge-ready because the new editor can silently rewrite existing persisted model metadata.

## What This Changes

The PR adds a custom-provider-only metadata prompt to `openclaw configure --section model`, plus helper functions and unit tests for editing `models.providers.*.models[]` fields.

## Best Possible Solution

Repair the metadata-preservation defects first, then have maintainers decide whether the final custom-provider metadata surface belongs in `configure`, onboarding, or a shared editor.

## Reproduction Assessment

Yes for the review findings by source inspection: an existing custom model row with `input: ["text", "audio"]` or tiered `cost` can be edited through the new helper and have those values overwritten. The feature request itself is not a bug reproduction.

## Solution Assessment

No. The PR is a plausible feature, but not the best merge shape until the editor preserves metadata it does not fully expose and maintainers confirm `configure` is the right surface.
