## Summary

Keep this PR open but not merge-ready: the Commander path is improved, but the route-first `openclaw sessions` parser still turns invalid present `--active` and `--limit` values into `undefined` after removing command-layer validation, so invalid filters can run unfiltered and the terminal proof is not sufficient.

## What This Changes

The PR moves `sessions` list and tail numeric option validation from command implementations into CLI registration and route-first parsing, updating option types and related tests.

## Best Possible Solution

Keep one validation contract across Commander and route-first sessions execution, either by rejecting invalid present values in `parseSessionsRouteArgs` before returning a route object or by preserving command-layer validation as the shared boundary.

## Reproduction Assessment

Yes. Source inspection traces `openclaw sessions` through `parseSessionsRouteArgs`, `route-specs`, and `sessionsCommand`; invalid present `--active` or `--limit` values become `undefined` and still run through the fast route on the PR head.

## Solution Assessment

No. CLI-layer validation is a reasonable direction, but the best fix must preserve equivalent validation for the route-first sessions path or keep command-layer normalization as the shared boundary.
