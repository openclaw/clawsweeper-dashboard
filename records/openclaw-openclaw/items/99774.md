## Summary

Keep open: the latest head partially addresses the earlier route-first mismatch, but invalid route-first `--active` and `--limit` values now parse to `undefined`, so `openclaw sessions --active abc` or `--limit abc` can silently run without the requested filter instead of rejecting the input.

## What This Changes

The PR moves validation for `openclaw sessions --active`, `openclaw sessions --limit`, and `openclaw sessions tail --tail` from session command code into CLI and route argument parsing, updating related tests and command option types.

## Best Possible Solution

Keep one canonical validation contract across Commander and route-first sessions list execution, either by making invalid route-first values fall back to Commander validation or by preserving command-layer normalization as the shared boundary.

## Reproduction Assessment

Yes. Source inspection traces `openclaw sessions` through `parseSessionsRouteArgs` into `sessionsCommand`; on the PR head, invalid present `--active` and `--limit` values become `undefined` and the route still runs.

## Solution Assessment

No. CLI-layer validation is a reasonable direction, but the best fix must preserve equivalent validation for the route-first sessions path or keep command-layer normalization as the shared boundary.
