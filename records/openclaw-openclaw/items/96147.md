## Summary

Keep this PR open: the patch is coherent and proof is sufficient, but it intentionally changes default `doctor --lint` behavior for existing multi-account configs, so a maintainer should explicitly accept or soften that compatibility risk before merge.

## What This Changes

The PR moves multi-account default-account routing warnings into a structured core doctor health check and wires it through doctor preview, lint, and repair output.

## Best Possible Solution

Keep the single structured warning path if maintainers accept the lint compatibility change; otherwise make the new lint check opt-in or softer while preserving preview and repair warnings.
