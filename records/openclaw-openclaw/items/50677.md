Keep open. Current main and the latest release still truncate the model-visible skills catalog to a sorted fitting prefix with only a count-based note, while the narrow omitted-skill recovery PR and the broader priority/pinning product decision are still unresolved.

The issue asks OpenClaw to stop silently omitting eligible user-created skills from the prompt, add recovery/visibility for omitted skills, document the budget, and consider priority or pinning controls.

## Best Possible Solution

Keep this as the canonical tracker until OpenClaw lands omitted-skill lookup or equivalent recovery, documents skills prompt truncation clearly, and maintainers decide the priority/pinning config contract.
