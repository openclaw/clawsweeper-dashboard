## Summary

Keep open. Current main and the latest release still can omit prompt-visible skills under the skills prompt budget with only a count-based model-facing note; the narrow omitted-key recovery PR is open, while pinning/priority remains a separate product/config decision.

## What This Changes

The issue asks OpenClaw to stop silently dropping eligible user skills from the agent prompt, surface truncation clearly, document the limit, and provide a way to prioritize or force-load important skills.

## Best Possible Solution

Keep this issue as the canonical tracker until omitted-skill lookup or equivalent recovery lands, public docs explain truncation and recovery, and maintainers decide whether priority/pinning belongs in the skills config contract or stays in https://github.com/openclaw/openclaw/issues/50199.

## Reproduction Assessment

Yes, as a source-level reproduction. Current main sorts prompt-visible skills, applies maxSkillsPromptChars/maxSkillsInPrompt, can binary-search down to a compact prefix, and emits only a count-based model-facing note.

## Solution Assessment

No, current main is not the full solution. The narrow omitted-key recovery belongs in the existing open PR, while priority/pinning and user-visible warning behavior need maintainer-approved config and UX direction.
