## Summary

Keep open. Current main and the latest release still truncate the prompt-visible skills catalog to an alphabetically sorted fitting prefix with only a count-based model-facing note, while omitted-skill recovery is still in an open PR and priority/pinning remains a config/product decision.

## What This Changes

Request to make skills prompt truncation visible and recoverable, and to add a way to prioritize or pin critical user-created skills.

## Best Possible Solution

Land or replace the omitted-skill recovery path, document the prompt budget and truncation outcome, and resolve priority/pinning through maintainer-approved skills config direction such as https://github.com/openclaw/openclaw/issues/50199.

## Reproduction Assessment

Yes, as a source-level reproduction. Current main sorts prompt-visible skills, truncates them to a fitting prefix under `maxSkillsPromptChars`, and emits only a count-based model-facing note; I did not run a live agent session because this review is read-only.

## Solution Assessment

No, current main is not the best solution because it still hides omitted skill identities from users and the agent. The best path is a narrow omitted-skill recovery fix plus docs, with priority/pinning handled only after maintainer-approved config direction.
