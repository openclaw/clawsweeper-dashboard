## Summary

Keep open. Current main and v2026.6.11 still truncate the prompt-visible skills catalog to a budget-fitting prefix with only a count-based model-facing note; docs now mention the limit, and open related work covers parts of the fix, but omitted-skill recovery and priority/pinning policy have not landed.

## What This Changes

The issue asks OpenClaw to stop silently hiding eligible user skills when the skills prompt budget is exceeded, with visibility, documentation, and possible priority or pinning controls.

## Best Possible Solution

Ship or repair the narrow omitted-skill recovery path first, keep the current docs budget note, and decide priority/pinning or smart indexing as staged product/config follow-up.
