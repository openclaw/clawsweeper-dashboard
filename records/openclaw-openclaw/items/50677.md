## Label Justifications

- `P2`: Large skills catalogs can hide eligible skills from the model-visible session context, but the blast radius is limited to skills prompt overflow rather than a core outage.
- `impact:session-state`: The model-visible skills snapshot can diverge from the user's installed and eligible skills when prompt truncation drops entries.
- `impact:ux-friction`: Users can diagnose through `openclaw skills check`, but omitted skills are not surfaced clearly during the affected run.

## Summary

Keep open. Current main still truncates the prompt-visible skills list to a fitting sorted prefix with only a count-based model-facing note, the latest release still has that behavior, and the open omitted-key PR plus priority/smart-indexing trackers have not landed or superseded this issue.

## What This Changes

The issue asks OpenClaw to stop silently dropping eligible user-created skills from the model-visible skills prompt when the skills catalog exceeds the prompt budget, with priority/pinning or user-visible truncation handling as possible remedies.

## Best Possible Solution

Ship or repair the narrow omitted-skill recovery path first, keep the docs budget note, and decide priority/pinning or smart indexing as staged product/config follow-up work.
