## Label Justifications

- `P2`: The issue affects prompt-visible skill state and can make eligible skills unavailable, but it is bounded to large skill catalogs and has manual audit workarounds.
- `impact:session-state`: The reported failure is that the runtime prompt state no longer represents the user's eligible skill set.
- `impact:ux-friction`: Users must cross-check `openclaw skills check` or inspect files to discover which eligible skills were omitted.

## Summary

Keep open. Current main and latest release still truncate prompt-visible skills to a fitting alphabetized prefix with only a count-based prompt note; the omitted-key recovery PR remains open, and priority/pinning is still a separate config/product decision.

## What This Changes

The issue asks OpenClaw to stop silently dropping eligible user skills when the skills prompt exceeds its budget, with possible omitted-skill warnings, priority/pinning, context-aware loading, and documentation.

## Best Possible Solution

Keep this issue as the canonical tracker until omitted-skill recovery lands or is replaced, then route priority/pinning to the dedicated priority issue and broader smart loading to the smart-indexing design.

## Reproduction Assessment

Yes, from source: with more prompt-visible skills than fit in `skills.limits.maxSkillsPromptChars`, `applySkillsPromptLimits` keeps only the largest fitting prefix and `buildSkillsLimitNote` reports only counts. I did not run a live model session in this read-only review.

## Solution Assessment

No, current main is not a complete solution. The narrow omitted-key recovery belongs in the existing PR, while pinning, per-topic required skills, and context-aware loading need maintainer-approved config and UX semantics.
