## Label Justifications

- `P2`: The issue affects skills prompt visibility for users with large catalogs, but it has a bounded skills-context blast radius and no current evidence of a release-blocking outage.
- `impact:session-state`: Prompt truncation can make the agent's session-visible skills snapshot diverge from the user's installed and eligible skills.
- `impact:ux-friction`: Users can diagnose with `openclaw skills check`, but the omitted skills are not surfaced clearly during the affected run.

## Summary

Keep open. Current main and v2026.6.11 still truncate prompt-visible skills to a budget-fitting prefix with only a count-based model-facing note; public docs now mention the budget, but omitted-skill recovery and priority/pinning behavior have not landed.

## What This Changes

The issue asks OpenClaw to stop silently hiding eligible user-created skills when the skills prompt overflows, and to add warning, priority, pinning, or context-aware loading behavior.

## Best Possible Solution

Ship a narrow omitted-skill recovery path first, keep the docs budget note, and decide priority/pinning or smart indexing as a staged product/config follow-up.
