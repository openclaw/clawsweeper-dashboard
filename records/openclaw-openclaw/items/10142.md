## Summary

Keep open: current main and latest release still lack the requested internal `session:end` HOOK.md event. The existing `session_end` lifecycle hook is real, but it is a typed plugin surface, and the open linked PR is a partial reset-hook candidate rather than an implementation of this internal hook contract.

## What This Changes

Request an internal `session:end` hook event that fires when an agent session completes so workflow orchestrators can react without requiring agents to run an explicit command.

## Best Possible Solution

Make an explicit maintainer API decision: either add a documented internal `session:end` event with typed guard/tests across relevant completion paths, or document typed plugin `session_end` as the supported workflow-integration surface and then close this request.
