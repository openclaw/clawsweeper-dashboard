## Summary

Keep open: current main and the latest release still lack the requested documented internal `session:end` hook, while the existing `session_end` support is a separate typed plugin hook and the linked implementation PR is open, partial, and unmerged.

## What This Changes

The issue requests a new internal `session:end` hook event for session-completion workflow orchestration.

## Best Possible Solution

Maintainers should choose and document the supported contract: add a narrow internal `session:end` event with coverage across completion paths, or explicitly point workflow integrations to the typed plugin `session_end` hook.

## Reproduction Assessment

Yes. Source inspection on current `main` reproduces the gap: internal hooks expose `session:patch` and other events, while session completion is only exposed through the separate typed plugin `session_end` surface.

## Solution Assessment

Unclear. Adding an internal event is plausible, but the existing typed plugin `session_end` hook may be the better owner, so maintainers should decide and document the supported contract before implementation.
