## Summary

Keep open: current main still lacks the requested internal `session:end` event, and the live linked PR only covers a narrower daily/idle reset hook path without adding new event names.

## What This Changes

Add an internal `session:end` hook event so workflow orchestration can react when an agent session completes.

## Best Possible Solution

Maintainers should choose and document the supported lifecycle contract: either add a narrow internal `session:end` event with coverage across completion paths, or declare typed plugin `session_end` the supported replacement and close or retarget the linked PRs accordingly.

## Reproduction Assessment

Yes, at source level: current main exposes `session:patch` internally and `session_end` as a typed plugin hook, but no documented or typed internal `session:end` event exists.

## Solution Assessment

Unclear. Adding an internal event is plausible for HOOK.md automation, but the existing typed plugin `session_end` surface may be the cleaner owner, so maintainers should decide the supported lifecycle hook contract first.
