## Summary

Keep open: current main exposes typed plugin lifecycle hooks, including `session_end`, but still does not establish the requested internal `session:end` HOOK.md contract. The open linked PR addresses daily/idle session retirement only and explicitly adds no new event, so it cannot resolve the broader finite-run completion request without a maintainer lifecycle-semantics decision.

## What This Changes

Add an internal `session:end` hook that emits when an agent session completes so external workflow orchestration can react without agent-authored cleanup commands.

## Best Possible Solution

Define session retirement and finite run completion as separate lifecycle concepts, then expose the chosen generic completion signal through the plugin-owned typed lifecycle API and, only if workspace automation needs it, a thin internal-hook dispatch with one canonical payload, shared emitters, focused ordering tests, and updated public hook documentation.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw treat persisted-session retirement and finite agent-task completion as separate lifecycle events, and which of those should be exposed to workspace internal hooks?

Rationale: Current reset, cron, webhook, agent-run, and subagent paths have different terminal semantics, while plugin and internal hooks are separate public surfaces; code alone cannot determine the intended permanent contract.

Likely owner: vincentkoc

Owner reason: The active implementation discussion routes hooks and plugin API review to this owner area.

Owner confidence: medium

Options:

- **Separate lifecycle events (recommended):** Keep `session_end` for session retirement and expose a distinct generic run-completion event for cron, webhook, agent, and subagent terminal outcomes.
- **Plugin hooks only:** Declare typed `agent_end`, `subagent_ended`, cron status, and `session_end` hooks the supported integration path and document that HOOK.md automation does not receive a universal completion event.
- **Universal internal session:end:** Add one internal `session:end` event across reset and finite-run paths, accepting a broader payload and more complex ordering contract.

## Reproduction Assessment

Yes, from source: internal HOOK-style automation and typed plugin lifecycle hooks remain separate, and no canonical internal event covers the requested completion semantics across session, cron, webhook, and subagent paths.

## Solution Assessment

No, not as a single literal event across every proposed path; the maintainable solution first separates persisted-session retirement from finite task completion and then adds one canonical dispatch surface for each supported lifecycle concept.
