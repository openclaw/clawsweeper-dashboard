## Summary

Keep open: current main still lacks the requested internal `session:end` HOOK.md event; the existing `session_end` lifecycle surface is a typed plugin hook, and the open linked PR at https://github.com/openclaw/openclaw/pull/61675 is only a partial reset-hook candidate that explicitly avoids new hook event names.

## What This Changes

The issue requests a new internal `session:end` hook event for session completion so external workflow systems can react without agent-authored CLI workarounds.

## Best Possible Solution

Maintainers should choose and document the supported lifecycle contract: either add a narrow internal `session:end` event with coverage across completion paths, or explicitly document typed plugin `session_end` as the supported replacement for this use case.

## Reproduction Assessment

Yes, at source level: current main exposes internal session patch/compaction hooks and a typed plugin `session_end` hook, but no documented or typed internal `session:end` event exists.

## Solution Assessment

Unclear. Adding an internal event is plausible for HOOK.md automation, but the existing typed plugin `session_end` surface may be the cleaner owner, so maintainers should decide the supported lifecycle hook contract before implementation.
