## Summary

Keep open: current main and the latest release still lack the requested internal `session:end` hook event, and the existing typed plugin `session_end` surface is a separate lifecycle hook contract. The open linked implementation candidate at https://github.com/openclaw/openclaw/pull/61675 should be reviewed, landed, or closed before this issue is cleaned up.

## What This Changes

Add an internal `session:end` hook event that fires when a session completes so external workflow orchestration can react without agent-authored CLI commands.

## Best Possible Solution

Keep this open until maintainers either land or close the linked implementation candidates, or explicitly document the typed plugin `session_end` hook as the supported replacement; if the internal surface is accepted, implement one typed `session:end` contract across the relevant completion paths with focused tests and docs.

## Reproduction Assessment

Yes at source level: current main and v2026.6.11 list only `session:patch` for internal session hooks while plugin `session_end` remains a separate surface. I did not run a live session completion scenario because the missing contract is visible in source and docs.

## Solution Assessment

Unclear as a final product direction: adding internal `session:end` would satisfy the requested HOOK.md workflow, but repository direction prefers plugin surfaces for deeper lifecycle control when they are adequate. Maintainers should choose the permanent contract before another autonomous fix attempt.
