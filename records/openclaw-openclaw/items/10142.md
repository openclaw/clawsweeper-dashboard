## What This Changes

The issue requests a new internal `session:end` hook event so operator hooks can react when an agent session completes.

## Best Possible Solution

Maintainers should choose and document the supported lifecycle contract: either add a narrow internal `session:end` event with tests across completion paths, or declare typed plugin `session_end` the supported replacement and update internal hook guidance accordingly.

## Reproduction Assessment

Yes, at source level: current main exposes internal session patch/compaction hooks and a typed plugin `session_end` hook, but no documented or typed internal `session:end` event exists.

## Solution Assessment

Unclear. Adding an internal event is plausible for HOOK.md automation, but the existing typed plugin `session_end` surface may be the cleaner owner, so maintainers should decide the supported lifecycle hook contract before implementation.
