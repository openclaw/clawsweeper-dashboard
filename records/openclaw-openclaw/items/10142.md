## Summary

Keep open: current main and v2026.6.11 still do not expose a documented typed internal `session:end` hook event. The typed plugin `session_end` hook is real and useful, but it is a separate surface, and the linked open pull request only partially overlaps with daily/idle reset behavior.

## What This Changes

Add an internal `session:end` hook event that fires when a session completes so external workflow orchestrators can react without relying on agent instructions.

## Best Possible Solution

End with one documented lifecycle completion contract: either bless the typed plugin `session_end` hook as the supported automation path, or add a narrow internal `session:end` event wired across the relevant completion paths with tests and docs.
