## Summary

Keep open: current main still lacks the requested internal `session:end` hook event; the existing `session_end` lifecycle hook is a typed plugin surface, and the open linked reset-hook PR is only a partial candidate rather than a merged fix.

## What This Changes

Add an internal `session:end` hook event that fires when a session completes so operator-installed hooks can signal workflow systems without agent-instruction workarounds.

## Best Possible Solution

Keep this issue open until maintainers either land a direct typed internal `session:end` event across the relevant completion paths or explicitly document `session_end` plugin hooks as the supported replacement for workflow integrations.

## Reproduction Assessment

Yes, at source level: current main documents and types `session:patch` for internal hooks and `session_end` for plugin hooks, but no internal `session:end` event is defined or dispatched. This is a feature gap rather than a broken existing behavior contract.

## Solution Assessment

Unclear as final product direction: adding an internal `session:end` event is a plausible narrow solution, but maintainers need to decide whether the existing typed plugin `session_end` hook should be the supported integration surface instead.
