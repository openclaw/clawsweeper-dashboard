## Summary

Keep open: current main and v2026.6.11 still lack the requested internal `session:end` HOOK.md event. The typed plugin `session_end` lifecycle hook is real, but it is documented as a separate plugin surface, and the open linked reset-hook PR explicitly avoids adding new event names.

## What This Changes

Add an internal `session:end` hook event that fires when an agent session completes so operator-installed hooks can signal external workflow systems.

## Best Possible Solution

Make an explicit maintainer API decision: either add a typed internal `session:end` event with docs and completion-path tests, or document typed plugin `session_end` as the supported workflow-integration surface and close this request then.

## Reproduction Assessment

Yes. Source inspection reproduces the API gap: current internal hook types and docs do not include `session:end`, while the existing `session_end` surface is typed plugin-only.

## Solution Assessment

Unclear. A narrow internal event could solve the requested operator-hook workflow, but maintainers need to decide whether that should duplicate or be replaced by the plugin lifecycle hook contract.
