## Summary

Keep open: current main and the latest release still lack the requested internal `session:end` HOOK.md event. The typed plugin `session_end` lifecycle hook is real and broader than before, but treating it as the replacement for operator-installed internal hooks still needs maintainer product/API direction, and the open linked reset-hook PR is only partial overlap rather than a merged fix.

## What This Changes

The issue requests an internal `session:end` hook event that fires when an agent session completes so external workflow systems can react without agent-authored cleanup commands.

## Best Possible Solution

Make an explicit maintainer API decision: either add a typed internal `session:end` event with docs and completion-path tests, or document plugin `session_end` as the supported workflow-integration surface and close this internal-hook request.

## Reproduction Assessment

Yes. Source inspection reproduces the API gap: current internal hook docs and typed guards do not include `session:end`, while the existing `session_end` lifecycle hook is a separate plugin surface.

## Solution Assessment

Unclear. A narrow internal event could solve the requested operator-hook workflow, but the best permanent solution needs maintainer direction to avoid duplicating or confusing the plugin lifecycle hook contract.
