## Summary

Keep open: current main and the latest release still do not expose the requested internal `session:end` HOOK.md event. The typed plugin `session_end` lifecycle hook is real and much broader now, but that adjacent surface has not been documented as the replacement for operator-installed internal hooks, and the open linked reset-memory PR is only partial overlap.

## What This Changes

The issue requests a new internal `session:end` hook event emitted when an agent session completes.

## Best Possible Solution

Keep this issue open until maintainers either define and wire a documented internal `session:end` event, or explicitly document typed plugin `session_end` as the supported replacement for this orchestration use case.

## Reproduction Assessment

Yes, at source level: current internal hook types and internal hook docs do not expose `session:end`, while related lifecycle support is implemented as typed plugin `session_end`. I did not run a live hook script because the absence is visible in the exported contract and docs.

## Solution Assessment

Unclear. A new internal event is plausible, but the cleaner long-term solution may be to make typed plugin `session_end` the documented lifecycle API if maintainers want session completion to stay on the plugin surface.
