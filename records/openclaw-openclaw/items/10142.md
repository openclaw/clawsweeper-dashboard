## Summary

Keep open. Current main and the latest release still lack the requested internal `session:end` contract; the existing typed plugin `session_end` hook is a distinct extension surface, and the open linked PR addresses only daily/idle reset behavior rather than general session completion. The remaining blocker is a maintainer product/API choice, not stale cleanup.

## What This Changes

Add an internal `session:end` lifecycle event so hook-pack automations can react when agent sessions complete.

## Best Possible Solution

Choose one canonical completion contract: preferably complete and document typed plugin `session_end` for the intended cron/subagent completion paths, or retain this issue for a distinctly scoped internal hook-pack event with stable semantics and full lifecycle tests.
