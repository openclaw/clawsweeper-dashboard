## Summary

Keep open: current main still lacks the requested internal `session:end` HOOK.md event. The existing `session_end` support is a typed plugin hook, and the open linked implementation candidate is unmerged and explicitly scoped away from adding new hook event names.

## What This Changes

Add an internal `session:end` hook event so operator-installed hooks can react when an agent session completes.

## Best Possible Solution

Maintainers should choose and document the supported lifecycle contract: either add a narrow internal `session:end` event with tests across completion paths, or declare typed plugin `session_end` the supported replacement for this workflow use case.

## Reproduction Assessment

Yes, at source level: current main exposes `session:patch` internally and `session_end` as a typed plugin hook, but no documented or typed internal `session:end` event exists.

## Solution Assessment

Unclear. Adding an internal event is plausible, but the existing typed plugin `session_end` surface may be the cleaner owner, so maintainers should decide the supported hook contract first.
