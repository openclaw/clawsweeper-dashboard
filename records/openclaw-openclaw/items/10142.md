## Summary

Current main still has no internal `session:end` event; it instead defines separate typed `agent_end`, `session_end`, and `subagent_ended` plugin lifecycles. Keep this issue open because the linked open PR claims to close it while only addressing daily/idle reset hooks, and maintainers must first choose the canonical completion contract. citeturn6view0turn2view0turn2view1turn1view0

## What This Changes

Add an internal `session:end` hook that lets operator automation react when session work completes.

## Best Possible Solution

Keep `agent_end` as the per-run workflow completion signal, `subagent_ended` as spawned-work completion, and `session_end` as persisted-session lifecycle; add an internal coarse event only if maintainers confirm operator-installed HOOK.md automation still needs a documented mirror of one exact boundary.
