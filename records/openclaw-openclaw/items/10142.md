## Summary

Keep open: current main and the latest release still lack the requested internal completion event, while the shipped plugin hook represents session finalization rather than a settled general task-completion contract. The only open linked PR addresses daily and idle reset behavior, so it should be reviewed as a partial implementation candidate rather than treated as a completed fix.

## What This Changes

Add a typed internal `session:end` lifecycle hook so external automation can react when an agent session completes.

## Best Possible Solution

Define precise terminal lifecycle reasons and coverage first, then extend the typed plugin hook as the canonical workflow-integration seam or add a distinctly named internal task-completion event only if operator-installed HOOK.md automation requires a separate contract.
