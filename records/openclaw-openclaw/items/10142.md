## Summary

Keep open: current main and the latest release still do not expose a documented internal `session:end` HOOK.md event. The existing `session_end` surface is a typed plugin hook, and the open linked implementation candidate at https://github.com/openclaw/openclaw/pull/61675 is partial, conflicting, and explicitly avoids new event names.

## What This Changes

Request to add an internal `session:end` hook event that fires when an agent session completes so operator-installed hooks can signal workflow orchestrators.

## Best Possible Solution

Maintainers should choose and document the supported lifecycle contract: add a narrow internal `session:end` event with tests across completion paths, or explicitly direct this workflow to typed plugin `session_end` and update internal-hook guidance.

## Reproduction Assessment

Yes, at source level: current main exposes `session:patch` internally and `session_end` as a typed plugin hook, but no documented or typed internal `session:end` event exists.

## Solution Assessment

Unclear. Adding an internal event is plausible for HOOK.md automation, but the existing typed plugin `session_end` surface may be the cleaner contract, so maintainers should decide the supported lifecycle hook surface before implementation.
