## Summary

Keep open: current main and the latest release still lack the requested internal `session:end` HOOK.md event. The typed plugin `session_end` lifecycle hook exists and has broader runtime coverage, but using it as the replacement for operator-installed internal hooks still needs maintainer API direction, and the linked reset-hook PR is open and only partially overlaps.

## What This Changes

The issue requests a new internal `session:end` hook event that fires when an agent session completes so external workflows can react without agent-authored cleanup commands.

## Best Possible Solution

Make an explicit maintainer API decision: either add and document a typed internal `session:end` event with completion-path coverage, or document plugin `session_end` as the supported workflow-integration surface and close this internal-hook request afterward.

## Reproduction Assessment

Yes. Source inspection reproduces the API gap: current internal hook docs and typed guards do not include `session:end`, while the existing `session_end` lifecycle hook is a separate plugin surface.

## Solution Assessment

Unclear. A narrow internal event could solve the requested operator-hook workflow, but the maintainable endpoint needs maintainer direction to avoid duplicating or confusing the plugin lifecycle hook contract.
