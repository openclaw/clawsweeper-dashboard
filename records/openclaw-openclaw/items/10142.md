## Summary

Keep open: current main still does not provide the requested internal `session:end` HOOK.md event, while the existing `session_end` support is a separate typed plugin hook and the open linked PR only covers related daily/idle reset hook behavior.

## What This Changes

Request adding an internal `session:end` hook event that fires when an agent session completes so external workflow systems can be signaled without agent-authored cleanup commands.

## Best Possible Solution

Maintainers should choose the supported lifecycle contract, then either add and document a narrow internal `session:end` event across the relevant completion paths or explicitly document typed plugin `session_end` as the supported integration surface.

## Reproduction Assessment

Yes, at source level: current main exposes `session:patch` internally and typed plugin `session_end`, but no documented or typed internal `session:end` event exists.

## Solution Assessment

Unclear. Adding an internal event is plausible, but the existing typed plugin `session_end` surface may be the cleaner owner, so maintainers should decide the supported contract before implementation.
