## Summary

Keep open: current main still lacks the requested internal `session:end` HOOK.md event, while the existing `session_end` lifecycle surface is a separate typed plugin hook and https://github.com/openclaw/openclaw/pull/61675 remains an open partial reset-hook candidate.

## What This Changes

Request to add an internal `session:end` hook event that fires when a session completes so operator hooks can signal external workflow systems.

## Best Possible Solution

Maintainers should choose and document the supported lifecycle contract: add a narrow internal `session:end` event with completion-path tests, or explicitly bless typed plugin `session_end` as the supported replacement in internal hook guidance.

## Reproduction Assessment

Yes, at source level: current main exposes `session:patch` internally and `session_end` as a typed plugin hook, but no documented or typed internal `session:end` event exists.

## Solution Assessment

Unclear. Adding an internal event is plausible, but the existing typed plugin `session_end` surface may be the better owner, so maintainers should decide the supported hook contract before implementation.
