## Summary

Keep open: current main still has typed plugin `session_end` lifecycle hooks, but it does not expose the requested internal `session:end` HOOK.md event, and the linked implementation work is still open/partial rather than a merged fix.

## What This Changes

The issue requests a new internal `session:end` hook event that fires when an OpenClaw agent session completes so workflow orchestrators can react without agent-authored CLI workarounds.

## Best Possible Solution

Keep the issue open until maintainers either land a supported internal session completion hook or explicitly document the typed plugin `session_end` hook as the intended replacement for this use case.

## Reproduction Assessment

Yes, at source level: current main exposes `session:patch` and compaction internal hooks plus typed plugin `session_end`, but no internal `session:end` event type, guard, docs entry, or dispatch path. I did not run a live hook because the absence is directly visible in source and docs.

## Solution Assessment

Unclear pending maintainer direction. Adding `session:end` directly matches the request, but OpenClaw policy and VISION may prefer documenting or extending the typed plugin hook surface if that is the intended lifecycle API.
