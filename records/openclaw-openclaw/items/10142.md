## Summary

Keep open: current main and the latest release still lack the requested internal `session:end` HOOK.md event, and the open linked PR is only a partial reset-hook candidate rather than a merged implementation of this API surface.

## What This Changes

Request to add an internal `session:end` hook event so operator hooks can react when an agent session completes without relying on agent-authored CLI commands.

## Best Possible Solution

Maintainers should decide whether internal HOOK.md automation gets a first-class `session:end` event or whether the typed plugin `session_end` hook is the supported replacement, then update code and docs consistently.

## Reproduction Assessment

## Solution Assessment

Unclear: adding an internal event is plausible, but the repo already has a typed plugin `session_end` hook, so maintainers need to choose the permanent supported surface before implementation.
