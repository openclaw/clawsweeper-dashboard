## Summary

Keep open: current main still lacks the requested typed/documented internal `session:end` HOOK.md event; the existing lifecycle surface is the separate typed plugin `session_end` hook, and the open linked PR is an unmerged partial reset-hook candidate.

## What This Changes

Add a `session:end` internal hook event that fires when a session completes so external workflow systems can react without agent-authored workaround commands.

## Best Possible Solution

Maintainers should choose and document the supported lifecycle contract: either add a narrow internal `session:end` event with tests across completion paths, or declare typed plugin `session_end` the supported replacement and update internal hook guidance accordingly.

## Reproduction Assessment

Yes, at source level: current main exposes internal `session:patch` and command/reset hooks plus typed plugin `session_end`, but no typed or documented internal `session:end` event exists. I did not run runtime tests because this is a read-only review.

## Solution Assessment

Unclear. Adding an internal event is plausible for HOOK.md automation, but the existing typed plugin `session_end` surface may be the cleaner supported contract, so maintainers should decide the supported lifecycle hook API before implementation.
