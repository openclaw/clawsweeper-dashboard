## Summary

Keep open: current main and the latest release still lack the requested internal `session:end` hook event. The existing `session_end` support is a separate typed plugin hook, and the open linked implementation candidate is unmerged and explicitly avoids adding a new hook event name.

## What This Changes

Add an internal `session:end` hook event that fires when a session completes so workflow orchestration systems can react without agent-authored cleanup commands.

## Best Possible Solution

Maintainers should choose and document the supported contract: either add a narrow internal `session:end` event across completion paths, or explicitly route workflow integrations to the typed plugin `session_end` hook and close or retarget the open candidate PR.

## Reproduction Assessment

Yes. Source inspection on current main reproduces the gap: internal hooks expose `session:patch` and other events, while session completion is only exposed through the separate typed plugin `session_end` surface.

## Solution Assessment

Unclear. Adding an internal event is plausible, but the existing typed plugin `session_end` hook may be the better owner, so maintainers should decide and document the supported contract before implementation.
