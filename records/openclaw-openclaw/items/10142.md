## What This Changes

Request adding a `session:end` internal hook event that fires when a session completes for workflow orchestration integrations.

## Best Possible Solution

Maintainers should choose and document the supported lifecycle contract: add a narrow internal `session:end` event with coverage across completion paths, or declare typed plugin `session_end` the supported replacement in the internal hook guidance.

## Reproduction Assessment

Yes, at source level: current main exposes `session:patch` internally and `session_end` as a typed plugin hook, but no documented or typed internal `session:end` event exists.

## Solution Assessment

Unclear. Adding an internal event is plausible for HOOK.md automation, but the existing typed plugin `session_end` surface may be the cleaner owner, so maintainers should decide the supported lifecycle hook contract before implementation.
