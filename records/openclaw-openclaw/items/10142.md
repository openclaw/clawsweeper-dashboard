## Summary

Keep open: current main and the latest release still lack the requested internal `session:end` HOOK.md event. The typed plugin `session_end` lifecycle hook is real but separate, and the open linked implementation candidate does not settle the internal-hook product/API decision.

## What This Changes

Add an internal `session:end` hook event that fires when a session completes so workflow orchestrators can react without agent-authored command workarounds.

## Best Possible Solution

Maintainers should choose and document the supported lifecycle contract: add a narrow internal `session:end` event with completion-path coverage, or explicitly bless typed plugin `session_end` as the replacement in internal hook guidance.

## Reproduction Assessment

Yes, at source level: current main exposes internal session patch/compaction hooks and a typed plugin `session_end` hook, but no documented or typed internal `session:end` event exists.

## Solution Assessment

Unclear. Adding an internal event is plausible for HOOK.md automation, but the existing typed plugin `session_end` surface may be the cleaner owner, so maintainers should decide the supported lifecycle hook contract before implementation.
