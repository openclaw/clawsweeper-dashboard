## Summary

Keep open: current main still lacks the requested internal `session:end` HOOK.md event, while the existing `session_end` implementation is a separate typed plugin hook and the open linked PR only covers a partial daily/idle reset hook path.

## What This Changes

Request to add a `session:end` internal hook event that fires when a session completes so external workflow orchestration can react without agent-authored cleanup commands.

## Best Possible Solution

Maintainers should choose and document the supported contract: either add a narrow internal `session:end` event with tests across completion paths, or declare typed plugin `session_end` the supported replacement and update internal hook guidance accordingly.

## Reproduction Assessment

Yes, at source level: current main exposes `session:patch` internally and `session_end` as a typed plugin hook, but no documented or typed internal `session:end` event exists.

## Solution Assessment

Unclear. Adding an internal event is plausible for HOOK.md automation, but the existing typed plugin `session_end` surface may be the cleaner owner, so maintainers should decide the supported lifecycle hook contract before implementation.
