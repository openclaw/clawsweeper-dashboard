## Summary

Keep open: current main and the latest release still lack the requested internal `session:end` HOOK.md event. The typed plugin `session_end` surface now covers several lifecycle cases, but it is a separate plugin API, and the linked open implementation candidate is still unresolved rather than a merged fix.

## What This Changes

Request to add an internal `session:end` hook event that fires when an OpenClaw session completes so external orchestrators can react without agent-instruction workarounds.

## Best Possible Solution

Maintainers should either define and document the internal `session:end` contract across the relevant completion paths, or explicitly document typed plugin `session_end` as the supported replacement and close the linked partial PRs accordingly.

## Reproduction Assessment

Yes, at source level: current main’s internal hook docs and types include `session:patch` but no `session:end`, while the available `session_end` implementation is a typed plugin hook. I did not run a live session because the absence of the requested internal event is directly visible in source and docs.

## Solution Assessment

Unclear: adding a core internal event is plausible, but VISION.md and plugin docs suggest runtime lifecycle integrations may belong on the typed plugin hook surface. The best path needs maintainer confirmation of whether internal HOOK.md scripts should gain this lifecycle event or plugin `session_end` should be the documented replacement.
