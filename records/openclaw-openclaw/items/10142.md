## Summary

Keep open: current main still lacks the requested internal `session:end` hook event. The existing typed plugin `session_end` hook is real, but the docs and source keep it on the plugin lifecycle surface, while the only open linked PR is a partial reset-hook candidate rather than a merged implementation of the requested internal event.

## What This Changes

Add an internal `session:end` hook event that fires when an agent session completes so external workflow systems can react without agent-authored cleanup commands.

## Best Possible Solution

Keep this issue open until maintainers either land a direct internal `session:end` design, intentionally document the typed plugin `session_end` hook as the supported replacement for workflow integrations, or narrow the issue to the reset-memory behavior covered by the linked PR.

## Reproduction Assessment

Yes at source level: current main documents and types `session:patch` for internal hooks and `session_end` for plugin hooks, but no internal `session:end` event is defined or dispatched. This is a feature gap rather than a failing existing contract.

## Solution Assessment

Unclear as a final product direction: adding a typed internal `session:end` event is a plausible narrow solution, but maintainers need to decide whether the existing typed plugin `session_end` hook should instead be the supported workflow integration surface.
