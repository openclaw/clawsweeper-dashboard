## Summary

Keep open: current main and the latest release still lack the requested internal `session:end` hook event, while the existing `session_end` support is a separate typed plugin hook and the open linked PR only partially overlaps the requested contract.

## What This Changes

Requested an internal `session:end` hook event that fires when an agent session completes so external workflow systems can react without agent-instruction workarounds.

## Best Possible Solution

Maintainers should choose and document one supported session-completion contract: either add a narrow internal `session:end` event with coverage across completion paths, or explicitly route workflow integrations to the typed plugin `session_end` hook.

## Reproduction Assessment

Yes, at source level: current main still lacks a documented internal `session:end` event while exposing session completion through the separate typed plugin `session_end` surface.

## Solution Assessment

Unclear. Adding an internal event is plausible, but the existing typed plugin `session_end` hook may be the better owner, so maintainers should decide and document the supported contract first.
