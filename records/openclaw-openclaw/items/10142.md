## Summary

Keep open: current main still lacks the requested internal `session:end` contract, while the existing typed plugin lifecycle hooks cover much of the orchestration use case without defining identical completion semantics. The linked open PR addresses daily/idle session retirement only, so maintainers must decide whether internal hooks should duplicate the plugin surface or whether plugin hooks are the supported integration boundary.

## What This Changes

Requests a typed internal `session:end` hook that signals external workflow systems when an agent session completes.

## Best Possible Solution

Standardize typed plugin hooks as the orchestration boundary: use `agent_end` or `subagent_ended` for completed work and `session_end` for persisted-session retirement, expose stable correlation fields such as `sessionKey` and `runId`, and document a ClawHub plugin pattern for signaling Temporal or similar systems.
