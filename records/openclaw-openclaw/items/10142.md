## Summary

Keep open: current main still lacks an internal `session:end` event, while the open linked PR only covers daily/idle reset hooks and does not resolve the broader task-completion contract. Maintainers must define whether session retirement and finite run completion are separate lifecycle concepts before choosing the canonical hook surface.

## What This Changes

Add an internal `session:end` hook so operator automation can react when an agent session or finite agent task completes.

## Best Possible Solution

Define persisted-session retirement and finite run completion as explicit lifecycle concepts; preferably retain typed plugin `session_end` for session retirement, add a distinct completion event for finite runs if required, and review https://github.com/openclaw/openclaw/pull/61675 independently as a reset-memory fix.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw expose finite cron, webhook, and subagent task completion as a new internal event, or redefine the existing session-end lifecycle contract to cover both task completion and persisted-session retirement?

Rationale: A session may remain reusable after an agent turn or subagent task finishes, while the existing plugin `session_end` contract represents retirement or replacement of persisted session state; source inspection cannot determine whether maintainers intend those concepts to be unified.

Likely owner: steipete

Owner reason: This account introduced and repeatedly evolved the internal hook system, giving it the clearest historical connection to the lifecycle contract decision.

Owner confidence: high

Options:

- **Separate completion event (recommended):** Keep `session_end` for persisted-session retirement and add a distinctly named internal or plugin event for finite run completion.
- **Mirror retirement internally:** Add internal `session:end` only when a persisted session is replaced, reset, compacted, or deleted, leaving task completion to another surface.
- **Broaden session end:** Define both internal and plugin session-end events to fire for cron, webhook, and subagent completion as well as persisted-session retirement.

## Reproduction Assessment

Not applicable as a failure reproduction: this is a feature request. Current source and public hook documentation provide high-confidence evidence that the requested internal event is absent.

## Solution Assessment

No, overloading `session:end` for both session retirement and finite task completion is not yet the safest solution. A distinct completion contract is narrower and avoids conflicting semantics unless maintainers explicitly choose to broaden the existing lifecycle event.
