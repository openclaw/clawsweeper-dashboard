## Summary

Keep open: current main still lacks the requested internal `session:end` HOOK.md event, and the existing `session_end` implementation is a separate typed plugin hook. The linked open PR covers daily/idle reset hook dispatch and explicitly avoids new event names, so it is only partial overlap rather than a merged fix.

## What This Changes

Request an internal `session:end` hook event that fires when a session completes so operator hooks can signal external workflow systems.

## Best Possible Solution

Maintainers should choose the supported contract: add a narrow internal `session:end` event with docs and tests across completion paths, or document typed plugin `session_end` as the supported replacement for this use case.

## Reproduction Assessment

Yes, at source level: current main exposes `session:patch` internally and `session_end` as a typed plugin hook, but no documented or typed internal `session:end` event exists.

## Solution Assessment

Unclear. Adding an internal event is plausible, but the existing typed plugin `session_end` surface may be the better contract, so maintainers should decide before implementation.
