## Summary

Keep open: current main still lacks the requested internal `session:end` HOOK.md event, while the existing `session_end` lifecycle hook is a typed plugin surface and the linked implementation work remains open/partial.

## What This Changes

Add an internal `session:end` hook event for session completion so operator hooks can signal workflow orchestrators without requiring explicit agent commands.

## Best Possible Solution

Make an explicit maintainer product decision: either add and document a narrow internal `session:end` contract across the relevant completion paths, or document typed plugin `session_end` as the supported replacement and close the linked partial work accordingly.

## Reproduction Assessment

Yes, at source level: current main documents and types internal `session:*` patch/compaction-style events but has no internal `session:end` event. I did not run a live Gateway scenario because this is a read-only review and the missing surface is visible in source/docs.

## Solution Assessment

Unclear as an implementation direction: adding `session:end` internally is plausible, but the existing typed plugin `session_end` hook covers some lifecycle use cases. Maintainers should choose the permanent internal-vs-plugin contract before more code is written.
