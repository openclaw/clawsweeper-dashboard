## What This Changes

Request to add an internal `session:end` hook event for session completion so orchestration workflows can react without agent-authored command workarounds.

## Best Possible Solution

Maintainers should choose and document the supported lifecycle contract: either add a narrow internal `session:end` event with completion-path coverage, or explicitly bless typed plugin `session_end` as the supported replacement in internal hook guidance.

## Reproduction Assessment

Yes, at source level: current `main` exposes internal session patch/compaction hooks and a typed plugin `session_end` hook, but no documented or typed internal `session:end` event exists.

## Solution Assessment

Unclear. Adding an internal event is plausible for HOOK.md automation, but the existing typed plugin `session_end` surface may be the cleaner owner, so maintainers should decide the supported lifecycle hook contract before implementation.
