## Summary

Keep open: current main still has no internal `session:end` event, and the live linked PR covers lazy daily/idle reset hooks rather than the requested general completion contract; maintainers need to choose whether this belongs in internal hooks or the typed plugin lifecycle API.

## What This Changes

Request an internal `session:end` hook that fires when an agent session completes so external workflow orchestrators can continue without agent-authored cleanup commands.

## Best Possible Solution

Establish one canonical lifecycle contract: use typed `agent_end` for completed runs and `session_end` for persisted-session retirement, documenting those plugin hooks for orchestration, or add a distinctly named internal event only if operator-installed HOOK.md automation must receive the same lifecycle signal.
