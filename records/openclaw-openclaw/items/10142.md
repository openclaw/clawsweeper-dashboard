## Summary

Keep open: current main and the latest release still lack the requested internal `session:end` hook; the existing `session_end` support is a typed plugin hook, and the linked open PR is only a partial daily/idle reset hook candidate.

## What This Changes

Add a `session:end` internal hook event that fires when an agent session completes so external workflow orchestration can react without agent-authored cleanup commands.

## Best Possible Solution

Maintainers should choose the supported contract: add and document a narrow internal `session:end` event across completion paths, or explicitly document typed plugin `session_end` as the replacement for this workflow.

## Reproduction Assessment

Yes, at source level: current main and the latest release expose `session:patch` internally and `session_end` as a typed plugin hook, but no documented or typed internal `session:end` event exists.

## Solution Assessment

Unclear. Adding the internal event is plausible, but the existing typed plugin `session_end` surface may be the better owner, so maintainers should decide the supported hook contract before implementation.
