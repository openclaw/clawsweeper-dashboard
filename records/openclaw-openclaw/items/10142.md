## Summary

Keep open: current `main` and the latest release still lack the requested internal `session:end` HOOK.md event. The typed plugin `session_end` lifecycle hook is real and well documented, but treating that as the replacement for operator-installed internal hooks needs maintainer product/API direction, especially with the linked reset-hook PR still open and conflicting.

## What This Changes

The issue requests a new internal `session:end` hook event that fires when an agent session completes for workflow orchestration integrations.

## Best Possible Solution

Make an explicit maintainer decision: either add and document a typed internal `session:end` event with focused completion-path tests, or document that plugin `session_end` is the supported replacement for workflow integrations and close the remaining internal-hook request.

## Reproduction Assessment

Yes. Source inspection reproduces the API gap: current internal hook docs and typed guards do not include `session:end`, while the existing `session_end` lifecycle hook is a separate plugin surface.

## Solution Assessment

Unclear. A narrow internal event could solve the requested operator-hook workflow, but the best permanent solution needs maintainer direction to avoid duplicating or confusing the plugin lifecycle hook contract.
