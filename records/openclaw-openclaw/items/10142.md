## Summary

Keep open: current `main` and the latest release still do not expose the requested internal `session:end` HOOK.md event. OpenClaw now has a typed plugin `session_end` lifecycle hook, but the docs and code keep that as a separate plugin surface, and the live linked PR is an open partial reset/memory fix rather than a merged implementation of this request.

## What This Changes

Add an internal `session:end` hook event that fires when sessions complete so workflow orchestrators can react without agent-authored CLI commands.

## Best Possible Solution

Maintainers should choose and document the supported contract: either add a narrow internal `session:end` event with coverage across completion paths, or declare typed plugin `session_end` the supported replacement and close this request with that guidance.

## Reproduction Assessment

Yes. Source inspection on current `main` reproduces the gap: internal hooks expose `session:patch` and other events, while session completion is only exposed through the separate typed plugin `session_end` surface.

## Solution Assessment

Unclear. Adding an internal event is plausible, but the existing typed plugin `session_end` hook may be the better owner, so maintainers should decide and document the supported contract before implementation.
