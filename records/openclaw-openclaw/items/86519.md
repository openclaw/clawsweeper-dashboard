## Summary

Keep open: the issue has credible reports of duplicate visible replies, but the surviving evidence points to more than one possible delivery path, so current main cannot be treated as fixed or as one proven root cause.

## What This Changes

Repair the regression where one incoming conversation turn can produce repeated or replayed assistant replies, especially after streamed output reaches Telegram or other channel delivery paths.

## System Context

OpenClaw’s auto-reply pipeline streams model output to a channel and also produces final reply payloads for delivery and transcript state. Duplicate suppression must keep already-visible streamed text and transcript-only mirror records from becoming additional user-facing messages.

## Architecture Diagram

## Best Possible Solution

Define one shared delivery-state contract for previews, final payloads, and transcript-only mirrors, then add cross-channel regression coverage that proves exactly one visible delivery while preserving genuinely new text and unsent media.
