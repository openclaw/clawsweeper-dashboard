## Summary

Keep open: current main implements the Telegram album part, but LINE still dispatches each downloadable media event as its own turn and no narrower open item owns that remaining LINE behavior.

## What This Changes

Requested optional media batching so rapid image/media messages, especially Telegram albums and LINE image bursts, reach the agent as one combined turn.

## Best Possible Solution

Implement only after maintainer approval as a LINE-plugin-owned, opt-in media buffer keyed by account, conversation, and sender, preserving Telegram mediaGroupFlushMs and shared text debounce semantics.

## Maintainer Decision

Question: Should LINE and other channels without native album metadata get opt-in heuristic media batching, and should that live in each channel plugin or a shared channel contract?

Rationale: Automation should not choose the defaults, grouping key, flush behavior, or public config shape for delayed webhook semantics on platforms without reliable grouping metadata.

Likely owner: steipete

Owner reason: This choice crosses public config policy, shared channel semantics, and plugin ownership boundaries where Peter has the strongest history signal.

Owner confidence: high

Options:

- **LINE opt-in plugin buffer (recommended):** Add a conservative LINE plugin config key and batch only same-account, same-conversation, same-sender downloadable media with documented latency and replay behavior.
- **Shared channel contract first:** Design a media-aware channel SDK/core contract before changing LINE, accepting broader architecture and compatibility review.
- **Document unsupported heuristic batching:** Keep native Telegram album buffering only and document that channels without grouping metadata dispatch media events individually.

## Reproduction Assessment

Yes, at source level: LINE handles each downloadable media webhook event with a fresh allMedia array and immediate processMessage call. I did not run a live LINE webhook burst.

## Solution Assessment

Unclear until maintainers choose the product boundary; a LINE-owned opt-in buffer is narrower than a gateway-global batcher, but defaults and heuristic semantics need approval first.
