## Summary

Keep open: current main covers Telegram albums with `mediaGroupFlushMs`, but the broader LINE-style independent media batching request is still missing and needs maintainer product/API direction before implementation.

## What This Changes

The issue requests optional gateway-layer media buffering so rapid image/media updates from the same chat and sender flush as one agent turn.

## Best Possible Solution

Implement the remaining behavior inside the LINE plugin boundary as an opt-in media buffer scoped by account, conversation, and sender, with explicit flush semantics, docs, config schema/types, and focused tests while leaving Telegram album buffering and shared text debounce unchanged.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add opt-in LINE-style heuristic media batching in the LINE plugin, design a shared media-batching contract first, or keep native-grouping-only behavior?

Rationale: LINE has no reliable album id, and automation should not choose the public config key, default latency, grouping key, flush-on-text behavior, or plugin-versus-core ownership for delayed webhook semantics.

Likely owner: Vincent Koc

Owner reason: Recent ownership signals point to this person across the LINE handler and shared debounce paths most affected by the decision.

Owner confidence: high

Options:

- **Add LINE opt-in batching (recommended):** Add a conservative LINE plugin setting that batches only same-account, same-conversation, same-sender downloadable media with documented latency and reply-token tradeoffs.
- **Design shared contract first:** Define a media-aware channel SDK or core batching contract before changing LINE, accepting broader architecture and compatibility review.
- **Keep heuristics unsupported:** Keep native Telegram album buffering only and document that channels without grouping metadata dispatch media events individually.

## Reproduction Assessment

Yes at source level for the remaining LINE behavior: the handler builds one media-bearing context per webhook event, and the shared inbound debounce policy explicitly excludes media. I did not run a live LINE burst, so this is not a live reproduction.

## Solution Assessment

No for the requested gateway-wide shape. The narrower maintainable path is a LINE plugin feature, or a shared SDK contract only if maintainers first choose that product direction.
