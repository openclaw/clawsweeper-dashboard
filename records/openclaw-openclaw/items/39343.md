## Summary

Keep open. Current main covers the Telegram album-buffering part, but the requested LINE-style rapid media batching is still absent and needs a maintainer product/config decision before a fix lane chooses buffering semantics.

## What This Changes

Request optional buffering/coalescing for rapid inbound image/media messages so Telegram albums and LINE-style image bursts can reach the agent as one turn.

## Best Possible Solution

Choose the product boundary first, then implement any accepted remaining behavior inside the LINE plugin as opt-in same-sender media batching; keep Telegram's current `mediaGroupFlushMs` path and avoid a gateway-global batcher unless maintainers approve a shared SDK contract.

Options:

- **Keep unsupported:** Keep native Telegram media-group handling only and document that channels without reliable grouping metadata dispatch media events individually.

## Solution Assessment

Unclear until maintainers choose the product boundary. A LINE-owned opt-in buffer is the narrowest likely implementation, while a gateway-global media batcher would cross plugin ownership and config policy.
