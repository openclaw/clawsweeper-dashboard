## Label Justifications

- `P2`: The remaining work is a normal-priority channel UX improvement with a bounded LINE plugin surface and no evidence of a full runtime outage.
- `impact:session-state`: Rapid media messages can become separate agent turns instead of one intended user context, causing transcript/session context drift from the user's intended batch.
- `impact:ux-friction`: Users who send several images quickly can get multiple fragmented replies or must rely on awkward agent-layer workarounds.

## Summary

Keep open. Current main implements the Telegram album half, including configurable `mediaGroupFlushMs`, but LINE still downloads and dispatches each media webhook event as its own agent turn and has no media batching config/docs surface.

## What This Changes

Request optional media batching for rapid image/media messages so Telegram albums and LINE image bursts can be flushed as one agent turn with configurable delay.

## Best Possible Solution

Add the remaining behavior inside the LINE plugin after product approval: an opt-in media batching delay keyed by account, conversation, and sender, flushing before same-key text or non-media events into one `LineInboundContext` while preserving Telegram and text debounce behavior.
