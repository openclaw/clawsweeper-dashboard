## Summary

Keep open: current main and v2026.6.11 cover the Telegram album/config half, but LINE still downloads and dispatches each media webhook event independently with no batching config, so the remaining feature needs maintainer product direction.

## What This Changes

The issue requests an optional media batching buffer that groups rapid related images/media into one agent turn instead of separate replies.

## Best Possible Solution

Implement the remaining behavior inside the LINE plugin as an opt-in media batching buffer scoped by account, conversation, and sender, with explicit flush semantics, docs, config schema/types, and focused tests while leaving Telegram album buffering and text debounce unchanged.

Rationale: LINE has no reliable album id, and automation should not choose the public config key, default latency, grouping key, flush-on-text behavior, or plugin-versus-core ownership for delayed webhook semantics.

Owner confidence: high

Options:

- **Add LINE opt-in batching (recommended):** Add a conservative LINE plugin setting that batches only same-account, same-conversation, same-sender downloadable media with documented latency and reply-token tradeoffs.
- **Design shared contract first:** Define a media-aware channel SDK/core batching contract before changing LINE, accepting broader architecture and compatibility review.
- **Keep heuristics unsupported:** Keep native Telegram album buffering only and document that channels without grouping metadata dispatch media events individually.

## Reproduction Assessment

Yes, at source level for the remaining LINE behavior: the handler builds and dispatches one media-bearing context per webhook event, and shared inbound debounce explicitly excludes media. I did not run a live LINE burst, so this is not a high-confidence live reproduction.

## Solution Assessment

No for the requested gateway-wide shape. The maintainable path is a LINE plugin feature that uses LINE imageSet metadata when available and only falls back to a scoped timing heuristic if maintainers approve the config surface.
