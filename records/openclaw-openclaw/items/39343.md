## Summary

Keep open. Current main covers the Telegram album/config half and text-only inbound debounce, but LINE media webhook events still dispatch one message at a time with no same-sender media buffer, so the remaining behavior is a real feature/config decision rather than conservative cleanup.

## What This Changes

The issue requests optional media batching so rapid image/media messages, using Telegram media_group_id or LINE sender/chat/time proximity, flush as one agent turn.

## Best Possible Solution

Choose a plugin-owned, opt-in LINE media batching design that buffers downloadable media by account, conversation, and sender while leaving Telegram mediaGroupFlushMs and shared text debounce unchanged.

## Maintainer Decision

Kind: product_direction

Question: Should channels without native grouping metadata, starting with LINE, support opt-in same-sender media batching, or should OpenClaw keep only native/explicit grouping such as Telegram media_group_id?

Rationale: The remaining behavior adds delayed webhook semantics and a public config surface for platforms without reliable album ids, so automation should not choose defaults, batching keys, or flush policy.

Likely owner: steipete

Owner reason: This is mainly a product/config-boundary decision, and steipete has the strongest cross-channel media/config history in the reviewed evidence.

Owner confidence: medium

Options:

- **Add LINE opt-in batching (recommended):** Add a conservative LINE plugin option that batches only same-account, same-conversation, same-sender downloadable media with documented latency and reply-token tradeoffs.
- **Design shared contract first:** Define a media-aware channel SDK/core contract before changing LINE, accepting broader architecture and compatibility review.
- **Do not support heuristic batching:** Keep native Telegram album buffering only and document that channels without grouping metadata dispatch media events individually.

Yes, source-level. LINE handles each downloadable media webhook event with a fresh allMedia array and no same-sender buffer; I did not run a live LINE webhook burst.

## Solution Assessment

Unclear until maintainers choose the product boundary. A LINE-owned opt-in buffer looks narrower than a gateway-global batcher, but defaults and heuristic semantics need approval first.
