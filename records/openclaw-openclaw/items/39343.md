## Summary

Keep open. Current main and v2026.6.11 already cover Telegram albums with `mediaGroupFlushMs`, but LINE still handles each downloadable media webhook event as its own immediate turn, so the remaining request needs maintainer product/config direction rather than cleanup closure.

## What This Changes

The issue requests an optional media batching buffer that coalesces rapid multi-image/media messages, especially Telegram albums and LINE image bursts, into one agent turn.

## Best Possible Solution

Choose the product boundary first, then implement any accepted remaining behavior inside the LINE plugin as opt-in media batching; keep Telegram's existing `mediaGroupFlushMs` path and avoid a gateway-global batcher unless maintainers approve a shared SDK contract.

Question: Should rapid media bursts on channels without native grouping metadata be supported as LINE-specific opt-in batching, designed as a shared channel SDK contract, or intentionally left unsupported?

Rationale: The remaining work adds delayed webhook semantics, a new config/default surface, and heuristic grouping for a channel without a reliable native album id, so automation should not choose the product boundary or defaults.

Likely owner: steipete

Owner confidence: medium

Options:

- **LINE opt-in batching (recommended):** Add a conservative LINE plugin config key and batch same-account, same-conversation, same-sender downloadable media with documented latency and reply-token tradeoffs.
- **Shared channel contract:** Design a media-aware channel SDK/core contract first, accepting broader architecture and compatibility review before changing LINE behavior.
- **Keep unsupported:** Keep Telegram's native media-group handling only and document that channels without reliable grouping metadata dispatch media events individually.

## Reproduction Assessment

Yes, at source level. Current main handles each downloadable LINE media event with a fresh `allMedia` array and immediate `processMessage`, though I did not run a live LINE webhook burst.

## Solution Assessment

Unclear until maintainers choose the product boundary. A LINE-owned opt-in buffer is the narrowest likely implementation, while a gateway-global media batcher would cut across plugin ownership and config policy.
