## Summary

Keep open. Current main implements the Telegram album/config slice, but the broader media-aware batching request is not fully solved: shared inbound debounce still excludes media and LINE still builds and dispatches one media event per agent turn with no batching key, delay setting, or docs surface.

## What This Changes

Request to buffer rapid media updates, especially Telegram albums and LINE image bursts, so one agent turn receives all related media instead of separate replies.

## Best Possible Solution

Keep this as the canonical media-aware batching tracker and resolve the remaining behavior inside channel/plugin boundaries, starting with an opt-in LINE media buffer or a maintainer-approved shared SDK helper rather than an unbounded gateway-layer buffer.

Rationale: The source gap is clear, but the fix adds new user-visible buffering behavior and likely a config surface, and the repository policy keeps channel behavior plugin-owned unless maintainers choose to expand the shared contract.

Owner confidence: high

Options:

- **LINE-owned opt-in buffer (recommended):** Add a LINE plugin setting for same-account/conversation/sender media batching, keep shared text debounce unchanged, and validate reply-token fallback plus docs.
- **Shared media-aware debounce contract:** Expand the shared inbound debounce/plugin SDK contract so several channels can batch media, accepting a broader compatibility and test surface.
- **Document as unsupported:** Leave heuristic media batching disabled for channels without grouping metadata and document that media/attachments dispatch immediately.

## Reproduction Assessment

Yes, at source level. Current LINE code builds and dispatches one media-bearing context per webhook message, while the shared debounce path intentionally excludes media/attachments.

## Solution Assessment

No for the exact gateway-layer proposal. The maintainable direction is a channel/plugin-owned media buffer or an explicitly approved shared SDK contract, because global gateway buffering would cross channel ownership and config boundaries.
