## Summary

Keep open. Current main and the latest release cover Telegram album buffering and fixed text-only inbound debounce, but LINE still processes rapid media webhook events one at a time, so the remaining request needs maintainer product/config direction rather than cleanup closure.

## What This Changes

The issue requests optional media/image batching so rapid related channel media is delivered to the agent as one coherent turn instead of separate replies.

## Best Possible Solution

Choose a plugin-owned, opt-in LINE media batching contract that buffers downloadable media by account, conversation, and sender while leaving Telegram mediaGroupFlushMs and generic text debounce unchanged.

Unclear until maintainers choose the product boundary. A LINE-owned opt-in buffer looks narrower than a gateway-global batcher, but defaults and heuristic semantics need approval first.
