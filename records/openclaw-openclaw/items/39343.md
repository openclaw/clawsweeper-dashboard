## Summary

Keep open: Telegram album buffering is now implemented, but current main and the latest release still process LINE media webhooks one message at a time, so the remaining request needs maintainer product/config direction rather than cleanup closure.

## What This Changes

The issue requests gateway-level buffering that batches rapid media messages into one agent turn, using Telegram media group IDs where available and heuristics for channels such as LINE.

## Best Possible Solution

Keep the Telegram album implementation, then approve an opt-in plugin-owned media batching path for LINE-style channels with explicit batching keys, flush behavior, latency defaults, docs, and tests.

Question: Should channels without native grouping metadata, starting with LINE, get opt-in same-sender media batching, a broader shared channel batching contract, or no heuristic media batching support?

Rationale: LINE has no reliable album id, and automation should not choose the default latency, grouping key, flush-on-text behavior, or plugin-versus-core ownership for a public config change.

Likely owner: steipete

Owner confidence: medium

Options:

- **Add LINE opt-in batching (recommended):** Add a conservative LINE plugin config key and batch only same-account, same-conversation, same-sender downloadable media with documented latency and reply-token tradeoffs.
- **Design a shared contract first:** Define a media-aware channel SDK/core contract before changing LINE, accepting broader architecture and compatibility review.
- **Keep heuristic batching unsupported:** Keep native Telegram album buffering only and document that channels without grouping metadata dispatch media events individually.

## Reproduction Assessment

Yes, at source level: LINE still builds and dispatches a fresh inbound context per downloadable media webhook event, while shared inbound debounce explicitly excludes media. I did not run a live LINE burst, so this is not a high-confidence live reproduction.

## Solution Assessment

Unclear until maintainers choose the product boundary. A LINE-owned opt-in buffer is narrower than a gateway-global batcher, but defaults, grouping keys, and flush semantics need approval first.
