## Summary

Keep open: current main and the latest release cover Telegram album buffering and shared text-only inbound debounce, but the requested media-aware batching remains unresolved for LINE-style independent media events and needs maintainer direction on the plugin/API/config boundary.

## What This Changes

The issue requests optional media-aware batching so rapid image/file events and nearby text are delivered as one coherent conversation turn instead of separate replies.

## Best Possible Solution

Keep the Telegram-specific implementation and approve an opt-in media-aware batching contract, preferably plugin-owned for LINE and similar channels unless maintainers choose a shared SDK/gateway seam.
