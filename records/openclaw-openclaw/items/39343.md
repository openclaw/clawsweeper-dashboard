## Summary

Keep open: current main and v2026.6.11 cover Telegram media groups and text-only inbound debounce, but the remaining LINE/media-batching behavior is still absent and needs maintainer product/config direction before implementation.

## What This Changes

The issue requests optional gateway-layer media batching so rapid images from channels such as LINE or Telegram albums arrive as one agent turn instead of separate replies.

## Best Possible Solution

Implement only after maintainer approval as a LINE-plugin-owned, opt-in media buffer scoped by account, conversation, and sender; keep Telegram mediaGroupFlushMs and shared text-only debounce unchanged.

## Maintainer Decision

Question: Should channels without native grouping metadata, starting with LINE, get opt-in same-sender media batching, a broader shared channel contract, or no heuristic batching support?

Rationale: The remaining behavior adds delayed webhook semantics and public configuration for platforms without a reliable album id, so automation should not choose defaults, keying, flush behavior, or plugin-vs-core ownership.

Likely owner: steipete

Owner confidence: high

Options:

- **LINE opt-in batching (recommended):** Add a conservative LINE plugin config key and batch only same-account, same-conversation, same-sender downloadable media with documented latency and reply-token tradeoffs.
- **Shared channel contract first:** Design a media-aware channel SDK/core contract before changing LINE, accepting broader architecture and compatibility review.
- **Keep unsupported:** Keep native Telegram album buffering only and document that channels without grouping metadata dispatch media events individually.

## Reproduction Assessment

Yes, at source level: LINE handles each downloadable media webhook event with a fresh allMedia array and no same-sender buffer. I did not run a live LINE webhook burst.

## Solution Assessment

Unclear until maintainers choose the product boundary. A LINE-owned opt-in buffer is narrower than a gateway-global batcher, but defaults and heuristic semantics need approval first.
