## Summary

Keep open: current main and v2026.6.11 cover Telegram album buffering and text-only inbound debounce, but independent LINE-style media events still become separate immediate agent turns and the remaining feature needs a product/API boundary decision.

## What This Changes

Request to add optional media batching so rapid image/media events from the same chat and sender can be delivered as one agent turn.

## Best Possible Solution

Keep the existing Telegram album path, then implement an opt-in media-aware batching contract in the owning channel plugin first, with a shared SDK seam only if plugin-local implementation exposes a real duplicated contract.
