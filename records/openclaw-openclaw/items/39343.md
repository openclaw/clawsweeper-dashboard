## Summary

Keep open: current main and v2026.6.11 cover the Telegram album/config portion, but LINE still handles each media webhook event as its own agent turn with no media batching config, so the remaining request needs maintainer product direction.

## What This Changes

The issue requests optional media batching so rapid image/media updates are buffered and delivered as one agent turn, using Telegram album metadata when available and LINE same-sender timing heuristics otherwise.

## Best Possible Solution

Implement the remaining behavior inside the LINE plugin as an opt-in media batching buffer keyed by account, conversation, and sender, with explicit flush semantics, docs, config schema/types, and focused tests while leaving Telegram album buffering and shared text debounce unchanged.
