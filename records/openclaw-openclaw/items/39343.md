## Summary

Keep open: current main implements Telegram album grouping and its flush config, but the broader media-aware batching request still is not implemented for LINE-style independent media events and needs a maintainer product/API boundary choice.

## What This Changes

The issue requests optional gateway or channel-layer buffering that batches rapid media messages from the same chat/sender into one agent turn, with Telegram using media group ids and LINE using time proximity.

## Best Possible Solution

Keep the current Telegram album implementation, then approve an opt-in media-aware batching design, preferably plugin-owned for LINE-style channels unless maintainers choose a shared SDK/gateway coalescing contract.
