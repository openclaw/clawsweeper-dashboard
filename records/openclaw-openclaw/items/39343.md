## Summary

Keep open: current main and the latest release cover Telegram media groups, but LINE-style independent media events still process one webhook message at a time and the remaining media-aware batching request needs maintainer product/API direction before implementation.

## What This Changes

The issue requests optional gateway-layer media batching so rapid image/media messages from the same sender can flush as one agent turn, with Telegram using media group metadata and LINE-style channels using sender/chat/time proximity.

## Best Possible Solution

Approve an opt-in media-aware batching contract, preferably plugin-owned for LINE/WhatsApp-style channels first, while keeping existing Telegram media-group handling and shared text-only debounce semantics intact.

## Maintainer Decision

Options:

- **Plugin-owned opt-in buffers (recommended):** Implement sender/conversation-scoped media buffers in affected channel plugins first, adding shared SDK helpers only when duplication becomes concrete.
- **Generic SDK/gateway coalescer:** Design a broader typed media coalescing contract before implementation, accepting a larger compatibility and ownership review.
- **Defer broad batching:** Keep text debounce plus Telegram album handling as the supported behavior and fix only narrower channel bugs such as WhatsApp steer media loss.

## Reproduction Assessment

Yes, source-level. Current main and v2026.6.11 still exclude media-bearing events from shared inbound debounce, and LINE still processes each downloadable media event as its own immediate turn.

## Solution Assessment

Unclear as requested. Telegram-specific album buffering is already in the right plugin owner, but LINE-style proximity batching needs a maintainer choice on plugin versus shared SDK/gateway ownership and public config shape.
