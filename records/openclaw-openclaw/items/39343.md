## Summary

Keep open: current main and the latest release cover Telegram album buffering and text-only inbound debounce, but they still do not implement LINE-style independent media batching; the remaining work changes channel latency, config, and plugin/core ownership, so it needs maintainer product direction.

## What This Changes

The issue requests optional gateway-layer buffering that batches rapid media messages into one agent turn, using Telegram media_group_id where available and time/sender heuristics for channels such as LINE.

## Best Possible Solution

Choose an opt-in plugin-owned media batching contract for LINE-like independent media events, preserving Telegram album buffering and shared text-only debounce unless maintainers explicitly approve a shared SDK/gateway seam.

- **Defer broad batching:** Keep text debounce and Telegram album support as the supported behavior for now, and handle only narrower channel bugs such as WhatsApp media loss through their own trackers.

## Solution Assessment
