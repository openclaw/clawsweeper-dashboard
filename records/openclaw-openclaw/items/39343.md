## Summary

Keep open: current main and v2026.6.11 cover Telegram album buffering, but the broader media-aware batching request remains unresolved for LINE-style independent media events and still needs maintainer product/API direction.

## What This Changes

The issue requests optional gateway-layer buffering for rapid image/media messages so related media can be delivered to the agent as one turn.

## Best Possible Solution

Approve an opt-in media-aware batching contract, preferably per affected channel/plugin first, and only promote a shared SDK/gateway seam after media metadata, batching keys, and flush semantics are explicit.

Options:

- **Approve plugin-owned media batching (recommended):** Implement an opt-in sender/conversation-scoped buffer in the affected channel plugin first, reusing shared helpers only where the media contract is clear.
- **Design a generic coalescer:** Create a broader channel SDK or gateway media coalescing contract before implementing channel-specific behavior, accepting a larger compatibility review.
- **Defer broad batching:** Keep current text debounce and Telegram album handling as supported behavior while handling only narrow channel bugs such as the open WhatsApp steer-media issue.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 still exclude media-bearing messages from shared inbound debounce, and LINE still processes each downloadable media event as its own immediate turn; I did not run a live LINE or WhatsApp scenario in this read-only review.

## Solution Assessment

No as written. A gateway-layer buffer is not clearly the best owner boundary under the plugin policy; a plugin-owned opt-in buffer is the safer first direction unless maintainers decide a generic SDK/gateway seam is needed.
