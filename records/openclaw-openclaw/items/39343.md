## Summary

Keep open: Telegram album buffering and flush config are implemented, but current main and v2026.6.11 still process LINE media webhook events one at a time, so the remaining LINE-style batching request needs maintainer product/config direction.

## What This Changes

The issue requests optional media batching so rapid image updates from Telegram or LINE are buffered and delivered as one agent turn.

## Best Possible Solution

Keep the Telegram album implementation and approve an opt-in LINE plugin media batching path with explicit keys, flush behavior, latency defaults, docs, and focused tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should LINE-style channels without native grouping metadata get opt-in same-sender media batching, a broader shared channel batching contract, or no heuristic media batching support?

Rationale: LINE has no reliable album id, and automation should not choose the default latency, grouping key, flush-on-text behavior, or plugin-versus-core ownership for a public config change.

Likely owner: steipete

Owner reason: This decision is primarily about shared inbound semantics and public config/product policy, where the shared debounce history points most strongly to this owner.

Owner confidence: medium

Options:

- **Add LINE opt-in batching (recommended):** Add a conservative LINE plugin config key and batch only same-account, same-conversation, same-sender downloadable media with documented latency and reply-token tradeoffs.
- **Design shared contract first:** Define a media-aware channel SDK/core batching contract before changing LINE, accepting broader architecture and compatibility review.
- **Keep heuristics unsupported:** Keep native Telegram album buffering only and document that channels without grouping metadata dispatch media events individually.

## Reproduction Assessment

Yes, at source level: LINE still builds and dispatches a fresh inbound context per downloadable media webhook event, while shared inbound debounce explicitly excludes media. I did not run a live LINE burst, so this is not a high-confidence live reproduction.

## Solution Assessment

Unclear until maintainers choose the product boundary. A LINE-owned opt-in buffer is narrower than a gateway-global batcher, but defaults, grouping keys, and flush semantics need approval first.
