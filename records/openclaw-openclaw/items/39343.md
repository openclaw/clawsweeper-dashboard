## Summary

Keep open: Telegram album buffering and configuration are implemented on current main and in v2026.6.11, but LINE still downloads and dispatches each media webhook event independently with no batching config, so the remaining behavior needs maintainer product direction.

## What This Changes

Request optional media batching so rapid image/media updates are delivered to the agent as one turn, using Telegram album metadata where available and LINE same-sender timing heuristics where approved.

## Best Possible Solution

Implement the remaining behavior inside the LINE plugin only if maintainers approve it: add an opt-in media batching delay keyed by account, conversation, and sender, flush predictably, aggregate into one LINE inbound context, and leave Telegram album buffering plus shared text debounce unchanged.
