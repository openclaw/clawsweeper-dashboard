## Summary

Keep open: current main covers Telegram album buffering and text-only inbound debounce, but the requested media-aware batching remains unresolved for LINE-style independent media events and still needs a product/API boundary decision before implementation.

## What This Changes

The issue requests an optional gateway-layer media batching buffer that groups rapid image/media events into one agent turn, with Telegram keyed by media_group_id and LINE keyed by sender/chat/time proximity.

## Best Possible Solution

Keep the current Telegram album implementation, then choose an opt-in media-aware batching contract, preferably plugin-owned for LINE and similar channels unless maintainers explicitly want a shared SDK/gateway seam.
