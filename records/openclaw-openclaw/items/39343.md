## Summary

Keep open. Current main has Telegram album/media-group buffering and config, but the LINE half of this request still processes each downloadable media webhook event as its own agent turn, so the remaining work needs a product decision on LINE-owned opt-in batching versus a shared channel contract.

## What This Changes

The issue requests optional media batching that groups rapid media messages, using Telegram media_group_id where available and sender/chat/time proximity for LINE, before forwarding one agent turn.

## Best Possible Solution

Choose the product boundary first, then implement any accepted remaining behavior inside the LINE plugin as an opt-in same-sender media buffer; keep Telegram's current mediaGroupFlushMs path and avoid a gateway-global batcher unless maintainers approve a shared SDK contract.
