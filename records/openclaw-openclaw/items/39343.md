## Summary

Keep open. Current main covers the Telegram album half with `mediaGroupFlushMs`, but the LINE half still processes each downloadable media webhook event as its own turn and the requested opt-in batching behavior needs a maintainer product/config decision before automation should build it.

## What This Changes

The issue requests gateway-level media batching so rapid multi-image channel updates can reach the agent as one combined turn.

## Best Possible Solution

Choose an opt-in, plugin-owned LINE media batching design if maintainers want heuristic batching; keep Telegram's existing `mediaGroupFlushMs` path and avoid a gateway-global batcher unless maintainers explicitly approve a shared SDK contract.

Options:

- **Plugin-owned LINE opt-in batching (recommended):** Add a LINE plugin config key with default-off or conservative timing, buffer only same account/conversation/sender downloadable media, and document the reply-token and latency tradeoff.

- **Keep heuristic batching unsupported:** Keep Telegram's native media-group handling only and document that LINE users should send combined media/text when no reliable grouping metadata exists.

## Solution Assessment
