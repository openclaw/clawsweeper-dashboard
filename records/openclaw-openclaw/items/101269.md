## Summary

Keep open: current main still calls `response.text()` in the no-reader fallback before applying `maxBytes`, and this issue is paired with open fixing PRs that should be reviewed before the issue closes.

## What This Changes

The issue asks OpenClaw to bound or fail closed the non-streaming `readResponseBodySnippet` fallback before any provider error body is materialized.

## Best Possible Solution

Land one narrow fix that never calls `text()` or `arrayBuffer()` for no-reader bodies before a bound is enforced, add regression tests proving those methods are not invoked, then close this issue after merge.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: pass a no-reader `Response`-like object with a large `text()` result to `readResponseBodySnippet`, and current main buffers the full text before applying `maxBytes`.

## Solution Assessment

Partly. Reusing a bounded helper is the right direction only if the no-reader helper path also avoids whole-body `text()` or `arrayBuffer()` calls; otherwise the fix only moves the unbounded read.
