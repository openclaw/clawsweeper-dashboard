## Summary

Keep open: current main still materializes the no-reader response body before enforcing the byte limit, and the linked fixing PR is open and needs review rather than pre-merge issue closure.

## What This Changes

The issue asks to bound `readResponseBodySnippet` when a response lacks a streaming reader so oversized provider error bodies cannot be fully buffered first.

## Best Possible Solution

Keep this issue open while https://github.com/openclaw/openclaw/pull/101270 is reviewed, and make the final fix bound the no-reader path before materializing the body rather than only moving the unbounded read to another helper.
