## Summary

Keep open: current main still materializes body-less/non-streaming response text before enforcing the byte limit, and the linked open PR is the active candidate but has not merged. A prior merged PR improved returned-snippet truncation, but it did not eliminate the pre-buffering failure mode this issue reports.

## What This Changes

The issue asks for readResponseBodySnippet to enforce maxBytes before buffering body-less or non-streaming responses.

## Best Possible Solution

Make the body-less fallback either genuinely bounded before buffering or explicitly treat non-streaming bodies as unavailable for snippets, then add regression coverage that fails if text() or arrayBuffer() is called before the cap.
