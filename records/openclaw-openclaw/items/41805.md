## Summary

Keep open: current main and the latest release still deliver generic Discord component clicks as text-only agent turns, while richer interaction fields are only exposed to plugin interactive handlers. The remaining work is a maintainer product/API decision for a typed agent-visible Discord interaction metadata contract.

## What This Changes

The issue requests structured Discord button/select/modal interaction metadata in generic agent callbacks, including message id, component id/custom data, label/value details, and clicker identity.

## Best Possible Solution

Define and document a typed Discord interaction metadata contract for generic agent-dispatched component callbacks, populated from the component registry plus sanitized Discord interaction fields across buttons, selects, and modals.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should generic Discord component clicks expose a new agent-visible structured interaction metadata envelope, and which fields should be public versus plugin-only?

Rationale: This changes the public agent inbound context and exposes Discord identifiers/callback data, so maintainers need to choose schema shape, compatibility behavior, privacy/security boundary, and documentation before implementation.

Likely owner: thewilloftheshadow

Owner reason: Shadow introduced the Discord component surface and related reusable/allowedUsers behavior that this API decision extends.

Owner confidence: high

Options:

- **Add Typed Agent Metadata (recommended):** Expose a narrow documented metadata envelope with message id, action kind, safe callback/custom data, label/value details, and clicker identity, backed by Discord plugin tests.
- **Keep Metadata Plugin-Only:** Leave rich interaction fields only in plugin interactive handlers and document that stateful Discord workflows should use plugin callbacks instead of generic fallback messages.
- **Start With Sender And Message:** Expose only clicker and originating message ids first, deferring callback payload semantics until a broader inbound metadata contract is settled.

## Reproduction Assessment

Yes. Source inspection of current main shows the generic Discord component callback path dispatches eventText as the agent body while richer interaction fields remain outside the generic agent-visible context.

## Solution Assessment

Unclear until maintainers choose the public contract. The durable fix should be a typed channel/inbound-context metadata API rather than an ad hoc raw Discord payload leak.
