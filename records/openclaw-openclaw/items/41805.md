## Summary

Keep open: current main and the latest release still route generic Discord component callbacks into text-only agent inbound events, while richer interaction data is available only to plugin interactive handlers. The remaining work is a maintainer product/API decision for a typed agent-visible metadata contract.

## What This Changes

The issue requests structured Discord button/select interaction metadata, including message, component, and clicker identifiers, in agent-visible callback context.

## Best Possible Solution

Define and document a narrow typed Discord interaction metadata envelope for generic component callbacks, populated from the component registry and Discord interaction payload without leaking raw transport data.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should generic Discord component clicks expose a new typed agent-visible interaction metadata envelope, and which fields should be public instead of plugin-only?

Rationale: The change would expand public inbound context and expose Discord identifiers and callback data, so maintainers need to choose the schema, compatibility shape, and trust boundary before implementation.

Likely owner: steipete

Owner reason: The active generic callback dispatch lines are currently owned by recent Discord monitor work, and this decision crosses the same Discord/plugin boundary.

Owner confidence: medium

Options:

- **Add Typed Agent Metadata (recommended):** Expose a documented minimal envelope with action kind, originating message id, safe callback/custom data, label/value details, and clicker identity, backed by Discord plugin tests.
- **Keep Metadata Plugin-Only:** Leave rich interaction fields on plugin interactive handlers and document generic callbacks as text-only fallback messages.
- **Start With Sender And Message:** Expose only clicker and originating message ids first, deferring callback payload semantics to a broader inbound metadata contract.

## Reproduction Assessment

Yes. Source inspection of current main shows the generic Discord component callback path dispatches only eventText to the agent while richer interaction fields remain plugin-only.

## Solution Assessment

Unclear until maintainers choose the public contract. The maintainable fix is a typed channel/inbound-context metadata API, not an ad hoc raw Discord payload leak.
