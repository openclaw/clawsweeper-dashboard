- `P2`: This is a normal-priority Discord interactive workflow/API improvement with limited blast radius and no evidence of a current runtime outage.

- `maturity:stable`: The affected Discord channel feature is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main still sends generic Discord component clicks to agents as normal text inbound messages, while richer interaction fields exist only on the plugin interactive-handler path. The remaining work is a public agent metadata and trust-boundary decision, not conservative cleanup.

## What This Changes

Request Discord button callbacks delivered to agents include structured interaction metadata such as originating message id, clicked component/custom id, label/value, and clicker identity.

## Best Possible Solution

Define a narrow documented Discord/channel interaction metadata contract populated from registry state and Discord interaction payload for buttons, selects, and modals, with focused tests and docs and without leaking raw Discord payloads to agents.

Options:

- **Add Typed Agent Metadata (recommended):** Expose a bounded metadata envelope with original message id, component kind, safe callback/custom data, label/value details, and clicker identity, backed by Discord plugin tests and docs.
- **Keep Rich Metadata Plugin-Only:** Leave structured fields on registered plugin interactive handlers and document that stateful Discord workflows should use plugin callbacks rather than generic fallback messages.
- **Start With Sender And Message:** Expose only clicker and originating message ids first, deferring callback payload semantics until a broader inbound metadata contract is settled.
