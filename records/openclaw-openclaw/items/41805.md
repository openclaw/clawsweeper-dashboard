- `maturity:stable`: The issue targets Discord Components v2 and callback behavior on the Discord channel surface, which qa/maturity-scores.yaml marks as M4 Stable.

## Summary

Keep open: current main and v2026.6.11 still route generic Discord component callbacks to agents as text plus ordinary sender fields, while original message/custom/click metadata is internal or plugin-handler-only. The remaining work needs a maintainer-approved inbound metadata schema and trust boundary.

## What This Changes

Expose structured Discord button interaction metadata, including originating message, clicked component, and clicker identity, to generic agent callbacks.

## Best Possible Solution

Define a narrow typed Discord interaction metadata contract for agent-dispatched component callbacks, document field semantics, and populate it from registry state plus the Discord interaction payload across buttons, selects, and modals.

Options:

- **Add Typed Agent Metadata (recommended):** Expose a documented envelope with action kind, originating message id, safe callback/custom data, selected values or label, and clicker identity, backed by Discord plugin tests.
- **Keep Metadata Plugin-Only:** Leave rich interaction fields on plugin interactive handlers and document that stateful Discord workflows should use plugin callbacks instead of generic agent fallback messages.
- **Expose Minimal Identity First:** Start with clicker and originating message ids only, deferring callback payload semantics until a broader inbound metadata contract is settled.

## Solution Assessment

Unclear until maintainers choose the public contract; the requested direction is useful, but the durable fix should be a typed inbound metadata API rather than an ad hoc raw Discord payload leak.
