## Summary

Keep open: current main still routes generic Discord component clicks to agents as text-oriented inbound turns, while richer interaction fields exist only on the plugin interactive handler path. This is a public metadata-contract and trust-boundary decision, not conservative cleanup.

## What This Changes

The issue requests structured Discord button/select callback metadata in agent inbound context, including original message, component/custom data, label/value details, and clicker identity.

## Best Possible Solution

Define a narrow documented Discord/channel interaction metadata contract populated from registry state and Discord interaction payload for buttons, selects, and modals, with tests and docs before exposing it to agents.

Options:

- **Add Typed Agent Metadata (recommended):** Expose a documented bounded metadata envelope with original message id, component kind, safe callback/custom data, label/value details, and clicker identity, backed by Discord plugin tests.
- **Keep Metadata Plugin-Only:** Leave rich interaction fields on plugin interactive handlers and document that stateful Discord workflows should use plugin callbacks rather than generic fallback messages.
- **Start With Sender And Message:** Expose only clicker and originating message ids first, deferring callback payload semantics until a broader inbound metadata contract is settled.
