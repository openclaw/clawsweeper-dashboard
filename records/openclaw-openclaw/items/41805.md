## Summary

Keep open: current main and the latest release still send generic Discord component callbacks to the agent as text plus ordinary sender context, while richer interaction fields are only exposed to plugin interactive handlers. This remains a maintainer product/API decision for a typed agent-visible Discord interaction metadata contract.

## What This Changes

Request to include structured Discord button interaction metadata such as original message id, component/custom id, button label, and clicker identity in agent callback context.

## Best Possible Solution

Define and document a typed Discord interaction metadata contract for generic agent-dispatched component callbacks, populated from the component registry plus Discord interaction payload across buttons, selects, and modals.

Options:

- **Add Typed Agent Metadata (recommended):** Expose a narrow documented metadata envelope with original message id, action kind, safe callback/custom data, label/value details, and clicker identity, backed by Discord plugin tests.
- **Keep Metadata Plugin-Only:** Leave rich interaction fields only in plugin interactive handlers and document that stateful Discord workflows should use plugin callbacks rather than generic agent fallback messages.
- **Start With Sender And Message:** Expose only clicker and originating message ids first, deferring callback payload semantics until a broader inbound metadata contract is settled.
