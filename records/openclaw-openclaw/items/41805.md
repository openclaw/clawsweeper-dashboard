## Summary

Keep open: current main and the latest release still route generic Discord component callbacks to agents as event text plus ordinary sender fields, while richer interaction details are only available to plugin interactive handlers. This needs a maintainer-owned public inbound-context contract rather than cleanup closure.

## What This Changes

The issue requests structured Discord button interaction metadata, including original message ID, component or callback ID, button label, and clicker identity, in the agent inbound context.

## Best Possible Solution

Define and document a typed Discord interaction metadata contract for generic agent-dispatched component callbacks, populated from the component registry and Discord interaction payload across buttons, selects, and modals.

Options:

- **Add Typed Agent Metadata (recommended):** Expose a narrow documented envelope with original message id, action kind, safe callback/custom data, label/value details, and clicker identity, backed by Discord plugin tests.
- **Keep Metadata Plugin-Only:** Leave rich interaction fields available only to plugin interactive handlers and document that stateful Discord workflows should use plugin callbacks rather than generic agent fallback messages.
- **Start With Message And Component IDs:** Expose only the originating message id and component id first, deferring callback payload semantics until a broader inbound metadata contract is settled.
