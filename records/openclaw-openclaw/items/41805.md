## Summary

Keep open: current main and v2026.6.11 still deliver generic Discord component callbacks to agents as text-oriented inbound turns, while richer interaction fields are only available on the plugin interactive-handler path. The remaining work is a public metadata-contract and trust-boundary decision, not conservative cleanup.

## What This Changes

The issue requests structured Discord button/select interaction metadata, including source message, clicked component, and user identity, in generic agent callbacks.

## Best Possible Solution

Define a narrow documented Discord/channel interaction metadata contract populated from registry state and Discord interaction payload for buttons, selects, and modals, with tests and docs before exposing it to agents.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should generic Discord component callbacks expose a new agent-visible structured interaction metadata envelope, and which fields should be public versus plugin-only?

Rationale: The requested change would create a public inbound-context contract and expose Discord identifiers plus callback data, so maintainers need to choose the schema, compatibility shape, and trust boundary before implementation.

Likely owner: steipete

Owner reason: This account has the strongest recent history on Discord component wiring and plugin SDK boundary decisions around this surface.

Owner confidence: high

Options:

- **Add Typed Agent Metadata (recommended):** Expose a documented bounded metadata envelope with original message id, component kind, safe callback/custom data, label/value details, and clicker identity, backed by Discord plugin tests.
- **Keep Metadata Plugin-Only:** Leave rich interaction fields on plugin interactive handlers and document that stateful Discord workflows should use plugin callbacks rather than generic fallback messages.
- **Start With Sender And Message:** Expose only clicker and originating message ids first, deferring callback payload semantics until a broader inbound metadata contract is settled.

## Reproduction Assessment

Yes, source-reproducible: current main builds generic component callbacks as `eventText` and dispatches BodyForAgent, RawBody, and CommandBody without a typed interaction metadata object. I did not run a live Discord click.

## Solution Assessment

Unclear until maintainers choose the public contract. The maintainable fix should be a typed channel/inbound interaction metadata contract, not an ad hoc raw Discord payload leak.
