## Summary

Keep open: current main and the latest release still send generic Discord component callbacks to the agent as text-only inbound turns, while richer interaction fields are only available to plugin interactive handlers. The remaining work is a maintainer product/API decision for an agent-visible Discord interaction metadata contract.

## What This Changes

Request to expose structured Discord button/select interaction metadata, including original message id, callback/custom id, label/value, and clicker identity, to agent callback context.

## Best Possible Solution

Define a typed, documented Discord interaction metadata contract for agent-dispatched component callbacks and populate it from the component registry plus Discord interaction payload across buttons, selects, and modals.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should generic Discord component clicks expose a new agent-visible structured interaction metadata envelope, and which fields should be public versus plugin-only?

Rationale: The change would alter the public agent inbound context and expose Discord identifiers/callback data, so maintainers need to choose the schema, compatibility shape, and trust boundary before implementation.

Likely owner: steipete

Owner reason: Peter Steinberger has the broadest recent history across the Discord component, plugin/channel boundary, and session/context surfaces involved in the decision.

Owner confidence: high

Options:

- **Add Typed Agent Metadata (recommended):** Expose a narrow documented envelope with message id, action kind, safe callback/custom data, label/value details, and clicker identity, backed by Discord plugin tests.
- **Keep Rich Metadata Plugin-Only:** Leave structured interaction fields on the plugin interactive-handler API and document generic agent fallback callbacks as text-only messages.
- **Ship Sender/Message First:** Expose only clicker and originating message ids initially, then defer callback payload semantics to the broader inbound metadata design.

## Reproduction Assessment

Yes, source-reproducible: the generic Discord component fallback builds an agent turn from eventText and ordinary sender/session context, while original message id, custom/callback id, and a structured interaction object are not added. I did not run a live Discord click in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract; the requested direction is useful, but the durable fix should be a typed channel/inbound-context API rather than an ad hoc raw Discord payload leak.
