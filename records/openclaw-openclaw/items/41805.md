## Summary

Keep open: current main still routes generic Discord component callbacks to agents as text-oriented inbound turns, while richer interaction fields are only exposed to plugin interactive handlers. The remaining work is a public metadata contract and trust-boundary decision, not conservative cleanup.

## What This Changes

The issue asks OpenClaw to surface structured Discord button interaction metadata, including source message, component, and clicker identity fields, to agent callbacks.

## Best Possible Solution

Define a narrow documented Discord/channel interaction metadata contract populated from registry state and Discord interaction payload for buttons, selects, and modals, with focused tests and docs.
