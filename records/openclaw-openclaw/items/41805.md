## Summary

Keep open: current main and the latest release still route generic Discord component callbacks to agents as text plus ordinary sender/conversation context, while richer interaction details are only available to plugin interactive handlers. This remains a product/API contract decision for agent-visible Discord interaction metadata.

## What This Changes

Request to include structured Discord interaction metadata, such as original message id, custom id/button identity, and clicking user, in agent-visible button callback context.

## Best Possible Solution

Define a typed, documented Discord interaction metadata contract for agent-dispatched component callbacks, populate it from the component registry and Discord interaction payload, and cover buttons/selects/modals with focused Discord plugin tests.

## Reproduction Assessment

Yes, at source level: current Discord component callbacks build the agent turn from eventText and ordinary sender/context fields, while original message id and custom interaction details are not included in the agent context. I did not run a live Discord button click in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public metadata contract; the request is useful, but the exact schema should be a typed channel/inbound-context API decision rather than an ad hoc raw Discord payload leak.
