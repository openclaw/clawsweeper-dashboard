## Summary

Keep open: current main and v2026.6.11 still send generic Discord component callbacks to the agent as event text plus ordinary sender context, while richer interaction fields are only exposed to plugin interactive handlers. This remains a maintainer product/API decision for a typed agent-visible Discord interaction metadata contract.

## What This Changes

The issue asks OpenClaw to expose structured Discord component interaction metadata, including originating message, clicked component, and clicker identity, to generic agent callbacks.

## Best Possible Solution

Define and document a typed Discord interaction metadata contract for generic agent-dispatched component callbacks, populated from the component registry plus Discord interaction payload across buttons, selects, and modals.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should generic Discord component clicks expose a new agent-visible structured interaction metadata envelope, and which fields should be public versus plugin-only?

Rationale: This changes the public agent inbound context and exposes Discord identifiers/callback data, so maintainers need to choose schema, trust boundary, and compatibility shape before implementation.

Likely owner: vincentkoc

Owner reason: Current source history most directly ties this person to the Discord component callback handler, dispatch context, and typed component boundary.

Owner confidence: high

Options:

- **Add Typed Agent Metadata (recommended):** Expose a narrow documented metadata envelope with original message id, action kind, safe callback/custom data, label/value details, and clicker identity, backed by Discord plugin tests.
- **Keep Metadata Plugin-Only:** Leave rich interaction fields only in plugin interactive handlers and document that stateful Discord workflows should use plugin callbacks rather than generic agent fallback messages.
- **Start With Sender And Message:** Expose only clicker and originating message ids first, deferring callback payload semantics until a broader inbound metadata contract is settled.

## Solution Assessment

Unclear until maintainers choose the public contract; the requested direction is useful, but the durable fix should be a typed channel/inbound-context API rather than an ad hoc raw Discord payload leak.
