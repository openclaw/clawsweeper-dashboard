## Summary

Keep open: current main and the latest release still route generic Discord component clicks to the agent as text-only inbound turns, while richer interaction fields are only available to Discord plugin interactive handlers. The remaining work is a maintainer product/API decision for an agent-visible typed interaction metadata contract.

## What This Changes

Request agent-visible structured metadata for Discord button/component callbacks, including originating message, clicked component/custom data, and clicker identity.

## Best Possible Solution

Define and document a typed Discord interaction metadata contract for generic agent-dispatched component callbacks, populated from the component registry plus sanitized Discord interaction context across buttons, selects, and modals.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should generic Discord component clicks expose a new agent-visible structured interaction metadata envelope, and which fields should be public versus plugin-only?

Rationale: This changes the public agent inbound context and exposes Discord identifiers/callback data, so maintainers need to choose schema shape, compatibility behavior, privacy/security boundary, and documentation before implementation.

Likely owner: thewilloftheshadow

Owner reason: This handle is the strongest history-backed owner for the Discord component feature surface named in the issue.

Owner confidence: high

Options:

- **Add Typed Agent Metadata (recommended):** Expose a narrow documented metadata envelope with message id, action kind, safe callback/custom data, label/value details, and clicker identity, backed by Discord plugin tests.
- **Keep Metadata Plugin-Only:** Leave rich interaction fields only in plugin interactive handlers and document that stateful Discord workflows should use plugin callbacks instead of generic fallback messages.
- **Start With Sender And Message:** Expose only clicker and originating message ids first, deferring callback payload semantics until a broader inbound metadata contract is settled.

## Reproduction Assessment

Yes, source-level. Current main converts generic Discord component callbacks into eventText and finalizes the agent context without a structured interaction metadata envelope; I did not run a live Discord click.

## Solution Assessment

Unclear until maintainers choose the public contract. The durable fix should be a typed channel/inbound-context metadata API, not an ad hoc raw Discord payload leak.
