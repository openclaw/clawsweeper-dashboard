## Summary

Keep open: current main and the latest release still convert generic Discord component callbacks into text-oriented inbound agent events, while richer interaction fields are only available on the plugin interactive handler path. The remaining work is a maintainer product/API decision for a typed agent-visible Discord interaction metadata contract.

## What This Changes

Request Discord component callbacks expose structured interaction metadata such as source message id, custom/callback id, clicked control details, and clicker identity to the agent.

## Best Possible Solution

Define and document a typed, sanitized Discord interaction metadata envelope for generic agent-dispatched component callbacks, populated from the component registry plus safe Discord interaction fields across buttons, selects, and modals.

## Maintainer Decision

Required: true

Question: Should generic Discord component clicks expose a new agent-visible structured interaction metadata envelope, and which fields should be public versus plugin-only?

Rationale: This changes the public inbound context and exposes Discord identifiers/callback data, so maintainers need to choose schema shape, compatibility behavior, privacy/security boundary, and documentation before implementation.

Likely owner: vincentkoc

Owner reason: The current handler, dispatch, plugin-interactive, and component-entry files most directly involved in the decision route through recent Vincent Koc history.

Owner confidence: high

Options:

- **Add Typed Agent Metadata (recommended):** Expose a narrow documented envelope with original message id, action kind, safe callback/custom data, label/value details, and clicker identity, backed by Discord plugin tests.
- **Keep Metadata Plugin-Only:** Leave rich interaction fields only in plugin interactive handlers and document that stateful Discord workflows should use plugin callbacks instead of generic fallback messages.
- **Start With Sender And Message:** Expose only clicker and originating message ids first, deferring callback payload semantics until a broader inbound metadata contract is settled.

## Reproduction Assessment

Yes, at source level. Current main dispatches generic Discord component callbacks as eventText and tests assert text fallback behavior; I did not run a live Discord click.

## Solution Assessment

Unclear until maintainers choose the public contract. The maintainable solution should be a typed channel/inbound metadata API, not an ad hoc raw Discord interaction payload leak.
