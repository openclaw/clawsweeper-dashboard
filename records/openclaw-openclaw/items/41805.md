## Summary

Keep open: current main and the latest release still turn generic Discord component callbacks into text-oriented inbound agent events, while richer interaction fields exist only on the plugin interactive handler path. The remaining work is a maintainer product/API decision for a typed agent-visible Discord interaction metadata contract, not a cleanup close.

## What This Changes

Request to include structured Discord button interaction metadata, such as message id, component/custom id, button label, and clicker identity, in agent-visible callback context.

## Best Possible Solution

Define and document a typed Discord interaction metadata contract for generic agent-dispatched component callbacks, populated from the component registry plus sanitized Discord interaction payload across buttons, selects, and modals.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should generic Discord component clicks expose a new agent-visible structured interaction metadata envelope, and which fields should be public versus plugin-only?

Rationale: This changes the public agent inbound context and exposes Discord identifiers and callback data, so maintainers need to choose schema shape, compatibility behavior, privacy/security boundary, and documentation before implementation.

Likely owner: vincentkoc

Owner reason: The current callback and plugin-interactive implementation lines are blamed to Vincent Koc's recent merged Discord component refactor.

Owner confidence: high

Options:

- **Add Typed Agent Metadata (recommended):** Expose a narrow documented metadata envelope with original message id, action kind, safe callback/custom data, label/value details, and clicker identity, backed by Discord plugin tests.
- **Keep Metadata Plugin-Only:** Leave rich interaction fields only in plugin interactive handlers and document that stateful Discord workflows should use plugin callbacks rather than generic fallback messages.
- **Start With Sender And Message:** Expose only clicker and originating message ids first, deferring callback payload semantics until a broader inbound metadata contract is settled.

## Reproduction Assessment

Yes. Source inspection of current main shows the generic Discord component callback path dispatches eventText as the agent body while richer interaction fields remain outside the generic agent-visible context.

## Solution Assessment

Unclear until maintainers choose the public contract. The durable fix should be a typed channel/inbound-context metadata API rather than an ad hoc raw Discord payload leak.
