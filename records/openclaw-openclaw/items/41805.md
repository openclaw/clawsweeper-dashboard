## Summary

Keep open: current main still routes generic Discord component callbacks to agents as text-oriented inbound turns, while richer interaction fields remain available only on the plugin interactive-handler path. The remaining work is a public metadata schema and trust-boundary decision, not conservative cleanup.

## What This Changes

The issue requests structured Discord button/select interaction metadata, including source message, clicked component, and clicker identity, in the generic agent callback context.

## Best Possible Solution

Define a narrow documented Discord/channel interaction metadata contract populated from registry state and Discord interaction payload for buttons, selects, and modals, with focused plugin tests and docs.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should generic Discord component callbacks expose a documented structured interaction metadata envelope to agents, or should rich interaction fields remain plugin-handler-only?

Rationale: The requested change would create a public inbound-context contract and expose Discord identifiers plus callback data, so automation should not choose the schema or trust boundary on its own.

Likely owner: steipete

Owner reason: This choice is primarily a public contract and plugin-boundary decision, and steipete has recent adjacent Discord component and metadata merge history.

Owner confidence: medium

Options:

- **Add Typed Agent Metadata (recommended):** Expose a bounded, documented metadata envelope with source message id, component kind, safe callback/custom data, label/value details, and clicker identity, backed by Discord plugin tests.
- **Keep Metadata Plugin-Only:** Leave rich interaction fields on plugin interactive handlers and document that stateful Discord workflows should use plugin callbacks rather than generic fallback messages.
- **Expose Minimal IDs First:** Expose only clicker and source message identifiers now, then defer callback payload semantics until a broader inbound metadata contract is settled.

## Reproduction Assessment

Yes, source-reproducible: current main builds generic Discord component callbacks as eventText and dispatches BodyForAgent, RawBody, and CommandBody without a typed interaction metadata object. I did not run a live Discord click.

## Solution Assessment

Unclear until maintainers choose the public contract. The maintainable fix should be a typed channel/inbound interaction metadata contract, not an ad hoc raw Discord payload leak.
