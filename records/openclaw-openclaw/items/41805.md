## Summary

Keep open: current main still sends generic Discord component callbacks to agents as text-only inbound events, while richer interaction data exists only on the plugin interactive handler path. This remains a public API and trust-boundary decision rather than conservative cleanup.

## What This Changes

Expose structured Discord button/select interaction metadata such as message id, callback/custom data, label/value details, and clicker identity to agent callbacks.

## Best Possible Solution

Define a narrow, documented Discord/channel interaction metadata contract populated from registry state and the Discord interaction payload for buttons, selects, and modals, with focused Discord tests and docs before exposing it to agents.
