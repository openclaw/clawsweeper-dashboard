## Summary

Keep open: current main and v2026.6.11 still route generic Discord component callbacks to agents as text-oriented inbound turns, while richer interaction fields are only exposed on the plugin interactive-handler path. The remaining work is a public metadata-contract and trust-boundary decision, not conservative cleanup.

## What This Changes

Request that generic Discord button/select callback turns include structured interaction metadata such as source message id, custom/callback id, button label, and clicker identity.

## Best Possible Solution

Define a narrow documented Discord/channel interaction metadata contract populated from registry state and Discord interaction payload for buttons, selects, and modals, with tests and docs before exposing it to agents.
