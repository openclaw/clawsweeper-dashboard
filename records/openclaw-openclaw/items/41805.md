## Summary

Keep open: current main and the latest release still collapse generic Discord component callbacks into text-oriented inbound turns, while richer interaction fields are only available to plugin interactive handlers. This remains a public metadata-contract and trust-boundary decision, not conservative cleanup.

## What This Changes

The issue requests structured Discord interaction metadata, including message id, component/custom id, button label, and clicker identity, in generic agent button callback context.

## Best Possible Solution

Define a narrow documented Discord/channel interaction metadata contract populated from registry state and the Discord interaction payload for buttons, selects, and modals, with focused tests and docs before exposing it to agents.

## Maintainer Decision

Question: Should generic Discord component callbacks expose a new agent-visible structured interaction metadata envelope, and which fields are public versus plugin-only?

Rationale: The request would create a public inbound-context contract and expose Discord identifiers plus callback data, so maintainers need to choose the schema, compatibility shape, and trust boundary before an implementation is safe.

Likely owner: steipete

Owner reason: This person has the strongest recent history on Discord component wiring and plugin SDK boundary decisions around the affected surface.

Owner confidence: high

Options:

- **Add Typed Agent Metadata (recommended):** Expose a documented bounded metadata envelope with original message id, component kind, safe callback/custom data, label/value details, and clicker identity, backed by Discord plugin tests.
- **Keep Metadata Plugin-Only:** Leave rich interaction fields on plugin interactive handlers and document that stateful Discord workflows should use plugin callbacks instead of generic fallback messages.
- **Start With Sender And Message:** Expose only clicker and originating message ids first, deferring callback payload semantics until a broader inbound metadata contract is settled.

## Reproduction Assessment

Yes. Source inspection shows current main builds generic Discord component callbacks as eventText and dispatches text-oriented inbound fields without a typed interaction metadata object.

## Solution Assessment

Unclear until maintainers choose the public contract. The maintainable fix should be a typed channel/inbound interaction metadata contract, not an ad hoc raw Discord payload leak.
