## Summary

Keep open: current main still routes generic Discord component callbacks into text-only agent turns, while richer interaction fields are available only to plugin interactive handlers. The remaining work is a public metadata-contract and trust-boundary decision, not conservative cleanup.

## What This Changes

Request structured Discord button interaction metadata, including source message, clicked component, and clicker identity, in the agent-visible inbound context.

## Best Possible Solution

Define a narrow documented Discord/channel interaction metadata contract populated from registry state and Discord interaction payload for buttons, selects, and modals, with tests and docs before exposing it to agents.

Owner confidence: high

Options:

- **Add Typed Agent Metadata (recommended):** Expose a documented bounded metadata envelope with source message id, component kind, safe callback/custom data, label/value details, and clicker identity, backed by Discord plugin tests.
- **Keep Metadata Plugin-Only:** Leave rich interaction fields on plugin interactive handlers and document that stateful Discord workflows should use plugin callbacks rather than generic fallback messages.
- **Start With Minimal IDs:** Expose only clicker and originating message ids first, deferring callback payload semantics until a broader inbound metadata contract is settled.

## Solution Assessment

Unclear until maintainers choose the public contract. The maintainable fix should be a typed channel/inbound interaction metadata contract, not an ad hoc raw Discord payload leak.
