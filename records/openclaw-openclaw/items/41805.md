## Summary

Keep open: current main and the latest release still route generic Discord component clicks to agents as text-only inbound turns, while richer interaction fields are available only to plugin interactive handlers. The remaining work is a maintainer product/API decision for a typed, agent-visible interaction metadata contract.

## What This Changes

Request to add agent-visible structured metadata for Discord button and select callbacks, including message id, custom/callback data, label/value, and clicker identity.

## Best Possible Solution

Define and document a typed Discord interaction metadata envelope at the plugin/SDK inbound boundary, populated from the component registry plus sanitized Discord interaction fields across buttons, selects, and modals.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should generic Discord component callbacks expose a new agent-visible structured interaction metadata envelope, and which fields are public versus plugin-only?

Rationale: This changes the public agent inbound context and exposes Discord identifiers/callback data, so maintainers need to choose schema shape, compatibility behavior, privacy/security boundary, and docs before implementation.

Likely owner: thewilloftheshadow

Owner reason: The Discord component callback surface traces back to their Components v2 work, making them the strongest history-backed routing candidate for the API direction.

Owner confidence: high

Options:

- **Add Typed Agent Metadata (recommended):** Expose a narrow documented envelope with message id, action kind, safe callback/custom data, label/value details, and clicker identity, backed by Discord plugin tests.
- **Keep Metadata Plugin-Only:** Leave rich interaction fields only in plugin interactive handlers and document that stateful Discord workflows should use plugin callbacks instead of generic fallback messages.
- **Start With Sender And Message:** Expose only clicker and originating message ids first, deferring callback payload semantics until a broader inbound metadata contract is settled.

## Reproduction Assessment

Yes, source-reproducible rather than live-reproduced. Current source and tests show generic Discord component clicks become text-only agent turns such as Clicked "Approve", while structured interaction fields remain confined to plugin handlers.

## Solution Assessment

Unclear until maintainers choose the public contract. The best fix should be a typed channel/inbound-context metadata API, not a raw Discord payload leak or label-parsing workaround.
