## Summary

Keep open: current main still dispatches generic Discord component clicks as text-only inbound events, while richer interaction fields exist only for plugin interactive handlers. The remaining work is a public API and trust-boundary decision, not conservative cleanup.

## What This Changes

Request to expose structured Discord interaction metadata, including original message id, component id/data, label, and clicker identity, to agent-visible Discord component callbacks.

## Best Possible Solution

Define a narrow documented Discord/channel interaction metadata contract populated from registry state and Discord interaction payload for buttons, selects, and modals, with focused Discord tests and docs before exposing it to agents.

Options:

- **Add Typed Agent Metadata (recommended):** Expose a documented, bounded metadata envelope with original message id, component kind, safe callback/custom data, label/value details, and clicker identity, backed by Discord plugin tests.
- **Keep Metadata Plugin-Only:** Leave rich interaction fields on plugin interactive handlers and document that stateful Discord workflows should use plugin callbacks rather than generic fallback messages.
- **Start With Sender And Message:** Expose only clicker and originating message ids first, deferring callback payload semantics until a broader inbound metadata contract is settled.

## Solution Assessment

Unclear until maintainers choose the contract. The durable fix should be typed channel/inbound interaction metadata rather than an ad hoc raw Discord payload leak.
