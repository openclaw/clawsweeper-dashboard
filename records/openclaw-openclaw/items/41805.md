## Summary

Keep open: current main still dispatches generic Discord component clicks as text-only inbound events, while richer interaction fields exist only for plugin interactive handlers. The remaining work is a public metadata contract and trust-boundary decision, not conservative cleanup.

## What This Changes

Request to expose structured Discord component interaction metadata, including originating message, clicked component/custom data, and clicker identity, to generic agent callbacks.

## Best Possible Solution

Define a narrow documented Discord/channel interaction metadata contract populated from registry state and Discord interaction payload for buttons, selects, and modals, with focused Discord tests and docs before exposing it to agents.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should generic Discord component callbacks expose a new agent-visible structured interaction metadata envelope, and which fields should be public versus plugin-only?

Rationale: The change would create a public agent inbound-context contract and expose Discord identifiers plus callback data, so maintainers need to choose schema, compatibility shape, and trust boundary before implementation.

Likely owner: vincentkoc

Owner reason: vincentkoc has recent history on the active Discord interactive component type surface where the public contract would likely be shaped.

Owner confidence: high

Options:

- **Add Typed Agent Metadata (recommended):** Expose a documented, bounded metadata envelope with originating message id, component kind, safe callback/custom data, label/value details, and clicker identity, backed by Discord plugin tests.
- **Keep Metadata Plugin-Only:** Leave rich interaction fields on plugin interactive handlers and document that stateful Discord workflows should use plugin callbacks rather than generic fallback messages.
- **Start With Sender And Message:** Expose only clicker and originating message ids first, deferring callback payload semantics until a broader inbound metadata contract is settled.

## Reproduction Assessment

Yes. Current main source and tests show the generic Discord component path dispatches eventText into BodyForAgent/RawBody/CommandBody without a typed interaction metadata object; I did not run a live Discord click.

## Solution Assessment

Unclear until maintainers choose the public contract. The maintainable solution should be typed and bounded, not a raw Discord payload leak or another text-label workaround.
