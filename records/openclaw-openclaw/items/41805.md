## Summary

Keep open: current main and the latest stable release still route generic Discord component clicks to agents as text-only inbound events, while richer interaction fields are only available to plugin interactive handlers. The remaining work is a public channel metadata contract and trust-boundary decision, not conservative cleanup.

## What This Changes

Request to expose structured Discord button/select interaction metadata to agents for generic component callbacks.

## Best Possible Solution

Define a narrow documented Discord interaction metadata contract populated from registry state and Discord interaction payload for buttons, selects, and modals, with tests and docs, without exposing the raw Discord payload wholesale.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should generic Discord component callbacks expose a new agent-visible structured interaction metadata envelope, and which fields are safe public contract versus plugin-only callback data?

Rationale: The change would expose Discord identifiers and callback data through a public agent inbound-context contract, so automation should not choose the schema or trust boundary.

Likely owner: steipete

Owner reason: steipete has the strongest recent history around Discord component wiring, plugin SDK boundaries, and inbound context refactors where this public contract would likely be shaped.

Owner confidence: medium

Options:

- **Add Bounded Metadata (recommended):** Expose documented safe fields such as component kind, originating message id, selected values, label, and clicker identity, with callback/custom data only in a maintainer-approved shape.
- **Keep Generic Callbacks Text-Only:** Leave richer interaction fields on plugin interactive handlers and document generic callbacks as label/value text for compatibility.
- **Start With Sender And Message:** Expose only clicker identity and originating message id first, deferring callback payload semantics until a broader inbound metadata contract is settled.

## Reproduction Assessment

Yes. Source inspection shows current main builds generic Discord component callbacks from eventText and finalizes BodyForAgent, RawBody, and CommandBody without a typed interaction object; I did not run a live Discord click.

## Solution Assessment

Unclear until maintainers choose the contract. The durable fix should be typed, bounded channel interaction metadata rather than an ad hoc raw Discord payload leak.
