## Summary

Keep open: current main still sends generic Discord component callbacks to the agent as text-only inbound messages, while richer interaction fields are only exposed to plugin interactive handlers. The remaining work is a public metadata schema and trust-boundary decision, not conservative cleanup.

## What This Changes

Request to expose structured Discord interaction metadata, including message, component, callback, and user fields, to agents handling Discord button/select callbacks.

## Best Possible Solution

Define a narrow documented Discord/channel interaction metadata contract populated from registry state and Discord interaction payloads for buttons, selects, and modals, with trust labeling, focused tests, and docs before exposing it to agents.

Options:

- **Add Typed Agent Metadata (recommended):** Expose a documented bounded metadata envelope with original message id, component kind, safe callback/custom data, label/value details, and clicker identity, backed by Discord plugin tests.
- **Keep Metadata Plugin-Only:** Leave rich interaction fields on plugin interactive handlers and document that stateful Discord workflows should use plugin callbacks rather than generic fallback messages.
- **Start With Sender And Message:** Expose only clicker and originating message ids first, deferring callback payload semantics until a broader inbound metadata contract is settled.

## Solution Assessment

Unclear until maintainers choose the contract. The maintainable fix should be typed channel/inbound interaction metadata rather than an ad hoc raw Discord payload leak.
