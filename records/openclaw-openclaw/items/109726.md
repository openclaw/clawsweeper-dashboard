## Summary

Keep open for product direction: current OpenClaw deliberately treats explicit user model selections as strict, while configured defaults already support runtime fallback, recovery probes, and visible notices; this request would change that established user-intent boundary rather than fix a missing general fallback mechanism.

## What This Changes

Requests automatic recovery when a session-pinned model fails by clearing or bypassing the pin, retrying the configured primary or fallback chain, and notifying the agent context.

## Best Possible Solution

If maintainers want this capability, add an explicit fallback policy for user-selected models that applies only to classified failover-worthy errors, defaults to preserving the user pin, uses the existing configured candidate chain, and surfaces an operational notice without injecting synthetic assistant-context text.

Options:

- **Temporary fallback (recommended):** Allow classified transient failures to use the existing fallback chain for the current run while retaining the user's session selection for later turns.
- **Strict selection:** Keep explicit session choices fail-closed and improve the error with a visible in-product action to reset or choose another model.
- **Clear failed selection:** Automatically remove the persisted user override and continue future turns from the configured primary or fallback state.

## Solution Assessment

No. Unconditionally clearing a session pin and adding another config switch is not the safest solution; temporary fallback for classified failures, without mutating the user's persisted choice, is the narrower design if maintainers approve the direction.
