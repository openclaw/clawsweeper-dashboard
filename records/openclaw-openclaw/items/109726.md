## Summary

Keep open for product direction: current OpenClaw intentionally treats explicit user-selected session models as strict, while configured defaults already support runtime fallback, recovery probes, and visible transition notices. This request changes the user-intent, cost, and provider-routing boundary rather than repairing a missing general fallback mechanism.

Likely related people: @BruceMacD (high confidence), @hoyyeva (high confidence), and @obviyus (medium confidence) based on merged model-selection and fallback history.

## What This Changes

Allow a failed session-pinned model to use the configured primary or fallback chain, notify the agent about the transition, and optionally clear the session pin.

## Best Possible Solution

Preserve strict user selections by default; if maintainers sponsor the capability, add an explicit opt-in fallback policy that temporarily uses a configured chain, emits an operational notice, and never clears or rewrites the user-owned model pin.
