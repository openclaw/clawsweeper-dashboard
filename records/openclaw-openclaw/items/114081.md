## Summary

This remains a plausible, high-impact compaction bug rather than a duplicate or completed fix. Current main still has separate preflight-compaction and memory-flush helpers, while the reported overflow-recovery route needs direct source and live-path confirmation before selecting a safe repair boundary.

## What This Changes

Ensure a configured pre-compaction durable-memory flush is considered when reactive context-overflow recovery compacts an embedded agent session.

## System Context

OpenClaw's embedded agent runner estimates context before a turn and can compact proactively; a separate error-recovery path handles provider context-overflow failures after a turn attempt. Memory Core supplies an optional flush plan that asks the agent to write durable notes before context is reduced.

## Best Possible Solution

Unify proactive and reactive compaction behind one lifecycle coordinator that evaluates the existing flush plan once per compaction cycle, then add focused tests for proactive and overflow-triggered compaction plus a live local-provider reproduction.
