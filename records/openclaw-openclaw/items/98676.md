## Summary

## What This Changes

The PR replaces `approvals set --file` with a bounded regular-file reader and adds filesystem regression tests for small, oversized, directory, and FIFO inputs.

## Best Possible Solution

Land the bounded reader once maintainers accept or document the 1 MiB regular-file import contract, keeping `--stdin` as the streaming path.

## Reproduction Assessment

Yes from source inspection: current main and `v2026.6.11` read the `--file` path with unbounded `fs.readFile`, while the stdin sibling already enforces a byte cap. I did not run an OOM repro in the read-only checkout.

## Solution Assessment

Yes, with a compatibility caveat: reading through the opened fd with a `maxBytes + 1` loop is the narrow fix for the OOM and non-regular-file paths. The remaining question is whether maintainers accept or document the new regular-file-only, 1 MiB `--file` policy.
