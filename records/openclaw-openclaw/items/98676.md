## Summary

Keep this PR open: it is a useful CLI hardening fix and the earlier short-read defect is repaired, but the new non-regular-file guard still opens user paths in blocking mode before `fd.stat()`, so FIFO inputs can stall instead of being rejected. Maintainers also need to explicitly accept or tune the new 1 MiB `--file` cap because it changes previously accepted input behavior.

## What This Changes

The PR adds a bounded `openclaw approvals set --file` reader in `src/cli/exec-approvals-cli.ts` and regression tests for small, oversized, and non-regular file inputs.

## Best Possible Solution

Use a nonblocking fd-based bounded reader that rejects non-regular paths without FIFO stalls, then land if maintainers accept the stdin-aligned 1 MiB `--file` cap or adjust the cap/docs first.

## Reproduction Assessment

Yes. Current main and `v2026.6.11` source route `openclaw approvals set --file` through unbounded `fs.readFile`, while the PR body includes terminal proof for normal, oversized, and directory inputs; the remaining FIFO stall is source-proven from POSIX FIFO open behavior and OpenClaw's existing nonblocking-open precedent.

## Solution Assessment

No, not yet. The bounded fd-based reader is the right layer and the short-read loop is now correct, but it should use nonblocking open flags before `fd.stat()` so non-regular FIFO paths fail fast instead of hanging.
