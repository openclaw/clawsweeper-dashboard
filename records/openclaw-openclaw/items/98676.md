## Summary

## What This Changes

## Best Possible Solution

Read at most `maxBytes + 1` bytes from the opened regular handle or stream, add a growth-after-stat regression test, and include redacted terminal proof for normal and oversized CLI file paths.

## Reproduction Assessment

Yes for the relevant code paths: current main still has an unbounded `fs.readFile` for `--file`, and a local Node proof shows the PR's `fd.stat()` plus `fd.readFile()` pattern can exceed the intended cap if the file grows after stat. ## Solution Assessment

No. Opening the fd before stat is a good partial fix for path swaps and non-regular files, but the best fix is a byte-limited read from the opened handle before JSON parsing.
