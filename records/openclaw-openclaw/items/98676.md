## Summary

Keep open: the latest branch appears to fix the bounded-read bug and addresses the prior stat-only, short-read, and FIFO-stall concerns, but maintainers should still accept the stricter `--file` input contract before landing.

## What This Changes

The PR replaces `approvals set --file` unbounded `fs.readFile` with a descriptor-based bounded regular-file read and adds helper tests for small, oversized, directory, and FIFO inputs.

## Best Possible Solution

Land the fd-based bounded reader once maintainers accept the regular-file-only, 1 MiB `--file` import contract, or add a short docs/help note before merge if that new contract should be explicit.

## Reproduction Assessment

Yes from source inspection: current main reads the `--file` path with an unbounded `fs.readFile`, while the stdin sibling already enforces a byte cap. I did not run a destructive large-file repro in the read-only checkout, but the code path is direct and the PR body includes after-fix CLI output.

## Solution Assessment

Yes, with a compatibility caveat: reading through the opened fd with a `maxBytes + 1` buffer is the maintainable fix for the OOM path and prior TOCTOU/non-regular bypasses. The only remaining decision is whether maintainers accept the new regular-file-only, 1 MiB `--file` policy as-is or want it documented first.
