## Summary

Keep open. The second commit fixes the earlier non-regular/path-swap problem, but the helper still performs a full `fd.readFile("utf8")` after `fd.stat()`, so the accepted regular file can grow past `maxBytes` before the read; the external-contributor proof is still unit-test output only.

## What This Changes

The PR adds a 1 MB bounded-read helper for `openclaw approvals set --file`, switches the CLI to it, and adds focused tests for oversized and non-regular files.

## Best Possible Solution

Read at most `maxBytes + 1` bytes from the opened regular handle or use OpenClaw's fs-safe bounded reader, add a regression for file growth after stat, and include redacted real CLI proof.

## Reproduction Assessment

Yes. Source inspection and a local Node proof show the PR's fd-stat-plus-`fd.readFile` pattern can read beyond the cap if the opened regular file grows after the stat.

## Solution Assessment

No. The fd-based stat check is a good step for non-regular files and path swaps, but the best fix is a byte-limited read from the opened handle before JSON parsing.
