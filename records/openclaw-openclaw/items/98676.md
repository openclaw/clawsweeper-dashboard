## Summary

Keep open: the hardening target is valid, but the stat-only guard is not a true bounded read and the PR proof is unit-test-only, so merge should wait for a bounded read or explicit regular-file policy plus real CLI proof.

## What This Changes

The PR adds a 1 MB stat-based pre-check before `openclaw approvals set --file` reads JSON and adds a focused helper test.

## Best Possible Solution

Bound the actual bytes read from approvals `--file` input, preferably by rejecting unsupported non-regular files or reading through an opened descriptor/stream with a `maxBytes + 1` cap before JSON5 parsing.

## Reproduction Assessment

Yes from source inspection: current main reads `opts.file` with `fs.readFile(..., "utf8")` while stdin counts chunks. The proposed stat-only helper would still proceed for non-regular paths that report size 0.

## Solution Assessment

No: this is a useful ordinary-file mitigation, but it is not the best fix for a bounded-read requirement. The maintainable fix should cap bytes actually read or reject unsupported non-regular inputs before reading.
