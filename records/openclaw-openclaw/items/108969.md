## Summary

The durable-custody direction is sound, but this implementation changes the payload seen by recovery hooks and can cause an attachment to survive a hook that removed or replaced its MEDIA directive. The supplied verification is comprehensive integration-test evidence, but it remains mock-boundary proof rather than an after-fix run from a real producer and recovery process.

## What This Changes

The PR projects media from legacy MEDIA text directives into structured queue-custody fields before spool staging and adds focused retry/recovery coverage.

## Best Possible Solution

Keep queue custody for directive media, but preserve the hook-visible carrier semantics by applying the spool substitution after replay hooks or by storing custody metadata separately until final normalization; add a regression where a hook removes or replaces the MEDIA directive, then provide redacted live recovery output after deleting the producer file.

Yes from source: current queue staging owns structured media but cannot see local media that only materializes from a MEDIA text directive, so deleting the producer file before recovery leaves the row pointing at a missing path. The supplied integration test describes this deterministic path, though it was not independently executed in this review.

## Solution Assessment

No. Reusing canonical normalization and the existing spool is the right ownership boundary, but persisting the materialized structured fields before recovery hooks changes their ability to remove or replace directive media.
