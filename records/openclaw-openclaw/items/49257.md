- `impact:security`: The requested diagnostic surface is about exposing pre-auth handshake, auth, device identity, and connection error details safely.

## Summary

Keep open: current main has authenticated Debug, Event Log, and Logs surfaces, but it still does not provide the requested session-only, copyable pre-auth Control UI connection diagnostic log; the security boundary for exposing handshake/auth/device details needs maintainer approval.

## What This Changes

The issue requests an ephemeral Control UI debug mode that captures WebSocket connection lifecycle, handshake, close/error details, and optional gateway logs for the current browser session only.

## Best Possible Solution

Define a support-safe Control UI diagnostics boundary first: an in-memory, redacted connection timeline for browser-side pre-auth failures, separate from authenticated gateway log tailing and aligned with the safe authenticated diagnostics work in https://github.com/openclaw/openclaw/issues/102689.

## Maintainer Decision

Required: true

Question: Which pre-auth Control UI connection details may be shown and copied in an ephemeral browser diagnostic log?

Rationale: The useful information is exactly the sensitive boundary: handshake frames, auth/device identity failures, origin checks, and close reasons can help support but may disclose credentials, identifiers, or deployment details if exposed too broadly.

Likely owner: steipete

Owner reason: steipete authored the adjacent safe UI diagnostics issue and has the strongest recent history on Control UI auth/reconnect UX and docs.

Owner confidence: high

Options:

- **Allowlist Redacted Browser Timeline (recommended):** Expose only browser-observed lifecycle phases, normalized error codes, timings, and redacted recovery hints in memory with copy/export redaction.
- **Authenticated Diagnostics Only:** Keep pre-auth details out of the UI and focus on the authenticated safe diagnostics page tracked in https://github.com/openclaw/openclaw/issues/102689.
- **Broader Log Streaming:** Permit gateway-side log streaming once authenticated, but require a separate design for what can ever be surfaced before auth completes.

## Reproduction Assessment

## Solution Assessment

Unclear until maintainers choose the security boundary. A narrow allowlisted, redacted, in-memory browser-side timeline looks safer than dumping handshake frames or raw gateway logs into the UI.
