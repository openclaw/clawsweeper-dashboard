## Summary

Keep open: current main has a Debug page, an in-memory post-handshake event log, richer login errors, and post-connect log tailing, but it still does not provide the requested session-only, copyable pre-auth connection diagnostic transcript; the direct implementation PR was closed unmerged.

## What This Changes

Request a Control UI debug mode that captures WebSocket connection lifecycle, handshake, close, and error details ephemerally in the browser with copyable support output.

## Best Possible Solution

Define and implement a redacted, session-only Control UI diagnostics drawer that records lifecycle/timing/close/error summaries before auth, offers safe copy/export, and links to post-connect `logs.tail` without durable browser storage.

Options:

- **Redacted phase log (recommended):** Expose lifecycle phases, timings, close codes, stable error codes, and sanitized recovery hints while redacting tokens, signatures, device fingerprints, raw headers, and endpoint secrets.
- **Post-auth only:** Keep pre-auth UI limited to current recovery messages and improve only the connected Debug page and `logs.tail` experience.
- **Raw diagnostic export:** Allow raw frame export behind an explicit advanced warning, accepting higher support value with higher sensitive-data risk.
