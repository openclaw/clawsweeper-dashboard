## Summary

Keep open: current main still does not provide the requested opt-in, session-only, copyable pre-auth connection diagnostic log. The existing Control UI has redacted login error details, connected-only Debug diagnostics, a post-connect event log, and connected-only log tailing, while the linked implementation PR is closed unmerged and the remaining work needs product/security review.

## What This Changes

The issue requests a session-only Control UI diagnostic mode that exposes WebSocket connection lifecycle logs, pre-auth errors, close details, and copyable support context without persistent browser storage.

## Best Possible Solution

Add a bounded, opt-in, in-memory Control UI connection diagnostic drawer that is available from the login gate through the authenticated Debug page, reuses existing connect timing/error hooks, redacts sensitive fields, and avoids localStorage/IndexedDB persistence.

## Reproduction Assessment

Yes, source inspection gives a high-confidence current-main path for the missing capability: login only shows redacted raw error details, Debug/log pages require an authenticated client, and connect.challenge/timing details are not surfaced as a copyable session log. I did not run a browser E2E because this read-only cleanup review did not need to mutate or generate artifacts.

## Solution Assessment

Unclear until maintainers choose the product/security boundary. The best shape is not a raw frame dump; it should be a narrowly redacted diagnostic surface built from existing connection timing, close/error, and safe event data.
