## Summary

Keep this PR open: current `main` still contains the three reported defects, but the proposed direct-file-read path has an actionable pathname race that can reintroduce the FIFO stall or bypass the size and file-type checks.

## What This Changes

The PR replaces per-untracked-file git subprocesses with in-process line counting and preserves state-only pull-request chips when GitHub detail enrichment becomes rate limited.

## Best Possible Solution

Keep the in-process optimization and state-only rate-limit degradation, but validate and read each untracked file through one nonblocking, non-following descriptor with deterministic FIFO and symlink replacement coverage.

No as submitted. The overall design is the narrowest maintainable fix, but it should use the repository’s existing single-handle nonblocking read pattern to make the stated no-stall guarantee true.
