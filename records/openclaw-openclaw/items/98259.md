## Summary

Keep this PR open, but do not merge it as written: it turns on cache parameters for every Azure AI Foundry hostname even though hostname alone does not establish that the deployed model supports those parameters. The contributor’s live Azure GPT proof is useful and the previous regional-host finding is addressed, but the new default needs a narrower capability boundary first.

## What This Changes

This PR centralizes automatic prompt-cache-key support for Azure OpenAI Chat Completions endpoints, carries it through provider and agent transports, preserves requested cache retention, and documents the behavior.

## System Context

OpenClaw resolves a model’s OpenAI-compatible endpoint policy before building Chat Completions requests. That policy decides whether session cache-routing parameters and requested retention pass through to the provider, affecting cache hits, latency, and whether an endpoint accepts the request.

## Architecture Diagram

flowchart LR

  B --> C{Prompt-cache support?}
  C -->|Yes| D[Provider and agent request builders]
  C -->|No| E[Omit cache parameters]
  D --> F[Azure or OpenAI Chat Completions]
  F --> G[Cache-hit usage data]

## Best Possible Solution

Limit automatic cache defaults to routes whose Azure OpenAI model capability is established; keep generic Foundry Chat Completions endpoints on the existing explicit `compat.supportsPromptCacheKey` opt-in, then document every supported hostname family and the model-specific long-retention constraint.
