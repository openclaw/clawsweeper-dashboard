## Summary

This remains a useful, bounded fix: the latest head addresses the earlier endpoint-detection, transport, retention, and extra-parameter blockers, and the PR body supplies redacted live Azure evidence. One non-blocking documentation gap remains: the runtime supports regional Azure AI Foundry `*.api.cognitive.microsoft.com` hosts, but the changed prompt-caching guide does not name that supported hostname family.

## What This Changes

The PR moves Azure OpenAI Chat Completions cache-key capability into shared endpoint compatibility defaults so direct and boundary-aware requests send stable session cache keys and preserve supported long retention.

## System Context

OpenClaw resolves model endpoint compatibility before its OpenAI Chat Completions builders form request payloads. That decision controls whether session-derived prompt-cache fields reach Azure OpenAI and Azure AI Foundry endpoints, affecting cache reuse, latency, and token cost on repeated agent turns.

  B --> C[Azure hostname detection]

  F --> G[Repeated-turn cache reuse]

## Best Possible Solution

Keep the shared endpoint-default design, add the regional Foundry hostname to the public prompt-caching guidance, and lock that hostname family into the compatibility regression table before merge.
