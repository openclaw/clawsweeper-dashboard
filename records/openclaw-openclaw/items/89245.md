## What This Changes

The issue asks OpenClaw to make Feishu direct `/reset` and `/new` recovery durable so session-family metadata cannot point at missing transcript ids or collapse later messages to generic failure copy.

## Best Possible Solution

Make direct `/reset` and `/new` lineage publication transactional with transcript durability or old-entry rollback, then prove Feishu direct recovery after a Codex failure without orphaned family ids or generic fallback loops.

Options:

- **Pre-create Before Publish (recommended):** Create the new transcript header before committing the new session entry, and roll back to the previous entry if creation fails.
- **Keep Old Until First Write:** Leave the previous transcript mapped until the next turn successfully writes the new transcript, avoiding orphan ids at the cost of delayed rotation semantics.
- **Repair Only:** Rely on cleanup/doctor repair plus clearer failure copy, which is lower risk to runtime flow but leaves live recovery weaker.
