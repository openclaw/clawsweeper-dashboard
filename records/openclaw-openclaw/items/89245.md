## Summary

Keep open. Current main still does not prove the Feishu/direct `/reset` and `/new` path only publishes session lineage after a durable transcript exists, and the closed compaction issue covers an adjacent failure mode rather than this direct reset/new recovery case.

## What This Changes

The issue reports a Feishu direct session becoming unusable after `/reset` or `/new`, with session lineage pointing at transcript IDs that have no durable files and later replies falling back to generic failure copy.

## Best Possible Solution

Make direct-chat reset/new rotation transactional: create or prewarm the new transcript before publishing the new mapping, otherwise keep the previous valid transcript active and surface an explicit session-repair recovery path.

Rationale: Both shapes can address missing transcript lineage, but they differ in user-visible reset semantics, failure recovery, and whether missing empty reset sessions are treated as invalid state.

Options:

- **Transactional rotation (recommended):** Create or prewarm the new transcript before updating the session store or lineage, keeping the previous transcript authoritative if creation fails.
- **Repair-after-publication:** Allow the mapping to advance, but immediately detect missing transcript files and remap to the newest valid family member with specific recovery copy.
- **Fold into broader UX work:** Leave this narrow durability issue open only as linked context under the broader Feishu failure-status policy issue.

## Reproduction Assessment

No for a full high-confidence live Feishu replay on current main; yes at source level for the missing durable-transcript invariant. The inspected reset/new path can append a new session id to lineage and persist the reply entry without using the transcript-creation helper.

## Solution Assessment

Unclear until maintainers choose the reset/new lifecycle contract. A transactional transcript prewarm looks like the narrowest durable fix, but repair/remap behavior may be preferred if maintainers intentionally allow empty reset sessions.
