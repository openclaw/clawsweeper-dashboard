Keep open. Current main still has source-visible `/new` and runner-reset paths that can publish rotated session lineage before there is a clear durable transcript guarantee, and related fixes only cover adjacent compaction or Feishu failure-copy slices.

## What This Changes

The issue asks OpenClaw to make Feishu direct `/reset` and `/new` recovery keep session-family metadata, transcript artifacts, and user-facing fallback behavior in sync after a failed Codex-backed turn.

## Best Possible Solution

Make `/reset` and `/new` publish direct-session lineage only after the replacement transcript is durable, or keep the prior valid transcript authoritative and surface an explicit repair message when rotation cannot be completed.
