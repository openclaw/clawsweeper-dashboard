## Summary

This PR remains necessary: the current Feishu static-card routes do not enforce the documented five-table ceiling, while the branch now guards all three static-card decision points and adds the previously requested boundary tests. No actionable patch defect remains, but the exact-head type/test checks are not green yet, so it should stay open for normal validation and maintainer review. Likely related people: @sliverp is the documented Feishu-area owner; @mushuiyu886 recently worked on adjacent Feishu streaming-card behavior.

## What This Changes

Adds a five-table preflight to Feishu static-card routing so oversized Markdown-table messages use the existing post path, with regression tests for auto and explicit-card modes.

## Best Possible Solution

Keep one shared five-table invariant across every Feishu static-card entry point, retain the existing post conversion as the safe fallback, leave CardKit streaming unchanged until its contract is verified, and merge only after focused extension tests plus exact-head type/check gates pass.
