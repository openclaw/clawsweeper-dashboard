## Summary

This PR is still necessary and the contributor resolved the prior request for boundary tests, but the static-card guard remains incomplete: it misses valid pipe-less Markdown tables and the reply dispatcher applies a per-card API limit to the whole reply before chunking. Both cases should be corrected before merge.

## What This Changes

The PR adds a five-table preflight guard to Feishu static-card routing so oversized Markdown-table replies use post delivery, with regression tests in the outbound adapter and reply dispatcher.

## Best Possible Solution

Use one shared, renderer-aligned table counter, evaluate the five-table cap against actual static-card payload chunks, and retain an ErrCode 11310 post fallback as a safety net for parser or platform drift.
