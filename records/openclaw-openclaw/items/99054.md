## Summary

Keep open: current main and the latest release still lack Microsoft Teams lifecycle handling for true app removal, and the linked fix PR is open rather than merged.

## What This Changes

The issue asks OpenClaw to stop silently reusing Microsoft Teams personal DM session history after a Teams bot/app is removed and re-added.

## Best Possible Solution

Treat true Microsoft Teams app removal as a plugin-owned lifecycle/session boundary, stale the matching personal DM session non-destructively, handle bot membersRemoved where Teams emits it, and keep Teams local Remove chat history documented as a separate non-detectable UI action.

Owner confidence: medium

Options:

- **Stale session and tombstone reference (recommended):** Use the existing non-destructive session-boundary pattern, clear stale proactive conversation references when applicable, and keep transcript deletion out of runtime unless a separate retention policy says otherwise.
- **Stale only the active session:** Adopt the narrowest Discord-like behavior, but leave cached proactive references as a separate follow-up risk.
- **Hard-delete retained Teams data:** Treat uninstall as a deletion boundary, which needs explicit data-loss policy, migration behavior, and stronger security review before implementation.
