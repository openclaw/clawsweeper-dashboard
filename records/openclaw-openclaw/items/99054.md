## Summary

Keep this issue open: current main and the latest release still ignore the Teams uninstall/reinstall lifecycle path that the report identifies, while the DM routing path continues to reuse and record the same direct-session metadata.

## What This Changes

The issue requests Teams personal-chat lifecycle handling so removing and re-adding the Teams bot/app does not silently continue the prior OpenClaw DM session history.

## Best Possible Solution

Implement Teams-plugin lifecycle handling for installationUpdate remove/add and bot membersRemoved, non-destructively stale/reset only the matching personal DM session, and add outbound stale-conversation cleanup for documented Teams roster/block errors if maintainers include that in the same bounded fix.

## Reproduction Assessment

Yes at the source level, but not from a fresh live Teams run in this review. Current main lacks installationUpdate dispatch and membersRemoved handling while the DM path continues to record the existing direct-session key.

## Solution Assessment

Unclear until maintainers choose the retention boundary. The narrowest maintainable direction appears to be plugin-owned lifecycle handling that marks the matching personal DM session stale without deleting transcripts, matching the existing Discord precedent.
