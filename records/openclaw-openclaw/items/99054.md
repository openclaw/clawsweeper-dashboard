## Summary

Keep open: current main and the latest release still ignore the Teams uninstall/reinstall lifecycle path that should bound a personal DM session, and the report has a clear source-level session-state and privacy risk.

## What This Changes

Handle Microsoft Teams personal app removal and re-addition so the bot does not silently continue using prior DM session history.

## Best Possible Solution

Implement plugin-owned Teams lifecycle handling that treats personal uninstall/remove as a non-destructive DM session boundary and tombstones stale proactive refs after confirming the Teams signal and retention policy.

## Reproduction Assessment

Yes at source level, but not by a live Teams run in this read-only review. Current main ignores installationUpdate and membersRemoved while DM routing keeps the same sender-derived session key, matching the reported retained-history path.

## Solution Assessment

Likely yes, with one open decision: the fix belongs in the Teams plugin lifecycle/session-store path rather than core session-key derivation or transcript deletion. Maintainers should confirm the retention behavior and the exact live Teams signal before implementation.
