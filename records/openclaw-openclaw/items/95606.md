## Summary

Keep open: current `main` and the latest release still leave the reproducible LanceDB recall-to-forget handoff gap, while the broader replacement/deprecation semantics are only partially overlapped by the open memory lifecycle tracker and the related fix PRs are closed unmerged.

## What This Changes

The issue asks for a reliable way to remove or supersede stale/conflicting memories after recall, either via usable deletion IDs or explicit replacement/deprecation semantics.

## Best Possible Solution

Approve a plugin-owned memory cleanup contract: either expose safe model-visible deletion handles from `memory_recall` now, with tests and live proof, or explicitly fold that handoff into the broader tombstone/supersede lifecycle tracked in https://github.com/openclaw/openclaw/issues/42650.
