## Summary

Keep open: current main and the latest release still leave the narrow recall-to-forget deletion handoff unresolved, while automatic replacement/deprecation of conflicting facts is broader memory lifecycle product work.

## What This Changes

The issue asks for stale or conflicting memories to be deletable after recall, either by accepting recall indexes, exposing deletable IDs, or adding replacement/deprecation semantics.

## Best Possible Solution

Add a maintainer-approved narrow recall-to-forget handoff, such as exposing deletable UUIDs in model-visible `memory_recall` output, while leaving conflict replacement, tombstones, and review/edit flows to the broader memory MVP work.

- **Defer to memory MVP:** Keep this issue as input to the broader review/edit/forget/conflict-resolution design and avoid a narrower tool-output contract for now.

Unclear until maintainers choose the tool contract. Exposing UUIDs in recall output looks like the narrowest maintainable fix for the deletion handoff; automatic replacement/deprecation belongs to the broader memory lifecycle design.
