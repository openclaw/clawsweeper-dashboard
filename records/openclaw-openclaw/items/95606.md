## Label Justifications

- `impact:session-state`: Persisted remembered facts can drift into future agent context and affect later decisions.

## Summary

Keep open: current main still leaves the reported memory cleanup gap. The shipped fix for `memory_forget(query=...)` candidate lists shows full UUIDs, but `memory_recall` still shows only numbered entries while exact deletion requires a UUID, and automatic replacement/deprecation of conflicting facts remains a memory product-contract decision.

## What This Changes

The issue asks for a reliable way to delete or replace stale built-in memory entries when corrected facts conflict with older memories.

## Best Possible Solution

Define the supported memory cleanup contract: preferably add a model-visible exact deletion selector to `memory_recall` for the immediate handoff, while leaving replacement/deprecation/conflict lifecycle semantics to the broader Memory MVP decision unless maintainers explicitly choose that scope.
