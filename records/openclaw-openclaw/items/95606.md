Keep open: current main and the latest release still leave the concrete recall-to-forget deletion gap, and the broader replacement/deprecation behavior remains an unsettled memory lifecycle decision. ## What This Changes

The issue asks for stale or conflicting LanceDB memories to be deletable or replaceable after recall, either through recall-visible deletion IDs, working forget-by-query, or explicit replacement/deprecation semantics.

## Best Possible Solution

Add a plugin-owned, model-visible exact deletion handle in memory_recall for the current UUID delete path, then track automatic replacement, tombstone, and conflict-resolution semantics through https://github.com/openclaw/openclaw/issues/42650 and https://github.com/openclaw/openclaw/issues/42648.
