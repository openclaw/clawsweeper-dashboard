## Summary

Keep open: current main and the latest release still leave a reproduced LanceDB memory cleanup gap. The query-based forget candidate list now shows full UUIDs, but `memory_recall` only exposes numbered visible entries while exact deletion requires a UUID, and conflicting-memory replacement/deprecation remains a product contract shared with https://github.com/openclaw/openclaw/issues/42650.

## What This Changes

The issue requests precise cleanup for stale or conflicting LanceDB memories through recall-to-forget deletion handles, semantic replacement/deprecation, or a listable deletable-ID workflow.

## Best Possible Solution

Adopt one plugin-owned memory cleanup contract: expose a safe model-visible exact deletion selector from recall for the narrow handoff, while keeping replacement, tombstone, supersede, and conflict-resolution semantics in the broader Memory MVP design.
