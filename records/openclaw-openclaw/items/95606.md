## Summary

Keep open: current main and the latest release still leave the model-visible recall-to-forget handoff incomplete, and broader replacement/deprecation of conflicting memories remains a memory lifecycle product decision rather than a safe cleanup close.

## What This Changes

The issue requests a reliable way to remove or replace stale built-in memory entries when corrected facts leave conflicting old memories visible.

## Best Possible Solution

Define one plugin-owned memory cleanup contract: expose a model-visible exact deletion selector from recall or add deliberate replacement/deprecation/conflict semantics with focused tests and docs.
