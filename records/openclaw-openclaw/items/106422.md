## Label Justifications

- `P1`: Foreground agent cancellation can be misreported as normal or running tool execution, allowing a broken agent workflow to continue after an operator stop.

## Summary

Keep open: the patch fixes the common foreground-cancellation path, but an abort that arrives while `runExecProcess` is still starting can run before the yield timer exists; the promise executor then arms that timer after cancellation, allowing a short `yieldMs` to fulfill a misleading `running` result before process finalization. Likely related people: c19354837 has the strongest history signal from the current exec abort-listener implementation.

## What This Changes

The PR changes foreground exec cancellation to reject with the signal reason or an `AbortError` after process finalization and adds regression coverage for cancellation during an armed yield window.

## Best Possible Solution

Make timer setup and initial abort observation atomic from the wrapper's perspective—either arm the yield timer before checking/registering the signal or refuse to arm it once `toolAborted` is set—while preserving post-finalization rejection and detached background-session behavior, then add a short-yield startup-abort regression test.
