- **[P1] Keep LID persistence inside Baileys:** `extensions/whatsapp/src/inbound/send-api.ts:154-158`
  - body: These direct auth-directory writes bypass Baileys’ `LIDMappingRepository`, which persists through the transactional key store and updates its in-memory cache only after success. The file state can therefore disagree with the live socket cache or overwrite a newer mapping, causing later sends to use the wrong JID. Use Baileys’ `getLIDForPN` and repository as the sole lookup and persistence owner.
  - confidence: 0.98
- **[P1] Do not bypass the account timelock from local token state:** `extensions/whatsapp/src/inbound/monitor.ts:776-777`
  - body: A usable locally stored token does not establish that WhatsApp’s account-level reachout timelock permits this send; Baileys already decides whether to attach that token during message construction. Returning here overrides the current public readiness result and can reintroduce locally accepted but undelivered direct messages. Keep the active timelock fail-before-send behavior authoritative.
  - confidence: 0.97
