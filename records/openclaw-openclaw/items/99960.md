## What This Changes

The PR snapshots cron add, update, and remove live scheduler state and restores it when saving the cron store fails, with regression tests for failed persistence and deferred auto-disable notifications.

## Best Possible Solution

Land the cron-owned rollback after maintainer review and final CI, while keeping quarantine-flush error propagation as a separately scoped follow-up if maintainers want that behavior changed.

## Reproduction Assessment

Yes. Source inspection on current main shows cron add/update/remove mutate live state before the durable save, and the PR body includes a real SQLite read-only before/after transcript; I did not run tests because this review was required to keep the checkout read-only.

## Solution Assessment

Yes. Snapshot-and-restore at the cron CRUD owner boundary is the narrow maintainable fix because those operations own the live mutation and durable save, while moving all mutation after persistence would require projecting the full recompute state separately.
