## Summary

Keep open. Current main and the latest release still define Android as a companion node rather than a Gateway host, so the requested Android/Termux Gateway hosting remains an unresolved platform, lifecycle, and security product decision.

## What This Changes

Request Android/Termux support for running the OpenClaw Gateway directly on mobile devices, including local dashboard access and remote node connections without a separate PC or VPS.

## Best Possible Solution

Keep this as the canonical Android/Termux Gateway-hosting decision until maintainers either define a scoped supported mode with real-device proof or explicitly keep Android node-only with clearer host guidance.

## Reproduction Assessment

Yes for source-level confirmation: current source still routes managed Gateway services only through darwin/linux/win32 adapters, so Android/Termux remains unsupported for `openclaw gateway start`. I did not run a live Android device reproduction.

## Solution Assessment

No for automation. The best route is a maintainer platform and security decision first, followed by either a scoped Android/Termux Gateway-hosting implementation or an explicit node-only documentation decision.
