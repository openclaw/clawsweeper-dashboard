## Summary

Keep open. Current main and v2026.6.11 still define Android as a companion node, not a Gateway host, while the managed Gateway service registry only supports darwin, linux, and win32; the linked AndroidForClaw project is useful external evidence but does not settle OpenClaw's platform and security boundary.

## What This Changes

Request Android/Termux support for running the OpenClaw Gateway service directly on Android, including local dashboard and remote node connectivity.

## Best Possible Solution

Keep this as the canonical Android/Termux Gateway-hosting platform decision until maintainers either define a scoped supported mode with real-device security proof or explicitly keep Android node-only with clearer host guidance.

## Reproduction Assessment

Yes for source-level confirmation, but not as a strict bug reproduction. Current main still excludes Android from the managed Gateway service registry, and docs define Android as a companion node rather than a Gateway host.

## Solution Assessment

No for automation. The best route is a maintainer platform and security decision first, followed by either a deliberately scoped Android/Termux Gateway-hosting implementation or an explicit node-only documentation decision.
