## Summary

Keep open. Current main and v2026.6.11 still define Android as a companion node that requires a separate Gateway host, while the Gateway service adapter remains limited to macOS, Linux, and Windows; AndroidForClaw is useful external evidence, but official Android/Termux Gateway hosting needs a maintainer platform and security decision.

## What This Changes

Requested support for running the OpenClaw Gateway service directly on Android/Termux so mobile-only users can access the dashboard and remote node workflows.

## Best Possible Solution

Maintainers should decide the official Android Gateway-hosting stance first, then either design a supported Termux/Android host path with service lifecycle, security, docs, and live-device proof, or explicitly document Android as companion-node only and point mobile-only users to external projects such as AndroidForClaw.

## Reproduction Assessment

Yes for the reported boundary: current source only registers darwin, linux, and win32 service adapters, so Android resolves to the unsupported service adapter. I did not run a live Termux device in this read-only review.

## Solution Assessment

Unclear. Supporting Android Gateway hosting is not a narrow bug fix because current docs define Android as a companion node requiring a separate Gateway host; maintainers need to choose whether Termux/Android becomes an official host platform.
