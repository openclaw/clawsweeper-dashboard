## Summary

Keep open. Current main and the latest release still define Android as a companion node rather than a Gateway host, so Android/Termux Gateway hosting remains an unresolved platform, lifecycle, and security product decision.

## What This Changes

Request Android/Termux support for running the OpenClaw Gateway directly on mobile devices without a separate PC, VPS, or Linux host.

## Best Possible Solution

Keep this as the canonical Android/Termux Gateway-hosting decision until maintainers either define a scoped supported mode with real-device proof or explicitly keep Android node-only with clearer host guidance.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw support Android/Termux as a Gateway host, or should Android remain a companion node with external/mobile-first Gateway-hosting projects kept outside core?

Rationale: The code and docs intentionally exclude Android from managed Gateway hosting today, and adding support would set platform, service lifecycle, background execution, dashboard exposure, and security policy for mobile devices.

Likely owner: steipete

Owner reason: The choice crosses Gateway lifecycle, security posture, release scope, and Android product direction, and steipete is the project lead with recent Gateway-service and Android-docs history.

Owner confidence: high

Options:

- **Scope a supported Android host design (recommended):** Keep this issue open while Android and Gateway owners define a narrow foreground or service-hosting mode, security constraints, docs, and real-device proof before implementation.
- **Keep Android node-only:** Document that official Android remains a companion node and close or redirect Android Gateway-hosting requests to external projects or future product planning.
- **Externalize mobile-first hosting:** Treat Android Gateway hosting as an external app/plugin/fork ecosystem path unless a missing core API is identified.

## Solution Assessment
