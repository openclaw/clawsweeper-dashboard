## Summary

Keep open. Current main and v2026.6.11 still define Android as a companion node while managed Gateway service hosting remains darwin/linux/win32 only; AndroidForClaw/HermesApp is useful prior art, but OpenClaw still needs a maintainer platform and security decision before supporting Android/Termux as a Gateway host.

## What This Changes

Request Android/Termux support for running the OpenClaw Gateway service and dashboard directly on mobile without a separate PC or VPS.

## Best Possible Solution

Keep this as the canonical Android/Termux Gateway-hosting decision until maintainers either define a scoped supported mode with real-device validation or explicitly keep Android node-only with clearer host guidance.

## Reproduction Assessment

## Solution Assessment

No for automation. The best route is a maintainer platform and security decision first, followed by either a deliberately scoped Android/Termux Gateway-hosting implementation or an explicit node-only documentation decision.
