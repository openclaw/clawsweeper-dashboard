## Summary

Keep open. Current main and v2026.6.11 still define Android as a companion node rather than a Gateway host, and the request remains a platform/security/product decision rather than a narrow implemented or duplicate cleanup item.

## What This Changes

Request Android/Termux support for running the OpenClaw Gateway service directly on mobile devices, including dashboard access and remote connections without a separate PC or VPS.

## Best Possible Solution

Keep this as the canonical Android/Termux Gateway-hosting platform decision until maintainers either define a scoped supported mode with real-device validation or explicitly keep Android node-only with clearer host guidance.

## Reproduction Assessment

Yes for source-level confirmation: current main excludes Android from the managed Gateway service registry and unsupported platforms throw on service lifecycle operations. I did not run a live Android/Termux device in this read-only review.

## Solution Assessment

No for automation. The best route is a maintainer platform and security decision first, followed by either a deliberately scoped Android/Termux Gateway-hosting implementation or an explicit node-only documentation decision.
