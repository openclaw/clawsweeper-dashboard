## Summary

Keep open: current `main` still applies the terminal-main transcript freshness guard to successful `status: "done"` sessions, and gateway, CLI, and auto-reply admission all treat that guard as a reason not to reuse the existing session. Three open linked PRs now own the concrete fix path, so the issue should stay open until one lands.

## What This Changes

The issue asks OpenClaw to stop rolling over successful main sessions into `.jsonl.reset.*` archives solely because the transcript file mtime is newer than `sessions.json.updatedAt`.

## Best Possible Solution

Land one focused fix in the shared session lifecycle guard, with regression coverage across gateway admission, CLI command session resolution, and auto-reply session initialization.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction shape: create an `agent:main:main` row with `status: "done"`, an older `updatedAt`, and a transcript file whose mtime is newer, then the current guard blocks reuse. I did not run a write-producing reproduction because this cleanup review is read-only.

## Solution Assessment

Yes, the best fix is in the shared lifecycle guard owner rather than caller-specific exceptions, because gateway, CLI command resolution, and auto-reply all consume the same `terminalMainTranscriptNewerThanRegistry` decision.
