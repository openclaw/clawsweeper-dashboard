## Summary

Keep open: current main and v2026.6.11 still route successful `status: "done"` main rows through the transcript-newer-than-registry guard, but multiple open closing PRs now target the bug, so this issue should remain the canonical tracker until one fix lands.

## What This Changes

The issue asks OpenClaw to stop rolling successful main-agent sessions into reset archives solely because transcript mtime is newer than `sessions.json.updatedAt`.

## Best Possible Solution

Land one canonical fix that skips the transcript freshness guard for successful `done` main rows, preserves interrupted and endedAt-only rollover behavior, and then let this issue close from the merged PR.

## Reproduction Assessment

Yes, at source level: create an `agent:main:main` row with `status: "done"`, an older `updatedAt`, and a transcript file whose mtime is newer; current source routes that row through the guard and blocks reuse. I did not execute a writing repro because this review is read-only.

## Solution Assessment

Yes, the best fix is a narrow shared session lifecycle correction, not a new reset mode or per-caller workaround. The open PRs use that owner boundary, but maintainers still need to choose one canonical landing path.
