## Label Justifications

- `P1`: The report describes a shipped-regression session-state workflow where successful main agent turns repeatedly lose continuity by rolling into new session ids after upgrade.
- `impact:session-state`: The affected behavior changes persisted session identity, transcript archival state, and main-agent continuity for normal successful runs.

## Summary

Keep open. Current main and the shipped v2026.6.11 source still treat a successful `status: "done"` main session as terminal for the transcript-mtime guard, so a newer transcript mtime can force rollover and `.jsonl.reset.*` archival even when daily/idle reset freshness is otherwise valid.

## What This Changes

The issue reports successful main agent sessions rolling over and being archived as `.jsonl.reset.*` when the transcript file mtime is newer than the session registry `updatedAt`.

## Best Possible Solution

Fix the session admission/marker contract so successful `done` main sessions remain reusable after normal transcript writes, while interrupted, timeout, killed, or stale endedAt-only rows still recover safely from the older stale-terminal condition.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: a main session row with `status: "done"`, positive `updatedAt`, and transcript mtime greater than `updatedAt` passes the terminal-main check and makes gateway reuse false.

## Solution Assessment

Yes, the issue should stay open and be fixed narrowly. The best repair is not the broader manual reset mode from https://github.com/openclaw/openclaw/issues/57369, but a session lifecycle fix that keeps successful `done` rows from false reset rollover while preserving stale-terminal recovery.
