## Summary

Keep open: current main and the latest release still let successful `status: "done"` main sessions reach the transcript-newer-than-registry rollover guard, and three open closing PRs are candidates rather than merged fixes. The issue should stay open until maintainers land one canonical fix.

## What This Changes

The issue asks OpenClaw to keep successful main sessions reusable when transcript mtime is newer than `sessions.json.updatedAt` instead of archiving them as reset rollovers.

## Best Possible Solution

Land one canonical fix, preferably the proof-positive branch with Gateway, CLI, and auto-reply coverage, while preserving rollover for interrupted or endedAt-only rows; close this issue only after that fix merges.

## Reproduction Assessment

Yes, at source level: create an `agent:main:main` row with `status: "done"`, an older `updatedAt`, and a transcript file whose mtime is newer; current source routes that case through the guard and blocks reuse. I did not run a writing reproduction because this review is read-only.

## Solution Assessment

Yes, the narrow shared lifecycle guard is the best fix boundary because Gateway, CLI command resolution, and auto-reply all consume it. The fix should skip successful `done` rows while preserving guarded rollover for interrupted or ambiguous terminal states.
