## Summary

Keep open: current main still applies the terminal-main transcript freshness guard to successful `status: "done"` rows, and gateway/CLI session admission both treat that guard as a reason not to reuse the existing session. The latest release contains the same guard, so the reported rollover remains a real session-state bug.

## What This Changes

The issue asks OpenClaw to stop rolling over successful main sessions solely because the transcript mtime is newer than the session registry `updatedAt`.

## Best Possible Solution

Successful `done` main-session rows should keep their session id and transcript continuity unless an actual reset, expiry, or unsafe recovery state applies, with regression coverage around the transcript mtime guard.

## Reproduction Assessment

Yes at source level: create an `agent:main:main` row with `status: "done"`, an older `updatedAt`, and a transcript file whose mtime is newer; current source routes that case through the guard and blocks reuse. I did not run a writing regression script because this review is read-only.

## Solution Assessment

Yes, the best fix is a narrow session lifecycle/admission correction rather than a new reset mode. The repair should preserve recovery behavior for interrupted or unsafe terminal states while allowing successful `done` sessions to continue.
