## Summary

Keep open: current main and the latest release still contain the reported terminal-main transcript freshness behavior, and current tests explicitly expect a `status: "done"` main session to roll over when transcript mtime is newer than registry `updatedAt`.

## What This Changes

The issue asks OpenClaw to keep successful terminal main sessions reusable when the transcript mtime is newer than the session registry timestamp.

## Best Possible Solution

Successful `done` main sessions should keep their session id and transcript continuity; the freshness guard should remain only for terminal states where rollover is still necessary for safety or recovery.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: create a fresh `agent:main:main` row with `status: "done"`, older `updatedAt`, and a transcript file whose mtime is newer than `updatedAt`; the current guard returns true and blocks reuse. I did not run the script because this review is read-only and avoids artifact-writing test commands.

## Solution Assessment

Yes, the best fix is a narrow session lifecycle/admission change, not a new reset mode. Either the guard should not apply to successful `done` sessions, or the successful transcript persistence path must reliably advance the registry marker before the next admission check.
