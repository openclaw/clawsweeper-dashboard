## Summary

Keep open: current main and v2026.6.11 still only provide `per-account-channel-peer` as a workaround for multi-account Feishu DMs; direct DM rows remain maintenance-removable and Feishu inbound sender IDs still enter direct session keys without Feishu-specific malformed-id validation or repair.

## What This Changes

The issue reports Feishu direct-message sessions being rebuilt after gateway restarts because account-scoped identity is not always present in DM session keys and session-store maintenance can prune direct-message entries.

## Best Possible Solution

Adopt a Feishu DM session identity and maintenance policy that prevents cross-app key collisions and preserves active direct-message history without unbounded store growth, with doctor repair for existing malformed or unscoped rows.
