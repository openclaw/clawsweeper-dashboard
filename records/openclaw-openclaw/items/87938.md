## Summary

Keep open: current main and v2026.6.11 still leave Feishu direct-message session rows removable by maintenance and still accept inbound Feishu sender IDs into session keys without Feishu-specific malformed-id validation or repair; `per-account-channel-peer` is a useful workaround for multi-account collisions, not a full fix.

## What This Changes

The issue asks OpenClaw to stop Feishu DM session rebuilds caused by maintenance pruning, cross-app direct-session keys, and malformed near-duplicate Feishu `open_id` session keys.

## Best Possible Solution

Adopt a maintainer-approved Feishu DM repair plan that combines account-scoped direct identity guidance, malformed `open_id` validation or repair, and a bounded direct-DM retention policy with upgrade-safe doctor coverage.
