## Summary

Keep open: current main still appears to only mitigate this Feishu DM continuity problem through documented account-scoped DM keys; direct Feishu DM rows remain removable maintenance candidates, and inbound Feishu open_id values still enter direct session keys without Feishu-specific malformed-id validation or repair.

## What This Changes

Feishu DM sessions can be rebuilt or forked after restart or session-store maintenance because direct-session rows are removable and multi-account Feishu open_id identity can create duplicate direct keys.

## Best Possible Solution

Adopt a maintainer-approved Feishu DM retention and identity repair plan with regression tests plus live or sanitized multi-account Feishu proof.
