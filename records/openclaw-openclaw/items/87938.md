## Summary

Keep open: current main and v2026.6.11 still only mitigate the Feishu DM session-continuity problem. Account-scoped DM keys are documented and implemented as a workaround, but direct DM rows remain maintenance-removable and Feishu inbound `open_id` values are still accepted into direct session keys without Feishu-specific malformed-id validation or repair.

## What This Changes

The issue reports Feishu direct-message sessions rebuilding after gateway restarts because accountless DM keys, malformed `open_id` variants, and session-store maintenance can create or prune duplicate direct-session rows.

## Best Possible Solution

Adopt a maintainer-approved Feishu DM continuity plan: account-aware routing remains the documented workaround, while the durable fix should combine bounded direct-DM retention with Feishu `open_id` validation and doctor/migration handling for existing malformed or duplicate keys.
