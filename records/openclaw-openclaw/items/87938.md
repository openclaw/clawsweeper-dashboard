## Summary

Keep open: current main and v2026.6.11 still only mitigate the Feishu DM session-continuity problem. Account-scoped DM keys are implemented and documented, but direct Feishu DM rows remain maintenance-removable and inbound Feishu sender IDs still become direct session keys without Feishu-specific malformed-id validation or repair.

## What This Changes

Feishu DM sessions can rebuild or fork after gateway restarts because direct session rows remain maintenance-removable and Feishu direct peer IDs are not validated or repaired.

## Best Possible Solution

Keep this open until maintainers choose a direct-DM retention policy and Feishu identity repair or migration plan, with per-account-channel-peer documented as the current multi-account workaround.
