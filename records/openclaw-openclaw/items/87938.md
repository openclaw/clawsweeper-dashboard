## Summary

Keep open: current main still leaves Feishu direct-message session continuity exposed to two reported failure classes. Account-scoped DM keys exist as a workaround, but direct rows remain generic maintenance prune candidates and Feishu inbound direct peer IDs are still accepted without Feishu-specific malformed-open-id validation or repair.

## What This Changes

The issue asks OpenClaw to stop Feishu DM sessions from rebuilding after gateway restarts by addressing direct-session maintenance pruning, multi-app DM key scoping, and malformed near-duplicate Feishu open_id keys.

## Best Possible Solution

Define a Feishu DM policy that validates malformed open_id peer IDs at the plugin boundary, keeps multi-account DMs account-scoped, and repairs existing duplicate or malformed direct keys through doctor/migration rather than runtime fallbacks.
