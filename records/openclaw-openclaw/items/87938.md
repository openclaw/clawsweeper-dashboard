## Summary

Keep open: current main and v2026.6.11 still only mitigate the reported Feishu DM session-continuity problem. Direct Feishu DM rows remain maintenance-removable, `per-channel-peer` still omits the account boundary, and Feishu inbound open IDs are still accepted into direct session keys without a Feishu-specific malformed-id repair path.

## What This Changes

The issue asks OpenClaw to stop Feishu DM session rebuilds by fixing direct-session maintenance pruning and Feishu open_id/session-key duplication in multi-account setups.

## Best Possible Solution

Keep this issue open until maintainers choose a Feishu direct-DM retention policy and Feishu identity repair plan, with `per-account-channel-peer` documented as the current multi-account workaround.
