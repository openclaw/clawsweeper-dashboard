## Summary

Keep open: current main still leaves Feishu direct-message sessions eligible for maintenance pruning/capping, and the documented account-scoped DM key remains a workaround rather than a repair for malformed or duplicate Feishu direct-session keys.

## What This Changes

The issue reports Feishu DM session keys being rebuilt or forked after gateway restart because direct sessions remain maintenance-removable and multi-app or malformed Feishu open_id values create duplicate direct-session keys.

## Best Possible Solution

Adopt maintainer-approved TTL-aware direct-DM preservation plus Feishu open_id validation or doctor repair, while keeping `per-account-channel-peer` as the documented multi-account workaround.
