## Repair Work Prompt

Fix the concurrent subagent orphan-recovery double-resume reported in https://github.com/openclaw/openclaw/issues/103724. Make recovery single-flight at the canonical registry/recovery lifecycle boundary so overlapping cold-restore, startup-sidecar, sweeper, and reactive scheduling requests cannot dispatch two resume turns for the same child session. Preserve retry semantics by keeping abortedLastRun true until gateway acceptance; do not add configuration, compatibility paths, or a guard that silently drops a recovery request arriving during an active scan. Coalesce such requests or run one follow-up pass. Add focused regression coverage that parks the first resume RPC, overlaps a second scheduling or recovery request with independent scan state, and proves one gateway dispatch, one registry remap or generation, the correct abort-state update, and later retry behavior. Keep the change scoped to recovery coordination and tests, and do not edit CHANGELOG.md.
