## Summary

Current main only partially fixes the report: plugin-opened Meet tabs are pinned to English, but the default tab-reuse and explicit recovery paths still run English-only selectors against pre-existing localized tabs. Keep this issue open, narrowed to those existing-tab paths, while crediting the merged mitigation as prior progress.

## What This Changes

Make Google Meet Chrome join, status, microphone, caption, and state detection work without silent failure when the Meet UI is not English.

## Best Possible Solution

Inspect a candidate existing tab’s document language before reuse: reuse English tabs, open a separate English-pinned tab for localized join automation without disrupting the existing tab, and make `recover_current_tab` return a clear unsupported-locale diagnostic rather than false state until locale-independent recovery is available.
