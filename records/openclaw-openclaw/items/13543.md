## Summary

Keep open: current main and v2026.6.11 still provide session-scoped sandbox activation plus sandbox tool allow/deny filtering, but not the requested per-tool host-vs-sandbox placement contract. The discussion also has unresolved security-boundary direction about whether this should be operator-configured, tool/plugin-declared, or folded into the broader sandbox model.

## What This Changes

The issue requests a schema-backed per-tool sandbox placement mode so selected tools can run isolated while trusted tools stay host-routed in the same session.

## Best Possible Solution

Define one documented core tool-placement contract with explicit precedence between session sandbox mode, tool/plugin declarations, browser and web_fetch behavior, gateway-owned tools, and elevated exec, then test placement separately from tool availability filtering.
