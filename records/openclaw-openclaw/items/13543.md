## Summary

Keep open: current main and v2026.6.11 still expose session-level sandbox activation plus sandbox tool allow/deny filtering, but not the requested per-tool host-vs-sandbox placement contract. The discussion and related PRs point to unresolved product/security design, not an already-implemented or superseded core change.

## What This Changes

Request to add schema-backed per-tool sandbox placement so tools like web_fetch and browser can always run isolated while trusted tools stay host-routed in the same session.

## Best Possible Solution

Define one documented core placement contract with explicit precedence between session sandbox mode, tool/plugin declarations, gateway-owned tools, browser/web_fetch behavior, and elevated exec, then test placement separately from tool availability filtering.

## Reproduction Assessment

Not applicable as a bug reproduction: this issue asks for a new execution-placement capability. Source and release inspection confirm current main and v2026.6.11 do not have the requested per-tool placement mode.

## Solution Assessment

No, not as the proposed always/never schema alone. The security goal is aligned, but maintainers should choose the placement owner, precedence model, and host-escape semantics before implementation.
