## Summary

Keep open: current main and v2026.6.11 still provide session-level sandbox activation plus sandbox tool allow/deny filtering, not a per-tool host-vs-sandbox placement contract. The issue discussion also shows unresolved product/security direction between an operator always/never map and a tool/plugin-declared gateway execution contract.

## What This Changes

Request a per-tool sandbox placement policy so tools such as web_fetch/browser can run in a sandbox while exec/message/cron/gateway remain host-routed in the same session.

## Best Possible Solution

Define one documented core placement contract with explicit precedence between sandbox mode, tool/plugin declarations, gateway-owned tools, browser/web_fetch behavior, and elevated exec, then test placement separately from tool availability filtering.

## Reproduction Assessment

Not applicable as a bug reproduction: this issue asks for a new execution-placement capability, and source plus release inspection confirm current OpenClaw has no per-tool placement mode.

## Solution Assessment

No, not as the proposed schema alone; the security goal is aligned, but maintainers should choose the placement owner and precedence model before committing to an always/never map or tool-declared gateway contract.
