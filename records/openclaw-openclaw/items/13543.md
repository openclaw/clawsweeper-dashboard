## Summary

Keep open: current main and the latest release still provide session-scoped sandbox activation, sandbox tool allow/deny filtering, browser sandbox settings, and exec/elevated routing, but not a schema-backed per-tool host-versus-sandbox placement contract. The remaining work is a security-boundary product decision rather than conservative cleanup.

## What This Changes

The issue requests a per-tool sandbox placement mode so tools such as `web_fetch` and `browser` can run in a sandbox while trusted tools such as `exec`, `message`, `cron`, and `gateway` stay host-routed in the same session.

## Best Possible Solution

Define one documented core tool-placement contract with explicit precedence between session sandbox mode, tool/plugin declarations, browser and web_fetch behavior, gateway-owned tools, and elevated exec, then test placement separately from tool availability filtering.
