## Summary

Keep open: current main and v2026.6.11 still provide session-scoped sandbox activation and sandbox tool allow/deny filtering, but not the requested per-tool host-vs-sandbox placement contract; the live discussion also shows unresolved product and security-boundary direction.

## What This Changes

The issue requests a schema-backed selective sandbox mode that can force tools such as web_fetch and browser into a sandbox while leaving trusted tools such as exec, message, cron, and gateway host-routed in the same session.

## Best Possible Solution

Define one documented core tool-placement contract with explicit precedence between session sandbox mode, tool/plugin declarations, browser and web_fetch behavior, gateway-owned tools, and elevated exec, then test placement separately from tool availability filtering.
