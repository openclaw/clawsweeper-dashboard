## Summary

Keep open: current main and v2026.6.11 still provide session-scoped sandbox modes, sandbox tool allow/deny filtering, and exec-specific host routing, but not the requested per-tool host-vs-sandbox placement contract; the discussion also shows unresolved product and security direction.

## What This Changes

Requests a core config/runtime capability to route selected tools to sandbox or host independently of the session sandbox mode.

## Best Possible Solution

Define one documented core placement contract with explicit precedence between session sandbox mode, tool/plugin declarations, gateway-owned tools, browser/web_fetch behavior, and elevated exec, then test placement separately from tool availability filtering.

## Reproduction Assessment

Not applicable as a bug reproduction; this asks for a new execution-placement capability, and source/release inspection confirms the placement mode is absent.

## Solution Assessment

No, not as the proposed always/never schema alone; the security goal is aligned, but maintainers should first choose the placement owner and precedence model.
