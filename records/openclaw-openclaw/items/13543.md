## Summary

Keep open: current main and the latest release still only provide session-scoped sandbox activation, sandbox tool allow/deny filtering, and exec elevated escape behavior; the requested per-tool host-vs-sandbox placement contract remains missing and still needs maintainer product/security direction.

## What This Changes

The issue requests schema-backed per-tool sandbox placement so selected tools such as web_fetch and browser can be forced into sandbox execution while trusted tools remain host-routed in the same session.

## Best Possible Solution

Keep this as the narrow canonical tracker until maintainers define one documented placement contract with explicit precedence between session sandbox mode, tool/plugin declarations, gateway-owned tools, browser/web_fetch behavior, and elevated exec.

## Reproduction Assessment

No bug reproduction is applicable because this is a new execution-placement capability request. Source and release inspection provide high-confidence proof that current main and v2026.6.11 do not have the requested per-tool placement mode.

## Solution Assessment

No, not as the proposed always/never schema alone. The security goal is aligned, but maintainers should first choose the placement owner and precedence model before committing to operator maps or tool-declared gateway escape semantics.
