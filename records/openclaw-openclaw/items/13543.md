## Summary

Keep open: current main and v2026.6.11 still expose session-scoped sandbox activation plus sandbox tool allow/deny filtering, not the requested per-tool host-vs-sandbox placement contract. The discussion also shows unresolved product/security direction between an operator always/never map and a tool/plugin-declared gateway execution contract.

## What This Changes

Request a schema-backed per-tool sandbox execution policy so tools such as web_fetch and browser can be sandboxed while exec, message, cron, and gateway remain host-routed in the same session.

## Best Possible Solution

Define one documented core tool-placement contract with explicit precedence between sandbox mode, tool/plugin declarations, gateway-owned tools, browser/web_fetch behavior, and elevated exec, then test placement separately from tool availability filtering.

## Reproduction Assessment

Not applicable as a bug reproduction: this issue asks for a new execution-placement capability. Source and release inspection confirm current main and v2026.6.11 do not have that per-tool placement mode.

## Solution Assessment

No, not as the proposed schema alone. The security goal is aligned, but maintainers should choose the placement owner and precedence model before committing to an always/never map or a tool-declared gateway contract.
