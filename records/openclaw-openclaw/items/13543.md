## Summary

Keep open: current main still has session/agent sandbox activation and sandbox tool allow/deny filtering, but not the requested per-tool host-vs-sandbox placement contract. The discussion also shows unresolved product/security direction around an operator `always`/`never` map versus a tool/plugin-declared gateway execution contract.

## What This Changes

The issue requests a per-tool sandbox placement policy so selected tools can run in an isolated sandbox while other tools stay host-routed in the same session.

## Best Possible Solution

Define one documented core placement contract with explicit precedence between sandbox mode, tool/plugin declarations, gateway-owned tools, browser/web_fetch behavior, and elevated exec, then test placement separately from tool availability filtering.

## Reproduction Assessment

Yes as source-level feature absence, not as a bug reproduction: current schema and runtime status code expose session/agent sandboxing and sandbox tool filtering, not per-tool placement.

## Solution Assessment

No for the proposed always/never map alone. The security goal is aligned, but maintainers should choose the placement owner and precedence model before committing to a specific schema.
