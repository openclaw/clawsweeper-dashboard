## Summary

Keep open: current `main` and v2026.6.11 still have session/agent-level sandbox activation plus sandbox tool allow/deny filtering, not the requested per-tool host-vs-sandbox placement contract. The discussion also shows unresolved product/security direction around whether selective sandboxing or a sandbox-default plus explicit gateway escape model is the right contract.

## What This Changes

The issue requests schema-backed per-tool sandbox placement so selected tools such as web fetch or browser can run in a sandbox while trusted tools remain host-routed in the same session.

## Best Possible Solution

Define a maintainer-approved core sandbox placement contract that keeps availability filtering, elevated exec, browser target selection, and gateway-only tools separate, then document and test the fresh-install and upgrade behavior.

## Reproduction Assessment

Not applicable as a bug reproduction: this issue asks for a new execution-placement capability. Source inspection does give high confidence that current `main` lacks the requested schema and runtime decision point.

## Solution Assessment

Unclear: the requested selective always/never schema is plausible, but it is not yet proven to be the best contract. The discussion raises an alternative where sandboxing is the default when enabled and only explicitly dangerous gateway-host tools opt out through a narrow manifest/config escape.
