## Summary

Keep open: current main still has session/agent-level sandbox activation, sandbox tool allow/deny filtering, browser target selection, and elevated exec, but not the requested per-tool host-vs-sandbox placement contract; the discussion also shows unresolved product/security direction.

## What This Changes

Add a schema-backed per-tool sandbox placement policy so tools like web_fetch and browser can be forced into a sandbox while trusted tools stay host-routed in the same session.

## Best Possible Solution

Define one documented core placement contract with explicit precedence across sandbox mode, gateway-owned tools, plugin/tool declarations, browser/web_fetch behavior, and elevated exec, then test placement separately from tool availability filtering.

## Reproduction Assessment

Not applicable as a bug reproduction: this issue asks for a new execution-placement capability. Source inspection confirms current main lacks that per-tool host-vs-sandbox placement contract.

## Solution Assessment

No, not as the proposed schema alone. The security goal is aligned, but maintainers should first choose the placement owner, threat model, and precedence model before implementing an always/never map or tool-declared gateway contract.
