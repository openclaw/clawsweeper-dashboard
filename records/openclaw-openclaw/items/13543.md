## Summary

Keep open: current `main` and the latest release still provide session-scoped sandbox activation, sandbox tool allow/deny filtering, browser target behavior, and exec/elevated host routing, but not a schema-backed per-tool placement policy for forcing `web_fetch`/`browser` into a sandbox while leaving trusted tools host-routed in the same session.

## What This Changes

Request to add schema-backed per-tool sandbox placement so selected tools such as `web_fetch` and `browser` can be forced into a sandbox while trusted tools such as `exec`, `message`, `cron`, and `gateway` remain host-routed in the same session.

## Best Possible Solution

Define one core tool-placement contract that cleanly separates where tools execute from which tools are allowed, then wire web/browser placement, exec/elevated behavior, schema/docs, and focused upgrade-safe tests around that contract.

Unclear: the requested selective mode is plausible, but the live discussion raises an alternate contract where sandboxed sessions inherit sandbox placement and only explicitly declared tools run on the gateway. Maintainers should choose that security model before code is queued.
