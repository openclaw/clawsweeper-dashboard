## Summary

Keep open: current main and v2026.6.11 still provide session-level sandbox modes plus sandbox tool allow/deny filtering, not the requested per-tool host-vs-sandbox placement contract, and the discussion shows unresolved product/security direction.

## What This Changes

The issue requests a schema-backed per-tool sandbox placement policy so untrusted tools can run in a sandbox while trusted tools stay on the host in the same session.

## Best Possible Solution

Define one documented core placement contract with explicit precedence between sandbox mode, tool/plugin declarations, gateway-owned tools, browser/web_fetch behavior, and elevated exec, then test placement separately from tool availability filtering.

## Reproduction Assessment

Not applicable as a bug reproduction: this issue asks for a new execution-placement capability. Source and release inspection confirm current main and v2026.6.11 do not have that per-tool placement mode.

## Solution Assessment

No, not as the proposed schema alone. The security goal is aligned, but maintainers should first choose the placement owner and precedence model before committing to an always/never map or a tool-declared gateway contract.
