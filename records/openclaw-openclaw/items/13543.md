## Summary

Keep open: current main and v2026.6.11 still have session-scoped sandboxing plus sandbox tool allow/deny filtering, not a per-tool host-vs-sandbox placement contract; the discussion also shows unresolved product and security direction.

## What This Changes

Request a schema-backed per-tool sandbox execution policy so web_fetch/browser can be sandboxed while exec/message/cron/gateway remain host-routed in the same session.

## Best Possible Solution

Define one documented core placement contract with explicit precedence between session sandbox mode, tool/plugin declarations, gateway-owned tools, browser/web_fetch behavior, and elevated exec, then test placement separately from tool availability filtering.
