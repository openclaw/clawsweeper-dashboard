## Summary

Keep open: current main and v2026.6.11 still expose session-scoped sandboxing, sandbox tool filtering, browser sandbox settings, and exec elevated escape behavior, but not the requested per-tool host-vs-sandbox placement contract; the discussion also shows unresolved product/security direction.

## What This Changes

Request a schema-backed policy to force selected tools such as web_fetch and browser into a sandbox while trusted tools remain host-routed in the same session.

## Best Possible Solution

Define one documented core placement contract with explicit precedence between session sandbox mode, tool/plugin declarations, gateway-owned tools, browser/web_fetch behavior, and elevated exec, then test placement separately from tool availability filtering.

## Reproduction Assessment

Not applicable as a bug reproduction: this issue asks for a new execution-placement capability. Source and release inspection confirm current main and v2026.6.11 do not have that per-tool placement mode.

## Solution Assessment

No, not as the proposed always/never schema alone. The security goal is aligned, but maintainers should first choose the placement owner, precedence model, and tool/plugin boundary before committing to operator maps or tool-declared gateway escape semantics.
