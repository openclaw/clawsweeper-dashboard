## Summary

Keep open: current main still has session/agent-level sandbox activation and sandbox tool allow/deny filtering, but not a schema-backed per-tool host-vs-sandbox placement contract; the discussion also shows the security/product direction is not settled.

## What This Changes

Request a per-tool sandbox placement mode that can force untrusted tools such as web_fetch and browser into sandbox execution while keeping trusted tools host-routed in the same session.

## Best Possible Solution

Define one documented core placement contract with explicit precedence between session sandbox mode, tool/plugin declarations, gateway-owned tools, browser/web_fetch behavior, and elevated exec, then test placement separately from tool availability filtering.

## Reproduction Assessment

Not applicable as a bug reproduction: this issue asks for a new execution-placement capability. Source inspection gives high confidence that current main lacks the requested per-tool placement mode.

## Solution Assessment

No, not as the proposed always/never schema alone. The security goal is aligned, but maintainers should first choose the placement owner and precedence model before committing to operator maps or tool-declared gateway escape semantics.
