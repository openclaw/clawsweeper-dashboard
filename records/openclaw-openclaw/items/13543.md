## Summary

Keep open: current main and v2026.6.11 still have session-scoped sandbox activation plus sandbox tool allow/deny filtering, but no schema-backed per-tool host-vs-sandbox placement contract; the issue discussion also leaves the product and security model unresolved.

## What This Changes

Request to add tool-level sandbox placement so selected tools such as web_fetch and browser run in a sandbox while trusted tools stay host-routed in the same session.

## Best Possible Solution

Define one documented core placement contract with explicit precedence between session sandbox mode, tool/plugin declarations, gateway-owned tools, browser/web_fetch behavior, and elevated exec, then test placement separately from tool availability filtering.

## Reproduction Assessment

Not applicable as a bug reproduction: this issue asks for a new execution-placement capability. Source and release inspection confirm current main and v2026.6.11 do not have that per-tool placement mode.

## Solution Assessment

No, not as the proposed always/never schema alone. The security goal is aligned, but maintainers should first choose the placement owner and precedence model before committing to operator maps or tool-declared gateway escape semantics.
