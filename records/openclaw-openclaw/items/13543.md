## Summary

Keep open: current main and v2026.6.11 still have session/agent sandbox modes, sandbox allow/deny filtering, browser sandbox settings, and exec host/elevated routing, but not the requested per-tool host-vs-sandbox placement contract; the discussion also shows unresolved product/security direction.

## What This Changes

Request to add schema-backed per-tool sandbox placement so tools like web_fetch and browser can be sandbox-routed while exec, message, cron, and gateway remain host-routed in the same session.

## Best Possible Solution

Define one documented core placement contract with explicit precedence between session sandbox mode, tool/plugin declarations, gateway-owned tools, browser/web_fetch behavior, and elevated exec, then test placement separately from tool availability filtering.

## Reproduction Assessment

Not applicable as a bug reproduction: this issue asks for a new execution-placement capability. Source and release inspection confirm current main and v2026.6.11 do not have the requested per-tool placement mode.

## Solution Assessment

No, not as the proposed schema alone. The security goal is aligned, but maintainers should first choose the placement owner and precedence model before committing to an always/never map or a tool-declared gateway contract.
