## Summary

Keep open: current main and v2026.6.11 still provide session-scoped sandbox activation plus sandbox tool allow/deny filtering, but not the requested per-tool host-vs-sandbox placement contract; the discussion also shows unresolved product/security direction.

## What This Changes

The issue requests schema-backed per-tool sandbox placement so untrusted-content tools such as web_fetch and browser can run in a sandbox while trusted tools such as exec, message, cron, and gateway remain host-routed in the same session.

## Best Possible Solution

Define one documented core placement contract with explicit precedence between session sandbox mode, tool/plugin declarations, gateway-owned tools, browser/web_fetch behavior, and elevated exec, then test placement separately from tool availability filtering.
