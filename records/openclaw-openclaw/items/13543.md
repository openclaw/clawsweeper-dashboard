## Summary

Keep open: current main and v2026.6.11 still provide session-level sandbox activation, sandbox tool allow/deny filtering, browser target selection, and exec host/elevated controls, but not the requested per-tool host-vs-sandbox placement contract. The remaining work is security-sensitive product design, not a stale or already-implemented cleanup item.

## What This Changes

Request a schema-backed tool-level sandbox placement policy that can force selected tools such as web_fetch and browser into sandboxed execution while keeping trusted tools host-routed in the same session.

## Best Possible Solution

Define one documented core placement contract with explicit precedence between sandbox mode, tool/plugin declarations, gateway-owned tools, web_fetch/browser behavior, and elevated exec, then implement schema, docs, and tests around that contract.

## Reproduction Assessment

Not applicable as a bug reproduction: this issue asks for a new execution-placement capability. Source and release inspection show current main and v2026.6.11 do not have that per-tool placement mode.

## Solution Assessment

No, not as the proposed schema alone. The security goal is aligned, but maintainers should first choose the placement owner and precedence model before committing to an always/never map or a tool-declared gateway contract.
