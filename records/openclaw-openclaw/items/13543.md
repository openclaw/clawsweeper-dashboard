## Summary

Keep open: current main and the latest release still expose session-scoped sandbox activation, sandbox tool allow/deny filtering, browser target selection, and exec host/elevated routing, but not the requested schema-backed per-tool host-versus-sandbox placement contract. The remaining work is security-boundary product design, not conservative cleanup.

## What This Changes

The issue requests a schema-backed per-tool sandbox placement mode so selected tools can run in an isolated backend while other tools remain host-routed in the same session.

## Best Possible Solution

Define one documented core tool-placement contract with explicit precedence between session sandbox mode, tool/plugin declarations, browser and web_fetch behavior, gateway-owned tools, and elevated exec, then test placement separately from tool availability filtering.
