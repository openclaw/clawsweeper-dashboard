## Summary

Keep open: current main and the latest release still provide session-level sandbox activation plus sandbox tool allow/deny filtering, but not the requested per-tool host-vs-sandbox placement contract. The remaining work is a security-boundary and product-direction decision, especially after the discussion questioned whether operator always/never config is the right model.

## What This Changes

The issue requests a per-tool sandbox placement policy so selected tools can run inside a sandbox while others remain host-routed in the same session.

## Best Possible Solution

Define one documented core placement contract with explicit precedence between session sandbox mode, tool/plugin declarations, browser and web_fetch behavior, gateway-owned tools, cron, and elevated exec, then test placement separately from tool availability filtering.
