## Summary

The linked retry bug remains valid, but this patch is not safe to merge because it treats any parenthesized three-digit number as an HTTP status across a shared error-classification surface, allowing permanent non-HTTP errors to be retried or misclassified.

## What This Changes

The PR adds fallback parsing for parenthesized HTTP status codes in provider-wrapped error messages so transient 5xx responses can trigger session retry.

## Best Possible Solution

Keep leading-status parsing strict, add an anchored parser for the repository's structured provider error envelopes such as `<provider> API error (<status>):`, and cover both exact OpenAI/Azure/Mistral positives and unrelated parenthesized-number negatives through the production retry classifier.

## Solution Assessment

No. Recognizing the repository's structured provider envelope is appropriate, but matching any parenthesized three-digit number anywhere in a widely shared helper is broader than the required fix and reintroduces false-positive status inference.
