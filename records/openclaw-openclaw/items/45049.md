## Label Justifications

- `P1`: The issue affects real tool-enabled agent workflows and can cause users to receive fabricated tool-use claims or miss intended actions.
- `impact:security`: The report concerns the protocol boundary for tool invocation, pre-execution hooks, policy checks, and execution provenance.
- `impact:message-loss`: When a model emits prose or fake tool text instead of a structured call, the intended tool-mediated action or reply can be silently skipped.
- `impact:session-state`: The failure leaves transcripts with assistant claims or fake result text that are not backed by matching tool-call/tool-result ledger entries.

## Summary

Keep open: current main still lacks a general agent-loop contract for fake tool-call text. The merged Gateway HTTP `tool_choice` work is useful, but it is scoped to caller-supplied HTTP client tools; core agent turns still need a maintainer security/product decision on warning, suppression, bounded promotion, retry, or fail-closed behavior.

## What This Changes

The issue asks OpenClaw to prevent agents from treating text that simulates tool use as a successful tool invocation, especially for local OpenAI-compatible models that need forced tool calls.

## Best Possible Solution

Define a maintainer-approved protocol-boundary contract for agent turns: real execution must stay structured and hook-visible, while fake tool-call text has explicit behavior for warning, suppression, promotion, retry, or fail-closed handling with focused coverage across agent loop, provider wrappers, Gateway HTTP, and local-model docs.

## Reproduction Assessment

Yes, from source inspection. Current main still has a structured-only dispatch boundary plus warning-only diagnostics for fake tool text, and no general retry or fail-closed gate for turns that needed a real tool call.

## Solution Assessment

Unclear. A protocol boundary is the right layer, but maintainers still need to choose the default behavior for fake text, bounded promotion, forced tool choice, retries, suppression, and local-model compatibility.
