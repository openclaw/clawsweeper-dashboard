## Label Justifications

- `P1`: The issue describes a broken real-agent tool workflow where enabled tools can be skipped while the user receives fabricated or simulated tool-use text.
- `impact:security`: The report concerns the protocol boundary for tool invocation, hook accounting, policy checks, and prompt-injection-resistant execution provenance.
- `impact:message-loss`: When a model emits prose or fake tool text instead of a real tool call, the intended tool-mediated action or result message can be silently skipped.
- `impact:session-state`: The transcript can record assistant claims or fake result text that are not backed by matching tool-call and tool-result ledger entries.

## Summary

Keep open because current main still treats fake tool-call-shaped assistant text as text with diagnostics, while the merged Gateway HTTP tool_choice work only covers caller-supplied HTTP client tools and does not implement the requested general agent-loop enforcement.

## What This Changes

The issue requests stricter agent-loop handling so models cannot satisfy tool-required prompts by emitting prose or JSON-looking text instead of real structured tool calls.

## Best Possible Solution

Define a maintainer-approved agent-turn contract that keeps real execution protocol-visible, composes with bounded text promotion, and adds focused coverage for local models, Gateway HTTP tools, provider streams, and final response delivery.

## Reproduction Assessment

Yes at source level: current main detects fake tool-call-shaped text, logs a warning, and continues treating it as text unless the narrow standalone promotion path applies; no live local-model repro was run in this read-only pass.

## Solution Assessment

No current solution is complete: the Gateway HTTP enforcement PR is useful but scoped, and the best fix needs a maintainer-approved policy for strict rejection, retry, suppression, or promotion at the agent-loop boundary.
