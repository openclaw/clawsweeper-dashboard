## Summary

Keep open: current main still dispatches tools only from structured toolCall/toolUse turns, while fake tool-shaped assistant text is logged as text and a bounded standalone-text promotion path still exists. The merged Gateway HTTP tool_choice work is useful and shipped, but it is scoped to caller-supplied HTTP tools, not the general agent-loop enforcement this issue asks for.

## What This Changes

The issue asks OpenClaw to prevent models from simulating tool calls in assistant text and to enforce real structured tool invocation in agent turns.

## Best Possible Solution

Define a maintainer-approved protocol-boundary contract for agent turns: real execution stays structured and hook-visible, fake tool-call text has explicit warning, suppression, promotion, retry, or fail-closed behavior, and local-model docs/tests cover the chosen compatibility story.
