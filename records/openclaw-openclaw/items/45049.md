## Label Justifications

- `P1`: The issue describes a broken agent/tool workflow that can deliver fabricated tool-use claims or skip required actions in real tool-enabled sessions.
- `impact:security`: The report concerns protocol-boundary enforcement for tool invocation, hook/policy visibility, and prompt-injection-resistant execution provenance.
- `impact:message-loss`: When the model emits prose or fake tool text instead of a real call, the intended tool-mediated action or reply can be silently skipped.
- `impact:session-state`: The failure leaves transcripts with assistant claims or fake result text that are not backed by matching tool-call/tool-result ledger entries.

## Summary

Keep open: current main still has only warning/limited-promotion behavior for assistant text that looks like a tool call, while the general agent-loop policy for strict enforcement, retry, suppression, or fail-closed behavior remains unresolved and security-sensitive.

## What This Changes

The issue reports that OpenClaw can finish an agent turn with assistant text that simulates or claims tool use instead of requiring a structured tool invocation.

## Best Possible Solution

Define a maintainer-approved agent-turn contract that keeps real tool execution protocol-visible, reconciles the existing bounded promotion path with strict fake-tool handling, and adds focused coverage for local models, provider streams, Gateway HTTP tools, and final response delivery.

## Reproduction Assessment

Yes, from source inspection. Current main still has a structured-only dispatch gate, warning-only fake-tool-text diagnostics, and no general retry or fail-closed path when a turn produces no structured `toolCall`.

## Solution Assessment

Unclear. A protocol boundary is the right layer, but maintainers still need to choose the default behavior for fake text, bounded promotion, forced tool choice, retries, suppression, and local-model compatibility.
