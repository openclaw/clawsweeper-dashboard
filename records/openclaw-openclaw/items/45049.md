## Summary

Keep open: current main fixed the OpenAI-compatible Gateway HTTP `tool_choice` subcase and documents/logs unsafe raw tool-looking assistant text, but the agent runtime still intentionally promotes some standalone assistant text into executable `toolCall` blocks for local-model compatibility. The remaining security and compatibility boundary needs maintainer direction rather than cleanup closure.

## What This Changes

The issue requests a stricter agent/tool-call boundary so simulated or text-only tool calls cannot be mistaken for completed executable tool invocations.

## Best Possible Solution

Settle the security contract first, then make assistant text non-executable by default with any local-model repair path explicit, documented, tested, and audit-visible.
