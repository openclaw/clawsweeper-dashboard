## Label Justifications

- `P1`: The issue affects real tool-enabled agent workflows and can leave users with fabricated tool-use claims or skipped intended actions.
- `impact:security`: The report concerns the protocol boundary for real tool invocation, pre-execution hooks, policy checks, and execution provenance.
- `impact:message-loss`: When a model emits prose or fake tool text instead of a structured call, the intended tool-mediated action or reply can be silently skipped.
- `impact:session-state`: The failure can leave transcripts with assistant claims or fake result text that are not backed by matching tool-call and tool-result ledger entries.

## Summary

Keep open: current main and the latest release still leave fake tool-call-shaped assistant text as warning-only text or bounded compatibility promotion, while the shipped Gateway tool_choice work only covers HTTP client tools.

## What This Changes

Request to make agent turns enforce real structured tool invocation, retry, or fail closed when a model emits simulated tool calls in assistant text.

## Best Possible Solution

Define a maintainer-approved protocol-boundary contract: real execution stays structured and hook-visible, fake tool-call text gets explicit warning, suppression, promotion, retry, or fail-closed behavior, and local-model docs/tests cover the chosen compatibility story.
