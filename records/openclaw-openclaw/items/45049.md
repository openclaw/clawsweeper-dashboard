## Summary

Keep open: current main and the latest release still preserve two different behaviors around simulated tool calls, with unstructured fake calls treated as warning-only text while standalone bracketed/XML-style tool-call text is promoted into structured tool calls for local-model compatibility. That is not a cleanup close because the remaining question is a real security and compatibility boundary.

## What This Changes

The issue asks OpenClaw to enforce the tool-call protocol so models cannot satisfy tool-required turns by emitting prose or serialized fake tool calls instead of structured tool calls.

## Best Possible Solution

Define one maintainer-owned protocol policy for assistant-authored tool-call text: structured tool calls should be authoritative by default, and any local-model text promotion that remains should be explicit, audited, documented, and covered by hook/ledger tests.

- **Default strict protocol (recommended):** Disable or default-off text-to-tool-call promotion, keep warning/scrubbing for fake calls, and require users to fix provider parsing or opt into a clearly named compatibility mode.

- **Defer to hard-gate design:** Leave this issue open as a narrow input into the broader pre-response enforcement design tracked in the related hard-gate issue.
