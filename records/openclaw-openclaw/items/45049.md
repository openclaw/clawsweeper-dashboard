- `P1`: The issue affects real tool-enabled agent workflows and can leave users with fabricated tool-use claims or skipped intended actions.
- `impact:security`: The report concerns the protocol boundary for real tool invocation, pre-execution hooks, policy checks, and execution provenance.

## Summary

Keep open: current main still treats unstructured tool-call-shaped assistant text as text with diagnostics, while the merged Gateway tool_choice work only covers OpenAI-compatible HTTP client-tool requests, so the central agent-loop enforcement/default behavior remains unresolved.

## What This Changes

The issue asks OpenClaw to prevent or recover from assistant text that simulates tool calls instead of emitting structured tool invocations.

## Best Possible Solution

Define a maintainer-approved protocol-boundary contract: real execution stays structured and hook-visible, while fake tool-call text gets explicit warning, suppression, promotion, retry, or fail-closed behavior with docs and regression coverage.
