## Summary

Keep open: current main and v2026.6.11 still leave fake tool-call-looking assistant text as warning-only text or bounded compatibility promotion, while the merged Gateway tool_choice work only covers caller-supplied HTTP client tools.

## What This Changes

The issue requests stricter agent-loop handling when a model emits tool-call-looking text instead of structured tool calls.

## Best Possible Solution

Define a maintainer-approved protocol-boundary contract: real execution stays structured and hook-visible, fake tool-call text gets explicit warning, suppression, promotion, retry, or fail-closed behavior, and local-model docs/tests cover the chosen compatibility story.
