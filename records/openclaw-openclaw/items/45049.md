## Label Justifications

- `P1`: The issue affects real tool-enabled agent workflows and can leave users with fabricated tool-use claims or skipped intended actions.
- `impact:security`: The report concerns the protocol boundary for real tool invocation, pre-execution hooks, policy checks, and execution provenance.
- `impact:message-loss`: When a model emits prose or fake tool text instead of a structured call, the intended tool-mediated response or action can be silently skipped.
- `impact:session-state`: The failure can leave transcripts with assistant claims or fake result text that are not backed by matching tool-call and tool-result ledger entries.

## Summary

Keep open: current main still treats unstructured tool-call-shaped assistant text as text with diagnostics, while the shipped Gateway tool_choice work only covers OpenAI-compatible HTTP client tools, so the central agent-loop enforcement/default behavior remains unresolved.

## What This Changes

The issue requests stricter agent-loop handling for model-emitted text that looks like tool usage so fake tool calls are not accepted as completed work.

## Best Possible Solution

Define a maintainer-approved protocol-boundary contract: real execution must stay structured and hook-visible, and fake tool-call text should have explicit warning, suppression, promotion, retry, or fail-closed behavior with local-model docs and focused regression coverage.
