## Summary

Close: this PR is superseded by the open proof-positive ledger-scoped fix at https://github.com/openclaw/openclaw/pull/100666; this branch removes the scan but changes byte retention to the whole shared SQLite database, which can incorrectly trim ACP replay state because unrelated tables count toward the limit.

## What This Changes

The branch changes ACP SQLite replay byte retention from aggregate replay-table size scans to `PRAGMA page_count * page_size` and adds a test asserting the aggregate SQL is no longer prepared.

## Best Possible Solution

Close this branch and focus review on https://github.com/openclaw/openclaw/pull/100666, or an equivalent ledger-scoped cached/delta byte-accounting fix that preserves ACP replay retention semantics.

## Solution Assessment

No. Removing repeated scans is the right goal, but this page-count implementation changes the retention owner boundary to the whole shared state DB; ledger-scoped cached or delta accounting is the safer fix shape.
