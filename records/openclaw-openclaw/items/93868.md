## Summary

The PR remains useful and its real Gateway proof is credible, but the current three-way merge changes fallback eligibility from speech-core’s canonical provider-specific configured check to the UI diagnostics check. Because `isConfigured` is a public plugin contract and current main can supply a provider-owned default timeout, this compatibility regression should be fixed before merge.

## What This Changes

The PR makes Gateway `tts.status` yield before provider diagnostics, reuses one config-aware provider inventory and configured-state pass for status and fallback filtering, and adds focused speech-core and Gateway tests.

## Best Possible Solution

Keep the yield and single inventory, but cache the canonical speech-core configured-state result for each provider—including provider-specific timeout resolution—and use that same exact result for both `providerStates` and fallback filtering.
