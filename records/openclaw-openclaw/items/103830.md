## Label Justifications

- `P1`: A single interrupted provider stream can poison active session history and cause repeated rejection of subsequent agent turns.
- `impact:data-loss`: The reported practical recovery is to discard or reset the affected session, losing its conversational history.
- `impact:session-state`: Malformed thinking metadata is persisted in conversation history and makes deterministic session replay unusable.

## Summary

Current main still allows an interrupted Anthropic thinking block to retain a partial streamed signature in finalized or retained output, while the direct candidate fix closed unmerged for an administrative PR-limit reason. The existing rejection-time retry and transcript rewrite provide defense in depth but do not remove this write-time corruption path, so the focused stability bug remains necessary.

## What This Changes

Prevent interrupted Anthropic extended-thinking signatures from being persisted and breaking subsequent session replay.

## Best Possible Solution

Use the existing content-block lifecycle as the integrity boundary: before every finalization path that retains partial output, replace only non-empty provider signatures from thinking blocks still open without content_block_stop with the established replay-safe representation, preserve completed and redacted signatures byte-for-byte, and retain rejection-time transcript repair for legacy poisoned sessions.

## Reproduction Assessment

Yes, at source level with high confidence. On current main, start a thinking block, append a non-empty signature_delta, omit content_block_stop, and terminate the stream; the partial signature remains on output handled by the success or partial-failure finalization path.

## Solution Assessment

Yes in direction. Tracking whether content_block_stop occurred is narrower and safer than inspecting opaque signature bytes, but regression coverage should include every termination path that can retain partial output rather than only a clean early stream end.
