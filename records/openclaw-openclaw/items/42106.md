## Summary

Keep open: current main and the latest stable release still consume the paragraph separator in the shared block-streaming chunker, and the two linked closing PRs are open candidate fixes rather than merged implementation.

## What This Changes

The issue reports that block streaming can remove blank-line paragraph boundaries when multi-paragraph Markdown is split across streamed deliveries.

## Best Possible Solution

Fix the shared chunker/coalescer boundary so paragraph semantics survive streamed delivery boundaries, preferably by reviewing or consolidating one of the open candidate PRs with regression coverage for both separator preservation and no doubled separators.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: a `flushOnParagraph` chunk emits text before the blank-line separator and then advances past that separator, while the coalescer can only add a joiner before a flush. I did not run a runtime test in this read-only review.

## Solution Assessment

Yes for the issue direction: the shared chunker/coalescer boundary is the right layer because downstream channel clients only receive plain text after a flush. The remaining solution choice is which open candidate or boundary representation maintainers want to standardize.
