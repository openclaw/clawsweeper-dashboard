## Summary

Keep open: current main and the latest release still consume paragraph separators in the shared block-streaming path, and two open closing PRs already target the bug pending maintainer choice of boundary semantics.

## What This Changes

The issue asks OpenClaw to preserve Markdown paragraph separators when a block-streamed reply is reconstructed across multiple streamed deliveries.

## Best Possible Solution

Land one consolidated shared chunker/coalescer fix that preserves paragraph boundaries across ordinary and near-maxChars splits without doubled separators, then close this issue when the fix merges.
