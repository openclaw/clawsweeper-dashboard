## Summary

Keep open: current main and the latest release still consume paragraph separators in the shared block-streaming chunker, and the two open closing PRs are candidate fixes rather than merged implementation.

## What This Changes

The issue requests preserving paragraph separators when block-streamed replies are reconstructed across multiple streamed deliveries.

## Best Possible Solution

Land one consolidated shared chunker/coalescer fix that preserves paragraph boundaries across streamed deliveries without doubled separators or over-limit chunks, then close this issue from the merged PR.

## Reproduction Assessment

Yes, source-level. Current main emits a paragraph chunk before the separator, advances past the matched newlines, and downstream coalescing can only add joiners while chunks stay in one buffered flush.

## Solution Assessment

Yes. The fix belongs in the shared chunker/coalescer streaming boundary; a channel-specific join rule cannot reliably distinguish paragraph boundaries from size or timing splits.
