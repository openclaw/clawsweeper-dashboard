## Summary

Keep open. Current main and v2026.6.11 still lack the requested Discord autoThread follow-up mention gate, while existing Discord autoThread and bound-thread paths continue to bypass mention requirements before no-mention drops run.

## What This Changes

Request adds a Discord per-channel policy that lets an autoThread starter trigger without a mention but requires explicit mentions for later replies in that thread.

## Best Possible Solution

Define an additive Discord-owned opt-in policy for autoThread follow-up replies that preserves current defaults, documents the config shape, and coordinates with the separate parent/thread override design.

## Reproduction Assessment

Yes, source-level. Current main still clears the mention requirement for bot-owned autoThreads and bound thread sessions, and the strict config schema lacks the requested thread-reply gate.

## Solution Assessment

Unclear until maintainers choose the public API. The safest implementation is an additive Discord opt-in policy, not an unconditional default change or the existing ordinary parent/thread override alone.
