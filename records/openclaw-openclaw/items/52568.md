## Summary

Keep open. Current main and v2026.6.11 still preserve Discord's bot-owned autoThread mention bypass, the strict Discord config schema has no thread-reply mention gate, and the related open issue tracks overlapping but different parent-thread semantics.

## What This Changes

Request an additive Discord per-channel config option so autoThread starter messages can be handled without mentions while later replies in the created thread require an explicit mention.

## Best Possible Solution

Add an additive Discord-owned opt-in policy for autoThread follow-up mention gating, with schema/types/docs/tests, and coordinate naming and semantics with https://github.com/openclaw/openclaw/issues/75938.

## Reproduction Assessment

Yes. Source inspection shows bot-owned autoThreads currently clear the mention requirement before the no-mention drop path, and the strict config schema lacks the requested thread-reply gate; no live Discord repro was run for this read-only cleanup review.

## Solution Assessment

Unclear until maintainers choose the public API. The safest direction is an additive opt-in Discord policy, not an unconditional default change or the existing ordinary thread override alone.
