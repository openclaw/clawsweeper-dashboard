## Summary

Keep open. Current main and v2026.6.11 still preserve Discord's bot-owned autoThread mention bypass, the Discord config schema has no thread-reply mention gate, and the related implementation PR was closed unmerged while the nearest open issue asks for different parent/thread semantics.

## What This Changes

The issue requests an additive Discord per-channel option that allows an unmentioned autoThread starter message to create a thread, then requires explicit mentions for later replies in that bot-created thread.

## Best Possible Solution

Define an additive Discord-owned autoThread follow-up mention policy that preserves current defaults, documents the new config shape, and coordinates with the separate parent/thread override design.

## Reproduction Assessment

Yes. Source inspection on current main shows bot-owned autoThreads clear the mention requirement before the no-mention drop path, and the strict Discord config schema lacks the requested thread-reply gate.

## Solution Assessment

Unclear until maintainers choose the public API. The safest direction is an additive opt-in Discord policy, not an unconditional default change or the existing ordinary thread override alone.
