## Summary

Keep open. Current main and v2026.6.11 still preserve Discord's bot-owned autoThread mention bypass, the requested thread-reply mention-gate config is absent, and the remaining work needs a maintainer API/product decision.

## What This Changes

Request adding a Discord per-channel option so autoThread starter messages can trigger without mention while follow-up thread replies require an explicit mention.

## Best Possible Solution

Define an additive Discord-owned thread-reply mention policy that preserves current defaults, documents the config shape, and coordinates with the separate parent/thread override design.

## Reproduction Assessment

Yes, source-level. Current main shows bot-owned autoThreads clear the mention requirement before the no-mention drop path, and the strict Discord config schema lacks the requested thread-reply gate.

## Solution Assessment

Unclear until maintainers choose the public API. The safest direction is an additive opt-in Discord policy, likely informed by Slack's thread.requireExplicitMention pattern, rather than an unconditional default change.
