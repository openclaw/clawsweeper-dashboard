## Summary

Keep open. Current main and v2026.6.11 still preserve Discord's bot-owned autoThread mention bypass, and the related Discord thread override work only partially overlaps because it asks for different thread semantics and its PR is closed unmerged.

## What This Changes

The issue requests a Discord channel option that lets auto-thread starter messages respond without a mention while requiring explicit mentions for later replies in the same thread.

## Best Possible Solution

Define an additive Discord-owned thread-reply mention policy, likely modeled on Slack's explicit thread mention option, that preserves current defaults and adds source, docs, schema, type, and preflight tests.

## Reproduction Assessment

Yes, source-level. Current main exposes only guild/channel boolean requireMention, and resolveDiscordShouldRequireMention clears the mention requirement for bot-owned autoThreads before no-mention drops run.

## Solution Assessment

Unclear until maintainers choose the public API. The safest direction is an additive opt-in Discord policy, not an unconditional default change or the adjacent ordinary-thread override alone.
