## Summary

Keep open. Current main and v2026.6.11 still preserve Discord bot-owned autoThread follow-up replies as mention-bypass traffic, and the closest related thread-override issue tracks a different parent-versus-thread policy rather than this starter-versus-follow-up gate.

## What This Changes

Request an additive Discord per-channel option so autoThread can respond to the starter message but require an explicit mention for later replies in the created thread.

## Best Possible Solution

Define an additive Discord-owned thread-reply mention policy that can opt bot-owned autoThread follow-ups into mention gating while preserving current defaults and coordinating with the related parent/thread override work.

## Reproduction Assessment

Yes, source-level. Current main resolves bot-owned Discord autoThread follow-ups to no mention requirement, and the no-mention drop path only runs when that resolved flag remains true.

## Solution Assessment

Unclear until maintainers choose the public API. The safest direction is an additive opt-in Discord policy, likely aligned with the Slack explicit-thread-mention precedent, rather than an unconditional default change.
