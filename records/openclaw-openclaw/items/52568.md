## Summary

Keep open. Current main and v2026.6.11 still preserve Discord bot-owned autoThread mention bypass, there is no thread-reply mention-gate config key, and the related implementation PR was closed unmerged while the nearby open issue covers different parent/thread override semantics.

## What This Changes

The issue requests a Discord config option that lets an auto-thread starter message run without an explicit mention while requiring explicit mentions for later replies in that same thread.

## Best Possible Solution

Define an additive Discord-owned autoThread follow-up mention policy that preserves current defaults, documents the new config shape, and coordinates with the separate parent/thread override design.

## Reproduction Assessment

Yes. Source inspection on current main shows bot-owned autoThreads clear the mention requirement before the no-mention drop path, and the strict config schema lacks the requested thread-reply gate.

## Solution Assessment

Unclear until maintainers choose the public API. The safest direction is an additive opt-in Discord policy, not an unconditional default change or the existing ordinary thread override alone.
