## Summary

Keep open. Current main and v2026.6.11 still preserve the Discord bot-owned autoThread mention bypass, and the related open thread override request is only a partial overlap because it asks for different thread semantics.

## What This Changes

Request an additive Discord channel configuration that responds to the autoThread starter without a mention but requires an explicit mention for later replies in that bot-created thread.

## Best Possible Solution

Define an additive Discord-owned thread-reply mention policy that can opt bot-owned autoThread follow-ups into explicit mention gating while preserving current defaults and coordinating with the broader thread override design.

## Reproduction Assessment

Yes, source-level. Current main resolves bot-owned autoThread threads to no mention requirement before the no-mention drop path, so unmentioned follow-up replies are admitted.

## Solution Assessment

Unclear until maintainers choose the public API. The safest direction is an additive opt-in Discord policy, not an unconditional default change or the closed ordinary-thread override alone.
