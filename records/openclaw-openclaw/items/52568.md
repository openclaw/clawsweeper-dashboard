## Summary

Keep open. Current main and v2026.6.11 still preserve Discord's bot-owned autoThread mention bypass, the requested thread-reply mention gate is absent from the public Discord config schema, and the related implementation PR was closed unmerged while a partially overlapping issue asks for different semantics.

## What This Changes

Add an opt-in Discord per-channel policy so autoThread starter messages can be handled without mention while follow-up replies in the created thread require an explicit mention.

## Best Possible Solution

Define an additive Discord-owned autoThread follow-up mention policy that preserves current defaults, documents the config shape, and coordinates with the separate parent/thread override design.

## Reproduction Assessment

Yes, source-level. Current main still clears the mention requirement for bot-owned autoThreads, and the strict Discord config schema lacks the requested thread-reply gate.

## Solution Assessment

Unclear until maintainers choose the public API. The safest direction is an additive opt-in Discord policy, not an unconditional default change or the closed ordinary thread override PR alone.
