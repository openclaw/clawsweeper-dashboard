## Summary

Keep open. Current main and v2026.6.11 still preserve Discord's bot-owned autoThread mention bypass, Discord has no opt-in thread-reply mention gate, and the related parent/thread override work only partially overlaps this starter-versus-follow-up request.

## What This Changes

Request an opt-in Discord per-channel config that lets autoThread starter messages invoke the agent but requires an explicit mention for later replies in the created thread.

## Best Possible Solution

Define an additive Discord-owned thread-reply mention policy that can opt bot-owned autoThread follow-ups into mention gating while preserving current defaults, updating schema/types/docs/tests, and coordinating with the related thread override issue.

## Reproduction Assessment

Yes, source-level. Current main resolves bot-owned Discord autoThread threads to no mention requirement before the no-mention drop path, so unmentioned follow-up replies are admitted.

## Solution Assessment

Unclear until maintainers choose the public API. The safest direction is an additive opt-in Discord policy, not an unconditional default change or the related parent/thread override alone.
