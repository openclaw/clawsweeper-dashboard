## Summary

Keep open. Current main still preserves Discord bot-owned autoThread mention bypass, lacks a thread-reply mention-gate config field, and the closest implementation PR was closed unmerged while the related open issue covers different parent/thread override semantics.

## What This Changes

Request an opt-in Discord policy/config that responds to the autoThread starter without a mention but requires an explicit mention for later replies in that thread.

## Best Possible Solution

Define an additive Discord-owned autoThread follow-up mention policy that preserves current defaults, documents the new config shape, and coordinates with the separate parent/thread override design.

## Reproduction Assessment

Yes, source-level. Current main still clears mention requirements for bot-owned autoThread threads and has no config key that requires mentions only for follow-up replies.

## Solution Assessment

Unclear until maintainers choose the public API. The safest direction is an additive opt-in Discord policy, not an unconditional default change or the existing ordinary thread override alone.
