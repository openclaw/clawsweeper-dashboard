## Summary

Keep open. Current main and v2026.6.11 still preserve the Discord bot-owned autoThread mention bypass, the requested thread-reply mention-gate config is absent from the public type and strict schema, and the nearest related issue tracks different parent/thread override semantics rather than this starter-versus-follow-up policy.

## What This Changes

The issue requests an opt-in Discord autoThread policy that responds to the thread starter without a mention but requires explicit mentions for follow-up replies in that thread.

## Best Possible Solution

Define an additive, default-preserving Discord-owned autoThread follow-up mention policy, document it with the existing Discord config surface, and coordinate it with the separate parent/thread override design.
