## Summary

The cleanup is a sound, narrowly scoped fix: current main stops consuming the NDJSON iterator once Ollama sends its semantic final chunk, while the parser retains the reader lock. The patch cancels the unread response body and releases that lock using the standard reader lifecycle, but it still needs direct regression coverage and real Ollama runtime proof before merge.

## What This Changes

The PR wraps Ollama’s NDJSON parser in `try/finally` so an early iterator exit cancels the reader and releases its stream lock.

## Best Possible Solution

Keep the parser-local `try/finally`, add a focused lifecycle regression test for early iterator exit, and attach redacted real Ollama stream evidence showing the cleanup path completes.

## Reproduction Assessment

Yes in source: the native Ollama stream consumer breaks on the semantic final record while `parseNdjsonStream` currently has no reader cleanup. A direct test can reproduce this with a controlled `ReadableStream` and an early iterator return.

## Solution Assessment

Yes, subject to regression coverage: cleanup belongs in the generator that owns the reader, and cancellation plus lock release is the narrowest way to stop unread response work and unlock the stream.
