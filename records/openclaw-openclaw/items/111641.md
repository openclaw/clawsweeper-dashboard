## Summary

The previous lifecycle blocker remains in the current head: the cleanup awaits `reader.cancel()`, so a cancellation promise that never settles prevents `reader.releaseLock()` from running. The PR also still needs after-fix evidence from a real Ollama streaming setup rather than mock-test output alone.

## What This Changes

The PR wraps Ollama’s NDJSON async generator in `try`/`finally` cleanup and adds tests for consumer `break` and `throw` exits.

## Best Possible Solution

Start cancellation as best effort without awaiting it, release the reader lock immediately, add a regression test with a never-settling cancellation promise, and provide redacted real Ollama early-abort proof before merge.

## Reproduction Assessment

Yes in source: make the reader’s `cancel()` return a never-settling promise, exit the async iterator early, and observe that the current `await` prevents `releaseLock()` from executing. This has not been demonstrated against a real Ollama runtime.

## Solution Assessment

No. The `try`/`finally` boundary is appropriate, but awaiting cancellation before releasing the lock defeats the stated early-exit guarantee; cancellation must be best effort and independent of immediate lock release.
