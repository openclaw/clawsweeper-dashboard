## Summary

Keep this PR open: the performance problem is valid and the SQLite-rollup direction fits repository policy, but the latest supplied diff still has a source-reproducible sequence-zero undercount that should block merge; the protected maintainer label also requires explicit maintainer handling.

## What This Changes

The PR replaces full transcript rescans with incremental per-session usage rollups stored in each agent’s SQLite database.

## Best Possible Solution

Keep strict greater-than semantics for tail reads, use a checkpoint before the first valid sequence for full SQLite rebuilds, and add a regression where sequence zero contains billable usage before the maintainer-reviewed head merges.

## Reproduction Assessment

Yes. The full-rebuild caller passes zero to a reader whose contract selects only greater sequence values, so a transcript beginning with a usage-bearing sequence-zero event provides a high-confidence source reproduction.

## Solution Assessment

Yes in architecture, but not yet in implementation: incremental rebuildable SQLite rollups are the narrow database-first solution, while the full-rebuild boundary must include sequence zero.
