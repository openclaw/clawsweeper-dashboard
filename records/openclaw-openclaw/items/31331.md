## Summary

Keep open. Current main and v2026.6.11 still pass Gateway-visible sandbox workspace and skill paths directly into Docker bind specs, while this issue is already the canonical parent for the broader Docker Gateway/DooD `workspaceAccess` host/container path mismatch.

## What This Changes

The issue requests Docker Gateway sandbox `workspaceAccess` bind sources to use host-resolvable paths instead of Gateway-container paths.

## Best Possible Solution

Keep this issue as the canonical Docker Gateway/DooD sandbox bind-source bug until maintainers land one security-reviewed host-path mapping, setup/doctor, docs, and live DooD proof path for workspace, sandbox, skill, and browser mounts.

Options:

- **Security-Reviewed Host Mapping (recommended):** Add a single core host-path mapping contract that validates mapped sources before Docker receives them, covers workspace/skill/browser mounts, updates schema/docs/doctor as needed, and requires live DooD proof.
- **Require Identical Host/Container Paths:** Document and enforce the current parity requirement with setup and doctor checks, avoiding path translation but making unsupported Docker volume layouts fail clearly.
- **Leave Docker Sandbox Limited:** Keep DooD sandboxing unsupported for non-parity volume layouts and document the limitation instead of expanding the sandbox bind-source contract now.

## Solution Assessment

Is this the best way to solve the issue? Unclear. Host-path translation is plausible, but the best fix needs a maintainer-approved sandbox security contract and live DooD proof rather than a one-off bind rewrite.
