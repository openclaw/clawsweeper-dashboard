## Summary

Keep open. Current main and v2026.6.11 still pass Gateway-visible workspace and skill paths directly into Docker bind specs, while the remaining fix requires a maintainer-approved Docker host-path mapping contract and sandbox-boundary review.

## What This Changes

The issue reports Docker-hosted Gateway sandbox containers receiving container-internal workspace bind sources, so `workspaceAccess` fails under Docker-outside-of-Docker installs.

## Best Possible Solution

Define and land one security-reviewed Docker host-path mapping contract for managed workspace and skill mounts, with schema/docs/doctor coverage and live DooD proof before closing this issue.
