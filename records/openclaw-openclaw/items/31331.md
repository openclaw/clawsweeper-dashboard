## Summary

Keep open. Current main still sends Gateway-visible sandbox workspace paths directly to Docker bind specs, multiple reports confirm the Docker-outside-of-Docker host/container namespace mismatch, and the remaining fix needs maintainer/security direction rather than automatic closure.

## What This Changes

The issue reports that Docker-hosted Gateway sandbox `workspaceAccess` mounts use container-internal paths instead of host-resolvable paths.

## Best Possible Solution

Define one maintainer-approved host-path contract for Docker-hosted Gateway sandboxes, apply it to managed workspace, agent workspace, materialized skill, custom, and browser mounts, validate mapped sources before Docker receives them, and prove it with a live redacted DooD run.

## Reproduction Assessment

Yes, at source level. Current main still formats Gateway-visible sandbox paths directly into Docker bind specs, while the docs confirm DooD bind sources are resolved in the host namespace.

## Solution Assessment

Unclear. Host-path remapping is plausible, but the best fix needs a maintainer-approved operator contract and security validation before it is safe to land.
