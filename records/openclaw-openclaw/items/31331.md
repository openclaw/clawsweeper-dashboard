## Summary

Keep open. Current main and v2026.6.11 still pass Gateway-visible workspace paths directly into Docker bind specs, while the live discussion keeps this as the canonical Docker Gateway/DooD workspaceAccess bind-source failure.

## What This Changes

The issue reports Docker-hosted Gateway sandbox containers receiving Gateway-internal workspace paths as Docker bind sources instead of host-resolvable workspace paths.

## Best Possible Solution

Define one security-reviewed Docker Gateway/DooD host-path contract for managed workspace, agent workspace, materialized skills, browser mounts, docs, and doctor or setup guidance, then close the cluster after live DooD proof.
