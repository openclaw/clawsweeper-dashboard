## Summary

Keep open. Current main and the latest release still format Gateway-visible sandbox workspace paths directly into Docker bind sources, while the discussion keeps this issue as the canonical Docker Gateway/DooD workspaceAccess bind-source mismatch needing maintainer security/product direction.

## What This Changes

The issue reports Docker-installed Gateway/DooD sandboxes using container-internal workspace paths for workspaceAccess bind sources, breaking /workspace mounting unless dangerous manual bind workarounds are used.

## Best Possible Solution

Define one security-reviewed Docker Gateway/DooD host-path contract for managed workspace, agent workspace, materialized skill, browser, and custom bind paths, with docs, doctor/setup guidance, tests, and live DooD proof before closing the cluster.
