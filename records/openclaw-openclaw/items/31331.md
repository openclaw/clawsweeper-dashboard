## Summary

Keep open: current main still builds Docker bind sources from Gateway/container-visible workspace paths, the DooD docs describe why those sources fail when the host Docker daemon resolves them, and the related repair work remains unmerged or narrower than this canonical cluster.

## What This Changes

The issue requests fixing Docker-install DooD sandbox `workspaceAccess` bind mounts so sandbox workspace paths resolve correctly when Gateway runs inside Docker.

## Best Possible Solution

Define and land a security-reviewed host/container path mapping contract shared by managed workspace, agent workspace, materialized skills, and related Docker bind handling, with docs and live DooD proof before closing this canonical issue.

## Reproduction Assessment

Yes at source level: current main passes Gateway-visible `/home/node` workspace paths into Docker bind mounts while the docs state the host Docker daemon resolves DooD bind sources in the host namespace; no live Docker run was performed in this read-only review.

## Solution Assessment

No current merged solution is sufficient: the best fix needs a maintainer-approved host-path mapping contract applied consistently across Docker sandbox bind surfaces with security validation and real DooD proof.
