## Summary

Keep open. Current main and the latest release still pass Gateway-visible workspace and sandbox paths directly to Docker bind mounts, while this issue is explicitly kept as the canonical Docker Gateway/DooD workspaceAccess bind-source failure.

## What This Changes

Docker-hosted Gateway sandbox workspaceAccess should mount host-resolvable workspace paths instead of Gateway-container internal paths.

## Best Possible Solution

Define one security-reviewed Docker Gateway/DooD path contract for managed workspace, agent workspace, materialized skills, and browser mounts, then document and prove it with a live DooD run.
