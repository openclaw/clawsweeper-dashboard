## Summary

Keep open. Current main and v2026.6.11 still pass Gateway-visible workspace paths directly into Docker bind sources, while live discussion keeps this as the canonical Docker Gateway/DooD sandbox workspaceAccess failure.

## What This Changes

Fix Docker-installed Gateway sandboxing so workspaceAccess mounts use host-resolvable bind sources instead of container-internal paths.

## Best Possible Solution

Define one security-reviewed Docker Gateway/DooD path contract for managed workspace, agent workspace, materialized skills, and browser mounts, then close the cluster only after live DooD proof.
