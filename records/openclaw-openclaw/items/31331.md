## Summary

Keep open. Current main and v2026.6.11 still pass Gateway-visible sandbox workspace paths directly into Docker bind specs, the Docker/DooD contract requires host-resolvable bind sources, and the direct remap PRs are closed unmerged while the open related PR covers a narrower materialized-skills variant.

## What This Changes

The issue reports Docker-installed Gateway/DooD sandbox `workspaceAccess` using container-internal bind sources such as `/home/node/.openclaw/...` instead of host paths, making sandbox `/workspace` unusable.

## Best Possible Solution

Land or replace the direct remap work with one security-reviewed Docker Gateway/DooD host-path contract shared by shell and browser workspace mounts, materialized skills, and custom binds, with docs/setup alignment and live DooD proof.

## Reproduction Assessment

Yes, at source level. Current main resolves Gateway-visible workspace paths and formats them directly into Docker bind specs, while Docker and OpenClaw docs confirm DooD bind sources are evaluated in the host namespace.

## Solution Assessment

Unclear. Host-source remapping is plausible and has prior direct PRs, but the best fix needs maintainer approval of the operator contract and sandbox validation before it is safe to land.
