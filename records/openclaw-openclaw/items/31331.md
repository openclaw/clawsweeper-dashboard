## Summary

Keep open. Current main and v2026.6.11 still pass Gateway-visible workspace paths directly to Docker bind mounts, and this issue remains the canonical Docker Gateway/DooD workspaceAccess bind-source failure with multiple confirming reports.

## What This Changes

Fix Docker Gateway/DooD sandbox workspaceAccess so sandbox containers receive host-resolvable workspace bind sources instead of Gateway-container-internal paths.

## Best Possible Solution

Define one security-reviewed Docker Gateway/DooD host-path contract for managed workspace, agent workspace, materialized skills, custom binds, and browser mounts, then document and prove it with live DooD validation.
