## Summary

Keep open. Current main and the latest release still pass Gateway-visible sandbox workspace paths directly into Docker bind specs, and maintainer discussion already marks this as the canonical Docker Gateway/DooD workspaceAccess bind-source failure.

## What This Changes

The issue reports that Docker-hosted Gateway sandboxing uses container-internal workspace paths as Docker bind sources instead of host-resolvable workspace paths.

## Best Possible Solution

Define one security-reviewed DooD host-path mapping contract for managed workspace, agent workspace, materialized skill, custom, and browser sandbox mounts, then back it with schema/docs/tests and redacted live Docker proof.

## Reproduction Assessment

Yes at source level: current main formats Gateway-visible workspace paths directly into Docker bind specs, while the docs confirm DooD bind paths are evaluated in the host namespace. I did not run a live DooD sandbox deployment in this read-only review.

## Solution Assessment

Unclear. Host-path translation is likely necessary, but the best fix needs a maintainer-approved operator/security contract rather than a one-off remap that bypasses validation or misses browser/custom bind paths.
