## Summary

Keep open. Current main still passes Gateway-visible sandbox workspace paths directly into Docker bind specs, the latest release has the same direct-bind behavior, and the discussion explicitly keeps this as the canonical Docker Gateway/DooD `workspaceAccess` bind-source mismatch.

## What This Changes

The issue reports that Docker-installed Gateway sandboxes use container-internal workspace paths as Docker bind sources, so `workspaceAccess` fails under Docker-outside-of-Docker unless users apply fragile manual bind workarounds.

## Best Possible Solution

Define one security-reviewed Docker Gateway/DooD host-path contract for managed workspace, agent workspace, materialized skills, browser mounts, docs, and doctor or setup guidance, then close the cluster after live DooD proof.
