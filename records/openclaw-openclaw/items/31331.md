## Summary

Keep open. Current main still formats Gateway-visible sandbox/workspace paths directly into Docker bind sources, while live discussion keeps this issue as the canonical Docker Gateway/DooD workspaceAccess bind-source failure and the only open related PR is narrower and not merged.

## What This Changes

Reports that Docker-hosted Gateway/DooD sandbox `workspaceAccess` passes Gateway-container paths as Docker bind sources, making `/workspace` unusable without dangerous manual bind workarounds.

## Best Possible Solution

Define one security-reviewed Docker Gateway/DooD host-path contract for managed workspace, agent workspace, materialized skills, custom/browser binds, docs or doctor guidance, and live DooD proof.
