## Summary

Keep open. Current main and v2026.6.11 still format Gateway-visible sandbox workspace paths directly into Docker bind specs, while the issue discussion and related reports keep this as the canonical Docker Gateway/DooD workspaceAccess bind-source mismatch that needs maintainer/security direction.

## What This Changes

The issue asks for Docker Gateway/DooD sandbox workspaceAccess mounts to use host-resolvable workspace paths instead of Gateway-container-internal paths.

## Best Possible Solution

Define one security-reviewed Docker Gateway/DooD host-path contract for managed workspace, agent workspace, materialized skills, browser mounts, docs, and doctor or setup guidance, then close the cluster after live DooD proof.

## Solution Assessment

Unclear until maintainers choose the host-path contract. Automatic remapping is plausible, but it must be security-reviewed against bind allowlists, reserved targets, browser mounts, custom binds, and upgrade/operator behavior.
