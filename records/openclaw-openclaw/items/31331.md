## Summary

Keep open. Current main and v2026.6.11 still pass Gateway-visible sandbox workspace paths directly into Docker bind specs, while live discussion marks this issue as the canonical Docker Gateway/DooD workspaceAccess bind-source mismatch and the open candidate PR only addresses a narrower materialized-skills subset.

## What This Changes

The issue reports that Docker-hosted Gateway sandbox `workspaceAccess` uses container-internal paths as Docker bind sources, leaving sandbox containers without the intended agent workspace.

## Best Possible Solution

Define one security-reviewed Docker Gateway/DooD host-path contract for managed workspace, agent workspace, materialized skill, browser, and custom bind paths, with docs, doctor/setup guidance, tests, and live DooD proof before closing the cluster.
