## Summary

Keep open. Current main and v2026.6.11 still format Gateway-visible sandbox workspace paths directly into Docker bind specs, while this issue remains the canonical Docker Gateway/DooD workspaceAccess bind-source mismatch.

## What This Changes

The issue reports that Docker Gateway plus Docker-outside-of-Docker sandboxing uses container-internal paths as host Docker bind sources, breaking expected `/workspace` access.

## Best Possible Solution

Define one security-reviewed Docker Gateway/DooD host-path contract for managed workspace, agent workspace, materialized skills, browser mounts, docs, and doctor or setup guidance, then close the cluster after live DooD proof.
