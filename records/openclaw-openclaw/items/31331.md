## Summary

Keep open. Current main and v2026.6.11 still build Docker sandbox managed mounts from Gateway-visible paths, while the live discussion keeps this as the canonical Docker Gateway/DooD workspaceAccess bind-source mismatch that needs maintainer security/product direction.

## What This Changes

The issue reports that Docker-installed Gateway sandbox containers bind workspace paths using container-internal paths instead of host-visible Docker-outside-of-Docker paths.

## Best Possible Solution

Define one security-reviewed Docker Gateway/DooD host-path contract for managed workspace, agent workspace, materialized skills, browser mounts, docs, and doctor/setup guidance, then close the cluster after live DooD proof.

- **Land Only Narrow Skill Repair:** Treat the open materialized-skills PR as a partial repair while leaving this canonical workspaceAccess issue open for the broader managed-mount contract.

Yes, at source level: current main resolves sandbox workspace paths in the Gateway namespace and formats them directly as Docker bind sources, while Docker/OpenClaw docs say DooD bind sources are evaluated in the host namespace. ## Solution Assessment

Unclear until maintainers choose the host-path contract. Automatic remapping is plausible, but it must be security-reviewed against bind allowlists, reserved targets, browser mounts, custom binds, and upgrade/operator behavior.
