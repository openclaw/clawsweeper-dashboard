## Summary

Keep open. Current main and v2026.6.11 still pass Gateway-visible sandbox workspace paths directly into Docker bind specs, while this issue remains the canonical Docker Gateway/DooD workspaceAccess bind-source failure with multiple user confirmations and only partial or unmerged fix attempts.

## What This Changes

The issue asks OpenClaw to make Docker Gateway/DooD sandbox workspaceAccess mount host-resolvable workspace paths instead of container-internal paths.

## Best Possible Solution

Define one security-reviewed Docker Gateway/DooD host-path contract for workspace, agent workspace, materialized skills, browser mounts, docs, and doctor or setup guidance, then close the cluster after live DooD proof.
