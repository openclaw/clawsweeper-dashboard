## Summary

Keep open: current main and v2026.6.11 still format Gateway-visible sandbox workspace paths directly into Docker bind specs, and maintainer discussion marks this as the canonical Docker Gateway/DooD workspaceAccess bind-source cluster.

## What This Changes

Docker-hosted Gateway sandbox workspaceAccess should bind host-visible workspace paths into sandbox containers instead of Gateway-container-internal paths.

## Best Possible Solution

Define one security-reviewed Docker Gateway/DooD host-path contract for managed workspace, agent workspace, materialized skills, browser mounts, docs, and doctor/setup diagnostics, then close the cluster after live DooD proof.
