## Summary

Keep open. Current main and v2026.6.11 still build Docker sandbox bind sources from Gateway-visible workspace paths, while the live discussion keeps this as the canonical Docker Gateway/DooD workspaceAccess path-mapping failure that needs a security-reviewed product decision.

## What This Changes

Docker Gateway/DooD sandbox workspaceAccess should bind host-resolvable workspace paths instead of Gateway container-internal paths.

## Best Possible Solution

Define one security-reviewed Docker Gateway/DooD host-path contract for managed workspace, agent workspace, materialized skills, browser mounts, docs, and doctor or setup guidance, then close the cluster after live DooD proof.
