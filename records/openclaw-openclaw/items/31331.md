Keep open. Current main and v2026.6.11 still pass Gateway-visible sandbox workspace paths directly into Docker bind mounts, while the discussion keeps this as the canonical Docker Gateway/DooD workspaceAccess failure that needs a security-reviewed product decision.

## What This Changes

The issue reports Docker-hosted Gateway/DooD sandbox workspaceAccess using container-internal bind sources instead of host-resolvable workspace paths.

## Best Possible Solution

Define one security-reviewed Docker Gateway/DooD host-path contract for managed workspace, agent workspace, materialized skills, browser mounts, docs, and doctor or setup guidance, then close the cluster after live DooD proof.
