## Summary

Keep open. Current main still formats Gateway-visible sandbox workspace paths directly into Docker bind specs, while the documented DooD constraint is only a host-path parity workaround; the live discussion also marks this issue as the canonical broader Docker Gateway/DooD workspaceAccess cluster.

## What This Changes

The issue asks Docker-installed Gateways using DooD sandboxing to mount the host workspace path for sandbox workspaceAccess instead of container-internal paths.

## Best Possible Solution

Keep this canonical issue open until maintainers land or sponsor one security-reviewed host-path mapping/parity contract for Docker Gateway DooD sandbox workspace, managed skill, browser, and custom bind mounts, backed by live Docker proof and docs.
