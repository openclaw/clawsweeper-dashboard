## Summary

Keep open. Current main and the latest release still pass Gateway-visible workspace paths directly into Docker bind sources; the current docs document the DooD path-parity requirement, but that is not the same as fixing the canonical Docker Gateway/DooD `workspaceAccess` failure, and the open related PR only targets a narrower materialized-skills subset.

## What This Changes

The issue requests Docker Gateway/DooD sandbox `workspaceAccess` mounts to use host-resolvable workspace paths instead of Gateway-container-internal paths.

## Best Possible Solution

Define one security-reviewed Docker Gateway/DooD path contract for managed workspace, agent workspace, materialized skills, custom binds, and browser mounts, then document and prove it with live DooD validation.
