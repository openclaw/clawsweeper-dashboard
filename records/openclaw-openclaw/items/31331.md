## Summary

Keep open. Current main and v2026.6.11 still pass Gateway-visible sandbox workspace paths directly into Docker bind specs, while live discussion marks this issue as the canonical Docker Gateway/DooD `workspaceAccess` bind-source failure and the related open PR is only a conflicting, narrower candidate for part of the same host/container path mismatch.

## What This Changes

The issue reports that Docker-install Gateway containers using Docker-outside-of-Docker sandboxing bind sandbox workspaces from container-internal paths instead of host paths, breaking `workspaceAccess`.

## Best Possible Solution

Define one security-reviewed Docker Gateway/DooD host-path mapping contract for managed workspace, agent workspace, and materialized skill mounts, cover it with docs plus live DooD proof, then close this issue and its duplicates after the fix lands.
