## Summary

Keep open. Current main still formats Gateway-visible sandbox workspace paths directly into Docker bind specs, the latest release still has the same direct-bind behavior, and the issue discussion explicitly keeps this as the canonical Docker Gateway/DooD workspaceAccess bind-source mismatch.

## What This Changes

The issue reports that Docker-installed Gateways using Docker-outside-of-Docker create sandbox workspaceAccess bind mounts from container-internal paths instead of host-resolvable paths.

## Best Possible Solution

Define one security-reviewed Docker Gateway/DooD host-path contract for managed workspace, agent workspace, materialized skills, browser mounts, docs, and doctor or setup guidance, then close the cluster after live DooD proof.
