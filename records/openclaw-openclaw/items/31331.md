## Summary

Keep open. Current main and v2026.6.11 still pass Gateway-visible workspace paths directly into Docker bind sources, while the docs now state Docker-out-of-Docker requires host/container path parity; the issue remains the canonical cluster for deciding whether OpenClaw should support secure remapping instead.

## What This Changes

Docker-installed Gateway sandbox workspaceAccess should bind the host workspace correctly when the Gateway runs in Docker-outside-of-Docker mode.

## Best Possible Solution

Define one security-reviewed Docker Gateway/DooD path contract for managed workspace, agent workspace, materialized skills, and browser mounts, then document it and prove it with a live DooD scenario.
