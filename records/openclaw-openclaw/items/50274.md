## Summary

Keep open. Current main and v2026.6.11 still lack the benchmark-backed fallback-order policy, and the model-input guardrail remains a compatibility-sensitive provider/config contract that is only partially covered by the focused open guardrail issue.

## Best Possible Solution

Define a documented benchmark-backed fallback policy for the active chain, then enforce capability-aware input validation from one canonical provider/catalog authority with focused tests, docs, and any needed doctor migration.
