## Summary

Keep open. Current main and v2026.6.11 still lack a benchmark-backed fallback ordering policy for the named active chain, and the model-input guardrail remains an unresolved config/provider contract decision that is only partly covered by https://github.com/openclaw/openclaw/issues/50287.

## What This Changes

Requests benchmarking and ranking active fallback models, defining fallback ordering policy, and adding validation/tests/docs for configured model input modalities.

## Best Possible Solution

Define a documented cost-first fallback policy backed by repeatable benchmark criteria, then settle one capability-authority contract for configured model inputs and enforce it consistently across schema, types, catalog normalization, tests, docs, and any needed doctor migration.

## Reproduction Assessment

Yes, at source level: current main still uses explicit fallback ordering and accepts audio/video model input metadata, while docs and tests show the guardrail contract is unresolved. I did not run live provider benchmarks because the remaining fallback-order ask depends on live policy data.

## Solution Assessment

Unclear as a single implementation: the direction is useful, but the fallback policy and input capability authority need maintainer decisions before a safe fix can be queued. A narrower guardrail subset is already tracked at https://github.com/openclaw/openclaw/issues/50287.
