## Summary

Keep open. Current main and v2026.6.11 still use explicit configured fallback order rather than a benchmark-backed latency/quality/cost policy, and the model-input guardrail remains an unresolved provider/config contract that overlaps but is not fully replaced by https://github.com/openclaw/openclaw/issues/50287.

## What This Changes

Requests benchmark-backed fallback ordering for a named active model chain plus a guardrail for unsupported `models.providers.*.models[*].input` declarations.

## Best Possible Solution

Publish a cost-first fallback policy backed by repeatable benchmark criteria, then resolve the configured-model capability authority in one contract shared by schema, types, catalog normalization, media selection, tests, docs, and any needed doctor migration.

## Reproduction Assessment

Yes, at source level: current main still uses explicit fallback ordering and still accepts audio/video configured model input metadata without semantic capability validation. I did not run live provider benchmarks because the remaining fallback-order ask depends on live policy data.

## Solution Assessment

Unclear as one implementation: the direction is useful, but fallback ranking needs a benchmark/product policy and the guardrail needs a compatibility-safe capability authority. The guardrail subset should stay coordinated with https://github.com/openclaw/openclaw/issues/50287.
