## Summary

Keep open. Current main and v2026.6.11 still expose ordered configured fallback chains and partial modality validation, but they do not provide the requested benchmark-backed fallback ordering policy or a settled capability-aware guardrail for `models.providers.*.models[].input`.

## What This Changes

The issue requests benchmarking/ranking active fallback models, defining latency/quality/cost fallback ordering policy, and adding tests/docs for model input modality guardrails.

## Best Possible Solution

Define a documented benchmark-backed fallback policy for the active model chain, then implement capability-aware input validation through the agreed provider/catalog authority while preserving valid custom multimodal models.
