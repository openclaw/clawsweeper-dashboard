## Summary

Keep open. Current main still lacks the requested benchmark-backed cost-first fallback ordering policy, while the model-input guardrail portion is only partially owned by the open narrower tracker at https://github.com/openclaw/openclaw/issues/50287; closing this would drop the remaining fallback-policy work because the older split tracker for that half is already closed.

## What This Changes

The issue asks for benchmark-backed ranking of the named OpenRouter fallback models, a documented cost-first fallback ordering policy, and capability-aware validation for `models.providers.*.models[*].input`.

## Best Possible Solution

Confirm the tracking shape, then either keep this as the umbrella or reopen/create a narrow cost-first fallback-policy item while letting https://github.com/openclaw/openclaw/issues/50287 own the model-input guardrail contract.

## Reproduction Assessment

Yes, at source level: current main still uses explicit fallback ordering and still accepts configured `audio`/`video` model input metadata while media-understanding trusts declared `image` support. I did not run live provider benchmarks because the fallback-order half depends on live policy data.

## Solution Assessment

No, not as one immediate code change: the requested direction is useful, but fallback ranking needs live benchmark/product policy and the guardrail needs a compatibility-safe capability authority. The guardrail subset should stay tied to https://github.com/openclaw/openclaw/issues/50287 while maintainers decide where the fallback-policy half lives.
