## Summary

Keep open. Current main and v2026.6.11 still lack both the benchmark-backed fallback-order policy and a capability-aware guardrail for configured model inputs; the focused guardrail work is open at https://github.com/openclaw/openclaw/issues/50287, but the fallback-policy half is not owned by a merged fix or safer canonical open item.

## What This Changes

The issue requests benchmarking active fallback models, defining a latency/quality/cost fallback-order policy, and adding validation for unsupported `models.providers.*.models[*].input` declarations.

## Best Possible Solution

Produce a documented cost-first fallback recommendation backed by repeatable benchmark data, then implement capability-aware input validation against an agreed provider/catalog authority with aligned schema, types, tests, docs, and any required doctor migration.

## Reproduction Assessment

Yes, at source level. Current main still accepts broad configured model input metadata, still lets media-understanding trust configured image rows, and still builds fallback candidates from explicit configured order rather than a benchmark policy.

## Solution Assessment

No for a direct schema-only implementation. The best path first defines the cost-first fallback policy and the model-input capability authority so the later code change does not break valid custom provider catalogs.
