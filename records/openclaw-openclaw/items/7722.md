## Summary

Keep open: current main and the latest release still only model `tools.fs.workspaceOnly`, while this issue asks for a configurable allow/deny filesystem policy and a clear exec boundary. The linked PRs are useful context, but they are open or partial, so this remains a maintainer-owned security/config design tracker.

## What This Changes

The issue requests a filesystem access policy config for OpenClaw tools with sandbox/full mode, allowed paths, deny paths, and read/write/exec enforcement.

## Best Possible Solution

Keep this as the canonical tracker until maintainers choose and land one versioned `tools.fs` path-policy contract with deny precedence, normalization/symlink semantics, explicit exec scope, docs, and security-focused tests.
