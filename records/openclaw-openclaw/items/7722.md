## Summary

Keep open: current main and v2026.6.11 still expose only the narrower `tools.fs.workspaceOnly` boolean, while this issue asks for a configurable allow/deny filesystem security boundary with an explicit exec strategy.

## What This Changes

Request to add a filesystem access config surface with allowed/denied paths and sandbox/full mode semantics across file tools and exec.

## Best Possible Solution

Keep this as the canonical tracker until maintainers choose a versioned `tools.fs` path policy, deny-wins normalization semantics, and an explicit exec-scope contract, then land one reviewed implementation with docs and security-focused tests.
