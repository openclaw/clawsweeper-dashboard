## Summary

Keep open: current main and v2026.6.11 still expose only the narrower `tools.fs.workspaceOnly` boolean, while this issue asks for a configurable path-rule filesystem boundary with allow/deny paths and an explicit exec strategy.

## What This Changes

The issue requests a filesystem access policy config with sandbox/full mode plus allow and deny path rules for read, write, edit, apply_patch, and exec-style access.

## Best Possible Solution

Keep this as the canonical tracker until maintainers choose a versioned `tools.fs` path policy, deny-wins normalization semantics, and an explicit exec-scope contract, then land one reviewed implementation with docs and security-focused tests.
