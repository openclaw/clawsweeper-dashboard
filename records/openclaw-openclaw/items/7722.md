## Summary

Keep open: current main and v2026.6.11 still expose only the narrower `tools.fs.workspaceOnly` boolean, while the requested allow/deny filesystem policy and exec scope remain unmerged security-sensitive product work.

## What This Changes

Request a filesystem access-control config with allow/deny paths and sandbox/full modes across file operations and exec.

## Best Possible Solution

Keep this as the canonical filesystem policy tracker until maintainers choose and land a versioned `tools.fs` or successor contract with deny precedence, normalization and symlink rules, file/media/apply_patch coverage, explicit exec scope, docs, and upgrade behavior.
