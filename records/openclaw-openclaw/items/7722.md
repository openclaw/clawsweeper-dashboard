## Summary

Keep open: current main and v2026.6.11 still only support the narrower `tools.fs.workspaceOnly` boolean, while this issue requests a new allow/deny filesystem policy and an explicit exec boundary. The open PathGuard PR is relevant but remains unmerged, conflicting, proof-gated, and explicitly leaves arbitrary shell execution out of scope.

## What This Changes

Request to add configurable filesystem sandboxing with mode, allowed paths, and denied paths for agent file and exec-style tool access.

## Best Possible Solution

Design a versioned core `tools.fs` filesystem policy with normalized deny-wins path rules for read/write/edit/apply_patch/media, plus an explicit exec strategy or a clearly linked exec limitation.
