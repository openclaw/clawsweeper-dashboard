## Summary

Keep open: current main still exposes only `tools.fs.workspaceOnly` plus the separate `apply_patch` workspace guard, while this issue asks for a configurable host filesystem path policy with allow/deny rules and an explicit exec strategy. The related PathGuard and roots PRs are open, conflicting, or partial, so they are not a safe basis for cleanup.

## What This Changes

Request a configurable filesystem access policy for agents, including allow/deny paths and sandbox/full behavior across file and exec tools.

## Best Possible Solution

Keep this as the canonical tracker until maintainers choose and land one versioned `tools.fs` path-policy contract with deny precedence, normalization semantics, explicit exec scope, docs, and security-focused tests.
