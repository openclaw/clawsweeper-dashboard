## Summary

Keep open: current main and v2026.6.11 still only expose the narrower `tools.fs.workspaceOnly` boolean, while this issue requests configurable allow/deny path rules and an explicit exec/filesystem security boundary.

## What This Changes

Request to add filesystem sandboxing configuration with allow/deny paths and sandbox/full modes for read, write, and exec-style access.

## Best Possible Solution

Keep this as the canonical tracker until maintainers choose a versioned `tools.fs` path-policy contract with normalization, symlink, deny-precedence, media/apply_patch coverage, and explicit exec scope, then land one reviewed implementation with docs and security tests.
