## Summary

Keep open: current main and v2026.6.11 still only expose the narrower `tools.fs.workspaceOnly` boolean, while this issue asks for a configurable allow/deny filesystem boundary with explicit exec behavior.

## What This Changes

The issue requests a `tools.fileAccess` or successor filesystem access policy with sandbox/full mode, `allowedPaths`, `denyPaths`, and enforcement across file and exec tools.

## Best Possible Solution

Keep this as the canonical tracker until maintainers choose a versioned `tools.fs` path-policy contract with deny precedence, normalization and symlink semantics, explicit exec scope, docs, and security-focused tests.
