## Summary

Keep open: current main and v2026.6.11 still expose only the narrower `tools.fs.workspaceOnly` boolean, while this issue asks for configurable allow/deny path enforcement and an explicit exec strategy.

## What This Changes

Request a configurable filesystem sandbox policy for agents, including allowed paths, denied paths, sandbox/full modes, and coverage across file and exec tools.

## Best Possible Solution

Keep this as the canonical tracker until maintainers choose a versioned `tools.fs` path policy, deny-wins normalization semantics, and an explicit exec-scope contract, then land one reviewed implementation with docs and security-focused tests.
