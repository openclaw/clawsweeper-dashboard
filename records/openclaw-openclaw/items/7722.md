## Summary

Keep open: current main and v2026.6.11 still only expose the narrower `tools.fs.workspaceOnly` and `tools.exec.applyPatch.workspaceOnly` controls, while the requested allow/deny filesystem policy and exec strategy remain unresolved security/product work.

## What This Changes

Add a configurable filesystem access policy with sandbox/full modes, allowed paths, denied paths, and enforcement across file operations and exec.

## Best Possible Solution

Define a versioned `tools.fs` filesystem policy contract with canonicalized deny-wins path rules, regression coverage for normalization/symlink/write-path cases, docs that state the exec boundary clearly, and either exec enforcement in the same design or a linked canonical follow-up.
