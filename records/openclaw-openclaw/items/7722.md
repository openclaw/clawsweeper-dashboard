## Summary

Keep open as the canonical filesystem-access security decision. The supplied July 17 review and discussion show that the current documented `tools.fs.workspaceOnly` boundary is materially narrower than configurable normalized allow/deny rules and does not settle arbitrary shell-mediated access; two open implementation directions still require a maintainer security/product choice.

## What This Changes

Add a filesystem sandbox configuration with allow/deny path rules and define whether it also constrains shell-mediated filesystem access.

## Best Possible Solution

Choose one versioned `tools.fs` policy contract, preserve or explicitly migrate the documented `workspaceOnly` default, enforce normalized deny-wins rules across every file-capable tool, and document either a credible exec boundary or an explicit v1 exclusion before selecting one implementation candidate.
