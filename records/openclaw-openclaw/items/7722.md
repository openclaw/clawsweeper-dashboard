## Summary

Keep open: current main and v2026.6.11 still expose only the narrower `tools.fs.workspaceOnly` boolean, while this issue asks for a configurable filesystem path-policy security boundary with allow/deny paths and an explicit exec strategy.

## What This Changes

The issue requests configurable filesystem sandboxing through a path-rule policy such as `tools.fileAccess` with mode, allowed paths, denied paths, and coverage for read, write, and exec tools.

## Best Possible Solution

Keep this as the canonical tracker until maintainers choose a versioned `tools.fs` path-policy contract, deny-wins normalization semantics, and an explicit exec-scope boundary, then land one reviewed implementation with docs and security-focused tests.
