## Summary

Keep open: current main and v2026.6.11 still expose only the narrower `tools.fs.workspaceOnly` boolean, while this request asks for a new allow/deny filesystem policy and an explicit exec boundary. The open PathGuard PR is relevant, but it is unmerged, conflicting, and explicitly leaves arbitrary shell execution out of scope.

## What This Changes

The issue requests configurable filesystem sandboxing through allowed and denied path rules for OpenClaw tool execution.

## Best Possible Solution

Design a versioned core `tools.fs` filesystem policy with normalized deny-wins path rules for read/write/edit/apply_patch/media, plus an explicit exec strategy or separately tracked exec limitation, and document the boundary honestly.
