Keep open: current main and v2026.6.11 still only expose the narrower `tools.fs.workspaceOnly` boolean, while this issue asks for a configurable filesystem path-policy boundary with allow/deny rules and an explicit exec strategy.

## What This Changes

The issue requests filesystem sandboxing configuration with mode, allowed paths, denied paths, and enforcement across file operations and exec.

## Best Possible Solution

Keep this as the canonical tracker until maintainers choose one versioned `tools.fs` path-policy API and exec-scope contract, then land or reject the selected implementation path with docs and security-focused tests.
