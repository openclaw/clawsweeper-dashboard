## Summary

Keep open: current main and v2026.6.11 still expose only the narrower `tools.fs.workspaceOnly` boolean, while the requested allow/deny filesystem policy and exec scope remain unmerged security-sensitive product work.

## What This Changes

The issue requests configurable filesystem access restrictions for tools, including sandbox/full modes plus allow/deny path rules enforced across file and exec-related operations.

## Best Possible Solution

Keep this as the canonical filesystem policy tracker until maintainers choose a versioned `tools.fs` or successor contract with deny-wins path semantics, normalization rules, media/apply_patch coverage, explicit exec scope, docs, and upgrade behavior.
