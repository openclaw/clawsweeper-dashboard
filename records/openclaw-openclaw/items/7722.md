## Summary

Keep open: current main and the latest release still expose only the narrower `tools.fs.workspaceOnly` boolean, while this issue asks for a configurable allow/deny filesystem policy and an explicit exec boundary. The related PRs are useful but open and partial, so this remains a maintainer-owned security/config design tracker.

## What This Changes

Request to add configurable filesystem access restrictions, including allow/deny path rules and sandbox/full mode semantics, for file and exec tools.

## Best Possible Solution

Keep this as the canonical tracker until maintainers choose and land one versioned `tools.fs` path-policy contract with deny precedence, normalization/symlink semantics, explicit exec scope, docs, and security-focused tests.
