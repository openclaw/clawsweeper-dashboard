## Summary

Current main and v2026.6.11 still provide only the binary `tools.fs.workspaceOnly` guard. The requested granular policy remains unimplemented, and the two open candidate PRs use competing contracts and require a maintainer security-boundary decision before either can land.

## What This Changes

Add configurable normalized filesystem allow/deny rules for file operations and define how those restrictions interact with exec.

## Best Possible Solution

Converge on one canonical policy under `tools.fs` with normalized deny-wins rules across every typed file-touching path, and state clearly that full containment requires exec denial or an OS-backed sandbox unless an enforceable exec backend is included.

- **Retain current controls:** Keep `workspaceOnly`, tool denial, and Docker or OS isolation as the supported model and close the candidate implementations.
