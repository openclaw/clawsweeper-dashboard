## Summary

Keep open: current main and v2026.6.11 still only expose `tools.fs.workspaceOnly`, not a configurable allow/deny filesystem policy or an exec-aware sandbox boundary. The related PathGuard/roots/traversal PRs are useful context, but they are open, partial, or intentionally leave exec out of scope.

## What This Changes

The issue requests a filesystem access configuration surface, originally `tools.fileAccess`, with allowed and denied paths enforced across file and exec tools.

## Best Possible Solution

Keep this as the canonical tracker until maintainers choose and land one versioned `tools.fs` path-policy contract with deny precedence, normalization/symlink semantics, docs, tests, and explicit exec scope or a linked exec split.
