## Summary

Current main still exposes only the binary `tools.fs.workspaceOnly` control. Granular path policy remains unresolved, and the two open candidate PRs are conflicting and encode competing public configuration and security contracts, so this issue should remain the canonical maintainer decision point.

## What This Changes

Requests configurable allow/deny filesystem path enforcement across file, media, and exec tools.

## Best Possible Solution

Define one canonical `tools.fs` v1 contract for normalized, deny-wins managed file and media access, explicitly separate arbitrary exec unless it is genuinely enforced, then sponsor one narrow candidate implementation with upgrade and cross-platform proof.
