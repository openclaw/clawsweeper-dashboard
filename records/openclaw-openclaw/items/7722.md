## Summary

Keep open: current main and v2026.6.11 still expose only the narrower `tools.fs.workspaceOnly` boolean, while this issue asks for a configurable allow/deny filesystem policy with an explicit exec boundary.

## What This Changes

The issue requests a configurable filesystem sandbox policy with allowed and denied paths for file and exec-style tool access.

## Best Possible Solution

Define and implement one canonical filesystem access policy under the approved config contract, with deny-wins normalized path checks across file tools, media, apply_patch, subagents, and a deliberately documented exec strategy.
