## What This Changes

The issue requests a configurable filesystem sandbox policy with allowed paths, denied paths, deny-overrides-allow semantics, and coverage for file and exec tools.

## Best Possible Solution

Keep this issue as the canonical filesystem-policy tracker until maintainers choose a versioned `tools.fs` or successor contract with canonical path evaluation, deny precedence, media/apply_patch coverage, and an explicit exec scope or linked exec follow-up.

No, not as the exact proposed shape. Adding `tools.fileAccess` verbatim would be only a plausible implementation; the best fix needs a maintainer-approved canonical contract for path rules, normalization, deny precedence, media/apply_patch behavior, and exec scope.
