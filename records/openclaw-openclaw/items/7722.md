## Summary

Keep open: current main and the latest release still expose only the narrower `tools.fs.workspaceOnly` boolean, while configurable allow/deny or root-scoped filesystem policy and exec-path scope remain unmerged security/product work.

## What This Changes

The issue requests a configurable filesystem sandbox policy such as `tools.fileAccess` with allow/deny path rules enforced across file and exec tools.

## Best Possible Solution

Choose one canonical `tools.fs` policy contract, enforce it after path normalization across file/media/apply_patch surfaces, and explicitly decide whether exec path access is in v1 or tracked separately by https://github.com/openclaw/openclaw/issues/74379.
