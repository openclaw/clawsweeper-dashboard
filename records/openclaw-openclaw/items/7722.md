## Summary

Keep open: current main still only has the narrower `tools.fs.workspaceOnly` boolean policy, while this issue asks for configurable allow/deny path policy and an explicit exec boundary. Related PRs are useful implementation candidates, but they are open, partial, or use competing API shapes, so this remains a maintainer-owned security/config design tracker.

## What This Changes

The issue requests a new filesystem access policy config with mode, allow paths, and deny paths enforced across file and exec tools.

## Best Possible Solution

Settle and land one versioned `tools.fs` path-policy contract with deny precedence, normalization/symlink semantics, explicit exec scope, docs, doctor/upgrade behavior, and security-focused tests.
