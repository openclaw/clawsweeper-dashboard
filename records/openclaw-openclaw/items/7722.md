## Summary

Keep open: current main and the latest release still only expose the narrower `tools.fs.workspaceOnly` boolean, while the requested configurable allow/deny filesystem policy and exec-path boundary remain unmerged security/product work.

## What This Changes

The issue requests a configurable filesystem sandbox policy, originally shaped as `tools.fileAccess` with sandbox/full mode plus `allowedPaths` and `denyPaths` for read, write, edit, and exec behavior.

## Best Possible Solution

Keep this issue as the canonical tracker until maintainers choose a versioned `tools.fs` or successor policy contract, land one reviewed implementation across file/media/apply_patch surfaces, and explicitly decide whether exec is covered in v1 or split to a linked follow-up.

## Solution Assessment

Not yet. The requested direction is valid, but the exact `tools.fileAccess` shape is not necessarily the best contract; maintainers should choose a canonical `tools.fs` or successor policy and decide the exec boundary before implementation.
