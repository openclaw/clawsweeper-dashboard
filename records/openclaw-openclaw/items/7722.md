## Summary

Keep open: current main and v2026.6.11 still only expose the narrower `tools.fs.workspaceOnly` boolean, while this issue asks for configurable allow/deny filesystem policy with an explicit exec boundary. The related PRs are useful context, but they are open, partial, or still under security/product review rather than merged completion.

## What This Changes

Request configurable filesystem access restrictions for agents, including mode, allowed paths, deny paths, and enforcement across file and exec tools.

## Best Possible Solution

Keep this as the canonical tracker until maintainers choose and land one versioned `tools.fs` path-policy contract with deny precedence, normalization/symlink semantics, explicit exec scope, docs, and security-focused tests.
