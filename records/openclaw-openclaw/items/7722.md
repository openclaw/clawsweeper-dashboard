## Summary

Keep open: current main and v2026.6.11 still expose only the narrower `tools.fs.workspaceOnly` boolean, while the requested allow/deny filesystem policy and exec scope remain unmerged security-sensitive product work.

## What This Changes

Add config-driven filesystem sandboxing with allow/deny paths and sandbox/full mode across read, write, and exec tools.

## Best Possible Solution

Keep this as the canonical filesystem policy tracker until maintainers choose a versioned `tools.fs` or successor contract with deny-wins path semantics, normalization/symlink rules, media/apply_patch coverage, explicit exec scope, docs, and upgrade behavior.
