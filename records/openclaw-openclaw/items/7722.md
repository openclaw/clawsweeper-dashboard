## Summary

Keep open: current main and v2026.6.11 still only expose the narrower `tools.fs.workspaceOnly` boolean, while the requested allow/deny filesystem policy and exec coverage remain unmerged security-sensitive product work.

## What This Changes

The issue requests a configurable filesystem sandbox policy with `mode`, `allowedPaths`, and `denyPaths` that applies to file tools and exec.

## Best Possible Solution

Keep this as the canonical filesystem policy tracker until maintainers choose a versioned `tools.fs` or successor contract that defines allow/deny semantics, path normalization, media/apply_patch coverage, and explicit exec scope.
