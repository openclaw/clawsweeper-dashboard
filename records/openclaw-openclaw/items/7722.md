## Summary

Keep open: current main and v2026.6.11 still expose only the narrower `tools.fs.workspaceOnly` and `tools.exec.applyPatch.workspaceOnly` controls, while the requested allow/deny filesystem policy and exec scope remain unresolved security/product work.

## What This Changes

Request a config-driven filesystem sandbox policy with allow/deny paths and sandbox/full mode, enforced across file operations and exec.

## Best Possible Solution

Keep this as the canonical tracker until maintainers choose a versioned `tools.fs` or successor policy, then implement deny-wins path rules with canonicalization, media and `apply_patch` coverage, explicit exec scope, docs, tests, and upgrade guidance.

## Solution Assessment

No. The literal `tools.fileAccess` shape is only a plausible direction; the best fix needs maintainer agreement on canonical config naming, path normalization, deny precedence, media/apply_patch coverage, and whether exec is covered or split into a linked policy.
