## Summary

Keep open: current main and the latest release still expose only the narrower `tools.fs.workspaceOnly` boolean, while configurable allow/deny path policy and the requested exec boundary remain unmerged security/product work with competing open implementation designs.

## What This Changes

The issue requests a filesystem sandboxing config surface such as `tools.fileAccess` or `tools.fs` allow/deny paths that restrict read, write, edit, media, apply_patch, and exec filesystem access.

## Best Possible Solution

Choose one canonical `tools.fs` policy contract, enforce it after path normalization across file, media, and apply_patch surfaces, and explicitly decide whether exec path access is included in v1 or tracked separately by https://github.com/openclaw/openclaw/issues/74379.
