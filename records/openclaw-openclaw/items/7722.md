## Summary

Keep open: current main and v2026.6.11 still expose only the narrower `tools.fs.workspaceOnly` boolean, while this issue asks for a configurable filesystem path policy with allow/deny semantics and an explicit exec strategy.

## What This Changes

Request a configurable filesystem sandbox/access policy, such as `tools.fileAccess` or a `tools.fs` successor, that limits agent file access to operator-defined allowed paths and denied paths across file tools and exec.

## Best Possible Solution

Keep this as the canonical tracker until maintainers choose one versioned `tools.fs` path-policy contract, normalization and deny precedence semantics, and an explicit exec-scope contract, then land one reviewed implementation with docs and security-focused tests.
