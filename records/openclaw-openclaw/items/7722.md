## Summary

Keep this issue open as the canonical maintainer decision point. Current main still provides only the binary `tools.fs.workspaceOnly` control, while two conflicting open PRs propose different granular contracts and neither settles whether arbitrary shell execution belongs inside the security boundary.

## What This Changes

Add configurable filesystem path restrictions that limit agent file and execution access to explicitly permitted host paths.

## Best Possible Solution

Select one canonical policy under `tools.fs`, define its defaults and upgrade behavior, enforce normalized deny-wins or typed-access semantics across every file/media path, and either integrate exec isolation or explicitly document exec as outside the guarantee.
