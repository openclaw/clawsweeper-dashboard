## Summary

Keep open: current main still implements only the narrower `tools.fs.workspaceOnly` and `apply_patch` workspace guard, while this issue asks for configurable allow/deny filesystem policy plus an explicit exec strategy. The related PathGuard/roots PRs are open, incomplete or conflicting, so this remains the canonical security/product design tracker.

## What This Changes

The issue requests a configurable filesystem sandboxing policy for agent tools with allowed paths, denied paths, sandbox/full mode, and coverage for read, write, and exec operations.

## Best Possible Solution

Keep this as the canonical tracker until maintainers choose and land one versioned `tools.fs` path-policy contract with deny precedence, normalization and symlink semantics, explicit exec scope, docs, and security-focused tests.
