## Summary

This PR addresses a real process-lifetime growth concern, but the capacity guard is placed on the delivery path and silently suppresses every non-deduplicated maintenance warning after 512 recorded contexts. The repair is narrow: keep delivering warnings when the map is full, only skip recording new keys, and add boundary coverage.

## What This Changes

The PR caps the session-maintenance warning deduplication map at 512 entries but returns without delivering warnings once that capacity is reached.

## Best Possible Solution

Bound only dedupe retention, not warning delivery: update existing keys, record new keys only while capacity remains or evict an old entry, always continue to send the current warning, and cover saturation plus changed-context behavior in the focused test suite.
