## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P2] Treat updated input transcripts as replacements:** `extensions/xai/realtime-voice-provider.ts:779-781`
  - body: This still forwards `conversation.item.input_audio_transcription.updated` as another partial chunk. xAI `updated` events are cumulative corrections, while Voice Call aggregates non-final user transcripts before finalizing; normal streams can duplicate or mangle the utterance that becomes `call.speech`. Track the current updated text as a replacement, or emit only the delta between successive cumulative updates.
  - confidence: 0.93
- **[P2] Keep the ready callback single-fire across reconnects:** `extensions/xai/realtime-voice-provider.ts:943`
  - body: `resetRealtimeSessionState()` runs on every WebSocket open and resets `sessionReadyFired`, so a reconnect followed by `session.updated` calls `onReady` again. Voice Call uses `onReady` to send the initial greeting when queued, so a transient xAI reconnect can inject that greeting as another user turn. Keep the ready flag scoped to the bridge lifetime instead of each connection.
  - confidence: 0.91
