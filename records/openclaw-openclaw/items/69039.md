Full review comments:

- **[P1] Stop persisting MCP app session and payload data:** `src/agents/mcp-ui-resource.ts:96-99`
  - body: `buildMcpAppCanvasJson` spreads `params.view.mcpApp`, which can include `sessionKey`, then stores full `toolInput` and `toolResult` in canvas JSON rendered from chat. That extends a session-bound capability and sensitive payloads beyond the live bridge; keep session binding in memory and persist only minimal non-sensitive view identity.
  - confidence: 0.9
- **[P1] Bound MCP App resource payloads before decode:** `src/agents/mcp-ui-resource.ts:49-53`
  - body: `fetchMcpAppView` accepts arbitrary text or base64 blob content from the MCP server and decodes it directly before passing it to `createCanvasDocument`. A large app resource can allocate memory during decode and then write unbounded HTML into canvas storage; add an explicit byte cap before decode and persistence.
  - confidence: 0.88
- **[P1] Enforce MCP resource CSP and permissions:** `ui/src/ui/components/mcp-app-view.ts:249-250`
  - body: The MCP Apps dependency exposes resource-level CSP and permissions metadata, but this iframe path applies only a fixed `navigate-to`/`form-action` CSP and never builds an iframe `allow` policy. Parse and enforce the resource metadata, or fail closed with documented denial semantics.
  - confidence: 0.84
