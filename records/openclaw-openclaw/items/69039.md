Full review comments:

- **[P1] Keep optional preview reads out of server backoff:** `src/agents/agent-bundle-mcp-materialize.ts:376-383`
  - body: Late finding: a successful tool call now immediately performs `fetchMcpAppView`, whose `runtime.readResource` uses the same three-failure backoff as ordinary tool calls. If an advertised UI resource is missing or temporarily unavailable, the preview is dropped but the failure is still counted; after three such calls the entire MCP server is paused and normal tools fail. Use a best-effort, non-health-counting resource read for previews and add coverage proving repeated preview failures do not pause ordinary calls.
  - late: true
  - confidence: 0.99
- **[P2] Advertise the sandbox contract applied to the app:** `ui/src/components/mcp-app-view.ts:247-251`
  - body: The official 1.7.4 bridge contract exposes applied CSP and permissions under `hostCapabilities.sandbox`, but this host initializes with only open-links, tools, and resources. Apps that gate functionality on initialization metadata therefore see no applied sandbox contract. Advertise the CSP actually enforced by the host and either explicitly report no permission grants or reject unsupported permission metadata consistently.
  - confidence: 0.98
- **[P2] Send resource teardown before removing its iframe:** `ui/src/components/mcp-app-view.ts:183-188`
  - body: The prior blocker remains: `teardown()` removes the iframe before `bridge.teardownResource()` uses its postMessage transport, so the app cannot receive the resource teardown request. Await the bounded teardown while the iframe is still attached, then remove the iframe and close the transport; retain the generation guard so stale teardown cannot affect a replacement view.
  - confidence: 0.97
