## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.84

Full review comments:

- **[P1] Stop persisting MCP app session and tool payload data:** `src/agents/mcp-ui-resource.ts:96-99`
  - body: `buildMcpAppCanvasJson` spreads `params.view.mcpApp`, which includes the session key created above, then adds the full tool input and result into canvas JSON. That JSON is lifted into chat/canvas state, so an MCP app view can persist a session-scoped capability plus potentially sensitive tool payloads beyond the live bridge. Keep the session binding in memory and persist only minimal non-sensitive view identity.
  - confidence: 0.9
- **[P1] Bound MCP App HTML before decode and write:** `src/agents/mcp-ui-resource.ts:49-53`
  - body: `fetchMcpAppView` accepts arbitrary `text` or base64 `blob` content from the MCP server and decodes it directly before passing it to `createCanvasDocument`. A large app resource can allocate memory during base64 decode and then write an unbounded HTML file into canvas storage. Add an explicit byte limit before decoding and before persistence, with tests for text and blob inputs.
  - confidence: 0.88
- **[P1] Enforce MCP resource CSP and permissions metadata:** `ui/src/ui/components/mcp-app-view.ts:249-250`
  - body: The `ext-apps` contract carries resource-level CSP and permissions metadata, but the iframe path here applies only a fixed `navigate-to`/`form-action` CSP and never builds an `allow` policy or resource-domain directives from the MCP resource metadata. That leaves the host neither honoring nor intentionally denying the server-declared browser policy. Parse and enforce the resource metadata, or fail closed with documented denial semantics.
  - confidence: 0.82
