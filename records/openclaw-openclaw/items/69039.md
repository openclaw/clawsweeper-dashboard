## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Stop persisting MCP session and tool payload data:** `src/agents/mcp-ui-resource.ts:96-100`
  - body: `buildMcpAppCanvasJson()` serializes `view.mcpApp` plus full `toolInput` and `toolResult` into chat/canvas metadata; `view.mcpApp` can include the session key from the runtime. That makes bearer-ish session routing data and sensitive tool payloads durable in transcript/canvas state instead of keeping the live bridge context in memory or persisting a minimal redacted identity.
  - confidence: 0.93
- **[P1] Bound MCP App resources before decode and write:** `src/agents/mcp-ui-resource.ts:49-54`
  - body: Enabled MCP Apps accept server-provided text or base64 HTML and pass it to canvas storage without an explicit byte cap. A trusted-but-buggy or compromised MCP server can drive memory or disk growth through this tool-result path, so enforce a small host-owned maximum before base64 decode and before document persistence.
  - confidence: 0.9
- **[P1] Apply MCP resource CSP and permissions metadata:** `ui/src/ui/components/mcp-app-view.ts:249-250`
  - body: The iframe host hard-codes only `navigate-to` and `form-action` and does not apply resource `_meta.ui.csp` or permissions metadata from the MCP Apps contract. That breaks apps which declare needed domains/permissions and also misses the dependency's secure defaults for omitted network/resource/frame access, so the resource metadata needs to be parsed, persisted, and enforced or intentionally denied.
  - confidence: 0.88
