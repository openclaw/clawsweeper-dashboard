## Summary

Current main and shipped releases already support granular custom seccomp and AppArmor overrides through the canonical Docker sandbox configuration, while rejecting the unsafe `unconfined` setting. The proposed parallel configuration keys would duplicate that existing surface, and Docker remains the authoritative validator for host profile loading.

## What This Changes

Request configurable custom AppArmor and seccomp profile overrides for Docker sandbox containers, including validation before application.

## Best Possible Solution

Keep the existing `agents.defaults.sandbox.docker.seccompProfile` and `apparmorProfile` settings as the single canonical surface, with Docker and the host policy loader providing authoritative profile parsing and loading errors; improve configuration documentation separately if discoverability remains a concern.

## Reproduction Assessment

No. Current main and `v2026.6.11` already accept custom seccomp profile paths and AppArmor profile names and pass them to Docker.

## Solution Assessment

No. Adding parallel `sandbox.security.*` keys would create a duplicate source of truth, while eager AppArmor file validation would conflict with Docker's named, host-loaded profile model.
