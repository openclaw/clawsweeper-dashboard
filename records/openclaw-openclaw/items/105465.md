## Summary

Current main and shipped releases already support restrictive custom Seccomp files and named AppArmor profiles through the canonical Docker sandbox configuration. OpenClaw rejects `unconfined`, applies profile changes through Docker, and documents the operator workflow; adding `sandbox.security.*` would duplicate the existing configuration.

## What This Changes

The issue requests custom AppArmor and Seccomp profile overrides with profile validation before Docker sandbox creation.

## Best Possible Solution

Keep the shipped `agents.*.sandbox.docker.seccompProfile` and `apparmorProfile` contract, rely on Docker and host tooling to load profiles, and open a narrower issue only for a concrete unclear diagnostic.
