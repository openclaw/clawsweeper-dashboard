## Summary

Keep open for a maintainer security and product-direction decision. The recent reporter update says the bypass evidence was revalidated privately on 2026.6.8, while the requested cross-harness, capability-level authority boundary is broader than the existing narrower external-verification discussion and cannot be safely accepted or closed without an explicit threat model and API direction.

## What This Changes

The issue requests a core, capability-scoped, exclusive, proof-bound approval-resolver seam so external providers can authoritatively gate consequential actions across native, Codex, and ACP harnesses.

## Best Possible Solution

Sponsor a narrow security RFC that first fixes the capability taxonomy, authoritative-resolver precedence, request/proof persistence, and per-harness coverage contract; keep wallet, passkey, and policy-provider implementations in plugins and add cross-harness conformance tests only after that contract is approved.
