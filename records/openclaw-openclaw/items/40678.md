## Summary

Keep open: current main and the latest release still lack a TUI observe/mirror CLI or config surface, and the open related PR only covers selected-session live transcript updates. The broader cross-channel visibility request remains a maintainer product/security decision.

## What This Changes

Request an opt-in TUI mode or setting to observe or mirror iMessage, Telegram, cron, and other channel activity for the same agent without reverting TUI session isolation.

## Best Possible Solution

Keep this as the canonical design issue for a default-off, authorization-aware TUI observe mode, and review https://github.com/openclaw/openclaw/pull/96252 separately for the narrower selected-session live-update bug.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add a default-off TUI cross-channel observer or mirror mode, and what transcript visibility boundary should it enforce across agents, sessions, channels, and operators?

Rationale: Existing Gateway events make the plumbing plausible, but exposing cross-channel transcripts changes privacy, retention, delivery, and public CLI/config behavior that automation cannot choose safely.

Likely owner: steipete

Owner reason: The TUI session isolation history and the active narrow live-update PR context make this the strongest routing candidate for the visibility-policy decision.

Owner confidence: high

Options:

- **Read-only observer first (recommended):** Add an `openclaw tui --observe`-style mode that shows only authorized activity for the selected agent/session scope and defers bidirectional channel mirroring.
- **Full bidirectional mirroring:** Allow TUI and channel messages to appear across surfaces only after explicit delivery, authorization, redaction, and upgrade policy are defined.
- **No core mode:** Keep logs, session tailing, or a future activity timeline as the supported monitoring path and avoid a core cross-channel TUI mirror feature.

## Reproduction Assessment

Yes, at source level: current main has no observe/mirror CLI or config surface, and the TUI does not consume live `session.message` events. I did not run a live cross-channel scenario, and the broad request is a feature/security-policy gap rather than a single current contract bug.

## Solution Assessment

Unclear for the full feature until maintainers choose the visibility policy. The narrow selected-session fix belongs with https://github.com/openclaw/openclaw/pull/96252, while cross-channel observation should be default-off and authorization-aware if accepted.
