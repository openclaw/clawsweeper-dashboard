## What This Changes

Add an opt-in TUI mode or setting to observe or mirror iMessage, Telegram, and other channel activity for the same agent without reverting TUI session isolation.

## Best Possible Solution

Keep this as the canonical design issue for a default-off, authorization-aware TUI observer mode, and land or replace the selected-session live-update PR separately for the narrower bug.

Question: Should OpenClaw add a default-off TUI cross-channel observer or mirror mode, and what transcript visibility boundary should it enforce across agents, sessions, channels, and operators?

Rationale: The existing Gateway event primitives make a narrow observer plausible, but exposing cross-channel transcripts changes privacy, security, retention, and public CLI/config expectations that automation cannot choose safely.

Likely owner: steipete

Owner reason: They have the clearest history on the TUI isolation behavior, current narrow live-update path, and maintainer-level visibility/security policy choice.

Owner confidence: high

Options:

- **Read-only observer first (recommended):** Add a default-off `openclaw tui --observe` style mode that only shows authorized activity for a selected agent/session scope and leaves bidirectional channel mirroring out of scope.
- **Full bidirectional mirroring:** Allow TUI and channel messages to appear across surfaces, but require explicit delivery, authorization, redaction, and upgrade policy before implementation.
- **No core observer mode:** Keep logs, existing session views, and future activity timelines as the supported monitoring paths and avoid a core cross-channel TUI mirror feature.

## Reproduction Assessment

Yes for the missing capability at source level: current main has no TUI observe/mirror CLI option or config setting, and TUI event handling remains selected-session scoped. The narrower selected-session live-tail gap is also source-reproducible through the existing `session.message` event path.

## Solution Assessment

Unclear until maintainers choose the visibility boundary. The narrow selected-session live-update fix belongs in https://github.com/openclaw/openclaw/pull/96252, while any cross-channel observer should be default-off and authorization-aware if accepted.
