## Summary

Keep open: current main and the latest release still lack a default-off TUI cross-channel observe or mirror mode, and the open related PR only covers the narrower selected-session live-update gap. The remaining request is useful but needs maintainer product and security policy because it can expose transcripts across channel, session, agent, and operator boundaries.

## What This Changes

The issue requests an opt-in TUI observe or mirror mode so iMessage, Telegram, cron, and other channel activity for an agent can be visible from one terminal without reverting TUI session isolation.

## Best Possible Solution

Keep this as the canonical design issue for a default-off, authorization-aware TUI observe mode, and handle the selected-session live-update bug through the narrower open PR or a replacement that preserves the hidden-run boundary.
