## Summary

## What This Changes

Requests a default-off TUI observe or mirror mode that can show iMessage, Telegram, cron, and other channel activity for the same agent without undoing per-TUI session isolation.

## Best Possible Solution

Define a default-off, security-reviewed TUI observe mode, preferably read-only, and keep selected-session live updates in the focused PR path.

Options:

- **Read-only observe mode (recommended):** Add an explicit observe mode that displays authorized cross-channel activity without sending mirrored replies to other transports.
- **Interactive mirror mode:** Allow bidirectional visible mirroring between TUI and channels behind a stronger opt-in, accepting higher delivery and privacy risk.
- **No broad mirror mode:** Limit core work to selected-session live updates and leave broader monitoring to logs, Control UI surfaces, or a future design.

## Reproduction Assessment

Yes at source level for the adjacent live-update failure: Gateway emits session.message and the TUI subscribes to session events but ignores session.message. The broader observe/mirror request is a new feature, so live reproduction is not the blocker.

## Solution Assessment

Unclear until maintainers choose the product boundary; a read-only explicit observe mode is safer than interactive mirroring. The selected-session live-sync subset should remain with https://github.com/openclaw/openclaw/pull/96252 rather than becoming a broad automatic fix job.
