## Label Justifications

- `P2`: This is a normal-priority power-user TUI/channel visibility feature with a logs workaround and bounded blast radius, but it needs maintainer policy before implementation.
- `impact:session-state`: The request is about seeing activity across sessions and channels without collapsing the isolated TUI session state.
- `impact:message-loss`: The user-visible impact is that channel messages and agent responses are not visible in the active TUI unless the user switches to logs or reloads a specific session.
- `impact:security`: Any cross-channel observer can expose transcripts across channel, identity, and session boundaries if authorization policy is wrong.

## Summary

Keep open: current main still has selected-session TUI behavior and no opt-in cross-channel observe or mirror mode. The related live-update PR only addresses stale updates for an already selected session, while this issue still needs a maintainer product and security boundary decision.

## What This Changes

The issue requests an opt-in TUI mode that can observe or mirror cross-channel activity from iMessage, Telegram, cron, and related agent sessions without reverting normal TUI session isolation.

## Best Possible Solution

Define a read-only-first, explicitly opt-in TUI observer policy with agent, identity, channel, and session visibility bounds, built on existing Gateway session event/history surfaces without changing default session isolation.
