Keep open: current main and v2026.6.11 still lack an opt-in TUI cross-channel observe/mirror mode. The open related PR only targets the narrower selected-session live-update gap, while the broader request needs maintainer product and security policy because it can expose transcripts across channel and session boundaries.

## What This Changes

The issue requests an opt-in TUI mode or setting to observe or mirror iMessage, Telegram, cron, and other channel activity without reverting TUI session isolation.

## Best Possible Solution

Keep this issue as the canonical design item for a default-off, authorization-aware TUI observe mode, while reviewing https://github.com/openclaw/openclaw/pull/96252 separately for the narrower selected-session live-update bug.

Options:

- **Read-only observer first (recommended):** Add a default-off `openclaw tui --observe` style mode that only shows authorized activity for a selected agent or explicitly scoped session set, and defer bidirectional channel mirroring.
- **Full bidirectional mirroring:** Allow TUI and channel messages to appear across surfaces, but require explicit delivery, authorization, redaction, and upgrade policy before implementation.
- **No core mode:** Keep raw logs, existing session selection, or a future activity timeline as the supported monitoring path and avoid a core cross-channel TUI mirror feature.

## Reproduction Assessment

Yes for the narrower selected-session live-tail gap at source level: Gateway emits `session.message`, while current TUI does not consume it. The broader observe/mirror request is a feature and security-policy question rather than a single runnable current-main bug reproduction.

## Solution Assessment

Unclear until maintainers choose the visibility policy. A read-only, default-off observer is the safer first shape; bidirectional mirroring or new config should wait for explicit product and security approval.
