## Summary

Keep open: current main and v2026.6.11 still lack an opt-in cross-channel TUI observe or mirror mode. Existing Gateway event primitives and the open related PR only address narrower selected-session live updates, while the broader request needs an explicit product and security boundary.

## What This Changes

Request an opt-in TUI mode or setting that can observe or mirror iMessage, Telegram, cron, and other channel activity for the same agent without undoing isolated TUI sessions.

## Best Possible Solution

Define a default-off, authorization-aware read-only TUI observe mode first, and let the linked selected-session live-update PR proceed separately for the narrower bug.
