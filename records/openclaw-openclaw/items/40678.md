## Summary

Keep open: current main and v2026.6.11 still lack an opt-in TUI observe/mirror mode, and the open related PR only addresses selected-session live updates. The remaining request needs maintainer product and security direction because it crosses channel and session visibility boundaries.

## What This Changes

The issue requests an opt-in TUI observe or mirror mode for cross-channel activity across iMessage, Telegram, cron, and other agent surfaces.

## Best Possible Solution

Define a read-only-first, explicitly opt-in TUI observer policy with agent, identity, channel, and session visibility bounds, then build it on existing Gateway session event/history surfaces without changing default session isolation.

Rationale: The request crosses channel/session privacy boundaries and may add public CLI or config surface, so automation cannot safely choose the security policy or product shape.

Owner confidence: high

Options:

- **Read-only scoped observe mode (recommended):** Add an explicit opt-in observer that displays only sessions the operator is authorized to see, with clear agent, identity, channel, and session scope.
- **Interactive bidirectional mirror:** Allow TUI to both observe and send across mirrored channels, accepting a larger delivery, message-loss, and privacy-policy surface before implementation.
- **Keep logs as workaround:** Do not add core observer/mirror mode now and leave `openclaw logs --follow` plus explicit session selection as the supported monitoring path.

## Reproduction Assessment

Yes at source level for the missing capability: current main has no TUI observe/mirror CLI or config surface and keeps live TUI chat handling selected-session scoped. I did not run a fresh live iMessage/Telegram/TUI observer scenario in this read-only review.

## Solution Assessment

Unclear until maintainers choose the security boundary: the best likely shape is a read-only, opt-in observer scoped by existing session visibility before any interactive bidirectional mirroring. The open selected-session live-update PR is a good narrow fix but not the full solution for this issue.
