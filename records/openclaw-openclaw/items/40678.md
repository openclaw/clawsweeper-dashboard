Keep open: current main and the latest release still lack an opt-in TUI observe or mirror mode, and the open related PR only addresses selected-session live transcript refresh. The broader cross-channel visibility request remains a product and security decision.

## What This Changes

Request an opt-in TUI mode or setting that can observe or mirror iMessage, Telegram, cron, and other channel activity for the same agent without reverting isolated TUI sessions.

## Best Possible Solution

Keep this as the canonical design issue for a default-off, authorization-aware TUI observe mode, while reviewing the selected-session live-update PR separately for the narrower bug.

## Maintainer Decision

Kind: product_direction

Question: Should OpenClaw add a default-off TUI cross-channel observer or mirror mode, and what transcript visibility boundary should it enforce across agents, sessions, channels, devices, and operators?

Rationale: Existing Gateway events make part of the plumbing plausible, but exposing cross-channel transcripts changes privacy, redaction, retention, delivery, CLI/config, and operator-scope policy that automation cannot choose safely.

Likely owner: steipete

Owner reason: This decision is tied to the original TUI isolation change and requires product/security policy for cross-channel transcript visibility.

Owner confidence: high

Options:

- **Read-only observer first (recommended):** Add an explicit observe mode that shows only authorized activity for the selected agent or session scope and defers bidirectional channel mirroring.
- **Full bidirectional mirroring:** Allow TUI and channel messages to appear across surfaces only after delivery, authorization, redaction, and upgrade policy are defined.
- **No core mirror mode:** Keep logs, sessions tail, selected-session tailing, or a future activity timeline as the supported monitoring path and avoid cross-channel TUI mirroring in core.

## Solution Assessment

Unclear until maintainers choose the visibility policy. The narrow selected-session live-update path belongs with https://github.com/openclaw/openclaw/pull/96252, while cross-channel observation should be default-off and authorization-aware if accepted.
