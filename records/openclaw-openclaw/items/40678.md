## Maintainer Decision

Question: Should OpenClaw add a default-off TUI cross-channel observer or mirror mode, and what transcript visibility boundary should it enforce across agents, sessions, channels, and operators?

Rationale: Existing Gateway events make part of the plumbing plausible, but exposing cross-channel transcripts changes privacy, retention, delivery, CLI/config, and operator-scope policy that automation cannot choose safely.

Likely owner: steipete

Owner reason: The TUI /new isolation provenance and the policy-sensitive session visibility boundary make steipete the best available owner from current history.

Owner confidence: medium

Options:

- **Read-only observer first (recommended):** Add a default-off openclaw tui --observe style mode that shows only authorized activity for the selected agent or session scope and defers bidirectional channel mirroring.
- **Full bidirectional mirroring:** Allow TUI and channel messages to appear across surfaces only after explicit delivery, authorization, redaction, and upgrade policy are defined.
- **No core mirror mode:** Keep logs, selected-session tailing, or a future activity timeline as the supported monitoring path and avoid a core cross-channel TUI mirror feature.

## Solution Assessment

Unclear for the full feature until maintainers choose the visibility policy. The narrow selected-session live-update path belongs with https://github.com/openclaw/openclaw/pull/96252, while cross-channel observation should be default-off and authorization-aware if accepted.
