## Summary

Keep open: current main still lacks an opt-in TUI observe/mirror mode, and the open related PR only addresses live updates for the currently selected session. The remaining request needs maintainer product and security direction because it can expose channel transcripts across session and operator boundaries.

## What This Changes

Request a default-off TUI flag, config option, or observe mode that can show iMessage, Telegram, and other channel activity without undoing isolated TUI sessions.

## Best Possible Solution

Define a default-off, authorization-aware read-only TUI observer first, using existing Gateway session-message primitives where appropriate, and keep bidirectional channel mirroring separate until its delivery and privacy policy is explicit.
