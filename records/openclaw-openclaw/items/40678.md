## Label Justifications

- `P2`: This is a concrete cross-channel TUI visibility improvement with source-backed gaps and workarounds, but it needs product/security design before implementation.
- `impact:security`: The requested observer mode would intentionally broaden who or what can view channel/session activity, so authorization and disclosure boundaries matter.
- `impact:message-loss`: Messages and replies that exist in other channel transcripts can be absent from the live TUI view, which users experience as missing activity.
- `impact:session-state`: The visible TUI session can diverge from the agent's active cross-channel work, especially for Telegram/iMessage and cron-triggered sessions.

## Summary

Keep open: current main still lacks the requested opt-in TUI observer or mirror mode, and the open TUI live-session PR only covers the narrower selected-session refresh gap.

## What This Changes

Add an opt-in TUI mode or setting that observes/mirrors activity from other channels such as iMessage and Telegram without reverting isolated TUI sessions.

## Best Possible Solution

Define a default-off, operator-controlled TUI observer design with explicit authorization, redaction, session-scope, and read-only versus interactive semantics; land the narrow live-session fix separately if it clears proof and review.
