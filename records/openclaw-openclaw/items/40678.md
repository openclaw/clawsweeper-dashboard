## What This Changes

Request an opt-in TUI mode or setting that mirrors or observes activity from iMessage, Telegram, and other channels for the same agent without undoing TUI session isolation.

## Best Possible Solution

Question: Should OpenClaw add a default-off TUI cross-channel observer or mirror mode, and what transcript visibility boundary should it enforce across agents, sessions, channels, and operators?

Rationale: The current Gateway primitives make a narrow observer plausible, but exposing cross-channel transcripts changes privacy, security, retention, and public CLI/config expectations that automation cannot choose safely.

Likely owner: steipete

Owner reason: They authored the TUI isolation change and have the clearest history on the related TUI/session visibility and policy boundary.

Owner confidence: high

Options:

- **Read-only observer first (recommended):** Add a default-off `openclaw tui --observe` style mode that only shows authorized activity for a selected agent or session scope and leaves bidirectional channel mirroring out of scope.
- **Full bidirectional mirroring:** Allow TUI and channel messages to appear across surfaces, but require explicit delivery, authorization, redaction, and upgrade policy before implementation.
- **No core observer mode:** Keep logs, explicit session views, and future activity timelines as the supported monitoring paths and avoid a core cross-channel TUI mirror feature.

## Reproduction Assessment

## Solution Assessment

Unclear until maintainers choose the visibility boundary. The narrow selected-session live-update fix belongs in https://github.com/openclaw/openclaw/pull/96252, while any cross-channel observer should be default-off and authorization-aware if accepted.
