## Summary

Keep open: current main and v2026.6.11 still lack the requested opt-in TUI observe/mirror mode. The open related PR only addresses the narrower selected-session live-update gap, while this broader cross-channel visibility request needs product and security direction.

## What This Changes

The issue requests an opt-in TUI mode or setting that mirrors or observes iMessage, Telegram, cron, and other same-agent channel activity without undoing TUI session isolation.

## Best Possible Solution

Define an explicit least-privilege TUI observer design, preferably read-only first, and keep broad channel-to-channel forwarding or mirroring out of core unless maintainers identify a missing core API.
