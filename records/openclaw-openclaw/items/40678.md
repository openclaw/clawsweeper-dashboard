## Label Justifications

- `P2`: This is a real multi-surface TUI visibility gap with workarounds and limited blast radius, but it affects active channel/session workflows.
- `impact:session-state`: The request concerns whether TUI session state can reflect activity from other channel sessions or the same selected channel session.
- `impact:message-loss`: Messages can exist in channel transcripts or other surfaces while being absent from the live TUI view without reload or raw log tailing.
- `impact:security`: Cross-channel transcript observation can reveal sensitive channel content unless authorization and visibility rules are designed explicitly.

## Summary

Keep open: current main and v2026.6.11 still lack a TUI observe/mirror CLI or config surface, and the open live-update PR only addresses selected-session transcript refresh. The broader cross-channel visibility request remains a product and security decision.

## What This Changes

Add an opt-in TUI observe or mirror mode for iMessage, Telegram, and other channel activity on the same agent without reverting isolated TUI sessions.

## Best Possible Solution

Define a default-off, authorization-aware read-only TUI observe mode first, keep isolated TUI sessions as the default, and leave bidirectional cross-channel mirroring for a separate explicit design.
