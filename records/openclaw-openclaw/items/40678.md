## What This Changes

The issue requests a default-off TUI mode or setting that can observe or mirror activity from iMessage, Telegram, cron jobs, sub-agents, and other channels without undoing TUI session isolation.

Keep this as the canonical design issue for a default-off, authorization-aware TUI observe mode, and review the selected-session live-update PR separately for the narrower bug.

Options:

- **Read-only observer first (recommended):** Add an openclaw tui --observe style mode that shows only authorized activity for a selected agent/session scope and defers bidirectional channel mirroring.
- **Full bidirectional mirroring:** Allow TUI and channel messages to appear across surfaces only after explicit delivery, authorization, redaction, and upgrade policy are defined.
- **No core mode:** Keep logs, session tailing, or a future activity timeline as the supported monitoring path and avoid a core cross-channel TUI mirror feature.

## Solution Assessment

Unclear for the full feature until maintainers choose the visibility policy. The narrow selected-session fix belongs with https://github.com/openclaw/openclaw/pull/96252, while cross-channel observation should be default-off and authorization-aware if accepted.
