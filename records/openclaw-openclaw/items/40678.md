## Summary

Keep open: this remains the canonical broad TUI observe/mirror product request. Current main still lacks an opt-in cross-channel TUI observer, and the open related PR only targets the narrower selected-session live transcript update gap.

## What This Changes

The issue requests a default-off TUI mode or config option that can observe or mirror iMessage, Telegram, cron, and other channel activity for the same agent without undoing TUI session isolation.

## Best Possible Solution

Define a guarded default-off TUI observe policy first, land or replace the narrow live-session update fix separately, then implement only the approved read-only/mirroring scope with security docs and live proof.
