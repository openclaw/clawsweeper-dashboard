## Summary

Keep open: current main and v2026.6.11 still do not provide an opt-in TUI observe/mirror mode, and the open related PR only addresses the narrower selected-session live-update bug. The remaining work needs maintainer product and security direction because cross-channel visibility can expose transcripts across session/channel boundaries.

## What This Changes

The issue asks for an opt-in TUI mode or setting that can observe or mirror iMessage, Telegram, cron, and other same-agent channel activity without reverting isolated TUI sessions.

## Best Possible Solution

Keep this as the canonical design issue for a default-off, authorization-aware TUI observe mode, and review the selected-session live-update PR separately for the narrower bug.

Options:

- **Read-only observer first (recommended):** Add a default-off `openclaw tui --observe` style mode that only shows authorized activity for the selected agent/session scope and defers bidirectional channel mirroring.
- **Full bidirectional mirroring:** Allow TUI and channel messages to appear across surfaces, but require explicit delivery, authorization, redaction, and upgrade policy before implementation.
- **No core mode:** Keep raw logs, session tools, or a future activity timeline as the supported monitoring path and avoid a core cross-channel TUI mirror feature.

## Reproduction Assessment

Yes for the narrower selected-session live-tail gap at source level: Gateway emits `session.message`, while current TUI does not consume it. The broader observe/mirror request is a feature and security-policy question rather than a single runnable current-main bug reproduction.

## Solution Assessment

Unclear for the full feature until maintainers choose the visibility policy. The narrow selected-session fix belongs in https://github.com/openclaw/openclaw/pull/96252, while cross-channel observation should be default-off and authorization-aware if accepted.
