## Summary

Keep open: current main and v2026.6.11 still lack an opt-in TUI cross-channel observe or mirror mode, while the open related PR only targets the narrower selected-session live-update bug. The remaining request needs maintainer product and security policy because it would expose transcript activity across channel and session boundaries.

## What This Changes

Request an opt-in TUI mode or setting that can observe or mirror iMessage, Telegram, cron, and other channel activity for the same agent without reverting TUI session isolation.

## Best Possible Solution

Keep this as the canonical design issue for a default-off, authorization-aware TUI observer mode, and handle selected-session live updates through the narrower linked PR path.

Owner confidence: medium

Options:

- **Read-only observer first (recommended):** Add a default-off `openclaw tui --observe` style mode that shows only authorized activity for an explicit agent/session scope and defers bidirectional delivery mirroring.
- **Full bidirectional mirroring:** Allow TUI and channel messages to appear across surfaces, but require explicit delivery, authorization, redaction, and upgrade policy before implementation.
- **No core observer mode:** Keep raw logs, session tools, or a future activity timeline as the supported monitoring path and avoid core cross-channel TUI mirroring.

## Reproduction Assessment

Yes for the narrower selected-session live-tail gap at source level: Gateway emits `session.message`, while current main's TUI subscribes to session events but does not dispatch that event. The broader observe/mirror request is a feature and security-policy question rather than a single runnable current-main bug reproduction.

## Solution Assessment

Unclear until maintainers choose the visibility policy. The narrow selected-session fix belongs in https://github.com/openclaw/openclaw/pull/96252, while any cross-channel observer should be default-off, scoped, and authorization-aware if accepted.
