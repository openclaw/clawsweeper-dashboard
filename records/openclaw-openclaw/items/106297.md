## Label Justifications

- `P1`: A critical loop can keep an agent run alive for hours after tools are blocked, consuming provider calls and runtime resources in an active workflow.

## Summary

This PR addresses a valid P1 runaway-loop bug, but it remains incomplete because the critical denial is terminalized only for Tool Search catalog execution while ordinary direct tool execution can still return the same denial and continue the run.

## What This Changes

Adds agent-run abortion when a Tool Search catalog execution returns a result with `details.deniedReason` set to `tool-loop`.

## Best Possible Solution

Handle a critical `tool-loop` result through one shared post-lifecycle terminalization path used by both direct tools and Tool Search, cover both entry points with regression tests, and demonstrate termination with redacted live run logs or a transcript.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes—source inspection plus the linked v2026.6.11 logs establish a high-confidence path: repeatedly invoke an identical direct tool until `generic_repeat` returns a critical `tool-loop` denial and observe whether provider turns continue. This review did not independently execute that live scenario.

## Solution Assessment

No. Aborting on the Tool Search catalog result is plausible but one-sided; the narrow maintainable fix must apply the same terminal outcome to the direct-tool sibling path, preferably through shared lifecycle-result handling.
