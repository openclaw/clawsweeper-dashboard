## Summary

Keep open for maintainer review: repeated synchronous filesystem hardening is shipped and source-confirmed, but it occurs after `COMMIT`, so the claimed transaction-lock extension and resulting `SQLITE_BUSY` mechanism are unsupported. A benchmark and security-safe sidecar lifecycle are needed before changing the behavior.

## What This Changes

Optimize repeated synchronous permission hardening performed after shared state-database writes while retaining private modes for the database and its SQLite sidecars.

## Best Possible Solution

Measure write-return and event-loop latency under representative concurrent gateway writes, then implement one lifecycle-aware permission path that avoids redundant checks while proving 0700 directories and 0600 main, WAL, SHM, and rollback-journal files across creation and recreation.
