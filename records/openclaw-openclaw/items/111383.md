## Summary

Keep this issue open for explicit maintainer handling: it carries the protected `maintainer` label and reports deterministic loss of a newly rescheduled cron invocation, so it is not eligible for conservative automated cleanup.

## What This Changes

The issue reports that completion cleanup for an active delete-after-run one-shot cron job can delete or disable a newly saved future schedule for that same job.

## Best Possible Solution

Make one-shot completion update only run metadata for the generation/schedule identity admitted at dispatch; leave a changed future schedule enabled and persisted, with regression coverage for delete-after-run and disable-after-run variants across restart.
