## Summary

Keep open: current main and the latest release still leave interactive LiteLLM onboarding on an API-key-only path, so a fresh remote LiteLLM proxy setup can still fall back to localhost plus the seeded model unless the user chooses Custom Provider, existing config, or the non-interactive custom base URL flag.

## What This Changes

Interactive LiteLLM onboarding should ask for the proxy URL/API key and offer the proxy model list instead of falling back to localhost plus one seeded model.

## Best Possible Solution

Add or explicitly reject a maintainer-approved LiteLLM interactive setup path that captures or confirms the proxy base URL before model selection, preserves the non-interactive --custom-base-url path, and documents when users should choose Custom Provider instead.
