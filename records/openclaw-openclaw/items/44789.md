## Summary

Keep open: current main and the latest release still leave the named LiteLLM interactive onboarding choice on a generic API-key path, so the reported base-URL/model-selection gap is real and needs maintainer UX/API direction rather than cleanup closure.

## What This Changes

The issue reports that `openclaw onboard` no longer prompts for LiteLLM server URL/API key setup and then only offers one model during model selection.

## Best Possible Solution

Add a maintainer-approved LiteLLM interactive setup path that captures or confirms the proxy base URL before model selection, preserves existing and non-interactive behavior, and documents when users should choose LiteLLM versus Custom Provider.
