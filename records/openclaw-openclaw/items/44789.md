## Summary

Keep open: current main and v2026.6.11 still route LiteLLM interactive onboarding through the generic API-key method, so remote LiteLLM users can still miss proxy base-URL setup and see only the seeded default model.

## What This Changes

Fix LiteLLM interactive onboarding so selecting LiteLLM captures the proxy URL/API key and presents usable proxy models instead of silently falling back to localhost and one default model.

## Best Possible Solution

Add a maintainer-approved LiteLLM setup path that captures or confirms the proxy base URL before model selection, preserves the non-interactive `--custom-base-url` behavior, and coordinates any live model discovery with provider-catalog safety policy.
