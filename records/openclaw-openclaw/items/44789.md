## Summary

Keep open: current main and v2026.6.11 cover the non-interactive LiteLLM --custom-base-url path, but the named interactive LiteLLM auth choice still prompts only for an API key and falls back to localhost plus one default model when no base URL already exists.

## What This Changes

The issue asks for LiteLLM onboarding to prompt for API key, server URL, and usable model selection instead of skipping URL configuration and offering only one model.

## Best Possible Solution

Add a maintainer-approved provider-owned interactive LiteLLM setup path that captures or confirms the proxy base URL before model selection, preserves the shipped non-interactive behavior, and documents when users should choose LiteLLM versus Custom Provider.
