## Summary

Keep open: current main and v2026.6.11 fixed the non-interactive `--custom-base-url` path, but the reported interactive LiteLLM onboarding path still has no provider-owned base-URL prompt before model selection.

## What This Changes

The issue reports that interactive `openclaw onboard` for LiteLLM skips server URL setup and leaves users with the localhost default plus one seeded model.

## Best Possible Solution

Add a maintainer-approved LiteLLM setup path that captures or confirms the proxy base URL before model selection, preserves the existing non-interactive `--custom-base-url` behavior, and aligns any live discovery with provider-catalog policy.
