## Summary

Keep open: current main and v2026.6.11 still leave the named LiteLLM interactive onboarding path on a generic API-key setup, so the reported URL/model-selection gap remains despite the related non-interactive custom-base-url fix.

## What This Changes

The issue requests LiteLLM onboarding to collect an API key and server URL, then present the proxy's available models instead of defaulting to localhost plus one model.

## Best Possible Solution

End state should be a maintainer-approved LiteLLM setup path that captures or clearly routes proxy base URL setup before model selection, with focused tests and docs for the chosen boundary.
