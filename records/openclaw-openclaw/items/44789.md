## Summary

Keep open: current main and the latest release still do not provide an interactive LiteLLM server URL prompt before LiteLLM model selection, so the reported onboarding gap remains real and needs maintainer direction.

## What This Changes

The issue reports that interactive `openclaw onboard` no longer prompts for the LiteLLM server URL and then only offers one default model.

## Best Possible Solution

Add a maintainer-approved LiteLLM interactive setup path that captures or confirms the proxy base URL before model catalog loading, preserves the Custom Provider and non-interactive paths, and documents when each path should be used.
