## Summary

Keep open: current main and the latest release still leave the named LiteLLM interactive onboarding choice on the generic API-key path, so the central URL prompt/model-discovery complaint remains despite the narrower non-interactive `--custom-base-url` fix that was carried forward from https://github.com/openclaw/openclaw/pull/66160.

## What This Changes

The issue asks for LiteLLM onboarding to collect the proxy API key and server URL interactively, then offer the proxy's available models instead of only the seeded default.

## Best Possible Solution

Add a maintainer-approved LiteLLM setup path that captures or confirms the proxy base URL before model selection, preserves the existing non-interactive `--custom-base-url` behavior, and keeps any live catalog discovery aligned with provider security policy.
