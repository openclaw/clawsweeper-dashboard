## Summary

Keep open: current main and v2026.6.11 still do not give LiteLLM interactive onboarding a base-URL step, so remote LiteLLM proxy users can still land on the localhost default and one seeded model. The remaining repair needs maintainer direction because the right product shape could be a LiteLLM-specific prompt, Custom Provider guidance, or broader live catalog discovery.

## What This Changes

The issue asks for LiteLLM onboarding to collect API key, server URL, and usable model choices instead of skipping URL setup and showing one model.

## Best Possible Solution

Add a maintainer-approved LiteLLM setup path that captures or confirms the proxy base URL before model selection, preserves the existing non-interactive --custom-base-url behavior, and coordinates any live model discovery with provider-catalog policy.
