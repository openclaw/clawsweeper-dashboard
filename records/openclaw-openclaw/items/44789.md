## Summary

Keep open: current main and the latest release still leave LiteLLM interactive onboarding on the generic API-key path, so the user can end up with the localhost default and one seeded model unless they use the non-interactive flag, existing config, or a custom-provider/manual path.

## What This Changes

The issue reports that LiteLLM onboarding skips the proxy URL configuration step and shows only one model during setup.

## Best Possible Solution

Add a maintainer-approved LiteLLM setup boundary that captures or confirms the proxy base URL before model selection, preserves the existing non-interactive --custom-base-url behavior, and aligns any dynamic model discovery with the broader provider-catalog roadmap.
