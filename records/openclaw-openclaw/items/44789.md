## Summary

Keep open: current main and v2026.6.11 still keep LiteLLM interactive onboarding on the generic API-key path, so remote LiteLLM proxy users can still miss the base-URL setup and end up with the localhost default plus one seeded model.

## What This Changes

The issue asks for LiteLLM interactive onboarding to prompt for the proxy URL and expose the configured proxy's models instead of falling back to localhost with one default model.

## Best Possible Solution

Add a maintainer-approved LiteLLM setup path that captures or confirms the proxy base URL before model selection, preserves the existing non-interactive `--custom-base-url` behavior, and coordinates any live model discovery with the broader provider-catalog policy.
