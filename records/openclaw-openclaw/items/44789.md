## Summary

Keep open: current main and the latest release still leave the named LiteLLM interactive onboarding path on the generic API-key flow, so the server-URL and richer model-selection gap remains a real provider setup issue.

## What This Changes

The issue requests that LiteLLM onboarding capture the proxy server URL and offer the proxy's model choices instead of defaulting to localhost with one model.

## Best Possible Solution

Add a maintainer-approved LiteLLM setup boundary that captures or confirms the proxy base URL before model selection, while preserving the existing non-interactive custom-base-url behavior and keeping broader dynamic discovery aligned with the catalog roadmap.
