## Summary

Keep open: current main and v2026.6.11 still route LiteLLM interactive onboarding through the generic API-key flow, so remote LiteLLM users can miss base URL setup and fall back to localhost plus the single seeded model described in the report.

## What This Changes

The issue asks for LiteLLM onboarding to prompt for API key, server URL, and model selection instead of skipping URL configuration and showing only one default model.

## Best Possible Solution

Make the supported LiteLLM setup path explicit: add provider-owned interactive base URL and model discovery/selection with focused tests and docs, or route remote LiteLLM users clearly to Custom Provider, non-interactive --custom-base-url, or manual config as the intended path.
