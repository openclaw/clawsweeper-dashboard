## Summary

Keep open: current main and the latest release still leave LiteLLM interactive onboarding on the generic API-key path, so remote-proxy users can hit the localhost default and one seeded model; the related PR only fixed non-interactive `--custom-base-url`.

## What This Changes

The issue asks interactive LiteLLM onboarding to prompt for API key and proxy URL, then offer discovered LiteLLM models instead of skipping URL setup and presenting one default model.

## Best Possible Solution

Add a maintainer-approved LiteLLM setup boundary that captures or confirms the proxy base URL before model selection, preserves non-interactive `--custom-base-url`, and aligns any dynamic model discovery with provider-catalog policy.
