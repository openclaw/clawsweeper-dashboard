## Summary

Keep this PR open for an explicit plugin-install owner decision. The patch is a focused, well-proven fix with no concrete correctness finding, but it intentionally changes rollback behavior: a transient rebuild failure can leave the previously installed plugin quarantined rather than restored.

## What This Changes

The PR quarantines managed npm project roots whose registry-backed lock metadata is missing, unreadable, or lacks integrity, rebuilds them cleanly, and adds regression coverage for successful and failed rebuilds.

## Best Possible Solution

Keep strict registry-integrity verification and clean rebuilding, but land only with an approved no-restore contract plus a precise user-facing quarantine path and recovery action when rebuilding fails.
