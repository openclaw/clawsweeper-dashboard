## Summary

Keep this PR open for maintainer review. The package-specific clean rebuild is a focused fix that preserves strict registry-integrity verification, but it intentionally changes rollback behavior: if the rebuild fails, the previously loadable but unverifiable plugin tree remains quarantined rather than becoming active again.

## What This Changes

The PR quarantines managed npm project artifacts when registry integrity exists but the installed lock entry is missing usable integrity metadata, rebuilds from a clean project root, and adds regression coverage.

## Best Possible Solution

Keep the generic package-specific quarantine and strict post-install integrity comparison, while explicitly confirming the fail-closed rollback policy and ensuring failed rebuilds report the quarantine location plus a supported repair path.
