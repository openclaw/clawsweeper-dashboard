## Label Justifications

- `P0`: The documented official WhatsApp ClawHub setup can complete install and QR linking but still leaves the channel unusable with no in-product recovery path.
- `impact:ux-release-blocker`: A community user following the official WhatsApp install/login flow is blocked from a working channel and recovery requires maintainer-level diagnosis of plugin provenance.
- `impact:message-loss`: The linked WhatsApp account remains stopped, so the channel cannot deliver or receive WhatsApp messages.
- `impact:security`: The bug sits directly on the trusted-plugin state boundary that controls which external plugins may use host-managed persistent queues and keyed stores.

## Summary

Keep open: this is a current, source-backed official WhatsApp startup blocker, and current main still lets workspace auto-discovery classify the installed ClawHub plugin before the install-record-backed global path can mark it trusted.

## What This Changes

The issue requests that an official `@openclaw/whatsapp` ClawHub install that links successfully be recognized as trusted so the linked account can start.

## Best Possible Solution

Keep the installed official WhatsApp plugin path trusted by preserving the install-record-backed global provenance when workspace auto-discovery resolves to the same extension directory, with regression coverage for the same-path case and negative coverage for unrelated workspace plugins.
