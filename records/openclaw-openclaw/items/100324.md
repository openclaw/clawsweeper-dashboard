## Summary

Keep open: current main and v2026.6.11 still have a source-reproducible trust/provenance gap where an official ClawHub WhatsApp install can be discovered as workspace-origin, miss `trustedOfficialInstall`, and hit the `openKeyedStore` runtime gate.

## What This Changes

The issue asks OpenClaw to let an official ClawHub-installed WhatsApp plugin start after successful install, enablement, and account linking instead of failing the trusted-plugin state check.

## Best Possible Solution

Add a narrow provenance-preserving rule or discovery normalization so recorded official ClawHub installs keep trusted-official status even when discovered through the workspace root, with regression tests proving unrecorded workspace/load-path/plugins.allow installs remain untrusted.
