## Summary

Keep open: current main still denies trusted state to official ClawHub WhatsApp installs when the resolved candidate is workspace-origin, so the linked-account startup failure remains a real core/plugin trust-boundary bug.

## What This Changes

The issue asks OpenClaw to let an official ClawHub `@openclaw/whatsapp` install start a linked WhatsApp account instead of failing the `openKeyedStore` trusted-plugin check.

## Best Possible Solution

Add a generic official-install provenance rule that trusts only matching official catalog identity, install record, and resolved install path for user-extension installs, with denial coverage for raw workspace shadows and non-official installs.
