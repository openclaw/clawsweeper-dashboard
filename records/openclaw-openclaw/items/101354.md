## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Consolidate the existing URL-embed capability:** `ui/src/lib/workspace/widgets/index.ts:24`
  - body: Workspaces already exposes `builtin:iframe-embed` with the same URL gate and sandbox contract. Adding `builtin:preview` for only reload and width controls creates a second persisted public kind whose policy, rendering, documentation, and migrations can drift; extend the existing embed contract with typed optional controls unless maintainers explicitly approve a permanent distinction.
  - confidence: 0.95
- **[P2] Render the resolved binding value:** `ui/src/lib/workspace/widgets/preview.ts:31-35`
  - body: The renderer receives the resolved widget value but discards it and reads `props.url` directly. That bypasses the standard binding pipeline, so a preview driven by a static or RPC binding will not track resolved value updates; pass the resolved value into the shared URL evaluator as iframe embed does.
  - confidence: 0.98
- **[P2] Keep viewport selection in owned state:** `ui/src/lib/workspace/widgets/preview.ts:48-90`
  - body: The selected viewport is initialized from props and then changed through direct DOM mutation, so a workspace rerender reconstructs the template from the initial value and loses the user's selection. Put the selection in the owning component or workspace state and render the class and `aria-pressed` values from that state.
  - confidence: 0.9
- **[P2] Synchronize the generated locale bundles:** `ui/src/i18n/locales/en.ts:2184-2196`
  - body: This adds nine English keys while leaving all generated locale bundles stale, and the PR body confirms the dedicated i18n check fails. Run the repository translation synchronization path or obtain the required generated update before merging so non-English builds satisfy the locale contract.
  - confidence: 0.99
