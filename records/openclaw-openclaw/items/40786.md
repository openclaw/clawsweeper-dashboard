## Label Justifications

- `P2`: The request is a meaningful backup security and reliability improvement, but it is a bounded CLI feature rather than an emergency runtime outage.
- `impact:data-loss`: Oversized or unreliable native backups can leave users without a restorable local-state archive when recovery is needed.
- `impact:security`: The issue specifically calls out inability to exclude sensitive workspace files such as `.env`, private keys, and PEM files from archives.

## Summary

Keep open: current main still lacks `.gitignore`-style backup exclude flags; it only has built-in filtering for volatile state and extension `node_modules` trees. https://github.com/openclaw/openclaw/pull/44288 is an open implementation candidate, and https://clawhub.ai/Ryce/keepmyclaw is a useful workaround mentioned in discussion, but neither makes the native backup CLI request implemented or obsolete.

## What This Changes

Add repeatable exclude patterns and an exclude-file style input to `openclaw backup create` so large, sensitive, or noisy files can be omitted from native backups.

## Best Possible Solution

Settle the native backup exclude contract in the linked PR or a replacement: explicit CLI flags, protected-path policy, default behavior, manifest privacy semantics, docs, and real backup/restore proof before closing this issue.
