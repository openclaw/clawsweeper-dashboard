## Label Justifications

- `P2`: This opt-in feature has two concrete normal-priority correctness blockers but does not currently break the released core runtime.
- `merge-risk: 🚨 session-state`: The new projected-run path can associate one agent's hidden worker run with another agent's shared session state.
- `merge-risk: 🚨 message-delivery`: The capacity-reset path can acknowledge an event and release its ownership before asynchronous fanout delivers it.

## Summary

The exact head is not merge-ready: projected hidden runs bypass the established per-agent scoping for the shared `global` session, and the capacity-reset path can release an accepted event’s exclusive claim before deferred gateway fanout processes it. The authenticated worker boundary itself is well constrained, but both correctness blockers and final-head real behavior proof remain outstanding.

## What This Changes

Adds a feature-negotiated worker live-event RPC with bounded replay, ACK and epoch fencing, exclusive run ownership, session identity rebinding, and projection through the existing agent/session fanout.

## Best Possible Solution

Keep the existing single fanout architecture, add agent-aware projected-run matching for shared session keys, retain each accepted event's ownership until its queued projection settles, and then demonstrate reconnect, replay, deduplication, fencing, and selected-session output on the final head in a real worker setup.

No, not in the current head. Reusing the existing fanout is the narrowest maintainable architecture, but the integration must first preserve its established agent scoping and accepted-event lifetime contracts.
