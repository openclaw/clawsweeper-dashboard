## Summary

The central bug remains on current main: caller-aborted foreground exec settles as a failed payload, which agent-core records as a non-error result; cancellation already stops the run, so continued model execution and resource-leak claims are not established.

## What This Changes

Correct foreground bash cancellation so caller aborts propagate as aborts rather than ordinary resolved tool results.

## Best Possible Solution

Record caller cancellation for foreground runs, kill the process, await the existing finalized run promise, then reject with the signal reason or a canonical AbortError while retaining normalized results for timeouts, explicit process kills, and background sessions.

## Reproduction Assessment

Yes at source level with high confidence: caller-aborted foreground exec fulfills with a failed payload, and agent-core marks fulfilled executions non-error. The reported extra model steps do not reproduce because the loop separately observes the aborted signal and stops.

## Solution Assessment

Yes in direction, but the proposed immediate rejection is not the safest implementation; rejection should occur after the killed process and owned sandbox/session finalization settle.
