## Label Justifications

- `P2`: The bug misclassifies a cancelled core tool call, but current code still terminates the agent run, limiting the blast radius.
- `impact:session-state`: The cancelled tool is recorded and emitted with a successful execution flag before the run's aborted terminal state.

## Summary

Current main does stop the agent run after cancellation, so the reported continued execution and resource-leak impact is overstated. However, the central classification bug remains: a cancelled foreground exec resolves a failed payload, and agent-core classifies every resolved tool execution as successful.

## What This Changes

Make a foreground bash exec cancelled by the agent AbortSignal settle as an aborted/error tool call rather than a successfully resolved execution.

## Best Possible Solution

Track caller-signal cancellation in the foreground wrapper, kill and await the existing run cleanup, then reject with the signal reason or canonical AbortError; retain normalized outcomes for timeouts, explicit process-tool kills, and background sessions.

## Reproduction Assessment

Yes at source level with high confidence: a caller-aborted foreground exec resolves a failed payload, and agent-core assigns isError false to resolved executions. The claimed extra model steps are not reproducible because the loop separately observes the aborted signal and stops.

## Solution Assessment

Yes in direction, with one correction: reject only after the killed process and sandbox finalization settle, rather than rejecting immediately from the abort callback. This preserves cleanup and the intentional background-session exception.
