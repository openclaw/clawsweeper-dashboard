## Summary

Current main still permits direct SIGTERM/SIGINT shutdown to exit after `server.close()` without awaiting an already-started `session_end` continuation whose session was removed from the active-session tracker. The issue remains necessary as a narrow follow-up to the earlier active-session shutdown fix.

**Likely related people**
- `steipete` — high confidence; recent contributor across the current gateway stop and work-admission paths.
- `pandadev66` — high confidence; introduced the active-session shutdown drain in the merged predecessor PR.
- Julia Bush — medium confidence; previously hardened the gateway SIGTERM lifecycle.

## What This Changes

Ensure direct gateway shutdown waits for pending asynchronous `session_end` plugin work before process exit.

## Best Possible Solution

Add a bounded drain primitive to the canonical gateway work-admission lifecycle and invoke it during direct stop before teardown and process exit, while keeping the active-session tracker responsible only for hooks that have not started.

## Reproduction Assessment

Yes, at source level with high confidence. Hold a normal reset-triggered `session_end` continuation pending after its tracker entry is forgotten, then signal direct gateway stop; the current stop path can exit without awaiting that continuation.

## Solution Assessment

No, not exactly as proposed. Returning and awaiting the hook promise at every normal caller would broaden reset/delete latency; the narrower maintainable repair is a bounded direct-stop drain of the existing canonical gateway root-work set.

## Repair Work Prompt

Reuse the canonical gateway work-admission subsystem by adding a bounded await/drain primitive for already-admitted root continuations and invoking it in the direct stop lifecycle before subsystem teardown and `exitProcess(0)`. The regression must cover a pending `session_end` continuation launched by normal reset, deletion, or compaction after `forgetActiveSessionForShutdown` removed its active-session tracker entry. Keep `drainActiveSessionsForShutdown` responsible for sessions whose hook has not started, preserve no-double-fire behavior, rejection cleanup, forced-restart semantics, and the existing shutdown watchdog, and do not add configuration, new hook reasons, a parallel hook-specific pending registry, compatibility fallbacks, or `CHANGELOG.md` edits. Add focused coverage for successful settlement, rejected continuation cleanup, bounded timeout behavior, direct-stop ordering, and unchanged restart behavior.
