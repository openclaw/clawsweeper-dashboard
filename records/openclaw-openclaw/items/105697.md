## Summary

Current source supports the reported race on direct gateway stop: normal lifecycle finalization removes the session from the active-session drain before its asynchronous `session_end` work settles, and SIGTERM/SIGINT close has no separate wait for that pending hook. The item remains necessary as a narrow follow-up to the shipped active-session shutdown fix.

## What This Changes

Ensure gateway shutdown does not terminate while an already-started asynchronous `session_end` plugin hook is still completing.

## Best Possible Solution

Extend the existing bounded shutdown finalization design to await `session_end` executions already started by normal lifecycle paths, without re-emitting them or slowing normal reset/delete responses.

## Reproduction Assessment

Yes at source level with high confidence: hold a reset-triggered `session_end` hook pending, then invoke direct gateway shutdown after its tracker entry is removed; the close drain has no remaining handle to await it. A live process reproduction was not run during this read-only review.

## Solution Assessment

No, not exactly as proposed; returning a promise can support the implementation, but the narrow maintainable fix is a bounded gateway-close drain of already-started session-end work rather than making every lifecycle caller synchronously wait for plugins.
