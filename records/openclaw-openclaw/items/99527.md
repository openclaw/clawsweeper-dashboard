## Summary

Keep open: current main still truncates the edit mismatch hint with UTF-16 `slice(0, 800)`, while this PR narrowly fixes that diagnostic boundary, adds focused coverage, and now includes sufficient copied live-output proof from a non-test edit-tool invocation.

## What This Changes

The PR changes the edit-tool mismatch hint formatter to truncate current-file-content diagnostics by Unicode code point and adds a regression test for an emoji at the cutoff.

## Best Possible Solution

Land the focused formatter and regression test after normal maintainer review, while preserving the same Unicode-safe truncation invariant if broader edit-mismatch diagnostic PRs land later.

## Reproduction Assessment

Yes. Source inspection shows current main slices the mismatch hint at 800 UTF-16 code units, so a file with 799 ASCII characters followed by an emoji and more text can be truncated between surrogate halves; I did not run the repro locally because this was a read-only review.

## Solution Assessment

Yes. Fixing the truncation primitive inside the private mismatch-hint formatter is the narrowest maintainable solution because it preserves edit matching, write behavior, protocols, renderers, and the existing truncation marker.
