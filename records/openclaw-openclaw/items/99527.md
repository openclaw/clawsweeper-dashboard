## Summary

Keep open: current main still truncates the edit mismatch hint with raw UTF-16 slicing, and this PR is a narrow correct fix, but the external-PR real behavior proof is still test/check-only.

## What This Changes

The PR replaces raw UTF-16 slicing in the edit-tool mismatch hint with private code-point truncation and adds a focused regression test.

## Best Possible Solution

Land the focused formatter and regression test after contributor-supplied non-test real behavior proof, then preserve the same truncation invariant in any broader edit-mismatch diagnostic work.

## Reproduction Assessment

Yes, source-level. Current main slices the mismatch hint at 800 UTF-16 code units, so a file with 799 ASCII characters followed by an emoji and more text can be truncated between surrogate halves; I did not execute a runtime repro in this read-only review.

## Solution Assessment

Yes. Fixing the truncation primitive inside the private mismatch-hint formatter is the narrowest maintainable solution because edit matching, write behavior, protocols, renderers, and config stay unchanged.
