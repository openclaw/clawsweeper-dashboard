## Summary

Keep open: current main still routes tool-result content through the conservative /2 estimator after CJK character inflation, while this branch fixes that remaining estimator path with focused regression coverage and sufficient helper-level proof.

## What This Changes

The PR changes preemptive compaction token-pressure estimation so CJK-heavy tool results use the normal CJK-aware ratio, adds a CJK-ratio helper, and adds regression tests for CJK, mixed, JSON, Latin-only, and circular payloads.

## Best Possible Solution

Land the focused estimator fix with its regression coverage once maintainers accept the CJK calibration risk; keep the merged context-engine skip as complementary partial coverage.

## Reproduction Assessment

Yes, source-reproducible: current main sends tool-result content through the /2 token-pressure path after CJK inflation, so a CJK-heavy tool result can be overestimated and routed to precheck overflow. I did not run tests because this review is read-only, but the PR body includes terminal output from production helpers showing the after-fix route change.

## Solution Assessment

Yes. The PR changes the owner estimator used by both pre-prompt and mid-turn precheck routing, preserves non-CJK conservatism, and covers structured/fallback payloads; the merged context-engine skip only fixes a narrower subset.
