## What This Changes

The PR makes preemptive-compaction tool-result token estimation choose the standard CJK-aware ratio for CJK-heavy content, adds an exported CJK ratio helper, and adds regression coverage for CJK, mixed, JSON, Latin, and unserializable payloads.

## Best Possible Solution

Land a narrow estimator fix that preserves conservative Latin tool-result accounting while using CJK-aware pressure for CJK-heavy tool results, with focused regression tests and no config or API surface.

## Reproduction Assessment

Yes by source inspection, though not by live execution in this read-only review. Current main divides weighted CJK tool-result content by 2, so CJK-heavy tool results can be estimated at about double the standard CJK-aware pressure and routed as false overflow.

## Solution Assessment

Yes. This is the narrow owner-boundary fix because it changes the built-in precheck estimator itself, preserves non-CJK conservative behavior, and avoids duplicating the context-engine-specific workaround.
