## Summary

Keep open: current main still uses the overestimating `/2` tool-result path, while this PR is a focused, proof-backed bug fix with no blocking code findings. The remaining merge call is maintainer acceptance of the calibrated CJK-heavy precheck routing.

## What This Changes

The PR adds CJK-ratio-aware token estimation for tool-result payloads in preemptive compaction and adds focused regressions for CJK, mixed, JSON, Latin-only, and non-serializable payloads.

## Best Possible Solution

Land the focused estimator fix after maintainers accept the CJK calibration risk; keep the merged ownsCompaction skip as the partial context-engine mitigation, not a replacement for this built-in estimator fix.

## Reproduction Assessment

Yes. On current main, a CJK-heavy toolResult message passed to `estimateLlmBoundaryTokenPressure` or `shouldPreemptivelyCompactBeforePrompt` follows the `/2` tool-result path after CJK inflation and can false-overflow; I did not run local tests because this review is read-only.

## Solution Assessment

Yes. Changing the owner estimator is the best bounded fix for the remaining built-in and mid-turn precheck path because it preserves non-CJK conservatism and covers structured/fallback payloads; the merged context-engine skip only covers one narrower configuration.
