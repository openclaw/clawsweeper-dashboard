## Summary

Keep this PR open but do not merge yet: the CJK-aware precheck fix is useful and well-proven for the helper it changes, but current main has a sibling tool-result context guard that still applies the old `/2` estimate and can truncate the same CJK-heavy payload before provider replay.

## What This Changes

The PR adds CJK-ratio-aware token pressure estimation for tool-result content, exports a CJK ratio helper, and adds preemptive-compaction regression tests for CJK, mixed, JSON, Latin-only, and non-serializable payloads.

## Best Possible Solution

Unify CJK-aware tool-result calibration across the pre-prompt estimator and the live tool-result context guard, with focused tests proving CJK-heavy results are not falsely compacted or truncated while Latin-heavy results remain conservative.

## Reproduction Assessment

Yes, source-reproducible: current main applies `/2` after CJK char inflation in estimateToolResultContentTokenPressure, and the sibling guard still multiplies tool-result chars by 4/2 before replay truncation. I did not run tests because this review is read-only.

## Solution Assessment

No, not yet: changing the precheck estimator is the right layer for one half of the bug, but the best fix also shares the same CJK calibration with the live tool-result context guard so the two runtime decisions cannot disagree.
