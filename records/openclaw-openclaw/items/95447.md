## Label Justifications

- `P1`: The PR fixes a user-facing agent workflow failure where CJK-heavy tool results can falsely trigger precheck context overflow and interrupt a run.

## Summary

Keep open: current main and the latest release still apply the conservative `/2` tool-result ratio after CJK character inflation, while this PR directly repairs that estimator path and has no blocking correctness or security findings from this review.

## What This Changes

This PR adds a CJK-ratio helper and uses it to apply the normal `/4` estimator to CJK-heavy tool-result payloads while preserving `/2` for non-CJK payloads, with regression coverage for text, mixed, JSON, and fallback content.

## Best Possible Solution

Land the focused estimator fix after normal maintainer review, keeping the non-CJK conservative path and the new payload-branch regression coverage intact.

## Reproduction Assessment

Yes, at source/proof-helper level: current main and v2026.6.11 still divide CJK-weighted tool-result content by `/2`, and the PR body plus CI proof show production-helper routing changes from false overflow to `fits`. I did not run a live provider repro in this read-only review.

## Solution Assessment

Yes. This is the narrowest maintainable fix I found because it repairs the implicated estimator directly, leaves non-CJK tool-result conservatism in place, and avoids broad context-engine or provider-specific policy changes.
