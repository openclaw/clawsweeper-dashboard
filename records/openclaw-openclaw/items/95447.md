- `P1`: The PR addresses a broken agent workflow where CJK-heavy tool results can falsely trigger pre-prompt overflow and interrupt real Chinese-language sessions.

## Summary

Keep open. Current main and the latest release still use the fixed /2 tool-result ratio, while this mergeable PR updates that estimator path with focused CJK/JSON/fallback coverage, sufficient terminal proof, and no blocking review finding.

## What This Changes

The PR changes preemptive compaction token estimation so CJK-heavy tool-result payloads use a CJK-aware ratio, adds an exported CJK-ratio helper, and extends the preemptive-compaction regression tests for CJK, JSON, mixed, and non-serializable payloads.

## Best Possible Solution

Land this focused estimator fix after maintainer review, and track continuous mixed-language weighting separately only if sub-50% CJK payloads still produce false overflows.

## Reproduction Assessment

Yes, by source inspection: current main and v2026.6.11 still estimate tool-result content with estimateStringChars(...)/2, which counts CJK-heavy tool results at about two tokens per CJK character before the safety margin. I did not rerun the helper script because this review was read-only, but the PR body includes terminal proof against the production helpers.

## Solution Assessment

Yes. The patch fixes the owner estimator path rather than bypassing precheck or changing context-engine policy; an exact tokenizer or continuous weighting model would be broader and can remain a follow-up unless the threshold heuristic proves insufficient.
