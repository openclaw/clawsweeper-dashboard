## Summary

Keep open for maintainer review: current main still overestimates CJK-heavy tool-result content in the built-in precheck path, and this PR is a focused fix with no blocking correctness finding. The remaining decision is whether maintainers accept the availability-path calibration risk before merge.

## What This Changes

The branch adds CJK-ratio-aware tool-result token pressure estimation, exports an `estimateCjkRatio` helper, and adds regression tests for CJK, mixed, JSON, Latin-only, and circular tool-result payloads.

## Best Possible Solution

Land the focused estimator fix after maintainer acceptance of the availability calibration; keep the merged https://github.com/openclaw/openclaw/pull/95342 as a complementary partial fix, not a replacement.

## Reproduction Assessment

Yes. On current main, a CJK-heavy `toolResult` content path calls `estimateStringChars` and then divides by `TOOL_RESULT_CHARS_PER_TOKEN = 2`, so the source path clearly double-counts CJK-rich tool results.

## Solution Assessment

Yes. This is the narrowest maintainable fix for the remaining built-in estimator path because it changes the owner calculator, preserves non-CJK conservatism, and covers structured and non-serializable payloads; the merged context-engine skip only handles a subset.
