## What This Changes

The PR changes built-in preemptive compaction token estimation so CJK-heavy tool-result payloads use the normal CJK-aware character/token ratio while non-CJK-heavy tool results keep the conservative estimate, with focused regression tests.

## Best Possible Solution

Land the focused estimator change once maintainers accept the CJK availability calibration and keep the merged context-engine skip as a separate partial protection.

## Reproduction Assessment

Yes, source-reproducible: current main applies `TOOL_RESULT_CHARS_PER_TOKEN = 2` to tool-result content after CJK character inflation, so a CJK-heavy toolResult payload can be overestimated enough to route to compaction or truncation before submission. I did not run tests because this review is read-only.

## Solution Assessment

Yes. Changing the owner estimator is the bounded fix for built-in and mid-turn precheck paths, while the merged context-engine skip only covers engines that own compaction.
