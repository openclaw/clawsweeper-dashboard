- `P1`: The PR addresses a user-facing agent availability failure where CJK-heavy tool results can trigger false precheck overflow and interrupt Chinese workflows.

## Summary

Keep open. The CJK overestimation is still present on current main and in the latest release, while this PR’s merge result applies the fix to the runtime estimator, adds focused regression coverage, and has sufficient terminal proof with no blocking findings from this review.

## What This Changes

The PR makes tool-result token pressure use the normal CJK-aware ratio for CJK-heavy payloads, keeps the conservative ratio for non-CJK tool results, and adds CJK, JSON, and serialization regression tests.

## Best Possible Solution

Land a focused estimator fix that keeps non-CJK conservative behavior, preserves current-main precheck accounting, and leaves broader measured-overflow recovery to its separate maintainer-owned PR.

## Reproduction Assessment

Yes by source inspection: current main and v2026.6.11 still apply `estimateStringChars(...)/2` to CJK-heavy tool results, which overestimates CJK payloads before the agent prompt is submitted. I did not run the contributor's standalone script in this read-only review.

## Solution Assessment

Yes. Adjusting the existing tool-result estimator is narrower than the earlier context-engine override attempt because it fixes the built-in precheck path directly without adding config, provider routing, or a second source of token-pressure truth.
