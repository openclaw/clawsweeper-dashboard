## Label Justifications

- `P1`: The PR addresses a broken agent precheck path that can interrupt CJK-heavy workflows with false context-overflow handling.
- `merge-risk: 🚨 availability`: Merging changes the overflow precheck estimate that decides whether an agent turn compacts before provider submission, so underestimation could surface as provider-side overflow.

## Summary

Keep this PR open: current main still overestimates CJK-heavy built-in tool-result payloads on the precheck path, while this focused patch fixes that estimator path and adds targeted text, JSON, mixed, Latin, and serialization fallback coverage. I found no blocking correctness or security finding, but the precheck remains availability-sensitive because it decides whether an agent turn compacts, truncates, or submits.

## What This Changes

The PR changes agent preemptive-compaction token estimation so CJK-heavy tool-result payloads use the shared CJK-aware character ratio while non-CJK payloads keep the conservative tool-result ratio.

## Best Possible Solution

Land a rebased version of this focused estimator change if maintainers accept the bounded token-estimation risk; keep broader tokenizer-specific precision as a separate design follow-up.

## Reproduction Assessment

Yes. Source inspection shows current main still applies the 2 chars/token tool-result divisor after CJK inflation, and the PR body's terminal proof exercises the production helpers showing CJK-heavy payloads move from false overflow to `fits`; I did not run local tests because this review is read-only.

## Solution Assessment

Yes. This is the best bounded fix for this bug class because it repairs the shared built-in tool-result estimator, preserves conservative non-CJK behavior, and covers text, JSON, and fallback payloads without adding config or a context-engine-only bypass.
