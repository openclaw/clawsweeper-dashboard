## Summary

Keep open: current main and the latest release still let startup catch-up collect a stale due `nextRunAtMs` before the already-executed slot guard runs, so duplicate isolated agent-turn cron reruns remain a valid narrow bug with no canonical fix PR.

## What This Changes

The issue asks OpenClaw to skip restart catch-up for cron jobs whose successful last run already covers the current schedule slot.

## Best Possible Solution

Apply the existing already-executed-slot invariant before startup catch-up queues candidates, while preserving failed/skipped retry behavior, error backoff, and legitimate missed-slot replay.
