- `impact:session-state`: The bug is driven by stale persisted cron run state causing an already-completed schedule slot to be treated as runnable again.

## Summary

Keep open: current main and the latest release still let startup catch-up collect a stale due cron `nextRunAtMs` before the already-executed-slot guard runs, and the two linked closing PRs are still open rather than merged.

## What This Changes

The issue requests that Gateway startup catch-up skip cron jobs whose current schedule slot already completed successfully.

## Best Possible Solution

Land one narrow cron scheduler fix that applies the already-executed-slot invariant before startup catch-up queues work, while preserving failed/backoff retry, later missed-slot replay, and exact-boundary replay.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, source-level: a cron job with stale due `nextRunAtMs`, `lastRunStatus: ok`, and `lastRunAtMs >= nextRunAtMs` can reach startup catch-up before maintenance recompute. I did not run the live macOS restart scenario in this read-only review.

## Solution Assessment

Yes, the best fix is a narrow scheduler runnable-gate change, not a new config option or broader catch-up policy. The remaining task is to consolidate and land one of the open candidate PRs with proof for stale-ok skip and missed-slot boundary behavior.
