## Summary

Keep open: current main still has a startup catch-up path that can treat a stale due `nextRunAtMs` as runnable before checking whether `lastRunStatus`/`lastRunAtMs` already cover that slot, and no open canonical PR owns this narrow duplicate-rerun fix.

## What This Changes

The issue requests skipping Gateway restart catch-up for cron jobs that already completed successfully within the current schedule window.

## Best Possible Solution

Teach startup catch-up to skip or recompute already-executed due slots before collecting candidates, while preserving failed/skipped retry behavior, error backoff, and legitimate missed-slot replay.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level: startup catch-up loads persisted cron state without recomputing and returns runnable for a due `nextRunAtMs` before checking whether `lastRunAtMs` already covers that slot. I did not run the live restart scenario in this read-only review.

## Solution Assessment

Yes. The narrow scheduler fix is to apply the existing already-executed-slot invariant before startup catch-up queues a job, with regression coverage for isolated agent-turn cron jobs using `lastRunStatus: ok` and stale due `nextRunAtMs`.
