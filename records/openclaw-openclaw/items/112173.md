## Summary

This appears to be a concrete Windows service regression: a hidden console can satisfy the ACP resolver’s TTY check even though no person can answer its permission prompt, leaving a worker blocked until later cleanup. Keep it open for source-level confirmation and a bounded fix; current-main, release, and history evidence could not be inspected because the read-only review environment failed before any repository command could run.

## What This Changes

Prevent ACP worker permission requests from waiting indefinitely when the Gateway runs as a Windows hidden-console service with unusable interactive input.

## Best Possible Solution

Make the canonical Windows service launch path explicitly non-interactive, preserve normal interactive Gateway behavior, and add regression coverage for hidden-console service execution or the equivalent service-marker contract.
