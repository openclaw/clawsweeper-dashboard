- **[P1] Restore the MCP client close hook:** `src/agents/agent-bundle-mcp-runtime.ts:713-726`
  - body: `createResolvedSession` now returns the session object without reattaching the `client.onclose` callback that current main uses to mark `connected = false` and set `disconnectReason`. After a transport closes, later catalog refreshes can treat a closed client as still connected instead of retiring/recreating it, so build the session object, attach the close handler, then return it.
  - confidence: 0.9

  - body: `connectedForCatalog` is assigned during catalog loading and retry setup but never read, which is already failing `check-prod-types` with TS6133 and `check-lint` with `no-unused-vars`. Remove the flag or use an existing connected-session state before merge.
  - confidence: 0.98
- **[P2] Preserve the caught disconnect error:** `src/agents/agent-bundle-mcp-runtime.ts:668-672`
  - body: These new errors are thrown inside `catch (error)` without attaching the caught error as `cause`, which drops the original transport failure and currently fails `check-lint` via `preserve-caught-error`. Wrap them with `{ cause: error }` or route through a helper that preserves the original error.
