## Summary

Keep open: current main has shipped partial structured `server_error` cron retry support, but the reported plain `LLM error api_error: Internal server error` cron/fallback path is still timeout-classified and not proven to fast-fail, alert, or recover missed scheduled windows before the outer cron timeout.

## What This Changes

Issue #45494 asks cron agent jobs to stop silently timing out during sustained LLM API outages and instead classify definitive provider errors, fail or back off quickly, and surface missed delivery windows.

## Best Possible Solution

Define and test a maintainer-approved policy where plain provider 500s fail early for cron without unsafe shared provider-health poisoning, with focused classifier, fallback timing, retry, and failure-alert coverage.
