## Summary

Keep open: current main and v2026.6.11 still do not prove the reported plain `api_error: Internal server error` cron outage path fast-fails before consuming the cron run window. The merged structured `server_error` work is a useful partial fix, but the plain provider error still routes through timeout-style classification and the remaining classification/cooldown policy needs maintainer direction.

## What This Changes

The issue requests cron agent jobs to fail and retry promptly when LLM provider outage errors repeat across the fallback chain instead of consuming the full cron timeout window.

## Best Possible Solution

Keep this as the canonical plain API internal-server cron outage item, choose the failure classification policy explicitly, then land focused coverage for plain SDK `api_error`, fallback timing, cron retry/backoff, and failure-alert behavior.

Options:
