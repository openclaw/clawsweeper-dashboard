## Summary

Keep open: current main has useful structured `server_error` cron retry support, but the reported plain `LLM error api_error: Internal server error` path remains a timeout/policy surface and is not proven to fast-fail before the cron wall-clock deadline.

## What This Changes

The issue asks OpenClaw cron agent jobs to fail fast, retry with backoff, and surface delivery notification when sustained provider HTTP 500/internal-server errors would otherwise consume the full cron timeout.

## Best Possible Solution

Keep the issue open for a maintainer-owned policy and proof pass: plain provider 500s should fail early for cron without unsafe shared provider-health poisoning, with regression coverage for the real cron fallback chain and failure-alert behavior.

## Maintainer Decision

Required: true

Kind: product_direction

Question: For plain provider messages like `LLM error api_error: Internal server error`, should OpenClaw treat them as shared provider cooldown signals, cron-local transient retry signals, or only generic timeouts with additional timing proof?

Rationale: Current main already handles structured `server_error`, but plain internal-server text remains timeout-like; changing that policy affects cron recovery, fallback latency, and whether provider/profile health may be suppressed across other runs.

Likely owner: steipete

Owner reason: The choice is a maintainer policy decision spanning cron, provider health, and fallback behavior, and steipete is the strongest human maintainer/area-routing signal in the checked history.

Owner confidence: medium

Options:

- **Cron-local transient server error (recommended):** Classify the cron-visible plain internal-server text as retryable `server_error` for cron retry and failure-alert behavior without marking shared auth-profile cooldown.
- **Shared provider cooldown:** Treat plain internal-server failures as provider outage signals that can skip same-provider candidates across runs, accepting broader cooldown effects.
- **Keep timeout-only with proof:** Leave plain provider 500 text timeout-like only if focused cron/fallback tests prove the run fast-fails before the outer deadline.
