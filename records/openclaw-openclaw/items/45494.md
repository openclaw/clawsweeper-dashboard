## Summary

Keep open: current main and the shipped structured `server_error` retry work cover only part of the cron outage problem, while the reported plain provider/SDK `api_error: Internal server error` fast-fail and cooldown behavior remains unresolved.

## What This Changes

Cron agent jobs should classify sustained provider API server errors early, avoid burning the full cron timeout, retry or back off, and surface skipped or failed runs to delivery.

## Best Possible Solution

Choose a maintainer-approved policy for plain provider internal-server errors, then add focused classifier, fallback timing, cron retry/backoff, and failure-alert coverage around that policy.
