## Summary

Keep open: current main has useful structured `server_error` cron retry support, but it does not prove the reported plain `LLM error api_error: Internal server error` path fast-fails across the fallback chain or surfaces the skipped cron window before the outer timeout.

## What This Changes

The issue asks cron agent jobs to fail, retry/back off, and notify quickly during sustained LLM provider 500 outages instead of consuming the full `timeoutSeconds` window.

## Best Possible Solution

Add a focused cron/provider-outage policy that handles plain API internal-server failures without burning the whole cron wall-clock budget, surfaces a failure notification, and leaves broader reason-aware guardrails to the open umbrella work.
