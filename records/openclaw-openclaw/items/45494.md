## Summary

Keep open: current main still does not prove the plain `api_error: Internal server error` cron outage path fast-fails before the cron run window is consumed. The merged structured `server_error` retry work is useful partial coverage, but the plain provider-error classification and cooldown policy still need maintainer direction.

## What This Changes

The issue asks for cron agent jobs to fast-fail, retry or back off, and surface delivery when sustained LLM provider 500/API errors would otherwise consume the full run timeout.

## Best Possible Solution

Choose the plain API internal-server classification policy explicitly, then land focused coverage for the plain SDK error, fast fallback before the cron window is consumed, cron retry/backoff, and failure-alert behavior while keeping stream-stall budgeting separate.
