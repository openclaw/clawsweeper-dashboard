## Summary

Keep #45494 open: current main has merged structured `server_error` cron retry/state support, but the reported plain provider/SDK `api_error: Internal server error` fast-fail path is still unresolved and changes provider classification plus cooldown semantics.

## What This Changes

The issue asks cron agent jobs to classify sustained provider API outages distinctly so they can stop retry storms, retry/back off appropriately, record the reason, and alert instead of burning the full timeout silently.

## Best Possible Solution

Choose a maintainer-approved policy for plain provider internal-server errors, then add focused classifier, fallback timing, cron retry/backoff, and alert-state coverage around that policy.
