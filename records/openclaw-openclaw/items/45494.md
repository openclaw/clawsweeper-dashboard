## Summary

Keep open: current main has useful partial coverage for structured `server_error` cron retries, but it still does not prove the reported plain `api_error: Internal server error` outage path fast-fails before the cron window is consumed, and the remaining classifier/cooldown behavior needs maintainer direction.

## What This Changes

The issue asks OpenClaw to make cron agent jobs fail or retry promptly during sustained LLM provider 500 outages instead of burning the full cron `timeoutSeconds` window and silently missing scheduled work.

## Best Possible Solution

Choose the plain API internal-server classification policy, then land focused coverage proving the plain SDK error fast-fails or retries before the cron window is consumed, surfaces failure notification, and keeps stream-stall budgeting separate.
