## Summary

This remains a plausible, narrowly scoped Slack probe bug: the outer deadline returns control but does not govern the SDK request lifecycle, while the Slack client has its own transport timeout and lengthy default retry behavior. Current source evidence is strong enough to keep and route the issue, but a controlled socket/request reproduction is still needed before calling it fully reproduced.

## What This Changes

Make Slack authentication probes terminate their underlying HTTP work when the configured probe timeout expires.

## Best Possible Solution

Configure the probe's Slack `WebClient` with the probe deadline as its native transport timeout and a probe-appropriate no-retry policy, then add focused coverage showing timeout completion does not trigger late requests or retries; do not add a new config or environment variable.
