## Summary

This remains a credible, narrowly owned Slack probe defect: the outer deadline can return while the Slack SDK request queue, retries, and transport continue independently. Current source and the official SDK contract support a focused repair, but the issue does not yet include a controlled socket-level reproduction proving the claimed leak magnitude.

## What This Changes

Make Slack health-probe timeouts terminate the underlying Web API request instead of only rejecting the outer deadline promise.

## Best Possible Solution

Construct the probe client with a transport timeout derived from `timeoutMs` and a probe-specific zero- or tightly bounded-retry policy, retain only a slightly wider outer guard if needed, and add a slow-server regression test proving that the request closes promptly without affecting normal Slack clients.
