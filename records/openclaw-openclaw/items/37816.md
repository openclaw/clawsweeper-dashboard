## Summary

Keep open: current main has Telegram preview/progress streaming, durable `/verbose` and `/reasoning` paths, and browser-local Control UI Activity, but it still does not provide the requested persistent per-step Telegram activity-message mode. The remaining work changes Telegram disclosure, retention, notification volume, and likely public config policy, so it needs maintainer product and security direction.

## What This Changes

Request a Telegram mode that mirrors Web UI activity visibility by rendering each reasoning, tool, memory, and final-answer step as persistent separate chat messages.

## Best Possible Solution

Define a default-off Telegram activity policy first; if accepted, implement bounded redacted activity messages with internal-turn exclusions, docs, tests, and live Telegram proof.
