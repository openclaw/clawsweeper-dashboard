- `impact:security`: The requested persistent activity stream would alter sensitive-data disclosure boundaries for reasoning, tools, memory, paths, URLs, credentials, and plugin diagnostics.
- `impact:ux-friction`: Telegram users currently lack a durable in-channel activity view comparable to the Web UI, which makes long-running or failing tasks harder to trust and debug.

## Summary

Keep open: current main has Telegram preview/progress drafts, a one-line collapse summary, durable verbose/reasoning paths, and Control UI Activity, but it still does not provide the requested first-class persistent per-step Telegram activity mode with Web UI parity.

## What This Changes

Request a Telegram mode or flag that renders each agent activity step as its own persistent visible message instead of only a final answer or editable preview.

## Best Possible Solution

Define a default-off Telegram activity policy first, then implement redacted persistent activity messages with NO_REPLY/internal-turn exclusions, volume limits, docs, tests, and live Telegram proof if maintainers accept the feature.
