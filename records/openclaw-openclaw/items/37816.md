- `P2`: This is a normal-priority feature improvement for Telegram transparency with limited blast radius, but it needs product/security design before implementation.
- `impact:security`: The requested persistent activity transcript could expose reasoning, tool details, command output, paths, memory activity, or secrets in Telegram.

## Summary

Keep open: current main and the latest release provide Telegram editable progress drafts, a collapse summary, and a browser-local Control UI Activity tab, but not the requested persistent per-step Telegram activity-message mode. The remaining work is a product and security decision because it would expose reasoning, tool progress, command/output details, and possibly memory activity in a durable chat transcript.

## What This Changes

Request a Telegram mode that mirrors Web UI agent activity by rendering each thinking/tool/memory step as a persistent separate Telegram message instead of only a transient preview or final answer.

## Best Possible Solution

Define an explicit opt-in Telegram activity visibility design with redaction, retention, group/DM safety, message-volume limits, and config/doctor/docs policy before implementing persistent activity messages in the Telegram channel.

Options:

- **Design redacted opt-in mode (recommended):** Add a maintainer-approved Telegram mode only after specifying safe defaults, redaction rules, allowed step types, retention semantics, and live Telegram proof requirements.
- **Keep current progress previews:** Close or defer this direction and keep Telegram on editable progress drafts plus the final answer, avoiding durable disclosure expansion.
- **Create shared observer API first:** Track a broader channel-safe observer stream/API before adding Telegram-specific persistent rendering, so Web UI, TUI, and Telegram do not drift.

## Reproduction Assessment

Yes for the missing capability: source and docs show Telegram supports only off/partial/block/progress preview modes, not a persistent per-step activity-message mode. I did not run a live Telegram session because this is a feature gap rather than a reported runtime failure.

## Solution Assessment

No current implementation is the full requested solution. The narrowest maintainable path is an explicit opt-in, redacted Telegram activity design rather than directly mirroring every Web UI activity event into durable Telegram messages.
