## Summary

Keep open: current main and v2026.6.11 provide Telegram preview/progress drafts, durable verbose/reasoning lanes, and a browser-local Control UI Activity tab, but not the requested opt-in Telegram mode that persists every activity step as separate durable messages. The remaining work is a product and security decision around durable Telegram disclosure, redaction, retention, and message volume.

## What This Changes

Request a Telegram mode that mirrors Web UI activity visibility by posting persistent per-step agent activity messages instead of only a final answer or transient progress preview.

## Best Possible Solution

Define a default-off Telegram activity visibility design with redaction, allowed activity types, retention semantics, group/DM safety, message-volume limits, docs, and live Telegram proof before implementing durable per-step messages.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Telegram gain a persistent per-step activity-message mode, and what disclosure, redaction, retention, and configuration policy should it use?

Rationale: Current code already has transient progress drafts and durable verbose/reasoning surfaces, but turning every activity step into persistent Telegram messages changes privacy, security, transcript retention, and public config behavior that automation should not choose.

Likely owner: vincentkoc

Owner reason: They have the strongest current-main ownership signal for Telegram progress, durable verbose behavior, and adjacent docs/code paths.

Owner confidence: high

Options:

- **Design a redacted opt-in mode (recommended):** Add a maintainer-approved default-off Telegram mode after specifying safe defaults, redaction rules, allowed step types, retention semantics, group/DM behavior, and live Telegram proof requirements.
- **Keep current preview and verbose surfaces:** Leave Telegram on progress drafts plus /verbose and /reasoning controls, and close or defer the durable per-step message direction.
- **Create shared observer API first:** Define a channel-safe observer/event API before adding Telegram-specific persistent rendering so Web UI, TUI, and Telegram activity views do not drift.

## Reproduction Assessment

Yes for the missing capability: source and docs show Telegram supports preview/progress modes plus /verbose and /reasoning controls, but not a persistent per-step activity-message mode. A live Telegram run was not needed because this is a feature gap rather than a runtime failure claim.

## Solution Assessment

No current implementation is the full requested solution. The maintainable path is an explicit opt-in, redacted Telegram activity design rather than directly mirroring every Web UI activity event into durable chat messages.
