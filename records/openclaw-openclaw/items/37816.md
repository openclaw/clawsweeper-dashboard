## Summary

Keep open: current main and v2026.6.11 cover Telegram preview/progress, verbose/reasoning controls, and browser-local Control UI Activity, but they do not implement the requested persistent per-step Telegram activity mode; the remaining work needs product and security policy before implementation.

## What This Changes

The issue requests a Telegram mode that mirrors Web UI agent activity visibility by sending persistent separate messages for thinking, tool calls, memory operations, and final answers.

## Best Possible Solution

Maintainers should choose an explicit default-off Telegram activity policy and, if accepted, implement redacted bounded activity messages with internal-turn exclusions, docs, tests, and live Telegram proof.
