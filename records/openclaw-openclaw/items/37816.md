## Summary

Keep open: current main and v2026.6.11 still provide Telegram preview/progress drafts, progress summaries, and browser-local Control UI Activity, but not the requested persistent per-step Telegram activity history. The remaining work is a product and security design decision, not a narrow cleanup close.

## What This Changes

Request a Telegram mode that renders persistent separate messages for agent activity steps, matching Control UI visibility more closely.

## Best Possible Solution

Design a default-off Telegram activity mode with explicit audience, redaction, retention, message-volume, NO_REPLY, reasoning/tool/memory scope, docs, tests, and live Telegram proof before implementation.

## Reproduction Assessment

Yes, at source level: current main exposes Telegram preview/progress drafts and browser-local Control UI Activity, but no persistent per-step Telegram activity-message mode. I did not run a live Telegram session because the missing mode is visible in the config types, docs, and dispatch code.

## Solution Assessment

No, not yet: the suggested config shapes are plausible, but maintainers should first choose the disclosure, redaction, retention, and message-volume policy for Telegram. A default-off design is safer than adding persistent activity messages as a simple streaming variant.
