## Summary

Keep open: current main and v2026.6.11 provide Telegram editable preview/progress behavior, durable verbose paths, and browser-local Control UI Activity, but not the requested persistent per-step Telegram activity-message mode. The remaining work changes Telegram disclosure, retention, message-volume, and public config policy, so it needs product and security direction.

## What This Changes

The issue requests a Telegram mode that renders each agent activity step as persistent separate messages, including tool calls, reasoning, and memory operations, instead of only final replies or editable previews.

## Best Possible Solution

Maintainers should define a default-off Telegram activity policy; if accepted, implement redacted bounded activity messages with internal-turn exclusions, docs, tests, and live Telegram proof.
