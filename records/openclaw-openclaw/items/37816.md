## Summary

Keep open: current main and v2026.6.11 have Telegram preview/progress modes, debug-oriented `/verbose` and `/reasoning` visibility, and browser-local Control UI Activity, but not the requested dedicated persistent per-step Telegram activity history with Web UI parity. The remaining work is a product and security design decision, not a narrow bug fix.

## What This Changes

Request a Telegram activity mode that persistently renders agent reasoning, tool/progress, memory/activity steps, and the final answer as separate visible messages.

## Best Possible Solution

Design a default-off Telegram activity mode or equivalent documented command/config path with explicit audience, redaction, retention, message-volume, NO_REPLY/internal-turn, and privacy rules before implementation.

## Reproduction Assessment

Yes, at source level: current main exposes Telegram `off | partial | block | progress` preview/progress modes and debug verbose/reasoning paths, but no dedicated persistent per-step Telegram activity-history mode. I did not run a live Telegram session because source and docs already establish the missing mode.

## Solution Assessment

No, not as a narrow automated fix. The suggested config shape is plausible, but maintainers should first choose the disclosure, redaction, retention, NO_REPLY, and message-volume policy for Telegram.
