## Summary

Keep open: current main still provides Telegram editable preview/progress drafts and a collapse summary, but not the requested persistent per-step activity-message mode. The remaining work is a product and security decision because it would durably expose reasoning, tool progress, command/output details, and possibly memory activity in Telegram chats.

## What This Changes

The issue requests a Telegram mode that renders each agent activity step as a persistent separate message, matching Web UI activity visibility more closely.

## Best Possible Solution

Define an explicit opt-in Telegram activity visibility design with redaction, retention, group/DM safety, message-volume limits, config/doctor/docs policy, and live Telegram proof before implementing persistent activity messages.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Telegram gain a persistent per-step activity-message mode, and what redaction, retention, group/DM, and configuration policy should it use?

Rationale: Current main intentionally provides transient editable previews and sanitized browser-local Activity summaries; making Telegram persist every activity step changes disclosure, retention, message volume, and public config behavior that automation cannot choose safely.

Likely owner: vincentkoc

Owner confidence: high

Options:

- **Design redacted opt-in mode (recommended):** Add a maintainer-approved Telegram mode only after specifying safe defaults, allowed step types, redaction rules, retention semantics, and live Telegram proof requirements.
- **Keep current previews:** Leave Telegram on editable progress drafts plus final answers and decline durable per-step activity messages for now.
- **Create shared observer API first:** Design a channel-safe observer stream/API before adding Telegram-specific persistent rendering so Web UI, TUI, and Telegram do not drift.

## Reproduction Assessment

Yes for the missing capability: current source and docs show Telegram supports off/partial/block/progress preview modes, but no persistent per-step activity-message mode or activityMessages option. I did not run a live Telegram session because this is a feature gap rather than a runtime failure.

## Solution Assessment

No current implementation is the full requested solution. The narrowest maintainable path is an explicit opt-in, redacted Telegram activity design rather than directly mirroring every Web UI activity event into durable Telegram messages.
