## Summary

Keep this PR open for a maintainer product decision. The patch and its documented real Linux proof support the reported ACP continuation flow, but it intentionally changes the one-shot lifecycle from terminal cleanup to retained resumable session state; that compatibility and session-state contract needs explicit sponsorship before merge.

## What This Changes

This PR retains verified ACP resume identity for completed parent-owned run-mode one-shots so a later `sessions_send` can reconnect to the original Codex or Claude backend conversation instead of creating a new one.

## System Context

ACP run-mode children are created by a parent agent, run one task, and persist ACP metadata while task maintenance normally removes terminal one-shot sessions. This change lets the parent route a later follow-up through the ACP manager to resume the verified backend transcript while still rejecting active, unsupported, or unsafe sessions.

## Architecture Diagram

flowchart LR
  Parent[Parent agent] --> Spawn[ACP run-mode child]
  Spawn --> Turn[Completed backend turn]
  Turn --> Identity[Stored ACP resume identity]
  Identity --> Gate{Idle, stable, supported, ready?}
  Gate -->|yes| Resume[Reconnect to owning backend]
  Gate -->|no| Reject[Reject unsafe follow-up]
  Resume --> Reply[Context-preserving reply]

## Best Possible Solution

Explicitly adopt or reject completed run-mode one-shot continuation as a supported ACP contract; if adopted, land this with a clear retention, invalidation, and operator-facing failure policy for resumable metadata, while keeping explicit close/reset flows authoritative.
