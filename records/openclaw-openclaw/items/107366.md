## Summary

This PR remains necessary because current main closes terminal one-shot ACP metadata and does not pass persisted resume identities when re-ensuring one-shots. The proposed capability/readiness gates, backend pinning, explicit active-turn rejection, regression coverage, green exact-head checks, and dual-provider live proof form a coherent fix with no concrete correctness defect found; it should continue through normal ACP owner review and merge gates.

## What This Changes

The branch preserves confirmed resumable ACP run-mode session metadata and routes later parent follow-ups back into the original backend conversation while rejecting active, unsupported, unready, or invalid resume cases.

## Best Possible Solution

Land the capability-gated, resume-ready design after ACP ownership confirms the retention boundary and ACP protocol ID preference, while keeping fail-closed missing-target behavior, backend pinning, active-turn rejection, and eventual session-store cleanup intact.
