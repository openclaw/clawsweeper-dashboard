Overall correctness: patch is incorrect

Full review comments:

- **[P1] Buffer JSON tool-call text before promotion:** `packages/tool-call-repair/src/payload.ts:549`
  - body: The new parser lets final `done` messages promote JSON objects, but the streaming normalizer still marks JSON-starting text as impossible because its buffer state only checks bracket, XML-ish, and Harmony prefixes. A provider that streams `{"name":"read","arguments":...}` will emit that JSON as visible text before the final message is promoted, unlike the existing serialized tool-call path that suppresses raw tool text.
  - confidence: 0.91
- **[P2] Promote every JSON tool_calls entry:** `packages/tool-call-repair/src/payload.ts:427`
  - body: The OpenAI-style wrapper path reads only `toolCalls[0]`, so a JSON wrapper containing multiple tool calls silently drops every later call. Since this parser returns an array of blocks and existing formats can promote multiple calls, the JSON wrapper should either produce one block per valid entry or reject the wrapper instead of executing only the first.
  - confidence: 0.89
