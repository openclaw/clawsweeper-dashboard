## Summary

This PR is still necessary because current main does not parse standalone JSON tool calls, but the proposed stream heuristic is not merge-ready: a valid call split before or inside its identifying JSON key leaks its initial prefix as visible text before terminal promotion. The shared package is the right implementation boundary, and the previously reported duplicate-append concern is addressed on the current head, but arbitrary chunking and exact affected-provider behavior still need proof.

## What This Changes

The PR extends shared plain-text tool-call repair to parse and promote standalone JSON calls and multi-call wrappers, buffer streamed JSON candidates, and add parser, normalizer, and plugin-SDK regression tests.

## Best Possible Solution

Buffer a bounded line-start JSON object from its opening brace until its shape can be conclusively accepted or rejected, replay false positives byte-for-byte, and cover splits before and inside every recognized key at both package and provider-wrapper levels before proving the Ollama path live.
