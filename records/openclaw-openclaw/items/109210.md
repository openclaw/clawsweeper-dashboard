## Summary

This is a valid, well-proven Vydra hang fix, but the deadline is applied only after the HTTP-success check, leaving non-2xx response bodies able to drip indefinitely before the bounded reader is reached.

## What This Changes

This PR adds a single wall-clock deadline across Vydra generated-asset header and successful-body reads and adds loopback regression coverage for a continuously dripping response.

## Best Possible Solution

Keep the provider-owned call-site deadline, but make the same remaining budget cover both non-2xx error-detail consumption and successful asset-body consumption, with regression cases for each response class.
