## Summary

Keep open: current main still lets an empty-detail OpenAI-compatible `response.failed` become `no_error_details` and then flow into shared auth-profile failure/cooldown state, so the Azure Foundry cooldown and fallback cascade is not solved by the older diagnostics or timeout-scoping fixes.

## What This Changes

The issue requests that Azure Foundry empty-detail `response.failed` events be treated as transient upstream failures without cooling down valid auth profiles or showing auth-login recovery copy.

## Best Possible Solution

Treat `no_error_details` like a transient provider/runtime failure for auth-health purposes: keep the diagnostic classification and retry/fallback behavior, but do not quarantine the shared auth profile or block sibling fallback models without affirmative auth evidence.
