## What This Changes

The branch removes the reversed-bound swap from `sliceUtf16Safe`, returns `""` when the normalized end is not after the start, and updates the colocated UTF-16 helper test expectation.

## Best Possible Solution

Adopt native `String.prototype.slice` ordering semantics for `sliceUtf16Safe` and keep that behavior covered by the helper test after maintainer sign-off on the SDK compatibility risk.

## Reproduction Assessment

Yes. Current main source swaps `to` and `from` when `to < from`, the current test expects the swapped substring, and the linked issue includes current-main runtime proof for the same reversed-bounds case.

## Solution Assessment

Yes, with maintainer compatibility sign-off. Returning before surrogate-boundary adjustment when `to <= from` is the narrowest fix that matches native slice ordering while preserving forward and tail slice behavior.
