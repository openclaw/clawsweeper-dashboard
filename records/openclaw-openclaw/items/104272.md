## Summary

The PR identifies a real Perplexity cancellation bug and uses the correct provider boundary, but it is not merge-ready: implicit provider selection can treat the new abort rejection as an ordinary failure and launch another provider, while the added test passes even when no signal is forwarded. The unrelated CI failure does not change that source-backed verdict.

## What This Changes

The branch forwards the web-search execution `AbortSignal` through Perplexity’s native Search API and Sonar chat-completions HTTP paths and adds a mocked-fetch regression test.

## Best Possible Solution

Keep the provider-local Perplexity signal plumbing, make an aborted parent signal terminal in the shared web-search fallback loop, replace the false-positive test with an exact signal assertion, and add redacted loopback or live proof that the held request closes without another provider starting.
