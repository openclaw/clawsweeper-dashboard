## Summary

Keep open. Current main and the latest stable release still split LINE text-plus-table replies so extracted Flex tables are pushed after the Reply API text, while https://github.com/openclaw/openclaw/pull/81299 is the open focused fix candidate rather than a merged implementation.

## What This Changes

The issue asks OpenClaw's LINE plugin to deliver text plus Markdown-derived table Flex messages through the same quota-free Reply API batch when reply slots remain instead of sending the table separately through Push API.

## Best Possible Solution

Review and land or explicitly reject https://github.com/openclaw/openclaw/pull/81299, or land an equivalent focused LINE batching fix, then close this issue once the fix reaches main.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level: current main extracts Markdown tables into Flex messages, sends text through sendLineReplyChunks, and then sends rich content through the Push path with allowReplyToken=false. I did not perform a live exhausted-quota LINE account reproduction.

## Solution Assessment

Yes, the narrow maintainable solution is to batch eligible rich/media messages into the same Reply API call before the reply token is consumed, then push only overflow. The open linked pull request owns that direction, so a new fix lane should not start while it remains viable.
