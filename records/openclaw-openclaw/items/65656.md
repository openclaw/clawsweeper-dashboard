## Summary

Keep open. Current main and v2026.6.11 still send the reporter's LINE text-plus-table path as text through Reply API followed by extracted Flex content through Push API, and the focused closing PR is open but unmerged.

## What This Changes

The issue reports LINE table Flex messages being routed through quota-bound Push API after text consumes the Reply API path, causing silent table loss on free plans with exhausted push quota.

## Best Possible Solution

Review and land or explicitly reject https://github.com/openclaw/openclaw/pull/81299 or an equivalent focused batching fix, then close this issue once the fix reaches main.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level: current main extracts Markdown tables into Flex messages, sends text through sendLineReplyChunks, then sends rich/media with allowReplyToken=false. I did not establish a live exhausted-quota LINE account reproduction in this read-only review.

## Solution Assessment

Yes. The narrow maintainable solution is to batch eligible rich/media messages into the same Reply API call before the reply token is consumed, then push only overflow; the open focused PR owns that direction.
