## What This Changes

Bundle LINE text and table Flex messages into the same Reply API batch when capacity permits, pushing only overflow so quota exhaustion cannot silently drop the table.

## Best Possible Solution

Refresh and review https://github.com/openclaw/openclaw/pull/109011 against current main, preserve its single reply-token batch with push-only overflow and failure safeguards, rerun focused LINE delivery tests, accept the supplied live LINE proof, and close this issue only after merge.

## Reproduction Assessment

Yes, at high confidence from source and live evidence: send a LINE reply containing text plus a Markdown table after exhausting push quota, and the text uses Reply API while the extracted table uses Push API and fails with 429. This read-only review did not independently consume a live account's quota.

## Solution Assessment

Yes. Building one ordered text/rich/media batch before reply-token consumption, using up to five Reply API slots, and pushing only overflow is narrower and safer than retrying quota failures or merely changing the later `allowReplyToken` argument.
