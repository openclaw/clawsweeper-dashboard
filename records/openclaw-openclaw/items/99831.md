## What This Changes

The issue requests a Slack `requestUsers` allowlist so all admitted room senders can remain observable while only approved senders can create actionable agent requests.

## Best Possible Solution

Add a Slack-plugin-owned, restrictive-only `requestUsers` config that preserves omitted behavior and consistently gates actionability after normal room admission without granting access beyond existing sender policies.

Yes, source-level: current main has no `requestUsers` field, Slack channel config resolves only `users`, and the inbound classifier keeps mentions, control text, aborts, and native commands as `user_request` under ambient mode. I did not run a live Slack workspace.

The implementation should not move Slack-specific policy into core or grant access beyond existing admission gates.
