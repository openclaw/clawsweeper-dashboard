## Summary

Keep open: current main does not provide the requested Slack `requestUsers` boundary, and the issue has the protected `maintainer` label, so cleanup auto-close is not allowed.

## What This Changes

The issue requests a Slack per-channel `requestUsers` allowlist so ambient senders can remain observable while only selected users can create actionable agent requests.

## Best Possible Solution

Add a Slack-plugin-owned `requestUsers` config that preserves omitted behavior, matches stable Slack user IDs, restricts only actionability, and is enforced consistently for message mentions, control/abort text, slash commands, and interactions.

## Reproduction Assessment

Yes, at source level: current main has no `requestUsers` field, `users` remains the only per-channel sender gate, and explicit Slack mentions/control/abort/native commands are still promoted to `user_request`. I did not run a live Slack workspace.

## Solution Assessment

Unclear until maintainers confirm the new config surface, but the proposed restrictive per-channel `requestUsers` boundary is the right shaped end state if it stays Slack-plugin-owned and preserves omitted behavior.
