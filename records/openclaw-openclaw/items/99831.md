## Summary

Keep open: current main still lacks a separate Slack request-only sender boundary, the issue has the protected `maintainer` label, and the nearest open Slack mention/config work does not implement these allowlist semantics.

## What This Changes

The issue requests a Slack `requestUsers` channel config that keeps admitted senders observable as ambient context while limiting who can create actionable Slack agent requests.

## Best Possible Solution

Add a Slack-plugin-owned `requestUsers` config that preserves omitted behavior, uses ID-first matching, gates only actionability, and applies consistently to messages, native slash commands, and interactions without widening existing admission access.

## Reproduction Assessment

Yes, source-level: current main and `v2026.6.11` have no `requestUsers` field, Slack resolves only `users`, and the ambient classifier promotes mentions, commands, and aborts to `user_request`. I did not run a live Slack workspace.

## Solution Assessment

Unclear until maintainer approval, but the proposed shape appears maintainable if it stays Slack-plugin-owned, restrictive-only, and omitted-compatible across all Slack ingress surfaces.
