## Label Justifications

- `P1`: A valid spawned workflow can silently terminate without its requested deliverable and cause the parent to duplicate work.
- `impact:message-loss`: The intended child deliverable is suppressed and replaced by an empty or progress-only completion.
- `impact:session-state`: A yield-ended child can be treated as terminal despite having no state transition capable of resuming it.

## Summary

Current `main` still accepts and immediately aborts for `sessions_yield` without verifying that the subagent has active child work or another continuation source; current documentation narrows the intended use but does not prevent the silent empty completion reported here.

## What This Changes

Guard or explicitly diagnose a spawned subagent calling `sessions_yield` without active child work or another continuation source, and clarify the model-facing waiting contract.

## Best Possible Solution

Enforce a shared safe-yield invariant at the runtime/lifecycle boundary: reject the tool call with corrective model guidance when no tracked continuation exists, preserve legitimate spawn-then-yield behavior, and cover ordinary spawned runs, required-completion runs, and direct sessions with focused tests.
