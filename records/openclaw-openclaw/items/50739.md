## Summary

Keep open: current main still has no priority or bypass contract for `openclaw system event`, and source/tests show immediate wakes can still skip with `requests-in-flight` when the target session lane is busy.

## What This Changes

Issue requests a high-priority or bypass-queue mode for system events so critical in-session alerts are not delayed behind congested session work.

## Best Possible Solution

Define one intentional urgent-alert contract first, then implement either a typed priority wake with safety gates or a canonical UI/control-plane notification path separate from prompt-stream injection.

- **Keep best-effort semantics:** Document that prompt-visible system events can be delayed under saturated lanes and rely on external channels or pre-failure triggers for outage alerts.
