## Summary

Keep open: current main and the latest release still route `system event --mode now` through queued system-event text plus heartbeat wake delivery, with no priority or bypass contract for urgent in-session alerts.

## What This Changes

The issue asks for a high-priority or bypass-queue mode for `openclaw system event --mode now` so urgent in-session alerts do not wait behind congested LLM work.

## Best Possible Solution

Define a typed urgent-alert contract that gives the operator/TUI an immediate visible alert and only mutates prompt-visible session state through a separately authorized, ordered, sanitized path.

## Solution Assessment

No, not as a bare bypass flag. The maintainable solution should separate immediate operator alerting from prompt-visible transcript mutation, or explicitly define both trust and ordering contracts.
