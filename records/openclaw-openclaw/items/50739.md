## Summary

Keep open. Current main still has no priority or bypass contract for `openclaw system event --mode now`; the command routes through the normal `wake` RPC, enqueues a regular system event, and heartbeat delivery still skips/retries when the target session lane is busy. Related UI notification work may solve the operator-visible alert half, but it does not settle prompt-visible session injection, ordering, or trust boundaries.

## What This Changes

Request a high-priority or bypass-queue mode for `openclaw system event --mode now` so degraded-system alerts can appear immediately instead of waiting behind congested session work.

## Best Possible Solution

Define one explicit urgent-alert contract: immediate operator-visible delivery for incident notifications, with prompt-visible transcript/prompt injection added only through a separately ordered and trust-reviewed session path.

## Reproduction Assessment

Yes from source inspection. Current main has no priority/bypass CLI or wake contract, `mode=now` enqueues then wakes heartbeat, and heartbeat skips busy session lanes with retryable `requests-in-flight`.

## Solution Assessment

No, not as a standalone flag yet. The maintainable path is to decide whether OpenClaw needs immediate operator-visible notification, prompt-visible transcript injection, or both before adding a typed CLI/protocol surface.
