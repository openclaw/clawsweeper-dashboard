## Summary

Keep open. Current main and v2026.6.11 still expose only queued system-event plus heartbeat wake delivery, with no priority or queue-bypass contract; the issue remains source-reproducible but needs maintainer product/security direction before implementation.

## What This Changes

The issue requests a high-priority or queue-bypass mode for `openclaw system event --mode now` so provider-incident alerts can appear in-session without waiting behind congested LLM work.

## Best Possible Solution

Define an explicit urgent-alert contract that gives operators immediate visible incident notifications, while any prompt/transcript mutation uses a separately ordered, authorized, rate-limited, and tested trusted path.

## Reproduction Assessment

Yes. Source inspection shows current main has no priority or bypass CLI/protocol field, and `mode: now` still enqueues a system event then wakes heartbeat; I did not run a live provider-outage congestion reproduction.

## Solution Assessment

No, not as a standalone flag yet. A queue-bypass flag is plausible, but the maintainable fix should first separate operator-visible urgent alerts from prompt-visible trusted session mutation and define ordering/security semantics.
