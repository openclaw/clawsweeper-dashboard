## Summary

Keep open: current main has no priority or bypass path for `openclaw system event`, and urgent wake delivery still retries later when the main or target session lane is busy.

## What This Changes

The issue requests a priority or bypass-queue mode for `openclaw system event` so urgent in-session alerts surface immediately despite congested session lanes.

## Best Possible Solution

Define one explicit high-priority alert contract first: default system events stay ordered/retry-based, while any bypass or notification path has scoped auth, rate guards, ordering semantics, tests, and TUI/Gateway proof.
