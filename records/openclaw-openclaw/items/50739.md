## Summary

Keep open. Current main and v2026.6.11 still route `openclaw system event --mode now` through the queued system-event plus heartbeat path, and the remaining work is a core urgent-alert/product-security contract rather than stale or external-only cleanup.

## What This Changes

Request a high-priority or bypass-queue mode for `openclaw system event` so incident alerts can appear in the active session without waiting behind congested LLM lanes.

## Best Possible Solution

Define one explicit high-priority system alert contract: immediate operator-visible delivery for incident notifications, with prompt-visible transcript injection only through a separately ordered, authorized, and sanitized session path.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 expose no priority/bypass CLI or wake contract, `mode: now` enqueues then wakes heartbeat, and heartbeat skips busy session lanes; I did not run a live provider-outage reproduction in this read-only review.

## Solution Assessment

No, not as a standalone `--bypass-queue` flag yet. The maintainable solution is to decide whether OpenClaw needs immediate operator-visible alerting, prompt-visible transcript injection, or both, then encode that as a typed gateway/CLI contract with security review.
