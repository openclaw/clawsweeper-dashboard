## Label Justifications

- `P2`: The issue reports a real alert reliability gap during degraded provider/session conditions, but it is a bounded core workflow design item rather than a current emergency outage.
- `impact:message-loss`: The delayed system event can arrive so late that the operator effectively misses the actionable alert window.
- `impact:session-state`: The requested bypass changes how urgent events relate to active session lanes, transcript ordering, and prompt-visible session state.
- `impact:security`: System events render as trusted `System:` prompt lines, so a bypass needs explicit authorization, spoofing, and ordering review.
- `maturity:stable`: `gateway-runtime` is M4 Stable and the Stable `Gateway RPC APIs and Events` category explicitly covers `system-event` and heartbeat RPCs.

## Summary

Keep open. Current main and v2026.6.11 still route `openclaw system event --mode now` through queued system-event plus heartbeat delivery, and heartbeat still skips busy session lanes; related snapshot, quota-pretrigger, and wake-routing context are useful but do not provide the requested immediate in-session alert contract.

## What This Changes

Request a high-priority or bypass-queue mode for `openclaw system event --mode now` so urgent in-session alerts are not delayed behind congested LLM session lanes.

## Best Possible Solution

Define a first-class urgent alert contract that can surface an operator-visible TUI/session notification immediately while keeping prompt-visible transcript injection ordered, authorized, and tested for busy-lane outages.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: current main enqueues the event, requests heartbeat, and heartbeat skips when the target session lane is busy. I did not run a live provider-outage reproduction.

## Solution Assessment

No, the raw `--priority high` or `--bypass-queue` flag is only a plausible mechanism, not yet the best complete fix. Maintainers should first choose whether the immediate path is UI-only alerting, prompt-visible injection, or a priority lane with explicit trust and ordering rules.
