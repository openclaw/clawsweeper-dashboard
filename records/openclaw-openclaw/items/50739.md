## Summary

Keep open. Current main and v2026.6.11 still route `system event --mode now` through queued system events plus heartbeat wake delivery, with no priority or bypass contract; the remaining decision is product and security design, not conservative cleanup.

## What This Changes

Requests a high-priority or bypass mode for `openclaw system event --mode now` so urgent alerts can surface in-session without waiting behind busy LLM lanes.

## Best Possible Solution

Define a trusted urgent-alert contract that separates immediate operator-visible notification from ordered prompt/transcript injection, then add CLI/protocol/runtime/TUI support with focused regression and security tests.

- **Add a prompt-visible bypass contract:** Permit trusted callers to inject directly into prompt-visible session state, but require explicit authorization, ordering, sanitization, and regression tests before implementation.
- **Keep existing best-effort semantics:** Document that `--mode now` is wake-only and rely on out-of-band channels such as Telegram for real-time outage alerts.

## Reproduction Assessment

Yes, source-level: current main has no priority or bypass field, `mode: now` enqueues a system event before requesting heartbeat delivery, and heartbeat can skip busy sessions with `requests-in-flight`. I did not run a live provider-outage replay in this read-only review.

## Solution Assessment

No, a bare `--priority high` or `--bypass-queue` flag is not yet the best fix. Maintainers should first decide whether urgent alerts are UI-only notifications, prompt-visible transcript mutations, or both with separate ordering rules.
