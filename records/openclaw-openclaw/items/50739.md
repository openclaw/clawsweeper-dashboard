## Summary

Keep open. Current main and v2026.6.11 support session-targeted system-event wakes, but they still have no priority or queue-bypass contract; `--mode now` enqueues a prompt-visible system event and requests heartbeat delivery, which can still defer behind busy lanes.

## What This Changes

Request a high-priority or bypass-queue mode for `openclaw system event --mode now` so critical alerts appear during congested in-session work.

## Best Possible Solution

Define a trusted urgent-alert contract that separates immediate operator-visible notification from ordered prompt/transcript injection, then add CLI/protocol/runtime/TUI support with focused regression and security tests.

## Reproduction Assessment

Yes, source-reproducible: current main has no priority or bypass field, and `mode: now` still enqueues a system event before requesting heartbeat delivery. I did not run a live provider-outage reproduction in this read-only review.

## Solution Assessment

No, a bare bypass flag is not yet the best fix. Maintainers should first choose the boundary between immediate operator-visible notification and prompt-visible transcript mutation, then encode that as a typed contract.
