## Summary

Keep this PR open for maintainer review: the duplicate-side-effect problem is credible and the supplied runtime probe is meaningful, but coalescing calls that Codex identifies with different `callId` values changes a protocol-facing execution boundary without a confirmed contract that those calls are retries rather than distinct operations.

## What This Changes

The PR adds a per-attempt in-flight coalescer for same-thread, same-turn Codex dynamic-tool calls with equal namespace, tool, and canonicalized arguments, and uses it in normal and side-question app-server flows.

## Best Possible Solution

Define or obtain confirmation of a Codex retry/duplicate identity contract, then coalesce only calls that meet that contract while preserving per-request diagnostics and terminal accounting for every distinct `callId`.
