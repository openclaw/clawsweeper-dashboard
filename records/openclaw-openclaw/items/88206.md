## Summary

Keep this PR open, but it needs a protocol-boundary correction before merge: the proposed key deliberately collapses requests with different Codex `callId` values, while the upstream app-server treats each `callId` as a distinct dynamic-tool operation and requires a response for that exact id. The supplied probe proves coalescing works, not that different ids are retry deliveries rather than intentional same-turn calls.

## What This Changes

The branch adds an in-memory coalescer for equivalent, concurrent Codex dynamic-tool calls and wires it into normal app-server attempts and `/btw` side questions with regression coverage.

## Best Possible Solution

Preserve `callId` as the execution identity unless upstream exposes a verified retry/replay identity; then deduplicate only within that explicit contract and add an integration regression proving the real duplicate-delivery path.
