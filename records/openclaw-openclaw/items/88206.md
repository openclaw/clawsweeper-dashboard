## Summary

This PR has credible runtime proof for a real duplicate-side-effect concern, but it still changes the operation contract for distinct Codex `callId`s without evidence that equal payloads are retries rather than independent tool operations. Keep it open for a maintainer decision; the prior P1 blocker remains unresolved.

## What This Changes

The branch coalesces same-thread, same-turn Codex dynamic-tool calls with equivalent namespace, tool, and canonicalized arguments while the first execution is in flight.

## Best Possible Solution

Preserve independent execution for distinct Codex `callId`s unless maintainers confirm a retry/idempotency contract; if that contract exists, encode it at the Codex request boundary with explicit per-request correlation and regression coverage for both duplicate delivery and intentional repeated calls.
