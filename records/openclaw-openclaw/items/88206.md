## Summary

Keep this PR open for maintainer review: it targets a plausible duplicate-side-effect path and includes real runtime proof, but it still deliberately treats distinct Codex `callId` operations as one OpenClaw execution without an established upstream idempotency/deduplication contract.

## What This Changes

The branch coalesces same-thread, same-turn Codex dynamic-tool requests with matching namespace, tool, and canonicalized arguments while their first execution remains in flight.

## Best Possible Solution

Preserve per-`callId` execution unless Codex explicitly guarantees that separately identified same-turn matching requests are duplicate delivery; if that guarantee exists, encode it at the protocol boundary with a narrow contract and tests for both distinct operations and retry duplicates.
