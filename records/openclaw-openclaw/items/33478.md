## Summary

Keep open: current main partially addresses thread-aware announce routing, but the central structured skip/no-reply contract is still missing and the remaining API shape needs maintainer product direction.

## What This Changes

The issue requests structured `sessions_send` callback actions plus inherited channel/thread context for automatic agent handoff announces.

## Best Possible Solution

Keep this open for a maintainer-approved handoff contract, then implement structured skip/no-reply actions with focused tests for exact-token compatibility, conversational-token failure avoidance, and inherited channel/thread delivery.

## Reproduction Assessment

Yes at source level: current `sessions_send` has no structured action parameter, and skip suppression still depends on exact sentinel text. I did not run a live multi-agent Telegram replay in this read-only review.

## Solution Assessment

Unclear until maintainers choose the permanent handoff API shape; a structured action/result contract is more maintainable than prompt-only sentinel text, but it overlaps broader `announceTarget` and dispatch-mode proposals.
