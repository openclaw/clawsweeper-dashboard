## Summary

Keep open: current main and the latest release still expose only text-driven `sessions_send` handoff controls, so the central structured skip/no-reply and explicit announce routing request remains unresolved. The narrower threadId fallback symptom has been fixed, but it does not replace the requested model-facing handoff contract.

## What This Changes

Request structured `sessions_send` callback actions plus announce routing/thread context inheritance so A2A handoffs do not depend on exact model text or lose target context.

## Best Possible Solution

Define one backward-compatible A2A handoff contract that carries structured control intent and routing context, then land focused sessions_send, announce, docs, and regression coverage against that contract.

## Reproduction Assessment

Yes, at source level: current main lacks structured `sessions_send` action/routing parameters and still relies on exact sentinel text. I did not run a live Telegram handoff because the missing public tool surface is directly visible in source, docs, and the latest release tag.

## Solution Assessment

Unclear as a final API shape. A structured handoff contract is the maintainable direction, but maintainers should settle how it relates to announceTarget, dispatch-only mode, private delivery, and handoff acknowledgements before implementation.
