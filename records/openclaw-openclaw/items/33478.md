## Summary

Keep open. Current main and the latest release have partial thread-route fixes for the A2A announce path, but the central requested structured `sessions_send` skip/no-reply action and explicit announce routing overrides are still missing, and a maintainer-side comment already framed this as concrete handoff reliability acceptance criteria.

## What This Changes

Request to replace fragile sentinel-string A2A handoff control with structured `sessions_send` actions and preserve or override channel/thread context for announce delivery.

## Best Possible Solution

Keep this as a maintainer-sponsored minimal A2A handoff contract: structured skip/no-reply outcomes, preserved channel/thread context, explicit routing override semantics if accepted, and backward-compatible default behavior.

## Reproduction Assessment

Yes by source inspection. Current main and v2026.6.11 lack a structured `sessions_send` action parameter and still rely on token-only `REPLY_SKIP`/`ANNOUNCE_SKIP` checks; I did not run a live Telegram workflow in this read-only review.

## Solution Assessment

Unclear as a final API choice. A structured action is a plausible cleaner solution than magic strings, but maintainers should settle the public `sessions_send`/A2A contract alongside the related announce-target and dispatch-mode issues.
