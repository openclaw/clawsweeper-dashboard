## Summary

Close: current main and the shipped v2026.6.11 release route every non-test Codex context projection call through a budget-derived cap, so the reported 24,000-character fallback path is no longer reachable.

## What This Changes

The issue requests that no-context-engine Codex continuity projections pass `maxRenderedContextChars` derived from `contextTokenBudget` instead of silently using the 24,000-character default.

## Best Possible Solution

Keep the merged shared projection-cap implementation from https://github.com/openclaw/openclaw/pull/94093 and treat any remaining native-thread churn as separate work, such as https://github.com/openclaw/openclaw/issues/84086.
