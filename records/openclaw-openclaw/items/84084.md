## Summary

Current main and the shipped v2026.6.11 release already route the relevant Codex continuity projections through a budget-derived rendered-context cap, so the reported 24,000-character fallback gap is resolved.

## What This Changes

The issue requests that Codex no-context-engine continuity projections honor `contextTokenBudget` by passing a budget-derived `maxRenderedContextChars` instead of falling back to 24,000 rendered characters.

## Best Possible Solution

Keep the shipped v2026.6.11 continuity projection implementation and handle any future native-thread churn as a separate report from projection-budget parity.

## Solution Assessment

Yes: the shipped fix uses the existing budget/reserve calculation for the no-context-engine continuity paths and keeps the separate native-thread churn concern out of scope. That is narrower than adding new config or changing context-engine ownership.
