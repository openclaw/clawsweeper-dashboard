## Summary

Close as implemented: current main and v2026.6.11 route Codex no-context-engine continuity projection through a budget-scaled `maxRenderedContextChars`, so the reported 24,000-character fallback cap no longer applies to the fresh-thread or stale-binding paths.

## What This Changes

The issue asks for Codex legacy mirrored-history continuity projection to derive `maxRenderedContextChars` from `contextTokenBudget` instead of falling back to the 24,000-character default.

## Best Possible Solution

Keep the shipped budget-scaled continuity projection from v2026.6.11 and track any remaining native thread churn separately from this projection-cap bug.
