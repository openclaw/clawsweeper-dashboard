## Summary

Close as implemented: current main and the shipped v2026.6.11 tag both route the Codex continuity projection call sites through a shared context-budget-derived rendered-context cap, so the reported 24k-character legacy fallback gap is gone.

## What This Changes

The issue reports that Codex no-active-context-engine mirrored-history continuity projections used the 24k-character default instead of a cap derived from `contextTokenBudget`.

## Best Possible Solution
