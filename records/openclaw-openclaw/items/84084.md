## Summary

Close: current main and the shipped v2026.6.11 release already fix the reported Codex legacy/no-context-engine projection cap via https://github.com/openclaw/openclaw/pull/94093, which routes the fresh, active, and stale projection paths through a budget-scaled cap.

## What This Changes

The issue requests that Codex legacy mirrored-history continuity projection use a `contextTokenBudget`-derived `maxRenderedContextChars` instead of falling back to the 24,000-character default.

## Best Possible Solution

Keep the shipped behavior from https://github.com/openclaw/openclaw/pull/94093: one budget-scaled Codex projection cap per attempt, passed to every continuity projection path and then bounded against Codex's turn/start text limit.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level for the reported v2026.5.18 path: the old no-context-engine projection call omitted `maxRenderedContextChars`, which selected the 24,000-character default. Current main no longer reproduces that failing path because the fresh and stale continuity projections now pass the budget-scaled cap.

## Solution Assessment

Yes, the landed fix is the best maintainable shape: it reuses the existing budget resolver across fresh, active, and stale projection paths without adding config or a parallel runtime path, and it also fits the final Codex turn/start input against the upstream cap.
