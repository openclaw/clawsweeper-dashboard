## Summary

Keep open for a focused Codex-integration investigation. Current main deliberately configures Codex to launch `openclaw hooks relay` subprocesses and bounds their normal command lifetime, but this review could not establish that a gateway SIGKILL or cgroup OOM also terminates the whole Codex helper tree; the reported abnormal-termination path therefore remains materially unverified. Likely related people: joshavant (high confidence) and evgyur (medium confidence) from the recent native-hook lifecycle work.

## What This Changes

The issue requests reliable cleanup of Codex native-hook relay helper processes when a gateway run terminates abnormally, preventing orphaned processes and Docker memory-pressure restart loops.

## Best Possible Solution

Reproduce on v2026.7.1 or current main with a process-tree capture before and after gateway SIGKILL/cgroup OOM, then fix cleanup at the actual owner boundary—OpenClaw only if it owns the surviving child tree, otherwise in the Codex runtime that spawns it—and add regression coverage for normal abort plus forced parent death where feasible.
