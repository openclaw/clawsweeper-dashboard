## What This Changes

Preserve a session’s recorded dashboard availability while its first Gateway board snapshot is pending or fails, while still clearing availability after an authoritative loaded-empty snapshot.

## System Context

Session dashboards are the persistent board face of an existing Gateway session. The Control UI requests board metadata with `board.get`, then decides whether sidebar navigation should expose the session’s dashboard face.

## Architecture Diagram

flowchart LR
  A[Recorded session availability] --> B[Control UI opens session]
  B --> C[Gateway board snapshot request]
  C --> D{Authoritative snapshot loaded?}
  D -->|No: pending or failed| E[Keep recorded availability]
  D -->|Yes: empty| F[Hide dashboard navigation]
  D -->|Yes: board exists| G[Show dashboard navigation]

## Best Possible Solution

Update the Control UI availability state so recorded availability survives only an unresolved initial board fetch, then add focused coverage for pending, failed, board-present, and authoritative loaded-empty outcomes.
