## Summary

This PR should remain open, but it is not ready to merge. Its transport-only filter bypasses the authored-override signal that protects runtime selection, while the linked report explicitly selects the OpenClaw runtime; the contributor’s inline helper results do not prove the resulting real Codex/OpenClaw request path.

## What This Changes

The branch changes embedded-run startup so a `transport`-only model policy does not count as a stream override, and adds unit tests for transport-only and mixed parameter cases.

## System Context

OpenClaw resolves a model policy into an agent-runtime choice and provider request settings before a turn begins. The stream-override marker is one of the facts used to decide whether the embedded runtime or the Codex app-server can faithfully execute that configured request.

## Architecture Diagram

  Params --> Override[Authored override detection]
  Override --> Select[Agent runtime selection]
  Select --> Embedded[OpenClaw embedded runtime]
  Select --> Codex[Codex app-server runtime]
  Embedded --> Request[Provider request]
  Codex --> Request

## Best Possible Solution

Keep explicit runtime selection authoritative, then implement transport support at the owning runtime boundary or pass a separately typed, contract-tested transport capability to Codex without erasing the authored-override signal.
