## Label Justifications

- `P1`: Feishu users can be unable to stop, reset, or inspect an active agent run through text commands during a live channel workflow.
- `impact:session-state`: The affected commands operate on active session state, including stop, reset/new-session, and status behavior during an existing run.

## Summary

Keep open: current main and latest release still only give Feishu abort text a dedicated lane; `/status` and `/new` remain on the ordinary same-chat queue, and Feishu text slash messages still are not built as structured text-command turns. The related open PR at https://github.com/openclaw/openclaw/pull/92962 is adjacent ordinary-followup queue work, not a fix for this text-command bypass regression.

## What This Changes

The issue reports that Feishu text commands such as `/stop`, `/new`, and `/status` stopped bypassing the active-run queue after OpenClaw 2026.3.8.

## Best Possible Solution

Maintainers should choose the Feishu text-command contract, then implement a Feishu-scoped fix that marks authorized whole-message slash commands as structured turns where appropriate and routes only explicitly immediate controls out of the normal same-chat lane.
