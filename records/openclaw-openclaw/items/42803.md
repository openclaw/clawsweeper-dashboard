## Label Justifications

- `P1`: Feishu users can be unable to stop, reset, or inspect an active agent run through text commands during a live channel workflow.
- `impact:session-state`: The affected commands operate on active session state, including stop, reset/new-session, and status behavior during an existing run.
- `impact:message-loss`: Command-only Feishu messages can be delayed until they no longer affect the active run or produce no useful visible command result.

## Summary

Keep open: current main still only partially addresses the Feishu active-run text-command regression. `/stop` now has a dedicated Feishu control lane, but `/status` and `/new` still resolve to the ordinary same-chat queue, and Feishu inbound context does not mark text slash messages as structured command turns.

## What This Changes

The issue requests restoring Feishu text command fast-path behavior so `/stop`, `/new`, and `/status` execute immediately during an active agent run instead of waiting behind the current run.

## Best Possible Solution

Choose a Feishu-scoped text-command contract, mark authorized whole-message slash commands as structured command turns where appropriate, route only explicit immediate controls out of the normal same-chat lane, and cover `/stop`, `/status`, and any approved `/new` behavior with focused Feishu tests plus live proof.
