## Label Justifications

- `P1`: Feishu users cannot reliably stop, reset, or inspect active agent runs through text commands during an in-flight channel workflow.
- `impact:session-state`: The affected commands operate on active session state, including stop, reset, and status behavior during an existing run.

## Summary

Keep open: current main and v2026.6.11 still only partially address the Feishu active-run command regression. `/stop` has a dedicated Feishu control lane, but `/status` and `/new` remain on the ordinary same-chat lane and Feishu text slash messages are not marked as structured text-command turns.

## What This Changes

The issue reports that Feishu text commands such as `/stop`, `/new`, and `/status` are queued behind active agent runs instead of taking the documented command fast path.

## Best Possible Solution

Keep this issue open as the canonical active-run Feishu text-command regression, then choose one Feishu command-turn and queue-bypass policy with focused tests and live Feishu proof for the selected command set.
