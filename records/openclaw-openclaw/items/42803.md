## Label Justifications

- `P1`: Feishu users can still have control/status commands blocked behind active runs, which is a broken real-user channel workflow.
- `impact:session-state`: The unresolved `/new` and active-run command behavior can change or delay session lifecycle control while a run is active.

## Summary

Keep open: current main and the latest release only partially address the Feishu active-run command regression. `/stop` now has a separate control lane, but `/status` and `/new` still map to the normal same-chat lane, so the documented command-only bypass is not restored for the full report.

## What This Changes

The issue reports that Feishu text commands such as `/stop`, `/new`, and `/status` are queued behind active agent runs instead of using the documented immediate command-only path.

## Best Possible Solution

Define a tested Feishu text-command lane policy that keeps `/stop` immediate, adds immediate handling for safe read-only command-only text such as `/status`, and explicitly decides whether `/new` should bypass active runs or stay queued with corrected docs.
