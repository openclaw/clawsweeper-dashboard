## Label Justifications

- `P1`: The report describes a regression that leaves Feishu users unable to interrupt, reset, or inspect active agent runs with text commands.
- `impact:session-state`: The affected `/new` and active-run control behavior changes which session state is reset, stopped, or left running.
- `impact:message-loss`: Feishu command-only messages that stay behind the active run can be delayed until they no longer produce a useful visible command result.

## Summary

Keep open: current main and the latest release still only partially address the Feishu active-run text-command regression. `/stop` has a dedicated control lane, but `/status` and `/new` still use the ordinary Feishu chat lane, and the remaining behavior needs an explicit maintainer policy decision before a safe repair.

## What This Changes

The issue reports a regression where Feishu text commands such as `/stop`, `/new`, and `/status` are queued behind an active agent run instead of taking the documented command fast path.

## Best Possible Solution

Keep this issue open as the specific Feishu active-run text-command regression, then land one maintainer-approved Feishu plugin policy that explicitly covers or excludes `/stop`, `/new`, `/status`, and related stateful text slash commands with focused tests and live Feishu proof.
