## Label Justifications

- `P1`: Feishu users cannot reliably stop, reset, or inspect active agent runs through text commands during an in-flight channel workflow.
- `impact:session-state`: The affected commands operate on active session state, including stop, reset, and status behavior during an existing run.

## Summary

Keep open: current main and the latest release still only partially address the Feishu active-run text-command regression. `/stop` now has a dedicated Feishu control lane, but `/status` and `/new` remain on the ordinary same-chat lane and Feishu text slash messages are not explicitly marked as authorized text-command turns.

## What This Changes

Feishu text commands such as `/stop`, `/new`, and `/status` should bypass active agent-run queueing instead of waiting behind the current run.

## Best Possible Solution

Keep this issue open as the canonical active-run Feishu text-command regression, then land one focused Feishu/core fix after maintainers choose the authorized text-command and queue-bypass policy for `/status`, `/stop`, and `/new`.
