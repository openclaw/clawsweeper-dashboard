## Label Justifications

- `P1`: Feishu users cannot reliably stop or inspect active agent runs through text commands, which breaks a real channel workflow.
- `impact:session-state`: The failing commands are intended to abort, reset, or report the active agent session state during an in-flight run.
- `impact:message-loss`: Feishu text commands can be delayed until they no longer affect the active run or produce no useful visible command handling.

## Summary

Keep open: current main and the latest release still only partially address the Feishu active-run text-command regression. `/stop` now has a separate Feishu control lane, but Feishu text turns are not marked as general `text-slash` command turns, `/status` remains on the ordinary same-chat lane, and open PR https://github.com/openclaw/openclaw/pull/85616 covers only a safe `/status`-style subset while explicitly excluding `/stop` and `/new`.

## What This Changes

Restore Feishu text commands such as `/stop`, `/new`, and `/status` so they bypass active-run queuing and execute immediately.

## Best Possible Solution

Keep this issue open as the canonical Feishu active-run text-command regression, review or land the safe subset PR if desired, then make an explicit maintainer decision for stateful text commands before changing `/stop` and `/new` behavior.
