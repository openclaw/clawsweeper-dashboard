## Label Justifications

- `P1`: Feishu users cannot reliably stop, reset, or inspect active agent runs through text commands during a live channel workflow.
- `impact:session-state`: The affected `/stop` and `/new` commands control or reset active agent session state.

## Summary

Keep open: current main and the latest release only partially address the Feishu active-run text-command regression. `/stop` now has a Feishu control lane, but `/status` and `/new` still do not have the same immediate structured text-command path, and the related open PR is adjacent follow-up queue work rather than a complete fix for this issue.

## What This Changes

Issue requests restoring immediate Feishu text slash-command handling for `/stop`, `/new`, and `/status` while an active agent run holds the normal Feishu queue.

## Best Possible Solution

Adopt one Feishu-owned command-turn and queue policy for authorized command-only text, then cover the selected `/status`, `/stop`, and `/new` behavior with focused Feishu tests and live Feishu proof.
