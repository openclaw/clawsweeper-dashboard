## Label Justifications

- `P1`: Feishu users cannot reliably stop, reset, or inspect active agent runs through text commands during an in-flight channel workflow.
- `impact:session-state`: The affected commands operate on active session state, including stop/reset/status behavior during an existing run.
- `impact:message-loss`: Command-only Feishu messages can be delayed until they no longer affect the active run or fail to produce a useful visible command result.

## Summary

Keep open: current `main` and the latest release still only partially address the Feishu active-run command regression. `/stop` has a separate Feishu control lane, but `/status` and `/new` still use the ordinary chat lane, and Feishu inbound context still does not mark whole-message text commands as structured `text-slash` turns.

## What This Changes

The issue reports that Feishu text commands such as `/stop`, `/new`, and `/status` are queued behind an active agent run instead of bypassing the queue.

## Best Possible Solution

Keep this issue open as the canonical active-run Feishu text-command regression, then choose and land one Feishu-owned command-turn and queue policy with tests and live proof for the selected command set.
