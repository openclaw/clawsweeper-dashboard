## Summary

The bounded-read direction is correct and the static oversized-file behavior is well proven, but the current head still has two blocking file-I/O defects: the cap is not descriptor-stable during concurrent transcript growth, and the oversized-tail path assumes one positional read returns the complete requested range.

## What This Changes

The PR caps session-memory transcript reads at 16 MiB and adds regression tests for preserving recent messages from oversized transcripts and rejecting a lone over-cap JSONL row.

## Best Possible Solution

Open the transcript once with safe read-only flags, use that handle for validation, size, and complete capped reads, and preserve only complete recent JSONL rows through the existing sanitizer and filtering pipeline.
