## Summary

Keep open for normal maintainer review: current main and the latest release still read the session-memory transcript with an unbounded whole-file read, while this PR is a focused mitigation with current-head terminal proof and no blocking review findings.

## What This Changes

The PR adds a 16 MiB bounded session-memory transcript reader that tails oversized JSONL files and adds regression coverage for preserving recent messages from the tail.

## Best Possible Solution

Land a narrow bounded-tail implementation in the existing session-memory transcript helper, with the fixed cap kept local unless maintainers later see evidence that it needs configuration.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 read the full transcript with fs.readFile before parsing. I did not run a live OOM reproduction in this read-only review, but the vulnerable code path and PR regression test are clear.

## Solution Assessment

Yes. The tail-preserving bounded read is the narrowest maintainable fix for this helper because rejecting oversized files would avoid OOM but lose recent context, and adding a new config option is not justified by the evidence.
