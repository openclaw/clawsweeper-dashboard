## Summary

Keep open. The PR fixed the prior caller-side cap ordering, but current head still asks the reverse transcript stream for the next line before it can enforce the 16 MiB cap; that shared reader accumulates and decodes a complete line before yielding, so a single oversized JSONL row can still be buffered and undermine the OOM fix.

## What This Changes

The PR changes session-memory transcript extraction to read recent transcript lines newest-first through the shared reverse stream with a 16 MiB retained-output cap, plus an oversized-transcript regression test.

## Best Possible Solution

Add a stream-level bounded tail or max-line reader for session-memory that can skip over over-cap JSONL rows without materializing them, preserve chronological sanitizer behavior for retained recent lines, and refresh terminal proof with large-line memory coverage.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: construct a transcript with small recent lines after a single huge earlier JSONL row, and the reverse helper must accumulate that huge row before the caller cap can reject it.

## Solution Assessment

No. Reusing the shared reverse reader is a good direction for ordinary long transcripts, but without a stream-level max-line or bounded-tail guard this only bounds retained output, not the bytes buffered while discovering the next line.
