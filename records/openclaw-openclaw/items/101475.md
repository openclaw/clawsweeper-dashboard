## What This Changes

The PR replaces the session-memory transcript whole-file read with a 16 MiB bounded reader and adds regression coverage for oversized JSONL transcripts.

## Reproduction Assessment

Yes. Current main and `v2026.6.11` both call `fs.readFile` on the session-memory transcript before JSONL splitting, so an oversized or corrupted transcript can force whole-file buffering.

## Solution Assessment

Yes. The PR fixes the hook-owned read path, reuses the existing reverse transcript streamer where safe, and adds a bounded tail path for over-cap files without adding config or broad policy.
