## Summary

Keep open: current main still intentionally delivers a child’s final result inside the parent completion event, and fresh 2026.7.1 reports show real subagent/session instability. Some premature-compaction evidence is separately explained by token-accounting work, so changing the completion contract needs an explicit product and compatibility decision rather than an automatic bug fix.

## What This Changes

Requests metadata-only subagent completion by default, explicit bounded child-result retrieval, bounded channel announcements, and an optional compatibility mode for result-bearing completion events.

## Best Possible Solution

Define one core completion contract with status and session identifiers, a strictly byte/token-capped child summary or final result, explicit bounded history/artifact retrieval, and no raw tool output; preserve or migrate the documented result-bearing behavior only after testing parent synthesis, nested orchestration, user-channel delivery, and upgrades.

Options:

- **Bounded result envelope (recommended):** Keep status, identifiers, and a strictly capped child summary/final result by default, with explicit bounded retrieval for additional detail.
- **Metadata-only default:** Deliver only status and a child-session handle by default, accepting an extra retrieval/model step and providing a documented migration path for existing workflows.
- **Keep current contract:** Retain automatic final-result delivery and address only accounting, sizing, stale-delivery, and channel-leak defects.

## Reproduction Assessment

Yes for the current contract: current main explicitly documents and prompts automatic child-result delivery into the parent completion event. The stronger claim that this payload alone causes premature compaction is not isolated because current reports also show cache/input accounting inflation.

## Solution Assessment

Unclear as proposed: metadata-only delivery is safer for context isolation but can break the documented supervisor contract. A hard-capped result envelope plus explicit bounded retrieval is the narrower compatibility-aware direction unless maintainers intentionally choose a breaking default.
