## Label Justifications

- `P2`: This is a bounded Discord delivery improvement with limited blast radius, but it affects user-visible attachment delivery.
- `impact:message-loss`: The current Discord paths cannot preserve multiple requested attachments through one native Discord send, so plural media can be split or dropped instead of delivered as intended.

## Summary

Keep open: current main and v2026.6.11 still send Discord uploads through scalar `mediaUrl` paths, and the open closing PR at https://github.com/openclaw/openclaw/pull/99515 is the active fix candidate rather than a reason to close this issue before merge.

## What This Changes

Allow Discord outbound messages to send multiple ordered file attachments in one native message, up to Discord's supported per-message attachment limit, instead of exposing only one attachment.

## Best Possible Solution

Review and land the Discord-plugin-owned batching path in https://github.com/openclaw/openclaw/pull/99515 if maintainers accept its delivery semantics, then close this issue from the merged PR.

## Reproduction Assessment

Yes. Current main is source-reproducible: the Discord action and low-level send helpers only accept scalar `mediaUrl`, and the latest release has the same one-file REST upload body; I did not run a live Discord bot round trip in this read-only review.

## Solution Assessment

Yes. A Discord-plugin-owned native batching path is the narrow maintainable solution, while a broad core fanout change or new config knob is unnecessary unless the plugin cannot express the behavior locally.
