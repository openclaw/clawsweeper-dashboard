## Summary

Keep open: current main and the latest release still route Discord uploads through scalar `mediaUrl` paths and one-file upload bodies. The right cleanup path is to leave this issue as the canonical tracker while https://github.com/openclaw/openclaw/pull/99515 and https://github.com/openclaw/openclaw/pull/96709 remain open candidate fixes.

## What This Changes

The issue requests native Discord delivery of up to the platform maximum number of file attachments in one message instead of exposing only one attachment per message.

## Best Possible Solution

Land one Discord-plugin-owned native batching implementation with proof for grouped attachments, overflow splitting, reply targeting, and receipt aggregation; then close this issue from the merged PR.
