## Summary

Keep open: current main and v2026.6.11 still expose Discord outbound uploads through scalar `mediaUrl` paths, while https://github.com/openclaw/openclaw/pull/99515 is the active open closing PR rather than a reason to close before merge.

## What This Changes

Allow Discord outbound sends to include up to Discord's native multi-file attachment limit in one message, with overflow split into follow-up messages.

## Best Possible Solution

Land the Discord-plugin-owned batching path from https://github.com/openclaw/openclaw/pull/99515 if maintainers accept its delivery semantics, then close this issue from the merged PR.

## Reproduction Assessment

Yes. Current main is source-reproducible: the Discord action and low-level send helpers accept only a scalar `mediaUrl`, and the latest release has the same one-file REST upload body; I did not run a live Discord bot round trip in this read-only review.

## Solution Assessment

Yes. A Discord-plugin-owned native batching path is the narrow maintainable solution; a broad core fanout change or a new config knob is unnecessary unless the plugin cannot express the behavior locally.
