## Summary

Keep this PR open for maintainer review. Current `main` still matches mention patterns and command text against the raw Nextcloud Talk JSON envelope, while this branch parses the documented rich-object payload and keeps shared reply-delivery policy intact; the remaining decision is whether this plugin-local text normalization is the intended permanent agent-input contract.

## What This Changes

The PR converts structured Nextcloud Talk webhook bodies into rendered text plus stable mention metadata, then uses that data for group mention gating, command parsing, and agent dispatch.

## System Context

Nextcloud Talk sends ActivityStreams webhook messages into the bundled channel plugin, which authorizes the sender and decides whether a group message explicitly addressed the bot. The plugin then builds OpenClaw’s inbound agent envelope and sends any response through the shared channel reply pipeline.

## Best Possible Solution

Keep rich-object normalization inside the Nextcloud Talk plugin, define the rendered-text versus command-text contract as the canonical inbound representation, and retain tests for bot actor IDs derived from the exact registered public URL.
