## Summary

Keep open: current main and the latest release still keep managed `openclaw` profiles and `existing-session` attach profiles separate, and the requested one-shot import remains a security-sensitive product decision rather than a completed bug fix.

## What This Changes

The issue requests an explicit one-shot flow to import or clone an existing browser session profile into a managed OpenClaw browser profile without making that copy automatic.

## Best Possible Solution

If maintainers accept the boundary, implement this in the bundled browser plugin as an explicit one-shot import with destination stop/reset, source untouched, transient-file stripping, focused tests, and security-forward docs.
