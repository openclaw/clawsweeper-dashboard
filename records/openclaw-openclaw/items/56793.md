## Summary

Keep open: current main still keeps managed `openclaw` profiles and Chrome MCP `existing-session` profiles separate, with profile CRUD/reset support but no explicit one-shot import/clone flow; the remaining blocker is maintainer product and security approval for copying signed-in browser state into managed agent storage.

## What This Changes

The issue requests an explicit one-shot command or API to copy an existing browser-session profile into a managed OpenClaw browser profile.

## Best Possible Solution

If maintainers accept the boundary, implement this inside the bundled browser plugin as an explicit consent-driven one-shot import that stops/resets only the destination, leaves the source untouched, strips transient browser runtime files, relaunches the managed profile, and documents that this is not live sync.

## Reproduction Assessment

Yes, at source level: current main has managed `openclaw` and Chrome MCP `existing-session` profile paths plus create/delete/reset surfaces, but no import command or route. This is a missing feature surface rather than broken existing behavior.

## Solution Assessment

Unclear until maintainers decide the security/product boundary. The explicit non-automatic import shape is plausible, but it should not be treated as an autonomous bug fix before consent, copy safety, and docs requirements are settled.
