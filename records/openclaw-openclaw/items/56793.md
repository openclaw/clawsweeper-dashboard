## Summary

Keep open: current main still separates managed `openclaw` and Chrome MCP `existing-session` profiles, and there is no import/clone route or CLI command. The request remains a security-sensitive product feature decision about moving signed-in browser state into managed agent storage.

## What This Changes

Add an explicit one-shot command or API to import an existing-session browser profile into a managed OpenClaw browser profile without live sync or source mutation.

## Best Possible Solution

If maintainers accept the boundary, implement this inside the bundled browser plugin as an explicit one-shot import with user consent, destination stop/reset, source untouched, transient-file stripping, focused tests, and security-forward docs; otherwise keep the documented profile separation.

## Reproduction Assessment

Yes, source-reproducible: current main has managed `openclaw` and Chrome MCP `existing-session` paths plus profile list/create/delete/reset surfaces, but no import command or route. This is a missing feature surface, not a broken existing behavior reproduction.

## Solution Assessment

Unclear until maintainers decide the product and security boundary. The proposed explicit, non-automatic import is the safest shape if accepted, but it should not be treated as an autonomous bug fix before that decision.
