## Summary

Keep open: current main and latest release still keep managed `openclaw` profiles and existing-session attach as separate profile modes, with no import/clone command or route. The remaining blocker is maintainer product/security approval, not implementation uncertainty.

## What This Changes

The issue requests an explicit one-shot flow to import a user's existing browser profile state into a managed `openclaw` browser profile without automatic syncing.

## Best Possible Solution

If maintainers accept the boundary, implement this in the bundled browser plugin as an explicit same-user local import with destination stop/reset, source untouched, transient-file filtering, focused tests, and security-forward docs.
