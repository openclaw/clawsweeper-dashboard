## Summary

Keep open: current main and v2026.6.11 still expose managed browser profiles and existing-session attach as separate profile modes, with create/delete/reset surfaces but no explicit one-shot import from signed-in browser state into the managed profile. The remaining blocker is a maintainer product/security decision, not missing implementation certainty.

## What This Changes

Request adds an explicit one-shot browser profile import/clone flow from an existing-session browser profile into the managed openclaw profile.

## Best Possible Solution

If maintainers accept the boundary, implement this in the bundled browser plugin as an explicit one-shot same-user local import with destination stop/reset, source untouched, transient-file stripping, focused tests, and security-forward docs.
