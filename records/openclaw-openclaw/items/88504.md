## Summary

This remains a valuable but unmergeable architecture PR: current main still has the single memory slot, while the PR's new per-agent dreaming contract is incomplete because the Control UI status path resolves global dreaming configuration for an agent-specific request. The mechanical caller fix is clear, but the five-role public config and plugin API contract still needs explicit maintainer sponsorship and exact-head UI proof.

## What This Changes

The PR adds five global and per-agent memory role slots and routes plugin activation, hooks, runtime selection, migrations, diagnostics, lifecycle cleanup, SDK types, tests, and documentation through them.

Thread the validated `agentId` through every dreaming owner/config lookup in `doctor.memory.status`, add a regression with distinct global and per-agent owners, capture redacted exact-head Control UI proof, and then have maintainers explicitly sponsor all five roles or narrow the public contract to roles with complete invocation semantics.
