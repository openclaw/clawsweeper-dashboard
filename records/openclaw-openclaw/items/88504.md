## Summary

The PR remains necessary because current core still has one exclusive memory owner, but this head is unsafe to merge. It can silently replace a legacy custom memory provider with `memory-core`, keeps a public plugin role type coupled to config ownership, has unresolved merge conflicts, and lacks full runtime proof on the current functional head.

## What This Changes

Adds global and per-agent memory role slots for recall, capture, compaction, dreaming, and user modeling, then threads role selection through configuration, plugin activation, hooks, runtimes, Doctor, lifecycle cleanup, SDK exports, CLI, UI, tests, and docs.

## Best Possible Solution

Keep the typed role architecture, but preserve legacy custom recall ownership through a tested Doctor or migration boundary or visible fail-closed recovery, move the shared role union into a leaf contract, resolve conflicts, and rerun fresh-config plus tagged-release upgrade and live Gateway proof on the exact final head.
