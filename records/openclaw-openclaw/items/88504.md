## Summary

The central design is coherent and prior runtime-routing findings remain fixed, but the current patch is not merge-ready: its public plugin type now imports the runtime-heavy role resolver, causing both the architecture cycle and SDK callable-export budget failure, and the generated docs map is stale. The durable five-role taxonomy, per-agent scope, and migration policy also still require explicit maintainer approval, while current-head selected-agent Control UI proof remains missing.

## What This Changes

The PR adds five global and per-agent memory role slots and integrates them across configuration, plugin APIs and activation, role-aware hook/runtime routing, migration, diagnostics, Control UI, tests, and documentation.

## Best Possible Solution

Move MemoryPluginRole and related selection shapes into a dependency-free leaf contract consumed by both the public Plugin API and runtime resolver, keep only intentionally public SDK exports, regenerate the docs map, then require current-head upgrade/runtime and selected-agent Control UI proof before maintainers approve the five-role taxonomy and legacy migration policy.
