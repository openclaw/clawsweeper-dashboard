Question: When a GitHub Copilot Claude `anthropic-messages` isolated run aborts with no assistant text, no tool metadata, and no timeout flags, should OpenClaw retry/fallback automatically or surface the abort as terminal?

Rationale: Current source proves the remaining gap, but safe behavior depends on maintainer policy because fallback after an aborted agent run can repeat side effects unless the no-output/no-tool state is treated as replay-safe.

Likely owner: steipete

Owner reason: The most relevant current history is concentrated in GitHub Copilot provider metadata/stream code and adjacent fallback-classifier work.

Owner confidence: medium

Options:

- **Define replay-safe fallback (recommended):** Treat aborted no-output/no-tool Copilot Claude runs as fallback-worthy only after live proof and focused tests show no committed work can be duplicated.
- **Transport-first repair only:** Fix the Copilot Anthropic stream to emit progress or first-token idle errors, and keep aborted run fallback conservative.
- **Keep terminal abort behavior:** Document that these aborts surface as cron errors and require operators to choose a different primary transport or explicit retry policy.

## Solution Assessment

No; current main is only a partial solution because it records aborted cron runs as errors but still leaves Copilot Claude `anthropic-messages` progress/fallback behavior unresolved. The best fix needs live Copilot proof plus maintainer agreement on replay-safe fallback semantics.
