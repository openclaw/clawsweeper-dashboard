Question: Should OpenClaw treat provider watchdog aborts with no assistant text, no tool lifecycle, and no message-tool delivery as fallback-safe for GitHub Copilot Claude `anthropic-messages` cron runs?

Rationale: The code can be changed narrowly, but the permanent behavior decides whether an aborted agent run may be retried on another model; that affects side-effect safety and provider default behavior.

Likely owner: steipete

Owner reason: He has the strongest current history across the Copilot provider routing, stream wrapper, and agent-runtime fallback surfaces involved in this decision.

Owner confidence: high

Options:

- **Approve guarded fallback policy (recommended):** Classify aborted no-output results as fallback-worthy only when no tool, subagent, or message delivery evidence exists, and require live Copilot proof before closing.
- **Transport-only recovery first:** Add a Copilot Anthropic first-token idle timeout or heartbeat mechanism and keep aborted embedded results fail-closed until transport evidence is clearer.
- **Keep fail-closed:** Continue surfacing the run as a cron error and document switching the primary away from Copilot Claude when the transport hangs.
