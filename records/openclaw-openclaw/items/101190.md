## Summary

Keep open: current main and the latest release have cron wake, process-poll guidance, and a subagent-oriented `sessions_yield`, but they do not provide the requested same-session sleep/self-pause tool. This is useful, aligned runtime work, but it needs maintainer product/API direction before implementation.

## What This Changes

The issue requests a first-class `sleep` tool that ends the current turn, waits without token burn, and later resumes the same session with optional resume context.

## Best Possible Solution

Define a maintainer-approved, bounded, non-durable same-session pause/resume contract that reuses existing cron/wake/yield seams where possible, with a conservative duration cap and clear user-message cancellation semantics.
