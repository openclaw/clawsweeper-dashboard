## Summary

This PR targets a real caller-scope authorization bug, but it is not merge-ready: the new checks treat account IDs as globally agent-bound instead of channel- and route-scoped, leaving a same-ID cross-channel bypass while rejecting valid wildcard bindings. The PR also provides only test/CI evidence, not an observed after-fix real run.

## What This Changes

The PR adds Gateway and delivery-resolution checks intended to prevent agent-scoped cron jobs from selecting delivery or failure-destination accounts bound to another agent.

## Best Possible Solution

Replace both ad hoc account-only checks with one canonical route-binding authorization helper that evaluates the effective agent, channel, account, and applicable target qualifiers while honoring wildcard bindings; use the merged current-job-plus-patch state for updates, retain runtime defense for persisted jobs, and cover add, update, failure destination, cross-channel duplicate IDs, peer-scoped routes, and wildcards.
