## Summary

The linked bug is valid, but this branch has two blockers: runtime resolution silently overrides documented explicit account selections for existing or operator-created jobs without bindings, and the new authorization predicate ignores the delivery channel, allowing cross-channel account-ID collisions. Likely related people are `vincentkoc` for recent cron routing work, `Takhoffman` for the Gateway cron surface, and `gumadeiras` for account-binding semantics.

## What This Changes

The PR adds caller-agent route-binding validation for cron delivery and failure-destination account IDs and changes isolated delivery resolution to discard explicit accounts not bound to the job owner.

## Best Possible Solution

Use one channel-aware authorization helper that rejects an account only when the effective channel/account is owned by another agent, preserves configured unbound explicit accounts for compatibility, and is shared by add, update, failure destinations, and runtime defense with focused upgrade and collision coverage.
