## What This Changes

The PR adds `thinkingLevelMap` metadata to the opencode-go DeepSeek V4 catalog entries and replaces the provider’s DeepSeek V4 stream wrapper with inline payload-patching logic that reads that map.

## Best Possible Solution

Expose `xhigh` and `max` for opencode-go DeepSeek V4 with the narrow provider/catalog policy, keep lower non-off levels mapped to `high`, preserve the shared DeepSeek V4 wrapper behavior, add focused regression coverage, and require real after-fix proof before merge.

## Solution Assessment

No. The right fix is narrower: expose the missing levels while preserving `high -> high` and the shared DeepSeek V4 wrapper contract instead of making catalog metadata a second wire-mapping source.
