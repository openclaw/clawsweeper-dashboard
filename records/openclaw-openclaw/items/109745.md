## What This Changes

The branch attaches a `Retry-After` value to memory-host HTTP errors and changes embedding-batch retries to use that hint while increasing fallback attempts and delays.

## System Context

The memory index command submits embedding batches through the memory-host SDK. That SDK turns failed HTTP responses into errors and sends them to the shared retry utility, which determines the next attempt delay before indexing continues or fails.

## Best Possible Solution

Keep provider-hint handling, parse both standard `Retry-After` forms, and scope the longer unhinted policy to HTTP 429 while preserving the existing 5xx failure behavior; add focused regressions and redacted live memory-index proof.
