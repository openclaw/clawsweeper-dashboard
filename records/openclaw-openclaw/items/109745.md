## Summary

Keep this PR open for revision. The destructive unrelated changes from the first review are gone, but the current head still has an invalid function signature, implements only one of the two standard `Retry-After` formats, broadly lengthens retries for 5xx failures, and provides no live after-fix memory-index proof.

## What This Changes

Adds `Retry-After` propagation to memory-host HTTP errors and changes batch HTTP retries from three short attempts to five attempts with delays of up to 60 seconds or a capped 120-second server hint.

## Best Possible Solution

Repair the signature, parse both delay-seconds and HTTP-date values in a focused helper, honor valid hints for rate limits, preserve the existing 5xx fallback schedule unless its expansion is separately justified, and cover both header forms plus cancellation with focused tests and a live redacted indexing transcript.
