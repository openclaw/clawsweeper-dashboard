## Summary

Keep open: the SQLite cache-owned exit close design is the right direction, but the PR currently registers the CLI debug-proxy exit finalizer before capture initialization succeeds, which can re-enter a failing store open from the exit event and mask the original startup failure.

## What This Changes

The branch adds process-exit close hooks for shared, agent, and proxy-capture SQLite caches, revalidates cached proxy stores, reorders CLI debug-proxy finalization, and adds lifecycle regression tests.

## Best Possible Solution

Keep the cache-owned exit close design, but only run the debug-proxy exit finalizer after capture initialization succeeds, with a regression test for an enabled debug proxy whose state DB open fails.

## Solution Assessment

No as submitted. The owner-level SQLite cache close is the best fix shape, but the run-main exit finalizer needs a success guard so startup errors are not replaced during process exit.
