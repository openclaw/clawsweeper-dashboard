## What This Changes

The branch changes cron startup recovery so a one-shot reminder rescheduled during an active run keeps its replacement schedule, including when that replacement became overdue before the gateway restarted.

## System Context

Cron persists one-shot reminders and their active-run markers, then repairs interrupted or finalized work when the gateway starts. The repair path determines whether a stored one-shot has been consumed or whether a newer replacement should continue into normal startup catch-up and delivery.

## Architecture Diagram

  B --> C[Startup run repair]
  C --> D{Newer replacement owns at slot?}
  D -->|No| E[Finalize old run and consume it]
  D -->|Yes| F[Preserve replacement schedule]
  F --> G[Normal startup catch-up]
  G --> H[Reminder delivery or isolated-agent deferral]

Keep the canonical persisted-slot ownership rule, prove future and overdue replacement recovery from a real persisted scheduler run on the final rebased head, then merge only if that proof matches the tested no-duplicate delivery behavior.
