## Label Justifications

- `P2`: Feishu interactive card submissions can silently drop user-entered form and selector data, but the blast radius is bounded to one bundled channel plugin path.
- `impact:data-loss`: Callback payload fields such as `form_value` and `input_value` are discarded before agents can consume them.
- `impact:message-loss`: The synthetic Feishu message delivered to the agent omits meaningful parts of the user's card interaction payload.

## Summary

Keep open. Current main and v2026.6.11 still narrow Feishu card-action callbacks to `action.value` and `tag`, while the same-author linked PR remains open and unmerged as the active fix candidate.

## What This Changes

The issue asks for Feishu card-action callbacks to pass through `form_value`, `input_value`, `name`, `option`, and `options` so agents receive structured interactive-card form and selector data.

## Best Possible Solution

Refresh, review, and land or replace the linked Feishu plugin PR with parser-boundary field preservation, a clear structured payload contract, focused parser/handler tests, and redacted real Feishu proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What agent-visible payload contract should Feishu card actions expose for `form_value`, `input_value`, `option`, `options`, and `name`?

Rationale: The missing fields are source-reproducible, but choosing JSON passthrough versus command-text appending changes channel behavior that existing button-command flows depend on.

Likely owner: m1heng

Owner reason: The package metadata names this handle as the community-maintained Feishu plugin contact, and this is a Feishu channel payload contract choice.

Owner confidence: high

Options:

- **Structured passthrough (recommended):** Expose non-button callback fields as structured JSON while keeping simple button command/text extraction unchanged.
- **Command-text append:** Append callback fields to the existing command text only if maintainers accept quoting, ordering, and value-serialization rules for downstream parsers.
- **Narrow form-first fix:** Ship only `form_value` initially and leave selector/input/name passthrough to a follow-up contract decision.

## Reproduction Assessment

Yes. Source inspection shows the raw Feishu card-action parser preserves only `action.value` and `tag`, and the fallback/handler path reads only `action.value`; no live Feishu tenant callback was run in this read-only review.

## Solution Assessment

Unclear until maintainers choose the payload contract. The owner boundary is right in the Feishu plugin parser/handler, but the best practical path is to refresh or replace the linked PR rather than queue a duplicate issue fix.
