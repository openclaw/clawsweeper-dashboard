## Label Justifications

- `P2`: The report describes a Feishu channel data-loss bug with limited plugin scope and an open fix candidate rather than a core emergency.
- `impact:data-loss`: Feishu form and selector values from card callbacks are silently discarded before the agent can use them.
- `impact:message-loss`: The affected card callback payload is converted into a synthetic agent message without the user-entered interactive fields.

## Summary

Keep open. Current main and the latest release still only preserve `action.value`/`tag` from Feishu card action callbacks, and the linked open PR remains the active fix candidate rather than a merged implementation.

## What This Changes

The issue requests passing Feishu card callback fields such as `form_value`, `input_value`, `name`, `option`, and `options` through to the synthetic message sent to the agent.

## Best Possible Solution

Preserve the Feishu-native callback fields at the plugin event boundary, expose them through one documented backward-compatible synthetic message format, and add regression coverage for form, input, selector, and unchanged simple-button behavior.
