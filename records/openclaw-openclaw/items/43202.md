## Label Justifications

- `P2`: Feishu card-action callbacks can silently omit user-submitted form/select/input data, but the blast radius is bounded to one channel plugin.
- `impact:data-loss`: User-entered card form or input values can be dropped before the agent can observe them.
- `impact:message-loss`: The synthetic message delivered to the agent contains only `action.value`, so parts of the Feishu interaction payload are lost.

## Summary

Keep open. Current main and v2026.6.11 still normalize Feishu card-action callbacks to `action.value` plus `tag`, dropping the sibling fields requested here, and the same-author closing pull request remains open and conflicting.

## What This Changes

The issue asks Feishu card-action callbacks to pass through `form_value`, `input_value`, `name`, `option`, and `options` instead of only forwarding button `action.value`.

## Best Possible Solution

Resolve this in the Feishu plugin by preserving raw card-action sibling fields, choosing one stable agent-visible payload shape, preserving simple button behavior, and validating with focused parser/dispatch tests plus live Feishu proof when feasible.
