## Summary

Keep open. Current main and the latest release still drop Feishu card-action fields outside `action.value`, and the same-author closing PR is still open, conflicting, and awaiting maintainer payload-contract review.

## What This Changes

The issue requests that Feishu card action callbacks pass through fields such as `form_value`, `input_value`, `name`, `option`, and `options` when creating the synthetic agent message.

## Best Possible Solution

Preserve the reported interactive fields in the Feishu plugin callback boundary, keep simple button clicks backward-compatible, and land that through the existing PR or a narrow replacement with tests and live/redacted callback proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What synthetic message contract should Feishu card actions use when callback fields outside `action.value` are present?

Rationale: The code fix is small, but the exact JSON-versus-command text format becomes user-visible agent input and may affect existing cards that expect plain command extraction.

Likely owner: steipete

Owner reason: Recent Feishu card-action fixes and refactors make this the best available routing candidate for the payload-contract decision.

Owner confidence: medium

Options:

- **Structured only for interactive fields (recommended):** Preserve the existing plain-button extraction path and emit a structured JSON payload only when `form_value`, `input_value`, `option`, or `options` is present.
- **Command-style append format:** Append form/select values to the command text as tokens, which may be easier for command parsers but can be ambiguous for arbitrary user input.
- **Defer the field pass-through:** Keep current behavior until a broader Feishu interactive-card contract is designed, accepting continued data loss for forms/selects in the meantime.

## Reproduction Assessment

Yes, source-reproducible. Current `handleFeishuCardAction` dispatches the fallback built from only `event.action.value`, and the event type does not carry the reported sibling action fields.

## Solution Assessment

Unclear until the payload contract is settled. The right owner boundary is the Feishu plugin handler, but maintainers should choose the structured-message format before landing the linked PR or a replacement.
