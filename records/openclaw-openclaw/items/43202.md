## Label Justifications

- `P2`: The bug blocks Feishu interactive-card form/select workflows but is scoped to one bundled channel plugin.
- `impact:data-loss`: User-entered form, input, and select values are silently discarded before agents or plugins can consume them.
- `impact:message-loss`: The synthetic message delivered to the agent omits meaningful fields that were present in the native Feishu card-action callback.

## Summary

Keep open. Current main and the latest release still reduce Feishu card-action callbacks to `action.value`/`tag`, and the same-author closing PR remains open rather than merged.

## What This Changes

The issue asks Feishu card-action callbacks to pass `form_value`, `input_value`, `name`, `option`, and `options` through to the agent while preserving simple button clicks.

## Best Possible Solution

Review and either land or replace the linked Feishu PR with a backward-compatible parser/handler change that preserves the extra callback fields, keeps simple button extraction unchanged, and includes focused tests plus redacted live Feishu callback proof.

Rationale: The field-loss bug is source-proven, but the permanent agent-visible payload format is a plugin behavior contract and affects existing command/button semantics.

Likely owner: m1heng

Owner confidence: high

Options:

- **Structured Additive Payload (recommended):** Forward `action.value` plus `form_value`, `input_value`, `name`, `option`, and `options` as structured JSON only when extra callback fields are present, while leaving simple button text and command behavior unchanged.
- **Command-Text Append:** Append selected callback fields to the legacy command string, which is smaller but can be ambiguous for arbitrary form keys and values.
- **Typed Contract First:** Pause the fix until maintainers define a broader typed card-action contract for Feishu and any sibling channel plugins.

## Reproduction Assessment

Yes. Source inspection is a high-confidence reproduction path: current main parses and dispatches only `action.value`/`tag`, so sibling Feishu callback fields cannot reach the synthetic message.

## Solution Assessment

Unclear until maintainer direction is confirmed. The fix belongs in the Feishu plugin parser/handler, but the agent-facing payload shape should be settled on the linked PR before merge.
