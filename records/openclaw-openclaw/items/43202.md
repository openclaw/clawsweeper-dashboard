## Summary

Keep open. Current main and v2026.6.11 still strip Feishu card action callbacks down to `action.value`/`tag`, and the open closing PR is currently conflicting rather than merged.

## What This Changes

The issue asks Feishu card action callbacks to pass `form_value`, `input_value`, `name`, `option`, and `options` through to the agent-visible synthetic message.

## Best Possible Solution

Land or replace the Feishu-plugin fix that preserves raw form/input/select fields through the parser and fallback path, with focused regression tests and redacted real Feishu proof.

## Reproduction Assessment

Yes, from source: the raw Feishu card-action parser preserves only `action.value` and `tag`, and the fallback text builder reads only `action.value`. I did not run a live Feishu callback in this read-only review.

## Solution Assessment

Yes on owner boundary: this belongs in the Feishu plugin parser/fallback/handler with focused tests. The exact JSON/text payload contract still needs maintainer review, so the linked PR should be refreshed or replaced instead of opening a duplicate fix.
