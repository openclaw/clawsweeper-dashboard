## Label Justifications

- `P2`: Feishu card-action callbacks can silently omit user-submitted form/select/input data, but the blast radius is bounded to one channel plugin.
- `impact:data-loss`: User-entered card form or input values can be dropped before the agent can observe them.
- `impact:message-loss`: The synthetic message delivered to the agent contains only `action.value`, so parts of the Feishu interaction payload are lost.

## Summary

Keep open. Current main and v2026.6.11 still normalize Feishu card-action callbacks to `action.value` plus `tag`, so the requested sibling fields are still dropped, and the same-author closing PR remains open and conflicting.

## What This Changes

The issue requests that Feishu card-action callbacks preserve `form_value`, `input_value`, `name`, `option`, and `options` when building the synthetic agent message.

## Best Possible Solution

Resolve this in the Feishu plugin by preserving raw card-action sibling fields at the parser boundary, choosing one stable agent-visible payload format, keeping simple button behavior unchanged, and validating with focused tests plus live Feishu proof when feasible.

Yes, source inspection provides a high-confidence reproduction path: the parser returns only `action.value` and `tag`, and the fallback dispatcher only reads `action.value`. A live Feishu callback would improve behavior proof but is not needed to see why sibling fields are lost.
