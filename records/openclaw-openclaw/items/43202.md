## Summary

Keep open. Current main and the latest release still narrow Feishu card-action callbacks to `action.value`/`tag`, and the same-author linked PR at https://github.com/openclaw/openclaw/pull/43953 remains open as the active fix candidate.

## What This Changes

The issue asks the Feishu card action handler to pass through `form_value`, `input_value`, `name`, `option`, and `options` from card callbacks while preserving simple button behavior.

## Best Possible Solution

Refresh, review, and land or replace the linked Feishu plugin PR with parser-boundary field preservation, a clear structured payload contract, focused tests, and redacted real Feishu proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What agent-visible payload contract should Feishu card actions expose for `form_value`, `input_value`, `option`, `options`, and `name`?

Rationale: The missing fields are source-reproducible and documented by Feishu, but choosing JSON passthrough versus command-text appending changes channel behavior that existing button-command flows depend on.

Likely owner: m1heng

Owner reason: The Feishu package metadata names this handle as the community-maintained plugin contact, and this is a Feishu channel payload-contract choice.

Owner confidence: high

Options:

- **Structured passthrough (recommended):** Expose non-button callback fields as structured JSON while keeping simple button command/text extraction unchanged.
- **Command-text append:** Append callback fields to the existing command text if maintainers accept quoting, ordering, and value-serialization rules for downstream parsers.
- **Narrow form-first fix:** Ship only `form_value` initially and leave selector, input, and name passthrough to a follow-up contract decision.

## Reproduction Assessment

Yes. Source inspection shows the raw Feishu card-action parser preserves only `action.value` and `tag`, and the fallback/handler path reads only `action.value`; no live Feishu tenant callback was run in this read-only review.

## Solution Assessment

Unclear until maintainers choose the payload contract. The owner boundary is right in the Feishu plugin parser/handler, but the best practical path is to refresh or replace the linked PR rather than queue a duplicate issue fix.
