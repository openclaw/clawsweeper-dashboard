## Label Justifications

- `P2`: Feishu card-action callbacks can silently omit user-submitted form/select data, but the blast radius is bounded to one bundled channel plugin path.
- `impact:data-loss`: The callback parser and fallback dispatch currently drop user-entered form/select fields before the agent can observe them.
- `impact:message-loss`: The synthetic message delivered to the agent contains only `action.value`, so parts of the Feishu card interaction payload are lost.

## Summary

Keep open. Current main and the latest release still drop Feishu card-action sibling fields outside `action.value`, and the same-author closing PR is still open and conflicting, so this issue remains the canonical bug thread.

## What This Changes

The issue asks Feishu card-action callbacks to preserve form, input, selector, and component fields in the synthetic message sent to the agent.

## Best Possible Solution

Resolve this in the Feishu plugin parser and handler by preserving raw action fields and emitting a maintainer-approved structured payload, preferably by refreshing the linked PR with focused regression tests and Feishu proof.
