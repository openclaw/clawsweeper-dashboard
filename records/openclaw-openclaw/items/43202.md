## Summary

Keep open. Current main and the latest release still drop sibling Feishu card-action fields before the synthetic agent message is built, and the same-author PR that closes this issue is open and conflicting rather than merged.

## What This Changes

The issue asks Feishu card-action callbacks to pass form, input, component-name, and selector fields through to the synthetic agent message instead of only forwarding `action.value`.

## Best Possible Solution

Review and either land or replace the linked Feishu PR with a backward-compatible parser/handler change that carries the extra callback fields, preserves simple button extraction, and includes focused tests plus redacted live Feishu callback proof.
