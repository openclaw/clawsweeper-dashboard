## Label Justifications

- `P2`: Feishu card-action callbacks can silently omit user-submitted form/select data, but the blast radius is bounded to one bundled channel plugin path.
- `impact:data-loss`: The callback parser and fallback dispatch currently drop user-entered form/input/select fields before the agent can observe them.
- `impact:message-loss`: The synthetic message delivered to the agent contains only `action.value`, so parts of the Feishu card interaction payload are lost.

## Summary

Keep open. Current main and latest release v2026.6.11 still retain only `action.value` plus `tag` from Feishu card-action callbacks, and the same-author PR that closes this issue remains open and conflicting, so this is still the canonical bug thread.

## What This Changes

Feishu card-action callbacks should pass `form_value`, `input_value`, `name`, `option`, and `options` through to the synthetic agent message instead of only forwarding `action.value`.

## Best Possible Solution

The Feishu plugin should preserve official card-action sibling fields at the parser boundary and send a durable structured payload while keeping simple button command extraction intact.

## Reproduction Assessment

Yes, at source level. A `card.action.trigger` payload with `action.form_value`, `input_value`, `option`, or `options` alongside `action.value` is normalized to only `value` plus `tag`, and fallback dispatch then builds the synthetic message from `action.value` only.

## Solution Assessment

Unclear until maintainers choose the payload contract. The fix belongs in the Feishu plugin parser and card-action handler, but the durable solution should settle structured JSON versus command-text append before landing.
