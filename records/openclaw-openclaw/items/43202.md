## Summary

Keep open. Current main and v2026.6.11 still drop Feishu card-action fields that sit beside `action.value`, and the open same-author PR remains the active but conflicting fix candidate.

## What This Changes

The issue requests passing Feishu card-action fields such as `form_value`, `input_value`, `name`, `option`, and `options` through to the synthetic agent message without changing simple button clicks.

## Best Possible Solution

Land or replace the linked Feishu plugin PR with a backward-compatible parser/handler change that preserves simple button text/command behavior, passes through form/input/select fields, and includes focused unit coverage plus redacted live Feishu callback proof.
