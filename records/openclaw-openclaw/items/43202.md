- `P2`: Feishu card callbacks can silently omit user-entered form/select data, but the blast radius is bounded to one bundled channel plugin path.
- `impact:data-loss`: The callback parser and fallback dispatch currently drop user-entered form/select fields before the agent can observe them.
- `impact:message-loss`: The synthetic message delivered to the agent contains only `action.value`, so parts of the Feishu card interaction payload are lost.

## Summary

Keep open. Current main and v2026.6.11 still discard Feishu card-action callback fields outside `action.value`, and the same-author closing PR is still open, conflicting, and needs maintainer review.

## What This Changes

Pass Feishu card-action callback fields such as `form_value`, `input_value`, `name`, `option`, and `options` through to the agent while preserving simple button behavior.

## Best Possible Solution

Resolve this in the Feishu plugin parser and handler by preserving raw action fields and emitting a maintainer-approved structured payload, preferably by refreshing or replacing the linked PR with focused regression tests and Feishu proof.
