## Summary

Keep open. Current main and the latest release still narrow Feishu card-action callbacks to `action.value` and `tag`, and the open linked pull request remains the active fix candidate rather than a reason to clean up this issue.

## What This Changes

Pass Feishu card-action `form_value`, `input_value`, `name`, `option`, and `options` fields through to the agent synthetic message while preserving simple button behavior.

## Best Possible Solution

Land or replace the linked Feishu plugin PR with parser-boundary preservation for the missing action fields, a maintainer-approved structured payload contract, focused tests, and redacted real Feishu proof.

Rationale: The missing fields are source-reproducible and part of Feishu's callback payload, but choosing JSON passthrough versus command-text appending changes channel behavior that existing button-command flows depend on.

Options:

- **Structured passthrough (recommended):** Expose non-button callback fields as structured JSON while keeping simple button command/text extraction unchanged.
- **Command-text append:** Append callback fields to the existing command text if maintainers accept ordering, quoting, and value-serialization rules for downstream parsers.
- **Narrow form-first fix:** Ship only `form_value` first and leave selector, input, and name passthrough to a follow-up contract decision.

Yes, at source level. The current parser preserves only `action.value` and `tag`, and the handler/fallback path reads only `action.value`, so the reported callback fields cannot reach the synthetic message on current main.

## Solution Assessment

Unclear until maintainers choose the payload contract. The Feishu plugin parser and card-action handler are the right boundary, but the practical path is reviewing or replacing the linked PR rather than opening a duplicate fix.
