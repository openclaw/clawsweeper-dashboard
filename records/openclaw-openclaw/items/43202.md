## Label Justifications

- `P2`: This is a bounded Feishu plugin bug with real workflow impact but limited blast radius outside card-action callbacks.
- `impact:data-loss`: User-entered form, input, and select values are silently discarded before they can reach the agent.
- `impact:message-loss`: The synthetic message delivered to the agent omits fields that were present in the native Feishu card-action callback.

## Summary

Keep open. Current main and the latest release still narrow Feishu card-action callbacks to `action.value`, while the same-author closing PR remains open and conflicting rather than merged.

## What This Changes

The issue asks for Feishu card-action callbacks to pass `form_value`, `input_value`, `name`, `option`, and `options` through to the synthetic agent message without changing simple button behavior.

## Best Possible Solution

Review and either land or replace the linked Feishu PR with a backward-compatible parser/handler change that preserves the extra callback fields, keeps simple button extraction unchanged, and includes focused tests plus redacted live Feishu callback proof.

## Maintainer Decision

Question: What Feishu card-action payload contract should OpenClaw support for callback fields that are siblings of `action.value`?

Rationale: The field-loss bug is source-proven, but the chosen JSON/text payload format affects downstream command parsing and existing Feishu button semantics.

Likely owner: Vincent Koc

Owner reason: Current-line blame and recent Feishu parser/fallback ownership make this the best available routing candidate for the payload-shape decision.

Owner confidence: high

Options:

- **Structured Additive Payload (recommended):** Forward `action.value` plus `form_value`, `input_value`, `name`, `option`, and `options` as structured JSON only when extra callback fields are present, while leaving simple button text and command behavior unchanged.
- **Command-Text Append:** Append selected callback fields to the legacy command string, which is smaller but can be ambiguous for arbitrary form keys and values.
- **Typed Contract First:** Pause the fix until maintainers define a broader typed card-action contract for Feishu and any sibling channel plugins.

## Reproduction Assessment

Yes. Source inspection is a high-confidence reproduction path: current main parses and dispatches only `action.value`/`tag`, so sibling Feishu callback fields cannot reach the synthetic message.

## Solution Assessment

Unclear until maintainer direction is confirmed. The narrow fix belongs in the Feishu plugin parser/handler, but the agent-facing payload shape should be settled on the linked PR before merge.
