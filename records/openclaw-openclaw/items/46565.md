## Summary

Keep open: current main has fixed subagent/cron allowlists and cache-stable timestamp helpers, but it still lacks the requested public bootstrap selector, bootstrap command expansion, and unified per-session context contract.

## What This Changes

Request deterministic dynamic bootstrap context, session-type filtering for bootstrap files, and built-in time context for agent sessions.

## Best Possible Solution

Define one maintainer-approved bootstrap context contract that keeps safe defaults, makes command execution explicit and sandboxed if accepted, and aligns narrower bootstrap PRs under that design.

Options:

- **Selector API first (recommended):** Add a narrow maintained bootstrap tier/selector contract and defer command expansion until a separate sandbox/provenance design is approved.
- **Hook-only context:** Route dynamic per-session context through documented hooks and keep core bootstrap loading limited to safe built-in files.
- **Full command expansion:** Pursue bootstrap command expansion only with explicit opt-in, sandboxing, provenance, docs, and tests across session types.

Unclear as filed. The direction is useful, but it bundles selector policy, command execution, and time context; a smaller maintainer-approved selector contract is the safer first step.
