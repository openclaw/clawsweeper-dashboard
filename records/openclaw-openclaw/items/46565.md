## Summary

Keep open: current main partially addresses bootstrap session filtering with fixed subagent and cron allowlists, but the requested public selector contract, bootstrap command expansion, and dynamic current-time injection remain unresolved product/security work.

## What This Changes

The issue requests dynamic bootstrap file preprocessing, session-type filtering for bootstrap injection, and built-in current time/timezone context for sessions.

## Best Possible Solution

Define one maintainer-approved bootstrap context contract that preserves safe defaults, keeps command execution behind an explicit reviewed boundary, and aligns the narrower bootstrap PRs under that design.

Options:

- **Narrow selector/tier API first (recommended):** Add a small maintained bootstrap tier or selector contract and defer command expansion until a separate security model is approved.
- **Plugin hook only:** Route dynamic per-session context through documented hooks and keep core bootstrap loading limited to safe built-in files.
- **Full command expansion:** Pursue bootstrap command expansion only with explicit sandboxing, provenance, opt-in behavior, and upgrade-safe docs/tests.

Unclear as filed. The direction is useful, but the request bundles selector policy, command execution, and built-in time context; a smaller maintainer-approved selector contract is the safer first step.
