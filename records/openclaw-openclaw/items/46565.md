## Summary

Keep open: current main has fixed subagent/cron filtering and cache-stable timezone guidance, but the requested public bootstrap selector, bootstrap command expansion, and deterministic per-session context contract are still unresolved product/security work.

## What This Changes

The issue requests dynamic bootstrap-file command expansion, session-type bootstrap filtering, and built-in time/timezone context for agent, subagent, heartbeat, and scheduled sessions.

## Best Possible Solution

Define one maintainer-approved bootstrap context contract that keeps safe defaults, scopes command execution behind an explicit reviewed boundary, and aligns the open tiered-loading and exact-session PRs under that design.

Options:

- **Narrow selector API first (recommended):** Add a small maintained tier or selector contract for session-scoped bootstrap inclusion and defer command expansion until a separate security design is approved.
- **Plugin hook only:** Keep core bootstrap loading limited to safe built-in files and route dynamic per-session context through documented hooks or plugins.
- **Full command expansion:** Pursue bootstrap !command expansion only with explicit sandboxing, provenance, opt-in behavior, and upgrade-safe docs/tests.
