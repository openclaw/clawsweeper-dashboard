## What This Changes

Allow an agent to read local media inside its own resolved `workspace-<agentId>` directory without treating that workspace as another agent’s protected sibling.

## System Context

OpenClaw’s local-media access layer decides which filesystem roots an agent may read before media is extracted or attached to an agent workflow. Agent identity and workspace configuration should feed that decision so the security boundary protects other workspaces without excluding the requesting agent’s own workspace.

## Best Possible Solution

Trace every agent-scoped media-read entry point, pass only the requesting agent’s resolved workspace as an explicit local root where needed, and add regression coverage proving that its own `workspace-<id>` is readable while a sibling agent workspace remains denied.
