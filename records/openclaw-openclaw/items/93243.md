## Summary

Keep open: the Mattermost recovery bug is real and the supplied proof is sufficient, but the branch still has a merge-blocking availability issue because it can process every returned thread post and await user lookups before trimming to `historyLimit`.

## What This Changes

The PR adds a Mattermost REST thread fetch and session-gated channel-thread history backfill after restart or session clear, with focused monitor/client tests.

## Best Possible Solution

Keep the Mattermost-owned session-gated recovery backfill, but bound eligible server-thread posts to `historyLimit` before any username lookup and prove long-thread recovery stays bounded.

## Reproduction Assessment

Yes, at source level: current main builds Mattermost thread context from a process-local `channelHistories` map and has no server-side thread fetch when that window is empty. I did not run a live Mattermost repro in this read-only review, but the PR supplies live Mattermost proof for the recovery behavior.

## Solution Assessment

No as submitted: the session-id recovery gate and bounded fetch timeout are the right shape, but the best fix must cap the server-thread post set before username resolution so recovery cannot stall on large threads.
