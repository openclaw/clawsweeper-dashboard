## Summary

Keep open: the Mattermost recovery fix is useful and current main still lacks it, but this head still has a merge-blocking availability problem because it resolves users for every returned server-thread post before trimming to `historyLimit`.

## What This Changes

This PR adds a Mattermost REST thread fetch helper, session-gated server backfill of channel-thread history, and regression tests for restart/session-clear recovery plus same-session no-refetch behavior.

## Best Possible Solution

Keep the session-gated recovery backfill design, but cap the eligible server-thread posts before any username lookup and prove long-thread recovery only does O(historyLimit) post processing.

## Reproduction Assessment

Yes, at source level: current main builds Mattermost thread context from an in-memory `channelHistories` map and has no server-side thread fetch when that window is empty. I did not run a live Mattermost repro in this read-only review, but the PR supplies live proof for the recovery behavior.

## Solution Assessment

No as submitted: session-id gating and the bounded thread fetch are the right shape, but the best fix must cap the server-thread post set before username resolution so recovery cannot stall on large threads.
