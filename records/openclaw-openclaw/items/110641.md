## Summary

Keep this PR open, but do not merge it as written: the UTF-16-safe helper can shorten a nominal 80-unit window to 79 (or 78) units, so the guard may match less than its stated minimum threshold. The supplied evidence reports tests only and does not show an after-fix gateway behavior run.

## What This Changes

The branch replaces raw `.slice()` calls in boot-echo guard chunk creation and matching with `sliceUtf16Safe` from `@openclaw/normalization-core`.

## Best Possible Solution

Generate surrogate-safe candidate boundaries while preserving one explicit minimum-match unit, then add focused boundary coverage proving that no accepted echo candidate is shorter than that minimum.
