## Summary

Keep this PR open, but do not merge it as written: the latest wrapper intentionally accepts UTF-16-safe slices shorter than `MIN_ECHO_CHARS`, allowing a 79-code-unit shared prefix before differing surrogate-pair characters to be classified as a substantial boot echo and suppress an outbound reply.

## What This Changes

The PR replaces raw UTF-16 slices in the gateway boot-echo sliding-window comparison with `sliceUtf16Safe()` and adds surrogate-boundary regression coverage.

## Best Possible Solution

Retain UTF-16-safe boundaries while preserving the 80-code-unit minimum: skip shortened adjusted windows or select an adjacent valid window that still meets the threshold, then add a regression test with equal 79-unit prefixes followed by different surrogate-pair characters.
