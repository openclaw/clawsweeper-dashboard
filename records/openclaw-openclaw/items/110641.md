## Summary

Keep this PR open: its new minimum-length clamp does not prevent `sliceUtf16Safe` from shortening a boundary-crossing candidate below the 80-code-unit echo threshold, so it can still create a false-positive echo match. The external-PR real-behavior-proof gate also remains unmet.

## What This Changes

The branch replaces raw UTF-16 code-unit slicing in boot-echo chunk generation and matching with `sliceUtf16Safe`, while clamping requested chunk length to the 80-unit minimum.

## Best Possible Solution

Generate and compare only whole-surrogate-pair windows that retain at least the configured 80-unit threshold, then add a focused emoji boundary regression and redacted gateway-runtime proof.
