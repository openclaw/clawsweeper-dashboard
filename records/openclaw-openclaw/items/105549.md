## Summary

Keep this PR open: current `main` still supplies the 10-second limit only through `RequestInit.signal`, while the guarded-fetch contract uses top-level `timeoutMs` to control both abort timing and Undici dispatcher timeouts. The patch is focused, preserves the Feishu plugin boundary, adds caller-path regression coverage, and includes convincing after-fix runtime proof; no blocking correctness or security defect was found.

## What This Changes

The PR routes a 10-second Feishu app-registration timeout through `fetchWithSsrFGuard`, removes redundant per-request abort signals, and adds a no-response timeout regression test.

## Best Possible Solution

Keep a single 10-second Feishu registration budget at the `fetchWithSsrFGuard` boundary so guarded abort and dispatcher floors stay synchronized, with the no-headers caller-path regression retained.
