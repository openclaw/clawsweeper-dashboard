## Summary

Keep open: current main and the latest release still strip final tags as plain tag removal and only collapse duplicate blocks split by blank lines, so the reported same-line and tag-boundary duplicate output remains unsolved. The direct fix PRs are closed unmerged, and the broader visible-output normalizer PR is still draft/conflicting rather than a safe canonical fix.

## What This Changes

The issue requests stricter user-facing output sanitization for same-line, partial, and final-tag-boundary duplicates that survive the existing sanitizer.

## Best Possible Solution

Land a conservative sanitizer repair for concrete glued final-tag repeats and explicitly approved adjacent duplicate forms, with regressions that preserve intentional repetition, single-newline formatting, trailing whitespace, and code indentation.

## Reproduction Assessment

Yes, at source level. Current main strips final tags before a paragraph-only duplicate collapse that returns unchanged for same-line or single-newline duplicates, so the reported glued duplicate shape remains unhandled without a live WhatsApp run.

## Solution Assessment

No, current main is not the best end state. The narrow maintainable fix is a tested sanitizer rule for concrete adjacent or tag-boundary duplicates; broad partial-duplicate cleanup needs maintainer bounds first.
