## Summary

Keep open: current main and the latest release still strip final tags as token removal and only collapse duplicate blocks separated by blank lines, so the reported same-line and final-tag-boundary duplicate output remains unresolved.

## What This Changes

The issue requests improving the user-facing output sanitizer so same-line, partial, and final-tag-boundary duplicate assistant text is detected without breaking normal reply formatting.

## Best Possible Solution

Land a conservative sanitizer repair for concrete adjacent or final-tag-boundary duplicates, with regression tests that preserve intentional repeats, single-newline prose, code indentation, and trailing whitespace.

## Reproduction Assessment

Yes, at source level. Current main strips final tags before a paragraph-only duplicate collapse that returns unchanged for same-line or single-newline duplicates, so the reported glued duplicate shape remains unhandled without a live WhatsApp run.

## Solution Assessment

No, current main is not the best end state. The narrow maintainable fix is a tested sanitizer rule for concrete adjacent or tag-boundary duplicates; broad partial-duplicate cleanup needs maintainer bounds first.
