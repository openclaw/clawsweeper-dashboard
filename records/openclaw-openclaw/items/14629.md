## Summary

Keep open: current main and v2026.6.11 still strip final tags as plain text and only collapse exact duplicate blocks separated by blank lines, so the reported same-line/tag-boundary duplicate gap remains. The direct fix PRs are closed unmerged, and the broader normalizer PR is still a draft/conflicting overlap rather than a safe canonical fix.

## What This Changes

The issue requests stronger user-facing output sanitation for same-line, single-newline, partial, and final-tag-boundary duplicate assistant text.

## Best Possible Solution

Land a conservative sanitizer repair for concrete glued final-tag repeats and any explicitly approved adjacent same-line or single-newline duplicate form, with regressions that preserve intentional repetition and formatting.

## Reproduction Assessment

Yes, at source level. Current main removes final tags before a blank-line-only duplicate collapse that returns unchanged for same-line or single-newline duplicates, so the reported glued duplicate shape remains unhandled without a live WhatsApp run.

## Solution Assessment

No, current main is not the best end state. The narrow maintainable fix is a tested sanitizer rule for concrete adjacent/tag-boundary duplicates; broader partial duplicate cleanup needs maintainer bounds first.
