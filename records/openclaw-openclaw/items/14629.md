## Summary

Keep open: current main and v2026.6.11 still strip final tags as token removal and only collapse duplicate blocks split by blank lines, so the reported same-line and final-tag-boundary duplicate output remains unsolved. The direct fix PRs are closed unmerged, while the broader visible-output normalizer PR is still draft/conflicting and not a safe canonical fix.

## What This Changes

The issue requests more conservative duplicate-output sanitization for same-line, single-newline, partial duplicate, and final-tag-boundary model output patterns.

## Best Possible Solution

Land a conservative sanitizer repair for concrete adjacent or final-tag-boundary duplicates, with regression tests that preserve intentional repeats, single-newline prose, code indentation, and trailing whitespace.

## Reproduction Assessment

Yes, at source level. Current main and the latest release strip final tags before a paragraph-only duplicate collapse that returns unchanged for same-line or single-newline duplicates, so the reported glued duplicate shape remains unhandled without a live WhatsApp run.

## Solution Assessment

No, current main is not the best end state. The narrow maintainable fix is a tested sanitizer rule for concrete adjacent or tag-boundary duplicates; broad partial-duplicate cleanup needs maintainer bounds first.
