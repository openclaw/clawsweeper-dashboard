## Summary

Keep open: current main and v2026.6.11 still strip final tags as token removal and only collapse exact duplicate blocks separated by blank lines, so the reported same-line, single-newline, and final-tag-boundary duplicate sanitizer gap remains unresolved. The direct fix PRs are closed unmerged, and the broader visible-output normalizer PR is still a draft/conflicting partial-overlap item rather than a safe canonical fix.

## What This Changes

The issue asks OpenClaw to improve `sanitizeUserFacingText()` so same-line, single-newline, partial, and final-tag-boundary duplicate assistant output is not delivered to users.

## Best Possible Solution

Land a conservative sanitizer repair for concrete adjacent or final-tag-boundary duplicates, with regression tests that preserve intentional repeats, ordinary single-newline prose, code indentation, and trailing whitespace.
