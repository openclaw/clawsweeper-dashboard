- `P2`: This is a normal-priority user-visible reply sanitation bug with limited blast radius rather than a core outage.
- `impact:message-loss`: The affected sanitizer can leave duplicated or malformed assistant reply text in delivered channel messages.

## Summary

Keep open: current main and the latest stable release still remove final tags as markers and then only collapse exact duplicate blocks separated by blank lines, so the same-line and final-tag-boundary duplicate gap remains. The issue is source-reproducible, but broad partial-duplicate cleanup needs maintainer bounds because it can erase intentional repeated output.

## What This Changes

The issue asks OpenClaw to improve `sanitizeUserFacingText()` so same-line, single-newline, partial, and final-tag-boundary duplicate assistant text is not delivered to users.

## Best Possible Solution

Land a conservative sanitizer rule for concrete adjacent/tag-boundary duplicates, with maintainer-approved bounds for any partial duplicate behavior and regressions that preserve intentional repetition and formatting.

## Reproduction Assessment

Yes. Current main removes `<final>` tags before a blank-line-only duplicate collapse that returns unchanged for same-line or single-newline repeats, so the reported glued duplicate shape is reproducible from source inspection.

## Solution Assessment

No, current main is not the best end state. A narrow, tested rule for adjacent or tag-boundary duplicates is maintainable, while broader partial duplicate cleanup needs maintainer bounds first.
