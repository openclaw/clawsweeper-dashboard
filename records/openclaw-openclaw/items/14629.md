## Label Justifications

- `P2`: This is a normal-priority user-visible reply sanitation bug with limited blast radius rather than a core outage.
- `impact:message-loss`: The affected sanitizer can leave duplicated or malformed assistant reply text in delivered channel messages.

## Summary

Keep open: current main and v2026.6.11 still strip `<final>` tags as plain tag removal and only collapse exact duplicate blocks separated by blank lines, so the same-line/tag-boundary duplicate gap remains.

## What This Changes

Request to extend `sanitizeUserFacingText()` so user-facing replies can conservatively remove same-line, single-newline, partial, or final-tag-boundary duplicate text.

## Best Possible Solution

Land a conservative, tested sanitizer repair for concrete glued `</final>` repeats and any maintainer-approved adjacent same-line or single-newline duplicate form while preserving intentional repetition and formatting.

## Reproduction Assessment

Yes, at source level. Current main removes `<final>` tags before a paragraph-only duplicate collapse that returns unchanged for same-line or single-newline duplicates, so the reported glued duplicate shape remains unhandled without a live WhatsApp run.

## Solution Assessment

No, current main is not the best end state. The best fix is a narrow sanitizer rule for concrete adjacent or tag-boundary duplicates; broader partial-duplicate cleanup needs maintainer bounds first.
