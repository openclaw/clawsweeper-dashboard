## Summary

Keep open: current main and the latest stable release still strip `<final>` markers textually and only collapse exact blank-line-separated duplicate blocks, so the same-line and final-tag-boundary duplicate gap remains. The direct fix attempts are closed unmerged, and the broader normalizer PR at https://github.com/openclaw/openclaw/pull/68986 is still draft, conflicting, and not a landed canonical fix.

## What This Changes

The issue requests stronger user-facing output sanitization for same-line, partial, and final-tag-boundary duplicate assistant text.

## Best Possible Solution

Land a conservative sanitizer rule for concrete adjacent and final-tag-boundary duplicates, with maintainer-approved bounds for any partial-duplicate behavior and regression tests that preserve intentional repetition and formatting.

## Reproduction Assessment

Yes. Current main removes `<final>` tags before a blank-line-only duplicate collapse that returns unchanged for same-line or single-newline repeats, so the reported glued duplicate shape is source-reproducible.

## Solution Assessment

No. Current main is not the best end state; a narrow adjacent/tag-boundary duplicate rule is maintainable, while broader partial-duplicate cleanup still needs maintainer bounds first.
