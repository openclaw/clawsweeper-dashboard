## Summary

Keep open: current main and the latest release still strip final tags without boundary-aware duplicate cleanup and still only collapse exact duplicate blocks separated by blank lines, so the reported same-line/tag-boundary duplicate gap remains.

## What This Changes

The issue requests better user-facing output sanitizer duplicate detection for same-line, partial, and final-tag-boundary repeated text.

## Best Possible Solution

Land a conservative sanitizer repair for concrete glued `</final>` repeats and any explicitly approved adjacent same-line or single-newline duplicate form, with regressions that preserve intentional repetition and formatting.

## Reproduction Assessment

Yes, at source level. Current main removes `<final>` tags before a paragraph-only duplicate collapse that returns unchanged for same-line or single-newline duplicates, so the reported glued duplicate shape remains unhandled without needing a live WhatsApp run to see the code path.

## Solution Assessment

No, current main is not the best end state. The narrow maintainable fix is a tested sanitizer rule for concrete adjacent/tag-boundary duplicates; broader partial duplicate cleanup needs maintainer bounds first.
