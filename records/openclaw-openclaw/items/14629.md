## Summary

Keep open: current main and the latest release still strip final tags as token removal and only collapse duplicate blocks separated by blank lines, so the reported same-line, single-newline, and final-tag-boundary duplicate output remains unresolved. The direct fix attempts are closed unmerged, and the broader visible-output normalizer PR is draft/conflicting rather than a safe canonical fix.

## What This Changes

The issue requests more conservative duplicate cleanup in user-facing output sanitization for same-line, single-newline, partial, and final-tag-boundary repeats.

## Best Possible Solution

Land a conservative sanitizer repair for concrete adjacent or final-tag-boundary duplicates, with regression tests that preserve intentional repeats, ordinary single-newline prose, code indentation, and trailing whitespace.
