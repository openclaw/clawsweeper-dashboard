## Summary

Current main and the shipped plugin contract already solve the central guardrail need through the dedicated fail-closed `before_agent_run` gate; however, this issue is paired with the same author's open implementation PR, so the pair should be resolved together rather than closing only the issue.

## What This Changes

Change `llm_input` from an observation-only hook into a sequential fail-closed prompt gate and add `sessionFile` to the agent hook context.

## Best Possible Solution

Keep `llm_input` observation-only, use `before_agent_run` for fail-closed policy decisions, and correlate sessions through `agentId`, `sessionKey`, and `sessionId` plus the supported transcript-runtime APIs rather than `sessionFile`.

## Reproduction Assessment

No—the claimed inability for plugins to block model submission does not reproduce on current main because `before_agent_run` is a documented fail-closed gate before `llm_input` and provider submission. The narrower observation that `llm_input` itself ignores results is expected behavior, not a broken contract.

## Solution Assessment

No—the proposed change duplicates the existing decision hook and would make observation-handler failures upgrade-sensitive. The existing dedicated gate plus identity-based transcript APIs is the narrower and safer solution.
