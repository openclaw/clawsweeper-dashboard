## Summary

Keep open: current main and v2026.6.11 still order and filter Sessions list rows from stored `updatedAt`, while the requested meaningful-activity timestamp, reason label, and parent/child rollup remain a product and projection-design decision.

## What This Changes

The issue requests that the Sessions panel sort by human-meaningful activity, explain the activity reason, and roll child session activity into parent session ordering instead of using raw update timestamps.

## Best Possible Solution

Define one shared read-time meaningful-activity projection for `sessions.list`, expose timestamp plus reason on `GatewaySessionRow`, roll child activity into the parent without background write amplification, and sort Sessions UI surfaces from that projection.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Sessions ordering use a read-time meaningful-activity projection or persisted activity timestamp fields, and which event classes count as meaningful?

Rationale: The source proves the gap, but the permanent choice affects Gateway RPC shape, row storage/write load, child-session rollup semantics, and the UI reason label contract.

Likely owner: steipete

Owner reason: Recent work by steipete touched the same Control UI session grouping and Gateway row projection surfaces needed for this product decision.

Owner confidence: high

Options:

- **Read-time projection (recommended):** Derive meaningful activity and reason from a bounded recent transcript/event tail plus child metadata, then sort UI surfaces by that projected field without rewriting rows for every qualifying event.
- **Persisted activity fields:** Add durable `lastEventAt`, `lastMeaningfulActivityAt`, and `lastVisibleConversationAt` fields with tested rollup writes and migration or doctor handling.
- **Narrow to discoverability:** Keep ordering on `updatedAt` for now and only improve visible labels/previews in follow-up UI work.

## Reproduction Assessment

Yes. Source inspection is enough to reproduce the current behavior: the Sessions page, Gateway list selection, and active filter compare or project `updatedAt`, and the row contract has no meaningful-activity field.

## Solution Assessment

No autonomous fix is best yet. The maintainable path needs a maintainer decision on read-time projection versus persisted fields and the event taxonomy before implementation.
