## Summary

Keep open: current main still sorts and filters Sessions rows by stored `updatedAt`, while the requested meaningful-activity taxonomy, reason label, and parent/child rollup remain unimplemented and need a maintainer product decision.

## What This Changes

The issue requests a Sessions panel activity model that sorts by human-meaningful activity instead of raw message or bookkeeping timestamps.

## Best Possible Solution

Define a single activity taxonomy and read-time projection for Sessions rows, then expose a bounded sort key and reason label through Gateway to the Control UI without adding heartbeat-driven parent-row write churn.

## Reproduction Assessment

Yes by source inspection for the current behavior: current main still defaults the Sessions page to `updated` descending and both UI and Gateway list paths compare `updatedAt`. This is a feature/UX request rather than a violation of a documented current contract.

## Solution Assessment

Unclear until maintainers decide the taxonomy and projection shape. A read-time, capped recent-event projection looks safer than persisted parent rollup writes, but the exact activity classes and UI reason labels need product ownership.
