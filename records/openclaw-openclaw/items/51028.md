## Summary

Keep open: current main and the latest release still sort/filter the Sessions panel from stored `updatedAt`, and the requested meaningful-activity projection, reason label, and parent/child rollup semantics remain unimplemented. The split label/readability issue is closed separately and does not cover this ordering work.

## What This Changes

The issue requests changing the Sessions panel to rank sessions by meaningful activity instead of raw message/update timestamps, with optional parent/child rollup and visible reason labels.

## Best Possible Solution

Define a gateway-owned activity projection with explicit reason codes and parent/child rollup semantics, then expose it through `sessions.list` for Control UI sorting without overloading `updatedAt`.

## Reproduction Assessment

Yes, at source level. Current main defaults the Sessions page to the `updated` sort, compares `row.updatedAt`, and server-side session listing/active filtering use entry `updatedAt`; no live UI run was performed in this read-only review.

## Solution Assessment

Unclear. The user problem is valid, but the proposed persisted `lastMeaningfulActivityAt` may not be the best implementation after the write-amplification concern, so maintainers should choose the activity taxonomy and projection strategy first.
