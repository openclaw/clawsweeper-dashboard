## Summary

Keep open: current main and the latest release still sort and filter Sessions rows by `updatedAt`, while `lastInteractionAt` is only a reset-freshness signal and no current Sessions row/protocol/UI surface exposes `lastMeaningfulActivityAt`, a reason label, or parent/child activity rollup.

## What This Changes

Request the Sessions panel to sort and explain rows by last meaningful human-facing activity, excluding heartbeat/background noise and rolling child activity up to parents.

## Best Possible Solution

Define a read-efficient meaningful-activity projection for session rows, with explicit event taxonomy, parent/child rollup semantics, and a UI reason label while preserving `updatedAt` for raw bookkeeping where needed.

## Reproduction Assessment

Yes. Source inspection on current main shows `sessions.list` projects, filters, and the UI sorts by `updatedAt`, with no row/protocol field carrying `lastMeaningfulActivityAt` or a reason label.

## Solution Assessment

Unclear. The requested direction is coherent, but maintainers need to choose the event taxonomy and read-time versus persisted projection before implementation.
