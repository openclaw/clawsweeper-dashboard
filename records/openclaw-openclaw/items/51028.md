## Summary

Keep open: current main still sorts Sessions rows by `updatedAt` and lacks the requested meaningful-activity timestamp, reason label, and parent/child activity projection; the remaining design is product-sensitive because persisted rollups could add write churn on noisy paths.

## What This Changes

Request to sort the Control UI Sessions panel by human-meaningful activity with reason labels and parent/child rollup instead of raw row update or last-message timestamps.

## Best Possible Solution

Define a maintainer-approved read-time activity projection over recent events or transcripts, expose bounded timestamp/reason fields through `sessions.list`, and render them in the Sessions UI without heartbeat-driven parent-row writes.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Sessions sorting use a read-time meaningful-activity projection, a persisted activity/rollup field, or keep `updatedAt` ordering with narrower UI improvements?

Rationale: The code path is clear, but the activity taxonomy, parent/child rollup semantics, and stable `sessions.list` contract shape are product/API choices that automation should not decide.

Likely owner: steipete

Owner reason: The strongest current ownership signal is recent work on the Gateway session-list projection and session row contract that this decision would change.

Owner confidence: medium

Options:

- **Prefer read-time projection (recommended):** Derive `lastMeaningfulActivityAt` and a reason label from a capped recent-events/transcript tail so noisy background paths do not constantly rewrite parent session rows.
- **Persist activity fields:** Add stored activity fields and parent rollup with explicit migration, write-amplification limits, and tests for noisy heartbeat/cron/sub-agent traffic.
- **Keep updatedAt for now:** Leave ordering unchanged and pursue narrower display improvements while collecting more evidence about the event taxonomy users need.

## Reproduction Assessment

Yes, by source inspection: current main still defaults the Sessions page to `updated` descending and both UI and Gateway list paths compare `updatedAt`. This is a feature/UX request rather than broken documented behavior.

## Solution Assessment

Unclear until maintainers choose the taxonomy and projection shape. A read-time bounded activity projection looks safer than persisted parent rollup writes, but that product/API choice needs ownership.
