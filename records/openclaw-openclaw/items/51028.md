## Summary

Keep open: current main and latest release still order Sessions surfaces from `updatedAt`, while the requested meaningful-activity sort key, visible reason, and parent/child rollup are not implemented. The source gap is clear, but the activity taxonomy and storage/projection strategy need maintainer direction before a safe fix PR can be scoped.

## What This Changes

Sort the Sessions panel by human-meaningful activity with child rollup and visible reason labels instead of raw updated/message timestamps.

## Best Possible Solution

Define one canonical bounded activity projection for `sessions.list`, expose timestamp plus reason on session rows, roll child activity into parents without background write amplification, and sort all Sessions UI entry points from that projection.
