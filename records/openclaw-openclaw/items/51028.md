## Summary

Keep open: current main and the latest release still rely on `updatedAt` for Sessions ordering and filtering, and they do not expose the requested meaningful-activity timestamp, visible reason, or parent/child rollup. The implementation choice remains a product and storage/projection decision.

## What This Changes

The issue requests sorting the Sessions panel by last meaningful activity, with noisy background events suppressed, child activity rolled up to parents, and a visible reason label per row.

## Best Possible Solution

Define one canonical bounded activity projection for `sessions.list`, expose timestamp plus reason on session rows, roll child activity into parents without background write amplification, and sort all visible Sessions entry points from that projection.

## Maintainer Decision

Question: Should Sessions ordering use a read-time bounded meaningful-activity projection, stored activity timestamp fields with rollups, or keep `updatedAt` ordering for now?

Rationale: The user-visible gap is clear, but the permanent choice affects Gateway RPC shape, row write load, parent/child rollup semantics, and which event classes count as meaningful activity.

Likely owner: steipete

Owner confidence: high

Options:

- **Read-Time Projection (recommended):** Derive the sort key and visible reason from bounded recent event/transcript metadata so noisy background work does not rewrite parent rows just to decide ordering.
- **Persist Activity Fields:** Add stored `lastEventAt`, `lastMeaningfulActivityAt`, and `lastVisibleConversationAt` fields with tested updates, rollups, and migration or doctor handling.
- **Defer Model Change:** Keep `updatedAt` ordering until maintainers approve a broader session activity model and accept the current UX friction in the meantime.
