## Summary

Keep open: current main and v2026.6.11 still order and filter Sessions rows by `updatedAt`, while the requested meaningful-activity taxonomy, child rollup, and reason label remain unimplemented product work.

## What This Changes

Request to make the Sessions panel order by a semantic last-meaningful-activity signal with heartbeat/noise suppression, parent/child rollup, and a visible reason label.

## Best Possible Solution

Choose a bounded read-time activity projection first, then expose it through `sessions.list` and the Control UI while preserving pinned/archive behavior and testing noise suppression plus child rollup.

## Maintainer Decision

Kind: product_direction

Question: What should count as meaningful session activity, and should the Sessions list derive that sort key at read time or persist a new projection?

Rationale: The requested UX is valid, but event classification and parent rollup affect session state semantics and write load, so automation should not choose the permanent product contract alone.

Likely owner: clay-datacurve

Owner reason: The strongest history trail for dashboard session API and session event semantics points to PR #50101 and follow-up commits by clay-datacurve.

Owner confidence: high

Options:

- **Derive At Read Time (recommended):** Compute a bounded meaningful-activity projection from recent transcript/session events for list rows, avoiding parent-row rewrites from background churn.
- **Persist A Projection:** Store `lastMeaningfulActivityAt` and reason metadata only with explicit qualifying write gates and upgrade tests for existing sessions.
- **Keep UpdatedAt Sort:** Leave ordering as-is and limit work to adjacent preview or label polish, accepting that heartbeat/background noise may still affect ordering.
