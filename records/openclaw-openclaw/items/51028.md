## Summary

Keep open: current main and the latest release still expose and sort session rows by `updatedAt`, while the requested meaningful-activity taxonomy, reason label, and parent/child rollup are not implemented and need a product/storage decision first.

## What This Changes

The issue requests Sessions panel ordering by last meaningful human-visible activity, with reason labels and child-session rollup instead of raw message or bookkeeping timestamps.

## Best Possible Solution

Define one shared read-time meaningful-activity projection for `sessions.list`, expose the timestamp and reason in `GatewaySessionRow`, roll child activity into the parent without background write amplification, and sort all Sessions UI entry points from that projection.

Rationale: The current source proves the gap, but the durable product choice affects write load, Gateway RPC shape, child-session rollup semantics, and UI explanation labels.

Likely owner: steipete

Owner reason: Recent session thread-management work spans the Gateway row contract and Control UI session surfaces that would absorb this decision.

Owner confidence: medium

Options:

- **Read-time projection (recommended):** Derive meaningful activity and reason from a bounded recent transcript/event tail plus child metadata, then sort UI surfaces by that projected field without rewriting rows for every qualifying event.
- **Persisted activity fields:** Add durable `lastEventAt`, `lastMeaningfulActivityAt`, and `lastVisibleConversationAt` fields with tested rollup writes and migration/doctor handling.
- **Narrow to previews only:** Leave ordering on `updatedAt` for now and handle only the related preview/timestamp discoverability work in the separate session-list UX item.

Yes, source inspection is enough to reproduce the current behavior: the Sessions page, sidebar recents, picker, and Gateway list selection all compare or project `updatedAt`, and the row contract has no meaningful-activity field.

No, this is not ready for an autonomous fix PR because the issue proposes multiple timestamp tiers and rollup behavior, while the discussion raises a real read-time versus persisted projection tradeoff.
