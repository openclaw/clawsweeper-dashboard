## Summary

Keep open: current main has a denoised `lastActivityAt` field, but the Sessions page, sidebar, and backend list ordering still use `updatedAt`, and the requested parent/child rollup plus reason label remain product-design work.

## What This Changes

The issue requests sorting the Sessions panel by denoised last meaningful activity, with child-session rollup and a visible reason for why a session moved.

## Best Possible Solution

Adopt one documented session-activity projection, likely based on `lastActivityAt`, with read-time child rollup and UI reason labels before changing the default Sessions ordering.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should the Sessions panel default ordering use the existing `lastActivityAt` field, and should child-session activity roll up at read time or through stored parent-row updates?

Rationale: Current main has the raw material for denoised activity, but the taxonomy, rollup behavior, and storage/projection strategy affect session-state semantics and hot-path write/read load.

Likely owner: steipete

Owner reason: Recent Sessions UI grouping and unread-state changes make this the best available owner for the UX/product choice.

Owner confidence: medium

Options:

- **Use read-time projection (recommended):** Sort by a derived activity key from `lastActivityAt` plus recent child rows and expose a reason label without rewriting parent rows for every child event.
- **Persist a rollup field:** Add a stored meaningful-activity sort key with tests for every qualifying event and an explicit migration/write-load plan.
- **Keep updatedAt ordering:** Leave Sessions ordering as pinned/updated recency and document `lastActivityAt` only as unread-state metadata.

## Reproduction Assessment

Yes. Source inspection shows current main exposes `lastActivityAt`, but the Sessions table, sidebar, date grouping, and gateway list window still use `updatedAt`.

## Solution Assessment

Unclear. Reusing `lastActivityAt` is the likely narrow base, but child rollup and reason labels need a maintainer-approved activity taxonomy and projection strategy first.
