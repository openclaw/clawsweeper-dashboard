## Summary

Keep open: current main and v2026.6.11 still project and sort session rows from `updatedAt`, while the requested meaningful-activity timestamp, explanation reason, and parent/child rollup remain unimplemented and need a product/storage decision.

## What This Changes

The issue requests a Sessions panel ordering model based on last meaningful activity instead of raw session-row updates, with visible activity reasons and child-session rollup.

## Best Possible Solution

Define one shared read-time meaningful-activity projection for `sessions.list`, expose timestamp plus reason on `GatewaySessionRow`, roll child activity into parent rows without background write amplification, and sort all Sessions UI entry points from that projection.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Sessions ordering use a read-time meaningful-activity projection or persisted activity timestamp fields, and which event classes count as meaningful activity?

Rationale: Source proves the current gap, but the durable choice affects Gateway RPC shape, row write load, parent/child rollup semantics, UI labels, and compatibility with current `updatedAt` listing/pruning behavior.

Likely owner: steipete

Owner reason: steipete is the strongest recent owner across the Sessions UI, gateway row contract, and session-management surfaces that would absorb this choice.

Owner confidence: high

Options:

- **Read-time projection (recommended):** Derive meaningful activity and reason from bounded recent transcript/event metadata and child rows at list time, avoiding extra writes from noisy background activity.
- **Persisted activity fields:** Add durable `lastEventAt`, `lastMeaningfulActivityAt`, and `lastVisibleConversationAt` fields with tested row updates, rollups, and migration/doctor handling.
- **Narrow UI-only polish:** Keep ordering on `updatedAt` for now and only improve labels/previews, leaving the meaningful-activity model for a later design item.

## Reproduction Assessment

Yes. Source inspection is enough: current main's Sessions page, sidebar recents, Gateway row projection, and Gateway list comparator all use `updatedAt`, and the row contract has no meaningful-activity timestamp or reason field.

## Solution Assessment

No. The issue describes a plausible direction, but the best maintainable fix needs a maintainer decision on read-time projection versus persisted fields before implementation.
