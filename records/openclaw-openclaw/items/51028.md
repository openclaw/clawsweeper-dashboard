## Summary

Keep open: current main still projects and sorts session rows from stored `updatedAt`, and the requested meaningful-activity timestamp, reason label, and parent/child rollup behavior are not implemented. The split label/readability work was closed separately and does not cover this ordering model.

## What This Changes

Request to make the Sessions panel order rows by human-meaningful activity with visible reason labels and parent/child rollup instead of raw `updatedAt` recency.

## Best Possible Solution

Define a bounded, read-efficient session activity projection that ignores heartbeat/internal noise, rolls child activity into parent rows, and exposes a reason label to the Control UI without adding persisted write churn unless maintainers choose and test a migration.

## Reproduction Assessment

Yes, source-reproducible: current main sorts gateway and UI session rows by `updatedAt`, and targeted search found no meaningful-activity projection fields. I did not run a live heartbeat/sub-agent churn scenario.

## Solution Assessment

Unclear: the requested end state is useful, but a stored `lastMeaningfulActivityAt` is not clearly the best implementation until maintainers choose read-time projection versus persisted updates and define the event taxonomy.
