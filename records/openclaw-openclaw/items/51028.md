## Summary

Keep open: current main and the latest release still expose and sort session rows by `updatedAt`, while the requested meaningful-activity timestamp, visible reason, and parent/child rollup remain unimplemented and need a product/storage decision.

## What This Changes

The issue requests that the Sessions panel order rows by human-meaningful activity, suppress heartbeat/internal churn, roll child-session activity into parents, and explain why each row moved.

## Best Possible Solution

Define one canonical bounded activity projection for `sessions.list`, expose timestamp plus reason on `GatewaySessionRow`, roll child activity into parent rows without background write amplification, and sort all Sessions UI entry points from that projection.

Rationale: The source gap is clear, but the durable choice affects Gateway RPC shape, row write load, parent/child rollup semantics, and which event classes count as meaningful.

Options:

- **Read-time projection (recommended):** Derive the sort key and visible reason from bounded recent metadata so noisy background work does not rewrite parent rows just to decide ordering.
- **Persist activity fields:** Add stored `lastEventAt`, `lastMeaningfulActivityAt`, and `lastVisibleConversationAt` fields with tested updates, rollups, and migration/doctor handling.
- **Defer model change:** Keep `updatedAt` ordering until maintainers approve a broader session activity model.
