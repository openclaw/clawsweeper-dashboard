## Summary

Keep open: current main still orders the Sessions surfaces by `updatedAt`, while the requested meaningful-activity sort key, reason label, and parent/child rollup are not implemented. The source gap is clear, but the activity taxonomy and read-time versus persisted rollup strategy need maintainer direction before a safe implementation can be scoped.

## What This Changes

The issue requests that the Sessions panel sort by last meaningful user-visible activity, exclude heartbeat/internal noise, roll child activity up to parents, and show why a row moved.

## Best Possible Solution

Define one canonical session-activity projection for list surfaces, preferably deriving bounded read-time `lastMeaningfulActivityAt` and reason fields from recent user-visible events, then update gateway paging, Control UI sorting, and tests without making background churn rewrite parent rows.
