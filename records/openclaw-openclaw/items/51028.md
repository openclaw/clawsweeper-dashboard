- `impact:session-state`: The issue is about how session freshness, child activity, and activity timestamps are projected into user-facing session state.
- `impact:ux-friction`: The current panel ordering can let heartbeat or background updates obscure real conversations, making the UI harder to trust without fully blocking use.

## Summary

Keep open: current main and the latest release still expose and sort Sessions panel rows by stored `updatedAt`; `lastInteractionAt` exists for reset freshness, but not as the requested meaningful-activity sort key, reason label, or parent/child rollup. The sub-agent label split is already implemented separately, so this issue remains the canonical product/API decision for activity ordering.

## What This Changes

Requests a Sessions panel activity model that sorts by last meaningful activity, explains why a row moved, and rolls relevant child-session activity into parent ordering.

## Best Possible Solution

Define a Gateway-owned activity projection with reason metadata and bounded parent rollup or read-time derivation, then expose it through `sessions.list` and update the Control UI sort and row label behavior.

## Reproduction Assessment

Yes. Source inspection shows current main still sorts, filters, and renders Sessions panel rows by `updatedAt`, while the row contract lacks the requested meaningful-activity timestamp and reason fields.

## Solution Assessment

Unclear. The user problem is well supported, but the proposed stored `lastMeaningfulActivityAt` plus parent rollup is not yet proven to be the best implementation after the write-amplification concern in discussion.
