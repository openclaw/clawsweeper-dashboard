## Summary

Keep open. The unbounded dedupe set is a valid concern, but this cap permanently demotes recovery events from every unseen session after saturation, and the PR provides no required real-behavior proof.

## What This Changes

The PR caps the process-wide set used to deduplicate aggregate tool-result recovery warnings at 512 entries.

## Best Possible Solution

Use bounded FIFO or LRU eviction so old session keys are discarded while every newly encountered session can still emit one warning, with focused saturation and eviction regression coverage.

## Reproduction Assessment

Yes, from source inspection: populate 512 distinct session keys and then process another new key; the changed branch logs that new recovery only at info level and never records the key.

## Solution Assessment

No. A hard stop on recording keys bounds memory but disables warning-level visibility for all later sessions; bounded eviction preserves both memory and deduplication semantics.
