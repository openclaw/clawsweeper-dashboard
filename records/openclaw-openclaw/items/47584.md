## Summary

Keep open: current main and v2026.6.11 still lack a parameterized iOS Siri/App Intent that accepts a dictated OpenClaw question and returns a spoken reply. Existing Talk and Share paths prove gateway messaging pieces exist, but this new native entry point needs maintainer product and security direction before implementation.

## What This Changes

Add native iOS Siri/App Intent support so a dictated question can reach a paired OpenClaw gateway and return a spoken reply.

## Best Possible Solution

Design a first-party iOS App Intent around the paired node/session identity with explicit auth and permission semantics, then prove on a real device that Siri/Shortcuts sends the intended turn and speaks the reply without widening hook credentials.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a new iOS capability request. The current-source check does confirm the absence of an AppIntent/Shortcuts implementation and disabled App Intents metadata on current main.

## Solution Assessment

Unclear: the user problem is valid, but the sample hook-based implementation is not obviously the best boundary. Maintainers should first choose whether Siri sends through paired node identity, `chat.send`, `node.event`/`agent.request`, or a hardened hook path.
