## Summary

Keep open: current main and v2026.6.11 still do not provide a native parameterized Siri/AppIntent flow that accepts a dictated OpenClaw question and returns a spoken reply. The request is useful, but it needs maintainer product and security direction before implementation because the proposed Siri/Shortcuts entry point would initiate Gateway-controlled agent work and must deliberately choose auth, confirmation, and session-routing boundaries.

## What This Changes

The issue requests native iOS Siri/AppIntent support so users can dictate a question to OpenClaw and receive a spoken response without opening the app.

## Best Possible Solution

Define a maintainer-approved iOS AppIntent design that reuses paired-device identity or an explicitly hardened hook boundary, chooses agent/session routing deliberately, handles local confirmation and permissions, and returns spoken replies without bypassing Gateway security controls.

## Reproduction Assessment

Not applicable for a feature request. Source and release inspection show there is no native Ask OpenClaw AppIntent, AppShortcutsProvider, or ProvidesDialog implementation to reproduce today.

## Solution Assessment

Unclear as proposed. Native AppIntent support likely belongs in the iOS app, but directly posting to /hooks/agent is not the best proven boundary until maintainers approve auth, session routing, reply collection, and spoken-dialog behavior.
