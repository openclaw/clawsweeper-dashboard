## Summary

Keep open: current main still lacks a native parameterized Siri/App Intent that accepts a dictated OpenClaw question and returns a spoken reply. The request is valid, but it needs maintainer product and security direction before implementation because it would add a new Siri/Shortcuts entry point into Gateway-backed agent execution.

## What This Changes

The issue requests native iOS Siri/App Intent support so a dictated OpenClaw question can be sent to the paired Gateway and returned as a spoken Siri/Shortcuts reply.

## Best Possible Solution

Define a maintainer-approved iOS App Intent design that reuses paired-device identity or an explicitly secured hook boundary, chooses agent/session routing deliberately, handles local confirmation and permissions, and returns spoken replies without bypassing Gateway security controls.

## Reproduction Assessment

Yes for source state: current main links AppIntents.framework but has no AppIntent/AppShortcutsProvider source implementing the requested native Siri Ask OpenClaw action. This is not a bug reproduction path because the item requests a new feature.

## Solution Assessment

Unclear as proposed. Native App Intent support likely belongs in the iOS app, but directly posting to `/hooks/agent` is not the best proven boundary until maintainers approve auth, session routing, reply collection, and spoken-dialog behavior.
