## Summary

Keep open: current main and the latest release still lack the requested parameterized Siri/App Intent that accepts a dictated OpenClaw question and returns a spoken reply. The open Action Button PR is only a partial overlap, and the remaining work needs maintainer product and security-boundary direction before implementation.

## What This Changes

The issue requests native iOS Siri/App Intent support so users can ask OpenClaw questions through Siri or Shortcuts and receive spoken responses.

## Best Possible Solution

Define a maintainer-approved iOS App Intent design that reuses paired-device identity or a hardened hook boundary, chooses agent/session routing deliberately, handles local permission or confirmation, and returns spoken replies without weakening Gateway controls.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should native Siri/App Intent support send agent requests through the paired iOS node identity, through a hardened /hooks/agent-style token boundary, or stay out of core for now?

Rationale: Current main has both paired-node chat/node-event paths and token-gated hook paths, and the correct boundary affects credentials, local confirmation, session state, and whether OS automations may trigger agent work.

Likely owner: steipete

Owner reason: The likely decision spans iOS AppIntents, Talk Mode, Gateway chat transport, and security defaults where steipete has the strongest feature-history signal.

Owner confidence: high

Options:

- **Use paired-node identity (recommended):** Build the intent around the existing authenticated iOS node/operator session and chat.send or node.event semantics, with explicit local confirmation and session routing.
- **Use hardened hook boundary:** Allow the Siri intent to call a hook-like boundary only after maintainers define token storage, session-key allowlisting, reply collection, and automation permissions.
- **Defer native Siri support:** Keep Shortcuts/webhook or Talk Mode workarounds until iOS voice-entry product direction is clearer.
