## Summary

Keep open: current main and v2026.6.11 still lack a native, parameterized iOS Siri/App Intent that accepts an OpenClaw question and returns a spoken reply. The request is useful and aligned with the iOS companion-app direction, but implementation needs maintainer product and security direction before code work.

## What This Changes

Add native iOS Siri/App Intent support so users can dictate an OpenClaw question through Siri or Shortcuts and receive a spoken reply without opening the app.

## Best Possible Solution

Define a maintainer-approved native iOS App Intent design that reuses paired-device identity or an explicitly hardened hook boundary, chooses agent/session routing deliberately, handles local confirmation and permissions, and returns spoken replies without bypassing Gateway security controls.

## Reproduction Assessment

Not applicable for a feature request. Source and release inspection show there is no native Ask OpenClaw App Intent, AppShortcutsProvider, or ProvidesDialog implementation to reproduce today.

## Solution Assessment

Unclear as proposed. Native App Intent support likely belongs in the iOS app, but directly posting to /hooks/agent is not the best proven boundary until maintainers approve auth, session routing, reply collection, and spoken-dialog behavior.
