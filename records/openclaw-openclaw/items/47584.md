## Summary

Keep open: current main still lacks a native Siri/App Intent that accepts a dictated OpenClaw question and returns a spoken reply, and the related PRs either cover only adjacent Talk-mode launch behavior or are closed unmerged. The request is useful, but it needs maintainer product and security direction before implementation because it would let an OS-level assistant surface initiate agent work against a paired gateway.

## What This Changes

Add native iOS Siri/App Intent support so users can ask OpenClaw a dictated question through Siri or Shortcuts and receive a spoken reply without opening the app.

## Best Possible Solution

Choose a maintainer-approved native iOS AppIntent design that reuses paired device/operator identity, bounded session routing, and explicit reply behavior instead of a broad unattended webhook-style trigger.

## Reproduction Assessment

Not applicable: this is a new native Siri/App Intent feature request, not a broken existing behavior. Source inspection gives high confidence that current main does not implement the requested AppIntent or Shortcuts provider.

## Solution Assessment

No, not as written: posting from the official iOS app to `/hooks/agent` would duplicate a credentialed webhook ingress path and needs a security decision. A better likely direction is a native AppIntent that reuses paired iOS device/operator identity plus existing node event, chat, or Talk RPC boundaries after maintainers choose the reply and session model.
