## Summary

Keep open: current main and v2026.6.11 still lack a native parameterized Siri/App Intent that accepts a dictated OpenClaw question and returns a spoken reply. The request remains useful, but the implementation needs maintainer product and security direction before code work because the proposed hook-based path would expose agent execution through Siri and Shortcuts.

## What This Changes

Request native iOS Siri/App Intent and Shortcuts support that accepts a dictated OpenClaw question, sends it to the paired Gateway, and returns a spoken reply.

## Best Possible Solution

Define a maintainer-approved iOS App Intent design that reuses paired-device identity or an explicitly secured hook boundary, chooses agent/session routing deliberately, handles local confirmation and permissions, and returns spoken replies without bypassing Gateway security controls.

## Reproduction Assessment

Not applicable for a feature request. Source and release inspection show there is no native Ask OpenClaw App Intent, AppShortcutsProvider, or ProvidesDialog implementation to reproduce today.

## Solution Assessment

Unclear as proposed. Native App Intent support likely belongs in the iOS app, but directly posting to /hooks/agent is not the best proven boundary until maintainers approve auth, session routing, reply collection, and spoken-dialog behavior.
