## Summary

The PR addresses a real config/routing regression and includes current-head terminal proof, but its new route shortcut can misroute an explicitly configured agent whose ID normalizes to `main`; repair that edge case before merge.

## What This Changes

The branch accepts exact implicit `main` bindings with a non-empty `agents.list`, preserves them during doctor repair, and resolves matching routes to the main agent.

## Best Possible Solution

Resolve configured normalized agent IDs through the existing lookup first, then fall back to implicit `main` only when no configured normalized match exists; add a focused regression for that collision alongside the exact-main case.
