## Summary

Keep open. Current main still treats `agents.list` as hot-reloadable and logs a successful hot reload, and I did not find a merged canonical fix for per-agent model-primary changes staying stale until restart.

## What This Changes

The issue reports that hot-reloading `agents.<id>.model.primary` in `openclaw.json` does not update running or fresh-thread model resolution until the gateway restarts.

## Best Possible Solution

Preserve the existing `agents.list` hot-reload contract by making new turns and fresh threads resolve per-agent model primary from the refreshed runtime config, with explicit restart-required logging only if in-process refresh is unsafe.

Yes, from source inspection there is a credible reproduction path: change `agents.<id>.model.primary`, trigger the current hot reload, and verify the next turn or fresh thread uses the old model. I did not run a live gateway proof, so confidence is medium rather than high.

## Solution Assessment

Yes, the best fix is to honor the current hot-reload contract by refreshing the stale model-resolution path for future turns and threads. If that proves unsafe, the narrower acceptable fallback is to mark this model change restart-required instead of logging a silent applied reload.
