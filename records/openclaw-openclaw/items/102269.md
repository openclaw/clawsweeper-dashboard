## Label Justifications

- `P2`: This is a normal-priority runtime bug with limited blast radius around model hot reload and session inheritance.
- `impact:session-state`: The reported stale model is carried by persisted session runtime fields and inherited into child sessions.
- `impact:auth-provider`: The affected behavior controls provider/model routing for agent turns after config changes.

## Summary

Keep open: current main updates the runtime config snapshot during reload, but the chat/session path still lets persisted session model fields win over the changed agent default, and parent-created sessions inherit those stale fields.

## What This Changes

Hot-reloading `agents.<id>.model.primary` should affect subsequent turns and fresh threads instead of keeping the pre-reload model.

## Best Possible Solution

Define the hot-reload semantics for agent model changes, then update only default-derived session runtime model state for affected agents and parent-created threads, or make the reload log explicitly say the sticky session model requires a reset or restart.

Options:

- **Apply to unpinned sessions (recommended):** Invalidate or update only default-derived `modelProvider`/`model` state for the affected agent while preserving explicit `providerOverride`/`modelOverride` pins.
- **Warn and preserve stickiness:** Keep current sticky session behavior but change the applied reload message and docs/diagnostics so operators know existing sessions and inherited threads need reset or restart.
- **Close as intentional:** Declare session model stickiness the supported behavior and document that config model changes apply only to sessions without runtime model state.

## Reproduction Assessment

Yes from source inspection: current `chat.send` resolves the model through stored session `modelProvider`/`model` before agent defaults, and `sessions.create` inherits those fields from a parent session. No live gateway repro was run in this read-only review.

## Solution Assessment

No final fix shape is selected yet; committing the runtime config snapshot is necessary but not sufficient because the session-level runtime model fields still outrank the changed agent default. The best fix needs a maintainer decision on sticky-session compatibility versus hot-reload immediacy.
