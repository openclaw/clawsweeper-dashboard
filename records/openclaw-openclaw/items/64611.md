## What This Changes

This PR changes heartbeat task due-time calculation to treat a future `lastRunMs` as due and adds focused `isTaskDue` unit coverage.

## Best Possible Solution

Land the narrow shared-helper guard only after a current-base refresh, real behavior proof, focused heartbeat test pass, and explicit acceptance that `heartbeatTaskState` stores last-run timestamps rather than future deferrals.

## Reproduction Assessment

Yes from source inspection: current main and v2026.6.11 compute `nowMs - lastRunMs` and compare it to the interval, so `isTaskDue(now + 5m, "30m", now)` returns false. I did not run a live NTP or VM-resume scenario in this read-only review.

## Solution Assessment

Yes for the code shape: the shared `isTaskDue` predicate is the narrow owner boundary, while clamping at runner callers would duplicate the rule. The proposed branch is not merge-ready until proof and current-base validation are in place.
