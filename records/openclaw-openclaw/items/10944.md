## Summary

Keep open: current main and the latest release still do not expose the requested Telegram parse/text-mode config, even though current code now has `richMessages` opt-in and internal HTML/rich/plain fallback behavior.

## What This Changes

Request to add top-level and per-account Telegram parse/text-mode configuration so users can choose plain text, HTML, or Markdown-style delivery.

## Best Possible Solution

Define a maintainer-approved Telegram formatting policy in the bundled Telegram plugin, preserve current HTML compatibility by default, and expose only modes with specified escaping, rich-message interaction, docs, and tests.

## Reproduction Assessment

Yes. Source inspection shows top-level and account-level `parseMode` are absent from the strict Telegram schema/types while send, edit, caption, and draft paths choose HTML, rich messages, or plain fallback internally.

## Solution Assessment

Unclear whether the proposed `none | Markdown | HTML` shape is the best permanent API. The safer path is a narrow maintainer-approved formatting policy that preserves current defaults and defines escaping/security behavior for each supported mode.
