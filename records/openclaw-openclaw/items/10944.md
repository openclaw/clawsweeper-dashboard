## Summary

Keep open: current main and v2026.6.11 still lack the requested Telegram top-level or per-account parse/text-mode config; current behavior is `richMessages` plus internal HTML/rich/plain fallback paths.

## What This Changes

Request to add Telegram parse/text-mode configuration, including a possible top-level default and per-account override.

## Best Possible Solution

Define a maintainer-approved Telegram formatting policy in the bundled Telegram plugin, preserve current HTML compatibility by default, and expose only modes whose escaping, rich-message interaction, and client behavior are specified and tested.

## Reproduction Assessment

Yes. Source inspection shows `channels.telegram.parseMode` and account-level `parseMode` are absent from current main and v2026.6.11 schema/types/docs, while delivery paths choose HTML, rich messages, or plain fallback internally.

## Solution Assessment

Unclear whether the proposed `none | Markdown | HTML` shape is the best permanent API. The safer solution is a maintainer-approved formatting policy that preserves current defaults and defines escaping/security behavior for every supported mode.
