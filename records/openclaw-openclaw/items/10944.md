## Summary

Keep open: current main and v2026.6.11 have adjacent Telegram controls like `richMessages` and `markdown.tables`, but they still do not expose the requested public channel/account parse or text-mode selector. The remaining work is a compatibility-sensitive product/security decision, not conservative cleanup.

The issue requests optional Telegram channel and per-account parse/text-mode configuration so users can choose plain text, HTML, or another supported Telegram formatting mode.

## Best Possible Solution

Define a Telegram-owned parse/text-mode contract that preserves the current compatible default, then implement it consistently across config, docs, sends, captions, edits, previews, delivery helpers, metadata, and tests.
