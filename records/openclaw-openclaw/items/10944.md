## Summary

Current main partially addresses this request through account-aware `richMessages` opt-in and compatible standard-text defaults, but it still lacks a supported way to deliberately select plain text or MarkdownV2. That remaining capability is source-proven and useful, yet its public config shape and safety semantics require maintainer direction.

## What This Changes

Add a channel-level and optional per-account Telegram setting for selecting outbound text rendering instead of relying only on the built-in rendering mode.

## Best Possible Solution

Use one account-aware Telegram rendering policy: retain standard rendered text as the safe default, add an explicit plain-text choice only if maintainers approve it, and design MarkdownV2 or raw HTML separately with clear escaping and trust contracts.

Options:

- **Add safe plain mode (recommended):** Evolve the existing account-aware rendering policy to support standard text, plain text, and rich messages while retaining standard text as the default.
- **Keep automatic fallback:** Leave plain text as parse-error recovery and fix individual formatter defects without adding another setting.
- **Add broad parse modes:** Support MarkdownV2 or raw HTML only after approving explicit escaping, trust, and compatibility semantics.

## Reproduction Assessment

Yes. Current source and docs show account-aware rich-message selection and error-triggered plain fallback, but no supported config that deliberately selects plain text or MarkdownV2 at channel or account scope.

## Solution Assessment

No. A standalone `parseMode` enum is not yet the best design because it overlaps with `richMessages`; the narrow maintainable direction is one canonical rendering policy with safe defaults and parity across every Telegram outbound funnel.
