## Summary

Keep open: current main and v2026.6.11 expose Telegram `richMessages` and `markdown.tables`, but they still do not provide a supported `parseMode` or equivalent plain/MarkdownV2/HTML text-mode config. The source gap is real, but adding this public Telegram config surface needs maintainer product direction before a fix PR is safe.

## What This Changes

The issue requests a Telegram channel/account parse-mode setting so users can choose plain text, Markdown-style formatting, or HTML instead of the plugin choosing formatting internally.

## Best Possible Solution

Decide the Telegram text-mode contract, then implement it inside the bundled Telegram plugin with current HTML compatibility preserved as the default and consistent wiring through sends, captions, draft previews, schema metadata, docs, and tests.

- **Keep existing richMessages-only surface:** Close or defer parseMode and document `richMessages: false` plus current HTML/plain fallback as the supported compatibility path.
- **Broaden into a formatting-design issue:** Convert this into a larger maintainer-owned design covering MarkdownV2, raw entities, rich messages, custom emoji, and per-account behavior together.

## Reproduction Assessment

Yes, source-reproducible for the missing config surface: current schemas, types, docs, and send/draft paths expose `richMessages` and `markdown.tables` but no `parseMode`. This is not a failing-runtime bug reproduction; it is proof that the requested feature remains absent.

## Solution Assessment

Unclear until maintainers choose the product contract. The right boundary is likely the Telegram plugin config surface, but current `richMessages` only covers rich Bot API opt-in and does not answer plain text, MarkdownV2, default, or per-account parse-mode policy.
