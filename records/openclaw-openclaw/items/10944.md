## Summary

Keep open: current main and v2026.6.11 have Telegram `richMessages` and `markdown.tables`, but still do not expose the requested public plain/HTML/Markdown parse-mode config; adding that config is a Telegram product/security decision, not conservative cleanup.

## What This Changes

The issue requests a supported Telegram channel parse/text-mode config, including optional per-account overrides, so users can choose plain text, Markdown, or HTML-style rendering.

## Best Possible Solution

Define the Telegram plugin's supported text-mode contract first, then wire the chosen mode consistently through config schema/types/metadata, outbound sends, media captions, streaming previews, docs, and focused Telegram formatting tests.

- **Design full parse-mode support:** Sponsor a broader Telegram contract for HTML, MarkdownV2, custom emojis/entities, escaping, fallback behavior, and live proof expectations.

Yes. Source inspection reproduces the missing capability because the strict Telegram schema and exported config types have `richMessages` and `markdown.tables`, but no public parse-mode field.

## Solution Assessment

Unclear until maintainers choose the public contract. The best implementation would be plugin-owned and consistent across send, caption, preview, and rich/plain fallback paths rather than a one-path send option.
