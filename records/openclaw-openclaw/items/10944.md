## Summary

Keep open. Current main and the latest release still lack a supported Telegram parse/text-mode config surface; the existing `richMessages` option and HTML/plain fallbacks solve adjacent delivery and rich-formatting cases but do not provide the requested top-level or per-account parse-mode selection.

## What This Changes

Request to add a configurable Telegram parse/text mode, potentially at both channel and account scope, instead of forcing outbound formatting choices internally.

## Best Possible Solution

Add a maintainer-approved Telegram formatting policy in the bundled Telegram plugin, likely as typed parse/text-mode config wired through send, edit, media-caption, draft-preview, outbound-adapter, docs, metadata, and tests, with `richMessages` interaction and escaping/security semantics explicit.

## Reproduction Assessment

Yes. Source inspection is high confidence: `channels.telegram.parseMode` and per-account `parseMode` are absent from the strict Telegram schema/types in current main and v2026.6.11, while delivery paths choose HTML, rich messages, or plain fallback internally.

## Solution Assessment

Unclear whether the exact proposed `none | Markdown | HTML` shape is the best permanent API. The safer solution is a maintainer-approved Telegram formatting policy that preserves current HTML defaults, keeps rich messages explicit, and only exposes modes whose escaping and client behavior are well defined.
