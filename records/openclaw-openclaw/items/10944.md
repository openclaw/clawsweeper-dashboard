## Summary

Keep open: current main and v2026.6.11 still have Telegram `richMessages` and per-send formatting plumbing, but no supported top-level or per-account Telegram parse/text-mode config that solves the requested operator control.

## What This Changes

The issue requests a configurable Telegram parse/text mode, including an optional per-account override, so users can choose plain text, HTML, or Markdown-style delivery behavior.

## Best Possible Solution

Add a maintainer-approved Telegram text/parse-mode config in the Telegram plugin, with a safe default, clear account inheritance, consistent send/edit/caption/preview wiring, docs, schema metadata, and focused tests.

## Reproduction Assessment

Yes, source inspection is enough to reproduce the gap: current schema/types/docs expose `richMessages` and per-send formatting behavior, but not the requested `channels.telegram.parseMode` or account-level `parseMode` config.

## Solution Assessment

Unclear until maintainers decide the product shape; a parse/text-mode config may be right, but the safe implementation needs explicit choices about defaults, supported modes, escaping, account inheritance, and interaction with `richMessages`.
