## Summary

Keep open: current main and the latest release have adjacent Telegram controls like `richMessages` and `markdown.tables`, but they still do not expose the requested public parse/text-mode selector for plain, HTML, Markdown, or MarkdownV2 delivery.

## What This Changes

The issue requests a public Telegram channel configuration surface for selecting parse/text mode globally and optionally per account.

## Best Possible Solution

Define a Telegram-owned parse/text-mode contract that preserves the current default, then implement it consistently across schema, exported types, generated metadata, docs, sends, captions, edits, previews, and focused tests.
