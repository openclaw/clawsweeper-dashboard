## Summary

Keep open: current main and v2026.6.11 still do not expose the requested Telegram parse/text-mode selector at channel or account scope. Existing `richMessages` and `markdown.tables` controls are adjacent, but this remains a public config and rendering-policy decision rather than conservative cleanup.

## What This Changes

The issue requests a Telegram channel/account parse-mode configuration so users can choose plain text, Markdown-style formatting, or HTML instead of relying on the current internal send mode.

## Best Possible Solution

Define a Telegram-owned parse/text-mode contract that preserves the current compatible default, then implement it consistently across config, docs, sends, captions, edits, previews, delivery helpers, metadata, and tests.
