## Summary

Keep open: current main and v2026.6.11 expose adjacent Telegram controls like `richMessages` and `markdown.tables`, but still do not expose the requested public parse/text-mode selector for plain, HTML, Markdown, or MarkdownV2 delivery.

## What This Changes

The issue requests a configurable Telegram parse/text mode, including top-level and per-account overrides for plain text, HTML, or Markdown-style delivery.

## Best Possible Solution

Define a Telegram-owned parse/text-mode contract that preserves the current default, then implement it consistently across schema, exported types, generated metadata, docs, sends, captions, edits, previews, and focused tests.
