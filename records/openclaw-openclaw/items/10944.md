## Summary

Keep open: current main and the latest release still do not expose the requested Telegram parse/text-mode config, while `richMessages` and `markdown.tables` only cover adjacent rich-message and table-format behavior.

## What This Changes

The issue requests a Telegram channel/account config option to choose plain text, HTML, Markdown, or similar parse-mode behavior for outbound Telegram rendering.

## Best Possible Solution

Keep this open for a Telegram plugin config-design decision, then implement the approved text/parse-mode contract across schema, types, account inheritance, sends, captions, edits, previews, docs, metadata, and focused tests while preserving current default behavior unless maintainers choose a migration.
