## Summary

Keep open: current main and the latest release still lack the requested supported Telegram parse/text-mode configuration, even though `richMessages` now handles the Telegram Web compatibility workaround as a separate opt-in surface.

## What This Changes

The issue requests top-level and per-account Telegram `parseMode` configuration so operators can choose plain text, Telegram Markdown, or Telegram HTML formatting.

## Best Possible Solution

Define a maintainer-approved Telegram formatting policy in the bundled Telegram plugin, keep current HTML compatibility and `richMessages` defaults intact, and expose only modes whose escaping, fallback, and client behavior are documented and tested.

## Reproduction Assessment

Yes. Source inspection shows `channels.telegram.parseMode` and account-level `parseMode` are absent from the strict Telegram schema/types on current main and v2026.6.11, while delivery paths choose HTML, rich messages, or plain fallback internally.

## Solution Assessment

Unclear whether the proposed `none | Markdown | HTML` shape is the best permanent API. The safer solution is a maintainer-approved formatting policy that preserves current defaults and defines escaping/security behavior for every supported mode.
