## Summary

Keep open: current main and v2026.6.11 still do not expose a public Telegram parseMode or equivalent channel/account text-mode config, even though newer rich-message compatibility work solved the narrower Telegram Web unsupported-message regression.

## What This Changes

The issue requests a configurable Telegram message parse mode at channel and per-account scope.

## Best Possible Solution

Approve one narrow Telegram plugin text-mode contract, preserve current standard HTML-compatible behavior by default, and wire the selected setting consistently through sends, captions, edits, streaming previews, schema/types, generated metadata/help, docs, and focused tests.

- **Decline Parse-Mode Config For Now:** Keep the existing richMessages and markdown.tables knobs and continue fixing formatter-specific issues without adding another public config surface.

## Reproduction Assessment

Yes for the source-level feature gap: current main accepts richMessages and markdown.tables but no parseMode key, while Telegram outbound paths still choose HTML, rich, or plain fallback internally. I did not run live Telegram proof because this is a public config-surface request, not a deterministic current-runtime bug report.

## Solution Assessment

Unclear until maintainers choose the public contract. A config setting is plausible, but the safest supported values and default behavior depend on product and security decisions around Telegram plain text, HTML, rich messages, MarkdownV2, raw HTML, and entity handling.
