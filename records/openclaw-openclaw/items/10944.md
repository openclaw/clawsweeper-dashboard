## Summary

Keep open: current main and v2026.6.11 have `richMessages` plus internal HTML/rich/plain fallback behavior, but still do not provide the requested top-level or per-account Telegram parse/text-mode configuration.

## What This Changes

The issue requests a configurable Telegram parse/text mode, including top-level and optional per-account overrides, instead of forcing one outbound formatting policy.

## Best Possible Solution

Define a maintainer-approved Telegram formatting policy in the bundled Telegram plugin, preserve current HTML compatibility by default, and expose only modes whose escaping, rich-message interaction, and client behavior are specified and tested.

## Reproduction Assessment

Yes. Source inspection shows `channels.telegram.parseMode` and account-level `parseMode` are absent from the strict Telegram schema/types on current main and v2026.6.11, while delivery paths choose HTML, rich messages, or plain fallback internally.

## Solution Assessment

Unclear whether the proposed `none | Markdown | HTML` shape is the best permanent API. The safer solution is a maintainer-approved formatting policy that preserves current defaults and defines escaping/security behavior for every supported mode.
