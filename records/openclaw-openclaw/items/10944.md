## Summary

Keep open: current main and v2026.6.11 still do not expose the requested Telegram parse/text-mode config, while the existing `richMessages` and `markdown.tables` settings cover adjacent rich-message and table-format behavior rather than a supported parse-mode selector.

## What This Changes

Request adds a Telegram channel and optional per-account `parseMode` configuration for plain, Markdown, or HTML delivery behavior.

## Best Possible Solution

Keep this open for a Telegram plugin config-design decision, then implement the approved text/parse-mode contract across schema, types, account inheritance, sends, captions, edits, previews, docs, generated metadata, and focused tests while preserving current default behavior unless maintainers choose a migration.
