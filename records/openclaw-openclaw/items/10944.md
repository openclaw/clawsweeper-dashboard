## Summary

Keep open: current main and v2026.6.11 still do not expose the requested Telegram parse/text-mode config, and the existing `richMessages` plus `markdown.tables` knobs only solve adjacent formatting and rich-message compatibility cases.

## What This Changes

The issue requests a public Telegram channel/account `parseMode` setting so users can choose plain text, HTML, or Markdown-style delivery instead of relying on internal hardcoded formatting choices.

## Best Possible Solution

Keep this open for a Telegram plugin config-design decision, then implement the approved text/parse-mode contract across schema/types, sends, captions, edits, previews, docs, and focused tests while preserving current HTML-compatible behavior by default unless maintainers choose a migration.
