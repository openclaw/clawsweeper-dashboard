## Summary

Keep open: current main and v2026.6.11 still lack the requested Telegram parse/text-mode config, while the existing `richMessages` and `markdown.tables` settings only cover adjacent rich-message and table-formatting behavior.

## What This Changes

The issue requests a configurable Telegram parse/text mode at channel and per-account scope so users can choose plain text, HTML, or markdown-style formatting instead of the plugin choosing transport formatting internally.

## Best Possible Solution

Approve a narrow Telegram plugin text-mode contract, then wire it through schema/types, sends, captions, edits, previews, metadata/docs, and tests while keeping the current HTML-compatible default unless maintainers intentionally choose a migration.
