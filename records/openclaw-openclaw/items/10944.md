## Summary

Keep open: current main and v2026.6.11 still lack the requested public Telegram `parseMode` or equivalent channel/account text-mode config; this remains a product/config-surface decision rather than an implemented feature.

## What This Changes

The issue requests a Telegram channel/account `parseMode` config so users can choose plain text, HTML, or Markdown-style rendering instead of relying on OpenClaw's internal Telegram formatting mode.

## Best Possible Solution

Keep this open for Telegram plugin config design; preserve current standard HTML/plain fallback behavior by default, then wire the approved parse/text-mode contract through schema, exported types, docs, send, captions, edits, previews, and focused tests.
