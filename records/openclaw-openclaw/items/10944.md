## Summary

Keep open. Current main documents a `richMessages` toggle between standard HTML delivery and Telegram rich messages, but still lacks the requested plain-text or general formatting-mode selector. The narrower rich-message compatibility work does not resolve this broader request, and recent v2026.7.1 feedback shows continuing formatting friction; maintainers must choose the supported modes and precedence before implementation.

## What This Changes

Add top-level and optionally per-account Telegram formatting configuration so operators can select plain text, standard HTML, or a Markdown mode.

## Best Possible Solution

Keep standard HTML as the compatibility default, repair any current conversion regression independently, and—if maintainers approve a new setting—add one Telegram-owned formatting contract with a safe plain-text option, explicit `richMessages` precedence, complete send/edit/preview/caption coverage, generated schema metadata, public docs, tests, and live Telegram proof.

## Reproduction Assessment

Not applicable as a single runtime bug, but the requested capability gap is source-reproducible: current Telegram configuration documents HTML and `richMessages` behavior without a plain or general parse-mode selector. The separate v2026.7.1 raw-Markdown symptom has not been reproduced here.

## Solution Assessment

Unclear until maintainers choose the public contract. A narrow HTML/plain selector is safer than the proposed unrestricted mode set, while the recent raw-Markdown behavior should be fixed at its root rather than hidden behind configuration.
