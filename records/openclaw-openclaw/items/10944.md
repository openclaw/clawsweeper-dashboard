## Summary

Keep open for a maintainer product decision. Current documentation still describes one Telegram outbound formatting path—Telegram-safe HTML with a plain-text retry—and does not document a supported global or per-account formatting-mode selector; the issue’s original Markdown baseline is outdated, but its central request remains unmet. The richer Telegram delivery work in https://github.com/openclaw/openclaw/pull/92679 improved rendering and delivery, not a stable user-configurable formatting contract.

## What This Changes

Add a Telegram channel setting, optionally overridable per account, to choose how outbound replies are formatted and parsed.

## System Context

The bundled Telegram plugin turns agent replies into Telegram delivery payloads for final messages, edits, captions, and streamed previews. Channel configuration feeds this formatting and delivery path, which then calls Telegram Bot API methods and presents the rendered reply to chat users.

## Best Possible Solution

Define one Telegram formatting policy in the bundled Telegram plugin: retain the current safe default, choose the supported alternative modes and escaping guarantees, specify top-level versus account precedence, and apply it consistently to final sends, edits, captions, and previews with focused configuration and delivery coverage.
