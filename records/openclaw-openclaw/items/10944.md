## Summary

Keep open: current main and the latest stable release expose `richMessages` and `markdown.tables`, but still do not expose the requested public Telegram `parseMode` or equivalent channel/account text-mode config. The remaining work is a Telegram plugin product/API decision about supported modes, defaults, and escaping/security behavior.

## What This Changes

The issue requests an optional Telegram channel and per-account parse-mode configuration so users can choose plain text, HTML, Markdown, or related Telegram formatting behavior.

## Best Possible Solution

Keep this open until maintainers choose the Telegram text/parse-mode contract; then implement the approved channel/account setting through schema, types, docs, metadata, sends, captions, edits, previews, and tests while preserving the current default unless a migration is explicitly chosen.
