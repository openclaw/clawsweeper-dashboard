## Summary

Keep open: current main and v2026.6.11 still expose `richMessages` and internal HTML/plain fallback behavior, but no supported top-level or per-account Telegram parse/text-mode config. The remaining decision is a public config and formatting-policy choice, not conservative cleanup.

## What This Changes

The issue requests a Telegram `parseMode` configuration surface, optionally per account, to choose plain text, Markdown, or HTML-style delivery.

## Best Possible Solution

Define a maintainer-approved Telegram formatting policy in the bundled Telegram plugin, preserve current HTML compatibility by default, and expose only modes whose escaping, rich-message interaction, docs, and tests are specified.
