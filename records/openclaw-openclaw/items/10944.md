## Summary

Keep open. Current main and the latest release still lack a supported Telegram parse-mode/plain-text config surface; `richMessages` is an adjacent opt-in for Bot API rich text and does not provide the requested top-level or per-account formatting mode selection.

## What This Changes

Requests a `channels.telegram.parseMode` setting, with optional per-account override, to choose Telegram plain text, Markdown, or HTML formatting behavior.

## Best Possible Solution

Define a maintainer-approved Telegram formatting policy in the bundled Telegram plugin, preserve current HTML compatibility by default, and wire any selected parse/text-mode config consistently through send, edit, caption, preview, schema, docs, metadata, and tests.

## Reproduction Assessment

Yes. Source inspection is high confidence: current main and `v2026.6.11` lack `channels.telegram.parseMode` and per-account `parseMode`, while Telegram delivery paths choose HTML, rich messages, or plain fallback internally.

## Solution Assessment

Unclear whether the exact proposed `none | Markdown | HTML` enum is the best permanent API. The safer solution is a maintainer-approved Telegram formatting policy that preserves current defaults, keeps `richMessages` interaction explicit, and exposes only well-defined modes.
