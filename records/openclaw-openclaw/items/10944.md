## Summary

Keep open: current main and v2026.6.11 still do not provide a supported Telegram `parseMode` or equivalent text-mode config, and the remaining work is a public Telegram formatting/config policy decision rather than conservative cleanup.

## What This Changes

The issue requests a supported Telegram channel/account parse-mode configuration so users can choose plain text, HTML, or Markdown-style rendering instead of relying on OpenClaw's current Telegram formatting modes.

## Best Possible Solution

Keep this open for a Telegram plugin config-design decision that wires any approved mode consistently across sends, captions, edits, draft previews, generated metadata/help, docs, and tests.

- **Keep existing knobs only:** Use `richMessages`, `markdown.tables`, and targeted formatter fixes instead of adding a parse-mode config surface.

## Reproduction Assessment

Yes for the source-level gap: current main exposes `markdown` and `richMessages` but no `parseMode` field, while Telegram send/edit/preview paths still derive HTML/rich/plain behavior from internal options and `richMessages`. ## Solution Assessment

Unclear as an implementation direction: a public config is plausible, but the best supported values and defaults are a product/security decision because Telegram plain text, HTML, rich messages, MarkdownV2, raw HTML, and entity handling have different compatibility and escaping tradeoffs.
