## Summary

Keep open: current main and v2026.6.11 still expose `richMessages` and `markdown.tables`, but no public Telegram `parseMode` or equivalent text-mode config, so the central request remains a product/config decision rather than conservative cleanup.

## What This Changes

The issue requests a configurable Telegram parse mode, optionally at both channel and account level, so users can choose plain text, Markdown, or HTML behavior for Telegram output.

## Best Possible Solution

Keep this open for a Telegram plugin config-design decision, then add the approved text-mode contract to schema/types/docs and wire it consistently through sends, captions, edits, previews, metadata, and focused tests while preserving the current default unless maintainers choose a migration.
