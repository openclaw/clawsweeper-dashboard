## Summary

Keep open: current main and the latest release still do not expose the requested Telegram parse/text-mode config, and the remaining decision is which public modes and defaults OpenClaw should support.

## What This Changes

The issue requests a top-level and per-account Telegram `parseMode` setting so users can choose plain text, HTML, or Markdown-style delivery instead of accepting the built-in Telegram renderer choice.

## Best Possible Solution

Have a maintainer choose the supported Telegram text-mode contract, then implement it in the Telegram plugin across schema/types/metadata/docs plus sends, edits, captions, draft previews, and focused tests while keeping the default backward-compatible.
