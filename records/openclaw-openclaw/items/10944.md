## Summary

Keep open: current main and v2026.6.11 still expose Telegram `richMessages` and internal HTML/rich/plain fallback behavior, but they do not provide the requested top-level or per-account parse/text-mode configuration.

## What This Changes

The issue requests a Telegram channel configuration surface for parse/text mode, including optional top-level and per-account overrides for plain text, Markdown-style formatting, or HTML.

## Best Possible Solution

Define a maintainer-approved Telegram formatting policy in the bundled Telegram plugin, preserve current HTML compatibility by default, and expose only the modes whose escaping, rich-message interaction, and client behavior are explicitly specified and tested.

## Reproduction Assessment

Yes. Source inspection shows `channels.telegram.parseMode` and account-level `parseMode` are absent from the strict Telegram schema/types on current main and v2026.6.11, while delivery paths choose HTML, rich messages, or plain fallback internally.

## Solution Assessment

Unclear whether the proposed `none | Markdown | HTML` shape is the best permanent API. The safer solution is a maintainer-approved formatting policy that preserves current defaults and defines escaping/security behavior for every supported mode.
