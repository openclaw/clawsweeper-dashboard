## What This Changes

The issue requests a configurable Telegram parse/text mode, including a possible per-account override, so users can choose plain text, Markdown-style, or HTML-style rendering instead of only OpenClaw's built-in Telegram formatting behavior.

## Best Possible Solution

Keep this issue open for a Telegram plugin config-design decision, then implement the approved text/parse-mode contract across schema, types, sends, captions, edits, previews, docs, and tests while preserving current defaults unless maintainers choose a migration.
