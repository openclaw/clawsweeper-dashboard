## Summary

Keep open: current main and v2026.6.11 have `richMessages`, `markdown.tables`, and per-message internal HTML handling, but they still do not expose the requested public Telegram `parseMode` or equivalent channel/account text-mode config.

## What This Changes

The issue asks for a Telegram channel and per-account `parseMode` config so users can choose plain text, Markdown-style formatting, or HTML behavior instead of relying on hardcoded outbound formatting.

## Best Possible Solution

Keep this open for a Telegram plugin config-design decision; the approved text/parse-mode contract should preserve current HTML-compatible behavior by default unless maintainers choose a migration, then wire the setting through sends, captions, edits, previews, schema/types, metadata/help, docs, and focused tests.
