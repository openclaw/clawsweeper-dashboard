## Summary

Keep open: current main and v2026.6.11 still have `richMessages` plus internal HTML/rich/plain fallback behavior, but no supported top-level or per-account Telegram parse/text-mode config.

## What This Changes

The issue requests a supported Telegram parse/text-mode configuration, including optional per-account override, so users can choose plain text, Markdown, or HTML instead of relying on the channel's hardcoded formatting behavior.

## Best Possible Solution

Define a maintainer-approved Telegram formatting policy, preserve current HTML compatibility by default, and wire only explicitly supported modes through schema/types, docs, sends, edits, captions, previews, and tests.

## Reproduction Assessment

Yes. Source inspection is high confidence: `channels.telegram.parseMode` and per-account `parseMode` are absent from the strict Telegram schema/types in current main and `v2026.6.11`, while delivery paths choose HTML, rich messages, or plain fallback internally.

## Solution Assessment

Unclear whether the exact proposed `none | Markdown | HTML` shape is the best permanent API. The safer solution is a maintainer-approved Telegram formatting policy that preserves current HTML defaults, keeps rich messages explicit, and only exposes modes whose escaping and client behavior are well defined.
