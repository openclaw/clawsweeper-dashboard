## Summary

Keep open: current main still lacks the requested Telegram parse/text-mode configuration, and the remaining work is a public Telegram config contract decision rather than a cleanup-close candidate.

## What This Changes

The issue requests a configurable Telegram parse/text mode, including top-level and per-account options, so users can choose plain text, Markdown, or HTML behavior instead of relying on OpenClaw's internal Telegram rendering choice.

## Best Possible Solution

Keep this issue open for a Telegram plugin config-design decision, then implement the approved text/parse-mode contract consistently across schema, types, sends, captions, edits, previews, docs, metadata, and focused tests while preserving current HTML-compatible behavior by default unless maintainers choose a migration.
