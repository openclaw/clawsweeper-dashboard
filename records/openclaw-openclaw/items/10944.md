## Summary

Keep open: current main and v2026.6.11 have adjacent Telegram controls such as richMessages and markdown.tables, but still do not expose the requested public parse/text-mode selector for plain, HTML, Markdown, or MarkdownV2 delivery.

## What This Changes

The issue requests a Telegram channel parse-mode configuration, including possible top-level and per-account overrides for plain text, Markdown, or HTML delivery.

## Best Possible Solution

Decide a narrow Telegram-owned text-mode policy first, then implement it consistently across config schema/types, account inheritance, final sends, captions, drafts, progress previews, docs, and focused Telegram tests while preserving the current compatible default.
