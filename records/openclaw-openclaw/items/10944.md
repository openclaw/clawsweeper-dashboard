## Summary

Current main and v2026.6.11 still lack a persistent Telegram parse/text-mode selector; adjacent rich-message and per-message controls do not fully satisfy the request, and the permanent values, precedence, and trust semantics require maintainer product judgment.

## What This Changes

Add a persistent Telegram parse/text-mode setting at channel scope with an optional per-account override.

## Best Possible Solution

Define one narrowly named, inherited Telegram text-delivery policy with a safe current default, explicit channel/account/per-message precedence, and consistent fallback behavior across every delivery funnel; treat MarkdownV2 or raw HTML as separate trust-sensitive decisions.

Options:

- **Narrow safe policy (recommended):** Add inherited current-HTML versus plain-text delivery, preserve current behavior as the default, and define typed per-message precedence.
- **Full parse modes:** Expose direct Telegram modes including MarkdownV2 or raw HTML with complete escaping, trust-boundary, fallback, documentation, and live-client proof.
- **Decline new config:** Keep the existing rich-message and per-message controls, document them clearly, and address concrete formatter defects separately.

## Reproduction Assessment

Yes. Current source directly shows that the persistent channel/account selector is absent and that standard delivery uses HTML rendering with plain fallback.

## Solution Assessment

No for the original three-value shape. A narrower delivery-policy model is more maintainable because it can distinguish safe rendered text from native rich messages and trust-sensitive raw modes.
