## Summary

Keep open: current main and v2026.6.11 still only support static mention/always group activation plus adjacent ambient room events, not the requested LLM-driven peeking/engaged state machine. The remaining work is a product and security-boundary decision, not conservative cleanup.

## What This Changes

The issue requests an LLM-driven contextual activation mode for Telegram and WhatsApp groups with peeking, engaged/disengaged state, model fallbacks, scheduling, decision history, logs, and CLI observability.

## Best Possible Solution

Define a default-off, consent-aware design that chooses core versus plugin/API ownership, reuses ambient room primitives where possible, and specifies provider exposure, retention/logging, config migration, channel coverage, and proof requirements before implementation.
