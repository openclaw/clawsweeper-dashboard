## Summary

Keep open: current main and v2026.6.11 still only expose static mention/always group activation plus adjacent ambient-room/history behavior, not the requested LLM-driven peeking/engaged contextual activation. This remains a product, privacy, provider, config, logging, and channel/API boundary decision rather than conservative cleanup.

## What This Changes

The issue requests a default-off contextual group activation mode for WhatsApp and Telegram that uses a lightweight decision model, fallback chain, decision history, scheduling, and peeking/engaged state to decide when unmentioned group messages should wake the agent.

## Best Possible Solution

Define a maintainer-sponsored, default-off group activation contract with explicit privacy, provider, logging, state, and channel/plugin API semantics before implementing any Telegram or WhatsApp integration.
