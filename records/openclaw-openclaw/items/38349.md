## Summary

Keep open: current main and v2026.6.11 still lack the requested LLM-driven peeking/engaged group activation mode. Existing ambient room events cover a useful adjacent always-on quiet-context workflow, but they do not provide the requested cheap decision model, fallback chain, engagement state, scheduling, or decision-log contract, so the remaining work is a maintainer product and security-boundary decision.

## What This Changes

Request to add contextual activation for Telegram and WhatsApp group chats using a lightweight decision model, fallback models, peeking/engaged state, scheduling, decision history, structured logs, and a CLI viewer.

## Best Possible Solution

Define a default-off, consent-aware design that chooses core versus plugin/API ownership, reuses ambient room primitives where appropriate, and specifies provider exposure, retention/logging, config migration, channel coverage, and proof requirements before implementation.
