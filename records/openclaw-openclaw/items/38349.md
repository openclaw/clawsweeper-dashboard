## Summary

Keep open: current main and v2026.6.11 still provide static mention/always group handling, skipped-message history, and adjacent observability work, but not the requested LLM-driven peeking/engaged contextual activation mode. The remaining work is a product, privacy, provider, config, and channel/API boundary decision rather than conservative cleanup.

## What This Changes

The issue requests a default-off contextual group activation mode for WhatsApp and Telegram that lets a lightweight model decide when the agent should peek, engage, disengage, log decisions, and use fallback decision models without explicit mentions.

## Best Possible Solution

Define a maintainer-sponsored, default-off group activation contract that preserves group allowlists and mention-gating safety, then implement it through the right shared channel/plugin SDK seam or explicitly decide to keep it out of core.
