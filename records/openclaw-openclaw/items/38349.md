## Summary

Keep open: current main and the latest release still lack the requested LLM-driven peeking/engaged group activation mode, and the remaining choice is a product, privacy, security, and ownership decision rather than conservative cleanup.

## What This Changes

The issue requests an LLM-driven contextual activation mode for Telegram and WhatsApp groups that can observe unmentioned chatter, decide when to engage, manage engaged/peeking state, and expose config, logs, and CLI visibility.

## Best Possible Solution

Define a default-off, consent-aware design that decides core versus plugin/API ownership, reuses ambient room primitives where possible, and specifies provider exposure, retention/logging, config migration, channel coverage, and proof requirements before implementation.
