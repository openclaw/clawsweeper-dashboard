## Summary

Keep open: current main and the latest release still only support static `mention` and `always` group activation, while this asks for a new LLM-driven cross-channel state machine with provider, config, logging, privacy, and message-delivery implications. Related items cover narrower attention-window, context-window, and passive-observation pieces, but none is a merged replacement for the requested design.

## What This Changes

Request to add configurable LLM-driven contextual activation for Telegram and WhatsApp groups, including peeking/engaged state, decision model fallbacks, decision history, schedules, logs, and a CLI viewer.

## Best Possible Solution

Keep this as a maintainer product/security design item and choose a narrow path, likely an API/plugin seam or scoped attention-window design, before adding any core config, model routing, state, or logging surface.

## Reproduction Assessment

Not applicable: this is a feature request, not a current-main bug reproduction. Source and release inspection confirm the requested contextual mode is absent and current behavior remains static `mention`/`always` activation.

## Solution Assessment

Unclear: the requested design is plausible but not yet the best proven shape because it bundles cross-channel activation, model routing, state, logs, and CLI surface. A narrower plugin/API seam, passive inbound hook, or attention-window design may be safer once maintainers decide the security model.
