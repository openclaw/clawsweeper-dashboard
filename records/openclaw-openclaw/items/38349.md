## Summary

Keep open: current main and v2026.6.11 still only support static mention/always group activation, not the requested LLM-driven peeking/engaged contextual activation mode. The remaining work is a product/security/API boundary decision, especially because it would observe unmentioned group traffic, call a decision model, add config surface, and log decisions.

## What This Changes

The issue requests an LLM-driven contextual activation mode for Telegram and WhatsApp groups with peeking/engaged state, model fallback, scheduling, history-aware decisions, and decision-log observability.

## Best Possible Solution

A maintainer-owned design should either add a generic, opt-in plugin/channel ingress seam first and let contextual activation live as a plugin, or explicitly approve a core opt-in mode with privacy, provider, logging, config, and migration rules.
