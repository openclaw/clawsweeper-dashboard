## Summary

Keep this PR open for normal merge review. The branch uses the shared bounded-response reader to cap Slack’s successful `response_url` inspection and supplies focused stalled/oversized-body coverage plus a real loopback proof; current main does not contain this bound.

## What This Changes

The PR changes Slack slash-command reply handling so inspection of a successful `response_url` response is limited to 16 KiB and 30 seconds, allowing the native-block fallback decision to finish instead of waiting indefinitely.

## System Context

Slack slash-command replies are sent through Slack’s `response_url`; when a native chart or table is rejected, the reply layer inspects the successful response body to decide whether to send a text fallback. This change sits between the response transport and fallback delivery, constraining the diagnostic read before the delivery loop proceeds.
