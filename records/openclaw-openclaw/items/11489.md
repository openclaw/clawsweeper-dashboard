## Label Justifications

- `P2`: This is a normal-priority cross-channel security and group-admission feature with meaningful design impact, while existing allowlist and disabled modes already prevent unauthorized group execution.
- `impact:security`: The issue is about approving or rejecting untrusted groups before a bot can engage there.
- `impact:session-state`: The proposed pending approvals and reader-agent mode would add authorization state that controls which group contexts can reach an agent.

## Summary

Keep open: current main and the latest release still keep pairing scoped to DMs, while group admission remains open, allowlist, or disabled. The related Telegram and WhatsApp items overlap with unknown-group handling and audit visibility, but they do not replace the requested cross-channel owner-notified group approval flow or pending read-only mode.

## What This Changes

Add cross-channel group pairing so newly added groups stay unprocessed pending owner notification, approve/reject, and optional read-only pending-group routing.

## Best Possible Solution

Define a shared group-admission contract first: fail closed by default, store pending approvals by channel/account/group, send redacted owner notifications, authorize approve/reject operations, and scope reader-agent observation as a separate explicit mode.

## Reproduction Assessment

Yes at source level, not as a bug: current main keeps group policies to open, allowlist, or disabled and keeps pairing on the DM path only.

## Solution Assessment

No current implementation is best yet. The maintainable path is a product/security-reviewed group admission contract rather than stretching DM pairing or merging narrower channel-specific proposals independently.
