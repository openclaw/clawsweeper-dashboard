## Summary

Keep open: current main and v2026.6.11 still keep pairing scoped to DMs while group admission is open, allowlist, or disabled. The related Telegram and WhatsApp items overlap, but none replaces the requested cross-channel owner-notified group approval flow with pending read-only mode.

## What This Changes

The issue requests a cross-channel group pairing flow with owner notification, group approve/reject controls, and an optional read-only reader-agent mode for unconfigured groups.

## Best Possible Solution

Define a shared group admission contract that fails closed by default, stores pending approvals by channel/account/group, sends redacted owner notifications, authorizes approve/reject operations, and scopes reader-agent observation as a separate explicit mode.

## Reproduction Assessment

Yes at source level, not as a bug: current main keeps group policies to open/allowlist/disabled and keeps pairing on the DM path only. The requested group approval, owner notification, and pending reader-agent state are absent from the inspected config, runtime, CLI, docs, and tests.

## Solution Assessment

No current implementation is best yet. The maintainable path is a product/security-reviewed group admission contract rather than stretching DM pairing or merging narrower channel-specific proposals independently.
