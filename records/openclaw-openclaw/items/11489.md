## Label Justifications

- `P2`: This is a normal-priority security and channel-admission feature, while existing allowlist and disabled modes already block unauthorized group execution.
- `impact:security`: The issue is about approving or rejecting untrusted groups before the bot engages and limiting prompt-injection exposure from shared rooms.

## Summary

Keep open: current main and v2026.6.11 still keep pairing on the DM path while group admission is open, disabled, or allowlist-only. The related Telegram and WhatsApp items are narrower mitigations, not a replacement for owner-notified cross-channel group approval and pending read-only routing.

## What This Changes

Requests a new group pairing flow with owner notification, group approve/reject controls, and optional read-only handling for unconfigured Telegram and WhatsApp groups.

## Best Possible Solution

Define a product/security-reviewed shared group admission contract that stores pending approvals by channel/account/group, sends redacted owner notifications, authorizes approve/reject operations, and treats read-only observation as an explicit isolated mode unless maintainers fold it into the same contract.
