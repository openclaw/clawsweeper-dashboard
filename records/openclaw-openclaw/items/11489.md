## Label Justifications

- `P2`: This is a normal-priority security and channel-admission feature while existing allowlist and disabled modes already prevent unauthorized group execution.
- `impact:security`: The issue asks for approving or rejecting untrusted groups before the bot engages and for reducing prompt-injection exposure from shared rooms.

## Summary

Keep open: current main still keeps pairing on the DM path and group admission on open/disabled/allowlist policy, so owner-notified group approval, group approve/reject operations, and pending read-only group routing remain unimplemented. The merged pairing hook and the open Telegram/WhatsApp group-security items are useful adjacent work, but none supersede this broader cross-channel contract.

## What This Changes

Requests a cross-channel group pairing flow that notifies the owner, stores pending group approval state, adds approve/reject controls, and optionally routes unconfigured groups through read-only observation.

## Best Possible Solution

Define a product/security-reviewed group admission contract that stores pending approvals by channel/account/group, sends redacted owner notifications, authorizes approve/reject operations, and treats read-only observation as an explicit isolated mode unless maintainers fold it into the same contract.
