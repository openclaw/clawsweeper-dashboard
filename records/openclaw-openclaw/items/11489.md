## Summary

Keep open: current main and v2026.6.11 still keep pairing scoped to DMs, while group admission remains allowlist/open/disabled only. Related Telegram/WhatsApp/access-request work overlaps, but none implements owner-notified group approval, pending group state, or read-only unconfigured-group routing.

## What This Changes

The issue requests group pairing, owner notification, approve/reject controls, and optional read-only handling for unconfigured Telegram/WhatsApp groups.

## Best Possible Solution

Define a product/security-reviewed group admission contract that stores pending approvals by channel/account/group, sends redacted owner notifications, authorizes approve/reject operations, and treats read-only reader-agent observation as a separately explicit isolated mode.

## Solution Assessment

No current implementation is best yet. The maintainable path is a shared product/security-reviewed group admission contract rather than stretching DM pairing or landing narrower channel-specific proposals independently.
