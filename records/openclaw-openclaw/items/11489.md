## Summary

Keep open: current main still keeps pairing scoped to DMs while group admission is open, allowlist, or disabled; related Telegram and WhatsApp items overlap but do not replace the requested cross-channel owner-notified approval flow or pending read-only mode.

## What This Changes

Request group pairing for Telegram/WhatsApp-style group chats, with owner notification, approve/reject controls, and optional read-only pending-group handling.

## Best Possible Solution

Define a shared group-admission contract first: fail closed by default, store pending approvals by channel/account/group, send redacted owner notifications, authorize approve/reject operations, and scope reader-agent observation as a separate explicit mode.

## Reproduction Assessment

Yes at source level, not as a bug: current main keeps group policies to open, allowlist, or disabled and keeps pairing on the DM path only.

## Solution Assessment

No current implementation is best yet. The maintainable path is a product/security-reviewed group admission contract rather than stretching DM pairing or merging narrower channel-specific proposals independently.
