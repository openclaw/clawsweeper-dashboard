## Label Justifications

- `impact:security`: The issue is about approving or rejecting untrusted groups before a bot can engage there.

## Summary

Keep open: current main and v2026.6.11 still keep pairing scoped to DMs and group admission limited to open, allowlist, or disabled; related open work covers DM pairing hooks or Telegram unknown-group warn/leave, not the requested cross-channel group approval flow with owner notification and pending read-only mode.

## What This Changes

The issue requests a cross-channel group pairing mode with owner notifications, approve/reject controls, and optional read-only handling for unconfigured groups.

## Best Possible Solution

Define a shared group-admission contract first: fail closed for pending groups, persist approvals by channel/account/group, send redacted owner notifications, authorize approve/reject operations, and scope reader-agent observation as a separate explicit mode.

## Reproduction Assessment

Yes, at source level: current main keeps group policies to open, allowlist, or disabled and keeps pairing on the DM path only. This is a feature request rather than a broken existing behavior reproduction.

## Solution Assessment

No current implementation is best yet. The maintainable path is a product/security-reviewed group admission contract rather than stretching DM pairing or merging narrower channel-specific proposals independently.
