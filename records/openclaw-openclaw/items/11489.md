## Summary

Keep open: current main and v2026.6.11 still keep pairing scoped to DMs while group admission is open, allowlist, or disabled; related Telegram/WhatsApp items overlap but do not replace the requested cross-channel owner-notified group approval flow and pending read-only mode.

## What This Changes

The issue requests a group pairing policy with owner notification, approve/reject controls, and optional read-only pending-group routing for Telegram and WhatsApp groups.

## Best Possible Solution

Define a shared group-admission contract first: fail closed by default, store pending approvals by channel/account/group, send redacted owner notifications, authorize approve/reject operations, and scope reader-agent observation as a separate explicit mode.

## Reproduction Assessment

Yes, at source level: current main keeps group policies to open, allowlist, or disabled and keeps pairing on the DM path only. This is a feature request rather than a broken existing behavior reproduction.

## Solution Assessment

No current implementation is best yet. The maintainable path is a product/security-reviewed group admission contract rather than stretching DM pairing or merging narrower channel-specific proposals independently.
