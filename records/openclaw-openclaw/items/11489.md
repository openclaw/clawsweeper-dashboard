## Summary

Keep open: current main still has DM-only pairing and group admission remains open, disabled, or allowlist-based, so owner-notified group approval and pending read-only group handling remain unimplemented. The merged channel-pairing hook is useful adjacent work, but it observes newly created DM pairing requests and does not add group approval state or group join notifications.

## What This Changes

Request adds a cross-channel group pairing flow with owner notification, approve/reject controls, and optional read-only handling for unconfigured groups.

## Best Possible Solution

Define a product/security-reviewed group admission contract that stores pending approvals by channel/account/group, sends redacted owner notifications, authorizes approve/reject operations, and treats read-only observation as an explicit isolated mode unless maintainers fold it into the same contract.
