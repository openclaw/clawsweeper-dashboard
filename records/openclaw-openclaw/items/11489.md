## Summary

Keep open: current main still keeps pairing scoped to DMs while group admission remains open, allowlist, or disabled. The related Telegram and WhatsApp items overlap on unknown-group security posture, but none replaces this broader owner-notified group approval and pending read-only mode request.

## What This Changes

Request a cross-channel group pairing flow that notifies the owner, supports group approve/reject, and optionally routes unconfigured groups through a read-only reader-agent.

## Best Possible Solution

Define a shared group admission contract that fails closed by default, stores pending approvals by channel/account/group, sends redacted owner notifications, authorizes approve/reject operations, and scopes reader-agent observation as a separate explicit mode.

## Reproduction Assessment

Yes, at source level rather than as a bug: current main keeps group policies to open, allowlist, or disabled and keeps pairing on the DM path only.

## Solution Assessment

No current implementation is best yet. The maintainable path is a product/security-reviewed shared group admission contract rather than stretching DM pairing or merging channel-specific proposals independently.
