## Summary

Keep open: current main still scopes pairing to DMs and group admission to open, allowlist, or disabled behavior; related items are narrower and do not replace the broader cross-channel owner-notified group approval request.

## What This Changes

The issue requests a group pairing flow with owner notification, approve/reject controls, and optional read-only pending-group handling for unconfigured groups.

## Best Possible Solution

Define a product/security-reviewed group admission contract that stores pending approvals by channel/account/group, sends redacted owner notifications, authorizes approve/reject operations, and treats read-only reader-agent observation as a separately explicit isolated mode.

## Reproduction Assessment

Yes, at source level: current main keeps group policies to open, allowlist, or disabled and keeps pairing on the DM path only. This is a feature absence rather than a broken existing-behavior bug reproduction.

## Solution Assessment

No current implementation is best yet. The maintainable path is a shared product/security-reviewed group admission contract rather than stretching DM pairing or landing narrower channel-specific proposals independently.
