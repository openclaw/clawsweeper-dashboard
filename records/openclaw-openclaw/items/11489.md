## Label Justifications

- `P2`: This is a normal-priority security and operator-control feature because existing allowlist and disabled policies already prevent unauthorized group execution.
- `impact:security`: The request changes authorization for newly added groups and whether unapproved content can reach agent processing.
- `impact:session-state`: The proposed reader mode could introduce unapproved group messages into persistent agent or transcript context.

## Summary

Current main and v2026.6.11 still provide DM pairing plus open, disabled, or allowlist group admission—not owner-approved group pairing. The merged pairing-request hook is a useful notification primitive but remains tied to DM request creation, while the open grouped access-request PR only partially overlaps and is not a safe canonical replacement.

## What This Changes

Add cross-channel group pairing with owner notification, approve/reject controls, and optional restricted processing while a group awaits approval.

## Best Possible Solution

Define an additive shared group-approval state keyed by channel, account, and group, let channel plugins detect joins and render notifications, and drop all unapproved content before agent execution; consider restricted observation later as a separate, explicitly secured mode.
