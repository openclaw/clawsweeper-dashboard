## Summary

Keep open: current main and v2026.6.11 still keep pairing on the DM path while group admission remains open, disabled, or allowlist-only. The related Telegram/WhatsApp items overlap on safer unknown-group handling, but none owns the broader owner-notified group approval state or pending read-only contract.

## What This Changes

The issue requests a group pairing flow with owner notification, approve/reject controls, and optional pending read-only handling for unconfigured Telegram/WhatsApp-style groups.

## Best Possible Solution

Define a product/security-reviewed group admission contract that stores pending approvals by channel/account/group, sends redacted owner notifications, authorizes approve/reject operations, and treats read-only observation as a separate explicit isolated mode unless maintainers fold it into the same contract.
