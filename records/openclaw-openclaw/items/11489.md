## Label Justifications

- `P2`: This is a normal-priority security and channel-admission enhancement while existing allowlist and disabled modes already prevent unauthorized group execution.
- `impact:security`: The issue asks OpenClaw to approve or reject untrusted groups before the bot engages and to reduce prompt-injection exposure from shared rooms.
- `impact:session-state`: The requested pending approvals and reader-agent mode would introduce durable authorization/session state for which group contexts may reach an agent.

## Summary

Keep open: current main still implements DM-only pairing plus group allowlist/open/disabled admission, so owner-notified group approval, group approve/reject operations, and pending read-only group routing remain missing.

## What This Changes

The issue requests a cross-channel group pairing flow with owner notification, approve/reject controls, and optional read-only handling for unconfigured groups.

## Best Possible Solution

Define a shared group admission contract that stores pending approvals by channel/account/group, sends redacted owner notifications, authorizes approve/reject operations, and treats read-only observation as an explicit isolated mode unless maintainers include it in the same contract.
