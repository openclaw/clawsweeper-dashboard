## Label Justifications

- `P2`: This is a normal-priority security and channel-admission feature, while existing allowlist and disabled modes already block unauthorized group execution.
- `impact:security`: The issue is about approving or rejecting untrusted groups before the bot engages and limiting prompt-injection exposure from shared rooms.

## Summary

Keep open: current main and v2026.6.11 still keep pairing scoped to DMs, while group admission remains open, disabled, or allowlist-only with no owner-notified pending group approval or read-only pending-group contract.

## What This Changes

The issue requests a cross-channel group pairing flow that notifies the owner when a bot is added to a group, blocks normal processing until approval, and optionally supports read-only pending-group observation.

## Best Possible Solution

Define a product/security-reviewed group admission contract that stores pending approvals by channel/account/group, sends redacted owner notifications, authorizes approve/reject operations, and treats read-only observation as a separate explicit isolated mode unless maintainers fold it into the same contract.
