## Label Justifications

- `P2`: This is a normal-priority security and channel-admission feature while existing allowlist and disabled modes already prevent unauthorized group execution.
- `impact:security`: The issue asks for approving or rejecting untrusted groups before the bot engages and for reducing prompt-injection exposure from shared rooms.

## Summary

Keep open: current main still has DM-only pairing and group admission remains open, disabled, or allowlist-based, so owner-notified group approval and pending read-only group handling remain unimplemented. Related Telegram, WhatsApp, and pairing-hook work is useful adjacent work but does not own the shared group-admission contract.

## What This Changes

Request group pairing for Telegram and WhatsApp groups with owner notification, approve/reject flow, and optional read-only pending-group routing.

## Best Possible Solution

Define a product/security-reviewed group admission contract storing pending approvals by channel/account/group, sending redacted owner notifications, authorizing approve/reject operations, and treating read-only observation as an explicit isolated mode unless folded into the same contract.
