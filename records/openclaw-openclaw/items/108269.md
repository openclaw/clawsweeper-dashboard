## Label Justifications

- `P2`: The gap causes repeated unwanted agent turns and token usage in active Mattermost threads, but it is an opt-in policy improvement rather than an unusable core workflow.
- `impact:ux-friction`: Operators cannot stop automatic thread participation through supported configuration and must disable or restart the bot to recover.

## Summary

Keep open: Mattermost currently treats bot participation as an implicit mention without the Slack-style opt-out, and the supplied production report shows concrete unwanted replies and token usage. The request is bounded and directionally aligned, but adding another channel configuration surface needs explicit Mattermost owner sponsorship.

## What This Changes

Add an opt-in `channels.mattermost.thread.requireExplicitMention` setting, including per-account resolution, so prior bot participation does not bypass mention gating when enabled.

## Best Possible Solution

Add the plugin-owned opt-in setting at top-level and per-account scope, preserve the existing false/unset default, propagate the resolved value into mention gating, and cover validation plus first-message and engaged-thread behavior in focused Mattermost tests and docs.
