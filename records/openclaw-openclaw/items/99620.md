## Summary

Keep open. Current main and the latest release still have the source-level separator-loss path described here, and the related open Anthropic replay PR may overlap but is not a merged or explicit closure for this silent-yield variant.

## What This Changes

The issue asks OpenClaw to prevent Anthropic replay from collapsing a silent NO_REPLY/sessions_yield separator into an adjacent tool-use assistant turn with multiple signed thinking blocks.

## Best Possible Solution

Make this the canonical NO_REPLY/runtime-context separator-loss issue, then fix both Anthropic request builders or the shared replay sanitizer so silent separator removal cannot produce provider-visible assistant content with multiple signed thinking blocks before tool_use, coordinated with https://github.com/openclaw/openclaw/pull/99383.

## Reproduction Assessment

Yes, at source level: current main contains the silent-token strip, historical runtime-context strip, and Anthropic signed-thinking serialization pieces needed for the reported request shape. I did not run a live Anthropic API reproduction in this read-only pass.

## Solution Assessment

Unclear as an implementation choice: dropping the earlier thinking block, preserving an explicit separator, or landing the broader completed-turn replay scoping from https://github.com/openclaw/openclaw/pull/99383 could each solve parts of the issue. Maintainers should choose the provider-safe policy and require focused tests plus live Anthropic proof for the chosen shape.
