## Label Justifications

- `merge-risk: 🚨 compatibility`: The patch silently changes established `resetAt` semantics from the upcoming monthly boundary to the current period’s start.

## Summary

Current main treats the month in ClawRouter’s budget `windowKey` as the active ledger month and exposes `resetAt` as the next reset boundary. For a July window, August 1 matches the shared formatter; this PR instead returns July 1, which is already past for almost the entire window and would display the budget as resetting “now.” The linked issue and PR should remain open while the contributor supplies authoritative ClawRouter contract evidence or revises the change.

## What This Changes

The PR subtracts one from the parsed `YYYY-MM` month before constructing ClawRouter monthly usage and billing reset timestamps, and changes the July fixture from August 1 to July 1.

## Best Possible Solution

Preserve the next-month reset boundary for a calendar-month ledger key, or update the parser only after authoritative ClawRouter API/source evidence proves that `YYYY-MM` names the upcoming reset month; regression coverage should assert the user-visible formatted reset as well as the raw timestamp.
