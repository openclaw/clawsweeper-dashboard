## Summary

Keep open: the previous P1 blocker remains. The no-op listener prevents an unhandled child-process error, but it still lets the managed update path report a started handoff and schedule restart when the detached helper failed to spawn, and the PR still lacks real OpenClaw handoff proof.

## What This Changes

The PR adds a ChildProcess `error` listener to the managed-service update handoff detached spawn and updates the Vitest spawn mock to expose `on`.

## Best Possible Solution

Wait for the helper child to emit `spawn` or `error` before returning `started`, reject async helper-spawn failure through the existing failed-handoff path, and add focused regression coverage plus redacted OpenClaw terminal or log proof.
