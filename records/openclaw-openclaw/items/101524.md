## Summary

Keep open. Current main still has the async detached-spawn crash path, but this PR is not merge-ready because the no-op listener can turn a failed helper spawn into a reported started managed-service handoff and gateway restart.

## What This Changes

The PR adds a no-op child-process error listener to the managed-service update handoff spawn and updates the adjacent Vitest spawn mock.

## Best Possible Solution

Wait for the detached helper to either emit `spawn` or `error` before reporting `started`, route async spawn failure through the existing failed-handoff path, and cover that behavior with focused tests and redacted OpenClaw proof.
