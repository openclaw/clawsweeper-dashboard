## Summary

Keep this PR open but not merge-ready: the no-op listener prevents the unhandled ChildProcess crash, but it also lets a failed helper spawn be reported as a started managed-service handoff and the PR still lacks OpenClaw-specific after-fix proof.

## What This Changes

The PR adds a no-op ChildProcess `error` listener before `unref()` in the managed-service update handoff spawn and updates the Vitest spawn mock to expose `on`.

## Best Possible Solution

Wait for the helper child to emit `spawn` or `error` before returning `started`, reject on async spawn failure through the existing `managed-service-handoff-failed` path, and add focused regression coverage plus redacted OpenClaw terminal or log proof.

No. The no-op listener is a plausible crash mitigation, but it is not the best fix because this handoff has a documented failed-spawn response path that should be preserved before reporting success.
