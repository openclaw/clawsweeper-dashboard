## Summary

Keep open. Current main and v2026.6.11 still load skills from `SKILL.md` roots and same-name replacement precedence only; the requested per-skill user preference sidecar remains a valid feature gap that needs a maintainer product/API decision.

## What This Changes

Request first-class per-skill user preferences or conventions that load with a selected skill without overriding the whole `SKILL.md` or using global context files.

## Best Possible Solution

Define one maintainer-approved per-skill preference contract, ideally a small markdown sidecar loaded with the selected skill and covered by prompt-version, watcher, security, and docs behavior.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw support a first-class per-skill user preference sidecar, and if so should the public contract be markdown sidecar, structured skill config, or no core support?

Rationale: The feature is missing in source, but adding it changes public skill loading, prompt composition, snapshot invalidation, and docs behavior rather than fixing an already-defined bug.

Likely owner: steipete

Owner reason: The freshest checked history and issue timeline point to steipete around grouped skill loading, docs, and skill config decisions.

Owner confidence: high

Options:

- **Standardize markdown sidecar (recommended):** Add a documented `preferences.md` or `conventions.md` sidecar that loads with the selected skill, lower precedence than `SKILL.md`, and participates in prompt-version, watcher, and security behavior.
- **Use structured skill config:** Keep preferences under `skills.entries.*.config` and require each skill or plugin to interpret them, avoiding markdown prompt composition at the cost of weaker natural-language convention support.
- **Decline core support:** Keep the current model of full skill overrides, Skill Workshop proposals, or global context files if maintainers do not want another skill-loading surface.

## Reproduction Assessment

Yes, as a source-level feature gap: current main and v2026.6.11 discover and prompt `SKILL.md` files only, with no supported `preferences.md` or `conventions.md` sidecar path.

## Solution Assessment

Unclear until maintainers choose the product contract. A markdown sidecar fits the reported natural-language convention use case, but the loader, watcher, snapshot, security, and docs behavior need an explicit API decision first.
