## Summary

Keep open. Current main and v2026.6.11 still expose skill roots through `SKILL.md`, same-name replacement, and structured `skills.entries` config only; the requested per-skill markdown preference sidecar remains a real product/API decision.

## What This Changes

The issue requests a standard per-skill user preference or conventions file that loads only when the related skill is used.

## Best Possible Solution

Define one maintainer-approved per-skill preference contract, preferably a markdown sidecar if natural-language conventions are accepted, and cover loader, prompt-version, watcher, security, sandbox, and docs behavior together.
