## Summary

Keep open. Current main and the latest release still treat `SKILL.md` as the loadable skill unit, replace same-named skills by source precedence, and do not define a supported `preferences.md` or `conventions.md` sidecar; this remains a product/API decision for the skills contract rather than an implemented feature.

## What This Changes

Request to add a supported skill-scoped user preferences or conventions contract that loads with an activated skill without overriding `SKILL.md` or putting skill-specific guidance in global context files.

## Best Possible Solution

Define one maintainer-approved skill preference contract covering filename, precedence, root containment, prompt-versioning, watcher invalidation, docs, and tests before implementing the loader change.

## Reproduction Assessment

Yes, as a source-level feature gap. Current main and `v2026.6.11` still load `SKILL.md` as the skill unit and do not support a `preferences.md` or `conventions.md` sidecar contract.

## Solution Assessment

Unclear. A markdown sidecar is plausible, but maintainers still need to choose the canonical filename, precedence, refresh behavior, security boundary, and whether this belongs in loader behavior or another documented skill/config contract.
