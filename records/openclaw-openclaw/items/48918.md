## Summary

Keep open. Current main and v2026.6.11 still load skills as `SKILL.md` units with replacement-style source precedence and no supported `preferences.md` or `conventions.md` sidecar, so this remains a real skill-loading product/API decision.

## What This Changes

The issue requests a supported user-level skill preference or convention file that is loaded only when the corresponding skill is used.

## Best Possible Solution

Define one maintainer-approved skill preference contract covering filename, precedence, root containment, prompt-versioning, watcher refresh, docs, and focused tests before implementation.

## Reproduction Assessment

Yes, as a source-level feature gap: current main still loads `SKILL.md` as the skill unit and has no supported `preferences.md` or `conventions.md` sidecar contract. This is not a failing bug reproduction because the issue asks for new supported behavior.

## Solution Assessment

Unclear. A markdown sidecar is plausible, but maintainers still need to choose the canonical filename, precedence, refresh behavior, security boundary, and whether this belongs in loader behavior or a different documented skill/config contract.
