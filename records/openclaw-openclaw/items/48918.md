## Summary

Keep open. Current main and the latest release still expose skills as `SKILL.md`-centered prompt resources, with replacement-by-precedence and no supported `preferences.md` or `conventions.md` sidecar, so this remains a real feature/product decision rather than conservative cleanup.

## What This Changes

Requested support for per-skill user preference or convention files that load only when the matching skill is triggered.

## Best Possible Solution

Define one maintainer-approved per-skill preference contract covering filename or config shape, precedence, containment, prompt-version invalidation, docs, and regression tests before implementing loader behavior.
