## Summary

Keep open. Current main and v2026.6.11 still treat skills as `SKILL.md` records with replacement-style source precedence and no supported `preferences.md` or `conventions.md` sidecar, so this remains a real skill-loading product/API decision rather than a cleanup close.

## What This Changes

Request support for user-scoped per-skill preference or convention files loaded only when the matching skill is used.

## Best Possible Solution

Define one maintainer-approved skill preference contract covering filename, precedence, root containment, prompt-versioning, watcher refresh, docs, and focused tests before implementation.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Which public contract should OpenClaw support for user-scoped skill preferences, if any: a markdown sidecar beside the skill, a structured config surface, or no core contract?

Rationale: The choice changes skill precedence, prompt snapshots, watcher invalidation, config surface area, and security/root-containment behavior, so implementation should wait for maintainer product/API direction.

Likely owner: steipete

Owner confidence: high

Options:

- **Approve markdown sidecar (recommended):** Standardize a markdown preference sidecar and require loader, prompt-version, watcher, docs, and regression-test coverage.
- **Use structured config:** Model preferences as canonical configuration and require schema, docs, and doctor/migration decisions before implementation.
- **Keep agent-managed convention only:** Do not add a core contract and document that users should keep conventions inside custom skills or skill-owned docs.
