## Summary

Keep open. Current main and v2026.6.11 still load and version skills around `SKILL.md`, replace same-named skills by source precedence, and document only structured per-skill config; there is no supported `preferences.md` or `conventions.md` sidecar loaded only when a skill triggers, so this remains a maintainer product/API decision.

## What This Changes

Request first-class user-level skill preferences or conventions that load only with the relevant skill instead of overriding `SKILL.md` or using global context.

## Best Possible Solution

Define one maintainer-approved skill preference contract covering filename, precedence, root containment, prompt versioning, watcher or snapshot invalidation, docs, and focused tests.

## Reproduction Assessment

Yes. Source inspection shows current main loads and versions `SKILL.md` only, while docs and schema have no supported `preferences.md` or `conventions.md` sidecar contract.

## Solution Assessment

Unclear. A markdown sidecar is plausible, but maintainers still need to choose the canonical filename, precedence, refresh behavior, security boundary, and whether the contract belongs in loader behavior or structured config.
