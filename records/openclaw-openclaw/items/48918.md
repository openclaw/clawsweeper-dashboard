## Summary

Keep open. Current main and v2026.6.11 still treat `SKILL.md` as the skill unit and do not support a `preferences.md` or `conventions.md` sidecar loaded only with the matching skill; the issue remains a product/API decision rather than a narrow repair.

## What This Changes

The issue asks OpenClaw to support user-level, per-skill preference or convention files that load only when the matching skill is triggered.

## Best Possible Solution

Define one maintainer-approved per-skill preference contract with filename or config shape, precedence, prompt-version invalidation, docs, and regression tests before implementing loader behavior.

Question: Should OpenClaw standardize a markdown per-skill preference sidecar, use structured `skills.entries.*.config`, or keep this as an unsupported user/ClawHub convention?

Rationale: The feature changes the public skill loading and prompt contract, including precedence, context injection, snapshot invalidation, and config policy, so code cannot safely choose the permanent shape on its own.

Likely owner: steipete

Owner confidence: high

Options:

- **Standardize markdown sidecars (recommended):** Adopt a canonical `preferences.md` or `conventions.md` file, load it with the selected skill, and include it in watcher/version/docs/tests.
- **Use structured skill config:** Route per-skill user preferences through the existing `skills.entries.<key>.config` shape and document how skill authors read it.
- **Keep it outside core:** Decline a core loader contract for now and document user-authored skill conventions or ClawHub bundle patterns instead.

## Reproduction Assessment

Yes, as a source-level feature gap. Current main and v2026.6.11 still load and version `SKILL.md` as the skill unit, with no supported `preferences.md` or `conventions.md` sidecar contract.

## Solution Assessment

Unclear. A markdown sidecar is plausible and has issue-discussion support, but maintainers still need to choose the canonical filename, precedence, refresh behavior, and whether this belongs in loader behavior or structured skill config.
