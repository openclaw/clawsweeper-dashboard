## Summary

Keep open. Current main and v2026.6.11 still treat `SKILL.md` as the skill unit, source precedence replaces same-named skills, and the supported config/docs do not define a `preferences.md` or `conventions.md` sidecar that loads only when that skill is triggered; this remains a product/API decision rather than cleanup-close material.

## What This Changes

The issue requests a supported per-skill user preferences or conventions file that loads only when the corresponding skill is triggered.

## Best Possible Solution

Define one maintainer-approved skill preference contract with filename, precedence, root containment, prompt-version input, watcher invalidation, docs, and regression tests before implementation.

## Reproduction Assessment

Yes, as a source-level feature gap. Current main loads and versions `SKILL.md`, watches `SKILL.md` paths, and has no supported `preferences.md` or `conventions.md` sidecar contract.

## Solution Assessment

Unclear. A markdown sidecar is plausible, but maintainers still need to choose the canonical filename, precedence, refresh behavior, security boundary, and whether this belongs in loader behavior or a different skills config contract.
