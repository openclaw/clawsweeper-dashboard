## Summary

Keep open. Current main and v2026.6.11 still treat skills as `SKILL.md` units with source precedence and snapshots, but there is no supported `preferences.md` or `conventions.md` sidecar loaded only when a skill is triggered; this remains a product/API decision, not a cleanup-close candidate.

## What This Changes

Request support for per-skill user preference or convention files so user guidance loads only with the relevant skill.

## Best Possible Solution

Define one maintainer-approved skill preference contract covering filename, precedence, containment, snapshot versioning, watcher invalidation, docs, and focused tests before implementing loader support.

## Reproduction Assessment

Yes, as a source-level feature gap: current main still loads and versions `SKILL.md` as the skill unit and has no supported `preferences.md` or `conventions.md` sidecar contract. This is not a failing bug reproduction because the issue asks for new supported behavior.

## Solution Assessment

Unclear. A markdown sidecar is plausible, but maintainers still need to choose the canonical filename, precedence, refresh behavior, security boundary, and whether this belongs in loader behavior or a different documented skill/config contract.
