## Summary

Keep open. Current main and the latest release still treat a skill as a single `SKILL.md`-backed prompt unit, so the requested skill-scoped `preferences.md`/`conventions.md` contract remains a real product/API decision rather than cleanup-safe stale work.

## What This Changes

Add a standardized way for users to keep per-skill personal preferences or conventions separate from full `SKILL.md` overrides and global context files.

## Best Possible Solution

Define one maintainer-approved skill preference contract covering filename, precedence, root containment, load timing, snapshot invalidation, docs, and regression tests before implementing loader changes.

## Reproduction Assessment

Yes, as a source-level feature gap: current main loads `SKILL.md` as the skill unit and has no supported `preferences.md` or `conventions.md` sidecar contract. I did not run a live agent scenario because the missing behavior is clear from loader, prompt, docs, and release inspection.

## Solution Assessment

Unclear. A markdown sidecar is plausible, but maintainers still need to choose the canonical filename, precedence, refresh behavior, and whether this belongs in the loader or a different documented skill/config contract.
