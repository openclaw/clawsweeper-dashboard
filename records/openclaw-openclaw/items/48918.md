## Summary

Keep open. Current main still treats `SKILL.md` as the only prompt-bearing skill file and supports only structured per-skill runtime config, so a user-level `preferences.md` or `conventions.md` contract remains a real feature/API decision.

## What This Changes

Request standardized user-scoped per-skill preferences or conventions that load only when the relevant skill is used, without replacing the whole `SKILL.md` or putting skill-specific notes in global context files.

## Best Possible Solution

Define one canonical per-skill preference contract, likely a markdown sidecar or explicitly rejected config shape, with filename, precedence, containment, prompt-version invalidation, docs, and focused regression tests.
