## Summary

Keep open. Current main and the latest release still load skills as `SKILL.md` units with documented source precedence and structured `skills.entries` config, but they do not support a skill-scoped `preferences.md` or `conventions.md` sidecar; this remains a maintainer product/API decision, not a cleanup-close candidate.

## What This Changes

The issue requests an official user-level skill preference convention, such as a per-skill markdown sidecar loaded only when that skill is triggered.

## Best Possible Solution

Define one maintainer-approved skill preference contract covering filename, precedence, root containment, snapshot versioning, watcher invalidation, docs, and focused tests before implementing loader support.
