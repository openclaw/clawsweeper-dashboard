Keep open. Current main and the latest release still load skills as `SKILL.md` units with replacement-style source precedence and no supported `preferences.md` or `conventions.md` sidecar, so this remains a real skill-loading product/API decision rather than a cleanup-close candidate.

Request standard support for user-level, skill-scoped preference or convention files that load only when the matching skill is triggered.

## Best Possible Solution

Define one maintainer-approved skill preference contract covering filename, precedence, root containment, snapshot versioning, watcher invalidation, docs, and focused tests before implementing loader support.
