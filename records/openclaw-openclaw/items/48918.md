## Summary

Keep open. Current main and v2026.6.11 still load, version, prompt, and watch `SKILL.md` only; a supported per-skill preference sidecar remains a real feature gap that needs a maintainer product/API decision.

## What This Changes

Request support for user-scoped per-skill preferences or conventions that load only when the skill triggers, without replacing `SKILL.md` or using global context files.

## Best Possible Solution

Define one maintainer-approved per-skill preference contract, preferably a Markdown sidecar loaded only with the selected skill and covered by prompt-version, watcher, sandbox, security, and docs behavior.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add a first-class per-skill user preference sidecar, and if so should the public contract be Markdown sidecar, structured skill config, or no core support?

Rationale: The feature is absent in current and shipped source, but adding it changes public skill loading, prompt composition, snapshot invalidation, sandbox/read boundaries, and documentation rather than fixing an already-defined bug.

Likely owner: steipete

Owner reason: The decision is primarily product/API direction, and this account has relevant skill docs/product history plus timeline routing on this issue.

Owner confidence: medium

Options:

- **Standardize Markdown sidecar (recommended):** Add a documented `preferences.md` or `conventions.md` sidecar that loads at lower precedence with the selected skill and participates in prompt-version, watcher, sandbox, and docs behavior.
- **Use structured skill config:** Keep preferences under `skills.entries.*.config` and require skills or plugins to interpret them, avoiding a new prompt-side Markdown surface but weakening natural-language convention support.
- **Decline core support:** Keep the current model of full skill overrides, Skill Workshop proposals, global memory/context, or manual skill instructions if maintainers do not want another skill-loading surface.

## Reproduction Assessment

Yes, as a source-level feature gap: current main and v2026.6.11 discover, hash, prompt, and watch `SKILL.md` files only, with no supported `preferences.md` or `conventions.md` sidecar path.

## Solution Assessment

Unclear until maintainers choose the product contract. A Markdown sidecar fits the natural-language convention use case, while structured config already exists for machine-readable settings but does not provide the requested prompt-scoped preference behavior.
