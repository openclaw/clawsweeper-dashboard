## Summary

Keep open. Current main and the latest release still load skills around `SKILL.md`, structured `skills.entries`, and session snapshots; they do not implement a supported `preferences.md` or `conventions.md` sidecar, so the remaining work is a real product/API decision rather than cleanup-closeable stale work.

## What This Changes

The issue requests a supported per-skill user preferences or conventions file that is loaded only when that skill is triggered.

## Best Possible Solution

Pick one explicit contract for skill-scoped user preferences, then implement it with loader, watcher/version, prompt, docs, and focused regression coverage; if core is not the right boundary, document the plugin/bundle convention instead of leaving it implicit.
