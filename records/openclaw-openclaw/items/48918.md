## Summary

Keep open. Current main and the latest release still expose skills as `SKILL.md`-rooted entries with same-name replacement precedence, and there is no supported per-skill markdown sidecar that is loaded only when that skill is selected; this remains a useful product/API decision rather than cleanup.

## What This Changes

The issue requests a supported per-skill user preferences or conventions sidecar that is loaded only when that skill is triggered.

## Best Possible Solution

Define one maintainer-approved skill preference contract, preferably a small markdown sidecar loaded with the selected skill and covered by prompt-version, watcher, security, and docs behavior, or explicitly decide that users should keep using full skill overrides and global context files.

Question: Should OpenClaw support a first-class per-skill user preference sidecar, and if so should the contract be markdown sidecar, structured `skills.entries.*.config`, or no core support?

Rationale: The requested behavior is not implemented, but adding it changes the public skill-loading and prompt-context contract rather than repairing a broken existing contract.

Likely owner: steipete

Owner reason: The decision is primarily about product/API scope for skills, ClawHub, and core prompt contracts, which recent docs and VISION history point to steipete.

Owner confidence: high

Options:

- **Standardize a markdown sidecar (recommended):** Add a documented `preferences.md` or `conventions.md` sidecar that loads with the selected skill, is lower precedence than `SKILL.md`, and participates in prompt snapshot and watcher refresh behavior.
- **Use structured config only:** Keep user preferences under `skills.entries.*.config` and require individual skills or plugins to interpret them, avoiding new prompt-side markdown composition.
- **Decline core support:** Keep the current model where users maintain a higher-precedence skill override, a separate personal skill, or global context guidance.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 discover and prompt `SKILL.md` only, with no supported `preferences.md` or `conventions.md` sidecar path.

## Solution Assessment

Unclear until maintainers choose the product contract. A markdown sidecar looks like the narrowest fit for natural-language conventions, but loader, watcher, prompt snapshot, security, and docs behavior need an explicit API decision first.
