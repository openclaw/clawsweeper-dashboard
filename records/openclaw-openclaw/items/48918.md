## Summary

Keep open: current main and the latest release still expose SKILL.md-centered skill loading plus per-skill env/config metadata, but not a first-class user preferences or conventions file loaded with a triggered skill. ## What This Changes

The issue requests a first-class user-level per-skill preferences or conventions file that loads only when that skill is triggered.

## Best Possible Solution

Decide the generic skill-preference contract first; if approved, implement a narrow markdown preference/conventions reader in the skill-loading and prompt-snapshot path with docs, watcher/versioning, path-containment, and regression tests.
