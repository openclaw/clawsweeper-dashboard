## Summary

Keep open. Current main and the latest release still treat skills as `SKILL.md` roots with same-name replacement precedence, and there is no supported `preferences.md` or `conventions.md` sidecar that gets appended only when a skill is triggered; this remains a real product/API decision rather than stale cleanup.

## What This Changes

The issue requests a supported per-skill user preferences or conventions sidecar that loads only with the matching skill instead of requiring full `SKILL.md` overrides or global context files.

## Best Possible Solution

Define one maintainer-approved skill preference contract, preferably a small markdown sidecar loaded with the selected skill and covered by prompt-version, watcher, security, and docs behavior, or explicitly decide that users should keep using full skill overrides and Skill Workshop.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw support a first-class per-skill user preference sidecar, and which contract should own it: markdown sidecar, structured `skills.entries.*.config`, or no core support?

Rationale: The source evidence shows the requested behavior is not implemented, but adding it changes the public skill-loading and prompt-context contract rather than fixing a broken existing contract.

Likely owner: steipete

Owner reason: The current skill-loading contract, ClawHub skill flows, and docs history most strongly point to steipete for the product/API choice.

Owner confidence: high

Options:

- **Standardize a markdown sidecar (recommended):** Add a documented `preferences.md` or `conventions.md` sidecar that is loaded with the selected skill, versioned with the prompt snapshot, watched for refresh, and kept lower precedence than `SKILL.md`.
- **Use structured skill config only:** Keep preferences under `skills.entries.*.config` and require each skill or plugin to interpret them, avoiding prompt-side markdown composition but leaving natural-language conventions less ergonomic.
- **Decline core support:** Keep the current model where users either maintain a higher-precedence skill override, create a personal skill, or use global context files, and close this direction as not planned.

## Reproduction Assessment

Yes. Source inspection shows OpenClaw currently discovers and prompts `SKILL.md` files only, while current docs and release code do not define a `preferences.md` or `conventions.md` sidecar path.

## Solution Assessment

Unclear until maintainers choose the product contract. A markdown sidecar looks like the narrowest fit for the reported natural-language conventions, but the loader, watcher, prompt snapshot, security, and docs behavior need an explicit API decision first.
