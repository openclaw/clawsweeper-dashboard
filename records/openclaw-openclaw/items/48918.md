## Summary

Keep open. Current main still lacks an official per-user, per-skill preferences or conventions sidecar loaded only when that skill is triggered, and the remaining choice is a maintainer-owned skill loading API decision rather than stale cleanup.

## What This Changes

The issue requests official support for user-level per-skill preference or convention files that avoid full `SKILL.md` overrides and global context pollution.

## Best Possible Solution

Maintainers should choose one canonical markdown sidecar contract, document its precedence and refresh/version semantics, then implement it in the skill loader and prompt snapshot path with focused tests.
