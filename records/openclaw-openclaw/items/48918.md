## Summary

Keep open. Current main and the latest release still load skills as SKILL.md records with documented source precedence and structured skills.entries config, but there is no supported skill-scoped preferences.md or conventions.md sidecar; the remaining work is a product/API decision rather than maintainer cleanup.

## What This Changes

The issue requests a supported per-skill user preference/convention mechanism that is loaded only when that skill is active.

## Best Possible Solution

Maintainers should choose one documented skill-scoped preference contract and wire it through discovery, prompt snapshots, watcher invalidation, docs/schema, security boundaries, and focused tests.

## Reproduction Assessment

Yes, as a source-level feature gap: current main loads SKILL.md as the skill unit and has no supported preferences.md or conventions.md sidecar contract.

## Solution Assessment

Unclear. A markdown sidecar is plausible, but maintainers still need to choose the canonical filename, precedence, refresh behavior, security boundary, and whether this belongs in loader behavior or another documented skill/config contract.
