## Summary

Keep open. Current main and the latest release still define skills around `SKILL.md`, structured per-skill config, and `SKILL.md`-only watcher invalidation; they do not implement an official `preferences.md` or `conventions.md` sidecar loaded only when a skill is triggered, so this remains a maintainer product/API decision.

## What This Changes

The issue requests an official per-skill user preferences or conventions file that loads only when the matching skill is triggered.

## Best Possible Solution

Keep this open for a maintainer-approved skill preference contract with filename, precedence, containment, prompt/snapshot invalidation, docs, and tests, or an explicit decision to route the convention to plugin/ClawHub authoring guidance instead of core runtime loading.

## Reproduction Assessment

Yes. Current main source and docs show skills are discovered and refreshed through `SKILL.md`, while no markdown preference sidecar is loaded or watched.

## Solution Assessment

Unclear. A markdown sidecar is plausible, but maintainers still need to choose the canonical filename, precedence, refresh behavior, security boundary, and whether this belongs in loader behavior or a documented skill/config/plugin contract.
