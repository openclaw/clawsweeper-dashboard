## Summary

Keep open. Current main and v2026.6.11 still load skills as `SKILL.md` units with documented `skills.entries` config, but they do not support a skill-scoped `preferences.md` or `conventions.md` sidecar; this remains a maintainer product/API decision rather than a cleanup-close candidate.

## What This Changes

Request a supported per-skill user preferences or conventions mechanism that loads only when the matching skill is used.

## Best Possible Solution

Define one maintainer-approved skill preference contract covering filename, precedence, root containment, prompt versioning, watcher invalidation, docs, and focused tests before implementing loader support.

## Reproduction Assessment

Yes, as a source-level feature gap: current main still loads and versions `SKILL.md` as the skill unit and has no supported `preferences.md` or `conventions.md` sidecar contract. This is not a failing bug reproduction because the issue asks for new supported behavior.

## Solution Assessment

Unclear. A markdown sidecar is plausible, but maintainers still need to choose the canonical filename, precedence, refresh behavior, security boundary, and whether this belongs in loader behavior or a different documented skill/config contract.
