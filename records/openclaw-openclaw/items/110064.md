## Label Justifications

- `P1`: The patch’s request-time secret resolution can make a real channel delivery workflow fail whenever an exec or file provider is temporarily unavailable.
- `merge-risk: 🚨 message-delivery`: An outbound send can now fail before client creation when request-time SecretRef resolution fails, despite a previously valid active token.
- `merge-risk: 🚨 auth-provider`: The patch changes when and how ClickClack credential providers are invoked rather than consuming the canonical materialized credential snapshot.
- `merge-risk: 🚨 availability`: Repeated external provider resolution adds a new gateway and outbound availability dependency to runtime operations.

## Summary

Keep this PR open for a focused correction: the immediate ClickClack bug is addressed, but the proposed runtime helper re-runs SecretRef provider resolution during gateway startup and outbound delivery instead of consuming the active materialized configuration snapshot, making delivery depend on request-time file or exec provider availability.

## What This Changes

The PR separates non-secret ClickClack inspection from runtime account resolution and materializes file or exec SecretRefs before gateway and outbound client creation.

## Best Possible Solution

Resolve ClickClack SecretRefs once through the normal activation or reload snapshot, then have inspection remain non-secret while gateway and outbound paths consume only the materialized token; add provider-call-count and failed-reload tests to protect that lifecycle.
