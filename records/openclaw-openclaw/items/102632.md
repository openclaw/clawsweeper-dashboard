## Summary

Keep open: current main has the prerequisite Telegram `webApp` button plumbing and Tailscale Serve/Funnel dashboard exposure, but it does not implement the requested end-to-end Telegram-owned dashboard Mini App launch or `initData`-backed Control UI session auth. The protected `maintainer` label and the auth/security boundary make this a maintainer-design item, not conservative cleanup.

## What This Changes

The issue requests opening the OpenClaw Control UI dashboard from Telegram as a Mini App using the existing Tailscale-published Gateway URL plus Telegram initData-backed authentication.

## Best Possible Solution

Design an explicit Telegram-owned dashboard Mini App flow that reuses Tailscale Serve/Funnel URL discovery, validates Telegram initData, and mints a bounded Control UI credential through existing device-bootstrap/pairing seams without auto-converting arbitrary URLs or adding public exposure defaults.
