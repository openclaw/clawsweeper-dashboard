## Summary

Keep this PR open, but it is not merge-ready: the same-process fallback still bypasses synchronization while the fallback writer can update the authorization file in place, so a synchronous exec decision can consume a snapshot that has not committed or may later be rolled back. The latest commit addresses formatting and an unused export, not the previously reported authorization-coherence blocker.

## What This Changes

The PR makes synchronous exec-approval reads bypass same-process lock contention, adds a regression test, and extracts the copy-based fallback write implementation into a separate module.

## Best Possible Solution

Preserve synchronous progress without reading the mutable destination: serve the last committed snapshot during same-process contention or restructure the caller so reads occur outside the async write section, then cover atomic-rename and fallback-copy/rollback paths and demonstrate the result in a live gateway run.
