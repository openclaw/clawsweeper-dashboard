## Summary

Keep open: the force-pushed head still resolves self-contention by dropping read serialization. Atomic replacement prevents torn JSON, but it does not prevent an authorization read from observing policy that an in-flight writer is revoking or tightening, so the prior P1 blocker remains.

## What This Changes

The PR makes synchronous exec-approval readers fall back to unlocked file reads during same-process async lock contention and adds a synthetic lock-file regression test.

## Best Possible Solution

Preserve one authoritative synchronization boundary: restructure the async transaction so synchronous readers cannot overlap an awaited write, or publish an authoritative in-process transaction snapshot that readers can consume without reverting to stale disk state; cover revocation, tightening, initial creation, and repeated-exec recovery.
