## Summary

This PR remains necessary for the linked regression, but the current fix still bypasses authorization-store serialization while the existing copy-based fallback can modify the live file in place; the new test only reads beneath an idle synthetic lock and does not cover that concurrent write path.

## What This Changes

The PR makes synchronous exec-approvals reads fall back to lockless disk reads during same-process lock contention, adds regression coverage, and extracts the copy-based write fallback into a separate module.

## Best Possible Solution

Keep synchronous authorization decisions on a coherent committed snapshot by introducing process-local read/write coordination or a last-committed in-memory snapshot for same-process contention, while retaining cross-process locking and adding coverage for both atomic-rename and copy-fallback writes.

## Solution Assessment

No. Avoiding the self-deadlock is necessary, but reading the live policy file without serialization is not safe while the supported copy fallback can rewrite that file in place; a process-local committed snapshot or coordination mechanism is the narrower durable fix.
