## Summary

This PR addresses a credible P1 exec-approval availability regression, but the proposed lockless fallback breaks the store’s revocation-serialization contract: a synchronous authorization read can consume the old permissive policy while a same-process async writer is revoking access. Atomic replacement protects byte consistency, not policy freshness, and real gateway proof is still missing.

## What This Changes

Adds same-process lock-timeout detection that lets synchronous exec-approval readers read an existing policy without the sidecar lock, plus a synthetic contention regression test.

## Best Possible Solution

Keep authorization reads serialized with policy updates and remove the mixed sync/async contention at the runtime caller boundary—prefer the async locked reader or an explicitly committed snapshot—then add a concurrent revocation regression test and real gateway proof.
