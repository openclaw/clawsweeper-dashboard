## Summary

The linked lock-wedge bug is credible, but the existing P1 blocker remains unchanged at head `8c9ce2174159d0de1bd282184dbc44fca98544f3`: synchronous authorization reads can bypass an active same-process writer even though the store retains a copy-based fallback that may update the destination in place when atomic rename is unavailable. The added test covers a synthetic lock file, not overlap with a real writer or fallback copy, so it does not establish that readers always observe committed policy state.

Likely related people: `Alex-Alaniz` and `BradGroux` are high-confidence routing candidates for the fallback write path; `steipete` is a medium-confidence adjacent owner from broader exec-approval and filesystem-safety history.

## What This Changes

The PR adds a same-process lock-contention exception that lets synchronous exec-approval reads proceed without the sidecar lock, extracts fallback persistence helpers, and adds a regression test.

## Best Possible Solution

When a same-process writer owns the lock, serve synchronous authorization reads from a process-local last-committed policy snapshot—or otherwise unify the read/write serialization contract—and update that snapshot only after persistence commits; preserve fail-closed initial creation and cover both atomic-rename and copy-fallback writes.
