## Summary

Keep open: current main still routes preserved ChatGPT human Notes through `String.prototype.replace` with a string replacement, so `$` sequences in user-authored notes can be expanded and corrupt the preserved block during re-import.

## What This Changes

The issue requests a fix for memory-wiki ChatGPT re-imports corrupting existing human Notes blocks that contain JavaScript replacement-pattern `$` sequences.

## Best Possible Solution

Patch the ChatGPT import preservation path to insert the extracted human block literally, then add a focused regression that re-imports a ChatGPT export after editing Notes with `$$`, `$&`, `$`` and `$'`.

## Reproduction Assessment

Yes, there is a high-confidence source-level reproduction path: current main passes a user-authored human block into a string replacement, and a focused Node probe shows the reported `$` sequences are expanded instead of preserved. I did not run the full importer because the checkout lacks installed TS runtime dependencies.

## Solution Assessment

Yes, the narrowest maintainable fix is to make `replaceSimpleManagedBlock` insert `params.replacement` literally, for example with a replacer function or equivalent slice-based replacement, and cover the ChatGPT re-import path with a regression test.
