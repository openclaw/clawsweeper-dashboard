## Summary

Keep open: current `origin/main` and the latest release still pass the extracted human Notes block to `String.prototype.replace` as a string replacement, so `$` sequences can corrupt user-authored memory-wiki Notes during ChatGPT re-import; no duplicate or fixing PR was found.

## What This Changes

The issue asks memory-wiki ChatGPT re-import to preserve user-authored `## Notes` containing JavaScript replacement `$` sequences byte-for-byte.

## Best Possible Solution

Patch the ChatGPT import preservation path to insert the extracted human block literally, then add a focused regression that re-imports a ChatGPT export after editing Notes with `$$`, `$&`, `$`` and `$'`.

## Reproduction Assessment

Yes, at source level: current `origin/main` passes the preserved human block into a string replacement, and a focused Node probe shows the reported `$` sequences are expanded instead of preserved. I did not run the full importer in this read-only review.

## Solution Assessment

Yes, the narrowest maintainable fix is to make `replaceSimpleManagedBlock` insert `params.replacement` literally, using a replacer function or equivalent slice-based replacement, and cover the ChatGPT re-import path with a regression test.
