## Summary

Keep open: current main and the latest release still pass the preserved ChatGPT Notes block to `String.prototype.replace` as a string replacement, so `$` sequences can corrupt user-authored memory-wiki Notes. Two open closing PRs now own the narrow fix path, so this issue should remain open until one lands or both are declined.

## What This Changes

Fix memory-wiki ChatGPT re-import so human `## Notes` blocks containing JavaScript replacement-pattern dollar sequences are preserved literally.

## Best Possible Solution

Review and land one narrow linked PR that switches the managed-block replacement to a replacer callback with regression coverage, then close the duplicate PR and let the issue close from the merged fix.

## Reproduction Assessment

Yes. Source inspection shows the preserved human Notes block is passed as a string replacement to `String.prototype.replace`; the issue body also includes an end-to-end import proof, but I did not run tests because this review is read-only.

## Solution Assessment

Yes. The linked PR shape, `replace(blockPattern, () => params.replacement)`, is the narrow maintainable fix because it preserves the extracted block literally without changing the importer, markers, or related-block preservation behavior.
