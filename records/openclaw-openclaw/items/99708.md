## Summary

Keep open: current main and the latest release still route preserved memory-wiki ChatGPT Notes through a string replacement that expands `$` sequences, and two open closing PRs now own candidate fixes. The issue should remain the canonical tracker until one fix merges.

## What This Changes

The issue asks memory-wiki's ChatGPT re-import to preserve user-authored Notes containing JavaScript `$` replacement sequences byte-for-byte.

## Best Possible Solution

Land one canonical fix PR that inserts the preserved human block literally and adds a ChatGPT re-import regression for `$$`, `$&`, `$`` and `$'`; after merge, close this issue as implemented and retire the duplicate candidate PR.

## Reproduction Assessment

Yes, at source level: current main passes the preserved human block into `String.prototype.replace` as a string replacement, and a focused probe shows the reported `$` sequences expand instead of preserving literal text. I did not run the full importer in this read-only review, so this is source-reproducible rather than fully reproduced here.

## Solution Assessment

Yes, the best fix is the narrow literal-insertion change already proposed by the linked PRs, plus a regression that drives ChatGPT re-import with dollar-sequence Notes. A broader refactor is unnecessary because the sibling preservation helper already proves the safe replacement shape.
