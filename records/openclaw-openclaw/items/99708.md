## Summary

Keep open: current main and the latest release still route the preserved ChatGPT human Notes block through a string replacement, while two open fixing PRs now explicitly close this issue and are the right path to resolve it.

## What This Changes

The issue reports silent corruption of user-authored memory-wiki ChatGPT import Notes containing JavaScript dollar replacement sequences during re-import.

## Best Possible Solution

Land one focused linked PR with the literal Notes preservation fix and regression coverage, close or supersede the duplicate PR, then close this issue once the fix reaches current main.

## Reproduction Assessment

Yes, at source level. Current main passes the preserved human Notes block into a string replacement, and the issue plus linked PR proof show the real ChatGPT import path corrupts dollar replacement sequences.

## Solution Assessment

Yes. The narrow maintainable fix is to insert `params.replacement` literally with a replacer callback or equivalent slice replacement and keep the regression on the ChatGPT re-import path.
