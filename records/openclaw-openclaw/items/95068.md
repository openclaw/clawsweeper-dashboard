## Summary

Keep open: current main and v2026.6.11 still hard-code envelope and system-event date order as YYYY-MM-DD, and the reporter's July 5 update confirms this is still blocking their workflow. The remaining question is product direction because adding `dateFormat` expands the public `agents.defaults` config surface and changes model-visible timestamp formatting.

## What This Changes

Request adds an `agents.defaults.dateFormat` option so envelope and system-event display dates can use ISO, UK, US, or locale ordering while machine-readable timestamps remain ISO.

## Best Possible Solution

Maintainers should decide the display-date contract first; if accepted, implement it once in the shared timestamp formatter, thread it through envelope and system-event callers, update schema/help/docs/tests, and keep filenames plus machine-readable `timestampUtc` fields ISO.
