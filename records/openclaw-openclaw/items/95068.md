## Summary

Keep open: current main and v2026.6.11 still hard-code prompt-facing envelope and system-event dates in ISO order, and the reporter recently confirmed an active UK-date post-processing workaround. The remaining decision is product direction because accepting this would add a new `agents.defaults` config surface and change model-visible timestamp formatting.

## What This Changes

The issue requests an `agents.defaults.dateFormat` option for ISO, UK, US, or locale date ordering in human-readable envelope and system-event timestamps while preserving ISO for machine-readable fields and filenames.

## Best Possible Solution

Maintainers should either explicitly keep ISO-only display or approve a narrow enum-backed display option; if approved, implement it centrally in the shared formatter, thread it through all prompt-facing timestamp callers, and leave machine-readable timestamps and artifact filenames ISO.
