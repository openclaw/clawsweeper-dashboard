## Summary

Keep open: current main and v2026.6.11 still render envelope and system-event date portions as YYYY-MM-DD, but adding `dateFormat` would be a new public config surface and needs maintainer product direction.

## What This Changes

Issue requests a configurable `dateFormat` setting for human-readable message envelope and system-event timestamps.

## Best Possible Solution

Maintainers should decide the date-display contract first; if accepted, implement it once in the shared timestamp formatter, thread it through envelope and system-event callers, update schema/help/docs, and keep filenames plus machine-readable fields ISO.

## Reproduction Assessment

Not applicable as a bug repro. Source inspection confirms current main has no `agents.defaults.dateFormat` schema entry and still renders envelope/system-event dates through YYYY-MM-DD formatters.

## Solution Assessment

Unclear until maintainers confirm the product contract. A shared date-format option is a plausible implementation path, but ISO-only behavior, locale behavior, or a narrower scope may be safer than adding another config key.
