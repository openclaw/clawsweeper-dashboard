## Summary

Keep open: current main and the latest release still have ISO-order envelope and system-event date rendering with no `agents.defaults.dateFormat`, but adding that knob would be a new public config surface that needs maintainer product direction.

## What This Changes

The issue requests an `agents.defaults.dateFormat` option so human-readable envelope and system-event dates can render as ISO, UK, US, or locale-preferred order.

## Best Possible Solution

Maintainers should decide the date-display contract first; if accepted, implement it once in the shared timestamp formatter, thread it through envelope and system-event callers, update schema/help/docs/tests, and keep machine-readable timestamps and filenames ISO.

## Reproduction Assessment

Not applicable as a bug reproduction. Source inspection confirms current main has no `agents.defaults.dateFormat` schema entry and still renders envelope/system-event date order as YYYY-MM-DD.

## Solution Assessment

Unclear until maintainers confirm the product contract. A shared date-format option is a plausible implementation path, but ISO-only behavior, locale behavior, or narrower scope may be safer than adding another config key.
