## Summary

Keep open: current main and the latest release still hard-code envelope and system-event date order as YYYY-MM-DD, but adding `dateFormat` is a new public config surface and needs maintainer product direction.

## What This Changes

The issue requests an `agents.defaults.dateFormat` option for envelope and system-event human-readable date portions while keeping machine-readable timestamps and filenames ISO.

## Best Possible Solution

Maintainers should decide the timestamp display contract first; if accepted, implement one shared date-format option through the formatter, envelope, and system-event callers with schema/help/docs/tests while leaving filenames and machine-readable timestamps ISO.

## Reproduction Assessment

Not applicable as a bug reproduction. Source inspection confirms current main has no `agents.defaults.dateFormat` schema entry and still renders envelope/system-event dates through YYYY-MM-DD formatters.

## Solution Assessment

Unclear until maintainers confirm the product contract. A shared date-format option is a plausible implementation path, but ISO-only behavior, locale behavior, or a narrower scope may be safer than adding another config key.
