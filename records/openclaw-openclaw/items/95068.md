## Summary

Keep open: current main and v2026.6.11 still render envelope and system-event dates in ISO order and have no `dateFormat` config key, while the reporter’s latest comment confirms this remains active. The remaining question is product direction because adding a new `agents.defaults` field changes public config and model-visible prompt formatting.

## What This Changes

The issue requests a new `agents.defaults.dateFormat` option so human-readable envelope and system-event dates can render as ISO, UK, US, or locale format instead of always using ISO order.

## Best Possible Solution

Maintainers should decide the date-display contract first; if accepted, implement one ISO-default display-only option in the shared timestamp formatter, thread it through envelope and system-event callers, update schema/help/docs/tests, and keep filenames plus `timestampUtc` fields ISO.
