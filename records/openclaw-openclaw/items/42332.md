## Summary

Keep open: current main and the latest release still accept direct and mapped hook-agent deliveries with `200`/`runId`; the remaining work is a public webhook admission policy choice, not a cleanup-close candidate.

## What This Changes

Add a sessionKey-based webhook admission guard so repeated hook-agent deliveries for an already active logical session can be rejected or skipped instead of starting overlapping work.

## Best Possible Solution

Define an explicit, compatibility-safe hook overlap policy at Gateway admission, keyed by the resolved sessionKey, that covers active and queued work while preserving current default behavior unless maintainers choose a breaking default.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should same-session hook-agent deliveries be rejected with 409, skipped, queued, or left accepted by default, and should any non-parallel behavior be opt-in per hook or mapping?

Rationale: The requested behavior changes the public webhook response contract and retry semantics, while the available alternatives create different compatibility, queueing, and operator-control tradeoffs that automation should not choose without maintainer intent.

Likely owner: vincentkoc

Owner reason: Current-main history ties this person to the hook request-handler and session admission path that would need the policy boundary.

Owner confidence: medium

Options:

- **Add Opt-In Overlap Policy (recommended):** Preserve accepted-by-default behavior and add a documented hook or mapping policy for reject, skip, or queue semantics keyed by the resolved sessionKey.
- **Make 409 The Default:** Reject active same-session hook deliveries by default and accept that existing webhook producers may need migration to avoid retry storms.
- **Leave Locking To Callers:** Keep OpenClaw’s hook endpoint accepted-by-default and document idempotency keys plus caller-managed locks as the supported overlap control.

## Reproduction Assessment

Yes. Source inspection shows repeated direct or mapped hook-agent POSTs with the same resolved sessionKey and no shared idempotency key are accepted with `200`/`runId` before async session admission can provide any caller-visible conflict.

## Solution Assessment

No for unconditional default `409`. The best fix needs a maintainer-approved overlap policy that chooses reject, skip, queue, compatibility defaults, and active-plus-queued semantics before implementation.
