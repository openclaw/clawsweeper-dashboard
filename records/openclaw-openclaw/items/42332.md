## Summary

Keep open: current main still returns 200/runId for direct and mapped hook-agent deliveries before async session work starts, so the requested caller-visible same-session 409/skip policy is not implemented; related persistent-session and queued-webhook work overlap but do not settle this overlap behavior.

## What This Changes

The issue requests a sessionKey-based webhook delivery concurrency guard that rejects or skips duplicate polling deliveries while a same-session hook run is already active.

## Best Possible Solution

Define an explicit, compatibility-safe hook overlap policy at Gateway admission that covers active and queued same-session work, preserves current defaults unless maintainers choose otherwise, and coordinates with persistent hook sessions and queued webhook ingestion.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should hook-agent deliveries with the same resolved sessionKey be rejected, skipped, queued, or remain parallel by default, and should any 409 behavior be opt-in?

Rationale: The requested behavior changes an external webhook response contract and retry semantics, so automation cannot safely choose the default or compatibility policy without maintainer intent.

Likely owner: steipete

Owner reason: Recent hook/session policy history and prior review framing make steipete the clearest owner for the product/API compatibility choice.

Owner confidence: medium

Options:

- **Add opt-in overlap policy (recommended):** Keep accepted-by-default behavior for compatibility, then let trusted hook mappings or direct hook calls opt into reject, skip, or queue semantics with documented retry behavior.
- **Make 409 the default:** Reject same-session active deliveries by default, accepting that existing webhook integrations may need migration to avoid retry storms.
- **Keep caller-managed locking:** Leave OpenClaw accepting hook deliveries and document idempotency keys plus client-side locks as the supported overlap control.

## Reproduction Assessment

Yes at source level. Repeated direct or mapped hook-agent POSTs with the same resolved sessionKey and no shared idempotency key take the dispatch path and receive 200/runId, with no active/queued same-session 409 path.

## Solution Assessment

No for an unconditional default 409. The better path is a maintainer-approved overlap policy that chooses reject, skip, queue, compatibility defaults, and active-plus-queued semantics before implementation.
