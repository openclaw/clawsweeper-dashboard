## Summary

Keep open: current main and the latest release still accept direct and mapped hook-agent deliveries and return 200 with a runId; the requested same-session overlap response remains an HTTP/API product decision rather than completed behavior.

## What This Changes

Add a sessionKey-based webhook delivery guard so a POST for an already-active hook session can be rejected, such as with 409 Conflict.

## Best Possible Solution

Define a maintainer-approved hook overlap policy keyed by the resolved dispatch sessionKey, preferably preserving today's default and adding explicit skip/queue/parallel semantics with coverage for direct hooks, mapped hooks, idempotency replay, docs, and upgrade behavior.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should same-session webhook deliveries be rejected with 409, queued, serialized, or left parallel by default, and should that policy be opt-in per hook or mapping?

Rationale: This changes an external HTTP webhook contract and retry semantics for existing integrations, so automation should not choose the permanent overlap/default policy.

Likely owner: vincentkoc

Owner reason: Vincent owns the current main hook request/dispatch code by blame, so he is the best available routing owner for the immediate contract decision.

Owner confidence: high

Options:

- **Add opt-in overlap policy (recommended):** Introduce an explicit hook or mapping policy such as skip, queue, or parallel while preserving today's default behavior for existing callers.
- **Adopt unconditional 409:** Implement the reporter's exact behavior for every same-session active hook delivery and accept the compatibility break for callers that currently expect 200/runId.
- **Fold into queued webhooks:** Defer this issue until queued-webhook ingestion chooses durable backlog, parallelism, and caller response semantics together.

## Reproduction Assessment

Yes. Source inspection on current main shows direct and mapped hook-agent deliveries with the same resolved sessionKey can reach dispatchAgentHook and return 200/runId unless the same idempotency key replays.

## Solution Assessment

Unclear. Returning 409 is plausible, but a compatibility-preserving overlap policy or the queued-webhook design may be the safer maintainable solution.
