## Summary

Keep open: current main still accepts repeated direct and mapped hook-agent POSTs with 200/runId and only idempotency-key replay; there is no sessionKey active-or-queued conflict policy, and related open work covers persistence, lanes, or durable queues rather than this admission/retry decision.

## What This Changes

Add a webhook hook-agent overlap guard keyed by sessionKey, proposed as a 409 response when the same logical session already has active work.

## Best Possible Solution

Define an explicit, compatibility-safe hook overlap policy at Gateway admission that covers active and queued same-session work, preserves current defaults unless maintainers choose otherwise, and coordinates with persistent hook sessions and queued webhook ingestion.

- **Make 409 Default:** Reject same-session active or queued hook deliveries by default, accepting that existing integrations may need migration to avoid retry storms.
- **Keep Caller-Managed Locking:** Document idempotency keys and client-side locks as the supported concurrency control and leave OpenClaw accepting repeated hook deliveries.

## Reproduction Assessment

Yes by source inspection. Repeated direct or mapped hook-agent POSTs with the same resolved sessionKey and no shared idempotency key are accepted with 200/runId, with no active-or-queued same-session 409 path.

## Solution Assessment

No for an unconditional default 409. The better path is a maintainer-approved overlap policy that chooses reject, skip, queue, compatibility defaults, and active-plus-queued semantics before implementation.
