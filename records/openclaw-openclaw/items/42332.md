## Summary

Keep open: current main still accepts direct and mapped hook-agent deliveries with 200/runId and only idempotency-key replay dedupe; no same-session active or queued admission policy exists yet.

## What This Changes

The issue requests a sessionKey-based webhook concurrency guard, such as returning 409 Conflict when a hook delivery targets a session that is already running.

## Best Possible Solution

Define an explicit, compatibility-safe hook overlap policy at Gateway admission that covers active and queued same-session work, preserves current defaults unless maintainers choose otherwise, and coordinates with persistent sessions and queued webhook ingestion.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should hook-agent deliveries with the same resolved sessionKey be rejected with 409, skipped, queued, or accepted by default, and should any overlap policy be opt-in per hook or mapping?

Rationale: The requested behavior changes an external HTTP webhook response contract, retry semantics, session-state admission, and trust-boundary expectations, so automation cannot safely choose the default or compatibility policy.

Likely owner: steipete

Owner reason: Peter has the clearest recent history across hook ingress, isolated session behavior, and the prior product-policy framing for this exact issue.

Owner confidence: high

Options:

- **Add Opt-In Overlap Policy (recommended):** Keep current 200/runId behavior by default and add a trusted hook/mapping overlap policy such as reject, skip, queue, or parallel with documented active-plus-queued semantics.
- **Make 409 The Default:** Reject same-session active deliveries by default and accept the migration risk for existing integrations that expect accepted asynchronous hook delivery.
- **Defer To Queue Design:** Leave this issue open until maintainers decide whether durable queued webhook ingestion should own overlap, backpressure, and retry semantics instead.

## Reproduction Assessment

Yes. Source inspection shows repeated direct or mapped hook-agent POSTs with the same resolved sessionKey and no shared idempotency key are accepted with 200/runId, with no active or queued same-session 409 path.

## Solution Assessment

No for an unconditional default 409. The better path is a maintainer-approved overlap policy that chooses reject, skip, queue, compatibility defaults, and active-plus-queued semantics before implementation.
