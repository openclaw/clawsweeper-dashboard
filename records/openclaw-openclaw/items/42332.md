## Summary

Keep open: current main still accepts direct and mapped hook-agent deliveries with `200`/`runId` and has no caller-visible same-session active or queued conflict policy; related persistent-session and queued-webhook items overlap but do not decide this exact webhook overlap behavior.

## What This Changes

The issue requests a sessionKey-based webhook delivery guard, such as returning `409 Conflict` when a prior webhook turn for the same sessionKey is still active.

## Best Possible Solution

Define an explicit, compatibility-safe hook overlap policy at Gateway admission, keyed by the resolved sessionKey, that covers active and queued same-session work while preserving existing default behavior unless maintainers intentionally choose a breaking default.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should same-session hook-agent deliveries be rejected with 409, skipped, queued, or left accepted by default, and should any non-parallel behavior be opt-in per hook or mapping?

Rationale: The requested behavior changes the public webhook response contract and retry semantics, while the alternatives create different compatibility, queueing, and operator-control tradeoffs that automation should not choose without maintainer intent.

Likely owner: steipete

Owner reason: Recent hook/session history and the public API compatibility tradeoff make steipete the best available routing owner from the reviewed evidence.

Owner confidence: medium

Options:

- **Add Opt-In Overlap Policy (recommended):** Keep current accepted-by-default behavior and add a documented hook or mapping policy for reject, skip, or queue semantics keyed by the resolved sessionKey.
- **Make 409 The Default:** Reject active same-session hook deliveries by default and accept that existing webhook producers may need migration to avoid retry storms.
- **Leave Locking To Callers:** Keep OpenClaw's hook endpoint accepted-by-default and document idempotency keys plus caller-managed locks as the supported overlap control.

## Reproduction Assessment

Yes. Source inspection shows repeated direct or mapped hook-agent POSTs with the same resolved sessionKey and no shared idempotency key are accepted with `200`/`runId` before async session work admission can provide any caller-visible conflict.

## Solution Assessment

No for unconditional default `409`. The best fix needs a maintainer-approved overlap policy that chooses reject, skip, queue, compatibility defaults, and active-plus-queued semantics before implementation.
