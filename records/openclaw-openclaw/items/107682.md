## Summary

Keep open: the latest supplied current-main reproduction shows a webchat operator can materialize another session’s transcript-bearing checkpoint, and no merged fix or canonical replacement resolves the security boundary. The permanent operator, admin, Control UI, and external-webchat authorization contract still needs explicit maintainer direction.

## What This Changes

Prevent webchat-class Gateway clients from branching another session’s compaction checkpoint into a readable child session.

## Best Possible Solution

Centralize checkpoint authorization around authenticated client identity, scope, and source-session access; apply it consistently to list, get, branch, and restore while preserving the intended trusted Control UI workflow, with cross-session regression coverage for external webchat, Control UI, operator, and admin callers.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should checkpoint branching remain an operator recovery capability for trusted Control UI and non-webchat clients while external webchat clients are rejected, or should every branch require admin scope?

Rationale: The reported path exposes transcript-bearing session state, but the feature intentionally used operator branch and restricted restore semantics, and the existing webchat predicate has previously overblocked the Control UI; repository history cannot choose that trust boundary safely.

Likely owner: scoootscooob

Owner reason: They introduced the checkpoint RPC surface and the operator-branch versus restricted-restore contract that this decision would revise.

Owner confidence: high

Options:

- **Preserve trusted operator branching (recommended):** Reject external webchat clients and enforce source-session access while retaining operator.write for authenticated Control UI and other trusted operator clients.
- **Require admin branching:** Make branch admin-only and document the loss of operator-level checkpoint recovery as an intentional security hardening decision.
- **Deny all webchat mode:** Apply the existing mode-based guard uniformly, accepting that Control UI branching may remain unavailable until its connection classification changes.

## Reproduction Assessment

Yes. The supplied production-handler harness uses a webchat client and victim checkpoint, observes restore denied but branch succeeding, and verifies copied pre-compaction content; the timeline records a current-main reproduction on July 15, 2026.

## Solution Assessment

No, blindly adding the current mode-only guard is not yet the best permanent fix. The narrow maintainable solution must preserve the intended trusted Control UI and operator recovery path while denying cross-session branching to external webchat clients and proving the full checkpoint surface uses one authorization rule.
