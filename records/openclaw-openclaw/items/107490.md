## Summary

Keep this issue open for explicit security-owner review: the report has not established an untrusted path from plugin credentials or a remote request into ACP’s process-level file arguments, and URL-encoded traversal is not interpreted by ordinary filesystem APIs. Likely related people: @joshavant (high), @vincentkoc (medium), and @jacobtomlinson (medium).

## What This Changes

Investigate whether ACP token/password file handling permits encoded or double-escaped relative-path traversal to read unintended host files.

## Best Possible Solution

Trace the provenance of every ACP token/password file argument; preserve arbitrary local operator-selected paths with direct-regular-file and symlink-safe reads, avoid URL-decoding filesystem paths, and add root confinement only to a demonstrably untrusted caller surface.
