## Summary

Keep open. Current main and the latest release still map every non-abort `plugin.approval.request` failure to the misleading agent-facing reason `Plugin approval required (gateway unavailable)`, even when the gateway rejected the request as `INVALID_REQUEST`.

## What This Changes

The issue requests clearer agent-facing error reporting when a plugin approval request is rejected by the gateway instead of treating it as gateway unavailability.

## Best Possible Solution

Fix `requestPluginToolApproval` to classify `GatewayClientRequestError` request rejections separately from real transport failures, preserving existing abort and no-route behavior.

## Reproduction Assessment

Yes, by source inspection. A plugin approval title over 80 characters violates the gateway schema, the gateway returns `INVALID_REQUEST`, and the before_tool_call catch block maps that rejection to the fixed gateway-unavailable reason.

## Solution Assessment

Yes. The narrow maintainable fix is to classify gateway request rejections in the before_tool_call approval request path and add regression coverage for rejected requests versus true gateway unavailability.
