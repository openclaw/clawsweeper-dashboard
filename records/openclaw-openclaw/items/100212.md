## Summary

This remains a valid, narrow bug: current main still converts any non-abort plugin approval gateway request failure into the misleading agent-facing reason `Plugin approval required (gateway unavailable)`, even when the gateway rejected the request as `INVALID_REQUEST`.

## What This Changes

The issue asks OpenClaw to report plugin approval request rejections to the agent as rejected/invalid requests instead of saying the gateway is unavailable.

## Best Possible Solution

Keep the issue open and fix `requestPluginToolApproval` to distinguish `GatewayClientRequestError` request rejections from real transport/unavailable failures, preserving the existing no-route and abort messages.

## Reproduction Assessment

Yes, by source inspection: a `requireApproval` title over 80 characters violates the gateway schema, the gateway returns `INVALID_REQUEST`, and the before-tool-call catch block maps that rejection to the fixed gateway-unavailable reason. I did not run a live gateway repro in this read-only pass.

## Solution Assessment

Yes, the best fix is a narrow error-classification change in the before-tool-call approval request path, with regression tests for `INVALID_REQUEST` versus true transport failure. Changing the schema caps or adding config would be the wrong layer for this bug.
