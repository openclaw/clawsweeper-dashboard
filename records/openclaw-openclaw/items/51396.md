## Summary

Keep open: current main and v2026.6.11 still clear device-less shared-token/password WebSocket operator scopes, while the plausible token-scope policy path remains open and security/product-sensitive.

## What This Changes

The issue reports that non-local WebSocket clients with valid token auth lose requested operator scopes and then fail write-scoped RPCs such as chat.send.

## Best Possible Solution

Resolve the canonical Gateway auth behavior with a maintainer-approved bounded token-scope or device-token contract, then land source, tests, docs, and real Gateway proof before closing this issue.

## Reproduction Assessment

Yes, at source level: current main clears device-less shared-token/password WebSocket operator scopes, and checked-in tests assert the resulting missing-scope behavior. I did not run a live LAN/tailnet Gateway scenario because this review is read-only.

## Solution Assessment

No for blanket retention of client-declared scopes. The safer path is a bounded maintainer-approved token-scope or device-token contract rather than trusting remote device-less operator scope claims by default.
