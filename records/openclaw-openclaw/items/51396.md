## Summary

Keep open: current main and v2026.6.11 still clear device-less shared-token/password WebSocket operator scopes, and the active related work is an unmerged security/product decision rather than cleanup-close evidence.

## What This Changes

Allow non-local device-less clients with valid shared-token auth to retain operator scopes so `chat.send` and other `operator.write` methods work.

## Best Possible Solution

Land a bounded maintainer-approved Gateway token-scope or device-token contract with source, tests, docs, and real Gateway proof, then close this issue and linked duplicates from the merged implementation.

## Reproduction Assessment

Yes, at source level: current main clears device-less shared-token/password WebSocket operator scopes, and checked-in tests assert the resulting missing-scope behavior. I did not run a live LAN/tailnet Gateway scenario in this read-only review.

## Solution Assessment

No for the literal request to unconditionally trust client-declared scopes from remote device-less token-auth clients. The safer path is a bounded maintainer-approved token-scope or device-token contract with explicit security limits.
