## Summary

Keep open: current main and the latest release still clear device-less shared-token WebSocket operator scopes outside narrow local preservation paths, and the remaining fix is a Gateway auth policy decision with open related design work.

## What This Changes

The issue reports that non-local token-authenticated Gateway WebSocket operator clients lose requested operator scopes and then fail write-scoped calls such as chat.send.

## Best Possible Solution

Resolve the Gateway auth policy explicitly, preferably by preserving secure defaults while landing a reviewed token-scope or paired-device path for trusted headless deployments with WebSocket regression coverage.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should non-local device-less WebSocket operator clients authenticated with the shared gateway token/password be allowed to retain operator scopes, and should that be the default or an explicit configured token-scope policy?

Rationale: Current source, tests, and docs intentionally clear these scopes, while the report asks to restore remote shared-token operator.write behavior; choosing between those outcomes changes the Gateway auth trust boundary.

Likely owner: steipete

Owner reason: steipete owns the open token-scope implementation PR and recently maintained the Gateway connect policy surface.

Owner confidence: high

Options:

- **Use explicit token scopes (recommended):** Keep device-less remote scope clearing as the default and land a bounded token-scope configuration for trusted headless deployments.
- **Restore remote token retention:** Treat successful shared token/password auth as enough for non-local WebSocket operators to retain requested scopes by default.
- **Document as unsupported:** Keep the current behavior and document that remote WebSocket operator clients must pair or use a supported configured scope path.

## Reproduction Assessment

Yes. Current main clears device-less shared-token operator scopes outside local preservation paths, and the default-token suite asserts the connected-with-cleared-scopes missing-scope behavior.

## Solution Assessment

Unclear as a straight bug fix. Preserving all remote token-declared scopes would fix the reported workflow but conflicts with current source, tests, docs, and security posture, so the maintainable path needs explicit maintainer policy approval.
