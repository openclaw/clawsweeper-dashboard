## Summary

Keep open: current main and the latest release still clear ordinary device-less shared-token/password WebSocket operator scopes, and checked-in gateway tests assert the resulting missing-scope behavior. The remaining fix is real but security-sensitive, with open product/design work around a bounded token-scope contract rather than a cleanup close.

## What This Changes

The issue asks OpenClaw to stop stripping operator scopes from non-local WebSocket clients that authenticate successfully with a gateway token/password and then call write-scoped methods.

## Best Possible Solution

Resolve the shared-token operator-scope contract with maintainer-approved safety bounds, then land source, tests, docs, and real gateway proof before closing this issue.

## Reproduction Assessment

Yes, at source level: current main clears device-less shared-token/password WebSocket operator scopes, and checked-in gateway auth tests assert the resulting missing-scope behavior. I did not run a live LAN/tailnet gateway scenario because this review is read-only.

## Solution Assessment

No for unconditional retention of self-declared scopes: the safer path is a bounded maintainer-approved token-scope or device-token contract. Current main is not a fix, and the open tokenScopes PR is an unmerged candidate policy path rather than an implemented resolution.
