## Summary

Keep open: current main still clears operator scopes for device-less shared-token WebSocket clients, and the remaining fix direction is security-sensitive and already tied to an open token-scope design/PR path that has not landed.

## What This Changes

The issue reports that non-local WebSocket clients authenticated with a valid gateway token lose operator scopes before calling write-scoped methods.

## Best Possible Solution

Resolve the shared-token WebSocket scope problem through a bounded Gateway/security-approved token-scope or device-identity policy, then close this issue from the merged implementation or a clearer canonical issue.

## Reproduction Assessment

Yes at source level. Current main still clears device-less shared-token WebSocket scopes and the default-token suite asserts the resulting missing-scope behavior; I did not run a live remote WebSocket repro in this read-only review.

## Solution Assessment

Unclear as originally requested. Preserving arbitrary client-declared scopes for any valid shared-token WebSocket client is risky; a configured token-scope or paired-device policy is the safer maintainable direction.
