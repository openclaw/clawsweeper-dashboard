## Summary

Keep open: current main and the latest release still clear device-less shared-token/password WebSocket operator scopes outside narrow preservation paths, checked-in tests assert the missing-scope behavior, and the remaining fix is a Gateway auth/security policy decision rather than conservative cleanup.

## What This Changes

The issue reports that non-local WebSocket clients with valid shared-token auth lose requested operator scopes and then fail write-scoped methods such as `chat.send`.

## Best Possible Solution

Keep this open until maintainers land a security-reviewed Gateway policy, likely configured token scopes or a device-bound trust path, with proof for non-local shared-token WebSocket clients instead of trusting self-declared scopes by default.
