## Summary

Keep open: current main and the latest release still clear scopes for device-less shared-token/password WebSocket operator sessions outside narrow trusted-local exceptions, and checked-in tests still assert the resulting missing-scope behavior. The remaining fix is a security-sensitive Gateway auth policy decision rather than conservative cleanup closure.

## What This Changes

The issue reports that non-local WebSocket clients authenticated with a valid gateway token lose requested operator scopes before write-scoped calls such as chat.send.

## Best Possible Solution

Keep this issue open until maintainers choose and land a bounded Gateway token-scope or device-token policy with docs, tests, security review, and real Gateway proof, likely through https://github.com/openclaw/openclaw/pull/81792 or a successor.
