## Summary

Keep open: current main and v2026.6.11 still clear device-less token/password WebSocket operator scopes by default, checked-in tests assert the resulting missing-scope behavior, and the remaining fix is a Gateway auth/security policy decision rather than cleanup-closeable stale work.

## What This Changes

The issue asks OpenClaw to preserve operator scopes for non-local WebSocket clients that authenticate with a valid Gateway token so `chat.send` and other write-scoped calls do not fail.

## Best Possible Solution

Keep this issue open until maintainers land a bounded, security-reviewed Gateway token-scope or device-identity policy with tests, docs, and real Gateway proof, likely through https://github.com/openclaw/openclaw/issues/80836 and https://github.com/openclaw/openclaw/pull/81792 or a successor.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 still clear scopes for device-less token/password operator connections outside narrow exceptions, and checked-in tests expect the resulting missing-scope behavior.

## Solution Assessment

No for unconditional self-declared scope retention. The maintainable path is a security-reviewed Gateway policy such as configured token scopes or a device-bound trust path, because current docs and tests intentionally clear device-less self-declared scopes by default.
