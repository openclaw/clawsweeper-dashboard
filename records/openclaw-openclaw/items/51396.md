## Summary

Keep open: current main and the latest release still clear device-less shared-token/password WebSocket operator scopes, checked-in Gateway tests assert the resulting missing-scope behavior, and the remaining fix is tied to security/product-sensitive Gateway auth work rather than conservative cleanup closure.

## What This Changes

The issue reports that non-local shared-token WebSocket operator clients lose requested operator scopes after successful auth, causing write-scoped calls such as chat.send to fail.

## Best Possible Solution

Resolve the canonical Gateway auth behavior with a maintainer-approved bounded token-scope or device-token contract, then land source, tests, docs, and real Gateway proof before closing this issue.

## Reproduction Assessment

Yes, at source level: current main clears device-less shared-token/password WebSocket operator scopes, and checked-in tests assert the resulting missing-scope behavior. I did not run a live LAN/tailnet Gateway scenario because this review is read-only.

## Solution Assessment

No for unconditional retention of client-declared scopes. The safer path is a bounded maintainer-approved token-scope or device-token contract rather than trusting remote device-less operator scope claims by default.
