## Summary

Keep open: current `main` and the latest release still clear scopes for device-less shared-token/password WebSocket operator connections, checked-in tests assert the resulting missing-scope behavior, and the remaining fix is security/product-sensitive with an unmerged related tokenScopes path.

## What This Changes

The issue asks OpenClaw to stop stripping operator scopes from non-local, token-authenticated Gateway WebSocket clients so write-scoped methods such as `chat.send` continue to work after a valid handshake.

## Best Possible Solution

Keep this issue open as the canonical bug report until a maintainer-approved Gateway auth patch or bounded token-scope policy lands with source, docs, and regression proof for remote token-auth operator clients.

## Reproduction Assessment

Yes. Current source and tests show device-less shared-token/password operator connections can be allowed while their requested scopes are cleared, which produces the reported missing-scope behavior for write methods.

## Solution Assessment

No, not as a cleanup close. The best path is to keep the issue open until maintainers resolve the security boundary through a bounded Gateway auth fix or token-scope contract.
