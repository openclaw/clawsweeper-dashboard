## Summary

Keep open: current main and the latest release still clear device-less shared-token/password WebSocket operator scopes outside narrow trusted-local exceptions, and checked-in tests assert the resulting missing-scope behavior. The remaining fix is Gateway auth/security policy work with related open design and implementation paths, not conservative cleanup closure.

## What This Changes

The issue requests preserving operator scopes for non-local WebSocket clients that authenticate with a valid shared token so write-scoped methods such as chat.send can succeed.

## Best Possible Solution

Keep this issue open until maintainers land a bounded, security-reviewed Gateway token-scope or device-token policy with tests, docs, and real Gateway proof.

## Reproduction Assessment

Yes, at source level. Current main still clears scopes for device-less token/password operator WebSocket connections outside narrow exceptions, and checked-in tests expect the resulting missing-scope behavior; I did not run a live remote WebSocket repro.

## Solution Assessment

No for unconditional retention of client-declared scopes. The safer solution is a bounded maintainer-approved token-scope or device-token contract rather than trusting remote device-less operator scope claims by default.
