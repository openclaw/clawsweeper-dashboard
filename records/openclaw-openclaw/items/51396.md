## Summary

Keep open: current main and v2026.6.11 still clear device-less shared-token WebSocket operator scopes outside narrow preservation exceptions, and the checked-in Gateway auth baseline still asserts the resulting missing-scope behavior. The remaining fix changes the Gateway auth/security boundary and overlaps an open token-scope design path, so this needs maintainer review rather than cleanup closure.

## What This Changes

The issue asks OpenClaw to retain operator scopes for non-local shared-token WebSocket clients with valid token auth so write-scoped RPCs such as `chat.send` work.

## Best Possible Solution

Resolve this through a maintainer-approved bounded token-scope or device-token contract, likely via https://github.com/openclaw/openclaw/pull/81792 or a successor, with Gateway security bounds, docs, tests, and real Gateway proof.
