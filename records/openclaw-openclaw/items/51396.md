## Summary

Keep open: current main and v2026.6.11 still clear device-less shared-token WebSocket operator scopes before scoped RPCs, and the related token-scopes implementation remains open, conflicting, and security/product-gated rather than merged.

## What This Changes

The issue asks OpenClaw to preserve effective operator scopes for valid non-local token-auth WebSocket operator clients so write-scoped calls such as chat.send do not fail after hello-ok.

## Best Possible Solution

Resolve this through a bounded Gateway auth contract, such as the tokenScopes PR or a successor device-token policy, with Gateway/security approval, docs, focused tests, and redacted real Gateway proof before closing the issue.

## Reproduction Assessment

Yes, at source level: current main clears device-less shared-token/password WebSocket operator scopes and checked-in tests assert the resulting missing-scope behavior. I did not run a live LAN/tailnet Gateway scenario in this read-only review.

## Solution Assessment

No for unconditional retention of client-declared scopes. The safer solution is a bounded maintainer-approved token-scope or device-token contract rather than trusting remote device-less operator scope claims by default.
