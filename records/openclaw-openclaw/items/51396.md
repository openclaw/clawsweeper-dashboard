## Summary

Keep open: current main and v2026.6.11 still clear device-less shared-token/password WebSocket operator scopes, and checked-in tests/docs assert the resulting missing-scope behavior; the remaining resolution needs Gateway/security product approval rather than cleanup closure.

## What This Changes

The issue requests preserving effective operator scopes for non-local, device-less clients that authenticate successfully with a shared Gateway token/password so write-scoped methods such as chat.send do not fail.

## Best Possible Solution

Resolve this with a maintainer-approved, bounded server-derived token-scope or device-token contract, plus focused Gateway tests, docs, and real remote Gateway proof before closing the issue.

## Reproduction Assessment

Yes, at source level: current main clears device-less shared-token/password WebSocket operator scopes and checked-in tests expect the resulting missing-scope behavior. I did not run a live LAN or tailnet Gateway scenario in this read-only review.

## Solution Assessment

No for unconditional retention of client-declared scopes. The safer maintainable fix is a bounded server-derived token-scope or device-token contract approved by Gateway/security owners.
