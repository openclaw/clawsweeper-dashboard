## Summary

Keep open: current main and the latest release still clear device-less shared-token/password WebSocket operator scopes outside narrow named exceptions, checked-in tests assert the resulting missing-scope behavior, and the remaining fix is a Gateway auth/security-boundary decision rather than cleanup-closeable work.

## What This Changes

The issue asks OpenClaw to preserve operator scopes for non-local WebSocket clients that authenticate with a valid gateway token so write-scoped methods such as chat.send keep working.

## Best Possible Solution

Keep this issue open until maintainers land a security-reviewed Gateway token-scope or device-identity policy, likely through https://github.com/openclaw/openclaw/issues/80836 and https://github.com/openclaw/openclaw/pull/81792 or a successor, with tests that cover both fresh and upgrade behavior.

- **Retain client-declared scopes:** Allow valid shared-token clients to keep requested scopes directly, accepting the broader shared-secret authorization boundary.
- **Require device identity for write scopes:** Keep the current fail-closed behavior and require device pairing or another identity-bearing path for operator.write/admin use.

## Solution Assessment

No for unconditional self-declared scope retention. The maintainable path is a security-reviewed Gateway policy such as configured token scopes or a device-bound trust path, because current docs and tests intentionally clear device-less self-declared scopes by default.
