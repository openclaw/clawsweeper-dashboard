## Summary

Keep open: current main and the latest release still clear device-less shared-token/password WebSocket operator scopes for generic clients, checked-in tests assert the resulting missing-scope behavior, and the remaining fix is a Gateway auth/security policy decision rather than conservative cleanup closure.

## What This Changes

The issue asks OpenClaw to preserve requested operator scopes for non-local WebSocket clients that authenticate with a valid shared token.

## Best Possible Solution

Settle a bounded shared-token scope policy: either land a reviewed `tokenScopes`/device-identity path with docs and upgrade proof, or document that remote shared-token clients must use device identity or explicitly configured scopes instead of self-declared connect scopes.
