## Summary

Keep open: current main and v2026.6.11 still keep Gateway LAN/custom bind paths IPv4-only, and the prior dual-stack implementation attempts were closed unmerged. The remaining work is valid, but it needs maintainer product/security direction because native IPv6 or dual-stack listening changes non-loopback Gateway exposure.

## What This Changes

Request native IPv6 or dual-stack Gateway listening for LAN/custom bind paths instead of the current IPv4-only listener behavior.

## Best Possible Solution

Define an explicit IPv6/dual-stack Gateway bind contract, then update bind resolution, listen-host creation, custom host validation, CLI probes/status, docs, tests, and security guardrails together.
