## Summary

Keep open: current main and v2026.6.11 still bind Gateway LAN/custom BYOH paths over IPv4-only addresses, so native IPv6 or dual-stack listening remains unsolved and needs maintainer product/security direction.

## What This Changes

The issue asks for Gateway bind mode to support IPv6 listening for LAN/BYOH deployments.

## Best Possible Solution

Define an explicit Gateway IPv6/dual-stack bind contract, then update bind resolution, listen-host creation, custom-host validation, CLI probes/status, docs, tests, and security guardrails together.

- **Keep IPv4-only core:** Leave core bind behavior IPv4-only and continue documenting reverse-proxy or sidecar workarounds for IPv6-only platforms.

## Solution Assessment

Unclear. Native IPv6 or dual-stack binding is plausible, but flipping lan directly to :: is only one option; the safer path depends on the maintainer-chosen exposure and upgrade contract.
