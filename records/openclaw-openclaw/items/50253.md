## Summary

Keep open: current main and the latest release still keep the Gateway LAN/custom BYOH bind path IPv4-only, while prior dual-stack PRs were closed unmerged. The request is valid and source-reproducible, but native IPv6 support needs maintainer product/security direction before implementation.

## What This Changes

Request native Gateway IPv6 or dual-stack listening for `bind=lan` and related non-loopback Gateway bind paths.

## Best Possible Solution

Define the Gateway IPv6/dual-stack bind contract first, then update bind resolution, listen-host creation, custom host validation, status/probe output, docs, and cross-platform socket coverage together.

## Reproduction Assessment

Yes. Source inspection shows `lan` resolves to `0.0.0.0`, non-loopback listen hosts are not expanded to IPv6, and `customBindHost` is IPv4-only on current main; I did not run a live IPv6 deployment.

## Solution Assessment

Unclear. Native IPv6 or dual-stack binding is plausible, but the best implementation depends on maintainer direction for exposure semantics, compatibility, and cross-platform socket behavior.
