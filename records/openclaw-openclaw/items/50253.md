## Summary

Keep open: current main and v2026.6.11 still implement and document Gateway LAN/custom BYOH binds as IPv4-only, while prior dual-stack PRs were closed unmerged. The request is valid, but native IPv6 or dual-stack Gateway listening needs maintainer product/security direction before implementation.

## What This Changes

Add native IPv6 or dual-stack support for Gateway `--bind lan` and related custom bind listening.

## Best Possible Solution

Define an explicit Gateway IPv6/dual-stack bind contract, then update bind resolution, listen-host creation, custom-host validation, CLI probes/status, docs, tests, and security guardrails together.
