## Summary

Keep open: current main and v2026.6.11 still implement and document Gateway LAN/custom BYOH binds as IPv4-only, and the remaining IPv6/dual-stack behavior needs maintainer product/security direction before a safe fix PR.

## What This Changes

Request native IPv6 or dual-stack listening support for Gateway LAN/custom BYOH bind mode.

## Best Possible Solution

Define an explicit Gateway IPv6/dual-stack bind contract, then update bind resolution, listen-host creation, custom-host validation, CLI probes/status, docs, tests, and security guidance together.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Which Gateway IPv6 bind contract should OpenClaw expose for LAN/custom BYOH deployments?

Rationale: Current source and docs intentionally describe this path as IPv4-only, while native IPv6 or dual-stack listening changes non-loopback reachability and upgrade expectations.

Likely owner: steipete

Owner reason: Recent Gateway bind and BYOH documentation history points to this area, though security review should also be involved before implementation.

Owner confidence: high

Options:

- **Add Explicit Opt-In Contract (recommended):** Introduce a documented IPv6 or dual-stack bind path with security warnings, platform listener semantics, and fresh-install plus upgrade proof.
- **Change LAN/Custom In Place:** Make existing `lan` or `customBindHost` accept IPv6 directly, accepting the compatibility and exposure risk as the new behavior for those modes.
- **Keep Core IPv4-Only:** Leave core bind behavior IPv4-only and continue documenting reverse-proxy or sidecar workarounds for IPv6-only platforms.

## Reproduction Assessment

Yes. Current main resolves LAN to `0.0.0.0`, does not expand non-loopback listen hosts to IPv6, and rejects IPv6 `customBindHost` values; the same behavior is present in v2026.6.11.

## Solution Assessment

Unclear until maintainers choose the exposure contract. A direct `lan` swap to `::` is plausible but not proven best because it changes security and platform semantics for existing non-loopback deployments.
