Keep open: current main and the latest release still make the Gateway LAN/custom BYOH bind path IPv4-only, and the dual-stack implementation PRs found in the related cluster are closed unmerged. ## What This Changes

The issue requests native IPv6 or dual-stack listening for Gateway LAN bind mode.

## Best Possible Solution

Define the Gateway IPv6/dual-stack bind contract, then update bind resolution, listen host creation, custom host validation, status/probe output, docs, and cross-platform socket coverage together.

## Reproduction Assessment

Yes. Source inspection shows `lan` resolves to `0.0.0.0`, non-loopback hosts are passed through as a single listener, and `customBindHost` is IPv4-only on current main; I did not run a live IPv6 deployment.

## Solution Assessment

Unclear. Native IPv6 or dual-stack binding is plausible, but changing `lan` straight to `::` needs maintainer choice on exposure semantics, platform compatibility, and upgrade behavior before it is the best fix.
