## Summary

This PR is still necessary: current `main` retains the entity- and surrogate-safe hard cut, while this branch adds the missing word-boundary preference. The prior P1 concern does not apply after tracing the caller: the splitter invokes the new helper only for text segments between recognized HTML tags, so whitespace inside tag attributes is never eligible as a boundary.

## What This Changes

The PR makes Telegram’s rendered-HTML chunker prefer newline or whitespace boundaries before its existing safe hard-cut fallback, with tests for ordinary words and oversized single tokens.

## System Context

Telegram renders outbound Markdown into Telegram-safe HTML, then splits that rendered output to fit Telegram message limits. The HTML splitter preserves entities, UTF-16 characters, and tag balance before sending each resulting chunk as a Telegram message.
