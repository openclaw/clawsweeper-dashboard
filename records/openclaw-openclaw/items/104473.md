## Summary

Keep this PR open, but do not merge it as written: the new raw-HTML whitespace scan can select a space inside an opening tag’s attributes, producing a chunk boundary inside markup. The supplied Mantis Telegram Desktop evidence is credible real-behavior proof for the ordinary case, but it does not cover this newly introduced HTML-markup edge case.

## What This Changes

This PR makes Telegram’s rendered-HTML chunk splitter prefer newline or whitespace boundaries before using its existing entity- and surrogate-safe hard-cut fallback, and adds regression tests for ordinary words and oversized single tokens.

## System Context

Telegram renders outbound Markdown into Telegram HTML and then divides that HTML into messages within Telegram’s size limit. The splitter must preserve text, entities, Unicode pairs, and valid markup so each resulting message can be delivered and parsed independently.

## Best Possible Solution

Choose word boundaries only from rendered text nodes, never raw markup, and add regression coverage for a long link or formatted element whose opening tag contains attribute whitespace before the first visible break.
