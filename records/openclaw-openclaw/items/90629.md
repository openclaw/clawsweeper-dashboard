## Summary

Keep open: current main and v2026.6.11 still keep heartbeat `lastTo` inheritance behind same-channel matching or an explicit allow-mismatch flag, while the direct fix attempt in https://github.com/openclaw/openclaw/pull/95021 is closed unmerged and the open qqbot reconnect PR only partially overlaps this failure mode.

## What This Changes

The issue asks for heartbeat poll final text from QQ C2C sessions to be delivered automatically to the QQ user instead of requiring an explicit `message(action=send, channel="qqbot", target="c2c:...")` call.

## Best Possible Solution

Keep the strict cross-channel default unless maintainers explicitly approve a heartbeat-specific delivery rule with QQ C2C live proof and regression tests; otherwise document explicit `target`/`to` or message-tool delivery as the required path.
