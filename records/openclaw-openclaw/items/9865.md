## Summary

Keep open. Current main and the latest release still lack first-class provider Batch API routing for delayed/background agent turns, and the issue remains the canonical product/API tracker rather than a stale or already-implemented request.

## What This Changes

The issue requests opt-in provider Batch API routing for background or async agent work such as cron jobs, heartbeats, and subagents to reduce provider cost.

## Best Possible Solution

Define one delayed/batch agent-turn lifecycle shared by provider runtime and the public Plugin SDK, then expose explicit opt-ins for cron, heartbeat, sessions, and subagents with provider implementations, docs, accounting, fallback, cancellation, and delayed delivery semantics.

## Reproduction Assessment

Not applicable: this is a feature request, and source inspection shows current main has no delayed/batch opt-in or provider lifecycle to reproduce as broken existing behavior.

## Solution Assessment

No current implementation path is selected; a cron-only or provider-local flag would be too narrow because the missing piece is a shared delayed-turn provider/runtime and Plugin SDK contract.
