## Summary

Keep open. Current main still lacks first-class provider Batch API routing for delayed/background agent turns, and the live discussion already treats this as the canonical tracker rather than a fixed or safely auto-repairable item.

## What This Changes

Request support for provider Batch APIs for non-real-time background work such as cron jobs, heartbeats, scheduled maintenance, and subagents.

## Best Possible Solution

Define one additive delayed/batch agent-turn contract in provider runtime and the Plugin SDK, then expose explicit opt-ins for cron, sessions_send, sessions_spawn/subagents, and heartbeat/background runs with provider implementations, docs, accounting, cancellation, fallback, and delayed-delivery semantics.
