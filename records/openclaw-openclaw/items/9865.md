## Summary

Current main and v2026.6.11 still lack first-class provider Batch API execution for agent turns, so this remains the canonical feature tracker; implementation should wait for a maintainer decision on the shared delayed-turn lifecycle and initial opt-in surfaces.

## What This Changes

Add opt-in provider Batch API execution for latency-tolerant cron, heartbeat, scheduled-maintenance, and subagent workloads.

## Best Possible Solution

Define one additive, durable delayed-turn lifecycle in the provider runtime and public Plugin SDK, keep provider-specific Batch API transport in provider plugins, and initially expose it only on background entry points with explicit persistence, cancellation, accounting, fallback, and delivery semantics.
