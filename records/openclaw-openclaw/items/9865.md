## Summary

This issue is still necessary and remains the canonical tracker. Current main continues to model provider inference as immediate streaming turns, while cron, heartbeat, and subagent execution lack a durable Batch API submit/poll/cancel/result lifecycle; the remaining blocker is maintainer agreement on the public delayed-turn contract and initial scope.

## What This Changes

Requests opt-in provider Batch API execution for latency-tolerant cron jobs, subagents, heartbeats, and other background agent tasks.

## Best Possible Solution

Add one generic, additive delayed-agent-turn lifecycle to the public provider Plugin SDK, persist pending work in the canonical SQLite state store, and initially expose it to isolated cron jobs with explicit provider eligibility, accounting, cancellation, failure, restart-recovery, and delivery semantics; expand to heartbeats and subagents only after that contract is proven.

- **Defer Batch API support:** Keep immediate streaming turns as the only supported agent execution mode and leave discounted batch workloads outside OpenClaw for now.
