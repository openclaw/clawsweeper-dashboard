## Summary

Keep open as the canonical tracker. The latest review context reports that current main still has no delayed Batch API lifecycle for agent turns, while the related batch-routing reports were closed as duplicates rather than shipped fixes; choosing the public provider/runtime contract and first supported caller still requires maintainer direction.

## What This Changes

Add opt-in Batch API execution for latency-tolerant background agent work, initially proposed for cron jobs, subagents, and heartbeats.

## Best Possible Solution

Design an additive delayed-turn provider/runtime and Plugin SDK contract, then pilot it with isolated cron agentTurn jobs before considering session, subagent, or heartbeat callers.
