## Summary

Keep open. Current main still lacks first-class delayed/provider Batch API routing for background agent turns; the only provider Batch API code I found is scoped to memory embeddings, and the related closed reports remain duplicate context rather than shipped fixes.

## What This Changes

Request to add provider Batch API support for non-real-time background agent work, including cron jobs, subagents, and heartbeat/background runs.

## Best Possible Solution

Define an additive delayed/batch agent-turn contract in provider runtime and the public Plugin SDK, then expose explicit opt-ins for cron, sessions_send, sessions_spawn/subagents, and heartbeat/background runs with provider implementations and docs.

## Reproduction Assessment

Not applicable: this is a feature request rather than broken existing behavior. Source inspection gives high-confidence evidence that current main has no delayed/batch agent-turn opt-in or provider lifecycle.

## Solution Assessment

No current implementation path is selected. The best fix needs a maintainer-approved generic delayed-turn contract rather than a provider-local or cron-only flag.
