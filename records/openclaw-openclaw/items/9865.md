## Summary

Keep open. Current main still lacks first-class provider Batch API routing for delayed/background agent turns, and this issue remains the canonical product/API tracker rather than something already fixed or safely auto-repairable.

## What This Changes

Request support for routing latency-tolerant background agent turns such as cron jobs, subagents, and heartbeat work through provider Batch APIs via explicit opt-in behavior.

## Best Possible Solution

Define an additive delayed/batch agent-turn contract in provider runtime and the Plugin SDK, then expose explicit opt-ins for cron, sessions_send, sessions_spawn/subagents, and heartbeat/background runs with provider implementations, docs, accounting, cancellation, fallback, and delayed delivery semantics.
