## Summary

Keep open as the canonical product tracker. The supplied current review context still identifies no delayed Batch API lifecycle for agent turns, and the request requires a maintainer-owned decision on provider/runtime and Plugin SDK contracts before a safe implementation can be scoped.

## What This Changes

Add opt-in provider Batch API execution for latency-tolerant background agent work, including cron jobs, heartbeats, and subagents.

## System Context

OpenClaw background work enters through cron, session, subagent, and heartbeat surfaces, then uses the shared provider runtime to execute an agent turn and deliver its result. Batch execution would need to preserve the existing session, cancellation, accounting, provider-auth, and delivery contracts while allowing delayed provider completion.

## Architecture Diagram

flowchart LR
  A[Background work request] --> B[Cron, session, subagent, or heartbeat]
  B --> C[Agent-turn routing]
  C --> D{Immediate or delayed mode}
  D --> E[Provider runtime]
  E --> F[Result, cancellation, and accounting]
  F --> G[Session and delivery output]

## Best Possible Solution

Define one additive delayed-agent-turn contract at the provider/runtime and public Plugin SDK boundary, initially support a narrowly chosen background caller such as isolated cron jobs, then add provider implementations and documented delivery, cancellation, accounting, and upgrade semantics.
