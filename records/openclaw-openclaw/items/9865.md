## Summary

Current main and v2026.6.11 still expose immediate stream-oriented agent turns without a provider Batch API lifecycle, and no newer PR owns the work. This remains a valid feature request, but its cross-cutting public contract and long-lived run semantics require maintainer product/API direction before implementation.

## What This Changes

Add opt-in provider Batch API routing for latency-tolerant cron, heartbeat, subagent, and other background agent turns.

## Best Possible Solution

Approve and design one additive provider-neutral delayed-turn lifecycle in the public plugin contract, then let provider plugins implement Batch APIs while cron, sessions, subagents, and heartbeat callers opt in through shared durable semantics.
