## Summary

Keep open: current main still has loop detection, channel tool allow/deny policy, and `sessions_spawn`, but not the requested per-channel max-per-turn tool-call budget or `warn`/`block`/`auto-delegate` overflow behavior. The remaining work is a product and security design decision rather than conservative cleanup closure.

## What This Changes

Request a per-channel tool-call budget config that can warn, block, or automatically delegate overflow work to a subagent.

## Best Possible Solution

Define a generic scoped tool-call budget model that composes with tool, channel, sandbox, and subagent policy; ship deterministic warn/block enforcement first, then design automatic delegation around `sessions_spawn` authority and completion handoff.
