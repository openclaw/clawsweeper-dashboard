## Summary

Keep open: current main and the latest release still have adjacent loop detection, trusted before-tool policy, per-channel allow/deny tool policy, and explicit `sessions_spawn`, but not the requested channel-scoped max-per-turn tool-call budget or `warn`/`block`/`auto-delegate` overflow behavior. The remaining work is a product and security design item, not conservative cleanup closure.

## What This Changes

The issue requests per-channel tool-call budgets that can warn, block, or automatically delegate overflow work to a subagent.

## Best Possible Solution

Define a generic scoped tool-call budget model that composes with global, agent, provider, channel/group, sandbox, trusted-policy, and subagent rules; ship deterministic warn/block enforcement first, then design auto-delegation separately around `sessions_spawn` authority and completion handoff.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction of the missing capability: current config and before-tool-call paths do not expose or enforce a channel-scoped tool-call budget. I did not run a live Discord/Telegram scenario because the central gap is the absent config and enforcement surface.

## Solution Assessment

No, the proposed channel-local JSON shape is a useful sketch but not enough by itself. The maintainable solution should resolve generic scoped policy precedence and deterministic warn/block behavior before adding automatic subagent creation.
