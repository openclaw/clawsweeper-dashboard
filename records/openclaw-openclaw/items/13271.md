## Summary

Keep open: current main still lacks channel-scoped per-turn tool-call budgets and the requested warn, block, and auto-delegation overflow behavior. Existing loop detection, channel tool allow/deny policy, bot-loop budgets, OpenResponses `max_tool_calls`, and `sessions_spawn` are adjacent pieces, but none closes the central request; this needs maintainer product and security design.

## What This Changes

Feature request for per-channel tool-call budgets with warn, block, and auto-delegation overflow behavior.

## Best Possible Solution

Define a generic scoped tool-call budget model with explicit precedence and per-turn accounting, ship deterministic warn/block enforcement first in the trusted before-tool path, and design auto-delegation separately around `sessions_spawn`, sandbox/tool inheritance, child-run tracking, and completion handoff.

## Reproduction Assessment

Yes for the source-level feature gap: current main has no channel-scoped per-turn tool-call budget or overflow action in the config and before-tool path. This is not a broken existing behavior repro; the Discord stability examples are product context for the requested feature.

## Solution Assessment

No for the literal one-step config plus immediate auto-delegation shape because it crosses security, channel delivery, and subagent authority boundaries. The maintainable path is staged generic budget enforcement first, then separately approved auto-delegation semantics.
