## Summary

Keep open: current main and the latest release still have adjacent loop detection, channel/group tool allow/deny policy, and explicit `sessions_spawn`, but not the requested channel-scoped per-turn tool budget or warn/block/auto-delegate overflow behavior. This remains a valid security-sensitive feature and config design item, not conservative cleanup closure.

## What This Changes

Request a per-channel tool-call budget config that can warn, block, or auto-delegate overflow work to a subagent after a channel-specific per-turn limit.

## Best Possible Solution

Define a generic scoped tool-budget model with explicit precedence and per-turn accounting; ship deterministic warn/block enforcement first in the trusted before-tool path, then separately design auto-delegation around `sessions_spawn`, sandbox/tool inheritance, child-run tracking, cancellation, and completion handoff.

## Reproduction Assessment

Yes for the source-level feature gap, not as a broken-behavior runtime repro: current config, before-tool, Discord channel, and subagent code show no channel-scoped per-turn budget or overflow handling. The reported Discord stability motivation remains production-context evidence rather than a live reproduction in this review.

## Solution Assessment

Unclear for the literal proposed config plus immediate auto-delegate behavior: the goal is sound, but the combined gateway interception and child-session authority needs maintainer product and security design. The safer path is staged warn/block enforcement first, then a separately approved auto-delegation contract.
