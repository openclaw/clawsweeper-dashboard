## Summary

Keep open: current main and the latest release still have adjacent loop detection, per-channel allow/deny tool policy, and explicit `sessions_spawn`, but they do not implement a channel-scoped max-per-turn tool-call budget or the requested warn/block/auto-delegate overflow behavior. The remaining work is a product and security design item, not conservative cleanup closure.

## What This Changes

The issue requests a per-channel tool-call budget configuration with warn, block, and automatic sub-agent delegation overflow behavior.

## Best Possible Solution

Define a generic scoped tool-call budget model that composes with global, agent, provider, channel/group, sandbox, trusted-policy, and subagent rules; ship deterministic warn/block enforcement first, then design auto-delegation separately around `sessions_spawn` authority and completion handoff.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction of the missing capability: current config and before-tool-call paths do not expose or enforce a channel-scoped tool-call budget.

## Solution Assessment

No. The proposed channel-local JSON shape is a useful sketch, but the maintainable solution should resolve generic scoped policy precedence and deterministic warn/block behavior before adding automatic subagent creation.
