## Summary

Keep open: current main still has adjacent loop detection, channel/group allow-deny policy, and `sessions_spawn`, but not a channel-scoped max-per-turn tool-call budget or the requested warn/block/auto-delegate overflow behavior. This remains valid feature work, but it needs maintainer product and security design rather than conservative cleanup closure.

## What This Changes

Request a per-channel tool-call budget that can warn, block, or automatically delegate overflow work to a subagent.

## Best Possible Solution

Define a generic scoped tool-budget model with explicit policy precedence and per-turn accounting; ship deterministic warn/block enforcement in the trusted before-tool path first, then separately approve auto-delegation semantics around `sessions_spawn`, sandbox/tool inheritance, child-run tracking, and completion handoff.
