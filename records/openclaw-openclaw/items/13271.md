## Summary

Keep open: current main still lacks channel-scoped max-per-turn tool-call budgets and the requested warn, block, or auto-delegate overflow behavior. The issue remains useful as the canonical per-channel budget tracker, separate from the open global iteration-budget and pre-tool routing design items.

## What This Changes

Request a per-channel tool-call budget that can warn, block, or auto-delegate remaining work after a configured per-turn limit is reached.

## Best Possible Solution

Define a generic scoped tool-budget model with explicit precedence and per-turn accounting; ship deterministic warn/block enforcement first in the trusted before-tool path, then separately design auto-delegation around sessions_spawn, sandbox/tool inheritance, child-run tracking, and completion handoff.

## Reproduction Assessment

Yes for the source-level feature gap: current main has no channel-scoped per-turn budget or overflow handling in the config/before-tool path. This is not a broken existing behavior repro; the Discord stability examples are production context for the requested feature.

## Solution Assessment

No for the literal single-step config plus immediate auto-delegation shape: the combined gateway interception and child-session behavior is too security- and routing-sensitive to land without design. The maintainable path is staged generic budget enforcement first, then separately approved auto-delegation semantics.
