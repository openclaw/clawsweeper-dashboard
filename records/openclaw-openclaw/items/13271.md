## Summary

Keep open: current main and latest release still have adjacent loop detection, channel tool allow/deny policy, and explicit `sessions_spawn`, but not a channel-scoped max-per-turn tool-call budget or the requested `warn`/`block`/`auto-delegate` overflow behavior. This remains a product and security design item rather than cleanup closure.

## What This Changes

Request a per-channel tool-call budget config that can warn, block, or automatically delegate overflow work to a subagent.

## Best Possible Solution

Define a generic scoped tool-call budget model that composes with existing tool, channel, sandbox, and subagent policies; ship deterministic warn/block enforcement first, then design auto-delegation separately around `sessions_spawn` authority and completion handoff.
