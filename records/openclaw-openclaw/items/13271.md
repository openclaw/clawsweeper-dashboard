## Summary

Keep open: current main and v2026.6.11 still lack a channel-scoped per-turn tool-call budget and the requested warn/block/auto-delegate overflow behavior. The request is valid, but it needs maintainer product and security design because automatic delegation would create a new child-session authority path.

## What This Changes

Request per-channel max-per-turn tool-call budgets with warn, block, and auto-delegate overflow behavior.

## Best Possible Solution

Define a generic scoped tool-budget model with explicit precedence and per-turn accounting; ship deterministic warn/block enforcement first in the trusted before-tool path, then separately design auto-delegation around sessions_spawn authority, sandbox/tool inheritance, child-run tracking, and completion handoff.

## Reproduction Assessment

Yes for the source-level feature gap: current main has no channel-scoped per-turn budget or overflow handling in the config/before-tool path. This is not a broken existing behavior repro; the Discord stability examples are production context for the requested feature.

## Solution Assessment

No for the literal single-step config plus immediate auto-delegation shape: the combined gateway interception and child-session behavior is too security- and routing-sensitive to land without design. The maintainable path is staged generic budget enforcement first, then separately approved auto-delegation semantics.
