## Summary

Keep this PR open for correction: it advertises `kimi/k3-256k` as a distinct Kimi API model, but Kimi’s current documentation lists `k3` as the only K3 model ID and describes 256K as a plan-dependent context limit for that same ID. The proposed catalog entry would let users choose an identifier that Kimi documents as invalid rather than solving the lower-tier context case.

## What This Changes

The PR adds `kimi/k3-256k` to the Kimi Coding provider catalog, updates K3 thinking and catalog tests, and revises provider documentation to present it as a separate 256K model option.

## System Context

The Kimi Coding plugin turns OpenClaw provider selections into Anthropic-compatible requests to Kimi Code. Its model catalog controls which model references users can select, their advertised limits, and the outbound model ID sent to the remote API.

## Best Possible Solution

Keep one canonical K3 model reference, `kimi/k3`, document that its available context is subscription-tier dependent, and remove the unsupported `k3-256k` catalog, tests, and documentation references before merge.
