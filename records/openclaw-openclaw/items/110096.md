## Summary

Keep this PR open: the implementation appears narrow and correct, but its mock-backed tests and ordinary-DNS curl do not prove that authorization-code exchange and refresh actually succeed through a fake-IP proxy, which remains a merge gate for this auth/security-boundary change.

## What This Changes

Adds an exact-host SSRF policy for OpenAI OAuth token exchange and refresh that permits RFC 2544 and IPv6 unique-local fake-IP ranges, with focused resolver-backed regression tests.

## Best Possible Solution

Keep the exact-host policy, but demonstrate a redacted real OAuth sign-in and token refresh through an actual Clash, Surge, or sing-box fake-IP setup before landing.
