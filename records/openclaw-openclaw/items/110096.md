The related merged callback-cleanup work at https://github.com/openclaw/openclaw/pull/89491 explicitly left fake-IP policy for a separate security decision.

## What This Changes

The branch permits RFC 2544 and IPv6 unique-local fake-IP resolutions only for `auth.openai.com` OAuth token POSTs and adds resolver-backed coverage for authorization-code and refresh-token exchanges.

## Best Possible Solution

Use one approved, exact-host fake-IP policy across every OpenAI OAuth token exchange that is intended to support proxy DNS, retain redirect and unrelated-host rejection, and attach redacted evidence from a real fake-IP-proxy login or refresh flow.
