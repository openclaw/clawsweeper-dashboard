## Summary

Keep this PR open: it removes the unbounded allocation but replaces the shipped approval behavior with an unconditional 8 MiB denial for otherwise valid script operands. The prior P1 remains unresolved, and the posted evidence is focused test/CI output rather than real approval-flow proof.

## What This Changes

The branch caps synchronous hashing of mutable approval-script operands at 8 MiB and returns a denial when the operand cannot be read under that cap.

## Best Possible Solution

Replace the reject-on-size policy with a fixed-buffer, chunked SHA-256 read that preserves approval support for arbitrarily sized regular script files while avoiding whole-file allocation, then prove both the oversized and ordinary approval flows in a redacted live run.
