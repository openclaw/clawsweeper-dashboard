## Label Justifications

- `P1`: The branch targets a hot approval and revalidation path where arbitrarily large operands can still synchronously stall runtime progress.
- `merge-risk: 🚨 availability`: The new loop removes allocation pressure but continues to execute synchronously until EOF on a user-controlled regular file.

## Summary

Keep this PR open: the chunked implementation removes the single-buffer allocation, but it still synchronously hashes every byte of an arbitrarily large operand on both approval and revalidation, so a large file can still stall the hot approval path. The contributor has supplied focused-test and CI claims, but not inspected real runtime behavior proof.

## What This Changes

The PR replaces whole-file synchronous hashing of approved script operands with descriptor-based chunked synchronous hashing and adds acceptance coverage for operands at and above 8 MiB.

## Best Possible Solution

Choose one explicit approval contract: preserve arbitrary-size scripts by moving snapshot and revalidation hashing off the synchronous hot path, or document and test a deliberate operand-size denial policy with an upgrade-safe rationale.
