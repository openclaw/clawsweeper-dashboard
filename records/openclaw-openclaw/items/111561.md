## Summary

The issue remains necessary: current main advertises `kimi/k3[1m]` as a distinct selectable Kimi Code model even though Kimi’s current third-party API contract says that suffix is Claude-Code-environment-only and API clients must send `k3`; the same catalog caps `k3` at 262,144 tokens despite Kimi documenting up to 1,048,576 for eligible accounts.

## What This Changes

Correct the bundled Kimi Code model catalog so it does not expose `k3[1m]` as an API model id and allows eligible `k3` users to use the provider’s documented 1M context window.

## Best Possible Solution

Keep one API model entry for `kimi/k3` with the documented 1,048,576-token maximum, remove `kimi/k3[1m]` from the selectable catalog, and add focused catalog coverage plus a redacted live Kimi check for the accepted wire id and entitlement boundary.
