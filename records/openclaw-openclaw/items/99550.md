## Summary

Current main does not solve the reported latency path: OpenClaw still exposes only the local Codex app-server transport, while the currently bundled Codex 0.142.4 still waits through the upstream WebSocket stream retry budget before activating HTTP fallback. This should stay open for Codex/OpenClaw owner review.

## What This Changes

The issue reports slow Codex/OAuth gpt-5.5 turns because upstream responses_websocket retries consume roughly two minutes before HTTP fallback succeeds.

## Best Possible Solution

Fix or configure the upstream Codex responses transport so failed WebSocket streams fall back to HTTP quickly without reusing the local `appServer.transport` setting for a different layer.
