## What This Changes

The issue reports that async gateway exec approval follow-up output delivered back to the agent is tailed to roughly 400 characters and newline-normalized.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/92185, or an equivalent narrow formatter fix, so approval-completion follow-ups preserve captured multiline output while ordinary background notifications stay compact.

## Reproduction Assessment

Yes for source-level reproduction: the remaining async gateway approval follow-up route still formats output through the 400-character tail and whitespace normalizer on current main. I did not run a live Discord DM reproduction because native Discord approvals now appear to wait inline.

## Solution Assessment

Yes: the narrow fix shape is to separate approval-completion output formatting from compact notifyOnExit summaries, which the open closing PR is already attempting with regression coverage.
