## Summary

Keep open: the linked ACP corruption bug is real, but this PR is not merge-ready because it still emits Gateway replacements as ordinary append-only ACP chunks and the current head fails test type-checking.

## What This Changes

The PR passes Gateway `replace` from chat delta payloads into the ACP translator, resets sent text/thought offsets for replacement deltas, and adds ACP translator regression tests for divergent and shorter revisions.

## Best Possible Solution

Define and implement an ACP-compatible replacement strategy for Gateway replace=true deltas, then prove the rendered client output for divergent and shorter revisions instead of only asserting the second emitted chunk.

Full review comments:

- **[P1] Do not send replacements as append chunks:** `src/acp/translator.ts:1147`
  - body: This resets the slice offset and emits the full replacement through the same `agent_message_chunk` stream. Standard ACP consumers append these chunks: OpenClaw's ACP CLI writes each chunk to stdout, and `@agentclientprotocol/sdk` `ActiveSession.readText()` appends chunk text, so `Hello world` -> `Goodbye world` renders as stale text plus the replacement rather than replacing it. Please implement an ACP-compatible replacement strategy and assert the rendered output, not only the second chunk.
  - confidence: 0.9
- **[P2] Use typed session update assertions:** `src/acp/translator.stop-reason.test.ts:668-670`
  - body: The current head fails `check-test-types` because the new mock-call filters infer `{}`/`unknown` for `p?.update?.sessionUpdate` and for `allChunks[n].update.content.text`. Reuse the existing typed helpers or add a narrow local type guard so the regression tests pass the repository's test-type lane.
  - confidence: 0.98
