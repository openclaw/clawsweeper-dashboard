The PR body supplies focused mocked-test output, not after-fix behavior proof from a configured Gateway/exporter path.

## What This Changes

The PR strips a trailing slash before testing for canonical OTLP signal paths and adds regression coverage for trace, metric, and log endpoints with a trailing slash followed by a query string.

## Best Possible Solution

Separate shared-base resolution from signal-specific override resolution: append `v1/<signal>` only to the shared endpoint, return every nonblank signal-specific config or environment endpoint unchanged, and cover custom paths plus query, fragment, and trailing-slash forms.
