Keep open for maintainer review: current main still lacks the heartbeat `AgentId` handoff, this PR is the current candidate fix for the linked wrong-agent heartbeat bug, and I found no blocking patch defect. ## What This Changes

The branch adds `AgentId` to `runHeartbeatOnce` reply context and tests that a secondary-agent heartbeat under `session.scope: "global"` keeps `SessionKey: "global"` while carrying the configured agent identity.

## Best Possible Solution

Land the narrow `MsgContext.AgentId` handoff if maintainers accept that global-scope heartbeat storage remains `global` while runtime identity resolves from the configured agent; otherwise hold for a broader session-boundary design.
