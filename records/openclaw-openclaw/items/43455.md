## Summary

Keep open: current main and the latest release still document Browserbase as a static generic CDP URL, while the only Sessions API implementation is an open dirty PR with unresolved route, credential, redaction, proof, and product-boundary questions.

## What This Changes

Request to replace the documented static Browserbase `cdpUrl` setup with Browserbase Sessions API lifecycle handling for browser profiles.

## Best Possible Solution

Ship a maintainer-approved Browserbase Sessions API path or a generic browser-backend plugin seam with credential policy, signed URL redaction, cleanup semantics, docs/tests, and live browser-tool proof; otherwise remove or correct the static Browserbase setup from the docs.
