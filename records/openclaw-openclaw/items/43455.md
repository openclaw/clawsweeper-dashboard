- `impact:security`: The affected Browserbase CDP/connect URLs contain API keys or signing material, so the fix must handle credential storage and redaction safely.
- `impact:auth-provider`: The remaining design includes how Browserbase API keys are supplied through env vars, SecretRef, or another credential surface.

## Summary

Keep open: current main and the latest release still document Browserbase as a static remote CDP URL and route it through the generic CDP profile path, while the Browserbase session-API PR remains open, conflicting, and blocked on proof, route coverage, credential, and security decisions.

## What This Changes

The issue asks OpenClaw to replace the documented static Browserbase CDP URL workflow with Browserbase session lifecycle handling that creates or refreshes a session connect URL before CDP attach.

## Best Possible Solution

Land a maintainer-approved Browserbase lifecycle design that resolves fresh connect URLs before every CDP/Playwright attach path, redacts signed URL material, aligns credential handling with SecretRef/security policy, updates docs/schema/tests, and includes redacted live Browserbase browser-tool proof.
