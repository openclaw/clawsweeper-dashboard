## Summary

Keep open: current main and the latest release still document Browserbase as a static `cdpUrl` and resolve it through generic CDP attach logic, while the Browserbase Sessions API fix remains an open, blocked PR with product/security questions.

## What This Changes

The issue asks OpenClaw to replace the documented static Browserbase CDP URL flow with Browserbase Sessions API lifecycle handling.

## Best Possible Solution

Land a maintainer-approved Browserbase Sessions API driver or generic browser-backend seam with credential policy, signed-URL redaction, session cleanup, and live browser-tool proof; otherwise stop recommending the static Browserbase setup in docs.
