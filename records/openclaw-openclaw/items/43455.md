## Summary

Keep open: current main still documents and implements Browserbase as a static remote CDP URL, while the Sessions API fix remains an open PR with unresolved credential, signed-URL, session-lifecycle, and product-boundary questions.

## What This Changes

The issue asks OpenClaw to replace the documented static Browserbase CDP URL setup with Browserbase Sessions API lifecycle handling for connectUrl creation and cleanup.

## Best Possible Solution

Ship or explicitly reject a maintainer-approved Browserbase Sessions path: either a revised first-party driver or a generic browser-backend seam with credential policy, signed URL redaction, cleanup semantics, docs/tests, and live browser-tool proof; otherwise stop advertising the static Browserbase setup as supported.
