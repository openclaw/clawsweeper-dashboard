- `impact:auth-provider`: The remaining design includes how Browserbase API keys are supplied through env vars, SecretRef, or another credential surface.

## Summary

Keep open: current main and the latest release still document Browserbase as a static CDP URL and route it through the generic raw `cdpUrl` path, while the candidate Browserbase session-API PR remains open, conflicting, and blocked on proof plus credential/security decisions.

## What This Changes

The issue requests Browserbase session lifecycle support because the documented static `cdpUrl` integration no longer works reliably and needs session API `connectUrl` resolution.

## Best Possible Solution

Land a maintainer-approved Browserbase lifecycle design that resolves fresh `connectUrl` values for every CDP/Playwright attach path, redacts signed URL material, aligns credential handling with SecretRef/security policy, updates docs/schema/tests, and includes redacted live Browserbase browser-tool proof.
