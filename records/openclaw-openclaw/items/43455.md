## Summary

Keep open: current main and the latest release still document Browserbase as a static remote CDP URL, while the browser profile schema/runtime have no Browserbase Sessions API driver, session creation, connectUrl refresh, or release lifecycle. The open Browserbase driver PR is a plausible candidate, but it is still open and blocked on conflicts, proof, and credential/security decisions, so it should not close this issue yet.

## What This Changes

The issue reports that the documented Browserbase static CDP URL flow returns 404 and asks OpenClaw to create Browserbase sessions and connect to the returned connectUrl automatically.

## Best Possible Solution

Replace the static Browserbase cdpUrl guidance with a maintainer-approved Browserbase session driver or browser-backend plugin seam that handles connectUrl refresh, credential storage/redaction, release lifecycle, docs, and live proof across open/snapshot/act.
