## Summary

Keep open: current main and the latest release still document Browserbase as a static `cdpUrl` profile and route it through the generic CDP path, while the Sessions API fix remains an open, unmerged PR with product/security/proof blockers.

## What This Changes

The issue asks OpenClaw to replace the documented static Browserbase CDP URL flow with Browserbase Sessions API lifecycle handling that creates or resolves a fresh `connectUrl` before browser tool attaches.

## Best Possible Solution

Land a maintainer-approved Browserbase Sessions API driver or generic browser-backend/plugin seam with credential policy, signed-URL redaction, session cleanup, and live browser-tool proof; until then, stop recommending the static Browserbase setup as a working path.
