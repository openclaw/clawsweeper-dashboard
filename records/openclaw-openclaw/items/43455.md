## Summary

Keep open: current main and v2026.6.11 still document Browserbase as a static CDP URL and route profiles through the generic CDP path, while the open Sessions API candidate PR remains blocked on conflicts, proof, security, and product-boundary decisions.

## What This Changes

The issue asks OpenClaw to replace the documented static Browserbase CDP URL flow with Browserbase session lifecycle handling that creates or resolves a fresh connect URL before CDP attach.

## Best Possible Solution

Land a maintainer-approved Browserbase Sessions API driver or browser-backend/plugin seam with credential policy, signed-URL redaction, session cleanup, and live browser-tool proof; otherwise revise the public docs so users are not sent to the static URL flow.
