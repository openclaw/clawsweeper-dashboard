## Summary

Keep open: current main and v2026.6.11 still document and resolve Browserbase as a static remote `cdpUrl`, while the Browserbase Sessions API work remains in an open, dirty PR with credential, security, and proof blockers.

## What This Changes

Make Browserbase browser profiles create or fetch Browserbase Sessions API connect URLs instead of relying on a static `wss://connect.browserbase.com?apiKey=...` `cdpUrl`.

## Best Possible Solution

Land a maintainer-approved Browserbase Sessions API path, preferably through the browser plugin/backend boundary, with credential policy, signed-URL redaction, session cleanup, docs updates, and live browser-tool proof.

## Reproduction Assessment

Yes, at source level: current main still documents a static Browserbase CDP URL and resolves it as a generic raw `cdpUrl` without Browserbase Sessions API calls. I did not run a live Browserbase account repro in this read-only pass.

## Solution Assessment

Unclear. Browserbase Sessions API support is needed if OpenClaw keeps this documented integration, but maintainers still need to choose the ownership boundary, credential contract, and session cleanup behavior.
