## Summary

Keep open: current main and the latest release still document Browserbase as a static remote CDP URL and route it through the generic CDP attach path, while the Browserbase Sessions API candidate PR remains open, conflicting, and blocked on product/security/proof concerns.

## What This Changes

The issue asks OpenClaw to replace the documented static Browserbase CDP URL flow with Browserbase Sessions API lifecycle handling that creates or resolves a session connectUrl before attaching.

## Best Possible Solution

Land a maintainer-approved Browserbase Sessions API driver or generic browser-backend/plugin seam with credential policy, signed-URL redaction, session cleanup, docs, and live browser-tool proof; until then, stop documenting the static Browserbase URL as a working setup.
