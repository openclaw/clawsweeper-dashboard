## Summary

This is a coherent, proof-backed operator-safety feature, but it intentionally changes the pending-approval contract: an approval prompt becomes invalid when its proposal version changes. The patch appears technically sound with no discrete correctness finding, yet that fail-closed compatibility choice still needs explicit maintainer endorsement before merge. Likely related people: `steipete` and `shakkernerd` were surfaced in the PR timeline as interested routing candidates, though ownership confidence is low without a completed local history pass.

## What This Changes

This PR adds a read-only Skill Workshop review action that shows canonical create content or update diffs before approval, paginates the preview, and binds later lifecycle actions to the reviewed proposal version.

## System Context

Skill Workshop stores pending reusable-skill proposals and later applies approved changes to a workspace skill. The new review path reads that proposal into a portable full-content or diff projection for the agent tool, CLI, and channel UI before the operator takes a lifecycle action.

## Architecture Diagram

  Projection --> Surface[Agent tool, CLI, or channel]
  Surface --> Operator[Operator examines proposal]
  Operator --> Gate[Version-bound approval decision]
  Gate --> Apply[Workspace skill lifecycle action]

## Best Possible Solution

Keep the portable review projection and version-aware stale-decision protection, but merge only after a maintainer explicitly accepts fail-closed invalidation as the durable pending-approval contract and documents the upgrade expectation through the existing Skill Workshop docs.
