## Summary

Keep open. Current `main` and `v2026.6.11` still render heartbeat prompt time through the shared natural-language `Current time:` plus `Reference UTC:` helper, and the queued wake trigger timestamp is stored internally but not passed to the heartbeat runner as a separate model-visible field.

## What This Changes

The issue requests ISO 8601 heartbeat `Current time` output and an optional separate `Heartbeat triggered at` timestamp.

## Best Possible Solution

Define the automation timestamp contract first, then update the shared current-time helper, heartbeat wake plumbing, docs, and focused tests so ISO current time and any trigger timestamp appear only in the approved prompt locations.

## Reproduction Assessment

Yes. Source inspection on current `main` shows heartbeat still sends the natural-language `Current time` / `Reference UTC` helper block, and the stored wake `requestedAt` value is not forwarded to the heartbeat runner.

## Solution Assessment

Unclear. The requested ISO/split format is plausible, but the best fix needs maintainer direction because the same helper feeds multiple prompt paths and overlaps prompt-cache placement work.
