## Summary

Keep open. Current main and the latest release still use the shared natural-language heartbeat/cron current-time block, and the queued wake trigger timestamp is still not forwarded into the heartbeat runner as a model-visible field.

## What This Changes

The issue asks heartbeat prompts to render `Current time` in ISO 8601 and optionally add a separate `Heartbeat triggered at` timestamp.

## Best Possible Solution

Define one automation timestamp contract, then update the shared current-time helper, heartbeat wake plumbing, docs, and focused tests so ISO current time and any trigger timestamp appear only in the approved prompt locations.

## Reproduction Assessment

Yes, at source level. Current main still sends heartbeat prompts through the natural-language `Current time` and `Reference UTC` helper, and the stored wake `requestedAt` value is not forwarded to the heartbeat runner.

## Solution Assessment

Unclear. The requested ISO/split format is plausible, but the best fix needs maintainer direction because the same helper feeds multiple prompt paths and overlaps the prompt-cache placement work at https://github.com/openclaw/openclaw/issues/71973.
