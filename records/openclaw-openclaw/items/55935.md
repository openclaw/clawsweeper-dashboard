## Summary

Keep open. Current main and the latest release still render heartbeat prompt time through the shared natural-language `Current time:` plus `Reference UTC:` helper, and the queued wake timestamp is stored internally but is not forwarded as a separate model-visible `Heartbeat triggered at` field.

## What This Changes

Request changing heartbeat prompt time context to ISO 8601 and optionally adding a separate heartbeat trigger timestamp line.

## Best Possible Solution

Define the automation timestamp contract first, then update the shared helper and heartbeat wake plumbing so ISO current time and any trigger timestamp appear only in approved prompt locations with focused coverage.

## Reproduction Assessment

Yes. Source inspection on current main shows heartbeat prompt bodies still flow through the natural-language `Current time:` / `Reference UTC:` helper, while pending wake `requestedAt` is not forwarded into the runner as a separate prompt field.

## Solution Assessment

Unclear. The requested ISO/split format is plausible, but the best fix needs maintainer direction because the same helper feeds several prompt paths and overlaps prompt-cache placement work.
