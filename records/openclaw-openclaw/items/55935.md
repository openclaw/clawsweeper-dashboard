## Summary

Keep open. Current main and the latest release still render heartbeat prompt time through the shared natural-language `Current time:` plus non-ISO `Reference UTC:` helper, and wake `requestedAt` is not forwarded as a separate model-visible trigger timestamp.

## What This Changes

Request to render heartbeat current-time context as ISO 8601 and optionally add a separate heartbeat trigger timestamp.

## Best Possible Solution

Define the automation timestamp contract first, then update the shared current-time helper, heartbeat wake plumbing, docs, and focused tests so ISO current time and any trigger timestamp appear only in approved prompt locations.

## Reproduction Assessment

Yes, at source level. Current main still sends heartbeat prompts through the natural-language `Current time` / `Reference UTC` helper, and the stored wake `requestedAt` value is not forwarded to the heartbeat runner.

## Solution Assessment

Unclear. The requested ISO/split format is plausible, but the best fix needs maintainer direction because the same helper feeds multiple prompt paths and overlaps prompt-cache placement work.
