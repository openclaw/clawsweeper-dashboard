## Summary

Keep open. Current `main` and `v2026.6.11` still render heartbeat/cron prompt time through the shared natural-language `Current time:` plus `Reference UTC:` helper, and the wake queue keeps `requestedAt` internally without forwarding it to the heartbeat runner as a model-visible trigger timestamp.

## What This Changes

The issue requests ISO 8601 heartbeat time context and an optional separate heartbeat trigger timestamp field.

## Best Possible Solution

Define the automation timestamp contract first, then update the shared current-time helper, heartbeat wake plumbing, docs, and focused tests so ISO current time and any trigger timestamp appear only in approved prompt locations.
