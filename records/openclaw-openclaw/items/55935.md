## Summary

Keep open: current main and the latest release still use the shared natural-language `Current time` plus `Reference UTC` prompt block, and wake trigger time is still not passed into the heartbeat runner.

## What This Changes

Request to make heartbeat prompt current time ISO 8601 and expose heartbeat trigger time separately from processing time.

## Best Possible Solution

Define the shared automation timestamp contract first, then update the current-time helper, heartbeat wake plumbing, docs, and focused tests so current time and heartbeat trigger time appear in approved prompt locations with machine-readable formatting.

## Maintainer Decision

Question: Should OpenClaw change the shared cron-style prompt timestamp contract to ISO 8601 and add a heartbeat trigger timestamp, or keep the current human-readable `Current time` plus `Reference UTC` contract?

Rationale: The source path is clear, but this changes a shared model-visible prompt contract and overlaps broader prompt-cache placement work, so automation should not choose the permanent timestamp semantics by itself.

Likely owner: Takhoffman

Owner confidence: high

Options:

- **Adopt shared ISO contract (recommended):** Update the shared current-time helper and affected heartbeat, cron, reset, status, and post-compaction tests so model-facing volatile time lines use ISO 8601, then add heartbeat trigger time where wake metadata exists.
- **Heartbeat-only trigger field:** Keep shared current-time formatting as-is but add a separate heartbeat wake trigger timestamp for event-driven heartbeats, accepting inconsistent timestamp formats across prompt surfaces.
- **Keep current contract:** Preserve the shipped natural-language local `Current time` plus `Reference UTC` contract and narrow or reject the ISO/trigger request.

## Reproduction Assessment

Yes. Source inspection of current main and `v2026.6.11` shows heartbeat prompt bodies still receive the shared natural-language current-time block, while wake `requestedAt` is stored internally but not forwarded to `runHeartbeatOnce`.

## Solution Assessment

Unclear. The requested ISO plus trigger split is plausible, but the best fix needs maintainer direction because the same helper feeds multiple prompt paths and overlaps prompt-cache placement work.
