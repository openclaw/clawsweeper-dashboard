## Repair Work Prompt

Fix https://github.com/openclaw/openclaw/issues/99976. Current main's src/gateway/server/close-reason.ts truncates close reasons with Buffer.subarray(0, maxBytes).toString(), which can split a multi-byte UTF-8 sequence and return U+FFFD that re-encodes above maxBytes. Implement UTF-8-safe truncation in the existing helper so empty reasons still return "invalid handshake", under-cap reasons are unchanged, truncated reasons never end with a replacement character from a split sequence, and Buffer.byteLength(result) <= maxBytes for default and near-RFC caps such as 120, 122, and 123. Keep the change scoped to the helper and focused tests; do not change WebSocket close codes, auth/pairing message text, config, protocol, or docs unless a test exposes a necessary local adjustment. No CHANGELOG.md edit.
