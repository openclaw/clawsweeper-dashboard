## Summary

This feature remains necessary: current Memory Wiki documentation exposes single-operation `ingest`, `apply`, and `search` commands, not bounded batch equivalents. The request fits the existing plugin-owned Memory Wiki surface and the project’s performance/ergonomics direction, but versioned machine-oriented CLI contracts and mutation semantics need plugin-owner product approval before implementation.

## What This Changes

Add bounded JSON batch commands to the Memory Wiki plugin’s CLI so automation can apply multiple ordered wiki updates and verify several exact search targets without restarting the command/plugin path for every item.

## System Context

Memory Wiki is an optional bundled plugin that turns durable source material into a compiled, provenance-rich vault beside the active memory provider. Its CLI receives local source and mutation requests, updates the selected vault, compiles the resulting digest, and exposes search results to operators and automation.

## Best Possible Solution

Approve a Memory Wiki plugin-owned design that preflights a bounded manifest, serializes each resolved vault’s ordered mutations through the existing coordination boundary, compiles no more than once, and returns a stable bounded JSON result while leaving existing single-operation commands unchanged.
