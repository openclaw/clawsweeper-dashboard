## Summary

This PR remains relevant as a fix attempt for the open cron/Ollama report, but the current implementation is not mergeable: it changes Ollama’s explicit `off` signal into an unset field even though upstream and shipped OpenClaw behavior deliberately distinguish those states. The narrow fix should preserve `think: false` and stop the cron path from manufacturing an explicit thinking override when the payload omitted one.

## What This Changes

The PR changes native Ollama request composition so runtime thinking level `off` omits the top-level `think` field unless the model has an explicitly configured value, and updates the corresponding mock test.

## Best Possible Solution

Preserve native Ollama `think: false` for explicit `off`, keep model-configured `params.think` or `params.thinking` precedence, and change the cron/thinking-resolution path so an actually omitted payload remains unspecified through provider dispatch; cover omitted and explicit cases separately and prove the result with a redacted real Qwen3.5 request/response run.
