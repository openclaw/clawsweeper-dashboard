## Best Possible Solution

Keep the shipped call-log, SMS, and node-session work, then split the remaining Android authority into permission-gated device-control design and a separate maintainer decision on ADB or dynamic execution through the generic node-tool contract.

Owner confidence: medium

Options:

- **Split And Gate Android Authority (recommended):** Implement only narrow permission-gated device-control commands after explicit permission UX and policy review, while deferring ADB and dynamic execution until the generic node-tool trust model is accepted.
- **Route Through Node-Hosted Tools:** Use the generic node-hosted tool design path first, then let Android expose only approved descriptors through that reviewed model.
- **Reject Arbitrary Android Execution:** Keep ADB and dynamic Android code execution out of OpenClaw core for now and require external plugins or app-specific forks for that authority.
