## Summary

Keep open: current main and v2026.6.11 cover Android call-log search, SMS search, device metadata/app listing, and node-scoped Android session keys, but device control, Android ADB-style access, and dynamic Android execution remain missing and need product/security direction.

## What This Changes

The issue requests expanded Android node tools for phone control, ADB-style access, dynamic program execution, and isolation of Android node sessions.

## Best Possible Solution

Keep the shipped call-log, SMS, and node-scoped session work, then split the remainder into narrow permission-gated Android device-control commands and a separate maintainer-approved ADB/dynamic-execution design through the generic node-tool or plugin contract.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw accept Android device-control, ADB-style access, or dynamic code execution from connected Android nodes, and should that live as Android-specific commands or behind the generic node-advertised tool contract?

Rationale: The remaining work changes phone authority, private-data access, and model-visible execution boundaries, so automation cannot safely choose the permanent product and security model.

Likely owner: steipete

Owner reason: The open node-hosted plugin tools work is the closest active owner signal for the generic node-to-model tool contract that would shape ADB or dynamic execution.

Owner confidence: medium

Options:

- **Split and gate Android authority (recommended):** Implement only narrow Android device-control commands after explicit permission UX and policy review, while deferring ADB and dynamic execution until the generic node-tool trust model is accepted.
- **Route through node-hosted tools:** Use the generic node-registered or node-hosted tool contract as the core path, then let Android expose only approved descriptors through that model.
- **Keep high-power execution out of core:** Reject ADB and dynamic Android code execution in OpenClaw core for now and require an external plugin, ClawHub package, or app-specific fork for that authority.
