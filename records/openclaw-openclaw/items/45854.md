## Summary

Keep open: current main and v2026.6.11 cover Android call-log search, SMS search, device metadata/app listing, and node-scoped Android session keys, but the requested device-control, ADB-style access, and dynamic Android execution remain missing and require product/security direction.

## What This Changes

Request to expand Android node tools with device control, ADB-style access, dynamic Kotlin/script execution, and stronger per-device session isolation.

## Best Possible Solution

Preserve the shipped call-log, SMS, and session-isolation work, then split the remaining roadmap into narrow permission-gated Android device-control commands plus a separate maintainer-approved ADB/dynamic-execution design through the generic node-tool or plugin contract.

- **Keep high-power execution out of core:** Reject ADB and dynamic Android code execution in OpenClaw core for now and require an external plugin, ClawHub package, or app-specific fork for that authority.
