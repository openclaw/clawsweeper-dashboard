## Summary

Keep open: current main and shipped releases cover call-log search, SMS search, and node-scoped Android sessions, but the remaining Android device-control, ADB-style access, and dynamic execution requests are still absent and need product/security direction. The open related app-session PR at https://github.com/openclaw/openclaw/pull/101927 is only a partial session follow-up, not a complete replacement for this umbrella.

## What This Changes

Request to expand Android node tools with device control, ADB-style access, dynamic Android execution, and per-device session isolation.

## Best Possible Solution

Split or sponsor the remaining work behind explicit maintainer design: narrow Android device-control commands with per-command permissions/policy first, and route ADB or dynamic execution through the existing node-host/plugin-tool security model unless maintainers approve a new Android-specific boundary.
