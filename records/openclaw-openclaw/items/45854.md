## Summary

Keep open: current main and v2026.6.11 cover call-log search, SMS search, Android device metadata/app listing, and node-scoped sessions, but the requested device control, ADB-style access, and dynamic Android execution remain missing and need maintainer product/security direction.

## What This Changes

The issue requests expanded Android node tools for call logs, SMS, device control, ADB-style access, dynamic Kotlin execution, and multi-device session isolation.

## Best Possible Solution

Keep the shipped call-log, SMS, and session-isolation work, then split the remaining roadmap into narrow permission-gated Android device-control commands and a separate maintainer-approved ADB/dynamic-execution design through the generic node-tool or plugin contract.

Options:

- **Split and gate Android authority (recommended):** Implement only narrow Android device-control commands after explicit permission UX and policy review, while deferring ADB and dynamic execution until the generic node-tool trust model is accepted.
- **Route through node-hosted tools:** Use the generic node-registered/node-hosted tool design first, then let Android expose approved descriptors through that contract.
- **Keep high-power execution external:** Decline ADB and dynamic Android code execution in core for now and require an external plugin, ClawHub package, or app-specific fork for that authority.
