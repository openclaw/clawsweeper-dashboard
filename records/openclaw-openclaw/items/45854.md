## Summary

Keep open: current main and v2026.6.11 implement Android call-log search, SMS search, per-device chat session keys, and some device metadata/app listing, but not device.control, ADB-style access, or dynamic Android code execution; the remaining work needs maintainer product and security direction.

## What This Changes

The issue requests Android node device-control, ADB-style, dynamic-execution, and session-isolation improvements, with several subtasks already merged.

## Best Possible Solution

Keep the issue open, preserve the shipped call-log/SMS/session-isolation work, and split the remaining roadmap into permission-gated Android device-control plus a separate maintainer design for ADB or dynamic execution through a generic node-tool/plugin boundary.

- **Keep high-power execution out of core:** Reject ADB and dynamic Android code execution in OpenClaw core for now and require external plugins, ClawHub packages, or app-specific forks for that authority.
