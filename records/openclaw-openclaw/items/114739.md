## Summary

Keep this PR open for maintainer review: its generic outbound presentation adapter opts into `model-picker` actions without checking a channel-declared picker capability, which conflicts with the stated fail-closed rollout contract. The PR also creates a new public plugin SDK mutation API, so its permanent API direction should be confirmed before merge.

## What This Changes

The PR centralizes model-selection session persistence in a reusable apply service and adds typed model-picker presentation actions and channel capability contracts to the plugin SDK.

## System Context

Model directives and future interactive picker actions resolve a provider, model, and runtime, then persist the authoritative session entry and emit post-commit queue and gateway effects. Channel plugins are meant to render and authenticate typed picker actions only after explicitly declaring their callback and presentation capabilities.

## Architecture Diagram

  B --> C[Session apply service]
  C --> D[Authoritative session persistence]
  D --> E[Gateway hooks and queue refresh]
  A --> F[Channel callback encoding]
  F --> G[Declared channel capability]
  G --> H[Rendered channel control]

## Best Possible Solution

Keep picker-action resolution disabled by default in shared outbound adaptation, enable it only from a channel that declares and implements the corresponding capability profile, and confirm whether the session-apply function is intended as a permanent public plugin API before stabilizing its export.
