## Summary

Keep open: current main and the latest release still block credential-shaped keys configured only in `skills.entries.<skill>.env`, and the remaining fix needs an explicit skill-secret-to-exec security boundary.

## What This Changes

The issue asks for `skills.entries.<skill>.env` values, including credential-shaped names, to be available to host `exec` subprocesses during skill-backed agent runs.

## Best Possible Solution

Land a maintainer-approved scoped boundary that admits explicitly configured env keys for intended active-skill host execution, keeps dangerous host/runtime names blocked, and prevents unrelated generic exec children from inheriting other skill secrets.
