## Summary

Keep open: current main and latest stable v2026.6.11 still block credential-shaped values from skills.entries.<skill>.env unless the skill metadata declares that exact env name, so the reported GOG_KEYRING_PASSWORD host-exec path remains broken.

## What This Changes

The issue requests that environment variables configured under skills.entries.<skill>.env be available to host exec subprocesses for skills such as gog.

## Best Possible Solution

Define a narrow skill-scoped host-exec env contract: explicit per-skill env keys can satisfy that skill's intended CLI subprocess, dangerous host override keys stay blocked, and unrelated generic exec strips active skill secrets.
