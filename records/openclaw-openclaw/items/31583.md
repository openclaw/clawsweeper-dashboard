## Summary

Keep open: current main and the latest release still block credential-shaped keys configured only in `skills.entries.<skill>.env`, and the linked fix path needs maintainer security-boundary review rather than cleanup closure.

## What This Changes

The issue reports that per-skill environment variables configured under `skills.entries.<skill>.env` do not reach host `exec` subprocesses when those keys look like credentials.

## Best Possible Solution

Land a maintainer-approved narrow fix that admits explicitly configured active skill env keys for intended host-run credential delivery, keeps dangerous host-env names blocked, and preserves unrelated exec secret isolation.
