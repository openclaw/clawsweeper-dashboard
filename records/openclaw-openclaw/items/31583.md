## Summary

Keep open: current main and v2026.6.11 still block credential-shaped keys configured only in `skills.entries.<skill>.env` unless skill metadata declares the key; the linked fix attempts are unmerged/conflicting and the remaining repair needs an explicit credential-to-exec security boundary.

## What This Changes

The issue asks for per-skill environment variables configured in `openclaw.json` to be inherited by `exec` subprocesses, especially credential keys used by CLI-backed skills like `gog`.

## Best Possible Solution

Approve and land a scoped fix that treats explicit `skills.entries.<skill>.env` keys as trusted only for the intended active-skill host run, keeps dangerous host/runtime env names blocked, and tests both intended CLI delivery and unrelated exec/ACP isolation.
