## Summary

Keep open: current main and v2026.6.11 still block credential-shaped keys configured only in `skills.entries.<skill>.env`, and the open repair path is a conflicting fork PR while the remaining fix requires a security-boundary decision.

## What This Changes

The issue asks for env vars configured in `skills.entries.<skill>.env` to be inherited by `exec` subprocesses so CLI-backed skills can authenticate headlessly.

## Best Possible Solution

Land a maintainer-approved scoped fix that admits only the active skill's explicitly configured env keys while preserving dangerous-host-env blocks and unrelated-exec secret isolation.
