## Summary

Keep open: current main and v2026.6.11 still block credential-shaped keys configured only in `skills.entries.<skill>.env`, while the linked fix candidate remains open/conflicting and the credential-to-exec boundary needs maintainer security review.

## What This Changes

The issue reports that per-skill env values such as `GOG_KEYRING_PASSWORD` are configured in `skills.entries.<skill>.env` but do not reach the agent `exec` subprocess that needs them.

## Best Possible Solution

Land or replace a narrow fix that permits explicitly configured per-skill env keys only for intended skill-owned host execution, while preserving dangerous host env blocking and unrelated generic exec secret isolation.
