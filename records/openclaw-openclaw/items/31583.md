## What This Changes

The issue requests that `exec` subprocesses receive per-skill environment variables from `skills.entries.<skill>.env`, including credential-shaped names such as `GOG_KEYRING_PASSWORD`.

## Best Possible Solution

Land a maintainer-approved narrow fix that trusts only explicitly configured env keys for the active skill, keeps dangerous host/runtime override names blocked, and proves both intended skill auth delivery and unrelated exec secret isolation.
