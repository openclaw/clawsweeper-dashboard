## Summary

Keep open: current main and the latest release still block credential-shaped keys configured only in `skills.entries.<skill>.env`, and the linked fix path needs maintainer security-boundary review rather than cleanup closure.

## What This Changes

The issue asks for per-skill `skills.entries.<skill>.env` values, especially credential variables like `GOG_KEYRING_PASSWORD`, to reach subprocesses spawned by the agent `exec` tool.

## Best Possible Solution

Land a maintainer-approved narrow credential boundary that trusts only explicitly configured active-skill env keys for intended host-run credential delivery, blocks dangerous env names, and proves both gog-like auth and unrelated exec isolation.
