## Summary

Keep open: current main and the latest release still block credential-shaped keys that are configured only in `skills.entries.<skill>.env`, while an open conflicting candidate PR and the secret-handling boundary still need maintainer security/product review.

## What This Changes

The issue asks for per-skill env values, including credential-shaped names such as `GOG_KEYRING_PASSWORD`, to reach host exec subprocesses spawned during skill-backed agent runs.

## Best Possible Solution

Land a maintainer-approved narrow fix that treats explicitly configured per-skill env keys as allowed secrets while continuing to block dangerous host/env override names and proving no cross-skill leakage.
