## Summary

Keep open: current main and the latest release still block configured-only credential-shaped `skills.entries.<skill>.env` keys before they can reach host `exec`, and the open fix candidate is unmerged/conflicting while the inverse secret-leak boundary still needs maintainer security judgment.

## What This Changes

Ensure environment variables configured under `skills.entries.<skill>.env` are available to subprocesses spawned by `exec` during skill-backed agent runs.

## Best Possible Solution

Make one maintainer-owned security decision for per-skill secret delivery, then land a compatible fix with regression coverage or document the stricter metadata allowlist model.
