## Summary

Keep open: current main and v2026.6.11 still block credential-shaped keys configured only in `skills.entries.<skill>.env`, and the remaining fix needs a maintainer security-boundary decision before another repair PR is queued.

## What This Changes

The issue reports that per-skill environment variables configured under `skills.entries.<skill>.env` are not inherited by subprocesses spawned through the `exec` tool.

## Best Possible Solution

Maintainers should approve a bounded host-only rule for explicit `skills.entries.<skill>.env` keys, keep dangerous host variables blocked, and land focused coverage for skill env injection, host exec inheritance, sandbox non-inheritance, and ACP/Codex isolation.
