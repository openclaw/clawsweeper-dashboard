## Summary

Keep open: current `main` and v2026.6.11 still block credential-shaped values from `skills.entries.<skill>.env` unless the skill metadata declares that env name, so the reported `GOG_KEYRING_PASSWORD` path remains broken. The useful fix is clear, but it needs a maintainer security-boundary decision because it overlaps open work to prevent skill-injected secrets from leaking into generic host `exec`.

## What This Changes

The issue asks OpenClaw to pass per-skill `skills.entries.<skill>.env` values, including credential-shaped keys, into host `exec` subprocesses used by skills.

## Best Possible Solution

Define a narrow skill-scoped host-exec env contract: explicit per-skill config env keys may satisfy that skill's own CLI subprocess needs, dangerous host override keys remain blocked, and unrelated generic exec paths continue stripping active skill secrets.
