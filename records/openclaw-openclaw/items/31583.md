## Summary

Keep open: current main and v2026.6.11 still reject credential-shaped keys configured only in `skills.entries.<skill>.env` unless the key is declared in skill metadata, while the open fix candidate is unmerged/conflicting and the adjacent skill-secret leak report needs the same boundary settled.

## What This Changes

The issue asks for `skills.entries.<skill>.env` values, especially credential-shaped keys like `GOG_KEYRING_PASSWORD`, to be available to host `exec` subprocesses during active skill runs.

## Best Possible Solution

Land a maintainer-approved narrow fix that trusts only explicitly configured env keys for the active skill's host run, preserves dangerous host-env blocking, and proves both gog-like credential delivery and unrelated exec isolation.
