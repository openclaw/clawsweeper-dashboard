## Summary

Keep open: current main and v2026.6.11 still block credential-shaped keys configured only in `skills.entries.<skill>.env`, and the remaining repair needs a maintainer-approved skill-secret-to-exec security boundary.

## What This Changes

The issue requests that `skills.entries.<skill>.env` values be available to `exec` subprocesses for the active skill, including credential-shaped names such as `GOG_KEYRING_PASSWORD`.

## Best Possible Solution

Land a scoped, maintainer-approved fix that admits only explicitly configured env keys for the active skill while keeping dangerous host env names blocked and preventing unrelated exec children from inheriting other skill secrets.
