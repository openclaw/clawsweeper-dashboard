## Summary

Keep open: current main and v2026.6.11 still reject credential-shaped keys configured only in `skills.entries.<skill>.env` unless the key is declared in skill metadata, and the available fix path needs maintainer security-boundary review before landing.

## What This Changes

The issue reports that per-skill environment variables configured under `skills.entries.<skill>.env` are not inherited by subprocesses spawned through the `exec` tool.

## Best Possible Solution

Land a maintainer-approved narrow fix that trusts only explicitly configured env keys for the active skill's host run, preserves dangerous host-env blocking, and proves both gog-like credential delivery and unrelated exec isolation.
