## Summary

Keep open: current main and v2026.6.11 still block credential-shaped keys configured only in `skills.entries.<skill>.env`, and the remaining repair needs an explicit skill-secret-to-exec security boundary.

## What This Changes

The issue requests that `exec` child processes receive environment variables configured under `skills.entries.<skill>.env`, including credential-shaped keys needed by CLI-backed skills.

## Best Possible Solution

Land a maintainer-approved scoped fix that lets only the active skill's explicitly configured env keys pass the sensitive-name filter while dangerous host/runtime env names stay blocked and unrelated exec children do not inherit other skill secrets.

Yes. Source inspection shows an env-only key matching `_PASSWORD` or `_TOKEN` enters `pendingOverrides`, is rejected by `sanitizeEnvVars`, and is not re-allowed unless declared in skill metadata.

## Solution Assessment
