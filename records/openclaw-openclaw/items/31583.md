## Summary

Keep open: current main still blocks credential-shaped keys configured only in `skills.entries.<skill>.env`, so the reported `GOG_KEYRING_PASSWORD` host-exec path remains unsolved and needs an explicit credential-to-exec security boundary.

## What This Changes

The issue requests that `skills.entries.<skill>.env` values, including credential-shaped keys such as `GOG_KEYRING_PASSWORD`, reach host `exec` subprocesses for skill-invoked CLI tools.

## Best Possible Solution

Land a maintainer-approved scoped skill env boundary that admits explicitly configured env keys for intended active-skill host execution, keeps dangerous host/runtime names blocked, and strips unrelated skill secrets from generic exec children.
