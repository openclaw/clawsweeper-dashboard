## Summary

Keep open: current main and the latest release still block credential-shaped `skills.entries.<skill>.env` keys unless the skill metadata declares them, and the open linked repair PR is conflicting and unmerged.

## What This Changes

The issue reports that per-skill environment variables configured under `skills.entries.<skill>.env` do not reach commands spawned by the `exec` tool.

## Best Possible Solution

Land or replace the linked repair with a narrow security-reviewed change that lets operator-configured per-skill env keys pass for host runs while preserving the hard blocklist for host-execution control variables and adding regression coverage.
