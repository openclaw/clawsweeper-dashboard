## Summary

Keep open: current main and v2026.6.11 still block credential-shaped keys configured only in `skills.entries.<skill>.env`, and the remaining fix crosses the skill-secret-to-exec security boundary with an unmerged conflicting linked PR.

## What This Changes

The issue asks for per-skill `skills.entries.<skill>.env` variables, including credential-shaped keys, to reach `exec` subprocesses for the active host-run skill.

## Best Possible Solution

Land a maintainer-approved scoped fix that admits only the active skill's explicitly configured env keys, preserves dangerous host-env blocks, and proves unrelated exec children do not inherit other skill secrets.
