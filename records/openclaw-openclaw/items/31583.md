## Summary

Keep open: current main and v2026.6.11 still block credential-shaped keys configured only in `skills.entries.<skill>.env`, while the open fixing PR is unmerged, conflicting, and not maintainer-editable.

## What This Changes

The issue asks for per-skill environment variables from `skills.entries.<skill>.env` to be available to `exec` subprocesses so CLI-backed skills can authenticate on headless systems.

## Best Possible Solution

Land or replace with a maintainer-approved narrow fix that trusts only the active skill's explicitly configured env keys for that host run, keeps dangerous host/runtime overrides blocked, and proves both gog-like credential delivery and unrelated exec isolation.
