## Summary

Keep open: current main and the latest release still block credential-shaped `skills.entries.<skill>.env` keys such as `GOG_KEYRING_PASSWORD` unless the skill metadata declares them, and an open linked PR is a conflicting candidate rather than a merged fix.

## What This Changes

The issue asks OpenClaw to pass configured `skills.entries.<skill>.env` values, including credential-shaped variables like `GOG_KEYRING_PASSWORD`, through to skill-invoked `exec` subprocesses.

## Best Possible Solution

Define and land a maintainer-approved skill-scoped host-exec env contract that permits explicit per-skill credential keys only for the owning skill while preserving dangerous-key blocks and unrelated exec secret stripping.
