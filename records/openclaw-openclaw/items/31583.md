- `impact:security`: The issue is about whether configured secret values such as keyring passwords may flow into executable subprocess environments without being exposed elsewhere.
- `impact:auth-provider`: The reported failure blocks CLI authentication for skills that depend on env-provided credentials or keyring passphrases.
- `impact:ux-friction`: Affected users can proceed only through fragile wrapper scripts, system-level env moves, or broader security workarounds.

## Summary

Keep open: current `main` and the latest release still block credential-shaped `skills.entries.<skill>.env` keys such as `GOG_KEYRING_PASSWORD` unless the skill metadata declares them, and the remaining fix is a security-boundary choice rather than conservative cleanup.

## What This Changes

The issue asks for per-skill environment variables from `skills.entries.<skill>.env` to reach CLI subprocesses launched through the exec tool.

## Best Possible Solution

Define a narrow skill-scoped host-exec env contract: explicit per-skill config env keys may satisfy that skill's own CLI subprocess needs, dangerous host override keys stay blocked, and unrelated generic exec paths keep stripping active skill secrets.

- **Require skill metadata declarations:** Keep credential-shaped names blocked unless the skill manifest declares them, then update the `gog` skill metadata or package docs for this credential path.
- **Keep fail-closed behavior:** Document that credential-shaped per-skill env names are intentionally blocked and require top-level/system env or an approved sandbox/env configuration instead.

## Reproduction Assessment

Yes, source-backed. `GOG_KEYRING_PASSWORD` matches the sanitizer's credential-name block pattern, the current `gog` skill metadata does not declare that key, and the skill-env sanitizer blocks it before host exec can inherit it.

## Solution Assessment

Unclear until the security boundary is confirmed. The best fix is not a broad allow-all change; it should preserve dangerous-key blocking and keep skill-injected secrets out of unrelated generic exec environments.
