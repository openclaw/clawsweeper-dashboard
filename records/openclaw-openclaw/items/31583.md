## Summary

Keep open: current main and v2026.6.11 still block credential-shaped `skills.entries.<skill>.env` keys unless the skill metadata declares them, and this issue has a security-boundary label plus an open unmerged linked fix PR.

## What This Changes

The issue requests that `exec` subprocesses inherit environment variables declared in `skills.entries.<skill>.env`, including credential-shaped keys used by CLI-backed skills.

## Best Possible Solution

Define a narrow skill-scoped host-exec env contract: explicit per-skill config env keys can satisfy that skill's own CLI subprocess needs, dangerous host override keys remain blocked, and unrelated generic exec paths keep stripping active skill secrets.

Rationale: The current source violates documented host skill-env behavior for affected users, but changing it decides when credential values may enter executable child-process environments.

Likely owner: steipete

Owner confidence: high

Options:

- **Allow skill-scoped credential env (recommended):** Permit user-configured per-skill env keys for that skill's own host exec context while keeping dangerous env names blocked and stripping skill secrets from unrelated generic exec.
- **Require metadata declarations:** Keep credential-shaped names blocked unless the skill manifest declares them, then update `gog` metadata or docs for `GOG_KEYRING_PASSWORD`.
- **Keep fail-closed behavior:** Document that credential-shaped per-skill env names are intentionally blocked and require top-level or system environment configuration.

## Reproduction Assessment

Yes. Source inspection shows `GOG_KEYRING_PASSWORD` matches the credential-name sanitizer and the bundled `gog` skill does not declare that key, so the configured value is blocked before host `exec` can inherit it; I did not run a live `gog` auth flow in this read-only review.

## Solution Assessment

Unclear until the security boundary is confirmed. The best fix is not a broad allow-all change; it should preserve dangerous-key blocking and keep skill-injected secrets out of unrelated generic exec environments.
