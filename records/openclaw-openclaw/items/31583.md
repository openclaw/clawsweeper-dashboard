## Summary

Keep open: current main and v2026.6.11 still block credential-shaped keys configured only in `skills.entries.<skill>.env`, and the remaining fix needs maintainer security-boundary approval because it must preserve unrelated exec secret isolation.

## What This Changes

The issue reports that `exec` subprocesses do not receive per-skill environment variables from `skills.entries.<skill>.env`, breaking headless CLI skill authentication such as `gog`.

## Best Possible Solution

Land a maintainer-approved narrow fix that trusts only explicitly configured env keys for the active skill's host run, preserves dangerous host-env blocking, and proves both gog-like credential delivery and unrelated exec isolation.
