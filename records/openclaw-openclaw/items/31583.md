## Summary

Keep open: current main and v2026.6.11 still block credential-shaped values from `skills.entries.<skill>.env` unless the skill metadata declares that exact env name, so the reported `GOG_KEYRING_PASSWORD` host-exec path remains broken. A linked external fix exists, but it is stale/conflicting and this needs a maintainer security-boundary decision because it overlaps generic exec secret-stripping work.

## What This Changes

The issue asks for per-skill env vars configured in `openclaw.json`, including credential-shaped keys, to be available to host `exec` subprocesses during skill use.

## Best Possible Solution

Define a narrow skill-scoped host-exec env contract: explicit per-skill config env keys can satisfy that skill's own CLI subprocess needs, dangerous host override keys remain blocked, and unrelated generic exec paths continue stripping active skill secrets.
