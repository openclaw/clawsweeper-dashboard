## Summary

Keep open: current main and latest release still block credential-shaped keys configured only in `skills.entries.<skill>.env`, and the open linked fix PR is unmerged and conflicting while the credential-to-exec boundary needs maintainer security review.

## What This Changes

The issue reports that credential env configured in `skills.entries.<skill>.env` is not inherited by host `exec` subprocesses, breaking headless skill CLI authentication.

## Best Possible Solution

Land a maintainer-approved fix that lets operator-configured per-skill env keys reach host runs while preserving always-blocked dangerous host env names, with regression coverage for sensitive key names and docs clarifying host versus sandbox scope.
