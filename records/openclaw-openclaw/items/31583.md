## Summary

Keep open: current main and v2026.6.11 still block credential-shaped values like `GOG_KEYRING_PASSWORD` from `skills.entries.<skill>.env` unless the skill metadata declares that env name, and `gog` does not. The remaining fix needs maintainer security/product review because the availability fix overlaps with the opposing secret-leak boundary tracked in a related open security issue.

## What This Changes

The issue asks for per-skill env entries, including credential-shaped values such as `GOG_KEYRING_PASSWORD`, to reach `exec` subprocesses during host skill runs.

## Best Possible Solution

Define a scoped credential-to-exec contract that lets intended skill invocations receive declared sensitive keys while stripping active skill secrets from unrelated generic exec children and keeping dangerous loader/startup env blocked.
