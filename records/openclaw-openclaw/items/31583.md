## Summary

Keep open: current main and v2026.6.11 still reject configured-only credential-shaped `skills.entries.<skill>.env` keys before host exec inheritance, while the linked fix PR is open but conflicting and the inverse skill-secret leak issue remains unresolved.

## What This Changes

The issue asks for `skills.entries.<skill>.env` values, including credential-shaped keys, to be available to host `exec` subprocesses for active skills.

## Best Possible Solution

Land a maintainer-approved narrow fix that trusts only explicitly configured env keys for the active skill's host run, preserves dangerous host-env blocking, and proves both gog-like credential delivery and unrelated exec isolation.
