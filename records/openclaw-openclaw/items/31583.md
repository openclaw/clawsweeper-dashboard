## Summary

Keep open: current main and v2026.6.11 still block credential-shaped per-skill env names unless the skill metadata declares them, and the linked fix/security PRs have not landed.

## What This Changes

The issue asks for per-skill `skills.entries.<skill>.env` values, including credential-shaped variables, to reach host `exec` subprocesses used by skills.

## Best Possible Solution

Land a maintainer-approved scoped skill-env boundary that admits intended active-skill host CLI credentials, keeps dangerous env names blocked, strips unrelated skill secrets from generic exec children, and proves both sides with focused tests and redacted runtime proof.
