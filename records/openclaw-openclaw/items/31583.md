## Summary

Keep open: current main and v2026.6.11 still block credential-shaped keys configured only in `skills.entries.<skill>.env`, and the remaining fix is a security-sensitive credential-to-exec boundary with an open but conflicting fix candidate.

## What This Changes

The issue asks for `skills.entries.<skill>.env` variables, including credential-shaped names, to be inherited by host `exec` subprocesses during active skill runs.

## Best Possible Solution

Land a maintainer-approved narrow fix that trusts only explicitly configured active-skill env keys for host-run credential delivery, blocks dangerous env names, and proves both gog-like auth and unrelated exec isolation.
