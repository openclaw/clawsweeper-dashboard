  - body: This handler imports `mkdirPathWithinRoot` and `removePathWithinRoot`, but current main's `src/infra/fs-safe.ts` no longer exports those helpers and routes callers through `root(rootDir).read/write`. A rebase would leave this file unable to typecheck unless it moves to the current root API or introduces an intentional supported helper.
  - confidence: 0.93
- **[P1] Move workspace schemas into the protocol package:** `src/gateway/protocol/schema/agents-workspace.ts:1`
  - body: The PR adds public `agents.workspace.*` schemas under `src/gateway/protocol`, but current main removed that tree and uses `packages/gateway-protocol` as the canonical protocol source. Keeping this path would reintroduce a parallel protocol tree that clients and generated models can drift from.
  - confidence: 0.92
- **[P1] Register workspace methods through core descriptors:** `src/gateway/server-methods.ts:8`
  - body: Current main builds core Gateway dispatch from lazy handler families plus `CORE_GATEWAY_METHOD_SPECS`, which also owns method listing, authorization, startup availability, and write policy. Importing and spreading `agentsWorkspaceHandlers` directly here bypasses that current architecture and will not survive a clean rebase without descriptor entries.
  - confidence: 0.9
- **[P1] Bound recursive workspace listings:** `src/gateway/server-methods/agents-workspace.ts:143-145`
  - body: When callers pass `recursive: true`, this read-scoped handler walks every subdirectory and returns every entry without depth, count, byte, timeout, or response-size limits. A large workspace can therefore stall the Gateway or produce an oversized response from a single list call.
  - confidence: 0.88
