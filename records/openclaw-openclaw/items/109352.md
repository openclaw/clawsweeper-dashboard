## Label Justifications

- `P1`: The reported defect repeatedly sends prior assistant output into active channel conversations and grows in severity over successive real-user runs.
- `impact:message-loss`: Final channel messages are duplicated and associated with the wrong run instead of delivering one correct reply per interaction.
- `impact:session-state`: The failure is caused by stale turn boundaries and mutable transcript projection state leaking across runs.

## Summary

Keep this issue open. Current `main` still derives the attempt boundary from a mutable transcript index and retains session-assistant fallback behavior, so a context-engine rewrite can plausibly select output outside the current run; the superficially similar https://github.com/openclaw/openclaw/issues/91959 concerned cumulative provider stream snapshots within one turn and does not own this cross-run bug.

## What This Changes

Make final assistant delivery resolve only the current run’s output when a context-engine plugin rewrites or condenses the working transcript.

## Best Possible Solution

Carry an immutable run-scoped assistant result from attempt execution through payload and final metadata construction, using mutable transcript inspection only for persistence or diagnostics, and add regression coverage for condensation, index shifts, multiple runs, and a run with zero assistant stream texts.
