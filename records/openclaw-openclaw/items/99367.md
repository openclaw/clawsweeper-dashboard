## Summary

Keep open: current main still splits exec command text into stages before heredoc recognition, so separators inside heredoc bodies can be rendered as extra executed-command summaries. Related newline-corruption and exec-failure wording work does not cover this shared display-parser bug.

## What This Changes

The issue asks for heredoc exec summaries to show only the launcher command instead of parsing heredoc body contents as command stages, and to preserve declined/blocked status when available.

## Best Possible Solution

Add heredoc-aware compaction in the shared exec display parser before top-level stage splitting, with focused regression coverage for heredoc bodies containing shell separators and generated YAML/JavaScript-like text.

## Reproduction Assessment

Yes, at source level: current main splits heredoc command text before heredoc recognition, so unquoted heredoc body separators can become extra display stages. I did not run a live Slack session in this read-only review.

## Solution Assessment

Yes: the narrowest maintainable fix is to detect/compact heredoc launcher commands before `splitTopLevelStages`, while preserving existing cwd suffixes and declined-status handling. Merged failure-wording work and the open newline-corruption PR do not solve this parser ordering issue.
