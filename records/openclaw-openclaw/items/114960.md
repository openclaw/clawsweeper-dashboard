## Summary

Keep this PR open: the fallback timer is started after preliminary keyword work, so the advertised 14-second maximum can still lose to the fixed outer 15-second deadline before FTS-only results are returned. The PR also needs inspectable after-fix runtime proof and an owner decision on adding a public timeout setting.

## What This Changes

The PR adds a configurable primary embedding timeout so built-in memory search can return same-call SQLite FTS keyword results when a cold embedding query exceeds its budget.

## System Context

Built-in memory search turns an agent query into keyword and vector candidates from the local memory index, then returns ranked results to the memory tool. This PR changes the deadline decision around primary query embeddings and the fallback mode reported to the caller.

## Best Possible Solution

Measure the primary embedding budget against the remaining time from one search-wide deadline, add a delayed-keyword regression that proves FTS-only output arrives before the outer deadline, and keep a public timeout option only if memory owners approve that configuration contract.
