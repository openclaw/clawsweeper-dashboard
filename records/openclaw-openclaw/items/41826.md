## Summary

Keep open: current main and v2026.6.11 still hardcode the Gateway-visible TUI display label as `openclaw-tui`, and `openclaw tui` still has no CLI/config carrier for a custom display name. The existing Gateway `displayName` seam makes the implementation bounded, but the public flag/config shape and privacy defaults need maintainer product direction first.

## What This Changes

Request to let `openclaw tui` set a custom Gateway-visible client display name for each TUI instance.

## Best Possible Solution

Add an explicit opt-in Gateway-mode TUI display-name override that preserves `openclaw-tui` as the default, validates/sanitizes the label, documents privacy-safe usage, and avoids automatic hostname/workdir labels unless maintainers explicitly approve them.
