## Summary

Keep open: current main and the latest release still hardcode the Gateway-visible TUI label and expose no CLI, config, or TUI option carrier for a custom display name. The Gateway protocol already has a displayName seam, but choosing the public flag/config shape and privacy defaults needs maintainer product direction.

## What This Changes

The issue requests a custom Gateway-visible display name for `openclaw tui` instances so multiple TUI windows can be distinguished.

## Best Possible Solution

Add an explicit opt-in Gateway-mode TUI display-name override that preserves `openclaw-tui` as the default, validates and bounds the label, documents privacy-safe usage, and avoids automatic hostname/workdir labels unless maintainers approve them.
