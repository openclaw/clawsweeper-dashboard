## Summary

Keep open: current main and the latest release still hardcode the Gateway-visible TUI label as `openclaw-tui`, and there is no `openclaw tui` CLI option, TUI option carrier, or docs path for a custom display name. The existing Gateway `displayName` seam makes the change feasible, but the public flag/config shape and privacy defaults need maintainer direction first.

## What This Changes

The issue requests a new `openclaw tui` display-name override so multiple Gateway-connected TUI windows can be distinguished.

## Best Possible Solution

Add an explicit opt-in Gateway-mode TUI display-name override that preserves `openclaw-tui` as the default, validates/sanitizes the label, documents privacy-safe usage, and avoids automatic hostname/workdir labels unless maintainers explicitly approve them.
