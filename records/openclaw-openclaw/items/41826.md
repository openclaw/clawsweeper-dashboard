## Summary

Keep open: current main and the latest release still send every Gateway-backed TUI connection with the same `openclaw-tui` display label, and there is no `openclaw tui` flag, TUI option carrier, or docs path for a custom client display name. The Gateway already has a `displayName` handshake seam, so this is a bounded feature, but the public flag/config shape and privacy defaults need maintainer direction first.

## What This Changes

Request adding a custom Gateway-visible display-name option for `openclaw tui` so multiple TUI windows can be distinguished.

## Best Possible Solution

Add an explicit opt-in Gateway-mode TUI display-name override that preserves `openclaw-tui` as the default, validates/sanitizes the label, documents privacy-safe usage, and avoids automatic hostname/workdir labels unless maintainers approve them.
