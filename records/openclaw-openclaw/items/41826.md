## Summary

Keep open: current main and the latest release still hardcode the Gateway-visible TUI label as `openclaw-tui`, while `openclaw tui` has no flag, option carrier, or docs path for a custom display name. The Gateway already has a `displayName` seam, but the public flag/config shape and privacy defaults need maintainer direction before a fix PR.

## What This Changes

Request to let `openclaw tui` set a custom Gateway-visible client display name instead of always advertising `openclaw-tui`.

## Best Possible Solution

Add an explicit opt-in Gateway-mode TUI display-name override that preserves `openclaw-tui` as the default, validates/sanitizes the label, documents privacy-safe usage, and avoids automatic hostname/workdir labels unless maintainers approve them.
