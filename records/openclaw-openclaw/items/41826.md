## Summary

Keep open: current main and v2026.6.11 still hardcode the Gateway-visible TUI label as `openclaw-tui`, and there is no CLI, TUI option carrier, config, or docs path for a custom TUI client display name. The existing Gateway `displayName` seam makes the implementation technically narrow, but the public flag/config shape and privacy defaults need maintainer direction first.

## What This Changes

The issue requests a user-controlled display name for Gateway-visible TUI clients, such as an `openclaw tui --client-name` or `--username` option, or an auto-generated unique name.

## Best Possible Solution

Add an explicit opt-in Gateway-mode TUI display-name override that preserves `openclaw-tui` as the default, validates and sanitizes the label, documents privacy-safe usage, and avoids automatic hostname/workdir labels unless maintainers approve them.
