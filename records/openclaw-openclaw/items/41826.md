## Summary

Keep open: current main and latest release still hardcode the Gateway-visible TUI label as `openclaw-tui`, and neither the TUI CLI, TUI options, nor docs expose a custom display-name path. The Gateway already has a displayName seam, but making it user-facing needs maintainer direction on flag name, validation, Gateway-only scope, and privacy defaults.

## What This Changes

Requested behavior: add a custom Gateway-visible display name for `openclaw tui` instances so multiple TUI windows are distinguishable.

## Best Possible Solution

Add an explicit opt-in Gateway-mode TUI display-name override that preserves `openclaw-tui` as the default, validates/sanitizes the label, documents privacy-safe usage, and avoids automatic hostname/workdir labels unless maintainers explicitly approve them.
