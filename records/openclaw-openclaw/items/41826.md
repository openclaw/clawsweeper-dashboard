## Summary

Keep open: current main and v2026.6.11 still hardcode the Gateway-visible TUI label as `openclaw-tui`, and there is no `openclaw tui` flag, TUI option carrier, config key, or docs path for a custom display name. The Gateway already supports a client `displayName`, so the remaining decision is product shape and privacy policy rather than missing protocol plumbing.

## What This Changes

Request to let `openclaw tui` use a custom or automatically derived Gateway-visible client display name so multiple TUI windows are distinguishable.

## Best Possible Solution

Add an explicit opt-in Gateway-mode TUI display-name override that preserves `openclaw-tui` as the default, validates and trims the label, documents privacy-safe usage, and avoids automatic host/workdir labels unless maintainers approve that policy.
