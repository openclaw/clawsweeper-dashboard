## Summary

Keep open: current main and the latest release still hardcode the Gateway-visible TUI display name as `openclaw-tui`, and `openclaw tui` has no flag, TUI option carrier, or docs path for an override. The Gateway already carries a client `displayName`, so the remaining work is a product decision about public flag/config shape and privacy defaults.

## What This Changes

Request to add a user-settable `openclaw tui` client display name, such as `--client-name`, so multiple TUI windows are distinguishable in Gateway presence or session lists.

## Best Possible Solution

Add an explicit opt-in Gateway-mode TUI display-name override that preserves `openclaw-tui` as the default, trims and validates the label, documents privacy-safe usage, and avoids automatic host/workdir labels unless maintainers approve that policy.
