## Summary

Keep open: current main and the latest release still hardcode the Gateway-visible TUI display label, and adding a public TUI identity override needs maintainer product/privacy direction before implementation.

## What This Changes

The issue requests a user-selectable display name for `openclaw tui` clients so multiple TUI windows can be distinguished in Gateway presence/session views.

## Best Possible Solution

Add an explicit opt-in Gateway-mode TUI display-name override that preserves `openclaw-tui` as the default, validates and bounds the label, documents privacy-safe usage, and avoids automatic hostname/workdir labels unless maintainers approve them.

Rationale: The Gateway already accepts `clientDisplayName`, but choosing a public identity surface and whether to derive local machine/workspace names has product and privacy implications that automation should not decide.

Likely owner: steipete

Owner confidence: high

Options:

- **Add CLI-Only Opt-In Flag (recommended):** Add a bounded `openclaw tui --client-name <name>` path for Gateway mode only, keep the existing default unchanged, and document privacy-safe usage.
- **Add Persisted TUI Config:** Add a `tui` config key if maintainers want a stable per-user default, with schema, docs, and no upgrade surprise for existing users.
- **Defer Or Decline:** Keep `openclaw-tui` as the only TUI label until a broader identity and privacy policy is decided.
