## Summary

Keep open: current main and the latest release still hardcode the Gateway-visible TUI label as `openclaw-tui`, with no supported CLI, TUI option, config key, or docs override. The technical seam exists, but the public flag/config shape and privacy defaults need maintainer product direction before automation should implement it.

## What This Changes

Request to let `openclaw tui` set a custom Gateway-visible client display name instead of every TUI instance appearing as `openclaw-tui`.

## Best Possible Solution

Add an explicit opt-in Gateway-mode TUI display-name override that preserves `openclaw-tui` as the default, validates and trims the label, documents privacy-safe usage, and avoids automatic host/workdir labels unless maintainers approve that policy.
