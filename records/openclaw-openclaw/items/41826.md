## Summary

Keep open: current main and v2026.6.11 still hardcode the Gateway-visible TUI display label as `openclaw-tui`, with no `openclaw tui` flag, TUI option, config key, or docs-supported override. The Gateway client already has a `displayName` handshake seam, so the remaining question is the public CLI/config shape and privacy default, not missing protocol plumbing.

## What This Changes

Request to let `openclaw tui` set a custom Gateway-visible client display name instead of always showing `openclaw-tui`.

## Best Possible Solution

Add an explicit opt-in Gateway-mode TUI display-name override that preserves `openclaw-tui` as the default, validates and trims the label, documents privacy-safe usage, and avoids automatic host/workdir labels unless maintainers approve that policy.
