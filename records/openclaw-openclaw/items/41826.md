## Summary

Keep open: current main and v2026.6.11 still hardcode the Gateway-visible TUI label as `openclaw-tui`, and there is no CLI, docs, or `TuiOptions` carrier for an override. The Gateway client already supports a display-name field, so the remaining blocker is the public TUI flag/config shape and privacy default decision.

## What This Changes

The issue asks for a custom Gateway-visible display name for each `openclaw tui` client instance.

## Best Possible Solution

Add an explicit opt-in Gateway-mode TUI display-name override that preserves `openclaw-tui` as the default, validates and bounds the label, documents privacy-safe usage, and avoids automatic hostname/workdir labels unless maintainers approve them.
