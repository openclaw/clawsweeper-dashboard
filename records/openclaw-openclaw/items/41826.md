## Summary

Keep open: current main and the latest release still hardcode the Gateway-visible TUI label as `openclaw-tui`, with no `openclaw tui` flag, TUI option carrier, or docs path for a custom display name. The existing Gateway client metadata seam can carry a display name, but the public CLI/config shape and privacy defaults need maintainer direction first.

## What This Changes

Request to let `openclaw tui` use a custom Gateway-visible client display name so multiple TUI windows can be distinguished.

## Best Possible Solution

Add an explicit opt-in Gateway-mode TUI display-name override that preserves `openclaw-tui` as the default, validates/sanitizes the label, documents privacy-safe use, and avoids automatic hostname/workdir labels unless maintainers approve them.
