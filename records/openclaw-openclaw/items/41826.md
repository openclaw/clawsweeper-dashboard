## Summary

Keep open: current main and the latest release still hardcode the Gateway-visible TUI label as `openclaw-tui`, and there is no CLI, TUI option, config key, or doc-supported override. The Gateway already has the technical `displayName` seam, so the remaining blocker is a product/privacy decision about the public surface.

## What This Changes

The issue asks for a user-specified `openclaw tui` display name so multiple Gateway-connected TUI windows are distinguishable.

## Best Possible Solution

Add an explicit opt-in Gateway-mode TUI display-name override that preserves `openclaw-tui` as the default, validates and trims the label, documents privacy-safe use, and avoids automatic host/workdir labels unless maintainers approve that policy.
