## Summary

Keep open: current main and v2026.6.11 still hardcode the Gateway-visible TUI display label as `openclaw-tui`, while the TUI CLI, docs, and `TuiOptions` expose no override. The Gateway client already has a display-name seam, so the remaining question is the public CLI/config shape and privacy defaults.

## What This Changes

The issue requests a user-settable TUI client display name so multiple TUI windows can be distinguished in Gateway session or presence views.

## Best Possible Solution

Add an explicit opt-in Gateway-mode TUI display-name override that preserves `openclaw-tui` as the default, validates and bounds the label, documents privacy-safe usage, and avoids automatic hostname/workdir labels unless maintainers approve them.

- **Defer Or Decline:** Keep `openclaw-tui` as the only TUI label until a broader identity and privacy policy is decided.
