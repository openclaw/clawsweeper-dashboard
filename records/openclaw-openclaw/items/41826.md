## Summary

Keep open: current main and v2026.6.11 still hardcode the Gateway-visible TUI label as `openclaw-tui`, with no `openclaw tui` flag, TUI option, or config key for a custom client display name. The Gateway already has a `displayName` handshake seam, so the remaining work is a product/privacy decision about the public surface rather than missing protocol support.

## What This Changes

The issue requests a user-controlled TUI client display name, such as an `openclaw tui` flag or auto-derived label, so multiple TUI Gateway connections can be distinguished.

## Best Possible Solution

Add an explicit opt-in Gateway-mode TUI display-name override that preserves `openclaw-tui` as the default, validates and trims the label, documents privacy-safe usage, and avoids automatic host/workdir labels unless maintainers approve that policy.
