## Summary

Keep open: current main and the latest release still hardcode the Gateway-visible TUI display label as `openclaw-tui`, and the remaining work is choosing the public CLI/config/privacy shape for a user-facing override.

## What This Changes

The issue requests a custom display name for Gateway-backed `openclaw tui` clients so multiple TUI windows can be distinguished in Gateway presence/session surfaces.

## Best Possible Solution

Add an explicit opt-in Gateway-mode TUI display-name override that preserves `openclaw-tui` as the default, validates and trims the label, documents privacy-safe usage, and avoids automatic host/workdir labels unless maintainers approve that policy.
