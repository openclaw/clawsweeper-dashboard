## Summary

Keep open: current `main` and v2026.6.11 still hardcode the Gateway-visible TUI display name as `openclaw-tui`, and the CLI, docs, and `TuiOptions` do not expose an override. The Gateway client already has a display-name seam, so the remaining work is a narrow but product/privacy-sensitive TUI identity feature.

## What This Changes

The issue requests a way for `openclaw tui` users to set or generate a unique Gateway-visible client display name instead of every TUI connection appearing as `openclaw-tui`.

## Best Possible Solution

Add an explicit opt-in Gateway-mode `openclaw tui --client-name <name>` override that preserves `openclaw-tui` as the default, validates and bounds the label, documents privacy-safe usage, and defers hostname/TTY/workdir auto-naming unless maintainers approve it.
