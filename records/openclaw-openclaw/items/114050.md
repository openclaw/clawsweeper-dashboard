## Label Justifications

- `P2`: This is a bounded provider-runtime bug that can corrupt an OpenRouter music track when malformed network audio is received.

## Summary

Keep open. The base branch still decodes malformed OpenRouter music SSE Base64 leniently, while this focused patch rejects invalid payloads before size accounting and decoding; the regression test and supplied before/after local SSE-proxy transcript support the fix.

## What This Changes

The PR validates each decoded segment of streamed OpenRouter music audio with the shared Base64 canonicalizer and adds a regression test that rejects malformed SSE audio data.

## System Context

The OpenRouter extension turns streamed music-generation SSE events into an audio track returned to the generic music-generation runtime. Audio text is accumulated across provider chunk boundaries, decoded under the configured media-size limit, and emitted as the generated track.

## Architecture Diagram

  B --> C[Base64 chunk accumulator]
  C --> D[Canonical Base64 validation]

  E --> F[Generated audio track]
  D --> G[Provider error on malformed data]

## Best Possible Solution

Retain the shared canonical Base64 validation immediately before OpenRouter audio size accounting and decoding, with the malformed-SSE regression coverage kept alongside the stream accumulator.
