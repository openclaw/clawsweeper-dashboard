Full review comments:

- **[P1] Document these markers as context, not proof:** `docs/help/environment.md:123-124`
  - body: The new docs say scripts can reliably identify the agent/session, while the linked workflows use these values for approvals, push policy, callback routing, and observability. Child-process env is ambient process data, so the docs should state these are routing/context hints and not sufficient authorization proof.
  - confidence: 0.88
- **[P1] Do not silently overwrite explicit env values:** `src/agents/bash-tools.exec-runtime.ts:676-677`
  - body: The PR writes the trusted values after `...opts.env`, so an existing exec call or plugin env that explicitly sets these names now receives OpenClaw's value, or `""`, without a clear reserved-name contract. Either reject these keys with a clear reserved error or preserve explicit override behavior until maintainers approve the breaking reservation; node and macOS paths should follow the same decision.
  - confidence: 0.9
- **[P2] Assert empty markers are actually present:** `src/agents/bash-tools.exec.path.test.ts:346-351`
  - body: The clearing tests print `${VAR:-}`, which is identical when the key is absent or present with an empty string. Capture the mocked supervisor `input.env` or use a shell presence check so the always-set contract is actually protected.
  - confidence: 0.96
