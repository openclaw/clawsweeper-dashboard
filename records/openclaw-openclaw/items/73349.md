  - body: The docs say scripts can reliably identify the agent and session from these env vars, while linked use cases include approval, push-policy, and observability decisions.   - body: Placing the trusted values after `...opts.env` means an existing exec call that explicitly sets `OPENCLAW_AGENT_ID` or `OPENCLAW_SESSION_KEY` now gets a different value, or an empty string, without warning. Either reject those keys as reserved with a clear error or preserve explicit override behavior until maintainers approve the breaking reservation; node and macOS should follow the same decision.
  - confidence: 0.9

  - body: The clearing tests assert empty command output, but `${VAR:-}` cannot distinguish an absent key from a present empty-string value. Capture the mocked supervisor `input.env` for these calls and assert the env object directly so the always-present empty-string contract is actually covered.
