## Summary

Keep open: current main and the latest release still perform a single `tailscale status --json` read immediately after Serve setup, and the open closing PR has not landed.

## What This Changes

The issue asks for a narrow retry/backoff around transient Tailscale status JSON failures during Gateway Serve startup, with a binary-path config option only as an alternate suggestion.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/91553 or a narrow replacement that retries the existing status JSON read, suppresses non-final retry noise, preserves fast missing-binary fallback, and avoids adding `gateway.tailscale.binaryPath`.
