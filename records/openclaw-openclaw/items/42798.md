## Summary

Keep open: current main and v2026.6.11 still have the immediate single Tailscale status read after Serve setup, and the open closing PR remains the active unresolved fix path.

## What This Changes

The issue reports that Tailscale Serve startup can log transient `tailscale status --json` failures because status is queried immediately after enabling Serve.

## Best Possible Solution

Resolve this through https://github.com/openclaw/openclaw/pull/91553 or a narrow replacement that retries the existing status JSON read, suppresses non-final retry noise, preserves quick fallback for missing binaries, and avoids adding `gateway.tailscale.binaryPath`.

## Solution Assessment
