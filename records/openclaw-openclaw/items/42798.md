## Summary

Keep open because current main and the latest release still do a one-shot `tailscale status --json` read immediately after Serve startup, while the linked closing PR remains open and conflicting rather than merged.

## What This Changes

The issue asks for retry/backoff around Tailscale status hostname discovery after enabling Tailscale Serve during gateway startup.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/91553 or a narrow replacement that retries the status JSON read, suppresses non-final retry noise, preserves fast missing-binary fallback, and avoids adding a Tailscale binary-path config option.
