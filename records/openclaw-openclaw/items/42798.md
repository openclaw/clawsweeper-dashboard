## Summary

Keep open because current main and the latest release still do a one-shot `tailscale status --json` immediately after Tailscale Serve startup, and the open closing PR has not merged.

## What This Changes

The issue requests a retry or short backoff for transient `tailscale status --json` failures during Gateway Tailscale Serve startup.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/91553 or a narrow replacement that retries the status JSON read, suppresses non-final retry noise, preserves fast missing-binary fallback, and avoids adding new Tailscale config surface.
