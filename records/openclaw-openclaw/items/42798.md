## Summary

Keep open because current main and the latest release still have the immediate one-shot `tailscale status --json` read after Tailscale Serve startup, and the open closing PR is unmerged and conflicting.

## What This Changes

The issue requests retry/backoff around `tailscale status --json` during Tailscale Serve startup to avoid transient startup log errors.

## Best Possible Solution

Resolve this through https://github.com/openclaw/openclaw/pull/91553 or a narrow replacement that retries the existing status JSON read, keeps non-final retry noise out of verbose logs, preserves fast missing-binary fallback, and avoids adding new Tailscale config surface.
