## Summary

## What This Changes

This PR changes the Chat workspace Copy path callback to use `copyToClipboard` and adds/shared plain-HTTP clipboard fallback E2E coverage.

## Best Possible Solution

Land this evidence-backed helper reuse, or one equivalent canonical PR with the workspace Copy path E2E regression, then close the linked issue and duplicate fix attempts after merge.

## Reproduction Assessment

Yes at source level: current main routes the rendered Copy path button through `onCopyPath` to a callback that only optional-calls `navigator.clipboard.writeText`. I did not run a failing browser repro locally, but the PR's after-fix browser E2E exercises the missing-clipboard condition.

## Solution Assessment

Yes: reusing the existing `copyToClipboard` helper is the narrowest maintainable fix. Patching the compiled bundle or adding another inline fallback would duplicate behavior and increase drift.
