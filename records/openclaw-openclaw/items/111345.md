## Label Justifications

- `P1`: A successful command cron job can currently back off or fail to delete after a delivery-only error, disrupting scheduled automation for affected users.
- `merge-risk: 🚨 compatibility`: Merging changes how existing jobs with omitted `bestEffort` react to announce-delivery failure.

## Summary

Keep this PR open for normal maintainer review: the current implementation conflates a successful command with failed announce delivery, and the proposed separation aligns with the documented command exit-status contract. The protected `maintainer` label prevents automated cleanup or merge routing.

## What This Changes

The branch changes command cron delivery-failure handling so only explicitly required delivery (`bestEffort: false`) converts a successful command run into an execution error, with focused regression coverage.

## Best Possible Solution

Keep execution success, scheduler cadence, and `deleteAfterRun` keyed to the command result; record failed implicit announce delivery only through the delivery-status fields, while preserving strict behavior for explicit `bestEffort: false`.
