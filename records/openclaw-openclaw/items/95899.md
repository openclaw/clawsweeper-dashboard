## Summary

This PR remains useful because current main still asks users to resend when a transcript tail cannot safely resume, but the unchanged P1 replay-precedence defect can discard a pending final reply and repeat already-completed work; maintainers should settle the replay policy before merge.

## What This Changes

The branch re-presents the last transcript user message for text-only assistant tails after Gateway restart, expands structured-content parsing and tail inspection, and adds restart-recovery tests.

## Best Possible Solution

Preserve pending-final delivery as the first recovery choice; only consider recovered-request replay when no pending result exists, and require a maintainer-approved confirmation or idempotency policy for turns that may already have performed side effects.
