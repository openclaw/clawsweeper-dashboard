## Summary

The latest commit resolves the previously reported queued-final ordering defect, but one blocking direct-delivery bug remains: generated block content is treated as successfully delivered, so a declined or failed block send can also suppress the buffered terminal warning.

## What This Changes

This PR buffers failed tool-progress events in regular verbose auto-reply and queued follow-up delivery, discarding them after successful reply delivery while retaining diagnostics for terminal failures and full verbose mode.

## Best Possible Solution

Track confirmed successful block delivery separately from generated block count, and discard buffered failures only after an actual clean final, observed message-tool delivery, or delivered block reply; cover routed suppression/failure and dispatcher-decline cases.

## Solution Assessment

No. Buffering recovered failures is the right policy, but generated block count is not reliable proof of user-visible delivery; the discard decision must use the actual delivery result.
