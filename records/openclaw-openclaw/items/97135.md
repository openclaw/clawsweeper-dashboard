## Summary

Keep this PR open: the central bug is real and current main still sends failed queued progress immediately, but the live patch introduces a queued follow-up message-delivery regression by dropping buffered failed progress before the final reply is known to have delivered.

## What This Changes

The PR buffers or hides recovered failed tool progress in regular verbose auto-reply and queued follow-up delivery while preserving full-verbose diagnostics.

## Best Possible Solution

Keep the recovered-progress buffering policy, but make queued follow-ups mirror direct dispatch by discarding buffered failed progress only after a clean final reply is confirmed delivered; otherwise flush the buffered failure.
