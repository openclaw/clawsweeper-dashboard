## Label Justifications

- `P1`: The issue blocks real multi-agent users from enabling memory-wiki safely on one gateway because wiki state and search can cross intended agent boundaries.
- `impact:session-state`: The reported behavior mixes memory-wiki vault content, prompt context, indexes, and search results across agents that operators expect to keep isolated.
- `impact:security`: A shared memory-wiki vault can expose private or tenant-specific knowledge across agent boundaries unless isolation semantics are defined.

## Summary

Keep open: current main and v2026.6.11 still resolve memory-wiki through one global plugin config and one vault path, while the issue discussion shows real shared-gateway multi-agent memory isolation and sensitive-data boundary impact that no merged PR now owns.

## What This Changes

Request per-agent memory-wiki vault configuration so agents in one gateway can keep wiki pages, indexes, and search results isolated instead of sharing one global vault.

## Best Possible Solution

Define one maintainer-approved memory-wiki isolation contract with schema precedence, vault routing, no-context behavior, security and upgrade guidance, docs, and a two-agent regression proving isolated writes and searches.

Rationale: The choice controls sensitive memory visibility, config precedence, plugin SDK surface, CLI/gateway semantics, and upgrade expectations, so automation cannot safely select the permanent product/security boundary from source evidence alone.

Owner confidence: high

Options:

- **Design plugin-owned vault isolation (recommended):** Add a memory-wiki-owned per-agent or context-aware vault contract first, coordinated with the broader per-agent plugin config issue but not blocked on it.
- **Wait for generic plugin overrides:** Keep this issue open behind #55401 and solve memory-wiki through a shared agents.list[].plugins precedence, SecretRef, validation, and lifecycle contract.
- **Document unsupported shared-gateway isolation:** Leave memory-wiki global for now and document separate gateways or separate installs as the only supported hard isolation boundary.
