## Label Justifications

- `P1`: The issue blocks real multi-agent users from enabling memory-wiki safely on one gateway because wiki state and search can cross intended agent boundaries.
- `impact:session-state`: The reported behavior can mix memory-wiki vault content, prompt context, indexes, and search results across agents that operators expect to keep isolated.

## Summary

Keep open: current main and v2026.6.11 still route memory-wiki through one global plugin config and one vault path, while the issue discussion shows real multi-agent memory isolation and security-boundary impact with no merged replacement owning the work.

## What This Changes

Add per-agent memory-wiki vault configuration so agents on one gateway can keep wiki writes, search, prompt context, and indexes isolated.

## Best Possible Solution

Define one maintainer-approved memory-wiki isolation contract with schema precedence, vault routing, no-context behavior, security/upgrade guidance, docs, and a two-agent regression proving isolated writes and searches.
