## Summary

Keep open: current main still resolves memory-wiki from one global plugin config and one vault path, while the issue discussion shows real multi-agent isolation and sensitive-memory boundary impact that no merged viable PR owns.

## What This Changes

The issue requests per-agent memory-wiki vault configuration so agents on one gateway can keep wiki storage and search isolated.

## Best Possible Solution

Define one maintainer-approved memory-wiki isolation contract with schema precedence, vault routing, no-context behavior, security/upgrade guidance, docs, and a two-agent regression proving isolated writes and searches.
