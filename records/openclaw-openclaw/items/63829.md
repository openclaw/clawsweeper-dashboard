## Label Justifications

- `P1`: The issue blocks real multi-agent users from enabling memory-wiki safely on one gateway because wiki state and search can cross intended agent boundaries.
- `impact:session-state`: The reported behavior mixes memory-wiki vault content, prompt context, indexes, and search results across agents that operators expect to keep isolated.
- `impact:security`: A shared memory-wiki vault can expose private or tenant-specific knowledge across agent boundaries unless isolation semantics are defined.

## Summary

Keep open: current main and v2026.6.11 still resolve memory-wiki through one global plugin config and one vault path, while the issue discussion shows real shared-gateway memory isolation and sensitive-data boundary impact that no merged or viable PR now owns.

## What This Changes

Add a per-agent memory-wiki vault/configuration contract so agents on one gateway can keep wiki content, indexes, prompts, and searches isolated.

## Best Possible Solution

Define one maintainer-approved memory-wiki isolation contract with schema precedence, vault routing, no-context behavior, security/upgrade guidance, docs, and a two-agent regression proving isolated writes and searches.
