## Label Justifications

## Summary

Keep open: current main and v2026.6.11 still resolve memory-wiki from one global plugin config and one vault path, while the discussion shows real multi-agent memory isolation and sensitive-data boundary impact with no merged or viable implementation PR now owning the work.

## What This Changes

Request per-agent memory-wiki vault configuration so agents sharing one gateway can keep wiki vaults, indexes, and search results isolated.

## Best Possible Solution

Pick a maintainer-approved memory-wiki-owned per-agent vault contract for the first increment, keep current global behavior as the default, and coordinate the generic `agents.list[].plugins` work separately.

Rationale: The source gap is clear, but the permanent contract affects memory isolation, security posture, config/default surface, CLI/gateway behavior, and upgrade/doctor expectations, so automation should not choose it alone.

Owner confidence: medium

Options:

- **Approve memory-wiki-owned per-agent vault scope (recommended):** Add a default-off `memory-wiki` config contract such as `vault.scope: "global" | "per-agent"` with explicit per-agent path resolution, no-context behavior, docs, and two-agent regression proof while leaving generic plugin overrides to https://github.com/openclaw/openclaw/issues/55401.
- **Defer to generic per-agent plugin config:** Keep this issue open as a memory-wiki consumer of https://github.com/openclaw/openclaw/issues/55401 and implement vault isolation only after the shared plugin config precedence and validation contract exists.
- **Reject same-gateway vault isolation for now:** Document separate gateways as the supported hard-isolation boundary and close or narrow memory-wiki vault work to docs and diagnostics only.
