## Label Justifications

- `P1`: The issue affects real multi-agent memory isolation for current users, but it is not a crash loop, data-loss emergency, or first-run release blocker.
- `impact:session-state`: All agents currently share the same memory-wiki vault path, so agent/session memory state can be mixed instead of isolated by configuration.
- `impact:security`: The requested isolation is also a sensitive-memory boundary because different agents may need separate private vaults and credentials.

## Summary

Keep open: current main and the latest release still resolve memory-wiki from one global plugin config and one vault path, while the issue discussion shows a real multi-agent memory isolation and security-boundary need that no merged implementation now owns.

## What This Changes

Request per-agent memory-wiki vault configuration so different agents can use isolated wiki vaults instead of the single global memory-wiki vault path.

## Best Possible Solution

Choose a maintainer-approved isolation contract, then implement memory-wiki vault selection consistently across tools, search/get/apply, prompt/corpus supplements, gateway/CLI surfaces, docs, tests, and any needed doctor or upgrade path.
