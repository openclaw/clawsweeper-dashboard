## Label Justifications

- `P1`: The issue blocks real multi-agent users from enabling memory-wiki safely on one gateway because wiki state and search can cross intended agent boundaries.
- `impact:session-state`: The reported behavior mixes memory-wiki vault content, indexes, prompt context, and search results across agents that operators expect to keep isolated.

## Summary

Keep open: current main still resolves memory-wiki through one global plugin config and one vault path, while the issue discussion shows real multi-agent isolation and security impact that no merged safe PR now owns.

## What This Changes

Add per-agent memory-wiki vault configuration or scoping so multiple agents on one gateway can keep wiki content isolated.

## Best Possible Solution

Choose and document a maintainer-approved agent-scoped memory-wiki contract covering config precedence, vault routing, no-context behavior, doctor/upgrade handling, and two-agent regression proof.
