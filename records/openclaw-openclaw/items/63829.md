## Label Justifications

- `P1`: Multiple users report memory-wiki is unsafe or disabled in real multi-agent gateway setups because wiki memory can cross intended agent boundaries.
- `impact:session-state`: The issue is about plugin-owned wiki memory and search state being shared across agents that operators expect to keep isolated.

## Summary

Keep open: current main and v2026.6.11 still use one registration-time memory-wiki vault config, while the discussion shows real multi-agent isolation and sensitive-memory boundary impact that needs maintainer product/security direction.

## What This Changes

Request per-agent memory-wiki vault configuration so agents on one gateway can keep isolated wiki vaults and search results instead of sharing one global memory-wiki vault.

## Best Possible Solution

Choose one maintainer-approved isolation contract, then implement memory-wiki vault routing consistently across tools, gateway methods, CLI, prompt/corpus supplements, docs, doctor/upgrade handling, and two-agent regression coverage.
