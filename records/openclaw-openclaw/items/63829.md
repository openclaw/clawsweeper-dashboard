## Label Justifications

- `P1`: The issue blocks real multi-agent users from enabling memory-wiki safely on one gateway because wiki state and search can cross intended agent boundaries.
- `impact:session-state`: The reported behavior mixes memory-wiki vault content, prompt context, indexes, and search results across agents that operators expect to keep isolated.
- `impact:security`: A shared memory-wiki vault can expose private or tenant-specific knowledge across agent or tenant boundaries unless isolation semantics are defined.

## Summary

Keep open: current main and latest stable still resolve memory-wiki from one global plugin config and one vault path, so the reported shared-gateway multi-agent vault isolation problem remains real and no merged replacement owns it.

## What This Changes

Add per-agent memory-wiki vault configuration so agents on one gateway can keep separate wiki roots and avoid cross-agent wiki search/write bleed.

## Best Possible Solution

Define one maintainer-approved memory-wiki isolation contract, then route wiki apply/search/get/prompt/corpus paths through the effective agent context with security guidance, upgrade docs, and a two-agent regression proving isolated writes and reads.
