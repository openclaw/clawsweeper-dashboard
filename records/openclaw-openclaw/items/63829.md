## Label Justifications

- `P1`: The issue blocks real multi-agent users from enabling memory-wiki safely on one gateway because wiki state and search can cross intended agent boundaries.
- `impact:session-state`: The reported behavior mixes memory-wiki vault content, prompt context, indexes, and search results across agents that operators expect to keep isolated.

## Summary

Keep open: current main and v2026.6.11 still resolve memory-wiki from one global plugin config and one vault path, while the discussion shows real multi-agent isolation and sensitive-memory boundary impact that no merged or viable PR owns.

## What This Changes

The issue requests per-agent memory-wiki vault configuration so multiple agents on one gateway can keep wiki pages, indexes, and search results isolated.

## Best Possible Solution

Define one maintainer-approved memory-wiki isolation contract with schema precedence, vault routing, no-context behavior, security/upgrade guidance, docs, and a two-agent regression proving isolated writes and searches.
