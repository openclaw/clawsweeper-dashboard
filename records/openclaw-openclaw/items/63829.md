## Label Justifications

- `P1`: The issue blocks real multi-agent users from safely enabling memory-wiki on one gateway because wiki state can cross intended agent boundaries.
- `impact:session-state`: A single shared vault can mix memory-wiki pages, prompts, corpus state, and search results across agents.

## Summary

Keep open: current main and the latest checked release still route memory-wiki through one global vault configuration, while the issue discussion and source inspection show a real multi-agent isolation problem that needs a maintainer product/security contract before implementation.

## What This Changes

The issue requests per-agent memory-wiki vault configuration so agents sharing one gateway can keep wiki files, prompts, search, and apply operations isolated.

## Best Possible Solution

Define one maintainer-approved memory-wiki isolation contract, then implement vault routing consistently across tools, prompt/corpus supplements, gateway, CLI, docs, and upgrade repair with two-agent regression proof.

Yes at source level: current code resolves one memory-wiki config and one vault path for all agents, while the strict agent schema has no plugin override field; no live write/search repro was run in this read-only review.

## Solution Assessment

Unclear until maintainers choose the contract; the requested outcome is valid, but a one-off partial override would be weaker than a consistent vault resolver with explicit no-context behavior and upgrade handling.
