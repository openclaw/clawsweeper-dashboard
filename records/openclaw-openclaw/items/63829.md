## Summary

Keep open: current main still resolves memory-wiki through one global plugin configuration and one vault path, while the issue discussion describes real multi-agent memory contamination and sensitive-state impact with no merged fix owning the work.

## What This Changes

Request per-agent memory-wiki vault configuration so agents sharing one gateway can use isolated wiki vaults instead of the single global `plugins.entries.memory-wiki.config.vault.path`.

## Best Possible Solution

Define one maintainer-approved memory-wiki isolation contract with schema precedence, agent/no-agent routing behavior, security/upgrade docs, and a two-agent write/search regression proving isolated vaults.

## Solution Assessment
