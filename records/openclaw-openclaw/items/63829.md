## Summary

Keep open: current main and v2026.6.11 still resolve memory-wiki from one global plugin config and one vault path, while the discussion shows a real multi-agent isolation and sensitive-memory boundary need that no merged or viable PR now owns.

## What This Changes

Add a memory-wiki vault isolation/configuration mechanism so each configured agent can use an isolated wiki vault instead of one global plugin vault.

## Best Possible Solution

Define one maintainer-approved memory-wiki isolation contract with schema precedence, vault routing, no-context CLI/gateway behavior, docs/doctor guidance, and a two-agent regression proving isolated writes and searches.
