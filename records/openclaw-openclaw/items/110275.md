## Summary

Keep this PR open: it restores throwing for malformed JSON, but it still accepts syntactically malformed base64url strings that Node decodes permissively, so the listener can continue returning 200 for an invalid policy URL.

## What This Changes

The PR removes the decoder’s catch-all fallback so malformed MCP sandbox CSP metadata throws and the existing HTTP listener can return 400.

## Best Possible Solution

Validate the encoded CSP as exact base64url before decoding, retain the listener as the sole HTTP-400 conversion owner, and add endpoint-level proof that a valid policy with a trailing invalid byte receives 400.

## Reproduction Assessment

Yes, from source: append an invalid non-base64url byte such as `!` to an otherwise valid encoded CSP. Node’s base64url decoding can ignore that byte, so JSON parsing still succeeds and the listener does not reach its existing 400 conversion path.

## Solution Assessment

No: removing the catch-all is directionally correct, but strict rejection also requires validating the encoded base64url form before parsing; otherwise a malformed value can still become a valid decoded policy.
