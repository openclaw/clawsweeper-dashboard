Keep open: current main and the latest release still lack provider quota windows in per-response `/usage` footers, and this PR is the active focused implementation candidate. ## What This Changes

The branch makes reply usage-line resolution async, appends provider usage-window summaries to usage-enabled reply footers, and updates the normal and follow-up reply callers plus regression tests.

## Best Possible Solution

Restore the token-use docs, keep provider-specific fetching inside the existing provider-usage/plugin seams, and land only after maintainers accept the bounded per-reply lookup or ask for a cached/preloaded quota design.

## Solution Assessment

Mostly yes. Reusing the generic provider-usage loader and formatter is the right implementation layer, but the branch should restore the dropped docs and maintainers still need to accept or revise the timeout tradeoff.
