## Summary

Keep open for maintainer landing: current main still permits a stalled OpenAI device-code request or response body to hang indefinitely, while the proposed provider-local fix is well-proven and has no identified correctness or security blocker. The branch is behind current main, so the exact rebased head still needs refreshed validation.

## What This Changes

The PR adds 30-second fetch-and-body deadlines, cancellation-preserving error handling, timeout retries for authorization polling, and regression coverage for OpenAI device-code authentication.

## Best Possible Solution

Keep the timeout provider-local, treat headers plus bounded body consumption as one operation, clamp poll operations to the existing overall authorization deadline, and preserve caller cancellation as a distinct non-retry outcome.

## Solution Assessment

Yes. A provider-local operation deadline composed with the existing caller signal is narrower and more maintainable than changing global fetch behavior, and clamping poll requests preserves the established overall authorization deadline.
