## Summary

This is a valid upgrade regression: a previously accepted config key is retired with a doctor migration, but strict validation can reject that key before the repair path runs, leaving the documented recovery command unusable and supervised gateways in a crash loop. No related item currently owns this repair; https://github.com/openclaw/openclaw/issues/106768 describes a distinct build-atomicity problem that only exposed this failure mode.

## What This Changes

Make `openclaw doctor --fix` able to remove the retired `cron.runLog` key before strict canonical-config validation rejects it.

## Best Possible Solution

Have doctor parse the raw config sufficiently to run registered legacy migrations, write the canonical result, and then enforce strict validation; add an upgrade regression test for `cron.runLog` and keep normal gateway runtime strict without an alias or fallback reader.
