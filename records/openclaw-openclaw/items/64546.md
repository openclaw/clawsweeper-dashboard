## Summary

Keep open: current main and v2026.6.11 still contain the Mattermost bot-token-derived interaction signing path, and this PR remains the linked candidate fix, but the branch is not merge-ready because the replacement can generate process-local secrets, lacks supported setup/docs/SecretRef wiring, and is currently dirty against main.

## What This Changes

The PR changes Mattermost interaction signing to use configured or generated per-account secrets instead of deriving the signing secret from the bot token.

## Best Possible Solution

Land a refreshed security fix, or a narrow replacement, that removes bot-token-derived Mattermost interaction signing while making the replacement secret durable or explicitly fail-closed through supported setup, SecretRef, docs, tests, and restart/split-process proof.

## Reproduction Assessment

Yes. Current main and v2026.6.11 source show the deterministic bot-token-derived HMAC secret used for Mattermost `_token` verification; I did not run a live Mattermost server in this read-only review.

## Solution Assessment

No. Removing bot-token-derived signing is the right direction, but the current in-memory fallback plus hidden credential surface is not the narrowest upgrade-safe solution for a secret shared by sender and callback verifier.
