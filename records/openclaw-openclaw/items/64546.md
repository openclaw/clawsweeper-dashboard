## Label Justifications

- `P1`: The PR addresses a Mattermost callback authorization vulnerability but currently has merge-blocking security-boundary and delivery regressions.
- `merge-risk: 🚨 compatibility`: Existing deployments without the new secret can change behavior or fail after upgrade, and account-level secret config can replace inherited interaction settings.

- `merge-risk: 🚨 security-boundary`: The patch changes the HMAC key material that gates Mattermost interaction callback authorization and leaves old signing guidance in docs.

## Summary

Keep open: this PR is the right security direction for the linked Mattermost token-forgery bug, but it is not merge-ready because the fallback secret is process-local, the public signing docs still describe the old bot-token-derived contract, account-level secret config can replace inherited interaction settings, and GitHub currently reports the branch as conflicting.

## What This Changes

The PR adds Mattermost `interactions.secret` config support and switches interaction-token signing from bot-token-derived HMAC secrets to configured or process-generated per-account secrets in send, monitor, schema, and tests.

## Best Possible Solution

Land a refreshed fix that removes bot-token-derived signing while making every Mattermost signer and verifier share a durable per-account secret, or explicitly requiring `interactions.secret`, with docs and tests covering the chosen upgrade path.

## Reproduction Assessment

Yes. Source inspection of current main shows the interaction secret is derived from the bot token with a public HMAC key and used to verify callback `_token` values; I did not run a live Mattermost server in this read-only review.

## Solution Assessment

No, not as currently proposed. Removing bot-token-derived signing is the right direction, but the unconfigured random fallback is not the best fix because Mattermost button signing and verification can happen in different processes.

## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Preserve a shared Mattermost interaction secret:** `extensions/mattermost/src/mattermost/interactions.ts:198-200`
  - body: When `interactions.secret` is unset, this branch generates a random secret in whichever process first calls `ensureInteractionSecret`. The sender and gateway monitor seed that state independently, so a button signed by one process can be rejected by the verifier as `Invalid token`; use a durable shared secret or explicitly require configured setup before merge.
  - confidence: 0.9
- **[P1] Update the Mattermost signing contract docs:** `extensions/mattermost/src/config-schema-core.ts:150`
  - body: This adds `interactions.secret`, but the Mattermost direct-API docs still instruct external scripts to derive the HMAC secret from the bot token with the old public key. After this patch that guidance is both the unsafe model being removed and a source of invalid callback tokens.
  - confidence: 0.88
- **[P2] Keep account interaction options merged:** `extensions/mattermost/src/mattermost/accounts.ts:118-123`
  - body: Resolving `merged.interactions?.secret` after adding an account-level secret is not enough because Mattermost account config only deep-merges `commands`. An account that sets only `interactions.secret` can drop inherited `interactions.callbackBaseUrl` or `allowedSourceIps`, which changes callback reachability and source filtering for that account.
  - confidence: 0.82
