## Label Justifications

- `P1`: This is a security-sensitive Mattermost interaction auth fix, but the current PR can break valid button callbacks in existing deployments.
- `merge-risk: 🚨 compatibility`: The PR changes the fallback signing root from bot-token-derived to generated/configured, which can break existing unset-secret upgrades.
- `merge-risk: 🚨 message-delivery`: A gateway restart or split sender/verifier process can make legitimate Mattermost button callbacks fail token verification.
- `merge-risk: 🚨 security-boundary`: The PR changes the credential that protects Mattermost interaction callbacks without complete provisioning, strength guidance, or operator docs.

## Summary

Keep open: current main and the latest release still have the Mattermost hardcoded-HMAC signing issue, and this PR is the linked candidate fix, but it is not merge-ready because the replacement secret can be process-local and the new credential surface is not provisioned or documented.

## What This Changes

The PR replaces Mattermost interaction signing secret derivation from the bot token with configured or generated per-account interaction secrets, plus schema, type, and test updates.

## Best Possible Solution

Land a refreshed PR that removes bot-token-derived signing while making the Mattermost interaction secret durable or explicitly provisioned, documented, and proven across restart or split sender/verifier execution.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 derive the Mattermost interaction HMAC secret from the bot token with a public key, and the PR's unset-secret regression is source-reproducible because generated secrets are process-local.

## Solution Assessment

No. Removing bot-token-derived signing is the right direction, but an in-memory random fallback plus hidden config is not the best upgrade-safe solution for a credential shared by sender and callback verifier.
