## Label Justifications

- `P1`: The PR addresses a high-impact Mattermost interaction-token forgery but currently has merge-blocking delivery and security-boundary uncertainty.
- `merge-risk: 🚨 compatibility`: Existing Mattermost deployments without the new secret can change behavior or fail closed after upgrade.
- `merge-risk: 🚨 message-delivery`: A per-process generated secret can make legitimate Mattermost button callbacks fail `_token` verification.
- `merge-risk: 🚨 security-boundary`: The patch changes the HMAC key material that gates Mattermost interaction callback authorization.

## Summary

Keep open: the security fix is still needed, but this PR is not merge-ready because the unconfigured fallback can generate different in-memory secrets in the sender and gateway processes, and GitHub currently reports the branch as conflicting.

## What This Changes

The PR adds Mattermost account-level `interactions.secret` support and replaces bot-token-derived interaction signing with configured or randomly generated per-account secrets.

## Best Possible Solution

Keep the security direction, but make the unconfigured path explicitly upgrade-safe: use one durable shared per-account interaction secret or require `interactions.secret` with clear docs, tests, and fail-closed setup guidance.

## Reproduction Assessment

Yes. Source inspection shows current main derives the Mattermost interaction signing secret from the bot token with a public HMAC key and verifies callback `_token` values with it; I did not run a live Mattermost server in this read-only review.

## Solution Assessment

No, not as currently proposed. Removing bot-token-derived signing is the right security direction, but generating an unpersisted per-process fallback is not the best fix because `send.ts` and `monitor.ts` can sign and verify with different secrets.

## Review Findings

Full review comments:

- **[P1] Preserve a shared interaction secret across processes:** `extensions/mattermost/src/mattermost/interactions.ts:198-200`
  - body: When `interactions.secret` is unset, this branch calls `ensureInteractionSecret` independently from the sender and the gateway monitor, and each process can generate its own random secret. A button sent by one process can then be rejected by the gateway as `Invalid token`, so the fallback needs a durable shared secret or an explicit fail-closed requirement before merge.
  - confidence: 0.89
- **[P2] Update the Mattermost signing docs for the new secret:** `extensions/mattermost/src/config-schema-core.ts:150`
  - body: This adds `interactions.secret`, but the Mattermost direct-API docs on the PR head still tell external scripts to derive the HMAC secret from the bot token with the old public key. After this patch those examples produce invalid tokens and preserve the unsafe model the PR is removing, so the docs/setup guidance need to move to the new secret contract.
  - confidence: 0.86
