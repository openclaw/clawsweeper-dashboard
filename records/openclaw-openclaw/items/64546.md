## Summary

Keep open: this is a real Mattermost security fix candidate, but the branch still has merge-blocking upgrade and authorization issues around the new interaction secret contract, and GitHub currently reports the PR as conflicting.

## What This Changes

The PR adds Mattermost `interactions.secret` support and switches interaction-token signing from bot-token-derived HMAC secrets to configured or generated per-account secrets.

## Best Possible Solution

Land a refreshed fix that removes bot-token-derived signing while making every signer and verifier share a durable per-account secret, or explicitly requiring `interactions.secret`, with docs, config-merge behavior, and tests covering the chosen upgrade path.

## Reproduction Assessment

Yes. Source inspection shows current main derives the Mattermost interaction signing secret from the bot token with a public HMAC key, and the PR-body runtime proof shows old bot-token-derived forged tokens fail after the patch.

## Solution Assessment

No, not as currently proposed. Removing bot-token-derived signing is the right direction, but the unconfigured random fallback is not the best fix because Mattermost button signing and verification can happen in different processes.

Full review comments:

- **[P1] Preserve a shared Mattermost interaction secret:** `extensions/mattermost/src/mattermost/interactions.ts:198-200`
  - body: When `interactions.secret` is unset, this branch generates a random secret in whichever process first calls `ensureInteractionSecret`. The sender and gateway monitor seed that state independently, so a button signed by one process can be rejected by the verifier as `Invalid token`; use a durable shared secret or explicitly require configured setup before merge.
  - confidence: 0.9
- **[P1] Update the Mattermost signing contract docs:** `extensions/mattermost/src/config-schema-core.ts:150`
  - body: This adds `interactions.secret`, but the Mattermost direct-API docs on the PR head still instruct external scripts to derive the HMAC secret from the bot token with the old public key. After this patch that guidance is both the unsafe model being removed and a source of invalid callback tokens.
  - confidence: 0.88
- **[P2] Keep account interaction options merged:** `extensions/mattermost/src/mattermost/accounts.ts:118-123`
  - body: Resolving `merged.interactions?.secret` after adding an account-level secret is not enough because Mattermost account config only deep-merges `commands`. An account that sets only `interactions.secret` can drop inherited `interactions.callbackBaseUrl` or `allowedSourceIps`, which changes callback reachability and source filtering for that account.
  - confidence: 0.82
