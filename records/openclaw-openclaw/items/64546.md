## Label Justifications

- `P1`: The PR addresses a high-impact Mattermost callback-token forgery path but may also break valid button callbacks if the replacement secret is not durable.
- `merge-risk: 🚨 compatibility`: Merging this PR can make existing unset-secret Mattermost deployments fail button callbacks after restart or split-process execution.
- `merge-risk: 🚨 message-delivery`: The changed signing state can cause legitimate Mattermost button click callbacks to be rejected as invalid tokens.
- `merge-risk: 🚨 security-boundary`: The PR changes the credential that gates Mattermost callback authorization and leaves the replacement provisioning model incomplete.

## Summary

This PR should stay open because current main and the latest release still use the forgeable bot-token-derived Mattermost interaction HMAC, and this branch is the linked candidate fix. It is not merge-ready yet: the replacement can fall back to a process-local random secret, the new credential surface is not wired through supported setup/SecretRef/docs paths, and the branch is currently dirty against the base.

## What This Changes

The PR changes Mattermost button callback signing from a bot-token-derived HMAC secret to configured or generated per-account interaction secrets, with related config schema and tests.

## Best Possible Solution

Choose an upgrade-safe Mattermost interaction-secret model, then wire setup, SecretRef target metadata, public Mattermost docs, restart or split-process coverage, and a clean branch refresh before merge.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 derive the Mattermost interaction HMAC secret from the bot token with a public key and use it for callback _token verification; I did not run a live Mattermost server in this read-only review.

## Solution Assessment

No. Removing bot-token-derived signing is the right direction, but an in-memory random fallback plus hidden config surface is not the narrowest upgrade-safe solution for a credential shared by sender and callback verifier.
