## Summary

Keep open: the PR targets a real Mattermost callback-signing security bug, but it is not merge-ready because the generated fallback secret is process-local, the new credential is not wired through supported setup/SecretRef/docs surfaces, and the head is currently conflicting with main.

## What This Changes

The PR adds a Mattermost `interactions.secret` credential and changes button HMAC signing to use configured or generated per-account secrets instead of deriving them from the bot token.

## Best Possible Solution

Land a refreshed or replacement fix that removes bot-token-derived signing while making the Mattermost interaction secret durable or explicitly fail-closed, with setup, SecretRef metadata, docs, restart/split-process proof, and old-forgery rejection coverage.

## Reproduction Assessment

Yes. Source inspection of current main and v2026.6.11 shows the interaction secret is deterministically derived from the bot token with a public HMAC key and then used for `_token` verification; I did not run a live Mattermost server in this read-only review.

## Solution Assessment

No. Removing bot-token-derived signing is the right direction, but the current in-memory fallback plus hidden credential surface is not the narrowest upgrade-safe solution for a secret shared by sender and callback verifier.
