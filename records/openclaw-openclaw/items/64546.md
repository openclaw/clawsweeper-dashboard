## Summary

Keep open: current main and v2026.6.11 still use the reported bot-token-derived Mattermost interaction signing root, and this PR is the open candidate fix, but the patch is not merge-ready because its unset-secret fallback is process-local and the new credential is not wired through supported setup/docs/SecretRef surfaces.

## What This Changes

The branch adds optional Mattermost `interactions.secret` config, resolves it into account state, and replaces bot-token-derived HMAC interaction signing with configured or generated per-account secrets plus tests.

## Best Possible Solution

Choose an upgrade-safe Mattermost interaction-secret model, then wire the runtime, setup/docs, SecretRef metadata, restart or split-process coverage, and a clean branch refresh before merge.

## Reproduction Assessment

Yes. Source inspection of current main shows bot-token-derived HMAC signing, and source inspection of the PR shows unset-secret tokens become process-local random values rather than a shared sender/verifier credential.

## Solution Assessment

No. Removing bot-token-derived signing is the right direction, but the current PR leaves the unset-secret path as process-local state and does not yet define the upgrade-safe provisioning model.
