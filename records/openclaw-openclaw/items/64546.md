## Summary

Keep open: this PR targets a real Mattermost interaction-token security bug, but the current patch replaces the forgeable deterministic secret with a process-local fallback and an under-wired credential surface, so it is not merge-safe yet.

## What This Changes

The PR changes Mattermost interaction signing to use configured or generated per-account secrets instead of deriving the signing secret from the bot token.

## Best Possible Solution

Land a refreshed security fix, or a narrow replacement, that removes bot-token-derived Mattermost interaction signing while making the replacement secret durable or explicitly fail-closed through supported setup, SecretRef, docs, tests, and restart or split-process proof.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: current main and `v2026.6.11` derive the interaction signing secret from the bot token with a public HMAC key. I did not run a live Mattermost server in this read-only review.

## Solution Assessment

No. Removing bot-token-derived signing is the right direction, but the current in-memory fallback plus hidden credential surface is not the narrowest upgrade-safe solution for a secret shared by sender and callback verifier.
