## Label Justifications

- `P1`: The PR addresses a high-impact Mattermost callback-token forgery path but can also break live button workflows if the replacement secret is not durable.
- `merge-risk: 🚨 compatibility`: Existing deployments without a configured interaction secret may start rejecting valid callbacks after restart or split-process sends.

## Summary

Keep open: the PR targets a real Mattermost interaction-token security flaw, but the proposed unset-secret fallback is process-local and the new credential is not wired through setup, SecretRef registry/reference docs, or Mattermost docs. GitHub also reports the branch as conflicting, so it is not a safe cleanup close or merge-ready patch.

## What This Changes

The PR changes Mattermost interaction token signing from bot-token-derived HMAC secrets to configured or generated per-account interaction secrets, with schema/types and focused tests.

## Best Possible Solution

Choose an upgrade-safe Mattermost interaction-secret model, then land a refreshed PR or narrow replacement that removes bot-token-derived signing while providing durable setup, docs, SecretRef coverage, and restart or split-process validation.

## Reproduction Assessment

Yes. Source inspection shows current main derives the Mattermost interaction HMAC secret from the bot token with a public key, and the PR's unset-secret delivery regression is source-reproducible because its generated fallback is module-local process memory.

## Solution Assessment

No. Removing bot-token-derived signing is the right direction, but an in-memory generated fallback plus schema-only credential is not the best upgrade-safe solution for a credential shared by sender and callback verifier.
