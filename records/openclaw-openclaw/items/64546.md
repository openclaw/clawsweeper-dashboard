## Summary

Keep open: this PR is the active candidate fix for https://github.com/openclaw/openclaw/issues/64545, but the current patch still has upgrade and security-review blockers around durable Mattermost interaction-secret provisioning, supported SecretRef/setup/docs wiring, and a conflicting head branch.

## What This Changes

The PR adds a Mattermost `interactions.secret` config value and changes interactive-button HMAC signing to use a configured or generated per-account secret instead of bot-token-derived secrets.

## Best Possible Solution

Land a refreshed or replacement fix that removes bot-token-derived signing while making the Mattermost interaction secret durable or explicitly fail-closed, with setup, SecretRef metadata, docs, restart/split-process proof, and old-forgery rejection coverage.

## Reproduction Assessment

Yes at source level: current main and v2026.6.11 derive the Mattermost interaction secret from the bot token with a public HMAC key and use it for `_token` verification. I did not run a live Mattermost exploit in this read-only review.

## Solution Assessment

No as currently implemented. Removing bot-token-derived signing is the right direction, but the in-memory fallback and hidden credential surface are not the narrowest upgrade-safe solution for a secret shared by sender and callback verifier.
