- `P1`: The PR addresses a security-sensitive Mattermost callback-auth bug, but the current patch can break existing button workflows and needs maintainer/security direction before merge.

## Summary

Keep open: this PR addresses a real Mattermost security issue, but it is not merge-ready because the random process-local fallback can break valid button callbacks after restart or split sender/verifier execution, the new signing credential is not wired through setup/docs/SecretRef audit, and GitHub reports the branch as dirty.

## What This Changes

The PR replaces Mattermost bot-token-derived interaction HMAC secrets with configured or randomly generated per-account secrets and updates schema, types, tests, and send/monitor call sites.

## Best Possible Solution

Choose an upgrade-safe Mattermost interaction-secret model, then wire setup, SecretRef registry/audit, public docs, restart or split-process coverage, and a clean branch refresh before merge.

## Reproduction Assessment

Yes. Source inspection of current main and v2026.6.11 shows the Mattermost interaction HMAC secret is derived from the bot token with a public key, and PR source inspection shows unset replacement secrets are random process-local values; I did not run a live Mattermost server in this read-only review.

## Solution Assessment

No. Removing bot-token-derived signing is the right direction, but an in-memory random fallback plus a schema-only credential is not the best upgrade-safe solution for a secret shared by sender and callback verifier.
