## What This Changes

The branch adds explicit named `/new` syntax and `/close`/`/delete` chat commands, wiring them through session lifecycle deletion, Control UI session creation, command registration, docs, and focused tests.

## System Context

Chat commands enter the auto-reply command dispatcher, which either starts/resets and names a session or asks the Gateway to delete the active session. Gateway deletion coordinates active chat runs, session-work admission, transcript/archive behavior, and the terminal reply returned to the channel or Control UI.

## Architecture Diagram

flowchart LR

  B --> C[New-session naming]
  B --> D[Close-session request]
  C --> E[Session metadata store]
  D --> F[Gateway lifecycle and active-run abort]
  F --> G[Transcript archive or deletion]
  G --> H[Terminal chat reply]

## Best Possible Solution

Keep a single lifecycle-owned `/close` command path, block persistence of its terminal success reply once deletion removes the selected session incarnation, report archive versus deletion truthfully, then capture a redacted current-head live transcript that proves the initiator receives its result while competing work is stopped.
