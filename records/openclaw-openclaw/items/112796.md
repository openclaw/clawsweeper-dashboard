## Label Justifications

- `P2`: Doctor can silently change an existing WhatsApp acknowledgement workflow, but the report is scoped to one legacy migration combination rather than an availability or security emergency.
- `impact:message-loss`: The migrated configuration suppresses acknowledgement reactions for direct messages that previously matched the legacy setting.

## Summary

This appears to describe a real WhatsApp migration regression: the legacy default means direct messages plus mentioned groups, while the shared canonical scope cannot express that combination. Keep it open for an explicit product/compatibility decision rather than silently narrowing existing acknowledgement behavior.

## What This Changes

Repair WhatsApp doctor migration so legacy acknowledgement-reaction settings do not silently disable direct-message reactions when they also enable mentioned-group reactions.

## System Context

Doctor rewrites older channel configuration into OpenClaw's current canonical config before the WhatsApp channel starts. The migrated acknowledgement scope then controls whether the WhatsApp auto-reply monitor sends an acknowledgement reaction for a direct message or a group message.

## Architecture Diagram

  E --> G[Group mention reaction]

## Best Possible Solution

Add a canonical acknowledgement-scope representation that preserves direct messages plus mentioned groups, migrate the WhatsApp legacy default to it, and cover doctor plus WhatsApp admission behavior with regression tests and clear upgrade documentation.
