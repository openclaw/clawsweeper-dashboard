## Summary

This issue remains necessary: current Matrix behavior is intentionally immediate, but current configuration and docs expose no receipt-timing policy. The request adds a compatibility-sensitive per-channel/per-account behavior choice, so it should stay open for Matrix-owner product review rather than receive an automatic fix attempt.

## What This Changes

Add Matrix `readReceiptMode` settings so receipts remain immediate by default but can be sent only after a successful visible reply or disabled per account.

## Best Possible Solution

Keep immediate as the unchanged default and, if approved, add one Matrix-plugin-owned resolved receipt policy with explicit delivery-success semantics and focused tests for immediate, on-reply, off, account override, no-reply, ignored, and failed-send paths.
