## Summary

Keep open: the PR still carries a meaningful unique fix for the broad memory-wiki bridge concurrency issue; current main has the shared guarded write retry from the merged narrower work, but not this PR's imported-source stat/read retry plus bridge import/index-refresh coalescing.

## What This Changes

The PR adds bounded retry handling for transient memory-wiki imported source-page `path-mismatch` failures and coalesces concurrent bridge-mode imported-source sync plus index refresh for the same resolved vault/config identity.

## Best Possible Solution

Land one memory-wiki owner-boundary fix that keeps the shared guarded write path from main, adds only bounded transient retry for imported-source stat/read/write races, and coalesces bridge imports by a maintainer-accepted identity that covers all source-discovery inputs.

## Reproduction Assessment

Yes at source level: current main still routes the affected gateway/CLI/tool calls through imported-source sync without coalescing, and the linked issue provides concrete path-mismatch and slow-import observations. I did not reproduce the full reporter-scale WSL2/RSS workload in this read-only review.

## Solution Assessment

Yes, with a maintainer acceptance caveat: `source-sync.ts` is the narrow shared owner boundary for bridge sync plus index refresh, and `vault-page-write.ts` remains the canonical guarded write helper. The safer alternative would be to tighten the coalescing key if maintainers identify any missing source-discovery input before merge.
