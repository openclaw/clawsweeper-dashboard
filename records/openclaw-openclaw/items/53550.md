## Summary

Keep open. Current main has documented the QMD/export/visibility gates and fixed archived QMD path mapping, but source still shows owner-scoped live/orphan session transcript hits can be dropped when no combined session-store row exists; https://github.com/openclaw/openclaw/pull/92261 is the targeted runtime fix candidate, while https://github.com/openclaw/openclaw/issues/99611 and https://github.com/openclaw/openclaw/pull/100140 cover broader product direction.

## What This Changes

The issue asks OpenClaw to make enabled session-memory search return gateway-dispatched session transcript content through memory_search across sessions when visibility permits it.

## Best Possible Solution

Review and land or reject https://github.com/openclaw/openclaw/pull/92261, or an equivalent narrow owner-scoped live-orphan fix that preserves the existing visibility guard; keep the broader remember-across-private-conversations product mode in https://github.com/openclaw/openclaw/issues/99611 and https://github.com/openclaw/openclaw/pull/100140.

## Reproduction Assessment

Yes. A source-level reproduction is high confidence: a same-agent live owner-scoped session hit with no combined session-store row reaches the visibility filter, resolves zero keys on current main, and is dropped; no live Gateway/QMD run was performed in this read-only pass.

## Solution Assessment

No, current main is not the complete solution. The best path is the narrow live-orphan fallback in the visibility layer, with explicit maintainer review because the surrounding defaults and broader cross-conversation memory behavior are privacy/product-sensitive.
