## Summary

Keep open only for a narrow architecture decision. Current main already assigns plugin and channel configuration schemas to cold plugin manifests, so the reported core-specific ownership problem is largely addressed; the issue does not identify a concrete remaining Discord, Telegram, or GitHub-auth schema that still needs extraction.

## What This Changes

Move any remaining plugin-specific configuration validation out of core and compose validation from plugin-owned schema metadata.

## Best Possible Solution

Keep cold validation manifest-first; if a specific core-owned plugin schema is found, move only that schema into the owning plugin's `configSchema` or `channelConfigs` metadata and add focused config-read, config-write, and live-schema regression coverage without executing plugin runtime code.
