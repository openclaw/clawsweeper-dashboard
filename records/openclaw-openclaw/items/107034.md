## Summary

Keep open for a narrow architecture decision, not immediate implementation. Current documentation and manifest contracts already place plugin and channel schemas at plugin boundaries and merge them into live validation, so the proposed wholesale extraction appears largely redundant; the issue does not identify a concrete remaining duplicated schema on current main.

## What This Changes

Audit and move any plugin-specific configuration validation still hardcoded in core into plugin-owned manifest or API contracts, with registry-composed validation.

## Best Possible Solution

Inventory concrete remaining core-owned plugin schemas against the existing configSchema, configContracts, and channelConfigs seams; move only proven owner-specific duplicates, preserve deterministic cold-start validation and schema export, and add fresh-install plus upgrade coverage.
