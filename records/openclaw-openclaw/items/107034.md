## Summary

Keep open only for a narrow maintainer architecture decision. Current documentation already defines plugin manifests as the canonical cold-path validation boundary for plugin and channel configuration, so the issue does not establish a concrete remaining core-owned Discord, Telegram, or GitHub-auth schema; however, its proposed runtime plugin interrogation conflicts with that manifest-first boundary and should not become an implementation task without an identified residual.

## What This Changes

Audit configuration validation and move any remaining plugin-owned schemas from core into declarative plugin manifest boundaries.

## Best Possible Solution

Keep manifest JSON Schema metadata as the canonical cold-path source; if maintainers identify a specific residual core-owned plugin schema, move only that schema to its owner manifest, compose it through the existing registry metadata path, and add focused validation and upgrade tests without loading plugin runtime code.
