## Summary

Keep open only for a narrow maintainer architecture decision. Current main already defines plugin manifests as the cold validation boundary for plugin and channel configuration, while the proposed boot-time runtime interrogation conflicts with that manifest-first design; no concrete residual hardcoded Discord, Telegram, or GitHub-auth schema has been identified.

## What This Changes

Refactor canonical configuration validation so plugin- and channel-specific schemas are owned and composed through plugin boundaries rather than hardcoded in core.

## Best Possible Solution

Keep the manifest-first cold validation path, and if a specific core-owned plugin schema remains, move only that schema into declarative plugin metadata with focused validation and schema-generation tests rather than importing plugin runtimes during boot.
