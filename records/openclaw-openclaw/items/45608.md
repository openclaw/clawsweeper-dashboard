## Summary

Keep open: current main and v2026.6.11 still run the tool-capable agentic memory flush only in the normal reply maintenance path, not before explicit or daily/idle session reset, and the remaining choice is a security/product boundary rather than cleanup closure.

## What This Changes

The issue requests a silent agentic memory flush before `/new`, `/reset`, and daily/idle session reset so curated memory can persist before the old session is retired.

## Best Possible Solution

Define a maintainer-approved reset-memory lifecycle that preserves curated memory before explicit, daily, and idle session destruction while honoring sandbox/tool approvals, read-only and CLI guards, timeouts, auditability, and plugin ownership.
