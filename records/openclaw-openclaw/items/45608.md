## Summary

Keep open: current main still separates reset rollover from the compaction memory-flush turn, so explicit, daily, and idle resets can rotate sessions without the requested agentic pre-reset write.

## What This Changes

Request an agentic memory-flush lifecycle step before `/new`, `/reset`, daily reset, and related reset rollovers so curated memory is saved like pre-compaction flushes.

## Best Possible Solution

Design one maintainer-approved reset-lifecycle memory preservation path covering explicit, daily, and idle rollovers with latency, consent, sandbox/tool access, provider routing, config/defaults, and plugin hook boundaries made explicit.

## Reproduction Assessment

Yes, source-level: current reset rollover and gateway/manual hooks rotate sessions and emit lifecycle hooks, while `runMemoryFlushIfNeeded` is only called from the reply-run memory-flush phase; no live reset was run because this review is read-only.

## Solution Assessment

Unclear as a final design: reusing the existing memory-flush turn is plausible, but blocking reset, background cleanup, raw-summary carry-forward, and plugin lifecycle contracts have different latency and security tradeoffs.
