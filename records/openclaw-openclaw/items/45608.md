## Label Justifications

- `P2`: The issue describes a real session continuity and memory-loss gap with limited blast radius that needs product/security review before implementation.
- `impact:session-state`: The central behavior is whether memory and context survive session id rotation across `/new`, `/reset`, daily, and idle reset.
- `impact:data-loss`: Unsaved learned context can be discarded at reset unless the agent or hooks persist it before the outgoing session is replaced.
- `impact:security`: The proposed fix would run a silent agent turn with tools and write transcript-derived memory to durable files, which affects sensitive-data handling and operator trust boundaries.

## Summary

Keep open: current main has partial reset-memory recovery through session-memory artifacts, startup-context preload, and lifecycle hooks, but it still does not run a silent tool-capable agentic memory flush against the outgoing session before `/new`, `/reset`, daily, or idle rollover destroys the active session context.

## What This Changes

Run a silent agentic memory flush before explicit and automatic session resets so durable memory can be curated before session state is replaced.

## Best Possible Solution

Add a core-owned reset lifecycle memory path only after maintainers choose the default, config, timeout, tool-permission, privacy, and security semantics; it should cover explicit, daily, and idle rollover while leaving startup context and session-memory artifacts as fallback recovery paths.
