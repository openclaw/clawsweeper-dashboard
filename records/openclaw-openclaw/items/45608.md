## Summary

Keep open: current main and v2026.6.11 still separate reset rollover from the silent agentic memory-flush path, and the active reset-hook PR is only a mechanical session-memory hook candidate rather than the requested reset-time agentic flush. The remaining work needs maintainer product and security direction before implementation.

## What This Changes

The issue requests a silent agentic memory flush before explicit and automatic session resets so curated memory is saved like it is before compaction.

## Best Possible Solution

Define one maintainer-approved reset-lifecycle memory preservation policy covering explicit, daily, and idle rollovers, with opt-out/config, timeout, dedupe, sandbox, consent, audit, and plugin-hook boundaries before implementation.

Options:

- **Define a bounded pre-reset flush (recommended):** Approve an explicit reset-memory policy with timeout, dedupe, opt-out/config, audit, sandbox, and security constraints before implementation.

- **Push continuity to memory plugins:** Require memory plugins or MCP-backed memory services to own continuous persistence and extend only missing core events or APIs.
