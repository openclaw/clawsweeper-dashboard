## Summary

Keep open: current main still rotates explicit, daily, and idle sessions without invoking the agentic `runMemoryFlushIfNeeded` path; related fixes improved slugged memory readback and raw hook behavior, but not the requested pre-reset curated flush.

## What This Changes

Request to run a silent agentic memory-flush turn before manual and automatic session resets so durable notes are written before the current session is rotated.

## Best Possible Solution

Design one maintainer-approved reset-lifecycle memory preservation path for explicit, daily, and idle rollovers, with consent, sandbox/tool access, timeout/background behavior, config/defaults, and plugin boundaries defined before implementation.

## Reproduction Assessment

Yes, source-level: current main evaluates daily/idle freshness and mints or commits a new session, while `runMemoryFlushIfNeeded` is only called inside the active reply runner. I did not execute a live reset because this review is read-only.

## Solution Assessment

Unclear as a final design: reusing the compaction flush runner is plausible, but blocking reset, background cleanup, raw-summary carry-forward, and plugin memory services have different latency and security tradeoffs.
