## Label Justifications

- `P2`: The issue affects real session continuity and memory preservation, but the remaining work is a bounded product/security-sensitive improvement rather than an emergency runtime outage.
- `impact:session-state`: The reported gap is about reset and rollover changing session state before the agent can carry curated context forward.
- `impact:data-loss`: Important learned context can be discarded at reset boundaries when it has not reached compaction or been manually written to memory.
- `impact:security`: The proposed automatic flush would process and persist potentially sensitive transcript content during reset lifecycle handling.

## Summary

Keep open: current main and the latest stable release still limit the agentic memory flush to the normal reply/compaction path, while manual, daily, idle, and gateway reset paths rotate sessions and emit lifecycle hooks without running the requested pre-reset agent turn.

## What This Changes

Request to add a silent agentic memory flush before `/new`, `/reset`, daily reset, and related rollover paths destroy or archive the outgoing session.

## Best Possible Solution

Keep #45608 open as the canonical reset-time agentic-memory design and land only a maintainer-approved lifecycle policy covering explicit, daily, idle, and gateway resets with bounded execution, privacy-safe defaults, docs, and tests.
