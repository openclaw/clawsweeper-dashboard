## Summary

Keep open: current main still has reset-time command/session lifecycle hooks and the normal compaction-gated memory-flush turn, but no source path that runs an agentic memory flush before explicit, daily, or idle session rollover. The linked world-model-mcp comment is useful external/plugin context, but it does not replace the missing core reset-boundary policy decision.

## What This Changes

The issue requests running an agentic memory flush before `/new`, `/reset`, and automatic session resets so curated memories survive reset boundaries.

## Best Possible Solution

Design one maintainer-approved reset-lifecycle memory preservation path that covers explicit, daily, and idle rollovers while keeping latency, consent, sandbox, and plugin boundaries explicit.

## Reproduction Assessment

Yes, from source inspection: reset rollover and memory-flush execution are separate current-main paths, so explicit or stale reset can rotate the session without invoking an agentic pre-reset write. I did not run an end-to-end reset because this review is read-only.

## Solution Assessment

Unclear: reusing the existing memory-flush turn is plausible, but blocking reset, background cleanup, copying existing compaction summaries, and plugin lifecycle contracts have different latency and security tradeoffs.
