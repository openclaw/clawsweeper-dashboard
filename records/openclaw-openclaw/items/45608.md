## Summary

Keep open: current main still separates reset rollover from the agentic pre-compaction memory flush, so the requested pre-reset flush remains a real product and security decision rather than completed cleanup.

## What This Changes

The issue requests a silent agentic memory flush before explicit and implicit session resets so durable memory can be curated before the old session is destroyed.

## Best Possible Solution

Define one reset-lifecycle memory contract that covers explicit, daily, and idle rollover with bounded execution, clear user/security policy, and tests for both fresh sessions and upgrade behavior.

Options:

- **Sponsor a bounded core design (recommended):** Add a reset-lifecycle memory flush contract covering `/new`, `/reset`, daily, and idle rollover with explicit timeout, sandbox, consent, and failure semantics.
- **Keep it plugin-owned:** Leave core rollover behavior unchanged and instead extend/document plugin hooks so memory plugins can implement pre-reset persistence without a core agent turn.
- **Limit to mechanical preservation:** Copy or expose existing compaction summaries and raw transcript data across reset while deferring agentic turns to a separate memory-system design.

## Reproduction Assessment

Yes. Source inspection shows reset rollover mints a new session and clears memory-flush state without calling `runMemoryFlushIfNeeded`, while the existing bundled hook only does command-scoped mechanical background capture.

## Solution Assessment

Unclear. Reusing the compaction flush is plausible, but the best fix needs maintainer direction on blocking versus background execution, default enablement, security consent, and whether this belongs in core or plugin lifecycle APIs.
