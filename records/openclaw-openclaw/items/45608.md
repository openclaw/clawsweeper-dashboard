## Summary

Keep open: current main still runs agentic memory flushing only from the reply/compaction path, while reset rollover archives/restarts sessions and emits lifecycle hooks without a pre-reset agent turn. The active reset-hook PR is useful partial work for mechanical persistence, but it does not settle the requested silent tool-capable flush policy.

## What This Changes

Request to run a silent agentic memory flush before `/new`, `/reset`, daily reset, and related reset rollovers destroy current session context.

## Best Possible Solution

Define one maintainer-approved reset-memory policy covering explicit, daily, and idle rollover with timeout, dedupe, opt-out/config, sandbox, consent, audit, and plugin-boundary rules before implementation.
