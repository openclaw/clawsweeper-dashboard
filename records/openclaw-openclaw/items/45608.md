## Summary

Keep open: current main still has reset rollover, reset hooks, and the pre-compaction agentic memory flush as separate paths, so the requested silent pre-reset agent turn remains a product and security decision rather than completed cleanup.

## What This Changes

The issue requests a silent tool-capable memory flush before manual and automatic session resets so reset paths preserve curated memory like compaction does.

## Best Possible Solution

Define one maintainer-approved reset-memory lifecycle policy covering explicit, daily, and idle rollovers, with timeout, dedupe, audit, consent, plugin, and config boundaries before implementation.

Rationale: The source-level gap is clear, but the permanent behavior affects latency, silent agent execution, sensitive memory persistence, and plugin/config contracts, so automation should not choose the policy alone.

Options:

- **Approve bounded pre-reset flush (recommended):** Define a default policy with timeout, dedupe, opt-out/config, audit, sandbox, and security constraints before a focused implementation.
- **Keep reset persistence mechanical:** Treat session-memory or reset-hook improvements such as https://github.com/openclaw/openclaw/pull/61675 as the supported reset boundary and narrow this issue away from silent agent execution.
- **Delegate to memory plugins:** Require external memory plugins or MCP-backed services to own continuous persistence and extend core lifecycle APIs only where current hooks are insufficient.

Yes. Source inspection shows reset rollover and the agentic memory-flush execution are separate current-main paths, so explicit or stale reset can rotate the session without invoking a pre-reset agent write.
