## Summary

Keep open: current main still has compaction-gated agentic memory flush and reset-time hook plumbing, but no source path that runs a silent agentic memory flush before explicit, daily, or idle rollover.

## What This Changes

The issue asks OpenClaw to run an agentic memory flush before manual, daily, and idle session resets so durable memory gets the same curated save path as compaction.

## Best Possible Solution

Define one reset-boundary memory policy for explicit, daily, and idle rollover, reusing the existing memory-flush runner or an equivalent plugin API only after maintainers decide the security/default behavior.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: current main evaluates daily/idle freshness and rotates sessions, while `runMemoryFlushIfNeeded` is only called from the normal reply runner. I did not run a live reset scenario because this read-only review was enough to prove the missing wiring.

## Solution Assessment

Unclear as an implementation direction: reusing the compaction memory flush is plausible, but making it run before every reset requires a maintainer decision about blocking versus background execution, security defaults, and plugin ownership.
