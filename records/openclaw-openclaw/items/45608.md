## Label Justifications

- `impact:data-loss`: The report is about losing unsaved conversational context when a session resets before curated memory is written.

## Summary

Keep open: current main has pre-compaction memory flush and reset/session lifecycle hooks, but no reset-boundary path that runs the silent agentic memory flush before explicit `/new`/`/reset` or daily/idle rollover. The remaining work is a maintainer product/security decision about silent reset-time agent execution, memory persistence boundaries, and reset latency/cost.

## What This Changes

Requests an agentic memory flush before manual and automatic session resets so curated memory is saved before the current session is destroyed.

## Best Possible Solution

Define one reset-boundary memory policy that covers explicit, daily, and idle rollover consistently, bounds latency/failures, respects read-only/CLI-owned/privacy cases, and either reuses the existing memory-flush plan or exposes a typed plugin lifecycle contract with tests.

## Reproduction Assessment

Yes from source inspection: reset rollover creates a new session and existing tests assert `/new`/`/reset` do not invoke the model, while `runMemoryFlushIfNeeded` is only called from the normal reply agent runner.

## Solution Assessment

Unclear: directly calling the existing compaction flush from reset is plausible, but reset-time silent agent execution changes latency, cost, privacy, and plugin/config boundaries, so maintainers should choose the reset-boundary contract first.
