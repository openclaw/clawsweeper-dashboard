## Summary

Keep open: current main still separates reset rollover from the compaction-gated agentic memory flush. The reset paths emit lifecycle/plugin hooks and preserve some reset metadata, but they do not run the silent tool-capable memory-flush turn before explicit, daily, or idle session rollover.

## What This Changes

The issue requests a silent agentic memory flush before explicit, daily, and idle session resets so durable memory can be curated before the old session is rotated.

## Best Possible Solution

Design one maintainer-approved reset-lifecycle memory preservation path that covers explicit, daily, and idle rollovers while making the core/plugin boundary, latency, consent, sandbox, and persistence defaults explicit.

## Reproduction Assessment

Yes, from source inspection: reset rollover and memory-flush execution are separate current-main paths, so explicit or stale reset can rotate the session without invoking an agentic pre-reset write. I did not run an end-to-end reset because this review is read-only.

## Solution Assessment

Unclear: reusing the existing memory-flush turn is plausible, but blocking reset, background cleanup, copying existing compaction summaries, and plugin lifecycle contracts have different latency and security tradeoffs.
