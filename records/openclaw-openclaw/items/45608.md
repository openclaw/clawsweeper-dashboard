## Summary

Keep open: current main still does not run an agentic memory flush before explicit, daily, or idle session rollover. Existing code archives/rotates the session, emits lifecycle hooks, and can preload already-written daily memory after reset, but the requested reset-boundary curation policy remains unresolved.

## What This Changes

Request to run a silent agentic memory flush before `/new`, `/reset`, daily reset, and idle rollover so curated memory survives session destruction.

## Best Possible Solution

Choose one reset-boundary memory policy, then implement it once across manual, daily, and idle rollover with clear timeboxing, no unsafe tool execution, documented config/defaults, and regression coverage for both fresh and upgrade paths.

Options:

- **Design a core reset-memory policy (recommended):** Define a timeboxed reset-boundary preservation contract for manual, daily, and idle rollover, then implement it with explicit security and config behavior.
- **Narrow to lifecycle hooks:** Keep agentic flushing outside core and make `session_end`/`before_reset` plus bundled or external plugins own memory persistence.
- **Defer to external memory plugins:** Leave core reset behavior unchanged and document that external memory systems such as world-model integrations own cross-reset continuity.

## Reproduction Assessment

Yes, at source level. Current main shows daily/idle freshness triggers session rollover and archive/lifecycle hooks, while `runMemoryFlushIfNeeded` is only reached later in the normal agent-run path and is gated by token/compaction state.

## Solution Assessment

Unclear. A pre-reset agentic flush is plausible, but the best fix may be a generic lifecycle hook or plugin-owned memory contract unless maintainers explicitly accept silent reset-time model execution and its security/default behavior.
