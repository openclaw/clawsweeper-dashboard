## Summary

Keep open: current main still separates reset rollover from the agentic memory-flush path. Mechanical hooks and startup context cover some reset-adjacent memory capture, but there is still no approved policy for a silent, tool-capable pre-reset agent turn before explicit, daily, or idle resets.

## What This Changes

Run an agentic memory flush before manual, daily, and idle session resets so curated memory survives session teardown.

## Best Possible Solution

Define one approved reset-memory lifecycle policy covering explicit, daily, and idle rollovers, with timeout, dedupe, audit, consent, plugin, provider/auth, and config boundaries before implementation.
