## Summary

Keep open: current main and the latest release still do not run the requested silent agentic memory flush before explicit or implicit session reset. The reset path archives/rotates and then fires session lifecycle hooks, while the compaction-style memory flush only runs in the normal reply path and the bundled session-memory hook remains mechanical command-triggered preservation.

## What This Changes

Request to run the compaction-style silent memory flush before `/new`, `/reset`, and daily or idle reset destroy session context.

## Best Possible Solution

A maintainer-approved reset-memory design should preserve curated memory before explicit, daily, and idle session destruction while honoring sandbox/tool approvals, read-only/CLI guards, timeouts, and plugin ownership.

Question: Should OpenClaw run a silent tool-capable memory-flush agent turn before explicit and implicit session resets, and what owner boundary/default should control it?

Rationale: The source-level gap is clear, but the fix changes reset latency and allows hidden agent/tool execution at a session lifecycle boundary, so automation cannot choose the security and product default.

Likely owner: @steipete

Owner reason: Peter Steinberger has the strongest sampled history on memory flush ownership and session lifecycle hardening, making him the best available owner for the product/security direction.

Owner confidence: medium

Options:

- **Design a bounded pre-reset memory contract (recommended):** Add a core-owned or memory-plugin-owned pre-reset capability that timeboxes the silent flush, preserves sandbox/approval/read-only guards, and covers explicit, daily, and idle resets.
- **Keep mechanical preservation only:** Rely on session_end/session-memory/transcript indexing for raw backup and leave curated agentic memory to active-session compaction and ordinary turns.
- **Defer to broader reset UX work:** Handle the user harm through warning, opt-out, or session-continuity work before adding a hidden reset-time agent turn.

## Reproduction Assessment

Yes, source-level: current main evaluates reset freshness and rotates the session without calling `runMemoryFlushIfNeeded`; that helper is only called in the normal reply path. I did not run a live reset because this is a read-only review.

## Solution Assessment

Unclear: directly wiring the existing compaction flush into reset is plausible, but the best fix likely needs a maintainer-approved pre-reset memory contract with security, timeout, default, and plugin-boundary decisions.
