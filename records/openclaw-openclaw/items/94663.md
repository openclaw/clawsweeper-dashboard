## Summary

Keep open: this is a useful MCP relay foundation, but it is not merge-ready because the new aggregate media cap runs after base64 canonicalization, so an over-budget document/resource blob can still allocate a large cleaned copy before being skipped; the host-owned local-media trust boundary also needs maintainer sign-off.

## What This Changes

The PR stages MCP image, audio, and blob resource tool-result content as host-owned outbound media attachments and lets the existing tool-result media filter relay those staged files.

## Best Possible Solution

Move the aggregate relay budget reservation ahead of base64 canonicalization while preserving rollback for invalid data, then land only after maintainers accept the host-owned MCP media registry and proof scope.
