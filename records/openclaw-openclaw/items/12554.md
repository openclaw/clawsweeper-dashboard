## Summary

Keep open: current main and the latest release still lack a session-scoped Gateway/RPC/CLI surface to list and terminate all exec child processes for a stored session; existing abort, HTTP kill, and process-tool paths cover narrower behavior only.

## What This Changes

The issue asks for session-level commands/RPCs to list and terminate every still-running exec process spawned by a session.

## Best Possible Solution

Define an additive, authorization-checked Gateway and CLI session exec-control contract that resolves canonical session scope, lists supervisor-owned active exec runs, cancels matching scopes with per-run outcomes and fallback behavior, and documents isolation without changing sessions.abort or sessions.delete defaults.

Options:

- **Extend existing maintenance methods:** Add explicit opt-in kill flags to existing session abort/delete methods while preserving current defaults and documenting upgrade behavior.
- **Defer public process control:** Keep the existing agent-scoped process tool only and handle orphan/restart cleanup through narrower lifecycle issues until a broader design is ready.

Yes, source-level: current main exposes sessions.abort/delete and internal process-control primitives, but no public session-wide exec process list/kill operation. I did not run a live orphan-process scenario in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public API shape and authorization model. The existing supervisor and process-tool primitives are useful building blocks, but exposing them session-wide is a product/security decision rather than a strict bug patch.
