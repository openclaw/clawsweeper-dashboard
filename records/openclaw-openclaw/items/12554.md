## Summary

Keep open: current main still lacks a public session-scoped exec list/kill operator, while the remaining Gateway/RPC/CLI contract and authorization semantics are security-sensitive maintainer decisions.

## What This Changes

Request a session kill/list surface that can terminate and inspect all active child exec processes spawned by a session.

## Best Possible Solution

Define an additive, authorization-checked Gateway and CLI session exec-control contract that resolves a canonical session scope, lists supervisor-owned active exec runs, cancels matching runs with per-run outcomes, and documents isolation and partial-failure behavior without silently changing sessions.abort or sessions.delete defaults.

## Reproduction Assessment

Yes, source-level: current main exposes session abort/delete plus internal process-control primitives, but no public session-wide exec process list/kill operation. I did not run a live orphan-process reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public API shape and authorization model. The internal supervisor and process tool primitives are useful building blocks, but the requested operator contract is a product/security decision.
