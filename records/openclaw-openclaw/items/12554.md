## Summary

Keep open: current main still lacks a public session-scoped Gateway/RPC/CLI surface to list and terminate exec child processes for a stored session. Existing active-run abort, the HTTP session kill route, and the agent-scoped process tool cover adjacent control paths but not this operator contract.

## What This Changes

The issue requests a session-level operator command or RPC that lists and terminates all live exec processes spawned by a session, including child process trees.

## Best Possible Solution

Define an additive, authorization-checked Gateway and CLI session exec-control contract that resolves canonical session scope, lists supervisor-owned active exec runs, cancels matching scopes with per-run outcomes and fallback behavior, and documents isolation without silently changing sessions.abort or sessions.delete defaults.

Options:

- **Add guarded session exec control (recommended):** Create additive Gateway and CLI methods for session exec list and kill with explicit operator scope, canonical session resolution, per-run outcomes, and tests for child, PTY, sandbox, and fallback behavior.
- **Extend existing session maintenance:** Add explicit opt-in kill-exec flags to sessions.abort or sessions.delete while preserving current defaults and documenting upgrade behavior.
- **Defer public operator surface:** Keep only the existing agent-scoped process tool for now and handle restart/orphan cleanup in narrower lifecycle issues until a broader process-control design is ready.

## Solution Assessment

Unclear until maintainers choose the public API shape and authorization model. The existing supervisor and process-tool primitives are useful building blocks, but exposing them session-wide is a product/security decision rather than a strict bug patch.
