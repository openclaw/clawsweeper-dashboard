## Summary

Keep open: current main can abort tracked chat and embedded agent work, but it still lacks an explicit session-scoped contract for enumerating managed exec runs and terminating their process trees. The related reports cover broader session controls or distinct shutdown, orphan-restart, and descendant-session failures, so none supersedes this request.

## What This Changes

Ensure session termination kills all session-owned exec process trees and provides a status view of those processes.

## Best Possible Solution

Add an additive, least-privilege Gateway contract that resolves canonical session ownership, returns bounded managed-run status, cancels only verified session-owned scopes, reports per-run outcomes, and explicitly documents restart and orphan limitations.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: What authorization and ownership rules should govern listing and terminating every managed exec run associated with a stored session?

Rationale: The feature crosses session, process, node-host, and operator-scope boundaries; source evidence cannot determine whether arbitrary-session control should be admin-only, requester-owned, or deferred pending durable ownership.

Likely owner: vincentkoc

Owner reason: The strongest available history connects Vincent to session control, kill-route authorization, and the supervisor-facing surface.

Owner confidence: high

Options:

- **Add admin-scoped controls (recommended):** Introduce separate list and kill methods that require admin scope and operate only on supervisor records proven to match the canonical session owner.
- **Extend sessions.abort:** Add an explicit terminate-children option to the write-scoped abort method with strict requester ownership checks and documented limitations.
- **Wait for durable ownership:** Defer the public API until restart reconciliation can reliably identify and control previously tracked process trees.

## Reproduction Assessment

Yes at source level: current main exposes active-run abort behavior but no explicit session-owned exec inventory or supervisor-scope termination contract. A live PID-level reproduction is still needed to measure which foreground and background process trees currently survive each abort path.

## Solution Assessment

No, process groups alone are not the best complete solution because PTY, child-process, sandbox, and remote node-host backends differ. The maintainable solution is an ownership-aware supervisor API with explicit authorization and structured per-run outcomes.
