## Summary

Keep open: current main and the latest release still lack a public session-scoped exec list/kill operator, while the remaining Gateway/RPC/CLI shape and authorization semantics are security-sensitive.

## What This Changes

The issue requests a session kill/list operator that can enumerate and terminate all running exec child processes associated with a session.

## Best Possible Solution

Define an additive, authorization-checked Gateway/CLI session exec-control contract that resolves a canonical session scope, lists supervisor-owned active exec runs, cancels matching runs with per-run outcomes, and documents isolation and partial-failure behavior without silently changing sessions.abort or sessions.delete defaults.

## Reproduction Assessment

Yes, source-level: current main exposes session abort/delete plus internal process-control primitives, but no public session-wide exec process list/kill operation. I did not run a live orphan-process reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public API shape and authorization model. The internal supervisor and process tool primitives are useful building blocks, but the requested operator contract is a product/security decision.
