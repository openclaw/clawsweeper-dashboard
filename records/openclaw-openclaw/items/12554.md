## Summary

Keep open: current main and v2026.6.11 still lack a public session-scoped exec list/kill operator, while the lower-level process tool and supervisor primitives remain internal/session-tool scoped and the remaining API, authorization, and process-isolation choices are security-sensitive.

## What This Changes

The issue requests a session-scoped command or RPC to list and terminate exec child processes spawned by a session.

## Best Possible Solution

Define an additive, authorization-checked Gateway/CLI exec-control contract that resolves the canonical session scope, lists matching supervised exec runs, cancels them with per-run status, and documents isolation and partial-failure semantics without silently changing `sessions.abort` or `sessions.delete` defaults.

## Reproduction Assessment

Yes, at source level: current main exposes session abort/delete plus internal process-control primitives, but no public session-wide exec process list/kill operation. I did not run a live orphan-process reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public API shape and authorization model. The internal supervisor and process-tool primitives are useful building blocks, but exposing them as a session operator is a product and security decision.
