## Summary

Keep open: current main still has scoped process-control primitives, but not the requested session-scoped Gateway/RPC/CLI surface for operators to list and terminate exec children for an arbitrary stored session.

## What This Changes

The issue requests a session-level operator that can list and terminate exec processes spawned by a session.

## Best Possible Solution

Define an additive, authorization-checked Gateway and CLI session exec-control contract that resolves canonical session scope, lists supervisor-owned active exec runs, cancels matching scopes with per-run outcomes, and documents isolation and partial-failure behavior without changing sessions.abort or sessions.delete defaults.

## Reproduction Assessment

Yes. Source inspection on current main shows internal scoped process list/kill primitives, but no public Gateway/RPC/CLI `sessions.kill`, `sessions.exec-list`, or `sessions.abort --kill-exec` surface.

## Solution Assessment

Unclear until maintainers choose the public API shape and authorization model. The internal supervisor and process-tool primitives are useful building blocks, but the requested operator contract is a product/security decision.
