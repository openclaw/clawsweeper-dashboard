## Summary

Keep open: current main and the latest release still lack the requested session-scoped Gateway/RPC/CLI operator surface to list and terminate child exec processes for an arbitrary session; only lower-level process-tool and supervisor primitives exist, and the remaining work needs product/security design.

## What This Changes

Request a session-scoped operator command/RPC/CLI surface to list and terminate active child exec processes started by a session instead of relying on cooperative stop messages.

## Best Possible Solution

Define an additive, authorization-checked Gateway protocol and CLI session exec-control contract that resolves the canonical session scope, lists supervisor-owned active exec runs, cancels matching scopes with process-tree fallback where appropriate, returns per-run outcomes, and documents isolation rules without silently changing sessions.abort or sessions.delete defaults.

## Reproduction Assessment

Yes, source-level: current main exposes session abort/delete and scoped process-tool primitives, but no public session-wide exec process list/kill operation. I did not run a live orphan-process reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public API shape, authorization model, and kill semantics. The existing supervisor and process-tool primitives are useful building blocks, but exposing them as an operator contract is the sensitive part.
