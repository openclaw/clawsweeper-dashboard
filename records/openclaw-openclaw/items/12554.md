## Summary

Keep open: current main and the latest release still have lower-level process-control primitives, but no session-scoped Gateway/RPC/CLI operator to list and terminate all exec children for an arbitrary session. The related open issues overlap, but none supersedes this narrower security-sensitive operator contract.

## What This Changes

The issue requests a session-scoped command or abort enhancement that can list and terminate child exec processes spawned by a session.

## Best Possible Solution

Design an additive, authorization-checked Gateway/CLI session exec-control contract that resolves the canonical session scope, lists supervisor-owned active exec runs, cancels matching scopes with per-run outcomes, and documents isolation and partial-failure behavior without changing default sessions.abort or sessions.delete semantics.

## Reproduction Assessment

Yes, source-level: current main exposes session abort/delete and internal process-control primitives, but no public session-wide exec process list/kill operation. I did not run a live orphan-process reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public API shape and authorization model. The internal supervisor and process-tool primitives are useful building blocks, but the requested operator contract is a product/security decision.
