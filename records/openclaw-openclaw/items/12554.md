## Summary

Keep open: current main and v2026.6.11 still lack the requested session-scoped Gateway/RPC/CLI surface to list and terminate child exec processes, while the remaining work is a security-sensitive product/API decision rather than stale cleanup.

## What This Changes

Request a session-scoped operator command/API to list and terminate active exec processes spawned by a session.

## Best Possible Solution

Define an additive, authorization-checked Gateway/SDK/CLI session exec-control contract that resolves the canonical session scope, lists supervisor-owned active exec runs, cancels matching scopes with per-run outcomes, and documents isolation and partial-failure behavior without silently changing sessions.abort or sessions.delete defaults.

## Reproduction Assessment

Yes, at source level: current main exposes sessions.abort/delete plus agent-local process list/kill primitives, but no public session-wide exec process list/kill operation. I did not run a live orphan-process reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public API shape and authorization model. The existing process supervisor, process tool, and kill-tree helpers are useful building blocks, but the requested operator contract is a product/security decision.
