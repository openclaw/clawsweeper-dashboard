## Summary

Keep open: current main and the latest release still lack a session-scoped Gateway/RPC/CLI surface to list and terminate exec child processes for a stored session. The lower-level process and subagent controls are useful building blocks, but exposing them as session-wide process control needs maintainer product and security direction.

## What This Changes

The issue requests a session-level command or RPC that lists and terminates active child exec processes spawned by a session.

## Best Possible Solution

Define an additive, authorization-checked Gateway and CLI session exec-control contract that resolves canonical session scope, lists supervisor-owned active exec runs, cancels matching scopes with per-run outcomes and documented fallback behavior, and leaves sessions.abort/delete defaults unchanged unless maintainers intentionally change them.
