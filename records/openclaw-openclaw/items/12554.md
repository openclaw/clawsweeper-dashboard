## Summary

Keep open: current main has scoped process-supervisor and process-tool primitives, but it still lacks a public session-wide Gateway/RPC/CLI surface to list or kill child exec processes; the remaining work needs product and security design.

## What This Changes

Requests a session-scoped operator command/RPC to list and terminate child exec processes spawned by a session.

## Best Possible Solution

Define an additive, authorization-checked Gateway and CLI session exec-control contract that resolves the canonical session scope, lists supervisor-owned active exec runs, cancels matching scopes with per-run outcomes, and documents isolation and partial-failure behavior without changing sessions.abort or sessions.delete defaults.

## Reproduction Assessment

Yes, source-level: current main exposes session abort/delete plus internal process-control primitives, but no public session-wide exec process list/kill operation. I did not run a live orphan-process reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public API shape and authorization model. The internal supervisor and process tool primitives are useful building blocks, but the requested operator contract is a product/security decision.
