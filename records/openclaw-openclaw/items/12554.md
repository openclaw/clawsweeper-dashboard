## Summary

Keep open: current main still lacks the requested session-scoped Gateway/RPC/CLI surface to list and terminate child exec processes spawned by a stored session. Existing pieces cover active chat aborts, subagent-run HTTP kill, and agent-scoped background process control, but not the operator contract requested here.

## What This Changes

Requests a `sessions_kill` or equivalent session abort enhancement that can list and terminate all running exec child processes associated with a session.

## Best Possible Solution

Define an additive, authorization-checked Gateway and CLI session exec-control contract that resolves canonical session scope, lists supervisor-owned active exec runs, cancels matching scopes with per-run outcomes and fallback behavior, and documents isolation without changing `sessions.abort` or `sessions.delete` defaults.

## Solution Assessment

Unclear until maintainers choose the public API shape and authorization model. The existing supervisor and process-tool primitives are useful building blocks, but exposing them session-wide is a product/security decision rather than a strict bug patch.
