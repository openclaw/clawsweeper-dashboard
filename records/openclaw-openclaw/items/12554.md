## Summary

Keep open: current main and v2026.6.11 still lack a public session-scoped exec list/kill operator, while the remaining contract crosses Gateway API, CLI, authorization, and process-isolation boundaries.

## What This Changes

The issue requests a `sessions_kill`-style command or abort enhancement that can list and terminate all active exec child processes associated with a session.

## Best Possible Solution

Define an additive Gateway protocol and CLI surface that resolves the canonical session scope, lists active managed exec runs for that scope, terminates them through supervisor cancellation with a bounded process-tree fallback, and documents authorization plus partial-failure semantics.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: current main exposes `sessions.abort`/`sessions.delete` and in-agent `process list`/`kill`, but no Gateway/RPC/CLI session-scoped exec list/kill operator. No live OS child-process scenario was run in this read-only review.

## Solution Assessment

Unclear as an implementation patch; the requested direction is valid, but the best fix requires a maintainer-approved operator contract, authorization model, and kill semantics before code should be queued.
