- `maturity:stable`: The affected Gateway runtime session API surface maps to `gateway-runtime`, which is scored Stable/M4 in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main and v2026.6.11 still lack the requested session-scoped Gateway/RPC/CLI operator surface to list and terminate child exec processes for a stored session. The lower-level process supervisor and agent-scoped `process` tool are useful building blocks, but exposing them as a session-wide emergency stop is a product and security-boundary decision.

## What This Changes

Request a `sessions_kill` or equivalent session abort enhancement that can list and terminate all running exec child processes spawned by a session.

## Best Possible Solution

Define an additive, authorization-checked Gateway and CLI session exec-control contract that resolves canonical session scope, lists supervisor-owned active exec runs, cancels matching scopes with per-run outcomes and fallback behavior, and documents isolation without silently changing `sessions.abort` or `sessions.delete` defaults.

- **Defer Public Operator Surface:** Keep the existing agent-scoped process tool only and track orphan/restart cleanup in narrower lifecycle issues until a broader process-control design is ready.
