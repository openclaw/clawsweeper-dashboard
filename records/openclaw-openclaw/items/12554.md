## Summary

Keep open: current main still lacks a session-scoped Gateway/RPC/CLI operator to list and terminate exec child processes, and the remaining work is an authorization-sensitive product contract rather than conservative cleanup.

## What This Changes

Request a `sessions_kill` or related session control surface that lists and terminates all running exec processes spawned by a session.

## Best Possible Solution

Define an additive authorization-checked Gateway/CLI session exec-control contract that resolves canonical session scope, lists supervisor-owned active exec runs, cancels matching scopes with per-run outcomes, and documents isolation and partial-failure behavior without changing `sessions.abort` or `sessions.delete` defaults.

## Reproduction Assessment

Yes, source-level: current main exposes session abort/delete plus internal process-control primitives, but no public session-wide exec process list/kill operation. I did not run a live orphan-process reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public API shape and authorization model. The internal supervisor and process-tool primitives are useful building blocks, but wiring them into a session operator is a product/security decision rather than a narrow repair.
