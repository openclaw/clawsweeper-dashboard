## Summary

Keep open: current main still lacks the requested session-scoped Gateway/RPC/CLI operator to list and terminate child exec processes for a stored session, and the latest release tag checked still exposes only narrower abort/delete/process-control paths.

## What This Changes

The issue requests a `sessions_kill` or equivalent session command that can list and terminate all child exec processes spawned by a session.

## Best Possible Solution

Define an additive, authorization-checked Gateway and CLI session exec-control contract that resolves canonical session scope, lists supervisor-owned active exec runs, cancels matching scopes with per-run outcomes and fallback behavior, and documents isolation without changing `sessions.abort` or `sessions.delete` defaults silently.

## Reproduction Assessment

Yes, source-level: current main exposes abort/delete and internal process-control primitives, but no public session-wide exec process list/kill operation. I did not run a live orphan-process scenario in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public API shape and authorization model. The existing supervisor and process-tool primitives are useful building blocks, but exposing them session-wide is a product/security decision rather than a strict bug patch.
