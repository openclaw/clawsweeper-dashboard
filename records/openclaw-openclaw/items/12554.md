## Summary

Keep open: current main and the latest local release still lack a public session-scoped exec list/kill operator, and wiring one safely requires maintainer decisions around Gateway/CLI API shape and authorization.

## What This Changes

Request a session-scoped exec list/kill command or abort option that terminates child exec processes spawned by an OpenClaw session.

## Best Possible Solution

Add an explicit, admin-scoped session exec list/kill contract that resolves a canonical session scope, returns per-run status, and documents authorization/isolation without silently changing sessions.abort or sessions.delete defaults.

Yes, at source level: current main exposes sessions.abort/delete plus internal scoped process-control primitives, but no public session-wide exec process list/kill operation; I did not run a live orphan-process scenario in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public API shape and authorization model; the supervisor and process tool primitives are useful building blocks, but the requested operator contract is a product/security decision.
