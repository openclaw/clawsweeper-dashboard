## Summary

Keep open: current main and v2026.6.11 still lack the requested public session-scoped Gateway/RPC/CLI surface to list and terminate child exec processes for a stored session. Existing subagent kill and agent-scoped process tools cover adjacent cases, but the session-wide operator contract remains a product and security-boundary decision.

## What This Changes

The issue requests a session-level command/API that can list and terminate all running exec processes associated with a session.

## Best Possible Solution

Define an additive, authorization-checked Gateway and CLI session exec-control contract that resolves canonical session scope, lists supervisor-owned active exec runs, cancels matching scopes with per-run outcomes and fallback behavior, and documents isolation without silently changing sessions.abort or sessions.delete defaults.
