## Summary

Keep open: current main and the latest release still have the reported processing/no-activeWorkKind stale-session fallthrough, but the healthy-run false-abort chain remains source-plausible rather than live-proven and changes would alter intentional stuck-session recovery behavior.

## What This Changes

The issue asks OpenClaw to stop classifying healthy processing runs as stale during transient event-loop stalls when diagnostic activity bookkeeping has no activeWorkKind.

## Best Possible Solution

Preserve genuine stale processing recovery, but make the classifier/recovery path evidence-backed so a healthy processing run with transient missing activity is observed or kept rather than aborted during event-loop stalls.
