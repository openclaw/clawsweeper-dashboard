## Summary

Keep open: current main still contains the processing/no-activeWorkKind stale-session fallthrough, but the healthy-run abort path remains source-plausible rather than live-proven, and changing it would alter intentional recovery behavior already covered by tests.

## What This Changes

The issue asks OpenClaw to avoid treating processing sessions with temporarily missing active-work bookkeeping as stale and abortable during event-loop stalls.

## Best Possible Solution

Preserve recovery for truly ownerless stale processing sessions while adding measured behavior that treats transient processing/no-activeWorkKind gaps as observe-only or long-running, backed by a deterministic or live stall proof.
