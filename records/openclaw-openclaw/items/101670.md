## Summary

Keep open: current main still has the processing/no-activeWorkKind stale-session classification path, but the reported healthy-run abort during a short event-loop stall remains unconfirmed and the current tests intentionally depend on stale-processing recovery.

## What This Changes

The issue asks OpenClaw to avoid classifying healthy processing runs as stale and abortable when activity bookkeeping is temporarily missing during event-loop stalls.

## Best Possible Solution

Preserve recovery for genuinely ownerless stale processing sessions, but require measured or deterministic proof before changing the classifier so healthy processing runs are observed or treated as long-running when activity bookkeeping is temporarily unavailable.
