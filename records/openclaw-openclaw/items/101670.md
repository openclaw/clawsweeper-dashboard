## Summary

Keep open: current main still has the processing/no-activeWorkKind stale-session fallthrough and recovery scheduling, but the healthy-run event-loop-stall abort path remains source-plausible rather than live-proven; existing tests intentionally cover part of the current recovery behavior.

## What This Changes

The issue asks OpenClaw to stop stuck-session liveness recovery from classifying healthy processing runs as stale during event-loop stalls and aborting them.

## Best Possible Solution

Preserve recovery for genuinely stale ownerless sessions while adding a measured classifier/recovery guard, backed by a deterministic stall test or live diagnostic log proof showing healthy processing work is kept rather than aborted.
