## Summary

The patch is a focused mitigation with credible real CLI proof, but it deliberately changes doctor behavior for every existing valid session store above 16 MiB. Keep this PR open for an explicit maintainer compatibility decision on whether skipping snapshot scan and repair at that ceiling is an acceptable supported outcome.

## What This Changes

The PR adds a 16 MiB pre-read size cap for doctor session-snapshot stores, reports oversized stores as structured health warnings, and adds a regression test that verifies the scan path does not call `readFileSync` for a 17 MiB store.

## Best Possible Solution

Adopt a bounded doctor read only after confirming that a 16 MiB store is outside supported repair scope, or replace the hard skip with a bounded recovery design that preserves the intended repair path for legitimate larger stores.
