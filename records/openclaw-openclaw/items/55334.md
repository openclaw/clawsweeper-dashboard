## Summary

Keep open: current main has important mitigations for the original `skillsSnapshot.prompt` bloat and session maintenance, but the broader Gateway OOM/session-store pressure is still unresolved because `systemPromptReport` remains persisted per session row, runtime object/snapshot cache retention is still tracked by an open PR, and transcript/artifact cleanup remains split across open focused items.

## What This Changes

The issue requests bounded Gateway session-store growth by pruning ephemeral sessions, cleaning orphan transcripts/artifacts, and eliminating duplicated `skillsSnapshot`/`systemPromptReport` payloads from `sessions.json`.

## Best Possible Solution

Keep this broad tracker open until focused fixes for prompt-report compaction, cache caps, transcript/artifact cleanup, and retention policy land or are explicitly rejected, then close only with release/current-main proof that large session stores and Gateway RSS stay bounded.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level and from repeated field reports: current main still persists bulky prompt-report metadata and whole-store cache behavior remains split across open work, but I did not run a live long-running OOM soak.

## Solution Assessment

Is this the best way to solve the issue? No, not as one broad automated patch; the maintainable path is focused, maintainer-reviewed fixes for durable prompt-report policy, cache caps, transcript/artifact cleanup, and retention semantics with representative soak proof.
