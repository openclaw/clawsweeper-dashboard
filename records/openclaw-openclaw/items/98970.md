## Summary

Keep open: current main still sends the implicit English audio prompt alongside explicit non-English audio language hints, and the three linked closing PRs remain open rather than merged.

## What This Changes

The issue asks OpenClaw to stop sending the default English audio prompt when audio transcription has an explicit non-English language hint and no custom prompt.

## Best Possible Solution

Land one narrow shared media-understanding fix that suppresses only the implicit English audio prompt for explicit non-English audio language hints while preserving explicit prompts and English/default behavior.

## Reproduction Assessment

Yes from source inspection: current main still resolves the implicit English audio prompt independently from the configured audio language and sends it through the provider request path. I did not run a live Groq or Telegram transcription because credentials and the original audio are not available in this read-only checkout.

## Solution Assessment

Yes, the best fix belongs in shared media-understanding prompt/request resolution rather than in a Groq-only branch, because Groq uses the shared OpenAI-compatible audio transcription adapter and the same request fields are exposed as core audio config.
