## Summary

Keep open: current main and v2026.6.11 still send the implicit English audio prompt alongside explicit non-English audio language hints, and the linked fix PRs are open but not merged.

## What This Changes

The issue asks OpenClaw to stop injecting the default English audio transcription prompt when an explicit non-English STT language hint is present.

## Best Possible Solution

Land one narrow shared media-understanding fix that suppresses only the implicit English audio prompt for explicit non-English audio language hints while preserving explicit prompts and English/default behavior.

## Reproduction Assessment

Yes, at source level: current main deterministically resolves the English default audio prompt and forwards it with the language hint into OpenAI-compatible provider requests. I did not run a fresh live Groq call, but the reporter supplied repeated direct Groq comparisons for the same audio.

## Solution Assessment

Yes, the maintainable fix belongs in shared media-understanding prompt/request resolution rather than a Groq-only branch, because the same OpenAI-compatible helper and prompt/language contract are shared across providers.
