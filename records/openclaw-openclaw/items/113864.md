## Label Justifications

- `P2`: The defect makes two documented optional Tavily tools unusable for configurations that otherwise use Brave web search, with bounded blast radius.
- `impact:auth-provider`: The failure is caused by SecretRef credential activation and provider/tool credential routing.

## Summary

This remains a valid current-main bug, not a duplicate of the earlier Tavily runtime-snapshot fix. The documented inactive-surface rule leaves Tavily’s configured key unresolved when Brave is selected, while the standalone Tavily tools still normalize that unresolved configured value before they can reach their documented environment fallback. ([github.com](https://github.com/openclaw/openclaw/blob/main/docs/gateway/secrets.md))

## What This Changes

Resolve the Tavily plugin SecretRef when its standalone `tavily_search` and `tavily_extract` tools are enabled, even if another provider is selected for generic `web_search`.

## System Context

Gateway startup builds a resolved SecretRef snapshot using active-surface rules, then plugin tools consume that snapshot during agent execution. Tavily has both a generic web-search provider and standalone search/extract tools, so its credential activation must reflect both entry paths.

## Architecture Diagram

flowchart LR
  A[OpenClaw configuration] --> B[Gateway SecretRef activation]
  B --> C{Active-surface policy}
  C -->|Brave selected| D[Tavily key marked inactive]
  D --> E[Runtime config snapshot]
  E --> F[Tavily standalone tools]
  F --> G[Credential normalization]
  G --> H[Search or extract request]

## Best Possible Solution

Teach the SecretRef active-surface collector that Tavily’s configured key is active when its standalone tools are enabled, retain the selected-provider optimization for provider-only credentials, and add Brave-selected regression coverage for both Tavily tools.

Required: false

## Reproduction Assessment

Yes, from source. Configure Brave as the generic provider and a file/exec SecretRef for Tavily’s configured key; active-surface filtering leaves it unresolved, and Tavily’s strict configured-key normalization runs before its environment fallback.

## Solution Assessment

Yes, with a narrower boundary than the report’s “all enabled plugins” wording. The correct repair is to make Tavily’s standalone-tool credential active when those tools are enabled, without globally activating every unselected web-search provider credential.
