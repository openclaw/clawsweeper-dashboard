## Summary

Keep this open: current main and the latest release still route declined Codex-native exec approvals through `lastToolError`/tool-warning and terminal-progress paths, which does not provide the requested same-turn continuation or a guaranteed non-success terminal invariant for empty user-addressed turns.

## What This Changes

The issue asks OpenClaw to treat declined native exec approvals as recoverable blocked tool results that either get one bounded continuation or produce a typed visible terminal failure instead of silent success.

## Best Possible Solution

Define one Codex-native approval-denial contract at the app-server bridge and attempt finalizer so declined exec approvals cannot finish a user-addressed turn as empty success; either preserve sibling results for one bounded continuation or emit a typed visible terminal failure.

## Reproduction Assessment

Yes, at source level: current main can project a declined Codex-native command as `lastToolError`, skip non-visible retry, and count that tool error as terminal progress. I did not rerun the reporter's live Slack/email timing reproduction.

## Solution Assessment

Yes on direction, with a product-decision gap: the issue points to the right bridge/finalization boundary, but maintainers still need to choose whether the permanent behavior is one bounded continuation or an immediate typed terminal failure.
