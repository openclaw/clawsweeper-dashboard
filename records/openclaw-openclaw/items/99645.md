## Summary

Keep this open: current main and v2026.6.11 still have only the partial `lastToolError` mitigation for declined Codex-native tools, while the requested continuation or typed terminal-failure invariant remains unresolved.

## What This Changes

The issue requests a native Codex exec-approval denial contract that prevents user-addressed turns from finalizing with empty assistant text or success after a declined command.

## Best Possible Solution

Define one native-approval-denial contract at the Codex bridge/finalization boundary so a declined native exec either gets a bounded continuation with sibling results preserved or emits a typed user-visible terminal failure, never an empty successful user-addressed turn.

## Reproduction Assessment

Yes, at source level: current main can project a declined Codex-native command as a blocked tool result and `lastToolError`, then count that as terminal progress with no assistant text. I did not run the reporter's Slack/email host reproduction, so live timing remains reporter-provided.

## Solution Assessment

No, the current `lastToolError` warning path is only a partial mitigation because it does not guarantee model continuation, preserve sibling results for a continuation, or enforce a non-success terminal invariant for user-addressed turns.
