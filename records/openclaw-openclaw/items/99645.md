- `maturity:stable`: The affected gateway approval and remote-execution surface maps to the M4 Stable Gateway runtime maturity area.

## Summary

Keep open: current main still records a declined Codex app-server native exec as `lastToolError` and can treat that as terminal progress, so the requested continuation or typed non-success invariant remains missing. Related issues are broader or adjacent; none safely supersedes this specific declined-native-approval failure class.

## What This Changes

Request a native approval-denial recovery contract so declined Codex execs produce a model continuation or a typed visible terminal failure instead of empty successful user-addressed turns.

## Best Possible Solution

Define one Codex native approval-denial contract at the bridge/finalization boundary: preserve blocked and completed sibling tool results, either allow one bounded continuation or emit a typed user-visible terminal failure, and never classify an empty user-addressed declined-approval turn as success solely because `lastToolError` exists.

## Reproduction Assessment

Yes at source level: current main can project a declined Codex-native command as `lastToolError`, then use that field as terminal progress while suppressing incomplete-turn fallback. I did not rerun the reporter's Slack/email host timing reproduction.

## Solution Assessment

Unclear pending maintainer product direction: the existing `lastToolError` payload path is a partial mitigation, not the best complete fix for guaranteed continuation, sibling-result preservation, and non-success terminal classification.
