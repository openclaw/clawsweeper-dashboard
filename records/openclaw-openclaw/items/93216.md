- **[P1] Bypass hook re-entry for streamed suffix chunks:** `extensions/telegram/src/lane-delivery-text-deliverer.ts:445`
  - body: This is the still-unfixed blocker from the prior review. After `beforeFinalizePreviewDelivery` has already run over the full streamed final, this loop sends each suffix through `sendPayload`; in Telegram that falls through to `deliverReplies`, which runs `message_sending` again for each payload. A long pass-through or rewrite can therefore cancel or mutate only the continuation chunks, violating the PR's exactly-once/per-message contract. Send already-gated suffixes through a path that does not re-enter `message_sending`, and cover pass-through/rewrite long finals.
