## Summary

Keep open for a maintainer product decision. Current main already provides Telegram reaction transport, passive incoming-reaction events, and outbound prompt guidance, but the requested incoming-reaction interpretation and separate `reactionGuidance` control are not established behavior and would overlap existing reaction settings.

## What This Changes

Request richer Telegram prompt guidance for sparse outbound reactions and interpretation of incoming reactions, plus a configurable `reactionGuidance` mode.

## Best Possible Solution

Keep outbound guidance derived from `reactionLevel` and add any concise incoming-event explanation only when `reactionNotifications` is enabled; introduce a separate setting only if maintainers explicitly need independently configurable prompt behavior.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Telegram reaction prompt behavior remain derived from `reactionLevel` plus `reactionNotifications`, or should OpenClaw add an independent `reactionGuidance` configuration contract?

Rationale: The existing controls already separately govern outbound reaction capability and incoming event visibility, while incoming events do not themselves start a turn; only maintainers can define whether another durable public setting and interaction promise are warranted.

Likely owner: joshp123

Owner reason: The contribution guide assigns the Telegram area to this owner, and the decision spans Telegram behavior, configuration, and user-facing documentation.

Owner confidence: medium

Options:

- **Compose existing controls (recommended):** Use `reactionLevel` for outbound guidance and condition a factual incoming-reaction note on enabled notifications, without adding a third user setting.
- **Add a prompt-only control:** Add `reactionGuidance` only after specifying its precedence, defaults, upgrade behavior, and relationship to passive reaction events.
- **Defer to reaction-input design:** Leave prompt semantics unchanged until the broader reaction-triggered-turn work establishes what reactions may cause an agent to do.

## Solution Assessment

No—not as written. A separate setting overlaps current reaction capability and notification controls; deriving narrowly scoped prompt text from those existing controls is the cleaner default unless maintainers explicitly choose independent semantics.
