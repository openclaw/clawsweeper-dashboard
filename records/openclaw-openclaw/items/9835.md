## Summary

Keep open. Current main implements outbound Telegram reaction guidance through `reactionLevel`, but it still does not interpret incoming reactions as soft signals or gate that guidance on `reactionNotifications`; the remaining config and prompt-policy contract requires maintainer direction.

## What This Changes

Requests configurable Telegram system-prompt guidance for sending reactions sparingly and interpreting received reactions as soft user signals.

## Best Possible Solution

Extend the existing `reactionLevel` prompt contract rather than adding a duplicate setting: preserve its outbound semantics, add incoming soft-signal guidance only when `reactionNotifications` is `own` or `all`, and align plugin config, strict schema, generated metadata, docs, and focused tests.

- **Extend reactionLevel (recommended):** Use the existing control for outbound guidance and conditionally add incoming soft-signal guidance when reaction notifications are enabled.
- **Add reactionGuidance:** Introduce an independent `off|minimal|full` setting with explicit composition rules, defaults, schema metadata, documentation, and compatibility tests.

## Reproduction Assessment

Yes, at source level. Current main shows outbound guidance sourced only from `reactionLevel`, no incoming soft-signal text in the shared prompt, and no notification-based prompt gating.

## Solution Assessment

No, not exactly as proposed. A separate `reactionGuidance` setting duplicates much of `reactionLevel`; extending the existing control with explicit `reactionNotifications` gating is the narrower maintainable design.
