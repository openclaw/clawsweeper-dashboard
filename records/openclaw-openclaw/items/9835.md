## Summary

Keep open. Current main implements outbound Telegram reaction guidance through `reactionLevel`, but it still lacks incoming soft-signal guidance and notification-aware prompt composition; the permanent config and behavior contract requires maintainer direction, and the related reaction-trigger and persistence issues do not replace this narrower prompt-policy request.

## What This Changes

Add configurable Telegram prompt guidance for sending reactions sparingly and interpreting incoming reactions as soft conversational signals.

## Best Possible Solution

Use one canonical Telegram reaction policy: preferably extend the existing `reactionLevel` prompt contract with incoming soft-signal guidance only when `reactionNotifications` can deliver those events, while keeping reaction-triggered execution explicitly opt-in and separately owned.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should incoming reaction interpretation be folded into the existing `reactionLevel` contract and gated by `reactionNotifications`, or should Telegram gain a separate public `reactionGuidance` setting?

Rationale: Both designs are implementable, but choosing configuration ownership, precedence, defaults, and separation from reaction-triggered execution is a public product and upgrade contract.

Likely owner: steipete

Owner reason: This account already provided the most recent item-specific product triage and identified the unresolved public contract.

Owner confidence: medium

Options:

- **Extend reactionLevel (recommended):** Keep one reaction-policy setting, add notification-aware incoming soft-signal guidance to its minimal and extensive modes, and avoid a parallel config source.
- **Add reactionGuidance:** Introduce a separate off/minimal/full setting with explicit precedence, migration, schema, metadata, documentation, and tests against reactionLevel and reactionNotifications.
- **Defer incoming semantics:** Keep current outbound-only guidance and leave reaction interpretation to the broader reaction-control design tracked in related issues.

## Reproduction Assessment

Yes, at source level: current main clearly derives outbound prompt guidance from `reactionLevel` and contains no incoming soft-signal text or notification-aware gating. A live Telegram run was not needed to establish the missing contract.

## Solution Assessment

No, not as written. A separate `reactionGuidance` setting duplicates the existing `reactionLevel` surface; extending the canonical policy and explicitly composing it with notifications is narrower and less likely to drift.
