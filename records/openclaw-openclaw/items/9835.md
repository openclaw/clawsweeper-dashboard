## Summary

Keep open. Current main and v2026.6.11 provide outbound Telegram reaction guidance through `reactionLevel`, but still lack incoming soft-signal guidance and notification gating; no related item has taken over that exact product decision.

## What This Changes

Requests configurable Telegram prompt guidance for sending reactions and interpreting incoming reactions as soft calls to action.

## Best Possible Solution

Extend one canonical Telegram reaction-level contract to cover optional incoming soft-signal guidance, gate it on accepted reaction notifications, document fresh-install and upgrade behavior, and leave reaction-triggered execution and durable feedback to their separate lifecycle owners.

Options:

- **Extend reactionLevel (recommended):** Keep one canonical config source, add optional incoming soft-signal guidance to minimal and extensive modes, and gate it on enabled accepted-reaction notifications.
- **Add reactionGuidance:** Add a separate prompt-only setting only after defining exact precedence and migration behavior against `reactionLevel` and `reactionNotifications`.
- **Keep events neutral:** Retain outbound guidance and incoming system events without prescribing emoji interpretations in the system prompt.

## Reproduction Assessment

Yes at source level: current main directly shows the existing `reactionLevel` and `reactionNotifications` contract and the absence of incoming soft-CTA prompt guidance. This is a verifiable feature gap, not a failing runtime bug reproduction.

## Solution Assessment

No, not exactly as proposed: a second `reactionGuidance` option would overlap the existing `reactionLevel` source of truth. Extending or intentionally replacing the canonical setting, with notification gating and upgrade tests, is the narrower maintainable solution.
