## Summary

Keep open. Current main provides bidirectional Telegram reaction transport and outbound reaction guidance, but incoming soft-signal guidance remains absent; a separate guidance setting would overlap existing reaction controls and needs product direction first.

## What This Changes

Add notification-aware Telegram prompt guidance for sending and interpreting reactions, optionally controlled by a new `reactionGuidance` setting.

## Best Possible Solution

Use `reactionLevel` for outbound behavior and compose a small incoming soft-signal section from `reactionNotifications`; add a separate setting only if maintainers require independent prompt suppression.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should reaction prompt policy be derived from the existing `reactionLevel` and `reactionNotifications` controls, or should Telegram expose an independently configurable guidance mode?

Rationale: Both existing settings already influence parts of the proposed behavior, so adding another defaulted config field could create overlapping policy and upgrade-visible prompt changes.

Likely owner: steipete

Owner reason: Recent issue triage already framed the unresolved product boundary between the existing controls and a new setting.

Owner confidence: medium

Options:

- **Compose Existing Controls (recommended):** Keep `reactionLevel` authoritative for outbound guidance and add incoming soft-signal guidance only when `reactionNotifications` is enabled.
- **Add Independent Guidance Mode:** Add `reactionGuidance: off|minimal|full` with explicit precedence, defaults, schema metadata, documentation, and upgrade tests.
- **Keep Transport Only:** Retain current reaction events and outbound guidance without prescribing model interpretation of incoming emoji.

## Reproduction Assessment

Yes at source level: current prompt composition deterministically shows outbound guidance from `reactionLevel`, while the strict schema and prompt text lack the requested incoming guidance and setting. No live Telegram run was needed to establish that product gap.

## Solution Assessment

No, not as currently specified. Adding incoming guidance is plausible, but a separate defaulted setting is not clearly better than composing the two existing reaction controls and would enlarge an already sensitive config surface.
