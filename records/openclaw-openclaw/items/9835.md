## Summary

Keep open. Current main and v2026.6.11 provide bidirectional Telegram reaction transport and outbound reaction guidance, but they still lack incoming-reaction interpretation, notification-aware prompt composition, and a settled product contract for whether that behavior belongs in the existing `reactionLevel` setting or a new setting.

## What This Changes

Add configurable Telegram prompt guidance for sending reactions and interpreting incoming reactions as soft user signals, composed with reaction-notification settings.

## Best Possible Solution

Keep one Telegram-plugin-owned reaction policy: preserve `reactionLevel` for outbound capability, add incoming soft-signal guidance only when reaction notifications are enabled, and introduce a new setting only if maintainers define a non-overlapping purpose, defaults, upgrade behavior, schema metadata, docs, and focused composition tests.

Options:

- **Extend existing policy (recommended):** Keep `reactionLevel` as the outbound control and append incoming soft-signal guidance only when `reactionNotifications` is not off.
- **Add separate guidance control:** Add `reactionGuidance` only after defining distinct off/minimal/full semantics and explicit composition with both existing settings.
- **Keep outbound guidance only:** Leave incoming reactions as plain system-event context and decline automatic emoji interpretation in the system prompt.

## Solution Assessment

No, not exactly as proposed. A separate `reactionGuidance` key would overlap the existing `reactionLevel` contract; extending the existing policy while gating only incoming guidance is the narrower maintainable direction.
