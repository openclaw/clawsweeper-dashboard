## Summary

Keep open. Current main provides outbound Telegram reaction guidance through `reactionLevel`, but incoming soft-signal guidance and notification-aware prompt composition remain absent; the overlapping configuration and reaction-trigger semantics require maintainer product direction.

## What This Changes

Request configurable Telegram prompt guidance for sending reactions sparingly and interpreting received reactions as soft user signals.

## Best Possible Solution

Keep `reactionLevel` and `reactionNotifications` as the canonical controls, add inbound soft-signal guidance only under explicitly enabled notification semantics, document whether guidance applies on the next normal turn or may wake the agent, and avoid a parallel config key unless maintainers deliberately approve that contract.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Telegram use the existing `reactionLevel` plus `reactionNotifications` to control inbound prompt guidance, or introduce a separate public `reactionGuidance` setting with independent defaults?

Rationale: The existing controls already partially own this behavior, while incoming reactions currently do not guarantee an agent turn; choosing a permanent config and execution contract cannot be resolved safely as a mechanical implementation detail.

Likely owner: steipete

Owner reason: They merged the original reaction feature and are already connected to the product-level issue discussion.

Owner confidence: high

Options:

- **Compose Existing Controls (recommended):** Use `reactionLevel` for outbound guidance and inject restrained inbound soft-signal guidance only when `reactionNotifications` permits delivery, without adding another config key.
- **Add Independent Guidance:** Introduce and document `reactionGuidance: off|minimal|full`, including explicit precedence, generated metadata, upgrade behavior, and interaction with both existing controls.
- **Keep Outbound Guidance Only:** Retain current behavior and decline standardized inbound emoji semantics until reaction-trigger and persistence policy is settled.

## Reproduction Assessment

Yes at source level, although this is not a broken-contract bug: current main clearly lacks a separate guidance setting, notification-aware prompt composition, and inbound soft-signal wording.

## Solution Assessment

No, not exactly as proposed. A second prompt-control setting would overlap `reactionLevel`; composing the existing controls is the narrower solution unless maintainers explicitly want independent configuration.
