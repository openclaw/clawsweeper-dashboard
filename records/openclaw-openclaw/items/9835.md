## Summary

Keep open: current main has Telegram reaction notifications and outbound reaction prompt guidance, but it still lacks the requested `reactionGuidance` config and incoming-reaction soft-CTA prompt semantics; the remaining work needs a maintainer product/config decision rather than cleanup closure.

## What This Changes

Request adds bidirectional Telegram reaction prompt guidance plus a `reactionGuidance: "off" | "minimal" | "full"` config option tied to Telegram reaction notifications.

## Best Possible Solution

Define one canonical Telegram reaction prompt policy: either extend existing `reactionLevel` and `reactionNotifications` with incoming soft-CTA guidance, or intentionally add `reactionGuidance` with schema, generated metadata, docs, defaults, and focused upgrade-safe tests.

Options:

- **Use existing reaction config (recommended):** Keep `reactionLevel` as the outbound guidance control and gate incoming soft-CTA guidance on `reactionNotifications`, avoiding a third reaction config knob.
- **Add reactionGuidance explicitly:** Add `reactionGuidance: off|minimal|full` with config schema, metadata, docs, and tests that define how it composes with `reactionLevel` and `reactionNotifications`.
- **Decline prompt semantics:** Keep reactions as raw events and message-tool actions only, leaving semantic interpretation to user prompts or future plugin policy.
