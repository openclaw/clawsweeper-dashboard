## Summary

Keep this issue open for a maintainer product decision. Telegram already supports inbound reaction events and outbound reaction behavior, but the requested separate prompt policy and incoming “soft CTA” interpretation remain a new, overlapping configuration and interaction contract rather than a defined bug fix.

## What This Changes

Request configurable Telegram prompt guidance for outbound reactions and for interpreting incoming user reactions as lightweight conversational signals.

## System Context

Telegram’s channel plugin receives reaction updates, controls whether they reach the agent, and supplies channel-specific reaction guidance to the shared system prompt. The resulting prompt influences agent tool use and how the next conversation turn treats reaction events.

## Architecture Diagram

flowchart LR
  A[Telegram reaction update] --> B[Telegram channel policy]
  B --> C[Reaction event queue]
  C --> D[Next agent turn]
  B --> E[Channel prompt guidance]
  E --> F[Shared system prompt]
  F --> G[Agent response or outbound reaction]

## Best Possible Solution

Choose one Telegram-owned contract: either document and retain the existing reaction-level behavior, or add one clearly differentiated opt-in guidance setting with defined interaction with notification delivery, defaults, metadata, docs, and focused tests.
