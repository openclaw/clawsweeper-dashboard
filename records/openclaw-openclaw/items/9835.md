## Summary

Keep open. Current main implements outbound Telegram reaction guidance through `reactionLevel`, but it still lacks incoming soft-signal guidance and notification-aware prompt composition; whether to add another configuration surface requires maintainer product direction.

## What This Changes

Requests configurable Telegram prompt guidance for sending reactions sparingly and interpreting incoming user reactions as soft calls to action.

## Best Possible Solution

Reuse `reactionLevel` for outbound behavior, add incoming soft-signal guidance only when effective `reactionNotifications` is not `off`, document the passive-next-turn limitation, and leave reaction-triggered execution to the canonical trigger discussion.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should incoming Telegram reaction interpretation reuse the existing `reactionLevel` and `reactionNotifications` controls, or should OpenClaw add an independent `reactionGuidance` configuration surface?

Rationale: Both controls already affect reaction-related model behavior, and adding a third setting changes the public configuration contract and could create conflicting modes; source inspection cannot determine the intended product semantics.

Likely owner: steipete

Owner reason: They supplied the most recent product-level triage on the precise configuration and prompt-semantics question.

Owner confidence: medium

Options:

- **Consolidate existing controls (recommended):** Keep `reactionLevel` as the outbound guidance control and gate incoming soft-signal guidance with `reactionNotifications`, avoiding another public setting.
- **Add independent guidance mode:** Add `reactionGuidance: off|minimal|full` with explicit precedence, migration, schema, metadata, documentation, and fresh-install/upgrade tests.
- **Keep passive events only:** Retain current reaction events and outbound guidance without teaching the agent a fixed incoming emoji interpretation map.

## Reproduction Assessment

Yes, from source inspection: current main clearly shows outbound reaction guidance while lacking incoming soft-CTA text, notification gating, and the requested configuration field. This is a missing-feature verification rather than a runtime failure reproduction.

## Solution Assessment

No, the proposed separate `reactionGuidance` option is not yet the best proven shape because it overlaps the existing `reactionLevel` and `reactionNotifications` controls. Consolidating those controls is narrower unless maintainers intentionally want independent policy axes.
