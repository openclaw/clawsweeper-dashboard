## Summary

The intent is useful, but this PR is not merge-ready because it says the parent `--json` flag must precede the browser subcommand even though current main deliberately supports both orders. The compatibility behavior was merged before this PR opened and is covered by focused browser CLI tests, so the docs should present the proposed order as canonical rather than mandatory. Likely related people: @ml12580 (high confidence, introduced the trailing-parent-option repair) and @steipete (high confidence, rewrote/merged that repair and has extensive browser CLI history).

## What This Changes

The PR updates two browser documentation pages to prescribe `openclaw browser --json status` and replace a trailing-flag status example.

## Best Possible Solution

Clarify that `--json` is owned by `openclaw browser`, show the pre-subcommand order as the canonical style, and avoid rejecting the supported `openclaw browser status --json` form.
