## Summary

Keep open. Current main and the latest release still have cron error classification plus generic transient retry/backoff, but they do not implement the requested recurring reason-aware guard layer, job-level cooldown/disabled guard state, Retry-After-aware cron scheduling, or full UI/docs/protocol policy coverage.

## What This Changes

The issue requests reason-aware cron guardrails that classify quota, auth, rate-limit, timeout, format, and unknown failures and apply different backoff, circuit-breaker, alerting, and observability behavior.

## Best Possible Solution

Keep this as the canonical umbrella until maintainers approve and land a cron guard policy that covers recurring scheduling, persisted guard state, Gateway/UI visibility, docs, and regression tests while coordinating with provider/auth cooldown behavior.

Yes for the source-level gap: current main records lastErrorReason but recurring cron still uses generic retry/backoff and public state lacks guard fields. I did not rerun a live provider retry-storm scenario.
