## Summary

Keep open: current main has structured cron error observability, transient retry policy, failure alerts, and generic recurring backoff, but it still lacks the requested reason-aware recurring guard policy and job-level circuit-break state. The production reports establish meaningful retry-storm and provider-lockout impact, while the default pause and recovery behavior requires maintainer direction.

## What This Changes

Add reason-aware recurring cron mitigation that distinguishes permanent billing, authentication, and format failures from transient rate-limit, timeout, network, and overload failures.

## Best Possible Solution

Extend the existing classification, retry, and failure-alert path with one canonical recurring-job guard state: transient failures remain enabled with bounded backoff, definitive billing/auth/format failures pause after a maintainer-selected threshold, and CLI/UI surfaces show the reason, recovery action, and single-alert status without creating a parallel retry-policy stack.

- **Opt-in strict guard:** Preserve current recurring behavior by default and add an explicit strict policy for operators who want automatic pausing.
- **Alerts and cooldowns only:** Keep jobs enabled indefinitely and rely on provider cooldowns, generic backoff, and failure notifications without a job-level circuit breaker.
