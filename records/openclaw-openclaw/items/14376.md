## Summary

Keep open. Current main and the latest release still provide partial observability plus generic recurring retry/backoff, but not the requested reason-aware recurring cron guard layer with billing/auth/format circuit breaking, Retry-After-aware scheduling, persisted guard state, and client-visible policy state.

## What This Changes

Request reason-aware cron guardrails that classify quota, auth, rate-limit, timeout, network, format, and unknown failures and apply safer backoff or circuit-break behavior for automated jobs.

## Best Possible Solution

Keep this as the canonical umbrella until maintainers approve and land a recurring cron guard policy that covers scheduler behavior, persisted guard state, Gateway/UI visibility, docs, tests, and provider/auth cooldown coordination.

Yes, at source level: current main records lastErrorReason but recurring cron still uses generic retry/backoff and public state lacks guard fields. I did not rerun a live provider retry-storm scenario in this read-only review.
