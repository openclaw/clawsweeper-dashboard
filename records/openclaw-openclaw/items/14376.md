## Summary

Keep open. Current main and v2026.6.11 still provide partial cron error observability plus generic/transient retry behavior, but not the requested recurring reason-aware guard layer with billing/auth/format circuit breaking, Retry-After-aware scheduling, and visible job-level guard state.

Request a reason-aware cron failure guard that classifies quota, auth, rate-limit, timeout, and format errors and applies backoff, circuit breaking, alerts, and visible state.

## Best Possible Solution

Keep this issue as the canonical umbrella until maintainers approve and land a recurring cron guard policy with persisted guard state, Gateway/UI visibility, docs, and regression coverage coordinated with provider/auth cooldown behavior.
