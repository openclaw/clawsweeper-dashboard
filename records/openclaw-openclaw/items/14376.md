## Summary

Keep open. Current main has classified cron error observability and generic transient retry/backoff, but it still lacks the requested reason-specific recurring cron guard layer, job-level cooldown/disabled state, Retry-After-aware scheduling, and full protocol/UI/docs/test coverage; the open related PRs are partial slices, not replacements for the umbrella issue.

## What This Changes

The issue requests reason-aware cron guardrails that classify quota, auth, rate-limit, timeout, format, and unknown failures and apply differentiated backoff, circuit-breaker, alerting, and state visibility behavior.

## Best Possible Solution

Keep this issue as the canonical umbrella and land a maintainer-approved cron guard policy across timer behavior, persisted state, Gateway/UI visibility, docs, and regression tests while coordinating with auth-profile/provider cooldowns and the partial PRs.

Yes, at source level: current main records lastErrorReason and has global retry/backoff, but recurring cron still falls through to generic consecutive-error backoff and public state lacks cooldown/disabled guard fields. I did not replay a live provider retry storm.
