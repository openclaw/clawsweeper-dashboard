## Summary

Keep this open: current main has partial stale-run recovery, but source still shows in-memory follow-up queues, process-fatal unhandled rejections, idle-watchdog disablement for effectively unlimited run budgets, queue retries without a per-item failure cap, and Codex wrapper idle guards gated by active app-server requests; the maintainer-protected umbrella needs product sequencing rather than cleanup closure.

## What This Changes

Request a staged run-lifecycle reliability design for bounded liveness, abort-to-release ownership, restart-safe follow-up queues, and completion-driving recovery.

## Best Possible Solution

Adopt the invariants as a maintainer-owned umbrella, then split Track A-D into focused PRs that extend existing terminal-outcome/stuck-recovery paths and move durable queue state into SQLite.
