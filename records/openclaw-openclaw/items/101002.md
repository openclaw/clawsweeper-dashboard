## Summary

Keep open: current main does not yet provide Android reasoning gating, but this PR still has a compatibility defect because it treats absent optional model reasoning metadata as explicit no-reasoning and would hide/send `off` for capable models with older or incomplete catalog rows.

## What This Changes

The PR adds Android client gating that hides thinking controls for selected non-reasoning models and sends `thinking: "off"` for immediate and active outbox sends, with Kotlin regression tests and native i18n metadata updates.

## Best Possible Solution

Keep the Android reasoning gate, but carry model reasoning as true/false/unknown, gate only explicit `reasoning: false`, preserve the current session-model hydration, and add a regression plus redacted real Android proof.

## Solution Assessment

No: the direction is right, but the implementation is too strict because it collapses unknown metadata into an explicit unsupported state. The narrower maintainable fix is to preserve unknown/fail-open semantics like the protocol and iOS sibling do.
