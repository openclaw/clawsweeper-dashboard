## Summary

The patch is correct and well-proven, but merge readiness depends on a ClickClack owner accepting the permanent timeout policy and its ambiguous-write semantics.

## What This Changes

Adds a fixed 30-second completion timeout to ClickClack JSON REST requests and response-body reads while preserving caller abort signals and excluding multipart uploads.

## Best Possible Solution

Have the ClickClack owner explicitly accept or retune the 30-second JSON deadline, multipart exception, and ambiguous committed-write behavior; if accepted, merge this bounded owner-local implementation without adding config surface.
