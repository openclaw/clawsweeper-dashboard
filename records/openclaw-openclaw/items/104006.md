## Summary

Keep open for owner review: the implementation and proof are strong, but the fixed 30-second JSON deadline and unbounded multipart exception intentionally change failure behavior for existing ClickClack operations and need explicit product/compatibility approval.

## What This Changes

The PR adds a private 30-second completion deadline to ClickClack JSON REST requests and response-body reads, preserves caller abort signals, and leaves multipart uploads unchanged.

## Best Possible Solution

Adopt owner-approved, private operation-class deadlines in the ClickClack client—retaining the proven bounded JSON path and either explicitly accepting the multipart exception with follow-up ownership or assigning uploads a suitably larger finite deadline—then rebase and rerun the focused client and channel tests.
