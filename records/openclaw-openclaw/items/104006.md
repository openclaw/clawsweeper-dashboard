## Summary

Keep this PR open for an area-owner decision. The provided prior review found no mechanical defect and the contributor supplied controlled-server timeout evidence, but the current head was force-pushed on July 26, 2026 and the permanent contract remains unresolved: whether ClickClack JSON reads and mutating REST requests should share an unconditional 30-second completion deadline, including the ambiguous outcome of a timed-out write.

## What This Changes

The PR adds a 30-second completion deadline to ClickClack JSON REST requests and response-body reads, preserves caller cancellation, and leaves multipart uploads and WebSocket handling outside that REST deadline.

## System Context

ClickClack is a bundled channel plugin whose REST client supports gateway startup, inbound lookup, outbound delivery, and activity updates. The client turns those operations into HTTP requests and returns parsed API results or errors to the channel runtime; WebSocket monitoring follows a separate path.

## Best Possible Solution

Adopt one documented owner-local REST policy for ClickClack: bound JSON request completion, preserve multipart behavior, and explicitly decide how callers should treat a timed-out mutating request before landing the current-head-tested implementation.
