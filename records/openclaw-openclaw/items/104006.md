## Summary

This remains useful and is not already implemented on current main: it bounds ClickClack REST stalls, while the related merged work covers only WebSocket handshakes. The patch has no discrete correctness finding, but an area owner must explicitly accept the permanent 30-second JSON deadline, ambiguous-write outcome, and multipart exception before merge.

## What This Changes

The PR adds a fixed 30-second completion deadline to ClickClack JSON REST requests and response-body reads, preserves caller cancellation, and leaves multipart uploads and WebSockets outside that REST deadline.

## Best Possible Solution

Accept a documented ClickClack REST policy that bounds JSON request completion at 30 seconds, preserves caller cancellation, treats timed-out writes as potentially ambiguous, and keeps multipart uploads exempt only if that exception is intentional; then rebase and validate the exact landing head.
