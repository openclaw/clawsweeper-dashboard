## Label Justifications

- `P2`: The issue describes a real Feishu streaming usability problem with bounded channel-specific blast radius and no evidence of data loss, security bypass, or unusable core runtime.
- `impact:ux-friction`: Feishu users can continue working, but streamed replies show avoidable progress noise and the documented hide-progress policy does not apply to Feishu.

## Summary

Keep open: current main no longer has production `Exec failed` command-output wording, but Feishu still renders transient tool status into streaming cards through a boolean-only config surface and still lacks the shared `toolProgress` or `commandText` preview controls.

## What This Changes

The issue asks for Feishu streaming cards to avoid alarming exec-progress interruptions and to gain a per-channel way to keep streaming while hiding or reducing tool-progress lines.

## Best Possible Solution

Make Feishu honor the shared streaming preview policy with backward-compatible schema, manifest, docs, and tests for default progress, opt-out, and status-only command text; keep gateway config mutation protection unchanged unless a separate security review approves a narrow allowlist change.

## Solution Assessment

Unclear until maintainers choose the Feishu config/API shape. Reusing the shared preview policy is the narrowest maintainable direction found; a one-off string filter or broad `config.patch` allowlist change would leave policy drift or operator-boundary risk.
