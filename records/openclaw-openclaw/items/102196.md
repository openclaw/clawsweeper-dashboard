## Label Justifications

- `P2`: The issue describes a real Feishu streaming usability problem with bounded channel-specific blast radius and no evidence of data loss, security bypass, or unusable core runtime.
- `impact:ux-friction`: Feishu users can continue working, but streamed replies show avoidable progress noise and the documented hide-progress policy does not apply to Feishu.

## Summary

Keep open: current main has moved away from the exact old production `Exec failed` command-output wording, but the remaining Feishu problem is still real because boolean Card Kit streaming appends progress status into the streamed card and Feishu still lacks the shared `preview.toolProgress` / `commandText` policy shape.

## What This Changes

The issue asks OpenClaw to reduce misleading Feishu exec/tool-progress interruptions while preserving streaming replies, preferably with a Feishu-specific progress visibility control and a supported toggle path.

## Best Possible Solution

Make Feishu honor the shared streaming preview policy with backward-compatible schema, manifest, docs, and tests for default progress, opt-out, and status-only command text; keep `config.patch` protection unchanged unless maintainers separately approve a narrow allowlist change.

Options:

- **Adopt shared Feishu preview policy (recommended):** Extend Feishu to accept the shared nested preview config while preserving current boolean defaults, and leave `config.patch` protection unchanged unless separately approved.
- **Only neutralize failed progress wording:** Keep Feishu streaming boolean-only and reduce scary non-zero exec wording, which is smaller but still leaves no way to stream answers while hiding progress lines.
- **Allow coarse gateway toggle:** Permit `channels.feishu.streaming` through `config.patch`, which helps recovery but broadens an operator-controlled config path and still lacks status-only progress.

## Reproduction Assessment

Yes, source-reproducible: with Feishu streaming enabled, `onToolStart` feeds progress text into `statusLine` and `buildCombinedStreamText` appends it into the streaming card. I did not run a live Feishu websocket deployment in this read-only review.

## Solution Assessment

Unclear until maintainers choose the Feishu config/API shape. Reusing the shared preview policy is the narrowest maintainable direction found; a one-off string filter or broad `config.patch` allowlist change would leave policy drift or operator-boundary risk.
