## Label Justifications

- `P2`: The issue describes a real Feishu streaming usability problem with bounded channel-specific blast radius and no evidence of data loss, security bypass, or unusable core runtime.
- `impact:ux-friction`: Feishu users can continue working, but streamed replies show avoidable progress noise and the documented hide-progress policy does not apply to Feishu.

## Summary

Keep open: current main and the latest release still leave Feishu on a boolean-only streaming surface, with transient tool status appended into streaming cards and no Feishu `preview.toolProgress` or `commandText` control. A fix is plausible, but it needs maintainer direction because the clean path changes Feishu's public config shape and touches the gateway config mutation boundary.

## What This Changes

The issue asks for Feishu streaming to stop surfacing misleading exec/tool-progress failure text and to gain a per-channel way to hide tool-progress while keeping streaming enabled.

## Best Possible Solution

Make Feishu honor the shared streaming preview policy with backward-compatible schema, manifest, docs, and tests for default progress, opt-out, and status-only command text; keep gateway config mutation protection unchanged unless maintainers separately approve a narrow allowlist change.
