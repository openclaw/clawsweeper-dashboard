## Label Justifications

- `P2`: The issue is a normal-priority Feishu streaming UX problem with limited channel blast radius and no evidence of data loss, security bypass, or full onboarding blockage.
- `impact:ux-friction`: Users can still complete work, but Feishu streaming previews can show noisy or misleading progress lines and require manual config edits to avoid them.

## Summary

Keep open: current main has moved away from the exact reported compact `Exec failed` wording for non-zero command output, but Feishu still injects tool-progress status into streaming cards whenever boolean streaming is enabled and still has no Feishu-supported `preview.toolProgress` or `commandText` control.

## What This Changes

Request that Feishu streaming-card previews stop showing misleading or noisy tool-progress for benign non-zero exec activity, or provide a Feishu per-channel control to hide or sanitize that progress while keeping streaming enabled.

## Best Possible Solution

Adopt one Feishu streaming policy that preserves current CardKit behavior, adds an explicit way to keep answer streaming while hiding or sanitizing tool progress, and documents whether the gateway tool may change it.
