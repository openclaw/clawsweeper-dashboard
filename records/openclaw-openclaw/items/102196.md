## Label Justifications

- `P2`: The report describes a real Feishu streaming usability issue with bounded channel-specific blast radius and no evidence of data loss, security bypass, or unusable core runtime.
- `impact:ux-friction`: Feishu users can continue working, but streamed replies show avoidable progress noise and the documented hide-progress policy does not apply to Feishu.

## Summary

Keep open: current main no longer appears to use the literal shared `Exec failed` command-output wording, but Feishu still renders work-tool status into streaming cards whenever boolean `streaming` is enabled and has no Feishu-supported `streaming.preview.toolProgress` or `commandText: "status"` opt-out.

## What This Changes

The issue asks Feishu to stop disruptive/noisy tool-progress lines for benign exec non-zero exits and to add a Feishu-supported way to keep streaming while hiding or reducing tool-progress detail.

## Best Possible Solution

Make Feishu honor the shared nested streaming preview policy for tool-progress visibility and command-text detail while preserving existing defaults; keep `config.patch` protection unchanged unless maintainers explicitly approve a narrow allowlist change.
