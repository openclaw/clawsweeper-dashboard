## Summary

Keep open: current main no longer appears to use the literal `Exec failed` command-output wording in the shared progress formatter, but Feishu still streams tool status into cards whenever boolean streaming is enabled and has no supported `streaming.preview.toolProgress` / `commandText` policy, so the Feishu-specific opt-out remains unresolved.

## What This Changes

The issue asks Feishu streaming to avoid misleading exec failure progress lines and to add a per-channel way to hide tool progress while keeping streaming enabled.

## Best Possible Solution

Make Feishu honor the shared nested streaming preview policy with backward-compatible schema, manifest, docs, and tests for default progress, opt-out, and status-only command text; keep `config.patch` protection unchanged unless maintainers explicitly approve a narrow allowlist change.

## Reproduction Assessment

Yes, source-level for the remaining gap: Feishu enables `onToolStart` whenever streaming is on and appends the resulting status line into the card stream, while its config schema and manifest only accept a boolean streaming setting. I did not run a live Feishu websocket deployment.

## Solution Assessment

Unclear until maintainers choose the Feishu config/API shape. Reusing the shared compact progress policy is the narrowest maintainable direction found; a one-off string filter or broad `config.patch` allowlist change would leave policy drift or operator-boundary risk.
