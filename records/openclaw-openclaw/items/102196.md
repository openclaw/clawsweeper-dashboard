## Summary

Keep open: current main still has Feishu-specific streaming-card behavior that appends tool status into live cards while Feishu only accepts a boolean `streaming` config, so the requested Feishu opt-out/status-only policy remains unresolved and needs product direction.

## What This Changes

The issue asks OpenClaw to reduce misleading Feishu tool-progress interruptions for benign non-zero exec exits and add a supported Feishu preview tool-progress control.

## Best Possible Solution

Make Feishu honor the shared streaming preview policy with backward-compatible schema, manifest, docs, and regression tests for default progress, opt-out, and status-only command text; keep gateway config mutation protection unchanged unless maintainers explicitly approve a narrow allowlist change.

Unclear until maintainers choose the Feishu config/API shape. Reusing the shared compact progress policy is the narrowest maintainable direction found; a one-off string filter or broad `config.patch` allowlist change would leave policy drift or operator-boundary risk.
