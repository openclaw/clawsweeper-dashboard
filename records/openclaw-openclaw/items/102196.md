## Summary

Keep open: current main partially addresses the scary command-output wording by rendering non-zero command output as `exit N`, but Feishu still has a boolean-only streaming config, appends work-tool status into the streaming card whenever streaming is enabled, and has no Feishu `preview.toolProgress` or `commandText: "status"` policy. That remaining behavior needs maintainer product direction before a fix PR should be queued.

## What This Changes

The issue asks OpenClaw to make Feishu streaming avoid misleading/noisy exec progress lines and provide a per-channel way to keep streaming while hiding or reducing tool-progress detail.

## Best Possible Solution

Make Feishu honor the shared streaming preview policy with backward-compatible schema, manifest, docs, and tests for default progress, opt-out, and status-only command text; keep gateway config mutation protection unchanged unless maintainers explicitly approve a narrow allowlist change.

Options:

- **Adopt shared Feishu preview policy (recommended):** Extend Feishu to accept the nested preview config while preserving current defaults, with focused tests and docs, and leave `config.patch` protection unchanged unless separately approved.
- **Only reduce progress wording:** Keep Feishu streaming boolean-only and make progress copy less alarming, which is smaller but still leaves no way to keep streaming while hiding progress lines.
- **Allow coarse streaming toggle:** Allow gateway `config.patch` to change `channels.feishu.streaming`, which helps recovery but broadens an operator-controlled path and does not provide status-only progress.

## Reproduction Assessment

Yes, source-level: Feishu enables tool status updates whenever streaming is on and appends the status line into the card stream, while its schema and docs only expose boolean streaming. I did not run a live Feishu websocket deployment, so this is source-reproducible rather than live-reproduced.

## Solution Assessment

Unclear until maintainers choose the Feishu config/API shape. Reusing the shared compact progress policy is the narrowest maintainable direction found; a one-off string filter or broad `config.patch` allowlist change would leave policy drift or operator-boundary risk.
