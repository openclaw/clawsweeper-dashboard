## Label Justifications

- `impact:ux-friction`: Feishu users can receive misleading or noisy streamed status text and lack an in-product per-channel way to keep streaming while hiding tool progress.

## Summary

Keep open: current main still has boolean-only Feishu streaming, routes progress/error status into Feishu streaming cards, and does not expose the shared preview tool-progress controls for Feishu, so the reported UX gap remains real.

## What This Changes

The issue asks for Feishu streaming to stop surfacing misleading benign exec failure progress and to gain a supported per-channel tool-progress or command-text streaming control.

## Best Possible Solution

Add Feishu-owned support for the shared preview streaming policy, including `streaming.preview.toolProgress` and `streaming.preview.commandText`, with schema/docs/doctor/test coverage; handle any gateway config.patch allowlist change as a separate trust-boundary decision.
