## Label Justifications

- `P2`: The issue describes a real Feishu streaming UX problem with limited blast radius and no evidence of data loss, security bypass, crash loop, or first-run blocker.
- `impact:ux-friction`: False failure progress lines interrupt the Feishu streamed reply and create avoidable confusion, but the report does not show that users are fully blocked.

## Summary

Keep open: current main still treats non-zero exec results as tool errors, Feishu still exposes only a boolean streaming setting with no shared `progress.toolProgress` control, and the agent-facing config patch rejection is expected fail-closed behavior rather than an available workaround.

## What This Changes

Feishu users want benign non-zero exec progress to avoid rendering as failure in streamed previews, plus a supported Feishu way to hide tool-progress while keeping streaming enabled.

## Best Possible Solution

Adopt a maintainer-approved Feishu progress policy surface, likely aligned with the shared streaming progress config, and narrow exec progress presentation so handled non-zero command results do not appear as mid-stream false failures.
