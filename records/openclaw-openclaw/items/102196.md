## Label Justifications

- `P2`: The issue describes a real Feishu streaming usability problem with bounded channel-specific blast radius and no evidence of data loss, security bypass, crash loop, or unusable core runtime.
- `impact:ux-friction`: Feishu users can continue working, but streamed replies show avoidable progress noise and the documented hide-progress policy does not apply to Feishu.

## Summary

Keep open: current main still appends Feishu tool-progress status into streaming cards, Feishu still exposes `streaming` as a boolean-only config surface, and the gateway config mutation guard still protects `channels.feishu.streaming`, so the requested Feishu opt-out/status-only path remains unresolved.

## What This Changes

The issue requests that Feishu streaming stop interrupting live previews with benign exec failure progress and gain a supported per-channel tool-progress or command-text control.

## Best Possible Solution

Make Feishu honor the shared streaming preview policy for `toolProgress` and `commandText` without invalidating existing boolean configs; keep `config.patch` protection unchanged unless maintainers explicitly approve a narrow security-boundary change.

- **Only soften exec progress wording:** Reduce scary benign non-zero exec wording while keeping Feishu streaming boolean-only, which is smaller but leaves no supported way to keep streaming while hiding progress lines.
- **Allow coarse gateway streaming toggle:** Permit gateway `config.patch` to change `channels.feishu.streaming`, which helps recovery but broadens an operator-controlled path and still does not provide status-only progress.

## Reproduction Assessment

Yes, from source inspection: Feishu enables `onToolStart` whenever streaming is on and appends the resulting status line into the card stream. I did not run a live Feishu websocket deployment, so this is source-reproducible rather than live-reproduced.

## Solution Assessment

Unclear until maintainers choose the Feishu config and operator-mutation policy. Reusing the shared compact progress policy is the narrowest maintainable direction found; a one-off string filter or broad `config.patch` allowlist change would leave policy drift or boundary risk.
