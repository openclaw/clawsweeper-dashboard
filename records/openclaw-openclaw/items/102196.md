## Label Justifications

- `P2`: The issue describes a real Feishu streaming usability problem with bounded channel-specific blast radius and no evidence of data loss, security bypass, or unusable core runtime.
- `impact:ux-friction`: Feishu users can continue working, but streamed replies can include avoidable progress noise and the documented hide-progress policy does not apply to Feishu.

## Summary

Keep open: current main still wires Feishu streaming cards to show tool-progress status lines whenever boolean streaming is enabled, while Feishu still lacks the shared preview policy shape needed to hide or status-only those progress lines.

## What This Changes

The issue requests less disruptive Feishu exec/tool progress during streaming plus a Feishu-specific way to keep streaming while hiding or reducing tool-progress text.

## Best Possible Solution

Make Feishu honor the shared streaming preview policy for tool-progress visibility and command text while preserving today’s defaults; keep the gateway config mutation boundary unchanged unless maintainers explicitly approve a narrow allowlist change.

Options:

- **Adopt shared Feishu preview policy (recommended):** Extend Feishu to accept and honor the shared nested preview config with backward-compatible defaults, and leave `config.patch` protection unchanged unless separately approved.
- **Only reduce progress wording:** Keep Feishu streaming boolean-only and make progress text less disruptive, which is smaller but leaves no supported way to stream answers while hiding progress lines.
- **Allow coarse gateway toggle:** Permit `config.patch` for `channels.feishu.streaming`, which helps recovery but broadens a protected config path and still lacks status-only progress control.

## Solution Assessment

Unclear until maintainers choose the Feishu config/API shape. Reusing the shared compact progress policy looks like the narrowest maintainable direction; a one-off string filter or broad `config.patch` allowlist change would leave policy drift or operator-boundary risk.
