## Label Justifications

- `P2`: The issue describes a real Feishu streaming usability problem with bounded channel-specific blast radius and no evidence of data loss, security bypass, or unusable core runtime.

## Summary

Keep open: current main still streams Feishu tool-progress status lines into Card Kit previews, and Feishu still exposes only a boolean streaming config, so the tool-progress opt-out/status-only request is unresolved and needs maintainer product direction.

## What This Changes

The issue requests safer Feishu streamed tool-progress behavior for benign non-zero exec exits plus a per-channel way to keep streaming while hiding or reducing tool-progress command text.

## Best Possible Solution

Make Feishu honor the shared streaming preview policy with backward-compatible schema, manifest, docs, and tests for default progress, opt-out, and status-only command text; keep gateway config mutation protection unchanged unless maintainers explicitly approve a narrow allowlist change.

Rationale: The source-level problem is clear, but the fix changes Feishu's public config shape and may affect the model-to-operator config mutation boundary, so maintainer product intent is required before implementation.

Likely owner: xzq-xu

Owner confidence: high

Options:

- **Adopt shared Feishu preview policy (recommended):** Extend Feishu to accept the shared nested streaming preview config while preserving current defaults and leave `config.patch` protection unchanged unless a separate security review approves it.
- **Only adjust progress wording:** Keep Feishu streaming config boolean-only and reduce scary non-zero exec wording, which is smaller but still leaves no way to keep streaming while hiding progress lines.
- **Allow coarse gateway toggle:** Add `channels.feishu.streaming` to the gateway mutation allowlist so agents can disable streaming, which helps recovery but broadens an operator-controlled config path and does not provide status-only progress.

## Reproduction Assessment

Yes, from source inspection: Feishu appends formatted tool status lines into streaming card text whenever `streaming` is enabled, and its schema does not accept the documented nested preview opt-out. I did not run a live Feishu websocket/Card Kit deployment, so this is source-reproducible rather than live-reproduced.

## Solution Assessment

Unclear until maintainers choose the Feishu config/API shape. Reusing the shared compact progress policy is the narrowest maintainable direction found; a one-off string filter or broad `config.patch` allowlist change would leave policy drift or operator-boundary risk.
