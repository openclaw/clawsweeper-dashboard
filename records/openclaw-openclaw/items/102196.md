## Label Justifications

- `P2`: The issue describes a bounded Feishu streaming usability problem without evidence of data loss, security bypass, crash loop, or unusable core runtime.
- `impact:ux-friction`: Feishu users can continue working, but live replies show avoidable progress noise and the documented hide-progress policy is not available for Feishu.

## Summary

Keep open: current main still has Feishu CardKit preview streaming wired to append progress/status text into the live card, while Feishu exposes only a boolean streaming config and does not support the shared per-channel tool-progress policy. The remaining fix requires a maintainer decision about Feishu's public config shape and the gateway config mutation boundary.

## What This Changes

The issue asks OpenClaw to stop misleading Feishu streamed previews for benign non-zero exec exits and add a Feishu-specific way to keep preview streaming while hiding or simplifying tool-progress lines.

## Best Possible Solution

Make Feishu honor the shared nested streaming preview policy with backward-compatible schema, manifest, docs, and tests for default progress, opt-out, and status-only command text; keep gateway config mutation protection unchanged unless maintainers explicitly approve a narrow allowlist change.

Options:

- **Adopt shared Feishu preview policy (recommended):** Extend Feishu to accept the shared nested streaming preview config while preserving current boolean/default behavior, and leave config.patch protection unchanged unless separately approved.
- **Only soften progress wording:** Keep Feishu boolean-only and reduce scary command failure wording, which is smaller but still leaves no Feishu way to keep streaming while hiding progress lines.
- **Allow coarse gateway toggle:** Allow agent-facing config.patch to change channels.feishu.streaming, which helps recovery but broadens an operator-controlled config path and still lacks status-only progress.

## Reproduction Assessment

Yes, source-reproducible: current Feishu enables streaming from a boolean config, wires onToolStart whenever streaming is enabled, and appends statusLine into the live CardKit preview. I did not run a live Feishu websocket deployment, so this is not a live reproduction.

## Solution Assessment

Unclear until maintainers choose the Feishu config/API shape. Reusing the shared compact progress policy is the narrowest maintainable direction found; a one-off string filter or broad config.patch allowlist change would leave policy drift or operator-boundary risk.
