## Label Justifications

## Summary

Keep open: current main partially reduces the scary command-output wording, but Feishu still has no supported way to keep streaming while hiding or status-only rendering tool-progress lines, and the remaining fix needs a maintainer config/product decision.

## What This Changes

The issue asks OpenClaw to stop Feishu streamed previews from showing misleading tool-progress failure/status lines for benign non-zero exec exits and to add a Feishu-specific way to hide tool progress while keeping streaming enabled.

## Best Possible Solution

Make Feishu honor a backward-compatible shared streaming preview policy for toolProgress and commandText, with schema, manifest, docs, and tests, while keeping the gateway mutation boundary unchanged unless maintainers explicitly approve a narrower recovery path.

Options:

- **Adopt shared Feishu preview policy (recommended):** Extend Feishu to accept the nested streaming preview config while preserving today's defaults and leave config.patch protection unchanged unless a separate security review approves it.
- **Only soften progress wording:** Keep Feishu streaming boolean-only and reduce scary command text, which is smaller but still leaves no supported way to keep streaming while hiding tool progress.
- **Allow coarse gateway toggle:** Permit gateway config.patch to change channels.feishu.streaming, which helps emergency recovery but broadens the operator mutation boundary and does not provide status-only progress.

## Reproduction Assessment

Yes, source-level: Feishu enables onToolStart progress updates whenever streaming is enabled and has no nested preview.toolProgress or commandText gate. I did not live-run a Feishu websocket deployment, so this is source-reproducible rather than live-reproduced.

## Solution Assessment

Unclear until maintainers choose the Feishu config shape. The best apparent direction is reusing the shared compact progress policy with backward-compatible defaults rather than adding a one-off string filter or broad config.patch allowlist change.
