## Label Justifications

- `impact:ux-friction`: Feishu users can continue working, but streamed replies can show avoidable progress noise and the documented hide-progress policy does not currently apply to Feishu.

## Summary

Keep open: current main still makes Feishu append tool-progress status into streaming cards while Feishu only accepts a boolean streaming config, so the hide-progress/status-only request remains unresolved and needs maintainer product direction.

## What This Changes

The issue asks OpenClaw to reduce misleading Feishu exec progress interruptions and add a supported Feishu way to keep streaming while hiding or reducing tool-progress text.

## Best Possible Solution

Make Feishu honor the shared streaming preview policy with backward-compatible schema, manifest, docs, and tests for default progress, opt-out, and status-only command text; keep gateway config mutation protection unchanged unless maintainers explicitly approve a narrower security-reviewed path.

Options:

- **Adopt shared Feishu preview policy (recommended):** Extend Feishu to accept the shared nested streaming preview config while preserving current defaults and leave config.patch protection unchanged unless a separate security review approves it.
- **Only adjust progress wording:** Keep Feishu streaming boolean-only and reduce scary non-zero exec wording, which is smaller but still leaves no way to keep streaming while hiding progress lines.
- **Allow coarse gateway toggle:** Add channels.feishu.streaming to the gateway mutation allowlist so agents can disable streaming, which helps recovery but broadens an operator-controlled config path and does not provide status-only progress.

## Reproduction Assessment

Yes, from source inspection: Feishu enables tool-start progress whenever streaming is on and appends the resulting status line into the streaming card text. I did not run a live Feishu websocket deployment, so this is source-reproducible rather than live-reproduced.

## Solution Assessment

Unclear until maintainers choose the Feishu config/API shape. Reusing the shared compact progress policy is the narrowest maintainable direction found; a one-off string filter or broad config.patch allowlist change would leave policy drift or operator-boundary risk.
