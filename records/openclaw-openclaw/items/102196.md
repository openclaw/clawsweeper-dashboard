## Label Justifications

- `P2`: This is a real Feishu streaming usability issue with bounded channel-specific blast radius and no evidence of data loss, security bypass, or unusable core runtime.
- `impact:ux-friction`: Feishu users can continue working, but streamed replies show avoidable tool-progress noise and the documented hide-progress policy does not currently apply to Feishu.

## Summary

Keep open: current main still makes Feishu streaming-card tool status unconditional when `streaming` is enabled, and Feishu still exposes only a boolean streaming config, so the Feishu opt-out/status-only request is not implemented and needs maintainer product direction.

## What This Changes

Request to stop benign exec non-zero progress from disrupting Feishu streaming cards and to add a Feishu-supported way to hide or soften tool-progress status while keeping streaming enabled.

## Best Possible Solution

Make Feishu honor the shared nested streaming preview policy with backward-compatible boolean handling, schema/manifest/docs/tests for default progress, opt-out, and status-only command text, and keep gateway config mutation protection unchanged unless maintainers explicitly approve a narrow security-reviewed allowlist change.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Feishu adopt the shared nested streaming preview policy for `streaming.preview.toolProgress` and `streaming.preview.commandText`, and should `channels.feishu.streaming` remain protected from agent-side `config.patch` writes?

Rationale: The source-level gap is clear, but the fix changes Feishu's public config shape and potentially the model-to-operator config mutation boundary, so automation should not choose the product/security contract alone.

Likely owner: xzq-xu

Owner reason: They introduced the Feishu streaming-card implementation and boolean config surface that this decision would extend.

Owner confidence: high

Options:

- **Adopt shared Feishu preview policy (recommended):** Extend Feishu to accept and honor the shared nested preview config while preserving the current boolean default, and leave gateway mutation protection unchanged unless a separate security review approves it.
- **Only soften progress wording:** Keep Feishu boolean-only and reduce raw/scary command wording, which is smaller but still leaves no supported way to keep streaming while hiding progress lines.
- **Allow coarse streaming toggle:** Add `channels.feishu.streaming` to the gateway mutation allowlist so agents can disable streaming, which helps recovery but broadens an operator-controlled config path and still does not provide status-only progress.

## Reproduction Assessment

Yes, at source level: current main wires Feishu `onToolStart` into streaming-card status whenever `streaming` is enabled and appends that status into the card text. I did not run a live Feishu websocket deployment, so this is source-reproducible rather than live-reproduced.

## Solution Assessment

Unclear until maintainers choose the Feishu config and mutation policy. Reusing the shared compact preview policy is the narrowest maintainable direction found; a one-off string filter or broad `config.patch` allowlist change would leave policy drift or operator-boundary risk.
