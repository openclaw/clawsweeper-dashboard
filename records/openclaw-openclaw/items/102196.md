## Label Justifications

- `P2`: The report describes a real Feishu streaming usability problem with bounded channel-specific blast radius and no evidence of data loss, security bypass, or unusable core runtime.
- `impact:ux-friction`: Feishu users can continue working, but streamed replies show avoidable progress noise and the documented hide-progress policy does not apply to Feishu.

## Summary

Keep open: current main has softened the shared command-output wording from the literal `Exec failed` phrase to `exit N`, but Feishu still appends tool-progress status lines into streaming cards and exposes only a boolean `streaming` setting, so the central Feishu opt-out/status-only request remains unresolved.

## What This Changes

The issue requests Feishu streaming to avoid interrupting replies with benign non-zero exec tool-progress lines and to expose a Feishu-specific way to hide or compact tool progress while keeping streaming.

## Best Possible Solution

Make Feishu honor the shared streaming preview policy with backward-compatible schema, manifest, docs, and tests for default progress, opt-out, and status-only command text; keep gateway config mutation protection unchanged unless maintainers explicitly approve a narrow allowlist change.

Options:

- **Adopt shared Feishu preview policy (recommended):** Extend Feishu to accept the shared nested streaming preview config while preserving current defaults and leave `config.patch` protection unchanged unless a separate security review approves it.
- **Only adjust progress wording:** Keep Feishu streaming config boolean-only and reduce scary non-zero exec wording, which is smaller but still leaves users without a way to keep streaming while hiding progress lines.
- **Allow coarse gateway toggle:** Add `channels.feishu.streaming` to the gateway mutation allowlist so agents can disable streaming, which helps recovery but broadens an operator-controlled config path and does not provide status-only progress.

## Reproduction Assessment

Yes from source inspection: Feishu enables `onToolStart` whenever streaming is on and appends the resulting status line into the card stream. I did not run a live Feishu websocket deployment, so this is source-reproducible rather than live-reproduced.

## Solution Assessment

Unclear until maintainers choose the Feishu config/API shape. Reusing the shared compact progress policy is the narrowest maintainable direction I found, while a one-off string filter or broad `config.patch` allowlist change would leave policy drift or operator-boundary risk.
