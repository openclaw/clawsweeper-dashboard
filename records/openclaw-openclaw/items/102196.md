## Label Justifications

- `P2`: The report describes a bounded Feishu streaming usability problem with no evidence of data loss, security bypass, or unusable core runtime.
- `impact:ux-friction`: Feishu users can continue working, but streamed replies can show avoidable progress noise and lack the documented hide-progress control used by other channels.

## Summary

Keep open: current main still leaves Feishu with a boolean-only streaming surface, appends work-tool status into streaming-card text, and has no Feishu `streaming.preview.toolProgress` or `commandText` opt-out; changing that config shape or the gateway mutation boundary needs maintainer product/security intent.

## What This Changes

The issue asks Feishu to avoid misleading exec-failure progress in streamed previews and to support hiding or compacting tool-progress lines without disabling streaming entirely.

## Best Possible Solution

Have Feishu adopt the shared nested streaming preview policy with backward-compatible defaults, tests for default/hidden/status-only tool progress, updated manifest/docs, and keep `config.patch` protection unchanged unless maintainers explicitly approve a narrow security-reviewed allowlist change.
