## Label Justifications

- `impact:ux-friction`: Feishu users can continue working, but streamed replies show avoidable progress noise and the documented hide-progress policy does not apply to Feishu.

## Summary

Keep open: current main has removed the literal `Exec failed` wording from the shared command-output progress renderer, but Feishu still renders work-tool status lines into streaming cards and only accepts boolean `streaming`, so the requested Feishu opt-out/status-only path remains unresolved and product-sensitive.

## What This Changes

Request Feishu to hide or soften confusing exec/tool-progress lines during streaming and expose a per-channel streaming preview policy without unsafe manual config edits.

## Best Possible Solution

Make Feishu honor the shared streaming preview policy with backward-compatible schema, manifest, docs, and tests for default progress, opt-out, and status-only command text; keep gateway config mutation protection unchanged unless maintainers explicitly approve a narrow allowlist change.

- **Allow coarse gateway toggle:** Add `channels.feishu.streaming` to the gateway mutation allowlist so agents can disable streaming, which helps recovery but broadens an operator-controlled config path and does not provide status-only progress.

Yes, source-level: Feishu enables `onToolStart` whenever streaming is on and appends the resulting status line into the card stream. I did not run a live Feishu websocket deployment, so this is source-reproducible rather than live-reproduced.

## Solution Assessment

Unclear until maintainers choose the Feishu config/API shape. Reusing the shared compact progress policy is the narrowest maintainable direction found; a one-off string filter or broad `config.patch` allowlist change would leave policy drift or operator-boundary risk.
