## Summary

Keep open: current main still has Feishu streaming progress coupled to the streaming-card path with only a boolean `streaming` config, so the Feishu opt-out/status-only request remains unresolved and needs maintainer product direction rather than cleanup close.

## What This Changes

The issue requests that Feishu streaming avoid disruptive/misleading exec tool-progress lines and expose a Feishu-specific way to keep streaming while hiding or reducing tool progress.

## Best Possible Solution

Make Feishu honor the shared streaming preview policy with backward-compatible schema, manifest, docs, and focused tests for default progress, opt-out, and status-only command text; keep the gateway mutation boundary unchanged unless maintainers explicitly approve a separate allowlist change.

Question: Should Feishu adopt the shared nested streaming preview policy for `streaming.preview.toolProgress` and `streaming.preview.commandText`, and should `channels.feishu.streaming` remain protected from gateway `config.patch`?

Rationale: The source-level gap is clear, but the fix changes Feishu's public config shape and may affect the model-to-operator config mutation boundary, so automation should not choose the policy unilaterally.

Likely owner: xzq-xu

Owner confidence: high

Options:

- **Adopt shared Feishu preview policy (recommended):** Extend Feishu to accept the shared nested streaming preview config while preserving current defaults and leave `config.patch` protection unchanged unless a separate security review approves it.
- **Only adjust progress wording:** Keep Feishu streaming boolean-only and reduce scary command-progress wording, which is smaller but still leaves no way to keep streaming while hiding progress lines.
- **Allow coarse gateway toggle:** Add `channels.feishu.streaming` to the gateway mutation allowlist so agents can disable streaming, which helps recovery but broadens an operator-controlled config path and does not provide status-only progress.

## Reproduction Assessment

Yes for the remaining Feishu progress/config gap: current source enables `onToolStart` whenever streaming is on, appends the status line into the streaming card, and only accepts boolean Feishu streaming config. I did not run a live Feishu deployment, and current shared command-output progress text is exit-code/status-oriented rather than the originally reported literal in every path.

## Solution Assessment

Unclear until maintainers choose the Feishu config and gateway mutation policy. Reusing the shared compact-progress preview policy looks like the narrowest maintainable end state; one-off filtering or a broad `config.patch` allowlist would leave policy drift or boundary risk.
