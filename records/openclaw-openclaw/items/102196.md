## Label Justifications

- `P2`: The report describes a bounded Feishu streaming usability problem without evidence of data loss, security bypass, crash loop, or unusable core runtime.
- `impact:ux-friction`: Feishu users can continue working, but streamed replies show avoidable progress noise and lack the documented hide-progress control available to other preview channels.

## Summary

Keep open: current main still exposes Feishu streaming as a boolean-only CardKit path, appends shared tool-progress status into the live card, and lacks the shared `preview.toolProgress` / `commandText` policy the issue asks for.

## What This Changes

The issue requests Feishu-specific handling for benign non-zero exec progress lines, a per-channel tool-progress preview toggle, and a supported way to change Feishu streaming without manual config edits.

## Best Possible Solution

Make Feishu honor the shared streaming preview policy with backward-compatible schema, manifest, docs, and tests for default progress, opt-out, and status-only command text; keep gateway config mutation protection unchanged unless maintainers explicitly approve a narrow allowlist change.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Feishu adopt the shared nested streaming preview policy for `streaming.preview.toolProgress` and `streaming.preview.commandText`, and should `channels.feishu.streaming` remain protected from gateway `config.patch`?

Rationale: The source problem is clear, but the fix changes Feishu's public config shape and may broaden the model-to-operator config mutation boundary, which needs maintainer product/security intent before implementation.

Likely owner: xzq-xu

Owner confidence: high

Options:

- **Adopt shared Feishu preview policy (recommended):** Extend Feishu to accept the shared nested streaming preview config while preserving current defaults, and leave `config.patch` protection unchanged unless separately approved.
- **Only reduce scary exec wording:** Keep Feishu boolean-only and make benign non-zero command status less alarming, but users still cannot keep streaming while hiding progress lines.
- **Allow coarse gateway toggle:** Add `channels.feishu.streaming` to the gateway mutation allowlist so agents can disable streaming, but this broadens operator-controlled config writes and does not provide status-only progress.

## Reproduction Assessment

Yes, source-reproducible: Feishu enables `onToolStart` whenever streaming is on and appends the resulting status line into the streaming card text. I did not run a live Feishu websocket deployment, so the exact user-visible timing is not live-reproduced here.

## Solution Assessment

Unclear until maintainers choose the Feishu config/API shape. Reusing the shared preview policy is the narrowest maintainable direction found; a one-off string filter or broad `config.patch` allowlist change would create policy drift or operator-boundary risk.
