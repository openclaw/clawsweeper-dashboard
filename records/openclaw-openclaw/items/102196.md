## Label Justifications

- `P2`: The issue describes a real Feishu streaming usability problem with bounded channel-specific blast radius and no evidence of data loss, security bypass, crash loop, or unusable core runtime.
- `impact:ux-friction`: Feishu users can continue working, but streamed replies show avoidable progress noise and the documented hide-progress policy does not apply to Feishu.

## Summary

Keep open: current main still has Feishu CardKit streaming controlled by a boolean-only setting, still appends transient tool-progress status into streaming cards, and still lacks the shared `toolProgress`/`commandText` preview policy available to other compact-progress channels.

## What This Changes

The issue requests Feishu streaming to avoid chat-visible benign exec progress interruptions and to expose a Feishu-specific way to hide or reduce tool-progress lines without disabling streaming.

## Best Possible Solution

Make Feishu honor the shared nested streaming preview policy with backward-compatible boolean defaults, schema/manifest/docs/tests, and live Feishu proof; keep the gateway config mutation boundary unchanged unless maintainers separately approve a narrower operator-safe toggle.

Options:

- **Adopt shared Feishu preview policy (recommended):** Extend Feishu to accept the shared nested preview config while preserving current boolean defaults, and leave `config.patch` protection unchanged unless separately reviewed.
- **Only soften progress wording:** Keep Feishu streaming boolean-only and reduce scary non-zero exec wording, which is smaller but still leaves no way to stream answers while hiding progress lines.
- **Allow coarse gateway toggle:** Allow `channels.feishu.streaming` through agent-facing `config.patch`, which helps recovery but broadens an operator-controlled config path and does not provide status-only progress.

## Reproduction Assessment

Yes, source-reproducible: with Feishu streaming enabled, `onToolStart` writes compact tool status into `statusLine`, and `buildCombinedStreamText` appends that status into the streaming card. I did not run a live Feishu websocket deployment in this read-only review.

## Solution Assessment

Unclear until maintainers choose the Feishu config and operator-boundary policy. Reusing the shared preview policy looks like the narrowest maintainable direction; a one-off string filter or broad `config.patch` allowlist change would leave policy drift or boundary risk.
