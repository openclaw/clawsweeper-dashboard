## Label Justifications

- `P2`: The issue describes a real Feishu streaming usability problem with bounded channel-specific blast radius and no evidence of data loss, security bypass, crash loop, or unusable core runtime.
- `impact:ux-friction`: Feishu users can continue working, but streamed replies show avoidable progress noise and the documented hide-progress policy does not apply to Feishu.

## Summary

Keep open: current main no longer uses the literal shared `Exec failed` command-output wording, but Feishu still streams work-tool status lines into Card Kit previews and still exposes only a boolean `streaming` config, so the Feishu opt-out/status-only request remains unresolved and needs maintainer product direction.

## What This Changes

The issue asks for Feishu streaming to avoid scary benign non-zero exec progress and to provide a supported way to keep streaming while hiding or reducing tool-progress lines.

## Best Possible Solution

Make Feishu honor the shared nested streaming preview policy with backward-compatible schema, manifest, docs, and tests for default progress, opt-out, and status-only command text; keep gateway config mutation protection unchanged unless maintainers explicitly approve a narrow security-reviewed change.

Options:

- **Adopt shared Feishu preview policy (recommended):** Extend Feishu to accept the shared nested streaming preview config while preserving current defaults, and leave `config.patch` protection unchanged unless a separate security review approves it.
- **Only reduce scary progress wording:** Keep Feishu streaming boolean-only and rely on the shared `exit N` wording, which is smaller but still leaves no way to keep streaming while hiding progress lines.
- **Allow coarse gateway toggle:** Add `channels.feishu.streaming` to the model-facing config mutation allowlist, which helps recovery but broadens operator-controlled config writes and does not provide status-only progress.

## Reproduction Assessment

Yes, at source level: Feishu enables tool-start status updates whenever streaming is on and appends the resulting status line into the Card Kit preview, while its config schema only accepts a boolean `streaming` value. I did not run a live Feishu websocket deployment.

## Solution Assessment

Unclear as a single automatic fix. A Feishu progress-toggle path appears necessary for the reported UX, but changing how non-zero exec results are labeled needs a maintainer decision because current Codex/OpenClaw contracts expose an exit code, not an expected-failure semantic.
