## Label Justifications

- `impact:message-loss`: The issue is specifically about approval notifications being misrouted to unrelated Telegram destinations.

## Summary

Keep this open as a likely multi-account Telegram approval-routing regression. Current documentation describes approval delivery that can use the originating chat or owner approver DMs, but the report’s single-request, six-account fan-out needs a source-level reproduction before deciding whether it is a routing defect or an intentionally configured shared approver route.

## What This Changes

The issue requests that an exec approval created by one agent be delivered only through that agent’s own Telegram account or originating chat, rather than fanning out to other agents’ Telegram accounts.

## Best Possible Solution

Preserve one canonical approval record while binding native Telegram delivery to the originating account and session/chat by default; retain only explicitly configured shared or out-of-band approver routes, and cover multi-account routing plus cross-route approval authorization with regression tests.
