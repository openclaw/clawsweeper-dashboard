Full review comments:

- **[P1] Preserve date-qualified SQLite reads:** `src/transcripts/store.ts:358-364`
  - body: `readUtterancesFromSessionDir` is used with a dated session directory, but the SQLite branch discards the date and queries by bare session id. If a fixed human id is reused across days, stop/summarize can mix transcript rows from multiple sessions; parse the date from the directory or pass the resolved `startedAt` into the query.
  - confidence: 0.9
- **[P1] Honor date-qualified stops in SQLite:** `src/transcripts/store.ts:461-471`
  - body: For a resolved non-active session, `stopTranscripts` passes the original selector to `updateStopped`; with a selector like `2026-07-02/standup`, this SQL compares the full selector to `session_id` and updates nothing. Preserve the resolved session identity or parse the qualified selector so stopped metadata is actually persisted.
  - confidence: 0.88
- **[P2] Wire the SQLite backend into real callers:** `src/transcripts/store.ts:143-146`
  - body: The constructor accepts a database handle, but current product callers still instantiate `TranscriptsStore` with only the file root. As written, the shared schema and backend are only tested directly and do not make `openclaw transcripts` or auto-start storage SQLite-backed; either wire the shared DB path with upgrade proof or scope this as dormant foundation work.
  - confidence: 0.86
- **[P2] Use the shared typed state DB layer:** `src/transcripts/store.ts:159-171`
  - body: The runtime CRUD path adds raw `DatabaseSync.prepare` helpers and string SQL even though the repo's SQLite runtime path is the shared typed Kysely/state DB layer. Route transcript storage through that layer so schema types, transactions, pragmas, and permission handling stay consistent.
  - confidence: 0.82
