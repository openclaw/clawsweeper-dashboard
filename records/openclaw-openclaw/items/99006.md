## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P2] Resolve directory reads by original session identity:** `src/transcripts/store.ts:389-391`
  - body: In SQLite mode this path queries `transcript_utterances.session_id` with the directory basename. `sessionDir()` uses `safeSegment()`, so a provider session id containing spaces or slashes is stored under the original id but read back with the sanitized id; the query returns no rows and then falls back to a file path that SQLite mode never wrote. Resolve the session row by date and directory identity, then query by the original `session_id`/`started_at`, with coverage for a transformed id.
  - confidence: 0.91
- **[P2] Preserve ambiguous selector errors:** `src/transcripts/store.ts:298-300`
  - body: Current file-backed behavior and CLI tests require a `YYYY-MM-DD/<session>` selector when the same session id exists on multiple dates. The SQLite path silently chooses the newest row with `ORDER BY started_at DESC LIMIT 1`, so a bare `standup` can stop or summarize the wrong transcript instead of forcing the user to disambiguate. Mirror the existing ambiguity error and add the SQLite regression case.
  - confidence: 0.93
- **[P2] Use the typed state DB helpers:** `src/transcripts/store.ts:154-160`
  - body: The new runtime backend wraps `DatabaseSync.prepare()` and raw SQL strings directly. OpenClaw runtime SQLite access is expected to go through the generated Kysely types and `executeSqliteQuerySync()`/transaction helpers, which keeps the schema contract typed and aligned with other shared-state stores. Rework this backend as a typed state-store helper instead of adding a raw SQL runtime path.
  - confidence: 0.84
