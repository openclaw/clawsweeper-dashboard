  - body: `sessionDir()` writes a safe filesystem segment, but SQLite rows keep the original `sessionId`.   - body: The file-backed store rejects bare ids when multiple dated sessions match, and the docs tell users to use the date-qualified selector. The SQLite path silently selects the newest row, so `show`, `summarize`, or `stop` can act on the wrong repeated session id after migration.
  - confidence: 0.84
- **[P2] Use the typed state DB helpers:** `src/transcripts/store.ts:159-171`
  - body: The new runtime CRUD path prepares raw SQL directly on `DatabaseSync`, bypassing the repository's typed Kysely/state DB helpers used for shared SQLite tables. Route these queries through the shared state DB layer so generated schema types, connection behavior, and future migrations stay consistent.
