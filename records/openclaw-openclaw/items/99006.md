## Summary

The latest head fixes the instance-local readiness flag and broad fallback, but it still switches production callers to SQLite before legacy meeting transcripts are durably detected and imported, so an upgrade can hide existing sessions; the PR also lacks after-fix migration and live runtime proof.

## What This Changes

The PR adds shared-state SQLite tables for meeting-capture sessions and utterances, wires production transcript callers to the database, and adds a Doctor importer for the legacy filesystem store.

## Best Possible Solution

Use one SQLite-only runtime authority guarded by a durable pending-legacy/import receipt, make `openclaw doctor --fix` perform an exclusive transactional and verified import before clearing that gate, retain only named summary artifacts on disk, and prove fresh plus upgrade behavior in a real meeting-capture setup.
