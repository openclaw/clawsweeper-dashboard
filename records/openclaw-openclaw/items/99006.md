## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Preserve date-scoped transcript identity:** `src/state/openclaw-state-schema.sql:1229`
  - body: Current docs support reusing a human session id on different days via `YYYY-MM-DD/<session>` selectors, but this schema makes `session_id` the sole primary key and `writeSession` uses `INSERT OR REPLACE`. A second same-id session would overwrite the first session metadata and merge or orphan utterance rows, so the SQLite identity needs to include the date/start/session row before merge.
  - confidence: 0.91
- **[P1] Keep SQLite summaries on the SQLite read path:** `src/transcripts/store.ts:356`
  - body: In DB mode `readSessionEntry` returns a computed `sessionDir` for a SQLite row, and existing summarize/stop flows pass that directory to `readUtterancesFromSessionDir`. This method always reads `transcript.jsonl`, so SQLite-backed sessions can summarize as empty even when utterances exist in `transcript_utterances`; return a session-aware entry or route this path back through SQLite.
  - confidence: 0.87
- **[P2] Wire the backend through the product state DB:** `src/transcripts/store.ts:143-146`
  - body: The new backend only activates when a caller passes a `DatabaseSync`, but the product transcript tool still constructs `TranscriptsStore` with just the file root. As written, merging this as a primary storage backend leaves real `openclaw transcripts` reads and writes file-backed while only tests use in-memory SQLite; either wire the shared state DB path with upgrade proof or scope this as a dormant foundation.
  - confidence: 0.9
- **[P2] Use the typed SQLite access helpers:** `src/transcripts/store.ts:159-171`
  - body: The PR adds generated DB types but the runtime store uses raw `prepare` wrappers and SQL strings for normal CRUD. Repository policy requires Kysely helpers for runtime SQLite access outside schema/bootstrap/migration primitives, so this should go through the typed state DB access path instead of adding an untyped parallel database layer.
  - confidence: 0.82
