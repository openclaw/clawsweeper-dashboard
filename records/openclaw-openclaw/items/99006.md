## Summary

The latest head still creates a split storage authority: production stores write to SQLite while their read-readiness flag is never durably enabled, and any database-open error silently returns to the retired filesystem backend. Both previously reported blockers therefore remain. Likely related people: @steipete (high confidence, recent shared-state migration owner), @jalehman (medium confidence, session/transcript SQLite flip), and @xydt-tanshanshan (high confidence, merged Web Push SQLite migration contributor).

## What This Changes

The PR adds shared-state SQLite tables, production wiring, and a Doctor importer for meeting-capture transcript metadata and utterances while retaining filesystem summary artifacts.

## Best Possible Solution

Use SQLite as the sole runtime authority, persist and verify a Doctor migration receipt or equivalent durable gate before enabling runtime access, fail closed while legacy data is pending, keep only named summary artifacts on disk, and prove both upgrade import and a live write/read/stop flow.
