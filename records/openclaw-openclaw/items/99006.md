## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Preserve date-qualified transcript identity:** `src/state/openclaw-state-schema.sql:1229`
  - body: Current transcript storage supports the same human session id on different days and requires `YYYY-MM-DD/<session>` selectors for disambiguation, but this schema makes `session_id` the sole primary key. A second `standup` session would overwrite/conflict with the first, so the SQLite path would lose the existing dated identity contract.
  - confidence: 0.94
- **[P1] Keep SQLite summaries on the SQLite read path:** `src/transcripts/store.ts:280`
  - body: When `readSessionEntry` is DB-backed it returns a computed `sessionDir`; the existing summarize flow treats any `sessionDir` as a signal to read `transcript.jsonl`. A SQLite-backed stored session would therefore ignore DB utterances and summarize an empty or stale file path.
  - confidence: 0.9
- **[P1] Wire the backend through real transcript flows:** `src/transcripts/store.ts:143-147`
  - body: The new backend only runs when a caller passes a `DatabaseSync`, but the production transcript tool and auto-start service still construct `TranscriptsStore` with only the state directory. Real start/import/stop/summarize flows continue using files, so the PR does not yet implement primary SQLite storage.
  - confidence: 0.92
- **[P2] Use the generated Kysely state database path:** `src/transcripts/store.ts:159-166`
  - body: These raw `DatabaseSync` helpers bypass the existing shared state DB lifecycle and generated Kysely query helpers, leaving the new generated table types unused and making it easier for schema drift or caller-supplied handles to miss the normal state DB guarantees.
  - confidence: 0.84
