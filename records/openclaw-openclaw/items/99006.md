## Summary

Current main still uses the filesystem meeting-transcript store, so this work remains relevant. The latest head is not safe to merge because upgraded installations switch to SQLite before legacy import completes, while database-open failures silently restore file writes and create competing transcript authorities.

## What This Changes

The PR adds two shared-state transcript tables, typed SQLite operations, production `TranscriptsStore` wiring, and a Doctor importer while retaining filesystem summaries and a runtime filesystem fallback.

## Best Possible Solution

Make shared SQLite the sole runtime authority, have an exclusive and retry-safe Doctor flow claim, import, verify, and retire legacy transcript state before runtime proceeds, retain only named summary artifacts on disk, and prove fresh-install and upgrade capture/read behavior.
