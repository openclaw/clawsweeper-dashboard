## Summary

Keep open: the SQLite direction is aligned, but the current head still switches to SQLite before legacy transcript import and silently falls back to filesystem storage when the database cannot open. Both behaviors can split or hide durable meeting-transcript state.

Likely related people: `jalehman` for the adjacent canonical session-storage flip, `xydt-tanshanshan` for the merged Web Push SQLite migration, and `steipete` for the recent APNs SQLite migration; confidence is medium because ownership is shared across storage surfaces.

## What This Changes

The PR adds shared-SQLite meeting-transcript tables, production `TranscriptsStore` wiring, and a Doctor importer while retaining filesystem summary artifacts.

## Best Possible Solution

Make shared SQLite the sole meeting-transcript runtime authority, refuse reads and writes while legacy transcript data is pending, and use an exclusive, retry-safe, verified `openclaw doctor --fix` import before enabling runtime access.
