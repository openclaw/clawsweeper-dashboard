## Summary

Keep open. Current main still has a Mistral Medium 3.5 id mismatch in the simple Mistral adapter, so a documented reasoning-capable model can map a simple reasoning request to `promptMode` instead of `reasoningEffort`.

## What This Changes

The issue asks OpenClaw to preserve Mistral prompt/reasoning request options when the selected Mistral model supports them.

## Best Possible Solution

Fix the Mistral simple-stream id/capability mapping so documented adjustable-reasoning models send `reasoningEffort`, keep unsupported models guarded, and add focused payload regression coverage.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, source-level. On current main, a `mistral-medium-3-5` model with `reasoning: true` and simple `reasoning: high` makes `usesReasoningEffort` return false, so `streamSimpleMistral` selects `promptMode` instead of `reasoningEffort`.

## Solution Assessment

Yes. The narrow maintainable fix is to align the direct Mistral helper with the documented/catalog model id and add regression coverage, not to forward reasoning fields unconditionally for unsupported models.
