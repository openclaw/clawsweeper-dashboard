## Summary

This PR needs one compatibility repair before merge. The previous attached-session custom-UA blocker is fixed and the real-Chrome proof is strong, but screenshot activation still uses the configured profile default rather than the managed Chrome process’s effective launch mode, so supported request-level headless overrides can invert the focus/availability decision.

## What This Changes

The PR passes managed-browser headless state into direct-CDP screenshot capture, skips implicit tab activation only for confirmed headed managed profiles, and adds focused activation tests.

## Best Possible Solution

Expose the effective running managed-browser headless mode through the profile runtime context and carry that prepared fact into screenshot capture; use `undefined` for attached or otherwise unowned sessions, preserve the current activation fallback, and cover both override directions.
