## Summary

The prior blocker is only partially resolved: managed browsers now use authoritative launch state and the real-behavior proof is strong, but attached headless sessions with a custom non-headless user agent can still be misclassified and lose the activation that prevents background screenshot timeouts.

## What This Changes

The PR makes direct-CDP screenshot activation conditional on managed launch mode or attached-session user-agent detection and adds focused headed, headless, and unavailable-detection coverage.

## Best Possible Solution

Use authoritative managed launch state, and for attached sessions skip activation only when a trustworthy runtime signal positively confirms headed mode; otherwise preserve the conservative activation default.
