## Summary

Keep this PR open, but do not merge it as written: the reported focus regression is valid, while the proposed headed-mode test can misclassify headless Chrome and reintroduce screenshot stalls; the PR also lacks real-browser after-fix proof.

## What This Changes

The PR queries `Browser.getVersion` before direct-CDP screenshots, skips `Page.bringToFront` when the returned user agent appears headed, and adds mocked headed, headless, and unavailable-detection tests.

## Best Possible Solution

Carry authoritative effective launch mode from the managed-browser lifecycle into screenshot execution, activate for headless or unknown sessions, and skip activation only for authoritatively headed sessions, with live headed and headless proof plus a custom-user-agent regression case.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Current main always sends `Page.bringToFront` before direct-CDP capture, so a headed two-tab browser activates the background target; the patch defect is also source-reproducible with headless mode plus a normal `--user-agent` override.

## Solution Assessment

No. User-agent branding is not authoritative runtime headless state because Chromium returns command-line user-agent overrides, so this implementation can remove required activation from a headless session.
