## Summary

Keep open: current main and the latest release still route ordinary channel agent turns through the shared `main` lane, and browser/per-channel isolation remains a product and scheduler-design decision.

## What This Changes

Request dedicated browser or per-channel/workload lane routing so long browser automation does not starve fast channel replies.

## Best Possible Solution

Define a default-compatible opt-in scheduler policy that isolates slow browser/workload/channel turns while preserving shared `main` defaults, aggregate caps, docs, and regression tests.

Options:

- **Design unified opt-in lane policy (recommended):** Keep shared `main` as the default, add maintainer-approved workload/channel/agent lane routing with aggregate caps, and require docs plus regression coverage.
- **Fold into per-agent lanes:** Treat this as a browser-heavy use case under https://github.com/openclaw/openclaw/issues/43235 and defer browser/per-channel routing until per-agent isolation proves insufficient.
- **Use fairness without new lane config:** Avoid a new lane config surface for now and instead pursue foreground reserves, priority aging, or preemption so fast user turns stay responsive on shared lanes.
