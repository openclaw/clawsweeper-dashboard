## Summary

Keep open: current main and the latest release still route ordinary channel agent turns through the shared main lane, while browser/per-channel isolation would add new scheduler and config semantics that need maintainer product direction.

## What This Changes

The issue requests a dedicated browser lane or per-channel lane routing so long browser automation cannot monopolize the shared main agent lane.

## Best Possible Solution

Define a default-compatible scheduler policy for workload/channel isolation, including lane naming, aggregate caps, fallback behavior, docs, and regression coverage for fast text turns staying responsive while browser-heavy turns are active.
