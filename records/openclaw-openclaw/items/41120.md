## Summary

Keep open: current main and v2026.6.11 still route ordinary channel agent turns through the shared main lane, while browser/per-channel isolation would add new scheduler and config semantics that need maintainer product direction.

## What This Changes

The issue requests browser-specific or per-channel lane routing so long browser automation turns do not consume all shared main-lane capacity for quick channel replies.

## Best Possible Solution

Define a default-compatible scheduler policy for workload/channel isolation, including lane naming, aggregate caps, routing ownership, fallback behavior, docs, and regression coverage for fast text turns staying responsive while browser-heavy turns are active.
