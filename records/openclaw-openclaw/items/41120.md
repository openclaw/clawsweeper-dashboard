## Summary

Keep open: current main and v2026.6.11 still route ordinary non-cron embedded runs through the shared `main` global lane, with no browser, workload, or per-channel lane routing surface; the open per-agent lane issue overlaps but does not fully own this browser/workload routing decision.

## What This Changes

Request dedicated browser/workload or per-channel lane routing so long browser automation no longer occupies all shared main-lane capacity for fast channel replies.

## Best Possible Solution

Design one server-owned scheduler/concurrency model that derives trusted workload, channel, or agent lanes from config, preserves an aggregate resource cap, and updates schema, docs, tests, and upgrade behavior together.
