## Summary

Keep open: current main and v2026.6.11 still route ordinary channel-originated agent turns through the shared main lane, and the requested browser/per-channel isolation needs a maintainer-owned scheduler and config decision rather than cleanup closure.

## What This Changes

The issue requests browser-specific or per-channel command-lane routing so long browser automation does not starve fast messaging-channel replies.

## Best Possible Solution

Define a default-compatible scheduler policy for workload/channel isolation, including lane naming, aggregate caps, fallback behavior, docs, and regression coverage for fast text turns staying responsive while browser-heavy turns are active.
