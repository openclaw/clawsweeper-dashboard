## Summary

Keep open: current main and v2026.6.11 still route ordinary non-cron embedded agent work through a per-session lane and then the shared `main` global lane, so the browser/workload or per-channel lane-isolation request remains unresolved and needs maintainer scheduler/config direction.

## What This Changes

The issue requests a dedicated browser/workload lane or per-channel lane routing so long browser automation does not occupy all shared main-lane slots for ordinary channel replies.

## Best Possible Solution

Design one core scheduler/concurrency model that isolates slow workload classes or channel/agent groups while preserving global resource caps, schema/docs consistency, and upgrade-safe defaults.

## Reproduction Assessment

Yes at source level for the contention shape: current non-cron embedded runs still use a per-session lane plus shared `main` global lane by default. I did not run a live browser-heavy multi-channel reproduction.

## Solution Assessment

Unclear: dedicated browser lanes and per-channel routing are plausible, but maintainers need to choose the public scheduler/config model rather than landing a one-off lane knob.
