## Summary

Keep open: current main and v2026.6.11 still route ordinary browser-heavy channel turns through the shared `main` global lane, so the central request remains a scheduler/config product decision rather than conservative cleanup.

## What This Changes

Request dedicated browser/workload or per-channel lane routing so slow browser automation does not consume all shared main-lane capacity needed for fast channel replies.

## Best Possible Solution

Design one server-owned scheduler model for slow workload, channel, or agent-group isolation with aggregate caps, upgrade-safe defaults, schema/help/docs alignment, and focused fresh-config plus upgrade tests.
