## Summary

Keep open: current main and v2026.6.11 still route ordinary non-cron channel turns through the shared `main` global lane, and the remaining work is a scheduler/config product decision rather than a narrow automatic bug fix.

## What This Changes

Request to isolate slow browser-heavy channel workloads from the shared main command lane with a dedicated browser lane or per-channel/workload lane routing.

## Best Possible Solution

Design one server-owned scheduler model that isolates slow workload classes or channel/agent groups while preserving a clear aggregate resource cap, upgrade-safe defaults, schema/docs alignment, and tests for fresh-install and existing-config behavior.
