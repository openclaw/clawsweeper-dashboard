## Summary

Keep open: current main and the latest release still route ordinary channel agent turns through the shared main lane, while browser/per-channel lane isolation would add public scheduler and config semantics that need maintainer direction.

## What This Changes

Add dedicated browser or per-channel/workload lane routing so long browser automation no longer consumes all shared main-lane slots needed by fast channel replies.

## Best Possible Solution

Define a default-compatible scheduler policy for workload/channel isolation, including trusted lane naming, aggregate caps, fallback behavior, docs, and regression coverage proving fast text turns stay responsive while browser-heavy turns are active.
