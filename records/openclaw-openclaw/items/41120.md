## Summary

Keep open: current main and latest release still route ordinary browser-heavy channel turns through the shared `main` global lane, and the remaining work is a public scheduler/config product decision rather than conservative cleanup.

## What This Changes

The issue asks for dedicated browser, per-channel, or workload-classified command-lane routing so slow browser automation does not starve fast channel replies.

## Best Possible Solution

Design one server-owned scheduler model for slow workload, channel, or agent-group isolation with aggregate caps, upgrade-safe defaults, schema/docs alignment, and focused tests for existing and fresh configs.
