## Summary

Keep this issue open. Current `main` documents the new `memory.search` shape and its configuration reference identifies the same canonical path, while released-package documentation still shows the older `agents.defaults.memorySearch` shape; that makes the reported validation failure plausible for an installed release and leaves a user-facing docs/versioning mismatch to resolve.

## What This Changes

Update the builtin-memory documentation so its provider configuration example matches the configuration schema available to users of the current released package.

## System Context

The public memory documentation tells users how to configure embedding-backed `memory_search`. That configuration is validated by the installed OpenClaw release, while the docs site is published from current source, so a schema rename can expose unreleased configuration to stable users.

## Best Possible Solution

Choose a release/docs compatibility policy, then make the public memory pages unambiguous: either publish release-versioned configuration examples or clearly label `memory.search` as requiring the release that contains its schema migration and retain the stable-release example until then.
