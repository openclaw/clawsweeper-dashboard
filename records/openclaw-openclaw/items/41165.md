## Summary

Keep open: current main and v2026.6.11 still resolve event-provided heartbeat wake session keys before explicit `heartbeat.session`, while Telegram DMs still intentionally default to the main session unless `session.dmScope` is configured.

## What This Changes

The issue requests preventing Telegram direct-message traffic and event-triggered heartbeats from polluting the agent main or configured heartbeat session.

## Best Possible Solution

Land a maintainer-approved heartbeat precedence fix where explicit `heartbeat.session` wins for event-triggered wakes, then decide Telegram DM default isolation separately with docs and regression coverage.
