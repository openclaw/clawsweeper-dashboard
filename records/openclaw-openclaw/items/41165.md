## Summary

Keep open: current main and v2026.6.11 still allow wake-provided session keys to win before `heartbeat.session`, and direct DM routing still defaults to `agent:main:main` unless configuration or route bindings isolate it. The linked fork PR with closing syntax is open but conflicting, so there is no landed canonical fix to close against.

## What This Changes

The issue reports Telegram DM and heartbeat wake routing can reuse `agent:main:main`, mixing ordinary DM conversation with heartbeat/main-session context instead of keeping those sessions isolated.

## Best Possible Solution

Land or adopt a narrow fix where explicit `heartbeat.session` wins over wake-provided session keys with event-migration coverage, and separately decide whether Telegram main-scoped DMs should remain a compatibility default or migrate to `per-channel-peer`.
