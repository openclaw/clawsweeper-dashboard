## Summary

Keep open: current main and v2026.6.11 still let a system-event heartbeat wake use the originating session before honoring explicit `heartbeat.session`, so the reported session contamination remains source-reproducible. The broader request to isolate Telegram DMs by default is compatibility-sensitive because current docs and tests define main-session DM sharing as the default.

## What This Changes

The issue asks OpenClaw to stop Telegram DM and system-event heartbeat routing from polluting `agent:main:main` when a configured heartbeat session should own the run.

## Best Possible Solution

Land a narrow maintainer-approved heartbeat fix that makes explicit `heartbeat.session` win for system-event and exec wakes, while keeping Telegram DM default isolation as a separate documented product decision or `session.dmScope` guidance.
