## Summary

Keep open: current main and the latest release still let a forced/event-provided heartbeat session key win before configured `heartbeat.session`, and current docs/tests confirm Telegram DMs may still intentionally collapse to `agent:<agent>:main` under `session.dmScope: "main"`. The issue is not implemented on main; the linked cross-repository fix PR is open, unmerged, and conflicting, so it is a review/adoption candidate rather than close proof.

## What This Changes

The issue requests strict isolation between Telegram direct-message sessions and heartbeat/main sessions so ordinary DM traffic and heartbeat/system-event traffic cannot pollute each other.

## Best Possible Solution

Land or adopt a narrow fix that makes explicit heartbeat session configuration outrank event-origin session keys and preserves queued event delivery semantics, while treating any change to Telegram DM default isolation as a separate maintainer product decision with migration/docs proof.
