## Label Justifications

- `P1`: The issue reports a real channel/heartbeat workflow where session routing pollution can mix user DMs with heartbeat context and disrupt heartbeat delivery.
- `impact:session-state`: The core failure is session/context contamination between `agent:main:main`, heartbeat, and Telegram direct-message sessions.

## Summary

Keep open: current main and the latest release still let an exec-event forced session key win before explicit `heartbeat.session`, so the later heartbeat-in-DM reproduction is not implemented on main; the Telegram DM default isolation part remains a compatibility/product decision rather than a cleanup close.

## What This Changes

The issue asks for Telegram DM and heartbeat session routing to stay isolated so direct-chat traffic and heartbeat work cannot pollute `agent:main:main` or each other.

## Best Possible Solution

Keep this issue open and land a narrow maintainer-approved fix that makes explicit `heartbeat.session` win for system-event-triggered heartbeats, with event migration/restoration tests, while leaving broader per-session heartbeat scheduling to https://github.com/openclaw/openclaw/issues/60275.
