## Summary

Keep open: current main and the latest release still let event-triggered heartbeat wakes resolve an originating session before an explicit heartbeat session, and default Telegram DM isolation remains an unresolved product-compatibility decision with an open fork PR candidate.

## What This Changes

The issue asks OpenClaw to prevent Telegram DM and heartbeat/session routing from polluting `agent:main:main`, especially when `heartbeat.session` or per-DM isolation should keep traffic separate.

## Best Possible Solution

Land a maintainer-approved narrow heartbeat wake repair that lets explicit `heartbeat.session` win for system-event wakes, then decide Telegram default DM isolation separately across channel policy, docs, and upgrade expectations.
