## Summary

Keep open: current main still resolves an event/wake-provided session before explicit `heartbeat.session`, and the Telegram DM default-isolation part is a compatibility-sensitive product decision rather than a landed fix. The open fork PR at https://github.com/BingqingLyu/openclaw/pull/1542 is an implementation candidate, not a reason to close this issue before a mergeable repair lands.

## What This Changes

The issue asks OpenClaw to prevent Telegram direct-message traffic and system-event-triggered heartbeat runs from polluting each other’s sessions.

## Best Possible Solution

Land a maintainer-approved heartbeat wake repair that makes explicit `heartbeat.session` win for system-event-triggered wakes, then handle Telegram default DM isolation through a separate compatibility decision with docs and tests.
