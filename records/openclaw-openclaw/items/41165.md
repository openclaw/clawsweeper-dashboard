## Label Justifications

- `P1`: The issue affects real Telegram plus heartbeat users with session contamination, token waste, and reported swallowed heartbeat delivery.
- `impact:session-state`: The central failure is cross-contamination between heartbeat/main sessions and Telegram direct-message sessions.

## Summary

Keep open: current main and the latest release still route event-provided heartbeat wake session keys before configured `heartbeat.session`, and Telegram direct messages still default to the agent main session unless `session.dmScope` isolates them. The linked fork PR is open but conflicting, so it is an implementation candidate to review rather than proof that this issue is fixed.

## What This Changes

The issue reports Telegram DM and event-triggered heartbeat routing can reuse or pollute `agent:main:main` instead of respecting isolated DM or configured heartbeat sessions.

## Best Possible Solution

Land a maintainer-approved fix that makes explicit `heartbeat.session` win for event-triggered wakes and preserves pending system events without cross-session pollution, then decide Telegram default DM isolation separately with docs and regression coverage.
