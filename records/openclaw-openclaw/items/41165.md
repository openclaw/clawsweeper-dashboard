## Label Justifications

- `P1`: The issue affects real Telegram plus heartbeat workflows by mixing sessions and potentially suppressing or misrouting heartbeat delivery.
- `impact:session-state`: The central failure is contamination between heartbeat/main and Telegram direct-message session contexts.
- `impact:message-loss`: A confirming report says heartbeat delivery to Telegram was silently swallowed until polluted session state was manually cleaned.

## Summary

Keep open: current main and the latest release still let a wake-provided session key win before explicit `heartbeat.session`, matching the reported heartbeat-in-DM pollution path. The issue should stay open while maintainers review the narrow heartbeat fix path and separately decide whether Telegram DMs should stop defaulting to the main session.

## What This Changes

The issue reports Telegram DM traffic and heartbeat/system-event traffic sharing or contaminating the wrong agent session instead of respecting isolated session routing.

## Best Possible Solution

Land or adapt a narrow fix that makes explicit `heartbeat.session` win for system-event-triggered heartbeats, then handle Telegram DM default isolation as a separate compatibility decision with docs and regression coverage.
