## Summary

Keep open: current main and v2026.6.11 still resolve a wake-provided session key before an explicit `heartbeat.session`, and Telegram DMs still default to the main session unless `session.dmScope` is configured. The same-repository fix PR is closed unmerged and the fork candidate is open but conflicting, so there is no landed canonical fix to close against.

## What This Changes

The issue reports Telegram direct messages and event-triggered heartbeat runs sharing or overriding main/heartbeat session context, polluting `agent:main:main` and sometimes swallowing heartbeat delivery.

## Best Possible Solution

Land a maintainer-approved fix that makes explicit `heartbeat.session` win for event-triggered wakes and handles pending system events without cross-session pollution, then decide Telegram DM default isolation separately with docs and regression coverage.

- **Bundle Telegram isolation:** Change Telegram DMs to isolate by default as part of this issue, accepting the upgrade and documentation impact for users relying on main-session continuity.
- **Defer to heartbeat entries:** Hold this behind native per-session heartbeat scheduling, which may be cleaner long term but leaves the current forced-session contamination path unresolved longer.

Yes. Source inspection shows exec and notification wake paths pass a session key into heartbeat, and `resolveHeartbeatSession` returns that forced session before evaluating `heartbeat.session`; I did not run a live Telegram heartbeat repro in this read-only review.

## Solution Assessment

No. Closing now is not the best solution because current main and the latest release still preserve forced-session precedence and documented Telegram DM-to-main defaults; the maintainable path is a heartbeat precedence fix plus a separate compatibility decision for Telegram DM defaults.
