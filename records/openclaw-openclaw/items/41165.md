## Label Justifications

- `P1`: The issue affects real Telegram plus heartbeat users with session contamination, token waste, and reported swallowed heartbeat delivery.
- `impact:session-state`: The central failure is cross-contamination between heartbeat/main sessions and Telegram direct-message or configured heartbeat sessions.

## Summary

Keep open: current main and the latest release still let an event-provided forced heartbeat session win before `heartbeat.session`, while the requested Telegram DM isolation would change the documented default main-session behavior. A narrower `dmScope=main` event-routing bug was fixed by a merged PR, but that does not fully close this report.

## What This Changes

The issue requests strict isolation between Telegram direct-message sessions and heartbeat/main sessions so DMs and event-triggered heartbeats cannot pollute each other's transcript context.

## Best Possible Solution

Land a maintainer-approved current-main fix that makes explicit `heartbeat.session` win for event-triggered wakes without losing pending system events, and handle Telegram DM default isolation as a separate compatibility decision with docs and regression coverage.
