## Label Justifications

- `P1`: The report describes a real channel/session routing bug that can pollute active sessions and suppress or misroute heartbeat delivery for Telegram users.
- `impact:session-state`: The central failure is conversation and heartbeat traffic entering the wrong session context.
- `impact:message-loss`: A confirmed commenter observed outbound heartbeat delivery being silently swallowed until the polluted session entry was manually removed.

## Summary

Keep open: current `main` and the latest release still resolve event-provided heartbeat session keys before `heartbeat.session`, and unset Telegram DM scope still falls back to the agent main session. The same-repo fix PRs that targeted these paths are closed unmerged, so there is no landed canonical fix to close against.

## What This Changes

The issue reports Telegram direct messages and event-triggered heartbeats sharing the wrong session, polluting `agent:main:main` or active DM sessions instead of keeping Telegram DMs and heartbeat sessions isolated.

## Best Possible Solution

Review or adopt a narrow heartbeat session-routing fix that gives configured heartbeat sessions clear precedence for event wakes, then make a separate maintainer decision on any default Telegram DM isolation change with upgrade proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should this fix only make event-triggered heartbeats honor configured heartbeat sessions, or should it also change Telegram's default DM session isolation away from the current `main` fallback?

Rationale: The heartbeat.session precedence bug is a narrow existing-behavior fix, but changing default Telegram DM isolation can alter existing users' shared-session setups and needs explicit product/compatibility intent.

Likely owner: Peter Steinberger

Owner reason: Most connected by history to both unified heartbeat behavior and routing/session defaults.

Owner confidence: medium

Options:

- **Fix heartbeat precedence first (recommended):** Land a reviewed version of the heartbeat session-priority and event-migration fix, while leaving default Telegram DM isolation unchanged until a separate compatibility plan exists.
- **Change Telegram DM default too:** Move default Telegram DMs to isolated session keys, but require doctor/docs/upgrade proof for users who relied on shared main sessions.
- **Document current setup only:** Treat onboarding's `per-channel-peer` default as sufficient and leave existing explicit `main` configurations to opt into shared behavior, accepting the remaining edge cases.

## Reproduction Assessment

No live high-confidence repro was run in this read-only review. Source inspection does show the reported preconditions on current main: event-provided session keys can win over `heartbeat.session`, and unset DM scope still routes direct DMs to the main session.

## Solution Assessment

No, the issue should not be closed or treated as solved by the current implementation. The best fix is a narrow heartbeat routing repair plus an explicit maintainer decision before changing Telegram's default DM isolation semantics.
