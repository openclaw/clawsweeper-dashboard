## Summary

Keep open: current main has a partial event-routing fix for single-owner `dmScope=main`, but forced heartbeat wake session keys still resolve before an explicit `heartbeat.session`, so the configured-session contamination path remains unresolved.

## What This Changes

The issue asks for Telegram direct-message and heartbeat session routing to stay isolated so normal DMs and event-triggered heartbeat runs cannot pollute `agent:main:main` or a configured heartbeat session.

## Best Possible Solution

Land a maintainer-approved heartbeat wake fix that makes explicit `heartbeat.session` win for event-triggered runs and handles pending system events safely; decide Telegram DM default isolation separately with docs and upgrade coverage.

- **Defer to native heartbeat entries:** Wait for the broader per-session heartbeat scheduling design, which may be cleaner but leaves the current precedence bug unresolved longer.
