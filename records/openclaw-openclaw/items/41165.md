## Summary

Keep open: current main and the latest release still resolve non-subagent heartbeat wake session keys before explicit `heartbeat.session`, and default-account Telegram DMs still share the main session unless `session.dmScope` isolates them. A linked fix candidate exists but is open in a fork, conflicting, and still needs maintainer direction on the compatibility-sensitive routing contract.

## What This Changes

The issue reports Telegram DM and heartbeat traffic sharing or overriding session routing so direct-message and heartbeat context can pollute each other.

## Best Possible Solution

Land or replace the linked work with a focused fix where explicit `heartbeat.session` wins over event wake session keys, with regression coverage for exec-triggered heartbeats and separate maintainer approval for any Telegram DM default-scope change.
