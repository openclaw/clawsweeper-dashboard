## Label Justifications

- `P1`: The issue affects real Telegram plus heartbeat users with session contamination, token waste, and reported swallowed heartbeat delivery.

## Summary

Keep open: current main still resolves event-triggered heartbeat wake session keys before explicit `heartbeat.session`, and Telegram DMs still default to the main session unless `session.dmScope` is configured. The same-repo fix PR was closed unmerged, and the fork copy is conflicting, so there is no landed canonical fix to close against.

## What This Changes

The issue asks OpenClaw to prevent Telegram direct-message traffic and event-triggered heartbeats from sharing or polluting the main heartbeat session.

## Best Possible Solution

Land a maintainer-approved fix that makes explicit `heartbeat.session` win for event-triggered wakes and preserves or migrates pending system events without cross-session pollution, then decide Telegram DM default isolation separately with docs and regression coverage.

No, closing now is not the best solution. The maintainable path is a heartbeat precedence fix with event migration coverage, plus a separate compatibility decision for Telegram DM defaults.
