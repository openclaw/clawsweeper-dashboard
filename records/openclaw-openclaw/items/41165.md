## Summary

Keep open: current main and the latest release still let exec-event heartbeat wakes resolve the originating forced session before an explicit heartbeat session, while Telegram DM default isolation remains a compatibility/product decision.

## What This Changes

The issue requests Telegram DM and heartbeat/system-event routing isolation so ordinary Telegram traffic cannot pollute heartbeat/main session context.

## Best Possible Solution

Land a narrow maintainer-approved fix that makes explicit `heartbeat.session` win for system-event-triggered heartbeats, with safe event migration/restoration coverage, and track Telegram DM default isolation separately if maintainers want to change that compatibility behavior.
