## Label Justifications

- `P1`: The issue affects real Telegram plus heartbeat users with session contamination, token waste, and reported swallowed or misrouted heartbeat delivery.
- `impact:session-state`: The central failure is cross-contamination between heartbeat/main sessions and Telegram direct-message or event-origin sessions.

## Summary

Keep open: current main and the latest release still let event-provided wake session keys win before an explicit `heartbeat.session`, while Telegram DMs still intentionally default to the agent main session unless `session.dmScope` is configured. The linked implementation candidate is open but conflicting, so this is not safe to close as fixed.

## What This Changes

The issue reports Telegram DM and heartbeat session routing contamination, where direct-message or event-triggered heartbeat traffic can land in the wrong session and pollute `agent:main:main`.

## Best Possible Solution

Land a maintainer-approved fix that makes explicit `heartbeat.session` win for event-triggered wakes and prevents pending system events from polluting the originating conversation, then handle Telegram DM default isolation as a separate compatibility/docs decision.

## Maintainer Decision

Question: Should maintainers split the remaining work into a heartbeat wake precedence bugfix first, or also change Telegram DMs away from the documented default main-session behavior?

Rationale: The heartbeat precedence path is a concrete bug, but changing Telegram's default DM session behavior would alter documented compatibility for existing users who rely on main-session continuity.

Likely owner: steipete

Owner confidence: medium

Options:

- **Split Heartbeat Precedence First (recommended):** Fix event-triggered heartbeat routing so explicit `heartbeat.session` wins, while keeping Telegram DM defaults controlled by existing `session.dmScope` until a separate decision.
- **Bundle Telegram DM Isolation:** Change Telegram DMs to isolate by default as part of this issue, accepting the upgrade and documentation impact for users relying on main-session sharing.
- **Defer To Native Heartbeat Entries:** Hold this behind the broader native per-session heartbeat scheduling design, which may be cleaner long term but leaves the current forced-session contamination path unresolved longer.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: exec and notification wakes carry a session key into the heartbeat runner, and `resolveHeartbeatSession()` resolves that forced key before `heartbeat.session`. I did not run a live Telegram heartbeat repro in this read-only review.

## Solution Assessment

No, closing now is not the best solution because current main and the latest release still preserve the implicated precedence and documented Telegram DM default. The maintainable path is a heartbeat precedence fix plus a separate compatibility decision for Telegram DM defaults.
