## Summary

Keep open: current main and the latest release still let event-provided heartbeat wake session keys resolve before explicit `heartbeat.session`, while default DM-to-main routing remains documented/configurable and an open conflicting fork PR owns a candidate fix.

## What This Changes

The issue requests preventing Telegram DMs and event-triggered heartbeats from polluting `agent:main:main` or another wrong session, preserving heartbeat and direct-message session isolation.

## Best Possible Solution

Land or adopt a narrow fix that makes explicit `heartbeat.session` win for event-triggered wakes and safely handles pending system events, then decide Telegram default DM isolation separately with docs and regression coverage if maintainers want that compatibility change.
