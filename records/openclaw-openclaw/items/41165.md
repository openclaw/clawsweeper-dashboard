## Summary

Keep open: current main and the latest release still resolve event-provided wake session keys before `heartbeat.session`, and Telegram DMs still default to the agent main session unless `session.dmScope` is configured. The linked fork PR is open but conflicting, so there is no landed canonical fix to close against.

## What This Changes

The issue asks for Telegram DM and heartbeat/session routing isolation so ordinary DMs cannot pollute `agent:main:main` or configured heartbeat sessions.

## Best Possible Solution

Land a maintainer-approved fix that makes explicit `heartbeat.session` win for event-triggered wakes and handles pending system events without cross-session pollution, then decide Telegram DM default isolation separately with docs and regression coverage.
