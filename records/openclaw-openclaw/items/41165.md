## Summary

Keep open: current main still has a source-level path where exec/system-event heartbeat wakes carry an originating session key that is resolved before explicit `heartbeat.session`, and Telegram DMs still default to the main session unless `session.dmScope` is configured. The issue has an open fork PR with closing syntax, but the remaining landing path needs maintainer review because the narrow heartbeat precedence bug overlaps a compatibility-sensitive Telegram DM default-routing decision.

## What This Changes

The issue asks OpenClaw to keep Telegram DM traffic and heartbeat/main sessions isolated, especially when event-triggered heartbeats and explicit `heartbeat.session` are involved.

## Best Possible Solution

Land a maintainer-approved heartbeat precedence fix so explicit `heartbeat.session` wins for system-event-triggered wakes, then decide Telegram DM default isolation separately with compatibility, docs, and regression coverage.
