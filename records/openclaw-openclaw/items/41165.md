## Summary

## What This Changes

The issue reports Telegram DM and heartbeat/session routing pollution where ordinary Telegram traffic or exec-event-triggered heartbeat work can reuse the wrong persistent session instead of staying isolated from `agent:main:main`.

## Best Possible Solution

Refresh or replace the linked PR with a main-based fix that makes explicit `heartbeat.session` win for wake-triggered heartbeat runs, with focused regression coverage for exec-event/system-event wakes, while treating Telegram DM default isolation as a separate product/compatibility decision.
