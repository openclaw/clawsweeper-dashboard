## Summary

Keep open: current main and the latest release still let exec/system-event heartbeat wakes carry an originating session key that wins before explicit `heartbeat.session`, while Telegram DMs still default to the main session unless `session.dmScope` isolates them. The remaining work needs maintainer direction because the narrow heartbeat precedence bug overlaps a compatibility-sensitive Telegram DM default-routing decision.

## What This Changes

The issue requests strict isolation between Telegram DM sessions and heartbeat/main sessions so Telegram traffic cannot pollute `agent:main:main` or configured heartbeat sessions.

## Best Possible Solution

Land a maintainer-approved heartbeat precedence fix so explicit `heartbeat.session` wins for system-event-triggered wakes, then decide Telegram DM default isolation separately with compatibility, docs, and regression coverage.
