## Label Justifications

- `P1`: The issue affects real Telegram plus heartbeat users with session contamination, token waste, and reported swallowed heartbeat delivery.
- `impact:session-state`: The central failure is cross-contamination between heartbeat/main sessions and Telegram direct-message sessions.
- `impact:message-loss`: A confirming report says heartbeat delivery to Telegram was silently swallowed until polluted session state was manually cleared.

## Summary

Keep open: current main and v2026.6.11 still allow event-provided heartbeat wake session keys to resolve before an explicit `heartbeat.session`, while Telegram DMs still intentionally default to the agent main session unless `session.dmScope` is changed. The related same-repository fix PR is closed unmerged, and the visible fork continuation is open but conflicting, so there is no landed canonical fix to close against.

## What This Changes

The issue reports Telegram DM and heartbeat/system-event traffic sharing or overriding session keys, causing `agent:main:main` or active DM sessions to receive unrelated heartbeat/user context.

## Best Possible Solution

Land a maintainer-approved fix that makes explicit `heartbeat.session` win for event-triggered wakes and preserves or migrates pending system events without cross-session pollution, then handle any change to Telegram's default DM isolation as a separate compatibility decision with docs and tests.

Options:

- **Split Heartbeat Precedence First (recommended):** Fix explicit `heartbeat.session` precedence and event migration/restore behavior now, and leave Telegram DM default isolation to a separate docs-backed product decision.
- **Bundle Telegram Isolation:** Change Telegram private DMs to isolate by default as part of this issue, accepting upgrade, docs, and migration review for users relying on main-session continuity.
- **Defer To Native Heartbeat Entries:** Wait for a broader per-session heartbeat scheduling design, which may be cleaner long term but leaves the current forced-session contamination path unresolved longer.

Yes. Source inspection shows exec-event wakes can forward an originating session key into `runHeartbeatOnce()`, and `resolveHeartbeatSession()` resolves that forced key before explicit `heartbeat.session`; I did not run a live Telegram reproduction in this read-only review.
