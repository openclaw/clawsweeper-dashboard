## Label Justifications

- `P1`: The issue affects real Telegram plus heartbeat users with session contamination, token waste, and reported swallowed heartbeat delivery.
- `impact:session-state`: The central failure is cross-contamination between heartbeat/main sessions and Telegram direct-message sessions.

## Summary

Keep open: current main and the latest release still resolve event-provided heartbeat wake session keys before explicit `heartbeat.session`, while Telegram DMs still default to the agent main session unless `session.dmScope` or a binding isolates them. The linked fix attempt is unmerged/conflicting, so there is no landed implementation to close against.

## What This Changes

The issue requests strict isolation between Telegram direct-message sessions and heartbeat/main sessions so normal DMs cannot pollute `agent:main:main` or override configured heartbeat session routing.

## Best Possible Solution

Land a maintainer-approved heartbeat fix that makes explicit `heartbeat.session` win for event-triggered wakes and preserves or migrates pending system events without cross-session pollution, then decide Telegram DM default isolation separately with docs and regression coverage.

Options:

- **Split heartbeat precedence first (recommended):** Fix event-triggered heartbeat routing so configured `heartbeat.session` wins, and leave Telegram DM default behavior behind the existing `session.dmScope` setting until a separate decision.
- **Bundle Telegram DM isolation:** Change Telegram DMs to isolate by default as part of this issue, accepting the upgrade, docs, and regression-test impact for users relying on shared main-session context.
- **Defer to per-session heartbeat design:** Hold the concrete bug for the broader native per-session heartbeat scheduling direction, which may be cleaner but leaves forced-session contamination unresolved longer.

Yes. Source inspection gives a high-confidence path: exec and node event wakes carry a session key into the heartbeat runner, and `resolveHeartbeatSession()` resolves that forced key before `heartbeat.session`; I did not run a live Telegram heartbeat repro in this read-only review.

## Solution Assessment

Unclear as one bundled change. The heartbeat precedence repair is a narrow bug fix, but changing Telegram DM default isolation is a compatibility decision that should be split or explicitly approved.
