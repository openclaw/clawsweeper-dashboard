## Summary

Keep open: current main and v2026.6.11 still resolve a non-subagent wake `sessionKey` before explicit `heartbeat.session`, and Telegram DMs still default to the agent main session unless `session.dmScope` isolates them. A linked fix candidate remains open in a fork but is conflicting and unmerged, so there is no landed implementation to close against.

## What This Changes

The issue reports Telegram DM and heartbeat/session routing contamination where direct-chat or system-event heartbeat traffic can reuse the wrong agent session.

## Best Possible Solution

Land a maintainer-approved fix that makes explicit `heartbeat.session` win for event-triggered wakes and handles queued system events without cross-session pollution, then decide Telegram DM default isolation separately with docs and regression coverage.
