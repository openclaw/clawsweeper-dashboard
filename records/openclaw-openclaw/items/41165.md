## Summary

Keep open: current main and latest release still let an event-provided heartbeat wake session key win before explicit `heartbeat.session`, and the linked implementation candidate is open but conflicting rather than merged.

## What This Changes

The issue asks for Telegram DM and heartbeat session selection to avoid polluting `agent:main:main` and direct-message sessions with each other.

## Best Possible Solution

Land a maintainer-approved heartbeat precedence fix where explicit `heartbeat.session` wins for event-triggered wakes, then handle Telegram DM default isolation separately with docs, tests, and any migration or doctor support required.
