## Summary

Keep open: current main and the latest release still let event-provided heartbeat wake session keys win before explicit `heartbeat.session`, and Telegram DMs still intentionally default to the main session unless `session.dmScope` or route bindings isolate them. The linked implementation candidate is open but conflicting, so there is no landed fix to close against.

## What This Changes

The issue reports Telegram DM and heartbeat/session routing mixing where direct messages or system-event-triggered heartbeats can reuse the wrong session and pollute `agent:main:main` or an active DM session.

## Best Possible Solution

Land a maintainer-approved fix that makes explicit `heartbeat.session` win for event-triggered wakes and preserves or migrates pending system events without cross-session pollution, then handle Telegram DM default isolation as a separate compatibility decision with docs and tests.
