## Label Justifications

- `P1`: The issue affects real Telegram plus heartbeat users with session contamination, token waste, and reported swallowed heartbeat delivery.
- `impact:session-state`: The central failure is cross-contamination between heartbeat/main sessions and Telegram direct-message sessions.

## Summary

Keep open: current main and the latest release still resolve event-provided wake session keys before explicit `heartbeat.session`, while Telegram DMs still default to the agent main session unless `session.dmScope` is configured. The linked fork PR is open but conflicting, so there is no landed canonical fix to close against.

## What This Changes

The issue asks OpenClaw to prevent Telegram direct-message and heartbeat traffic from sharing or overriding the same session context.

## Best Possible Solution

Land a maintainer-approved fix that makes explicit `heartbeat.session` win for event-triggered wakes and preserves or migrates pending system events without cross-session pollution, then decide Telegram DM default isolation separately with docs and regression coverage.
