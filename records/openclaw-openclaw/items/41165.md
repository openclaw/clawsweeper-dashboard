## Summary

Keep open: current main still lets exec/system-event heartbeat wakes carry an originating session that resolves before explicit `heartbeat.session`, and Telegram DMs are still documented and tested to default to the agent main session unless isolation is configured.

## What This Changes

The issue asks OpenClaw to prevent Telegram DMs and system-event-triggered heartbeats from sharing or polluting the heartbeat/main session, especially when `heartbeat.session` is configured.

## Best Possible Solution

Land a maintainer-approved heartbeat precedence repair so explicit `heartbeat.session` wins for system-event wakes, then decide Telegram DM default isolation separately with docs and compatibility coverage.

No, not as one bundled Telegram-default change; the safer fix is a narrow heartbeat precedence repair plus a separate maintainer decision for Telegram DM default isolation.
