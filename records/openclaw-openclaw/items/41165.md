## Summary

Keep open: current main and latest release still let a wake-provided session key win before explicit `heartbeat.session`, and Telegram DMs still default to main-session routing unless `session.dmScope` isolates them. The same-repository fix PR was closed unmerged, and the fork mirror is conflicting, so there is no landed canonical fix.

## What This Changes

Telegram direct messages and heartbeat-triggered system events can share the wrong session, polluting `agent:main:main` or DM transcripts instead of using isolated Telegram/heartbeat session keys.

## Best Possible Solution

Land a maintainer-approved heartbeat precedence fix first, then decide Telegram DM default isolation separately with docs and regression coverage.
