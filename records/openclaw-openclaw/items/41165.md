## Summary

Keep open: current main and v2026.6.11 still route event-provided heartbeat wake session keys before an explicit `heartbeat.session`, and Telegram DMs still default to the agent main session unless `session.dmScope` isolates them. The remaining work is paired with a conflicting open fix candidate and needs maintainer direction rather than cleanup closure.

## What This Changes

The issue requests strict separation between Telegram direct-message sessions and heartbeat/main sessions so DMs or system-event wakes cannot pollute the wrong session.

## Best Possible Solution

Land a maintainer-approved fix that makes explicit `heartbeat.session` win for event-triggered wakes and safely moves or preserves pending system events, then handle Telegram DM default isolation as a separate compatibility decision with docs and tests.

No, closing is not the best solution because current main and the latest release still preserve the implicated behavior. The safer path is a focused heartbeat precedence fix plus a separate maintainer decision for Telegram DM default isolation.
