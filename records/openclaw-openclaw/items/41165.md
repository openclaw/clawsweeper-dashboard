## Summary

Keep open: current main still lets event-provided wake session keys win before an explicit `heartbeat.session`, so the heartbeat/session pollution bug remains source-reproducible; the related PR is open but unmerged/conflicting, and changing Telegram DMs away from the documented main-session default is a separate compatibility-sensitive product choice.

## What This Changes

The issue asks OpenClaw to stop Telegram DM and wake-triggered heartbeat work from polluting the agent main/heartbeat session after the prior duplicate-reply fix.

## Best Possible Solution

Land a focused heartbeat precedence repair that lets explicit `heartbeat.session` win over event wake keys, while leaving Telegram DM default isolation to the documented `session.dmScope` setting unless maintainers choose a separate compatibility plan.
