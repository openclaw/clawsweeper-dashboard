## Summary

Keep open: current main and the latest release still allow event-provided heartbeat wake session keys to win before configured `heartbeat.session`, and Telegram DMs still default to the agent main session unless `session.dmScope` isolates them. The linked fork PR is open but conflicting, so it is a review/adoption candidate rather than proof that this issue is fixed.

## What This Changes

The issue asks OpenClaw to prevent Telegram DM and heartbeat traffic from polluting `agent:main:main`, especially when DMs or configured heartbeat sessions should be isolated.

## Best Possible Solution

Land a maintainer-approved heartbeat wake precedence fix so explicit `heartbeat.session` wins for event-triggered wakes, then decide Telegram default DM isolation separately with docs and regression coverage.
