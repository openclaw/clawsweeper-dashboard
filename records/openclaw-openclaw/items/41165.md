## Summary

Keep open: current main and the latest release still allow event-provided wake session keys to resolve before `heartbeat.session`, while Telegram DMs still intentionally default to the agent main session unless `session.dmScope` is changed. The linked fork PR is open but conflicting, so there is no landed canonical fix to close against.

## What This Changes

The issue requests stricter Telegram DM and heartbeat session isolation so direct-message traffic and event-triggered heartbeats cannot pollute `agent:main:main`.

## Best Possible Solution

Land a maintainer-approved fix that makes explicit `heartbeat.session` win for event-triggered wakes and preserves or migrates pending system events without cross-session pollution, then handle Telegram DM default isolation as a separate compatibility decision with docs and tests.
