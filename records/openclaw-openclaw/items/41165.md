## Summary

Keep open: current main still lets event-provided heartbeat wake session keys win before `heartbeat.session`, and Telegram DMs still default to the agent main session unless `session.dmScope` changes that behavior. The linked fixing PR is open but conflicting, so there is no landed canonical fix to close against.

## What This Changes

The issue reports Telegram DM and event-triggered heartbeat traffic contaminating `agent:main:main` instead of staying isolated from the configured heartbeat/direct-message session.

## Best Possible Solution

Land a maintainer-approved fix that makes explicit `heartbeat.session` win for event-triggered wakes and handles pending system events without cross-session pollution, then decide Telegram DM default isolation separately with docs and regression coverage.
