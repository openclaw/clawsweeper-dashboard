## Summary

The branch fixes the missing verdict request, but it still renders the same misleading `Unavailable` fallback during the asynchronous verdict request; the existing loading state should be rendered as a pending status before this is merged.

## What This Changes

The PR exports and invokes the existing ClawHub verdict loader for route-provided Skills reports, retries after connection, and adds focused loader and Skills-page tests.

## Best Possible Solution

Render the existing `clawhubVerdictsLoading` state as a neutral pending/checking badge, and reserve `Unavailable` for a completed verdict request that has no usable entry or reports an actual failure.
