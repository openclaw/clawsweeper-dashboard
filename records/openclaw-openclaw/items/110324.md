## Summary

Keep open: the route-data hydration fix is narrowly scoped and addresses the missing RPC, but it still permits the Skills view to render a missing verdict as the security state `Unavailable` while the new verdict request is in flight. That is the same concrete P2 defect identified in the prior review cycle, and this head does not change the rendering path that distinguishes pending from unavailable.

**Likely related people:** `steipete` is a low-confidence routing candidate because the adjacent Control UI refactor in commit `8590655190d342639b353d97ce182259b55bd27d` is the only supplied merged-history signal for this page surface.

## What This Changes

The PR exports and invokes the existing ClawHub verdict loader for route-provided Skills reports, retries an empty verdict map after gateway connection, and adds focused UI and loader tests.

## Best Possible Solution

Render `clawhubVerdictsLoading` as a distinct pending/refreshing state for linked skills, reserve `Unavailable` for an absent verdict after hydration completes, and add a regression assertion for the intermediate render.
