## Summary

The prior EOF-hashing blocker is resolved in the latest head, but the new 50 MiB decision is still made from a pathname before a second pathname read. A concurrent replacement can therefore route an oversized replacement through `readFileSync`, defeating the stated bounded-memory safety goal; keep this PR open for that narrow repair and real runtime proof.

## What This Changes

The PR adds a 50 MiB threshold to `safeHashFile`, streaming larger regular files through a fixed 64 KiB buffer and adding an oversized-file hash regression test.

## Best Possible Solution

Open the file descriptor before determining its size, use `fstatSync` on that descriptor, and use the same descriptor for either bounded in-memory reading or EOF streaming; then provide redacted after-fix installed-plugin-index runtime evidence.
