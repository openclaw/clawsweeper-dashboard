## Summary

Keep open for maintainer handling. Current main appears to prevent the reported fresh-session replay for an overall CLI timeout by reserving the retry path for a silent no-output timeout, but the requested user-facing explanation for terminated CLI-internal background work and timeout-specific guidance still needs focused verification. ([raw.githubusercontent.com](https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/cli-runner.ts))

## What This Changes

Prevent active Claude CLI work from being replayed after an overall turn timeout and distinguish overall-timeout guidance from the no-output watchdog.

## Best Possible Solution

Retain the current no-replay behavior for overall timeouts, add a regression test for an active CLI turn that reaches the overall budget, and make the resulting failure text name the fired timeout plus the child-work cancellation consequence.
