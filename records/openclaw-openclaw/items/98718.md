## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P1] Check the schema version before running durable DDL:** `src/durable/sqlite-store.ts:343-344`
  - body: The future-version guard currently runs only after this helper has already executed all durable `CREATE TABLE`/index DDL and `ALTER TABLE ... ADD COLUMN` backfills. A user who opens a newer durable database with this older build will still have that database mutated before the "newer than supported" error is thrown; move the version check ahead of any durable DDL/backfill, matching the shared state DB pattern.
  - confidence: 0.88
- **[P2] Align the worker flag with the mutating recovery loop:** `docs/cli/durable.md:74`
  - body: The docs say `OPENCLAW_DURABLE_WORKER` starts the recovery worker, but the gateway starts `startDurableRecoveryWorker` whenever only `OPENCLAW_DURABLE_RUNTIME` is enabled. That loop mutates state by marking stale runs lost, firing timers, and consuming signals, so operators enabling runtime for inspection do not get the documented worker opt-in behavior; either gate this loop explicitly or document that recovery mutation is part of the runtime flag.
  - confidence: 0.82
