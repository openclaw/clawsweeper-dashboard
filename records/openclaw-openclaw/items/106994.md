Full review comments:

- **[P1] Allow the actual packed prepare hook:** `src/infra/package-update-lifecycle.ts:20-25`
  - body: The staged lifecycle contract requires `prepare` to be absent, but the packed OpenClaw manifest retains its prepare script. Normal supported npm candidates therefore fail contract validation and never activate; either remove the hook during packaging with release validation or accept the exact published hook here.
  - confidence: 0.98
- **[P1] Preserve validated legacy downgrade targets:** `src/infra/package-update-lifecycle.ts:159-164`
  - body: Requiring the new completion guard rejects every older package that predates it, even though the tarball checker accepts releases through 2026.7.1 as valid legacy packages and the CLI supports confirmed downgrades. Add a narrowly validated guardless legacy path instead of breaking those targets.
  - confidence: 0.97
- **[P1] Defer user-state migration until activation:** `src/infra/package-update-lifecycle.ts:180-187`
  - body: The staged candidate's postinstall can migrate the plugin registry before dist verification and swap complete. If either later step fails, the old package remains installed against state changed by an unactivated candidate; suppress or split user-state migration until activation succeeds.
  - confidence: 0.97
- **[P1] Validate the Node used by the installed shim:** `src/infra/package-update-lifecycle.ts:34-36`
  - body: Ordinary npm updates default to `process.execPath`, while the installed command uses an env-based Node shim. With a newer updater Node but an older PATH Node, this can approve and activate a release that ordinary `openclaw` invocations cannot start; probe the installed shim runtime before activation.
  - confidence: 0.96
