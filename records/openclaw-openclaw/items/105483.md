## Summary

Keep this PR open. Current `main` still passes Claude `resets_at` values directly through `new Date(...).getTime()` at all three usage-window sites, so the reported `NaN` path remains. The proposed finite-value guard is a narrow, compatible fix, but it lacks regression coverage for malformed timestamps and the PR body provides only mocked test output rather than after-fix real-behavior proof.

## What This Changes

The branch replaces direct Claude usage reset-date parsing with a finite timestamp helper so invalid `resets_at` values become `undefined` instead of `NaN`.

## Best Possible Solution

Keep the helper-based normalization, add focused malformed-reset regression coverage for every affected response shape, and attach redacted after-fix runtime or terminal evidence before merging.

## Solution Assessment

Yes, the finite timestamp helper is the narrowest maintainable repair because it preserves valid-date behavior and keeps the existing optional `resetAt` contract; it should be paired with a regression test.
