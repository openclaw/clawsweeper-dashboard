## Summary

Keep open. Current main implements important pieces of the field report, especially selector-backed managed-browser actions, ARIA/role ref handling, selector waits, and lower-level batch execution, but the model-facing browser tool still lacks several requested signals and capabilities, including explicit stale-ref/action-result hints, CAPTCHA signaling, CDP element inspection, post-fill verification, wait-by-ref, and model-schema exposure for batch.

## What This Changes

The issue requests seven browser-tool ergonomics and reliability improvements from a real-world automation field test: selector targeting, stale-ref/state signals, CDP element inspection, batch actions, form-fill verification, CAPTCHA signaling, and richer waits.

## Best Possible Solution

Keep the issue as a maintainer-owned browser-plugin umbrella, then split one approved slice at a time into narrow work such as model-facing batch schema/docs, stale-ref/action-result hints, CAPTCHA/manual-blocker detection, CDP element inspection, or wait-by-ref semantics.
