## Summary

Keep open. Current `main` and `v2026.6.11` still strip non-text MCP content fields in the HTTP loopback path, and https://github.com/openclaw/openclaw/pull/100336 is an open candidate fix rather than a merged implementation.

## What This Changes

Issue requests preserving non-text HTTP MCP loopback tool-call content blocks so image/audio/resource fields are not stripped before client validation.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/100336 or an equivalent narrow replacement that preserves SDK-valid non-text content blocks, safely falls back for malformed/unknown blocks, and adds route-level regression coverage.

## Reproduction Assessment

Yes, by source inspection: any loopback `tools/call` result with an image block containing `data` and `mimeType` is remapped to only `type` and `text` before JSON-RPC response serialization. I did not run a live loopback screenshot client in this read-only review.

## Solution Assessment

Yes, the best fix belongs at the gateway normalizer boundary, with preservation of SDK-valid content blocks and route-level tests. The current open PR is the right candidate path, but it needs maintainer review for malformed/unknown block handling before the issue closes.
