## Summary

Keep open. Current main and the latest release still strip non-text MCP content fields in the HTTP loopback `tools/call` response path, and https://github.com/openclaw/openclaw/pull/100336 is now the open closing PR that should be reviewed and landed or closed before this issue is resolved.

## What This Changes

HTTP MCP loopback `tools/call` results should preserve image, audio, resource, and resource_link content block fields instead of normalizing every block to text.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/100336 or an equivalent narrow gateway fix that preserves SDK-valid MCP content blocks through HTTP `tools/call`, keeps fallback behavior for malformed results, and adds regression coverage for non-text blocks.
