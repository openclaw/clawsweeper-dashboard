## Summary

This remains a concrete OpenAI OAuth failure-classification report rather than a duplicate of the related cooldown and pre-expiry-refresh issues. The report identifies a plausible path where an OAuth refresh returns no credential, model selection falls through to the generic missing-key error, and user-facing copy incorrectly asks for re-authentication; no merged or open PR in the supplied context owns that exact behavior.

## What This Changes

Treat a transient OpenAI ChatGPT OAuth refresh that yields no credential as a retryable refresh failure rather than reporting that no API key exists or that the user must sign in again.

## System Context

OpenClaw resolves an auth profile before a model request, refreshing an expired OAuth access token when needed. The refresh result then feeds model credential selection, failure classification, cooldown handling, and the user-facing gateway reply.

## Architecture Diagram

flowchart LR
  A[OpenAI ChatGPT OAuth profile] --> B[OAuth credential resolver]

  C -->|yes| D[Model request]
  C -->|no credential| E[Model credential selection]
  E --> F[Failure classification]
  F --> G[Gateway reply and cooldown handling]

## Best Possible Solution

Add a typed or otherwise explicit transient-refresh outcome at the OAuth resolver boundary, propagate it through model-auth failure classification, and add focused coverage proving that valid stored refresh material which yields no refreshed credential does not render the expired-login/API-key guidance.
