## Summary

The malformed-UTF-8 fix is directionally correct and the supplied direct runtime proof supports the reported U+FFFD collision, but the new decoder also strips a valid leading UTF-8 BOM by default. That violates the function’s stated round-trip contract for valid encoded session keys, so this PR needs a small correction before merge.

## What This Changes

The PR replaces forgiving UTF-8 decoding of session-state notice context keys with fatal `TextDecoder` decoding and adds regression coverage for malformed payloads.

## Best Possible Solution

Keep fatal UTF-8 validation, explicitly preserve a leading BOM with `ignoreBOM: true`, and add a round-trip regression test for a session key beginning with U+FEFF before merging.

Yes, source inspection and the supplied direct decoder transcript provide a focused reproduction path: decode an invalid `session-state:ff` payload and compare it with a valid U+FFFD target. ## Solution Assessment

No. Fatal UTF-8 decoding is the right narrow defense, but the decoder must preserve all valid UTF-8 payloads; setting `ignoreBOM: true` is the safer complete fix.
