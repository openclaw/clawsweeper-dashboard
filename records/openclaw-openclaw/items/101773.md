## Summary

Current main still performs an unbounded plugin-manifest read, and this PR is focused, tested, and backed by live CLI proof. It should remain open for a security owner to confirm that the audit-only 1 MiB cutoff is the intended manifest contract and that warning-and-skip behavior cannot leave accepted plugin entrypoints outside deep-scan coverage.

## What This Changes

The PR caps plugin package-manifest reads at 1 MiB during deep security audits, rejects non-regular targets through shared file helpers, and adds oversized-manifest regression coverage.

## Best Possible Solution

Use one canonical plugin-manifest acceptance contract across installation, runtime loading, and security audit: either reject oversized manifests everywhere or obtain audit entrypoints from the same trusted bounded parser or registry so executable entries are never accepted while omitted from deep scanning.
