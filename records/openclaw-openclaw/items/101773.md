## Summary

This PR is still necessary: current main still reads installed plugin manifests with unbounded `fs.readFile`, while the PR adds a focused size cap through the existing regular-file helper and regression coverage. I found no blocking code defect, but this external PR still needs real behavior proof from a live audit path before merge.

## What This Changes

The PR bounds `readPluginManifestExtensions` package.json reads to 1 MiB with `statRegularFile`/`readRegularFile` and adds an oversized-manifest regression test.

## Best Possible Solution
