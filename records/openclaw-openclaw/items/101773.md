## Summary

The patch remains useful and appears technically correct: it bounds a deep-audit manifest read through existing secure-file helpers, preserves a visible warning, and has convincing CLI proof. ## What This Changes

This PR caps installed-plugin package.json reads at 1 MiB during deep security audits, rejects unsafe file targets through regular-file helpers, and adds oversized-manifest regression coverage.

## Best Possible Solution

Land a bounded regular-file read with a security-owner-approved shared limit or clearly named audit-specific limit, retaining the warning and directory-scan fallback while documenting reduced forced-entry coverage for rejected manifests.
