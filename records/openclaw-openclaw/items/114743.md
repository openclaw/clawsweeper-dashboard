## What This Changes

This PR shares identical Control UI chat startup, history, and fallback metadata requests across matching split panes while preserving each pane’s connection, session, agent, and request-version ownership checks.

## System Context

A Control UI chat pane loads history and startup metadata from the Gateway, then applies those results to its local pane state. This change inserts a browser-client-scoped shared in-flight request layer so matching split panes avoid duplicate Gateway work while each pane independently rejects stale results.
