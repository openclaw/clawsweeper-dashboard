## Summary

Keep open: this still describes a plausible Feishu message-delivery regression, and current main plus v2026.6.11 still only prove the zero-final fallback gate, not that long markdown-heavy finals are delivered or counted correctly.

## What This Changes

The issue asks OpenClaw to stop sending Feishu's no-visible-content fallback when a long markdown-heavy assistant reply was actually generated and should be visible.

## Best Possible Solution

Preserve Feishu's fallback for truly empty turns, but first prove where long markdown finals disappear and then fix that owner boundary so visible text is either delivered and counted or fails with an accurate recoverable state.
