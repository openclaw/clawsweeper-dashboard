## Summary

Keep open: current main still has MiMo v2.5/v2.5-pro on the reasoning-content path, but the response-side visible-text wrapper only covers older MiMo V2 models and existing tests explicitly leave newer MiMo replay models unchanged.

## What This Changes

The issue asks OpenClaw to stop duplicated MiMo v2.5/v2.5-pro thinking content from leaking into visible text replies when reasoning is enabled through OpenAI-compatible completions.

## Best Possible Solution

Add a narrow Xiaomi/OpenAI-compatible stream sanitizer for MiMo v2.5/v2.5-pro that removes duplicated reasoning prefixes from visible text while preserving real answer text and tool calls.

Yes from source inspection, but not from a live provider run: current main routes MiMo v2.5 through reasoning_content handling while excluding it from the only visible-text response wrapper, and that wrapper returns early when text is already present.

## Solution Assessment

Yes in direction: the maintainable fix belongs in the Xiaomi/OpenAI-compatible stream boundary, not in Feishu or channel rendering, and should preserve non-duplicated visible text instead of disabling reasoning globally.
