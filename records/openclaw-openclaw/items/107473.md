## Summary

This PR remains necessary because current main still permits an unterminated Ollama NDJSON record to grow the decoded buffer without a per-record bound, while the branch has convincing before/after production-path proof and no concrete correctness defect.

Likely related people: @BrokenFinger98 introduced the native Ollama streaming parser, @steipete merged and reviewed that implementation, and @taitruong contributed recent adjacent Ollama request/runtime work.

## What This Changes

Adds a 16 MiB byte limit per native Ollama NDJSON record, cancels overflowing readers, and tests overflow cancellation plus newline-based limit resets.

## Best Possible Solution

Rebase onto current main, retain the pre-decode per-record byte cap and cancellation coverage, and merge after maintainers confirm that 16 MiB is an acceptable compatibility boundary and required checks pass.
