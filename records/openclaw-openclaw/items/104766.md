## Summary

The structured device-code UI is a sound follow-up to the native provider-auth flow, but the new exported input can emit values rejected by its own gateway schema, and the PR still lacks after-fix macOS proof.

## What This Changes

The PR adds structured device-code metadata to wizard steps, uses it in xAI device authorization, and renders a dedicated macOS code-copy and browser-verification view.

## Best Possible Solution

Normalize and validate device-code metadata at the wizard session boundary so the exported method and wire schema share one contract, retain the text fallback, and attach redacted signed-macOS proof of the complete flow.
