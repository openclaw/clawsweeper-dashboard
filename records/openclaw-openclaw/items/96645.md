Full review comments:

- **[P1] Preserve the matched directory entry kind:** `extensions/mattermost/src/session-route.ts:56-60`
  - body: Late discovery from this review cycle: `resolveMattermostOutboundSessionRoute` now trusts `resolvedTarget.kind === "group"`, but the shared directory resolver still returns the requested lookup kind rather than the matched entry's kind. For a public `O` channel resolved by name or `#general`, Mattermost's directory entry can be `kind: "channel"` while the resolver still passes `group`, so the PR can still fork a phantom `group:<id>` session for public channels. Carry `entry.kind` through the resolved target, or add an equivalent Mattermost resolver path plus a route-level regression test.
  - late: true
  - confidence: 0.9
- **[P2] Avoid caching non-authoritative channel fallbacks:** `extensions/mattermost/src/mattermost/target-resolution.ts:107`
  - body: Late discovery from this review cycle: after a user 404, `resolveMattermostChannelKind` returns `channel` for any channel lookup failure, and this line caches that result. A transient Mattermost 500 or permission hiccup on the first lookup can permanently classify a private channel as `channel` for the process lifetime, recreating the namespace split. Only cache successful channel-kind lookups, or return a non-cacheable fallback from the failure path.
  - late: true
  - confidence: 0.86
