## What This Changes

The branch makes Mattermost private channels keep the `group` session namespace during outbound and bound-cron route reconstruction while continuing to post to the `channel:<id>` wire target.

## System Context

Mattermost inbound processing receives the authoritative channel type and records a `group` or `channel` session identity. Outbound replies and isolated cron deliveries later reconstruct a route from a wire target, so they must preserve that identity to avoid splitting one conversation across two session keys.

## Architecture Diagram

  D[Outbound target or bound cron job] --> E[Outbound route reconstruction]
  C --> E
  E --> F[Mattermost delivery]
  F --> G[Existing thread session reused]

## Best Possible Solution

Keep isolated cron behavior as the generic default, add or use a narrow plugin-owned opt-in contract for preserving a validated bound conversation identity during route reconstruction, and let Mattermost implement that contract with its current group/channel safeguards.
