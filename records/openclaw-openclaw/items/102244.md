## Summary

Keep this issue open: current main and the latest release still preserve Anthropic/Bedrock signature fields only when the value survives normal secret redaction, so credential-shaped substrings inside opaque provider signatures can still fall through to masking and poison replay state.

## What This Changes

The issue reports transcript redaction corrupting Anthropic/Bedrock opaque reasoning signatures when secret-pattern redaction rewrites credential-shaped substrings inside provider signature fields.

## Best Possible Solution

Preserve structurally valid provider-minted opaque reasoning signatures only in known signed-thinking fields, keep ordinary credential redaction active everywhere else, and add repair or send-side protection for already-poisoned signatures.

Options:

- **Field-scoped signature preservation (recommended):** Preserve validated opaque replay tokens only in known provider signature fields, and add focused repair coverage for already-redacted signature values.
- **Pattern-only hardening:** Make vendor token patterns stricter or case-sensitive while keeping the current redaction-idempotency requirement, accepting that other false positives may still corrupt signatures.
- **Send-side guard only:** Drop ellipsis-marked or invalid Bedrock/Anthropic signatures before replay, preventing provider 400s but leaving upstream transcript corruption possible.

Yes. Source inspection shows a high-confidence path: an Anthropic/Bedrock signature field containing a credential-shaped substring fails `isOpaqueReplayToken`, then remains eligible for normal masking before transcript persistence.

## Solution Assessment

Yes on direction, but not as an automatic patch yet. The narrow maintainable solution is route- and field-scoped signature preservation with regression coverage and a maintainer-approved security boundary.
