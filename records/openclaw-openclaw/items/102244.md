## Summary

Keep this open: current main and v2026.6.11 still have the redaction-idempotency gate that can fail to preserve credential-looking opaque Anthropic/Bedrock signatures, and the reporter added live Bedrock evidence that a corrupted signature still rejects replay.

## What This Changes

The issue requests a fix for transcript redaction corrupting Anthropic/Bedrock signed-thinking replay signatures when secret-pattern matching false-positives inside opaque provider tokens.

## Best Possible Solution

Preserve structurally valid provider-minted replay signatures only in scoped signed-thinking fields, keep ordinary credential redaction intact elsewhere, and add Bedrock/Anthropic guard or repair coverage that drops already-poisoned thinking blocks as a whole.

## Maintainer Decision

Rationale: The current tests deliberately redact credential-shaped provider signature fields, but the report shows that policy can corrupt real opaque replay tokens; changing it adjusts the transcript secret-redaction boundary.

Owner confidence: high

Options:

- **Scoped Structural Preservation (recommended):** Preserve only validated opaque signatures in known provider signed-thinking fields while keeping arbitrary text, missing-route fields, and malformed payloads redacted.
- **Pattern-Only Hardening:** Tighten fixed-case vendor prefixes and boundaries but keep the current redaction-idempotency requirement for provider signatures.
- **Send-Side Recovery Only:** Drop visibly corrupted Bedrock/Anthropic thinking blocks before replay without changing transcript-redaction preservation.

## Reproduction Assessment

Yes. Current main still has a source-level path where a credential-looking opaque signature fails preservation, is redacted before transcript write, and is later forwarded by Bedrock; I did not rerun live Bedrock in this read-only pass.

## Solution Assessment

Unclear until maintainers choose the security boundary. The narrowest maintainable shape appears to be scoped structural preservation plus whole-thinking-block replay hardening, while pattern-only hardening would not cover every opaque-token false positive.
