## Summary

Keep this open: current main and the latest release still contain the redaction-preservation gate that can reject credential-looking opaque provider signatures, and Bedrock still forwards any nonblank stored thinking signature without an ellipsis/corruption guard.

## What This Changes

The issue requests a fix for transcript-redaction false positives that rewrite opaque Anthropic/Bedrock reasoning signatures and poison later session replay.

## Best Possible Solution

Preserve provider-minted opaque replay signatures only in scoped signed-thinking fields, keep ordinary credential redaction intact elsewhere, and add Bedrock/Anthropic guard or repair coverage for already-poisoned signatures.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: For provider-minted signed-thinking fields, should OpenClaw preserve structurally valid opaque replay tokens even when their bytes contain credential-shaped substrings, or keep the current redaction-idempotency gate and only harden individual secret patterns?

Rationale: The current tests deliberately redact credential-shaped provider signature fields, but the report shows that policy can corrupt real opaque replay tokens; maintainers should choose the transcript redaction boundary before automation changes it.

Likely owner: vincentkoc

Owner reason: The current-main blame and recent secret-redaction history point to this person across the active redaction and replay surfaces.

Owner confidence: medium

Options:

- **Scoped Structural Preservation (recommended):** Preserve validated opaque signatures only in known provider signed-thinking fields while leaving arbitrary text, missing-route fields, and malformed payloads redacted.
- **Pattern-Only Hardening:** Make fixed-case vendor prefixes and boundaries stricter but keep the current idempotent-redaction requirement for provider signatures.
- **Send-Side Recovery Only:** Drop visibly corrupted thinking blocks on Bedrock/Anthropic send and rely on recovery without changing transcript-redaction preservation.

## Reproduction Assessment

Yes. Current main still has the source path where a credential-looking opaque signature fails preservation, falls through to redaction, and is persisted before later Bedrock replay.

## Solution Assessment

Unclear until the security boundary is chosen. The narrowest maintainable direction appears to be scoped structural preservation plus corrupted-block replay/repair hardening; pattern-only hardening would not cover every opaque-token false positive.
