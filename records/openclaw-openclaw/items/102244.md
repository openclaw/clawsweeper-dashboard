## Summary

Keep this open: current main and the latest release still contain the redaction gate that can refuse to preserve credential-looking opaque reasoning signatures, and Bedrock still forwards any nonblank thinking signature without an ellipsis/corruption guard.

## What This Changes

The issue asks OpenClaw to stop transcript redaction from corrupting Anthropic/Bedrock signed reasoning tokens that contain credential-looking substrings and to handle already-poisoned replay blocks.

## Best Possible Solution

Preserve structurally valid provider-minted opaque signatures only in scoped signed-thinking fields, keep ordinary credential redaction intact elsewhere, and add Bedrock/Anthropic drop-or-repair coverage for already-poisoned signatures.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: For provider-minted signed-thinking fields, should OpenClaw preserve structurally valid opaque replay tokens even when their bytes contain credential-shaped substrings, or keep the current redaction-idempotency gate and only harden individual secret patterns?

Rationale: The current tests intentionally redact credential-shaped provider signature fields, but the report shows that policy can corrupt real opaque replay tokens; the durable fix changes the boundary between transcript secret redaction and provider-owned opaque bytes.

Likely owner: steipete

Owner reason: This person authored the PR commits that scoped and validated the current provider replay signature boundary.

Owner confidence: high

Options:

- **Scoped Structural Preservation (recommended):** Preserve validated opaque signatures only in known provider signed-thinking fields while leaving arbitrary text, missing-route fields, and malformed payloads redacted.
- **Pattern-Only Hardening:** Make fixed-case vendor prefixes and boundaries stricter while keeping the current redaction-idempotency requirement for provider signatures.
- **Send-Side Recovery Only:** Drop visibly corrupted signatures on Bedrock/Anthropic send and rely on recovery without changing transcript-redaction preservation.

## Reproduction Assessment

Yes. Source inspection shows the current redaction predicate still rejects opaque replay-token preservation when redactSensitiveText would change the value, and the reporter added live Bedrock replay evidence for the corrupted-signature failure shape.

## Solution Assessment

Unclear until the security boundary is chosen. The narrow maintainable direction appears to be scoped structural preservation plus replay hardening, while pattern-only hardening would not cover every opaque-token false positive.
