## Label Justifications

- `P1`: The report describes a current provider replay failure that can persistently break real Anthropic/Bedrock signed-thinking sessions after transcript persistence.
- `impact:session-state`: The corrupted signature is written into the on-disk session transcript and replayed on later turns.
- `impact:security`: The affected code is the transcript secret-redaction boundary, and the repair must avoid leaking credential-shaped data while preserving opaque provider bytes.
- `impact:message-loss`: Affected follow-up turns can fail before a usable assistant response is delivered.

## Summary

Keep this open: current main still has the redaction-idempotency gate that can fail to preserve credential-looking opaque provider signatures, and Bedrock still forwards any nonblank stored thinking signature without an ellipsis/corruption guard.

## What This Changes

Fix transcript redaction so opaque Anthropic/Bedrock reasoning signatures are not masked and persisted as corrupted replay state.

## Best Possible Solution

Preserve provider-minted opaque replay signatures only in scoped signed-thinking fields, keep ordinary credential redaction intact elsewhere, and add Bedrock/Anthropic guard or repair coverage for already-poisoned signatures.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: For provider-minted signed-thinking fields, should OpenClaw preserve structurally valid opaque replay tokens even when their bytes contain credential-shaped substrings?

Rationale: The current tests intentionally redact credential-shaped provider signature fields, but this report shows that policy can corrupt real opaque replay tokens; maintainers need to choose the transcript redaction boundary before automation changes it.

Likely owner: vincentkoc

Owner confidence: high

Options:

- **Scoped Structural Preservation (recommended):** Preserve validated opaque signatures only in known provider signed-thinking fields while leaving arbitrary text, missing-route fields, and malformed payloads redacted.
- **Pattern-Only Hardening:** Make fixed-case vendor prefixes and boundaries stricter but keep the current idempotent-redaction requirement for provider signatures.
- **Send-Side Recovery Only:** Drop visibly corrupted signatures on Bedrock/Anthropic send and rely on recovery without changing transcript-redaction preservation.

## Reproduction Assessment

Yes, at source level: current main still rejects opaque replay-token preservation when redactSensitiveText would change the value, then persists the redacted message. I did not run a live Bedrock request in this read-only pass.

## Solution Assessment

Unclear until the security boundary is chosen; the narrow direction appears to be scoped structural preservation plus replay hardening. Pattern-only hardening would reduce some false positives but would not cover every opaque-token collision.
