## Summary

Keep this open: current main and the latest release still have the redaction-idempotency gate that can reject preservation for credential-looking Anthropic/Bedrock opaque signatures, and the existing related PRs cover adjacent replay/recovery cases rather than this redaction-time corruption source.

## What This Changes

The issue asks OpenClaw to stop transcript secret redaction from corrupting provider-owned Anthropic/Bedrock reasoning signatures and to handle already-poisoned persisted thinking blocks.

## Best Possible Solution

Preserve validated provider-owned Anthropic/Bedrock opaque signature fields by route and shape, keep ordinary credential redaction active everywhere else, and add a cleanup/drop path for persisted thinking blocks already carrying a redaction footprint.

Owner confidence: medium

Options:

- **Route-scoped replay-token preservation (recommended):** Preserve only validated opaque replay tokens in direct assistant Anthropic/Bedrock signature slots, then keep all other credential-shaped text redacted.
- **Pattern-only hardening:** Tighten vendor-prefix regex case and boundaries while keeping the existing idempotency gate, accepting residual opaque-token false positives if another pattern matches.
- **Recovery-only mitigation:** Leave redaction behavior unchanged and only drop or repair corrupted thinking blocks on replay, reducing failures without preventing future transcript poisoning.

## Reproduction Assessment

Yes at source level: current code still rejects opaque replay-token preservation when redaction would change the value, and the default token patterns can match credential-looking substrings inside opaque signatures. I did not run a live Bedrock replay during this read-only cleanup review.

## Solution Assessment

Unclear until the maintainer security boundary is chosen. The narrowest maintainable direction appears to be route-scoped structural preservation plus repair/drop handling, not broad relaxation of secret patterns alone.
