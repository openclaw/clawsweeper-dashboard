## Label Justifications

- `P1`: The issue describes a current-main provider replay failure that can persistently break real Anthropic/Bedrock signed-thinking sessions after transcript persistence.
- `impact:session-state`: The corrupted signature is written into the on-disk session transcript and replayed on later turns.
- `impact:security`: The affected code is the transcript secret-redaction boundary, and the repair must avoid leaking credential-shaped data while preserving opaque provider bytes.
- `impact:message-loss`: Affected follow-up turns can fail before a usable assistant response is delivered.

## Summary

Keep this open: current main and the latest shipped release still preserve provider signatures only when redaction is idempotent, so credential-looking bytes inside Anthropic/Bedrock opaque signatures can still fall through to masking and poison replay state.

## What This Changes

The issue asks OpenClaw to stop transcript secret redaction from corrupting Anthropic/Bedrock signed-thinking replay signatures that contain credential-pattern false positives.

## Best Possible Solution

Preserve structurally valid provider-minted replay signatures only in known signed-thinking fields, keep ordinary secret redaction active elsewhere, and add Bedrock/Anthropic replay repair for already-poisoned thinking blocks.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: For provider-minted signed-thinking fields, should OpenClaw preserve structurally valid opaque replay tokens even when their bytes contain credential-shaped substrings, or keep the current redaction-idempotency gate and only harden individual secret patterns?

Rationale: The current tests deliberately redact credential-shaped provider signature fields, but the issue shows that policy can corrupt real opaque replay tokens; the permanent boundary affects both credential secrecy and session replay correctness.

Likely owner: steipete

Owner reason: Recent history connects this person to both secrets/redaction and Anthropic/Bedrock thinking behavior, making them the best available owner for the security-boundary choice.

Owner confidence: medium

Options:

- **Scoped Structural Preservation (recommended):** Preserve validated opaque signatures only in known provider signed-thinking fields while leaving arbitrary text, missing-route fields, and malformed payloads redacted.
- **Pattern-Only Hardening:** Make fixed-case vendor prefixes and boundaries stricter while keeping the current idempotent-redaction requirement for provider signatures.
- **Send-Side Recovery Only:** Drop visibly corrupted signatures on Bedrock/Anthropic send and rely on recovery without changing transcript-redaction preservation.

## Reproduction Assessment

Yes. Current main still has the exact source path: credential-looking opaque signatures fail the preservation predicate, fall through to redaction, and are persisted before later Bedrock replay.

## Solution Assessment

Unclear until the security boundary is chosen. The narrow best direction appears to be scoped structural preservation plus replay/repair hardening; pattern-only hardening would not cover every opaque-token false positive.
