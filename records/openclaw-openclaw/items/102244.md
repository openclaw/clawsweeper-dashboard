## Summary

Keep this open: current main and the latest shipped release still have the transcript-redaction gate that can reject preservation for credential-looking opaque provider signatures, and Bedrock still forwards any nonblank stored thinking signature without a corruption-footprint guard.

## What This Changes

The issue asks OpenClaw to stop transcript redaction from corrupting Anthropic/Bedrock signed reasoning signatures that contain credential-shaped substrings and to handle already-poisoned replay state.

## Best Possible Solution

Preserve provider-minted opaque replay signatures only in scoped signed-thinking fields, keep ordinary credential redaction intact elsewhere, and add Bedrock/Anthropic guard or repair coverage for already-poisoned signatures.

Question: For provider-minted signed-thinking fields, should OpenClaw preserve structurally valid opaque replay tokens even when their bytes contain credential-shaped substrings, or keep the current redaction-idempotency gate and only harden individual secret patterns?

Rationale: The current tests deliberately redact credential-shaped provider signature fields, but the report shows that policy can corrupt real opaque replay tokens; maintainers need to choose the transcript redaction boundary before automation changes it.

Likely owner: vincentkoc

Owner confidence: high

Options:

- **Scoped Structural Preservation (recommended):** Preserve valid opaque signatures only in known provider signed-thinking fields while still redacting arbitrary text, missing-route fields, malformed payloads, and sibling secrets.
- **Pattern-Only Hardening:** Make fixed-case vendor prefixes and boundaries stricter while keeping the current idempotent-redaction requirement for provider signatures.
- **Send-Side Recovery Only:** Drop visibly corrupted Bedrock/Anthropic thinking blocks during replay and repair, but leave transcript redaction behavior unchanged.

## Reproduction Assessment

Yes, at source level: current main still rejects opaque replay-token preservation when redactSensitiveText would change the value, then persists the redacted message. I did not run a live Bedrock request in this read-only pass, but the reporter added live Bedrock control/corruption results.

## Solution Assessment

Unclear until the security boundary is chosen; the narrowest maintainable direction appears to be scoped structural preservation plus Bedrock/Anthropic guard or repair coverage. Pattern-only hardening would reduce false positives but not cover every opaque-token corruption case.
