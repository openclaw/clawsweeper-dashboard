## Label Justifications

- `impact:session-state`: The corrupted signature is written into the on-disk session transcript and replayed on later turns.

- `impact:message-loss`: Affected follow-up turns can fail before a usable assistant response is delivered.

## Summary

Keep this open: current main and the latest release still contain the redaction-idempotency gate that can fail to preserve credential-looking opaque reasoning signatures, and Bedrock still forwards any nonblank thinking signature without a U+2026/corruption guard.

## What This Changes

The issue asks OpenClaw to stop transcript secret-redaction from rewriting valid Anthropic/Bedrock signed-thinking replay signatures that contain credential-looking substrings, and to account for already-poisoned signatures.

## Best Possible Solution

Preserve structurally valid provider-minted opaque replay signatures only in scoped signed-thinking fields, keep ordinary credential redaction intact elsewhere, and add Anthropic/Bedrock guard or repair coverage for already-poisoned signatures.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: For provider-minted signed-thinking fields, should OpenClaw preserve structurally valid opaque replay tokens even when their bytes contain credential-shaped substrings, or keep the current redaction-idempotency gate and harden individual patterns instead?

Rationale: The current tests deliberately redact credential-shaped provider signature fields, but the report shows that policy can corrupt real opaque replay tokens; maintainers need to choose the transcript redaction boundary before automation changes it.

Likely owner: vincentkoc

Owner reason: Current-source blame and release history point to this person across the active redaction and Bedrock replay surfaces, although the blame commit is a broad import.

Owner confidence: medium

Options:

- **Scoped Structural Preservation (recommended):** Preserve validated opaque signatures only in known provider signed-thinking fields while leaving arbitrary text, missing-route fields, and malformed payloads redacted.
- **Pattern-Only Hardening:** Make fixed-case vendor prefixes and boundaries stricter while keeping the current idempotent-redaction requirement for provider signatures.
- **Send-Side Guard Only:** Drop visibly corrupted signatures on Anthropic/Bedrock send paths and rely on recovery without changing transcript-redaction preservation.

## Reproduction Assessment

Yes, at source level: current main still rejects opaque replay-token preservation when redactSensitiveText would change the value, then persists the redacted message. I did not run a live Bedrock request in this read-only pass.

## Solution Assessment

Unclear until the security boundary is chosen; the strongest direction appears to be scoped structural preservation plus replay hardening, while pattern-only hardening would not cover every opaque-token false positive.
