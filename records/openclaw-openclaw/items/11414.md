## Summary

Keep this canonical feature request open. Current main and the shipped v2026.6.11 release support Telegram forum-topic creation and editing only; close, reopen, and delete remain absent, and permanent deletion needs a maintainer-approved authorization/default contract before implementation.

## What This Changes

Add Telegram forum-topic close, reopen, and delete operations alongside the existing create and edit message-tool actions.

## Best Possible Solution

Implement one coherent Telegram plugin-owned lifecycle: add typed close and reopen actions across discovery, runtime, transport, schema, docs, and tests, while placing permanent deletion behind an explicitly approved, preferably disabled-by-default permission.

## Maintainer Decision

Question: Should permanent Telegram forum-topic deletion require a separate disabled-by-default action permission, while close and reopen follow the ordinary topic-management model?

Rationale: Current create/edit actions are enabled by default, so extending that behavior to irreversible deletion changes the authorization and upgrade contract for existing Telegram installations.

Likely owner: steipete

Owner confidence: high

Options:

- **Dedicated deletion opt-in (recommended):** Add close and reopen normally, but expose deleteForumTopic only through a distinct disabled-by-default action setting.
- **Default-enabled full lifecycle:** Expose close, reopen, and delete using the same default-enabled per-action model as create and edit.
- **Reversible lifecycle only:** Add close and reopen but keep permanent topic deletion outside the agent action surface.

## Reproduction Assessment

Yes. Current main and v2026.6.11 advertise and dispatch only topic-create and topic-edit, directly proving that close, reopen, and delete are unavailable.

## Solution Assessment

No, not exactly as proposed. The Telegram plugin and shared typed action family are the correct boundary, but irreversible deletion needs an explicit safe authorization and default contract rather than automatically inheriting create/edit behavior.
