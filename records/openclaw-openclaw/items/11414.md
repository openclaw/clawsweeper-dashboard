## Summary

Current main and the latest release still expose only Telegram forum-topic creation and editing; close, reopen, and delete remain meaningful missing capabilities. Keep this canonical feature request open for a maintainer decision because permanent deletion would inherit a default-enabled action model unless the public permission/configuration contract is deliberately narrowed.

## What This Changes

Add Telegram forum-topic close, reopen, and delete actions to the message tool alongside the existing create and edit actions.

## Best Possible Solution

Keep one plugin-owned Telegram topic lifecycle surface: add close and reopen consistently with create/edit, and expose permanent delete only through a maintainer-approved, disabled-by-default destructive capability with aligned schema, discovery, transport helpers, docs, and focused tests.

Options:

- **Dedicated delete opt-in (recommended):** Add close/reopen under topic management and expose permanent deletion only through a separate disabled-by-default action flag.
- **Shared topic authorization:** Authorize create, edit, close, reopen, and delete through the same topic-management action model.
- **Defer permanent deletion:** Implement close/reopen while leaving delete unsupported until a separate destructive-action design is sponsored.
