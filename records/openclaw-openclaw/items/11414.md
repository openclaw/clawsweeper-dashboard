## Summary

Keep open as the canonical remaining Telegram forum-topic lifecycle request. Topic creation and editing were merged, but the supplied July 16 review found no shared close, reopen, or delete lifecycle actions; the closed deletion-only PR is not a viable replacement. The destructive delete operation also needs an explicit security and product-boundary decision before implementation.

## What This Changes

Add Telegram message-tool actions to create, edit, close, reopen, and delete forum topics in enabled supergroups.

## Best Possible Solution

Implement a plugin-owned, explicit topic lifecycle contract: add close and reopen beside the existing create/edit actions, and add delete only after maintainers approve its destructive-operation authorization and confirmation semantics, with matching discovery, runtime, transport, configuration, docs, and contract tests.

Options:

- **Approve explicit lifecycle actions (recommended):** Add distinct close, reopen, and delete topic actions, with deletion governed by a maintainer-approved destructive-operation contract rather than overloading ordinary message delete.
- **Ship reversible operations first:** Land close and reopen on the existing Telegram action seam, and retain deletion as a separate follow-up until its authorization semantics are agreed.
- **Keep topic management out of the message tool:** Retain create/edit only and direct broader administrative automation to a separately designed plugin capability.
