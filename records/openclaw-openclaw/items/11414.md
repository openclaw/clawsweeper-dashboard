## Summary

Keep this canonical feature request open: current main covers topic creation and editing, but the reversible close/reopen operations and destructive deletion operation remain missing, and deletion requires a distinct permission and safety decision.

## What This Changes

Add Telegram forum-topic create, edit, close, reopen, and delete operations to the message tool.

## Best Possible Solution

Add explicit reversible `topic-close` and `topic-reopen` actions, and expose `topic-delete` only through a separately documented, default-off destructive-action gate with focused authorization, dispatch, and live Telegram proof.

## Maintainer Decision

Rationale: Telegram deletion irreversibly removes every message in the topic and uses a stronger administrator permission than the reversible lifecycle methods, so action naming and default exposure require explicit maintainer intent.

Options:

- **Split destructive deletion (recommended):** Add close and reopen normally, while placing `topic-delete` behind its own explicit default-off gate and documentation.
- **Exclude permanent deletion:** Implement create, edit, close, and reopen but leave deletion outside the agent-facing message tool.
- **Enable the full lifecycle:** Expose all lifecycle actions by default and rely on Telegram administrator permissions as the only guard.

## Risks / Open Questions

- Mapping permanent topic deletion onto the generic message `delete` action could erase an entire topic and all of its messages when the caller intended to delete one message.
- Close and reopen require `can_manage_topics`, while permanent deletion requires `can_delete_messages`; sharing one gate would obscure materially different authorization boundaries.
- New action names and config gates become user-facing message-plugin contracts, so inconsistent naming or default enablement would create compatibility and safety debt.
