## Summary

Keep open: current main and `v2026.6.11` still resolve Telegram approval prompts with `clear-actions`, which clears buttons but leaves the delivered approval message content in chat; same-repo fix attempts are closed unmerged, and the only open closing reference is a conflicting fork PR against an obsolete handler path.

## What This Changes

The issue asks for Telegram exec approval messages to disappear after the user approves instead of leaving the approval prompt in the chat.

## Best Possible Solution

Fix the active Telegram native approval runtime so resolved approvals use the shared `delete` final-action path, expired approvals keep the button-only clear path, and the fix includes focused tests plus redacted real Telegram proof.

## Reproduction Assessment

Yes, source-level: current main returns `clear-actions` for resolved Telegram approvals, and the shared runtime leaves delivered content in place for that action. I did not run a live Telegram approval flow in this read-only pass.

## Solution Assessment

Yes: the narrow maintainable fix belongs in `extensions/telegram/src/approval-handler.runtime.ts`, using the existing shared `delete` final-action seam for resolved approvals while preserving `clear-actions` for expiration.
