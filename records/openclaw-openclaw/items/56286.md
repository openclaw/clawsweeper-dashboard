## Summary

Keep open: current main and the latest release still resolve Telegram approval prompts with `clear-actions`, which clears buttons but leaves the delivered approval message visible; the same-repository fix attempts are closed unmerged, and the remaining fork PR is conflicting and targets a removed handler path.

## What This Changes

The issue requests that Telegram exec approval prompts be dismissed after the user approves instead of remaining visible in chat.

## Best Possible Solution

Fix the active Telegram native approval runtime so resolved approvals use the shared `delete` final-action path, expired approvals keep button-only `clear-actions`, and the branch includes focused tests plus redacted live Telegram proof.

## Reproduction Assessment

Yes, at source level: current main resolves Telegram approvals with `clear-actions`, and the shared runtime leaves delivered content in place for that final action. I did not run a live Telegram bot flow in this read-only review.

## Solution Assessment

Yes: the narrow maintainable fix is to use the existing shared `delete` final-action seam in `extensions/telegram/src/approval-handler.runtime.ts`, not to revive the removed delayed-delete handler branch.
