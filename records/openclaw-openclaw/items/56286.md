## Summary

Keep open: current main and the latest release still clear only the Telegram inline approval buttons after a resolved exec approval, leaving the approval message content in chat. The same-repo fix attempts are closed unmerged, and the remaining linked fork PR is conflicting and targets the removed handler path.

## What This Changes

The issue reports that Telegram exec approval prompts remain visible after the user clicks approve, when the expected behavior is for the approval message to disappear.

## Best Possible Solution

Fix `extensions/telegram/src/approval-handler.runtime.ts` so resolved approvals use the shared `delete` final-action path with `deleteMessageTelegram`, while expired approvals keep the button-only `clear-actions` path and the change has focused tests plus redacted live Telegram proof.

## Reproduction Assessment

Yes, source-level: current main resolves Telegram approvals with `clear-actions`, and the shared runtime leaves delivered content in place for that action. I did not run a live Telegram bot flow in this read-only review.

## Solution Assessment

Yes: the narrow maintainable fix is to use the existing shared `delete` final-action seam in the active Telegram approval runtime, not to revive the removed delayed-delete handler branch.
