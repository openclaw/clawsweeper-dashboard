## Summary

Keep open: current main and v2026.6.11 still resolve Telegram approval prompts with `clear-actions`, which clears inline buttons but leaves the approval message content in chat. The same-repo fix attempts are closed unmerged, and the remaining open fork PR is conflicting and targets the removed handler path.

## What This Changes

The issue asks for Telegram exec approval prompt messages to disappear after the user approves instead of leaving a stale approval bubble in chat.

## Best Possible Solution

Fix the active Telegram native approval runtime so resolved approvals use the shared `delete` final-action path, expired approvals keep button-only `clear-actions`, and the fix includes focused tests plus redacted real Telegram proof.

## Reproduction Assessment

Yes, source-level: current main returns `clear-actions` for resolved Telegram approvals, and the shared runtime leaves delivered content in place for that action. I did not run a live Telegram bot flow in this read-only review.

## Solution Assessment

Yes: the narrow maintainable solution is to use the existing shared `delete` final-action seam in `extensions/telegram/src/approval-handler.runtime.ts`, while preserving `clear-actions` for expired approvals. The obsolete delayed-delete handler branch should not be revived.
