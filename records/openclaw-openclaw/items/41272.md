## Summary

Keep open: current main and the latest release still reject explicit `timeoutSeconds: 0` in the Control UI cron form, while the gateway and cron runtime already accept zero as the no-timeout sentinel. The open linked pull request remains the active fix candidate, so the issue should stay open until that PR lands, is replaced, or is closed with an alternative fix path.

The issue asks the Control UI cron form to accept `timeoutSeconds: 0` as the no-timeout value.

## Best Possible Solution

Land or replace the focused Control UI fix so validation accepts explicit zero, payload construction preserves `timeoutSeconds: 0`, and regression coverage proves zero is valid while negative and malformed values remain invalid.
