## Summary

Keep open: current main and v2026.6.11 still reject or drop explicit `timeoutSeconds: 0` in the Control UI cron form, while the gateway/runtime contract accepts zero as no-timeout. The linked open pull request at https://github.com/openclaw/openclaw/pull/41275 uses closing syntax for this issue, so this should remain open until that fix lands or is replaced.

## What This Changes

The issue asks for the Control UI cron form to accept `timeoutSeconds: 0` as the no-timeout sentinel instead of treating it as invalid.

## Best Possible Solution

Land or replace the focused UI fix so validation accepts finite zero, the payload preserves explicit zero, negative and non-finite values remain invalid, and regression coverage matches the gateway contract.

## Solution Assessment

Yes. The narrow maintainable fix is in the Control UI cron form and payload builder, because the gateway schema and cron runtime already accept and interpret zero correctly.
