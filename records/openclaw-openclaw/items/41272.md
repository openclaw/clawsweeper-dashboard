## Summary

Keep open: current main and the latest release still reject or drop explicit `timeoutSeconds: 0` in the Control UI cron form, while the gateway and cron runtime already accept zero as the no-timeout sentinel. The linked open pull request at https://github.com/openclaw/openclaw/pull/41275 uses closing syntax for this issue, so this issue should stay open until that fix lands, is refreshed, or is replaced.

## What This Changes

The issue requests Control UI cron form support for `timeoutSeconds: 0` as the existing no-timeout mode.

## Best Possible Solution

Refresh, land, or replace the focused Control UI fix so finite zero is accepted and preserved, negative and non-finite input remains invalid, and regression tests cover zero plus non-numeric input without changing the gateway/runtime contract.
