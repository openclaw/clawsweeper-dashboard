## Summary

Keep open: current main and v2026.6.11 still reject `timeoutSeconds: 0` in the Control UI and drop explicit zero from the payload, while the gateway/runtime contract already accepts zero and an open linked PR owns the focused fix candidate.

## What This Changes

The issue asks for the Control UI cron form to accept and preserve `timeoutSeconds: 0` as the existing no-timeout sentinel.

## Best Possible Solution

Land or replace the linked Control UI fix so validation accepts finite zero, rejects invalid and negative values, preserves `timeoutSeconds: 0` in payloads, and updates focused UI tests.
