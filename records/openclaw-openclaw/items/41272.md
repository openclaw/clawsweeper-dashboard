## Summary

Keep open: current main still rejects and drops explicit Control UI cron `timeoutSeconds: 0`, while the gateway/runtime cron contract accepts zero as no-timeout. The open linked pull request is the active fix candidate, so the issue should remain open until that PR lands, is refreshed, or is replaced.

## What This Changes

The issue requests that the Control UI cron job form accept `timeoutSeconds: 0` as no-timeout and preserve that value when saving.

## Best Possible Solution

Land or replace the focused Control UI fix so validation accepts finite zero, payload building preserves explicit zero, negative and non-finite values remain invalid, and regression coverage matches the gateway cron contract.
