## Summary

Keep open: current main and the latest release still reject explicit `timeoutSeconds: 0` in the Control UI cron form, while the gateway and cron runtime contract already accepts zero as no-timeout. The open linked pull request is the current fix candidate, not close evidence.

## What This Changes

The issue asks for the Control UI cron form to accept `timeoutSeconds: 0` as no-timeout instead of showing `cron.errors.timeoutInvalid`.

## Best Possible Solution

Land or replace the focused UI fix in `ui/src/lib/cron/index.ts` so validation accepts finite zero, payload creation preserves explicit zero, invalid negative or non-finite values stay rejected, and regression coverage matches the gateway no-timeout contract.
