## Summary

Keep open: current main and latest release still reject or drop explicit `timeoutSeconds: 0` in the Control UI cron form, while the gateway cron contract accepts zero. The open linked pull request at https://github.com/openclaw/openclaw/pull/41275 is the active fix candidate, so this issue should stay open until that PR lands or is replaced.

## What This Changes

The issue reports that the Control UI cron form rejects an explicit `timeoutSeconds` value of `0` even though that value should mean no timeout.

## Best Possible Solution

Land or replace the linked focused UI fix so validation accepts finite zero, payload construction preserves explicit zero, invalid negative/non-finite input stays rejected, and regression coverage matches the gateway contract.
