## Summary

Keep open: current main and the latest release still reject explicit `timeoutSeconds: 0` in the Control UI cron form even though the cron backend accepts zero. The open linked pull request is an implementation candidate, so this issue remains necessary until that PR lands or is replaced.

## What This Changes

Accept `timeoutSeconds: 0` in the Control UI cron form as explicit no-timeout mode.

## Best Possible Solution

Refresh or replace the linked focused UI fix so the Control UI accepts finite zero, sends explicit `timeoutSeconds: 0`, keeps negative/non-finite values invalid, and updates regression coverage to match the backend contract.
