## Summary

Keep open: current main and the latest release still reject explicit Control UI cron `timeoutSeconds: 0`, and the open linked PR remains the active but unlanded fix candidate.

## What This Changes

The issue asks for the Control UI cron form to accept `timeoutSeconds: 0` as no-timeout and preserve that value in the submitted cron payload.

## Best Possible Solution

Land or replace the focused Control UI fix so validation accepts finite zero, payload building preserves explicit zero, negative and non-finite values remain invalid, and regression coverage matches the gateway cron contract.
