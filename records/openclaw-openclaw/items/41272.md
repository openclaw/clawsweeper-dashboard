## Summary

Keep open: current main and the latest release still reject explicit `timeoutSeconds: 0` in the Control UI cron form, while the backend cron contract already accepts zero as the no-timeout sentinel. The open linked pull request remains the active fix candidate, so this issue should stay open until that PR lands or is replaced.

## What This Changes

The issue asks for the Control UI cron form to accept `timeoutSeconds: 0` as an explicit no-timeout mode.

## Best Possible Solution

Land a focused Control UI fix that accepts explicit zero in validation, preserves `timeoutSeconds: 0` in the payload, and updates regression coverage; if the linked PR cannot be repaired, replace it with that narrow fix.
