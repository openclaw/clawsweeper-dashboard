## Summary

Keep open: current main and v2026.6.11 still reject or drop explicit `timeoutSeconds: 0` in the Control UI cron form, while the gateway/runtime contract already accepts zero. The open linked pull request at https://github.com/openclaw/openclaw/pull/41275 uses closing syntax, so this issue should remain open until that fix lands or is replaced.

## What This Changes

The issue requests that the Control UI cron form accept explicit `timeoutSeconds: 0` as no-timeout mode and preserve that value in the submitted cron payload.

## Best Possible Solution

Land or replace the focused UI fix so validation accepts finite zero, payload building preserves explicit zero, negative and non-finite values remain invalid, and regression coverage matches the gateway/runtime contract.
