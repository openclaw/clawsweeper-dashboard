## Summary

Keep open: current main and the latest release still reject explicit `timeoutSeconds: 0` in the Control UI cron form, while the gateway cron contract accepts zero. The open linked pull request is the candidate fix path, so this issue should stay open until that PR lands or is replaced.

## What This Changes

The issue reports that the Control UI cron form rejects `timeoutSeconds: 0`, which should represent no-timeout mode for cron agent-turn jobs.

## Best Possible Solution

Land or replace the linked focused UI fix so `validateCronForm` accepts finite zero, `buildCronPayload` preserves explicit zero, negative and non-finite values remain invalid, and the cron UI regression test matches the gateway contract.
