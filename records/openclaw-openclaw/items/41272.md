## Summary

Keep open: current main and the latest release still reject explicit `timeoutSeconds: 0` in the Control UI cron form, while the backend contract already accepts zero as the no-timeout sentinel. The open linked pull request is the active fix candidate, not close evidence.

## What This Changes

The issue requests that the Control UI cron form accept `timeoutSeconds: 0` as no-timeout mode instead of rejecting it during validation.

## Best Possible Solution

Land a focused Control UI fix that accepts explicit zero in validation, preserves `timeoutSeconds: 0` in the cron payload, and updates the cron form regression test; if the linked PR cannot be repaired, close it and replace it with that narrow fix.
