## Summary

Keep open: current main and the latest release still reject or drop explicit `timeoutSeconds: 0` in the Control UI cron form, while the gateway/runtime cron contract accepts zero. The open linked pull request at https://github.com/openclaw/openclaw/pull/41275 uses closing syntax for this issue, so this issue should stay open until that fix lands or is replaced.

## What This Changes

The issue asks for the Control UI cron form to accept `timeoutSeconds: 0` as an explicit no-timeout value.

## Best Possible Solution

Land or replace the focused Control UI fix so validation accepts finite zero, payload building preserves explicit zero, negative and non-finite values remain invalid, and regression coverage matches the gateway cron contract.
