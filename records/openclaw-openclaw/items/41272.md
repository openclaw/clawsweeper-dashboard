## Summary

Keep open: current main and the latest release still reject `timeoutSeconds: 0` in the Control UI even though cron runtime accepts 0 as the no-timeout sentinel. The open linked pull request remains the active fix candidate, so this issue should stay open until that PR lands, is refreshed, or is replaced.

## What This Changes

The issue asks for the cron job UI to accept `timeoutSeconds: 0` as a no-timeout value instead of rejecting it as invalid.

## Best Possible Solution

Land a current-path Control UI fix that accepts finite nonnegative timeout input, preserves explicit `0` in the cron payload, rejects invalid negatives/non-finite values, and updates focused regression coverage.
