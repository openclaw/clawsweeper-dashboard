## What This Changes

The issue requests that the Control UI cron job form accept `timeoutSeconds: 0` as an explicit no-timeout value instead of rejecting it.

## Best Possible Solution

Land, adopt, or replace the existing linked cron UI fix so validation accepts finite zero, the payload builder preserves explicit zero, and negative or non-numeric values remain invalid.
