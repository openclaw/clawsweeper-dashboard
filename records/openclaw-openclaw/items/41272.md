## Summary

Keep open: current main and v2026.6.11 still reject or drop explicit zero in the Control UI cron form, while the gateway schema and cron timeout policy already treat `timeoutSeconds: 0` as a valid no-timeout sentinel. The issue is also paired with the open fix candidate at https://github.com/openclaw/openclaw/pull/41275, so it should stay open until a viable fix lands or that PR is replaced.

## What This Changes

The issue asks the Control UI cron form to accept `timeoutSeconds: 0` as no-timeout instead of rejecting it.

## Best Possible Solution

Land or replace the focused Control UI fix so validation accepts explicit zero, the payload preserves `timeoutSeconds: 0`, negative or non-finite input remains rejected, and the cron UI tests cover the no-timeout case.

## Reproduction Assessment

Yes by source inspection. Current main rejects `timeoutSeconds: "0"` in `validateCronForm`, drops explicit zero in `buildCronPayload`, and the adjacent UI test still expects the invalid-timeout error.

## Solution Assessment

Partly. Accepting zero in validation is necessary, but the best fix must also preserve explicit `timeoutSeconds: 0` in the payload so cron receives the existing no-timeout sentinel.
