## Summary

Keep open: current main and v2026.6.11 still reject or drop explicit `timeoutSeconds: 0` in the Control UI cron form, while the cron gateway/runtime contract accepts zero. The open linked pull request at https://github.com/openclaw/openclaw/pull/41275 uses closing syntax for this issue, so this issue should stay open until that fix lands or is replaced.

## What This Changes

The issue asks for the Control UI cron form to accept `timeoutSeconds: 0` as no-timeout mode instead of showing `cron.errors.timeoutInvalid`.

## Best Possible Solution

Land or replace the focused Control UI fix so validation accepts finite zero, payload building preserves explicit zero, negative and non-finite values remain invalid, and regression coverage matches the gateway cron contract.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, by source inspection on current main: `validateCronForm` rejects `timeoutSeconds: "0"`, `buildCronPayload` drops explicit zero, and the gateway/runtime cron contract accepts zero.

## Solution Assessment

Yes. The best fix is the narrow Control UI alignment: accept and preserve explicit zero while keeping invalid timeout values rejected, because the backend contract and runtime already support zero.
