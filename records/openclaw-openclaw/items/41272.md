## Summary

Keep open: current main and the latest release still reject explicit `timeoutSeconds: 0` in the Control UI cron form, while the backend cron contract already accepts zero as the no-timeout sentinel. The open linked pull request at https://github.com/openclaw/openclaw/pull/41275 is the candidate fix path, not close evidence.

## What This Changes

The issue asks for Control UI cron job form validation to accept `timeoutSeconds: 0` as no-timeout mode.

## Best Possible Solution

Land or replace the focused Control UI fix so validation accepts explicit `0`, payload construction preserves `timeoutSeconds: 0`, malformed values still fail, and regression coverage covers zero and non-numeric input.

## Solution Assessment

Yes. The narrow maintainable solution is in the Control UI validation and payload conversion path because the gateway schema and cron runtime already support zero as the no-timeout value.
