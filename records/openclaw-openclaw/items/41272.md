## Summary

Keep open: current main and the latest release still reject `timeoutSeconds: 0` in the Control UI cron form, and the open linked pull request is the active fix candidate rather than close evidence.

## What This Changes

The issue asks for the cron job UI to accept `timeoutSeconds: 0` as the no-timeout mode instead of treating it as an invalid timeout.

## Best Possible Solution

Land or replace the linked PR with a focused Control UI fix that accepts zero, preserves `timeoutSeconds: 0` in the payload, and still rejects malformed or negative timeout input.

## Reproduction Assessment

Yes. Source inspection on current main shows `validateCronForm` rejects `timeoutSeconds: "0"`, `buildCronPayload` omits explicit zero, and the controller test still expects the invalid-timeout error.

## Solution Assessment

Yes for the fix direction, but not for a validation-only patch. The maintainable fix is in the existing Control UI cron controller and must update both validation and payload preservation while relying on the existing backend zero-timeout contract.
