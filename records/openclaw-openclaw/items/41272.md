## Summary

Keep open: current main and the latest release still reject `timeoutSeconds: 0` in the cron web UI even though the cron protocol/runtime accept zero as the no-timeout sentinel. The linked pull request https://github.com/openclaw/openclaw/pull/41275 is the active candidate, but it is currently conflicting and proof-blocked, so this issue should remain the canonical tracker until a fix lands.

## What This Changes

The issue asks for the cron web UI to accept and preserve `timeoutSeconds: 0` as no-timeout mode instead of treating it as a validation error.

## Best Possible Solution

Land a focused current-file fix that accepts zero in cron UI validation, preserves explicit zero in the submitted agent-turn payload, and updates the controller tests for zero, negative, and malformed timeout values.
