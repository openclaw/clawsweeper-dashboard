## Summary

Keep open: current main still rejects explicit Control UI cron `timeoutSeconds: 0` and would drop the value from the submitted payload, while the gateway/runtime cron contract already accepts zero as no-timeout. The open linked pull request remains the active fix candidate, so this issue should stay open until that PR lands, is refreshed, or is replaced.

## What This Changes

The issue requests allowing `timeoutSeconds: 0` in the cron job Control UI as the supported no-timeout mode.

## Best Possible Solution

Land or replace a focused Control UI fix that accepts finite zero, preserves explicit `timeoutSeconds: 0` in the payload, continues rejecting negative and non-finite values, and updates the cron UI regression tests.
