## Summary

Keep open: current main and the latest release still reject or drop explicit `timeoutSeconds: 0` in the Control UI cron form, while the gateway cron contract and runtime already support zero as no-timeout. The open linked pull request at https://github.com/openclaw/openclaw/pull/41275 uses closing syntax for this issue, so this issue should remain the canonical tracker until that fix lands or is replaced.

## What This Changes

The issue asks for the Control UI cron form to accept `timeoutSeconds: 0` as no-timeout mode instead of rejecting it as invalid.

## Best Possible Solution

Land or replace the focused UI fix so validation accepts finite zero, the payload preserves explicit zero, negative and non-finite values remain invalid, and regression coverage matches the gateway contract.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, by source inspection. Current main rejects `timeoutSeconds: "0"` in `validateCronForm`, drops explicit zero in `buildCronPayload`, and the adjacent UI test still expects the invalid-timeout error.

## Solution Assessment

Yes. The best fix is the narrow Control UI alignment: accept and preserve explicit zero while keeping invalid timeout values rejected, because the backend contract and runtime already support zero.
