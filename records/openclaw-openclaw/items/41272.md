## Summary

Keep open: current main and the latest stable release still reject or drop explicit `timeoutSeconds: 0` in the Control UI cron form, while the gateway cron contract accepts zero. The open linked pull request at https://github.com/openclaw/openclaw/pull/41275 uses closing syntax for this issue, so this issue should remain open until that fix lands, is refreshed, or is replaced.

## What This Changes

The issue reports that the cron job UI rejects `timeoutSeconds: 0`, which should mean no timeout.

## Best Possible Solution

Land or replace the focused Control UI fix so validation accepts finite zero, the payload preserves explicit zero, negative and non-finite values remain invalid, and regression coverage matches the gateway contract.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, by source inspection. Current main rejects `timeoutSeconds: "0"` in `validateCronForm`, drops explicit zero in `buildCronPayload`, and the adjacent UI test still expects the invalid-timeout error.

## Solution Assessment

Yes. The best fix is the narrow Control UI alignment: accept and preserve explicit zero while keeping invalid timeout values rejected, because the backend contract and runtime already support zero.
