## Summary

OpenClaw still lacks a general final-output sensitive-data sanitizer on current main; existing redaction covers logs, transcripts, tool/UI payloads, and channel scaffolding cleanup, so this should stay open for a maintainer/security product decision rather than be closed as implemented or queued as an automatic fix.

## What This Changes

Request automatic sanitization of sensitive values in agent responses and tool output, with configurable scopes, patterns, exceptions, reporting, and per-agent overrides.

## Best Possible Solution

Keep the issue open for a security/product design decision that chooses core versus plugin ownership, defines defaults/scopes/reporting, and reuses existing redaction helpers and outbound hook seams instead of adding a parallel sanitizer stack.
