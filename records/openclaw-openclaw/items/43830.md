## Summary

Keep this open: current main still lacks a general final-output sensitive-data sanitizer. Existing code redacts logs, persisted transcripts, diagnostics, and some tool/presentation paths, but final channel delivery only strips internal scaffolding or channel-specific presentation artifacts, so the requested security boundary still needs maintainer/security direction.

## What This Changes

The issue requests configurable automatic sanitization of sensitive data such as API keys, tokens, passwords, and PII in agent outputs and final responses.

## Best Possible Solution

Define a maintainer-approved security design that chooses core versus plugin ownership, reuses existing redaction helpers where possible, and adds focused coverage for final replies, tool-result-derived output, channel payloads, config/docs, and false-positive behavior.
