## Summary

Keep open: current main and the latest release still lack a general final-output sensitive-value sanitizer, while existing protection is scoped to logs, transcripts, tool/UI diagnostics, and internal scaffolding cleanup; this needs a maintainer security/product decision before implementation.

## What This Changes

The issue requests automatic sanitization of sensitive data in agent/tool outputs and final responses, with configurable modes, scopes, patterns, exceptions, and reporting.

## Best Possible Solution

Decide the security boundary first, then implement either a narrow core final-output policy that reuses existing redaction helpers and docs/schema tests, or an official plugin/ClawHub path using the existing outbound hooks if core should stay policy-light.
