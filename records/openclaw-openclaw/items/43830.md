## Summary

Keep open: current main and the latest release have log, transcript, tool-payload, diagnostic, and internal-scaffolding redaction, but they still do not provide the requested automatic sensitive-value sanitizer for final agent-visible outputs or the proposed output-sanitization configuration surface. The related privacy/sanitization implementation PRs are closed unmerged, so the remaining work is a maintainer/security product decision rather than conservative cleanup.

## What This Changes

The issue requests automatic sanitization of agent outputs for API keys, tokens, passwords, PII, and similar sensitive data, with new global and per-agent configuration controls.

## Best Possible Solution

Define a maintainer-approved security design for the final output boundary, defaults, config shape, false-positive policy, and whether the sanitizer belongs in core delivery, shared redaction helpers, plugin hooks, or a ClawHub plugin package.
