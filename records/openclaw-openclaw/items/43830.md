## Summary

Keep this open: current main has strong log, transcript, tool-payload, diagnostics, and internal-scaffolding redaction, but it still does not define a general sensitive-value sanitizer for final user-visible agent output; the remaining work is a security/product boundary decision rather than a safe automatic fix.

The issue requests automatic sanitization/redaction of sensitive data in agent outputs, tool outputs, and final responses with configurable modes and reporting.

## Best Possible Solution

Keep this issue open for a security/product design that chooses core versus plugin ownership, reuses the existing redaction engine where possible, and defines exact final-output, tool-output, provider-boundary, memory, config, docs, and test expectations before implementation.
