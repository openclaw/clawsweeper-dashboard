## Summary

Keep open: current main has strong adjacent redaction for logs, transcripts, tool payloads, diagnostics, and SecretRef/provider credentials, but it still lacks the requested automatic sensitive-data sanitizer for final user-visible agent output.

## What This Changes

Add automatic, configurable sanitization of API keys, tokens, passwords, and PII in agent outputs before user-visible delivery.

## Best Possible Solution

Define the approved core-vs-plugin security boundary first, then reuse the existing redaction registry in a narrow final-output sanitizer with focused tests for final replies, tool payloads, transcripts, and channel delivery as applicable.
