## Summary

Keep open: current main still lacks a general automatic sensitive-value sanitizer for final agent output, while existing protections cover logs, transcripts, tool/UI payloads, diagnostics, and internal scaffolding cleanup rather than the requested configurable outputSanitization policy.

## What This Changes

Request to add automatic sensitive-data sanitization for agent outputs, tool results, and responses with configurable modes, scopes, patterns, exceptions, and reporting.

## Best Possible Solution

Keep the issue open for a security/product design that chooses core versus plugin ownership, reuses the existing redaction helpers and outbound hook seams where appropriate, and defines defaults, scope, reporting, docs, and tests before implementation.
