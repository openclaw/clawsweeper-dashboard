## Summary

This member-authored, protected-label PR remains necessary because current main does not provide catalog-initiated session creation, but the current head should not merge yet: its globally advertised catalog model is submitted with whichever agent the user selects even though runtime routing is agent-scoped. The additive catalog direction is plausible, but the permanent plugin SDK and gateway protocol contract also needs explicit owner confirmation.

## What This Changes

The PR adds catalog-targeted session creation, per-agent sidebar creation actions and hierarchy styling, and duplicate-session suppression for Claude Code-backed OpenClaw sessions.

## Best Possible Solution

Keep an additive generic catalog-creation capability, but carry catalog identity into the new-session flow and validate or recompute its target for the selected agent before creation, with multi-agent override coverage and a documented narrow SDK contract.
