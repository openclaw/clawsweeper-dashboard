## Summary

Keep open. The patch correctly starts consuming the existing channel threading contract, but its fallback still treats any non-empty unregistered channel identifier as known and preserves an explicit reply tag while `replyToMode` is off. That conflicts with the documented known-provider-only default and the PR’s stated fail-closed behavior. It also needs after-fix real channel/plugin proof before merge. Likely related people: Vincent Koc (high confidence) for Slack’s threading opt-out work, and aldoeliacim (medium confidence) for the earlier shared explicit-reply-tag behavior.

## What This Changes

This PR changes shared reply filtering so a loaded channel’s threading adapter can opt out of preserving explicit reply tags when reply mode is off, while retaining the deprecated adapter-field alias.

## System Context

Inbound channel messages enter the auto-reply flow, which applies the configured reply mode before an outgoing message reaches its channel transport. Channel plugins declare threading traits, and this shared filter must translate those declarations without allowing unknown channel identifiers to bypass the off-mode policy.
