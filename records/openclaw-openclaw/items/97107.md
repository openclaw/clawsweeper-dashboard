## Summary

Keep open, but this head is not merge-ready: the PR addresses a real exec-friction area, but it broadens the `security=full` bypass into approval mode and the docs now overstate when host approvals stop applying. The contributor's proof is CI/unit-test output only, so the external-PR real behavior proof gate is still not satisfied.

## What This Changes

The PR threads exec security into script preflight so `security=full` bypasses the ambiguous-interpreter fail-closed heuristic, then updates exec tests and docs for that behavior.

## Best Possible Solution

Narrow the policy change so approval-mode `ask=always` keeps the ambiguous-interpreter fail-closed protection unless a maintainer explicitly accepts that security-boundary expansion, align the docs/tests with the chosen policy, and add redacted real behavior proof.

## Reproduction Assessment

Yes by source inspection for the broader no-target examples: current main does not skip script preflight for `security=full, ask=on-miss`, and the existing fail-closed cases reject ambiguous interpreter forms. The exact direct `python3 some_script.py | head -30` shape appears less clear because current main parses direct script operands before the ambiguous branch.

## Solution Assessment

No: the PR is a plausible mitigation for full/on-miss false positives, but applying the bypass to `ask=always` crosses the approval-mode boundary and the docs change misstates when approvals apply. The safer fix is to preserve approval-mode fail-closed behavior unless maintainers approve the broader policy.
