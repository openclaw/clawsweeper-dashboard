Keep open: the patch is narrow, but it deliberately broadens an exec security boundary for `security="full"` with approval-gated ask modes, and the latest contributor proof is still CI/unit-test output rather than a real exec/preflight run.

## What This Changes

Threads exec security into script preflight, skips the ambiguous-interpreter fail-closed heuristic whenever security is `full`, and updates exec docs plus regression tests.

## Best Possible Solution

Have maintainers decide whether full security alone should bypass the ambiguous-interpreter heuristic, then either land this with aligned approval docs and live proof or scope the bypass back to the YOLO ask-off contract.

## Reproduction Assessment

Yes, for the broader policy behavior from source: current main only skips script preflight for gateway `security=full` with `ask=off`, so full-security `ask=on-miss` and `ask=always` reach the fail-closed helper. I did not run a live exec command in this read-only review, and the original direct `python3 script.py | head` shape appears separately target-extractable on current main.

## Solution Assessment

Unclear until maintainers decide the trust policy. The implementation is narrow, but the best fix may be either this broader full-security bypass with aligned docs and proof or keeping the bypass limited to YOLO ask-off behavior.
