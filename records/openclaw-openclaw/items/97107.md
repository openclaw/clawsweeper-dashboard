## Best Possible Solution

Narrow the bypass to the maintainer-approved full-trust mode, or get explicit security/product approval for the broader ask-independent policy, then add real exec proof before merge.

## Solution Assessment

No for the current PR shape. Bypassing the heuristic for `security=full` without carrying ask mode is plausible for `on-miss`, but too broad for `ask=always` without maintainer security/product approval.
