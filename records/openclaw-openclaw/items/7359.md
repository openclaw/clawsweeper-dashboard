## Summary

Keep open. Current main still preserves the reported Slack blind spot: Slack DM/main sessions and Slack channel sessions resolve to different session keys, message-tool sends mirror only to the destination session, and default session-tool visibility does not expose sibling channel sessions back to a DM turn.

## What This Changes

Request a safe Slack self-activity recall path so an agent asked in a DM can reference its own messages sent to Slack channels.

## Best Possible Solution

Add a bounded Slack self-activity recall path keyed by agent, Slack account/team, destination channel/thread, and Slack message id/timestamp, exposing only authorized agent-authored outbound messages without merging full transcripts or widening general session visibility.

## Reproduction Assessment

Yes, at source level. Current main routes Slack DMs and Slack channel sends to distinct session keys, mirrors outbound sends to the destination session, and default tree session visibility denies sibling channel history from the DM/main turn.

## Solution Assessment

No for the broad unified-session options in the discussion. The safer solution is a narrow authorization-aware self-activity recall path, potentially using existing sent-hook signals as input, rather than merging full Slack DM and channel transcripts.
