## Summary

Keep open. Current main and v2026.6.11 still keep Slack DM/main sessions separate from Slack channel sessions, mirror message-tool sends only to the destination session, and default session-tool visibility does not expose sibling channel sessions back to a DM turn; the remaining work is a product/security design item, not conservative cleanup.

## What This Changes

The issue requests that a Slack agent in a DM/main session be able to recall its own outbound messages sent to Slack channels.

## Best Possible Solution

Add a bounded Slack self-activity recall path keyed by agent, Slack account/team, destination channel/thread, and Slack message id/timestamp, exposing only the agent's own authorized outbound messages without merging full transcripts or widening general session visibility.

## Reproduction Assessment

Yes, at source level. Current main routes Slack DMs and Slack channel sends to distinct session keys, mirrors outbound sends to the destination session, and default tree session visibility denies the sibling channel session.

## Solution Assessment

No for the broad unified-session options proposed in discussion. A narrow, authorization-aware self-activity recall path is safer than merging full Slack DM and channel transcripts or globally widening session visibility.
