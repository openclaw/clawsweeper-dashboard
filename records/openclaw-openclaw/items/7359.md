## Summary

Keep open. Current main still has the Slack DM/channel self-activity gap: channel sends resolve and mirror to the destination session, while default session-tool visibility does not expose sibling channel sessions back to a DM/main turn; the remaining fix needs product and security boundary decisions.

## What This Changes

Request that Slack DM sessions can recall the agent's own outbound messages sent to Slack channels so the agent can answer follow-up questions coherently.

## Best Possible Solution

Add a bounded Slack self-activity recall path keyed by agent, Slack account/team, destination channel/thread, and Slack message id/timestamp, exposing only authorized agent-authored outbound messages without merging full transcripts or widening general session visibility.

## Reproduction Assessment

Yes, at source level. Current main routes Slack DMs and Slack channel sends to distinct session keys, mirrors outbound sends only to the destination session, and default tree session visibility denies sibling channel history from the DM/main turn.

## Solution Assessment

No for the broad unified-session or generic cross-session-history options in the discussion. The safer solution is a narrow authorization-aware self-activity recall mechanism, potentially fed by message_sent signals, rather than merging full Slack DM and channel transcripts.
