## Summary

Keep open. Current main still separates Slack DM/main sessions from Slack channel sessions, mirrors message-tool sends only into the destination session, and keeps default session-tool visibility scoped to the requester tree, so the requested Slack self-activity recall remains unimplemented and needs product/security design.

## What This Changes

Request Slack self-activity recall so a DM/main session can see the agent's own outbound Slack channel messages.

## Best Possible Solution

Add a bounded Slack self-activity recall path keyed by agent, Slack team/account, destination channel/thread, and Slack message id/timestamp, exposing only authorized own outbound messages without merging full transcripts or widening general session visibility.

## Reproduction Assessment

Yes, at source level. Current main routes Slack DMs and Slack channels into separate session keys, mirrors outbound sends to the destination session, and default tree session visibility denies the sibling channel session.

## Solution Assessment

No for the broad unified-session options in the discussion. A narrow, authorization-aware self-activity recall path is safer than merging Slack DM and channel transcripts or globally widening session visibility.
