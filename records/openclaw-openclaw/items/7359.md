## Summary

Keep open. Current main and the latest tagged release still route Slack DMs and Slack channel conversations into separate session buckets, mirror message-tool sends only into the destination session, and keep default session-tool visibility scoped away from sibling channel sessions, so the requested Slack self-activity recall remains missing.

## What This Changes

The issue requests a Slack self-activity view so an agent asked in DMs can recall its own outbound Slack channel messages without losing cross-context continuity.

## Best Possible Solution

Add a bounded Slack self-activity recall path keyed by agent, Slack account/team, destination channel/thread, and Slack message id/timestamp, exposing only the agent's own authorized outbound messages without merging full transcripts or globally widening session visibility.

## Reproduction Assessment

Yes, at source level. Current main routes Slack DMs and Slack channels into separate session keys, mirrors outbound sends to the destination session, and default tree session visibility denies the sibling channel session.

## Solution Assessment

No for the broad unified-session options proposed in the discussion. A narrow, authorization-aware self-activity recall path is safer than merging full Slack DM and channel transcripts or globally widening session visibility.
