## Summary

Keep open. Current main records outbound Slack messages in the destination conversation session, while DM/main and channel sessions remain separate and default session-tool visibility excludes sibling sessions; the requested privacy-scoped recall remains unimplemented and needs an explicit product/security contract. ([github.com](https://github.com/openclaw/openclaw/blob/main/src/routing/session-key.ts))

## What This Changes

Allow an agent in a Slack DM session to recall and reference messages that the same agent previously sent to Slack channels.

## Best Possible Solution

Add a narrowly authorized, queryable outbound-activity ledger keyed by agent, Slack workspace/account, destination channel or thread, and Slack message identity, with explicit retention and edit/delete handling; expose only self-authored activity to DM/main sessions without merging full transcripts or widening general session visibility.

Options:

- **Add a scoped activity ledger (recommended):** Record and query only the agent's own outbound Slack activity with workspace, account, destination, authorization, retention, and deletion constraints.
- **Use broad same-agent visibility:** Document `tools.sessions.visibility: "agent"` as the solution, accepting that it exposes complete same-agent sibling transcripts rather than only self-authored Slack activity.
- **Preserve session isolation:** Decline automatic cross-session recall and document explicit memory or session-tool workflows as the supported boundary.

## Reproduction Assessment

Yes at source level: outbound sends are routed and mirrored to the destination Slack session, while default `tree` visibility prevents the requesting DM/main session from accessing that sibling session. A live Slack reproduction was not run during this read-only review.

## Solution Assessment

No, neither a unified Slack session nor blanket same-agent transcript visibility is the best fix. A narrow self-authored activity ledger preserves session isolation while solving the observable recall problem.
