## Summary

Keep open. Current main and v2026.6.11 still separate Slack DM/main and channel sessions, mirror message-tool sends only to the destination session, and keep default session tools scoped to the current tree, so the requested Slack self-activity recall remains unimplemented and needs product/security design.

## What This Changes

Request to let Slack DM sessions recall the agent's own outbound Slack channel messages and activity across isolated sessions.

## Best Possible Solution

Add a narrow, authorization-aware Slack self-activity recall path keyed by agent, Slack account/team, destination channel/thread, and Slack message id/timestamp, without merging full DM/channel transcripts or widening general session visibility.

## Reproduction Assessment

Yes, at source level. Current main still separates Slack DM/main and channel session keys, mirrors outbound sends only to the destination session, and defaults session tools to tree visibility that excludes sibling channel sessions.

## Solution Assessment

No for the broad unified-session options. The safer direction is a bounded self-activity ledger or scoped session-history bridge for the agent's own authorized outbound Slack messages only.
