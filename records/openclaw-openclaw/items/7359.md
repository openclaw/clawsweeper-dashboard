## Summary

Keep open. Current main still has the reported Slack DM/channel self-activity blind spot: Slack DMs and channels are separate session buckets, outbound message-tool sends mirror into the destination session, and default session-tool visibility does not expose sibling channel sessions back to a DM turn.

## What This Changes

The issue requests Slack self-activity visibility so an agent in a DM can recall its own outbound messages sent to Slack channels.

## Best Possible Solution

Add a bounded Slack self-activity recall path keyed by agent, Slack account/team, destination channel/thread, and Slack message id/timestamp, exposing only authorized agent-authored outbound messages without merging full transcripts or widening general session visibility.

- **Shared Session Grouping:** Treat this as part of broader configurable shared Slack/Discord channel sessions, accepting larger context, migration, and privacy design work.
- **Keep Isolation Documented:** Keep current session isolation and document that operators must opt into broader session visibility or manual memory workflows.

## Reproduction Assessment

Yes, at source level. Current main routes Slack DMs and Slack channel sends to distinct session keys, mirrors outbound sends only to the destination session, and default tree session visibility denies sibling channel history from the DM/main turn.

## Solution Assessment

No for the broad unified-session or generic cross-session-history options in the discussion. The safer solution is a narrow authorization-aware self-activity recall mechanism, potentially fed by message_sent signals, rather than merging full Slack DM and channel transcripts.
