## Summary

Current main still has the reported Slack blind spot: outbound sends are recorded under the destination channel session, while a DM/main turn does not receive sibling channel history under default tree visibility. No merged fix or canonical replacement now owns the narrower self-activity request, and the access boundary still needs maintainer product/security direction.

## What This Changes

Provide a Slack DM session with privacy-scoped recall of the same agent’s outbound channel messages without merging complete DM and channel transcripts.

## Best Possible Solution

Add a plugin-owned, canonical SQLite self-activity record or narrowly scoped query that exposes only the agent’s own authorized Slack outbound messages, keyed by agent, Slack account/team, destination, thread, and message ID with bounded retention; do not merge full transcripts or broaden general session visibility.

- **Sibling session history access:** Allow DM turns to query sibling Slack session transcripts, accepting a substantially broader content and authorization surface.
- **Preserve strict isolation:** Keep current boundaries and make explicit shared memory or targeted session operations the supported cross-context workflow.

## Reproduction Assessment

Yes at source level: current routing creates separate DM/main and channel sessions, outbound sends mirror only to the destination session, and default tree visibility excludes sibling channel sessions. This read-only review did not perform a live Slack workspace reproduction.

## Solution Assessment

No, unifying all Slack activity into one session is not the best solution because it weakens isolation and can leak unrelated context. A bounded self-activity surface is the narrowest maintainable direction.
