## Summary

Keep open. Current main still has the Slack DM/channel self-activity blind spot: DM and channel sessions remain separate, outbound sends are mirrored only to the destination session, and the merged Slack `message_sent` hook work provides an event feed but no DM-visible recall path.

## What This Changes

Request Slack DM/main sessions be able to recall the agent's own outbound messages sent to Slack channels without merging full channel transcripts.

## Best Possible Solution

Add a bounded Slack self-activity recall path keyed by agent, Slack team/account, destination channel/thread, and Slack message id/timestamp, exposing only authorized agent-authored outbound messages without merging full transcripts or widening general session visibility.

- **Fold into shared sessions:** Treat this as part of the broader shared-session design in https://github.com/openclaw/openclaw/issues/19929, accepting larger routing, migration, and privacy scope.
- **Document isolated behavior:** Keep current session isolation and document that operators need explicit memory/plugin workflows for cross-channel recall.

## Reproduction Assessment

Yes, at source level. Current main routes Slack DMs and Slack channel sends to distinct session keys, mirrors outbound sends only to the destination session, and default tree session visibility denies sibling channel history from the DM/main turn.

## Solution Assessment

No for the broad unified-session or generic cross-session-history options in the discussion. The safer solution is a narrow authorization-aware self-activity recall mechanism, potentially fed by `message_sent` signals, rather than merging full Slack DM and channel transcripts.
