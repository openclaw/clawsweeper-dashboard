## Summary

Current main still defaults Slack DM and channel activity into separate session scopes, so the reported blind spot remains unless an operator enables broader same-agent session-tool visibility. Keep this open because choosing between that broad transcript access and a narrower outbound-only recall surface is an unresolved product and privacy decision.

## What This Changes

Add a privacy-safe way for a Slack DM session to recall the agent’s own outbound channel messages and follow up on that activity.

## Best Possible Solution

Keep `tree` as the secure default and add a narrow self-activity recall contract that records only the agent’s outbound Slack deliveries with bounded retention, redaction, account/team isolation, destination identifiers, and access checks; document `tools.sessions.visibility: agent` only as the broader trusted-workspace alternative.

## Reproduction Assessment

Yes, at source level. Default `tree` visibility excludes sibling Slack channel sessions, and outbound sends are mirrored to the destination session; this read-only review did not run a live Slack workspace reproduction.

## Solution Assessment

No, a unified Slack session or general automatic sibling-session visibility is not the best fix. A bounded outbound-only activity surface preserves session and audience isolation better, while existing `agent` visibility remains an explicit broader option.
