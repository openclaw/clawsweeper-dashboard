## Summary

Current main still preserves separate Slack DM/main and channel sessions, mirrors outbound content into the destination session, and defaults agent session tools/search to tree visibility; the metadata-only audit ledger does not provide message recall. The issue remains necessary, but any cross-session content bridge needs an explicit privacy and product contract. ([github.com](https://github.com/clawdbot/clawdbot/blob/main/docs/channels/slack.md))

## What This Changes

Add a Slack-scoped way for a DM session to recall the agent’s own outbound channel messages without merging unrelated conversations.

## Best Possible Solution

Add a bounded, agent-facing outbound activity record keyed by agent, Slack account/team, destination channel/thread, and Slack message identity, exposing only the agent’s own sent content under an explicit authorization, retention, and deletion contract rather than merging full transcripts.

- **Use agent-wide session visibility:** Document an opt-in tools.sessions.visibility=agent path, accepting that it exposes broader inbound and outbound transcript content than this request needs.
- **Preserve isolation:** Keep channel content unavailable from DM sessions and document explicit memory or session-tool workflows for operators who accept broader access.

## Reproduction Assessment

Yes at source level: Slack DMs and channels resolve to separate sessions, outbound content is mirrored only to the destination, and default tree visibility excludes the sibling channel session. A live Slack run was not needed to establish the current design gap.

## Solution Assessment

No, merging Slack sessions or enabling broad agent-wide transcript visibility is not the best fix. A narrow self-authored outbound activity surface is safer and more maintainable, but its authorization and retention contract needs maintainer approval first.
