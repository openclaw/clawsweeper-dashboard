## Summary

Keep open. This remains a distinct Slack cross-session recall request, and the latest maintainer-facing review kept it open because exposing channel activity inside DM turns requires an explicit privacy and authorization contract rather than a routine transcript merge.

## What This Changes

Add a way for a Slack DM session to recall the agent’s own messages previously sent to Slack channels without losing coherent conversation state.

## Best Possible Solution

Define and implement a narrowly authorized Slack self-activity recall surface—keyed to the same agent and Slack account and limited to the agent’s outbound message metadata/content—without merging general DM and channel transcripts or widening sibling-session tool visibility.

Options:

- **Approve scoped self-activity recall (recommended):** Add a Slack-owned, same-agent/account activity record that exposes only the agent’s outbound channel messages with destination metadata to authorized DM turns.
- **Keep session isolation strict:** Retain current session separation and document that cross-context recall is intentionally unavailable unless a future explicit capability is designed.
- **Design a generic session-history capability:** Create a broader SDK-level authorization contract only if maintainers want configurable cross-session history beyond Slack self-activity.

No high-confidence live reproduction is currently attached to this review. The prior source review provides a medium-confidence path: a Slack DM/main session, a separate channel session, and an outbound message-tool send remain separate unless a deliberately scoped bridge is added.

## Solution Assessment

Unclear until maintainers choose the privacy contract. A same-agent, same-account self-activity ledger is safer than unified transcripts or unrestricted sibling-session visibility because it limits recall to the reported need.
