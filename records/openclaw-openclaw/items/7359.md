## Summary

Keep open. The central behavior remains a distinct Slack cross-session recall gap: outbound channel sends are retained with their destination session while a DM/main session does not automatically receive sibling-session context. Bridging that gap needs an explicit privacy and authorization contract, not a routine session-history merge.

## What This Changes

Add a privacy-scoped way for a Slack DM session to recall the agent’s own outbound messages sent to Slack channels or threads.

## System Context

Slack inbound events and message-tool sends are mapped into OpenClaw session keys. The session transcript and session tools then determine what an agent can recall during a later DM turn, so cross-session recall affects both conversational continuity and privacy boundaries.

## Architecture Diagram

flowchart LR
  A[Slack DM or channel event] --> B[Slack routing]
  C[Agent message-tool send] --> D[Destination session route]
  B --> E[Session key and transcript]
  D --> E
  E --> F[DM turn session visibility]
  F --> G[Agent recall and reply]

## Best Possible Solution

Define a narrow Slack self-activity recall contract keyed by agent and Slack workspace that exposes only the agent’s own outbound channel/thread messages to an authorized DM/main session, while leaving ordinary transcript visibility and session isolation unchanged.
