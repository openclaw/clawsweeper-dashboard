## Summary

Keep open. Current main still has the Slack DM/channel self-activity blind spot: Slack channel sends are routed and mirrored to the destination channel session, while default session visibility does not expose that sibling channel session back to the DM/main turn.

## What This Changes

The issue requests Slack DM/main-session visibility into the agent's own outbound Slack channel messages so the agent can answer follow-up questions about messages it sent elsewhere.

## Best Possible Solution

Add a bounded Slack self-activity recall path keyed by agent, Slack team/account, destination channel/thread, and Slack message id/timestamp, exposing only authorized agent-authored outbound messages without merging full transcripts or widening general session visibility.

## Reproduction Assessment

Yes, at source level. Current main routes Slack DMs and Slack channel sends to distinct session keys, mirrors outbound sends only to the destination session, and default tree session visibility denies sibling channel history from the DM/main turn.

## Solution Assessment

No for the broad unified-session or generic cross-session-history options in the discussion. The safer solution is a narrow authorization-aware self-activity recall mechanism, potentially fed by message_sent signals, rather than merging full Slack DM and channel transcripts.
