## Summary

Current main still has the reported Slack blind spot: outbound sends are recorded only in the resolved destination session, while default tree visibility prevents a DM session from reading an unrelated sibling channel session. The newer audit ledger is metadata-only, and lifecycle hooks do not provide an agent-facing recall path, so this issue remains necessary and requires an explicit product/security decision.

## What This Changes

Allow a Slack DM session to recall the same agent’s outbound messages and conversations from separate Slack channel sessions.

## Best Possible Solution

Keep destination transcripts isolated and add a permissioned record of successful self-authored outbound messages, stored in the appropriate SQLite owner and queryable only through explicit agent, workspace, account, and destination authorization with bounded retention and deletion semantics.
