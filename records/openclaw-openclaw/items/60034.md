## Summary

Current main and the latest release still lack the requested session-memory path/template configuration. The related outputDir PR was closed unmerged, and the remaining question is a compatibility-sensitive product/config contract rather than conservative cleanup.

## What This Changes

The issue asks for the bundled `session-memory` hook to support configurable output paths and filename templates instead of always writing flat dated files under the workspace memory directory.

## Best Possible Solution

Define a backward-compatible, workspace-safe session-memory artifact contract first, then implement only the accepted path/template behavior with docs and focused upgrade-proof coverage.

Options:

- **Approve a narrow outputDir contract (recommended):** Add one workspace-relative, root-validated `outputDir` option while keeping the existing filename format and collision behavior unchanged.
- **Approve full path and filename templates:** Support output path and filename templates only after specifying allowed tokens, validation, collision rules, docs, and tests for upgrade/fresh-install behavior.
- **Keep the hook fixed for now:** Leave `session-memory` at the fixed memory layout and steer users toward documented memory-search guidance or a future plugin-level memory artifact surface.

Yes. Source inspection on current main and `v2026.6.11` shows the hook still writes to `<workspace>/memory` with a fixed date-plus-slug filename; I did not run a live `/new` flow because the source and tests already establish the current behavior.

Unclear. Configurable output is a plausible fix, but the proposed full templating/daily/cleanup scope is broader than the narrowest safe first step and needs maintainer product direction.
