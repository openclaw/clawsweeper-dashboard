## Label Justifications

- `P1`: Current agent find and grep calls can remain hung indefinitely when their helper process stalls and no outer abort signal is supplied.
- `merge-risk: 🚨 compatibility`: The fixed 60-second default can stop searches that existing users previously allowed to run longer, including searches that are still making progress.
- `merge-risk: 🚨 availability`: The PR changes child termination and stream teardown across timeout, abort, and result-limit paths, so an incorrect lifecycle decision could stall calls or terminate useful work.

## Summary

Keep open: the prior forced-termination finding is addressed with bounded SIGKILL escalation, stream cleanup, and real-process coverage. The remaining blocker is an explicit maintainer choice between a fixed 60-second total-runtime deadline and an inactivity deadline that preserves long-running searches which continue making progress.

## What This Changes

The PR adds 60-second execution deadlines, forced child-process termination, stream cleanup, and regression coverage for stalled fd and ripgrep executions in the agent find and grep tools.

## Best Possible Solution

Use a 60-second inactivity deadline that resets on meaningful stdout or stderr progress, while retaining the new bounded SIGTERM-to-SIGKILL escalation and deterministic stream cleanup; if maintainers intentionally prefer a hard total-runtime cap, record that choice and cover a progressing long search in tests.
