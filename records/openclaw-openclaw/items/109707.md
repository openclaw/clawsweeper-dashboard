## What This Changes

The PR adds fixed 60-second execution deadlines and regression tests for spawned fd and ripgrep search helpers.

## Best Possible Solution

Keep a bounded search deadline, but define whether it measures total runtime or inactivity, then use definitive child termination with complete stream cleanup and coverage for a helper that ignores the initial signal.

## Maintainer Decision

Question: Should built-in find and grep enforce a fixed 60-second total-runtime deadline, or should they time out only after 60 seconds without search activity?

Rationale: Both choices prevent indefinite hangs, but a total-runtime deadline can terminate legitimate large or remote-tree searches while an inactivity deadline requires slightly more lifecycle logic.

Likely owner: c19354837

Owner confidence: medium

Options:

- **Use an inactivity deadline (recommended):** Reset the 60-second deadline on meaningful helper output and force-terminate only when the search has made no progress for the full interval.
- **Keep the wall-clock deadline:** Accept that all searches longer than 60 seconds fail, while still requiring definitive termination and cleanup before merge.
- **Defer the execution timeout:** Pause this PR until maintainers establish a shared timeout contract for built-in filesystem search tools.

## Solution Assessment

No, not yet. Adding a bounded deadline is the right boundary, but the implementation should guarantee subprocess termination and use maintainer-approved total-runtime or inactivity semantics.
