## Summary

Keep open: current main and the latest release still lack Android Talk Bluetooth input-route selection, and the issue has source-level plus adb reproduction evidence. I found no duplicate or merged/open fix that owns the remaining Android headset microphone work.

## What This Changes

Android realtime Talk should capture from a connected Bluetooth headset microphone, or at least expose the active/selectable input route, instead of silently using the phone microphone.

## Best Possible Solution

Fix Android Talk capture so it selects and restores the appropriate Bluetooth input route when available, reports the active route when useful, and proves the behavior on a real Android Bluetooth headset setup.

## Reproduction Assessment

Yes at source and reporter-evidence level: current main records realtime Talk audio with AudioRecord and no input-route selection, while the issue includes adb evidence that OpenClaw was recording from AUDIO_DEVICE_IN_BUILTIN_MIC. I did not run the Pixel/Bluetooth hardware reproduction myself.

## Solution Assessment

Unclear pending Android route design: the fix belongs in Android Talk capture rather than Gateway/provider code, but maintainers should choose the automatic routing, active-route display, and fallback UX before implementation.
