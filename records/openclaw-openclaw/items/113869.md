## Summary

Keep this PR open. It targets a credible multi-turn OpenAI Responses replay failure, but the new shared `rs_tmp_` prefix rule drops reasoning state across generic and proxy-compatible Responses paths without an established upstream contract for that prefix; it also lacks after-fix real provider evidence.

## What This Changes

The PR stops transient OpenAI Responses reasoning items with `rs_tmp_*` IDs from being persisted or replayed, while retaining their visible reasoning summaries.

## System Context

OpenAI Responses streaming converts provider reasoning output into assistant transcript blocks. Later turns pass those transcript blocks through two Responses request converters, which can replay provider reasoning state into the next request.

## Best Possible Solution

Establish the transient-item contract with a redacted after-fix OpenAI Responses run, then scope filtering to the provider or capability boundary that guarantees `rs_tmp_*` items are non-replayable and retain focused coverage for stable and proxy-compatible replay.
