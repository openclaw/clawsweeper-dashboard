## Summary

The patch is correct, focused, and still necessary on current main: ClawHub GitHub resolutions are accepted without full-SHA validation even though the resulting install is marked immutable. The PR fixes that at the correct acceptance boundary, has convincing real CLI proof, and introduces no actionable correctness or security finding; the only merge-relevant tradeoff is intentional rejection of nonconforming third-party registry responses.

## What This Changes

The PR rejects mutable or malformed ClawHub GitHub refs and canonicalizes accepted full commit SHAs before download, policy evaluation, provenance, lock metadata, and telemetry.

## Best Possible Solution

Land one acceptance-boundary validation that makes the successful resolver object the canonical immutable identity, while retaining direct Git installation as the explicit supported path for mutable refs.
