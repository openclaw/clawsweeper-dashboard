## Summary

Keep open for maintainer review: current main still allows the resolver commit string to reach GitHub codeload and install metadata, and the PR is a narrow, well-proven fix, but it deliberately tightens compatibility for custom ClawHub-compatible registries that may return branch, tag, or short-SHA refs.

## What This Changes

The PR validates ClawHub GitHub-backed skill resolver commits as full immutable SHAs before download and uses the normalized SHA for install metadata, with regression tests.

## Best Possible Solution

Keep the immutable-commit guard and merge after maintainers accept that ClawHub-compatible GitHub install resolutions must be full commit SHAs, with custom-registry mutable-ref leniency deliberately unsupported.

## Solution Assessment

Yes, subject to maintainer compatibility acceptance. Reusing the existing 40-hex normalizer at the lifecycle boundary covers the only current downloader caller and keeps download, display, and recorded provenance aligned.
