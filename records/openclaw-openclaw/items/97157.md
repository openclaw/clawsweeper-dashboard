## Summary

Keep open for maintainer review: the patch is a narrow, well-supported hardening of the ClawHub GitHub-backed skill install path, but it deliberately makes custom ClawHub-compatible registries fail closed when they return branch names, tags, or short SHAs.

## What This Changes

The PR validates ClawHub GitHub-backed skill install resolver commits as full immutable commit SHAs before download and uses the normalized commit in install metadata.

## Best Possible Solution

Keep the immutable-commit guard and merge after maintainers accept that ClawHub-compatible GitHub install resolutions must return full commit SHAs, with mutable-ref custom-registry leniency deliberately unsupported or explicitly designed separately.

## Reproduction Assessment

Yes. Source inspection shows current main passes latestResolution.github.commit from external resolver JSON into both GitHub codeload and install metadata, and the PR body provides real CLI fixture proof showing the mutable main ref accepted before and rejected after the patch.

## Solution Assessment

Yes, subject to maintainer compatibility acceptance. Reusing the existing 40-hex normalizer at the ClawHub lifecycle boundary is the narrowest maintainable fix because it aligns download, provenance display, and recorded install metadata without adding a parallel policy path.
