## Summary

Keep open: current main still lacks a skill-creation authority or routing model that can make a custom workflow run before `skill_workshop` is selected. The merged related PR fixed the direct skill-creator write bypass, but it explicitly left this broader extensibility question unresolved.

## What This Changes

Request to make Skill Workshop composable so custom skill-creation workflows can run before validated content is submitted to Skill Workshop proposals.

## Best Possible Solution

Define a maintainer-approved skill-creation authority model that composes custom tools or skills with the existing Skill Workshop proposal lifecycle without adding another skill-write path.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add a first-class skill-creation authority or pre-selection workflow hook for custom skill creation, and if so should it live in plugin hooks, tool policy/config, or a ClawHub workflow convention?

Rationale: Current code already has Skill Workshop as a proposal primitive plus generic tool policy and `before_tool_call` hooks, but none of those establish the product contract for making a custom workflow run before `skill_workshop` is selected.

Likely owner: shakkernerd

Owner reason: The likely decision sits closest to the Skill Workshop write-boundary and lifecycle ownership shown in recent history.

Owner confidence: medium

Options:

- **Design a first-class authority seam (recommended):** Add a maintainer-owned plugin/config contract for skill-creation routing while keeping Skill Workshop as the only persistence boundary.
- **Document policy-only composition:** Keep current APIs and document that operators must hide `skill_workshop` and expose their custom tool when they want a custom creation flow.
- **Defer to ClawHub/meta workflows:** Treat custom skill creation workflows as external skill/plugin packages until a broader meta-skill direction is accepted.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature/API-direction request. Source inspection does verify the current gap: `skill_workshop` is prompt-preferred when available, while current hooks are per-tool-call policy hooks rather than a pre-selection skill-creation authority interface.

## Solution Assessment

Unclear. A dedicated hook or config model may be the right API, but current code already has tool policy hooks, optional plugin tools, and a proposal-content primitive, so maintainers should choose the permanent product boundary before implementation.
