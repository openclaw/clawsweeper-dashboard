## Summary

Keep open: the merged direct-bypass fix removed the old bundled helper that wrote live skills, but current main still has no maintainer-approved way to make a custom skill-creation workflow run before the model selects `skill_workshop`.

## What This Changes

The issue requests an extensible Skill Workshop design where custom skill-creation workflows can prepare and validate content before using Skill Workshop as the governed proposal/apply boundary.

## Best Possible Solution

Define and document one narrow skill-creation authority model that lets custom workflow plugins prepare and validate content before `skill_workshop`, while keeping Skill Workshop as the only proposal/apply persistence boundary.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add a core/plugin API or config model that lets custom skill-creation workflows become the authority before `skill_workshop`, or should custom workflows remain ordinary plugin tools/skills that prepare content and then call Skill Workshop?

Rationale: The current code already supports plugin tools, tool-call hooks, allowlists, and caller-supplied proposal content, but none of those surfaces defines who owns pre-selection skill-creation authority; choosing that boundary affects product behavior and plugin SDK compatibility.

Likely owner: steipete

Owner reason: steipete introduced the bundled skill-creator surface and recently adjusted the Skill Workshop prompt/tool contract, making him the best evidenced owner for the product-routing choice.

Owner confidence: medium

Options:

- **Design a narrow authority seam (recommended):** Accept the use case and design a generic plugin/tool-policy seam that can route skill-creation requests through a configured custom workflow before final Skill Workshop proposal persistence.
- **Keep current routing:** Treat custom workflows as ordinary tools or skills that prepare proposal content and rely on prompting/tool policy, without adding a new authority interface.
- **Use a ClawHub convention only:** Encourage publishing custom skill creators as ClawHub plugins or skills and document the convention, but do not add core routing or config surface now.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature/API-direction request. Source inspection and the reporter's follow-up support the current gap: `skill_workshop` is built in and prompt-preferred, while existing hooks apply after a tool call is selected.

## Solution Assessment

Unclear: the requested layered design is plausible, but maintainers need to choose whether skill-creation authority belongs in a new plugin hook, tool policy, config surface, or a ClawHub convention before implementation is the best fix.
