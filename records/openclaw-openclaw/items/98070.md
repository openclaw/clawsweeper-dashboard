## Summary

Keep open: current main has the governed Skill Workshop proposal primitive and the recent direct-write bypass fix, but it still lacks a maintainer-approved pre-selection skill-creation authority or routing model for custom workflows.

## What This Changes

The issue requests an extensible Skill Workshop architecture so custom skill-creation workflows can run before Skill Workshop persists proposals.

## Best Possible Solution

Define one maintainer-approved skill-creation authority model that lets custom authoring workflows prepare proposal content while keeping Skill Workshop as the only governed persistence/apply boundary.

Rationale: The requested behavior changes plugin API semantics, tool routing, optional config, and governed skill-write policy, so source inspection can show the gap but cannot choose the product boundary.

Owner confidence: high

Options:

- **Design a narrow authority hook (recommended):** Add a maintainer-owned plugin/API design for skill-creation authority that runs before `skill_workshop` selection and still submits final content through Skill Workshop.
- **Use existing tools and prompts:** Document the supported pattern as custom tools preparing proposal content and then calling `skill_workshop`, without adding new routing authority.
- **Move to ClawHub convention:** Keep core unchanged and ask custom skill-creation workflows to ship as ClawHub skills or plugins that users invoke explicitly.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature/API-direction request. Source inspection verifies the current gap because `skill_workshop` is prompt-preferred when available and existing hooks operate around selected tool calls rather than as a skill-creation authority.

## Solution Assessment

Unclear pending maintainer direction. The proposed hook/config layering is plausible, but the safest end state is a single governed Skill Workshop persistence boundary with any custom workflow authority designed as a narrow plugin/API contract.
