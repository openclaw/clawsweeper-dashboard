## Summary

Keep open: current main has the Skill Workshop proposal primitive, plugin tools, tool policy, and `before_tool_call` hooks, but it still lacks a dedicated authority/routing contract that makes a custom skill-creation workflow run before `skill_workshop` is selected.

## What This Changes

Request to make Skill Workshop composable so custom skill-creation workflows can run before the final proposal/apply mechanism.

## Best Possible Solution

Define a maintainer-approved skill-creation authority contract that lets custom workflows prepare and validate proposal content before Skill Workshop persists it, without adding a second live skill-write path.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw support a first-class skill-creation authority or routing API that can run custom workflows before `skill_workshop`, and if so should it live as a generic plugin hook, tool policy/config surface, or documented ClawHub workflow convention?

Rationale: Current main has enough primitives to create proposal content and intercept selected tool calls, but not enough policy to guarantee a custom workflow is selected before the built-in tool; choosing that contract changes product/API direction.

Likely owner: Shakker

Owner reason: They introduced the core Skill Workshop service path and are the strongest feature-history routing candidate in local evidence.

Owner confidence: medium

Options:

- **Design a narrow plugin authority contract (recommended):** Add or specify a generic plugin-owned pre-selection/routing contract for skill-creation workflows while keeping Skill Workshop as the only persistence/apply boundary.
- **Keep current convention:** Document that custom workflows may prepare proposal content but cannot become the enforced authority over built-in `skill_workshop` selection.
- **Use tool policy only:** Rely on `tools.allow`/`tools.deny` and `before_tool_call` to block or steer direct `skill_workshop` calls, accepting that this is not a dedicated skill-creation workflow API.

## Reproduction Assessment

No high-confidence live model-rate repro was established, but source inspection does reproduce the design gap: current main exposes both visible skills and `skill_workshop` without a hard pre-selection authority for custom skill-creation workflows.

## Solution Assessment

Unclear until maintainers choose the product boundary; a hook/config design may be viable, but the safest direction is a narrow plugin API or explicit convention that preserves Skill Workshop as the single persistence boundary.
