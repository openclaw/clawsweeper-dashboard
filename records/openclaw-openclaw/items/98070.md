## Summary

Keep open: current main has Skill Workshop as a proposal primitive plus generic plugin tools, tool policy, and before_tool_call hooks, and https://github.com/openclaw/openclaw/pull/98346 removed the opposite direct-write bypass, but there is still no maintainer-approved skill-creation authority model that makes a custom workflow run before skill_workshop is selected.

## What This Changes

Request to make Skill Workshop composable with custom skill-creation workflows, including pre-workflow hooks, direct-call policy, and validation guardrails.

## Best Possible Solution

Define a maintainer-approved skill-creation authority model that lets custom workflows prepare proposal content while keeping Skill Workshop as the single governed proposal and apply boundary.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw support a first-class skill-creation authority/routing API, or should custom skill-creation workflows stay as plugin tools/skills that prepare proposal_content before using the existing skill_workshop primitive?

Rationale: The current code has generic plugin tools, prompt hooks, before_tool_call policy, and Skill Workshop proposal persistence, but none of those expresses a pre-selection authority for skill creation; choosing that contract changes plugin API and tool-routing semantics.

Likely owner: Jason (Json)

Owner reason: This person is the clearest current-main owner signal for the central Skill Workshop prompt/tool/service files in this checkout.

Owner confidence: medium

Options:

- **Add a narrow authority seam (recommended):** Create a generic, documented hook or policy layer for skill-creation routing while preserving skill_workshop as the only persistence/apply tool.
- **Use existing plugin/tool policy only:** Document custom workflows as plugin tools or skills that prepare proposal_content and rely on operator tool policy or prompt guidance instead of adding a new API.
- **Defer the direction:** Keep this issue open as product backlog until maintainers decide whether this is core plugin API scope or a ClawHub workflow convention.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature/API-direction request. Source inspection does confirm the current gap: skill_workshop is prompt-preferred when available, while current hooks and tool policy do not define a pre-selection skill-creation authority.

## Solution Assessment

Unclear. A dedicated hook or config model may be the right solution, but maintainers should first choose whether the permanent boundary belongs in generic plugin hooks, tool policy, prompt guidance, or a new Skill Workshop-specific API.
