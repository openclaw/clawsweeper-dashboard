## Summary

Keep open: current main fixed the narrower direct-write bypass in https://github.com/openclaw/openclaw/pull/98346, but it still does not provide a skill-creation authority or pre-selection routing model that can reliably run a custom workflow before `skill_workshop` is chosen.

## What This Changes

Request to make Skill Workshop composable so custom skill-creation workflows can run before `skill_workshop` creates or applies proposals.

## Best Possible Solution

Define a narrow maintainer-approved skill-creation authority API or tool-policy convention that lets custom workflows prepare proposals while keeping Skill Workshop as the sole write/apply boundary.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add a first-class skill-creation authority/routing API for custom workflows before `skill_workshop`, or keep the current model where custom tools prepare proposal content and then call Skill Workshop directly?

Rationale: The code already supports proposal content as a primitive, plugin tools, allowlists, and `before_tool_call`, but none of those choose a custom creation workflow before the model selects `skill_workshop`; adding that choice changes product/API boundaries and possibly config.

Likely owner: momothemage

Owner reason: They provided the most recent related boundary decision in the merged direct-bypass fix and pointed separate bridge/API work back to this thread.

Owner confidence: medium

Options:

- **Design narrow authority API (recommended):** Define a plugin-facing pre-selection or policy convention that can prioritize custom skill creators while keeping Skill Workshop as the only persistence and lifecycle mechanism.
- **Keep current model:** Document that custom workflows must be exposed through ordinary tools/skills and call `skill_workshop` themselves, accepting that model routing may still choose the built-in tool first.
- **Defer to ClawHub conventions:** Treat custom creation workflows as ClawHub skills/plugins only until a more concrete missing API is proven by additional implementations.

## Reproduction Assessment

Not applicable as a strict bug reproduction: the expected behavior is a new authority/routing capability. Source inspection does verify the current gap: `skill_workshop` is prompt-preferred when available, and existing hooks are tool-call policy hooks rather than pre-selection skill-creation workflow hooks.

## Solution Assessment

Unclear until maintainers choose the product boundary. The best shape is likely a narrow plugin/API seam that preserves the existing proposal lifecycle, not a broad Skill Workshop rewrite or a second skill-write path.
