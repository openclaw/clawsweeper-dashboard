## Summary

Keep open: current main has the governed Skill Workshop proposal primitive, plugin tools, tool allowlists, and `before_tool_call` hooks, and the merged related PR removed the direct live-write bypass, but none of that adds the pre-selection custom skill-creation authority this issue requests.

## What This Changes

The issue requests making Skill Workshop composable so custom skill-creation workflows can run before using the workshop as the proposal/apply primitive.

## Best Possible Solution

Define a maintainer-approved skill-creation authority model that composes custom tools with the existing Skill Workshop proposal lifecycle and explicitly does not create another live skill-write path.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw support custom skill-creation authorities before `skill_workshop` selection, and if so should that live as a plugin API hook, a tool-policy convention, or documented ClawHub workflow guidance?

Rationale: Current code has proposal primitives, plugin tools, allowlists, and per-tool-call hooks, but choosing a pre-selection authority model changes product behavior and plugin/API boundaries.

Likely owner: momothemage

Owner reason: They recently landed the adjacent bypass fix and explicitly identified this issue as the broader boundary thread.

Owner confidence: medium

Options:

- **Design a narrow plugin/API authority (recommended):** Add a bounded plugin or policy contract that can route skill-creation requests through approved custom workflows before they submit proposal content to Skill Workshop.
- **Document current composition only:** Keep Skill Workshop as the prompt-preferred path and document that custom tools may prepare proposal content but cannot replace model tool selection.
- **Close as out of core:** Treat custom skill-creation workflows as ClawHub skill/plugin convention only, accepting that OpenClaw core will not enforce a pre-selection authority.

## Reproduction Assessment

No as a runtime bug: the reported 80/20 model-choice rate was not reproduced. Source inspection does show the current gap: Skill Workshop is prompt-preferred and current hooks run after a tool has already been selected.

## Solution Assessment

Unclear pending maintainer direction. A dedicated authority hook may be the right solution, but current code already supports custom proposal content, plugin tools, allowlists, and `before_tool_call`, so the permanent boundary needs a product/API decision first.
