## Summary

Keep open: current main has a proposal-first Skill Workshop primitive, plugin tools, tool policy, and `before_tool_call` hooks, but it still lacks a supported pre-selection skill-creation authority that can guarantee a custom workflow runs before `skill_workshop` is chosen. The merged related PR only removed the direct live-write bypass and explicitly left this broader extensibility question open.

## What This Changes

Requested extensibility for Skill Workshop so custom skill-creation workflows can run before proposal creation while still using Skill Workshop as the final persistence and lifecycle primitive.

## Best Possible Solution

Define a maintainer-approved skill-creation authority model that lets plugins or custom tools prepare and validate proposal content before calling Skill Workshop, without adding another live skill-write path.

- **Add a narrow authority extension (recommended):** Create a supported hook or authority model that lets custom skill-creation workflows run before Skill Workshop proposal persistence while preserving one write boundary.
- **Document tool-policy composition only:** Use existing `tools.deny` and custom plugin tools as the supported workaround, accepting that OpenClaw will not guarantee pre-selection routing.
- **Keep Skill Workshop direct:** Decline first-class custom workflow authority and keep Skill Workshop as the only model-facing durable skill creation path.

## Reproduction Assessment

Not applicable as a bug reproduction because this is a feature/API-direction request. Source inspection does confirm the current gap: Skill Workshop is prompt-preferred when available, while existing hooks are per-tool-call policy hooks rather than pre-selection skill-creation workflow authority.

Unclear until maintainers choose the API boundary. The requested hook/config direction is plausible, but the maintainable end state should reuse the existing proposal service and avoid a second skill-write path.
