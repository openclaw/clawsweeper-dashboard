## Summary

Keep open: current main has the Skill Workshop proposal primitive, plugin tools, tool policy, and after-selection `before_tool_call` hooks, and a related merged pull request fixed the narrower direct-write bypass, but the requested pre-selection skill-creation authority remains a product/API design question.

## What This Changes

Request to make Skill Workshop composable so custom skill-creation workflows can run before final proposal persistence and approval.

## Best Possible Solution

Maintain a single Skill Workshop persistence/apply boundary, then either define a narrow plugin/API authority for custom pre-proposal workflows or explicitly document existing plugin tools plus tool policy as the supported path.

Options:

- **Design a narrow authority API (recommended):** Keep this issue open and define a small contract that lets custom workflows prepare proposal content while Skill Workshop remains the only write/apply boundary.
- **Document current surfaces only:** Treat custom creators as plugin or skill tools that prepare content and call Skill Workshop, with operators using tool policy to influence exposure.
- **Move to ClawHub convention:** If maintainers decide no core routing API belongs here, define the workflow packaging convention outside core through ClawHub skills or plugins.
