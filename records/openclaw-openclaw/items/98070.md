## Summary

Keep open: https://github.com/openclaw/openclaw/pull/98346 removed the narrower bundled skill-creator direct-write bypass, but current main still does not provide a pre-selection skill-creation authority or routing model that can force a custom workflow to run before `skill_workshop` is chosen.

## What This Changes

Request to make Skill Workshop composable with custom skill-creation workflows, including hooks or policy that route skill creation through custom preprocessing before final proposal persistence.

## Best Possible Solution

Define a narrow maintainer-approved plugin/skill authority model that lets custom workflows prepare proposal content while keeping Skill Workshop as the only persistence and apply boundary.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add a core/plugin SDK skill-creation authority that can route custom workflows before `skill_workshop`, or keep Skill Workshop as the direct governed path and rely on existing skills, plugin tools, and tool policy?

Rationale: The source gap is real, but the permanent boundary affects product UX, plugin API shape, config/policy semantics, and the single Skill Workshop write boundary, so model judgment should not choose it alone.

Likely owner: shakkernerd

Owner reason: They have the strongest feature-history trail for the Skill Workshop proposal lifecycle and would be best placed to judge whether a new authority hook fits that boundary.

Owner confidence: medium

Options:

- **Design a narrow authority hook (recommended):** Add a small plugin/skill authority surface that can prepare validated proposal content before final Skill Workshop persistence, with docs and compatibility tests.
- **Keep current routing model:** Document that custom workflows should use skills/plugin tools plus tool policy, and close this direction if maintainers do not want a new authority concept.
- **Limit to ClawHub convention:** Treat custom skill creators as ClawHub-distributed bundles/plugins without a core routing guarantee, and revisit only if a concrete missing API remains.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature/API-direction request. Source inspection does verify the current gap: `skill_workshop` is prompt-preferred and current hooks are per-tool-call policy hooks, not a pre-selection skill-creation authority.

## Solution Assessment

Unclear: a dedicated hook/config model may be right, but the best permanent solution depends on maintainer API and product direction. Any implementation should preserve Skill Workshop as the single persistence/apply boundary.
