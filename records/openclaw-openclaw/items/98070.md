## Summary

Keep open: current main has a governed Skill Workshop proposal primitive and existing plugin/tool hooks, and https://github.com/openclaw/openclaw/pull/98346 fixed the direct bundled skill-creator write bypass, but there is still no pre-selection skill-creation authority model that can make a custom workflow run before `skill_workshop` is chosen.

## What This Changes

Request to make Skill Workshop composable so custom skill-creation workflows can run validation/research steps before handing proposal content to the existing Skill Workshop lifecycle.

## Best Possible Solution

Define a maintainer-approved skill-creation authority seam that lets custom workflows prepare and validate proposal content before the existing Skill Workshop persistence boundary, without adding a second live skill-write path.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add a dedicated skill-creation authority/pre-selection API for custom workflows before `skill_workshop`, or keep the current Skill Workshop-first routing plus existing tool policy surfaces?

Rationale: The requested change would define new product and plugin API semantics around who owns skill creation, when core tool routing yields to custom workflows, and whether any new config can disable direct workshop use.

Likely owner: steipete

Owner reason: Recent merged Skill Workshop prompt, diagnostics, and skill-suggestion work makes this handle the clearest current routing/product owner candidate among the history signals.

Owner confidence: high

Options:

- **Design a narrow authority seam (recommended):** Add a small plugin/runtime contract that lets an enabled custom workflow prepare proposal content before Skill Workshop persists it, while keeping Skill Workshop as the only write boundary.
- **Use existing policy surfaces:** Document `tools.allow`/`tools.deny`, optional plugin tools, and `/learn` as the supported customization path, accepting that model routing will not have a first-class custom authority guarantee.
- **Defer to meta-skill work:** Wait for the broader meta-skill orchestration direction in https://github.com/openclaw/openclaw/pull/89959 before deciding whether this needs a separate API.

## Reproduction Assessment

Not applicable as a strict bug reproduction: this is a feature/API-direction request. Source inspection does confirm the current gap: existing hooks run around selected tool calls, while `skill_workshop` remains the direct durable skill-work routing rule.

## Solution Assessment

Unclear until maintainers decide the product boundary. A dedicated authority seam may be the best long-term answer, but existing plugin tools, tool policy, `/learn`, and the proposal-content primitive should be weighed before adding new API/config surface.
