## Summary

Current main and shipped releases now keep the default sandbox image Python-capable and no longer recreate it by tagging plain Debian, so the default-image write/edit failure is resolved; Python-free custom slim images remain operator-provided images that must include the helper runtime.

## What This Changes

The issue reports Docker sandbox edit/write failures when `openclaw-sandbox:bookworm-slim` lacks Python for the pinned sandbox mutation helper.

## Best Possible Solution

Keep the shipped default-image contract and fail-fast guard; users who choose custom slim images should use a Python-capable image or rebuild the documented default image.
