## Summary

Current main and the shipped v2026.4.27 release already fix the reported default Docker sandbox image problem: OpenClaw no longer tags plain Debian as the default image, and the default build path includes python3 for write/edit helpers.

## What This Changes

Report that Docker sandbox write/edit failed because the default `openclaw-sandbox:bookworm-slim` image lacked python3 required by the sandbox mutation helper.

## Best Possible Solution

Keep the shipped default-image guard and docs; treat Python-less custom sandbox images as explicit user configuration unless maintainers open a separate diagnostics or Python-optional-helper issue.

## Maintainer Decision

Required: false

## Reproduction Assessment

No current-main failing reproduction remains for the default image path: source, docs, release content, and regression coverage now show python3 is part of the default image contract and missing default images fail fast. The historical failure is source-reproducible from v2026.4.26, where `ensureDockerImage()` still pulled and tagged plain Debian.

## Solution Assessment

Yes. Fixing the default image resolution boundary and documenting the python3 image contract is the narrow maintainable fix for the reported default-image regression; a Python-optional mutation helper would be a separate product/compatibility decision for custom images.
