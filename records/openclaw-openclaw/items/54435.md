## Summary

Keep this open: current main and the latest release still short-circuit non-template literal `session.store` paths through a single-store branch, so sibling agent/channel sessions can remain absent from `sessions.list` and the Control UI. The open same-repository fix candidate is linked but unmerged, so the issue is still necessary.

## What This Changes

The issue requests that `sessions_list` and the Control UI Sessions dashboard list all active agent/channel sessions instead of only `agent:main:main`.

## Best Possible Solution

Repair and land https://github.com/openclaw/openclaw/pull/54716, or an equivalent narrow replacement, so literal per-agent paths under `agents/<id>/sessions/sessions.json` discover sibling agent stores while true shared literal stores remain single-store.

## Reproduction Assessment

Yes, at source level. Configure `session.store` as a literal `agents/main/sessions/sessions.json` path with a sibling agent store, and current main returns from the single-store branch before all-agent discovery runs.

## Solution Assessment

Yes, the linked PR direction is the narrow maintainable fix, but this issue should not close before that work merges. The fix should distinguish literal per-agent store paths from true shared literal stores and keep focused regression coverage.
