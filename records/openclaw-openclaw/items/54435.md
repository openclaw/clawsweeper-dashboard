Keep this issue open: current main and v2026.6.11 still take the literal `session.store` single-store path, so sibling agent sessions can remain missing from `sessions.list` and the dashboard. The issue asks for `sessions_list` and the Control UI Sessions view to include all active sessions instead of only the main session when multiple agent/channel sessions exist.
