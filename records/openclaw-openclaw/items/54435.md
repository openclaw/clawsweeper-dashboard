## Summary

Keep this open: current main and v2026.6.11 still take the single-store branch for a non-template literal `session.store`, so sibling agent sessions can remain missing from `sessions.list` and the Control UI. ## What This Changes

The issue reports that `sessions_list` returns only the main session, leaving Telegram or other agent sessions missing from the Control UI and API.

## Best Possible Solution

Land a refreshed https://github.com/openclaw/openclaw/pull/54716 or an equivalent narrow replacement that handles literal agent-tree paths with regression coverage and an explicit compatibility decision.

## Reproduction Assessment

Yes, at source level. With `session.store` set to a literal `agents/main/sessions/sessions.json` path and a sibling agent store on disk, current main returns from the literal single-store branch before all-agent discovery runs.

## Solution Assessment

Unclear as a final merge shape. The linked PR or a replacement is the right narrow direction, but maintainers need to decide whether literal agent-tree paths should discover sibling stores or preserve single-file isolation by default.
