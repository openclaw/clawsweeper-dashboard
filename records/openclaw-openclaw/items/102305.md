- `merge-risk: 🚨 auth-provider`: `modelProvider` controls provider/model routing, and ignoring valid runtime-only provider fields can route turns or tool resolution through the wrong provider.

## Summary

Keep open: the direction is right, but the current patch still breaks gateway model/session compatibility by ignoring valid runtime-only model metadata and by returning reset model identity on an unconsumed response field; proof is still limited to tests.

## What This Changes

The branch changes gateway session reset and model resolution so default-derived runtime model fields are not persisted, runtime-only rows re-resolve from current agent defaults, and reset responses include a computed model field.

## Best Possible Solution

Keep default-derived reset metadata out of persisted rows, preserve legitimate runtime-only model rows unless a reliable stale-default marker exists, return reset identity through the existing `resolved` contract, and add redacted live hot-reload proof.
