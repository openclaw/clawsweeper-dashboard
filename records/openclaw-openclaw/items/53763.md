## Summary

Keep open. Current main and v2026.6.11 still keep `web_fetch` and `web_search` as HTTP/provider-backed tools while the managed browser is a separate plugin/tool, so the central browser-backed rendered web-access request remains a real product/security design item.

## What This Changes

Request to add first-class browser-backed web access so agents can handle JS-rendered and login-required pages without relying on user Chrome, third-party extraction APIs, or fragile browser relay paths.

## Best Possible Solution

Keep this as the canonical browser-backed web-access design tracker, then split maintainer-approved work into rendered extraction semantics, browser/runtime packaging, session/proxy security policy, and benchmarked acceptance criteria.
