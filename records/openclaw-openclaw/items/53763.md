## Summary

Keep open. Current main and v2026.6.11 ship a strong managed browser plugin, but the central request is still missing: `web_fetch` and `web_search` remain HTTP/provider paths, while browser-rendered extraction with session, proxy, packaging, and security semantics still needs maintainer design.

## What This Changes

The issue requests first-class browser-backed web access so agents can render JavaScript pages, keep login/session state, and avoid depending on user Chrome or third-party extraction APIs.

## Best Possible Solution

Keep this as the canonical browser-backed web-access design tracker, then split approved work into plugin-owned rendered extraction, benchmarked fallback semantics, session/proxy policy, and security acceptance criteria.
