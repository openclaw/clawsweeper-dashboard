## Summary

Keep open. Current main and v2026.6.11 already have a bundled browser plugin, but the central request is not implemented because `web_fetch` and `web_search` remain separate HTTP/provider paths rather than browser-rendered extraction with session, proxy, packaging, and security semantics.

## What This Changes

Request to make browser-rendered web access first-class so agents can reliably fetch/search JS-heavy and login-required pages without relying on the user’s Chrome or third-party APIs.

## Best Possible Solution

Keep this as the canonical browser-backed web-access design tracker, then split approved work into plugin-owned rendered extraction, benchmarked fallback semantics, session/proxy policy, and security acceptance criteria.
