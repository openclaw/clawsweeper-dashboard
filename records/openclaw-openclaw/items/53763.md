## Summary

Keep open. Current main and v2026.6.11 already ship a strong managed browser plugin, but the central request is still not implemented: `web_fetch` and `web_search` remain HTTP/provider paths, while browser-backed rendered extraction with session, proxy, packaging, and security semantics still needs maintainer design.

## What This Changes

Request a built-in headless Chromium-backed web access path that can render JS and login pages, persist sessions, support proxies, and work without user Chrome or third-party APIs.

## Best Possible Solution

Keep this as the canonical browser-backed web-access design tracker, then split approved work into plugin-owned rendered extraction, benchmarked fallback semantics, session/proxy policy, and security acceptance criteria.
