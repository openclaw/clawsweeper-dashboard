## Summary

Keep open. Current main and v2026.6.11 already provide a strong managed browser plugin, but `web_fetch` and `web_search` still use HTTP/provider paths rather than browser-rendered extraction, so the central session/proxy/security product decision remains unresolved.

## What This Changes

Request a first-class headless browser-backed web access capability for JavaScript-rendered and login-required pages without relying on user Chrome or third-party extraction APIs.

## Best Possible Solution

Keep this as the canonical browser-backed web-access design tracker, then split approved work into plugin-owned rendered extraction, benchmarked fallback semantics, session/proxy policy, packaging guidance, and security acceptance criteria.
