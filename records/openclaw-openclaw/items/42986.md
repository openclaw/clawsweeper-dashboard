- `impact:session-state`: The request is about keeping persistent spawned subagent sessions associated with the intended Telegram conversation or topic.

## Summary

Keep open. Current main and v2026.6.11 have Telegram conversation-binding primitives and core adapter-based `thread:true` subagent binding, but Telegram still defaults to current-conversation placement and the requested child-topic/session exposure is owned by open product/API work rather than safely cleanup-closeable.

## What This Changes

The issue requests Telegram support for persistent `sessions_spawn(thread:true, mode:"session")` subagent sessions bound to Telegram conversations or forum topics.

## Best Possible Solution

Land or replace the active Telegram candidate with maintainer-approved child-topic subagent binding through the core session-binding adapter path, preserving default current-topic behavior and requiring final-head live Telegram proof.
