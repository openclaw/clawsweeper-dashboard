## Summary

Keep open. Current main and the latest release support Telegram current-conversation thread binding, but they do not implement the requested child forum-topic subagent session behavior; that remaining choice is already represented by an open proof-backed PR and conflicts with a separate open Telegram UX direction issue.

## What This Changes

Request Telegram support for persistent thread-bound subagent sessions, especially `sessions_spawn(thread:true, mode:"session")` binding to Telegram conversations or forum topics.

## Best Possible Solution

Keep this as the canonical Telegram subagent forum-topic binding discussion until maintainers either land a narrowed, proof-backed version of https://github.com/openclaw/openclaw/pull/82023 or decide Telegram should remain current-conversation-only by default.
