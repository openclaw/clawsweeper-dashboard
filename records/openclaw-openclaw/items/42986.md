## Summary

Keep open. Current main has moved past the old missing-hook failure by using core SessionBindingService and a Telegram adapter, but Telegram still defaults thread-bound subagent sessions to the current conversation while the requested child forum-topic behavior remains an open product/API decision with an active conflicting candidate PR.

## What This Changes

The issue requests Telegram support for `sessions_spawn` with `mode="session"` and `thread=true`, including binding spawned subagent sessions to Telegram conversations or forum topics.

## Best Possible Solution

Keep this issue as the canonical Telegram subagent forum-topic binding decision and resolve it by either landing a narrowed, proof-backed version of https://github.com/openclaw/openclaw/pull/82023 or explicitly deciding that Telegram should remain current-conversation-only by default.

- **Keep current-conversation only:** Document that Telegram binds subagent sessions to the current conversation/topic and does not create child forum topics by default.
- **Defer to channel policy design:** Hold this behind broader thread-binding policy/API work before changing Telegram routing semantics.

## Solution Assessment

Unclear until maintainers choose the product direction. A narrowed explicit child-topic capability looks plausible, but it must preserve Telegram’s current default placement and resolve visibility concerns for internal subagent topics.
