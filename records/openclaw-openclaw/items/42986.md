## Summary

Keep open. Current main has Telegram current-conversation binding and the core adapter path for thread-bound native subagent sessions, but the child-topic/model-visible Telegram behavior remains unresolved and is owned by open, conflicting candidate work that needs maintainer product/API review.

## What This Changes

The issue requests Telegram support for persistent thread-bound `sessions_spawn(..., mode="session", thread=true)` subagent sessions, originally modeled after Discord thread binding.

## Best Possible Solution

Land or replace the active Telegram candidate with maintainer-approved child-topic subagent binding through the core session-binding adapter path, while preserving default current-topic behavior unless maintainers explicitly choose visible child topics.
