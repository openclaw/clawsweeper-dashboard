## Summary

Keep open. Current main and v2026.6.11 have the core session-binding adapter path and Telegram binding primitives, but Telegram still defaults to current-conversation placement and the model-visible `sessions_spawn` thread/session affordance remains tied to child-thread default placement; the remaining child-topic subagent behavior is still owned by open, unresolved product/API work.

## What This Changes

Issue requests Telegram support for persistent thread-bound subagent sessions via `sessions_spawn(thread=true, mode="session")`.

## Best Possible Solution

Land or replace the active Telegram candidate with maintainer-approved child-topic subagent binding via the core session-binding adapter path, while preserving Telegram's default current-topic behavior and requiring final-head live Telegram proof.

## Reproduction Assessment

## Solution Assessment

No, the original hook-based approach is no longer the best layer after https://github.com/openclaw/openclaw/pull/88416. The best path is a maintainer-approved capability/API exposure that keeps Telegram transport behavior plugin-owned and preserves safe defaults.
