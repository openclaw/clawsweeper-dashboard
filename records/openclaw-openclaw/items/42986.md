## Summary

Keep open. Current main has Telegram session-binding primitives, including child forum-topic binding support, but Telegram is still configured as current-conversation placement and the model-visible `sessions_spawn(thread:true, mode:"session")` child-topic path remains a product/API decision with an active implementation candidate.

## What This Changes

The issue requests Telegram support for persistent thread-bound native subagent sessions created with `sessions_spawn(thread:true, mode:"session")`.

## Best Possible Solution

Land or replace the active Telegram candidate with a maintainer-approved child-topic subagent capability through the core session-binding adapter path, preserving Telegram's normal current-topic default and requiring final-head live Telegram proof.
