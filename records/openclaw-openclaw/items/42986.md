## Summary

Keep open: current main and v2026.6.11 now support Telegram subagent thread binding through the shared session-binding adapter, but the remaining child-forum-topic/automatic spawn affordance is still a product decision with an open conflicting implementation path.

## What This Changes

Request Telegram `sessions_spawn(mode="session", thread=true)` support so persistent subagent sessions can bind to Telegram conversations or topics.

## Best Possible Solution

Define Telegram's intended default and opt-in child-topic behavior, then either document current-conversation binding as the supported path or land a narrow, live-proven child-topic capability.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Telegram expose explicit child forum-topic subagent sessions, or should `thread:true` remain a current-conversation binding by default?

Rationale: Current code already supports Telegram session binding, but child-topic creation changes user-visible chat behavior and conflicts with the open issue asking Telegram not to create user-visible threads for internal subagent runs.

Likely owner: steipete

Owner reason: He authored the core thread-binding refactor and is the clearest owner for deciding whether the shared binding model should grow a Telegram child-topic affordance.

Owner confidence: medium

Options:

- **Keep current-conversation default (recommended):** Treat current main as the supported Telegram behavior and handle child-topic creation only through a separately approved opt-in design.
- **Sponsor child-topic support:** Adopt or replace the open Telegram PR after resolving conflicts, compatibility risks, and live Telegram proof.
- **Reject child topics for subagents:** Close the child-topic direction and update docs/tool affordances so Telegram subagent binding is clearly current-conversation only.

## Solution Assessment

Unclear as a product direction: current main is a maintainable solution for current-conversation binding, but explicit child forum-topic spawning needs a maintainer decision and live Telegram proof before it is the best fix.
