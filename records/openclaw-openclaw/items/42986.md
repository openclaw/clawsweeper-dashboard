## Summary

Keep open. Current main and the latest release have Telegram session-binding primitives, including child topic creation, but Telegram still advertises normal top-level placement as current and `sessions_spawn` only exposes thread/session fields for automatic child-placement channels; the direct candidate remains open and needs maintainer API/product review.

## What This Changes

Request to let Telegram users create persistent `sessions_spawn(mode="session", thread=true)` subagent sessions bound to a Telegram conversation or forum topic.

## Best Possible Solution

Land or replace the active Telegram work with a maintainer-approved, narrow child-topic subagent capability that uses the core session-binding adapter path, preserves Telegram's default current-topic behavior, and includes final-head live Telegram proof.

## Reproduction Assessment

Yes, at source level. Current main keeps Telegram top-level placement as `current` while `sessions_spawn` hides thread/session fields unless the channel supports automatic child-thread spawn.

## Solution Assessment

No, not as originally proposed. Adding new primary `subagent_spawning` routing is now the wrong layer because current docs and code route new thread-bound subagent work through core session-binding adapters.
