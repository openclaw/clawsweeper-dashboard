## Summary

Keep open. Current main has Telegram conversation-binding primitives and explicit core adapter binding, but it still keeps Telegram's default placement as the current conversation and does not expose Telegram as an automatic child-topic subagent spawn channel; the remaining work is tied to open product/API decisions and an active implementation candidate.

## What This Changes

Request support for Telegram `sessions_spawn(thread=true, mode="session")` so persistent subagent sessions can bind to Telegram conversations or forum topics.

## Best Possible Solution

Land or replace the active Telegram candidate with maintainer-approved child-topic subagent binding through core session-binding adapters, while preserving Telegram's normal current-topic default and requiring final-head live Telegram proof.
