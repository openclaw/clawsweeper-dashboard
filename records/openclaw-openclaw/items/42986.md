## Summary

Keep open. Current main has core-owned Telegram session-binding support, but it still defaults Telegram subagent thread spawns to the current conversation; the requested child forum-topic behavior is still owned by the open candidate https://github.com/openclaw/openclaw/pull/82023 and conflicts with the open product-direction concern in https://github.com/openclaw/openclaw/issues/98918.

## What This Changes

The issue requests Telegram support for persistent thread-bound subagent sessions created with `sessions_spawn(thread: true, mode: "session")`, including lifecycle binding behavior comparable to Discord.

## Best Possible Solution

Keep this as the canonical Telegram subagent forum-topic binding discussion until maintainers either land a narrowed, proof-backed version of https://github.com/openclaw/openclaw/pull/82023 or decide that Telegram should remain current-conversation-only by default.
