## Summary

Current main has the core session-binding foundation for Telegram forum topics, but it still does not expose the requested Telegram child-topic `sessions_spawn(thread:true, mode:"session")` capability to agents; the remaining work needs a maintainer API/product decision because it conflicts with the current Telegram default of staying in the existing topic and with related follow-up work on hidden internal subagents.

## What This Changes

Request support for binding Telegram delegated subagent sessions to their own forum topics instead of routing child session output back into the parent conversation.

## Best Possible Solution

Define the Telegram behavior as an explicit opt-in child-topic subagent capability on the current core session-binding path, preserve current-topic/default behavior for ordinary Telegram runs, and require focused tests plus live Telegram proof before closing this issue.
