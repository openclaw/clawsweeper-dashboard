## Summary

Keep open. Current main and v2026.6.11 support Telegram current-conversation session binding, but they still do not expose the requested child forum-topic subagent behavior; https://github.com/openclaw/openclaw/pull/82023 is the open implementation candidate and https://github.com/openclaw/openclaw/issues/98918 leaves a real Telegram UX product decision unresolved.

## What This Changes

Request Telegram support for persistent thread-bound subagent sessions, especially `sessions_spawn(thread:true, mode:"session")` routing into Telegram conversation/forum-topic bindings with configurable behavior.

## Best Possible Solution

Keep this issue as the canonical Telegram subagent forum-topic binding discussion until maintainers either land a narrowed, proof-backed replacement for https://github.com/openclaw/openclaw/pull/82023 or decide Telegram should stay current-conversation-only by default.
