## Summary

Keep open: current main has Telegram thread-binding primitives, but Telegram still defaults normal binding to the current conversation and the model-visible `sessions_spawn(thread:true, mode:"session")` affordance is gated to child-placement channels. The remaining work is the Telegram child-topic subagent exposure/product decision, with https://github.com/openclaw/openclaw/pull/82023 as the direct but conflicting implementation candidate.

## What This Changes

Request Telegram support for persistent `sessions_spawn(thread:true, mode:"session")` subagent sessions bound to Telegram conversations or topics.

## Best Possible Solution

Rework or land the existing Telegram candidate around the current core session-binding path, keeping ordinary Telegram placement current-topic while exposing a maintainer-approved explicit child-topic subagent capability with focused tests and redacted live Telegram proof.
