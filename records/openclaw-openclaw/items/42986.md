## Summary

Keep open. Current main and the latest release have Telegram conversation-binding primitives and a core adapter path for explicit thread-bound subagent spawns, but Telegram still defaults to current-conversation placement and the model-visible child-topic subagent session path remains an unresolved product/API decision with open candidate work.

## What This Changes

Request Telegram support for persistent `sessions_spawn` subagent sessions that bind to a Telegram conversation or forum topic.

## Best Possible Solution

Land or replace the active Telegram candidate with a maintainer-approved core session-binding capability that preserves Telegram's current-topic default, makes child-topic subagent spawning explicit, and refreshes final-head live Telegram proof.
