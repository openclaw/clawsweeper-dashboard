## Summary

Keep open. Current main has Telegram conversation-binding primitives and core adapter-based binding for explicit thread-bound subagent spawns, but Telegram still uses current-conversation placement and the remaining child-topic/session exposure is owned by open, unresolved candidate work that needs maintainer product/API review.

## What This Changes

Request support for Telegram `sessions_spawn(thread: true, mode: "session")` subagent sessions bound to Telegram conversations or forum topics.

## Best Possible Solution

Land or replace the active Telegram candidate with maintainer-approved child-topic subagent binding via core session-binding adapters, while preserving default current-topic behavior and adding final-head live Telegram proof.
