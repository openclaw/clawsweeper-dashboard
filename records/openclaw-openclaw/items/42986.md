## Summary

Keep open: current main and v2026.6.11 have Telegram thread-binding primitives, but Telegram still defaults to current-topic placement and the model-visible `sessions_spawn(thread:true, mode:"session")` child-topic path remains a maintainer product/API decision with an open, conflicting implementation candidate.

## What This Changes

Request Telegram support for persistent thread-bound subagent sessions, including `sessions_spawn(thread:true, mode:"session")` routing into Telegram conversations or forum topics.

## Best Possible Solution

Rework or land the existing Telegram candidate on the current core session-binding path, keeping ordinary Telegram placement current-topic while exposing only a maintainer-approved explicit child-topic subagent capability with focused tests and redacted live Telegram proof.
