## Summary

Keep open. Current main has Telegram conversation-binding primitives and documents current-conversation binding, but it still does not expose the requested Telegram child-topic subagent session path in the model-visible `sessions_spawn` surface; the remaining behavior is owned by open candidate work and needs maintainer product/API review.

## What This Changes

Request Telegram support for persistent thread-bound subagent sessions when `sessions_spawn` is used with `thread=true` and `mode="session"`.

## Best Possible Solution

Land or replace the active Telegram candidate with a maintainer-approved per-kind child-topic spawn capability, while preserving Telegram's current-topic default and requiring final-head live Telegram proof.
