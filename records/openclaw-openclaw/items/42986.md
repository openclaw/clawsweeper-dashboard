## Summary

Keep open: current main and v2026.6.11 have Telegram binding primitives, but they still keep Telegram's normal placement on the current conversation and hide automatic `sessions_spawn(thread:true, mode:"session")` affordances unless the channel advertises child-thread placement. The remaining work is an explicit Telegram child-topic subagent capability decision, with https://github.com/openclaw/openclaw/pull/82023 as the direct but conflicting implementation candidate.

## What This Changes

The issue requests Telegram support for `sessions_spawn` with `mode="session"` and `thread=true`, binding spawned subagent sessions to Telegram conversations or forum topics.

## Best Possible Solution

Rework or land the existing Telegram candidate around the current core session-binding path, keeping ordinary Telegram placement current-topic while exposing a maintainer-approved explicit child-topic subagent capability with focused tests and redacted live Telegram proof.
