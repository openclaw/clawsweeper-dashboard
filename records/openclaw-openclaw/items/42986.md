## Summary

Keep open: current main and v2026.6.11 have Telegram session-binding primitives, but Telegram still defaults to current-topic placement and the model-visible `sessions_spawn(thread:true, mode:"session")` affordance remains gated to child-placement channels. The open implementation candidate directly targets this request, but it is conflicting and still needs maintainer product/API direction rather than conservative cleanup closure.

## What This Changes

Request Telegram support for persistent thread-bound native subagent sessions, including `sessions_spawn(thread:true, mode:"session")` binding to Telegram conversations or forum topics.

## Best Possible Solution

Approve a narrow Telegram child-topic subagent capability on the current core session-binding path, keep ordinary Telegram placement current-topic by default, and require focused tests plus redacted live Telegram proof before closing this issue.
