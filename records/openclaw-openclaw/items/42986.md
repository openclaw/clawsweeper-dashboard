## Summary

Close as implemented on current main. Telegram now has core session-binding support for explicit thread-bound subagent sessions through the channel binding adapter path rather than the legacy `subagent_spawning` hook path; child-topic default behavior remains separate narrower follow-up work.

## What This Changes

Request Telegram support for `sessions_spawn(thread:true, mode:"session")` so spawned subagent sessions stay bound to a Telegram conversation or topic, with related thread-binding configuration.

## Best Possible Solution

Keep the current core-owned Telegram session-binding implementation, and route child-topic default/noisy-thread policy questions to narrower follow-ups such as https://github.com/openclaw/openclaw/pull/82023 and https://github.com/openclaw/openclaw/issues/98918.
