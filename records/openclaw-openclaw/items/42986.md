## Summary

Keep open. Current main and v2026.6.11 have Telegram conversation-binding primitives and a core adapter path for explicit thread-bound subagent spawns, but Telegram still defaults to current-conversation placement and the requested child-topic/model-visible subagent session behavior remains an unresolved product/API decision with open candidate work.

## What This Changes

Request Telegram support for persistent `sessions_spawn(thread:true, mode:"session")` subagent sessions bound to Telegram conversations or topics.

## Best Possible Solution

Land or replace the active Telegram candidate with a maintainer-approved core SessionBindingService/channel capability that preserves Telegram's current-topic default, makes child-topic subagent spawning explicit, and refreshes final-head live Telegram proof.
