## Summary

Keep open. Current main has the newer core SessionBindingService path and Telegram conversation-binding adapter, but Telegram still defaults subagent thread spawns to the current conversation, while the requested child forum-topic behavior remains owned by an open conflicting candidate PR and a related product-direction issue about avoiding user-visible subagent threads.

## What This Changes

The issue requests Telegram support for persistent thread-bound subagent sessions via `sessions_spawn(mode="session", thread=true)`.

## Best Possible Solution

Keep this issue as the canonical Telegram subagent forum-topic binding discussion and resolve it by either landing a narrowed, proof-backed version of https://github.com/openclaw/openclaw/pull/82023 or explicitly deciding that Telegram should stay current-conversation-only by default.
