## Summary

Keep open. Current main has Telegram session-binding primitives and explicit core adapter binding, but Telegram still defaults to current-conversation placement and is not exposed as an automatic child-topic native subagent spawn channel; the remaining work needs maintainer product/API direction and is already represented by an open implementation candidate.

## What This Changes

The issue requests Telegram support for persistent `sessions_spawn` native subagent sessions bound to a Telegram conversation or topic, originally framed as adding Telegram subagent lifecycle/thread-binding hooks.

## Best Possible Solution

Land or replace the active Telegram candidate with maintainer-approved child-topic subagent binding through the core session-binding adapter path, while preserving Telegram's normal current-topic default and requiring final-head live Telegram proof.
