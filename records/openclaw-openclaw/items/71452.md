## Summary

Keep this issue open: current main includes the merged formatter/display-limit partial fix, but the reopened issue explicitly asks for end-to-end cursor or page iteration, and source still shows provider paths such as Discord search exposing only a single capped page.

## What This Changes

Request message list, pin list, search, and chat listing actions to honor requested limits and support pagination instead of stopping at a hardcoded or provider-capped first page.

## Best Possible Solution

Define a small shared message-action pagination contract for read, pins, search, and channel-list, then implement provider-specific cursor/page iteration behind that contract while preserving the merged formatter limit behavior.
