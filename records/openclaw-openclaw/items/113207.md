## Summary

Keep this PR open for a safer repair. The proposed runtime shortcut deletes every boot-session mapping without first proving it is a legacy pre-7.1 entry, so it can discard valid session state; the PR body also provides tests and a narrative but no after-fix run from an upgraded installation.

## What This Changes

This PR makes temporary session snapshots treat keys ending in `:boot` as absent so the restore phase removes a stale boot-session entry after a failed startup hook.

## System Context

BOOT.md startup hooks run through the gateway’s agent-command session lifecycle. That lifecycle snapshots a temporary session mapping before admission and restores or removes it afterward, affecting the persistent session entry used by later boot runs.

## Architecture Diagram

flowchart LR
  A[Gateway starts] --> B[BOOT.md startup hook]
  B --> C[Agent command session admission]
  C --> D[Temporary session snapshot]
  D --> E[Restore or delete session mapping]
  E --> F[Next gateway boot]
  F --> B

## Best Possible Solution

Add a narrow core Doctor migration that identifies only legacy `agent:<id>:boot` entries lacking the current lifecycle ownership fields, removes them before the next boot run, and proves both fresh and upgrade behavior without changing valid runtime mappings.
