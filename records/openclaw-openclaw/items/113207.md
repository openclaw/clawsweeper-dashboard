## Summary

Keep this PR open. It repairs a real upgrade regression, but it performs legacy persisted-state cleanup during normal gateway execution and deliberately leaves the first boot failing; repository policy requires legacy state migration to happen through `openclaw doctor --fix`, not steady-state runtime. The submitted evidence is also test-only rather than a redacted upgraded-gateway recovery run.

## What This Changes

The PR changes temporary boot-session restoration so a `:boot` mapping without `lifecycleRevision` is removed after a failed run instead of restored indefinitely.

## System Context

Gateway boot hooks use a temporary per-agent session mapping while starting BOOT.md work. The session lifecycle wrapper snapshots persisted mapping state before the run and restores or removes it afterward, which determines whether subsequent gateway boots can execute the hook.

## Architecture Diagram

flowchart LR
  A[Gateway boot] --> B[BOOT.md hook]
  B --> C[Session mapping snapshot]
  C --> D[Session admission]
  D --> E[Restore or remove mapping]
  E --> F[Later gateway boot]
  F --> B

## Best Possible Solution

Add a narrow, idempotent `openclaw doctor --fix` migration that removes only verified legacy `agent:<id>:boot` entries before gateway startup, then keep runtime restoration on canonical session state and prove both upgraded and fresh-install behavior.
