## Summary

The current head still wraps each aggregate Claude CLI attempt in the existing `model.call.*` lifecycle. OpenClaw’s established diagnostics contract uses that lifecycle for individual provider inference calls, while this span can include Claude Code orchestration, tools, background work, retries, cleanup, and cumulative turn usage. The automated coverage is strong, but a diagnostics owner must choose a distinct public CLI-turn semantic before merge.

## What This Changes

The PR adds synthetic Claude Code CLI harness, run, and model-call diagnostics, cumulative usage and content export, OpenTelemetry documentation, and lifecycle regression tests across one-shot, managed-stdio, and paired-node execution.

## Best Possible Solution

Keep `model.call.*` reserved for observed provider inference calls and represent the Claude Code boundary with a distinct trusted CLI-turn or harness-operation lifecycle—using an `invoke_agent` or `invoke_workflow` semantic where appropriate—while retaining the useful content, timing, terminal-outcome, and cumulative-usage fields under that separate span.
