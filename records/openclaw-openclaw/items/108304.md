## Summary

Keep this maintainer-authored draft open, but the prior telemetry-contract blocker remains: adding `openclaw.harness.run` and `openclaw.run` parents does not make an aggregate Claude CLI turn an individual model call. Current documentation defines `openclaw.model.call` usage and latency as belonging to one provider call, while this branch still reports a synthetic CLI attempt with terminal cumulative usage that can include internal Claude activity.

**Likely related people**
- `vincentkoc` — medium confidence; recent contributor to OTLP trace-correlation behavior.
- `joshavant` — medium confidence; recent contributor across diagnostics and agent-runtime tracing surfaces.

## What This Changes

The PR adds synthetic Claude Code CLI turn diagnostics for one-shot, managed-stdio, and paired-node execution, exports them as OpenTelemetry model-call spans, and adds lifecycle tests and documentation.

## Best Possible Solution

Keep `model.call.*` reserved for observable individual provider requests; represent the Claude CLI attempt with the existing harness/run hierarchy or a distinct CLI-turn span, and retain cumulative usage on the aggregate run-accounting surface unless maintainers deliberately version the public model-call contract.
