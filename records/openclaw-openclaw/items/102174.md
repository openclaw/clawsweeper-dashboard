## Summary

Keep open: current main still treats the returned CLI text as the cron result, then tears down the isolated cron Claude live session, and the existing interim-message mitigation only covers a narrow hint/subagent path rather than pending foreground Bash/native tool work.

## What This Changes

The issue asks cron `agentTurn` to wait for or explicitly flag pending foreground Bash work under `claude-cli` instead of delivering a placeholder success and killing the subprocess tree.

## Best Possible Solution

Define one cron/`claude-cli` contract: a cron run must not record/deliver success while native foreground tool work is still pending, and any unsupported long-running pattern should fail with explicit diagnostics or be routed through a supported OpenClaw exec/cron/on-exit mechanism.
