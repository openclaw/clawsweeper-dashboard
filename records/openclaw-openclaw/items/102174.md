## Label Justifications

- `P1`: The issue describes a scheduled agent workflow that can report and deliver success while foreground work is killed, affecting real automated agent runs.
- `impact:data-loss`: The reported failure leaves partial per-run state and discards the intended completed foreground work output.
- `impact:message-loss`: Cron can announce placeholder success instead of delivering the actual completed foreground Bash result.
- `impact:session-state`: The failure is caused by live-session/process lifecycle state diverging from the cron run's recorded outcome.
- `maturity:stable`: The affected Gateway runtime lifecycle/process-supervision surface maps to gateway-runtime, which is scored M4 Stable in qa/maturity-scores.yaml.

## Summary

Keep open: current main still has the cron-to-Claude CLI path where isolated cron accepts returned CLI text as the run outcome, then closes the Claude live session and cancels its process tree, while the existing interim-reply handling only covers narrow acknowledgement/subagent cases rather than pending foreground native Bash work.

## What This Changes

The issue asks OpenClaw to prevent cron agentTurn from recording and announcing success while a long foreground Bash tool subprocess is still pending or killed.

## Best Possible Solution

Define a cron/Claude CLI contract where isolated cron cannot record or deliver success while foreground native tool work remains pending; unsupported long foreground work should fail with explicit diagnostics or move to a durable command/on-exit/exec-process path.
