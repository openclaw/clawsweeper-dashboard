## Label Justifications

- `P1`: The issue describes a scheduled agent workflow that can report and deliver success while foreground work is killed, affecting real automated agent runs.
- `impact:data-loss`: The reported failure leaves partial per-run state and can discard the intended final foreground Bash output.

## Summary

Keep open: current main still has the isolated cron/Claude CLI shape where returned CLI text can become the cron result while the live Claude session is closed and its process tree is cancelled. The related long-work issues share the lifecycle root cause, but they do not fully own this issue's cron `ok` status, announce delivery, and partial-state invariant.

## What This Changes

The issue asks OpenClaw to prevent cron `agentTurn` from reporting and delivering success while foreground Claude CLI Bash work is still pending or killed.

## Best Possible Solution

Define a cron/Claude CLI contract where isolated cron cannot record or deliver success while foreground native tool work remains pending; unsupported long foreground work should fail with explicit diagnostics or be routed through durable command/on-exit/exec-process paths.
