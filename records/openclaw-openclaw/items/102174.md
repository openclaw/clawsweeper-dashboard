## Label Justifications

- `P1`: The issue describes a scheduled agent workflow that can report and deliver success while foreground work is killed, affecting real unattended agent runs.
- `impact:data-loss`: The reported failure leaves partial per-run state and can discard the intended final foreground Bash output or audit artifacts.
- `impact:message-loss`: Cron can announce placeholder success instead of delivering the actual completed foreground Bash result.
- `impact:session-state`: The failure is caused by live-session/process lifecycle state diverging from the cron run's recorded outcome.
- `maturity:stable`: The process-supervised Gateway runtime path involved in cleanup and run recording maps to the M4 Stable `gateway-runtime` surface, even though the direct cron and agent-runtime surfaces are M3.

## Summary

Keep open: current main still allows isolated cron/Claude CLI output to become an `ok` cron result without any pending foreground native-tool signal, while run-end Claude live-session cleanup can cancel the managed process tree. The related open long-work issues share the lifecycle root cause but do not fully own this issue's cron green-status, fallback announce, and partial-state invariant.

## What This Changes

The issue asks for cron `agentTurn`/Claude CLI runs to avoid reporting and delivering success while foreground Bash work is still pending and vulnerable to run-end cleanup.

## Best Possible Solution

Define a cron/Claude CLI lifecycle contract where isolated cron cannot record or deliver success while foreground native tool work remains pending; unsupported long foreground work should fail with explicit diagnostics or be routed through command/on-exit/exec-process cron paths.
