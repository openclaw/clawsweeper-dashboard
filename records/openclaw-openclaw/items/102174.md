## Label Justifications

- `P1`: A scheduled channel workflow can be reported ok and delivered while foreground tool work is killed mid-run, losing the intended final digest and leaving partial state.
- `impact:message-loss`: The operator receives a placeholder announce message instead of the final digest produced from the Bash wrapper output.
- `impact:session-state`: Cron/session lifecycle state can diverge from real tool execution because the run records success while the subprocess is terminated and workspace state remains partial.
- `maturity:stable`: The process-tree cleanup side of the bug touches Gateway runtime lifecycle behavior, and Gateway runtime is scored M4 Stable in qa/maturity-scores.yaml.

## Summary

Keep open: current main still allows an isolated cron CLI run to hand its final text to cron delivery while cleanup then closes the Claude live session, and the existing cron mitigations only cover short interim acknowledgements and subagent descendants, not foreground Bash/tool subprocesses or a pending-tool run-record signal. The open sibling lifecycle issue is related but does not supersede this cron-specific green-run/placeholder failure mode.

## What This Changes

The issue asks OpenClaw to keep cron agentTurn runs from finishing green and delivering an interim placeholder while foreground Bash/tool work is still in flight, and to surface or document that failure mode.

## Best Possible Solution

Define an owner-approved cron/claude-cli lifecycle contract that either blocks or marks failure while foreground tool work is pending, preserves bounded process cleanup, and records a typed pending-tool/forced-cleanup signal instead of a green placeholder run.

Options:

- **Bounded drain plus failure signal (recommended):** Detect pending CLI-owned tool work at turn end, wait only within the cron timeout/cleanup ceiling, and record timeout or forced cleanup as a non-green cron result when it cannot drain.
- **Telemetry first:** Keep cleanup behavior for now but add a run-record diagnostic and operator-visible warning whenever a cron run ends with pending CLI tool work or forced process-tree cleanup.
- **Document unsupported foreground waits:** Declare long foreground Bash-in-agentTurn cron jobs unsupported and steer users to command cron, systemEvent, detached tasks, or explicit disk-handoff patterns.
