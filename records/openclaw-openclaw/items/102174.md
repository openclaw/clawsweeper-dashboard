## Label Justifications

- `P1`: The issue describes a scheduled agent workflow that can report and deliver success while foreground work is killed, affecting real automated agent runs.
- `impact:data-loss`: The reported failure leaves partial per-run state and can discard the intended final foreground work output.
- `impact:message-loss`: Cron can announce placeholder success instead of delivering the actual completed foreground Bash result.
- `impact:session-state`: The failure is caused by live-session and process lifecycle state diverging from the cron run's recorded outcome.

## Summary

Keep open: current main still allows isolated cron to accept returned Claude CLI text as the run result, close the live session, and cancel the process tree without a pending foreground native-tool signal; related long-work issues share the lifecycle root cause but do not fully own this cron success and delivery invariant.

## What This Changes

The issue reports isolated cron `agentTurn` on `claude-cli` returning and announcing placeholder text before a long foreground Bash subprocess finishes, then killing that subprocess during live-session cleanup.

## Best Possible Solution

Define a cron/Claude CLI lifecycle contract where isolated cron cannot record or deliver success while foreground native tool work is still pending; unsupported long foreground work should fail with typed diagnostics or route through a durable command/on-exit/exec-process path.
