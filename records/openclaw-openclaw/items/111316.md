## Summary

The proposed runner-local deadline addresses a real startup availability failure without adding configuration or changing the tunnel protocol. The supplied current-main/PR context does not prove the change is already present on `main`, and the branch contains focused regression coverage plus real-run evidence, so this PR remains useful for normal maintainer review.

## What This Changes

This PR makes worker SSH tunnel startup reject and kill an SSH child after 30 seconds when it never emits the readiness marker, and adds regression tests for timeout and successful-marker paths.

## System Context

Cloud-worker environments open a host-key-pinned reverse SSH tunnel before the gateway can use the assigned worker. The runner turns SSH process output and lifecycle events into a readiness promise that the tunnel connection flow awaits.

## Architecture Diagram

flowchart LR
  A[Worker environment request] --> B[SSH tunnel runner]
  B --> C[SSH child process]
  C --> D{Ready marker received?}
  D -->|Yes| E[Tunnel becomes usable]
  D -->|No within 30 seconds| F[Kill child and reject startup]
  F --> G[Gateway reports connection failure]

## Best Possible Solution

Keep readiness bounded inside the SSH runner, retain the focused timeout and success-path coverage, and land after confirming that 30 seconds is the intended worker-startup limit.
