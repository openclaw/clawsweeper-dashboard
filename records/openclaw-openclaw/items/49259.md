## Summary

Keep open: current main has selected-session deletion and generic sessions cleanup, but it still does not provide a Dashboard workflow that detects, previews, and prunes old Telegram/Discord orphan sessions; the remaining work needs maintainer-approved destructive cleanup semantics.

## What This Changes

Request a Dashboard Sessions prune flow that previews and deletes old Telegram/Discord-backed orphan session rows with configurable age and optional auto-prune.

## Best Possible Solution

Design a preview-first Dashboard prune flow backed by plugin-owned Telegram/Discord reachability checks, explicit age and retention policy, and safe transcript/session deletion semantics while keeping generic session maintenance protective by default.

## Reproduction Assessment

Yes for the current-main absence: source inspection shows selection deletion and generic cleanup, but no path that computes Telegram/Discord orphan candidates, previews them by age, or prunes them from the Dashboard. A live transport deletion scenario was not run in this read-only review.

## Solution Assessment

Unclear as proposed: a preview-first operator flow is the right direction, but automatic pruning and configurable defaults need maintainer policy before implementation. The safer architecture keeps transport reachability checks in the owning plugins and avoids making generic core cleanup assume a 403/404 target is disposable data.
