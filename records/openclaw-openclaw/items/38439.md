## Summary

The issue should stay open because current main now handles ordinary workspace-relative IDENTITY.md avatars, but the reporter's confirmed oversized-avatar case still has a source-level UI failure path: metadata reports no usable avatar while chat fallback can still request the raw avatar URL and show a broken image instead of clear guidance.

## What This Changes

Request clearer handling for agent avatars defined in workspace IDENTITY.md, especially when local avatar files are rejected by size or validation limits.

## Best Possible Solution

Keep the authenticated raw avatar route conservative, expose only safe diagnostics through existing metadata/UI surfaces unless maintainers approve reason-specific HTTP errors, and suppress direct chat fallback for every rejected local-avatar reason.
