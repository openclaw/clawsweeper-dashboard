## Summary

Keep this PR open: its direct use of `AbortSignal.timeout()` adds an unguarded browser requirement to an Activity surface that Discord documents for web, iOS, and Android. On a client without that static API, the new call throws before `fetch`, so otherwise working launches fall into the generic “Gateway offline” UI; the supplied controlled-DOM test evidence does not establish real-client compatibility. ([docs.discord.com](https://docs.discord.com/developers/developer-tools/embedded-app-sdk?utm_source=openai))

## What This Changes

The PR adds a 15-second `AbortSignal.timeout()` signal to each Discord Activity token/widget fetch and introduces generated-shell regression tests for stalled requests.

## Best Possible Solution

Use a small Activity-local timeout helper built on broadly supported `AbortController` plus a cleared timer (or a feature-detected equivalent), cover the fallback in the generated-shell test, and attach redacted proof from a real Discord Activity launch before merge.
