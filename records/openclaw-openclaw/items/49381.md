## Summary

Keep open: current main still permits Feishu to close an errored or failed final and later show a recovered final for the same user turn, while the direct candidate PR is closed unmerged and the remaining fix boundary needs maintainer choice.

## What This Changes

The issue asks OpenClaw to prevent Feishu from sending multiple final assistant replies for one inbound DM when a rate-limited primary model fails over to a fallback model.

## Best Possible Solution

Land or adopt a focused final-delivery coordination fix that treats failed-primary plus recovered-fallback output as one user-visible Feishu turn while preserving explicit distinct diagnostics, with regression tests and redacted live Feishu failover proof.
