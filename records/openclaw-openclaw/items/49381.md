## Summary

Keep open: current main still permits the Feishu error-closeout shape where an errored/failed final and a later recovered final can both become visible, while the direct candidate PRs are closed unmerged and related issues only partially cover the failover-specific duplicate-final path.

## What This Changes

The issue reports duplicate Feishu final replies after a rate-limited primary model fails and a fallback model later succeeds for the same inbound message.

## Best Possible Solution

Land or adopt a focused Feishu/final-delivery coordination fix that treats failed-primary plus recovered-fallback output as one user-visible turn while preserving intentional distinct diagnostics, with regression tests and redacted live Feishu failover proof.
