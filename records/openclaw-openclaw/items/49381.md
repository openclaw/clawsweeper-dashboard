## Summary

Keep open: current main and latest v2026.6.11 still preserve later Feishu finals after an error closeout, while the merged identical-final dedupe only covers byte-identical payload entries and the direct Feishu candidate PR is closed unmerged.

## What This Changes

The issue reports duplicate Feishu final replies when a rate-limited primary model fails over to a fallback model.

## Best Possible Solution

Land or adopt a focused Feishu/final-delivery coordination fix that treats failed-primary plus recovered-fallback output as one user-visible turn while preserving intentional distinct diagnostics, backed by regression tests and redacted live Feishu failover proof.
