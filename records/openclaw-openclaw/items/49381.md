## Summary

Keep open: current main now dedupes byte-identical final payload entries, but the Feishu error-closeout path still intentionally allows an errored/failed final and a later recovered final to both become visible, and the direct Feishu candidate PR is closed unmerged.

## What This Changes

Prevent one Feishu inbound message from producing duplicate final assistant replies when the primary model rate-limits and a fallback model succeeds.

## Best Possible Solution

Land or adopt a focused Feishu/final-delivery coordination fix that treats failed-primary plus recovered-fallback output as one user-visible turn while preserving intentional distinct diagnostics, with regression tests and redacted live Feishu failover proof.
