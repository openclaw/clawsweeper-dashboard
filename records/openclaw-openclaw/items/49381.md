## Summary

Keep open: current main has the adjacent shared dedupe for byte-identical non-streaming final payloads, but it still preserves the Feishu error-closeout plus later recovered-final shape that this failover report is about.

## What This Changes

The issue reports duplicate user-visible final replies in Feishu when a rate-limited primary model fails over to a fallback model and both the failed attempt and recovered attempt can surface as final-looking replies.

## Best Possible Solution

Land or adopt a focused Feishu/final-delivery coordination fix that treats failed-primary plus recovered-fallback output as one user-visible turn while preserving intentional distinct diagnostics, with regression coverage and redacted live Feishu failover proof before release.

Owner confidence: high

Options:

- **Narrow Feishu Recovery Guard (recommended):** Make Feishu keep or replace the errored-attempt card during transient failover and deliver only the recovered fallback final for that user turn, with explicit tests for distinct diagnostics.
- **Shared Final Identity Contract:** Define a cross-channel same-turn final identity rule so failed-attempt and recovered-fallback duplicates collapse in the shared dispatcher without losing intentional repeated finals.
- **Fold Into Durable Delivery Roadmap:** Track this only under the broader durable final-delivery contract and defer a Feishu-local fix until that cross-channel design is ready.
