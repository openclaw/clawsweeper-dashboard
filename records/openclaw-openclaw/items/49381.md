## Summary

Keep open: current main still permits the Feishu error-closeout shape where an errored/failed final and a later recovered final can both become visible, and the direct candidate PRs are closed unmerged while related issues only partially cover this failover-specific duplicate-final path.

## What This Changes

The issue reports duplicate Feishu final replies when a primary model is rate-limited and a fallback model later succeeds.

## Best Possible Solution

Land or adopt a focused Feishu/final-delivery coordination fix that treats failed-primary plus recovered-fallback output as one user-visible turn while preserving intentional distinct diagnostics, with regression tests and redacted live Feishu failover proof.

- **Fold Into Durable Delivery Roadmap:** Track this only under the broader durable final-delivery contract and defer a Feishu-local fix until that cross-channel contract is designed.
