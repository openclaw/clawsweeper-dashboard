## Summary

Keep open: current main still has the Feishu error/failover closeout shape where an errored visible final and a recovered fallback final can both remain user-visible, while the direct candidate PR is closed unmerged and overlapping issues do not fully own this failover-specific duplicate-final report.

## What This Changes

The issue reports that one Feishu direct message can produce duplicate final assistant replies when the primary model is rate-limited and OpenClaw falls back to a secondary model.

## Best Possible Solution

Land or adopt one focused Feishu/final-delivery coordination fix that treats failed-primary plus recovered-fallback output as one user-visible turn while preserving intentional distinct diagnostics, with regression tests and redacted live Feishu failover proof.
