## Summary

Keep open: the Gateway-owned lock fix is useful and has strong live proof, but the current head still treats any nonempty `OPENCLAW_GATEWAY_PORT` as an explicit target. Malformed env values are ignored by the shared port resolver, so this raw check can skip the active-lock lookup and route TUI back to config/default port.

## What This Changes

The PR records the resolved Gateway runtime port in the lock, verifies the live lock owner/process identity, makes TUI use that active local port when no explicit target exists, and updates focused tests and TUI docs.

## Best Possible Solution

Merge after the TUI resolver uses the same parsed valid-port semantics as `resolveGatewayPort` before suppressing active-lock lookup, with a focused malformed-env regression test.
