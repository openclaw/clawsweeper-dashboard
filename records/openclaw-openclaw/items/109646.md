## Summary

Keep this PR open for a narrow correction and contributor proof: bounding the process-wide warning set is reasonable, but the proposed eviction order weakens the existing duplicate-warning suppression once the cache is full.

## What This Changes

The PR caps the process-wide Telegram invalid `allowFrom` warning deduplication set at 256 entries and evicts the oldest cached entry when the limit is reached.

## Best Possible Solution

Check for an existing entry first, evict the oldest key only when inserting a new distinct value at capacity, and cover both capacity eviction and duplicate hits before providing redacted runtime log proof.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, from source: fill the cache with 256 distinct entries, process an entry already present, then process the oldest original entry; the patch evicts that oldest value on the cache hit and warns for it again later.

## Solution Assessment

No in its current ordering; a bounded Set is an appropriate small solution, but eviction should happen only after determining that a new distinct key will be inserted.
