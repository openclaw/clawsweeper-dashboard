## Summary

Keep this issue open: current main includes the merged provider replay fixes, but the later aggregate-truncation report still matches current source because fresh text tool results can be cleared to empty provider-prompt text.

## What This Changes

The issue reports ordinary text tool results degrading to `(see attached image)` or empty model-visible content in long-lived agent sessions after prompt-history truncation/provider replay.

## Best Possible Solution

Fix the aggregate prompt-history truncation layer so the freshest in-run tool-result batch remains model-visible after per-result caps, and make any unavoidable elision non-empty and explicit.

## Reproduction Assessment

Yes. Source inspection shows the aggregate truncation recovery path can clear text blocks to `""`, and the embedded runner applies that transform to provider prompt history with shared per-run projection state.

## Solution Assessment

No current-main solution is sufficient. The merged provider replay fixes reduce placeholder masking, but they do not prevent the aggregate truncation layer from wiping fresh ordinary text before provider conversion.
