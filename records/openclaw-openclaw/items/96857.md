## Summary

Keep open. Current main has fixed narrower provider/transport placeholder branches, but the latest repro points to a still-present aggregate prompt-history truncation path that can clear fresh tool-result text before the model sees it.

## What This Changes

The issue reports that ordinary text tool outputs can reach agent-visible model context as `(see attached image)` or empty text instead of the original text payload.

## Best Possible Solution

Keep this issue as the canonical tracker for aggregate prompt-history truncation, and land a focused fix that protects fresh in-run tool results from aggregate clearing while leaving explicit non-empty elision markers for truly dropped old results.

## Reproduction Assessment

Yes, source-level. Current main still applies aggregate tool-result prompt truncation on each provider call and can clear eligible text blocks to empty strings after projection entries are frozen; I did not run a local live session repro in this read-only review.

## Solution Assessment

No current merged fix is complete. The provider replay extractor work is the right layer for structured placeholders, but the remaining best fix belongs in the aggregate truncation/projection path so fresh tool results are not cleared before the model can react.
