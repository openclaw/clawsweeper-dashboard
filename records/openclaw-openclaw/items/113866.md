## Summary

Keep this PR open for a narrow replay-safety fix. Its real Claude CLI proof is strong, but the new lifecycle-only timeout classification is not limited to resumed turns, so a first-turn init-only stall can enter retry handling and replay the initial prompt. Likely related people: `steipete` (CLI-runner history, medium confidence) and `obviyus` (session-resumption history, medium confidence).

## What This Changes

The PR recovers a safely stalled resumed Claude CLI session by forking its native session, persisting the successor ID, and falling back to transcript reconstruction only if that retry fails safely.

## System Context

OpenClaw’s CLI agent runner starts provider CLIs and persists their native session bindings in the agent session store. When a Claude CLI turn stalls, this path decides whether retrying is safe, then either preserves native conversation/cache continuity through a fork or reconstructs the turn from the OpenClaw transcript.

## Architecture Diagram

flowchart LR
  A[User turn] --> B[CLI agent runner]
  B --> C[Claude CLI live session]
  C --> D{No-output watchdog}
  D -->|Safe resumed stall| E[Fork native Claude session]
  E --> F[Persist successor binding]
  D -->|Unsafe or failed recovery| G[Transcript reconstruction fallback]
  F --> H[Next user turn resumes successor]
  G --> H

## Best Possible Solution

Preserve the cache-aware fork design, but classify lifecycle-only no-output timeouts as replayable only when the attempted Claude turn is resuming an existing native session; add regression coverage proving a fresh init-only stall remains non-retryable.
