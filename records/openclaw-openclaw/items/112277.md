## What This Changes

The issue asks to mount `/workspace/.openclaw/sandbox-skills/skills` read-write so sandboxed agents can delete materialized skills during autonomous uninstallation.

## Best Possible Solution

Keep the materialized directory owner-managed and make supported uninstallation remove the canonical workspace skill then trigger a controlled materialization refresh or sandbox recreation so the active view is regenerated without granting arbitrary writes to generated content.
