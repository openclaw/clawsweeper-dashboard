## Summary

The current head retains the previously reported P1 defect: it prevents an unbounded allocation but silently omits a symlinked mcporter registry that remains active at runtime. The real CLI proof is strong for oversized regular files, but the runtime/audit mismatch must be repaired before merge.

## What This Changes

The PR replaces the security audit’s unbounded mcporter registry read with a 16 MiB symlink-rejecting regular-file read and adds oversized-file regression coverage.

## Best Possible Solution

Retain the 16 MiB cap while using bounded path semantics compatible with mcporter, or emit a dedicated incomplete-audit finding whenever an existing registry cannot be safely inspected; cover valid symlinked and oversized registries.
