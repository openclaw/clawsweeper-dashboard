## Summary

Keep open: current main and v2026.6.11 have Feishu group sender/topic session scoping, DM-only dynamic agent creation, and explicit thread-bound subagent bindings, but not automatic group-sender agent provisioning with isolated workspaces, skills, config, memory, lifecycle, quota, and authorization.

## What This Changes

Request automatic Feishu group-chat per-sender subagents with isolated skills, configuration, memory, and reply routing.

## Best Possible Solution

Define a maintainer-approved identity-to-agent binding, authorization/quota/lifecycle, and shared/private memory contract first, then implement optional Feishu group-sender provisioning through channel-owned routing and existing agent-binding seams.

## Maintainer Decision

Kind: product_direction

Question: Should Feishu support automatic group-sender agent provisioning, and what identity, authorization, quota/lifecycle, and shared/private memory boundaries should become the public contract?

Rationale: The request creates durable agents, workspaces, skills, config, memory, and routing authority from group-chat senders, which cannot be safely inferred from current session scoping or thread-bound subagent hooks.

Likely owner: steipete

Owner reason: They appear in recent history for the relevant Feishu, docs, plugin SDK, and subagent-runtime surfaces and are the best current routing candidate among the observed owners.

Owner confidence: medium

Options:

- **Design generic contract first (recommended):** Define admin-authorized identity-to-agent lifecycle, private/shared memory tiers, quotas, and cleanup as reusable channel/plugin contracts before adding Feishu behavior.
- **Keep current supported paths:** Document groupSessionScope, static bindings, and explicit thread-bound subagents as the supported Feishu group-chat model for now.
- **Route outside core:** Reject automatic provisioning in OpenClaw core and let a Feishu-specific external plugin own the durable group identity policy if current plugin seams are sufficient.

## Reproduction Assessment

Yes, source-level: the group path can route by sender/topic session key, but dynamic agent creation is gated to DMs and subagent binding requires an explicit thread-bound spawn.

## Solution Assessment

No, implicit Feishu-only subagent factories are not yet the best fix; maintainers need a generic or Feishu-owned identity-to-agent lifecycle and memory/security contract first.
