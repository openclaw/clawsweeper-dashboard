## Summary

Keep open: current main has Feishu group sender/topic session scoping, DM-only dynamic agent creation, and Feishu subagent conversation binding, but it still does not implement automatic per-sender group subagents with isolated skills, config, memory, lifecycle, and admin policy. The KinthAI comments add useful prior art for sender-keyed sessions, private/shared memory tiers, TTLs, warm pools, and cost governance, so this remains product/security design work rather than cleanup closure.

## What This Changes

Request Feishu group chats to dynamically create and route per-sender subAgents with isolated workspace, skills, config, memory, and lifecycle.

## Best Possible Solution

Define a maintainer-approved identity-to-agent binding, authorization/quota/lifecycle, and shared/private memory contract first, then implement optional Feishu group-sender provisioning through existing channel routing and agent-binding seams.
