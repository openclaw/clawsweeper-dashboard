## Summary

Keep open: current main has Feishu per-sender group session scopes, DM-only dynamic agents, and Feishu topic/DM subagent binding, but it does not implement automatic group-chat per-user subagents with isolated skills, config, memory, lifecycle, and orchestrator routing.

## What This Changes

The issue requests Feishu group-chat per-user subagents with isolated skills, config, memory, routing, admin controls, and lifecycle management.

## Best Possible Solution

Split this into owner-approved narrower work: keep using groupSessionScope for sender session isolation, resolve the concrete multi-bot identity bug in #40194, and design any Feishu group per-sender dynamic-agent/subagent API with explicit lifecycle, permission, memory, and live-proof requirements.
