## Summary

Keep open: current main and the latest release have Feishu sender/topic-scoped group sessions, DM dynamic agents, and Feishu subagent/thread bindings, but they still do not implement automatic group-chat per-user subagents with isolated skills, hot config, memory, lifecycle, and admin controls. This remains a product and security-boundary decision, not a conservative cleanup close.

## What This Changes

Request per-user Feishu group-chat subagents with isolated skills, configuration, memory, lifecycle, routing, and admin control.

## Best Possible Solution

Define a Feishu-owned design that separates sender-scoped session routing, memory namespaces, subagent lifecycle, skill/config policy, cleanup/quotas, and admin controls, then implement only the approved seam in the Feishu plugin or SDK.
