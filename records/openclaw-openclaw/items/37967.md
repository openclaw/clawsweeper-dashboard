## Summary

Keep open: current main has Feishu per-sender group session scopes, DM-only dynamic agent creation, and Feishu subagent thread binding, but it does not implement the requested Feishu group-chat per-sender subagent lifecycle with isolated skills, config, memory, admin controls, cleanup, and routing policy.

## What This Changes

The issue requests dynamic Feishu group-chat subagents keyed per sender or role, with isolated skills, configuration, memory, routing, lifecycle cleanup, and admin controls.

## Best Possible Solution

Choose a bounded Feishu plugin design: either keep current sender-scoped sessions, bindings, and DM dynamic agents as the supported path, or add an explicit opt-in group-subagent mode with limits, cleanup, permissions, docs, and focused live proof.
