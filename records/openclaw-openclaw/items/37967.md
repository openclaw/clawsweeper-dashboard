## Label Justifications

- `P2`: This is a substantial Feishu group-chat capability and isolation design gap, but it is not a current core outage or release-blocking regression.
- `impact:session-state`: The request centers on per-sender agent sessions, memory, skill state, and conversation isolation in Feishu groups.
- `impact:security`: Automatic group identities creating durable agents would affect authorization, tool access, workspace boundaries, and memory visibility.
- `impact:message-loss`: The requested routing changes determine which user-specific subagent receives and answers each Feishu group message, with misrouting as a stated failure mode.

## Summary

Keep open: current main and v2026.6.11 provide Feishu group sender/topic session scoping, DM-only dynamic agent creation, and explicit thread-bound subagent hooks, but they do not provide automatic durable group-sender subagents with isolated workspace, skills, config, memory, lifecycle, quota, and authorization boundaries.

## What This Changes

Request automatic Feishu group-chat routing to durable per-sender subagents with isolated skills, config, memory, lifecycle, and replies relayed back through the main bot.

## Best Possible Solution

Define an admin-authorized identity-to-agent lifecycle, quota/TTL, shared/private memory, and per-agent skill/config contract first, then implement opt-in Feishu group-sender provisioning through channel/plugin routing seams.
