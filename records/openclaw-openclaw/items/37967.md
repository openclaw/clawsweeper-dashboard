## Summary

Keep open: current main and the latest release only cover Feishu group sender/topic session scoping, DM-only dynamic agent creation, and explicit thread-bound subagent hooks; the requested automatic durable per-sender group agents with isolated workspaces, skills, config, memory, lifecycle, quotas, and authorization remain a product/security decision.

## What This Changes

Request automatic Feishu group-chat routing that creates and uses per-sender subagents with isolated skills, config, memory, workspace state, and admin lifecycle controls.

## Best Possible Solution

Define a maintainer-approved generic identity-to-agent lifecycle, authorization, quota/cleanup, and shared/private memory contract first, then let Feishu adopt it through channel/plugin routing seams.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should Feishu support automatic group-sender agent provisioning, and what identity, authorization, quota/lifecycle, and shared/private memory boundaries should become the public contract?

Rationale: The request changes durable agent creation, workspace/config mutation, memory isolation, routing authority, and cost/security boundaries rather than fixing an existing Feishu session-key bug.

Likely owner: Peter Steinberger

Owner reason: This choice spans Feishu routing, plugin APIs, subagent semantics, memory/security policy, and VISION.md core-lean product direction where this history is strongest.

Owner confidence: medium

Options:

- **Design the generic contract first (recommended):** Approve a generic admin-authorized identity-to-agent lifecycle plus shared/private memory contract, then implement Feishu as one adopter.
- **Keep explicit routing only:** Keep current group session scoping plus explicit thread-bound subagents and document external deployment patterns for per-user agent fleets.
- **Decline automatic provisioning:** Close this direction if group-chat sender identities should not automatically create durable agents inside OpenClaw.

## Reproduction Assessment

Yes, source-level. Current main can scope Feishu group sessions by sender/topic and can create dynamic agents for DMs, but the group path never calls the dynamic-agent factory and Feishu subagent hooks require explicit thread-bound spawning.

## Solution Assessment

No, not as an implicit Feishu-only subagent factory. The safer solution is a generic admin-authorized identity-to-agent lifecycle and memory contract before a Feishu implementation.
