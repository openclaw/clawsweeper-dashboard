## Summary

Keep open: current main has Feishu sender-scoped group sessions, DM dynamic agents, and Feishu subagent/thread bindings, but it still does not implement the requested group-chat per-user subagent lifecycle with isolated skills, hot config, and memory. This remains a product and security-boundary decision rather than conservative cleanup-closeable.

## What This Changes

Requested Feishu group-chat routing that dynamically creates per-sender subagents with isolated skills, configuration, memory, lifecycle controls, and group reply relay.

## Best Possible Solution

Define a Feishu-owned design that separates sender-scoped session routing, memory namespaces, subagent lifecycle, skill/config policy, cleanup/quotas, and admin controls, then implement only the approved seam in the Feishu plugin or SDK.
