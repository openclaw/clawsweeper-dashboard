## Summary

Keep open: current main has Feishu group session scoping, DM-only dynamic agent creation, and explicit thread-bound subagent hooks, but not automatic persistent per-sender group subagents with isolated workspaces, skills, config, memory, lifecycle, quotas, and authorization.

## What This Changes

Request automatic Feishu group-chat routing that creates or reuses a dedicated subagent per sender or role with isolated skills, config, memory, and reply delivery.

## Best Possible Solution

Define a maintainer-approved identity-to-agent binding, authorization/quota/lifecycle model, and shared/private memory contract first, then implement opt-in Feishu group-sender provisioning through the channel plugin and existing agent-routing seams.

## Risks / Open Questions

- Implicitly creating durable agents from group-chat sender identities can grant workspaces, tools, credentials, config, and cost-bearing model access without a defined admin authorization model.
- The requested shared/private memory split is central; a namespace mistake could leak one participant's context, preferences, or tool results into another participant's agent.
