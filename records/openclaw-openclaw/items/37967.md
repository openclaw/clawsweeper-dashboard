## Summary

Keep open: current main and v2026.6.11 cover Feishu group sender/topic session scoping, DM-only dynamic agent creation, and explicit thread-bound subagent hooks, but they do not implement automatic durable per-sender group agents with isolated workspaces, skills, config, memory, lifecycle, quotas, and authorization.

## What This Changes

Request automatic Feishu group-chat routing that creates or reuses per-sender subagents with isolated skills, configuration, memory, and replies relayed through the main bot.

## Best Possible Solution

Define a maintainer-approved identity-to-agent lifecycle plus authorization, quota, retention, and shared/private memory contract first, then implement optional Feishu group-sender provisioning through channel/plugin routing seams.

Yes, source-level. Current main can scope Feishu group sessions by sender/topic and can create dynamic agents for DMs, but the group path never calls the dynamic-agent factory and Feishu subagent hooks require an explicit thread-bound spawn.

## Solution Assessment

No, not as an implicit Feishu-only subagent factory. The safer solution is a generic admin-authorized identity-to-agent lifecycle and memory contract before a Feishu implementation.
