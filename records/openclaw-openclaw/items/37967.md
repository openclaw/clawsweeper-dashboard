## Summary

Keep open: current main and v2026.6.11 support Feishu group sender/topic session scoping and DM-only dynamic agent creation, but the requested automatic group-sender subagent provisioning with isolated workspaces, skills, config, memory, lifecycle, quotas, and authorization is still missing and needs maintainer product/security direction.

## What This Changes

Request automatic Feishu group-chat routing that creates one durable, isolated subagent per sender or role, with per-user skills, config, memory, lifecycle, and admin controls.

## Best Possible Solution

Define a maintainer-approved identity-to-agent binding plus authorization, quota/lifecycle, and shared/private memory contract first, then implement optional Feishu group-sender provisioning through channel/plugin routing seams.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Feishu support automatic group-sender agent provisioning, and what identity, authorization, quota/lifecycle, and shared/private memory boundaries should become the public contract?

Rationale: The request changes durable agent creation, workspace/config mutation, memory isolation, routing authority, and cost/security boundaries rather than only fixing a Feishu session-key bug.

Likely owner: steipete

Owner reason: This decision spans Feishu routing, plugin API boundaries, subagent semantics, memory/security policy, and core-lean product direction where recent history points to this owner as the strongest routing candidate.

Owner confidence: high

Options:

- **Design the generic contract first (recommended):** Approve a generic, admin-authorized identity-to-agent lifecycle and shared/private memory contract, then implement Feishu as one channel/plugin adopter.
- **Keep explicit routing only:** Keep current group session scoping plus explicit thread-bound subagents and document external deployment patterns for per-user agent fleets.
- **Decline automatic provisioning:** Close this direction if group chat sender identities should not automatically create durable agents inside OpenClaw.

## Reproduction Assessment

Yes, as a source-level feature gap. Current main can scope Feishu group sessions by sender/topic and can create dynamic agents for DMs, but the group path never calls the dynamic-agent factory and the helper writes direct-peer bindings only.

## Solution Assessment

No, not as an implicit Feishu-only subagent factory. The safer solution is a generic admin-authorized identity-to-agent lifecycle, quota, and memory contract before a Feishu implementation.
