## Summary

Keep open: current main and v2026.6.11 provide adjacent Feishu group sender/topic session scoping, DM-only dynamic agent creation, and explicit thread-bound subagent hooks, but they do not provide automatic durable Feishu group-sender subagents with isolated workspace, skills/config, memory, lifecycle/quota, and authorization.

## What This Changes

Request automatic Feishu group-chat routing to per-sender subagents with isolated skills, configuration, memory, and lifecycle management.

## Best Possible Solution

Define a generic opt-in identity-to-agent lifecycle, authorization/quota/TTL, shared/private memory, and per-agent skill/config contract, then implement Feishu group-sender provisioning through channel/plugin seams.

## Security Review

Status: needs_attention

Summary: The issue is security-sensitive because automatic group identities would create durable agents with isolated memory and skills, requiring explicit authorization, namespace, and lifecycle policy before implementation.

Concerns:

- **[high] Define group identity authorization before provisioning agents:**
  - body: A Feishu group event would become a durable agent-creation trigger, so maintainers need a contract for which sender identities may create agents and what skills/config/tool access they inherit.
  - confidence: 0.9
- **[high] Separate shared group memory from private sender memory:**
  - body: Per-sender agents need a hard memory namespace boundary plus a deliberate shared-context layer, or group conversations can leak one sender's private history to another.
  - confidence: 0.88
- **[medium] Bound lifecycle and cost growth:**
  - body: Lazy group-sender provisioning needs TTL, quotas, cleanup, and cost attribution before it is safe for groups with many members or hostile senders.
  - confidence: 0.86
