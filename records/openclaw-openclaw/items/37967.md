## Summary

Keep open. Current main has Feishu sender/topic-scoped group sessions, DM-only dynamic agent creation, and Feishu subagent thread bindings, but it does not implement automatic per-sender group-chat subagents with isolated skills, config, memory, lifecycle, and admin controls.

## What This Changes

Request to add Feishu group chat routing that creates per-sender subagents with isolated skills, config, memory, lifecycle, and admin controls.

## Best Possible Solution

Define a Feishu-owned group isolation contract first: choose the canonical routing model, lifecycle limits, memory/skill inheritance rules, admin controls, and live Feishu proof requirements before implementation.

Options:

- **Use scoped sessions and bindings first (recommended):** Keep group isolation in Feishu session routing and explicit bindings, add only missing plugin API/config pieces, and avoid default dynamic subagent trees.
- **Adopt group dynamic subagents:** Design explicit lifecycle, quotas, admin commands, memory/skill boundaries, and live Feishu proof before implementing automatic per-sender agents.
- **Defer to narrower issues:** Resolve multi-bot account/session collision and context-pollution issues before revisiting full per-user group subagents.

## Reproduction Assessment

Not a bug reproduction; as a source-level feature gap, current main supports group sender/topic session scoping and DM dynamic agent creation, but not automatic group sender subagent creation with isolated skill/config/memory.

## Solution Assessment

Unclear. Per-user subagents are plausible for advanced Feishu team workflows, but a simpler groupSessionScope/account-scoped session policy or plugin-owned binding path may be safer than making group subagents the default orchestration model.
