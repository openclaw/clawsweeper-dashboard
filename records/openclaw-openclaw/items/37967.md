## Summary

Keep open: current main has Feishu sender/topic-scoped group sessions, DM-only dynamic agent creation, and Feishu subagent/thread binding for DMs and topic conversations, but it still lacks the requested Feishu group-chat per-user subagent lifecycle with isolated skills, config, memory, and admin policy. The remaining work is product and security-boundary design rather than conservative cleanup-closeable work.

## What This Changes

Request Feishu group chat routing to create per-sender subagents with isolated skills, config, memory, workspace, and admin-controlled lifecycle.

## Best Possible Solution

Define a Feishu-owned design that separates sender-scoped session routing, memory namespace tiers, subagent lifecycle/cleanup/quotas, skill/config/admin policy, and live Feishu proof before implementing plugin or SDK changes.
