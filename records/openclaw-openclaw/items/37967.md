## Summary

Keep open: current main has Feishu sender-scoped group/topic sessions, direct-message dynamic agent creation, and Feishu subagent/thread bindings, but it still does not implement the requested group-chat per-user subagent lifecycle with isolated skills, hot config, and memory. The remaining work is a product and security boundary decision, not conservative cleanup-closeable.

## What This Changes

The issue requests Feishu group-chat routing that dynamically creates per-sender subagents with isolated skills, configuration, and memory.

## Best Possible Solution

Define a Feishu group-persona model that uses existing sender-scoped sessions where sufficient, and only adds automatic per-user agent provisioning after maintainers decide lifecycle, quota, skill/config authority, and memory namespace rules.

## Reproduction Assessment

Yes for the source-level gap, not for a live Feishu run: current code only creates dynamic Feishu agents for direct messages and has no group-chat per-user agent provisioning path. The issue is primarily a feature request, so live failure reproduction is not the main blocker.

## Solution Assessment

Unclear as proposed: automatic per-user subagents may solve isolation, but it is not obviously the best default because sender-scoped sessions and plugin-owned routing may cover part of the need with less security and lifecycle risk.
