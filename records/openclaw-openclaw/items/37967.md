## Summary

Keep open: current main supports Feishu group sender/topic session scoping, DM-only dynamic-agent creation, and explicit thread-bound subagent hooks, but not automatic durable per-sender group subagents with isolated workspaces, skills/config, memory, lifecycle, quotas, and authorization; the KinthAI comments add useful real-world design evidence rather than making the core request obsolete.

## What This Changes

Request automatic Feishu group-chat per-sender subagents with isolated workspace, skills/config, memory, and routing.

## Best Possible Solution

Define a maintainer-approved identity-to-agent binding plus authorization, quota/lifecycle, and shared/private memory contract first, then implement optional Feishu group-sender provisioning through channel/plugin routing seams.

## Solution Assessment

No, not as an implicit Feishu-only subagent factory; the safer solution is a generic admin-authorized identity-to-agent lifecycle and shared/private memory contract before a Feishu implementation.
