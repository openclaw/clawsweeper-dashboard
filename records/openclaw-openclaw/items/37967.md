## Summary

Keep open: current main covers Feishu group sender/topic session keys, DM-only dynamic agent creation, and thread-bound ACP/subagent hooks, but it does not implement automatic durable Feishu group-sender subagents with isolated workspaces, skills, config, memory, lifecycle, quotas, and authorization.

## What This Changes

The issue requests Feishu group chat routing that dynamically creates one isolated subagent per unique sender or role with separate skills, configuration, memory, and replies relayed through the group bot.

## Best Possible Solution

Design this as an explicit opt-in Feishu plugin capability, with maintainer-approved authorization, quotas, lifecycle cleanup, per-agent skill/memory boundaries, migration/docs, and live Feishu proof before implementation.
