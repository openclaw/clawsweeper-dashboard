## Summary

Keep open: current main and v2026.6.11 still provide only adjacent Feishu group sender/topic session scoping, DM-only dynamic agent creation, and explicit thread-bound subagent hooks. They do not implement automatic persistent group-sender subagents with isolated workspaces, skills, config, memory, lifecycle, quotas, or authorization; the KinthAI comments are useful production-design evidence, not a reason to close.

## What This Changes

Request Feishu group-chat routing that creates or reuses user-specific subagents with isolated skills, configuration, memory, and replies per sender.

## Best Possible Solution

Define a maintainer-approved identity-to-agent binding and lifecycle contract first, then implement optional Feishu group-sender provisioning with quotas, SQLite-backed state, memory isolation, deterministic routing, and security/audit coverage.

## Reproduction Assessment

Yes, at source level: current main has Feishu group sender/topic session scoping and DM dynamic-agent creation, but group messages do not trigger automatic persistent per-sender agent provisioning with isolated workspace, skills, config, and memory.

## Solution Assessment

No, not as an implicit Feishu-only subagent factory. The safer path is a generic administrator-authorized identity-to-agent binding and lifecycle contract, followed by an optional Feishu implementation using existing group session and conversation-binding seams.
