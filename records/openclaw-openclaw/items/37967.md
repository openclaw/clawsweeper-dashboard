## Summary

Keep open: current main and v2026.6.11 provide Feishu group session scoping, DM-only dynamic agent creation, and explicit thread-bound subagent hooks, but they do not implement automatic persistent group-sender subagents with isolated workspaces, skills, config, memory, lifecycle, quotas, and authorization.

## What This Changes

Request automatic Feishu group-chat routing that creates or reuses sender-specific subagents with isolated memory, skills, config, and replies relayed through the group bot.

## Best Possible Solution

Define a maintainer-approved identity-to-agent binding, authorization/quota/lifecycle, and shared/private memory contract first, then implement optional Feishu group-sender provisioning through existing channel routing and agent-binding seams.

- **Keep Session-Only Routing:** Keep current groupSessionScope and explicit subagent/thread mechanisms, documenting full per-user agent orchestration as a separate deployment or plugin pattern for now.
- **Reject Automatic Provisioning:** Close the feature direction if maintainers decide group identities should never create durable OpenClaw agents automatically.

Yes. Source-level reproduction is high confidence: current Feishu group handling can scope sessions by sender/topic, but only the non-group DM path calls maybeCreateDynamicAgent and the subagent hook requires explicit thread-bound spawning.

## Solution Assessment

No, not as an implicit Feishu-only subagent factory. A generic admin-authorized identity-to-agent lifecycle and shared/private memory contract is the safer owner boundary before implementing Feishu-specific behavior.
