## Summary

Keep open: current main and v2026.6.11 provide adjacent Feishu group session scoping, DM-only dynamic agent creation, and explicit thread-bound subagent hooks, but not automatic persistent group-sender subagents with isolated workspaces, skills, config, memory, lifecycle, quotas, and authorization.

## What This Changes

Request Feishu group-chat routing that creates or reuses user-specific subagents with isolated skills, configuration, memory, and replies relayed through the main bot.

## Best Possible Solution

Define a maintainer-approved identity-to-agent binding, authorization/quota/lifecycle, and shared/private memory contract first, then implement optional Feishu group-sender provisioning through existing channel routing and agent-binding seams.

- **Keep session-only routing:** Keep current groupSessionScope and explicit subagent/thread mechanisms, documenting that full per-user agent orchestration belongs in an external plugin or deployment pattern for now.
- **Reject automatic provisioning:** Close this feature if maintainers decide group identities should never create durable OpenClaw agents automatically.

## Reproduction Assessment

Yes, source-level: current Feishu group messages can be scoped by sender/topic and DMs can create dynamic agents, but the group path never calls the dynamic-agent factory and subagent hooks require explicit thread-bound spawn.

## Solution Assessment

No, not as an implicit Feishu-only subagent factory; a generic admin-authorized identity-to-agent lifecycle and memory contract is safer before implementing the Feishu-specific behavior.
