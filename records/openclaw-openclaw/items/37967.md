## Summary

Keep open: current main and v2026.6.11 have Feishu group sender/topic session scoping, DM-only dynamic agent creation, and explicit thread-bound subagent hooks, but they do not implement automatic persistent Feishu group-sender subagents with isolated workspaces, skills, config, memory, lifecycle, quotas, and authorization. The KinthAI comments add useful prior-art detail around sender-keyed sessions, private/shared memory, TTLs, warm pools, and cost controls, which reinforces that this needs maintainer product and security design rather than cleanup closure.

## What This Changes

Request automatic Feishu group-chat routing that creates or reuses one isolated subagent per sender or role, with per-user skills, config, memory, lifecycle, and replies relayed back through the main bot.

## Best Possible Solution

Define a maintainer-approved identity-to-agent binding, authorization/quota/lifecycle, and shared/private memory contract first, then implement optional Feishu group-sender provisioning through channel-owned routing and existing agent-binding seams.

## Solution Assessment

No, not as an implicit Feishu-only subagent factory. A generic admin-authorized identity-to-agent lifecycle and shared/private memory contract is safer before implementing Feishu-specific automatic provisioning.
