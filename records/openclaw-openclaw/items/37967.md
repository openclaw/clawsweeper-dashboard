## Summary

Keep open: current main has Feishu group sender/topic session scopes, DM-only dynamic agent creation, and subagent thread binding, but it still does not implement automatic per-sender Feishu group subagents with isolated skills, config, memory, and lifecycle. The KinthAI comments add relevant prior art around sender-keyed sessions, private/shared memory tiers, TTLs, warm pools, and cost governance, which supports maintainer design review rather than cleanup closure.

## What This Changes

Request automatic Feishu group-chat subagents per sender, with isolated skills, configuration, memory, routing, admin controls, and lifecycle management.

## Best Possible Solution

Define an opt-in Feishu-owned group-sender agent mode that composes with existing groupSessionScope, bindings, and subagent APIs, with lifecycle limits, memory visibility, authorization, audit, docs, and tests before implementation.
