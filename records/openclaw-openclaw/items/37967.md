## Summary

Keep open: current main has Feishu group sender/topic session scoping, DM-only dynamic agent creation, and explicit Feishu thread-bound subagent hooks, but it still lacks automatic durable per-sender group agents with isolated workspaces, skills, config, memory, lifecycle, quotas, and authorization.

## What This Changes

The issue requests Feishu group-chat routing that creates durable per-sender subagents with isolated skills, config, memory, lifecycle, and replies.

## Best Possible Solution

Define a maintainer-approved identity-to-agent binding plus authorization, quota/lifecycle, and shared/private memory contract first, then implement optional Feishu group-sender provisioning through channel/plugin routing seams.

- **Decline automatic provisioning:** Close this direction if group chat sender identities should not automatically create durable agents inside OpenClaw.

## Reproduction Assessment

Yes, source-level: current main can scope Feishu group sessions by sender/topic and can create dynamic agents for DMs, but group messages do not enter the dynamic-agent factory and Feishu subagent hooks require explicit thread-bound spawning.

## Solution Assessment

No, not as an implicit Feishu-only subagent factory; the safer solution is a generic admin-authorized identity-to-agent lifecycle and memory contract before a Feishu implementation.
