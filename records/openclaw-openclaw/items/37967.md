## Summary

Keep open: current main and v2026.6.11 cover adjacent pieces, including Feishu group sender/topic session scopes and DM-only dynamic agents, but they do not implement dynamic per-sender subagents for Feishu group chats. The KinthAI comments add useful prior-art detail around sender-keyed sessions, private/shared memory tiers, lifecycle TTLs, warm pools, and cost governance, which strengthens the case for a maintainer design pass rather than cleanup closure.

## What This Changes

Request Feishu group chats dynamically create and route each sender to an isolated subagent with separate workspace, skills, config, memory, and group reply relay.

## Best Possible Solution

Define an opt-in Feishu-owned group-sender agent-isolation design that reuses existing groupSessionScope, bindings, and subagent/session APIs, then add explicit lifecycle, memory, permission, and migration rules before implementation.
