## Summary

Keep open: current main and v2026.6.11 have Feishu group sender/topic session scoping, DM-only dynamic agent creation, and explicit thread-bound subagent hooks, but they still do not provide automatic durable per-sender group agents with isolated workspaces, skills, config, memory, lifecycle, quotas, and authorization.

## What This Changes

The issue requests Feishu group chat routing that dynamically creates durable per-sender subagents with isolated skills, configuration, memory, lifecycle, and replies relayed back into the group.

## Best Possible Solution

Define a maintainer-approved generic identity-to-agent binding plus authorization, quota/lifecycle, and shared/private memory contract first, then make Feishu an optional channel/plugin adopter.

## Solution Assessment

No, not as an implicit Feishu-only subagent factory. The safer path is a generic admin-authorized identity-to-agent lifecycle and memory contract before a Feishu implementation.
