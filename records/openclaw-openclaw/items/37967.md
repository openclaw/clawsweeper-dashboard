## Summary

Keep open: current main and v2026.6.11 cover adjacent Feishu group sender/topic session routing, DM-only dynamic agent creation, and explicit thread-bound subagent hooks, but they do not implement automatic persistent group-sender subagents with isolated workspaces, skills, config, memory, lifecycle, quotas, and authorization.

## What This Changes

Request automatic Feishu group-chat routing to per-sender subagents with isolated skills, configuration, memory, and reply delivery.

## Best Possible Solution

Define an opt-in Feishu plugin design that reuses current group_sender/group_topic_sender routing where possible, but explicitly specifies authorization, memory namespace, skills/config inheritance, lifecycle/TTL, quotas, admin controls, and upgrade behavior before implementation.
