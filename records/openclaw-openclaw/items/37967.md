## Summary

Keep open: current main and latest v2026.6.11 support Feishu group sender/topic session scoping, DM-only dynamic agents, and explicit thread-bound subagent hooks, but they still do not provide automatic durable per-sender group agents with isolated workspaces, skills, config, memory, lifecycle, quotas, and authorization. The KinthAI comments are useful deployment evidence for the pattern, but they also reinforce that lifecycle, shared/private memory, routing, and cost controls need product/security review before implementation.

## What This Changes

The issue requests automatic Feishu group-sender subAgent creation and routing with isolated workspace, skills, config, memory, lifecycle, and admin controls.

## Best Possible Solution

Define a maintainer-approved identity-to-agent binding plus authorization, quota/lifecycle, and shared/private memory contract first, then implement optional Feishu group-sender provisioning through channel/plugin routing seams.
