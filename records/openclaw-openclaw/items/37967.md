## Summary

Keep open: current main and latest v2026.6.11 still provide Feishu group sender/topic session scoping, DM-only dynamic agent creation, and explicit thread-bound subagent hooks, but not automatic durable per-sender group subagents with isolated workspaces, skills, config, memory, lifecycle, quotas, and authorization.

## What This Changes

The issue requests automatic Feishu group-chat per-sender subagents with isolated workspaces, skills, configuration, memory, lifecycle, and replies relayed back to the group.

## Best Possible Solution

Define a maintainer-approved identity-to-agent lifecycle, authorization, quota/lifecycle, and shared/private memory contract first, then implement optional Feishu group-sender provisioning through plugin/channel routing seams.

- **Decline automatic provisioning:** Close this direction if group chat sender identities should not automatically create durable agents inside OpenClaw.

Yes, at source level: current main can route Feishu group sessions by sender/topic and can create dynamic agents for DMs, but the group path never calls the dynamic-agent factory and Feishu subagent hooks require explicit thread-bound spawn. ## Solution Assessment

No, not as an implicit Feishu-only subagent factory. The safer solution is a generic admin-authorized identity-to-agent lifecycle and memory contract before a Feishu implementation.
