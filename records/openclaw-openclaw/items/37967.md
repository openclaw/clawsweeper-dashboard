## Label Justifications

- `P2`: This is a substantial but non-emergency feature/design request with limited blast radius until maintainers choose a safe contract.
- `impact:session-state`: The request is fundamentally about per-user sessions, memory, context, and durable agent state in Feishu group chats.
- `impact:security`: Automatic group-sender agent creation would affect authorization, tool access, private memory boundaries, transcript storage, and per-user config control.
- `impact:message-loss`: The requested orchestrator must route each subagent reply back to the correct Feishu group sender/thread, so message misrouting or dropped replies is part of the problem class.

## Summary

Keep open: current main and v2026.6.11 have adjacent Feishu group sender/topic session scoping, DM-only dynamic agent creation, and explicit thread-bound subagent bindings, but they do not provide automatic durable group-sender subagents with isolated workspaces, skills, config, memory, lifecycle, quotas, and authorization.

## What This Changes

Request automatic Feishu group-chat routing to user-specific subagents with isolated workspaces, skills, config, memory, lifecycle, and admin controls.

## Best Possible Solution

Define an opt-in identity-to-agent lifecycle contract covering identity keys, group/private memory namespaces, authorization, quotas/TTL, skill/config ownership, and cleanup, then implement Feishu group sender support on that seam with docs and regression proof.
