## Summary

Keep open: current main has Feishu group sender/topic session scopes, DM-only dynamic agent creation, and explicit thread-bound subagent hooks, but it still does not implement automatic per-sender Feishu group subagents with isolated skills, config, memory, lifecycle, and admin controls.

## What This Changes

Request dynamic Feishu group-chat subagents per sender or role, with isolated skills, configuration, memory, lifecycle, and group reply routing.

## Best Possible Solution

Define a maintainer-approved opt-in identity-to-agent binding, authorization/quota/lifecycle model, and shared/private memory contract, then implement Feishu group-sender provisioning through the existing channel routing and agent-binding seams.

## Solution Assessment

No, not as an implicit Feishu-only subagent factory; a generic admin-authorized identity-to-agent lifecycle and memory contract is safer before implementing Feishu-specific routing behavior.
