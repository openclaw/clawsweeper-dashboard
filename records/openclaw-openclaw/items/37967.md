## Label Justifications

- `P2`: This is a substantial Feishu group-chat isolation capability and design gap, but it is not a current release-blocking outage for all users.
- `impact:session-state`: The request centers on per-sender agent sessions, memory, skill state, and conversation isolation in Feishu group chats.
- `impact:security`: Automatic group identities creating durable agents would affect authorization, tool access, workspace boundaries, and memory visibility.

## Summary

Keep open: current main and v2026.6.11 have adjacent Feishu group session scoping, DM-only dynamic agent creation, and explicit thread-bound subagent hooks, but they still do not provide automatic durable Feishu group-sender subagents with isolated workspaces, skills, config, memory, lifecycle, quotas, and authorization.

## What This Changes

Request automatic Feishu group-chat routing that creates or reuses one isolated subagent per sender or role, with per-user skills, config, memory, and admin lifecycle controls.

## Best Possible Solution

Define an opt-in, admin-authorized identity-to-agent lifecycle contract first, including Feishu sender identity, group/topic routing, private/shared memory namespaces, quotas, TTL cleanup, per-agent skill/config inheritance, and security review, then implement Feishu through that approved seam.
