## Summary

Keep open: current main has Feishu group/sender session scoping, DM-only dynamic agent creation, and explicit thread-bound subagent hooks, but it does not implement automatic durable Feishu group-sender subagents with isolated workspaces, skills, config, memory, lifecycle, quotas, and authorization.

## What This Changes

Request automatic Feishu group-chat per-sender subagents with isolated workspaces, skills, config, memory, lifecycle, and admin controls.

## Best Possible Solution

Define an explicit opt-in Feishu group per-sender agent model with approved auth, memory, lifecycle, quota, and threading semantics, reusing current groupSessionScope, DM dynamic-agent, and subagent binding primitives instead of silently spawning agents for every group sender.
