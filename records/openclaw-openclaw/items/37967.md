## Summary

Keep open: current main still has adjacent Feishu group sender/topic session scoping and DM-only dynamic agent creation, but it does not implement automatic persistent group-sender subagents with isolated workspaces, skills, config, memory, lifecycle, quotas, and admin controls. The KinthAI comments are useful production evidence for lifecycle, warm pools, cost tracking, and shared/private memory, which reinforces that this needs maintainer product and security design before implementation.

## What This Changes

The issue requests automatic Feishu group-chat sender-specific subagents with isolated workspace, skills, config, memory, lifecycle management, and admin controls.

## Best Possible Solution

Define a maintainer-approved identity-to-agent binding, lifecycle, quota, and shared/private memory contract first, then implement an optional Feishu group-sender path on top of existing group session, dynamic-agent, and thread-binding seams.

## Reproduction Assessment

Yes, at source level. Current main routes Feishu group sessions by group/topic/sender and creates dynamic agents only for direct Feishu peers, so automatic persistent group-sender agent provisioning is absent.

## Solution Assessment

No, not as a one-off implicit Feishu subagent factory. The safer path is a generic administrator-authorized identity-to-agent binding and lifecycle contract, followed by an optional Feishu implementation that uses the existing group session and conversation-binding seams.
