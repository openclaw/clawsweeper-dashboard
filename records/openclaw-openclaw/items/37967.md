## Summary

Keep open: current main has Feishu group sender/topic session scoping, DM-only dynamic agent creation, and thread-bound subagent delivery, but it does not implement automatic Feishu group per-sender subagents with isolated skills, config, memory, admin controls, lifecycle cleanup, and security policy.

## What This Changes

Request automatic Feishu group-chat per-sender subagents with isolated skills, configuration, memory, and runtime/admin controls.

## Best Possible Solution

Define a Feishu plugin-owned, default-off group-subagent design that reuses existing groupSessionScope, thread-binding, and subagent limits while explicitly covering lifecycle, memory namespaces, tool policy, admin controls, and live Feishu proof.
