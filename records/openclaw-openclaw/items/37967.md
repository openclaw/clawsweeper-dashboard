## Summary

Keep open: current main has adjacent Feishu group sender/topic session scoping, DM-only dynamic agent creation, and explicit thread-bound subagent hooks, but it does not provide automatic persistent Feishu group-sender agents with isolated workspaces, skills, config, memory, lifecycle, quotas, and authorization.

## What This Changes

Request automatic Feishu group-chat per-sender subAgents with isolated skills, configuration, memory, and reply routing.

## Best Possible Solution

Define a maintainer-approved identity-to-agent binding, authorization/quota/lifecycle, and shared/private memory contract first, then implement optional Feishu group-sender provisioning through the existing channel routing and agent-binding seams.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Feishu support automatic group-sender agent provisioning, and what identity, authorization, quota/lifecycle, and memory boundaries should become the public contract?

Rationale: The request creates durable agents, workspaces, configs, skills, memory namespaces, and message-routing authority from group-chat identities, so automation cannot safely choose the security and product contract.

Likely owner: m1heng

Owner confidence: medium

Options:

- **Design Generic Contract First (recommended):** Create a generic admin-authorized identity-to-agent lifecycle and memory contract, then let Feishu implement it as one channel owner surface.
- **Keep Session-Only Routing:** Keep current groupSessionScope and explicit subagent/thread mechanisms, documenting that full per-user orchestration belongs in an external plugin or deployment pattern for now.
- **Reject Automatic Provisioning:** Close this feature if maintainers decide group identities should never create durable OpenClaw agents automatically.

## Reproduction Assessment

Yes. Source inspection shows current Feishu group messages can be scoped by sender/topic and DMs can create dynamic agents, but the group path never calls the dynamic-agent factory and subagent hooks require explicit thread-bound spawn.

## Solution Assessment

No, not as an implicit Feishu-only subagent factory. A generic admin-authorized identity-to-agent lifecycle and memory contract is safer before implementing the Feishu-specific behavior.
