## Summary

Keep open: current main has Feishu sender-scoped group/topic sessions, Feishu subagent thread-binding hooks, and DM-only dynamic agent creation, but it does not implement the requested group-chat per-user subagent lifecycle with isolated skills, config, memory, admin controls, and security policy.

## What This Changes

The issue requests dynamic Feishu group-chat subagents keyed by sender or role, with isolated skills, configuration, memory, routing, lifecycle, and admin controls.

## Best Possible Solution

Keep this as a maintainer-owned Feishu/plugin API design item: prove the group-chat lifecycle and security model in the Feishu plugin where possible, then add only the missing generic SDK/core seams needed for per-user agent/profile isolation.
