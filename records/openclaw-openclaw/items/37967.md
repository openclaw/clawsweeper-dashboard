## Summary

Keep open: current main and v2026.6.11 have adjacent Feishu group session scoping, DM-only dynamic agent creation, and explicit thread-bound subagent hooks, but they do not implement automatic group-sender subagents with isolated workspaces, skills, config, memory, lifecycle, quotas, and authorization.

## What This Changes

Request automatic Feishu group-chat subagents per sender or role, with isolated workspace, skills, config, memory, lifecycle, and group reply routing.

## Best Possible Solution

Define a maintainer-approved identity-to-agent lifecycle, authorization/quota/cleanup model, and shared/private memory contract first, then implement optional Feishu group-sender provisioning through the existing channel routing and agent-binding seams.

## Reproduction Assessment

## Solution Assessment

No, not as an implicit Feishu-only subagent factory; the safer path is a generic admin-authorized identity-to-agent lifecycle and memory contract before implementing Feishu-specific behavior.
