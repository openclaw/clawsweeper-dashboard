## Summary

Keep open: current main has Feishu sender/topic session scoping, DM-only dynamic agent creation, and explicit Feishu subagent conversation binding, but it still does not implement automatic per-sender group subagents with isolated skills, config, memory, lifecycle, and admin policy.

## What This Changes

Request automatic Feishu group-chat routing that creates one isolated subagent per sender or role with separate skills, config, memory, and replies relayed through the main bot.

## Best Possible Solution

Define a maintainer-approved identity-to-agent binding, authorization/quota/lifecycle, and shared/private memory contract first, then implement optional Feishu group-sender provisioning through existing channel routing and agent-binding seams.

## Reproduction Assessment

Yes, source-level: current Feishu group messages can be scoped by sender/topic and DMs can create dynamic agents, but the group path never calls the dynamic-agent factory and subagent hooks require explicit thread-bound spawn.

## Solution Assessment

No, not as an implicit Feishu-only subagent factory; a generic admin-authorized identity-to-agent lifecycle and memory contract is safer before implementing the Feishu-specific behavior.

Status: needs_attention

Summary: The issue is security-sensitive because group sender identities would be allowed to create durable agents, workspaces, tool policies, and memory boundaries.

  - body: Group-chat senders should not implicitly receive durable OpenClaw agents, workspaces, or tools until maintainers define admission, admin approval, quota, and cleanup behavior.
