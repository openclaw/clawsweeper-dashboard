## Summary

Keep open: current main has Feishu group sender/topic session scoping, DM-only dynamic agent creation, and Feishu subagent thread binding, but it still does not implement automatic per-sender group subagents with isolated skills, config, memory, lifecycle, and admin policy. The KinthAI comments add useful prior art for sender-keyed sessions, private/shared memory tiers, TTLs, warm pools, and cost governance, so this should stay open for maintainer design review rather than cleanup closure.

## What This Changes

Request Feishu group chats to dynamically create and route per-sender subagents with isolated skills, configuration, memory, sessions, lifecycle, and orchestrated replies.

## Best Possible Solution

Define an opt-in Feishu-owned group-sender agent mode that composes with existing groupSessionScope, bindings, and subagent APIs, with lifecycle limits, memory visibility, authorization, audit, docs, tests, and live Feishu proof before implementation.
