## Summary

Keep open: current main has Feishu DM dynamic agents and configurable group session scoping, but it does not implement the requested Feishu group per-sender subagent provisioning with isolated skills, memory, config, lifecycle, and admin controls.

## What This Changes

Request Feishu group chats to route each unique sender to an isolated subagent with separate skills, config, memory, lifecycle, and administration.

## Best Possible Solution

Design an opt-in Feishu/channel-session architecture that uses current group session scopes where sufficient, then adds per-sender agent provisioning only with explicit lifecycle limits, memory namespace rules, skill/config ownership, and security/admin controls.
