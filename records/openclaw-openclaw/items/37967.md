## Summary

Keep open: current main has Feishu sender/topic session scopes, DM dynamic agents, and direct/topic subagent binding primitives, but it still does not provide automatic Feishu group per-sender subagent lifecycle with isolated skills, memory, config/admin controls, TTL/quota cleanup, and safe reply routing.

## What This Changes

The issue requests Feishu group-chat routing that creates or reuses per-sender subagents with isolated skills, configuration, session memory, lifecycle controls, and relay behavior.

## Best Possible Solution

Define a Feishu-owned isolation contract for sender/topic routing, shared/private memory namespaces, subagent lifecycle/TTL/quota/cost, skill/config/admin policy, and reply routing, then implement the approved plugin/SDK seam with live Feishu multi-user proof.
