## Summary

Keep open: current main supports adjacent Feishu group session scoping, DM-only dynamic agent creation, and explicit thread-bound subagent hooks, but it still does not provide automatic durable Feishu group-sender subagents with isolated workspaces, skills, config, memory, lifecycle, quotas, and authorization.

## What This Changes

The issue requests automatic Feishu group-chat routing to durable per-sender subagents with isolated skills, config, memory, lifecycle, and admin controls.

## Best Possible Solution

Define an admin-authorized identity-to-agent lifecycle, quota/TTL, shared/private memory, and per-agent skill/config contract first, then implement opt-in Feishu group-sender provisioning through channel routing seams.

Options:

- **Keep session-only routing plus explicit subagents:** Continue using group_sender or group_topic_sender session scoping, static bindings, and explicit thread-bound sessions_spawn until a broader contract is approved.
- **Defer to deployment-specific plugins:** Leave automatic provisioning to external deployments or plugins unless a missing OpenClaw channel/API seam is identified.

## Reproduction Assessment

Yes, at source level: current main can scope Feishu group sessions by group/sender/topic, but dynamic agent creation is gated to DMs and Feishu subagent hooks require explicit thread spawning.

## Solution Assessment

No, not as a direct Feishu-only implicit subagent factory; the safer shape is a generic opt-in lifecycle, authorization, quota, and memory-boundary contract before channel-specific implementation.
