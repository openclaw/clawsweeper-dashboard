## Summary

Keep open: current main and v2026.6.11 provide adjacent Feishu group session scoping, DM-only dynamic agent creation, and explicit thread-bound subagent hooks, but not automatic durable group-sender subagents with isolated workspaces, skills/config, memory, lifecycle, quotas, and authorization.

## What This Changes

The issue requests Feishu group chat routing that creates per-sender subagents with isolated skills, configuration, memory, and lifecycle management.

## Best Possible Solution

Define an admin-authorized identity-to-agent lifecycle, quota/TTL, shared/private memory, and per-agent skill/config contract first, then implement opt-in Feishu group-sender provisioning through channel routing seams.

- **Keep session-only routing plus explicit subagents:** Continue using group_sender or group_topic_sender session scoping, static bindings, and explicit thread-bound sessions_spawn until a broader contract is approved.
- **Defer to deployment-specific plugins:** Leave automatic provisioning to external deployments or plugins unless a missing OpenClaw channel/API seam is identified.

## Solution Assessment

No, not as a Feishu-only implicit subagent factory. The maintainable solution needs a generic opt-in lifecycle, authorization, quota, and memory-boundary contract first.
