## Summary

Keep open: current main and v2026.6.11 still do not expose broad private-network access for arbitrary `web_fetch` URLs, and the remaining work is a security-sensitive public config decision with only stale or unmerged implementation candidates.

## What This Changes

The issue requests an opt-in `tools.web.fetch.allowPrivateNetwork` config key so `web_fetch` can reach private or internal network addresses.

## Best Possible Solution

Define a maintainer-approved, default-off `web_fetch` SSRF policy surface with explicit dangerous naming, metadata/link-local rules, redirect/cache/provider/audit coverage, docs, and focused tests before landing the core config change.
