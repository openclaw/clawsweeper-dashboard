Keep open: current main and v2026.6.11 still lack a broad private-network opt-in for arbitrary `web_fetch` URLs, and the remaining work is a security-sensitive public config/API decision with overlapping unmerged implementation attempts.

## What This Changes

The issue requests a default-off `tools.web.fetch.allowPrivateNetwork` config option so `web_fetch` can reach localhost and private/internal network targets.

## Best Possible Solution

Keep this open until maintainers choose and land a default-off, audited `web_fetch` SSRF policy, preferably nested under `ssrfPolicy` and scoped narrowly with redirect, metadata, cache, audit, docs, and real-run proof.
