## Summary

Keep open: current main and the latest release still do not expose broad private-network access for arbitrary `web_fetch` URLs, and the remaining work is a security-sensitive config/product decision with an open but unmerged candidate PR.

## What This Changes

The issue requests an opt-in `tools.web.fetch.allowPrivateNetwork` config key so `web_fetch` can access localhost or private-network URLs when explicitly enabled.

## Best Possible Solution

Define a maintainer-approved `web_fetch` SSRF policy surface with explicit dangerous naming, hard metadata/link-local behavior, redirect/cache/provider/audit coverage, per-agent authorization semantics, docs, and focused tests before landing the core config change.
