## Summary

Keep open: current main and v2026.6.11 still lack a broad private-network opt-in for arbitrary `web_fetch` URLs, and the remaining work is a security-sensitive config/API decision with an open but non-merge-ready maintainer draft exploring a safer shape.

## What This Changes

The issue requests an opt-in `web_fetch` configuration surface that allows trusted operators to fetch localhost, RFC1918, LAN, and other private/internal network targets.

## Best Possible Solution

Land a maintainer-approved nested `web_fetch` SSRF policy with dangerous naming, per-agent or otherwise scoped trust, audit output, docs, cache separation, and tests for private targets, redirects, metadata/link-local handling, and default strict behavior.
