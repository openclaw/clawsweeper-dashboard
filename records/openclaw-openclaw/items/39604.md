## Summary

Keep open: current main and the latest stable release still lack a broad private-network opt-in for arbitrary `web_fetch` URLs, and the remaining choice is a security-sensitive public config/API decision rather than cleanup-close material.

## What This Changes

The issue requests a default-off `tools.web.fetch.allowPrivateNetwork` configuration option so `web_fetch` can reach private or internal network addresses when explicitly enabled.

## Best Possible Solution

Land a maintainer-approved, default-off web_fetch SSRF policy under the canonical nested policy surface, preferably scoped per agent, with dangerous naming, audit/docs, cache-key coverage, redirect checks, and metadata/link-local tests.
