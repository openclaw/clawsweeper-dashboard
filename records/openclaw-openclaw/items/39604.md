## Summary

Keep open: current main and v2026.6.11 still expose only narrow fake-IP web_fetch SSRF opt-ins, while arbitrary private-network web_fetch access remains a security-sensitive config/product decision with open but non-merged candidate work.

## What This Changes

Requested an opt-in tools.web.fetch.allowPrivateNetwork setting so web_fetch can reach private/internal network addresses when explicitly enabled.

## Best Possible Solution

Define one default-off nested web_fetch SSRF policy that scopes private-network access to trusted agents or host patterns, preserves metadata/link-local protections, partitions cache by policy, checks redirects/provider fallback, and ships docs plus focused tests.
