## Summary

Keep open: current main and v2026.6.11 still keep arbitrary `web_fetch` private-network access blocked, and the remaining work is a security-sensitive config/product decision rather than a cleanup close.

## What This Changes

Request adding a default-off `tools.web.fetch` private-network opt-in so `web_fetch` can reach loopback, LAN, and private/internal addresses when explicitly enabled.

## Best Possible Solution

Define one default-off nested SSRF policy for `web_fetch` that scopes private-network access to trusted agents or hosts, preserves metadata/link-local protections, partitions cache by policy, checks redirects/provider fallback, and ships docs plus focused tests.

Yes at source level, though not as a strict bug reproduction: current main has a strict `tools.web.fetch` schema without broad private-network keys and the runtime only passes narrow fake-IP SSRF flags to the guarded fetch path.

## Solution Assessment

Unclear as originally proposed: a top-level `allowPrivateNetwork` boolean is plausible, but current code and discussion point toward a safer nested, scoped SSRF policy with explicit metadata, redirect, cache, and audit semantics.
