## Summary

Keep open: current main and the latest release still keep arbitrary `web_fetch` private-network access blocked, and the remaining work is a security-sensitive public config decision with open, unmerged implementation paths.

## What This Changes

The issue requests a default-off `tools.web.fetch.allowPrivateNetwork` option so `web_fetch` can access localhost, LAN, and other private/internal network targets when explicitly enabled.

## Best Possible Solution

Define one default-off nested SSRF policy for `web_fetch` that scopes private-network access to trusted agents or hosts, preserves metadata/link-local protections, partitions cache by policy, checks redirects and provider fallback, and ships docs plus focused tests.
