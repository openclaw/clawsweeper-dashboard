## Summary

Keep open: current main and the latest release still lack a broad private-network opt-in for arbitrary `web_fetch` URLs, and the remaining work is a security-sensitive public config/API decision with unmerged candidates.

## What This Changes

Request to add an opt-in `tools.web.fetch.allowPrivateNetwork` or equivalent config so `web_fetch` can reach private/internal network targets when explicitly enabled.

## Best Possible Solution

Define one maintainer-approved nested `tools.web.fetch.ssrfPolicy` contract with dangerous naming, default-off behavior, metadata/link-local policy, redirect/cache/provider/audit coverage, docs, and focused tests before landing core config changes.
