## Summary

Keep open: current main and v2026.6.11 still lack a broad private-network opt-in for arbitrary `web_fetch` URLs, and the remaining work is a security-sensitive public config/API decision rather than cleanup-close material.

## What This Changes

Request to add a default-off `web_fetch` config option that allows private/internal network targets when explicitly enabled by an operator.

## Best Possible Solution

Define one maintainer-approved, default-off `web_fetch` SSRF policy surface with dangerous naming, hard metadata/link-local semantics, redirect/cache/provider/audit coverage, docs, and focused tests before landing the config change.

Options:

- **Approve Nested SSRF Policy (recommended):** Land a narrowly documented `tools.web.fetch.ssrfPolicy` design that allows private-network access only with explicit operator intent plus metadata, redirect, cache, provider, and audit safeguards.
- **Keep Only Narrow Fake-IP Support:** Leave current main as-is and document that arbitrary private-network `web_fetch` remains intentionally unsupported for now.
- **Fold Into Broader Egress Policy:** Route this through the broader web-tool egress firewall design so private access, domain allowlists, and per-agent authorization are decided together.
