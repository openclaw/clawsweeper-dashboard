## Summary

Keep open: current main and the latest release still keep arbitrary `web_fetch` private-network access blocked, while an open protected draft PR overlaps the implementation path and the remaining choice is a security-sensitive product/config decision.

## What This Changes

The issue requests an opt-in `tools.web.fetch.allowPrivateNetwork` configuration key so `web_fetch` can reach localhost and private/internal network addresses.

## Best Possible Solution

Land a maintainer-approved SSRF policy that keeps default-deny behavior, names dangerous private-network opt-ins clearly, scopes exceptions to trusted agents or hosts, preserves metadata/link-local protections, covers redirects/cache/provider fallback, and documents audit/doctor expectations.

Options:

- **Sponsor scoped per-agent SSRF policy (recommended):** Use https://github.com/openclaw/openclaw/pull/67421 or a successor to expose private-network access only under explicit per-agent/config policy with metadata, link-local, redirect, cache, provider-fallback, docs, and audit safeguards.
- **Keep arbitrary web_fetch strict:** Reject broad private-network access for arbitrary `web_fetch` and close this family after documenting supported alternatives such as fake-IP proxy opt-ins, trusted proxy mode, hostname allowlists, or browser/tool-specific controls.
- **Accept a simpler global flag:** Expose a global dangerous flag for trusted deployments, accepting a wider blast radius and requiring strong docs/tests/security-audit coverage before merge.

## Reproduction Assessment

Yes, source-reproducible rather than live-run: current main uses a strict `tools.web.fetch` schema without broad private-network keys and only threads narrow fake-IP SSRF flags into the guarded fetch path. A localhost/RFC1918 `web_fetch` request remains blocked by the shared SSRF guard unless a broader policy is introduced elsewhere.

## Solution Assessment

Unclear as proposed: a global `allowPrivateNetwork` boolean is plausible, but the current evidence points toward a safer scoped policy such as the open per-agent override PR or a host/confirmation-based design. The best fix needs maintainer security direction before implementation details are chosen.
