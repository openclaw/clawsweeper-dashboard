## Summary

Keep open: current main and v2026.6.11 still do not expose broad private-network access for arbitrary `web_fetch` URLs, and the remaining work is a security-sensitive config/product decision with an open but unmerged draft candidate.

## What This Changes

The issue requests an opt-in `tools.web.fetch.allowPrivateNetwork` config key so `web_fetch` can reach private or local network addresses when explicitly enabled.

## Best Possible Solution

Define a maintainer-approved, default-off `web_fetch` SSRF policy surface with explicit dangerous naming, metadata/link-local rules, redirect/cache/provider/audit coverage, docs, and focused tests before landing the core config change.
