Keep open: current main and v2026.6.11 still do not expose broad private-network access for arbitrary `web_fetch` URLs, and the remaining work is a security-sensitive public config/API decision rather than maintainer cleanup.

## What This Changes

The issue requests an opt-in `tools.web.fetch.allowPrivateNetwork` config key so `web_fetch` can reach private/internal network targets when explicitly enabled.

## Best Possible Solution

Define one default-off, nested `web_fetch` SSRF policy that scopes private-network access to trusted agents or hosts and specifies metadata/link-local, redirect, cache, audit, docs, and upgrade behavior before merge.
