## Summary

Keep open: current main and v2026.6.11 still do not expose broad private-network access for arbitrary `web_fetch` URLs, and the remaining work is a security-sensitive config/product decision rather than cleanup-close material.

## What This Changes

The issue requests an opt-in `tools.web.fetch.allowPrivateNetwork` config key so `web_fetch` can access localhost or private network addresses when explicitly enabled.

## Best Possible Solution

Define a maintainer-approved `web_fetch` SSRF policy surface with dangerous naming, hard metadata/link-local handling, redirect/cache/provider/audit coverage, and focused tests before landing the core config change.
