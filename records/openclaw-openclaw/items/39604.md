## Summary

Keep open: current main and v2026.6.11 still do not expose broad private-network access for arbitrary `web_fetch` URLs, and the remaining work is a security-sensitive product/config decision with overlapping but unmerged PRs.

## What This Changes

Request adding a default-off `web_fetch` config option so explicitly trusted agents can fetch private, internal, or loopback network targets.

## Best Possible Solution

Define one maintainer-approved, default-off nested `web_fetch` SSRF policy contract that composes with existing fake-IP flags, keeps credential-metadata handling explicit, partitions cache by effective policy, and ships with docs, audit coverage, tests, and real configured-run proof.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 accept only narrow fake-IP SSRF policy keys for `web_fetch` and still block localhost/private targets through the guarded fetch path. A live localhost fetch is not needed to verify the missing public config contract.

## Solution Assessment

Unclear for final direction: the operator use case is valid, but the exact top-level key is not the best settled shape. The safer solution is a maintainer-approved nested SSRF policy with explicit metadata, redirect, cache, audit, and documentation semantics.
