## Summary

Keep open: current main and v2026.6.11 still do not expose broad private-network access for arbitrary `web_fetch` URLs, and the remaining work is a security-sensitive public config/API decision with open or closed-unmerged implementation candidates.

## What This Changes

Request an opt-in `tools.web.fetch.allowPrivateNetwork` or equivalent config surface so `web_fetch` can reach localhost, LAN, and other private/internal addresses when explicitly enabled.

## Best Possible Solution

Define one maintainer-approved nested `tools.web.fetch.ssrfPolicy` contract with dangerous naming, default-off behavior, hard metadata/link-local policy, redirect/cache/provider/audit coverage, docs, and focused tests before landing core config changes.

- **Keep arbitrary private fetch blocked:** Leave current main limited to narrow fake-IP/proxy opt-ins and document arbitrary private-network `web_fetch` as intentionally unsupported for now.
