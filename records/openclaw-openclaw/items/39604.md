Keep open: current main and v2026.6.11 still lack a broad private-network opt-in for arbitrary `web_fetch` URLs, and the remaining work is a security-sensitive public config/API decision with overlapping but unmerged PR attempts.

## What This Changes

The issue requests a default-off `tools.web.fetch.allowPrivateNetwork` config key so `web_fetch` can reach localhost or private network addresses when explicitly enabled.

## Best Possible Solution

Land a maintainer-approved, default-off nested `web_fetch` SSRF policy, preferably scoped per agent, with dangerous naming, audit warnings, docs, cache/redirect/metadata tests, and real configured-run proof.
