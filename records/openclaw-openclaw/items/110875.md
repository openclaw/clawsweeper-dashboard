## Summary

Keep this PR open, but it is not ready to merge: adding Mattermost to the global provider-read-gate allowlist bypasses the host’s exact-current-conversation restriction for delegated Mattermost reactions as well as reads. The proposed read capability is useful and directly advances the remaining work in https://github.com/openclaw/openclaw/issues/107915, but the authorization boundary must be action-scoped and receive real Mattermost proof before merge.

## What This Changes

The branch adds a default-enabled, plugin-owned Mattermost `message read` action with guarded delegated access, an `actions.messages` configuration toggle, REST client support, tests, and documentation.

## Best Possible Solution

Use an action-scoped provider authorization seam so Mattermost can own delegated `read` policy without relaxing the host gate for reactions or other actions, then document and prove the default/override behavior against a real Mattermost server.
