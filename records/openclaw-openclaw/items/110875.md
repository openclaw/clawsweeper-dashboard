## Summary

Keep this PR open, but it is not merge-ready: its core escape hatch recognizes Mattermost only when the adapter is marked bundled, while Mattermost is documented as a downloadable plugin. That makes the claimed delegated cross-channel path unreachable for the installed plugin and leaves the new default history-read permission boundary uncalibrated.

## What This Changes

Adds guarded Mattermost channel-history reads through the shared message action and CLI, with REST pagination, action configuration, authorization checks, tests, and documentation.

## Best Possible Solution

Route provider-owned read authorization through a plugin/registry capability that works for the installed Mattermost plugin, then land the feature only with an explicit owner decision on default enablement and redacted proof from a real Mattermost server for direct and delegated reads.
