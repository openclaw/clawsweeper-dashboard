## Summary

Keep open: current main still resolves Discord routing before cross-agent active-target selection and still matches configured mention regexes against the full message text. A related open PR only covers the narrower bot-authored native-reply policy, so the broader role, quoted-text, other-agent, and default-owner behavior remains unresolved.

## What This Changes

The issue reports overly permissive Discord mention and route preflight behavior in multi-agent setups, especially for other-agent targets, role mentions, quoted mentions, and bot-authored messages.

## Best Possible Solution

Confirm the Discord active-target contract, then implement target selection inside the Discord plugin before default routing with focused regression coverage for other-agent, role, quoted-mention, and bot-authored cases.

## Reproduction Assessment

Yes, at source level: current main still feeds full message text into mention matching and only checks explicit/reply metadata against the current bot id. I did not run a live Discord replay in this read-only review.

## Solution Assessment

Unclear until maintainers confirm the product contract. The attention-window direction is plausible, but the durable fix needs approved precedence for cross-bot targets, role mentions, quoted text, home-channel defaults, and bot-authored messages.
