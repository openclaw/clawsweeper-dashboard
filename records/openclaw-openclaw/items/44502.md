## Summary

Keep open: current main and v2026.6.11 still scope Discord mention/reply decisions to the current handler bot and full message text, without a configured other-agent target map or attention-window filter. The report remains source-reproducible, but the final Discord multi-agent precedence and role semantics need maintainer confirmation before a repair is queued.

## What This Changes

The issue requests stricter Discord preflight routing so messages aimed at another agent, unrelated roles, quoted/later mentions, and bot-authored mention-only traffic do not wake the current agent.

## Best Possible Solution

Confirm the Discord active-target contract, then implement target selection in the Discord plugin before default routing with focused tests for explicit bot mentions, reply targets, quoted/later mentions, role mentions, and bot-authored loop prevention.

## Reproduction Assessment

Yes, at source level: current main still routes and evaluates mention state before any configured other-agent active-target selection, and regex mention matching uses the provided full base text. I did not run a live Discord multi-bot replay in this read-only review.

## Solution Assessment

Unclear as a final product contract. The local patch direction is plausible, but the best fix should first confirm the Discord precedence and role semantics, then implement the narrowest plugin-owned target-selection path with regression and live transport proof.
