## Summary

Keep open: current main and v2026.6.11 still resolve the Discord route before any cross-agent active-target selection, compare explicit/reply metadata only to the current handler bot id, and run configured mention regexes over the full message text rather than an opening attention window.

## What This Changes

The issue reports Discord preflight mention-gating that can accept or route messages for the wrong agent when other agents, roles, quoted mentions, bot senders, or home-channel delegation are present.

## Best Possible Solution

Confirm the Discord active-target contract, then implement target selection inside the Discord plugin before default routing with focused regression coverage for other-agent, role, quoted-mention, bot-authored, and home-channel default-owner cases.

## Reproduction Assessment

Yes, at source level: current main resolves Discord routing before cross-bot target selection, matches configured mention regexes against the full message text, and compares explicit/reply metadata only to the current handler bot id. I did not run a live Discord replay in this read-only review.

## Solution Assessment

Unclear until maintainers confirm the product contract. The attention-window direction is plausible, but the durable fix needs approved precedence for cross-bot targets, role mentions, quoted text, home-channel defaults, and bot-authored messages.
