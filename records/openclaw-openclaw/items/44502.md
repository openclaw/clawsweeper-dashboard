## Summary

Keep open: current main and v2026.6.11 still resolve Discord routing before any cross-agent active-target selection, and mention detection still uses the full message text/current bot id rather than a scoped attention window or competing-agent decision. The report remains source-reproducible, but the durable fix needs maintainer confirmation for multi-agent precedence, role mentions, quoted text, and bot-authored messages.

## What This Changes

Tighten Discord preflight so wrong-agent, unrelated-role, quoted, or bot-authored messages do not pass mention gating for the current agent.

## Best Possible Solution

Confirm the Discord active-target contract, then implement target selection inside the Discord plugin before default admission with focused regression coverage for other-agent, role, quoted-mention, and bot-authored cases.

## Reproduction Assessment

Yes, at source level: current main still resolves Discord routing before cross-bot target selection, matches configured mention regexes against full message text, and compares explicit/reply metadata only to the current handler bot id. I did not run a live Discord replay in this read-only review.

## Solution Assessment

Unclear until maintainers confirm the product contract. The attention-window direction is plausible, but the durable fix needs approved precedence for cross-bot targets, role mentions, quoted text, home-channel defaults, and bot-authored messages.
