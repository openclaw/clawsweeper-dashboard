## Summary

Keep open: current main still resolves Discord routing before any configured cross-agent active-target decision, compares mention/reply metadata only to the running bot, and lacks scoped attention-window or role-target semantics for the broader cases reported here. Related open issues cover narrower slices, but none supersedes the quoted-text, role, other-agent, and bot-loop scope of this issue.

## What This Changes

The issue requests tighter Discord preflight mention gating so messages are admitted only when the current agent is the active target in multi-agent Discord setups.

## Best Possible Solution

Define the Discord active-target contract, then implement a Discord-owned selector before default admission using native mention/reply metadata plus scoped attention text.
