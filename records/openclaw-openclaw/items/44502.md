## Summary

Keep open: current main and v2026.6.11 still route Discord messages before resolving cross-agent active-target signals, compare mention/reply metadata only to the current handler bot ID, and lack a suppression state for messages that target another configured agent or only contain later/role mention noise.

## What This Changes

The issue requests stricter Discord preflight mention gating so other-agent targets, unrelated role mentions, later quoted mentions, and bot-authored mention-only traffic do not route to the wrong agent.

## Best Possible Solution

Confirm the Discord active-target contract, then implement target selection in the Discord plugin before shared default routing with a configured bot-user-id to account/agent map, focused suppression tests, and separate handling for role-trigger and command-targeting follow-ups.

## Reproduction Assessment

Yes, at source level: current main routes Discord messages before cross-bot target selection, only compares explicit/reply metadata to the current botUserId, and has no other-target suppression state. I did not run a live Discord multi-bot replay in this read-only review.

## Solution Assessment

Unclear until maintainers confirm the product contract. The requested direction is valid, but the best fix should be a Discord-owned active-target selection layer before shared default routing rather than a broad local patch that mixes role-trigger, quoted-text, bot-loop, and command-target semantics.
