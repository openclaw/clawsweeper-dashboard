## Summary

Keep open: the reporter reconfirmed the false error on the latest stable release after a successful explicit Telegram send, and the prior source review found that targetless hook delivery still lacks a resolved target for the verifier to match. The remaining question is the intended delivery-policy rule, not whether the side effect occurred.

## What This Changes

The issue requests that hook delivery verification recognize a successful explicit Telegram `message` tool send, or report the precise target mismatch rather than recording a false failure.

## Best Possible Solution

Define a single hook-delivery rule that treats a successful explicit `message` send with a concrete channel and target as verified when no delivery target was planned, records that target for audit, and retains strict mismatch errors whenever a planned target exists; cover both cases with regression tests.
