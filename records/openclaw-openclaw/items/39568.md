## Summary

Keep open: current main and v2026.6.11 still have the Feishu structured-mentions false-negative path, and the exact fix remains only in a closed same-repository PR plus an open fork PR that has not landed upstream.

## What This Changes

The issue reports that Feishu reply messages can miss bot mention detection and can route replies into the wrong thread when the bot is @-mentioned in a group reply.

## Best Possible Solution

Land or replace a narrow Feishu-plugin fix that detects dropped bot mentions in reply payloads with bot-specific evidence and chooses reply targets after session scope is known.

## Reproduction Assessment

Yes. Source inspection shows a Feishu reply with a nonempty mentions array that omits the bot will return false from checkBotMentioned, and requireMention group admission can then reject the message before dispatch.

## Solution Assessment

Yes, the right owner is the Feishu plugin parser, mention detector, and scope-aware reply routing. The current open fork PR is a candidate path, but upstream should review, rebase, adopt, or replace it before closing this issue.
