- `impact:message-loss`: When Feishu drops the bot from structured mentions, OpenClaw can reject a reply that explicitly addressed the bot before dispatch.

## Summary

Keep open: current main and the latest release still have the Feishu reply-mention false-negative path and still preserve rootId before scope-aware routing, while the exact candidate fix is only an open conflicting cross-repo PR.

## What This Changes

The issue asks Feishu to detect bot @mentions in reply messages when Feishu omits the bot from structured mentions, and to avoid routing explicitly mentioned replies into the wrong thread.

## Best Possible Solution

Review, rebase, repair, or replace the linked Feishu candidate with a narrow fix that uses bot-specific dropped-mention evidence and scope-aware reply routing, then close this issue after that fix merges.

## Reproduction Assessment

Yes, source-reproducible: a Feishu group reply with parent/root metadata, an orphaned text placeholder, and a structured mentions array lacking the bot follows the early-return path and can fail the mention gate. I did not run a live Feishu replay in this read-only review.

## Solution Assessment

No, not exactly as proposed: fixing Feishu mention detection is the right layer, but parse-time rootId clearing is too broad. The safer fix should prove bot-specific dropped-mention evidence and let scope-aware routing choose main-chat versus topic replies.
