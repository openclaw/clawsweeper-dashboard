## Summary

Keep open: current `main` still only schema-checks `gateway.nodes.denyCommands` as strings at config-write time, while the ineffective/unknown-command warning and suggestions live in `openclaw security audit`. The issue remains a valid security-config hardening gap, but the final warning-versus-fail behavior and plugin/custom command handling need maintainer direction.

## What This Changes

The issue asks OpenClaw to warn or fail when `gateway.nodes.denyCommands` contains unrecognized command names during `openclaw config set`.

## Best Possible Solution

Share the security-audit command vocabulary and suggestion logic with the config-write path, warning on likely typos or patterns while preserving a deliberate path for plugin/custom command names unless maintainers choose a stricter contract.

## Reproduction Assessment

Yes from source inspection: `denyCommands` is only accepted as `z.array(z.string())` at schema/config-write time, while the unknown-command and suggestion checks are only in security audit. I did not run the CLI because this review is read-only and tests would create artifacts.

## Solution Assessment

No current solution is implemented on `main`. The best fix is likely a narrow shared validator/warning path, not a static enum in the schema, because plugin and custom node commands can extend the known command vocabulary.
