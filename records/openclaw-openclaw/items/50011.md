## Summary

Keep open: current main and the latest release still accept `gateway.nodes.denyCommands` as a free-form string array at config-write time, while unknown or pattern-like entries are only diagnosed later by the security audit path. The remaining blocker is maintainer/security policy for warning-only versus fail-closed validation, and there are linked open fork candidates plus prior closed target PRs in the cluster.

## What This Changes

The issue requests write-time validation or warning for invalid `gateway.nodes.denyCommands` entries so operators do not believe ineffective denylist entries are blocking node commands.

## Best Possible Solution

Add a maintainer-approved write-time warning that reuses the security audit/runtime command vocabulary and suggestions, while preserving exact custom/plugin command IDs unless maintainers explicitly choose fail-closed behavior.
