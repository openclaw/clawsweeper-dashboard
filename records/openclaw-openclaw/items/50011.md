## Summary

Keep open: current main and v2026.6.11 still accept `gateway.nodes.denyCommands` as arbitrary strings during config writes, while unknown or pattern-like entries are only diagnosed later by the security audit path. The remaining blocker is the maintainer/security policy choice for warning-only versus fail-closed validation with custom or plugin command IDs.

## What This Changes

The issue asks for write-time validation or warning for invalid `gateway.nodes.denyCommands` entries instead of only detecting them later in `openclaw security audit`.

## Best Possible Solution

Add a maintainer-approved write-time warning that reuses the security audit command catalog and suggestions while preserving custom/plugin command IDs unless maintainers explicitly choose fail-closed behavior.
