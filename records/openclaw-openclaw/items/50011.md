## Best Possible Solution

Add a maintainer-approved warning-first validator for direct and ancestor `gateway.nodes` config mutations that reuses the audit/runtime command vocabulary and preserves custom command flexibility.

## Reproduction Assessment

I did not run `openclaw config set` because this review is read-only and must not mutate config files.

## Solution Assessment

Unclear until maintainers choose warning versus failure semantics. A warning-first shared validator is the safest likely fix because plugin/custom node command names may be legitimate even when absent from the built-in vocabulary.
