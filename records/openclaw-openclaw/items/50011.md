## Summary

Keep open: current main still accepts arbitrary `gateway.nodes.denyCommands` strings at config-write time, while runtime exact matching makes typos ineffective and security audit only reports them later. No same-repository PR has merged the write-time warning/failure behavior, and the remaining decision is warning-first validation versus stricter failure semantics for plugin/custom commands.

## What This Changes

Warn or fail during `openclaw config set` when `gateway.nodes.denyCommands` contains unknown or pattern-like command names instead of only surfacing that problem in `security audit`.

## Best Possible Solution

Add a maintainer-approved warning-first config mutation validator for direct and ancestor `gateway.nodes` writes that reuses the audit/runtime command vocabulary, preserves custom command flexibility, and includes focused CLI plus audit regression tests.

## Reproduction Assessment

Yes, source-reproducible: current schema accepts arbitrary `gateway.nodes.denyCommands` strings, the config write path persists them without a denyCommands warning, runtime matching is exact, and security audit flags the problem only later. I did not run the CLI because this review is read-only and config-write commands can mutate files.

## Solution Assessment

Unclear until maintainers choose warning versus failure semantics. A warning-first validator in the shared config mutation path looks like the safest solution because plugin/custom commands may be valid even when absent from the built-in vocabulary.
