## Summary

Keep open: current main and v2026.6.11 still accept `gateway.nodes.denyCommands` as arbitrary strings at config-write time, while unknown or pattern-like entries are only diagnosed later by the security audit path. The remaining blocker is maintainer/security policy for warning-only versus fail-closed validation, especially for custom or plugin command IDs.

## What This Changes

The issue asks for config-write-time validation or warning when `gateway.nodes.denyCommands` contains unknown command names.

## Best Possible Solution

Add a maintainer-approved write-time warning that reuses the security audit command catalog and suggestions while preserving custom/plugin command IDs unless maintainers explicitly choose fail-closed behavior.
