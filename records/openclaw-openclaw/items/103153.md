## Summary

Keep this PR open for maintainer merge judgment. Current main still sends full model-visible message bodies into compaction planning workers, and the patch appears correct and well-proven for summary-oriented operations with no blocking findings; however, it intentionally leaves history-prune worker payloads unbounded and does not include the seconds/RSS benchmark requested for agents performance changes.

## What This Changes

Bounds summary-oriented compaction planning worker payloads by sampling oversized text, removing image bytes, preserving conservative token estimates, and remapping selected indexes to exact sanitized originals.

## Best Possible Solution

Land the projection-and-index design if the agents-runtime owner accepts it as a scoped mitigation, then handle history pruning through a separate repair-aware compact result contract that bounds worker input without ever using projected content as persisted summary input.
