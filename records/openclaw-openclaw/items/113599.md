## Summary

Keep this issue open for maintainer review. Current documentation describes a persistent per-agent `models.json` catalog whose nonempty API key wins during the merge with configuration, so stale credentials can plausibly override a later `openclaw.json` edit; however, the report has not yet established whether the affected value is actually in `auth_profile_store`, the model catalog, or both.

## What This Changes

Ensure that rotating a provider API key in `openclaw.json` does not leave the credential used by the gateway stale after restart.

## System Context

Provider configuration feeds the gateway’s model-provider resolution, which merges configured provider entries with a persistent per-agent model catalog before requests reach the selected provider. Authentication profiles are a separate persisted credential surface, so the fix must identify the authoritative store without overwriting deliberate per-agent overrides.

## Architecture Diagram

flowchart LR
  A[openclaw.json provider config] --> B[Gateway startup]
  C[Per-agent models catalog] --> D[Provider configuration merge]
  E[Authentication profile store] --> D
  D --> F[Resolved provider credential]
  F --> G[Provider API request]

## Best Possible Solution

First reproduce the credential selected after a restart in a clean profile and distinguish `models.json` from `auth_profile_store`; then adopt one explicit, tested ownership rule that refreshes only configuration-derived credentials while preserving intentional per-agent overrides.
