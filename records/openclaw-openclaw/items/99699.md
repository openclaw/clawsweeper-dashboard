## Summary

Keep open: this is maintainer-authored, protected-label architecture work, and current main has only the prerequisite shared CLI/adapter pieces rather than the requested unified live-runtime factory host for the existing live QA commands.

## What This Changes

The issue requests routing existing Telegram, Slack, WhatsApp, and Matrix live QA commands through one shared factory-backed runtime host without changing channel behavior.

## Best Possible Solution

A maintainer-approved QA SDK live-runtime factory/host should own command routing and lifecycle while preserving each channel plugin’s current runtime behavior and artifacts.

## Reproduction Assessment

Yes from source, although this is not a bug reproduction. Current main shows shared option parsing and a shared gateway helper, but the named live commands still invoke their own channel runtime paths and Matrix remains routed through qaRunners.

## Solution Assessment

Unclear as a final design until maintainers confirm the SDK boundary. The proposed shared host matches the QA docs rule to put cross-runner behavior in qa-lab, but the exact factory contract and migration proof need human architecture review.
