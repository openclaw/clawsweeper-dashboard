## Summary

Keep open. Current main and the latest release still model `tools.sessions.visibility` as one string-valued scope shared by send, history, list, and status, so the requested per-capability authorization object remains unimplemented and needs maintainer product/security review.

## What This Changes

Request to replace the single `tools.sessions.visibility` enum with backward-compatible per-capability session-tool authorization knobs for send, history, list, and metadata.

## Best Possible Solution

Define one backward-compatible, maintainer-approved session authorization model that keeps current string shorthands, adds only the approved per-capability controls, preserves sandbox/A2A restrictions, and updates schema, docs, generated config help, and isolation tests together.

## Reproduction Assessment

Yes, for source verification rather than runtime bug reproduction. Current main schema, types, docs, and shared guards still expose only `self | tree | agent | all`, so the requested object-shaped configuration cannot be expressed.

## Solution Assessment

Unclear until maintainers choose the durable permission model. The proposed object form is plausible, but it should be reconciled with A2A policy, per-agent scoping, allowlists, sandbox clamps, and status/list/history semantics before implementation.
