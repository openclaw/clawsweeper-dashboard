## Summary

Keep open. Current main and v2026.6.11 still use one string-valued `tools.sessions.visibility` scope across list, history, send, and status, while the requested per-capability authorization model remains unimplemented and security-sensitive.

## What This Changes

Request a backward-compatible object form for `tools.sessions.visibility` that can grant session send, history, list, and metadata access separately.

## Best Possible Solution

Define one maintainer-approved, backward-compatible session-tool authorization model that preserves existing string shorthands, adds only approved capability controls, keeps sandbox and A2A gates intact, and updates schema, docs, and tests together.
