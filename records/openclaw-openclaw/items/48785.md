## Summary

Keep open. Current main and the latest release still use one string-valued session visibility scope across list, history, send, and status, so the requested per-capability authorization model remains unimplemented and still needs maintainer product/security review.

## What This Changes

Request adding a backward-compatible object form for `tools.sessions.visibility` so send, history, list, and metadata visibility can be controlled separately.

## Best Possible Solution

Define one backward-compatible session-tool capability model that keeps current string shorthands, adds only maintainer-approved per-capability controls, and updates schema, docs, generated help, and isolation tests together.

## Reproduction Assessment

Yes for source-level verification, not as a bug reproduction. Current main and `v2026.6.11` still expose only the single string visibility setting and shared guard, so the requested configuration cannot be expressed today.

## Solution Assessment

Unclear until maintainers choose the durable permission model. The proposed object form is plausible, but it should be reconciled with per-agent scoping, target allowlists, sandbox visibility, and A2A-send-specific proposals before implementation.
