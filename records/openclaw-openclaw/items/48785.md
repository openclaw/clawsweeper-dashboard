## Summary

Keep open. Current main and the latest release still implement `tools.sessions.visibility` as one string-valued scope shared by list, history, send, and status, so the requested per-capability authorization model remains missing and needs maintainer security/product direction.

## What This Changes

The issue requests replacing the single `tools.sessions.visibility` scope enum with per-capability controls for send, history, list, and metadata.

## Best Possible Solution

Define one backward-compatible session-tool authorization model that preserves string shorthands, adds only approved capability controls, keeps sandbox and A2A gates intact, and updates schema, docs, and focused tests together.
