## Summary

Keep open. Current main and the latest release still expose `tools.sessions.visibility` as one string-valued scope shared by list, history, send, and status, so the requested per-capability authorization model remains unimplemented and needs maintainer product/security direction rather than cleanup closure.

## What This Changes

Request to replace the single `tools.sessions.visibility` setting with per-capability controls so cross-agent sends can be allowed without granting transcript/list/metadata access.

## Best Possible Solution

Define one maintainer-approved session-tool authorization model that preserves the existing string shorthands, adds only the accepted granular capability controls, keeps sandbox and A2A policy isolation intact, and updates schema, docs, generated help, and tests together.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction of the gap: all session actions still share one `SessionToolsVisibility` decision path, so no current config can allow cross-agent send while denying cross-agent history/list/status.

## Solution Assessment

Unclear. Per-capability visibility is a plausible security model, but it changes public authorization config and overlaps per-agent A2A, allowlist, and send-only proposals that maintainers need to reconcile first.
