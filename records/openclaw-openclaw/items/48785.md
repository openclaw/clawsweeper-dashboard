## Summary

Keep open. Current main and the latest release still expose `tools.sessions.visibility` as one string-valued scope shared by list, history, send, and status, so the requested per-capability authorization model remains unimplemented and needs maintainer product/security direction rather than cleanup closure.

## What This Changes

The issue requests replacing the single `tools.sessions.visibility` scope with per-capability controls for send, history, list, and metadata access.

## Best Possible Solution

Define one maintainer-approved session-tool authorization model that preserves existing string shorthands, adds only the accepted granular capability controls, keeps sandbox and A2A policy isolation intact, and updates schema, docs, generated help, and tests together.
