## Summary

Keep open. Current main and the latest release still expose `tools.sessions.visibility` as one string-valued scope shared by list, history, send, and status, while the requested per-capability object form remains unimplemented and needs maintainer product/security review.

## What This Changes

Request split `tools.sessions.visibility` into separate capability controls so cross-agent sends can be allowed without granting transcript history, list, or metadata access.

## Best Possible Solution

Define one backward-compatible session-tool authorization model that keeps current string shorthands, adds only approved per-capability controls, preserves sandbox and A2A gates, and updates schema, docs, help, and isolation tests together.

## Reproduction Assessment

Yes for source verification, not as a bug reproduction. Current main can be checked in schema, docs, and the shared guard, and all still lack the proposed per-capability object form.

## Solution Assessment

Unclear until maintainers choose the durable permission model. The object form is plausible, but it should be reconciled with per-agent scoping, allowlists, sandbox visibility, and A2A-send-specific proposals before implementation.
