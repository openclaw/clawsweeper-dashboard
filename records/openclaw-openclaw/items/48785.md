## Summary

Keep open. Current main and the latest release still use one string-valued session visibility scope across list, history, send, and status, so the requested per-capability authorization model remains unimplemented and needs maintainer product/security review.

## What This Changes

The issue requests replacing the single `tools.sessions.visibility` scope with per-capability session access controls for send, history, list, and metadata.

## Best Possible Solution

Define one backward-compatible session-tool capability model that preserves current string shorthands, adds maintainer-approved per-capability controls, keeps sandbox and A2A restrictions coherent, and updates schema, docs, generated help, and isolation tests together.

## Reproduction Assessment

Yes for source verification, but not as a bug reproduction. Current main still exposes only the single string visibility setting and shared guard, so the requested configuration cannot be expressed today.

## Solution Assessment

Unclear until maintainers choose the durable permission model. The proposed object form is plausible, but per-agent scoping, target allowlists, sandbox visibility, and an A2A-send-specific exception may need to be consolidated with it.
