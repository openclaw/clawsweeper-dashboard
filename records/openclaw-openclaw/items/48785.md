## Summary

Keep open. Current main and latest release still use one string-valued session visibility scope shared by list, history, send, and status, so the requested per-capability privacy model remains unimplemented and needs maintainer security/product direction.

## What This Changes

Request to replace or extend `tools.sessions.visibility` with per-capability controls so cross-agent sends can be allowed without granting transcript, list, or metadata access.

## Best Possible Solution

Define one maintainer-approved, backward-compatible session-tool authorization model that preserves existing string shorthands, adds only approved capability controls, keeps sandbox and A2A gates intact, and updates schema, docs, and tests together.
