## Summary

Keep open. Current main and the latest release still use one string-valued `tools.sessions.visibility` scope for list, history, send, and status, so the requested per-capability authorization model remains unimplemented and needs maintainer product/security review.

## What This Changes

Request to replace the single `tools.sessions.visibility` enum with per-capability controls for send, history, list, and metadata access.

## Best Possible Solution

Define one maintainer-approved session authorization model, then implement it consistently across schema, shared visibility checks, session tool callers, docs, generated help, and focused isolation tests without weakening current defaults.

## Reproduction Assessment

Yes, for source-level verification rather than a bug reproduction. Current main and `v2026.6.11` both accept only the single string visibility enum and deny cross-agent actions before any per-capability decision can exist.

## Solution Assessment

Unclear. Per-capability visibility is a plausible clean shape, but maintainers should reconcile it with the related per-agent, allowlist, sandbox, and A2A-send proposals before choosing the permanent public config contract.
