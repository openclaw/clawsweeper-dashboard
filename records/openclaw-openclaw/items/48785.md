## Summary

Keep open. Current main and the latest release still use one string-valued `tools.sessions.visibility` scope for list, history, send, and status, so the requested per-capability authorization model remains unimplemented and needs maintainer product/security direction.

## What This Changes

Request to replace the single session visibility enum with per-capability controls so cross-agent send can be allowed without also granting transcript read or broad listing access.

## Best Possible Solution

Define one maintainer-approved session-tool authorization model that preserves existing string shorthands, adds only the accepted granular controls, keeps sandbox and A2A isolation intact, and updates schema, docs, generated help, and tests together.
