## Summary

Keep open. Current main and the latest release still expose one shared `tools.sessions.visibility` scope for list, history, send, and status, so the requested per-capability authorization model remains unimplemented and needs maintainer product/security direction rather than cleanup closure.

## What This Changes

The issue requests replacing the single `tools.sessions.visibility` string scope with per-capability session visibility controls for send, history, list, and metadata.

## Best Possible Solution

Define one maintainer-approved session-tool authorization model that preserves the existing string shorthands, adds only the accepted granular capability controls, keeps sandbox and A2A policy isolation intact, and updates schema, docs, generated help, and tests together.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction of the gap: all session actions still share one `SessionToolsVisibility` decision path, so no current config can allow cross-agent send while denying cross-agent history.

## Solution Assessment

Unclear. Per-capability visibility is a plausible security model, but it changes public authorization config and overlaps per-agent A2A allowlist work that maintainers need to reconcile first.
