## Summary

Keep open. Current main and the latest release still use one string-valued `tools.sessions.visibility` scope across send, history, list, and status, so the requested per-capability authorization model remains unimplemented and needs maintainer product/security review.

## What This Changes

The issue requests replacing the single `tools.sessions.visibility` string enum with additive per-capability controls for send, history, list, and metadata access.

## Best Possible Solution

Define one backward-compatible, maintainer-approved session authorization model that preserves current string shorthands, adds only approved per-capability controls, and updates schema, docs, generated help, and isolation tests together.

## Reproduction Assessment

Yes for source verification, but not as a bug reproduction. Current main and `v2026.6.11` still expose only the single string visibility setting and shared guard, so the requested configuration cannot be expressed today.

## Solution Assessment

Unclear until maintainers choose the durable permission model. The proposed object form is plausible, but per-agent scoping, target allowlists, sandbox visibility, and an A2A-send-specific exception should be reconciled with it.
