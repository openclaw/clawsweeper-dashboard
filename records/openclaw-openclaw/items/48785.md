## Summary

Keep open. Current main and the latest release still expose `tools.sessions.visibility` as one string-valued scope shared by list, history, send, and status, so the requested per-capability authorization model is not implemented and needs maintainer product/security review.

## What This Changes

Requests replacing the single string-valued `tools.sessions.visibility` scope with additive per-capability controls for send, history, list, and metadata access.

## Best Possible Solution

Adopt one maintainer-approved, backward-compatible session authorization model that preserves current string shorthands, separates write/read/list/status access only where intended, and updates schema, docs, and tests together.

## Reproduction Assessment

Yes for source verification, not as a bug reproduction. Current main exposes only the string union and shared guard, so the requested object-shaped per-capability config cannot be expressed today.

## Solution Assessment

Unclear until maintainers choose the durable permission model. The proposed object form is plausible, but it should be reconciled with the adjacent send-only, per-agent, allowlist, and sandbox visibility proposals before implementation.
