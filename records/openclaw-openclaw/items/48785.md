## Summary

Keep open. Current main and the latest release still use one string-valued `tools.sessions.visibility` scope shared by list, history, send, and status, so the requested per-capability authorization model remains missing and needs maintainer security/product direction.

## What This Changes

Request a backward-compatible object form for `tools.sessions.visibility` so send, history, list, and metadata access can be controlled independently.

## Best Possible Solution

Define one backward-compatible session-tool authorization model that preserves string shorthands, adds only approved capability controls, keeps sandbox and A2A gates intact, and updates schema, docs, generated help, and focused tests together.
