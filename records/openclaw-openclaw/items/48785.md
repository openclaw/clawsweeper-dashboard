## Summary

Keep open. Current main and v2026.6.11 still have one string-valued `tools.sessions.visibility` gate shared by list, history, send, and status, so the requested per-capability privacy model remains unimplemented and needs maintainer security/product direction.

## What This Changes

Request to replace or augment the single `tools.sessions.visibility` enum with per-capability controls for send, history, list, and metadata.

## Best Possible Solution

Define one maintainer-approved, backward-compatible session-tool authorization model that preserves existing string shorthands, adds only approved capability controls, keeps sandbox and A2A gates intact, and updates schema, docs, generated help, and focused tests together.
