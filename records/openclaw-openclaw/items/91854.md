## Summary

Keep open: current main and the latest release still route memory-core Dream Diary narrative runs through the generic plugin subagent path without a no-tools or restricted-tools control, so the reported `apply_patch` exposure remains a valid maintainer follow-up.

## What This Changes

The issue asks OpenClaw to stop giving memory-core Dream Diary narrative/REM subagents mutating tools such as `apply_patch` when those runs only need to produce prose.

## Best Possible Solution

Add a maintainer-approved plugin subagent no-tools or explicit allowlist contract, then make memory-core Dream Diary narrative runs use it while keeping diary file writes in the plugin-owned writer path and adding focused regression coverage.
