## Summary

Keep open: current main still gives memory-core Dream Diary narrative runs no typed way to request a prose-only or no-tools subagent profile, so the reported `apply_patch` exposure remains a valid security-sensitive cleanup item.

## What This Changes

The issue reports that memory-core Dream Diary narrative subagents can receive `apply_patch` and occasionally try to use it for prose output, causing recurring log noise with fallback diary writes.

## Best Possible Solution

Add a typed plugin subagent tool restriction, such as a no-tools or explicit allowlist path, carry it through gateway agent dispatch, and use it for memory-core Dream Diary narrative runs; prompt tightening can be supplemental.
