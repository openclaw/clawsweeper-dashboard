## Summary

Keep open: current main and the latest release still route Feishu markdown-table replies through interactive-card sends without a table-limit fallback, and https://github.com/openclaw/openclaw/pull/86901 is the open implementation candidate that has not landed.

## What This Changes

Feishu should avoid silently dropping replies with too many markdown tables by falling back to post/plain text or otherwise rendering the tables safely.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/86901 with a narrow Feishu plugin fallback that keeps cards for safe content and uses the existing post/plain-text path when markdown tables exceed Feishu's card limit.

## Solution Assessment

Yes for the central bug. A narrow fallback to the existing Feishu post/plain-text path is the maintainable fix; image rendering would add unnecessary media and rendering surface for this delivery failure.
