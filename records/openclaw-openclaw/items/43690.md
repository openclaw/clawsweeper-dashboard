## Summary

Keep open: current main and v2026.6.11 still send Feishu Markdown-table replies through interactive-card paths without a table-count guard, and the same remaining work is already owned by https://github.com/openclaw/openclaw/pull/86901.

## What This Changes

Feishu interactive-card replies with too many Markdown tables should fall back to a deliverable text/post path instead of dropping the reply.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/86901 with a narrow table-count guard on the static card decisions, falling back to the existing post/plain path while leaving unproven CardKit streaming behavior separately tracked.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Source inspection shows `renderMode: auto` or `card` still routes Markdown-table replies into Feishu card sends, and Feishu documents a five-table card cap; I did not perform a live Feishu send in this read-only review.

## Solution Assessment

Yes for the central bug. A narrow table-count preflight plus fallback to the existing post/plain sender is more maintainable than rendering tables as images, which would add a heavier rendering subsystem.
