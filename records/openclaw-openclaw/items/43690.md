## What This Changes

The issue asks Feishu to avoid dropping replies when markdown-table content exceeds the interactive-card table limit by falling back to text/post mode or otherwise rendering tables safely.

## Best Possible Solution

Land or replace the narrow Feishu static-card table-limit fallback against current main, with focused reply-dispatcher and outbound coverage; keep CardKit streaming separately tracked unless the same limit is proven there.
