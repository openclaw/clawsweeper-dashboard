## Summary

Keep open: current main and v2026.6.11 still route Feishu markdown-table replies through interactive-card paths without a five-table guard or fallback, and the remaining fix is already represented by an open but conflicting candidate PR.

## What This Changes

The issue requests that Feishu avoid silently dropping replies when interactive cards exceed the upstream table-count limit, preferably by falling back to a text/post path or otherwise avoiding over-limit card tables.

## Best Possible Solution

Rebase and land the open Feishu static-card fallback candidate, or replace it with an equivalent current-main patch that adds focused five-table and six-table routing coverage without changing unproven streaming-card behavior.

## Solution Assessment

Yes, for the static-card failure: preflighting oversized markdown-table content into the existing post/text sender is the narrowest maintainable fix. Rendering tables as images is a larger feature and should not block the message-loss fallback.
