Keep open: current main and v2026.6.11 still route Feishu markdown-table replies through interactive-card paths without a five-table guard or fallback, and the remaining fix is already owned by an open but conflicting candidate PR.

## What This Changes

The issue requests that Feishu avoid dropping replies when markdown-table card rendering hits the platform table-count limit, preferably by falling back to text/post mode or otherwise rendering tables safely.

## Best Possible Solution

Land or replace the active Feishu plugin fix with a shared table-count preflight and post/text fallback for over-limit replies, plus five-table and six-table regression coverage and real Feishu proof.
