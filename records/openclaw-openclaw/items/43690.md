## Summary

Keep open: current main and the latest release still route Feishu table-containing replies into interactive-card sends without a table-count guard or fallback, while https://github.com/openclaw/openclaw/pull/86901 remains the active but conflicting fix candidate.

## What This Changes

The issue requests Feishu reply delivery to avoid the card table-count failure by falling back to plain/post text or another safe rendering when Markdown tables exceed the platform limit.

## Best Possible Solution

Land or replace the open Feishu fix with a narrow table-count guard applied to reply-dispatcher and outbound static card decisions, preserving card mode for supported content and falling back to post/plain text for oversized table replies.

## Solution Assessment
