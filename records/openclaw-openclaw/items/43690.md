## Summary

Keep open: current main and v2026.6.11 still route Feishu markdown-table replies through interactive-card paths without a five-table guard or fallback, and the active candidate fix remains open but dirty.

## What This Changes

The issue asks Feishu delivery to avoid silently dropping replies when markdown-table cards exceed Feishu's card table limit, preferably by falling back to post/raw text or otherwise rendering tables safely.

## Best Possible Solution

Land or replace the active Feishu plugin fix with a rebased table-count preflight and post/text fallback for over-limit static card replies, plus five-table and six-table regression coverage and explicit streaming scope proof.
