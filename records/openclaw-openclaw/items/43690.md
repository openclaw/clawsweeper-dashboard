## Summary

Keep open: current origin/main and v2026.6.11 still route Feishu table-heavy replies through interactive-card sends without a table-count guard or table-limit fallback, and the active fix candidate remains open and dirty rather than merged.

## What This Changes

Feishu should avoid dropping table-heavy replies when interactive card creation hits the platform table limit by falling back to text/post mode or otherwise rendering tables safely.

## Best Possible Solution

Land or replace the narrow Feishu static-card table-limit fallback against current main with focused outbound and reply-dispatcher tests, and track CardKit streaming separately unless the same limit is proven there.

## Solution Assessment
