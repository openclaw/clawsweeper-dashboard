## What This Changes

The issue asks Feishu delivery to avoid silent message loss when markdown-table-heavy replies exceed the interactive-card table limit, by falling back to text/post mode or otherwise avoiding over-limit cards.

## Best Possible Solution

Land or replace the active Feishu plugin fix with a narrow static-card guard/fallback that keeps card mode for valid content and delivers oversized markdown-table replies through the existing post/text path with reply-dispatcher and outbound regression coverage.
