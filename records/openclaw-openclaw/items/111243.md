## Summary

The Matrix cursor guard on current main still accepts decoded lookalikes of OpenClaw’s synthetic thread-start marker, so this PR remains necessary. The proposed round-trip checks are narrowly scoped, preserve opaque Matrix tokens, and have focused production-function proof; it is ready for ordinary maintainer review once the current merge-head checks finish.

## What This Changes

This PR makes Matrix threaded reads treat a cursor as OpenClaw’s internal first-page marker only when its base64url payload and JSON envelope exactly match the canonical cursor OpenClaw emits.

## System Context

Matrix threaded-message reads receive a pagination cursor and decide whether it is OpenClaw’s synthetic “start relations” marker or an opaque Matrix homeserver token. That decision controls whether the Matrix SDK starts a thread-relation read from the beginning or receives the caller’s token unchanged.

## Best Possible Solution

Merge the focused canonical-cursor validation after the current merge head is refreshed, retaining Matrix pagination tokens as opaque values except for the one exact marker OpenClaw creates.
