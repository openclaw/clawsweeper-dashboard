## Summary

Keep open. The reported diagnostic bug is valid, but this implementation derives a semantic blocked state from free-form error text, so ordinary commands that execute and return messages such as `Permission denied` would be mislabeled as pre-execution blocks; it also lacks after-fix real behavior proof. Likely related people: Swader (high confidence), vincentkoc (high confidence), and RenzoMXD (medium confidence) based on merged history around tool-error warning policy and structured error summaries.

## What This Changes

The PR makes exec/bash warnings say `blocked` when the error contains one of seven denial-related substrings, adds three payload tests, and carries unrelated usage-meter tests from earlier branch commits.

## Best Possible Solution

Propagate a closed `blocked`/`declined` outcome from the exec result into `ToolErrorSummary`, format the verb from that code while retaining `failed` for commands that actually ran, add collision coverage for runtime permission failures, and remove the unrelated usage-meter changes.
