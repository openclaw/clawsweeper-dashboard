## Summary

Keep open. Current main still has reasoning visibility controls, thinking-effort controls, provider replay sanitizers, and plugin hook workarounds, but it does not define a core mode that runs reasoning while excluding thinking blocks from durable session transcripts and transcript-facing APIs.

## What This Changes

Request to add a silent reasoning mode that keeps model reasoning enabled while preventing thinking blocks from being persisted in session transcripts.

## Best Possible Solution

Define a core transcript-persistence policy separate from model thinking effort and reasoning visibility, with explicit semantics for storage, provider replay state, transcript APIs, compaction, memory indexing, UI/config, plugin hooks, and docs.

- **Defer beyond replay hardening:** Keep current provider replay sanitizers and close or pause this feature until maintainers decide silent durable transcripts are product scope.

## Reproduction Assessment

Yes, source-level. Current main has only thinking effort and reasoning visibility controls, while the transcript append path stores the assistant message it receives and session/ACP readers can still expose stored thinking blocks.

## Solution Assessment

Unclear pending maintainer API choice. Decoupling reasoning production from durable transcript persistence is the right boundary, but stripping at one write or read site would be too narrow without provider replay and transcript-consumer semantics.
