## Summary

Keep open. Current main still has thinking effort controls, reasoning visibility controls, provider replay sanitizers, and a plugin hook workaround, but it does not provide a core mode that lets reasoning run while excluding thinking blocks from durable session transcripts and transcript-facing APIs.

## What This Changes

Request a silent reasoning mode that preserves model reasoning quality while preventing thinking blocks from being stored in session transcripts or consumed by memory/context systems.

## Best Possible Solution

Define a single core reasoning persistence contract that separates thinking effort, user/channel visibility, durable transcript storage, transcript APIs, memory/compaction inputs, plugin hooks, and provider-private replay state.

- **Keep replay-only pruning:** Limit token and signature handling to provider/context replay views such as https://github.com/openclaw/openclaw/issues/98298 while leaving durable transcripts complete.
- **Rely on plugin filtering:** Treat before_message_write or memory-plugin filtering as the supported workaround, accepting that core transcript APIs keep current behavior.

## Reproduction Assessment

Yes, at source level. Current main has thinking effort and reasoning visibility controls, but no hidden persistence mode; the transcript append/read and ACP replay paths still preserve and expose stored assistant thinking blocks.

## Solution Assessment

Unclear until maintainers choose the contract. Decoupling reasoning production from durable transcript persistence is the right boundary, but implementing it at only one write/read site would be too narrow without provider replay and transcript-consumer semantics.
