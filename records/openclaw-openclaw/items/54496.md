## Summary

Keep open. Current main and the latest release still provide thinking-effort and reasoning-visibility controls, plus replay and memory sanitizers, but they do not provide the requested silent-reasoning persistence mode that lets reasoning run while excluding thinking blocks from durable session transcripts and transcript-facing APIs.

## What This Changes

Request to add a silent reasoning mode that decouples model thinking production from transcript persistence so thinking blocks are not stored in session history.

## Best Possible Solution

Define one core transcript-persistence policy separate from thinking effort and reasoning visibility, with explicit storage, provider-replay, session API, ACP, compaction, memory, UI/config, and docs semantics.

## Reproduction Assessment

Yes, source-level: current main exposes thinking effort and reasoning visibility, while the assistant transcript append and sessions.get/ACP paths still preserve stored thinking blocks. I did not run a live provider session in this read-only review.

## Solution Assessment

Unclear until maintainers choose the API. Decoupling reasoning production from durable persistence is the right boundary, but a one-site strip would be too narrow without provider replay and transcript-consumer semantics.
