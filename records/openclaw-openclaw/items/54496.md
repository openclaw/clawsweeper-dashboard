## Summary

Keep open. Current main still has thinking-effort controls, reasoning-visibility controls, replay sanitizers, and transcript/memory cleanup helpers, but it does not expose a schema-backed silent-reasoning mode that runs reasoning while excluding thinking blocks from durable session transcripts and transcript APIs.

## What This Changes

The issue requests a silent reasoning mode that keeps model reasoning enabled while excluding thinking blocks from persisted session transcripts and transcript consumers.

## Best Possible Solution

Define a core transcript-persistence policy separate from model thinking effort and user/channel reasoning visibility, including storage, replay, transcript APIs, compaction, memory indexing, UI/config, and docs semantics.

## Reproduction Assessment

Yes, source-level. Current main exposes thinking effort and reasoning visibility, while the assistant transcript append path and sessions.get/ACP transcript consumers still allow stored thinking blocks to persist and be replayed or exposed.

## Solution Assessment

Unclear pending maintainer API choice. Decoupling reasoning production from durable persistence is the right boundary, but a one-site strip would be too narrow without provider replay and transcript-consumer semantics.
