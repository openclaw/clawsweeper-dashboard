## Summary

Keep open: current main and the latest release still preserve fenced `MEDIA:` lines as visible text without a warning signal, and the open linked runtime PR is the active candidate fix but still needs maintainer review.

## What This Changes

Requests that fenced-code `MEDIA:` directives stop failing silently, either by extracting them, warning, or documenting the standalone-line requirement.

## Best Possible Solution

Preserve the no-extract fenced-example contract, add a delivery-boundary diagnostic warning through every path that can show fenced `MEDIA:` text, and keep the docs note for standalone legacy `MEDIA:` lines aligned.

## Maintainer Decision

Question: Should OpenClaw keep treating fenced `MEDIA:` lines as code examples and add warn-only diagnostics, or change the parser to extract those lines as media?

Rationale: Both behaviors are plausible, but they trade off safe code examples against recovering common model output mistakes; current review discussion favors a delivery-boundary warning but maintainer intent is still required before merging the linked PR.

Likely owner: vincentkoc

Owner confidence: high

Options:

- **Warn Only At Delivery Boundary (recommended):** Preserve current fenced-code semantics and emit one warning when a user-visible delivery path would otherwise show a skipped fenced `MEDIA:` line.
- **Extract From Fences:** Treat standalone fenced `MEDIA:` lines as intended attachments, accepting the risk that documentation or code examples can become media sends.
- **Docs Only:** Leave runtime behavior unchanged and document that legacy `MEDIA:` lines must be standalone plain text.

## Solution Assessment

Unclear until maintainers choose the parser contract. The safest current direction appears to be warn-only at the outbound delivery boundary, but the linked PR still needs its changes-requested review resolved.
