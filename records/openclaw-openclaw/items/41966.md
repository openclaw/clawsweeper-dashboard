## Summary

Keep open: current main and the latest release still keep fenced `MEDIA:` lines as visible text with no warning signal, and an open closing-reference PR already owns the candidate warn-only fix.

## What This Changes

The issue asks OpenClaw to make legacy `MEDIA:` directives inside Markdown code fences debuggable or deliverable instead of silently leaving the attachment unsent.

## Best Possible Solution

Keep fenced examples safe by default while making intended fenced `MEDIA:` delivery failures visible, preferably through a delivery-boundary warning unless maintainers explicitly choose extraction or docs-only behavior.

- **Warn Only At Delivery Boundary (recommended):** Keep fenced tokens as visible text, emit one diagnostic warning in the actual outbound delivery path, and resolve the open warn-only PR.
- **Extract From Fences:** Treat standalone fenced `MEDIA:` lines as attachments, accepting the risk that code examples can become deliverable media unless a stricter policy is designed.
- **Docs Only:** Keep runtime behavior unchanged and rely on documentation that legacy `MEDIA:` lines must be standalone plain text.

## Solution Assessment

Unclear until maintainers choose the contract. The linked warn-only path is the lowest-risk mitigation, while extracting fenced tokens could turn code examples into attachments.
