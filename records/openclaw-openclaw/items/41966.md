## Summary

Keep open: current main and the latest release still keep fenced `MEDIA:` lines as visible text with no warning, while https://github.com/openclaw/openclaw/pull/80396 remains the open candidate runtime fix and needs maintainer parser-contract review before this issue can close.

## What This Changes

The issue asks OpenClaw to make fenced-code-block `MEDIA:` directive skips observable or avoid them, because models often wrap final media paths in Markdown code fences and the attachment is not delivered.

## Best Possible Solution

Review and either land or intentionally reject the linked warn-only runtime PR after choosing the fenced-`MEDIA:` contract; keep automatic extraction from code examples off unless maintainers explicitly approve that behavior.

- **Extract fenced tokens:** Treat standalone valid `MEDIA:` lines inside fences as attachments, accepting the risk that examples can trigger delivery.
- **Document only:** Keep runtime unchanged and rely on docs/prompt guidance, leaving the failure silent in logs.

Yes from source inspection, though I did not run tests in this read-only review. A reply containing a fenced standalone `MEDIA:` line takes the `isInsideFence` branch in `splitMediaFromOutput()`, remains visible text, and produces no warning on current main.

Unclear until the parser contract is confirmed. The linked warn-only PR looks like the safest immediate mitigation because it preserves the current code-example safety behavior while making the failure visible.
