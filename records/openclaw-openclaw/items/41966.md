Options:

- **Warn Only At Delivery Boundary (recommended):** Keep fenced tokens as text, emit one warning in the actual outbound delivery path, and land the linked PR after its remaining delivery-path repair.
- **Extract From Fences:** Treat standalone fenced `MEDIA:` lines as attachments, accepting the risk that code examples can become deliverable media unless stricter policy is designed.
- **Docs Only:** Keep runtime behavior unchanged and rely on docs that legacy `MEDIA:` lines must be standalone plain text.

Yes. Source-level reproduction is high confidence: current `splitMediaFromOutput()` keeps fenced lines before the `MEDIA:` parsing branch, and the adjacent parser test expects the fenced token to remain visible text.

## Solution Assessment

Unclear until maintainers choose the contract. The linked warn-only path is the lowest-risk mitigation, while extracting fenced tokens could turn code examples into attachments.
