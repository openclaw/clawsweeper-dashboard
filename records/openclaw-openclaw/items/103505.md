## What This Changes

Create one durable, authenticated approval lifecycle so authorized operators can inspect and resolve the same exec or plugin approval from Control UI, channels, mobile clients, and ancestor session views.

## System Context

Gateway approval services receive exec and plugin approval requests, persist reviewer-safe lifecycle state, and expose canonical reads and resolutions to Control UI, channels, and native clients. Those surfaces render the same approval outcome while authorization and first-answer-wins resolution remain gateway-owned.

## Best Possible Solution

Keep the gateway-owned durable lifecycle, settle timeout semantics as a separate explicit contract, and close this umbrella issue only after the remaining strict-exec and forwarded-Telegram behavior is resolved or deliberately scoped to canonical follow-ups.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw support an explicitly recorded expiry outcome for non-authorizing advisory plugin gates, while all execution-authorizing approvals remain fail-closed?

Rationale: The current merged hardening intentionally removes runtime allow-on-timeout authority, while an active plugin use case requests a bounded advisory outcome; deciding whether that distinct capability belongs in the approval API requires product and security intent.

Likely owner: steipete

Owner reason: The current main architecture and the linked merged approval series were authored through this coordinated implementation effort.

Owner confidence: high

Options:

- **Separate advisory from execution approvals (recommended):** Keep execution approvals deny-by-default and define any advisory expiry as a clearly non-authorizing, durable terminal outcome.
- **Keep one strict approval model:** Retain fail-closed expiry for every approval request and direct soft workflow notifications to a separate mechanism.
- **Restore allow-on-timeout behavior:** Permit request-level expiry allowance for plugin approvals, accepting a broader execution-authority compatibility and security contract.
