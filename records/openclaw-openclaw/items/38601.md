## Summary

Keep open: current main and the latest release still suppress an explicit sandboxed `pty: true` request by computing PTY as `params.pty === true && !sandbox`, with no sandbox-specific warning or error. The related OpenClaw PR attempts are closed unmerged, and the only live candidate is an open fork PR, so the issue still needs maintainer direction rather than cleanup closure.

## What This Changes

The issue asks for sandboxed `exec` calls with `pty: true` to warn or fail instead of silently falling back to non-PTY execution.

## Best Possible Solution

Make the sandboxed `pty: true` downgrade explicit in the exec result and docs, preferably with a narrow warning-only runtime change unless maintainers decide explicit PTY should fail fast.

Question: Should explicit `pty: true` in sandboxed exec warn and continue without PTY, fail fast, or remain documentation-only?

Rationale: The source bug is clear, but the permanent behavior changes an operator-visible sandbox boundary and maintainers should choose the product/security semantics before another fix PR lands.

Likely owner: steipete

Owner confidence: high

Options:

- **Warn and continue (recommended):** Add a user-visible warning when sandbox mode disables PTY while preserving the current non-PTY sandbox execution behavior.
- **Fail explicit PTY:** Treat `pty: true` as a hard requirement in sandbox mode and return an error instead of running without PTY, accepting the compatibility break for explicit calls.
- **Document only:** Keep runtime behavior unchanged and document the limitation, leaving explicit calls to continue silently at runtime.

## Reproduction Assessment

Yes from source: current main sets `usePty` false whenever a sandbox runtime is selected and does not add a warning for `params.pty === true && sandbox`. I did not run a live sandbox command because this cleanup review is read-only.

## Solution Assessment

Unclear until maintainer direction: warning-only is the narrowest non-breaking repair, while fail-fast may be preferable if explicit PTY is considered a hard requirement at the sandbox boundary.
