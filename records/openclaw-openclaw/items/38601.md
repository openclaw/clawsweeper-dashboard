## Summary

Keep open: current main and v2026.6.11 still turn explicit sandboxed `pty: true` into non-PTY execution without a sandbox-specific warning, and maintainers need to choose warning-versus-rejection semantics for this sandbox boundary.

## What This Changes

Warn or reject when an exec call explicitly requests `pty: true` but the effective sandbox host cannot provide PTY semantics.

## Best Possible Solution

Keep sandbox isolation unchanged, then add the maintainer-approved warning or rejection path with focused docs and regression coverage for sandboxed and non-sandboxed `pty:true`.
