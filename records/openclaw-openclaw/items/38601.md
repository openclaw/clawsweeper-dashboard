## Summary

Keep open: current `main` and the latest release still suppress explicit sandboxed `pty: true` exec calls without a sandbox-specific warning, and the only linked fix candidates are closed unmerged same-repo PRs plus an unmerged fork PR.

## What This Changes

This issue asks OpenClaw to warn or fail when `exec` receives `pty: true` but sandbox execution forces non-PTY mode.

## Best Possible Solution

Preserve sandbox PTY suppression by default, then add a clear user-visible warning through the existing exec warning channel, update docs, and add focused regression proof once maintainers confirm warning instead of failure.

Yes. Source inspection shows current main resolves sandboxed explicit PTY requests to `usePty=false` and lacks a sandbox-specific warning branch; I did not run a live sandboxed exec command in this read-only review.

## Solution Assessment

Unclear until maintainers choose the sandbox behavior. A warning-only fix through the existing warnings path is the narrowest compatibility-preserving option, while failing explicit PTY is a defensible stricter policy choice.
