## Summary

Keep open: current main and the latest release still turn explicit sandboxed `pty: true` into non-PTY exec without a sandbox-specific warning, and the remaining choice is warning-versus-reject behavior for a sandbox execution boundary.

## What This Changes

Report requests a user-visible warning or explicit rejection when `exec` is called with `pty: true` while sandboxing suppresses PTY.

## Best Possible Solution

Keep PTY disabled under sandbox, then add a maintainer-approved warning or rejection path, user docs for the limitation, and focused regression coverage for sandboxed explicit PTY.
