## Summary

Keep open: current main and v2026.6.11 still convert explicit sandboxed `pty: true` into non-PTY execution without a sandbox-specific warning, and the remaining blocker is maintainer choice between warning-and-continue versus fail-closed semantics.

## Best Possible Solution

Keep sandbox isolation unchanged, then add the maintainer-approved warning or rejection path with focused docs and regression coverage for sandboxed and non-sandboxed `pty:true`.
