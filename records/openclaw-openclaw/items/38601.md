## Summary

Keep open: current main and the latest release still suppress an explicit `pty: true` request when sandbox execution is selected, and the existing warning path only covers PTY spawn fallback after a host PTY attempt. The open closing PR at https://github.com/BingqingLyu/openclaw/pull/102 is still unmerged, so this issue should stay open until maintainers land, adopt, or replace that fix.

## What This Changes

The issue asks for a warning or error when `pty: true` is requested for the exec tool but sandbox mode prevents PTY allocation.

## Best Possible Solution

Keep PTY disabled under sandbox unless maintainers separately choose broader sandbox PTY support, but emit a clear existing-warning-path message and document the sandbox limitation.

## Reproduction Assessment

Yes. Source inspection of current main shows explicit `pty: true` becomes `usePty=false` whenever `sandbox` is present, with no warning branch before execution; I did not run a live sandboxed exec command in this read-only review.

## Solution Assessment

Yes for the narrow repair. Emitting through the existing warnings path explains the ignored explicit request without weakening the sandbox boundary; throwing or enabling sandbox PTY would be broader product/security work.
