## Summary

Keep open: current main and the latest release still turn explicit sandboxed `pty: true` exec requests into non-PTY execution without a sandbox-specific warning, and the remaining behavior choice is security-sensitive.

## What This Changes

The issue asks OpenClaw to warn or fail when sandboxed exec receives `pty: true` but cannot provide a PTY.

## Best Possible Solution

Keep PTY disabled under sandbox, add a clear warning through the existing exec warnings channel when explicit `pty: true` is ignored, document the limitation, and add focused regression coverage.
