## Summary

Keep open: current main and the latest release still suppress explicit sandboxed `pty: true` without a sandbox-specific warning, and the same-repo PRs that attempted the warning are closed unmerged. The remaining decision is the sandbox-boundary behavior: warn and continue, fail closed, or intentionally support backend PTY in sandbox.

## What This Changes

The issue asks OpenClaw to warn or reject when `exec` is called with `pty: true` while sandbox routing prevents PTY semantics.

## Best Possible Solution

Keep sandbox policy explicit: either honor backend PTY safely or surface a warning/rejection through the existing warning/error path, with docs and regression coverage for sandbox and gateway exec paths.
