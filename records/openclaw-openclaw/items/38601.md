## Summary

Keep open: current main and the latest release still turn explicit sandboxed `pty: true` exec requests into non-PTY execution without a sandbox-specific warning. Same-repo fix attempts are closed unmerged, and the only open closing PR is a fork candidate, so maintainers still need to choose and adopt the warning-vs-fail behavior.

## What This Changes

The issue asks OpenClaw to warn or error when `exec` receives `pty: true` but sandbox routing prevents PTY execution.

## Best Possible Solution

Keep PTY disabled under sandbox by default, then add a clear warning through the existing exec warning channel, document the sandbox limitation, and cover the behavior with focused regression proof once maintainers choose warning versus fail.
