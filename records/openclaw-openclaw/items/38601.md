## Summary

Keep open: current main and the latest release still suppress explicit sandboxed `pty: true` without a sandbox-specific warning, and the remaining choice is warning-versus-fail-closed sandbox behavior rather than cleanup closure.

## What This Changes

The issue requests a warning or explicit error when `exec` is called with `pty: true` but the effective host is sandboxed, plus documentation of that limitation.

## Best Possible Solution

Keep PTY disabled under sandbox, surface explicit PTY suppression through a maintainer-approved warning or rejection path, document the limitation, and add focused regression coverage.
