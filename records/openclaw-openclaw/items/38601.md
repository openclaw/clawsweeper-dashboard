## Summary

Keep open: current main and the latest release still suppress explicit sandboxed `pty: true` requests by running without PTY and without a sandbox-specific warning; the same-repo fix attempts are closed unmerged, and the remaining choice is warning-and-continue versus fail-explicit-PTY.

## What This Changes

The issue asks OpenClaw to warn or error when `exec` is called with `pty: true` in sandbox mode because sandbox routing disables PTY.

## Best Possible Solution

Keep PTY disabled under sandbox, then either emit a clear warning through the existing exec warnings path or fail explicit sandboxed PTY requests after maintainer security review; update the public exec docs and add focused sandbox/non-sandbox PTY coverage.
