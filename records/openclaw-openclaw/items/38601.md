## Summary

Keep open: current main and the latest release still coerce sandboxed `pty:true` to non-PTY execution without a sandbox-specific warning, and the same-repo fix attempts are closed unmerged while the fork candidate remains unmerged.

## What This Changes

The issue requests a warning or error when the exec tool receives `pty:true` but sandbox routing disables PTY.

## Best Possible Solution

Keep PTY disabled in sandbox by default, surface an explicit warning through the existing exec warnings path, document the sandbox limitation, and add focused regression coverage; fail the call only if maintainers explicitly choose that stricter boundary.
