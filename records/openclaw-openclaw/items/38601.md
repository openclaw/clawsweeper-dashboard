## Summary

Keep open: current main and v2026.6.11 still convert explicit sandboxed `pty: true` requests to non-PTY execution without a sandbox-specific warning, and the same-repo fix attempts are closed unmerged while the remaining open fix candidate is only in a fork.

## What This Changes

Requests a warning or error when an explicit `pty: true` exec request is ignored because sandbox execution disables PTY.

## Best Possible Solution

Keep PTY disabled under sandbox by default, add a clear warning through the existing exec warning channel when explicit `pty: true` is ignored, document the sandbox limitation, and cover the sandbox and non-sandbox PTY paths.
