## Summary

Keep open: current main and the latest release still suppress explicit sandboxed `pty: true` into non-PTY execution without a sandbox-specific warning, and the remaining choice is warning-versus-rejection semantics for a security-sensitive exec boundary.

## What This Changes

The issue asks OpenClaw to warn or fail when an exec tool call requests `pty: true` but sandbox mode prevents PTY execution.

## Best Possible Solution

Keep PTY disabled under sandbox, then add a maintainer-approved warning or explicit rejection path with user docs and focused regression coverage.
