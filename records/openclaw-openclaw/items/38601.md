## Summary

Keep open: current main and the latest release still turn explicit sandboxed `pty: true` exec requests into non-PTY execution without a sandbox-specific warning, and the same-repo fix attempts are closed unmerged while the only open closing candidate is a fork PR.

## What This Changes

The issue asks OpenClaw to warn or error when an explicit `pty: true` exec request is routed to sandbox execution and PTY is ignored.

## Best Possible Solution

Keep sandboxed exec non-PTY by default, surface explicit `pty: true` suppression through a warning or maintainer-approved fail-closed policy, document the limitation, and cover it with focused proof.
