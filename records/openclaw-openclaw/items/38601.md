## Summary

Keep open: current main and v2026.6.11 still turn sandboxed explicit `pty: true` into non-PTY execution without a sandbox-specific warning or error, and the remaining choice is maintainer-owned sandbox behavior rather than cleanup closure.

## What This Changes

The issue requests a warning or explicit error when `exec` receives `pty: true` but sandbox mode disables PTY.

## Best Possible Solution

Keep PTY disabled under sandbox, then add a maintainer-approved warning or rejection path, user-facing docs, and focused regression coverage.
