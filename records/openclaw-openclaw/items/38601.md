## Summary

Keep open: current main and v2026.6.11 still suppress explicit sandboxed `pty: true` by computing non-PTY execution without a sandbox-specific warning, and the target-repo candidate PRs are closed unmerged while the remaining behavior choice is security-sensitive.

## What This Changes

The issue asks OpenClaw to warn or error when `exec` receives `pty: true` but sandbox mode prevents PTY execution.

## Best Possible Solution

Keep PTY disabled under sandbox, surface explicit `pty: true` suppression through the existing exec warnings channel unless maintainers choose fail-closed behavior, document the limitation, and add focused regression coverage.
