## Summary

This PR remains necessary because current `main` still computes Codex computer duration budgets with permissive `Number(...)` coercion, while the downstream computer tool uses strict finite-number parsing. The revised head reuses that canonical parser, preserves accepted decimal, scientific, fractional, and numeric inputs, rejects the hex mismatch, and has no actionable correctness or security finding. ([github.com](https://github.com/openclaw/openclaw/blob/main/extensions/codex/src/app-server/dynamic-tool-execution.ts))

## What This Changes

The PR changes Codex computer dynamic-tool timeout parsing to use the computer tool’s strict finite-number grammar and adds focused regression coverage for accepted and rejected duration forms.

## Best Possible Solution

Keep one canonical duration grammar by deriving the Codex outer watchdog from the same strict finite-number parser used by the computer executor, with focused coverage ensuring accepted executor inputs are never underbudgeted.
