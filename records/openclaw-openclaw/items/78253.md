## Summary

Current main still ignores the diagnostic recommendation, so the linked bug remains real, but this PR is not merge-ready: it adds a compatibility-sensitive environment contract without real behavior proof, misstates its storage scope, and accepts whitespace-only values as a relative filesystem root.

## What This Changes

The PR makes QQBot legacy data and download paths honor a new `QQBOT_DATA_DIR` environment variable, documents the variable, and adds unit tests for custom, fallback, tilde, and non-creating path behavior.

## Best Possible Solution

Keep active QQBot state under the canonical `OPENCLAW_STATE_DIR`; if a separate override is retained, define it narrowly for legacy and download paths, require a trimmed absolute path, align diagnostics and docs with that scope, and prove both existing-home and overridden-path behavior.
