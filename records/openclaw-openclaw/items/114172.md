## Summary

Keep this PR open, but do not merge it as written: the new trailing-token alternative uses two nested greedy wildcards on a shared pre-delivery path, so a long reply ending in an attached nonmatching token can trigger excessive regex backtracking. The supplied direct `normalizeReplyPayload` output is good after-fix proof for the reported leak, but the matcher needs a bounded implementation first.

## What This Changes

This PR updates auto-reply cleanup so a final `NO_REPLY` token attached directly to a multi-word sentence ending in `.`, `!`, or `?` is removed before the visible reply is delivered.

## System Context

Auto-reply normalizes model output before channel adapters deliver it to users. Its token helper distinguishes the internal `NO_REPLY` control marker from literal prose, and the normalized text then becomes the outgoing reply.

## Best Possible Solution

Replace the nested-greedy regular-expression branch with a bounded, linear-time trailing-token check that preserves the current literal-token exclusions, then add focused long nonmatching-input coverage alongside the punctuation regression cases.
