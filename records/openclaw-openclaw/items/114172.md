## Summary

The PR remains necessary: current `main` still removes a trailing `NO_REPLY` only when it begins at the start of text, after whitespace, or after asterisks, so sentence-attached tokens can reach outbound reply text. The proposed rule is a narrow delivery-path repair, keeps the existing token-only and leading-token rules separate, and the updated PR body now supplies direct after-fix terminal output; no discrete patch defect was found.

## What This Changes

This PR updates auto-reply normalization so a trailing `NO_REPLY` attached to a multi-word sentence ending in `.`, `!`, or `?` is removed while preserving the visible sentence and punctuation.

## System Context

Auto-reply normalizes raw model output before OpenClaw delivers it to a channel. Silent-token helpers either suppress token-only responses or remove a trailing control token from mixed visible text, and `normalizeReplyPayload` passes the resulting text onward to channel transforms and delivery.
