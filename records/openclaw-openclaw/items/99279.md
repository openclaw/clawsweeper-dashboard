## Summary

Keep open. Current main and latest release still lack Mattermost inbound bot-identity facts or a Mattermost bot-admission/loop-guard surface, so bot-authored Mattermost posts that pass ordinary sender policy can reach dispatch without the shared bot-pair guard.

## What This Changes

Add Mattermost inbound bot identity handling or explicit bot-admission support so bot-authored Mattermost messages are not processed as ordinary senders without loop protection.

## Best Possible Solution

Add Mattermost-owned bot sender classification, feed admitted bot-authored turns into the shared pair-loop guard, and document/test maintainer-approved defaults for user bots and webhook posts.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 drop only self/system Mattermost posts and never pass botLoopProtection facts into the shared turn guard. I did not run a live two-bot Mattermost deployment.

## Solution Assessment

Unclear as a final product shape: the right owner boundary is the Mattermost plugin plus the existing shared pair-loop guard, but maintainers still need to choose bot admission defaults, config shape, and webhook trust semantics.
