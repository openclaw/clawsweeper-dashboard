## Summary

Keep open. Current main and the latest release still do not classify Mattermost inbound bot or webhook senders, and accepted Mattermost turns are not passed to the shared bot-pair loop guard.

## What This Changes

Request Mattermost inbound bot identity support so shared bot-loop protection or an explicit bot-admission policy can guard bot-to-bot loops.

## Best Possible Solution

Add Mattermost-owned bot and webhook identity resolution, decide the default admission/config semantics, feed accepted bot-authored turns into the shared pair-loop guard, and document/test the behavior.

## Reproduction Assessment

Yes at source level: current Mattermost code drops self/system posts but otherwise admits allowed senders without bot identity facts, and its strict config schema has no allowBots or botLoopProtection surface. I did not run a live two-bot Mattermost deployment.

## Solution Assessment

Unclear as a final product shape: wiring reliable bot facts into the existing shared pair-loop guard is the right owner boundary, but maintainers still need to choose Mattermost defaults, allowBots semantics, and webhook handling.
