## Summary

Keep open: the earlier side-question and fractional-timeout blockers are addressed, but the current mapping arms the outer Codex dynamic-tool watchdog at the same budget that tools such as `sessions_send` use internally, so it can replace a structured timeout result with a generic hard-timeout response.

The PR updates Codex dynamic-tool timeout readers and tests so `timeoutSeconds` is used when `timeoutMs` is absent on the main and side-question paths, and adds a proof script for those handlers.

## Best Possible Solution

Land one consolidated Codex app-server fix that preserves `timeoutMs` precedence, treats `timeoutSeconds` as a bounded outer watchdog with small grace over tool-owned waits, applies the same helper to main and side-question readers, and proves a `sessions_send`-style structured timeout result wins before the watchdog.
