## Summary

Keep open: current main still ignores seconds-form dynamic-tool timeouts, and this PR is a viable candidate fix for the canonical Codex timeout bug. The runtime/test shape is sound, but the public Codex harness timeout docs still need the new precedence and headroom semantics before this ships cleanly.

## What This Changes

The PR changes Codex dynamic-tool timeout resolution to use integer `timeoutSeconds` with 30s outer watchdog grace when `timeoutMs` is absent, and makes side-question calls share the main handler and resolver.

## Best Possible Solution

Land the shared Codex dynamic-tool timeout resolver after documenting `timeoutMs` precedence, `timeoutSeconds` fallback, and the 30s outer-headroom behavior, then close the canonical timeout issue and supersede competing duplicate PRs through the merged fix.

Yes, this is the best fix shape: it preserves `timeoutMs` precedence, gives `sessions_send`-style inner timeouts headroom, and removes the duplicate side-question timeout stack. The safer pre-merge follow-up is documentation, not a different runtime layer.
