## Summary

Keep open: the PR now honors `timeoutSeconds` on both Codex dynamic-tool paths, but it still arms the outer watchdog at the exact seconds budget, so `sessions_send` can lose its structured timeout result with `runId` to a generic hard-timeout response.

## What This Changes

The PR updates Codex dynamic-tool timeout readers, side-question timeout readers, focused tests, and a proof script so `timeoutSeconds` is used when `timeoutMs` is absent and fractional seconds are rejected.

## Best Possible Solution

Use one shared seconds-timeout conversion for the main and side-question Codex dynamic-tool readers that preserves exact `timeoutMs` precedence while adding enough outer-watchdog headroom for tool-owned `timeoutSeconds` results to win.
