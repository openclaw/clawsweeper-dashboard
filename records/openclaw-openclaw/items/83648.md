## Summary

Keep open: the PR fixes the source-visible bare cron preflight probe for common bearer-header local providers, but the current head still skips credential fallback when `request.auth.mode` is `provider-default`, leaving that documented provider-default path headerless.

## What This Changes

The PR changes isolated cron local-provider preflight to build provider/request headers through shared auth utilities, pass agent/workspace dirs into credential lookup, and add auth/header regression tests.

## Best Possible Solution

Keep the shared resolver approach, but treat provider-default as default credential fallback while preserving request headers and retaining maintainer sign-off on credentialed local/private preflight scope.

## Reproduction Assessment

Yes. Current main and the latest release send local cron preflight probes as bare GET requests, and the inspected LiteLLM screenshot shows `/models` changing from 401 to 200 for the bearer-header path after the patch; the remaining provider-default gap is source-reproducible from the sanitizer and fallback gate.

## Solution Assessment

No, not yet. Delegating to the shared resolver is the right owner-boundary fix, but provider-default must be treated as default credential fallback rather than as a custom auth override that suppresses fallback.
