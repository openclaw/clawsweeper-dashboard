## Summary

Keep open: the latest head fixed the prior request-header fallback gap, but it still suppresses provider credential fallback when `request.auth.mode` is explicitly `provider-default`, leaving those preflight probes headerless while normal provider requests use built-in auth.

## What This Changes

The branch changes isolated cron local-provider preflight to resolve provider/request headers through shared auth utilities, pass agent/workspace dirs, and add auth/header regression tests.

## Best Possible Solution

Keep the shared resolver approach, but treat provider-default auth as default credential fallback, preserve sanitized headers, and retain maintainer sign-off on credentialed local/private preflight scope.

## Reproduction Assessment

Yes, at source level: current main sends local cron preflight probes as bare GET requests, and the inspected LiteLLM screenshot shows /models changing from 401 to 200 after adding auth headers. The remaining provider-default gap is also source-reproducible from the sanitized auth state and fallback gate.

## Solution Assessment

No, not yet. Delegating through the shared resolver is the right owner-boundary fix, but the fallback gate must treat provider-default as default provider auth rather than a custom override.
