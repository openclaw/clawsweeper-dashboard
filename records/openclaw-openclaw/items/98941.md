## Summary

Keep open; the response-size hardening is useful, but this PR is not merge-ready because the thread-ownership change can fail open on an oversized 409 conflict body and the proof does not exercise the changed extension paths.

## What This Changes

The PR replaces three native `response.json()` / `resp.json()` reads in Discord webhook sends, Hugging Face model discovery, and thread-ownership conflict handling with bounded text reads plus JSON parsing.

## Best Possible Solution

Keep the bounded reads, but make thread-ownership cancel based on status 409 regardless of whether owner-body parsing succeeds, then add changed-path proof for normal and oversized responses.

## Reproduction Assessment

Yes, source-level. Current main and the latest release use unbounded native JSON reads in the three touched paths, and the PR diff shows the oversized thread-ownership 409 parse failure would reach the existing fail-open catch.

## Solution Assessment

No as submitted. The owner boundary and shared bounded-reader direction are right, but thread-ownership should cancel on 409 before optional body parsing and the PR needs changed-path proof.
