## Summary

## Best Possible Solution

Keep the bounded reads, but make thread-ownership treat 409 as authoritative cancellation regardless of owner-body parse success, add focused oversized-409 regression coverage, and require changed-path proof before merge.

## Reproduction Assessment

Yes, source-level. Current main uses unbounded native JSON reads in the touched paths, and the PR's thread-ownership change can be traced to a parse-before-cancel path that fails open on oversized 409 bodies.

## Solution Assessment

No as submitted. The bounded-reader direction is the right owner-boundary fix, but thread-ownership should cancel based on the 409 status before optional owner parsing and the PR needs changed-path proof.
