Keep open for maintainer review: current main still rejects comma-joined repeated Content-Length values, while this PR fixes the shared media parser with direct caller-path proof and no blocking findings. Landing should still wait for exact-head CI to finish green.

## What This Changes

The PR changes media Content-Length parsing to accept comma-separated repeated matching values while still rejecting malformed, unsafe, empty, or conflicting values.

## Best Possible Solution

Merge the shared parser fix after exact-head CI is green, keeping repeated Content-Length policy in packages/media-core rather than adding per-caller parsing.

## Solution Assessment

Yes. The shared media-core parser is the right owner because core media fetch, input-file fetching, and plugin SDK consumers share this Content-Length policy; broader non-media parsers are adjacent but not required for this PR's stated media boundary.
