## Summary

Keep open. Current main still routes `exec host=node` through synchronous `node.invoke system.run` with one final result, and the open timeout PR only addresses the wait budget while explicitly deferring task handoff, heartbeat, and progress semantics.

## What This Changes

Request a first-class async/progress path for long-running node-host commands so callers can receive intermediate updates before the final result.

## Best Possible Solution

Design an additive, permission-checked node-host async task/progress contract that preserves one-shot node.invoke, maps host=node background/yield requests to a real process/task handle or explicit guardrail, and updates protocol schemas, gateway handling, node-host dispatch, docs, and focused tests together.

## Reproduction Assessment

Yes, at source level. Current main delegates host=node exec to synchronous node.invoke system.run and only local gateway/sandbox exec reaches the process-session yield/background handoff; the July 4 production comment reports the same behavior on v2026.6.11.

## Solution Assessment

Unclear as a concrete API. A shared core node-host async/progress primitive is the right layer, but maintainers need to decide the protocol, security, lifecycle, buffering, cancellation, and docs shape before implementation.
