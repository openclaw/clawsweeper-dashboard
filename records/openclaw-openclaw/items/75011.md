## Summary

Keep open: the docs gap still exists on current main and the latest release, but this PR cannot merge as written because its stale-token recovery advice tells operators to reject the pending request even though approval is the path that issues the replacement token.

## What This Changes

This PR adds a Troubleshooting section to docs/gateway/pairing.md for dropped pre-approval commands, missing pending node pairing requests, and stale tokens after re-pairing.

## Best Possible Solution

Keep the troubleshooting addition, but rewrite stale-token recovery to approve the visible pending request or reconnect/rerun the node and approve the new request, then refresh the branch and run docs validation.

## Reproduction Assessment

Yes. The docs gap is visible in current docs, and the wording defect is source-reproducible by comparing the PR paragraph with approveNodePairing and rejectPendingPairingRequest; no live run is needed for this docs-only review.

## Solution Assessment

No, not as written. The pairing page is the right docs surface, but stale-token recovery should be approval-first or reconnect-then-approve, not reject-and-reapprove.
