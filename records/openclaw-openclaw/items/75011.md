## Summary

Keep open: the gateway pairing docs gap still exists on current main and the latest release, but the PR needs changes because its stale-token recovery text tells operators to reject and re-approve even though approval is the path that issues a fresh token.

## Best Possible Solution

Keep the troubleshooting section, but rewrite stale-token recovery to approve the visible pending request or reconnect/rerun the node and approve the new request, then refresh the branch and run docs validation.

## Reproduction Assessment

Yes. The docs gap is visible in current `docs/gateway/pairing.md`, and the proposed stale-token wording defect is source-reproducible against `approveNodePairing` and `rejectPendingPairingRequest`.

## Solution Assessment

No, not as written. The pairing page is the right docs surface, but token recovery should be approval-first or reconnect-then-approve instead of reject-and-reapprove.
