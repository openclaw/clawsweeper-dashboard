## What This Changes

## Best Possible Solution

Land the narrow handler guard only after redacted Discord runtime proof shows malformed missing-id events are dropped without blocking a following valid message, or after maintainers explicitly accept the defensive boundary as a proof override.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Source inspection and the added handler tests show current main can admit malformed mapped missing-id data into the handler path, but there is no high-confidence live Discord gateway reproduction of a crash or restart.

## Solution Assessment

Is this the best way to solve the issue? Yes for the narrow mapped MESSAGE_CREATE missing-id boundary: dropping before replay/debounce/preflight is cleaner than relying on every downstream consumer, while broader raw gateway payload validation would belong in the mapper if maintainers want that too.
