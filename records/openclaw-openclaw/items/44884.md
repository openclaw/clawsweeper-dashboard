  - body: These new Gateway keys are added only to the TypeScript config type. The current Gateway Zod schema is `.strict()` and still lacks `ipAllowlist`, `ipBlocklist`, `requestRateLimit`, and `tls.terminatedUpstream`, and the schema help/labels are also missing, so user config and `openclaw config set` paths will not have a complete contract for the advertised feature.

- **[P1] Keep request throttling behind an approved default:** `src/gateway/server.impl.ts:531`
  - body: `createRequestRateLimiter()` is created unconditionally from possibly absent config, so merging this would make existing Gateway HTTP/WS traffic subject to a new 120 req/min/IP default and possible 429s after upgrade. That needs an opt-in default or explicit maintainer approval with fresh-install and upgrade proof before it can be a safe security default.
  - confidence: 0.9
- **[P1] Keep HSTS opt-in unless the default is approved:** `src/gateway/server-runtime-config.ts:201-202`
  - body: When Gateway TLS is enabled and no HSTS config is set, this now emits `Strict-Transport-Security: max-age=31536000`. Current docs describe HSTS as an operator-set header, and a long-lived automatic browser policy can surprise staging or reverse-proxy deployments, so this should stay explicit unless maintainers approve the default with docs and upgrade proof.
  - confidence: 0.88
- **[P1] Define audit-log privacy before enabling it by default:** `src/gateway/server.impl.ts:534`
  - body: The server always creates the auth audit logger, and log entries can include `clientIp` and `user` in a persistent JSONL file under the state logs directory. Before this is default-on, the PR needs an explicit opt-in or maintainer-approved retention/redaction/privacy policy with docs, otherwise existing deployments can start storing identifiable access metadata unexpectedly.
  - confidence: 0.87
- **[P2] Thread the audit logger into auth verification paths:** `src/gateway/server-http.ts:764`
  - body: The server accepts `authAuditLogger`, and `authorizeGatewayConnect()` can emit `auth_success` and `auth_failure`, but the HTTP/plugin auth paths shown here still pass only `rateLimiter` into their auth helpers. That leaves the advertised auth outcome audit trail incomplete even though the IP block and rate-limit events are logged.
  - confidence: 0.82
