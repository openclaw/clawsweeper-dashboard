  - body: `createRequestRateLimiter()` is created unconditionally with 120 req/min defaults, so upgraded non-loopback Gateways can start returning 429 without an operator opting in. Keep this explicit, migrate safely, or get maintainer approval plus upgrade proof for the new default.
  - confidence: 0.9
- **[P1] Keep HSTS explicit for existing TLS gateways:** `src/gateway/server-runtime-config.ts:201-202`
  - body: This auto-adds `Strict-Transport-Security: max-age=31536000` whenever TLS is enabled and no header was configured. HSTS is sticky browser state, and current docs describe it as an explicit operator setting for controlled HTTPS origins, so this needs to remain opt-in or have a clear upgrade policy.
  - confidence: 0.89
- **[P1] Define audit-log retention before persisting auth metadata:** `src/gateway/auth-audit-log.ts:18-21`
  - body: The new JSONL audit log writes client IP, method, reason, and user fields under the state log directory by default. That can be useful, but it needs an explicit privacy/retention/ownership story and docs before becoming default behavior for Gateway auth events.
  - confidence: 0.87
- **[P1] Pass the audit logger into auth verification callers:** `src/gateway/auth.ts:86-94`
  - body: Adding `auditLogger` to `authorizeGatewayConnect` is not enough: the HTTP auth call shown in `server-http.ts` still calls `authorizeHttpGatewayConnect` without passing the logger, so the advertised auth_success/auth_failure events are incomplete. Wire the logger through the relevant HTTP/WS auth call sites or narrow the audit-log claim.
  - confidence: 0.86
