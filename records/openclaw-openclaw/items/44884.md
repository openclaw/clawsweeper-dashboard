## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P1] Wire the new Gateway config into validation:** `src/config/types.gateway.ts:443-450`
  - body: The PR adds runtime reads for `gateway.ipAllowlist`, `gateway.ipBlocklist`, `gateway.requestRateLimit`, and `gateway.tls.terminatedUpstream`, but it only adds TypeScript types. The current Gateway schema is strict and the PR head does not add those keys, so user config for the new controls will be rejected instead of enabling the hardening.
  - confidence: 0.95
- **[P1] Keep request throttling behind an approved default:** `src/gateway/server.impl.ts:530-531`
  - body: This creates a per-IP request limiter for every Gateway with default limits. That can start returning 429s for existing deployments, especially behind shared proxies, before maintainers have approved the default-on behavior and before the new config key is schema-valid.
  - confidence: 0.86
- **[P1] Keep HSTS opt-in unless the default is approved:** `src/gateway/server-runtime-config.ts:199-202`
  - body: Current main treats HSTS as an explicit operator setting, but this branch emits `Strict-Transport-Security: max-age=31536000` whenever Gateway TLS is enabled. That changes existing TLS responses and should not land without an explicit default-policy decision and upgrade proof.
  - confidence: 0.88
- **[P1] Do not enable sensitive audit logs by default:** `src/gateway/server.impl.ts:533-534`
  - body: The Gateway now creates the auth audit logger unconditionally, and that logger writes client IP and user metadata to disk. A security hardening PR needs an explicit retention/opt-out policy and docs before silently adding this new sensitive local log surface for every Gateway start.
  - confidence: 0.82
- **[P2] Thread the audit logger into auth callers:** `src/gateway/auth-audit-log.ts:13`
  - body: The new `auth_success` and `auth_failure` event types are only emitted when callers pass `auditLogger`; the WS auth context and readiness auth caller still call the wrappers without it. The advertised audit trail will miss normal auth outcomes unless the logger is threaded through those real auth paths or the event claim is narrowed.
  - confidence: 0.86
