  - body: The PR adds `gateway.tls.terminatedUpstream`, `gateway.ipAllowlist`, `gateway.ipBlocklist`, and `gateway.requestRateLimit` to the TypeScript config types, but current Gateway config parsing is strict and this diff does not add those keys to the zod schema/help/labels/docs contract.   - confidence: 0.95
- **[P1] Keep request throttling behind an approved default:** `src/gateway/server.impl.ts:531`
  - body: `startGatewayServer` now creates the request limiter unconditionally and the HTTP/WS paths return 429 before normal routing. That can change existing Gateway client behavior after upgrade without an explicit operator opt-in or maintainer-approved migration, and the missing strict schema wiring also leaves users without a supported tuning surface.
  - confidence: 0.93
- **[P1] Keep HSTS opt-in unless the default is approved:** `src/gateway/server-runtime-config.ts:201-202`
  - body: Current docs and runtime treat `gateway.http.securityHeaders.strictTransportSecurity` as an operator-set header for HTTPS origins the operator controls. Auto-emitting `max-age=31536000` for every TLS-enabled Gateway changes browser behavior for staging and reverse-proxy deployments, so this needs explicit default-policy approval and upgrade proof before merge.
  - confidence: 0.9
- **[P1] Define audit-log retention before enabling it by default:** `src/gateway/server.impl.ts:534`
  - body: The server now creates the auth audit logger for every Gateway start and the logger persists client IPs and user identifiers to JSONL under state logs. That is a new persistent privacy/security surface; it needs opt-in or an explicit retention/redaction policy and docs before becoming default runtime behavior.
  - confidence: 0.88
- **[P2] Pass the audit logger into auth verification:** `src/gateway/server-http.ts:764`
  - body: The PR receives `authAuditLogger` in the HTTP server, but the inspected HTTP/WS auth verification call sites still do not pass it into the new `auditLogger` parameter on `authorizeGatewayConnect`. The advertised `auth_success` and `auth_failure` events will therefore remain missing for normal Gateway authentication paths.
  - confidence: 0.84
