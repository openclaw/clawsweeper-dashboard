## Label Justifications

- `P2`: This is a current provider-specific behavior bug that hides actionable Guardrail outcomes but does not crash the runtime or block all Bedrock use.
- `impact:message-loss`: AWS returns configured blocked-response text for Guardrail intervention, but the reported path suppresses it and sends a generic failure instead.
- `impact:ux-friction`: Users cannot distinguish intentional Guardrail enforcement from an infrastructure timeout, and operators lose useful diagnostic context.

## Summary

Current main still converts the Bedrock stream’s generic `An unknown error occurred` into a timeout/failover error, while AWS defines guardrail intervention as a normal `guardrail_intervened` response with configured blocked text and optional trace metadata. The report is distinct from the earlier empty-assistant-turn issue and should remain open as a provider error-contract bug.

## What This Changes

Preserve AWS Bedrock Guardrail intervention details so users receive the configured blocked response and operators receive useful guardrail diagnostics instead of a generic timeout error.

## Best Possible Solution

Handle `guardrail_intervened` at the Bedrock provider boundary, preserve AWS's configured blocked text as the visible assistant response, emit a sanitized structured diagnostic from trace metadata, and prevent the event from entering timeout failover classification.
