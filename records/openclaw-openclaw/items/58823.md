## Summary

Keep open: current main and the latest release still let the shared `agent-scope` helper choose an agent primary before the global subagent default, and isolated cron consumes that helper. The PR remains a viable fix candidate, but the precedence change is compatibility-sensitive and needs maintainer acceptance before merge.

## What This Changes

This PR reorders shared subagent model selection so per-agent subagent config wins first, the global subagent default second, and the agent primary last, with cron-related regression coverage and a proof script.

## Best Possible Solution

Choose one canonical precedence contract, then either land this shared-helper and cron fix after sequencing with the broader runtime work or update docs/tests to preserve the agent-primary order intentionally.

## Solution Assessment

Yes, pending maintainer acceptance of the compatibility tradeoff. Moving the precedence in the shared helper is the narrowest remaining fix because the direct native resolver is already fixed and cron now consumes the shared helper.
