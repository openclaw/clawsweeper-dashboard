## Summary

Keep open: current main still has the shared `agent-scope` helper and isolated cron consumer using the agent primary before the global subagent default, while this PR is a focused candidate for that remaining mismatch. The patch looks correct, but the precedence change is compatibility-sensitive and should be explicitly accepted and sequenced with the broader runtime/session persistence work before merge.

## What This Changes

The PR changes shared subagent model selection so per-agent subagent model wins first, global `agents.defaults.subagents.model` wins second, and the agent primary model is only the fallback, with agent/cron tests and a proof script updated to match.

## Best Possible Solution

Land this focused helper/cron precedence fix if maintainers accept the documented global-subagent-default-before-agent-primary contract, and coordinate the same rule with the broader runtime/session persistence work.

## Reproduction Assessment

Yes. Source inspection on current main shows `resolveSubagentModelConfigSelectionResult` evaluates `agentConfig.model` before `agents.defaults.subagents.model`, and isolated cron calls that helper; no tests were run because this review is read-only.

## Solution Assessment

Yes for the remaining helper/cron mismatch, pending maintainer acceptance of the compatibility tradeoff. Reordering the shared helper is the narrowest maintainable fix; the alternative is to keep agent-primary precedence and update docs/tests consistently.
