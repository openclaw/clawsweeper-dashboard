- `merge-risk: 🚨 availability`: The changed worker spawn path can still fail to start new local embedding workers in the reported stale-Cellar environment if it relies on `process.argv[0]` or an unavailable PATH fallback.

## Summary

This PR is still not merge-ready: it targets the right local embedding worker fork path, but the resolver still relies on `process.argv[0]` as the preserved Homebrew launch symlink even though Node preserves that value in `process.argv0`; real Homebrew/Gateway after-fix proof is also missing.

## What This Changes

The PR adds a worker Node executable resolver that checks `process.execPath`, `process.argv[0]`, and PATH before passing an explicit `execPath` to the local embedding worker fork.

## Best Possible Solution

Use `process.argv0` or a package-local stable Homebrew resolver before PATH fallback, add focused stale-Cellar coverage, and include redacted macOS Homebrew/Gateway proof for a fresh worker fork.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level. Current main omits `execPath` on the worker `fork()`, Node defaults that executable to `process.execPath`, and this PR's `process.argv[0]` fallback is contradicted by Node's runtime argv behavior.

## Solution Assessment

No. Passing an explicit worker `execPath` is the right layer, but this implementation should use `process.argv0` or a stable Homebrew resolver before PATH fallback and should include stale-Cellar proof.
