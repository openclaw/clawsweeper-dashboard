## Summary

This PR should stay open but is not merge-ready: it still relies on `process.argv[0]` for the claimed preserved launch symlink, while Node preserves that value in `process.argv0`, and the added proof does not show the reported macOS/Homebrew Gateway recovery path.

## What This Changes

The PR adds a helper in `packages/memory-host-sdk` to resolve a Node executable from `process.execPath`, `process.argv[0]`, or PATH and passes it as `execPath` to the local embedding worker fork.

## Best Possible Solution

Use `process.argv0` or a package-local stable Homebrew resolver before PATH fallback, add focused stale-Cellar worker coverage, and include redacted macOS/Homebrew Gateway proof for a fresh worker fork.

## Maintainer Decision

## Reproduction Assessment

Yes, at source level. Current main omits `execPath` on the worker `fork()`, Node defaults that executable to `process.execPath`, and this PR's `process.argv[0]` fallback is contradicted by Node's runtime argv behavior.

## Solution Assessment

No. Passing an explicit worker `execPath` is the right layer, but this implementation should use `process.argv0` or a stable Homebrew resolver before PATH fallback and should include stale-Cellar proof.
