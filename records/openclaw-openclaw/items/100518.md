## Summary

Keep this PR open, but it is not merge-ready: the patch targets the right local embedding worker availability bug, yet the current branch still uses `process.argv[0]` for the launch-symlink fallback even though Node exposes that original value as `process.argv0`, and the PR still lacks real Homebrew/Gateway proof for the reported stale-Cellar path.

## What This Changes

The PR adds a local embedding worker Node executable resolver that passes an explicit `execPath` to `child_process.fork`, checking `process.execPath`, `process.argv[0]`, and PATH.

## Best Possible Solution

Use `process.argv0` or a package-local stable Homebrew Node resolver before PATH fallback, add focused stale-Cellar regression coverage, and include redacted macOS Homebrew/Gateway proof for a fresh worker fork.

Yes, at source level. Current main omits `execPath` on the worker `fork()`, Node defaults that executable to `process.execPath`, and this PR's `process.argv[0]` fallback is contradicted by Node's runtime argv behavior.

## Solution Assessment

No. Passing an explicit worker `execPath` is the right layer, but this implementation should use `process.argv0` or a stable Homebrew resolver before PATH fallback and should include stale-Cellar proof.
