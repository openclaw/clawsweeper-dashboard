## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P2] Protect session.started with the trajectory finally:** `src/agents/cli-runner/execute.ts:479-488`
  - body: This creates the recorder and records `session.started` before prompt/image/skills/args/queue prep, but the catch/finally that records `session.ended` and flushes starts later. Because recorder creation writes the pointer immediately, any post-start prep failure exits with incomplete trajectory state; move all post-recorder prep inside the protected lifecycle scope or delay `session.started` until that scope starts.
  - confidence: 0.94
- **[P2] Move prompt.submitted to the CLI execution boundary:** `src/agents/cli-runner/execute.ts:511-517`
  - body: `prompt.submitted` is emitted before skills plugin prep, execution-arg resolution, CLI arg construction, queue-key resolution, and `enqueueCliRun`. A failure in those steps records a submitted prompt even though no CLI process could receive it, so emit this event only after execution-blocking prep has succeeded and cover the late-prep failure path.
  - confidence: 0.9
- **[P2] Flush trajectory even when cleanup throws:** `src/agents/cli-runner/execute.ts:1546`
  - body: The new flush block sits after `cleanupOuterResource(...)` calls, but on a successful run a cleanup rejection can rethrow before this block is reached. That drops the queued `model.completed` and `session.ended` events; run the trajectory flush from a nested finally or otherwise preserve and rethrow cleanup errors after flushing.
  - confidence: 0.91
