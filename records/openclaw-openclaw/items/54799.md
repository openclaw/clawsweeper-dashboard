Keep open for maintainer product and security review: current main and latest release still lack declarative scheduled/event SKILL.md trigger metadata, automatic cron registration from skill frontmatter, skill-level last-triggered output, and an approved permission boundary. The cron-operator comment is useful real-world evidence that explicit Gateway/skill scheduling is painful, but this remains a public automation contract rather than a narrow bug fix.

## What This Changes

Request optional SKILL.md trigger metadata for scheduled or event-driven skills, automatic cron/event registration, and last-triggered/audit output.

## Best Possible Solution

Define a permissioned skill automation contract first, then implement one coordinated path for metadata parsing, scheduler/event registration, audit state, CLI/docs output, and regression coverage.
