## Summary

Keep open for maintainer product and security review: current main and the latest release still do not support declarative scheduled/event SKILL.md trigger metadata, automatic cron registration from skill frontmatter, or last-triggered/audit output. The related operator comment is useful evidence that manual cron and skill scheduling is painful, but this is a public automation and trust-boundary decision rather than a narrow bug fix.

## What This Changes

Request adding optional SKILL.md trigger metadata for scheduled/event-driven skills, automatic cron/event registration, and trigger audit/list output.

## Best Possible Solution

Define the permissioned automation contract first, then implement one canonical metadata, scheduler-registration, event/audit-state, CLI/docs, and regression-test path or explicitly route scheduling through approved cron/plugin flows instead.
