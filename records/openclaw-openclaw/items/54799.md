## Summary

Keep open for maintainer product and security review: current main still has explicit cron jobs and skill snapshots, but not declarative SKILL.md schedule/event trigger metadata, automatic registration from skill metadata, last-triggered skill audit state, or a settled trust boundary for autonomous execution.

## What This Changes

The issue requests optional SKILL.md frontmatter for scheduled and event-based skill triggers, with cron registration, lifecycle-event triggering, and skills-list/audit visibility.

## Best Possible Solution

Keep this open until maintainers decide the permissioned contract for skill-owned automation, then implement the smallest core/plugin API surface that records operator approval and audit state.
