## Summary

Keep open for maintainer product and security review: current main and v2026.6.11 still lack declarative scheduled/event SKILL.md trigger metadata, automatic cron registration from skill frontmatter, skill-level last-triggered output, and a settled trust boundary. The cron-operator comment adds useful real-world evidence that manual Gateway/skill scheduling is painful, but this remains a public automation contract rather than a narrow bug fix.

## What This Changes

Request optional SKILL.md frontmatter for scheduled/event triggers, automatic cron or event registration, last-triggered skills output, and a minimal documentation-only trigger field.

## Best Possible Solution

Define the permissioned automation contract first, then implement one coordinated path for metadata parsing, scheduler registration, event/audit state, CLI/docs output, and regression tests.
