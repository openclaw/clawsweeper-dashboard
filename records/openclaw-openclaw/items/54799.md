## Summary

Keep open for maintainer product and security review: current main and v2026.6.11 still lack declarative scheduled/event SKILL.md trigger metadata, automatic cron registration from skill frontmatter, skill-level last-triggered output, and never-triggered audit support. The cron-operator comment adds credible real-world scheduling pain, but this is a public autonomous-execution contract rather than a narrow bug fix.

## What This Changes

Request declarative scheduled/event trigger metadata in SKILL.md so skills can register cron/event automation and expose last-triggered or audit state.

## Best Possible Solution

Define the permissioned automation contract first, then implement metadata parsing, scheduler/event registration, trigger state/audit output, docs, and focused tests as one coordinated design.

## Reproduction Assessment

Yes for a source-level feature gap, not for a broken existing behavior: current main and v2026.6.11 omit trigger metadata from skill parsing, prompt/status output, cron registration, and skills CLI audit/listing.

## Solution Assessment

Unclear until maintainers choose the product and security boundary; a SKILL.md field is plausible, but standing orders, explicit cron jobs, plugin manifest metadata, ClawHub indexing, or plugin hook APIs may need to be part of the final contract.
