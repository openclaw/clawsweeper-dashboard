## Summary

Keep open: current main and v2026.6.11 still lack declarative scheduled/event SKILL.md trigger metadata, automatic cron registration from skill frontmatter, last-triggered skill status, and a never-triggered audit surface. The cron-operator comment is useful real-world evidence, but this remains a public automation and security contract that needs maintainer design rather than a cleanup close.

## What This Changes

Add optional SKILL.md trigger metadata for schedule/event-driven skills, scheduler registration, and skills CLI trigger audit/status output.

## Best Possible Solution

Define a maintainer-approved trigger metadata contract, permission model, and scheduler/hook ownership first, then implement parser/types, cron/event registration, CLI status/audit, docs, and focused tests together.

## Reproduction Assessment

Yes, by source inspection: current main omits trigger metadata from skill parsing, types, prompt rendering, skills list output, cron registration, and public docs.

## Solution Assessment

Unclear until maintainers choose the public contract; a SKILL.md trigger field is plausible, but scheduler ownership, event semantics, permissions, and relationship to plugin/ClawHub APIs must be settled first.
