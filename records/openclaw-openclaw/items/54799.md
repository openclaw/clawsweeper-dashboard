## Summary

Keep open for maintainer product and security review: current main and v2026.6.11 still lack declarative scheduled/event SKILL.md trigger metadata, automatic skill-to-cron/event registration, last-triggered skill status, and a never-triggered audit surface. The cron-operator comment adds useful real-world evidence, and the open durable-routines work overlaps the scheduler direction but does not replace this skill-owned trigger contract decision.

## What This Changes

Request to let skills declare schedule or event trigger metadata in SKILL.md frontmatter and expose trigger state through scheduler registration, skill listing, and audits.

## Best Possible Solution

Define a maintainer-approved skill trigger contract with opt-in permissions and alignment to routines/plugin hooks, then implement parsing/types, scheduler or event registration, status/audit output, docs, and focused tests together.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 omit schedule/event trigger metadata from skill parsing, loaded skill contracts, prompt rendering, skills list output, cron registration, and public skill docs; this is a source-reproducible feature gap, not a broken existing-behavior bug.

## Solution Assessment

Unclear until maintainers choose the contract. A SKILL.md trigger field is plausible, but the best solution must settle metadata placement, scheduler ownership, event semantics, permission boundaries, audit state, and overlap with durable routines and plugin hooks.
