## Summary

Keep open for maintainer product and security review: current main and v2026.6.11 still lack declarative scheduled/event SKILL.md trigger metadata, automatic scheduler registration, last-triggered skill status, and never-triggered audit support.

## What This Changes

Add declarative schedule/event trigger metadata to SKILL.md frontmatter so skills can self-register cron or lifecycle-triggered runs and expose trigger status in skill tooling.

## Best Possible Solution

Adopt a single maintainer-approved trigger contract with explicit security/permission rules, then implement parser/types, scheduler and event registration, CLI status/audit output, docs, and focused tests together.

## Reproduction Assessment

Yes, by source inspection: current main and v2026.6.11 omit scheduled/event trigger metadata from skill parsing, types, prompt rendering, skills list output, cron contracts, and public docs. This is a source-reproducible feature gap rather than a broken existing behavior bug.

## Solution Assessment

Unclear until maintainers choose the contract. A SKILL.md trigger field is plausible, but the best solution must settle metadata placement, scheduler ownership, event semantics, permission boundaries, and relation to ClawHub/plugin APIs.
