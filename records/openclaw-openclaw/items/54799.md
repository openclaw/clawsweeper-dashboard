## Summary

Keep open for maintainer product and security review: current main and the latest release still do not support declarative scheduled/event SKILL.md trigger metadata, scheduler registration from skills, last-triggered skill status, or never-triggered audits. The request is useful, but it defines an autonomous execution contract rather than a narrow bug fix.

## What This Changes

Request declarative scheduled/event trigger metadata in SKILL.md frontmatter so skills can register cron/event triggers, expose last-triggered state, and support never-triggered audits.

## Best Possible Solution

Define a maintainer-approved skill trigger contract, permission/provenance model, and integration with existing cron/hook APIs first, then implement parser/types, scheduler/event registration, status/audit output, docs, and focused tests together.

## Reproduction Assessment

Yes. Source inspection of current main and v2026.6.11 shows skill parsing, prompt rendering, skills list/status output, cron contracts, and public docs omit scheduled/event SKILL.md trigger metadata and last-triggered/audit state.

## Solution Assessment

Unclear until maintainers choose the contract. A declarative trigger field is plausible, but the best solution must settle metadata placement, scheduler ownership, event semantics, permission boundaries, and relationship to ClawHub/plugin APIs.
