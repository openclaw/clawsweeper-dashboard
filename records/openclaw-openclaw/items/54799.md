## Summary

Keep open for maintainer product and security review: current main and v2026.6.11 still do not define scheduled/event SKILL.md trigger metadata, automatic cron registration from skill frontmatter, or skill-level last-triggered audit output. The operator comment adds useful evidence that manual cron scheduling is painful, but the requested behavior would become a public autonomous-execution contract rather than a narrow bug fix.

## What This Changes

Request to add optional SKILL.md trigger metadata for scheduled and event-driven skills, with cron registration, lifecycle event triggering, last-triggered CLI output, and audit support.

## Best Possible Solution

Define a permissioned automation contract first, then implement one coordinated path for metadata parsing, scheduler registration, event/audit state, CLI/docs output, and focused regression tests.

- **Start With Documentation-Only Metadata:** Allow a non-executable trigger_description or audit hint first, while deferring automatic cron/event registration until the security boundary is settled.
