## Summary

The process-identity-first liveness change addresses a real current-main startup race, but the new UUID release fence is not successor-safe because its ownership read and unlink are separate operations. The PR should remain open for that bounded correctness repair and contributor-owned real concurrency proof.

## What This Changes

The PR makes verified Gateway process identity authoritative over temporary port availability, preserves stale unknown-owner recovery, and adds UUID-tagged lock release fencing.

## Best Possible Solution

Keep the process-identity-first classification, but use an established cross-platform lock primitive or generation-removal design with no read-then-unlink replacement window, then prove startup and handoff with two real Gateway processes.
