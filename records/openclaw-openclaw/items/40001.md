## Summary

Keep this issue open: current main and the latest release still expose ordinary `write` as overwrite-only, while the active append-mode fix remains open and needs maintainer API-shape review.

## What This Changes

The issue requests a first-class append-capable write path so isolated cron and ordinary agent sessions do not truncate shared memory or workspace files when they intend to accumulate content.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/77127, or replace it with an equally narrow append-capable write contract that preserves overwrite defaults, workspace/sandbox guards, and queued file mutation behavior.
