## Summary

Keep this issue open: current main and v2026.6.11 still expose ordinary `write` as overwrite-only, while https://github.com/openclaw/openclaw/pull/77127 is the open unmerged implementation candidate for the reported data-loss class.

Add a safe append-capable file write primitive for ordinary agent and cron writes so shared memory/workspace files are not truncated by overwrite-only `write` calls.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/77127, or replace it with an equally narrow append-capable write contract that preserves overwrite defaults plus workspace and sandbox guards.
