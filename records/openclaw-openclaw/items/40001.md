## Summary

Keep this issue open: current main and the latest release still expose ordinary `write` as create-or-overwrite only, while the memory-flush append wrapper is scoped to memory-triggered runs and does not cover isolated cron or ordinary agent writes. The linked open pull request is the active candidate fix, but the remaining choice is maintainer API direction rather than cleanup closure.

## What This Changes

Request a first-class append-capable file write primitive so cron and ordinary agent sessions can append to shared workspace or memory files without truncating existing content.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/77127 or an equivalent narrow append-capable write primitive after maintainer API sign-off, preserving default overwrite behavior plus workspace, sandbox, and session-state guards.
