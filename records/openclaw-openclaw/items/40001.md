## Summary

Keep this issue open: current main and v2026.6.11 still expose ordinary `write` as overwrite-only, while the linked append-mode PR is open/unmerged and needs maintainer API-shape review.

## What This Changes

The issue requests a first-class append-safe path for the agent `write` tool so isolated cron and ordinary sessions cannot silently truncate shared workspace memory files.

## Best Possible Solution

Review and land the open append-mode PR, or replace it with an equally narrow append-capable write contract that preserves overwrite defaults, workspace/sandbox guards, and queued file mutation behavior.
