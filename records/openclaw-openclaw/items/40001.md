## Summary

Keep this issue open: current main and v2026.6.11 still expose ordinary `write` as overwrite-only, and the open linked implementation candidate has not merged, so the central data-loss risk remains.

## What This Changes

Request to add a safe append-capable write primitive for ordinary agent and cron file writes so shared memory/workspace files are not truncated by overwrite-only `write`.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/77127, or replace it with an equally narrow append-capable write contract that preserves overwrite defaults, workspace/sandbox guards, and queued file mutation behavior.

Yes as a product direction, but not as completed work. A first-class append primitive at the shared write-tool boundary is the maintainable fix because prompt-only guards and read-concatenate-overwrite flows are racy; the exact API shape still needs maintainer acceptance.
