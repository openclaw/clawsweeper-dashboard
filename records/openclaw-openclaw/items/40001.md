## Summary

Keep this issue open: current main and the latest release still expose ordinary `write` as overwrite-only, and the active open implementation path is https://github.com/openclaw/openclaw/pull/77127 rather than a reason to close before merge.

## What This Changes

The issue requests first-class append semantics for the agent `write` tool so cron and general agent sessions can add to shared memory/workspace files without destructive overwrites.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/77127, or replace it with an equally narrow append-capable write contract that preserves overwrite defaults and workspace/sandbox guards.

## Reproduction Assessment

Yes. Current main is source-reproducible: ordinary `write` accepts only `path` and `content`, calls `ops.writeFile`, and isolated cron uses `trigger: "cron"` rather than the memory-only append wrapper.

## Solution Assessment

Yes as a direction, but not as completed work. A first-class append mode is the maintainable boundary because prompt-only guards and read-concatenate-overwrite flows are racy; the linked PR should be reviewed, landed, or explicitly replaced.
