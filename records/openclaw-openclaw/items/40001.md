## Summary

Keep this open: current main and v2026.6.11 still expose ordinary `write` as overwrite-only, while the linked append-mode PR is open, unmerged, and currently needs maintainer API-shape review/refresh before it can close the data-loss report.

## What This Changes

The issue requests a first-class append-safe file write primitive, or equivalent write-tool append mode, to prevent isolated cron and ordinary agent sessions from truncating shared workspace files.

## Best Possible Solution

Revise or land the linked append-mode PR so ordinary agent and cron writes get a first-class append path that preserves existing path-policy guards and keeps overwrite behavior explicit by default.
