## Summary

Keep this issue open: current main and the latest release still expose ordinary `write` as create/overwrite only, the append-only path is limited to memory-flush runs, and the linked append-mode PR is open, unmerged, and currently conflicting.

## What This Changes

Request a safe append-capable write primitive for ordinary agent and cron file writes to prevent shared memory/workspace files from being overwritten.

## Best Possible Solution

Land the linked PR or an equivalent narrow append-capable write contract that preserves default overwrite behavior plus workspace, sandbox, and session-state guards.
