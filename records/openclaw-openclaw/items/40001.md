## Summary

Keep this issue open: current main and the latest release still expose ordinary `write` as overwrite-only, the existing append wrapper is limited to memory-flush runs, and the linked append-mode PR is open but not merged and currently needs maintainer API-shape review.

## What This Changes

The issue requests a first-class append-safe write path so isolated cron or ordinary agent sessions do not overwrite shared memory files when they intend to append.

## Best Possible Solution

Resolve and land https://github.com/openclaw/openclaw/pull/77127, or replace it with an equally narrow append-capable write contract that preserves overwrite defaults plus workspace, sandbox, and session guards.
