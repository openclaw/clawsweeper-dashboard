## Summary

Keep this issue open: current main and the latest release still expose ordinary `write` as create-or-overwrite only, and the open linked append-mode pull request is the active but unmerged implementation candidate.

## What This Changes

The issue requests a safe append capability for agent file writes so isolated cron or normal sessions do not silently overwrite shared memory/workspace files.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/77127, or replace it with an equally narrow append-capable write contract that preserves overwrite defaults, workspace/sandbox guards, and queued mutation behavior.

## Reproduction Assessment

Yes. Current main is source-reproducible because ordinary `write` accepts only `path` and `content`, calls `ops.writeFile`, and the append-only wrapper is scoped to memory-triggered flush runs.

## Solution Assessment

Yes for the product direction, but the issue is not solved yet. A first-class append primitive at the shared write-tool boundary is the maintainable fix because prompt-only guards and read-concatenate-overwrite flows are racy; the exact API shape still needs maintainer acceptance.
