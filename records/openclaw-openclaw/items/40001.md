## Summary

Keep this issue open: current main and the latest release still expose ordinary `write` as an overwrite-only tool, while the only append-safe wrapper is scoped to memory-flush runs; the linked append-mode PR is open, conflicting, and still needs maintainer API-shape review.

## What This Changes

Add a safe append path for the `write` tool so isolated cron and ordinary agent sessions can append to shared workspace files without destructive overwrite.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/77127 with a backwards-compatible append primitive that preserves overwrite-by-default behavior, workspace/sandbox guards, per-file serialization, and focused regression coverage.
