## Summary

Keep this issue open: current main and the latest release still expose ordinary agent `write` as create-or-overwrite only, while the existing append-only wrapper is limited to memory-triggered flushes and does not cover isolated cron or normal agent writes. The linked open pull request is the active candidate fix, so the remaining question is maintainer API direction and PR review, not cleanup closure.

## What This Changes

The issue requests a first-class append path or equivalent file-safety protection so agent and cron writes to shared workspace files do not depend on destructive read-concatenate-overwrite behavior.

## Best Possible Solution

Land or explicitly redirect the linked append-mode candidate after maintainer review of the write-tool contract, preserving current overwrite defaults plus workspace, sandbox, and mutation-queue guards.
