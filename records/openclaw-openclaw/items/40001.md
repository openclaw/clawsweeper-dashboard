## Summary

Keep this issue open: current main and the latest release still expose ordinary `write` as overwrite-only, the existing append behavior is limited to memory-flush runs, and the open implementation candidate at https://github.com/openclaw/openclaw/pull/77127 has not merged yet.

## What This Changes

The issue requests a first-class append-capable write path so isolated cron and ordinary agent sessions cannot silently truncate shared memory or workspace files when they intend to append.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/77127, or replace it with an equally narrow append-capable write contract that preserves overwrite defaults plus workspace and sandbox guards.

## Reproduction Assessment

Yes. Current main is source-reproducible: ordinary `write` accepts only `path` and `content`, calls `ops.writeFile`, and isolated cron uses `trigger: "cron"` rather than the memory-only append wrapper.

## Solution Assessment

Yes as a product direction, but not as completed work. A first-class append primitive at the shared write-tool boundary is the maintainable fix because prompt-only guards and read-concatenate-overwrite flows are racy; the exact API shape still needs maintainer acceptance.
