## Summary

Keep this issue open: current main and the latest release still expose ordinary agent `write` as overwrite-only, while the append-capable fix path is an open, unmerged pull request that needs maintainer API-shape review.

## What This Changes

The issue requests a safe append-capable write primitive so isolated cron and ordinary agent sessions do not truncate shared memory/workspace files.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/77127, or replace it with an equally narrow append-capable write contract that preserves overwrite defaults plus workspace, sandbox, cancellation, and mutation-queue guards.

Yes. Current main is source-reproducible: ordinary `write` accepts only `path` and `content`, calls `writeFile`, and cron-triggered runs do not enter the memory-flush append-only wrapper.

## Solution Assessment

Yes as a direction, but not yet as completed work. A first-class append primitive at the shared write-tool boundary is the maintainable fix because prompt-only guards and read-concatenate-write flows are racy; the exact API shape still needs maintainer acceptance.
