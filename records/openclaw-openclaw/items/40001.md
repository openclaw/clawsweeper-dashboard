## Summary

Keep this issue open: current main and the latest release still expose ordinary `write` as overwrite-only, while the linked append-mode implementation remains open and unmerged.

## What This Changes

Add a first-class append path for ordinary agent `write` calls so cron and agent workflows can accumulate shared memory or workspace files without truncating existing content.

## Best Possible Solution

Review, refresh, and land https://github.com/openclaw/openclaw/pull/77127, or replace it with an equally narrow append-capable write contract that preserves default overwrite behavior plus workspace, sandbox, and session-state guards.

Yes. Current main is source-reproducible: ordinary `write` accepts only `path` and `content`, calls `ops.writeFile`, and cron runs use `trigger: "cron"` rather than the memory-only append wrapper.

## Solution Assessment

Yes as a direction, but not as completed work. A first-class append primitive at the shared write-tool boundary is the maintainable fix because prompt-only guards and read-concatenate-overwrite flows are racy; the exact API shape still needs maintainer acceptance.
