## Summary

Keep open. The original stale SQLite-handle path has an unmerged related repair proposal, but fresh field evidence dated July 25, 2026 describes a distinct remaining gateway configuration-snapshot failure: CLI indexing uses changed memory settings while the already-running agent tool still evaluates the boot-time scope. That behavior needs a maintainer decision on reload versus explicit restart semantics before a new overlapping fix is attempted.

## What This Changes

The issue requests that the agent-facing `memory_search` tool stop retaining stale memory-index identity after a successful rebuild or a persisted memory-search configuration change.

## System Context

The bundled memory-core extension provides the agent-facing memory search tool through a long-lived gateway manager. CLI commands can rebuild and inspect the SQLite index using current configuration, while the gateway manager must reconcile its cached settings and database state before returning search results.

## Best Possible Solution

Define one supported long-running-gateway contract for changed memory-search settings: either refresh or evict the scoped manager through the canonical configuration lifecycle, or explicitly report that a gateway restart is required; then make the agent-facing remediation preserve classified provider/indexing failures instead of always recommending another reindex.

- **Narrow diagnostic only:** First surface the stale settings fingerprint and provider failure clearly, then defer reload behavior until the wider gateway configuration policy is settled.
