## Summary

Keep open: current main still has the reported source-level hydration gap, and the related owner-qualified lookup issues produce the same badge through a distinct backend failure rather than superseding this UI bug.

## What This Changes

Hydrate clean ClawHub security verdicts during the Skills page’s initial route load instead of rendering an empty verdict cache as Unavailable.

## Best Possible Solution

Make the initial Skills bootstrap explicitly complete by loading both the status report and verdict state for the same agent, retaining a guarded page-level verdict fallback for reconnects and showing distinct loading, fetch-error, and post-fetch-missing states.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: route-provided status data causes the page to skip the only path that populates verdicts, and the view deterministically maps the resulting missing entry to Unavailable. The report also includes live Gateway output and a same-instance manual hydration that changes the badge to Clean.

## Solution Assessment

Yes in direction, although the best implementation should hydrate verdicts without repeating the full status request. The transient `connected=false` observation should remain a test case rather than prompting removal of connection-lifecycle guards without separate proof.
