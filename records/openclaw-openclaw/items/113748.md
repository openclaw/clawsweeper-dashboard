## Summary

Current `main` appears to have retired the QMD file-lock path that this report describes: QMD updates no longer reference `qmd-write.lock.lock`, and the current QMD documentation says coordination uses SQLite leases instead. The reported v2026.7.1 deployment may still need an upgrade/restart or Doctor guidance, but I could not establish the exact fixing commit and first release with the required provenance, so this issue should remain open for a maintainer to confirm that upgrade boundary before cleanup.

## What This Changes

Fix a QMD session-export and index-update stall caused by a zero-byte orphaned `qmd-write.lock.lock` file surviving a process crash and restart.

## System Context

The QMD memory backend exports eligible agent-session turns into Markdown, then updates QMD collections used by memory search. Its write coordination determines whether transcript exports, collection changes, and embedding updates can safely proceed after gateway lifecycle events.

## Best Possible Solution

Confirm the first release containing SQLite-backed QMD write coordination, then direct affected users to upgrade, stop all gateways sharing the state directory, restart on the new version, and run the existing Doctor cleanup path rather than adding an mtime-based reclaim rule to the generic lock helper.
