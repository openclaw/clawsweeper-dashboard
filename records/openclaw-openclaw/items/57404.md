## Summary

Keep open: current main and v2026.6.11 still expose token usage through RPC/session/message surfaces rather than a passive Gateway WebSocket lifecycle or run-usage event, while two third-party client comments describe active demand and polling workarounds.

## What This Changes

The issue requests per-run token, cost, provider, and model usage data on the Gateway WebSocket lifecycle/run event stream without requiring clients to poll usage RPCs.

## Best Possible Solution

Keep this issue as the canonical product/API decision until maintainers select a documented additive event shape and land coverage across the relevant agent run paths.
