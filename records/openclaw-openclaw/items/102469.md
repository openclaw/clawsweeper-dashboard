## Summary

Keep open: the remaining blocker is real, because the PR drops fenced code contents even though the Telegram cache text can retain the rendered code body, so fenced-code replies can still miss the session/cache dedupe match.

## What This Changes

The PR applies `stripMarkdown` to Telegram prompt-context dedupe and timestamp matching, exports the dedupe helper for tests, adds focused dedupe tests, and changes `stripMarkdown` to remove fenced code blocks.

## Best Possible Solution

Normalize fenced Markdown by removing only fence delimiters and optional language markers while preserving inner code text, keeping the timestamp-qualified dedupe boundary and adding transcript-vs-cache regression coverage.
