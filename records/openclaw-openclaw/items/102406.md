## Summary

Keep this draft open. It is an experimental, stacked core feature with unresolved P1 security-boundary defects: a manifest can still contribute an unbrokered stdio command to global MCP configuration, and exact global-name reuse is accepted without an explicit host authorization boundary. The newest branch fixes earlier source-placeholder, pending-write, schema, and dry-run disclosure concerns, but it does not provide real after-fix CLI/config/process evidence and remains protected by the `maintainer` label.

## What This Changes

The branch adds experimental Claw ownership, lifecycle state, status/export, reconciliation, and cleanup for MCP server declarations stored in OpenClaw source configuration.

## Best Possible Solution

Keep the feature gated and draft until the RFC/owners choose one canonical global-MCP authority, then require a brokered or allowlisted stdio execution path, explicit host authorization for sharing, and redacted end-to-end proof of add, status, export, drift, recovery, and remove behavior.
