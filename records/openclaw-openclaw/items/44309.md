## Summary

Keep open: current main still exposes `sessions_send` as conversation-style A2A delivery with reply-back and announce behavior, while this issue asks for a first-class one-way dispatch semantic. The linked reverse-call PR is narrower and explicitly leaves result delivery unchanged.

## What This Changes

The issue requests a first-class one-way A2A dispatch or handoff mode for `sessions_send` so target-session delivery does not trigger reply-back ping-pong or requester announce behavior.

## Best Possible Solution

Define a first-class per-send dispatch contract that persists the target-session message and can return an optional delivery acknowledgement without starting reply-back or announce, while preserving current conversation mode as the default.

Rationale: The requested behavior is still missing, but it changes model-facing session semantics and compatibility for existing A2A workflows, so automation should not choose the permanent API shape.

Likely owner: steipete

Owner confidence: high

Options:

- **Add Explicit Dispatch Mode (recommended):** Extend `sessions_send` with a clearly named one-way mode that keeps current conversation behavior as the default and adds docs/tests for both modes.
- **Create Separate Primitive:** Add a `sessions_deliver` or `sessions_enqueue` style tool so one-way dispatch cannot be confused with conversational `sessions_send`.
- **Defer Dispatch Semantics:** Keep the current conversation lifecycle and handle narrower duplicate-delivery bugs such as the open reverse-call fix separately.

## Reproduction Assessment

Yes at source level: current peer `sessions_send` still has no dispatch parameter and still starts the A2A reply/announce flow for ordinary peer sends. I did not run a live multi-agent replay in this read-only cleanup pass.

## Solution Assessment

Unclear as an implementation until maintainers choose the API shape. First-class framework semantics are the right boundary, but `mode`, separate primitive, and flag-based designs have different compatibility tradeoffs.
