## Summary

Keep open: current main still exposes `sessions_send` as the existing A2A conversation lifecycle, with a global ping-pong limit and narrow parent/cron skips, but no explicit one-way dispatch mode that suppresses requester reply-back and target announce.

## What This Changes

The issue requests dispatch-only A2A handoff semantics for `sessions_send` or a new primitive that persists work into the target session without reply-back ping-pong or announce.

## Best Possible Solution

Add a maintainer-approved explicit dispatch/delivery semantic at the core session-tool boundary, preserving today’s conversation default while allowing one-way handoff with focused tests, docs, and live multi-agent proof.

- **Defer to narrower guard fixes:** Keep this issue as design context while landing reverse-call, cycle, and acknowledgement fixes separately without adding a dispatch mode yet.

## Reproduction Assessment

Yes, at source level: current main has no dispatch parameter and still schedules the A2A reply/announce lifecycle for ordinary `sessions_send` calls. I did not run a live webchat multi-agent replay in this read-only review.

## Solution Assessment

Unclear until maintainers choose the API shape. A first-class dispatch semantic is the right solution class, but the existing global `maxPingPongTurns=0` knob is not a complete per-call no-announce handoff solution.
