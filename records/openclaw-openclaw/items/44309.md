## Label Justifications

- `P2`: This is a real multi-agent workflow gap with transcript pollution and duplicate/misrouted message risk, but it requires product/API direction rather than urgent regression repair.
- `impact:session-state`: The reported behavior pollutes requester transcripts and changes which session owns follow-up turns during A2A handoffs.
- `impact:message-loss`: The current A2A lifecycle can duplicate, misroute, or suppress expected handoff messages through reply-back and announce paths.

## Summary

Keep open: current main still has only conversation-oriented `sessions_send` semantics, with a global ping-pong limit and a target announce step, while this issue asks for a per-call one-way dispatch/handoff semantic. Related open work addresses reverse-calls, duplicate message-tool replies, and handoff acknowledgements, but none is a merged or canonical replacement for the requested dispatch mode.

## What This Changes

Request an explicit one-way A2A dispatch mode for `sessions_send` or a new primitive that delivers into the target session without requester reply-back ping-pong or announce.

## Best Possible Solution

Add a backward-compatible per-call dispatch path that enqueues the target turn and returns a structured delivery acknowledgement while skipping requester reinjection and target announce by default, leaving the current conversation mode as the default behavior.
