## Summary

Keep open: current main still exposes `sessions_send` as conversation-style A2A delivery and has no first-class per-send dispatch mode. The open reverse-call PR and related issues are narrower; this issue still needs maintainer product/API direction.

## What This Changes

The issue requests a one-way A2A dispatch or handoff mode that persists work into the target session without reply-back ping-pong or requester announce behavior.

## Best Possible Solution

Define a first-class per-send dispatch contract that preserves current conversation mode by default and adds focused docs/tests for dispatch, optional acknowledgement, reply-back suppression, and announce suppression.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should one-way A2A handoff be added as a `sessions_send` dispatch mode, as a separate one-way primitive, or deferred while only narrower ping-pong/reverse-call bugs are fixed?

Rationale: The requested behavior is still missing, but it changes model-facing session semantics and compatibility for existing A2A workflows, so automation should not choose the permanent API shape.

Likely owner: steipete

Owner reason: steipete has the strongest feature-history signal across the central sessions_send tool and A2A behavior surface.

Owner confidence: high

Options:

- **Add explicit dispatch mode (recommended):** Extend `sessions_send` with a clearly named one-way mode that keeps current conversation behavior as the default and documents/tests both modes.
- **Create a separate primitive:** Add a `sessions_deliver` or `sessions_enqueue` style tool so one-way handoff cannot be confused with conversational `sessions_send`.
- **Defer dispatch semantics:** Keep the current conversation lifecycle and continue handling narrower reverse-call, loop, and announce issues separately.

## Reproduction Assessment

Yes, source-level: current main has no dispatch parameter and still starts reply-back/announce follow-up for ordinary peer sends. I did not run a live multi-agent replay in this read-only review.

## Solution Assessment

Unclear as an implementation until maintainers choose the API shape. First-class framework semantics are the right boundary, but `mode`, separate primitive, and flag-based designs carry different compatibility tradeoffs.
