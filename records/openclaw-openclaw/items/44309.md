## Summary

Keep open: current main and v2026.6.11 still expose ordinary peer `sessions_send` as conversation-style A2A delivery with bounded reply-back turns plus announce, while this issue asks for a first-class one-way dispatch/handoff contract. The linked reverse-call work overlaps duplicate-message symptoms but does not supersede the broader dispatch-mode API decision.

## What This Changes

The issue requests an explicit one-way A2A dispatch/handoff mode for `sessions_send` or a new primitive that persists work into a target session without reply-back reinjection or announce-back behavior.

## Best Possible Solution

Keep this open for maintainer API direction, then implement an additive dispatch path that writes the target-session message and returns optional delivery acknowledgement without starting reply-back or announce, while preserving current conversation mode by default.

- **Fold into broader handoff protocol work:** Defer this issue until a canonical A2A handoff contract covers dispatch, structured skip, announce routing, and cron session output together.

## Solution Assessment

Yes as product direction, but not yet as an implementation: a first-class dispatch contract is more maintainable than prompt conventions or `timeoutSeconds: 0`. The exact API shape still needs maintainer choice.
