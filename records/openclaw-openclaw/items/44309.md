## Summary

Keep open: current main and v2026.6.11 still expose ordinary peer `sessions_send` as conversation-style A2A delivery with bounded reply-back turns plus announce, while this issue asks for a first-class one-way dispatch/handoff contract. The linked reverse-call work overlaps duplicate-message symptoms but does not supersede the broader dispatch-mode API decision.

## What This Changes

Add an explicit one-way dispatch mode or primitive for A2A `sessions_send` handoffs that writes to the target session without reply-back ping-pong or requester announce.

## Best Possible Solution

Keep this open for maintainer API direction, then implement a narrow first-class dispatch path that persists the target-session message and returns optional delivery acknowledgement without starting reply-back or announce, while preserving the existing conversation mode.

## Reproduction Assessment

Yes at source level: current peer `sessions_send` still has no dispatch parameter and still starts the A2A reply/announce flow for ordinary peer sends. I did not run a live multi-agent replay in this read-only cleanup pass.

## Solution Assessment

Yes as product direction, but not yet as an implementation: first-class framework semantics are more maintainable than prompt conventions or `timeoutSeconds: 0`. The exact API shape still needs maintainer choice.
