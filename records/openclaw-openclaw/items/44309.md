## Summary

Keep open: current main and the latest release still lack a first-class one-way A2A dispatch mode, and related open work only covers narrower duplicate-delivery, reverse-call, or acknowledgement subproblems.

## What This Changes

Issue requests a dispatch-only A2A handoff mode that sends work to a target session without reply-back ping-pong or announce back to the requester.

## Best Possible Solution

Define an explicit per-send dispatch contract that persists the target-session message and can return an optional acknowledgement without starting reply-back or announce, while preserving current conversation mode as the default.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add one-way A2A handoff as a sessions_send mode, a separate one-way primitive, or defer that semantic while only fixing narrower duplicate-delivery bugs?

Rationale: The requested behavior is still missing, but it changes model-facing session-tool semantics and compatibility for existing A2A workflows, so automation should not choose the permanent API shape.

Likely owner: Peter Steinberger

Owner reason: Peter has the strongest feature-history signal for the sessions_send A2A lifecycle and its model-facing docs/API surface.

Owner confidence: high

Options:

- **Add Explicit Dispatch Mode (recommended):** Extend sessions_send with a clearly named one-way mode, keep current conversation behavior as the default, and add docs/tests for both modes.
- **Create Separate Primitive:** Add a sessions_deliver or sessions_enqueue style tool so one-way dispatch cannot be confused with conversational sessions_send.
- **Defer Dispatch Semantics:** Keep the current conversation lifecycle and handle narrower duplicate-delivery bugs such as reverse-call and message-mirror fixes separately.

## Reproduction Assessment

Yes at source level: current sessions_send has no dispatch parameter and still starts reply/announce follow-up for ordinary peer sends; no live multi-agent replay was run in this read-only review.

## Solution Assessment

Unclear until maintainers choose the API shape; first-class framework semantics are the right boundary, but a mode, a separate primitive, and flags carry different compatibility tradeoffs.
