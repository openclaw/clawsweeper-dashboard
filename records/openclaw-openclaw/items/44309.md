## Summary

Keep open: current main still exposes only the normal `sessions_send` conversation lifecycle plus a global ping-pong limit and narrow parent/cron skips, not a per-call dispatch-only handoff semantic. The related open PRs address reverse-calls, cycles, or acknowledgements, but none is a merged canonical implementation of the requested one-way mode.

## What This Changes

The issue requests a first-class one-way dispatch mode for `sessions_send`/A2A handoffs that persists work into a target session without requester reply-back reinjection or announce behavior.

## Best Possible Solution

Add a maintainer-approved per-call dispatch/delivery semantic in the core session tool boundary, preserving today’s conversation/announce default while allowing explicit one-way handoff with focused tests and live multi-agent proof.
