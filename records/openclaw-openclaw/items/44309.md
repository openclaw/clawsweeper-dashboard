## Summary

Keep open: current main and v2026.6.11 still expose `sessions_send` only as send-and-optionally-wait plus the existing A2A reply-back/announce lifecycle, so the requested dispatch-only handoff semantic is not implemented and still needs maintainer API direction.

## What This Changes

The issue requests a first-class one-way A2A dispatch mode for `sessions_send` so controller agents can hand work to a target session without reply-back or announce ping-pong.

## Best Possible Solution

Define an additive, maintainer-approved A2A handoff contract that preserves today's conversation mode by default while providing explicit dispatch-only delivery with regression coverage for no requester reinjection and no announce step.
