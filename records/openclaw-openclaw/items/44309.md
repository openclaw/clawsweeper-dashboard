## Summary

Keep open: current main and the latest release still expose `sessions_send` as conversation-style A2A delivery with reply-back and announce behavior, while this issue asks for an explicit one-way dispatch contract. The strongest related PRs address narrower reverse-call, mirror-duplicate, or acknowledgement subproblems, not the requested no-reply-back/no-announce handoff semantic.

## What This Changes

Add an explicit one-way A2A dispatch or handoff mode that persists a task into the target session without reply-back ping-pong or automatic announce back to the requester.

## Best Possible Solution

Define an explicit per-send dispatch contract that persists the target-session message and can return an optional delivery acknowledgement without starting reply-back or announce, while preserving current conversation mode as the default.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add one-way A2A handoff as a `sessions_send` mode, a separate one-way primitive, or defer that semantic while only fixing narrower reverse-call and duplicate-delivery bugs?

Rationale: The requested behavior is still missing, but it changes model-facing session-tool semantics and compatibility for existing A2A workflows, so automation should not choose the permanent API shape.

Likely owner: steipete

Owner reason: steipete has the strongest feature-history and current API/docs signal for the `sessions_send` and A2A behavior surface.

Owner confidence: high

Options:

- **Add Explicit Dispatch Mode (recommended):** Extend `sessions_send` with a clearly named one-way mode that keeps current conversation behavior as the default and adds docs/tests for both modes.
- **Create Separate Primitive:** Add a `sessions_deliver` or `sessions_enqueue` style tool so one-way dispatch cannot be confused with conversational `sessions_send`.
- **Defer Dispatch Semantics:** Keep the current conversation lifecycle and handle narrower duplicate-delivery bugs such as the open reverse-call and message-mirror fixes separately.

## Reproduction Assessment

Yes at source level: current `sessions_send` still has no dispatch parameter and still starts the A2A reply/announce flow for ordinary peer sends. I did not run a live multi-agent replay in this read-only cleanup pass.

## Solution Assessment

Unclear until maintainers choose the API shape. First-class framework semantics are the right boundary, but a mode, a separate primitive, and flag-based designs have different compatibility tradeoffs.
