## Summary

Keep open: current main and v2026.6.11 still implement `sessions_send` as conversation-style A2A delivery, while this issue asks for first-class one-way dispatch semantics. The open reverse-call fix at https://github.com/openclaw/openclaw/pull/91161 overlaps the duplicate-message symptom but does not replace the broader dispatch-mode product/API decision.

## What This Changes

The issue requests a dispatch-only mode for agent-to-agent session handoffs so the target session receives work without reply-back or announce behavior.

## Best Possible Solution

Define a first-class per-send dispatch contract that persists the target-session message and can return an optional delivery acknowledgement without starting reply-back or announce, while preserving existing conversation mode as the default.

Rationale: Source inspection proves the requested behavior is missing, but the fix changes model-facing session semantics and compatibility for existing A2A workflows, so automation should not choose the permanent API shape.

Owner confidence: high

Options:

- **Add explicit dispatch mode (recommended):** Extend `sessions_send` with a clearly named one-way mode that keeps current conversation behavior as the default and adds docs/tests for both modes.
- **Create a separate primitive:** Add a `sessions_deliver` or `sessions_enqueue` style tool so dispatch cannot be confused with conversational `sessions_send`, accepting the cost of another model-facing tool.
- **Defer dispatch semantics:** Keep only the current conversation lifecycle for now and handle narrower duplicate-delivery bugs such as the open reverse-call fix separately.

## Reproduction Assessment

Yes at source level: current `sessions_send` has no dispatch parameter and still starts the A2A reply/announce flow for ordinary peer sends. I did not run a live multi-agent replay in this read-only pass.

## Solution Assessment

Unclear as an implementation until maintainers choose the API shape. First-class framework semantics are the right boundary, but `mode`, separate primitive, and flag-based designs have different compatibility tradeoffs.
