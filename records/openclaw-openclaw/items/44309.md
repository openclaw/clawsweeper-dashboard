## Summary

Keep open: current main and the latest release still expose `sessions_send` as conversation-style A2A delivery with optional reply-back turns and a target-side announce step, while this issue asks for a first-class one-way dispatch semantic. The open reverse-call PR is narrower and does not replace the requested dispatch-only mode.

## What This Changes

The issue requests an explicit one-way A2A `sessions_send` dispatch or equivalent primitive that persists work into the target session without reply-back ping-pong or announce delivery.

## Best Possible Solution

Define a first-class per-send dispatch contract that persists the target-session message and can return an optional delivery acknowledgement without starting reply-back or announce, while preserving current conversation mode as the default.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add one-way A2A handoff as a `sessions_send` mode, a separate one-way primitive, or defer that semantic while only fixing narrower reverse-call and ping-pong bugs?

Rationale: The requested behavior is still missing, but it changes model-facing session semantics and compatibility for existing A2A workflows, so automation should not choose the permanent API shape.

Likely owner: steipete

Owner reason: steipete has the strongest feature-history signal across the central sessions_send tool and A2A behavior surface.

Owner confidence: high

Options:

- **Add explicit dispatch mode (recommended):** Extend `sessions_send` with a clearly named one-way mode that keeps current conversation behavior as the default and adds docs/tests for both modes.
- **Create separate primitive:** Add a `sessions_deliver` or `sessions_enqueue` style tool so one-way dispatch cannot be confused with conversational `sessions_send`.
- **Defer dispatch semantics:** Keep the current conversation lifecycle and handle narrower duplicate-delivery bugs such as the open reverse-call fix separately.

## Reproduction Assessment

Yes, source-level: current main has no dispatch parameter and still starts the A2A reply/announce flow for ordinary peer sends. I did not run a live multi-agent replay in this read-only cleanup pass.

## Solution Assessment

Unclear as an implementation until maintainers choose the API shape. First-class framework semantics are the right boundary, but `mode`, separate primitive, and flag-based designs carry different compatibility tradeoffs.
