## Summary

Keep open: current main and the latest release still expose ordinary peer `sessions_send` as conversation-style A2A delivery with reply-back turns plus announce, while this issue asks for a first-class one-way dispatch/handoff contract.

## What This Changes

Request an explicit one-way A2A dispatch mode for `sessions_send` or a new delivery primitive that persists work in the target session without reply-back ping-pong or requester announce.

## Best Possible Solution

Define a narrow model-facing dispatch contract that persists the target-session message and returns optional delivery acknowledgement without starting reply-back or announce, while preserving the existing conversation mode.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Which first-class A2A API shape should OpenClaw support for one-way dispatch without reply-back or announce?

Rationale: The source-level gap is clear, but adding or changing model-facing session semantics affects compatibility, docs, tests, and existing peer coordination workflows.

Likely owner: steipete

Owner reason: The current A2A/session-send behavior and recent split files are most strongly tied to this history trail.

Owner confidence: high

Options:

- **Add explicit dispatch mode (recommended):** Add a per-call `sessions_send` mode such as `mode: "dispatch"` that keeps the existing conversation behavior as the default.
- **Add a separate primitive:** Introduce a new `sessions_deliver` or `sessions_enqueue` tool with one-way semantics, avoiding overloading `sessions_send`.
- **Defer to global ping-pong config:** Leave `sessions_send` as conversation-only and document `agentToAgent.maxPingPongTurns=0`, accepting that it is not a per-send dispatch solution.

## Reproduction Assessment

Yes at source level: current peer `sessions_send` has no dispatch parameter and still starts the A2A reply/announce flow for ordinary peer sends. I did not run a live multi-agent replay in this read-only cleanup pass.

## Solution Assessment

Yes as product direction, but not yet as an implementation: first-class framework semantics are more maintainable than prompt conventions or `timeoutSeconds: 0`. The exact API shape still needs maintainer choice.
