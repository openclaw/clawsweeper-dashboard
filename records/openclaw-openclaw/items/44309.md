## Summary

Keep open: current main still treats ordinary peer `sessions_send` as conversation-style A2A delivery, with no per-send dispatch-only mode, and the open reverse-call fix only addresses a narrower duplicate-message vector.

## What This Changes

The issue requests a first-class one-way A2A handoff mode that persists a task into the target session without requester reply-back ping-pong or target announce behavior.

## Best Possible Solution

Define an explicit per-send dispatch contract that persists the target-session message and returns optional delivery acknowledgement without starting requester reply-back or target announce, while keeping the existing conversation mode as the default unless maintainers choose a broader migration.

## Maintainer Decision

Rationale: The source gap is clear, but the fix changes model-facing session semantics and could affect existing peer A2A coordination, so automation should not choose the permanent API shape.

Likely owner: steipete

Options:

- **Add explicit dispatch mode (recommended):** Extend `sessions_send` with a typed dispatch mode that disables reply-back and announce for that call while preserving current conversation behavior by default.
- **Create separate delivery primitive:** Add a new one-way tool such as `sessions_deliver` or `sessions_enqueue`, reducing ambiguity at the cost of another model-facing surface.
- **Defer one-way core API:** Keep this open or close by product decision after landing narrower reverse-call and delivery fixes, leaving dispatch workflows to prompt/config workarounds for now.

## Reproduction Assessment

Yes, at source level: current main has no dispatch parameter and still runs the A2A reply/announce flow for ordinary peer sends. I did not run a live multi-agent replay in this read-only cleanup pass.

## Solution Assessment

Unclear as an implementation until maintainers choose the API shape. First-class framework semantics are the right boundary, but `mode`, separate primitive, and flag-based designs have different compatibility tradeoffs.
