## Summary

Keep open: current main has partial mitigations for A2A loops, but it still lacks a first-class one-way `sessions_send` dispatch mode that persists into the target session without requester reinjection and announce semantics. The related reverse-call and cyclic-route PRs are narrower than this product/API request.

## What This Changes

The issue requests an explicit one-way A2A dispatch or handoff mode for `sessions_send` so work can be delivered into a target session without reply-back reinjection or announce behavior.

## Best Possible Solution

Define an additive, compatibility-preserving A2A handoff contract that keeps current `sessions_send` behavior as the default and adds an explicit dispatch-only path with focused tests for target persistence, no requester reinjection, no announce, and optional structured acknowledgement.
