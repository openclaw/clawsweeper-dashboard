## Label Justifications

- `P2`: This shipped bug silently changes affected scheduled-command configuration, but its blast radius is limited to cron requests containing malformed environment values.
- `impact:data-loss`: One non-string value causes every valid entry in the submitted command environment map to be discarded without warning.

## Summary

Current main and v2026.6.11 both silently discard a command job’s complete `env` map when any value is non-string, because normalization removes the field before gateway schema validation. No duplicate or open fix PR owns this concrete shipped bug, so it should remain open for a focused repair.

## What This Changes

Reject malformed cron command environment maps instead of silently deleting the entire `env` field before request validation.

## Best Possible Solution

Make a present malformed `env` map fail clearly at the shared cron normalization or validation boundary, preserve valid string maps byte-for-byte, and add create/update regression tests proving one invalid entry cannot silently remove valid siblings.
