## Summary

Keep open for maintainer scoping. Current main confirms bounded-retention and unsupervised post-timeout work concerns, but the proposal combines those with new configuration, plugin API cancellation, fallback behavior, and forced cleanup that alter deliberate shipped lifecycle contracts.

## What This Changes

Refactor gateway session shutdown tracking to reduce retained memory, configure drain timing, cancel overdue hooks, and clean session resources after stop timeouts.

## Best Possible Solution

Measure retained heap and hook-overrun behavior, then make a focused internal change that reduces captured tracker state and supervises late failures while preserving bounded concurrent finalization and retry-safe active-run cleanup; consider public timeout or cancellation APIs only as separately approved, additive contracts.

## Risks / Open Questions

- Reloading configuration during shutdown could produce a different hook context from the snapshot associated with session_start, while the proposed baseline fallback conflicts with the repository rule against steady-state runtime compatibility fallbacks.
- Force-disposing MCP or browser resources after the wait timeout could race an agent that is still executing and contradicts the tested retry-safe delete/reset contract.
- Adding a gateway timeout setting expands compatibility-sensitive configuration without measurements showing that the existing internal budget cannot meet realistic shutdown needs.
- AbortSignal support changes the public session_end plugin contract, and handlers that do not cooperate with cancellation would still continue after the gateway timeout.
