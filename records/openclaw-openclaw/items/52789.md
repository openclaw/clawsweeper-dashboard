- `impact:session-state`: The requested mode would inject scheduled output into another session and affects session context/provenance.

- `impact:message-loss`: The issue is about preventing cron output from being silently dropped when model-driven `sessions_send` calls omit required parameters.

## Summary

Close as duplicate: current main and v2026.6.11 still lack cron session delivery, but the open canonical cron output-routing issue explicitly covers session targets, while one-way A2A dispatch remains an adjacent design dependency.

## What This Changes

Request adds cron `delivery.mode="session"` so completed cron job output can be delivered internally to a target session via `sessions_send` instead of relying on visible channel delivery or model tool calls.

## Best Possible Solution

Keep the cron output-routing design centralized in https://github.com/openclaw/openclaw/issues/49078, with https://github.com/openclaw/openclaw/issues/44309 informing one-way A2A semantics before any standalone `delivery.mode="session"` contract is added.
