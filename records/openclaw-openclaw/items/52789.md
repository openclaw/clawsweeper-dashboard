## Label Justifications

- `P2`: This is a normal-priority multi-agent cron reliability feature with real user impact, but it needs product and security direction before implementation.
- `impact:session-state`: The requested mode would write cron output into another agent session and affect transcript/context routing semantics.
- `impact:security`: Invisible framework-owned cross-session delivery requires explicit authorization, visibility, and provenance decisions.
- `impact:message-loss`: The report says cron results can be silently dropped when models fail to call `sessions_send` correctly.

## Summary

Keep open: current main and the latest release still expose cron completion delivery as `none`, `announce`, or `webhook` only, while the requested internal session delivery mode remains a product and security-sensitive cron/A2A API decision.

## What This Changes

The issue requests a new cron delivery mode that routes completed cron output internally to a target session through `sessions_send` instead of visible channel announcement or model-authored tool calls.

## Best Possible Solution

Design a maintainer-approved cron-to-session output contract that composes with A2A dispatch, defines authorization and provenance, then update schema, runtime delivery, CLI/tool/docs surfaces, and focused tests together.

## Reproduction Assessment

No strict bug reproduction is required because this is a feature/config request. Source inspection gives high confidence the requested public mode is absent from cron types, parsing, protocol schema, runtime planning, docs, and the latest release.

## Solution Assessment

Unclear. Framework-owned session delivery is plausible, but maintainers still need to choose the permanent cron output API shape, A2A relationship, authorization, and transcript semantics before implementation.
