## Label Justifications

- `P2`: This is a normal-priority cron reliability and multi-agent workflow feature with meaningful power-user impact but no core runtime outage.
- `impact:session-state`: The request is about injecting cron output into another agent/session context as first-class session state.
- `impact:message-loss`: The report describes cron outputs being silently lost when prompt-driven `sessions_send` or `message` delivery fails.
- `impact:security`: Framework-owned invisible cross-session delivery needs authorization and audit boundaries before implementation.

## Summary

Close as duplicate/superseded: the requested cron-to-session delivery mode is still absent on current main, but the remaining product/API work is already covered by the broader open cron output-routing tracker, with the one-way A2A dispatch issue as the adjacent session-semantics dependency.

## What This Changes

The issue requests a new cron `delivery.mode: "session"` that delivers completed cron output internally to a target session instead of a visible channel or webhook.

## Best Possible Solution

Keep the remaining cron output-target API discussion on https://github.com/openclaw/openclaw/issues/49078 and let https://github.com/openclaw/openclaw/issues/44309 inform any one-way session dispatch semantics.

## Reproduction Assessment

Yes, at source level: current main exposes only `none`, `announce`, and `webhook` cron delivery modes in types, parser, protocol schema, planner, and docs. A live run is not needed to reproduce a missing feature contract.

## Solution Assessment

No, not as a standalone issue. The maintainable path is to handle this as the session-delivery subset of the broader cron output-routing contract, with one-way A2A dispatch semantics decided alongside it.
