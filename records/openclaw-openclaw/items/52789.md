## Summary

Keep open: current main and the latest release still expose cron completion delivery as `none`, `announce`, or `webhook` only, so the requested internal session delivery mode remains missing and needs maintainer product/security direction.

## What This Changes

Request to add cron `delivery.mode: "session"` so completed job output is routed internally to a target session by the framework instead of relying on visible delivery or model-issued tool calls.

## Best Possible Solution

Design one maintainer-approved cron-to-session output contract that shares the right A2A authorization/provenance semantics, then update schema, runtime delivery, docs, UI/tool surfaces, and focused tests together.

## Reproduction Assessment

Yes. Current main source and the latest release both show the public cron delivery contract has only `none`, `announce`, and `webhook`, so the requested mode is reproducibly absent without a live cron run.

## Solution Assessment

Unclear. Framework-owned session delivery is plausible, but maintainers still need to choose whether this belongs as a cron delivery mode, a broader output-target contract, or a reusable one-way A2A dispatch primitive.
