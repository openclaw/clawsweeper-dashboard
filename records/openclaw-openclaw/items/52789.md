## Label Justifications

- `P2`: The request is a normal-priority cron reliability and ergonomics feature with meaningful power-user impact but no emergency runtime outage.
- `impact:message-loss`: The motivating failure is cron output being missed when model-authored session delivery drops required parameters or fails.
- `impact:session-state`: The requested behavior would write cron job output into another agent session.
- `impact:security`: Invisible framework-owned cross-session delivery needs authorization, provenance, and audit boundaries before implementation.

## Summary

Close as duplicate/superseded: the remaining cron-to-session delivery need is already covered by the open broader cron output-target tracker, while the lower-level one-way A2A/session primitive is tracked separately.

## What This Changes

The issue requests a new cron delivery mode that sends completed job output internally to a target session instead of relying on visible channel delivery or model-authored `sessions_send` tool calls.

## Best Possible Solution

Use https://github.com/openclaw/openclaw/issues/49078 as the canonical cron output-routing design, and use https://github.com/openclaw/openclaw/issues/44309 for any needed one-way A2A dispatch primitive instead of keeping this parallel session-only tracker open.

## Reproduction Assessment

Yes for the feature gap at source level: current main and v2026.6.11 expose only `none`, `announce`, and `webhook` cron delivery modes. This is not a broken existing-behavior bug reproduction; it is a request for a new cron output/session delivery contract.

## Solution Assessment

No as a separate tracker: a one-off `delivery.mode="session"` issue is narrower than the maintainable solution. The better path is the broader cron output-target contract in https://github.com/openclaw/openclaw/issues/49078, with one-way A2A semantics coordinated through https://github.com/openclaw/openclaw/issues/44309 if needed.
