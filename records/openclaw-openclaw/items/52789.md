## Label Justifications

- `P2`: This is a normal-priority cron reliability and multi-agent workflow feature with limited blast radius but clear power-user impact.
- `impact:session-state`: The request is about injecting scheduled output into another agent/session context without visible chat delivery.
- `impact:message-loss`: The motivating failure mode is cron output silently not reaching the intended internal recipient when model-driven tool calls are malformed.
- `impact:security`: Framework-owned hidden cross-session delivery from scheduled jobs needs explicit authorization, provenance, and audit semantics.

## Summary

Close as duplicate/superseded: the requested cron-to-session delivery mode is still missing, but the remaining product/API/security work is already owned by the broader open cron output-routing tracker, with the one-way A2A dispatch issue as the adjacent session-semantics dependency.

## What This Changes

Request to add a `delivery.mode: "session"` cron delivery mode that sends completed cron output internally to a target session via `sessions_send`.

## Best Possible Solution

Use https://github.com/openclaw/openclaw/issues/49078 as the canonical cron output-target design, with https://github.com/openclaw/openclaw/issues/44309 informing one-way session dispatch semantics.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 exclude `session` from cron delivery types, parsing, protocol schema, runtime planning, and docs.

## Solution Assessment

No, not as a standalone tracker. The safer path is to handle this as the session-target subset of the broader cron output-routing contract, while the A2A dispatch issue defines the one-way session semantics.
