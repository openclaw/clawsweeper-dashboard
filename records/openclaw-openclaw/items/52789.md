## Label Justifications

- `P2`: This is a normal-priority cron/session routing feature with meaningful multi-agent reliability impact but no emergency core runtime outage.
- `impact:message-loss`: The report says cron results can be silently dropped when models fail to call `sessions_send` correctly.
- `impact:session-state`: The requested mode would inject cron output into another agent session and affect transcript/context routing semantics.
- `impact:security`: Invisible framework-owned cross-session delivery requires explicit authorization, provenance, and audit semantics.

## Summary

Close as superseded: the requested cron-to-session delivery mode is still not implemented, but the remaining product/API/security work is now owned by the broader open cron output-routing tracker, with the A2A dispatch semantics tracked separately.

## What This Changes

The issue requests a new cron delivery mode that sends completed job output into an internal session via `sessions_send` rather than visible channels or model-authored tool calls.

## Best Possible Solution

Follow https://github.com/openclaw/openclaw/issues/49078 for the cron output-target contract and https://github.com/openclaw/openclaw/issues/44309 for one-way A2A dispatch semantics; keep this narrower context linked there instead of tracking a separate core issue.

## Reproduction Assessment

Yes, at source level. Current main still exposes cron completion delivery as `none`, `announce`, or `webhook` in types, parser, protocol schema, docs, and tool description.

## Solution Assessment

No as a standalone tracker. The maintainable path is to resolve the broader cron output-target API in https://github.com/openclaw/openclaw/issues/49078 and compose it with the A2A dispatch decision in https://github.com/openclaw/openclaw/issues/44309.
