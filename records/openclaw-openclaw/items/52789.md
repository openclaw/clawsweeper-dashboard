## Label Justifications

- `P2`: The remaining work is a normal-priority cron reliability and multi-agent workflow feature, not an urgent runtime outage.
- `impact:session-state`: The requested behavior would inject cron output into another agent session and therefore affects session routing/state semantics.
- `impact:message-loss`: The issue describes cron output being silently lost when model-authored tool calls omit required delivery parameters.
- `impact:security`: Internal session delivery needs authorization, provenance, and audit rules before scheduled jobs can write invisible cross-session messages.

## Summary

The current issue is the session-only subset of the broader open cron output-routing tracker; current main and v2026.6.11 still lack `delivery.mode: "session"`, but the remaining work is already owned by the canonical cron output-target issue, with the A2A dispatch issue covering adjacent one-way session semantics.

## What This Changes

The issue requests a new cron delivery mode that routes completed cron output internally to a session via `sessions_send` instead of posting to a visible channel or relying on model tool calls.

## Best Possible Solution

Use https://github.com/openclaw/openclaw/issues/49078 as the canonical cron output-target design, with https://github.com/openclaw/openclaw/issues/44309 informing any one-way session dispatch semantics.

## Reproduction Assessment

Yes, at source level. Current main shows the requested public mode is absent from cron delivery types, protocol schema, runtime delivery planning/dispatch, and docs; a live run is not needed to reproduce a missing feature contract.

## Solution Assessment

No, not as a standalone issue. The safer solution is to handle this as the session-target subset of the broader cron output-routing contract, with A2A dispatch semantics decided alongside it.
