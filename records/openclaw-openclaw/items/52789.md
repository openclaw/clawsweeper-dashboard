## Label Justifications

- `P2`: This is a normal-priority cron reliability feature with real multi-agent impact, but it is not an emergency runtime outage.
- `impact:message-loss`: The report describes scheduled output being silently dropped when cheaper models fail to call `sessions_send` correctly.
- `impact:session-state`: The requested mode would write scheduled job output into another agent session and affect transcript/context routing semantics.
- `impact:security`: Invisible framework-owned cross-session delivery needs explicit authorization, provenance, and audit decisions.

## Summary

Close: the requested cron-to-session delivery mode is the session-target subset of the open canonical cron output-routing design issue, while current main and the latest release still lack the requested mode.

## What This Changes

Request adds a cron `delivery.mode="session"` route so scheduled job output can be delivered invisibly to a target session instead of relying on model-called `sessions_send`.

## Best Possible Solution

Use https://github.com/openclaw/openclaw/issues/49078 as the canonical cron output-routing design, with https://github.com/openclaw/openclaw/issues/44309 informing any one-way session dispatch semantics.

## Reproduction Assessment

Not applicable as a strict bug reproduction; this is a feature/config request. Source, protocol, docs, and v2026.6.11 show the requested session delivery mode is absent.

## Solution Assessment

No as a standalone implementation path. A one-off `delivery.mode="session"` would race the broader cron output-target contract and A2A dispatch semantics that need one maintainer-approved design.
