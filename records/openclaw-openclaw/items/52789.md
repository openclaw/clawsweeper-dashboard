## Label Justifications

- `P2`: The request affects real multi-agent cron reliability, but it is a bounded feature requiring maintainer direction rather than an urgent regression.
- `impact:message-loss`: The report says cron output can be silently lost when the model fails to call sessions_send with the right parameters.
- `impact:session-state`: The requested mode would inject cron output into another session and change transcript/context routing behavior.
- `impact:security`: Invisible framework-owned cross-session delivery needs authorization, provenance, and audit semantics before implementation.

## Summary

Close as duplicate/superseded: the requested cron-to-session delivery behavior is still missing, but the remaining work is now covered by the broader open cron output-routing tracker, with the one-way A2A dispatch issue as an adjacent dependency for session semantics.

## What This Changes

The issue requests a new cron job delivery mode that routes completed cron output to another OpenClaw session through framework-owned internal session delivery instead of visible channel announcement or model-driven tool calls.

## Best Possible Solution

Use https://github.com/openclaw/openclaw/issues/49078 as the canonical cron output-target design, with https://github.com/openclaw/openclaw/issues/44309 informing any one-way session dispatch semantics.

## Reproduction Assessment

Yes, at source level. Current main shows the requested public mode is absent from cron delivery types, parser, protocol schema, planner, runtime delivery dispatch, and docs; a live run is not needed to reproduce a missing feature contract.

## Solution Assessment

No, not as a standalone issue. The safer solution is to handle this as the session-target subset of the broader cron output-routing contract, with A2A dispatch semantics decided alongside it.
