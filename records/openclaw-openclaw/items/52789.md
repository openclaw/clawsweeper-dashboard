## Label Justifications

- `P2`: This is a normal-priority multi-agent cron reliability feature with real user impact, bounded scope, and required product/security direction before implementation.
- `impact:session-state`: The requested mode would write cron output into another agent session and affect transcript/context routing semantics.
- `impact:security`: Invisible framework-owned cross-session delivery requires explicit authorization, visibility, and provenance decisions.
- `impact:message-loss`: The report says cron results can be silently dropped when models fail to call `sessions_send` correctly.

## Summary

Keep open: current main and v2026.6.11 still expose cron completion delivery as `none`, `announce`, or `webhook` only. The requested internal session delivery remains a new public cron/session contract that needs maintainer product and security direction, and the related open items at https://github.com/openclaw/openclaw/issues/49078 and https://github.com/openclaw/openclaw/issues/44309 overlap without fully superseding this narrower request.

## What This Changes

Request adding `delivery.mode: "session"` to cron jobs so completion output is delivered internally to a target session via `sessions_send` instead of visible channel delivery, webhook delivery, or model-authored tool calls.

## Best Possible Solution

Keep this open for a maintainer-approved cron-to-session output contract that defines authorization, provenance, transcript behavior, and its relationship to broader output routing and one-way A2A dispatch before updating schema, parser, runtime, protocol, docs, and tests.

## Reproduction Assessment

Yes at source level. Current main type/schema/parser/planner/docs list `none`, `announce`, and `webhook` only, so no live run is needed to confirm the requested mode is missing.

## Solution Assessment

Unclear as an implementation. Framework-owned session delivery is plausible, but maintainers still need to choose the cron output API shape, A2A relationship, authorization, and transcript semantics before a safe implementation exists.
