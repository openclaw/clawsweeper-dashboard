## Summary

The reported failure is present in both v2026.6.11 and current main: a dependency-backed card is moved to `running` by its first claim, then a repeat claim rejects that status before checking the active lease. The issue should stay open as a narrow workboard bug; the broader CLI and dispatch UX suggestions should not be bundled into the repair.

## What This Changes

Make repeated claims on dependency-backed workboard cards report the active claim rather than incorrectly reporting unfinished dependencies.

## Best Possible Solution

Check an unexpired active lease before dependency readiness validation and preserve the established `already claimed by <owner>` behavior, with a focused regression test for a completed parent and claimed child.
