## Summary

Keep open. Current main does not implement the requested iOS Privacy notification controls, and this PR is the active fix candidate, but the latest head still has a source-reproducible notification-delivery bug in the hosted-relay enable flow plus insufficient APNs/register-unregister proof.

## What This Changes

The PR moves iOS notification controls into Settings > Privacy, adds an app-level notification-serving preference, and changes APNs registration acknowledgement/unregister handling between the iOS app and gateway.

## Best Possible Solution

Preserve enable intent through relay disclosure and iOS settings recovery, keep notification delivery gated by system permission plus an explicit off toggle, and prove fresh-install plus upgrade APNs behavior before merge.

## Reproduction Assessment

Yes for the PR defect from source inspection. In a hosted-relay build with notification status denied, checking, or unknown, accepting disclosure writes the app-level preference off before opening iOS Settings, while registration later requires that preference on.

## Solution Assessment

No. Moving Notifications into Privacy is a plausible product direction, but this implementation must preserve the user's enable intent through disclosure/settings and prove the new APNs registration state behavior.
