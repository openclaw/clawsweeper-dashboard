## Label Justifications

## Summary

Current main intentionally permits a configured default agent whose ID is not `main`, so the reported silent dangling-reference behavior deserves review, but enforcing a literal `main` entry would conflict with existing configuration semantics. The protected `security` label and open linked fix PR require explicit maintainer security and compatibility review rather than cleanup closure.

## What This Changes

Detect or prevent configurations that remove the effective primary agent and leave sessions or channel bindings targeting an unavailable agent.

## Best Possible Solution

Preserve configurable default-agent IDs, validate that the resolved default and every binding reference an existing agent, and provide clear startup diagnostics plus an explicit `openclaw doctor --fix` repair instead of silently requiring or recreating literal `main`.
