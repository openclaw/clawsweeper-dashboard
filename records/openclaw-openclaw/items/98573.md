## Summary

Keep open: current main and the latest release still pass bare `gemini` through a Windows supervisor shim allowlist that excludes it, and the related open/closed PRs do not provide a merged canonical fix.

## What This Changes

The issue asks OpenClaw to handle Windows npm `.cmd` shims when launching the `google-gemini-cli` backend's `gemini` command.

## Best Possible Solution

Land one focused Windows CLI-backend spawn fix that resolves npm `.cmd` shims for shipped CLI backends through a hardened generic boundary, with regression coverage for Gemini.

## Reproduction Assessment

Yes at source level, though I did not run Windows live. Current main sends `backend.command` as bare `gemini`, and the Windows child adapter only appends `.cmd` for package-manager names, matching the reported `spawn gemini ENOENT` logs.

## Solution Assessment

The requested `.cmd` handling is the right class of fix. The maintainable solution should live at the supervisor/CLI spawn boundary and avoid a Gemini-only workaround or a broad new shell fallback.
