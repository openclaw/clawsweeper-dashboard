## Summary

Keep open: the patch is a focused, evidence-backed candidate fix, but it intentionally changes cron status/backoff semantics for delivery-only failures, so it should wait for maintainer approval rather than be auto-closed or auto-merged.

## What This Changes

This PR reclassifies nonfatal isolated cron delivery-dispatch failures from run `status=error` to `status=ok` with `deliveryStatus=not-delivered`/`deliveryError`, and adds cron finalizer plus run-log readback regression coverage.

## Best Possible Solution

Land one maintainer-approved cron contract: either accept this narrow `ok` plus `deliveryStatus:not-delivered` split with the added diagnostics, or supersede it with the broader warning-status design before changing shipped semantics.

- Existing operators or integrations that key on cron run `status=error` to detect undelivered runs would stop seeing delivery-only failures through that field and must read `deliveryStatus`/`deliveryError` instead.
- Delivery-only failures would no longer increment `consecutiveErrors` or trigger execution-failure backoff/alerts; that matches the reported bug but is still an intentional status-policy change.
- The broader warning-status direction remains open in https://github.com/openclaw/openclaw/issues/49190 and https://github.com/openclaw/openclaw/pull/80139, so merging this PR chooses a narrower `ok` plus delivery metadata contract for now.
