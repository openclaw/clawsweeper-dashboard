- `P2`: This is a normal-priority cron correctness fix with bounded but meaningful impact on scheduled reporting and operator status semantics.

## Summary

Keep this PR open: the patch is a focused, well-proven fix candidate with no blocking code findings, but merging it still requires a maintainer decision on cron execution-status versus delivery-failure semantics.

## What This Changes

This PR changes isolated cron finalization so nonfatal agent runs keep `status=ok` when post-run delivery fails, threads a dedicated `deliveryError` through cron state/run logs, and adds regression/readback tests.

## Best Possible Solution

Adopt one explicit cron execution-versus-delivery contract: land this focused `ok` plus `not-delivered` split with operator/release context, or pause it in favor of a broader warning-status contract across API, CLI, UI, docs, and compatibility proof.
