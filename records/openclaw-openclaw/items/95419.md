## Label Justifications

- `P2`: This is a normal-priority cron correctness fix with meaningful but bounded impact on scheduled reporting and operator status semantics.
- `merge-risk: 🚨 compatibility`: Consumers that key off cron run `status=error` for undelivered successful runs would observe a changed status contract after merge.
- `merge-risk: 🚨 message-delivery`: The PR changes how failed post-run delivery is classified and surfaced, so undelivered scheduled messages may no longer trigger existing error/backoff/alert flows.

## Summary

Keep open for maintainer review; this is an active, focused fix candidate with sufficient proof and no blocking code findings, but it intentionally changes cron status/backoff semantics for successful runs whose delivery fails.

## What This Changes

This PR reclassifies successful isolated cron runs with post-run delivery dispatch failures as `status=ok` while preserving delivery diagnostics through `deliveryError`, cron state, finished events, and run-log readback tests.

## Best Possible Solution

Use one explicit cron status contract: either land this focused execution/delivery split with an operator-visible release note, or choose the broader warning-status model and close the narrower duplicates.
