## Label Justifications

- `P2`: This is a normal-priority cron correctness fix with bounded but meaningful impact on scheduled reporting and operator status semantics.
- `merge-risk: 🚨 compatibility`: Consumers that key off cron run `status=error` for undelivered successful runs would observe a changed status contract after merge.
- `merge-risk: 🚨 message-delivery`: The PR changes how failed post-run delivery is classified and surfaced, so undelivered scheduled messages may no longer trigger existing error/backoff/alert flows.

## Summary

Keep open for maintainer review: the patch is narrow and well-proven with no blocking code findings, but it intentionally changes persisted cron status, backoff, and delivery-alert semantics for successful isolated runs whose post-run delivery fails.

## What This Changes

This PR changes isolated cron finalization so successful nonfatal agent runs keep `status=ok` when post-run delivery fails, threads `deliveryError` through cron state/run logs, and adds regression/readback tests.

## Best Possible Solution

Adopt one explicit cron execution-versus-delivery contract: either land this focused `ok` plus `not-delivered` split with operator/release context, or pause it in favor of a broader warning-status contract across API, CLI, UI, docs, and compatibility proof.
