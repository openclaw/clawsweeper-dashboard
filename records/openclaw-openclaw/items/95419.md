## Summary

Keep open: the patch has no blocking code-review finding, but it changes cron status/backoff semantics for successful executions whose post-run delivery fails, so a maintainer should explicitly choose the status contract before merge.

## What This Changes

The PR changes isolated cron finalization so nonfatal successful agent runs keep `status=ok` when post-run delivery fails, while delivery failure details flow through `deliveryError`, cron state, finished events, and run-log readback tests.

## Best Possible Solution

Adopt one explicit cron execution-versus-delivery contract: either land this focused `ok` plus `not-delivered` split with release/operator context, or pause it in favor of a broader warning-status contract that updates API, CLI, UI, docs, and compatibility proof together.
