## What This Changes

The PR keeps successful isolated cron agent runs at `status=ok` when post-run delivery fails, threads `deliveryError` to service/run logs, and adds regression/readback tests.

## Best Possible Solution

Land the narrow decoupling only after a maintainer accepts the `status=ok` plus `deliveryStatus=not-delivered` semantics, and keep any first-class warning-state work on the broader canonical thread.
