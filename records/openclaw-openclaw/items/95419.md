## Label Justifications

- `P2`: This is a normal-priority cron correctness fix with meaningful but bounded impact on scheduled reporting and operator status semantics.
- `merge-risk: 🚨 compatibility`: Consumers that key off cron run `status=error` for undelivered successful runs would observe a changed status contract after merge.
- `merge-risk: 🚨 message-delivery`: The PR changes how failed post-run delivery is classified and surfaced, so undelivered scheduled messages may no longer trigger existing error/backoff/alert flows.

## Summary

Keep open for maintainer review: the patch is focused, source-backed, and has sufficient real behavior proof, but it intentionally changes cron status/backoff semantics and overlaps a broader warning-status proposal.

## What This Changes

The branch keeps successful isolated cron execution at `status=ok` when post-run delivery fails, threads a separate `deliveryError` through cron service/run-log state, and adds focused regression/readback tests.

## Best Possible Solution

Use one explicit cron status contract: either land this focused `ok` plus `not-delivered` split with operator-visible release context, or choose the broader warning-status model and narrow/close the competing PRs accordingly.
