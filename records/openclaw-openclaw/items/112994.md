## Summary

The current model-picker contract intentionally filters custom-provider catalogs through the agent model allowlist. This report does not include a complete valid provider catalog or any `agents.defaults.models` entries, so the empty menu is not yet a source-level regression that OpenClaw can fix; it is best handled as a configuration diagnosis and reopened with a complete redacted reproduction if that documented setup still fails.

## What This Changes

The issue asks for the UI and companion app to list models from five locally hosted Ollama providers configured on separate ports.

## System Context

Custom-provider definitions supply model catalog entries and endpoint details to OpenClaw. The gateway and companion/control UI then filter that catalog through the agent’s allowed model references before offering selectable models.

## Architecture Diagram

flowchart LR
  Config[OpenClaw configuration] --> Providers[Custom Ollama providers]
  Providers --> Catalog[Model catalog]
  Allowlist[Agent model allowlist] --> Filter[Allowed-model filter]
  Catalog --> Filter
  Filter --> Picker[Control and companion model pickers]
  Picker --> Selected[Selected provider/model]

## Best Possible Solution

Keep the existing provider-catalog and allowlist boundary; configure each custom provider with complete model rows and add explicit `provider/model` or `provider/*` entries to `agents.defaults.models`, then reopen only with a complete redacted current-version reproduction if the picker remains empty.
