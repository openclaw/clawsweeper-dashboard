## Label Justifications

- `merge-risk: 🚨 session-state`: The patch changes how persisted transcript results are attributed across turns, and an incorrect reservation can lose or mis-associate session context.

## Summary

Keep open: the overall repair direction is plausible, but the new reservation scan counts later errored or aborted assistant turns even when the selected replay policy will drop those turns, so a real result can still be reserved away from the healthy turn and then discarded. The claimed production verification also lacks inspectable after-fix output.

## What This Changes

The PR changes transcript repair to pair repeated tool-call IDs per assistant turn using record identity and occurrence ordering, with expanded regression coverage.

## Best Possible Solution

Use turn-scoped occurrence pairing whose reservation model includes only later turns eligible to survive the selected error/aborted policy, add regression cases for dropped turns with repeated IDs, and attach redacted before/after provider diagnostics showing the formerly poisoned session succeeds.

No, not yet. Turn-scoped pairing is the correct ownership direction, but the implementation must align future-result reservations with errored and aborted turn policies before it is the narrowest safe fix.
