## Summary

Keep this PR open: the reported LINE failures are valid and the live proof is strong, but the new composite-batch fallback can turn one invalid rich or media object into total reply loss, so that failure path should be repaired before merge.

## What This Changes

Bundles LINE text, rich, and media replies onto one reply-token batch, pushes only overflow, and moves quick replies to the final delivered message.

## Best Possible Solution

Keep the single reply-token batch for valid payloads, but when the composite send is rejected, preserve valid text through a decomposed fallback before separately attempting rich and media delivery, without replaying any batch known to have succeeded.
