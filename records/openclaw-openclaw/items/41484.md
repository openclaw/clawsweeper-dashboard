## Summary

Keep open: current main has adjacent agent cron caller scoping, but elevated exec is still authorized by provider/sender allowlists and cron/heartbeat state still lacks the requested trusted per-job or last-modified provenance.

## What This Changes

The issue requests per-cron-job and heartbeat-scoped elevated execution provenance so internal cron and heartbeat events no longer need wildcard elevated privileges.

## Best Possible Solution

Define one security-reviewed provenance model for scheduled and heartbeat elevated execution, store operator-approved authority with cron jobs or heartbeat configuration, and migrate users away from wildcard internal-source elevation with audit and docs.
