## Summary

Keep open: current main still lacks per-job or heartbeat-specific elevated-exec provenance, and the merged cron caller-scope work only partially addresses the scheduling side.

## What This Changes

The issue requests a per-cron-job elevated-exec authority flag plus heartbeat elevation provenance so internal cron and heartbeat events no longer depend on all-or-nothing `cron-event` or `heartbeat` wildcard allowlists.

## Best Possible Solution

Define one security-reviewed provenance contract that binds approved cron and heartbeat elevation to create, update, and execution authority, then migrate away from internal-source wildcards.
