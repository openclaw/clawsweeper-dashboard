## Summary

Keep open: current main has adjacent agent-scoped cron ownership, but cron jobs and heartbeat still lack persisted elevated-approval provenance, so this remains a security/product design item rather than cleanup.

## What This Changes

The issue requests per-job and heartbeat-scoped elevated exec authority so trusted scheduled work can run elevated without granting wildcard elevated access to all cron or heartbeat internal sources.

## Best Possible Solution

Design one security-reviewed provenance model for scheduled and heartbeat elevated execution, store operator-approved authority with cron and heartbeat state, and migrate users away from wildcard internal-source elevation with audit and docs.
