## Summary

Keep open: current main still authorizes elevated execution through synthetic heartbeat/cron providers and sender allowlists, while cron jobs and heartbeat state still lack the requested trusted per-job or last-modified elevated provenance.

## What This Changes

The issue requests a trusted per-job elevated flag for cron jobs plus heartbeat provenance so internal cron/heartbeat runs no longer require wildcard elevated allowlists.

## Best Possible Solution

Define one security-reviewed provenance model for scheduled and heartbeat elevated execution, store operator-approved authority with cron jobs or heartbeat configuration, and migrate users away from wildcard internal-source elevation with audit and docs.
