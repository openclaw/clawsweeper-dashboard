## Summary

Keep open: current main has agent-scoped cron ownership from https://github.com/openclaw/openclaw/pull/96883, but elevated execution still resolves through provider/sender allowlists and wildcards, and cron jobs plus heartbeat config still lack durable per-job or per-modification elevated provenance.

## What This Changes

The issue requests per-job and heartbeat-specific elevated execution authority so internal cron and heartbeat sources no longer need wildcard elevated allowlists.

## Best Possible Solution

Design one security-reviewed provenance model for scheduled and heartbeat elevated execution, store operator-approved authority with cron and heartbeat state, and migrate users away from wildcard internal-source elevation with audit and docs.
