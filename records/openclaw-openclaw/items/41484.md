## Summary

Keep open: current main still authorizes elevated exec through provider/sender allowlists and synthetic cron/heartbeat providers, while cron jobs and heartbeat config still lack the requested trusted per-job or last-modified elevated provenance; merged PR #96883 only added adjacent agent cron caller scoping.

## What This Changes

The issue requests per-job and per-heartbeat elevated exec scoping so only explicitly trusted scheduled or heartbeat work can inherit elevated host exec authority.

## Best Possible Solution

Define one security-reviewed provenance model for scheduled and heartbeat elevated execution, store operator-approved authority with the job or heartbeat configuration, and migrate users away from wildcard internal-source elevation with audit and docs.
