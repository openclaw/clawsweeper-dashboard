## Summary

Keep open: current main still does not provide trusted per-job cron or heartbeat provenance for elevated exec, and the merged cron caller-scope work only addresses agent ownership, not the internal-source wildcard elevation boundary.

## What This Changes

The issue requests per-job elevated exec scoping for cron and heartbeat so scheduled or autonomous runs cannot inherit elevated host exec solely through wildcard internal-provider allowlists.

## Best Possible Solution

Define one security-reviewed provenance model for scheduled and heartbeat elevated execution, store operator-approved authority with the relevant cron or heartbeat state, and migrate users away from wildcard internal-source elevation with audit and docs.
