## Summary

Keep open: current main has same-agent cron scoping from merged PR #96883, but it still does not provide the requested per-job elevated authorization/provenance model for cron or heartbeat; elevated exec remains controlled by provider-level allowlists such as cron-event/heartbeat.

## What This Changes

Add per-job elevated exec scoping and provenance for cron jobs and heartbeat so internal cron/heartbeat sources do not require broad elevated allowlists.

## Best Possible Solution

Define a maintainer-approved cron/heartbeat elevated authority contract with persisted job trust/provenance, owner-approved changes, heartbeat trust semantics, migration/docs/tests, and no reliance on broad cron-event or heartbeat allowlists.
