## Summary

Keep open: current main has adjacent cron caller scoping, but it still does not provide trusted elevated-exec provenance for individual cron jobs or heartbeat state, and the remaining work is a security/product boundary decision.

## What This Changes

The issue requests per-job elevated approval for cron jobs and trusted heartbeat elevated provenance so internal cron/heartbeat sources no longer need wildcard elevated access.

## Best Possible Solution

Define one security-reviewed provenance and approval model for scheduled and heartbeat elevated execution, then migrate users away from wildcard internal-source elevation with audit, docs, and focused tests.
