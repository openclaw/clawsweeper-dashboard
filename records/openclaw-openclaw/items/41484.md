## Summary

Keep open: current main has adjacent agent cron caller scoping, but elevated exec is still decided by provider/sender allowlists and cron/heartbeat persisted state still lacks trusted per-job or last-modified approval provenance.

## What This Changes

Request per-job and heartbeat-scoped elevated execution provenance so cron/heartbeat internal events no longer rely on wildcard elevated allowlists.

## Best Possible Solution

Define one security-reviewed provenance model for scheduled and heartbeat elevated execution, store operator-approved authority with cron jobs or heartbeat config, and migrate users away from wildcard internal-source elevation with audit/docs.
