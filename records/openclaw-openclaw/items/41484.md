## Label Justifications

- `P1`: The issue concerns elevated host-exec authority for autonomous cron and heartbeat runs in multi-user setups.
- `impact:security`: The requested change is about preventing unauthorized scheduled or heartbeat paths from inheriting elevated execution authority.

## Summary

Keep open: current main has agent-scoped cron ownership from merged PR #96883, but elevated execution still resolves through provider/sender allowlists and wildcards, and cron jobs plus heartbeat config still lack durable per-job or per-modification elevated provenance.

## What This Changes

Request per-job cron and heartbeat elevated-exec scoping so approved scheduled or heartbeat work can use host exec without granting wildcard elevated access to all cron or heartbeat events.

## Best Possible Solution

Design one security-reviewed provenance model for scheduled and heartbeat elevated execution, store operator-approved authority with cron and heartbeat state, and migrate users away from wildcard internal-source elevation with audit and docs.
