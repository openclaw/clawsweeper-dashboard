## Summary

Keep open: current main partially scopes agent cron CRUD to the calling agent, but it still lacks durable per-job elevated approval, heartbeat elevated provenance, and an upgrade-safe replacement for internal `cron-event`/`heartbeat` wildcard elevation.

## What This Changes

Requests a per-job and heartbeat provenance model so unattended cron and heartbeat runs can use elevated exec only when explicitly approved.

## Best Possible Solution

Define one Gateway-stamped security contract that binds cron and heartbeat elevation to approved creation, update, execution, audit, and migration semantics before replacing internal-source wildcard elevation.
