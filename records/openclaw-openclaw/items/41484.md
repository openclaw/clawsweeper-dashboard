## Label Justifications

- `P1`: Unattended heartbeat or cron execution can still reach elevated host-exec authority through broad internal-source allowlists, which is an urgent security hardening gap for agent workflows.
- `impact:security`: The issue concerns non-forgeable authority and provenance for elevated host-exec access during scheduled or autonomous agent runs.

## Summary

Keep open: current main still lacks a non-forgeable elevated-execution authority model for cron and heartbeat runs, and the merged cron scoping work only limits agent cron operations to the caller rather than recording operator-approved elevated provenance for scheduled execution.

## What This Changes

Request per-job or heartbeat-scoped elevated exec authority so cron and heartbeat runs no longer depend on broad internal-source wildcard elevation.

## Best Possible Solution

Design one security-reviewed provenance model for scheduled and heartbeat elevated execution, store operator-approved authority with cron or heartbeat state, and migrate users away from wildcard internal-source elevation.

Rationale: The choice changes host-exec trust boundaries, cron storage/protocol shape, heartbeat semantics, audit expectations, and compatibility for users currently relying on wildcard cron-event or heartbeat elevation.

Options:

- **Fold Into Scheduling Provenance (recommended):** Use one authority model across cron APIs, execution receipts, heartbeat state, audit, and migration so scheduled agent actions have non-forgeable provenance.
- **Add Narrow Elevated Markers:** Add per-job and heartbeat elevated markers now, accepting the risk of a separate authority model from the broader scheduling provenance RFC.
- **Fail Closed For Internal Sources:** Remove broad internal-source elevation and require explicit operator reconfiguration, accepting upgrade friction for existing unattended workflows.

## Solution Assessment

Unclear until maintainers choose the trust model; a per-job flag is plausible, but the safe fix should also cover cron add/update/run, heartbeat provenance, audit, migration, docs, and existing users.
