## Summary

Keep open: current main has useful adjacent cron caller-scope and owner-attribution work, but it still lacks the requested per-job elevated approval state and heartbeat modifier provenance, so the core security problem remains.

## What This Changes

Add per-job elevated exec scoping for cron jobs and heartbeat so trusted owner-created work can run elevated without wildcard internal-event allowlists.

## Best Possible Solution

Define one security-reviewed provenance model for scheduled and heartbeat elevated execution, store operator-approved authority with cron jobs or heartbeat configuration, and migrate users away from wildcard internal-source elevation with audit and docs.
