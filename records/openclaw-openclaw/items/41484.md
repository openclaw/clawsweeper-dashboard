## Summary

Keep open: current main has partial cron caller scoping, but it still lacks the requested per-job elevated-exec approval/provenance and heartbeat-specific elevated authority model. This remains a security-boundary design item, not a closeable implemented fix.

## What This Changes

Request per-job elevated-exec scoping for cron jobs and heartbeat so internal cron or heartbeat runs do not require wildcard elevated permission and cannot be created or modified into elevated authority by non-elevated users.

## Best Possible Solution

Design one core provenance contract that binds elevated cron and heartbeat authority to approved creation/update/execution records, with an explicit migration or doctor path away from internal-source wildcards.
