## Summary

Current main still lacks the requested durable elevated-exec authority and provenance boundary for scheduled or heartbeat-originated work. The merged cron caller-scope work narrows agent cron ownership, but it does not add per-job approval metadata, heartbeat modification provenance, or a migration from ambient provider/sender elevated allowlists, so this security/product item remains necessary.

## What This Changes

The issue requests per-job cron elevated-exec approval and heartbeat modification provenance so autonomous scheduled work cannot inherit broad elevated permissions without durable operator intent.

## Best Possible Solution

Design one security-reviewed provenance model for scheduled and heartbeat elevated execution, persist operator-approved authority with the job or heartbeat source, and document/migrate away from relying on broad internal-source elevated allowlists for autonomous work.
