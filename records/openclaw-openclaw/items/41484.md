## Summary

Keep open: current main has adjacent cron owner/caller scoping, but elevated exec is still authorized from provider/sender allowlists and cron/heartbeat state still lacks trusted per-job or last-modified elevated provenance.

## What This Changes

The issue requests per-job elevated-exec provenance for cron jobs and heartbeat so internal event sources no longer need wildcard elevated privileges.

## Best Possible Solution

Define one security-reviewed provenance model for scheduled and heartbeat elevated execution, store operator-approved authority with cron jobs or heartbeat configuration, and migrate users away from wildcard internal-source elevation with audit and docs.
