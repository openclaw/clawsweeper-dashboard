## Label Justifications

## Summary

Keep open: current main still authorizes elevated exec for cron and heartbeat through provider/sender allowlists, while cron jobs and heartbeat config lack the requested trusted per-job or last-modified elevated provenance.

## What This Changes

Request per-job elevated authority for cron plus heartbeat provenance so internal event sources no longer need wildcard elevated allowlists.

## Best Possible Solution

Define one security-reviewed provenance model for scheduled and heartbeat elevated execution, store operator-approved authority with the relevant cron or heartbeat state, and migrate users away from wildcard internal-source elevation with audit and docs.
