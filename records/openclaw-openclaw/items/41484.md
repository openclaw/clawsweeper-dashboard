## Summary

Keep open: current main still lacks trusted per-job cron or heartbeat elevated-exec provenance, and the related cron caller-scope work does not replace the wildcard internal-source elevated boundary.

## What This Changes

Request per-job cron and heartbeat elevated-exec scoping so internal cron-event and heartbeat sources no longer rely on all-or-nothing wildcard elevated allowlists.

## Best Possible Solution

Define one security-reviewed provenance model for scheduled and heartbeat elevated execution, store operator-approved authority with the relevant cron or heartbeat state, and migrate users away from wildcard internal-source elevation with audit and docs.
