## Label Justifications

- `P1`: The issue concerns elevated host-exec authority for autonomous cron and heartbeat runs, a high-impact security boundary for multi-user setups.
- `impact:security`: The requested change prevents unauthorized scheduled or heartbeat paths from inheriting elevated execution authority through internal-source wildcards.

## Summary

Keep open: current main still has adjacent agent-cron caller scoping, but not the requested per-job cron elevated authority or heartbeat last-modified/elevated provenance model.

## What This Changes

The issue requests owner-approved per-job cron elevation plus heartbeat elevation provenance so internal `cron-event`/`heartbeat` wildcard elevation is no longer needed.

## Best Possible Solution

Define one security-reviewed scheduled/heartbeat elevation provenance model, store operator-approved authority with cron and heartbeat state, and migrate users away from wildcard internal-source elevation with audit and docs.
