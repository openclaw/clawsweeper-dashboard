## Summary

Keep open: current main has adjacent agent cron caller scoping, but it still lacks trusted elevated-exec provenance for cron jobs and heartbeat, and the remaining fix is a security/product decision.

## What This Changes

The issue requests per-job elevated-exec provenance for cron jobs and heartbeat so internal scheduled or heartbeat runs do not inherit blanket elevated permissions.

## Best Possible Solution

Define one security-reviewed provenance model for scheduled and heartbeat elevated execution, store operator-approved authority with cron jobs or heartbeat configuration, and migrate users away from wildcard internal-source elevation with audit and docs.
