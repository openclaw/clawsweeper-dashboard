## Summary

Keep open: current main has adjacent cron caller scoping, but it still has no per-job elevated approval state or heartbeat last-modifier provenance, and the remaining trust model is security/product-sensitive.

## What This Changes

Requests a cron job `elevated` trust flag and heartbeat provenance so scheduled and heartbeat work only inherits elevated exec when an elevated sender approved that specific job or state.

## Best Possible Solution

Define one security-reviewed provenance and approval model for scheduled and heartbeat elevated execution, then migrate users away from wildcard internal-source elevation with audit, docs, and focused tests.
