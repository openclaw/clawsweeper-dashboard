## Label Justifications

- `P1`: The issue concerns elevated host-exec privilege propagation through scheduled cron/heartbeat work in multi-user gateway setups.
- `impact:security`: The requested change is about preventing privilege escalation from less-trusted senders into elevated exec via cron or heartbeat state.

## Summary

Keep open: current main has adjacent agent cron caller scoping, but cron job schema/state still lacks a trusted elevated flag or approval provenance, and heartbeat still has no last-modified trust semantics for elevated exec.

## What This Changes

Request adding per-cron-job and heartbeat provenance controls so elevated exec can be granted to trusted scheduled work without allowing every cron/heartbeat-originated turn.

## Best Possible Solution

Define a core security contract for scheduled elevated execution: non-forgeable creator/approver provenance on cron jobs, a heartbeat trust marker or migration, and upgrade behavior that removes the need for cron-event/heartbeat wildcard elevated allowlists.
