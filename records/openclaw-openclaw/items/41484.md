## Summary

Keep open: current main still has synthetic cron/heartbeat providers feeding the normal elevated allowlist path, while cron jobs and heartbeat state still lack a trusted per-job or last-modified elevated provenance model.

## What This Changes

Request to add per-job elevated execution scoping for cron jobs and heartbeat so internal scheduled work cannot inherit host-elevated exec solely from wildcard internal-source allowlists.

## Best Possible Solution

Define one security-reviewed provenance model for scheduled and heartbeat elevated execution, store operator-approved authority with cron jobs or heartbeat configuration, and migrate users away from wildcard internal-source elevation with audit and docs.
