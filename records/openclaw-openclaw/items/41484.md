## Label Justifications

- `impact:security`: The requested change is about preventing unauthorized scheduled or heartbeat paths from inheriting elevated execution authority.

## Summary

Keep open: current main still lacks trusted per-job elevated cron provenance and heartbeat mutation provenance; the merged agent cron caller-scope work is useful adjacent hardening but does not solve the reported elevated-exec trust boundary.

## What This Changes

The issue requests owner-approved elevated execution metadata for cron jobs and heartbeat state so internal `cron-event` and `heartbeat` provider wildcards are no longer required for privileged scheduled/background runs.

## Best Possible Solution

Define one security-reviewed provenance model for scheduled and heartbeat elevated execution, store operator-approved authority with cron/heartbeat state, and migrate users away from wildcard internal-source elevation with audit and docs.

## Solution Assessment

Unclear until maintainers choose the trust model; the per-job flag is plausible, but the best fix should cover cron create/update paths, execution-time checks, heartbeat provenance, audit, migration, and docs together.
