## Summary

Current main only implements agent cron caller scoping; the requested per-job/per-heartbeat elevated exec authority with durable provenance and approval semantics is still missing, so the issue remains necessary and should stay open for security/product design.

## What This Changes

Request per-job elevated exec scoping for cron and heartbeat so recurring/autonomous runs cannot inherit broad elevated exec permission without explicit provenance-bound approval.

## Best Possible Solution

Define one security-reviewed provenance contract that binds elevated cron and heartbeat execution to creation/update authority, approval receipts, audit, and migration behavior before changing runtime enforcement.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should elevated exec for cron and heartbeat be solved as a narrow per-job/per-heartbeat marker, or folded into the broader Gateway-owned scheduling and execution provenance model?

Rationale: The unresolved behavior changes who may grant host exec authority to autonomous runs and likely touches cron protocol/storage, heartbeat runtime, audit, and upgrade semantics, which automation cannot choose safely.

Likely owner: joshavant

Owner reason: Recent merged work on cron caller scoping is the closest current-main implementation boundary for the cron side of this security decision.

Owner confidence: medium

Options:

- **Fold Into Provenance Design (recommended):** Treat this issue as part of a Gateway-owned scheduling/execution provenance contract that covers cron, heartbeat, approval receipts, audit, and migrations.
- **Narrow Cron/Heartbeat Marker:** Add only a focused elevated marker for cron jobs and heartbeat runs, accepting a smaller patch with more follow-up security design remaining.
- **Defer Elevated Autonomy:** Keep broad elevated exec unavailable to autonomous cron/heartbeat paths until the larger agent scheduling security model is ready.

## Reproduction Assessment

Yes, source inspection shows current main still resolves elevated exec from provider/sender allowlists and wildcard tokens while cron jobs and heartbeat runs lack a durable elevated authority/provenance record.

## Solution Assessment

The requested per-job flag is directionally useful but incomplete unless paired with provenance, audit, update semantics, migration behavior, and explicit heartbeat authority rules.
