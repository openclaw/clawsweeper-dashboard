## Summary

Keep open: current main partially narrowed agent-originated cron ownership, but cron jobs and heartbeat runs still do not carry durable elevated-exec authority provenance, so the reported security boundary remains unresolved.

## What This Changes

The issue requests per-job and heartbeat-scoped elevated execution authority so internal cron and heartbeat sources no longer need wildcard elevated allowlists.

## Best Possible Solution

Design one security-reviewed, non-forgeable authority model for scheduled and heartbeat elevated execution, with stored approval provenance, auditability, docs, and an upgrade path away from wildcard internal-source elevation.
