## Summary

Keep open: current main has caller-scoped cron operations from PR #96883, but it still lacks the requested trusted per-job elevated exec authority and heartbeat provenance needed to distinguish operator-approved scheduled work from autonomous or spoofable heartbeat/cron sources.

## What This Changes

Issue requests per-job elevated exec scoping for cron plus explicit heartbeat provenance so scheduled or autonomous runs cannot inherit broad provider-level elevation without trusted approval context.

## Best Possible Solution

Adopt one security-reviewed Gateway provenance model that covers cron jobs and heartbeat runs with stored operator-approved elevated authority, auditability, docs, and upgrade-safe config behavior.
