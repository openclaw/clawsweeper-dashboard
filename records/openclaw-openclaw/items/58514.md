## Label Justifications

- `P1`: The issue reports a broken Google Chat Space workflow where accepted group messages can be dropped before any agent response for affected users.
- `impact:message-loss`: Space messages are reported as accepted by the webhook but silently produce no agent response.
- `impact:session-state`: The failure is specifically missing `googlechat:group` session creation while Google Chat DMs create sessions and work.

## Summary

Keep open: current main and v2026.6.11 include the modern Google Chat Space/DM classifier from https://github.com/openclaw/openclaw/pull/58993, but the issue discussion and current access-policy code still show a remaining Space mention-gating path that can drop accepted Space messages before `googlechat:group` session creation.

## What This Changes

Google Chat Space/group messages should create and process `googlechat:group` sessions when the app is mentioned, instead of returning HTTP 200 and being silently ignored while DMs work.

## Best Possible Solution

Keep this issue open until a live-verified Google Chat fix proves mentioned Space messages create and process `googlechat:group` sessions while preserving sender allowlists and explicit mention-gating safety.
