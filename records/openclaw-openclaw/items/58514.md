## Label Justifications

- `P1`: The issue reports a broken Google Chat Space workflow where accepted messages can be dropped before agent handling for affected users.
- `impact:message-loss`: Space messages are reported as received with HTTP 200 but no agent response, and current source still has a pre-session mention-gate skip path.
- `impact:session-state`: The failure mode is specifically missing `googlechat:group` session creation while Google Chat direct sessions work.

## Summary

Keep open: the modern Google Chat Space/DM classifier is now on main and in v2026.6.11, but the remaining report is still supported by current source and fresh user evidence: Space messages can be accepted by the webhook and then skipped before `googlechat:group` session creation when mention activation does not recognize the app mention.

## What This Changes

Google Chat Spaces should process mentioned group messages and create `googlechat:group` sessions instead of returning HTTP 200 and silently dropping them.

## Best Possible Solution

Keep this issue open as the canonical Google Chat Space ingress bug, land a live-verified plugin-local mention-detection or diagnostic fix, and only consolidate it once maintainers intentionally move the remaining Space routing work to a narrower canonical issue.
