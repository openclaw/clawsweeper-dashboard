## Label Justifications

- `P1`: The issue reports a broken Google Chat Space workflow where delivered messages can be accepted and then dropped before agent handling for real users.
- `impact:message-loss`: Space messages are reported as received by the webhook but silently produce no agent response unless mention gating is disabled.
- `impact:session-state`: The observed failure is missing `googlechat:group` session creation while direct-message sessions continue to be created.
- `impact:ux-friction`: The current failure mode is silent and the reported workaround requires manual configuration and restart steps rather than an in-product recovery path.

## Summary

Keep open: current main and v2026.6.11 include the merged Google Chat Space/DM classifier fix, but post-fix reporter evidence and current source still show a remaining path where delivered Space @mentions can be skipped by mention gating before a `googlechat:group` session or agent run is created.

## What This Changes

The issue requests that delivered Google Chat Space messages create and process `googlechat:group` sessions instead of returning HTTP 200 and being silently ignored while DMs work.

## Best Possible Solution

Keep this as the canonical Google Chat Space ingress bug until a live-verified plugin fix proves delivered @mentions create and process `googlechat:group` sessions, or maintainers explicitly consolidate the remaining mention/routing work into one narrower Google Chat item.
