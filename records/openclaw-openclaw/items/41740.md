## Summary

Keep open: current main and v2026.6.11 still omit `tlsFingerprint` from the shared operator-approval/bootstrap GatewayClient path, and https://github.com/openclaw/openclaw/pull/80204 is the active but conflicting/unmerged candidate fix.

## What This Changes

Discord exec approval resolution should pass the local self-signed Gateway TLS fingerprint into the GatewayClient when using a local `wss://` Gateway.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/80204 or a clean successor that centralizes TLS fingerprint resolution for bootstrap clients while preserving local, remote, CLI/env override, and non-WSS semantics.

Yes, at source level: current main routes Discord approval resolution through shared operator approval GatewayClient construction without `tlsFingerprint`, while `callGateway` resolves and forwards the local TLS pin. I did not run a live Discord approval repro in this read-only review.

## Solution Assessment

Yes on direction: the shared bootstrap resolver/pass-through path is the narrow maintainable fix because ACP, MCP, and native approval clients share this missing TLS fingerprint boundary. A Discord-only patch would be too narrow for the current architecture.
