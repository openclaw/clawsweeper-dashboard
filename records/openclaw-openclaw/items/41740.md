## Summary

Keep open: current main and `v2026.6.11` still omit `tlsFingerprint` from the shared bootstrap/operator-approval GatewayClient path, and the active candidate fix at https://github.com/openclaw/openclaw/pull/80204 is open but conflicting.

## What This Changes

Discord/native exec approval clients should pass the local Gateway TLS fingerprint when connecting to a local self-signed `wss://` Gateway.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/80204 or a clean successor that centralizes TLS fingerprint resolution for bootstrap clients while preserving local, remote, override, and non-WSS semantics.
