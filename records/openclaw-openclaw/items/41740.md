## Summary

Keep open: current main and v2026.6.11 still omit `tlsFingerprint` from the shared bootstrap/operator-approval GatewayClient path, and the active shared fix is https://github.com/openclaw/openclaw/pull/80204, which is open but dirty/unmerged.

## What This Changes

Discord exec approval handling should trust the local Gateway TLS fingerprint when resolving approvals against a local self-signed WSS Gateway.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/80204 or a clean successor that centralizes TLS fingerprint resolution for bootstrap clients and preserves local, remote, override, and non-WSS semantics.

## Solution Assessment

Yes on direction: the shared bootstrap resolver/pass-through path is the best fix because ACP, MCP, and native approval clients share this missing TLS fingerprint boundary. A Discord-only patch would be too narrow for the current architecture.
