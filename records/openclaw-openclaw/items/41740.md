## Summary

Keep open: current main and the latest release still omit `tlsFingerprint` from the shared operator-approval/bootstrap GatewayClient path, and https://github.com/openclaw/openclaw/pull/80204 is the active but dirty/unmerged candidate fix.

## What This Changes

Discord exec approval resolution should pass the local Gateway TLS fingerprint when connecting to a local self-signed WSS Gateway.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/80204 or a clean successor that centralizes TLS fingerprint resolution for bootstrap clients while preserving local, remote, override, and non-WSS semantics.

## Reproduction Assessment

Yes, at source level: current main routes Discord approval resolution through operator approval GatewayClient construction without `tlsFingerprint`, while the sibling `callGateway` path resolves and forwards the local TLS pin. I did not run a live Discord approval repro in this read-only review.

## Solution Assessment

Yes on direction: the shared bootstrap resolver/pass-through path is the best fix because ACP, MCP, and native approval clients share this missing TLS fingerprint boundary. A Discord-only patch would be too narrow for the current architecture.
