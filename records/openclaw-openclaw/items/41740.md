## Summary

Keep open: current main and v2026.6.11 still omit `tlsFingerprint` from the shared approval/bootstrap GatewayClient path, and https://github.com/openclaw/openclaw/pull/80204 is the active but conflicting candidate fix.

## What This Changes

The issue reports that Discord exec approvals fail against a local self-signed TLS Gateway because the approval GatewayClient path does not pass the local TLS fingerprint.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/80204 or a clean successor that centralizes TLS fingerprint resolution for bootstrap clients while preserving local, remote, override, and non-WSS semantics.

## Solution Assessment

Yes on direction: fixing the shared bootstrap resolver/pass-through is the narrow maintainable solution because ACP, MCP, and native approval clients share this missing TLS fingerprint boundary. A Discord-only patch would now be too narrow.
