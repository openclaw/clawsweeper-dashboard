## Summary

Keep open: current main and v2026.6.11 still omit tlsFingerprint from shared approval/bootstrap GatewayClient construction, while https://github.com/openclaw/openclaw/pull/80204 remains the active but conflicting candidate fix.

## What This Changes

The issue requests that Discord/native exec approval Gateway clients inherit the local self-signed WSS Gateway TLS fingerprint when local TLS is enabled.

## Best Possible Solution

Land a refreshed shared Gateway bootstrap TLS fingerprint propagation fix through https://github.com/openclaw/openclaw/pull/80204 or an equivalent branch, then close this issue from merged commit proof.

## Reproduction Assessment

Yes, at source level: local TLS selects a wss:// loopback target, callGateway can resolve the local TLS fingerprint, but shared approval/bootstrap clients construct GatewayClient without that option. I did not run a live Discord approval flow in this read-only review.

## Solution Assessment

Yes in direction: the maintainable fix is shared bootstrap TLS fingerprint propagation with local, remote, override, fallback, and non-WSS coverage. A Discord-only patch is now too narrow because Discord uses the shared operator approval Gateway path.
