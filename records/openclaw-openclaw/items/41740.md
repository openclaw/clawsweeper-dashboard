## Summary

Keep open: current main and v2026.6.11 still omit `tlsFingerprint` from shared approval/bootstrap `GatewayClient` construction, while the active candidate fix remains open, conflicting, and waiting on author follow-up.

## What This Changes

Discord exec approval resolution should trust the local self-signed WSS gateway by passing the resolved local TLS fingerprint into `GatewayClient`.

## Best Possible Solution

Land a narrow shared gateway TLS fingerprint propagation fix through https://github.com/openclaw/openclaw/pull/80204 or a clean successor, with regression coverage for local WSS, overrides, and non-TLS cases.

## Solution Assessment

Yes on direction, but the best fix is the shared bootstrap resolver shape from the active candidate PR rather than a Discord-only patch. The issue should stay open until that shared fix or an equivalent clean successor merges.
