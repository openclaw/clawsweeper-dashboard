## Summary

Keep open: current main and v2026.6.11 still omit `tlsFingerprint` from the shared approval/bootstrap `GatewayClient` path, and the active candidate fix remains open, dirty, and unmerged.

## What This Changes

The issue requests that Discord/operator approval Gateway clients propagate the local TLS certificate fingerprint when connecting to a local self-signed `wss://` Gateway.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/80204 or a clean successor that centralizes bootstrap TLS fingerprint resolution while preserving local, remote, CLI override, env override, and non-WSS semantics.
