## Summary

Keep this active PR open for maintainer review. The patch is a narrow, contract-aligned Telegram fix: current main still creates provider-visible drafts without checking modifying outbound hooks, while the plugin SDK now requires those hooks to settle before any preview becomes visible; the branch adds that missing guard without expanding the Plugin SDK.

## What This Changes

The PR disables Telegram answer and reasoning previews when `reply_payload_sending` or `message_sending` hooks are registered, while preserving previews for hook-free and observer-only setups.

## System Context

Telegram dispatch turns an agent response into an optional in-place preview and then final delivery. Outbound plugin hooks can rewrite or cancel the final payload, so preview creation must respect that delivery boundary to avoid exposing content that the hooks would change or suppress.

## Best Possible Solution

Land the narrow preview gate once sanitized after-fix Telegram evidence confirms both the no-leak modifying-hook path and the retained observer-only preview path; retain final hook-governed delivery as the sole visible route whenever a modifying hook is registered.
