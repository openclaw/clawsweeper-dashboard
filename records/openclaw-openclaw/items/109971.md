## Summary

Keep open: the latest commits resolve the prior reasoning and setup-propagation findings, but the dynamic resolver now accepts a model absent from the catalog when its only verification probe fails, contradicting the documented typo-rejection behavior and deferring failure to runtime.

## What This Changes

The PR adds a distinct failed-`/api/show` state across Ollama discovery, setup, and dynamic model resolution so failed inspection disables tools without suppressing reasoning name heuristics.

## Best Possible Solution

Apply the three-state capability behavior only where model existence is already established by `/api/tags` or a static catalog entry; unresolved dynamic model references must continue requiring successful `/api/show` metadata.
