## Summary

Keep open: current main and the latest release still allow Discord partial preview finals to complete by editing the existing preview message, and this issue has a distinct missed-completion-notification impact that is not fully owned by the related progress-preservation request.

## What This Changes

The issue asks OpenClaw to make Discord partial-streamed turns produce a visible completion notification or unread highlight when final content currently arrives via editing an existing preview message.

## Best Possible Solution

Have maintainers choose the Discord-owned partial-preview finalization policy, then implement it with default/upgrade behavior, docs and schema updates if config is added, focused tests, and live Discord proof.

## Reproduction Assessment

Yes. The reporter supplied a current Discord example with created/edited timestamps, and source inspection shows partial-mode finals can take the existing-preview edit path; I did not run a live Discord client unread test.

## Solution Assessment

Unclear. Sending or appending a fresh final message is likely the right notification primitive, but changing partial mode's edit-in-place contract or adding a finalization option needs maintainer UX and compatibility direction.
