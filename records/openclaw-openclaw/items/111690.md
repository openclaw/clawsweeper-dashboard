## Summary

Keep this PR open: its manual abort relay retains a listener and controller for every completed request that shares a long-lived caller signal, and the supplied live proof does not demonstrate the new automatic 30-second request deadline or 10-second proxy-connect deadline.

## What This Changes

The PR adds a 30-second request timeout, a 10-second proxy connection timeout, and caller-signal abort forwarding to the Anthropic Vertex Google-auth fetch implementation.

## Best Possible Solution

Compose the caller signal and request deadline without retaining listeners, preserve the shared dispatcher behavior, add regression coverage for completed requests sharing a long-lived signal, and provide redacted live transport evidence for both automatic timeout layers.

## Maintainer Decision

## Reproduction Assessment

Yes, for the introduced listener-retention defect: a caller can reuse one long-lived `AbortSignal` across successful auth requests, and each request leaves its abort listener attached. The original indefinite-hang report is source-reproducible on current main, but no current-main runtime reproduction was run in this read-only review.

## Solution Assessment

No. A request deadline is reasonable, but manually forwarding abort events is not the safest implementation because successful calls retain listener/controller pairs; a composed abort signal is narrower and preserves cancellation semantics without that lifetime leak.
