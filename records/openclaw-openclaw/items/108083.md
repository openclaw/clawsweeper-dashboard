## Summary

The source change is narrow and plausibly bounds a genuinely unbounded fetch, but this PR should remain open because its latest actual-app evidence shows the dashboard already rendering while the request is pending and does not demonstrate the claimed before/after startup or connection improvement. The timeout also creates a slow-deployment fallback contract that a Control UI owner should consciously accept before merge; likely related people are @drobison00 (high confidence, introduced the authenticated bootstrap retry path) and @BunsDev (medium confidence, substantial adjacent Control UI ownership).

## What This Changes

The PR adds a 15-second default abort deadline to each Control UI bootstrap configuration fetch attempt and adds focused tests for signal wiring and stalled-fetch fallback.

## Best Possible Solution

Keep the existing caller-cancellation seam, add an owner-approved bounded bootstrap deadline with explicit per-attempt versus whole-operation semantics, and prove an unpatched stalled endpoint blocks a concrete Control UI operation that the patched build recovers.
