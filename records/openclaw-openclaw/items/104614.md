## Summary

Current main still has a source-reproducible Discord-specific stale-config bug: agent default changes hot-reload without restarting the Discord monitor, while the model picker continues resolving its catalog and fallback current model from the monitor’s startup config snapshot. The issue is distinct from the linked session-snapshot, Control UI, and replace-mode reports, and no open fix PR or canonical duplicate currently owns it.

## What This Changes

Update Discord’s `/model` picker to reflect hot-reloaded default-model changes and describe stale picker interactions as expired rather than falsely unavailable.

## Best Possible Solution

At each Discord picker command or component interaction, obtain one current runtime-config snapshot and use it consistently for routing, catalog/default resolution, session lookup, and model application; when an older message references a selection absent from that refreshed snapshot, instruct the user to reopen `/model`.

## Reproduction Assessment

Yes at source level. A default-model change is dynamically applied without restarting Discord, but the picker’s no-override path resolves both catalog data and its current-model fallback from the monitor’s startup config object.

## Solution Assessment

Yes. Reusing the existing runtime-config snapshot at the interaction boundary is the narrowest maintainable fix; a Discord-only cache, models.json fallback, or session shim would duplicate state and preserve the underlying freshness bug.
