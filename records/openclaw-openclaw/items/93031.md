## Summary

Keep open: current main and v2026.6.11 still allow legacy/defaulted cron rows to persist with `agent_id` null, and the prior closing PR is closed unmerged. Current runtime falls back to the default agent for ownerless jobs, so the original scheduler-skip theory is not proven on current main, but the migration ownership gap still needs maintainer resolution.

## What This Changes

The issue asks OpenClaw to migrate legacy `jobs.json` cron jobs into SQLite with a nonblank/defaulted `agent_id` so upgraded jobs keep running after upgrade.

## Best Possible Solution

Decide the legacy cron ownership semantics, then repair the doctor/gateway migration path to either persist a config-aware owner or deliberately preserve ownerless fallback behavior with upgrade proof.

Rationale: Both choices are compatibility-sensitive for multi-agent installs: stamping a concrete owner fixes blank persisted rows but can freeze ownership to the migration-time default, while preserving ownerless rows keeps dynamic fallback semantics but leaves the reported SQLite shape unresolved.
