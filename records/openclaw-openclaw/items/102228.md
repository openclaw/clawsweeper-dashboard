## Summary

This remains a necessary, unique RFC-stack slice that current main does not implement, but the exact head is not merge-ready: skill packages remain unreachable, plugin security checks still occur after durable Claw mutation, the generated database type omits authoritative columns, and only test-based proof is supplied. ## What This Changes

Adds exact-version ClawHub skill and plugin installation to experimental Claw creation, persists ownership-aware package references in shared SQLite state, and exposes dependent-Claw warnings through shared plugin uninstall paths.

## Best Possible Solution

Create one canonical read-only package resolution phase that completes identity, version, trust, and safety decisions for both skills and plugins before any durable mutation; carry approved immutable install inputs into execution, regenerate and consume the complete Kysely state contract, then prove live add, reuse, conflict, partial-failure, drift-warning, fresh-install, and upgrade behavior on the final stacked head.
