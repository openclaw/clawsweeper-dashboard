## Summary

## What This Changes

This draft wires Claw plugin entries into the existing plugin install command during `claws apply --yes`, tracks direct-vs-Claw artifact ownership, and changes plugin uninstall to detach direct ownership when Claw refs remain.

## Best Possible Solution

Keep the installer delegation through the existing plugin command path, but make artifact ownership and apply ordering atomic enough that every installed plugin is either correctly Claw-owned, correctly direct-owned, or rolled back before returning failure.

## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Preserve Claw ownership when reusing installed artifacts:** `src/claws/artifact-installers.ts:120-122`
  - body: This treats any plugin already present in install records as a direct user install. If a previous Claw apply created the plugin, reapplying that Claw or applying another Claw that references it will set `preexistingDirectInstall`, inflate `refCount`, and allow `plugins uninstall` to detach a direct owner that never existed. Check existing Claw refs before adding the artifact key to `directArtifactKeys`.
  - confidence: 0.9
- **[P1] Record or roll back plugin installs before workspace failures:** `src/cli/claws-cli.runtime.ts:249`
  - body: The CLI installs plugin artifacts before workspace writes, but only persists Claw artifact provenance after workspace writes succeed. A later workspace conflict or IO error therefore leaves the plugin installed as a direct install with no Claw ref, so Claw remove/audit cannot clean up the partial apply. Preflight later mutations first, or persist and roll back artifact ownership as part of the same apply contract.
  - confidence: 0.88
