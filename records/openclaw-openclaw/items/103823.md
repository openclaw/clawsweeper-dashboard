## Label Justifications

- `P1`: The reported race can execute the same orphaned subagent's tools, file edits, external actions, and model work twice during restart recovery.

## Summary

The normal concurrent-scan race is convincingly reproduced and the per-child claim is narrower than serializing all recovery, but the patch still permits duplicate execution when the first resume is accepted and its persisted marker update fails.

## What This Changes

The PR adds a process-wide per-session in-flight claim and fresh session-entry recheck to prevent concurrent orphan-recovery scans from resuming the same child twice, with a regression test.

## Best Possible Solution

Keep the child-keyed concurrency boundary, but add generation-aware accepted-resume de-duplication that survives marker-write failure without suppressing recovery for a later genuine interruption, plus a delayed-overlap regression for that failure path.
