## Summary

Current main has implemented most of the original organization layer—custom session groups, pin/rename/archive/delete actions, batch session triage, whole-session forks, and split-pane chat—but still lacks selected-message branch/move semantics and multi-target composer fanout. The remaining work is useful, but it should be narrowed and requires a maintainer product decision because transcript edits must preserve the session DAG and VISION.md favors lean, session-first primitives over a new hierarchy framework.

## What This Changes

Add project-tree session organization, routed or fanned-out composer entry points, selected-message split/move triage, and cross-project context seeding in Control UI.

## Best Possible Solution

Narrow this issue to a session-first contract for DAG-safe selected-message branch/copy and optional typed route targets, reusing current custom groups, whole-session forks, lifecycle actions, and split panes rather than introducing a broad Project hierarchy.
