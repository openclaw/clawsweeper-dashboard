## Summary

Current main now covers substantial session organization—custom groups, naming and lifecycle actions, parent/fork relationships, checkpoint branches, and multi-pane viewing—but it still does not implement selected-message split/move, seed-to-another-project semantics, or one composer send routed to multiple contexts. Those remaining behaviors require an explicit product decision about durable project identity and transcript-copy semantics, so this issue remains useful rather than being fully implemented or superseded.

Likely related people:
- @steipete — high confidence; authored the merged session-thread-management work and has reviewed this issue’s product boundary.

## What This Changes

Add project-tree organization, context-targeted or fanout composer sends, selected-message thread splitting, and cross-project context seeding to the Control UI.

## Best Possible Solution

Choose one additive project/thread metadata model, then extend the existing session-group, parent/fork, checkpoint-branch, and split-pane paths with explicit partial-transcript copy semantics and a typed multi-target send contract, including Gateway, UI, upgrade, and browser behavior proof.

Options:

- **First-class project metadata (recommended):** Add additive project identity and branch lineage to the Gateway session model, then build tree navigation, selected-context copying, and routed sends on that canonical model.
- **Extend custom groups only:** Treat projects as existing custom session groups and limit the feature to navigation and organization without cross-project transcript or fanout semantics.
- **Split the product tracks:** Keep project organization, partial-transcript branching, and multi-target sends as separate canonical features with independently reviewed contracts.
