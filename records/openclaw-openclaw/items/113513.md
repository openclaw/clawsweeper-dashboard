## What This Changes

This PR extracts the guarded-fetch redirect loop’s physical one-hop request into an internal dispatcher and passes a validated `network-guard/v1` profile that records the already-decided route, DNS, TLS, and address-policy constraints.

## System Context

OpenClaw’s guarded-fetch layer evaluates an outbound URL against SSRF policy, chooses direct or proxy transport and DNS ownership, then performs one redirect-controlled HTTP exchange. This PR places a validated representation of those security decisions between route selection and the physical fetch so another connection owner could eventually consume it.
