## Summary

Keep open: the terminal-boundary timeout notice is useful and has real setup proof, but the current branch can still emit a duplicate timeout error after a `message_tool_only` source reply was already delivered because the new gate omits `didDeliverSourceReplyViaMessageTool`.

## What This Changes

## Best Possible Solution

Preserve the terminal-boundary notice, but have its suppression gate use the shared terminal-output/source-reply evidence and add a timed-out source-reply regression before merge.

## Reproduction Assessment

Yes, source-level. A timed-out attempt with `didDeliverSourceReplyViaMessageTool: true`, no mirror payloads, and no ordinary messaging-tool evidence can reach the new notice branch before the shared terminal path preserves source-reply suppression.

## Solution Assessment

No, not yet. The embedded-runner terminal boundary is the right layer for the notice, but the gate needs to preserve the existing source-reply delivery terminal state before this is the best fix.
