## Summary

Keep open: the timeout notice fix is useful and has real-behavior proof, but the current head still omits source-reply delivery evidence from the new notice gate, so `message_tool_only` runs can receive a duplicate timeout error after a visible source reply already landed.

## What This Changes

Adds an embedded-runner turn-budget and idle-timeout notice branch, a pure helper, and regression coverage for timed-out no-payload turns.

## Best Possible Solution

Keep the terminal-boundary timeout notice, but gate it on delivered source-reply evidence as well and add a focused regression for timed-out message-tool-only source replies.

## Reproduction Assessment

Yes, at source level. A timed-out attempt with `didDeliverSourceReplyViaMessageTool: true`, no mirror payloads, and no ordinary messaging-tool evidence can reach the new notice branch before the terminal path preserves source-reply suppression.

## Solution Assessment

No, not quite. The embedded-runner terminal boundary is the right layer for the notice, but the best fix must preserve delivered source-reply evidence in the new gate.
