## Summary

Needs changes before merge: the latest head fixes the client-tool and yield terminal-state gap, but the new timeout-notice gate still omits the existing delivered source-reply terminal-output signal, so it can duplicate a visible `message_tool_only` reply with an extra timeout error.

## What This Changes

The PR adds a user-visible embedded-agent timeout notice for no-payload turns that exhaust the agent time budget or run deadline.

## Best Possible Solution

Keep the terminal-boundary timeout notice, but gate it on delivered source-reply evidence as well and add a focused regression for `timedOut` plus `didDeliverSourceReplyViaMessageTool`.

## Reproduction Assessment

Yes, at source level. A timed-out attempt with `didDeliverSourceReplyViaMessageTool: true`, no mirror payloads, and no ordinary messaging-tool evidence can still reach the new timeout-notice branch before the terminal path suppresses automatic replies.

## Solution Assessment

No, not quite. The embedded-runner terminal boundary is the right layer for the notice, but the gate needs to preserve the existing delivered source-reply terminal state before this is the best fix.
