## Label Justifications

- `P1`: A documented outbound interception hook can silently fail open for Feishu/plugin users, including safety and rewrite plugins.
- `impact:security`: Plugins relying on `message_sending` for moderation, DLP, audit, or cancellation can be bypassed on the affected Feishu auto-reply path.
- `impact:message-loss`: Plugin hook decisions and lifecycle events can be silently dropped even when the visible Feishu message is delivered.
- `impact:session-state`: Post-send analytics, audit, and usage-tracking plugins can miss outbound sends, causing downstream session projections to drift.

## Summary

Keep open: current main covers the durable `message` send path through shared outbound delivery, but Feishu auto-reply still enters `dispatchReplyFromConfig` with a prebuilt dispatcher that never gets the `message_sending` hook, and normal-channel `inbound_claim` expansion remains an unresolved plugin API/security decision.

## What This Changes

The issue requests Feishu auto-reply and durable message sends to invoke outbound plugin hooks, and asks normal Feishu inbound traffic to emit `inbound_claim`.

## Best Possible Solution

Split the work: land Feishu outbound hook parity through the shared dispatcher hook seam, keep durable-send behavior aligned with shared outbound delivery, and decide normal `inbound_claim` expansion as a separate plugin API/security contract.
