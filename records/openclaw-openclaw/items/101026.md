## Label Justifications

- `P1`: A documented outbound interception hook can silently fail open for real Feishu/plugin users, including safety and rewrite plugins.
- `impact:security`: Plugins that rely on `message_sending` for moderation, DLP, audit, or cancellation can be bypassed on the affected Feishu auto-reply path.
- `impact:message-loss`: Plugin hook decisions and lifecycle events can be silently dropped even when the visible Feishu message is delivered.
- `impact:session-state`: Post-send analytics, audit, and usage-tracking plugins can miss outbound sends, causing downstream projections to drift from actual channel traffic.

## Summary

Keep open: current main still leaves the Feishu prebuilt auto-reply dispatcher outside the `message_sending` before-deliver chain, while durable `message` sends now go through shared outbound delivery for `message_sending`/`message_sent`; normal-channel `inbound_claim` remains a plugin API/security decision rather than an implemented fix.

## What This Changes

The issue requests uniform plugin hook coverage for Feishu auto-replies, durable `message` tool sends, and normal Feishu inbound claim handling.

## Best Possible Solution

Split the work: land a narrow outbound hook parity fix that keeps Feishu on the same exactly-once `message_sending` path as other channel replies, and handle normal-channel `inbound_claim` as a separate plugin API/security decision.
