## Summary

Keep open: current main still leaves Feishu auto-reply and comment dispatch on a prebuilt `dispatchReplyFromConfig` path where `message_sending` is not installed, while the durable `message` send path now delegates into the hook-aware shared outbound layer. The remaining work needs maintainer selection because the narrow outbound parity fix should be separated from the broader normal-channel `inbound_claim` API/security decision.

## What This Changes

The issue asks OpenClaw to restore plugin outbound hook coverage for Feishu auto-reply and `message` sends, and to decide whether normal Feishu inbound traffic should emit `inbound_claim`.

## Best Possible Solution

Land one maintainer-selected outbound parity fix that covers Feishu auto-reply and comment dispatch with exactly-once hook semantics, while tracking normal-channel `inbound_claim` as a separate plugin API/security decision.
