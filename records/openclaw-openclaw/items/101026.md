## Summary

Keep open: current main and v2026.6.11 still leave the Feishu prebuilt auto-reply/comment dispatcher path without `message_sending`, while the durable `message` path now routes through shared outbound delivery hooks. The remaining work should be split from the broader normal-channel `inbound_claim` API/security decision and coordinated with the open canonical outbound-hook PRs.

## What This Changes

The issue asks for Feishu auto-reply, durable `message` sends, and normal inbound traffic to invoke the documented outbound and inbound plugin hooks consistently.

## Best Possible Solution

Split the work: land one maintainer-chosen exactly-once outbound hook parity fix that preserves the Feishu auto-reply/comment acceptance criteria, and track normal-channel `inbound_claim` as a separate plugin API/security decision.
