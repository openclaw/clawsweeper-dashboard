## Label Justifications

- `P1`: A documented outbound interception hook is silently bypassed on real Feishu reply paths used by plugin-based channel workflows.
- `impact:message-loss`: Bypassed send hooks can prevent plugins from rewriting, cancelling, or observing outbound messages before delivery.

## Summary

Keep open: current main still leaves the Feishu prebuilt-dispatcher auto-reply and comment paths without the documented `message_sending` gate, while the durable `message` tool path now routes through the shared outbound hook layer. The remaining outbound bug should stay coordinated with the existing `message_sending` bypass PRs, and the normal-channel `inbound_claim` request needs a separate plugin API/security decision.

## What This Changes

The issue requests uniform Feishu outbound hook coverage for auto-replies and durable sends, plus broader normal-channel `inbound_claim` behavior for passive observer plugins.

## Best Possible Solution

Split the work: land one canonical exactly-once outbound hook fix that preserves the Feishu auto-reply and comment acceptance criteria, keep durable sends on the shared outbound path, and track normal-channel `inbound_claim` as a separate plugin API/security decision.
