## Label Justifications

- `P1`: The issue describes a source-reproducible silent hook-coverage regression on a real Feishu outbound workflow used by downstream plugins.

## Summary

Keep open: current main has moved the durable `message` path back onto shared outbound delivery hooks, but Feishu auto-reply and comment dispatch still pass prebuilt dispatchers that do not install `message_sending`, and normal-channel `inbound_claim` remains a separate plugin API/security decision.

## What This Changes

The issue asks OpenClaw to restore outbound plugin hook coverage for Feishu auto-reply and `message` sends, and to make `inbound_claim` available on normal inbound channel traffic.

## Best Possible Solution

Split the work: land one canonical outbound hook parity fix for Feishu/configured dispatchers, keep durable message sends on shared outbound delivery, and track normal-channel `inbound_claim` as a separate plugin API/security decision.
