## Summary

Keep open: current main still leaves the Feishu prebuilt-dispatcher auto-reply and comment paths without `message_sending`, while the durable `message` path now routes through shared outbound delivery hooks. The normal-channel `inbound_claim` request is a separate plugin API/security decision, so this is not safe to close or auto-repair as one narrow bug.

## What This Changes

The issue asks OpenClaw to run documented outbound plugin hooks on Feishu auto-reply and durable message sends, and to decide whether normal Feishu inbound should emit `inbound_claim` outside plugin-owned bindings.

## Best Possible Solution

Split the work: keep this issue as Feishu-specific outbound hook evidence, land one maintainer-selected exactly-once outbound hook fix through the shared hook-bypass track, and track normal-channel `inbound_claim` as a separate plugin API/security decision.
