## Label Justifications

- `P1`: A documented outbound interception hook can silently fail open for real Feishu/plugin users, including rewrite, cancellation, and safety plugins.
- `impact:security`: Plugins that rely on `message_sending` for moderation, DLP, audit, or cancellation can be bypassed on the affected Feishu auto-reply path.
- `impact:message-loss`: Plugin rewrite/cancel decisions and lifecycle hook observations can be silently skipped even when the visible Feishu message is delivered.
- `impact:session-state`: Post-send analytics, audit, and usage-tracking plugins can miss outbound sends and drift from actual channel traffic.

## Summary

Keep open: current main still leaves the Feishu auto-reply/comment dispatcher path outside the documented `message_sending` before-deliver hook, while the durable `message` path is now routed through shared outbound delivery and normal-channel `inbound_claim` remains a separate plugin API/security decision.

## What This Changes

The issue asks OpenClaw to run documented outbound plugin hooks on Feishu auto-reply and message-tool sends, and to broaden `inbound_claim` beyond plugin-owned bindings.

## Best Possible Solution

Split the work: land a narrow Feishu outbound hook parity fix through the shared dispatcher/channel seam with coverage for bot and comment replies, keep durable `message` sends on shared outbound delivery, and track normal-channel `inbound_claim` broadening as a separate plugin API/security decision.
