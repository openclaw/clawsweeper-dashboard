## Summary

Keep open: current main still leaves the Feishu prebuilt auto-reply dispatcher without `message_sending`, while the durable `message` path now goes through shared outbound delivery hooks. The outbound parity work should stay separate from the normal-channel `inbound_claim` API/security decision.

## What This Changes

The issue requests uniform `message_sending`, `reply_payload_sending`, `message_sent`, and normal-channel `inbound_claim` hook coverage for Feishu auto-reply and message-tool outbound flows.

## Best Possible Solution

Split the work: land one canonical exactly-once outbound hook fix that preserves the Feishu auto-reply and comment-path acceptance criteria, and track normal-channel `inbound_claim` broadening as a separate plugin API/security decision.
