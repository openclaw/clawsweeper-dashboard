## Label Justifications

- `P1`: A documented outbound interception hook can silently fail open for real Feishu/plugin users, including safety and rewrite plugins.
- `impact:security`: Plugins that rely on `message_sending` for moderation, DLP, audit, or cancellation can be bypassed on the affected Feishu auto-reply path.
- `impact:message-loss`: Plugin hook decisions and lifecycle events can be silently dropped even when the visible Feishu message is delivered.
- `impact:session-state`: Post-send analytics, audit, and usage-tracking plugins can miss outbound sends, causing downstream projections to drift from actual channel traffic.

## Summary

Keep open: current main partially repaired the durable `message` path through the shared outbound delivery layer, but Feishu auto-reply still uses a prebuilt channel dispatcher that never gets the `message_sending` before-deliver hook, and the requested normal-channel `inbound_claim` behavior remains a plugin API/product decision rather than an implemented fix.

## What This Changes

Issue requests consistent `message_sending`, `reply_payload_sending`, `message_sent`, and `inbound_claim` plugin hook coverage for Feishu auto-reply, durable `message` sends, and normal Feishu inbound traffic.

## Best Possible Solution

Split the work: land a narrow Feishu outbound `message_sending` parity fix through the shared dispatcher hook seam, keep durable-send hook behavior aligned with `deliverOutboundPayloadsInternal`, and decide normal `inbound_claim` expansion as a separate plugin API contract.
