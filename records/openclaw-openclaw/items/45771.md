## Summary

Keep open. Current main has provider usage visibility and reactive auth-profile cooldown/failover, but it still lacks the requested Anthropic response-header capture, pace-tier projection, pace config, status/session_status pace output, and autonomous throttling policy.

## What This Changes

The issue requests built-in pace-aware rate limiting for autonomous agents using Anthropic usage headers, projected pace tiers, status/session_status visibility, and optional throttling controls.

## Best Possible Solution

Define a provider usage/pace contract and observability-first status/session surface, then add opt-in throttling only after maintainers decide config, persistence, and recovery semantics.
