## Summary

Keep open: current main has provider usage visibility and reactive rate-limit/cooldown handling, but it does not implement pace projection, response-header capture, durable pace state, `agents.defaults.pace`, autonomous throttling, or structured `session_status` pace data.

## What This Changes

Request built-in Anthropic/provider pace awareness for autonomous agents, including usage-window capture, projected pace tiers, status/session_status exposure, and optional throttling config.

## Best Possible Solution

Define a maintainer-scoped design that reuses existing provider usage/status surfaces, adds visibility first, and only then introduces opt-in pace admission with durable SQLite state and explicit upgrade-safe config semantics.
