## Summary

Keep open: current main and the latest stable release still expose provider usage windows and reactive auth-profile cooldowns, but they do not implement pace projection tiers, persisted pace state, `agents.defaults.pace`, status/session_status pace output, or autonomous-agent throttling policy; related rate-limit, budget, and provider-pool issues overlap without replacing this specific request.

## What This Changes

Add built-in pace-aware rate limiting for autonomous agents by capturing Anthropic usage signals, projecting 5h/7d pace, surfacing it in status/session_status, and optionally throttling subagents.

## Best Possible Solution

Have maintainers scope a visibility-first pace contract that reuses provider usage hooks, starts with status/session_status context, and adds opt-in throttling or persistence only after the provider/state/config boundary is chosen.
