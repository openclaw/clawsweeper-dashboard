## Summary

Issue #45771 remains open because current main exposes provider usage summaries and reactive cooldown/failover, but it does not implement Anthropic response-header capture, projected pace states, structured pace data in status/session_status, or autonomous admission controls; the work is still a product/API design question rather than a small repair.

## What This Changes

Request built-in pace-aware rate limiting for autonomous agents, including Anthropic quota-header usage projection, visible pace state, and optional autonomous throttling or blocking.

## Best Possible Solution

Approve a visibility-first design that captures provider usage windows at the right provider seam and exposes projected pace in status/session_status, then add opt-in admission controls only after maintainers choose config semantics and SQLite-backed state ownership.
