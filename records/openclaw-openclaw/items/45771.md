## Summary

Keep open. Current main has provider usage-window visibility and reactive rate-limit cooldown/failover, but the requested pace-tier projection, Anthropic response-header capture, persisted pace state/config, status/session_status pace output, and autonomous throttling policy remain absent and need maintainer product/API scoping.

## What This Changes

Request built-in Anthropic/provider usage pace tracking, pace-tier projection, status/session_status surfacing, and optional autonomous subagent throttling.

## Best Possible Solution

Define an observability-first provider usage/pace contract, then add disabled-by-default enforcement only after maintainers choose the config, persistence, provider-scope, and recovery semantics.
