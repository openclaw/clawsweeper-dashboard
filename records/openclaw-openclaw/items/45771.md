## Summary

Keep open. Current main has provider usage/quota visibility and reactive auth-profile cooldowns, but it still lacks the requested pace-tier projection, Anthropic response-header capture, persisted pace policy/state, status/session_status pace reporting, and autonomous throttling behavior; the remaining work needs maintainer product/API scoping before implementation.

## What This Changes

The issue requests built-in pace-aware rate limiting for autonomous agents, including provider quota projection, status visibility, configurable thresholds, and throttling behavior.

## Best Possible Solution

Define a maintainer-approved pace policy contract first, preferably advisory status/session_status visibility with provider-owned quota metadata before any opt-in blocking or throttling mode is added with migration and upgrade tests.
