## Summary

Keep open: current main and the latest release expose provider usage/quota summaries and reactive provider cooldown/failover, but they do not implement Anthropic response-header capture, projected pace tiers, structured pace data in `session_status`, or autonomous admission controls. The issue is still a product/API/config design question, not a safe cleanup close.

## What This Changes

Request to add built-in Anthropic-aware usage pace tracking, projected quota burn, status/session_status reporting, and optional throttling for autonomous agent work.

## Best Possible Solution

Approve a visibility-first design that captures provider quota/usage at the right provider seam and exposes projected pace in status/session_status, then add opt-in admission controls only after maintainers choose config, persistence, and provider-contract semantics.
