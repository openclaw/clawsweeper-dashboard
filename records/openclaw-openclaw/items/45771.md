## Summary

Keep open. Current main and the latest release have provider usage visibility plus reactive auth-profile cooldown/fallback behavior, but they do not implement pace projection tiers, persisted pace state, `agents.defaults.pace`, status/session_status pace output, or autonomous-agent throttling policy; related issues and the open provider-rate-limit PR overlap but do not replace this specific pace-governance request.

## What This Changes

Request built-in pace-aware rate-limit visibility and autonomous-agent throttling based on provider utilization windows.

## Best Possible Solution

Scope a visibility-first core design that reuses provider usage hooks, keeps provider-specific capture in provider boundaries, and adds opt-in throttling or persistence only after maintainers define safe defaults and upgrade behavior.
