## Summary

Keep open. Current main exposes provider usage snapshots and reactive auth-profile cooldown/failover, but it still lacks the requested Anthropic rate-limit header capture, pace-tier projection, pace config, status/session_status pace output, and autonomous throttling policy; this remains a product/API scoping item rather than conservative cleanup.

## What This Changes

Add built-in pace-aware usage tracking, projection, status output, and optional autonomous throttling for agents based on Anthropic/provider usage windows.

## Best Possible Solution

Define an observability-first provider usage/pace contract, then add opt-in enforcement only after maintainers choose config, persistence, and recovery semantics.
