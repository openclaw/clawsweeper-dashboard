## Summary

Keep open. Current main has provider usage-window visibility and reactive auth-profile cooldown/block handling, but it still lacks the requested response-header capture, pace-tier projection, persisted pace state/config, status/session_status pace output, and autonomous throttling policy.

## What This Changes

Requests built-in pace tracking for provider usage windows, projected pace tiers, status/session_status output, and optional throttling for autonomous agents.

## Best Possible Solution

Define an observability-first, provider-agnostic pace contract for usage windows, then add disabled-by-default enforcement only after maintainers choose config, persistence, provider-scope, and recovery semantics.
