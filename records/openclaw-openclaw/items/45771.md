## Summary

Keep open. Current main has provider usage visibility and reactive auth-profile cooldown/failover, but the requested pace-tier projection, Anthropic response-header capture, pace config, status/session_status pace output, and autonomous throttling policy remain absent; this needs maintainer product/API scoping.

## What This Changes

Request to add built-in pace-aware provider usage tracking and throttling for autonomous agents, including Anthropic usage capture, projected pace tiers, new agent config, status output, and session_status integration.

## Best Possible Solution

Define a core/provider usage contract and observability-first status surface first, then add opt-in autonomous throttling only after maintainers decide the config, persistence, and recovery semantics.
