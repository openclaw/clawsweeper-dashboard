## Summary

Keep open: current main has provider usage snapshots and status rendering, but it does not implement response-header pace capture, projected pace tiers, durable pace state, `agents.defaults.pace`, autonomous throttling, or structured `session_status` pace data.

## What This Changes

Add built-in provider pace tracking from Anthropic usage headers/windows, status and `session_status` exposure, and autonomous-agent throttling based on projected quota consumption.

## Best Possible Solution

Define a maintainer-scoped design that reuses existing provider usage/status surfaces, adds visibility first, and only then introduces opt-in pace admission with durable SQLite state and explicit upgrade-safe config semantics.
