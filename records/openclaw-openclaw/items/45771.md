## Summary

Keep open. Current main and the latest release expose provider usage windows plus reactive cooldown/failover, but the requested response-header capture, pace projection/tiering, persisted pace state/config, status/session_status pace output, and autonomous throttling policy remain absent and need maintainer product/API scoping.

## What This Changes

Request built-in pace-aware Anthropic/provider usage tracking for autonomous agents, including status visibility, session_status context, persisted state/config, and optional subagent throttling.

## Best Possible Solution

Define an observability-first provider usage/pace contract and status/session_status output, then add disabled-by-default enforcement only after the config, persistence, provider-scope, and recovery semantics are approved.
