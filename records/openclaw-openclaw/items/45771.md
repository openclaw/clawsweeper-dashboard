## Summary

Keep open. Current main exposes provider usage windows and reactive auth-profile cooldowns, but the requested Anthropic response-header capture, persisted pace/projection state, pace config, status/session_status contract, and autonomous throttling policy remain absent.

## What This Changes

Request built-in pace-aware provider quota tracking and optional autonomous throttling for agents.

## Best Possible Solution

Start with a maintainer-approved visibility/context phase that reuses provider usage snapshots for status/session_status, then make any throttling opt-in with upgrade-safe config and recovery UX.

Options:

- **Visibility/context first (recommended):** Expose pace context through provider usage, status, and session_status without automatic blocking, then revisit throttling after the data model proves useful.
- **Full opt-in throttling:** Design a core policy that persists pace state and gates subagents or non-interactive work only behind explicit upgrade-safe config.
- **Plugin/API primitives only:** Keep Anthropic-specific pacing policy outside core and add only the generic provider usage or admission hooks that plugins cannot currently express.

## Solution Assessment

Unclear until scope is approved; visibility/context is the narrowest maintainable first step, while automatic blocking needs explicit policy because it can interrupt autonomous work.
