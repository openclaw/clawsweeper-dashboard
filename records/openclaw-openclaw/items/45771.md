## Summary

Keep open. Current main and v2026.6.11 provide Anthropic/provider usage-window visibility and reactive cooldown/failover, but they still lack pace-tier projection, Anthropic response-header capture, persisted pace policy/config, status/session_status pace fields, and autonomous throttling semantics.

## What This Changes

The issue requests built-in Anthropic pace-aware usage tracking, status visibility, and autonomous-agent throttling based on rate-limit utilization windows.

## Best Possible Solution

Define a generic, observability-first pace contract for provider usage windows, then add disabled-by-default enforcement only after maintainers choose the provider scope, config shape, persistence owner, and recovery semantics.
