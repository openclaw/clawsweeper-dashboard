## Summary

Keep open. Current main has provider usage visibility and reactive auth-profile cooldown/failover, but the requested pace-tier projection, Anthropic response-header capture, pace config, persisted pace state, status/session_status pace output, and autonomous throttling policy remain absent and need maintainer product/API scoping.

## What This Changes

The issue requests built-in pace-aware Anthropic usage tracking and autonomous-agent throttling based on projected 5-hour and 7-day quota consumption.

## Best Possible Solution

Define a provider usage/pace contract and observability-first status surface before adding opt-in autonomous throttling with explicit config, persistence, and recovery semantics.
