## Summary

Keep this PR open, but it is not merge-ready: the slash picker is useful iOS UX, yet the current head still scopes the catalog to the default agent and adds client-side fail-closed command validation before Gateway command parsing, with only screenshot proof for the visible UI.

## What This Changes

Adds an iOS/shared Swift slash-command picker backed by `commands.list`, including filtering, selection, send-time validation, Swift tests, and screenshot assets.

## Best Possible Solution

Keep the picker as discovery and selection UI, thread active-agent/session context into the catalog request, and leave command parsing and authorization with the Gateway unless maintainers explicitly define a stricter client validation contract.

## Reproduction Assessment

Yes, source-reproducible: current iOS supports agent-scoped chat session keys, while the PR calls `commands.list` without `agentId` and then blocks uncataloged slash text before `chat.send`. I did not run the iOS app because this was a read-only review.

## Solution Assessment

No. The picker itself is a plausible UX improvement, but the best fix should mirror the existing TUI pattern by using the catalog for discovery while keeping active-agent scoping and final command authority in the Gateway.
