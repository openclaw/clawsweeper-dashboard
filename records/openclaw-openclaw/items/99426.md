## Label Justifications

- `P2`: This is a normal-priority user-facing iOS feature with limited blast radius, but it has concrete command delivery and compatibility blockers.
- `merge-risk: 🚨 compatibility`: The new picker validates against a catalog request that is default-agent scoped even when iOS chat is using a non-default agent session.
- `merge-risk: 🚨 message-delivery`: The new send-time validation can block slash-prefixed drafts before `chat.send` reaches the Gateway.

## Summary

Keep open: the picker is a useful iOS discoverability feature, but the patch is not merge-ready because it validates against the wrong command authority and can suppress messages before the Gateway sees them.

## What This Changes

Adds an iOS/shared Swift slash-command picker backed by `commands.list`, with filtering, selection, send-time validation, Swift tests, and screenshot assets.

## Best Possible Solution

Keep the picker as discovery and selection UI, thread selected-agent context into the catalog request, and leave command parsing/authorization with the Gateway unless maintainers add an explicit validation contract.

## Reproduction Assessment

Yes, source-reproducible: current iOS supports agent-scoped chat session keys, while the PR calls `commands.list` without `agentId` and then blocks uncataloged slash text before `chat.send`. I did not run the iOS app because this was a read-only review.

## Solution Assessment

No. The picker itself fits the existing command discovery direction, but the best fix should mirror the TUI pattern: use the catalog for autocomplete/selection while keeping command parsing and authorization in the Gateway.
