## Summary

Keep open: current main still exposes `subagents list` as a direct-controller listing with descendant summaries, but no depth/recursive API that returns nested worker rows.

## What This Changes

Requests a `--depth` or `--recursive` option for subagent listing so a parent orchestrator can inspect nested descendant agents.

## Best Possible Solution

Define a maintainer-approved read-only descendant listing that keeps direct-child listing as the default, adds explicit depth/recursive output with parent/depth metadata, reuses existing descendant traversal, and does not expand mutation permissions.

## Reproduction Assessment

Yes, at source level. Current main has no `depth` or `recursive` parameter on the `subagents` tool or slash-command path, and the list implementation receives direct controlled runs while only summarizing descendants.

## Solution Assessment

Unclear until maintainers choose the API semantics. A depth flag is plausible, but the best fix should align with broader session-chain work and preserve existing control boundaries.
