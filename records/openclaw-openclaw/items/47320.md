## Summary

Keep open: current main and v2026.6.11 still expose `subagents` as a direct requester listing with descendant counts only, and recursive/depth listing remains an additive public API decision.

## What This Changes

Request adds `--depth`/`--recursive` and an equivalent tool parameter so a parent agent can list nested subagent rows with hierarchy metadata.

## Best Possible Solution

Define an additive read-only descendant listing that keeps direct-child listing as the default, returns flattened rows with parent/depth metadata for explicit depth or recursive calls, and does not expand mutation permissions.
