## Summary

Keep open: current main and the latest release still expose `subagents list` as a direct-child view with no public `depth` or `recursive` parameter. The request is valid, but it remains a feature/product decision because recursive ancestor visibility should align with the open session-chain work without broadening kill, steer, send, focus, or stop permissions.

## What This Changes

Request adds `--depth`/`--recursive` support and a tool-call `depth` option to `subagents list` so an ancestor agent can inspect nested subagent labels, status, runtime, model, task, and hierarchy metadata.

## Best Possible Solution

Define a read-only descendant listing contract that keeps direct-child listing as the default, adds explicit bounded depth or recursive expansion plus parent/depth metadata, and reuses canonical lineage/traversal without expanding control permissions.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 have no `depth` or `recursive` parameter on the `subagents` tool or slash-command list path, and the list implementation receives direct controlled runs while only summarizing descendants.

## Solution Assessment

Unclear until maintainers choose the API semantics. A depth flag is plausible, but the maintainable fix should align with the broader session-chain issue and keep recursive read visibility distinct from descendant control permissions.
