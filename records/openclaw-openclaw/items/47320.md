## Summary

Keep open: current main and v2026.6.11 still expose `subagents` as a direct-controller listing with descendant counts only, and the requested depth/recursive API remains a product/API decision.

## What This Changes

Add a `depth` or `recursive` option to `subagents list` and the model-facing `subagents` tool so parent agents can inspect nested worker subagents.

## Best Possible Solution

Define an additive read-only descendant listing that keeps direct-child listing as the default, returns flattened rows with parent/depth metadata for explicit depth or recursive calls, and does not expand mutation permissions.
