## Summary

Keep open: current main has targeted host-environment sanitization and an app-server `clearEnv` blocklist, but no positive OpenClaw allowlist governing inherited variables across spawn boundaries. The request fits the security roadmap, but the configuration shape and backward-compatible defaults require explicit maintainer direction.

## What This Changes

Add an opt-in positive allowlist controlling which gateway environment variables reach exec commands, spawned agent processes, and the Codex app-server.

## Best Possible Solution

Define one canonical, compatibility-preserving process-environment policy with explicit inheritance and include/exclude semantics, apply it only at verified OS spawn boundaries, and map Codex behavior onto its upstream `shell_environment_policy` contract while separately constraining the app-server process environment.
