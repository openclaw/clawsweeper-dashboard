## Summary

Keep open: the bounded WebSocket direction is useful, but the 1 MiB ceiling is below Mattermost's valid post-envelope surface and can reject legitimate Mattermost events before OpenClaw can parse or deliver them.

## What This Changes

The PR adds a 1 MiB `ws` `maxPayload` limit to the Mattermost monitor default WebSocket factory and adds a loopback test for normal plus oversized inbound frames.

## Best Possible Solution

Keep the resource bound, but choose a Mattermost-compatible ceiling backed by upstream post limits and add a regression test for a valid near-limit post envelope plus an oversized hostile frame.

## Reproduction Assessment

Yes. The PR body gives loopback output for the intended oversized-frame behavior, and source/dependency inspection gives a high-confidence reproduction path for the PR-introduced regression with a valid large Mattermost post event above 1 MiB.

## Solution Assessment

No. The default factory is the right layer for a resource bound, but the proposed 1 MiB value is too low unless maintainers intentionally narrow supported Mattermost post envelopes.
