## Summary

Keep this PR open for maintainer review: the patch is focused and appears correct, but it intentionally changes Mattermost monitor delivery from the `ws` 100 MiB client default to a 4 MiB inbound event cap, so the remaining question is acceptance of that compatibility envelope.

## What This Changes

The PR adds a 4 MiB `maxPayload` to the Mattermost monitor WebSocket factory and a loopback regression test for normal, large-valid, and oversized inbound events.

## Best Possible Solution

Land the 4 MiB transport cap if maintainers accept that event envelope; otherwise raise the constant to the chosen supported ceiling and keep the same focused loopback coverage.

## Reproduction Assessment

Yes, from source and PR proof. Current main and the latest release omit `maxPayload`, while the PR's loopback output exercises the production default socket factory with normal, large-valid, and oversized frames.

## Solution Assessment

Yes, with maintainer acceptance of the compatibility envelope. The default Mattermost WebSocket factory is the narrow owner boundary for this resource guard; the safer alternative, if needed, is only changing the cap value and preserving the same test shape.
