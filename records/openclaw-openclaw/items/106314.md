## Summary

Keep this PR open: the previous P2 blocker remains on the unchanged reviewed head. Node emits `close` after a failed spawn, so moving the unconditional restart policy there makes launch failures enter the five-second respawn loop that the old `exit`-only path generally avoided.

## What This Changes

Buffers Gmail watcher stderr across chunks, classifies bind errors before truncation, and defers restart decisions until child stdio closes.

## Best Possible Solution

Keep stderr classification and restart decisions on `close`, but only allow respawn after the child successfully spawned; preserve the existing terminal behavior for launch failures and cover both `error`→`close` and exit-before-final-stderr sequences.
