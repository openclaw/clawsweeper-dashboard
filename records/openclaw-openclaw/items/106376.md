## Summary

The EventKit call is a narrow and plausible implementation, but this PR should remain open until maintainers confirm that every existing `dueISO` call should begin producing notifications and the contributor supplies after-fix iOS behavior proof.

## What This Changes

The PR attaches an absolute `EKAlarm` whenever the iOS `reminders.add` command creates a reminder with `dueISO`.

## Best Possible Solution

Define whether `dueISO` contractually includes a due-time notification; if it does, retain the single canonical EventKit alarm path and prove creation plus notification delivery on a real iOS setup, otherwise expose alert scheduling explicitly rather than silently changing all existing calls.
