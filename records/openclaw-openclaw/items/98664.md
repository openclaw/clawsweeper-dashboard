## Summary

Keep this PR open for maintainer review. Current main and the latest release still have the unbounded `--batch-file` read, and the latest PR head addresses the previous FIFO blocking concern; no blocking code findings remain, but the new 50 MB fail-closed limit is a compatibility decision maintainers should explicitly accept before merge.

## What This Changes

The branch replaces the unbounded `openclaw config set --batch-file` read with a 50 MB bounded `openSync`/`readSync` path, adds parser regression tests, and updates CLI/docs copy.

## Best Possible Solution

Merge this bounded-read approach after maintainers accept the documented 50 MB ceiling, or adjust the ceiling before merge if they know of legitimate larger batch-file workflows.

## Reproduction Assessment

Yes from source inspection: current main and `v2026.6.11` both read the user-provided batch file with unbounded `fs.readFileSync` before parsing. I did not run an OOM reproduction because this was a read-only review.

## Solution Assessment

Yes, contingent on maintainer acceptance of the cap. The parser boundary is the narrowest maintainable place to preserve `--batch-json` behavior while bounding only `--batch-file`, and the PR now uses nonblocking open plus a capped read loop for the prior FIFO concern.
