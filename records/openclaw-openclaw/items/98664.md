## Summary

Keep open: this is a focused hardening PR, but the stat-only guard does not actually bound all reads from user-supplied paths, and the real-behavior proof is insufficient for the claimed fix.

## What This Changes

The PR adds a 1 MB size check before reading `openclaw config set --batch-file` input and adds a regression test for oversized regular files.

## Best Possible Solution

Bound the actual bytes read from user-supplied batch-file paths, for example by accepting only regular files plus a bounded read/open path or by streaming up to the 1 MB cap before parsing.

## Reproduction Assessment

Yes from source inspection: current `parseBatchSource` reads `--batch-file` with `fs.readFileSync()` and no pre-read byte bound. The PR's own proof target also names `/dev/zero`, which reports size 0 on this review host and is not rejected by the proposed stat-only guard.

## Solution Assessment

No: the stat-only check is a useful partial mitigation for large regular files, but it is not the best fix for a bounded-read requirement. The maintainable fix should cap the actual bytes read or reject unsupported non-regular inputs before reading.
