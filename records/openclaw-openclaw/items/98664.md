## Summary

Keep open: the latest branch fixes the original unbounded regular-file read and includes useful terminal proof, but it still opens user paths in blocking mode before `fstat`, so a FIFO can hang the CLI before the bounded read runs.

## What This Changes

## Best Possible Solution

Keep the bounded-read approach, but open with nonblocking flags when available, reject non-regular handles before reading, and retain the 50 MB docs/help/tests once maintainers accept the cap.

## Reproduction Assessment

Yes. Source inspection shows current main and the latest release read `--batch-file` with unbounded `readFileSync`, and a local FIFO proof shows the PR's blocking `openSync(path, "r")` can still hang before `fstat`.

## Solution Assessment

No. The PR is in the right layer and mostly fixes ordinary oversized files, but the best fix must avoid blocking opens and reject non-regular file handles before reading.
