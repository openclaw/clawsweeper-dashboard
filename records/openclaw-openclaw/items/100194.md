## Summary

Keep open. Current main and the latest release still use gateway-backed in-memory mobile chat/session state, and the protected `maintainer` label plus transcript persistence make this a product/security design item rather than cleanup-close material.

## What This Changes

Request a bounded, per-gateway offline read-only cache for recent mobile sessions and messages on iOS and Android, with cache-first cold open and offline browsing.

## Best Possible Solution

Define a shared mobile cache and security contract first, then implement bounded platform-native read-through caches with offline read-only UI and reconnect reconciliation on both apps.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes from source inspection: both mobile chat paths initialize session/message state in memory and fetch history from the gateway, but no live mobile cold-open repro was run.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainers approve the storage/security contract; a bounded read-only cache is plausible, but iOS and Android should share one reconciliation model rather than diverging.
