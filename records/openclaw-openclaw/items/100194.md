## Label Justifications

- `P2`: This is a meaningful mobile reliability improvement with limited immediate blast radius, but it is a new feature rather than an urgent regression.
- `impact:session-state`: The request is about preserving visible recent sessions and transcript state across cold opens and gateway outages.
- `impact:ux-friction`: Mobile users currently get blank or unavailable chat/session surfaces when the gateway is slow or unreachable, creating avoidable friction.
- `impact:security`: A local transcript cache would persist sensitive conversation content on mobile devices and needs explicit storage safeguards.
- `maturity:stable`: The issue affects the M4 Stable `android-app` and `ios-app` maturity features, including Mobile Chat / Chat and Sessions.

## Summary

Keep open. The issue is protected by the `maintainer` label, and current main still uses gateway-backed in-memory mobile chat/session state rather than a bounded offline transcript cache for iOS and Android.

## What This Changes

Add a bounded read-only per-gateway mobile cache so iOS and Android can show recent sessions/messages immediately on cold open and browse them offline with composing/actions disabled.

## Best Possible Solution

Define a shared mobile cache contract first, then implement platform-native bounded read-through caches on Android and iOS with explicit offline read-only UI and reconnect reconciliation.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Source inspection supports the reported gap: both mobile chat paths currently request sessions/history from the gateway and keep visible message/session state in memory, but I did not run a mobile-device cold-open repro.

## Solution Assessment

Is this the best way to solve the issue? Unclear: a bounded read-only cache is plausible, but maintainers should first settle the shared storage and reconciliation contract so iOS and Android do not diverge.
