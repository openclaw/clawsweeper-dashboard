## Summary

The exact head preserves a useful early size limit, but it does not solve the reported credential disclosure: both OpenAI OAuth failure paths still interpolate bounded provider response text without redaction.

## What This Changes

The PR changes the shared OpenAI OAuth token POST helper to cap failed response bodies at 16 KiB while retaining a 1 MiB success cap, and adds loopback tests for response-size behavior.

## Best Possible Solution

Retain the early 16 KiB failure cap, but normalize and redact the bounded response once in the shared postTokenForm boundary so both OAuth callers preserve safe status and OAuth diagnostics without exposing sensitive text.
