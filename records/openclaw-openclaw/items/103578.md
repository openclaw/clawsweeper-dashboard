## Summary

The final force-push correctly moves the 16 KiB failure-body cap into the shared token request helper, but it removes the earlier refresh redaction and still returns raw normal-sized provider text from both OAuth callers. The central credential-disclosure bug therefore remains, so this PR needs a narrow shared-owner repair plus new exact-head proof before merge.

## What This Changes

The PR caps failed OpenAI OAuth token responses at 16 KiB before buffering and adds real-loopback tests for oversized, normal failure, and successful response paths.

## Best Possible Solution

Keep the shared 16 KiB pre-buffer cap, then use the canonical provider-error extractor for both exchange and refresh so useful status and OAuth detail survive while credential values and raw provider JSON never reach returned messages.
