## Summary

Current and released code evaluate a cached ESM import expression for every accepted gateway request, but no benchmark or profile establishes material latency or CPU impact. The gateway has intentional startup import boundaries, so this remains a low-priority, benchmark-gated cleanup rather than a justified static-import change.

## What This Changes

The issue requests eliminating or caching a per-request dynamic import in the gateway WebSocket dispatcher to reduce hot-path overhead.

## Best Possible Solution

Retain on-demand message-handler loading, add a repeatable benchmark for warmed dispatch and first-connection startup, and cache the server-methods import promise at module scope only if it shows a meaningful gain without changing failure or protocol behavior.
