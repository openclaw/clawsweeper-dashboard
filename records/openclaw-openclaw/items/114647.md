## Summary

Keep this PR open for a maintainer decision and a correctness-preserving revision. The bounded probes improve the expensive session-list path, but the fixed 100-event cap deliberately turns valid long-transcript title or preview values into `null`, changing existing output rather than only optimizing its retrieval. Likely related people: steipete is a low-confidence routing candidate through recent merged gateway work and this PR’s adjacent production investigation.

## What This Changes

The PR replaces full SQLite transcript materialization for session-list title and last-preview derivation with bounded head and tail event-page probes.

## System Context

Gateway `sessions.list` reads persisted session transcripts to add derived titles and last-message previews for agent tools and bridge clients. The transcript reader supplies those fields to session-list responses, which callers display or forward to users.

## Architecture Diagram

flowchart LR

  B --> C[SQLite transcript store]
  C --> D[Head and tail event probes]
  D --> E[Derived title and preview]
  E --> F[ACP, MCP, and agent-tool callers]

## Best Possible Solution

Keep bounded ordinary reads, but preserve output correctness on cap misses through a store-level lookup or a fallback traversal that finds the required first and last eligible fields without imposing a semantic 100-event limit.
