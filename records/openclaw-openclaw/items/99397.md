## Summary

Keep open: this is a plausible Discord message-loss bug fix with sufficient real Discord terminal proof, but the current patch is too broad and can duplicate already delivered text on long media replies when a later follow-up chunk fails.

## What This Changes

The PR catches Discord media-send failures in `sendMessageDiscord`, retries the original text through `sendDiscordText`, and adds a unit test for a mocked oversized-media rejection.

## Best Possible Solution

Land a Discord-owned fallback that only sends text when the media upload fails before any Discord message is created, with regression coverage for long media replies and follow-up failures, then resolve the sibling candidates.

## Reproduction Assessment

Yes, at source level: current Discord media sends post caption and file together, and the PR fallback catches the whole media send call. I did not run a live repro in this read-only review; the PR body includes after-fix real Discord terminal proof for the 413 path.

## Solution Assessment

No. The Discord send layer is the right owner boundary, but this implementation is too broad because it can fallback after partial delivery; the safer fix scopes fallback to the initial media upload/no-message-sent path or carries partial-send evidence.
