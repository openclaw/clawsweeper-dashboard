## Summary

Keep open: current main and v2026.6.11 already have durable SQLite cron run logs with run-id/status/delivery/query paging, but timestamp filters, a logs/history CLI with follow/export, success-rate aggregates, and explicit retention/prune/vacuum decisions remain missing and security-sensitive.

## What This Changes

Request persistent, filterable cron execution history with CLI logs/history commands, list aggregates, export/follow behavior, and retention/pruning controls.

## Best Possible Solution

Extend the existing SQLite cron.runs contract with maintainer-approved timestamp filters and a CLI/docs surface, while explicitly defining export, follow, aggregates, redaction, authorization, and retention/prune policy instead of adding a parallel history store.
