## Summary

Keep open: current main and v2026.6.11 have durable SQLite cron run history with status, delivery, run-id, query, paging, and UI/API filters, but the requested time-range filters, `openclaw cron logs`/`cron history` CLI surface, follow/export behavior, success-rate aggregates, and manual prune/vacuum or day-retention workflow are still missing.

## What This Changes

Request persistent cron execution history with filtering, CLI log/history commands, list aggregates, export/follow support, and retention/pruning controls.

## Best Possible Solution

Define a narrow core cron-history contract on top of the existing SQLite `cron.runs` path, adding accepted timestamp filters, CLI/docs/export/follow/summary behavior, and explicitly scoped retention/security semantics.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature request. Source, docs, release, and protocol inspection give high confidence that only the existing SQLite `cron.runs` subset is present today.

## Solution Assessment

No for an automated one-shot fix: the requested surface spans CLI, protocol, UI, docs, config/retention, and security policy. The maintainable path is to extend the existing SQLite run-log contract rather than add a parallel history store.
