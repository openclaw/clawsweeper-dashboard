## Summary

Keep open: current main and v2026.6.11 provide durable SQLite cron run history with status, delivery, run-id, query, paging, UI/API filters, and row-count pruning, but the requested timestamp filters, `openclaw cron logs` or `cron history` CLI surface, follow/export behavior, success-rate aggregates, and explicit prune/vacuum or day-retention workflow remain missing and need maintainer scoping.

## What This Changes

## Best Possible Solution

Define a narrow core cron-history contract on top of the existing SQLite `cron.runs` path: add accepted timestamp filtering and any approved CLI/docs/export/follow/summary behavior while explicitly scoping retention and security before adding new config or prune commands.
