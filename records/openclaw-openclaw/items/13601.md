## Summary

Keep open, but narrow the request: current main and v2026.6.11 already provide durable SQLite cron history, Control UI filtering, JSON CLI output, and automatic row retention; timestamp filters, equivalent CLI filters, follow behavior, success-rate aggregates, and manual maintenance remain unimplemented product and security decisions.

## What This Changes

Add persistent cron execution history with status and time filtering, export or follow support, reliability summaries, and retention maintenance controls.

## Best Possible Solution

Add bounded after and before filters to the existing SQLite-backed `cron.runs` path and expose existing status and query filters plus time bounds in `openclaw cron runs`; add bounded summary queries separately, while omitting raw follow/export and manual vacuum unless maintainers define authorization, redaction, and database-maintenance contracts.
