## Summary

Keep open: current main and the latest release already provide durable SQLite cron run history with paging, status/delivery/run-id/query filters, UI filtering, and row-count pruning, but the requested timestamp filters, `openclaw cron logs` or `cron history` CLI surface, follow/export behavior, success-rate aggregates, and explicit prune/vacuum or day-retention workflow remain missing.

## What This Changes

The issue requests a persistent cron execution-history product surface with status/time filters, JSON export, live following, summary aggregates, and retention controls.

## Best Possible Solution

Have maintainers narrow the core scope, then extend the existing SQLite `cron.runs` path with timestamp filters, a clearer CLI history/logs surface, JSON export, summary aggregates, and security-scoped docs/tests while reusing `cron.runLog.keepLines` unless day-based retention or manual prune/vacuum is explicitly approved.
