## Summary

Keep open: current main and v2026.6.11 already have durable SQLite cron run history with status, delivery, run-id, query, paging, and UI/API filters, but the requested CLI logs/history aliases, timestamp filters, follow/export behavior, success-rate aggregates, and explicit retention/prune/vacuum workflow are still missing.

## What This Changes

Requested persistent cron execution history with CLI filtering, time ranges, JSON export/follow, list aggregates, and retention/prune controls.

## Best Possible Solution

Use the existing SQLite run-log backend and land a maintainer-approved additive CLI/protocol/UI/docs contract for time filters, logs/history aliases, follow/export, aggregates, and secure retention/redaction behavior.

## Reproduction Assessment

Not applicable: this is a feature request for a broader cron audit/logging and retention surface, not a broken-behavior report. Source inspection confirms the remaining CLI/time-range/export/aggregate workflow is absent on current main and v2026.6.11.

## Solution Assessment

Partly: persistent storage should stay on the current SQLite-backed run-log path, but JSON log files and a separate cron-history database would conflict with current storage policy. The public CLI, filtering, export/follow, aggregate, and retention pieces need maintainer product/security design before implementation.
