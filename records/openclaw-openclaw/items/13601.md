## Summary

Keep open: current main and the latest release already provide durable SQLite cron run history with status, delivery, run-id, query, paging, UI/API filters, and row-count pruning, but the requested timestamp filters, `openclaw cron logs` or `cron history` CLI surface, follow/export behavior, success-rate aggregates, and explicit prune/vacuum or day-retention workflow remain missing.

## What This Changes

Request to add persistent cron execution history with filtering, export/follow CLI views, summary aggregates, and retention/pruning controls.

## Best Possible Solution

Extend the existing SQLite cron.runs path with maintainer-approved timestamp filters and CLI/docs behavior, while explicitly scoping export, follow, aggregates, retention, redaction, and access rules instead of adding a parallel history store.
