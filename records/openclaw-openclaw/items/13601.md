## Summary

Keep open: current main and the latest stable release persist cron run history in SQLite with paging, run-id, status, delivery, query, and row-count retention, but the requested CLI logs/history aliases, timestamp filters, follow/export behavior, success-rate aggregates, and explicit prune/vacuum/security policy remain missing.

## What This Changes

Request persistent cron execution history with status/time filtering, CLI log/history commands, export/follow support, list aggregates, and retention/pruning controls.

## Best Possible Solution

Use the existing SQLite run-log backend and land a maintainer-approved additive CLI/protocol/docs contract for time filters, JSON/follow/export, aggregates, and secure retention/redaction behavior.

## Reproduction Assessment

Not applicable: this is a feature request for a broader cron audit/logging and retention surface, not a broken-behavior report. Source inspection confirms the remaining CLI time-range/export/follow/aggregate workflow is absent.

## Solution Assessment

Partly: persistent storage should stay on the current SQLite-backed run-log path, but adding a separate JSONL/history database or competing retention model would be the wrong direction without maintainer product and security approval.
