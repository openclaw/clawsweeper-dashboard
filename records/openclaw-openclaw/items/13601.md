## Summary

Keep open: current main and v2026.6.11 already have durable SQLite cron run history with run-id/status/delivery/query paging and UI filtering, but the requested logs/history CLI surface, timestamp filters, follow/export behavior, success-rate aggregates, and explicit retention/prune/vacuum workflow are still missing.

## What This Changes

The issue requests persistent cron execution history with CLI filtering, export/follow, aggregates, and retention/prune controls.

## Best Possible Solution

Use the existing SQLite run-log store as the backend, then add an explicit additive CLI/protocol/docs design for logs/history status and time filters, JSON/follow semantics, aggregates, and secure retention/redaction behavior.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a feature request. Source inspection confirms current main lacks the requested CLI time-range/export/follow/aggregate/history-maintenance workflow while already covering durable storage.

## Solution Assessment

Partly: persistent storage should stay on the current SQLite-backed run-log path, not new JSON sidecars, but the CLI, filtering, export/follow, aggregate, and retention pieces need maintainer narrowing before implementation.
