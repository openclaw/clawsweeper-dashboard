## Summary

Keep open: current main and the latest release have durable SQLite cron run history with status, delivery, run-id, query, paging, and UI/API filters, but the requested timestamp filters, `openclaw cron logs`/`cron history` CLI surface, follow/export behavior, success-rate aggregates, and explicit prune/vacuum or day-retention workflow are still missing.

## What This Changes

The issue requests persistent cron job execution history with filtering, export, summary, and retention controls.

## Best Possible Solution

Define a narrow core cron-history contract on top of the existing SQLite `cron.runs` path: add timestamp filtering and any accepted CLI/docs/export/follow/summary behavior, while explicitly scoping retention and security before adding new config or prune commands.

## Solution Assessment

No for an automated one-shot fix: the requested surface spans CLI, protocol, UI, docs, config/retention, and security policy. The best path is a maintainer-scoped product decision that extends the existing SQLite run-log path rather than adding a parallel history store.
