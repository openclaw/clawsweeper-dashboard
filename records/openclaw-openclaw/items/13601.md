## Summary

Keep open: current main and v2026.6.11 have durable SQLite cron run history with paging, status, delivery, run-id, query, and row-count pruning, but the requested timestamp filters, richer CLI logs/history surface, follow/export behavior, success-rate summaries, and explicit prune/vacuum or day-retention workflow remain unimplemented.

## What This Changes

The issue requests persistent cron execution history with status/time filtering, JSON export, live follow, success/failure summaries, and configurable cleanup controls.

## Best Possible Solution

Extend the existing SQLite cron.runs path with maintainer-approved timestamp filters and CLI/docs behavior, while explicitly scoping export, follow, aggregates, retention, redaction, and access rules instead of adding a parallel history store.
