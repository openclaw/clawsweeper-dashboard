## Summary

Keep open: current main still force-refreshes the Codex app-server OAuth callback while upstream Codex still cancels external auth refresh after 10 seconds. The merged JSON-RPC and invalidated-token fixes improve adjacent masked-error cases, but they do not prove that valid-but-slow OAuth refreshes no longer fail cron, heartbeat, or agent turns.

## What This Changes

The issue asks OpenClaw to stop valid OpenAI/Codex OAuth sessions from failing cron, heartbeat, and embedded agent runs when the Codex app-server auth refresh callback exceeds 10 seconds.

## Best Possible Solution

Define a single Codex external-auth contract: answer refresh callbacks from a still-usable cached OpenAI OAuth token when safe, fail fast with targeted re-auth and degraded health when not safe, and continue upstream work to make Codex's 10-second deadline configurable for genuinely expired-token refreshes.
