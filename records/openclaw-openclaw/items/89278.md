## Summary

Keep open: current main includes partial fixes for malformed JSON-RPC errors and revoked-token false-green handling, but the central 10-second Codex external-auth callback remains source-reproducible. Current OpenClaw still force-refreshes the Codex app-server token-refresh callback, while current upstream Codex still cancels that external-auth request after 10 seconds; https://github.com/openclaw/openclaw/pull/93952 is related runtime-deadline work but is still open and does not by itself prove this exact callback path fixed.

## What This Changes

The issue asks for valid OpenAI/Codex OAuth-backed cron, heartbeat, and embedded turns to stop failing with a 10-second auth refresh timeout when the refresh path is slow or the actionable auth error is masked.

## Best Possible Solution

Keep this issue open until maintainers choose and validate the Codex auth-bridge end state: a safe cached-token response for still-usable credentials, an upstream configurable timeout, or an equivalent bridge/runtime design with status and reauth guidance that proves cron, heartbeat, and embedded turns no longer hit the 10-second callback failure.
