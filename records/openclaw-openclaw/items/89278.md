## Summary

Keep open: current main still routes the Codex app-server refresh callback through a forced OpenClaw OAuth refresh, while current upstream Codex still cancels that external-auth callback after 10 seconds. The 120s OpenClaw OAuth refresh budget is real, but it does not by itself satisfy the upstream 10s callback deadline, and there is fresh v2026.6.11 production evidence that the shipped runtime still exposes this failure.

## What This Changes

The issue asks OpenClaw to stop valid Codex/OpenAI OAuth cron, heartbeat, and embedded turns from failing when the app-server auth refresh callback exceeds 10 seconds.

## Best Possible Solution

Keep this issue as the canonical tracker until maintainers choose and validate a Codex auth-bridge mitigation that handles usable cached tokens, bounded refresh contention, clear degraded auth/status, and the upstream 10s callback contract.
