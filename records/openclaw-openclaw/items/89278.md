## Summary

Keep open: current main fixes two masking paths, but OpenClaw still force-refreshes the Codex app-server auth callback while upstream Codex still cancels that callback after 10 seconds, so the central valid-but-slow refresh failure is not fully resolved.

## What This Changes

The issue asks OpenClaw to prevent Codex OAuth refreshes that take longer than 10 seconds from breaking cron, heartbeat, and embedded agent runs when auth is otherwise present.

## Best Possible Solution

Choose and implement a Codex auth bridge policy that answers the upstream 10-second refresh callback deterministically, preferably by reusing still-valid canonical tokens or failing fast with parseable reauth guidance while tracking broader quarantine/status work separately.
