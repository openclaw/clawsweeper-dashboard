## Summary

This PR still addresses a real current-main gap: the explicit `memory_recall` tool already opens a per-agent cooldown after embedding trouble, while the prompt-build auto-recall path does not. The patch reuses that existing breaker and includes credible live before/after evidence; keep it open for the normal maintainer merge decision after the behind-base branch is refreshed.

## What This Changes

The PR makes the LanceDB memory plugin’s automatic prompt-build recall skip work during the existing per-agent recall cooldown and record that cooldown after embedding failures or timeouts.

## System Context

The memory-lancedb plugin runs automatic vector recall before an agent prompt is built, while its explicit memory tool runs on demand. Both paths depend on the configured embedding service and then feed matching memories into the agent’s context, so an embedding outage can otherwise delay each turn before model execution.

## Best Possible Solution

Keep one per-agent cooldown as the canonical failure boundary, rebase the focused patch onto current `main`, and land it with the cross-path timeout regression test once the merge result still preserves the existing cooldown contract.
