## Summary

Keep open: the July 17 force-push removed the earlier duplicate cache-table design, but the replacement no longer preserves the claimed restart/cold-start optimization, its submitted runtime proof targets the removed SQLite implementation, and the target-stat token can miss same-size edits whose mtime is restored.

## What This Changes

The current branch adds corpus revision tokens and target stat identity to skip rebuilding unchanged QMD session exports within a live exporter, with supporting memory-host SDK revision plumbing and regression tests.

## Best Possible Solution

Keep the corpus-owned opaque revision token, but either persist the minimum export revision state through the canonical scoped agent cache and validate target ctime/bytes, or explicitly narrow the PR to an interval-only optimization; then align the title/body and provide current-head runtime proof for the selected lifetime.
