## Label Justifications

- `P2`: This is a source-proven multimodal feature gap with meaningful user friction, but it is not an urgent regression, outage, data-loss event, or active security incident.
- `impact:security`: Direct video upload would forward original user video bytes through managed storage or provider egress, so limits, retention, and policy are security-relevant.
- `impact:auth-provider`: The requested behavior depends on provider/model capability routing and native LLM media payload support.
- `impact:ux-friction`: Users who want direct LLM video analysis must leave the chat flow and use manual extraction, external tools, or separate media-understanding commands.

## Summary

Keep open: current main still filters chat video uploads and lacks a first-class LLM chat/session video content path; the related implementation PRs are closed unmerged, while the open MiniMax tracker is narrower provider-specific work.

## What This Changes

The issue requests direct video file uploads in chat/message flows, video previews, and delivery to LLM models that support native video input.

## Best Possible Solution

Keep this as the canonical tracker until maintainers approve one coherent video-aware contract across WebChat, Gateway validation/staging, LLM content types, provider delivery, fallback/security policy, docs, and tests.

Options:

- **Approve first-class chat video input (recommended):** Define a coherent WebChat/Gateway/LLM/provider contract with security limits and then land or replace the implementation accordingly.
- **Keep video in media-understanding only:** Defer direct chat/model video uploads and document the supported `infer video describe` and media-understanding paths instead.
- **Narrow to provider-specific plugins first:** Let providers prove native video behavior behind provider-owned seams before adding a generic core chat-video content contract.

Yes, at source level: current main filters MP4/WebM/MOV/M4V before WebChat send, and the chat/LLM contracts only provide native image content plus generic offloaded media. I did not run a live browser upload in this read-only review.

## Solution Assessment

No for immediate automation. Existing `infer video describe` and media-understanding video support are useful but distinct, so the best path is a maintainer-approved product/API/security design or a repaired implementation PR rather than a duplicate fix branch.
