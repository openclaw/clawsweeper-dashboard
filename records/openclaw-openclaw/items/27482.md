## Summary

Keep open: current main and latest release still reject WebChat video uploads before send and do not provide a native chat-video delivery contract; the closed direct-upload PR did not land, and the open native-media PR is only partial/conflicting overlap.

## What This Changes

Request direct video uploads in chat/message flows so video-capable LLMs can receive MP4/WebM/MOV inputs natively with UI preview and appropriate fallback handling.

## Best Possible Solution

Keep this as the canonical tracker until maintainers approve and land one coherent video-aware contract across WebChat, Gateway validation/staging, model catalog metadata, provider delivery, fallback/security policy, docs, and tests.

## Reproduction Assessment

Yes, at source level: current main filters MP4/WebM/MOV/M4V before WebChat send, and the Gateway/model contracts only provide native image prompt content plus generic offloaded media. I did not run a live browser upload in this read-only review.

## Solution Assessment

No for immediate automation. Existing media-understanding `video.description` plumbing is useful, but it does not satisfy direct WebChat/model upload, so the best path is a maintainer-approved product/API/security design or a repaired implementation PR rather than a duplicate fix branch.
