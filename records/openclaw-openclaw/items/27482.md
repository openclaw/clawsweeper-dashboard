## Summary

Keep open: current main still filters video out of the chat composer and the core chat/model message contract remains image-native plus generic managed-media staging, so the requested direct video upload/native LLM video path is not implemented.

## What This Changes

The issue requests direct video file upload and provider-native LLM video delivery from OpenClaw chat interfaces.

## Best Possible Solution

Keep this as the canonical generic tracker until maintainers approve one video-aware contract across WebChat accept/preview, Gateway validation/staging, native provider content, fallback/security policy, docs, and tests.
