## Summary

Keep open: current main still blocks WebChat video uploads and has no native chat-video content path to LLM providers; the direct implementation PR is closed unmerged, while the active native audio/video PR is conflicting and only partially overlaps.

## What This Changes

Request direct upload of MP4/WebM/MOV video files through the message tool and chat UI to video-capable LLMs with preview, validation, storage or encoding, and provider-native delivery.

## Best Possible Solution

Keep this issue as the canonical tracker until maintainers approve one coherent video-aware contract across WebChat, Gateway validation/staging, model catalog, provider delivery, fallback/security policy, docs, and tests.

## Solution Assessment

No for immediate automation. Existing media-understanding and infer video describe paths are useful but do not satisfy direct WebChat/model upload, so the best path is a maintainer-approved product/API/security design or a repaired implementation PR rather than a duplicate fix branch.
