## Summary

Keep open: current main still lacks first-class direct video upload from WebChat/chat attachments into provider-native LLM video inputs, while the related implementation attempts are closed unmerged or provider-specific follow-ups.

## What This Changes

Request direct upload of MP4/WebM/MOV video attachments through chat/message flows to video-capable LLMs with preview, validation, and provider-native delivery.

## Best Possible Solution

Keep this as the canonical tracker until maintainers approve and land one coherent video-aware contract across WebChat, Gateway validation/staging, model catalog metadata, provider delivery, fallback/security policy, docs, and tests.

## Solution Assessment

No for immediate automation. Existing video.description media-understanding plumbing is useful but distinct, so the best path is a maintainer-approved product/API/security design or a repaired implementation PR rather than a duplicate fix branch.
