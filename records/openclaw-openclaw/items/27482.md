## Summary

Keep open: current main still rejects WebChat video attachments and lacks an end-to-end native video content path from chat upload through LLM provider transport; the directly related implementation PRs are closed unmerged, while the MiniMax M3 tracker is only a provider-specific overlap.

## What This Changes

The issue requests direct video upload support from WebChat/message tooling through to video-capable LLM provider payloads.

## Best Possible Solution

Add a maintainer-approved native-video chat contract that covers UI acceptance/preview, Gateway validation and staging, LLM content types, provider-specific serialization, safe raw-media policy, fallback to media-understanding when unsupported, docs, and regression proof.
