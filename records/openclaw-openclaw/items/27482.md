## Summary

Keep open: current main and the latest release still block Control UI/WebChat video uploads and do not have a typed native chat-video content path to LLM providers; existing video media-understanding support is a separate summary/fallback path, and the direct implementation PR is closed unmerged while the active native-media PR only partially overlaps.

## What This Changes

The issue requests direct chat/message video uploads to video-capable LLMs with validation, preview, storage or encoding, and provider-native payload delivery.

## Best Possible Solution

Keep this as the canonical tracker until maintainers approve one coherent video-aware contract across WebChat, Gateway validation/staging, model catalog, provider transports, fallback/security policy, docs, and tests.

## Reproduction Assessment

Yes, at source level: Control UI filters MP4/WebM/MOV/M4V before WebChat send, and the Gateway/LLM contracts only provide native image prompt content plus generic offloaded media. I did not run a live browser upload in this read-only review.

## Solution Assessment

No for immediate automation. Existing media-understanding and video-generation paths are useful but do not satisfy direct WebChat/model upload, so the best path is a maintainer-approved product/API/security design or a repaired implementation PR rather than a duplicate fix branch.
