## Summary

Keep open: current main and the latest stable release still reject WebChat video uploads and lack a first-class chat/model video content contract; adjacent video.description support is not the requested direct provider-native LLM input path.

## What This Changes

The issue requests direct MP4/WebM/MOV-style video upload from chat/message surfaces to LLM models that support native video understanding.

## Best Possible Solution

Keep this as the canonical tracker until maintainers approve and land one coherent video-aware contract across WebChat, Gateway validation/staging, model catalog metadata, provider delivery, fallback/security policy, docs, and tests.
