## Summary

Keep open: current main and the latest release still block WebChat video uploads and do not provide a first-class provider-native chat video content path; the direct implementation attempts are closed unmerged, and https://github.com/openclaw/openclaw/issues/98084 is narrower MiniMax-specific follow-up work.

## What This Changes

The issue requests direct chat/WebChat video upload and native delivery to video-capable LLMs instead of requiring frame extraction or separate media-understanding workflows.

## Best Possible Solution

Keep this as the canonical generic tracker until maintainers approve one coherent video-aware contract across WebChat, Gateway validation/staging, model capability metadata, provider delivery, fallback/security policy, docs, and tests.
