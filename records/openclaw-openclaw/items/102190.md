## Summary

Keep open: current main still source-reproduces the silent failed-image-load path, no merged fix owns this exact visibility contract, and the remaining choice is where and how OpenClaw should surface the skipped image.

## What This Changes

The issue reports that failed native image attachment loads are counted internally but discarded before model submission, so the model can answer as if no image was sent.

## Best Possible Solution

Define one safe skipped-image visibility contract in core image loading and consume it consistently from embedded, CLI, and harness callers without exposing full local paths by default.

Question: Where should OpenClaw surface failed native image attachment loads: model-visible prompt markers, user/operator diagnostics, turn failure, or a combination?

Rationale: The code bug is clear, but the permanent contract affects model-visible text, user-facing behavior, log level, path disclosure, and multiple runtime callers.

Likely owner: vincentkoc

Owner confidence: high

Options:

- **Prompt Marker Contract (recommended):** Return safe skipped-image metadata and have embedded, CLI, and harness callers add a model-visible marker/count without full local paths.
- **Diagnostics Only:** Emit a user/operator warning while leaving the model prompt unchanged, which avoids prompt wording policy but still lets the model answer without the missing image.
- **Fail Current Turn:** Treat failed current-turn image loads as input errors, which gives the strongest user signal but may break workflows where optional prompt refs fail.

## Reproduction Assessment

Yes, source-reproducible: current main counts failed image loads in skippedCount and then embedded, CLI, and Copilot harness callers drop that count before model submission. A live corrupt-image or sandbox-denied run was not captured.

## Solution Assessment

Unclear until maintainers choose the surface. The narrowest maintainable fix appears to be a shared skipped-image result contract consumed by the embedded, CLI, and harness paths.
