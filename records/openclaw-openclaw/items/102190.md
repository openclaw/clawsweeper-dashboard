## Summary

Keep open: current main and the latest release still source-reproduce the skipped native-image load path, and no merged or open canonical PR owns the remaining visibility contract.

## What This Changes

The issue asks OpenClaw to surface failed native image attachment loads instead of silently omitting them from the model prompt.

## Best Possible Solution

Define a shared skipped-native-image visibility contract in core image loading and consume it consistently from embedded, CLI, and harness callers, with safe wording that avoids full local-path disclosure by default.

Rationale: The source bug is clear, but the durable behavior affects prompt text, user-facing diagnostics, path disclosure, log level, and multiple caller surfaces.

Likely owner: vincentkoc

Owner confidence: high

Options:

- **Shared Safe Prompt Marker (recommended):** Return skipped-image metadata and have embedded, CLI, and harness callers add a safe model-visible count/marker without full local paths so the model cannot answer as if no image was sent.
- **Diagnostics Only:** Emit user/operator-visible diagnostics while leaving the model prompt unchanged, which avoids prompt wording policy but still lets the model answer without the missing image.
- **Fail Current Turn:** Treat failed current-turn native image loads as input errors, giving the strongest user signal at the cost of a stricter runtime behavior change.

## Reproduction Assessment

Yes, source-reproducible: current main counts failed image loads in skippedCount and then drops that count before model submission. A live corrupt-image or sandbox-denied run has not been captured.

## Solution Assessment

Unclear until maintainers choose the surface. The narrowest maintainable direction appears to be a shared skipped-image result contract consumed by embedded, CLI, and harness callers.
