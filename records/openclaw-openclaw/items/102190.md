- `P2`: The issue is source-reproducible and can silently omit user-supplied image content, but it is a bounded media prompt-path bug rather than a core runtime outage.

## Summary

Keep open: current main still source-reproduces failed native prompt-image loads being counted and then discarded, and no merged fix or viable canonical PR owns the skipped-image visibility contract.

## What This Changes

The issue requests a visible model/user/operator signal when a native image attachment fails to load instead of silently omitting it from the model prompt.

## Best Possible Solution

Define one safe skipped-image visibility contract in core image loading and consume it consistently from embedded, CLI, and harness callers without exposing full local paths by default.

Options:

- **Prompt Marker Contract (recommended):** Return safe skipped-image metadata and have embedded, CLI, and harness callers add a model-visible marker or count without full local paths, so the model cannot answer as if no image was sent.
- **Diagnostics Only:** Emit a user/operator warning while leaving the model prompt unchanged, which avoids prompt wording policy but still lets the model answer without the missing image.
- **Fail Current Turn:** Treat failed current-turn image loads as input errors, which gives the strongest signal but may break workflows where optional prompt refs fail.

## Reproduction Assessment

Yes, at source level. Current main counts failed native image loads in `skippedCount` and then the embedded, CLI, and harness callers drop that count before model submission; no live model run was captured.

## Solution Assessment

Unclear until maintainers choose the visibility surface. The narrowest maintainable direction appears to be a shared skipped-image result contract consumed by embedded, CLI, and harness callers.
