## Summary

Keep open: the PR addresses a real Gateway requester-provenance spoofing bug, but the patch is incomplete because the existing gateway-executed message-action bridge still connects with `operator.write` and would lose trusted requester identity under the new gate.

## What This Changes

The PR changes Gateway `message.action` dispatch so requester identity and `senderIsOwner` are forwarded only when the RPC client has `operator.admin`.

## Best Possible Solution

Keep the server-side strip for untrusted write callers, but update the trusted Gateway bridge to use or prove full-scope provenance when it forwards requester fields, then add focused regression and real Gateway proof for both trusted and untrusted paths.
