## Label Justifications

- `P0`: The issue describes first-run CLI setup accepting unusable AI access and blocking the first useful agent run for new or stale-auth installs.
- `impact:ux-release-blocker`: A first-time CLI user without working provider auth has no guided in-product path to enter and verify credentials before the first agent run.
- `impact:auth-provider`: The affected flow is model/provider auth selection and verification during onboarding.
- `maturity:stable`: The issue affects the CLI maturity feature `cli-install-update-onboard-doctor`, which is scored M4 Stable and includes onboarding/auth setup.

## Summary

Keep open: current main has the macOS live-verification building blocks, but the CLI default still routes through Crestodian chat setup that chooses detected auth before a live setup activation test. The protected `maintainer` label and first-run UX/product implications make this a maintainer-owned direction rather than cleanup-close material.

## What This Changes

The issue requests guided CLI onboarding that live-verifies AI access before persisting setup and preserves classic wizard fallback.

## Best Possible Solution

CLI onboarding should reuse the existing setup-inference activation path for guided live verification, keep `--classic` and scripted contracts intact, provide an in-product masked manual key path, and update CLI docs to match the chosen default.
