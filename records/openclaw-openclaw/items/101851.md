## Label Justifications

- `P0`: A first-time CLI user can complete setup with stale or missing AI access and then be blocked on the first useful agent run without a non-technical in-product recovery path.
- `impact:auth-provider`: The issue concerns selecting, verifying, and persisting model/provider credentials during onboarding.
- `impact:ux-release-blocker`: The reported first-run CLI setup path can strand users until they understand and repair provider auth outside the guided flow.
- `maturity:stable`: The affected CLI setup/onboarding surface matches the M4 Stable `cli-install-update-onboard-doctor` maturity shortlist entry.

## Summary

Keep open: current main still lacks default CLI guided live verification and masked manual-key onboarding, while the protected `maintainer` label and default-onboarding UX make this a maintainer-owned product decision.

## What This Changes

Request guided CLI onboarding that live-tests detected AI access before persistence, falls through candidates, supports verified manual API-key entry, and preserves classic/non-interactive contracts.

## Best Possible Solution

Add a deterministic CLI guided verifier around `detectSetupInference`/`activateSetupInference`, with masked manual-key entry, candidate fall-through, explicit classic/Crestodian/skip escape hatches, and updated CLI docs/tests.

- **Keep chat-first onboarding:** Leave the current conversational setup default and accept that first live model failure happens after setup unless a separate recovery path is added.
