## Summary

Keep this PR open for maintainer review. The final branch appears to address the guarded-CDP DNS-pinning gap and incorporates the requested Chrome MCP and tab-metadata follow-ups, but it deliberately changes compatibility for explicit guarded Chrome MCP endpoints and lacks after-fix real behavior output for the later substantive commits on the current head.

## What This Changes

The Browser plugin retains the SSRF-approved DNS lookup through CDP HTTP/WebSocket operations, rejects guarded Chrome MCP attachments that cannot preserve it, and carries the pin into tab snapshots, diagnostics, permissions, and related browser actions.

## System Context

Browser profiles supply a CDP endpoint and SSRF policy to the Browser plugin, which discovers and attaches to Chrome through raw CDP, Playwright, or Chrome MCP. The changed path validates an endpoint, carries its approved DNS lookup into later network sockets, and prevents the Chrome MCP subprocess route from bypassing that invariant.

## Best Possible Solution

Keep the raw and Playwright paths pinned, preserve default Chrome MCP attachment where policy does not demand pinning, and land the fail-closed guarded Chrome MCP behavior only after the owner accepts the upgrade policy and exact-head redacted runtime proof confirms the allowed and denied cases.
