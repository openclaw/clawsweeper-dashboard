## Summary

Keep this PR open for the assigned Browser review: the final branch appears to address the previously raised raw-CDP, Chrome MCP, endpoint-metadata, and transport-contract concerns, but it deliberately makes guarded `existing-session` profiles with an explicit `cdpUrl` fail instead of attaching through Chrome MCP. ## What This Changes

The Browser plugin now retains SSRF-approved DNS lookup pins across CDP discovery, WebSocket, Playwright, and tab-operation paths; it fail-closes Chrome MCP `existing-session` profiles that cannot carry the pin and uses file payloads for guarded remote uploads.

## System Context

Browser profiles use CDP endpoints to discover and control Chrome tabs through direct sockets, Playwright, or the Chrome MCP subprocess. This PR turns endpoint validation into a pinned transport fact that flows into discovery, attachment, snapshots, and tab operations, while rejecting the subprocess path that cannot preserve it.
