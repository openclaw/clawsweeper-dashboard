## Summary

Keep open: current `main` and the latest release still spawn the detached gateway update child without an `error` listener, so an asynchronous ChildProcess `error` can still terminate the parent process before the update fallback path runs.

## What This Changes

The issue reports that `spawnDetachedGatewayProcess` can crash the parent Node process because a detached child process may emit an unhandled `error` event after `spawn`.

## Best Possible Solution

Handle the detached gateway child `error` event before `unref()` and add a focused regression test so async spawn failures fall back instead of crashing the parent process.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: current `main` lacks a child `error` listener, and a Node spawn probe confirms an unhandled ChildProcess `error` terminates the parent process. I did not run a live OpenClaw gateway ENOMEM or update-respawn failure repro.

## Solution Assessment

Yes: the narrow maintainable fix is to consume or handle the detached child `error` in `spawnDetachedGatewayProcess` before `unref()`, then pin that behavior in `src/infra/process-respawn.test.ts`.
