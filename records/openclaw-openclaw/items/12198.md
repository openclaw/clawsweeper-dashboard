## Summary

Keep open. Current main still loads workspace bootstrap Markdown and local `SKILL.md` content through boundary and metadata checks without a shared prompt-bearing Markdown validation contract. ClawHub scan state and local install-policy hooks cover only part of the requested boundary, and the remaining security and compatibility policy needs explicit maintainer direction.

## What This Changes

Add security validation for Markdown that becomes model-visible prompt content, with publishing/install enforcement or tagging and configurable severity or overrides.

## Best Possible Solution

Define a shared typed validation-result contract for model-visible Markdown, apply it at core bootstrap and skill-ingestion boundaries, let ClawHub own publish scan/tag and appeal policy, default uncertain findings to visible warnings, reserve blocking for narrowly agreed high-confidence rules, and track workspace secret/DLP prevention separately rather than using a second Git repository cache.

## Reproduction Assessment

## Solution Assessment

No, not as proposed in full. A shared validator is the maintainable direction, but blanket HTML-comment rejection, a second `.git` cache, and secret-write prevention should not be adopted without a scoped contract and separate ownership.
