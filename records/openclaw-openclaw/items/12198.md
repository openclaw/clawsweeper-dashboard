## Summary

Keep open: current main and v2026.6.11 still have adjacent boundary checks, scanner hardening, and Skill Workshop proposal scanning, but no shared prompt-bearing Markdown validation contract across workspace bootstrap files, extra bootstrap files, runtime SKILL.md reads, and ClawHub skill install/publish paths. The related scanner PR is useful but open, conflicting, and only covers part of the requested security hardening.

## What This Changes

Request shared Markdown validation or linting for prompt-bearing files such as SKILL.md and workspace bootstrap Markdown to reduce prompt-injection and unsafe-instruction risk.

## Best Possible Solution

Define one shared prompt-bearing Markdown validation contract and apply it consistently to workspace bootstrap ingestion, extra bootstrap files, runtime SKILL.md discovery/read paths, source and ClawHub skill install/update, and ClawHub publish/verification tagging with explicit docs and tests.

## Reproduction Assessment

Yes. Source inspection on current main and v2026.6.11 shows prompt-bearing bootstrap Markdown and SKILL.md bodies can still reach prompt-visible paths without a shared Markdown validation policy; I did not run a live mutation test because this review is read-only.

## Solution Assessment

Unclear as an implementation path because no patch is being reviewed. The requested direction is valid, but the best fix is a shared security contract with maintainer-approved severity, override, install/publish, and tagging semantics rather than a one-off linter in a single loader.
