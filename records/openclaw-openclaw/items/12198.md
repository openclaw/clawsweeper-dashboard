## Summary

Keep open. Current main still places prompt-bearing workspace Markdown into model context without a shared content-validation contract, while the existing skill scanner and install checks cover narrower code-safety boundaries. The remaining rule taxonomy and enforcement posture are security-sensitive product decisions.

## What This Changes

Add configurable security validation for prompt-bearing Markdown, including workspace bootstrap files, skill definitions, and ClawHub publishing or installation paths.

## Best Possible Solution

Define one structured validator that produces stable finding identifiers, severity, location, and provenance, then apply it at every prompt-bearing ingestion boundary while keeping enforcement policy separate: core should own runtime warnings or blocking behavior, and ClawHub should own publish/install scanning and labeling. Document overrides, compatibility behavior, diagnostics, and focused tests before enabling fail-closed enforcement.
