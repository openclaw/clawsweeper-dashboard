## Summary

Keep this open: current main and the latest release still have boundary checks, size limits, frontmatter parsing, install policy hooks, and Skill Workshop proposal scanning, but they do not provide the shared prompt-bearing Markdown validation contract requested across bootstrap files, runtime SKILL.md reads, native skill installs, and ClawHub publish/install policy.

## What This Changes

The issue requests validation for Markdown files that can become prompt-bearing instructions, especially workspace bootstrap files and SKILL.md skill definitions.

## Best Possible Solution

Define one shared prompt-bearing Markdown validation contract, then apply it consistently to workspace bootstrap ingestion, extra bootstrap files, normal SKILL.md discovery/read paths, native ClawHub skill install/update, and ClawHub publish-side scan/tag behavior.

## Reproduction Assessment

Yes: source inspection shows the relevant prompt-bearing Markdown paths still apply boundary, size, frontmatter, or code-scanner checks without a shared Markdown injection validation contract.

## Solution Assessment

Unclear until maintainers decide the policy: the useful direction is shared validation, but the severity model, overrides, ClawHub tagging, and install/publish behavior are product and security choices.
