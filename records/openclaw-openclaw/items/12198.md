## Summary

Keep open. Current main now has ClawHub scan visibility, trust-envelope verification, a cross-source `security.installPolicy` hook, and governed Skill Workshop writes, but prompt-bearing workspace Markdown and selected `SKILL.md` content still reach the model without one shared content-validation contract. The remaining finding taxonomy and block-versus-warn behavior require explicit security/product direction.

## What This Changes

Request a shared Markdown security-validation layer for prompt-bearing workspace files, skill reads, ClawHub publishing/install, and optionally agent-written files.

## Best Possible Solution

Define one shared, explainable finding schema for model-visible Markdown; apply it at workspace-context and skill-read boundaries, reuse it in Skill Workshop and ClawHub trust signals, default to warnings or quarantine, and reserve blocking for high-confidence findings with explicit operator override.
