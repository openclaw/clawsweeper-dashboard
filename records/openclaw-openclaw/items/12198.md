## Summary

Keep this open. Current main still inserts user-editable workspace Markdown into Project Context, and the related Markdown scanner PR was closed unmerged; deciding which prompt-bearing Markdown is blocked, warned, tagged, or allowed remains a shared security and product-contract decision rather than a narrow scanner fix.

## What This Changes

Add validation or safety handling for Markdown that OpenClaw reads into agent prompt context, especially workspace bootstrap files and skill `SKILL.md` content.

## System Context

OpenClaw loads workspace bootstrap files and skills, then assembles selected Markdown into the agent system prompt as Project Context. This proposal would add a trust and validation boundary before those files influence model-visible instructions.

## Architecture Diagram

flowchart LR
  A[Workspace bootstrap files] --> C[Workspace and skill loaders]
  B[Skill SKILL.md files] --> C
  C --> D[Prompt-bearing Markdown policy]
  D --> E[Warnings, blocks, or annotations]
  E --> F[System prompt Project Context]
  G[ClawHub install and publish] --> D

## Best Possible Solution

Define one owner-approved prompt-bearing Markdown trust contract, apply it consistently at every ingestion boundary, and specify severity, diagnostics, optional overrides, ClawHub publish/install behavior, documentation, and focused cross-path tests before implementation.
