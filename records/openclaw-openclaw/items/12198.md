## Summary

Keep open: current main and the latest release still do not provide a shared prompt-bearing Markdown validation contract across bootstrap context, runtime SKILL.md reads, Skill Workshop, active scanner/audit paths, and ClawHub install or publish policy. The open scanner PR is useful related work, but it is unmerged, conflicting, and only covers one slice of the requested security hardening.

## What This Changes

The issue requests validation for Markdown files that become model-visible prompt content, especially skill definitions and ClawHub publishing or install paths, to flag prompt-injection and security-risk patterns.

## Best Possible Solution

Define one threat-model-backed prompt-bearing Markdown validation and diagnostics contract, then apply it consistently to bootstrap context, runtime SKILL.md loading, Skill Workshop, ClawHub install/update, and ClawHub publish-side scan/tag behavior with explicit docs and tests.

## Reproduction Assessment

Yes, at source level: current bootstrap, prompt assembly, runtime SKILL.md loading, scanner/audit, and ClawHub install paths show no shared prompt-bearing Markdown validation policy. This is not a strict bug reproduction because current docs/tests do not already promise such a validator.

## Solution Assessment

No, not as the full proposal or as a scanner-only change. The maintainable solution is a shared security contract with maintainer-decided rules, severity, overrides, workspace-write behavior, and ClawHub policy.
