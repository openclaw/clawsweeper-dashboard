## Summary

Keep open: current main and v2026.6.11 still have only partial skill-content scanning and do not provide a shared prompt-bearing Markdown validation contract across bootstrap files, normal SKILL.md reads, ClawHub install/update, and publish policy; the open scanner PR is partial and unmerged.

## What This Changes

Request to add validation for Markdown files that become prompt context, especially SKILL.md and ClawHub skill content, to catch prompt-injection or security-risk patterns.

## Best Possible Solution

Define one threat-model-backed prompt-bearing Markdown validation and diagnostics contract, then apply it consistently to bootstrap context, runtime SKILL.md loading/reads, native ClawHub install/update, and publish-side scan/tag behavior without hidden git-state tracking.

## Reproduction Assessment

Yes, at source level: current main still appends bootstrap context and exposes SKILL.md reads without a shared prompt-bearing Markdown validator. This is not a strict bug reproduction because current docs/tests do not define that validator as existing behavior.

## Solution Assessment

No, not as a scanner-only change or the full proposed validation-state design. The maintainable solution is a shared security contract with maintainer-decided rules, severity, override behavior, workspace-write scope, and ClawHub policy.
