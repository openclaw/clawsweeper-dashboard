## Label Justifications

- `P1`: The item concerns an unbounded gateway restart loop, while the proposed implementation can also stall channel recovery.
- `merge-risk: 🚨 availability`: The new pre-continuation cap can leave a channel unavailable in pending recovery until an hourly record expires.
- `merge-risk: 🚨 compatibility`: Existing low `maxRestartsPerHour` configurations would acquire a new recovery-stalling behavior and larger values would count one two-pass recovery twice.

## Summary

The report identifies a real current-main bug, but this implementation can block the intentional second pass of a timed-out recovery whenever the first pass exhausts the hourly budget. The PR needs a narrow accounting repair plus focused and real-runtime proof before merge.

## What This Changes

The PR makes pending channel restart attempts consume the hourly restart budget while retaining their cooldown exemption.

## Best Possible Solution

Preserve completion of the current two-pass recovery, then count and cap only additional failed recovery cycles so permanently pending state is bounded without blocking the in-progress handoff.
