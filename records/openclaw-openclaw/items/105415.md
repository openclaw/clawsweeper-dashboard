## Summary

Current main still contains the reported infinite pending-restart budget bypass, and this PR remains a viable fix candidate. It is not merge-ready because the contributor evidence is test-harness-only and the intentional extra completion call needs gateway-owner confirmation against the documented restart ceiling.

## What This Changes

The PR counts pending channel recovery attempts against the hourly restart budget, permits one unrecorded completion attempt at the cap, resets that allowance when rolling-window capacity returns, and adds regression tests.

## Best Possible Solution

Use one gateway-owned restart state machine that accounts for pending recovery, allows at most one explicitly approved completion handoff per rolling window, resets that allowance when capacity reopens, and documents the resulting effective ceiling.
