## Summary

Keep this PR open: current main still has the pending-restart budget bypass, and the proposed state-machine repair has no blocking code finding, but this external PR still lacks inspectable after-fix real-environment proof for the full cap-to-rollover-to-re-cap lifecycle.

## What This Changes

The PR makes pending gateway restarts consume the hourly restart budget, permits one unrecorded completion attempt at the cap, resets that allowance when pruning reopens capacity, and adds regression coverage.

## Best Possible Solution

Land the monitor-local budget accounting only after redacted continuous runtime evidence shows one real monitor cap pending retries, remain capped, reopen after rolling-window pruning, consume fresh capacity, grant one completion pass, and cap again.
