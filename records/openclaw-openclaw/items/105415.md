## Summary

Keep this PR open as the live candidate for the pending-restart loop. Earlier correctness findings appear resolved and no new patch defect is established, but the posted evidence remains a synthetic Vitest scenario rather than real channel-adapter proof, and the intentional one-call-over-cap behavior needs gateway-owner confirmation before merge.

## What This Changes

The PR makes pending channel restarts consume hourly restart slots, permits one unrecorded completion pass at the cap, resets that pass when rolling-window capacity reopens, and adds regression coverage.

## Best Possible Solution
