## Summary

This PR addresses a real pending-restart loop, but the current implementation still blocks the required second pass when the initiating recovery consumes the final hourly slot. The force-push added regression coverage without changing that previously reported P1 defect, and the PR still lacks observed gateway behavior proof.

## What This Changes

The PR makes pending channel restart continuations consume and obey the hourly restart budget and adds a fake-timer regression test for a permanently pending channel.

## Best Possible Solution

Charge the initiating recovery once, permit its pending completion pass exactly once even at the limit, and reject later stuck-pending retries until a new recovery is admitted.
