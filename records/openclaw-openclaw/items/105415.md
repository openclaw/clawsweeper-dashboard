## Summary

Keep open: the patch plausibly fixes the pending-restart budget bypass, but merge still needs real gateway proof and an owner decision on whether the configured hourly maximum may intentionally permit one additional unrecorded call.

## What This Changes

The PR makes pending channel restart attempts consume the hourly restart budget, adds a one-time completion pass at the cap, resets that pass after rolling-window capacity reopens, and adds regression tests.

## Best Possible Solution

Define maxRestartsPerHour as either a strict invocation cap or a documented logical-restart budget, implement that contract as one explicit monitor state machine, and prove cap-to-rollover behavior on a real configured gateway.
