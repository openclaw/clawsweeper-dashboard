## Summary

Keep open: the mobile drawer fallbacks use a valid ordinary-property cascade shape, but the focus-ring fallback still gets overwritten by an unsupported color-mix() custom-property value and the external PR still lacks inspectable after-fix browser proof.

## What This Changes

The PR adds CSS fallbacks for Control UI focus rings, mobile nav drawer shadow/backdrop, and collapsed-sidebar active accents in browsers without color-mix().

## Best Possible Solution

Keep solid --focus-ring defaults, move blended values into @supports or use-site fallbacks, preserve the mobile ordinary-property fallbacks, and require redacted older-browser visual proof.

Yes, source inspection gives a high-confidence reproduction path: current main and the PR head route focus-visible shadows through --focus-ring values that can still contain color-mix() in no-color-mix browsers. I did not run Firefox 112 or old Safari in this read-only review.

## Solution Assessment

No. The layout.mobile.css additions are the right fallback pattern, but base.css needs @supports-guarded custom-property values or use-site fallbacks so the solid ring actually wins in older browsers.
