## Summary

Keep open. The mobile ordinary-property fallbacks are shaped correctly, but current PR head still immediately overrides the focus-ring fallback with a color-mix() custom-property value, and the PR has no inspectable after-fix browser proof.

## What This Changes

Adds CSS fallback declarations for Control UI focus-ring custom properties and mobile navigation drawer, backdrop, and accent styles when color-mix() is unsupported.

## Best Possible Solution

Keep solid --focus-ring values as the default, apply blended values only inside @supports or at box-shadow use sites, keep the drawer ordinary-property fallbacks, and require redacted no-color-mix browser proof before merge.

## Solution Assessment

No. The mobile drawer fallback shape is acceptable, but base.css needs @supports-guarded custom-property values or use-site fallbacks so the solid ring actually wins in no-color-mix browsers.
