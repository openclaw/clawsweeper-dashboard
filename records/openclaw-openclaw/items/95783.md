## Summary

Keep open: the mobile drawer ordinary-property fallbacks are plausible, but the focus-ring custom-property fallback still gets overridden by color-mix() and there is no inspectable real-browser proof attached.

## What This Changes

The PR adds CSS fallback declarations for Control UI focus-ring custom properties and mobile drawer shadow/backdrop/accent styles when color-mix() is unsupported.

## Best Possible Solution

Keep the solid focus-ring value as the default, move blended color-mix() focus-ring values behind @supports or to use-site fallbacks, keep the ordinary-property mobile drawer fallbacks, and merge only after inspectable no-color-mix browser proof.

## Solution Assessment

No. The layout.mobile.css fallback shape is acceptable, but base.css needs @supports-guarded custom-property values or use-site fallbacks so the solid ring actually wins in no-color-mix browsers.
