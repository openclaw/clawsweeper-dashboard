## Summary

Keep open: the PR targets a real older-browser Control UI compatibility bug, but the current head still leaves the focus-ring fallback ineffective and lacks inspectable real behavior proof.

## What This Changes

The PR adds CSS fallback declarations for Control UI focus rings, mobile drawer shadows/backdrops, and collapsed sidebar active accents when color-mix() is unsupported.

## Best Possible Solution

Keep the solid focus-ring value as the default, move blended color-mix() focus-ring values behind @supports or use-site fallbacks, keep the ordinary-property drawer fallbacks, and require inspectable older-browser proof before merge.

## Reproduction Assessment

Yes at source level: current main puts color-mix() in --focus-ring and mobile drawer declarations used by focus-visible and drawer UI paths. I did not run Firefox 112 or old Safari in this read-only review.

## Solution Assessment

No as-is: layout.mobile.css uses the right ordinary-property fallback shape, but base.css needs @supports-guarded custom-property values or use-site fallbacks so the solid ring actually wins in no-color-mix browsers.
