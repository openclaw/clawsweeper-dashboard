## Summary

Keep this PR open because current main and the latest release still have the older-browser `color-mix()` compatibility problem, but the current PR head still does not actually fix the `--focus-ring` custom-property fallback and it lacks inspectable real behavior proof.

## What This Changes

The PR adds CSS fallback declarations for Control UI focus rings, the mobile navigation drawer shadow/backdrop, and collapsed-sidebar active accents when `color-mix()` is unsupported.

## Best Possible Solution

Keep the solid `--focus-ring` value as the default, move the blended `color-mix()` focus-ring values behind `@supports` or equivalent use-site fallbacks, keep the ordinary-property mobile drawer fallbacks, and require inspectable older-browser proof before merge.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, by source inspection. Current main and `v2026.6.11` route focus-visible shadows through `var(--focus-ring)` while `--focus-ring` contains `color-mix()`, and mobile drawer styles also use `color-mix()` without release fallbacks.

## Solution Assessment

No. The mobile drawer fallback pattern is reasonable, but the `base.css` custom-property fallback is not the best fix because the later `color-mix()` declaration still wins unless it is guarded by `@supports` or moved to validated use sites.
