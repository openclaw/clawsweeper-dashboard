## Summary

Keep open: this PR addresses a real current-main sandbox hardening gap, but the proposed unconditional default is upgrade-sensitive and still lacks a documented opt-out contract, focused tests, and real Docker behavior proof.

## What This Changes

Adds a `DEFAULT_SANDBOX_PIDS_LIMIT = 1024` constant and uses it as the fallback Docker sandbox `pidsLimit` when agent and global config omit the field.

## Best Possible Solution

Land this or a narrow replacement only after maintainers approve the default and opt-out semantics, then align schema, type/docs, focused tests, and real Docker proof.

## Reproduction Assessment

Yes. Source-level reproduction is clear: resolve Docker sandbox config with no `pidsLimit`, then build Docker create args; current main leaves the value undefined and emits no `--pids-limit`.

## Solution Assessment

No. The resolver fallback is a plausible mitigation, but it is not the best mergeable shape until the default value, opt-out semantics, schema/docs, tests, and real Docker proof are aligned.
