## Summary

Keep open: the PR targets a real current-main sandbox hardening gap, but it changes Docker sandbox default and upgrade behavior without a validated opt-out contract, docs/tests, or real Docker behavior proof.

## What This Changes

The PR adds a `DEFAULT_SANDBOX_PIDS_LIMIT` constant and makes `resolveSandboxDockerConfig` default unset Docker sandbox `pidsLimit` to 1024.

## Best Possible Solution

Merge a narrow sandbox hardening patch only after the default PID cap and validated opt-out behavior are approved, documented, covered by resolver/create-args tests, and shown with real Docker proof.

## Reproduction Assessment

Yes, source-level. On current main, resolving Docker sandbox config with no `pidsLimit` leaves it undefined and `buildSandboxCreateArgs` emits no `--pids-limit`; Docker CLI help confirms that flag is the container PID cap.

## Solution Assessment

No, not yet. The resolver fallback is the right layer for a default, but this PR is incomplete because it changes upgrade behavior without an aligned opt-out contract, docs, tests, and real Docker proof.
