## Summary

Keep open: current main and v2026.6.11 still leave Docker sandbox `pidsLimit` unset by default, but this PR is not merge-ready because it changes an upgrade-sensitive sandbox default without a clear opt-out/schema/docs/test contract or real Docker proof.

## What This Changes

The PR adds a `DEFAULT_SANDBOX_PIDS_LIMIT = 1024` constant and uses it as the fallback value when sandbox Docker config has no agent or global `pidsLimit`.

## Best Possible Solution

Land this only after maintainers approve the default cap and the patch includes an explicit opt-out/upgrade contract, docs/schema alignment, focused tests, and real Docker proof.

## Reproduction Assessment

Yes for source reproduction: current main resolves unset `pidsLimit` to `undefined`, and `buildSandboxCreateArgs` emits no `--pids-limit` when the value is unset. I did not run a real Docker sandbox in this read-only review.

## Solution Assessment

No, not as submitted. The resolver fallback is the narrow implementation point, but the best fix also needs maintainer-approved default/opt-out semantics, docs/schema alignment, tests, and real Docker proof.
