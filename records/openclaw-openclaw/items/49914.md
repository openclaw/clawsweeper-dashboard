## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Restore or clear the full session boundary:** `src/auto-reply/reply/commands-sessions.ts:277-280`
  - body: This rewrites the active entry to the target session and then only reapplies the small `SessionHistoryItem.metadata` subset. Fields such as auth profile overrides, CLI/ACP runtime bindings, runtime model cache, fallback notices, abort state, cost, and exec/elevated policy can remain from the outgoing session, so a restored transcript may continue under the wrong credentials or tool policy.
  - confidence: 0.87
- **[P1] Protect retained history transcripts from cleanup:** `src/config/sessions/types.ts:253-257`
  - body: The new `sessionHistory` state intentionally keeps old transcripts switchable, but the existing disk-budget reference graph only marks each active entry and compaction checkpoints as referenced. With `session.maintenance.maxDiskBytes`, a retained history transcript can be pruned as unreferenced while `/sessions` still lists it as switchable.
  - confidence: 0.83
- **[P2] Honor disabled history before resolving targets:** `src/auto-reply/reply/commands-sessions.ts:258-264`
  - body: `/sessions` builds targets from persisted history before checking `session.historyLimit`, and the switch path only enforces the limit after selecting a target. If an operator changes the limit to `0` while history exists, old sessions remain listed and switchable, and the current session is pushed then immediately evicted and archived.
  - confidence: 0.9
