## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P2] Honor disabled history before listing or switching:** `src/auto-reply/reply/commands-sessions.ts:170`
  - body: `session.historyLimit=0` is documented as disabling switchable history, but this path builds `/sessions` output and switch targets from persisted `sessionHistory` before reading the limit. If an operator disables the feature after history exists, old sessions remain reachable and switching with limit 0 archives the current session through the zero-limit eviction path.
  - confidence: 0.9
- **[P1] Restore or reset the full session boundary on switch:** `src/auto-reply/reply/commands-sessions.ts:280`
  - body: Switching rewrites the active `SessionEntry` and then restores only the narrow history metadata subset. Fields such as abort cutoffs, auth profile overrides, exec/elevated policy, CLI/ACP runtime handles, runtime model, fallback state, cost, and system prompt reports can leak from the session being left into the session being resumed.
  - confidence: 0.88
- **[P1] Protect retained history transcripts during cleanup:** `src/auto-reply/reply/session.ts:648-649`
  - body: The PR keeps old transcripts live while their session ids remain in `sessionHistory`, but the disk-budget sweep only protects active entry transcript paths. With `session.maintenance.maxDiskBytes` enabled, retained history transcripts can be deleted while `/sessions` still lists them as switchable.
  - confidence: 0.84
- **[P2] Document the new slash command in source docs:** `src/auto-reply/commands-registry.shared.ts:297-300`
  - body: This registers a user-visible `/sessions` command, but the source slash-command docs still list only `/new`, `/reset`, `/session idle`, and `/session max-age` for this area. The command should be documented with its supported targets and direct-chat scope so docs do not drift from runtime behavior.
  - confidence: 0.82
