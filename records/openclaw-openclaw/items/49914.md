## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.82

Full review comments:

- **[P1] Align the command contract with the advertised switch forms:** `src/auto-reply/reply/commands-sessions.ts:148-150`
  - body: The PR body and linked request advertise `/session <number|sessionId|back>`, but this new handler only matches `/sessions`. Current `handleSessionCommand` still returns usage for any `/session` action other than `idle` or `max-age`, so users following the advertised command cannot switch sessions; either wire those forms through the switch path or deliberately change the public contract and docs/tests after maintainer agreement.
  - confidence: 0.9
- **[P1] Restore or clear all session-scoped state before persisting:** `src/auto-reply/reply/commands-sessions.ts:119-141`
  - body: `applyHistoryMetadata` restores only a subset of SessionEntry before `persistSessionEntry`, leaving auth profile overrides, runtime model fields, CLI/ACP handles, exec/elevated policy, fast/usage mode, fallback notice state, abort state, and cost totals from the outgoing session. A resumed transcript can therefore keep talking with the wrong credentials, provider-side thread, or execution policy until a later turn happens to overwrite those fields.
  - confidence: 0.86
- **[P1] Preserve history transcripts in disk-budget references:** `src/auto-reply/reply/session.ts:649`
  - body: This line intentionally keeps prior transcripts switchable by storing them in `sessionHistory`, but the existing disk-budget cleanup only marks each store entry's active `sessionId` and compaction checkpoints as referenced. With `session.maintenance.maxDiskBytes` enabled, retained history transcripts can be deleted as unreferenced while `/sessions` still lists them, so switching back can land in an empty or missing transcript.
  - confidence: 0.82
- **[P2] Block disabled-history switches before building targets:** `src/auto-reply/reply/commands-sessions.ts:258-264`
  - body: The switch path resolves targets from existing `sessionHistory` before enforcing `historyLimit`. If an operator changes `session.historyLimit` to `0` after history exists, `/sessions` can still list and switch to stale entries, and the current session is pushed then immediately archived by the zero-limit eviction loop.
  - confidence: 0.78
