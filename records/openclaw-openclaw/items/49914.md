Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Restore or clear the full session boundary:** `src/auto-reply/reply/commands-sessions.ts:280`
  - body: `/sessions` rewrites the live `SessionEntry` into the target session and only reapplies `SessionHistoryItemMetadata`. That metadata omits auth profile, runtime model/provider, CLI/ACP handles, abort/fallback/cost, and exec/elevated policy fields, so the resumed transcript can inherit credentials or sandbox/runtime state from the outgoing session.
  - confidence: 0.9
- **[P1] Protect retained history transcripts from cleanup:** `src/auto-reply/reply/session.ts:649`
  - body: The reset path now keeps previous transcripts switchable while they are in `sessionHistory`, but the disk-budget reference graph still only protects active entry artifacts and compaction checkpoints. A retained history transcript can therefore be removed as an unreferenced primary transcript while `/sessions` still lists it as switchable.
  - confidence: 0.87
- **[P2] Honor disabled history before listing switch targets:** `src/auto-reply/reply/commands-sessions.ts:258`
  - body: The command builds switch targets from existing `sessionHistory` before checking `historyLimit`. If an operator sets `session.historyLimit` to `0` after history exists, `/sessions` still exposes old sessions and switching pushes the current session into a zero-length history, archiving it during the attempted switch.
  - confidence: 0.84
