## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Restore or clear the full session boundary:** `src/auto-reply/reply/commands-sessions.ts:277-280`
  - body: This switches sessions by rewriting the current `SessionEntry` and then applying only `SessionHistoryItem.metadata`. Current main stores auth profile overrides, execution/elevated settings, runtime model/harness, CLI/ACP bindings, delivery state, plugin state, fallback notices, and pending delivery on the same object, so the resumed session can continue under state from the session the user meant to leave.
  - confidence: 0.9
- **[P1] Keep retained history transcripts referenced:** `src/auto-reply/reply/session.ts:690-719`
  - body: The PR intentionally leaves history transcripts switchable until LRU eviction, but current disk-budget cleanup only treats active session entries and compaction checkpoints as referenced. With `session.maintenance.maxDiskBytes`, a retained history transcript can be deleted while `/sessions` still lists it, so switching back can reopen an empty or missing conversation.
  - confidence: 0.87
- **[P2] Honor disabled history before listing or switching:** `src/auto-reply/reply/commands-sessions.ts:213-219`
  - body: `/sessions` builds targets from persisted `sessionHistory` before checking `session.historyLimit`. If an operator changes the setting to `0`, stale sessions remain visible and selectable; switching then requeues and immediately evicts the current session instead of treating history as disabled.
  - confidence: 0.88
- **[P2] Archive cleared history when disabling retention:** `src/auto-reply/reply/session.ts:650-651`
  - body: When `historyLimit` is `0`, this clears the entire existing `sessionHistory` array but later archives only the immediately previous session. Older retained history entries are dropped from state without going through the archive path, leaving transcript files orphaned outside the intended retention lifecycle.
  - confidence: 0.82
- **[P2] Match ID prefixes before numeric indices:** `src/auto-reply/reply/commands-sessions.ts:219-222`
  - body: The command treats an all-digit argument as a rendered list index before exact or prefix session-id matching. Numeric session-id prefixes therefore cannot select the advertised matching session and can jump to a different index or report not found.
  - confidence: 0.76
