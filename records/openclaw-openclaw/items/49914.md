## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Honor disabled history before listing or switching:** `src/auto-reply/reply/commands-sessions.ts:170`
  - body: This still builds `/sessions` output from `sessionHistory` before checking `session.historyLimit`. If an operator changes the limit to `0` while retained entries exist, the command still exposes and can switch to stale sessions, and the later eviction loop archives the outgoing session as a side effect instead of treating history as disabled.
  - confidence: 0.94
- **[P1] Protect retained history transcripts from cleanup:** `src/auto-reply/reply/session.ts:649`
  - body: The PR now intentionally keeps old transcripts switchable while they are in `sessionHistory`, but disk-budget cleanup still only treats each store entry's active transcript as referenced. Under `session.maintenance.maxDiskBytes`, a retained history transcript can be deleted while `/sessions` still lists it, so switching back lands on an empty or missing transcript.
  - confidence: 0.9
- **[P1] Restore the full session boundary before persisting:** `src/auto-reply/reply/commands-sessions.ts:280`
  - body: The switch path rewrites `sessionId`/`sessionFile` and applies only `SessionHistoryItem.metadata`, leaving outgoing-session fields such as auth profile overrides, CLI bindings, ACP runtime state, execution/elevated settings, runtime model, cost/fallback state, abort cutoffs, and plugin session extensions on the resumed session. That can resume a transcript under the wrong credentials, provider runtime, or tool policy; restore a complete session-owned snapshot or narrow the feature so these fields cannot leak.
  - confidence: 0.92
