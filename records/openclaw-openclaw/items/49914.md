## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P2] Honor disabled history before building targets:** `src/auto-reply/reply/commands-sessions.ts:170`
  - body: `session.historyLimit=0` is documented as disabling switchable history, but this path still builds `/sessions` output from persisted `sessionHistory` before checking the limit. If an operator disables the feature after history exists, old sessions remain visible and switchable until another reset happens.
  - confidence: 0.9
- **[P1] Restore or clear the full session boundary:** `src/auto-reply/reply/commands-sessions.ts:280`
  - body: Switching rewrites the active `SessionEntry` and then restores only the narrow history metadata subset. Fields such as abort cutoffs, fast/usage settings, auth profile overrides, exec/elevated policy, CLI/ACP handles, runtime model, fallback state, cost, and system prompt reports can leak from the session being left into the resumed session.
  - confidence: 0.88
- **[P1] Protect retained history transcripts during cleanup:** `src/auto-reply/reply/session.ts:691-692`
  - body: The PR keeps old transcripts live while their session ids remain in `sessionHistory`, but the disk-budget sweep only protects active entry transcript paths. With `session.maintenance.maxDiskBytes` enabled, retained history transcripts can be deleted while `/sessions` still lists them as switchable.
  - confidence: 0.84
