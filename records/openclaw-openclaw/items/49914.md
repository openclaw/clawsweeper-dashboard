Full review comments:

- **[P1] Honor disabled history before building switch targets:** `src/auto-reply/reply/commands-sessions.ts:213`
  - body: `buildSwitchableSessionList` always includes persisted `sessionHistory`, and the handler does not read `historyLimit` until after it has resolved the requested target. If an operator changes `session.historyLimit` to `0` while history entries already exist, `/sessions` can still list and switch to those prior conversations even though the config says switchable history is disabled.
  - confidence: 0.91
- **[P1] Restore or clear the full session boundary:** `src/auto-reply/reply/commands-sessions.ts:280`
  - body: After replacing `sessionId` and `sessionFile`, the switch path only applies the small `SessionHistoryItem.metadata` subset. Fields omitted from that snapshot, including CLI bindings, auth profile overrides, ACP state, execution settings, abort flags, runtime model fields, fallback notices, and cost/usage state, remain from the outgoing session and can make the next turn continue under the wrong backend, credentials, or policy.
  - confidence: 0.9
- **[P1] Protect retained history transcripts during cleanup:** `src/auto-reply/reply/session.ts:649`
  - body: This PR intentionally leaves prior transcripts unarchived while they remain in `sessionHistory`, but disk-budget cleanup still only treats the active store entry and compaction checkpoints as referenced. Deployments with `session.maintenance.maxDiskBytes` can delete a retained history transcript as unreferenced while `/sessions` still advertises it as switchable, causing the restored session to reopen empty or incomplete.
  - confidence: 0.87
