## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P1] Honor disabled history before listing sessions:** `src/auto-reply/reply/commands-sessions.ts:170`
  - body: `/sessions` builds its list from stored `sessionHistory` before checking `session.historyLimit`, and switching resolves targets before the limit is read. If an operator changes the limit to `0` while history entries exist, old sessions remain visible and switchable even though history is disabled; return the disabled-history response before listing or resolving targets.
  - confidence: 0.91
- **[P1] Keep retained transcripts referenced during cleanup:** `src/auto-reply/reply/session.ts:649`
  - body: This PR intentionally leaves history transcripts on disk while they remain switchable, but disk-budget cleanup only marks the active entry transcript and compaction files as referenced. With `session.maintenance.maxDiskBytes`, a retained history transcript can be deleted while `/sessions` still lists it, so switching back lands in an empty or missing transcript; include `sessionHistory` transcript paths in cleanup references or archive them instead.
  - confidence: 0.89
- **[P1] Restore or clear the whole session boundary:** `src/auto-reply/reply/commands-sessions.ts:280`
  - body: After changing `sessionId` and `sessionFile`, the switch path reapplies only a small metadata subset. Session-bound fields such as auth profile overrides, CLI bindings, ACP runtime state, fast mode, exec/elevated settings, abort state, fallback notices, and system prompt reports can leak from the session being left into the resumed session, so persist and restore the full boundary or deliberately clear those fields.
  - confidence: 0.93
