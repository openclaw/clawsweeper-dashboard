Full review comments:

- **[P1] Restore the full session boundary before persisting the switch:** `src/auto-reply/reply/commands-sessions.ts:280`
  - body: `applyHistoryMetadata` only restores a narrow subset of `SessionEntry`. After the PR mutates `sessionEntry.sessionId`, the resumed transcript can inherit the outgoing session's auth profile, provider runtime, CLI/ACP handles, exec/elevated policy, abort/fallback state, or cost/runtime model fields, so future turns can run under the wrong session boundary. Restore or deliberately clear the full session-scoped state before persisting the switch.
  - confidence: 0.88
- **[P1] Protect retained history transcripts from cleanup:** `src/auto-reply/reply/session.ts:649`
  - body: This keeps old transcripts switchable by storing them in `sessionHistory`, but existing disk-budget cleanup only marks each active entry and compaction checkpoints as referenced. A retained historical transcript can therefore be removed as unreferenced while `/sessions` still lists it, causing a switch back into an empty/missing conversation.
  - confidence: 0.84
- **[P2] Block switching when history is disabled:** `src/auto-reply/reply/commands-sessions.ts:258-264`
  - body: The command resolves targets from persisted history before checking `session.historyLimit`. If an operator changes the new setting to `0` after history exists, stale entries remain listable and switchable until a later rollover clears them, contradicting the documented disable behavior and potentially archiving the current session during the switch.
  - confidence: 0.82
