Full review comments:

- **[P1] Honor disabled history before resolving targets:** `src/auto-reply/reply/commands-sessions.ts:213`
  - body: `allItems` is built from persisted `sessionHistory` before `historyLimit` is read at line 258. If an operator changes `session.historyLimit` to `0` while retained entries still exist, `/sessions <n>` can still switch to them and then evict/archive the outgoing current session even though history is disabled.
  - confidence: 0.88
- **[P1] Keep retained history transcripts referenced by cleanup:** `src/auto-reply/reply/session.ts:649`
  - body: This PR deliberately leaves prior transcripts switchable by assigning `sessionHistory`, but current main's disk-budget reference collector only protects active entry artifacts and checkpoints. With `session.maintenance.maxDiskBytes`, cleanup can delete a transcript that `/sessions` still advertises as switchable.
  - confidence: 0.86
- **[P1] Restore or clear the full session boundary:** `src/auto-reply/reply/commands-sessions.ts:280`
  - body: The switch mutates the live `SessionEntry` and reapplies only the small history metadata subset. Fields such as `authProfileOverride`, CLI/ACP handles, exec/elevated policy, abort/fallback/runtime model, response usage, and cost are neither restored nor cleared, so the target session can inherit credentials or tool policy from the outgoing session.
  - confidence: 0.9
