## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P1] Honor disabled history before listing targets:** `src/auto-reply/reply/commands-sessions.ts:170`
  - body: `session.historyLimit=0` is documented as disabling switchable history, but this path still builds `/sessions` output and switch targets from any persisted `sessionHistory` before checking the limit. If an operator disables history after entries exist, old sessions remain visible/reachable and switching immediately archives the current session through the `while (nextHistory.length > historyLimit)` path.
  - confidence: 0.94
- **[P1] Preserve retained history transcripts during cleanup:** `src/auto-reply/reply/session.ts:649`
  - body: The PR intentionally leaves old transcripts switchable by storing them only in `sessionHistory`, but current disk-budget cleanup marks only active store entries and compaction checkpoints as referenced. Deployments with `session.maintenance.maxDiskBytes` can delete a retained historical transcript while `/sessions` still lists it, causing a switch back into an empty or missing conversation.
  - confidence: 0.9
- **[P1] Restore or clear the full session boundary:** `src/auto-reply/reply/commands-sessions.ts:280`
  - body: After changing `sessionEntry.sessionId`, this call reapplies only the small history metadata subset. Fields such as `authProfileOverride`, CLI session bindings, `elevatedLevel`/`exec*`, `modelProvider`/`model`, `acp`, abort state, fallback notices, and accumulated cost can be inherited from the previous conversation, so a restored session may run with the wrong credentials, sandbox policy, provider thread, or status state.
  - confidence: 0.93
- **[P2] Match session ID prefixes before numeric indexes:** `src/auto-reply/reply/commands-sessions.ts:219-222`
  - body: The advertised target accepts a `sessionId prefix`, but a numeric-only prefix is always interpreted as a rendered list index before exact or prefix matching runs. Session IDs can start with digits, so `/sessions 1234` cannot select the unique session whose ID starts with `1234`; it jumps to item 1234 or reports not found instead.
  - confidence: 0.82
