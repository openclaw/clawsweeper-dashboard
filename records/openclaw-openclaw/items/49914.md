## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Restore the whole session boundary on switch:** `src/auto-reply/reply/commands-sessions.ts:119-141`
  - body: This switch path rewrites `sessionId` and only reapplies the small `SessionHistoryItem.metadata` subset. Current session entries also carry auth profiles, exec/elevated policy, CLI/ACP bindings, runtime model state, abort/fallback state, and other per-session fields, so the resumed session can inherit credentials, tool policy, provider-side threads, or stop state from the outgoing session. Snapshot/restore or explicitly clear the full session boundary before persisting.
  - confidence: 0.91
- **[P1] Reference retained history transcripts during cleanup:** `src/auto-reply/reply/session.ts:649`
  - body: The PR keeps prior transcripts switchable by storing them in `sessionHistory` instead of archiving them, but the current disk-budget sweep only treats the active `entry.sessionId` and compaction checkpoint files as referenced. With a session disk budget enabled, a retained history transcript can be deleted while `/sessions` still lists it, so switching back can land in a missing or empty transcript.
  - confidence: 0.86
- **[P2] Honor disabled history before listing or switching:** `src/auto-reply/reply/commands-sessions.ts:170`
  - body: `historyLimit` is resolved only after the command has built switch targets. If an operator changes `session.historyLimit` to `0` while old history entries exist, `/sessions` can still list and switch to them, and the switch path then pushes the current session into a zero-length queue and archives it. Return the disabled-history response before listing or selecting targets, and clear/archive stale history deterministically.
  - confidence: 0.84
