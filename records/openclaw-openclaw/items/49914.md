## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Honor disabled history before listing or switching:** `src/auto-reply/reply/commands-sessions.ts:213`
  - body: `/sessions` builds targets from persisted `sessionHistory` before checking `session.historyLimit`. If an operator changes the limit to `0` while history entries exist, old sessions remain visible and switchable, and the switch path can then archive the outgoing current session even though history is meant to be disabled.
  - confidence: 0.88
- **[P1] Reference retained history transcripts during cleanup:** `src/auto-reply/reply/session.ts:648-649`
  - body: This PR intentionally leaves history transcripts on disk so they can be switched back to, but current disk-budget cleanup only treats the active entry transcript and compaction checkpoint files as referenced. Deployments with `session.maintenance.maxDiskBytes` can therefore delete transcripts that `/sessions` still advertises as switchable.
  - confidence: 0.86
- **[P1] Restore the full session boundary before persisting:** `src/auto-reply/reply/commands-sessions.ts:280`
  - body: The switch path mutates the active `SessionEntry` and reapplies only the small history metadata subset. Fields such as auth profile, CLI/ACP handles, execution policy, abort state, runtime model, fallback notices, response usage, and cost can be inherited from the outgoing session, so a resumed session can run with the wrong credentials, tool policy, or provider-side thread.
  - confidence: 0.9
