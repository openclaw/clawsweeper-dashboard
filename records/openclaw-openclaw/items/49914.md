## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Restore the full session boundary before persisting:** `src/auto-reply/reply/commands-sessions.ts:280`
  - body: This switch mutates the live `SessionEntry` into the target session and only reapplies `SessionHistoryItem.metadata`. Fields such as auth profile overrides, CLI/ACP session bindings, exec/elevated policy, runtime model state, fallback notice state, abort state, usage mode, and cost can remain from the outgoing session, so the resumed transcript can run under the wrong credentials or execution policy.
  - confidence: 0.9
- **[P2] Honor disabled history before resolving switch targets:** `src/auto-reply/reply/commands-sessions.ts:213`
  - body: `session.historyLimit=0` is documented as disabling switchable history, but this builds targets from persisted `sessionHistory` before checking the limit. If an operator disables history after entries exist, `/sessions` still exposes them and `/sessions back` can switch while archiving the current session.
  - confidence: 0.86
- **[P2] Keep retained history transcripts referenced during cleanup:** `src/auto-reply/reply/session.ts:649`
  - body: The PR intentionally keeps prior transcripts switchable through `sessionHistory`, but current disk-budget cleanup only treats active entries and compaction checkpoints as referenced. With `session.maintenance.maxDiskBytes`, a retained history transcript can be deleted while `/sessions` still lists it as switchable.
  - confidence: 0.84
