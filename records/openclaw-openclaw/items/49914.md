## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Honor disabled history before resolving targets:** `src/auto-reply/reply/commands-sessions.ts:213`
  - body: `/sessions` builds switch targets from persisted `sessionHistory` before checking `session.historyLimit`. If an operator disables history while stale entries exist, old sessions remain listable and switchable, and the switch path can archive the outgoing current session even though history is disabled.
  - confidence: 0.88
- **[P1] Keep retained history transcripts referenced by cleanup:** `src/auto-reply/reply/session.ts:648-649`
  - body: This PR intentionally keeps prior transcripts switchable by assigning `sessionHistory`, but disk-budget cleanup only treats active entry artifacts and checkpoints as referenced. Deployments with `session.maintenance.maxDiskBytes` can delete a transcript that `/sessions` still advertises as switchable.
  - confidence: 0.86
- **[P1] Restore or clear the full session boundary:** `src/auto-reply/reply/commands-sessions.ts:280`
  - body: The switch path mutates the active `SessionEntry` and reapplies only the small history metadata subset. Fields such as auth profile, CLI/ACP handles, execution policy, abort state, runtime model, fallback notices, response usage, and cost can be inherited from the outgoing session, so a resumed session can run with the wrong credentials, tool policy, or provider-side thread.
  - confidence: 0.9
