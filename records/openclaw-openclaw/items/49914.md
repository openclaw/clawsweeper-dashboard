Overall correctness: patch is incorrect

Full review comments:

- **[P1] Restore or clear the full session boundary:** `src/auto-reply/reply/commands-sessions.ts:277-280`
  - body: The switch updates the active `SessionEntry` to the target id/file and applies only the narrow history metadata snapshot. Current main has auth profile, runtime/model, CLI/ACP, exec/elevated policy, plugin, delivery, fallback, pending-delivery, and recovery fields that can remain from the session the user just left, so the resumed transcript can run with stale credentials or policy.
  - confidence: 0.9
- **[P1] Keep retained history transcripts referenced:** `src/auto-reply/reply/session.ts:641-649`
  - body: This reset path intentionally leaves prior sessions unarchived while they remain in `sessionHistory`, but the existing disk-budget cleanup only treats active entry artifacts and compaction checkpoints as referenced. A maintenance sweep can therefore delete a transcript that `/sessions` still lists as switchable.
  - confidence: 0.86
- **[P2] Honor disabled history before switching:** `src/auto-reply/reply/commands-sessions.ts:258-264`
  - body: `/sessions <target>` resolves stale history entries before reading `historyLimit`, so a user who sets `session.historyLimit=0` can still switch to an old entry and immediately archive the current session. The command should reject switching when switchable history is disabled.
  - confidence: 0.88
- **[P2] Archive retained entries when disabling history:** `src/auto-reply/reply/session.ts:650-651`
  - body: When history is disabled, this branch clears inherited `sessionHistory` but only archives the immediate previous session later. Older retained transcript entries are silently dropped from the store without being moved into reset-archive retention.
  - confidence: 0.82
