Overall confidence: 0.91

Full review comments:

- **[P1] Block switching when history is disabled:** `src/auto-reply/reply/commands-sessions.ts:213`
  - body: `allItems` is built from persisted `sessionHistory` before the handler reads `session.historyLimit`. If an operator changes the limit to `0` while history exists, `/sessions back` can still switch and then immediately evict/archive the current session, so disabled history is not actually disabled.
  - confidence: 0.91
- **[P1] Reference retained history transcripts during cleanup:** `src/auto-reply/reply/session.ts:649`
  - body: This PR keeps old transcripts switchable by storing `sessionHistory`, but the disk-budget reference collector still only marks active entries and compaction checkpoints. With `session.maintenance.maxDiskBytes`, a retained transcript can be deleted while `/sessions` still lists it.
  - confidence: 0.88
- **[P1] Restore or clear the whole session boundary:** `src/auto-reply/reply/commands-sessions.ts:280`
  - body: The switch mutates the live entry to the target session and applies only `SessionHistoryItemMetadata`. Fields such as auth profile, CLI/ACP bindings, exec policy, abort/fallback state, fast/usage, runtime model, system prompt report, and cost can leak from the session being left into the resumed one.
  - confidence: 0.9
