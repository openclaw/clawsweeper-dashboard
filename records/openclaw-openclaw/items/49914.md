Full review comments:

- **[P1] Restore or clear the full session boundary:** `src/config/sessions/types.ts:81-112`
  - body: `SessionHistoryItemMetadata` only snapshots a small subset of `SessionEntry`, but current main has session-scoped auth profile, runtime/harness, exec/elevated policy, CLI/ACP handles, fallback, delivery, plugin, goal, and stop state. After `/sessions` switches, omitted fields remain from the outgoing conversation, so the resumed transcript can run under the wrong credentials, provider, sandbox, or runtime state.
  - confidence: 0.91
- **[P1] Keep retained history transcripts referenced:** `src/auto-reply/reply/session.ts:648-649`
  - body: This branch intentionally keeps previous transcripts unarchived while they are in `sessionHistory`, but current cleanup only marks active entries and compaction checkpoints as referenced. A disk-budget or unreferenced-artifact sweep can delete a still-listed transcript, leaving `/sessions` pointing at a session that reopens empty or missing history.
  - confidence: 0.87
- **[P2] Honor disabled history before listing or switching:** `src/auto-reply/reply/commands-sessions.ts:213-219`
  - body: `/sessions` builds targets from persisted `sessionHistory` before checking `session.historyLimit`. If an operator changes the config to `0`, stale entries remain visible and selectable; switching then requeues and immediately evicts the current session instead of treating history as disabled.
  - confidence: 0.88
- **[P2] Match ID prefixes before numeric indices:** `src/auto-reply/reply/commands-sessions.ts:219-222`
  - body: The command treats any all-digit argument as a rendered list index before trying exact or prefix session-id matching. Numeric session-id prefixes therefore cannot select the advertised matching session and either jump to a different index or report not found.
  - confidence: 0.76
