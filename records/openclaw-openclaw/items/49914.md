## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P1] Restore or clear the full session boundary:** `src/auto-reply/reply/commands-sessions.ts:280`
  - body: After changing `sessionId`, this only reapplies `SessionHistoryItem.metadata`, which omits current-main session fields such as auth profile, CLI/ACP runtime state, exec/elevated policy, abort/cutoff state, runtime model/fallback notice, and cost. The next turn can therefore run the restored transcript with the outgoing session's credentials, runtime handle, or tool policy instead of the selected session's own state.
  - confidence: 0.9
- **[P1] Protect retained history transcripts from cleanup:** `src/auto-reply/reply/session.ts:649`
  - body: This PR intentionally keeps old transcripts unarchived while they are present in `sessionHistory`, but the disk-budget reference graph on main only marks the active entry transcript and compaction checkpoints as referenced. With `session.maintenance.maxDiskBytes` or unreferenced-artifact cleanup enabled, a retained history transcript can be deleted while `/sessions` still advertises it as switchable, so switching back can land on an empty/missing transcript.
  - confidence: 0.86
- **[P2] Honor disabled history before resolving targets:** `src/auto-reply/reply/commands-sessions.ts:213`
  - body: The command builds list/switch targets from persisted `sessionHistory` before checking `session.historyLimit`, so changing the config to `0` does not immediately disable existing switchable entries. During that window `/sessions` can still show old sessions and `/sessions <n>` can switch to one, then evict/archive the current session because the limit is zero.
  - confidence: 0.82
