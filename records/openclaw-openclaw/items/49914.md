## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Restore the full session boundary on switch:** `src/auto-reply/reply/commands-sessions.ts:280`
  - body: `/sessions` rewrites the active `SessionEntry` to the target session, but `applyHistoryMetadata` restores only a small subset of fields. Current main stores auth profile, runtime/harness, exec/elevated policy, abort cutoff, CLI binding, ACP, fallback, cost, delivery, and plugin state on the same entry, so the next turn can run under the wrong credentials/backend/sandbox or inherit stale stop state. Restore every session-bound field deliberately or clear the fields that must not cross sessions, with focused regression coverage.
  - confidence: 0.91
- **[P1] Reference history transcripts during cleanup:** `src/auto-reply/reply/session.ts:691-692`
  - body: This PR intentionally keeps prior transcripts switchable while they remain in `sessionHistory`, but current disk-budget cleanup only marks each entry's active transcript and compaction checkpoints as referenced. A deployment using `session.maintenance.maxDiskBytes` can delete a retained history transcript while `/sessions` still lists it, so switching back can land in an empty or missing conversation. Add history items to the referenced artifact set or prune/archive the history entry with the file.
  - confidence: 0.89
- **[P2] Honor disabled history before listing or switching:** `src/auto-reply/reply/commands-sessions.ts:258`
  - body: The handler builds list and switch targets from persisted `sessionHistory` before it checks `session.historyLimit`. If an operator changes the new config to `0`, stale retained sessions remain visible and selectable until another rollover, and a switch can immediately evict/archive the current session. Gate both list and switch paths on `historyLimit === 0` and clear/archive existing history consistently.
  - confidence: 0.86
