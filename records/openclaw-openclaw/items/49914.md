- **[P1] Honor disabled history before resolving targets:** `src/auto-reply/reply/commands-sessions.ts:213-214`
  - body: `allItems` is built from persisted `sessionHistory` before `session.historyLimit` is checked.   - confidence: 0.93
- **[P1] Protect retained history transcripts from cleanup:** `src/auto-reply/reply/session.ts:649`
  - body: This assigns retained history to the new session entry, but current disk-budget cleanup only marks the active entry transcript and compaction checkpoints as referenced. A retained history transcript can therefore be swept as an unreferenced primary transcript while `/sessions` still advertises it as switchable.
  - confidence: 0.88
- **[P1] Restore the whole session boundary on switch:** `src/auto-reply/reply/commands-sessions.ts:280`
  - body: The switch mutates `sessionId` and then reapplies only the small `SessionHistoryItem.metadata` subset. Fields such as auth profile overrides, CLI/ACP bindings, exec/elevated policy, runtime model, abort/fallback state, and cost state remain from the outgoing session, so a resumed chat can continue with the wrong credentials, provider thread, or execution policy.
  - confidence: 0.9
