Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P2] Honor disabled history before listing or switching:** `src/auto-reply/reply/commands-sessions.ts:170`
  - body: `session.historyLimit=0` is documented here as disabling switchable history, but this path still builds `/sessions` output and switch targets from persisted `sessionHistory` before reading the limit. If an operator disables the feature after history exists, old sessions remain reachable and switching archives the current session through the zero-limit eviction path.
  - confidence: 0.9
- **[P1] Restore or clear the full session boundary on switch:** `src/auto-reply/reply/commands-sessions.ts:280`
  - body: Switching rewrites the active `SessionEntry` and then restores only the narrow history metadata subset. Fields such as abort cutoffs, fast/usage settings, auth profile overrides, exec/elevated policy, CLI/ACP runtime handles, runtime model, fallback state, cost, and system prompt reports can leak from the session being left into the session being resumed.
  - confidence: 0.88
- **[P1] Reference history transcripts during disk cleanup:** `src/auto-reply/reply/session.ts:648-649`
  - body: The PR keeps old transcripts live while their session ids remain in `sessionHistory`, but the current disk-budget sweep only protects active entries and compaction checkpoint files. With `session.maintenance.maxDiskBytes` enabled, retained history transcripts can be deleted while `/sessions` still advertises them as switchable.
  - confidence: 0.84
