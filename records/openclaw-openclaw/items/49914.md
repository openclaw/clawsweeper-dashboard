## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Restore or clear the full session boundary:** `src/auto-reply/reply/commands-sessions.ts:280`
  - body: After selecting a target, this rewrites the active `sessionEntry` and only reapplies the small history metadata subset. Fields such as auth profile overrides, runtime model/provider, CLI/ACP handles, exec/elevated policy, abort state, fallback notices, and cost state can remain from the outgoing session, so a resumed transcript can continue under the wrong credentials or execution policy. Store and restore a complete session-owned snapshot, or clear every non-restored field before persisting.
  - confidence: 0.9
- **[P1] Protect retained history transcripts from cleanup:** `src/auto-reply/reply/session.ts:649`
  - body: This keeps old transcripts unarchived while they remain in `sessionHistory`, but the existing disk-budget cleanup only counts each store entry's active `sessionId` as referenced. With `session.maintenance.maxDiskBytes`, a retained transcript can be deleted while `/sessions` still lists it, so switching back lands in an empty or missing conversation. Include history entries in cleanup references or archive/remove them consistently.
  - confidence: 0.86
- **[P2] Honor disabled history before selecting targets:** `src/auto-reply/reply/commands-sessions.ts:213-214`
  - body: The switch target list is built from persisted `sessionHistory` before checking `session.historyLimit`. If an operator changes the limit to `0` while history exists, `/sessions back` or `/sessions <n>` can still select a stale target and then immediately evict/archive the current session even though switchable history is disabled. Guard list/switch behavior when the limit is zero and clean up stale history through the reset path.
  - confidence: 0.82
