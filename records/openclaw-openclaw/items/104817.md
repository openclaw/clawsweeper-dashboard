## Summary

This PR should remain open for contributor follow-up, but the current patch is not merge-ready: supported Exa calls already receive a centrally prepared credential, while the new provider-local rule disagrees with that layer’s intentional ambient-key recovery and has no live proof of a production bypass.

## What This Changes

The PR switches Exa web-search API-key lookup to the shared SecretRef-aware provider resolver and adds tests for literal keys, ambient fallback, env SecretRefs, and unresolved refs.

## Best Possible Solution

Keep runtime secret preparation as the single credential authority; if a supported caller bypasses it, route that caller through preparation, or separately align the centralized fallback policy across affected providers with explicit compatibility approval and fresh-install, upgrade, diagnostic, and live proof.
