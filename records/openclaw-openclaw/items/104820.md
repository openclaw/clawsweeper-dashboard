This remains a useful, narrowly scoped fix, but it deliberately changes the upgrade contract for an explicitly configured SearXNG URL. The supplied prior review found no code defect and shows the intended endpoint-routing behavior; the remaining decision is whether configured-but-unavailable values should fail closed rather than use the ambient fallback, plus refreshed real-runtime evidence for current head `114a65aca58cc16cb45ba370f1bc89e67c08785f`.

## What This Changes

The PR makes configured SearXNG `baseUrl` values authoritative by failing before network access when they are blank, malformed, or unresolved, while retaining `SEARXNG_BASE_URL` fallback only when `baseUrl` is absent.
