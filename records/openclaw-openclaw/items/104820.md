## Summary

This PR remains necessary if OpenClaw intends an explicit-but-unavailable SearXNG `baseUrl` to block requests rather than silently use `SEARXNG_BASE_URL`. The prior P1 compatibility decision is still unresolved, and the latest head `c972ce9cf36ea53f07a0dc9f73c12998b16d6efa` is newer than the supplied exact-head runtime proof, so it should not merge until the contract owner approves the behavior and current-head proof is refreshed.

## What This Changes

The PR changes SearXNG endpoint resolution so invalid or unresolved explicitly configured base URLs fail before a request, while ambient `SEARXNG_BASE_URL` remains available only when configuration omits `baseUrl`.

## System Context

The bundled SearXNG plugin selects the endpoint used by OpenClaw’s web-search provider. Configuration and SecretRef resolution feed that selection, which either produces a normalized URL for the HTTP client or returns an actionable configuration error before network access.

## Best Possible Solution
