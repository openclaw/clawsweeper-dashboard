Overall confidence: 0.89

Full review comments:

- **[P1] Keep lifecycle keys as plugin ids:** `src/plugins/installs.ts:90`
  - body: The new compound map key is still consumed by existing lifecycle code as if it were the canonical plugin id: update selection returns `Object.keys(installs)`, uninstall selection returns the map key for spec matches, and update logic then acts on that value. Once a record is stored as `demo:coding`, those paths target `demo:coding` instead of `demo`, so update/uninstall/registry lifecycle behavior drifts from the actual plugin identity. Preserve plugin ids as lifecycle ids and model scope separately, or update every selector/caller before writing scoped keys.
  - confidence: 0.9
- **[P1] Expose scoped uninstall before writing scoped installs:** `src/cli/plugins-cli.ts:191`
  - body: This adds `plugins install --agent`, but the uninstall command still has no `--agent` option and `runPluginUninstallCommand` still calls `planPluginUninstall` without an agent id and with the global extensions dir. Users can create agent-scoped records that the CLI cannot directly remove, which is a lifecycle regression for the new persisted state.
  - confidence: 0.92
- **[P1] Preserve shared config during scoped uninstall:** `src/plugins/uninstall.ts:387`
  - body: Adding `opts.agentId` here only changes which install record is removed; the same function still deletes `plugins.entries[pluginId]`, allow/deny policy, and selected slots unconditionally. A scoped uninstall must not disable or deconfigure a global or another-agent install of the same plugin, so this needs an other-install check before shared plugin config is removed.
  - confidence: 0.9
- **[P2] Validate the agent id before persisting it:** `src/cli/plugins-install-command.ts:1043`
  - body: The install command resolves the workspace with `opts.agent` and then persists that raw string as `agentId`. `resolveAgentWorkspaceDir` normalizes internally and falls back for unknown ids, so `--agent ' Ops '` or a typo can write a record/key that does not match the normalized configured agent; explicit agent-scoped plugin installs should normalize once and reject ids not present in `listAgentIds` before choosing the install root or saving the record.
  - confidence: 0.86
