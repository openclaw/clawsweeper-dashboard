- **[P1] Keep scoped installs out of global discovery:** `src/cli/plugins-install-command.ts:1011-1012`
  - body: This resolves `--agent` to an agent workspace install root, but current discovery still iterates every install record and calls `discoverFromPath(... origin: "global")` without checking `agentId`. Installing a plugin for one agent would still place that plugin in the global registry, defeating the isolation and security goal.
  - confidence: 0.91
- **[P1] Preserve lifecycle lookups for scoped records:** `src/plugins/installs.ts:90`
  - body: Building install record keys as `pluginId:agentId` leaves existing lifecycle consumers behind: registry matching uses `installRecords[pluginId]`, and update selection passes record keys as expected plugin ids. A scoped record such as `demo:coding` will not match manifest id `demo`, so update/provenance/installed-record handling can fail or rewrite the wrong record.
  - confidence: 0.9
- **[P2] Expose scoped uninstall before writing scoped installs:** `src/cli/plugins-cli.ts:191`
  - body: The branch adds `plugins install --agent`, but `plugins uninstall` still has no `--agent` option and the command never passes an agent id into planning or record removal. Users can create scoped install records that the CLI cannot remove by scope.
  - confidence: 0.88
- **[P1] Preserve shared plugin config for other scopes:** `src/plugins/uninstall.ts:393-399`
  - body: Even when an `agentId` is passed, `removePluginFromConfig` still removes `plugins.entries`, allow/deny policy, and slots by bare plugin id. A scoped uninstall would disable or disturb the shared/global plugin configuration while other agent or global installs for the same plugin remain.
  - confidence: 0.86
