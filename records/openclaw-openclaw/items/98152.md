## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Preserve lifecycle lookups for scoped install records:** `src/plugins/installs.ts:90`
  - body: This still stores scoped installs under keys like `pluginId:agentId`, while current index/update flows look up install records by manifest plugin id. Scoped installs can lose metadata or be updated as if the compound key were the plugin id, so every lifecycle consumer needs the same scoped identity before writing these records.
  - confidence: 0.91
- **[P2] Expose scoped uninstall before writing scoped installs:** `src/cli/plugins-cli.ts:191`
  - body: The PR adds `plugins install --agent`, but there is still no matching `plugins uninstall --agent` command. Users who create scoped records will not have a supported way to remove that scoped install or its agent workspace files.
  - confidence: 0.9
- **[P1] Do not remove shared plugin state during scoped uninstall:** `src/plugins/uninstall.ts:393`
  - body: Even when `agentId` is supplied to the helper, this function still removes `plugins.entries`, allow/deny lists, slots, load paths, and channel config by plain plugin id. A scoped uninstall would therefore deconfigure global or sibling-agent installs instead of removing only the selected agent's record/files.
  - confidence: 0.88
- **[P2] Validate the requested agent before choosing an install root:** `src/cli/plugins-install-command.ts:1008-1009`
  - body: `resolveAgentWorkspaceDir` synthesizes fallback workspace paths for unknown non-default ids, so this install path does not fail closed for a typo or unconfigured agent. Normalize and validate the agent id against configured agents before installing plugin code and persisting the scoped record.
  - confidence: 0.86
