## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Keep scoped records out of global discovery:** `src/plugins/installs.ts:57`
  - body: This key change writes scoped installs as `pluginId:agentId`, but current discovery still scans every install record path and the registry still looks up metadata with the bare plugin id. A plugin installed with `--agent coding` can therefore still become a global candidate while losing lifecycle metadata/trusted precedence, so the advertised isolation is not true.
  - confidence: 0.9
- **[P2] Add scoped uninstall before writing scoped installs:** `src/cli/plugins-cli.ts:191`
  - body: The PR exposes `plugins install --agent`, but the public `plugins uninstall` command still has no `--agent` option and the uninstall command still plans against the global extensions root without passing an agent id. Users can create scoped records that the CLI cannot cleanly target, which leaves cleanup and wrong-record removal behavior unresolved.
  - confidence: 0.91
- **[P1] Preserve shared config during scoped uninstall:** `src/plugins/uninstall.ts:387`
  - body: Adding `agentId` to `removePluginFromConfig` does not stop this function from removing shared `plugins.entries`, allow/deny lists, slots, and channel config by bare plugin id. Once a scoped uninstall path calls this helper, uninstalling one agent's record can still tear down configuration needed by another agent or the global install.
  - confidence: 0.88
- **[P2] Reject unknown agents before choosing an install root:** `src/cli/plugins-install-command.ts:1011`
  - body: `resolveAgentWorkspaceDir` synthesizes a fallback workspace for any id, so a typo like `--agent codign` will install executable plugin code under a new fallback path instead of failing closed as the PR claims. Validate the id against configured agents before resolving the install root.
  - confidence: 0.86
