Full review comments:

- **[P1] Preserve lifecycle lookups for scoped install records:** `src/plugins/installs.ts:90`
  - body: This still stores agent-scoped installs under keys like `pluginId:agentId`, but current installed-index and update code still use install-map keys as plugin ids. Scoped records can lose install metadata or be updated as a synthetic plugin id unless every lifecycle consumer is updated before writing compound keys.
  - confidence: 0.91
- **[P2] Expose scoped uninstall before writing scoped installs:** `src/cli/plugins-cli.ts:191`
  - body: The PR adds `plugins install --agent`, but `plugins uninstall` still has no matching `--agent` option and the uninstall command still plans against the global extension root. Users can create scoped records without a supported way to remove that scoped install and its files.
  - confidence: 0.9
- **[P1] Do not remove shared plugin state during scoped uninstall:** `src/plugins/uninstall.ts:393`
  - body: Even when `agentId` is supplied, this helper still removes `plugins.entries`, allow/deny policy, slots, and channel config by plain `pluginId`. A scoped uninstall would deconfigure global or sibling-agent installs of the same plugin instead of removing only the selected agent's record/files.
  - confidence: 0.88
- **[P2] Validate the requested agent before choosing an install root:** `src/cli/plugins-install-command.ts:1011`
  - body: `resolveAgentWorkspaceDir` falls back to synthesized workspace paths for unknown non-default ids, so `--agent typo` can install plugin code into an unintended workspace and persist that id. Validate the normalized id against configured agents, or require explicit agent creation, before staging plugin code.
  - confidence: 0.86
