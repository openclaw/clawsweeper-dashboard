## Summary

Keep open: this PR is a useful attempt at the per-agent plugin install feature, but it is not merge-ready because the new compound install keys break existing plugin-id lifecycle consumers, scoped installs cannot be removed through the CLI, scoped uninstall still removes shared plugin config, and the agent id is not validated before selecting an install root.

## What This Changes

Adds an optional `--agent` flag to plugin installation, records `agentId` on plugin install records, and changes install/uninstall persistence helpers to use agent-scoped compound install keys.

## Best Possible Solution

Define and implement one per-agent plugin lifecycle contract covering install record identity, discovery/provenance/update/uninstall, agent validation, security policy, docs, and focused upgrade tests before merging.

Full review comments:

- **[P1] Preserve lifecycle lookups for scoped install records:** `src/plugins/installs.ts:57`
  - body: This still stores scoped installs under `pluginId:agentId`, but current registry/provenance/version-drift consumers attach install metadata by the manifest plugin id. A scoped install of `demo` would be persisted under `demo:coding`, while `buildInstalledPluginIndexRecords` looks up `installRecords[record.id]` for `demo` and provenance checks use `installRules.get(params.pluginId)`, so installed metadata and explicit-install provenance are lost for the scoped record.
  - confidence: 0.9
- **[P2] Expose scoped uninstall before writing scoped installs:** `src/cli/plugins-cli.ts:191`
  - body: The branch adds `--agent` to `plugins install`, but `plugins uninstall` still has no `--agent` option and `runPluginUninstallCommand` receives no agent id. That lets users create `pluginId:agentId` records they cannot target through the public CLI, leaving scoped installs stuck or forcing unsafe manual state edits.
  - confidence: 0.92
- **[P1] Do not remove shared plugin state during scoped uninstall:** `src/plugins/uninstall.ts:393-399`
  - body: Even when `agentId` is provided, `removePluginFromConfig` still removes the shared `plugins.entries`, allowlist, denylist, slot, and channel config for the plugin id. A future scoped uninstall would therefore remove global/other-agent activation state while only deleting one scoped install record.
  - confidence: 0.91
- **[P2] Validate the requested agent before choosing an install root:** `src/cli/plugins-install-command.ts:1011`
  - body: `resolveAgentWorkspaceDir` is a permissive resolver: for an unknown non-default id it fabricates a fallback workspace under the state directory. Using it directly here means `openclaw plugins install --agent codign ...` can install plugin code under a typo-created workspace and record that typo as the owning agent instead of failing closed.
  - confidence: 0.88
