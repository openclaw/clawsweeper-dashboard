## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Keep install record keys compatible with plugin-id lookups:** `src/plugins/installs.ts:57`
  - body: This writes scoped records under keys like `pluginId:agentId`, but registry/index/update/inspect consumers still look install metadata up by the manifest plugin id. A scoped install can be discovered from its path while losing trusted install metadata and update/drift associations, so keep the canonical map key or update every lifecycle consumer before writing scoped records.
  - confidence: 0.92
- **[P2] Expose scoped uninstall before writing scoped installs:** `src/cli/plugins-cli.ts:191`
  - body: The new install flag can create agent-scoped records, but `plugins uninstall` still has no `--agent` option and `runPluginUninstallCommand` always plans against the global root. Users who install a plugin for one agent have no matching CLI path to remove that same scoped install without touching or missing global state.
  - confidence: 0.95
- **[P1] Preserve shared config during scoped uninstall:** `src/plugins/uninstall.ts:393-399`
  - body: Even when `opts.agentId` is provided, this branch still removes `plugins.entries` for the whole plugin id, and the later allow/deny/slot cleanup is also global. A scoped uninstall would disable or clear shared/global plugin config for other installs, so those removals need to be gated on whether any other scoped or global install still owns the plugin.
  - confidence: 0.91
- **[P2] Validate and canonicalize the agent scope once:** `src/cli/plugins-install-command.ts:1011-1012`
  - body: `resolveAgentWorkspaceDir` normalizes the id for the path and can synthesize a workspace for an unknown or malformed id, while the install records store raw `opts.agent`. Case variants or typos can target one workspace but create mismatched record keys, so validate the requested agent and pass one canonical id through every install branch.
  - confidence: 0.86
