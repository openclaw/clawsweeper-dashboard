Full review comments:

- **[P1] Preserve lifecycle lookups for scoped install records:** `src/plugins/installs.ts:90`
  - body: This writes scoped installs under keys like `pluginId:agentId`, but current index, inspect, update, and doctor consumers still look up install records by the manifest plugin id. Scoped records can therefore lose metadata or be treated as synthetic plugin ids; either keep record identity compatible or update every lifecycle consumer before writing compound keys.
  - confidence: 0.91
- **[P2] Expose scoped uninstall before writing scoped installs:** `src/cli/plugins-cli.ts:191`
  - body: The PR adds `plugins install --agent`, but `plugins uninstall` still has no `--agent` option or runtime wiring. Users who create scoped records have no supported way to remove that scoped install or its agent workspace files.
  - confidence: 0.9
- **[P1] Do not remove shared plugin state during scoped uninstall:** `src/plugins/uninstall.ts:393`
  - body: Even when `agentId` is supplied, this path still removes `plugins.entries`, allow/deny lists, slots, and channel config by plain plugin id. A scoped uninstall would deconfigure global or sibling-agent installs instead of only removing the selected agent's record/files.
  - confidence: 0.88
- **[P2] Validate the requested agent before choosing an install root:** `src/cli/plugins-install-command.ts:1011-1012`
  - body: `resolveAgentWorkspaceDir` synthesizes a fallback workspace for unknown non-default ids, so this direct call does not fail closed for a typo or unconfigured agent. Normalize and validate the agent id against configured agents before installing plugin code and persisting the scoped record.
  - confidence: 0.86
