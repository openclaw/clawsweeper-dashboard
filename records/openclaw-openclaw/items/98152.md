Full review comments:

- **[P1] Preserve lifecycle lookups for scoped install records:** `src/plugins/installs.ts:90`
  - body: This stores agent-scoped installs under keys like `pluginId:agentId`, but current index and update code still look up records by manifest plugin id. Scoped installs can lose install metadata or be treated as different plugin ids during update/repair flows, so every lifecycle consumer must agree on scoped identity before writing these keys.
  - confidence: 0.91
- **[P2] Expose scoped uninstall before writing scoped installs:** `src/cli/plugins-cli.ts:191`
  - body: The PR adds `plugins install --agent`, but `plugins uninstall` still has no matching `--agent` option or runtime wiring. Users who create scoped records do not have a supported way to remove that scoped install or its agent workspace files.
  - confidence: 0.9
- **[P1] Do not remove shared plugin state during scoped uninstall:** `src/plugins/uninstall.ts:393`
  - body: Even when `agentId` is supplied, this function still removes `plugins.entries`, allow/deny policy, slots, and some channel config by plain plugin id. A scoped uninstall would disable or deconfigure global and sibling-agent installs instead of removing only the selected agent's record/files.
  - confidence: 0.88
- **[P2] Validate the requested agent before choosing an install root:** `src/cli/plugins-install-command.ts:1011`
  - body: `resolveAgentWorkspaceDir` synthesizes fallback workspace paths for unknown non-default ids, so this line does not fail closed for a typo or unconfigured agent. Validate and normalize the agent id against configured agents before installing plugin code and persisting the scoped record.
  - confidence: 0.86
