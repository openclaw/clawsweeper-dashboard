## Review Findings

Overall confidence: 0.9

Full review comments:

- **[P1] Keep scoped install keys out of update plugin ids:** `src/plugins/installs.ts:57`
  - body: This stores scoped installs under keys like `demo:coding`, but `updateNpmInstalledPlugins` uses `Object.keys(plugins.installs)` as plugin ids and passes those values to the installer as `expectedPluginId`. A scoped record will be updated as `demo:coding` instead of manifest id `demo`, causing update failures or migration back to the global key.
  - confidence: 0.91
- **[P1] Preserve shared config on scoped uninstall:** `src/plugins/uninstall.ts:395`
  - body: When `agentId` is supplied, this function still removes `plugins.entries[pluginId]`, allow/deny policy, and slots by the plain plugin id. A scoped uninstall would disable or reset the global and other-agent install state even though only one `pluginId:agentId` record was targeted.
  - confidence: 0.9
- **[P2] Expose the matching scoped uninstall path:** `src/cli/plugins-cli.ts:191`
  - body: The new install option can create agent-scoped records, but `plugins uninstall` still has no `--agent` option and `runPluginUninstallCommand` never receives an agent id. Users can create scoped installs that the documented CLI cannot remove without falling back to internal state surgery.
  - confidence: 0.88
- **[P2] Validate the agent before resolving the install root:** `src/cli/plugins-install-command.ts:1011`
  - body: `resolveAgentWorkspaceDir` falls back to a synthetic workspace for unknown ids, so `plugins install --agent typo` will install executable plugin code into a new workspace path instead of failing closed for a configured agent. The PR should validate the requested agent id before selecting the install root.
  - confidence: 0.86
