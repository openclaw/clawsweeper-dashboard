## Label Justifications

- `P0`: Affected users can lose in-product access to prior session history after an update/reset, and recovery currently requires technical filesystem or support steps before archive retention can prune data.
- `impact:ux-release-blocker`: There is no in-product recovery path for a community user whose prior sessions disappear from supported history surfaces after reset/archive rotation.
- `impact:data-loss`: The data may still exist in `.reset.*` files, but it is hidden from supported product surfaces and can later be pruned by retention cleanup.
- `impact:security`: Any archive recovery path changes access to sensitive prior transcript content and needs an explicit visibility boundary.

## Summary

Keep open. Current main and v2026.6.11 include a latest reset-archive fallback when the active transcript is missing, but they still do not provide the requested restore/re-index command or a full reset-family/archive history selector; the remaining direction is a product and security-boundary decision.

## What This Changes

Request to restore `.jsonl.reset.<timestamp>` session archives back into usable session history, initially via a restore/re-index script and later as broader archived-history recovery tooling.

## Best Possible Solution

Land one maintainer-approved opt-in read-only family/archive history API with bounded reads and source metadata; add a doctor-owned restore/re-index command only if maintainers explicitly accept archive mutation semantics.

- **Add Doctor Restore/Re-Index:** Provide a deliberate `openclaw doctor --fix` style recovery command for affected users that preserves archive provenance and warns about retention and privacy effects.
- **Reject Archive Mutation:** Keep `.reset.*` archives immutable and route remaining recovery work to read-only history, export, and reset-policy improvements.

## Reproduction Assessment

Yes, at source level. Current main has no restore/re-index command and no `includeArchived`/`includeFamily` selector, while the existing fallback only reads a latest reset archive when the active transcript is missing.

## Solution Assessment

Unclear as originally proposed. A standalone rename script helps affected users, but the maintainable core path should be a bounded read-only family/archive API first, with any mutation restore owned by an explicit doctor recovery workflow.
