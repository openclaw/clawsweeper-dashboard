## Summary

Keep open. Current main and v2026.6.11 still lack the requested restore/re-index recovery path, and the active read-path work is still in open pull requests such as https://github.com/openclaw/openclaw/pull/90239 rather than merged on main.

## What This Changes

This issue requests a recovery utility that restores `.jsonl.reset.*` session transcript archives, rebuilds session indexing, and addresses the broader reset-archive discoverability gap.

## Best Possible Solution

Land a maintainer-approved, bounded, read-only reset-family history path first, then add a doctor-owned restore/re-index command only if maintainers accept the mutation and recovery semantics.

Options:

- **Land read-only family history first (recommended):** Use the bounded `includeFamily` style path as the supported retrieval mechanism before adding any archive-mutating command.
- **Add doctor-owned restore/re-index:** Create a deliberate recovery command for already affected users that preserves source metadata and explains retention and security consequences.
- **Reject mutation-style restore:** Keep archives read-only and track only discovery/export surfaces for reset archives.

## Reproduction Assessment

Yes, at source level: current main exposes no restore/re-index command and no archive-family selector, while reset fallback only reads one latest archive when the active transcript is absent. I did not run a live multi-day reset scenario in this read-only review.

## Solution Assessment

Unclear as originally proposed: a standalone rename script helps affected users, but the safer core solution is read-only family history or doctor-owned recovery with lineage, retention, and security semantics.
