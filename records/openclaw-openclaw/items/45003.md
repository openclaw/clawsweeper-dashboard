## Summary

Keep open. Current main and v2026.6.11 still do not provide the requested restore/re-index utility, and current code only has a latest-reset-archive fallback when the active transcript is missing; the concrete read-path work is still in open PRs such as #90239.

## What This Changes

Add a recovery utility or supported path to restore/re-index `.jsonl.reset.*` session archives so older history becomes accessible again after reset.

## Best Possible Solution

Land a maintainer-approved, bounded, header-checked read-only family-history path, then decide whether a separate doctor-style restore/re-index command is still needed for already affected users.
