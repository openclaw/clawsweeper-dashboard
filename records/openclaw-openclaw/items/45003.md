## Summary

Keep open. Current main and v2026.6.11 only provide latest-reset-archive fallback when the active transcript is missing; the broader restore/re-index and family-history recovery direction remains unmerged and needs maintainer product/security direction.

## What This Changes

The issue requests a utility to restore `.jsonl.reset.<timestamp>` session transcript archives back into usable session history and rebuild session indexing.

## Best Possible Solution

Land or explicitly reject a bounded, header-checked read-only family-history path first; if maintainers still want mutation recovery, implement it as a doctor-owned restore/re-index command that preserves lineage metadata and warns about retention/security consequences.
