## Summary

Keep open. Current main and v2026.6.11 still do not provide the requested restore/re-index utility or a merged archive-family history selector; main only has partial mitigations for missing-active transcripts and session-memory/archive search, while the most relevant retrieval fix remains the open maintainer-review PR at https://github.com/openclaw/openclaw/pull/90239.

## What This Changes

The issue requests a recovery path for session transcripts archived as `.reset.<timestamp>` files so users can restore or access hidden session history after reset/archive rotation.

## Best Possible Solution

Land one maintainer-approved, bounded, permission-checked readback path for reset/archive family history first, then add a separate explicit Doctor or restore command only if maintainers decide archived transcripts should be mutated back into active session state.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 expose no restore/re-index utility and no archive-family selector for `chat.history` or `sessions_history`; the reset fallback only helps when the active transcript is missing.

## Solution Assessment

Unclear until maintainers choose the recovery contract. A read-only, opt-in, header-checked family-history path is the safest first step; a restore/re-index script is a stronger state mutation that should be separate and explicitly approved.
