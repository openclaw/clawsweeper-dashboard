## Summary

Keep open. Current main and latest release still lack the requested restore/re-index utility, and the remaining archive-family history work is only covered by open maintainer-review items such as https://github.com/openclaw/openclaw/issues/92062 and https://github.com/openclaw/openclaw/pull/90239.

## What This Changes

Request a recovery utility that restores `.jsonl.reset.*` session transcripts into active session history and rebuilds session indexing after daily reset archival.

## Best Possible Solution

Land a maintainer-approved, bounded, header-checked read-only family-history path, then decide whether a separate doctor-style restore/re-index command is still needed for already affected users.

## Reproduction Assessment

Yes, source-level: current main exposes no restore/re-index command and no chat.history/sessions_history archive-family selector; active-missing fallback only reads a single latest reset archive when the active file is absent. I did not run a live multi-day reset scenario in this read-only review.

## Solution Assessment

Unclear as originally proposed. A script can help already affected users, but the safer maintainable path is a maintainer-approved read-only family-history API or doctor recovery command with source metadata, retention, and security semantics.
