## Label Justifications

- `P0`: Affected users can see session history disappear after reset/upgrade and currently need technical recovery before reset archives are pruned.
- `impact:data-loss`: Reset archives are retained for a configured window, so lack of recovery can become permanent transcript loss after cleanup.
- `impact:session-state`: The issue concerns session history, context continuity, and agent recall being split across active and reset transcript files.
- `impact:ux-release-blocker`: A community user whose history disappears has no in-product recovery path and must inspect files or run a script.

## Summary

Keep open. Current main and v2026.6.11 still lack a complete restore/re-index path or maintainer-approved archive/family history selector; the only implemented behavior is a narrow read fallback when the active transcript file is missing.

## What This Changes

The issue requests a utility or product recovery path to restore and re-index session transcripts archived as `.reset.<timestamp>` after daily/session reset behavior made them disappear from normal history surfaces.

## Best Possible Solution

Approve one bounded in-product recovery contract: either a Doctor/restore flow that backs up and safely re-indexes archives, or an opt-in read-only family-history API with ownership/header checks, source metadata, retention warnings, and UI/tool discoverability.
