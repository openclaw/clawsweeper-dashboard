## Summary

Keep open. Current main and v2026.6.11 have a latest-reset-archive fallback when the active transcript is missing, but they still do not provide the requested restore/re-index flow or a merged reset-family history selector; the current read-only candidate is still open.

## What This Changes

The issue requests a restore/re-index utility or product recovery path for session transcript files archived as `.jsonl.reset.<timestamp>` after daily/manual resets.

## Best Possible Solution

Land a maintainer-approved, bounded read-only reset-family history path first, then add a Doctor-owned restore/re-index command only if maintainers accept the archive mutation and recovery semantics.
