## Label Justifications

- `P0`: The issue describes non-technical users losing sidebar/agent access to prior session history after upgrade/reset with recovery requiring filesystem scripts or manual transcript/index edits.
- `impact:data-loss`: Archived transcript data can become effectively inaccessible and later pruned, creating perceived and possible permanent loss of session history.
- `impact:session-state`: The affected behavior splits logical conversations across reset archives and hides prior context from session history and agent recall.
- `impact:ux-release-blocker`: Users who hit the upgrade/reset path cannot recover normal history visibility from the product without technical recovery steps.

## Summary

Keep open. Current main still lacks a first-class restore/re-index recovery path for `.jsonl.reset.*` session archives, and the active read-only family-history fixes are still open PRs rather than merged behavior.

## What This Changes

Request for a recovery utility that restores `.jsonl.reset.*` session transcript archives into indexed session history after daily or manual reset archiving hides prior history from normal views.

## Best Possible Solution

Land a maintainer-approved recovery design: preferably a bounded, header-checked read path for archive/family history plus a doctor or explicit recovery command for already-affected users when mutation is required.

## Maintainer Decision

Rationale: The central user pain is real, but the permanent shape affects session-state semantics, archive retention, privacy boundaries, and whether recovery belongs in `openclaw doctor --fix`, a user command, or a read-only history surface.

Options:

- **Adopt Bounded Read Path First (recommended):** Use the open `includeFamily` direction as the canonical retrieval path and add a narrow doctor/restore follow-up only for already-archived users who need mutation.
- **Add Explicit Restore Command:** Build a guarded CLI/doctor recovery command that backs up state, restores selected archives, and rebuilds the session index with tests and migration guidance.
- **Keep As External Script:** Leave archive mutation outside core and document manual recovery, accepting that non-technical users remain blocked without first-class recovery UX.

## Reproduction Assessment

Yes, at source level: current main still archives reset transcripts and only falls back to `.reset.*` files when the active transcript is missing, while `chat.history` and `sessions_history` have no restore, re-index, or family-history selector on main. I did not run a destructive restore scenario in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product shape. A community script is a useful stopgap, but the safer core solution is a bounded read path plus a guarded doctor/restore command if mutation is accepted.
