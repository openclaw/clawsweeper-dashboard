## Summary

Keep open. Current main and v2026.6.11 still only provide latest reset-archive fallback when the active transcript is missing; the broader restore/re-index and full reset-family recovery direction remains open behind product and security-boundary review.

## What This Changes

Request a supported restore or re-index recovery path for session transcripts archived as `.jsonl.reset.*` by daily or manual session resets.

## Best Possible Solution

Land or explicitly reject a bounded opt-in family-history API first; if mutation recovery is still desired, implement it as a doctor-owned restore/re-index command with lineage preservation and retention/security warnings.
