## Label Justifications

- `impact:message-loss`: The reported path suppresses a user-visible reply or fallback after a yielded terminal turn.

- `maturity:stable`: The affected gateway/session runtime maps to the M4 Stable `gateway-runtime` maturity feature.

## Summary

Keep open: current `main` still treats `yieldDetected` as terminal state by itself and suppresses the incomplete-turn fallback for yielded attempts, so the reported direct-session silent parking path remains source-reproducible. Related open yield issues cover adjacent wake and delivery failures, but none clearly owns this exact no-fresh-continuation-source invariant.

## What This Changes

The issue requests a runtime guard or visible fallback when `sessions_yield` is accepted before an interactive direct turn has any viable continuation source.

## Best Possible Solution

Define and enforce one continuation invariant for interactive direct yields: a yielded turn must either have a known runtime wake source or produce a visible unsafe/fallback result instead of silently parking.

## Reproduction Assessment

Yes at source level: current `main` still allows `yieldDetected` to count as terminal state by itself and skips the incomplete-turn fallback when it is true. I did not run the full Telegram incident live.

## Solution Assessment

Unclear on the exact implementation semantics: a runtime guard or visible fallback is the right layer, but maintainers need to define what counts as an existing continuation source so valid waits are preserved.
