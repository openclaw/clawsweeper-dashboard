## Summary

Keep open: current main still treats `yieldDetected` as terminal progress by itself, so an interactive direct turn can end as paused/end_turn with no assistant text and no same-turn accepted wake source.

## What This Changes

The issue reports that `sessions_yield` can silently park an interactive direct session when it is called before creating a fresh continuation or visible fallback source.

## Best Possible Solution

Define a yield-safety invariant for interactive direct turns: accept `sessions_yield` silently only when the turn has durable continuation evidence, otherwise emit a visible failure/fallback and diagnostic while preserving supported yielded subagent and async workflows.

## Reproduction Assessment

Yes at source level: `sessions_yield` sets `yieldDetected`, persists hidden context with `triggerTurn: false`, and the runner treats the turn as paused/end_turn while fallback guards skip visible recovery. I did not run the live Telegram reproduction in this read-only pass.

## Solution Assessment

Unclear until maintainers choose the contract: the narrow fix is a runner/finalization guard that requires continuation evidence or emits a visible fallback, but rejecting every bare yield could break intentional follow-up-event workflows.
