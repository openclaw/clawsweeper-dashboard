## Summary

Keep open: current main and the latest release still allow a yielded interactive turn to become a clean paused/end_turn terminal state without proving a fresh continuation source, and no related issue or PR clearly owns this exact invariant.

## What This Changes

The issue requests a runtime guard or visible fallback when `sessions_yield` is called before a direct interactive session has created a viable wake or continuation source.

## Best Possible Solution

Define and enforce a continuation-source invariant for interactive direct yields, with a visible fallback for dead-end yields and tests covering valid re-yields on already-active child work.

## Reproduction Assessment

Yes, at source level: current main accepts a yielded attempt as terminal without requiring independent wake-source evidence, and the latest release has the same shape. I did not run the full live Telegram incident.

## Solution Assessment

Unclear pending maintainer semantics. A runtime guard or visible fallback is the narrow maintainable direction, but maintainers need to define the valid wake-source contract before automation enforces it.
