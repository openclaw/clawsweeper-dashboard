## Label Justifications

- `P1`: Interactive direct users can see an accepted turn go silent until they manually nudge the session, which is a broken agent/channel workflow.
- `impact:session-state`: The reported path leaves the direct session parked from the user's perspective after a yielded terminal turn.
- `impact:message-loss`: The user-visible reply or fallback is absent even though the yielded turn completed successfully.
- `maturity:stable`: The affected interactive gateway/session delivery path maps to the M4 Stable `gateway-runtime` scorecard surface.

## Summary

Keep open: current `main` still lets `sessions_yield` become terminal output on its own, and the empty-turn fallback path still exits early when `yieldDetected` is true. The report is source-reproducible, but the exact guard semantics need maintainer agreement because valid re-yield turns may already be waiting on active child work.

## What This Changes

The issue requests a runtime guard or visible fallback so `sessions_yield` cannot silently park an interactive direct session before a fresh continuation or wake source exists.

## Best Possible Solution

Define one continuation invariant for interactive direct yielded turns: a yield is safe only when a known continuation source exists, otherwise the runtime should emit a visible fallback or diagnostic error instead of silently parking.

## Reproduction Assessment

Yes at source level: an attempt with `yieldDetected: true`, no assistant text, no accepted spawn, no cron add, and no message-tool delivery is treated as terminal and skips the incomplete-turn fallback. I did not run the full Telegram incident live.

## Solution Assessment

Unclear until maintainers choose the exact yield-continuation semantics. The maintainable layer is the runner/session continuation invariant, not docs-only or prompt-only guidance, but the guard must preserve valid waits on already-active child work.
