## Label Justifications

- `P1`: An accepted interactive direct turn can go silent until a human manually nudges the session, breaking a real channel workflow.
- `impact:session-state`: The reported path leaves the session parked from the user's perspective after a yielded terminal turn.
- `impact:message-loss`: The direct user receives no visible reply or fallback after the yielded turn completes.
- `maturity:stable`: The affected gateway/session runtime maps to the M4 Stable `gateway-runtime` surface in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main still lets `sessions_yield` end an interactive turn without checking for a fresh continuation source, and the terminal-output logic treats `yieldDetected` itself as enough to avoid visible fallback. Related open yield and delivery issues overlap, but none clearly owns this exact no-fresh-wake-source guard.

## What This Changes

The issue asks OpenClaw to reject or visibly recover interactive direct-session `sessions_yield` calls that have no known continuation source.

## Best Possible Solution

Define a runtime yield-continuation invariant for interactive direct turns, then emit a visible fallback or reject the yield when no accepted spawn, active child wait, committed delivery, cron continuation, or equivalent wake source exists.

## Reproduction Assessment

Yes at source level: current main accepts `sessions_yield`, sets `yieldDetected`, and suppresses incomplete-turn fallback even when no accepted spawn or delivery evidence is present. I did not run a live Telegram reproduction.

## Solution Assessment

Unclear until maintainers define valid wake-source semantics. The narrow maintainable direction is a runtime guard or visible fallback, not prompt-only guidance, but it must preserve valid waits on already-active child work.
