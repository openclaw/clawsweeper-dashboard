- `maturity:stable`: The affected interactive gateway/session delivery fallback surface maps to M4 Stable `gateway-runtime` in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main still lets `sessions_yield` by itself mark an interactive turn as terminal/paused, so the reported no-fresh-wake-source shape remains source-reproducible and is not owned by a merged or open exact fix.

## What This Changes

The issue asks OpenClaw to reject, visibly fail, or create a deterministic continuation when an interactive direct turn calls `sessions_yield` without establishing any viable wake source.

## Best Possible Solution

Define the runtime yield-continuation invariant for interactive direct turns, then enforce a visible fallback or rejection when no continuation source exists while preserving valid waits on active child work.

## Reproduction Assessment

Yes at source level: `sessions_yield` sets `yieldDetected`, and current terminal-state logic treats that flag as sufficient terminal output even when no accepted spawn, message-tool delivery, or cron continuation was recorded. I did not run the full Telegram incident live.

## Solution Assessment

Unclear until maintainers choose the exact semantics for existing wake sources. The narrow maintainable direction is a runtime guard or visible fallback, not prompt-only guidance, but it must avoid rejecting valid waits on already-active child work.
