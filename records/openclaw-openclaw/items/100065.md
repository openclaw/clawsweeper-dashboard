## Summary

Keep open: current main still lets `sessions_yield` alone count as terminal progress, so an interactive direct turn can end as paused/end_turn with no payload and no verified fresh continuation source. Related open issues cover adjacent wake, cron, announce, or empty-output failures, but none clearly owns this exact no-fresh-wake-source guard.

## What This Changes

Guard `sessions_yield` so interactive direct sessions cannot silently complete and park without a valid continuation source or visible fallback.

## Best Possible Solution

Define a runtime continuation invariant for interactive direct turns: a yielded turn should have a known current or newly accepted continuation source, otherwise it should fail visibly and record diagnostics instead of counting as silent success.

## Reproduction Assessment

Yes at source level: `sessions_yield` sets `yieldDetected`, and current terminal/fallback logic treats that flag as sufficient progress even when no accepted spawn, message-tool delivery, cron add, or async wake source was recorded. I did not run the full Telegram incident live.

## Solution Assessment

Unclear until maintainers define what counts as a valid existing wake source. The maintainable direction is a runtime guard or visible fallback rather than prompt-only guidance, but it must avoid rejecting valid waits on already-active child work.
