## Summary

Keep open: current main still treats `yieldDetected` as a successful terminal/yielded state by itself, and no merged or open canonical item clearly owns this exact no-fresh-continuation-source guard.

## What This Changes

The issue asks OpenClaw to prevent an interactive direct `sessions_yield` turn from silently parking when no accepted spawn, delivery, cron wake, or other continuation source exists.

## Best Possible Solution

Define and enforce an interactive direct-turn yield invariant: accept `sessions_yield` only when a known continuation source exists, or emit a visible fallback/error instead of silently parking the lane.

## Reproduction Assessment

Yes at source level: `sessions_yield` sets `yieldDetected`, and current terminal-state logic treats that flag as successful terminal progress even without accepted spawns, message-tool delivery, cron adds, or visible payloads. I did not run the full Telegram incident live.

## Solution Assessment

Unclear until maintainers choose the exact wake-source semantics. The maintainable direction is a runtime guard or visible fallback, but it must preserve legitimate waits on already-active child work.
