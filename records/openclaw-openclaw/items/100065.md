## Summary

Keep open: current main and the latest release still allow `sessions_yield` to terminate an interactive turn without proving a fresh wake source, and the incomplete-turn fallback is explicitly skipped once `yieldDetected` is set. The related open issues cover adjacent empty-output, lost-delivery, cron, and child-announce wake failures, but none clearly owns this exact no-fresh-continuation-source guard.

## What This Changes

The issue requests a runtime guard or visible fallback when `sessions_yield` is called in an interactive direct session before a viable continuation source exists.

## Best Possible Solution

Define and enforce a yield-continuation invariant for interactive direct turns: a yielded turn should have a known continuation source or emit a visible recovery message instead of silently parking.

## Reproduction Assessment

Yes, at source level. `sessions_yield` sets `yieldDetected`, and current terminal/fallback logic treats that flag as sufficient terminal output even when no accepted spawn, message-tool delivery, cron add, or other continuation source was recorded.

## Solution Assessment

Unclear until maintainers choose the exact wake-source semantics. The maintainable direction is a runtime guard or visible fallback, not prompt-only guidance, but it must avoid rejecting valid waits on already-active child work.
