## Summary

Keep open. Current main and the latest release have bounded recall/read and bounded dreaming-promotion behavior, but they still do not provide the requested hard-limited memory add/replace/remove/list write contract with capacity feedback, duplicate/consolidation semantics, snapshot behavior, and secret-safety policy.

## What This Changes

The issue requests a first-class bounded memory write tool with hard per-store character limits, add/replace/remove operations, usage feedback, duplicate handling, session-start snapshot semantics, and optional credential-pattern blocking.

## Best Possible Solution

Define a memory-core-owned bounded CRUD contract, including write authority, capacity feedback, hard-limit behavior, replacement identity, duplicate/consolidation policy, secret handling, docs, and focused tests before implementation.
