## Summary

Keep open. Current main and the latest release still expose memory recall, bounded reads, bounded bootstrap injection, promotion compaction, and a narrow append-only memory-flush path, but they do not implement the requested hard-limited add/replace/remove/list memory write contract with usage feedback, duplicate handling, snapshot semantics, and secret-safety policy.

## What This Changes

Request a built-in bounded memory write tool with hard character limits, CRUD-style updates, usage feedback, duplicate handling, session-start snapshots, and optional credential-pattern blocking.

## Best Possible Solution

Keep this issue open until maintainers define a memory-core-owned bounded CRUD contract with explicit write authority, hard-limit and usage semantics, replacement identity, duplicate/consolidation policy, secret handling, docs, and focused tests.

## Reproduction Assessment

Yes for the source-level capability gap: current main and v2026.6.11 expose only memory_search and memory_get, while the requested bounded write operations are absent. I did not live-reproduce the multi-week memory-bloat workload.

## Solution Assessment

No as an immediate automated fix. The proposal is plausible, but the best path needs maintainer decisions on the public memory write API, per-store config shape, replacement identity, duplicate handling, and secret-safety policy.
