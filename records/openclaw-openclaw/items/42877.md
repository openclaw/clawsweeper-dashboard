## Summary

Keep open. Current main and v2026.6.11 still provide memory recall, bounded reads, bounded Codex memory injection, dreaming promotion compaction, and a narrow append-only memory-flush path, but not the requested hard-limited memory add/replace/remove/list write contract with usage feedback, duplicate/consolidation behavior, snapshot semantics, and secret-safety policy.

## What This Changes

Request a built-in bounded memory write tool with hard per-store character limits, add/replace/remove operations, usage feedback, duplicate handling, startup snapshot semantics, and optional credential-pattern blocking.

## Best Possible Solution

Define a memory-core-owned bounded CRUD contract with explicit write authority, hard-limit and usage semantics, replacement identity, duplicate/consolidation policy, secret handling, docs, and focused tests before implementation.
