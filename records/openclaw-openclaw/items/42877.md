## Summary

Keep open. Current main and v2026.6.11 still have recall-only memory tools plus partial bounded read, promotion, and flush behavior, but not the requested hard-limited memory add/replace/remove/list write contract with usage feedback, duplicate/consolidation behavior, snapshot semantics, and secret-safety policy.

## What This Changes

The issue requests a built-in bounded memory write tool with add/replace/remove semantics, per-store hard character limits, usage feedback, duplicate handling, snapshot semantics, and optional credential blocking.

## Best Possible Solution

Define a memory-core-owned bounded CRUD contract with explicit write authority, hard-limit and usage semantics, replacement identity, duplicate/consolidation policy, secret handling, docs, and focused tests before implementation.
