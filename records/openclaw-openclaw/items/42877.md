## Summary

Keep open: current main and the latest release still expose memory recall plus partial read/promotion limits, but not the requested bounded add/replace/remove write contract with hard store limits, usage feedback, duplicate handling, snapshot semantics, and credential-safety policy.

## What This Changes

The issue requests a first-class bounded memory write tool for add/replace/remove operations with hard per-store character limits and safety checks.

## Best Possible Solution

Define a memory-core-owned bounded CRUD contract with explicit write authority, hard-limit and usage semantics, replacement identity, duplicate/consolidation policy, secret handling, docs, and focused tests before implementation.
