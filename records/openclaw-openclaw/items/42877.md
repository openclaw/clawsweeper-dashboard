## Summary

Keep open. Current main and v2026.6.11 still expose recall-oriented memory_search/memory_get plus partial bounded read, promotion, and flush behavior, but not the requested hard-limited memory add/replace/remove/list write contract with usage feedback, duplicate/consolidation behavior, snapshot semantics, and secret-safety policy.

## What This Changes

The issue requests a first-class bounded memory write tool with hard per-store character limits, add/replace/remove semantics, usage feedback, duplicate handling, session-start snapshots, and credential-pattern safeguards.

## Best Possible Solution

Define a memory-core-owned bounded CRUD contract with explicit write authority, hard-limit and usage semantics, replacement identity, duplicate/consolidation policy, secret handling, docs, and focused tests before implementation.
