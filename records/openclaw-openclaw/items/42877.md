## Summary

Keep open. Current main and v2026.6.11 still lack the requested first-class bounded memory write/CRUD contract; existing code only partially bounds bootstrap injection, dreaming promotion writes, and optional LanceDB memory capture, so this remains a product/API/security decision rather than conservative cleanup.

## What This Changes

Request for a built-in bounded memory write tool with hard per-store character limits, add/replace/remove behavior, duplicate handling, session-start snapshots, and optional credential-pattern blocking.

## Best Possible Solution

Define an approved memory-core bounded write/CRUD contract, including API shape, per-store limit semantics, target model, identity for edits, duplicate/consolidation policy, secret handling, docs, and regression coverage, before implementation.
