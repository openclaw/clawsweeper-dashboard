## Summary

Keep open: current main still provides recall, bounded reads, Codex memory-injection limits, and bounded auto-promotion compaction, but it does not provide the requested hard-limited memory add/replace/remove/list write contract with usage feedback, duplicate/consolidation behavior, snapshot semantics, and secret-safety policy.

## What This Changes

Request a built-in bounded memory write tool with hard per-store character limits, add/replace/remove operations, duplicate handling, snapshot injection semantics, and optional credential-pattern blocking.

## Best Possible Solution

Define a memory-core-owned bounded CRUD contract with explicit write authority, hard-limit and usage semantics, replacement identity, duplicate/consolidation policy, secret handling, docs, and focused tests before implementation.
