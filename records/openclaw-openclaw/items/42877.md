## Summary

Keep open: current main and v2026.6.11 still expose memory recall, bounded read output, and partial promotion/flush guards, but not the requested bounded memory add/replace/remove write contract with hard per-store limits, usage feedback, duplicate handling, snapshot semantics, and credential-safety policy.

## What This Changes

The issue requests a built-in bounded memory write tool with add/replace/remove actions, hard per-store character limits, duplicate handling, snapshot semantics, and optional credential-pattern blocking.

## Best Possible Solution

Define a memory-core-owned bounded CRUD contract with explicit write authority, hard-limit and usage semantics, replacement identity, duplicate/consolidation policy, secret handling, docs, and focused tests before implementation.
