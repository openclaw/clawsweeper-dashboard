## Summary

Keep open: current main and the latest stable release still expose recall-only memory tools plus partial bounded read, promotion, and flush safeguards, but not the requested hard-limited memory add/replace/remove/list write contract with usage feedback, duplicate handling, snapshot semantics, and secret-safety policy.

## What This Changes

Requested a built-in bounded memory write tool with hard per-store character limits, add/replace/remove semantics, usage feedback, duplicate handling, snapshot injection, and optional credential-pattern blocking.

## Best Possible Solution

Define a memory-core-owned bounded CRUD contract with explicit write authority, hard-limit and usage semantics, replacement identity, duplicate/consolidation policy, secret handling, docs, and focused tests before implementation.
