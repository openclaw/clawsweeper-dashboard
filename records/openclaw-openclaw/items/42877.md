## Summary

Keep open. Current main and v2026.6.11 still expose memory recall plus narrower promotion and memory-flush controls, but not the requested built-in bounded add/replace/remove memory write contract with hard store budgets, usage feedback, duplicate/consolidation behavior, snapshot semantics, and secret-safety policy.

## What This Changes

The issue requests a built-in memory write tool for add/replace/remove operations that enforces hard per-store character limits and rejects over-budget durable memory writes with structured usage feedback.

## Best Possible Solution

Define a memory-core-owned bounded CRUD contract first, including write authority, hard-limit and usage semantics, replacement identity, duplicate/consolidation policy, secret handling, docs, and focused regression coverage before implementation.
