## Summary

Keep open. Current main and v2026.6.11 still expose only memory_search and memory_get in memory-core; the remaining bounded write/CRUD work is a product, API, config, persistence, and security decision rather than an implemented cleanup candidate.

## What This Changes

The issue requests a built-in bounded memory write/CRUD tool with hard per-store character limits, duplicate/consolidation behavior, session-start snapshots, and optional credential-pattern blocking.

## Best Possible Solution

Define an approved memory-core bounded CRUD/write contract, including limit semantics, target-store model, stable selection identity, duplicate/consolidation policy, secret handling, docs, and regression coverage, before implementation.
