## Summary

Keep open. Current main and v2026.6.11 still expose recall-only memory tools plus bounded reads and narrower memory-flush guard work, but not the requested bounded add/replace/remove memory write contract with hard store limits, usage feedback, duplicate/consolidation behavior, snapshot semantics, or secret-safety policy.

## What This Changes

Request a first-class bounded memory write tool with add/replace/remove semantics, hard per-store limits, usage feedback, duplicate handling, snapshot semantics, and secret-safety policy.

## Best Possible Solution

Define a memory-core-owned bounded CRUD contract with explicit write authority, hard-limit and usage semantics, replacement identity, duplicate/consolidation policy, secret handling, docs, and focused tests before implementation.

- **Prototype Externally First:** Ask contributors to prototype the write policy as a memory plugin or ClawHub package until a missing core/plugin API gap is proven.

No as an immediate automated fix. The proposal is plausible, but the best path needs maintainer decisions on the public memory write API, per-store config shape, replacement identity, duplicate handling, snapshot semantics, and secret-safety policy.
