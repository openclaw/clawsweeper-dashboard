## Summary

Keep open. Current main has recall-only memory tools, bounded reads, bootstrap diagnostics, memory-flush guidance, and promotion compaction, but it still lacks the requested bounded add/replace/remove memory write contract and the remaining API, config, snapshot, duplicate, and secret-handling choices need maintainer direction.

## What This Changes

Request a first-class bounded memory write tool for add/replace/remove with configurable hard character limits, usage feedback, duplicate handling, snapshot semantics, and optional credential-pattern blocking.

## Best Possible Solution

Define a memory-core-owned bounded CRUD contract with explicit write authority, hard-limit and usage semantics, replacement identity, duplicate/consolidation policy, secret handling, docs, and focused tests before implementation.
