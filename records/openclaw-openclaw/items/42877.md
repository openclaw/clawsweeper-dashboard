## Summary

Keep open. Current main and v2026.6.11 still lack the requested first-class bounded memory CRUD/write contract; existing bounds cover bootstrap injection, dreaming promotion snippets, and a narrower open memory-flush append PR, so the remaining work is a product, API, and security decision.

## What This Changes

The issue requests a built-in bounded memory write tool with hard per-store character limits, add/replace/remove behavior, duplicate handling, session-start snapshots, and optional credential-pattern blocking.

## Best Possible Solution

Define an approved memory-core bounded CRUD/write contract, including limit semantics, target-store model, selection identity, duplicate/consolidation policy, secret handling, docs, and regression coverage, before implementation.
