## Summary

Keep open: current main and v2026.6.11 still expose recall-only memory tools plus partial bounded read/promotion behavior, but not the requested bounded add/replace/remove write contract with hard store limits, usage feedback, duplicate handling, snapshot semantics, and credential-safety policy.

## What This Changes

The issue requests a first-class bounded memory write tool with configurable hard character limits, add/replace/remove actions, duplicate handling, usage feedback, snapshot semantics, and optional credential-pattern blocking.

## Best Possible Solution

Define a memory-core-owned bounded CRUD contract with explicit write authority, hard-limit and usage semantics, replacement identity, duplicate/consolidation policy, secret handling, docs, and focused tests before implementation.
