## Summary

Keep open: current main and shipped v2026.6.11 still expose memory-core as read/search only, while the requested bounded write/CRUD contract remains a product, API, config, and security design decision. Existing partial mitigations and optional memory plugins reduce some risk but do not provide the requested default hard-limit memory tool.

## What This Changes

Request a built-in bounded memory write/CRUD tool with hard per-store character limits, replace/remove support, duplicate handling, session-start snapshots, and secret scanning.

## Best Possible Solution

Define the approved default memory write contract first, including limit enforcement, stable selection identity, duplicate/consolidation rules, secret handling, docs, tests, and whether this belongs in memory-core or an optional plugin path.
