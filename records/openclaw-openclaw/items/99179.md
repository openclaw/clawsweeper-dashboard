## Summary

Keep open: the PR addresses the reported queue hole, but the patch is broader than the shared-app-server contract because it serializes selected-agent/global local runs even when the Codex client key may resolve to a separate app-server, and the after-fix proof is mock-only.

## What This Changes

The branch broadens `EmbeddedTuiBackend` local-run queueing from same session/agent scope to any active non-BTW local run and adds regression tests for different-session, `/btw`, and selected-agent cases.

## Best Possible Solution

Serialize non-BTW embedded local runs only when they share the same runtime backend/client lease, keep `/btw` and scoped stop outside that queue, and require live proof of that boundary before merge.

## Reproduction Assessment

Yes by source, not by live execution here: current main queues only the same run scope, so different session keys skip the wait path. The PR’s new tests model the bug, but they do so with mocked agent ingress.

## Solution Assessment

No: the PR is a plausible fix for the reported symptom but too broad for the stated shared-app-server boundary. The narrower maintainable fix should queue by shared backend/client identity, or otherwise preserve independent selected-agent scopes when they do not share one backend.
