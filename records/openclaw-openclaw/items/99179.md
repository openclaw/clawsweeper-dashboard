## Summary

Keep this PR open, but not merge-ready: it targets a real source-proven TUI local-run queueing bug, yet the patch broadens queueing to every active non-BTW local run instead of the narrower shared app-server/client boundary and still lacks live embedded app-server proof.

## What This Changes

The branch changes `EmbeddedTuiBackend` so every non-BTW local send waits behind any active non-BTW local run, and adds regression tests for different-session, `/btw`, and selected-agent cases.

## Best Possible Solution

Serialize non-BTW embedded local runs by shared backend/client lease identity, keep `/btw` and scoped stop independent, and require live proof of shared and non-shared cases before merge.

## Reproduction Assessment

Yes by source, not by live execution here: current main queues only the same run scope, so different session keys skip the wait path. The PR’s new tests model the bug, but they do so with mocked agent ingress.

## Solution Assessment

No: the PR is a plausible fix for the reported symptom but too broad for the stated shared-app-server boundary. The narrower maintainable fix should queue by shared backend/client identity, or preserve independent selected-agent scopes when they do not share one backend.
