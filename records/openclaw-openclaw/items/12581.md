  - body: `ExtensionContext` does not define or create `sessionKey`/`sessionId`, but the new code reads those fields and the pruner suppresses hook emission when they are absent.   - body: This awaits `triggerInternalHook` from the context-pruning path, while `triggerInternalHook` awaits each registered handler with no timeout. A slow or hung `session:prune` handler can stall context assembly before every model call that prunes, so best-effort prune observability should be fire-and-forget or time-bounded.

- **[P2] Sanitize tool names before exposing them to hooks:** `src/agents/pi-extensions/context-pruning/pruner.ts:289`
  - body: The new payload forwards raw `msg.toolName` values into hook context. Tool names can be restored from transcript state and hook handlers commonly log or persist context, so validate, bound, and document this field or omit it by default.
  - confidence: 0.77
