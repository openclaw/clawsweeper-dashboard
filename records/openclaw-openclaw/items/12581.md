- **[P1] Port prune hook to the active pruning extension:** `src/agents/pi-extensions/context-pruning/extension.ts:23-31`
  - body: This PR still changes `src/agents/pi-extensions/context-pruning`, but current main deleted that tree and now runs context pruning from `src/agents/agent-hooks/context-pruning`. Until the hook is rebased and ported to the active extension/pruner, merging this branch would not add the lifecycle event to the code path users actually run.
  - confidence: 0.96
- **[P1] Use a typed session identity source:** `src/agents/pi-extensions/context-pruning/extension.ts:29-30`
  - body: `ExtensionContext` does not declare `sessionKey` or `sessionId`, and the current runner's `createContext()` does not provide those properties. Reading them through casts means the normal extension path can pass `undefined`, causing `emitPruneHook` to return early and silently suppress every `session:prune` event.
  - confidence: 0.93
- **[P1] Bound prune hook delivery before awaiting handlers:** `src/agents/pi-extensions/context-pruning/pruner.ts:293`
  - body: `triggerInternalHook()` awaits each registered handler without a timeout, and this PR awaits it from context pruning before the provider request proceeds. A slow or never-settling hook handler can therefore hang context assembly for any turn that prunes; make this fire-and-forget or time-bounded before merging.
  - confidence: 0.9
- **[P1] Define a safe metadata contract before emitting tool names:** `src/agents/pi-extensions/context-pruning/pruner.ts:289`
  - body: The new payload forwards raw `toolNames` from transcript messages to internal hook handlers. Tool names can be derived from tool-call metadata and should be treated as untrusted and potentially sensitive; either omit them, sanitize/allowlist/cap them, and document the trust boundary before exposing them as hook contract.
  - confidence: 0.86
- **[P2] Document the prune hook payload contract:** `docs/automation/hooks.md:235`
  - body: The docs entry only says when `session:prune` fires, but the useful surface is the context payload and its trust rules. Hook authors need the supported fields, types, and escaping expectations documented before this becomes public hook API.
  - confidence: 0.88
