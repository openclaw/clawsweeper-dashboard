  - confidence: 0.93
- **[P1] Use a typed session identity source:** `src/agents/pi-extensions/context-pruning/extension.ts:29-30`
  - body: `ExtensionContext` does not declare or construct `sessionKey` or `sessionId`, so these casts can be `undefined` in the normal context handler and silently suppress every prune event. Thread a real typed session identity from the active runtime or define it on the context contract with coverage for the extension-to-pruner-to-hook path.
  - confidence: 0.9
- **[P1] Bound prune hook delivery before awaiting handlers:** `src/agents/pi-extensions/context-pruning/pruner.ts:293-295`
  - body: `triggerInternalHook` awaits each registered handler, and this patch awaits it from context pruning. A slow or hanging hook can therefore stall prompt assembly for any turn that prunes context; make delivery fire-and-forget or time-bounded before coupling it to pruning.
  - confidence: 0.88
- **[P1] Define a safe metadata contract before emitting tool names:** `src/agents/pi-extensions/context-pruning/pruner.ts:285-290`
  - body: The new payload forwards raw `toolName` values and `sessionId` to installed hook handlers. Tool names are not a sanitized public telemetry field here, so the hook should use a bounded allowlisted/sanitized payload, or omit names until maintainers approve the privacy and logging contract.
  - confidence: 0.86
- **[P2] Document the prune hook payload contract:** `docs/automation/hooks.md:235`
  - body: The docs add the `session:prune` event name but not its context fields. Hook consumers need the supported payload shape and safety notes documented at the same time as the event is introduced.
  - confidence: 0.82
