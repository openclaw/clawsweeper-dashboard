  - body: The added casts read `sessionKey` and `sessionId` from `ExtensionContext`, but current `ExtensionContext` and `createContext()` do not expose those fields. In normal context handlers this leaves `hookSessionKey` undefined, so the new event can silently never emit.
  - confidence: 0.94
- **[P1] Bound prune hook delivery before awaiting handlers:** `src/agents/pi-extensions/context-pruning/pruner.ts:293`
  - body: `triggerInternalHook` awaits registered handlers sequentially and has no timeout, while context handlers are awaited before model input is assembled. A slow or stuck `session:prune` hook would now block context pruning and the agent turn.
  - confidence: 0.92
- **[P1] Define a safe metadata contract before emitting tool names:** `src/agents/pi-extensions/context-pruning/pruner.ts:289`
  - body: The new payload forwards raw `ToolResultMessage.toolName` values to hook handlers. Tool names can come from repaired assistant tool calls, and hook handlers commonly log or forward event context, so this needs sanitization or an explicit metadata-only trust contract before merge.
  - confidence: 0.89
- **[P2] Document the prune hook payload contract:** `docs/automation/hooks.md:235`
  - body: The docs entry only names when `session:prune` fires; it does not describe the context fields, timestamp semantics, sanitized/omitted tool names, or the intentional absence of pruned content. Hook authors need that contract to use the event safely.
  - confidence: 0.94
