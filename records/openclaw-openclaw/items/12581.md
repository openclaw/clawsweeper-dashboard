  - body: `sessionKey` and `sessionId` are not declared on the current `ExtensionContext`, so these casts can be `undefined` in the normal extension path and silently suppress every prune hook emission.   - confidence: 0.9
- **[P1] Bound prune hook delivery before awaiting handlers:** `src/agents/pi-extensions/context-pruning/pruner.ts:293`
  - body: `triggerInternalHook` awaits registered handlers sequentially with no timeout. Awaiting it from context pruning puts model-call preparation behind arbitrary hook code, so a slow or hung `session:prune` handler can stall runs. Use a non-blocking or time-bounded delivery contract and test that pruning cannot hang on hook handlers.
  - confidence: 0.88
- **[P1] Define a safe metadata contract before emitting tool names:** `src/agents/pi-extensions/context-pruning/pruner.ts:289`
  - body: `toolNames` forwards raw names from pruned transcript messages into hook context. Tool names are metadata from model/tool-call state and may be logged or indexed by handlers, so the hook should emit sanitized, bounded metadata or omit names by default, with explicit trust/logging documentation.
  - confidence: 0.85
- **[P2] Document the prune hook payload contract:** `docs/automation/hooks.md:235`
  - body: The docs entry only names `session:prune`, but hook authors need the payload shape and delivery semantics to use it safely. Once the contract is chosen, document fields such as counts, timestamp, session identity, sanitized tool metadata, and whether pushed hook messages are ignored.
  - confidence: 0.86
