  - body: `ExtensionContext` does not declare `sessionKey` or `sessionId`, and the runner-created context only exposes session identity through `ctx.sessionManager` methods.   - body: `triggerInternalHook` awaits registered handlers sequentially and has no timeout, so awaiting it from context pruning can hang prompt assembly when a hook handler stalls. Keep pruning best-effort with a bounded wait or fire-and-forget delivery before merging this into the model-call path.
  - confidence: 0.9
- **[P1] Define a safe metadata contract before emitting tool names:** `src/agents/pi-extensions/context-pruning/pruner.ts:289-290`
  - body: The hook forwards collected `toolName` strings directly into hook context without a documented sanitizer, length cap, or trust contract. Tool names can become log or telemetry fields in user-installed hooks, so this needs a bounded metadata contract before becoming a lifecycle surface.
  - confidence: 0.87
- **[P2] Document the prune hook payload contract:** `docs/automation/hooks.md:235`
  - body: The docs entry only says when `session:prune` fires, but it omits the payload shape and trust expectations. Hook consumers need the supported fields, types, and sanitization guarantees documented with the new event.
  - confidence: 0.91
