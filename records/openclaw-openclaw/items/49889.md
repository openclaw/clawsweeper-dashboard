## Summary

Keep this issue open: current main and the latest release still have source-level Telegram partial-stream delivery-state ambiguity, and the linked candidate PR remains open, conflicting, and missing live Telegram proof.

## What This Changes

The issue requests clearer Telegram partial-stream final delivery observability so operators can distinguish sent messages, preview finalization, retained previews, cancellations, transport failures, and intentional skips.

## Best Possible Solution

Land a rebased current-main Telegram fix that records explicit final outcome state only after all final preview continuation sends settle, preserves the one-visible-preview invariant, and includes redacted live Telegram proof.

## Reproduction Assessment

Yes at source level: current main marks the lane delivered before remaining Telegram final chunks are sent, and the dispatcher later uses the delivery summary for fallback decisions. I did not run live Telegram proof in this read-only review.

## Solution Assessment

Yes for the core fix direction: delaying delivered-state success until final continuation sends settle is the narrow Telegram-owned repair. The optional strict fresh-final mode and broader cross-channel semantics remain product decisions, so the open linked PR or a current-main replacement is the right path before closing this issue.
