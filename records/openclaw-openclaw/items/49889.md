## Summary

Keep this open: current main and the latest release still have the Telegram partial-stream delivered-state gap, and the linked closing PR remains open, conflicting, and missing real Telegram proof.

## What This Changes

The issue requests clear Telegram partial-stream final delivery observability for sent, preview-finalized, preview-retained, canceled, failed, and skipped outcomes.

## Best Possible Solution

Land a rebased Telegram-owned fix, or a current-main successor, that delays delivered-state success until final chunks settle and adds explicit outcome signals without adding a strict fresh-final config mode unless maintainers approve it.

## Reproduction Assessment

Yes, at source level: current main marks Telegram preview-finalized delivery before remaining final chunks settle, and fallback/visibility logic then trusts that delivered state. I did not run a live Telegram reproduction in this read-only review.

## Solution Assessment

Partially. Delaying delivered-state success until all final chunks succeed is the narrow Telegram-owned fix, but the broader outcome taxonomy and any strict fresh-final behavior need maintainer product judgment.
