## Summary

Keep this issue open: current main and v2026.6.11 still have source-level Telegram partial-stream final delivery ambiguity, and the linked closing PR is still open, conflicting, and missing real Telegram proof.

## What This Changes

Request clearer Telegram partial-stream final delivery outcome observability and delivery-state parity for sent, preview-finalized, retained, canceled, failed, and intentionally skipped replies.

## Best Possible Solution

Land the linked Telegram fix or a current-main successor that delays delivered-state success until all final chunks settle, emits explicit delivery outcome signals, and leaves strict fresh-final behavior behind maintainer approval.

## Reproduction Assessment

Yes, at source level: current main marks Telegram partial-stream finals delivered before remaining continuation chunks settle, and the dispatcher later treats delivered state as visible-response evidence. I did not run a live Telegram reproduction in this read-only review.

## Solution Assessment

Yes for the narrow reliability direction: delaying delivered-state success until final continuation chunks succeed is the clean Telegram-owned repair. The broader delivery-mode taxonomy and strict fresh-final mode still need maintainer product judgment.
