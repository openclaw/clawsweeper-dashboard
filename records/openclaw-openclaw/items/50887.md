## Summary

Close as implemented on main: current main now decodes default UTF-8 subprocess output statefully, so split Chinese code points no longer turn into U+FFFD on the shared child/process-output path; the fix is current-main-only and not in v2026.6.11.

## What This Changes

The issue reports corrupted Chinese characters in streamed WebChat/group-chat responses when multibyte UTF-8 output is split across chunks.

## Best Possible Solution

Keep the shared streaming decoder implementation on main and let the next release carry the fix; older child-local PR attempts can remain closed or be superseded by this main implementation.
