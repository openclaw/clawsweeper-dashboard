## Summary

Close: current main now uses a stateful UTF-8 decoder for subprocess stream chunks, the child adapter routes stdout/stderr through that decoder, and the fix is included in v2026.7.1-beta.2.

## What This Changes

The issue reports corrupted Chinese characters in streamed webchat/group-chat agent responses when UTF-8 code points are split across streaming chunks.

## Best Possible Solution

Keep the merged shared-decoder implementation and direct affected users to v2026.7.1-beta.2 or newer; no new OpenClaw core work is needed for this report.
