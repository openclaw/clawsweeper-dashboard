## Summary

Keep open: current main and v2026.6.11 still do not define the Telegram channel_post plus sender-scoped per-chat allowFrom rule, and https://github.com/openclaw/openclaw/pull/49063 remains an open, conflicting implementation candidate that explicitly leaves this policy unresolved.

## What This Changes

Request to define and document how Telegram channel_post native command authorization behaves when a per-chat sender-scoped allowFrom override is configured.

## Best Possible Solution

Choose one Telegram channel_post authorization policy, preferably fail-closed with a clear unsupported message when sender-scoped per-chat allowFrom is configured unless maintainers explicitly accept explicit-chat-only semantics, then update code, tests, docs, and live Telegram proof to match.
