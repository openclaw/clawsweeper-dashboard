## Summary

Keep open: current main and v2026.6.11 still do not define Telegram `channel_post` behavior when sender-scoped `groups[chatId].allowFrom` is configured, and the linked open PR is conflicting and explicitly leaves that policy unresolved.

## What This Changes

Telegram `channel_post` authorization should define how sender-scoped `groups[chatId].allowFrom` behaves when Telegram does not expose a normal human sender.

## Best Possible Solution

Choose one Telegram `channel_post` authorization policy, then update the Telegram plugin code, focused auth tests, public Telegram docs, and redacted live Telegram proof to match it.
