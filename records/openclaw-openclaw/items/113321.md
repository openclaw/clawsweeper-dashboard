## Summary

Keep open pending a current-iOS-build reproduction. Current main’s native Talk code is designed to synthesize through the configured gateway provider via `talk.speak`, then fall back to the system voice only after an error; that directly conflicts with the reported always-system route, but the available evidence does not establish when this iOS implementation landed or whether the reported build contains it.

Likely related people: steipete is a low-confidence routing candidate because they previously reviewed and closed the same `talk.speak` architecture gap on the macOS side.

## What This Changes

The issue reports that iOS Native Talk ignores a configured ElevenLabs provider and can leave playback silent instead of using gateway synthesis or showing an actionable fallback state.

## System Context

iOS Native Talk captures speech locally, sends the transcript through the Gateway’s chat session, then requests synthesized audio from the active Talk provider. The client plays that audio locally and should use the iOS system voice only as a visible recovery path when gateway synthesis fails.
