## Label Justifications

- `P1`: The issue reports a shipped macOS app repeatedly minting new device/node identities, breaking paired-node workflows and accumulating stale auth state.
- `impact:session-state`: The reported failure is persistent identity state drift across reconnects, with node IDs and related local state becoming stale.
- `impact:auth-provider`: The issue affects device authentication and pairing tokens because every reconnect can create a new approved device identity.
- `maturity:stable`: The affected macOS Gateway host and Gateway runtime pairing surfaces are listed as M4 Stable in the maturity shortlist.

## Summary

Keep open: current main and the latest release still prefer app-group identity storage before legacy storage, silently ignore Swift identity write failures, and sign the macOS bundle without an App Groups entitlement, so the reported identity churn remains a credible shipped bug.

## What This Changes

The issue reports that the shipped macOS app can generate new device and node identities on every reconnect because its app-group identity store is selected but not usable without the App Groups entitlement.

## Best Possible Solution

Choose a signed macOS identity-storage fix that either ships and validates the App Groups entitlement or entitlement-checks and falls back to a writable legacy identity store, with regression coverage and signed-app proof on macOS 27.

## Reproduction Assessment

No, not as a live macOS 27 signed-app run in this review. Source inspection shows the reported failure path is credible when the app-group URL is selected but unreadable: load misses, save failure is swallowed, and a fresh identity is returned.

## Solution Assessment

Unclear. The right fix likely needs maintainer choice between provisioning App Groups for the macOS bundle and adding an entitlement-aware fallback/migration path that preserves existing identities.
