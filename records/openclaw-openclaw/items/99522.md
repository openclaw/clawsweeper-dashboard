## Label Justifications

- `P1`: The latest released macOS app can lose device identity continuity on reconnect, causing repeated auto-pairing and broken node-targeted workflows for affected users.
- `impact:data-loss`: The selected identity store can be unreadable or unwritable, so persisted device identity state is effectively lost each time the app reconnects.
- `impact:session-state`: Changing device and node ids leaves stale node records behind and breaks workflows pinned to the previous node identity.
- `impact:auth-provider`: Device auth tokens and pairing approvals are keyed to the changing device id, so auth continuity breaks even though the physical Mac is the same.
- `maturity:stable`: The report affects gateway-runtime Device Auth and Pairing plus macOS Gateway host behavior, both tied to M4 Stable surfaces in the checked maturity scorecard.

## Summary

Keep open: current main and the latest release still prefer the macOS App Group identity directory without a macOS app-groups entitlement and silently regenerate when that store cannot be read or written, so the reported reconnect identity churn remains actionable.

## What This Changes

The issue asks OpenClaw to stop the macOS app from regenerating device and node identities when the App Group identity store is unavailable and to improve fallback or diagnostics.

## Best Possible Solution

Preserve a stable macOS device identity by using only an entitled and writable App Group store, falling back or repairing to the legacy Application Support identity when needed, and adding signed-app plus doctor coverage for identity churn.

## Reproduction Assessment

Unclear for a full live macOS 27 beta packaged-app repro in this read-only review. The failure condition is source-reproducible: if the selected App Group identity file cannot be read or written, current main generates a fresh identity and hides the save failure.

## Solution Assessment

Unclear whether entitlement shipping or fallback should be the primary maintainer choice, but the state-dir override workaround is not the right product fix. The maintainable direction is entitlement/writeability-aware identity storage with regression coverage and visible diagnostics.
