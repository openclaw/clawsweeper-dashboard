## Summary

Keep open. Current main and the latest release still type `toolSummary.failures` as a number but populate it from a boolean `lastToolError` state, so multi-failure turns remain capped at one rather than counted.

## What This Changes

The issue asks for `toolSummary.failures` to stop undercounting multiple failed tool calls in one agent turn.

## Best Possible Solution

Preserve `toolSummary.failures` and make it a true per-attempt failed-tool count using the existing tool-result error classifier, with focused regression coverage for multiple failed calls in one turn.
