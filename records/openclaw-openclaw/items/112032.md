## Summary

Likely related people: steipete, who introduced the current SQLite MCP OAuth store, is the strongest routing candidate.

## What This Changes

This PR records the authorization-server issuer alongside MCP OAuth tokens and refuses to provide a stored refresh token when later discovery selects a different issuer.

## System Context

Remote MCP connections obtain OAuth credentials through the MCP OAuth provider, which reads persisted server credentials and gives the MCP SDK a token for authenticated requests or refreshes. The SDK's discovery and challenge flow can change the authorization server, so the provider is the boundary that must keep a stored refresh token attached to its original issuer.

  D --> E[Issuer comparison]
  E -->|same issuer| F[Refresh token endpoint]
  E -->|different or unknown issuer| G[Interactive MCP login]

## Best Possible Solution

Preserve existing credentials safely by allowing an unbound legacy token through the unchanged-discovery path until a resource-metadata transition snapshots the prior issuer, then retain the new cross-issuer withholding; add an explicit upgrade regression covering that sequence.
