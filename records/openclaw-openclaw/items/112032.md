Likely related people: steipete is the strongest routing candidate from the merged SQLite MCP OAuth ownership work (high confidence).

## What This Changes

The PR stores the issuer that produced an MCP OAuth token and withholds a stored refresh token when later discovery selects a different issuer, requiring the user to authorize again.

## System Context

OpenClaw stores OAuth credentials for outbound remote MCP servers in its shared SQLite state and supplies them to the MCP SDK while connecting or retrying authenticated requests. A 401 resource-metadata challenge can change discovery, so the credential provider must decide whether the stored refresh token is safe to expose to the newly selected authorization server.

## Best Possible Solution

Keep the issuer-bound guard in the MCP OAuth credential provider and accept a one-time reauthorization for legacy token-only imports rather than retaining a path that can replay a refresh token to an untrusted issuer.
