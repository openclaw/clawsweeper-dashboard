## Label Justifications

- `merge-risk: 🚨 session-state`: Competing destructive removers can corrupt or mis-associate a session worktree and its snapshot or registry state.
- `merge-risk: 🚨 availability`: Racing removal and marker cleanup can leave the filesystem and registry inconsistent or make later worktree operations fail.

## Summary

Keep this PR open: the underlying data-loss race is real and the submitted real-process proof is convincing, but the rewritten head does not make removal ownership exclusive. A second remover can overwrite the live removal marker, allowing competing destructive operations and foreign cleanup of the marker.

## What This Changes

The PR adds shared SQLite-backed run leases, removal claims, stale-owner recovery, and secondary Git locks to protect managed session worktrees during agent runs.

## Best Possible Solution

Use an opaque claim handle for each removal operation, reject any non-stale incumbent marker, and require the matching handle for abort and finalization so ownership cannot be overwritten or cleared by another process.
