## Label Justifications

- `P0`: The underlying bug can delete an active session checkout and destroy uncommitted in-flight work.
- `merge-risk: 🚨 session-state`: The patch changes authoritative admission and cleanup state for session-bound managed worktrees.
- `merge-risk: 🚨 availability`: An exhausted cleanup retry can leave normal worktree removal and GC blocked for the lifetime of the gateway process.

## Summary

The proof and main concurrency design are strong, but the exhausted release path still silently strands the lease in a long-lived process because production has no later retry handle.

## What This Changes

The PR adds SQLite-backed shared run leases and exclusive removal claims for managed worktrees, integrates leasing before agent workspace preparation, and adds race and cleanup regressions.

## Best Possible Solution

Keep SQLite as the authoritative admission/removal gate, but make exhausted release cleanup durably retry with lifecycle-owned backoff while retaining the git guard until the row is deleted, then prove recovery after more than three consecutive failures.

## Solution Assessment

No, not yet. The transactional lease/claim model is the right ownership boundary, but the only production release call must guarantee eventual cleanup rather than depend on an unavailable later manual retry.
