## Summary

Keep open: the core race is convincingly demonstrated and the SQLite design is largely sound, but failed Git-unlock cleanup can detach from the active lock generation and prematurely remove protection from a newer run.

## What This Changes

Adds SQLite-backed shared run leases and exclusive removal claims to protect managed session worktrees during agent preparation and execution.

## Best Possible Solution

Retain the SQLite admission/removal transaction, but represent each process-local Git guard with one canonical generation-safe state whose refcount, lock status, and failed-unlock obligation remain coherent across reacquisition.

## Repair Work Prompt

Fix stale pending Git-unlock ownership in src/agents/worktrees/run-lease.ts. Cleanup from an older lease must never unlock the Git guard owned by a newer active lease or create an unprotected gap before reacquisition is represented in SQLite. Keep refcount, Git-lock status, and failed-unlock obligation in one canonical generation-safe per-worktree state. Add a regression that fails unlock, releases the old lease, acquires a new lease, retries cleanup, proves the Git lock stays live while the new lease is active, and proves it unlocks only after final release. Preserve SQLite admission/removal semantics, stale-owner pruning, force behavior, and existing preparation/removal proof. Do not modify the separate GC caller-liveness work in https://github.com/openclaw/openclaw/pull/104146. Do not edit CHANGELOG.md.
