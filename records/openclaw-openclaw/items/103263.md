## Summary

The core SQLite lease design and real behavior proof are strong, but the latest cleanup rewrite introduces a blocking ownership race: cleanup from an older released lease can later remove the Git guard held by a newer active lease on the same worktree.

## What This Changes

The PR adds SQLite-backed shared run leases and exclusive removal claims for managed session worktrees, acquires leases during agent preparation, and adds concurrency, stale-owner, and cleanup regressions.

## Best Possible Solution

Keep the SQLite admission/removal transaction, but represent the process-local Git guard as one generation-safe refcounted owner whose failed unlock remains attached to canonical state; reacquisition must absorb or cancel the old unlock obligation rather than letting stale cleanup unlock a newer holder.
