## Summary

The exact-head proof is strong and the SQLite ownership model is directionally correct, but the branch still has bounded cleanup and concurrency defects that can leave worktrees blocked or drop the secondary Git guard too early.

## What This Changes

The PR adds SQLite-backed shared run leases and exclusive removal claims for managed worktrees, acquires leases before agent workspace preparation, and adds race, stale-owner, cleanup, and removal regressions.

## Best Possible Solution

Keep SQLite as the atomic admission/removal gate, but give failed cleanup a process-lifecycle owner until both the token row and Git guard are released, and serialize shared Git-lock refcount transitions across concurrent acquisitions.
