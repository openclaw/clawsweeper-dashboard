## Label Justifications

- `P0`: The underlying race can delete an active agent run's managed worktree and destroy in-flight workspace files.
- `merge-risk: 🚨 session-state`: The patch changes persistent ownership and cleanup of session-bound worktree state across processes.
- `merge-risk: 🚨 availability`: A failed final cleanup can strand a lease and block worktree removal or garbage collection until process exit.

## Summary

The current head preserves the lease row and Git guard after a failed cleanup, but it still depends on a later `release()` call that the production finalizer never makes. A transient SQLite failure can therefore block removal and GC until process exit, so this needs one more focused repair before merge.

## What This Changes

The PR adds SQLite-backed shared run leases and exclusive removal claims for managed session worktrees, integrates lease acquisition into agent runs, and adds race-focused tests.

## Best Possible Solution

Keep the shared-reader and exclusive-removal design, but make one production cleanup invocation perform a bounded retry of token-row deletion while retaining the Git guard, then release that guard only after deletion succeeds and prove removal works without an external second call.
