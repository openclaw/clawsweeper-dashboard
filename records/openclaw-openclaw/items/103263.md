## Summary

Keep open: the patch convincingly demonstrates and narrows the destructive GC race, but it does not guarantee mutual exclusion between session activation and worktree removal, so the claimed data-loss fix remains incomplete.

## What This Changes

The PR adds a second owner-activity check immediately before idle GC force-removes a managed session worktree, with a regression test for a resumed session.

## Best Possible Solution

Have session run admission acquire a lifecycle-owned, ref-counted worktree lease before using the checkout, and require idle GC to hold the mutually exclusive removal side through the destructive git operation.
