## Summary

Keep open: the prior blocker is still present on the same head SHA, because the PR changes Slack unset status reactions to opt-in even on paths where native Slack status cannot run and only a static acknowledgement remains.

## What This Changes

The PR makes Slack lifecycle reaction updates require `messages.statusReactions.enabled: true`, keeps acknowledgement reactions static by default, and updates Slack/config docs and focused Slack tests for that default.

## Best Possible Solution

Prefer native Slack assistant status only when a usable status thread target exists, and preserve lifecycle reaction progress by default whenever the native status call would no-op.
