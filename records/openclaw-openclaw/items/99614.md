## Summary

Keep open: the PR targets a real gateway watch crash-loop, but it is not merge-ready because the helper still accepts a build-stamp state that current `run-node` rebuilds, deferred restarts are not deterministic once `dist/` changes are ignored, and the submitted proof does not show a real `gateway:watch` race run.

## What This Changes

Adds an `isBuildReadyForRestart` guard to `scripts/watch-node.mjs`, declaration support, and `src/infra` regression tests to defer gateway watch restarts when build output is missing or stale.

## Best Possible Solution

Make source-checkout watch restarts transactional: prepare or validate the replacement build for the current checkout before signaling the healthy gateway child, with deterministic follow-up if maintainers accept a narrower guard.

## Reproduction Assessment

Yes, source-reproducible with high confidence: current main signals the watched child before `run-node` has completed a valid replacement build, and the linked production report includes redacted systemd logs for the missing-entrypoint restart loop. I did not run a destructive live systemd reproduction in this read-only pass.

## Solution Assessment

No. This is a plausible partial mitigation, but the best fix is a replacement-build boundary before signaling the healthy gateway, with deterministic deferred restart behavior if a narrower guard lands.

## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Reject headless build stamps before restarting:** `scripts/watch-node.mjs:109`
  - body: `run-node` treats a build stamp without `head` as stale whenever Git HEAD is available, but this helper only rejects mismatches when both values exist. A source checkout with an older headless stamp can still pass the guard, SIGTERM the healthy gateway, and rebuild after the stop.
  - confidence: 0.9
- **[P2] Trigger the deferred restart when output becomes ready:** `scripts/watch-node.mjs:554-560`
  - body: When the guard returns false, `requestRestart()` only logs and returns. Since `dist` is ignored by the watcher, a rebuild completing under `dist/` will not necessarily emit another relevant event, leaving the old child running indefinitely after a checkout update.
  - confidence: 0.84
- **[P3] Format the helper so required script lint passes:** `scripts/watch-node.mjs:94-109`
  - body: The head SHA `check-lint` job fails on the new helper with `no-shadow` for the `fs` parameter and missing-curly errors on one-line `if` statements. Rename the parameter and add braces so the required script lint lane can pass.
  - confidence: 0.95
