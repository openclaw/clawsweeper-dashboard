## Summary

Keep open: the patch is a focused mitigation, but it still checks only the current `dist/entry.js` before killing the healthy gateway child, while the replacement `run-node` can rebuild for a changed checkout and clean `dist` after that stop. The linked production crash-loop issue remains open, and the sibling PR is not a proof-positive canonical replacement.

## What This Changes

The PR adds `dist/entry.js` guard checks to `scripts/watch-node.mjs` and new `src/infra/watch-node.test.ts` coverage for missing-entry restart paths.

## Best Possible Solution

Make gateway watch restarts transactional: prepare or validate replacement build output for the new checkout before signaling the healthy child, then prove the real source-checkout watch race.

## Reproduction Assessment

Yes from source: current main kills the watched gateway child before the replacement runner rebuilds and proves a valid entrypoint, and `run-node` may rebuild for reasons where the old entry still exists. No live systemd reproduction was run in this read-only pass.

## Solution Assessment

No: this is a plausible mitigation for one missing-entry timing window, but it does not validate the replacement build for the new checkout before killing the healthy gateway.
