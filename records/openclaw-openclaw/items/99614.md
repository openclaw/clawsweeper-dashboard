## Summary

Keep open: this PR is a useful narrow missing-entry guard, but it is not the best fix for the linked gateway outage because an old `dist/entry.js` can still exist while the replacement `run-node` path must rebuild and clean `dist` after the healthy child has already been stopped.

## What This Changes

This PR adds `dist/entry.js` existence guards to `scripts/watch-node.mjs` before restart/respawn and expands `src/infra/watch-node.test.ts` coverage for missing-entry restart paths.

## Best Possible Solution

Make gateway watch restarts transactional: prepare or validate replacement build output for the new checkout before signaling the healthy child, then prove the real source-checkout watch race with redacted runtime output.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes from source: current main stops the watched gateway child before the replacement runner rebuilds and proves a valid entrypoint; no live systemd reproduction was run in this read-only pass.

## Solution Assessment

Is this the best way to solve the issue? No: the PR is a plausible mitigation for one missing-entry timing window, but it does not validate the replacement build for the new checkout before killing the healthy gateway.
