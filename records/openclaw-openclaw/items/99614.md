## Summary

Keep open. The latest head is still not merge-ready because the watcher guard only checks a subset of the `run-node` readiness contract and can also drop a deferred restart until another watched source event arrives.

## What This Changes

The PR adds a build-readiness guard to `scripts/watch-node.mjs`, exposes it in `scripts/watch-node.d.mts`, and adds watch-node regression tests.

## Best Possible Solution

Prepare or validate the replacement build/runtime tree for the current checkout before signaling the healthy gateway child; if maintainers choose a smaller mitigation, share `run-node` readiness and schedule a deterministic pending restart.

## Reproduction Assessment

Yes. The canonical issue gives a concrete source-checkout/systemd/git-update scenario, and current source shows the watcher can signal the child before `run-node` completes a replacement build; I did not run the destructive live race in this read-only review.

## Solution Assessment

No. This is a plausible partial mitigation, but it is not the best fix until it shares `run-node` readiness and deterministically restarts after deferral; a transactional prepare-then-signal boundary is safer.
