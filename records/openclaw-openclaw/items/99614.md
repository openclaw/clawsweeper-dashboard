## What This Changes

The PR adds dist/entry.js existence guards to scripts/watch-node.mjs restart paths and adds watch-node tests for the missing-entry case.

## Best Possible Solution

Make gateway watch restarts transactional by preparing or validating the replacement build for the changed checkout before signaling the healthy child, update the script declarations, and add real redacted gateway watch proof.

## Reproduction Assessment

No live systemd reproduction was run in this read-only review. Source inspection shows the current watcher can signal the running child before run-node finishes rebuilding and launching a valid replacement, and tsdown cleans dist during that rebuild.

## Solution Assessment

No: this is a plausible partial mitigation, but it is not the best fix because it checks only the current dist/entry.js instead of proving replacement build readiness before killing the healthy gateway.
