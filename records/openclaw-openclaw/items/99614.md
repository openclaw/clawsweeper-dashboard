## Label Justifications

- `P1`: The PR targets an open production gateway crash-loop report that can stop or stall a systemd-managed source-checkout gateway.
- `merge-risk: 🚨 availability`: The diff changes gateway watch restart lifecycle behavior and can leave hot reload stalled after a Git HEAD change or still fail to prove a safe replacement before stopping the healthy process.

## Summary

Keep open: the updated head improves on the earlier entry-exists-only guard, but it can now wait forever after a Git HEAD change because the watcher waits for a matching build stamp without starting the replacement `run-node` process that normally creates it. Real source-checkout `gateway:watch` proof is also still missing.

## What This Changes

This PR adds a build-readiness helper, deferred polling restart path, exit-handler guard, and watch-node tests for gateway hot-reload restarts when `dist/entry.js` or the build stamp is not ready.

## Best Possible Solution

Make the watch restart transactional: prepare or validate the replacement build for the new checkout before signaling the healthy child, then prove the source-checkout hot-reload race with redacted live output.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Source-reproducible: current main stops the watched child before `run-node` rebuilds, and the PR branch can wait for a matching build stamp without starting the process that creates it; no live systemd reproduction was run in this read-only review.

## Solution Assessment

Is this the best way to solve the issue? No: this is a plausible partial guard, but the maintainable fix is to prepare or validate the replacement build before stopping the healthy gateway child.
