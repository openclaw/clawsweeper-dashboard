## Summary

Keep this PR open: the prior rollback-isolation blocker remains on the latest approach because custom-class registry objects can still be shared by reference across the snapshot and live registry. The linked bug remains open, and current `main` still uses a shallow registry snapshot.

## What This Changes

The PR replaces shallow plugin-registry transaction snapshots with recursive cloning and adds rollback tests for nested objects, Dates, functions, and custom-class values.

## Best Possible Solution

Use a prototype-preserving, recursive clone for mutable custom instances and add a rollback test that mutates a custom instance’s own nested state before rollback; keep functions and genuinely immutable runtime handles by reference only when their non-mutation contract is explicit.

## Solution Assessment

No. Deep cloning the mutable registry graph is the right repair boundary, but retaining arbitrary custom instances by reference is not a complete rollback solution; preserve prototypes while recursively copying mutable own state instead.
