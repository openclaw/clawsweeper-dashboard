## Summary

The PR addresses the shallow nested-mutation rollback bug, and its updated clone now preserves callable entries, but the new generic object branch changes `Date` values such as `PluginRecord.failedAt` into plain objects during any rollback. That is a blocking rollback regression; the branch also still lacks after-fix real runtime proof.

## What This Changes

The branch replaces shallow plugin-registry snapshot copying with a recursive clone that preserves functions and adds nested-config rollback coverage.

## Best Possible Solution

Use a type-preserving snapshot strategy for registry data—at minimum retaining `Date` and other non-plain object semantics while preserving function references—add regression coverage for those values, then show a redacted runtime rollback trace from a real plugin registration path.
