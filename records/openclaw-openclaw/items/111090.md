## Summary

Keep this PR open for maintainer review. The latest branch resolves the previously raised collection and prototype-reconstruction problems, but it deliberately makes opaque custom-class registry values non-transactional: mutations to those objects survive rollback. That is a plugin-registry value-contract decision, not a mechanical follow-up the contributor can safely choose alone.

## What This Changes

The PR replaces shallow plugin-registry transaction snapshots with recursive cloning for plain objects, arrays, Maps, Sets, and structured-cloneable typed values, while preserving functions and opaque custom-class instances by reference.

## Best Possible Solution

Maintain one explicit registry snapshot contract: recursively restore supported mutable data values, treat opaque class instances as immutable references, and obtain owner approval that plugin registrations may rely on that boundary before merge.
