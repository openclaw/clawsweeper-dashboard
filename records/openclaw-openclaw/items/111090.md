## Label Justifications

- `P1`: Plugin installation-timeout rollback can corrupt registered plugin metadata and leave the plugin runtime in an inconsistent state.
- `merge-risk: 🚨 compatibility`: The snapshot helper changes rollback semantics for all registry object values, including plugin-provided typed metadata.

## Summary

Keep this PR open: it addresses the reported rollback defect and now includes credible built-module rollback output, but the proposed `structuredClone` fallback does not preserve ordinary custom-class instances as its stated contract requires. That can silently replace plugin-owned typed metadata with a plain object during rollback, so this needs a narrow repair and regression test before merge.

## What This Changes

The PR replaces shallow plugin-registry snapshot copying with recursive cloning and adds rollback coverage for nested mutations, `Date` values, and callable entries.

## Best Possible Solution

Clone only values with explicit supported clone semantics (including nested arrays, maps, plain records, and typed built-ins such as `Date`), retain non-plain custom instances by reference, add a custom-instance rollback regression, then rebase and validate the current head.

## Solution Assessment

No. Deep-copying mutable plain registry data is the right boundary, but using `structuredClone` as a generic class-instance detector is not safe; classify plain versus non-plain objects before cloning.
