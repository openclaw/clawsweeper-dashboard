## Summary

This PR addresses an open rollback bug, but its generic custom-instance cloning creates instances that can retain a prototype while lacking private or non-enumerable state. The central rollback guarantee is still necessary; the clone boundary needs a maintainer-approved contract before merge.

## What This Changes

The branch replaces shallow plugin-registry transaction snapshots with recursive cloning and adds rollback regression coverage for nested values, Dates, functions, custom instances, Maps, and Sets.

## Best Possible Solution

Define the supported transaction-snapshot value contract, then deep-clone only canonical mutable registration data or provide an explicit clone/restore contract for opaque plugin-owned values instead of generically reconstructing arbitrary class instances.
