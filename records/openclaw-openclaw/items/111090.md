## Label Justifications

- `P1`: The patch targets plugin installation rollback, but mutable custom registry values can still retain failed-transaction state.
- `merge-risk: 🚨 compatibility`: Changing registry snapshot semantics can alter rollback behavior for existing plugin-provided typed values and leave stale state when the fallback shares references.

## Summary

The prior callable, Date, and custom-instance prototype concerns are addressed, and the supplied runtime proof is credible; however, the new custom-instance fallback still shares mutable instances with the live registry, so it does not fulfill rollback isolation for mutations inside such values.

## What This Changes

The PR replaces shallow plugin-registry transaction snapshots with recursive cloning and adds rollback coverage for nested data, `Date` values, functions, and custom instances.

## Best Possible Solution

Preserve custom-instance prototypes while cloning their mutable own data recursively, add a rollback-mutation regression case for such an instance, and keep functions or truly opaque state by reference only where the registry contract proves they cannot mutate.
