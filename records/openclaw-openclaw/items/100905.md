## Summary

Keep open, but the patch is not correct as written: it repeats the broad `provider_error_4xx` fail-open policy that prior maintainer feedback rejected, and it has only unit-test proof rather than after-fix real behavior proof.

## What This Changes

The branch adds timeout and provider 4xx/5xx preflight compaction failures to the skip predicate and adds regression tests for those classifications.

## Best Possible Solution

Keep the runtime guard as the likely fix layer, but replace the broad 4xx skip with a structured retryability whitelist: timeout, 5xx, and only an explicitly approved 429 path should skip, while 400/401/403 keep throwing with positive and negative tests plus real behavior proof.
