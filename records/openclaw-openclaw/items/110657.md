## Summary

The focused curl change is technically sound, but this PR still needs real behavior proof for the production command: the published terminal runs deliberately omit the installer’s `--retry 3 --retry-delay 1`, so they establish only a single connection attempt rather than the user-visible installer outcome.

## What This Changes

The PR adds `--connect-timeout 10` to the curl download paths in both shell installers and updates the corresponding command-assertion tests.

## Best Possible Solution

Keep the narrow per-attempt timeout if maintainers accept the ten-second threshold, but add a redacted terminal transcript using the complete production curl options and clarify that retries bound each attempt rather than the installer’s total wall-clock time.
