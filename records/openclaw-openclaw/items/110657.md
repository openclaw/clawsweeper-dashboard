## Summary

Keep this PR open: the timeout hardening is useful, but the proposed 60-second `--max-time` caps every successful curl transfer attempt and can turn slow yet progressing installs into failures. The supplied regression test only inspects mocked curl arguments, so it does not provide after-fix real-behavior proof.

## What This Changes

The branch adds curl connect and total-transfer time limits to both installer download helpers and adds a shell-level assertion for the new arguments.

## Best Possible Solution

Keep the 10-second connect bound, replace the global 60-second transfer cap with a stall-sensitive curl policy that permits sustained progress, cover both duplicated installer helpers, and obtain a redacted real curl transcript showing the intended timeout behavior.
