## Summary

Keep open: current main and v2026.6.11 still lack an opt-in Kubernetes ServiceAccount TokenReview auth path for autoscaled worker/node pods, the prior implementation PR is closed unmerged, and the broader distributed-runtime issues only partially cover this security-sensitive auth request.

## What This Changes

Add opt-in Kubernetes ServiceAccount/TokenReview authentication so autoscaled worker pods can connect to the gateway without interactive device pairing, plus deployment support.

## Best Possible Solution

Keep this as the canonical security/product discussion until maintainers either sponsor a narrow opt-in Kubernetes ServiceAccount Trust design or fold the auth requirement into the distributed runtime work, with fail-closed TokenReview validation and explicit namespace, service account, audience, TLS/CA, pairing-skip, tests, docs, and upgrade behavior.
