## What This Changes

The PR changes `parseProcessList` in the ACPX plugin to parse PID and PPID into locals, skip non-finite parsed values, and otherwise emit the same process record shape.

## Best Possible Solution

Land the focused ACPX-local guard after ordinary maintainer review, without expanding this PR into shared PID helper imports or unrelated ACPX cleanup changes.

## Reproduction Assessment

No. Current main lacks the proposed guard, but the parser regex only captures digit-only PID fields and downstream kill targets are filtered to positive integer PIDs, so the reported `process.kill(NaN)` path was not reproduced as a current-main failure.

## Solution Assessment

Yes as cleanup, not as a proven bug fix. Keeping the finite guard inline in the ACPX parser is the narrowest owner-boundary-preserving change, and importing shared PID helpers would add unnecessary cross-boundary coupling.
