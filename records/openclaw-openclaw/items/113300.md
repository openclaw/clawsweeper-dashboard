## Summary

Keep this PR open, but do not merge it as written. Its new call advances a process-wide cron lifecycle generation rather than cancelling the selected job, so removing one active job can change tracking for other active cron work and still does not demonstrate that the target execution is aborted.

## What This Changes

This PR makes cron removal wait for an active scheduled job to stop before deleting its stored job definition and cleanup data.

## System Context

Cron is the Gateway’s built-in scheduler: it persists job definitions, starts executions, and can deliver results to chat or other destinations. The removal operation must coordinate the selected stored job with its in-memory run ownership without disrupting unrelated scheduled executions.

## Architecture Diagram

## Best Possible Solution

Add a job-id-scoped cancellation and drain path at the cron run owner boundary, then prove with focused tests and a redacted live run that removal stops only the selected active job before its persisted definition is deleted.
