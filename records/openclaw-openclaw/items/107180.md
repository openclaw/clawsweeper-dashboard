- `P2`: The PR addresses a limited-scope but real shared channel-runtime loop that can hammer edit APIs and prevent a flush from settling.
- `merge-risk: 🚨 compatibility`: The diff changes when the exported plugin SDK `flush()` promise resolves, potentially invalidating existing caller assumptions.

## Summary

The fix is focused and source-plausible, but this external PR still needs real channel/runtime proof before merge, and a maintainer should confirm the changed completion semantics of the exported `flush()` API.

## What This Changes

Caps each draft-stream flush at 20 consecutive sends, reschedules remaining pending text through the throttle timer, and adds a continuous-replenishment regression test.

## Best Possible Solution

Land a bounded-yield implementation only after preserving or explicitly approving the exported `flush()` completion contract, adding stop-after-flush compatibility coverage, and demonstrating scheduled remainder delivery in an instrumented real channel runtime.

## Reproduction Assessment

Yes at source level: an asynchronous producer can replenish `pendingText` after every awaited send, preventing current `main` from reaching its empty-pending exit. The supplied before-fix test process also times out, although the reproduction uses a mocked sender.

## Solution Assessment

Unclear. A bounded yield is appropriate, but returning from the exported `flush()` method with pending work may not be the safest contract; separating bounded scheduled batches from explicit draining is the narrower compatibility-preserving design.
