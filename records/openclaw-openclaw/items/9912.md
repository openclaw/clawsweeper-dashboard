## Summary

The hard agent-iteration guard remains absent from current main and v2026.6.11. A proof-positive open implementation PR now owns the concrete work, so this issue should stay open until maintainers approve that PR’s opt-in round-budget contract or require broader total-call and timeout semantics.

## What This Changes

Add configurable hard limits for agent tool-calling rounds, total tool calls, and post-tool-call duration so runaway runs stop with a user-visible terminal result.

## Best Possible Solution

Adopt one opt-in typed agent-level budget enforced before the next tool-calling round, with deterministic blocked terminal metadata and a bounded text-only closeout; track total-call and elapsed-time budgets separately unless maintainers require a unified initial contract.
