## Summary

Keep open: current main and the latest release still lack a global/per-agent hard budget for model-tool turns or total tool calls. Existing loop detection, whole-run timeouts, and the OpenResponses `max_tool_calls` compatibility field are adjacent but do not implement the requested cap; https://github.com/openclaw/openclaw/pull/97485 is an open candidate, not merged.

## What This Changes

The issue requests global and per-agent configuration to cap agent model-tool iterations, total tool calls, and post-tool-call waiting time so runaway tool loops stop with a usable response.

## Best Possible Solution

Review and land, narrow, or close https://github.com/openclaw/openclaw/pull/97485 or an equivalent maintainer-approved implementation that adds opt-in global/per-agent iteration budgeting with explicit exhaustion semantics, docs, and focused embedded-runner/harness tests.

## Reproduction Assessment

No, there is not a high-confidence executable reproduction against current main from the report alone. Source inspection does confirm the requested config/runtime budget is absent, and the production log describes the user-visible runaway-loop symptom.

## Solution Assessment
