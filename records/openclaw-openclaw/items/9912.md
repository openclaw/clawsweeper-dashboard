## Summary

Keep open: current main and the latest release still lack a hard agent iteration budget; existing protections are pattern- or time-based, and the linked implementation PR remains open with unresolved counting, exhaustion, and correctness concerns. A prior maintainer review also explicitly retained this as the canonical global/per-agent request.

## What This Changes

Requests configurable agent-level turn, tool-call, and post-tool timing limits to stop runaway iterations and ensure a terminal response.

## Best Possible Solution

Adopt one typed, opt-in agent iteration-budget contract with per-agent inheritance, count calls at a single canonical agent-core boundary, block before executing the over-budget call, emit a deterministic terminal outcome, and document precedence with existing loop and timeout guards.
