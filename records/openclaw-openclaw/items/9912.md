## Maintainer Decision

Kind: product_direction

Question: Should OpenClaw add a global/per-agent hard iteration budget, and what counted unit and exhaustion behavior should become the permanent runtime contract?

Rationale: The feature adds strict public configuration and changes terminal behavior during active model-tool execution, so maintainers must choose between tool-call, tool-round, timeout, and forced-summary semantics.

Likely owner: steipete

Owner reason: The feature history and prior issue review connect this person most directly to the current loop guard and unresolved product/API decision.

Owner confidence: high

Options:

- **One hard tool-round budget (recommended):** Count each model-to-tools round once, allow default and per-agent/subagent overrides, and stop with a defined final status when exhausted.
- **Separate call and time budgets:** Expose independent total-call, round, and post-first-tool timeout controls at the cost of substantially more configuration and precedence complexity.
- **Keep heuristic guards:** Rely on loop detection and whole-run timeouts, avoiding new configuration while leaving non-repetitive runaway usage uncapped.

## Reproduction Assessment

Yes at source level: current main has heuristic loop guards and whole-run timeouts but no general hard turn or tool-call budget, and the report includes a concrete production log sequence. This review did not repeat the provider-specific run live.

## Solution Assessment

No, not exactly as proposed: central runtime enforcement is the right boundary, but one clearly defined budget unit and terminal outcome is safer than immediately adding three overlapping knobs.
