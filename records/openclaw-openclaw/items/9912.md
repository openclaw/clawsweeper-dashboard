## Summary

Keep open: current main and the latest release still lack a global/per-agent hard budget for agent tool-calling turns or total tool calls. The active implementation candidate at https://github.com/openclaw/openclaw/pull/97485 is open and not merged, so this issue remains the canonical tracker until that work lands or is replaced.

## What This Changes

Requested agent-level configuration limits for model-tool iterations and tool invocations so runaway agents stop and return a response.

## Best Possible Solution

Use the active implementation candidate or a replacement to land one opt-in typed agent iteration-budget contract that gates the next tool-calling round before execution, composes with loop detection and run timeouts, and documents deterministic exhaustion behavior.

## Reproduction Assessment

Yes for the missing capability: current strict schemas, docs, and the core agent loop show no global or per-agent hard max-turn/max-tool-call budget. The specific KIMI/NVIDIA production loop was not live-reproduced in this read-only review.
