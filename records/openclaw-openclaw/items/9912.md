## Summary

Keep open: current main and v2026.6.11 still lack a global/per-agent hard budget for model-tool turns, total tool calls, or timeout-after-first-tool-call behavior. Existing loop detection and OpenResponses `max_tool_calls` are adjacent but do not implement the requested cap, and https://github.com/openclaw/openclaw/pull/97485 is an open conflicting candidate rather than a merged fix.

## What This Changes

Request an agent-level hard limit for model-tool turns, tool-call counts, and post-tool-call timeout behavior to prevent runaway agent loops before a final response is delivered.

## Best Possible Solution

Review and either land, narrow, or close https://github.com/openclaw/openclaw/pull/97485, or an equivalent maintainer-approved implementation that adds opt-in global/per-agent iteration budgeting with explicit exhaustion semantics, docs, and focused embedded-runner/harness tests.
