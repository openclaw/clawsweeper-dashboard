## Summary

Current `main` and the latest release still do not provide a TUI `$VISUAL`/`$EDITOR` compose handoff. The issue should stay open because the missing feature is source-reproducible, the related long-prompt and vi-mode issues are adjacent rather than replacements, and the remaining blocker is maintainer product/security approval for the shortcut or command UX plus local editor/temp-file handling.

## What This Changes

Request a TUI external-editor compose mode that opens current composer text in `$VISUAL` or `$EDITOR`, then loads the edited content back without auto-submitting.

## Best Possible Solution

Approve one guarded core TUI handoff that reuses the existing suspension pattern, writes restrictive temporary markdown drafts, launches `$VISUAL` then `$EDITOR` without unsafe shell parsing, reloads edited text without auto-submit, reports failures clearly, cleans up safely, and documents the keybinding or command.
