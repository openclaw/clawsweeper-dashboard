## Summary

Keep open: current main and v2026.6.11 still lack a VISUAL/EDITOR TUI compose handoff, and the related long-prompt issues cover adjacent newline, vi-mode, or web composer ergonomics rather than this local editor round trip. The remaining blocker is maintainer direction on the trigger UX and the local process/temp-file security boundary.

## What This Changes

The issue requests a TUI external-editor compose mode that opens VISUAL or EDITOR for multiline prompt drafting and loads the edited text back without auto-submitting.

## Best Possible Solution

Keep this open for a maintainer-approved core TUI compose flow with a chosen trigger, explicit local-process and temp-file guardrails, no auto-submit, clear status/errors, public TUI docs, and focused TUI tests.
