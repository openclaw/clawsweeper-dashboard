## Summary

Keep open: current main and the latest release still lack the requested TUI external-editor compose flow, and the remaining decision is the keyboard/slash UX plus the local-process and temporary-file security boundary.

## What This Changes

The issue requests a TUI external-editor compose mode that opens `$VISUAL`/`$EDITOR` on the current draft and returns edited text without auto-submitting.

## Best Possible Solution

Keep this open for a maintainer-approved TUI implementation that suspends the TUI, writes a secure temporary markdown draft, launches `$VISUAL` then `$EDITOR`, reloads the edited text without auto-sending, reports clear errors, and documents the workflow while keeping vi/vim input-mode work separate.
