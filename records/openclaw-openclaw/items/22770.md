## Summary

Keep open. Current `main` still lacks a `openclaw tui` external-editor compose flow, the related issues are adjacent long-prompt/input-mode work rather than substitutes, and the requested local process/temp-file handoff needs maintainer UX and security-boundary signoff before implementation.

## What This Changes

The issue requests a TUI compose mode that opens `$VISUAL`/`$EDITOR` on a temporary prompt file, then reloads edited text without auto-submitting.

## Best Possible Solution

Add a guarded core TUI compose flow after maintainer signoff: suspend the TUI, write the current composer text to a private temporary markdown file, launch `$VISUAL` then `$EDITOR`, reload edited content without auto-submit, surface missing/editor-failed/file-error statuses, clean up safely, and document it in the public TUI guide while keeping vi-mode, Shift+Enter, and expand-modal requests separate.
