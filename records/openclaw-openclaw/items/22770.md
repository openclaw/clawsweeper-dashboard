## Summary

Keep open: current main and v2026.6.11 still lack a TUI `$VISUAL`/`$EDITOR` compose handoff, and the related newline, expand-modal, and vi-mode issues do not replace this request.

## What This Changes

The issue requests an external `$VISUAL`/`$EDITOR` compose mode for the TUI so users can edit long prompts in a temporary markdown file and return the result to the composer without auto-submit.

## Best Possible Solution

Approve and implement one core TUI external-editor compose path with a maintainer-approved trigger, argv-safe `$VISUAL`/`$EDITOR` resolution, restrictive temporary markdown drafts, cleanup, no auto-submit, clear status/error messages, focused tests, and public TUI docs; keep the adjacent vi, newline, and expand-modal requests separate.
