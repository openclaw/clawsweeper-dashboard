## Summary

Keep this issue open, but narrow it: current main appears to fix the missing-cost crash and therefore the normalization-triggered provider disappearance, while automatic discovery of newly released Anthropic models remains a meaningful provider-catalog product gap. ([github.com](https://github.com/openclaw/openclaw/blob/main/extensions/anthropic/register.runtime.ts))

## What This Changes

The issue reports that new Anthropic models are absent from discovery, manually configured models crash `models list`, and the resulting normalization failure hides Anthropic from the Control UI picker.

## Best Possible Solution

The Anthropic plugin should provide one resilient catalog path that merges bundled entries, configured rows, and optional provider browsing, while isolating malformed rows so one model can never suppress the provider or terminate listing.

- **Keep release-managed catalogs:** Continue shipping curated entries and forward-compatible runtime resolution, but add a lightweight independently refreshable catalog/update mechanism and clearer stale-catalog diagnostics.
- **Track discovery separately:** Close the crash portion as fixed on main and move automatic discovery into a narrower canonical feature issue before implementation.
