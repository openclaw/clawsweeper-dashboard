## Summary

Current `main` still contains the reported mismatch: `typingMode: "message"` prevents initial typing in the message and tool paths until renderable text exists, but the execution-activity path starts typing without that guard. This is a valid, narrow core bug; no merged fix or canonical replacement is established.

## What This Changes

The issue requests that execution-phase typing signals honor `typingMode: "message"` and not start channel typing before renderable assistant text exists.

## Best Possible Solution

Gate only the initial execution-activity start in message mode until renderable text is known, preserve refresh behavior for already-active typing, and add focused mode-matrix regression coverage.
