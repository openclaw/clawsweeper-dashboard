## Summary

Keep open: current main has TUI agent switching and channel `/focus` for already-existing bound subagent/ACP sessions, but it still does not provide the requested chat `/agent <id>` command for switching a channel conversation to any configured agent without restarting Gateway. The remaining work is a product and security boundary decision, not conservative cleanup.

## What This Changes

The issue requests a per-conversation chat command to list and switch the active channel-bound agent without restarting Gateway or rewriting global bindings.

## Best Possible Solution

Implement this only as a narrow conversation-binding command that reuses the existing session binding and route-resolution path, with explicit target allow/authorization semantics and no global binding rewrite or broad agent-hierarchy layer.
