## Summary

Keep open: current main still has static/default-agent channel routing, `/agents` is a thread-bound subagent/session-binding status command, and `/agent <id>` is only implemented for the TUI, so the requested channel-visible dynamic agent switch remains missing.

## What This Changes

The issue requests session-level `/agents` and `/agent <name>` commands that can temporarily switch a channel conversation to another configured agent without restarting the Gateway or changing global bindings.

## Best Possible Solution

Define a maintainer-approved, authorization-gated session-level agent switch that keeps static bindings as defaults and preserves per-agent workspace, credential, transcript, and audit boundaries.
