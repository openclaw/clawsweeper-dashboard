## Summary

Keep open: current main still lacks a channel-level `/agent <id>` command that temporarily switches a direct conversation to another configured agent. Existing `/agents` and `/focus` are thread/subagent session controls, and the TUI `/agent` command is a separate local UI path; the remaining work needs an explicit product and security decision.

## What This Changes

Request a channel chat command set that lists configured agents and temporarily switches the current conversation to another configured agent without restarting Gateway.

## Best Possible Solution

Add a maintainer-approved, opt-in conversation-level routing contract that reuses configured agent ids, enforces explicit target authorization, preserves per-agent session and memory isolation, and avoids hot-editing global bindings.
