## Summary

Keep open: current main still lacks the requested channel chat `/agent <id>` command. The existing channel command surface supports `/agents` and `/focus` for visible subagent/ACP/session bindings, while arbitrary configured-agent switching would cross workspace, auth, session, memory, and sandbox boundaries, so this needs maintainer product/security direction rather than conservative cleanup.

## What This Changes

Request a session-scoped channel chat command to list configured agents and switch the current conversation to another configured agent without restarting Gateway.

## Best Possible Solution

Add this only after maintainer approval as a narrow guarded conversation-binding command that reuses existing route-resolution/session-binding paths and explicit allow policy, not as hot edits to global `bindings`.
