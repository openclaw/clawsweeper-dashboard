## Summary

Keep open: current main still lacks the requested chat-level `/agent <id>` switch for retargeting future inbound channel messages. Existing surfaces cover TUI agent switching, Feishu auto-created per-user bindings, and `/focus` for bound sessions, but none provide the requested temporary, authorized, session-level channel agent switch without changing global bindings.

## What This Changes

The issue requests temporary chat commands to list configured agents and switch the current channel session to another agent without restarting Gateway or changing global bindings.

## Best Possible Solution

If maintainers accept the feature, implement it as a generic authorized conversation/session routing contract that can target configured agent sessions without mutating global bindings and without bypassing per-agent policy.
