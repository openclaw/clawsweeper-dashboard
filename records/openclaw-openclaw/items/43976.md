## Summary

This issue should stay open because current main still lacks the requested channel-visible `/agent <name>` command that temporarily switches a conversation to another configured agent without changing global bindings or restarting Gateway. Existing code covers static binding/default routing, TUI-local agent switching, configured-agent discovery, and thread-bound subagent/session focus, but not this channel-general routing override.

## What This Changes

The issue requests `/agents` and `/agent <name>` channel commands to switch a single conversation's active configured agent temporarily without restarting Gateway or mutating global bindings.

## Best Possible Solution

Define a guarded, session-scoped routing override that reuses configured-agent discovery and existing subagent/tool/sandbox policy, stores canonical session state, exposes typed command actions, and never mutates global bindings.
