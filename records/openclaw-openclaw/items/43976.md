## Summary

This issue should stay open: current main still has static binding/default routing plus thread-bound subagent/session focus, but no channel-visible `/agent <name>` command that temporarily switches one conversation to another configured agent without Gateway restart.

## What This Changes

Request channel commands `/agents` and `/agent <name>` to list configured agents and temporarily switch the active conversation to another agent without mutating global bindings or restarting Gateway.

## Best Possible Solution

Define a guarded, session-scoped routing override that reuses configured-agent discovery, typed command actions, existing subagent/tool/sandbox authorization, canonical session storage, and leaves global bindings unchanged.
