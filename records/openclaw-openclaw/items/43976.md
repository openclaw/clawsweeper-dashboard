## Summary

This issue should stay open because current main still has only adjacent mechanisms, not a channel-general `/agent <name>` command that temporarily switches a conversation to another configured agent without mutating global bindings or restarting Gateway. The remaining work is a product/security boundary decision, not conservative cleanup.

## What This Changes

The issue requests channel commands to list configured agents and temporarily switch the current conversation's active agent without restarting Gateway or changing global bindings.

## Best Possible Solution

Define a guarded session-scoped routing override that reuses existing agent discovery/delegation policy, stores canonical session state, exposes typed portable command actions, and never mutates global bindings.
