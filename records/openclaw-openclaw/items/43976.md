## Summary

This issue should stay open because current main still does not provide a channel-visible `/agent <name>` command that temporarily reroutes a conversation to another configured agent without changing global bindings or restarting Gateway. The existing surfaces cover static binding resolution, thread-bound subagent/session focus, and TUI-local switching, so the remaining work is a product/security decision around cross-agent session routing.

## What This Changes

The issue requests `/agents` and `/agent <name>` channel commands for temporary session-scoped switching between configured agents without restarting Gateway.

## Best Possible Solution

Define a guarded session-scoped agent-selection model, or explicitly decline it in favor of static bindings plus existing thread focus, before adding any channel command or runtime state.
