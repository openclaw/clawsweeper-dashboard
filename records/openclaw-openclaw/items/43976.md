## Summary

Keep open: current main still has TUI-local agent selection and subagent/focused-session chat commands, but no channel-level `/agent <id>` command that temporarily switches a direct conversation to another configured agent. The remaining work needs maintainer product and security direction for authorization, routing ownership, and per-agent state isolation.

## What This Changes

Request to add channel chat commands that list configured agents and temporarily reroute the current direct conversation to another agent without restarting Gateway.

## Best Possible Solution

Add an opt-in conversation-level agent routing contract that reuses configured agent ids, enforces explicit target authorization, preserves per-agent memory/session isolation, and avoids hot-editing global bindings.
