## Summary

Keep open: current main and the latest release still route channel messages through configured bindings or the default agent; channel `/agents` only reports thread-bound subagents/session bindings, while `/agent` switching exists only in the TUI, so the requested Gateway/channel feature remains missing and needs a product/security decision.

## What This Changes

Request to add channel-visible `/agents` and `/agent <name>` commands that temporarily switch the active agent for a conversation without restarting Gateway or mutating global bindings.

## Best Possible Solution

Define a maintainer-approved, authorization-gated session-level agent switch that keeps static bindings as defaults and preserves per-agent workspace, credential, transcript, audit, and recovery boundaries.
