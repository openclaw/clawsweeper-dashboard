## Summary

Keep open: current main still lacks a channel-visible, session-level agent switch; the existing `/agents` command reports thread-bound subagents/session bindings, `/agent <id>` is TUI-local, and the requested cross-agent routing behavior needs maintainer product/security direction.

## What This Changes

The issue requests channel commands `/agents` and `/agent <name>` to temporarily switch a conversation’s active agent without editing bindings or restarting Gateway.

## Best Possible Solution

Define a maintainer-approved, authorization-gated session-level agent switch that keeps static bindings as defaults and preserves per-agent workspace, credential, transcript, audit, and recovery boundaries.
