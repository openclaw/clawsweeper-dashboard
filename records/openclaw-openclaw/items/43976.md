## Summary

Keep this open: current main still lacks a channel-visible command that temporarily switches the current conversation to another configured agent, while the existing routing and focus commands cover different scopes.

## What This Changes

The issue requests `/agents` and `/agent <name>` channel commands for session-scoped agent switching without changing global bindings or restarting Gateway.

## Best Possible Solution

Define a guarded session-scoped routing override that reuses typed channel commands, canonical conversation-binding storage, and explicit configured-agent authorization while leaving global bindings unchanged.

- **Keep static routing plus focus:** Decline configured-agent switching and keep channel routing limited to bindings/defaults plus existing `/focus` session-target controls.
- **Add a plugin/API seam first:** Expose the missing generic routing hook so a channel or plugin can implement this policy without adding one-off core behavior.

Unclear until maintainers choose the authorization and persistence model; the safest implementation would extend the existing typed command and conversation-binding architecture rather than mutate global bindings from chat.
