## Summary

Keep open: current main and v2026.6.11 still support configured binding routing, TUI `/agent` switching, and thread-bound `/agents`/`/focus`, but not a channel-visible temporary `/agent <id>` switch for direct chats. The remaining work crosses agent workspace, auth, tool, memory, and session ownership boundaries, so it needs maintainer product and security direction before implementation.

## What This Changes

Request to add channel-visible `/agents` and `/agent <name>` commands that temporarily switch a direct chat's active agent without restarting Gateway or changing global bindings.

## Best Possible Solution

Add an opt-in conversation-level routing contract that targets configured agent ids, enforces explicit authorization, preserves per-agent session/auth/memory isolation, and avoids hot-editing global bindings.
