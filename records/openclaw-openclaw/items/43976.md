## Summary

Keep open: current main has configured binding routing, TUI-only agent switching, and thread-bound `/focus`/`/agents`, but it still does not provide a channel-visible `/agent <id>` temporary switch for direct chats. The remaining work needs maintainer product and security direction because it changes which agent workspace, auth profiles, tools, memory, and session store own later messages.

## What This Changes

Request a channel command that temporarily switches the current direct-chat session to another configured agent without restarting Gateway or changing global bindings.

## Best Possible Solution

Add an opt-in conversation-level routing contract that uses configured agent ids, enforces explicit target authorization, preserves per-agent session/auth/memory isolation, and avoids hot-editing global bindings.
