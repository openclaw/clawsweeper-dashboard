## Summary

Keep open: current main and the latest release still have static binding/default-agent channel routing, `/agents` is only a subagent/session-binding status command, and `/agent <id>` is implemented only for the TUI, so the requested channel-visible dynamic agent switch remains missing.

## What This Changes

Requests channel-visible `/agents` and `/agent <name>` commands to list configured agents and temporarily switch the current conversation's agent without restarting Gateway.

## Best Possible Solution

Define a maintainer-approved, authorization-gated session-level agent switch that keeps static bindings as defaults and preserves per-agent workspace, credential, transcript, audit, and recovery boundaries.
