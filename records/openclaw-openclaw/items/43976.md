## Summary

Keep open: current main still lacks the requested chat-level `/agent <id>` temporary switch for a direct conversation. Existing code covers configured routing, config hot reload, gateway/operator `agents.list`, and thread/session focus commands, but those are adjacent surfaces rather than the requested per-conversation configured-agent handoff.

## What This Changes

Request adds chat commands to list configured agents and temporarily switch the current channel conversation to a selected agent without restarting Gateway.

## Best Possible Solution

Design a permissioned current-conversation agent binding flow that reuses existing routing/session-binding seams, or explicitly narrow the request to an owner-only/operator surface before implementation.
