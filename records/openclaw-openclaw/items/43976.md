## Summary

Keep open: current main still lacks a channel-visible `/agent <id>` switch, while `/agents` remains a thread-bound subagent/session-binding status command and normal channel routing still resolves from static bindings or the default agent.

## What This Changes

The issue requests session-level channel commands to list configured agents and temporarily switch the active agent for a conversation without restarting Gateway or changing global bindings.

## Best Possible Solution

Define a maintainer-approved, authorization-gated session-level agent switch that keeps static bindings as defaults and preserves per-agent workspace, credential, transcript, and audit boundaries.
