## Summary

Keep open: current main still has thread-bound subagent focus/list commands and configured binding routing, but it does not implement the requested direct-chat `/agent <id>` temporary switch to another configured agent. The remaining work is product/security-sensitive because it changes active conversation ownership across agent workspace, tools, credentials, memory, and session state.

## What This Changes

Request a user-facing `/agents` and `/agent <id>` command flow that temporarily switches a direct channel conversation to another configured agent without restarting Gateway.

## Best Possible Solution

Add an opt-in conversation-level routing contract that uses configured agent ids, enforces explicit target authorization, preserves per-agent session/auth/memory isolation, and avoids hot-editing global bindings.
