## Summary

Keep open: current main still has configured binding routing, TUI agent switching, and thread-bound `/agents`/`/focus` behavior, but it does not implement a channel-visible `/agent <id>` temporary switch for direct chats. ## What This Changes

Request a channel command that temporarily switches the current conversation to another configured agent without editing bindings or restarting Gateway.

## Best Possible Solution

Add an opt-in conversation-level routing contract that uses configured agent ids, enforces explicit target authorization, preserves per-agent session/auth/memory isolation, and avoids hot-editing global bindings.
