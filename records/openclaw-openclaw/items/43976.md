## Summary

Keep open: current main and v2026.6.11 still lack a channel-visible configured-agent switch; existing support covers static binding/default routing, TUI-local agent switching, configured-agent RPC discovery, and thread-bound subagent focus, but not this session-scoped channel routing override.

## What This Changes

The issue requests channel-visible `/agents` and `/agent <name>` commands that temporarily switch the active configured agent for one conversation without mutating global bindings or restarting Gateway.

## Best Possible Solution

Define a guarded, channel-agnostic session routing override that reuses configured-agent discovery, stores canonical session state, enforces per-channel sender authorization, and avoids mutating global bindings.

- **Expose Plugin/Command Seam First:** Design a generic SDK or typed command action seam so channel plugins can implement visible switching only after the core policy contract exists.

Yes, at source level: current main has binding/default routing, `/focus`, `/agents` for thread-bound subagents, configured-agent RPC discovery, and TUI-local `/agent`, but no channel-native `/agent <configured-agent>` switch for the active conversation.

## Solution Assessment

Unclear until maintainers choose the product/security boundary. A session-scoped route override is closer to the request than hot-updating bindings, but it must reuse typed command actions, canonical state, and explicit authorization rather than becoming a one-channel patch.
