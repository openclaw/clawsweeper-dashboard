## Summary

Keep open: current main still routes channel messages through static bindings or the default agent, `/agents` is a subagent/session-binding status command, and `/agent <id>` exists only in the TUI. The source gap is clear, but the requested channel-visible switch needs maintainer product and security decisions before implementation.

## What This Changes

Add channel-visible commands to list available agents and temporarily switch the current conversation's agent without restarting Gateway or changing global bindings.

## Best Possible Solution

Define a maintainer-approved, authorization-gated session-level agent switch that uses canonical runtime/session state, keeps static bindings as the default fallback, and preserves per-agent workspace, credential, transcript, audit, and recovery boundaries.
