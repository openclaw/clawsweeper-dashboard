## Summary

Keep open: current main has configured binding routing, `sessions_spawn`, and thread-bound `/focus`/`/agents` flows, but it still lacks a direct-chat `/agent <id>` command that temporarily switches the active configured agent without a Gateway restart. The remaining work needs product and security direction because it would move later messages across agent workspaces, session stores, tool policy, and credentials.

## What This Changes

Request a session-scoped chat command for listing configured agents and temporarily switching the current channel conversation to another agent without changing global bindings or restarting Gateway.

## Best Possible Solution

Define a guarded, session-scoped routing design that reuses existing conversation-binding and subagent allowlist concepts where possible, keeps global `bindings[]` unchanged, and makes cross-agent workspace/auth/tool boundaries explicit before implementation.

Options:

- **Design guarded session switch (recommended):** Add a session-scoped switch only after defining sender authorization, target allowlists, transcript ownership, rollback, and channel capability rules; this is the recommended path if the feature is accepted.
- **Limit to existing focus model:** Keep `/focus` and thread-bound subagent/ACP sessions as the supported temporary-routing mechanism and document that direct configured-agent switching is intentionally unsupported.
- **Decline core command:** Leave configured agent routing to static `bindings[]`, Control UI/operator surfaces, or plugin-specific workflows where the security boundary can be owned by that integration.
