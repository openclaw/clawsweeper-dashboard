## Summary

Keep open: current main and v2026.6.11 still have thread/subagent binding controls and a TUI-local `/agent` selector, but no channel-level `/agent <id>` command that temporarily reroutes a direct conversation to another configured agent. The missing behavior is real, but implementation needs maintainer product/security direction before a fix PR.

## What This Changes

The issue requests channel chat commands to list configured agents and temporarily switch the active conversation to another configured agent without editing bindings or restarting Gateway.

## Best Possible Solution

Add an opt-in conversation-level routing contract that reuses configured agent ids, enforces explicit target authorization, preserves per-agent session and memory isolation, and avoids hot-editing global bindings as the command path.
