## Label Justifications

- `P2`: Native audio input is a useful multimodal capability gap with real user value, but it is not an outage, urgent regression, or blocked first-run path.
- `impact:session-state`: Skipping STT changes what is stored in transcripts, snapshots, replay, and audit history compared with current transcription output.
- `impact:security`: The requested behavior would forward original voice/audio bytes to model providers and needs explicit egress, retention, and audit boundaries.
- `impact:auth-provider`: The feature depends on provider/model capability routing and provider-specific native audio serialization rather than only local channel handling.

## Summary

Keep open: current main and v2026.6.11 still route batch inbound audio through transcription/text media-understanding, not native audio model-input blocks. The overlapping open implementation PR is a candidate, but it is conflicting and still has provider-contract, auth/transport, raw-media egress, session/audit, and proof blockers.

## What This Changes

The issue requests opt-in native forwarding of voice/audio attachments to audio-capable omni-modal models instead of always using speech-to-text transcription.

## Best Possible Solution

Define a shared typed native-audio attachment contract covering provider serialization, model-capability checks, explicit raw-media egress gating, payload limits, unsupported-model fallback, and transcript/session audit semantics before landing a channel-facing implementation.

## Reproduction Assessment

Yes, source-level: current main has audio.transcription outputs, transcript-text session insertion, and text/image-only normalized LLM content, so native audio blocks are not available on the active model turn path.

## Solution Assessment

No for the issue's proposed flag alone. The maintainable path is a shared provider/media/session contract with explicit egress and audit policy, then channel integration and live proof.
