## Label Justifications

- `P2`: Native inbound audio is a meaningful multimodal media/provider improvement, but it is not an urgent regression, outage, or data-loss event.
- `impact:session-state`: Skipping STT would change what session transcripts, restore, replay, and audit paths can represent.
- `impact:security`: The requested behavior would forward original voice/audio bytes to model providers and needs explicit egress and retention boundaries.
- `impact:auth-provider`: The feature depends on provider/model capability routing and provider-specific native audio serialization.

## Summary

Keep open: current main and v2026.6.11 still route inbound voice/audio through transcription text or image-only attachment paths, while native audio model input needs maintainer decisions on typed media blocks, provider routing, raw-media egress, fallback behavior, and transcript/audit semantics. The open implementation PR is a blocked candidate, not a landed fix.

## What This Changes

The issue requests opt-in native audio input for channel voice notes so omni-modal models can receive raw audio directly instead of only an STT transcript.

## Best Possible Solution

Keep this as the canonical native inbound audio tracker and converge implementation on a maintainer-approved typed audio media contract with provider serialization, explicit raw-media egress policy, fallback behavior, payload limits, and transcript/audit metadata.
