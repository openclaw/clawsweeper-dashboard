## Summary

Keep open: current main and v2026.6.11 still route inbound audio through transcription/text paths, and native audio input needs a maintainer-approved media/content, provider routing, raw-media egress, fallback, and transcript/audit contract before implementation is safe.

## What This Changes

The issue requests opt-in native forwarding of inbound voice/audio media to audio-capable omni-modal models instead of forcing STT transcription first.

## Best Possible Solution

Keep this as the canonical native inbound-audio design tracker and converge any implementation on a typed native-audio contract with explicit egress policy, provider serialization, fallback behavior, payload limits, and transcript/audit metadata.
