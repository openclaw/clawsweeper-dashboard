## Summary

## What This Changes

The issue requests opt-in native forwarding of inbound voice/audio to audio-capable omni-modal models instead of forcing transcription-first handling.

## Best Possible Solution

Define a capability-gated native audio media contract with typed content blocks, provider serialization, explicit raw-media egress policy, fallback behavior, and transcript/audit metadata, then land it through a reviewed canonical implementation path.

## Reproduction Assessment

Yes, source-level. Current main routes audio through `provider.transcribeAudio` and records `audio.transcription` text, while normalized LLM messages and tool results support text/image blocks only.
