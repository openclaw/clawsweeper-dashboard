## Summary

## What This Changes

Request to add opt-in native audio input forwarding for omni-modal models so voice notes can bypass STT transcription with safe fallback.

## Best Possible Solution

Keep this issue as the canonical product/security design tracker, then converge implementation on a typed native-audio media contract with provider serialization, explicit raw-media egress policy, fallback behavior, payload limits, and transcript/audit metadata.

## Reproduction Assessment

Yes, source-level. Current main routes audio media through audio.transcription outputs and the normalized agent/model content contracts remain text/image-only for this path, so native audio blocks have no implemented voice-note forwarding path.

## Solution Assessment

Unclear for implementation. The requested opt-in behavior is plausible, but the best fix needs maintainer decisions on typed native media blocks, provider fallback/routing, raw-media egress, and transcript/audit semantics before code should be queued.
