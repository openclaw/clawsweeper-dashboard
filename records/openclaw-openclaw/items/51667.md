## Summary

Keep open: current main and v2026.6.11 still treat inbound audio as STT/transcription media, while this issue is the canonical tracker for the unresolved native-audio content, provider, config, security, and transcript contract.

## What This Changes

Request opt-in native forwarding of inbound voice/audio attachments to audio-capable omni-modal models instead of always routing them through STT first.

## Best Possible Solution

Define a typed, opt-in native audio media contract with provider capability checks, explicit raw-media egress policy, payload limits, transcript/audit semantics, fallback behavior, schema/docs, and real channel proof before landing implementation.
