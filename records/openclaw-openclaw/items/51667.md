## Summary

Keep open: current main and v2026.6.11 still expose inbound audio as transcription-oriented media understanding, while the requested native audio path requires a maintainer decision on content contracts, provider routing, raw-media egress, fallback behavior, and transcript/audit semantics.

## What This Changes

The issue requests opt-in native audio forwarding from channel voice notes to audio-capable omni-modal models instead of always using STT transcription.

## Best Possible Solution

Keep this issue as the canonical design tracker, then converge implementation on a typed native-audio media contract with provider serialization, explicit raw-media egress policy, fallback behavior, payload limits, and transcript/audit metadata.
