- `P2`: This is a meaningful multimodal media/provider improvement with clear user value, but it is not an urgent regression, outage, or active data-loss event.

## Summary

Keep open: current main and v2026.6.11 still route inbound audio through `audio.transcription` text, and native audio forwarding needs maintainer decisions on typed media blocks, provider routing, raw-media egress, fallback behavior, and transcript/audit semantics. This issue remains the canonical tracker; the closest open PR is a blocked implementation candidate, not a landed fix.

## What This Changes

This issue asks for opt-in native forwarding of inbound voice/audio attachments to audio-capable models instead of always converting them to STT transcript text.

## Best Possible Solution

Keep this issue as the canonical product/security design tracker, then converge implementation on a typed native-audio media contract with provider serialization, explicit raw-media egress policy, fallback behavior, payload limits, and transcript/audit metadata.
