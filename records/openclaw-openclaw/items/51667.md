## Summary

Keep open: current main and v2026.6.11 still route inbound audio through transcription text, and the remaining work is a product/security/API contract decision for native audio blocks, provider routing, fallback behavior, and transcript/audit semantics.

## What This Changes

Request native voice-note/audio forwarding to omni-modal models with an opt-in config path that can skip STT and fall back to transcription when needed.

## Best Possible Solution

Define a capability-gated native audio media contract with typed content blocks, provider serialization, explicit raw-media egress policy, fallback behavior, and transcript/audit metadata before landing implementation.

## Reproduction Assessment

Yes, source-level. Current main routes audio through provider.transcribeAudio and records audio.transcription text, while normalized LLM messages and tool results support text/image blocks only.

## Solution Assessment

Unclear for implementation. The requested opt-in behavior is plausible, but the best fix needs maintainer decisions on typed content contracts, provider fallback/routing, raw-media egress, and transcript/audit semantics before code should be queued.
