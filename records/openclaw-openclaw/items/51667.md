## Summary

Keep open: current main and v2026.6.11 still route inbound audio through transcription text, while native audio model input requires maintainer decisions on typed media blocks, provider routing, raw-media egress, fallback behavior, and transcript/audit semantics. This issue remains the canonical tracker; the closest open PR is a blocked implementation candidate, not a landed fix.

## What This Changes

Request native opt-in forwarding of inbound voice/audio attachments to omni-modal models instead of always converting them through STT first.

## Best Possible Solution

Keep this as the canonical design tracker and converge implementation on a typed native-audio media contract with provider serialization, explicit raw-media egress policy, fallback behavior, payload limits, and transcript/audit metadata.
