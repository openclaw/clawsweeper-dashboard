## Summary

Keep open: current main and the latest release still treat inbound audio as transcription text, while this request needs product/security decisions for native audio content blocks, provider routing, fallback behavior, and session audit semantics.

## What This Changes

Request to send inbound voice/audio attachments directly to audio-capable omni-modal models instead of always routing them through STT transcription.

## Best Possible Solution

Define a capability-gated native audio media contract with typed content blocks, provider serialization, explicit raw-media egress policy, fallback behavior, and transcript/audit metadata, then land through the canonical implementation path.

## Reproduction Assessment

Yes, source-level. Current main routes audio through provider.transcribeAudio and records audio.transcription text, while normalized LLM messages and tool results support text/image blocks only.

## Solution Assessment

Unclear for implementation. The requested opt-in behavior is plausible, but the best fix needs maintainer decisions on typed content contracts, provider fallback/routing, raw-media egress, and transcript/audit semantics before code should be queued.
