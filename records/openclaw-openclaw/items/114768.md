## What This Changes

Replace scattered reply-visibility heuristics with a per-dispatch ledger that records settled, visible delivery before suppressing the no-visible-reply fallback.

## System Context

Reply dispatch converts agent output, routed replies, and streamed blocks into outbound channel messages. At finalization it determines whether a user-visible message was delivered and, if not, whether to send a fallback reply.

## Architecture Diagram

flowchart LR
  A[Agent turn output] --> C[Reply dispatch]
  B[Tool and block delivery results] --> C
  C --> D[Settled delivery state]
  D --> E[Visible reply decision]
  E --> F[Fallback reply gate]
  C --> G[Channel transport]
  G --> H[User-visible message]

## Best Possible Solution

Define one core settled-delivery contract with an explicit timeout, lane ownership, and observed-delivery trust rules, then replace the existing visibility inference in a focused implementation with regression coverage for suppressed finals, failed blocks, and hook-cancelled sends.
