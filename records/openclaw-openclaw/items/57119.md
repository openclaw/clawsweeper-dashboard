## Summary

Keep open. Current main still treats `skills.entries.<key>.enabled: false` as skill eligibility and prompt filtering, while `read` and `exec` remain governed by generic filesystem, sandbox, approval, and tool policy rather than a disabled-skill access-control boundary.

## What This Changes

Request to make disabled skills unreadable and non-executable instead of only hiding them from skill selection and prompts.

## Best Possible Solution

Define the disabled-skill security contract first, then enforce one central skill-access policy across prompt exposure, file tools, exec/sandbox execution, Gateway/UI status, docs, and regression tests.
