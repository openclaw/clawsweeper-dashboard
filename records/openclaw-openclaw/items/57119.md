## Summary

Keep open. Current main and v2026.6.11 still treat `skills.entries.<key>.enabled: false` as skill eligibility/prompt/status filtering, while filesystem access and `exec` remain governed by generic workspace/tool/approval policy rather than disabled-skill roots.

## What This Changes

The issue requests treating `skills.entries.<name>.enabled: false` as an enforced read and execution boundary for disabled skill directories, not only as a skill visibility toggle.

## Best Possible Solution

Define the disabled-skill security contract first, then implement one central skill-access policy reused by skill discovery, filesystem tools, `exec`, sandbox materialization, Gateway/UI surfaces, docs, and regression tests.

- **Keep visibility-only semantics:** Document that disabled skills only affect eligibility and require operators to use workspace, sandbox, and exec policy controls for isolation.
