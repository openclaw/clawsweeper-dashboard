## Summary

Keep open. Current main and v2026.6.11 still treat `skills.entries.<key>.enabled: false` as skill eligibility and prompt visibility, while read and exec access remain governed by generic filesystem, sandbox, approval, and tool policy rather than a disabled-skill deny boundary.

## What This Changes

The issue asks OpenClaw to make `skills.entries.<name>.enabled: false` block manual read and exec access to that skill directory, not just prompt auto-matching.

## Best Possible Solution

Make maintainers choose the disabled-skill security contract, then enforce it centrally across skill discovery, read/write/edit/apply_patch, exec/sandbox materialization, Gateway/UI status, docs, and focused upgrade tests.
