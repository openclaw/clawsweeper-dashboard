## Summary

Keep open. Current main and the latest release still treat `skills.entries.<key>.enabled: false` as skill eligibility/prompt filtering, while read/write/edit and exec remain governed by generic filesystem, workspace, sandbox, and approval policy rather than a disabled-skill deny boundary.

## What This Changes

The issue requests that disabled skills become an enforced filesystem and execution boundary rather than only being removed from automatic skill matching.

## Best Possible Solution

Define the disabled-skill security contract explicitly, then enforce it through a central skill-access policy reused by prompt exposure, filesystem tools, exec/sandbox execution, Gateway/UI status, docs, and regression tests.
