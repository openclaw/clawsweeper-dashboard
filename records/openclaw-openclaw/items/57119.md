## Summary

Keep open. Current main and v2026.6.11 still treat `skills.entries.<key>.enabled: false` as skill eligibility and visibility, while host read and exec access remain governed by generic filesystem, sandbox, approval, and tool policy rather than a disabled-skill access boundary.

## What This Changes

The issue requests making `enabled: false` enforce a real skill access boundary that blocks agent reads and script execution from disabled skill directories.

## Best Possible Solution

Define one maintainer-approved disabled-skill security contract and then enforce or document it consistently across skill discovery, filesystem tools, exec policy, sandbox materialization, Gateway/UI status, docs, and tests.

- **Make disabled skills a hard boundary (recommended):** Treat disabled skill directories as denied for relevant read and execution paths, with tests and docs making the stricter security semantics explicit.
