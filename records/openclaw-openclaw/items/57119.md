## Summary

Keep open. Current main and v2026.6.11 still treat `skills.entries.<key>.enabled: false` as skill eligibility and prompt/status visibility, while read and exec access remain controlled by generic filesystem, sandbox, approval, and exec policy rather than a disabled-skill access boundary.

## What This Changes

The issue requests that disabled skills become inaccessible to agent file reads and script execution, not merely hidden from automatic skill selection.

## Best Possible Solution

Define the disabled-skill security contract explicitly, then enforce one central skill-access policy across discovery/status, read/write/edit/apply_patch, exec, sandbox materialization, UI, docs, and tests.
