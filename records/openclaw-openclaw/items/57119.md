## Summary

Keep open. Current main still implements `skills.entries.<key>.enabled: false` as skill eligibility and prompt visibility filtering, while `read` and `exec` remain governed by generic filesystem, sandbox, approval, and tool-policy controls rather than a disabled-skill access boundary.

## What This Changes

Requests changing disabled skills from visibility-only entries into an enforced read and exec access boundary.

## Best Possible Solution

Define the disabled-skill security contract explicitly, then enforce it centrally or add an explicit strict isolation profile across skill discovery, file tools, exec/sandbox, UI/status, docs, and regression tests.
