## Summary

Keep open. Current main and v2026.6.11 still treat `skills.entries.<key>.enabled: false` as skill eligibility, prompt, and status filtering, while `read` and `exec` remain governed by generic filesystem, sandbox, approval, and exec policy rather than a disabled-skill access boundary.

## What This Changes

Request that disabling a skill via `skills.entries.<key>.enabled: false` also block agent reads and script execution inside that skill directory.

## Best Possible Solution

Define one central disabled-skill security contract, then enforce it consistently across skill discovery/status, read/write/edit/apply_patch, exec/sandbox materialization, Gateway/UI docs, and regression tests.
