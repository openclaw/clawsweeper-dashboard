## Summary

Keep open. Current main still treats `skills.entries.<key>.enabled: false` as skill eligibility and visibility, while read and exec access remain governed by generic filesystem, sandbox, approval, and tool policy rather than a disabled-skill access boundary.

## What This Changes

The issue requests hard read and exec denial for disabled skill directories instead of only hiding disabled skills from automatic matching and prompt visibility.

## Best Possible Solution

Maintainers should first define the disabled-skill security contract, then enforce it centrally across skill discovery, file tools, exec/sandbox materialization, UI/status, docs, and focused regression tests.
