## Summary

Keep open. Current main and the latest release still treat `skills.entries.<key>.enabled: false` as skill eligibility/status, while read and exec access are governed by generic filesystem, sandbox, tool, and exec policy rather than a disabled-skill access boundary.

## What This Changes

The issue requests that disabled skills become an enforced read and exec access boundary instead of only being removed from skill eligibility and prompts.

## Best Possible Solution

Define the disabled-skill security contract explicitly, then enforce one central skill-access policy across discovery, filesystem tools, exec/sandbox execution, Gateway/UI status, docs, and regression tests.
