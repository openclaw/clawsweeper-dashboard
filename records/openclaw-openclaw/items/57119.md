## Summary

Keep open. Current main and latest release still treat disabled skills as eligibility/prompt-hidden entries, not as a hard read or exec boundary, and the related filesystem-roots PR is only a partial overlap because it explicitly leaves exec and disabled-skill semantics unchanged.

## What This Changes

Request to make `skills.entries.<name>.enabled: false` block reading and executing files inside that skill directory, not just remove the skill from matching and prompt lists.

## Best Possible Solution

Define the disabled-skill security contract first, then enforce one central policy across skill discovery, filesystem tools, exec/sandbox paths, Gateway/UI wording, docs, and regression tests.
