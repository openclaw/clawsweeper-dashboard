## Summary

Keep open. Current main and v2026.6.11 still treat `skills.entries.<key>.enabled: false` as skill eligibility/prompt visibility, while read and exec access remain governed by generic filesystem, sandbox, approval, and tool policy rather than a disabled-skill access boundary.

## What This Changes

Request to make disabled skills inaccessible to agent file reads and script execution, not merely hidden from skill auto-matching.

## Best Possible Solution

Define the disabled-skill security contract explicitly, then enforce it through a central skill-access policy across skill discovery, filesystem tools, exec/sandbox execution, Gateway/UI status, docs, and regression tests.

- **Document current semantics only:** Clarify that disabled skills are hidden from prompt/selection only and instruct multi-user deployments to use sandboxing, tool deny lists, OS users, or containers for enforcement.
