## Summary

Keep open. Current main and the latest release still treat `skills.entries.<name>.enabled: false` as skill eligibility, prompt, and status filtering, while read and exec access remain governed by generic filesystem, sandbox, approval, and tool policy controls.

## What This Changes

Request to make `skills.entries.<name>.enabled: false` enforce a hard read/exec denial boundary for that skill directory instead of only hiding it from skill eligibility.

## Best Possible Solution

Define and document a central disabled-skill access contract, then enforce it across skill discovery, file tools, exec/sandbox behavior, Gateway/UI status, and regression tests.
