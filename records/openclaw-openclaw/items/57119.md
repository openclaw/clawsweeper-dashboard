## Summary

Keep open. Current main and the latest release still treat `skills.entries.<key>.enabled: false` as skill eligibility and prompt/status filtering, while manual `read` and `exec` access are governed by generic filesystem, sandbox, approval, and tool policy rather than a disabled-skill access boundary.

## What This Changes

The issue requests that disabling a skill also block reading or executing files inside that disabled skill directory.

## Best Possible Solution

Define the disabled-skill security contract explicitly, then enforce it through a central skill-access policy across skill discovery, filesystem tools, exec/sandbox execution, Gateway/UI status, docs, and regression tests.

- **Document current semantics only:** Clarify that disabled skills are hidden from prompt/selection only and instruct multi-user deployments to use sandboxing, tool deny lists, OS users, or containers for enforcement.
