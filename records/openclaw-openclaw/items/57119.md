## Summary

Keep open. Current main and v2026.6.11 still treat `skills.entries.<key>.enabled: false` as eligibility/prompt/status filtering, while manual `read` and `exec` remain governed by generic filesystem, sandbox, approval, and tool-policy controls rather than a disabled-skill access boundary.

## What This Changes

The issue requests that disabling a skill also block agent reads and script execution inside that skill directory.

## Best Possible Solution

Define the disabled-skill security contract explicitly, then enforce it through a central skill-access policy across skill discovery, filesystem tools, exec/sandbox execution, Gateway/UI status, docs, and regression tests.
