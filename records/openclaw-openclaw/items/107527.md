## Summary

Keep this protected security issue open for security-owner validation, but do not patch the reported ACP files: current main’s ACP server is a stdio-to-authenticated-WebSocket bridge, while the potentially relevant HTTP mutation surface is the separate, default-off `admin-http-rpc` plugin. The remaining question is whether browser-ambient trusted-proxy or no-auth deployments permit a cross-origin request to pass the plugin’s request validation and authentication.

## What This Changes

Investigate and add CSRF or browser-origin protection for local HTTP control-plane routes capable of configuration mutations.

## Best Possible Solution

Add a focused live regression harness for `admin-http-rpc` covering bearer, trusted-proxy, and explicit no-auth modes; if a browser-origin request succeeds, reject present untrusted origins while preserving documented non-browser requests with no Origin header, then cover config mutation methods and document the boundary.
