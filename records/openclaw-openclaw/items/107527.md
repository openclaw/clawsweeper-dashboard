## Summary

Keep this protected security issue open for security-owner validation. The report points at ACP files that implement a stdio-to-authenticated-Gateway-WebSocket bridge rather than the browser-facing mutation route; the relevant surface is the optional `admin-http-rpc` plugin, and current documentation already promises generic browser-Origin enforcement, but the provided evidence does not prove that every `trusted-proxy` and explicit `none` deployment rejects a cross-site simple request before dispatch. citeturn232339search0turn564510search1turn841903search1

## What This Changes

Validate and, if necessary, add cross-site request protection for browser-reachable local administrative HTTP mutations.

## Best Possible Solution

Keep one centralized Gateway-authenticated plugin-route guard that rejects unapproved browser origins before dispatch, then prove it with focused request tests covering bearer/password, trusted-proxy, and explicit `none` modes plus simple-form and JSON requests; add a route-specific nonce only if that matrix demonstrates a real gap.
