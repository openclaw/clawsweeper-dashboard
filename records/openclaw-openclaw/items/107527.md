## Summary

Keep this protected security issue open for security-owner validation, but do not patch the named ACP files: current main documents ACP as a stdio-to-authenticated-Gateway-WebSocket bridge, while the relevant configuration-mutation surface is the separate, default-off `admin-http-rpc` plugin behind Gateway HTTP authentication. The remaining security question is whether a browser request can bypass shared origin enforcement in trusted-proxy or no-auth deployments.

## What This Changes

Validate and, if necessary, add cross-origin request protection for browser-reachable HTTP routes that can mutate OpenClaw configuration.

## Best Possible Solution

Reproduce the request against the default-off `admin-http-rpc` plugin under bearer-token, trusted-proxy, and no-auth configurations; if a bypass exists, fix the shared Gateway-authenticated plugin-route boundary and add focused origin-policy coverage rather than changing ACP transport code.
