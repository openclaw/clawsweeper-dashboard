## Summary

Keep this protected security issue open for explicit security-owner confirmation. Current source does not support the named ACP attack path: one cited file does not exist, while `src/acp/server.ts` is a stdio NDJSON bridge rather than an HTTP server; configuration mutations normally use authenticated Gateway RPC, though the optional admin HTTP RPC plugin creates a separate route whose intended CSRF boundary still merits confirmation. ([github.com](https://github.com/openclaw/openclaw/tree/main/src/acp/control-plane))

## What This Changes

Determine whether browser-originated requests can execute configuration-changing control-plane operations without adequate origin or anti-CSRF validation.

## Best Possible Solution

All browser-reachable control-plane mutations should pass the canonical Gateway authentication, scope, and explicit-origin boundary; add a token check only if security owners identify a concrete authenticated route where that boundary is insufficient, without changing ACP's stdio or WebSocket transports.
