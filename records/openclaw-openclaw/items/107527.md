## Summary

Keep this protected security issue open for focused validation, but do not implement the proposed ACP patch yet. Current main documents ACP as a stdio-to-Gateway WebSocket bridge, while the actual HTTP configuration surface is the separate, default-off, Gateway-authenticated admin HTTP RPC plugin. The report provides neither an exact current-main endpoint nor a successful cross-origin mutation. Likely related people: @osolmaz for the original ACP control-plane work and @steipete for recent Gateway configuration and security-boundary work; routing confidence is medium.

## What This Changes

Investigate and, if confirmed, add CSRF defenses to local control-plane configuration-mutation routes.

## Best Possible Solution

Reproduce the actual `/api/v1/admin/rpc` route from a hostile browser origin under each supported auth mode; if an unauthenticated simple request can mutate configuration, enforce a centralized origin or explicit anti-CSRF contract on state-changing Gateway HTTP routes and add browser-level regression coverage.
