## Summary

Keep this protected security issue open for explicit security-owner review. The named ACP files implement a stdio/NDJSON bridge rather than the reported HTTP control plane, but the separate default-off admin HTTP RPC plugin exposes authenticated mutation methods, and current policy intentionally supports both `auth.mode="none"` and origin-less automation. Existing origin guards cover adjacent browser paths without conclusively settling that combination.

## What This Changes

Determine whether browser-originated requests can invoke local administrative HTTP mutations without adequate CSRF or origin validation, and harden the applicable route.

## Best Possible Solution

Apply the shared browser-request policy at the actual administrative HTTP route before body parsing or method dispatch: reject cross-site browser origins and unsafe browser-simple mutation requests, preserve origin-less non-browser automation using the established Fetch Metadata/origin pattern, and cover token, trusted-proxy, and no-auth modes with focused live and regression proof.
