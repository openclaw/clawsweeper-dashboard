## Summary

Keep this protected security issue open for focused security-owner validation. The report points at ACP stdio bridge files rather than the browser-reachable Gateway HTTP route, but current documentation promises browser-origin enforcement for gateway-authenticated plugin routes, so the remaining question is whether the shipped generic route gate actually rejects cross-site simple POST requests in every supported auth mode.

## What This Changes

Validate and, if necessary, add origin or CSRF defenses for browser-origin requests reaching local control-plane HTTP mutations.

## Best Possible Solution

Test the enabled admin-http-rpc route with hostile Origin and Sec-Fetch-Site headers under token, password, trusted-proxy, and explicit no-auth configurations; if any browser-origin request reaches dispatch, reject it once in the generic gateway-auth plugin route boundary with focused same-origin, allowed-origin, loopback-origin, and host-automation regression coverage.

## Maintainer Decision

Question: Should all Origin-bearing gateway-authenticated plugin HTTP requests be required to pass the Control UI origin policy, including explicit auth.mode="none" private-ingress deployments?

Rationale: The repository documents origin enforcement for trusted-proxy browser requests, but the permanent policy for explicit no-auth private ingress affects both browser security and supported non-browser automation and therefore needs an owner-confirmed boundary.

Likely owner: steipete

Owner confidence: medium

Options:

- **Enforce on every browser-origin request (recommended):** Apply the shared origin check whenever Origin or browser fetch metadata is present, while leaving requests without browser headers available to trusted host automation.
- **Limit enforcement to identity-bearing auth:** Keep token/password protected by bearer authentication and enforce origin only for trusted-proxy requests, documenting auth.mode="none" as fully ingress-owned.
- **Require per-route anti-CSRF tokens:** Add a separate nonce contract to mutable plugin HTTP routes, increasing client and compatibility cost beyond the existing origin and bearer model.

## Reproduction Assessment

No. The report does not provide a current-main request, auth mode, headers, response, or dispatched method, and the named ACP files are not the browser HTTP route; source and docs narrow the test to the optional admin-http-rpc Gateway route.

## Solution Assessment

No, not as proposed. Adding CORS or CSRF checks inside the ACP stdio bridge would target the wrong owner boundary; any confirmed fix should be centralized in the Gateway's generic gateway-authenticated plugin HTTP route gate.
