## Summary

Keep this protected security issue open for security-owner validation. The named ACP files are a stdio-to-Gateway-WebSocket bridge rather than the browser-facing mutation endpoint; the relevant surface is the optional `admin-http-rpc` plugin. Current documentation says browser-origin requests must pass the Gateway origin allowlist, but the available evidence does not demonstrate that cross-site simple POST requests are rejected before dispatch under every supported `trusted-proxy` and explicit `none` configuration.

## What This Changes

Require effective origin or anti-CSRF enforcement for browser requests that can mutate configuration through local control-plane HTTP routes.

## Best Possible Solution

Verify the real Admin HTTP RPC endpoint with cross-site simple and preflighted POST requests under token, trusted-proxy, and explicit `none` modes; if any path reaches body parsing or dispatch, enforce the shared Gateway origin gate before authentication and dispatch and add mode-specific regression coverage.
