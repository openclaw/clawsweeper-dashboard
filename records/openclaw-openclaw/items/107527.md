## Summary

Keep this protected security issue open for explicit security-boundary review. The reported ACP files are not browser-facing HTTP route owners, and current documentation says browser-origin Gateway HTTP requests are already checked against the configured origin policy, but the available evidence does not prove complete coverage for every enabled state-changing HTTP handler. ## What This Changes

Determine whether browser-originated requests can reach state-changing local Gateway control-plane HTTP operations without origin or anti-CSRF validation.

## Best Possible Solution

Audit enabled state-changing Gateway HTTP handlers across token, password, none, and trusted-proxy modes; reject disallowed browser origins at the shared HTTP-auth boundary before dispatch while preserving authenticated non-browser clients, and add focused cross-origin acceptance and rejection tests.
