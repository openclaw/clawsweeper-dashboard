## Summary

Keep it open because the external-contributor merge gate still lacks after-fix proof from a real configured memory search.

## What This Changes

The PR trims built-in memory search queries at entry, returns `[]` for blank input before provider/index bootstrap, and adds manager-level regression coverage.

## Best Possible Solution

Keep the early trimmed-query eligibility guard at the built-in backend entry point, preserve the existing debug callback, and land it after redacted real-runtime evidence confirms whitespace-only search returns `[]` without provider initialization or index bootstrap.
