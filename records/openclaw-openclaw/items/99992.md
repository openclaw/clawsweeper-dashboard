## What This Changes

The branch adds a 1 MiB `ws` `maxPayload` option to both Signal container receive WebSocket constructors and updates tests to assert the option.

## Best Possible Solution

## Solution Assessment

Yes. Passing `maxPayload` at the two owner-local Signal container receive constructors is the narrow enforcement point; the remaining question is maintainer acceptance of the 1 MiB cap value, not a code-layer defect.
