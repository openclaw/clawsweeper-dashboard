## Summary

Keep open: current main still normalizes only inline directive tags on the Telegram prompt-context dedupe and timestamp-handoff path, so Markdown-formatted transcript text can still mismatch Telegram cache text. The active same-author candidate fix is https://github.com/openclaw/openclaw/pull/102259, so this issue should stay paired with that review instead of spawning a duplicate repair lane.

## What This Changes

Telegram prompt-context dedupe should normalize Markdown formatting differences between raw transcript text and Telegram cache text so the same assistant reply is not injected twice.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/102259 or an equivalent narrow fix that applies shared delivery-visible Markdown normalization on both timestamp handoff and dedupe-key generation, with redacted hidden prompt-context proof showing one assistant row.

## Reproduction Assessment

Yes, at source level. Current main stores and compares Telegram prompt-context text after directive-only normalization, so a raw Markdown transcript body and Telegram-stripped cache body can produce different timestamp-qualified dedupe keys.

## Solution Assessment

Yes on direction, with implementation care. The best fix is shared visible-text normalization on both timestamp alignment and dedupe-key surfaces, preferably using the existing stripMarkdown helper rather than a custom character-stripping regex.
