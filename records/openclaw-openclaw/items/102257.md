## Summary

Keep open: current main still normalizes Telegram prompt-context dedupe only for inline directive tags, so Markdown-formatted transcript text can miss the Telegram cache row. The active candidate fix is https://github.com/openclaw/openclaw/pull/102259, so this issue should stay paired with that review instead of spawning a separate repair lane.

## What This Changes

Reports duplicate Telegram assistant prompt-context rows when raw Markdown transcript text is compared with Telegram-stripped cache text during dedupe.

## Best Possible Solution

Land a narrow fix through https://github.com/openclaw/openclaw/pull/102259 or equivalent that applies shared delivery-visible normalization to both timestamp alignment and dedupe keys, with proof that one assistant row reaches Telegram prompt context.

## Solution Assessment

Yes on direction, with implementation care. The best fix is shared visible-text normalization on both timestamp alignment and dedupe-key surfaces while preserving timestamp-qualified matching, not a new setting or broader fuzzy dedupe policy.
