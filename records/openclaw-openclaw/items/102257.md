## Summary

Keep open: current main still normalizes only inline directive tags on the Telegram prompt-context dedupe path, so the Markdown-formatting mismatch remains source-reproducible. The open same-author PR at https://github.com/openclaw/openclaw/pull/102259 is the candidate fix, so this issue should stay paired with that review rather than spawning a separate repair lane.

## What This Changes

The issue requests Markdown-aware normalization for Telegram prompt-context dedupe when the session transcript keeps raw Markdown but the Telegram cache stores rendered plain text.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/102259 or an equivalent narrow fix that shares delivery-visible Markdown normalization across timestamp handoff and dedupe-key generation, with regression proof that one assistant row reaches prompt context.

Yes, at source level. Current main stores and compares Telegram prompt-context text after directive-only normalization, so a raw Markdown transcript body and Telegram-stripped cache body can produce different timestamp-qualified dedupe keys.

## Solution Assessment

Yes on direction, with implementation care. The best fix is a narrow shared visible-text normalization on both timestamp alignment and dedupe-key surfaces, not a new setting or broader text-only matching policy.
