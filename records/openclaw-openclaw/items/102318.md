## Label Justifications

- `P2`: This is a source-backed settings bug with limited blast radius that can change provider request timeout and retry behavior for users who split `retry.provider` fields across scopes.
- `impact:other`: The concrete impact is provider retry/timeout policy drift from configured settings, which is meaningful but does not fit the narrower owned impact labels.

## Summary

Keep open: current main and the latest release still shallow-merge nested settings objects, so split `retry.provider` fields can still lose sibling timeout/retry settings. Three open PRs already reference this issue as candidate fixes, so the issue should stay open until one lands or maintainers choose a different fix path.

## What This Changes

Settings scope merging should preserve sibling `retry.provider` fields when different settings scopes set different provider retry options.

## Best Possible Solution

Land one focused PR that recurses through plain nested settings objects and proves `retry.provider` fields merge across global, project, and runtime scopes without changing array or primitive override semantics.
