## Summary

Keep open: current main and the latest release still shallow-merge nested settings objects, and three open linked PRs are candidate fixes rather than a reason to close the issue before merge.

## What This Changes

The issue reports that split-scope `retry.provider` settings lose sibling fields because nested settings objects are shallow-merged.

## Best Possible Solution

Land one narrow recursive merge fix that preserves primitive and array override semantics and proves global, project, and runtime `retry.provider` fields merge field-by-field.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. The current source still assigns `{ ...baseValue, ...overrideValue }` for nested objects, so a project `retry.provider` object replaces the lower-precedence provider object before `getProviderRetrySettings()` reads it.

## Solution Assessment

Yes. Recursing in the existing shared merge helper is the narrowest maintainable fix because global/project/runtime layering already funnels through `deepMergeSettings`; tests must lock down array and primitive override behavior.
