## Summary

Keep open: current main and the latest release still shallow-merge nested settings objects, so split `retry.provider` settings can still lose sibling timeout/retry fields before provider requests.

## What This Changes

The issue requests that `retry.provider` fields from global, project, and runtime settings scopes merge field-by-field instead of clobbering sibling fields.

## Best Possible Solution

Make `deepMergeSettings` recurse for plain nested objects and add focused `SettingsManager` coverage proving `retry.provider` fields survive global/project/runtime scope splits.
