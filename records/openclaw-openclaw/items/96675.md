## Summary

Keep open. Current main has adjacent memory source metadata, external-content warnings, tool approval hooks, and reviewable dreaming output, but it still lacks the requested owner-confirmed lifecycle for making assistant or skill outputs durable memory, reusable evidence, revocable rules, or future context.

## What This Changes

The issue requests optional owner-signed responsibility gates before assistant outputs, skill results, memories, and evidence become durable or reusable state.

## Best Possible Solution

Define one maintainer-approved responsibility/trust contract that coordinates existing approval hooks, memory provenance, dreaming promotion, and plugin SDK seams, adding core/plugin API only where current plugin or ClawHub paths cannot represent the durable lifecycle.
