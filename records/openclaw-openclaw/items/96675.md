## Summary

Keep open. Current main still has adjacent exec/plugin approvals, external-content wrappers, Skill Workshop proposal gates, and memory provenance guidance, but it does not provide the requested durable owner-confirmed lifecycle for promoting assistant or skill output into persistent memory, reusable evidence, revocable rules, or future context; the linked UMP and SCBKR discussion is useful design input rather than a reason to close core security/product work.

## What This Changes

The issue requests optional owner-signed confirmation gates before assistant outputs, skill results, memories, or evidence become persistent or reusable context.

## Best Possible Solution

Define a maintainer-approved responsibility/trust contract that coordinates existing approvals, Skill Workshop proposals, memory/wiki provenance, and plugin APIs, adding core state only where current seams cannot represent owner confirmation.
