## Summary

Keep open. Current main has adjacent plugin approvals, input provenance, external-content wrapping, and memory search/index contracts, but it still does not provide the requested owner-confirmed durable lifecycle for promoting assistant or skill outputs into persistent memory, reusable evidence, revocable rules, or future context.

## What This Changes

The issue requests optional owner-signed confirmation and reuse-policy gates for persistent memory, skill/action outputs, external messages, file modifications, credential-related actions, and reusable evidence.

## Best Possible Solution

Define a maintainer-approved responsibility/trust contract that coordinates existing approval hooks, memory/plugin APIs, and provenance markers with durable owner-confirmed reuse state, adding core or plugin API only where current seams cannot represent it.
