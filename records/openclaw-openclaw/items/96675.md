## Summary

Keep open: current main and v2026.6.11 have adjacent provenance, approval, external-content, and memory guidance, but they still do not implement owner-confirmed durable lifecycle states for promoting assistant or skill output into persistent memory, reusable evidence, rules, or future context.

## What This Changes

The issue requests optional owner-signed responsibility gates and reuse-policy states for assistant memory, actions, skills, and reusable evidence.

## Best Possible Solution

Define a maintainer-approved responsibility and trust lifecycle contract that coordinates existing approval hooks, memory provenance, Skill Workshop, and plugin APIs, adding core or SDK surface only where current seams cannot represent owner-confirmed reuse state.
