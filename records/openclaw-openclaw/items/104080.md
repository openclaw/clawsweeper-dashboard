## Summary

Current main has the reported admission gap: reconnect recovery can remain active outside the Gateway root-work registry while suspension reports ready. The issue is necessary, narrowly actionable, and not covered by the broader lifecycle-telemetry proposal.

## What This Changes

Add Gateway root-work admission for Telegram and WhatsApp reconnect delivery drains so suspension cannot become ready during active recovery.

## Best Possible Solution

Admit the shared reconnect drain as independent Gateway root work, preserving immediate suspendability for dormant rows while testing in-flight blocking, prepared-state fencing, and release on rejection or error.
