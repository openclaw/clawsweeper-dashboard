Keep open: current main and the latest release still reject Synology Chat HEAD probes and still acknowledge accepted POST webhooks with 204/no body. ## What This Changes

Synology Chat webhook handling should accept HEAD liveness probes and return HTTP 200 with {"success":true} for accepted POST ACKs instead of 204/no body.

## Best Possible Solution

Land or replace the focused Synology Chat fix so the plugin accepts HEAD probes and returns 200 {"success":true} for accepted POST ACKs while preserving POST token validation, allowlist checks, rate limits, invalid-token throttling, and in-flight guards.
