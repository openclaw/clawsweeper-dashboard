Keep open: current main and v2026.6.11 still reject Synology Chat HEAD probes and still acknowledge accepted webhook POSTs with 204/no body, while the focused fixing PR at https://github.com/openclaw/openclaw/pull/53441 is open but not merged.

## What This Changes

The issue asks Synology Chat webhook handling to accept HEAD probes and acknowledge successful POSTs with 200 plus a JSON success body.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/53441, or explicitly supersede it with a narrow replacement that keeps the change inside the Synology Chat plugin, accepts HEAD probes, returns 200 {"success":true} for accepted POST ACKs, and preserves token validation, allowlist checks, rate limiting, invalid-token throttling, and in-flight guards.

## Solution Assessment

Yes in direction, but not by closing this issue yet. The narrow maintainable fix belongs in the Synology Chat webhook handler and tests, with the linked PR or a replacement preserving current POST safeguards.
