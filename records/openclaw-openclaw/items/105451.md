## Summary

This is a plausible gateway resilience improvement, but current main already applies per-account exponential backoff with jitter and intentionally starts a fresh recovery cycle after those retries are exhausted. The remaining question is narrower: whether same-cycle recovery launches need bounded cross-account staggering, which requires maintainer intent and timing evidence rather than an unconditional second exponential retry policy.

## What This Changes

Add staggered jitter and exponential backoff to Channel Health Monitor recovery restarts so multiple unhealthy channels or accounts do not reconnect in a burst.

## Best Possible Solution

Measure same-cycle recovery launch timing, then add bounded jitter only at the shared health-monitor dispatch boundary if starts can bunch, while preserving ChannelManager as the sole owner of exponential retry state and resetting the stagger after stable recovery.
