## Label Justifications

- `P2`: This is a normal-priority Android/gateway session-management improvement with bounded blast radius but real compatibility and authorization review needs.
- `merge-risk: 🚨 compatibility`: The Android client sends a new strict-schema RPC field while the gateway protocol version remains unchanged, so older compatible gateways can reject archived deletes.
- `merge-risk: 🚨 security-boundary`: The gateway would newly allow `operator.write` clients to delete archived sessions through `sessions.delete`.

## Summary

Keep open: the archive-gated delete direction is useful, but this PR is not merge-ready because Android sends a new strict-schema RPC parameter while the gateway protocol version stays unchanged, and the write-scoped delete boundary needs maintainer acceptance.

## What This Changes

The PR adds an `archivedOnly` `sessions.delete` parameter, makes `sessions.delete` dynamically authorize write-scoped archived deletes, keeps the kill HTTP endpoint admin-only, and updates Android to delete only archived rows with that flag.

## Best Possible Solution

Land archive-gated write-scope deletes only after adding a protocol/version or capability gate that prevents Android from sending `archivedOnly` to gateways that do not support it, with maintainer approval for the write-scope delete boundary.
