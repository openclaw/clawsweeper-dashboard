## Summary

The ownership cleanup is plausible, but the issue does not identify a specific hardcoded OAuth value, blocked provider, or caller that existing provider-auth and transport hooks cannot handle. Current main already provides OAuth login, refresh, runtime-auth, parameter-normalization, stream-wrapping, and transport-policy seams, while the published `@openclaw/ai` contract deliberately keeps provider credentials outside `AiTransportHost`; a provider/transport owner should confirm the missing seam before implementation.

## What This Changes

Extract provider-specific OAuth flow parameters from the LLM transport core into an injectable configuration contract used by the transport host.

## Best Possible Solution

Name the concrete parameter and blocked consumer, then keep provider-specific values in existing provider hooks; add a generic `AiTransportHost` port only if the value is demonstrably shared host policy with focused provider and library-consumer tests.
