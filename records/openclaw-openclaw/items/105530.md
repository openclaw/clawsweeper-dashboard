## Summary

Current main and v2026.6.11 still combine shared managed skills with a workspace-only ClawHub lock and install-root check, so this is a real bounded status bug with no canonical fix found.

## What This Changes

Prevent globally installed ClawHub skills from being falsely shown as invalid because skill status checks only the selected workspace’s ClawHub lockfile.

## Best Possible Solution

Resolve ClawHub linkage against each skill’s owning install scope, preserving all origin, registry, version, provenance, and expected-directory checks while adding global and cross-scope isolation regressions.

## Solution Assessment
