## Label Justifications

- `P1`: The report describes a broken Slack channel workflow where inbound user messages can be silently lost after gateway restarts while the gateway still appears healthy.
- `impact:message-loss`: The central symptom is inbound Slack events being routed to dead Socket Mode connections instead of the live OpenClaw gateway.

## Summary

Keep open: current main detects and warns about shared Slack Socket Mode connections, and it attempts graceful stop on abort, but it still does not prevent or recover the reported restart ghost-connection message-loss mode.

## What This Changes

The issue reports Slack Socket Mode ghost connections after gateway restarts causing inbound Slack messages to be silently dropped while outbound Slack sends still work.

## Best Possible Solution

Add a Slack-plugin-owned restart-ghost detection or recovery path with live Slack proof that stale same-gateway connections stop stealing events, while preserving documented multi-gateway, relay, and HTTP deployment choices.
