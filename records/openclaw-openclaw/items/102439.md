## Label Justifications

- `P1`: The report describes a broken Slack channel workflow where inbound user messages can be silently lost after gateway restarts while the gateway still appears healthy.
- `impact:message-loss`: The central symptom is Slack inbound events being delivered to dead Socket Mode connections instead of the live OpenClaw gateway.
- `impact:ux-friction`: The workaround requires an operator to stop the gateway, wait for Slack to time out old connections, and restart cleanly.

## Summary

Keep open: current main detects and warns about shared Slack Socket Mode connections and has local shutdown hardening, but it still does not prevent or recover the reported restart ghost-connection path; a direct fix needs live Slack proof and maintainer policy because multiple active Socket Mode connections are also a supported deployment pattern.

## What This Changes

The issue asks OpenClaw to stop Slack Socket Mode restart ghost connections from silently stealing inbound events after gateway restarts.

## Best Possible Solution

Add a Slack-plugin-owned restart-ghost recovery or fencing path only after live Slack proof, while preserving documented multi-gateway choices through relay, HTTP Request URLs, or explicit operator policy.
