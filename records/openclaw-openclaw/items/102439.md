## Summary

Keep open: current main has Slack Socket Mode shared-connection diagnostics and recovery-stop hardening, but it does not yet solve the reported restart ghost-connection loss mode or distinguish stale restart ghosts from intentional multi-gateway Socket Mode deployments. Slack's own Socket Mode docs support the reported failure mode because payloads may go to any active connection when multiple WebSockets are open. ([docs.slack.dev](https://docs.slack.dev/apis/events-api/using-socket-mode?utm_source=openai))

## What This Changes

The issue reports Slack Socket Mode ghost connections after gateway restarts causing silent inbound message loss while outbound Slack sends still work.

## Best Possible Solution

Add a Slack-plugin-owned restart recovery path that turns suspected stale same-app Socket Mode connections into an explicit degraded/retry or user-facing recovery state, while preserving the documented relay, HTTP, and separate-app paths for intentional multi-gateway deployments.
