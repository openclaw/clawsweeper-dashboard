## Summary

Keep open for maintainer product/API decision: current main still supports only one heartbeat model override for the whole heartbeat turn, while related plugin routing covers whole-turn policy and the open cron issue covers a different scheduled-job contract.

## What This Changes

The issue requests per-task model hints in HEARTBEAT.md so selected heartbeat tasks can use a different model than the run-level heartbeat.model.

## Best Possible Solution

Maintainers should choose the permanent contract first: document whole-turn plugin routing, fold scheduled model overrides into the cron/job-level path, or define native HEARTBEAT.md task model fields with task-splitting semantics.
