- `P2`: This is a useful scheduled-automation model-routing feature with cost and quality impact, but it is not an urgent outage or first-run blocker.
- `impact:session-state`: The motivating workaround is sub-agent delegation losing shared memory context, and any native fix must avoid leaking task-specific model state into the shared session.
- `impact:auth-provider`: The request directly changes model/provider selection for heartbeat task execution.

## Summary

Keep open for a product/API decision: current main supports one heartbeat model per heartbeat turn, not per HEARTBEAT.md task, and the existing plugin hook can route a whole turn but cannot selectively re-run one due task on a different model.

## What This Changes

Requests a HEARTBEAT.md task-level model hint or escalation marker so high-quality periodic tasks can use the primary model while routine heartbeat tasks use a cheaper model.

## Best Possible Solution

Maintainers should choose one permanent contract: document whole-turn plugin routing, fold scheduled model selection into the cron/job-level override track, or implement native HEARTBEAT.md task model fields with explicit precedence, validation, session-state cleanup, docs, and regression coverage.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw support native per-task model hints in HEARTBEAT.md, or should heartbeat model routing remain per-turn and be handled through plugins or the cron/job-level override track?

Rationale: The missing capability is source-proven, but the fix changes public task-file syntax, provider/model precedence, and session-state behavior, so automation should not choose the product contract.

Likely owner: steipete

Owner reason: steipete has the strongest product-boundary signal from prior dynamic model-routing decisions and the hook split that defines the current plugin seam.

Owner confidence: medium

Options:

- **Fold into scheduled-job routing (recommended):** Use the open cron/job-level model override track as the canonical scheduled-work model selection path and avoid adding another HEARTBEAT.md-specific syntax until cron and heartbeat semantics converge.
- **Add native task hints:** Define model/provider fields in HEARTBEAT.md tasks and split due-task execution by effective model with explicit timestamp and session-state rules.
- **Keep whole-turn plugin routing:** Document that heartbeat ticks are one model-routed turn and that before_model_resolve or ClawHub plugins may escalate the whole run, not individual tasks.

## Reproduction Assessment

Yes, source-level: current main parses only name/interval/prompt task data, batches due HEARTBEAT.md tasks into one prompt, and applies at most one heartbeat model override for the whole turn.

## Solution Assessment

Unclear until maintainers choose the product contract; native task hints would solve the exact request, while whole-turn plugin routing and the cron override track may be cleaner boundaries.
