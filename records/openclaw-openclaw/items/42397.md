## Summary

Keep open: current main and v2026.6.11 still only support a run-level heartbeat model, while due `HEARTBEAT.md` tasks are parsed as name/interval/prompt and grouped into one heartbeat turn. This remains a product/API decision because task-level model hints would add public heartbeat metadata and routing semantics.

## What This Changes

Add a per-task model hint or override in `HEARTBEAT.md` so selected heartbeat tasks can run on a different model than the run-level `heartbeat.model`.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level `heartbeat.model` while specifying syntax, split-or-group execution, alias/fallback/auth behavior, docs, and focused tests.

## Reproduction Assessment

Yes at source level for the missing capability: current main parses heartbeat tasks as `name`/`interval`/`prompt`, batches due tasks, and forwards one run-level `heartbeatModelOverride`. This is not a broken-behavior repro; it is a feature gap confirmed from source and docs.

## Solution Assessment

Unclear: a `HEARTBEAT.md` model hint is plausible, but the best fix needs maintainer choice on syntax, alias/fallback behavior, and whether due tasks should be split or grouped by model.
