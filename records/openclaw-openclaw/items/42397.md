## Summary

Keep open: current main and v2026.6.11 still support only a run-level heartbeat model override, while due `HEARTBEAT.md` tasks are parsed as `name`/`interval`/`prompt` and batched into one heartbeat turn. This remains a product/API decision because per-task model hints require public heartbeat task metadata plus split/grouped execution semantics.

## What This Changes

Request per-task model hints in `HEARTBEAT.md` so selected heartbeat tasks can run on a different model than the run-level `heartbeat.model`.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level `heartbeat.model`, including syntax, split-or-grouped execution semantics, alias/fallback/auth behavior, docs, and focused tests.
