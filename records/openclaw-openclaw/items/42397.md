## Summary

Keep open: current main and v2026.6.11 still only support run-level heartbeat model selection, while HEARTBEAT.md task mode parses and batches tasks without task-level model metadata. This remains a heartbeat/model-routing product and config-contract decision, not conservative cleanup.

## What This Changes

Request per-task model hints in HEARTBEAT.md so selected heartbeat tasks can use a different model than the run-level heartbeat.model setting.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level heartbeat.model while specifying syntax, split-or-grouped execution, alias/fallback/auth behavior, docs, and focused tests.

## Maintainer Decision

Question: Should OpenClaw add task-level model metadata to HEARTBEAT.md, or should heartbeat task routing be handled through a broader per-turn/plugin model-routing contract?

Rationale: The missing behavior is clear, but implementation depends on maintainer intent for public HEARTBEAT.md syntax, task batching versus split turns, and how model overrides compose with provider auth, fallbacks, and session state.

Owner confidence: high

Options:

- **Design shared routing contract first (recommended):** Keep this issue open and decide a reusable heartbeat or per-turn routing contract before accepting HEARTBEAT.md-only syntax.
- **Add heartbeat-only task metadata:** Implement a narrow HEARTBEAT.md task model field with explicit split/group semantics, alias/fallback rules, docs, and compatibility tests.
- **Keep routing plugin-owned:** Document whole-turn before_model_resolve plugins as the supported routing path and accept that multiple due heartbeat tasks cannot be independently routed today.

## Reproduction Assessment

Yes, source-level: current main parses heartbeat tasks as name/interval/prompt, batches all due tasks into one prompt, and forwards one heartbeatModelOverride for the whole run. This is a missing feature contract rather than a broken existing behavior path.

## Solution Assessment

Unclear: a HEARTBEAT.md model hint is plausible, but the best fix needs maintainer choice on syntax, alias/fallback behavior, and whether due tasks should be split or grouped by model.
