## Summary

Keep open: current main and v2026.6.11 still only support a single run-level heartbeat model override, while `HEARTBEAT.md` tasks are parsed as `name`/`interval`/`prompt` and batched into one heartbeat turn. The request remains a real heartbeat task model-routing product/API decision, not conservative cleanup.

## What This Changes

The issue requests a `HEARTBEAT.md` task-level model hint or escalation keyword so selected heartbeat tasks can use a different model than the run-level `heartbeat.model`.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level `heartbeat.model` and specifies syntax, split-or-grouped execution, alias/fallback/auth behavior, docs, and focused tests.
