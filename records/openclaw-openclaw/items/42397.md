## Summary

Keep open: current main and v2026.6.11 still have only a single run-level heartbeat model override, while due HEARTBEAT.md tasks are parsed as name/interval/prompt and batched into one heartbeat turn. The existing before_model_resolve plugin route and @glasshousehq/openclaw-routing-yaml are useful whole-turn routing paths, but they do not independently route multiple due heartbeat tasks inside the batched heartbeat prompt.

## What This Changes

The issue requests per-task model hints in HEARTBEAT.md so selected scheduled tasks can use a stronger model than the run-level heartbeat model.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level heartbeat.model while specifying syntax, split-or-group execution, alias/fallback/auth behavior, docs, and focused tests.
