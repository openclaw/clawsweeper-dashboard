## Summary

Keep open: current main still supports only a run-level `heartbeat.model`, while `HEARTBEAT.md` tasks parse as `name`/`interval`/`prompt` and all due tasks are batched into one heartbeat turn. The requested per-task model hint would add a public heartbeat task metadata and model-routing contract, so it needs maintainer product/API direction rather than conservative cleanup.

## What This Changes

The issue requests a per-task model override or escalation hint inside `HEARTBEAT.md` so selected heartbeat tasks can use a different model than the run-level heartbeat default.

## Best Possible Solution

Define one canonical scheduled-work model-routing contract that preserves run-level `heartbeat.model`, including syntax, split-or-grouped execution semantics, alias/fallback/auth behavior, docs, and focused tests.
