## Summary

Keep open: current main and the latest release still only support a single run-level `heartbeat.model`, while `HEARTBEAT.md` task mode parses `name`/`interval`/`prompt` and batches all due tasks into one model turn. This remains a heartbeat/model-routing product and config-contract decision rather than conservative cleanup.

## What This Changes

The issue requests a per-task model hint or escalation keyword in `HEARTBEAT.md` so selected heartbeat tasks can run on a different model than the run-level heartbeat model.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level `heartbeat.model` while specifying syntax, split-or-grouped execution, alias/fallback/auth behavior, docs, and focused tests.

Unclear: a HEARTBEAT.md model hint is plausible, but the best fix needs maintainer choice on syntax, alias/fallback behavior, and whether due tasks should be split or grouped by model.
