## Summary

Keep open for maintainer product/API direction: current main and the latest release only support one heartbeat model for the whole heartbeat turn, while due HEARTBEAT.md tasks are batched into one prompt and the existing plugin hook can route that whole turn but cannot express a native per-task split.

## What This Changes

The issue requests a way to select a different model for individual HEARTBEAT.md task blocks instead of using one heartbeat-wide model.

## Best Possible Solution

Maintainers should choose one scheduled-routing contract first; if native heartbeat task hints are accepted, implement typed task model/provider fields with grouped execution, run-scoped model restoration, docs, and regression tests.
