## Summary

Keep open: current main and v2026.6.11 still support only a run-level heartbeat model override, while HEARTBEAT.md tasks are parsed as name/interval/prompt and batched into one heartbeat turn. The request remains valid, but it needs maintainer product/API direction before implementation.

## What This Changes

The issue requests per-task model hints in HEARTBEAT.md so some heartbeat tasks can run on a different model than the run-level heartbeat model.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level heartbeat.model while specifying syntax, split-or-group execution, alias/fallback/auth behavior, docs, and focused tests.
