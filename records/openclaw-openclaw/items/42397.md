## Summary

Keep open: current main and v2026.6.11 still support only a run-level `heartbeat.model`, while structured `HEARTBEAT.md` tasks are parsed as `name`/`interval`/`prompt` and batched into one model turn. The request remains a product/config-contract decision, not conservative cleanup.

## What This Changes

The issue requests a `HEARTBEAT.md` task-level model hint so selected periodic heartbeat tasks can use a different or primary model while routine heartbeat work stays on a cheaper model.

## Best Possible Solution

Define one canonical heartbeat task routing contract that preserves run-level `heartbeat.model` while specifying task syntax, split-or-grouped execution, alias/fallback/auth behavior, state updates, docs, and regression coverage.
