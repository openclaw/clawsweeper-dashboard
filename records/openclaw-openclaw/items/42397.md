## Summary

Keep open: current main and v2026.6.11 still support only a single heartbeat-run model override, while HEARTBEAT.md task mode parses name/interval/prompt and batches all due tasks into one model turn. The issue remains a product/config-contract decision, not conservative cleanup.

## What This Changes

Request per-task HEARTBEAT.md model hints or escalation so selected periodic heartbeat tasks can run on a different model than routine heartbeat checks.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level heartbeat.model while specifying syntax, split-or-grouped execution, alias/fallback/auth behavior, docs, and focused tests.
