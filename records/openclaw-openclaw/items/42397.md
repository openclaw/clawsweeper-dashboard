## Summary

Keep open: current main still supports only one heartbeat model per heartbeat run, and the existing plugin hook can route a whole turn but does not provide native per-task HEARTBEAT.md model selection.

## What This Changes

The issue requests per-task model hints or escalation in HEARTBEAT.md so individual periodic heartbeat tasks can use a different model than the run-level heartbeat model.

## Best Possible Solution

Choose one supported contract and document it: either keep heartbeat model routing whole-turn/plugin-owned, or add a native task-level model/provider field with explicit grouping, timestamp, session-state, and precedence behavior.
