## Summary

Keep open for product/API decision: current main only supports one heartbeat model per heartbeat turn and batches due HEARTBEAT.md tasks into one run, while plugin routing can change a whole turn but does not express the requested native per-task split.

## What This Changes

Request to let individual HEARTBEAT.md task blocks choose or escalate to a different model than the global heartbeat.model.

## Best Possible Solution

Maintainers should first choose the permanent contract: document plugin/per-turn routing for whole heartbeat ticks, or add a narrow native HEARTBEAT.md task model field that splits due tasks by model and preserves session state.

Rationale: Current main lacks the requested native task boundary, but the existing before_model_resolve hook and a community routing plugin cover broader whole-turn routing; choosing the core contract affects public syntax, model precedence, and session-state behavior.

Options:

- **Keep routing plugin-owned (recommended):** Document that heartbeat ticks currently run as one model-routed turn and use before_model_resolve or ClawHub plugins for routing policy unless a missing generic seam is proven.

- **Fold into scheduled-job routing:** Make #42631 the canonical scheduled model override path and avoid another heartbeat-specific routing syntax until cron and heartbeat semantics converge.
