## Summary

Keep open: current main and v2026.6.11 still support only a run-level heartbeat model, while HEARTBEAT.md task parsing and execution have no per-task model hint or split per-task model call. Existing plugin routing helps whole-turn model selection, but the heartbeat-specific task syntax and split/group execution semantics still need maintainer product direction.

## What This Changes

Request to let individual HEARTBEAT.md tasks specify a model hint or primary-model escalation while routine heartbeat work uses a cheaper model.

## Best Possible Solution

Define one canonical heartbeat or scheduled-task model-routing contract that preserves run-level heartbeat.model while specifying task syntax, split-or-group execution, provider/auth/fallback behavior, docs, and focused tests.

- **Keep whole-turn plugin routing:** Document before_model_resolve and community routing plugins as the supported model-routing path while leaving multiple due heartbeat tasks batched.

## Reproduction Assessment

Yes, at source level: current main parses HEARTBEAT.md tasks as name, interval, and prompt, batches all due tasks into one prompt, and forwards one run-level heartbeatModelOverride. That directly reproduces the requested missing per-task model override without a live provider call.

## Solution Assessment

Unclear: a HEARTBEAT.md model hint is plausible, but the best fix needs maintainer choice on task syntax, split-versus-grouped execution, and provider/auth/fallback behavior. The existing plugin hook is useful for whole-turn routing, not a complete per-task heartbeat solution.
