## Summary

Keep open: current main and v2026.6.11 still support only run-level `heartbeat.model`; `HEARTBEAT.md` task parsing has no task model field and all due tasks are batched into one heartbeat turn. This remains a useful feature request, but it needs a maintainer product decision before implementation.

## What This Changes

Requested behavior: allow individual `HEARTBEAT.md` tasks to select or escalate to a different model than the run-level heartbeat model.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level `heartbeat.model` while specifying task syntax, split-or-group execution, alias/fallback/auth behavior, session state, docs, and focused tests.

Options:

- **Design shared routing contract first (recommended):** Keep this issue open and decide a reusable heartbeat or per-turn routing contract before accepting `HEARTBEAT.md`-only syntax.
- **Add heartbeat-only task metadata:** Implement a narrow `HEARTBEAT.md` task model field with explicit split/group semantics, alias/fallback rules, docs, and compatibility tests.
- **Keep routing plugin-owned:** Document whole-turn `before_model_resolve` plugins as the supported routing path and accept that multiple due heartbeat tasks cannot be independently routed today.
