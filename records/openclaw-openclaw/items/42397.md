## Summary

Keep open: current main still only supports a run-level `heartbeat.model`, while parsed `HEARTBEAT.md` tasks are `name`/`interval`/`prompt` entries that are batched into one heartbeat turn. Per-task model hints would add a new public heartbeat task metadata and model-routing contract, so this needs maintainer product/API direction rather than conservative cleanup.

## What This Changes

Request to let individual `HEARTBEAT.md` task blocks select or escalate to a different model than the run-level `heartbeat.model`.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level `heartbeat.model`, including syntax, split-or-grouped execution semantics, alias/fallback/auth behavior, docs, and focused tests.
