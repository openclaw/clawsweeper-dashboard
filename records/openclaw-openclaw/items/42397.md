## Summary

Keep open: current main and v2026.6.11 still support only one heartbeat model override per heartbeat turn, while `HEARTBEAT.md` tasks are parsed as `name`/`interval`/`prompt` and batched into one model call. Per-task model hints need a new public heartbeat task metadata and execution-routing contract, not conservative cleanup.

## What This Changes

Requests support for assigning different models to individual `HEARTBEAT.md` tasks instead of using one run-level heartbeat model.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level `heartbeat.model`, specifies task syntax, split/group execution semantics, alias/auth/fallback behavior, docs, and regression coverage.
