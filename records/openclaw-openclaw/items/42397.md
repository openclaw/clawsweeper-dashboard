## Summary

Keep open: current main and v2026.6.11 still only offer a run-level `heartbeat.model`, while due `HEARTBEAT.md` tasks are parsed as `name`/`interval`/`prompt` and batched into one heartbeat turn. Adding task-level model hints would define a new public heartbeat task metadata and routing contract, so this remains a maintainer product/API decision rather than conservative cleanup.

## What This Changes

Request a per-task `HEARTBEAT.md` model hint or escalation mechanism so specific heartbeat tasks can use a stronger model without running the whole heartbeat on that model.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level `heartbeat.model`, including syntax, split-or-grouped execution semantics, alias/fallback/auth behavior, docs, and focused tests.
