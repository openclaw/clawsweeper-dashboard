## Summary

Keep open: current main and v2026.6.11 still support only a run-level heartbeat model override, while HEARTBEAT.md tasks are parsed as name/interval/prompt entries and batched into one heartbeat turn. The request remains a feature and product/API decision, not a conservative cleanup close.

## What This Changes

The issue requests per-task model hints in HEARTBEAT.md so selected heartbeat tasks can run with a different model than the run-level heartbeat.model override.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level heartbeat.model, including syntax, grouping or split-turn semantics, alias/fallback/auth behavior, docs, and focused tests; otherwise document per-turn plugin routing as the supported alternative.

## Reproduction Assessment

Yes, source-level: current main's HeartbeatTask type and parser expose only name, interval, and prompt, while the runner sends all due tasks through one heartbeatModelOverride.

## Solution Assessment

Unclear: the HEARTBEAT.md model hint is plausible, but the best fix needs maintainer choice on syntax, alias/fallback behavior, and whether due tasks should be split or grouped by model.
