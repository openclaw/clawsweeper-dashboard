## Summary

Keep open for maintainer product/API decision: current main still runs HEARTBEAT.md due tasks as one heartbeat turn with one heartbeat model override, so exact per-task escalation is neither implemented nor safely auto-fixable.

## What This Changes

The issue requests a per-task HEARTBEAT.md model hint so cheap heartbeat tasks and higher-quality memory/log tasks can use different models in the same scheduled heartbeat flow.

## Best Possible Solution

Define one explicit contract for scheduled model routing: either document plugin/job-level routing as the supported path, or add a narrow HEARTBEAT.md task model field that splits due tasks by effective model while preserving shared-session state.
