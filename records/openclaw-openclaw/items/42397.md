## Summary

Keep open: current main and the latest release still support only a run-level heartbeat model, while due HEARTBEAT.md tasks are parsed without model metadata and batched into one heartbeat turn. The existing plugin routing path and the published routing-yaml plugin help with whole-turn routing, but they do not split multiple due heartbeat tasks across different models.

## What This Changes

Request per-task model hints in HEARTBEAT.md so individual heartbeat tasks can run on different models within one heartbeat run.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level heartbeat.model while specifying syntax, split-or-group execution, alias/fallback/auth behavior, docs, and focused tests.
