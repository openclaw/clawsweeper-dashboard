## Summary

Keep open: current main and v2026.6.11 still provide only a run-level heartbeat model override, while HEARTBEAT.md task mode batches all due tasks into one model turn. This remains a heartbeat/model-routing product and config-contract decision, not conservative cleanup.

## What This Changes

Request per-task model hints in HEARTBEAT.md so selected periodic heartbeat tasks can run on a different model than the run-level heartbeat.model.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level heartbeat.model while specifying syntax, split-or-grouped execution, alias/fallback/auth behavior, docs, and focused tests.

Question: Should OpenClaw add task-level model metadata to HEARTBEAT.md, or should heartbeat task routing stay whole-turn/plugin-owned unless a broader routing contract is designed?

Rationale: The source gap is clear, but the implementation changes public HEARTBEAT.md syntax and model-routing semantics, and automation should not choose split-versus-batched execution or provider fallback behavior on its own.

Owner reason: The strongest combined history is across the model hook seam, heartbeat task batching, and product-boundary decisions for config/routing surfaces.

Owner confidence: high

Options:

- **Design shared routing contract first (recommended):** Keep this issue open and decide reusable heartbeat or per-turn routing semantics before accepting HEARTBEAT.md-only syntax.
- **Add heartbeat-only task metadata:** Implement a narrow HEARTBEAT.md task model field with explicit split/group semantics, alias/fallback rules, docs, and compatibility tests.
- **Keep routing plugin-owned:** Document whole-turn before_model_resolve plugins as the supported routing path and accept that multiple due heartbeat tasks cannot be independently routed today.

## Reproduction Assessment

Yes, source-level: current main parses heartbeat tasks as name/interval/prompt, batches all due tasks into one prompt, and forwards one heartbeatModelOverride for the whole run. This is a missing feature contract rather than broken existing behavior.

## Solution Assessment

Unclear: a HEARTBEAT.md model hint is plausible, but the best fix needs maintainer choice on syntax, alias/fallback behavior, and whether due tasks should be split or grouped by model.
