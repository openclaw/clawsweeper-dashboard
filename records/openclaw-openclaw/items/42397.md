## Summary

Keep open for a maintainer product/API decision: current main still supports only one heartbeat model override per heartbeat turn, parses HEARTBEAT.md tasks without a model field, and batches due tasks into one model call.

## What This Changes

Request to add per-task model hints or escalation semantics for tasks defined in HEARTBEAT.md.

## Best Possible Solution

Choose one permanent contract: keep heartbeat model routing whole-turn and plugin-owned, or add native HEARTBEAT.md task model fields that group or split due tasks while preserving session state.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw core support native per-task model hints in HEARTBEAT.md, or should heartbeat model routing remain per-turn and plugin-owned until a broader scheduled-routing design lands?

Rationale: Source inspection proves the capability is missing, but adding it changes public HEARTBEAT.md syntax, model precedence, task execution grouping, and session-state semantics; automation should not choose that API shape.

Likely owner: vincentkoc

Owner reason: The current heartbeat parser/runner history and active model/config surface work make this the best available owner for choosing a safe implementation boundary.

Owner confidence: medium

Options:

- **Add native task hints (recommended):** Define model/provider fields for HEARTBEAT.md tasks, group or split due tasks by effective model, and add tests/docs for precedence, timestamps, and session restoration.
- **Keep whole-turn routing:** Document that heartbeat.model and before_model_resolve route an entire heartbeat tick, accepting that exact per-task escalation is not supported in core.
- **Fold into scheduled routing:** Defer this to the broader scheduled model override track so cron and heartbeat use one shared model-routing contract instead of a HEARTBEAT-specific syntax.

## Reproduction Assessment

Yes, source-level. Current main parses only name/interval/prompt task fields, batches due tasks into one prompt, and passes a single heartbeatModelOverride for the whole run.

## Solution Assessment

Unclear until maintainers choose the product contract. Exact per-task escalation needs a native task execution boundary, while the existing plugin hook is only a whole-turn routing seam.
