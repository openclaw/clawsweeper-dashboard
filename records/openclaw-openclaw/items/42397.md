## Summary

Keep open: current main and v2026.6.11 still support only run-level `heartbeat.model`, while `HEARTBEAT.md` tasks are parsed as `name`/`interval`/`prompt` and batched into one heartbeat turn. The linked routing plugin path is useful for whole-turn model routing, but it does not independently route multiple due heartbeat tasks inside the current batched prompt.

## What This Changes

Allow individual `HEARTBEAT.md` tasks to specify a model or escalation hint instead of using only the run-level heartbeat model.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level `heartbeat.model` while specifying syntax, split-or-group execution, alias/fallback/auth behavior, docs, and focused tests.
