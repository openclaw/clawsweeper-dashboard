## Summary

Keep open: current main still has only a run-level heartbeat model override, while due HEARTBEAT.md tasks are parsed as name/interval/prompt and batched into one heartbeat prompt. Existing before_model_resolve plugins can route a whole heartbeat turn, but they do not independently route multiple due heartbeat tasks inside that batched run.

## What This Changes

The issue requests a per-task HEARTBEAT.md model hint or escalation marker so selected heartbeat tasks can run on a different model than routine heartbeat work.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level heartbeat.model while specifying syntax, split-or-group execution, alias/fallback/auth behavior, docs, and focused tests.
