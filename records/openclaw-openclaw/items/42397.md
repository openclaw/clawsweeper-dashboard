## Summary

Keep open: current main and the latest release still only support a run-level `heartbeat.model`, while `HEARTBEAT.md` tasks remain `name`/`interval`/`prompt` entries batched into one heartbeat turn. Related plugin work is useful for whole-turn routing, including the `@glasshousehq/openclaw-routing-yaml` plugin mentioned on a sibling issue, but it does not independently route multiple due heartbeat tasks inside the current batched prompt.

## What This Changes

Request to add a per-task model hint or escalation keyword to `HEARTBEAT.md` so selected heartbeat tasks can run on a different model than the default heartbeat model.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level `heartbeat.model` while specifying syntax, split-or-group execution, alias/fallback/auth behavior, docs, and focused tests.
