## Label Justifications

- `P2`: This is a meaningful heartbeat/model-routing enhancement with cost and quality impact, but it is not an urgent regression or outage.
- `impact:auth-provider`: The requested behavior changes provider/model choice for heartbeat task execution and overlaps alias, allowlist, fallback, and auth-provider routing semantics.

## Summary

Keep open: current main still supports only a run-level heartbeat model override, and due `HEARTBEAT.md` tasks are batched into one heartbeat turn. The request would add a new public heartbeat task metadata and model-routing contract, so it needs maintainer product/API review rather than conservative cleanup.

## What This Changes

Request per-task model hints in `HEARTBEAT.md` so selected heartbeat tasks can run on a different model than the run-level `heartbeat.model`.

## Best Possible Solution

Define one canonical heartbeat task routing contract, or explicitly route this use case to cron/plugin surfaces, before adding `HEARTBEAT.md` syntax that changes model, fallback, auth, and shared-session behavior.
