## Summary

Keep open: current main still has only a run-level heartbeat model override, while HEARTBEAT.md tasks are parsed as name/interval/prompt and batched into one heartbeat turn. This is a real feature gap, but the fix requires a product/API decision for task syntax, model aliasing, fallback/auth behavior, and shared-session semantics.

## What This Changes

The issue requests a HEARTBEAT.md task-level model hint or escalation marker so selected heartbeat tasks can run on a different model than the run-level heartbeat model.

## Best Possible Solution

Define one canonical heartbeat task routing contract that preserves run-level heartbeat.model while specifying task syntax, split/group execution semantics, model aliases, fallbacks, auth, docs, and focused tests.
