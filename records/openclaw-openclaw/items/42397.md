## Summary

Keep open: current main still supports only a run-level `heartbeat.model`; `HEARTBEAT.md` tasks parse as `name`/`interval`/`prompt` and all due tasks are batched into one heartbeat turn. Existing `before_model_resolve` plugins, including the linked `@glasshousehq/openclaw-routing-yaml` plugin, can route whole turns but do not independently route multiple due heartbeat tasks inside the batched prompt.

## What This Changes

Request per-task model hints for `HEARTBEAT.md` tasks so routine and higher-quality periodic work can use different models.

## Best Possible Solution

Define one canonical heartbeat task-routing contract that preserves run-level `heartbeat.model` while specifying syntax, split-or-group execution, alias/fallback/auth behavior, docs, and focused tests.
