## Summary

Keep open: current main and the latest release still provide only a run-level `heartbeat.model`, while `HEARTBEAT.md` tasks are parsed as `name`/`interval`/`prompt` and batched into one heartbeat turn. The existing `before_model_resolve` hook and the linked `@glasshousehq/openclaw-routing-yaml` plugin are useful whole-turn routing paths, but they do not independently route multiple due heartbeat tasks within the current batched heartbeat prompt.

## What This Changes

The issue requests a task-level model hint or escalation marker in `HEARTBEAT.md` so individual periodic heartbeat tasks can use different models.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level `heartbeat.model` while specifying syntax, split-or-group execution, alias/fallback/auth behavior, docs, and focused tests.
