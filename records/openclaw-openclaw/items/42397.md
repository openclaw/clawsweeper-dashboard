## Summary

Keep open: current main still has only a run-level heartbeat model, batches due HEARTBEAT.md tasks into one reply run, and the existing plugin hook can route a whole turn but not the requested native per-task split.

## What This Changes

Request per-task model hints in HEARTBEAT.md so selected periodic heartbeat tasks can run on a different model than the heartbeat default.

## Best Possible Solution

Choose one permanent contract first; if native task hints are accepted, add model/provider task fields, split or group due tasks by effective model, validate through existing provider/model routing, and preserve heartbeat session/timestamp semantics with docs and tests.
