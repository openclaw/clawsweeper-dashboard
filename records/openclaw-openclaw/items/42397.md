## Summary

Keep open: current main and v2026.6.11 still only support a run-level `heartbeat.model`, while structured `HEARTBEAT.md` tasks have no model metadata and are batched into one heartbeat turn. The remaining work is a product/API decision for task-level syntax, split-or-grouped execution, and provider/model routing semantics.

## What This Changes

Request to allow specific `HEARTBEAT.md` task blocks to select or escalate to a different model than the run-level `heartbeat.model`.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level `heartbeat.model`, including syntax, split-or-grouped execution semantics, alias/fallback/auth behavior, docs, and focused tests.
