## Summary

Keep open for maintainer product/API decision: current main still has only one heartbeat model override for the whole heartbeat run, while HEARTBEAT.md tasks are parsed as name/interval/prompt and batched into one prompt with no per-task execution boundary.

## What This Changes

The issue requests per-task model hints or escalation markers in HEARTBEAT.md so selected heartbeat tasks can run on a different model than the rest of the heartbeat run.

## Best Possible Solution

Maintainers should choose one scheduled model-routing contract first, then either document whole-turn plugin routing, fold the need into cron/job-level overrides, or define native HEARTBEAT.md task model fields with explicit task-splitting semantics.

Options:

- **Keep routing per-turn/plugin-owned (recommended):** Document that heartbeat runs are one model-routed turn today and use `before_model_resolve` or ClawHub plugins for whole-turn routing unless maintainers explicitly sponsor native task splitting.

- **Fold into cron override work:** Make the open cron/job-level model override issue the canonical scheduled-routing contract and avoid heartbeat-specific syntax until the scheduling model converges.
