## Summary

Keep open: current main and the latest stable release still support only a run-level heartbeat model override, while HEARTBEAT.md tasks are parsed as name/interval/prompt and batched into one heartbeat turn. The request is still useful, but it needs maintainer product/API direction before implementation.

## What This Changes

The issue asks OpenClaw to support per-task model hints or escalation metadata for tasks defined in HEARTBEAT.md.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level heartbeat.model while specifying syntax, split-or-group execution, alias/fallback/auth behavior, docs, and focused tests.
