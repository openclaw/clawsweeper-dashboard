## Summary

Keep open for maintainer product/API decision: current main and the latest release still support only one heartbeat model for a heartbeat turn, while existing plugin routing is whole-turn and the related cron issue tracks a different scheduled-job contract.

## What This Changes

Request task-level model/provider hints or escalation semantics in HEARTBEAT.md so routine heartbeat tasks can use cheaper models while selected tasks run on the primary model.

## Best Possible Solution

Define one supported scheduled-model-routing contract and document its precedence; avoid ad hoc HEARTBEAT.md fields unless maintainers intentionally want heartbeat task splitting.
