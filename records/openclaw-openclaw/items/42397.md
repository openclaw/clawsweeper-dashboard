## Summary

Keep open: current main and v2026.6.11 still only support a whole-heartbeat model override; HEARTBEAT.md tasks parse only task name, interval, and prompt, and due tasks are batched into one model call. The remaining work needs maintainer product direction because it would define public HEARTBEAT.md syntax and heartbeat model-routing semantics.

## What This Changes

Request support for per-task HEARTBEAT.md model hints so selected heartbeat tasks can run on a different model than the run-level heartbeat model.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level heartbeat.model and specifies syntax, split-or-batch execution, provider/alias/fallback behavior, docs, and focused parser/runner tests.
