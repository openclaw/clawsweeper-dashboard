## Summary

Keep open: current main still supports only a single heartbeat-level model override and batches due HEARTBEAT.md tasks into one agent turn, while the exact per-task split requested here remains a product/API decision rather than cleanup. The open cron model-override issue at https://github.com/openclaw/openclaw/issues/42631 overlaps on scheduled model selection, but it does not own HEARTBEAT.md task syntax.

## What This Changes

The issue requests a per-task model hint in HEARTBEAT.md so selected heartbeat tasks can run on a different or primary model while routine heartbeat work stays on a cheaper model.

## Best Possible Solution

Choose the permanent contract first: either document plugin/per-turn routing as the supported path, or add a narrow native HEARTBEAT.md task model/provider field that groups or splits due tasks by effective model with explicit session-state and docs/test coverage.
