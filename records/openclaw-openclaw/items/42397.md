## Summary

Keep open: current main still supports only a run-level `heartbeat.model`; `HEARTBEAT.md` due tasks are parsed as `name`/`interval`/`prompt` and batched into one heartbeat turn. The existing `before_model_resolve` plugin path and the published `@glasshousehq/openclaw-routing-yaml` plugin are useful for whole-turn routing, but they do not independently route multiple due heartbeat tasks inside the current batched prompt.

## What This Changes

Request to add per-task model hints or overrides in `HEARTBEAT.md` so selected periodic heartbeat tasks can use a different model than the run-level heartbeat model.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level `heartbeat.model` while specifying syntax, split-or-group execution, alias/fallback/auth behavior, docs, and focused tests.
