## Summary

Keep open: current main and v2026.6.11 still provide only a run-level `heartbeat.model`, while HEARTBEAT.md task parsing keeps only name, interval, and prompt and batches all due tasks into one heartbeat turn. Related model-routing issues and the existing plugin hook cover adjacent per-turn routing, but they do not replace the requested HEARTBEAT.md task-level syntax or split/re-execute semantics.

## What This Changes

The issue requests per-task model hints in HEARTBEAT.md so selected heartbeat tasks can run on a different model than the rest of the heartbeat run.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level `heartbeat.model` while specifying syntax, split-or-group execution, alias/fallback/auth behavior, docs, and focused tests.

## Reproduction Assessment

Yes at source level: current main parses HEARTBEAT.md tasks as name, interval, and prompt, batches all due tasks, and forwards one run-level `heartbeatModelOverride`. That directly reproduces the requested gap without needing a live provider call.

## Solution Assessment

Unclear: a HEARTBEAT.md `model` hint is plausible, but the best fix needs maintainer choice on syntax, split-versus-grouped execution, and provider/auth/fallback behavior. The existing plugin hook is a useful adjacent path for whole-turn routing, not a complete per-task heartbeat solution.
