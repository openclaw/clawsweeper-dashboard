## Summary

Keep open for maintainer product/API decision: current main still batches due HEARTBEAT.md tasks into one heartbeat run and passes one heartbeat-wide model override, while the plugin router hook can choose a model for a whole turn but not split one heartbeat tick by task.

## What This Changes

Request to let individual HEARTBEAT.md tasks specify or escalate to a different model than the heartbeat-wide model.

## Best Possible Solution

Maintainers should choose one contract first: keep heartbeat model routing per-turn/plugin-owned, fold the need into scheduled-job model override work, or add a native HEARTBEAT.md task model field that groups/splits due tasks safely.
