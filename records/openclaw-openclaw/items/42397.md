## Summary

Keep open: current main and v2026.6.11 still support only a run-level heartbeat model override, and HEARTBEAT.md due tasks are parsed as name/interval/prompt then batched into one heartbeat turn. Existing before_model_resolve plugins can route a whole turn, but they do not provide independent model selection for multiple due heartbeat tasks.

## What This Changes

Request per-task model hints in HEARTBEAT.md so selected periodic heartbeat tasks can run on a different model than the heartbeat run default.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level heartbeat.model while specifying HEARTBEAT.md syntax, split-or-group execution, alias/fallback/auth behavior, docs, and focused tests.
