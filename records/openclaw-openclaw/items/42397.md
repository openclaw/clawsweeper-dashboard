## Summary

Keep open: current main and v2026.6.11 still support only a run-level heartbeat model override, while HEARTBEAT.md tasks are parsed as name/interval/prompt and batched into one heartbeat turn. The request is still useful, but it needs maintainer product/API direction before implementation.

## What This Changes

Requests per-task HEARTBEAT.md model hints or escalation so selected heartbeat tasks can use a different model from the run-level heartbeat.model.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level heartbeat.model while specifying syntax, split-or-group execution, alias/fallback/auth behavior, docs, and focused tests.
