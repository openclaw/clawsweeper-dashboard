## Summary

Keep open: current main and v2026.6.11 still expose only a run-level heartbeat model, while HEARTBEAT.md task parsing and execution do not support per-task model hints or split per-task model calls. The remaining work needs maintainer product direction because it changes public heartbeat syntax, model routing, and session semantics.

## What This Changes

Request per-task model hints or escalation semantics in HEARTBEAT.md so selected periodic heartbeat tasks can run on a different model than the run-level `heartbeat.model`.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level `heartbeat.model` while specifying syntax, split-or-group execution, provider/alias/fallback behavior, docs, and focused tests.

## Reproduction Assessment

Yes, at source level: current main parses HEARTBEAT.md tasks as name, interval, and prompt, batches all due tasks, and forwards one run-level `heartbeatModelOverride`. That directly reproduces the requested gap without needing a live provider call.

## Solution Assessment

Unclear: a HEARTBEAT.md `model` hint is plausible, but the best fix needs maintainer choice on syntax, split-versus-grouped execution, and provider/auth/fallback behavior. The existing plugin hook is useful for whole-turn routing, not a complete per-task heartbeat solution.
