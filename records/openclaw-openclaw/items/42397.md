## Summary

Keep open for product/API decision: current main and the latest release still support only one heartbeat model per heartbeat run, while due `HEARTBEAT.md` tasks are parsed as name/interval/prompt entries and batched into one model turn. The existing plugin hook can route a whole turn, but it does not provide the requested native per-task heartbeat split.

## What This Changes

The issue requests per-task model hints in `HEARTBEAT.md` so selected heartbeat tasks can use a different model than the configured heartbeat default.

## Best Possible Solution

Maintainers should choose one scheduled-work model-routing contract first, then either document per-turn plugin routing as the supported path or add a narrow native task-level heartbeat field with tests for grouping, timestamps, and session-model restoration.
