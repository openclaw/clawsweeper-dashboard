## Summary

Keep open for maintainer product/API direction: current main still has only a run-level heartbeat model override, while HEARTBEAT.md tasks are parsed and batched without any per-task provider/model contract.

## What This Changes

Request to allow HEARTBEAT.md task blocks to select or escalate to a different model than the heartbeat run default.

## Best Possible Solution

Define one scheduled-model-selection contract first, then either apply it to HEARTBEAT.md task execution with explicit task-splitting semantics or document that heartbeat routing remains whole-turn/plugin-owned.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add native per-task model hints to HEARTBEAT.md, fold this into a broader scheduled-run model override contract, or keep heartbeat model routing whole-turn/plugin-owned?

Rationale: The source gap is real, but the fix changes public task syntax, model/provider precedence, session-state behavior, and the boundary between core heartbeat scheduling and plugin-owned routing.

Likely owner: vincentkoc

Owner reason: vincentkoc has the strongest recent overlap across heartbeat parsing/docs and plugin model-routing seams.

Owner confidence: high

Options:

- **Fold Into Scheduled Routing (recommended):** Use one generic scheduled-run model selection contract so heartbeat tasks and cron jobs do not grow competing provider/model semantics.
- **Add HEARTBEAT.md Task Hints:** Define model/provider fields in task blocks, split due tasks by effective model, and cover timestamp/session behavior in tests and docs.
- **Keep Whole-Turn Routing:** Document before_model_resolve or ClawHub plugins as the supported routing path and accept that one heartbeat turn uses one effective model.

## Reproduction Assessment

Yes, source-level. Current main parses only name/interval/prompt task fields, batches all due tasks into one prompt, and applies heartbeat.model once for the whole heartbeat run.

## Solution Assessment

Unclear until maintainers choose the contract. Existing plugin hooks can route a whole heartbeat turn, but exact per-task escalation needs either native task execution boundaries or a broader scheduled-run override design.
