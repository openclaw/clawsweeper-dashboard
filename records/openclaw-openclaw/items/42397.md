## Summary

Keep open for maintainer product/API decision: current main still batches HEARTBEAT.md due tasks into one heartbeat turn with one heartbeat model override, and the cron/plugin alternatives do not implement exact per-task HEARTBEAT.md escalation.

## What This Changes

Allow tasks in HEARTBEAT.md to request a different model or escalate specific due tasks to the primary model without running every heartbeat task on that model.

## Best Possible Solution

Pick one supported scheduled model-routing contract: keep heartbeat as a whole-turn mechanism and document cron/plugin routing for model-specific work, or define a native HEARTBEAT.md model field with clear session/model precedence and tests.

## Maintainer Decision

Question: Should OpenClaw add native model/provider hints to HEARTBEAT.md task blocks, or keep heartbeat tasks as one run and direct model-specific scheduled work to cron/plugin routing?

Rationale: The source gap is clear, but any fix would add public task-file syntax or change model/session precedence; that is a product/API decision rather than a narrow bug repair.

Likely owner: steipete

Owner reason: The choice is primarily a core-vs-plugin/product-surface decision around an existing model-routing hook seam and new public HEARTBEAT.md syntax.

Owner confidence: medium

Options:

- **Keep heartbeat whole-turn routing (recommended):** Document that HEARTBEAT.md tasks share one heartbeat model today and route model-specific standalone work through cron agent-turn jobs or plugin before_model_resolve routing.
- **Add native HEARTBEAT.md model hints:** Define model/provider fields in task blocks, split due tasks by effective model, and add validation, docs, timestamp, and session-state tests.
- **Fold into cron override design:** Treat this as overlap with the main-session cron model override track and decide both scheduled model-selection contracts together.

## Reproduction Assessment

Yes, source-level: current main parses HEARTBEAT.md tasks as name/interval/prompt only, batches due tasks into one prompt, and passes one heartbeatModelOverride for the run.

## Solution Assessment

Unclear until maintainers choose the product contract; plugin per-turn routing and cron agent-turn model selection are existing narrower surfaces, while exact per-task heartbeat escalation needs a native task execution boundary.
