## Summary

Keep open: current main and the latest stable release still support only a run-level heartbeat model override, while HEARTBEAT.md tasks are parsed as name/interval/prompt and grouped into one model turn.

## What This Changes

Request task-level model hints in HEARTBEAT.md so individual periodic heartbeat tasks can use a different model than the rest of the heartbeat run.

## Best Possible Solution

Define one canonical heartbeat task model-routing contract that preserves run-level heartbeat.model and specifies task syntax, batching versus split execution, alias/fallback/auth behavior, docs, and tests.
