## Summary

Keep open for maintainer review: the patch looks correct and well-proven, but it intentionally changes oversized Codex sandbox `fs/copy` from a full-buffer copy attempt to the existing 512 MiB read-cap failure mode.

## What This Changes

The PR factors the Codex sandbox exec-server read-size check into a helper, applies it before file-copy reads, and adds an oversized `fs/copy` regression test.

## Best Possible Solution

Land the shared read-size guard at the current full-buffer copy/read boundary, and treat streaming support for files above 512 MiB as separate protocol and bridge work if maintainers want it.
