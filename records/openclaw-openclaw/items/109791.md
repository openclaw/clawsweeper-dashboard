## Label Justifications

- `P0`: A single unavailable optional skill credential can currently prevent the Gateway—the core runtime—from starting at all.
- `merge-risk: 🚨 compatibility`: The PR deliberately changes existing startup semantics from whole-Gateway failure to successful startup with one configured skill disabled.
- `merge-risk: 🚨 session-state`: The PR changes persisted skill snapshot contents and can rebuild an existing session's skill prompt when a degraded owner is detected.

## Summary

This PR remains necessary and appears to be the correct skill-specific continuation of the merged generic SecretRef owner-isolation design. No actionable patch defect is established, but the protected maintainer label, deliberate startup compatibility change, persisted-session reconstruction, and incomplete checks warrant normal maintainer review rather than cleanup closure.

## What This Changes

The PR assigns each skill API-key SecretRef an isolatable owner and consistently excludes an unavailable skill from Gateway startup, prompts, persisted snapshots, and runtime environment injection while preserving healthy skills.

## Best Possible Solution

Keep the generic owner-isolation model, retain the optional snapshot identity for legacy compatibility, and land after the remaining CI completes with a focused Gateway smoke confirming readiness, healthy-skill visibility, cold-skill omission, and legacy-session filter preservation.
