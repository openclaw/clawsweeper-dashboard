## Label Justifications

- `P0`: A single unresolved optional skill secret can currently prevent the core Gateway from starting, leaving the runtime unusable until the secret or configuration is repaired.
- `merge-risk: 🚨 session-state`: The patch changes persisted skill prompt reconstruction and can leave recovered skill availability stale in existing sessions.

## Summary

Keep open: the owner-isolation direction is sound, but the current head can permanently reuse a degraded persisted prompt after the skill secret recovers, so the patch is not ready to merge.

## What This Changes

The PR assigns per-skill secret owners and excludes unavailable skills from live discovery, persisted prompt reconstruction, and live or snapshot environment injection while keeping the Gateway and healthy skills available.

## Best Possible Solution

Add the active degraded-skill-owner revision or a deterministic fingerprint to reusable snapshot invalidation, preserving custom skill keys and saved filters, and cover both healthy-to-degraded and degraded-to-recovered transitions with focused regression tests.

Yes. Create a reusable snapshot while a skill owner is degraded, clear the active degraded-owner state to model successful recovery, then resolve the prompt again; the current early return continues using the snapshot that omitted the recovered skill.

## Solution Assessment

No, not yet. Per-owner isolation is the correct boundary, but the implementation must make snapshot reuse observe both degradation and recovery rather than handling only the degraded state.
