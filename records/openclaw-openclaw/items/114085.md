## What This Changes

The PR centralizes freshness rules for task snapshots so overlapping task-list responses, Gateway events, and detail lookups do not regress concurrent task progress in the Tasks page or chat task rail.

## System Context

The web UI combines task-list responses, pushed Gateway task events, and opened-task details into a per-task state collection. That collection feeds both the Tasks page and the chat background-task rail, so its reconciliation policy determines whether completed tasks or live tool progress can be overwritten by stale data.
