Replace the sanitizer internals with a linear implementation that preserves the existing normalization, null-byte rejection, and control-character semantics, and cover the large-message path without adding a new protocol size cap.

## Repair Work Prompt

Fix the Gateway chat input sanitizer performance issue reported in https://github.com/openclaw/openclaw/issues/102915. Preserve `sanitizeChatSendMessageInput` behavior exactly: NFC normalization, existing null-byte rejection/error, removal of disallowed C0 control characters and DEL, and preservation of tab/newline/carriage return. Replace the per-character string-concatenation implementation in `src/gateway/chat-input-sanitize.ts` with a linear, bounded implementation such as a precompiled regex/native replace or an array-join path that avoids repeated string growth. Add focused regression coverage for a large message that proves allowed content is preserved and disallowed characters are stripped without changing `chat.send` API behavior. Do not add a new payload limit or protocol/schema cap; prior PR https://github.com/openclaw/openclaw/pull/44015 shows that is a separate compatibility-sensitive decision. No `CHANGELOG.md` edit is needed; include user-visible performance context in the PR body if appropriate.
