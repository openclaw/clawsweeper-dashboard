## Summary

The latest revision narrows the patch appropriately, but the prior blocking deadline defect remains: each error-body chunk receives a fresh timeout, so a continuously trickling response can still keep an outbound send pending indefinitely. The controlled-socket tests are useful regression coverage but do not satisfy the external-contributor real-behavior gate.

Likely related people: @vincentkoc and @zpbrent have recent merged Tlon behavior history; @dlauer is associated with the original Tlon integration history.

## What This Changes

Adds a fixed request timeout and idle-bounded error-body reads to Tlon outbound and SSE-side Urbit channel pokes, with controlled live-socket regression tests.

## Best Possible Solution

Carry one absolute deadline from request start through headers and error-body consumption, add a trickling-body regression case for both poke implementations, and provide redacted after-fix output from a real Urbit ship before merge.
