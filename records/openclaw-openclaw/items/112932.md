## Summary

Keep this PR open for a narrow auth-classification repair. The tombstone/re-seed design addresses a credible OAuth recovery failure and has focused tests, but the new permanent-failure predicate can classify the known `refresh_token_reused` rotation-race message as permanent when its provider text also says to sign in again; that conflicts with the PR’s stated requirement to keep this race transient.

## What This Changes

The PR adds a persisted dead-refresh marker for permanently rejected OAuth grants, allowing a different external Codex CLI credential to re-seed an otherwise wedged OpenAI auth profile while refusing to re-adopt the same dead grant.

## System Context

Agent runs obtain OAuth credentials from an auth-profile store, then the OAuth manager refreshes and persists rotating token material. External Codex CLI synchronization can seed an OpenAI profile, but its bootstrap gate currently treats any stored credential as occupied.

## Architecture Diagram

flowchart LR
  A[External Codex CLI credential] --> B[Auth-profile store]
  B --> C[OAuth refresh manager]
  C --> D{Refresh outcome}
  D -->|success| E[Persist rotated credential]
  D -->|permanent rejection| F[Dead-grant marker]
  F --> G[External re-seed gate]
  G --> H[OpenAI provider request]

## Best Possible Solution

Make `refresh_token_reused` unambiguously transient before any generic sign-in-again classification, add the exact combined provider message as a regression test, then attach redacted live terminal or log evidence showing the dead-grant marker and different-grant re-seed path.
