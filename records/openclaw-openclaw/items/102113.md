## Summary

Keep this issue open: current main and v2026.6.11 still record `non_deliverable_terminal_turn` as trajectory/display-state evidence without a generic outbound notification path for channel plugins, and the linked fix remains an open PR requiring maintainer API direction.

## What This Changes

The issue asks OpenClaw to surface non-deliverable terminal turns to channel plugins so Octo and other SDK channels do not silently miss a terminal failure reply.

## Best Possible Solution

Choose one generic non-deliverable terminal-turn delivery contract, then land or reshape https://github.com/openclaw/openclaw/pull/102117 with focused run-meta, auto-reply, followup, and channel/plugin SDK coverage.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw handle `non_deliverable_terminal_turn` for channel plugins by automatically pushing a core fallback through outbound delivery, by adding a public plugin SDK terminal-failure hook, or by leaving the behavior plugin-owned?

Rationale: Both viable fixes change user-visible delivery semantics, and the hook option changes the public plugin API, so automation should not choose the permanent owner boundary.

Likely owner: Vincent Koc

Owner reason: The strongest adjacent history ties this decision to silent-turn fail-closed behavior and outbound reply routing.

Owner confidence: medium

Options:

- **Core automatic fallback (recommended):** Core treats non-deliverable terminal turns as a generic terminal failure and sends the fallback through the existing outbound path so current plugins get protection by default.
- **Plugin SDK terminal hook:** OpenClaw adds a documented hook so channel plugins can render their own terminal-failure copy, trading control for opt-in implementation work.
- **Plugin-owned workaround:** Core leaves the contract unchanged and asks Octo and other plugins to inspect or recover their own terminal-failure cases.

## Reproduction Assessment

Yes at source level: current main records `non_deliverable_terminal_turn` and projects fallback text for display, but the run return shape and channel plugin outbound contract still have no terminal-failure notification path. I did not run a live Octo session.

## Solution Assessment

Unclear until maintainers choose the owner boundary: core-side automatic fallback is the broadest user protection, while an SDK hook gives plugins control at the cost of a new public contract.
