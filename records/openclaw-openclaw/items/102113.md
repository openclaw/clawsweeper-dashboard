## Summary

Keep open: current main still records `non_deliverable_terminal_turn` only in trajectory/display paths and does not notify SDK channel outbound delivery; open PR #102117 is the candidate fix but still needs maintainer contract direction and proof.

## What This Changes

Request that `non_deliverable_terminal_turn` produce an outbound notification or fallback message for channel plugins so Octo and other SDK channels do not go silent.

## Best Possible Solution

Choose one generic delivery contract, then land #102117 or a replacement with redacted real SDK-channel proof and focused tests for exactly-once fallback delivery.

Options:

- **Leave recovery plugin-owned:** Core keeps `message_tool_only` strict and expects Octo or other plugins to inspect run state or implement their own recovery loop.

## Solution Assessment

Unclear until maintainers choose the owner boundary; core fallback is the broadest user protection, while an SDK hook is cleaner plugin control at the cost of a new public contract.
