## Label Justifications

- `P1`: The issue describes an agent/channel workflow where a completed turn can leave the user with no visible channel notification.
- `impact:message-loss`: The reported failure is specifically that channel plugins receive no outbound notification or delivered fallback for a non-deliverable terminal turn.

## Summary

Keep open: current main still records `non_deliverable_terminal_turn` as trajectory/display-layer state, but there is no core or plugin-SDK path that reliably turns that terminal marker into an outbound notification for channel plugins. The generic terminal-copy and Discord guard issues overlap, but neither fully owns the third-party channel-plugin notification contract.

## What This Changes

The issue requests that `non_deliverable_terminal_turn` produce a channel-plugin-visible notification or SDK hook instead of only a display-projection fallback.

## Best Possible Solution

Centralize a sanitized non-deliverable terminal failure notice in the core final-delivery path, or deliberately add a narrow SDK lifecycle hook, with tests that cover external channel plugins and `message_tool_only` privacy boundaries.

Owner confidence: high

Options:

- **Core-Managed Terminal Failure Notice (recommended):** Route a generic, sanitized terminal-failure payload through the existing delivery pipeline when no committed delivery exists, while preserving explicit `message_tool_only`, room-event, and send-policy guardrails in tests.
- **Plugin SDK Hook:** Add a narrow hook such as `onNonDeliverableTurn` so channel plugins can decide how to surface the failure, at the cost of opt-in adoption and a new public API surface.
- **Keep Channel-Specific Fixes Only:** Leave OpenClaw core unchanged and ask affected plugins such as Octo to fix delivery envelopes or local fallback behavior, accepting that generic plugin channels may still miss this signal.
