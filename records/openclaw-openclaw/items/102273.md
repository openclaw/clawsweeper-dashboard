- `P3`: This is model-picker ergonomics with an existing CLI workaround and no blocked setup, data loss, crash, or runtime outage.

## Summary

Current main now satisfies the core provider-visibility request without a new config flag: the TUI labels picker rows as provider/model, and Control UI groups model choices by provider while rendering provider labels on each option. The fix is current-main only; no release tag contains the provider-aware picker commit yet.

## What This Changes

The issue requests an opt-in config flag to always show the provider in TUI and Control UI model pickers instead of only suffixing providers on friendly-name collisions.

## Best Possible Solution

Keep the current provider-visible picker behavior as the canonical default and avoid adding a new config flag unless a later setting solves a broader model identity problem.
