## Summary

This issue remains necessary: current main still resolves persisted ACP metadata as ready without a liveness check, while later turn execution contains fresh-handle retry logic that does not prove restart recovery occurs before the reported hang. The report is recent, detailed, and distinct from the pending-identity and poisoned-session reports, with no merged fix or current-release proof supporting closure.

## What This Changes

Recover ACP binding sessions after a gateway restart when persisted open-session state references a dead child process.

## Best Possible Solution

Make the acpx-owned ensure/resume path detect an unusable persisted process record, clear or close only that stale runtime state, and create a fresh handle within a bounded timeout while preserving valid resumable identities; add focused restart regression coverage at the manager/plugin boundary rather than a generic core startup sidecar.
