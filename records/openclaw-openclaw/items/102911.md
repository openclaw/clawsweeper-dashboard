## Summary

Keep this issue open: current main and the latest release still have the underscore-only Discord italics rebalance path, and https://github.com/openclaw/openclaw/pull/102926 is an open fix candidate rather than a merged implementation.

## What This Changes

The issue reports that Discord chunking can prepend an italics underscore before a markdown code fence or inline-code chunk, breaking Discord markdown rendering.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/102926, or an equivalent small fix, so italics rebalancing does not prepend underscores before backtick-starting Discord chunks and regression tests cover the boundary.

## Reproduction Assessment

Yes, at source level: a reasoning-italics message split before a backtick-starting chunk reaches `rebalanceReasoningItalics`, whose current guard only skips chunks already starting with `_`. I did not execute a runtime repro because this cleanup review is read-only.

## Solution Assessment

Yes, the narrow fix shape is to skip the italics reopen when the next chunk begins with code markup. Because an open linked PR already targets that exact guard, the best next step is review and land that candidate or an equivalent patch, not queue another fix PR.
