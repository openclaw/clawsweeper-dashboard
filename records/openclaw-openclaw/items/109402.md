## Summary

Keep open. Current main still lacks OS-enforced child-process resource budgets, but this is a new, cross-platform core execution contract rather than a narrow bug fix; maintainers should confirm the ownership and result semantics before implementation.

Likely related people: `steipete` is the strongest product-direction routing candidate (medium confidence).

## What This Changes

Add optional capability-reported memory, swap, CPU, and subprocess limits to OpenClaw’s shared process execution path, with explicit outcomes when a host cannot enforce them.

## Best Possible Solution

Define one lower-level `resourceBudget` contract on the runner/spawn boundary, preserve identical behavior when absent, report pre-launch capability declines separately from process termination, and prove a Linux cgroup/systemd adapter without promising unsupported-platform enforcement.

## Risks / Open Questions

- Platform adapters have materially different guarantees: Linux cgroup/systemd capabilities, CPU quota versus scheduling weight, swap controls, and unsupported-host behavior need one explicit contract.
- Wrapping execution through an OS adapter could alter process identity, signal propagation, process-tree cleanup, exit attribution, and cancellation behavior that existing callers rely on.
- Changing shared command option and result surfaces may affect internal callers and the plugin runtime API, so capability-decline and upgrade behavior need focused compatibility review.
