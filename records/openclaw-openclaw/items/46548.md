## Summary

Keep open: current main and v2026.6.11 still preserve compact user-visible tool warnings without ordinary failure reasons, and retry success is only internal state cleanup. The related merged PRs are useful partial fixes, but the remaining behavior needs maintainer product/security policy before implementation.

## What This Changes

The issue asks for chat-visible tool failure warnings to include the failure reason and to show recovery or retry-success confirmation when a later attempt succeeds.

## Best Possible Solution

Define a maintainer-approved warning policy that distinguishes unresolved failures from recovered same-turn failures, redacts channel-visible error reasons safely, and updates payload construction plus focused tests around that contract.

## Reproduction Assessment

Yes: current source and tests show ordinary compact warnings can still omit detailed reasons, and same-action retry success only clears `lastToolError` rather than surfacing a recovered status. I did not run live channel proof because this review was read-only.

## Solution Assessment

Unclear until maintainers choose the policy: adding raw reasons everywhere is not the best fix because it can leak sensitive details, but the current compact warning behavior leaves operators without enough recovery context.
