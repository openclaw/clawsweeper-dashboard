## Summary

Keep open: current main and v2026.6.11 still do not satisfy the central request. Normal chat warnings still intentionally hide most failure reasons, and same-action retry success clears internal error state without emitting a visible recovered/succeeded confirmation; the remaining change needs a security-sensitive product decision before implementation.

## What This Changes

Requests chat-visible tool failure warnings to include a safe failure reason and to confirm when a failed tool is retried successfully.

## Best Possible Solution

Define a recovery-aware, sanitized warning contract: normal chat should show safe failure classes and same-action recovered status, while raw commands, paths, and sensitive details stay behind trusted verbose diagnostics or explicit operator policy.
