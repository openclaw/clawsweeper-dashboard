## Summary

Keep open: current main and v2026.6.11 still only include raw tool failure details in narrow detail modes and clear same-action retry state internally without a visible recovery confirmation. The remaining behavior is valid, but it needs maintainer product and security policy before implementation.

## What This Changes

Requests chat-visible tool failure warnings to include a safe failure reason and to show recovery or retry-success when a later same-turn retry resolves the failure.

## Best Possible Solution

Define a core warning policy that emits redacted, safe failure summaries and a recovered-before-final state for matching same-turn retries, while preserving successful side-effect receipts and keeping raw diagnostics out of untrusted channels.
