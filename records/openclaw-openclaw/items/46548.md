## Summary

Keep open: current main still omits ordinary tool failure reasons from compact chat warnings and clears matching retry state internally without a visible recovered/retry-success confirmation. The source path is clear, but changing default chat-visible failure copy needs maintainer product and security policy.

## What This Changes

The issue requests chat-visible tool failure messages that include a failure reason and show when a later retry or recovery succeeded.

## Best Possible Solution

Define a core warning policy that emits redacted safe failure summaries and a recovered-before-final state for matching same-turn retries while keeping raw diagnostics out of untrusted channels.
