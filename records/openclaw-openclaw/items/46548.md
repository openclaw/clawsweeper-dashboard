- `impact:message-loss`: The report and follow-up describe ambiguous failure warnings after accepted external sends, which can cause duplicate or mistaken messaging actions.

## Summary

Keep open: current main and the latest release still do not meet the central request because normal chat warnings intentionally omit most failure reasons and same-action retry success is only reflected by clearing internal state, not by a visible recovery confirmation. Related open work covers warning order, suppression, native recovery, and recovered-progress hiding, but none fully owns this issue's failure-reason plus retry-confirmation acceptance criteria.

## What This Changes

The issue asks for chat-visible tool failure messages to include the failure reason and to show when a retry or same-turn recovery succeeded.

## Best Possible Solution

Define a recovery-aware, sanitized warning contract: normal chat should show safe failure classes and same-action recovered status, while raw commands, paths, and sensitive detail stay behind trusted verbose diagnostics or explicit operator policy.

Options:

- **Sanitized Recovery Status (recommended):** Show a scrubbed reason class or safe receipt plus a same-action recovered confirmation, keeping raw commands and paths in verbose/full diagnostics.
- **Keep Details Hidden:** Keep the current normal-mode warning contract and handle only narrower ordering or suppression bugs in related issues.
- **Trusted-Channel Details:** Expose richer failure reasons only for explicitly trusted operator channels or admin modes, accepting a larger configuration and audit surface.
