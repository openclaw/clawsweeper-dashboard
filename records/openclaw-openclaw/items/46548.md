## Summary

Keep open: current main and the latest release still omit ordinary compact tool failure reasons and only clear internal retry state, while the June 23 production comment adds a credible duplicate-side-effect risk that needs maintainer product and security policy.

## What This Changes

The issue requests chat-visible tool failure messages that include a safe failure reason and a confirmation or recovery state when a retry later succeeds.

## Best Possible Solution

Define a core chat-warning policy that emits redacted, safe failure summaries and a recovered state for matching same-turn retries, while preserving successful side-effect receipts and keeping raw diagnostics out of untrusted channels.
