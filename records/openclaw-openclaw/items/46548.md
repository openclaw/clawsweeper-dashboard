## Label Justifications

- `P2`: The issue affects confusing and potentially unsafe tool-failure reporting in channel workflows, but the remaining work is a bounded product/security policy fix rather than a runtime outage.
- `impact:security`: Failure-reason surfacing can expose commands, paths, provider output, customer data, or secrets across a chat boundary unless redacted.
- `impact:message-loss`: A stale or unclear failure warning after successful external sends can prompt duplicate retries and misrepresent delivered message state.

## Summary

Keep open: current main and the latest release still only partially address the request. Ordinary chat-visible tool warnings still omit failure reasons unless a detail policy allows them, and same-action retry success clears internal error state without emitting a user-visible recovery confirmation.

## What This Changes

The issue asks for chat-visible tool failure warnings to include a safe failure reason and to indicate when a failed action was later retried or recovered successfully.

## Best Possible Solution

Define a channel-safe tool-failure notification policy that shows redacted actionable reasons when appropriate and emits recovered-state notices only when a matching failed action is later resolved.
