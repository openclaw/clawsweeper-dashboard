## Summary

Keep open: current main and the latest release still only partially address this request. Normal chat-visible tool warnings intentionally hide most raw failure reasons, and same-action retry success clears internal error state without creating the requested visible recovery confirmation.

## What This Changes

Request chat-visible tool failure warnings to show a safe failure reason and confirm when a retry or same-action recovery succeeds.

## Best Possible Solution

Define a recovery-aware, sanitized warning contract: normal chat should show safe failure classes and same-action recovered status, while raw commands, paths, and sensitive detail stay behind verbose or explicitly trusted diagnostics.

## Solution Assessment

Unclear as an implementation path: appending raw tool errors to normal chat would not be the best fix. The maintainable solution needs a sanitized reason and recovery-status policy before code should change.
