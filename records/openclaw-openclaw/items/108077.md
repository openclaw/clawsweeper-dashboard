## Summary

Keep open for a maintainer timeout-contract decision before merge. The patch fixes a real indefinite pending state and has strong real-HTTP proof with no discrete correctness or security finding, but the new unconditional 30-second cutoff is an upgrade-sensitive behavior contract not established by the current Nostr endpoint documentation or discussion.

## What This Changes

Adds 30-second AbortController deadlines and abort-aware JSON parsing to Control UI Nostr profile publish/import helpers, with focused regression tests.

## Best Possible Solution

Define one documented timeout contract owned by the Nostr profile endpoint, keep server work bounded, and set the Control UI abort deadline slightly beyond that contract while preserving the patch's body-read propagation and timer cleanup.

## Maintainer Decision

Question: Should Control UI Nostr profile publish/import enforce an unconditional 30-second client deadline, or should its deadline derive from a bounded gateway operation contract?

Rationale: Bounded failure is clearly preferable to an indefinite hang, but the maximum duration that may terminate a valid slow operation is a product and compatibility choice that source inspection cannot safely determine.

Likely owner: steipete

Owner confidence: medium

Options:

- **Derive the gateway contract (recommended):** Define a bounded server-side maximum and set the Control UI deadline slightly above it so stalled work terminates without arbitrarily cutting off valid operations.
- **Confirm a fixed 30 seconds:** Accept that any publish or import exceeding 30 seconds fails in Control UI and document and test that value as the supported contract.

## Reproduction Assessment

Yes at source level: current main awaits both fetch and body parsing without cancellation, so a server that leaves either stage pending reproduces the hang. The submitted real-HTTP proof directly demonstrates the corresponding stalled-body case after the fix, though it was not run against the unmodified current-main helper.

## Solution Assessment

Unclear. Abort propagation, timer cleanup, and coverage are the narrow maintainable fix shape, but the hard-coded 30-second value is best only if maintainers confirm it against the endpoint's intended maximum duration.
