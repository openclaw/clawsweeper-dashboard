## What This Changes

The PR skips the gateway wrapper’s redundant plugin route-registry lookup after the lazy plugin HTTP handler has loaded, while testing dynamic route removal and replacement.

## System Context

Gateway HTTP requests pass through a lazy plugin-route dispatch stage before reaching plugin-owned handlers. The stage must avoid importing plugin HTTP runtime when no routes exist, while already-loaded handlers must continue to follow the active route registry.

## Architecture Diagram

  D --> E[Lazy-load plugin handler]
  C -- Yes --> E
  E --> F[Resolve active plugin routes]
  F --> G[Plugin response or next handler]

## Best Possible Solution
