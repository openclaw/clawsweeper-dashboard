## Summary

Keep open: the PR is a good direction for the usage-cost cache bloat, but it still misses the upgrade path for already-fresh old-shape cache files, so existing affected users may keep the duplicated per-entry fingerprints on disk.

## What This Changes

The branch moves usage-cost cache `pricingFingerprint` storage to a cache-level field, strips it from serialized entries, invalidates entries on pricing changes, and adds a cold-cache round-trip test.

## Best Possible Solution

Land one canonical fix that stores the pricing fingerprint once per cache object, preserves pricing-change invalidation, and rewrites or rebuilds existing v4 per-entry caches on the next refresh.

## Reproduction Assessment

Yes, at source level. A fresh old-shape cache can be normalized in memory, but the refresh path only writes when stale/deleted entries mark the cache dirty, so the old on-disk duplication can remain.

## Solution Assessment

No, not yet. Cache-level fingerprint storage is the right narrow shape, but the branch needs an upgrade path that rewrites or rebuilds existing fresh old-shape caches.
