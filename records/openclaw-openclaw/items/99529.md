## Summary

Keep open: the branch is aimed at the right cache-storage boundary, but it still misses already-fresh existing cache files because normalization compacts only in memory and no write is forced when all entries are fresh.

## What This Changes

The branch moves usage-cost cache `pricingFingerprint` storage to the cache file level, strips it from serialized entries, clears entries when pricing changes, and adds a cold cache round-trip test.

## Best Possible Solution

Land one canonical fix that stores the pricing fingerprint once per cache object, preserves pricing-change invalidation, and rewrites or rebuilds existing fresh old-shape caches on the next refresh.

## Reproduction Assessment

Yes. Source inspection shows a fresh old-shape cache can be normalized in memory, but `refreshCostUsageCacheForPath` only writes when `cacheMutated` or `dirtyCount` is set, so an all-fresh cache is not compacted on disk.

## Solution Assessment

No, not yet. Cache-level fingerprint storage is the right narrow solution, but the PR also needs an upgrade path that rewrites or rebuilds existing fresh old-shape caches rather than waiting for unrelated staleness.
