## Summary

## What This Changes

The PR moves usage-cost cache pricing fingerprints to a cache-level field, strips them from serialized entries, rewrites migrated old-shape caches, invalidates entries on pricing changes, and adds a cache round-trip test.

## Best Possible Solution

Land one canonical cache-level fingerprint fix, preferably a versioned v5 rebuild or a tightly tested v4 migration that never serializes internal migration markers.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 store `pricingFingerprint` on every usage-cost cache file entry, matching the linked large-cache report. I did not run a large live cache replay in this read-only review.

## Solution Assessment

Acceptable but not clearly best. Cache-level fingerprint storage is the right narrow fix, but a v5 rebuild is cleaner than steady-state dual-shape v4 normalization unless maintainers explicitly prefer this migration path.
