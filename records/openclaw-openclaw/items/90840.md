## Label Justifications

- `P1`: A shipped direct-message workflow can expose the wrong completion and suppress the intended parent response for active multi-agent users.

## Summary

Keep open: the latest-release Telegram report on July 21, 2026 independently confirms that direct subagent completion delivery can send the child’s raw result while dropping the parent’s generated reply. The linked open PR addresses the `sessions_yield` sibling only; this non-yield direct-message fallback still needs a security and delivery-semantics decision.

## What This Changes

The issue requests that subagent `mode="run"` completions remain internal to the parent session so direct-chat users receive only an intentional parent reply.

## Best Possible Solution

Define a typed completion-delivery contract: direct external delivery must use only an explicitly marked public parent reply, while child completion text remains internal; absent that signal, do not mirror the child result to the external DM.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: For direct subagent completions without an explicit messaging-tool send, should OpenClaw suppress external delivery entirely, or add a typed sanitized/public parent-reply signal that can be delivered safely?

Rationale: The observed fallback leaks internal child output, but a narrow suppression changes no-reply behavior and auto-promoting parent final text can leak the same private content through another field.

Likely owner: openperf

Owner reason: Their open work covers the adjacent announce lifecycle and they are the strongest available routing candidate from the supplied feature context.

Owner confidence: medium

Options:

- **Add an explicit public completion signal (recommended):** Introduce a typed parent-owned public-delivery result and send only that to the channel, keeping child completion text internal.
- **Fail closed for message-tool-only delivery:** Remove or gate the direct child-text fallback so absent an explicit message-tool send there is no external completion message.
- **Retain the child fallback:** Keep current empty-parent resilience, accepting that internal child text can reach the requester’s direct channel.
