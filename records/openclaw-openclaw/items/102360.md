## Summary

Keep open. Current main still prepares the Crestodian approval-intent classifier without the utility-model flag, and the shared selector only honors `utilityModel` when that flag is set, so the reported model-tier bug remains actionable.

## What This Changes

Route Crestodian's approval-intent classifier through the configured `utilityModel` for ambiguous approval replies instead of the primary model.

## Best Possible Solution

Add `useUtilityModel: true` to the approval-intent model preparation and cover the ambiguous-message path, while leaving the Crestodian command planner on the primary model.

Yes, from source inspection. With a configured `utilityModel`, the approval classifier's current call omits `useUtilityModel: true`, and the selector only reads `utilityModel` when that flag is present.
