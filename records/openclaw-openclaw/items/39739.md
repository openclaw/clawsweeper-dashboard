## Summary

Keep open: current main and the latest release still only support exact parsed origins or the global `*`, while this issue asks for a new scheme-level wildcard policy on a Gateway browser-origin security boundary.

## What This Changes

Request support for scheme-level wildcard entries such as `chrome-extension://*` in `gateway.controlUi.allowedOrigins` so Chrome extension origin IDs can change without reconfiguration.

## Best Possible Solution

Decide a constrained Gateway browser-origin wildcard contract first, then implement it in the shared origin helper with exact/wildcard negative tests, WebSocket and trusted-proxy coverage, and docs.
