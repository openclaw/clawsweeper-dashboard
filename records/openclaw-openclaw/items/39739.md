## Summary

Keep open: current main and v2026.6.11 still support only exact full-origin matches or the global `*` entry for `gateway.controlUi.allowedOrigins`; related work covers exact custom-scheme origins, constrained loopback patterns, or the official extension relay, but not this scheme-level wildcard policy request.

## What This Changes

The issue requests support for scheme-level wildcard entries such as `chrome-extension://*` in `gateway.controlUi.allowedOrigins`.

## Best Possible Solution

Resolve the security policy first: either adopt a narrow schema-validated origin-pattern design with audit/docs/tests, or narrow this in favor of exact custom-scheme matching plus the dedicated `/browser/extension` route.
