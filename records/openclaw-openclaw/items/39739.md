## Summary

Keep open: current main still does not support scheme-level wildcard origin entries, and this request changes a Gateway browser-origin security boundary that needs maintainer product/security direction before implementation.

## What This Changes

The issue requests support for `gateway.controlUi.allowedOrigins` entries such as `chrome-extension://*` so Chrome extension clients do not need exact extension IDs in config.

## Best Possible Solution

Keep this open until maintainers choose a constrained origin-pattern policy for extension origins; exact custom-scheme allowlisting PRs can land separately but do not close the wildcard semantics requested here.
