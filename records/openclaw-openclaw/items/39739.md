## Summary

Keep open: current main and the latest release still only accept exact parsed origins or the global `*`, while scheme-level wildcard support would widen Gateway browser-origin authorization and needs an explicit security/product decision.

## What This Changes

Support opt-in scheme-level wildcard entries such as `chrome-extension://*` in `gateway.controlUi.allowedOrigins` so changing Chrome extension IDs do not require repeated config edits.

## Best Possible Solution

Adopt a constrained, security-reviewed origin pattern contract for this boundary, preferably a narrow parser or dedicated pattern surface rather than arbitrary prefix matching, while exact opaque-origin bugs continue through their linked PRs.
