## Summary

Keep open: current main and the latest release still lack scheme-level wildcard support for `gateway.controlUi.allowedOrigins`; related work covers exact opaque-origin matching, constrained loopback-port patterns, or the separate built-in extension relay, not the requested Gateway allowlist policy.

## What This Changes

The issue requests support for scheme-level wildcard entries such as `chrome-extension://*` in `gateway.controlUi.allowedOrigins`.

## Best Possible Solution

Decide the allowed wildcard grammar for Gateway browser origins first, then implement the narrowest accepted matcher with shared helper coverage for WebSocket, trusted-proxy HTTP, docs, and negative security cases.

Rationale: This changes which browser origins may reach Gateway HTTP/WebSocket handling, and the current documented contract intentionally allows only full origins plus the global `*` escape hatch.

Options:

- **Approve a constrained grammar (recommended):** Define a small documented pattern contract, implement it in the shared origin helper, and cover allowed, rejected, exact, global wildcard, WebSocket, and trusted-proxy HTTP cases.
- **Keep exact origins only:** Reject scheme wildcards for this boundary and rely on exact opaque-origin fixes plus the built-in Chrome extension relay for supported extension workflows.
- **Defer to pattern-design work:** Wait for the constrained loopback-pattern contract to settle, then decide whether Chrome extension scheme wildcards belong in that same surface or a separate one.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: current `checkBrowserOrigin` only accepts exact parsed origins or global `*`, and Node serializes `chrome-extension://...` origins as `null`. I did not run a live Gateway WebSocket reproduction.

## Solution Assessment

No, the issue body's prefix-loop sketch is only a plausible implementation. The best fix is a maintainer-approved constrained grammar with shared Gateway tests and docs, not an ad hoc `endsWith("*")` prefix match on a security boundary.
