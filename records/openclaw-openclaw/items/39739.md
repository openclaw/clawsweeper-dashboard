## Summary

Keep open: current main and latest release still only support exact parsed origins or global `*`, while the requested `chrome-extension://*` behavior remains a Gateway browser-origin security policy decision rather than a narrow parser bug.

## What This Changes

The issue requests scheme-level wildcard support in `gateway.controlUi.allowedOrigins`, especially `chrome-extension://*` for changing Chrome extension IDs.

## Best Possible Solution

Define a maintainer-approved constrained origin-pattern policy for extension origins, then implement it consistently in origin checks, config help/schema, security audit, docs, and focused allow/reject tests.
