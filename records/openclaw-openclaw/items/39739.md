## Summary

Keep open: current main and v2026.6.11 still only accept exact parsed origins or the global `*`, while the requested scheme-level wildcard changes Gateway browser-origin authorization. Related open PRs cover exact opaque origins or loopback port patterns, but none safely owns `chrome-extension://*` wildcard policy.

## What This Changes

Support scheme-level wildcard entries such as `chrome-extension://*` in `gateway.controlUi.allowedOrigins` for browser-extension Gateway WebSocket clients.

## Best Possible Solution

Define a constrained, security-reviewed origin pattern contract for extension/custom-scheme browser origins, with explicit matching rules, docs, audit coverage, and Gateway handshake tests before implementation.
