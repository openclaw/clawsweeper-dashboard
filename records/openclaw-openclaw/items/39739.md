## Summary

Keep open: current main and v2026.6.11 still accept only exact parsed origins or the global `*`, while the requested `chrome-extension://*` grammar would widen a Gateway origin authorization boundary and needs maintainer security/product direction.

## What This Changes

Support scheme-level wildcard patterns such as `chrome-extension://*` in `gateway.controlUi.allowedOrigins` so Chrome extension origins can remain allowlisted when the extension ID changes.

## Best Possible Solution

Define a constrained, security-reviewed origin pattern contract for extension or custom-scheme origins, with parser rules, docs, audit behavior, and negative Gateway tests; keep exact-origin fixes separate from wildcard policy.
