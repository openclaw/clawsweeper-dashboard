## Summary

Keep open: current main and the latest release still only match exact parsed origins or the global `*`, and the open related PRs cover exact opaque origins or different constrained pattern cases rather than the requested `chrome-extension://*` policy.

## What This Changes

Request support for opt-in scheme-level wildcard entries like `chrome-extension://*` in `gateway.controlUi.allowedOrigins` so Chrome extension clients do not need config updates when their extension ID changes.

## Best Possible Solution

Define a maintainer-approved constrained origin-pattern policy, then update the shared origin checker, HTTP/WS callers, security audit/docs, and regression tests together.
