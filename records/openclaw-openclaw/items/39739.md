## Summary

Keep open: current main and the latest release still only support exact parsed origins or the global `*`, while scheme-level wildcard support would change a Gateway browser-origin authorization boundary and needs maintainer security/product approval.

## What This Changes

The issue requests scheme-level wildcard support such as `chrome-extension://*` in `gateway.controlUi.allowedOrigins` so Chrome extension origins can survive extension ID changes.

## Best Possible Solution

Decide the accepted Gateway browser-origin wildcard grammar first, then implement the narrowest approved matcher with shared HTTP/WS coverage, docs, and negative security tests.

- **Defer to broader origin-pattern design:** Wait for the loopback pattern work to settle and decide whether extension scheme wildcards belong in the same contract or a separate one.
