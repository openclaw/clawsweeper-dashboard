## Summary

Keep open: current main and v2026.6.11 still only support exact parsed origins or the global `*` entry for `gateway.controlUi.allowedOrigins`; related work covers exact custom-scheme origins, constrained loopback patterns, or the official Chrome extension route, but not this scheme-level wildcard policy request.

## What This Changes

Support opt-in scheme-level wildcard entries such as `chrome-extension://*` in `gateway.controlUi.allowedOrigins` so Chrome-extension WebSocket origins remain allowed when extension IDs change.

## Best Possible Solution

Resolve the origin-policy contract first: either add a constrained, schema-validated and documented pattern surface with audit and negative tests, or explicitly keep Chrome extension access on exact origins plus the dedicated `/browser/extension` route.
