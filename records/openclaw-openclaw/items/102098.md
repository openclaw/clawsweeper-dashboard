- `maturity:stable`: The affected gateway/agent runtime authorization path maps to the M4 Stable gateway-runtime surface in qa/maturity-scores.yaml.

## Summary

Keep open: current main and the latest release still lack a trusted cron/subagent requester-identity contract for OAuth-dependent plugin tools, and the remaining work is a security-sensitive Plugin SDK/runtime API decision rather than a narrow bug fix.

## What This Changes

The issue requests a generic user-context mechanism for cron and subagent execution so OAuth-dependent plugin tools can run as a user.

## Best Possible Solution

Design a typed, runtime-supplied requester identity contract for cron and subagent execution in the Plugin SDK, with explicit consent, audit, privacy, revocation, authorization, and concurrency rules plus focused cron, subagent, and plugin-tool coverage.

## Solution Assessment

Unclear until maintainers choose the security and API shape. A typed runtime/Plugin SDK requester-context seam is safer than process.env or fixed sender config fallbacks.
