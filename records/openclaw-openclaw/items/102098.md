## Summary

Keep open: current main and v2026.6.11 still lack a trusted requester-identity contract for cron and spawned subagent runs, and the remaining work is a security-sensitive Plugin SDK/runtime API decision rather than a narrow bug fix.

## What This Changes

Cron and subagent sessions are requested to carry trusted user identity context so OAuth-backed plugin tools can run outside inbound user-message handlers.

## Best Possible Solution

Design a typed runtime-supplied requester identity contract for cron and subagent execution in the Plugin SDK, with explicit consent, audit, privacy, revocation, concurrency, and multi-account rules.
