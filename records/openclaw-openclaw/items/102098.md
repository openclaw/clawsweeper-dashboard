## Summary

Keep open: current main and v2026.6.11 still do not provide a cron or sessions_spawn requester-identity contract for OAuth-dependent plugin tools, and the fix is a security-sensitive Plugin SDK/runtime API decision rather than conservative cleanup.

## What This Changes

The issue requests a generic requester/user-context mechanism for cron and subagent executions so OAuth-dependent plugin tools can run outside inbound message handling.

## Best Possible Solution

Design a typed, runtime-supplied requester identity contract for cron and subagent execution in the Plugin SDK/Gateway boundary, with explicit authorization, audit, privacy, and revocation rules plus focused cron, subagent, and plugin-tool coverage.
