## Summary

Keep open: current main still lacks a cron/subagent requester-context contract for OAuth-dependent plugin tools, and the remaining work is a security-sensitive Plugin SDK/runtime API decision rather than a narrow bug fix.

## What This Changes

The issue requests a generic requester identity contract for cron tasks and sessions_spawn subagents so OAuth-dependent plugin tools can act for an authorized user outside inbound message handling.

## Best Possible Solution

Design a typed runtime and Plugin SDK requester-identity contract for cron and subagent execution, with explicit authorization, consent, audit, revocation, privacy, and concurrency semantics before wiring it into plugin OAuth tools.
