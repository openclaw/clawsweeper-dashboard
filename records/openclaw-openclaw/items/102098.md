## Summary

Keep open: current main still lacks a cron/subagent requester-context contract for OAuth-dependent plugin tools, and the requested fix is a security-sensitive runtime and Plugin SDK API decision rather than a narrow bug fix.

## What This Changes

Request a generic requester user-context mechanism for cron agent turns and sessions_spawn/subagent runs so OAuth-dependent plugin tools can resolve the acting user.

## Best Possible Solution

Design a typed runtime-supplied requester identity contract for cron and subagent execution in the Gateway protocol and Plugin SDK, with explicit authorization, audit, privacy, and revocation rules, rather than env-var or fixed-sender fallbacks.
