## Summary

Keep open: current main and the latest release still lack a cron/subagent requester-context contract for plugin OAuth tools, and the requested identity propagation crosses Plugin SDK, cron API, auth, and security-boundary design.

## What This Changes

Request a generic way for cron agent turns and spawned subagent sessions to carry user/requester context so OAuth-dependent plugin tools can run outside inbound message handling.

## Best Possible Solution

Design a typed, privacy-aware cron/subagent requester-context contract in the Plugin SDK with explicit auth, audit, and ownership semantics plus focused cron, subagent, and plugin-tool tests.
