## Summary

Keep open: current main and the latest release still lack a cron or Plugin SDK contract for carrying a scheduled run's requester/user identity into plugin tools, and the requested OAuth user-context surface needs maintainer API and security direction rather than cleanup closure.

## What This Changes

The issue requests a way for cron agent turns to carry user context such as sender and account identity so OAuth-dependent plugin tools can run outside an inbound message handler.

## Best Possible Solution

Define a typed, privacy-aware scheduled-run requester context contract in cron and the Plugin SDK, then let Yach and similar plugins consume that explicit context with docs and focused cron/plugin tests.
