## Summary

Keep open: current main and v2026.6.11 still lack a cron/subagent requester-context contract for OAuth-dependent plugin tools, and the remaining work is a security-sensitive Plugin SDK/runtime API decision rather than a narrow bug fix.

## What This Changes

The issue requests a generic way for cron jobs and spawned subagent sessions to carry trusted user identity for plugin OAuth tool calls.

## Best Possible Solution

Design a typed, runtime-supplied requester identity contract for cron and subagent execution in the Plugin SDK, with explicit consent, audit, privacy, and authorization rules plus focused cron, subagent, and plugin-tool coverage.
