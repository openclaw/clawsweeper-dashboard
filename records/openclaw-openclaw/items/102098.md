## Summary

Keep open: current main and v2026.6.11 still lack a cron/subagent requester-context contract for OAuth-dependent plugin tools, and the remaining work is a security-sensitive Plugin SDK/runtime API decision rather than conservative cleanup.

## What This Changes

The issue requests a generic requester user-context mechanism for cron jobs and `sessions_spawn` so plugin OAuth tools can resolve per-user identity outside inbound message turns.

## Best Possible Solution

Design a typed runtime-supplied requester identity contract for cron and subagent execution in the Plugin SDK, with explicit consent, audit, privacy, revocation, authorization, and regression coverage across cron, subagents, and plugin tools.
