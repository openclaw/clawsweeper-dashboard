## Summary

Keep open: current main still lacks a cron/subagent requester-context contract for OAuth-dependent plugin tools, and the remaining work is a security-sensitive runtime and Plugin SDK API decision rather than a narrow cleanup close.

## What This Changes

The issue requests a generic user context contract for cron and subagent executions so OAuth-dependent plugin tools can identify a requester outside inbound message handling.

## Best Possible Solution

Design a typed runtime and Plugin SDK requester-identity contract for cron and subagent execution, with explicit consent, audit, privacy, revocation, and concurrency semantics instead of process.env or fixed sender fallbacks.
