## Summary

Keep open: current main and v2026.6.11 still do not provide a requester/user identity contract for cron agent turns or sessions_spawn child runs, and the requested fix is a security-sensitive runtime/Plugin SDK API decision rather than conservative cleanup.

## What This Changes

Add a generic runtime/Plugin SDK requester identity context for cron agent turns and sessions_spawn subagent runs so OAuth-dependent plugin tools can resolve user authorization outside inbound message handlers.

## Best Possible Solution

Design one typed runtime-supplied requester identity contract for cron and subagent execution in the Plugin SDK, with explicit consent, audit, privacy, revocation, and authorization rules plus focused cron, subagent, and plugin-tool coverage.
