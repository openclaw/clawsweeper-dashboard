## Summary

Keep open: current main and v2026.6.11 still lack a generic cron/subagent requester identity contract for OAuth-dependent plugin tools, and the remaining work is a security-sensitive Plugin SDK/runtime API decision.

## What This Changes

The issue requests a generic requester/user context for cron jobs and `sessions_spawn` so OAuth-dependent plugin tools can resolve user-scoped credentials.

## Best Possible Solution

Design a typed runtime-supplied requester identity contract for cron and subagent execution in the Plugin SDK/protocol, with explicit consent, audit, revocation, privacy, and authorization rules plus coverage across cron, subagent, and plugin tools.
