## Summary

Keep this PR open for explicit maintainer review. The focused patch and supplied native-Windows proof address the reported PowerShell 7 discovery failure, but it deliberately changes precedence in the shared Windows resolver for every extensionless shell lookup; the existing `maintainer` label requires a human acceptance of that compatibility policy before merge.

## What This Changes

This PR makes Windows agent shell discovery prefer a native `.exe` found anywhere on `PATH`, such as PowerShell 7, before accepting an earlier extensionless shim, and adds regression tests for the PowerShell fallback path.

## System Context

Agent sessions and process commands use a shared shell resolver to locate default executables. On Windows, the selected path is handed to process and PTY launch paths, so resolver precedence determines whether users receive PowerShell 7 or the Windows PowerShell 5.1 fallback.
