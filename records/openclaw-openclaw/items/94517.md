  - body: This was raised in the prior cycle and is still not fixed. Preserve the existing label in the rebuilt record and add a regression test.
  - confidence: 0.9
- **[P2] Mirror operator labels in the Control UI:** `src/cli/devices-cli.runtime.ts:942`
  - body: The PR applies the new label precedence only in the CLI. `device.pair.list` is also consumed by the Control UI, but `ui/src/lib/nodes/index.ts` still has no `operatorLabel` field and `ui/src/pages/nodes/view.ts` still renders `displayName || deviceId`, so web users keep seeing the old name/id after a rename. Add the field, render it with the same precedence, and cover it in the nodes device view test.
  - confidence: 0.88
- **[P2] Sanitize the rename label before gateway logging:** `src/gateway/server-methods/devices.ts:562`
  - body: This new log line writes `trimmed` directly even though the label comes from the RPC caller and `NonEmptyString` still allows control characters and ANSI escapes. Use the existing log-safe formatter/sanitizer before interpolation so a device label cannot forge gateway log lines or inject terminal escapes.
  - confidence: 0.93
- **[P2] Remove the unrelated release-age exclusions:** `pnpm-workspace.yaml:93-94`
  - body: The branch adds two `minimumReleaseAgeExclude` entries while implementing a device rename command.   - confidence: 0.87
- **[P3] Document the devices rename command:** `src/cli/devices-cli.ts:98-101`
  - body: The CLI now registers a user-facing `openclaw devices rename` command, but the Devices CLI docs still list `list`, `approve`, `reject`, `remove`, `clear`, `rotate`, and `revoke` only. Add the command syntax, scope/authorization behavior, label precedence, and JSON behavior so users and copied setup snippets do not drift from the CLI.
  - confidence: 0.84
