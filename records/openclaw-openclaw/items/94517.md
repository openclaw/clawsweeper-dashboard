## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P2] Preserve labels across pairing rebuilds:** `src/infra/device-pairing.ts:115`
  - body: Adding `operatorLabel` to the stored record and patch path is not enough because `buildApprovedPairedDevice` rebuilds an existing approved record without copying the existing label. Repair or reapproval of the same device will silently drop the rename, so carry the field through and add regression coverage.
  - confidence: 0.94
- **[P2] Mirror renamed labels in Control UI:** `src/cli/devices-cli.runtime.ts:942`
  - body: This changes the CLI table to prefer `operatorLabel`, but the same `device.pair.list` response also feeds the Control UI, whose paired-device renderer still uses `displayName` or `deviceId`. After a successful rename, CLI and Control UI can show different names for the same device.
  - confidence: 0.92
- **[P2] Sanitize labels before gateway logging:** `src/gateway/server-methods/devices.ts:562`
  - body: `displayName` is only validated as a non-empty string, then `label=${trimmed}` is written directly to Gateway logs. A label containing newlines or control sequences can forge or obscure log output; sanitize the label with the existing log-safe helper or omit the raw value.
  - confidence: 0.9
- **[P3] Document the devices rename surface:** `src/cli/devices-cli.ts:98-101`
  - body: This adds a new public `openclaw devices rename` command and `device.pair.rename` method, but the public devices docs still list only the older command set. Add the command syntax, scope behavior, and label precedence so the shipped surface is discoverable.
  - confidence: 0.86
