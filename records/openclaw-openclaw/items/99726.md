## Summary

Keep this PR open for maintainer review: the lifecycle-owned readiness preflight is the right direction, but the branch currently changes shared Go skill install environment handling beyond onboarding and can override an existing user's Go install destination.

## What This Changes

The PR adds lifecycle installer readiness preflight for brew, Go, and uv skill installers, uses it from onboarding to group skipped manual prerequisites, updates docs/i18n copy, and expands installer fallback tests.

## Best Possible Solution

Keep the lifecycle-owned readiness preflight, but preserve existing Go install destinations for already-installed Go and limit fallback GOBIN/PATH changes to OpenClaw-bootstrapped Go paths with matching docs and tests.

## Reproduction Assessment

## Solution Assessment

No. The lifecycle preflight is the right owner-boundary fix, but the current patch also changes shared Go install destination behavior and should preserve existing Go env semantics before merge.
