## What This Changes

The PR changes Unix process-tree cleanup to verify process-group leadership before group kill, passes `detached: true` through known detached-spawn cleanup paths, and adds focused kill-tree regression and fail-safe tests.

## Best Possible Solution

Land this PR or an equivalent process-cleanup fix after maintainer acceptance of the compatibility-sensitive signal semantics and a green or explained CI state, then close the linked issue through the merge.

## Reproduction Assessment

Yes. Current main and `v2026.6.11` still compute omitted-`detached` Unix cleanup as group kill, and the linked issue provides a managed macOS gateway SIGTERM scenario; I did not rerun the full live Telegram/launchd flow in this read-only review.

## Solution Assessment

Yes, this appears to be the best current fix shape: the shared helper enforces the process-group leader invariant for omitted callers while explicit `detached: true` preserves known detached process-group cleanup. A pure caller audit would leave future omitted callers as traps, while defaulting to direct-PID only would be safer but more likely to orphan descendants.
