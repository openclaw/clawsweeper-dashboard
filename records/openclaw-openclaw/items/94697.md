## Summary

The central leader-verification fix is sound, but this head still forces group signaling from two PID-only session paths that do not retain actual spawn mode. Those paths can represent service-managed attached children, so merging as-is can recreate the gateway-wide termination regression.

## What This Changes

The PR verifies Unix process-group leadership before group signaling and adds explicit detached overrides to process cleanup callers.

## Best Possible Solution

Keep the central leader verification, but use its checked default whenever only a PID is known; callers may bypass it only when actual successful spawn mode is carried forward as an authoritative session fact.
