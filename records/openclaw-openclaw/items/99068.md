## Summary

Keep open: current main and the latest release still preserve the same Discord native reply reference across text chunks and media-caption follow-up chunks, contrary to the documented `replyToMode: "first"` behavior.

## What This Changes

The issue reports duplicate Discord native reply references on every physical chunk when `replyToMode: "first"` should only apply to the first Discord message for one logical reply.

## Best Possible Solution

Patch the Discord shared send layer so one logical reply's native reply reference is emitted only on the first physical Discord message, with focused regression tests for long text and media-caption chunking.

## Reproduction Assessment

Yes, at source level: direct Discord sends with `replyTo` and internal text/media caption chunking currently pass `replyTo` into every physical chunk. I did not run a live Discord repro in this read-only checkout.

## Solution Assessment

Yes. The narrow maintainable fix is to gate the native reply reference inside `extensions/discord/src/send.shared.ts` for internal chunks, then update the existing request-body tests; no new config or product decision is needed.
