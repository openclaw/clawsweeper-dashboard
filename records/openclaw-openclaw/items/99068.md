## Summary

Keep open: current main still has source-backed Discord lower-level chunking behavior that preserves the same native reply reference across physical chunks, and existing tests currently encode that behavior despite docs saying `replyToMode: "first"` attaches the implicit native reply to the first outbound Discord message for the turn.

## What This Changes

Discord `replyToMode: "first"` should attach the native Discord reply reference only to the first physical message produced by one logical chunked reply.

## Best Possible Solution

Patch the Discord shared sender so lower-level text/media chunking emits `message_reference` only on the first physical message for one logical send, and update the existing chunked-reply tests to lock that behavior down.

## Reproduction Assessment

Yes by source inspection and existing test expectations: direct Discord sends with `replyTo` and internally chunked text/media captions currently carry `message_reference` on every chunk. I did not perform a live Discord run during this read-only review.

## Solution Assessment

Yes. The narrow maintainable fix is in the Discord plugin's shared send chunking path, with focused request-body assertions for text chunks and media-caption follow-ups; no new config or product direction is needed.
