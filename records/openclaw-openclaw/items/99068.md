## What This Changes

Discord `replyToMode: "first"` should attach the native Discord reply reference only to the first physical chunk of a long logical reply.

## Best Possible Solution

Land one focused, source-aware fix that covers Discord text/media chunking and the shared outbound reply-consumption path, with regression coverage for implicit first/batched behavior and reusable explicit/all-mode replies.

## Reproduction Assessment

Yes. Current source and tests show the request body keeps `message_reference` on all lower-level Discord chunks, and the reporter supplied live instrumentation logs; I did not run a live Discord reproduction in this read-only pass.

## Solution Assessment

Yes, with the follow-up included. The narrow maintainable fix is to consume a single-use reply once across physical Discord chunks and shared outbound planned units, while preserving explicit/all-mode reusable behavior where that is intentional.
