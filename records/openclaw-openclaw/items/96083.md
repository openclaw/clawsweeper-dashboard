## Summary

The current head still contains both previously reported P1 defects: it quarantines main-session rows before establishing recovery ownership and adds a second durable state machine beside the existing subagent fuse. The underlying availability bug is valid and the branch has useful work, but merge should wait for a single-owner recovery design and real production-entrypoint proof.

## What This Changes

The PR adds persistent restart-recovery attempt and quarantine fields, applies the budget to main and subagent recovery, clears it after successful lifecycle completion, and adds regression tests plus a standalone logic repro.

## Best Possible Solution

Use one locked, accepted-attempt fuse per recovery owner: revalidate main rows after routing, ownership, and dedupe guards; implement any cumulative subagent policy through subagentRecovery; and demonstrate both through the real file-backed recovery entrypoints before merge.
