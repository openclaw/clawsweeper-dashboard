## Summary

The reported cross-boot restart loop remains valid, but this head still has two P1 persistence defects: quarantine bypasses established ownership guards and can be applied from a stale scan. Tests are useful, but the external-PR proof gate also remains unmet because no real file-backed current-head run is provided.

## What This Changes

The PR adds persisted main-session restart-recovery attempt and quarantine fields, increments them during restart marking, gates over-budget recovery, and clears them after successful session progress.

## Best Possible Solution

Use one store-locked, ownership-aware retry-fuse transition after all existing guards; revalidate session identity, eligibility, and attempt state before reserving or quarantining, then prove fresh-row, upgrade-row, threshold, stale-scan, and successful-progress behavior through the production recovery entry point.
