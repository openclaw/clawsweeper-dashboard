## Summary

Keep this PR open for revision. The force-pushed head still quarantines sessions before existing routing, ownership, and dedupe guards, and the quarantine transaction can mutate a replacement row that no longer matches the scanned session. The competing PR is currently conflicting, so it is not a safe supersession target, and this branch still lacks real current-head behavior proof.

## What This Changes

Adds persistent main-session restart-recovery attempt and quarantine fields, charges the budget during interruption marking, quarantines over-budget entries, clears the metadata after successful lifecycle completion, reserves the slot keys, and adds focused tests.

## Best Possible Solution

Move durable budget reservation and exhaustion handling after all existing routing, ownership, and dedupe guards; perform it atomically against the exact scanned session identity, count accepted automatic recovery dispatches with pre-acceptance rollback, and prove exhausted plus healthy-next-turn behavior in a real file-backed or supervised gateway run.
