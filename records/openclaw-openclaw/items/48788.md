## Summary

Keep open: current main and v2026.6.11 still split filename decoding between remote-media and Feishu-local parsers, while the shared-decoder candidate PR is open, conflicting, and explicitly partial.

## What This Changes

The issue requests a central filename utility that handles RFC 5987, charset-specific Content-Disposition values, mojibake recovery, and reuse across channel adapters.

## Best Possible Solution

Choose one plugin-safe shared media filename decoder boundary, then land a refreshed implementation that wires remote media and the proven Feishu filename paths through that helper.
