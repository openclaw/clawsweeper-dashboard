## Summary

Keep open: current main and v2026.6.11 still use separate remote-media and Feishu filename parsers rather than a central multi-encoding decoder, and the open shared-decoder PR is unmerged and explicitly partial.

## What This Changes

Request a shared filename decoder for Content-Disposition parsing, RFC 5987, mojibake recovery, and multi-charset filename handling across media and channel adapters.

## Best Possible Solution

Choose one plugin-safe media filename decoder boundary, then land a refreshed implementation that routes remote media and proven Feishu filename paths through the same helper with focused regression coverage.
