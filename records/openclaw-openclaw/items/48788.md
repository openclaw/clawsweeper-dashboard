## Summary

Keep open: current main and v2026.6.11 still have separate Feishu and remote-media filename parsers rather than the requested shared multi-encoding decoder, and the open candidate at https://github.com/openclaw/openclaw/pull/71517 remains unmerged and partial.

## What This Changes

The issue requests a shared filename decoding utility for Content-Disposition filenames, including RFC 5987 and common legacy/misencoded charsets across channel adapters.

## Best Possible Solution

Choose a plugin-safe media-core or SDK boundary, then land a refreshed version of https://github.com/openclaw/openclaw/pull/71517 or a narrower replacement that routes remote media and Feishu metadata/fallback filenames through one tested decoder.
