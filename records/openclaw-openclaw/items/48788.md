## Summary

Keep open: current main and v2026.6.11 still have local filename parsers plus Feishu-specific recovery, not the requested shared multi-encoding Content-Disposition utility, and the open shared-decoder PR remains an unmerged partial candidate.

## What This Changes

Request a shared filename-decoding utility for Content-Disposition that handles RFC 5987, mojibake recovery, and explicit charset cases across channel adapters.

## Best Possible Solution

Define a maintainer-approved media-core/plugin-safe filename decoder, reuse an existing parser dependency where it is adequate, cover RFC 5987 plus explicit charset and mojibake cases with tests, and migrate first consumers incrementally.
