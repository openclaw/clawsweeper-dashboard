## What This Changes

The issue requests a central filename utility for RFC 5987 Content-Disposition parsing and multi-encoding filename recovery across channel adapters.

## Best Possible Solution

Have maintainers choose one plugin-safe media filename decoder boundary, then refresh and land https://github.com/openclaw/openclaw/pull/71517 or a narrower replacement that wires remote media and Feishu/channel metadata paths through the same helper.

## Reproduction Assessment

Yes, at source level: current main still lacks a shared multi-encoding decoder and keeps separate remote-media and Feishu filename parsers. I did not run a live channel reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the API boundary. A shared decoder is the right direction, but the maintainable solution should be one plugin-safe media seam rather than duplicated core and plugin helpers.
