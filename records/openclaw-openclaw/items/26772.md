## Label Justifications

- `P2`: The issue affects costly long-running memory indexing reliability, but it is a bounded improvement rather than an immediate core outage.
- `impact:data-loss`: Interrupted full reindexes can discard hours of newly generated indexing work and embeddings before publish.
- `impact:session-state`: The affected state is the durable memory/search index used for agent recall and session memory search.

## Summary

Keep this issue open: current main improves the old whole-file temp-swap design, but full builtin memory reindex still starts from a fresh random shadow database and has no durable checkpoint cursor or resume-on-restart state for interrupted long rebuilds.

## What This Changes

Request checkpoint/resume support for long-running builtin memory full reindex operations so crashes or interruptions do not discard hours of indexing work.

## Best Possible Solution

Add a durable SQLite-backed resume design for full builtin memory reindex that preserves the known-good published index until completion while recording enough source/chunk progress to continue safely after restart.
