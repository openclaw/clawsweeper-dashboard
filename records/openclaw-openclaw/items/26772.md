## Summary

Keep open: current main and the latest release still build forced/full builtin memory reindexes in a fresh shadow SQLite database and publish only after completion, with no durable checkpoint/resume contract for interrupted work.

## What This Changes

The issue requests durable checkpoint/resume support for long-running memory indexing so partial reindex progress survives process crashes.

## Best Possible Solution

Add memory-core-owned durable checkpoint/resume metadata for validated shadow full reindexes, resume only compatible incomplete generations, and keep public config minimal unless maintainers choose knobs.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should memory-core implement checkpoint/resume as a validated resumable shadow generation, as direct incremental writes to the live DB, or defer resumable full reindexing for now?

Rationale: The repair changes durable memory index generation semantics, incomplete-index status/search behavior, and possibly public memorySearch config, so source inspection proves the gap but does not choose the product contract.

Likely owner: steipete

Owner reason: The safe reindex lineage and prior keep-open review route the product-shape decision most directly to steipete.

Owner confidence: high

Options:

- **Resumable shadow generation (recommended):** Persist generation/checkpoint state for the shadow DB and publish only after validation, preserving the current safe-rebuild invariant while allowing restart resume.
- **Direct incremental live writes:** Write checkpointed progress into the live DB with explicit incomplete-generation filtering and status semantics, accepting a larger migration and config surface.
- **Defer resume support:** Keep the current atomic full rebuild behavior and rely on embedding-cache reuse and cleanup until maintainers prioritize a broader memory indexing redesign.

## Reproduction Assessment

Yes from source inspection, but not from a live destructive run in this review. Current main still creates a fresh random shadow DB for a full reindex, publishes only after completion, and has no durable cursor to reuse after a process kill.

## Solution Assessment

Unclear until maintainers choose the product contract. A validated resumable shadow generation appears safer than direct live writes because it preserves the current known-good-index invariant while addressing the lost-progress gap.
