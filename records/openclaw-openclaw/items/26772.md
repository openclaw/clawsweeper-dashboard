## Summary

Keep open: current main still protects the live memory index by rebuilding into a fresh random shadow SQLite database and publishing only after completion, but it does not persist a durable checkpoint cursor or resume interrupted shadow progress. The issue remains valid and needs maintainer direction because a correct fix changes generation identity, invalidation, locking, and status/search semantics.

## What This Changes

The issue requests durable checkpoint/resume support for long-running builtin memory indexing so interrupted full reindexes do not lose all progress.

## Best Possible Solution

Add memory-core-owned durable generation/checkpoint metadata for validated shadow full reindexes, resume only compatible incomplete generations, and keep public config minimal unless maintainers explicitly choose knobs.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: a forced full memory reindex creates a fresh random shadow DB, publishes only after completion, and has no durable cursor to reuse after a process kill; I did not run a destructive kill/restart scenario in this read-only review.

## Solution Assessment

No, the direct-write plus public config proposal is not clearly the best default shape. A validated resumable shadow generation appears safer because it preserves the current database-first publish invariant with less new config surface, but maintainers need to choose the final semantics.
