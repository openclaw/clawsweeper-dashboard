- `impact:data-loss`: The issue is about losing persisted memory-index progress after an interrupted long-running reindex.

## Summary

Keep open: current main and the latest release still rebuild builtin memory indexes into a fresh shadow SQLite database and publish only after the full rebuild completes, so interrupted long-running reindexes still cannot resume durable progress.

## What This Changes

The issue requests durable checkpoint/resume support for long-running builtin memory indexing so crashes or interruptions do not discard hours of progress.

## Best Possible Solution

Add memory-core-owned durable generation/checkpoint metadata for validated shadow full reindexes, resume only compatible incomplete generations, and keep public config minimal unless maintainers explicitly choose knobs.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: a forced full memory reindex creates a fresh random shadow DB, publishes only after completion, and has no durable cursor to reuse after a process kill.

## Solution Assessment

No. The requested outcome is valid, but the direct-write plus public config proposal is not clearly the best default shape because a validated resumable shadow generation better preserves the current database-first publish invariant.
