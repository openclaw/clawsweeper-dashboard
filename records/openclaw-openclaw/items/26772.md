## Label Justifications

- `P2`: The issue is a valid reliability improvement for long builtin memory indexing runs, but it is not a crash-loop, security bypass, or first-run release blocker.
- `impact:data-loss`: Interrupted long reindexes discard hours of generated embedding/index progress and force users to recompute from zero.
- `impact:session-state`: The missing checkpoint/resume state affects memory index generation state and whether session/memory context is available after an interrupted rebuild.

## Summary

Keep open: current main and v2026.6.11 still rebuild builtin memory indexes through a fresh random shadow SQLite database and publish only after the full rebuild completes, with no durable checkpoint cursor or resume-on-restart state for interrupted long reindexes.

## What This Changes

The issue requests durable checkpoint/resume capability for long-running builtin memory indexing, including safer progress persistence, status visibility, and possible `memorySearch` indexing controls.

## Best Possible Solution

Keep this issue open until memory-core has a maintainer-approved checkpoint/resume design that persists generation progress, resumes interrupted full reindexes safely, exposes honest incomplete-generation status, and documents/tests any new config or status surface.

Options:

- **Sponsor automatic checkpoint/resume (recommended):** Design memory-core to resume interrupted full reindexes by default while preserving the existing safe-publish invariant and adding status/tests/docs for incomplete generations.
- **Keep safe rebuild and improve retries/status only:** Treat process-death progress loss as acceptable for now and focus narrower work on retry, metadata, and clearer operator status around failed rebuilds.
- **Require explicit opt-in configuration:** Add checkpoint/resume behind a documented config switch with upgrade proof for both default compatibility and opt-in behavior.

## Reproduction Assessment

Yes at source level: forced/full reindex still creates a fresh random shadow database, rebuilds everything there, publishes only after completion, and removes the temp path instead of recording a resumable cursor. I did not run a live multi-hour crash test in this read-only review.

## Solution Assessment

No, the issue's requested direction is not ready for an automated fix as written because the exact checkpoint model and any config surface need maintainer approval. The maintainable solution is a memory-core-owned durable generation design that keeps incomplete indexes out of clean search/status paths.
