## Summary

Keep open: current main and the latest release still rebuild memory into a fresh random shadow SQLite database and publish only after completion, without durable checkpoint or resume metadata. Adjacent retry and stale-temp cleanup work reduces some failure modes but does not solve process-crash resume, and the remaining design touches memory-index durability, search/status semantics, and config-surface policy.

## What This Changes

Request adds checkpoint/resume support so long-running memory full reindexes can recover committed progress after crashes instead of restarting from zero.

## Best Possible Solution

Add memory-core-owned durable generation/checkpoint metadata for validated shadow full reindexes, resume only compatible incomplete generations, and keep public config minimal unless maintainers choose knobs.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: a forced full memory reindex creates a fresh random shadow DB, publishes only after completion, and has no durable cursor to reuse after process death; I did not run a destructive kill/restart scenario in this read-only review.

## Solution Assessment

No, the direct-write plus public config proposal is not clearly the best default shape. A resumable shadow-generation design likely better preserves the current publish invariant, but maintainers need to choose the final semantics.
