## Summary

Keep this PR open: its bounded retry is a plausible fix for the linked QA false negative, but it still turns a persistent structured retryable gateway failure into an uninformative timeout, losing the diagnostics that QA needs to explain the failure. The protected `maintainer` label also requires explicit maintainer handling rather than cleanup closure.

## What This Changes

The branch preserves gateway request errors as causes and retries retryable `chat.history` rebuild failures within the existing QA polling deadline.

## Best Possible Solution

Keep the bounded retry, but retain the final retryable structured error as the timeout cause so persistent transcript rebuilds remain diagnosable in QA results.
