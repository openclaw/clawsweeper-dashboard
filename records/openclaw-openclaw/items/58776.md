## Summary

Keep open: current main still lacks the requested sub-agent `first-progress` and typed `startup-failed` lifecycle contract, while the direct open PR is not a safe landing path and the remaining work needs maintainer product/API review.

## What This Changes

The issue requests additive sub-agent lifecycle signals so parents can distinguish silent startup aborts from healthy slow starts or normal mid-run timeouts.

## Best Possible Solution

Define the accepted startup-progress lifecycle contract on current main, then implement it through active embedded-agent, subagent registry, gateway wait/session projection, SDK normalization, docs, and focused regression proof.
