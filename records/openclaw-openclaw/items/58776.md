## Summary

Keep open: current main still lacks the requested sub-agent `first-progress` and typed `startup-failed` lifecycle contract, and the open candidate PR is conflicted/stale enough that the issue remains the canonical work item for maintainer direction.

## What This Changes

The issue requests additive sub-agent lifecycle phases so parent runs can distinguish first progress, startup aborts, startup timeouts, empty-output startup failures, and auth failures from ordinary long-running child work.

## Best Possible Solution

Accept or reject one core startup-lifecycle contract, then implement it on current main across embedded-agent subscribe, subagent registry, gateway wait/session projection, SDK normalization, docs, and focused startup-abort proof.
