## Summary

Keep open: current OpenClaw already ships an opt-in mid-turn tool-loop precheck, but it only reacts to prompt pressure that no longer fits the budget; it does not establish the proposed cost-, density-, or no-progress-based compaction policy for a still-fitting 172K/200K loop. ([github.com](https://github.com/openclaw/openclaw/blob/main/docs/reference/session-management-compaction.md))

## What This Changes

Request proactive safeguard compaction during dense tool loops before near-limit threshold behavior causes repeated large-context input costs.

## Best Possible Solution

Reproduce the reported loop on v2026.7.1 with `midTurnPrecheck.enabled` enabled, then make an explicit product decision on extending that guard with a bounded proactive trigger rather than adding a parallel cost-aware mode.
