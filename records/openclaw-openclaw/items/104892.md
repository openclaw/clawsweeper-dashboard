## Summary

Keep this maintainer-owned PR open, but the current head still has a blocking false-attribution path: an incidental PR reference in a main commit body can be mistaken for that commit’s own PR identity and suppress the legitimate release backport record.

## What This Changes

## Best Possible Solution

Treat only a guaranteed PR identity signal—such as the candidate subject’s PR suffix, a strict dedicated original-PR marker, or authoritative GitHub association—as canonical, while preserving author/path checks, unique-match failure safety, and fallback to the release PR.
