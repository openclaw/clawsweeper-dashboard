## Summary

## What This Changes

The PR wraps Discord `audioAsVoice` final-payload voice delivery so rejected voice sends fall back to visible or TTS supplement text, with regression tests for reply targets and duplicate suppression.

## Best Possible Solution

Land the Discord-owned fallback if maintainers accept visible text recovery for rejected voice-note final replies; otherwise narrow the catch to known pre-send failures.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 await `sendVoice` before any fallback in the Discord `audioAsVoice` payload branch, so a rejected voice send exits before visible text can be delivered.

## Solution Assessment

Yes, if maintainers accept the fallback policy. The change is in the Discord outbound payload owner and reuses the existing TTS supplement contract; the safer alternative is to limit fallback to known pre-send failures if ambiguous duplicate delivery is unacceptable.
