- `merge-risk: 🚨 session-state`: The new default can cause Active Memory recall and session toggles to apply to agents that were previously not targeted by omitted plugin config.

## Summary

Keep this PR open: it is a useful candidate for the linked Active Memory targeting issue, but it still changes the meaning of omitted `active-memory.config.agents` for existing installs and needs maintainer default-policy approval plus stronger final-branch behavior proof before merge.

## What This Changes

The PR changes Active Memory config normalization so omitted `config.agents` targets configured agents or `main`, preserves explicit empty and non-empty allowlists, and updates tests, docs, and plugin UI help.

## Best Possible Solution

Make a maintainer-visible default-policy decision first: either approve the broad omitted-agents default with upgrade notes, or narrow the fix to the linked single-agent command/session bug without changing multi-agent omitted-config behavior.

## Reproduction Assessment

Yes, at source level. Current main normalizes omitted Active Memory `config.agents` to `[]`, then the agent gate checks `config.agents.includes(agentId)`, so omitted configs do not target the default agent or configured agents.

## Solution Assessment

Unclear as a final product decision. Central normalization is clean if maintainers want omission to mean configured agents, but a narrower default-main repair would have less upgrade blast radius.
