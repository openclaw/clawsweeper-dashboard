## Summary

Keep this PR open for an Active Memory owner decision. The implementation is focused, but it changes the shipped explicit-targeting contract: existing configurations that enable Active Memory while omitting `config.agents` would begin running recall for configured agents, including agents added later. The supplied runtime output shows a healthy gateway and memory search, not final-head Active Memory eligibility or injection behavior.

## What This Changes

Changes Active Memory normalization so an omitted agent list inherits configured agent IDs or implicit `main`, while preserving explicit empty and non-empty lists and updating tests, docs, plugin help, and generated baselines.

## Best Possible Solution

Keep explicit agent targeting as the safe default; if maintainers want all-configured-agent convenience, expose it as a deliberate setup or UI choice rather than assigning broad activation semantics to an omitted field, with fresh-install and upgrade proof.
