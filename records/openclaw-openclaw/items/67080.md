- **[P1] Avoid activating plugin registries from request misses:** `src/plugins/runtime/http-route-registry-loader.ts:30-38`
  - body: `loadScopedGatewayPluginHttpRouteRegistry` is reached from the HTTP route-miss path and calls `loadOpenClawPlugins` without `activate:false`; the current loader defaults to active runtime loading, so unmatched network requests can force plugin initialization and process-global registry churn. Move this to a gateway-owned non-activating lifecycle or stable snapshot before dispatch.
  - confidence: 0.91
- **[P2] Run auth against the same route set used for dispatch:** `src/gateway/server/plugins-http.ts:83-90`
  - body: The scoped registry is resolved after the `plugin-auth` stage has already decided whether to authorize the request from the startup registry. A scoped-only `auth: "gateway"` route on a non-default-protected path will then be blocked later with `gatewayAuthSatisfied` still false, even when the caller supplied valid credentials.
  - confidence: 0.86
- **[P2] Keep one bad route owner from blocking scoped routes:** `src/plugins/runtime/http-route-registry-loader.ts:32`
  - body: With `throwOnLoadError: true`, a single failing plugin in the scoped route-owner set throws the whole loader. Because plugin HTTP dispatch is a continue-on-error stage, that skips healthy scoped routes for the request instead of isolating the broken owner.
  - confidence: 0.84
