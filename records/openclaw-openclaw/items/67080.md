## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Do not activate plugin registries from request misses:** `src/plugins/runtime/http-route-registry-loader.ts:30-38`
  - body: `loadScopedGatewayPluginHttpRouteRegistry` is reached from an HTTP route miss and calls `loadOpenClawPlugins` without `activate: false`. The loader defaults to activating registries, so a network request can replace process-global plugin runtime state and hook runners; move this to a gateway-owned non-activating lifecycle before dispatch.
  - confidence: 0.92
- **[P2] Run auth against the same route registry used for dispatch:** `src/gateway/server/plugins-http.ts:85-90`
  - body: Scoped routes are only discovered after the earlier `plugin-auth` stage has decided whether gateway auth is required from a different registry. A scoped-only `auth: "gateway"` route can then be rejected despite valid credentials, or auth and dispatch can disagree; resolve the scoped route snapshot before auth or share one route set across both stages.
  - confidence: 0.86
- **[P2] Do not let one scoped owner failure block healthy routes:** `src/plugins/runtime/http-route-registry-loader.ts:32`
  - body: Using `throwOnLoadError: true` for the whole scoped owner set means one broken route-owner plugin throws the loader and skips the entire plugin-http stage for that request. Isolate per-owner failures so unrelated healthy scoped routes can still match and handle traffic.
  - confidence: 0.84
