## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Avoid activating plugin registries from requests:** `src/plugins/runtime/http-route-registry-loader.ts:30-38`
  - body: This scoped route loader is called from the HTTP request fallback path, but it calls `loadOpenClawPlugins` without `activate:false`. The loader activates registries by default, so a network request can replace process-global plugin runtime state instead of using a gateway-owned stable route snapshot.
  - confidence: 0.91
- **[P2] Authorize scoped gateway routes before dispatch:** `src/gateway/server/plugins-http.ts:83-90`
  - body: Scoped routes are matched only after `plugin-auth` has already decided whether gateway auth is required from the startup registry. A scoped route with `auth: "gateway"` on a non-protected path can then be blocked without `gatewayAuthSatisfied`, making that route class unreachable even when the caller sends valid credentials.
  - confidence: 0.86
- **[P2] Isolate failing scoped route owners:** `src/plugins/runtime/http-route-registry-loader.ts:32`
  - body: The scoped loader uses `throwOnLoadError: true` for the whole planned owner set. If one route-owner plugin is broken or unconfigured, the exception skips the plugin-http stage for the request, so healthy scoped routes do not get a chance to match.
  - confidence: 0.84
