## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Do not activate plugin registries from request misses:** `src/plugins/runtime/http-route-registry-loader.ts:30-38`
  - body: `loadScopedGatewayPluginHttpRouteRegistry` is called from the plugin HTTP request path after a route miss, but this call to `loadOpenClawPlugins` does not set `activate: false`. On current main, activating loads clear and restore process-global plugin state and call `setActivePluginRegistry`/global hook initialization, so a remote unmatched path can churn gateway runtime state instead of using a gateway-owned non-activating snapshot.
  - confidence: 0.9
- **[P2] Run auth against the same route registry used for dispatch:** `src/gateway/server/plugins-http.ts:85-90`
  - body: The scoped registry is resolved only inside plugin dispatch, after `plugin-auth` has already decided whether gateway auth is required from the startup registry. A scoped-only route with `auth: "gateway"` can therefore be blocked without `gatewayRequestAuth` even when the request supplied valid gateway credentials; scoped route resolution needs to happen before or during the shared auth decision.
  - confidence: 0.86
- **[P2] Do not let one scoped owner failure block healthy routes:** `src/plugins/runtime/http-route-registry-loader.ts:32`
  - body: Passing `throwOnLoadError: true` means any failed plugin in the scoped owner set throws the whole scoped load. Because the plugin HTTP stage is `continueOnError`, that skips plugin dispatch for the request, so one broken route-owner plugin can prevent unrelated healthy scoped routes from handling the path.
  - confidence: 0.86
