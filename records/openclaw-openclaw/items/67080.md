## What This Changes

The PR adds manifest `activation.onRoutes` route hints, route-id normalization, route-owner planning/trust filtering, bundled plugin manifest/doc updates, and a gateway plugin HTTP fallback that loads a scoped route registry on startup-registry misses.

## Best Possible Solution

Rebase and replace request-miss activation with a gateway-owned non-activating lifecycle cache prepared before auth, dispatch, and upgrade handling, while preserving manifest trust filters and the startup registry fallback.

## Reproduction Assessment

Yes, source-reproducible: the PR head calls `loadOpenClawPlugins` from the scoped request fallback without `activate: false`, computes scoped matches after the gateway-auth stage, and throws on any scoped owner load error. I did not run live gateway tests because this review is read-only.

## Solution Assessment

No; this is a plausible direction but not the best merge shape because request misses should not activate global plugin registries or split auth and dispatch snapshots. The safer design is a non-activating gateway-owned scoped route registry prepared before auth, dispatch, and upgrades.

## Review Findings

Overall confidence: 0.89

Full review comments:

- **[P1] Avoid activating plugin registries from request misses:** `src/plugins/runtime/http-route-registry-loader.ts:30-38`
  - body: `loadScopedGatewayPluginHttpRouteRegistry` is called after a route miss, but this `loadOpenClawPlugins` call does not pass `activate: false`. The loader activates by default, so a remote HTTP miss can clear and replace process-global plugin runtime state and hook lifecycle while the gateway is serving traffic.
  - confidence: 0.93
- **[P2] Authenticate scoped routes before dispatch:** `src/gateway/server/plugins-http.ts:84-90`
  - body: Scoped routes are discovered inside plugin dispatch after the `plugin-auth` stage already checked only the startup route registry. A scoped-only route with `auth: "gateway"` will not get `gatewayAuthSatisfied`, so valid gateway credentials cannot make that route reachable; the scoped registry must participate in the auth decision before dispatch.
  - confidence: 0.88
- **[P2] Isolate failing scoped owners from healthy routes:** `src/plugins/runtime/http-route-registry-loader.ts:31-33`
  - body: Using `throwOnLoadError: true` for the whole scoped owner set means one broken route-owner plugin throws the fallback load. Because plugin HTTP is a `continueOnError` gateway stage, that skips all scoped plugin routes for the request, including healthy owners that could have matched.
  - confidence: 0.86
