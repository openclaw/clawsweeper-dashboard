## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Avoid activating plugin registries from request misses:** `src/plugins/runtime/http-route-registry-loader.ts:30-38`
  - body: `loadScopedGatewayPluginHttpRouteRegistry` is reached from plugin HTTP route misses and calls `loadOpenClawPlugins` without `activate:false`; current main treats that as an active runtime load, so unmatched network requests can force plugin initialization and process-global registry churn. Move this to a gateway-owned non-activating lifecycle or stable snapshot before dispatch.
  - confidence: 0.91
- **[P2] Run auth against the same route set used for dispatch:** `src/gateway/server/plugins-http.ts:83-90`
  - body: The scoped registry is resolved inside `plugin-http`, after `plugin-auth` has already decided whether to authenticate the request from the startup registry. Scoped-only `auth: "gateway"` routes on paths outside the default protected set can then be rejected with `gatewayAuthSatisfied` still false even when the caller sends valid credentials.
  - confidence: 0.86
- **[P2] Keep one bad route owner from blocking scoped routes:** `src/plugins/runtime/http-route-registry-loader.ts:32`
  - body: With `throwOnLoadError: true`, one failing plugin in the scoped route-owner set throws the whole loader. Because plugin HTTP dispatch is a continue-on-error stage, that skips healthy scoped routes for the request instead of isolating the broken owner.
  - confidence: 0.84
