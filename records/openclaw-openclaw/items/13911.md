## Summary

Keep open: current main and the latest release still lack structural per-channel or per-spawn sub-agent announce suppression, and the related open reports overlap without replacing this channel-specific product/API decision.

## What This Changes

Request a per-channel configuration or policy to suppress or reroute sub-agent completion announcements so chat channels do not receive raw sub-agent output.

## Best Possible Solution

Define one backward-compatible completion-delivery policy that defaults to current behavior and can mark selected channel or spawn completions suppressed/internal before active wake, requester handoff, and direct fallback delivery.

## Reproduction Assessment

Yes for the missing capability. Source inspection shows current main and v2026.6.11 expose no per-channel suppression config or public sessions_spawn parameter while completion delivery still resolves external requester targets and fallback sends.

## Solution Assessment

Unclear as proposed. A channel key such as channels.telegram.subagentAnnounce is plausible, but maintainers should choose one completion-delivery policy that composes with global suppression, parent routing, hooks, and fallback reliability.
