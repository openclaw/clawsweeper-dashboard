## Summary

Keep open: current main and the latest release still lack a public per-channel or per-spawn policy for suppressing sub-agent completion announcements, and the open related items overlap without replacing this channel-specific product/API decision.

## What This Changes

Request a configurable way to suppress or reroute sub-agent completion announcements per channel so Telegram and similar chats do not receive raw automated completion output.

## Best Possible Solution

Define one backward-compatible completion-delivery policy that defaults to current behavior and can make selected channel or spawn completions suppressed/internal before active wake, requester handoff, and direct text/media fallback paths.

## Reproduction Assessment

Yes for the missing capability. Source inspection on current main shows no per-channel sub-agent announce suppression config or public sessions_spawn parameter while top-level completion delivery still resolves an external requester target.

## Solution Assessment

Unclear as proposed. A channel key such as channels.telegram.subagentAnnounce is plausible, but maintainers should choose one completion-delivery policy that composes with global suppression, parent routing, extension hooks, and fallback reliability.
