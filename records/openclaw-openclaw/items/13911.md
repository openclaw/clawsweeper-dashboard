## Summary

Keep open: current main and v2026.6.11 still do not expose per-channel or per-spawn sub-agent announce suppression, and the issue remains a clear product/API decision rather than a cleanup close.

## What This Changes

Request a framework-level way to suppress or reroute sub-agent completion announcements per channel so Telegram and similar chats are not cluttered by raw sub-agent output.

## Best Possible Solution

Define a backward-compatible completion-delivery policy that defaults to current behavior and can mark selected channel or spawn completions as suppressed or internal before every user-facing delivery and fallback path.

## Reproduction Assessment

Yes. Source inspection on current main shows no public per-channel sub-agent announce suppression config or `sessions_spawn` parameter, while docs and delivery code still route top-level completions to an external target by default.

## Solution Assessment

Unclear as proposed. A channel key such as `channels.telegram.subagentAnnounce` is plausible, but maintainers should choose one completion-delivery policy that composes with global suppression, parent routing, extension hooks, and fallback reliability.
