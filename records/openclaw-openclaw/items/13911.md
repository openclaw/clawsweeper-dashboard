## Label Justifications

- `P2`: This is a normal-priority sub-agent messaging workflow improvement with repeated channel reports, but it is not a core outage or emergency.
- `impact:message-loss`: The issue is about whether sub-agent completion messages are delivered to, suppressed from, or routed away from user-facing chat channels.
- `impact:ux-friction`: Users report noisy raw sub-agent completions in Telegram and iMessage and rely on fragile behavioral workarounds or sanitizer proxies.

## Summary

Keep open: current main and v2026.6.11 still lack a structural per-channel or per-spawn policy for suppressing sub-agent completion announcements, and the related open items overlap without replacing this channel-specific product/API decision.

## What This Changes

Add a config or tool policy to suppress or reroute sub-agent completion announcements per channel so Telegram and similar chats are not cluttered with raw sub-agent output.

## Best Possible Solution

Define one backward-compatible completion-delivery policy that defaults to current behavior and can suppress or internalize selected channel or spawn completions before active wake, requester handoff, and direct fallback paths.

Rationale: The missing behavior is clear, but the fix adds public config/tool surface and overlaps global suppression, parent routing, hooks, and fallback reliability semantics that automation should not choose alone.

Owner confidence: high

Options:

- **Unify Completion Delivery Policy (recommended):** Add one backward-compatible policy that can express channel suppression and internal-only completion delivery while covering all delivery and fallback branches.
- **Narrow Per-Channel Suppression:** Add only a channel-level suppression key, accepting that parent routing and hook use cases remain tracked separately.
- **Defer To Hook Or Audience Work:** Keep this blocked until maintainers choose a broader event-audience or post-completion hook API that can subsume channel suppression.

## Reproduction Assessment

Yes for the missing capability. Source inspection shows current main and v2026.6.11 expose no per-channel or per-spawn sub-agent announce suppression policy while delivery still resolves external targets and fallback sends.

## Solution Assessment

Unclear as proposed. A per-channel key is plausible, but maintainers should choose a unified completion-delivery policy that composes with global suppression, parent routing, hooks, and fallback reliability.
