## Summary

Keep open: current main and v2026.6.11 still lack a structural per-channel or per-spawn suppression policy for sub-agent completion announcements, and the related reports overlap without replacing this channel-specific product/API decision.

## What This Changes

Request a structural policy to suppress or reroute sub-agent completion announcements for selected channels such as Telegram.

## Best Possible Solution

Define one backward-compatible completion-delivery policy that defaults to current behavior and can suppress or internalize selected channel or spawn completions before active wake, requester handoff, and direct fallback delivery paths.

## Reproduction Assessment

Yes for the missing capability: source inspection shows no public per-channel sub-agent announce suppression config or sessions_spawn parameter, and current completion delivery still resolves external requester targets. I did not run a live Telegram scenario in this read-only review.

## Solution Assessment

Unclear as proposed. A per-channel key is plausible, but maintainers should choose one completion-delivery policy that composes with global suppression, parent routing, extension hooks, and fallback reliability.
