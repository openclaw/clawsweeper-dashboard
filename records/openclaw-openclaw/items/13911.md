## Summary

Keep open: current main and v2026.6.11 still lack a structural per-channel or per-spawn policy for suppressing sub-agent completion announcements, while the delivery path still resolves external requester routes and has direct-message fallback behavior. The remaining work is real, but the public API/config shape needs maintainer product direction before a fix lane.

## What This Changes

The issue requests a structural way to suppress or reroute sub-agent completion announcements per channel so raw child results do not automatically clutter channel chats.

## Best Possible Solution

Add a backward-compatible completion delivery policy that defaults to current behavior but can suppress or make sub-agent completions internal-only for selected channels and/or spawn calls, applied before both requester-agent delivery and direct fallback sends.
