## Summary

Keep open: current main and the latest release still lack a structural per-channel or per-spawn suppression policy for sub-agent completion announcements, and the related reports overlap without replacing this channel-specific product/API decision.

## What This Changes

The issue requests a config or delivery-policy surface to suppress or reroute sub-agent completion announcements for selected channels.

## Best Possible Solution

Define a backward-compatible completion-delivery policy that defaults to current behavior and can make selected channel or spawn completions suppressed/internal before active wake, requester handoff, and direct text/media fallback paths.

## Reproduction Assessment

Yes for the missing capability. Source inspection shows current main and v2026.6.11 expose no per-channel sub-agent announce suppression config or public sessions_spawn parameter while completion delivery still resolves external requester targets and fallback sends.

## Solution Assessment

Unclear as proposed. A channel key such as channels.telegram.subagentAnnounce is plausible, but maintainers should choose one completion-delivery policy that composes with global suppression, parent routing, extension hooks, and fallback reliability.
