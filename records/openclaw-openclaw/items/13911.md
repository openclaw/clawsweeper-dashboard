## Summary

Keep open: current main and latest release still lack a public per-channel or per-spawn policy to suppress sub-agent completion announces, and the related open items overlap without replacing this channel-specific product/API decision.

## What This Changes

The issue requests a config or delivery policy that can suppress or reroute sub-agent completion announcements for selected channels while keeping normal interactive replies working.

## Best Possible Solution

Define one backward-compatible completion-delivery policy that defaults to current behavior and can mark selected channel or spawn completions suppressed/internal before active wake, requester handoff, and direct fallback delivery paths.

## Reproduction Assessment

Yes, for the missing capability. Source inspection on current main shows no per-channel sub-agent announce suppression config or public sessions_spawn parameter while top-level completion delivery still resolves an external requester target.

## Solution Assessment

Unclear as proposed. A per-channel key is plausible, but maintainers should choose one completion-delivery policy that composes with global suppression, parent routing, extension hooks, and fallback reliability.
