## Summary

Keep open: current main and v2026.6.11 still lack a structural per-channel or per-spawn policy for suppressing sub-agent completion announcements, and the remaining work is a compatibility-sensitive product/API decision rather than an obsolete cleanup item.

## What This Changes

The issue requests a configurable way to suppress or reroute sub-agent completion announcements per channel so chat users do not receive raw sub-agent output directly.

## Best Possible Solution

Define one backward-compatible completion-delivery policy that defaults to current behavior and can suppress or internalize selected channel or spawn completions before active wake, requester handoff, and direct fallback paths.

- **Defer To Broader Hook Or Audience Work:** Keep the issue open until maintainers choose a broader event-audience or post-completion hook API that can subsume channel suppression.

Yes for the missing capability. Source inspection shows current main and v2026.6.11 expose no per-channel or per-spawn sub-agent announce suppression policy while delivery still resolves external targets and fallback sends.

## Solution Assessment

Unclear as proposed. A per-channel key is plausible, but maintainers should choose a unified completion-delivery policy that composes with global suppression, parent routing, hooks, and fallback reliability.
