## Summary

Keep open: current main and latest release still lack a public per-channel or per-spawn policy to suppress sub-agent completion announcements, and related open issues overlap without replacing this channel-specific API/product decision.

## What This Changes

Request a per-channel or broader announce policy that can suppress or internalize sub-agent completion announcements so chat channels such as Telegram and iMessage are not cluttered by automated worker output.

## Best Possible Solution

Define one backward-compatible completion-delivery policy that defaults to current behavior and can suppress or internalize selected channel or spawn completions before active wake, requester handoff, and direct text/media fallback paths.

## Reproduction Assessment

Yes for source-level reproduction: current main exposes no per-channel sub-agent announce suppression config or public sessions_spawn parameter, and top-level completion delivery still resolves an external requester target.

## Solution Assessment

Unclear as a final product choice; a channel key is plausible, but maintainers should choose one policy that composes with global suppression, per-spawn skip, parent routing, and plugin-hook boundaries.
