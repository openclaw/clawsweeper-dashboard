## Summary

Keep open: current main and v2026.6.11 still lack a public per-channel or per-spawn policy to suppress sub-agent completion announcements, and the open related issues overlap without replacing this channel-specific product/API decision.

## What This Changes

The issue requests a configurable policy to suppress or reroute sub-agent completion announcements per channel instead of always using the requester chat delivery context.

## Best Possible Solution

Define one backward-compatible completion-delivery policy that defaults to current behavior and can make selected channel or spawn completions suppressed/internal before active wake, requester-agent handoff, and direct fallback delivery.

## Reproduction Assessment

Yes for the missing capability. Current source exposes no per-channel sub-agent announce suppression config or public `sessions_spawn` parameter while top-level completion delivery still resolves an external requester target.

## Solution Assessment

Unclear as proposed. A channel key such as `channels.telegram.subagentAnnounce` is plausible, but maintainers should choose one completion-delivery policy that composes with global suppression, parent routing, extension hooks, and fallback reliability.
