## Summary

Keep open: current main and the latest release still lack a public per-channel or per-spawn policy for suppressing sub-agent completion announcements, while related issues overlap without replacing this channel-specific product/API decision.

## What This Changes

The issue requests a config or delivery policy that can suppress sub-agent completion announcements for selected channels such as Telegram while leaving normal interactive replies intact.

## Best Possible Solution

Define one backward-compatible completion-delivery policy that defaults to current behavior and can suppress or internalize selected channel or spawn completions before active wake, requester handoff, and direct fallback paths.

## Reproduction Assessment

Yes. Source inspection on current main shows no per-channel sub-agent announce suppression config or public sessions_spawn parameter, and top-level completion delivery still resolves an external requester target.

## Solution Assessment

Unclear as a final product choice. A channel-level key is plausible, but maintainers should choose one policy that composes with global suppression, per-spawn skip, parent routing, and plugin-hook boundaries.
