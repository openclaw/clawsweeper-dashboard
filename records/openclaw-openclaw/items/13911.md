## Summary

Keep open: current main and v2026.6.11 still lack a structural per-channel or per-spawn policy for suppressing sub-agent completion announcements, while the delivery path still resolves external requester routes and can use direct fallback sends. The missing behavior is real, but choosing the public config/tool API belongs to maintainers because it overlaps global suppression, parent routing, hooks, and delivery fallback semantics.

## What This Changes

The issue requests a framework-level way to suppress or reroute sub-agent completion announcements per channel, especially for Telegram-style chat sessions.

## Best Possible Solution

Define one backward-compatible completion-delivery policy that defaults to current behavior and can suppress or internalize selected channel or spawn completions before active wake, requester handoff, and direct fallback paths.
