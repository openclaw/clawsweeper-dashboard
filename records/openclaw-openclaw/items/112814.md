## Summary

This issue remains necessary: the open typing-focused work covers only part of the queued-turn failure, while the reported Telegram draft-progress lifecycle is a separate, source-backed behavior gap. The report and follow-up discussion identify a plausible lifecycle ownership failure, but current-main live reproduction and a full cross-channel lifecycle audit are still needed before choosing a repair shape.

## What This Changes

Repair queued Telegram follow-up turns so they show typing and temporary tool-progress drafts while running, then clean those feedback surfaces up after final delivery.

## System Context

Telegram inbound dispatch creates typing and progress-feedback callbacks for a reply; when the session is busy, the follow-up runner later executes the queued turn through those callbacks. The queued turn eventually sends its final payload through channel delivery, so lifecycle cleanup must remain valid until that later run ends.

## Architecture Diagram

flowchart LR
  A[Telegram inbound message] --> B[Telegram dispatch feedback lifecycle]
  B --> C[Session queue]
  C --> D[Queued follow-up run]
  D --> E[Typing and tool-progress drafts]
  D --> F[Final Telegram delivery]
  E --> G[Feedback cleanup after completion]
  F --> G

## Best Possible Solution

Create or explicitly transfer a queued-run-owned feedback lifecycle when the follow-up is admitted, keep native tool-progress callbacks independent of verbose text summaries, and add regression coverage for typing, draft creation, final delivery, cleanup, and multiple queued turns.
