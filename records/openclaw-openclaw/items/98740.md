## Summary

Keep open: current main and the latest release still resolve Mattermost gateway-auth bypass paths through a bundled-only artifact loader, while the linked fix PR is open and not merged yet. The issue should close only after that PR or an equivalent fix lands.

## What This Changes

The issue reports that Mattermost native slash-command callbacks started returning gateway-level 401 responses after the Mattermost plugin was externalized in 2026.6.11.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/98819, or replace it with an equivalent activation-gated installed-plugin artifact resolver that preserves Mattermost’s per-command token validation.

## Reproduction Assessment

Yes. Source inspection shows the protected `/api/channels` path still depends on a bundled-only bypass artifact, and the issue/PR discussion provides live packaged-install before/after evidence for the gateway-level 401.

## Solution Assessment

Yes, the best fix is to make the gateway-auth artifact lookup installed-plugin-aware through the activation-gated plugin seam, not to weaken gateway auth or alter Mattermost command-token validation.
