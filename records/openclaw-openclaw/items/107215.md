## Summary

Keep open for explicit owner handling: current main is correct under default-agent-only adoption, but the report identifies a credible future cross-agent session-state gap, and the protected `maintainer` label plus plugin-contract compatibility require a maintainer decision before implementation.

## What This Changes

Carry provider-authoritative `agentId` through session-catalog continue results and use it to write and disambiguate adopted-session upstream links.

## Best Possible Solution

Have the session-catalog owner define one canonical adopted-session identity result containing `sessionKey` and provider-authoritative `agentId`, populate it in bundled adapters, consume it through the gateway and composite link lookup, and provide a narrow compatibility transition for any shipped external provider contract.

Options:

- **Stage the additive contract (recommended):** Add optional `agentId`, populate every bundled adapter, prefer it in core with focused compatibility tests, and define when the legacy fallback is removed.
- **Require identity immediately:** Make `agentId` mandatory only with evidence that no supported external providers break or with an explicit plugin API migration and deprecation plan.
- **Defer the contract:** Keep the issue open as the prerequisite for any future non-default-agent adoption and implement both changes together.
