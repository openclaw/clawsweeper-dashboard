## Summary

Keep open for explicit owner handling: current main is intentionally correct only under default-agent adoption, while this issue identifies a credible future cross-agent state-association gap; the protected `maintainer` label and compatibility-sensitive provider contract make automated cleanup or implementation inappropriate.

## What This Changes

Add provider-authoritative `agentId` to session-catalog continuation results and use it to persist and disambiguate adopted-session upstream links.

## Best Possible Solution

Before enabling non-default-agent adoption, make the provider result carry authoritative `agentId`, require bundled adapters to populate it, use it for gateway event/link writes and watch-cursor disambiguation, and add focused default-agent plus duplicate-key cross-agent regression tests.
