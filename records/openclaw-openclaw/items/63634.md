## Label Justifications

- `P1`: A configured bundled MCP server can lose its complete tool catalog when one tool omits the root `inputSchema.type` field.
- `merge-risk: 🚨 compatibility`: The patch changes catalog discovery from rejecting the server’s strict schema failure to accepting and normalizing a missing root type.
- `merge-risk: 🚨 security-boundary`: The relaxation consumes metadata from third-party MCP servers and depends on a private SDK cache to retain downstream validation guards.

## Summary

The proposed fix still addresses a live bundled-MCP cataloging path and has strong behavioral proof, but merging it requires an explicit maintainer decision to rely on the pinned MCP SDK’s private metadata-cache method.

## What This Changes

The PR replaces strict bundled MCP `tools/list` parsing with an SDK-derived schema that accepts a missing root `inputSchema.type`, backfills it to `object`, filters explicit non-object roots, and refreshes MCP client metadata.

## Best Possible Solution

Land the single-response validation approach only if maintainers explicitly accept the version-pinned private SDK seam; otherwise obtain or add a supported SDK integration point for custom list parsing plus metadata caching, then use that public boundary.
