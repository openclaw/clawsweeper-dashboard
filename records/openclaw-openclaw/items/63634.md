## Summary

The reported bundled-MCP catalog failure remains live on current main, and this revision appears to fix it without re-listing a potentially different server response. The remaining merge gate is maintainer approval of the deliberate dependency on the MCP SDK’s private metadata-cache method, which preserves output-schema and task guards but is not a supported SDK API.

## What This Changes

The PR replaces strict bundled MCP `tools/list` parsing with an SDK-derived schema that accepts a missing root `inputSchema.type`, backfills it to `object`, filters explicit non-object roots, and refreshes MCP client metadata.

## Best Possible Solution

Approve the narrowly scoped compatibility policy only if maintainers accept owning the private SDK metadata-cache seam; otherwise pursue an upstream/public SDK hook that validates a caller-supplied relaxed tool-list schema while retaining metadata caching.
