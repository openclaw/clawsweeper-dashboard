## Summary

Keep this PR open for maintainer review. Current `main` still catalogs bundled MCP tools through the SDK’s strict `client.listTools()` path, so the reported missing-root-type failure remains relevant; this branch supplies focused regression coverage and real stdio-runtime proof. The remaining merge decision is whether OpenClaw should accept the deliberately pinned private SDK metadata-cache seam. **Likely related people:** `nxmxbbd` is the strongest routing candidate from the recent bundled MCP catalog work; `vincentkoc` is an adjacent contributor on invalid bundle-tool quarantine behavior.

## What This Changes

The PR replaces strict bundled MCP `tools/list` parsing with a schema derived from the SDK contract but permitting a missing root `inputSchema.type`, normalizes accepted tools, filters explicit non-object roots, preserves metadata caching, and expands MCP runtime tests.

## Best Possible Solution

Land a narrow single-response relaxed parser only after maintainers approve the private SDK-cache dependency or select a supported SDK/upstream alternative, while preserving strict validation for every schema field other than an omitted root `inputSchema.type`.
