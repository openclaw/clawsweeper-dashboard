## What This Changes

Fix embedded Automation runs so an explicit empty `toolsAllow` list deliberately produces a tool-less run even when configuration inherits a non-empty tool allowlist.

## System Context

Automation `agentTurn` payloads enter the embedded agent runner, which combines runtime tool policy with inherited configuration before building a callable tool catalog. A guard rejects invalid explicit allowlists before model invocation, so its distinction between intentional tool-less execution and broken allowlists determines whether an Automation can start.

## Architecture Diagram

flowchart LR
  A[Automation agentTurn payload] --> B[Embedded agent runner]
  C[Inherited tool allowlist] --> B
  B --> D[Callable tool catalog]
  D --> E[Explicit allowlist guard]
  E --> F[Model invocation]

## Best Possible Solution

Land a narrowly tested guard change that recognizes an effective runtime `toolsAllow: []` as intentional tool disabling for inherited sources while retaining explicitly enforced restrictions.
