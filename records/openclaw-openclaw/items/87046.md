## Summary

Keep this PR open for a maintainer ownership decision, but do not merge it as written: it fixes a real registry-wipe mechanism by retaining every prior harness, including plugin-owned executable registrations that an intentional empty scope is supposed to remove.

## What This Changes

The PR snapshots and restores registered agent harnesses after the plugin loader or gateway activates an empty plugin registry, with a loader regression test.

## Best Possible Solution

Make intentional empty activation clear all plugin-owned registrations; if an empty scope is accidental, fix the scope planner or caller so required plugin IDs are retained, and keep any genuinely core-owned always-on harness outside the plugin lifecycle or restore it through an explicit owner classification with both removal and survival tests.

## Solution Assessment

No. Restoring every previous harness is broader than the reported need and violates plugin ownership; the safer fix is to preserve only an explicit core-owned class or prevent the erroneous empty scope at its source.
