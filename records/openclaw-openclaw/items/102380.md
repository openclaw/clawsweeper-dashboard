## Summary

Keep open. Current main and the latest release still route Slack reply controls through a queued `slack:interaction` system event plus an immediate heartbeat wake; the remaining work is the maintainer decision about whether user-initiated controls should move to the normal inbound reply pipeline.

## What This Changes

The issue asks Slack reply-button/select clicks to be dispatched as synthetic inbound reply turns instead of heartbeat wakes.

## Best Possible Solution

Choose one delivery owner for user-initiated Slack reply controls, preferably inbound-turn dispatch with regression coverage and live Slack proof for clicked value, thread delivery, and busy-run behavior while preserving plugin and native-approval handlers.

## Solution Assessment

Unclear until maintainers choose the owner boundary. Inbound-turn dispatch is a plausible best fix for user-initiated controls, but it changes the current heartbeat-owned interaction design and must be coordinated with plugin/approval early returns and session-conflict handling.
