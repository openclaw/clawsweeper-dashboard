## Summary

Keep open. Current main and v2026.6.11 still route Slack reply controls through a queued Slack interaction system event plus an immediate heartbeat wake; the predecessor value-surfacing report and the broader session-init conflict report do not resolve the Slack delivery-owner decision.

## What This Changes

Requests Slack reply button and select clicks be handled as normal inbound reply turns instead of immediate heartbeat wakes.

## Best Possible Solution

Maintainers should choose one delivery owner for user-initiated Slack controls, preferably inbound-turn dispatch with regression coverage and live Slack proof for clicked value, thread delivery, and busy-run behavior while preserving plugin and approval early returns.
