## Summary

Keep open. Current main still routes Slack reply button/select clicks through queued system events plus an immediate heartbeat wake rather than the normal inbound reply pipeline; the earlier value-injection subproblem is closed, but this fresh issue raises a remaining delivery/ownership question that is not implemented.

## What This Changes

The issue requests changing Slack reply button/select interactions from heartbeat wakes to normal inbound reply turns so clicked values are delivered reliably.

## Best Possible Solution

Make Slack reply button/select clicks a single reliable user-initiated reply path: either synthesize inbound turns with the existing channel-inbound APIs, or keep heartbeat delivery only if maintainers document and prove value delivery, visible replies, and busy-session retries without loss.
