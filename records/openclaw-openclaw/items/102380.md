## Summary

Keep open. Current main and the latest release still route Slack reply button/select clicks through queued `slack:interaction` system events plus an immediate heartbeat; the closed predecessor covers value surfacing and the open conflict issue covers one race, but no merged/current item resolves the heartbeat-vs-inbound-turn delivery-owner decision.

## What This Changes

Requests changing Slack reply button/select handling so user clicks are modeled as synthetic inbound reply turns instead of heartbeat wakes.

## Best Possible Solution

Maintainers should choose one delivery owner, preferably inbound-turn dispatch for user-initiated Slack reply controls with regression and live Slack proof while keeping plugin/approval early returns and idle heartbeat behavior intact.
