## Summary

Keep open. Current main and the latest stable release still route Slack reply controls through a queued `slack:interaction` system event plus an immediate hook heartbeat; related closed items cover wake/thread/value surfacing, and the open conflict issue covers one race, but no merged/current item resolves the heartbeat-vs-inbound-turn delivery-owner decision.

## What This Changes

The issue requests that Slack reply buttons/selects dispatch a normal inbound reply turn with synthetic user input instead of waking the session through the heartbeat path.

## Best Possible Solution

Maintainers should choose one delivery owner, preferably inbound-turn dispatch for user-initiated Slack reply controls with regression and live Slack proof, while keeping plugin/approval handlers and idle heartbeat behavior intact.

Rationale: Current source proves the path is still heartbeat-owned, but changing it would replace a recently accepted Slack system-event design and must preserve plugin interactive handlers, native approvals, thread routing, and session-conflict handling.

Options:

- **Move Reply Controls To Inbound Turns (recommended):** Treat user-initiated Slack reply controls like normal channel input, with tests and live proof for clicked value, thread delivery, and busy-run behavior.
- **Keep Heartbeat And Harden It:** Retain the system-event heartbeat design, but require proof that values, visible replies, and retry behavior are reliable end to end.
- **Wait For Shared Conflict Review:** Defer this delivery-owner choice until the related session-init conflict work is reviewed, then retest Slack interactions against the chosen recovery layer.

## Reproduction Assessment

Yes at source level: current main and `v2026.6.11` still enqueue Slack reply-control interactions and request an immediate hook heartbeat, and current tests assert that path. The intermittent visible reply-drop and active-run race still need live Slack proof on current main.

## Solution Assessment

Unclear until maintainers choose the owner boundary. Inbound-turn dispatch is a plausible best fix for user-initiated controls, but it changes the current heartbeat-owned interaction design and must be coordinated with plugin/approval early returns and session-conflict handling.
