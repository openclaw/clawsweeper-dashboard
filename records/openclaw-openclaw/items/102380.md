## Summary

Keep open. Current main and v2026.6.11 still route Slack reply controls through a queued `slack:interaction` system event plus an immediate hook heartbeat; the predecessor value-surfacing issue was closed with proof of the production drain path, and the active-run race is tracked separately, but no merged/current item resolves the Slack heartbeat-vs-inbound-turn delivery-owner decision.

## What This Changes

The issue requests changing Slack reply-button/select interactions from a heartbeat wake to the inbound reply-turn pipeline so clicked values are modeled and delivered like normal user replies.

## Best Possible Solution

Maintainers should choose one delivery owner: preferably inbound-turn dispatch for user-initiated Slack reply controls with focused regression and live Slack proof, while leaving plugin/approval handlers and idle heartbeat behavior intact.

Question: Should Slack reply button/select clicks continue to be delivered as heartbeat-owned system events, or should the Slack plugin synthesize normal inbound reply turns for these user-initiated actions?

Options:

- **Move Reply Controls To Inbound Turns (recommended):** Treat user-initiated Slack reply controls like normal channel input, with tests and live proof for clicked value, thread delivery, and busy-run behavior.
- **Keep Heartbeat And Harden It:** Retain the system-event heartbeat design but require proof that values, visible replies, and retry behavior are reliable end to end.
- **Wait For Shared Conflict Review:** Defer this delivery-owner choice until the related session-init conflict work is reviewed, then retest Slack interactions against the chosen recovery layer.

## Reproduction Assessment

Yes at source level: current main and v2026.6.11 still enqueue Slack reply-control interactions and request an immediate hook heartbeat, and current tests assert that path. The intermittent visible reply-drop and active-run race still need live Slack proof on current main.

## Solution Assessment

Unclear until maintainers choose the owner boundary. Inbound-turn dispatch looks cleaner for user-initiated clicks, but prior maintainer proof accepted heartbeat draining for value surfacing, so the safest next step is an explicit direction decision.
