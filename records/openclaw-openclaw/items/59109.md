## Summary

Keep open: current main has useful building blocks and a newly merged Codex-specific native-thread tool, but the requested generic public fork/resume/continue session lifecycle contract is still missing and needs maintainer product/API direction.

## What This Changes

Request a public session lifecycle API and UX for forking an existing session, resuming by session ID, and continuing the latest session.

## Best Possible Solution

Define one maintainer-approved public session lifecycle contract across SDK, Gateway protocol, CLI/chat/TUI UX, and docs, reusing existing resolution, checkpoint, transcript fork, and Codex-native primitives only where their ownership and security rules fit.
