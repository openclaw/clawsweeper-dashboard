## Summary

Keep open: current main and the latest release still do not expose `agents.list[].subagents.workspace`; default same-agent subagents intentionally inherit the requester workspace, while existing `requireAgentId` and cross-agent workspace fixes only cover adjacent mitigation paths.

## What This Changes

The issue requests an `agents.list[].subagents.workspace` config option so default subagents spawned by a parent agent can use a separate workspace from the parent.

## Best Possible Solution

Maintainers should choose the product/security direction first: either document `requireAgentId` plus isolated target profiles as the supported pattern, or add a narrow `subagents.workspace` contract across config schema, spawn resolution, bootstrap/attachment behavior, docs, and focused regression tests.

## Reproduction Assessment

Yes, source-level: current `sessions_spawn` falls back omitted `agentId` to the requester agent and same-agent workspace tests expect the child run to keep the requester workspace. I did not run tests because this review is read-only.

## Solution Assessment

Unclear: `subagents.workspace` is a plausible solution, but it adds a security-sensitive config surface and may not be better than requiring explicit isolated target profiles unless maintainers want same-agent child workspaces as a first-class contract.
