## Summary

Keep open: current main and v2026.6.11 still do not define a per-agent `subagents.workspace` override, and same-agent default subagent spawns continue to inherit the requester workspace. The linked PLUR1BUS memory plugin is useful adjacent context for per-agent memory/workspace separation, but it does not replace the missing core spawn/workspace config contract.

## What This Changes

The issue requests an `agents.list[].subagents.workspace` config option so default subagents spawned without `agentId` can use an isolated workspace instead of inheriting the parent agent workspace.

## Best Possible Solution

Define one opt-in child-workspace isolation contract across config, spawn resolution, docs, and tests, preserving current inheritance unless maintainers deliberately choose a migration or stricter default.

## Reproduction Assessment

Yes, at source level: current main omits `subagents.workspace` from the strict config schema and same-agent omitted-agent spawns still inherit `ctx.workspaceDir`. I did not run a live spawn because this is a read-only review.

## Solution Assessment

Unclear: a per-agent `subagents.workspace` override is plausible, but maintainers still need to choose precedence and the exact security boundary. The existing supported mitigation is explicit child agent profiles with `agentId` and optional `requireAgentId`, which is not the same UX.
