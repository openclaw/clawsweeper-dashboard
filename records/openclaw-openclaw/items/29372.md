## Summary

Keep open: current main and v2026.6.11 still do not implement `agents.list[].subagents.workspace`; same-agent/default subagent spawns inherit the requester workspace, while the supported isolation path today is a separate configured target agent or manual `cwd`, which does not change bootstrap workspace context. This remains useful but needs maintainer product/security direction because it adds a new config surface for session/workspace isolation.

## What This Changes

Request to add per-agent `agents.list[].subagents.workspace` config so default child subagents can use a different workspace from their parent agent.

## Best Possible Solution

Define a maintainer-approved isolation contract: either document the existing separate-agent/sandbox path as the intended model, or add a narrow `subagents.workspace` override with strict schema, docs, tests, and migration/doctor semantics.

## Reproduction Assessment

Yes, by source inspection: a default same-agent `sessions_spawn` uses the caller workspace as `explicitWorkspaceDir`, persists it as `spawnedWorkspaceDir`, and Gateway reuses it for the child run. I did not run a live agent reproduction because this review is read-only and cannot create runtime state.

## Solution Assessment

Unclear. The requested key is plausible, but repository policy sets a high bar for new config/env surface, so maintainers should decide whether a new core config key, existing per-agent profiles, sandboxing, or a plugin/API seam is the right long-term boundary.
