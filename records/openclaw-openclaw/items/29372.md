## Summary

Keep open: current main and v2026.6.11 still do not support `agents.list[].subagents.workspace`; the existing path is explicit target agents plus `requireAgentId`/sandbox policy, and the related cross-agent workspace bug is already fixed but does not cover same-agent default children.

## What This Changes

Request adds a per-agent `subagents.workspace` config option so default child sub-agents can use a separate workspace without defining a separate agent profile.

## Best Possible Solution

Maintainers should choose the intended isolation model: either document/enforce explicit target-agent profiles for isolated children, or approve a narrow `subagents.workspace` design with schema, docs, tests, and sandbox/bootstrap semantics.
