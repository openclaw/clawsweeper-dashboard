## Summary

Keep open: current main and v2026.6.11 still do not expose `agents.list[].subagents.workspace`; same-agent default subagents inherit the requester workspace, while `cwd`, `requireAgentId`, target-agent profiles, and sandbox settings are only partial alternatives. The linked Plur1bus repository is useful adjacent workspace-isolation context, but it does not close the missing core security/config decision.

## What This Changes

Request adds a per-agent `subagents.workspace` config option so default subagents can use an isolated workspace instead of inheriting the parent workspace.

## Best Possible Solution

Make a maintainer-approved core decision for default subagent workspace isolation, then implement either a narrow opt-in config contract or a documented profile/sandbox path with schema, docs, doctor expectations, and focused spawn tests aligned.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature/config request. Source inspection gives high confidence that current main lacks the requested key and that same-agent subagents still inherit the requester workspace.

## Solution Assessment

Unclear: the proposed per-agent config is plausible, but it changes a security-sensitive default/config surface. A better final design may use explicit target-agent profiles, sandbox defaults, or a narrower opt-in core contract after maintainer review.
