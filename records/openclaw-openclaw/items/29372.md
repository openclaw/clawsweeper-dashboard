## Summary

Keep open: current main and v2026.6.11 still lack `agents.list[].subagents.workspace`; default same-agent subagents intentionally inherit the requester workspace, while existing mitigations are named target agents, `requireAgentId`, and manual `sessions_spawn.cwd`. The request is useful but security- and config-sensitive, so it needs maintainer product/security review rather than auto-close or an automated fix PR.

## What This Changes

Request to add a per-agent `agents.list[].subagents.workspace` config option so default subagents spawned without `agentId` can use an isolated child workspace.

## Best Possible Solution

Choose a maintainer-approved isolation model: either document `requireAgentId` plus named agent profiles as the supported path, or add a narrow explicit subagent workspace policy with schema, docs, source tests, and security/upgrade behavior.

## Reproduction Assessment

Not applicable as a feature request, but source inspection gives high confidence about the current behavior: default same-agent subagents inherit the requester workspace and the strict schema has no `subagents.workspace` key.

## Solution Assessment

Unclear. The requested config is plausible, but the best solution may be named child agent profiles with `requireAgentId` unless maintainers want a new default-subagent workspace contract.
