- `impact:security`: The request is about preventing default child subagents from receiving bootstrap access to a parent workspace that may contain sensitive files.
- `impact:session-state`: The requested behavior changes how spawned child sessions select and persist workspace context.

## Summary

Keep open: current main still lacks a `subagents.workspace` config field, and same-agent default subagent spawns still inherit the requester workspace; the linked Plur1bus plugin is useful adjacent memory/workspace isolation context but does not implement this OpenClaw runtime/config behavior.

## What This Changes

Request adding `agents.list[].subagents.workspace` so default child subagents can use a separate workspace from the parent agent without requiring separate child profiles.

## Best Possible Solution

Define a narrow opt-in default-child workspace isolation contract across config schema, spawn resolution, persisted session metadata, docs, and tests, preserving current inheritance unless maintainers explicitly choose a migration path.

## Reproduction Assessment

Yes, at source level: current main omits `subagents.workspace` from strict config schemas and same-agent omitted-agent spawns still inherit `ctx.workspaceDir`. I did not run a live spawn because this is a read-only review.

## Solution Assessment

Unclear: the proposed config key is plausible, but maintainers need to define precedence and the isolation boundary before implementation. The current supported alternative is explicit child agent profiles with `agentId` and optional `requireAgentId`, which is not the same user experience.
