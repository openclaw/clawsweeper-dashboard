## Summary

Keep open: current main still lacks `agents.list[].subagents.workspace`, and same-agent default subagents continue to inherit the requester workspace. This is a security-sensitive public config/product decision, not a conservative cleanup close.

## What This Changes

The issue requests a per-agent `subagents.workspace` config option so default child subagents spawned without `agentId` can use a separate workspace from the parent agent.

## Best Possible Solution

Maintainers should first choose the supported isolation model, then either document explicit child profiles as the security boundary or add a narrow opt-in default-child workspace override with schema, docs, doctor/security review, and regression coverage.
