## Summary

Keep open: current main still lacks a per-agent `subagents.workspace` override, and default same-agent subagent spawns still inherit the requester workspace. Related fixes cover explicit target-agent workspace selection, `requireAgentId`, and `cwd` separation, but none implement this requested config contract.

## What This Changes

Request adds `agents.list[].subagents.workspace` so default subagents can use a configured child workspace instead of inheriting the parent workspace.

## Best Possible Solution

Design an opt-in child-workspace isolation contract with explicit precedence and security limits, then implement schema, runtime, docs, and regression tests across native and ACP subagent paths.

## Reproduction Assessment

Yes, at source level: current main omits `subagents.workspace` from the strict config schema and same-agent omitted-agent spawns still inherit `ctx.workspaceDir`. I did not run a live spawn because this is a read-only review.

## Solution Assessment

Unclear: the proposed field is plausible, but maintainers still need to define the exact isolation boundary and precedence. The current supported mitigations are explicit child profiles with `requireAgentId`, sandbox policy, and per-call `cwd`, which are not the same UX.
