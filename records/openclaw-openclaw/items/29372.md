## Summary

Keep open: current main and v2026.6.11 still lack the requested per-agent `subagents.workspace` override. The linked PLUR1BUS plugin is useful adjacent memory-isolation context, and `requireAgentId` is a supported mitigation, but neither changes default same-agent subagent workspace inheritance.

## What This Changes

The issue requests an `agents.list[].subagents.workspace` option so default subagents can use a separate workspace from their parent without defining a separate agent profile.

## Best Possible Solution

Define one opt-in child-workspace isolation contract, then wire it through config schema/types, spawn workspace resolution, docs, and focused regressions while preserving current inheritance unless maintainers choose a migration.

## Reproduction Assessment

Yes, at source level: current main omits `subagents.workspace` from the strict schema/type and same-agent spawns still inherit the requester workspace. I did not run a live spawn because this review is read-only.

## Solution Assessment

Unclear: a per-agent `subagents.workspace` override is plausible, but maintainers still need to choose precedence and the exact security boundary. The current explicit-profile plus `requireAgentId` path is a mitigation, not an equivalent solution.
