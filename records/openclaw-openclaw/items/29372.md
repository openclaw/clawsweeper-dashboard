## Summary

Keep open: current main and the latest release do not implement the requested per-agent subagent workspace config. Source shows same-agent/default subagents still inherit the requester workspace, while current docs only offer explicit target agents, `requireAgentId`, and `cwd` as mitigations, so this remains a security-sensitive config/product decision rather than a narrow bug fix.

## What This Changes

Add a per-agent `agents.list[].subagents.workspace` option so default child subagents can use an isolated workspace instead of inheriting the parent workspace.

## Best Possible Solution

Design an opt-in core subagent workspace policy only if maintainers accept the security/config direction, preserving current behavior by default or pairing any breaking change with docs and doctor migration coverage.

## Reproduction Assessment

Yes for the current behavior: source and tests show omitted-`agentId` same-agent subagents inherit the requester workspace, and the strict config schema has no `subagents.workspace` key. This is still a feature/config request rather than a broken documented behavior contract.

## Solution Assessment

Unclear: the proposed config directly targets default child workspace isolation, but it adds a public security-sensitive config surface. Maintainers should choose the desired default compatibility and sandbox/ACP semantics before implementation.
