## Summary

Keep open: current main and the latest release still do not support `agents.list[].subagents.workspace`, and same-agent/default subagent spawns still inherit the caller workspace. Current main does provide the safer `requireAgentId` plus explicit target-agent workspace path as a mitigation, but that does not satisfy the requested default-subagent workspace override; the Plur1bus plugin linked in discussion is useful adjacent context, not a replacement for this core spawn/workspace contract.

## What This Changes

Request a per-agent `subagents.workspace` config option so default subagents spawned without `agentId` can use a different workspace from their parent agent.

## Best Possible Solution

Decide one explicit subagent isolation model: either add a narrow opt-in child workspace contract with schema/docs/tests for native and ACP spawn paths, or keep the current `requireAgentId` plus configured target-agent profile pattern as the supported isolation boundary.

## Reproduction Assessment

Yes for the current behavior: source inspection shows omitted `agentId` resolves to the requester and same-agent spawns pass the caller workspace as the inherited workspace. This is not a broken documented contract; it is a request for a new isolation option.

## Solution Assessment

Unclear: the proposed override is plausible, but it may duplicate the existing target-agent workspace and `requireAgentId` model. A maintainer should decide whether the best product shape is a new config key, stricter explicit-profile guidance, or a broader workspace/sandbox contract.
