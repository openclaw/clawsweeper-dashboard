## Summary

Keep open: current main and v2026.6.11 still do not support `agents.list[].subagents.workspace`; same-agent default child spawns still inherit the requester workspace, while the supported mitigations are explicit target agents, `requireAgentId`, sandbox policy, and per-call `cwd`.

## What This Changes

The issue requests a per-agent `agents.list[].subagents.workspace` config option so default subagents spawned without `agentId` can use a different workspace from their parent agent.

## Best Possible Solution

Maintainers should first choose the workspace isolation policy, then either document explicit child profiles as the supported boundary or add a narrow opt-in config with schema, docs, doctor/security review, and regression coverage for same-agent, cross-agent, `cwd`, and sandbox paths.
