## Summary

Keep open: current main and v2026.6.11 still do not support `agents.list[].subagents.workspace`; this remains a security-sensitive product decision about whether default subagents should get a new workspace override or continue using explicit child profiles plus `requireAgentId`.

## What This Changes

The issue requests an `agents.list[].subagents.workspace` option so default subagents can use a workspace different from their parent agent without defining separate agent profiles.

## Best Possible Solution

Maintainers should choose the supported isolation model first: keep explicit child profiles plus `requireAgentId`, or approve a narrow opt-in `subagents.workspace` contract with schema, docs, doctor/security review, and regression coverage across same-agent, cross-agent, `cwd`, and sandbox paths.
