## Summary

Keep open: current main and v2026.6.11 still do not support `agents.list[].subagents.workspace`; related merged work added `requireAgentId`, cross-agent target workspace routing, and per-call `cwd`, but the requested default-child workspace boundary remains a product/security decision. The linked Plur1bus plugin is useful adjacent per-agent memory isolation context, but it does not replace the missing core subagent workspace contract.

## What This Changes

The issue requests an `agents.list[].subagents.workspace` option so default child subagents can use a workspace different from their parent agent.

## Best Possible Solution

Maintainers should choose the supported isolation model first: keep explicit child profiles plus `requireAgentId`, or approve a narrow opt-in `subagents.workspace` contract with schema, docs, doctor/security review, and regression coverage across same-agent, cross-agent, `cwd`, and sandbox paths.
