## Summary

Keep open: current main and the latest release still lack the requested per-agent `subagents.workspace` config, and same-agent/default subagent spawns continue to inherit the requester workspace. This is security- and session-boundary-relevant, but it adds public config behavior and needs maintainer product/security direction before implementation.

## What This Changes

The issue requests a new `agents.list[].subagents.workspace` config option so default subagents can use an isolated workspace without explicit child agent profiles.

## Best Possible Solution

Define one opt-in child-workspace isolation contract across config schema, spawn resolution, docs, and regression tests, while preserving current inheritance unless maintainers approve a migration.

## Reproduction Assessment

Yes, at source level: current main omits `subagents.workspace` from strict config and same-agent omitted-agent spawns still inherit `ctx.workspaceDir`. I did not run a live spawn because this is a read-only review.

## Solution Assessment

Unclear: the requested config is plausible, but maintainers still need to choose precedence and the real security boundary. The existing workaround is explicit child profiles plus `agentId` and optional `requireAgentId`, which avoids accidental default spawns but does not provide the requested ergonomic isolation.
