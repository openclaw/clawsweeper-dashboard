## Summary

Keep open: current main and v2026.6.11 still do not implement a per-agent `subagents.workspace` override; omitted-agent same-agent spawns continue to inherit the requester workspace, and `requireAgentId` is only an explicit-profile mitigation.

## What This Changes

The issue requests a per-agent `agents.list[].subagents.workspace` option so default child subagents can use a separate workspace from their parent agent.

## Best Possible Solution

Define one opt-in child-workspace isolation contract, or an equivalent explicit-profile flow, that covers schema, spawn precedence, native and ACP behavior, docs, and security regression tests while preserving current inheritance unless maintainers choose otherwise.

## Reproduction Assessment

Yes, at source level: current main strictly defines per-agent `subagents` without `workspace`, and omitted-agent same-agent spawns still derive child workspace from requester context. I did not run a live spawn because this review is read-only.

## Solution Assessment

Unclear: per-agent `subagents.workspace` is plausible, but maintainers still need to choose the isolation boundary and precedence rules. The existing explicit child-profile plus `requireAgentId` path is a mitigation, not the requested default-subagent workspace override.
