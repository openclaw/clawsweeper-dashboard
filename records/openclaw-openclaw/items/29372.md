## Summary

Keep open: current main still has no `agents.list[].subagents.workspace` config, and same-agent default subagents continue to inherit the requester's workspace. Related fixes added cross-agent target workspace routing and explicit `cwd`, but they do not provide the requested default child workspace override.

## What This Changes

The issue requests a per-agent `subagents.workspace` configuration option so default subagents spawned without `agentId` can use a separate workspace from the parent agent.

## Best Possible Solution

Decide and document a narrow opt-in child-workspace policy for default subagents, with schema/types/docs/tests and clear interaction with `requireAgentId`, explicit agent profiles, `cwd`, sandbox inheritance, and doctor/config compatibility.

## Reproduction Assessment

Yes at source level, but not by an executed live repro in this read-only review. Current main lacks `subagents.workspace`, and omitted-agent native spawns set the target to the requester while passing the requester's workspace as the explicit inherited workspace.

## Solution Assessment

Unclear: the requested config is plausible, but maintainers should choose whether a per-agent child workspace key, stricter `requireAgentId`/profile guidance, or a broader subagent workspace policy is the right permanent boundary.
