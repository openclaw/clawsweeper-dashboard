## Summary

Keep open: current main and v2026.6.11 still do not support `agents.list[].subagents.workspace`; the supported mitigations are explicit target agents, `requireAgentId`, sandbox policy, and per-call `cwd`, while no-agentId same-agent children still inherit the requester workspace.

## What This Changes

Request to add `agents.list[].subagents.workspace` so default child subagents can use an isolated workspace without requiring separate child agent profiles.

## Best Possible Solution

Maintainers should choose the product boundary first: either keep explicit target agent profiles as the supported isolation model, or add a narrow opt-in default-child workspace config with schema, docs, doctor/security review, and regression coverage for same-agent, cross-agent, cwd, and sandbox paths.

- **Defer for broader spawn policy:** Hold this until subagent workspace, cwd, sandbox, and skill workdir isolation are designed together with https://github.com/openclaw/openclaw/issues/87253.

Unclear: the proposed config directly solves the no-agentId isolation request, but the current supported path is explicit child profiles with `requireAgentId` and optional per-call `cwd`. Maintainers need to decide whether the extra config surface is worth the security-boundary complexity.
