## Summary

Keep open: current main still has no `agents.list[].subagents.workspace` or equivalent default-subagent workspace override. Same-agent/default native subagents still inherit the requester workspace; merged work only fixed cross-agent target workspace selection and separated task `cwd` from agent bootstrap workspace.

## What This Changes

The issue requests a per-agent `subagents.workspace` config option so default subagents can run from an isolated workspace without creating separate agent profiles.

## Best Possible Solution

Maintainers should choose the workspace-isolation model first: either keep explicit child agent profiles as the supported path, or add a narrow `subagents.workspace` contract with schema, docs, tests, security review, and clear precedence rules.

## Reproduction Assessment

Yes from source inspection: default/same-agent spawns carry the requester workspace into `spawnedWorkspaceDir`, and the config schema has no `subagents.workspace` key. This is a feature gap rather than a broken current contract.

## Solution Assessment

Unclear: the proposed config key is plausible, but it is not yet proven better than explicit child agent profiles, `requireAgentId`, sandbox/workspace-only policy, or broader path permissions. Maintainers need to settle the product and security contract before implementation.
