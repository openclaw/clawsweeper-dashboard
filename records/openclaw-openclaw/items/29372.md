## Summary

Keep open: current main and the latest release still do not support `agents.list[].subagents.workspace`; this remains a security-sensitive product/config decision because the supported mitigations are explicit child agent profiles, `subagents.requireAgentId`, sandbox workspace policy, and per-call `cwd`.

## What This Changes

Requested support for an `agents.list[].subagents.workspace` option so default child subagents can use a different workspace from their parent agent.

## Best Possible Solution

Maintainers should choose one supported isolation contract: keep explicit child profiles plus `requireAgentId`, or approve a narrow opt-in `subagents.workspace` with schema, docs, doctor/security review, and coverage across native, ACP, `cwd`, sandbox, and cross-agent paths.
