## Summary

Keep open: current main and v2026.6.11 still do not support `agents.list[].subagents.workspace`; the linked Plur1bus repository is useful adjacent context, but this remains a core product/security-boundary decision rather than something current plugin or config surfaces already solve.

## What This Changes

Request to add `agents.list[].subagents.workspace` so default child subagents spawned without `agentId` can use an isolated workspace distinct from the parent agent workspace.

## Best Possible Solution

Maintainers should choose the supported isolation model first: keep explicit child profiles plus `requireAgentId`, or approve a narrow opt-in `subagents.workspace` contract with schema, docs, doctor/security review, and regression coverage across same-agent, cross-agent, `cwd`, and sandbox paths.
