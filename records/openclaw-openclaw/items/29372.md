## Summary

Keep open: current `main` and the latest release still do not support `agents.list[].subagents.workspace`; the supported mitigations are explicit child agent profiles, `subagents.requireAgentId`, sandbox workspace policy, and per-call `cwd`, so this remains a maintainer product/security-boundary decision.

## What This Changes

The issue requests a per-agent `subagents.workspace` configuration field so default child subagents can use a workspace different from the parent agent without defining separate agent profiles.

## Best Possible Solution

Maintainers should choose the supported isolation model first: keep explicit child profiles plus `requireAgentId`, or approve a narrow opt-in `subagents.workspace` contract with schema, docs, doctor/security review, and regression coverage across same-agent, cross-agent, `cwd`, and sandbox paths.
