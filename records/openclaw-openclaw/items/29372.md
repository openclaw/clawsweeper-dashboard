## Summary

Keep open: current main and v2026.6.11 still do not support `agents.list[].subagents.workspace`; the remaining question is whether OpenClaw should add a new public, security-sensitive workspace-boundary config or keep explicit child agent profiles plus `requireAgentId` as the supported isolation model. The linked Plur1bus repository is useful adjacent context for per-workspace isolation, but it does not replace the missing OpenClaw core config decision.

## What This Changes

Request adds an `agents.list[].subagents.workspace` config option so default child subagents spawned without `agentId` can use a separate workspace from the parent agent.

## Best Possible Solution

Maintainers should choose the supported isolation model first: keep explicit child profiles plus `requireAgentId`, or approve a narrow opt-in `subagents.workspace` contract with schema, docs, doctor/security review, and regression coverage across same-agent, cross-agent, `cwd`, and sandbox paths.
