- `impact:security`: The request is about preventing default subagents from receiving access to a parent workspace that may contain sensitive files.

## Summary

Keep open: current main and the latest release still lack a per-agent `subagents.workspace` override, while `cwd` and `requireAgentId` only provide manual or explicit-profile mitigations. The linked Plur1bus repository is useful adjacent memory-isolation context, but it does not implement this core spawn/workspace config contract.

## What This Changes

The issue requests an `agents.list[].subagents.workspace` config option so default subagents can use an isolated child workspace instead of inheriting the parent workspace.

## Best Possible Solution

Define one opt-in child-workspace isolation contract across config schema, spawn resolution, docs, doctor/security guidance, and regression tests, preserving current inheritance unless maintainers choose a migration or stricter default.

## Reproduction Assessment

Yes, at source level: current main omits `subagents.workspace` from the strict config schemas and tests assert same-agent omitted-agent spawns inherit the requester workspace. I did not run a live spawn because this review is read-only.

## Solution Assessment

Unclear: a per-agent `subagents.workspace` override is plausible, but maintainers still need to choose precedence and the exact security boundary. The existing supported mitigations are explicit child agent profiles, `requireAgentId`, sandbox settings, and per-call `cwd`, which do not provide the same UX.
