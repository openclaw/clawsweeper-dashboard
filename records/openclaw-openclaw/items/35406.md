## Summary

Keep open: current main and the latest release still send non-image Office/PDF reads through the generic text-decoding path, and an open closing PR exists but is conflicting and needs maintainer direction rather than issue cleanup.

## What This Changes

The issue asks for the `read` tool to avoid returning raw binary output for PDF and Office document formats, either by returning a clear unsupported-file message or by using a document parser.

## Best Possible Solution

Add a narrow read-tool fallback that detects known PDF/Office binary document formats, returns a clear unsupported-document message, and points users to the PDF/document workflow while leaving richer Office parsing or provider-native forwarding to the broader document-input issues.
