## Summary

Keep open: current main and v2026.6.11 still decode non-image `read` targets as text, while the linked fallback PR is open but conflicting and still targets retired `pi-tools` paths. Broader document attachment and provider-native file issues are useful context, but they do not resolve this local read-tool token-waste behavior.

## What This Changes

The issue asks OpenClaw to prevent the `read` tool from returning raw binary document bytes for formats like DOCX, PDF, PPTX, and XLSX, either by returning a safe fallback message or by extracting document text.

## Best Possible Solution

Land or replace a narrow read-tool fallback that detects Office/PDF binary documents before text decoding, while routing true extraction to the document-extract/plugin or broader file-input design with explicit security limits.

- **Defer To File Design:** Keep the read tool unchanged for now and track the behavior under broader provider-native or attachment/document extraction roadmap items.
