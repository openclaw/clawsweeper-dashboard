## Label Justifications

- `P2`: The issue describes a bounded but real core read-tool token/context waste problem with limited blast radius.

## Summary

Keep open: current main and the latest release still let non-image `read` inputs fall through to text decoding, so PDF/Office bytes can still enter the tool result. The direct same-repo guard PRs are closed unmerged, and the only open closing candidate is a conflicting fork PR that needs maintainer review or replacement.

## What This Changes

The issue requests safer `read` handling for binary document formats such as PDF, DOCX, PPTX, and XLSX so raw bytes do not waste tokens or pollute context.

## Best Possible Solution

Decide the narrow read-tool contract, then land or replace the linked guard with a bounded current-main fallback that prevents raw binary document bytes from entering context while leaving richer parsing and provider-native file support to the related document work.
