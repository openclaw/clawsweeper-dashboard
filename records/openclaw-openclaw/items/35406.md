## Summary

Keep open: current main and the latest release still let non-image PDF/Office reads fall through to text decoding, while the only linked live implementation is an open conflicting fork PR rather than a merged fix. The narrow fallback is source-proven, but maintainers still need to choose warning-only behavior versus broader document parsing.

## What This Changes

Request that the read tool stop returning garbled binary bytes for PDF/Office formats by warning or parsing document text.

## Best Possible Solution

Adopt a narrow read-tool fallback for known binary document formats, with focused tests for host and sandbox reads, while leaving full document extraction to the pdf tool or broader document-ingest work.

- **Guidance Only:** Update tool guidance and rely on existing document-specific tools, accepting that unsupported binary reads can still be attempted.
- **Fold Into Document Ingest:** Track the behavior under broader provider-native or document-extraction work and require parser/security decisions before changing read.

## Reproduction Assessment

Yes, at source level. Current read checks only image MIME and then decodes non-image buffers as text, while PDF/Office MIME mappings are not used to return an unsupported-document fallback.

## Solution Assessment

Unclear until maintainers choose scope. A narrow fallback is the smallest maintainable first step; automatic parsing belongs in dedicated PDF/document surfaces or a broader document-ingest design.
