## Summary

Keep open: current `main` and the latest release still let non-image `read` inputs fall through to text decoding, so PDF/Office bytes can still enter the tool result. Same-repo guard PRs are closed unmerged, and the only open closing PR is a conflicting fork branch that needs maintainer review or replacement.

## What This Changes

The issue requests safer `read` handling for binary document formats such as `.docx`, `.pdf`, `.pptx`, and `.xlsx` so raw bytes are not returned as garbled text and wasted context.

## Best Possible Solution

Land or replace the linked guard with a bounded read-tool fallback that prevents raw binary document bytes from entering context, while leaving richer parsing and provider-native file forwarding to approved document work.
