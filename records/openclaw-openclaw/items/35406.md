## Summary

Keep open: current main and v2026.6.11 still decode non-image `read` targets as text, while the only linked read-tool fallback PR is open and conflicting and the broader document/attachment issues do not solve this local read-tool behavior.

## What This Changes

The issue requests that the read tool stop returning raw garbled binary contents for Office/PDF-style documents and instead warn or route users to document extraction.

## Best Possible Solution

Land or replace a narrow read-tool fallback that detects Office/PDF binary documents before text decoding, while routing true extraction to the document-extract/plugin or broader file-input design with explicit security limits.
