## Summary

Keep open: current `main` and the latest release still send non-image `read` targets through text decoding, while the only open closing PR is unmerged and conflicting. The narrow fallback is still useful, but maintainers need to choose the safe-fallback boundary versus broader document parsing/provider-native file work.

## What This Changes

The issue requests that the `read` tool stop emitting garbled raw binary text for Office/PDF-style document formats and either return a safe fallback message or extract readable document text.

## Best Possible Solution

Land or replace a narrow read-tool fallback that detects Office/PDF binary documents before text decoding and returns a clear unsupported-document message, while keeping actual extraction in the dedicated PDF/document/plugin or broader file-input design with explicit limits.
