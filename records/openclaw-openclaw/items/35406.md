## Summary

Keep this issue open: current main and the latest release still route non-image `read` content through text decoding, so the binary-document token-waste problem remains. The open linked fork PR is a candidate implementation path, not a merged fix, and the broader document/file-input issues only partially overlap this narrower read-tool fallback request.

## What This Changes

The issue asks OpenClaw to stop the `read` tool from returning raw binary-looking output for document formats such as PDF, DOCX, PPTX, and XLSX, either by returning a safe fallback message or by extracting readable text.

## Best Possible Solution

Resolve the open candidate PR, then implement a bounded binary-document fallback in the shared read path while leaving full document extraction or provider-native forwarding to the dedicated media/document issues.
