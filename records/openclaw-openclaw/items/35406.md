## Summary

Keep this issue open: current main and the latest release still route non-image read-tool files through text decoding, so the requested binary-document fallback is not implemented. The linked open fork PR is useful context but is conflicting and targets older read-tool paths, while broader document extraction issues only partially overlap.

## What This Changes

The issue requests that the `read` tool avoid returning raw binary output for document formats such as `.docx`, `.pdf`, `.pptx`, and `.xlsx`, either by returning a clear unsupported-file message or by extracting text.

## Best Possible Solution

Add a bounded unsupported-document fallback in the current shared read tool, and leave full document parsing or provider-native file forwarding to the broader media/document work unless maintainers explicitly choose that direction.
