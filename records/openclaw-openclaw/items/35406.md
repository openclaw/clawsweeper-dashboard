## Summary

Keep open: current main still lets the `read` tool treat non-image binary document formats as UTF-8 text, and the related PR attempts are unmerged, conflicting, or closed rather than a safe canonical fix.

## What This Changes

The issue requests safer `read` behavior for PDF and Office-style binary documents to avoid raw binary output and token waste, with possible fallback guidance or document extraction support.

## Best Possible Solution

Approve a narrow read-tool guard that blocks raw PDF/Office binary bytes from transcript context and points users to the `pdf` or document extraction path, while leaving richer native parsing/provider forwarding to the related product-design issues.
