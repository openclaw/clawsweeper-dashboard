## Summary

Keep open: current main and the latest release still let non-image `read` targets fall through to text decoding, so binary document reads can still waste context. The linked fork PR is open but conflicting, and the broader document/media issues only partially overlap the direct read-tool fallback request.

## What This Changes

Request to make the `read` tool avoid returning raw binary document bytes for formats like `.docx`, `.pdf`, `.pptx`, and `.xlsx`, either by warning or extracting text.

## Best Possible Solution

Add bounded binary-document detection in the shared `read` path that returns a compact actionable fallback, while leaving full document extraction and provider-native file handling to dedicated document/media-input work.
