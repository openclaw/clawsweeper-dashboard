## Summary

Keep open: current main and v2026.6.11 still route non-image PDF/Office-style reads through text decoding, and the linked implementation candidate is open but conflicting and targets older read-tool files.

## What This Changes

The issue asks OpenClaw’s read tool to avoid returning raw binary bytes for PDF and Office-style document formats, either by warning or by parsing extracted text.

## Best Possible Solution

Approve a narrow read-tool fallback guard for known binary document formats, and keep full document extraction or provider-native forwarding in the broader linked document/file issues.

## Solution Assessment

Unclear until maintainers choose the boundary. A narrow unsupported-format fallback is the safest small fix for token waste; automatic parsing belongs in the shared document extraction or provider-native file tracks.
