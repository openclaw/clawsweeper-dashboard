## Summary

Keep open: current main and the latest release still route non-image read inputs through text decoding, so PDF/Office bytes can still enter the tool result. The open linked implementation candidate is unmerged and conflicting, so this issue should stay open until maintainers review, replace, or close that path.

## What This Changes

Request to make the agent read tool avoid raw binary output for PDF and Office-style documents, preferably with a safe fallback message or a parser-backed extraction path.

## Best Possible Solution

Review, repair, replace, or close the linked guard PR, with a bounded read-tool fallback that prevents raw binary document bytes from entering context while leaving richer extraction and provider-native forwarding to their separate design tracks.
