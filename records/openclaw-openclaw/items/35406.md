## Summary

Keep open: current main and v2026.6.11 still route non-image read inputs through text decoding, so PDF/Office bytes can still become tool-result text. The only open closing implementation is a conflicting fork PR, so this needs maintainer direction rather than cleanup closure.

## What This Changes

Request to make the read tool avoid raw PDF/Office binary output by returning a fallback warning or extracted text.

## Best Possible Solution

Approve and land a narrow read-tool fallback for known binary document formats, while keeping full document parsing and provider-native file handling in the broader linked design issues or plugin path.
