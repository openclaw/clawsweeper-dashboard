## Summary

Keep open: current main still sends non-image reads through UTF-8 text decoding, so binary Office/PDF reads can still waste context; the open linked guard PR is an implementation candidate, not a reason to close this issue before it lands or is replaced.

## What This Changes

The issue asks OpenClaw to prevent the read tool from returning raw binary document bytes for formats such as PDF, DOCX, PPTX, and XLSX, either by warning or by extracting text.

## Best Possible Solution

Add a bounded MIME/content-aware safe fallback in the shared read-tool path for known binary document formats, and leave native document extraction to the existing PDF/document tools or separate maintainer-approved extraction issues.

- **Defer to document-input tracks:** Keep read unchanged and route all document handling to broader attachment, input_file, or provider-native file issues.

## Reproduction Assessment

Yes, at source level: current main checks only image MIME before decoding every non-image file buffer as text, so DOCX/PDF/Office bytes can still become model-visible output. I did not run a live agent turn in this read-only cleanup pass.

## Solution Assessment

Yes for the issue's safe-fallback option; no for broad automatic parsing in the read tool without maintainer direction. The narrow maintainable fix is a shared read guard plus tests, while extraction belongs in dedicated document paths.
