## Summary

Keep open: current main and the latest release still let the `read` tool decode non-image files as text, so PDF/Office bytes can still pollute the tool result. The closed same-repo PRs did not land, and the open cross-repo PR that references this issue is conflicting rather than a safe canonical fix.

## What This Changes

Request to make the `read` tool avoid raw binary output for PDF and Office document formats, either by warning/fallback or by extracting readable text.

## Best Possible Solution

Add a bounded core `read` guard that prevents raw binary document bytes from entering context, points users to the existing PDF/document path where appropriate, and keeps broader Office extraction or provider-native forwarding in the already-related product/design threads.

## Reproduction Assessment

Yes at source level. Current main only branches for image MIME before decoding non-image file buffers as text, so a DOCX ZIP or PDF buffer can become `read` tool text output; I did not run a live binary read in this read-only review.

## Solution Assessment

Unclear. A safe fallback guard is likely the narrowest first fix, but automatic parsing and PDF routing need maintainer decisions about ownership, security limits, and shared extractor boundaries.
