## Summary

Keep open: current main still routes non-image read inputs through text decoding, so PDF/Office bytes can still become model-visible tool output. The narrow fallback direction is plausible, but it still needs maintainer direction because richer parsing/provider-native document work overlaps and the open closing fork PR is conflicting.

## What This Changes

The issue requests that the read tool avoid returning raw binary output for PDF/Office-style documents and instead return a safe warning or parsed text.

## Best Possible Solution

Land or explicitly reject a bounded current-main read guard for known binary document formats, while leaving richer document extraction/provider-native file support to the existing document capability issues.
