## Summary

Keep open: current main and v2026.6.11 still route non-image reads into text decoding, so PDF/Office bytes can still become tool output. The only open closing PR is an unmerged fork candidate that GitHub reports as conflicting.

## What This Changes

Request that the `read` tool stop returning raw binary output for PDF and Office documents, either by showing a safe fallback message or by routing to document extraction.

## Best Possible Solution

Adopt a bounded read-path fallback that prevents known binary document bytes from entering context, while leaving richer parsing and provider-native file forwarding to the narrower document and attachment design threads.
