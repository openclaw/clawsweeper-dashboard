## Summary

Keep open: current main and v2026.6.11 still route non-image `read` payloads into text decoding, and the only open closing PR is a conflicting fork branch rather than a landed fix.

## What This Changes

The issue asks OpenClaw to stop the `read` tool from returning raw binary-looking content for PDF and Office document formats, either by warning or by extracting readable text.

## Best Possible Solution

Approve a narrow read-tool fallback that detects PDF/Office-like binary documents, avoids transcript pollution, and points users to the `pdf` tool or external document extraction while leaving richer Office parsing/provider-native forwarding to the related design issues.
