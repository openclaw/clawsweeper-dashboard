## Summary

Keep this issue open: current main and v2026.6.11 still route non-image `read` buffers through text decoding, so the binary-document token-waste problem is not implemented on main. The linked fork PR is useful context but is open, conflicting, and edits older `pi-tools` paths rather than the current shared read implementation.

## What This Changes

Request that `read` avoid returning raw binary document bytes for Office/PDF formats by warning or extracting readable text.

## Best Possible Solution

Add a bounded safe fallback in the shared `read` path for known binary document formats, and keep full document extraction or provider-native file forwarding in the dedicated document/media issues.
