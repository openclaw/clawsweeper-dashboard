## Summary

Keep this issue open: current main and the latest release still route non-image read results through text decoding, so the binary-document token-waste problem remains. The open linked fork PR is a candidate path, not an implementation, and the broader document/file-input issues only partially overlap this narrower read-tool fallback request.

## What This Changes

The issue requests that the read tool avoid returning raw binary output for Office/PDF-style documents, either by warning or by extracting text.

## Best Possible Solution

Resolve the open candidate PR, then implement a bounded binary-document fallback in the shared read path while leaving full document extraction or provider-native forwarding to the dedicated media/document issues.
