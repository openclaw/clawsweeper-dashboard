## Summary

Keep this issue open: current main still decodes non-image files through the shared read tool as text after image-only MIME handling, so the reported binary-document token waste is not implemented on main. The open linked fork PR is not a safe close reason because it is conflicting and targets retired pi-tools files, while broader document extraction/provider-native issues only partially overlap.

## What This Changes

Request to prevent the read tool from dumping raw binary document bytes by returning a compact fallback or extracting supported document text.

## Best Possible Solution

Add bounded binary/document detection in the current shared read path that returns a compact actionable fallback, and leave full document extraction/provider-native file handling to the narrower document/media-input issues or dedicated tools.
