## Summary

Keep open: current `main` still decodes non-image `read` inputs as text, so PDF/Office bytes can still enter the tool result. The direct same-repo guard PRs are closed unmerged, and the only open linked implementation candidate is a conflicting fork PR that needs maintainer review or replacement.

## What This Changes

The issue asks OpenClaw to stop the `read` tool from returning garbled raw bytes for PDF and Office-style binary documents, either by warning with a structured fallback or by extracting document text.

## Best Possible Solution

Land or close the linked implementation candidate after deciding the narrow contract, with a bounded `read` guard that prevents raw binary document bytes from entering context and leaves richer parsing/provider-native file handling to approved document work.
