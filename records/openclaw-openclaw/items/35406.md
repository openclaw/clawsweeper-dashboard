## Summary

Keep open: current `main` still routes non-image PDF/Office files through text decoding in the `read` tool, and the only open linked fix candidate is an external fork PR that is stale/conflicting rather than a landable canonical fix.

## What This Changes

The issue requests safer `read` tool behavior for binary document formats so raw Office/PDF bytes are not returned as model context.

## Best Possible Solution

Approve a narrow read-tool safe fallback for known binary document MIME types/extensions, then either adopt/replace the linked fork PR or close it if maintainers choose broader document extraction/provider-native file work instead.
