## Summary

Keep open: current main and the latest release still route non-image `read` inputs through text decoding, so PDF/Office bytes can still become model-visible text. The remaining choice is product direction: land a narrow safe fallback for known binary document formats now, or fold richer parsing into broader document/provider-native file work.

## What This Changes

The issue requests that the `read` tool avoid returning raw binary document bytes for PDF/Office-style files, either by warning or by extracting text.

## Best Possible Solution

Adopt the narrow safe-default contract first: make `read` detect known PDF/Office binary document formats and return an actionable fallback pointing to the `pdf` tool or document-parser/plugin path, while keeping automatic Office parsing and provider-native file forwarding in the broader document issues.
