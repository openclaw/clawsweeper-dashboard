## Label Justifications

## Summary

Keep open: current main and v2026.6.11 still send non-image document files through the read tool's text-decoding path, and the only linked closing PR is an open conflicting fork PR rather than a merged fix. Broader document-ingest issues overlap, but they do not replace this narrow read-tool fallback decision.

## What This Changes

Prevent the read tool from returning raw decoded binary document bytes for PDF and Office-style files by returning a helpful fallback or routing users to document parsing tools.

## Best Possible Solution

Adopt a narrow, well-tested read-tool fallback for known binary document formats while leaving full PDF and Office extraction to dedicated document tools or broader document-ingest work.

- **Fold into broader document ingestion:** Track this under provider-native/document attachment work and require security and dependency review before adding broader parsing behavior.

Unclear until maintainers choose the product scope. A narrow fallback is the smallest maintainable first step; automatic parsing belongs in the existing PDF/document extraction surfaces or broader document-ingest design.
