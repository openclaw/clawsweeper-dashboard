## Summary

Keep open: current main and the latest release still route non-image PDF/Office bytes through the generic read text-decoding path, and the linked fork PR is open but conflicting, so this issue remains the canonical tracking point until maintainers choose the read-tool boundary.

## What This Changes

Request that the read tool avoid returning raw PDF/Office binary bytes, either by returning a safe fallback message or by extracting document text.

## Best Possible Solution

Approve a narrow read-tool fallback that blocks raw PDF/Office binary bytes from transcript context and points users to the PDF/document extraction path, while leaving richer native parsing or provider forwarding to the related product-design issues.
