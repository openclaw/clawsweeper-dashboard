## Summary

Keep open: current main and v2026.6.11 still only special-case images before non-image files are decoded as text, so Office/PDF binary reads can still waste context; the remaining choice is whether to land a narrow safe fallback or defer to broader document handling work.

## What This Changes

The issue requests that the agent read tool avoid returning raw binary document bytes for Office/PDF formats and instead return a safe warning or parsed text.

## Best Possible Solution

Adopt a bounded safe fallback in the shared read path for known binary document formats, point PDFs to the dedicated pdf tool, and keep native parsing/forwarding in the linked document-handling trackers.

- **Narrow to safe fallback (recommended):** Implement bounded MIME/extension detection in the shared read path and return a clear message for known binary document formats, leaving parsing to existing PDF and linked document work.
- **Fold into document extraction:** Treat this as part of the broader Office/document extraction and provider-native file design instead of changing read behavior independently.
- **Defer core behavior:** Leave the read tool unchanged and rely on existing tools/plugins until maintainers approve a document handling boundary.

## Solution Assessment

Unclear until maintainers pick scope. The best narrow fix is a bounded safe fallback in the shared read tool; automatic document parsing belongs behind a separate document extraction/provider-native decision.
