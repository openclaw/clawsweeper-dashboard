## Summary

Keep this issue open: current main and the latest release still route non-image `read` buffers through text decoding, so the binary-document token-waste problem remains. The linked candidate PR is open but conflicting and based on older paths, while broader document/file-input issues only partially overlap this narrower read-tool fallback request.

## What This Changes

Prevent the `read` tool from returning raw binary-looking output for Office/PDF documents, either by returning a safe unsupported-document message or by adding document extraction.

## Best Possible Solution

Add a bounded binary-document fallback in the shared `read` path, review or port the linked guard PR, and leave full document extraction or provider-native file forwarding to the dedicated document/media issues.
