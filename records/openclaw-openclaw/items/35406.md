## Summary

Keep open: current main still only treats images specially and otherwise decodes read-tool bytes as text, so PDF/Office reads can pollute context. Prior same-repo guard PRs are closed unmerged, and the open linked fork PR is conflicting, so the remaining step is maintainer product direction.

## What This Changes

The issue asks OpenClaw to prevent the `read` tool from returning raw binary Office/PDF bytes and either warn or provide document extraction.

## Best Possible Solution

Adopt a bounded current-main read fallback that uses shared MIME detection to avoid raw PDF/Office bytes in context, and leave rich extraction or provider-native forwarding to the broader document/file issues.
