## Summary

Keep this issue open: current main and v2026.6.11 still send non-image `read` buffers through text decoding, so the direct binary-document token-waste problem is not implemented. The open linked fork PR at https://github.com/BingqingLyu/openclaw/pull/1676 is a candidate but is conflicting and unmerged, while the broader document/media issues only partially overlap.

## What This Changes

The issue requests that the `read` tool avoid returning raw binary document bytes for Office/PDF-style formats, either by returning a safe unsupported-file message or by extracting document text.

## Best Possible Solution

Add a bounded binary-document detector in the shared `read` path that returns a compact actionable fallback, and keep full document extraction or provider-native file handling in the dedicated document/media-input work.
