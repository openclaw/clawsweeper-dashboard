## Summary

Keep open: current `main` and the latest release still route non-image `read` inputs through text decoding, so PDF/Office bytes can still enter the tool result. The open linked implementation candidate is conflicting and unmerged, so this issue needs maintainer direction rather than cleanup closure.

## What This Changes

Request that the `read` tool avoid returning raw binary document bytes for formats such as `.docx`, `.pdf`, `.pptx`, and `.xlsx`, either by returning a clear fallback message or by extracting text.

## Best Possible Solution

Choose the narrow contract first, then land or replace the linked guard so binary document reads return a clear fallback while richer parsing and provider-native file handling stay in the broader document work.
