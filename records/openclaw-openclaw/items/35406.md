## Summary

Keep this issue open: current main and the latest release still decode non-image `read` buffers as text, so the direct binary-document token-waste problem remains. There is an open linked fork PR, but it is conflicting and based on older read-tool paths, while broader document/file-input issues only partially overlap this narrower fallback request.

## What This Changes

Request that the `read` tool avoid returning raw binary-looking output for Office/PDF document formats by warning with a compact fallback message or extracting readable text.

## Best Possible Solution

Resolve the open candidate PR, then add a bounded binary-document fallback in the shared `read` path while leaving full document extraction or provider-native file forwarding to the dedicated media/document issues.
