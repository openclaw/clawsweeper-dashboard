## Summary

Keep this issue open: current main and the latest release still decode non-image `read` buffers as text, so the direct binary-document token-waste problem remains. The related document/file issues only partially overlap, and the open fork PR is a useful but conflicting candidate rather than a landed fix.

## What This Changes

The issue asks OpenClaw to stop the `read` tool from returning raw decoded binary document bytes for formats such as `.docx`, `.pdf`, `.pptx`, and `.xlsx`.

## Best Possible Solution

Add a bounded safe fallback in the shared `read` path for known binary document formats, and keep full document extraction or provider-native file forwarding in the dedicated document/media issues.
