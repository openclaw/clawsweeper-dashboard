## Summary

Keep this issue open: current main still only treats images specially in the `read` tool and otherwise decodes non-image buffers as text, so the binary-document token-waste problem remains. A linked open PR attempts the safe fallback but is conflicting and based on older file paths, so the next step is maintainer review rather than cleanup closure.

## What This Changes

The issue asks OpenClaw to prevent the `read` tool from returning raw binary document bytes for formats such as PDF, DOCX, PPTX, and XLSX, either by returning a safe unsupported-document message or by extracting text.

## Best Possible Solution

Review or port the linked safe-fallback PR into the current shared `read` path, while leaving full document extraction and provider-native file forwarding to the dedicated document/media issues.
