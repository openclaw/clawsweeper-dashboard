## Summary

Keep open: current main still lets non-image binary document formats fall through the `read` text-decoding path, and the linked fix PR is open but conflicting/unmerged, so there is no safe close reason yet.

## What This Changes

The issue requests that the `read` tool stop returning raw binary-looking content for PDF and Office document formats, either by warning or by extracting text.

## Best Possible Solution

Approve a narrow read-tool fallback that blocks raw PDF/Office binary bytes from transcript context and points users to the `pdf` tool or document extraction path, while leaving richer native parsing/provider forwarding to the related product-design issues.
