## Summary

Keep open: current main and the latest release still route non-image `read` inputs through text decoding, so PDF/Office bytes can still enter the tool result. The narrow guard direction is useful, but the remaining choice between a bounded fallback, parser-backed extraction, and broader document/file handling still needs maintainer direction.

## What This Changes

The issue asks for `read` to avoid returning raw binary document bytes for `.docx`, `.pdf`, `.pptx`, and `.xlsx` by warning or extracting text.

## Best Possible Solution

Approve a narrow read-tool fallback contract that detects known binary document formats with bounded checks, returns a clear message pointing to dedicated document tooling such as `pdf`, and leaves richer extraction/provider-native file work to the linked document tracks.
