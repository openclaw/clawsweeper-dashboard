## Summary

Keep this issue open: current main and the latest release still route non-image `read` buffers through text decoding, so the direct binary-document token-waste problem is not implemented on main. An open fork PR claims to close it but is conflicting, and the broader document/media-input issues only partially overlap rather than replacing this direct read-tool fallback request.

## What This Changes

The issue asks for the `read` tool to avoid returning raw binary output for document formats such as `.docx`, `.pdf`, `.pptx`, and `.xlsx`, either by warning or by extracting text.

## Best Possible Solution

Add bounded binary-document detection in the shared `read` path that returns a compact actionable fallback, and leave full document extraction or provider-native file handling to dedicated document/media-input work.
