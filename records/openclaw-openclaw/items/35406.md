## Summary

Keep open: current main still detects only images before decoding non-image read targets as text, so PDF/Office bytes can still enter tool output; the open closing fork PR is conflicting and the remaining direction needs maintainer choice.

## What This Changes

The issue asks for the read tool to avoid returning garbled raw bytes for binary document formats by warning or extracting readable text.

## Best Possible Solution

Choose and land a bounded text-safe read fallback for known binary document formats while leaving richer parsing and provider-native file forwarding to the broader document-ingestion issues.
