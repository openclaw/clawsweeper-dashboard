## Summary

Keep open: current main still computes memory-wiki bridge status from an unscoped process-wide artifact list, and the agent tool plus Gateway status/doctor callers still provide no caller agent identity. The sibling report at https://github.com/openclaw/openclaw/issues/103087 is the stronger full-content disclosure surface, but this status/doctor existence leak remains distinct and unresolved.

## What This Changes

The issue reports that `wiki_status` and `openclaw wiki doctor` expose another agent's bridged memory artifact existence through an unscoped artifact count and derived warning.

## Best Possible Solution

Thread an effective agent scope into agent-visible memory-wiki status calls, filter bridge artifacts by `agentIds`, and keep any operator-global diagnostic view explicit and covered by regression tests.
