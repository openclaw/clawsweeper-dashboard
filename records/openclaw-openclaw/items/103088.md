## Summary

Keep open: current main still computes the bridge artifact count from an unfiltered process-wide artifact list while `wiki_status` has no caller agent context. The sibling report at https://github.com/openclaw/openclaw/issues/103087 shares the bridge scoping root cause, but it covers content disclosure; this issue has a distinct status/doctor existence-leak surface that still needs an explicit fix.

## What This Changes

The issue asks memory-wiki status and doctor output to scope bridge public-artifact counts and warnings to the calling agent instead of all agents.

## Best Possible Solution

Make agent-visible memory-wiki status and doctor counts filter bridge artifacts by the caller’s effective agent scope, keep any operator-global CLI view explicit, and add a regression test with a secondary-only artifact suppressing neither the main-agent count nor warning.
