- `impact:session-state`: The affected dynamic tool calls include session helpers whose timeout handling can leave agent/session waits bounded incorrectly.

## Summary

Keep open: current main and the latest release still read only `timeoutMs` for Codex dynamic-tool hard timeouts, while `sessions_send` exposes `timeoutSeconds` as the tool argument the model can send.

## What This Changes

Dynamic tool hard timeout should honor `timeoutSeconds` when `timeoutMs` is absent.

## Best Possible Solution

Patch the existing Codex dynamic-tool timeout reader to use `timeoutSeconds` as a seconds-form fallback only when `timeoutMs` is absent, and add focused resolver tests for precedence, invalid values, and clamping.

## Reproduction Assessment

Yes at source level: a dynamic tool argument object with only `timeoutSeconds` currently falls through to configured/default timeout because the reader only checks `timeoutMs`. I did not run a live current-main Codex timeout turn because this review is read-only.

## Solution Assessment

Yes; the narrow maintainable fix is in the existing timeout reader, preserving `timeoutMs` precedence and the existing failed dynamic-tool response path.
