## Summary

Keep open. Current main and the latest release still derive non-shared Docker and sandbox-browser runtime names from scope keys without workspace or instance identity, while https://github.com/openclaw/openclaw/pull/96866 is the active but unmerged candidate fix.

## What This Changes

The issue reports Docker sandbox container-name collisions when multiple HOME-isolated OpenClaw instances use the same default agent key on one host.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/96866 or an equivalent security-reviewed fix that scopes non-shared sandbox runtime identity by resolved workspace across Docker, browser, SSH, recreate, docs, and regression tests.

## Reproduction Assessment

Yes. Current main is source-reproducible: non-shared sandbox scope keys and Docker/browser container names are derived without workspace identity, matching the co-hosted instance collision report.

## Solution Assessment

Yes on direction, but maintainer/security review is still needed. Workspace-scoping the sandbox lifetime key is better than a Docker-only name patch because Docker, browser, SSH, skills workspace, registry, and recreate paths all consume that scope contract.
