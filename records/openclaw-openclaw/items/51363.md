## Summary

Keep open. Current main and the latest release still derive non-shared Docker and sandbox-browser runtime names from scope keys without workspace or instance identity; the active fix path remains the open candidate PR at https://github.com/openclaw/openclaw/pull/96866.

## What This Changes

The issue asks for Docker sandbox runtime names to include instance or workspace identity so co-hosted OpenClaw instances do not share an exec container.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/96866, or replace it with an equivalent workspace-qualified non-shared scope-key fix that preserves shared scope behavior and documents upgrade cleanup.

## Reproduction Assessment

Yes from source inspection: agent-scoped sandboxes with the same agent/session key still derive the same Docker and browser runtime names because workspace identity is not in the scope key or name. I did not run live Docker in this read-only cleanup review.

## Solution Assessment

Yes, the active PR’s workspace-qualified non-shared scope key is the right owner layer because Docker containers, browser containers, SSH runtime roots, skills workspaces, and recreate filtering all consume that scope contract. The remaining question is maintainer acceptance of upgrade behavior, not whether this issue is obsolete.
