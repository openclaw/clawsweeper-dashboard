## Summary

Keep open. Current main and v2026.6.11 still derive non-shared Docker and browser sandbox names from scope keys without instance identity, and the active unmerged fix candidate is https://github.com/openclaw/openclaw/pull/96866.

## What This Changes

The issue asks OpenClaw to prevent Docker sandbox container-name collisions when multiple HOME-isolated instances on one host use the same default agent key.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/96866, or an equivalent security-reviewed fix that scopes non-shared sandbox runtime identity by resolved workspace across Docker, browser, SSH, recreate, docs, and regression tests.

## Reproduction Assessment

Yes. Current main is source-reproducible: non-shared sandbox scope keys and Docker/browser container names are derived without workspace identity, matching the co-hosted instance collision report.

## Solution Assessment

Yes on direction, but maintainer/security review is still needed. Workspace-scoping the sandbox lifetime key is better than a Docker-only name patch because Docker, browser, SSH, registry, skills workspace, and recreate paths all consume that scope contract.
