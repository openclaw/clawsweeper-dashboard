## Summary

Keep open. Current main and the latest release still derive Docker and sandbox-browser runtime names from shared or agent scope keys before workspace identity participates, while the workspace-scoped fix is still an open candidate PR rather than merged code.

## What This Changes

The issue reports Docker sandbox container-name collisions when multiple OpenClaw instances on one host use the same default agent key with different HOME/workspace roots.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/96866 or an equivalent workspace-scoped sandbox identity fix that covers Docker, browser, SSH/runtime registry, recreate filtering, and upgrade cleanup guidance.

## Reproduction Assessment

Yes. Source inspection is enough to reproduce the collision path: agent scope resolves to the same `agent:<id>` key across co-hosted instances and Docker/browser names are derived from that key; I did not run a live Docker repro in this read-only sweep.

## Solution Assessment

No, current main is not the best solved state because workspace identity is still absent from runtime names. The best active path is the open workspace-scoped identity PR with maintainer review for upgrade and security behavior.
