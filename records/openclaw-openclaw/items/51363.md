## Summary

Keep open. Current main and latest release v2026.6.11 still derive non-shared Docker and browser sandbox runtime names from agent/session scope keys before workspace identity participates, while the workspace-scoped fix remains an open candidate PR rather than merged code.

## What This Changes

The issue reports Docker sandbox container-name collisions when multiple HOME-isolated OpenClaw instances on one host use the same default agent key.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/96866 or an equivalent security-reviewed workspace-scoped sandbox identity fix that covers Docker, browser, SSH, recreate filtering, docs, and regression tests.

## Reproduction Assessment

Yes. Current main source inspection shows non-shared Docker and browser container names are derived from shared/agent scope keys without workspace identity; I did not run a live two-HOME Docker repro in this read-only review.

## Solution Assessment

Yes on direction, but it needs maintainer/security sign-off before this issue closes. The active candidate fix scopes sandbox lifetime identity by workspace across sibling runtimes rather than patching only Docker container names.
