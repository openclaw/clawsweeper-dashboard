## Summary

Keep open. Current main and the latest release still derive non-shared sandbox runtime names from the agent/session scope without workspace or instance identity, and https://github.com/openclaw/openclaw/pull/96866 remains the active unmerged candidate fix.

## What This Changes

The issue requests unique Docker sandbox container identity for co-hosted OpenClaw instances that use the same default agent key.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/96866 with a workspace-qualified non-shared sandbox identity fix, including explicit upgrade handling for the one-time runtime reset.

## Reproduction Assessment

Yes. The current-main source path is source-reproducible: the sandbox scope key and Docker container name omit workspace identity, while the reported multi-instance setup reuses the same default agent key.

## Solution Assessment

Yes, the active workspace-scoped non-shared identity fix is the right layer because Docker, browser, SSH, registry, skills workspace, and recreate flows all consume the shared scope-key contract. Maintainer acceptance is still needed for the one-time runtime identity reset.
