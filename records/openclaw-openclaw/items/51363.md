## Summary

Keep open. Current main and the latest release still derive non-shared sandbox runtime names from scope keys without workspace or instance identity, and https://github.com/openclaw/openclaw/pull/96866 remains the active unmerged candidate fix for this security-sensitive bug.

## What This Changes

The issue reports Docker sandbox container-name collisions across co-hosted HOME-isolated OpenClaw instances using the same default agent id, allowing sandbox exec/browser work to target another instance's workspace.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/96866, or an equivalent security-reviewed fix that scopes non-shared sandbox runtime identity by resolved workspace across Docker, browser, SSH, recreate, docs, and regression tests.
