## Summary

Keep open. Current main and v2026.6.11 still derive non-shared Docker and browser sandbox names from scope keys without workspace or instance identity, and the active fix path is the still-open https://github.com/openclaw/openclaw/pull/96866.

## What This Changes

The issue reports that co-hosted HOME-isolated OpenClaw instances with Docker sandboxing can reuse the same sandbox container when they share the default agent key.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/96866 or an equivalent security-reviewed fix that scopes non-shared sandbox runtime identity by resolved workspace across Docker, browser, SSH, recreate commands, docs, and regression tests.

## Reproduction Assessment

Yes. Current main is source-reproducible: non-shared Docker and browser sandbox names are derived from shared or agent scope keys without workspace identity, matching the co-hosted HOME-isolated collision report.

## Solution Assessment

Yes on direction, with maintainer review. Centralizing workspace identity in the non-shared sandbox scope key is more maintainable than a Docker-name-only patch because Docker, browser, SSH, registry, workspace, and recreate paths consume that scope contract.
