## Summary

Keep open: current main still has a source-level path that can classify a known Slack mpDM as a channel when a later bot-authored event lacks `channel_type`, splitting one room across group and channel session keys. The related fix at https://github.com/openclaw/openclaw/issues/80091 covers native IM `D...` targets, not this C-prefixed mpDM fallback.

## What This Changes

The issue asks OpenClaw to keep Slack mpDM inbound routing on one group session when bot-authored events arrive without `channel_type`.

## Best Possible Solution

Add a Slack-plugin channel-type cache or authoritative lookup that preserves explicit or Slack API `mpim` classification for later missing-type events, with focused regression tests and no new config.

## Solution Assessment

Yes: the narrow fix belongs in the Slack plugin's inbound conversation type resolution, not core routing. It should preserve or resolve known mpDM type before the C-prefix channel fallback while leaving normal channels and the existing D-prefix DM fix intact.
