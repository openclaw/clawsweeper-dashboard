## What This Changes

The PR adds MCP loopback JSON-RPC notification detection to HTTP response batching and a regression test for a `tools/list` message without an `id` returning `202` with an empty body.

## Best Possible Solution

Land the protocol fix after live loopback proof is added, keeping notification suppression at the HTTP batching layer so omitted-`id` notifications execute without responses while explicit IDs and malformed messages still respond.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes by source inspection: current main turns a no-`id` `tools/list` request into a `jsonRpcResult(undefined, ...)` response and pushes it into the HTTP payload. I did not execute the test because this review is read-only and the PR is untrusted contributor code.

## Solution Assessment

Yes: the HTTP batching layer is the narrowest maintainable fix because it can distinguish an omitted `id` member from explicit `id: null` before serializing responses. Moving this into `jsonRpcResult` would blur malformed/unknown-id responses with true notifications.
