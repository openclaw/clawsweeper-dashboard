## Label Justifications

- `P1`: The existing rapid-switch race can silently return the TUI to an older session and route the user's next message to the wrong session.

## Summary

The PR fixes the reproduced stale-success race at the correct history-application boundary, but it does not fully implement its stated stale-completion no-op rule because a superseded request that rejects still writes an error into the newly selected session. The branch is focused and otherwise composes with the current `sessions.changed` reload state machine, so it should remain open for a narrow repair and real TUI proof.

## What This Changes

The PR adds a generation guard so an older asynchronous TUI history load cannot overwrite a newer session switch, plus a focused out-of-order response regression test.

## Best Possible Solution

Discard fulfilled and rejected history completions from superseded switches before any transcript, render, activity, error, or session mutation, retain same-session reload behavior, and demonstrate rapid A-to-B switching through the repository's fake-backend or local PTY TUI lane.
