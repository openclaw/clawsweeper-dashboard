## Summary

This PR addresses the reported direct-key and label paths, but it still validates before the shared resolver canonicalizes non-key session references. A raw session ID that resolves to an unknown `agent:<id>:...` key can therefore still reach dispatch; the existing P1 blocker remains. It also needs real Gateway proof showing no dispatch or persisted session after the rejection.

## What This Changes

The PR adds `sessions_send` checks intended to reject malformed and unconfigured agent session keys before an agent run is started, plus regression-test configuration cleanup.

## System Context

`sessions_send` accepts either a direct session reference or a label, resolves it to a canonical target session, applies visibility and agent-to-agent policy, then calls the Gateway to start work. This change adds an agent-existence check in the path between reference input and Gateway dispatch.
