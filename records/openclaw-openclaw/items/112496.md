## Summary

This PR is still necessary, but its new configured-agent check runs only on the raw `sessionKey` before session-reference resolution. An opaque session ID can still resolve to `agent:ghost:main` and reach the agent Gateway dispatch without the promised rejection, so the prior P1 blocker remains on the unchanged head.

## What This Changes

The PR rejects malformed and unconfigured agent session keys in `sessions_send`, adds regression coverage for direct and label-based inputs, and restores runtime-config test spies after each suite.

## System Context

`sessions_send` accepts an agent ID, a session key, a label, or an opaque session reference and resolves that input into a target session before asking the Gateway to dispatch work. The configured-agent boundary must apply to the final canonical session key so unknown agents cannot create runs, sessions, or workspace state.
