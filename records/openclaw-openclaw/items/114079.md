## Summary

Keep this PR open. The atomic Control UI edit fixes the earlier split-write concern, but the new claim-time uniqueness check can deadlock two provisional cards that share a session key: both remain unclaimed and neither can be claimed. The PR also still needs inspectable after-fix behavior evidence rather than an assertion of a local SQLite run.

## What This Changes

The branch adds explicit Workboard session bind, rebind, and detach behavior, propagates the caller session through agent mutations, and saves Control UI session-link edits atomically with the card update.

## System Context

The Workboard plugin persists task cards and exposes them through Gateway methods, agent tools, and the Control UI. Session keys connect cards to agent conversations, so the store must preserve both card mutation authorization and a coherent one-card-per-session lifecycle rule.

## Architecture Diagram

flowchart LR

  B --> C[Workboard card store]

## Best Possible Solution

Make the uniqueness invariant consistent across direct update, bind/rebind, and claim: either reject duplicate bindable cards when the session key is first persisted, or let one provisional card claim and become the sole active binding. Add focused regression coverage for the duplicate-provisional sequence and post redacted real SQLite or Gateway proof of bind, rebind, detach, rejected conflict, and atomic failure behavior.
