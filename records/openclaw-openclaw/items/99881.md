## Summary

Keep open. ## What This Changes

Report that uploading an image in WebChat with a non-multimodal DeepSeek model corrupts subsequent tool-output rendering and can coincide with reply-session initialization conflicts.

## Best Possible Solution

Add a focused WebChat/DeepSeek text-only image regression that verifies subsequent ordinary tool results replay/render as text, while preserving the intentional media-only `(see attached image)` placeholder.

## Reproduction Assessment

We have a medium-confidence source-level path, not a live repro: the provider replay code can emit `(see attached image)` only when a tool result is classified as image-only, and the reported sequence plausibly contaminates that classification after a WebChat image upload.

## Solution Assessment

The existing text-only image offload path is not enough to close this because it already shipped in v2026.6.11; the best fix is a narrow regression and repair in tool-result classification/replay or session transcript state, not a new config option or provider route.
