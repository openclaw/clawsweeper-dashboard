## Summary

Keep open. This newly reported, concrete cron authorization failure is not covered by the open delegated-run PR: isolated cron execution has no external requester to inherit, so it needs a separately reviewed internal authorization boundary rather than a duplicate close.

## What This Changes

The issue requests that trusted isolated cron executions avoid inheriting a restrictive wildcard `toolsBySender` policy when they run without external sender or trusted-group identity.

## Best Possible Solution

Define a cron-specific internal authorization contract that preserves ordinary sender-policy restrictions for external runs, never fabricates a sender identity, and has focused regression coverage for restrictive wildcard rules plus trusted delivery targets.
