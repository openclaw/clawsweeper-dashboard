## Summary

Keep open: current main covers the model-attribution half through response-prefix template variables, but it still has no opt-in approval gate before executing a configured fallback model.

## What This Changes

Request an opt-in fallback approval mode plus optional model attribution in outbound messages.

## Best Possible Solution

Keep model attribution on the existing responsePrefix template surface, and only add fallback approval after maintainers define a per-agent core contract for approval delivery, timeout, and resume/fail behavior.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a feature request. Source inspection gives high confidence that attribution is partly covered today and confirm-before-fallback behavior is absent on current main.

## Solution Assessment

Unclear until maintainers choose the product shape. The attribution half is best solved by the existing responsePrefix templates, while fallback approval needs a deliberate core design rather than an automatic narrow patch.
