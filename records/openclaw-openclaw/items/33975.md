## Summary

Keep open: current main covers the model-attribution half through `messages.responsePrefix` templates, but the requested opt-in approval gate before executing configured model fallbacks is still missing and needs a maintainer product decision.

## What This Changes

The issue requests an opt-in confirmation step before model fallback plus visible provider/model attribution in replies.

## Best Possible Solution

Keep the existing response-prefix attribution path, then have maintainers decide whether a default-off fallback approval gate belongs in core model routing, an approval/channel event surface, or a plugin API extension before implementation.
