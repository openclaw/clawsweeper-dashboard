## Summary

Keep open: current main and the latest release cover model attribution through `messages.responsePrefix` templates, but there is still no approval gate before executing the next configured fallback model. The remaining request is a product/config decision, not a strict bug fix.

## What This Changes

The issue requests an opt-in approval gate before model fallback plus optional model attribution in outbound messages.

## Best Possible Solution

Keep model disclosure on `messages.responsePrefix`, and define a default-off per-agent fallback approval policy only after maintainers choose approval route, timeout, fail/proceed behavior, docs, and regression coverage.
