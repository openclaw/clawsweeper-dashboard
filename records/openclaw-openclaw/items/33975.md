## Summary

Keep open: current main covers the model-attribution side through `messages.responsePrefix` templates and fallback notices, but it still has no opt-in approval gate before executing configured model fallbacks. The remaining behavior is a feature/config/product decision, not conservative cleanup to close.

## What This Changes

The issue requests opt-in approval before executing a configured fallback model and visible model attribution in outbound responses.

## Best Possible Solution

Keep the existing response-prefix and fallback-notice visibility paths, then decide a default-off fallback approval contract in core model routing or an extension API before implementation.
