## Summary

Keep open: current main and latest v2026.6.11 cover much of the model-visibility need through responsePrefix templates and fallback notices, but they still lack an opt-in approval gate before executing configured model fallbacks. Related search shows this issue remains the canonical tracker for that remaining product/config decision.

## What This Changes

Request an optional approval prompt before switching to fallback models, plus visible model attribution in user-facing replies.

## Best Possible Solution

Define a default-off fallback approval contract, including timeout behavior, channel delivery semantics, and upgrade-safe config, while keeping the existing responsePrefix and fallback-notice visibility paths.
