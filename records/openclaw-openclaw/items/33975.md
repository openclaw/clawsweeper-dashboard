## Summary

Keep open: current main covers model attribution through `messages.responsePrefix` templates, but it still has no opt-in approval gate before executing the next fallback model. The related fallback-confirmation report is already closed in favor of this issue, so this remains the canonical tracker for the remaining product decision.

## What This Changes

The issue requests opt-in approval before switching to a fallback model plus visible model attribution in outbound responses.

## Best Possible Solution

Keep attribution on the existing `messages.responsePrefix` path, and only add fallback approval after maintainers define a per-agent opt-in schema plus approval routing, timeout, fail/proceed, docs, and tests.

## Reproduction Assessment

Yes, from source inspection: configure any fallback chain and current `runWithModelFallbackInternal` will advance to later candidates after failure without a config-backed approval stop. Attribution can be verified through `messages.responsePrefix: "[{modelFull}]"`.

## Solution Assessment

Unclear for the approval half: a per-agent opt-in mode is plausible, but maintainers still need to choose the approval surface, timeout behavior, and whether fallback should fail or proceed on no response. The attribution half is already best handled by `messages.responsePrefix` instead of a duplicate `modelAttribution` config key.
