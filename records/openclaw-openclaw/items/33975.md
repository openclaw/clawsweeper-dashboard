## Summary

Keep open: current main covers the model-attribution half through `messages.responsePrefix` template variables and fallback notices, but it still has no opt-in approval gate before executing configured model fallbacks. That remaining behavior is a feature/config/product decision, not conservative cleanup work to close.

## What This Changes

The issue requests an optional fallback-approval config before model failover and optional visible model/provider attribution in generated messages.

## Best Possible Solution

Keep the existing response-prefix and fallback-notice visibility paths, then decide a default-off fallback approval contract in core model routing or an extension API before implementation.
