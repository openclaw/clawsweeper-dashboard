## Summary

Keep open: current main covers the model-attribution half through `messages.responsePrefix`, but the requested opt-in approval gate before trying a fallback model is still absent and needs maintainer product direction.

## What This Changes

The issue requests an optional fallback approval mode plus model attribution in chat responses.

## Best Possible Solution

Keep model disclosure on `messages.responsePrefix`, and define a per-agent opt-in fallback approval policy only after maintainers choose the approval route, timeout, resume, and docs/test contract.

Rationale: The missing behavior is not a strict bug; it adds config and changes fallback reliability, provider routing, and channel approval semantics that need maintainer product intent.

Likely owner: steipete

Owner confidence: high

Options:

- **Design a core approval gate (recommended):** Add a default-off per-agent fallback approval policy after specifying approval delivery, timeout, fail/proceed behavior, docs, and regression coverage.
- **Keep automatic fallback only:** Reject approval gating and rely on existing fallback notices plus `messages.responsePrefix` for transparency.
- **Defer to external orchestration:** Leave core unchanged and document that users needing approval before provider changes should orchestrate model selection outside the fallback loop.
