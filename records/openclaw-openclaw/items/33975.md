## Summary

Keep open: current main covers model attribution through `messages.responsePrefix` templates, but the requested opt-in approval gate before executing configured model fallbacks is still missing and needs maintainer product direction.

## What This Changes

Requests opt-in approval before model fallback and optional visible provider/model attribution on assistant messages.

## Best Possible Solution

Keep `messages.responsePrefix` as the model-attribution path, and have maintainers define a default-off fallback approval contract with timeout, denial/proceed behavior, delivery surface, docs, and tests before implementation.
