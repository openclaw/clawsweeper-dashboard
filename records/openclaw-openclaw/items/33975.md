## Summary

Keep open: current main covers model disclosure through fallback notices and `messages.responsePrefix` templates, but it still has no approval gate before executing a configured fallback model.

## What This Changes

Request an opt-in fallback approval mode plus optional visible model attribution in outbound messages.

## Best Possible Solution

Keep model disclosure on existing prefix and fallback-notice surfaces, and add fallback approval only after maintainers define a default-off per-agent policy with delivery, timeout, resume, docs, and tests.

Options:

- **Design Core Approval Gate (recommended):** Add a default-off per-agent fallback approval policy after specifying channel delivery, timeout handling, resume behavior, docs, and regression coverage.
- **Keep Automatic Fallback Only:** Reject approval gating and rely on fallback notices plus `messages.responsePrefix` for transparency without changing fallback reliability semantics.
- **Defer To External Orchestration:** Leave core fallback behavior unchanged and document that pre-provider-change approval must be handled outside the fallback loop.
