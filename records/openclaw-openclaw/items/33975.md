## Summary

Keep open: current main covers the model-attribution half through `messages.responsePrefix` template variables, but it still has no opt-in approval gate before the fallback loop runs the next model. The same fallback-confirmation request was closed elsewhere in favor of this issue, so this remains the canonical product-decision tracker.

## What This Changes

The issue requests opt-in user approval before switching to a fallback model and optional model attribution in outbound messages.

## Best Possible Solution

Keep attribution on the existing response-prefix template path, and only add fallback approval after maintainers define a per-agent opt-in config shape plus approval delivery, timeout, resume, docs, and test expectations.

## Reproduction Assessment

Yes for source-level verification, not as a bug reproduction: current schema and runtime code show attribution support exists while confirm-before-fallback behavior is absent.

## Solution Assessment

Unclear until maintainers decide the product shape. The attribution half is already best handled by `messages.responsePrefix`; the fallback approval half needs a deliberate core design rather than an automatic one-file fix.
