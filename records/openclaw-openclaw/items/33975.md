## Summary

Keep open: current main covers the model-attribution half through `messages.responsePrefix` templates, but the requested opt-in approval gate before trying a fallback model is still absent and product-sensitive.

## What This Changes

The issue requests opt-in approval before model fallback plus optional model/provider attribution in outbound messages.

## Best Possible Solution

Keep model disclosure on `messages.responsePrefix`, and define a default-off per-agent fallback approval policy only after maintainers choose the approval route, timeout, resume, and docs/test contract.

- **Keep Automatic Fallback:** Reject pre-fallback approval and rely on responsePrefix/model visibility plus logging or notifications for transparency.
- **Defer To External Orchestration:** Leave the fallback loop unchanged and document that users needing approval before provider changes should orchestrate model selection outside core.
