## Summary

Keep open: current main covers model visibility through `messages.responsePrefix` template variables and fallback state notices, but it still lacks the requested opt-in approval gate before executing a fallback model.

## What This Changes

The issue requests an optional confirm-before-fallback mode plus optional model attribution in outbound replies.

## Best Possible Solution

Keep the existing response-prefix attribution path, and add fallback approval only after maintainers define the per-agent config shape plus approval delivery, timeout, and resume semantics.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Not applicable as a bug reproduction, but yes as a source-level feature gap: the schema and runtime fallback loop show attribution support exists while confirm-before-fallback behavior is absent.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainers decide the product shape; attribution is best handled by `messages.responsePrefix`, while fallback approval needs a deliberate core design rather than an automatic narrow fix.
