## Summary

Keep open: current main covers the model-attribution half through `messages.responsePrefix` templates and fallback notices, but the remaining opt-in approval gate before executing configured model fallbacks is still missing and needs maintainer product direction.

## What This Changes

Request an opt-in fallback approval mode plus optional visible model attribution in assistant messages.

## Best Possible Solution

Keep the existing response-prefix and fallback-notice visibility paths, and have maintainers decide whether a default-off fallback approval gate belongs in core model routing, an existing approval/channel event surface, or a plugin/API extension before implementation.

## Solution Assessment

Unclear until maintainers choose the product contract. The attribution half is best served by the existing `messages.responsePrefix` templates, while fallback approval needs a deliberate core or extension-point design rather than a narrow bug-fix PR.
