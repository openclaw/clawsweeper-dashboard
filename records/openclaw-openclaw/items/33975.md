## Summary

Keep open: current main covers the model-attribution half through `messages.responsePrefix` template variables and related UI metadata, but it still has no opt-in approval gate before running the next fallback model. The related fallback-confirmation issue is already closed in favor of this issue, so this remains the canonical tracker for the remaining product decision.

## What This Changes

The issue requests opt-in user approval before model fallback plus optional model attribution in outbound messages.

## Best Possible Solution

Keep attribution on the existing `messages.responsePrefix`/message metadata path, and only add fallback approval after maintainers define a per-agent opt-in config shape plus approval routing, timeout, resume, and docs/test expectations.

## Reproduction Assessment

Not applicable as a bug reproduction, but yes for source-level verification: current schema and runtime code show attribution support exists while confirm-before-fallback behavior is absent.

## Solution Assessment

Unclear until maintainers decide the product shape. The attribution half is already best handled by `messages.responsePrefix`; the fallback approval half needs a deliberate core design rather than an automatic one-file fix.
