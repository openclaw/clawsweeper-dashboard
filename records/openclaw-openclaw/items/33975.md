## Summary

Keep open: current main covers the model-attribution half through `messages.responsePrefix` template variables and fallback notices, but it still has no opt-in approval gate before executing the next fallback model. The remaining behavior is a product/config decision, not a stale or implemented item.

## What This Changes

The issue requests opt-in user approval before model fallback and visible model attribution in replies.

## Best Possible Solution

Keep model disclosure on the existing response-prefix and fallback-notice surfaces, and only add fallback approval after maintainers define a per-agent opt-in config plus approval routing, timeout, resume, and fail/proceed semantics.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a feature request. Source inspection gives a high-confidence current-main check: attribution support exists through response prefixes, while fallback approval is absent from schema, types, docs, and fallback execution.

## Solution Assessment

Unclear until maintainers decide the product shape. The attribution half is best solved by the existing `messages.responsePrefix` templates; the approval half needs a deliberate core fallback policy rather than an automatic fix PR.
