## Summary

Keep open: current main and the latest release cover the model-attribution half through `messages.responsePrefix` template variables such as `{modelFull}`, but there is still no schema or runtime approval gate before OpenClaw advances to the next fallback model. That remaining behavior is a new fallback/config contract and needs maintainer product direction before a fix PR is safe.

## What This Changes

Request an opt-in approval prompt before model fallback plus optional model/provider attribution in outbound messages.

## Best Possible Solution

Keep using `messages.responsePrefix` for attribution, and have maintainers decide whether to add a per-agent opt-in fallback approval contract with explicit timeout, fail/proceed, channel delivery, and upgrade semantics.
