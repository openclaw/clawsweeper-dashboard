## Summary

Keep open: current main covers the model-attribution half through response-prefix templates, but it still has no approval gate before executing the next configured model fallback, and that remaining behavior needs a maintainer product decision.

## What This Changes

The issue requests opt-in user approval before model fallback plus optional provider/model attribution in outbound messages.

## Best Possible Solution

Keep model disclosure on `messages.responsePrefix`, and define a default-off per-agent fallback approval policy only after maintainers choose the approval route, timeout, fail/proceed behavior, docs, and regression coverage.
