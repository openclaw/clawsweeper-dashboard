## Summary

Keep open: current main covers model visibility through response-prefix templates and fallback notices, but it still lacks an opt-in approval gate before executing a fallback model.

## What This Changes

The issue requests an opt-in approval gate before fallback model execution and optional model attribution in outbound messages.

## Best Possible Solution

Keep the existing response-prefix attribution path, then design core fallback approval semantics before adding schema, runtime, docs, and tests.

## Reproduction Assessment

Not applicable as a bug reproduction, but source inspection gives high confidence that current main has attribution support and no confirm-before-fallback path.

## Solution Assessment

Unclear until maintainers decide the product shape; attribution is best handled by `messages.responsePrefix`, while fallback approval needs deliberate core routing and timeout semantics.
