## Summary

This protected feature remains necessary: current main and v2026.6.11 have no GPT-Live/quicksilver path, and no duplicate or implementation PR owns it. The OpenAI plugin is the correct boundary, but Codex selects quicksilver as realtime protocol v1 rather than through a `gpt-live-*` naming rule, so maintainers must confirm the pre-GA product contract before implementation.

## What This Changes

Add early-access GPT-Live full-duplex WebRTC sessions and actionable rejection on unsupported realtime WebSocket paths.

## Best Possible Solution

Keep full-duplex support in the OpenAI plugin, choose an explicit preview protocol/capability contract, reject it with actionable guidance on gateway-relay paths, preserve `gpt-realtime-2.1` as the default, and require a successful redacted WebRTC session before public documentation.
