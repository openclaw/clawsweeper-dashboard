## Summary

This protected, newly opened feature remains necessary: current main has no GPT-Live/quicksilver path, and no duplicate or implementation PR owns it. The OpenAI plugin is the correct ownership boundary, but Codex models quicksilver as an alpha protocol version rather than a `gpt-live-*` naming rule, so maintainers must confirm the pre-GA product and configuration contract before implementation.

## What This Changes

Add early-access GPT-Live full-duplex WebRTC sessions to the bundled OpenAI realtime voice provider and reject unsupported relay transport with actionable guidance.

## Best Possible Solution

Keep GA Realtime as the default, define a provider-owned and forward-compatible quicksilver selection contract, reject unsupported transports before connection setup, document the early-access limitations, and require an entitled live WebRTC before/after proof.

## Solution Assessment

Unclear: keeping the change inside the OpenAI provider and splitting WebRTC from relay is the right boundary, but automatic model-family detection is not yet proven to be the best durable interface because Codex selects quicksilver by protocol version.
