## What This Changes

The PR changes `waitForAgentJob` so its outer fallback timer forwards pending hard-timeout snapshots through the shared terminal-outcome classifier and adds regression coverage for hard, soft, and restart-cancelled timeout cases.

## Best Possible Solution

Land or replace this classifier-based wait-layer fix, while keeping the broader no-output delivery work on the canonical issue or a separately proven PR.

## Reproduction Assessment

Yes, source-reproducible: the canonical issue has a live `runTimeoutSeconds` repro, and current main plus v2026.6.11 still show the outer wait timer ignoring pending timeout snapshots. I did not run a fresh live provider scenario in this read-only pass.

## Solution Assessment

Yes for this PR's scoped wait-layer slice: using `terminalOutcomeFromSnapshot()` is the best local shape because it shares hard-timeout, soft-timeout, and restart-cancelled precedence. It is not the complete solution for the broader no-deliverable-payload delivery path.
