## Summary

Keep open. Current main still routes Dashboard/Workboard Stop through immediate `chat.abort` without typed user-stop provenance or embedded-run drain/recovery proof, while host exec still intentionally defaults to full/no-approval under the trusted single-operator model; the remaining work is a security/product boundary decision, not stale cleanup.

The issue requests durable Stop-button cancellation that cannot corrupt session JSONL files plus per-agent filesystem/exec guardrails that prevent one agent from deleting another agent's state.
