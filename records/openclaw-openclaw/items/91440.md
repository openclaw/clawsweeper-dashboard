## Summary

Keep open. Current main still routes Workboard Stop through generic `chat.abort` with immediate run-state removal rather than an embedded-run drain/recovery handshake, and host exec still defaults to no-approval full host authority outside sandbox; related #88903/#88971 only covers the narrower user-stop context-pollution slice.

## What This Changes

The issue requests fixing Dashboard Stop cancellation so it cannot corrupt session JSONL, and adding guardrails so one agent's exec authority cannot destructively access another agent's durable state.

## Best Possible Solution

Split the work into two maintainer-owned end states: a recorded Stop/cancel lifecycle that proves parseable transcript persistence after in-flight tool cancellation, and a separate host-exec isolation/default policy with explicit upgrade guidance.
