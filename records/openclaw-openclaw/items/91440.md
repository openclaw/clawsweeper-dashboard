## Summary

Keep open. Current main has partial abort-persistence hardening, but it does not prove the Dashboard Stop path drains or recovers in-flight tool/session writes, and host exec still has an intentional trusted full/off default unless operators configure sandboxing or approvals.

## What This Changes

The issue asks OpenClaw to prevent Dashboard Stop from corrupting session JSONL during in-flight tools and add guardrails so one agent cannot destructively modify another agent's state through host exec.

## Best Possible Solution

Split this into maintainer-owned hardening: prove Stop as a recorded cancel/drain/recovery transition first, then decide an auditable per-agent host-exec isolation or destructive-action approval policy.
