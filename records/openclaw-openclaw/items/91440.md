## Summary

Keep open. Current main has useful partial-abort persistence and JSONL repair, but it still does not prove Dashboard Stop drains in-flight tool/session writes before aborting, and host exec still intentionally defaults to trusted full/no-approval outside sandbox, so the reported data-loss/security boundary is not fully implemented.

## What This Changes

Request to make Dashboard Stop durable against in-flight tool/session writes and add guardrails so one agent cannot destructively modify another agent's state by default.

## Best Possible Solution

Keep this open, split Stop/session durability from host-exec isolation policy, land or replace the narrower user-stop provenance work only after proof, and make exec isolation changes through explicit sandbox/approval/doctor policy rather than an unreviewed silent default break.
