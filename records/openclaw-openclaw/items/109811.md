## Summary

Keep open: the bug and intended direction are valid, but the patch does not cover the normal CLI startup path, which still reads config and may initialize profile state before the changed handler runs.

## What This Changes

The PR makes `config file` resolve the active config path directly and adds coverage asserting that this operation does not create profile state.

## Best Possible Solution

Keep the direct path resolution, add `config file` to the exact no-config-bootstrap path, and cover an isolated-home invocation through the full CLI entry point so both fresh and typo-profile cases prove no directory or SQLite creation.

No. Direct path resolution is appropriate inside the handler, but the narrow complete fix must also bypass configuration bootstrap for this exact read-only command and test the real entry point.
