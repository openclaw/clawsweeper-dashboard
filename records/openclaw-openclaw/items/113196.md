## Summary

Keep this issue open. Current `main` does not expose `traceparent` on Gateway WebSocket request frames, and the same author has an open linked implementation PR that explicitly closes this issue; it should be reviewed and landed or declined rather than closing the issue early.

## What This Changes

Add an optional request-level W3C `traceparent` field to authenticated Gateway WebSocket RPC frames so each agent execution can continue its caller’s observability trace without coupling concurrent requests on one socket.

## System Context

The Gateway accepts authenticated WebSocket request frames, validates them through the shared protocol, and dispatches them into request handlers. Diagnostic context needs to be attached at that per-request boundary so downstream agent work is correlated without changing authentication, routing, or socket-wide state.

## Best Possible Solution

Adopt one bounded, additive protocol field only if maintainers approve request-scoped trace propagation, with validation and tests proving authentication isolation, malformed-value fallback, and concurrent-request context isolation across generated clients.
