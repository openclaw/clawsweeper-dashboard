## Summary

Keep open: current main does not implement the requested Slack user-level event and act-as-user reply path. The remaining work is a Slack plugin feature with a security-boundary decision, not conservative cleanup.

## What This Changes

Request support for Slack user-level `message.im` events and replies sent through a configured user token so DMs to a regular Slack user can route through OpenClaw.

## Best Possible Solution

If maintainers accept the capability, implement it inside the Slack plugin behind an explicit account-level act-as-user opt-in that maps inbound Slack authorizations to approved user tokens, selects reply tokens from that inbound authorization, documents scopes, and includes live Slack proof.
