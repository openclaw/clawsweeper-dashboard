## Summary

Keep open: current main and v2026.6.11 still run Slack Socket Mode and normal inbound replies through the bot/app-token path, so the requested user-authorized DM routing and reply-as-user behavior is not implemented. The request fits the Slack plugin boundary, but it changes Slack identity, token selection, and authorization semantics, so it needs maintainer product/security approval plus live Slack proof.

## What This Changes

Request support for Slack user-level `message.im` events and reply routing through a configured user token so DMs to a dedicated Slack user can be handled without the app badge.

## Best Possible Solution

Keep this open for a Slack-plugin design that explicitly opts into user-authorized inbound DMs, validates required user scopes, routes by the authorizing user/team, and selects the reply token from the inbound authorization with live Slack proof and security docs.
