## Summary

Keep open: current main and the latest release still construct Slack Socket Mode around the bot token, document bot-token-first writes, and do not implement user-authorized DM event routing or per-inbound user-token replies. The request is useful but needs product and security review because it would let OpenClaw receive and respond as a regular Slack user identity.

## What This Changes

Request support for Slack user-level `message.im` events and replies through a configured user token so DMs to a regular Slack user can be handled by OpenClaw.

## Best Possible Solution

Design a Slack-plugin-owned user-account DM mode that explicitly maps inbound Slack authorizations to configured user tokens, selects the matching send token, documents required scopes and audit tradeoffs, and keeps bot/app behavior as the default.
