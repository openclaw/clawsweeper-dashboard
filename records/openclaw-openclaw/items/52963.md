## Summary

Keep open: current main and v2026.6.11 still run Slack Socket Mode and normal replies through the bot identity, with no user-authorized `message.im` routing or per-event user-token reply selection. The request is a real Slack capability gap, but it changes identity and credential boundaries enough to need maintainer product/security approval before implementation.

## What This Changes

Support Slack user-level Socket Mode DM events and send replies through a configured Slack user token so OpenClaw can operate as a dedicated Slack user account.

## Best Possible Solution

Design an explicit Slack-plugin-owned user-account DM mode that maps inbound Slack authorizations to configured user tokens, keeps bot/app behavior as the default, documents scopes and audit tradeoffs, and includes source tests plus redacted live Slack proof.
