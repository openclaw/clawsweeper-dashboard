## Summary

Keep open: current main and the latest release still treat Slack Socket Mode and monitor replies as bot/app-token paths, so the requested user-authorized DM routing and reply-as-user behavior is not implemented. The remaining work is real but security-sensitive and needs maintainer product approval plus live Slack proof before implementation.

## What This Changes

The issue requests Slack support for receiving user-level `message.im` events and replying through the configured Slack user token so DMs to a regular Slack user can be routed to OpenClaw.

## Best Possible Solution

Add an explicit opt-in Slack user-identity mode in the Slack plugin that preserves the bot-token default, routes inbound events by authorizing Slack user/team, sends replies with the matching user token, and includes security docs, focused tests, and live Slack proof.
