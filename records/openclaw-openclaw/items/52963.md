- `P2`: This is a meaningful Slack channel improvement with message-loss impact for dedicated user-account agents, but the existing bot DM workaround keeps the core Slack workflow usable.

## Summary

Keep open: current main and v2026.6.11 still use Slack bot/app-token Socket Mode and bot-token monitor replies, so the requested user-authorized DM routing and reply-as-user behavior remains a product/security decision rather than cleanup.

## What This Changes

Support Slack user-level `message.im` events for a configured user token and route replies through that user identity.

## Best Possible Solution

Add an explicit Slack user-identity mode in the Slack plugin that keeps bot identity as the default, routes inbound events by authorizing Slack user/team, selects the matching user token only under opt-in, and ships with docs, focused tests, and redacted live Slack proof.
