## Summary

Keep open: current main and v2026.6.11 still use the Slack bot/app token monitor path and normal replies still post with the bot token, so the requested user-authorized DM routing and reply-as-user behavior remains unimplemented.

## What This Changes

The issue requests Slack support for receiving user-level `message.im` events for a configured Slack user token and replying as that regular Slack user.

## Best Possible Solution

Add an explicit Slack user-identity mode in the Slack plugin that keeps bot-token behavior as the default, routes inbound events by authorizing Slack user/team, sends replies only with the matching operator-approved user token, and includes security docs plus live Slack proof.
