## Summary

Keep open: current main and the latest release still run Slack inbound monitoring and normal replies through the bot identity, so Slack user-authorized DM routing is not implemented. The request is useful, and the m13v comment points at the right authorization/token-selection seam, but this needs maintainer product and security approval before implementation.

## What This Changes

Request support for Slack user-authorized `message.im` events and user-token replies so DMs to a regular Slack user can be handled by OpenClaw without the Slack app badge.

## Best Possible Solution

Design a Slack-plugin-owned, explicit user-identity DM mode that maps inbound Slack authorizations to configured user tokens, selects the matching reply token, documents required scopes and audit tradeoffs, and preserves bot/app behavior as the default.
