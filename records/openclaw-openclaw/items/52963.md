## Label Justifications

- `P2`: This is a meaningful Slack channel enhancement with message-loss impact for dedicated-agent accounts, but the existing bot DM workaround keeps the core workflow usable.
- `impact:security`: The request would let OpenClaw receive and send as a regular Slack user identity using a user token, which affects a sensitive identity boundary.
- `impact:message-loss`: The reported symptom is that DMs sent to the configured regular Slack user are silently not processed by OpenClaw.
- `impact:auth-provider`: The requested behavior depends on Slack token selection, user-token authorization, and inbound identity routing.

## Summary

Keep open: current main and v2026.6.11 still handle Slack Socket Mode through the bot/app token path and normal monitor replies through the bot token, so user-authorized DM routing is not implemented. The request is valid but changes Slack identity, authorization, and token-selection behavior, so it needs maintainer product/security review and live Slack proof before implementation.

## What This Changes

Support Slack `message.im` events authorized on behalf of a configured user token and reply through that user identity for regular-user DM routing.

## Best Possible Solution

Add a maintainer-approved Slack user-identity mode in the Slack plugin that routes inbound envelopes by authorizing user/team, selects the send token from the inbound authorization, preserves the bot-token default, and includes security docs plus live Slack proof.

## Reproduction Assessment

No live current-main reproduction was run. Source inspection confirms the requested user-level authorization routing is absent from the Slack monitor and reply path, but Slack delivery of those user-authorized events still needs live verification.

## Solution Assessment

Unclear as an implementation. The requested direction matches the missing surface, but the best fix needs maintainer product/security approval for the identity model before deciding whether existing `userTokenReadOnly: false` is sufficient or an explicit user-identity mode is required.
