## Summary

Keep open: current main and the latest release still build Slack inbound monitoring and normal replies around the bot token, while the docs/tests define `userToken` as read-oriented or a write fallback. The requested user-authorized DM routing remains missing and needs product/security review before implementation.

## What This Changes

Request support for Slack Socket Mode events delivered on behalf of a configured user token, including routing inbound DMs and replying through that user identity.

## Best Possible Solution

Add an explicit maintainer-approved Slack user-event mode that routes inbound events by Slack authorization context, selects xoxp or xoxb per inbound event, keeps safe bot-token defaults, and includes live Slack proof plus regression tests.

## Reproduction Assessment

Reproduction is not directly applicable because this is a feature request for a new supported Slack identity mode. Source inspection does verify the current unsupported behavior: the monitor and reply paths are still bot-token centered.

## Solution Assessment

No, overloading `userTokenReadOnly: false` alone is not the best way to solve this. The safer route is an explicit user-account DM mode with authorization mapping, token selection, tests, docs, and security guardrails.
