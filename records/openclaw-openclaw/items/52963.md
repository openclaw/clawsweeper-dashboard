## Summary

Keep open: current main and v2026.6.11 still run Slack Socket Mode and normal monitor replies through the bot/app token path, so the requested user-authorized DM routing and reply-as-user behavior is not implemented. The useful part remains, but it changes Slack identity, authorization, and token-selection semantics and needs maintainer product/security approval plus live Slack proof.

## What This Changes

Support Slack user-authorized DM events and reply-as-user behavior when a Slack user token is configured.

## Best Possible Solution

Add an explicit Slack user-identity mode in the Slack plugin that preserves the bot-token default, routes inbound events by authorizing Slack user/team, sends replies with the matching user token only under operator opt-in, and includes security docs plus live Slack proof.
