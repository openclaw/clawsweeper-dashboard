## Label Justifications

- `P2`: This is a meaningful Slack channel improvement with message-loss impact for dedicated user-account agents, while the existing bot DM workaround keeps the core Slack workflow usable.
- `impact:security`: The request would let OpenClaw receive and send as a regular Slack user identity using a user token, which affects identity and authorization boundaries.

- `impact:auth-provider`: The requested behavior depends on Slack credential selection, user-token authorization, and inbound identity routing.

## Summary

Keep open: current main still uses a bot/app-token Slack monitor and sends normal Slack replies with the bot token, so the requested user-authorized DM routing and reply-as-user behavior remains unimplemented. The request is valid product work, but it changes Slack identity and authorization semantics and needs maintainer security/product approval plus live Slack proof.

## What This Changes

Support Slack user-level Socket Mode `message.im` events so DMs to a configured Slack user token can route into OpenClaw and reply as that user.

## Best Possible Solution

Add an explicit Slack user-identity mode in the Slack plugin that preserves the bot-token default, routes inbound events by authorizing Slack user/team, sends replies with the matching user token only under operator opt-in, and includes security docs plus live Slack proof.
