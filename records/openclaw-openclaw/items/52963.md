## Summary

Keep open: current main and v2026.6.11 still implement Slack Socket Mode and normal monitor replies around the bot/app token pair, not user-authorized DM event routing. The request is meaningful, but acting as a regular Slack user changes identity, token-selection, and authorization semantics, so it needs maintainer product/security review and live Slack proof rather than cleanup close.

## What This Changes

Request to receive Slack user-level `message.im` events and reply as the configured Slack user when a writable `userToken` is configured.

## Best Possible Solution

Add a maintainer-approved, default-off Slack user-identity mode that routes inbound envelopes by authorizing Slack user/team, selects the reply token from that authorization, preserves the current bot-token default, and ships with security docs plus live Slack proof.

## Reproduction Assessment

No live current-main reproduction was run. Source inspection shows the requested user-authorized DM route and user-token reply selection are absent, but live Slack proof is still needed to distinguish an OpenClaw routing drop from Slack scope/subscription setup.

## Solution Assessment

Unclear as implementation. The requested direction matches the likely missing surface, but the best fix needs maintainer product/security approval before choosing the permanent identity mode, config semantics, and upgrade behavior.
