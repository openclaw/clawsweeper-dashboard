## Summary

Keep open: current main and v2026.6.11 still require the Slack bot/app Socket Mode identity and route ordinary replies through bot-token delivery, while current tests intentionally reject treating a user token as the bot identity. The remaining request is a Slack identity/auth feature that needs maintainer product/security approval plus live Slack proof.

## What This Changes

The issue asks OpenClaw's Slack channel to ingest user-token `message.im` events and send DM replies as the configured Slack user instead of the bot/app identity.

## Best Possible Solution

Add this only as an explicit, maintainer-approved Slack user-identity mode with clear authorization boundaries, token selection rules, docs, focused tests, and live Slack Socket Mode proof; otherwise keep the current bot-first behavior.
