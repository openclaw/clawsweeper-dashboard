## Summary

Keep open: current main and v2026.6.11 still treat Slack Socket Mode and normal replies as bot-token paths, while the requested user-authorized DM routing and reply-as-user mode is not implemented and needs product/security approval.

## What This Changes

The issue requests Slack user-token event handling so direct messages to a regular Slack user can be routed to OpenClaw and answered as that user.

## Best Possible Solution

Design a Slack-plugin-owned, default-off user-account DM mode that maps inbound Slack authorizations to configured user tokens, selects the matching send token, documents scopes and audit tradeoffs, and keeps bot/app behavior as the default.

## Solution Assessment

No, overloading userTokenReadOnly alone is not the best solution. The maintainable path is an explicit user-account DM mode with authorization mapping, token selection, tests, docs, and security guardrails.
