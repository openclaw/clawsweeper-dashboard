## Summary

Keep open: current main and v2026.6.11 still make Slack Socket Mode and normal reply delivery bot/app-token centered, while the requested no-APP-badge user identity path is a security and product boundary decision.

## What This Changes

Support Slack user-level `message.im` events and reply routing through a configured xoxp user token for regular-user DM conversations.

## Best Possible Solution

Add a Slack-plugin-owned, explicit opt-in user-identity mode that maps inbound authorizations to a configured xoxp user, enforces allowlist/pairing and audit rules, selects the matching send token, documents scopes, and ships with live Slack proof.
