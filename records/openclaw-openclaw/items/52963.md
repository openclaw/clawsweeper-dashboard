## Label Justifications

- `P2`: The request affects a real Slack DM workflow with message delivery/auth impact, but the bot-DM workaround works and this is not a first-run blocker or outage.

## Summary

Keep open: current main and v2026.6.11 still run Slack Socket Mode and normal replies through the configured bot identity, not a Slack user-token authorization path. The request fits Slack channel improvement work, but acting as a regular Slack user is a product and security-boundary decision before implementation.

## What This Changes

Support Slack user-level Socket Mode `message.im` events and replies as a configured Slack user identity for DM routing.

## Best Possible Solution

Add a Slack-plugin-owned, explicit opt-in user-identity mode that maps Socket Mode authorizations to a configured xoxp user, checks pairing/allowlists/audit rules, selects the matching send token, documents scopes, and ships with live Slack proof.
