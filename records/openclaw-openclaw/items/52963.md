## Label Justifications

- `P2`: This affects a real Slack DM workflow with identity and delivery impact, but the bot-DM workaround works and it is not an outage or first-run blocker.
- `impact:security`: The requested no-APP-badge reply behavior would let OpenClaw act as a regular Slack user identity, crossing an authorization and audit boundary.
- `impact:message-loss`: The reported user-level `message.im` events are not routed into agent turns, so DMs sent to the regular Slack user can be silently missed.
- `impact:auth-provider`: The requested behavior changes Slack token and identity routing between bot/app tokens and xoxp user tokens.

## Summary

Keep open: current main still supports Slack bot/app-token Socket Mode and bot-identity replies, while the requested user-level event routing and no-APP-badge user-token replies remain a product and security-boundary decision.

## What This Changes

The issue requests Slack DM ingestion for user-level `message.im` events and reply delivery through a configured xoxp user token.

## Best Possible Solution

Add a Slack-plugin-owned, explicit opt-in user-identity mode that binds inbound authorizations to a configured xoxp user, selects the matching reply token, preserves pairing/allowlist/audit checks, documents scopes, and ships with live Slack proof.
