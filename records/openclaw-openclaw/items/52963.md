## Label Justifications

- `P2`: This is a meaningful Slack channel improvement with message-loss impact for dedicated user-account agents, but bot/app DMs remain a usable workaround.
- `impact:security`: The request would let OpenClaw receive and send as a regular Slack user identity using a user token, which changes a sensitive identity and authorization boundary.

- `impact:auth-provider`: The requested behavior depends on Slack credential selection, user-token authorization, and inbound identity routing.

## Summary

Keep open: current main and v2026.6.11 still treat Slack Socket Mode and normal monitor replies as bot-token flows, so the requested user-authorized DM routing and reply-as-user behavior is not implemented. The remaining work is security/product-sensitive because it changes Slack identity and token-selection semantics.

## What This Changes

Request support for Slack user-authorized `message.im` events and reply-as-user routing for DMs to a configured Slack user token.

## Best Possible Solution

Add an explicit Slack user-identity mode in the Slack plugin that preserves bot identity by default, routes inbound events by authorizing Slack user/team, selects the matching user token only under opt-in, and ships with docs, security notes, tests, and live Slack proof.
