## Summary

Keep open: current main and the latest release still use the Slack bot-token identity for monitor startup and normal reply delivery, while `userToken` is documented and tested as supplemental read/fallback-write support. The requested regular-user DM ingress and reply-as-user behavior is a real Slack plugin feature, but it changes Slack identity, authorization, and token-selection semantics and needs maintainer product/security approval plus live Slack proof.

## What This Changes

The issue requests Slack user-level Socket Mode events and reply-as-user DM routing when a configured xoxp user token is intended to control a regular Slack user.

## Best Possible Solution

Keep the issue open for an explicit Slack user-identity mode or equivalent maintainer-approved design that covers user-event authorization, token selection, scopes/docs, auditability, and live Slack proof.
