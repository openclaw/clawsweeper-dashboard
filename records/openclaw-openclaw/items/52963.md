## Summary

Keep open: current main and the latest release still require Slack bot/app tokens for Socket Mode and send normal monitor replies with the bot token, so the requested user-authorized DM routing and reply-as-user mode is still missing and needs maintainer product/security review.

## What This Changes

The issue requests Slack user-level Socket Mode event handling so DMs to a configured user token can route into OpenClaw and replies can be sent as that Slack user.

## Best Possible Solution

Add a maintainer-approved, explicit Slack user-identity mode in the Slack plugin that keeps bot-token behavior as the default, routes inbound events by authorizing Slack user/team, sends replies with the matching user token only under opt-in, and includes security docs plus live Slack proof.
