## Label Justifications

- `impact:security`: The request would let OpenClaw receive and send as a regular Slack user identity using a user token, which affects a sensitive identity and authorization boundary.

## Summary

Keep open: current main and the latest release still run the Slack monitor through bot/app-token Socket Mode and deliver normal monitor replies with the bot token, so user-authorized DM routing and reply-as-user behavior remain missing. The request is useful, but it changes Slack identity, token selection, and authorization semantics, so it needs maintainer product/security approval plus live Slack proof.

## What This Changes

The issue requests Slack `message.im` handling for events authorized on behalf of a configured user token, with replies sent through that user token so DMs appear from the regular Slack user.

## Best Possible Solution

Add an explicit Slack user-identity mode in the Slack plugin that keeps bot identity as the default, routes inbound events by authorizing Slack user/team, sends replies with the matching user token only under operator opt-in, and includes docs, tests, and live Slack proof.
