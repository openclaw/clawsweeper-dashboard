## Summary

Keep open: current main and v2026.6.11 still use Slack bot/app-token Socket Mode and bot-token replies, so the requested user-authorized DM routing and reply-as-user behavior remains unimplemented and needs a Slack identity/security product decision.

## What This Changes

Request to let the Slack channel process user-authorized `message.im` events and reply as the configured Slack user via xoxp token.

## Best Possible Solution

Add an explicit Slack user-identity mode in the Slack plugin that preserves the bot-token default, routes inbound envelopes by Slack `authorizations.user_id/team_id`, sends replies with the matching configured user token only under opt-in, and includes docs, security tests, and live Slack proof.
