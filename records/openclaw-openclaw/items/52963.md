## Summary

Keep open: current main and v2026.6.11 still build Slack Socket Mode around the bot/app token pair and route normal monitor replies through the bot token, so user-authorized DM routing remains unimplemented. The request is meaningful, but it changes Slack identity, authorization, and reply-token semantics, so it needs maintainer product/security review and live Slack proof before implementation.

## What This Changes

Support receiving Slack `message.im` events authorized on behalf of a configured user token and replying through that user identity for natural user-DM routing.

## Best Possible Solution

Add a maintainer-approved Slack user-identity mode in the Slack plugin that routes inbound envelopes by authorizing user/team, selects the reply token from that authorization, preserves the bot-token default, and includes docs, focused tests, and live Slack proof.

## Reproduction Assessment

No live current-main Slack reproduction was run. Source inspection confirms the requested user-authorized routing path is absent, while Slack delivery still needs live proof with user-token event subscriptions and `im:history`.

## Solution Assessment

Unclear as a concrete implementation. The best path is an explicit maintainer-approved Slack user-identity mode rather than silently changing existing bot-token-first behavior.
