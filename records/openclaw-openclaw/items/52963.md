## Summary

Keep open: current main and the latest release still implement Slack Socket Mode and normal replies around the bot token, while the requested user-authorized DM ingestion and xoxp reply routing remain a security-sensitive product decision.

## What This Changes

The issue requests Slack user-level `message.im` events and replies sent as the configured Slack user account instead of the Slack app bot identity.

## Best Possible Solution

Design an explicit Slack-plugin-owned user-account DM mode that maps inbound Slack authorizations to configured user tokens, selects the matching send token, documents scopes and audit tradeoffs, and keeps bot/app behavior as the default.
