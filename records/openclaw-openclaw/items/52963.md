## Summary

Keep open: current main and the latest release still treat Slack Socket Mode and normal monitor replies as bot/app-token paths, while the requested user-authorized `message.im` routing and reply-as-user behavior is still missing. The remaining work is useful but security-sensitive and needs maintainer product approval plus live Slack proof before implementation.

## What This Changes

The issue requests Slack user-token inbound DM event routing and reply-as-user behavior for Slack user-level events.

## Best Possible Solution

Add an explicit opt-in Slack user-identity mode in the Slack plugin that keeps bot-token behavior as the default, routes inbound events by authorizing Slack user/team, selects the matching user token for replies, documents the security model, and includes focused tests plus live Slack proof.
