## Summary

Keep open: current main and v2026.6.11 still run Slack Socket Mode and normal replies through the bot/app token path, so the requested user-authorized DM routing and reply-as-user behavior is not implemented. The feature is useful, but it changes Slack identity, authorization, and token-selection semantics and needs maintainer product/security approval plus live Slack proof.

## What This Changes

Request support for Slack user-authorized `message.im` events and replies sent as the configured Slack user identity for dedicated user-account agents.

## Best Possible Solution

Add an explicit Slack user-identity mode in the Slack plugin that preserves the bot-token default, routes inbound events by authorizing Slack user/team, sends replies with the matching user token only under operator opt-in, and includes security docs plus live Slack proof.
