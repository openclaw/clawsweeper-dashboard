## Summary

Keep open: current main still treats Slack Socket Mode as bot/app-token based and sends normal monitor replies with `ctx.botToken`, so the requested user-authorized DM routing and reply-as-user behavior remains missing. The remaining work is useful, but it changes Slack identity, authorization, and audit semantics, so it needs maintainer product/security direction plus live Slack proof before implementation.

## What This Changes

Request Slack to process user-authorized `message.im` DM events and reply through configured user tokens so a dedicated regular Slack user can be controlled by OpenClaw.

## Best Possible Solution

Add an explicit Slack user-identity mode in the Slack plugin that preserves bot identity as the default, routes inbound events by Slack authorization user/team, sends replies with the matching configured user token only under operator opt-in, and includes docs plus live Slack proof.
