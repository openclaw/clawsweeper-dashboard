## Summary

Keep open: current main still has the `agents set-identity --workspace` contract mismatch. The CLI uses `--workspace` as an identity/agent locator and echoes it as `workspace` in success output, while the existing lower-level Gateway update API can mutate workspace but there is no documented `openclaw agents` relocation path.

## What This Changes

The issue asks OpenClaw to resolve the `agents set-identity --workspace` mismatch where the flag locates identity data but the success response can be read as confirming a stored agent workspace update.

## Best Possible Solution

Keep `set-identity --workspace` locator-only or make any behavior change explicit, add a documented existing-agent workspace update path backed by `agents.update` if relocation is desired, and make JSON/text output distinguish locator paths from stored workspace state.
