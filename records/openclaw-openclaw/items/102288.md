## Summary

Keep open: current main still has the `set-identity --workspace` contract mismatch, and the existing Gateway workspace update primitive is not exposed as a documented `openclaw agents` relocation command.

## What This Changes

The issue asks OpenClaw to resolve the misleading `agents set-identity --workspace` behavior where a locator path is echoed as `workspace` without updating the stored agent workspace.

## Best Possible Solution

Keep `set-identity --workspace` locator-only, make text and JSON output distinguish the identity-source locator from the stored agent workspace, and add a documented CLI workspace-update path backed by `agents.update` if maintainers want relocation support.

## Maintainer Decision

Question: Should the public CLI solve existing-agent relocation with a dedicated workspace setter, or only clarify that `set-identity --workspace` is a locator?

Rationale: Both fixes are technically plausible, but they choose public CLI semantics and JSON output compatibility for a shipped command.

Likely owner: steipete

Owner reason: The original public identity CLI shape traces to this owner, and the remaining choice is about command semantics rather than only the Gateway implementation.

Owner confidence: high

Options:

- **Add Dedicated Setter (recommended):** Add `agents set-workspace` or `agents update --workspace` backed by the existing `agents.update` path, while making `set-identity` output explicit about locator versus stored workspace.
- **Clarify Output Only:** Keep relocation out of the CLI for now and add additive output/docs wording so `set-identity` cannot be read as confirming a stored workspace update.
- **Repurpose Set Identity:** Make `set-identity --workspace` update the stored workspace too, accepting compatibility risk against current help text and docs.

## Reproduction Assessment

Yes, by source inspection: `set-identity` only writes identity fields into config but returns the locator directory as `workspace`. I did not run the CLI because this review is read-only.

## Solution Assessment

Unclear until maintainers choose the CLI contract. The narrow bug repair is output/docs clarification, while the complete relocation workflow likely needs a dedicated setter using the existing `agents.update` API.
