## Summary

Keep open: current main still has the source-level CLI contract mismatch, and the existing lower-level Gateway workspace update path does not give users a documented `openclaw agents` relocation command.

## What This Changes

The issue asks OpenClaw to resolve the mismatch between `agents set-identity --workspace` locator semantics, its JSON success response, and the absence of a documented existing-agent workspace setter.

## Best Possible Solution

Keep `set-identity --workspace` locator-only with explicit locator-versus-stored-workspace output, and add a dedicated documented workspace-update command backed by `agents.update` only if maintainers want existing-agent relocation in the CLI.

Options:

- **Add Dedicated Setter (recommended):** Add an `agents set-workspace` or `agents update --workspace` command backed by `agents.update`, while making `set-identity` output explicit about locator versus stored workspace.
- **Clarify Output Only:** Keep relocation out of the CLI for now and add additive output/docs wording so `set-identity` cannot be read as confirming a stored workspace update.
- **Repurpose Set Identity:** Make `set-identity --workspace` update the stored workspace too, accepting compatibility risk against current help text and docs.
