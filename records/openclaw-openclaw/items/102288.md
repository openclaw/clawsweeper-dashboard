## Summary

Keep open: current main and v2026.6.11 still echo the `set-identity` locator directory as `workspace` without updating the stored agent workspace. The remaining blocker is maintainer direction on the public CLI contract, because both a dedicated workspace setter and an output/docs clarification are plausible fixes.

## What This Changes

The issue asks OpenClaw to stop `agents set-identity --workspace` from implying that the stored agent workspace was updated, either by adding a CLI workspace setter or clarifying the locator-only output.

## Best Possible Solution

Keep `set-identity --workspace` locator-only, make its text and JSON output distinguish identity-source locator from stored agent workspace, and add a dedicated documented CLI workspace-update path backed by `agents.update` if maintainers want relocation support.

Question: Should the public CLI solve this by adding a dedicated existing-agent workspace setter, or by only clarifying that `set-identity --workspace` is a locator?

Rationale: Both repairs are technically valid, but the choice changes public CLI semantics and JSON output compatibility, so automation should not choose it without maintainer intent.

Owner confidence: medium

Options:

- **Add Dedicated Setter (recommended):** Add an `agents set-workspace` or `agents update --workspace` path backed by `agents.update`, while making `set-identity` output explicit about locator versus stored workspace.
- **Clarify Output Only:** Keep relocation out of the CLI for now and add or rename additive output fields so `set-identity` cannot be read as confirming a stored workspace update.
- **Repurpose Set Identity:** Make `set-identity --workspace` update stored workspace too, accepting compatibility risk against current help text, docs, and scripts.

## Reproduction Assessment

Yes. Source inspection shows `set-identity` only writes identity fields but returns the locator directory as `workspace`, and v2026.6.11 still has the same output shape; I did not run the CLI because this review is read-only.

## Solution Assessment

Unclear until maintainers choose the CLI contract. The narrow bug repair is output/docs clarification, while the complete relocation workflow likely needs a dedicated setter using the existing `agents.update` API.
