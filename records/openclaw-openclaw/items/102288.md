## Summary

Keep open: current main still has a real CLI contract mismatch where `set-identity --workspace` is documented as a locator/selector but the success output reports that locator as `workspace`, while no public CLI workspace-update path is documented.

## What This Changes

The issue requests that `openclaw agents set-identity --workspace` stop silently looking like a stored-workspace update, either by becoming an actual setter or by exposing a separate documented workspace-update path and clearer output.

## Best Possible Solution

Keep `set-identity --workspace` locator-only, make its text/JSON output distinguish the identity-source workspace from the stored agent workspace, and add a dedicated documented CLI workspace-update path backed by the existing `agents.update` mutation if maintainers want relocation support.
