## Summary

Keep open: current main still has the CLI contract mismatch, and the existing lower-level Gateway workspace update path does not provide a documented `openclaw agents` relocation command.

## What This Changes

The issue reports that `openclaw agents set-identity --workspace` echoes a supplied workspace path without updating the agent's stored workspace, leaving operators with no documented CLI relocation command.

## Best Possible Solution

Keep `set-identity --workspace` locator-only, make its text/JSON output distinguish identity-source locator from stored workspace, and add a documented `agents set-workspace` or `agents update --workspace` path if maintainers want relocation support.
