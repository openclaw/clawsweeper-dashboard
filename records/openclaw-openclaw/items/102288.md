## Summary

Keep open: current main still has the reported CLI contract mismatch, and the existing Gateway workspace update primitive does not provide a documented `openclaw agents` relocation command.

## What This Changes

`openclaw agents set-identity --workspace <dir>` is reported as echoing a locator path in a `workspace` success field without updating the stored agent workspace.

## Best Possible Solution

Keep `set-identity --workspace` locator-only, make its output distinguish the identity-source locator from the stored agent workspace, and add a dedicated documented workspace-update CLI backed by `agents.update` if maintainers want relocation support.
