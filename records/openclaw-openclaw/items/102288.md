## Summary

Keep open: current main still has the CLI contract mismatch, and the existing lower-level Gateway workspace update path does not give users a documented `openclaw agents` relocation command.

## What This Changes

The issue asks OpenClaw to stop implying that `agents set-identity --workspace` updates an agent's stored workspace, or to add a documented CLI path that actually updates it.

## Best Possible Solution

Keep `set-identity --workspace` locator-only, make its text/JSON output distinguish the identity-source locator from the stored agent workspace, and add a dedicated documented CLI workspace-update path backed by `agents.update` if maintainers want relocation support.

Options:

- **Add Dedicated Setter (recommended):** Add an `agents set-workspace` or `agents update --workspace` command backed by the existing `agents.update` API while making `set-identity` output explicit about locator versus stored workspace.
- **Clarify Output Only:** Keep relocation out of the CLI for now and add/rename output fields so `set-identity` cannot be read as confirming a stored workspace update.
- **Repurpose Set Identity:** Make `set-identity --workspace` update the stored workspace too, accepting compatibility risk against current help text and docs.
