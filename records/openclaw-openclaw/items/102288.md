## Summary

Keep open: current main still has the reported CLI contract mismatch, and the existing Gateway workspace-update API does not provide a documented `openclaw agents` relocation command or make `set-identity` output unambiguous.

## What This Changes

The issue asks for `agents set-identity --workspace` to stop implying that it changed the stored agent workspace, either by becoming a real workspace setter or by clarifying the locator-only CLI/output contract.

## Best Possible Solution

Keep `set-identity --workspace` locator-only, make text/JSON output distinguish the locator from the stored agent workspace, and add a dedicated documented `agents update --workspace` or `agents set-workspace` path backed by `agents.update` if maintainers want CLI relocation support.
