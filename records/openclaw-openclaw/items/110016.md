## Summary

The bounded pinned-read mechanism is sound and the live mTLS proof is convincing, but this PR intentionally turns previously accepted client certificate and key files above 64 KiB into upgrade failures without an established supported-size contract. The force-pushed head preserves the same two-file change and no prior blocker was resolved, so an MCP transport owner still needs to choose and validate the compatibility ceiling before merge.

## What This Changes

Routes MCP client certificate and private-key reads through the pinned secret-file reader with a 64 KiB per-file limit and adds focused normal and oversized-read tests.

## Best Possible Solution

Keep the pinned bounded reader, establish and document a defensible maximum for MCP client certificate and key files, and add a valid certificate-chain regression near that boundary alongside the oversized pre-dispatch rejection test.
