## Summary

Keep this PR open: the bounded pinned-file read is a strong, well-proven fix, but the new 64 KiB limit becomes an upgrade-sensitive compatibility boundary that needs explicit owner acceptance and valid certificate-chain coverage before merge.

## What This Changes

Routes MCP client certificate and private-key reads through the pinned secret-file reader with a 64 KiB limit and adds focused bounded-read tests.

## Best Possible Solution

Keep the pinned bounded reader, make the supported TLS-file limit an explicit reviewed contract, and add a valid multi-certificate-chain regression near that boundary alongside the oversized rejection proof.
