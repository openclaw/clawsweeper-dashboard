## Summary

The optimization targets an unreleased compile-only facade that currently prepares every query, but no benchmark shows that this is a material OpenClaw bottleneck. Keep the issue open for a maintainer to set the performance threshold and approve a bounded, explicit-lifecycle design rather than the proposed unbounded cache and finalizers.

## What This Changes

Add database-scoped reuse of prepared node:sqlite statements for repeated Kysely-compiled synchronous queries.

## Best Possible Solution

Benchmark representative repeated state and gateway query shapes on supported Node versions, then add one bounded per-database cache shared by eager and iterator paths only if the improvement is material, clearing it through the existing explicit database lifecycle hook rather than finalizers.
