## Summary

Keep open: current main still has the replay-unsafe post-tool incomplete-turn path and marks these runs abandoned rather than providing deterministic session recovery. The recent completed-post-tool fix only covers stale pre-tool snapshots when a final answer exists; it does not solve this report's failed-continuation recovery gap.

## What This Changes

The issue requests durable recovery state for cases where tool execution succeeds but the assistant continuation or gateway delivery fails afterward.

## Best Possible Solution

Define a generic replay-unsafe post-tool recovery contract that preserves or resumes session state safely, with durable receipts and tool summaries as diagnostics rather than the only recovery mechanism.
