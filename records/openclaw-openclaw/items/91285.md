## Summary

Keep open: current main and v2026.6.11 still fail closed with the same post-tool incomplete-turn warning when replay metadata says tool side effects may exist, and the remaining question is recovery/session-survival semantics rather than warning copy.

## What This Changes

The issue asks OpenClaw to make successful tool execution followed by failed assistant continuation recoverable and observable without forcing the user to manually inspect side effects before retrying.

## Best Possible Solution

Define a maintainer-approved recovery contract for post-tool non-deliverable turns, likely centered on session survival, replayInvalid/liveness metadata, and durable quarantine or repair records before adding retries or receipt UI.

Options:

- **Session-survival and quarantine first (recommended):** Define durable liveness/quarantine semantics so replay-unsafe incomplete turns cannot poison future context and users get a clear resume or reset path.
- **Receipt-only observability:** Add richer tool lifecycle receipts and diagnostics without changing retry or session-recovery behavior, improving manual recovery but not automatic continuation.
- **Narrow safe replay policy:** Allow retries only for provably idempotent or no-side-effect current-turn states while preserving fail-closed behavior for unknown tools and committed side effects.
