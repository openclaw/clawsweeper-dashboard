## Summary

Keep open: current main and the latest release still resolve Discord routing before cross-bot mention or reply-target selection, and the remaining fix changes stable multi-bot default-owner behavior that needs maintainer product direction.

## What This Changes

The issue asks Discord multi-bot routing to prefer explicit bot mentions, then native reply targets, then the per-channel default owner while suppressing default-owner responses in targeted cases.

## Best Possible Solution

Implement the precedence in the Discord plugin/preflight owner boundary after maintainer confirmation, with tests for explicit mention, reply-target, and untagged default-owner cases plus live or redacted Discord proof on the resulting PR.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence current-main reproduction path: Discord preflight resolves the effective route before target metadata and only treats reply metadata as an implicit mention for the current handler bot ID.

## Solution Assessment

Unclear until maintainers confirm the product contract. The durable solution should be Discord-owned active-target selection before default routing, not only the narrower bot-authored reply policy in https://github.com/openclaw/openclaw/pull/80235.
