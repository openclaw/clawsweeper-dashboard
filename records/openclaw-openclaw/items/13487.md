## Summary

Keep open: current main and latest release still resolve Discord routing before cross-bot mention or reply-target selection, compare mention and reply metadata only to the running bot ID, and lack a default-owner suppression result for messages targeting another configured bot.

## What This Changes

This issue requests deterministic Discord multi-bot routing precedence: explicit bot mention first, native reply target second, and channel default owner only when no targeted signal exists.

## Best Possible Solution

Maintainers should confirm the Discord active-target contract, then implement target selection in the Discord plugin before shared default routing with a configured bot-user-id to account/agent map and focused suppression tests.
