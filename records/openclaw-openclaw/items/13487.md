## Label Justifications

- `P1`: The issue affects live multi-bot Discord routing and can cause missing, duplicate, or wrong-agent responses in channel workflows.
- `impact:message-loss`: Targeted Discord messages can be consumed by the default owner or fail to reach the intended bot response path.
- `impact:session-state`: Routing a targeted Discord message to the default owner can attach the turn to the wrong agent session and conversation state.
- `maturity:stable`: Discord is scored M4 Stable, including Conversation Routing and Delivery, and this issue targets that surface.

## Summary

Keep open: current main and v2026.6.11 still choose the Discord route before cross-bot mention/reply target selection, compare target signals only to the currently running bot user ID, and lack a default-owner suppression state for another targeted bot. The open related PR only handles a narrower implicit-reply policy, so this issue is still necessary.

## What This Changes

Request deterministic Discord multi-bot routing where explicit bot mentions win over native reply targets, both suppress the default owner, and untagged messages route only to the per-channel default owner.

## Best Possible Solution

Confirm the Discord active-target contract, then implement target selection inside the Discord plugin before shared default routing using a configured bot-user-id to account/agent map, with explicit mentions first, referenced-message bot author second, and the default owner only when no target signal exists.

## Reproduction Assessment

Yes, at source level: current main resolves Discord routing before mention/reply target selection and compares mention/reply metadata only to the current handler botUserId. I did not run a live Discord multi-bot replay in this read-only review.

## Solution Assessment

Unclear until maintainers confirm the product contract. Generic mention suppression alone is not the best fix because Discord needs a configured bot/account/agent target map before default routing.
