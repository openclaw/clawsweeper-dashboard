## Summary

Keep open: current main still resolves Discord routing before cross-bot mention/reply target selection, only compares reply metadata to the running handler's bot ID, and lacks a default-owner suppression result for messages targeting another configured bot.

## What This Changes

The issue requests deterministic Discord multi-bot routing precedence: explicit bot mention, then reply-target bot, then per-channel default owner, with the default owner suppressed for targeted messages.

## Best Possible Solution

Implement the precedence in the Discord plugin/preflight owner boundary after maintainer confirmation, with tests for explicit mention, reply-target, and untagged default-owner cases plus live or redacted Discord proof on the resulting PR.
