## Summary

Keep open: current main still resolves Discord routing before cross-bot mention or reply-target selection, only compares Discord mention/reply metadata to the running handler bot ID, and lacks a default-owner suppression result for messages targeting another configured bot.

## What This Changes

The issue requests deterministic Discord multi-bot routing where explicit bot mentions win first, native reply targets win second, and the default owner responds only to untargeted messages.

## Best Possible Solution

Maintainers should confirm the Discord active-target contract, then implement target selection in the Discord plugin before shared default routing with a configured bot-user-id to account or agent map and focused suppression tests.
