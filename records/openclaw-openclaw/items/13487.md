## Summary

Keep open: current main still resolves Discord routing before cross-bot mention or reply-target selection, compares mention/reply metadata only to the running handler bot ID, and lacks a default-owner suppression state for another targeted bot. The latest release tag has the same missing behavior, and the open related PR only covers bot-authored reply activation policy, not the full mention > reply-target > default-owner contract.

## What This Changes

The issue requests deterministic Discord multi-bot routing where explicit bot mentions win over reply-target metadata, reply targets win over the default owner, and the default owner is suppressed whenever a specific bot is targeted.

## Best Possible Solution

Confirm the Discord active-target policy, then implement target selection in the Discord plugin before shared default routing so explicit mentioned bot accounts win, referenced bot authors win next, and the default owner is used only when no targeted signal exists.

## Reproduction Assessment

Yes, at source level: current main resolves Discord routing before mention/reply target selection and compares mention/reply metadata only to the current handler botUserId. I did not run a live Discord multi-bot replay in this read-only review.

## Solution Assessment

Unclear until maintainers confirm the product contract. Generic mention suppression alone is not the best fix because Discord needs a configured bot/account/agent target map before default routing.
