## Label Justifications

- `P1`: The issue affects live multi-bot Discord routing and can cause wrong-agent, duplicated, or missing replies in shared channel workflows.
- `impact:message-loss`: Messages addressed to a specific Discord bot can be consumed by or fall through to the wrong responder instead of only reaching the intended target.
- `impact:session-state`: Wrong-agent routing can attach a Discord turn to the default owner's session instead of the agent the user mentioned or replied to.
- `maturity:stable`: Discord is scored M4 Stable in `qa/maturity-scores.yaml`, and this issue affects its routing and delivery behavior.

## Summary

Keep open: current main and v2026.6.11 still resolve the Discord route before any cross-bot mention/reply-target selection, compare mention and reply metadata only to the running handler's bot ID, and lack a suppression result for targeted messages that should not wake the default owner.

## What This Changes

The issue asks for deterministic Discord multi-bot routing where explicit mentions beat reply targets, reply targets beat the channel default owner, and targeted messages suppress default-owner responses.

## Best Possible Solution

Define the Discord active-target contract, then implement target selection in the Discord plugin before default routing: explicit mentioned configured bots first, referenced-message bot author second, default owner only when no target exists, with focused preflight/routing tests and live multi-bot Discord proof.
