## Label Justifications

- `P1`: The issue affects live multi-bot Discord routing and can cause missing, duplicate, or wrong-agent responses in shared channel workflows.
- `impact:message-loss`: Targeted Discord replies or mentions can fail to reach the intended bot or can be consumed by the default owner path.
- `impact:session-state`: Wrong-agent routing can attach a targeted Discord turn to the default owner instead of the bot or account the user addressed.
- `maturity:stable`: The issue affects Discord Conversation Routing and Delivery, and Discord is scored M4 Stable in the maturity scorecard.

## Summary

Keep open: current main and v2026.6.11 still resolve the Discord route before cross-bot mention or reply-target selection, compare mention/reply metadata only to the current handler bot ID, and have no default-owner suppression state for another targeted bot.

## What This Changes

The issue requests deterministic Discord multi-bot routing precedence: explicit mention first, native reply target second, and default owner only when no targeted signal exists.

## Best Possible Solution

Confirm the Discord active-target contract, then implement target selection in the Discord plugin before shared default routing with a configured bot-user-id to account/agent map and focused suppression tests.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 resolve Discord routing before mention/reply target selection and compare mention/reply metadata only to the current handler botUserId. I did not run a live Discord multi-bot replay in this read-only review.

## Solution Assessment

Unclear until maintainers confirm the product contract. The narrower implicit-reply policy in https://github.com/openclaw/openclaw/pull/80235 is not the best complete fix because this issue needs a configured bot/account/agent target map before default routing.
