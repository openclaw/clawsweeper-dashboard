## Label Justifications

- `P1`: The issue affects active multi-bot Discord workflows through missing replies, duplicate responders, or routing to the wrong agent.
- `impact:message-loss`: Reply-shaped or targeted messages can receive no visible response or can be handled by an unintended responder.
- `impact:session-state`: Routing a targeted Discord message through the default owner associates the turn with the wrong agent and session context.

## Summary

Keep open: the requested deterministic cross-bot routing remains necessary. Recent source review found Discord route selection occurs before cross-bot mention or reply-target resolution, current documentation still describes binding/default routing rather than targeted-bot precedence, and the related proposed fixes are either closed unmerged or address narrower reply-policy behavior.

## What This Changes

Make Discord multi-bot routing prefer explicit bot mentions, then replied-to bot identity, then the channel default owner, while suppressing non-target responders.

## Best Possible Solution

Implement Discord-owned target selection before effective route finalization: map configured bot user IDs to Discord accounts and agents, select explicit mentioned bots first, select the referenced-message bot second, and fall back to the existing channel owner only when neither signal exists; prove suppression, binding interaction, and human-versus-bot reply behavior with focused tests and live multi-bot Discord evidence.

Options:

- **Adopt Discord target precedence (recommended):** Make explicit bot mentions and replied-to bot identity authoritative before channel-owner fallback, with non-target handlers suppressed.
- **Keep bindings authoritative:** Continue using mentions and replies only for activation while requiring explicit bindings or focus commands to select another agent.
- **Add an opt-in policy:** Preserve current defaults and introduce a Discord configuration switch for targeted-bot routing, at the cost of another compatibility-sensitive config surface.

## Reproduction Assessment

Yes at source level: configure multiple Discord bot accounts with a channel default owner, then mention or reply to a different bot; the reviewed preflight has no cross-account target map or default-owner suppression path. A commenter also reported live mention-versus-reply behavior consistent with this gap.

## Solution Assessment

Unclear until maintainers confirm that Discord mention and reply metadata should override bindings. If approved, a Discord-plugin target-selection step before route finalization is narrower and more maintainable than adding content matching or a generic configuration knob.
