## Summary

Keep open: current main and v2026.6.11 still resolve the Discord route before cross-bot mention or reply-target selection, compare Discord mention/reply metadata only to the running handler bot ID, and have no default-owner suppression state for another targeted bot. The open pull request at https://github.com/openclaw/openclaw/pull/80235 is related but only covers bot-authored implicit reply activation policy, not mention > reply-target > default-owner routing.

## What This Changes

Request deterministic Discord multi-bot routing where explicit bot mentions win over reply targets, reply targets win over the channel default owner, and targeted messages suppress the default owner.

## Best Possible Solution

Confirm the Discord active-target contract, then implement target selection in the Discord plugin before shared default routing: explicit mentioned configured bot accounts first, referenced bot author second, and the per-channel default owner only when no target signal exists.

## Reproduction Assessment

Yes, at source level: current main resolves Discord routing before mention/reply target selection and compares mention/reply metadata only to the current handler botUserId. I did not run a live Discord multi-bot replay in this read-only review.

## Solution Assessment

Unclear until maintainers confirm the product contract. Generic mention suppression alone is not the best fix because Discord needs a configured bot/account/agent target map before default routing.
