- `impact:message-loss`: Targeted Discord messages can fail to reach the intended bot path or be consumed by the default owner.
- `impact:session-state`: Routing a targeted Discord message to the default owner can attach the turn to the wrong agent session and conversation state.
- `maturity:stable`: The issue affects Discord Conversation Routing and Delivery, and Discord is scored M4 Stable in the maturity scorecard.

## Summary

Keep open: current main and v2026.6.11 still resolve Discord routing before cross-bot mention/reply-target selection, compare mention and reply metadata only to the running handler bot, and lack a default-owner suppression state. The open related PR at https://github.com/openclaw/openclaw/pull/80235 covers only bot-authored reply activation policy, not the full mention > reply-target > default-owner contract.

## What This Changes

Requests deterministic Discord multi-bot routing where explicit bot mentions win first, reply-target bot authors win second, and the per-channel default owner responds only when no targeted signal exists.

## Best Possible Solution

Confirm the Discord active-target policy, then implement target selection in the Discord plugin before shared default routing so explicit mentioned bot accounts win, referenced bot authors win next, and the default owner is used only when no targeted signal exists.

## Reproduction Assessment

Yes, at source level: current main resolves Discord routing before mention/reply target selection and compares mention/reply metadata only to the current handler botUserId. I did not run a live Discord multi-bot replay in this read-only review.

## Solution Assessment

Unclear until maintainers confirm the product contract. Generic mention suppression alone is not the best fix because Discord needs a configured bot/account/agent target map before default routing.
