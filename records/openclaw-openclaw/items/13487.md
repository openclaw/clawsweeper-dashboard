## Label Justifications

- `P1`: The issue affects live multi-bot Discord channel routing and can cause missing, duplicate, or wrong-agent responses in user workflows.
- `impact:message-loss`: A targeted Discord mention or reply can fail to reach the intended bot path or be consumed by the default owner.
- `impact:session-state`: Routing a targeted Discord message to the default owner can attach the turn to the wrong agent session and conversation state.
- `maturity:stable`: Discord is scored M4 Stable and the issue targets its mention gating and conversation routing surfaces.

## Summary

Keep open: current main and the latest release still resolve the Discord route before cross-bot mention or reply-target selection, compare mention/reply metadata only to the running bot ID, and have no default-owner suppression result for another targeted bot.

## What This Changes

Requests deterministic Discord multi-bot routing precedence where explicit bot mentions win, reply targets win next, and the default owner is used only when no targeted signal exists.

## Best Possible Solution

Confirm the Discord active-target product contract, then implement target selection in the Discord plugin before shared default routing with focused tests proving default-owner suppression in targeted cases.

## Reproduction Assessment

Yes, at source level: current main resolves Discord routing before active target selection and compares mention/reply metadata only to the current handler botUserId. A commenter also reported a live multi-bot Discord repro, but I did not run a live replay in this read-only review.

## Solution Assessment

Unclear until maintainers confirm the product contract. The maintainable owner boundary is Discord plugin target selection before shared default routing; generic mention suppression alone is too narrow because it lacks the configured bot/account/agent map.
