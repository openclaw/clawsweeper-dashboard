## Label Justifications

- `P1`: The issue affects live multi-bot Discord routing and can cause missing, duplicate, or wrong-agent responses in shared channel workflows.
- `impact:message-loss`: Targeted Discord replies or mentions can fail to reach the intended bot or can be consumed by the default-owner path.
- `impact:session-state`: Wrong-agent Discord routing can attach a targeted Discord turn to the default owner instead of the bot or account the user addressed.
- `maturity:stable`: Discord is scored M4 Stable, and this issue affects its Conversation Routing and Delivery area.

## Summary

Keep open: current main and the latest release still resolve Discord routing before cross-bot active-target selection, compare explicit mentions and reply metadata only to the running handler bot ID, and do not expose a default-owner suppression result for messages targeting another configured bot.

## What This Changes

The issue requests deterministic Discord multi-bot routing precedence: explicit bot mentions first, reply-target bot second, and the channel default owner only when no targeted signal exists.

## Best Possible Solution

Maintainers should confirm the Discord active-target contract, then implement target selection in the Discord plugin before shared default routing with a configured bot-user-id to account/agent map and focused suppression tests.
