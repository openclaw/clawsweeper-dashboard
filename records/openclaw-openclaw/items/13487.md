## Summary

Keep open: current main and the latest release still resolve Discord routing before cross-bot mention/reply target selection, compare mention/reply metadata only to the current handler bot ID, and have no default-owner suppression state. The open related PR only covers bot-authored reply activation policy, not the full mention > reply-target > default-owner contract.

## What This Changes

The issue requests deterministic Discord multi-bot routing where explicit bot mentions win over reply targets, reply targets win over the per-channel default owner, and the default owner is suppressed for targeted messages.

## Best Possible Solution

Confirm the Discord active-target contract, then implement a Discord-owned bot-user-id to account/agent target map before shared route fallback so explicit mentions win, referenced bot authors win next, and the default owner is used only when no targeted signal exists.

## Reproduction Assessment

Yes, at source level: current main resolves the Discord route before mention/reply target selection and compares mention/reply metadata only to the current handler botUserId. I did not run a live Discord multi-bot replay in this read-only review.

## Solution Assessment

Unclear until maintainers confirm the product contract. Generic mention suppression alone is not the best fix because Discord needs a configured bot/account/agent target map before default routing.
