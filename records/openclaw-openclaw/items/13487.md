## Label Justifications

- `P1`: The issue affects real Discord multi-bot channel routing where replies or mentions can be lost, ignored, or answered by the wrong/default bot.
- `impact:message-loss`: The requested behavior prevents targeted Discord messages from being dropped or answered by an unintended default owner.
- `impact:session-state`: Wrong-agent routing can attach the conversation to the wrong agent/session in multi-bot Discord channels.
- `maturity:stable`: Discord is listed as an M4 Stable surface, and Conversation Routing and Delivery is part of the stable Discord taxonomy entry.

## Summary

Keep open: current main and the latest release still resolve the Discord route before cross-bot mention or reply-target selection, compare Discord target metadata only to the currently running bot ID, and lack a default-owner suppression result for messages targeting another configured bot.

## What This Changes

The issue requests Discord multi-bot inbound routing precedence: explicit bot mention first, native reply target second, and default owner only when no target signal is present.

## Best Possible Solution

Implement the precedence in the Discord plugin before default routing: map configured Discord bot user IDs to accounts/agents, select explicit mentioned bots first, select the referenced bot author second, and use the channel default owner only when no target signal exists.

## Reproduction Assessment

Yes at source level: current Discord preflight resolves the route before target metadata, only compares mentions/replies to the current bot ID, and has no other-agent/default-owner suppression state. I did not run a live Discord multi-bot reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers confirm the product contract. The requested precedence is the narrow maintainable shape for the reported multi-bot behavior, but it changes default-owner semantics and should be accepted explicitly before implementation.
