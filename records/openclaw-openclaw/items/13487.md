## Label Justifications

- `P1`: The issue affects live multi-bot Discord routing and can cause missing, duplicate, or wrong-agent responses in shared channel workflows.
- `impact:message-loss`: Targeted Discord messages can be consumed by the default owner or fail to reach the intended bot response path.

## Summary

Keep open: current main and v2026.6.11 still choose the Discord route before cross-bot mention or reply-target selection, compare target metadata only to the current handler bot ID, and have no default-owner suppression state for another targeted bot.

## What This Changes

Request deterministic Discord multi-bot routing where explicit bot mentions win first, Discord reply-target bot authors win second, and the channel default owner is used only when no targeted signal exists.

## Best Possible Solution

Confirm the Discord active-target contract, then implement target selection inside the Discord plugin before shared default routing using a configured bot-user-id to account/agent map, with explicit mentions first, referenced-message bot author second, and default owner only when no target signal exists.

## Reproduction Assessment

Yes, at source level: current main resolves Discord routing before mention/reply target selection and compares mention/reply metadata only to the current handler botUserId. I did not run a live Discord multi-bot replay in this read-only review.

## Solution Assessment

Unclear until maintainers confirm the product contract. Generic mention suppression or the narrower implicit-reply policy is not the best full fix because Discord needs a configured bot/account/agent target map before default routing.
