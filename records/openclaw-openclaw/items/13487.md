## Label Justifications

- `P1`: The issue affects live multi-bot Discord routing and can cause missing, duplicate, or wrong-agent responses in shared channel workflows.
- `impact:message-loss`: Targeted Discord messages can be consumed by the default owner or fail to reach the intended bot response path.
- `impact:session-state`: Routing a targeted Discord message to the default owner can attach the turn to the wrong agent session and conversation state.
- `maturity:stable`: Discord is scored M4 Stable and this issue targets its conversation routing and delivery behavior.

## Summary

Keep open: current main and v2026.6.11 still route Discord messages before cross-bot mention/reply target selection, compare mention metadata only to the current handler bot ID, and lack a default-owner suppression outcome for another targeted bot.

## What This Changes

Discord multi-bot routing should prefer explicit mentions, then reply targets, then the channel default owner, with default-owner suppression for targeted messages.

## Best Possible Solution

Confirm the Discord active-target contract, then implement target selection in the Discord plugin before shared default routing using a configured bot-user-id to account/agent map, with explicit mentions first, referenced-message bot authors second, and the default owner only when no target signal exists.

## Reproduction Assessment

Yes, at source level: current main resolves Discord routing before mention/reply target selection and compares mention/reply metadata only to the current handler botUserId. I did not run a live Discord multi-bot replay in this read-only review.

## Solution Assessment

Unclear until maintainers confirm the product contract. Generic ignoreOtherMentions suppression or the narrower implicit-reply policy is not the best full fix because Discord needs configured bot/account/agent target selection before default routing.
