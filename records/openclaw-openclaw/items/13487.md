## Summary

Keep open: current main still resolves Discord routing before cross-bot mention or reply-target selection, only compares Discord mention/reply metadata to the running handler's bot ID, and has no default-owner suppression result for messages targeting another configured bot.

## What This Changes

The issue requests deterministic Discord multi-bot routing precedence: explicit bot mention first, native reply target second, and per-channel default owner only when no targeted signal exists.

## Best Possible Solution

Maintainers should confirm the Discord active-target contract, then implement target selection in the Discord plugin before shared default routing with a configured bot-user-id to account/agent map and focused suppression tests.
