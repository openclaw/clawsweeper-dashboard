## Summary

Keep open: current main and v2026.6.11 still resolve the Discord route before cross-bot mention/reply target selection, and the open related PR only covers a narrower reply policy knob.

## What This Changes

Requests deterministic Discord multi-bot routing where explicit mentions outrank reply targets, which outrank the per-channel default owner, with default-owner suppression in targeted cases.

## Best Possible Solution

Confirm the Discord active-target contract, then implement target selection inside the Discord plugin before shared default routing with tests for mention, reply-target, and default-owner suppression precedence.

## Reproduction Assessment

Yes, at source level: current main resolves Discord routing before active mention/reply target selection and compares those target signals only to the current handler botUserId. I did not run a live Discord multi-bot replay in this read-only review.

## Solution Assessment

Unclear until maintainers confirm the product contract. A generic mention-suppression tweak is not enough; Discord needs an approved configured bot/account/agent target map before default routing.
