## Summary

Keep open: current main and v2026.6.11 still resolve the Discord route before cross-bot mention/reply target selection, compare explicit and reply metadata only to the running bot ID, and lack a default-owner suppression state for another targeted bot.

## What This Changes

The issue requests deterministic Discord multi-bot routing precedence where explicit mentions beat reply targets, reply targets beat the default owner, and the default owner is suppressed when a targeted signal exists.

## Best Possible Solution

Confirm the Discord active-target contract, then implement target selection in the Discord plugin before default routing with explicit mentioned bot accounts first, referenced bot author second, and default owner only when no target signal exists.

## Reproduction Assessment

Yes, at source level: current main resolves Discord routing before mention/reply target selection and compares mention/reply metadata only to the current handler botUserId. I did not run a live Discord multi-bot replay.

## Solution Assessment

Unclear until maintainers confirm the product contract. Generic mention suppression alone is not enough because Discord needs a configured bot/account/agent target map before the default owner route is chosen.
