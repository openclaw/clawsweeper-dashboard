## Label Justifications

- `P1`: The issue affects live multi-bot Discord routing and can cause missing, duplicate, or wrong-agent responses in shared channel workflows.
- `impact:message-loss`: Targeted Discord messages can be consumed by the default owner or fail to reach the intended bot response path.

## Summary

Keep open: current main and v2026.6.11 still resolve Discord routing before cross-bot target selection, compare mention and reply metadata only to the running handler bot ID, and lack a default-owner suppression state for another targeted bot. The broader Discord active-target issue remains canonical, but this issue carries useful narrow acceptance criteria, so it should not be closed as a duplicate yet.

## What This Changes

Request deterministic Discord multi-bot routing where explicit bot mentions beat reply targets, reply targets beat the per-channel default owner, and targeted signals suppress default-owner responses.

## Best Possible Solution

Confirm the Discord active-target contract, then implement the precedence inside the Discord plugin using a configured bot-user-id to account/agent map before default routing, with tests for explicit mention, reply target, and untagged default-owner cases.

## Reproduction Assessment

Yes, at source level: current main resolves Discord routing before mention/reply target selection and compares mention/reply metadata only to the current handler botUserId. I did not run a live Discord multi-bot replay in this read-only review.

## Solution Assessment

Unclear until maintainers confirm the product contract. Generic mention suppression or the open implicit-reply policy PR alone is too narrow because Discord needs configured bot/account/agent target selection before default routing.
