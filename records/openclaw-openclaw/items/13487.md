## Summary

Keep open: current main and the latest release still resolve Discord routing before cross-bot mention or reply-target selection, so the requested mention > reply-target > default-owner suppression behavior remains missing. The open related PR only covers bot-authored reply-only activation and does not implement the full precedence contract.

## What This Changes

Request deterministic Discord multi-bot routing where explicit bot mentions win over reply targets, reply targets win over the default owner, and targeted messages suppress the default owner.

## Best Possible Solution

Confirm the Discord active-target policy, then implement target selection in the Discord plugin before shared default routing with a configured bot-user-id to account/agent map and focused suppression tests.

## Reproduction Assessment

Yes, source-reproducible: current main resolves the Discord route before target signals and compares mention/reply metadata only to the current handler botUserId. I did not run a live Discord multi-bot replay in this read-only review.

## Solution Assessment

Unclear until maintainers confirm the product contract. Generic mention suppression alone is too narrow because Discord needs a configured bot-user-id to account/agent map before default routing.
