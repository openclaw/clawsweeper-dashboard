## Summary

Current main still leaves Feishu docx remote-image reads unbounded after response headers, while this PR correctly uses the shared media deadline contract and provides convincing wiring and runtime proof. It should remain open for normal Feishu owner review and fresh-head checks.

## What This Changes

Routes Feishu docx markdown and upload-image URL reads through selected-account response-header and body-idle deadlines while preserving existing remote file-upload reads.

## Best Possible Solution

Keep the timeout policy Feishu-owned but implement it through the shared guarded media reader as proposed, refresh onto current main, rerun focused and required checks, then merge after Feishu owner review.

Yes, with high confidence from source: serve response headers and then stop yielding body bytes, invoke a Feishu docx markdown or upload-image URL path, and current main has no body-idle deadline. ## Solution Assessment

Yes. Reusing the guarded media reader's existing header and idle deadlines is narrower and more maintainable than adding another downloader or a complete-operation timeout, and preserving upload_file behavior avoids unrelated compatibility churn.
