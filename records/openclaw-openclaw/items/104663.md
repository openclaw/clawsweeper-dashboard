## Summary

This PR remains necessary because current main still performs Feishu docx image URL reads without response-header or body-idle deadlines. The proposed change is scoped, reuses the existing account timeout policy, and has convincing runtime proof with no actionable correctness finding; the behind branch and current-head check failures still need refresh and attribution before merge.

## What This Changes

Routes Feishu docx markdown-image and upload-image URL reads through response-header and body-idle deadlines derived from the selected account’s existing HTTP timeout while leaving remote file-upload reads unchanged.

## Best Possible Solution

Keep docx image URL reads bounded by selected-account response-header and body-idle deadlines, allow healthy transfers to continue while they make progress, and preserve the existing timeout-neutral remote file-upload path.
