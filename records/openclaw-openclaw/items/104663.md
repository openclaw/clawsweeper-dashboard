## Summary

Keep open because current main does not bound stalled Feishu docx image response bodies, this PR provides a unique and well-proven fix, and the related inbound-media PR addresses a separate runtime boundary.

## What This Changes

Routes Feishu docx markdown-image and upload-image URL reads through the selected account’s response-header and body-idle timeouts while leaving remote file-upload reads unchanged.

## Best Possible Solution

Land the Feishu-local timeout wiring after rebasing onto current main and confirming that both stalled-header and stalled-body failures degrade through existing docx error handling without changing the remote file-upload path.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at the production media-reader boundary: return HTTP headers and then leave the response body open; current main supplies no body-idle deadline from the Feishu docx path. A live Feishu tenant reproduction was not performed.

## Solution Assessment

Yes. Reusing the existing account timeout as separate header and body-idle deadlines in the Feishu-owned docx path is narrower than changing shared defaults and preserves healthy long-running downloads that continue making progress.
