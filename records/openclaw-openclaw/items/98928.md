## Summary

Keep open for normal maintainer review: this PR is the live candidate fix for the macOS config-health sidecar bug, the previous SwiftFormat blocker is fixed, and the latest relevant checks are green, but the deliberate storage/upgrade behavior change still deserves maintainer acceptance before merge.

## What This Changes

The PR changes the macOS config-health helper to keep health state in memory instead of rewriting the retired `logs/config-health.json` sidecar.

## Best Possible Solution

Merge this sidecar-removal shape after maintainer acceptance that durable config health belongs in SQLite, without reintroducing a JSON sidecar or a second fallback store.

## Reproduction Assessment

Yes, source-reproducible: current main writes `logs/config-health.json` from macOS config observation while core migrates that same file into SQLite and warns on conflicts. I did not run a live macOS GUI reproduction in this read-only review.

## Solution Assessment

Yes. Stopping the macOS app from recreating the retired JSON sidecar is the narrow owner-boundary fix because durable config health already belongs to `config_health_entries`; writing SQLite directly from the app would be a broader native/core coupling change.
