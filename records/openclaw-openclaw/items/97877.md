## Summary

Keep open: current main and v2026.6.11 still gate empty-error retries on cumulative `replayMetadata.hadPotentialSideEffects`, and the linked fixing PRs are still unmerged.

## What This Changes

The issue requests that transient empty provider errors retry after prior session tool use when the failed turn itself produced no side effects.

## Best Possible Solution

Land one focused fix that carries current-attempt replay metadata into the silent provider-error retry gate, includes `server_error` coverage, and preserves same-attempt side-effect fail-closed behavior.
