## Summary

Keep open: current main and v2026.6.11 still gate the silent provider-error retry on cumulative replay metadata, and the linked candidate fix PRs are still open rather than merged.

## What This Changes

The issue asks OpenClaw to retry transient empty provider-error turns after prior session tool calls without replaying same-attempt side effects.

## Best Possible Solution

Review and land one linked fix PR that separates current-attempt side-effect evidence from accumulated replay history for silent provider-error retries, while preserving same-attempt replay safety and covering classified server errors.

## Solution Assessment

Yes. The best fix is to split current-attempt side-effect evidence from accumulated replay safety for this retry path, then keep retries blocked when the failed attempt itself produced tools, delivery, approvals, spawns, async work, or terminal output.
