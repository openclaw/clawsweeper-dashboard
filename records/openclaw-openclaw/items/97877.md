## Summary

Keep open: current main and the latest release still gate empty provider-error retries on cumulative `replayMetadata.hadPotentialSideEffects`, so the reported silent terminal failure remains source-reproducible. Several open PRs already use closing syntax for this issue, so the issue should stay open until one canonical fix lands.

## What This Changes

The issue reports that the embedded agent's empty provider-error retry is blocked by session-accumulated replay side effects after any prior tool call, causing silent terminal failures on transient provider 5xxs.

## Best Possible Solution

Review and land one narrow candidate PR that adds a current-attempt replay-safety signal, retries clean empty provider errors after prior-session side effects, includes classified `server_error`, and keeps same-attempt side effects fail-closed.

## Reproduction Assessment

Yes at source level: current main still passes accumulated replay state into attempts and the silent-error retry rejects attempts whose replay metadata reports side effects. I did not run a live OpenRouter 5xx reproduction in this read-only review.

## Solution Assessment

Yes: splitting current-attempt side-effect evidence from cumulative replay state is the narrow maintainable fix. A broad retry that ignores same-attempt effects would be unsafe.
