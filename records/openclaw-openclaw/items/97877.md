## Summary

Keep open: current main and the latest release still use cumulative `replayMetadata.hadPotentialSideEffects` to block silent-error retry, and the issue has open closing PRs that should be reviewed rather than closing the report early.

## What This Changes

The issue reports that empty provider-error retries are blocked after prior session tool activity because retry gating uses session-accumulated side-effect metadata.

## Best Possible Solution

Land a narrow per-attempt replay-safety fix with regression coverage, preserving cumulative replay metadata for liveness/compaction while letting clean current-attempt transient provider errors retry.
