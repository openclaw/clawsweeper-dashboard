## Summary

Keep open: current main and the latest release still block the reported retry path, and open candidate PRs exist but none has merged as the canonical fix.

## What This Changes

The issue reports that transient empty provider 5xx turns do not retry after any prior tool call because the empty-error retry gate uses accumulated replay side-effect metadata.

## Best Possible Solution

Land one canonical fix that separates current-attempt side effects from accumulated replay history, includes classified server_error retry routing, proves same-attempt side effects still block retry, and closes this issue after merge.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: current main passes accumulated replay state into attempts and the silent-error retry helper rejects attempts whose resolved replay metadata has prior side effects. I did not run a live OpenRouter 5xx reproduction in this read-only review.

## Solution Assessment

Yes: the best fix is a narrow current-attempt replay metadata boundary plus server_error routing, while preserving same-attempt side-effect blocking. Current main and the latest release do not yet implement that.
