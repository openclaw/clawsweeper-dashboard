## Summary

Keep open: current main still lacks a supported cross-channel acknowledgement text contract that sends before agent processing and then continues normal dispatch. Existing reactions, status reactions, typing indicators, preview streaming, and terminal `before_dispatch` behavior only partially address the visible-latency problem.

## What This Changes

Request a supported pre-processing text acknowledgement, such as `messages.ackText`, that sends before agent work and then lets normal dispatch continue across messaging channels.

## Best Possible Solution

Choose a maintainer-approved, default-off acknowledgement-text or send-and-continue hook contract, then update config types, strict schema/help, public docs, channel docs, and focused regression coverage for the affected messaging surfaces.

## Reproduction Assessment

Yes, at source level: current main and `v2026.6.11` expose reactions, typing indicators, preview drafts, terminal hooks, and final replies, but no supported send-and-continue acknowledgement-text path. No live transport run is needed to prove the requested capability is absent.

## Solution Assessment

Unclear until maintainers choose the boundary; messages.ackText is plausible, but a non-terminal plugin or channel hook may be the cleaner long-term seam.
