## Summary

Keep open: current main and v2026.6.11 still lack a supported cross-channel pre-processing text acknowledgement that sends before agent work and then continues normal dispatch. Existing ack reactions, status reactions, typing indicators, progress drafts, and the terminal before_dispatch hook do not satisfy the requested send-and-continue text contract.

## What This Changes

Request adds configurable acknowledgement text before agent processing, with scope behavior similar to ackReaction, for messaging channels such as Slack, WhatsApp, WebChat, and Feishu.

## Best Possible Solution

Choose a maintainer-approved, default-off acknowledgement-text or non-terminal send-and-continue hook contract, then align config types, strict schema/help, public docs, channel docs, and focused cross-channel regression coverage.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 expose reactions, typing indicators, progress drafts, terminal hooks, and final replies, but no supported send-and-continue acknowledgement-text path. No live transport run is needed to prove the requested contract is absent.

## Solution Assessment

Unclear until maintainers choose the product/API boundary. A messages.ackText-style setting is plausible, but a non-terminal plugin or channel hook may be the cleaner long-term seam for cross-channel and channel-specific behavior.
