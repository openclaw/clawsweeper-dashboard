## Summary

Keep open: current main and v2026.6.11 still do not provide a supported cross-channel text acknowledgement that sends before agent processing and then continues normal dispatch. Existing reactions, status reactions, typing indicators, and terminal pre-dispatch hooks are adjacent but do not satisfy the requested acknowledgement-text contract.

## What This Changes

Request a configurable pre-processing text acknowledgement, similar to ack reactions, for Slack, WhatsApp, WebChat, Feishu, and other messaging channels.

## Best Possible Solution

Choose a default-off, maintainer-approved acknowledgement-text contract or non-terminal plugin/channel hook, then align config types, strict schema/help, docs, and regression plus live channel proof.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: current main and v2026.6.11 expose reaction/status/typing cues and terminal hooks but no accepted messages.ackText config or send-and-continue text hook.

## Solution Assessment

Unclear until maintainers choose the API boundary; messages.ackText is plausible, but a non-terminal plugin/channel hook may be cleaner to avoid duplicating channel-specific placeholder lifecycles.
