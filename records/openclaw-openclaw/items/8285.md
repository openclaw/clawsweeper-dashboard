## Summary

Keep open: current main still has reaction, status, and typing signals, but no supported cross-channel pre-processing acknowledgement text that sends before agent work and then continues normal dispatch. The issue is concrete and source-reproducible, but the implementation shape is a maintainer product/API decision across config, channel delivery, and plugin hooks rather than a safe automatic cleanup close.

## What This Changes

Issue #8285 requests a configurable cross-channel acknowledgement text message, such as `messages.ackText`, sent before agent processing begins.

## Best Possible Solution

Define one maintainer-approved, default-off acknowledgement contract, either `messages.ackText` with scoped per-channel/account overrides or a documented non-terminal pre-processing hook that can send interim text and then continue normal dispatch.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: `messages.ackText` is not accepted by the strict config schema, and existing interim surfaces are reactions, typing/status signals, or terminal `before_dispatch` handling rather than send-and-continue text.

## Solution Assessment

Unclear until maintainers choose the boundary. A cross-channel `messages.ackText` config is plausible, but a non-terminal plugin/channel hook may be cleaner depending on plugin API ownership and per-channel delivery constraints.
