## Summary

Keep open: current main and v2026.6.11 still lack a supported cross-channel text acknowledgement that sends before agent processing and then continues normal dispatch; related items are narrower channel-specific presence, reaction, or placeholder work.

## What This Changes

The issue requests a configurable pre-processing text acknowledgement for messaging channels, similar to ack reactions but delivered as a visible message.

## Best Possible Solution

Define one default-off send-and-continue acknowledgement lifecycle contract with config, docs, and focused channel tests, or explicitly route each channel-specific placeholder through its narrower issue.

Options:

- **Add Global messages.ackText:** Implement the requested global config shape directly and make supported channels interpret it consistently.
- **Keep Placeholders Channel-Specific:** Let Slack, Telegram, Discord, Feishu, and other plugins implement visible placeholders independently without a cross-channel core contract.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 expose reactions, status reactions, typing indicators, and terminal hooks, but no supported send-and-continue acknowledgement-text path. A live transport run is not needed to prove the requested capability is absent.

## Solution Assessment

Unclear until maintainers choose the product/API boundary. messages.ackText is plausible, but a generic non-terminal plugin/channel hook may be the cleaner long-term seam for cross-channel and channel-specific behavior.
