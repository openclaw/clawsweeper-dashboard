## Summary

Keep open: current main and v2026.6.11 still provide reactions, typing, and generated-content previews, but no supported cross-channel text acknowledgment that is sent before model processing and then continues the normal turn. The narrower Telegram, Slack, and Discord items do not replace this broader product/API decision.

## What This Changes

Add a supported automatic text acknowledgment before agent processing, scoped across messaging channels similarly to acknowledgment reactions.

## Best Possible Solution

Define one typed early-progress lifecycle with channel capability adapters for create, edit, delete, and fallback behavior; then expose carefully scoped global and per-channel/account settings only if maintainers want fixed acknowledgment text, reusing existing status and draft-delivery ownership rather than adding a parallel sender.

- **Keep feedback channel-owned:** Decline a global text acknowledgment and continue improving reactions, typing, and draft previews independently in each channel.

## Reproduction Assessment

Yes, at source level. Current main has no text acknowledgment config, the closest pre-dispatch hook terminates normal processing when it sends text, and generated-content previews do not begin before generation.

## Solution Assessment

No, the proposed `ackText` field alone is not yet the best established solution. A shared typed lifecycle with channel capability handling is safer than introducing an independent sender that could diverge from previews, final delivery, and cleanup.
