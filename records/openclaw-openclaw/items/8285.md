## Summary

Keep open: current main still lacks a supported cross-channel acknowledgement text message that sends before agent processing and then continues normal dispatch.

## What This Changes

Request a configurable pre-processing text acknowledgement, similar to ack reactions, for messaging channels such as Slack, WhatsApp, webchat, and Feishu.

## Best Possible Solution

Define one default-off send-and-continue acknowledgement lifecycle contract with config, docs, and focused channel tests, or explicitly route each channel-specific placeholder through its narrower issue.

Options:

- **Add global messages.ackText:** Implement the requested global config shape directly, accepting a new core config surface that channels must interpret consistently.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 expose reactions, status reactions, typing indicators, and terminal hooks, but no supported send-and-continue acknowledgement-text path. A live transport run is not needed to prove the requested capability is absent.

## Solution Assessment

Unclear until maintainers choose the product/API boundary. messages.ackText is plausible, but a generic non-terminal plugin/channel hook may be the cleaner long-term seam for cross-channel and channel-specific behavior.
