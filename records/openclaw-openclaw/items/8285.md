## Summary

Keep open: current main and v2026.6.11 still lack a supported cross-channel text acknowledgement that sends before agent processing and then continues normal dispatch. Existing ack reactions, status reactions, typing indicators, progress drafts, and terminal hooks overlap the UX problem but do not provide the requested `messages.ackText`-style contract.

## What This Changes

Requested configurable text acknowledgement that sends before agent processing and then continues normal dispatch across messaging channels.

## Best Possible Solution

Choose a maintainer-approved, default-off acknowledgement-text or send-and-continue hook contract, then update config types, strict schema/help, public docs, channel docs, and focused regression coverage with live proof for affected channels.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 expose reactions, typing indicators, progress drafts, terminal hooks, and final replies, but no supported send-and-continue acknowledgement-text path. No live transport run is needed to prove the requested contract is absent.

## Solution Assessment

Unclear until maintainers choose the product/API boundary. `messages.ackText` is plausible, but a non-terminal plugin or channel hook may be the cleaner long-term seam for cross-channel and channel-specific behavior.
