## Summary

Keep this PR open, but do not merge it as-is: the new SSRF guard is only selected when no ClawHub token is configured, leaving token-configured installs on the pre-existing off-origin request path. The tokenless loopback proof and retry repair are useful, but they do not cover that remaining security-relevant branch.

## What This Changes

The PR sends off-origin ClawHub skill archive downloads through the shared SSRF guard, preserves bounded retries for transient failures, and adds regression coverage for the guarded path.

## System Context

ClawHub resolves a skill archive URL from registry metadata, and the skill installer downloads, validates, and writes that archive before installation. The changed code decides whether that registry-controlled URL uses the authenticated registry request path or the guarded external-download path.

## Architecture Diagram

flowchart LR
  Registry[ClawHub registry metadata] --> Resolver[Skill archive resolver]
  Resolver --> Origin{Archive matches registry origin?}
  Origin -->|yes| AuthFetch[Authenticated registry download]
  Origin -->|no| Guard[SSRF-protected external download]
  Guard --> Retry[Bounded transient retry]
  AuthFetch --> Archive[Archive validation and write]
  Retry --> Archive
  Archive --> Install[Installed skill]

## Best Possible Solution

Classify archive trust solely by origin: route every off-registry-origin URL through the SSRF guard, preserve authentication only for the configured registry origin, and add explicit token-configured regression coverage before merge.
