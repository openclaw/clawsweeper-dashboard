## Summary

Keep this PR open for maintainer security review. The current branch closes the demonstrated registry-controlled SSRF and token-forwarding path, preserves the prior bounded retry behavior, and has credible real-runtime proof; the remaining question is whether the intentional fail-closed policy for self-hosted off-origin private archive hosts is acceptable.

## What This Changes

Routes ClawHub registry-supplied skill archive URLs outside the configured registry origin through OpenClaw’s shared SSRF guard, preserves transient-read retries, and adds regression coverage for internal targets and token handling.

## System Context

The ClawHub skill installer resolves a skill through the registry and then downloads its archive before installing it locally. This change sits at the boundary between registry-controlled archive URLs and OpenClaw’s network client, determining whether a request is authenticated, guarded, retried, and written to the temporary archive.

## Best Possible Solution

Confirm the origin-based trust policy, then land a rebased version that keeps same-origin authenticated downloads intact while rejecting all registry-selected off-origin private or special-use targets.
