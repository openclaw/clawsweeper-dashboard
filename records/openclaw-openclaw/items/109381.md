## Summary

Keep this PR open, but it still needs changes before merge: the previously reported transient-status retry defect remains on the exact head because a dripping HTTP 5xx body can consume the deadline before retry classification sees the status.

## What This Changes

## Best Possible Solution

Classify 500, 502, 503, and 504 immediately after headers and enter the retry path without awaiting their bodies, while retaining bounded error-detail reads for non-retryable statuses and adding a dripping-503 regression that proves a second request occurs.
