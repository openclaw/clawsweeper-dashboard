## Summary

This remains a useful, narrowly scoped fix with credible loopback proof, but it deliberately changes the generated-music timeout from a header/request limit into an operation-wide body deadline. A maintainer should confirm that existing slow-but-progressing audio downloads are intended to fail at that configured budget before merge.

## What This Changes

The PR adds a shared wall-clock deadline across generated-music response headers, status handling, and body reads; restores retry handling for transient HTTP statuses; and adds loopback regressions.
