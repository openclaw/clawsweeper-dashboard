## Summary

Keep this PR open for maintainer review. The latest head appears to fix the continuously dripping response-body hang while preserving transient HTTP retries, and all previously reported correctness findings are resolved; the remaining question is whether the configured timeout should intentionally become one total wall-clock budget across fetch, retries, diagnostics, and successful body reads.

## What This Changes

The PR gives generated-music asset downloads a shared wall-clock deadline, restores retry handling for transient HTTP statuses, cancels retryable error bodies, and adds loopback regression coverage.

## Best Possible Solution

Generated-music downloads should use one bounded total operation budget, preserve transient-status retries, cancel retryable error bodies promptly, and retain bounded diagnostic detail for terminal HTTP errors.
