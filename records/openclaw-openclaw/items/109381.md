## Summary

Keep open: the wall-clock deadline is useful and well proven, but the latest patch still bypasses the existing transient HTTP-status retry boundary, so a temporary provider failure can fail immediately instead of retrying.

## What This Changes

Adds one wall-clock deadline across generated-music response headers, non-2xx error-detail reads, and successful asset-body reads, with slow-drip regression coverage.

## Best Possible Solution

Keep the single wall-clock deadline, but execute bounded non-2xx response validation inside each retry attempt so retryable statuses retain the shared download-retry contract while error bodies remain deadline-bound.
