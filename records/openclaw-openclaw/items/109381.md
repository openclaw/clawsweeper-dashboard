## Summary

Keep open: the hang is credible and the deadline approach is useful, but the patch bypasses the purpose-built download error path and therefore removes transient HTTP-status retries; contributor proof also remains test-harness-only.

## What This Changes

The PR adds one wall-clock deadline across generated-music response headers, error-detail reads, and successful asset-body reads, with loopback slow-drip regression tests.

## Best Possible Solution

Teach the shared download helper to bound error-detail reads under the operation deadline while retaining its retry classification, then use the same remaining deadline for the successful body and cover both slow-drip and retryable-status cases.

## Reproduction Assessment

Yes at source level: a loopback server can continuously drip body chunks through the production download helper, preventing the existing chunk-idle timer from firing. An independent current-main runtime execution was not established, so this is source-reproducible rather than reproduced.

## Solution Assessment

No in its current shape. A shared bounded error-reader or download-helper extension is narrower and safer because it can enforce the wall-clock deadline without discarding established transient HTTP retry behavior.
