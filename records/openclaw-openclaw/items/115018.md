## Summary

This PR has a coherent, narrowly scoped fix for stalled Slack read operations: it gives dedicated read clients a per-attempt timeout while retaining unbounded shared and write-capable clients to avoid ambiguous mutation outcomes. The available patch, discussion, and runtime proof support keeping it open for normal maintainer review rather than closing or replacing it; the related older PR is a partial predecessor, not a safe canonical replacement because it is currently conflicted. 

Likely related people: zw-xysk is the original contributor on the related timeout approach (medium confidence); steipete is the current implementation author and co-author credit preserves that contribution (medium confidence).

## What This Changes

The PR introduces a dedicated Slack read-only Web API client with a default 30-second request-attempt deadline and routes probes, scope discovery, channel classification, and unknown-send reconciliation through it without changing shared or write client defaults.

## System Context

The bundled Slack channel plugin uses Web API clients for both read-only discovery/probe work and message-affecting operations. This change separates those call paths so stalled reads release their callers while delivery, uploads, and Bolt-managed mutations retain their existing timeout behavior.
