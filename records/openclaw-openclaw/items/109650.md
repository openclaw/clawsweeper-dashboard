## Summary

This fresh, well-scoped ergonomics request remains necessary: current documentation explicitly defines `status`, proposal `version`, and proposal `date` as lifecycle-managed fields, while the documented create/update/revise result contract does not describe a warning when supplied values are replaced. ([docs.openclaw.ai](https://docs.openclaw.ai/tools/skill-workshop))

## What This Changes

Add a non-blocking warning when Skill Workshop create, update, or revise input contains lifecycle-managed top-level frontmatter keys.

## Best Possible Solution

Detect only top-level lifecycle-managed keys at the shared Skill Workshop service boundary, preserve existing replacement semantics, and return structured warnings listing the conflicting keys and effective proposal values across create, update, and revise.
