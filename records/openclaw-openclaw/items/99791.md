## Summary

## What This Changes

The PR resolves default video models during media-understanding auto-selection for active and key-selected providers and adds video runner coverage for default-model and no-default skip behavior.

## Best Possible Solution

Land the resolver-boundary fix once maintainers accept that auto-selected video providers must publish `defaultModels.video` or be configured with an explicit model; otherwise add a documented compatibility path before merge.

## Reproduction Assessment

Yes. Source inspection of current main shows video auto-selection can build a provider entry with `model` unset, and `runProviderEntry` passes that unset value into `describeVideo`.

## Solution Assessment

Yes, with maintainer acceptance. Resolving default video models at the resolver boundary is narrower than adding provider-specific execution fallbacks, but skipping no-default providers is a compatibility-sensitive contract choice.
