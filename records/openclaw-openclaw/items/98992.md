Keep open: this PR directly addresses the canonical diagnostics gap by emitting plugin runtime LLM usage and carrying plugin attribution into OTel/Prometheus. I found no blocking code findings, but the exported diagnostics label shape change needs maintainer acceptance before one canonical PR lands.

## What This Changes

Adds `pluginId` to `model.usage`, emits a trusted usage diagnostic after successful plugin runtime LLM completions, and updates OTel/Prometheus exporters, docs, and tests for plugin attribution.

## Best Possible Solution

Land one canonical implementation that emits usage at the plugin runtime LLM boundary and intentionally accepts the low-cardinality plugin attribution shape in diagnostics exports.

## Reproduction Assessment

Yes, at source level. Current main computes and returns plugin `runtime.llm.complete` usage without emitting `model.usage`, while diagnostics exporters only observe `model.usage` events.

## Solution Assessment

Yes. Emitting once at the plugin runtime LLM completion boundary is the narrowest maintainable fix because that is where normalized usage, cost, trusted plugin identity, and diagnostics config are available.
