## Summary

Keep open: current main and the latest release still implement Gateway auth limiting as per-scope/per-client-IP, and the strict config schema has no IP-agnostic/global mode. The request is valid security hardening, but it adds a new auth config surface with a security-versus-all-client-lockout tradeoff, so it needs maintainer/security direction before implementation.

## What This Changes

The issue requests a `gateway.auth.rateLimit` option that aggregates failed Gateway auth attempts across client IPs for public-exposed deployments.

## Best Possible Solution

Have Gateway/security maintainers decide the policy, then if accepted add an opt-in IP-agnostic rate-limit mode with explicit docs, schema/type support, focused per-IP and global-mode tests, and warnings about all-client lockout behavior while preserving the current per-IP default.
