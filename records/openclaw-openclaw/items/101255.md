## Summary

Keep open: current main and the latest release still key Gateway auth failures by scope plus client IP, and no `gateway.auth.rateLimit` global/keying option exists. The request is valid security hardening, but it expands a strict auth config surface and needs maintainer security/product direction before implementation.

## What This Changes

Request an opt-in `gateway.auth.rateLimit` mode that counts failed Gateway auth attempts across all client IPs for public-exposed deployments.

## Best Possible Solution

If maintainers accept the direction, add an explicit opt-in rate-limit keying mode with default per-IP behavior, schema/types/docs/audit guidance, and focused HTTP plus WebSocket tests; otherwise document that public deployments should use identity-aware proxying, strong secrets, and existing per-IP throttling.
