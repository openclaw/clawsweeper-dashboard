## Summary

Keep open: current main and the latest release still key Gateway auth rate limiting per auth scope and client IP, and the strict config schema has no IP-agnostic mode. The linked open PR https://github.com/openclaw/openclaw/pull/101287 is now the candidate fix path, but the new global lockout mode needs Gateway/security product review before this issue can close.

## What This Changes

Request an opt-in Gateway auth rate-limit mode that aggregates failed attempts across all client IPs for public-exposed password/token deployments.

## Best Possible Solution

Have Gateway/security maintainers decide the policy, then if accepted land a default-off IP-agnostic limiter mode with explicit docs, schema/type support, regression tests, and warnings about all-client lockout behavior.
