## Summary

Keep open: current main still implements gateway auth limiting as per-scope/per-client-IP, and there is no `gateway.auth.rateLimit` global mode in the config type or schema. The request is valid security hardening, but it adds a new compatibility-sensitive auth config knob and needs maintainer product/security direction before implementation.

## What This Changes

The issue requests an opt-in global gateway auth rate-limit mode so failed password/token attempts can be counted across client IPs for public-exposed deployments.

## Best Possible Solution

If maintainers accept the direction, add an explicit opt-in rate-limit keying mode with default per-IP behavior, schema/types/docs/audit guidance, and focused HTTP plus WebSocket tests; otherwise document that public deployments should use identity-aware proxying, strong secrets, and existing per-IP throttling.
