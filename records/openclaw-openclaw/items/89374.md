## Summary

Keep open: current main and v2026.6.11 fix the narrower Codex automatic-compaction ownership skip, but the timeout-compaction path still treats successful compaction as enough to retry and can fall through after repeated timeouts without a safe affected-session reset or rollover policy.

## What This Changes

The issue asks OpenClaw to make Codex timeout-compaction recovery safe when compaction reports success but the affected channel session remains too large or unrecoverable.

## Best Possible Solution

Define a guarded automatic reset or rollover policy for unrecoverable Codex channel sessions after repeated timeout compactions, then prove it with focused runner tests and a live high-context channel flow.
