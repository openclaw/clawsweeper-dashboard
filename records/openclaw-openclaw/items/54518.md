## Summary

Keep open: current main still treats the agent workspace as the default working directory/policy input, not a universal hard filesystem boundary. The existing opt-in `tools.fs.workspaceOnly` and sandbox settings are relevant workarounds, but the default host read/write/edit path can still access outside the intended agent workspace, and the related PRs/issues are open, conflicting, or narrower than this report.

## What This Changes

Requests hard per-agent workspace containment so agents cannot access or modify files outside their own workspace.

## Best Possible Solution

Adopt a maintainer-approved filesystem isolation policy that gives non-main or multi-agent setups a hard per-agent workspace boundary without silently breaking trusted-host workflows.
