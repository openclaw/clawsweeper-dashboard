## Summary

Keep open: current main and v2026.6.11 still make filesystem workspace confinement optional, while the reported workflow needs a security/default decision rather than cleanup; related PRs are partial or not yet merged.

## What This Changes

The issue asks OpenClaw to prevent agents from reading or modifying files outside their own workspace, especially in multi-agent skill workflows.

## Best Possible Solution

The desired end state is a maintainer-approved workspace confinement policy with upgrade-safe defaults, docs, doctor or migration guidance if defaults change, and tests covering file tools, prompt media, apply_patch, and exec boundaries.

## Reproduction Assessment

Yes from source: with `tools.fs.workspaceOnly` unset or false, current host read/write/edit paths are built without workspace guards. I did not run a live Feishu/minimax reproduction in this read-only review.

## Solution Assessment

Unclear as an implementation path: stronger default confinement is aligned with the security goal, but simply flipping `tools.fs.workspaceOnly` would be compatibility-sensitive and incomplete for exec/sandbox boundaries.
