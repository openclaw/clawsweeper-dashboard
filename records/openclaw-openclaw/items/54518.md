## Summary

Keep open: current main and v2026.6.11 still make per-agent workspace confinement opt-in for file tools, while the broader default/exec/sandbox boundary remains a security-sensitive product decision with only partial open PR coverage.

## What This Changes

The issue asks for agents to be prevented from reading or modifying files outside their own configured workspace, similar to a directory-scoped filesystem server.

## Best Possible Solution

Keep this as the concrete workspace-confinement tracker until maintainers choose and land the desired default/tool-policy/sandbox boundary with upgrade-safe docs and regression coverage.

## Solution Assessment

Unclear as an implementation path. Existing `tools.fs.workspaceOnly` helps for file tools, but making per-agent confinement the default or extending it across exec/sandbox behavior needs maintainer security and compatibility decisions.
