## Summary

Keep open: current main and the latest release still treat an agent workspace as the default working directory, not a hard filesystem boundary. The available related work is partial or still open, so this needs a maintainer security/product decision rather than cleanup closure.

## What This Changes

Request to prevent agents from reading or modifying files outside their own per-agent workspace by default.

## Best Possible Solution

Define a maintainer-approved workspace confinement policy, then land the chosen default/upgrade path with docs and regression coverage across file tools, exec/process, sandboxing, and per-agent overrides.

- **Keep opt-in only:** Document the existing sandbox and `tools.fs.workspaceOnly` knobs as the supported answer and close the broader default-change direction separately.
