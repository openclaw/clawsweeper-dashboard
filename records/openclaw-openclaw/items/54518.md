## Summary

Keep open: current main and v2026.6.11 still treat the agent workspace as the default cwd, not a hard filesystem boundary. Host read/write/edit can still touch paths outside the workspace unless operators opt into `tools.fs.workspaceOnly` or sandboxing, and the related PRs/issues are partial, conflicting, closed unmerged, or broader architecture trackers rather than a safe replacement.

## What This Changes

The issue asks for per-agent filesystem containment so agents cannot read or modify files outside their assigned workspace.

## Best Possible Solution

Keep this as the concrete workspace-confinement tracker until maintainers choose the default confinement, upgrade path, and exec/sandbox scope.
