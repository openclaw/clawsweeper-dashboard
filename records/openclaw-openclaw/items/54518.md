## Summary

Keep open: current main and v2026.6.11 still treat the agent workspace as a default working directory, not a hard filesystem boundary, unless operators enable `tools.fs.workspaceOnly` or sandboxing. The open related PRs cover useful subsets but are unmerged and do not settle the broader default, exec, and compatibility decision.

## What This Changes

Require agents to be unable to read or modify files outside their own workspace through an enforced filesystem boundary.

## Best Possible Solution

Keep this as the concrete workspace-confinement tracker while maintainers choose the default confinement policy across file tools, exec/native runtime surfaces, sandboxing, migration, docs, and regression proof.
