## Summary

Keep open: current main and v2026.6.11 still allow host filesystem tools to read/write/edit outside an agent workspace unless `tools.fs.workspaceOnly` or sandboxing is enabled, and the related open PRs only cover partial filesystem hardening rather than the full per-agent workspace boundary.

## What This Changes

Request that agents be unable to access or modify files outside their assigned workspace after a Feishu PM agent modified another workspace's skill files.

## Best Possible Solution

Keep this as the concrete workspace-confinement tracker while maintainers define the default filesystem, sandbox, and exec boundary, then land the chosen policy with migration guidance, docs, and regression coverage.
