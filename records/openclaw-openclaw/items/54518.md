## Summary

Keep open: current main and the latest release still document and implement the agent workspace as a default cwd, not a hard boundary. The existing opt-in controls help, but default host read/write/edit access can still touch paths outside the workspace, and the related PRs are partial or not viable replacements.

## What This Changes

The issue asks for agents to be prevented from reading or modifying files outside their own workspace.

## Best Possible Solution

Keep this as the concrete workspace-confinement tracker until maintainers define the default confinement policy across file tools, exec/process access, sandboxing, docs, and upgrade compatibility.
