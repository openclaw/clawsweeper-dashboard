The merged prepared-runtime lifecycle work in https://github.com/openclaw/openclaw/pull/111173 and configless reuse follow-up in https://github.com/openclaw/openclaw/pull/111423 are relevant provenance, but neither is evidence that this distinct activation path is already fixed.

## What This Changes

Fix configless Control UI Model Setup activation so a provider-env-derived prepared model runtime can be committed and setup completes instead of redirecting admins back to first-run setup.

## Best Possible Solution

Add a narrow lifecycle fix that lets configless provider-derived owners satisfy Model Setup activation’s commit contract, with regression coverage for the Control UI activation path and separate coverage that configured-owner replacement remains correct.
