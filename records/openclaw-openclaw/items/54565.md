## Summary

Keep open. Current main and v2026.6.11 still do not support `channels.whatsapp.groups.<jid>.debounceMs`; the source gap is clear, but adding this public config surface needs maintainer direction on precedence and WhatsApp-only versus cross-channel scope.

## What This Changes

The issue requests per-group WhatsApp debounce configuration so one noisy group can batch rapid messages without changing debounce behavior for every WhatsApp group or account.

## Best Possible Solution

Approve or reject a narrow WhatsApp-owned group-level debounce override; if approved, wire schema/types/docs and a per-item runtime resolver through the existing debouncer with focused regression coverage.

## Reproduction Assessment

Yes, at source level. Current schema and types reject `channels.whatsapp.groups.<jid>.debounceMs`, and the runtime resolves a single WhatsApp inbound debounce from account, channel, or global inbound config rather than per group.

## Solution Assessment

Unclear until maintainers choose the config contract. The narrowest maintainable path appears to be a WhatsApp-owned group override that reuses the existing debouncer seam, not a broad cross-channel rollout in one change.
