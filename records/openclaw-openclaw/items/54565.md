## Summary

Keep open. Current main and v2026.6.11 still lack WhatsApp group-level `debounceMs`; the gap is source-reproducible, but the requested public config surface and media-batching semantics still need maintainer direction.

## What This Changes

The issue requests a per-group WhatsApp `debounceMs` override, with possible cross-channel equivalents, so one busy group can batch related messages without slowing every group on the account.

## Best Possible Solution

Approve a narrow WhatsApp-owned group-level debounce override only after maintainers choose precedence and media scope, and keep broader media/timestamp coalescing in the existing adjacent WhatsApp batching trackers.

## Reproduction Assessment

Yes, at source level. Current schema and types reject `channels.whatsapp.groups.<jid>.debounceMs`, and the runtime resolves WhatsApp debounce only from account, default-account, channel, and global inbound scopes.

## Solution Assessment

Unclear until maintainers choose the config contract. A group-level override is plausible, but config-only debounce may not solve the image burst use case because current media messages intentionally bypass debounce.
