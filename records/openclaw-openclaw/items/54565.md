## Summary

Keep open. Current main and v2026.6.11 still lack WhatsApp group-level `debounceMs`; the gap is source-reproducible, but adding this public config key needs maintainer direction on scope and precedence rather than conservative cleanup closure.

## What This Changes

Request to allow per-group WhatsApp `debounceMs` so selected groups can batch rapid messages without raising debounce for the whole channel or account.

## Best Possible Solution

Approve a narrow WhatsApp-owned group-level debounce override only if maintainers want the new config contract, then wire it through the existing per-item debouncer seam with schema, docs, and focused regression tests.

## Reproduction Assessment

Yes, at source level. Current schema and types reject `channels.whatsapp.groups.<jid>.debounceMs`, and the runtime resolves WhatsApp debounce only from account, default-account, channel, and global inbound scopes.

## Solution Assessment

Unclear until maintainers choose the config contract. The narrowest maintainable path appears to be a WhatsApp-only group override that reuses `createInboundDebouncer.resolveDebounceMs`, not a broad cross-channel rollout in one change.
