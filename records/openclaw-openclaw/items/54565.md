## Summary

Keep open. Current main and v2026.6.11 still do not support `debounceMs` inside WhatsApp `groups.<jid>` entries; the gap is source-reproducible, but adding the new public group-level config key needs maintainer direction on precedence and WhatsApp-only versus cross-channel scope.

## What This Changes

Request adding per-group `debounceMs` overrides for WhatsApp group config so one group can batch rapid multi-message context without changing the account or channel debounce window.

## Best Possible Solution

Approve a narrow WhatsApp-owned group-level debounce override only if maintainers want the new config contract, then wire it through the existing debouncer seam with schema, docs, and focused regression tests.

## Reproduction Assessment

Yes, at source level. Current main rejects `channels.whatsapp.groups.<jid>.debounceMs` through the strict schema/type surface and resolves WhatsApp debounce only from account, default-account, channel, and global inbound scopes; I did not run a live WhatsApp scenario.

## Solution Assessment

Unclear until maintainers choose the config contract. The narrowest maintainable path appears to be a WhatsApp-owned per-group override that reuses the existing debouncer seam, not a broad cross-channel rollout in one change.
