## Summary

Keep open. Current main and the latest release still do not support `debounceMs` inside WhatsApp per-group config, and adding that key is a new public config contract that needs maintainer direction on precedence and scope.

## What This Changes

Request to allow group-scoped inbound debounce windows for WhatsApp, with possible later extension to other channel group configs.

## Best Possible Solution

Approve a narrow WhatsApp-owned group-level debounce override only if maintainers want the new config contract, then wire it through the existing debouncer seam with schema, docs, and focused regression coverage.

## Reproduction Assessment

Yes, at source level. Current main’s strict WhatsApp group schema and `WhatsAppGroupConfig` omit `debounceMs`, and the runtime only resolves debounce from account, default-account, channel, and global inbound scopes.

## Solution Assessment

Unclear until maintainers choose the config contract. The narrowest maintainable path appears to be a WhatsApp-owned per-group override that reuses the existing debouncer seam, not a broad cross-channel rollout in one change.
