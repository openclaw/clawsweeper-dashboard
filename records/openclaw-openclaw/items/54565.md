## Summary

Keep open. Current main and v2026.6.11 still lack the requested WhatsApp group-level `debounceMs`; the source gap is clear, but adding this public config key needs maintainer direction on scope and precedence before a fix PR should be queued.

## What This Changes

Request support for `channels.whatsapp.groups.<jid>.debounceMs`, with a possible extension to similar per-group channel config surfaces.

## Best Possible Solution

Approve a narrow WhatsApp-owned group-level debounce override only if maintainers want the new config contract, then wire it through the existing per-item debouncer seam with schema, docs, and regression coverage.

## Reproduction Assessment

Yes, at source level: current schema and types reject `channels.whatsapp.groups.<jid>.debounceMs`, and the runtime resolves WhatsApp debounce only from account, default-account, channel, and global inbound scopes. I did not run a live WhatsApp repro because the gap is a missing config/runtime capability.

## Solution Assessment

Unclear until maintainers choose the config contract. A narrow WhatsApp-owned per-group override is plausible, but the precedence rules and whether to generalize beyond WhatsApp need product review first.
