## Summary

Keep open. Current main and the latest release still lack WhatsApp group-level `debounceMs`; the gap is source-reproducible, but adding this public config key needs maintainer direction on precedence and WhatsApp-only versus cross-channel scope.

## What This Changes

The issue requests a per-group `debounceMs` override for WhatsApp group config, with possible cross-channel equivalents, so one noisy group can batch rapid messages without slowing every chat.

## Best Possible Solution

Approve a narrow WhatsApp-owned group-level debounce override only if maintainers want the new config contract, then wire it through the existing per-item debouncer seam with schema, docs, and regression coverage; leave cross-channel generalization to a separate design if needed.

## Reproduction Assessment

Yes, at source level. Current main rejects `channels.whatsapp.groups.<jid>.debounceMs` through the strict group schema and resolves WhatsApp debounce only from account, default-account, channel, and global inbound scopes; I did not run a live WhatsApp reproduction.

## Solution Assessment

Unclear until maintainers choose the config contract. The narrowest maintainable path appears to be a WhatsApp-owned per-group override reusing the existing debouncer seam, not a broad cross-channel rollout in one change.
