## Summary

The prior P1 blocker remains on the latest head: the schema is now Codex-only, but generic `message_tool_only` prompt surfaces still require `final`, so sibling runtimes can be instructed to send an unavailable argument. The Telegram evidence convincingly proves the premature-release bug and intended progress-then-final behavior, but merge should wait for the narrow scoping repair and maintainer confirmation of the permanent completion contract.

## What This Changes

The PR adds a Codex-only `final` field to message sends, keeps omitted or false progress sends non-terminal, and releases `message_tool_only` turns only after confirmed current-source delivery with `final: true`.

## Best Possible Solution

Make explicit final delivery one coherent Codex-owned capability controlling schema projection, generic prompt prelude, system-prompt wording, runtime termination, and positive and negative sibling-runtime coverage; then land it only if maintainers choose that contract over the prompt-only alternative.
