## Summary

Keep open: current main and v2026.6.11 do not implement the modular-dashboard binding substrate or the requested stream, command, and computed binding kinds. The issue remains a security-sensitive child of the open Wave 2+ dashboard roadmap, and periodic command bindings need maintainer direction before implementation.

## What This Changes

Request new modular-dashboard data-binding kinds for push streams, allowlisted periodic commands, and values computed from other bindings.

## Best Possible Solution

Settle the Wave 1 dashboard substrate first, then design stream and computed bindings separately from command execution unless maintainers explicitly approve a command-binding security model.

## Maintainer Decision

Question: Should the dashboard binding roadmap include allowlisted periodic command execution, or should command bindings be split into a separate security-reviewed design after stream and computed bindings?

Rationale: Automation cannot choose the product and security boundary for running commands from dashboard data resolution, and the underlying dashboard substrate is still an open PR stack rather than current main.

Likely owner: steipete

Owner reason: The strongest current-main history signal is the recently landed Control UI plugin-tab seam and Logbook precedent that this dashboard stack reuses.

Owner confidence: high

Options:

- **Split Command Security Design (recommended):** Proceed with stream and computed binding design only after the dashboard substrate lands, and require a separate maintainer-approved proposal for command execution.
- **Approve All Binding Kinds Together:** Allow stream, computed, and command bindings in one feature, with implementation carrying the full allowlist, permission, audit, and proof burden.
- **Defer Dashboard Apps Layer:** Keep the roadmap item open but pause implementation until maintainers decide whether the modular dashboard apps layer belongs in bundled OpenClaw.

## Reproduction Assessment

Not applicable; this is a new dashboard data-binding capability request rather than broken existing behavior. Source inspection confirms the requested binding kinds are absent from current main and the open dashboard backend candidate.

## Solution Assessment

Unclear: stream and computed bindings are plausible once the substrate lands, but bundling command execution into the same feature is not the safest default. The better path is to split command execution behind a separate maintainer-approved allowlist and security design.
