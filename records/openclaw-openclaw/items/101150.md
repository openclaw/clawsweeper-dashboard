## What This Changes

Request to add stream, allowlisted command, and computed/derived data-binding kinds for modular dashboard widgets.

## Best Possible Solution

Land or reject the Wave 1 dashboard substrate first, then design stream and computed bindings separately from any command-execution binding unless maintainers approve that security model.

Rationale: Automation cannot safely choose the product and security boundary for dashboard bindings that periodically execute commands, especially while the underlying dashboard substrate is still outside current main.

Likely owner: steipete

Owner confidence: medium

Options:

- **Split command execution design (recommended):** Proceed with stream/computed binding design only after the dashboard substrate lands, and require a separate maintainer-approved proposal for command execution.
- **Approve unified binding surface:** Accept stream, computed, and command bindings as one feature, with the implementation carrying the full allowlist, permission, audit, and proof burden.
- **Defer apps-layer bindings:** Keep the roadmap item open but pause implementation until maintainers decide whether this modular dashboard layer belongs in bundled OpenClaw.

## Solution Assessment
