## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P2] Stop speech when starting a new chat:** `apps/android/app/src/main/java/ai/openclaw/app/NodeRuntime.kt:2660-2661`
  - body: The new lifecycle stop is only wired into explicit session switches. The header New chat path still calls `MainViewModel.startNewChat()` -> `NodeRuntime.startNewChat()` -> `ChatController.startNewChatAwait()`, which loads the created session with `beginHistoryLoad(createdKey, clearMessages = true)` but never calls `stopMessageSpeech()`. If the user starts a new chat while an old assistant reply is speaking, playback continues after the transcript and inline stop affordance disappear; please stop speech on this session-replacement path too.
  - confidence: 0.93
- **[P2] Retry local TTS after init failure:** `apps/android/app/src/main/java/ai/openclaw/app/chat/MessageSpeechController.kt:260`
  - body: Late catch: this was already visible at the prior reviewed SHA. When on-device `TextToSpeech` initialization reports failure, `ensureEngine()` returns `null` but leaves the completed `ready=false` deferred and failed engine cached; every later fallback reuses that same failed result, so Listen stays silent until process restart even if system TTS becomes available. Clear `ready`/`engine` and shut down the failed instance so the next Listen can retry.
  - late: true
  - confidence: 0.9
