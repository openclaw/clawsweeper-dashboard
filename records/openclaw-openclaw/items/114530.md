## Summary

Keep this PR open: current `main` still classifies a normalized allowlist containing both `*` and an additive entry as restrictive, so the reported spawned-agent tool ceiling remains unfixed. The narrow wildcard-dominance change matches the policy contract and preserves bounded allowlists and inherited denylists, but this external PR still needs real after-fix behavior proof beyond unit-test output before merge.

## What This Changes

The PR changes spawned-agent tool-policy classification so a parent using `tools.alsoAllow` without a bounded allowlist does not pass its concrete tool snapshot as the child agent’s inherited allowlist.

## System Context

The agent runtime normalizes parent tool settings before creating coding and spawned-agent tools. That restrictive-policy decision controls whether the child receives a hard parent allowlist ceiling or retains its target-specific authorized tools, while denials continue to propagate.
