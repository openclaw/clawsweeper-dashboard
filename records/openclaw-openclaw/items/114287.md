## Summary

Keep this draft open for explicit product and security-boundary direction. The branch turns a local Git hook into a mandatory publication gate, but a client-side hook can be bypassed and therefore cannot provide the claimed fail-closed guarantee; it also changes the normal push path for existing source checkouts.

## What This Changes

This PR adds a repository-local `pre-push` hook, a publication-manifest checker, integration tests, and contributor documentation intended to prevent pushes unless a reviewed manifest approves the exact commit.

## System Context

The proposed hook runs in contributor source checkouts before Git sends refs to a remote. It delegates to a new script that validates local branch, diff, identity, inventory, and approval data, then either allows or rejects the push.

## Best Possible Solution

Decide whether this should be an optional local contributor aid, or move any mandatory publication enforcement to a remotely enforced repository control; only then implement the smallest documented path with explicit upgrade behavior and real-run evidence.
