## Summary

Keep this PR open for maintainer review. The current main store still applies only a per-session byte cap, so the linked production-growth problem remains necessary; the branch adds a plausible bounded-retention fix, but its permanent data-retention policy and real after-fix database proof need human confirmation before merge.

## What This Changes

This PR adds age- and database-wide retention for persisted trajectory runtime events, caps stored final-prompt text, and preserves truncation metadata in trajectory exports.

## System Context

Trajectory runtime events are diagnostic records captured during agent runs and persisted in each agent’s SQLite database. The store feeds trajectory export, CLI diagnostics, and QA/replay tooling, so retention affects how much historical debugging data remains available.
