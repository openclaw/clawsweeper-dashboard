## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.95

Full review comments:

- **[P2] Split the plain fallback before retrying:** `extensions/telegram/src/send.ts:668`
  - body: The retry sends the source-derived fallback as one `sendMessage` payload. Markdown source can be longer than the rendered rich chunk because link destinations remain in the source, so a fallback can exceed Telegram's 4096-character limit and fail instead of preserving delivery. Split and sequence the source fallback at the Telegram boundary before retrying.
  - confidence: 0.92
- **[P2] Preserve link previews in the direct fallback:** `extensions/telegram/src/send.ts:84`
  - body: The direct plain retry does not carry `link_preview_options`, so a send configured with link previews disabled can unexpectedly generate a preview only after rich parsing fails. Pass the existing preview option through the fallback request and cover it with the forced-error test.
  - confidence: 0.95
- **[P2] Preserve link previews in the reply fallback:** `extensions/telegram/src/bot/delivery.send.ts:157`
  - body: The ordinary reply fallback rebuilds its plain `sendMessage` parameters without `link_preview_options`, which drops the user's link-preview preference on the exact recovery path added here. Preserve the option alongside reply, thread, silent, and markup parameters.
  - confidence: 0.95
