## Summary

This issue should stay open because current main still appears to auto-enable `acpx` in effective config without guaranteeing that the bundled `acpx` startup lifecycle runs for the fresh-start ACP configuration path. The broader restart-loop report and open fix PR overlap, but this issue's central fresh-start behavior is not yet proven fixed by that PR.

## What This Changes

The issue asks for ACP config auto-enable to fully load the bundled `acpx` plugin when `acp.backend` is `acpx`, without requiring a manual `plugins.entries.acpx.enabled` setting.

## Best Possible Solution

Fix the gateway startup activation path so ACP-selected `acpx` auto-enable causes the bundled plugin lifecycle to run on fresh start, while coordinating with the broader reload-loop work in https://github.com/openclaw/openclaw/issues/102205.
