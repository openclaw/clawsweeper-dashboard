## Summary

Keep open, but this PR is not merge-ready: it fixes a real cron/diagnostic timeout conflict, yet the implementation applies the collapsed agent timeout to every isolated cron run and can stretch stuck-session active-abort recovery from the default six-minute window to the 48-hour agent default.

## What This Changes

The PR adds a diagnostic `timeoutBudgetMs` session field, uses it as the heartbeat stuck-session abort threshold, and sets it from isolated cron agentTurn timeout state.

## Best Possible Solution

Scope the diagnostic timeout budget to explicit cron payload timeouts or preserve the default diagnostic abort threshold for implicit timeouts, add focused explicit/default regression coverage, and keep the broader recovery policy tied to https://github.com/openclaw/openclaw/issues/88870.

## Reproduction Assessment

Yes at source level. PR head writes the always-present `prepared.context.timeoutMs` into diagnostic state, while current main and docs show that value can be the implicit 48-hour agent default and the heartbeat then uses it as the active-abort threshold.

## Solution Assessment

No. The maintainable fix needs to distinguish explicit per-run cron timeout from the collapsed/default agent timeout that current code already separates with `runTimeoutOverrideMs`.
