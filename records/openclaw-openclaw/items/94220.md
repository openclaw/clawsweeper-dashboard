## Summary

Keep open: current main still retries and repairs Anthropic thinking-signature failures inside the active session, but I found no current guard that clears stale detached work, requires a fresh trigger, or coordinates sibling ownership after a heal. Fresh discussion also reports the trigger still recurring on v2026.6.11, so the central post-heal lifecycle hazard is still necessary to track.

## What This Changes

The issue requests that automatic session-medic recovery avoid resuming stale detached work after an Anthropic thinking-signature heal, plus better coordination or signaling around multi-session races.

## Best Possible Solution

Define a bounded recovery/task lifecycle rule that preserves Anthropic self-heal while preventing stale detached work from continuing without an explicit fresh trigger, owner signal, or task handoff; keep the Anthropic signature creation/replay trigger on the linked canonical cluster.

## Reproduction Assessment

No high-confidence full reproduction path yet: current source shows recovery retries and repairs the same active session without a stale-work guard, and latest-release comments confirm the heal trigger still fires, but the multi-session artifact race still needs redacted incident data or a focused harness.

## Solution Assessment

Unclear: suppressing stale detached-task continuation after a heal is plausible, but maintainers should choose whether the boundary is abort, fresh trigger, checkpoint, owner notification, or task handoff. The shared-artifact lock proposal is likely separate from the minimum recovery safety rule.
