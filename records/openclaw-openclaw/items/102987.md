## What This Changes

The PR replaces `Retry-After` HTTP-date parsing in the guarded provider fetch and ChatGPT Responses retry paths with component parsing plus UTC round-trip validation, and adds regression tests for invalid dates and valid obsolete RFC 850 dates.

## Best Possible Solution

Land the strict Retry-After parser after redacted live/runtime proof and a clean exact-head check run show both retry consumers behave correctly.

## Reproduction Assessment

Yes from source inspection: current main routes regex-shaped HTTP-date `Retry-After` values into `Date.parse`, and Node normalizes invalid calendar dates such as `31 Feb` to a future timestamp. I did not run a full provider scenario in this read-only review.

## Solution Assessment

Yes, the PR’s component parsing plus UTC round-trip validation is the right narrow fix for this bug across both retry consumers. A shared helper would reduce future drift, but the current duplicated shape follows the two pre-existing local retry implementations and is not a blocking defect.
