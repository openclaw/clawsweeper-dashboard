## Summary

Keep open: the report identifies a real, intentionally unsupported Slack workflow rather than a regression already fixed on main. Current behavior deliberately keeps ordinary Slack DM roots and replies on one stable DM session, while the requested independent per-thread execution model requires a new compatibility-sensitive product and configuration decision. ([github.com](https://github.com/openclaw/openclaw/pull/82418))

## What This Changes

Add an opt-in Slack account setting that gives each top-level DM thread its own session and execution lane while preserving the current shared-DM default.

## Best Possible Solution

If maintainers accept the product direction, add a Slack-plugin-owned account-level `dm.sessionScope` with `shared` as the unchanged default and `thread` as an opt-in; derive root and reply keys from the root timestamp, preserve explicit runtime bindings, and prove fresh and upgraded configurations across routing, queueing, status, tools, follow-ups, commands, and docs.
