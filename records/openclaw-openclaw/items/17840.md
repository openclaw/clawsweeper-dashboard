## Summary

Keep open: current main and the latest release still treat accepted reactions as passive queued system events, and the open implementation PRs are candidates that still need maintainer API/product direction before this broader cross-channel request can close.

## What This Changes

Request an opt-in mechanism, such as per-message or config-scoped policy, so accepted reaction events can wake an agent turn instead of waiting for a later text message or heartbeat.

## Best Possible Solution

Land one maintainer-approved opt-in notification-wake contract that keeps queued reactions as the safe default, makes wake/off behavior explicit, and documents/tests precedence across the supported reaction-capable channels.

## Reproduction Assessment

Yes at source level. Current main shows accepted Discord, Telegram, Slack, Matrix, and iMessage reaction paths enqueue system events without an opt-in reaction wake contract; I did not run a live channel repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract. A default-safe queue/wake/off policy after existing channel gates looks safer than unconditional wake or per-channel drift, but the exact config/API shape is a product decision.
