## Summary

Keep open: current main still treats accepted reaction events as queued system events rather than an opt-in wake/turn trigger, and the open implementation PRs are unmerged candidates that still need maintainer product/API direction.

## What This Changes

Request an opt-in mechanism so accepted reaction events can wake the routed agent turn instead of waiting for the next text or heartbeat event.

## Best Possible Solution

Keep this as the canonical cross-channel request, have maintainers choose a default-safe opt-in wake contract, then land it through shared policy/config/docs/tests after existing channel filters pass.

## Reproduction Assessment

Yes, at source level: current main shows accepted reaction paths enqueue system events without any documented wake contract or requestHeartbeat call. No live channel repro was run in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public API. A shared default-queue policy with explicit wake/off modes is safer than unconditional wake or a one-channel-only config surface.
