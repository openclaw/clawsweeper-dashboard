## Summary

Keep open: current main and v2026.6.11 still expose reaction notifications as passive queued system events, with no opt-in wake policy merged. The overlapping shared and Discord-specific PRs are useful candidates, but they remain open and require maintainer API/default-policy direction before this canonical cross-channel issue can close.

## What This Changes

The issue requests an opt-in mechanism for reaction events to wake the agent and start a turn instead of remaining passive system events.

## Best Possible Solution

Land one maintainer-approved, default-off shared reaction wake policy that preserves queued-by-default behavior, wakes only after existing channel filters, and updates schemas, generated metadata, docs, and focused channel tests.

## Reproduction Assessment

Yes, at source level. Current Discord, Telegram, Slack, and Matrix reaction handlers enqueue system events, and targeted search found no current-main reaction wake policy or heartbeat request in those inspected reaction paths; no live channel repro was run in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public API shape. A shared default-off queue/wake/off policy after existing filters is safer than unconditional or one-channel wake behavior, and the open candidate PRs still need maintainer review before this can close.
