## Summary

Keep open: current main and v2026.6.11 still expose accepted reactions as queued system events, but the requested opt-in wake policy is not merged; the open shared and Discord-specific PRs are candidates, not closure evidence.

## What This Changes

Request an opt-in mechanism, likely config or per-message scoped, that lets reaction events trigger routed agent turns instead of remaining passive queued system events.

## Best Possible Solution

Land one maintainer-approved, default-off shared reaction wake policy that preserves queue-by-default behavior, applies only after existing channel filters, and updates schemas, generated metadata, docs, and focused channel tests.

## Reproduction Assessment

Yes, at source level. Current Discord, Telegram, Slack, and Matrix reaction paths enqueue system events, and targeted search found no current-main reaction wake policy or heartbeat request in those inspected reaction handlers; no live channel repro was run.

## Solution Assessment

Unclear until maintainers choose the public API shape. A shared default-off queue/wake/off policy after existing filters looks safer than unconditional or one-channel wake behavior, and the open shared-policy PR is the broad candidate to review.
