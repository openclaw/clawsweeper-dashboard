## Summary

This should stay open: current main still only exposes reaction notifications as passive/system-event context, while the requested opt-in policy that wakes an agent turn on accepted reactions is not implemented and still needs a cross-channel product/API decision. The open Discord/shared wake-policy PRs are candidate implementations, but they are not merged and do not make this issue obsolete.

## What This Changes

The issue requests a default-off, opt-in mechanism that lets selected reaction events trigger agent turns for lightweight confirm/cancel, polling, and reaction-driven workflows.

## Best Possible Solution

Keep this as the canonical product/API issue, choose a default-off reaction wake contract, and land it through the shared channel/config surface or clearly documented channel-specific rollout with tests and docs.

## Reproduction Assessment

Yes, from source inspection: accepted reaction events are enqueued as system events in current reaction handlers, while the searched config/docs/code surface has no opt-in reaction wake policy. I did not run a live channel reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product contract; a default-off shared policy such as reactionTriggersTurn looks maintainable, but a Discord-first patch would need to avoid creating a second incompatible channel policy.
