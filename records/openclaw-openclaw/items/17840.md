## Summary

Keep open: current main still treats accepted reactions as passive queued system events across representative Discord, Telegram, Slack, Signal, and Matrix paths, and the open implementation PRs are unmerged/conflicting candidates rather than shipped fixes.

## What This Changes

The issue requests an opt-in mechanism for reactions to wake the agent and trigger a turn for lightweight interactive workflows.

## Best Possible Solution

Adopt one maintainer-approved notification-wake contract that preserves passive queueing by default, supports explicit wake/off policy, and applies only after existing channel authorization and reaction-notification filters pass.

## Reproduction Assessment

Yes at source level: current main queues accepted Discord, Telegram, Slack, Signal, and Matrix reactions as system events, while targeted search found no `notificationWake` or `reactionTriggersTurn` implementation. I did not run a live channel repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the canonical policy. A shared queue-by-default/wake/off contract after existing channel gates looks safer than unconditional wake or a one-channel-only config split.
