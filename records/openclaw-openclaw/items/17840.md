## Summary

Keep open: current main and v2026.6.11 still expose accepted reactions as passive queued system events, while the linked implementation PRs are unmerged candidates and the public wake/config contract still needs maintainer direction.

## What This Changes

The issue requests an opt-in mechanism for accepted reaction events to wake the agent and start an agent turn instead of remaining passive queued system events.

## Best Possible Solution

Keep this as the canonical cross-channel request, have maintainers choose a default-safe opt-in wake contract, then land it through shared policy/config/docs/tests after existing channel filters pass.

## Reproduction Assessment

Yes, at source level: current main shows accepted reaction paths enqueue system events without any documented wake contract or requestHeartbeat call. I did not run a live channel repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public API. A shared default-queue policy with explicit wake/off modes is safer than unconditional wake or a one-channel-only config surface.
