## Summary

Keep open: current main and v2026.6.11 still treat accepted reactions as passive queued system events, and the requested opt-in wake/config contract remains unmerged product/API work with overlapping open PR candidates.

## What This Changes

The issue requests an opt-in mechanism for accepted reaction events to wake an agent turn instead of remaining passive system events.

## Best Possible Solution

Land one maintainer-approved, queue-by-default reaction wake policy across the relevant bundled plugins, preserving existing filters and documenting config, defaults, upgrade behavior, and focused tests.
