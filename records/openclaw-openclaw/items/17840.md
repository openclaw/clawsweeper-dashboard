## Summary

Keep open: current main and v2026.6.11 still treat accepted reactions as passive queued system events, and the remaining work is a product/API decision with overlapping unmerged PR candidates.

## What This Changes

Request an opt-in mechanism that lets accepted reaction events wake an agent turn for reaction-based workflows.

## Best Possible Solution

Land one maintainer-approved, queue-by-default opt-in reaction notification wake policy across the relevant bundled plugins, preserving passive defaults, existing filters, schema/docs alignment, and focused channel tests.
