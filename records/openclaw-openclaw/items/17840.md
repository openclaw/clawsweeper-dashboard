## Summary

Keep open: current main and the latest release still expose accepted reactions as passive queued system events, while the overlapping implementation PRs are open and still require maintainer product/API direction before this canonical cross-channel request can close.

## What This Changes

Request an opt-in mechanism so accepted reaction events can wake an agent turn for reaction-capable channels instead of waiting for a later text message or heartbeat.

## Best Possible Solution

Keep this as the canonical cross-channel request, have maintainers choose a default-safe opt-in wake contract, then land one shared policy/config/docs/test path after each channel’s existing filters pass.

## Reproduction Assessment

Yes, at source level. Current main shows accepted reaction paths enqueue system events without any documented wake contract or requestHeartbeat call; I did not run a live channel repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public API. A shared default-queue policy with explicit wake/off modes is safer than unconditional wake or a one-channel-only config surface.
