## Summary

Keep open: current main and the latest release still expose accepted reactions as passive queued system events, while the requested opt-in wake/turn contract remains unmerged and needs maintainer product/API direction.

## What This Changes

The issue requests an opt-in mechanism for reaction events to wake an agent turn for lightweight confirm, cancel, polling, and mode-switch workflows.

## Best Possible Solution

Land a maintainer-approved default-safe notification wake policy that runs only after existing reaction notification filters and authorization, keeps queue-only behavior as the default, and documents/tests the chosen channel scope.

## Reproduction Assessment

Yes, at source level: current main has accepted Discord, Telegram, Slack, Signal, Matrix, and iMessage reaction paths that enqueue system events, and targeted search found no wake/turn opt-in surface. I did not run a live channel repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the contract. A shared queue/wake/off notification policy after existing channel filters looks like the most maintainable shape, but the exact config/API surface and channel rollout still need product direction.
