## Summary

Keep open: current main and v2026.6.11 still treat accepted reaction notifications as passive queued system events, while the requested opt-in wake policy remains unmerged product/API work with overlapping open implementation PRs.

## What This Changes

The issue requests an opt-in mechanism for channel reactions to trigger agent turns, such as a per-message await flag or a config-level reaction wake policy.

## Best Possible Solution

Land one maintainer-approved, default-off shared reaction wake policy that preserves queue-by-default behavior, applies only after existing channel filters, and updates schemas, generated metadata, docs, and focused channel tests.

## Reproduction Assessment

Yes, at source level. Current Discord, Telegram, Slack, Matrix, and Signal reaction paths enqueue system events, and targeted search found no current-main reaction wake policy or heartbeat request in those inspected reaction handlers.

## Solution Assessment

Unclear until maintainers choose the public API shape. A shared default-off queue/wake/off policy after existing filters looks safer than unconditional or one-channel wake behavior.
