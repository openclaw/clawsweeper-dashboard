## Label Justifications

## Summary

Keep open: the latest supplied current-main and release evidence still shows reactions as passive system events, while the open shared-policy PR is an implementation candidate rather than a merged fix and the durable public contract still needs maintainer direction.

## What This Changes

Requests a default-off mechanism that lets accepted message reactions trigger agent turns across reaction-capable channels.

## Best Possible Solution

Adopt one shared default-off notification wake policy that reaction-capable plugins apply only after authorization, notification filtering, canonical session routing, successful enqueue, and deduplication, with focused fresh-install and upgrade-safe channel tests.

Options:

- **Shared default-off policy (recommended):** Define one notification wake contract and have each bundled channel apply it after existing ingress filters.
- **Channel-specific policies:** Allow plugins to expose independent wake settings, accepting configuration drift and uneven cross-channel behavior.
- **Per-message awaiting state:** Wake only for explicitly marked outbound messages, requiring durable message-state and lifecycle design first.

## Reproduction Assessment

Yes, at source level: bundled reaction ingress queues system events while heartbeat wake remains a separate operation, and the current discussion identifies no opt-in wiring between them. No live current-main channel scenario was run during this read-only review.

## Solution Assessment

Not yet: a shared default-off policy appears narrower and more maintainable than channel-local configuration or persisted per-message awaiting state, but maintainers must confirm that public contract before implementation lands.
