## Summary

Keep open: current main and v2026.6.11 still treat accepted reaction notifications as queued system events, while the requested opt-in wake/turn policy remains unmerged product/API work with overlapping open implementation PRs.

## What This Changes

The issue requests an opt-in mechanism so accepted reaction events can wake the routed agent turn for reaction-driven workflows.

## Best Possible Solution

Land one maintainer-approved, default-safe opt-in notification wake policy that runs only after existing reaction notification and access filters pass, documents precedence, and proves fresh-install plus upgrade behavior for the reaction-capable channels it covers.

## Reproduction Assessment

Yes at source level: current reaction handlers for Discord, Telegram, Slack, Matrix, and Signal enqueue accepted reaction system events without calling the heartbeat wake primitive. I did not run a live multi-channel repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract. A default-safe queue/wake/off policy after existing channel gates looks more maintainable than unconditional wake, but the exact scope and precedence need product approval.
