## Summary

Keep open: current main and v2026.6.11 still expose reactions as passive queued system events, while the requested opt-in wake policy remains unmerged product/API work. The open shared-policy and Discord-specific PRs are implementation candidates, not a basis to close this canonical cross-channel issue before one lands.

## What This Changes

The issue requests an opt-in policy that lets accepted reaction events wake the agent and start a turn instead of remaining passive system events.

## Best Possible Solution

Land one maintainer-approved, default-off shared reaction wake policy that preserves queue-by-default behavior, applies only after existing channel filters, and updates schemas, generated metadata, docs, and focused channel tests.

## Reproduction Assessment

Yes at source level. Current Discord, Telegram, Slack, Matrix, Signal, and iMessage paths enqueue reaction system events, and targeted search found no current-main reaction wake policy or heartbeat request in the inspected reaction handlers; no live channel repro was run in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public API shape. A shared default-off queue/wake/off policy after existing filters looks safer than unconditional or one-channel wake behavior, and the open shared-policy PR is the broad candidate to review.
