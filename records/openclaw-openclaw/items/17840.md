## Summary

Keep open: current main and v2026.6.11 still treat accepted reactions as passive queued system events, while the requested opt-in wake/turn contract is unmerged and still needs maintainer product/API direction.

## What This Changes

Request an opt-in mechanism, such as a per-message flag or config policy, so accepted reaction events can trigger agent turns instead of waiting for a later text message.

## Best Possible Solution

Choose one default-off shared reaction notification wake contract, keep passive queueing as the default, and land it after existing channel gates with aligned schemas, docs, and tests for the supported reaction-capable channels.

## Reproduction Assessment

Yes at source level. Current main shows accepted Discord, Slack, Telegram, Signal, Matrix, and iMessage reactions enqueue system events, and targeted search shows no wake/turn config or heartbeat call for those reaction paths.

## Solution Assessment

Unclear until maintainers choose the public contract. A shared default-off notification wake policy after existing channel gates is safer than unconditional wake or a one-channel-only config that could fragment behavior.
