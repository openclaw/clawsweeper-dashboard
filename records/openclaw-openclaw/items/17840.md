## Summary

Keep open: current main and v2026.6.11 still treat accepted reaction notifications as queued system events, while the requested opt-in wake/turn policy remains unmerged product/API work. The open shared-policy and Discord-specific PRs are candidates, but they are still open and do not close this canonical cross-channel issue.

## What This Changes

Request an opt-in mechanism, such as a config policy or per-message flag, so accepted reaction events can wake the routed agent turn instead of remaining passive system events.

## Best Possible Solution

Land one maintainer-approved, default-off shared reaction wake policy that preserves queue-by-default behavior, applies only after existing channel authorization and reaction filters, and updates schemas, generated metadata, docs, and focused channel tests.

## Reproduction Assessment

Yes, at source level: current Discord, Telegram, Slack, and Matrix reaction paths enqueue system events, and targeted search found no current-main reaction wake policy or heartbeat request in those inspected handlers.

## Solution Assessment

Unclear until maintainers choose the public API shape. A shared default-off queue/wake/off policy after existing filters looks safer than unconditional or one-channel wake behavior.
