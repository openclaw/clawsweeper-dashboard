## Summary

Keep open: current main and v2026.6.11 still only expose reaction notifications as passive queued system events, while the requested opt-in reaction wake policy remains unmerged product/API work. The broad shared-policy PR and narrower Discord PR are active candidates, so maintainers should review those instead of closing this canonical issue early.

## What This Changes

The issue requests an opt-in mechanism for accepted reaction events to wake an agent turn instead of waiting as passive queued system events.

## Best Possible Solution

Land one maintainer-approved, default-off shared reaction wake policy that preserves queue-by-default behavior, wakes only after accepted reaction enqueue, and updates schemas, generated metadata, docs, and focused channel tests.

## Reproduction Assessment

Yes, at source level. Current Discord, Telegram, Slack, Matrix, and iMessage reaction paths enqueue system events, while targeted search found no current-main reaction wake policy or heartbeat request wiring in those inspected paths.

## Solution Assessment

Unclear until maintainers choose the public API shape. A shared default-off queue/wake/off policy after existing filters looks safer than unconditional or one-channel wake behavior, and the broad shared-policy PR is the main candidate to review.
