## Summary

Keep open: current main and v2026.6.11 still treat accepted reactions as queued system events, and the requested opt-in reaction wake/turn contract remains unresolved product/API work with open candidate PRs rather than an implemented feature.

## What This Changes

The issue requests an opt-in mechanism that lets reactions wake the agent for lightweight confirm/cancel, polling, and mode-switching workflows.

## Best Possible Solution

Keep this as the canonical cross-channel tracker until maintainers choose and land one default-off or queue-by-default reaction wake contract with docs, generated config metadata, and focused channel tests.
