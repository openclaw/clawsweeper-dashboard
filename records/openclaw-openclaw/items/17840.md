## Summary

Keep open: current main and v2026.6.11 still expose reaction notifications as passive queued system events with no opt-in wake contract, and the open implementation PRs are not merged or canonical enough to close this issue.

## What This Changes

The issue requests an opt-in mechanism so accepted reaction events can wake the agent and trigger a routed agent turn.

## Best Possible Solution

Land one maintainer-approved, default-off shared reaction wake policy that preserves queued behavior by default, wakes only after existing channel filters pass, and updates config/schema metadata, docs, and focused channel tests before closing this issue.

## Reproduction Assessment

Yes, at source level. Current Discord, Telegram, Slack, Signal, Matrix, and iMessage reaction paths enqueue system events, and targeted search found no current-main reaction wake policy or heartbeat request in the inspected reaction handlers; no live channel repro was run in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public API shape. A shared default-off queue/wake/off policy after existing channel filters is safer than unconditional wake or a one-channel-only contract, but the open PRs still need maintainer direction before this issue can close.
