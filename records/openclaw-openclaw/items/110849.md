## What This Changes

The PR trims leading and trailing whitespace from Gateway cron job IDs before exact lookups, routes legacy `cron.update` through the shared normalization helper, and tests blank-selector handling for `cron.runs`.

## System Context

Gateway cron RPC handlers accept job selectors from CLI and WebSocket callers, normalize and validate them, then read, update, run, or list entries in the cron scheduler. This change sits at the request-validation boundary before the scheduler receives an exact job ID.

## Architecture Diagram

  C --> D{Valid nonblank ID?}
  D -->|Yes| E[Cron scheduler lookup or action]
  D -->|No| F[Invalid request response]
  E --> G[Job, run, update, or log response]

## Best Possible Solution

Keep one shared normalized job-ID boundary for every exact cron lookup, retain the explicit blank-selector rejection for `cron.runs`, then merge the refreshed branch once current-base checks pass.
