The branch trims `id`/`jobId` values in the shared cron lookup helper, routes `cron.update` through it, and adds padded-ID coverage for `cron.get` and `cron.run`.

## Best Possible Solution

Keep one canonical trim point in `resolveCronJobId`, retain the `cron.update` call-site consolidation, and add redacted live Gateway request/response evidence showing a padded existing ID resolves successfully.
