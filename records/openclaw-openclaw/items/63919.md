## Summary

This PR remains necessary because current `main` does not expose built-in coding tools through Gateway direct invocation. The implementation is well-gated and well-proven, but merging requires explicit acceptance of the remote host-filesystem mutation boundary and resolution of the current narrow merge conflict.

Likely related people: `jacobtomlinson` for the owner-only HTTP authorization boundary, `steipete` for recent Gateway tool-resolution maintenance, and `ai-hpc` for the shared SDK `tools.invoke` surface.

## What This Changes

The PR adds two Gateway config opt-ins and materializes built-in `read`, `write`, and `edit` tools for owner-authenticated HTTP and SDK direct invocation, with audits, documentation, tests, and compatibility handling for same-named plugin tools.

## Best Possible Solution

Preserve the triple-gated, owner-only resolver design and same-name plugin compatibility, reconcile the SDK budget conflict, and merge only after a security owner explicitly accepts `hostFsWrite` as a supported Gateway boundary.
