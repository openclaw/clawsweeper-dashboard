## Label Justifications

## Summary

Keep open: current stable reports still show native hook relay subprocess fan-out starving Codex-backed gateways, while the documented loop-detection opt-out and the linked open PR address only narrower portions of the problem.

## What This Changes

Prevent Codex native PreToolUse/PostToolUse relay subprocesses from exhausting CPU or memory and making gateway RPC and channel delivery unresponsive during tool-call bursts.

## Best Possible Solution

Keep required native policy relays intact while adopting a maintainable pre-spawn reduction strategy and a lightweight or bounded execution path, then prove gateway responsiveness and policy enforcement under a concurrent Codex tool-call load test.
