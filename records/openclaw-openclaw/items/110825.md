## Summary

Keep this PR open, but it needs one focused correction before merge: its exported declaration accepts any `Uint8Array`, while the implementation decodes using Buffer-only UTF-8 behavior. The bounded formatter path itself passes a Buffer and the submitted proof credibly demonstrates that path; the mismatch was introduced by the latest declaration-only follow-up.

## What This Changes

The PR trims leading UTF-8 continuation bytes from capped `format-docs` formatter-output tails and adds a declaration plus focused tests for the helper.

## Best Possible Solution

Make `decodeUtf8Tail` genuinely decode any `Uint8Array` after the continuation-byte skip, then add one plain-`Uint8Array` regression test while preserving the existing Buffer-backed formatter path.
