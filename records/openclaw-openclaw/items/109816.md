## Summary

Keep open: the core-lifecycle direction is sound, but the latest head still emits two immediate passive typing notifications for each QQ C2C turn and lacks live after-fix QQ proof.

## What This Changes

## Best Possible Solution

Keep the core TypingController integration, but make the early gateway cue and `onReplyStart` handoff share one initial budget spend, add a regression assertion for one time-zero notification, and prove the lifecycle with a redacted live QQ C2C run.
