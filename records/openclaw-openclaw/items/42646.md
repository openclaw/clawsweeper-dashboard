## Summary

Keep open. Current main and the latest release still use Markdown files as durable memory plus SQLite `memory_index_*` tables for retrieval/index/cache storage, so the requested typed canonical SQLite memory record model remains unimplemented product/data-model work.

## What This Changes

Define a v1 typed SQLite durable memory schema and canonical record model for memory-core, with revision/status/entity fields and embeddings kept retrieval-only.

## Best Possible Solution

Define the plugin-owned durable memory record contract and migration boundary across the Memory MVP cluster, then implement a conservative SQLite schema while keeping embeddings retrieval-only.
