## Summary

Keep open. Current main and the latest release still use Markdown as durable memory plus SQLite memory_index_* tables for retrieval/indexing, so the typed canonical SQLite memory record model remains unimplemented product/data-model work.

## What This Changes

The issue requests a v1 SQLite-backed canonical memory schema with typed records, lifecycle statuses, revision history, entity fields, and retrieval-only embeddings.

## Best Possible Solution

Define the plugin-owned durable memory record contract and migration boundary across the Memory MVP cluster, then implement a conservative SQLite schema while keeping embeddings retrieval-only.
