## Summary

Keep open. Current main and the latest release still use Markdown as durable memory while SQLite stores the memory search/index data, so the requested typed canonical record schema remains unimplemented and needs product/data-model direction.

## What This Changes

The issue requests a v1 SQLite schema and canonical record model for local-first durable memory records.

## Best Possible Solution

Define the memory-core-owned durable SQLite record/revision/status contract and migration boundary across the Memory MVP cluster, keeping embeddings retrieval-only and any Markdown transition explicit.
