## Summary

Keep open. Current main still uses Markdown files as durable memory and SQLite as retrieval/index storage, so the requested typed canonical SQLite record model remains unresolved product and data-model work.

## What This Changes

Define a v1 local-first SQLite durable memory schema with typed records, canonical current state, revision history, explicit statuses, and entity normalization.

## Best Possible Solution

Have maintainers define a plugin-owned v1 durable memory contract for records, statuses, revisions, provenance, and doctor/migration behavior before implementing SQLite tables.
