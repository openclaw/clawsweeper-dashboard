## Summary

Keep open: current main has a SQLite memory index and SQLite-backed plugin state, but durable memory is still Markdown/plugin-owned and the requested typed canonical record schema is not implemented.

## What This Changes

Define a v1 SQLite-backed canonical memory record schema with typed records, revisions, statuses, timestamps, validity windows, and entity normalization.

## Best Possible Solution

A maintainer-sponsored memory design should choose the active memory-slot owner, then add a minimal SQLite record/revision/provenance schema with migration and tests in that owner, keeping embeddings retrieval-only.
