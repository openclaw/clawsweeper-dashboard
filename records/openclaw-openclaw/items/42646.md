## Summary

Keep open: current main has a SQLite-backed memory index and SQLite-backed plugin state, but it does not implement the requested typed durable memory record model with revisions, statuses, validity windows, and entities. This is a foundational product/storage decision rather than a narrow bug fix.

## What This Changes

Requests a v1 SQLite-backed durable memory schema with typed records, explicit status transitions, revision history, entity normalization, and embeddings kept retrieval-only.

## Best Possible Solution

Keep this as the design tracker until maintainers choose the canonical durable-memory storage model, then implement one schema/migration path that does not leave Markdown, plugin state, and typed records competing.
