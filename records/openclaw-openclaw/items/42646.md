## Summary

Keep open. Current main and the latest release still treat Markdown files as durable memory while SQLite stores the search/index layer, so the requested typed canonical SQLite record model remains unimplemented product/data-model work.

## What This Changes

The issue requests a v1 SQLite-backed canonical memory record schema with typed records, statuses, revision history, and entity fields.

## Best Possible Solution

Maintainers should first decide whether the canonical durable memory record model belongs in memory-core's per-agent SQLite store or behind a plugin API, then implement one schema/migration path with focused tests and docs.

- **Close as not planned:** Reject typed canonical records for now and keep Markdown plus search index as the memory source of truth.
