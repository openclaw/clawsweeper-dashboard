## Summary

Keep open. Current main and v2026.6.11 still use Markdown as durable memory plus SQLite memory_index_* tables for retrieval/indexing, so the requested typed canonical SQLite memory record model remains unimplemented product/data-model work.

## What This Changes

Define a v1 SQLite durable memory schema with typed records, canonical current state, revision history, lifecycle status, validity windows, and entity normalization.

## Best Possible Solution

Define the plugin-owned durable memory record contract and migration boundary across the Memory MVP cluster, then implement a conservative SQLite schema while keeping embeddings retrieval-only.
