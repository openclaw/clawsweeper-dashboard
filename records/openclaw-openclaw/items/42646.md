## Summary

Keep open. Current main still treats Markdown files as durable memory and SQLite as memory index/retrieval storage, so the requested typed canonical SQLite record model remains real product/data-model work rather than cleanup that can be closed.

## What This Changes

Define a v1 SQLite durable memory schema with typed records, canonical current state, revision history, lifecycle statuses, timestamps, validity windows, and entity normalization.

## Best Possible Solution

Keep Markdown as the current durable source until maintainers approve a memory-core durable SQLite record contract and migration plan; then implement the conservative schema with embeddings strictly retrieval-only.
