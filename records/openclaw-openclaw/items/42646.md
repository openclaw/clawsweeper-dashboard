## Summary

Keep open. Current main and the latest release still use Markdown files as durable memory and SQLite as retrieval/index storage, so the requested typed canonical SQLite record model remains unresolved product and data-model work.

## What This Changes

Define a v1 SQLite-backed canonical durable memory record schema with typed records, status transitions, revisions, entity fields, confidence, timestamps, and validity windows.

## Best Possible Solution

Have maintainers define a plugin-owned v1 durable memory contract for records, statuses, revisions, provenance, and doctor/migration behavior before implementing SQLite tables.
