## Summary

Keep open. Current main and the latest release still use Markdown as the durable memory source while SQLite backs retrieval indexes/cache, so the requested typed canonical SQLite record model remains unresolved product/data-model work.

## What This Changes

Define a v1 typed SQLite durable-memory schema and canonical record model with revisions, statuses, validity windows, and entity fields.

## Best Possible Solution

Have maintainers define a plugin-owned v1 durable-memory contract for records, statuses, revisions, provenance, and doctor/migration behavior, then implement the schema with embeddings remaining retrieval-only.
