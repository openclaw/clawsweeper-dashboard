## Summary

Keep open. Current main and v2026.6.11 still use Markdown files as durable memory and SQLite as the retrieval/index/plugin-state substrate, so the requested typed canonical SQLite record model remains real product/data-model work that needs maintainer direction.

## What This Changes

Define a v1 SQLite-backed durable memory record schema with typed records, canonical current state, revision history, statuses, validity windows, and entity/subject fields.

## Best Possible Solution

Define the plugin-owned durable memory record contract and migration boundary across the Memory MVP cluster, then implement a conservative SQLite schema while keeping embeddings retrieval-only.
