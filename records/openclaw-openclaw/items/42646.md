## Summary

Keep open. Current main and v2026.6.11 still use Markdown as the durable memory source while SQLite backs index/cache tables, so the requested typed canonical SQLite record model remains unresolved product/data-model work.

## What This Changes

The issue asks OpenClaw to define a v1 SQLite-backed durable memory schema with typed canonical records, revision history, lifecycle statuses, timestamps, validity windows, and normalized entities.

## Best Possible Solution

Maintainers should first define a plugin-owned v1 durable memory contract for records, statuses, revisions, provenance, migration/doctor behavior, and the Markdown-to-SQLite boundary, then implement it in memory-core with embeddings remaining retrieval-only.
