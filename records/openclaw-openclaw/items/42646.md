## Summary

Keep open. Current main and the latest release still treat Markdown files as durable memory and SQLite as a retrieval/index store, so the requested typed canonical durable-memory record model remains missing and needs maintainer data-model direction.

## What This Changes

Request defines a v1 SQLite-backed durable memory record schema with typed records, revision history, status transitions, validity windows, and normalized subjects/entities.

## Best Possible Solution

Maintainers should define the plugin-owned durable memory data model and doctor/migration boundary across the Memory MVP cluster, then implement a conservative SQLite schema with embeddings kept retrieval-only.

## Reproduction Assessment

Not applicable; this is a stored data-model feature request, not a current-main bug report. Source and docs inspection show the requested durable SQLite record model is missing rather than failing at runtime.

## Solution Assessment

Unclear until maintainers choose the product and ownership boundary. A typed SQLite model is plausible, but it should be designed together with the open provenance, write-pipeline, review/edit/forget, and CLI/skill follow-ups.
