## Summary

Keep open. Current main and the latest release still make Markdown files the durable memory source while SQLite is used for memory indexing, FTS/vector search, and cache state, so the requested typed canonical SQLite memory record model remains unimplemented product/data-model work.

## What This Changes

Define a v1 SQLite-backed durable memory record schema with typed records, canonical current state, revision history, lifecycle status, timestamps, validity windows, and entity normalization.

## Best Possible Solution

Define the plugin-owned durable memory record contract and migration boundary across the Memory MVP cluster, then implement a conservative SQLite schema while keeping embeddings retrieval-only.
