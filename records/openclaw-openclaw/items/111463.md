## What This Changes

The PR filters bridge-owned Memory Wiki pages for sandboxed callers in direct wiki reads and Memory Core corpus fallback, while retaining global-vault sharing for non-sandboxed callers.

## System Context

Memory Wiki compiles bridge artifacts from agent memory into a vault and serves them through wiki lookup/search APIs. Memory Core can fall back to that same wiki corpus when its primary memory store has no result, so caller identity and sandbox state must survive both routes before page content is returned.

  D --> E[Caller identity and sandbox context]
  B --> F[Bridge page ownership metadata]
  E --> G[Visibility decision]
  F --> G
  G --> H[Allowed page or filtered result]

## Best Possible Solution

Land one owner-approved sandbox visibility rule that blocks foreign owned bridge pages through both direct Wiki and Memory Core fallback paths, preserves documented non-sandboxed global sharing, and keeps regressions at each public read boundary.
