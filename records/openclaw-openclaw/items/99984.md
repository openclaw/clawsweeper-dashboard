## Summary

This issue should stay open: current main and the latest release still have a Windows `gateway --force` listener parser that only accepts the literal English `LISTENING` state, while the affected command path is documented and wired into gateway startup.

## What This Changes

Fix Windows CLI port listener detection so `gateway --force` and related diagnostics do not miss listeners when `netstat` output is localized or parsed differently.

## Best Possible Solution

Unify Windows listener PID detection for force-free and diagnostics around one parser/helper that does not require an English `netstat` state token, while preserving exact port matching and duplicate PID behavior.

## Reproduction Assessment

Yes at source level: a Windows `netstat` listener row whose state token is not exactly `LISTENING` is skipped by `listPortListeners`. I did not run a live localized Windows host, so runtime reproduction is still unproven.

## Solution Assessment

Yes, a narrow shared Windows listener parser/helper is the best fix. Copying only the current diagnostic parser would reduce divergence but still needs explicit localized-state coverage because that parser also searches for an English listen substring.
