## Summary

Current main and the latest release still expose the message tool `channel` parameter as an undescribed optional string, while the linked implementation PR remains open and merge-conflicted. Keep this issue open until that PR is refreshed and merged or replaced; a static enum should not block the narrow description fix because valid channel ids are plugin-defined.

## What This Changes

Clarify that the message tool `channel` parameter expects a messaging provider or channel-plugin id rather than a destination conversation, channel, or user id.

## Best Possible Solution

Refresh and land the linked PR’s narrow description plus generated-schema regression test, then consider a separate registry-derived enum only if post-fix evidence shows the wording is insufficient.
