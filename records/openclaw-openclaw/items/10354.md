## Summary

Keep open. Current `main` and the latest release still expose the shared message tool `channel` schema without provider-name metadata, and https://github.com/openclaw/openclaw/pull/84589 is the active open implementation candidate rather than a merged fix.

## What This Changes

The issue asks for clearer schema metadata on the shared `message` tool `channel` parameter so agents pass a provider id such as `slack` or `discord`, not a destination channel id.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/84589 if description-only closure is acceptable, then track dynamic enum support separately if maintainers still want it.

## Reproduction Assessment

Yes, at source level. Current `main` defines `channel` as a bare optional string in the shared message tool routing schema, and outbound channel selection can still reject destination-like channel ids as unknown channels.

## Solution Assessment

Yes for the description gap: TypeBox metadata plus a focused schema assertion is the narrow maintainable repair. The enum portion needs maintainer direction because channel/plugin availability is dynamic.
