## Summary

Keep open: current main and the latest release still expose the message tool `channel` parameter without provider-name schema guidance, and https://github.com/openclaw/openclaw/pull/84589 is the active open fix candidate rather than a merged fix.

## What This Changes

The issue requests a description and possible enum for the message tool `channel` parameter so agents pass provider ids like `slack` or `discord` instead of destination channel ids.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/84589 if description-only closure is acceptable, then track registry-derived enum support separately only if maintainers still want it.

## Reproduction Assessment

Yes, at source level. Current main exposes `channel` without schema guidance, and outbound selection can reject destination-like values as `Unknown channel` when no valid fallback applies.

## Solution Assessment

Yes for the description gap: TypeBox metadata plus a focused schema assertion is the narrow maintainable repair. Enum support is a separate product/API decision because a static enum could drift from registered channel/plugin ids.
