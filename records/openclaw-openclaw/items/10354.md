## Summary

Keep open: current main and v2026.6.11 still expose the message tool `channel` parameter as an undescribed optional string, and https://github.com/openclaw/openclaw/pull/84589 is an open fix candidate rather than a merged fix.

## What This Changes

Request to add provider-name guidance, and possibly enum constraints, to the message tool `channel` parameter so agents do not pass destination conversation IDs there.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/84589 after deciding closure scope; if enum support remains desired, track a dynamic registered-channel enum as separate focused work.

## Reproduction Assessment

Yes, at source level. Current main exposes `channel` without schema guidance, and outbound channel selection can reject destination-like values as `Unknown channel` when no valid fallback applies.

## Solution Assessment

Yes for the description gap: TypeBox metadata plus a focused schema assertion is the narrow maintainable repair. Enum support needs maintainer scope because a static enum could drift from registered or configured channel/plugin ids.
