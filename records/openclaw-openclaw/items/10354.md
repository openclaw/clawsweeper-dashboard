## Summary

Keep open: current main and v2026.6.11 still expose the message tool `channel` parameter as an undescribed optional string, and the open linked PR is the active fix candidate rather than a merged fix.

## What This Changes

The issue requests TypeBox schema guidance, and possibly an enum, so models pass a messaging provider id such as `slack` instead of a destination channel id.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/84589 if maintainers accept description-only closure; track registry-derived enum support separately only if still desired.

## Reproduction Assessment

Yes, at source level. Current main exposes `channel` without schema guidance, and outbound channel selection can still reject destination-like values as `Unknown channel` when no valid fallback applies.

## Solution Assessment

Yes for the description gap: TypeBox metadata plus a focused schema assertion is the narrow maintainable repair. Enum support needs maintainer scope because a static enum could drift from registered channel/plugin ids.
