## Summary

Keep open. Current main and v2026.6.11 still expose the message tool `channel` schema as an undescribed optional string, and the open linked PR is the active fix candidate rather than a merged implementation.

## What This Changes

The issue requests clearer schema metadata for the message tool `channel` parameter so agents pass a provider id such as `slack` or `discord`, not a destination conversation id.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/84589 if description-only closure is acceptable, then track registry-derived enum support separately only if maintainers still want it.

## Reproduction Assessment

Yes, at source level. Current main exposes `channel` without schema metadata, and the channel-selection path plus tests show destination-like values can still fail as unknown channels.

## Solution Assessment

Yes for the description gap: TypeBox metadata plus a focused schema assertion is the narrow maintainable repair. The enum portion needs maintainer direction because channel/plugin availability is dynamic.
