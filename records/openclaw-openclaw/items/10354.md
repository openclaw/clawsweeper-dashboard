## Summary

Keep open: current main and the latest release still expose the message tool `channel` parameter as an undescribed optional string, and https://github.com/openclaw/openclaw/pull/84589 is the active open fix candidate rather than a merged fix.

## What This Changes

Request to add provider-name guidance, and possibly enum metadata, to the message tool `channel` parameter so agents do not pass destination IDs as channel provider IDs.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/84589 after deciding closure scope; if enum support remains desired, derive it from registered or configured channel ids in a separate focused item.

## Reproduction Assessment

Yes, at source level. Current main exposes `channel` without schema guidance, and the outbound selection path can reject destination-like values as `Unknown channel` when no valid fallback applies.

## Solution Assessment

Yes for the description gap: TypeBox metadata plus a focused schema assertion is the narrow maintainable repair. Enum support needs maintainer scope because a static enum could drift from registered channel/plugin ids.
