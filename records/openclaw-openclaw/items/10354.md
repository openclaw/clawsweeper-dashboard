## Summary

Current main and v2026.6.11 still lack tool-schema guidance for `channel`, and the open linked implementation PR remains unmerged and conflicted. Keep the issue open while maintainers refresh that candidate and decide whether its description-only scope is sufficient or a plugin-aware enum is also required.

## What This Changes

Clarify that the message tool’s `channel` parameter selects a messaging provider/plugin rather than a destination ID, with enum metadata considered only if it can support dynamic plugins safely.

## Best Possible Solution

Refresh the linked PR onto current main, land the lightweight provider/plugin-ID description and focused schema assertion, and add enum enforcement only if maintainers explicitly choose that scope and it can derive deterministically from a lightweight registered-channel artifact.
