## Summary

Keep open. Current main and the latest release still expose the message tool `channel` schema without provider-name metadata, and the open linked PR is the active implementation candidate rather than a merged fix.

## What This Changes

Add tool-schema guidance for the message tool `channel` parameter so agents pass a messaging provider or plugin id instead of a destination channel or conversation id.

## Best Possible Solution

Review and land the linked schema/test PR if description-only closure is acceptable, then track registry-derived enum support separately if maintainers still want it.

## Reproduction Assessment

Yes, at source level. Current main exposes `channel` without schema guidance, and outbound routing can still reject destination-like explicit channel values as unknown.

## Solution Assessment

Yes for the description gap: TypeBox metadata plus a focused schema assertion is the narrow maintainable repair. The enum portion needs maintainer direction because channel and plugin availability is dynamic.
