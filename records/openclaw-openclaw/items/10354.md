## Summary

Keep open. Current main and the latest release still lack the requested message tool `channel` schema metadata, and https://github.com/openclaw/openclaw/pull/84589 is the open implementation candidate rather than a merged fix.

## What This Changes

Add provider-name guidance, and possibly enum metadata, to the shared message tool `channel` parameter so agents do not pass destination conversation/channel IDs there.

## Best Possible Solution

Review and land the linked schema/test PR if description-only closure is acceptable, then track registry-derived enum support separately if maintainers still want it.

## Reproduction Assessment

Yes, at source level. Current main exposes `channel` without the requested schema metadata, and the channel-selection path can still reject destination-like values as unknown channels.

## Solution Assessment

Partly. A narrow TypeBox description plus focused schema assertion is the best repair for the description gap, but enum support needs maintainer direction because channel/plugin availability is dynamic.
