## Summary

Keep open: current main and the latest release still expose the message tool channel schema without the requested provider-name metadata, and the open linked PR is the implementation candidate rather than a merged fix.

## What This Changes

The issue requests adding provider-name guidance, and possibly an enum, to the shared message tool channel parameter schema so agents do not pass Slack or Discord destination IDs as provider ids.

## Best Possible Solution

Review and land the linked schema/test PR if description-only closure is acceptable, then track registry-derived enum support separately only if maintainers still want it.

## Reproduction Assessment

Yes, at source level. Current main exposes `channel` without schema metadata, and the channel-selection path can still reject destination-like explicit channel values as unknown channels; I did not run a live Slack reproduction in this read-only review.

## Solution Assessment

Yes for the description gap: TypeBox metadata plus a focused schema assertion is the narrow maintainable repair. The enum portion needs maintainer direction because channel/plugin availability is dynamic.
