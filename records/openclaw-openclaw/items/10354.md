## Summary

Keep open. Current main and the latest release still expose the message tool `channel` schema as an undescribed string, and https://github.com/openclaw/openclaw/pull/84589 is the active open fix candidate rather than a merged implementation.

## What This Changes

The issue requests clearer message-tool schema metadata so agents pass a messaging provider id in `channel`, not a destination conversation or channel id.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/84589 if description-only closure is acceptable, then track registry-derived enum support separately if maintainers still want it.

## Reproduction Assessment

Yes. Source inspection on current main shows the `channel` parameter lacks the requested schema metadata, and the channel-selection path can still reject destination IDs as unknown channels.

## Solution Assessment

Yes for the description gap: a narrow TypeBox description plus focused schema assertion is the maintainable repair. The enum portion needs maintainer direction because channel and plugin availability is dynamic.
