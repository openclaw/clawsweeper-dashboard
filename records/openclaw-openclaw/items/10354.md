## Summary

Keep open: current main and v2026.6.11 still expose the shared message tool `channel` parameter as an undescribed optional string, and https://github.com/openclaw/openclaw/pull/84589 is the active unmerged fix candidate rather than a landed implementation.

## What This Changes

The issue requests provider-name guidance, and possibly enum metadata, for the message tool `channel` parameter so models do not pass destination IDs as channel providers.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/84589 if maintainers accept description-only closure; track registry-derived enum support separately only if tighter schema validation is still desired.

## Reproduction Assessment

Yes, at source level. Current main exposes `channel` without schema metadata, and the outbound selection path can reject destination-like values as `Unknown channel` when no valid fallback applies.

## Solution Assessment

Partly. TypeBox description metadata plus a focused schema assertion is the narrow maintainable repair for the description gap, while enum support needs maintainer scope because a static enum could drift from registered channel/plugin ids.
