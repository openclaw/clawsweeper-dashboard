## Summary

Keep open: current main and the latest release still expose the shared message tool `channel` parameter as an undescribed optional string, and the open linked PR is the active fix candidate rather than a merged implementation.

## What This Changes

Request to add provider-name guidance, and possibly enum constraints, to the message tool `channel` parameter so agents do not pass destination channel IDs as provider IDs.

## Best Possible Solution

Review and land `https://github.com/openclaw/openclaw/pull/84589` if maintainers accept description-only closure; track registry-derived enum support separately if that remains desired.

## Reproduction Assessment

Yes, at source level. Current main exposes `channel` without schema guidance, and the outbound selection path can reject destination-like values as `Unknown channel` when no valid fallback applies.

## Solution Assessment

Yes for the description gap: TypeBox metadata plus a focused schema assertion is the narrow maintainable repair. Enum support is broader and should be maintainer-scoped because static values could drift from registered channel/plugin ids.
