## Summary

Keep open. Current main and the latest release still expose the message tool `channel` schema without provider-name metadata, and the open linked PR is the active unmerged implementation candidate.

## What This Changes

The issue asks for provider-name guidance, and possibly an enum, on the message tool `channel` parameter so agents do not pass destination channel IDs.

## Best Possible Solution

Review and land the linked schema/test PR for the description gap, then track dynamic enum support separately only if maintainers still want it.

## Reproduction Assessment

Yes. Source inspection on current main shows the `channel` parameter lacks the requested schema metadata, and outbound channel selection can still reject destination IDs as unknown channels when no valid fallback applies.

## Solution Assessment

Yes for the description gap: a narrow TypeBox description plus a focused schema assertion is the maintainable repair. The enum portion is unclear because channel/plugin availability is dynamic and needs maintainer direction or separate tracking.
