Keep open. The most recent source review still found the schema gap on main and in v2026.6.11, while the proven implementation candidate at https://github.com/openclaw/openclaw/pull/84589 remains open and expressly closes this issue; the remaining choice is whether description-only guidance fully resolves the optional enum request.

## What This Changes

Add model-facing guidance to the message tool’s optional `channel` parameter and consider constraining it to valid messaging provider or channel-plugin IDs.

## Best Possible Solution

Land the linked description-and-test change as the narrow fix, keep `channel` optional, and defer enum validation unless it can be derived deterministically from the active channel registry without excluding plugin IDs.
