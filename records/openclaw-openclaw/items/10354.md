## Summary

Keep open. The issue identifies a narrow message-tool schema usability gap, but the provided record only proves that earlier description-only PRs were closed unmerged; it does not provide current-main source or provenance evidence that the request is now implemented. The remaining maintainer choice is whether to add durable guidance only or expose a dynamically derived channel-id enum.

## What This Changes

Clarify the message tool’s optional `channel` parameter as a provider or channel-plugin identifier rather than a destination conversation ID, with an enum only if it can stay aligned with registered channel plugins.

## System Context

The shared message tool turns an agent’s channel and destination inputs into outbound routing. Its schema guides model tool calls before channel selection resolves a configured provider and sends the message to the requested target.

## Best Possible Solution

Keep `channel` optional, add provider-versus-destination guidance in the shared message-tool schema with a focused schema assertion, and add an enum only if maintainers endorse a dynamically derived registered-plugin contract.
