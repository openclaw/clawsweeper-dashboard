## Summary

Keep open. Current main and v2026.6.11 still expose the message tool `channel` schema without provider-name metadata, and https://github.com/openclaw/openclaw/pull/84589 is the active open fix candidate rather than a merged implementation.

## What This Changes

Request adds provider-name description and possible enum metadata to the message tool `channel` parameter so agents do not pass destination conversation IDs.

## Best Possible Solution

Review and land the linked schema/test PR if description-only closure is acceptable, then track registry-derived enum support separately if maintainers still want it.

## Reproduction Assessment

Yes, at source level. Current main exposes `channel` without schema metadata, while outbound routing treats explicit `channel` values as provider/channel ids and can reject destination-like values as `Unknown channel`.

## Solution Assessment

Yes for the description gap: TypeBox metadata plus a focused schema assertion is the narrow maintainable repair. The enum portion needs maintainer direction because channel/plugin availability is dynamic.
