## Summary

Keep open. Current main and the latest release still expose the message tool `channel` parameter without provider-name schema metadata, and the linked implementation PR is open but unmerged.

## What This Changes

The issue requests `message` tool schema guidance, and possibly enum metadata, so agents pass provider names such as `slack` rather than destination channel IDs.

## Best Possible Solution

Review and land the linked schema/test PR if description-only closure is acceptable, then track registry-derived enum support separately if maintainers still want it.

## Reproduction Assessment

Yes, at source level. Current main exposes `channel` without schema metadata, and outbound routing still treats explicit `channel` values as provider/channel ids that can fail as `Unknown channel`.

## Solution Assessment

Yes for the description gap: a TypeBox description plus focused schema assertion is the narrow maintainable repair. The enum portion needs maintainer direction because channel/plugin availability is dynamic.
