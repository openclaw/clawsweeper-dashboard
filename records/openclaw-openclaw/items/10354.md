## Summary

Current `main` and v2026.6.11 still lack the requested schema guidance. The open linked PR is the canonical narrow fix, but it conflicts with current `main`, and maintainers still need to decide whether description-only scope fully resolves the optional enum request.

## What This Changes

Add message-tool schema guidance that `channel` expects a messaging provider or channel-plugin id rather than a destination id, with optional plugin-aware enum support.

## Best Possible Solution

Refresh and land the existing narrow PR with an optional string, explicit provider/channel-plugin-id wording, and focused schema coverage; omit a static enum unless maintainers approve a lightweight registry-backed design preserving plugin ids and aliases.
