## Summary

Keep open: current main and the latest release still expose the shared message tool `channel` parameter as an undescribed optional string, and https://github.com/openclaw/openclaw/pull/84589 is the active open fix candidate rather than a merged fix.

## What This Changes

Request to clarify the shared `message` tool schema so its optional `channel` parameter tells agents to pass a provider/channel plugin id, not a destination conversation id.

## Best Possible Solution

Review and land the linked schema/test PR if maintainers accept description-only closure, and track registry-derived enum behavior separately if still desired.

## Reproduction Assessment

Yes, at source level. Current main exposes `channel` without schema metadata, and outbound selection can reject destination-like explicit channel values as `Unknown channel` when no valid fallback applies.

## Solution Assessment

Yes for the description gap: TypeBox metadata plus focused schema coverage is the narrow maintainable repair. Enum support needs maintainer scope because static enums can drift from registered channel/plugin ids.
