## Summary

Keep open: current main and v2026.6.11 still expose the message tool `channel` parameter as an undescribed optional string, and https://github.com/openclaw/openclaw/pull/84589 is the active open fix candidate rather than a merged fix.

## What This Changes

Request to add provider-name guidance, and possibly an enum, to the message tool `channel` parameter schema so agents do not pass destination channel IDs there.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/84589 if maintainers accept description-only closure; track registry-derived enum support separately only if still desired.

## Reproduction Assessment

Yes, at source level. Current main exposes `channel` without schema guidance, and the outbound selection path can reject destination-like values as `Unknown channel` when no valid fallback applies.

## Solution Assessment

Yes for the description gap: TypeBox metadata plus a focused schema assertion is the narrow maintainable repair. Enum support is a separate product/API decision because a static enum could drift from registered channel/plugin ids.
