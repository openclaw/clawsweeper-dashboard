## Summary

Keep open: current main and v2026.6.11 still expose the shared message tool `channel` parameter as an undescribed optional string, and https://github.com/openclaw/openclaw/pull/84589 is the active open fix candidate rather than a merged implementation.

## What This Changes

Request to add provider-name guidance, and possibly enum constraints, to the message tool `channel` parameter so agents do not pass destination conversation IDs there.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/84589 if description-only closure is accepted; otherwise keep this issue as the canonical tracker for registry-derived enum scope.

## Reproduction Assessment

Yes, at source level. Current main exposes `channel` without schema guidance, and the outbound selection path can reject destination-like values as `Unknown channel` when no valid fallback applies.

## Solution Assessment

Partly. The open PR is the narrow maintainable repair for the description gap, but enum support needs maintainer scope because a static enum could drift from registered channel/plugin ids.
