## Summary

Keep open. Current main and the latest release still expose the message tool `channel` parameter without the requested provider-name schema metadata, and the linked open PR is the active fix candidate rather than a merged implementation.

## What This Changes

Request to add provider-name guidance, and possibly enum metadata, to the message tool `channel` parameter so agents do not pass destination channel IDs as provider IDs.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/84589 if description-only closure is acceptable, then track registry-derived enum support separately only if maintainers still want it.

## Reproduction Assessment

Yes, at source level. Current main exposes `channel` without schema metadata, and the outbound channel-selection path can still reject destination-like values as unknown channels when no valid fallback applies.

## Solution Assessment

Yes for the description gap: TypeBox metadata plus a focused schema assertion is the narrow maintainable repair. The enum portion needs maintainer direction because channel and plugin availability are dynamic.
