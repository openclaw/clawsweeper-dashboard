## Summary

Keep open because current main and the latest release still expose the message tool `channel` parameter as an undescribed optional string, and an open linked fix PR is the active implementation path rather than a reason to close the issue before merge.

## What This Changes

Request to add provider-name guidance, and possibly an enum, to the shared message tool `channel` parameter so agents do not pass destination channel IDs there.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/84589 after deciding the closing-reference and enum scope; track registry-derived enum support separately if maintainers still want it.

## Reproduction Assessment

Yes, at source level. Current main exposes `channel` without schema metadata, and outbound channel selection can reject destination-like values as `Unknown channel` when no valid context fallback is available.

## Solution Assessment

Yes for the description gap: adding TypeBox metadata and a focused schema assertion is the narrow maintainable repair. Unclear for full issue closure until maintainers decide whether enum support is required now or should be a follow-up.
