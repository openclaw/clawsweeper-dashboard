## Summary

Keep open: current main and v2026.6.11 still expose the shared message tool `channel` parameter as an undescribed optional string, and https://github.com/openclaw/openclaw/pull/84589 is the active open fix candidate rather than a merged fix.

## What This Changes

The issue asks for the shared message tool schema to describe `channel` as a messaging provider id rather than a destination channel or conversation id, with possible enum guidance.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/84589 if maintainers accept description-only closure; track registry-derived enum support separately only if still desired.

## Reproduction Assessment

Yes, at source level. Current main exposes `channel` without schema guidance, and the outbound selection path can reject destination-like values as `Unknown channel` when no valid fallback applies.

## Solution Assessment

Yes for the description gap: TypeBox metadata plus a focused schema assertion is the narrow maintainable repair. Enum support needs maintainer scope because a static enum could drift from registered channel/plugin ids.
