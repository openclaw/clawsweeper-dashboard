## Summary

Keep open: current main and latest release still expose the shared message tool `channel` parameter as an undescribed optional string, while https://github.com/openclaw/openclaw/pull/84589 is the active open fix candidate rather than a merged fix.

## What This Changes

The issue asks for clearer message tool `channel` schema metadata so agents pass provider names such as `slack` or `discord`, not conversation/channel IDs.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/84589 or an equivalent narrow update that keeps `channel` optional, adds provider-name schema guidance, and adds focused schema coverage; defer enum support unless it is dynamically derived from registered channel/plugin ids.

## Reproduction Assessment

Yes. Source inspection on current main shows the message tool still publishes `channel` as a bare optional string while the prompt/runtime expect a provider/channel id, so the schema gap is high-confidence without running a live Slack setup.

## Solution Assessment

Yes for the description-and-test portion: the linked PR is the narrowest maintainable fix for the model-facing schema. A static enum is not clearly the best path because channel ids include registered plugins, so enum support should be dynamic or deferred by maintainer choice.
