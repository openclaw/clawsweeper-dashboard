## Summary

Keep open: current main and v2026.6.11 still expose the shared message tool `channel` parameter as an undescribed optional string, and the linked implementation PR is still open rather than merged.

## What This Changes

The issue requests clearer schema guidance for the shared message tool `channel` parameter so agents pass provider names rather than destination IDs.

## Best Possible Solution

Review and land the open schema-description PR if maintainers accept description-only closure, with registry-derived enum support tracked separately only if still desired.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 still expose `channel` without schema metadata, and outbound selection can reject destination-like values as `Unknown channel` when no valid fallback applies.

## Solution Assessment

Yes for the description gap: TypeBox metadata plus a focused schema assertion is the narrow maintainable repair. Enum support needs maintainer scope because static enums may drift from registered channels/plugins.
