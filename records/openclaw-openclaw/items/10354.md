## What This Changes

The issue requests clearer schema guidance for the shared message tool channel parameter so agents pass provider ids rather than Slack or Discord conversation ids.

## Best Possible Solution

Review and land the linked schema/test PR if description-only closure is acceptable, then track registry-derived enum support separately only if maintainers still want it.

## Reproduction Assessment

Yes. Source inspection on current main shows the channel parameter lacks provider-name schema metadata, and channel-selection tests/source show destination-like explicit channel values can still fail as unknown channels.

## Solution Assessment

Yes for the description gap: a narrow TypeBox description plus a focused schema assertion is the maintainable repair. The enum portion needs maintainer direction because channel/plugin availability is dynamic.
