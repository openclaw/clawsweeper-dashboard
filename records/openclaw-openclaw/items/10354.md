## Summary

Keep open. Current main and v2026.6.11 still expose the shared message tool `channel` schema as an undescribed optional string, and https://github.com/openclaw/openclaw/pull/84589 is the open fix candidate that should be reviewed before this issue closes.

## What This Changes

The issue asks for the message tool `channel` parameter schema to describe provider-name usage and possibly constrain allowed values.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/84589 if description-only closure is acceptable, then track registry-derived enum support separately only if maintainers still want it.

## Reproduction Assessment

Yes, source-level: current main still builds the shared message tool `channel` property as an undescribed optional string, and the channel-selection path can still reject destination IDs as unknown channels when no valid fallback applies.

## Solution Assessment

Yes for the description gap: a narrow TypeBox description plus focused schema assertion is the maintainable repair. The enum portion needs maintainer direction because channel/plugin availability is dynamic.
