## Summary

Keep open: current main has adjacent update dry-run, doctor lint, plugin-only post-upgrade JSON probes, post-update plugin convergence, and safe-update docs, but it still lacks the requested unified pre/post-update compatibility scanner with risk scoring, smoke recommendations, and rollback hints.

## What This Changes

The issue requests a native `doctor --upgrade-scan` style upgrade scanner with pre-update schema/deprecation checks, post-update smoke checks, risk-scored JSON/human output, and rollback recommendations.

## Best Possible Solution

Define one maintainer-approved upgrade assessment contract that composes existing doctor, update, plugin compatibility, config migration, health/status, backup, and rollback guidance surfaces with explicit redaction, severity, JSON, and smoke-check semantics.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a new tooling/report contract request. Source, docs, live issue context, and related-item inspection give high confidence that the unified upgrade-scan capability is still missing.

## Solution Assessment

Yes in direction, but only as a maintainer-defined orchestration/reporting layer over existing doctor, update, plugin, config, backup, and health-check contracts. A separate parallel validator would be too easy to drift from the real update/startup paths.
