## What This Changes

The issue requests automatic or configurable per-agent Bedrock requestMetadata on model calls so multi-agent Bedrock usage can be attributed per agent.

## Best Possible Solution

Keep this as a maintainer-owned Bedrock provider feature: choose the attribution policy first, then implement sanitized provider-owned requestMetadata handling with tests, docs, merge semantics, and redacted live AWS invocation-log proof.

## Maintainer Decision

Question: Should OpenClaw's Amazon Bedrock provider add per-agent requestMetadata automatically, expose an opt-in/configured metadata path, or leave cost attribution to AWS-native profile/IAM patterns?

Rationale: AWS records requestMetadata in invocation logs, warns against sensitive values, and says it is not a native Cost Explorer/CUR cost allocation tag, so this is a product and security policy choice before implementation. Likely owner: vincentkoc

Owner confidence: high

Options:

- **Opt-in minimized Bedrock metadata (recommended):** Add provider-owned support for sanitized, low-cardinality agent metadata or templates, document log-based attribution, and require redacted AWS proof.
- **Automatic per-agent metadata:** Default-on injection maximizes coverage but intentionally sends local agent identity to AWS logs and needs explicit acceptance of that privacy tradeoff.
- **Document AWS-native attribution:** Keep runtime unchanged and guide users toward application inference profiles, IAM principal attribution, Projects, or Workspaces for native billing attribution.
