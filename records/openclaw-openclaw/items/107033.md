## Label Justifications

- `impact:ux-release-blocker`: The documented setup path lacks an in-product warning or recovery flow before the installed node becomes unreachable.

## Summary

Current main still exposes the reported failure: Linux node installation creates a user service without applying the existing linger flow, and all relevant node docs omit the persistence requirement. Two open pull requests explicitly target this issue, so it should remain open until one canonical fix is reviewed and merged.

## What This Changes

Document and enforce Linux systemd lingering for installed node services so headless nodes remain online after SSH logout.

## Best Possible Solution

Reuse the existing Gateway linger flow after node service installation: attempt non-interactive enablement, preserve an actionable human and JSON warning when denied, document recovery in node setup, CLI, and troubleshooting pages, and cover Linux, non-Linux, ordering, and structured-output behavior.
