## Label Justifications

- `P0`: A headless node can appear successfully installed and then become unreachable immediately after the setup SSH session ends, with no in-product recovery path.
- `impact:crash-loop`: The issue concerns process-level node availability and reports that conflicting recovery services can enter repeated failure cycles.
- `impact:ux-release-blocker`: Recovery after the silent disconnect can require terminal expertise, manual service repair, or physical access to the node.

## Summary

Keep this canonical issue open: current main still documents `openclaw node install` as a persistent background service without warning that a Linux systemd user service can stop after logout, and two unmerged closing pull requests are competing to fix that gap. ([docs.openclaw.ai](https://docs.openclaw.ai/nodes))

## What This Changes

Ensure Linux node services remain available after logout by handling disabled systemd lingering and documenting the required recovery command.

## Best Possible Solution

Reuse the established gateway linger helper after successful Linux node-service installation, attempt non-interactive enablement, return an explicit text/JSON warning with `loginctl enable-linger <user>` when denied, document the requirement, and prove the full SSH-logout persistence path before landing.
