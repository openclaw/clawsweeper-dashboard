## What This Changes

The PR changes duplicate model-alias handling to log a warning and retain the first matching configured model instead of silently retaining the last.

## Best Possible Solution

Centralize duplicate detection so every alias consumer uses one precedence rule, preserve current last-wins behavior by default while warning with both targets, and add focused tests proving direct resolution and alias-index callers agree; change precedence only with explicit maintainer approval and upgrade documentation.

- **Reject duplicate aliases:** Make duplicate aliases a validated configuration error with an in-product diagnostic and a doctor-assisted recovery path rather than choosing either entry silently.
