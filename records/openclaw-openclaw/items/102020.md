## Summary

Keep open. Multiple independent reports establish a serious reply-session initialization failure on OpenClaw 2026.6.11, including silent inbound-message loss across several channels; the supplied discussion suggests one metadata-only revision variant was addressed, but it also documents a later cache/hydration divergence variant that still needs current-main and current-release verification. Likely related people: harjothkhara (adjacent root-cause investigator, low confidence) and aspalagin (detailed reproduction investigator, low confidence).

## What This Changes

Fix reply-session initialization conflicts that can reject a follow-up inbound message before an agent run starts, leaving the message dropped, retried indefinitely, or surfaced as an error depending on the channel.

## System Context

Inbound channel messages resolve a persistent reply-session entry before handing the turn to the auto-reply runtime. That initialization uses a session revision to avoid committing over another writer; a false conflict currently causes the channel dispatch to fail before the agent can record or answer the inbound turn.

## Best Possible Solution

Verify the deterministic cache/hydration and metadata-drift cases on current main and the current release; if either remains, make reply-session revision comparison canonical and ensure a conflict refreshes stale writer state before retrying, with regression coverage and channel-level proof that the inbound message is neither lost nor poison-retried.
