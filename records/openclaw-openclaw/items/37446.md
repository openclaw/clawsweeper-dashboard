## Summary

Keep open: current main has gateway exact-key idempotency and the merged message-tool retry mitigation, but it still does not provide durable logical-action identity or replay semantics for arbitrary sub-agent side effects after a lost acknowledgement. The linked ClawHub skill is useful operator guidance, not a substitute for a core contract if maintainers want this guarantee in OpenClaw.

## What This Changes

The issue requests durable idempotency or replay detection for sub-agent POST side effects when a successful server-side commit loses its client acknowledgement and the retry creates duplicate actions.

## Best Possible Solution

Define a narrow durable logical-action idempotency contract for sub-agent/tool side effects, including target scope, payload digest, expiry, result replay, and audit behavior, then prove it with a lost-ack regression or live scenario.
