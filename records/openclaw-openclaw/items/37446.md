## Summary

Keep open: current main has exact-key idempotency for gateway/message-tool retries, but it still does not provide the durable logical-action identity and replay semantics needed for arbitrary sub-agent POST side effects after a lost acknowledgement.

## What This Changes

The issue requests a core idempotency/recovery contract so sub-agent timeout retries do not duplicate externally committed POST actions.

## Best Possible Solution

Define a narrow durable logical-action idempotency contract for sub-agent/tool side effects, including target scope, payload digest, expiry, result replay, and audit behavior, then prove it with a lost-ack regression or live scenario.
