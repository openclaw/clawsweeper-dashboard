## Summary

Keep open: current main has exact-key gateway/message-tool retry mitigation, but it still lacks the durable logical-action identity and claim/replay semantics needed to prevent arbitrary sub-agent POST side effects from being duplicated after a lost acknowledgement.

## What This Changes

The issue requests durable idempotency for sub-agent timeout recovery so one logical POST side effect cannot be replayed as duplicate comments or actions.

## Best Possible Solution

Define a narrow durable logical-action idempotency contract for sub-agent/tool side effects, including target scope, payload digest, expiry, result replay, and audit behavior, then prove it with a lost-ack regression or live scenario.
