## Summary

Keep this issue open for a maintainer product decision. The current shared newline planner intentionally packs short adjacent paragraphs, while the linked open PR proposes changing that cross-runtime, cross-channel contract; a Codex-only or WhatsApp-only split would create an inconsistent second policy.

## What This Changes

The request is to make newline-mode automatic replies preserve blank-line-separated paragraphs as separate outbound WhatsApp bubbles when Codex supplies the reply as one accumulated text payload.

## System Context

Automatic visible replies flow from an agent runtime into the shared outbound message planner, which converts text into channel send units before WhatsApp delivers them. Codex commonly provides one final accumulated text item, so paragraph grouping is decided by the common planner rather than by WhatsApp after delivery.

## Architecture Diagram

  B --> C[Automatic visible reply]
  C --> D[Shared newline planner]
  D --> E[Outbound message units]
  E --> F[WhatsApp bubbles]

## Best Possible Solution

Maintain one explicit shared newline-to-message-boundary contract across runtimes and channels; if maintainers choose paragraph preservation, land a refreshed shared-planner change with compatibility coverage rather than adding a Codex projector or WhatsApp-specific heuristic.
