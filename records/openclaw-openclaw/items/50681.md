## Summary

Keep open: current main and v2026.6.11 still only deny/drop unknown Telegram groups, while the requested optional warn/leave config and runtime behavior are absent; the paired implementation PR at https://github.com/openclaw/openclaw/pull/50682 is closed unmerged, so the remaining action is maintainer product/security direction.

## What This Changes

Request a Telegram config and runtime path to ignore, warn, or auto-leave groups not allowed by `channels.telegram.groups` before assistant execution.

## Best Possible Solution

Maintainers should choose a narrow opt-in Telegram design that preserves existing deny/drop defaults, triggers only on a non-allowlisted chat decision, updates schema/types/docs, covers native commands and normal messages consistently, and requires live Telegram warn/leave proof before closing this issue.
