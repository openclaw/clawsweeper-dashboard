## Summary

Keep open: current main and v2026.6.11 still deny non-allowlisted Telegram groups by dropping/logging normal messages or sending a static native-command denial, while the requested configurable warn/leave behavior remains unmerged in the paired open PR that needs maintainer product and security review.

## What This Changes

Request a Telegram config path that rejects non-allowlisted groups before assistant execution, optionally warns with cooldown, and can leave the group automatically.

## Best Possible Solution

Review and either land, revise, or replace the paired Telegram PR with a narrow opt-in Telegram plugin implementation that updates schema/types/docs, shares behavior across normal messages and native commands, rate-limits warnings, preserves forum-topic delivery, and proves real Telegram warn/leave behavior.

## Solution Assessment

Unclear until maintainers decide the product and security semantics. The requested shape is plausible, but the best implementation must be opt-in, narrowly classify unknown groups, and be proven against real Telegram behavior before the issue closes.
