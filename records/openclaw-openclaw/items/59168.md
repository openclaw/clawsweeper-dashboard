## Summary

Keep open. Current main and the latest release still use provider/model-id as the selectable model identity, while this proposal asks for a new model-profile/API-id contract that needs maintainer product and migration direction.

## What This Changes

Request to use provider/name as the internal model key, reserve id for the upstream API model id, and allow model-profile reasoning levels.

## Best Possible Solution

Maintain this as the canonical design issue until maintainers choose one model-profile/API-id contract and land schema, runtime resolution, UI/session state, docs, and doctor migration together.
