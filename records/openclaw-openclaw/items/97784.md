## Summary

No blocking findings. The PR remains useful because current main still has seven unbounded MSTeams graph-upload success JSON reads, while the branch swaps those exact reads to the shared bounded provider JSON helper and adds focused loopback proof.

## What This Changes

The branch replaces seven MSTeams graph-upload success-path `res.json()` calls with `readProviderJsonResponse` and adds loopback tests for normal, malformed, and oversized JSON responses.

## Best Possible Solution

Land the narrow helper reuse after maintainers accept the standard 16 MiB fail-closed cap for graph-upload success responses, and track other MSTeams raw JSON readers separately.

## Reproduction Assessment

Yes. Current main has raw `res.json()` reads on graph-upload success paths, so an oversized streaming success response can still exercise an unbounded read; I did not run a local repro because this review is read-only.

## Solution Assessment

Yes. Reusing the existing public `openclaw/plugin-sdk/provider-http` bounded JSON reader is the narrowest maintainable fix for this module; a custom MSTeams reader would duplicate shared provider behavior.
