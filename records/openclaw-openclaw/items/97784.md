## Summary

Keep open: current main and the latest release still use unbounded successful `res.json()` reads in MSTeams graph-upload, while this PR cleanly switches those paths to the shared bounded provider JSON reader and now has sufficient loopback proof with no blocking findings.

## What This Changes

The PR replaces seven MSTeams graph-upload successful `res.json()` reads with `readProviderJsonResponse` and adds loopback tests for normal, malformed, and oversized JSON responses.

## Best Possible Solution

Land the narrow graph-upload helper reuse after normal maintainer review, and track broader MSTeams response-read hardening in separate focused PRs.

## Reproduction Assessment

Yes from source: current main and `v2026.6.11` route MSTeams graph-upload success responses through raw `res.json()`, so an oversized streaming success body can exercise the unbounded read path. I did not run a live tenant repro in this read-only review.

## Solution Assessment

Yes. Reusing the existing public `openclaw/plugin-sdk/provider-http` bounded JSON helper is the narrowest maintainable fix for this graph-upload scope; broader raw JSON reads are distinct follow-ups.
