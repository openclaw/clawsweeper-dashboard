## Label Justifications

- `P1`: The failure repeatedly disables all inbound Telegram delivery for hours while appearing to restart, requiring a full gateway restart to recover.
- `impact:message-loss`: Telegram retains inbound updates upstream, but OpenClaw stops fetching and delivering them until the gateway is restarted.

## Summary

Keep open: the report provides a repeated, specific message-loss signature, and current main still has a separate gateway restart handoff where Telegram stop releases the polling lease before a later start call; the evidence does not show that v2026.7.1 or current main reliably handles a failed or hung stop-to-start transition.

## What This Changes

Make Telegram health-monitor recovery reliably restart long polling after a stopped lease, with bounded retries and explicit failure diagnostics.

## Best Possible Solution

Make per-account health-monitor restarts a serialized, observable operation: bound stop completion, clear stale lifecycle state, start exactly one replacement provider, log and retry failed starts with backoff, and add a regression test for a disconnect arriving during Telegram polling shutdown.
