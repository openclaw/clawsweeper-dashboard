## Summary

Keep open: this is a focused Discord bug-fix PR for a real linked formatting issue, but the current patch is not merge-ready because the one-line guard can leave code-start chunks with orphan trailing italics markers, and the external proof is still test-only.

## What This Changes

The PR changes Discord reply chunking to avoid prepending the reasoning italics opener when the next chunk begins with a backtick, and adds regression tests for code-fence and inline-code chunk starts.

## Best Possible Solution

Update the rebalance logic and tests so code-start chunks neither begin with an underscore before backticks nor carry orphan closing underscores, then add real Discord/render-path proof before merge.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source inspection: current main's rebalanceReasoningItalics prepends '_' to any following reasoning chunk that does not already start with '_', so a split before a code fence or inline-code backtick produces an '_`' prefix. I did not run the test suite because this review is read-only.

## Solution Assessment

No: skipping only the opener is too narrow because the helper still appends or preserves closing italics markers on the code-start chunk. The safer fix should preserve the existing balanced-marker invariant while keeping backtick fences and inline code unprefixed.

Full review comments:

- **[P2] Keep code-start chunks' italics markers balanced:** `extensions/discord/src/chunk.ts:325`
  - body: When this skips reopening italics for a chunk that starts with a backtick, the rest of the helper still treats that chunk as part of the `_..._` wrapper: the previous chunk may get a closing `_`, and the code-start chunk can still carry the source's final `_` or receive a closing `_` later. That allows outputs such as a second inline-code chunk ending in a lone `_`, violating the existing balanced-marker invariant and leaving Discord with malformed markdown. The fix needs to suppress or pair the corresponding closing marker for code-start chunks, and the new tests should assert the emitted reasoning chunks remain balanced.
  - confidence: 0.88
