## Summary

Keep this PR open: current main still only treats explicit `SlackRetryableInboundError` instances as retryable, while this branch adds focused Slack retry handling for wrapped reply-session initialization conflicts and covers the native, relay, and already-delivered replay cases. I found no blocking patch findings; the maintainer label means this should continue through normal maintainer and required-check handling rather than cleanup closure.

## What This Changes

The branch updates Slack message handling to recognize wrapped reply-session initialization conflicts as retryable inbound failures, avoid recording transient failed deliveries, and add regression tests for native retry, relay redelivery ownership, and already-delivered relay replays.

## Best Possible Solution

Land the focused Slack handler fix after normal maintainer review and required checks, keeping retry ownership split between native Slack retries and relay redelivery as the PR now does.

## Solution Assessment

Yes. The Slack message handler is the narrow owner boundary because it owns Slack inbound delivery persistence, seen-message release, and relay ack behavior; the PR avoids moving policy into core and keeps relay retries owned by router redelivery.
