## Summary

Keep open for product/API review. Current main still exposes a flat prompt-visible catalog of eligible skills; it mitigates oversized catalogs through budgeting and compact formatting, but does not provide declared dependency graphs, graph-driven runtime expansion, or graph CLI output. The runtime portion overlaps related open proposals, while visualization already has an external implementation, so the remaining core direction needs consolidation rather than an autonomous fix.

## What This Changes

Add declared skill dependency graphs, demand-driven dependency expansion, DOT graph output, and configurable traversal depth to reduce prompt token overhead.

## Best Possible Solution

Consolidate core token optimization around one explicit, evaluated skill-discovery contract—prefer declared metadata or a search/index API over parsing runtime calls—while keeping graph visualization in the existing external tool unless a concrete missing core API is identified; add config only after defaults, fallback discovery, and quality/token benchmarks are agreed.
