## Summary

Keep open. Current main still has only partial `message_sending` coverage: shared routed sends run the hook, but configured dispatcher `beforeDeliver` paths omit it, Signal replies still send directly, Discord preview-final edits bypass the shared send path, and hook failures remain fail-open.

## What This Changes

Request to make every outbound message pass through a single pre-send policy boundary that can validate, rewrite, or block delivery.

## Best Possible Solution

Define a versioned core outbound lifecycle for user-visible sends, migrate direct and streaming/edit paths onto it, and document intentional non-user-content exceptions.

## Reproduction Assessment

Yes. Source-level reproduction is high confidence: current main still has configured `beforeDeliver`, Signal direct-send, Discord preview-edit, and fail-open hook paths that do not satisfy the requested unbypassable boundary.

## Solution Assessment

Unclear pending maintainer design. A unified pre-send boundary is the right end state, but maintainers need to decide whether `message_sending`, a new versioned outbound policy API, or both own fail-closed semantics and streaming/edit behavior.
