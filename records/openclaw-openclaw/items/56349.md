## Summary

Keep open. Current main still has only partial outbound pre-send coverage: shared delivery can run `message_sending`, but configured dispatcher paths can omit it, Signal replies send directly, Discord edit/final paths are separate, and hook failures remain fail-open.

## What This Changes

The issue requests a single unbypassable outbound pre-send policy boundary that can validate, modify, or block all user-visible outbound messages before channel delivery.

## Best Possible Solution

Define one versioned core outbound lifecycle for user-visible sends, migrate remaining direct and streaming/edit paths onto it, and document intentional non-user-content exceptions.

## Reproduction Assessment

Yes. Current-main source deterministically shows channel-configured delivery can skip `message_sending`, and the test suite asserts that omission.

## Solution Assessment

Unclear pending maintainer design. A unified pre-send boundary is the right end state, but maintainers need to decide whether `message_sending`, a new versioned outbound policy API, or both own fail-closed semantics and streaming/edit behavior.
