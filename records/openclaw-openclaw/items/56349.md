## Summary

Keep open. Current main and v2026.6.11 still have only partial pre-send coverage: shared outbound delivery can run `message_sending`, but configured dispatcher paths can omit it, Signal replies still send through their channel delivery path, and hook failures remain fail-open.

## What This Changes

The issue requests a single non-bypassable pre-send outbound policy boundary that can validate, modify, or block all channel-bound messages.

## Best Possible Solution

Define one versioned outbound lifecycle for every user-visible send, migrate remaining direct and streaming/edit paths onto it, and document intentional non-user-content exceptions.

## Reproduction Assessment

Yes at source level. Current main deterministically shows configured dispatcher paths can omit `message_sending`, the test suite pins that omission, and Signal reply delivery still follows a direct channel path; I did not run live channel traffic.

## Solution Assessment

Unclear pending maintainer design. A unified pre-send boundary is the right end state, but maintainers need to choose whether `message_sending`, a new versioned outbound policy API, or both own fail-closed behavior and streaming/edit semantics.
