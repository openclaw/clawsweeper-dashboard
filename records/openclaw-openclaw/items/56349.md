## Summary

Keep open. Current main and v2026.6.11 still provide only partial `message_sending` coverage: configured dispatcher delivery can skip it, Signal monitor replies still send directly, and hook failures still fail open, so the requested unbypassable pre-send guarantee is not implemented.

## What This Changes

The issue requests a guaranteed pre-send outbound policy boundary that can validate, rewrite, or block every user-visible outbound message before channel delivery.

## Best Possible Solution

Define one versioned outbound lifecycle boundary for user-visible sends, migrate direct and streaming/edit delivery paths onto it, and document intentional non-user-content exceptions.

Options:

- **Design a versioned policy API (recommended):** Create a dedicated outbound policy contract that can be fail-closed, audited, scoped, and documented without overloading existing best-effort hook semantics.
- **Elevate message_sending:** Make `message_sending` the universal exactly-once fail-closed gate and migrate all direct delivery paths onto that contract.
- **Keep hooks advisory:** Document that strict DLP and compliance enforcement are not guaranteed by current hook surfaces and keep policy enforcement outside core for now.
