## Summary

Keep open. Current main and the latest release still provide only partial pre-send coverage: shared delivery can run `message_sending`, but channel-configured dispatcher paths can skip it, hook failures remain fail-open, and narrower open issues/PRs cover only subsets of this umbrella.

## What This Changes

Request a single enforceable outbound pre-send policy boundary that every user-visible outbound path must pass through before channel delivery.

## Best Possible Solution

Define one versioned outbound lifecycle for user-visible sends, migrate remaining direct and streaming/edit paths onto it, and document intentional non-user-content exceptions plus fail-closed behavior.

## Reproduction Assessment

Yes. Current-main source shows configured dispatcher paths can skip `message_sending`, and the existing test suite asserts `runMessageSending` is not called on that branch.

## Solution Assessment

Unclear pending maintainer design. A unified pre-send boundary is the right end state, but maintainers need to decide whether `message_sending`, `reply_payload_sending`, a new versioned API, or a combination owns fail-closed semantics and streaming/edit behavior.
