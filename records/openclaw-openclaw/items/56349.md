## Summary

Keep open. Current main has several partial implementations of `message_sending` before delivery, but the requested unbypassable guarantee is still missing because at least the Signal reply path sends directly without an inspected pre-send hook, and the central durable path still fails open when the hook throws.

## What This Changes

The issue requests a single enforceable pre-send outbound policy boundary that can validate, modify, or block every outbound message path before channel delivery.

## Best Possible Solution

Define a single core/plugin-owned outbound policy contract with explicit fail-open or fail-closed semantics, then migrate every direct channel reply, tool, and send path to that boundary with cross-channel regression coverage.

- **Continue narrow channel repairs:** Track each missing channel or tool path separately while avoiding a global security guarantee until semantics are settled.
- **Document best-effort behavior:** Decline the unbypassable guarantee and document `message_sending` as useful but not security-grade enforcement.
