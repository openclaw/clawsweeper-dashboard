## Summary

Keep open. Current main and the latest release still have only partial pre-send coverage: shared outbound delivery can run `message_sending`, but configured dispatcher paths can omit it, some channel reply paths still send directly, and hook failures remain fail-open.

## What This Changes

The issue requests a single, unbypassable outbound pre-send policy boundary that can validate, rewrite, or block every user-visible outbound message path.

## Best Possible Solution

Define one versioned core outbound lifecycle for user-visible sends, migrate remaining direct and streaming/edit paths onto it, and document any intentional exceptions and fail-closed policy semantics.

## Reproduction Assessment

Yes. Current-main source deterministically shows configured dispatcher delivery can skip `message_sending`, Telegram supplies such a hook, and the current test suite asserts `runMessageSending` is not called on that path.

## Solution Assessment

Unclear pending maintainer design. A unified pre-send boundary is the right end state, but maintainers need to decide whether the existing `message_sending` hook, a new versioned outbound policy API, or both own fail-closed and streaming/edit semantics.
