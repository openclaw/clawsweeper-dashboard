## Summary

Keep open. Current main still has partial pre-send coverage: configured dispatcher paths can omit `message_sending`, Signal replies still send directly, and shared outbound delivery remains fail-open on hook errors, so the requested unbypassable policy boundary is not implemented.

## What This Changes

The issue requests a guaranteed pre-send outbound policy boundary so all outbound messages can be validated, modified, or blocked before channel delivery.

## Best Possible Solution

Define one versioned outbound lifecycle for user-visible sends, route remaining direct and channel-specific paths through it, and document intentional exceptions plus fail-closed/security semantics.

## Reproduction Assessment

Yes at source level: current main still has paths that omit `message_sending` before user-visible delivery, and a test asserts one omission. I did not run live channel traffic in this read-only workflow.

## Solution Assessment

Unclear pending maintainer design. A unified pre-send boundary is the right end state, but maintainers need to choose the versioned API, trusted plugin authority, fail-closed behavior, streaming/edit scope, and internal-hook relationship.
