## Summary

The branch addresses a real delegated-workflow failure, but its new subagent exemption removes the requester’s exact sender-policy ceiling rather than carrying it into the child. A sender-specific deny can therefore be bypassed by spawning a recognized subagent, so this needs a security-sensitive repair before merge.

## What This Changes

The PR skips `toolsBySender` resolution for recognized subagent sessions and adds resolver and effective-tool-policy coverage for an exact E164 allow policy, anonymous wildcard denial, and subagent restrictions.

## Best Possible Solution

Represent the parent’s resolved sender-policy ceiling in the spawned-session capability path, then intersect it with normal subagent restrictions so child sessions neither hit anonymous wildcard policy nor gain tools denied to their requester.

No. Skipping the child lookup is only safe if the already-resolved requester ceiling is carried forward; otherwise the patch trades wildcard denial for a sender-policy authorization bypass.
