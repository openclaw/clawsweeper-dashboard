## Summary

Keep open: current main and the latest release contain internal Gateway client/App SDK groundwork, but the requested public, installable, platform-agnostic Gateway WebSocket client SDK is still not available and needs maintainer product/security direction.

## What This Changes

The issue requests a reusable `@openclaw/gateway-client` package for external apps to connect to the Gateway WebSocket protocol instead of reimplementing CLI and Control UI client behavior.

## Best Possible Solution

Keep the internal extracted package as groundwork, then have maintainers decide whether the supported public external-client contract should be the higher-level `@openclaw/sdk`, a published low-level `@openclaw/gateway-client`, or both with clearly documented security and compatibility boundaries.
