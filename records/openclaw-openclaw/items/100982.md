## Label Justifications

- `P1`: The issue describes a source-backed compaction loop that can keep long-running channel sessions from reclaiming context and repeatedly reprocess growing transcripts.
- `impact:session-state`: The affected behavior is session transcript compaction and replay state, where malformed compaction telemetry prevents truncation from taking effect.

## Summary

Keep open: current main still has the source-backed path where delivery-mirror-shaped usage can produce non-finite `tokensBefore`, and the transcript reader still rejects compaction entries unless `tokensBefore` is numeric. The latest release also has the same consumer guard, while three linked fix PRs are still open rather than merged.

## What This Changes

The issue asks OpenClaw to stop malformed delivery-mirror token telemetry from invalidating compaction records and preventing transcript truncation.

## Best Possible Solution

Land one focused fix that prevents synthetic transcript-only assistant rows from poisoning token sampling, clamps or falls back from non-finite token telemetry before persistence, and keeps replay from discarding otherwise valid compaction summaries solely because telemetry is malformed.

## Reproduction Assessment

Yes, source-reproducible: current main can calculate non-finite `tokensBefore` from malformed assistant usage and later reject the JSON round-tripped compaction record because `tokensBefore` is no longer numeric. I did not run a live long-session Telegram or safeguard compaction reproduction.

## Solution Assessment

Yes, the requested layered repair is the maintainable shape: protect the usage sampler/producer boundary and make compaction replay tolerate bad telemetry. A consumer-only relaxation is a useful mitigation but should not be the only durable fix if malformed usage can keep propagating.
