## Summary

Keep open. Current main still has the core source path for malformed assistant usage to produce non-finite compaction token counts while successor transcript loading still requires a numeric `tokensBefore`, so the reported session-state bug is not fixed or superseded.

## What This Changes

The issue reports that delivery-mirror usage can poison compaction `tokensBefore`, causing transcript truncation to reject the compaction boundary and repeatedly recompact long-running channel sessions.

## Best Possible Solution

Normalize or skip transcript-only/malformed assistant usage before compaction, ensure `tokensBefore` is finite or estimated before persistence, and harden successor transcript loading so telemetry cannot invalidate an otherwise valid compaction boundary.

Yes, source-reproducible but not live-reproduced in this review. A malformed/OpenAI-style assistant usage object can produce `NaN` in `calculateContextTokens`, JSONL serialization can turn that into `null`, and `readTranscriptFileState` rejects compaction records whose `tokensBefore` is not a number.

## Solution Assessment

Yes, the issue's suggested producer plus consumer hardening is the right direction. The narrow maintainable fix should avoid new config, normalize/ignore poisoned usage at the compaction boundary, and ensure valid compaction records remain usable even when telemetry is bad.

## Repair Work Prompt

Fix the delivery-mirror/usage compaction `tokensBefore` poisoning path without adding config or changing compaction policy. On current main, `calculateContextTokens` in `packages/agent-core/src/harness/compaction/compaction.ts` can return `NaN` when usage has OpenAI-style aliases such as `total_tokens`, `prompt_tokens`, and `completion_tokens` but lacks top-level `totalTokens`, `cacheRead`, and `cacheWrite`; session compaction then persists `tokensBefore`, and `src/agents/embedded-agent-runner/transcript-file-state.ts` rejects a serialized `tokensBefore: null` compaction record during successor transcript assembly. Add focused coverage with a delivery-mirror or malformed-usage assistant immediately before compaction, prove compaction/append/rotation keeps a valid boundary and shrinks the successor transcript, and include both producer-side finite normalization or fallback and reader-side hardening for existing malformed compaction rows. Do not add a new config knob, do not change compaction trigger policy, and do not create a broad runtime compatibility path beyond bounded repair of malformed compaction telemetry.
