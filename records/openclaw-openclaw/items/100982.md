## Summary

Keep open: current main still has the source-backed path where `delivery-mirror` usage can poison `tokensBefore`, and the transcript loader still rejects compaction records whose `tokensBefore` is not numeric. Two closing PRs are open but unmerged, so this issue remains necessary until one reviewed fix lands.

## What This Changes

Report that delivery-mirror assistant usage can make compaction `tokensBefore` null or zero, causing transcript replay to reject compaction records and long-running sessions to compact without truncating.

## Best Possible Solution

Review and land one fix path that prevents transcript-only mirror rows from poisoning compaction telemetry, clamps or falls back from non-finite token estimates, and keeps valid compaction summaries from being rejected solely because telemetry is malformed.

## Solution Assessment

Yes, the requested layered repair is the right direction. The best implementation should protect both producer and consumer boundaries instead of only patching the replay guard or only normalizing one usage shape.
