## Summary

Keep open: current main and the latest shipped v2026.6.11 source still have the `tokensBefore` producer and replay-validator paths described here, and the two linked closing PRs are still open rather than merged.

## What This Changes

The issue reports a compaction bug where delivery-mirror usage can make `tokensBefore` serialize as `null`, causing transcript replay to reject compaction entries and fail to truncate sessions.

## Best Possible Solution

Land one layered fix that skips transcript-only mirror usage for sampling, prevents non-finite token counts from being persisted, and keeps replay from discarding otherwise valid compaction summaries; keep this issue open until that PR merges.
