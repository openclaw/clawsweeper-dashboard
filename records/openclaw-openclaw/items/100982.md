## Summary

Keep open: current main and v2026.6.11 still have the source-backed `tokensBefore` poisoning and compaction-record rejection path. Two open fix PRs already reference this issue, so the maintainer cleanup path is to review and land the best candidate rather than close or queue another repair.

## What This Changes

The issue reports that delivery-mirror assistant usage can produce non-finite `tokensBefore` telemetry, causing compaction records to be rejected and long-running sessions to keep replaying untruncated history.

## Best Possible Solution

Land one layered fix, preferably the broader candidate that skips transcript-only mirror rows for usage sampling, normalizes finite token telemetry, and keeps replay from discarding valid compaction summaries solely because telemetry is malformed.
