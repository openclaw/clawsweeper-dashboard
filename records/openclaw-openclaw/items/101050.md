## Label Justifications

- `P2`: This is a focused session-streaming bugfix PR, but the current patch has a blocking merge-risk finding before it can land.
- `merge-risk: 🚨 session-state`: A swallowed read error can make manual compaction rewrite transcript state from an incomplete stream.
- `merge-risk: 🚨 compatibility`: The PR changes the shared iterator from propagating read failures to reporting a clean truncated iteration, affecting existing caller error handling.

## Summary

Keep this PR open, but it is not merge-ready. The crash mitigation is plausible, but swallowing every read error inside the shared forward transcript iterator changes a fail-closed error contract into partial-success behavior for callers that may rewrite transcript state.

## What This Changes

The PR makes `streamSessionTranscriptLines` swallow mid-stream read errors and adds a Vitest regression plus a proof script for that behavior.

## Best Possible Solution

Keep stream read errors propagated by default and add an explicit tolerant mode or caller-local handling only for read-only paths that can safely accept truncated results.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, by source inspection. On the PR head, a read error after `trimSessionTranscriptForManualCompact` has read more than `maxLines` is swallowed as EOF, so the caller proceeds to transcript replacement with partial tail lines.

## Solution Assessment

No. The safer fix is to preserve error propagation for the shared iterator and make truncation-on-error an explicit read-only behavior where callers can prove partial results are safe.
