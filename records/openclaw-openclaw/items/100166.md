## Summary

Keep this PR open: the helper-based pagination direction is useful, but the patch still ties the Graph page size to the final reply window, so small `maxReplies` values can under-scan long threads before the 50-page cap and still miss the newest context. The external contributor proof is also unit/source-only; no redacted live Teams or Graph evidence is present yet.

## What This Changes

The PR changes Microsoft Teams `fetchThreadReplies` to follow Graph pagination, select a newest bounded reply window, and adds focused `graph-thread` unit coverage.

## Best Possible Solution

Keep the `fetchAllGraphPages` approach, but request full reply pages for scanning, use the clamped reply count only for the final newest-window slice, and require redacted live Teams or Graph proof unless a maintainer explicitly accepts the external-API risk.
