## Summary

Keep open: the central bug is valid, but this head still uses the requested reply limit as the Graph page size, so `maxReplies < 50` can scan too little of a long thread and still miss the newest context; the PR also still lacks live Teams or Graph proof.

## What This Changes

The branch changes Microsoft Teams `fetchThreadReplies` to follow Graph pagination, select a newest bounded reply window, and add unit coverage for paginated thread replies.

## Best Possible Solution

Keep the helper-level fix, but request full-page Graph scanning (`$top=50`) with `maxReplies` applied only after pagination, focused tests for small `maxReplies` on long threads, and redacted live Teams or Graph proof for an over-50-reply thread.
