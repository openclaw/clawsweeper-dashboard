## Summary

Keep open: current main and v2026.6.11 still lack a configurable reset greeting model, suppression flag, or unified reset-start policy; related open items cover prompt text or fallthrough behavior only partially.

## What This Changes

Allow users to configure how bare `/new` and `/reset` handle reset greetings, including using a cheaper greeting model or suppressing the greeting/model turn.

## Best Possible Solution

Define one maintainer-approved reset-start policy covering acknowledgements, startup/model turns, prompt text, greeting suppression, and optional greeting-model routing across schema, types, help, docs, auto-reply, Gateway, and tests.

## Maintainer Decision

Question: What public reset-start policy should OpenClaw expose for bare `/new` and `/reset` across static acknowledgements, startup/model turns, prompt text, greeting suppression, and optional cheaper greeting-model routing?

Rationale: The remaining work adds compatibility-sensitive config and changes session-start and model-routing semantics, so automation should not invent the key shape or default behavior.

Likely owner: steipete

Owner reason: This handle is tied to the current bare reset acknowledgement contract and prior policy review, making it the best available owner for the default/config decision.

Owner confidence: high

Options:

- **Define One Reset-Start Policy (recommended):** Add one typed policy that keeps defaults explicit and covers startup turns, prompt text, suppression, and greeting-model routing without separate competing knobs.
- **Restore Startup Turns By Default:** Make bare resets run the startup/model turn again and intentionally accept the token-cost, latency, and upgrade behavior change.
- **Defer New Reset Controls:** Keep acknowledgement-only behavior and leave users with `/new <message>` plus the narrower prompt-text and fallthrough discussions until a broader policy is approved.

## Reproduction Assessment

Yes, at source level for the missing capability. Current main and v2026.6.11 have static acknowledgement paths and hardcoded reset prompts, while strict schemas lack the requested greeting model, suppression, or unified reset-start policy keys.

## Solution Assessment

Unclear until maintainers choose the reset-start contract. A standalone `resetGreetingModel` or `resetGreeting` flag is plausible, but the safer solution is one typed policy that aligns prompt text, startup turns, suppression, model routing, and Gateway behavior.
