## Summary

Keep open: current main and the latest release already avoid the original token spend for ordinary bare reset commands by returning fixed acknowledgements, but the requested public policy is still missing because users cannot opt into a cheaper reset-specific greeting model, suppress or restore greeting behavior via config, or align this with the related prompt/fallthrough issues.

## What This Changes

Request to add a configurable reset-start greeting policy so bare `/new` and `/reset` can suppress the model turn or use a cheaper reset-specific model.

## Best Possible Solution

Define one maintainer-approved reset-start policy covering acknowledgement-only resets, optional startup/greeting turns, prompt customization, reset-specific model routing, schema/types/help/docs, and focused tests across auto-reply and Gateway.

## Reproduction Assessment

Yes, at source level. Current main has acknowledgement-only bare reset paths, a hardcoded downstream reset prompt for model-run resets, and strict config schemas with `startupContext` but no reset greeting model or reset greeting policy key.

## Solution Assessment

Unclear. The issue identifies a real reset-start policy gap, but adding the proposed keys independently is not the best fix until maintainers choose one typed cross-surface policy and default behavior.
