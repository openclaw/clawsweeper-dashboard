## Summary

Keep open: current main and v2026.6.11 do not provide a reset-greeting policy, cheaper reset-greeting model, or suppress-greeting config. Ordinary bare chat and Gateway resets now use static acknowledgements, while the downstream reset model path still has a hardcoded greeting prompt when reached, so this remains a real cross-surface product/config decision rather than cleanup.

## What This Changes

Request to let users choose a cheaper model for bare `/new` and `/reset` greeting turns or suppress that greeting/model turn entirely.

## Best Possible Solution

Define one maintainer-approved reset-start policy covering acknowledgement-only resets, optional startup/greeting turns, prompt customization, and reset-specific model routing across schema, auto-reply, Gateway, docs, and tests.

## Reproduction Assessment

Yes, at source level: current main has acknowledgement-only bare reset paths, a hardcoded downstream reset prompt, and no reset greeting model or reset greeting policy key in strict config schemas. I did not run a live Gateway scenario for this read-only review.

## Solution Assessment

Unclear. The issue identifies a real reset-start policy gap, but the proposed separate keys should wait until maintainers choose one typed cross-surface policy and default behavior.
