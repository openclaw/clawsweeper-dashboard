## Summary

Keep open: current main and v2026.6.11 still have hardcoded bare-reset acknowledgement behavior and no public reset-greeting model, suppression flag, or unified reset-start policy; related items cover prompt text or fallthrough behavior but do not fully own this config/product decision.

## What This Changes

Request to let users configure bare `/new` and `/reset` greeting behavior, either by routing the greeting through a cheaper model or suppressing the model-generated greeting.

## Best Possible Solution

Define one maintainer-approved reset-start policy that covers acknowledgements, startup/model turns, prompt text, greeting suppression, and optional greeting-model routing across auto-reply, Gateway, schema, docs, and tests.
