## Summary

Keep open: current main and v2026.6.11 remove the original token-burn path for ordinary bare resets by returning static acknowledgements, but they still do not provide the requested configurable reset-greeting policy, cheaper greeting model routing, or cross-surface restore/suppress behavior.

## What This Changes

The issue requests a config-supported way to use a cheaper model for bare `/new` and `/reset` greetings or suppress that greeting entirely.

## Best Possible Solution

Define one reset-greeting policy for chat acknowledgements, reply-producing reset turns, and Gateway agent resets, with schema/types/help/docs/tests covering suppression, explicit model selection, and the chosen default.
