## Summary

Keep open: current main and the latest release avoid token burn for ordinary bare resets by acknowledging without a model turn, but the requested configurable reset-start policy and cheaper reset greeting model still do not exist.

## What This Changes

Request to add configurable `/new` and `/reset` greeting behavior, either by routing the greeting through a cheaper model or suppressing the greeting/model turn.

## Best Possible Solution

Define one maintainer-approved reset-start policy covering acknowledgement-only resets, optional startup/greeting turns, prompt customization, and reset-specific model routing across schema, runtime, Gateway, docs, and tests.

## Reproduction Assessment

Yes, at source level: current main has acknowledgement-only bare reset paths, a hardcoded downstream reset prompt, and no reset greeting model or reset greeting policy key in strict config schemas. I did not run a live Gateway scenario for this read-only review.

## Solution Assessment

Unclear. The request identifies a real reset-start policy gap, but the proposed separate keys should not be added independently before maintainers choose one typed cross-surface policy and default behavior.
