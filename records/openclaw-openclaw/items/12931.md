## Summary

Keep open: current main and v2026.6.11 already avoid the original bare-reset token burn with static acknowledgements, but the requested configurable reset-greeting policy and cheaper greeting model route still do not exist and need maintainer product direction.

## What This Changes

The issue requests a public configuration surface to choose a cheaper model for, or suppress, the model-backed greeting after bare `/new` or `/reset`.

## Best Possible Solution

Define one typed reset-start policy covering acknowledgement-only resets, startup/model turns, prompt text, optional greeting model routing, bootstrap safeguards, schema/help/docs, and focused tests.
