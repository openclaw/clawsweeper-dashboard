## Summary

Keep open: current main and v2026.6.11 cover the cheapest ordinary bare reset path with static acknowledgements, but they do not add a configurable reset-greeting model, suppression policy, or unified reset-start contract; related open items only partially overlap.

## What This Changes

Request configurable bare `/new` and `/reset` greeting behavior, either by selecting a cheaper greeting model or suppressing the model-run greeting.

## Best Possible Solution

Define one maintainer-approved reset-start policy covering ack-only resets, startup/model turns, prompt text, greeting suppression, optional greeting-model routing, docs, and tests across auto-reply and Gateway.

## Solution Assessment

Unclear until maintainers choose the reset-start contract. A standalone `resetGreetingModel` or `resetGreeting` flag is plausible, but the safer solution is one typed policy that aligns prompt text, startup turns, suppression, model routing, and Gateway behavior.
