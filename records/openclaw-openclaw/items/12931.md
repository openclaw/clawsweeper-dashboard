## Summary

Keep open: current main and v2026.6.11 avoid the ordinary bare reset model turn with static acknowledgements, but the requested typed reset-greeting policy, cheaper greeting model routing, and configurable suppression/restoration semantics are still missing.

## What This Changes

Request to add configuration for bare `/new` or `/reset` greetings so users can choose a cheaper greeting model or suppress the greeting/model turn.

## Best Possible Solution

Define one maintainer-approved reset-start policy covering acknowledgement-only resets, startup-turn greetings, optional greeting-model routing, prompt text behavior, and Gateway/auto-reply parity before adding public config.

## Reproduction Assessment

Yes. Source inspection confirms current main and v2026.6.11 lack the requested config keys and either acknowledge bare resets without a model turn or use the hardcoded reset prompt when a model path is reached.

## Solution Assessment

Unclear. The request identifies a real gap, but the best fix is a unified reset-start policy rather than an ad hoc single config key that could conflict with prompt text, startup context, Gateway behavior, or provider routing.
