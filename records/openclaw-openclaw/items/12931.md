Keep open: current main and v2026.6.11 suppress ordinary bare reset model turns with fixed acknowledgements, but there is still no typed reset-greeting policy or reset-specific cheaper model routing, and related open items cover adjacent prompt text or fallthrough behavior rather than replacing this broader product decision.

## What This Changes

Request to add a configurable bare reset greeting policy, including cheaper reset greeting model routing and/or suppressing the model-generated greeting for `/new` and `/reset`.

## Best Possible Solution

Define one maintainer-approved reset-start policy covering acknowledgement-only resets, optional startup/greeting turns, prompt customization, and reset-specific model routing across schema, auto-reply, Gateway, docs, and tests.
