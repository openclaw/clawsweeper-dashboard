## Summary

Keep open: current main and v2026.6.11 avoid the original bare-chat token burn by returning static acknowledgements, but the requested reset-greeting policy, cheaper greeting model routing, and configurable suppress/restore behavior are still missing and overlap active product-direction work.

## What This Changes

The issue requests a configurable model for the bare `/new` or `/reset` greeting turn, or an option to suppress that greeting entirely.

## Best Possible Solution

Define one typed reset-greeting policy across bare chat acknowledgements, reply-producing reset turns, and Gateway agent resets, with schema/help/docs/tests covering suppress/static-ack/greeting-model behavior and preserving an intentional default.
