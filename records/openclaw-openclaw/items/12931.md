## Summary

Keep open: current main and v2026.6.11 still lack a maintainer-approved reset-start policy for cheaper greeting-model routing, explicit greeting suppression, or opt-in startup/model turns; this remains a product/config decision rather than cleanup-close material.

## What This Changes

The issue asks for configurable bare `/new` and `/reset` greeting behavior, either by routing that greeting through a cheaper model or suppressing the model greeting entirely.

## Best Possible Solution

Define one maintainer-approved reset-start policy that covers acknowledgement-only resets, startup/model turns, prompt text, greeting suppression, and optional greeting-model routing across auto-reply, Gateway, schema, docs, and tests.
