## Summary

Keep open: current main and v2026.6.11 have partially addressed the original token-cost concern by making ordinary bare reset commands acknowledgement-only, but OpenClaw still lacks the requested typed reset-greeting policy for suppression, cheaper greeting model routing, or intentional startup-turn restoration.

## What This Changes

Requests public configuration to use a cheaper model for bare `/new` and `/reset` greetings or suppress those greetings entirely.

## Best Possible Solution

Define one maintainer-approved reset-greeting policy that covers acknowledgement-only resets, startup-turn greetings, optional cheaper model routing, prompt text customization, Gateway/auto-reply parity, config schema/help/docs, and upgrade expectations.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 show terminal acknowledgements for ordinary bare reset commands, while strict config schemas do not accept the requested reset-greeting suppression or model-routing keys.

## Solution Assessment

Unclear. The request identifies a real product gap, but the best fix is not an ad hoc single key; maintainers need to choose one reset-start policy that aligns config, model routing, prompt text, Gateway behavior, docs, and tests.
