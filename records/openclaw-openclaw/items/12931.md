## Summary

Keep open: current main and v2026.6.11 still do not provide a configurable reset-greeting model or suppression policy. Ordinary bare chat and Gateway reset paths now use static acknowledgements, while related prompt/fallthrough items only cover adjacent parts of the broader reset-start contract.

## What This Changes

The issue requests a configurable reset-greeting policy so bare `/new` or `/reset` can use a cheaper model or suppress the model greeting entirely.

## Best Possible Solution

Define one typed reset-start policy covering acknowledgement-only resets, startup/model turns, prompt text, optional greeting model routing, bootstrap/current-time safeguards, schema, docs, and focused tests.
