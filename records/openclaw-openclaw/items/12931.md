Keep open: current main and v2026.6.11 still do not provide a public reset-greeting model, suppression flag, or unified reset-start policy; the existing work only covers static acknowledgements and startup-context prelude behavior.

## What This Changes

The issue requests configurable bare `/new` and `/reset` greeting behavior, including using a cheaper greeting model or suppressing the model-generated greeting entirely.

## Best Possible Solution

Define one maintainer-approved reset-start policy that covers acknowledgements, startup/model turns, prompt text, greeting suppression, and optional greeting-model routing across auto-reply, Gateway, schema, docs, and tests.
