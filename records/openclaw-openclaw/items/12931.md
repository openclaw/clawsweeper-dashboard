## Summary

Keep open: current main and v2026.6.11 avoid the original ordinary bare-reset token burn by returning static acknowledgements, but OpenClaw still lacks a typed reset-start policy for suppression, prompt customization, and cheaper greeting-model routing. The related open items cover prompt text or restoring greeting fallthrough, not this full config/product decision.

## What This Changes

This issue requests configuration for bare `/new` and `/reset` to either suppress the reset greeting or run it with an explicit cheaper model.

## Best Possible Solution

Define one typed reset-start policy covering acknowledgement-only resets, startup/model turns, prompt text, optional greeting-model routing, bootstrap safeguards, schema, docs, and focused tests.
