Keep open: current main and v2026.6.11 still lack a typed reset-greeting policy, cheaper greeting model routing, and configurable restore/suppress semantics; related prompt and fallthrough items only cover parts of the broader behavior choice.

## What This Changes

Request configurable `/new` and `/reset` greeting behavior so reset starts can use a cheaper model or skip the model-generated greeting.

## Best Possible Solution

Define one maintainer-approved reset-start policy across auto-reply, Gateway, config schema/help/docs, and tests that covers acknowledgement-only reset, startup-turn greeting, suppression, prompt text customization, and optional cheaper model routing without competing ad hoc keys.
