## Summary

Keep open: current main and v2026.6.11 already avoid the expensive ordinary bare reset model turn with static acknowledgements, but the requested typed reset-greeting policy, cheaper greeting model routing, and configurable restore/suppress semantics are still missing and overlap active reset-contract discussions.

## What This Changes

Request a configurable policy for bare `/new` and `/reset` greetings, including using a cheaper greeting model or suppressing the greeting/model turn.

## Best Possible Solution

Define one maintainer-approved reset-greeting policy that covers ack-only resets, startup-turn greetings, optional cheaper greeting model routing, prompt text behavior, and Gateway/auto-reply parity before adding public config.

## Reproduction Assessment

Yes. Source inspection shows current main suppresses ordinary bare reset model turns with terminal acknowledgements and strict schemas lack the requested reset greeting model or suppression policy keys.

Unclear. The request identifies a real gap, but the best fix is not an ad hoc single key; maintainers need to choose one reset-start policy that aligns config, model routing, prompt text, Gateway behavior, docs, and tests.
