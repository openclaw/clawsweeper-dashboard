## Summary

Keep open: current main has made bare reset acknowledgements the cheap default path, but it still lacks the requested typed policy for suppressing a reset greeting, opting into a greeting/startup turn, or choosing a cheaper reset-specific model.

## What This Changes

The issue requests a configurable bare reset greeting policy, including suppressing the model greeting or selecting a cheaper reset-specific model.

## Best Possible Solution

Define one maintainer-approved reset-start policy covering acknowledgement-only resets, optional startup/greeting turns, prompt customization, reset-specific model routing, schema/types/help/docs, and focused tests across auto-reply and Gateway.

Yes, at source level. Current main has terminal acknowledgement-only bare reset paths, hardcoded downstream reset-prompt code when a model reset turn is reached, and strict schema/help for `startupContext` but no reset greeting policy or `resetGreetingModel` key.
