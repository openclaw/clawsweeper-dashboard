## Summary

Keep open: current main and the latest release make bare reset commands cheap by returning static acknowledgements without a model turn, but the requested typed reset-greeting policy, reset-specific model routing, and opt-in startup/greeting behavior are still missing.

## What This Changes

Request to add reset-greeting configuration so bare `/new` or `/reset` can suppress the model greeting or use a cheaper reset-specific greeting model.

## Best Possible Solution

Define one maintainer-approved reset-start policy covering acknowledgement-only resets, optional startup/greeting turns, prompt customization, reset-specific model routing, schema/types/help/docs, and focused auto-reply plus Gateway tests.

## Reproduction Assessment

Yes, at source level. Current main has acknowledgement-only bare reset paths, hardcoded downstream reset prompts for model-run reset paths, and strict config schemas that lack the requested reset-greeting model or policy keys.

Unclear. The issue identifies a real reset-start policy gap, but the proposed separate keys should not be added independently before maintainers choose one typed cross-surface policy and default behavior.
