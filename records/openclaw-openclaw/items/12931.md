## Summary

Keep open: current main and v2026.6.11 use cheap static acknowledgements for ordinary bare resets, but this issue still asks for a supported reset-start policy covering greeting suppression, cheaper greeting-model routing, and startup-turn behavior rather than a hardcoded default.

## What This Changes

The issue requests a configurable cheaper reset greeting model and/or a config option to suppress model-generated greetings for bare `/new` and `/reset`.

## Best Possible Solution

Define one maintainer-approved reset-start policy that covers acknowledgements, startup/model turns, prompt text, greeting suppression, and optional cheaper-model routing across auto-reply, Gateway, schema, docs, and tests.
