## Summary

Keep open: current main and the latest release still do not provide a reset-greeting model override or a typed suppression policy, while related reset-prompt and bare-fallthrough items only cover narrower parts of the reset-start behavior.

## What This Changes

The issue requests configuration to use a cheaper model for bare `/new` or `/reset` greeting turns, or to suppress that greeting/model turn entirely.

## Best Possible Solution

Define a single typed reset-start policy that covers acknowledgement-only resets, reply-producing reset turns, optional prompt customization, startup-context safeguards, and any reset-specific model selection across chat and gateway paths.

## Reproduction Assessment

Yes, at source level: current main has static bare-reset acknowledgements, a hardcoded reply-producing reset prompt, and no accepted reset-greeting model or suppression config key. I did not run live gateway proof in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract; the proposed knobs are plausible, but the maintainable fix is one reset-start policy instead of independent ad hoc options.
