## Summary

Keep open: current main has made bare reset acknowledgements the documented/tested cheap path, but it still lacks the requested typed policy for suppressing a reset greeting, opting into a startup/greeting turn, or choosing a cheaper reset-specific model.

## What This Changes

The issue requests configurable bare `/new` and `/reset` greeting behavior, including a cheaper greeting model or a way to suppress the greeting/model turn entirely.

## Best Possible Solution

Define one maintainer-approved reset-start policy covering acknowledgement-only resets, optional startup/greeting turns, prompt customization, reset-specific model routing, schema/types/help/docs, and focused tests across auto-reply and Gateway.

## Reproduction Assessment

Yes, at source level. Current main has acknowledgement-only bare reset paths, a hardcoded downstream reset prompt for model-run resets, and strict config schemas with `startupContext` but no reset greeting model or reset greeting policy key.

## Solution Assessment

Unclear. The issue identifies a real reset-start policy gap, but the proposed separate keys should not be added independently before maintainers choose one typed cross-surface policy and default behavior.
