## Summary

Keep open: current main and v2026.6.11 have the cheap acknowledgement path for bare resets, but they still lack a typed policy for choosing a reset-greeting model or restoring/suppressing model-backed startup turns across chat and Gateway surfaces.

## What This Changes

The issue asks for configurable bare `/new` and `/reset` reset-greeting behavior, either by using a cheaper model for the greeting turn or suppressing that turn entirely.

## Best Possible Solution

Define one typed reset-start policy covering acknowledgement-only resets, startup/model turns, prompt text, optional greeting model routing, bootstrap safeguards, schema, docs, and focused tests.
