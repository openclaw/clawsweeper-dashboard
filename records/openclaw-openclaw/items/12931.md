## Summary

Keep open: current main and v2026.6.11 still lack a supported reset-greeting model or suppression policy, and related open items only cover prompt text or bare-reset fallthrough pieces.

## What This Changes

The issue requests a configurable cheaper model for bare `/new` or `/reset` greeting turns, or a supported way to suppress that greeting/model run.

## Best Possible Solution

Define one maintainer-approved typed reset-start policy covering static acknowledgements, startup/model turns, prompt text, greeting suppression, and optional greeting-model routing across auto-reply, Gateway, config schema, docs, and tests.

Rationale: The request adds compatibility-sensitive config and changes session-start/model-routing semantics, so automation should not invent a key shape or default behavior.

Owner confidence: high

Options:

- **Add Explicit Reset-Start Policy (recommended):** Keep the current cheap acknowledgement default unless maintainers choose otherwise, and add a typed opt-in policy for startup turns, suppression, prompt text, and greeting model routing.
- **Restore Startup Turns By Default:** Make bare resets run the startup/model turn again and explicitly accept the token-cost, latency, and upgrade behavior change.
- **Keep Ack-Only Behavior:** Decline new reset greeting controls for now and point users to `/new <message>` plus the narrower prompt-customization discussion.
