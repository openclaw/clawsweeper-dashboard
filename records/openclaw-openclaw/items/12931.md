## Summary

Keep open: current main and v2026.6.11 still lack a public reset-greeting model, suppression flag, or unified reset-start policy; related open work covers prompt text or fallthrough behavior but does not fully own this broader config/product decision.

## What This Changes

The issue requests a configurable cheaper model for bare `/new` and `/reset` greeting turns, or a way to suppress that greeting/model invocation entirely.

## Best Possible Solution

Define one maintainer-approved reset-start policy covering acknowledgements, startup/model turns, prompt text, greeting suppression, and optional greeting-model routing across auto-reply, Gateway, schema, docs, and tests.
