## Summary

Keep open: current `main` and the latest release no longer spend a model turn for ordinary bare chat and gateway resets, but the requested typed reset-greeting policy, cheaper greeting model routing, and configurable restore/suppress semantics are still absent.

## What This Changes

The issue requests configurable bare `/new` and `/reset` greeting behavior, either by using a cheaper greeting model or suppressing the model-generated greeting.

## Best Possible Solution

Define one documented reset-greeting policy across chat and gateway resets, covering static acknowledgement, model greeting, suppression, and any explicit cheaper model override without changing unrelated reset semantics.

Question: What public reset-greeting contract should OpenClaw support for bare `/new` and `/reset`: static ack, model greeting, suppressible ack, model override, or a typed combination?

Rationale: Current main intentionally avoids model cost, related reports request restoring the persona greeting, and adding a config/model-routing surface is compatibility-sensitive product policy rather than a narrow repair.

Likely owner: steipete

Owner reason: They authored the current static acknowledgement behavior and the previous review framing this as an unresolved reset-greeting product decision.

Owner confidence: high

Options:

- **Define a typed reset-greeting policy (recommended):** Add one cross-surface config contract that preserves a safe default while allowing explicit model greeting, static ack/suppression, and optional cheaper model routing with docs and focused tests.
- **Keep static acknowledgements only:** Close the configurable greeting direction and treat current no-model reset acknowledgement as the supported product behavior, leaving greeting users to send a post-reset message.
- **Restore greeting fallthrough by default:** Return to the historical model turn for bare resets and require a separate suppression path, accepting the token-cost and upgrade implications for current users.

## Solution Assessment

Unclear. A config policy is likely the right end state, but the exact shape must reconcile current static acknowledgements with users who want restored persona greeting and model override behavior.
