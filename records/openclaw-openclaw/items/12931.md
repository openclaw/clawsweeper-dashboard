## Summary

Keep open: current main and v2026.6.11 avoid the original bare-reset token burn on ordinary chat and Gateway reset paths by returning static acknowledgements, but OpenClaw still has no configurable reset-greeting policy, cheaper greeting model route, or suppression/startup-turn mode. The remaining work is a compatibility-sensitive product/config decision rather than a stale or already-implemented issue.

## What This Changes

The issue requests a configurable policy for bare `/new` and `/reset` greetings, including an optional cheaper greeting model or suppressing the model-generated greeting entirely.

## Best Possible Solution

Define one typed reset-start policy covering acknowledgement-only resets, optional startup/model greeting turns, prompt text, optional greeting model routing, bootstrap safeguards, schema/help/docs, and focused tests.
