## Summary

Keep open: current main and v2026.6.11 remove the original ordinary bare-reset token burn by returning static acknowledgements, but they still do not provide the requested typed reset-greeting policy, cheaper model routing, or configurable suppress/restore behavior across reset surfaces.

## What This Changes

The issue requests configuration for bare `/new` and `/reset` greeting behavior, including using a cheaper greeting model or suppressing the greeting model turn.

## Best Possible Solution

Define one reset-greeting policy for chat acknowledgements, reply-producing reset turns, and Gateway agent resets, with schema/types/help/docs/tests covering suppression, explicit model selection, and the chosen default.
