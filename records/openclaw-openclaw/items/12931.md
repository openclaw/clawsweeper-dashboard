## Summary

Keep open: current main and v2026.6.11 avoid the original expensive model turn for ordinary bare reset acknowledgement paths, but OpenClaw still lacks a supported reset-start policy for choosing a cheaper greeting model, suppressing/restoring greeting turns consistently, or aligning the related prompt/fallthrough behavior.

## What This Changes

The issue asks for configurable bare `/new` and `/reset` greeting behavior, including a cheaper greeting model or an option to suppress the greeting turn.

## Best Possible Solution

Define one maintainer-approved reset-start policy that covers acknowledgements, startup/model turns, prompt text, suppression, and optional greeting-model routing across auto-reply, Gateway, schema, docs, and tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What public reset-start policy should OpenClaw expose for bare `/new` and `/reset` across static acknowledgements, startup/model turns, prompt text, greeting suppression, and optional cheaper greeting-model routing?

Rationale: The remaining work adds compatibility-sensitive config and changes session-start/model-routing semantics, while related users are asking for both cheaper/suppressed greetings and restored persona greetings; automation should not invent the key shape or default behavior.

Likely owner: steipete

Owner reason: This handle is tied to the current bare reset acknowledgement contract and prior policy review, making it the best available owner for the default/config decision.

Owner confidence: high

Options:

- **Add explicit reset-start policy (recommended):** Keep current acknowledgement behavior unless maintainers choose otherwise, and add one typed opt-in policy for startup turns, prompt text, suppression, and greeting-model routing.
- **Restore startup turns by default:** Make bare resets run the startup/model turn again and explicitly accept the token-cost, latency, and upgrade behavior change.
- **Defer new reset controls:** Keep current acknowledgement-only behavior and use `/new <message>` plus the narrower prompt-text tracker until a broader reset policy is approved.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 have terminal acknowledgement branches for bare resets and strict schemas without the requested greeting model, suppression, or reset-start policy keys. I did not run a live reset flow in this read-only review.

## Solution Assessment

Unclear until maintainers choose the reset-start contract. A standalone `resetGreetingModel` or `resetGreeting` flag is plausible, but the safer solution is one typed policy that aligns prompt text, startup turns, suppression, model routing, and Gateway behavior.
