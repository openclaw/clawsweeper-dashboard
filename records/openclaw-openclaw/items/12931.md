## Summary

Keep open: current main and v2026.6.11 still do not provide a configurable reset-greeting policy or cheaper greeting model routing, while related prompt-override and greeting-restoration items cover adjacent but narrower behavior.

## What This Changes

The issue requests configurable handling for bare `/new` and `/reset` greetings, either by using a cheaper greeting model or by suppressing the model-generated greeting.

## Best Possible Solution

Define one maintainer-approved reset-greeting policy covering acknowledgement-only resets, startup/model turns, optional prompt text, optional greeting model routing, bootstrap safeguards, schema/help/docs, and focused tests.
