## Summary

Keep open: current main and v2026.6.11 still provide static bare-reset acknowledgements and hardcoded reset prompt behavior, but no configurable greeting model, suppression flag, or unified reset-start policy.

## What This Changes

The issue requests a configurable reset-greeting policy so bare `/new` or `/reset` can use a cheaper greeting model or skip the model-generated greeting.

## Best Possible Solution

Define one maintainer-approved reset-start policy that covers acknowledgements, startup/model turns, prompt text, greeting suppression, and optional greeting-model routing across auto-reply, Gateway, schema/types/help, docs, and tests.
