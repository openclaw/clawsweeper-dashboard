## Summary

Keep open: current main and v2026.6.11 still do not expose a supported reset-greeting suppression or cheaper greeting-model policy, and the related open items only cover prompt text or startup/model fallthrough pieces.

## What This Changes

The issue requests configurable behavior for bare `/new` and `/reset` so the reset greeting can either use a cheaper model or be suppressed.

## Best Possible Solution

Define one maintainer-approved typed reset-start policy that covers acknowledgements, startup/model turns, prompt text, suppression, and optional greeting-model routing across auto-reply, Gateway, schema, docs, and tests.

Rationale: The request adds compatibility-sensitive config and model-routing behavior, so automation should not invent a new key or default without maintainer intent.

Likely owner: steipete

Owner confidence: high

Options:

- **Add One Explicit Reset-Start Policy (recommended):** Expose a single typed opt-in policy that covers startup turns, prompt text, suppression, and greeting-model routing while preserving current acknowledgement behavior unless maintainers choose otherwise.
- **Restore Startup Turns By Default:** Make bare resets run the startup/model turn again and explicitly accept the token-cost, latency, and upgrade behavior change.
- **Defer New Reset Controls:** Keep current acknowledgement-only behavior and route prompt customization or startup-turn restoration through the narrower related trackers until the broader policy is approved.
