## Summary

Keep open: current main and v2026.6.11 still have acknowledgement-only bare `/new` and `/reset` paths and no supported reset-greeting model or suppression config, while related open items cover only prompt text or fallthrough behavior rather than this full policy.

## What This Changes

The issue requests a configurable bare reset greeting policy, including either a cheaper model for the greeting turn or suppressing the greeting/model call entirely.

## Best Possible Solution

Define one typed reset-start policy that preserves the current acknowledgement-only default unless maintainers choose otherwise, then support explicit greeting suppression and optional startup/greeting model routing across auto-reply, Gateway, schema, docs, and tests.
