## Summary

Keep open: current main and v2026.6.11 avoid the expensive bare-reset model call on ordinary chat and Gateway paths, but they still do not provide a configurable reset-greeting model, suppression policy, or unified reset-start contract; related open items cover prompt text or fallthrough but do not fully own this broader model/suppression request.

## What This Changes

Request to add configurable behavior for bare `/new` and `/reset` greetings, either by selecting a cheaper greeting model or by suppressing the greeting/model turn.

## Best Possible Solution

Define one maintainer-approved reset-start policy that covers acknowledgements, startup/model turns, prompt text, greeting suppression, and optional greeting-model routing across auto-reply, Gateway, schema/types/help, docs, and tests.
