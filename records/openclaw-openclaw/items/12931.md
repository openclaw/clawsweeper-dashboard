## Summary

Keep open: current main and v2026.6.11 avoid the original token burn for bare chat and Gateway resets by returning static acknowledgements, but they still do not provide a maintainer-approved reset greeting policy, configurable greeting model, or explicit suppress/startup-turn mode across reset surfaces.

## What This Changes

The issue requests a configurable bare `/new` and `/reset` greeting policy, including either a cheaper greeting model or a way to suppress the greeting/model turn.

## Best Possible Solution

Define one typed reset-start policy across auto-reply and Gateway that preserves the current cheap acknowledgement default unless maintainers intentionally choose otherwise, and add schema, docs, and tests for suppressing, startup-turn, and optional greeting-model behavior under that policy.
