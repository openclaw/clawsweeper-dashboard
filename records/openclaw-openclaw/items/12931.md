## Summary

Keep open: current main and v2026.6.11 suppress ordinary bare reset model turns by default, but there is still no typed config to select a greeting model or choose reset greeting behavior consistently across auto-reply and Gateway; related open items cover prompt text or fallthrough slices only.

## What This Changes

Request to add a configurable reset greeting policy so bare `/new` and `/reset` can either avoid a model turn or run the greeting on a cheaper explicit model.

## Best Possible Solution

Define one typed reset-start policy covering acknowledgement-only resets, startup/model turns, prompt customization, and optional greeting-model override across auto-reply, Gateway, config schema/help, docs, and tests.
