## Summary

Keep open: current main and v2026.6.11 avoid the original bare-reset token burn for ordinary bare resets with static acknowledgements, but they still do not provide a configurable reset-greeting policy or cheaper greeting model routing. The related prompt-override and greeting-restoration items cover adjacent pieces, not this full product/config decision.

## What This Changes

The issue requests configurable bare `/new` and `/reset` greeting behavior, either by routing the greeting through a cheaper model or suppressing the model greeting entirely.
