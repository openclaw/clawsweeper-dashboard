## Summary

Keep open: current main and v2026.6.11 still lack a supported reset-start policy for choosing a cheaper greeting model, suppressing the greeting, or consistently restoring startup/model turns; related open work only covers narrower prompt or fallthrough behavior.

## What This Changes

Request to add a supported bare `/new` and `/reset` reset-start control that can suppress the greeting or run it on a cheaper model.

## Best Possible Solution

Define one maintainer-approved reset-start policy that covers acknowledgements, startup/model turns, prompt text, suppression, and optional greeting-model routing across auto-reply, Gateway, schema, docs, and tests.
