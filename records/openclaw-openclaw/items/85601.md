## Summary

Keep open: the report still describes a real Claude CLI bundled-MCP lifecycle conflict, and current main no longer has the session-owned cleanup transfer that originally fixed this class of tempDir race. A later retry-artifact fix changed the ownership model, so this should stay maintainer-owned rather than be closed as stale or implemented.

## What This Changes

Investigate and fix recurring claude-cli bundled MCP tempDir cleanup that leaves resumed/live-session spawns with a missing `--mcp-config` `mcp.json`.

## Best Possible Solution

Reconcile Claude live-session artifact ownership so persistent processes keep the MCP config they were launched with while fresh recovery retries also receive valid artifacts, with focused coverage for normal reuse, restart/abort cleanup, capture mode, and fresh retry.

Rationale: The current source conflict is between two real bug fixes: the original tempDir lifetime fix and the later recovery-retry artifact fix. A blind reapply or blind revert could break one of those paths.

Owner confidence: high

Options:

- **Split ownership by artifact lifetime (recommended):** Keep the persistent process's MCP config session-owned, keep retry-only artifacts run-owned or regenerate them before retry, and cover both paths with tests.
- **Keep run-owned artifacts:** Accept the current retry-oriented model only after live proof shows persistent Claude sessions cannot respawn with stale `--mcp-config` paths.
- **Restore session ownership broadly:** Reapply the older transfer shape and separately change fresh retries to rebuild artifacts before respawn.

No high-confidence live reproduction was run in this read-only review. The source path is reproducible enough to keep open: current main keeps prepared cleanup at run scope while generated Claude MCP config files are still tempDir-backed and injected into live/resume args.

## Solution Assessment

Unclear as a one-line fix. The old cleanup-transfer patch fixed the persistent-session tempDir race, but current main intentionally changed that ownership for retry safety, so the best repair should reconcile both lifetimes rather than simply restore either side.
