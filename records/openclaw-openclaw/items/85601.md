## Summary

Keep open: current main does not currently prove the bundled Claude CLI MCP tempDir race is fixed, and source inspection shows the live-session path can still leave generated `mcp.json` cleanup owned by the per-run cleanup path rather than the live session lifecycle.

## What This Changes

Report that bundled Claude CLI MCP temp config directories can disappear before resumed live-session spawns, causing strict MCP config failures during sustained claude-cli backed sessions.

## Best Possible Solution

Restore a single correct ownership boundary so generated Claude MCP config directories remain alive until no live or resumed Claude process can reference them, with focused full-run regression coverage and a redacted live claude-cli proof.

## Reproduction Assessment

Yes at source level, but not with a fresh live run in this pass. Current main still creates a generated MCP config path, passes it into Claude live/resume args, leaves prepared cleanup outside the live-session callback, and runs that cleanup after the CLI attempt.

## Solution Assessment

Unclear as an implementation shape. The old release fix is a strong reference point, but the current main lifecycle cleanup refactor means maintainers should choose the correct ownership model and prove it with full-run regression coverage.
