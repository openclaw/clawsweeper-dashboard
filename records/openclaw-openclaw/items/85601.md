## Summary

Keep open: current main still has a source-reproducible bundled MCP tempDir lifecycle bug, and the latest release fix is not present in the current main implementation. The remaining work needs maintainer review because the prior cleanup-transfer fix and the later retry-artifact fix pull on the same live-session ownership boundary.

## What This Changes

Reports a regression where Claude CLI live sessions can respawn or resume with a deleted bundled MCP config tempDir, producing `Invalid MCP configuration` and generic user-visible failures.

## Best Possible Solution

Keep the generated Claude bundle MCP config and skills artifacts alive for the full live-session process and any in-run fresh-session retry, with regression tests for cross-turn reuse, restart, and retry cleanup.

## Reproduction Assessment

No deterministic live repro was run, but there is a high-confidence source reproduction path: current main generates a temp `mcp.json`, normalizes its path for live-session reuse, and still runs prepared cleanup after the turn. The reporter also supplied later-release stderr matching that exact missing-file symptom.

## Solution Assessment

Unclear that simply restoring the older transfer hunk is the best complete fix, because the later retry-artifact fix intentionally changed the same lifecycle. The best fix should reconcile live-session persistence with same-run retry artifact retention rather than choosing only one behavior.
