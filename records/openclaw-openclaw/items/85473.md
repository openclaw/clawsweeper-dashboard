## Summary

Keep open: current main still has memory-core-owned dreaming plus selected-memory-slot config and sidecar handling, but no public dreaming provider protocol that lets arbitrary memory plugins own OpenClaw-managed dreaming. The linked ClawHub LanceDB dreaming plugin is a useful workaround, not evidence that the requested SDK/runtime contract is solved in core.

## What This Changes

Request to expose dreaming as a memory plugin protocol so non-memory-core memory plugins can implement Light/REM/deep consolidation under OpenClaw scheduling.

## Best Possible Solution

Define or reject a narrow public dreaming capability contract in the plugin SDK, coordinated with memory role-slot work; keep standalone ClawHub dreaming plugins as the current workaround until that decision lands.
