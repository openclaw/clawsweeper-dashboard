## Summary

Keep open: current main and the latest release still implement dreaming as memory-core-owned orchestration with a memory-core sidecar for selected memory plugins, not as a public dreaming provider protocol. The ClawHub LanceDB dreaming plugin and open memory role-slot work are useful context, but they do not settle the OpenClaw plugin-SDK/config/scheduler product decision.

## What This Changes

Request to decouple dreaming from memory-core by exposing a memory-plugin dreaming protocol so non-memory-core backends can implement dreaming lifecycle behavior.

## Best Possible Solution

Have maintainers decide a public plugin-SDK dreaming contract in coordination with memory role-slot architecture, or explicitly document that non-memory-core dreaming remains plugin-owned standalone orchestration through ClawHub.
