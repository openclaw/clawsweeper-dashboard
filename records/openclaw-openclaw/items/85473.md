## Summary

Keep open: current main and v2026.6.11 still expose memory-core-owned dreaming plus a memory-core sidecar path for other selected memory plugins, not a public dreaming provider protocol. The ClawHub LanceDB dreaming plugin is a useful workaround and the open role-slot PR is relevant, but neither settles the core/plugin-SDK product decision.

## What This Changes

The issue requests a public dreaming protocol so non-memory-core memory plugins can implement Light, Deep, and REM consolidation under OpenClaw orchestration.

## Best Possible Solution

Maintainers should decide a public plugin-SDK dreaming contract, preserve memory-core as the default behavior, and coordinate any implementation with memory role-slot work or explicitly keep LanceDB/vector-native dreaming as plugin-owned ClawHub functionality.
