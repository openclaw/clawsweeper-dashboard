## Summary

Keep open: current main and v2026.6.11 still expose memory-core-owned dreaming orchestration, with only slot-owned config lookup and a memory-core sidecar for non-core memory plugins. The posted ClawHub LanceDB dreaming plugin is a useful workaround, but it does not settle the missing OpenClaw plugin-SDK/protocol decision.

## What This Changes

The issue requests a public dreaming protocol so memory plugins other than memory-core can participate in Light, Deep, and REM consolidation.

## Best Possible Solution

Have maintainers decide the public dreaming plugin contract, ideally coordinated with the memory role-slot work, while keeping the current memory-core engine and pointing LanceDB users to the ClawHub workaround until that direction is settled.
