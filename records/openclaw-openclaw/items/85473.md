## Summary

Keep open: current main and the latest checked release still implement memory-core-owned dreaming with selected-slot configuration and a memory-core sidecar, not a public dreaming provider protocol for arbitrary memory plugins. The ClawHub memory-lancedb-dreaming workaround and the open role-slot work help LanceDB users, but the remaining SDK/config/scheduler contract is still a maintainer-owned product/API decision.

## What This Changes

The issue requests decoupling dreaming from memory-core so any memory plugin can implement a dreaming protocol.

## Best Possible Solution

Use the role-slot work as groundwork, then either design a narrow versioned dreaming provider contract with storage/session/state responsibilities or explicitly document plugin-owned ClawHub orchestration as the supported path.
