## Summary

Keep open: current main and latest release still expose memory-core-owned dreaming plus a memory-core sidecar path, not a public dreaming provider protocol for arbitrary memory plugins. The linked ClawHub plugin is a useful LanceDB workaround, but it does not settle the OpenClaw plugin-SDK/config/scheduler decision.

## What This Changes

The issue requests a public dreaming protocol so memory plugins other than memory-core can implement query, promotion, reporting, and OpenClaw-managed scheduling.

## Best Possible Solution

Have maintainers decide the public plugin-SDK dreaming provider, config, lifecycle, and scheduler contract, likely in coordination with memory role-slot work; otherwise document that vector-native dreaming remains plugin-owned through ClawHub.
