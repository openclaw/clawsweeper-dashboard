## Summary

Keep open: current main and v2026.6.11 still provide selected-memory-plugin dreaming config plus a memory-core sidecar engine, not a public dreaming lifecycle protocol that any memory plugin can implement. The ClawHub LanceDB dreaming plugin is a useful workaround, but the OpenClaw SDK/runtime product decision remains unresolved.

## What This Changes

The issue requests a public dreaming protocol so memory plugins other than memory-core can participate in Light, Deep, and REM consolidation.

## Best Possible Solution

Keep this open until maintainers decide the public dreaming plugin API boundary, ideally coordinated with the memory role-slot work; if maintainers reject OpenClaw-managed orchestration, document that dreaming remains plugin-owned through ClawHub.
