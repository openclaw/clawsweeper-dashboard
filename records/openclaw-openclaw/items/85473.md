## Summary

Keep open: current main, latest stable v2026.6.11, and latest beta v2026.7.1-beta.2 still use memory-core-owned dreaming and a memory-core sidecar path, not a public dreaming provider protocol. The posted memory-lancedb-dreaming ClawHub plugin is a useful workaround for LanceDB users, and PR #88504 may provide role-slot routing, but the requested SDK/runtime protocol remains a maintainer product/API decision.

## What This Changes

Request to expose an OpenClaw-managed memory dreaming protocol so non-memory-core memory plugins can declare config and implement the dreaming lifecycle.

## Best Possible Solution

Have maintainers decide the public dreaming plugin protocol in coordination with memory role-slot work, preserving memory-core defaults and documenting whether alternate dreaming remains ClawHub-owned.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw define a public plugin-SDK dreaming protocol and runtime orchestration contract for memory plugins, or keep dreaming orchestration plugin-owned through ClawHub plugins?

Rationale: Current main and releases only provide selected-slot config plus a memory-core sidecar, while a real provider protocol would add public SDK, config, scheduler, migration, and compatibility obligations.

Likely owner: @steipete

Owner reason: This is a cross-cutting public API and product-boundary decision, and @steipete is the listed project decision owner in CONTRIBUTING.md.

Owner confidence: medium

Options:

- **Design SDK protocol with role-slot work (recommended):** Define a documented dreaming provider contract after or alongside memory role slots, keeping memory-core as the default implementation and adding upgrade-safe docs/tests.
- **Keep dreaming plugin-owned:** Document that alternate dreaming implementations should ship as ClawHub plugins and that OpenClaw core only exposes the current selected-slot config behavior.
- **Defer until PR #88504 settles:** Leave this issue open but pause implementation until the memory role-slot PR lands or closes, then revisit the lifecycle/provider API shape.
