## Summary

Keep open: current main and v2026.6.11 still do not expose a public dreaming provider protocol; dreaming remains memory-core-owned with a sidecar path for selected memory plugins. The ClawHub LanceDB dreaming plugin is a useful workaround, but the remaining question is a core/plugin-SDK product decision.

## What This Changes

Request to expose OpenClaw-managed dreaming as a memory plugin protocol so non-memory-core memory plugins can participate in light, REM, and deep consolidation.

## Best Possible Solution

Decide a narrow public plugin-SDK dreaming contract in coordination with memory role-slot work, or explicitly document that dreaming orchestration remains plugin-owned through ClawHub packages.
