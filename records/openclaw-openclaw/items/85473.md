## Summary

Keep open: current main and v2026.6.11 still make memory-core the built-in dreaming engine. The ClawHub memory-lancedb-dreaming plugin is a useful workaround for LanceDB users, but it does not resolve the requested OpenClaw Plugin SDK/manifest protocol decision.

## What This Changes

The issue requests a public dreaming protocol so non-memory-core memory plugins can participate in Light/Deep/REM consolidation.

## Best Possible Solution

Maintainers should either approve a documented Plugin SDK/manifest dreaming provider contract with memory-core as one implementation, or explicitly document that built-in dreaming stays memory-core-owned while vector-native dreaming lives as ClawHub plugins.

Rationale: Current main has selected-plugin dreaming config and a memory-core sidecar engine, but query/promote/report/scheduler ownership would be a new public plugin API and config contract that automation should not invent without maintainer direction.

- **Defer to multi-slot memory:** Track the request under the broader memory role-slot architecture before adding a dreaming-specific API.
