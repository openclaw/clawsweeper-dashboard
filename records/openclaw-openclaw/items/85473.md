## Summary

Keep open: current main and v2026.6.11 still route dreaming through memory-core-owned config, state, cron, and command paths rather than a public memory-plugin dreaming protocol. The ClawHub LanceDB dreaming plugin is a useful workaround, and the open multi-slot memory PR is relevant, but neither settles the core/plugin-SDK API decision requested here.

## What This Changes

Request to expose dreaming as a memory-plugin protocol so non-memory-core memory plugins can implement the config, scheduling, and Light/REM/Deep lifecycle.

## Best Possible Solution

Have maintainers decide whether dreaming remains plugin-owned through ClawHub packages or becomes a documented SDK/role-slot contract, then implement that chosen boundary with memory-core kept as the default-compatible provider.
