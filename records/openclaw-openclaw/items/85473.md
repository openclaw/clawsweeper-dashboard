## Summary

Keep open: current main and the latest stable release still run dreaming through memory-core-owned scheduling/sidecar paths and do not expose a public dreaming provider protocol. The linked ClawHub package is useful for LanceDB users today, but it does not settle the core plugin-SDK/config decision.

## What This Changes

The issue requests a public dreaming protocol, config surface, and runtime boundary so non-memory-core memory plugins can implement Light/REM/Deep consolidation.

## Best Possible Solution

Decide the memory role-slot direction in https://github.com/openclaw/openclaw/pull/88504, then design a narrow dreaming provider SDK contract only if maintainers still want OpenClaw-managed scheduling across memory plugins.
