## Summary

Keep open: current main and v2026.6.11 still provide memory-core-owned dreaming plus selected-memory-slot config plumbing, not a public dreaming provider protocol. The posted `memory-lancedb-dreaming` ClawHub plugin is useful for LanceDB users today, but it does not settle the OpenClaw plugin-SDK/API ownership decision.

## What This Changes

Request to add a plugin-SDK/runtime dreaming protocol so memory plugins other than memory-core can implement Light/REM/deep consolidation under OpenClaw orchestration.

## Best Possible Solution

Decide the public dreaming provider API together with memory role-slot work, then either land a documented SDK/runtime contract with upgrade proof or explicitly keep dreaming orchestration plugin-owned through ClawHub.
