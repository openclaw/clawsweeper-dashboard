## Summary

Keep open: current main still has a fixed persistent TUI footer, while messages.usageTemplate, /usage provider quota work, and the PluginStatusProvider proposal only cover narrower pieces of this cost/balance/cooldown footer-design request.

## What This Changes

Request customizable TUI footer fields/templates for model, token, cost, balance, and rate-limit status via config or a plugin/hook-style provider.

## Best Possible Solution

Keep this as the broad TUI footer observability tracker, settle the plugin/API versus core-config boundary, and let the narrower PluginStatusProvider and /usage quota PRs land or close independently.
