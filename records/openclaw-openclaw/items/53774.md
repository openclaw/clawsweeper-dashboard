## Summary

Keep open: current main and v2026.6.11 still lack configurable persistent TUI footer fields for cost, balance, or rate-limit status. The linked `/usage` quota-footer and PluginStatusProvider work are useful but narrower, open, and do not subsume the broad TUI footer customization decision.

## What This Changes

Request configurable TUI footer fields for model, tokens, estimated session cost, remaining provider balance, and rate-limit status.

## Best Possible Solution

Keep this as the broad TUI footer observability tracker, land or close the narrower related PRs on their own merits, then choose a plugin/API-driven footer design with bounded provider-usage behavior instead of hardcoding provider-specific fields in the TUI.

Options:

- **Plugin/API-first footer seam (recommended):** Use the linked PluginStatusProvider direction as the extension boundary, then add a TUI render path and provider-usage fields only after the API shape, ordering, truncation, and caching policy are approved.

- **Keep existing status surfaces:** Leave `/status`, `/usage`, CLI status, and menu-bar usage as the supported quota/cost surfaces and close persistent footer customization as not planned.
