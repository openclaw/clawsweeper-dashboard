## Summary

Keep open: current main and v2026.6.11 still lack configurable persistent TUI footer fields for cost, balance, or rate-limit status. Existing `/usage` templates, provider usage/status output, and the open PluginStatusProvider work cover useful slices, but none subsume the broader persistent TUI footer product/API decision.

## What This Changes

The issue requests configurable TUI footer/status fields for model, token, estimated cost, provider balance, and cooldown or rate-limit state.

## Best Possible Solution

Keep this as the broad TUI footer observability tracker, land or close the narrower related PRs on their own merits, then choose a plugin/API-driven footer design with bounded provider-usage behavior instead of hardcoding provider-specific fields in the TUI.
