- `P2`: This is a normal-priority feature/product decision with workarounds through `/status`, `/usage`, and external scripts, not a blocking outage.

## Summary

Keep open: current main and v2026.6.11 only partially address cost/quota visibility through `/usage` and `/status`; the TUI footer itself remains fixed, while open related work covers narrower provider-quota and plugin-status seams.

## What This Changes

Request configurable TUI footer/status fields for model, token, estimated cost, provider balance, and rate-limit or cooldown status through a template or provider hook.

## Best Possible Solution

Keep this as the broad TUI footer/status strategy tracker: review the narrower provider-quota usage footer and plugin status-provider seams, then decide whether a core TUI template/config surface belongs in OpenClaw or should be provided through plugins with strict security and latency boundaries.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature request. Source inspection confirms the requested TUI footer template/status-provider behavior is not present on current main or v2026.6.11.

## Solution Assessment

Unclear until maintainers choose the product shape. A plugin-owned status-provider seam plus existing `/usage` and `/status` surfaces looks cleaner than direct provider-specific TUI polling, but a core footer template/config surface would be a new compatibility commitment.
