## Summary

Keep open: current main still lacks configurable persistent TUI footer fields, and the open related work only covers narrower PluginStatusProvider and `/usage` quota-footer pieces.

## What This Changes

The issue requests configurable TUI footer fields for model, tokens, cost, balance, and rate-limit status, either through a TUI template or footer-provider hook.

## Best Possible Solution

Keep this as the broad TUI footer observability tracker, review the narrower API and `/usage` PRs, then choose a plugin/API-driven footer design with bounded provider-usage behavior instead of hardcoding provider-specific fields into core.
