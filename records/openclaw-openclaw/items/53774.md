## Summary

Keep open: current main and the latest release still lack persistent configurable TUI footer fields for cost, balance, or cooldown status; existing `/usage`, `/status`, provider-usage APIs, and linked PRs cover narrower pieces but do not settle the broader TUI product/API/security design.

## What This Changes

Request configurable TUI footer fields for cost, remaining provider balance, and rate-limit/cooldown status via a footer template or plugin hook.

## Best Possible Solution

Keep this as the broad TUI footer observability tracker, prefer a plugin/status-provider seam plus existing provider-usage APIs, and avoid hardcoding provider-specific balance polling into core until maintainers choose the API and security boundary.

## Reproduction Assessment

## Solution Assessment

Unclear: the direct core footer-template and provider balance-polling proposal is plausible but not proven best. A plugin-driven status-provider seam plus reuse of existing provider-usage APIs appears safer, pending maintainer product/API approval.
