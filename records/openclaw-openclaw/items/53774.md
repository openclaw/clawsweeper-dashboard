## Summary

Keep open: current main still has a fixed persistent TUI footer and only partial `/usage` and `/status` surfaces; related open PRs address narrower PluginStatusProvider or per-response usage quota pieces, not the requested configurable cost/balance/rate-limit TUI footer.

## What This Changes

Request configurable persistent TUI footer fields/templates for model, tokens, estimated cost, provider balance, and rate-limit or cooldown status.

## Best Possible Solution

Keep this as the broad TUI footer observability tracker, review the narrower plugin-status-provider and `/usage` quota-footer PRs, then choose a plugin/API-driven footer design with bounded provider-usage behavior.
