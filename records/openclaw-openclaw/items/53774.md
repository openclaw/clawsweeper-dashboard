## Summary

Keep open: current main and the latest release still do not provide persistent configurable TUI footer fields for cost, balance, or rate-limit/cooldown status. Existing `/status`, `/usage`, and provider usage-window surfaces cover useful pieces, and the linked plugin API work is a promising narrower seam, but the broad footer product/API boundary remains undecided.

## What This Changes

The issue requests configurable TUI footer fields for live session cost, remaining provider balance, and rate-limit or cooldown status.

## Best Possible Solution

Choose a maintainer-approved narrow extension path, preferably a plugin/status-provider seam plus bounded TUI rendering rules, then let provider-specific cost, balance, and cooldown contributors live behind explicit redaction and polling contracts.
