## Summary

Keep open: current main and v2026.6.11 still lack configurable persistent TUI footer fields for cost, balance, or rate-limit status. The open PluginStatusProvider and `/usage` quota-footer PRs are useful partial overlaps, but they do not resolve the broader persistent TUI footer product/API decision.

## What This Changes

Request configurable TUI footer fields for estimated cost, provider balance, and rate-limit/cooldown status.

## Best Possible Solution

Keep this as the broad TUI footer observability tracker, review the narrower linked PRs on their own merits, and prefer a plugin/API-driven footer design with bounded provider-usage behavior over hardcoded provider-specific TUI fields.

- **Keep status surfaces only:** Leave /status, /usage, CLI status, and gateway usage APIs as the supported quota/cost surfaces and reject persistent footer customization for now.
