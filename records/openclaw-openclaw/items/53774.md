## Summary

Keep open: current main still lacks configurable persistent TUI footer fields for cost, balance, or rate-limit status, and the open related PRs only cover narrower `/usage` quota-footer or PluginStatusProvider API slices.

## What This Changes

The issue requests configurable persistent TUI footer fields for model, token usage, estimated cost, provider balance, and rate-limit or cooldown status.

## Best Possible Solution

Keep this as the broad TUI footer observability tracker, land or close the narrower related PRs on their own merits, then choose a plugin/API-driven footer design with bounded provider-usage behavior instead of hardcoding provider-specific fields in the TUI.
