## Summary

Keep open: current main and v2026.6.11 still lack configurable persistent TUI footer fields for cost, provider balance, or cooldown/rate-limit status. Existing `/usage`, `/status`, and provider-usage surfaces cover useful slices, and the linked PluginStatusProvider and provider-quota-footer PRs are narrower open candidates rather than a complete replacement for the product/API decision.

## What This Changes

The issue requests configurable TUI footer fields for session cost, provider balance, and rate-limit/cooldown status.

## Best Possible Solution

Keep this as the broad footer-observability tracker, review https://github.com/openclaw/openclaw/pull/72557 and https://github.com/openclaw/openclaw/pull/96339 on their narrower merits, then prefer a plugin/API-driven footer seam with bounded cached provider-usage behavior over hardcoded provider-specific TUI fields.
