## Summary

Keep open: current main and v2026.6.11 still do not implement configurable persistent TUI footer fields for cost, balance, or rate-limit status. The linked PluginStatusProvider and `/usage` quota-footer work are useful but narrower, open, and do not settle this broader TUI footer product/API decision.

## What This Changes

The issue requests configurable TUI footer fields for model, token usage, estimated cost, provider balance, and rate-limit cooldown status.

## Best Possible Solution

Keep this as the broad TUI footer observability tracker, review the narrower related PRs on their own merits, and choose a plugin/API-first footer design before adding provider-specific cost, balance, or cooldown fields.
