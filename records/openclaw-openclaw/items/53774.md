## Summary

Keep open: current main still lacks configurable persistent TUI footer fields for cost, balance, or rate-limit status. Existing `/usage` templates, `/status` provider-usage output, and the open PluginStatusProvider work are useful partial overlaps but do not settle this broader TUI footer product/API decision.

## What This Changes

The issue requests configurable persistent TUI footer fields for model, tokens, estimated cost, provider balance, and rate-limit cooldown status.

## Best Possible Solution

Keep this as the broad persistent TUI footer observability tracker, review the narrower `/usage` quota-footer and PluginStatusProvider PRs on their own merits, then choose a plugin/API-driven footer design before adding core config fields.

Options:

- **Plugin/API-first footer seam (recommended):** Use the PluginStatusProvider direction as the extension boundary, then add TUI rendering and provider-usage fields only after ordering, truncation, caching, and privacy rules are approved.

- **Keep existing status surfaces:** Leave `/status`, `/usage`, CLI status, and menu-bar usage as the supported quota/cost surfaces and close persistent footer customization as not planned.
