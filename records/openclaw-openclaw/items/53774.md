## Summary

Keep open: current main still lacks configurable persistent TUI footer fields for cost, balance, or rate-limit status. The open `/usage` quota-footer and PluginStatusProvider work are useful but narrower, so they do not settle the broader TUI footer product/API boundary.

## What This Changes

Request configurable persistent TUI footer/statusline fields for model, token, cost, balance, and cooldown visibility via config templates or plugin/script providers.

## Best Possible Solution

Keep this as the broad TUI footer observability tracker, land or close the narrower related PRs on their own merits, and choose a plugin/API-first footer design before adding provider-specific fields to the TUI.

- **Keep Existing Status Surfaces:** Keep `/status`, `/usage`, CLI status, and related status surfaces as the supported quota/cost visibility path and do not add persistent footer customization now.

## Solution Assessment

Unclear until maintainers choose the product boundary. A config template is plausible, but a plugin/API-driven footer seam fits OpenClaw's plugin-first architecture better than hardcoding provider-specific fields in the TUI.
