## Summary

Keep open: current main and v2026.6.11 still do not implement configurable persistent TUI footer fields for cost, balance, or rate-limit status. Related `/usage` quota-footer and PluginStatusProvider work are useful partial overlaps, but they are open/narrower and do not settle the broader TUI footer product/API boundary.

## What This Changes

Request configurable persistent TUI footer fields/templates that can show model, token, cost, provider balance, and rate-limit cooldown status via core config or plugin/provider hooks.

## Best Possible Solution

Keep this as the broad TUI footer observability tracker, land or close the narrower related PRs on their own merits, and choose a plugin/API-first persistent footer design before adding provider-specific cost, balance, or cooldown rendering.

- **Keep existing usage surfaces:** Keep `/status`, `/usage`, CLI status, and menu-bar usage as the supported quota/cost surfaces and close persistent footer customization as not planned.
