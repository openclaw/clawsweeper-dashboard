## Summary

Keep open: current main and v2026.6.11 still have a fixed TUI footer with model/tokens only, while `/usage` templates, usage-cost commands, and provider-quota work only partially cover the requested persistent TUI footer fields.

## What This Changes

Request configurable TUI footer fields for model, token, cost, balance, and rate-limit/cooldown status via a footer template or plugin hook.

## Best Possible Solution

Keep this as the broad TUI footer observability tracker while maintainers choose a plugin status-provider, TUI config, or provider-usage reuse design that avoids core one-off polling.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a feature request. Source inspection verifies the requested configurable persistent TUI footer is absent on current main and v2026.6.11, while related `/usage` and `/status` surfaces exist.

## Solution Assessment

No; a direct core footer template plus provider balance poller is not clearly the best solution without maintainer direction. A Plugin SDK status-provider seam or narrower provider-usage reuse may be cleaner, but those paths do not yet cover the full requested TUI behavior.
