## Summary

Keep open: current main and v2026.6.11 still have a fixed persistent TUI footer, while existing `/usage` templates, `/status` quota output, and related PRs only cover narrower pieces of the requested cost, balance, and cooldown footer design.

## What This Changes

The issue requests configurable persistent TUI footer fields for model, tokens, estimated cost, provider balance, and rate-limit/cooldown status.

## Best Possible Solution

Keep this as the broad TUI footer observability tracker, decide the core-config versus plugin/API boundary, and let the narrower `/usage` quota and PluginStatusProvider PRs land or close on their own merits.

- **Keep existing status surfaces:** Leave `/status`, `/usage`, CLI status, and menu-bar usage as the supported quota/cost surfaces and reject persistent footer customization for now.
