## Summary

Keep open: current main and the latest release still have a fixed persistent TUI footer, while `/usage`, `/status`, provider-usage, and usage-template work only partially cover the cost/quota visibility request. The linked PluginStatusProvider and provider-quota `/usage` items are useful but narrower, so this remains the broad product/API tracker.

## What This Changes

The issue requests customizable TUI footer fields for estimated cost, remaining balance, rate-limit/cooldown status, and possibly plugin-provided footer data.

## Best Possible Solution

Keep this as the broad TUI footer observability tracker, use existing `/status` and `/usage` surfaces meanwhile, and have maintainers choose whether the durable shape is a PluginStatusProvider seam, a TUI config surface, or narrower provider-usage footer follow-ups.

## Reproduction Assessment

Not applicable as a bug repro; this is a feature request. Source inspection verifies the requested configurable persistent TUI footer is absent on current main and v2026.6.11, while related `/usage` and `/status` surfaces exist.

## Solution Assessment

No, not as the direct core template/balance-poller proposal in the issue. A Plugin SDK status-provider seam, a carefully scoped TUI config surface, or reuse of provider-usage surfaces may be cleaner, but maintainers need to choose the public API and security boundary first.
