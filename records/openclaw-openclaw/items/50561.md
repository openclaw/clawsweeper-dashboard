## Summary

Keep open. Current main and the latest release still keep Gateway startup read-only for config repair: startup validates, refuses invalid config, and tells the operator to run doctor instead of auto-applying repairs.

## What This Changes

The issue requests automatic safe doctor repair during Gateway startup, or an opt-in `doctor.autoFix`-style setting for that behavior.

## Best Possible Solution

A maintainer should first decide the startup mutation policy; if allowed, implement only a narrow, logged, opt-in safe-repair subset with upgrade, provider, security, and channel tests rather than running broad `doctor --fix` during Gateway startup.
