## Summary

Keep open. Current main and v2026.6.11 still keep Gateway startup repair manual, while the requested unattended startup repair would mutate compatibility- and security-sensitive config/channel/provider/plugin state and needs maintainer policy before implementation.

## What This Changes

Request to auto-apply safe, non-destructive `openclaw doctor --fix` repairs during Gateway startup, or add a `doctor.autoFix`-style opt-in with audit logging.

## Best Possible Solution

Define a bounded startup repair contract first: classify unattended-safe doctor mutations, exclude security/sandbox/channel/provider/plugin/auth changes unless explicitly opted in, log every redacted changed path with backup details, and keep broad repair behind manual `openclaw doctor --fix`.

## Reproduction Assessment

Yes, at source level: Gateway startup validates the snapshot and emits doctor guidance instead of invoking the doctor repair sequence. I did not run a live Gateway because this review is read-only.

## Solution Assessment

No, auto-running the whole existing doctor repair sequence during every startup is not the best fix. The maintainable path is a bounded safe-repair subset or explicit opt-in with audit logs and no-clobber boundaries for security, provider, plugin, auth, and channel settings.
