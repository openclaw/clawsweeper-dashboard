## Summary

Keep open. Current main and the latest release still keep ordinary Gateway startup repair manual, while the issue discussion shows unattended broad doctor writes can affect sandbox posture and channel availability, so this remains a product/security policy decision rather than cleanup closure.

## What This Changes

The issue requests automatic safe `doctor --fix` behavior during Gateway startup, or a configuration option for it, to avoid repeated startup warnings and config drift.

## Best Possible Solution

Define a narrow startup repair contract first: classify unattended-safe doctor mutations, exclude security/sandbox/channel/provider/plugin/auth changes unless explicitly opted in, log every redacted changed path with backup details, and keep broad repair behind manual `openclaw doctor --fix`.
