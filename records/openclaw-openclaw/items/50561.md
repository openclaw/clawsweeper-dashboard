## Summary

Keep open. Current main and v2026.6.11 still keep ordinary Gateway startup repair manual, and the issue discussion shows unattended broad doctor writes can affect sandbox and channel availability, so this needs maintainer product/security policy before implementation.

## What This Changes

The issue asks OpenClaw to auto-apply safe, non-destructive doctor fixes during Gateway startup, optionally behind a `doctor.autoFix` setting, and log what changed.

## Best Possible Solution

Define a bounded startup repair contract first: classify unattended-safe doctor mutations, exclude security/sandbox/channel/provider/plugin/auth changes unless explicitly opted in, log every redacted changed path with backup details, and keep broad repair behind manual `openclaw doctor --fix`.

## Reproduction Assessment

Yes, by source inspection: Gateway startup validates the snapshot and emits doctor guidance instead of invoking the doctor repair sequence, and the recovery test pins invalid config as rejected without automatic recovery. I did not run a live Gateway because this review is read-only.

## Solution Assessment

No for the broad requested shape: auto-running the whole existing doctor repair sequence during every startup is not the best fix. The maintainable path is a bounded safe-repair subset or explicit opt-in with audit logs and no-clobber boundaries for security, provider, plugin, auth, and channel settings.
