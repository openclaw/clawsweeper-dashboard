## Summary

Keep open. Current main and the latest release still keep ordinary Gateway startup repair manual, while the discussion shows unattended broad doctor writes can affect sandbox posture and channel availability, so this remains a product/security policy item rather than cleanup closure.

## What This Changes

The issue requests automatic safe doctor repair during Gateway startup, or an opt-in setting, so users do not repeatedly see manual `openclaw doctor --fix` guidance.

## Best Possible Solution

Define a narrow startup repair contract first: classify unattended-safe doctor mutations, exclude security/sandbox/channel/provider/plugin/auth changes unless explicitly opted in, log every redacted changed path with backup details, and keep broad repair behind manual `openclaw doctor --fix`.

## Reproduction Assessment

Yes, by source inspection: Gateway startup validates the snapshot and emits doctor guidance instead of invoking the doctor repair sequence. I did not run a live Gateway because this review is read-only.

## Solution Assessment

No, auto-running the whole existing doctor repair sequence during every startup is not the best fix. A bounded safe-repair subset or explicit opt-in with audit logs and no-clobber boundaries is the safer maintainable direction.
