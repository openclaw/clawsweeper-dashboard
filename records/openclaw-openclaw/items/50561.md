## Summary

Keep open. Current main still rejects invalid Gateway startup config with manual doctor guidance and only runs doctor repairs from explicit repair modes, while unattended repair would cross security, channel-delivery, provider, auth, plugin, and persisted-config boundaries that need maintainer policy.

## What This Changes

Request auto-applying safe, non-destructive doctor repairs during Gateway startup, or adding a `doctor.autoFix` opt-in, with logs of applied changes.

## Best Possible Solution

Define a narrow, maintainer-approved startup repair contract that only runs classified unattended-safe mutations, logs redacted changed paths with backup details, and leaves broad doctor repair behind manual `openclaw doctor --fix` or explicit opt-in.
