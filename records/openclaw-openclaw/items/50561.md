## Summary

Keep open. Current main and the latest release still keep Gateway startup mostly read-only: startup validates config, applies only runtime-only plugin auto-enable, and emits manual `openclaw doctor --fix` guidance, while broad doctor repair remains explicit repair-mode behavior that needs maintainer policy before it runs during startup.

## What This Changes

The issue requests unattended safe doctor repair during Gateway startup, or an opt-in `doctor.autoFix` setting, with logs showing what changed.

## Best Possible Solution

Define a narrow startup repair contract before implementation: keep broad `doctor --fix` manual, and allow only logged, backed-up, operator-approved or explicitly opt-in unattended repairs for classes maintainers classify as safe.
