## Summary

Keep open. Current main and v2026.6.11 still reject invalid Gateway startup config with manual `openclaw doctor --fix` guidance instead of applying doctor repairs, and the discussion includes credible safety counterexamples where unattended repair changed sandbox and Telegram settings.

## What This Changes

Request Gateway startup to auto-apply safe, non-destructive doctor repairs or expose a `doctor.autoFix`-style option while logging applied changes.

## Best Possible Solution

Define a narrow, auditable startup-repair contract: only idempotent schema/state migrations should run unattended, every mutation needs a log/diff summary, and security/channel/provider toggles should remain manual or explicit opt-in.
