## Summary

Keep open. Current main and v2026.6.11 still validate Gateway startup config and emit manual doctor guidance rather than auto-applying doctor repairs, while the discussion shows broad startup `doctor --fix` can silently affect sandbox and Telegram availability.

## What This Changes

Request to auto-apply safe doctor fixes on Gateway startup, or add a `doctor.autoFix`-style option, so repeated config-drift warnings do not require manual repair.

## Best Possible Solution

Define a narrow, maintainer-approved startup repair contract that only runs explicitly classified unattended-safe doctor mutations, excludes security/sandbox/channel/auth/provider/plugin-disablement changes unless opted in, logs every redacted changed path with backup details, and leaves broad repair behind manual `openclaw doctor --fix`.
