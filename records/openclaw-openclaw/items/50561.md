## Summary

Keep open. Current main still keeps ordinary Gateway startup read-only for doctor repairs and explicitly points users to `openclaw doctor --fix`; the request remains a product/security decision because unattended repair can affect sandbox, channel availability, plugin/provider routing, and persisted config.

## What This Changes

Request auto-applying safe or non-destructive doctor fixes during Gateway startup, optionally via an opt-in config setting, with logs of applied changes.

## Best Possible Solution

Define a vetted startup repair contract before implementation: keep broad doctor repair manual, allow only audited safe startup mutations or a named opt-in mode, exclude security/channel/provider/auth changes by default, and log redacted changed paths with backup/recovery details.
