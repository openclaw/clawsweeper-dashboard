## Summary

Keep open. Current main and the latest release still keep Gateway startup repair manual, and the discussion shows unattended doctor writes can affect sandbox and channel availability, so this needs maintainer product/security policy rather than cleanup closure.

## What This Changes

The issue asks for Gateway startup to auto-apply safe, non-destructive doctor fixes or offer an opt-in setting, with logging of any applied changes.

## Best Possible Solution

Define an explicit, audited startup-repair policy first: an opt-in or very narrow default-safe subset, no silent security/channel changes, logged diffs, and upgrade tests for both successful repairs and skipped risky fixes.

## Reproduction Assessment

Yes, at source level. Current Gateway startup loads and validates config, sets `wroteConfig = false`, and tests assert invalid config is rejected with a doctor hint instead of automatic recovery.

## Solution Assessment

No, not as unconditional auto-apply. The maintainable path is a maintainer-approved safe-repair policy with logging, security/channel exclusions, and clear default or opt-in semantics.
