## Summary

Keep open. Current main and v2026.6.11 still keep ordinary Gateway startup read-only for config repair: startup validates, emits `openclaw doctor --fix` guidance, and leaves persistent doctor repair to explicit doctor/update paths. The requested unattended startup repair remains a product/security policy decision because broad doctor repair can mutate channel, plugin, auth, provider, and sandbox-adjacent config before an operator sees a diff.

## What This Changes

Request to auto-apply safe doctor fixes during Gateway startup, or expose an opt-in `doctor.autoFix`-style setting, while logging what was changed.

## Best Possible Solution

Define a narrow startup repair contract before implementation: keep broad `doctor --fix` manual, and only allow logged, backed-up, opt-in unattended repairs for explicitly safe classes with provider, security, upgrade, and channel regression coverage.
