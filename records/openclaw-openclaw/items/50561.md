## Summary

Keep open. Current main and v2026.6.11 still keep ordinary Gateway startup read-only for persisted config: startup validates, emits manual `openclaw doctor --fix` guidance, and only applies runtime-only startup adjustments, while broad doctor repair remains an explicit repair-mode path that needs maintainer policy before it runs unattended.

## What This Changes

The issue requests automatic safe doctor repairs during Gateway startup, or an opt-in `doctor.autoFix` setting, to reduce repeated doctor warnings and config drift.

## Best Possible Solution

Define a narrow startup repair contract first: keep broad `doctor --fix` manual, allow only logged and backed-up unattended repairs that maintainers classify as safe, and require explicit opt-in for security-, sandbox-, provider-, or channel-affecting changes.
