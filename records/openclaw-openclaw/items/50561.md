## Summary

Keep open. Current main and latest release still make Gateway startup validate and guide the operator to `openclaw doctor --fix`, while the requested unattended repair would mutate config during a security-, provider-, and channel-sensitive startup path that needs maintainer policy.

## What This Changes

Request auto-applying safe doctor repairs during Gateway startup, or adding an opt-in `doctor.autoFix` configuration path with logging of applied repairs.

## Best Possible Solution

Define a narrow startup repair contract before implementation: keep broad `doctor --fix` manual, and only allow logged, backed-up, opt-in unattended repairs for explicitly safe classes with provider, security, upgrade, and channel regression coverage.
