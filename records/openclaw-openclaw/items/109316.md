## Summary

Keep open. Current main provides shared inbound, ingress, reply-pipeline, and durable-delivery primitives, but repository documentation still identifies channel-owned prepared dispatchers and transport side effects that prevent the requested single core-owned lifecycle; the protected `maintainer` label also requires explicit maintainer handling. ([docs.openclaw.ai](https://docs.openclaw.ai/plugins/sdk-channel-inbound))

## What This Changes

Refactor inbound channel processing so core owns shared routing, context, session, dispatch, and delivery lifecycle while channel plugins provide transport-specific facts and native operations.

## Best Possible Solution

Extend the existing channel-inbound and message-lifecycle primitives into one core planner, migrate bundled channels in coherent stages with sibling parity and architecture guards, and remove prepared paths only after every channel-specific delivery side effect has an explicit tested contract.
