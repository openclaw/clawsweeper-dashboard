## Summary

Keep this PR open for maintainer review. It has strong focused test and formatter-transcript evidence, but the prior P1 remains: ZaloUser relies on parser metadata that is intentionally hidden from the public `MarkdownIR`/plugin-SDK contract, creating an undocumented cross-package coupling that needs an explicit supported seam or maintainer-approved internal-contract decision.

## What This Changes

The PR replaces ZaloUser’s local Markdown block scanner with CommonMark parser metadata for headings, lists, containers, indentation, and code-block styles.

## System Context

ZaloUser converts outgoing Markdown into Zalo range styles before the channel sends a message. The shared markdown-core parser produces the intermediate representation consumed by the formatter, so parser metadata must remain stable for the formatter to preserve Zalo list and block rendering.

## Architecture Diagram

flowchart LR

  B --> C[Markdown IR and block metadata]
  C --> D[ZaloUser formatter]
  D --> E[Zalo style ranges]
  E --> F[Zalo delivery]

## Best Possible Solution

Define one supported ownership boundary for parser block metadata: either expose a narrow documented plugin-SDK capability with compatibility tests, or record maintainer approval for a deliberately internal bundled-plugin facade and test that facade as a stable contract.
