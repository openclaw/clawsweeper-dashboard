Full review comments:

- **[P2] Keep cron retry warnings aligned with actual fallback:** `src/cron/service/timer.ts:875-886`
  - body: This warning runs whenever `normalNext` is `undefined`, before the later `job.schedule.kind` branch. For cron schedules, current main then calls `resolveCronNextRunWithLowerBound(...)`, logs the existing unresolved-schedule warning, and clears `nextRunAtMs`; it does not fall back to error backoff. Move this warning to the actual non-cron fallback or make the message schedule-specific.
  - confidence: 0.92
- **[P2] Do not warn for normal on-exit completions:** `src/cron/service/timer.ts:959-968`
  - body: The completion warning is in the non-cron `else` branch and fires whenever `naturalNext` is `undefined`. On current main, `on-exit` schedules are event-driven and intentionally return `undefined` from `computeNextRunAtMs`, so a successful forced on-exit run can produce a false warn-level "unresolved" diagnostic. Gate the warning to schedule kinds where missing `nextRunAtMs` is actually a degradation.
  - confidence: 0.85
