## Summary

Keep this PR open, but it is not merge-ready: the observability direction is useful, yet the transient-error warning is currently misleading for cron schedules and the contributor proof is still only focused Vitest output rather than real runtime logs or terminal evidence.

## What This Changes

The PR adds warn logs and regression tests for cron paths where `nextRunAtMs` becomes `undefined` after completion, transient-error retry, or maintenance recompute.

## Best Possible Solution

Keep the observability work, but gate or reword the transient-error warning so it matches the actual cron/non-cron branch, then require redacted real runtime or terminal proof before merge.

## Reproduction Assessment

Yes, source-level. The PR inserts the new transient-error warning before the current schedule-kind branch, and current main then clears cron schedules through `resolveCronNextRunWithLowerBound` when `normalNext` is undefined.

## Solution Assessment

No. Adding warnings is reasonable, but the transient-error warning should be moved, gated, or reworded so cron does not emit a fallback-to-backoff diagnostic when the schedule is actually cleared.
