Overall correctness: patch is incorrect

Full review comments:

- **[P2] Gate completion warnings away from on-exit jobs:** `src/cron/service/timer.ts:962-970`
  - body: This warning sits in the generic non-cron completion branch. After merging with current main, successful `on-exit` jobs also reach this branch, and their `computeNextRunAtMs` is intentionally `undefined` because they are event-driven. That would produce a misleading unresolved-schedule warning for normal on-exit completions; restrict this to the intended schedule kinds or skip `on-exit`.
  - confidence: 0.92
- **[P2] Do not claim cron retries fall back to backoff:** `src/cron/service/timer.ts:878-886`
  - body: This warning runs before the later schedule-kind branch. For cron jobs, current main then calls `resolveCronNextRunWithLowerBound(...)`, which warns and clears the schedule when `normalNext` is undefined, so operators would see a conflicting message that says the job is falling back to error backoff. Move or reword the warning so cron keeps one accurate diagnostic.
  - confidence: 0.91
