## Summary

This PR still contains useful cron observability work, but it is not merge-ready: the transient-error warning can describe the wrong behavior for cron schedules, and the contributor proof is still mock/test output rather than real cron runtime logs or terminal evidence. The related narrower PR was closed unmerged after maintainer feedback, so it is not a viable superseding fix path.

## What This Changes

The PR adds warn logs and regression tests for cron paths that clear `nextRunAtMs` to `undefined` after completion, transient-error retry, or maintenance recompute.

## Best Possible Solution

Keep the observability goal, but make the transient-error warning match the actual schedule-kind behavior, handle invalid schedule state at the cron creation/load/doctor boundary when that is the reachable path, and require redacted real runtime or terminal proof before merge.

## Reproduction Assessment

Yes for the patch defect. Source inspection shows the new warning runs when `normalNext` is undefined before the later cron branch calls `resolveCronNextRunWithLowerBound`, which logs and clears the schedule instead of using error backoff.

## Solution Assessment

No. Adding warnings is a reasonable goal, but the transient-error warning should be moved or gated to the actual non-cron fallback path, and invalid schedule-state handling should live at creation/load/doctor boundaries when that is the concrete reachable case.
