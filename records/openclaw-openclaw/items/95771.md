## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P2] Make the retry warning match the actual branch:** `src/cron/service/timer.ts:878-886`
  - body: This warning runs as soon as `normalNext` is undefined, before the later schedule-kind branch. For cron jobs, that branch calls `resolveCronNextRunWithLowerBound(...)`, logs the existing unresolved-schedule warning, and clears `nextRunAtMs`, so operators would see a new message claiming an error-backoff fallback that is not actually scheduled. Move this warning to the non-cron fallback or make it schedule-specific.
  - confidence: 0.91
- **[P3] Skip event-driven schedules in the completion warning:** `src/cron/service/timer.ts:959-967`
  - body: `on-exit` schedules intentionally never have a time-based next run, and supported force-runs of an enabled on-exit job can reach this generic non-cron completion branch. In that case the new warning says the job will not reschedule even though the event watcher is the schedule, so gate this warning to the concrete `every`/cron unresolved paths or reword it for schedule kind.
  - confidence: 0.77
