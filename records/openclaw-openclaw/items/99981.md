## Summary

Keep open. Current main still raw-slices node-host exec event output at the tail boundary, and a focused source check confirms that an odd UTF-16 tail cut can leave a lone low surrogate; the repository already has a tested helper for this exact boundary.

## What This Changes

The issue requests fixing node-host exec event tail truncation so UTF-16 surrogate pairs are not split when output is capped.

## Best Possible Solution

Make node-host exec output truncation use the existing UTF-16-safe helper, add a boundary regression, and keep the output caps and configuration unchanged.

## Reproduction Assessment

Yes for the core failure mode: current source uses the reported raw slice, and a focused Node check reproduces a non-well-formed tail string. I did not run a full node-host system.run scenario in this read-only review.

## Solution Assessment

Yes. Reusing `sliceUtf16Safe` for tail truncation is the narrowest maintainable fix, with a small follow-through check for downstream exec event compaction.
