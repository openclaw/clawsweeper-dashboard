## Summary

Keep open: current main and the latest release still use raw UTF-16 `slice` for node-host exec event tail truncation, and a focused Node check reproduces an ill-formed string when the cut lands inside an emoji surrogate pair.

## What This Changes

The issue asks OpenClaw to make node-host `system.run` exec output truncation UTF-16-surrogate-safe instead of using raw `String.slice`.

## Best Possible Solution

Reuse the existing UTF-16-safe helper at the node-host exec output tail boundary, audit adjacent exec-event compaction, and add a regression test with emoji or CJK-extension output crossing the truncation boundary.

## Reproduction Assessment

Yes at source level: current main uses the same raw tail-slice expression, and a focused Node command reproduces `isWellFormed() === false`. I did not run the full node-host `system.run` path end-to-end.

## Solution Assessment

Yes: using the existing `sliceUtf16Safe`/`truncateUtf16Safe` helper is the narrowest maintainable fix because the repository already has that contract and tests for this exact Unicode boundary.
