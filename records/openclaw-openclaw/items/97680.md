## Summary

Keep open: current main still resolves an explicit beta package tag for the core update but passes only the selected/stored update channel into post-core official plugin convergence, so the reported beta-core/latest-plugin drift remains source-reproducible.

## What This Changes

Ensure explicit beta-tag OpenClaw updates align official external npm plugins with the requested beta version, or clearly warn/fail instead of silently installing latest-stable plugins.

## Best Possible Solution

Define explicit-tag semantics: when core installs an exact OpenClaw beta version, trusted official default-line plugins should target that same exact version when available, with ordinary beta-channel fallback kept separate and documented.

- **Exact match fail-closed:** Require matching official plugin artifacts for explicit beta core updates and fail the post-core update when any active trusted official plugin cannot align.
- **Keep current fallback:** Keep beta plugin convergence on channel/default fallback semantics and document that explicit core tags do not imply plugin exact-version alignment.

## Solution Assessment

Unclear until maintainers choose warn-versus-fail semantics. The narrow maintainable shape is to pass the resolved exact core beta version into trusted official plugin sync while preserving ordinary beta-channel fallback behavior.
