## Summary

Keep open: current main still routes post-core official plugin convergence through update-channel context rather than the explicit beta version requested for the core package, and the stable-target retest only proves the stable path now behaves correctly.

## What This Changes

The issue asks for beta-tagged `openclaw update --tag <beta-version>` to keep official external plugins aligned to the requested beta version or warn/fail when matching plugin artifacts are unavailable.

## Best Possible Solution

Define exact-version semantics for explicit update tags, then implement trusted official plugin convergence so matching plugin versions are selected or the operator gets a clear warning/failure.

## Reproduction Assessment

Yes for source-level reproduction, but not for a live end-to-end beta-tag replay. Current main resolves the explicit core package tag while post-core plugin convergence still receives only channel context and can fall back to latest/default.

## Solution Assessment

Unclear until maintainers choose the exact-tag semantics. The narrow maintainable path is to pass the resolved explicit OpenClaw target into trusted official plugin sync and preserve beta-channel fallback only where it does not defeat an explicit requested version.
