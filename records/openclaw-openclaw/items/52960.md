## Summary

Keep open: current main and v2026.6.11 still expose only coarse Control UI run state and a boolean session active-run flag, while the requested compact phase/progress strip depends on unresolved gateway/session activity semantics and open implementation candidates.

## What This Changes

Request a compact Control UI run-progress surface showing run phase, latest meaningful action, last activity, elapsed time, and reconnect/subagent/tool wait state for long or multi-agent tasks.

## Best Possible Solution

Land one gateway-backed session activity and attention contract, then render a compact Control UI status strip from that state without raw logs, message-text inference, or channel-local heuristics.
