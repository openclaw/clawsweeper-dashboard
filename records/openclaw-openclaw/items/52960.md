## Summary

Keep open: current main still exposes only coarse Control UI active-run state, while the requested compact progress strip needs phase/latest-action/last-activity/elapsed/reconnect semantics and likely depends on the still-open gateway activity contract.

## What This Changes

Request a compact Control UI run-progress surface for long or multi-agent tasks, including active phase, latest meaningful action, timing, and reconnect context.

## Best Possible Solution

Land one gateway-backed session activity/attention contract, then render a compact Control UI status strip near the active chat composer or thread without raw logs or message-text inference.

## Reproduction Assessment

Yes, at source level: current main renders only coarse in-progress/done/interrupted chat status and exposes no sessions.activity RPC or activity statechange event. This is a feature gap rather than a failing documented command reproduction.

## Solution Assessment

Unclear until maintainers settle the API and UX shape. The maintainable direction is a gateway-backed activity/attention contract plus a small Control UI presentation layer, not local inference from existing tool streams alone.
