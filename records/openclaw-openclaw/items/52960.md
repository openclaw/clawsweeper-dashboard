## What This Changes

Request a compact Control UI run-progress display for long or multi-agent tasks, including phase, latest action, timing, and reconnect/session context.

## Best Possible Solution

Define or reuse one gateway-backed session activity and attention contract, then render a compact Control UI status strip near the composer or thread without raw logs or message-text inference.

## Reproduction Assessment

Yes, at source level: current main renders only a coarse in-progress/done/interrupted composer chip and exposes no sessions.activity RPC or activity statechange model. This is a feature gap rather than a failing documented command reproduction.

## Solution Assessment

Yes for the requested direction, if implemented as a gateway-backed activity/attention model plus compact UI. A UI-only heuristic over message text, abortability, or tool streams would not be the best fix.
