Keep open: current main and the latest release still provide only coarse Control UI/session run state, while the requested compact progress strip needs phase, latest action, last activity, elapsed time, and reconnect context. ## What This Changes

The issue requests a compact Control UI run-progress surface for long or multi-agent tasks, including phase, latest action, last activity, elapsed time, and reconnect context.

## Best Possible Solution

Define or reuse one canonical gateway session activity/attention contract, then render a compact Control UI status strip near the composer or thread without raw logs or message-text inference.

## Reproduction Assessment

Yes, at source level: current main renders only coarse in-progress/done/interrupted chat status and exposes no sessions.activity RPC or activity statechange event. This is a feature gap rather than a failing documented command reproduction, and I did not run a live multi-agent Control UI scenario.

## Solution Assessment

No current implementation is sufficient. The maintainable path is a gateway-backed activity/attention contract plus a small Control UI presentation layer, not local UI inference from message text, abortability, or tool streams alone.
