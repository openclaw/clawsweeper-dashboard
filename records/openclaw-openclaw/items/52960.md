## Summary

Keep open: current main still has only coarse chat/session run status and tool-activity summaries, while the requested compact active-run progress strip depends on an unresolved gateway/session activity contract and unmerged related PRs.

## What This Changes

The issue requests a compact Control UI run-progress surface for long or multi-agent tasks, including phase, latest activity, elapsed time, reconnect context, and waiting/subagent state.

## Best Possible Solution

Land one gateway-backed session activity and attention contract, then render a compact Control UI status strip from that structured state without raw logs or message-text inference.
