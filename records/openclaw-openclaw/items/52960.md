## Summary

Keep open: current main and the latest release still expose only coarse chat run status plus session/tool events, while the canonical backend activity issue and implementation PR candidates remain open and need maintainer API/UX review before this UI request can close.

## What This Changes

The issue requests a compact Control UI active-run progress display with phase, latest action, timing, and reconnect context for long or multi-agent tasks.

## Best Possible Solution

Define or reuse one canonical gateway session activity/attention contract, then render a compact Control UI status strip near the composer or thread without raw logs or message-text inference.

## Reproduction Assessment

Yes at source level: current main renders only coarse in-progress/done/interrupted chat status and exposes existing `session.tool`/`sessions.changed` surfaces, not a compact run-progress model with phases, latest action, last activity, elapsed time, and reconnect context.

## Solution Assessment

No current implementation is sufficient. The maintainable path is a gateway-backed activity/attention contract plus a small Control UI presentation layer, not local UI inference from message text, abortability, or tool streams alone.
