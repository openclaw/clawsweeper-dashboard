## Summary

Keep open: current main and v2026.6.11 still expose only coarse chat run status and session active-run flags, not the requested compact phase/latest-activity/elapsed/reconnect progress strip. The related implementation PR remains open but conflict-marked and blocked on proof/API review, so it is not a merged replacement.

## What This Changes

Request a compact, low-noise Control UI run-progress surface for long or multi-agent runs, including phase, latest action, last activity, elapsed time, and reconnect context.

## Best Possible Solution

Define or reuse one canonical gateway session activity/attention contract, then render a compact Control UI status strip near the composer or thread without raw logs or message-text inference.

## Reproduction Assessment

Yes at source level: current main renders only a coarse in-progress/done/interrupted composer chip and exposes no compact activity model with phase, latest action, last activity, elapsed time, or reconnect context. This is a feature gap rather than a failing documented command reproduction.

## Solution Assessment

Unclear until maintainers settle the API and UX contract. The maintainable direction is gateway-backed activity/attention state plus a small Control UI presentation layer, not local inference from message text or tool streams alone.
