## Summary

Keep open: current main still lacks the requested compact phase/progress model, and overlapping open issues and PRs show the remaining work needs a maintainer-owned gateway activity contract plus Control UI UX boundary.

## What This Changes

Request to add a compact Control UI run-progress/status strip for long or multi-agent tasks, including phase, latest action, last activity, elapsed time, and reconnect context.

## Best Possible Solution

Define one gateway-backed session activity and attention contract first, then render a compact Control UI status strip from that state without raw logs, message-text inference, or browser-local lifecycle guesses.
