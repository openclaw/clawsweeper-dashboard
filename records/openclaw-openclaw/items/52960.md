## Summary

Keep open: current main and the latest release still expose only coarse Control UI run status and active-run flags, while the overlapping implementation PRs remain open and need maintainer API/UX direction plus real behavior proof before this issue can close.

## What This Changes

The issue requests a compact Control UI run-progress surface for long and multi-agent tasks, including current phase, latest meaningful action, last activity, elapsed time, and reconnect context.

## Best Possible Solution

Settle one gateway-backed activity/attention contract, then render a compact Control UI status strip near the composer or thread without raw logs or message-text inference.
