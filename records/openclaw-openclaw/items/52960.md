## Summary

Keep open: current main and the latest release still expose only coarse Control UI run status and session active-run flags, while the requested compact phase/progress strip depends on unresolved gateway/session activity semantics and overlapping open implementation candidates.

## What This Changes

The issue requests a compact Control UI run-progress/status surface for long or multi-agent tasks, including phase, latest meaningful action, last activity, elapsed time, and reconnect signal.

## Best Possible Solution

Settle one gateway-backed session activity and attention contract, then render a compact Control UI status strip from that state without raw logs, message-text inference, or channel-local heuristics.
