## Summary

Keep open: current main still has only coarse Control UI run status plus active-run flags, while the canonical gateway activity contract and open UI implementation candidates are not merged or accepted yet.

## What This Changes

The issue requests a compact Control UI run-progress strip for long or multi-agent tasks, including current phase, latest action, last activity, elapsed time, and reconnect context.

## Best Possible Solution

Define or reuse a canonical gateway-backed session activity/attention contract, then render a compact Control UI status strip near the composer or thread without raw logs or message-text inference.

## Reproduction Assessment

Yes, at source level: current main renders only a coarse in-progress/done/interrupted composer chip and active-run boolean, not the requested compact phase/latest-action/elapsed/reconnect progress model. I did not run a live browser scenario in this read-only review.

## Solution Assessment

No current implementation is sufficient. The maintainable path is a gateway-backed activity/attention contract plus a small Control UI presentation layer, not local UI inference from message text, abortability, or tool streams alone.
