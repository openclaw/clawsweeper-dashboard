## Summary

Keep open: current main still exposes only coarse active/terminal run state in the Control UI and sessions RPCs, while this issue asks for a new compact phase/progress model that overlaps unresolved session-activity API and UI direction.

## What This Changes

The issue requests a compact Control UI status strip for long or multi-agent runs, including phase, latest meaningful action, last activity, elapsed time, and reconnect context.

## Best Possible Solution

Land one gateway-backed session activity and attention contract, then render a compact Control UI status strip from that state without raw logs, message-text inference, or channel-local heuristics.
