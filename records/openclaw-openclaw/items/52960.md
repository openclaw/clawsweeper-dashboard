## Summary

Keep open: current main and v2026.6.11 still expose only coarse chat/session activity signals, not the requested compact active-run progress strip with phase, latest action, last activity, elapsed time, and reconnect context. ## What This Changes

Request a compact Control UI run-progress/status surface for long or multi-agent tasks.

## Best Possible Solution

Land one gateway-backed session activity/attention contract, then render a compact Control UI status strip near the active chat composer or thread without raw logs or message-text inference.

## Reproduction Assessment

Yes, at source level: current main renders only coarse in-progress/done/interrupted chat status and exposes no sessions.activity RPC or activity statechange event. This is a feature gap rather than a failing documented command reproduction.

## Solution Assessment

Yes directionally, but the implementation path needs maintainer API/UX review. The maintainable fix is a gateway-backed activity/attention contract plus a small Control UI presentation layer, not local UI inference from existing tool streams alone.
