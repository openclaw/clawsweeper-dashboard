## Summary

Keep open: current main and v2026.6.11 still provide only a coarse Control UI run chip plus browser-local tool Activity, not the requested compact active-run progress model with phase, latest action, last activity, elapsed time, and reconnect context. The broader gateway activity contract remains open at https://github.com/openclaw/openclaw/issues/39127, while https://github.com/openclaw/openclaw/pull/96672 and https://github.com/openclaw/openclaw/pull/92697 are open, conflict-marked implementation candidates that still need maintainer review and proof.

## What This Changes

This issue requests a compact Control UI progress surface for long or multi-agent runs that shows current run state, latest meaningful activity, timing, and reconnect context without exposing verbose logs.

## Best Possible Solution

Define one gateway-owned activity/attention contract, or explicitly accept a narrower existing task/session signal, then render a compact Control UI status strip near the composer or thread without raw logs or message-text inference.

## Reproduction Assessment

Yes, at source level: current main exposes only coarse run status and browser-local tool Activity, while the requested activity fields/RPC/event are absent from the Control UI and gateway contracts. This is a feature gap rather than a failing existing contract reproduction.

## Solution Assessment

Unclear until maintainers accept the product/API shape. The maintainable direction is a gateway-backed activity/attention contract plus a small Control UI presentation layer, not local inference from message text, abortability, or tool streams alone.
