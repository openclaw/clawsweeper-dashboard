## Summary

Keep open. Current main still does not handle the generic missing-cwd ACP init failure, so the PR is useful, but the proposed catch path can also delete bindings for pre-runtime policy rejections and needs a narrow repair before merge.

## What This Changes

The PR adds cwd-aware ACP dispatch stale-binding cleanup for generic ACP session init failures and regression tests for missing versus existing persisted cwd.

## Best Possible Solution

Keep the missing-cwd recovery, but confine cwd-based unbinding to errors from ACP runtime initialization/runTurn and add a policy-rejection negative regression before maintainer acceptance of the remaining session-state semantics.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path for the PR-introduced blocker: ready ACP session metadata with a missing cwd plus disallowed cfg.acp.allowedAgents throws ACP_SESSION_INIT_FAILED before runTurn and then reaches the new cwd-based cleanup.

## Solution Assessment

No. The recovery direction is right, but the current catch makes the cwd signal too broad; the best fix is to limit it to actual runtime-init/runTurn failures and add the policy-rejection negative test.
