## Summary

Keep open: current main still lacks cwd-based cleanup for the generic ACP init failure, and this branch is a focused useful fix, but the current diff can still delete persisted ACP bindings for pre-runtime policy failures rather than only runtime-init failures.

## What This Changes

The PR extends ACP dispatch stale-binding cleanup to unbind a bound session when a generic ACP_SESSION_INIT_FAILED is paired with a filesystem-confirmed missing persisted runtime cwd, with regression tests.

## Best Possible Solution

Keep the missing-cwd recovery, but confine cwd-based unbinding to errors from ACP runtime initialization/runTurn and add a policy-rejection negative regression before accepting the remaining session-state semantics.

## Reproduction Assessment

Yes. The central missing-cwd recovery has copied live staging proof in the PR body, and the remaining blocker is source-reproducible: a ready ACP session with missing cwd plus disallowed allowedAgents throws ACP_SESSION_INIT_FAILED before runTurn and reaches the new cwd cleanup.

## Solution Assessment

No. The recovery direction is right, but the current catch makes the cwd signal too broad; the best fix is to limit it to actual runtime-init/runTurn failures and add the policy-rejection negative test.
