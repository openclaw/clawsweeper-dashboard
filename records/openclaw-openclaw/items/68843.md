## Summary

Keep open: the missing-cwd recovery is useful and has strong live log proof, but the current patch can also delete bound-session state for a pre-runtime allowed-agent policy rejection because the widened cwd signal is evaluated in the broad dispatch catch.

## What This Changes

The PR extends ACP dispatch stale-binding cleanup to unbind bound conversations when a generic ACP_SESSION_INIT_FAILED is paired with a filesystem-confirmed missing persisted runtime cwd, plus regression tests.

## Best Possible Solution

Keep the missing-cwd recovery, but confine cwd-based unbinding to runtime init/runTurn failures and then get explicit maintainer acceptance for the remaining session-state deletion semantics.

## Reproduction Assessment

Yes. The central missing-cwd recovery has copied live staging proof in the PR body and gist, and the remaining blocker is source-reproducible from the ready-session, missing-cwd, allowedAgents rejection path.

## Solution Assessment

No. The recovery direction is right, but the current catch makes the cwd signal too broad; the best fix is to limit it to runtime init/runTurn failures and add the policy-rejection negative test.
