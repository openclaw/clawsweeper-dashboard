## Summary

Keep this PR open: it is a useful ACP stale-binding bug fix with good live proof, but the current patch can delete persisted conversation bindings for a pre-runtime agent-policy rejection rather than an actual stale runtime init failure.

## What This Changes

The PR changes ACP dispatch cleanup so a generic ACP session init failure unbinds a bound conversation when the persisted ACP runtime cwd is missing, with regression coverage for missing and existing cwd cases.

## Best Possible Solution

Keep the missing-cwd recovery, but only honor cwd-based unbinding after the ACP runtime init/runTurn path is actually attempted, then get maintainer acceptance for the remaining session-state deletion semantics.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path for the PR-introduced blocker: a ready ACP session with missing runtimeOptions.cwd plus acp.allowedAgents rejecting the resolved agent throws ACP_SESSION_INIT_FAILED before runTurn and then reaches the new cwd-based cleanup.

## Solution Assessment

No. The recovery direction is right, but the current catch makes the cwd signal too broad; the best fix is to limit it to actual runtime-init/runTurn failures and add the policy-rejection negative test.
