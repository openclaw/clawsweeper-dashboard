## What This Changes

The branch changes `EmbeddedTuiBackend.start()` so the `onAgentEvent` fire-and-forget call attaches a noop rejection handler to `handleAgentEvent(evt)`.

## Best Possible Solution

Land the listener catch after redacted real embedded TUI or focused injected-handler proof is added, with a small regression test if maintainers want stronger local coverage.

## Reproduction Assessment

Yes, from source inspection: current main ignores an async `handleAgentEvent` promise, and that handler can reject when TUI event delivery throws. I did not run a live embedded TUI reproduction in this read-only review.

## Solution Assessment

Yes, this is an acceptable narrow fix: the event bus does not observe returned promises, so observing the fire-and-forget promise at the subscription site addresses the rejection shape without changing TUI event semantics.
