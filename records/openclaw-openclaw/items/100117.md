## What This Changes

The branch changes `EmbeddedTuiBackend` so the `onAgentEvent` listener attaches a noop `.catch()` to the fire-and-forget `handleAgentEvent` promise.

## Best Possible Solution

Land the narrow listener catch after real embedded TUI or focused injected-handler proof is added, with a small regression test in `src/tui/embedded-backend.test.ts` if maintainers want stronger local coverage.

## Reproduction Assessment

Yes, from source inspection: current main ignores an async `handleAgentEvent` promise, and that handler can reject when TUI event delivery throws. I did not run a live embedded TUI reproduction in this read-only review.

## Solution Assessment

Yes, this is an acceptable narrow fix: the shared listener helper only isolates synchronous listener failures, and the PR observes the async wrapper's rejection at the local fire-and-forget call site. Removing `async` or adding logging are alternatives, but the proposed layer is not wrong.
