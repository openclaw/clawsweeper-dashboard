## What This Changes

The PR changes `EmbeddedTuiBackend` so the `onAgentEvent` subscription attaches a noop `.catch()` to the fire-and-forget `handleAgentEvent` promise.

## Best Possible Solution

Keep the narrow fail-open TUI listener fix, preferably with a focused regression test, and require real embedded TUI proof or an explicit maintainer proof override before merge.

## Reproduction Assessment

Yes, from source inspection: current main calls an async `handleAgentEvent` promise without a rejection handler, and that method can reject if the embedded backend event path throws. I did not run a live TUI repro in this read-only review.

## Solution Assessment

Yes, this is an acceptable narrow fix: catching the fire-and-forget promise restores the fail-open listener behavior that synchronous listeners already get. Making `handleAgentEvent` synchronous is a possible cleanup alternative, but the proposed patch is not the wrong layer.
