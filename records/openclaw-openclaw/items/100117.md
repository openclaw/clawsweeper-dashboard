## What This Changes

The PR changes `EmbeddedTuiBackend` so the `onAgentEvent` listener attaches a noop `.catch()` to the fire-and-forget `handleAgentEvent` promise.

## Best Possible Solution

Land the narrow listener catch after real embedded TUI proof is added or a maintainer explicitly overrides the proof gate; a focused regression test in `src/tui/embedded-backend.test.ts` would further strengthen the patch.

## Reproduction Assessment

Yes, from source inspection rather than a live run: current main calls an async `handleAgentEvent` promise without a rejection handler, and that handler can reject if TUI event delivery throws. I did not run a real embedded TUI reproduction in this read-only review.

## Solution Assessment

Yes, this is an acceptable narrow fix: the shared listener helper already isolates synchronous listener failures, and the PR extends that fail-open behavior to this async wrapper. Making the handler synchronous or adding logging are alternatives, but the proposed layer is not wrong.
