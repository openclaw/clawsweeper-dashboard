## Summary

Keep open: current main and v2026.6.11 still lack a trusted parent-scoped mid-run send path for sub-agents; existing parent handoff covers completion events, not child-originated progress updates or clarifying questions.

## What This Changes

Request a parent-only session send mechanism so spawned sub-agents can send mid-run updates or questions to their direct parent session without arbitrary session targeting.

## Best Possible Solution

Define one narrow parent-only send contract derived from trusted active sub-agent metadata, then update policy, resolver/tool schema, delivery behavior, docs, and security regression tests together.

- **Reserve sessionKey:"parent":** Keep sessions_send as the public tool but make parent a trusted resolver keyword rather than a literal caller-provided session key.
- **Decline native mid-run sends:** Keep child-originated mid-run sends unsupported and document completion handoff, sessions_yield, and explicit trusted operator opt-ins as the supported paths.

## Solution Assessment

Yes in direction, but not as a broad ordinary sessions_send opt-in; the maintainable solution is a narrow parent-only operation backed by trusted metadata and security tests.
