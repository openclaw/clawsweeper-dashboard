## Summary

Keep open: current main and the latest release still lack a trusted parent-scoped child-to-parent mid-run send path. Completion handoff, ACP-only parent streaming, and broad opt-in paths for `sessions_send` are adjacent, but they do not implement the requested parent-only, same-tree, no-chaining contract.

## What This Changes

Request to add a safe parent-scoped send mechanism so sub-agents can send mid-run updates or questions only to their direct parent session.

## Best Possible Solution

Define one narrow parent-only send contract derived from canonical active sub-agent metadata, then update policy, resolver, delivery, docs, and security regression tests together.

## Solution Assessment

Yes in direction, but not as a broad opt-in to ordinary `sessions_send`. The maintainable solution is a dedicated parent-only operation or trusted parent selector backed by active run metadata and security tests.
