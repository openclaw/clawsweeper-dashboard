## Summary

Keep open: current main and the latest release still lack a trusted parent-scoped child-to-parent mid-run send path. Completion handoff, ACP-only parent streaming, and broad `sessions_send` opt-ins are adjacent, but they do not implement the requested parent-only, same-tree, no-chaining contract.

## What This Changes

Request a parent-scoped `sessions_send` path so sub-agents can send mid-run updates or questions only to their direct parent session.

## Best Possible Solution

Define one narrow parent-only send contract derived from canonical active sub-agent metadata, then update policy, resolver, delivery, docs, and security regression tests together.

- **Defer To Completion Handoff:** Keep mid-run child-to-parent sends unsupported and focus only on completion announce/session-yield orchestration.
- **Document Broad Opt-In:** Use existing broader allowlist and visibility configuration for trusted operators while accepting the larger authorization surface.

## Reproduction Assessment

Yes, at source level. Current main still denies `sessions_send` to sub-agents by default, has no `sessions_send_parent` tool, and does not resolve a trusted `parent` target from sub-agent metadata.

## Solution Assessment

Yes in direction, but not as a broad opt-in to ordinary `sessions_send`. The maintainable solution is a dedicated parent-only operation or trusted parent selector backed by active run metadata and security tests.
