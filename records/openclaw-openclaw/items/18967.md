## Label Justifications

- `P2`: This is a bounded but security-sensitive sub-agent coordination feature with real workflow impact, not a current outage or data-loss emergency.
- `impact:session-state`: The request changes how active child and parent sessions exchange progress, questions, and state during a sub-agent run.
- `impact:security`: The requested capability creates a new session authorization edge that must enforce parent-only, same-tree, and no-chaining restrictions.

## Summary

Keep open: current main still lacks a trusted parent-scoped mid-run send path for native sub-agents, and the remaining work is a security-sensitive model-facing API decision rather than cleanup.

## What This Changes

Request a native parent-only way for sub-agents to send mid-run progress updates or questions to the direct parent session without arbitrary session targeting.

## Best Possible Solution

Define one narrow parent-only send contract derived from canonical active sub-agent metadata, then update policy, resolver, delivery, docs, and security regression tests together.

Options:

- **Add a dedicated parent-only contract (recommended):** Implement a dedicated tool or trusted parent selector that derives the direct parent from active spawn metadata and rejects missing, stale, sibling, ancestor, cross-agent, and auto-forwarded targets.
- **Reserve sessionKey:"parent":** Keep one sessions_send tool but make parent a special trusted selector rather than a literal user-supplied session key.
- **Decline native mid-run sends:** Keep child-originated mid-run sends unsupported and document completion handoff, sessions_yield, or explicit trusted operator opt-ins as the supported paths.

## Reproduction Assessment

Yes, at source level. Current main still denies sessions_send to sub-agents by default, has no sessions_send_parent tool, and does not resolve a trusted parent target from sub-agent metadata.

## Solution Assessment

Yes in direction, but not as a broad opt-in to ordinary sessions_send. The maintainable solution is a dedicated parent-only operation or trusted parent selector backed by active run metadata and security tests.
