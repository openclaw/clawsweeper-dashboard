## Summary

Keep open: current main and v2026.6.11 still lack a trusted child-to-direct-parent mid-run send path, and the remaining work is a security-sensitive model-facing API decision rather than conservative cleanup.

## What This Changes

Add a parent-scoped send mechanism so native sub-agents can send mid-run updates or questions only to the session that spawned them.

## Best Possible Solution

Define one narrow parent-only send contract derived from active spawn/session metadata, then update policy, resolver, delivery, docs, and regression tests while keeping broad `sessions_send` and `message` opt-ins separate.

## Solution Assessment

Yes in direction, but not as a broad opt-in to ordinary `sessions_send`. The maintainable solution is a dedicated parent-only operation or trusted parent selector backed by active run metadata and security tests.
