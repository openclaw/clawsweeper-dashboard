## Summary

Keep open: current main and the latest release still lack a trusted parent-scoped native send path for mid-run sub-agent updates, while related announce-routing and message-tool items cover adjacent but different behavior.

## What This Changes

Request to add a parent-scoped way for spawned sub-agents to send mid-run updates or questions only to their direct parent session.

## Best Possible Solution

Define one narrow parent-only send contract derived from trusted active sub-agent metadata, then update policy, resolver, delivery behavior, docs, and security regression tests together.

Rationale: The source gap is clear, but the permanent API shape changes child-to-parent session authorization and model-facing tool semantics.

Likely owner: steipete

Owner confidence: high

Options:

- **Add a dedicated parent-only contract (recommended):** Implement a dedicated tool or trusted parent selector that derives the direct parent from active spawn metadata and rejects missing, stale, sibling, ancestor, cross-agent, and forwarded targets.
- **Reserve `sessionKey: "parent"`:** Keep one `sessions_send` tool but make `parent` a trusted resolver keyword rather than a literal caller-provided session key.
- **Decline native mid-run sends:** Keep child-originated mid-run sends unsupported and document completion handoff, `sessions_yield`, and explicit trusted operator opt-ins as the supported paths.

Yes. Source inspection shows current main and v2026.6.11 still deny `sessions_send` to sub-agents by default and expose no `sessions_send_parent` tool or trusted `parent` selector.

## Solution Assessment

Unclear pending maintainer direction. The maintainable direction is a narrow parent-only operation backed by trusted metadata and security tests, not a broad ordinary `sessions_send` opt-in.
