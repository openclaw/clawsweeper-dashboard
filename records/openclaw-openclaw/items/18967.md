## Summary

Keep open: current main has parent/requester completion handoff for sub-agents, but it still lacks the requested mid-run child-to-direct-parent send primitive; `sessions_send` remains denied to sub-agents by default and there is no `sessions_send_parent` tool or trusted `sessionKey: "parent"` resolver.

## What This Changes

Request a safe sub-agent mechanism to send mid-run updates or questions only to the direct parent session.

## Best Possible Solution

Add a narrow parent-scoped send surface, preferably `sessions_send_parent` or a trusted `sessionKey: "parent"` resolver, with direct-parent, same-tree, no-chaining enforcement plus policy, resolver, docs, and regression tests.

- **Keep announce/yield only:** Do not add a mid-run child-to-parent send path and keep orchestration on completion handoff plus `sessions_yield`.
