## Summary

Keep open: current main and the latest release still do not provide a parent-scoped mid-run send path for sub-agents; completion handoff and ACP parent streaming exist, but they do not satisfy the requested direct child-to-parent session injection API.

## What This Changes

The issue requests a parent-scoped session-send path so spawned sub-agents can send mid-run updates or questions only to their direct parent session.

## Best Possible Solution

Design a narrow parent-scoped send primitive that derives the parent from trusted sub-agent metadata, keeps default sub-agent sessions_send denied, rejects sibling/ancestor/cross-agent targets, avoids automatic forwarding beyond the direct parent, and updates policy, resolver, docs, and regression tests together.

## Reproduction Assessment

Yes at source level: current main still denies sessions_send to sub-agents by default, sessions_send has no parent-only schema, and the resolver has no trusted parent alias. I did not run a live user-path repro because the issue is a missing feature rather than a broken existing command contract.

## Solution Assessment

Unclear pending maintainer design review: a dedicated parent-scoped primitive or trusted parent alias looks safer than a broad config unlock, but the product/security boundary needs explicit maintainer confirmation.
