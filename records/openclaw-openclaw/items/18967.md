- `impact:session-state`: The request changes how active child and parent sessions exchange progress, questions, and state during a sub-agent run.

## Summary

Keep open: current main and v2026.6.11 still lack a trusted parent-scoped mid-run send path for native sub-agents. Completion handoff, ACP-only parent streaming, and broad `sessions_send` opt-ins are adjacent, but they do not implement the requested parent-only, same-tree, no-chaining contract.

## What This Changes

Request a parent-only sub-agent send path so child sessions can send mid-run progress or questions to their direct parent session.

## Best Possible Solution

Define one narrow parent-only send contract derived from trusted active sub-agent metadata, then update tool policy, session resolution, delivery behavior, docs, and security regression tests together.

- **Defer To Completion Handoff:** Keep mid-run child-to-parent sends unsupported and focus orchestration on completion handoff plus `sessions_yield`.
- **Document Broad Opt-In:** Use existing allowlist and visibility configuration for trusted operators while accepting a wider authorization surface.

## Reproduction Assessment

Yes, at source level. Current main still denies `sessions_send` to sub-agents by default, has no `sessions_send_parent` tool, and does not resolve a trusted `parent` target from sub-agent metadata.

## Solution Assessment

Yes in direction, but not as a broad opt-in to ordinary `sessions_send`. The maintainable solution is a dedicated parent-only operation or trusted parent selector backed by active run metadata and security tests.
