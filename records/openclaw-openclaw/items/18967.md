## Summary

Keep open: current main and the latest release still lack a trusted parent-scoped child-to-parent mid-run send path. Existing completion handoff, ACP-only parent streaming, and broad `sessions_send` opt-ins are related, but they do not implement the requested parent-only, same-tree, no-chaining contract.

## What This Changes

Request a native parent-scoped way for sub-agents to send mid-run progress updates or questions directly to their spawning parent session.

## Best Possible Solution

Define a narrow parent-only send contract derived from trusted active sub-agent metadata, then update policy, resolver, delivery, docs, and security regression tests together.

Rationale: The change creates a new child-to-parent session authorization edge and model-facing tool semantic, so automation should not choose the permanent API shape or security boundary without maintainer intent.

Options:

- **Add Dedicated Parent-Only Contract (recommended):** Implement a dedicated tool or trusted parent selector that derives the direct parent from spawn metadata and rejects missing-parent, sibling, ancestor, cross-agent, stale-parent, and automatic-forwarding cases.
- **Defer To Completion Handoff:** Keep mid-run child-to-parent sends unsupported and rely on completion handoff plus `sessions_yield` for native orchestration.
- **Document Broad Opt-In:** Use existing allowlist and visibility configuration for trusted operators while accepting that it is not a parent-only security boundary.

## Reproduction Assessment

Yes, at source level. Current main still denies `sessions_send` to sub-agents by default, has no `sessions_send_parent` tool, and does not resolve a trusted `parent` target from sub-agent metadata.

## Solution Assessment

Yes in direction, but not as a broad opt-in to ordinary `sessions_send`. The maintainable solution is a dedicated parent-only operation or trusted parent selector backed by active run metadata and security tests.
