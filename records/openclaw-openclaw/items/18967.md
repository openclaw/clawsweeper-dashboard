## Summary

Keep open: current main and v2026.6.11 still lack a trusted parent-scoped mid-run send path for native sub-agents, and the remaining work is a security-sensitive model-facing API decision.

## What This Changes

Request a parent-only sub-agent send mechanism for mid-run progress updates and clarifying questions to the direct parent session.

## Best Possible Solution

Define one narrow parent-only send contract derived from canonical active sub-agent metadata, then update policy, resolution, delivery, docs, and security regression tests together.

Options:

- **Add a dedicated parent-only contract (recommended):** Implement a dedicated tool or trusted parent selector that derives the direct parent from active spawn metadata and rejects missing, stale, sibling, ancestor, cross-agent, and auto-forwarded targets.

- **Decline native mid-run sends:** Keep child-originated mid-run sends unsupported and document completion handoff, sessions_yield, or explicit trusted operator opt-ins as the supported paths.

Unclear until maintainer intent is confirmed. The best direction is a narrow parent-only contract; a broad sessions_send allowlist or visibility change is not the best safe implementation.
