## Summary

Keep open: current main and v2026.6.11 still lack a trusted parent-scoped mid-run send path for native sub-agents, and the remaining work is a security-sensitive model-facing API decision rather than conservative cleanup.

## What This Changes

Add a parent-scoped way for spawned sub-agents to send mid-run progress updates or questions only to their direct parent session.

## Best Possible Solution

Define one narrow parent-only send contract derived from canonical active sub-agent metadata, then update tool policy, session resolution, delivery behavior, docs, and security regression tests together.

Options:

- **Add a dedicated parent-only contract (recommended):** Implement a dedicated tool or trusted parent selector that derives the direct parent from active spawn metadata and rejects missing, stale, sibling, ancestor, cross-agent, and auto-forwarded targets.
- **Use existing sessions_send with a reserved parent selector:** Keep one tool but make parent a trusted resolver keyword rather than a literal user-supplied session key, with the same metadata and rejection guarantees.
- **Decline native mid-run sends:** Keep child-originated mid-run sends unsupported and document completion handoff, sessions_yield, or explicit trusted operator opt-ins as the supported paths.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 still deny sessions_send to sub-agents by default and expose no sessions_send_parent tool or trusted parent selector.

## Solution Assessment

Yes in direction, but not as a broad sessions_send opt-in. The maintainable path is a narrow parent-only operation or trusted parent selector backed by active run metadata and security tests.
