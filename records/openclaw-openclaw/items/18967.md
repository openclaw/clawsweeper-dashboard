## Summary

Keep open: current main and v2026.6.11 still lack a trusted child-to-direct-parent mid-run send path. Existing behavior covers completion handoff, ACP-only parent streaming, and broad opt-ins, but not a parent-only, same-tree, no-chaining session API.

## What This Changes

The issue requests a parent-only `sessions_send` path so sub-agents can send mid-run updates or questions to the direct parent session.

## Best Possible Solution

Define one narrow parent-only send contract derived from canonical active sub-agent metadata, then update policy, resolver, delivery, docs, and security regression tests together.

## Reproduction Assessment

Yes, at source level. Current main still denies `sessions_send` to sub-agents by default, has no `sessions_send_parent` tool, and does not resolve a trusted `parent` target from sub-agent metadata.

## Solution Assessment

Yes in direction, but not as a broad opt-in to ordinary `sessions_send`. The maintainable solution is a dedicated parent-only operation or trusted parent selector backed by active run metadata and security tests.
