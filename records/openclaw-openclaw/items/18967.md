## Summary

Keep open: current main and v2026.6.11 still lack a trusted parent-scoped mid-run send path for native sub-agents, and adding it changes a model-facing session authorization boundary that needs maintainer design and security review.

## What This Changes

Request a parent-only mechanism that lets native sub-agents send mid-run updates or questions to their direct parent session.

## Best Possible Solution

Define one narrow parent-only send contract derived from canonical active sub-agent metadata, then update policy, resolver, delivery behavior, docs, and security regression tests together.

Question: Should OpenClaw add a model-facing parent-only sub-agent send contract, and should that be a dedicated `sessions_send_parent` tool or a reserved `sessionKey: "parent"` target on `sessions_send`?

Rationale: The source gap is clear, but the permanent API shape changes child-to-parent session authorization and model-facing tool semantics.

Likely owner: steipete

Owner reason: This handle is most directly connected to recent sub-agent handoff, sessions_send, session resolution, and docs contract history for the requested API.

Owner confidence: high

Options:

- **Add a dedicated parent-only contract (recommended):** Implement a dedicated tool or trusted parent selector that derives the direct parent from active spawn metadata and rejects missing, stale, sibling, ancestor, cross-agent, and auto-forwarded targets.
- **Reserve `sessionKey: "parent"`:** Keep one `sessions_send` tool but make `parent` a special trusted selector rather than a literal user-supplied session key.
- **Decline native mid-run sends:** Keep child-originated mid-run sends unsupported and document completion handoff, `sessions_yield`, or explicit trusted operator opt-ins as the supported paths.

## Reproduction Assessment

Yes, at source level. Current main and the latest release still deny `sessions_send` to sub-agents by default and do not expose a parent-only selector or tool.

## Solution Assessment

Yes in direction, but not as a broad opt-in to ordinary `sessions_send`. The maintainable solution is a dedicated parent-only operation or trusted parent selector backed by active run metadata and security tests.
