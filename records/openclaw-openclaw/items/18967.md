## Summary

Keep open: current main and the latest release still lack a trusted parent-scoped mid-run send path for native sub-agents, and the remaining work is a security-sensitive product/API decision rather than cleanup.

## What This Changes

The issue requests a native parent-scoped session send path so spawned sub-agents can send mid-run updates or questions only to their direct parent session.

## Best Possible Solution

Define one narrow parent-only send contract derived from canonical active sub-agent metadata, then update policy, resolver, delivery, docs, and security regression tests together.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw add a model-facing parent-only sub-agent send contract, and should that contract be a dedicated sessions_send_parent tool or a reserved sessionKey:"parent" selector?

Rationale: The source gap is clear, but this changes child-to-parent session authorization and model-facing tool semantics, so automation should not choose the permanent API shape.

Likely owner: steipete

Owner reason: This handle is most directly connected to recent sessions_send, session resolution, and sub-agent security-boundary history for the requested API.

Owner confidence: high

Options:

- **Add dedicated parent-only contract (recommended):** Implement a dedicated tool or trusted parent selector that derives the direct parent from active spawn metadata and rejects missing, stale, sibling, ancestor, cross-agent, and auto-forwarded targets.
- **Reserve parent selector:** Keep one sessions_send tool but make parent a trusted selector rather than a literal user-supplied key, with the same security checks.
- **Decline native mid-run sends:** Keep child-originated mid-run sends unsupported and document completion handoff, sessions_yield, and explicit operator opt-ins as the supported paths.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 still deny sessions_send to sub-agents by default and do not expose a parent-only selector or tool.

## Solution Assessment

Yes in direction, but not as a broad opt-in to ordinary sessions_send. The maintainable solution is a dedicated parent-only operation or trusted parent selector backed by active run metadata and security tests.
