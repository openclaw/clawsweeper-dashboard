## Summary

Keep open: current main still denies `sessions_send` for sub-agents and has no trusted parent-scoped send tool or `sessionKey: "parent"` resolver, so the remaining work is a security-sensitive model-facing API decision.

## What This Changes

Request a parent-scoped sub-agent send path so child agents can send mid-run updates or questions only to their direct parent session.

## Best Possible Solution

Define one narrow parent-only send contract derived from canonical active sub-agent metadata, then update policy, resolver, delivery, docs, and security regression tests together.
