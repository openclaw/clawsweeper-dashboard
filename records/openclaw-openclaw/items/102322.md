## Summary

Keep open: current main still has the ACP append-slicing path while Gateway explicitly emits non-prefix replacements, and no open PR currently owns this exact fix. The remaining blocker is not source uncertainty; it is choosing an ACP-compatible replacement strategy because standard ACP message chunks are append-oriented.

## What This Changes

The issue reports corrupted or stale ACP assistant/thought text when Gateway revises an in-progress response with a non-append replacement.

## Best Possible Solution

Define an ACP-compatible replacement strategy first, then update the ACP translator and focused tests so divergent and shorter Gateway revisions cannot leave stale assistant or thinking text in ACP clients.
