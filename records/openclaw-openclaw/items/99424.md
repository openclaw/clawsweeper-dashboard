Keep open: current main and the latest release still omit `CONDA_PREFIX` from the host exec sanitizer policy, and https://github.com/openclaw/openclaw/pull/99425 is an open linked fix candidate that has not merged.

## What This Changes

The issue requests stripping `CONDA_PREFIX` from OpenClaw-managed host subprocess environments the same way the sanitizer strips `VIRTUAL_ENV`.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99425, or an equivalent narrow policy update that adds `CONDA_PREFIX`, regenerates the macOS mirror, and keeps inherited plus override regression coverage.

## Reproduction Assessment

Yes for source-level reproduction: current main's policy includes `VIRTUAL_ENV` but not `CONDA_PREFIX`, and the sanitizer derives inherited and override blocking from that policy. I did not run a live Conda-launched OpenClaw agent turn.

## Solution Assessment

Yes. The linked PR's narrow policy-bucket update with macOS mirror regeneration and focused sanitizer tests is the maintainable fix shape; broader Conda or `PATH` filtering would be riskier.
