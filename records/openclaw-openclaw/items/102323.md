## Summary

Keep open: current main still forwards unsupported image MIME strings into Anthropic image blocks, and the existing HEIC normalization paths cover gateway/media-understanding surfaces rather than this direct Anthropic provider path.

## What This Changes

The issue asks OpenClaw to transcode or normalize within-limit HEIC/TIFF image payloads before sending them to Anthropic so the turn does not fail with a 400.

## Best Possible Solution

Add an owner-boundary-safe Anthropic image normalization path that converts unsupported image bytes to an allowed format before both user-message and tool-result image blocks are serialized, with guards/tests proving unsupported MIME strings cannot reach Anthropic by relabeling alone.
