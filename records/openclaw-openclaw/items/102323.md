## Summary

Keep open: current main still forwards unsupported image MIME values into Anthropic image blocks, while the existing HEIC normalization fixes only gateway and media-understanding paths. This is a narrow provider-media bug with a clear repair path.

## What This Changes

Fix Anthropic image handling so within-limit unsupported image MIME inputs such as HEIC/TIFF are transcoded or normalized before Messages API payload construction.

## Best Possible Solution

Add one shared Anthropic inline-image normalization/transcode path before payload construction, reused by the packaged adapter and custom transport for user and tool-result image blocks, with regressions for unsupported and already-supported image types.

Yes, by source inspection and the issue's loopback proof: an `image/heic` block can reach Anthropic payload construction and be emitted as `media_type: "image/heic"`. I did not execute a fresh local or live Anthropic repro in this read-only review.

## Solution Assessment

Yes, the best fix is to normalize/transcode unsupported image bytes before the Anthropic payload boundary and cover both Anthropic mappers. A type cast or media_type relabel would be the wrong layer because it would not change the encoded image bytes.
