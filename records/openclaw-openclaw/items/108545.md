## Summary

The UTF-8 boundary approach and live HTTP proof are strong, but the patch still treats any short `FileHandle.read()` as EOF, so a legitimate partial read can reintroduce the replacement character the PR is intended to remove.

## What This Changes

The PR changes QA Lab text and JSON preview reads to omit incomplete trailing UTF-8 sequences at the 12 KiB cap and adds a real-server boundary regression test.

## Best Possible Solution

Fill the cap-plus-sentinel buffer through repeated positional reads until it is full or a zero-byte read proves EOF, then decode the first 12 KiB and add a regression that simulates a non-EOF short read ending inside a multibyte character.
