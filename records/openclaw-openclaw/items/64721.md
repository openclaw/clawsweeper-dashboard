## Summary

Keep open. Current main and the latest release already cover the `model` and `timeoutSeconds` pieces, but `contextTokens` and `maxSpendUsd` still are not cron tool, gateway protocol, payload type, CLI, or runtime enforcement contracts; the open related PR is only a partial candidate, not a complete replacement.

## What This Changes

Request that cron add/update tooling accept and pass through per-job `model`, `timeoutSeconds`, `contextTokens`, and `maxSpendUsd` fields.

## Best Possible Solution

Define a cron-owned per-job context and spend-budget contract, then align the agent tool schema, gateway protocol, cron store/runtime, CLI, and docs while preserving the settled `model` and `timeoutSeconds` behavior.
