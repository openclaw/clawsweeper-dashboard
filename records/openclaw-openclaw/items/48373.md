## Summary

Keep open: current main and v2026.6.11 still route `feishu_doc` create through `createDoc` without writing or rejecting supplied `content`; same-repo fix attempts are closed unmerged, and the remaining open candidate is only a fork PR.

## What This Changes

The issue asks for `feishu_doc` create to stop silently discarding supplied `content`, preferably by creating and populating the document in one call.

## Best Possible Solution

Adopt one Feishu plugin contract: either write supplied create content through the existing write path with explicit partial-failure handling and live proof, or reject `content` on create with a clear error plus matching tests/docs.

Rationale: Both fixes are mechanically bounded, but the choice defines the Feishu tool contract and the behavior when document creation succeeds but the follow-up write fails.

Options:

- **Support create-time content (recommended):** Create the document, write supplied markdown through the existing write path, and preserve created metadata or roll back if the write step fails.
- **Reject content on create:** Keep `create` title-only but fail clearly when callers supply `content`, with docs and tests that point users to create then write.
- **Review or replace the fork PR:** Keep this issue open while the open fork candidate is reviewed, repaired, merged into the target repository, or explicitly replaced.

Yes. Source inspection gives a high-confidence path: a call with `action: "create"`, `title`, and `content` reaches the create branch and returns after `createDoc` without writing or rejecting the content.

## Solution Assessment

Unclear until maintainers choose the contract. Create-plus-write is the better UX but needs partial-failure handling; explicit rejection is safer but keeps the two-step workflow.
