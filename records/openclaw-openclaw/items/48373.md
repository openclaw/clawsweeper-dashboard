## Summary

Keep open: current main and the latest release still route `feishu_doc` create directly to document creation without writing or rejecting supplied content, and an open linked implementation candidate means the issue should wait for maintainer contract review rather than be closed.

## What This Changes

The issue asks for `feishu_doc` create to stop silently dropping a supplied `content` body, preferably by creating and populating the document in one call.

## Best Possible Solution

Choose and land either create-plus-write with explicit partial-failure metadata or rollback plus live Feishu proof, or reject `content` before document creation with a clear error.

Rationale: Both outcomes would fix the silent-drop bug, but they define different user-facing tool contracts and partial-failure behavior for a bundled Feishu plugin.

- **Support create-time content (recommended):** Adopt a create-plus-write fix, preserve created document metadata or roll back on write failure, and require redacted live Feishu proof before landing.

- **Defer to plugin owner:** Pause the issue until the Feishu plugin owner confirms the preferred contract and proof requirements.

Yes. Source inspection gives a high-confidence path: a create call can carry `content` through model-facing schema normalization, but the Feishu create branch neither writes nor rejects it.

## Solution Assessment

Unclear until maintainers choose the contract. Create-plus-write is likely the best UX, while pre-create rejection is the safer contract if create should remain title-only.
