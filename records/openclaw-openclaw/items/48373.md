## Summary

Keep open: current main and the latest release still route Feishu document creation through `createDoc` without writing or rejecting a supplied `content` value, while the same-repository implementation attempts remain closed unmerged and an open cross-repo candidate has not landed in this repository.

## What This Changes

The issue asks for `feishu_doc` create to stop silently ignoring supplied document body content, either by writing it during creation or rejecting it clearly.

## Best Possible Solution

Adopt one explicit Feishu plugin contract: either support create-time markdown through the existing write path with recoverable partial-failure output, or reject `content` on create with a clear error and aligned docs/schema behavior.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should `feishu_doc` create support initial `content` via an internal create-then-write sequence, or should create reject `content` and require the documented two-call workflow?

Rationale: Source inspection proves the silent-drop path, but the permanent tool contract and write-failure recovery behavior are user-visible Feishu product decisions rather than a purely mechanical cleanup.

Likely owner: Takhoffman

Owner reason: They have adjacent create-branch history and were already pulled into the prior create-with-content discussion.

Owner confidence: medium

Options:

- **Support create-time content (recommended):** Create the document, write supplied markdown through the existing write path, and preserve created metadata or roll back if the write step fails.
- **Reject content on create:** Keep create title-only but fail clearly when callers provide `content`, with tests and docs pointing to create then write.
- **Use a separate action:** Add a distinct create-with-content action only if maintainers want to keep create metadata-only while giving models a one-call path.

## Reproduction Assessment

Yes. Source inspection shows a direct or flattened-provider call with `action: "create"`, `title`, and `content` reaches the create branch, which returns after `createDoc` without writing or rejecting `content`; I did not run a live Feishu API call in this read-only review.

## Solution Assessment

Unclear. The current silent-ignore behavior is not acceptable, but maintainers need to choose whether the best fix is create-plus-write with explicit partial-failure handling or a clear unsupported-parameter rejection.
