## Summary

Keep open: current `main` and the latest release still route Feishu doc creation through the title-only `createDoc` path without consuming or rejecting supplied `content`, and the same-repository fix PR is closed unmerged. The remaining decision is whether maintainers want `create` to support initial content or to fail before creating an empty document.

## What This Changes

The issue requests that `feishu_doc` stop silently ignoring `content` during `action: "create"`, either by writing the initial markdown or rejecting the parameter before creation.

## Best Possible Solution

Land or sponsor a refreshed Feishu plugin fix that eliminates the silent drop by either writing create-time markdown through the existing write path with explicit partial-failure behavior, or rejecting `content` before document creation.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: model-facing union flattening can allow a broad `content` field to reach tool execution, and the Feishu `create` branch neither consumes nor rejects `p.content`.

## Solution Assessment

Unclear until maintainers choose the public contract. Create-plus-write through `writeDoc` is a narrow implementation path, but rejecting unsupported `content` before creation is also a valid safer fix if `create` should remain title-only.
