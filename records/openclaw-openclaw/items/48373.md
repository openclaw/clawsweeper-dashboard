## Summary

Keep open: current main still has a source-reproducible silent-drop path because the Feishu tool schema is normalized into a permissive model-facing object that can accept `content`, while the `create` branch still calls only `createDoc` and never writes or rejects that value. The linked same-repo implementation PR is closed unmerged, and the remaining live implementation candidate is an open fork PR rather than a merged target-repo fix.

## What This Changes

The issue reports that `feishu_doc` accepts `content` on `create` but creates an empty document instead of writing or rejecting the supplied content.

## Best Possible Solution

The Feishu plugin should make `create` with `content` non-silent, either by rejecting `content` before document creation with a clear error or by implementing create-then-write with explicit recovery details if the write fails.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should `feishu_doc` support initial `content` on `create`, or should `create` reject `content` before creating a document?

Rationale: Both fixes remove the silent data loss, but they define different public tool contracts and different partial-failure behavior after a document has already been created.

Likely owner: m1heng

Owner reason: The Feishu plugin README identifies this handle as the community owner for the Feishu/Lark plugin, making them the best available routing target for the tool contract choice.

Owner confidence: medium

Options:

- **Reject content on create (recommended):** Return a clear validation/tool error before document creation when `action: "create"` includes `content`, and keep `write` as the documented content path.
- **Create then write:** Support the reporter's one-call workflow by creating the document and then calling `writeDoc`, with a response or error shape that preserves the created document id if writing fails.
- **Use a separate create-with-content action:** Add an explicit action for initial content so the current `create` behavior stays narrow while models get a discoverable one-call workflow.

## Reproduction Assessment

Yes from source: the model-facing schema path can validate a `content` key while the `create` branch still calls only `createDoc` and returns success without using that value. I did not run live Feishu proof in this read-only sweep.

## Solution Assessment

Unclear: both reject-on-create and create-then-write remove the silent drop, but the Feishu tool contract and partial-write failure semantics need maintainer choice before an automated fix.
