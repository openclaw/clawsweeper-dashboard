## Summary

Keep open: current `main` and the latest release still route `feishu_doc` create directly to `createDoc` without writing or rejecting supplied `content`, and the remaining open fix candidate is unmerged outside the target repository.

## What This Changes

The issue asks OpenClaw to stop silently dropping `content` passed to `feishu_doc` with `action: "create"`, either by writing the initial content or rejecting it clearly.

## Best Possible Solution

Land or sponsor a refreshed Feishu plugin fix that either writes create-time markdown through the existing write path with explicit partial-failure behavior, or rejects `content` before document creation with a clear error.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: model-facing schema normalization can expose `content`, validated args are passed into tool execution, and the Feishu `create` branch never consumes or rejects `p.content`.

## Solution Assessment

Unclear until maintainers choose the contract. Create-plus-write through `writeDoc` is narrow, but rejecting unsupported `content` before creation is also a safer valid fix if create should remain title-only.
