## Summary

Keep open: current `main` and the latest release still create Feishu documents through `createDoc` without writing or rejecting a supplied `content` value, while the same-repository implementation attempts are closed unmerged and the newer fork candidate has not landed in this repository.

## What This Changes

The issue reports that Feishu `feishu_doc` accepts `content` with `action: "create"` and returns a created document while leaving the requested body empty.

## Best Possible Solution

Adopt one explicit Feishu plugin contract: either support create-time markdown through the existing write path with recoverable partial-failure output, or reject `content` on create with a clear error and aligned schema/docs behavior.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should `feishu_doc` create support initial `content` via an internal create-then-write sequence, or should create reject `content` and require the two-call workflow?

Rationale: Source inspection proves the silent-drop path, but the permanent tool contract and write-failure recovery behavior are user-visible Feishu product decisions rather than a purely mechanical cleanup.

Likely owner: Takhoffman

Owner reason: They have adjacent create-branch history and were already pulled into the earlier create-with-content discussion.

Owner confidence: high

Options:

- **Support create-time content (recommended):** Create the document, write supplied markdown through the existing write path, and preserve created metadata or roll back if the write step fails.
- **Reject content on create:** Keep create title-only but fail clearly when callers provide `content`, with tests and docs pointing to create then write.
- **Use a separate action:** Add a distinct create-with-content action only if maintainers want to keep create metadata-only while giving models a one-call path.

## Reproduction Assessment

Yes. Source inspection shows a call with `action: "create"`, `title`, and `content` reaches the create branch, which returns after `createDoc` without writing or rejecting `content`; I did not run a live Feishu API call in this read-only review.

## Solution Assessment

Unclear. The current silent-ignore behavior is not acceptable, but maintainers need to choose whether the best fix is create-plus-write with explicit partial-failure handling or a clear unsupported-parameter rejection.
