## Summary

Keep this PR open for author changes: the reported Telegram retryable-failure class is real from source, but the patch is too broad because current live paths also record `failed-retryable` after sending a visible apology that was intentionally acked without replay. The PR also needs after-fix live or restart-replay proof before merge.

## What This Changes

The PR changes Telegram bot core so live `failed-retryable` processing results leave the update incomplete, and updates the normal polling regression to expect no watermark advancement until retry succeeds.

## Best Possible Solution

Narrow the ack change to failures that truly produced no visible fallback or final response, preserve completion for live apology-sent paths, and add live or restart-replay proof plus regression coverage for both branches.
