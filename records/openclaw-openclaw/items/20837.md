## Summary

Keep open: current main still has a source-confirmed gap where `/context` and `/export-session` rebuild the command system prompt without the channel, capabilities, shell, or channel-action metadata that normal agent runs already receive. The linked fix PR is closed unmerged, and the selective reply-routing part remains a separate product decision.

## What This Changes

The issue requests that agents receive incoming communication-channel context and optionally support channel-aware reply routing.

## Best Possible Solution

Implement prompt metadata parity in `resolveCommandsSystemPromptBundle()` using the embedded-runner pattern, and keep channel-selective delivery under existing message-tool policy or a separate maintainer-approved API follow-up.
