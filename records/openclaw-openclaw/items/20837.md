## Summary

Keep open: current main and v2026.6.11 still omit channel, capability, shell, channel-action, and message-tool metadata from slash-command prompt reconstruction, while inbound metadata and the normal embedded-runner prompt path already carry that context; the related repair PR is closed unmerged.

## What This Changes

Requests that agents receive inbound communication-channel context and eventually support controlled channel-specific replies.

## Best Possible Solution

Split the work: repair command prompt reconstruction to include the same runtime channel metadata as the embedded runner, and leave selective reply routing for a separate maintainer-designed channel/API follow-up.

## Reproduction Assessment

Yes, at source level: `/context` and `/export-session` rebuild prompts through `resolveCommandsSystemPromptBundle()`, whose runtime payload still lacks channel-related fields on current main and v2026.6.11. I did not run tests because this review was read-only.

## Solution Assessment

Yes for the first part: mirroring or extracting the embedded-runner runtime metadata assembly is the narrow maintainable repair. Selective reply routing should be handled separately because docs define reply routing as deterministic host behavior, not model-chosen delivery.
