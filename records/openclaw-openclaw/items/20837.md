## Summary

Keep open. Current main still exposes channel metadata in normal inbound and runner paths, but slash-command prompt reconstruction omits runtime channel/capabilities/shell metadata, and https://github.com/openclaw/openclaw/pull/21271 is closed unmerged while selective delivery remains a product/API decision.

## What This Changes

Request to expose the incoming communication channel to the agent and optionally support channel-selective replies.

## Best Possible Solution

Implement metadata parity in resolveCommandsSystemPromptBundle() using the embedded-runner runtime prompt pattern, and split prompt-driven channel-selective delivery into a maintainer-approved API/policy follow-up.
