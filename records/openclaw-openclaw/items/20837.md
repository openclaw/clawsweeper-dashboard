## Summary

Keep open. Current main still exposes channel metadata in the normal agent-run prompt path, but the slash-command prompt reconstruction used by `/context` and `/export-session` still omits channel, shell, capabilities, and channel-action metadata; the linked candidate PR is closed unmerged.

## What This Changes

Requests that agents receive source communication-channel context and, optionally, selectively route replies by channel.

## Best Possible Solution

Implement prompt metadata parity in `resolveCommandsSystemPromptBundle()` only, using the embedded-runner pattern with account-aware channel capabilities/actions, and split selective reply routing into a separate maintainer-approved delivery-policy/API decision.
