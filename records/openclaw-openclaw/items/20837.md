## Summary

Keep open: current main and v2026.6.11 still omit channel/capability/shell/action metadata from slash-command prompt reconstruction, while the normal inbound and embedded-runner paths already carry that metadata. The linked repair PR is closed unmerged, and the selective reply-routing part overlaps an open product/security routing discussion.

## What This Changes

Request agent prompts to expose the source communication channel and eventually support channel-selective replies.

## Best Possible Solution

Split the work: add account-aware runtime channel/capability/shell/action metadata to resolveCommandsSystemPromptBundle(), then track selective reply routing separately as a maintainer-approved routing policy.

## Reproduction Assessment

Yes, at source level: buildCommandContext has channel metadata, but resolveCommandsSystemPromptBundle() rebuilds /context and /export-session prompts without passing channel-related runtime fields. No live Telegram/dashboard turn was run in this read-only review.

## Solution Assessment

Yes for the first part: reusing or extracting the embedded-runner runtime metadata assembly is the narrow maintainable repair. The selective reply-routing portion should not be implemented until maintainers choose the product/API boundary.
