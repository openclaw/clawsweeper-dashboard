## Summary

Keep open. Current main still exposes channel metadata in the normal inbound and agent-run path, but `/context` and `/export-session` prompt reconstruction still build runtime info with unknown host fields and no channel/capabilities/shell/action metadata; the linked candidate fix is closed unmerged.

## What This Changes

Request to expose the inbound communication channel to the agent and optionally support selective channel replies.

## Best Possible Solution

Implement prompt metadata parity in `resolveCommandsSystemPromptBundle()` and leave selective delivery routing to existing host-controlled message-tool policy, channel docking, or a separate maintainer-approved API direction.
