## Summary

Keep open. Current main still exposes channel metadata in the normal inbound/agent-run path, but `resolveCommandsSystemPromptBundle()` still omits runtime channel/capabilities/shell/channelActions for `/context` and `/export-session`; the linked candidate PR is closed unmerged, so no canonical fix has landed.

## What This Changes

The issue requests exposing inbound communication-channel metadata to the agent context and optionally enabling channel-selective replies.

## Best Possible Solution

Implement prompt metadata parity only in `resolveCommandsSystemPromptBundle()` using the embedded-runner pattern and account-aware channel capabilities, while leaving selective delivery policy to existing message-tool behavior or a separate product/API decision.

## Reproduction Assessment

Yes. Source inspection shows command prompt reconstruction still drops runtime channel metadata even though `buildCommandContext()` has it and the normal embedded runner passes it to the system prompt.

## Solution Assessment

Partly. The narrow command prompt metadata parity fix is the best implementation path for the confirmed gap, but selective reply routing should be handled through existing visible-reply/message-tool policy or a separate maintainer-approved API direction.
