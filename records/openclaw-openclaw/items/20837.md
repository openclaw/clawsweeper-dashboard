## Summary

Keep open: current main still carries channel metadata in the normal inbound and embedded-runner paths, but slash-command prompt reconstruction for `/context` and `/export-session` still drops channel/capability/shell/action metadata; the linked repair PR usefully diagnosed this but closed unmerged.

## What This Changes

Request to expose the inbound communication channel to the agent context and optionally support channel-selective replies.

## Best Possible Solution

Split the work: add account-aware runtime channel/capability/shell/action metadata to `resolveCommandsSystemPromptBundle()`, then track selective reply routing separately as a channel/API product decision.

## Reproduction Assessment

Yes, at source level: `/context` and `/export-session` rebuild through `resolveCommandsSystemPromptBundle()`, whose runtime payload still lacks channel-related fields on current main and v2026.6.11. I did not run live commands because this review is read-only.

## Solution Assessment

Yes for the first part: mirroring or extracting the embedded-runner metadata assembly is the narrow maintainable repair. The selective reply-routing portion should not be bundled until maintainers confirm the API and product direction.
