## Summary

Keep open. Current main exposes channel metadata in the normal inbound and agent-run paths, but slash-command prompt reconstruction still omits channel, capabilities, shell, and channel-action runtime metadata; the linked candidate PR is closed unmerged, and the broader selective-reply part still needs product scoping.

## What This Changes

The issue requests communication-channel awareness in agent context and optional channel-selective visible replies.

## Best Possible Solution

Implement prompt metadata parity only in `resolveCommandsSystemPromptBundle()`, using the embedded-runner pattern with account-aware capabilities and channel action/message guidance, while leaving selective delivery policy to existing message-tool configuration or a separate API design.
