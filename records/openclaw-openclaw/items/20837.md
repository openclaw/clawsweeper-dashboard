## Summary

Keep open: current main and v2026.6.11 still drop runtime channel/capability/shell/action metadata from slash-command prompt reconstruction, while the normal inbound and embedded-runner paths already carry that metadata; the linked repair PR is closed unmerged and selective reply routing still needs product direction.

## What This Changes

The issue requests making the agent aware of the incoming communication channel and optionally enabling channel-specific reply behavior.

## Best Possible Solution

Split the scope: add account-aware runtime channel/capability/shell/action metadata to resolveCommandsSystemPromptBundle(), and track selective reply routing separately as a channel/API product decision.
