## Summary

Keep open. Current main and v2026.6.11 still expose channel metadata in the normal inbound/runtime prompt path but omit shell/channel/capabilities/channelActions from slash-command prompt reconstruction, and the linked candidate fix is closed unmerged.

## What This Changes

The issue requests channel-origin awareness in agent context and a possible future ability to constrain replies to selected communication channels.

## Best Possible Solution

Implement prompt metadata parity only in resolveCommandsSystemPromptBundle(), using the embedded-runner pattern and account-aware channel capabilities, while leaving selective delivery policy to existing message-tool/config surfaces or a separate product/API discussion.

## Reproduction Assessment

Yes, at source level. Current main shows command prompt reconstruction still drops runtime channel metadata even though buildCommandContext() has it and the normal embedded runner passes it to the system prompt.

## Solution Assessment

Partly. The narrow command prompt metadata parity fix is the best implementation path for the confirmed gap, but selective reply routing should be handled through existing visible-reply/message-tool policy or a separate maintainer-approved API direction.
