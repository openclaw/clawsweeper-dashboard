## Summary

Keep open. Current main and the latest release still omit runtime channel metadata from slash-command prompt reconstruction, while the normal embedded runner already supplies channel, capabilities, shell, and channel actions; the linked candidate fix is closed unmerged.

## What This Changes

Make the agent aware of the inbound communication channel and optionally able to choose or restrict the reply channel.

## Best Possible Solution

Implement prompt metadata parity only in `resolveCommandsSystemPromptBundle()` using the embedded-runner pattern and account-aware channel capabilities; leave selective delivery policy to existing routing/message-tool behavior or a separate maintainer-approved API.

## Reproduction Assessment

Yes, source-level. Current main shows command prompt reconstruction still drops runtime channel metadata even though `buildCommandContext()` has it and the normal embedded runner passes it to the system prompt.

## Solution Assessment

Partly. The narrow command prompt metadata parity fix is the best implementation path for the confirmed gap, but selective reply routing should be handled through existing message-tool policy or a separate maintainer-approved API direction.
