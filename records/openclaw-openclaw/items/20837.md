Keep open: current main still has the source-confirmed command prompt metadata gap, and the broader prompt-driven selective reply behavior still needs maintainer product direction.

## What This Changes

The issue asks for agents to know which communication channel produced an incoming message and optionally control which channel receives replies.

## Best Possible Solution

Implement command prompt runtime metadata parity only, with account-aware capability/action resolution, and track prompt-driven channel-selective routing separately behind maintainer-approved delivery/API policy.
