## Summary

Keep open: current main still has the slash-command reconstruction gap. Normal inbound and embedded-runner paths carry channel metadata, but `resolveCommandsSystemPromptBundle()` still rebuilds `/context` and `/export-session` prompts with unknown host fields and no channel, capabilities, shell, or channel-action metadata; the linked fix PR is closed unmerged.

## What This Changes

The issue requests that agents receive communication-channel context and, optionally, gain a way to route replies selectively by channel.

## Best Possible Solution

Add account-aware runtime metadata to `resolveCommandsSystemPromptBundle()` for `/context` and `/export-session`, matching the embedded-runner prompt pattern, and leave selective cross-channel reply routing to a separate product/API discussion.

## Reproduction Assessment

Yes. Source inspection shows the normal inbound and embedded-runner paths have channel metadata, while the slash-command prompt bundle still omits it and is used by `/context` and `/export-session`.

## Solution Assessment

Yes for the narrowed metadata portion: the best fix is to reuse the embedded-runner runtime prompt metadata pattern in `resolveCommandsSystemPromptBundle()` only. The selective reply-routing request should stay separate because it changes channel behavior and product/API semantics.
