## Summary

Keep open: current main still has the channel-aware normal agent run path, but `/context` and `/export-session` prompt reconstruction continue to omit channel, shell, capabilities, and channel-action metadata, while the linked fix PR is closed unmerged.

## What This Changes

The issue requests that agents know which communication channel a message came from and eventually support channel-selective replies.

## Best Possible Solution

Add account-aware channel/runtime metadata parity to `resolveCommandsSystemPromptBundle()`, and keep selective cross-channel reply routing as a separate product/API decision.

## Reproduction Assessment

Yes, at source level: current main still reconstructs command/export system prompts without channel runtime metadata, while normal agent runs pass those fields. I did not run a live Telegram/dashboard repro in this read-only review.

## Solution Assessment

No, current main is not yet the full solution. The narrow maintainable fix is command-bundle metadata parity; selective reply routing should be handled separately instead of coupled to prompt reconstruction.
