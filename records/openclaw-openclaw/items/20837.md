## Summary

Keep open. Current main still exposes channel metadata in the normal inbound/runtime path but not in slash-command prompt reconstruction, and the linked candidate PR is closed unmerged while prompt-driven selective reply routing still needs maintainer scoping.

## What This Changes

Requested that agents know the source communication channel and optionally restrict which channel receives replies.

## Best Possible Solution

Implement prompt metadata parity only in `resolveCommandsSystemPromptBundle()`, using the embedded-runner pattern with account-aware capabilities and channel action/message guidance, while leaving model-selected delivery policy to existing routing or a separate approved API.
