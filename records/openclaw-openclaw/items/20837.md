## Summary

Keep open: current main exposes channel metadata in the normal inbound and agent-run path, but slash-command prompt reconstruction still drops runtime channel, capabilities, shell, and channel action metadata; the related fix PR is closed unmerged.

## What This Changes

The issue requests giving the agent inbound communication-channel context and optionally allowing channel-selective replies.

## Best Possible Solution

Add normalized, account-aware runtime metadata to `resolveCommandsSystemPromptBundle()` for `/context` and `/export-session`, while keeping selective reply routing as a separate host/API product decision.

## Reproduction Assessment

Yes at source level: current main still has `resolveCommandsSystemPromptBundle()` omit channel runtime metadata even though command context and the normal runner have it. I did not run a live Telegram/WebChat scenario in this read-only review.

## Solution Assessment

The best path is narrower than the full request: fix command prompt reconstruction to match the normal runner, but do not make prompt text select delivery channels without a separate routing/API decision.
