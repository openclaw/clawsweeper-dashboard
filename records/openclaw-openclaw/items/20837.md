## Summary

Keep open. Current main already carries channel metadata through the normal inbound/runner path, but slash-command prompt reconstruction still omits runtime channel/capability metadata, and the selective reply-routing request still needs product scoping.

## What This Changes

The issue asks for agents to know which communication channel produced an inbound message and optionally choose replies by channel.

## Best Possible Solution

Implement prompt metadata parity only in `resolveCommandsSystemPromptBundle()`, using the embedded-runner pattern with account-aware capabilities and channel action/message guidance, while leaving selective delivery policy to a separate maintainer-approved API follow-up.
