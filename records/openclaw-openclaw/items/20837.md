## Summary

Keep open: current main and latest release still omit channel/runtime metadata from slash-command prompt reconstruction, while normal inbound and embedded-runner paths already carry it. The closed related PR was not merged, and the remaining selective-reply-routing request should stay a separate maintainer/product decision.

## What This Changes

The issue requests exposing the inbound communication channel to the agent and optionally supporting channel-selective replies.

## Best Possible Solution

Narrow the implementation to `resolveCommandsSystemPromptBundle()` mirroring the embedded-runner runtime metadata path, then track selective channel reply routing separately if maintainers want that product behavior.

## Reproduction Assessment

Yes, at source level: `/context` and `/export-session` rebuild prompts through `resolveCommandsSystemPromptBundle()`, which still omits runtime channel metadata even though command context and normal inbound metadata carry it. I did not run a live channel scenario in this read-only review.

## Solution Assessment

No for the broad request as filed: the best fix is the narrow command-prompt metadata repair, not model-directed channel routing. Selective reply routing should be a separate product/API discussion unless maintainers explicitly fold it into this issue.
