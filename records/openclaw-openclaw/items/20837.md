## Summary

Keep open: current main and the latest release still omit runtime channel/capability/shell/action metadata from slash-command prompt reconstruction, while normal inbound and embedded-runner paths already carry that metadata; the linked repair PR is closed unmerged.

## What This Changes

The issue requests agent-visible incoming channel context and, optionally, prompt/rule-based control over which communication channel receives replies.

## Best Possible Solution

Split the work: add account-aware runtime channel/capability/shell/action metadata to resolveCommandsSystemPromptBundle(), then track selective reply routing separately as a channel/API product decision.

## Reproduction Assessment

Yes, at source level: /context and /export-session rebuild through resolveCommandsSystemPromptBundle(), whose runtime payload still lacks channel-related fields on current main and v2026.6.11. I did not run live commands because this review is read-only.

## Solution Assessment
