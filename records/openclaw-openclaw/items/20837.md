## Summary

Keep this issue open: current main and the latest release already expose channel metadata in the normal inbound/agent-run path, but `/context` and `/export-session` prompt reconstruction still omit the runtime channel metadata. The linked fix PR was closed unmerged, so no merged/current implementation owns the remaining narrow gap.

## What This Changes

Request to expose inbound communication channel context to the agent and eventually allow channel-selective replies.

## Best Possible Solution

Add the missing runtime metadata only to `resolveCommandsSystemPromptBundle()` so `/context` and `/export-session` reconstruct the same channel-aware prompt facts as normal agent runs; handle selective reply routing separately.

## Reproduction Assessment

Yes. Source inspection shows the command bundle has channel/account metadata available through `params.command`, but the reconstructed system prompt runtime fields still omit channel/capabilities/shell while normal agent runs include them.

## Solution Assessment

Yes for the narrow metadata half: reusing or extracting the embedded-runner runtime prompt pattern in `resolveCommandsSystemPromptBundle()` is the maintainable fix. The channel-selective reply half should not be solved in the same change without a separate product/API decision.
