## Summary

Keep open. Current main still exposes channel metadata in the normal inbound and agent-run paths, but `resolveCommandsSystemPromptBundle()` still reconstructs `/context` and `/export-session` prompts with `unknown` host fields and without runtime channel, capabilities, shell, or channel actions; the linked candidate fix is closed unmerged.

## What This Changes

The issue requests adding source communication-channel context to agent messages and optionally allowing channel-selective replies.

## Best Possible Solution

Implement prompt metadata parity only in `resolveCommandsSystemPromptBundle()`, using the embedded-runner runtime pattern and account-aware channel capabilities, while keeping selective delivery policy in existing visible-reply/message-tool config or a separate maintainer-approved API.

## Reproduction Assessment

Yes, source-level. Current main shows the command prompt reconstruction path still drops runtime channel metadata even though `buildCommandContext()` has the channel and the normal embedded runner passes channel metadata to the system prompt.

## Solution Assessment

Partly. The narrow command prompt metadata parity fix is the best implementation path for the confirmed gap, but channel-selective reply policy should use the existing visible-reply/message-tool configuration or a separate maintainer-approved API direction.
