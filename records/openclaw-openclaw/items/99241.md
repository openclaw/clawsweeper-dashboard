## Summary

This issue should stay open: current main has some shared tool-result text extraction, but the canonical closing PR is still open and adds the missing provider/transport guard that prevents stale media placeholders from winning when a tool result carries a text block.

## What This Changes

The issue reports that text tool outputs can be projected to the agent as image or attachment placeholders, hiding stdout/stderr and breaking verification loops.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/99756 or an equivalent provider/transport fix that guarantees text tool-result blocks stay model-visible and media placeholders are reserved for media-only results.

Yes. The issue has multiple concrete live reports, and current main still has a source-visible path where provider conversions can use media placeholders unless the open PR's has-text-block guard is applied.
