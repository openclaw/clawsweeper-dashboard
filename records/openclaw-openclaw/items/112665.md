## What This Changes

Add a supported gateway or CLI operation that atomically renames an established agent ID while preserving correctly associated agent state and paths.

## System Context

Agent configuration selects an agent ID and its owned workspace and state directories. The agent database validates that its persisted owner matches the requested ID before runtime uses it, so a rename must coordinate configuration, paths, database metadata, and participating plugin state rather than relax that check.

## Best Possible Solution

Define a single core-owned, journaled rename contract that preserves explicit workspace paths by default, moves only OpenClaw-owned default paths when approved, and exposes a typed plugin migration/verification seam before implementing CLI or gateway entry points.
