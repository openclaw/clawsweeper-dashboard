## Summary

Keep open. This is a substantive core feature request for a coordinated agent-identity migration, not a defect in the existing ownership guard: the report correctly identifies rejection of a database owned by another agent as the intended safety boundary. The remaining workspace-path policy, gateway quiescing, journal recovery, and plugin-owned-state contract require maintainer direction before implementation.

## What This Changes

Add a supported CLI or Gateway operation that safely renames an established agent ID and migrates its owned state without accepting old-ID runtime fallbacks.

## System Context

Agent IDs connect the configured agent list to its workspace, agent-scoped SQLite database, and plugin-owned state. A rename operation would need to coordinate configuration and storage changes before the Gateway resumes work under the new ID.

## Architecture Diagram

## Best Possible Solution

Define one core-owned, journaled rename transaction that keeps runtime on canonical IDs only, preserves explicit workspace paths by default, moves only clearly OpenClaw-owned default paths, and exposes a typed plugin migration contract with verification and interrupted-transaction recovery through `openclaw doctor --fix`.
