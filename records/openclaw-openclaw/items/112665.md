## Summary

Keep open. This is a substantive feature request for a coordinated agent-identity migration, not a regression in the existing runtime guard: the report explicitly recognizes that rejecting a database owned by a different agent ID is the intended safety boundary. Current evidence supports the operator need, but the workspace-path and plugin-state contracts require maintainer product and ownership decisions before implementation.

## What This Changes

Add a supported CLI or gateway operation that safely renames an established agent ID while migrating its configured identity, owned paths, and agent-scoped persistent state.

## System Context

Agent configuration selects an agent ID and its workspace, while each agent’s SQLite database is bound to that ID to prevent state from being used by the wrong agent. A rename operation would need to coordinate config, owned directories, database ownership metadata, and participating plugin state before the renamed agent can resume.

## Best Possible Solution

Design one journaled, quiescing rename operation with a canonical migration owner; preserve explicit workspace paths by default, move only clearly OpenClaw-owned default paths, and add an opt-in typed plugin migration contract before exposing the command.
