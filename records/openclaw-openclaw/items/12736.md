## Summary

Keep open: current main and the latest release still lack a cron-scoped tool deny policy or explicit inheritance from `tools.subagents.tools`; existing per-job `toolsAllow` and delivery guards are useful mitigations but do not satisfy the requested hard cron policy.

## What This Changes

The issue requests a system-wide cron job tool restriction such as `tools.cron.tools.deny` or explicit cron inheritance from `tools.subagents.tools`.

## Best Possible Solution

Approve a cron tool-policy design that defines cron allow/deny or explicit inheritance, precedence, schema/type/docs updates, and regression coverage for announce and direct-delivery behavior.

## Maintainer Decision

Kind: security_boundary

Question: Should isolated cron jobs get a first-class `tools.cron.tools.allow/deny` policy, inherit `tools.subagents.tools`, or continue with only per-job `payload.toolsAllow` plus delivery safeguards?

Rationale: The choice defines the scheduled-run tool-access boundary and public config contract, including how hard denies interact with existing cron jobs that may intentionally use direct `message` delivery.

Likely owner: steipete

Owner reason: steipete has the strongest combined signal from prior review context plus recent cron runner and scoped tool-policy foundation work.

Owner confidence: high

Options:

- **Add Cron-Scoped Policy (recommended):** Introduce `tools.cron.tools.allow/deny` with explicit precedence and tests for message-tool denial across cron delivery modes.
- **Inherit Subagent Policy:** Apply `tools.subagents.tools` to cron sessions too, reducing config surface while coupling two different execution modes.
- **Keep Per-Job Only:** Avoid a new global cron policy and rely on `payload.toolsAllow`, documentation, and delivery-mode safeguards for scheduled runs.

## Reproduction Assessment

Yes, at source level. Current schema/types still lack `tools.cron.tools`, and current policy resolution only applies `tools.subagents.tools` to subagent envelopes while cron relies on per-job `toolsAllow` plus delivery safeguards.

## Solution Assessment

Unclear until maintainers choose the security and product direction. A cron-scoped policy looks cleaner than overloading subagent semantics, but the best fix must define precedence and upgrade behavior first.
