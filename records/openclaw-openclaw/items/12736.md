## Summary

Keep open: current main still has per-job cron `toolsAllow` and delivery mitigations, but it does not provide the requested cron-scoped allow/deny config or explicit inheritance from `tools.subagents.tools`, so this remains a security-sensitive product/config decision.

## What This Changes

Request to add `tools.cron.tools.deny` or equivalent inheritance so isolated cron jobs can be hard-restricted from tools such as `message`.

## Best Possible Solution

Define one explicit cron tool-policy contract, preferably `tools.cron.tools.allow/deny`, with documented precedence and compatibility behavior, then update schema/types/docs and cover embedded plus CLI cron runs with focused tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add a cron-scoped tool-policy config surface, make cron runs inherit subagent tool policy, or intentionally leave cron restrictions limited to per-job `payload.toolsAllow`?

Rationale: The choice defines a public config and security-boundary contract for scheduled autonomous runs, and automation should not choose the default, inheritance, or upgrade behavior without maintainer intent.

Likely owner: steipete

Owner reason: steipete has the strongest current blame and prior review signal for the schema/tool-policy boundary decision.

Owner confidence: high

Options:

- **Add cron-scoped policy (recommended):** Introduce explicit `tools.cron.tools.allow/deny` with precedence, docs, schema/type coverage, and upgrade-safe defaults.
- **Inherit subagent policy:** Reuse `tools.subagents.tools` for cron sessions, reducing config surface but coupling two distinct session classes and risking upgrade surprises.
- **Keep per-job only:** Leave cron restrictions to `payload.toolsAllow` and delivery mitigations, accepting the current operator ergonomics and defense-in-depth gap.

## Reproduction Assessment

Yes. Source inspection reproduces the structural gap: current main has subagent/sandbox policy and per-job cron `toolsAllow`, but no cron-scoped policy or inheritance from subagent policy.

## Solution Assessment

Unclear until maintainers choose the policy boundary. An explicit cron-scoped policy appears cleaner than implicit subagent inheritance because cron and subagent sessions are distinct runtime classes.
