## Summary

Keep open: current main and v2026.6.11 still lack a cron-scoped hard allow/deny config or subagent-policy inheritance; the landed work only provides per-job `toolsAllow`, creator-surface caps, and CLI default-cap handling.

## What This Changes

The issue requests a cron-scoped tool deny policy such as `tools.cron.tools.deny`, or cron inheritance from existing subagent tool restrictions.

## Best Possible Solution

Define one maintainer-approved cron tool-policy contract, then implement it across schema, exported types, config metadata/help, docs, runtime policy resolution, and regression tests for isolated cron delivery modes.
