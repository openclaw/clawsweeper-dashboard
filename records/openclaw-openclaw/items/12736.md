## Summary

Keep open: current main and the latest release still do not provide a cron-scoped `tools.cron.tools.allow/deny` policy or explicit inheritance from `tools.subagents.tools`, so the remaining work is a security-sensitive public config/default decision rather than cleanup.

## What This Changes

The issue requests a cron-scoped tool deny policy, such as `tools.cron.tools.deny`, or explicit cron inheritance from existing subagent tool restrictions.

## Best Possible Solution

Approve and implement a cron-scoped tool-policy contract with explicit precedence, schema/types/help/docs updates, and regression coverage for isolated cron message-tool denial across delivery modes.

Question: Should isolated cron jobs get first-class `tools.cron.tools.allow/deny`, inherit `tools.subagents.tools`, or continue with only per-job `payload.toolsAllow` plus delivery safeguards?

Rationale: The choice defines a scheduled-run tool-access boundary and public config/default contract with security and upgrade implications for existing cron jobs.

Likely owner: steipete

Owner reason: steipete has the strongest current history across scoped capability policy and recent cron runtime work.

Owner confidence: high

Options:

- **Add cron-scoped policy (recommended):** Introduce `tools.cron.tools.allow/deny` with documented precedence against existing policy layers and per-job `toolsAllow`.
- **Inherit subagent policy:** Apply `tools.subagents.tools` to cron sessions too, reducing config surface but coupling two execution modes with different semantics.
- **Keep per-job policy only:** Avoid a new global cron policy and rely on `payload.toolsAllow`, docs, and delivery safeguards for scheduled runs.

## Reproduction Assessment

Yes, at source level. Current schema/types still lack `tools.cron.tools`, and current policy resolution only applies `tools.subagents.tools` to subagent envelopes while cron relies on per-job `toolsAllow` plus delivery safeguards.

## Solution Assessment

Unclear until maintainers choose the security and product direction. A cron-scoped policy looks cleaner than overloading subagent semantics, but the best fix must define precedence and upgrade behavior first.
