## Summary

Keep open: current main and the latest release still expose per-job cron `toolsAllow`, but they do not provide a cron-scoped hard allow/deny config or documented inheritance from subagent tool policy. The remaining work is a security-boundary and public-config precedence decision, not conservative cleanup.

## What This Changes

The issue requests a cron-scoped tool restriction policy, such as `tools.cron.tools.deny`, or explicit cron inheritance from `tools.subagents.tools`.

## Best Possible Solution

Define one maintainer-approved cron tool-policy contract, then implement it across schema, exported types, config help/metadata, docs, runtime policy resolution, and regression tests for isolated cron delivery modes.
