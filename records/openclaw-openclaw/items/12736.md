## Summary

Keep open: current main and v2026.6.11 still lack a cron-scoped hard allow/deny policy or subagent-policy inheritance, and existing per-job `toolsAllow` plus delivery safeguards do not cover the reported security and duplicate-message gap.

## What This Changes

Request a cron-scoped hard tool allow/deny config option, or equivalent inheritance, so isolated cron jobs cannot call tools such as `message` when operators deny them.

## Best Possible Solution

Define one maintainer-approved cron tool-policy contract, then implement it across schema, exported types, config metadata/help, docs, runtime policy resolution, and regression tests for isolated cron delivery modes.
