## Summary

Keep open: current main and the latest release still lack a cron-scoped tool allow/deny policy or cron inheritance from `tools.subagents.tools`, so this remains a security-sensitive product/config decision rather than conservative cleanup.

## What This Changes

Requests a cron-scoped tool policy such as `tools.cron.tools.deny` or inheritance from `tools.subagents.tools` so isolated cron jobs can be hard-denied tools like `message`.

## Best Possible Solution

Define and document a cron-scoped tool-policy contract with explicit precedence, schema/types/help/docs updates, and regression coverage for isolated cron message-tool denial across delivery modes.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should isolated cron jobs get a first-class `tools.cron.tools.allow/deny` policy, inherit `tools.subagents.tools`, or continue with only per-job `payload.toolsAllow` plus delivery safeguards?

Rationale: The choice creates a public scheduled-run security/config boundary and can change compatibility for cron jobs that currently send messages directly.

Likely owner: steipete

Owner reason: steipete has the strongest recent history across cron runtime/config work and prior review context for this exact boundary.

Owner confidence: high

Options:

- **Add cron-scoped policy (recommended):** Introduce `tools.cron.tools.allow/deny` with documented precedence against existing policy layers and per-job `toolsAllow`.
- **Inherit subagent policy:** Apply `tools.subagents.tools` to cron sessions too, reducing config surface but coupling two execution modes with different semantics.
- **Keep per-job policy only:** Avoid a new global cron policy and rely on `payload.toolsAllow`, docs, and delivery safeguards for scheduled runs.

## Reproduction Assessment

Yes, at source level. Current schema/types still lack `tools.cron.tools`, runtime policy resolution applies `tools.subagents.tools` only to subagent envelopes, and docs/tests preserve cron message-tool availability through delivery-mode logic.

## Solution Assessment

Unclear until maintainers choose the security and product direction. A cron-scoped policy looks cleaner than overloading subagent semantics, but the best fix must define precedence and upgrade behavior first.
