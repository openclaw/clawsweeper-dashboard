## Summary

Keep open: current main and v2026.6.11 still lack the requested cron-scoped tool policy; current safeguards reduce duplicate announce risk but do not provide operator-wide cron denies.

## What This Changes

The issue requests a cron-scoped tool allow/deny policy, or cron inheritance from subagent policy, so scheduled isolated jobs can be prevented from calling tools such as `message`.

## Best Possible Solution

Keep this issue open for a maintainer-approved cron tool-policy design that defines either `tools.cron.tools.allow/deny` or deliberate inheritance, plus schema/types/help/docs and regression coverage for announce and direct-message behavior.

- **Inherit subagent policy:** Reuse `tools.subagents.tools` for cron runs to reduce config surface, accepting that subagents and scheduled jobs become coupled policy domains.
- **Keep per-job only:** Do not add a global cron policy; rely on per-job `toolsAllow`, docs, and delivery safeguards for scheduled-run tool restriction.
