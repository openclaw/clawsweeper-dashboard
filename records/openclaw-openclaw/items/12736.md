## Summary

Keep open: current main still lacks a cron-scoped tool deny config surface, and the existing per-job `toolsAllow` plus message-delivery prompt safeguards do not provide the requested enforceable cron-wide policy.

## What This Changes

Request to add `tools.cron.tools.deny` or equivalent cron inheritance so isolated cron jobs can be denied tools such as `message`.

## Best Possible Solution

Keep this as the cron-scoped policy tracker until maintainers choose explicit `tools.cron.tools.allow/deny` or documented cron inheritance with precedence, schema/types/help/docs coverage, upgrade guidance, and regression tests.

## Reproduction Assessment

Yes, for the missing capability: current main has no `tools.cron.tools` config surface and cron sessions do not enter the subagent policy layer. No live cron run was executed because this review is read-only.

## Solution Assessment

Unclear until maintainers choose the product/security shape. `tools.cron.tools.deny` is plausible, but the maintainable solution must define precedence against existing policy layers and per-job `toolsAllow` before implementation.
