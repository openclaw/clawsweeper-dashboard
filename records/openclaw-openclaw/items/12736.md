## Summary

Keep open: current main and the latest stable release still lack a cron-scoped hard tool allow/deny policy, and the issue has concrete security and duplicate-message evidence that per-job `toolsAllow` does not fully replace.

## What This Changes

Add a cron-scoped hard tool policy, such as `tools.cron.tools.deny` or cron inheritance from subagent policy, for scheduled agent turns.

## Best Possible Solution

Add or explicitly decline a cron-owned hard tool policy after defining precedence for global/agent/provider/group/sandbox/subagent policy layers, per-job `toolsAllow`, default creator caps, and CLI-backed runtimes.
