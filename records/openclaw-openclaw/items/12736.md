## Summary

Keep open: current main and v2026.6.11 still lack a cron-scoped tool allow/deny policy or explicit inheritance from `tools.subagents.tools`; the remaining work is a security-sensitive config and precedence decision rather than stale cleanup.

## What This Changes

The issue requests a cron-scoped tool restriction config, or cron inheritance from subagent tool policy, so isolated scheduled jobs can deny tools such as `message` without relying on prompts.

## Best Possible Solution

Approve a cron tool-policy contract with explicit precedence, then implement schema/types/runtime/docs/tests so scheduled runs have an operator-controlled hard boundary instead of prompt guidance alone.

- **Inherit Subagent Policy:** Apply `tools.subagents.tools` to cron sessions too, reducing config surface but coupling two different execution modes.
