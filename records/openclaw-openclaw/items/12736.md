## Summary

Keep open: current main and v2026.6.11 still lack a cron-scoped hard allow/deny policy or subagent-policy inheritance, and the issue discussion shows this remains a security and duplicate-delivery gap for scheduled runs.

## What This Changes

Request a cron-scoped hard tool allow/deny policy, or explicit inheritance from subagent tool restrictions, so scheduled cron sessions cannot call denied tools such as `message`.

## Best Possible Solution

Define one maintainer-approved cron tool-policy contract, then implement it across schema, exported types, config metadata/help, docs, runtime policy resolution, and regression tests for isolated cron delivery modes.
