## Summary

Keep open: current main still has per-job cron `toolsAllow` and delivery safeguards, but no cron-wide hard allow/deny config and no documented inheritance from `tools.subagents.tools`; the remaining choice is a public config and scheduled-tool security-boundary decision.

## What This Changes

The issue requests a cron-scoped tool restriction policy, such as `tools.cron.tools.deny`, or explicit cron inheritance from the existing subagent tool policy.

## Best Possible Solution

Define one maintainer-approved cron tool-policy contract, then implement it across schema, exported types, config help/metadata, docs, runtime policy resolution, and regression tests for isolated cron delivery modes.
