## Summary

Keep open: current main and v2026.6.11 still have only per-job cron `toolsAllow` plus delivery safeguards, not a system-wide cron tool deny policy or inheritance from `tools.subagents.tools`. The remaining work is a maintainer security/config decision, not conservative cleanup.

## What This Changes

The issue requests a cron-scoped tool restriction option so isolated cron runs can deny tools such as `message` instead of relying on prompt instructions.

## Best Possible Solution

Keep this issue open until maintainers approve a cron tool-policy contract, then implement either first-class `tools.cron.tools.allow/deny` or documented inheritance with schema/types/docs and regression coverage for per-job `toolsAllow` plus announce delivery.

- **Inherit subagent policy:** Make cron runs reuse `tools.subagents.tools`, reducing config surface while coupling two distinct execution modes.
- **Keep per-job only:** Document that operators must use per-job `toolsAllow` and delivery safeguards instead of a global cron policy.
