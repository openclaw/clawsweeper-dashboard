## Summary

Keep open: current main and v2026.6.11 still lack a cron-scoped hard allow/deny config or subagent-policy inheritance, and the remaining choice defines a public config and scheduled-tool security boundary.

## What This Changes

Request a cron-scoped hard tool-policy config, such as `tools.cron.tools.deny`, or cron inheritance from `tools.subagents.tools` so isolated scheduled jobs can be restricted from tools like `message`.

## Best Possible Solution

Define one maintainer-approved cron tool-policy contract, then implement it across schema, exported types, config metadata/help, docs, runtime policy resolution, and regression tests for isolated cron delivery modes.
