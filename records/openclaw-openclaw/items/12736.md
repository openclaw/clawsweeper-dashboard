## Summary

Keep open: current main and latest v2026.6.11 still lack a system-wide cron tool allow/deny policy or explicit inheritance from `tools.subagents.tools`; per-job `toolsAllow` and delivery safeguards do not satisfy the requested cron-scoped hard boundary.

## What This Changes

Request adding `tools.cron.tools.deny` or cron inheritance from subagent tool policy so isolated cron jobs can be restricted from tools such as `message`.

## Best Possible Solution

Approve a cron-scoped tool-policy contract with explicit precedence, schema/types/help/docs updates, and regression coverage for isolated cron message-tool denial across delivery modes.

Question: Should isolated cron jobs get a first-class `tools.cron.tools.allow/deny` policy, inherit `tools.subagents.tools`, or continue with only per-job `payload.toolsAllow` plus delivery safeguards?

Rationale: This decision creates a public config and scheduled-run security boundary, including whether existing announce-mode cron jobs that directly use `message` remain allowed by default.

Likely owner: steipete

Owner reason: He has the strongest recent history across the scoped capability profile and prior review context for this policy boundary.

Owner confidence: high

Options:

- **Add Cron-Scoped Policy (recommended):** Introduce `tools.cron.tools.allow/deny` with explicit precedence and tests for message-tool denial across cron delivery modes.
- **Inherit Subagent Policy:** Apply `tools.subagents.tools` to cron sessions too, reducing new config surface while coupling two different execution modes.
- **Keep Per-Job Only:** Avoid a new global cron policy and rely on `payload.toolsAllow`, docs, and delivery safeguards for scheduled runs.

## Reproduction Assessment

Yes, at source level. Current schema/types lack `tools.cron.tools`, current policy resolution only applies `tools.subagents.tools` to subagent envelopes, and current cron tests keep `message` enabled for announce delivery.

## Solution Assessment

Unclear until maintainers choose the security and product direction. A cron-scoped policy looks cleaner than overloading subagent semantics, but the best fix must define precedence and upgrade behavior first.
