## Summary

Keep open: current main and the latest release still lack a cron-scoped hard allow/deny tool policy or documented inheritance from subagent policy, while the discussion includes source-level and runtime evidence that cron message-tool access remains a real unattended-delivery boundary.

## What This Changes

Request a `tools.cron.tools.deny` config option, or equivalent cron inheritance from `tools.subagents.tools`, so isolated cron jobs can be hard-restricted from tools such as `message`.

## Best Possible Solution

Define one canonical cron/session tool-policy contract, then implement cron enforcement with schema/types/help/docs and regression tests for message denial, delivery modes, and `toolsAllow` precedence.
