## Summary

Keep open: current main still lacks a cron-scoped tool allow/deny config layer or explicit inheritance from subagent tool policy, and the remaining work is a security-sensitive config/product decision rather than an already-implemented cleanup target.

## What This Changes

Request a cron-scoped tool restriction config such as `tools.cron.tools.deny`, or explicit inheritance from `tools.subagents.tools`, so isolated cron jobs can be denied tools like `message`.

## Best Possible Solution

Keep this open until maintainers approve a cron tool-policy contract with explicit precedence, upgrade behavior, schema/types/docs updates, and regression coverage for isolated cron message-tool denial across delivery modes.
