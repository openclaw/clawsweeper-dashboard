## Summary

Keep open: current main and v2026.6.11 still do not implement `tools.cron.tools.allow/deny` or cron inheritance from `tools.subagents.tools`; the remaining work is a security-sensitive config/product decision, not conservative cleanup.

## What This Changes

The issue requests a cron-scoped tool deny policy so isolated cron jobs can be prevented from using tools such as `message` directly.

## Best Possible Solution

Add a maintainer-approved cron tool-policy design that either introduces `tools.cron.tools.allow/deny` or explicitly defines inheritance from existing policy layers, with schema/types/docs and regression coverage for announce delivery and message-tool denial.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should cron jobs get their own `tools.cron.tools.allow/deny` policy, inherit an existing policy layer such as `tools.subagents.tools`, or rely on per-job `payload.toolsAllow` plus delivery safeguards?

Rationale: Current main lacks the requested config, and choosing precedence/default behavior changes a security and compatibility surface for unattended jobs.

Likely owner: Vincent Koc

Owner reason: Recent current-main history points to this person on the relevant config and cron/tool-policy paths.

Owner confidence: medium

Options:

- **Add cron-scoped policy (recommended):** Introduce `tools.cron.tools.allow/deny` with explicit precedence against global/provider/agent/sandbox/subagent policy and per-job `toolsAllow`.
- **Inherit subagent policy:** Treat cron isolated sessions as inheriting `tools.subagents.tools`, reducing new config but coupling two different session types.
- **Keep per-job only:** Do not add a global cron policy and instead document/configure per-job `toolsAllow` plus delivery safeguards.

## Reproduction Assessment

Yes. Source inspection shows current main has no `tools.cron.tools` schema/type surface and cron sessions do not inherit the subagent policy branch; no runtime tests were run because this review is read-only.

## Solution Assessment

Unclear until maintainers choose the policy shape. A cron-scoped policy is the cleanest match to the request, while inheritance from `tools.subagents.tools` is a possible alternative with different compatibility tradeoffs.
