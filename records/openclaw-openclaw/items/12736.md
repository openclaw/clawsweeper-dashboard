## Summary

Keep open: current main and v2026.6.11 still have per-job `toolsAllow` and cron delivery safeguards, but no cron-scoped `tools.cron.tools` policy or explicit inheritance from subagent tool policy, so the requested security/config decision remains necessary.

## What This Changes

This issue requests a `tools.cron.tools.deny` config option, or cron inheritance from `tools.subagents.tools`, so scheduled cron jobs can be hard-blocked from tools such as `message`.

## Best Possible Solution

Define a maintainer-approved cron tool-policy contract with explicit precedence, schema/types/help/docs updates, and regression coverage for isolated cron message-tool denial across delivery modes.

- **Inherit Subagent Policy:** Apply `tools.subagents.tools` to cron sessions too, reducing config surface while coupling two different execution modes.
