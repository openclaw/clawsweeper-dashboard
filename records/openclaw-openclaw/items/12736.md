## Best Possible Solution

Keep this issue open for a maintainer-approved cron tool-policy design that defines either `tools.cron.tools.allow/deny` or explicit cron inheritance, documents precedence, and adds focused tests for isolated cron message-tool denial across delivery modes.

Options:

- **Add explicit cron policy (recommended):** Define a cron-specific hard policy layer with clear precedence against existing policies and per-job `toolsAllow`, then update schema/help/docs and regression tests.

- **Keep per-job allowlists only:** Document `payload.toolsAllow` and delivery-mode safeguards as the supported approach, leaving no system-wide cron deny option.
