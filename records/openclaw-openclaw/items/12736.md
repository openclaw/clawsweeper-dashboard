## Summary

Keep open: current main and the latest release still lack a cron-scoped tool allow/deny config surface or cron inheritance from `tools.subagents.tools`; the remaining behavior is per-job `toolsAllow` plus message-delivery safeguards, so the requested security boundary is still unresolved.

## What This Changes

Request to add a cron-scoped tool deny policy, such as `tools.cron.tools.deny`, so scheduled isolated cron runs can be prevented from using tools like `message`.

## Best Possible Solution

Keep this as the canonical cron-scoped policy tracker until maintainers choose explicit `tools.cron.tools.allow/deny` or documented cron inheritance, then update schema, exported types, help/docs, config metadata, and regression coverage for delivery modes and per-job `toolsAllow` precedence.
