## Summary

Keep open: current main and v2026.6.11 still lack a cron-scoped tool deny config surface, and the existing per-job `toolsAllow` plus delivery safeguards only partially cover the reported scheduled-message risk.

## What This Changes

Request to add a cron-scoped tool allow/deny policy, or make cron inherit subagent policy, so scheduled cron runs cannot use restricted tools such as `message`.

## Best Possible Solution

Keep this as the canonical cron policy tracker until maintainers choose explicit `tools.cron.tools.allow/deny` or documented cron inheritance, then update schema/types/help/docs and add regression coverage across delivery modes and per-job `toolsAllow` precedence.
