## Summary

Keep this open: current main still lacks a cron-scoped configured tool deny policy, and the remaining work is a security-sensitive config/product decision rather than a stale or already-implemented request.

## What This Changes

Request to add `tools.cron.tools.deny` or equivalent inheritance so isolated cron agent turns can be restricted from tools such as `message` at the config policy layer.

## Best Possible Solution

Define one cron tool-policy layer in the existing tool-policy resolver, document its precedence against per-job `toolsAllow` and delivery modes, then update schema/types/help/docs and add focused isolated-cron `message` denial coverage.
