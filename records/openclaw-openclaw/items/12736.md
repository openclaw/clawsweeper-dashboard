## Summary

Keep open: current main and v2026.6.11 still have per-job cron `toolsAllow` and message-delivery safeguards, but no cron-scoped hard allow/deny config or subagent-policy inheritance; the remaining choice is a public config and scheduled-tool security boundary.

## What This Changes

Request a hard cron-session tool restriction mechanism, such as `tools.cron.tools.deny` or cron inheritance from `tools.subagents.tools`, so scheduled jobs cannot directly use denied tools like `message`.

## Best Possible Solution

Define one maintainer-approved cron tool-policy contract, then implement it across schema, exported types, config metadata/help, docs, runtime policy resolution, and regression tests for isolated cron delivery modes.
