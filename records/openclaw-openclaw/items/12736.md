## Summary

Keep open: current main and the latest release still do not provide a system-level cron tool policy such as `tools.cron.tools.allow/deny`, and the existing per-job `toolsAllow` plus announce/message safeguards are partial controls rather than the requested cron-scoped deny boundary.

## What This Changes

Request a cron-scoped tool restriction config, such as `tools.cron.tools.deny`, or explicit cron inheritance from `tools.subagents.tools`.

## Best Possible Solution

Keep this as the cron-scoped policy tracker until maintainers choose explicit `tools.cron.tools.allow/deny` or documented cron inheritance with clear precedence, docs, schema/types, and upgrade behavior.

## Reproduction Assessment

Yes, source-level: current main has no `tools.cron.tools` schema/type surface and cron sessions do not enter the subagent policy path. I did not run a live cron job in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product/security shape; `tools.cron.tools.deny` is plausible, but the best implementation must define precedence against existing policy layers, per-job `toolsAllow`, and delivery modes.
