## Summary

Keep open: current main still lacks a cron-scoped tool allow/deny policy or cron inheritance from `tools.subagents.tools`, and the shipped per-job `toolsAllow` plus announce-delivery behavior does not satisfy the requested operator-enforced deny boundary.

## What This Changes

The issue requests a cron-scoped tool restriction config such as `tools.cron.tools.deny`, or cron inheritance from `tools.subagents.tools.deny`, to prevent scheduled jobs from using tools like `message` directly.

## Best Possible Solution

Define a maintainer-approved cron tool-policy contract with explicit precedence, schema/types/help/docs updates, and regression coverage for isolated cron `message` denial across announce, none, and webhook delivery modes.

- **Keep current safeguards:** Leave cron control to per-job `toolsAllow` and message-delivery safeguards, keeping config smaller but not solving the requested operator deny boundary.
