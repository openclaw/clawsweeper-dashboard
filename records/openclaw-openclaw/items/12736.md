## Summary

Keep open: current main and the latest release still lack a cron-scoped hard allow/deny config policy or documented inheritance from subagent tool policy. The shipped pieces are per-job `toolsAllow` plus delivery safeguards, so the remaining work is a security-boundary/product decision, not conservative cleanup.

## What This Changes

The issue requests a cron-scoped tool deny policy, such as `tools.cron.tools.deny`, so scheduled cron jobs can be hard-restricted from tools like `message`.

## Best Possible Solution

Keep this open for a maintainer-approved cron tool-policy contract, or explicit subagent-policy inheritance, with schema/types/docs and regression tests for `message` denial across cron delivery modes and per-job `toolsAllow` precedence.
