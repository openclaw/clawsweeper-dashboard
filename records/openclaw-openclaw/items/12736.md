## Summary

Keep open: current main still lacks a cron-scoped hard tool allow/deny policy or explicit inheritance from subagent policy; current cron code only provides per-job `toolsAllow` plus message-delivery safeguards, so the requested security/config decision remains unresolved.

## What This Changes

Add a hard cron job tool restriction policy, likely `tools.cron.tools.deny` or cron inheritance from `tools.subagents.tools`, to prevent scheduled isolated runs from using disallowed tools such as `message`.

## Best Possible Solution

Approve a cron-scoped tool-policy contract with explicit precedence, schema/types/help/docs updates, and regression coverage for isolated cron message-tool denial across delivery modes.

- **Inherit Subagent Policy:** Apply `tools.subagents.tools` to cron sessions as well, reducing config surface but coupling two different execution modes.
- **Keep Per-Job Only:** Avoid a new global cron policy and rely on `payload.toolsAllow`, docs, and delivery safeguards for scheduled runs.
