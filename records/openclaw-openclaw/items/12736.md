## Summary

Keep this open: current main has per-job `toolsAllow` and duplicate-delivery safeguards, but it still does not provide a system-wide cron-scoped `tools.cron.tools.allow/deny` policy or make cron inherit `tools.subagents.tools`.

## What This Changes

The issue requests a cron-scoped tool deny policy so scheduled isolated jobs can restrict tools such as `message` independently from existing subagent tool restrictions.

## Best Possible Solution

Keep the issue open for a maintainer-approved cron tool-policy design that either adds `tools.cron.tools.allow/deny` or deliberately defines inheritance, with schema/types/docs and regression coverage for announce/direct-message behavior.
