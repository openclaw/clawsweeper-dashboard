## Summary

Keep open: current main and v2026.6.11 still lack a cron-scoped tool allow/deny config surface or cron inheritance from `tools.subagents.tools`; per-job `toolsAllow` and delivery safeguards only partially mitigate the reported message-tool risk.

## What This Changes

Add a cron-scoped tool allow/deny policy, or make cron sessions inherit subagent tool restrictions, so scheduled jobs cannot use denied tools such as `message`.

## Best Possible Solution

Keep this as the canonical cron-scoped policy tracker until maintainers choose explicit `tools.cron.tools.allow/deny` or documented cron inheritance, then update schema, types, help, docs, and regression coverage for delivery modes and per-job `toolsAllow` precedence.
