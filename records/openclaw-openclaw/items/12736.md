## Summary

Keep open: current main and the latest release still lack a cron-scoped allow/deny or inheritance path; existing controls are per-job `toolsAllow` plus delivery safeguards, so the security-sensitive config decision remains.

## What This Changes

Request a `tools.cron.tools.deny` or allow policy, or inheritance from subagent policy, so isolated cron jobs cannot use configured denied tools such as `message`.

## Best Possible Solution

Maintainers should choose the cron tool-policy contract, then implement it through config schema/types/help/docs, policy resolution, and regression tests for isolated cron message-tool denial across delivery modes.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should isolated cron jobs get a first-class `tools.cron.tools.allow/deny` policy, inherit `tools.subagents.tools`, or continue with only per-job `payload.toolsAllow` plus delivery safeguards?

Rationale: This choice defines a scheduled-run tool-access boundary and public config contract, including whether existing announce-mode cron jobs that directly use `message` keep working by default.

Likely owner: steipete

Owner reason: He has the strongest combined signal from current tool-policy pipeline ownership and prior review context for this issue.

Owner confidence: high

Options:

- **Add Cron-Scoped Policy (recommended):** Introduce `tools.cron.tools.allow/deny` with explicit precedence and tests for message-tool denial across cron delivery modes.
- **Inherit Subagent Policy:** Apply `tools.subagents.tools` to cron sessions too, reducing config surface but coupling two different execution modes.
- **Keep Per-Job Only:** Avoid a new global cron policy and rely on `payload.toolsAllow`, docs, and delivery safeguards for scheduled runs.

## Reproduction Assessment

Yes, at source level. Current schema/types still lack `tools.cron.tools`, and current policy resolution only applies `tools.subagents.tools` to subagent envelopes while cron relies on per-job `toolsAllow` plus delivery safeguards.

## Solution Assessment

Unclear until maintainers choose the security and product direction. A cron-scoped policy looks cleaner than overloading subagent semantics, but the best fix must define precedence and upgrade behavior first.
