## Summary

Keep open: current main and the latest release still provide per-job cron `toolsAllow`, but not a cron-scoped hard allow/deny config or documented inheritance from subagent tool policy. The remaining work is a security-boundary and public-config precedence decision, not conservative cleanup.

## What This Changes

The issue requests a cron-scoped tool deny policy so scheduled cron jobs can be prevented from using tools such as `message` directly.

## Best Possible Solution

Define one maintainer-approved cron tool-policy contract, then implement it across schema, exported types, config help/metadata, docs, runtime policy resolution, and regression tests for isolated cron delivery modes.
