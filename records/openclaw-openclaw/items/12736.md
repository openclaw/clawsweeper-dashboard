## Summary

Keep open: current main and v2026.6.11 still lack a cron-scoped tool policy or explicit inheritance from `tools.subagents.tools`; per-job `toolsAllow` and duplicate-delivery safeguards do not satisfy the requested system-wide hard boundary.

## What This Changes

Requests a first-class cron-scoped tool allow/deny policy, or cron inheritance from subagent tool policy, so isolated cron jobs can block tools such as `message`.

## Best Possible Solution

Approve and implement a cron-scoped tool-policy contract with explicit precedence, schema/types/help/docs updates, and regression coverage for isolated cron message-tool denial across delivery modes.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add a cron-scoped tool-policy config surface, make cron runs inherit subagent tool policy, or intentionally leave cron restrictions limited to per-job `payload.toolsAllow`?

Rationale: This chooses a scheduled-run security boundary and public config/default contract, including whether existing cron jobs that directly use `message` during announce delivery keep working by default.

Likely owner: steipete

Owner reason: steipete has the strongest combined signal from cron runtime history, scoped tool-policy context, and prior review routing for this issue.

Owner confidence: high

Options:

- **Add Cron-Scoped Policy (recommended):** Introduce `tools.cron.tools.allow/deny` with explicit precedence and upgrade-safe tests for message-tool denial across cron delivery modes.
- **Inherit Subagent Policy:** Apply `tools.subagents.tools` to cron sessions too, reducing config surface while coupling two different execution modes.
- **Keep Per-Job Only:** Avoid a new global cron policy and rely on `payload.toolsAllow`, docs, and delivery safeguards for scheduled runs.

## Reproduction Assessment

Yes, at source level: current schema/types still lack `tools.cron.tools`, and current policy resolution only applies `tools.subagents.tools` to subagent envelopes while cron relies on per-job `toolsAllow` plus delivery safeguards.

## Solution Assessment

Unclear until maintainers choose the security and product direction. A cron-scoped policy looks cleaner than overloading subagent semantics, but the best fix must define precedence, defaults, and upgrade behavior first.
