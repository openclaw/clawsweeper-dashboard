## Summary

Keep open: current main still lacks a cron-scoped tool deny config surface, and the existing per-job `toolsAllow`, creator-surface capture, and cron delivery safeguards only partially cover the reported scheduled-message risk.

## What This Changes

Request for a cron-scoped tool policy such as `tools.cron.tools.deny`, or defined inheritance from `tools.subagents.tools`, so scheduled isolated cron runs can enforce tool restrictions system-wide.

## Best Possible Solution

Keep this as the cron-scoped policy tracker until maintainers choose explicit `tools.cron.tools.allow/deny` or documented cron inheritance, then update schema/types/help/docs and add regression coverage across announce, none, webhook, creator-captured, and per-job `toolsAllow` precedence.
