## Summary

Keep open: current main still lacks a cron-scoped tool allow/deny policy or explicit inheritance from `tools.subagents.tools`, while the reported security and duplicate-message concern remains covered only by per-job `toolsAllow` plus delivery safeguards.

## What This Changes

Request a cron-scoped tool restriction config, such as `tools.cron.tools.deny`, or explicit inheritance from subagent tool policy for isolated cron jobs.

## Best Possible Solution

Approve a first-class cron tool-policy contract with explicit precedence against global/provider/agent/group/sandbox/subagent/inherited layers and per-job `toolsAllow`, then update schema/types/docs and add regression coverage for message denial across cron delivery modes.
