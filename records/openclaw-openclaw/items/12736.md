## Summary

Keep open: current main still lacks a cron-scoped tool allow/deny policy or cron inheritance from `tools.subagents.tools`; the remaining behavior is per-job `payload.toolsAllow` plus message-delivery prompt safeguards, which does not provide the requested operator-enforced deny boundary.

## What This Changes

Requests a cron-scoped tool policy such as `tools.cron.tools.deny` or inheritance from `tools.subagents.tools` so isolated cron jobs cannot use denied tools like `message`.

## Best Possible Solution

Approve and implement a cron tool-policy contract with explicit precedence, schema/types/help/docs updates, and regression coverage for isolated cron message-tool denial across delivery modes.
