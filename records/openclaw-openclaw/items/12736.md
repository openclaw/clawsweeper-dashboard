## Summary

Keep open: current main and v2026.6.11 still do not provide a cron-scoped `tools.cron.tools.allow/deny` policy or make cron sessions inherit `tools.subagents.tools`; the remaining work is a security-sensitive config/product decision, not conservative cleanup.

## What This Changes

The issue requests a cron-scoped tool deny policy so scheduled isolated runs can block tools such as `message` independently of subagent policy.

## Best Possible Solution

Approve a cron tool-policy contract first, then implement either first-class `tools.cron.tools.allow/deny` or documented inheritance with schema/types/docs and regression coverage for per-job `toolsAllow` plus announce delivery.
