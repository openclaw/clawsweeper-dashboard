## Summary

Keep open: current main and v2026.6.11 still lack a cron-scoped tool allow/deny policy or cron inheritance from `tools.subagents.tools`; existing per-job `toolsAllow` and delivery safeguards do not provide the requested operator-enforced cron tool boundary.

## What This Changes

Requests a cron-scoped tool restriction config such as `tools.cron.tools.deny`, or cron inheritance from `tools.subagents.tools`, to prevent scheduled isolated runs from using tools like `message` directly.

## Best Possible Solution

Add a maintainer-approved cron tool-policy contract with explicit precedence, schema/types/help/docs updates, and regression coverage for isolated cron message-tool denial across delivery modes.
