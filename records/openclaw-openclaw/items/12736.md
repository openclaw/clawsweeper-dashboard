## Summary

Keep open: current main still lacks a cron-scoped tool deny config surface, and the existing per-job `toolsAllow` plus cron delivery safeguards only partially cover the reported scheduled-message risk.

## What This Changes

The issue requests a cron-scoped tool deny policy, such as `tools.cron.tools.deny`, so isolated scheduled cron jobs can be prevented from using tools like `message`.

## Best Possible Solution

Keep this as the cron-scoped policy tracker until maintainers choose explicit `tools.cron.tools.allow/deny` or documented cron inheritance, then update schema/types/help/docs and add regression coverage across announce, none, webhook, and per-job `toolsAllow` precedence.
