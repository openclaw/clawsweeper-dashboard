## Summary

Keep open: current main and v2026.6.11 still lack a cron-scoped tool allow/deny policy or cron inheritance from subagent policy, while existing docs and tests preserve shared cron message-tool delivery.

## What This Changes

Request to add `tools.cron.tools.deny` or equivalent cron-session inheritance so scheduled isolated cron runs can be restricted from tools such as `message`.

## Best Possible Solution

Define an explicit cron tool-policy contract, preferably `tools.cron.tools.allow/deny`, with documented precedence, config/schema/docs updates, and regression tests for message-tool denial across cron delivery modes.
