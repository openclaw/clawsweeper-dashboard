## Summary

Keep open: current main and latest v2026.6.11 still lack a cron-scoped tool allow/deny policy or cron inheritance from subagent tool policy; per-job toolsAllow and duplicate-delivery guards are useful partial mitigations but do not provide the requested operator-enforced cron boundary.

## What This Changes

The issue requests a cron-specific tool restriction config such as tools.cron.tools.deny, or explicit inheritance from tools.subagents.tools, so scheduled isolated cron jobs can be prevented from using tools like message and tts.

## Best Possible Solution

Add a maintainer-approved cron tool-policy contract with clear precedence, schema/types/help/docs updates, and regression coverage for isolated cron message-tool denial across announce, webhook, and no-delivery modes.
