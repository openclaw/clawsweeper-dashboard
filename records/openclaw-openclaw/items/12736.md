## Summary

## What This Changes

The issue requests a system-level cron tool restriction, either as `tools.cron.tools.deny` or cron inheritance from existing subagent tool policy.

## Best Possible Solution

Approve a cron-scoped tool-policy contract only after maintainers settle precedence, defaults, upgrade behavior, schema/types/help/docs updates, and regression coverage for message-tool denial across cron delivery modes.

- **Add Cron-Scoped Policy (recommended):** Introduce tools.cron.tools.allow/deny with explicit precedence and tests for message-tool denial across cron delivery modes.
- **Inherit Subagent Policy:** Apply tools.subagents.tools to cron sessions too, reducing config surface while coupling two different execution modes.

## Solution Assessment

Unclear until maintainers choose the security and product direction. A cron-scoped policy looks cleaner than overloading subagent semantics, but the best fix must define precedence and upgrade behavior first.
