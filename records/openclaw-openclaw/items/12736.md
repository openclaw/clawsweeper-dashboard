## Summary

Keep open: current main still lacks a cron-scoped hard tool policy, and the existing per-job `toolsAllow` plus message-delivery prompt guards do not satisfy the requested operator-level deny control.

## What This Changes

Requests a cron-scoped tool deny configuration, or equivalent inheritance, so isolated cron jobs cannot use disallowed tools such as `message`.

## Best Possible Solution

Make a maintainer-owned security/config decision for cron tool-policy precedence, then implement one canonical enforcement path with schema, exported types, docs, and regression coverage for isolated cron delivery modes.
