## Summary

Keep open: current main and the latest release still lack `tools.cron.tools.allow/deny` or explicit cron inheritance from `tools.subagents.tools`. The remaining work is a security-sensitive public config/default decision, and this issue remains the narrow canonical tracker rather than a duplicate of broader session-policy RFCs.

## What This Changes

The issue requests a cron-scoped hard tool restriction config such as `tools.cron.tools.deny`, or explicit inheritance from subagent tool policy, for scheduled cron agent runs.

## Best Possible Solution

Approve a cron-scoped tool-policy contract only after maintainers settle precedence, defaults, upgrade behavior, schema/types/help/docs updates, and regression coverage for isolated cron message-tool denial across delivery modes.

## Maintainer Decision

Question: Should OpenClaw add a cron-scoped tool-policy config surface, make cron runs inherit subagent tool policy, or intentionally leave cron restrictions limited to per-job `payload.toolsAllow`?

Rationale: This chooses a scheduled-run security boundary and public config/default contract, including whether existing cron jobs that directly use `message` during announce delivery keep working by default.

Likely owner: steipete

Owner confidence: high

Options:

- **Add Cron-Scoped Policy (recommended):** Introduce `tools.cron.tools.allow/deny` with explicit precedence and upgrade-safe tests for message-tool denial across cron delivery modes.
- **Inherit Subagent Policy:** Apply `tools.subagents.tools` to cron sessions too, reducing config surface while coupling two different execution modes.
- **Keep Per-Job Only:** Avoid a new global cron policy and rely on `payload.toolsAllow`, docs, and delivery safeguards for scheduled runs.

## Reproduction Assessment

Yes. Source inspection reproduces the structural gap: current main has subagent/sandbox policy and per-job cron `toolsAllow`, but no cron-scoped policy or inheritance from subagent policy.

## Solution Assessment

Unclear until maintainers choose the security and product direction. A cron-scoped policy looks cleaner than overloading subagent semantics, but the best fix must define precedence, defaults, and upgrade behavior first.
