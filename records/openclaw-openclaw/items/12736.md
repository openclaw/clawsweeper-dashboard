## Summary

Keep open: current main still lacks a cron-scoped hard tool allow/deny policy or explicit inheritance from `tools.subagents.tools`, and the related issues cover broader or adjacent cron/tool-policy problems rather than superseding this narrow security/config decision.

## What This Changes

The issue requests a cron-scoped hard tool allow/deny policy, such as `tools.cron.tools.deny`, so isolated cron jobs can be restricted from tools like `message`.

## Best Possible Solution

Approve a cron-scoped tool-policy contract with explicit precedence, upgrade behavior, schema/types/help/docs updates, and regression coverage for isolated cron message-tool denial across delivery modes.

- **Inherit Subagent Policy:** Apply `tools.subagents.tools` to cron sessions too, reducing config surface while coupling two distinct execution modes.
- **Keep Per-Job Only:** Avoid a new global cron policy and rely on `payload.toolsAllow`, docs, and delivery safeguards for scheduled runs.
