## Summary

Keep open: current main and v2026.6.11 still lack a cron-scoped config deny policy, and the shipped mitigations are per-job `toolsAllow` plus cron delivery safeguards rather than the requested system-level boundary.

## What This Changes

The issue requests a `tools.cron.tools.deny` policy or cron inheritance from `tools.subagents.tools` so isolated scheduled jobs can be blocked from selected tools such as `message`.

## Best Possible Solution

Keep this as the cron-scoped policy tracker until maintainers choose explicit `tools.cron.tools.allow/deny` or documented cron inheritance, then update schema/types/help/docs and cover announce, none, webhook, and per-job `toolsAllow` precedence.
