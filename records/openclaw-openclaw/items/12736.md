## Summary

Keep open: current main and the latest release still lack a cron-scoped hard allow/deny config or inheritance from subagent tool policy, while existing per-job `toolsAllow` only covers individual scheduled jobs and leaves the requested security/delivery policy undecided.

## What This Changes

Request a cron-scoped tool restriction policy such as `tools.cron.tools.deny` or equivalent inheritance from existing subagent tool policy for scheduled cron sessions.

## Best Possible Solution

Define one maintainer-approved cron tool-policy contract, then implement it across schema, exported types, config metadata/help, docs, runtime policy resolution, and regression tests for isolated cron delivery modes.
