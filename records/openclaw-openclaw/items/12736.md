## Summary

Keep open: current main and the latest release still lack a cron-scoped tool deny config surface; per-job `toolsAllow` and message-delivery safeguards mitigate parts of the report but do not provide the requested system-wide cron policy.

## What This Changes

The issue requests a cron-scoped tool restriction configuration such as `tools.cron.tools.deny` or explicit cron inheritance from the existing subagent tool policy.

## Best Possible Solution

Define a maintainer-approved cron tool-policy model, then align schema, exported config types, docs, generated metadata, and regression coverage while preserving existing per-job `toolsAllow` semantics.
