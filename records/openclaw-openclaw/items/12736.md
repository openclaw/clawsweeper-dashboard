- `impact:security`: The requested policy controls scheduled-run access to powerful tools such as `message`, `exec`, and `tts`.

## Summary

Keep open: current main and the latest release still lack a cron-scoped tool allow/deny policy or cron inheritance from `tools.subagents.tools`; existing per-job `toolsAllow` and message-delivery safeguards reduce duplicate sends but do not provide the requested operator-enforced cron tool boundary.

## What This Changes

The issue requests a `tools.cron.tools.deny`-style cron job tool policy, or cron inheritance from subagent tool policy, so scheduled isolated runs can be denied tools such as `message`.

## Best Possible Solution

Add a maintainer-approved cron tool-policy contract with explicit precedence against existing policy layers and per-job `toolsAllow`, plus schema/types/help/docs updates and regression coverage for announce, webhook, and no-deliver cron runs.
