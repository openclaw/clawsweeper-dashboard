## Summary

Keep open: current main and v2026.6.11 still lack a cron-scoped tool deny policy, and the remaining work is a product/security decision about scheduled-run tool-policy precedence rather than stale cleanup.

## What This Changes

Add or inherit a cron-scoped tool deny policy so isolated cron jobs can block tools like `message` without relying on prompt instructions.

## Best Possible Solution

Keep this as the focused cron tool-policy design issue until maintainers choose explicit `tools.cron.tools.allow/deny` versus documented inheritance, then align schema, types, docs, help/config metadata, and regression tests across delivery modes and per-job `toolsAllow` precedence.
