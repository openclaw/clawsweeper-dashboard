## Summary

Keep open: current main and v2026.6.11 still lack a cron-scoped tool allow/deny policy or explicit cron inheritance from `tools.subagents.tools`; current safeguards are per-job `payload.toolsAllow` and cron delivery/message-tool duplicate handling.

## What This Changes

Request a cron-scoped tool allow/deny policy, or cron inheritance from subagent policy, so isolated scheduled jobs can hard-block tools such as `message`.

## Best Possible Solution

Approve a cron tool-policy contract with explicit precedence, then implement it across schema, types, runtime, docs, and regression tests so scheduled runs have an operator-controlled hard boundary.
