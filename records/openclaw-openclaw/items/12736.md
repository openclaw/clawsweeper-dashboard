## Summary

Keep open: current main still lacks `tools.cron.tools.allow/deny` or explicit inheritance from `tools.subagents.tools`, while docs and tests confirm isolated cron can still use the `message` tool through announce delivery unless per-job `toolsAllow` excludes it.

## What This Changes

The issue requests a system-level cron tool restriction config such as `tools.cron.tools.deny`, or explicit inheritance from `tools.subagents.tools`, to prevent isolated cron jobs from using disallowed tools like `message`.

## Best Possible Solution

Approve and implement a cron-scoped tool-policy contract with explicit precedence, schema/types/help/config-doc updates, and regression coverage for isolated cron message-tool denial across delivery modes.
