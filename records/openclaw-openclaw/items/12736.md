## Summary

Keep open: current main still lacks a cron-scoped hard allow/deny policy or subagent-policy inheritance; existing per-job `toolsAllow` and delivery prompts do not settle the public config/security-boundary decision.

## What This Changes

Request a cron-scoped hard tool policy, such as `tools.cron.tools.deny` or cron inheritance from `tools.subagents.tools`, so isolated cron agent turns cannot call denied tools like `message`.

## Best Possible Solution

Define a maintainer-approved cron tool-policy contract and implement it consistently across config schema/types, metadata/help/docs, runtime policy resolution, and isolated-cron delivery tests.
