## Summary

Keep open: current main still has per-job `toolsAllow` and cron delivery mitigations, but it does not provide the requested cron-scoped tool allow/deny policy or explicit inheritance from subagent tool policy, so the remaining work is a security-sensitive config/product decision rather than a conservative cleanup close.

## What This Changes

The issue requests a cron-specific tool restriction config surface, or explicit cron inheritance from subagent tool policy, so scheduled isolated runs cannot use tools such as `message` when an operator expects delivery-only behavior.

## Best Possible Solution

Define a single cron tool-policy contract, preferably cron-scoped allow/deny with explicit precedence and compatibility behavior, then align schema/types/docs and cover CLI and embedded cron runs with focused tests.

## Maintainer Decision

Required: true

Question: Should OpenClaw add a cron-scoped tool-policy config surface, make cron runs inherit subagent tool policy, or intentionally leave cron restrictions limited to per-job `payload.toolsAllow`?

Rationale: This sets a public config and security-boundary contract for scheduled autonomous runs, and the safest default depends on maintainer intent for upgrades, delivery semantics, and policy precedence.

Likely owner: steipete

Owner reason: The strongest local history points to recent subagent/tool-policy work and prior review context on this exact issue.

Owner confidence: high

Options:

- **Add cron-scoped policy (recommended):** Introduce an explicit cron tool-policy config with documented precedence over global, sandbox, subagent, and per-job policy layers, plus upgrade-safe defaults.
- **Inherit subagent policy:** Reuse `tools.subagents.tools` for cron sessions, reducing config surface but coupling two distinct session classes and risking unexpected upgrade behavior.
- **Keep per-job only:** Leave system-wide cron restrictions out of core and require operators to set `payload.toolsAllow` per job, accepting the current security and delivery ergonomics gap.

## Reproduction Assessment

Yes, source inspection reproduces the gap: current main has subagent and sandbox tool policy paths plus per-job cron `toolsAllow`, but no cron-scoped tool policy or cron inheritance from subagent policy; no live run was needed for that structural check.

## Solution Assessment

Unclear until maintainers choose the policy boundary; an explicit cron-scoped policy appears cleaner than implicit subagent inheritance because cron and subagent sessions are distinct runtime classes.
