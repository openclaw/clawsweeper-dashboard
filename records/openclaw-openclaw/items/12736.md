## Summary

Keep open: current main and v2026.6.11 still lack a cron-scoped hard allow/deny policy or subagent-policy inheritance, and the merged per-job toolsAllow surface does not cover the reported cron-wide security and duplicate-delivery gap.

## What This Changes

The issue requests a cron-scoped tool policy such as tools.cron.tools.deny, or cron inheritance from subagent tool policy, so scheduled agent turns can block tools like message globally.

## Best Possible Solution

Define one maintainer-approved cron tool-policy contract, then implement it across schema, exported types, config metadata/help, docs, runtime policy resolution, and regression tests for isolated cron delivery modes.
