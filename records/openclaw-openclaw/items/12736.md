## Summary

Keep open: current main and the latest release still lack a cron-scoped tool deny policy or documented inheritance from subagent tool policy; existing per-job `toolsAllow` and message-delivery safeguards are useful partial controls but do not provide the requested enforced cron policy.

## What This Changes

Request a cron-scoped tool deny policy such as `tools.cron.tools.deny` or explicit cron inheritance from `tools.subagents.tools` for scheduled isolated cron runs.

## Best Possible Solution

Keep this as the cron-scoped policy tracker until maintainers choose explicit `tools.cron.tools.allow/deny` or documented cron inheritance from subagent policy with precedence, upgrade behavior, docs, and regression tests.

## Reproduction Assessment

Yes for the missing capability from source inspection: current main has no `tools.cron.tools` config surface and cron sessions do not enter the subagent-policy path. I did not run a live cron job in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product/security shape. `tools.cron.tools.deny` is plausible, but the best implementation must define precedence against existing policy layers, per-job `toolsAllow`, and announce/message delivery behavior.
