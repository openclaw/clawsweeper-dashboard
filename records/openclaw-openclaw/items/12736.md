## Summary

Keep open: current main still lacks a cron-scoped tool deny policy, and the existing per-job `toolsAllow` plus delivery-mode safeguards do not provide the requested enforceable cron-wide config surface.

## What This Changes

Request to add cron job tool restrictions through a config option such as `tools.cron.tools.deny`, or by making cron isolated sessions inherit existing subagent tool policy.

## Best Possible Solution

Keep this as the narrow cron tool-policy tracker until maintainers choose explicit `tools.cron.tools.allow/deny` or documented cron inheritance, then update schema/types/help/docs and add regression tests for cron message-tool denial across delivery modes.

## Reproduction Assessment

Yes, for the missing capability: current main has no `tools.cron.tools` config surface and cron sessions do not enter the subagent policy layer. No live cron run was executed because this review is read-only.

## Solution Assessment

Unclear until maintainers choose the product/security shape. `tools.cron.tools.deny` is plausible, but the maintainable solution must define precedence against existing policy layers and per-job `toolsAllow` before implementation.
