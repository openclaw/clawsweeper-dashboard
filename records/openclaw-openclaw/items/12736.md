## Summary

Keep open: current main still lacks a cron-scoped hard allow/deny policy or documented inheritance from subagent tool policy, and the issue has concrete duplicate-delivery evidence when cron can call `message` directly.

## What This Changes

Request a cron-wide tool restriction policy such as `tools.cron.tools.deny`, or explicit inheritance from `tools.subagents.tools`, so scheduled cron agent turns can be denied tools like `message`.

## Best Possible Solution

Define one maintainer-approved cron tool-policy contract, then implement it across schema, exported types, config help/metadata, docs, runtime policy resolution, and regression tests for isolated cron delivery modes.
