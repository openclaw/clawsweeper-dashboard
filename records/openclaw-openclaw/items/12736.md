## Summary

Keep open: current main still has per-job `toolsAllow` and cron delivery safeguards, but no cron-scoped allow/deny config or explicit inheritance from subagent tool policy, so the requested hard cron tool restriction remains unresolved.

## What This Changes

Request a cron-scoped tool policy such as `tools.cron.tools.deny` so isolated cron jobs cannot use selected tools like `message` only by prompt convention.

## Best Possible Solution

Define one first-class cron tool-policy model in core, update schema/types/help/docs, and add regression coverage for isolated cron message-tool denial across announce, webhook, and none delivery modes.
