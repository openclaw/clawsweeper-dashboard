- `impact:security`: The request is about hard enforcement of which tools scheduled cron agents may call.
- `impact:message-loss`: The reported use case is preventing duplicate or misrouted visible messages when announce-mode cron runs can call `message` directly.

## Summary

Keep open: current main still lacks a cron-scoped tool policy such as `tools.cron.tools.allow/deny` or explicit inheritance from `tools.subagents.tools`; per-job `payload.toolsAllow` and message-delivery safeguards are useful partial controls but do not provide the requested reusable operator policy.

## What This Changes

Add a cron-scoped tool restriction policy so isolated cron jobs can be denied tools such as `message` without relying on prompt instructions or per-job allowlists.

## Best Possible Solution

Approve a typed cron tool-policy contract, or an explicit cron-inherits-subagent contract, with precedence rules, schema/types/labels/docs, and regression coverage for announce-mode `message` denial.

Options:

- **Add cron-scoped tool policy (recommended):** Introduce `tools.cron.tools.allow/deny` with explicit precedence over global/provider/agent/sandbox/subagent policy and per-job `toolsAllow`, plus docs and tests.
- **Make cron inherit subagent policy:** Reuse `tools.subagents.tools` for cron sessions, but document the coupling and add upgrade proof for existing cron jobs that currently rely on message delivery.
- **Keep per-job controls only:** Decline a reusable cron config layer and document `payload.toolsAllow` as the supported hard policy surface for each job.

## Reproduction Assessment

Yes, as source-level feature-gap proof: current main has no `tools.cron.tools` schema/type/docs surface and applies subagent policy only to subagent envelopes. I did not run a live cron job in this read-only review.

## Solution Assessment

Unclear until maintainers choose the policy shape. A cron-specific allow/deny config is plausible, but inheriting subagent policy or documenting per-job `toolsAllow` are product/security alternatives with different compatibility costs.
