## Summary

Keep open: current main and the latest release still lack a cron-scoped hard allow/deny policy or subagent-policy inheritance, and per-job `toolsAllow` plus delivery safeguards do not cover the reported security and duplicate-message gap.

## What This Changes

The issue requests a cron-scoped tool deny policy so scheduled isolated jobs can be prevented from using tools such as `message`.

## Best Possible Solution

Define one maintainer-approved cron tool-policy contract, then implement it across schema, exported types, config metadata/help, docs, runtime policy resolution, and regression tests for isolated cron delivery modes.
