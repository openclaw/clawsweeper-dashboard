## Summary

Keep open: current main and v2026.6.11 still lack a cron-scoped tool allow/deny config layer or explicit inheritance from subagent tool policy; the remaining work is a security-sensitive product/config decision, not a stale cleanup close.

## What This Changes

Request a `tools.cron.tools.deny` configuration option, or cron inheritance from `tools.subagents.tools`, so isolated cron jobs can be hard-restricted from tools such as `message`.

## Best Possible Solution

Keep this issue open until maintainers approve a cron tool-policy contract with explicit precedence, upgrade behavior, schema/types/docs updates, and regression coverage for isolated cron message-tool denial across delivery modes.
