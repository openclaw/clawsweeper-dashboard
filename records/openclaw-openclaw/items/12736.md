## Summary

Keep open: current main and v2026.6.11 still lack a cron-scoped tool deny policy, and the existing per-job `toolsAllow` plus cron message-delivery safeguards do not provide the requested enforceable config surface.

## What This Changes

The issue requests a `tools.cron.tools.deny` policy, or equivalent cron inheritance, so isolated cron jobs can restrict tools such as `message` without relying on prompts.

## Best Possible Solution

Keep this as the cron-scoped policy tracker until maintainers choose explicit `tools.cron.tools.allow/deny` or documented cron inheritance with precedence, docs, schema/type coverage, upgrade guidance, and regression tests.

## Reproduction Assessment

Yes, for the missing capability: current main has no `tools.cron.tools` config surface and cron sessions do not enter the subagent policy layer. No live cron run was executed because this review is read-only.

## Solution Assessment

Unclear until maintainers choose the product/security shape. `tools.cron.tools.deny` is plausible, but the maintainable solution must define precedence against existing policy layers and per-job `toolsAllow` before implementation.
