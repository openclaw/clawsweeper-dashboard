## Summary

Keep open: current main still lacks a cron-scoped tool allow/deny config surface, and cron sessions still do not inherit `tools.subagents.tools`; current per-job `toolsAllow` and duplicate-delivery safeguards only partially mitigate the reported risk.

## What This Changes

Request a cron-scoped tool policy, or inheritance from subagent tool policy, so isolated cron jobs cannot use denied tools such as `message`.

## Best Possible Solution

Keep this as the canonical cron-scoped policy tracker until maintainers choose explicit `tools.cron.tools.allow/deny` or documented cron inheritance, then update schema, types, help, docs, and regression coverage across delivery modes and per-job `toolsAllow` precedence.
