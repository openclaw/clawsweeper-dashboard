## What This Changes

The issue requests a cron-scoped tool deny policy, such as `tools.cron.tools.deny`, so cron jobs can be restricted independently from sub-agent sessions.

## Best Possible Solution

Keep this as the cron-scoped policy tracker until maintainers choose either explicit `tools.cron.tools.allow/deny` or documented cron inheritance from subagent policy with clear precedence and upgrade behavior.

## Reproduction Assessment

Yes for the missing capability from source inspection: current main has no `tools.cron.tools` config surface, cron sessions are classified separately from subagents, and the tool pipeline has no cron policy stage. I did not run a live cron job because this review is read-only.

## Solution Assessment

Unclear until maintainers choose the product/security shape; `tools.cron.tools.deny` is plausible, but the best implementation must define precedence against existing policy layers and per-job `toolsAllow`.
