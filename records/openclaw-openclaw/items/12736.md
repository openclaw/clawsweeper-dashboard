## Summary

Keep open: current main and v2026.6.11 still lack a cron-scoped tool deny policy or explicit inheritance from subagent tool policy. The remaining work is a security-sensitive config/product decision; current mitigations are per-job `toolsAllow` plus cron delivery safeguards, not the requested system-wide cron policy.

## What This Changes

The issue requests `tools.cron.tools.allow/deny` or cron inheritance from `tools.subagents.tools` so isolated cron jobs can be hard-restricted from tools such as `message`.

## Best Possible Solution

Approve a cron-scoped tool-policy contract only after maintainers define precedence, upgrade behavior, docs/schema shape, and regression coverage for isolated cron message-tool denial across delivery modes.
