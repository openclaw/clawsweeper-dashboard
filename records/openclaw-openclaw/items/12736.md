## Summary

Keep open: current main and v2026.6.11 still lack a cron-scoped tool allow/deny config surface or cron inheritance from subagent tool policy; the remaining work is a product/security decision about scheduled-run tool-access precedence.

## What This Changes

Request a `tools.cron.tools.deny` configuration option, or equivalent cron inheritance from `tools.subagents.tools`, so cron jobs can be hard-restricted from tools such as `message`.

## Best Possible Solution

Keep this as the canonical cron-scoped policy tracker until maintainers choose explicit `tools.cron.tools.allow/deny` or documented cron inheritance, then update schema, exported types, config metadata/help, docs, and regression tests for delivery modes and per-job `toolsAllow` precedence.
