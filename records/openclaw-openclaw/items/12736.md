## Summary

Keep open: current main and v2026.6.11 still do not expose a cron-scoped tool policy or make cron sessions inherit `tools.subagents.tools`; existing safeguards are per-job `toolsAllow` and delivery handling, so the requested operator-enforced cron boundary remains real but needs maintainer product/security direction.

## What This Changes

Request to add a cron-scoped tool allow/deny policy, such as `tools.cron.tools.deny`, so isolated cron jobs can be restricted independently of subagent policy and per-job `toolsAllow`.

## Best Possible Solution

Keep the issue open for a maintainer-owned cron tool-policy design that either adds `tools.cron.tools.allow/deny` or explicitly defines cron inheritance, with schema/types/docs/config metadata and tests covering precedence against per-job `toolsAllow` and announce delivery.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should cron runs get their own `tools.cron.tools.allow/deny` policy, inherit `tools.subagents.tools`, or continue relying on per-job `toolsAllow` plus delivery safeguards?

Rationale: This is a new public config and security boundary, and automation should not choose precedence or default message-tool behavior across cron, subagent, sandbox, provider, agent, group, sender, and per-job policy layers without maintainer intent.

Likely owner: steipete

Owner reason: steipete has the strongest combined signal from recent cron/session commits and the prior maintainer-style review on this issue.

Owner confidence: high

Options:

- **Add cron-scoped policy (recommended):** Define `tools.cron.tools.allow/deny` as the cron-specific hard policy layer, document precedence, and add targeted cron delivery/tool tests.
- **Make cron inherit subagent policy:** Treat isolated cron sessions as part of the existing subagent restriction model, reducing new config surface but coupling two different runtime concepts.
- **Keep per-job controls only:** Decline a system-wide cron policy and document `--tools`/`payload.toolsAllow` as the supported hard-enforcement mechanism for scheduled jobs.
