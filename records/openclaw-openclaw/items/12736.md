## Summary

Keep open: current main and latest release still lack a cron-scoped hard tool allow/deny policy or subagent-policy inheritance for cron sessions, while the issue has concrete security and duplicate-message impact evidence.

## What This Changes

The issue requests a first-class cron-scoped tool deny policy, such as `tools.cron.tools.deny`, or explicit inheritance from `tools.subagents.tools` so isolated cron sessions cannot call tools like `message`.

## Best Possible Solution

Make a maintainer-owned cron/session tool-policy decision, then implement one hard enforcement path with schema, exported types, config metadata/help, docs, and regression coverage for isolated cron delivery modes.
