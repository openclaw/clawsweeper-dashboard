## Summary

Keep open: current main still lacks a cron-scoped tool allow/deny config surface, and cron sessions still do not inherit `tools.subagents.tools`; per-job `toolsAllow` and message-delivery safeguards only partially cover the reported risk.

## What This Changes

Request a cron-scoped tool restriction policy, or cron inheritance from subagent tool policy, so scheduled jobs can be denied tools such as `message`.

## Best Possible Solution

Keep this as the canonical cron-scoped policy tracker until maintainers choose explicit `tools.cron.tools.allow/deny` or documented cron inheritance, then update schema, types, runtime policy resolution, docs, and delivery-mode regression coverage.
