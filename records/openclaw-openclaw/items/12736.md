## Summary

Keep open: current main still lacks a cron-scoped hard allow/deny tool policy or documented inheritance from subagent policy, and the discussion includes runtime evidence that cron message access can duplicate visible delivery. This remains a security-boundary/product-design item rather than conservative cleanup.

## What This Changes

Request to add a cron-scoped tool restriction config such as `tools.cron.tools.deny`, or make cron sessions inherit subagent tool restrictions.

## Best Possible Solution

Keep this open for a typed cron tool-policy contract, or explicit subagent-policy inheritance, with schema/types/docs and regression tests for `message` denial across cron delivery modes and `toolsAllow` precedence.
