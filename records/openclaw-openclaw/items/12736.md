## Summary

This issue should stay open because current main and the latest checked release still lack a cron-scoped operator tool policy, while the existing per-job `toolsAllow` and delivery fallback logic only partially mitigate the reported message/tool exposure problem.

## What This Changes

Request a cron-specific tool policy such as `tools.cron.tools.deny`, or explicit inheritance from `tools.subagents`, so isolated cron jobs can be prevented from using tools like `message`.

## Best Possible Solution

Define one cron tool-policy contract with explicit precedence against per-job `toolsAllow`, creator inherited caps, delivery fallback, and CLI-backend restrictions, then implement schema, docs, runtime wiring, and regression coverage together.
