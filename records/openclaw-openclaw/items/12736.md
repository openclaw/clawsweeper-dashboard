## Summary

Keep open: current main and v2026.6.11 still lack a cron-wide tool deny/allow policy or explicit inheritance from subagent tool policy; current mitigations are per-job `toolsAllow` and delivery safeguards, not the requested hard scheduled-run boundary.

## What This Changes

Add a cron-scoped tool policy such as `tools.cron.tools.deny` or make cron sessions inherit the existing subagent tool policy.

## Best Possible Solution

Approve and implement a cron-scoped tool-policy contract with explicit precedence, schema/types/help/docs updates, and regression coverage for isolated cron message-tool denial across delivery modes.
