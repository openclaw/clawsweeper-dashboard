## Summary

Keep open: current main and v2026.6.11 still lack `tools.cron.tools.allow/deny` or explicit inheritance from `tools.subagents.tools`; per-job `toolsAllow` and delivery safeguards exist, but the requested system-wide cron tool boundary remains a security-sensitive product/config decision.

## What This Changes

Request a cron-scoped tool restriction config such as `tools.cron.tools.deny`, or cron inheritance from `tools.subagents.tools`, so isolated cron jobs can be hard-blocked from tools like `message`.

## Best Possible Solution

Approve and implement a cron-scoped tool-policy contract with explicit precedence, schema/types/help/label/docs updates, and regression coverage for isolated cron message-tool denial across delivery modes.
