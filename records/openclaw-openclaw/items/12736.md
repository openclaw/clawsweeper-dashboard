## Summary

Keep open: current main still lacks a cron-scoped tool policy or documented inheritance from subagent tool restrictions, and the existing per-job `toolsAllow` plus announce-delivery safeguards do not provide the requested system-level deny enforcement.

## What This Changes

Request a cron-scoped tool policy such as `tools.cron.tools.deny`, or cron inheritance from `tools.subagents.tools`, so scheduled isolated cron jobs cannot use restricted tools like `message`.

## Best Possible Solution

Choose an explicit cron policy design, then update schema/types/help/docs and tests for either `tools.cron.tools.allow/deny` or documented cron inheritance with clear precedence against per-job `toolsAllow` and delivery-mode message behavior.

## Reproduction Assessment

Yes, from source: current config schemas and types do not expose a cron tool-policy scope, and cron sessions do not enter the subagent-policy classifier that powers `tools.subagents.tools.deny`.

## Solution Assessment

Unclear until maintainers choose the product/security shape; a cron deny config is plausible, but precedence and upgrade behavior must be designed before implementation.
