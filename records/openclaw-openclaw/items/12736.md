## Summary

Keep open: current main still lacks `tools.cron.tools.allow/deny` or explicit inheritance from `tools.subagents.tools`; newer per-job `toolsAllow` and message-delivery safeguards reduce one symptom but do not provide the requested system-wide cron policy.

## What This Changes

The issue requests a cron-scoped tool deny policy, such as `tools.cron.tools.deny`, so cron jobs can be prevented from using tools like `message` directly.

## Best Possible Solution

Keep this issue open until maintainers approve a cron tool-policy design with explicit precedence, schema/types/help/labels/docs updates, and regression coverage for isolated cron `message` denial across delivery modes.

- **Inherit Subagent Policy:** Apply `tools.subagents.tools` to cron sessions too, reducing config surface but coupling two different execution modes.
- **Keep Per-Job Only:** Avoid a new global cron policy and rely on `payload.toolsAllow`, docs, and delivery safeguards for scheduled runs.
