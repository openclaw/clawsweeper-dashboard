## Summary

Keep open: current main and v2026.6.11 still lack a cron-scoped hard allow/deny policy or subagent-policy inheritance, and adjacent `toolsAllow` fixes do not cover the global cron deny request.

## What This Changes

Request a `tools.cron.tools.deny` config option, or equivalent cron inheritance from `tools.subagents.tools`, so isolated cron jobs cannot call restricted tools such as `message`.

## Best Possible Solution

Define one maintainer-approved cron tool-policy contract, then implement it across schema, exported types, config metadata/help, docs, runtime policy resolution, and regression tests for isolated cron delivery modes.
