## Summary

Keep open: current main still lacks a cron-scoped tool deny policy, and the existing per-job `toolsAllow` plus delivery-mode safeguards only partially cover the scheduled-message risk.

## What This Changes

Requests a cron-scoped tool restriction surface such as `tools.cron.tools.deny` or explicit inheritance from `tools.subagents.tools` for isolated cron jobs.

## Best Possible Solution

Keep this as the cron-scoped policy tracker until maintainers choose explicit `tools.cron.tools.allow/deny` or documented cron inheritance, then update schema/types/help/docs and add regression coverage across delivery modes and per-job `toolsAllow` precedence.
