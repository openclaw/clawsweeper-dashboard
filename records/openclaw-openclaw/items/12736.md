## Summary

Keep open: current main and v2026.6.11 still lack `tools.cron.tools.allow/deny` or inheritance from `tools.subagents.tools`; existing per-job `payload.toolsAllow` and delivery safeguards do not provide the requested system-wide cron deny boundary.

## What This Changes

Request to add a cron-scoped tool allow/deny policy, or have cron inherit subagent policy, so scheduled isolated jobs can be prevented from using tools like `message`.

## Best Possible Solution

Keep this as the canonical cron tool-policy design issue until maintainers approve cron-specific allow/deny or explicit inheritance with precedence, schema/types/docs, and tests for delivery modes.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should isolated cron jobs get first-class `tools.cron.tools.allow/deny`, inherit `tools.subagents.tools`, or continue with only per-job `payload.toolsAllow` plus delivery safeguards?

Rationale: The choice defines a scheduled-run tool-access boundary and public config/default contract, including how hard denies interact with existing policy layers and cron jobs that use direct delivery.

Likely owner: steipete

Owner reason: steipete has the strongest combined signal from current schema/policy blame, recent cron runner work, and prior routing on this issue.

Owner confidence: high

Options:

- **Add cron-scoped policy (recommended):** Introduce `tools.cron.tools.allow/deny` with explicit precedence and regression coverage for message-tool denial across cron delivery modes.
- **Inherit subagent policy:** Apply `tools.subagents.tools` to cron sessions too, reducing config surface while coupling two different execution modes.
- **Keep per-job only:** Avoid a new global cron policy and rely on `payload.toolsAllow`, documentation, and delivery-mode safeguards for scheduled runs.

## Reproduction Assessment

Yes, at source level. Current schemas/types expose global, subagent, sandbox, and per-job `payload.toolsAllow` policy surfaces, but no cron-scoped policy, and policy resolution only includes subagent policy for subagent envelopes.

## Solution Assessment

Unclear until maintainers choose the security and product direction. A cron-scoped policy looks cleaner than overloading subagent semantics, but the best fix must define precedence and upgrade behavior first.
