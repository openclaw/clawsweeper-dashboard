## Summary

Keep open: current main and the latest release still lack a cron-scoped tool allow/deny config or explicit inheritance from subagent policy. The existing per-job `payload.toolsAllow` and cron delivery safeguards are useful, but they do not solve the requested system-wide cron tool restriction boundary.

## What This Changes

The issue requests a cron-scoped tool restriction policy such as `tools.cron.tools.deny`, or explicit cron inheritance from existing subagent tool restrictions.

## Best Possible Solution

Approve a cron-scoped tool-policy contract only after maintainers settle precedence, defaults, upgrade behavior, schema/types/help/docs updates, and regression coverage for isolated cron message-tool denial across delivery modes.
