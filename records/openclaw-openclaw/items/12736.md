## Summary

Keep open: current main still lacks a cron-scoped hard tool policy or explicit inheritance from subagent tool policy; existing per-job `payload.toolsAllow` and announce-delivery safeguards are useful but do not satisfy the requested system-wide cron deny/default policy.

## What This Changes

The issue requests a hard tool allow/deny policy for cron job sessions, such as `tools.cron.tools.deny` or explicit inheritance from subagent tool policy, to prevent cron jobs from directly using restricted tools like `message`.

## Best Possible Solution

Keep a cron-owned hard tool-policy design open, with precedence defined against global/agent/group/provider/sandbox/subagent policy layers, per-job `payload.toolsAllow`, CLI-vs-embedded runtime support, and announce delivery safeguards.
