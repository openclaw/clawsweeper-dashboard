## Summary

Keep open: current main still lacks a cron-scoped hard allow/deny tool policy or documented inheritance from subagent policy, even though adjacent per-job `toolsAllow` and cron delivery safeguards now exist. The issue remains a security-boundary/product-design item rather than conservative cleanup.

## What This Changes

Request a `tools.cron.tools.deny` config option, or equivalent inheritance from `tools.subagents.tools`, so isolated cron jobs can be hard-restricted from tools such as `message`.

## Best Possible Solution

Keep this open for a typed cron tool-policy contract, or explicit subagent-policy inheritance, with schema/types/docs and regression tests for `message` denial across cron delivery modes and `toolsAllow` precedence.
