## Summary

Keep open: the selector, render, and cross-run echo changes address a real iMessage poll-voting regression, but the new poll-comment fold can silently drop legitimate inline replies to a recent poll before they reach the agent.

## What This Changes

This PR updates iMessage poll-vote capability gating, inbound poll rendering, cross-run poll-vote echo suppression, and monitor handling for poll comments, with focused tests.

## Best Possible Solution

Keep the selector, render, and session echo fixes, but narrow or remove the poll-comment fold so only proven native poll captions are folded and normal inline replies to polls still dispatch.

## Reproduction Assessment

Yes from source inspection: after a poll is remembered, any inbound message with a matching reply_to_id enters the new poll-comment branch and returns before dispatch. I did not run a live iMessage repro in this read-only review.

## Solution Assessment

No: the useful poll-vote gating, render cue, and cross-run echo guard are plausible, but treating every recent reply-to-poll as a caption is too broad. The safer solution must preserve ordinary inline replies while handling the native caption case.
