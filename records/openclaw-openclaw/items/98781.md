- **[P1] Keep poll-vote gated on the vote initializer:** `extensions/imessage/src/actions.ts:813-820`
  - body: Current imsg source and README advertise `selectors.pollVoteMessage` for poll voting, and `handleSendPollVote` still checks `pollVoteMessageInitializerAvailable()` before constructing the vote message. By switching both discovery and execution to `pollPayloadMessage`, this branch can expose `poll-vote` on a bridge that can create polls but cannot construct vote messages; keep the vote selector plus `poll.vote` unless the upstream imsg contract changes.
  - confidence: 0.9
- **[P1] Narrow poll-comment folding to real captions:** `extensions/imessage/src/monitor/monitor-provider.ts:900-907`
  - body: This branch treats any inbound message whose `reply_to_id` targets a recently seen poll as the poll's caption and returns before the normal inbound dispatch path. OpenClaw already preserves iMessage reply_to_id/reply_to_text as ordinary reply context, so a user reply to the poll within the five-minute window would be silently dropped; narrow this to a proven caption signal or remove the drop path and add a normal-reply regression test.
  - confidence: 0.91
