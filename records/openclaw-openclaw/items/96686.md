## What This Changes

## Best Possible Solution

Land the prompt-rendering fix after maintainers accept the prompt-facing cron identity tradeoff, while keeping actual isolated-cron routing, transcript, cleanup, and delivery state per-run.

## Solution Assessment

Yes, with maintainer sign-off: prompt-facing normalization in `buildRuntimeLine` is narrower than reusing one cron session across runs, and the existing `promptCacheKey` path alone does not remove volatile Runtime prompt bytes.
