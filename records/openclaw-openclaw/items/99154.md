## Summary

This PR should stay open because the current head still has a blocking compatibility regression in the manual byte counter: non-partial property values with key-aware `toJSON(key)` no longer see their property key, so observable `responseStreamBytes` can drift.

## What This Changes

The PR rewrites model-call diagnostic stream byte accounting and base event construction to avoid hot-path object copies, with focused regression tests and a linked runtime benchmark artifact.

## Best Possible Solution

Keep the allocation reduction, but preserve object-property `JSON.stringify` semantics for non-partial values and refresh the current-head runtime proof before merge.

## Reproduction Assessment

Yes. A focused Node probe reproduces the PR-introduced byte-count drift for a non-partial property value whose `toJSON(key)` branches on the property key; the broader multi-day Gateway RSS plateau was not reproduced here.

## Solution Assessment

No. The affected diagnostic helper is the right layer for the hot-path mitigation, but the current manual serializer is not yet the best fix because it changes object-property JSON semantics.
