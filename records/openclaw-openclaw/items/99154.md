## Summary

Keep open: the PR has current-head runtime proof and fixes prior root `toJSON` / `__proto__` concerns, but the new manual byte counter still changes `JSON.stringify` semantics for key-aware nested `toJSON` values, so it should not merge until that regression is repaired.

## What This Changes

The PR changes model-call diagnostic stream byte accounting and base event construction to reduce hot-path object-copy churn, with regression tests for partial snapshots, `toJSON`, `__proto__`, and JSON-unsupported fields.

## Best Possible Solution

Land the narrow diagnostic hot-path mitigation only after the byte counter preserves `JSON.stringify` semantics for both root and property-value `toJSON` cases, while leaving the broader Gateway RSS/OOM tracker open at https://github.com/openclaw/openclaw/issues/91588.

## Reproduction Assessment

Yes for the PR-introduced regression: a focused Node probe shows a non-partial chunk value whose `toJSON` depends on its property key produces different bytes under object-rest `JSON.stringify` than under the new manual counter. The broader multi-day Gateway RSS/OOM behavior was not reproduced here.

## Solution Assessment

No; the hot-path owner boundary is right, but this implementation is not yet the best fix because it sacrifices a JSON serialization contract the surrounding diagnostic path already depended on. A safer fix keeps the allocation reduction while preserving property-key-aware value serialization.
