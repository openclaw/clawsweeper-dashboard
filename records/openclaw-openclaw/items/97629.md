## Summary

The PR is still necessary because current main does not gate the xAI lazy tool factories on the active provider, and the current PR head fixes the previous factory-test blocker. It should remain open for maintainer review and real behavior proof because the fail-closed behavior is a compatibility-sensitive auth/provider change.

## What This Changes

The PR exports the xAI lazy `code_execution` and `x_search` tool factories, makes both return `null` unless `activeModel.provider` is `xai`, and adds factory-level tests for xAI, non-xAI, missing-model, undefined-provider, and empty-provider contexts.

## Best Possible Solution

Land the fail-closed xAI provider gate only after maintainers accept the missing-provider compatibility behavior and the contributor adds redacted real behavior proof showing xAI tools are hidden for non-xAI or missing-provider tool resolution while still available for xAI models.
