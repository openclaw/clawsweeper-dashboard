## Label Justifications

## Summary

Keep this PR open for maintainer review. The remote-logout fix is well targeted, but the new terminal sentinel changes the meaning of one value that legacy channel adapters are explicitly allowed to return, so an unrelated exact `{ outcome: "terminal" }` result would now silently suppress the established restart policy.

## What This Changes

The PR makes WhatsApp stop restarting after a remotely logged-out Baileys session, presents the account as logged out, and adds a Gateway terminal-exit result for channel adapters.

## System Context

Channel plugins start individual accounts through the Gateway, which monitors exits and applies restart policy. WhatsApp's Baileys monitor feeds connection decisions and health status into that loop, then channel status projects the account state for operators.

## Architecture Diagram

flowchart LR
  A[WhatsApp remote logout] --> B[Baileys connection decision]
  B --> C[WhatsApp channel monitor]
  C --> D[Gateway account start]
  D --> E{Account exit result}
  E -->|ordinary exit| F[Restart policy]
  E -->|terminal exit| G[Stopped logged-out status]
  G --> H[Operator relinks channel]

## Best Possible Solution

Keep the WhatsApp logged-out behavior, but make terminal exit handling explicit and opt-in at the channel-adapter boundary so existing `startAccount` implementations retain their full legacy `unknown` result semantics.
