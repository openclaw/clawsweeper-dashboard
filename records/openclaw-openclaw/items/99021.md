## Summary

Keep open: current main still lets Discord outbound media default to a 100 MB OpenClaw cap, sends caption text and file in one multipart message, and has no Discord-size fallback that preserves the text when the file upload is rejected.

## What This Changes

The issue reports that an oversized Discord outbound attachment can reject the entire agent reply, dropping both the media and text while diagnostics appear successful.

## Best Possible Solution

Add a Discord-owned outbound media failure path that preserves user-visible text, reports the media upload failure clearly, and avoids retrying the same oversized attachment as a full successful delivery.

## Reproduction Assessment

Yes, at source level: current main accepts a 10.7 MB Discord media file under the default 100 MB OpenClaw cap and sends the caption and file in one multipart Discord request. I did not run a live Discord upload in this read-only review.

## Solution Assessment

Yes, the best fix belongs in the Discord outbound send/delivery path rather than a core-wide workaround, because the limit and fallback semantics are channel-specific. The fix should preserve text and failure accounting without adding a new config knob unless maintainers choose one explicitly.
