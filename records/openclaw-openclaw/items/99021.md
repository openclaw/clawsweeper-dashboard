## Summary

Keep open: current main and the latest release still send Discord caption text and non-video media in one all-or-nothing upload, while the candidate fixes are open and unmerged.

## What This Changes

The issue asks Discord oversized media replies to preserve the text fallback and report delivery failure instead of silently completing after HTTP 413.

## Best Possible Solution

Land one canonical Discord-owned fallback that preserves text on oversized media rejection, records the media failure as partial delivery, and closes this issue after proof.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 accept the reported file size under the 100 MB OpenClaw preflight cap and send the caption plus file in one Discord multipart request. I did not run a live Discord upload in this read-only review.

## Solution Assessment

Yes, the right solution is a Discord-owned fallback plus honest partial-delivery accounting. The issue should stay open until one of the candidate PRs lands with proof.
