## Summary

Keep this open: current main and the latest release still have the reported source-level behavior, but changing it would revise an intentionally merged session-takeover safety contract. The best next step is maintainer review of whether the existing broader PR should own the fix.

## What This Changes

The issue requests allowing model fallback to see provider-level timeouts preserved inside an embedded-attempt cleanup takeover wrapper instead of aborting on the wrapper's session-takeover name.

## Best Possible Solution

Maintainers should decide the session-takeover contract, then either land or narrow the promptError-aware path from the open broader session-takeover PR so provider timeouts fall back while pure takeovers still abort.

## Reproduction Assessment

Yes at source level: current main constructs a takeover-named wrapper with `.promptError`, then the fallback classifier returns local coordination before any path can inspect that field. I did not run a live timeout race, but the inspected path matches the reporter's logs.

## Solution Assessment

Unclear until maintainers decide the session-takeover versus provider-fallback contract. The suggested `promptError` unwrapping is a plausible narrow repair, and the open broader PR already explores the adjacent implementation path, but the current abort behavior was intentionally merged for session-state safety.
