## Label Justifications

- `P1`: A configured fallback chain can be bypassed during real main-turn timeouts, breaking a live agent workflow for affected users.
- `impact:session-state`: The timeout is wrapped by embedded session-takeover cleanup state, and the safe behavior depends on that session-state contract.
- `impact:auth-provider`: The issue is about provider/model fallback routing deciding whether to try configured fallback candidates after a timeout.

## Summary

Keep this issue open: current main and the latest release still make takeover-named prompt-error wrappers abort model fallback before `.promptError` can be classified as a provider timeout. The source path is clear, but changing it revisits the session-takeover safety contract that was intentionally merged in https://github.com/openclaw/openclaw/pull/84321 and is also being worked through in https://github.com/openclaw/openclaw/pull/89039.

## What This Changes

The issue requests that main-turn timeouts preserved inside `EmbeddedAttemptPromptErrorWithCleanupTakeoverError.promptError` continue through model fallback instead of being aborted as cleanup/session-takeover coordination errors.

## Best Possible Solution

Maintainers should settle the session-takeover safety contract, then either land or narrow the `promptError`-aware fallback path from https://github.com/openclaw/openclaw/pull/89039 so provider timeouts can fall back while pure takeover errors still abort, or explicitly keep the current takeover-fatal behavior.

## Reproduction Assessment

Yes, at source level: current main constructs a takeover-named wrapper with `.promptError`, and the fallback classifier aborts on the takeover name before inspecting that field. I did not run the live timeout/takeover race in this read-only review.

## Solution Assessment

Unclear. The suggested `promptError` unwrapping is a plausible narrow repair, but current tests encode the opposite takeover-abort contract, so a maintainer should decide the safety boundary before automation changes it.
