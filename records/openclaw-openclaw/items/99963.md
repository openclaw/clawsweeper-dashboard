## Label Justifications

- `P1`: A configured model fallback chain can be bypassed during real main-turn timeouts, breaking a live agent workflow for affected users.
- `impact:auth-provider`: The issue is about provider/model fallback routing deciding whether to try configured fallback candidates after a timeout.
- `impact:session-state`: The timeout is wrapped by embedded session-takeover cleanup state, and the safe handling depends on that session-state contract.

## Summary

Keep this issue open: current main and the latest release still preserve the timeout in `promptError` but then classify the wrapper by its takeover name, so model fallback aborts before the next candidate can run. The fix direction is plausible, but it changes the session-takeover versus provider-fallback contract that was intentionally merged in https://github.com/openclaw/openclaw/pull/84321, so maintainers should decide that contract before implementation.

## What This Changes

The issue requests prompt-error-aware failover classification so main-turn timeout errors wrapped by embedded cleanup takeover handling can continue through the configured model fallback chain.

## Best Possible Solution

Maintainers should decide whether a preserved provider `promptError` should override cleanup-takeover aborts for fallback; if yes, add promptError-aware classification with regressions proving timeout/rate-limit prompt errors fall back while pure takeover errors still abort.

## Reproduction Assessment

Yes, at source level: current main constructs a takeover-named wrapper with `.promptError`, then the fallback classifier returns local coordination before walking that field. I did not run a live timeout race, but the inspected code path matches the reporter's logs.

## Solution Assessment

Unclear until maintainers decide the contract. The suggested `promptError` unwrapping is a plausible narrow repair, but it changes the intentionally merged behavior that takeover-marked provider errors abort fallback.
