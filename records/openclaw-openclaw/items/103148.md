## Summary

Keep this PR open: current `main` still lacks the requested `sessions.create` ownership enforcement, and the patch now appears internally coherent, but the contributor has supplied only Vitest harness evidence rather than an after-fix run through a real loaded plugin runtime and Gateway process.

## What This Changes

The PR adds exact plugin-owner authorization to parent-session creation and takeover paths, rechecks ownership during lifecycle admission, preserves ownership across resets, and consolidates delete authorization into the same helper.

## Best Possible Solution

Adopt one canonical gateway session-ownership authorization contract across create, delete, and patch; require exact owner equality against the authoritative row inside lifecycle admission, preserve ownership on every write/reset path, explicitly approve fail-closed handling for ownerless rows, and prove it with a real loaded-plugin Gateway transcript.
