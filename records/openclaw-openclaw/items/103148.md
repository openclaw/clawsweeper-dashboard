## Summary

Keep this PR open. The patch appears to close a real cross-plugin session-ownership gap with focused regression coverage, but it intentionally fails closed for ownerless legacy parent/target sessions and still lacks proof from a normally loaded plugin calling an authenticated running Gateway. That compatibility/security boundary needs explicit maintainer confirmation before merge.

## What This Changes

The PR forwards a plugin runtime’s authenticated owner identity into Gateway session creation and uses a shared guard to prevent cross-owner parent use, target takeover, reset races, and deletion.

## System Context

Gateway session RPCs create, reset, and delete persisted agent sessions for operator clients and in-process plugin runtimes. A plugin runtime’s owner identity must be checked before session lifecycle operations can read inherited metadata, fork transcripts, or mutate stored session state.

## Architecture Diagram

flowchart LR

  B --> C[Owner identity propagation]
  C --> D[Parent or target authorization]
  D --> E[Lifecycle lock and reset]
  E --> F[Persisted session store]
  F --> G[Create reset or delete response]

## Best Possible Solution

Preserve a single shared owner-equality guard, obtain redacted loaded-plugin Gateway proof for allowed and rejected cases, and land only after an owner explicitly accepts the fail-closed treatment of legacy ownerless sessions.
