## Label Justifications

- `P0`: The reported current-main path allows an authenticated scoped plugin runtime to copy or link another owner's session transcript and metadata, which is a security-boundary bypass.
- `merge-risk: 🚨 compatibility`: Strict equality makes legacy ownerless sessions unusable by plugin-runtime callers without a demonstrated migration or approved breaking-upgrade contract.
- `merge-risk: 🚨 session-state`: The patch changes which plugin may fork, link, reset, overwrite, or delete persisted session rows and therefore can alter established session lineage and reuse behavior.
- `merge-risk: 🚨 security-boundary`: The PR defines a new shared authorization rule for cross-plugin and ownerless session access, so incorrect or inconsistent application would weaken or unexpectedly change the boundary.

## Summary

Keep open. The patch direction is credible and prior line-level findings appear addressed, but merge still requires a human decision on legacy ownerless-session authority, coordination with the overlapping patch PR, genuine runtime proof, and a clean rebase with the failing checks resolved.

## What This Changes

The PR adds a shared gateway session-owner guard, passes authenticated plugin ownership into session creation, preserves ownership across resets, consolidates delete authorization, and expands ownership regression coverage.

## Best Possible Solution

Adopt one canonical exact-owner authorization helper across create, patch, reset, and delete, with an explicit maintainer-approved legacy-ownerless policy, upgrade coverage, and real authenticated Gateway proof before landing.
