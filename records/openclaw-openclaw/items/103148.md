The PR enforces plugin-owner equality when Gateway session creation uses a parent or existing target and persists ownership across create and reset paths.

## Best Possible Solution

## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.99

Full review comments:

- **[P1] Lock ordinary parent links before reauthorizing:** `src/gateway/session-create-service.ts:351-355`
  - body: Moving the reload into `createChildSession` does not close this race because the wrapper below still acquires `runExclusiveSessionLifecycleMutation` only for forks or command hooks. A plain `fork: false` parent link can therefore reload, then consume a parent that is concurrently deleted and recreated. Widen the wrapper to every parent-consuming path.
  - confidence: 0.99
- **[P1] Reauthorize reset ownership inside the reset mutation:** `src/gateway/session-create-service.ts:303-310`
  - body: This owner check runs before `performGatewaySessionReset`, which later acquires its own lifecycle lock and reloads the row without the authenticated plugin owner. A delete and recreate between those steps can reset another plugin's session. Pass expected owner and session identity into the reset service and assert it under that lock.
  - confidence: 0.99
