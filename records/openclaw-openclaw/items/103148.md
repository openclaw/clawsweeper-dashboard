## Label Justifications

- `P0`: The underlying bug crosses a plugin isolation boundary and can expose another session's transcript or let a plugin claim session state it does not own.
- `merge-risk: 🚨 compatibility`: The patch intentionally changes accepted plugin session reuse into fail-closed behavior based on persisted ownership.
- `merge-risk: 🚨 session-state`: The patch changes ownership written to session entries and preserved across creation and reset lifecycle operations.
- `merge-risk: 🚨 security-boundary`: The change governs cross-plugin authorization for transcript, metadata, parent linkage, and existing session targets.

## Summary

Keep this PR open: the exact head still lets a plugin claim an existing ownerless session through explicit-key creation, and the posted after-fix evidence remains test-harness proof rather than a real installed Gateway/plugin-runtime run.

## What This Changes

The PR adds plugin-owner checks to session creation, persists plugin ownership on newly created sessions, and preserves that ownership across session resets.

## Best Possible Solution

Authorize every existing session before applying patches or ownership changes: require exact owner equality for plugin callers, reject ownerless and differently owned targets, and stamp ownership only when the target is genuinely new.
