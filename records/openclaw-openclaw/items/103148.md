## Label Justifications

- `P0`: The reported current behavior permits a write-scoped plugin runtime to read or inherit another plugin's session transcript and metadata, which is a concrete security-boundary bypass.
- `merge-risk: 🚨 compatibility`: Exact fail-closed ownership can stop existing plugin workflows that use legacy ownerless session rows after upgrade.
- `merge-risk: 🚨 session-state`: The patch changes authorization, inheritance, reset, and ownership persistence for parent and target session state.
- `merge-risk: 🚨 security-boundary`: Correctness depends on consistently enforcing authenticated plugin ownership across pre-lock and lifecycle-locked session operations.

## Summary

Keep open: the patch addresses a real cross-plugin session-isolation gap and appears functionally sound, but the external PR still needs live after-fix proof and explicit ownership of the fail-closed legacy-session security boundary before merge.

## What This Changes

The PR threads authenticated plugin ownership into session creation, rejects foreign or ownerless parent and target sessions before and inside lifecycle admission, preserves ownership during reset, and adds regression coverage.

## Best Possible Solution

Use one shared gateway session-owner authorization primitive across create, patch, and delete; enforce it before and inside lifecycle locks, preserve owner metadata on every creation/reset path, and explicitly approve and prove fail-closed handling of legacy ownerless rows.
