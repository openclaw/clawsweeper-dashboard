## Summary

The PR addresses a real cross-plugin transcript-isolation vulnerability and has strong current-head behavior proof, but it remains unmergeable because two parent-consuming paths rely on a stale pre-lock owner snapshot, allowing a delete-and-recreate race to bypass the intended boundary.

## What This Changes

The PR passes plugin runtime ownership into session creation, rejects mismatched parent and existing-target use, stamps ownership on created sessions, preserves it through reset, and adds an ownership scenario matrix.

## Best Possible Solution

Authorize the current parent entry under lifecycle serialization immediately before every reset, link, metadata inheritance, hook, or transcript-fork use, while preserving exact owner equality and establishing an explicit migration or fail-closed policy for legacy ownerless rows.
