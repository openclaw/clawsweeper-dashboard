## Label Justifications

- `P1`: The PR addresses cross-plugin transcript and session-state access in a live gateway workflow, but native plugins share the trusted process boundary so this is not a P0 sandbox bypass.

## Summary

Keep this PR open: current main still lacks the proposed create-side ownership enforcement and no blocking code defect is established, but the current head has no real plugin-runtime Gateway proof, the PR body references a proof test absent from the seven-file diff, and the fail-closed handling of legacy ownerless rows plus coordination with the overlapping sessions.patch PR require explicit maintainer direction.

## What This Changes

The PR propagates authenticated plugin ownership into session creation, enforces exact ownership for parent and target session use, preserves ownership across resets, consolidates delete authorization into a shared helper, and adds regression tests.

## Best Possible Solution

Use one canonical session-owner authorization helper across create, delete, and patch; stamp and preserve pluginOwnerId on every plugin-created generation; reauthorize against the authoritative row inside lifecycle or transaction admission; explicitly approve the ownerless-row upgrade policy; and verify same-owner success plus foreign-owner and ownerless rejection through a real loaded plugin and Gateway with redacted persisted-state evidence.
