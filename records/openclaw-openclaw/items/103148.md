## Summary

The patch is not merge-ready because it closes only one cross-plugin fork case while still allowing plugin runtimes to clone ownerless user/operator sessions and use cross-owner parents without a fork. The linked security issue should remain open with this PR treated as a partial candidate fix.

## What This Changes

The PR passes the caller’s plugin owner into `createGatewaySession`, rejects forks from differently plugin-owned parent sessions, and adds focused gateway regression coverage.

## Best Possible Solution

Authorize every plugin-runtime use of `parentSessionKey` only when the parent session’s normalized `pluginOwnerId` exactly matches the caller, then cover fork, non-fork link, ownerless parent, matching owner, and non-plugin cases with focused and real runtime proof.
