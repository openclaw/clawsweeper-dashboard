## Label Justifications

- `P1`: Cross-plugin session access is a broken Gateway workflow that can expose or mutate another plugin’s persisted session state.
- `merge-risk: 🚨 compatibility`: Plugin runtimes may fail after upgrade when they encounter legacy ownerless rows that were previously usable.
- `merge-risk: 🚨 session-state`: The patch changes authorization and owner persistence for parent, target, creation, and reset session paths.
- `merge-risk: 🚨 security-boundary`: The change defines whether one plugin runtime can access another plugin’s transcripts and session metadata.

## Summary

This remains necessary security hardening: current `main` does not contain the new shared ownership helper or equivalent `sessions.create` enforcement. The branch has focused regression coverage and green CI, but merge should wait for a gateway/session owner to confirm the intentional fail-closed behavior for legacy ownerless rows, coordinate the overlapping patch authorization work, and receive real loaded-plugin proof rather than helper-driven tests alone.

## What This Changes

The PR passes authenticated plugin ownership into Gateway session creation, rejects a plugin using another owner’s parent or existing target session, preserves owner metadata on reset, and shares the authorization check with session deletion.

## System Context

Gateway session RPCs create, reset, and delete persisted agent sessions. An authenticated plugin runtime supplies its owner identity to the Gateway, which must prevent that plugin from reading, inheriting, replacing, or mutating another plugin’s session state.

## Architecture Diagram

flowchart LR
  A[Plugin runtime request] --> B[Gateway session RPC]
  B --> C[Authenticated plugin owner]
  C --> D[Parent and target ownership checks]
  D --> E[Lifecycle reset or creation]
  E --> F[Persisted session entry]
  F --> G[Gateway response]

## Best Possible Solution

Adopt one canonical Gateway session-owner authorization helper across create, reset, delete, and patch; retain a deliberately fail-closed policy unless maintainers approve a safe, explicit migration for legacy rows; then add redacted loaded-plugin Gateway proof showing foreign access rejection and own-session success.
