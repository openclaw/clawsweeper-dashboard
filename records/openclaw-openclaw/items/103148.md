## Label Justifications

- `P0`: Current behavior permits one write-scoped plugin runtime to read or inherit another plugin's session transcript and metadata, constituting a concrete authorization bypass.
- `merge-risk: 🚨 compatibility`: Exact equality intentionally rejects legacy ownerless rows and can stop previously working plugin-runtime session operations after upgrade.
- `merge-risk: 🚨 session-state`: The patch changes ownership propagation and authorization across parent linkage, takeover, reset, and delete paths where inconsistency could strand or mis-associate session state.
- `merge-risk: 🚨 security-boundary`: The diff establishes a plugin-to-plugin transcript and metadata isolation boundary whose correctness depends on authenticated owner propagation and lifecycle-time rechecks.

## Summary

The current head appears to resolve the previously identified code defects and implements the missing plugin-session ownership checks. It still needs a maintainer decision on fail-closed legacy ownerless sessions, coordination with the same-root `sessions.patch` PR, and real deployed Gateway/plugin-runtime proof rather than another Vitest request harness.

## What This Changes

The PR passes authenticated plugin ownership into session creation, enforces exact ownership for parent use and target takeover, preserves ownership across resets, consolidates delete authorization, narrows mismatch error handling, and adds regression coverage.

## Best Possible Solution

Adopt one canonical gateway session-owner authorization contract across create, reset, delete, and patch, fail closed on ownerless rows only with explicit owner approval, and land it after redacted live proof from two normally loaded plugins against a running Gateway.
