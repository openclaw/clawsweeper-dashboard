## Label Justifications

- `P0`: The reported pre-fix behavior allows one plugin runtime to clone another owner's full transcript, which is a concrete security-boundary bypass.
- `merge-risk: 🚨 compatibility`: Exact equality intentionally rejects legacy ownerless rows and can stop existing plugin parent/reset or explicit-target workflows after upgrade.
- `merge-risk: 🚨 session-state`: The patch changes ownership persistence and lifecycle admission across creation, reset, parent linking, and existing-session replacement paths.
- `merge-risk: 🚨 security-boundary`: The merge defines which authenticated plugin runtime may read, fork, link, reset, or replace sessions, so incomplete coverage could preserve or create an isolation gap.

## Summary

This PR remains necessary: it closes a demonstrated cross-plugin transcript and session-metadata authorization gap, and the latest head addresses the prior reset-error regression. The implementation is directionally correct and proof-positive, but the ownerless-row upgrade policy, the failing LOC-ratchet check, and untested cross-store behavior need maintainer-visible resolution before merge.

## What This Changes

The branch propagates authenticated plugin ownership into session creation, enforces exact ownership for parent and existing-target use, reauthorizes parent ownership under lifecycle locks, preserves ownership during reset, and adds gateway regression coverage.

## Best Possible Solution

Keep the exact-owner rule at the session service boundary, reauthorize it inside every lifecycle mutation, persist ownership on every creation/reset path, fail closed on unattributable ownerless rows with explicit maintainer approval, and land with focused cross-store coverage plus a clean LOC-ratchet result.
