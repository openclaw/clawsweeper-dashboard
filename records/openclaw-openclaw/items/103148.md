## Label Justifications

- `P0`: The underlying current-main bug permits cross-plugin transcript disclosure through a core gateway session operation.
- `merge-risk: 🚨 session-state`: The patch can make newly created child sessions unusable by their creator because their persisted ownership is left unset.
- `merge-risk: 🚨 security-boundary`: The change enforces cross-plugin authorization but does not preserve the ownership identity needed for later authorization decisions.

## Summary

Keep open: the security hardening is necessary, but the patch leaves newly created plugin sessions ownerless, so the creating plugin can be denied when it later reuses or deletes its own child. The previous parent-authorization findings are fixed; this is a late finding on the unchanged exact head.

## What This Changes

The PR passes the plugin runtime owner into session creation, rejects parent-session use unless ownership matches exactly, and adds seven authorization scenarios covering fork and non-fork creation.

## Best Possible Solution

Normalize the caller owner once, authorize the exact parent against it, persist it as the new child's `pluginOwnerId`, and prove that the creator can reuse and delete the child while foreign plugins cannot.
