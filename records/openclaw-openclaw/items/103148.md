## Label Justifications

- `P0`: The underlying bug permits a plugin runtime to cross a session-isolation boundary and access or acquire state it does not own.
- `merge-risk: 🚨 compatibility`: The patch introduces fail-closed behavior for ownerless parent sessions that legacy plugin workflows may currently use.

- `merge-risk: 🚨 security-boundary`: The patch controls cross-plugin access to session transcripts, metadata, and ownership but still leaves target takeover branches open.

## Summary

Keep open: the exact head still permits a plugin caller to acquire an existing session through uncovered target-creation branches, so the security boundary is not yet complete; required real-runtime proof is also missing.

## What This Changes

The PR adds plugin-owner authorization for parent and target sessions, persists ownership on newly created sessions, and preserves ownership across session resets.

## Best Possible Solution

Use the storage callback's pre-mutation `existingEntry` to authorize every existing target before patching, forking, resetting, or assigning ownership; reject both ownerless and differently owned targets for plugin callers, stamp ownership only on genuinely absent targets, and prove fresh and legacy behavior through a real Gateway with two installed plugin runtimes.
