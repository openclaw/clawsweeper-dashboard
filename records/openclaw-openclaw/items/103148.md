## Label Justifications

- `P0`: Current behavior permits a write-scoped plugin runtime to cross a plugin ownership boundary and potentially copy another session's transcript.
- `merge-risk: 🚨 compatibility`: The new fail-closed rule can stop existing plugin workflows that use foreign or legacy ownerless sessions as parents.
- `merge-risk: 🚨 session-state`: The patch changes session parent admission, target takeover, and persistence of pluginOwnerId across creation and reset.
- `merge-risk: 🚨 security-boundary`: Correctness determines whether one plugin runtime can read or inherit another plugin's session transcript and metadata.

## Summary

Keep open: this addresses a valid P0 cross-plugin authorization gap, but the current head introduces a second session-ownership policy alongside the existing delete guard and still lacks after-fix proof from a real plugin-runtime Gateway setup.

## What This Changes

The PR adds plugin-runtime owner checks to session creation and reset paths, persists owner metadata, narrows mismatch error handling, and adds ownership regression coverage.

## Best Possible Solution

Use one shared owner-equality authorization helper across create, reset, patch, and delete, enforce it both before and inside lifecycle admission, preserve pluginOwnerId on every canonical write path, and prove same-owner success plus foreign and ownerless rejection through a real plugin-runtime Gateway transcript.
