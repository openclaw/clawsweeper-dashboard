## Summary

The stale-claim diagnosis is valid, but this PR should stay open because the new outer `status !== "done"` guard also exempts genuinely running executions after an operator moves their card to done, violating the stated owner-capacity invariant.

**Likely related people**
- @RomneyDa — high-confidence recent Workboard lifecycle contributor based on merged stale-lifecycle work.

## What This Changes

The PR changes Workboard owner-capacity accounting to ignore done cards and adds a store-backed regression showing a retained claim no longer blocks the next ready card.

## Best Possible Solution

Count a running card or running execution regardless of card status, ignore only a claim attached to a done card, and add paired regressions for stale-claim release and live-execution capacity before supplying a redacted live dispatch transcript.
