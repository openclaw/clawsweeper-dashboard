## Summary

This PR remains necessary, but the exact head is not safe to merge: it fixes unbounded chat-history decoding by embedding a chat-specific size ceiling in a decoder also used by workspace previews.

## What This Changes

This PR bounds Android structured chat images before decoding, centralizes the 300 KiB chat-image constant, and syncs generated native i18n metadata.

## Best Possible Solution

Keep early structured-chat rejection, but make image decode limits caller-owned: chat and Markdown should use 300 KiB while workspace previews retain their existing gateway payload allowance.

Yes from source inspection: structured history images reach Android's decoder without the chat budget on current main, and the PR adds focused 307,201-character boundary tests. No live device reproduction was provided.

## Solution Assessment

No. Parser-level bounding is the right fix boundary, but an unconditional limit in the shared decoder is broader than the reported bug and regresses workspace previews; the maximum should be caller-specific.
