## Summary

Keep open as a narrow installation-documentation defect. Current documentation still presents bare global npm installation, while npm 11 documents `--allow-scripts` as the global-install mechanism and its project-oriented approval suggestion cannot repair a global install; however, current OpenClaw packaging no longer relies on postinstall to eagerly install bundled-plugin dependencies, so the reported missing staging is not itself a confirmed runtime failure.

## What This Changes

Clarify the documented npm global-install path for npm 11+ so users can make the required lifecycle-script approval decision instead of receiving an unusable global-install warning.

## System Context

The installation guide sends users to a global npm install, where npm decides whether package lifecycle hooks can run. OpenClaw’s packaged postinstall now cleans and validates packaged plugin state rather than eagerly installing plugin dependencies, and the resulting package is then used by the CLI and Gateway.

## Best Possible Solution

Add npm 11+ guidance to the public installation page after a clean global-install and upgrade proof identifies the minimal reviewed allowlist; state plainly whether users must allow the OpenClaw hook for a supported install or whether the warning can safely be ignored for a particular path.
