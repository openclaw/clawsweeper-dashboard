## Label Justifications

- `impact:session-state`: The affected path is persisted compaction-count bookkeeping after successful auto-compaction.

- `maturity:stable`: The issue affects M4 Stable runtime and CLI packaging surfaces from the maturity shortlist, including gateway-runtime and cli-install-update-onboard-doctor.

## Summary

Keep open: current main and v2026.6.11 still emit wildcard-only runtime aliases while the compaction path lazy-imports a default-only helper; the linked open PR is the right implementation path and the issue should close only after that or an equivalent fix merges.

## What This Changes

The issue reports that stable runtime aliases use wildcard-only re-exports, dropping default exports needed by post-compaction bookkeeping after auto-compaction.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99678 or an equivalent generator fix that forwards default exports only when the target chunk actually has one, with regression coverage for default-only runtime chunks.

## Reproduction Assessment

Yes. Source-level reproduction is high confidence: current main emits wildcard-only runtime aliases, the compaction handler imports default through that alias, the runtime helper exports default, and a Node ESM probe confirms wildcard re-exports omit default.

## Solution Assessment

Yes. The best fix boundary is the alias generator because the caller and runtime helper agree on a default export, and the generated alias is the layer dropping it; the linked PR targets that boundary.
