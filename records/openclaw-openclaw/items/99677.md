## Label Justifications

- `impact:session-state`: The affected path is persisted compaction-count bookkeeping after successful auto-compaction.

## Summary

Keep open: current main and v2026.6.11 still emit wildcard-only runtime aliases, while the compaction path default-imports a default-only runtime helper; the linked fix PR is open and should remain the implementation path until merged.

## What This Changes

The issue asks for generated stable and legacy runtime aliases to preserve default exports from hashed runtime chunks so post-compaction count reconciliation can persist.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99678 or an equivalent runtime-postbuild generator fix that forwards default exports only when the target chunk actually has one, with regression coverage for default-only chunks.

## Reproduction Assessment

Yes for source-level reproduction: current main emits wildcard-only runtime aliases, the compaction handler imports default through that alias, and a no-file Node ESM probe confirms wildcard re-exports omit default. I did not run a packaged live compaction scenario.

## Solution Assessment

Yes, the best fix boundary is the alias generator because the caller and runtime helper agree on a default export and the generated alias is the layer dropping it. The linked PR targets that boundary, so this issue should stay open until that fix or an equivalent one merges.
