## Label Justifications

- `P1`: A lost subagent completion announce can park a parent session indefinitely and block queued user messages in active multi-agent workflows.
- `impact:session-state`: The reported failure leaves the requester session stuck in yielded/processing state and may make the persisted transcript unresumable.

## Summary

Keep open: current main still has retry-limit/expiry give-up paths that mark or suspend failed subagent completion delivery without a requester-visible wake, and current stable comments confirm the failure still affects real deployments. Open PRs and the durable-queue design issue are relevant candidate paths, but nothing has merged that fully closes this issue.

## What This Changes

The issue asks OpenClaw to wake a parent waiting in `sessions_yield` when subagent completion announce delivery gives up, and separately proposes configurable retry limits, delays, and expiry.

## Best Possible Solution

Land or replace a bounded requester-wake fix that also closes the parent transcript/tool-result pairing on retry-limit or expiry give-up, then decide durable queue and retry-config knobs separately.
