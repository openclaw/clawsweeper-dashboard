## Label Justifications

- `P1`: The issue reports real multi-subagent workflows where a parent session parks indefinitely and queued user messages wait behind it.
- `impact:session-state`: The failure leaves the parent session stuck in yielded/processing state or potentially malformed after a dropped completion handoff.

## Summary

Keep open: current main still has retry-limit/expiry give-up paths that mark subagent completion delivery failed or blocked without a guaranteed requester wake, and multiple open candidate PRs/design threads now own parts of the fix.

## What This Changes

The issue requests that subagent announce retry-limit or expiry give-up wake the parent waiting in `sessions_yield` with a synthetic failure/completion event, plus asks to make announce retry and expiry limits configurable.

## Best Possible Solution

Review and land or replace the focused requester-wake fixes, especially https://github.com/openclaw/openclaw/pull/95080, while deciding retry/expiry configurability as a separate product/config question.

Yes at source level: current main still reaches retry-limit/expiry give-up, records failed/blocked delivery, and suppresses non-cancelled subagent terminal task delivery before a guaranteed requester wake. I did not run the timing-sensitive live Signal/K8s scenario in this read-only review.

## Solution Assessment

Yes for the narrow bug: announce give-up should close the requester-visible completion/tool-result contract instead of silently stranding the parent. No for automatically bundling retry/expiry config knobs, because that adds public config surface and needs maintainer direction.
