## Label Justifications

- `P1`: The bug can leave real parent sessions stuck indefinitely with queued user messages behind them in multi-subagent workflows.
- `impact:session-state`: A yielded parent session can remain parked or become unresumable after the child completion give-up path.
- `impact:message-loss`: The child completion/failure event can be marked failed or blocked without a requester-visible wake event.

## Summary

Keep open: current main and v2026.6.11 still have retry-limit/expiry give-up paths that mark subagent delivery failed/blocked while non-cancelled subagent terminal task delivery remains suppressed, so a yielded requester can still miss the wake. The open fix path is https://github.com/openclaw/openclaw/pull/95080, with broader durability tracked in https://github.com/openclaw/openclaw/issues/94153.

## What This Changes

The issue requests that subagent announce retry-limit/expiry give-up wake a requester waiting in `sessions_yield` with a synthetic failure/completion event, plus a possible public retry/expiry configuration surface.

## Best Possible Solution

Land a narrow give-up recovery that queues a requester-visible blocked completion/tool-result wake, then decide separately whether durable announcement queues or retry/expiry config belong in a follow-up.
