## Summary

Keep open: the patch addresses the direct cron service path, but the production gateway starts with the lazy cron state, so the first real hot reload would still cancel the loaded watcher and rebuild from no preserved watcher state. The PR also lacks after-fix real behavior proof beyond test and lint commands.

## What This Changes

This PR reuses cron on-exit watcher managers across cron hot reload, refreshes callbacks, and adds gateway cron/reload watcher regression tests.

## Best Possible Solution

Forward or unwrap the loaded lazy cron state so hot reload can stop only scheduling, reuse the existing watcher manager, refresh handlers, and then reconcile removed or changed jobs.

## Reproduction Assessment

Yes, at source level: current main maps cron.* changes to restart-cron and the production lazy cron wrapper cancels the loaded watcher on stop. I did not run a live config-file hot reload during this read-only review.

## Solution Assessment

No. Reusing the watcher manager is the right fix shape, but this implementation is incomplete because it does not carry the existing loaded watcher manager through createLazyGatewayCronState, which is the production startup path.
