## Summary

Keep open: this is a focused bug-fix PR, but it is not merge-ready because the production gateway stores cron behind a lazy proxy, and the new watcher handoff only works for direct cron states. The first real hot reload after startup can still cancel active on-exit watchers, and the PR also lacks after-fix real behavior proof.

## What This Changes

The PR changes gateway cron hot reload to reuse on-exit watcher state, refresh watcher callbacks, and add focused regression tests around watcher reuse.

## Best Possible Solution

Expose or transfer loaded exit watcher state through the lazy gateway cron wrapper, add a regression test for the real startup shape, and provide redacted real gateway hot-reload proof.

## Reproduction Assessment

Yes. Source inspection and the linked issue show the current-main reload path cancels and rebuilds on-exit watchers; I did not run a live gateway repro in this read-only review.

## Solution Assessment

No, not yet. Preserving watcher state is the right fix shape, but it must cover the lazy GatewayCronState used by production startup, not only direct buildGatewayCronService states.

- **[P1] Preserve watchers through the lazy cron state:** `src/gateway/server-reload-handlers.ts:478`
  - body: Production startup stores cron as `createLazyGatewayCronState`, whose returned state does not expose `exitWatchers` or `stopCronForHotReload`; once loaded, its `cron.stop()` still cancels the hidden watcher manager.
