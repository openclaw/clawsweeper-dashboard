## Summary

Keep open: the PR is the right candidate for the linked cron hot-reload bug, but it still preserves active on-exit watchers during a same-store `cron.enabled=false` reload until async reconciliation cancels them, leaving a narrow window where a disabled cron job can still fire.

## What This Changes

The PR reuses same-store gateway cron on-exit watcher managers across hot reloads, refreshes callbacks in rebuilt cron services, cancels on store changes, and adds focused regression tests.

## Best Possible Solution

Preserve watchers only for same-store reloads where the next cron state remains enabled; cancel synchronously for store changes, cron disable, shutdown, and then land with focused regression coverage.
