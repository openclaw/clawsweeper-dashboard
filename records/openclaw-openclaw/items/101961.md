## Summary

Keep open: current main includes the merged `node_exec` dynamic tool, but it is only exposed when the effective Codex exec host is already `node`; the issue asks for a mixed-session local-default lane with a separate approved node-exec surface and structured stale-node failure semantics.

## What This Changes

Request a first-class scoped way for Telegram/Codex agent lanes to run approved shell commands on a paired node while local exec remains the default and stale nodes fail softly.

## Best Possible Solution

Define a maintainer-approved secondary node exec dynamic tool or binding that pins host/node internally for trusted sessions, preserves local Codex native exec as default, reuses existing approvals/audit policy, and returns structured retryable node-unavailable results for stale nodes.
