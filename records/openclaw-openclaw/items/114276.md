## Summary

This PR remains necessary as the open candidate fix for the linked Gateway restart problem. Its focused tests and real-process boundary proof support the intended distinction, but the change deliberately reduces restart-driving severity for existing deployments that set an explicit Node heap limit, so a Gateway-area maintainer should explicitly accept that operational tradeoff before merge.

## What This Changes

The PR makes Gateway heap-pressure thresholds scale with V8’s heap limit for direct operator heap overrides, while preserving the legacy 1 GiB warning and 2 GiB critical thresholds for managed resource-derived heap sizing.

## System Context

The managed Gateway derives a Node V8 heap limit from available memory and emits diagnostic memory-pressure events from sampled process memory. Those events feed stability and restart handling, so the threshold policy determines when an active Gateway is considered critical.

## Best Possible Solution

Preserve fixed thresholds for managed resource-derived Gateway heaps, scale only demonstrably operator-controlled heap limits, and land the change after a Gateway owner accepts the resulting restart-policy change for explicit overrides.
