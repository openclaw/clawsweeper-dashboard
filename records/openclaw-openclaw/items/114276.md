## Summary

This PR addresses the reported false-critical condition for an explicitly enlarged V8 heap and includes credible after-fix runtime evidence, but it still changes restart-driving defaults for any environment whose resource-derived V8 limit exceeds 4 GiB. The current implementation has no boundary that distinguishes an operator-configured enlarged heap from an automatically larger Node/V8 default, so the prior P1 compatibility finding remains unresolved.

## What This Changes

The PR replaces fixed diagnostic heap warning and critical defaults with floors that scale to 25% and 50% of V8’s reported heap limit, and adds regression tests for constrained, 4 GiB, and 8 GiB heap-limit cases.

## System Context

OpenClaw’s diagnostic memory sampler receives process memory measurements, resolves pressure thresholds, and emits warning or critical events to the diagnostic and stability paths. Those events can drive gateway drain-and-restart behavior, so threshold defaults affect running deployments as well as diagnostics.

## Best Possible Solution

Define the supported compatibility boundary for adaptive heap thresholds, preserve the established thresholds for resource-derived defaults unless maintainers intentionally approve a behavior change, and add focused coverage for both automatic and explicitly configured large-heap modes before merge.
