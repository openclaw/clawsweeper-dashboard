## Summary

Keep open: current main still lacks the requested generic web-tool domain allow/deny egress firewall. The low-level SSRF matcher can enforce hostname allowlists, but `web_fetch` only exposes narrow fake-IP proxy SSRF flags, Codex-native `allowedDomains` is a separate hosted-search-only path, the earlier `tools.web.urlAllowlist` merge was reverted, and the active PRs are partial or competing direction-setting work rather than merged replacements.

## What This Changes

Request to add config-level `allowedDomains`/`denyDomains` network egress controls for OpenClaw web tools such as `web_fetch` and `web_search`.

## Best Possible Solution

Keep this issue as the canonical web-tool egress-policy tracker until maintainers choose one public contract and land schema, runtime enforcement, cache/provider fallback behavior, search/fetch scope, docs, audit, and upgrade behavior around that contract.

## Reproduction Assessment

No high-confidence bug reproduction is needed because this is a feature request, not a broken documented behavior. Source inspection does confirm the reported gap: current main lacks a generic web_fetch/web_search domain allow/deny policy.

## Solution Assessment

Unclear. Reusing `SsrFPolicy.hostnameAllowlist` is plausible for direct `web_fetch`, but the best final solution needs maintainer-approved scope across fetch, search, redirects, cache isolation, provider fallback, proxy routing, docs, and audit behavior.
