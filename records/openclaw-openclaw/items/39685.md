## Summary

Keep open: current main and the latest release still lack a generic operator-controlled allow/deny domain firewall for `web_fetch` plus managed `web_search`; the related PRs are open, draft/conflicting, and cover different partial security-boundary choices.

## What This Changes

The issue requests operator-controlled outbound network allow/deny domain policy for web tools, especially `web_fetch` and managed `web_search`.

## Best Possible Solution

Define a maintainer-approved web egress security contract, then land schema, runtime enforcement, cache/provider-fallback behavior, docs, audit output, and upgrade handling around that contract.

## Maintainer Decision

Question: What should own OpenClaw's public web-tool egress boundary: a scoped `web_fetch` policy, a cross-tool search/fetch/browser policy, or managed-proxy-owned egress?

Rationale: This is a public security/config surface that users will treat as an exfiltration boundary, and the currently open implementation directions choose different guarantees.

Likely owner: Peter Steinberger

Owner reason: Peter Steinberger has the strongest feature-history connection to the SSRF guard and hostname allowlist primitive that any native policy would extend.

Owner confidence: medium

Options:

- **Sponsor Scoped web_fetch First (recommended):** Use the narrow hostname-allowlist PR direction as the first contract while leaving denied domains, managed search, browser, and proxy behavior as explicit follow-up work.
- **Design Shared Egress Policy:** Pause narrow knobs until maintainers define one cross-tool policy for fetch, search, browser, providers, redirects, caches, and proxy routing.
- **Delegate To Managed Proxy:** Make `proxy.enabled` plus external operator policy the supported egress boundary instead of adding local domain firewall knobs to web tools.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a new security/config capability. Source inspection confirms current main and `v2026.6.11` lack generic allowed/denied domain policy for `web_fetch` and all managed `web_search` paths.

## Solution Assessment

Unclear until maintainers set the boundary. `SsrFPolicy.hostnameAllowlist` is a good primitive for direct `web_fetch`, but deny semantics and coverage across search, redirects, cache, provider fallback, browser, and proxy paths need approval.
