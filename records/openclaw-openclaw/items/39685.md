## Summary

Keep open: current main still lacks a generic web-tool domain allow/deny egress firewall, and the related implementation/proxy directions are open security-boundary decisions rather than merged replacements.

## What This Changes

The issue requests configurable domain allow/deny controls for agent web egress so operators can restrict `web_fetch` and related web search/fetch paths to approved destinations.

## Best Possible Solution

Define one maintainer-approved web egress contract, then land schema, runtime guard wiring, cache/provider-fallback behavior, audit/docs, and upgrade handling around that contract.
