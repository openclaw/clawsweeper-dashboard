## Summary

Keep open for explicit maintainer direction. This is a bounded but cross-boundary feature proposal: it changes ClickClack discussion presentation and proposes a new gateway-event facade, while the issue carries the protected `maintainer` label.

## What This Changes

Add human-readable ClickClack discussion channel names based on session titles, with collision handling, title generation when opening a discussion, and faster rename reconciliation.

## System Context

ClickClack’s discussion service maps OpenClaw session metadata into workspace discussion channels shown in the ClickClack sidebar. Session titles and gateway session-change notifications would feed label selection and synchronization, which then affects how operators identify active discussions.

## Architecture Diagram

flowchart LR
  A[OpenClaw session metadata] --> B[Session title and label fields]
  B --> C[ClickClack discussion service]
  D[Session change events] --> C
  C --> E[Channel naming and collision handling]
  E --> F[ClickClack workspace sidebar]
  F --> G[Operator navigation]

## Best Possible Solution

Approve a narrowly scoped design in which ClickClack owns naming and reconciliation, while core exposes a generic documented session-change seam only if an existing plugin-facing event path cannot meet the need; retain a readable deterministic fallback when title generation is unavailable.
