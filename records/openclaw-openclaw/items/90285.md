## Summary

Keep open: current main still exposes internal `runningAtMs` reservation and process-local active markers, but not a public cron claim/lease, CAS remove, claim-aware exit code, or documented dispatch/removal precondition contract.

## What This Changes

The issue requests an additive public cron claim/lease, compare-and-set remove, or enforced single-flight dispatch contract so external code can safely retire jobs during concurrent dispatch.

## Best Possible Solution

Choose one additive cron precondition contract, then align the Gateway schema, CronService result types, CLI flags/help, docs, and focused concurrency tests around that contract.
