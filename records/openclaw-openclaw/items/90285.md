## Summary

Keep open: current main and v2026.6.11 still expose an id-only `cron.remove` path plus an internal `runningAtMs` reservation, but not the requested public claim/lease, CAS remove, claim-aware exit code, or documented single-flight contract.

## What This Changes

The issue requests an atomic cron dispatch/removal primitive: lease-aware claiming, compare-and-set removal, or an enforced single-flight dispatch contract.

## Best Possible Solution

Choose one additive cron precondition contract, then align Gateway schema, service result types, CLI flags/help, docs, and focused concurrency tests around that contract.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Which public cron concurrency contract should OpenClaw support for dispatch/remove races: full lease tokens, compare-and-set removal, or an internal single-flight guarantee with documentation?

Rationale: The implementation gap is clear, but the durable API shape, conflict exit code, caller retry behavior, and whether a lease token should become part of wake payloads require maintainer product/API intent.

Likely owner: steipete

Owner reason: The central current-main cron remove, timer, and Gateway schema history points to steipete as the best available owner for the API direction choice.

Owner confidence: high

Options:

- **Add narrow CAS/remove preconditions (recommended):** Add an `--if-unclaimed` or expected-version remove path with a documented conflict result before considering a broader lease-token payload contract.
- **Design full lease tokens:** Expose dispatch claims with token, holder, expiry, revocation behavior, and wake-payload validation for callers that need strict in-flight authority.
- **Document internal single-flight only:** Keep the public remove surface small and instead enforce and document non-overlap/dropped-wake semantics if maintainers do not want a caller-visible claim API.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a feature/API request. Source inspection gives high confidence that current main lacks the requested public claim, lease, CAS, and documented conflict-exit contract.

## Solution Assessment

Unclear until maintainers choose the public contract. A narrow additive CAS or `--if-unclaimed` remove path looks smaller than a full lease-token system, but either path is an API/product decision.
