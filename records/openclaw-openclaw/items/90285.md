## Summary

Keep open: current main and v2026.6.11 still expose unconditional cron removal, plus internal `runningAtMs` reservation, but not the requested public claim/lease, CAS remove, conflict exit code, or documented single-flight contract.

## What This Changes

Request an additive public cron claim/lease, CAS remove, or single-flight dispatch contract so external automation can retire jobs without dispatch/remove races.

## Best Possible Solution

Choose one additive public cron precondition contract, then align the Gateway schema, service result type, CLI flags/help, docs, and focused dispatch/remove concurrency tests around it.

Question: Which public cron concurrency contract should OpenClaw expose for safe removal during or around dispatch?

Rationale: The remaining work is not a narrow bug patch; it creates public RPC, CLI, exit-code, and possibly persisted-state semantics that maintainers need to own before implementation.

Likely owner: steipete

Owner reason: Recent cron Gateway schema/service work makes this the most direct API/product routing owner from the inspected history.

Owner confidence: medium

Options:

- **Add narrow CAS/if-unclaimed remove (recommended):** Add an explicit precondition flag or version check to `cron.remove`/`cron rm`, return a distinct conflict result/exit code, and leave full lease-token state out unless later needed.
- **Add full claim/lease tokens:** Expose claim token, holder, and expiry state across show/remove/run payloads, accepting a larger public data model for stronger external coordination.
- **Document internal single-flight only:** Treat `runningAtMs` as an internal scheduler guarantee and document what `cron rm` can and cannot promise without exposing a new removal precondition.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a feature/API request. Source inspection of current main and v2026.6.11 confirms the requested public claim/lease/CAS fields, CLI flags, and documented exit-code contract are absent.

## Solution Assessment

Unclear until maintainers choose the public contract. A narrow additive CAS or `--if-unclaimed` remove path appears smaller than a full lease-token system, but either choice is an API/product decision.
