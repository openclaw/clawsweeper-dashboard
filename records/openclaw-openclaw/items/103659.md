## Summary

The issue remains necessary because current main has no scoped Tool Search setting and no exact canonical item owns the request. The implementation boundary is clear, but maintainers must choose whether the durable contract is agent-scoped, capability-driven, or a full agent/provider precedence matrix.

## What This Changes

Add per-agent and per-provider overrides for the global Tool Search mode and tuning settings.

## Best Possible Solution

Add a centralized agent-first Tool Search resolver that inherits the global setting, permits a full per-agent override, and adds provider/model scope only if maintainers confirm a provider-wide requirement; automatic selection should use explicit capability metadata.

## Reproduction Assessment

Yes for the central configuration limitation: current types, schema, and docs show Tool Search is global-only. The specific `glm-4.7-flash` silent-action behavior has not been independently reproduced on current main, so that symptom remains medium-confidence.

## Solution Assessment

Not conclusively; the requested full matrix is plausible but broader than necessary. An agent-first override through the existing centralized resolution boundary is the narrowest maintainable starting point, with explicit capability metadata as the safer automatic alternative.
