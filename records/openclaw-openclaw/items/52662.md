## Summary

Keep open. Current main and v2026.6.11 still use a Docker-managed sandbox-browser lifecycle, and external CDP/noVNC support remains a security-sensitive sandbox/browser API decision rather than implemented or fully owned by the broader browser-backend issue.

## What This Changes

The issue requests external CDP/noVNC endpoints so sandbox browser automation can use an externally managed browser without requiring Docker lifecycle control.

## Best Possible Solution

Define a maintainer-approved sandbox-browser backend or external-endpoint contract that preserves CDP auth, SSRF checks, noVNC observer-token handling, lifecycle semantics, docs, and regression coverage.

## Reproduction Assessment

Yes, at source level: current main still routes sandbox browser setup through Docker lifecycle and rejects sandbox browser for backends that do not advertise browser capability. I did not run a live Kubernetes, Docker Compose, or external CDP sidecar deployment in this read-only review.

## Solution Assessment

Unclear as proposed. Optional endpoint fields are a plausible unblocker, but the best fix needs maintainer agreement on backend ownership, auth, SSRF/noVNC policy, and config contract rather than a one-off shortcut.
