## Summary

Keep open. Current main and the latest release still use a Docker-managed sandbox-browser lifecycle, and the requested external CDP/noVNC endpoint support remains a security-sensitive product/API decision rather than implemented or fully covered by broader browser-driver work.

## What This Changes

Request external CDP/noVNC endpoint support so sandbox browser automation can use non-Docker, externally managed browser backends.

## Best Possible Solution

Define one maintainer-approved sandbox-browser backend or endpoint contract that supports externally managed browsers while preserving CDP auth, SSRF policy, noVNC observer tokens, lifecycle semantics, docs, and tests.

## Reproduction Assessment

Yes, at source level. Current main lacks the requested sandbox-browser external endpoint fields and routes `ensureSandboxBrowser` through Docker lifecycle, but I did not run a live Kubernetes, Docker Compose, or external CDP sidecar deployment in this read-only review.

## Solution Assessment

Unclear as proposed. Optional endpoint fields are a plausible unblocker, but the best fix needs maintainer agreement on backend ownership, auth, SSRF/noVNC policy, and config contract rather than a one-off shortcut.
