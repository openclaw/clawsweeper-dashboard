## Summary

Keep open. Current main and v2026.6.11 still run the sandbox browser through a Docker-managed container lifecycle, and the requested external CDP/noVNC endpoint path is not implemented or safely superseded.

## What This Changes

Add sandbox browser support for externally managed CDP/noVNC endpoints so non-Docker or containerized deployments do not need OpenClaw to manage a Docker browser container.

## Best Possible Solution

Design a maintainer-approved sandbox browser endpoint/backend contract, ideally aligned with the broader browser backend plugin work, then implement it with explicit security controls, config schema/docs, and focused sandbox browser tests while preserving the current Docker default.

## Reproduction Assessment

Yes. Source inspection is enough to reproduce the gap: the sandbox browser config and runtime path only support Docker-managed browser containers and Docker-published CDP/noVNC ports.

## Solution Assessment

Unclear. The proposed endpoint fields are a plausible minimal unblocker, but the best fix needs maintainer choice on whether this should be a narrow endpoint config or a more general browser backend/plugin contract with security review.
