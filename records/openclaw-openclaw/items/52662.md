## Summary

Keep open. Current main and v2026.6.11 still use a Docker-managed sandbox-browser lifecycle, the sandbox browser schema has no external CDP/noVNC endpoint fields, and the related browser-backend issue is broader rather than a replacement for this sandbox lifecycle/security contract.

## What This Changes

Request support for externally managed sandbox-browser CDP/noVNC endpoints so containerized deployments can avoid requiring Docker daemon access for browser automation.

## Best Possible Solution

Define a maintainer-approved sandbox-browser backend or endpoint contract that supports externally managed browsers while preserving CDP auth, SSRF policy, noVNC observer tokens, lifecycle semantics, docs, and tests.

## Reproduction Assessment

Yes, at source level. Current main still routes sandbox browser setup through Docker lifecycle and rejects browser support for backends without browser capability; I did not run a live Kubernetes, Docker Compose, or external CDP sidecar deployment in this read-only review.

## Solution Assessment

Unclear as proposed. Optional endpoint fields are a plausible unblocker, but the best fix needs maintainer agreement on backend ownership, auth, SSRF/noVNC policy, and the config contract rather than a one-off shortcut.
