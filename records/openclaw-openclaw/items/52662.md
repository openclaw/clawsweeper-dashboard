## Summary

Keep open. Current main and the latest release still run the sandbox browser through Docker-managed container lifecycle, and the requested external CDP/noVNC endpoint support remains a security-sensitive config/API product decision rather than an implemented capability or a clean duplicate of the broader browser-backend tracker.

## What This Changes

Request support for externally managed sandbox-browser CDP/noVNC endpoints so containerized or non-Docker sandbox deployments can use browser automation without Docker daemon access.

## Best Possible Solution

Keep this as the narrow sandbox-browser endpoint/backend design item, then implement a maintainer-approved contract that preserves CDP auth, noVNC observer tokens, SSRF policy, lifecycle semantics, docs, and focused tests.

## Reproduction Assessment

Yes, at source level for the missing capability: current main still routes sandbox browser setup through Docker lifecycle and has no external CDP/noVNC sandbox-browser config fields. I did not run a live Kubernetes, Docker Compose, or external sidecar deployment in this read-only review.

## Solution Assessment

Unclear as proposed. Optional endpoint fields are a plausible unblocker, but the best fix needs maintainer agreement on backend ownership, auth, SSRF/noVNC policy, lifecycle, and config contract rather than a one-off shortcut.
