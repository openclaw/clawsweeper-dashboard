## Summary

Keep open. Current main and the latest release still use a Docker-managed sandbox-browser lifecycle with no external CDP/noVNC sandbox-browser config, and the related browser-backend items overlap but do not replace this narrower security-sensitive endpoint contract request.

## What This Changes

Request support for configuring sandbox-browser external CDP/noVNC endpoints so browser automation can run with non-Docker sandbox backends or externally managed sidecars.

## Best Possible Solution

Define a maintainer-approved sandbox-browser backend or external-endpoint contract that preserves CDP auth, SSRF policy, noVNC observer access, lifecycle semantics, docs, and focused tests before adding public config.

## Reproduction Assessment

Yes, at source level: current main still routes sandbox browser setup through Docker lifecycle and has no external CDP/noVNC sandbox-browser config fields. I did not run a live Kubernetes, Docker Compose, or external sidecar deployment in this read-only review.

## Solution Assessment

Unclear as proposed. External endpoint fields are a plausible unblocker, but the best fix needs maintainer agreement on backend ownership, auth, SSRF/noVNC policy, validation, and public config shape before implementation.
