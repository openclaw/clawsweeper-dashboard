## Summary

Keep open: current main and v2026.6.11 still use a Docker-managed sandbox-browser lifecycle, and external CDP/noVNC endpoint support remains a security-sensitive feature/config decision rather than implemented cleanup.

## What This Changes

Request to let the sandbox browser attach to externally managed CDP/noVNC endpoints so non-Docker sandbox backends can use browser automation without a Docker daemon.

## Best Possible Solution

Define a maintainer-approved sandbox-browser backend or endpoint contract that supports externally managed browsers while preserving CDP auth, SSRF policy, noVNC observer tokens, lifecycle semantics, docs, doctor/audit checks, and focused tests.

## Reproduction Assessment

Yes, at source level: current main still routes sandbox browser setup through Docker lifecycle and rejects browser support for non-browser-capable backends. I did not run a live Kubernetes, Docker Compose, or external CDP sidecar deployment in this read-only review.

## Solution Assessment

Unclear as proposed. Optional endpoint fields are a plausible unblocker, but the best fix needs maintainer agreement on backend ownership, CDP/noVNC auth, SSRF policy, config contract, and docs/tests rather than a one-off shortcut.
