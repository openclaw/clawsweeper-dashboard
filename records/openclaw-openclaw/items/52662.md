## Summary

Keep open. Current main and the latest release still run sandbox-browser lifecycle through Docker, and the requested external CDP/noVNC endpoint support remains a security-sensitive public config/API decision.

## What This Changes

Request to let sandboxed browser control attach to externally managed CDP/noVNC endpoints so non-Docker sandbox deployments can use browser automation without a Docker daemon.

## Best Possible Solution

Define a maintainer-approved sandbox-browser backend or external-endpoint contract that supports externally managed browsers while preserving CDP auth, SSRF/source filtering, noVNC observer access, lifecycle semantics, docs, and focused tests.

## Reproduction Assessment

Yes, at source level: current main still routes sandbox browser setup through Docker lifecycle and has no external CDP/noVNC sandbox-browser config fields. I did not run a live Kubernetes, Docker Compose, or external sidecar deployment in this read-only review.

## Solution Assessment

Unclear as proposed. External endpoint fields are a plausible unblocker, but the best fix needs maintainer agreement on backend ownership, auth, SSRF/noVNC policy, validation, lifecycle, and public config shape before implementation.
