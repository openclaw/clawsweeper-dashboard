## Summary

Current main does not contain the reported remote-manifest fetch modules or an installation path matching the described SSRF; supported remote plugin installs clone or download a package before validating its local manifest, and remote marketplace manifests cannot point directly to HTTP(S) plugin sources.

## What This Changes

Investigate and prevent alleged SSRF through remote external-plugin manifest resolution, including private-address DNS results and redirect hops.

## Best Possible Solution

Keep the current clone/package-then-local-validation boundary; if a different shipped URL-fetch path is vulnerable, report it privately with the exact command, version or SHA, attacker-control boundary, redirect chain, DNS results, and network trace.
