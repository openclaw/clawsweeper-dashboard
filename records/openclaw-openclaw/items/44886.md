## Summary

Keep open. Current main and v2026.6.11 still accept Telegram `direct.*.tools` in schema/types while the runtime policy path remains group-scoped, so the reported per-DM tool-policy enforcement gap is still present and security-sensitive.

## What This Changes

The issue asks whether Telegram `channels.telegram.accounts.<account>.direct.<peer>.tools` should enforce per-DM tool permissions, or be removed/clarified if it is not intended.

## Best Possible Solution

Define and implement one enforced Telegram DM/direct tool-policy contract, including explicit-vs-wildcard precedence, account scoping, topic/parent fallback, docs, and regression plus live Telegram proof; if maintainers reject that contract, remove or clarify the accepted config surface instead.
