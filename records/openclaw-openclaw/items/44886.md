## Summary

Keep open: current main and v2026.6.11 still expose Telegram `direct.<peer>.tools`/`toolsBySender` in schema and types, but the active tool-policy path only derives group/channel context and reads channel `groups`, not Telegram `direct` entries. The related candidate PR was closed unmerged, and the broader binding-policy issue only partially overlaps.

## What This Changes

The issue asks whether Telegram `direct.<peer>.tools` should enforce per-DM tool policy, or whether the accepted config surface should be clarified or retired.

## Best Possible Solution

Keep this issue open until maintainers either enforce the existing Telegram direct `tools`/`toolsBySender` surface through a direct-aware resolver with exact/wildcard DM regression coverage, or deliberately retire/diagnose the schema surface with doctor and docs.
