## Summary

Keep open: current main still accepts and types Telegram `direct.<peer>.tools`/`toolsBySender`, while the active policy path derives only group/channel context and resolves only `groups`, not Telegram `direct` entries. The linked repair PR is closed unmerged, the duplicate issue is already closed back to this issue, and the broader binding-policy issue only partially overlaps.

## What This Changes

The issue asks whether Telegram direct-message `direct.<peer>.tools` should be enforced as per-DM tool policy, because the schema accepts it while runtime enforcement appears group/channel-centered.

## Best Possible Solution

Keep this issue open until maintainers either enforce Telegram direct `tools` and `toolsBySender` through a direct-aware resolver with exact, wildcard, account-scoped, topic/parent, and sender-precedence coverage, or deliberately retire the accepted surface with doctor/docs diagnostics.

- **Defer To Broader Binding Policy:** Keep this blocked on the broader per-binding policy design while accepting that Telegram direct policy remains unreliable until that design lands.
