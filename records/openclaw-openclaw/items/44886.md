## Summary

## What This Changes

The issue asks whether Telegram DM `direct.<peer>.tools` is intended to enforce per-DM tool permissions, and if so to fix the schema/runtime enforcement mismatch.

## Best Possible Solution

Maintainers should define the Telegram direct-message tool-policy contract, then either enforce `direct.*.tools` through a DM-aware policy resolver with focused Telegram coverage and live proof, or remove/diagnose the accepted config surface and document the unsupported path.
