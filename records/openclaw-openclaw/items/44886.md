## Summary

Keep open: current main and the latest release still accept Telegram `direct.<peer>.tools` and `toolsBySender`, but the active tool-policy path only derives group/channel scope and reads channel `groups`, not Telegram `direct` entries. The related fix PR is closed unmerged, and the broader binding-policy issue only partially overlaps.

## What This Changes

The issue asks whether Telegram direct-message peer-level `tools` and `toolsBySender` config should enforce actual per-DM tool permissions.

## Best Possible Solution

Keep this issue open until maintainers either enforce the existing Telegram direct `tools`/`toolsBySender` surface through a direct-aware resolver with exact/wildcard/account/thread/sender tests, or deliberately retire and diagnose the schema surface with doctor/docs.

- **Defer To Binding Policy Design:** Keep this open but make the broader binding-policy decision the canonical product route, accepting that Telegram direct policy remains unreliable until that design lands.
