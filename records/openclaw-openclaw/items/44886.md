## Summary

Keep open. Current main and the latest release still accept Telegram `direct.*.tools` / `toolsBySender`, but the enforcement path is still group/channel-scoped, so this remains a security-sensitive schema/runtime mismatch that needs maintainer direction before repair.

## What This Changes

The issue asks whether Telegram per-DM `direct.<peer>.tools` should be enforced as actual per-user tool policy because the config is accepted but not reliably applied at runtime.

## Best Possible Solution

Define one maintainer-approved contract, preferably enforcing the already accepted Telegram `direct.*.tools` surface end to end with account, wildcard, topic/thread, and sender precedence covered by tests; if maintainers reject that boundary, retire or clarify the schema with a doctor/docs path instead.
