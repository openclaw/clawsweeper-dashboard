## Summary

Keep open: current main and v2026.6.11 still accept Telegram `direct.<peer>.tools`/`toolsBySender` while the active tool-policy path is group/channel-scoped and does not read Telegram direct entries.

## What This Changes

The issue asks OpenClaw to confirm and enforce Telegram direct-message `direct.<peer>.tools` and `toolsBySender` as per-user tool-policy controls, or clarify/remove the accepted config surface.

## Best Possible Solution

Keep the issue open until maintainers either enforce the existing Telegram direct `tools`/`toolsBySender` surface through a direct-aware resolver with exact/wildcard/account/thread/sender tests, or deliberately retire and diagnose the schema surface in doctor/docs.
