## What This Changes

The issue asks whether Telegram per-DM `direct.<peer>.tools` and `toolsBySender` are intended to enforce actual tool permissions, and to fix or clarify that surface.

## Best Possible Solution

Keep the issue open and converge on an end-to-end Telegram/direct policy contract: either enforce accepted `direct.*.tools`/`toolsBySender` with shared resolver coverage and live proof, or explicitly retire/warn on that config surface.
