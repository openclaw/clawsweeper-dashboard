## Summary

Keep open: current main still accepts Telegram `direct.*.tools` / `toolsBySender` while the inspected enforcement path remains group/channel-scoped. The duplicate report was closed back to this canonical issue, and the related repair PR is closed unmerged.

## What This Changes

The issue asks whether Telegram DM `direct.<peer>.tools` should enforce per-DM tool permissions, and if not, to clarify or remove the accepted config surface.

## Best Possible Solution

Make the Telegram direct tool-policy contract explicit: either enforce it through a direct-aware resolver with regression and live Telegram proof, or retire/diagnose the config surface and point users to supported global/per-agent `toolsBySender`.
