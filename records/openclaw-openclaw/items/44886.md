## Summary

Keep open: current main still accepts Telegram `direct.<peer>.tools`/`toolsBySender`, applies direct config to DM prompts, and resolves runtime tool policy through group-only paths. The duplicate issue is already closed back to this one, and the related fix PR closed unmerged, so there is no safe close target.

## What This Changes

Ensure schema-accepted Telegram direct-message `tools` and `toolsBySender` policies are either enforced per DM user or retired/diagnosed if unsupported.

## Best Possible Solution

Either enforce Telegram direct `tools` and `toolsBySender` through a direct-aware resolver with exact, wildcard, account, thread, and sender regression coverage, or retire the accepted schema surface with doctor/docs diagnostics so operators cannot rely on a silent no-op.
