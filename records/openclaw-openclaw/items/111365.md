## Summary

This PR should remain open because it is linked to the still-open canonical upgrade report, but the submitted change does not address the current repair-path ordering it describes. On current main, the canonical assertion only validates schema shape; the canonical SQL runs later and is already preceded by additive-column repair when `audit_events` exists. The no-`audit_events` path intentionally leaves the legacy version for normal opening, whose migration path adds columns before executing schema SQL.

## What This Changes

The PR moves additive shared-state SQLite column repair outside the `audit_events` guard and adds a test for a legacy database whose audit tables and additive media-record columns are absent.

## System Context

OpenClaw's shared-state SQLite database is opened by the gateway and repaired by `openclaw doctor --fix` when an upgrade leaves an older schema. The repair path validates or repairs legacy tables, while the normal open path performs the full schema creation and migration sequence before the gateway can use the database.
