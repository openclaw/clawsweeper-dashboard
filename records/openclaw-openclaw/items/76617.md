## Summary

Keep open, but this PR is not merge-ready: it changes only the Zalo Personal send-helper fallback while current main's normal outbound and monitored bot reply paths pass the shared resolver's `length` default explicitly, so the stated long-reply behavior can still split mid-word. It also lacks real Zalo after-fix proof.

## What This Changes

This PR changes the Zalo Personal send helper default chunk mode from `length` to `newline` and adds a unit regression test for paragraph-boundary splitting.

## Best Possible Solution

Decide whether Zalo Personal should default to natural-boundary chunking, then apply that consistently through the resolver-backed outbound/reply paths with focused tests and redacted real Zalo proof.

## Reproduction Assessment

Yes at source level: current main's helper fallback and shared resolver default both remain `length`, and normal Zalouser outbound/reply paths pass the resolver mode explicitly. I did not run a live Zalo scenario in this read-only review.

## Solution Assessment

No. Changing only the send-helper fallback is too narrow for the stated long bot reply behavior; the maintainable fix must either align the resolver-backed default or clearly scope this PR to helper-only sends.
