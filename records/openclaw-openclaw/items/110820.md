## Summary

This PR is still necessary as a reliability fix, but its `execFileSync` timeout does not establish the claimed hard bound for the reported stale-filesystem case: Node waits for the Git child to exit after signalling it, and a child blocked in uninterruptible filesystem I/O may not exit on `SIGKILL`. Keep it open for a bounded-caller design or a deliberately narrowed, proven scope.

## What This Changes

The PR adds a 120-second timeout and `SIGKILL` to the Git helper used by Testbox lease-freshness checks.

## Best Possible Solution

Make the lease-freshness caller independently deadline-bounded even if its Git child cannot terminate, with explicit cleanup semantics, then attach redacted terminal evidence for the blocked-command path and the normal success path.
