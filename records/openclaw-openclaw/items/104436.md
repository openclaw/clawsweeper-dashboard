## Summary

Current main confirms the need for separate gateway and OS-level trust boundaries, but this issue proposes a new privileged hosting control plane whose ownership is not settled. The protected maintainer and security signals make an explicit core-versus-external orchestration decision necessary before implementation.

## What This Changes

Add an `openclaw fleet` CLI supervisor that manages one hardened containerized OpenClaw cell per tenant and documents the hosted trust model.

## Best Possible Solution

First define and validate a hardened cell contract covering image provenance, isolation, secrets, storage, networking, health, upgrades, rollback, deletion, and host trust; add a core supervisor only if security review proves maintained external orchestration cannot satisfy that contract.
