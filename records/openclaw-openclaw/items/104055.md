## Summary

This PR takes the right compatibility direction by separating CJK-aware token-share accounting from the existing physical `toolResultMaxChars` ceiling, but the unchanged exact head still lets qualifying short sibling blocks bypass their share while larger blocks consume allocations derived from the full budget. That P1 allocator defect and the absence of provider-backed multi-turn proof block merge; the PR should remain open for a focused correction and contributor-supplied runtime evidence.

## What This Changes

The PR adds dual estimated/physical CJK-aware tool-result budgets, propagates them through live runner, recovery, and session persistence paths, and expands focused regression tests.

## Best Possible Solution

Keep the dual-budget design, reserve both estimated and physical capacity for every intact block before distributing the remainder, add a mixed short-ASCII/dense-CJK regression, refresh against current main, and prove the next provider request receives bounded content.
