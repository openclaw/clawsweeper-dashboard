## Summary

Keep open: current main and the latest release still allow OpenAI refresh-failure recovery to return an external Codex OAuth credential based on local expiry/identity checks, while the status path can remain green from the managed profile. The related open reports overlap, but they do not fully own this false-green managed-profile to invalidated-external-fallback sequence.

## What This Changes

The issue reports that managed OpenAI OAuth status can look healthy while a real agent turn falls back to an invalidated external Codex OAuth credential after managed-profile refresh failure.

## Best Possible Solution

Define a single managed OpenAI OAuth fallback contract: after managed-profile refresh failure, either fail closed/quarantine, validate external fallback with a real provider probe, or surface a degraded unverified-external-fallback state, with relog hints carrying the affected profile id and gateway 1006 reported separately.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 still return an external OpenAI/Codex fallback credential after managed OAuth refresh failure using local usability and identity checks, and the issue includes a sanitized live stable-release smoke showing the returned path can fail with token_invalidated.

## Solution Assessment

No automated fix path is best yet. The durable repair needs a maintainer fallback-policy choice because fail-closed behavior, provider probing, explicit opt-in fallback, and degraded status each have different compatibility and operator-impact tradeoffs.
