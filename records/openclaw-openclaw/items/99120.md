## Summary

Keep open: current main and the latest release still allow the OpenAI OAuth refresh path to return an external Codex CLI credential after managed-profile refresh failure, and the status path can still rate locally usable OAuth state as healthy without proving the real model call will accept that token. The related open issues overlap, but they do not fully subsume this focused false-green plus invalidated external-fallback report.

## What This Changes

The issue requests hardening OpenAI/Codex OAuth refresh and status behavior so managed profiles do not appear healthy while runtime can fall back to an invalidated external credential.

## Best Possible Solution

Define one maintainer-approved OpenAI/Codex auth fallback contract: after managed-profile refresh failure, external Codex credentials should be either verified, explicitly marked degraded, quarantined, or bypassed, with status and recovery hints matching the real agent call path.

## Reproduction Assessment

Yes, at source level and from sanitized live evidence: current main and v2026.6.11 still return an external OpenAI/Codex fallback credential after managed-profile refresh failure when local shape, expiry, and identity checks pass. I did not perform a live credential-backed reproduction in this read-only pass.

## Solution Assessment

Unclear as a single automated fix: the report is valid, but the best repair requires a maintainer decision on fallback policy and status semantics before changing upgrade-sensitive auth behavior.
