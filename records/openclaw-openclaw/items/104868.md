- `impact:other`: The issue suppresses an agent-runtime tool action, a meaningful impact not covered by the channel-message or session-state labels.

## Summary

The bug remains present on current main and the latest release. A linked PR directly owns the repair, but its parser has a documented valid-input defect and overlaps an older broader Gemma4 parser proposal, so this issue should remain open until one corrected implementation lands.

## What This Changes

Recover Gemma4-family tool calls leaked as raw text at end-of-stream so they execute instead of appearing as user-visible text.

## Best Possible Solution

Adopt one delimiter-aware Gemma4 parser, call it from the completions transport’s final flush, preserve internal string contents and nested values, fall back to visible text on malformed input, and cover terminal, split-chunk, quoted-string, nested-object, array, and mixed-text cases.

## Maintainer Decision

## Reproduction Assessment

Yes. Source inspection gives a high-confidence deterministic path: the final Gemma4 payload stays in a text block because current main never finalizes or reparses terminal text after the stream loop.

## Solution Assessment

No, the current direct PR is not yet the best implementation because it introduces a second parser with a known quoted-string failure. The narrowest maintainable fix combines its final-flush wiring with one robust reusable Gemma4 parser.
