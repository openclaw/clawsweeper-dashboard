## Summary

Keep this issue open as a narrow MS Teams delegated-auth health bug: current main reports an expired access token as failed even though the normal client path can refresh it. Likely related people: @sudie-codes introduced the delegated-auth probe behavior, and @BradGrouX merged and reviewed that feature path.

## What This Changes

Correct the MS Teams probe so a refreshable expired delegated access token is not reported as failed authentication.

## Best Possible Solution

Use the same refresh-aware token resolution contract as normal MS Teams API calls and mark delegated authentication failed only when refresh cannot produce a usable token; do not treat refresh-token presence alone as proof of validity.

## Reproduction Assessment

Yes at source level: the existing focused test constructs an expired token with a refresh token and confirms delegatedAuth.ok becomes false. A live reproduction of the claimed restart behavior has not been provided.

## Solution Assessment

No, checking only for refresh-token presence is not the safest fix because a stored refresh token can be revoked or invalid. The probe should exercise or reuse the existing refresh-aware resolver and fail only when refresh fails.
