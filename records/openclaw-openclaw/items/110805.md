## Summary

Keep this PR open: the revised shared fallback still calls `response.arrayBuffer()` before applying `maxBytes`, so it can allocate the complete error body and does not deliver the claimed bounded-read protection. It also still needs contributor-supplied after-fix runtime evidence before merge.

## What This Changes

The PR releases an Ollama response-stream reader lock, changes body-less HTTP error snippets to an `arrayBuffer()` path, and cancels Firecrawl’s original response body after clone-based error parsing.

## Best Possible Solution

Replace the fallback with a mechanism that enforces the byte limit before full-body allocation while preserving the valid response contract, add focused regression coverage, and provide redacted runtime output exercising the affected error paths.
