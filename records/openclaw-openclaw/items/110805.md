## Summary

Keep this PR open: the body-less fallback still calls `response.arrayBuffer()` before the byte cap can take effect when `Content-Length` is absent, so it can still materialize an unbounded error payload. The Firecrawl cleanup remains conditional on a truthy parsed payload, and the branch also removes an unrelated release-tooling declaration. The submitted proof is synthetic/test-harness evidence rather than inspectable after-fix runtime output.

## What This Changes

The branch adds explicit Ollama reader-lock release, rewrites shared HTTP error-body fallback handling, conditionally cancels a Firecrawl response body after parsed JSON errors, and deletes declarations from the release-candidate checklist type contract.

## Best Possible Solution

Make the body-less fallback genuinely allocation-safe by returning no snippet when it lacks a bounded stream or trustworthy in-limit length, make Firecrawl cleanup cover every clone-consumption outcome without breaking any documented fallback, restore the unrelated declaration, then attach redacted real runtime evidence for the affected paths.
