- `impact:security`: The affected behavior is the SSRF DNS-resolution guard for outbound `web_fetch` requests.

## Summary

Keep open: current main and v2026.6.11 still reject a resolved DNS set as soon as any entry is blocked, before the IPv4-first pinned-address ordering can use the safe public address. The direct fix PRs for this issue are closed unmerged, and the remaining choice changes the default SSRF DNS-answer security boundary.

## What This Changes

The issue requests that web_fetch allow mixed DNS results when at least one resolved address is safe, while still blocking all-blocked/private/special-use result sets.

## Best Possible Solution

A maintainer-approved SSRF fix should keep all-blocked result sets fail-closed, filter blocked resolved addresses before pinning or overrides, and add mixed-answer regression tests for public IPv4 plus blocked IPv6 cases.
