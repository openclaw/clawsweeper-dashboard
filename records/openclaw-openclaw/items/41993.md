## Summary

Keep open: current main and the latest release still reject a DNS answer set as soon as any resolved address is blocked, before IPv4-first pinning can use a safe public address. The direct fix PRs are closed unmerged, and the remaining decision is a security-sensitive default SSRF behavior choice.

## What This Changes

The issue requests that web_fetch allow a DNS result set when at least one resolved address is public/allowed, while still blocking all-blocked result sets.

## Best Possible Solution

After maintainer security approval, implement filtered mixed-answer semantics: fail only when no allowed DNS candidates remain, pass only allowed candidates into pinned dispatcher paths, preserve all-blocked failures, and add focused regression coverage.
