## Summary

Keep open: current main and the latest release still reject a mixed allowed-plus-blocked DNS answer before IPv4-first pinning can use the safe address. The direct fix PRs are closed unmerged, and the remaining choice changes default SSRF DNS-answer behavior.

## What This Changes

The issue requests changing web_fetch SSRF DNS handling so a public fetch can proceed when at least one resolved address is allowed, while blocked DNS candidates are not used.

## Best Possible Solution

A maintainer-approved SSRF fix should filter resolved DNS candidates down to allowed addresses, fail closed when none remain, preserve all-blocked/private checks, and add mixed-answer regression coverage.

- **Make mixed polluted DNS opt-in:** Preserve the current default and add or reuse an explicit operator-controlled policy for environments that need this behavior.
