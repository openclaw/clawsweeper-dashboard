## Summary

Keep open: current main and v2026.6.11 still reject a resolved DNS set as soon as any address is blocked, before IPv4-first pinning can use a safe public address. The direct candidate fixes are all closed unmerged, and the remaining blocker is maintainer/security intent for default SSRF DNS-answer semantics.

## What This Changes

The issue reports that web_fetch rejects public URLs on dual-stack DNS answers when a blocked IPv6 special-use address is returned alongside an allowed public IPv4 address.

## Best Possible Solution

Approve and land a focused SSRF fix that filters blocked resolved addresses out of the pinned candidate set, fails closed when none remain, preserves special-use blocks, and adds mixed-answer plus all-blocked regression coverage.

- **Make polluted DNS handling opt-in:** Preserve the current default and add or reuse an operator-controlled SSRF policy knob for mixed polluted DNS environments.
