## Summary

Keep open: current main and v2026.6.11 still reject a DNS result set when any resolved address is blocked before IPv4-first pinning can use a safe public address. The direct fix PRs are closed unmerged, so the remaining item is a security-sensitive default SSRF behavior decision.

## What This Changes

The issue asks `web_fetch` to tolerate mixed DNS answers by using safe public addresses when other resolved IPv6 answers are special-use or blocked.

## Best Possible Solution

Settle the SSRF policy direction and, if approved, land a narrow change that filters blocked DNS answers before pinning while retaining all-blocked rejection and adding mixed-DNS regression tests.

Question: Should `web_fetch` default DNS-result validation filter blocked answers and proceed when at least one safe public address remains, or keep the current reject-any-blocked DNS policy?

Rationale: The code fix is small, but it changes the default SSRF interpretation for hostile or polluted DNS answers; automation should not choose that security boundary without owner intent.

Options:

- **Filter blocked answers by default (recommended):** Land a narrow fix that pins only allowed addresses, rejects all-blocked result sets, and adds mixed IPv4/IPv6 regression coverage.
- **Keep strict reject-any-blocked behavior:** Leave the current security posture in place and document that affected deployments must use trusted proxy or explicit fake-IP config where applicable.
- **Add an explicit opt-in mode:** Preserve the current default and add a named configuration switch for mixed-answer tolerance, with migration-free docs and tests.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: a lookup that returns a public IPv4 plus blocked IPv6 enters `resolvePinnedHostnameWithPolicy`, then throws in `assertAllowedResolvedAddressesOrThrow` before IPv4-first pinning. I did not run tests because this review is read-only.

## Solution Assessment

Unclear pending maintainer security intent: filtering blocked results and rejecting all-blocked sets is the narrowest code fix, but it changes default SSRF semantics. The best implementation, if approved, belongs in `src/infra/net/ssrf.ts` with regression coverage in `src/infra/net/ssrf.pinning.test.ts`.
