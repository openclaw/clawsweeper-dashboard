## Summary

Keep open: current main and v2026.6.11 still reject the whole DNS result set when any resolved address is blocked, and the direct candidate fixes are closed unmerged. The remaining change is small in code but changes the default SSRF DNS-answer security boundary, so it needs maintainer security/product approval rather than automated cleanup.

## What This Changes

The issue requests changing `web_fetch` SSRF DNS validation so mixed public-plus-special-use DNS answers can proceed using only allowed addresses instead of failing the whole request.

## Best Possible Solution

A maintainer-approved SSRF fix should filter DNS results down to allowed candidates, fail closed when none remain, pass only allowed candidates into pinning/dispatcher override paths, and add mixed-answer plus all-blocked regression coverage.
