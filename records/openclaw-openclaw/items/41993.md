- `impact:security`: The affected behavior is the SSRF DNS-resolution guard for outbound web_fetch requests.

## Summary

Keep open: current main and v2026.6.11 still reject the whole DNS result set when any resolved address is blocked, before IPv4-first pinning can use a safe address. The direct fix PRs are closed unmerged, so the remaining step is maintainer approval of the SSRF default behavior change.

## What This Changes

Allow `web_fetch` to succeed on mixed DNS answers when at least one resolved address is safe, while keeping blocked-only DNS answers rejected.

## Best Possible Solution

A maintainer-approved SSRF change should filter blocked DNS candidates before pinning, fail closed when none remain, and cover mixed-answer plus all-blocked cases in regression tests.

- **Approve filtered mixed-answer semantics (recommended):** Allow the request only when at least one resolved address is allowed, pass only allowed addresses into the pinned dispatcher, and add focused all-blocked plus mixed-answer tests.

- **Make mixed-answer behavior opt-in:** Preserve the current default and add or reuse an explicit operator-controlled policy for polluted DNS environments.
