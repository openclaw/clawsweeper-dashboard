## Summary

Keep open: current main and v2026.6.11 still reject a DNS result set as soon as any resolved address is blocked, before IPv4-first pinning can use a safe public address. The direct fix PRs for this issue are closed unmerged, and the remaining action is a security-boundary decision for default SSRF behavior.

## What This Changes

The issue asks for `web_fetch` to tolerate DNS answers that mix blocked special-use IPv6 addresses with valid public IPv4 addresses by using only allowed candidates.

## Best Possible Solution

Approve and land a focused SSRF fix that filters blocked resolved addresses out of the pinned candidate set, fails closed when none remain, preserves special-use blocks, and adds mixed-answer plus all-blocked regression coverage.
