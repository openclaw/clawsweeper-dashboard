## Summary

Keep open: current main and the latest release still reject a DNS result set when any resolved address is blocked, before IPv4-first pinning can use an allowed public IPv4 address. The direct fix PRs are closed unmerged, while merged proxy and fake-IP work only covers adjacent opt-in paths.

## What This Changes

The issue reports that web_fetch rejects public hosts on dual-stack DNS results when a blocked IPv6 special-use address is returned alongside an allowed IPv4 address.

## Best Possible Solution

Keep this open for a maintainer-approved SSRF fix that filters blocked DNS candidates before pinning, fails closed when no allowed address remains, and adds mixed-answer regression coverage.

## Reproduction Assessment

Yes. Source-level reproduction is high confidence: a lookup result containing a blocked IPv6 answer such as :: plus a public IPv4 answer still reaches an any-blocked-address assertion before IPv4-first pinning.

## Solution Assessment

Unclear until maintainer security review. Filtering blocked resolved addresses before pinning is the narrow candidate fix, but maintainers need to approve the mixed-answer SSRF policy change and verify blocked candidates cannot be used later.
