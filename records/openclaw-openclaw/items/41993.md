## Summary

Keep open: current `main` and the latest release still reject a mixed DNS answer set as soon as any resolved address is blocked. The source-level repro is clear, but changing this behavior relaxes the default SSRF DNS-answer policy and needs maintainer/security approval.

## What This Changes

The issue reports that `web_fetch` rejects public hosts on dual-stack DNS responses when a blocked IPv6 special-use address is returned alongside an allowed IPv4 address.

## Best Possible Solution

A maintainer-approved SSRF change should filter blocked resolved addresses out of the pinned candidate set, reject only when no allowed addresses remain, preserve all-blocked/private checks, and add mixed-answer regression coverage.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw change the default SSRF DNS-answer rule from failing on any blocked resolved address to filtering blocked candidates and proceeding when at least one allowed address remains?

Rationale: The implementation shape is narrow, but the default governs outbound SSRF behavior under polluted or hostile DNS answers, so automation should not choose the security boundary by itself.

Likely owner: steipete

Owner reason: The strongest history signal for SSRF policy and the current security-boundary decision points to steipete's central work on host/IP checks, IPv6 special-use blocking, and DNS pinning hardening.

Owner confidence: high

Options:

- **Approve filtered mixed-answer semantics (recommended):** Allow mixed DNS result sets only after removing every blocked candidate from the pinned address pool, with tests for mixed-allowed and all-blocked results.
- **Keep any-blocked fail-closed:** Treat any blocked DNS answer as an intentional stop and document trusted proxy or fake-IP opt-in settings as the supported workaround.
- **Make the behavior opt-in:** Preserve the current default and add or reuse an explicit operator-controlled policy for DNS-polluted environments.

## Reproduction Assessment

Yes. A source-level repro is high-confidence: a lookup returning a public IPv4 plus a blocked IPv6 address still hits the any-blocked assertion before IPv4-first pinning.

## Solution Assessment

Unclear until maintainer security review. Filtering blocked candidates before pinning is the narrow candidate fix, but maintainers need to approve changing the default SSRF mixed-answer rule.
