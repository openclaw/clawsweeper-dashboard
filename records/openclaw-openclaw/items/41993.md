## Summary

Keep open: current main and v2026.6.11 still reject mixed DNS answers as soon as any resolved address is blocked, before IPv4-first pinning can use an allowed public address. The direct candidate fixes are closed unmerged, and the remaining change is a default SSRF security-boundary decision.

## What This Changes

The issue asks OpenClaw web_fetch to allow a DNS result set when at least one resolved address is public/allowed, while still blocking all-blocked or private-only answers.

## Best Possible Solution

Approve one explicit SSRF behavior: either filter blocked DNS candidates and pin only allowed addresses by default with all-blocked fail-closed tests, or intentionally keep the strict default and document the trusted proxy/fake-IP opt-ins as the supported path.

## Maintainer Decision

Question: Should OpenClaw change the default SSRF DNS-answer rule for web_fetch from fail on any blocked resolved address to filter blocked candidates and proceed when at least one allowed address remains?

Rationale: The code repair is narrow, but the default controls outbound request safety under polluted or hostile DNS answers, so automation should not choose the SSRF boundary without maintainer/security intent.

Likely owner: steipete

Owner confidence: high

Options:

- **Approve filtered mixed-answer semantics (recommended):** Filter every blocked resolved address out of the pinned pool, reject only when no allowed address remains, and add mixed-allowed plus all-blocked regression coverage.
- **Keep any-blocked fail-closed:** Treat any blocked DNS answer as intentional hard failure and document trusted proxy or fake-IP policy settings as the supported workaround.
- **Make the behavior opt-in:** Preserve the current default and add or reuse an explicit operator-controlled policy for DNS-polluted environments.

Yes, at source level: a lookup returning one public IPv4 plus one blocked IPv6 address still hits the any-blocked assertion before IPv4-first pinning. I did not run a live dual-stack DNS-pollution environment.

## Solution Assessment

Unclear until maintainer security review. Filtering blocked candidates before pinning is the narrow maintainable fix, but changing the default SSRF mixed-answer rule needs approval.
