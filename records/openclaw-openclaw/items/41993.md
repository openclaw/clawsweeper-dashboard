## Summary

Keep open: current main and the latest release still reject a mixed DNS answer as soon as any resolved address is blocked, before IPv4-first pinning can use an allowed address. The direct candidate fixes are closed unmerged, and changing this default SSRF DNS-answer rule needs maintainer/security approval.

## What This Changes

The issue asks OpenClaw to let `web_fetch` proceed when DNS returns at least one allowed public address alongside blocked IPv6 special-use addresses.

## Best Possible Solution

Approve one explicit SSRF behavior: filter blocked resolved addresses out of the pinned candidate set, reject only when no allowed addresses remain, preserve all-blocked/private checks, and add mixed-answer regression coverage.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw change the default SSRF DNS-answer rule from fail on any blocked resolved address to filter blocked candidates and proceed when at least one allowed address remains?

Rationale: The implementation shape is narrow, but the default governs outbound requests under polluted or hostile DNS answers, so automation should not choose the SSRF boundary.

Likely owner: steipete

Owner reason: They have the strongest visible history in the SSRF host/IP and IPv6 special-use security boundary.

Owner confidence: high

Options:

- **Approve filtered mixed-answer semantics (recommended):** Allow mixed DNS result sets only after removing every blocked candidate from the pinned address pool, with tests for mixed-allowed and all-blocked results.
- **Keep any-blocked fail-closed:** Treat any blocked DNS answer as an intentional stop and document trusted proxy or fake-IP opt-in settings as the supported workaround.
- **Make this opt-in:** Preserve the current default and add or reuse an explicit operator-controlled policy for DNS-polluted environments.

Yes. A source-level repro is high-confidence: a lookup returning a public IPv4 plus a blocked IPv6 address still hits the any-blocked assertion before IPv4-first pinning.

## Solution Assessment

Unclear until maintainer security review. Filtering blocked candidates before pinning is the narrow candidate fix, but maintainers need to approve changing the default SSRF mixed-answer rule.
