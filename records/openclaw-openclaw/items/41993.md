## Summary

Keep open: current main and the latest release still reject a DNS result set as soon as any resolved address is blocked, before IPv4-first pinning can use a safe public address. The direct candidate PRs are closed unmerged, and the remaining fix is a small but security-sensitive default SSRF behavior decision.

## What This Changes

Requests that web_fetch tolerate mixed DNS responses by using allowed public addresses instead of failing when any resolved IPv6 special-use address is present.

## Best Possible Solution

A maintainer-approved SSRF fix should compute allowed DNS candidates once, use only those candidates for pinning, fail closed when none remain, and add mixed-answer plus all-blocked regression coverage.
