## Summary

Keep open: current main and the latest release still reject the whole DNS answer set when any resolved address is private/internal/special-use, so the reported dual-stack `web_fetch` failure remains source-reproducible. Direct fix PRs were closed unmerged, and the remaining choice is a maintainer security decision about default mixed-DNS SSRF semantics.

## What This Changes

The issue asks OpenClaw to let `web_fetch` proceed when DNS returns at least one allowed public address alongside blocked IPv6 special-use answers, while keeping all-blocked answer sets rejected.

## Best Possible Solution

Adopt a maintainer-approved mixed-DNS SSRF rule that filters blocked answers out of all pinned candidates, fails closed when no allowed answers remain, and adds focused regression coverage.
