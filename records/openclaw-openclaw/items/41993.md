## Summary

Keep open: current main and v2026.6.11 still reject a DNS result set as soon as any resolved address is blocked, before IPv4-first pinning can use a safe public address. The direct fix PRs for this issue are closed unmerged, and the remaining change is a security-sensitive default SSRF behavior decision.

## What This Changes

The issue asks `web_fetch` to allow mixed DNS answers when at least one resolved address is safe and to filter blocked candidates before pinning.

## Best Possible Solution

A maintainer-approved SSRF fix should return only allowed DNS candidates, fail closed when none remain, preserve all-blocked/private checks, and add mixed-answer regression coverage.
