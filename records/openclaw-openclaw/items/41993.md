## Summary

Keep open: current main and v2026.6.11 still reject a DNS answer set as soon as any resolved address is blocked, before IPv4-first pinning can use a safe public address. The direct fix PRs are closed unmerged, and the remaining blocker is a maintainer security decision about default SSRF mixed-DNS semantics.

## What This Changes

The issue asks `web_fetch` to allow mixed DNS answer sets when at least one resolved address is allowed, while still filtering blocked private/internal/special-use addresses before pinning.

## Best Possible Solution

A maintainer-approved SSRF fix should return only allowed DNS candidates, fail closed when none remain, preserve all-blocked/private checks, and add mixed-answer regression coverage across pinned DNS and `web_fetch`.

- **Approve filtered mixed-answer semantics (recommended):** Allow the request only when at least one resolved address is allowed, pass only allowed addresses into pinned dispatch, and add all-blocked plus mixed-answer tests.
- **Keep any-blocked fail-closed:** Treat polluted mixed DNS answers as intentionally blocked and document trusted proxy or fake-IP opt-in configuration as the supported workaround.
- **Make mixed-answer behavior opt-in:** Preserve the current default and add or reuse an explicit operator-controlled policy for polluted DNS environments.
