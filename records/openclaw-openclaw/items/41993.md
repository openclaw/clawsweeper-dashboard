## Summary

Keep open: current main and v2026.6.11 still reject the entire DNS result set when any resolved address is blocked, so the reported dual-stack `web_fetch` failure remains source-reproducible. The remaining choice is a security/product decision about default SSRF DNS-answer semantics.

## What This Changes

The issue requests changing `web_fetch` SSRF DNS validation so mixed public-plus-blocked DNS answers can proceed using only allowed addresses.

## Best Possible Solution

Adopt a maintainer-approved mixed-DNS SSRF rule that filters blocked answers out of pinned candidates, fails closed when no allowed answers remain, and adds focused regression coverage.
