## Summary

Keep open: current main and v2026.6.11 still reject the entire DNS result set when any resolved address is blocked, so the reported dual-stack `web_fetch` failure remains source-reproducible. The code change is small, but it changes the default SSRF DNS-answer security boundary and still needs maintainer security/product approval.

## What This Changes

`web_fetch` should continue when DNS returns at least one public allowed address and only special-use or private answers are filtered out.

## Best Possible Solution

Adopt a maintainer-approved SSRF rule for mixed DNS answers, fail closed when no allowed address remains, and pass only allowed candidates into the pinned lookup and dispatcher paths with focused regression coverage.
