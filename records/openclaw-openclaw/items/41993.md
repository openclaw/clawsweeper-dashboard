- `impact:security`: The affected code is the SSRF DNS-resolution guard for outbound `web_fetch` requests.

## Summary

Keep open: current main and the latest release still reject a mixed DNS answer set as soon as any resolved address is blocked, and the direct candidate fixes are closed unmerged.

## What This Changes

The issue requests that `web_fetch` allow mixed DNS answer sets when at least one resolved address is public and safe, while still blocking all-private or all-special-use results.

## Best Possible Solution

A maintainer-approved SSRF change should filter blocked resolved addresses out of the pinned candidate set, reject only when no allowed addresses remain, preserve all-blocked/private checks, and add mixed-answer regression coverage.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw change the default SSRF DNS-answer rule from fail on any blocked resolved address to filter blocked candidates and proceed when at least one allowed address remains?

Rationale: The implementation shape is narrow, but the default controls outbound SSRF behavior for polluted or hostile DNS answers, so automation should not choose the security boundary by itself.

Likely owner: steipete

Owner reason: The strongest history signal for the current SSRF assertion and adjacent hardening work points to `steipete`.

Owner confidence: high

Options:

- **Approve filtered mixed-answer semantics (recommended):** Allow mixed DNS result sets only after removing every blocked candidate from the pinned address pool, and add tests for mixed-allowed and all-blocked results.
- **Keep any-blocked fail-closed:** Treat any blocked DNS answer as an intentional stop and document trusted proxy or fake-IP opt-in settings as the supported workaround.
- **Make the behavior opt-in:** Preserve the current default and add or reuse an explicit operator-controlled policy for DNS-polluted environments.

Unclear until maintainer security review. Filtering blocked candidates before pinning is the narrow candidate fix, but maintainers need to approve changing the default SSRF mixed-answer rule.
