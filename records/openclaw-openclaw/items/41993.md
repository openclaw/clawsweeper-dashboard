## Summary

Keep open: current main and the latest release still reject a DNS answer set as soon as any resolved address is blocked, before IPv4-first pinning can use a safe public address. The direct fix PRs are closed unmerged, and the remaining decision is a security-sensitive default SSRF behavior choice.

## What This Changes

The issue reports that `web_fetch` blocks public fetches when DNS returns a safe IPv4 address alongside a blocked special-use IPv6 address.

## Best Possible Solution

A maintainer-approved SSRF fix should return only allowed DNS candidates, fail closed when none remain, preserve all-blocked/private checks, and add mixed-answer regression coverage.

Options:

- **Approve filtered mixed-answer semantics (recommended):** Allow the request only when at least one resolved address is allowed, pass only allowed addresses into the pinned dispatcher, and add all-blocked plus mixed-answer tests.

- **Make mixed-answer behavior opt-in:** Preserve the current default and add or reuse an explicit operator-controlled policy for polluted DNS environments.
