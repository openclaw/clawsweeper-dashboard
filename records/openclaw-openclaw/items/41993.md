- `impact:security`: The affected behavior is the SSRF DNS-resolution guard for outbound web_fetch requests.

## Summary

Keep open: current main and the latest release still reject a DNS result set as soon as any resolved address is blocked, before the IPv4-first pinned lookup can use a safe public address. The direct fix PRs are closed unmerged, and the remaining fix changes a security-sensitive default SSRF rule.

## What This Changes

The issue requests that web_fetch allow mixed DNS results when at least one resolved address is public and safe, instead of failing because another returned IPv6 address is special-use.

## Best Possible Solution

A maintainer-approved SSRF fix should filter resolved DNS results to allowed candidates before pinning, fail closed when no allowed candidate remains, preserve all-blocked and metadata/link-local protections, and add mixed-answer regression tests.
