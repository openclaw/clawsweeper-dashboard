## Summary

Keep open: current main and the latest release still reject a mixed DNS answer set as soon as any resolved address is blocked, and all direct candidate fixes are closed unmerged. The source-level repro is clear, but the fix changes the default SSRF boundary and needs maintainer/security approval before automation should queue a patch.

## What This Changes

The issue requests that `web_fetch` succeed for mixed DNS answers when at least one resolved address is allowed, instead of failing because another returned IPv6 address is special-use.

## Best Possible Solution

A maintainer-approved SSRF change should filter blocked resolved addresses out of the pinned candidate set, reject only when no allowed addresses remain, preserve all-blocked/private checks, and add mixed-answer regression coverage.

- **Make the behavior opt-in:** Preserve the current default and add or reuse an explicit operator-controlled policy for DNS-polluted environments.
