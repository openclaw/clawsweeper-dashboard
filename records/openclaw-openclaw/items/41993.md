## Summary

Keep open: current `main` and latest release `v2026.6.11` still fail closed when any DNS answer is blocked, so the reported mixed public/special-use DNS failure remains source-reproducible. The code change is small, but it changes the default SSRF DNS-answer boundary and needs maintainer security/product approval before repair.

## What This Changes

The issue reports that `web_fetch` rejects public hosts on dual-stack DNS responses when any returned IPv6 special-use address is blocked, even if another returned address is public and usable.

## Best Possible Solution

Keep this open for a maintainer security/product decision; if approved, implement a narrow resolver change that filters blocked DNS records before pinning and proves mixed-public/special-use and all-blocked cases.

- **Filter blocked answers:** Allow requests when at least one resolved address is allowed, but filter blocked records before pinning and add focused regression tests for mixed public/special-use answers and all-blocked answers.
- **Add explicit opt-in:** Preserve current default and add a narrow documented config mode for deployments affected by DNS pollution.

## Solution Assessment

Unclear until maintainer security direction is explicit; filtering blocked DNS answers is the narrow code fix, but preserving fail-closed defaults or making the behavior opt-in may be the better product/security answer.
