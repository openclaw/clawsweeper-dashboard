## Summary

Keep open: current main and the latest release still reject a mixed DNS answer set as soon as any resolved address is blocked, before IPv4-first pinning can use a safe public address. The direct fix PRs are closed unmerged, and changing this default SSRF behavior needs maintainer security intent.

## What This Changes

The issue requests changing `web_fetch` SSRF DNS handling so mixed allowed-plus-blocked answers can proceed using only safe resolved addresses.

## Best Possible Solution

A maintainer-approved SSRF fix should filter blocked DNS candidates before pinning, fail closed when no allowed address remains, preserve all-blocked/private checks, and add mixed-answer regression coverage.
