## Summary

Keep open: current main and v2026.6.11 still reject a DNS result set as soon as any resolved address is blocked, before IPv4-first pinning can use a safe public address. The direct fix PRs are closed unmerged, so the remaining call is a maintainer security-boundary decision.

## What This Changes

The issue reports that `web_fetch` rejects public hostnames on dual-stack DNS responses when any returned IPv6 special-use address is blocked, even if a valid public IPv4 address is also present.

## Best Possible Solution

A maintainer-approved SSRF fix should return only allowed DNS candidates, fail closed when none remain, preserve all-blocked/private checks, and add mixed-answer regression coverage.
