## Summary

Keep open: current main and v2026.6.11 still reject a DNS result set as soon as any resolved address is blocked, so the reported mixed public IPv4 plus special-use IPv6 web_fetch failure remains valid. The direct fix PRs are all closed unmerged, and the remaining choice is a security-sensitive default SSRF behavior decision.

## What This Changes

The issue requests that web_fetch tolerate mixed DNS answers by using allowed public resolved addresses instead of failing the whole request when one special-use IPv6 answer is present.

## Best Possible Solution

Approve a narrow SSRF fix that filters resolved DNS answers to allowed candidates, fails closed when none remain, pins only the filtered list, and adds mixed-answer plus all-blocked regression coverage.

- **Require Explicit Opt-In:** Preserve the current default and add or reuse an operator-controlled policy for polluted DNS environments.
