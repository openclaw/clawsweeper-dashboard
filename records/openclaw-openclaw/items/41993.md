## Summary

Keep open: current main and the latest release still reject a mixed DNS answer set as soon as any resolved address is blocked, before the IPv4-first pinned lookup can use a safe public address. The direct fix PRs for this issue are closed unmerged, and the remaining decision changes a default SSRF security boundary.

## What This Changes

The issue reports that web_fetch rejects public hosts in dual-stack DNS responses when any AAAA result is a special-use IPv6 address, even when an allowed public IPv4 result is also available.

## Best Possible Solution

A maintainer-approved fix should filter DNS answers to allowed candidates, fail closed when none remain, pass only allowed addresses into pinned dispatcher/override handling, and add mixed-answer plus all-blocked regression tests.
