## Summary

Keep open: current main and the latest release still reject mixed DNS results when any resolved address is blocked, before the IPv4-first pinned lookup can use a safe public address. The direct fix PRs are all closed unmerged, and the remaining choice changes the default SSRF security boundary.

## What This Changes

The issue requests changing web_fetch SSRF DNS handling so public fetches can proceed when DNS returns at least one allowed address alongside blocked IPv6 special-use answers.

## Best Possible Solution

After maintainer/security approval, filter resolved DNS results to allowed candidates before pinning, fail closed when no allowed candidate remains, preserve metadata/link-local protections, and add mixed-answer plus all-blocked regression tests.
