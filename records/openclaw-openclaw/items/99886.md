## Label Justifications

- `P2`: This is a bounded Slack channel media/context bug with real turn confusion and token waste, but it does not block the whole runtime.
- `impact:session-state`: Previously uploaded thread-root media is promoted into later turn state, causing Slack thread context drift.
- `impact:message-loss`: A text-only Slack reply can be misrepresented as a fresh media-bearing message, changing what the agent receives.

## Summary

Keep open: current main and v2026.6.11 still hydrate Slack thread-starter files and pass them as current-turn inbound media on text-only thread replies, while the prior fix PR is closed unmerged and the remaining fix needs a maintainer call on the thread-root media inheritance contract.

## What This Changes

The issue asks OpenClaw to stop re-injecting Slack thread attachments as fresh media on later text-only replies in the same thread.

## Best Possible Solution

Keep this as the canonical issue and implement a Slack-plugin-local, session-aware media policy: deliver reply-owned uploads, stop presenting already-delivered root files as fresh media on later text-only turns, and update tests/docs to preserve or deliberately revise first-turn root-media inheritance.

## Reproduction Assessment

Yes, at source level: current main hydrates starter.files into threadStarterMedia and then uses that as effectiveMedia for a Slack thread reply with no direct media. I did not run a live Slack reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the thread-root media contract. The older unconditional-skip PR was not the best fix because it conflicts with documented root-media inheritance; a session-aware de-duplication policy is safer.
