## Label Justifications

- `P2`: This is a bounded Slack channel media/context bug with real turn confusion and token waste, but it does not block the whole runtime.
- `impact:message-loss`: Previously uploaded thread media can be duplicated into later Slack turns where the user sent only text.
- `impact:session-state`: Thread-root media is promoted into later turn state, causing Slack thread context drift across replies.

## Summary

Keep open: current main and v2026.6.11 still hydrate Slack thread-starter files as effective inbound media for text-only thread replies, while the prior fix PR is closed unmerged and the remaining repair needs a maintainer decision on the documented thread-root media inheritance contract.

## What This Changes

The issue asks OpenClaw to stop treating previously uploaded Slack thread attachments as new inbound media on later text-only replies in the same thread.

## Best Possible Solution

Define a Slack-plugin-local, session-aware media policy: deliver current-message uploads, avoid re-delivering already-seen root files as fresh media on later text-only turns, and update docs/tests for the chosen first-turn inheritance behavior.

## Reproduction Assessment

Yes. Source inspection shows a text-only Slack thread reply with a starter containing files still hydrates `starter.files` into `threadStarterMedia` and uses it as `effectiveMedia`; no live Slack run was performed in this read-only pass.

## Solution Assessment

Unclear until maintainers choose the thread-root media contract. The old unconditional-skip PR was not the best fix because it conflicted with documented first-turn root-media inheritance; a session-aware repair is safer.
