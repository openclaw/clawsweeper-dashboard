- `impact:message-loss`: The same attachment can be duplicated into later Slack turns where the user did not send media.
- `impact:session-state`: Previously uploaded thread-root media is promoted into later turn state, causing Slack thread context drift.

## Summary

Keep open: current main and v2026.6.11 still contain the Slack source path that hydrates thread-starter files as effective inbound media on text-only thread replies, and the prior fix PR was closed unmerged after review found the behavior contract needed maintainer judgment.

## What This Changes

The issue reports that Slack thread replies with no new upload repeatedly deliver earlier thread attachments as fresh inbound media.

## Best Possible Solution

Keep this as the canonical issue and define a Slack-plugin-local, session-aware media policy: current-message uploads should be delivered, previously delivered root files should not reappear as fresh media on later text-only turns, and docs/tests should reflect the chosen first-turn inheritance behavior.

## Reproduction Assessment

Yes at source level: current main hydrates starter.files into threadStarterMedia and then uses it as effectiveMedia for a text-only Slack thread reply with no direct media. I did not run a live Slack reproduction in this read-only pass.

## Solution Assessment

Unclear until maintainers choose the thread-root media contract. The old unconditional-skip PR was not the best fix because it conflicted with documented first-turn root-media inheritance; a session-aware repair is safer.
