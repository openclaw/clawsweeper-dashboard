## Summary

Keep open: current main has restart deferral and supervised lock-conflict guards, but the managed and in-process restart paths still stop or exit the active gateway before replacement health is proven. The requested old-instance-preserving handoff remains a cross-platform lifecycle design item.

## What This Changes

The issue asks for gateway restarts to preserve the running instance until a replacement starts and passes health checks.

## Best Possible Solution

Define a maintainer-approved cross-platform restart continuity contract, then implement a handoff that keeps the current listener reachable until replacement health succeeds or the restart is rejected safely.

## Reproduction Assessment

Yes at source level: managed and in-process restart paths stop, exit, or restart the active gateway before replacement health is proven. I did not run a live supervisor repro in this read-only review.

## Solution Assessment

Unclear as an implementation-ready proposal: preserving the old gateway until a replacement passes health is the right end state, but the best fix needs a designed cross-platform supervisor, port, lock, rollback, and notification contract.
