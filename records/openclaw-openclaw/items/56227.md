## Summary

Keep open: current main still performs gateway restart health checks after the active gateway has been restarted, closed, or signaled, so the requested old-instance-preserving replacement handoff is not implemented. The recent main drift improves deferral and diagnostics but does not solve the central availability problem.

## What This Changes

The issue asks for gateway restarts to start and health-check a replacement before stopping the currently running gateway, so a bad restart cannot disconnect all channels.

## Best Possible Solution

Define a cross-platform restart continuity contract, then implement a supervisor-aware handoff that keeps the current listener alive until replacement health succeeds or the restart is rejected safely.

## Reproduction Assessment

Yes at source level: current restart paths still restart, close, or signal the active gateway before replacement health is proven. I did not run a live supervisor repro in this read-only pass.

## Solution Assessment

Unclear as an implementation-ready proposal: the atomic handoff goal is sound for availability, but the best fix needs a designed cross-platform supervisor, port, lock, rollback, and notification contract.
