## Summary

Keep open: current main still has preflight, deferral, and post-restart health checks, but it does not provide the requested old-instance-preserving gateway handoff when replacement startup fails.

## What This Changes

The issue requests gateway restart semantics that start and health-check a replacement before stopping the currently working gateway, so failed restarts do not disconnect all channel and API access.

## Best Possible Solution

Define a maintainer-approved gateway restart continuity contract, then implement the handoff so supported restart paths keep the current listener available until replacement health succeeds or reject the restart safely with clear diagnostics and channel notification when possible.

## Reproduction Assessment

Yes at source level: current main validates before restart and checks health after restart, but the service-manager and SIGUSR1 paths do not prove a replacement healthy before terminating or restarting the active instance. I did not run a live supervisor failure scenario in this read-only review.

## Solution Assessment

No implemented solution exists yet. The requested atomic-swap goal is reasonable, but the best fix needs a designed cross-platform supervisor, port, lock, rollback, and notification contract rather than a narrow patch to one caller.
