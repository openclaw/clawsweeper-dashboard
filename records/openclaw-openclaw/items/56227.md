## Summary

Keep open: current main and v2026.6.11 still close or restart the active gateway before replacement health is proven; existing config preflight and crash-guard mitigations reduce some failures but do not implement the requested old-instance-preserving handoff.

## What This Changes

Request that gateway restarts use an atomic handoff so a failed replacement startup leaves the previous gateway instance serving clients.

## Best Possible Solution

Define a maintainer-approved cross-platform restart continuity contract, then implement a fail-open handoff that keeps the current gateway reachable until replacement health succeeds or the restart is rejected safely.

## Reproduction Assessment

Yes, at source level: the current restart loop closes the active server before attempting the next startup, and failed post-initial startup leaves no old listener to serve clients. I did not run a live supervisor repro.

## Solution Assessment

Unclear as an implementation-ready proposal: the availability goal is sound, but the best fix needs a designed cross-platform supervisor, port, lock, rollback, and notification contract rather than a small local patch.
