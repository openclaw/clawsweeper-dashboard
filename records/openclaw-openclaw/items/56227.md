## Summary

Keep open: current main still closes, restarts, or delegates the active gateway before a replacement listener is proven healthy, so the requested old-instance-preserving restart handoff is not implemented.

## What This Changes

The issue requests an atomic gateway restart flow that starts and health-checks the replacement before stopping the currently working gateway.

## Best Possible Solution

Define a cross-platform restart continuity contract, then implement a two-phase restart handoff that keeps the current listener available until replacement health succeeds or the restart is rejected with user-visible recovery guidance.
