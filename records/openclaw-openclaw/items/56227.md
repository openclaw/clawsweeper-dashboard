## Summary

Keep open: current main and the latest release still close or retire the active gateway before a normal replacement restart is proven healthy, so the requested old-instance-preserving restart handoff remains real product work.

## What This Changes

The issue requests gateway restart behavior that starts and health-checks a replacement instance before stopping the active gateway, keeping the old instance available when replacement startup fails.

## Best Possible Solution

Define a core gateway lifecycle design that proves replacement readiness before retiring the active listener/channel stack, or explicitly narrow the product direction to last-known-good config fallback plus doctor recovery.
