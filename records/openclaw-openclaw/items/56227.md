## Summary

Keep open: current main still closes, restarts, or service-manager-terminates the active gateway before replacement health is proven, so the requested old-instance-preserving restart handoff is not implemented.

## What This Changes

The issue requests safer gateway restart semantics that keep the previous gateway instance alive until a replacement instance has started and passed a health check.

## Best Possible Solution

Define a cross-platform restart continuity contract, then implement a handoff or in-product recovery path that keeps a reachable gateway until replacement health succeeds, with Doctor/Fix guidance when a supervisor mode cannot safely provide atomic replacement.

## Reproduction Assessment

Yes, at source level: restart closes or terminates the existing gateway before replacement startup is proven, and current tests cover failed restart startup as a live process without a server handle. I did not run a live supervisor repro because this review is read-only and must not mutate the host service state.

## Solution Assessment

Unclear as implementation-ready: the availability goal is sound, but the best fix needs a maintainer-approved contract across in-process restarts, service-manager restarts, update handoff, port ownership, health checks, and channel notification.
