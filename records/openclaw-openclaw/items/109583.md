## Summary

The production-path proof now demonstrates the intended `ws` rejection behavior, but the prior blocker remains: the 1 MiB inbound ceiling is derived from OpenClaw’s outbound text limit rather than a QQ inbound gateway contract, so it could reject valid events and churn the connection.

## What This Changes

Adds a fixed 1 MiB inbound payload limit to the QQBot gateway WebSocket client and updates its constructor-option tests.

## Best Possible Solution

Keep the limit at the QQBot WebSocket construction boundary, but select it from an authoritative or owner-approved inbound QQ gateway ceiling with measured headroom, then cover valid near-limit delivery and oversize close/reconnect behavior.
