Full review comments:

- **[P1] Fix retry detection for Cellar Node paths:** `packages/memory-host-sdk/src/host/embeddings-worker.ts:269-272`
  - body: The reported Homebrew path ends in `/bin/node`, so this condition evaluates false for the exact stale Cellar executable the PR is trying to recover from. The ENOENT then falls through as a generic process error instead of retrying.
  - confidence: 0.97
- **[P1] Resolve an executable before retrying:** `packages/memory-host-sdk/src/host/embeddings-worker.ts:233-240`
  - body: `require.resolve("node")` does not produce a Node executable here; the local Node 24 check throws `MODULE_NOT_FOUND`, and the catch returns the same stale `process.execPath`. The retry must use a real stable executable path or PATH lookup.
  - confidence: 0.96
- **[P1] Replay the pending request on retry:** `packages/memory-host-sdk/src/host/embeddings-worker.ts:310-317`
  - body: The retry branch starts a replacement child asynchronously but immediately rejects all pending requests. During provider creation that rejects the initialize call and closes the client, so the retried worker never receives the request that failed.
  - confidence: 0.94
- **[P2] Keep worker failure codes aligned:** `packages/memory-host-sdk/src/host/embeddings-worker.ts:311-314`
  - body: This branch emits `LOCAL_EMBEDDING_WORKER_STALE_NODE_PATH`, but memory-core's local-worker failure detector still only recognizes the existing exited, process, and IPC codes. That can bypass the degraded-provider handling used for local worker failures.
  - confidence: 0.9
- **[P2] Remove the stale core-bridge allowlist:** `src/plugins/contracts/extension-package-project-boundaries.test.ts:62-64`
  - body: The final head no longer imports the core stable-node helper from the worker, but the contract test still allowlists `embeddings-worker.ts` as a core bridge. Keeping that exception weakens the package-boundary guard without a current need.
  - confidence: 0.88
