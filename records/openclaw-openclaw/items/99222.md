- **[P1] Replay the worker request after retry:** `packages/memory-host-sdk/src/host/embeddings-worker.ts:313-320`
  - body: This branch starts a retry child on ENOENT, but then immediately rejects all pending requests and returns. The initialize request that triggered the stale execPath failure is never resent to the retry child, so provider creation still fails even if the second fork succeeds.
  - confidence: 0.92
- **[P1] Resolve a Node executable, not a module name:** `packages/memory-host-sdk/src/host/embeddings-worker.ts:240-247`
  - body: `require.resolve("node")` is module resolution; on the supported Node runtime here it throws `MODULE_NOT_FOUND`, so the catch returns the same stale `process.execPath` and retries the deleted binary. Reuse the stable-path resolver or search for an executable instead.
  - confidence: 0.94
- **[P1] Use the resolved stable path for fork calls:** `packages/memory-host-sdk/src/host/embeddings-worker.ts:258`
  - body: The branch initializes and later updates `stableNodePathPromise`, but `ensureChild()` never reads it and still passes `execPath: process.execPath`. Normal worker launches, and later launches after a retry child exits, can keep using the stale Cellar path.
  - confidence: 0.9
- **[P1] Keep local worker error codes in sync:** `packages/memory-host-sdk/src/host/embedding-worker-errors.ts:8`
  - body: Adding `staleNodePath` only to the SDK list means memory-core's local-worker failure detector will not recognize the new error, so the degradation/cache-clearing path is skipped for this exact failure.
  - confidence: 0.88

  - confidence: 0.9
