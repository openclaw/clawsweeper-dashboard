- **[P1] Fix retry detection for Cellar Node paths:** `packages/memory-host-sdk/src/host/embeddings-worker.ts:269-272`
  - body: The reported executable is shaped like `/opt/homebrew/Cellar/node/<version>/bin/node`, so this `/bin/node` exclusion makes `doRetry` false for the exact stale Cellar path the PR is meant to recover. The error then falls through with no retry.
  - confidence: 0.98
- **[P1] Resolve an executable path before retrying:** `packages/memory-host-sdk/src/host/embeddings-worker.ts:233-240`
  - body: `require.resolve("node")` is module resolution, not PATH executable lookup; local Node reports `MODULE_NOT_FOUND` for it, so the catch returns the same stale `process.execPath`. Even if the predicate is fixed, the retry can spawn the deleted binary again.
  - confidence: 0.97
- **[P1] Replay the pending request on retry:** `packages/memory-host-sdk/src/host/embeddings-worker.ts:310-318`
  - body: The ENOENT branch starts a replacement child and then immediately rejects every pending request. The initialize or embed request that exposed the stale path is never sent to the retry child, so caller-visible recovery still fails even if the second fork succeeds.
  - confidence: 0.93
- **[P2] Keep worker failure codes aligned with memory-core:** `packages/memory-host-sdk/src/host/embedding-worker-errors.ts:8`
  - body: Adding `staleNodePath` only to the SDK list leaves memory-core's worker-failure detector unaware of the new code, so local-provider degradation and cache clearing can skip this failure shape.
  - confidence: 0.9
- **[P2] Remove the stale core-bridge allowlist entry:** `src/plugins/contracts/extension-package-project-boundaries.test.ts:63`
  - body: The final PR head no longer imports the core `src/infra` resolver from `embeddings-worker.ts`, but this test still blesses that package-to-core bridge. Keeping the exception weakens the package boundary without a current need.
  - confidence: 0.86
