  - body: The reported executable is shaped like `/opt/homebrew/Cellar/node/<version>/bin/node`, so this `/bin/node` exclusion makes `doRetry` false for the exact stale Cellar path the PR is meant to recover. The error then falls through with no retry.
  - confidence: 0.97
- **[P1] Resolve a Node executable, not a module:** `packages/memory-host-sdk/src/host/embeddings-worker.ts:241-246`
  - body: `require.resolve("node")` is module resolution, not PATH executable lookup; the inspected Node runtime returns MODULE_NOT_FOUND for it, so the catch returns the same stale `process.execPath`. Even if the predicate is fixed, the retry can spawn the deleted binary again.
  - confidence: 0.96
- **[P1] Use the stable executable for normal forks:** `packages/memory-host-sdk/src/host/embeddings-worker.ts:256-258`
  - body: The branch initializes and updates `stableNodePathPromise`, but `ensureChild()` never reads it and still passes `execPath: process.execPath`. Normal launches and later launches after a retry child exits can keep using the stale Cellar path, and CI already reports the cache as unused.
  - confidence: 0.95
- **[P1] Replay the request after starting the retry child:** `packages/memory-host-sdk/src/host/embeddings-worker.ts:313-320`
  - body: The ENOENT branch starts a replacement child and then immediately rejects every pending request. The initialize or embed request that triggered recovery is never sent to the retry child, so caller-visible recovery still fails even if the second fork succeeds.
  - confidence: 0.92
- **[P2] Keep local worker error codes in sync:** `packages/memory-host-sdk/src/host/embedding-worker-errors.ts:8`
  - body: Adding `staleNodePath` only to the SDK list leaves memory-core's worker-failure detector unaware of the new code, so local-provider degradation and cache clearing can skip this failure shape.
  - confidence: 0.89

  - body: The mock `send` callback is modeled as the third parameter, but the production code calls `child.send(payload, callback)`, so the error-path tests do not drive the callback as intended. The same new test file is currently failing test type checks.
  - confidence: 0.9
