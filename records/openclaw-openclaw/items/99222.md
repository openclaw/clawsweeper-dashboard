## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.97

Full review comments:

- **[P1] Fix the retry predicate for Cellar execPath:** `packages/memory-host-sdk/src/host/embeddings-worker.ts:276-279`
  - body: The reported executable is shaped like `/opt/homebrew/Cellar/node/<version>/bin/node`, so this `/bin/node` exclusion makes `doRetry` false for the exact stale Cellar path the PR is meant to recover. The error then falls through with no retry.
  - confidence: 0.98
- **[P1] Resolve a Node executable, not a module:** `packages/memory-host-sdk/src/host/embeddings-worker.ts:240-246`
  - body: `require.resolve("node")` is module resolution, not PATH executable lookup; local Node 24 reports `MODULE_NOT_FOUND` for it, so the catch returns the same stale `process.execPath`. Even if the predicate is fixed, the retry can spawn the deleted binary again.
  - confidence: 0.97
- **[P1] Use the stable executable for normal forks:** `packages/memory-host-sdk/src/host/embeddings-worker.ts:256-258`
  - body: The branch initializes and updates `stableNodePathPromise`, but `ensureChild()` never reads it and still passes `execPath: process.execPath`. Normal launches and later launches after a retry child exits can keep using the stale Cellar path.
  - confidence: 0.96
- **[P1] Replay the request after starting the retry child:** `packages/memory-host-sdk/src/host/embeddings-worker.ts:313-320`
  - body: The ENOENT branch starts a replacement child and then immediately rejects every pending request. The initialize or embed request that exposed the stale path is never sent to the retry child, so caller-visible recovery still fails even if the second fork succeeds.
  - confidence: 0.93
- **[P2] Keep local worker error codes in sync:** `packages/memory-host-sdk/src/host/embedding-worker-errors.ts:8`
  - body: Adding `staleNodePath` only to the SDK list leaves memory-core's worker-failure detector unaware of the new code, so local-provider degradation and cache clearing can skip this failure shape.
  - confidence: 0.9
- **[P2] Model child.send and worker messages correctly:** `packages/memory-host-sdk/src/host/embeddings-worker-stale-node.test.ts:40-68`
  - body: Production calls `child.send(payload, callback)`, but this mock treats the callback as the third argument and ignores registered `message` handlers. The new tests therefore do not exercise successful initialization or the IPC error path they are meant to prove.
  - confidence: 0.92
