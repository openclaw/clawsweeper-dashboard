## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Replay the worker request after a successful retry:** `packages/memory-host-sdk/src/host/embeddings-worker.ts:303`
  - body: This branch starts a retry child, but then immediately rejects all pending requests and returns. The initialize request that triggered the stale execPath error is never resent to the retry child, so provider creation still fails even if the second fork succeeds.
  - confidence: 0.92
- **[P1] Resolve a Node executable, not a module named node:** `packages/memory-host-sdk/src/host/embeddings-worker.ts:240`
  - body: `require.resolve("node")` is module resolution; on the supported Node runtime here it throws `MODULE_NOT_FOUND`, so this catch returns the same stale `process.execPath` and retries the deleted binary. Reuse the stable-path resolver or search PATH for an executable instead.
  - confidence: 0.94
- **[P1] Keep local worker error codes in sync with memory-core:** `packages/memory-host-sdk/src/host/embedding-worker-errors.ts:8`
  - body: Adding `staleNodePath` only to the SDK code list means memory-core's `isLocalEmbeddingWorkerFailure()` will not recognize the new error, so `markLocalEmbeddingProviderDegraded()` will skip the degradation/cache-clearing path for this exact failure.
  - confidence: 0.88
- **[P2] Test through exported APIs or export the helpers explicitly:** `packages/memory-host-sdk/src/host/embeddings-worker-stale-node.test.ts:61`
  - body: The new test imports `LocalEmbeddingWorkerClient` and later `resolveWorkerExecArgv`, but neither symbol is exported by `embeddings-worker.ts`. That makes the regression test/type checks fail before they can prove the retry behavior.
  - confidence: 0.91
