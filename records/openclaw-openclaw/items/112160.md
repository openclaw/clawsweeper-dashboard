## Summary

Close as implemented. The current SSH sandbox contract routes inbound-media staging through the remote workspace after the initial seed, directly addressing the reported reused-runtime case; that behavior entered the core SSH backend before the reported release.

## What This Changes

Ensure inbound attachments are staged in an existing remote SSH sandbox workspace so sandboxed agents can process them.

## System Context

Inbound channel attachments enter the agent reply pipeline and are staged into the active sandbox workspace before tools consume them. For the SSH backend, the remote workspace is canonical after initial creation, so the filesystem bridge sends writes to the SSH target rather than relying on a later host-to-remote sync.
