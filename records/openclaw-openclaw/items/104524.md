## Label Justifications

- `P1`: A single stalled Telegram Bot API request can hold a live channel lane for up to 500 seconds and delay subsequent inbound and outbound work.
- `impact:ux-friction`: The lane appears unresponsive and ordinary logs do not identify the stalled request, creating substantial diagnosis and recovery burden.

## Summary

Current main still leaves reachable Telegram Bot API methods without an OpenClaw timeout, allowing one stalled request to occupy a serialized delivery lane until grammY’s 500-second default expires. No linked fix PR or narrower canonical item owns this valid, focused reliability bug.

## What This Changes

Report that Telegram Bot API methods absent from the timeout table inherit grammY’s 500-second default and can block serialized reply delivery.

## Best Possible Solution

Give every non-getUpdates Bot API method a bounded 60-second default while retaining explicit shorter and media guards, configured higher timeout floors, abort propagation, and transport fallback behavior; handle broader delivery-lifecycle proposals separately.
