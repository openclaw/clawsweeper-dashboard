## Summary

Keep this PR open: the reported message-loss bug is valid, the queue-owned media approach is directionally sound, and the contributor supplied strong real-process proof, but the reclamation path appears able to delete media still needed by retry rows whose backoff deadline has not arrived.

## What This Changes

Adds a private delivery-queue media spool, stages authorized local attachments before durable enqueue, reclaims artifacts by producer-process identity, and releases them when queue rows become terminal.

## Best Possible Solution

Use a storage-layer query that enumerates every non-terminal, replayable queue row regardless of due time or startup cutoff, retain those exact spool paths during reclamation, and add a regression where a dead producer's row has a future `next_attempt_at`; also expose bounded cleanup diagnostics for indefinitely unverifiable generations.
