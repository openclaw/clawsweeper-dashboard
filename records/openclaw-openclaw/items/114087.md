## Summary

Keep this PR open. It is the active implementation candidate for Telegram Business Connect, but it still has concrete multi-account routing, inbound update sequencing, and outbound-action delivery blockers; it also lacks after-fix proof from a connected Telegram Business account.

## What This Changes

Adds Telegram Business Connect support to the bundled Telegram plugin so a connected business account's private chats can enter OpenClaw sessions and receive replies sent on that account's behalf.

## System Context

The Telegram plugin turns Telegram updates into OpenClaw channel events and session keys, then routes agent replies back through the Telegram Bot API. This PR adds Business Connect connection and chat-route state between inbound private-chat updates and outbound replies.

## Architecture Diagram

flowchart LR

  B --> C[Business connection and chat-route state]
  C --> D[OpenClaw session routing]
  D --> E[Agent reply or action]
  E --> F[Telegram Bot API business send]
  C --> G[Read receipt and connection checks]

## Best Possible Solution

Keep Business Connect in the Telegram plugin, but make persisted routes account-plus-chat scoped, extend the ordinary update sequencing/dedupe contract to Business updates, and either route every supported outbound action with the connection id or reject it explicitly before adding redacted real-account proof.
