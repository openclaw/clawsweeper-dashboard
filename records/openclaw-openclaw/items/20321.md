## Summary

Keep open: current main and v2026.6.11 still lack the requested bundled Telegram `members` group policy, and the related implementation PRs are closed unmerged. The chat-only-trigger plugin is useful adjacent prior art, but it does not replace a first-class Telegram group authorization mode.

## What This Changes

The issue requests a Telegram `groupPolicy: "members"` mode that authorizes new groups when all current members are in the trusted user allowlist.

## Best Possible Solution

Define and land an explicit bundled Telegram `members` policy across config schema/metadata, inbound and native-command authorization, security audit semantics, docs, and focused tests while preserving existing policies and failing closed on uncertain membership checks.

## Reproduction Assessment

Yes for the missing capability: source inspection shows current main and v2026.6.11 reject `groupPolicy: "members"` at the type/schema layer and have no Telegram membership-verification branch. This is a feature request rather than a broken shipped policy, so no live Telegram repro was run.

## Solution Assessment

Unclear until maintainers choose the access-control contract. If accepted, the maintainable solution belongs in the bundled Telegram group-policy path rather than relying on the adjacent chat-only-trigger plugin workaround, because inbound and native-command authorization own this safety boundary.
