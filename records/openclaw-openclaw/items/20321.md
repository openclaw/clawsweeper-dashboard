## Summary

Keep open: current main and the latest release still expose only `open`, `disabled`, and `allowlist`, and the same-purpose implementation PRs are closed unmerged. The chat-only-trigger plugin is useful adjacent workaround context, but it does not provide the requested bundled Telegram authorization policy.

## What This Changes

Request to add a bundled Telegram `groupPolicy: "members"` mode that authorizes new groups by trusted member IDs instead of per-group chat IDs.

## Best Possible Solution

Define and land an explicit bundled Telegram `members` policy across config schema/metadata, inbound and native-command authorization, security audit semantics, docs, and focused tests while preserving existing `open`, `disabled`, and `allowlist` behavior.
