## Summary

Keep open: current main and the latest release still expose only `open`, `disabled`, and `allowlist` for Telegram group policy, while the requested `members` mode changes Telegram group authorization and needs an explicit maintainer/security decision.

## What This Changes

Request a Telegram `groupPolicy: "members"` mode that authorizes newly created groups when all current members are trusted users instead of requiring every group chat ID to be allowlisted.

## Best Possible Solution

Define and land a bundled Telegram-only `members` policy across config schema/metadata, inbound and native-command authorization, security-audit semantics, docs, and focused tests, with fail-closed behavior and unchanged existing policies.
