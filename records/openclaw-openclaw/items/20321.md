## Label Justifications

- `impact:security`: The requested policy changes who can trigger agents from Telegram groups and how group membership is trusted.

## Summary

Keep open: current main and v2026.6.11 still expose only `open`, `disabled`, and `allowlist` group policies, and the Telegram inbound/native-command path still has no all-current-members authorization mode. The chat-only-trigger community plugin and the closed implementation PRs are useful prior art, but they do not replace a bundled Telegram authorization policy.

## What This Changes

This issue requests a Telegram `groupPolicy: "members"` mode that allows newly created groups when every current participant is trusted via user allowlists instead of requiring each group chat ID in config.

## Best Possible Solution

Define and land a bundled Telegram-only `members` policy across config schema/metadata, inbound and native-command authorization, security audit semantics, docs, and focused tests, with fail-closed behavior and unchanged existing policies.
