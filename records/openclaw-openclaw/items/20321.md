## Summary

Keep open: current main and `v2026.6.11` still expose only `open`, `disabled`, and `allowlist`, so the requested bundled Telegram `members` policy remains missing; the chat-only-trigger plugin is useful adjacent workaround context, not the requested authorization mode.

## What This Changes

Request adding a Telegram `groupPolicy: "members"` mode that authorizes new groups when all current members are trusted users instead of requiring each group chat ID in config.

## Best Possible Solution

Define and land an explicit bundled Telegram `members` policy across config schema/metadata, inbound and native-command authorization, security-audit semantics, docs, and focused tests while preserving existing policies.
