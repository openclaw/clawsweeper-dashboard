## Summary

Keep open: current main and the latest release still expose only `open`, `disabled`, and `allowlist`, so the requested bundled Telegram `members` group policy remains unimplemented and needs maintainer/security direction before a repair lane is safe.

## What This Changes

Request a Telegram `groupPolicy: "members"` mode that authorizes newly created groups when all current participants are in a trusted user allowlist instead of requiring each group chat ID to be configured.

## Best Possible Solution

Define and land an explicit bundled Telegram `members` policy across config schema/metadata, inbound and native-command authorization, security audit semantics, docs, and focused tests while preserving existing `open`, `disabled`, and `allowlist` behavior.
