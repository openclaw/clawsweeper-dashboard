## Summary

Keep open: current main and the latest release still accept only `open`, `disabled`, and `allowlist`, so the requested bundled Telegram `members` group policy remains missing. The related implementation PRs are closed unmerged, and the published chat-only-trigger plugin is useful workaround context rather than the requested bundled Telegram authorization mode.

## What This Changes

The issue requests a Telegram `groupPolicy: "members"` mode that authorizes new groups based on trusted participant membership instead of manually allowlisting each group chat ID.

## Best Possible Solution

Define and land an explicit bundled Telegram `members` policy across config schema/metadata, inbound and native-command authorization, security audit semantics, docs, and focused tests while preserving existing `open`, `disabled`, and `allowlist` behavior.
