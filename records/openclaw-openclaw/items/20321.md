## Label Justifications

- `impact:security`: The issue changes who may invoke an OpenClaw agent in Telegram groups.
- `impact:ux-friction`: The current allowlist-by-group workflow forces extra manual config when users create many Telegram groups.

## Summary

Keep open: current main and the latest release still expose only `open`, `disabled`, and `allowlist`, so the requested bundled Telegram `members` group policy is not implemented. The closed implementation PRs and the chat-only-trigger community plugin are useful prior art/workaround context, but they do not replace a maintained Telegram authorization policy.

## What This Changes

The issue requests a Telegram `groupPolicy: "members"` mode that authorizes new groups based on trusted participants instead of allowlisting every group chat ID.

## Best Possible Solution

Define and land an explicit bundled Telegram `members` policy with config schema/metadata, inbound and native-command authorization, security audit semantics, docs, and tests that preserve existing `open`, `disabled`, and `allowlist` behavior.
