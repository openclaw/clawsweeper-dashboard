## Summary

Keep open: current `main` and latest release still expose only `open`, `disabled`, and `allowlist` for Telegram group policy, while the requested `members` policy remains a security-sensitive product/config decision rather than conservative cleanup-close material.

## What This Changes

The issue requests a Telegram `groupPolicy: "members"` mode that authorizes new groups based on trusted users rather than allowlisted group chat IDs.

## Best Possible Solution

Define and land a bundled Telegram-only `members` policy across config schema/metadata, inbound and native-command authorization, security audit semantics, docs, and focused tests, with fail-closed behavior and unchanged existing policies.
