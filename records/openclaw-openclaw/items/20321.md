Keep open: current main and v2026.6.11 still only support Telegram group policies `open`, `disabled`, and `allowlist`; the requested `members` policy remains a security-sensitive product/config decision rather than cleanup-close material.

## What This Changes

The issue requests a Telegram `groupPolicy: "members"` mode that lets bots reply in newly created groups when every current group member is in the trusted user allowlist.

## Best Possible Solution

Define and land a bundled Telegram-only `members` policy across config schema/metadata, inbound and native-command authorization, security audit semantics, docs, and focused tests, with fail-closed behavior and unchanged existing policies.
