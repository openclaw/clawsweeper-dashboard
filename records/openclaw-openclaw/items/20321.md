## Label Justifications

- `P2`: This is a normal-priority Telegram access-control enhancement with clear usability value but no current core outage.
- `impact:security`: The requested policy changes who may trigger an agent from Telegram groups and how group membership is trusted.
- `impact:ux-friction`: The current supported path requires manually registering each Telegram group chat ID, which creates recurring setup friction for heavy Telegram group users.

## Summary

Keep open: current main and the latest release still accept only `open`, `disabled`, and `allowlist`, so the requested bundled Telegram `members` policy is not implemented. The closed implementation PRs and the chat-only-trigger community plugin are useful prior art/workaround context, but they do not replace a maintained Telegram authorization policy.

## What This Changes

The issue requests a Telegram `groupPolicy: "members"` mode that authorizes new groups by trusted participants instead of requiring each group chat ID to be allowlisted.

## Best Possible Solution

Define and land an explicit bundled Telegram `members` policy across config schema/metadata, inbound and native-command authorization, security audit semantics, docs, and focused tests while preserving existing `open`, `disabled`, and `allowlist` behavior.
