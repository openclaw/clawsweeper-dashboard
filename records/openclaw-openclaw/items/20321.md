## Summary

Keep open: current main and the latest release still only support `open`, `disabled`, and `allowlist`, so the bundled Telegram `members` group policy remains missing. The closed implementation PRs and the chat-only-trigger plugin are useful prior art/workarounds, but the remaining work changes Telegram access-control semantics and needs maintainer/security direction before implementation.

## What This Changes

Request a Telegram `groupPolicy: "members"` mode that allows newly created groups when all current Telegram members are trusted users instead of requiring each group chat ID to be configured.

## Best Possible Solution

Define and land an explicit bundled Telegram `members` policy across config schema/metadata, inbound and native-command authorization, security audit semantics, docs, and focused tests while preserving existing `open`, `disabled`, and `allowlist` behavior.
