## Summary

Keep open: current main and the latest release still expose only `open`, `disabled`, and `allowlist`, so the requested bundled Telegram `members` group policy remains missing and needs maintainer/security direction before implementation.

## What This Changes

The issue requests a Telegram `groupPolicy: "members"` mode that authorizes new groups when all current members are trusted users instead of requiring each group chat ID to be allowlisted.

## Best Possible Solution

Define and land an explicit bundled Telegram `members` policy across config schema/metadata, inbound and native-command authorization, security audit semantics, docs, and focused tests while preserving existing `open`, `disabled`, and `allowlist` behavior.
