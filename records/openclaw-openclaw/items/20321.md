## Summary

Keep open: current main and the latest release still only support `open`, `disabled`, and `allowlist` for Telegram group policy, so the requested bundled `members` policy remains missing and needs maintainer/security direction.

## What This Changes

Request to add a Telegram `groupPolicy: "members"` mode that authorizes groups by verifying trusted members instead of requiring every group chat ID to be allowlisted.

## Best Possible Solution

Define and land an explicit bundled Telegram `members` policy across config schema/metadata, inbound and native-command authorization, security audit semantics, docs, and focused tests while preserving existing `open`, `disabled`, and `allowlist` behavior.
