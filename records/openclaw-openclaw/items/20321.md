## Summary

Keep open: current main and latest release still only support `open`, `disabled`, and `allowlist`, while the requested Telegram `members` policy changes a real authorization boundary. The closed implementation PRs and the chat-only-trigger community plugin are useful prior art/workarounds, but no merged/open canonical PR currently owns the bundled policy.

## What This Changes

The issue requests a Telegram `groupPolicy: "members"` mode that authorizes newly created groups based on allowlisted members instead of allowlisted group chat IDs.

## Best Possible Solution

Define and land an explicit Telegram-only `members` policy with config types/schema/metadata, inbound and native-command authorization, security-audit semantics, docs, and focused tests; keep the community chat-only-trigger plugin as a workaround rather than treating it as the core policy.
