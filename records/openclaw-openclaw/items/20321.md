## Summary

Keep open: current main and v2026.6.11 still only support `open`, `disabled`, and `allowlist` group policies, while this issue asks for a new Telegram authorization mode with security-sensitive membership semantics. The closed unmerged implementation attempts and the chat-only-trigger plugin are useful prior art and workaround context, but they do not replace a bundled Telegram inbound/native-command policy.

## What This Changes

Request a Telegram `groupPolicy: "members"` mode that authorizes new groups when every current member is in a trusted user allowlist, avoiding per-group chat ID registration.

## Best Possible Solution

Define and land a bundled Telegram-only `members` policy across config schema/metadata, inbound and native-command authorization, security audit semantics, docs, and focused tests, with fail-closed behavior and unchanged existing policies.
