## Summary

Keep open: current main and the latest release still only support `open`, `disabled`, and `allowlist`, so the requested bundled Telegram `members` group policy remains missing and needs maintainer/security direction before implementation.

## What This Changes

Request a Telegram `groupPolicy: "members"` mode that allows new groups when every current group member is trusted by user allowlist rather than by group chat ID.

## Best Possible Solution

Define and land a bundled Telegram-only `members` policy across config schema/metadata, inbound and native-command authorization, security audit semantics, docs, and focused tests, with fail-closed behavior and unchanged existing policies.
