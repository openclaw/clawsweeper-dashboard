## Summary

Keep open: current main and the latest release still only support `open`, `disabled`, and `allowlist`, so the requested bundled Telegram `members` policy is not implemented. The closed implementation PRs and the chat-only-trigger community plugin are useful prior art/workaround context, but they do not replace a maintained Telegram authorization policy.

## What This Changes

The issue requests a Telegram `groupPolicy: "members"` mode that authorizes new groups based on trusted participants instead of per-group chat IDs.

## Best Possible Solution

Define and land an explicit bundled Telegram `members` policy across config schema/metadata, inbound and native-command authorization, security-audit semantics, docs, and focused tests while preserving existing `open`, `disabled`, and `allowlist` behavior.
