## Summary

Keep open: current main and v2026.6.11 still expose only `open`, `disabled`, and `allowlist`, and Telegram inbound/native-command authorization has no all-current-members verification branch. The closed implementation PRs and the chat-only-trigger plugin are useful prior art/workarounds, but they do not replace a bundled Telegram authorization policy with defined security semantics.

## What This Changes

Add a Telegram `groupPolicy: "members"` mode that authorizes groups based on trusted current members instead of manually allowlisting each group chat ID.

## Best Possible Solution

Define and land a bundled Telegram-only `members` policy across config schema/metadata, inbound and native-command authorization, security audit semantics, docs, and focused tests, with fail-closed behavior and unchanged existing policies.
