## Summary

Keep open: current main and the latest release still expose only `open`, `disabled`, and `allowlist`, so the requested bundled Telegram `members` group policy remains missing and still needs maintainer/security direction.

## What This Changes

The issue requests a Telegram `groupPolicy: "members"` mode that allows newly created groups when all group participants are trusted users rather than requiring each group chat ID to be allowlisted.

## Best Possible Solution

Define and land an explicit bundled Telegram `members` policy across config schema/metadata, inbound and native-command authorization, security audit semantics, docs, and focused tests while preserving existing `open`, `disabled`, and `allowlist` behavior.
