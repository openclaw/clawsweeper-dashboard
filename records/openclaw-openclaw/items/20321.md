## Summary

Keep open: current main and the latest release still only support `open`, `disabled`, and `allowlist`, so the requested bundled Telegram `members` group policy remains missing and needs maintainer/security direction before implementation.

## What This Changes

Request to add a Telegram `groupPolicy: "members"` mode that authorizes newly created groups when every current group member is trusted via `groupAllowFrom` or bot identity.

## Best Possible Solution

Define and land an explicit bundled Telegram `members` policy across config schema/metadata, inbound and native-command authorization, security audit semantics, docs, and focused tests while preserving existing `open`, `disabled`, and `allowlist` behavior.
