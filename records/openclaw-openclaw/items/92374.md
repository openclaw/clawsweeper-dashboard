## Summary

Keep this open: current `main` and latest release still omit `message_sending` from configured channel `beforeDeliver` delivery, while the linked PRs are open candidate fixes rather than merged replacements.

## What This Changes

The issue reports that `message_sending` plugin hooks are silently bypassed for channel agent-reply delivery paths, especially Telegram paths with custom `beforeDeliver`.

## Best Possible Solution

Review and land one canonical fix that runs `message_sending` exactly once per visible outbound agent reply across shared dispatcher delivery and Telegram preview-finalized streaming, with focused regression tests and Telegram-equivalent proof.

## Reproduction Assessment

Yes. Current-main source deterministically chooses the configured `beforeDeliver` branch that excludes `message_sending`, and the adjacent test asserts the hook is not called on that path.

## Solution Assessment

Yes as a bug-fix direction, but it should be resolved through one reviewed linked PR rather than another issue-queued repair. The safest fix must cover configured dispatcher delivery and Telegram streamed finals without double-running hooks.
