## Label Justifications

- `P1`: A documented outbound interception hook is silently bypassed on primary channel reply paths, affecting real safety and delivery workflows.
- `impact:security`: Safety, DLP, compliance, and audit plugins using `message_sending` can silently fail open on outbound agent replies.
- `impact:message-loss`: Plugin cancellation and rewrite decisions can be ignored, causing messages to be delivered when a hook expected suppression or modification.

## Summary

Keep this open: current main and the latest release still skip the documented `message_sending` hook when a channel supplies `beforeDeliver`, and the linked PRs are still open candidate fixes rather than merged replacements.

## What This Changes

The issue reports that documented plugin `message_sending` hooks are skipped for agent-reply delivery paths when channels provide `beforeDeliver`, including Telegram direct and streamed reply paths.

## Best Possible Solution

Land one canonical exactly-once repair that composes `message_sending` for configured dispatcher branches while preserving Telegram delivery-owned coverage for direct, fallback, media, native-command, and streamed-final paths.

## Reproduction Assessment

Yes. Source inspection on current main shows configured `beforeDeliver` excludes `buildMessageSendingBeforeDeliver`, Telegram supplies that configured no-op path, and a current test explicitly expects `runMessageSending` not to run in that case.

## Solution Assessment

Yes as a direction, but not yet implemented. The best path is to restore the documented pre-send hook through one exactly-once delivery model; the open PRs are candidates and none is merged.
