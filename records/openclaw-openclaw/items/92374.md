## Label Justifications

- `P1`: A documented outbound interception hook is silently bypassed on primary channel reply paths, affecting real safety and delivery workflows.
- `impact:security`: Safety, DLP, compliance, and audit plugins using `message_sending` can silently fail open on outbound agent replies.
- `impact:message-loss`: Plugin cancellation and rewrite decisions can be ignored, so messages may be delivered when a hook expected suppression or modification.

## Summary

Keep open: current main and latest v2026.6.11 still skip the documented `message_sending` hook when a channel supplies `beforeDeliver`, and the linked PRs are candidate fixes rather than merged replacements.

## What This Changes

Ensure plugin `message_sending` hooks run on channel agent-reply delivery paths, including Telegram configured `beforeDeliver` and streamed-final delivery.

## Best Possible Solution

Land one canonical fix that runs `message_sending` exactly once per visible outbound agent reply across configured dispatcher delivery and Telegram streamed finals, with focused regression tests and real Telegram proof.

## Reproduction Assessment

Yes. Current-main source shows configured `beforeDeliver` excludes `message_sending`, Telegram supplies configured `beforeDeliver`, and the adjacent test asserts the hook is not called on that path; I did not run live Telegram in this read-only review.

## Solution Assessment

Yes as a direction, but not via a narrow one-liner alone. The best fix should restore the documented pre-send hook through an exactly-once delivery model and cover the Telegram streamed-final path.
