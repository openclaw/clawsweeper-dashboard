## Label Justifications

- `P1`: A documented outbound interception hook is silently bypassed on primary channel reply paths, affecting real safety and delivery workflows.
- `impact:security`: Safety, DLP, compliance, and audit plugins using `message_sending` can silently fail open on outbound agent replies.
- `impact:message-loss`: Plugin cancellation and rewrite decisions can be ignored, causing messages to be delivered when a hook expected suppression or modification.

## Summary

Keep this open: current main and the latest release still skip the documented `message_sending` hook when a channel supplies `beforeDeliver`, and several linked PRs remain open candidate fixes rather than merged replacements.

## What This Changes

The issue requests restoring `message_sending` plugin hook coverage for channel agent-reply delivery paths, especially Telegram configured `beforeDeliver` and streamed preview-finalized replies.

## Best Possible Solution

Land one canonical fix that runs `message_sending` exactly once per visible outbound agent reply across configured dispatcher delivery and Telegram preview-finalized streaming, with focused regression tests and Telegram-equivalent proof.

## Reproduction Assessment

Yes. Current-main source deterministically chooses the configured `beforeDeliver` branch that excludes `message_sending`, Telegram supplies that hook, and the existing test still asserts the bypass; I did not run a live Telegram repro in this read-only review.

## Solution Assessment

Yes as a direction: restore the documented pre-send hook through one exactly-once delivery model. A dispatcher-only one-liner is too narrow because Telegram already has delivery-owned hook calls and a streamed-final path outside `deliverReplies`.
