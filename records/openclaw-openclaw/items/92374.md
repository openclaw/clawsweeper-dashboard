## Label Justifications

- `P1`: A documented outbound interception hook is silently bypassed on primary channel reply paths, affecting real safety and delivery workflows.
- `impact:security`: Safety, DLP, compliance, and audit plugins using `message_sending` can silently fail open on outbound agent replies.
- `impact:message-loss`: Plugin cancellation and rewrite decisions can be ignored, so messages may be delivered despite a hook expecting suppression or modification.

## Summary

Keep this open: current main and latest release still skip the documented `message_sending` hook on configured channel `beforeDeliver` paths, and the linked PRs are open candidate fixes rather than merged replacements.

## What This Changes

The issue asks OpenClaw to make plugin `message_sending` rewrite/cancel hooks run on channel agent-reply delivery paths, including Telegram paths that supply `beforeDeliver`.

## Best Possible Solution

Land one canonical exactly-once repair that runs `message_sending` for configured dispatcher replies and Telegram preview-finalized streaming without double-running Telegram delivery-owned hook paths.

## Reproduction Assessment

Yes. Current-main source deterministically chooses the configured `beforeDeliver` branch that excludes `message_sending`, and Telegram supplies that hook; a July 4 comment also reports live 2026.6.9 Telegram confirmation.

## Solution Assessment

Yes as a direction, but not by merging a narrow dispatcher-only branch without exactly-once proof. The best fix should coordinate the shared dispatcher seam with Telegram delivery-owned and preview-finalized streaming paths.
