## Label Justifications

- `P1`: A documented outbound interception hook is silently bypassed on primary channel reply paths, affecting real safety and delivery workflows.
- `impact:security`: Safety, DLP, compliance, and audit plugins using `message_sending` can silently fail open on outbound agent replies.
- `impact:message-loss`: Plugin cancellation and rewrite decisions can be ignored, so messages may be delivered when a hook expected suppression or modification.

## Summary

Keep this open: current main still omits `message_sending` from the configured `beforeDeliver` dispatcher branch, Telegram still selects that branch, and the linked PRs are open candidate fixes rather than merged replacements.

## What This Changes

The issue requests that plugin `message_sending` hooks run on channel agent-reply delivery paths when a channel supplies `beforeDeliver`, including Telegram’s direct and streamed-final reply paths.

## Best Possible Solution

Land one canonical fix that runs `message_sending` exactly once per visible outbound agent reply across configured dispatcher delivery and Telegram preview-finalized streaming, with focused regression coverage and Telegram-equivalent proof.

## Reproduction Assessment

Yes. Current-main source deterministically selects the configured `beforeDeliver` branch that excludes `message_sending`, and the existing test asserts the hook is not called on that branch; no live Telegram repro was run in this read-only review.

## Solution Assessment

Yes as a direction: restoring the documented pre-send hook through an exactly-once delivery model is the narrow maintainable fix. A simple dispatcher-only one-liner is too narrow because Telegram has delivery-owned hook calls and a preview-finalized path outside `deliverReplies`.
