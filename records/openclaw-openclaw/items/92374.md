## Label Justifications

- `P1`: The issue breaks a documented outbound rewrite/cancel hook on primary channel reply paths, affecting real safety and delivery-policy plugins.
- `impact:security`: `message_sending` is the documented pre-send safety boundary for DLP, compliance rewrites, and cancellation plugins, and this bypass makes those plugins fail open.
- `impact:message-loss`: The bypass changes delivery semantics by ignoring plugin rewrites and cancellations that are supposed to suppress or modify outbound channel messages.

## Summary

Keep this open: current main and the latest release still skip the documented `message_sending` hook when a channel supplies `beforeDeliver`, and the linked pull requests are unmerged candidate fixes rather than landed replacements.

## What This Changes

The issue asks OpenClaw to invoke plugin `message_sending` rewrite/cancel hooks on channel agent-reply delivery paths, including Telegram paths that configure `beforeDeliver` and streamed final replies.

## Best Possible Solution

Land one canonical exactly-once fix that composes the shared dispatcher gate while preserving Telegram delivery-owned and streamed-final `message_sending` coverage, then close this issue after the merge ships or reaches main.

## Reproduction Assessment

Yes. Current source and tests show that a configured channel `beforeDeliver` excludes `buildMessageSendingBeforeDeliver`, and Telegram supplies such a hook; I did not run a live Telegram repro because this is a read-only review.

## Solution Assessment

Yes, the best fix is to restore the documented hook coverage at the dispatcher and Telegram delivery ownership boundaries with exactly-once semantics. The open linked pull requests should be reviewed or repaired rather than creating another competing fix from this issue.
