## Label Justifications

- `P1`: A documented outbound interception hook is silently bypassed on primary channel reply paths, affecting real safety and delivery workflows.
- `impact:security`: DLP, compliance, and safety plugins using `message_sending` can fail open without an operator-visible failure.

## Summary

Keep this open: current main and the latest release still omit `message_sending` from the channel-configured `beforeDeliver` branch, while multiple open PRs are candidate fixes rather than merged replacements.

## What This Changes

The issue asks for documented `message_sending` plugin hooks to run on channel agent-reply delivery paths, including Telegram paths that install their own `beforeDeliver` hook.

## Best Possible Solution

Land one canonical fix that runs `message_sending` exactly once per visible outbound agent reply across configured dispatcher delivery and Telegram preview-finalized streaming, with regression tests and Telegram-equivalent proof.

## Reproduction Assessment

Yes. Current-main source deterministically chooses a configured `beforeDeliver` branch that excludes `message_sending`, and Telegram supplies that hook; I did not run a live Telegram repro in this read-only review.

## Solution Assessment

Yes as a direction, but the best fix is broader than a dispatcher-only one-liner: preserve exactly-once `message_sending` semantics across configured `beforeDeliver` and Telegram preview-finalized delivery.
