## Label Justifications

- `P1`: A documented outbound interception hook is silently bypassed on primary channel reply paths, affecting real safety and delivery workflows.
- `impact:security`: Safety, DLP, compliance, and audit plugins using `message_sending` can silently fail open on outbound agent replies.
- `impact:message-loss`: Plugin cancellation and rewrite decisions can be ignored, causing messages to be delivered when a hook expected suppression or modification.

## Summary

Keep this open: current main and the latest release still omit `message_sending` from the channel-configured `beforeDeliver` dispatcher branch, and the linked PRs are open candidate fixes rather than merged replacements.

## What This Changes

The issue requests restoring documented `message_sending` hook coverage for channel agent replies, including Telegram paths that currently supply their own `beforeDeliver` and streamed final delivery.

## Best Possible Solution

Land one canonical fix that runs `message_sending` exactly once per visible outbound agent reply across shared dispatcher delivery and Telegram preview-finalized streaming, with focused regression tests and Telegram proof.

## Reproduction Assessment

Yes. Current-main source deterministically chooses the configured `beforeDeliver` branch that excludes `message_sending`, Telegram supplies that hook, and a July 4 comment confirms the same symptom on live Telegram agent replies in 2026.6.9.

## Solution Assessment

Yes as a direction, but not as a dispatcher-only one-liner. The maintainable fix needs a single exactly-once hook ownership model covering configured dispatcher paths and Telegram streamed finalization without double-running Telegram delivery hooks.
