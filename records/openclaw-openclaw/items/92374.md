## Label Justifications

- `P1`: A documented outbound interception hook is silently bypassed on primary channel reply paths, affecting real safety and delivery workflows.
- `impact:security`: Safety, DLP, compliance, and audit plugins using `message_sending` can silently fail open on outbound agent replies.
- `impact:message-loss`: Plugin cancellation and rewrite decisions can be ignored, causing messages to be delivered when a hook expected suppression or modification.

## Summary

Keep this open: current main and the latest release still omit `message_sending` from configured `beforeDeliver` dispatcher paths, and the linked PRs are open candidate fixes rather than merged replacements.

## What This Changes

The issue asks OpenClaw to ensure plugin `message_sending` hooks run on channel agent-reply delivery paths, including Telegram configured `beforeDeliver` and streamed preview-finalized replies.

## Best Possible Solution

Land one canonical fix that runs `message_sending` exactly once per visible outbound agent reply across configured dispatcher delivery and Telegram preview-finalized streaming, with focused regression tests and Telegram-equivalent proof.

## Reproduction Assessment

Yes. Current main and `v2026.6.11` both compose only the channel `beforeDeliver` and `reply_payload_sending` on configured dispatcher paths, and the issue comments include a 2026.6.9 Telegram confirmation.

## Solution Assessment

Yes as a direction, but not via a narrow dispatcher-only one-liner. The maintainable fix should restore the documented pre-send hook with an exactly-once model covering shared dispatcher delivery and Telegram streamed finals.
