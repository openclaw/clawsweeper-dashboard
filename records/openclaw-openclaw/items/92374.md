## Label Justifications

- `P1`: A documented outbound interception hook is silently bypassed on primary channel reply paths, affecting real safety and delivery workflows.
- `impact:security`: Safety, DLP, compliance, and audit plugins using `message_sending` can silently fail open on outbound agent replies.
- `impact:message-loss`: Plugin cancellation and rewrite decisions can be ignored, causing messages to be delivered when a hook expected suppression or modification.

## Summary

Keep this open: current main and the latest release still skip the documented `message_sending` hook when a channel supplies `dispatcherOptions.beforeDeliver`, and the open linked PRs are candidate fixes rather than merged replacements.

## What This Changes

The issue reports that documented plugin `message_sending` pre-send hooks are bypassed for channel agent replies, especially Telegram paths that provide a no-op `beforeDeliver`.

## Best Possible Solution

Merge one canonical fix that enforces `message_sending` exactly once per visible outbound agent reply across configured dispatcher delivery and Telegram preview-finalized streaming, then close this issue from the merged PR.

## Reproduction Assessment

Yes for source-level reproduction: current main chooses the configured `beforeDeliver` branch that excludes `message_sending`, and the current test asserts that `runMessageSending` is not called in that case. I did not run a live Telegram session in this read-only review.

## Solution Assessment

Yes as a direction: restoring the documented pre-send hook is the right fix. The best implementation should be an exactly-once delivery model rather than a dispatcher-only one-liner, because Telegram normal delivery already has hook handling while preview-finalized streaming does not.
