## Label Justifications

- `P1`: A documented outbound interception hook is silently bypassed on primary channel reply paths, affecting real safety and delivery workflows.
- `impact:security`: Safety, DLP, compliance, and audit plugins using `message_sending` can silently fail open on outbound agent replies.
- `impact:message-loss`: Plugin cancellation and rewrite decisions can be ignored, causing messages to be delivered when a hook expected suppression or modification.

## Summary

Keep this open: current main still omits the documented `message_sending` hook from the configured `beforeDeliver` branch, Telegram still supplies that branch, and the streamed preview-finalized path still does not run the pre-send hook. The open linked PRs are candidate fixes, not merged replacements.

## What This Changes

The issue requests restoring documented `message_sending` hook execution for channel agent-reply paths, including Telegram configured `beforeDeliver` and streamed finals.

## Best Possible Solution

Land one canonical fix that runs `message_sending` exactly once per visible outbound agent reply across shared dispatcher delivery and Telegram preview-finalized streaming, with focused regression tests and live Telegram proof.

## Reproduction Assessment

Yes. Current-main source deterministically chooses the configured `beforeDeliver` branch that excludes `message_sending`, Telegram supplies that hook, and a live user comment confirms the same symptoms on v2026.6.9; I did not run a live Telegram repro in this read-only review.

## Solution Assessment

Yes as a direction, but not as a dispatcher-only one-liner. The best fix needs an exactly-once model because Telegram already runs `message_sending` in `deliverReplies` for normal replies while preview-finalized streaming still needs coverage.
