## Label Justifications

- `P1`: A documented outbound interception hook is silently bypassed on primary channel reply paths, affecting real safety and delivery workflows.
- `impact:security`: Safety, DLP, compliance, and audit plugins using `message_sending` can silently fail open on outbound agent replies.

## Summary

Keep this open: current main and latest release v2026.6.11 still skip the documented `message_sending` hook when a channel supplies `beforeDeliver`, Telegram still supplies that hook, and the linked PRs are open candidate fixes rather than merged replacements.

## What This Changes

The issue reports that plugin `message_sending` hooks are bypassed on channel agent-reply delivery paths, especially Telegram paths with channel-supplied `beforeDeliver`.

## Best Possible Solution

Land one canonical fix that runs `message_sending` exactly once per visible outbound agent reply across shared dispatcher delivery and Telegram preview-finalized streaming, with focused regression tests and Telegram-equivalent proof.

## Reproduction Assessment

Yes. Current-main source deterministically chooses the configured `beforeDeliver` branch that excludes `message_sending`, and Telegram supplies that branch; I did not run a live Telegram repro in this read-only review.

## Solution Assessment

Yes as a direction. The maintainable solution is one canonical exactly-once hook path covering the shared dispatcher branch and Telegram preview-finalized streaming, rather than a dispatcher-only one-liner that can leave streamed finals uncovered or double-run Telegram delivery hooks.
