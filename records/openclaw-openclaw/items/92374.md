## Label Justifications

- `P1`: A documented outbound interception hook can be silently bypassed on primary agent-reply paths, breaking real safety and delivery workflows.
- `impact:security`: Safety, DLP, compliance, and audit plugins using `message_sending` can fail open without an operator-visible error.
- `impact:message-loss`: Plugin cancellation and rewrite decisions can be ignored, so messages may be delivered when a hook expected suppression or modification.

## Summary

Keep this open: current main and latest v2026.6.11 still omit `message_sending` from the configured `beforeDeliver` dispatcher branch, and open linked PRs are candidate fixes rather than merged replacements.

## What This Changes

The issue asks OpenClaw to make documented `message_sending` plugin hooks run on channel agent-reply delivery paths that provide their own `beforeDeliver`, including Telegram streamed finals.

## Best Possible Solution

Review and land one canonical exactly-once fix that covers configured dispatcher delivery, normal Telegram delivery, and Telegram preview-finalized streaming with focused regression tests and live Telegram-equivalent proof.

## Reproduction Assessment

Yes for source reproduction: current main deterministically omits `buildMessageSendingBeforeDeliver` from the configured `beforeDeliver` branch, and Telegram/Discord provide channel `beforeDeliver` hooks. I did not run a live Telegram repro in this read-only pass.

## Solution Assessment

Yes as a direction: restore the documented pre-send hook through an exactly-once delivery model. A dispatcher-only one-liner is too narrow because Telegram already has delivery-owned hook calls and a streamed-final path outside `deliverReplies`.
