## Summary

Keep this issue open: it has a current assignee and an open PR explicitly positioned as its fix, so it should not close before a maintainer confirms the canonical implementation and it lands. Current main has a centralized outbound-delivery hook path, but the available evidence does not prove that Telegram preview-finalized streaming replies enter that path exactly once; that is the remaining decision point.

## What This Changes

Repair plugin `message_sending` hook coverage so channel agent replies, including Telegram streaming finals, can be inspected, rewritten, or cancelled without bypassing the documented delivery-policy seam.

## System Context

Channel-originated agent runs produce normalized reply payloads that are delivered through channel adapters. Plugin message hooks sit at the outbound-delivery boundary, where they can rewrite or suppress content before a transport sends it and then observe the delivered result.

## Architecture Diagram

  F --> H[message_sent observation]

## Best Possible Solution

Establish one canonical outbound policy boundary for every visible channel reply, explicitly prove its Telegram preview-finalized behavior is once per message, and then land one focused fix with regression coverage for normal, cancelled, rewritten, and streamed replies.
