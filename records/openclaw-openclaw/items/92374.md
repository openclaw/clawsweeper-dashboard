## Summary

Keep this open: current main and the latest release still omit the documented `message_sending` gate when a channel supplies `beforeDeliver`, and the linked PRs are open candidate fixes rather than merged replacements.

## What This Changes

The issue reports that documented plugin `message_sending` hooks are silently bypassed on channel agent-reply delivery paths, especially Telegram configured `beforeDeliver` and streamed preview-finalized replies.

## Best Possible Solution

Land one canonical fix that runs `message_sending` exactly once per visible outbound agent reply across configured dispatcher delivery and Telegram preview-finalized streaming, with focused regression tests and Telegram proof.

## Reproduction Assessment

Yes. Current-main source deterministically chooses the configured `beforeDeliver` branch that excludes `message_sending`, and Telegram supplies that hook; I did not run a live Telegram repro in this read-only review.

## Solution Assessment

Yes as a direction: restore the documented pre-send hook through one exactly-once delivery model. A dispatcher-only one-liner is too narrow because Telegram already has delivery-owned hook calls and a streamed-final path outside `deliverReplies`.
