## Summary

Keep this open: current `main` and `v2026.6.11` still omit `message_sending` from configured `beforeDeliver` dispatcher branches, and the linked PRs are open candidate fixes rather than merged replacements.

## What This Changes

The issue reports that plugin `message_sending` hooks are bypassed on channel agent-reply delivery paths, especially Telegram paths that provide a channel `beforeDeliver` hook.

## Best Possible Solution

Land one canonical exactly-once hook repair covering configured dispatcher delivery and Telegram streamed-final behavior, then close this issue with the merged PR and release provenance.

## Reproduction Assessment

Yes at source level: current-main dispatcher composition, the pinned dispatch test, and the latest release tag all show the configured `beforeDeliver` path omits `message_sending`. I did not run a live Telegram repro in this read-only review.

## Solution Assessment

Yes as a direction: restoring the documented pre-send hook with exactly-once semantics is the right fix. A dispatcher-only patch is too narrow unless it also accounts for Telegram delivery-owned and streamed-final paths.
