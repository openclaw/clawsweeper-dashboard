## Summary

Keep open: current main and the latest release still skip the documented `message_sending` hook when a channel supplies `beforeDeliver`, and the linked pull requests are unmerged candidate fixes rather than implemented replacements.

## What This Changes

The issue reports that plugin `message_sending` hooks are silently bypassed for channel agent-reply delivery paths when a channel provides its own `beforeDeliver`, especially Telegram.

## Best Possible Solution

Keep this issue open until one canonical fix lands that composes `message_sending` with channel `beforeDeliver` and covers Telegram preview-finalized replies exactly once, with focused tests and Telegram/security proof.

## Reproduction Assessment

Yes, source-reproducible rather than live-reproduced: current main routes configured `beforeDeliver` around `buildMessageSendingBeforeDeliver`, and the adjacent test explicitly expects `runMessageSending` not to run in that case.

## Solution Assessment

No, closing is not the best solution because the documented hook contract remains broken. The best fix is to land or repair a comprehensive candidate such as https://github.com/openclaw/openclaw/pull/93216 rather than accepting a one-sided branch that misses streaming or exactly-once semantics.
