## Label Justifications

- `P1`: A documented outbound interception hook is silently bypassed on primary channel reply paths used by safety and delivery-policy plugins.
- `impact:security`: Safety, DLP, compliance, and audit plugins using `message_sending` can fail open on outbound agent replies.
- `impact:message-loss`: Plugin cancellation and rewrite decisions can be ignored, so messages may be delivered when a hook expected suppression or modification.

## Summary

Keep this open: current main and latest release still skip the documented `message_sending` hook when a channel supplies `beforeDeliver`, and the linked PRs are open candidate fixes rather than merged replacements.

## What This Changes

The issue reports that plugin `message_sending` rewrite/cancel hooks are silently bypassed on channel agent-reply delivery paths, especially Telegram paths that provide `dispatcherOptions.beforeDeliver`.

## Best Possible Solution

Land one canonical fix that runs `message_sending` exactly once per visible outbound agent reply across shared dispatcher delivery and Telegram preview-finalized streaming, with focused regression tests and Telegram-equivalent proof.

## Reproduction Assessment

Yes. Current main and `v2026.6.11` route configured `beforeDeliver` through a chain that omits `buildMessageSendingBeforeDeliver`, and Telegram supplies such hooks; I did not run a live Telegram repro in this read-only pass.

## Solution Assessment

Yes as a direction. Restoring the documented pre-send hook through an exactly-once delivery model is the maintainable fix; a dispatcher-only one-liner is too narrow because Telegram already has delivery-owned hook calls and a streamed-final path outside normal delivery.
