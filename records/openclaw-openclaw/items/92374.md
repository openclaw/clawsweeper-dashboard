## Label Justifications

- `impact:security`: Safety, DLP, compliance, and audit plugins using `message_sending` can silently fail open on outbound agent replies.

## Summary

Keep this open: current main and v2026.6.11 still bypass the documented `message_sending` hook when a channel supplies `beforeDeliver`, and the linked PRs are unmerged implementation candidates rather than a landed fix.

## What This Changes

The issue asks OpenClaw to run plugin `message_sending` hooks on channel agent-reply delivery paths, including Telegram paths that provide `beforeDeliver` and streamed preview-finalized replies.

## Best Possible Solution

Land one canonical exactly-once hook fix that covers configured dispatcher delivery and Telegram preview-finalized streaming, with focused regression tests and Telegram-equivalent proof.

## Reproduction Assessment

Yes. Current-main source deterministically omits `message_sending` from the configured `beforeDeliver` branch, and Telegram supplies that branch; I did not run a live Telegram repro in this read-only review.

## Solution Assessment

Yes as a direction: restore the documented pre-send hook through an exactly-once delivery model. A dispatcher-only one-liner is too narrow because Telegram has both delivery-owned hook calls and a streamed-final path outside `deliverReplies`.
