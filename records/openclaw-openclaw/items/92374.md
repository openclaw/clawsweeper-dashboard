## Label Justifications

- `P1`: A documented outbound interception hook is silently bypassed on primary channel reply paths, affecting real safety and delivery workflows.
- `impact:security`: Safety, DLP, compliance, and audit plugins using `message_sending` can silently fail open on outbound agent replies.

## Summary

Keep this open: current main and latest release still skip the documented `message_sending` hook when a channel supplies `beforeDeliver`, and the linked PRs are open candidate fixes rather than merged replacements.

## What This Changes

The issue reports that plugin `message_sending` rewrite/cancel hooks are bypassed on channel agent-reply delivery paths, especially Telegram configured dispatcher and streamed-final paths.

## Best Possible Solution

Land one canonical repair that runs `message_sending` exactly once per visible outbound agent reply across shared dispatcher delivery and Telegram preview-finalized streaming, with focused regression tests and Telegram-equivalent proof.

## Reproduction Assessment

Yes. Current-main source deterministically chooses the configured `beforeDeliver` branch that excludes `message_sending`, Telegram supplies that hook, and the current test still asserts the bypass; I did not run a live Telegram repro in this read-only review.

## Solution Assessment

Yes as a direction: restoring the documented pre-send hook through one exactly-once delivery model is the maintainable fix. A dispatcher-only one-liner is too narrow because Telegram already has delivery-owned hook calls and a streamed-final path outside `deliverReplies`.
