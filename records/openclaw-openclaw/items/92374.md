## Label Justifications

- `P1`: A documented outbound interception hook is silently bypassed on primary channel reply paths, affecting real safety and delivery workflows.
- `impact:security`: Safety, DLP, compliance, and audit plugins using `message_sending` can silently fail open on outbound agent replies.
- `impact:message-loss`: Plugin cancellation or rewrite decisions can be ignored, causing messages to be delivered when a hook expected suppression or modification.

## Summary

Keep this open: current main and the latest checked release still omit `message_sending` from the channel-configured `beforeDeliver` branch, and the linked pull requests are open candidate fixes rather than merged replacements.

## What This Changes

The issue reports that documented plugin `message_sending` rewrite/cancel hooks are silently skipped for channel agent-reply delivery when a channel supplies its own `beforeDeliver`, especially Telegram replies.

## Best Possible Solution

Review, repair if needed, and land one canonical fix that runs `message_sending` exactly once for visible outbound agent replies across configured dispatcher delivery and Telegram preview-finalized streaming, with focused regression tests and Telegram-equivalent proof.

## Reproduction Assessment

Yes. Current-main source deterministically chooses the channel-configured `beforeDeliver` branch that excludes `message_sending`, the current test suite still asserts that bypass, and the v2026.6.11 tag contains the same branch.

## Solution Assessment

Yes as a direction, but the best path is not another independent fix PR. The maintainable solution is a single exactly-once hook model that covers the shared dispatcher branch and Telegram streamed finals without double-running normal Telegram delivery.
