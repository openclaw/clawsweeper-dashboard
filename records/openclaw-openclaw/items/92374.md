## Label Justifications

- `P1`: A documented outbound interception hook is silently bypassed on primary channel reply paths, affecting active safety, rewrite, and cancellation workflows.
- `impact:security`: Safety, DLP, compliance, and audit plugins using `message_sending` can silently fail open on outbound agent replies.
- `impact:message-loss`: Plugin cancellation or rewrite decisions can be ignored, so messages may be delivered when a hook expected suppression or modification.

## Summary

Keep open: current main and v2026.6.11 still skip the documented `message_sending` hook on channel-configured `beforeDeliver` paths, and the linked PRs are open candidate fixes rather than merged replacements.

## What This Changes

The issue reports that documented plugin `message_sending` rewrite/cancel hooks are skipped on agent-reply delivery when a channel supplies dispatcher `beforeDeliver`, especially Telegram.

## Best Possible Solution

Land one canonical fix that runs `message_sending` exactly once per visible outbound agent reply across shared dispatcher delivery and Telegram preview-finalized streaming, with focused regression tests and Telegram-equivalent proof.

## Reproduction Assessment

Yes. Current-main source deterministically chooses the configured `beforeDeliver` branch that excludes `message_sending`, and Telegram supplies that branch; I did not run a live Telegram session in this read-only review.

## Solution Assessment

Yes as a direction: restore the documented pre-send hook through one exactly-once delivery model. A dispatcher-only one-liner is too narrow because Telegram has delivery-owned hook calls and a streamed-final path outside `deliverReplies`.
