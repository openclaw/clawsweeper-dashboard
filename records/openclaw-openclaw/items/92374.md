## Summary

Keep this open: current main still omits `message_sending` from the channel-configured `beforeDeliver` dispatcher branch, and the linked PRs are open/conflicting candidates rather than merged fixes.

## What This Changes

The issue reports that documented `message_sending` plugin hooks are silently bypassed for channel agent-reply delivery paths when a channel supplies its own `beforeDeliver`, especially Telegram.

## Best Possible Solution

Land or repair one canonical fix that runs `message_sending` exactly once per visible outbound agent reply across shared dispatcher delivery and Telegram preview-finalized streaming, with focused tests and Telegram proof.

## Reproduction Assessment

Yes. Current-main source deterministically chooses the configured `beforeDeliver` branch that excludes `message_sending`, and an adjacent test still asserts that behavior; I did not run a live Telegram repro in this read-only review.

## Solution Assessment

Yes as a direction: restoring the documented pre-send hook through an exact-once delivery model is the right fix. A dispatcher-only one-liner is too narrow unless it also accounts for Telegram delivery-owned hooks and streamed finalization.
