## Label Justifications

- `P1`: A documented outbound safety hook can be silently skipped on real channel agent-reply delivery paths.
- `impact:security`: Safety, DLP, compliance, and audit plugins using `message_sending` can silently fail open on outbound agent replies.
- `impact:message-loss`: Plugin cancellation and rewrite decisions can be ignored, causing messages to be delivered when a hook expected suppression or modification.

## Summary

Keep this open: current main and the latest release tag still skip dispatcher-level `message_sending` when a channel supplies `beforeDeliver`, and the linked PRs are open candidate fixes rather than merged replacements.

## What This Changes

The issue reports that channel-supplied agent-reply delivery hooks bypass documented plugin `message_sending` hooks, especially for Telegram replies.

## Best Possible Solution

Land one canonical fix that runs `message_sending` exactly once per visible outbound agent reply across shared dispatcher delivery and Telegram preview-finalized streaming, with focused regression tests and Telegram-equivalent proof.

## Reproduction Assessment

Yes from source: the configured `beforeDeliver` branch still omits `buildMessageSendingBeforeDeliver`, and the nearby test locks that bypass in current main. I have not run a live Telegram repro in this read-only review.

## Solution Assessment

Yes as a direction: restore the documented pre-send hook through one exactly-once delivery model. A dispatcher-only one-liner is too narrow because Telegram already has delivery-owned hook calls and a streamed-final path outside `deliverReplies`.
