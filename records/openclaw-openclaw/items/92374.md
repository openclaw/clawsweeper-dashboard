## Summary

Keep this open: current main still bypasses the documented `message_sending` hook when a channel supplies `beforeDeliver`, Telegram still supplies that hook on the agent-reply path, and the linked fix PRs are open candidates rather than merged replacements.

## What This Changes

The issue reports that plugin `message_sending` hooks are silently skipped for channel agent-reply delivery paths, especially Telegram paths with channel-supplied `beforeDeliver`.

## Best Possible Solution

Land one canonical fix that composes the documented `message_sending` gate with configured channel delivery while preserving exactly-once semantics for Telegram non-streamed, streamed, and durable delivery paths.

## Reproduction Assessment

Yes. Current-main source shows the configured `beforeDeliver` branch excludes `buildMessageSendingBeforeDeliver`, Telegram supplies such a `beforeDeliver`, and the adjacent test still asserts `runMessageSending` is not called for that path.

## Solution Assessment

Yes, the best fix is to restore the existing documented hook contract in the delivery pipeline rather than add a new option. The broad linked PR appears to cover the exactly-once Telegram streaming complication better than the narrower dispatcher-only variants, but it still needs maintainer review and conflict repair.
