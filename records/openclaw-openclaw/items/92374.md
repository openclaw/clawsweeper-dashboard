## Summary

Keep this open: current main and latest release v2026.6.11 still omit `message_sending` from channel-configured `beforeDeliver` chains, Telegram still selects that path with no-op `beforeDeliver`, and all linked fixes remain open/conflicting rather than merged.

## What This Changes

Issue reports that plugin `message_sending` hooks are bypassed on channel agent-reply delivery paths when channels provide their own `beforeDeliver`, especially Telegram.

## Best Possible Solution

Review and land or reject a canonical fix that composes `message_sending` exactly once across channel-configured dispatcher paths and handles Telegram preview-finalized replies without double-running normal Telegram delivery.

## Reproduction Assessment

Yes from source and discussion: current main and v2026.6.11 still omit `message_sending` from the channel-configured `beforeDeliver` branch, Telegram still supplies that branch, and a recent commenter reports real Telegram confirmation.

## Solution Assessment

Yes as a direction: the best fix is a single canonical exactly-once hook path covering configured dispatcher delivery and Telegram streamed finalization. A dispatcher-only one-liner is too narrow because Telegram normal delivery already owns hook calls and preview-finalized streaming bypasses `deliverReplies`.
