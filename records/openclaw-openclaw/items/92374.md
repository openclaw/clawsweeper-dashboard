## Label Justifications

- `P1`: A documented outbound interception hook is silently bypassed on primary channel reply paths, affecting real safety and delivery workflows.
- `impact:security`: Safety, DLP, compliance, and audit plugins using `message_sending` can silently fail open on outbound agent replies.
- `impact:message-loss`: Plugin cancellation and rewrite decisions can be ignored, so messages may be delivered despite a hook expecting suppression or modification.

## Summary

Keep this open: current main and the latest release still omit `message_sending` from the channel-configured dispatcher branch, and Telegram streamed preview-finalized replies still bypass the hook path. The linked PRs are implementation candidates, not merged replacements.

## What This Changes

The issue requests that documented plugin `message_sending` hooks run on channel agent-reply delivery paths, including configured `beforeDeliver` and Telegram streamed finals.

## Best Possible Solution

Land one canonical fix that runs `message_sending` exactly once per visible outbound agent reply across shared dispatcher delivery and Telegram preview-finalized streaming, with focused regression tests and Telegram-equivalent proof.

## Reproduction Assessment

Yes. Current-main source deterministically chooses a configured `beforeDeliver` branch that excludes `message_sending`, and Telegram supplies that hook; I did not run a live Telegram repro in this read-only review.

## Solution Assessment

Yes as a direction: restore the documented pre-send hook through one exactly-once delivery model. A dispatcher-only one-liner is too narrow because Telegram already has delivery-owned hook calls and a streamed-final path outside `deliverReplies`.
