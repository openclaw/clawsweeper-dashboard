## Label Justifications

- `P1`: The issue affects a documented outbound interception hook used by safety, rewrite, cancellation, and DLP-style plugins on primary channel reply paths.
- `impact:security`: Bypassing `message_sending` can silently disable policy, DLP, compliance, or cancellation plugins before outbound delivery.
- `impact:message-loss`: Ignored rewrite/cancel hooks can cause messages to be delivered, modified, or unsuppressed differently than the plugin contract requires.

## Summary

Keep this open: current main and the latest release still have the configured `beforeDeliver` branch that drops the dispatcher-level `message_sending` gate, and the linked PRs are still open candidate fixes rather than merged replacements.

## What This Changes

The issue asks OpenClaw to ensure plugin `message_sending` hooks run on channel agent-reply delivery paths, including Telegram configured-dispatcher and streamed-final delivery paths, instead of being silently bypassed.

## Best Possible Solution

Land one canonical fix that runs `message_sending` exactly once per visible outbound reply across the shared dispatcher, Telegram delivery-owned sends, and Telegram preview-finalized streaming, then close or supersede the overlapping PRs.

## Reproduction Assessment

Yes. Current source shows the configured dispatcher branch omits `message_sending`, the test suite still asserts that omission, and the issue discussion includes a recent Telegram runtime confirmation; I did not run live Telegram in this read-only review.

## Solution Assessment

Yes in direction, but not yet landed. The maintainable solution is to repair the shared dispatcher hook composition while preserving Telegram exactly-once delivery ownership and streamed-final coverage, which the open candidate PRs still need to resolve before merge.
