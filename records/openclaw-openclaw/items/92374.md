## Summary

Keep this open: current main and v2026.6.11 still bypass `message_sending` when a channel supplies `beforeDeliver`, and the linked PRs are open implementation candidates rather than merged fixes.

## What This Changes

Ensure plugin `message_sending` hooks run on channel agent-reply delivery paths, including channel-configured `beforeDeliver` and Telegram streamed final replies.

## Best Possible Solution

Land one canonical fix that runs `message_sending` exactly once on configured `beforeDeliver` replies and Telegram streamed finals, then close this issue after security review and real Telegram proof.

## Reproduction Assessment

Yes. Source inspection on current main shows Telegram supplies a custom `beforeDeliver`, the shared dispatcher omits `buildMessageSendingBeforeDeliver` on that branch, and an adjacent test still asserts `runMessageSending` is not called.

## Solution Assessment

Yes, the requested direction is the right fix boundary, but the best implementation should handle both the shared dispatcher branch and Telegram preview-finalized replies with exactly-once hook semantics.
