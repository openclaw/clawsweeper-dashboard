## Summary

Keep this issue open. Current main contains a merged partial repair for normal routed replies, but its own merge context explicitly leaves provider-owned finalization paths outside that change; the remaining Telegram preview-finalized path is still tracked by an open draft candidate and needs a maintainer decision on the exact pre-send boundary.

## What This Changes

Ensure plugin `message_sending` hooks run exactly once for channel agent replies, including replies finalized by channel-specific streaming paths.

## System Context

Channel messages start an agent turn, which produces reply payloads for a channel delivery path. Plugin `message_sending` hooks are the pre-send guard that can inspect, rewrite, or cancel those outbound replies before users see them.

## Architecture Diagram

flowchart LR

  C --> D[Channel routing]
  D --> E[Pre-send plugin hook]
  E --> F[Normal delivery]
  D --> G[Provider-owned stream finalization]
  G --> H[Visible channel reply]

## Best Possible Solution

Keep the merged normal-routed-reply coverage and land a narrow follow-up that invokes the same guard exactly once at each provider-owned finalization boundary, with documented cancellation and rewrite behavior for streamed replies.
