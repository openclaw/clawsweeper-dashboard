## Label Justifications

- `P1`: The issue reports a live documented outbound safety-hook bypass on primary channel reply paths with user confirmation on recent releases.
- `impact:security`: Plugins using `message_sending` for DLP, filtering, or compliance can fail open without an operator-visible diagnostic.
- `impact:message-loss`: Plugin cancellation and rewrite decisions can be ignored, causing outbound messages to be delivered when a hook expected suppression or modification.

## Summary

Keep this open: current `origin/main` and the latest release still preserve the configured `beforeDeliver` path that skips the documented `message_sending` hook, and the linked closing PRs are still open candidate fixes rather than merged replacements.

## What This Changes

The issue asks OpenClaw to ensure plugin `message_sending` hooks run on channel agent-reply delivery paths even when a channel supplies `beforeDeliver`, including Telegram streamed finals.

## Best Possible Solution

Land one canonical exactly-once hook fix that covers shared dispatcher `beforeDeliver` composition and Telegram streamed-final delivery without double-running or dropping delivery-owned hook coverage.

## Reproduction Assessment

Yes. Current `origin/main` and `v2026.6.11` source still omit `message_sending` in the configured `beforeDeliver` branch, and the adjacent test asserts the hook is not called; I did not run a live Telegram repro in this read-only review.

## Solution Assessment

Yes as a direction, but it should land through one canonical PR. A dispatcher-only one-liner is too narrow because Telegram already has delivery-owned hook calls and a streamed-final path outside `deliverReplies`.
