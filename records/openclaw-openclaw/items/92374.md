## Summary

Keep this open: current `main` and latest release `v2026.6.11` still omit `message_sending` from the channel-configured `beforeDeliver` branch, and the linked PRs are open candidate fixes rather than merged replacements.

## What This Changes

The issue reports that documented `message_sending` rewrite/cancel hooks are bypassed on channel agent replies when the channel supplies `beforeDeliver`, especially Telegram.

## Best Possible Solution

Land one canonical fix that preserves exactly-once `message_sending` coverage across configured dispatcher delivery and Telegram streamed-final delivery without duplicate hook invocation.

## Reproduction Assessment

Yes. Current-main source deterministically chooses the configured `beforeDeliver` branch that excludes `message_sending`, Telegram supplies that branch, and the adjacent test asserts `runMessageSending` is not called; I did not run live Telegram proof in this read-only pass.

## Solution Assessment

Yes as a direction, but the best fix is one exactly-once delivery model rather than a narrow dispatcher-only one-liner. The repair needs to cover both configured dispatcher delivery and Telegram preview-finalized streaming without duplicate hook invocation.
