## Label Justifications

- `P1`: A documented outbound interception hook is silently bypassed on primary channel reply paths, affecting real safety and channel-delivery workflows.
- `impact:security`: Safety, DLP, compliance, and audit plugins using `message_sending` can fail open on outbound agent replies.
- `impact:message-loss`: Hook cancellation and rewrite decisions can be ignored, so messages may be delivered when a plugin expected suppression or modification.

## Summary

Keep this open: current main and the latest v2026.6.11 release still omit `message_sending` from configured `beforeDeliver` reply paths, and the linked closing PRs remain open rather than merged.

## What This Changes

The issue reports that plugin `message_sending` hooks are silently bypassed for channel agent replies when a channel supplies `dispatcherOptions.beforeDeliver`, especially Telegram.

## Best Possible Solution

Land one canonical fix that runs `message_sending` exactly once per visible outbound agent reply across configured dispatcher delivery and Telegram preview-finalized streaming, with focused regression tests and live Telegram proof.

## Reproduction Assessment

Yes. Current-main source deterministically chooses the configured `beforeDeliver` branch that excludes `message_sending`, the existing test asserts that `runMessageSending` is not called, and Telegram supplies that configured hook; I did not run a live Telegram repro in this read-only pass.

## Solution Assessment

Yes as a direction: restoring the documented pre-send hook with exactly-once semantics is the narrow maintainable fix. The best implementation should cover both shared configured dispatch and Telegram preview-finalized delivery rather than landing a one-sided one-line repair.
