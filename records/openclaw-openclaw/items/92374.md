## Label Justifications

- `P1`: A documented outbound interception hook is silently bypassed on primary channel agent-reply paths, affecting real safety and delivery workflows.
- `impact:security`: Safety, DLP, compliance, and audit plugins using `message_sending` can silently fail open on outbound agent replies.
- `impact:message-loss`: Plugin cancellation and rewrite decisions can be ignored, causing messages to be delivered when a hook expected suppression or modification.

## Summary

Keep this open: current main still skips the documented `message_sending` hook when a channel supplies `beforeDeliver`, Telegram still selects that configured path, and the linked fix PRs remain open rather than merged.

## What This Changes

The issue asks for documented `message_sending` plugin hooks to run, rewrite, cancel, or visibly fail on channel agent-reply delivery paths, especially Telegram configured `beforeDeliver` and preview-finalized streaming replies.

## Best Possible Solution

Land one canonical fix that runs `message_sending` exactly once per visible outbound agent reply across the shared dispatcher path and Telegram preview-finalized streaming, with focused regression tests and real Telegram-equivalent proof.
