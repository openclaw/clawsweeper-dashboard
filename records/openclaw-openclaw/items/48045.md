## Summary

Keep open: current main and the latest release still have the direct browser `/navigate` CDP attachment-download gap, and https://github.com/openclaw/openclaw/pull/89416 is the open closing fix candidate rather than a merged implementation.

## What This Changes

The issue reports that browser `/navigate` over Playwright CDP fails attachment downloads with `Download is starting` and can drop the downloaded file instead of returning structured download metadata.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/89416 or an equivalent browser-plugin fix, then close this issue once direct `/navigate` attachment downloads return managed metadata without weakening navigation policy checks.

## Reproduction Assessment

Yes, source-level: current main calls Playwright `page.goto()` through the guarded navigation helper and rethrows non-policy errors, while Playwright 1.60.0 throws `Download is starting` for CDP download navigations. I did not run a live CDP browser repro in this read-only pass.

## Solution Assessment

Yes. The best fix belongs at the browser plugin's Playwright `/navigate` seam, with download capture around navigation and policy validation before managed persistence; the open closing PR follows that shape, so a second fix PR should not be queued.
