## What This Changes

Add an opt-in staged-publication lifecycle for Automations that keeps a durable job non-runnable until an external host atomically finalizes the authorized revision.

## System Context

Automation hosts create and update durable scheduled jobs through the gateway, and the scheduler later evaluates those jobs through timer, force-run, startup, and catch-up paths. The proposed lifecycle would add a publication gate between host authorization and every path that can execute an Automation.

## Architecture Diagram

flowchart LR
  Host[Governed external host] --> Gateway[Automation gateway API]
  Gateway --> Store[Durable Automation record]
  Store --> Gate[Publication gate and revision check]
  Gate --> Scheduler[Timer, force-run, restart, catch-up]
  Scheduler --> Run[Automation execution]

## Best Possible Solution

Decide whether OpenClaw should expose a minimal generic scheduler publication gate with opaque host-owned authorization, then specify the stored state, CAS finalization, all execution-path checks, proof redaction, and migration/upgrade contract before accepting implementation work.
