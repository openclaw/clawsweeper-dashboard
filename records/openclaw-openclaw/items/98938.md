## Summary

Current main and the latest release already address the two concrete retention mechanisms named in the reporter's follow-up: the old provider-hook provider-array cache is gone, and schema validation now uses a bounded cache plus schema fingerprints to avoid recompiling equivalent schema objects.

## What This Changes

The issue reports sustained JS heap retention in long-lived multi-account Matrix gateways, later narrowed to provider-hook cache identity churn plus repeated schema-validator compilation.

## Best Possible Solution

Keep the shipped provider-runtime cache and bounded schema-validator implementation; reopen only with a fresh heap trace from v2026.6.11 or newer showing a distinct remaining retainer.

## Reproduction Assessment

Yes for the old released code path: the reported 2026.4.23 source contains the exact provider-hook cache and schema identity recompilation paths. I did not reproduce the live Matrix heap slope on current main because the named retaining mechanisms are already changed there.

## Solution Assessment

Yes. The current solution removes the specific unbounded provider-array cache shape and reuses compiled validators by cache key plus schema fingerprint without adding new config or product surface.
