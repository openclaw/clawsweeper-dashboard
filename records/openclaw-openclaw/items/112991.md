## Summary

Keep this PR open: current `main` still starts a fresh diagnostic trace for every Gateway HTTP request, so the linked feature remains necessary. The proposed direct-peer trust boundary and child-span shape are plausible, but this new inbound trust surface needs maintainer product acceptance and redacted after-fix behavior proof beyond the in-repo test suite.

## What This Changes

The PR lets Gateway HTTP requests inherit a valid W3C `traceparent` from a direct peer listed in `gateway.trustedProxies`, then starts OpenClaw work as a child span and documents the proxy-sanitization requirement.

## System Context

Gateway HTTP is the ingress for hooks, OpenAI-compatible endpoints, plugin routes, and Control UI routes. This change would turn a trusted upstream trace header into the diagnostic context that follows the request into agent runs, logs, and OpenTelemetry export.

## Best Possible Solution

Keep HTTP-only propagation narrowly bound to the existing direct-peer trusted-proxy check, obtain maintainer acceptance for that trust contract, and add redacted real Gateway/proxy evidence showing an upstream parent and OpenClaw child span on one trace.
