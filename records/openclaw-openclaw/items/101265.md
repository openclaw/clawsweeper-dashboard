## Summary

Keep this PR open: the reported Gateway outage is real and the branch has strong after-fix proof, but the implementation needs an explicit maintainer decision on whether TTS fail-open behavior applies only to cold startup or to every secrets snapshot activation.

## What This Changes

The PR makes missing built-in TTS API-key SecretRefs produce a warning and provider-local failure instead of aborting Gateway startup, while preserving fatal handling for other secret resolution failures.

## Best Possible Solution

Make missing-value degradation activation-context aware: allow a cold Gateway startup without optional TTS credentials, preserve the last-known-good snapshot on reload, reject unresolved TTS refs during config-write preflight, and cover all three paths with focused tests and aligned documentation.

- **Retain universal fail-fast:** Close the PR and keep all active SecretRefs mandatory for every snapshot activation despite the optional-TTS outage.
