## Summary

Keep open: the current head reintroduces the previously identified lifecycle bug by allowing unavailable-owner isolation during non-activating startup preparation, although the policy is intended only for the first activating Gateway startup.

## What This Changes

The PR adds cold-start SecretRef owner isolation for built-in TTS and configured model providers, reports degraded owners through status and doctor, prevents credential fallback, and returns typed unavailable errors from affected runtime paths.

## Best Possible Solution

Keep the generic owner-isolation design, but permit it only when `activationParams.activate === true` during the first cold startup; retain strict behavior for every preparation, validation, reload, restart-check, and write-preflight path, then rerun exact-head live Gateway proof.
