## Summary

The implementation and proof support the narrow behavior, and prior blocking findings are resolved; the remaining blocker is explicit maintainer acceptance of changing configured TTS SecretRefs from the existing fail-fast startup contract to a scoped fail-open policy.

## What This Changes

The PR makes absent built-in TTS provider API-key SecretRefs non-fatal during Gateway startup while preserving fail-closed handling for required credentials, invalid refs, policy failures, and invalid resolved values.

## Best Possible Solution

Approve and retain the narrowly typed TTS-only degradation rule if maintainers accept the boundary, keep all policy, validation, contract, and value-shape failures fail-closed, and land only after refreshing the final head against current main.
