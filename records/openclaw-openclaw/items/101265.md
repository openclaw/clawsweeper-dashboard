## Summary

The refreshed PR remains necessary and has strong Gateway evidence, but it deliberately creates an asymmetric activation policy: cold startup degrades missing built-in TTS keys while reload, restart-check, and config-write preflight reject the same configuration. The prior activation-scope defect appears fixed, but a maintainer must approve this permanent compatibility and security boundary, and the latest head still needs matching real-behavior proof.

## What This Changes

The PR adds typed SecretRef failure classification and optional-assignment handling so missing built-in TTS API-key refs degrade only during cold Gateway startup, with warnings, localized TTS failure, strict reload/write paths, documentation, and regression coverage.

## Best Possible Solution

Approve one explicit lifecycle contract, preserve fatal handling for every non-absence or non-TTS failure, and require exact-head Gateway proof for cold startup, reload or restart-check, and config-write before merge.
