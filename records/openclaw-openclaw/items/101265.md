## Summary

The latest head resolves the prior lifecycle finding and provides convincing exact-head Gateway/RPC proof, with no concrete correctness or security defect found. The remaining blocker is explicit maintainer sponsorship: this changes the documented shared SecretRef startup contract from universal fail-fast to a narrowly scoped fail-open policy for one optional credential class.

## What This Changes

The PR lets cold activating Gateway startup continue when a built-in TTS provider API-key SecretRef is absent, while keeping reload, restart-check, config-write, policy, contract, and invalid-value paths fail-closed.

## Best Possible Solution

If maintainers want this policy, sponsor and reopen this narrow no-new-config implementation, preserving exact missing-ref classification, cold-activation-only gating, strict reload/write behavior, and the focused live proof; otherwise retain universal startup fail-fast.
