## Label Justifications

- `P0`: The reported current behavior can prevent the entire Gateway from starting because one optional TTS credential is absent.
- `merge-risk: 🚨 compatibility`: Existing operators can lose startup-time detection of missing configured TTS credentials and encounter the failure later during use.
- `merge-risk: 🚨 security-boundary`: The PR introduces fail-open behavior inside shared credential activation, and the current lifecycle condition also reaches a path documented as strict.

## Summary

This PR addresses a real Gateway-wide outage, but the current head still applies the exception to non-activating startup preparation, contradicting its promised cold-activation-only boundary; product sponsorship also remains necessary because current documentation defines active SecretRefs as startup-fatal.

## What This Changes

The PR makes absent built-in TTS API-key SecretRefs degrade the affected provider during cold Gateway startup while adding typed resolution errors, warnings, tests, and documentation.

## Best Possible Solution

If maintainers sponsor the policy, restrict degradation to `reason === "startup" && activate === true` before the first snapshot, retain strict behavior everywhere else, and prove both sides on the final head.
