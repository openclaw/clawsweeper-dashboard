## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Keep local health probes on a loopback-safe endpoint:** `apps/macos/Sources/OpenClaw/GatewayProcessManager.swift:415-419`
  - body: `probeLocalGatewayHealth()` builds a fresh channel from `GatewayEndpointStore.localConfig()` and passes token/password into it. That config can resolve `gateway.bind=custom` or `tailnet`, and the channel sends auth in the websocket `connect` frame, so a process-manager health poll can leak Gateway credentials to a non-loopback endpoint. Keep this probe on an injected/loopback-only path, or add an explicit maintainer-approved credential boundary.
  - confidence: 0.9
- **[P1] Block page-dot navigation until acknowledgement is explicit:** `apps/macos/Sources/OpenClaw/OnboardingView+Layout.swift:115-116`
  - body: The new security notice only disables the Next button, but the page dots still jump to later pages while unchecked, and `finish()` then writes the acknowledgement key unconditionally. A first-run user can therefore complete onboarding without acknowledging the notice. Route dot navigation through the same gate or do not persist acknowledgement unless the checkbox was actually set.
  - confidence: 0.88
- **[P1] Preserve env and launchd auth before blocking node mode:** `apps/macos/Sources/OpenClaw/NodeMode/MacNodeModeCoordinator.swift:145-147`
  - body: `shouldConnectNodeMode()` only preserves connectivity when `openclaw.json` has wizard/auth keys. Existing local installs can instead get valid Gateway credentials from `OPENCLAW_GATEWAY_TOKEN` / `OPENCLAW_GATEWAY_PASSWORD` or the launchd snapshot, which `GatewayEndpointStore` already honors, so this gate can disconnect a configured Mac node after an onboarding-version bump.
  - confidence: 0.84
- **[P2] Keep the gateway readiness test hook on the waited path:** `apps/macos/Sources/OpenClaw/GatewayProcessManager.swift:380`
  - body: `waitForGatewayReady()` now calls `probeLocalGatewayHealth()` instead of the injected `self.connection`, while the existing GatewayProcessManager test still drives readiness with `setTestingConnection()`. That makes the test hook unable to exercise the wait path and forces a real local endpoint in tests/debug builds. Keep the injected connection on this path or inject the probe.
  - confidence: 0.83
- **[P2] Add a recheck path after manual CLI installs:** `apps/macos/Sources/OpenClaw/OnboardingView+Pages.swift:747-749`
  - body: The manual install command can be copied, but while the user stays on this page `Next` remains disabled until `cliInstalled` is refreshed; refreshes only happen on page entry or after the in-app installer path runs. Add a visible recheck button or polling path for the manual-install branch so users are not stuck after installing in Terminal.
  - confidence: 0.8
- **[P2] Do not install latest implicitly for debug builds:** `apps/macos/Sources/OpenClaw/GatewayEnvironment.swift:99-102`
  - body: Returning `nil` for `.debug` bundle identifiers makes `CLIInstaller.install()` fall back to `latest`. Debug/test builds can run on real machines, so this swaps a pinned app/CLI pairing for a moving installer target without an explicit opt-in or integrity boundary.
  - confidence: 0.76
