## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Keep local health probes on loopback:** `apps/macos/Sources/OpenClaw/GatewayProcessManager.swift:415-419`
  - body: `probeLocalGatewayHealth()` now builds its probe from `GatewayEndpointStore.localConfig()` and sends token/password to that URL. `localConfig()` may resolve `gateway.bind = custom` or `tailnet` to a non-loopback host and also pulls env/launchd credentials, so automatic startup probes can leak gateway credentials off-machine or over plaintext `ws://`. Keep process-manager health checks on a loopback-only endpoint or preserve the existing connection path.
  - confidence: 0.92
- **[P1] Block page dots behind the acknowledgement:** `apps/macos/Sources/OpenClaw/OnboardingView+Layout.swift:115-124`
  - body: The new security acknowledgement only gates `canAdvance`; page-dot navigation still sets `currentPage` directly for any unlocked dot. A first-run user can skip from page 0 to the final page and `finish()` will persist the acknowledgement without the checkbox, so the gate is ineffective. Route dot navigation through the same gate or include this blocker in `isLocked`.
  - confidence: 0.9
- **[P1] Preserve env and launchd auth in the onboarding gate:** `apps/macos/Sources/OpenClaw/NodeMode/MacNodeModeCoordinator.swift:145-148`
  - body: The new node-mode gate falls back only to `OnboardingWizardModel.hasExistingLocalSetup(root:)`, which inspects `openclaw.json`. Existing local installs can be valid through `OPENCLAW_GATEWAY_TOKEN` / `OPENCLAW_GATEWAY_PASSWORD` or the launchd snapshot that `GatewayEndpointStore` already honors, so this can disconnect node mode after an onboarding-version bump until the user reruns setup. Check the same credential sources or keep the previous runtime connectivity behavior.
  - confidence: 0.88
