## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Keep health probes on a local or injected connection:** `apps/macos/Sources/OpenClaw/GatewayProcessManager.swift:415-419`
  - body: This creates a new channel from `GatewayEndpointStore.localConfig()` and passes token/password for attach/start polling. That config can resolve custom or tailnet hosts, and `GatewayChannelActor` sends those credentials in the connect frame, so startup health checks can leak Gateway auth off-loopback instead of using the existing controlled connection path.
  - confidence: 0.88
- **[P1] Block every navigation path until acknowledgement:** `apps/macos/Sources/OpenClaw/OnboardingView+Layout.swift:115-123`
  - body: The new security acknowledgement only gates `canAdvance`, but the page dots still jump directly to any unlocked page. A first-run user can skip page 0, finish onboarding, and `finish()` then persists the acknowledgement anyway, so the consent gate is ineffective.
  - confidence: 0.86
- **[P2] Add a recheck path after manual CLI install:** `apps/macos/Sources/OpenClaw/OnboardingView+Pages.swift:747-749`
  - body: The manual install option only copies the command. Because `Next` is disabled until `cliInstalled` refreshes, a user who runs the copied command in Terminal remains stuck on this page until they leave and re-enter onboarding or restart it.
  - confidence: 0.82
- **[P2] Preserve env and LaunchAgent auth before blocking node mode:** `apps/macos/Sources/OpenClaw/NodeMode/MacNodeModeCoordinator.swift:145-147`
  - body: This fallback only checks `openclaw.json` through `hasExistingLocalSetup(root:)`, but the app also treats `OPENCLAW_GATEWAY_TOKEN`, `OPENCLAW_GATEWAY_PASSWORD`, and LaunchAgent snapshots as valid local auth sources. Existing installs that rely on those sources can have node mode disconnected after an onboarding-version bump even though Gateway auth is already configured.
  - confidence: 0.8
