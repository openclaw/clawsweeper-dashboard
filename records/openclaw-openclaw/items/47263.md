Full review comments:

- **[P1] Keep local health probes on loopback:** `apps/macos/Sources/OpenClaw/GatewayProcessManager.swift:415-419`
  - body: `localConfig()` is not loopback-only: current source resolves `gateway.bind=tailnet` or `gateway.bind=custom` to tailnet/custom hosts and also returns token/password. This new process-manager probe passes those credentials into a fresh channel during startup polling, so local health checks can send Gateway auth to a non-loopback `ws://` endpoint. Force this probe to loopback or validate/TLS-gate the endpoint before attaching credentials.
  - confidence: 0.9
- **[P1] Block page dots behind the acknowledgement:** `apps/macos/Sources/OpenClaw/OnboardingView+Layout.swift:115-123`
  - body: The new security acknowledgement only disables `Next`; the page dots still call `currentPage = index` with no security lock, and `finish()` then writes the acknowledgement key unconditionally. A first-run user can jump past page 0 and complete onboarding without checking the box, so all navigation paths need to enforce the same gate.
  - confidence: 0.87
- **[P1] Preserve env and launchd auth in the onboarding gate:** `apps/macos/Sources/OpenClaw/NodeMode/MacNodeModeCoordinator.swift:145-147`
  - body: This fallback decides whether node mode may connect by calling `hasExistingLocalSetup(root:)`, which only inspects `openclaw.json`. Current endpoint resolution also accepts `OPENCLAW_GATEWAY_TOKEN`, `OPENCLAW_GATEWAY_PASSWORD`, and launchd-snapshot credentials, so upgraded local installs using those supported auth sources can be disconnected until they rerun onboarding.
  - confidence: 0.82
