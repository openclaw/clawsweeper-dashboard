## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P1] Keep local health probes on loopback:** `apps/macos/Sources/OpenClaw/GatewayProcessManager.swift:415-419`
  - body: `probeLocalGatewayHealth()` builds a new channel from `GatewayEndpointStore.localConfig()` and passes through `token`/`password`. That config can resolve `tailnet` or `custom` local hosts, and `GatewayChannelActor` sends those credentials in the websocket `connect` frame, so startup health checks can leak gateway auth to a non-loopback endpoint. Use a loopback-only unauthenticated probe or validate the endpoint before sending credentials.
  - confidence: 0.93
- **[P1] Block page dots behind the acknowledgement:** `apps/macos/Sources/OpenClaw/OnboardingView+Actions.swift:62`
  - body: The new acknowledgement gate only disables `Next`; the page dots still assign `currentPage` directly, and `finish()` records the acknowledgement unconditionally. A first-run user can jump to the final page and finish without checking the box, making the security notice ineffective.
  - confidence: 0.9
- **[P1] Preserve env and launchd auth in the onboarding gate:** `apps/macos/Sources/OpenClaw/NodeMode/MacNodeModeCoordinator.swift:145-147`
  - body: The fallback now depends only on `hasExistingLocalSetup(root:)`, which reads `openclaw.json`. Existing local installs can keep valid gateway auth only in `OPENCLAW_GATEWAY_TOKEN`/`OPENCLAW_GATEWAY_PASSWORD` or the launchd snapshot, and `GatewayEndpointStore` still accepts those sources, so this gate can disconnect node mode after upgrade until the user reruns onboarding.
  - confidence: 0.88
