Full review comments:

- **[P1] Require explicit acknowledgement before persisting it:** `apps/macos/Sources/OpenClaw/OnboardingView+Actions.swift:62`
  - body: `finish()` now always writes the acknowledgement flag, but the page dots still let a first-run user jump away from page 0 while only the Next button is blocked. Finishing from a later page can therefore record acknowledgement that the user never gave; gate every page transition or only persist after the checkbox is actually set.
  - confidence: 0.9
- **[P1] Do not send local health probes to configured remote hosts:** `apps/macos/Sources/OpenClaw/GatewayProcessManager.swift:415-419`
  - body: `probeLocalGatewayHealth()` builds a new channel from `GatewayEndpointStore.localConfig()` and passes token/password. That local config can resolve custom or tailnet hosts and env/launchd credentials, so automatic startup probes can send gateway secrets to a non-loopback endpoint; keep the existing connection path, force loopback, or use an unauthenticated local health probe.
  - confidence: 0.88
- **[P2] Keep debug installs pinned unless explicitly opted in:** `apps/macos/Sources/OpenClaw/GatewayEnvironment.swift:99-102`
  - body: Returning `nil` for `.debug` bundle identifiers flows into the existing `?? "latest"` installer and manual command paths, so developer/tester builds silently install a moving CLI target. Use a pinned app version by default or require an explicit local-development opt-in for `latest`.
  - confidence: 0.78
- **[P2] Preserve env and launchd auth when gating node mode:** `apps/macos/Sources/OpenClaw/NodeMode/MacNodeModeCoordinator.swift:145-147`
  - body: The fallback for upgraded installs now delegates to `hasExistingLocalSetup(root:)`, which only inspects openclaw.json. `GatewayEndpointStore` already treats `OPENCLAW_GATEWAY_TOKEN`, `OPENCLAW_GATEWAY_PASSWORD`, and the launchd snapshot as valid local auth sources, so those upgraded installs can be disconnected until they rerun onboarding.
  - confidence: 0.82
