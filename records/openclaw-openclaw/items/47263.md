## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Keep local health probes on a loopback-only path:** `apps/macos/Sources/OpenClaw/GatewayProcessManager.swift:415-419`
  - body: This uses `GatewayEndpointStore.localConfig()` for process-manager health checks, but that resolver can return tailnet/custom hosts and token/password credentials. Since `GatewayChannelActor` sends those credentials in the WebSocket connect frame, local attach/start polling can leak gateway auth to a non-loopback endpoint instead of probing only the managed local process.
  - confidence: 0.9
- **[P1] Enforce acknowledgement for every page transition:** `apps/macos/Sources/OpenClaw/OnboardingView+Actions.swift:62`
  - body: `finish()` persists the acknowledgement unconditionally, while the page dots can still jump away from page 0 without checking `canAdvance`. A first-run user can skip the checkbox, reach the final page, and mark the security notice as acknowledged anyway.
  - confidence: 0.88
- **[P2] Preserve env and launchd auth in the node-mode gate:** `apps/macos/Sources/OpenClaw/NodeMode/MacNodeModeCoordinator.swift:147`
  - body: The upgrade fallback only inspects `openclaw.json`, but the app already accepts `OPENCLAW_GATEWAY_TOKEN`, `OPENCLAW_GATEWAY_PASSWORD`, and launchd snapshot credentials as valid local auth sources. Existing installs using those paths will be treated as unconfigured and node mode will disconnect until onboarding is rerun.
  - confidence: 0.86
- **[P2] Add a recheck path for manual CLI installs:** `apps/macos/Sources/OpenClaw/OnboardingView+Pages.swift:747-751`
  - body: Users who copy the manual install command have no way to refresh `cliInstalled` from this page, while `Next` remains disabled until that state changes. They can complete the install in Terminal and still be stuck unless they leave and re-enter onboarding.
  - confidence: 0.82
- **[P2] Keep readiness checks using the injected test connection:** `apps/macos/Sources/OpenClaw/GatewayProcessManager.swift:380`
  - body: Switching `waitForGatewayReady` to `probeLocalGatewayHealth()` bypasses the existing `testingConnection` seam used by GatewayProcessManagerTests, so the tests can no longer drive readiness through the fake WebSocket session and instead depend on a real local socket.
  - confidence: 0.8
