- `impact:ux-release-blocker`: The reported failure locks the user out of the native dashboard/Settings UI and provides no usable in-product recovery path.
- `impact:auth-provider`: The issue is specifically about gateway auth token and SecretRef resolution across the macOS app, launchd service environment, and dashboard auto-auth.
- `maturity:stable`: The affected macOS Gateway host surface is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main and the latest release still let the macOS app treat an env-template gateway token as a literal dashboard credential, while the CLI dashboard path already has the safer SecretRef behavior.

## What This Changes

The issue asks the macOS app to stop opening the dashboard with an unresolved gateway token placeholder and provide a recoverable SecretRef/auth path.

## Best Possible Solution

Make macOS dashboard auth resolution share the SecretRef/no-placeholder invariant with `openclaw dashboard`, using the launchd service snapshot when appropriate and showing a recoverable native Settings or Doctor path when unresolved.
