## Summary

Keep open: current main and the latest release still have the source-level macOS dashboard path that can treat `${OPENCLAW_GATEWAY_TOKEN}` as a literal token before the LaunchAgent fallback, and the related fixing PRs are still open rather than merged.

## What This Changes

The issue asks the macOS app to avoid passing unresolved gateway auth env placeholders into the dashboard URL and to provide an in-app recovery path when the app process cannot resolve the token.

## Best Possible Solution

Land one narrow macOS app fix that treats valid `$NAME` and `${NAME}` gateway auth inputs as SecretRef-style env placeholders, falls through to the LaunchAgent-resolved local token when available, and prevents unresolved placeholders from entering the dashboard URL while showing native recovery guidance.

## Reproduction Assessment

Yes. By source inspection, with `gateway.auth.token` set to `${OPENCLAW_GATEWAY_TOKEN}`, an empty app env, and a LaunchAgent snapshot containing the real token, current main returns the raw config string before LaunchAgent fallback and later encodes any non-empty token into the dashboard fragment.

## Solution Assessment

Yes. The best fix is a narrow native macOS resolver/dashboard guard plus Swift regression tests, reusing the existing SecretRef shorthand contract instead of adding a new config option or broad fallback.
