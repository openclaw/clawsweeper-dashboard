## Summary

Keep open: current main still has a native macOS app path that can return the literal configured token string before consulting the LaunchAgent token, so the reported dashboard lockout remains source-reproducible and is distinct from the already-fixed CLI dashboard SecretRef issue.

## What This Changes

The issue reports that the macOS app dashboard opens with an unresolved `${OPENCLAW_GATEWAY_TOKEN}` placeholder when the app cannot see the LaunchAgent-scoped env var, leaving dashboard/settings recovery unavailable.

## Best Possible Solution

Make the native macOS dashboard auth path follow the existing SecretRef/LaunchAgent contract: never pass unresolved `${...}` placeholders into the dashboard URL, use the LaunchAgent-resolved local token when available, and show a native actionable recovery path when no usable token can be resolved.

## Reproduction Assessment

Yes by source inspection: with `gateway.auth.token` set to `${OPENCLAW_GATEWAY_TOKEN}`, empty app env, and a LaunchAgent snapshot containing the token, the current Swift resolver returns the raw config string before the LaunchAgent fallback and the dashboard URL builder can encode it into `#token=`. I did not live-run the packaged app in this read-only review.

## Solution Assessment

Yes, the best fix is a narrow native app resolver change plus tests, not a new config option. The macOS app should reuse the existing SecretRef semantics or equivalent Swift detection, prefer the LaunchAgent-resolved local token when appropriate, and fail with native recovery UI when unresolved.
