## Summary

Keep open: current main and v2026.6.11 still let the native macOS resolver return a literal `${OPENCLAW_GATEWAY_TOKEN}` config value before the LaunchAgent token fallback, and the linked fixing PR is still open rather than merged.

## What This Changes

The issue asks the macOS app to avoid using an unresolved `${OPENCLAW_GATEWAY_TOKEN}` placeholder as the dashboard token and to provide a native recovery path when token resolution fails.

## Best Possible Solution

Land a focused native macOS fix that treats unresolved env-template tokens like SecretRefs, falls back to the LaunchAgent token when available, and shows a native recovery path instead of passing placeholders into dashboard URLs.

## Reproduction Assessment

Yes by source inspection. With `gateway.auth.token` set to `${OPENCLAW_GATEWAY_TOKEN}`, an empty app process env, and a LaunchAgent snapshot containing the real token, current main returns the raw config string before the LaunchAgent fallback and can embed it in `#token=`.

## Solution Assessment

Yes, the best fix is a narrow native macOS resolver/dashboard URL change plus Swift regression coverage. This should follow the existing SecretRef/LaunchAgent contract rather than adding a new config option or separate product mode.
