## Summary

Keep open: current main and the latest release still let a non-empty `gateway.auth.token` string such as `${OPENCLAW_GATEWAY_TOKEN}` win before the macOS app reaches its LaunchAgent token fallback, and the linked fix PRs are still open.

## What This Changes

The issue asks for the macOS app dashboard to avoid using an unresolved gateway token placeholder and to provide an in-app recovery path when the token is only available to the LaunchAgent.

## Best Possible Solution

Land one canonical native macOS resolver fix that follows the SecretRef env-template grammar, falls through to LaunchAgent-resolved local credentials when the app env cannot resolve them, and shows a native actionable recovery path when no usable token exists.
