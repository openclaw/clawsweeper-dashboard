## Summary

Keep open: current main and v2026.6.11 still let the native macOS app return a literal `${OPENCLAW_GATEWAY_TOKEN}` config string before the LaunchAgent token fallback, and the open closing PR has not landed yet.

## What This Changes

Fix native macOS dashboard auth so unresolved `${OPENCLAW_GATEWAY_TOKEN}` placeholders are not embedded in the dashboard URL when the app cannot see the service-scoped env var.

## Best Possible Solution

Land or replace the open fixing PR with a native resolver change that skips unresolved env-template credentials, uses the LaunchAgent-resolved local credential when available, and provides an in-app recovery/error path when no usable credential can be resolved.

## Solution Assessment

Yes, the best direction is a narrow native macOS auth resolver and dashboard URL guard that aligns with the existing SecretRef contract, plus an in-app recovery/error path. The open fixing PR is the right candidate path, but it has not merged yet.
