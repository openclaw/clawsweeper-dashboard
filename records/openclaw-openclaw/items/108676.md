## Summary

Keep this PR open, but it is not merge-ready as written. The reported spawn behavior is source-reproducible, yet the patch solves it by adding a second public MCP enablement key while OpenClaw and Codex currently use `enabled`; that config-contract direction needs maintainer approval, a canonical migration shape, and real gateway proof.

## What This Changes

The PR maps MCP server `disabled: true` to canonical `enabled: false` during config reads and writes, adds the alias to config types and schema metadata, and adds unit regression coverage.

## Best Possible Solution

Keep `enabled` as the sole runtime and persisted field; if maintainers want to accommodate observed `disabled` input, migrate and remove it through `openclaw doctor --fix` or the MCP write path, define conflict handling, and prove the resulting config against a real gateway process.
