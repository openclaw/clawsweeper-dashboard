## Summary

Keep this PR open for maintainer review: it turns `disabled` into a supported runtime MCP configuration setting even though the current contract uses `enabled` and doctor-based normalization, while still leaving `disabled: false` non-canonical and without live gateway proof.

## What This Changes

The PR accepts `disabled` as an MCP server configuration alias and normalizes `disabled: true` to `enabled: false` so disabled servers are not started.

## Best Possible Solution

Keep `enabled` as the sole runtime MCP setting and migrate any supported legacy `disabled` input in `openclaw doctor --fix`; if maintainers intentionally support the alias, define conflict precedence and fully normalize both boolean values on every persistence boundary.
