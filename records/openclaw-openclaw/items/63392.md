## Summary

Keep open: current main and v2026.6.11 still expose whole-install `backup create`/`backup verify` only, while the requested per-agent `--agent`/`--as` restore and clone workflow remains a core feature and security decision. The open encrypted-snapshot backup PR overlaps this area, but it is not merged and does not settle the per-agent clone contract.

## What This Changes

The issue requests per-agent backup, restore, and clone support through new `openclaw backup`/restore CLI flags.

## Best Possible Solution

Keep this as the narrow per-agent recovery tracker and design a maintainer-sponsored backup/restore extension that reuses the manifest and SQLite snapshot model while defining credential, transcript, rollback, and clone-renaming policy.
