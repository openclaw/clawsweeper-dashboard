## Summary

Keep open: current main and v2026.6.11 still expose whole-install backup creation and verification only, while the requested per-agent restore/clone workflow remains missing and needs product/security design before implementation.

## What This Changes

Request adding agent-scoped backup, restore, and clone CLI support with `--agent` and `--as`, including workspace, per-agent state, sessions, and config entry handling.

## Best Possible Solution

Keep this as the narrow per-agent recovery tracker and design a maintainer-sponsored core extension that reuses the backup manifest/SQLite snapshot model, defines credential and transcript portability, and adds guarded `--agent`/`--as` behavior with tests and docs.
