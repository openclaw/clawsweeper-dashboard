## Summary

Keep open: current main and the latest release still expose whole-install `backup create`/`backup verify` only, while the requested per-agent `--agent` and `--as` restore/clone workflow remains missing and security-sensitive.

## What This Changes

The issue requests per-agent backup, restore, and clone support for agent workspace, config entry, sessions, and per-agent state.

## Best Possible Solution

Keep this as the narrow per-agent recovery tracker and design a maintainer-sponsored core backup/restore extension that reuses the manifest/SQLite snapshot model, defines secret and session portability, and adds guarded `--agent`/`--as` restore tests plus docs.
