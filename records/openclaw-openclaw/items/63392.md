## Summary

Keep open: current main and v2026.6.11 still expose whole-install backup creation/verification only, while the requested per-agent `--agent` backup, restore, and `--as` clone workflow remains missing and needs product/security scoping before implementation.

## What This Changes

The issue requests per-agent backup, restore, and clone support that can archive one agent, restore one agent, or restore it under a new agent id.

## Best Possible Solution

Keep this as the narrow per-agent recovery tracker and design a maintainer-sponsored core backup/restore extension that reuses the manifest/SQLite snapshot model, defines secret and transcript portability, and adds guarded `--agent`/`--as` behavior with tests and docs.
