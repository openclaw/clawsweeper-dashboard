## Summary

Keep open: current main and v2026.6.11 still expose only instance-level backup creation and verification, while per-agent restore/clone remains a real feature gap that needs product and security direction.

## What This Changes

The issue requests `--agent` and `--as` support for backing up, restoring, and cloning one agent's workspace, state, sessions, and config entry.

## Best Possible Solution

Keep this as the narrow per-agent recovery tracker and design it as part of one maintainer-approved backup/restore contract with explicit archive contents, credential portability, transcript policy, path rewrites, overwrite/rollback behavior, and docs.
