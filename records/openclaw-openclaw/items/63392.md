## Summary

Keep open: current main and v2026.6.11 still expose whole-install backup creation and verification only, while the requested per-agent `--agent`/`--as` restore and clone workflow remains missing. The issue is still useful as the narrow tracker, but it needs maintainer product and security direction before implementation.

## What This Changes

The issue requests per-agent backup, restore, and clone support for the backup CLI, including scoped archives and optional restore under a new agent id.

## Best Possible Solution

Keep this as the narrow per-agent recovery tracker and design a maintainer-sponsored backup/restore extension that reuses the manifest and SQLite snapshot model, defines secret and transcript portability, and adds guarded `--agent`/`--as` tests plus docs.
