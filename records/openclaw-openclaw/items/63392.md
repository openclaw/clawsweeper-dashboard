## Summary

Keep open: current main and the latest release still expose whole-install backup creation and verification only, while the requested per-agent `--agent` backup, restore, and `--as` clone workflow remains missing. This is a valid feature gap, but it needs maintainer product and security direction before implementation because it would move or rewrite credentials, SQLite-backed state, workspaces, and session history.

## What This Changes

The issue requests `openclaw backup` and restore support for backing up, restoring, and cloning one configured agent by id.

## Best Possible Solution

Keep this as the narrow per-agent recovery tracker and design a maintainer-sponsored backup/restore extension that reuses the manifest and SQLite snapshot model while defining secret, session, workspace, rollback, and clone semantics up front.
