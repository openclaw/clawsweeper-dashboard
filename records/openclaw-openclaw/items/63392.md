## Summary

Keep open: current main and v2026.6.11 still expose whole-install backup creation and verification only, while the requested per-agent `--agent` backup, restore, and `--as` clone workflow remains missing and needs product/security scoping.

## What This Changes

Add per-agent backup, restore, and clone support to the existing backup CLI, including archive scoping, restore renaming, config rewrites, workspace/state handling, and session history policy.

## Best Possible Solution

Keep this as the narrow per-agent recovery tracker until maintainers define a security-reviewed archive contract that reuses the backup manifest/SQLite snapshot model, applies existing auth portability rules, and coordinates with broader restore and transcript work.

- **Route Clone Workflow Outside Core:** Leave core focused on archive verification and missing APIs while a plugin or ClawHub package owns optional per-agent clone workflows that do not need privileged state rewrites.
