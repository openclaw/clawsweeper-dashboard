## Summary

Keep open: current main and v2026.6.11 still provide whole-install `backup create` and `backup verify` only, while the requested per-agent `--agent`/`--as` restore and clone workflow remains unimplemented. Related backup/restore work overlaps this area but is either broader, unmerged, or docs-only, so it does not replace this narrower tracker.

## What This Changes

Request to add agent-scoped backup, restore, and clone CLI support that archives one agent’s workspace, state, sessions, and config entry and can restore under a new agent id.

## Best Possible Solution

Keep this as the narrow per-agent recovery tracker and design a maintainer-sponsored core backup/restore extension that reuses the manifest/SQLite snapshot model, defines credential and transcript portability, adds guarded `--agent`/`--as` behavior, and covers docs plus upgrade tests.
