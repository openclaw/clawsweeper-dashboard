## Summary

Keep open: current main and the latest release still expose whole-install `backup create` and `backup verify` only, while the requested per-agent `--agent`/`--as` restore and clone workflow remains missing and needs a product/security decision before implementation.

## What This Changes

Add per-agent backup, restore, and clone support to the backup CLI, including `--agent` selection and `--as` clone/rename behavior.

## Best Possible Solution

Keep this as the narrow per-agent recovery tracker and design a maintainer-sponsored core extension that reuses the manifest/SQLite snapshot model while defining credential portability, transcript policy, path rewrites, rollback, and docs before implementation.
