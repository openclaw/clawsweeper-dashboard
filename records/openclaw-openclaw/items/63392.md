## Summary

Keep open: current `main` and v2026.6.11 still expose whole-install backup creation and verification only, while the requested per-agent `--agent` backup, restore, and restore-as clone workflow remains missing. The issue is valid, but the restore/clone contract would move sensitive per-agent state and should stay behind maintainer product and security review.

## What This Changes

The issue requests per-agent backup, restore, and clone support through `openclaw backup create --agent`, `openclaw restore --agent`, and restore-as rename behavior.

## Best Possible Solution

Keep this as the narrow per-agent recovery tracker, settle the archive contents and credential/session portability policy with maintainers, then implement one guarded restore/clone path with rollback, conflict handling, and focused multi-agent tests.
