## Summary

Keep open: current main still has whole-install `backup create` and `backup verify` only, while per-agent `--agent` backup, restore, and `--as` clone behavior remains unimplemented and security-sensitive.

## What This Changes

Request per-agent backup, restore, and clone support that can archive one agent's workspace, state, sessions, and config entry and optionally restore it under a new agent id.

## Best Possible Solution

Keep this as the narrow per-agent recovery tracker and define a maintainer-sponsored core restore/clone contract before implementation, including archive contents, secret/session portability, path rewrites, conflict handling, rollback, and docs.
