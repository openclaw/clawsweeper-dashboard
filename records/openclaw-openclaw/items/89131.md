## Summary

Keep open: current main and v2026.6.11 still have Talk relay audio/tool plumbing plus `supportsVideoFrames` metadata, but not the requested shared video-frame contract, bridge append method, provider mappings, or gateway append-video RPC. The related browser-direct PR remains open/conflicting and explicitly leaves gateway-relay image transport to this issue, while the earlier SDK-seam PR was closed unmerged.

## What This Changes

The issue requests a shared provider/gateway realtime video-frame transport so relay sessions can submit one-shot visual context frames to active realtime voice sessions.

## Best Possible Solution

Decide the security/API direction first; if approved, add an additive one-shot frame contract through the Plugin SDK, gateway protocol, relay runtime, provider mappings, docs, and focused live-provider proof with redaction-safe logging and payload validation.
