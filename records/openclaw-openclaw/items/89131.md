## Summary

Keep open: current main and v2026.6.11 still expose realtime Talk relay as audio/tool transport plus `supportsVideoFrames` metadata, but not the requested shared frame contract, bridge append method, gateway append-video RPC, or provider mappings. The remaining work is a product/security/API decision, not conservative cleanup.

## What This Changes

Request a provider/gateway realtime video-frame transport for relay sessions, including a shared frame contract, optional bridge method, append-video RPC, and provider-specific image mapping.

## Best Possible Solution

Maintainers should approve or reject a narrow one-shot frame transport contract with consent, payload/MIME limits, redaction/logging rules, provider-retention expectations, protocol docs, and focused relay/provider tests before any implementation PR.
