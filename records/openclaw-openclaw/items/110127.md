## Summary

Keep this PR open: its detached post-connect snapshot task still permits a later socket event to be delivered before the hello snapshot, so the ordering regression identified in the existing review remains. The `maintainer` label also requires explicit maintainer handling rather than cleanup closure.

## What This Changes

The PR makes the Swift gateway connection handshake retain its decoded hello snapshot, schedules its general callback after socket setup, and adds a bounded wait to the node-session callback test.

## Best Possible Solution

Publish or otherwise serialize the hello snapshot as the first admitted connection baseline after route validity is established but before any post-hello socket frame can reach node callbacks; add a regression case that injects an immediate post-hello event and proves it cannot overtake the snapshot.

## Solution Assessment

No. Deferring snapshot admission until the route is valid is appropriate, but detaching it after receipt is armed does not preserve the hello snapshot as the ordered connection baseline; a serialized admission barrier is safer.
