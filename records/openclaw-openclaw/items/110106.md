## Summary

Keep this PR open for maintainer review. The latency problem and live improvement are well demonstrated, but the new caller deadline leaves the 65-second Codex operation running while the sidebar polls every 30 seconds, allowing repeated catalog reads to overlap on a persistently slow host.

## What This Changes

The PR adds eight-second caller deadlines around passive paired-node Claude and Codex session catalog reads while retaining the existing longer node invocation timeouts.

## Best Possible Solution

Keep one query-compatible catalog invocation in flight per paired node, let callers independently stop waiting after eight seconds, clear the single-flight entry when the invocation settles, and test that a second poll does not start duplicate native discovery.
