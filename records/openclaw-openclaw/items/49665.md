## Summary

Current main no longer uses the vulnerable per-tab lazy loader for the Channels page; routed page imports now surface failures through a visible error/retry state, and the proof commit is current-main-only after the latest release.

## What This Changes

The issue requests visible, retryable handling for Control UI lazy-loaded view failures so the Channels page does not stay permanently blank when a dynamic import rejects.

## Best Possible Solution

Keep the current router-owned lazy-loading boundary with visible error and retry behavior, and let the next release carry the main-only fix to released users.

## Reproduction Assessment

No for current main: the old report was source-plausible in the older Control UI lazy-loading path, but current main routes page modules through `@openclaw/uirouter` and renders an error/retry state on import rejection.

## Solution Assessment

Yes; the current router-owned boundary is a better fix than adding per-view catch blocks because it centralizes module-load failure handling and retry for routed Control UI pages.
