## Summary

Current main and the latest release both solve the reported silent Control UI lazy-load blank page: shipped code records lazy import failures and renders a visible error/retry panel, while current main’s router outlet carries route load errors into a visible retryable error state.

## What This Changes

The issue asks for Control UI lazy-loaded pages, especially Channels, to show a recoverable error instead of permanently rendering blank when a dynamic import fails.

## Best Possible Solution

Keep the shipped lazy-view recovery and current router-outlet error boundary; any remaining open fix PR for the old createLazy path should be treated as obsolete rather than reintroducing that path.

## Reproduction Assessment

No for current main: the historical v2026.3.13-1 source shows the no-catch lazy path, but v2026.6.11 and current main both route lazy/route-load failures into visible retryable error states. I did not run a browser repro because this was a read-only cleanup review and the source, dependency, test, and release evidence prove the current behavior.

## Solution Assessment

Yes. The best current solution is the shared lazy-view/router error boundary, because it handles every lazy route with visible failure feedback and retry rather than adding a one-off Channels-only catch.
