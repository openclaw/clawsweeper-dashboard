## Label Justifications

- `impact:ux-friction`: The report concerned a silent blank Control UI page with poor operator diagnostics, not lost data, channel message loss, auth, or session-state corruption.

## Summary

Current main no longer has the vulnerable `createLazy()` path, and Channels now goes through a route-owned lazy component loader that records import failures, renders a visible error, and offers retry. The same user problem is also covered in the latest release line by `v2026.6.11`'s `createLazyView()` error and retry UI.

## What This Changes

Handle Control UI lazy-loaded view import failures so the Channels page and sibling views do not remain silently blank.

## Best Possible Solution

Keep the current route-owned lazy loading/error boundary on main and treat older one-off `createLazy()` PRs as superseded by the shipped/current implementations.

## Reproduction Assessment

No current-main repro: the old `createLazy()` helper is gone, and the current router records lazy component import failures as route errors that render with Retry. I did not run a browser E2E in this read-only cleanup pass because source, dependency, history, and release evidence prove the reported path is no longer present.

## Solution Assessment

Yes: the current router-level error boundary is a broader and more maintainable solution than adding a catch to the removed legacy helper, because it covers Channels and sibling route component imports through one shared path.
