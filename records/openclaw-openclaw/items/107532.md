## Summary

The reported missing recovery state machine does not match current or released behavior: the gateway client already reconnects after transient socket closure with exponential backoff, resets the backoff after a successful handshake, detects silent connections, and deliberately rejects rather than blindly replaying interrupted requests.

## What This Changes

Add automatic gateway WebSocket reconnection with exponential backoff and buffer outbound client messages while the connection recovers.

## Best Possible Solution

Keep the existing bounded reconnect lifecycle and require any future replay proposal to name the affected RPCs, preserve idempotency, bound memory use, and prove that retries cannot duplicate side effects; do not add a generic in-memory message buffer.
