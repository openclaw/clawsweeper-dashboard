## Summary

Current main and the latest release already contain an explicit gateway WebSocket reconnect lifecycle with exponential backoff; the report provides no reproduction showing that lifecycle failing, while generic in-memory request replay would introduce separate idempotency and ordering concerns.

## What This Changes

Report intermittent gateway WebSocket disconnects as unrecovered and propose exponential-backoff reconnect plus in-memory outbound buffering.

## Best Possible Solution

Keep the existing reconnect supervisor and reject unresolved calls on connection loss; investigate any future report with socket-close evidence and add replay only through an explicit per-method idempotency contract.
