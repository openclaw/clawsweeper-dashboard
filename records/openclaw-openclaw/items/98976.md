## Summary

Keep open: current main still turns Anthropic refusals and OpenAI `content_filter` finishes into assistant error results without a distinct failover classification, and the overlapping open PR is blocked on the security/product question of whether moderation refusals may fall back across providers.

## What This Changes

The issue asks OpenClaw to treat provider refusal/content-filter terminal results as failover-eligible so configured model fallbacks run and diagnostics preserve a refusal reason.

## Best Possible Solution

Define explicit maintainer-approved refusal/moderation semantics, likely a named failover reason rather than `rate_limit`, then add Anthropic/OpenAI regression coverage for fallback, exhausted-chain messaging, and no-fallback behavior.

## Reproduction Assessment

Yes at source level. Current main maps Anthropic refusals and OpenAI `content_filter` to assistant error results, while the fallback classifier and reason union have no refusal/content-policy path; I did not run a live provider refusal replay.

## Solution Assessment

Unclear. The narrow source fix is feasible, but the best solution needs explicit maintainer-approved refusal/moderation semantics instead of inheriting `rate_limit` cooldown and cross-provider routing behavior.
