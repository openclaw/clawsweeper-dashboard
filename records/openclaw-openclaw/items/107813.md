## Summary

Keep this PR open, but do not merge the current patch: it fixes the reported freshness symptom by replacing per-attempt usage with cumulative thread usage, which changes the meaning of assistant-message and per-response usage data. The linked issue remains valid, while the PR also lacks after-fix proof from a real Codex app-server turn.

## What This Changes

The PR changes the Codex event projector to prefer cumulative `tokenUsage.total` over per-call `tokenUsage.last` and updates projector tests accordingly.

## Best Possible Solution

Preserve `tokenUsage.last` for attempt and assistant-message accounting, carry `tokenUsage.total` through a distinct absolute session-context snapshot, and prove both stable `/status` freshness and unchanged per-response usage with consecutive live Codex turns.
