## Summary

Keep open because current main still leaves the media-understanding image path sending ordinary non-HEIC images to the provider without the shared resize/compression ladder; the image-tool `media://` path now appears covered, but the configured media-understanding and explicit `infer image describe --model` paths are not.

## What This Changes

The issue requests that `media://` image refs and media-understanding image descriptions downscale oversized channel photos using the existing image resize settings before provider calls.

## Best Possible Solution

Centralize image compression at the media-understanding image-preparation boundary so local files, `media://` refs, configured media-understanding runs, and explicit-model `infer image describe` calls all obey the existing image resize policy before provider execution.
