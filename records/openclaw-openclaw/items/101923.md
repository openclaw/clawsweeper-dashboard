## Summary

Keep open: current main still sends media-understanding image buffers to providers after only HEIC/HEIF normalization, so ordinary oversized JPEG/PNG channel photos can still bypass the resize ladder. The issue is already paired with three open fix PRs, so the right cleanup path is to review and land or close those candidates rather than close this issue now.

## What This Changes

The issue asks for media-understanding and `media://` image inputs to use the same `imageMaxDimensionPx`/`imageQuality` resize ladder as the image tool before provider calls.

## Best Possible Solution

Land one narrow fix that applies the shared image compression policy at the media-understanding image preparation boundary for local files, `media://` refs, configured attachment understanding, and explicit `infer image describe` calls.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level: current main leaves non-HEIC media-understanding image buffers unchanged before provider execution, while the sibling image tool passes its inputs through `loadWebMedia` with `imageCompression`. I did not run the live provider repro in this read-only review.

## Solution Assessment

No complete fix is on current main. The best fix is to reuse the existing web-media/image compression ladder in the media-understanding input preparation path, not add a new config surface or provider-specific workaround.
