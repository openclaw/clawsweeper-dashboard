## Summary

Keep open because current main only partially covers the report: the image tool now appears to load media:// refs through the shared web-media compression path, but the media-understanding image path still prepares non-HEIC images without resizing before provider execution.

## What This Changes

The issue reports that media:// image references and the infer image describe path bypass the image resize ladder, causing oversized channel images to reach vision providers unmodified.

## Best Possible Solution

Centralize image compression at the media-understanding image preparation boundary so file paths, media:// refs, configured media-understanding runs, and explicit-model infer image describe calls all obey the same provider limits.
