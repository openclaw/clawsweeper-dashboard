## Summary

Keep open. Current main appears to have fixed the agent image tool’s `media://` resize path, but the explicit media-understanding pre-pass used by `openclaw infer image describe --model ...` still reads local JPEGs and sends non-HEIC inputs onward unchanged, so the oversized-image provider failure remains actionable.

## What This Changes

The issue asks for `media://` image references and `openclaw infer image describe` inputs to use the same resize ladder and `imageQuality` controls before provider calls.

## Best Possible Solution

Thread the existing model-aware image compression policy into media-understanding file preparation, reusing shared web-media optimization for local, remote, and media refs with regression coverage for oversized JPEG and `media://inbound/...` inputs.
