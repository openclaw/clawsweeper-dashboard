## Summary

Keep open. Current main still stores untrimmed plugin node.invoke policy approval titles/descriptions, the latest release shows the same behavior, and the linked fix candidate is still open rather than merged.

## What This Changes

The issue reports that plugin node.invoke policy approval requests can store whitespace-only titles/descriptions, causing pending approvals to be dropped by the Control UI parser.

## Best Possible Solution

Land a focused gateway-side normalization fix after reviewing the linked PR against sibling plugin approval request paths, then close this issue from the merged implementation.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: pass whitespace-only title/description through ctx.approvals.request in a plugin node.invoke policy, and current main stores that whitespace while the Control UI parser normalizes the title to empty and returns null.

## Solution Assessment

Yes. The best fix is to normalize or fallback plugin-supplied approval copy before registering pending gateway records, with PR review checking whether the invariant should be shared with the sibling plugin.approval.request path.
