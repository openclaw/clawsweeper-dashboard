## Label Justifications

- `P1`: The PR attempts to fix a high-impact auto-compaction regression in active long-running agent sessions, but the current patch can still break session context accounting.
- `merge-risk: 🚨 session-state`: Merging this fallback can make cached sessions underestimate live context and miss needed compaction when totalTokens is unavailable.

## Summary

Keep open: this PR targets the right compaction bug, but the proposed fallback drops cached prompt context whenever totalTokens is zero or missing, so it can replace premature compaction with under-compaction or overflow in cached sessions. It also still needs redacted real behavior proof from an affected or representative run before merge.

## What This Changes

The PR changes calculateContextTokens to fall back to input plus output instead of input, output, cacheRead, and cacheWrite, and adds compaction regression tests for zero totalTokens cached usage.

## Best Possible Solution

Make compaction use a trusted latest real context or last-call prompt snapshot instead of turn-aggregated cache buckets, with coverage for both aggregated cached turns and ordinary cached missing-total usage.

## Reproduction Assessment

Yes at source level: the linked token sample and current main fallback reproduce the inflated estimate when totalTokens is zero. I did not run a live Anthropic/container reproduction in this read-only review.

## Solution Assessment

No: the PR changes the right function, but input plus output is not a safe context fallback when cache fields may represent real cached prompt context. The safer fix is to carry the latest real context or prompt total into compaction rather than dropping all cache buckets.
