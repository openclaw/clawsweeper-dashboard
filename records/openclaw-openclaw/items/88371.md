- `impact:auth-provider`: The failure is caused by provider auth/model selection and Anthropic billing state for the configured default model.

- `maturity:stable`: The affected first-run CLI onboarding/auth setup path belongs to the M4 Stable CLI surface in the maturity scorecard.

## Summary

Keep open: current main and the latest release still allow Anthropic QuickStart to seed an Opus default and launch the terminal hatch path without a paid-credit or billing-readiness warning, so the central first-run UX problem remains.

## What This Changes

The issue asks OpenClaw to avoid or clearly warn about a paid Anthropic Opus first-chat default during Windows QuickStart onboarding.

## Best Possible Solution

Define a first-run Anthropic policy that makes Opus/API-key billing explicit before terminal hatch, preserves deliberate user model choices, and makes billing failures clearly say setup succeeded but provider billing/auth failed.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What should Anthropic QuickStart do before launching the first terminal chat when the selected default is an Opus/API-key path that may require paid credits?

Rationale: The source gap is clear, but changing provider defaults, adding confirmation, or adding billing preflight changes first-run UX and provider-cost policy, which needs maintainer intent before automation should patch it.

Likely owner: steipete

Owner reason: The default-policy history points to steipete, and this is a provider default/product decision rather than a narrow implementation defect.

Owner confidence: medium

Options:

- **Require pre-hatch billing confirmation (recommended):** Keep Anthropic available, but warn about Opus/API-key billing and require explicit confirmation or a model change before the first terminal chat launches.
- **Change the default model:** Move Anthropic first-run setup to a lower-cost default and require explicit user selection for Opus-class models.
- **Improve failure copy only:** Leave the Opus default unchanged and only make first-chat billing failures clearer, accepting that users may still discover the credit requirement after setup.

## Reproduction Assessment

Yes at source level, but not as a live Windows repro: current main still applies the Anthropic Opus default during setup and launches the terminal hatch path without a billing preflight. A low-credit Anthropic account was not exercised in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product policy. The narrowest maintainable solution is likely a pre-hatch billing/default confirmation plus clearer billing failure copy, rather than a blind one-line model swap.
