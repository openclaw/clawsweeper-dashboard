## Summary

This PR remains necessary and is a focused, correct fix for a reproduced Package Acceptance failure: the trusted workflow checkout intentionally has no installed dependencies, but current main imports the npm `tar` package before the candidate checkout can package the requested ref. The system-tar extraction preserves that checkout boundary, uses safe absolute paths on the affected workflow, and has no supported blocking defect; the protected `maintainer` label leaves final landing to normal maintainer review.

## What This Changes

The PR replaces the Docker package helper’s npm `tar` extraction with system `tar` and adds regression tests for dependency-free harness loading and workflow-checkout isolation.

## Best Possible Solution

Keep the trusted workflow checkout dependency-free through the established system-tar command boundary, with the candidate checkout remaining the sole dependency-installed source and the new regression coverage retained.
