## Summary

Keep open: this is a valid candidate for the linked sessions_send misrouting bug, but it is not merge-ready because the patch reads only the target entry's top-level channel while current session routing state can be canonicalized from route, deliveryContext, and last* fields. The updated proof is terminal output for a hand-written expression, not an observed cross-channel sessions_send run through the production path.

## What This Changes

The branch moves target session entry loading earlier in sessions_send and passes targetSessionEntry.channel, falling back to webchat, as the nested agent call channel.

## Best Possible Solution

Derive sendParams.channel from normalized session delivery state, add focused regression coverage for deliveryContext/route/lastChannel cases, then require redacted real cross-channel proof or a maintainer proof override.

## Reproduction Assessment

Yes at source level: current main still hardcodes webchat for the nested sessions_send agent call, and gateway delivery planning treats an explicit webchat request as internal even when session route metadata has an external target. I did not run a live multi-channel replay in this read-only review.

## Solution Assessment

No. The tool-layer direction is plausible, but this patch is too narrow because it reads only top-level channel instead of the normalized session delivery context already used by sibling route code.
