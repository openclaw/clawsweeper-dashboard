## Summary

Keep open: the PR targets the right `sessions_send` bug, but the patch still reads only the session entry's top-level `channel` and can miss the canonical route stored in `deliveryContext`, `route`, or `lastChannel`.

## What This Changes

The PR hoists the target session lookup in `src/agents/tools/sessions-send-tool.ts` and uses `targetSessionEntry.channel` for the nested gateway `agent` call instead of always passing `webchat`.

## Best Possible Solution

Derive `sendParams.channel` from the canonical normalized session delivery context, cover stale-webchat and external-context route shapes in tests, and require redacted production-path cross-channel proof before merge.

## Reproduction Assessment

Yes at source level: current main still hardcodes `channel: INTERNAL_MESSAGE_CHANNEL`, and current helpers/tests show canonical external route data can live outside `entry.channel`. No live multi-channel replay was run in this read-only review.

## Solution Assessment

No. The tool-layer fix is plausible, but reading only `targetSessionEntry.channel` is too narrow; the maintainable fix should use the existing normalized session delivery-context helper or a maintainer-approved gateway-layer authority rule.
