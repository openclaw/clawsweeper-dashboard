## Summary

The patch appears functionally sound and still addresses behavior missing from current main, but the external-PR proof gate remains unmet: the real CLI transcript removes the bundled plugin install record before update processing, while the state-preservation evidence comes from a focused harness rather than a real non-bundled plugin update. The overlapping open PR covers the destructive failure policy but omits this branch's additional update-check parser change, so it does not safely supersede this PR.

## What This Changes

Classifies non-E404 npm metadata preflight failures as non-destructive, preserves installed plugin configuration after those failures, and accepts singleton-array npm metadata in the update checker.

## Best Possible Solution

Land one canonical implementation that preserves healthy plugin state only for typed pre-install metadata failures, keeps E404, security, integrity, policy, and post-resolution failures fail-closed, and normalizes npm 12 singleton arrays in every affected metadata parser with focused regression coverage.
