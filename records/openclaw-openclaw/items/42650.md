## Summary

Keep open: current main and the latest release still lack the requested first-class review, edit, non-destructive forget, tombstone/supersede, and conflict-resolution lifecycle contract. Existing Memory Wiki and LanceDB memory paths are useful partial surfaces, and the KinthAI production comment adds helpful design evidence, but this remains product/API work rather than a closeable implemented item.

## What This Changes

The issue requests first-class operator flows for reviewing, editing, forgetting, and resolving conflicts in the Memory MVP.

## Best Possible Solution

Define a plugin-owned memory lifecycle contract with SQLite-backed status/revision state, provenance, safe tombstones, conflict resolution, operator CLI/UI flows, docs, and regression coverage before implementation lands.

- **Defer active-memory lifecycle:** Rely on Memory Wiki and LanceDB experiments for now while concrete stale-memory bugs remain tracked separately.
