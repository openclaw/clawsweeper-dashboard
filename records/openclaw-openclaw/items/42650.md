## Summary

Keep open: current main still lacks first-class durable-memory review, edit, non-destructive forget, tombstone/supersede, and conflict-resolution flows. Existing Memory Core, Memory Wiki, and LanceDB surfaces cover useful adjacent pieces, and the KinthAI comment adds concrete design evidence, but the remaining work is a product/API lifecycle contract rather than cleanup that can be closed.

## What This Changes

Add operator-facing durable-memory lifecycle flows for review, edit, non-destructive forget, and conflict resolution.

## Best Possible Solution

Define a durable memory lifecycle contract in the active memory plugin/API first, then implement review/edit/forget/conflict flows on explicit statuses, provenance, and non-destructive tombstone or supersede transitions.
