## Summary

Keep open: current main still lacks first-class review, edit, non-destructive forget, tombstone/supersede, and conflict-resolution flows for durable memory. Existing `memory-core` and `memory-wiki` surfaces are useful partial pieces, and the KinthAI comment adds good design evidence, but the remaining work is product/API design rather than an implemented cleanup candidate.

## What This Changes

The issue requests first-class operator flows to review, edit, non-destructively forget, and resolve conflicts in durable memory.

## Best Possible Solution

Define a durable memory lifecycle contract in the active memory plugin/API first, then implement review/edit/forget/conflict flows on top of explicit statuses, provenance, and non-destructive tombstone or supersede transitions.
