## Summary

Keep open: current main and the latest release still do not provide first-class memory review, edit, non-destructive forget, tombstone/supersede, or conflict-resolution lifecycle flows. The existing memory-core, memory-lancedb, and memory-wiki surfaces cover adjacent search, promotion, physical delete, and knowledge-lint workflows, but the requested durable lifecycle semantics still need maintainer product/API direction.

## What This Changes

Request first-class memory lifecycle flows for operator review, correction, non-destructive forget, supersede/tombstone states, and conflict resolution.

## Best Possible Solution

Define the durable memory lifecycle contract first, then implement minimal plugin-owned schema/API/CLI or UI flows for review, correction, non-destructive forget, supersede, and conflict resolution.
