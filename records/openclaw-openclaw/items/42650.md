## Summary

Keep open: current main and the latest release still expose memory search/get, promotion, Dreaming review artifacts, and memory-wiki claim tooling, but not the requested first-class review, edit, non-destructive forget, tombstone/supersede, and conflict-resolution lifecycle flows. The KinthAI production comment is useful design input, and this should wait for maintainer product/API direction rather than a speculative fix PR.

## What This Changes

The issue requests first-class operator flows to review, edit, forget, tombstone/supersede, and resolve conflicts in durable memory without direct database access.

## Best Possible Solution

Define the durable memory lifecycle contract first, then implement the minimal plugin-owned schema/API/CLI or UI flows for review, correction, non-destructive forget, supersede, and conflict resolution.
