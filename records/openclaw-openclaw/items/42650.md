## Summary

Keep open: current main has memory search/get, promotion, Dreaming review artifacts, and memory-wiki claim tooling, but it still lacks the requested first-class review, edit, non-destructive forget, tombstone/supersede, and conflict-resolution memory lifecycle flows. The KinthAI production comment is useful design input, but this needs maintainer product/API direction before implementation.

## What This Changes

Request first-class operator flows for reviewing, editing, forgetting, tombstoning/superseding, and resolving conflicts in durable memory.

## Best Possible Solution

Define the memory lifecycle contract first, then implement the minimal plugin-owned schema/API/CLI or UI flows that expose review, correction, non-destructive forget, and conflict resolution without direct DB access.
