## Summary

Keep open: current main and the latest stable release still lack a first-class active-memory lifecycle contract for review, edit, non-destructive forget, tombstone/supersede states, and conflict resolution. Existing memory-core, memory-lancedb, and memory-wiki surfaces are useful partial or adjacent implementations, and the KinthAI production comment is strong design input, but this remains product/API work rather than implemented cleanup.

## What This Changes

Add first-class memory review, edit, non-destructive forget, and conflict-resolution flows for memory lifecycle quality.

## Best Possible Solution

Define a plugin-owned memory lifecycle contract with SQLite-backed status/revision state, provenance, safe tombstones, conflict resolution, operator CLI/UI flows, docs, and regression coverage before implementation lands.
