## Summary

Keep open: current main still lacks first-class memory review, edit, non-destructive forget, tombstone/supersede, and conflict-resolution flows. The existing memory-core, Dreaming, and memory-wiki surfaces are useful partial pieces, and the KinthAI production comment is good design input, but the remaining work needs a maintainer product/API decision before implementation.

## What This Changes

The issue requests operator-facing durable memory lifecycle flows for review listing, edit, forget, conflict resolution, and tombstone or superseded states without direct DB access.

## Best Possible Solution

Define the v1 durable memory lifecycle contract in the active memory plugin/API first, then implement review/edit/forget/conflict flows on explicit statuses, provenance, and non-destructive tombstone or supersede transitions.
