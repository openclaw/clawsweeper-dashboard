## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Keep user delimiters out of runtime context:** `src/agents/embedded-agent-runner/run/runtime-context-prompt.ts:62`
  - body: This helper still uses the raw user prompt as the synthesized `transcriptPrompt` after appending the generated runtime block. Because the splitter extracts every line-delimited internal-context block whenever `transcriptPrompt` is defined, a prompt containing those delimiter lines is moved into the hidden `openclaw.runtime-context` custom message and labeled as runtime-generated context. Escape the user prompt before enabling extraction, or extract only the exact block this helper appended.
  - confidence: 0.91
- **[P2] Preserve empty-transcript runtime events when appending context:** `src/agents/embedded-agent-runner/run/runtime-context-prompt.ts:56-57`
  - body: When callers intentionally pass `transcriptPrompt: ""` for runtime-only turns, this branch returns the prompt with the new runtime self-context block while keeping the empty transcript. The later runtime-event splitter then extracts the generated block and drops the original event text, so memory flushes or heartbeat/runtime events can deliver only the self-context instead of the event. Preserve the pre-append prompt as runtime context too, or avoid appending through this extraction path for empty-transcript events.
  - confidence: 0.89
- **[P2] Report missing accelerator data as unknown:** `src/runtime-self-context/render.ts:92-96`
  - body: `accelerators` is optional in the new config schema, but this renderer treats an omitted field as an empty array and emits `no accelerator` whenever any resources object exists. CPU or memory-only config snippets therefore become a negative hardware claim that was never probed, which can steer agents away from GPU/NPU work incorrectly. Render `no accelerator` only for an explicit empty array; otherwise leave accelerator availability unknown.
  - confidence: 0.9
- **[P3] Regenerate the docs map for the new page:** `docs/docs.json:1326`
  - body: The PR adds `docs/tools/runtime.md` and links it from `docs/docs.json`, but the generated `docs/docs_map.md` still has no `tools/runtime` entry and the live `check-docs` check is failing. Regenerate the docs map with the repo docs generator so the new public page is discoverable by docs tooling.
  - confidence: 0.87
