## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Keep User Delimiters Out Of Runtime Context:** `src/agents/embedded-agent-runner/run/runtime-context-prompt.ts:62`
  - body: This carried blocker is still present at the current head. For prompt-only callers, this uses the raw pre-append prompt as `transcriptPrompt`; if the user included line-delimited internal-context markers, `resolveRuntimeContextPromptParts` extracts that user block alongside the generated runtime block and labels it as hidden runtime-generated context. Escape the user prompt before using it as the split boundary, or extract only the block appended by this helper.
  - confidence: 0.89
- **[P2] Preserve Empty-Transcript Runtime Events:** `src/agents/embedded-agent-runner/run/runtime-context-prompt.ts:56-57`
  - body: When `transcriptPrompt` is the intentional empty string used for runtime-only turns, this returns the appended prompt while keeping the empty transcript. With `runtimeContext` exposed, the extractor sees the generated runtime block and never falls back to the original event text, so heartbeat/runtime-event turns can deliver only runtime self-context instead of the event content. Preserve the pre-append prompt as runtime context too, or avoid this append path for empty-transcript events.
  - confidence: 0.87
- **[P2] Report Missing Accelerator Data As Unknown:** `src/runtime-self-context/render.ts:92-96`
  - body: `accelerators` is optional in the new schema, but this coerces an omitted field to `[]` and then tells the model `no accelerator` whenever any other resource is present. A CPU-only snippet that simply has not probed GPU/NPU state becomes a false negative placement signal; render `no accelerator` only when the config explicitly provides an empty accelerator list, otherwise leave accelerator availability unknown.
  - confidence: 0.86
