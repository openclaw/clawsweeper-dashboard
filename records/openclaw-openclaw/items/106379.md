## Label Justifications

- `P0`: The configured Gateway deterministically remains in a supervisor restart loop with its control plane unavailable after the recovery breaker has tripped.
- `impact:crash-loop`: The issue concerns repeated process exits and supervisor restarts that the persisted crash-loop breaker fails to stabilize.

## Summary

This issue should remain open: the documented crash-loop breaker promises a control-plane-safe startup, the reported startup ordering prevents that recovery when a suppressed channel SecretRef is unavailable, and the only closing fix is still an open pull request. The source-level case is strong, while full service-managed convergence proof remains outstanding.

## What This Changes

Ensure crash-loop safe mode prunes suppressed channel SecretRef surfaces before eager startup resolution while retaining fail-closed handling for Gateway auth and required non-channel secrets.

## Best Possible Solution

Land a narrowly scoped fix that passes the breaker-selected channel suppression into startup SecretRef projection without mutating global skip state, preserves fail-closed non-channel secrets, and proves convergence with a generated systemd service and an unavailable channel credential.
