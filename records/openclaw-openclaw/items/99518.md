## Summary

Keep open. Current main still routes gateway and node exec approval decisions through the generic allowlist, durable approval, and auto-review paths, with special explicit-approval guards for other sensitive classes but no OpenClaw lifecycle mutation guard.

## What This Changes

The issue requests explicit approval for OpenClaw gateway/daemon lifecycle mutation commands before generic exec allowlist or auto-review paths in non-yolo modes.

## Best Possible Solution

Add a narrow shared lifecycle-mutation classifier used by both gateway and node exec approval paths before durable allowlist or auto-review can allow the command, with regression coverage for mutating and read-only command forms.

## Reproduction Assessment

Yes, from source inspection: current main has explicit approval guards for some sensitive exec classes, but gateway and node host approval paths do not classify OpenClaw lifecycle mutations before allowlist, durable approval, or auto-review decisions. No tests were run because this review was constrained to read-only inspection.

## Solution Assessment

Yes, a shared exec-policy classifier is the narrowest maintainable fix; putting the guard only in one host path would leave the sibling gateway/node surface inconsistent.
