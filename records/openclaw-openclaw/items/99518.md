## Summary

Keep open: current main still lacks an OpenClaw lifecycle approval guard before generic durable allowlist or auto-review paths, and the linked fixing PR is open but unmerged.

## What This Changes

OpenClaw gateway/daemon lifecycle exec commands should require explicit approval before durable allowlist or auto-review can approve them in non-yolo modes.

## Best Possible Solution

Land a shared internal lifecycle classifier before durable allowlist or auto-review across gateway-host, node-host, and direct system.run paths after maintainer/security acceptance of the mutating-versus-read-only taxonomy.

## Reproduction Assessment

Yes, source-reproducible. Current main shows the gateway, node-host, and direct system.run paths can consider durable allowlist or auto-review without first classifying OpenClaw lifecycle mutation commands.

## Solution Assessment

Yes, the linked PR appears to target the right layer: classify lifecycle mutation before durable allowlist or auto-review. The remaining question is maintainer/security acceptance of the exact lifecycle taxonomy and fail-closed upgrade behavior.
