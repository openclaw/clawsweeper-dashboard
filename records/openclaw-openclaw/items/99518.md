## Summary

Keep open: current main still only has the existing generic exec approval and security-audit-suppression guard, while the lifecycle-command guard is still in the open linked fix PR, so this issue should remain open until that PR lands or is rejected.

## What This Changes

The issue asks OpenClaw to require explicit approval for gateway/daemon lifecycle mutations in non-yolo exec modes before durable allowlist or auto-review can approve them.

## Best Possible Solution

Review and land or reject the linked fix PR; the desired end state is a core exec-approval lifecycle classifier that gates self-mutation before allowlist or auto-review while leaving read-only status inspection cheap.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: on current main, lifecycle commands are not classified before durable allowlist or auto-review, while the existing special guard only covers security audit suppression edits. I did not run tests because this review is read-only.

## Solution Assessment

Yes on direction, but the exact implementation should be judged through the linked PR review. The maintainable fix belongs at the shared exec approval boundary so gateway-host, node-host, and direct `system.run` paths share the same lifecycle invariant.
