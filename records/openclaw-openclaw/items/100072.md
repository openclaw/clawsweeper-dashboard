## Summary

Current main does not implement the requested opt-in boot fallback: startup still rejects invalid config, hot reload skips invalid edits, and last-known-good restore is owned by doctor repair. The issue should stay open for maintainer product judgment because adding a degraded cold-start fallback would change config and fail-closed startup semantics.

## What This Changes

The issue requests an opt-in gateway cold-start fallback that boots from the last-known-good config when the current config fails validation.

## Best Possible Solution

Design a maintainer-approved, explicit degraded startup mode if availability should win over fail-closed config validation, including schema/docs/status signaling and tests for default fail-closed behavior plus opt-in fallback behavior.

## Reproduction Assessment

Yes, from source inspection rather than a live systemd repro. Current startup tests expect invalid config to reject with doctor guidance, and reload tests expect invalid external edits to be skipped without recovery.

## Solution Assessment

Unclear. The requested opt-in fallback is plausible, but repository policy makes fallback/config behavior a product decision; a safer design must preserve fail-closed defaults and make degraded fallback explicit and visible.
