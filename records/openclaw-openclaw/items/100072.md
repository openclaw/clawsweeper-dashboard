## Summary

Keep open: current main and the latest release still intentionally fail closed on invalid startup config while preserving last-known-good for doctor repair, so the requested opt-in boot fallback is real remaining work but needs maintainer product/security review before implementation.

## What This Changes

The issue requests an opt-in gateway cold-start fallback that boots from last-known-good config after startup validation failure while surfacing degraded state and preserving the rejected candidate.

## Best Possible Solution

Design an explicit degraded cold-start recovery mode that is off by default, visible in health/status, preserves the rejected candidate, and does not weaken doctor-owned config repair or plugin-local cleanup rules.

## Reproduction Assessment

Yes from source, not from a live systemd repro: current startup tests assert invalid config is rejected before startup without automatic recovery, and release docs state startup does not restore last-known-good automatically.

## Solution Assessment

Unclear as an implementation plan: the opt-in fallback is plausible and aligned with availability goals, but the best fix needs maintainer decisions around security posture, health/status signaling, rejected-candidate preservation, and plugin-local recovery boundaries.
