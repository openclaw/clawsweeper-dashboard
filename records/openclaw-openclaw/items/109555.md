## What This Changes

The branch stops Mattermost from passing a preview draft back to shared live delivery after that preview was finalized into the successful assistant reply, so a later tool warning is sent separately without deleting the reply.

## System Context

Mattermost streaming creates a temporary preview post while OpenClaw emits reply payloads. When the preview becomes the durable final reply, later payloads still pass through the shared live-delivery fallback, whose draft cleanup must not delete that finalized post.

## Architecture Diagram

flowchart LR
  A[Agent reply payloads] --> B[Mattermost preview stream]
  B --> C[Finalize successful reply]
  C --> D[Preview ownership state]
  D --> E[Shared live delivery]
  E --> F[Durable assistant reply]
  E --> G[Separate tool warning]

## Best Possible Solution

Keep preview ownership inside the Mattermost plugin: once an in-place final succeeds, later payloads must use ordinary durable sends rather than draft cleanup, with the ordered final-then-warning trace retained as regression coverage.
