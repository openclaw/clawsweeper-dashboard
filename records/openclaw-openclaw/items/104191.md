## Summary

Current main does not provide an authoritative post-reconciliation baseline: docs tell external schedulers to reconcile from `gateway_start`, while cron starts later. The PR cleanly introduces the missing boundary, and the deferred-sidecar finding is not supported because plugin loading activates the global runner before sidecars are deferred; the item should stay open for maintainer API approval and real behavior proof.

## What This Changes

Adds a typed public `cron_reconciled` plugin hook after startup and reload cron reconciliation, with stale-generation suppression, serialized dispatch, tests, documentation, and SDK baseline updates.

## Best Possible Solution

Approve the minimal observation-only hook, retain exact scheduler access through `ctx.getCron()`, and require a redacted live external-plugin run proving startup, disabled-cron, and reload delivery before merge.
