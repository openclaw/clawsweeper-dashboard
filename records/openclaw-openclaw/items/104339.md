## Summary

Keep this PR open for repair: the proposed timer runs after the gateway has already reconnected, so it does not reduce connection attempts and instead delays READY observation; the new 30-second cap also makes shutdown substantially less responsive.

## What This Changes

The PR replaces the fixed post-reconnect Discord gateway READY polling pause with a capped exponential post-reconnect pause.

## Best Possible Solution

Place an abort-aware exponential delay before each timeout-driven gateway reconnect, then prove exact connect timing, immediate READY recognition, cap behavior, and prompt shutdown with focused tests and redacted runtime evidence.
