## Summary

This PR addresses a valid shutdown-truncation bug, but the current head still duplicates the existing root-work waiter with an unreferenced polling timer, so the awaited drain may not keep an otherwise-idle process alive. The supplied process proof is useful but does not exercise a registered `session_end` hook through the running Gateway shutdown path.

## What This Changes

The PR adds a two-second bounded drain of tracked Gateway root-work continuations before direct-stop exit, with admission-helper and run-loop tests.

## Best Possible Solution

Use `waitForActiveGatewayRootWork(2_000)` as the single canonical waiter in the direct-stop path, retain focused timeout and success tests, and demonstrate a delayed registered `session_end` hook completing during a real Gateway SIGTERM shutdown.
