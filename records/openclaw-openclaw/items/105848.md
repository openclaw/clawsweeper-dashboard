## What This Changes

The PR adds a two-second bounded drain of tracked Gateway root-work continuations before direct-stop process exit, plus admission-helper and run-loop regression tests.

## Best Possible Solution

Direct stop should perform a bounded wait for already-tracked root-work continuations without making ordinary reset, delete, or compaction flows synchronous or changing restart-drain semantics.

## Reproduction Assessment

Yes at source level: current main forgets a finalized session before its asynchronous `session_end` continuation settles, while direct stop exits after server close without a root-work wait. The PR also supplies real process-level mechanism evidence, but not the complete Gateway/plugin scenario.

## Solution Assessment

Yes. A stop-only bounded drain is narrower and more maintainable than making every normal session finalization await plugin hooks, while preserving the existing root-work ownership model and separate restart policy.
