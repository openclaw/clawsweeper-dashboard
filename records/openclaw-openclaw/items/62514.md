## Summary

Keep open: current main and v2026.6.11 still intentionally ignore HTTP(S) prompt image URLs before native vision assembly, while the same-repo closing PR is still open and needs maintainer policy review around prompt-controlled remote media preloading.

## What This Changes

The issue asks OpenClaw to assemble Web UI mixed-image inputs deterministically so multimodal models do not ignore image context or misuse the fallback image tool with hallucinated paths or URLs.

## Best Possible Solution

Keep this issue as the canonical tracker, then land or replace the linked candidate with a policy-bound mixed-image assembly fix that preserves media safety and includes focused regression coverage plus live Web UI proof.

- **Defer to manual model/tool policy:** Keep the issue open until maintainers decide whether weak model tool-calling should be handled by model routing, tool filtering, or media preload behavior.
