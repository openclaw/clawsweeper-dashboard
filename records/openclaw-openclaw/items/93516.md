## Summary

Keep open for Matrix-owner review. Current `main` still drops a configured homeserver path prefix when its custom transport resolves rooted Matrix endpoints, while this PR preserves that prefix, supplies focused coverage, and includes credible live connection proof; the remaining question is whether path-qualified `channels.matrix.homeserver` values are an intended supported compatibility contract before merge.

## What This Changes

This PR makes Matrix transport requests resolve API endpoints relative to a configured homeserver’s full path, allowing reverse-proxy deployments such as `https://host/proxy/base/` to connect without losing the proxy prefix.

## System Context

The Matrix plugin reads a homeserver URL from channel configuration and uses it for both its authenticated helper requests and Matrix SDK traffic. Those requests pass through the guarded Matrix transport, which builds the destination URL before applying SSRF-aware fetching and returning status, sync, and message results.

## Best Possible Solution

Accept path-qualified homeserver URLs as a supported Matrix configuration value, rebase the narrow transport fix onto current `main`, and retain the focused URL regressions; add a path-prefixed message round-trip only if the Matrix owner considers delivery proof necessary for this contract change.
