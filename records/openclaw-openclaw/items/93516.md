## Summary

This PR remains necessary: current `main` still resolves Matrix endpoints with `new URL(relativeEndpoint, homeserver)`, which drops a configured reverse-proxy path when the homeserver URL lacks a trailing slash. The patch makes the configured homeserver path part of the request base and adds focused transport coverage; it has sufficient live connection proof, but an owner should confirm the compatibility-sensitive homeserver-URL semantics and review a refreshed merge head before landing.

## What This Changes

The PR changes Matrix HTTP endpoint construction so a homeserver URL with a reverse-proxy path prefix remains part of connection and API request URLs, with regression coverage for root and prefixed paths.

## System Context

The Matrix channel receives a homeserver URL from channel configuration and passes it into its HTTP transport for status probes, authentication, and Matrix API calls. The transport resolves each endpoint into the outbound request URL, which then determines where Matrix connection and message traffic is delivered.
