## Summary

Keep this PR open for one remaining P2 repair: the new best-effort cover path still awaits the ordinary Feishu image upload before sending the video, so an unavailable upload can delay delivery for the media client's 120-second timeout despite the new 5-second ffmpeg bound.

## What This Changes

The PR extracts a JPEG frame for outbound Feishu videos, uploads it as a cover image, and adds its `image_key` to media-message payloads while falling back to file-only video delivery on cover-generation failure.

## Best Possible Solution

Bound only the optional cover-image upload with a short preview-specific timeout, log and discard its failure, then send the already-uploaded video with `{ file_key }`; retain the existing 120-second timeout for required media uploads.
