## Summary

The preview-cover behavior is useful and convincingly proven, but the optional preview upload still shares Feishu’s 120-second media client timeout and is awaited before the video send; the dirty merge state also requires a fresh rebase before landing.

## What This Changes

The PR extracts a JPEG cover from outbound Feishu videos, uploads it, includes the resulting `image_key` in media messages, and adds success, fallback, remote-media, and timeout tests.

## Best Possible Solution

Keep the Feishu-owned preview-cover design and file-key fallback, but give the optional image upload a short dedicated deadline, retain focused fallback tests for extraction and upload timeouts, then rebase cleanly onto current main.
