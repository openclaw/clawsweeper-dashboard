## Summary

Keep open: current main still lacks the LSP child-process error guard and the patch looks like a narrow, appropriate crash fix, but the external real-behavior proof is still insufficient because the posted proof adds its own child `error` listener.

## What This Changes

The branch changes the LSP spawn helper to attach a no-op child `error` listener and adds a regression test that emits `error` on the mocked child process.

## Best Possible Solution

Land the narrow LSP spawn crash guard after contributor proof shows a missing binary survives by relying on the internal handler, preferably through the bundle LSP startup path or a helper run without an extra proof-only listener.

## Reproduction Assessment

Yes. Current main returns the LSP child without an `error` listener, and a Node 24 failed-spawn probe reproduces the unhandled `error` crash path; I did not run the full gateway path in this read-only review.

## Solution Assessment

Yes, as a narrow crash fix. Installing the listener at `spawnLspServerProcess` covers both the exported helper and the bundle runtime caller without changing command construction, but the proof needs to rely on that internal listener.
