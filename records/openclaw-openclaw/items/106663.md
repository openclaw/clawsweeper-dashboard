## Summary

The reported traversal does not reproduce against current main: the cited `config-paths.ts` handles dot-notation object keys rather than filesystem locations, while the actual `$include` loader rejects the exact `../../../etc/shadow` payload before reading and revalidates symlinks at open time.

## What This Changes

Require configuration imports to remain within the designated config roots so traversal paths cannot read arbitrary host files.

## Best Possible Solution

Keep the existing lexical, realpath, and guarded-open confinement; if a distinct current path can still escape it, report that concrete call chain and reproduction through the repository's private security process rather than adding a duplicate prefix check to unrelated config-object helpers.
