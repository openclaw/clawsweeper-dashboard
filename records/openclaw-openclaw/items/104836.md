## Summary

Keep this PR open for repair: configured headers and proxy/private-network opt-in are propagated correctly, but the new conditional bypasses the SSRF guard whenever `allowPrivateNetwork` is false and no dispatcher exists, so the patch still does not consistently enforce the resolved request policy and leaves the linked xAI download vulnerability reachable under default configuration.

## What This Changes

The PR sanitizes and applies configured xAI request policy across video creation, polling, and generated-media download transport, preserves API/media header isolation, and adds unit plus controlled local HTTP coverage.

## Best Possible Solution

Route xAI poll and provider-returned generated-media URLs through the SSRF-guarded transport for both default and explicitly false policy, honor explicit private-network opt-in and dispatcher settings, and continue keeping authorization and configured API headers off the media origin.
