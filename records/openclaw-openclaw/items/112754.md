## Summary

This PR remains necessary: current main resolves Git installs from npm dist-tags and then fails only with a generic missing-ref error, while this branch adds the requested exact-tag guidance, prevents a wrong tagged tree from being installed, and fixes the prepared-checkout path. The earlier `--no-git-update` blocker appears addressed, but the contributor still needs a redacted end-to-end Git-install transcript before merge because the supplied evidence is tests and helper/control-flow output rather than a completed installer run.

## What This Changes

The PR makes Git-based installation reject missing exact release tags with actionable guidance, checks that a tagged checkout matches its `package.json` version, and preserves an existing Git checkout when `--no-git-update` is selected.

## System Context

OpenClaw’s shell installers resolve a requested Git version, fetch or preserve a source tree, then install dependencies and expose the CLI. This behavior sits between npm release metadata and a user’s source-based installation, so a wrong ref or unwanted checkout can install a different release than intended.

## Best Possible Solution

Keep the fail-closed invariant, preserve prepared checkouts under `--no-git-update`, and merge after a redacted real Git-install proof covers both missing-tag failure and a prepared-checkout install; release publishing should continue to create the exact immutable tag for every npm version.
