## Summary

Keep this PR open. The fail-closed direction is sensible, but the current control flow appears to validate the npm-resolved tag even when a normal Git update is skipped because the checkout is dirty; that turns an existing prepared checkout into an avoidable install failure. The body’s terminal transcript also proves helper outcomes, not a completed prepared- or dirty-checkout installation path.

## What This Changes

The PR makes Git-based installation reject missing exact release tags, verifies that tagged checkouts match `package.json`, and preserves an existing checkout when `--no-git-update` is used.

## System Context

The shell installers resolve a requested Git ref, optionally update a local OpenClaw checkout, then install dependencies and the CLI from that tree. This change sits at the ref-resolution and checkout boundary, where it determines whether an installer proceeds with the intended source version or stops before installing mismatched code.

  D --> F[Validate checked-out version]

## Best Possible Solution

Keep exact-tag refusal, but derive validation from the ref actually checked out and bypass tag-version validation whenever the installer intentionally retains a prepared or dirty checkout; then add redacted end-to-end terminal proof for both preserved-checkout and missing-tag refusal paths.
