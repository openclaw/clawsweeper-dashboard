## What This Changes

The PR makes Git installs reject missing exact release tags, verifies a checked-out version tag against `package.json`, and intends for `--no-git-update` to install an existing checkout without replacing it.

## System Context

The shell installers select either an npm package or a Git checkout, resolve a requested version, then prepare and install that source tree. This change sits between version resolution and dependency installation, where it determines whether an existing checkout is replaced, accepted, or rejected.

## Architecture Diagram

flowchart LR

  B --> C[Git checkout selection]
  C --> D{Update existing checkout?}
  D -->|Yes| E[Checkout requested ref]
  D -->|No| F[Use prepared checkout]
  E --> G[Verify installed version]
  F --> G
  G --> H[Install dependencies and CLI]

## Best Possible Solution

Apply exact tag/package validation only after the installer actually checks out the requested version tag, while letting `--no-git-update` use the prepared tree without resolving or enforcing an unrelated npm version; add behavioral coverage for both shell installers.
