## Summary

Keep open. Current main and v2026.6.11 still enqueue WhatsApp connected/disconnected lifecycle notices into prompt-visible system events, and the remaining fix needs a maintainer policy decision about suppression, throttling, surface filtering, and config/default compatibility.

## What This Changes

Request to suppress, throttle, or surface-filter transient channel connection lifecycle system events so brief WhatsApp reconnects do not clutter unrelated sessions.

## Best Possible Solution

Define a default-compatible WhatsApp-owned lifecycle notification policy with short-outage coalescing and preservation tests, then generalize to a plugin SDK helper only if multiple channel plugins need the same contract.
