## Summary

Keep open: current main still plans account-scoped channel config changes as whole-channel restarts, and the same author has an open candidate PR that targets this exact behavior rather than a merged fix.

## What This Changes

The issue requests account-scoped channel config reloads to restart only the changed account instead of disconnecting every account on that channel.

## Best Possible Solution

Review and either land or reject https://github.com/openclaw/openclaw/pull/99312; the durable fix belongs in the gateway reload planner and executor using the existing accountId lifecycle seam.

## Reproduction Assessment

Yes: source inspection gives a high-confidence reproduction path. A channels.<kind>.accounts.<id> change currently becomes a channel-level restart plan, and the executor restarts that channel without passing accountId.

## Solution Assessment

Yes, the proposed direction appears to be the right boundary: carry account-scoped restart entries through the gateway reload plan and execute them via the existing stopChannel/startChannel accountId parameter. The open PR is the candidate implementation and still needs full PR review before merge.
