## Label Justifications

- `P1`: The issue affects live multi-account gateway deployments by disconnecting unaffected channel accounts during account-scoped config writes.
- `impact:message-loss`: Whole-channel restarts during account-scoped edits can disrupt or suppress delivery for accounts whose config did not change, and the canonical related report includes final reply failures on this path.
- `maturity:stable`: The issue affects Gateway runtime config reload behavior, and `gateway-runtime` is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main and v2026.6.11 still collapse account-scoped channel config writes into whole-channel restarts, and the same-author implementation PR remains open rather than merged.

## What This Changes

The issue requests account-scoped gateway config reloads so edits under `channels.{kind}.accounts.{accountId}` restart only the affected account instead of every account on the channel.

## Best Possible Solution

Review and land one canonical current-base gateway reload fix, preferably https://github.com/openclaw/openclaw/pull/99312 if maintainers accept its generic account-scoped restart contract, then close this duplicate and https://github.com/openclaw/openclaw/issues/43935 as implemented.

## Reproduction Assessment

Yes, at source level: an account-scoped Mattermost path matches the broad channel reload prefix, the plan stores only the channel id, and the handler restarts that whole channel without an account id.

## Solution Assessment

Yes, the best fix is to carry `(channel, accountId)` restart targets through the generic reload planner and handler using the existing ChannelManager account-id seam, while preserving whole-channel fallback cases.
