## Label Justifications

- `P1`: The issue affects live multi-account gateway/channel deployments by disconnecting unaffected accounts during account-scoped config writes.
- `impact:message-loss`: Whole-channel restarts during account-scoped config edits can interrupt active channel delivery windows for accounts whose config did not change.
- `maturity:stable`: The affected gateway runtime config reload surface maps to `gateway-runtime`, which is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main and the latest release still model channel reloads as whole-channel restarts, and the same-author implementation PR is open rather than merged. The older canonical report covers the same root cause, but this issue adds useful Mattermost production measurements.

## What This Changes

The issue requests account-scoped hot-reload planning so `channels.{kind}.accounts.{accountId}.*` changes restart only the affected channel account instead of every account on that channel.

## Best Possible Solution

Land one canonical generic reload-planner fix, likely https://github.com/openclaw/openclaw/pull/99312 if maintainers accept it, then close the duplicate/same-root reports with the merged proof.

## Reproduction Assessment

Yes. Source inspection shows an account-scoped channel path can only become a whole-channel `restartChannels` entry, and the executor calls whole-channel stop/start; I did not run a live multi-account gateway in this read-only review.

## Solution Assessment

Yes. Carrying `(channel, accountId)` restart targets through the generic reload plan and handler is the narrow maintainable fix because the channel manager already exposes account-scoped lifecycle calls.
