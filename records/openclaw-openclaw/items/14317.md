Keep open: current main and the latest release still lack Slack `groupPolicy: "private"`, and the remaining work changes Slack authorization/config semantics enough to require maintainer product and security approval.

## What This Changes

The issue requests a Slack `groupPolicy: "private"` mode that admits private Slack channels while dropping public channels unless explicitly allowlisted.

## Best Possible Solution

If maintainers approve the trust boundary, add a Slack-scoped private policy across config/schema/metadata, normal and slash routing, security audit guidance, public docs, and focused tests while preserving existing defaults unless separately approved.

## Reproduction Assessment

Yes, at source level: current main accepts only `open`, `disabled`, and `allowlist`, and Slack routing has no privacy-aware policy branch. A live Slack workspace reproduction is not needed to prove this requested feature is absent.

## Solution Assessment

Unclear pending product and security approval. A Slack-scoped private policy is plausible, but maintainers need to decide whether private-channel membership is an acceptable authorization boundary and how to prevent a Slack-only value from widening shared channel behavior.
