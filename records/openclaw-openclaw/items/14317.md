## Summary

Keep open: current main and the latest stable release still lack Slack `groupPolicy: "private"` in the config contract and Slack authorization paths, so the remaining work needs maintainer security/product approval rather than cleanup closure.

## What This Changes

Request adding a Slack-only `groupPolicy: "private"` mode that allows invited private channels while blocking public channels unless explicitly allowlisted.

## Best Possible Solution

Have maintainers approve or reject the Slack private-channel trust boundary; if approved, implement it as a Slack-scoped policy across config/schema, metadata, message/slash/action authorization, security audit guidance, docs, and focused tests while preserving current defaults unless separately approved.
