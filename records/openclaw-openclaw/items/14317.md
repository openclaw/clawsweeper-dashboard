## Summary

Keep open: current main and the latest release still lack Slack `groupPolicy: "private"`, and the remaining blocker is maintainer security/product approval for treating Slack private-channel membership as an authorization boundary.

## What This Changes

Requested behavior is adding a Slack-only `groupPolicy: "private"` mode that allows private channels while requiring explicit allowlist entries for public channels.

## Best Possible Solution

Have maintainers approve or reject the Slack private-channel trust boundary; if approved, implement a Slack-scoped policy across config/schema, normal routing, slash/action authorization, security audit guidance, docs, and focused tests while preserving existing defaults unless a migration is explicitly approved.
