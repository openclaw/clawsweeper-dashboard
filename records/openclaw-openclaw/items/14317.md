## Summary

Keep open: current main still lacks Slack `groupPolicy: "private"`, no canonical PR supersedes the request, and only the old missing-config default-open subpoint has shipped via https://github.com/openclaw/openclaw/pull/23367. The remaining work changes Slack access-control semantics, so it needs maintainer security/product approval before implementation.

## What This Changes

Requested addition of a Slack-only `groupPolicy: "private"` mode that responds in private channels and ignores public channels unless explicitly allowlisted.

## Best Possible Solution

Have maintainers approve or reject the Slack private-channel trust boundary; if approved, implement it as a Slack-scoped policy across config/schema, routing, slash/action authorization, security audit guidance, docs, and focused tests while preserving the shipped fail-closed allowlist default unless a migration is separately approved.
