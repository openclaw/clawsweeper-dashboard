## Summary

Keep open: current main and v2026.6.11 still lack Slack `groupPolicy: "private"`, and the remaining blocker is maintainer security/product approval for treating Slack private-channel membership as an authorization boundary.

## What This Changes

The issue requests a new Slack `groupPolicy: "private"` mode that admits private Slack channels the bot belongs to while requiring explicit allowlist entries for public channels.

## Best Possible Solution

Have maintainers approve or reject the Slack private-channel trust boundary; if approved, implement a Slack-scoped policy across config/schema, routing, slash/action authorization, security audit guidance, docs, and tests while preserving existing defaults unless a migration is explicitly approved.
