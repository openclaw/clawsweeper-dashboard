## Summary

Keep open: current main and the latest release still do not accept Slack `groupPolicy: "private"`, and the remaining blocker is maintainer security/product approval for treating Slack private-channel membership as an authorization boundary.

## What This Changes

Add a Slack `groupPolicy: "private"` mode that admits private Slack channels the bot has joined while dropping public channels unless explicitly allowlisted.

## Best Possible Solution

Have maintainers approve or reject the Slack private-channel trust boundary; if approved, implement a Slack-scoped policy across config/schema, normal routing, slash/action authorization, security audit guidance, docs, and focused tests while preserving existing defaults unless a migration is explicitly approved.
