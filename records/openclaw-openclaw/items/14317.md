## Summary

Keep open: current main and the latest release still lack Slack `groupPolicy: "private"`, and the remaining blocker is maintainer security/product approval for treating Slack private-channel membership as an authorization boundary.

## What This Changes

The issue requests a Slack-only `groupPolicy: "private"` mode that admits private Slack channels by membership while rejecting public channels unless allowlisted.

## Best Possible Solution

Have maintainers approve or reject Slack private-channel membership as a trust boundary; if approved, implement a Slack-scoped policy across config/schema, normal/slash/action routing, security audit guidance, docs, and focused tests without changing defaults unless a migration is explicitly approved.
