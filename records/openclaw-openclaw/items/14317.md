## Summary

Keep open: current main and the latest release still lack Slack `groupPolicy: "private"`, and the remaining blocker is maintainer security/product approval for using Slack private-channel membership as an authorization boundary.

## What This Changes

Add Slack `groupPolicy: "private"` so invited private channels are allowed while public channels require an explicit allowlist.

## Best Possible Solution

Have maintainers approve or reject the Slack private-channel trust boundary; if approved, implement it Slack-scoped across config/schema, routing, slash/action authorization, security audit, docs, and tests without changing defaults unless separately approved.
