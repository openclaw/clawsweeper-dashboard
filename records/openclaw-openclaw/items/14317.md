## Summary

Keep open: current main and v2026.6.11 still lack Slack `groupPolicy: "private"`, and the remaining work is a security-sensitive Slack authorization/config feature that needs maintainer product approval before implementation.

## What This Changes

Add a Slack `groupPolicy: "private"` mode that allows invited private channels while ignoring public channels unless explicitly allowlisted.

## Best Possible Solution

If maintainers approve the trust boundary, add a Slack-scoped private policy across config/schema/metadata, normal and slash routing, security audit guidance, public docs, and focused tests while preserving existing defaults unless separately approved.

## Reproduction Assessment

Yes, at source level: current main's `GroupPolicy` and `GroupPolicySchema` accept only `open`, `disabled`, and `allowlist`, and Slack normal/slash routing calls `isSlackChannelAllowedByPolicy` without any `is_private` input. A live Slack workspace is not needed to prove the feature is absent.

## Solution Assessment

Unclear pending product/security approval. A Slack-scoped private policy is a plausible narrow implementation, but maintainers should first decide whether private-channel membership is an acceptable trust boundary and avoid widening the shared group-policy contract accidentally.
