The issue requests a Slack-only `groupPolicy: "private"` mode that allows invited private channels while dropping public channels unless explicitly allowlisted.

## Best Possible Solution

If maintainers approve the trust boundary, add a Slack-scoped private policy across config/schema/metadata, normal and slash routing, read/action authorization, security guidance, public docs, and focused tests while preserving existing defaults unless separately approved.

## Reproduction Assessment

Yes, at source level: current main accepts only `open`, `disabled`, and `allowlist`, and Slack routing has no privacy-aware policy branch. A live Slack workspace run is not needed to prove the requested feature is absent.
