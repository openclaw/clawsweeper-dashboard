Keep open: current main and the latest release still lack Slack `groupPolicy: "private"`, and the remaining work is a security-sensitive Slack access-control/config feature that needs maintainer product approval before implementation.

## What This Changes

Request adds a Slack `groupPolicy: "private"` mode so OpenClaw can respond in private Slack channels while excluding public channels unless explicitly allowlisted.

## Best Possible Solution

If maintainers approve the trust boundary, add a Slack-scoped private policy across config/schema/metadata, normal and slash routing, read/action authorization, security audit guidance, public docs, and focused tests while preserving existing defaults unless separately approved.

## Reproduction Assessment

Yes, at source level: current main accepts only `open`, `disabled`, and `allowlist`, and Slack routing has no privacy-aware policy branch. A live Slack workspace run is not needed to prove the requested feature is absent.

## Solution Assessment

Unclear pending product/security approval. A Slack-scoped private policy is plausible, but maintainers need to decide whether private-channel membership is an acceptable authorization boundary and avoid widening the shared group-policy contract accidentally.
