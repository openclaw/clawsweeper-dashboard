## What This Changes

Add a Slack `groupPolicy: "private"` option that allows private Slack channels by default while keeping public channels blocked unless explicitly allowlisted.

## Best Possible Solution

If maintainers approve the trust boundary, add a Slack-scoped private policy across config/schema/metadata, normal and slash routing, read/action authorization, security audit guidance, public docs, and focused tests while preserving existing defaults unless separately approved.

## Solution Assessment

Unclear pending product and security approval. A Slack-scoped private policy is plausible, but maintainers need to decide whether private-channel membership is an acceptable authorization boundary and avoid accidentally widening the shared group-policy contract.
