Keep open: current main and the latest release still lack Slack `groupPolicy: "private"` in the shared config contract, Slack route authorization, slash-command authorization, and docs. ## What This Changes

Request to add a Slack `groupPolicy: "private"` mode that admits invited private channels and falls back to explicit allowlisted public channels.

## Best Possible Solution

Have maintainers approve or reject the Slack private-channel trust boundary; if approved, implement it as a Slack-scoped policy across config/schema, normal routing, slash/action authorization, security audit guidance, docs, and focused tests while preserving current defaults unless a migration is explicitly approved.

## Reproduction Assessment

Yes, at source level: current main accepts only `open`, `disabled`, and `allowlist`, and Slack routing/action paths have no privacy-aware policy branch. This proves the requested feature is absent without a live Slack workspace run.

## Solution Assessment
