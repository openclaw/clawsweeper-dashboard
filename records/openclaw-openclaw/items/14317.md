## Summary

Keep open: current main and v2026.6.11 still reject Slack `groupPolicy: "private"`, and the remaining decision is whether Slack private-channel membership is an acceptable authorization boundary.

## What This Changes

Add a Slack-only `groupPolicy: "private"` option that allows bot responses in private Slack channels while requiring public channels to be explicitly allowlisted.

## Best Possible Solution

Have maintainers approve or reject the Slack private-channel trust boundary; if approved, implement a Slack-scoped policy across config/schema, normal routing, slash/action authorization, security audit guidance, docs, and tests while preserving existing defaults unless a separate migration is approved.
