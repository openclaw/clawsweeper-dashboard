## Summary

## What This Changes

The issue requests a Slack-only `groupPolicy: "private"` mode that allows private Slack channels by membership while requiring public channels to be explicitly allowlisted.

## Best Possible Solution

Have maintainers approve or reject the Slack private-channel trust boundary; if approved, implement it as a Slack-scoped policy across config/schema, normal routing, slash/action authorization, security audit guidance, docs, and tests while preserving existing defaults unless a migration is explicitly approved.

## Reproduction Assessment

Yes, at source level: current main accepts only `open`, `disabled`, and `allowlist`, and Slack routing/action paths have no privacy-aware policy branch. This proves the requested feature is absent without a live Slack workspace run.

## Solution Assessment

Unclear pending maintainer security/product approval. A Slack-scoped private policy is plausible, but the final fix must avoid accidental shared-contract widening and keep normal messages, slash commands, action reads, docs, and security audit behavior aligned.
