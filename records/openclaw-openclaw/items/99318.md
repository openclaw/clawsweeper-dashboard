## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P2] Preserve one worker during async execPath resolution:** `packages/memory-host-sdk/src/host/embeddings-worker.ts:302-303`
  - body: `ensureChild()` now awaits the stable-path lookup before assigning `this.child`. After a worker exits, two concurrent embedding requests can both pass the connected-child check, await the same resolver, and fork separate children; because the children share one pending map, an error or exit from either child can reject requests sent to the other. Track an in-flight startup or recheck after the await so one client owns one worker.
  - confidence: 0.88
- **[P3] Mock execPath in the non-Cellar resolver test:** `packages/memory-host-sdk/src/host/embeddings-worker-stable-execpath.test.ts:19-25`
  - body: This test claims to cover `/usr/bin/node`, but it uses the real `process.execPath`. On a Homebrew macOS runner or maintainer machine that value can be a Cellar path and the resolver may correctly return the opt/bin symlink, making the test fail in the target environment. Set `process.execPath` to a non-Cellar value here, like the other tests do.
  - confidence: 0.76
