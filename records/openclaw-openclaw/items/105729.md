## Label Justifications

- `P1`: The shipped provider transport behavior repeatedly prevents ordinary replies and tool execution for affected OpenAI-compatible local-model routes.
- `impact:auth-provider`: The failure is caused by provider transport routing and model completion-budget handling for OpenAI-compatible endpoints.

## Summary

Keep open: current main still intentionally applies a character-estimate-based remaining-context clamp to proxy-like OpenAI Chat Completions requests, and the report provides a credible A/B showing that this secondary estimate can collapse a valid 6,000-token budget to one token.

## What This Changes

Fix OpenAI-compatible proxy transport budgeting so a request accepted by context precheck is not silently reduced to a one-token completion budget.

## Best Possible Solution

Compute context usage once at the agent precheck boundary, carry that prepared budget into the transport, preserve the configured output cap when precheck has established sufficient room, and compact or return a clear context-budget error instead of sending a one-token request.

## Solution Assessment

No, the temporary LiteLLM provider exclusion is not the best fix because other proxy-like providers can hit the same estimator mismatch. The narrow maintainable repair is to share the authoritative precheck budget while retaining the genuine over-context protection added for strict compatible servers.
