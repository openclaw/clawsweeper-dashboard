## Summary

Keep open: current main still allows prepared tool calls to proceed into raw host exec, and the exec approval predicate does not hard-classify OpenClaw config/model/gateway lifecycle commands as confirmation-required under documented full/off policy. The broader response-level confirmation gate remains open at https://github.com/openclaw/openclaw/issues/23451, but this concrete config/provider mutation scenario is useful security evidence rather than a disposable duplicate.

## What This Changes

The issue reports that an agent auto-ran example OpenClaw config commands and a gateway restart without explicit user confirmation.

## Best Possible Solution

Define and test a runtime approval boundary for model-initiated OpenClaw self-management commands, coordinated with the broader response-level confirmation-gate design at https://github.com/openclaw/openclaw/issues/23451.
