## Summary

Keep open: current main still allows model-issued host exec to run OpenClaw config and gateway lifecycle commands without a general confirmation boundary, and the related broader confirmation-gate tracker does not make this concrete config/auth-provider report obsolete.

## What This Changes

The issue asks OpenClaw to stop agents from automatically executing example configuration and gateway commands without explicit user confirmation.

## Best Possible Solution

Define a maintainer-approved execution-consent boundary for high-risk model-initiated host exec and OpenClaw self-management commands, coordinated with the broader tool confirmation design and existing exec/plugin approval primitives.

## Reproduction Assessment

Yes, at source level. Current main still routes prepared model tool calls into exec, host exec defaults to `security=full` and `ask=off` outside the sandbox, and no current guard classifies the reported OpenClaw config or gateway restart commands as confirmation-required.

## Solution Assessment

Unclear until maintainers decide the policy. A hard runtime approval boundary is the maintainable direction, but prompt-only guidance or a one-command denylist would be too narrow for the same-response text plus tool-call failure mode.
