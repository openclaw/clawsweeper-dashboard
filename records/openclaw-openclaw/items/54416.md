## Summary

Keep open: current main still lacks a hard confirmation boundary for model-issued OpenClaw config/model-default writes and gateway restart commands through raw exec, and the broader tool-confirmation design remains open in https://github.com/openclaw/openclaw/issues/23451.

## What This Changes

The issue reports that an agent treated example OpenClaw provider/model configuration commands and a gateway restart as executable tool calls without explicit user confirmation.

## Best Possible Solution

Define a maintainer-approved hard exec/tool confirmation boundary for model-initiated OpenClaw self-management commands, coordinated with https://github.com/openclaw/openclaw/issues/23451 and the existing exec/plugin approval surfaces.

## Reproduction Assessment

Yes, at source level. Current main still permits raw gateway/node exec under documented full/off policy, and the hard guard does not classify `openclaw config set` or `openclaw gateway restart` as confirmation-required; I did not run a destructive live Feishu repro.

## Solution Assessment

Unclear until maintainers settle the security policy. A hard runtime approval boundary is the right class of solution, while a prompt-only instruction would be too weak and a broad configurable gate belongs with the canonical design thread.
