## Summary

Keep open: current main still has lower-level exec approvals and plugin approval hooks, but no hard confirmation boundary for model-issued OpenClaw self-management commands like config/model-default writes or gateway restarts through raw exec. The broader confirmation-gate design is tracked at https://github.com/openclaw/openclaw/issues/23451, but this issue remains useful as a concrete security-sensitive config/auth-provider manifestation.

## What This Changes

The issue asks OpenClaw to stop model-issued example config, model-switch, and gateway-restart commands from running through exec without explicit user confirmation.

## Best Possible Solution

Define a maintainer-approved runtime consent boundary for model-initiated OpenClaw self-management commands, coordinated with the broader confirmation-gate design while preserving existing exec/plugin approval semantics.

## Reproduction Assessment

Yes at source level: current main still permits raw gateway/node exec under documented `security=full` plus `ask=off`, and the approval predicate has no special confirmation class for `openclaw config set` or `openclaw gateway restart`. I did not run a destructive live repro because it would intentionally mutate config and restart the gateway.

## Solution Assessment

Unclear until maintainers settle the security policy. A hard runtime approval or protected-command boundary is the maintainable direction; prompt wording alone is not enough to stop same-response text plus tool-call execution.
