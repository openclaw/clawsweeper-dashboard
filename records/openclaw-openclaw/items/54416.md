## Summary

Keep open: current main still lacks a hard confirmation boundary for model-issued OpenClaw self-management commands sent through raw exec, and the remaining fix is security/product policy work rather than stale cleanup.

## What This Changes

Issue requests preventing agent-issued example `openclaw config set` and `openclaw gateway restart` commands from executing without explicit user confirmation.

## Best Possible Solution

Add a hard approval boundary for model-initiated OpenClaw self-management commands, coordinated with the broader confirmation-gate design and existing exec/config approval surfaces.

## Reproduction Assessment

Yes at source level: current `main` still routes prepared tool calls into execution and the raw gateway exec path remains full/off unless the operator has configured a stricter exec policy. I did not run a live destructive Feishu repro because the reported commands would mutate config and restart the gateway.

## Solution Assessment

Unclear until maintainers settle the security policy. A hard approval boundary for OpenClaw self-management commands is the maintainable direction; prompt-only wording would not enforce same-response text plus tool-call execution.
