## Summary

Keep open: current main and v2026.6.11 still allow model-issued OpenClaw config and gateway restart commands through raw host exec under documented no-approval policy, so the reported consent boundary is not fixed.

## What This Changes

Prevent agents from automatically executing example OpenClaw config, provider/model, and gateway restart commands without explicit user confirmation.

## Best Possible Solution

Define a maintainer-approved hard policy for model-initiated OpenClaw self-management commands, composing with the broader confirmation-gate work, existing exec approvals, and the gateway config tool guard.

## Reproduction Assessment

Yes, at source level. Current main still executes tool-use batches after a model response, host exec defaults to full/off outside the sandbox, and the hard shell guard does not classify config writes or gateway restarts as confirmation-required.

## Solution Assessment

Unclear until maintainers choose the security semantics. A hard exec/tool approval boundary is the maintainable layer; a prompt-only instruction would not reliably stop same-response text plus tool-call execution.
