## Summary

The projection fingerprint and stale-completion guards address the direct-send race, but the unchanged re-review head still re-arms corrections only from `delivered`; obsolete payloads recorded as `session_queued` or fallback-queued `failed` can still suppress the corrected terminal notification. The PR also has deterministic mocked regressions but no after-fix live task-notification proof.

## What This Changes

The PR fingerprints each rendered task terminal destination/content projection, rejects stale asynchronous delivery completions, retries superseded generations, and adds focused race/idempotency tests.

## Best Possible Solution

Keep one canonical projection-generation mechanism, but re-arm a changed projection from every delivery state that has already exposed or queued older content, with regressions for direct delivery, session queueing, fallback queueing, and unchanged-projection idempotency.
