## Summary

Keep open: the implementation is coherent and source-backed, but it changes the deliberate native attachment policy from JPEG normalization to preserving every PNG without maintainer-confirmed product direction, and the external PR provides test coverage rather than an after-fix native-client run.

## What This Changes

Changes Android chat, Apple chat, and the iOS share extension to re-encode PNG inputs as bounded PNG attachments while retaining JPEG conversion for other decoded image formats.

## Best Possible Solution

Adopt one documented policy across Android chat, Apple chat, and Apple share—preferably preserving PNG only when transparency is present while keeping opaque images as bounded JPEGs—then prove the selected policy through a real native-client-to-gateway run without weakening metadata stripping or payload limits.
