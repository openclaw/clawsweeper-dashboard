## Summary

Keep open: current main still parses `nodes invoke --params` with a bare `JSON.parse`, so malformed input can surface the raw parser error instead of an option-specific CLI diagnostic; searches found adjacent node.invoke JSON work but no canonical fix for this CLI path.

## What This Changes

The issue asks for `openclaw nodes invoke --params <bad-json>` to report an actionable `--params` JSON validation error before sending `node.invoke`.

## Best Possible Solution

Add a narrow node CLI JSON-params parser that reports `--params` must be valid JSON and exits before `node.invoke`, with focused regression coverage in the existing nodes CLI test harness.
