Full review comments:

- **[P1] Target the active auth-profile store:** `src/infra/sealed-json-file.ts:107-114`
  - body: Current main reads and writes auth profiles through the SQLite auth_profile_store row, but this helper only seals legacy JSON files. Landing this would advertise credential sealing while leaving the active provider credential store outside the encryption boundary.
  - confidence: 0.93
- **[P1] Block plaintext downgrades without passphrase:** `src/infra/sealed-json-file.ts:111-114`
  - body: This write path falls back to plaintext whenever OPENCLAW_PASSPHRASE is unset, even after a sealed load failed. Migration or external-CLI sync can therefore replace encrypted credentials with plaintext instead of failing closed.
  - confidence: 0.91
- **[P1] Write sealed credentials atomically and privately:** `src/infra/sealed-json-file.ts:113-114`
  - body: writeFileSync followed by chmodSync truncates the destination in place and only fixes permissions after creation. Credential-bearing files should use the existing atomic private replace pattern so interrupted writes do not corrupt credentials and new files are never exposed with default permissions.
  - confidence: 0.88
- **[P1] Read inherited stores through the sealed loader:** `src/agents/auth-profiles/store.ts:416`
  - body: This branch can now save inherited stores in sealed form, but the subagent inheritance path still reads the main store with the plain JSON loader. With OPENCLAW_PASSPHRASE enabled, subagents can silently fail to inherit credentials.
  - confidence: 0.86
- **[P2] Preserve expectFinal timeout semantics:** `src/gateway/client.ts:520-524`
  - body: Current main intentionally leaves expectFinal requests without the default request timeout unless the caller opts in. This stale implementation applies the 30s default to every request, which can break long-running accepted/final flows.
  - confidence: 0.86
- **[P2] Record KDF parameters in the sealed envelope:** `src/infra/sealed-json-file.ts:38-39`
  - body: deriveKey uses implicit Node scrypt defaults and the envelope stores no KDF metadata. Without explicit persisted parameters, future tuning or compatibility checks cannot know how existing credential files were derived.
  - confidence: 0.82
