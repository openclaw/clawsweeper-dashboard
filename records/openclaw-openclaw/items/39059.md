Full review comments:

- **[P1] Target the active auth-profile store:** `src/agents/auth-profiles/store.ts:526`
  - body: Current main no longer treats `auth-profiles.json` as the active credential store; `saveAuthProfileStore` writes the canonical secrets payload through SQLite. Sealing only the legacy JSON file leaves active provider credentials unprotected and creates a competing persistence story after rebase.
  - confidence: 0.9
- **[P1] Block plaintext downgrades without a passphrase:** `src/agents/auth-profiles/store.ts:438`
  - body: If a sealed store exists but `OPENCLAW_PASSPHRASE` is missing, this path can still reach `saveSealedJsonFile` after legacy/OAuth/CLI sync and overwrite the encrypted store as plaintext. That contradicts the claimed fail-closed behavior and can leak or lose credential material.
  - confidence: 0.94
- **[P1] Write sealed credential files atomically and privately:** `src/infra/sealed-json-file.ts:113-114`
  - body: `writeFileSync` creates or truncates the credential file directly, then chmods it afterward. Credential-bearing writes need an atomic temp-and-rename path with private mode at creation time, otherwise a partial write or permissive creation window can expose or corrupt auth data.
  - confidence: 0.88
- **[P2] Preserve long-running final-response requests:** `src/gateway/client.ts:520-524`
  - body: This default timeout also applies to `expectFinal` requests when no per-call timeout is supplied. Current main intentionally leaves those requests without an implicit default timeout, so porting this logic would break long-running gateway operations that first return `accepted` and finish later.
  - confidence: 0.82
- **[P2] Persist KDF parameters in the envelope:** `src/infra/sealed-json-file.ts:38-39`
  - body: The sealed format derives keys with implicit `scryptSync` defaults but does not record the KDF parameters in the file. That makes the format harder to audit and unsafe to tune later without compatibility ambiguity for already-sealed stores.
  - confidence: 0.78
