## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.93

Full review comments:

- **[P1] Target credential sealing at the active SQLite store:** `src/agents/auth-profiles/paths.ts:32`
  - body: Current main persists auth-profile secrets in the per-agent SQLite auth_profile_store row, but this branch only seals legacy auth-profiles.json creation and writes. Rebase the design onto the SQLite persistence/migration path or users can enable sealing while the active credential store remains unsealed.
  - confidence: 0.95
- **[P1] Block plaintext downgrades when the passphrase is absent:** `src/agents/auth-profiles/store.ts:436-438`
  - body: When a sealed auth-profiles.json cannot be read because OPENCLAW_PASSPHRASE is missing, this path can still set shouldWrite through legacy/OAuth/external-CLI sync and then save plaintext over the sealed file. The write path needs to fail closed or become read-only when an existing sealed store cannot be decrypted.
  - confidence: 0.94
- **[P1] Use the sealed reader for inherited main auth:** `src/agents/auth-profiles/store.ts:412`
  - body: The subagent inheritance path still reads the main store through loadJsonFile, so a sealed main auth store cannot be inherited by subagents. Use the same protected/sealed reader here or the new passphrase mode breaks credential inheritance.
  - confidence: 0.88
- **[P2] Preserve expectFinal request timeout semantics:** `src/gateway/client.ts:520-524`
  - body: This branch applies a default timeout to every request unless a numeric override is supplied, but current main supports timeoutMs: null and leaves expectFinal requests without automatic timeout by default. Re-porting this stale implementation would break long-running accepted/final gateway flows.
  - confidence: 0.86
- **[P2] Write sealed credentials atomically and privately:** `src/infra/sealed-json-file.ts:113-114`
  - body: saveSealedJsonFile writes credential material with writeFileSync and only then chmods the destination. Credential writes should use the existing atomic/private-at-create-time replacement path so crashes, permission windows, symlink edges, or chmod failures cannot expose or corrupt auth material.
  - confidence: 0.89
- **[P2] Record explicit KDF parameters in sealed files:** `src/infra/sealed-json-file.ts:38-39`
  - body: The sealed envelope derives keys with scryptSync but does not store explicit KDF parameters. Persisted credential formats need stable, auditable work factors so future tuning does not create ambiguous or incompatible encrypted files.
  - confidence: 0.82
