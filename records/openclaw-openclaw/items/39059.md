## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Target the active auth-profile store:** `src/infra/sealed-json-file.ts:107-114`
  - body: This helper only seals legacy JSON files, but current main persists the active auth-profile payload through the SQLite auth_profile_store row. As written, the PR can claim credential sealing while leaving the real provider credential store unencrypted, so the encryption work needs to move to the current SQLite-backed persistence path or explicitly migrate it.
  - confidence: 0.93
- **[P1] Block plaintext downgrades when passphrase is absent:** `src/infra/sealed-json-file.ts:111-114`
  - body: The new save path writes plaintext whenever OPENCLAW_PASSPHRASE is unset, even if the previous store was sealed or a sealed load failed. That can silently replace encrypted credentials with plaintext during migration/sync paths and turns a missing passphrase into a credential leak or loss mode.
  - confidence: 0.91
- **[P1] Write sealed credentials atomically and privately:** `src/infra/sealed-json-file.ts:113-114`
  - body: writeFileSync followed by chmodSync truncates the destination in place and only fixes permissions after creation. Credential-bearing files should use the existing atomic private replace pattern so interrupted writes do not corrupt credentials and temporary contents are never exposed with default permissions.
  - confidence: 0.88
- **[P2] Preserve current expectFinal timeout semantics:** `src/gateway/client.ts:517-520`
  - body: Current main already implements gateway request timeouts in packages/gateway-client and intentionally avoids applying the default timeout to expectFinal requests unless a caller opts in. This stale client-side implementation applies a fixed default timer to all requests, which can break long-running accepted/final flows if revived unchanged.
  - confidence: 0.86
- **[P2] Record KDF parameters in the sealed envelope:** `src/infra/sealed-json-file.ts:38-40`
  - body: deriveKey uses implicit Node scrypt defaults and the file format stores only version, algorithm, salt, iv, tag, and ciphertext. Without explicit KDF metadata, future tuning or compatibility checks cannot tell how existing credential files were derived.
  - confidence: 0.82
