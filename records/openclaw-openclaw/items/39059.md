  - body: Current main persists provider credentials through the SQLite auth_profile_store row, but this helper only seals legacy JSON paths. Landing this would advertise credential sealing while leaving the active auth-profile store outside the encryption boundary.
  - confidence: 0.93
- **[P1] Block plaintext downgrades without a passphrase:** `src/infra/sealed-json-file.ts:111-114`
  - body: When OPENCLAW_PASSPHRASE is missing, saveSealedJsonFile writes plaintext. After a sealed load fails, migration or external-CLI sync can therefore replace encrypted credentials with plaintext instead of failing closed.
  - confidence: 0.91
- **[P1] Write sealed credential files atomically and privately:** `src/infra/sealed-json-file.ts:113-114`
  - body: writeFileSync followed by chmodSync truncates the destination in place and only fixes permissions after creation. Credential-bearing files should use the existing atomic private replace pattern so interrupted writes do not corrupt credentials or expose default permissions.
  - confidence: 0.88
- **[P2] Preserve expectFinal timeout semantics:** `src/gateway/client.ts:520-524`
  - body: Current main intentionally leaves expectFinal requests without the default request timeout unless the caller opts in. This stale implementation applies the 30s default to every request, which can break long-running accepted/final flows.
  - confidence: 0.86
- **[P2] Persist KDF parameters in the sealed envelope:** `src/infra/sealed-json-file.ts:38-39`
  - body: deriveKey uses implicit Node scrypt defaults and the envelope stores no KDF metadata. Without explicit persisted parameters, future tuning or compatibility checks cannot know how existing credential files were derived.
  - confidence: 0.82
