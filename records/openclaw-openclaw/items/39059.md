## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P1] Target the active SQLite auth store:** `src/agents/auth-profiles/store.ts:438`
  - body: Current main stores auth profiles in `openclaw-agent.sqlite`, not as the JSON `auth-profiles.json` runtime store this branch seals. Carrying this forward would leave active `auth_profile_store.store_json` credential payloads unsealed while claiming auth-store encryption, so the auth hardening needs to target the current SQLite persistence boundary or be dropped from this PR.
  - confidence: 0.92
- **[P1] Block plaintext downgrade when passphrase is missing:** `src/agents/auth-profiles/store.ts:438`
  - body: If an existing store is sealed and `OPENCLAW_PASSPHRASE` is missing, the load path returns no store, then legacy/OAuth/CLI sync can set `shouldWrite` and call this save without a passphrase. That rewrites the sealed credential store as plaintext, defeating the fail-closed behavior and risking credential exposure or loss.
  - confidence: 0.96
- **[P1] Write sealed credential files atomically and privately:** `src/infra/sealed-json-file.ts:113-114`
  - body: This writes the destination directly and only then applies `chmod(0o600)`, so a newly-created credential file can have a permissive mode window and a failed write can leave partial contents. Credential storage should use the existing atomic/private replacement path or an equivalent DB-level design before this security boundary is mergeable.
  - confidence: 0.9
- **[P2] Preserve long-running final-response requests:** `src/gateway/client.ts:520-524`
  - body: The new default timeout is applied even when `expectFinal` is true. Current main explicitly leaves `expectFinal` requests unbounded unless a caller opts into `timeoutMs`, because long-running agent/session calls can legitimately wait past the normal RPC deadline.
  - confidence: 0.88
- **[P2] Persist KDF parameters in the sealed envelope:** `src/infra/sealed-json-file.ts:38-39`
  - body: The sealed format derives keys with `scryptSync` defaults but does not store KDF parameters in the envelope. That makes the security posture hard to audit and makes future tuning or compatibility changes risky for credential files that must remain decryptable.
  - confidence: 0.78

## Risks / Open Questions
