Overall correctness: patch is incorrect

Overall confidence: 0.93

Full review comments:

- **[P1] Target the active SQLite auth-profile store:** `src/agents/auth-profiles/store.ts:526`
  - body: This sealing path writes `auth-profiles.json`, but current main persists active auth profiles in per-agent `openclaw-agent.sqlite` and tests assert runtime no longer reads legacy JSON. Carrying this forward would leave the active credential store unsealed while presenting the feature as auth-store encryption; the fix needs to target the SQLite store and doctor migration path, or defer to https://github.com/openclaw/openclaw/issues/43794.
  - confidence: 0.95
- **[P1] Block plaintext downgrade when the passphrase is missing:** `src/agents/auth-profiles/store.ts:438`
  - body: When a sealed store is loaded without `OPENCLAW_PASSPHRASE`, `loadProtectedAuthJson()` returns `undefined`; this later write path can still persist migrated OAuth/external CLI credentials through `saveSealedJsonFile()`, which writes plaintext with no passphrase. That violates the stated fail-closed behavior and can replace encrypted credentials with plaintext.
  - confidence: 0.94
- **[P1] Write sealed credential files atomically and privately:** `src/infra/sealed-json-file.ts:113-114`
  - body: `writeFileSync()` opens/truncates the destination and only applies `chmod(0600)` afterward, so credential files get a permission window and can be left partial or clobbered through symlink-style paths. Use the repository's atomic/private write pattern for credential material instead of a direct rewrite plus post-write chmod.
  - confidence: 0.9
- **[P2] Preserve long-running final-response requests:** `src/gateway/client.ts:520-524`
  - body: This default timeout applies even when `expectFinal` is true, so long-running accepted/final gateway calls can time out after 30 seconds. Current main intentionally leaves `expectFinal` requests without an automatic client timeout unless the caller passes one; the rebased fix should preserve that behavior.
  - confidence: 0.86
- **[P2] Persist KDF parameters in the sealed envelope:** `src/infra/sealed-json-file.ts:38-39`
  - body: The sealed format derives keys with implicit Node `scryptSync` defaults and does not write KDF metadata into the envelope, making auditability and future tuning/decryption compatibility unclear. Store explicit KDF parameters with the envelope before introducing this as a credential-at-rest format.
  - confidence: 0.78
