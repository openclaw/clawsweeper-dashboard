## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Target the active auth-profile store:** `src/infra/sealed-json-file.ts:102-114`
  - body: Current main and v2026.6.11 persist provider credentials through the SQLite `auth_profile_store` row, but this helper only seals legacy JSON paths. Landing this would advertise credential sealing while leaving the active auth-profile store outside the encryption boundary.
  - confidence: 0.93
- **[P1] Block plaintext downgrades without a passphrase:** `src/infra/sealed-json-file.ts:111-114`
  - body: When `OPENCLAW_PASSPHRASE` is missing, `saveSealedJsonFile` writes plaintext. After a sealed load fails, migration or external-CLI sync can therefore replace encrypted credentials with plaintext instead of failing closed.
  - confidence: 0.91
- **[P1] Write sealed credential files atomically and privately:** `src/infra/sealed-json-file.ts:113-114`
  - body: `writeFileSync` followed by `chmodSync` truncates the destination in place and only fixes permissions after creation. Credential-bearing files should use the existing atomic private replace pattern so interrupted writes do not corrupt credentials or expose default permissions.
  - confidence: 0.88
- **[P1] Read inherited stores with the sealed reader:** `src/agents/auth-profiles/store.ts:416`
  - body: This branch can write the main auth store in sealed form, but the subagent inheritance path still reads `mainAuthPath` with `loadJsonFile`. With a passphrase-enabled store, that parse fails and subagents silently lose inherited credentials.
  - confidence: 0.86
- **[P2] Preserve expectFinal timeout semantics:** `src/gateway/client.ts:520-524`
  - body: Current main intentionally leaves `expectFinal` requests without the default request timeout unless a caller opts in. This stale implementation applies the 30s default to every request, which can break long-running accepted/final flows.
  - confidence: 0.86
- **[P2] Persist KDF parameters in the envelope:** `src/infra/sealed-json-file.ts:38-39`
  - body: `deriveKey` uses implicit scrypt parameters and the envelope stores no KDF metadata. Without explicit persisted parameters, future tuning or compatibility checks cannot know how existing credential files were derived.
  - confidence: 0.82
- **[P3] Remove the release-owned changelog edit:** `CHANGELOG.md:750`
  - body: Normal PRs should not edit `CHANGELOG.md` because release generation owns it. Keep the release-note context in the PR body or squash message instead of adding a manual changelog line.
  - confidence: 0.8

Summary: The diff is security-sensitive and has concrete credential-storage concerns around active-store coverage, plaintext downgrade, non-atomic writes, and KDF metadata.

  - body: Current main stores auth-profile payloads in SQLite JSON, while the PR seals legacy JSON paths, leaving the real provider credential store outside the new encryption boundary.

  - body: The sealed envelope cannot record or verify scrypt cost settings, which makes future security tuning and compatibility audits unsafe.
