## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P1] Target the active SQLite auth-profile store:** `src/agents/auth-profiles/store.ts:526`
  - body: This seals the legacy auth-profiles.json path, but current main persists active auth-profile secrets in openclaw-agent.sqlite auth_profile_store.store_json and tests assert runtime no longer reads auth-profiles.json. Merging this would leave the live credential store unsealed while adding an obsolete second path; the fix needs to target SQLite plus migration/doctor behavior.
  - confidence: 0.95
- **[P1] Block plaintext downgrade when the passphrase is missing:** `src/agents/auth-profiles/store.ts:435-438`
  - body: When a sealed auth-profiles.json cannot be decrypted because OPENCLAW_PASSPHRASE is missing, this path can still set shouldWrite via legacy/OAuth/CLI sync and then save the store. Because saveSealedJsonFile writes plaintext without a passphrase, a sealed credential store can be overwritten with plaintext instead of failing closed.
  - confidence: 0.94
- **[P1] Write sealed credential files atomically and privately:** `src/infra/sealed-json-file.ts:113-114`
  - body: The new secret writer truncates the destination with writeFileSync and only applies chmod after writing. Credential material should use the repo's atomic/private replace pattern so a failed write, permission window, or link race cannot corrupt or expose the store.
  - confidence: 0.9
- **[P2] Preserve long-running final-response requests:** `src/gateway/client.ts:520-524`
  - body: This computes a default 30s timeout even when opts.expectFinal is true. Current main intentionally leaves expectFinal requests unbounded unless a caller supplies timeoutMs, because final-response RPCs can legitimately run longer than the normal request watchdog.
  - confidence: 0.88
- **[P2] Persist KDF parameters in the sealed envelope:** `src/infra/sealed-json-file.ts:38-39`
  - body: deriveKey uses implicit Node scrypt defaults and the envelope stores no KDF parameters. That makes future cost tuning and decrypt compatibility ambiguous for a credential-at-rest format that users may need to keep readable across releases.
  - confidence: 0.82

## Security Review

Status: needs_attention

Summary: The diff changes credential-at-rest protection but currently misses the active SQLite secret store and can downgrade or unsafely rewrite credential files.

- **[high] Live credential store remains unsealed:** `src/agents/auth-profiles/store.ts:526`
  - body: The PR seals legacy JSON files, while current main stores active auth profile secrets in SQLite; users could believe credentials are encrypted while the live store remains plaintext.
  - confidence: 0.95
- **[high] Sealed store can be overwritten as plaintext:** `src/agents/auth-profiles/store.ts:435`

  - confidence: 0.94
- **[medium] Secret file write is not atomic or private from creation:** `src/infra/sealed-json-file.ts:113`
  - body: Direct writeFileSync plus chmod-after-write can truncate an existing credential file and creates a permission window before mode 0o600 is applied.
  - confidence: 0.9

  - body: Implicit scrypt defaults without persisted KDF parameters make long-term audit and format evolution for encrypted credentials fragile.
  - confidence: 0.82

## Risks / Open Questions

- The sealing implementation targets legacy auth-profiles.json and oauth.json while current main stores active auth-profile secrets in openclaw-agent.sqlite, so merging as-is would leave the live credential store unencrypted.
- Missing or invalid OPENCLAW_PASSPHRASE can make a sealed store look absent and let legacy/OAuth/CLI sync paths overwrite it with plaintext credentials.
- The new credential writer uses direct writeFileSync plus chmod-after-write instead of the repo's atomic/private write pattern, exposing truncation, permission-window, and symlink/TOCTOU risk on secrets.
- OPENCLAW_PASSPHRASE is a new operator env surface with startup, unattended service, recovery, and lost-passphrase implications that need a maintainer-approved migration and support design.
- The gateway timeout part is superseded by current main, and the PR's older implementation would reintroduce a default timeout for expectFinal requests that current tests intentionally avoid.
