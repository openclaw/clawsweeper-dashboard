## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Target the active auth-profile store:** `src/agents/auth-profiles/paths.ts:29`
  - body: Current main no longer persists active auth-profile secrets through this JSON-file writer: `saveAuthProfileStore` writes the secrets payload into `openclaw-agent.sqlite` via `writePersistedAuthProfileStoreRaw`. Sealing `auth-profiles.json` after rebase would either miss the active credentials or reintroduce a stale persistence path, so the credential encryption work needs to move to the SQLite auth-profile store.
  - confidence: 0.9
- **[P1] Block plaintext downgrades without a passphrase:** `src/agents/auth-profiles/store.ts:438`
  - body: When the existing store is sealed and `OPENCLAW_PASSPHRASE` is absent, `loadProtectedAuthJson` returns `undefined`; this path can still set `shouldWrite` via legacy/OAuth/CLI migration and call `saveSealedJsonFile` with no passphrase. That overwrites the sealed credential store as plaintext instead of failing closed.
  - confidence: 0.94
- **[P1] Write sealed credential files atomically and privately:** `src/infra/sealed-json-file.ts:113`
  - body: This writes credential-bearing data directly to the destination and only applies `chmod(0o600)` afterward. A crash can corrupt or truncate the store, and newly-created files can exist with default permissions before chmod; use the repo's private atomic replace pattern or an equivalent secure writer before this becomes a credential boundary.
  - confidence: 0.9
- **[P2] Preserve expectFinal timeout semantics:** `src/gateway/client.ts:520-524`
  - body: This applies the 30s default timeout to every request, including `expectFinal` calls that may intentionally wait after an accepted response for a long-running agent result. Current main explicitly leaves `expectFinal` requests without an automatic request timeout unless a caller supplies one, so a rebase should preserve that behavior.
  - confidence: 0.86
- **[P2] Persist KDF parameters in the envelope:** `src/infra/sealed-json-file.ts:39`
  - body: The sealed format derives keys with implicit Node `scryptSync` defaults and does not record KDF parameters in the file envelope. That makes future tuning or compatibility review harder for a shipped credential format; store explicit KDF metadata and validate it on read before this format lands.
  - confidence: 0.82
- **[P3] Remove the release-owned changelog edit:** `CHANGELOG.md:750`
  - body: Normal PRs should not edit `CHANGELOG.md`; release generation owns that file. Keep the release-note context in the PR body or squash message and drop this changelog hunk before merge.
  - confidence: 0.92

## Security Review
