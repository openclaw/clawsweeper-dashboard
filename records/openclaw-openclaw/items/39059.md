## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Target the active SQLite auth-profile store:** `src/infra/sealed-json-file.ts:107-114`
  - body: This new sealing helper only protects JSON files, but current main reads and writes auth-profile secrets through the per-agent `openclaw-agent.sqlite` `auth_profile_store` row. After a rebase this would leave the active credential store plaintext while adding a stale JSON sealing path, so the credential-at-rest change needs to move to the current SQLite/config persistence design.
  - confidence: 0.92
- **[P1] Block plaintext downgrade when the passphrase is missing:** `src/agents/auth-profiles/store.ts:435`
  - body: When a sealed store cannot be read because `OPENCLAW_PASSPHRASE` is missing, this load path returns no store and later migration or external-CLI sync can call `saveSealedJsonFile` without a passphrase. That rewrites the destination as plaintext, so the intended fail-closed behavior is not actually preserved.
  - confidence: 0.93
- **[P1] Write sealed credential files atomically and privately:** `src/infra/sealed-json-file.ts:113-114`
  - body: `writeFileSync` followed by `chmodSync` creates the file before restrictive permissions are guaranteed and rewrites credentials in place. Credential writes need the existing atomic/private replace pattern or equivalent `0600` creation-time handling so partial writes, readable windows, and symlink/clobber cases are not introduced on a security boundary.
  - confidence: 0.88
- **[P2] Preserve long-running final-response requests:** `src/gateway/client.ts:517-523`
  - body: This timeout default applies to all requests, including `expectFinal` calls that can legitimately wait past 30 seconds after an accepted response. Current main's packaged client intentionally skips the default watchdog for `expectFinal` unless a caller passes `timeoutMs`, so carrying this implementation forward would regress long-running agent/chat requests.
  - confidence: 0.86
- **[P2] Persist KDF parameters in the sealed envelope:** `src/infra/sealed-json-file.ts:38-40`
  - body: The sealed format derives keys with implicit `scryptSync` defaults but does not record KDF parameters in the envelope. For a credential-at-rest format, the work factors need to be explicit and versioned so reviewers can audit strength and future changes do not strand existing sealed stores.
  - confidence: 0.78

## Security Review

Status: needs_attention

Summary: The PR changes credential-at-rest behavior but leaves concrete active-store coverage, downgrade, atomic-write, and KDF-envelope security issues unresolved.

Concerns:

- **[high] Active SQLite credentials remain unsealed:** `src/infra/sealed-json-file.ts:107`
  - body: Current main persists auth-profile secrets in `openclaw-agent.sqlite`, while the PR only seals legacy JSON paths, so the advertised auth-store encryption would not cover the active provider credential store after rebase.
  - confidence: 0.92
- **[high] Missing passphrase can downgrade sealed JSON to plaintext:** `src/agents/auth-profiles/store.ts:435`
  - body: The load path swallows the passphrase-required condition, and later write paths can save plaintext when the passphrase is absent, causing credential exposure and possible data loss.
  - confidence: 0.93
- **[medium] Credential writes are not atomic or private at creation:** `src/infra/sealed-json-file.ts:113`
  - body: Direct `writeFileSync` plus post-write chmod can expose credentials under permissive umask, lose prior contents on partial writes, and follow attacker-controlled links in unsafe state directories.
  - confidence: 0.88
- **[medium] KDF parameters are implicit and unversioned:** `src/infra/sealed-json-file.ts:38`
  - body: The sealed envelope omits explicit scrypt parameters, making brute-force posture and future decryptability harder to audit or evolve safely.
  - confidence: 0.78
