## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Target the active SQLite credential store:** `src/infra/sealed-json-file.ts:102-115`
  - body: Current main writes auth profiles to `openclaw-agent.sqlite` (`auth_profile_store.store_json`), and docs describe legacy `auth-profiles.json` as a doctor-import source. Adding sealed JSON here does not encrypt the active credential path, so this branch would ship partial coverage while leaving the current store plaintext.
  - confidence: 0.91
- **[P1] Block plaintext overwrite when the passphrase is missing:** `src/agents/auth-profiles/store.ts:32-39`
  - body: When a sealed auth store is loaded without `OPENCLAW_PASSPHRASE`, this code logs and returns `undefined`; the later migration/CLI sync path can then call `saveSealedJsonFile`, which writes plaintext with no passphrase. That silently downgrades an encrypted credential store and can lose the sealed contents.
  - confidence: 0.93
- **[P1] Write sealed credential files atomically and privately:** `src/infra/sealed-json-file.ts:113-114`
  - body: `writeFileSync(pathname, ...)` followed by `chmodSync` truncates the target in place and only restricts permissions after creation. For credential material this keeps the old partial-write lockout risk, creates a readable permission window, and follows symlinks before chmod; use the established private atomic replacement pattern instead.
  - confidence: 0.88
- **[P2] Preserve long-running final-response requests:** `src/gateway/client.ts:519-524`
  - body: This branch gives every request a default timeout even when `expectFinal` is true. Current main explicitly leaves `expectFinal` requests untimed by default and tests that behavior because final agent responses can legitimately run longer than the normal RPC watchdog.
  - confidence: 0.86
- **[P2] Persist KDF parameters in the sealed envelope:** `src/infra/sealed-json-file.ts:38-40`
  - body: The encrypted envelope derives keys with implicit Node `scryptSync` defaults and does not record KDF parameters. That makes the security cost hard to audit and leaves no stable per-file parameters for future tuning without risking decryptability drift.
  - confidence: 0.78
