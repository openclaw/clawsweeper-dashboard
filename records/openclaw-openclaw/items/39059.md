## Summary

Keep the PR open for maintainer/security review: the gateway-timeout idea is now largely covered by current main, while the credential-at-rest path is not merge-ready because it misses the active SQLite auth store and introduces downgrade/file-safety risks.

## What This Changes

The PR adds gateway request timeouts, optional `OPENCLAW_PASSPHRASE` sealing for auth-profile/OAuth JSON files, mirrored transcript chmod hardening, tests, and a changelog note.

## Best Possible Solution

Rebase and split the work so current package gateway behavior is preserved, credential-at-rest protection is redesigned around the active SQLite auth store with approved key-management/migration/recovery policy, and any file envelope uses atomic private writes with explicit KDF metadata.

## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Target the active SQLite auth-profile store:** `src/agents/auth-profiles/store.ts:523`
  - body: The PR seals `auth-profiles.json`, but current main persists active auth-profile secrets in `openclaw-agent.sqlite` via `auth_profile_store.store_json`. Landing this path would leave the primary credential store unsealed while advertising auth-store encryption, so the design needs to move to the SQLite auth store and its migration/recovery flow before merge.
  - confidence: 0.93
- **[P1] Keep subagent inheritance sealed-aware:** `src/agents/auth-profiles/store.ts:413`
  - body: This PR can write the main auth store in sealed form, but the subagent inheritance path still reads the main store with the old JSON loader before saving the inherited copy. With `OPENCLAW_PASSPHRASE` configured, that reader cannot parse the sealed prefix, so subagents silently stop inheriting credentials.
  - confidence: 0.86
- **[P1] Block plaintext downgrades without a passphrase:** `src/infra/sealed-json-file.ts:113`
  - body: When a sealed auth file exists but `OPENCLAW_PASSPHRASE` is missing, the loader returns `undefined`; later migration or CLI sync paths can call this writer without a passphrase and overwrite the sealed file as plaintext. A sealed destination must not be rewritten unless the passphrase is available or maintainers explicitly choose a recovery path.
  - confidence: 0.94
- **[P1] Write sealed credential files atomically and privately:** `src/infra/sealed-json-file.ts:113-114`
  - body: This direct `writeFileSync` followed by `chmodSync` opens a credential path with a post-write permission fix and no atomic replacement. Credential writes should use the existing fs-safe atomic/private writer pattern so partial writes, symlinks, and transient permissions are not part of the security boundary.
  - confidence: 0.88
- **[P2] Persist KDF parameters in the sealed envelope:** `src/infra/sealed-json-file.ts:38-39`
  - body: The sealed format derives keys with implicit `scryptSync` defaults but does not store the KDF settings in the envelope. That makes the at-rest security level and future decryptability/migration behavior ambiguous, so the envelope should record explicit parameters before this becomes a persisted credential format.
  - confidence: 0.82
- **[P2] Preserve long-running final-response requests:** `src/gateway/client.ts:520-524`
  - body: This timeout applies to every request, including `expectFinal` calls that can legitimately wait for a final agent response after an accepted ack. Current main's package client deliberately leaves `expectFinal` unbounded unless a caller supplies `timeoutMs`, so any rebased timeout change must preserve that behavior.
  - confidence: 0.86

## Security Review

Status: needs_attention

Summary: The diff introduces a credential-at-rest path but leaves concrete downgrade, active-store coverage, filesystem-safety, subagent inheritance, and KDF-envelope concerns.

Concerns:

- **[high] Credential sealing misses the active auth store:** `src/agents/auth-profiles/store.ts:523`
  - body: Current main stores auth-profile secrets in SQLite, while the PR seals legacy JSON files, so users could believe auth profiles are protected even though the active store remains plaintext JSON in SQLite.
  - confidence: 0.93
- **[high] Sealed files can be overwritten in plaintext:** `src/infra/sealed-json-file.ts:113`
  - body: A sealed file without `OPENCLAW_PASSPHRASE` is treated as missing, and later writes can persist plaintext over it, defeating the fail-closed security claim and risking credential exposure or loss.
  - confidence: 0.94
- **[medium] Credential file writes are not atomic/private at creation:** `src/infra/sealed-json-file.ts:113`
  - body: The new writer writes the destination directly and chmods afterward rather than using a temp-file atomic replace with private mode, which is too weak for a credential boundary.
  - confidence: 0.88
- **[medium] KDF parameters are implicit and not stored:** `src/infra/sealed-json-file.ts:38`
  - body: The envelope omits explicit scrypt parameters, making both auditability and future migration/decryption behavior unclear for a persisted secret format.
  - confidence: 0.82
