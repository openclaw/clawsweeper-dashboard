Full review comments:

- **[P1] Target the active auth-profile store:** `src/agents/auth-profiles/paths.ts:32`
  - body: This changes the legacy auth-profiles.json path, but current main persists auth profiles in SQLite and tests assert auth-profiles.json is absent and ignored at runtime. Landing this as credential-at-rest hardening would leave the active provider credential store unsealed and create a stale second storage policy.
  - confidence: 0.93
- **[P1] Block plaintext downgrades when passphrase is absent:** `src/agents/auth-profiles/store.ts:438`
  - body: If a sealed store cannot be read because OPENCLAW_PASSPHRASE is missing, this path can still decide to write migrated/OAuth/external CLI data and call saveSealedJsonFile. With no passphrase, that helper writes plaintext, so a sealed credential store can be replaced with plaintext instead of failing closed.
  - confidence: 0.92
- **[P1] Write sealed credentials atomically and privately:** `src/infra/sealed-json-file.ts:113-114`
  - body: writeFileSync followed by chmodSync truncates the destination in place and only fixes permissions after creation. Credential-bearing files should use the existing private atomic replace pattern so interrupted writes do not corrupt credentials and temporary contents are not exposed under default permissions.
  - confidence: 0.89
- **[P2] Preserve expectFinal timeout semantics:** `src/gateway/client.ts:520-524`
  - body: Current main already implements request timeouts in packages/gateway-client and intentionally avoids applying the default timeout to expectFinal requests unless a caller opts in. This stale implementation applies a default timer to every request, which can break accepted/final flows if revived unchanged.
  - confidence: 0.84
- **[P2] Persist KDF parameters in the sealed envelope:** `src/infra/sealed-json-file.ts:38-39`
  - body: deriveKey uses implicit Node scrypt defaults, and the envelope stores only version, algorithm, salt, iv, tag, and ciphertext. Without explicit KDF metadata, future tuning or compatibility checks cannot tell how existing credential files were derived.
  - confidence: 0.82

## Security Review

Status: needs_attention

Summary: The diff changes credential storage but leaves concrete downgrade, active-store coverage, atomic-write, and KDF metadata concerns unresolved.

- **[high] Active credential store remains unencrypted:** `src/agents/auth-profiles/paths.ts:32`
  - body: Current main stores auth-profile payloads in SQLite JSON, while the PR seals legacy JSON paths, leaving the real provider credential store outside the new encryption boundary.
  - confidence: 0.93

  - confidence: 0.92
