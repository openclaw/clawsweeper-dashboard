## Summary

Keep open: this protected maintainer/security PR is not cleanup-closeable, and the current patch is not merge-ready because its auth sealing targets legacy JSON paths while current main stores active auth profiles in SQLite, with additional downgrade and secret-writer risks.

## What This Changes

The PR adds bounded GatewayClient request timeouts, optional `OPENCLAW_PASSPHRASE` sealing for auth JSON stores, transcript chmod hardening, tests, and a changelog entry.

## Best Possible Solution

## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.93

Full review comments:

- **[P1] Target the active SQLite auth-profile store:** `src/agents/auth-profiles/store.ts:526`
  - body: Current main stores active auth-profile secrets in `openclaw-agent.sqlite` via `writePersistedAuthProfileStoreRaw`, but this patch seals only `auth-profiles.json`/legacy JSON paths. That would leave the live credential store outside the new protection, so the auth-at-rest design needs to cover the SQLite row and its migration/doctor path before merge.
  - confidence: 0.95
- **[P1] Block plaintext downgrade when the passphrase is missing:** `src/agents/auth-profiles/store.ts:438`
  - body: If a sealed `auth-profiles.json` cannot be read because `OPENCLAW_PASSPHRASE` is missing, this path can still set `shouldWrite` from legacy/OAuth/CLI sync and then call `saveSealedJsonFile` without a passphrase. That rewrites the store as plaintext instead of failing closed.
  - confidence: 0.96
- **[P1] Write sealed credential files atomically and privately:** `src/infra/sealed-json-file.ts:113-114`
  - body: `saveSealedJsonFile` writes the credential file directly and only then chmods it. Secret-bearing writes need the repo's atomic/private replacement pattern or equivalent create-with-0600 behavior to avoid truncation, permission-window, and symlink/TOCTOU exposure.
  - confidence: 0.9
- **[P2] Preserve long-running final-response requests:** `src/gateway/client.ts:520-524`
  - body: The PR applies the default timeout even when `expectFinal` is true, but current main intentionally leaves `expectFinal` requests without a default auto-timeout unless the caller passes `timeoutMs`. Reintroducing a 30s default here can abort long-running agent/final-response flows.
  - confidence: 0.86
- **[P2] Persist KDF parameters in the sealed envelope:** `src/infra/sealed-json-file.ts:39`
  - body: The sealed format derives keys with implicit `scryptSync` defaults and stores no KDF metadata, making the crypto parameters hard to audit and future tuning/decryption compatibility ambiguous. The envelope should include explicit KDF parameters before this becomes a durable credential format.
  - confidence: 0.78
