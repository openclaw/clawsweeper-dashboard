## Summary

Keep open: the PR is close and has strong proof for the original manual `deleteAfterRun` bug, but a due `at` job whose manual run succeeds can still lose its scheduled slot through the post-run maintenance recompute, so it needs one narrow fix before merge.

## What This Changes

The PR adds manual-run isolation to cron result handling, records `lastRunWasManual` in cron state/protocol, preserves scheduled retry/backoff/failure-alert state for manual runs, and expands cron regression coverage.

## Best Possible Solution

Manual runs should record their outcome while preserving the scheduled `nextRunAtMs` for one-shot jobs in all terminal statuses, with scheduled runs still deleting, disabling, retrying, and backing off normally.
