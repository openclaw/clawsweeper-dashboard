## What This Changes

The branch makes manual `openclaw cron run` executions preserve one-shot jobs and scheduler timing while retaining consuming behavior for scheduled timer runs and gateway on-exit watcher runs.

## System Context

OpenClaw’s cron service stores scheduled jobs and their execution state, while the gateway invokes it from the scheduler, CLI/RPC operator requests, and on-exit watchers. Each execution result updates job persistence, retry timing, alerts, and optional one-shot deletion before later scheduler ticks use that state.

  E --> F[Persist run outcome]
  F --> G[Scheduler state and retry timing]
  F --> H[One-shot deletion or preservation]

## Best Possible Solution

Keep the public cron run API operator-only, preserve watcher-terminal behavior behind the concrete gateway entry point, and add a redacted final-head live gateway proof covering manual preservation, scheduled deletion, watcher-terminal deletion, and restart/upgrade state reload.
