## Summary

Keep this PR open: the reported bug remains valid and the branch has substantial regression coverage, but scheduler-only origin control is still exposed through the shared cron service API, and the supplied exact-head evidence is a direct-function Vitest harness rather than a real CLI and Gateway watcher run.

## What This Changes

The PR distinguishes timer, Gateway watcher, and operator cron origins so operator runs preserve one-shot jobs and scheduler-owned counters, backoff, and next-run state.

## Best Possible Solution

Keep the explicit origin model internally, leave the public/plugin-facing cron run options operator-only, route watcher-terminal execution through a Gateway-owned internal method, and prove both paths with a real exact-head CLI/Gateway lifecycle.
