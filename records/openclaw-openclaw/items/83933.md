## Summary

This PR still carries a blocking owner-boundary defect: the scheduler-only run origin remains exposed through the public cron service options, allowing plugin-facing callers to request consuming scheduler semantics. The central bug remains valid and is not implemented on current main, so the PR should stay open for a narrow repair and live current-head proof.

## What This Changes

The PR distinguishes operator, timer, and watcher-terminal cron runs so manual runs preserve one-shot jobs and scheduler state while scheduled runs retain consuming behavior.

## Best Possible Solution

Keep `CronServiceRunOptions` payload-only, route watcher-terminal provenance through an internal gateway-to-cron seam, retain the explicit origin model inside cron internals, and prove both operator preservation and watcher consumption on a live current-head Gateway.
