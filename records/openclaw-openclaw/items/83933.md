## Summary

Keep this PR open for human review. The patch targets the reported destructive manual-run behavior and preserves the timer/on-exit distinction, but its supplied live gateway transcript is pinned to an earlier head while later commits changed the same timer and operator-run paths; a redacted final-head run is still needed before merge, along with confirmation that manual cron runs should be non-consuming by contract.

## What This Changes

The branch introduces internal cron run origins so public manual runs preserve one-shot jobs and scheduler state, while timer and gateway on-exit runs continue to consume scheduler-owned state.

## Best Possible Solution

Keep public `cron run` as an explicitly non-consuming verification operation only if maintainers confirm that contract, then add a final-head live gateway + CLI + SQLite transcript covering operator preservation, watcher-terminal deletion, a restart reload, and a paced-job pending-slot case.
