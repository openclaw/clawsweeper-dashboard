## Summary

Keep this PR open: current main still has the reported manual-run bug, but the exact head exposes a scheduler-only origin through the public cron service contract and still lacks after-fix proof through the real CLI and Gateway watcher paths.

## What This Changes

The PR distinguishes operator, timer, and Gateway watcher cron origins so operator runs preserve one-shot jobs, counters, backoff, enabled state, and next-run timing.

## Best Possible Solution

Keep ordinary `CronServiceContract.run` operator-only, add a Gateway-owned internal watcher execution seam that supplies consuming semantics without exposing the origin selector to plugins, and prove operator plus watcher behavior against a real persisted cron store.
