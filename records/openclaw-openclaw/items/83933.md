## Summary

Keep open: the PR still carries a meaningful bug fix that current main and v2026.6.11 do not have, and I found no blocking code finding on the current head. The remaining blocker is maintainer acceptance of the compatibility-sensitive cron contract: manual runs become non-consuming for deleteAfterRun, counters, retry/backoff, failure alerts, and persisted state.

## What This Changes

The branch adds manual-run awareness to cron result handling, preserves scheduled cron state during manual runs, exposes `lastRunWasManual` in cron state/protocol schemas, and adds focused cron regression coverage.

Accept a documented non-consuming manual cron contract after exact-head gates, with scheduled timer behavior and schema compatibility explicitly owned by maintainers.
