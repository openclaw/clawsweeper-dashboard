## Summary

Keep open. Current main still routes manual and on-exit force runs through the same finalization behavior, so the reported destructive manual-run behavior remains relevant; the PR’s private watcher-terminal path is a plausible bounded fix, but its changed public cron-run contract requires maintainer confirmation and current-head runtime proof before merge.

## What This Changes

The PR makes public cron runs operator-only so they preserve scheduler-owned counters, next-run state, and delete-after-run one-shots, while retaining consuming behavior for timer and gateway on-exit watcher runs.

## Best Possible Solution

Adopt one explicit documented contract: public cron runs are non-consuming verification runs, while the gateway’s on-exit watcher alone uses a private consuming entry point; then prove that contract on the final head with a live gateway, CLI, SQLite readback, restart/maintenance recomputation, and watcher-terminal deletion scenario.
