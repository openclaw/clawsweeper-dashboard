## Summary

The latest head resolves both prior P1 findings by carrying an explicit execution origin and preserving watcher-terminal one-shot consumption, but one changed invalid-persisted-run path still hard-codes the origin as `operator`, so watcher-terminal failures can be finalized with manual-run semantics.

## What This Changes

Threads explicit timer, watcher-terminal, and operator origins through cron finalization, persists manual-run provenance, and expands scheduler, restart, deletion, alert, and backoff regression coverage.

## Best Possible Solution

Keep one explicit, trusted origin value from every entry point through every terminal path, add watcher-terminal invalid-spec coverage, rebase onto current main, and provide current-head live proof that operator runs preserve jobs while watcher-terminal runs still consume successful one-shots.
