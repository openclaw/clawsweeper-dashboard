## Summary

Keep open. Current main still applies one-shot deletion and scheduler-state mutations without distinguishing operator runs, while the branch fixes the latest prior origin-forwarding finding and appears functionally sound. No blocking code defect remains, but the exact-head evidence exercises source through a Vitest harness rather than a live CLI/Gateway user flow, so the external real-behavior proof gate remains unmet.

## What This Changes

The branch adds explicit timer, watcher-terminal, and operator cron-run origins so manual runs preserve scheduled one-shots and scheduler counters while timer and gateway watcher runs retain consuming semantics.

## Best Possible Solution

Land the explicit origin model after exact-head live proof shows an operator CLI/RPC run preserves a scheduled one-shot and its counters, while a real gateway watcher-terminal run still consumes a successful on-exit one-shot; then refresh against current main and keep consuming origins unavailable to external RPC input.
