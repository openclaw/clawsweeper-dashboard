## Summary

Keep this PR open for maintainer confirmation of the permanent operator-run contract. The implementation and live proof are strong, but the fix deliberately broadens manual-run semantics across persisted counters, backoff, alerts, timing, enabled state, and one-shot consumption, and several current checks still report failures.

## What This Changes

This PR introduces internal cron run origins so operator runs preserve one-shot jobs and scheduler-owned state while timer and on-exit watcher runs retain consuming semantics.

## Best Possible Solution

Adopt one explicit internal origin model where operator runs record history but never own scheduler state, keep consuming origins inaccessible through public cron contracts, preserve watcher-terminal deletion, and land only with confirmed upgrade behavior and green attributable checks.
