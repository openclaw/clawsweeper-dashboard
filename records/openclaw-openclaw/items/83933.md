## Summary

Keep this PR open: the core bug and explicit-origin model are well supported, but the current head still exposes scheduler-only origins through the public cron service contract, lacks an actual exact-head CLI/Gateway runtime cycle, and broadens operator-run semantics without maintainer confirmation.

## What This Changes

The PR threads timer, Gateway watcher, and operator run origins through cron finalization so operator runs preserve one-shot jobs and scheduler-owned state while scheduled origins remain consuming.

## Best Possible Solution

Keep `CronService.run` operator-only, route the Gateway exit watcher through a private/internal consuming entry point, centralize origin-based finalization internally, and prove both operator preservation and watcher consumption through exact-head CLI/Gateway runtime cycles after maintainers confirm the operator-state policy.
