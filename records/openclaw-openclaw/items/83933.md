## Summary

The current PR head still misclassifies user-invoked trigger checks as scheduler-owned when the trigger does not fire or its evaluator fails. The original manual-run data-loss bug remains valid and current main does not implement the requested isolation, so this PR should stay open for one bounded repair rather than close.

## What This Changes

The branch prevents manual cron runs from consuming delete-after-run jobs or scheduled retry state, adds a persisted last-run origin field, and expands regression coverage across manual and timer-owned execution paths.

## Best Possible Solution

Carry a closed execution-origin value from the public run and timer entry points through preparation and result application; every public due/force invocation remains manual, while only timer-owned polling mutates scheduled retry state.
