## Label Justifications

- `P1`: The PR addresses destructive behavior that can silently consume a scheduled one-shot and corrupt its scheduler state during operator verification.
- `merge-risk: 🚨 compatibility`: The patch intentionally changes the established semantics of public manual cron runs across counters, alerts, timing, enabled state, and deletion.
- `merge-risk: 🚨 session-state`: The patch separates the visible last-run result from scheduler-owned persisted counters and timing, making restart and mixed-origin coherence merge-critical.

## Summary

This PR remains necessary because current main still lets manual cron runs consume one-shots and mutate scheduler-owned state. The internal-origin design appears correct and the live proof is strong, but landing it requires explicit agreement that every operator run is observational and non-consuming, not only the reported successful `deleteAfterRun` case.

## What This Changes

The PR distinguishes operator, timer, and on-exit watcher cron runs so manual executions preserve one-shot jobs, scheduler counters, retry timing, and enabled state.

## Best Possible Solution

Adopt a single internal origin-aware finalization path where public operator runs record diagnostics only, timer and watcher executions exclusively own scheduling state, and persisted tests prove that boundary across restart and upgrades.
