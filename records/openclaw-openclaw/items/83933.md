## Summary

The central manual-run bug is valid and strongly proven, but the current patch still conflates execution origin with trigger outcome. It consequently gives operator due-mode errors scheduled semantics while giving scheduler-owned on-exit watcher runs manual semantics, so it is not safe to merge yet.

## What This Changes

The PR makes operator cron runs preserve one-shot jobs and scheduler-owned counters, backoff, alerts, and scheduling state, while persisting whether the last run was manual.

## Best Possible Solution

Carry a closed operator/timer/watcher execution-origin value from each entry point and apply non-consuming preservation only to operator-origin runs, with caller-specific regressions for due-mode trigger checks, timer evaluations, and on-exit watchers.
