## Summary

The latest head still conflates caller origin with trigger outcome: a user-invoked `due` check is reclassified as scheduled when its evaluator errors or is unavailable. Because that path mutates retry, alert, backoff, and persisted run-origin state, the prior P1 remains merge-blocking despite strong proof for the central deletion fix.

## What This Changes

The PR makes manual cron runs preserve scheduled deletion, retry, backoff, alert, and due-slot state, and adds persisted run-origin metadata plus regression coverage.

## Best Possible Solution

Carry an explicit scheduler-versus-user origin through cron execution, keep every public `cron.run` and `enqueueRun` completion non-consuming, and exercise timer-owned evaluator failures through a distinct scheduled path.
