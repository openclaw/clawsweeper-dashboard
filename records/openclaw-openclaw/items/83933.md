## Label Justifications

- `P1`: The PR fixes a cron workflow that can silently consume scheduled one-shot jobs and lose future scheduled work during manual verification.
- `merge-risk: 🚨 compatibility`: Manual `cron run` behavior changes from consuming scheduled state to preserving delete, retry, counter, and alert state.

- `merge-risk: 🚨 message-delivery`: Preserving one-shot jobs after manual runs changes whether later scheduled cron deliveries still occur, which is intended but user-visible.

## Summary

Keep open: current main still has the manual cron run bug, and this active PR remains the canonical fix path. The latest head fixes the previous backoff-preservation finding, so I found no new blocking code finding, but the cron state/protocol behavior change still needs maintainer acceptance and exact-head merge validation.

## What This Changes

The PR makes manual cron runs non-consuming by passing an `isManual` flag through cron completion, preserving scheduled delete-after-run jobs, counters, retry/backoff state, failure-alert cooldowns, and adding `lastRunWasManual` to cron state/protocol schemas.

## Best Possible Solution

Adopt one cron contract where scheduled runs own delete/retry/counter/failure-alert state, manual runs record their result without consuming scheduled state, and clients treat `lastRunWasManual` as an optional cron state field.
