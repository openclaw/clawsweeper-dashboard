## Summary

Keep this PR open, but do not merge the current head. The live proof is strong and the earlier public-origin and watcher-terminal concerns are fixed, but the previously reported P1 remains: an operator run can lose an already-overdue scheduled slot because the run preparation consumes the in-memory slot while operator finalization deliberately avoids restoring or recomputing scheduler-owned state.

## What This Changes

The PR separates operator cron runs from timer and on-exit watcher runs so manual executions preserve one-shot jobs, counters, backoff, enabled state, and scheduled timing.

## Best Possible Solution

Carry the authoritative pre-run nextRunAtMs through operator preparation and restore it during operator finalization, while leaving timer and watcher-terminal ownership unchanged; add overdue at, every, and cron-schedule regressions plus the existing watcher consumption controls.
