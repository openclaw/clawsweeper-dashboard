## Summary

This is a plausible, narrowly scoped fix for the destructive manual-run behavior reported by https://github.com/openclaw/openclaw/issues/83538, and the branch keeps the scheduler-consuming on-exit path internal. However, the supplied live transcript is pinned to an earlier head and does not directly cover the later overdue-slot and recurring-slot corrections, so current-head runtime proof and cron-owner confirmation remain necessary before merge.

Likely related people: `yetval` is a high-confidence routing candidate for recent cron scheduling-state work; `ObliviateRickLin` is a medium-confidence candidate for the merged on-exit delete-after-run contract.

## What This Changes

The PR makes public cron runs operator-only, preserving delete-after-run jobs and scheduler-owned counters for manual runs while retaining consuming behavior for timer and gateway on-exit watcher executions.

## Best Possible Solution

Keep the public run API operator-only, retain the concrete watcher-terminal entry for the gateway, and add one redacted current-head live gateway/CLI transcript that proves manual one-shot preservation through maintenance/restart plus the next scheduled timer fire; obtain cron-owner confirmation of the public compatibility contract before landing.
