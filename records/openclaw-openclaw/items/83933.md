## Summary

Keep open for maintainer review: the patch appears correct and well-proven, but it intentionally changes compatibility-sensitive manual cron semantics and the public cron state surface.

## What This Changes

The branch marks manual cron completions as manual, preserves scheduled delete/retry/backoff/counter/alert state for those runs, exposes `lastRunWasManual`, and expands cron regression/protocol coverage.

## Best Possible Solution

Merge or revise the shared `applyJobResult` manual-run isolation after maintainers confirm `cron run` is a non-consuming verification command; keep failed-run deletion and isolated-job default cleanup policy in separate linked work.
