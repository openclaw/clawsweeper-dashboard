## Summary

This PR remains necessary because current main still lets manual cron runs consume one-shot jobs and mutate scheduled state, but the current head still misclassifies user-invoked trigger checks as scheduler work and can back off the scheduled fire it intends to preserve.

## What This Changes

The PR prevents manual cron runs from consuming `deleteAfterRun` jobs or altering scheduled retry, backoff, alert, and due-slot state, and adds persisted last-run origin metadata with regression coverage.

## Best Possible Solution

Carry an explicit scheduler-owned versus user-owned run origin into result application: every public `cron.run(..., "due" | "force")` request should remain manual, while only timer-owned trigger polling should update scheduled counters and backoff.
