## Summary

Keep open: this PR targets a real Discord reply-fanout bug, but the current patch is not merge-ready because it suppresses explicit/direct chunked replies based on mode alone and widens the reply mode type to `string`.

## What This Changes

The PR changes Discord outbound send wiring so chunked implicit first-mode replies only carry the native Discord reply reference on the first physical chunk.

## Best Possible Solution

Make the Discord send-layer suppression source-aware and keep `replyToMode` on the closed `ReplyToMode` type so implicit single-use replies only reference the first physical chunk while explicit/direct reusable replies keep existing chunk behavior.

## Reproduction Assessment

Yes. Current-main tests, docs, and `createReplyToFanout` source show that explicit/direct reply ids are reusable, while the PR’s changed gate suppresses trailing chunks based only on mode.

## Solution Assessment

No. The safer fix is source-aware gating with a closed `ReplyToMode` option, because it addresses implicit first-mode notification fanout without overwriting the existing explicit/direct reply contract.
