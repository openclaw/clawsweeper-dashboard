## Summary

Keep open: this is a valid Discord delivery bug, but the current PR still gates trailing chunks by `replyToMode` without honoring `replyToIdSource`, so it can suppress reusable explicit/direct replies in first or batched mode. The Discord screenshot is useful evidence for one implicit-first text path, but it does not prove the latest head or the compatibility-sensitive explicit/all media paths.

## What This Changes

The PR forwards Discord reply policy metadata into the Discord send layer and suppresses native reply references on trailing chunks when `replyToMode` is single-use.

## Best Possible Solution

Make the Discord send layer source-aware: suppress trailing native reply references only for implicit single-use replies, preserve explicit/direct/all reusable references, and cover text, media, payload, and audioAsVoice paths with focused tests plus current-head Discord proof.

Yes. The linked issue is source-reproducible on current main because `sendDiscordText` and media caption follow-ups reuse the same `replyTo` across physical chunks, and the reporter provided instrumented Discord request logs.

## Solution Assessment

No. The PR is in the right owner area, but the best fix must preserve the existing explicit-source contract instead of suppressing by mode alone.
