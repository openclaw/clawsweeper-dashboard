## Label Justifications

- `P1`: A reproducible authorization-context regression prevents spawned agents from using required tools and breaks active delegated workflows for affected installations.
- `impact:security`: The issue concerns how requester-scoped tool authority is preserved and constrained across a trusted internal session boundary.
- `impact:session-state`: The effective authorization changes incorrectly when execution moves from the inbound requester session into sender-less child or fallback session state.

## Summary

The report identifies a credible current-main authorization-context bug: sender policy is recalculated after trusted internal delegation loses external sender fields, so the wildcard policy can incorrectly remove tools from a spawned child. The related reports describe different roots, and no merged fix or current-main behavior was found that resolves this specific sender-policy path.

## What This Changes

Preserve the requester's effective sender-scoped tool authorization across spawned subagents and internal completion continuations while still enforcing normal subagent restrictions.

## Best Possible Solution

Carry a trusted, normalized effective sender-policy projection through internal delegation and continuation state, intersect it with inherited and configured subagent restrictions, never synthesize public sender identity, and add positive and non-escalation tests for spawn and fallback paths.
