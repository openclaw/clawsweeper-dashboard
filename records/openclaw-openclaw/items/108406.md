## Summary

Keep this issue open: current main still constructs the ordinary local Gateway RPC target as loopback even when the configured Gateway listens only on a tailnet address. The report is distinct from the intermittent loopback closure in https://github.com/openclaw/openclaw/issues/98753, although its gateway-probe claim should be narrowed because that command is documented to always include a loopback probe.

## What This Changes

Make local CLI health, cron, and doctor Gateway calls reach a locally configured non-loopback bind without requiring manual URL environment overrides.

## Best Possible Solution

Centralize a safe same-host target policy for local Gateway calls—preferably reusing the existing bind-aware probe-host logic or ensuring a loopback companion listener—while preserving URL/auth/TLS precedence and keeping gateway probe's documented loopback diagnostic target explicit.
