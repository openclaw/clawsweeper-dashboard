## Summary

Keep open: current main still derives the reply thread from inbound/session context, and the public outbound-hook results do not expose a destination override. The request is not covered by a canonical related item, but the permanent plugin API and routing boundary need maintainer direction before implementation.

## What This Changes

Requests a plugin hook or routing surface that can redirect a regular outbound reply to a different forum-topic thread than the inbound message.

## Best Possible Solution

Add one generic, typed, validated reply-destination override at the core delivery boundary, with Telegram mapping it to a forum-topic thread and focused sibling-channel behavior, rather than repurposing ACP child placement or adding a Telegram-only global default.
