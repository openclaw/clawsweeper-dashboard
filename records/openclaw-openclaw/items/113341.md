## Summary

This is a credible fix for the scoped-allowlist MCP regression, with updated before/after app-server proof described in the PR body. Keep it open for a maintainer decision because scoped turns intentionally change configured static MCP servers from Codex-native attachment to OpenClaw dynamic tools, which changes the approval and naming boundary. Likely related people: jleonelion (low confidence) authored the earlier approach in the superseded PR.

## What This Changes

This PR keeps user-configured MCP tools available to Codex agents with scoped tool allowlists by exposing allowlisted static servers through OpenClaw’s dynamic-tool bridge while retaining native attachment for unrestricted turns.

## System Context

Codex app-server attempts receive an OpenClaw effective tool policy plus configured user MCP servers. The runtime decides whether those servers are attached directly to Codex or materialized as OpenClaw dynamic tools, then the resulting tools become available to the agent turn.
