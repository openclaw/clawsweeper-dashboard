## Summary

The reported stale-cache path does not match current behavior: configuration and environment values are evaluated on every call, supplied discovery bypasses the cache, and plugin metadata changes are explicitly restart- or owner-reload-bound rather than hot-reloaded.

## What This Changes

Investigate whether the module-level persisted-auth channel ID cache becomes stale after configuration reloads or dynamic plugin installation.

## Best Possible Solution

Keep the bounded persisted-auth metadata cache; any future supported in-process plugin reload should atomically replace the owner-managed discovery snapshot rather than add an independent config-presence invalidation hook.
