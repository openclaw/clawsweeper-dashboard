## Summary

Keep open: current main and v2026.6.11 still lack an agent-facing `queue_status` tool or equivalent stable workload/capacity surface for intelligent dispatch; the related queue diagnostics PR is closed unmerged and was superseded by this issue.

## What This Changes

Request to add a permissioned agent-facing `queue_status` tool that reports lane depth, active versus max concurrent runs, and per-agent workload so agents can route `sessions_spawn` work intelligently.

## Best Possible Solution

Design one shared read-only queue/workload snapshot backend in core and expose it through a permissioned `queue_status` agent tool with catalog/profile/policy wiring, docs, and focused tests.

## Reproduction Assessment

Yes, as a source-level feature gap: current main exposes internal lane snapshots but no `queue_status`, `sessions_capacity`, exact `diagnostics.queue`, or equivalent model-facing workload tool. I did not run a live workload because the requested public surface is absent.

## Solution Assessment

Unclear until maintainers choose the public metadata contract. The likely best shape is a shared read-only snapshot backend reused by a permissioned agent-facing tool and any future operator diagnostics surface.
