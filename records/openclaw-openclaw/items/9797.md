## Summary

Keep open: current main still has internal queue snapshots, logs, and session/subagent listing tools, but no stable agent-facing `queue_status` or equivalent workload/capacity surface for dispatch decisions. The related operator-diagnostics PR is closed unmerged and explicitly did not add an in-agent tool.

## What This Changes

Request a model-facing `queue_status` tool exposing lane queue depth, active/max concurrency, and per-agent workload for smarter `sessions_spawn` dispatch.

## Best Possible Solution

Design a shared queue/workload snapshot in core and expose a permissioned `queue_status` tool with catalog/profile/policy entries, docs, and focused tests.

## Reproduction Assessment

Yes, as a source-level feature gap: current main has no `queue_status`, no `diagnostics.queue`, and no equivalent model-facing workload/capacity tool. I did not run a live workload because the requested surface is absent.

## Solution Assessment

Unclear until maintainers choose the public metadata contract. The likely best shape is a shared read-only queue snapshot backend reused by a permissioned agent-facing tool and any future operator surface.
