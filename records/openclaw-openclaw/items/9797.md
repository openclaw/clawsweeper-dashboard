## Summary

Current tool and documentation surfaces still expose delegation and requester-owned subagent status but no agent-readable queue or capacity snapshot; the issue also has explicit maintainer follow-up, so it remains necessary while maintainers choose the visibility boundary.

## What This Changes

Add an agent-facing workload snapshot for queue lanes and agents so dispatchers can route subagent work using current capacity.

## Best Possible Solution

Create one canonical read-only queue snapshot provider, expose broader detail through operator diagnostics, and give agents a visibility-filtered capacity/workload view plus structured `sessions_spawn` backpressure outcomes using existing session visibility policy.
