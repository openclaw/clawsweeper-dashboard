## Summary

Keep open: current main still has internal lane snapshot primitives but no agent-facing `queue_status`, `sessions_capacity`, `diagnostics.queue`, or equivalent workload-aware dispatch surface. The closest queue-diagnostics PR is closed unmerged and explicitly did not add the in-agent tool.

## What This Changes

Request an agent-facing `queue_status` tool that exposes lane queue depth, active/max concurrency, and per-agent workload so dispatcher agents can route `sessions_spawn` work intelligently.

## Best Possible Solution

Design one shared read-only queue/workload snapshot backend in core, then expose a maintainer-approved subset through a permissioned `queue_status` agent tool with catalog/profile/policy entries, docs, and focused tests.
