## Summary

Keep open: current main still has internal queue/lane snapshot helpers, but no stable agent-facing `queue_status`, no `sessions_capacity`, and no `diagnostics.queue` surface that would let agents make workload-aware dispatch decisions. The related operator diagnostics PR was closed unmerged and explicitly deferred the remaining work back to this issue.

## What This Changes

The issue requests a model-facing `queue_status` tool that exposes lane and per-agent workload so dispatcher agents can route work intelligently.

## Best Possible Solution

Design one shared read-only queue/workload snapshot backend in core, then expose it through a permissioned `queue_status` agent tool with catalog/profile/policy entries, docs, and focused tests coordinated with https://github.com/openclaw/openclaw/issues/10467.

## Reproduction Assessment

Yes, as a source-level feature gap: current main exposes internal queue snapshots but no `queue_status`, no `sessions_capacity`, and no equivalent model-facing workload/capacity tool. I did not run a live workload because the requested public surface is absent.

## Solution Assessment

Unclear until maintainers choose the public metadata contract. The likely best shape is a shared read-only snapshot backend reused by a permissioned agent-facing tool and any future operator surface.
