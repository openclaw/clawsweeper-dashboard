## Summary

Keep open: current main still lacks the requested model-facing `queue_status` tool or equivalent workload/capacity surface for dispatch decisions; existing queue snapshots remain internal and the related operator diagnostics PR was closed unmerged.

## What This Changes

The issue requests an agent-facing `queue_status` tool that exposes queue depth, active concurrency, and per-agent workload so dispatchers can route `sessions_spawn` work intelligently.

## Best Possible Solution

Design a shared read-only queue/workload snapshot in core and expose it through a permissioned `queue_status` tool with catalog/profile/policy entries, docs, and focused tests.

## Reproduction Assessment

Yes, as a source-level feature gap: current main has no `queue_status`, no `diagnostics.queue`, and no equivalent model-facing workload/capacity tool. I did not run a live workload because the requested surface is absent.

## Solution Assessment

Unclear until maintainers choose the public metadata contract. The likely best shape is a shared read-only queue snapshot backend reused by a permissioned agent-facing tool and any future operator surface.
