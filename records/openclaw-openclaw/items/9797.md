## What This Changes

Add an agent-facing `queue_status` tool that reports queue depth, active runs, lane capacity, and per-agent workload for dispatcher-style task routing.

## Best Possible Solution

Design one shared read-only queue/workload snapshot backend in core, then expose a maintainer-approved subset through a permissioned `queue_status` agent tool with catalog/profile/policy entries, docs, and focused tests.

## Reproduction Assessment

Yes, as a source-level feature gap: current main has internal lane snapshots but no `queue_status`, no `diagnostics.queue`, and no equivalent model-facing workload/capacity tool.

## Solution Assessment

Partly: `queue_status` is a plausible consumer, but the best fix is a shared read-only snapshot backend reused by agent and operator surfaces after maintainers settle the metadata contract.
