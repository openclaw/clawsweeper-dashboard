## Summary

Keep open: current main and v2026.6.11 still lack an agent-facing `queue_status`, `sessions_capacity`, `diagnostics.queue`, or equivalent workload snapshot, and the remaining work needs a maintainer-approved public metadata contract.

## What This Changes

Request an agent-facing `queue_status` tool that exposes lane queue depth, active/max concurrency, and per-agent workload so dispatcher agents can route `sessions_spawn` work intelligently.

## Best Possible Solution

Define one shared read-only queue/workload snapshot backend in core, then expose a maintainer-approved redacted subset through `queue_status` with catalog/policy wiring, docs, and focused tests.
