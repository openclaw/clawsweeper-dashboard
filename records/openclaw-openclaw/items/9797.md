## Summary

Keep open: current main and v2026.6.11 have the internal lane-snapshot data needed for capacity reporting, but no registered agent tool exposes queue depth, concurrency saturation, or equivalent dispatch-capacity information. The remaining work is a product decision because the public contract must define caller visibility, metadata filtering, and stable scheduling semantics.

## What This Changes

Add an agent-facing queue workload and concurrency snapshot so agents can route tasks based on available capacity.

## Best Possible Solution

Reuse the existing all-lanes snapshot primitive behind one read-only, authorization-aware capacity projection that returns stable aggregate saturation and only caller-visible agent/session workload, with shared types for any later operator consumer.
