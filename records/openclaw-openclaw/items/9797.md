## Summary

Keep this issue open: current main and v2026.6.11 contain the internal lane-snapshot backend, but neither exposes queue depth or concurrency capacity through an agent-facing tool; the remaining API needs a maintainer decision on cross-agent visibility.

## What This Changes

Expose queue depth, active concurrency, and workload capacity to agents so they can make informed dispatch decisions.

## Best Possible Solution

Reuse the canonical command-lane snapshot and expose advisory active, queued, maximum, and remaining capacity only for agents the caller is authorized to target, omitting unrelated session identities unless a separate privileged operator surface is approved.
