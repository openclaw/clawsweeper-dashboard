## Summary

Keep open: current main and v2026.6.11 still lack an agent-facing `queue_status`, `sessions_capacity`, `diagnostics.queue`, or equivalent workload snapshot, and the related operator-diagnostics PR is closed unmerged and explicitly did not add an in-agent tool.

## What This Changes

The issue requests a read-only `queue_status` tool exposing lane queue depth, active versus max concurrency, and per-agent workload so agents can dispatch work intelligently.

## Best Possible Solution

Define one shared read-only queue/workload snapshot backend in core, then expose a maintainer-approved redacted subset through `queue_status` with catalog/profile/policy wiring, docs, and focused tests.
