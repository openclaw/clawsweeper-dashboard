## Summary

Keep open: current main and v2026.6.11 still have internal queue/lane snapshot helpers, but no stable agent-facing `queue_status`, no `sessions_capacity`, and no `diagnostics.queue` replacement for workload-aware dispatch. The related operator-diagnostics PR is closed unmerged and explicitly scoped out the in-agent tool, so this issue remains the canonical tracker.

## What This Changes

Issue requests an agent-facing `queue_status` tool that exposes queue/lane and per-agent workload state for smarter `sessions_spawn` dispatch.

## Best Possible Solution

Design one shared read-only queue/workload snapshot backend in core and expose it through a permissioned `queue_status` agent tool, with catalog/profile/policy entries, docs, and focused tests.

## Reproduction Assessment

Yes, as a source-level feature gap: current main has internal queue snapshots but no `queue_status`, no `diagnostics.queue`, and no equivalent model-facing workload/capacity tool. I did not run a live workload because the requested public surface is absent.

## Solution Assessment

Unclear until maintainers choose the public metadata contract. The likely best shape is a shared read-only queue snapshot backend reused by a permissioned agent-facing tool and any future operator surface.
