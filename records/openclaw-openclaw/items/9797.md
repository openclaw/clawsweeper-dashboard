## Best Possible Solution

Design one shared read-only queue/workload snapshot backend in core, then expose it through a permissioned `queue_status` agent tool while coordinating with operator diagnostics and multi-lane spawn semantics.

## Solution Assessment

Unclear until maintainers choose the public metadata contract. The maintainable direction is a shared read-only backend with one permissioned agent tool and compatible operator consumers rather than separate bespoke queue views.
