## Summary

Keep open: current main still lacks the requested agent-facing `queue_status`, `sessions_capacity`, or equivalent workload/capacity tool, and related cleanup has made this issue the canonical tracker for queue/workload visibility.

## What This Changes

Request adds a read-only queue/workload status surface so agents can inspect lane depth, active/max concurrent runs, and per-agent workload before dispatching with `sessions_spawn`.

## Best Possible Solution

Design one shared read-only queue/workload snapshot backend in core, then expose a maintainer-approved subset through a permissioned `queue_status` agent tool with catalog/profile/policy entries, docs, and focused tests.
