## Summary

Keep open: current main and the latest release still expose internal queue/lane snapshot helpers but no stable agent-facing `queue_status`, `sessions_capacity`, or `diagnostics.queue` surface for workload-aware dispatch. The closest related operator-diagnostics PR is closed unmerged and explicitly did not add an in-agent tool, so this issue remains the canonical tracker.

## What This Changes

Request to add an agent-facing `queue_status` tool that reports lane queue depth, active versus maximum concurrency, and per-agent workload so agents can dispatch tasks intelligently.

## Best Possible Solution

Define a shared read-only queue/workload snapshot backend in core and expose it through a permissioned `queue_status` agent tool, with catalog/profile/policy entries, docs, and focused tests.

## Reproduction Assessment

Yes, as a source-level feature gap: current main has internal queue snapshots but no `queue_status`, no `sessions_capacity`, and no equivalent model-facing workload/capacity tool. I did not run a live workload because the requested public surface is absent.

## Solution Assessment

Unclear until maintainers choose the public metadata and permission contract. The likely best path is a shared read-only snapshot backend reused by a permissioned agent-facing tool and any future operator surface.
