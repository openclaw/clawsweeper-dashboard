## Summary

Keep open: current main still has internal queue/lane snapshot helpers and session listing/status tools, but no agent-facing `queue_status`, `sessions_capacity`, or merged operator diagnostics surface that gives agents workload-aware dispatch visibility. The related queue diagnostics PR was closed unmerged and explicitly did not add the in-agent tool, so this issue remains the canonical tracker.

## What This Changes

The issue requests a read-only `queue_status` tool that lets agents inspect lane queue depth, active runs, max concurrency, and per-agent workload before dispatching subagents.

## Best Possible Solution

Design one shared read-only queue/workload snapshot backend in core, then expose a maintainer-approved subset through a permissioned `queue_status` agent tool with catalog/profile/policy entries, docs, and focused tests.

## Reproduction Assessment

Yes, as a source-level feature gap: current main has internal queue snapshots but no `queue_status`, no `diagnostics.queue`, and no equivalent model-facing workload/capacity tool. I did not run a live workload because the requested public surface is absent.

## Solution Assessment

Unclear until maintainers choose the public metadata contract. The likely best shape is a shared read-only queue snapshot backend reused by a permissioned agent-facing tool and any future operator surface.
