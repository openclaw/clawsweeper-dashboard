## Summary

Keep open: current main still lacks an agent-facing `queue_status`, `sessions_capacity`, `diagnostics.queue`, or equivalent workload snapshot, and the remaining work needs a maintainer-approved public metadata contract.

## What This Changes

The issue requests an agent-facing `queue_status` tool so agents can inspect lane queue depth, active runs, concurrency limits, and per-agent workload before dispatching tasks.

## Best Possible Solution

Define one shared read-only queue/workload snapshot backend in core, then expose a maintainer-approved redacted subset through `queue_status` with catalog, policy, docs, and focused tests.
