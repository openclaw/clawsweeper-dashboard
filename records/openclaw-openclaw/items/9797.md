## Summary

Keep this issue open: current main has reusable lane snapshots but still provides no agent-facing queue or capacity tool, and the remaining authorization scope requires explicit product direction before implementation.

## What This Changes

Requests an agent-facing queue snapshot tool so dispatchers can inspect lane concurrency, backlog, and per-agent workload before spawning tasks.

## Best Possible Solution

Create one read-only core snapshot provider, then expose an agent tool that defaults to the caller's permitted agent and descendant workload plus anonymized lane capacity; reuse the same typed model for future operator consumers and document that values are advisory.

Kind: product_direction

Question: What workload information may an agent inspect: only its own session and spawned descendants, anonymized global lane capacity, or raw cross-agent queue/session details?

Rationale: The queue data exists, but repository policy does not define whether operational workload metadata is private per agent, globally visible, or operator-only; that choice determines the tool schema, authorization checks, and reusable API boundary.

Likely owner: steipete

Owner reason: The queue and agent-tool boundaries have substantial history under this contributor, including the original queue implementation and recent gateway/tool maintenance.

Owner confidence: high

Options:

- **Scoped agent view (recommended):** Expose the caller's own and descendant workload with anonymized global lane counts, withholding unrelated agent and session identifiers.
- **Operator-wide view:** Expose raw lanes and per-agent/session workload only to an explicit privileged tool policy or operator capability.
- **Operator diagnostics only:** Keep workload snapshots out of agent tools and expose them solely through authenticated CLI, RPC, or Control UI diagnostics.

Yes at source level: current main exposes internal lane snapshots but neither tool assembly nor the tool catalog contains an agent-callable queue or capacity surface. Runtime failure reproduction is not applicable because this is a new capability request.

## Solution Assessment

Yes, conditionally: a shared snapshot provider with a narrowly authorized agent consumer is the cleanest design, but the visibility contract must be decided before fixing the schema or implementation boundary.
