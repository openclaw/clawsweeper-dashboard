## Summary

Keep open: current main and the latest release still leave native macOS voice recognition on Apple Speech, while existing OpenAI-compatible transcription support lives in the separate media-audio path. This remains a valid product and security design issue rather than conservative cleanup closure.

## What This Changes

Request configurable speech-to-text backends, especially OpenAI-compatible custom ASR HTTP endpoints, for OpenClaw voice input while keeping platform speech as the default.

## Best Possible Solution

Define the supported native voice ASR provider boundary first, then add an opt-in backend that reuses existing media-audio or Talk transcription contracts where appropriate, with explicit credential, private-network, test-connection, fallback, and UX rules.
