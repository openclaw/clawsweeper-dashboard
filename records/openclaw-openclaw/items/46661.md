## Label Justifications

- `P2`: This is a meaningful voice-input feature request with clear user value, but current native speech workflows are not reported as globally unusable.
- `impact:security`: The requested feature would send microphone audio and possibly authorization material to configurable ASR infrastructure.
- `impact:auth-provider`: The request adds speech-to-text backend/model selection and credential-sensitive provider routing decisions.

## Summary

Keep open: current main still has native macOS, iOS, and Android voice capture tied to Apple/Android platform speech recognizers, while the existing OpenAI-compatible transcription path is only a separate media-understanding/Gateway surface. This remains a valid feature request that needs product and security direction rather than cleanup closure.

## What This Changes

The issue requests an opt-in custom ASR/STT provider setting for native voice input, including an OpenAI-compatible HTTP endpoint, optional credentials, model, language hint, test connection, and fallback behavior.

## Best Possible Solution

Define a native ASR/STT boundary that preserves platform speech as the default, reuses existing media-audio/provider security contracts where suitable, and documents endpoint/auth, private-network, fallback, and platform scope before implementation.

Options:

- **Design native STT seam first (recommended):** Add a maintainer-scoped native ASR/STT abstraction, start with the smallest approved flow, and reuse tools.media.audio or provider contracts where that is the chosen owner boundary.
- **Narrow to macOS PTT slice:** Use https://github.com/openclaw/openclaw/issues/87140 as the first implementation slice while this broader issue remains the design tracker.
- **Defer native backend selection:** Keep native voice input on Apple/Android platform speech until maintainers define the cross-platform privacy, endpoint, and fallback policy.

Yes for the current behavior by source inspection, though this is a feature request rather than a bug reproduction. Native voice paths still instantiate platform speech recognizers directly and no custom ASR endpoint selector is present.

## Solution Assessment

Unclear until maintainers choose the product and security boundary. Reusing tools.media.audio, Talk transcription, and provider/plugin contracts is safer than adding a parallel native HTTP preference by default.
