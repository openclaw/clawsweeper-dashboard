- `impact:security`: The requested feature would send microphone audio and possibly authorization material to configurable ASR infrastructure.
- `impact:auth-provider`: The request adds speech-to-text backend/model selection and credential-sensitive provider routing decisions.

## Summary

Keep open: current main and v2026.6.11 still route native macOS, iOS, and Android voice capture through Apple or Android platform speech recognizers. OpenAI-compatible audio transcription exists in `tools.media.audio`, but it is a separate media-understanding path, so this remains a product and security design request rather than cleanup closure.

## What This Changes

Request an opt-in native ASR/STT provider setting for custom OpenAI-compatible transcription endpoints, with URL/auth/model/language configuration and platform-speech fallback.

## Best Possible Solution

Define a native ASR/STT boundary that preserves platform speech as the default, reuses or bridges to existing media-audio/provider contracts where suitable, and documents credential, network, fallback, and platform scope before implementation.
