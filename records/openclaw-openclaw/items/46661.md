## Label Justifications

- `P2`: This is a meaningful feature/design request for voice-input users, but the default platform speech workflow is not reported as globally broken.
- `impact:security`: The requested custom ASR backend would route captured microphone audio and possibly credentials to user-configured local, LAN, or remote services.
- `impact:auth-provider`: The request needs provider/endpoint/model/auth routing decisions and credential isolation for OpenAI-compatible STT backends.

## Summary

Keep open: current main still lacks a native custom ASR/STT endpoint setting or shared provider seam for the voice-input paths. Existing `tools.media.audio`, OpenAI-compatible batch transcription, and realtime transcription registries are useful adjacent capabilities, but they do not replace the platform recognizer loops behind native Talk, VoiceWake, and Push-to-Talk.

## What This Changes

Request to let users configure a custom ASR/STT server endpoint, model, language, and credentials instead of relying only on built-in platform speech recognition.

## Best Possible Solution

Define a native STT provider boundary and security policy first, then land a narrow opt-in slice that preserves platform speech defaults and reuses existing media or Talk provider contracts where possible.

Options:

- **Start With macOS PTT Seam (recommended):** Use the narrower macOS Push-to-Talk slice to define a batch STT backend contract while preserving Apple Speech as the default and reusing Gateway/media provider policy where feasible.
- **Design Broad Cross-Platform ASR:** Plan one provider/config surface across macOS, iOS, Android, and WebChat, accepting a larger product and security design before implementation.
- **Defer Native ASR:** Keep self-hosted STT limited to current `tools.media.audio`, Talk relay, channel, and sidecar paths until maintainers prioritize native-app extension points.

## Reproduction Assessment

Yes, source-reproducible for the missing capability: native voice paths instantiate platform recognizers directly, and current config/docs expose no native custom ASR endpoint selector. This is a feature gap rather than a failing bug reproduction.

## Solution Assessment

Unclear until maintainers choose the product and security boundary. A provider seam is safer than wiring a one-off URL into native capture code, with the macOS PTT slice likely the narrowest first implementation.
