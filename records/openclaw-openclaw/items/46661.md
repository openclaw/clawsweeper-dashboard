## Summary

Keep open: current main and the latest release still route native macOS, iOS, and Android voice input through platform speech recognizers, while OpenAI-compatible batch transcription and realtime transcription remain adjacent Gateway/provider seams. The request is valid, but it needs maintainer product and security direction before implementation.

## What This Changes

Request adding an opt-in custom ASR/STT server/provider setting for native voice input, including endpoint, auth, model, language, and fallback behavior.

## Best Possible Solution

Define a native ASR/STT boundary that preserves platform speech as the default, reuses Gateway media-audio or realtime-transcription provider contracts where appropriate, and documents endpoint, credential, private-network, fallback, and platform-scope policy before implementation.
