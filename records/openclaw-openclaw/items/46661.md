## Summary

Keep open: current main and the latest release still hardwire native macOS, iOS, and Android voice capture to Apple or platform speech recognizers. Existing OpenAI-compatible audio transcription support lives in the separate `tools.media.audio` media-understanding path, so this remains a valid feature request that needs maintainer product and security design rather than cleanup closure.

## What This Changes

Allow native voice input to use a configurable custom ASR/STT endpoint with optional auth, model, and language settings while preserving platform speech as the default.

## Best Possible Solution

Define a maintainer-scoped native ASR/STT boundary that keeps platform speech as the default, reuses or bridges to existing Talk/media provider contracts where appropriate, and documents credential, network, fallback, and platform scope before implementation.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a feature request. Source inspection gives a high-confidence behavior check that native voice input is still platform-recognizer-backed and has no custom ASR endpoint selector.

## Solution Assessment

Unclear until maintainers choose the product and security scope. Reusing existing `tools.media.audio`, Talk transcription, provider request, and plugin contracts is safer than adding a parallel native HTTP preference by default.
