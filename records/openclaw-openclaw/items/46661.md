## Summary

Keep open: current main and latest release still route native macOS, iOS, and Android voice capture through Apple or Android platform recognizers. Existing OpenAI-compatible transcription support is adjacent media/Talk infrastructure, not a native custom-ASR provider setting, and related open issues cover narrower slices rather than superseding this broader product/security request.

## What This Changes

The issue asks for an opt-in configurable OpenAI-compatible custom ASR server endpoint while preserving platform speech as the default.

## Best Possible Solution

Define a native ASR/STT boundary that preserves platform speech as the default, reuses or bridges to existing media-audio/provider contracts where suitable, and documents credential, network, fallback, and platform scope before implementation.
