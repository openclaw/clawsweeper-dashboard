## Summary

Keep open: current main and v2026.6.11 still do not provide the requested custom native ASR/STT server setting. Native voice capture remains wired to platform recognizers, while the existing OpenAI-compatible transcription path is an adjacent media/gateway surface that does not yet own native voice input.

## What This Changes

Request to add an opt-in custom ASR/STT provider setting for native voice input, with endpoint URL, optional auth/model/language, fallback behavior, and settings validation.

## Best Possible Solution

Design a narrow native STT backend seam first, likely macOS batch Push-to-Talk, keep Apple Speech as the default, reuse gateway-mediated `tools.media.audio` or an explicit provider contract where safe, and require credential/private-network/fallback policy before broad settings UI.
