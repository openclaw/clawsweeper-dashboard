## Summary

Keep open: current main still hardwires native macOS voice recognition to Apple Speech, while the existing OpenAI-compatible/custom audio transcription support lives in the separate Gateway media-understanding path. The narrower macOS Push-to-Talk issue is useful related work, but this broader request still needs product and security decisions before implementation.

## What This Changes

Request to add a user-configurable custom ASR/STT provider endpoint, credentials, model, and language setting while keeping built-in macOS speech recognition as the default.

## Best Possible Solution

Design a maintainer-scoped native ASR/STT boundary that preserves platform speech as the default, reuses Gateway media-audio or Talk provider contracts where appropriate, and documents credential, network, fallback, and platform scope before implementation.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a feature request. Source inspection gives high confidence that native macOS Push-to-Talk and Talk still use Apple Speech and have no configurable custom ASR endpoint selector.

## Solution Assessment

Unclear until maintainers choose the product and security scope. Reusing existing Gateway media-audio, Talk session, provider request, and plugin contracts is safer than adding a parallel native HTTP preference by default.
