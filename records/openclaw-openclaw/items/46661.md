## Summary

Keep open: current main still does not provide the requested custom ASR/STT server setting for native voice input. The issue is valid, but it remains a product and security design item because the existing media-audio and realtime-transcription paths are adjacent provider surfaces, not a settled native ASR preference.

## What This Changes

Request custom Speech-to-Text backend configuration so users can route voice input to an OpenAI-compatible or self-hosted ASR endpoint instead of only platform speech recognition.

## Best Possible Solution

Define a native ASR/STT boundary that keeps platform speech as the default, reuses Gateway media-audio or realtime-transcription provider contracts where appropriate, and documents endpoint, credential, private-network, fallback, and platform-scope policy before implementation.
