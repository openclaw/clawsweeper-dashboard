## Summary

Keep open: current main and v2026.6.11 still keep native voice capture on platform speech recognizers, while the existing OpenAI-compatible audio transcription support belongs to the separate `tools.media.audio` media-understanding path. This remains a product and security design request, not conservative cleanup.

## What This Changes

Request an opt-in custom ASR/STT provider setting so native voice input can use an OpenAI-compatible transcription endpoint instead of only platform speech recognition.

## Best Possible Solution

Define a native ASR/STT boundary that keeps platform speech as the default, starts with the smallest approved flow, and reuses existing media-audio or Talk provider contracts only after the credential, network, fallback, and platform-scope rules are agreed.
