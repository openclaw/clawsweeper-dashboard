## Summary

Keep open: current main still lacks a unified native custom ASR/STT endpoint setting or provider seam for the requested native voice workflows. Existing `tools.media.audio`, SenseAudio/OpenAI-compatible batch transcription, Talk relay, and Android gateway transcription are useful adjacent paths, but they do not fully replace the macOS/iOS platform-recognizer loops or settle the requested provider/security/fallback policy.

## What This Changes

The issue requests an opt-in custom ASR/STT provider setting for native voice input, with endpoint, auth, model, language, test-connection, and fallback controls while preserving platform speech as the default.

## Best Possible Solution

Define the native STT provider boundary and security policy first, then land a narrow opt-in slice that reuses existing Gateway media or Talk provider contracts without changing platform speech defaults.

Options:

- **Design shared seam, start with macOS PTT (recommended):** Preserve Apple Speech by default, use the narrower macOS Push-to-Talk issue as the first implementation slice, and make the provider/security contract reusable for later native surfaces.
- **Build broad cross-platform settings:** Add macOS, iOS, Android, and possibly WebChat native ASR settings in one larger project, accepting substantially more design and validation risk up front.
- **Defer native ASR core work:** Keep self-hosted STT on existing media, Talk relay, channel, plugin, or sidecar paths until maintainers prioritize a native-app extension point.

## Reproduction Assessment

Yes, source-reproducible as a feature gap: current macOS and iOS native voice paths still instantiate platform recognizers directly, while current docs/config expose batch media transcription rather than a native ASR endpoint selector. Android has a partial Gateway transcription path, but the broad native settings and policy request remains missing.

## Solution Assessment

Unclear as proposed: a custom endpoint setting is plausible, but the best fix is not wiring a URL into each native recognizer. The maintainable path is a provider seam plus explicit security, fallback, and owner-boundary policy that reuses existing media or Talk contracts where possible.
