## Summary

Keep open: current main and the latest release still do not provide a unified native custom ASR/STT endpoint setting or provider seam for the requested native voice workflows. Existing batch media transcription and Android Gateway transcription are useful adjacent paths, but they do not replace macOS/iOS platform-recognizer loops or settle the provider/security/fallback policy.

## What This Changes

The issue requests a configurable custom ASR/STT provider for native voice input, including OpenAI-compatible custom transcription endpoints, while preserving platform speech as the default.

## Best Possible Solution

Define the native STT provider boundary and security policy first, then land a narrow opt-in slice that preserves platform speech defaults and reuses Gateway media or Talk provider contracts where maintainers choose that owner boundary.
