## Summary

Keep open: current main and v2026.6.11 still lack an owner/human handoff config or per-DM pause state, and the only implementation attempt is closed unmerged prior art rather than shipped behavior.

## What This Changes

The issue requests a configurable owner/human takeover mechanism that pauses DM auto-replies when the account owner manually replies in the same DM thread.

## Best Possible Solution

Approve a narrow, plugin-owned opt-in design after live proof: detect non-gateway manual `fromMe` DM messages, store per-account/per-conversation pause state, support explicit or cooldown resume, and document/test the upgrade path.
