## Summary

Keep this PR open for a focused repair: partial newest-first import is the right direction, but imported legacy rows are persisted as brand-new writes, so later capacity eviction can discard fresher live Telegram cache rows before older migrated rows.

## What This Changes

The PR changes legacy plugin-state migration to import the newest subset that fits, defer remaining entries, tolerate mid-import cap eviction, and align preflight capacity with the effective per-plugin cap.

## Best Possible Solution

Keep partial imports, but add an internal migration-only write path that preserves each legacy entry's original creation timestamp and verify that the next live write evicts the oldest logical entry without removing fresher pre-existing Telegram state.
