## Summary

Keep open: the updated branch fixes the earlier transcript-only regression, but the `script -- ...` branch still treats a BSD/macOS transcript-file operand as a command-only form that the documented `script(1)` contract does not support. That can mis-bind exec approval analysis, and the posted proof is still test output rather than real macOS/FreeBSD wrapper behavior.

## What This Changes

The PR changes `src/infra/dispatch-wrapper-resolution.ts` so `flock` skips `--` after a lock target and `script` treats a consumed `--` as meaning there is no transcript file.

## Best Possible Solution

Keep `script` on the documented file-then-command contract unless a maintainer approves a different platform contract with real OS proof; land `flock --` only with focused regression coverage.

## Reproduction Assessment

Yes, source-reproducible: the PR head returns `commandIndex` after a consumed `--`, so `script -- echo hello` becomes `echo hello` in wrapper analysis even though the `script(1)` contract still requires a transcript file before a command. I did not run tests because this review is read-only.

## Solution Assessment

No. The `flock` part is plausible, but the `script` part is not the best safe fix because it creates an unsupported command-only interpretation instead of preserving file-then-command parsing and fail-closed transcript-only behavior.
