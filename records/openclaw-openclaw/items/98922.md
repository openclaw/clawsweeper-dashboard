## Summary

Keep open: the latest head fixes the prior forced-mention/message-id blocker, but the new `submitText` path still runs after plugin callback dedupe is committed, so a retry of the same Telegram callback update can be dropped; current-head live proof for the submit path is also still missing.

## What This Changes

The PR preserves reply-payload presentation metadata through outbound normalization and adds a Telegram plugin callback `submitText` result so portable buttons can submit text through the inbound path.

## Best Possible Solution

Keep the `reply_payload_sending` presentation boundary, but change the Telegram plugin callback lifecycle so dedupe commits only after `submitText` processing succeeds or is released on failure, then refresh current-head Telegram proof.

## Solution Assessment

No. The `reply_payload_sending` presentation boundary is the right layer, but the current Telegram callback implementation must preserve retry semantics before it is the best fix.
