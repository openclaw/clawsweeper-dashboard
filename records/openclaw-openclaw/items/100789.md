Full review comments:

- **[P2] Filter the Recent fetch to terminal tasks:** `ui/src/pages/tasks/tasks-page.ts:107`
  - body: The Recent request is still unfiltered, so if queued/running rows fill the first 200 activity-ordered results, `partitionTasks()` can show no completed/failed/cancelled rows even though terminal tasks exist. Request terminal statuses here, or page until enough terminal rows are collected.
  - confidence: 0.91
- **[P2] Prefer terminal end time for terminal task updates:** `src/gateway/server-methods/task-summary.ts:29`
  - body: `taskUpdatedAt()` uses `lastEventAt` before `endedAt`, but finalizers such as `tryFinalizeTrackedAgentTask()` can provide only `endedAt`; a just-finished long-running task can therefore sort by stale progress time and miss the Recent page. Use terminal end time first for non-active statuses.
  - confidence: 0.88
- **[P2] Keep task pagination stable while tasks update:** `src/gateway/server-methods/tasks.ts:124-131`
  - body: This sorts `tasks.list` by mutable activity time while retaining numeric offset cursors. Workboard follows `nextCursor`; if a later-page task emits progress between page requests, it can move before the offset and be skipped, so the list needs stable ordering or an opaque snapshot/keyset cursor.
  - confidence: 0.86
- **[P2] Ignore stale cancel responses after gateway changes:** `ui/src/pages/tasks/tasks-page.ts:139-140`
  - body: Late discovery: this code is unchanged since the previous ClawSweeper-reviewed head. If Cancel is clicked and the page reconnects or switches gateways before `tasks.cancel` resolves, this path can still apply the old client's `result.task` to the new page; capture the generation/client and check them before mutating state.
  - late: true
  - confidence: 0.87
