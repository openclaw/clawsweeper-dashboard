## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Keep task pagination stable under progress updates:** `src/gateway/server-methods/tasks.ts:124-131`
  - body: This changes `tasks.list` to sort by `taskUpdatedAt` but keeps `nextCursor` as a numeric offset. Existing paged clients such as Workboard follow those cursors; if a later-page task emits progress between requests, it can move before the offset and be skipped. Use a stable ordering/cursor for paged results or isolate last-activity ordering to a non-paginated/status-specific view.
  - confidence: 0.88
- **[P2] Prefer terminal end time for task freshness:** `src/gateway/server-methods/task-summary.ts:28-30`
  - body: `taskUpdatedAt` prefers `lastEventAt` over `endedAt` for all statuses, but finalizers can set `endedAt` without updating `lastEventAt`. A just-finished long-running task can then be ranked by stale progress time and drop out of the Recent page; use `endedAt` first for terminal statuses, matching the existing task status snapshot logic.
  - confidence: 0.9
- **[P2] Request terminal rows for the Recent fetch:** `ui/src/pages/tasks/tasks-page.ts:105-108`
  - body: The Recent refresh asks for an unfiltered first page, then `partitionTasks` removes active rows. With 200 or more active tasks newer than any terminal row, Recent shows no completed/failed/cancelled work even though terminal tasks exist. Fetch terminal statuses explicitly or page until enough terminal rows are collected.
  - confidence: 0.89
