## What This Changes

This PR routes Linux desktop Gateway start, stop, restart, connect, installation, and dashboard-triggered operations through one serial worker so concurrent requests execute in queue order instead of racing for a mutex.

## System Context

The Linux desktop app accepts Gateway work from tray menus, Tauri commands, deep links, Quick Chat, and installer/bootstrap flows. Those requests call the desktop Gateway controller and update the tray or renderer with the resulting snapshot or error.
