## Summary

Keep open: this PR is a focused candidate fix for the linked managed-service handoff timeout bug, and current main plus v2026.6.11 still use the fixed 60s parent wait. ## What This Changes

The PR changes the managed-service update handoff helper so parent-exit wait uses a 300s floor, any larger update timeout, and a 30s reserve, with focused tests.

## Best Possible Solution

Land this helper-level fix if maintainers accept the longer timeout policy; otherwise cap or split the parent-exit budget while preserving coverage for the 300s restart drain.

## Reproduction Assessment

Yes. At source level, current main can drain restart work for 300s plus shutdown time while the managed-service helper can currently time out after restart delay plus 60s; I did not run a live Windows npm-global self-update.

## Solution Assessment

Yes for code shape. The fix belongs in the shared managed-service handoff helper using the existing timeout input and Gateway drain budget; the remaining decision is whether the longer stuck-parent wait should land as-is or be capped.
