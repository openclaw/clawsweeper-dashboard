## Summary

Keep open: this is a focused fix for the linked managed-service handoff timeout bug, but the current patch can still time out when the Gateway consumes the full default restart-drain budget before beginning shutdown.

## What This Changes

The PR raises the managed-service handoff parent-exit wait from a fixed 60s to a 300s default and uses the provided update timeout as a larger floor, with two regression tests.

## Best Possible Solution

Keep the narrow helper-level fix, but add a bounded shutdown/scheduling reserve on top of the chosen drain/update timeout and cover the full-budget default case before merging.

## Reproduction Assessment

Yes, source-reproducible: current main waits only 60s for the managed-service parent, while the Gateway restart path can legally drain active work for 300s plus shutdown time before exiting.

## Solution Assessment

No, not quite: the fix belongs in the helper timeout calculation, but the current patch matches the default drain budget exactly and needs a shutdown reserve to cover the documented full-budget case.
