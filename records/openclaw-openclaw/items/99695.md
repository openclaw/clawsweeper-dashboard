## Summary

Keep open: current main still has the 60s managed-service parent-exit wait, and this PR remains the open candidate fix for the linked timeout bug. The patch looks correct as a narrow helper-level fix, but maintainers still need to accept the longer stuck-parent wait window before merge.

## What This Changes

This PR replaces the fixed 60s managed-service handoff parent-exit grace with a 300s floor plus 30s reserve, lets explicit update timeouts extend that wait, and adds focused helper tests.

## Best Possible Solution

Land the helper-level timeout fix if maintainers accept the longer stuck-parent wait policy; otherwise cap or tune the parent-exit wait before merge while preserving the 300s drain-budget coverage.

## Reproduction Assessment

Yes, at source level: current main can drain restart work for 300000ms plus shutdown time, while the managed-service helper can report parent timeout after only restart delay plus 60000ms. I did not run a live Windows npm-global update in this read-only review.

## Solution Assessment

Yes for code shape: the fix belongs in the shared managed-service handoff helper using existing timeout inputs and the Gateway drain budget, not a new config option or updater rewrite. The remaining question is maintainer acceptance of the longer stuck-parent wait, especially for auto-update.
