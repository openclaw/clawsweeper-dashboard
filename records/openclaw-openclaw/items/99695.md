## Summary

## What This Changes

The PR changes the managed-service update handoff helper to compute parent-exit wait from the update timeout with a 300s floor and 30s reserve, plus focused tests for the new timeout behavior.

## Best Possible Solution

Land the helper-level timeout fix if maintainers accept the longer stuck-parent wait policy; otherwise tune or cap the parent-exit budget while preserving coverage for the 300s Gateway drain window.

## Reproduction Assessment

## Solution Assessment

Yes for code shape: the fix belongs in the shared managed-service handoff helper using existing timeout inputs and Gateway drain budget, not a new config option or updater rewrite. The remaining question is maintainer acceptance of the longer stuck-parent wait, especially for auto-update.
