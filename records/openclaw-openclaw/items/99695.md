## Summary

Keep open: this PR is a focused fix for the linked managed-service update timeout bug, but the patch still leaves default `update.run` handoffs at the old 60s parent-exit wait when callers omit `timeoutMs`, so it is not ready to merge as the complete fix.

## What This Changes

The PR changes the managed-service update handoff helper to use the caller's update timeout as a floor for the parent-exit wait and adds regression tests for explicit-timeout and default-timeout behavior.

## Best Possible Solution

Make the parent-exit wait drain-aware when no explicit update timeout is supplied, keep the explicit-timeout behavior, and add coverage for the default managed `update.run`/handoff path.

## Reproduction Assessment

Yes, source-reproducible: current main waits only 60s for the parent process, while the Gateway restart drain can legitimately run for 300s. I did not run a live Windows npm-global update in this read-only review.

## Solution Assessment

No. The PR is a good partial fix for callers that pass `timeoutMs`, but it is not the best complete fix because `timeoutMs` is optional and the default managed update path still keeps the old 60s parent wait.
