## Summary

Keep this PR open for one narrow repair: the current head still probes `dimensions` on every embedding call after the provider has already rejected it, adding repeated latency and provider error/rate-limit noise. Likely related people: steipete (high confidence, recent implementation work) and scotthuang (high confidence, introduced the current dimensions-forwarding behavior).

## What This Changes

The branch retries structured embedding-dimension rejections without `dimensions`, truncates the fallback vector locally, preserves the timeout budget, validates dimensions, and adds focused regression coverage.

## Best Possible Solution

Remember a structured dimensions rejection for the lifetime of the embedding client, preserve the first-call probe for accepting providers, and send later requests directly without `dimensions` while retaining timeout and truncation safeguards.
