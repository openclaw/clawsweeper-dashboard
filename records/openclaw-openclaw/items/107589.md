## Summary

Keep this issue open. The v2026.7.1 evidence describes a distinct native Apple transcript-convergence failure after tool runs: Gateway history remains canonical while the client later duplicates, reorders, and misprojects older entries. The merged provisional-final and reconnect fixes cover adjacent races but do not establish convergence for this stable-connection, repeated-history-refresh case.

## What This Changes

Prevent the iOS chat transcript from duplicating, reordering, or flattening completed tool-using turns when live events reconcile with repeated history responses.

## Best Possible Solution

Extend the shared Apple reconciliation invariant so each session coalesces history refresh demand, rejects stale responses, adopts live rows by stable canonical identity, orders durable rows by Gateway sequence, and preserves tool steps as structured content; lock this down with a deterministic replay where delayed history and live events complete in multiple orders.
