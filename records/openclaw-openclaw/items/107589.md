## Summary

Keep this issue open: the shipped v2026.7.1 trace shows persistent iOS transcript duplication and chronology corruption after overlapping history refreshes, while the recent native-chat fixes cover provisional-final adoption and reconnect ordering without proving convergence for multiple delayed `chat.history` responses. ## What This Changes

Fix iOS chat reconciliation so overlapping history refreshes after tool runs cannot duplicate, flatten, or reorder canonical transcript entries.

## Best Possible Solution

Use one generation-aware native reconciliation path that discards stale history results, performs a single terminal refresh after active runs, adopts rows by stable Gateway identity, orders by canonical sequence, and preserves tool entries as typed progress UI; prove it with delayed out-of-order replay fixtures and an iOS device or simulator run.
