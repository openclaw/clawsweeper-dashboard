## Summary

Keep this issue open: it reports a fresh, detailed release-level iOS reproduction that is distinct from the transient live-final duplication fixed by https://github.com/openclaw/openclaw/pull/98117, and current evidence does not show that delayed concurrent history responses are safely reconciled on main.

## What This Changes

Prevent the native iOS chat transcript from duplicating or reordering completed tool-run messages when live events and concurrent `chat.history` refreshes reconcile.

## Best Possible Solution

Make shared native history loading single-flight or generation-guarded, defer redundant full refreshes during active runs, apply only the newest canonical response, order by stable sequence identity, and add a deterministic delayed-response tool-run regression before changing production behavior.
