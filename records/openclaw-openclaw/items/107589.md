## Summary

The report remains necessary: current main contains substantial native-chat reconciliation defenses, including provisional-final adoption and stale-history response guards, but the examined path does not establish single-flight history refreshes, canonical sequence ordering, or coverage for delayed tool-run history responses completing out of order.

## What This Changes

Prevent the native iOS chat transcript from duplicating and reordering completed tool-using turns when live events and concurrent `chat.history` responses reconcile.

## Best Possible Solution

Make shared native-chat history refreshes coalesced or single-flight, reject stale completions, reconcile by canonical identity, preserve structured tool entries, and project the final transcript in Gateway sequence order with a focused delayed-response regression.
