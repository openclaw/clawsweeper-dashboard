## Summary

Keep this issue open: it documents a fresh latest-release iOS failure where durable Gateway history remains correct but native rendered state duplicates and reorders completed tool runs. The merged transient-final fix addressed a narrower live-event race, and there is no evidence that current main rejects stale, concurrently completed history responses. citeturn23view0turn2view0

## What This Changes

Prevent iOS history refreshes from duplicating, flattening, or reordering completed assistant and tool-run entries when concurrent history responses reconcile with live events.

## Best Possible Solution

Add a deterministic shared-native regression that completes multiple delayed history responses out of order around a live tool run, then make history application monotonic and idempotent—coalesce refresh requests, discard superseded generations, reconcile stable identities, preserve tool-step projection, and order canonical rows by Gateway sequence.
