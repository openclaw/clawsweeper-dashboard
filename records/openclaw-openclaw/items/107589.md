## Summary

Keep this issue open: the v2026.7.1 trace describes persistent native transcript duplication and chronology corruption after overlapping history refreshes, while the merged provisional-final and reconnect fixes address adjacent event-ordering cases without establishing convergence for multiple delayed `chat.history` responses. The clean Gateway transcript makes this a distinct client reconciliation bug rather than server-side duplication. ([github.com](https://github.com/openclaw/openclaw/issues/107589))

## What This Changes

Fix iOS chat reconciliation so concurrent history refreshes cannot duplicate, reorder, or flatten completed tool-using turns.

## Best Possible Solution

Make Apple history refreshes single-flight or generation-ordered, apply only the newest applicable snapshot, reconcile canonical rows by stable identity and sequence, preserve live tail state and tool-step presentation, and add a deterministic delayed-response regression plus device or simulator proof.
