## Summary

Keep open: current main improves adjacent visibility with an active-model control, a provider quota pill in chat, and provider billing cards on the Usage page, but it still does not provide the requested persistent model plus session token/context status in the Control UI header. The remaining question is a genuine product choice about placement, semantics, freshness, and responsive density rather than a missing narrow bug fix.

## What This Changes

Add an always-visible Control UI status display showing the active model and current token or context usage.

## Best Possible Solution

Define one compact, session-aware status contract and render it through the existing chat header/sidebar controls: show the effective active model, session context used versus limit, and provider quota only when available, with clear stale/unavailable states and responsive collapse behavior; avoid adding another debug polling path or a new setting unless product review proves it necessary.
