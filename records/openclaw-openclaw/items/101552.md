## Summary

Keep open: current main and the latest release still run the all-agent `usage.cost` aggregation with an unbounded `Promise.all` over configured agents. The exact SQLite starvation wording is not proven from source, but the per-agent usage-cache work is clearly unbounded and the repo already has a bounded helper used by the sibling `sessions.usage` path.

## What This Changes

The issue asks to bound all-agent usage-cost aggregation so many agents do not hit usage cache/database paths concurrently and destabilize the Gateway.

## Best Possible Solution

Bound `loadAllAgentCostUsageSummary` with the existing `runTasksWithConcurrency` worker helper, preserve the current aggregation/cache behavior, and add a regression that proves max in-flight per-agent loads stays capped.
