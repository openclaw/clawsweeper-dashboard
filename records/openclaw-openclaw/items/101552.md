## Summary

Keep open: current main and the latest release still run `usage.cost` all-agent aggregation through an unbounded `Promise.all`, while the sibling `sessions.usage` path already uses the bounded concurrency helper for the same per-agent usage-cache fan-out class.

## What This Changes

The issue requests bounding all-agent `usage.cost` aggregation so loading the usage dashboard or CLI summary cannot start one concurrent cache/database load per configured agent.

## Best Possible Solution

Bound `usage.cost` all-agent fan-out with the existing concurrency runner or an equivalent per-agent worker pool, and add a regression test proving peak loads stay capped while aggregation semantics remain unchanged.
