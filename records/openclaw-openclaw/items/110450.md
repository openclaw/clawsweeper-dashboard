## Summary

This PR has credible real-call-chain proof and correctly targets both dreaming markdown read paths, but it introduces a new hard failure for existing user-managed files above 16 MiB. A maintainer should explicitly choose that compatibility policy before merge rather than treating the cap as a purely internal safety change.

## What This Changes

Caps daily inline dreaming markdown and `DREAMS.md` reads at 16 MiB before managed-block updates, with oversized-file regression coverage.

## Best Possible Solution

Adopt an explicit compatibility contract for oversized existing dreaming files—either preserve an upgrade-safe recovery path or deliberately document and surface the fail-fast limit with an appropriate user-facing remediation path.
