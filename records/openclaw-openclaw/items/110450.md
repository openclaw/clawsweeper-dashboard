## Label Justifications

- `P2`: This is a bounded reliability fix for optional memory-core dreaming with a limited but real existing-workspace compatibility impact.
- `merge-risk: 🚨 compatibility`: The branch makes previously readable large user-managed daily or Dream Diary Markdown fail during dreaming once it exceeds 16 MiB.

## Summary

The PR is still necessary: current `main` performs unbounded reads for both inline daily dreaming markdown and `DREAMS.md`. The focused implementation uses the existing safe regular-file reader and has credible after-fix terminal proof, but the new 16 MiB rejection changes behavior for pre-existing large user-managed diary files and needs an explicit maintainer acceptance of that upgrade tradeoff before merge.

## What This Changes

The branch caps dreaming reads of daily inline markdown and `DREAMS.md` at 16 MiB and adds tests that reject oversized files before dreaming events are written.

## Best Possible Solution

Keep the bounded safe-reader implementation, but make the 16 MiB existing-workspace failure mode an explicit accepted compatibility policy and provide a clear recovery path for users whose Dream Diary or inline daily file already exceeds the cap.
