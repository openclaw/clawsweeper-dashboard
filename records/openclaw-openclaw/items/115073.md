## Summary

Keep this issue open. The report describes a credible gap between static plugin discovery and the effective context engine used by a real agent session, but the available evidence does not establish current-main behavior or whether doctor is intentionally limited to static checks. The third-party bootstrap failure was resolved by updating the plugin; the remaining question is OpenClaw’s observability contract for selected capability owners and runtime fallback.

## What This Changes

Request clearer diagnostics when a selected context-engine plugin loads successfully but fails during session bootstrap, is quarantined, and OpenClaw falls back to another engine.

## System Context

Plugin discovery and doctor inspect installed plugin metadata and loadability, while agent-session startup activates the selected context engine. If activation fails, the runtime quarantines that engine and selects a fallback, which affects the context path used for the session.

## Best Possible Solution

Define a single effective-capability diagnostic that records selected-owner bootstrap failure, process quarantine, and fallback selection, then have doctor clearly distinguish static plugin checks from that runtime-derived state rather than running arbitrary session bootstrap implicitly.
