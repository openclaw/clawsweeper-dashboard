## Summary

Keep this PR open for contributor follow-up. The persistence repair is aimed at a real P1 data-integrity regression and the diff preserves existing full-history defaults while making bounded views explicit, but the current head adds iPad bounded-list behavior without current-head real client evidence. The supplied prior ClawSweeper review identified the same gap, and the PR body still only shows runtime proof for the earlier `e9b73b7d922399ee04da1010480b72a2faadc73e` head.

## What This Changes

The branch stops later Workboard card writes from deleting historical SQLite proof rows, then adds explicit bounded proof views and cursor-based proof paging for Gateway, agent tools, web Control UI, and iPad list reads.

## System Context

Workboard persists cards and proof history in its plugin-owned SQLite database, then returns card data through Gateway methods, agent tools, local CLI commands, the Control UI, and iPad. The patch separates complete canonical proof history from optional smaller read projections so later writes cannot turn an output-size limit into permanent data loss.
