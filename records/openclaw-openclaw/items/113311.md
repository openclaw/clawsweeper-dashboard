## Summary

The proposed fix directly targets the linked, deterministic Workboard data-loss report and includes exact-head runtime evidence that an older SQLite proof row survives an unrelated status change under metadata pressure. The lossless persistence repair appears sound from the supplied diff, but this PR also adds two public bounded-view parameters and two proof-pagination operations; that permanent Workboard API expansion needs maintainer confirmation before merge.

## What This Changes

This PR makes Workboard proof history append-only in SQLite across later card writes, while adding explicit bounded proof views and backward pagination for Gateway, agent-tool, and Control UI reads.

## System Context

Workboard records card lifecycle data and proof in a plugin-owned SQLite database, then returns cards through Gateway methods, agent tools, local CLI JSON, and the Control UI. Card mutations update persisted state; read surfaces either return the full canonical card or, with this PR, an explicit bounded proof projection.

Keep canonical proof rows lossless and append-only, retain complete-history responses by default, and merge the bounded projection only after maintainers confirm that the Gateway and agent-tool pagination interfaces are the intended durable Workboard contract.
