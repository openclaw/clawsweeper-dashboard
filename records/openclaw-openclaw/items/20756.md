## Summary

Keep open: current main and v2026.6.11 still lack single-enabled-account inference, and the active implementation candidate at https://github.com/openclaw/openclaw/pull/85671 is open, conflicting, and unmerged.

## What This Changes

The issue requests that the outbound message tool infer the single enabled account for a selected channel when `accountId` is omitted instead of falling back to a disabled `default` account.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver that preserves explicit/default/bound precedence, uses plugin config adapter hooks, and documents zero, one, and multiple enabled-account behavior.

## Solution Assessment

Yes for the owner boundary, but it needs product acceptance: a shared resolver after channel selection is more maintainable than a WhatsApp-only fallback, while the compatibility policy belongs in maintainer review of the linked PR.
