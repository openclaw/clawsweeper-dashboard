## Summary

Keep open: current main and the latest release still do not infer the single enabled account when the message tool omits `accountId`, and https://github.com/openclaw/openclaw/pull/85671 is an open unmerged candidate fix rather than a reason to close this issue now.

## What This Changes

The issue requests message-tool account selection to fall back from a disabled default account to the only enabled configured account when `accountId` is omitted.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound account precedence, uses plugin config adapter hooks, and documents zero, one, and multiple enabled-account behavior.
