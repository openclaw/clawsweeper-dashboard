## Summary

Keep open: current main and v2026.6.11 still do not infer the only enabled account when the message tool omits `accountId`, and the open linked pull request is the active but unmerged implementation candidate.

## What This Changes

The issue asks the message tool to infer the only enabled configured account when `accountId` is omitted instead of falling back to a disabled default account.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence, uses plugin config adapter hooks, documents zero/one/multiple enabled-account behavior, and includes real behavior proof.

Yes for the owner boundary if maintainers accept the behavior: a shared resolver after channel selection is more maintainable than a WhatsApp-only fallback. The remaining blocker is product policy for omitted-account fallback semantics plus proof and conflict handling on the linked PR.
