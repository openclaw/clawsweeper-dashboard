## Summary

Keep open: current main and v2026.6.11 still fall back to default-account behavior when the message tool omits `accountId`, and the open implementation candidate has not merged yet.

## What This Changes

Auto-select the only enabled configured account for message-tool sends when `accountId` is omitted instead of falling back to a disabled default account.

## Best Possible Solution

Land or replace the linked implementation with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence, infers exactly one enabled configured account, and documents/tests clear ambiguous or missing-account failures.

## Reproduction Assessment

Yes, at source level: current main leaves `accountId` unset unless it is explicit/default/bound, and WhatsApp omitted-account sends then use the default helper. I did not run a live WhatsApp send in this read-only review.

## Solution Assessment

Yes for the owner boundary, but it still needs product acceptance: a shared resolver after channel selection is better than a WhatsApp-only fallback, while the fail-closed ambiguity behavior needs maintainer review.
