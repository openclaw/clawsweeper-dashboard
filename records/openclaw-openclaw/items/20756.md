## Summary

Keep open: current main and v2026.6.11 still do not infer the only enabled account when the message tool omits `accountId`, and the linked implementation PR remains open, conflicting, and unmerged.

## What This Changes

Request that the message tool infer the single enabled channel account when `accountId` is omitted instead of falling back to `default`.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence, uses plugin config adapter hooks, and documents zero, one, and multiple enabled-account behavior.
