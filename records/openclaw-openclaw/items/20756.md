## Summary

Keep open: current main and v2026.6.11 still route omitted message-tool account IDs through explicit/default/bound-account behavior only, and the linked implementation PR is open rather than merged.

## What This Changes

The issue asks the message tool to infer the only enabled/configured account when `accountId` is omitted instead of falling back to a disabled `default` account.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence, uses plugin config adapter hooks, and documents zero, one, and multiple enabled-account behavior.
