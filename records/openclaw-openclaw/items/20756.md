## Summary

Keep open: current main and v2026.6.11 still lack single-enabled account inference for omitted message-tool account IDs, and the active linked implementation PR is open rather than merged.

## What This Changes

The issue requests that the message tool infer the only enabled account for a selected channel when `accountId` is omitted instead of falling through to a disabled `default` account.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence, uses plugin config adapter hooks, and documents zero, one, and multiple enabled-account behavior.
