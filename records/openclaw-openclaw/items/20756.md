## Summary

Keep open: current main and v2026.6.11 still do not auto-select a single enabled account for omitted-account message sends, and the active implementation candidate at https://github.com/openclaw/openclaw/pull/85671 is open but not merged.

## What This Changes

Auto-select the single enabled configured channel account for message-tool sends when `accountId` is omitted instead of falling back to a disabled default account.

## Best Possible Solution

Land or replace the linked shared outbound account resolver after preserving explicit/default/bound account precedence, adding focused tests/docs, and getting maintainer acceptance for ambiguous-account failure behavior.

## Reproduction Assessment

Yes, at source level: current main leaves `accountId` unset unless it is explicit/default/bound, and WhatsApp omitted-account sends then fall back to the default helper. I did not run a live WhatsApp send in this read-only review.

## Solution Assessment

Yes for the owner boundary: a shared resolver after channel selection is the maintainable direction, while a WhatsApp-only fallback would be too narrow. The compatibility policy for ambiguous accounts still needs maintainer acceptance before merge.
