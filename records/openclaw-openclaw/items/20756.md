## Summary

Keep open: current main and v2026.6.11 still preserve only explicit/default/bound account IDs, while https://github.com/openclaw/openclaw/pull/85671 is the unmerged candidate fix and the fallback policy still needs maintainer acceptance.

## What This Changes

The issue requests that the message tool infer the only enabled account when `accountId` is omitted instead of falling back to a disabled default account.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence, uses plugin config adapter hooks, and documents zero, one, and multiple enabled-account behavior.
