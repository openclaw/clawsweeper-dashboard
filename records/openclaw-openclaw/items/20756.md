## Summary

Keep open: current main and v2026.6.11 still lack single-enabled-account inference for omitted message-tool account IDs, and the linked implementation PR is open but unmerged, conflicting, and still needs maintainer policy review.

## What This Changes

The issue requests that the message tool infer the only enabled configured account when accountId is omitted instead of falling back to a disabled default account.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/85671 with a maintainer-approved shared outbound account resolver after channel selection that preserves explicit/default/bound account precedence, uses plugin config adapter hooks, and documents zero, one, and multiple enabled-account behavior.
