## Summary

Keep open: current main and v2026.6.11 still route omitted message-tool account IDs through explicit/default/bound-account behavior only, while https://github.com/openclaw/openclaw/pull/85671 is open but unmerged as the active fix candidate.

## What This Changes

The issue requests message-tool account inference so an omitted `accountId` uses the only enabled account for the selected channel instead of falling through to a disabled default.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence, uses plugin config adapter hooks, and documents zero, one, and multiple enabled-account behavior.
