## Summary

Keep open: current `main` and v2026.6.11 still use explicit/default/bound account IDs only, while https://github.com/openclaw/openclaw/pull/85671 is an open unmerged implementation candidate rather than a merged fix.

## What This Changes

The issue requests omitted message-tool account IDs to select the single enabled configured account for a channel instead of falling back to a disabled `default` account.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence, uses plugin config adapter hooks, and documents zero, one, and multiple enabled-account behavior.
