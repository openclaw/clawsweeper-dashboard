## Summary

Keep open: current main and v2026.6.11 still lack enabled-account inference for omitted message-tool account IDs, and https://github.com/openclaw/openclaw/pull/85671 is an open candidate fix that should be reviewed before this canonical tracker closes.

## What This Changes

The issue requests that the message tool infer the only enabled configured account when `accountId` is omitted instead of falling back to a disabled `default` account.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence, uses plugin adapter hooks, and documents zero, one, and multiple enabled-account behavior.
