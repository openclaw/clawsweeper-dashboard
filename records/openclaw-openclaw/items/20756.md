## Summary

Keep open: current main and v2026.6.11 still preserve only explicit, default, or bound account IDs, while WhatsApp omitted-account sends still fall back to the default account; the linked closing PR is open, conflicting, and not proof-cleared.

## What This Changes

The issue asks for the message tool to auto-select the only enabled account when accountId is omitted instead of falling back to a disabled default account.

## Best Possible Solution

Land or replace a narrow shared outbound account resolver after channel selection that preserves explicit/default/bound accounts first, auto-selects exactly one enabled configured account, errors clearly for zero or multiple choices, and updates focused tests and docs after maintainer policy approval.
