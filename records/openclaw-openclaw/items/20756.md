## Summary

Keep open: current main and v2026.6.11 still do not infer the single enabled account when the message tool omits accountId, and the linked implementation remains an open unmerged PR rather than a completed fix.

## What This Changes

The issue requests that the message tool infer the single enabled channel account when accountId is omitted instead of falling back to a disabled default account.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound account precedence, uses plugin config adapter hooks, and documents zero, one, and multiple enabled-account behavior.
