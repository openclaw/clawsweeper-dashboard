## Summary

Keep open: current main and v2026.6.11 still do not infer the only enabled account for omitted message-tool account IDs, and the linked implementation PR is open, unmerged, and still needs maintainer review.

## What This Changes

The issue asks the message tool to infer the single enabled configured account when no accountId is provided instead of falling back to a disabled default account.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence, uses plugin config adapter hooks, and documents zero, one, and multiple enabled-account behavior.
