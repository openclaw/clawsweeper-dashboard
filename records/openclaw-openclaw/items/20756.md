## Summary

Keep open: current main and v2026.6.11 still do not infer the only enabled account when the message tool omits `accountId`, and https://github.com/openclaw/openclaw/pull/85671 is an open unmerged candidate rather than a reason to close this issue.

## What This Changes

The issue requests that omitted message-tool `accountId` values use the enabled default account or exactly one enabled configured account instead of falling through to a disabled `default` account.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence, uses plugin config adapter hooks, and documents zero, one, and multiple enabled-account behavior.
