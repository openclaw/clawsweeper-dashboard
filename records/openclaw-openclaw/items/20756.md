## Summary

Keep open: current `main` and v2026.6.11 still preserve only explicit/default/bound account IDs, and the open closing PR is an unmerged implementation candidate that needs maintainer policy review, conflict handling, and proof before this issue can close.

## What This Changes

The issue requests that the outbound `message` tool infer the only enabled account for a selected channel when `accountId` is omitted and the configured default account is disabled.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver that preserves explicit/default/bound precedence, uses plugin account adapter hooks, and documents zero, one, and multiple enabled-account behavior.
