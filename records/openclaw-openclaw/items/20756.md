## Summary

Keep open: current main and v2026.6.11 still do not infer the only enabled account for omitted message-tool accountId, and the linked implementation PR is open, unmerged, proof-blocked, and not contained in any current branch or release tag.

## What This Changes

The issue requests automatic account selection for the message tool when one enabled channel account exists and no accountId was provided.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence, uses plugin config adapter hooks, and documents zero, one, and multiple enabled-account behavior.
