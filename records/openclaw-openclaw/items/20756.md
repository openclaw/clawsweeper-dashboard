## Summary

Keep open: current `main` still does not infer the single enabled account for omitted message-tool `accountId`, and the open linked implementation PR is unmerged and currently conflicting, so it cannot be treated as an implemented fix.

## What This Changes

The issue asks the message tool to use the only enabled account for a selected channel when `accountId` is omitted instead of falling back to a disabled `default` account.

## Best Possible Solution

Land a shared outbound account resolver after channel selection that preserves explicit/default/bound account IDs first, then infers exactly one enabled configured account with clear zero-or-multiple-account errors and matching docs/tests.
