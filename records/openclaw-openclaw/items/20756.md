## Summary

Keep open: current main and v2026.6.11 still use the documented default-account fallback instead of enabled-account inference, and the closing implementation PR is open, dirty, and not merged.

## What This Changes

The issue asks the message tool to infer the only enabled account for a selected multi-account channel when `accountId` is omitted instead of falling back to a disabled `default` account.

## Best Possible Solution

Land or replace a narrow shared outbound account resolver after channel selection that preserves explicit/default/bound accounts first, auto-selects exactly one enabled configured account, errors clearly for zero or multiple choices, and updates focused tests and docs after maintainer policy approval.
