## Summary

Keep open: current main and latest release still route omitted message-tool account IDs through explicit/default/bound-account behavior only, and the linked implementation PR is open but unmerged.

## What This Changes

The issue requests message-tool account inference when a selected channel has exactly one enabled account and no `accountId` was provided.

## Best Possible Solution

Land or replace the linked PR with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence, uses plugin config adapter hooks, and documents zero, one, and multiple enabled-account behavior.
