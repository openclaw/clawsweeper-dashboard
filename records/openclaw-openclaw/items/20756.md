## Summary

Keep open: current main and v2026.6.11 still do not infer the only enabled account when the message tool omits `accountId`, and https://github.com/openclaw/openclaw/pull/85671 is the active open implementation candidate rather than a merged fix.

## What This Changes

The issue requests message-tool account selection that preserves explicit/default/bound account precedence, then auto-selects exactly one enabled configured channel account when `accountId` is omitted.

## Best Possible Solution

Review and either land or replace https://github.com/openclaw/openclaw/pull/85671 with a shared post-channel-selection account resolver that preserves explicit/default/bound precedence and documents zero, one, and multiple enabled-account behavior.
