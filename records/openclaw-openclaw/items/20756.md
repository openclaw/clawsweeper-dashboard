## Summary

Keep open: current main and v2026.6.11 still do not infer the only enabled account, and the open closing PR remains the candidate implementation rather than a merged fix.

## What This Changes

The issue asks the message tool to infer the single enabled configured account when `accountId` is omitted instead of falling back to a disabled default account.

## Best Possible Solution

Adopt a maintainer-approved shared outbound account resolver after channel selection that preserves explicit/default/bound precedence and uses channel plugin account adapter hooks for enabled/configured account inference.
