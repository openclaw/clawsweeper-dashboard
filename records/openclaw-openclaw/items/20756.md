## Summary

Keep open. Current main still does not infer the only enabled account for omitted message-tool `accountId`, and the active linked fix PR is open but not merged, so this issue remains the canonical tracking item.

## What This Changes

The issue requests that the outbound message tool infer the only enabled account when `accountId` is omitted instead of falling back to a disabled `default` account.

## Best Possible Solution

Keep this issue open as the canonical report and resolve it by landing or replacing the linked shared outbound resolver after proof, rebase, and compatibility review.

## Reproduction Assessment

Yes at source level: current main leaves `accountId` unset unless it is explicit/default/bound, and WhatsApp omitted-account sends then use the default helper. I did not run a live WhatsApp or CLI send in this read-only review.

## Solution Assessment

Yes, the best direction appears to be a shared outbound resolver after channel selection using the plugin config adapter seam, not a WhatsApp-only special case. The linked PR still needs mergeability, proof, and maintainer acceptance of the fallback policy before this issue can close.
