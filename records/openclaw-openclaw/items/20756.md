## Summary

Keep open. Current `main` and the latest release still preserve only explicit/default/bound account IDs, so the requested single-enabled-account selection is not implemented; the open linked PR is the active candidate and this issue should remain canonical until that PR lands or is replaced.

## What This Changes

The issue requests that the `message` tool infer the only enabled channel account when `accountId` is omitted and the default account is disabled.

## Best Possible Solution

Keep this issue open as the canonical report, then land or replace the linked shared outbound resolver after maintainers accept the compatibility policy and the PR has proof.

## Reproduction Assessment

Yes at source level: current `main` preserves explicit/default/bound account IDs only, and WhatsApp omitted-account sends still fall back to the default-account helper. I did not run a live WhatsApp send in this read-only review.

## Solution Assessment

Yes for the likely owner boundary, but not complete yet: a shared resolver after channel selection is the maintainable shape, while a WhatsApp-only fallback would duplicate policy. The final behavior still needs maintainer acceptance because it changes omitted-account fallback semantics.
