## Summary

Keep open: current main and v2026.6.11 still preserve only explicit, default, or bound account IDs, while the closing implementation PR is open and unmerged.

## What This Changes

The issue asks the message tool to infer the selected channel's single enabled account when accountId is omitted instead of falling back to a disabled default account.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence, uses plugin config adapter hooks, and documents zero, one, and multiple enabled-account behavior.
