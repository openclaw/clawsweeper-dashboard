## Summary

Keep open: current main and v2026.6.11 still do not infer the only enabled account when the message tool omits `accountId`, and the linked implementation PR is open, conflicting, and not yet a merged fix.

## What This Changes

Request auto-selecting the sole enabled account for an outbound message channel when `accountId` is omitted and the configured/default account is disabled.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence, uses plugin config adapter hooks, documents zero/one/multiple enabled-account behavior, and includes real behavior proof.
