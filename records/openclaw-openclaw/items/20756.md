## Summary

Keep open: current main still lacks single-enabled account inference for omitted message-tool accountId, and the open linked pull request is an unmerged/conflicting candidate rather than a landed fix.

## What This Changes

Request message-tool sends without accountId to select an enabled default account or the only enabled configured account instead of falling through to a disabled default.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver that preserves explicit/default/bound precedence and documents zero, one, and multiple enabled-account behavior.
