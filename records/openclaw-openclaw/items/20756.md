## Summary

Keep open: current main and the latest release still lack single-enabled-account inference for omitted message-tool `accountId`, and https://github.com/openclaw/openclaw/pull/85671 is an open unmerged candidate fix rather than a reason to close this issue now.

## What This Changes

The issue requests that omitted message-tool account selection choose the only enabled account for a channel instead of falling back to a disabled default account.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound account precedence, uses plugin config adapter hooks, and documents zero, one, and multiple enabled-account behavior.
