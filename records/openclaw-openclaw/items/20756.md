## Summary

Keep open: current main and v2026.6.11 still do not infer the only enabled configured account when the message tool omits accountId, and https://github.com/openclaw/openclaw/pull/85671 is the active open implementation candidate rather than a merged fix.

## What This Changes

The issue asks the message tool to auto-select the only enabled account for a selected channel when accountId is omitted instead of falling back to a disabled default account.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence, uses plugin config adapter hooks, documents zero/one/multiple enabled-account behavior, and includes real behavior proof.
