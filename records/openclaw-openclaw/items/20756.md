## Summary

Keep open: current main and v2026.6.11 still route omitted `accountId` through explicit/default/bound/default fallback, and https://github.com/openclaw/openclaw/pull/85671 is open, conflicting, and unmerged rather than a landed fix.

## What This Changes

Request that the message tool infer exactly one enabled configured account when `accountId` is omitted instead of falling back to a disabled default account.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence and documents zero, one, and multiple enabled-account behavior.
