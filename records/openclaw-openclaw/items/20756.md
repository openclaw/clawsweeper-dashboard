## Summary

Keep open: current main and the latest release still do not infer the only enabled account for omitted-account message-tool sends, and the open linked fix candidate has not merged.

## What This Changes

Request account inference for message-tool sends so an omitted `accountId` selects the only enabled configured account instead of falling through to a disabled/default account.

## Best Possible Solution

Land or replace the linked shared outbound account resolver after resolving its mergeability, proof, and compatibility-policy questions; keep this issue open until that fix merges.

## Reproduction Assessment

Yes at source level: current main leaves `accountId` unset unless it is explicit/default/bound, and WhatsApp omitted sends then use the default helper. I did not run a live WhatsApp or CLI send in this read-only review.

## Solution Assessment

Yes for the owner boundary: a shared resolver after channel selection is cleaner than a WhatsApp-only fallback. Maintainers still need to accept the compatibility policy for zero and multiple enabled accounts before landing the linked PR.
