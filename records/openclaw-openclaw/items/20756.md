## Summary

Keep open: current main and the latest release still do not infer the only enabled account for omitted message-tool account IDs, and https://github.com/openclaw/openclaw/pull/85671 is the open implementation candidate rather than a merged fix.

## What This Changes

The issue asks for outbound message sends without an explicit accountId to infer the only enabled account instead of falling back to a disabled default account.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence, uses plugin config adapter hooks, and documents zero, one, and multiple enabled-account behavior.
