## Summary

Keep open: current main and v2026.6.11 still do not infer the single enabled account for omitted-account message sends, and the open linked PR is the active implementation candidate rather than a reason to close this issue.

## What This Changes

The issue asks the message tool to infer the only enabled account for a selected channel when no accountId is supplied.

## Best Possible Solution

Review, update, and land or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound account precedence, uses plugin config adapter hooks, and includes focused tests and docs.

## Reproduction Assessment

Yes at source level: current main leaves accountId unset unless it is explicit, input-defaulted, or agent-bound, and WhatsApp omitted-account sends then use the default-account helper. I did not run a live WhatsApp delivery path in this read-only review.

## Solution Assessment

Yes on direction, with maintainer policy review still needed: a shared resolver after channel selection is better than a WhatsApp-only fallback because the adapter contract already exposes account listing, enabled, and configured hooks. The open PR should be reviewed or replaced rather than spawning another duplicate fix.
