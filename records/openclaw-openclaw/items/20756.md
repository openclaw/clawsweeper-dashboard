## Summary

Keep open: current main and v2026.6.11 still do not infer the only enabled configured account for omitted message-tool `accountId`, and the linked implementation candidate is still open, unmerged, and conflicting.

## What This Changes

The issue asks for omitted message-tool account IDs to infer the single enabled configured account after honoring explicit, default, and bound account precedence.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence, uses plugin config adapter hooks, and documents zero, one, and multiple enabled-account behavior.
