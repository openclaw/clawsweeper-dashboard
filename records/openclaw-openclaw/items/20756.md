## Summary

Keep open: current main and the latest release still do not infer the only enabled account when the message tool omits `accountId`, and https://github.com/openclaw/openclaw/pull/85671 is an open, unmerged candidate fix rather than landed behavior.

## What This Changes

The issue requests message-tool account selection to use the only enabled configured account instead of falling through to a disabled default account when `accountId` is omitted.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence and documents zero, one, and multiple enabled-account behavior.
