Keep open: current main still falls through explicit/default/bound account behavior when the message tool omits `accountId`, and the linked implementation PR is open but unmerged.

## What This Changes

The issue requests omitted message-tool `accountId` to infer the single enabled configured account for the selected channel instead of falling through to a disabled `default` account.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence, uses plugin config adapter hooks, and documents zero, one, and multiple enabled-account behavior.
