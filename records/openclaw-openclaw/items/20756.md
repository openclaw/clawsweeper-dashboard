## Summary

Keep open: current main and v2026.6.11 still do not auto-select the only enabled account when the message tool omits `accountId`, and https://github.com/openclaw/openclaw/pull/85671 is the active open implementation candidate rather than a merged fix.

## What This Changes

The issue requests message-tool account inference that uses the only enabled account when `accountId` is omitted and the configured default account is disabled.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared post-channel-selection account resolver that preserves explicit/default/bound precedence and documents zero, one, and multiple enabled-account behavior.
