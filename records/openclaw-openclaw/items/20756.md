## Summary

Keep open: current main and v2026.6.11 still do not infer the only enabled account for omitted message-tool `accountId`, and https://github.com/openclaw/openclaw/pull/85671 is the active unmerged candidate fix.

## What This Changes

The issue requests auto-selecting the only enabled account for the selected message channel when `accountId` is omitted instead of falling back to a disabled default account.

## Best Possible Solution

Review, land, or replace https://github.com/openclaw/openclaw/pull/85671 with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence, uses plugin config adapter hooks, and documents zero, one, and multiple enabled-account behavior.

- **Move Fallback To Channel Ownership:** Require channel-owned inference rules if maintainers do not want core to define this fallback policy across message channels.

## Solution Assessment

Yes for the owner boundary, but it still needs maintainer policy acceptance: a shared resolver after channel selection is more maintainable than a WhatsApp-only fallback, while preserving explicit/default/bound precedence avoids surprising existing callers.
