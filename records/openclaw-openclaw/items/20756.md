## Summary

Keep open: current main and v2026.6.11 still do not infer the only enabled account when the message tool omits `accountId`, and the active implementation path is the open, unmerged https://github.com/openclaw/openclaw/pull/85671.

## What This Changes

The issue asks for the outbound message tool to infer the only enabled account when `accountId` is omitted instead of falling back to a disabled `default` account.

## Best Possible Solution

Land or replace the active shared outbound resolver after maintainer acceptance of the omitted-account compatibility policy, real behavior proof, and conflict/snapshot cleanup.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: omit `accountId` for WhatsApp with `default` disabled and one other enabled account, and current main still resolves through the default-account helper.

## Solution Assessment

Unclear. A shared outbound resolver after channel selection is the best-looking owner boundary, but the active linked PR still needs maintainer acceptance of fallback policy, conflict resolution, and real proof before it is the accepted fix.
