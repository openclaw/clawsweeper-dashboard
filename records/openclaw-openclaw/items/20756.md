## Summary

Keep open: current main and v2026.6.11 still do not auto-select the single enabled account, and the linked implementation PR is open, conflicting, and not merged.

## What This Changes

The issue asks the message tool to infer the only enabled configured account when `accountId` is omitted instead of falling back to a disabled `default` account.

## Best Possible Solution

Land or replace the linked PR with a shared outbound account resolver after channel selection that preserves explicit/default/bound precedence, uses plugin config adapter hooks, and documents zero, one, and multiple enabled-account behavior.

- **Require channel-owned fallback:** Ask for channel-owned behavior if maintainers do not want core to own this inference policy across message channels.

## Reproduction Assessment

Yes at source level: current main leaves `accountId` unset unless it is explicit/default/bound, and WhatsApp omitted-account sends then ask the default helper. I did not run a live WhatsApp or CLI send in this read-only review.

## Solution Assessment

Yes for the owner boundary, but maintainer policy acceptance is still needed. A shared resolver after channel selection is more maintainable than a WhatsApp-only fallback because it can use the existing plugin config adapter seam.
