## Summary

This is a plausible, well-proven Codex lifecycle fix, but it intentionally changes terminal-close semantics: an explicit final or yield may leave the Codex turn live for up to 10 seconds and may append post-final output before completion. The branch is also currently conflict-dirty, so a maintainer should choose that policy and require a rebase with exact-head validation before merge.

## What This Changes

The PR replaces immediate `turn/interrupt` after Codex terminal dynamic-tool delivery with natural `turn/completed`, using a 10-second or new-inbound interrupt fallback and preserving delivered replies as successful.

## Best Possible Solution

Choose the explicit-final/yield policy, then rebase onto current main and validate the selected behavior for clean completion, post-final runaway, and new-inbound interruption on the exact mergeable head.
