## Summary

Keep this PR open: the underlying legacy-profile failure is still present on current main, but the latest head is not mergeable as a fix. It replaces the full shared auth module and its main profile test suite with one-line files, and its global `modelstudio` → `qwen` alias conflicts with the existing custom-`modelstudio` ownership boundary. The contributor's tests are useful regression evidence, but they are not real-runtime proof and do not establish safe upgrade behavior for custom providers.

## What This Changes

This PR adds Qwen auth aliases for legacy `modelstudio` and `qwencloud` profile IDs, retries missing explicit legacy profile IDs through the canonical provider, and adds regression tests for the resolution path.

## System Context

OpenClaw's agent auth resolver turns a selected provider and optional stored profile ID into credentials for model execution. Qwen plugin metadata feeds provider-auth aliases into that resolver, so an alias decision can affect stored credentials, configured provider ownership, and every agent run using that provider.
