## Summary

Keep open: the current head still routes non-Arch hosts with any `pacman` command into the pacman installer branch because `is_arch_linux` still treats `pacman` itself as Arch evidence, and the external real-behavior proof gate is still missing.

## What This Changes

The PR changes `scripts/install.sh` so the Linux Node.js pacman branch requires both `command -v pacman` and `is_arch_linux`.

## Best Possible Solution

Use an Arch distro check that does not treat `pacman` alone as OS identity for the Node route, preserve the intended Arch pacman path, add Debian/Ubuntu fake-pacman regression coverage, and attach redacted terminal proof for both affected and preserved paths.

## Reproduction Assessment

Yes. A focused sourced `install_node` invocation with `pacman` defined on PATH reproduced the false pacman route on current main and on the PR head before NodeSource is reached.

## Solution Assessment

No. Changing `||` to `&&` is only a plausible-looking fix because `is_arch_linux` still falls back to `pacman`; the best fix is an Arch identity helper that is independent of the package-manager executable for this decision.
