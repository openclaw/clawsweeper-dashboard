## Summary

Keep open: the PR head still routes a Debian-like shell with an unrelated `pacman` command into the pacman Node installer path, so the patch does not fix the reported installer bug and still lacks real behavior proof.

## What This Changes

The PR changes `scripts/install.sh` so the Linux Node.js pacman branch requires both `command -v pacman` and `is_arch_linux`.

## Best Possible Solution

Make the Arch identity check used by the Node installer independent of the `pacman` executable, preserve the intended Arch pacman path, add a Debian/Ubuntu fake-pacman regression test, and attach redacted terminal proof for both affected and preserved routes.

## Reproduction Assessment

Yes. A focused sourced `install_node` invocation against the PR head with `pacman` defined on PATH reproduced the false pacman route before NodeSource is reached.

## Solution Assessment

No. Changing `||` to `&&` is only a plausible-looking fix because `is_arch_linux` still falls back to `pacman`; the best fix is an Arch identity helper that is independent of the package-manager executable for this decision.
