## Summary

Keep open: the PR is not merge-ready because `is_arch_linux` still returns true when any `pacman` command is on PATH, so the new `&&` guard still selects the pacman Node install path on non-Arch systems with a pacman executable. The external contributor also has not supplied real installer proof.

## What This Changes

The branch changes `scripts/install.sh` so the Linux Node.js pacman branch requires both a `pacman` command and `is_arch_linux`.

## Best Possible Solution

Make the Node install Arch distro check independent of the `pacman` executable fallback, preserve the intended Arch pacman path, and add both a focused regression test and redacted live installer proof.

## Reproduction Assessment

Yes. A focused shell invocation against current main and the PR head shows a non-Arch host with a `pacman` command still routes `install_node` through pacman before NodeSource.

## Solution Assessment

No. The `&&` change is only a plausible-looking fix; the best fix is to remove the `pacman` fallback from this distro decision or add a separate os-release-only Arch helper for the Node route.
