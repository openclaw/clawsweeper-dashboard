## Summary

Keep this PR open for normal maintainer review. The implementation appears to address the linked auto-discovery bug without adding configuration or changing explicitly configured browser paths, and the latest head was updated by the assigned maintainer; however, the posted live proof names an earlier SHA, so the current head needs an equivalence check or refreshed redacted live output before merge.

## What This Changes

The PR replaces existence-only checks in automatic browser discovery with executable-access checks so macOS and Linux skip an inaccessible browser candidate and continue to a runnable later candidate.

## System Context

The bundled browser plugin resolves a local Chromium-family executable before browser automation launches. It considers the configured path first, then platform default-browser metadata and ordered platform candidates, returning a browser path for the launch layer.

## Architecture Diagram

  F --> B
  E --> G[Browser automation launch]

## Best Possible Solution

Keep the narrow executable-access predicate for automatic candidates, verify the maintainer’s latest simplification is behaviorally equivalent, and retain explicit user-configured paths as a separate existence-validated contract.
