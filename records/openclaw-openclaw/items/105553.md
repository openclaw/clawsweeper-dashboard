## Summary

The patch is correct and strongly proven, but the fixed fail-closed timeout can change behavior for unusually slow Mattermost proxies; a Mattermost reconnect owner should explicitly accept the 30-second availability boundary before merge.

## What This Changes

Adds a 30-second timeout to the default Mattermost WebSocket handshake and regression coverage showing stalled upgrades return control to the reconnect loop.

## Best Possible Solution

Use the native `ws` handshake timeout in the Mattermost default factory and retain the reconnect regression, landing the patch once the fixed 30-second plugin policy is explicitly accepted.
