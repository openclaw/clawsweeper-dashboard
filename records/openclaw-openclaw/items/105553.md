## Summary

The patch is a focused, correct reliability fix with strong standalone proof; it should remain open because changing Mattermost from an unbounded wait to a fixed 30-second fail-closed boundary is an availability-policy choice that needs explicit Mattermost owner acceptance.

## What This Changes

Adds a private 30-second `ws` handshake timeout to Mattermost’s default WebSocket factory and regression coverage showing a stalled upgrade returns control to the reconnect loop.

## Best Possible Solution

Keep the private owner-local timeout and reconnect coverage, with the Mattermost owner explicitly confirming that 30 seconds is the intended default; avoid adding a config option unless real deployments demonstrate a legitimate need to tune it.
