## What This Changes

Adds a 30-second timeout to Mattermost WebSocket upgrade handshakes and regression coverage showing stalled upgrades return control to the reconnect loop.

## Best Possible Solution

Keep the timeout in the Mattermost default factory, retain the stalled-peer reconnect regression, and land the fixed 30-second sibling-aligned bound once the channel owner accepts the slow-upgrade tradeoff; avoid adding configuration unless real deployments demonstrate that the default is unsuitable.
