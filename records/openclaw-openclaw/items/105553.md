## Summary

The patch appears correct and well-proven, but this PR should remain open until a Mattermost owner accepts the unconditional 30-second fail-closed budget because unusually slow proxy, TLS, or server upgrades would now reconnect instead of continuing to wait.

## What This Changes

Adds a 30-second timeout to the default Mattermost WebSocket handshake and regression coverage showing stalled upgrades return control to the reconnect loop.

## Best Possible Solution

Keep one bounded timeout in the Mattermost production WebSocket options, retain the existing reconnect path and no-config design, and land an owner-approved fixed budget with the current transport-level regression proof.
