## Summary

Current `main` still permits an indefinitely stalled Mattermost WebSocket upgrade, while this focused patch correctly releases that attempt into the existing reconnect loop. The only remaining blocker is explicit owner acceptance of the fixed 30-second availability boundary.

## What This Changes

The PR adds a private 30-second `ws` handshake timeout to Mattermost’s default WebSocket factory and regression coverage showing stalled upgrades return control to reconnect.

## Best Possible Solution

Keep the native `ws` handshake deadline in the plugin’s canonical client options with the existing reconnect proof, after a Mattermost owner explicitly accepts 30 seconds as the default boundary.

- **Defer the timeout:** Retain indefinite waits until deployment evidence establishes a safe default, accepting the existing stalled-reconnect failure mode.

## Solution Assessment

Yes, subject to timeout-policy approval. Using upstream `ws`’s native `handshakeTimeout` in the Mattermost-owned default factory is narrower and safer than adding a parallel timer or new configuration surface.
