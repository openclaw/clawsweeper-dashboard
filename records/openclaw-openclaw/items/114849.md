## Summary

The PR is a focused, contract-aligned fix for the reported silent failure: `/hooks/agent` already routes final replies through `channel` plus `to`, while `channelId` is not a documented delivery field. The patch now rejects that unsupported input before dispatch and provides remediation instead of returning a misleading successful run. Its only meaningful merge consideration is intentional compatibility: callers currently sending `channelId` will change from a silent success to HTTP 400, so a gateway-area reviewer should explicitly accept that fail-loud upgrade behavior.

## What This Changes

This PR makes `/hooks/agent` return HTTP 400 for the unsupported `channelId` request field, documents `channel` plus `to` as the delivery route for the final agent reply, and adds unit and HTTP coverage.

## System Context

The Gateway hook endpoint accepts authenticated external events and starts an isolated agent run. When delivery is requested, the run’s final reply is routed through a configured messaging channel and target; this change validates the incoming hook payload before that dispatch occurs.
