## Summary

Keep open: the PR targets the right diagnostic bug, but resetting `queueDepth` on every idle transition is too broad and can erase legitimate queued backlog outside the accepted active-run steering case.

## What This Changes

The branch changes diagnostic idle accounting to reset `queueDepth` to zero and adds a regression test for multiple queued messages followed by idle.

## Best Possible Solution

Preserve normal queue-depth backlog accounting and fix the active embedded steering source, ideally by not counting accepted steering messages as queued backlog and proving the behavior in real embedded-agent diagnostics.

## Reproduction Assessment

Yes from source inspection, but not from a live run: accepted active-run steering can increment `queueDepth` multiple times while normal run completion emits one idle reconciliation. The introduced PR risk is also source-provable because the reset changes the shared idle transition used by other lifecycle paths.

## Solution Assessment

No. Resetting `queueDepth` on every idle transition solves the reported symptom by discarding shared queue state; the safer fix is to stop counting accepted active embedded-run steering as backlog while preserving normal queue accounting.
