## What This Changes

The issue requests syntax-aware Code Mode module-access validation so ordinary object members named `import` or `require` remain valid while all direct loader-call variants are rejected before QuickJS execution.

## System Context

Code Mode accepts model-generated JavaScript or TypeScript and validates it before sending it into the QuickJS-WASI guest runtime. The validator must distinguish ordinary language syntax from direct module-loader access so valid object APIs run while unsupported module access fails at the host boundary.

## Best Possible Solution

Implement a shared AST-based direct-loader detector for JavaScript and TypeScript, preserve ordinary member/property syntax, and add focused parser plus real QuickJS-worker regressions for every reported direct-call form.
