## Summary

The report is a valid current-main regression: the headless node advertises the built-in MCP command family only when server inventory is non-empty, while gateway reconnect reconciliation treats the later declaration as a privileged pairing-surface upgrade. The issue should remain open because the protected maintainer label requires explicit handling and https://github.com/openclaw/openclaw/pull/104745 is an open direct fix candidate, not a merged implementation.

## What This Changes

Fix headless nodes requesting a second admin pairing approval when the first MCP server is added after initial pairing.

## Best Possible Solution

Review and land the linked PR’s invariant-preserving fix, retaining one explicit upgrade approval only for pre-fix pairings while ensuring fresh pairings can add, remove, or filter MCP servers with a node-host restart and no new approval.

## Reproduction Assessment

Yes. The issue provides a deterministic Blacksmith Testbox cold-pair scenario, and current main’s conditional MCP declaration plus reconnect upgrade comparison explains the observed second approval request.

## Solution Assessment

Yes. Declaring the built-in MCP command family independently of configured inventory restores the established pairing invariant, while the MCP manager still controls actual tool availability and the disconnect specialization preserves the structured error contract.
