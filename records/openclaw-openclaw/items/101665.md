## Summary

The previous finalization-order concern is fixed and the single-tool proof is strong, but the new public contract remains unsafe for default-parallel tool batches and needs explicit scheduling semantics before merge.

## What This Changes

The PR adds a public plugin tool-result yield control, applies it after result-finalization hooks, preserves it through tool adapters and catalog paths, and maps embedded sessions onto the existing turn-yield lifecycle.

## Best Possible Solution

Make yield capability known before tool execution so the host can force the whole batch onto sequential scheduling, or reject yield controls from tools that did not predeclare that capability; retain the finalized-result hook and existing session-yield lifecycle.
