## Summary

This PR is still useful and well-proven, but it cannot merge until the public Plugin SDK contract prevents yield-capable tools from racing parallel sibling calls and the conflicted branch is refreshed against current main. The existing `sessions_yield` behavior explicitly skips remaining queued tool work, while this result-level control is discovered only after parallel tools may already have started. ([github.com](https://github.com/openclaw/openclaw/pull/36537))

## What This Changes

The PR adds `AgentToolResult.control` and `yieldToolResult(...)`, propagates yield requests through plugin tool execution paths, and maps finalized controls to embedded session turn handoff.

## Best Possible Solution

Define yield-capable tools as sequential before execution—preferably by requiring the existing `executionMode: "sequential"` declaration, rejecting incompatible yielding results explicitly, documenting that contract, and proving that later sibling tools never start.

Question: What permanent scheduling contract should the public `yieldToolResult(...)` API require when its tool appears in a multi-tool assistant batch?

Rationale: A result-only signal arrives too late to stop already-started parallel siblings, so maintainers must choose whether yield capability requires existing sequential metadata, a new pre-execution capability marker, or deliberately weaker semantics.

Likely owner: jalehman

Owner reason: They made and merged the original architectural decision that `sessions_yield` must produce a real turn-ending idle-session handoff.

Owner confidence: high

Options:

- **Require sequential tools (recommended):** Require tools that may return `yieldToolResult(...)` to declare `executionMode: "sequential"`, reject misuse explicitly, and test that later siblings do not start.
- **Add yield-capable metadata:** Add a dedicated pre-execution tool capability that makes any containing batch sequential, increasing the public SDK surface but making intent explicit.
- **Use next-turn-only semantics:** Permit parallel siblings to finish and document that result-level yield only prevents another model turn, which is weaker than existing `sessions_yield` behavior.
