## Summary

The prior scheduling blocker is fixed and the external-plugin proof is convincing, but the latest head makes every sequential tool bypass Tool Search and Code Mode, expanding a new yield feature into an unapproved compatibility change for existing plugin tools.

## What This Changes

The PR adds a public `yieldToolResult(...)` Plugin SDK helper and result-level runtime control, applies finalized yield requests in agent-core, routes them through embedded-session handoff, and changes sequential tools to remain directly model-visible.

## Best Possible Solution

Add an explicit yield-capability or direct-exposure declaration to the tool descriptor, require that capability to use sequential execution, and use it—not generic `executionMode`—to keep only yield-capable tools outside catalog bridges.
