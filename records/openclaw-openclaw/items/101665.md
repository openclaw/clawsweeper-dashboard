## Summary

Keep this PR open, but do not merge the current head: the yield primitive is useful and well-proven, while the patch still changes catalog eligibility for every sequential tool rather than only yield-capable tools. The linked feature issue should remain open until maintainers choose the permanent Plugin SDK contract and this compatibility blocker is repaired.

## What This Changes

The PR adds a public Plugin SDK yield result, finalized agent-loop control handling, embedded-session turn handoff, sequential-tool catalog restrictions, regression tests, and plugin-author documentation.

## Best Possible Solution

Add an explicit definition-level yield or direct-execution capability to the public plugin tool contract, let catalogs inspect that capability before execution, retain `executionMode: "sequential"` solely for scheduling, and cover both yield-capable direct tools and ordinary sequential catalog tools with regression tests.
