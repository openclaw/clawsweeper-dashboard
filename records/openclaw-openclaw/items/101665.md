## Summary

Keep this PR open, but do not merge the current head: the new yield request is observed only after tool execution, so it cannot guarantee a clean handoff when the yielding tool was admitted in a parallel batch. The latest test proves the safe sequential case, not the unrestricted public API documented for plugin authors.

## What This Changes

The PR adds a public Plugin SDK yield-result helper and result control, propagates it through agent-core and catalog execution paths, and maps finalized controls to embedded session turn handoff.

## Best Possible Solution

Require yield-capable tools to declare the existing sequential execution mode, reject finalized yield controls from undeclared or parallel tools, and document and test that contract across normal, hook-added, Tool Search, and Code Mode paths.
