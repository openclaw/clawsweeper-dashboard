## Summary

Keep open. The external-plugin proof is strong and direct-tool scheduling is covered, but the latest same-head Tool Search blocker remains: the catalog bridge preserves the result control without preserving the target tool’s sequential execution contract. The new public Plugin SDK boundary also needs an explicit maintainer decision before landing.

## What This Changes

The PR adds a Plugin SDK yield result, propagates finalized tool-result controls through agent and catalog execution, and maps successful yield requests onto embedded-session turn handoff.

## Best Possible Solution

Use a maintainer-approved, narrow yield contract, preserve the selected target’s sequential execution metadata through every catalog or deferred wrapper, and add a batch regression proving a yielded catalog target prevents later siblings before rebasing and rerunning exact-head gates.
