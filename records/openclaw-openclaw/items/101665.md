## Summary

This PR should remain open for a maintainer decision on the permanent public SDK contract—especially whether `executionMode: "sequential"` should also become the catalog-visibility signal—and the conflicted head must be refreshed before landing.

## What This Changes

The PR adds `AgentToolResult.control` and `yieldToolResult(...)`, applies finalized yield controls in agent-core, preserves them through plugin tool adapters, and maps them to embedded-session turn handoff.

## Best Possible Solution

Adopt a single documented host-owned yield capability only after maintainers confirm its permanent SDK shape; ideally use an explicit static yield-capability declaration if sequential scheduling alone should not change catalog visibility, then rebase and prove the final exact head.
