## Summary

Keep open: the previously reported P1 blocker remains on the current head. A yield request is handled only after one tool finishes, while the default parallel path may already have started every sibling tool, so the advertised clean external-interaction handoff is not guaranteed. Likely related people: @badlogic for the upstream agent-loop contract and @steipete for the OpenClaw SDK/runtime decision.

## What This Changes

The PR adds a public plugin tool-result yield control, wires it through agent-core and embedded sessions, documents and tests the SDK helper, and includes minor installer-test cleanup.

## Best Possible Solution

Rebase onto current main and define yield-capable tools as enforced scheduler barriers—preferably using the existing per-tool sequential execution seam—so later same-batch calls do not start after a tool yields, with explicit SDK documentation and a two-tool regression test.
