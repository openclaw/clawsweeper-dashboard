## Summary

The PR addresses a credible P1 agent-session recovery bug and its captured-generation approach is a narrowly scoped fit, but it still needs after-fix real behavior proof before merge. The provided evidence is focused Vitest, static checks, CI claims, and an autoreview report; it does not show a runtime recovery watchdog preserving a newly registered replacement run while the stale captured run is drained.

## What This Changes

The PR changes stuck-session recovery so it aborts, waits for, and force-clears only the originally captured embedded and reply-run generation rather than a replacement registered under the same session ID.

## System Context

The embedded agent runner tracks the active queue handle for each session, while the reply registry tracks the associated reply operation. Stuck-session recovery reads those registries, cancels stale work, waits for cleanup, and may force-clear it so the session can recover without affecting later work.
