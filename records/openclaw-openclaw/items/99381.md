## Summary

Keep open. The feature is useful and the previous CI blockers are fixed, but the latest head still has a source-reproducible auth-owner bug: a custom configured default agent can inherit a main-store profile, pass the owner check, and then report removal even though the write path only updates the selected agent store.

## What This Changes

The PR adds `openclaw models auth remove` for explicit or guarded provider-wide model auth profile deletion, plus auth-store pruning helpers, CLI registration, docs, and tests.

## Best Possible Solution

Fix the owner-store check so inherited profiles are either rejected or removed from the actual persisted owner store, then land the command if maintainers accept the destructive auth CLI contract.

## Reproduction Assessment

Yes, source-level. With a configured default agent that is not the main auth store, the list/remove path can see an inherited main-store profile, pass the default-agent owner check, and then write only the selected agent store.

## Solution Assessment

No, not as-is. The `models auth` boundary and auth-store helper reuse are right, but the owner check must be based on the actual persisted store owner instead of the configured default agent id.
