## Summary

Keep open: current main and the latest release still contain the unsafe answered-call `realtime` dereference, and the only direct fix PR is closed unmerged.

## What This Changes

The issue reports that answered voice-call conversation calls crash when `config.realtime` is omitted because the manager path reads `this.config.realtime.enabled` without guarding the optional config object.

## Best Possible Solution

Land a narrow voice-call manager guard plus regression coverage, then add redacted answered-call logs or a maintainer proof note if real-provider reachability remains impractical.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level, but not as a live provider run. If `CallManager` handles `call.answered` with `config.realtime` absent, current main dereferences undefined; normal config resolution usually supplies the object, so real setup reachability remains unproven.

## Solution Assessment

Yes, the narrow maintainable fix is optional chaining at the manager read plus focused answered-call regression coverage. A broader config migration is not indicated unless live proof identifies a shipped legacy config source that bypasses normalization.
