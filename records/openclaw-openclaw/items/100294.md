## Summary

Keep open: current main and the latest release still contain the unsafe `this.config.realtime.enabled` read in the voice-call answered-call path, and the only direct fix PR is closed unmerged. ## What This Changes

The issue asks for voice-call answered conversation calls to tolerate an omitted `realtime` config object instead of throwing before the initial greeting/listening path starts.

## Best Possible Solution

Land a narrow optional guard plus regression test in the voice-call manager path, with redacted live answered-call logs or an explicit proof note if maintainers require reachability proof.
