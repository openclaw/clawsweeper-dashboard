## Label Justifications

- `P1`: A released Telegram channel workflow can deliver model-produced links that navigate to the wrong destination for real users.
- `impact:message-loss`: The delivered Telegram message can lose the intended URL query separator semantics, so the user receives a corrupted actionable link.

## Summary

Keep open. Current main and the latest release still route Telegram markdown/rich output through linkification plus a renderer that HTML-escapes every text segment, so the reported bare-URL ampersand corruption remains source-reproducible and no canonical Telegram fix was found.

## What This Changes

The issue reports Telegram HTML/rich message rendering corrupting bare URLs with ampersand query separators by displaying or navigating them as `&amp;`, causing taps to open the wrong destination.

## Best Possible Solution

Fix the Telegram/markdown rendering boundary so auto-linked bare URL labels preserve navigable query separators while href attributes remain safely escaped, with regression tests and live Telegram proof.

## Reproduction Assessment

Yes by source inspection: current main linkifies Telegram markdown and then escapes every rendered text slice, including auto-linked bare URL text. I did not perform a live Telegram tap test in this read-only review, so final acceptance should include real-client proof.

## Solution Assessment

No, the current implementation is not the best behavior because it lets URL text escaping affect the user-visible/navigable destination. The best fix is a narrow renderer or Telegram link-text change that preserves HTML safety without corrupting bare URL query separators.
