## Summary

Keep open: current main still excludes aborted Bedrock prompt attempts from the prompt-failover path, and the open core fix at https://github.com/openclaw/openclaw/pull/99608 has not merged yet. This issue should close only after that PR or an equivalent current-main fix lands.

## What This Changes

The issue asks OpenClaw to recover Bedrock Converse stream aborts in long-context agent sessions by retrying or falling back instead of losing the run and transcript state.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99608 or an equivalent core fix that preserves intentional aborts while allowing replay-safe provider-originated Bedrock prompt aborts to use existing model fallback.

## Reproduction Assessment

Yes, at source level: current main still requires !aborted before prompt failover, while the reported trajectory has promptError=true and aborted=true. I did not run a fresh live AWS Bedrock long-stream reproduction in this read-only review.

## Solution Assessment

Yes. The narrowest maintainable solution is to route only replay-safe provider-originated prompt aborts through the existing model fallback path, as the open core fix PR attempts, rather than adding new config or a broad retry layer.
