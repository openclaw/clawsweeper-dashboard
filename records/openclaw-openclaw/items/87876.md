## Summary

Keep open: current main still bypasses prompt failover when the reported Bedrock prompt error also marks the attempt aborted, and the open closing PR has not merged yet.

## What This Changes

Recover long Bedrock Converse Streaming agent sessions by retrying or failing over on replay-safe provider aborts instead of ending with lost work.

## Best Possible Solution

Land a narrow core fix that lets replay-safe provider prompt aborts enter the existing fallback chain while preserving external abort, timeout, and unsafe replay guards.

## Reproduction Assessment

Yes at source level, but I did not run a live AWS reproduction here. The issue includes production logs for `promptError` plus `aborted: true`, and current main still requires `!aborted` before prompt failover can run.

## Solution Assessment

Yes, the linked core fix direction is the best current path because it reuses the existing model fallback chain with replay-safety guards. A Bedrock-local retry alone would not address the generic runner gate that currently suppresses fallback for this abort envelope.
