## Summary

The maintainer-approved doctor-first migration direction is valid, but the unchanged head still removes shipped flat-aware behavior from the public `channel-outbound` resolver family, which can silently break external plugins whose own schemas legitimately use flat streaming fields. The PR also still lacks contributor-posted real upgrade proof, so it is not ready to merge.

## What This Changes

The PR removes six flat streaming-key fallbacks from shared runtime and plugin SDK resolvers, adds doctor migrations and strict schemas for nested-streaming channels, and updates related tests, docs, and generated config metadata.

## Best Possible Solution

Keep the approved doctor-owned migration and nested-only bundled runtime, while preserving the existing flat-aware exported resolvers or adding separately named nested-only helpers for bundled callers plus an external-plugin compatibility test.
