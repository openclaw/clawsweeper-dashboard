## Summary

Keep open: current main and v2026.6.11 still let multiple Feishu accounts in the same group resolve the same durable group session key, so the reported bot identity/session mixup remains source-reproducible and needs maintainer-owned migration/security direction.

## What This Changes

The issue reports Feishu multi-bot group sessions being keyed only by group identity instead of bot application/account identity, causing bot identity mixups and shared session state.

## Best Possible Solution

Define a maintainer-approved Feishu account/app-scoped group conversation contract, add migration or doctor handling for existing group sessions, and prove fresh-install plus upgrade behavior with focused tests and redacted live multi-bot Feishu evidence.
