## Label Justifications

- `P1`: The reported Feishu multi-bot group workflow can route mentions through one durable bot session/account boundary, affecting real multi-bot users.
- `impact:session-state`: Multiple Feishu bot applications in one group can share or collide on the same group session identity.
- `impact:security`: Replies and context can cross configured bot/application account boundaries and appear under the wrong identity.
- `impact:message-loss`: Messages addressed to one bot can be handled by the wrong bot session, producing misrouted or effectively lost replies.

## Summary

Keep open: current main and v2026.6.11 still build durable Feishu group sessions from chat/topic/sender identity without a bot app or account discriminator, so the reported same-group multi-bot identity collision remains a valid session, delivery, and security-boundary bug.

## What This Changes

The issue asks Feishu group sessions to distinguish bot application/account identity when multiple Feishu bot apps are installed in the same group.

## Best Possible Solution

Adopt a maintainer-approved Feishu group session identity that includes a stable bot/account boundary, plus upgrade-safe doctor or migration handling, regression tests, and live multi-bot Feishu proof.
