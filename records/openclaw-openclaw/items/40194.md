## Summary

Keep open: current main and v2026.6.11 still omit a Feishu bot/app/account discriminator from group session identity, so the multi-account support now present does not fully solve the reported multi-bot group session collision.

## What This Changes

Report that multiple Feishu bots in the same group can share one durable group session/account boundary, causing mentions to one bot to run under another bot's session.

## Best Possible Solution

Add a maintainer-approved Feishu group session identity that includes a stable bot/account boundary, plus upgrade-safe doctor or migration handling, regression tests, and live multi-bot Feishu proof.

## Reproduction Assessment

Yes, from source inspection rather than a live Feishu run. Current main still builds Feishu group peer ids from chat/topic/sender only, and the generic group session key omits accountId/appId.

## Solution Assessment

Unclear: the requested group+app discriminator is the right class of fix, but maintainers still need to choose the stable Feishu identity and migration path before changing durable session keys.
