## Summary

Keep open: current main and v2026.6.11 still build Feishu group session identity from group/topic/sender peer data while accountId/appId stay outside the durable non-direct session key, so the reported same-group multi-bot identity collision remains source-reproducible and needs maintainer direction before repair.

## What This Changes

The issue reports that multiple Feishu bot apps in one group share the same durable group session/account identity, causing replies to come from the wrong bot persona.

## Best Possible Solution

Define a maintainer-approved Feishu account/app-scoped group conversation contract, add migration or doctor handling for existing group sessions, and prove fresh-install plus upgrade behavior with focused tests and redacted live multi-bot Feishu evidence.
