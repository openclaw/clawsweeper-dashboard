## Label Justifications

- `P1`: The reported Feishu multi-bot group workflow can route mentions through the wrong durable bot session/account boundary for real users.
- `impact:session-state`: Multiple Feishu bot applications in one group can share or collide on one group session identity.
- `impact:security`: A response can cross bot/application account boundaries and appear under the wrong configured identity.
- `impact:message-loss`: Messages addressed to one Feishu bot can be handled by the wrong bot session, producing misrouted replies.

## Summary

Keep open: current main and v2026.6.11 still build Feishu group session identity from group/topic/sender data without a bot app or account discriminator, so the reported multi-bot group collision remains valid.

## What This Changes

The issue reports Feishu group sessions shared across multiple bot apps because durable group session keys are scoped by group/topic/sender but not by bot app/account.

## Best Possible Solution

Adopt a maintainer-approved Feishu group session identity that includes a stable bot/account boundary, with upgrade-safe doctor or migration handling, regression tests, and live multi-bot Feishu proof.
