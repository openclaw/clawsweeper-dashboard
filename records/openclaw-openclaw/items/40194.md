## Label Justifications

- `P1`: The reported Feishu multi-bot group workflow can route all mentions through one durable bot session/account boundary.
- `impact:session-state`: Multiple Feishu bot applications in one group can share or collide on one persisted group session identity.
- `impact:security`: Replies and state can cross configured Feishu bot application/account boundaries and appear under the wrong identity.
- `impact:message-loss`: Messages addressed to one bot can be handled by the wrong bot session, producing misrouted or suppressed replies.

## Summary

Keep open: current main and v2026.6.11 still omit a Feishu bot/app/account discriminator from durable group session identity, so multi-bot Feishu groups can still share the same group session and reply under the wrong account boundary.

## What This Changes

The issue requests Feishu group sessions to distinguish multiple bot applications in the same group so each @mentioned bot uses its own session and identity.

## Best Possible Solution

Adopt a maintainer-approved Feishu group session identity that includes a stable bot/account boundary, with upgrade-safe doctor or migration handling, focused regression tests, and redacted live multi-bot Feishu proof.
