## Summary

Keep open: current main still passes Feishu account identity into routing but drops account/app identity from durable non-direct session keys, so the reported multi-bot Feishu group session collision remains unresolved.

## What This Changes

The issue reports that multiple Feishu bot apps in one group share one group session identity, causing replies and context to use the wrong bot/account persona.

## Best Possible Solution

Adopt a maintainer-approved Feishu group session identity that includes a stable account/app boundary, with doctor or migration handling for existing accountless group sessions and focused regression/live proof.
