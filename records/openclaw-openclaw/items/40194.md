## Label Justifications

- `P1`: A real Feishu multi-bot group workflow can route messages through the wrong session/account identity for active channel users.
- `impact:session-state`: Multiple Feishu bot identities in one group can share one agent session key, mixing conversation context and route state.
- `impact:security`: Wrong-account session reuse can cross bot/persona boundaries and cause one bot to answer with another bot's context or identity.
- `impact:message-loss`: Messages addressed to one Feishu bot may be misrouted or suppressed in same-group multi-bot setups.

## Summary

Keep open: current main and v2026.6.11 still drop account/app identity from Feishu non-DM group session keys, while the related open mention-recognition work does not resolve this persistent session-boundary bug.

## What This Changes

The issue requests Feishu group sessions for multiple bot apps in the same group to be separated by bot app/account identity so mentions route to the intended bot persona and session.

## Best Possible Solution

Define a Feishu-owned account/app-scoped group and topic session contract, add doctor or migration handling for existing unscoped group sessions, and require proof that target bots respond while non-target bots stay quiet.
