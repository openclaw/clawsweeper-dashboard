## Summary

Keep open: current main and v2026.6.11 still build Feishu group sessions from group/topic/sender peer data while accountId/appId only affect route matching and direct-message key scopes, so the multi-bot same-group collision remains source-reproducible.

## What This Changes

Feishu multi-bot group messages should keep bot/account session identity separate when several Feishu applications are in the same group.

## Best Possible Solution

Define a maintainer-approved Feishu account/app-scoped group conversation contract, add migration or doctor handling for existing group sessions, update docs/tests, and prove fresh-install plus upgrade behavior with redacted live multi-bot Feishu evidence.
