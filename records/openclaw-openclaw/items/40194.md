## Label Justifications

- `P1`: The reported Feishu multi-bot group workflow can route all mentions through one durable bot session/account boundary.
- `impact:session-state`: Multiple Feishu bot applications in one group can share or collide on one persisted group session identity.
- `impact:security`: Replies and state can cross configured Feishu bot application/account boundaries and appear under the wrong identity.
- `impact:message-loss`: Messages addressed to one bot can be handled by the wrong bot session, producing misrouted or suppressed replies.

## Summary

Keep open: current main still builds durable Feishu group session identity from chat/topic/sender while carrying accountId only as routing metadata, so multiple Feishu bot apps in one group can still share one persisted group session and reply across the wrong account boundary.

## What This Changes

Request to isolate Feishu group sessions by bot application/account so multiple Feishu bots in one group do not share one session or identity.

## Best Possible Solution

Adopt a maintainer-approved Feishu group session identity that includes a stable bot/account boundary, with upgrade-safe doctor or migration handling, regression tests, and redacted live multi-bot Feishu proof.
