## Label Justifications

- `P1`: The reported Feishu multi-bot group workflow can route all mentions through one durable bot session/account boundary.
- `impact:session-state`: The issue is about multiple Feishu bot applications sharing or colliding on one group session identity.
- `impact:security`: A reply can cross bot/application account boundaries and appear under the wrong configured identity.
- `impact:message-loss`: Messages addressed to one bot can be handled by the wrong bot session, producing misrouted replies.

## Summary

Keep open: current main and v2026.6.11 still build Feishu group session identity from group/topic/sender data without a bot app or account discriminator, so the reported multi-bot group session collision remains a valid session-state, message-routing, and security-boundary issue.

## What This Changes

The issue asks OpenClaw to distinguish Feishu group sessions by group plus bot application or account identity so multiple Feishu robots in one group do not share the same session.

## Best Possible Solution

Adopt a maintainer-approved Feishu group session identity that includes a stable bot/account boundary, with upgrade-safe doctor or migration handling, regression tests, and live multi-bot Feishu proof.
