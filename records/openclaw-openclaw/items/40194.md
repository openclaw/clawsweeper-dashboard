## Label Justifications

- `P1`: The issue can route group replies across the wrong Feishu bot/account boundary in an active multi-bot channel workflow.
- `impact:security`: The reported collision crosses bot/app/account identity boundaries in shared Feishu group conversations.
- `impact:message-loss`: Messages can be handled by the wrong Feishu bot session instead of the mentioned or bound bot identity.
- `impact:session-state`: Multiple Feishu bot accounts in one group can share one durable group session key and mixed context.

## Summary

Keep open: current main still passes Feishu account identity into routing but drops account/app identity from the durable group session key, so the multi-bot Feishu group collision remains unresolved.

## What This Changes

The issue asks OpenClaw to distinguish Feishu group sessions by both group and bot app/account identity so multiple bots in the same group do not share one durable session.

## Best Possible Solution

Adopt a maintainer-approved Feishu group session identity that includes a stable account/app boundary, with doctor or migration handling for existing group sessions and focused tests.
