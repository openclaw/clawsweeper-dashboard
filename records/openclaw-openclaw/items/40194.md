## Summary

Keep open: current main and v2026.6.11 still build Feishu group session identity from chat/topic/sender data without a bot app or account discriminator, so the reported multi-bot group session collision remains a valid session-state, message-routing, and security-boundary issue.

## What This Changes

The issue reports Feishu group sessions colliding when multiple bot apps share one group because session identity is keyed by group rather than group plus bot application/account identity.

## Best Possible Solution

Adopt a maintainer-approved Feishu group session identity that includes a stable bot/account boundary, with upgrade-safe doctor or migration handling, regression tests, and live multi-bot Feishu proof.
