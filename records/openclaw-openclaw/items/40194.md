## Summary

Keep open: current main and v2026.6.11 still derive Feishu group session identity from chat/topic/sender data and the shared non-direct session key shape omits accountId/appId, so the reported multi-bot group session collision remains valid.

## What This Changes

The issue requests Feishu group sessions to distinguish multiple bot applications in the same group instead of sharing one group-scoped session.

## Best Possible Solution

Adopt a maintainer-approved Feishu group session identity that includes a stable account/bot boundary, with upgrade-safe doctor or migration handling, regression tests, and live multi-bot Feishu proof.
