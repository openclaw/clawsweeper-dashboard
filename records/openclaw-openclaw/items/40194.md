## Summary

Keep open: current main still carries Feishu group route accountId separately but builds non-DM group session keys without account/app identity, so same-group multi-bot sessions can still collide and need a maintainer-approved migration/security decision.

## What This Changes

The issue reports Feishu group chats with multiple bot applications sharing one session/account identity because group session routing is not scoped by Feishu app or account.

## Best Possible Solution

Adopt a Feishu-owned account/app-scoped group session contract with migration or doctor repair for existing state, then validate same-group multi-bot routing with focused tests and redacted live Feishu proof.
