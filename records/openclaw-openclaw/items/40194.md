## Label Justifications

- `P1`: The report describes a real multi-bot Feishu group workflow where messages can route through the wrong bot session and identity.
- `impact:session-state`: The central failure is durable Feishu group session identity collapsing multiple bot accounts in one group.
- `impact:security`: Wrong bot identity and shared context can expose one bot/account's conversation state to another bot in the same group.
- `impact:message-loss`: Misrouted @mentions can cause the intended Feishu bot not to handle the message correctly.

## Summary

Keep open: current main and v2026.6.11 still make Feishu group session keys from agent, channel, group/topic/sender peer identity without account/app identity, so multi-bot same-group sessions can still collide even though account-aware binding routing exists.

## What This Changes

The issue requests Feishu group sessions distinguish multiple bot apps in the same group so @mentions do not share one durable session/account identity.

## Best Possible Solution

Define a canonical Feishu group conversation identity that separates bot accounts/apps, migrate or intentionally preserve existing group sessions, and validate with focused tests plus redacted live multi-bot Feishu proof.

- **Document Current Limitation:** Leave group sessions shared across Feishu accounts and document that same-group multi-bot setups need separate agents/groups until a broader identity design lands.
