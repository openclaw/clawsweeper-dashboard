## Label Justifications

- `P1`: A real Feishu multi-bot group workflow can route all mentions through one durable bot session/account boundary.
- `impact:session-state`: The issue is about multiple Feishu bot applications sharing or colliding on one group session identity.
- `impact:security`: A reply can cross bot/application account boundaries and appear under the wrong configured identity.
- `impact:message-loss`: Messages addressed to one bot can be handled by the wrong bot session, producing misrouted replies.

## Summary

Keep open: current main still builds Feishu group session identity from chat/topic/sender data while the shared non-direct session key shape omits accountId/appId, so the reported multi-bot group session collision remains valid and security-sensitive.

## What This Changes

Feishu group messages addressed to different bot applications should route to isolated bot/account sessions instead of sharing one durable group session.

## Best Possible Solution

Adopt a maintainer-approved Feishu group session identity that includes a stable bot/account boundary, with upgrade-safe doctor or migration handling, regression tests, and live multi-bot Feishu proof.
