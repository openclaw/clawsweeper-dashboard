## Summary

Keep open: current main and v2026.6.11 still build Feishu group sessions from agent + channel + group/topic/sender identity, while accountId/appId only participate in account routing and not the durable group session key. The reported multi-bot same-group identity collision remains source-reproducible and needs maintainer-owned session/account migration direction before a fix PR is safe.

## What This Changes

The issue reports that multiple Feishu bots in the same group share one group session keyed only by group identity, causing replies and account identity to mix across bots.

## Best Possible Solution

Define a maintainer-approved Feishu account/app-scoped group conversation contract, add migration/doctor handling for existing group sessions, and prove fresh-install plus upgrade behavior with focused tests and redacted live multi-bot Feishu evidence.
