## Label Justifications

- `P1`: The reported Feishu multi-bot group workflow can route mentions through the wrong durable bot session/account boundary for real users.
- `impact:session-state`: Multiple Feishu bot applications in one group can share or collide on one group session identity.
- `impact:security`: A reply can cross bot/application account boundaries and appear under the wrong configured identity.
- `impact:message-loss`: Messages addressed to one Feishu bot can be handled by another bot session, producing misrouted replies.

## Summary

Keep open: current main and v2026.6.11 still build Feishu group session identity from chat/topic/sender data while the generic group session-key shape omits accountId/appId, so the reported multi-bot group session collision remains a valid session-state, message-routing, and security-boundary issue.

## What This Changes

The issue requests Feishu group sessions to distinguish multiple bot applications/accounts in the same group so each @mention routes to the correct bot identity and session.

## Best Possible Solution

Adopt a maintainer-approved Feishu group session identity that includes a stable bot/account boundary, plus upgrade-safe doctor or migration handling, regression tests, and live multi-bot Feishu proof.
