## Summary

Keep open: current main and v2026.6.11 still derive Feishu group sessions from group/topic/sender peer data while accountId/appId only affect routing context and direct-message key scopes, so the same-group multi-bot session collision remains source-reproducible.

## What This Changes

The issue reports that multiple Feishu bot apps in one group share a group session key, causing @mentions to different bots to run under the same account/session identity.

## Best Possible Solution

Define a maintainer-approved Feishu account/app-scoped group conversation contract, add migration or doctor handling for existing group sessions, update docs/tests, and prove fresh-install plus upgrade behavior with redacted live multi-bot Feishu evidence.
