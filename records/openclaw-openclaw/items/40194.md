## Summary

Keep open: current main and v2026.6.11 still build Feishu group session keys without account/app identity, while the fix changes persistent session and bot-identity boundaries that need maintainer-approved migration and security handling.

## What This Changes

The issue reports that multiple Feishu bot apps in one group can share one group-scoped OpenClaw session key, causing @mentions to route through the wrong bot/account identity.

## Best Possible Solution

Define a Feishu-owned account/app-scoped group and topic session contract, add doctor or migration handling for existing unscoped group sessions, and prove target and non-target multi-bot behavior.
