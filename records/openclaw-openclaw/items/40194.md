## Label Justifications

- `P1`: The reported Feishu multi-bot group workflow can route all mentions through one durable bot session/account boundary.
- `impact:session-state`: Multiple Feishu bot applications in one group can share or collide on a single group session identity.
- `impact:security`: Replies and context can cross Feishu bot application/account boundaries and appear under the wrong configured identity.
- `impact:message-loss`: Messages addressed to one bot can be handled by the wrong bot session, producing misrouted or suppressed replies.

## Summary

Keep open: current main and the latest release still build Feishu group session identity from chat/topic/sender only, while Feishu multi-account bot setups are documented, so the reported multi-bot session/account collision remains a valid session, delivery, and security-boundary bug.

## What This Changes

Feishu group chats with multiple bot applications should keep bot/account sessions isolated so mentioning one bot does not route through another bot's session.

## Best Possible Solution

Adopt a maintainer-approved Feishu group session identity that includes a stable bot/account boundary, with upgrade-safe migration or doctor handling, regression tests, and redacted live multi-bot Feishu proof.
