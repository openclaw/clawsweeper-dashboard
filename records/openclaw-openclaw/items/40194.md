## Label Justifications

- `P1`: A real Feishu multi-bot group workflow can route addressed messages through one shared durable session/account boundary.
- `impact:session-state`: Multiple Feishu bot applications in one group can collide on one persisted group session identity.
- `impact:security`: State and replies can cross configured Feishu bot application/account boundaries.
- `impact:message-loss`: Messages addressed to one bot can be handled by the wrong bot session or suppressed by the wrong account context.

## Summary

Keep open: current main still builds Feishu group session identity from group/topic/sender data while storing the active account only as route metadata, so multiple Feishu bot accounts in one group can share one durable session and overwrite the account boundary.

## What This Changes

The issue requests Feishu group sessions to be keyed by both group and bot/app/account identity so different bots in one group do not share one session.

## Best Possible Solution

Make Feishu group session identity account/app-aware at the plugin/routing boundary with an explicit migration or doctor repair plan and regression coverage for same-group multi-account routing.
