## Label Justifications

- `P1`: The reported Feishu multi-bot group workflow can route all mentions through one durable bot session/account boundary, breaking a real channel workflow.
- `impact:session-state`: Multiple Feishu bot applications in one group can share or collide on one group session identity.
- `impact:security`: A reply can cross bot/application account boundaries and appear under the wrong configured identity.
- `impact:message-loss`: Messages addressed to one bot can be handled by the wrong bot session, producing misrouted or effectively lost replies.

## Summary

Keep open: current main and the latest v2026.6.11 release still build Feishu group session identity from chat/topic/sender peer data while keeping accountId separate from the durable group session key, so the reported multi-bot group identity collision remains valid.

## What This Changes

The issue reports Feishu group chats with multiple OpenClaw bot applications sharing one durable group session/account identity instead of isolating replies by the addressed bot app or account.

## Best Possible Solution

Adopt a maintainer-approved Feishu group session identity that includes a stable bot/account boundary, with upgrade-safe doctor or migration handling, regression tests, and live multi-bot Feishu proof.
