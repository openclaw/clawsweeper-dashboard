## Label Justifications

- `P1`: The reported Feishu multi-bot group workflow can route mentions through one durable bot session/account boundary.
- `impact:session-state`: Multiple Feishu bot applications in one group can share or collide on one persisted group session identity.

- `impact:message-loss`: Messages addressed to one bot can be handled by the wrong bot session, producing misrouted or suppressed replies.

## Summary

Keep open: current main and v2026.6.11 still omit a Feishu bot/app/account discriminator from durable group session identity, so multi-bot Feishu groups can still share one group session and reply across the wrong account boundary.

## What This Changes

The issue reports Feishu group chats with multiple bot apps sharing the same durable group session and replying under the wrong bot identity.

## Best Possible Solution

Adopt a maintainer-approved Feishu group session identity that includes a stable bot/account boundary, with upgrade-safe doctor or migration handling, focused regression tests, and redacted live multi-bot Feishu proof.

Unclear. The requested group-plus-app discriminator is the right class of fix, but the best implementation needs a maintainer-approved discriminator and migration or doctor plan before changing durable session keys.
