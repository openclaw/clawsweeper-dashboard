## Label Justifications

- `P1`: A real Feishu multi-bot group workflow can route mentions through the wrong durable bot session/account boundary.
- `impact:session-state`: The issue is about multiple Feishu bot applications sharing or colliding on one group session identity.
- `impact:security`: A reply can cross configured bot/application account boundaries and appear under the wrong identity.
- `impact:message-loss`: Messages addressed to one bot can be handled by the wrong bot session, producing misrouted replies.

## Summary

Keep open: current main and v2026.6.11 still scope Feishu group session identity to chat/topic/sender rather than bot account/app identity, so the reported multi-bot group collision remains source-reproducible and needs maintainer direction.

## What This Changes

Feishu multi-bot group sessions should distinguish bot application/account identity so @mentions of different robots do not share one session or reply as the wrong bot.

## Best Possible Solution

Adopt a maintainer-approved Feishu group session identity that includes a stable account/bot boundary, with upgrade-safe doctor or migration handling, regression tests, and live multi-bot Feishu proof.
