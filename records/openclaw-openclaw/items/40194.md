## Label Justifications

- `P1`: The reported Feishu multi-bot group workflow can route mentions through the wrong durable bot session/account boundary.
- `impact:session-state`: Multiple Feishu bot apps in one group can share or collide on one group session identity.
- `impact:security`: The collision can cross bot/application account boundaries and reply under the wrong configured identity.
- `impact:message-loss`: Messages addressed to one bot can be handled by another bot session, producing misrouted replies.

## Summary

Keep open: current main and v2026.6.11 still build Feishu group session identity from chat/topic/sender without a bot app or account discriminator, so the multi-bot group collision remains source-reproducible.

## What This Changes

The issue asks OpenClaw to isolate Feishu group sessions for multiple bot apps in the same group instead of sharing one group-only session key.

## Best Possible Solution

Add a maintainer-approved Feishu group session identity that includes a stable bot/account boundary, plus upgrade-safe doctor or migration handling, focused regression tests, and live multi-bot Feishu proof.

## Reproduction Assessment

Yes, at source level: current main builds Feishu group peers from chat/topic/sender only, and generic non-direct session keys omit accountId/appId. I did not run a live Feishu tenant with multiple bot apps.

## Solution Assessment

No implemented fix is present. The issue's appId-suffixed key is plausible, but the best fix must choose the durable discriminator and migration path before changing persisted session identity.
