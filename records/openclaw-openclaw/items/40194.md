## Label Justifications

- `P1`: The issue can route active Feishu group replies through the wrong bot/account session in a real multi-bot channel workflow.
- `impact:session-state`: Multiple Feishu bot accounts in one group can share one durable group session key and mix conversation context.
- `impact:security`: The reported collision crosses bot app/account identity boundaries in shared Feishu group conversations.
- `impact:message-loss`: Messages can be handled by the wrong Feishu bot session instead of the mentioned or bound bot identity.

## Summary

Keep open: current main still carries Feishu account identity into routing but drops account/app identity from Feishu group conversation ids and the durable non-DM session key, so multiple Feishu bot apps in one group can still share group session state and reply context.

## What This Changes

Request that Feishu group chats with multiple bot apps isolate sessions by group plus app/account identity so separately mentioned bots do not share one session.

## Best Possible Solution

Adopt a maintainer-approved Feishu group session identity that includes a stable account/app boundary, with doctor or migration handling for existing accountless group sessions and focused tests across groupSessionScope modes.
