## Summary

Keep open. Current main has the active/non-streaming admission slice, but the documented and implemented behavior is still boundary steering rather than the requested pause-or-abort, inject, and resume soft-steer lifecycle.

## What This Changes

The issue requests true mid-stream soft steering so a user message can pause or abort an active generation or tool phase, enter context immediately, and resume with the new input.

## Best Possible Solution

Keep this as the broad soft-steer tracker until maintainers land or reject a lifecycle design covering pause/abort/resume semantics, fallback behavior, transcript ordering, backend failures, Codex steer/interrupt boundaries, and channel ingress.

## Reproduction Assessment

Yes, at source level: current main drains steering at model/tool boundaries and does not implement a pause-or-abort, partial-output capture, and resume lifecycle. I did not run a live channel replay in this read-only review.

## Solution Assessment

No, current main is only a partial solution. The best path needs maintainer-approved lifecycle semantics that preserve tool-result pairing and transcript ordering while deciding interrupt/resume, fallback, admission, and security behavior.
