## Summary

Keep open: current main includes the partial active/non-streaming steering fix from the merged Telegram/Codex work, but it still documents and implements boundary-based steering rather than the requested pause-or-abort, inject, and resume lifecycle.

## What This Changes

Request true mid-stream soft-steer behavior so a user message can pause or abort an active generation, enter context immediately, and resume with the new instruction.

## Best Possible Solution

Keep this issue as the broad product/runtime tracker, finish the narrower active-run admission fixes separately, and design true soft-steer behavior with explicit lifecycle, fallback, and upgrade semantics.
