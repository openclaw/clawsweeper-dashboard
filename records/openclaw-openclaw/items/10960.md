## Summary

Keep open: current main has partial active-run and active-non-streaming steering fixes, but it still implements boundary-based steering plus separate interrupt rather than the requested pause-or-abort, inject, and resume soft-steer lifecycle.

## What This Changes

Request true mid-stream soft steering that pauses or aborts an active generation/tool wait, injects the user message into context, and resumes with awareness of the new input.

## Best Possible Solution

Keep this as the broad product/runtime tracker, land the narrower active-run admission fixes separately, and design any true soft-steer behavior as an explicit lifecycle with fallback and upgrade semantics.
