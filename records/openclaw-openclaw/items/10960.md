## Summary

Keep open: current main has improved active-run steering for some non-streaming handles, but it still implements boundary-based steering/fallback rather than the requested pause-or-abort, inject, and resume lifecycle, and the remaining behavior needs maintainer product/runtime review.

## What This Changes

Request true mid-stream soft steering so a new user message can interrupt active generation or long tool work, enter context immediately, and let the agent resume with that input.

## Best Possible Solution

Define a maintainer-approved soft-steer contract first, then implement it across embedded and reply-run paths with explicit abort/resume, partial-output, backend rejection, fallback, and regression-test semantics.
