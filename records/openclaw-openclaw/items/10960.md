## Summary

Keep open. Current main has a partial active-run steering admission fix, but the requested true soft-steer lifecycle still is not implemented: steering remains boundary-based and does not pause or abort an in-flight generation/tool phase, inject user input, and resume with captured context.

## What This Changes

The issue requests mid-stream soft steering that can pause or abort active generation, inject new user input into context, and resume with awareness of the new input.

## Best Possible Solution

Keep boundary steering as the current contract, resolve the narrower ingress bug separately, and add true soft-steer only after maintainers define opt-in abort/capture/inject/resume semantics with docs and regression coverage.

Rationale: The requested behavior changes when active runs may be interrupted, how partial assistant output and tool results are preserved, and which session context receives injected input; current code and docs intentionally define boundary steering plus a separate interrupt mode.

Options:

- **Design opt-in soft steer (recommended):** Define a new mode or policy for abort/capture/inject/resume semantics, with tests for streaming, tools, Codex turn/steer, fallback, and transcript state.
- **Keep boundary steering only:** Close or narrow the broader soft-steer direction and use https://github.com/openclaw/openclaw/issues/48003 for remaining boundary-steering ingress bugs.
- **Change steer globally:** Make existing steer more aggressive by default, accepting compatibility risk for users who expect tool-boundary behavior.

## Reproduction Assessment

Yes, at source level: current docs and the agent loop show boundary steering and explicit non-interruption of in-flight tools, while the requested pause-or-abort, inject, and resume lifecycle is not present. I did not run a live channel reproduction for this read-only review.

## Solution Assessment

Unclear as an implementation, because this asks for a product-level lifecycle change rather than a single code defect. The safest solution is an opt-in design that preserves current boundary steering unless maintainers intentionally change the default.
