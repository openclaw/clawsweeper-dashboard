## Summary

Keep open: current main has useful partial steering fixes, but it still implements boundary-based steering and fallback rather than the requested pause-or-abort, inject, and resume soft-steer lifecycle. The remaining work is a product/runtime decision, with narrower active-run admission work tracked separately.

## What This Changes

The issue requests true soft steering that interrupts or pauses an active generation, injects the new user message into context, and resumes with awareness of the new input.

## Best Possible Solution

Keep this as the broad product/runtime tracker, finish the narrower active-run admission fixes separately, and design true soft steer as an explicit lifecycle with documented fallback, backend, and upgrade semantics.

Options:

- **Design Opt-In Soft Steer (recommended):** Add a separate explicit mode or command for pause-or-abort, inject, and resume semantics with lifecycle, fallback, and backend-compatibility tests.
- **Keep Boundary Steering:** Treat current boundary-based steering as the supported default and limit follow-up work to messages reaching the existing queue policy.
- **Broaden Default Steer:** Change default steer to stronger interruption semantics only after maintainer-approved upgrade proof across channels and runtimes.
