## Summary

Keep open: current main has a partial active-run steering admission fix, but the requested true soft-steer lifecycle still remains boundary-based and needs maintainer product/runtime design before this can close.

## What This Changes

Requests a soft-steer behavior that can pause or abort active generation, inject new user input into context, and resume with the new input instead of waiting for the next boundary.

## Best Possible Solution

Keep this as the broad soft-steer product/runtime tracker, reconcile the narrower active-run ingress work, and only close after maintainers approve and document the pause-or-boundary lifecycle semantics.

## Reproduction Assessment

Yes. At source level, docs and packages/agent-core show queued steering drains at runtime/model boundaries rather than true mid-generation pause, injection, and resume; I did not run a live channel replay in this read-only review.

## Solution Assessment

No, current main is only a partial solution. The active/not-stopped admission fix is useful, but the best solution still needs maintainer-approved lifecycle semantics plus the remaining ordinary-message ingress work.
