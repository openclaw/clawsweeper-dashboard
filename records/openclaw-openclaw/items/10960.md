## Summary

Keep open: current main has partially improved active non-streaming steer admission, but it still implements boundary-based steering rather than the requested pause-or-abort, inject, and resume soft-steer lifecycle. The latest release predates the partial fix, and narrower related work remains open for active-run ingress and product/runtime semantics.

## What This Changes

Request true mid-stream soft steering so user guidance can interrupt active generation or long tool phases, enter context immediately, and resume with that input.

## Best Possible Solution

Keep this as the broad soft-steer product/runtime tracker and resolve it through a maintainer-approved lifecycle design that documents and tests streaming, active non-streaming/tool execution, abort/resume, fallback, backend rejection, and transcript ordering.

## Reproduction Assessment

Yes, at source level for the current limitation: current main drains steering at supported runtime boundaries and docs say it does not abort in-flight tools. The full pause-or-abort/resume behavior is a requested feature, not an existing behavior contract.

## Solution Assessment

No, current main is not the full requested solution. PR https://github.com/openclaw/openclaw/pull/98126 is a useful partial fix, but the maintainable path still needs an explicit soft-steer lifecycle design rather than another isolated admission patch.
