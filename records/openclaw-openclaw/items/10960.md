## Summary

Keep open. Current main has improved active-run steering ingress for active non-streaming runs, but the requested true soft-steer lifecycle still is not implemented: steering is documented and coded as boundary delivery, not pause-or-abort, inject, and resume mid-generation or mid-tool execution.

## What This Changes

The issue requests a new soft-steer behavior that can interrupt an active generation or long tool phase, inject the user's latest message into context, and resume without waiting for the next runtime boundary.

## Best Possible Solution

Define an explicit soft-steer lifecycle, preferably opt-in at first, with documented semantics for stream abort, tool execution, partial transcript capture, queued context insertion, resume behavior, fallback, and regression coverage across embedded-runner and reply-run registry paths.
