## Summary

Keep open. Current main has the active/non-streaming steer admission slice, but this issue asks for a broader soft-steer lifecycle that pauses or aborts in-flight work, injects context immediately, and resumes with documented semantics; that behavior is still not implemented and the remaining work overlaps open canonical follow-up.

## What This Changes

Request true soft-steer behavior that can pause or abort an in-flight generation or tool wait, inject the new user message, and resume with updated context.

## Best Possible Solution

Keep this issue as the broad soft-steer product/runtime tracker until maintainers land or explicitly reject pause-or-abort/resume semantics, ordinary-message admission follow-up, and docs/tests for the chosen lifecycle contract.

## Reproduction Assessment

Yes, at source level: current docs and agent-loop code show steering drains at runtime/model boundaries and does not abort in-flight tools. I did not run a live channel replay in this read-only review.

## Solution Assessment

No, current main is only a partial solution. The best path is maintainer-approved lifecycle semantics that preserve tool-result pairing and transcript ordering while deciding interrupt/resume, fallback, admission, and security behavior.
