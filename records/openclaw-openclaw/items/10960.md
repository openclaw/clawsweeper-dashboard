## Summary

Keep open: current main has a useful active-run steering partial fix, but the documented behavior is still boundary-based and does not implement the requested pause-or-abort, inject, and resume soft-steer lifecycle.

## What This Changes

Request true soft-steer behavior that can pause or abort active generation/tool work, inject a user message into context, and resume with the new input.

## Best Possible Solution

Keep this issue as the broad product/runtime tracker, finish narrower active-run admission fixes separately, and design any true soft-steer behavior with explicit lifecycle, fallback, and upgrade semantics.

Options:

- **Design Opt-In Soft Steer (recommended):** Add a separate mode or command for pause-or-abort, inject, and resume semantics with coverage for partial output, tool calls, backend rejection, and fallback.

- **Finish Narrow Admission First:** Land or replace the PR 89238-style ordinary-message admission fix before deciding whether true pause/resume soft steer belongs in core.
