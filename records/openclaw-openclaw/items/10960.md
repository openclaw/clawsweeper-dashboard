## Summary

Keep open: current main has partial active non-streaming steering admission, but it still implements boundary-based steering rather than the requested pause-or-abort, inject, and resume soft-steer lifecycle.

## What This Changes

Request true mid-stream soft steering so user messages can interrupt or redirect an active generation or long tool phase without waiting for the current turn to finish.

## Best Possible Solution

Keep this issue as the broad soft-steer tracker and resolve it through a maintainer-approved lifecycle design with docs and tests for streaming, tool execution, abort/resume, backend rejection, transcript ordering, and ordinary-message ingress.

## Reproduction Assessment

Yes, at source level for the current limitation: current main drains steering at supported runtime boundaries and docs say it does not interrupt an already-running tool call. The full pause-or-abort/resume behavior is a requested feature rather than an existing behavior contract.

## Solution Assessment

Unclear as a concrete implementation plan. The requested direction is valid, but the maintainable fix needs an explicit soft-steer lifecycle design rather than another isolated admission patch.
