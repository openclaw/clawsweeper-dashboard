## Summary

Keep this issue open: current main supports active-run steering at safe runtime boundaries, including active non-streaming phases, but it still does not implement the requested transparent abort, immediate context injection, partial-output preservation, and context-aware continuation lifecycle; the remaining behavior requires an explicit product decision.

## What This Changes

Add a soft-steer mode that interrupts an active generation, injects new user input into its context, and resumes the task without discarding prior progress.

## Best Possible Solution

Add an explicit, capability-negotiated soft-interrupt mode that preserves existing boundary-based steer defaults, defines partial-output and tool-side-effect handling, commits the new user turn exactly once, and falls back visibly when a runtime cannot safely continue.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add an opt-in soft-interrupt lifecycle that aborts the active model operation, commits any safe partial state, injects the new user message, and starts a context-aware continuation, or keep steering limited to runtime boundaries plus explicit run replacement?

Rationale: Current steer and interrupt modes deliberately provide different safety guarantees; combining them changes transcript semantics, tool-side-effect handling, provider compatibility, and the meaning of an existing default queue mode.

Likely owner: steipete

Owner reason: This person supplied the existing product-level review and has adjacent lifecycle history spanning the affected runtime and reply surfaces.

Owner confidence: high

Options:

- **Add opt-in soft interrupt (recommended):** Introduce a distinct capability-negotiated mode with explicit partial-output, tool-side-effect, transcript, fallback, and continuation semantics while leaving existing steer behavior compatible.
- **Keep current mode split:** Retain boundary-only steer and explicit interrupt as separate operations, documenting that transparent continuation is not supported.
- **Redefine steer globally:** Make existing steer abort and continue immediately where possible, accepting a compatibility change for users relying on safe-boundary delivery.

## Reproduction Assessment

Yes, at source level: current documentation and runtime paths explicitly provide boundary steering or full interruption, not transparent abort, injection, and context-aware continuation. No live run is needed to establish that product gap.

## Solution Assessment

No, the issue's implementation sketch is not yet the best specified solution because polling, arbitrary stream abort, and synthetic resume prompting do not define transcript or tool-side-effect safety. A distinct capability-negotiated mode is safer than silently redefining the current steer default.
