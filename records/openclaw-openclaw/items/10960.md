## Summary

Keep open: current main improves active-run steering, but this issue asks for a stronger soft-steer lifecycle that pauses or aborts active work, injects user input, and resumes; current docs and source still define boundary-based steering plus a separate interrupt mode.

## What This Changes

Request true mid-stream soft steering that pauses or aborts an active generation/tool phase, injects the new user message into context, and resumes generation with that input.

## Best Possible Solution

Keep this as the broad product/runtime tracker, land or retire the narrower admission fixes separately, and design any soft-steer mode as an explicit lifecycle with fallback, partial-output, backend rejection, and upgrade semantics.
