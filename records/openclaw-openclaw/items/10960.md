## Label Justifications

- `P2`: The issue describes meaningful runtime and channel UX work, but the remaining work is a product-level lifecycle feature rather than an emergency outage or narrow regression fix.
- `impact:session-state`: Soft steering would change how partial assistant output, injected user input, tool results, and active session context are associated within a run.
- `impact:message-loss`: The reported failure mode is user steering input arriving too late to affect the active turn it was meant to redirect.

## Summary

Keep open: current main has partial active-run steering fixes, but it still implements documented boundary steering rather than the requested true pause-or-abort, inject, and resume soft-steer lifecycle.

## What This Changes

The issue requests a new soft-steer behavior that can interrupt an in-progress agent response, inject a user correction, and resume with the added context.

## Best Possible Solution

Preserve documented boundary steering as the default, land or close narrower active-run ingress fixes through their own trackers, and add true soft-steer only after maintainers define opt-in abort/capture/inject/resume semantics with provider, Codex, transcript, and channel proof.

- **Design Opt-In Soft Steer (recommended):** Add a new explicit mode or policy for abort/capture/inject/resume while keeping current boundary steering as the default.
- **Keep Boundary Steering Only:** Decide that steer remains a model-boundary feature and close or narrow the broad soft-steer request after active-run ingress issues are resolved.
- **Change Steer Globally:** Make existing steer more aggressive by default, accepting compatibility risk for workflows that depend on current boundary behavior.

## Reproduction Assessment

Yes, at source level: current docs and agent-loop code show steering is delivered at runtime/model boundaries, not by aborting an in-flight generation and resuming with injected context. I did not run live channel proof for this read-only review.

## Solution Assessment

Unclear as an implementation, because this issue asks for a product-level lifecycle contract rather than one broken code path. The safer maintainable direction is an opt-in soft-steer design while preserving current boundary steering and tracking narrower active-run ingress fixes separately.
