## Label Justifications

- `P2`: The request has clear user impact for steering active agent work, but it is a feature/product lifecycle change with current boundary-steer and interrupt workarounds rather than an urgent regression.
- `impact:session-state`: Soft steering would change how active session context, partial assistant output, tool results, and late user input are associated with one run.
- `impact:message-loss`: The reported failure mode is user steering input arriving too late to affect the active turn it was intended to redirect.

## Summary

Keep open. Current main partially fixes active-run steering admission, but true soft-steer remains unimplemented because current docs and the core loop still wait for runtime/model boundaries instead of pausing or aborting, injecting input, and resuming with explicit partial-output semantics.

## What This Changes

Request true soft-steer so user input sent during active generation or tool work can interrupt or pause the run, enter context, and resume immediately with the new constraint.

## Best Possible Solution

Maintain boundary steering as the current contract, resolve narrower active-run ingress separately, and add true soft-steer only after maintainers define an opt-in abort/capture/inject/resume lifecycle with transcript, provider, tool, and fallback semantics.
