## Label Justifications

- `P2`: The request has clear user value and runtime impact, but it is a product-level enhancement with partial boundary-steering behavior already present and narrower regressions tracked separately.
- `impact:session-state`: Soft steering would change how partial assistant output, injected user input, tool results, and active session context are associated with one run.
- `impact:message-loss`: The reported failure mode is user steering input arriving too late to affect the active turn it was meant to redirect.

## Summary

Keep open: current main has documented boundary steering and a partial active non-streaming admission fix, but it still does not implement true pause/abort, inject, and resume soft-steer semantics.

## What This Changes

Request true soft-steer behavior that pauses or aborts an active generation, injects the user's message into context, and resumes with that input instead of waiting for the next runtime boundary.

## Best Possible Solution

Preserve documented boundary steering, resolve the narrower active-run ingress tracker separately, and add true soft-steer only after maintainers define opt-in abort/capture/inject/resume semantics with transcript, tool-result, fallback, and provider-harness coverage.
