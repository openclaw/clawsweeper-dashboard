## Label Justifications

- `P2`: Immediate redirection during long agent work is a meaningful improvement, but shipped interrupt mode provides a bounded path and this is not an emergency.
- `impact:session-state`: The unresolved requirement is whether partial assistant and tool state must survive interruption and resume.
- `impact:ux-friction`: Boundary-only steering can force users to wait or explicitly select interrupt mode when they need to correct an active task.

## Summary

Current releases provide explicit abort-and-next-turn interruption, but they do not establish the stronger checkpoint-and-resume behavior requested here; an open linked implementation PR also means this issue should remain open until maintainers define the intended contract and resolve that PR path.

## What This Changes

Add soft steering that interrupts an active generation, injects the newest user message, and continues with updated session context.

## Best Possible Solution

Keep `steer` as safe-boundary injection and define `interrupt` as the explicit immediate-redirection contract: retain the newest user message, abort and drain the active run, then start the next turn in the same session with documented partial-output semantics and cross-backend coverage.
