## Summary

Keep this issue open: current main supports same-turn steering at runtime boundaries and a separate abort-and-replace operation, but it still does not preserve an interrupted generation and resume it with newly injected context. The merged delivery improvements and the narrower open ingress regression do not supersede this broader lifecycle request.

## What This Changes

Requests pausing or aborting an active generation, injecting a new user message into context, and resuming the generation with awareness of that input.

## Best Possible Solution

Define a capability-gated interrupted-turn continuation contract covering partial-output persistence, tool-state handling, injected-input ordering, and fallback to boundary steering or abort-and-replace.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw support preserving and resuming an interrupted turn after injecting new user input, beyond its current boundary-steering and abort-and-replace contracts?

Rationale: Current main intentionally separates safe same-turn boundary injection from cancellation and replacement; combining them creates a new cross-runtime transcript, tool, and provider lifecycle that cannot be selected mechanically.

Likely owner: steipete

Owner reason: The current product boundary, queue-steering history, and existing issue review make steipete the strongest available owner for this lifecycle decision.

Owner confidence: high

Options:

- **Design resumable soft steer (recommended):** Specify provider-neutral partial-output, tool-state, capability, continuation, and fallback semantics before implementation.
- **Keep current contracts:** Retain boundary steering plus abort-and-replace and explicitly document that an interrupted generation is not resumed.
- **Limit to native runtimes:** Offer resumable behavior only for harnesses that expose a proven native interrupted-turn continuation protocol.

## Reproduction Assessment

Yes. Current source, docs, and the Codex contract show boundary steering and abort-and-replace, but no path that preserves and resumes the interrupted generation with the new message.

## Solution Assessment

No. The proposed polling and prompt-reconstruction hypothesis is not the best established solution; a formal capability-based interrupted-turn lifecycle built on the existing queue and abort seams is safer and more maintainable.
