- `P2`: The issue is a meaningful runtime enhancement with clear user impact, but the remaining work is a product-level lifecycle design rather than an emergency outage or narrow regression fix.
- `impact:session-state`: Soft steering would change how partial assistant output, injected user input, tool results, and active session context are associated with one run.
- `impact:message-loss`: The reported failure mode is user steering input arriving too late to affect the active turn it was meant to redirect.

## Summary

Keep open. Current main implements boundary steering and a partial active non-streaming admission fix, but it still does not implement the requested true soft-steer lifecycle: pause or abort an in-flight generation, inject the user message, and resume with that context.

## What This Changes

The issue requests mid-stream soft steering so user messages can redirect an active generation instead of waiting for the next runtime boundary or later turn.

## Best Possible Solution

Preserve documented boundary steering as the default, resolve the narrower active-run ingress tracker separately, and add true soft-steer only after maintainers define opt-in abort/capture/inject/resume semantics with transcript, tool-result, fallback, Codex, embedded-runtime, and channel proof.

Yes, at source level: current docs and the agent loop show steering is delivered at runtime/model boundaries, not by aborting an in-flight generation and resuming with injected context. I did not run a live channel reproduction for this read-only review.
