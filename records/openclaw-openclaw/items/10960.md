## Label Justifications

- `P2`: This is a meaningful runtime/channel UX feature with partial fixes on main, but it is not an emergency or first-run blocker.
- `impact:session-state`: Soft steering changes when user guidance enters the active run context and how the agent resumes from that state.
- `impact:message-loss`: The user-visible problem is that guidance intended for the active turn can be delayed into a later follow-up or miss the intended decision point.

## Summary

Keep open: current main has a partial active/non-streaming steering fix, but the requested true soft-steer lifecycle still remains boundary-based and the narrower ordinary-message ingress work is still open.

## What This Changes

Request true mid-stream soft steering so a user message can interrupt or pause an active generation/tool run, enter context immediately, and let the agent resume with that input.

## Best Possible Solution

Keep this as the broad soft-steer product tracker and resolve it through maintainer-approved lifecycle semantics plus the narrower active-run ordinary-message ingress work.

## Reproduction Assessment

Yes, at source level: current docs and the agent loop still define steering at model/runtime boundaries and explicitly do not abort in-flight tools, which does not satisfy true mid-stream pause/abort and resume.

## Solution Assessment

No, current main is only a partial solution. The best path is a maintainer-approved lifecycle design that preserves boundary steering compatibility while adding a deliberate soft-steer or interrupt-resume behavior.
