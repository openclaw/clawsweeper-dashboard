## Summary

Keep this issue open because current main still does not provide the requested transparent pause-or-abort, immediate injection, and context-aware continuation lifecycle. The narrower boundary-steering regression remains separately tracked, while the linked implementation candidate has not landed.

## What This Changes

Add soft steering that interrupts an active generation, incorporates new user input immediately, and continues with the existing task context.

## Best Possible Solution

Define one canonical interrupt-and-continue lifecycle that persists usable partial output, fences or cancels in-flight work, injects the new message, and resumes through shared run-state machinery; keep restoration of existing boundary steering scoped to https://github.com/openclaw/openclaw/issues/48003.

## Maintainer Decision

Kind: product_direction

Question: Should soft steer terminate the current model turn and start a context-preserving follow-up, or guarantee transparent continuation of the same logical run after partial output and tool state are checkpointed?

Rationale: These options create materially different transcript, cancellation, tool-side-effect, backend, and user-experience contracts, so permanent behavior requires maintainer intent.

Likely owner: vincentkoc

Owner reason: Recent history and replacement work are closest to the active-run lifecycle and non-streaming steering boundary.

Owner confidence: high

Options:

- **Abort and preserve context (recommended):** End the current model turn cleanly, persist usable partial output, and immediately start a new turn containing the steering message.
- **Resume the same run:** Checkpoint and resume the same logical run across generation and tool execution, accepting substantially broader runtime complexity.
- **Keep boundary steering:** Limit steer to documented safe model or tool boundaries and retain immediate interruption as a separate explicit abort action.

## Reproduction Assessment

Yes, at source level: send another user message while a run is generating or executing a long tool and observe that it reaches only supported steering boundaries or a later follow-up. A live current-main run would still help quantify provider-specific timing, but the contract gap is explicit.

## Solution Assessment

No, the proposed polling and generic checkpoint design is not yet the best implementation shape. The narrow maintainable approach is one shared lifecycle contract with explicit partial-output, cancellation, tool-side-effect, transcript, and fallback semantics.
