## Summary

Keep open: current main contains the source-side reply-session fixes, but the stable npm `latest` and GitHub stable release remain `v2026.6.11`, and the packed npm artifact still ships stale bundled store-writer code without reentrant writer support.

## What This Changes

The issue reports that the `v2026.6.11` npm package ships stale bundled store-writer code, so reply-session initialization can still conflict and drop messages despite fixed source on main.

## Best Possible Solution

Publish a patched stable package from the fixed source and add release/tarball parity coverage that fails when bundled dist lacks the reentrant store-writer path.

## Reproduction Assessment

Yes for the shipped artifact: `npm pack openclaw@2026.6.11` shows the bundled store-writer queue lacks `AsyncLocalStorage` and `reentrant` handling while npm `latest` still points at that version. This is not a current-main source failure because current main already has the reentrant path.

## Solution Assessment

Yes. The narrow durable fix is a patched stable release built from fixed source plus a tarball parity guard; local dist hot-patching or retry-budget tweaks are only workarounds.
