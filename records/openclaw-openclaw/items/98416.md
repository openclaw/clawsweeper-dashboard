## Summary

Keep open: current main contains the source-side reply-session fixes, but the latest stable release is still v2026.6.11 and the inspected npm tarball still ships the stale bundled store-writer queue that caused the reported released-artifact failure.

## What This Changes

The issue reports that the published OpenClaw v2026.6.11 npm dist lacks the reply-session store-writer reentrancy plumbing present in source, causing reply-session initialization conflicts and dropped channel messages.

## Best Possible Solution

Ship or promote a stable package built from the fixed source, then add a tarball parity guard so release checks fail when bundled dist lacks the reentrant store-writer and reply-session commit path.

## Reproduction Assessment

Yes for the released artifact: inspecting the openclaw@2026.6.11 npm tarball shows the bundled store-writer queue lacks AsyncLocalStorage and reentrant handling, matching the reported source-vs-dist divergence. It is not a current-main source failure because current main already contains the fixed code path.

## Solution Assessment

Yes, the best fix is release/package parity: ship a stable package from the fixed source and add a tarball guard for the reentrant store-writer/reply-init path. A local dist hot patch or a source-only close would not solve the reported npm latest artifact problem.
