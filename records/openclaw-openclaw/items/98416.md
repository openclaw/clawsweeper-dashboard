## Summary

Keep open: current main has the source-side session initialization fixes, but the latest stable GitHub release and npm `latest` still point to `v2026.6.11`, and the downloaded npm tarball still contains a stale `store-writer-queue` bundle without reentrant writer support.

## What This Changes

The issue reports that the published `openclaw@2026.6.11` package drops the reply-session reentrancy guard, causing `reply session initialization conflicted` errors and message loss across channels.

## Best Possible Solution

Publish a stable package that includes the current source-side session writer and reply-init fixes, then add a package/tarball parity guard so future releases cannot ship stale dist for this path.

## Reproduction Assessment

Yes. I did not run a live chat repro, but the npm tarball inspection reproduces the package-level defect: the latest stable package lacks the reentrant writer implementation that current source now has, and the issue discussion includes multiple live channel logs with the same error.

## Solution Assessment

Yes for the source fix, but not complete for the issue. The right end state is release/package parity plus a package artifact guard, because another source-only PR would not repair users already installing the stale stable artifact.
