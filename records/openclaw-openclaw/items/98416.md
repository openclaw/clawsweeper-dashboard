## Summary

Keep open: current main contains the source-side reply-session fixes, but npm `latest` is still `2026.6.11` and the published stable tarball still carries the stale pre-reentrancy `store-writer-queue` bundle. The remaining work is release/package parity, not another ordinary source fix PR.

## What This Changes

The issue reports that the published v2026.6.11 npm artifact shipped stale bundled store-writer code, leaving reply-session reentrancy ineffective and causing reply-session initialization conflicts.

## Best Possible Solution

Cut or promote a stable package release built from the fixed source, then add a release/tarball parity guard that fails if bundled dist lacks the reentrant store-writer path.

## Reproduction Assessment

Yes. The released artifact is directly inspectable: `openclaw@2026.6.11` contains a 72-line `store-writer-queue` bundle with no `AsyncLocalStorage` or `reentrant` handling, while current source contains that support.

## Solution Assessment

Yes. The narrow maintainable fix is to ship the fixed source in a new stable package and add tarball parity coverage; local dist hot-patching is only an operational workaround.
