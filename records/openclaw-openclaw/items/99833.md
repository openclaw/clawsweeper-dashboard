## Summary

Keep open: current main still preserves raw rich HTML tables under the rich-message column limit, has separate rich-to-plain fallback branches across Telegram send surfaces, and the protected `maintainer` label blocks conservative cleanup closure.

## What This Changes

The issue requests canonical Telegram rich HTML normalization for raw tables and literal whitespace, plus one shared rich-to-plain fallback policy across Telegram send surfaces.

## Best Possible Solution

Implement one Telegram-plugin normalizer/fallback boundary used by durable send, bot delivery, and draft streaming so raw tables either become the canonical rich grid or a logged plain/preformatted fallback, with literal whitespace normalization outside code/pre contexts.
