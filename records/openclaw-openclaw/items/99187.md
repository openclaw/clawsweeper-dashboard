## Summary

Keep open for maintainer review: the source path and Node fork contract support the bug fix, and the latest head addresses the prior blank-PATH executable concern, but the fallback from a stale Gateway executable to an ambient PATH Node is compatibility-sensitive upgrade behavior that maintainers should explicitly accept or narrow before merge.

## What This Changes

This PR resolves a usable Node executable before forking the local embedding worker, preferring the current process executable, then a Homebrew stable symlink, then a filtered PATH lookup, with focused helper tests.

## Best Possible Solution

Land the worker fork fix once maintainers explicitly accept the filtered PATH fallback, or narrow the fallback to Homebrew stable paths before merge.

## Reproduction Assessment

Yes at source level: current main omits execPath in the worker fork, and Node's fork implementation defaults that executable to process.execPath. The PR body also includes terminal before/after output, but this review did not run a live Homebrew upgrade reproduction.

## Solution Assessment

Mostly yes: the fix belongs at the worker fork boundary, and the latest head filters blank PATH entries. The generic PATH fallback remains a compatibility policy choice that maintainers should explicitly own before merge.
