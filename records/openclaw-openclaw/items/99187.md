## What This Changes

The PR adds a synchronous embedding-worker executable resolver that passes an explicit `execPath` to the local embedding worker fork, preferring the current executable, then Homebrew stable symlinks, then PATH.

## Best Possible Solution

Land a worker-path fix after adding focused stale-execPath regression coverage and redacted real Gateway or equivalent worker proof for the after-upgrade path.

## Reproduction Assessment

Yes at source level. Current main omits `execPath` in the worker fork, and Node's `fork()` defaults to `process.execPath`, matching the stale Homebrew Cellar ENOENT report.

## Solution Assessment

Not merge-ready yet. The resolver is an acceptable fix at the right fork boundary, but it needs checked-in stale-execPath coverage and stronger after-fix worker proof before it is the best maintainable solution.
