## Summary

Keep this PR open, but it is not merge-ready: the linked bug is valid, yet this patch uses ambient PATH lookup instead of the existing deterministic Homebrew Cellar-to-symlink pattern and only provides unit-test output rather than real behavior proof.

## What This Changes

The PR adds local embedding-worker executable resolution that checks `process.execPath`, searches PATH for `node` when it is missing, and passes that result as `execPath` to `fork()`.

## Best Possible Solution

Resolve stale Homebrew Cellar `process.execPath` values to the stable opt/bin symlink before any PATH fallback, add focused worker regression coverage, and include redacted real Gateway or equivalent terminal proof.

## Reproduction Assessment

Yes at source level. Current main omits `execPath` at the worker `fork()` call, and Node's fork implementation defaults that executable to `process.execPath`, matching the linked Homebrew stale-Cellar failure.

## Solution Assessment

No. The PR is a plausible mitigation, but the best fix should first resolve the stale Cellar path to OpenClaw's stable Homebrew symlink pattern instead of relying on ambient PATH.
