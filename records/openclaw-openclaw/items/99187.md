## Summary

Keep this PR open: current main still has the stale `process.execPath` worker-fork bug, and the latest branch fixes the earlier blank-PATH executable-selection issue. The remaining concern is maintainer acceptance of the compatibility-sensitive PATH fallback when the Homebrew stable path is unavailable.

## What This Changes

This PR adds a synchronous executable resolver for local embedding worker forks, preferring the current executable, then a Homebrew stable symlink, then filtered PATH Node, with helper tests.

## Best Possible Solution

Land the worker fork fix once maintainers explicitly accept the fallback policy, or narrow the fallback to Homebrew stable paths before merge.

## Reproduction Assessment

Yes at source level: current main omits execPath in the worker fork, and Node's fork implementation defaults to process.execPath. The PR body also includes terminal before/after output, but I did not run a live Homebrew upgrade reproduction.

## Solution Assessment

Mostly yes: the fix belongs at the worker fork boundary, and the latest head filters blank PATH entries. The generic PATH fallback remains a compatibility policy choice that maintainers should explicitly own before merge.
