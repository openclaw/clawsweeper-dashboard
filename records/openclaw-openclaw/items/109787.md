## Summary

Keep this PR open but do not merge the current head: the new distinct-string fallback makes a single-value watermark non-monotonic for noncanonical IDs, so an older same-timestamp message can be accepted again and replace a newer watermark. Likely related people: @vincentkoc, with medium confidence from recent cross-channel replay and session-state work.

## What This Changes

The PR restricts numeric watermark ordering to canonical non-negative decimal message IDs, uses `bigint` for those comparisons, and adds focused regression coverage.

## Best Possible Solution

Keep canonical decimal IDs on an exact numeric path, but give equal-timestamp noncanonical IDs a genuinely monotonic representation—such as tracking all observed IDs at the maximum timestamp—or obtain explicit owner approval for another stable ordering, with forward, duplicate, restart, and out-of-order replay tests.
