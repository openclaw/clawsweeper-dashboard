## Summary

Keep this PR open: the new lexical fallback prevents a watermark from moving backward, but it can still suppress an unseen same-timestamp message when opaque and decimal ID formats are mixed, so the ordering contract needs an owner decision before merge.

## What This Changes

The branch changes ambient transcript and Telegram history watermark comparison to use `bigint` ordering only for canonical decimal IDs and lexical ordering otherwise, with focused regression tests.

## Best Possible Solution

Define the generic same-timestamp opaque-ID contract first, then preserve every unseen entry by using a source ordering key where available or a latest-timestamp seen-ID representation rather than lexical ordering across ID formats.
