## Summary

This PR remains open because the current head still carries the previously identified timeout-eligibility mismatch: active-memory raises the default deadline from the configured runtime route before the embedded runner proves that subscription-auth CLI dispatch is actually eligible. The core bug and live proof are credible, but the timeout behavior can still change for API-key, missing-backend, or otherwise non-dispatched runs, so the patch is not ready to merge as written.

## What This Changes

The PR adds opt-in subscription-auth CLI backend dispatch for active-memory embedded runs, grant-scoped loopback MCP tools, transcript mirroring, and a 45-second Claude CLI recall timeout default.

## Best Possible Solution

Use one shared eligibility result for both timeout selection and embedded CLI dispatch, so only runs that will actually execute through the fresh Claude CLI process receive the 45-second default while explicit operator timeouts and all passthrough paths remain unchanged.
