## Label Justifications

- `P1`: The PR addresses a reproduced agent-memory workflow failure and unintended metered billing risk for subscription-only Claude CLI users.
- `merge-risk: 🚨 compatibility`: The patch adds an embedded-run parameter and PluginRuntime method while placing provider-specific eligibility policy behind a potentially lasting core API contract.

- `merge-risk: 🚨 availability`: Eligible recalls switch to fresh CLI processes with a longer default deadline, which can materially affect latency and runtime process pressure.

## Summary

Keep open: the patch is technically strong and proof-positive, but merge should wait for an explicit maintainer decision on whether subscription-dispatch eligibility belongs in generic core code or Anthropic-owned CLI backend metadata.

## What This Changes

The PR adds opt-in subscription-auth CLI backend dispatch for embedded runs, applies it to active-memory recall, scopes loopback MCP tools, mirrors transcripts, and conditionally increases the recall timeout.

## Best Possible Solution

Keep the generic embedded CLI-dispatch, transcript, and server-side MCP enforcement machinery, but express subscription-dispatch eligibility as an Anthropic-owned CLI backend capability that core consumes generically before landing the active-memory opt-in.
