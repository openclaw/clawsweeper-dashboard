## Label Justifications

- `P1`: The PR addresses a reproducible auth-routing failure that disables active-memory recall or can unexpectedly consume metered billing for subscription-only Claude CLI users.
- `merge-risk: 🚨 compatibility`: The patch changes the effective default recall timeout and introduces a new embedded execution path that can alter latency and lifecycle behavior for existing configurations.
- `merge-risk: 🚨 auth-provider`: The patch changes credential-sensitive routing between direct provider API execution and Claude subscription CLI execution, which directly controls billing and rejection behavior.
- `merge-risk: 🚨 security-boundary`: The new CLI path executes tools through an MCP loopback grant under potentially permissive CLI modes, making correct server-side tool restriction a merge-critical boundary.

## Summary

Keep this PR open: the latest live proof demonstrates a successful subscription-only recall and the earlier lane-admission concern is fixed, but the conditional timeout default still changes API-key setups that remain on the embedded path, and the permanent core-versus-provider dispatch boundary needs owner confirmation.

## What This Changes

Adds opt-in subscription-auth CLI backend dispatch for active-memory helper runs, including grant-scoped MCP tools, transcript mirroring, route-sensitive timeout handling, and focused tests.

## Best Possible Solution

Use a generic, provider-owned CLI-backend capability to drive one canonical helper-dispatch decision, derive the active-memory timeout from the actual selected execution path, and retain the PR's server-enforced MCP grant and transcript-parity protections.
