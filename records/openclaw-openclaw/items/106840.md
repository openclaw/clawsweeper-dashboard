## Summary

The central bug is valid and the live proof is strong, but this head should not merge until dispatch eligibility preserves explicit per-run auth selection and a runtime owner approves whether Claude-specific eligibility belongs in core or in the provider/backend capability contract.

## What This Changes

Adds opt-in CLI-backend dispatch for subscription-auth embedded runs and uses it for active-memory recall with scoped MCP tools, transcript mirroring, and a longer eligible default timeout.

## Best Possible Solution

Keep one generic embedded-run dispatch path whose eligibility is declared by the CLI backend/provider capability, resolve it from the exact effective auth profile used for execution, and let active-memory consume that shared decision for routing and timeout budgeting.
