## Summary

Keep open. The PR is aimed at a real Feishu card-action field-loss bug, but the current branch only teaches the handler about the extra fields; live callbacks are still narrowed by the Feishu webhook parser before they can reach that handler, and the new JSON branch can also change command dispatch for existing cards that carry a command plus select/form metadata.

## What This Changes

The PR adds Feishu card-action `input_value`, `name`, `form_value`, `option`, and `options` fields to the handler type, emits a structured JSON message when those fields are present, and adds direct handler unit tests.

## Best Possible Solution

Refresh or replace the PR with a Feishu-plugin fix that preserves the raw fields at the parser boundary, keeps the existing command path stable, adds parser-through-dispatch regression tests, and includes redacted live Feishu proof.

## Reproduction Assessment

Yes, from source. The current raw Feishu card-action parser returns only `action.value` and `tag`, so the requested sibling fields cannot reach the handler; no live Feishu callback run was provided in this review.

## Solution Assessment

No. The handler-only approach is incomplete; the best fix must preserve fields in `parseFeishuCardActionEventPayload` and settle a command-preserving payload contract before merge.
