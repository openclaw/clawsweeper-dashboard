## Summary

Needs changes before merge: the agent-side receipt guard is a plausible fix for unsupported SMS delivery claims, but the current gateway projection still reads fields that real MessageReceipt objects do not expose at the top level, so gateway-routed SMS sends can lose verified status evidence.

## What This Changes

Adds current-turn SMS message delivery evidence extraction and guards embedded agent visible replies, streams, final payloads, retry carryover, and gateway send responses against unsupported delivery receipt claims.

## Best Possible Solution

Keep the agent-side guard, but derive sanitized gateway evidence from the actual MessageReceipt shape and add gateway-shaped coverage before maintainers decide whether to accept the visible-text compatibility tradeoff.

## Reproduction Assessment

Yes for source-level behavior: current main has no visible-reply receipt guard, and the current PR head shows a gateway SMS MessageReceipt would not populate the sanitized status evidence the guard requires. I did not run a live SMS send in this read-only review.

## Solution Assessment

No for the current head: the agent-side guard is the right owner-boundary fix, but the gateway support path now projects from fields real receipts do not have. A narrow sanitized projection helper plus gateway-shaped coverage is the safer repair.
