## Summary

Keep this PR open for maintainer review. The submitted boundary is conservative and the provided after-fix terminal proof shows the intended distinction: only a different, active reply run holding the exact session lock is silent; ended and uncorrelated owners still produce the normal failure. The remaining decision is whether that user-visible no-reply policy precisely matches the duplicate-report scope.

## What This Changes

The PR carries private reply-run ownership through session-lock acquisition, suppresses a duplicate timeout reply only for another active owner of the same session, adds regression coverage, and routes an existing Codex prewarm test into its full-suite shard.

## System Context

OpenClaw reply turns serialize writes to a session transcript with a file lock. When a competing turn times out, the reply error handler turns that failure into a user-visible terminal response; this PR adds ownership correlation so a known concurrent reply can finish without generating a second generic error.
