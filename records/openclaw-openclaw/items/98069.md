## Summary

Keep open: current main and v2026.6.11 still have Skill Workshop proposal storage, static scanning, apply-time write checks, rollback, CLI, Gateway, and agent-tool lifecycle actions, but no pre-apply runtime validation command/action/API. The request is useful but needs maintainer product/security direction because it would load or execute pending generated skill behavior before approval/apply.

## What This Changes

The issue requests an optional Skill Workshop runtime validation phase that can load a pending proposal, validate its tool schema, optionally invoke it with representative inputs, and record proposal health before apply.

## Best Possible Solution

Define a staged Skill Workshop validation contract in the shared service: start with load/discovery/schema smoke checks and proposal health reporting, then add invocation only behind an explicit sandbox and side-effect/test-oracle contract chosen by maintainers.

Options:

- **Stage smoke validation first (recommended):** Add load/discovery/schema validation and health reporting first, and defer real invocation until a sandboxed side-effect contract exists.
- **Allow sandboxed invocation:** Permit representative tool invocation only in an isolated runtime with explicit allowed side effects and proposal-provided or generated test oracles.
- **Fold into lifecycle contract first:** Keep this issue open as a concrete subtask but require the broader lifecycle contract in https://github.com/openclaw/openclaw/issues/98002 to define validation authority first.

## Reproduction Assessment

Not applicable: this is a feature request, not a broken existing-behavior bug. Source and release inspection confirm there is currently no `openclaw skills workshop test` command, no agent-tool test action, and no Gateway proposal runtime-test API.

## Solution Assessment

Unclear: pre-apply validation is directionally useful, but the invocation portion is not the best final shape until maintainers define sandboxing, side effects, and the test oracle. A safer MVP is load/discovery/schema validation first, with invocation deferred or tightly bounded.
