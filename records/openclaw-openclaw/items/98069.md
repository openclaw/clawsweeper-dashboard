## Summary

Keep open: current main and v2026.6.11 still lack a Skill Workshop pre-apply runtime validation command, agent action, or Gateway API, and the remaining work needs product/security direction because it may execute or simulate unapproved skill content before apply.

## What This Changes

The issue requests optional runtime validation for Skill Workshop proposals, including load/discovery checks and possible representative tool invocation before apply.

## Best Possible Solution

Define a bounded Skill Workshop validation contract first: load/discovery/schema smoke checks can be the safe MVP, while invocation and apply-blocking should wait for an explicit isolated execution and test-oracle model.

Options:

- **Staged load/schema MVP (recommended):** Add proposal load, discovery, and schema validation first, record skipped invocation status, and defer side-effecting invocation until a test-case/sandbox contract exists.

- **Keep manual runtime testing:** Leave Skill Workshop apply gated by static scan and human review only, and document that runtime behavior remains an operator proof step for now.
