## Summary

Keep open: current main and the latest release still lack a Skill Workshop pre-apply runtime validation command or shared runtime-test action, and the remaining work is security-sensitive product design rather than a narrow bug fix.

## What This Changes

The issue requests automated pre-apply runtime validation for Skill Workshop proposals, including skill discovery, schema validation, optional invocation, and proposal health reporting.

## Best Possible Solution

Define one shared Skill Workshop validation contract first: load/discovery/schema smoke checks can be the MVP, with isolated representative invocation added only after the side-effect and test-oracle boundaries are explicit across CLI, Gateway, and the agent tool.

Rationale: Executing or simulating pending skill behavior before apply changes the approval and side-effect boundary, and the repository cannot infer the acceptable sandbox/tool-policy contract from existing code.

Options:

- **Start with smoke-test validation (recommended):** Add a shared validation result for proposal loadability, registry discovery, and tool schema visibility, while marking invocation as skipped until a safe test-case contract exists.
- **Define sandboxed invocation now:** Require a fuller design for representative inputs, allowed tools, network/filesystem isolation, side-effect assertions, and override semantics before implementation begins.
- **Fold into lifecycle-contract work:** Keep this as a subtask of the broader Skill Workshop lifecycle-contract issue and implement runtime testing only after that contract has an owner-approved shape.

## Reproduction Assessment

Not applicable: this is a feature request, not a broken existing-behavior bug. Source and release inspection show there is currently no `openclaw skills workshop test` command, no `skill_workshop` test action, and no Gateway runtime-test proposal API.

## Solution Assessment

Unclear: pre-apply validation is useful, but arbitrary invocation is not the best first step until maintainers define the sandbox, side-effect, and test-oracle contract. A safer MVP is shared load/discovery/schema validation with invocation explicitly skipped unless safe representative input exists.
