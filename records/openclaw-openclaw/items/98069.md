## Summary

Keep open: current main and the latest release still lack a pre-apply Skill Workshop runtime validation command/action. The request is useful, but it needs maintainer product/security direction before implementation because proposal invocation can cross approval, sandbox, tool-policy, filesystem, network, and side-effect boundaries.

## What This Changes

Add an optional Skill Workshop runtime validation phase that loads proposed skills and, where safe, invokes them before apply.

## Best Possible Solution

Define one shared Skill Workshop proposal-health contract at the service boundary, start with load/discovery/schema validation, record skipped invocation when no safe test oracle exists, and expose the same result through CLI, Gateway, and the agent tool only after the side-effect boundary is explicit.

Unclear: pre-apply validation is directionally useful, but the proposed invocation phase is not yet the best final shape until maintainers define sandboxing, side-effect handling, and the test-oracle contract. A safer MVP is load/discovery/schema validation with explicit skipped invocation.
