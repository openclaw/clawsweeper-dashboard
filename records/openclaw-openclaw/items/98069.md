## Summary

Keep open: current main and the latest release still lack the requested Skill Workshop pre-apply runtime validation command/action/API. The work is useful, but it needs maintainer product and security direction because invoking or simulating pending skill behavior before apply changes the execution boundary.

## What This Changes

Request automated Skill Workshop runtime validation that loads a pending proposal, checks discoverability/schema, optionally invokes representative behavior, and records a pre-apply status.

## Best Possible Solution

Define a staged Skill Workshop validation contract first: load/discovery/schema checks as the safe MVP, with invocation only behind explicit sandbox, test-case, and side-effect rules shared by CLI, Gateway, and the agent tool.

Question: What pre-apply execution boundary should Skill Workshop runtime validation use for pending skill proposals?

Rationale: Running or simulating generated skill behavior before apply can cross approval, filesystem, tool-policy, and side-effect boundaries, so automation should not choose the permanent contract.

Likely owner: shakkernerd

Owner reason: The Skill Workshop proposal store, CLI, and Gateway lifecycle all trace to shakkernerd's feature-introduction commits.

Owner confidence: high

Options:

- **Stage load/schema validation first (recommended):** Add a shared runtime-validation service that checks proposal load, registry discovery, and schema visibility, while deferring invocation until a safe oracle and side-effect model exists.
- **Allow sandboxed invocation now:** Define proposal-provided or generated representative inputs plus strict sandbox/tool/network/filesystem limits before adding invoke and side-effect checks.
- **Fold into lifecycle-contract work:** Track this only as part of the broader Skill Workshop lifecycle contract so one artifact owns validation semantics and apply readiness.

Not applicable: this is a feature request rather than a broken existing-behavior bug. Source and release inspection confirm there is currently no `openclaw skills workshop test` command, agent-tool test action, or Gateway proposal runtime-test API.

## Solution Assessment

Unclear: pre-apply validation is directionally useful, but invocation is not yet the best final shape until maintainers define sandboxing, side-effect handling, and the test oracle. A safer MVP is load/discovery/schema validation first.
