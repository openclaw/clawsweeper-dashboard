## Summary

Keep open: current main still lacks pre-apply Skill Workshop runtime validation, and the request is not obsolete. The remaining decision is product/security direction because invoking pending skill behavior before apply crosses sandbox, tool-policy, filesystem, network, and side-effect boundaries.

## What This Changes

Request adding a Skill Workshop test phase that loads, exposes, and optionally invokes pending skill proposals before apply.

## Best Possible Solution

Define a staged core-owned validation contract first: add shared load/discovery/schema checks through the Skill Workshop service, CLI, Gateway, and agent tool, then allow invocation or side-effect tests only behind an explicit sandbox and test-case contract.
