## Summary

Current main still has the reported cross-generation race: stuck recovery resolves a session, but abort, drain waiting, and force-clear are keyed only by session ID and can act on a replacement run. The adjacent open PR only adds idle-zombie detection and does not repair this identity invariant, so this issue remains necessary and is suitable for a focused fix PR.

## What This Changes

Prevent stuck-session recovery from aborting, treating as drained, or clearing a newer embedded run that replaced the stale run under the same session ID.

## Best Possible Solution

Add a registry-owned captured run-generation operation whose abort, end wait, and force-clear all target the same identity, while preserving separate explicit current-session and global abort APIs for administrative callers.

## Reproduction Assessment

Yes. A deterministic current-main test can replace the registered handle after recovery selects the session and demonstrate that abort, session-only drain waiting, or force-clear crosses into the newer generation.

## Solution Assessment

No, not exactly as suggested. Handle equality is the correct invariant, but the complete fix must bind abort, drain notification, and force-clear to one captured run generation rather than adding guards to only two functions.
