## Summary

Keep open: current main and the latest release still pass Docker E2E default resource caps straight into Docker without a retry, and the linked fixing PR is open rather than merged.

## What This Changes

The issue asks Docker E2E helpers to retry once without only OpenClaw-injected default resource caps when Docker rejects those caps during container create/start.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/98579, or an equivalent narrow helper change, then close this issue after the fix is merged.

## Reproduction Assessment

Yes. The issue and follow-up comment provide a constrained-daemon path where plain `docker run` succeeds but resource-limited `docker run` fails, and current source inspection shows the helpers still inject those caps without retry.

## Solution Assessment

Yes. A helper-level retry that removes only OpenClaw-injected default caps after classified Docker resource-limit create/start failures is the narrowest maintainable fix; the manual env var is only a workaround.
