## What This Changes

The issue requests that Docker E2E helpers retry without only OpenClaw-injected default resource caps when Docker rejects those caps, while preserving ordinary Docker failures and cleaning failed container artifacts.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/98579, or an equivalent narrow helper change, so only OpenClaw-injected default caps are retried away while ordinary Docker failures still fail normally.

## Reproduction Assessment

Yes. The issue provides a high-confidence constrained-daemon path where plain docker run succeeds but resource-limited docker run fails, and source inspection confirms current main still injects those caps without retry.

## Solution Assessment

Yes. The narrow maintainable fix is a helper-level retry that removes only OpenClaw-injected default caps after a classified daemon resource-limit create/start failure; the manual environment variable remains a workaround, not a complete fix.
