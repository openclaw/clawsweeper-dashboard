## Summary

Keep open: current main and the latest release still pass Docker E2E default resource caps straight into Docker without retry, and the linked fixing PR is open rather than merged. The issue has live constrained-daemon proof, so it should close only after that PR or an equivalent fix lands.

## What This Changes

The issue asks Docker E2E helpers to retry once without OpenClaw-injected default Docker resource caps when a Docker daemon rejects those caps during container create/start.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/98579, or an equivalent narrow helper change, so only OpenClaw-injected default caps are retried away while ordinary Docker failures still fail normally.

## Reproduction Assessment

Yes. The issue and follow-up comment provide a high-confidence constrained-daemon path where plain `docker run` succeeds but resource-limited `docker run` fails, and source inspection confirms current main still injects those caps without retry.

## Solution Assessment

Yes. The narrow maintainable fix is to retry only after a Docker daemon resource-limit create/start rejection and remove only OpenClaw's injected default caps; the existing manual env var is a workaround, not enough automatic recovery for E2E lanes.
