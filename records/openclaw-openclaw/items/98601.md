## Summary

Keep open: current main and the latest release still pass default Docker resource caps directly into Docker without retry, and the linked fixing PR is open rather than merged. The issue is valid and should close only after that PR or an equivalent fix lands.

## What This Changes

The issue reports Docker E2E and package-backed Docker helper failures when Docker rejects OpenClaw's default `--memory`, `--cpus`, or `--pids-limit` controls.

## Best Possible Solution

Land a narrow helper-level retry that drops only OpenClaw-injected default resource caps for Docker resource-limit rejection, preserves ordinary Docker failures, safely cleans failed artifacts, and includes focused tests plus real constrained-Docker proof.

## Reproduction Assessment

Yes from source at medium confidence: current main injects default Docker resource caps and has no retry path, matching the provided constrained-host Docker error. I did not run a daemon with missing cgroup controllers in this read-only review.

## Solution Assessment

Yes in direction, but not complete through the current PR yet: the fix belongs in the Docker helper layer so all callers share retry semantics, while the open candidate PR still needs its review finding addressed and real host proof.
