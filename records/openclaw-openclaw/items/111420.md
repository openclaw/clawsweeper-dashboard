## Summary

This remains necessary: it is the active candidate fix for a deterministic cron state-loss bug, and the supplied real Gateway evidence plus focused coverage support the ownership approach. Keep it open for explicit maintainer review because it carries the protected `maintainer` label and introduces persisted cron/ledger ownership fields that need upgrade-safety confirmation before merge.

## What This Changes

The PR records durable run-generation and schedule/state ownership identities so an older cron execution cannot consume or overwrite a job edited, replaced, or rescheduled while that execution is active.

## Best Possible Solution

Land a single canonical ownership model only after maintainer review confirms forward and downgrade compatibility for cron-store and task-ledger records; retain the public-state stripping and the scheduled, manual, on-exit, and startup-recovery regression coverage.
