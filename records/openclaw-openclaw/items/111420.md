## Summary

Keep this PR open: its central ownership fix is useful and has substantial targeted coverage, but the current on-exit path can still drop a predecessor completion when the watched job is re-armed between terminal-state persistence and run admission. The `maintainer` label and assignment also require maintainer-controlled handling rather than cleanup closure.

## What This Changes

The PR adds durable cron run-generation, schedule, trigger, and state ownership snapshots so stale active-run completion and restart recovery cannot mutate a job that was edited, re-armed, or replaced.

## Best Possible Solution

Finalize an exited on-exit predecessor from its admitted snapshot in schedule-preserve mode while retaining any re-armed replacement schedule, then attach redacted final-head Gateway proof that covers the re-arm race and a restart after ownership-state persistence.

## Reproduction Assessment

Yes, from source: start an on-exit watcher, let it persist its terminal disable, re-enable or edit the job before `runOnExit` admission, then complete the watched process. The current expected-identity check rejects the predecessor and the watcher ignores the resulting `ran: false`.

## Solution Assessment

No: durable ownership is the right boundary, but rejecting a stale on-exit predecessor entirely is not the narrowest correct outcome. Preserve-mode finalization should retain the predecessor’s history and payload without consuming the newer schedule.
