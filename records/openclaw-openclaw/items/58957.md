## Summary

Keep open: current main has useful compaction and overflow mitigations, but the central model-switch carried-context problem remains because session model changes are still persisted and acknowledged without a target-context budget decision or shared recovery policy.

## What This Changes

Report that long sessions can fail, route, or recover unclearly after model switches when carried-over context exceeds the selected model's effective budget.

## Best Possible Solution

Define one shared model-switch and continuation policy that estimates carried context against the selected model budget and consistently compacts, warns, or fails across chat directives, Control UI, sessions.patch, heartbeat, fallback, and runtime paths.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What should OpenClaw do when a persisted model switch or continuation would carry a session over the selected model's effective context budget?

Rationale: Current code has enough budget metadata and multiple partial recovery paths, but choosing compact, warn, fail, fallback, or runtime-specific behavior affects provider routing, session state, replay safety, and documented overflow policy.

Likely owner: Peter Steinberger

Owner reason: The live model-switch pending history and current product-policy boundary make Peter Steinberger the best available routing owner from the sampled history.

Owner confidence: medium

Options:

- **Shared budget check with recovery (recommended):** Add a common switch/continuation budget check that auto-compacts when safe and otherwise gives explicit user-visible recovery guidance before or during the next run.
- **Warn only before switching:** Keep model switching immediate but surface target-budget risk and recommend /compact or /new without automatically changing the session transcript.
- **Keep runtime-owned recovery:** Document that overflow remains compaction/retry-owned after the next run starts, and improve diagnostics without adding a switch-time policy gate.
