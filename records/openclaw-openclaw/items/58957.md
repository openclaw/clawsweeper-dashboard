## Summary

Keep open. Current main has later pre-prompt context-budget machinery and metadata fixes, but the model-switch surfaces still persist and acknowledge a new model without a shared carried-context risk decision or recovery policy, so the central user problem remains.

## What This Changes

The issue requests clearer model-switch/context-overflow recovery when a long-running session carries too much context into a smaller or stricter target model.

## Best Possible Solution

Define one shared model-switch policy that estimates carried context against the selected model's effective budget and then compacts, warns, or fails consistently across chat directives, Control UI/TUI, sessions.patch, heartbeat, and runtime fallback paths.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What should OpenClaw do when an existing session is switched to a model whose effective budget may not fit the carried context?

Rationale: The code has metadata and pre-prompt compaction pieces, but choosing automatic compaction versus warning, fail-closed behavior, fallback routing, or a fresh-session handoff changes provider routing and session-state UX.

Likely owner: steipete

Owner reason: The current model-switch and sessions.patch carrier lines blame to steipete, and this decision crosses core session/provider behavior rather than a narrow plugin boundary.

Owner confidence: medium

Options:

- **Warn and Offer Recovery (recommended):** Keep model switching non-destructive, surface the target-budget risk, and offer `/compact` or `/new` recovery before the next run.
- **Auto-Compact on Switch:** Attempt compaction during model switch when carried context exceeds the target budget, accepting extra latency and compaction side effects.
- **Fail Closed on Risk:** Reject risky model switches until the user explicitly compacts or starts a fresh session, reducing silent failures but changing current permissive behavior.
