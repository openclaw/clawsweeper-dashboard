Full review comments:

- **[P1] Preserve cron retention before switching history reads:** `src/cron/task-run-history.ts:117`
  - body: The new reader makes `task_runs` authoritative while per-source retention is explicitly deferred. Terminal task rows use the task ledger's shorter cleanup lifecycle, so existing cron history retained by `cron.runLog.keepLines` can disappear after upgrade. Add equivalent cron-source retention before flipping the read path, or keep legacy reads authoritative until that follow-up lands.
  - confidence: 0.98
- **[P1] Reconcile existing thin cron mirrors during import:** `src/infra/state-migrations.cron-run-logs.ts:49`
  - body: The `detail_json IS NOT NULL` predicate excludes every pre-upgrade thin cron mirror from the already-mirrored set. Importing its matching run-log entry therefore creates a second task row for the same execution, leaving duplicate task counts and failures until cleanup. Match and upgrade the legacy mirror instead of adding another record.
  - confidence: 0.99
- **[P1] Move persistent history import out of database open:** `src/state/openclaw-state-db.ts:1558`
  - body: This call performs a potentially large user-history rewrite synchronously inside ordinary state-database opening. A large or malformed run-log table can now delay or fail every Gateway startup, and it bypasses the repository's explicit doctor/migration ownership for persistent user state. Run this through the dedicated migration owner with resumable verification rather than the schema-open path.
  - confidence: 0.97
- **[P2] Recover stale tasks through the migrated run identity:** `src/infra/state-migrations.cron-run-logs.ts:126`
  - body: Imported terminal rows use a new deterministic import identity, so recovery by the original thin task's task/run identity cannot find the completed execution and can mark it lost. Preserve a durable original execution identity during import or make recovery match the imported row through the legacy run metadata.
  - confidence: 0.94
