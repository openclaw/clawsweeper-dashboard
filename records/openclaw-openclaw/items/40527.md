## Summary

Keep open: current main and the latest release still eagerly refresh remote skill bins for connected macOS nodes that advertise `system.which` or `system.run`; the static allowlist cause was narrowed, but the connect/readiness timing problem is not proven fixed and the related PRs are not safe canonical fixes.

## What This Changes

The issue reports macOS app-backed node remote skill binary probes timing out during gateway startup or reconnect, especially when the app node is co-located with the gateway.

## Best Possible Solution

Preserve the macOS app node `system.which`/`system.run` contract, make remote skill-bin refresh readiness-aware with bounded deferral/backoff or a narrowly proven co-located skip, and require live proof for both co-located and remote macOS app nodes.
