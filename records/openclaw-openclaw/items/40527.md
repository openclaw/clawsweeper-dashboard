## Summary

Keep open: current main mitigated the old static macOS default-command cause, but macOS app nodes still advertise `system.which`/`system.run` and the gateway still kicks remote skill-bin probing on node connect without a readiness delay/backoff decision. The remaining behavior needs maintainer direction and live macOS proof before cleanup can safely close it.

## What This Changes

The issue reports timeout warnings and startup/reconnect delay from automatic remote skill-bin probes against macOS app-backed nodes, especially when the app node is co-located with the gateway.

## Best Possible Solution

Settle the macOS app-node readiness and remote-bin probe policy in the active runtime so probes wait for a ready node or back off cleanly without disabling legitimate remote node execution.
