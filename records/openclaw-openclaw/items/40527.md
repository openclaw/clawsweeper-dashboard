## Summary

Keep open: current main partially fixed the original missing-handler/default-command cause, but approved macOS app-backed nodes can still advertise `system.which`/`system.run` and enter the immediate remote-bin probe path; the remaining timing/co-location policy is not resolved by a merged PR.

## What This Changes

The issue requests that remote macOS skill-bin probing stop timing out or warning when a macOS app node is co-located with the gateway or not yet ready after reconnect.

## Best Possible Solution

Settle and implement a macOS app-node readiness/probe policy that defers or backs off remote-bin probes until the node is ready, while preserving legitimate remote macOS skill execution.
