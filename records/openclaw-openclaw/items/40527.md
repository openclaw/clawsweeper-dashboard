## Summary

Keep open: current main implements macOS app node `system.which`/`system.run` support and some command-policy filtering, but the reported automatic remote skill bin probe timing/backoff problem for macOS app-backed nodes is still present and overlaps with unresolved node stability work.

## What This Changes

Issue requests that macOS app-backed node remote skill binary probing stop causing startup/session timeout warnings when the app is co-located with or slow to register with the gateway.

## Best Possible Solution

Choose a maintainer-owned probe policy that preserves approved remote macOS skill execution while deferring, coalescing, or backing off automatic probes until macOS app nodes are ready.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should automatic remote skill bin probing for macOS app-backed nodes be deferred/backed off, skipped only for proven co-located app nodes, or disabled by default for app nodes?

Rationale: Current main intentionally supports approved macOS app-node `system.which` and `system.run`, so changing the probe policy crosses readiness timing, retry behavior, co-located-node handling, and remote skill availability.

Likely owner: steipete

Owner reason: The strongest history signal for both remote skill probing and mac node exec policy points to this owner path.

Owner confidence: high

Options:

- **Defer and back off app-node probes (recommended):** Keep remote macOS skill support, but wait for node readiness and add coalescing/backoff so slow or co-located app nodes do not spam timeout warnings.
- **Skip only proven co-located app nodes:** Avoid the original same-host timeout case while keeping normal remote macOS app nodes eligible for skill probing.
- **Disable app-node probing by default:** Remove the warning source broadly, but risk making documented remote macOS skill execution less automatic unless users opt in later.

Yes, source-reproducible with medium confidence: current main still starts automatic remote bin probes from node connection paths, but this review did not run a live macOS app-node repro.
