## Summary

Keep open: current main no longer matches the original missing `system.which` handler theory, but it still immediately probes macOS app-backed nodes that advertise `system.which` or `system.run`, and no merged related PR has settled the remaining readiness/co-location policy.

## What This Changes

The issue reports repeated remote skill binary probe timeouts for macOS app-backed nodes, especially when the app node is co-located with the gateway.

## Best Possible Solution

Settle and implement one macOS app-node readiness/probe policy that preserves legitimate remote node execution while delaying, backing off, or skipping probes when the app node is not ready or is co-located with the gateway.
