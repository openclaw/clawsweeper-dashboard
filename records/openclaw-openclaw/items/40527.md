## Summary

Keep open: current main has narrowed the old static macOS command-default problem, but it still probes connected macOS nodes that advertise `system.which` or `system.run`, and the macOS app still advertises and handles those commands. The related candidate PRs are open/stale or conflicting, and a rejected closed PR confirms maintainers do not want to solve this by removing the app-node exec surface.

## What This Changes

The issue asks OpenClaw to stop remote skill binary probe timeouts and startup warning spam for co-located or app-backed macOS nodes without blocking valid remote macOS node execution.

## Best Possible Solution

Preserve macOS app-node `system.run` and `system.which`, then land a narrow active-runtime probe readiness/backoff or proven co-located-node skip with redacted real macOS gateway proof.
