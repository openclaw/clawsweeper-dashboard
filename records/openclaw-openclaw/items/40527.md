## Summary

Keep open: current main and the latest release still immediately refresh remote skill-bin state for connected macOS nodes that advertise `system.which` or `system.run`; the old default-allowlist cause is mitigated, but the remaining readiness/timing behavior is not proven fixed.

## What This Changes

The issue reports remote skill binary probe timeouts and misleading connectivity warnings for macOS app-backed nodes, especially when the app node is co-located with the gateway.

## Best Possible Solution

Keep the macOS app node exec contract intact, make remote skill-bin refresh readiness-aware with bounded deferral/backoff, and require live proof for both co-located and remote macOS app nodes.
