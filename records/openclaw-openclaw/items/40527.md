## Summary

Keep open: current main still probes connected macOS nodes that advertise `system.which` or `system.run`, and the related evidence points to a remaining readiness/timing decision rather than an implemented fix or a safe canonical PR.

## What This Changes

The issue reports timeout warnings and startup/reconnect delay from automatic remote skill binary probing against macOS app-backed nodes, especially co-located gateway/app setups and early post-connect probes.

## Best Possible Solution

Keep the macOS app node exec contract intact, make remote skill-bin refresh readiness-aware with bounded deferral/backoff or a proven co-located-only skip, and require live proof for both co-located and remote macOS app nodes.
