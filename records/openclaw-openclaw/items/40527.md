## Summary

Keep open: current main and v2026.6.11 still contain the automatic remote macOS bin-probe path for connected app nodes that advertise `system.which` or `system.run`, and the remaining fix needs maintainer judgment on readiness, co-location, and retry/backoff semantics.

## What This Changes

The issue asks OpenClaw to stop automatic remote skill bin probes from timing out against macOS app-backed nodes during gateway startup or reconnect.

## Best Possible Solution

Settle the macOS app-node readiness/probe policy in the active runtime so automatic probes wait for a ready node or back off cleanly, without adding a broad config disable or blocking legitimate node-host execution.

## Reproduction Assessment

Yes from source at medium confidence: current main and v2026.6.11 still automatically probe connected macOS nodes that expose `system.which` or `system.run`. No live macOS repro was run here, so the precise timeout timing remains to be proven with real app-node logs.

## Solution Assessment

No final implementation is proven best yet. The safest direction is a narrow active-runtime fix for app-node readiness, co-location, and backoff semantics, not the broad disable flag suggested as one possible workaround.
