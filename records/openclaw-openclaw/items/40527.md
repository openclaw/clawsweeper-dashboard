## Summary

Keep open: current main and the latest release still eagerly start remote skill-bin refresh for connected macOS nodes that advertise `system.which` or `system.run`; the original static-default allowlist cause was narrowed, but the reported readiness/timing problem is not proven fixed.

## What This Changes

The issue asks OpenClaw to stop remote skill-bin probe timeouts and warning spam for macOS app-backed nodes, especially when the app node is co-located with the gateway.

## Best Possible Solution

Keep the macOS app node exec contract intact, make remote skill-bin refresh readiness-aware with bounded deferral/backoff, and require live proof for both co-located and remote macOS app nodes.
