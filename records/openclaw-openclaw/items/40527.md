## Summary

Keep open: current main and the latest release still start remote skill-bin probes immediately for connected macOS nodes that advertise `system.which` or `system.run`; the old static-default allowlist cause is narrowed, but the co-location/readiness timing problem is not proven fixed.

## What This Changes

The issue asks OpenClaw to avoid remote skill-bin probe timeouts for macOS app-backed nodes, especially when co-located with the gateway, without disabling legitimate remote node exec.

## Best Possible Solution

Keep the macOS app node exec contract intact, make remote skill-bin refresh readiness-aware with bounded deferral/backoff, and require live proof for both co-located and remote macOS app nodes.
