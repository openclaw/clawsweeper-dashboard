## Summary

The current source still routes connected macOS app-node sessions into automatic remote bin probing when they advertise `system.which` or `system.run`, and the overlapping repair PRs remain open/conflicting rather than merged. The original “app cannot handle system.which” diagnosis is partly outdated, but the timing/co-location/backoff policy remains unresolved and needs maintainer direction plus live macOS proof.

## What This Changes

The issue requests a fix for macOS app-backed node remote skill binary probes timing out during gateway startup or reconnect, especially when the app node is co-located with the gateway.

## Best Possible Solution

Settle a narrow macOS app-node readiness, co-location, and retry/backoff policy in the remote skills runtime, preserve valid `system.run` and `system.which` behavior, and prove it with a real macOS app node.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should automatic remote skill bin probing for macOS app-backed nodes be deferred/backed off, skipped only for proven co-located app nodes, or disabled by default for app nodes?

Rationale: Current code intentionally supports macOS app-node `system.run` and `system.which`, so the remaining fix crosses readiness timing, co-location detection, retry policy, and documented node exec compatibility rather than a purely mechanical patch.

Likely owner: Peter Steinberger

Owner reason: The decision spans command policy, app-node capability defaults, and product compatibility, and this owner has the strongest history on node command policy in the available git evidence.

Owner confidence: medium

Options:

- **Defer And Back Off Probes (recommended):** Keep remote macOS skills supported, but delay the initial app-node probe until readiness is stronger and add bounded retry/backoff after failed probes.
- **Skip Only Co-located App Nodes:** Avoid probing loopback or same-install app nodes that cannot add remote skill value while preserving remote app-node probing.
- **Disable App-node Probing By Default:** Stop automatic app-node remote skill eligibility unless explicitly enabled, reducing warning noise at the cost of default remote skill support.
