## Summary

Keep open: current main and v2026.6.11 still probe macOS nodes immediately when they advertise `system.which` or `system.run`; the old default-allowlist issue is mitigated, but the reported readiness/backoff timeout behavior is not fixed by a merged PR.

## What This Changes

The issue reports remote macOS app-node skill binary probes timing out during gateway startup or reconnect, especially when the macOS app is co-located with the gateway or not ready when the automatic probe fires.

## Best Possible Solution

Make remote skill-bin refresh readiness-aware with bounded deferral/backoff, preserve approved macOS node exec semantics, and prove both co-located and remote macOS app-node behavior with redacted live logs.
