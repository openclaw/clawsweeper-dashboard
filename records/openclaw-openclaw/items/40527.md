## Summary

Keep open: current main has partial fixes for missing macOS command handling, but the active runtime still immediately probes macOS app-backed nodes that advertise `system.which` or `system.run`, and the remaining readiness/co-location/backoff policy is not settled by a merged PR.

## What This Changes

The issue reports remote skill binary probes timing out for macOS app-backed nodes, especially when the app node is co-located with the gateway.

## Best Possible Solution

Settle the active runtime policy so macOS app-node probes wait for a ready node or use bounded backoff/co-location skip behavior while preserving legitimate remote Mac execution, then prove it with real macOS app-node logs.
