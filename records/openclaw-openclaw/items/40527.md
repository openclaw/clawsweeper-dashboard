## Summary

Keep open: current main and the latest release still automatically probe connected macOS app-backed nodes that advertise `system.which` or `system.run`; the original missing-handler diagnosis is partly obsolete, but the readiness/co-location/backoff problem remains and the overlapping PRs are not safe merged resolutions.

## What This Changes

The issue reports repeated remote skill binary-probe timeouts and startup or reconnect delay when macOS app-backed nodes are co-located with the gateway or are probed before they are ready.

## Best Possible Solution

Preserve macOS app-node remote execution, then make `src/skills/runtime/remote.ts` readiness-aware with bounded defer/backoff or a narrow loopback skip, backed by real macOS app plus gateway proof.
