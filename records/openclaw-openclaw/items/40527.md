## Summary

Keep open: current main has moved past the original missing macOS `system.which` handler, but the active runtime still immediately probes macOS app-backed nodes that advertise `system.which` or `system.run`, and the remaining timing/co-location policy is not settled by any merged PR.

## What This Changes

The issue asks OpenClaw to stop remote skill binary probes from timing out for macOS app-backed nodes, especially when the app node is co-located with the gateway.

## Best Possible Solution

Settle the macOS app-node readiness and remote-bin probe policy in the active runtime so probes wait for a ready node or back off cleanly without disabling legitimate remote node execution.
