## Summary

Keep open: current main and v2026.6.11 still immediately probe connected macOS nodes that advertise `system.which` or `system.run`; the original default-allowlist mismatch is partly fixed, but the remaining app-node readiness/co-location/backoff policy is unresolved.

## What This Changes

The issue reports timeout spam and startup delay from remote skill binary probing against macOS app-backed nodes, especially co-located app-plus-gateway setups.

## Best Possible Solution

Settle the macOS app-node readiness, co-location, and retry/backoff policy in `src/skills/runtime/remote.ts` while preserving valid remote macOS `system.run`/`system.which` workflows, then prove it with a real macOS app node.
