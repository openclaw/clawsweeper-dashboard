## Summary

Keep open: current main has moved past the original missing macOS `system.which` handler, but it still immediately probes macOS app-backed nodes that advertise `system.which` or `system.run`; the related fixes are either open/conflicting or closed unmerged.

## What This Changes

The issue asks OpenClaw to stop automatic remote skill binary probes from timing out for macOS app-backed nodes, especially co-located gateway/app nodes, without disabling legitimate remote node execution.

## Best Possible Solution

Preserve app-backed node execution commands, then fix the remote-bin probe path with a readiness-aware defer/backoff or a narrow co-located-node skip backed by real macOS app plus gateway proof.

- **Disable App-node Probing By Default:** Stop automatic app-node remote skill eligibility unless users explicitly enable it, reducing warning spam at the cost of default remote skill support.
