## Summary

Keep open: current main and the latest release still immediately refresh remote skill-bin probes for macOS nodes that advertise `system.which` or `system.run`; the old desktop default-allowlist cause is mitigated, but the remaining readiness/backoff behavior is not resolved by a merged fix.

## What This Changes

The issue asks OpenClaw to avoid remote skill-bin probe timeouts and warning spam for macOS app-backed nodes, especially co-located gateway/app nodes, without disabling legitimate remote node execution.

## Best Possible Solution

Make remote skill-bin refresh readiness-aware with bounded deferral/backoff, preserve approved macOS node exec semantics, and prove both co-located and remote macOS app-node behavior with redacted live logs.
