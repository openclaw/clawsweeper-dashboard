## Summary

Keep open: current main and the latest release still immediately probe connected macOS app-backed nodes that advertise `system.which` or `system.run`; the oldest missing-handler diagnosis is partly fixed, but the remaining app-node readiness/co-location/backoff policy is unresolved.

## What This Changes

The issue reports remote skill binary probes timing out for macOS app-backed nodes during gateway startup or reconnect, especially when the app node is co-located with the gateway.

## Best Possible Solution

Settle the macOS app-node readiness, co-location, and retry/backoff policy in `src/skills/runtime/remote.ts` while preserving valid remote macOS `system.run`/`system.which` workflows, then prove it with a real macOS app node.
