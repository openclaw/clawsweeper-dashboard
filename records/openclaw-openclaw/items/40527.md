## Summary

Keep open: current main and the latest release still start remote skill-bin refresh immediately for connected macOS nodes that advertise `system.which` or `system.run`; the old static macOS default issue is mitigated, but the readiness/backoff/co-location behavior remains unresolved and linked PRs are not safe canonical fixes.

## What This Changes

The issue reports startup and reconnect timeouts from automatic remote skill binary probes against macOS app-backed nodes, especially when the app node is co-located with the gateway.

## Best Possible Solution

Make remote skill-bin refresh readiness-aware with bounded deferral/backoff, preserve approved macOS node exec semantics, and prove both co-located and remote macOS app-node behavior with redacted live logs.
