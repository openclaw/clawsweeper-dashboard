## Summary

Keep this PR open for normal maintainer review. The proposed recovery-owner boundary is a focused, plausible fix with targeted regression coverage and no discrete code defect found, but the supplied live logs are pre-fix and do not yet show the changed gateway reaching the intended give-up state in a real run; the protected `maintainer` label also requires explicit maintainer handling.

## What This Changes

The PR makes the gateway health monitor defer to a channel account’s own crash-restart supervisor so repeated crashes can exhaust that supervisor’s backoff ladder and reach its terminal give-up state.

## System Context

Channel plugins publish account runtime snapshots to the gateway’s channel manager. The health monitor consumes those snapshots to recover unhealthy accounts; this change adds an ownership signal so it does not compete with an already scheduled supervisor restart.

## Architecture Diagram

flowchart TD
  A[Channel account crashes] --> B[Channel restart supervisor]
  B --> C[Backoff or replacement start]
  C --> D[Runtime snapshot]
  D --> E[Gateway health monitor]
  E --> F{Supervisor owns recovery?}
  F -->|Yes| G[Defer restart]
  F -->|No| H[Health-monitor recovery]
  B --> I[Give-up terminal state]

## Best Possible Solution

Keep one recovery owner at a time: land the narrowly scoped supervisor-ownership guard only after a redacted real gateway run demonstrates the terminal give-up transition and the subsequent health-monitor handoff, with the exact-head required checks complete.
