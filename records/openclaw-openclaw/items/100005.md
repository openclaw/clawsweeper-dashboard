## What This Changes

The PR adds a records-only plugin install-index commit path for `plugins update` and updates gateway reload dedupe so plugin-index-only changes can trigger reload/restart without rewriting `openclaw.json`.

## Best Possible Solution

Land this PR or an equivalent bounded fix after redacted after-fix CLI proof is added and maintainers accept the records-only persistence boundary, while keeping config writes for actual source-config mutations.

## Reproduction Assessment

Yes at source level: current main routes changed plugin install records through `commitPluginInstallRecordsWithConfig` and then `replaceConfigFile`, while the linked issue provides a Windows upgrade log with the size-drop rejection. I did not run the Windows upgrade path in this read-only review.

## Solution Assessment

Yes, pending proof: the narrow fix is to skip `openclaw.json` replacement only when the projected source config is unchanged, while preserving stale-config rejection, plugin validation, rollback, and gateway reload signaling. Rewriting config for every record change is the behavior that caused the reported failure.
