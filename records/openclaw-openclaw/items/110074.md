## Label Justifications

- `P1`: A current stable user reports that restarting the Gateway can leave an active agent workflow unusable for roughly thirteen minutes and require another message to recover.
- `impact:session-state`: The embedded run's lock ownership, persisted transcript fingerprint, and client-visible running state diverge after restart.
- `impact:crash-loop`: The affected embedded turn hangs for many minutes before terminating, creating a session-level availability failure.

## Summary

Keep open: the shipped v2026.7.1 report describes a concrete active-turn hang and terminal takeover error, while current main still retains immediate/plain restart paths that are distinct from the coordinated safe-restart path. Existing related reports cover different takeover causes or broader restart recovery, so none clearly supersedes this failure.

## What This Changes

Prevent an active embedded agent turn from remaining falsely marked as running after a gateway restart and eventually failing with a session-takeover error.

## Best Possible Solution

Make the restart lifecycle atomically drain or cancel each active embedded run, release its session ownership, and publish one prompt terminal state to connected clients before the old Gateway exits; retain the session fence as corruption protection rather than using it as restart recovery.
