## Summary

Keep this issue open. Current main has already reduced the transcript-lock portion with a configurable max-hold threshold and an in-process watchdog, but the reported session-targeted cron failure needs a current-main queue-versus-setup-timeout trace before it can be considered resolved.

## What This Changes

Report that in-process transcript locks can block a session for their full hold period and that session-targeted `agentTurn` cron jobs can fail their setup watchdog while waiting behind a busy lane.

## Best Possible Solution

Retain the current configurable transcript-lock watchdog, then make the cron lifecycle start its setup watchdog only after lane admission or record queue waiting under a separate bounded policy with phase-specific diagnostics.
