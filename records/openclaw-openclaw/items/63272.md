## Summary

Keep open: current main and the latest release still lack `openclaw skills uninstall`, while ClawHub skill update still consumes stale lockfile entries. The linked implementation attempt at https://github.com/openclaw/openclaw/pull/94828 is closed unmerged, so this remains the canonical maintainer decision point for the CLI uninstall contract.

## What This Changes

Add an `openclaw skills uninstall <slug>` command that removes a ClawHub-installed skill directory and its `.clawhub/lock.json` entry.

## Best Possible Solution

A maintainer-sponsored narrow CLI command should remove only the selected ClawHub-tracked skill directory plus lockfile/origin state with safe slug resolution, confirmation/dry-run/JSON behavior, and focused tests; manual, bundled, dashboard, and Gateway RPC scopes should stay separate unless maintainers approve them.

- **Defer core support:** Leave manual deletion/documented workarounds in place until maintainers decide ClawHub skill lifecycle belongs outside the OpenClaw CLI.

## Reproduction Assessment

Yes. Source inspection shows the skills CLI lacks an uninstall command while install writes lockfile/origin metadata and `skills update --all` consumes lockfile entries, so manual deletion can leave state that reinstalls the skill.

## Solution Assessment

Unclear until maintainers decide the product contract. The proposed narrow CLI/lifecycle implementation is a plausible fit, but destructive semantics and non-ClawHub/manual skill handling need approval first.
