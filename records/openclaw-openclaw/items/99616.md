## Label Justifications

- `P2`: The issue describes a meaningful privacy and memory-integrity improvement, but it is a feature request rather than an urgent broken current workflow.
- `impact:security`: The request is about preventing sensitive corporate entity names and domains from reaching external LLM providers in plaintext.
- `impact:data-loss`: The issue describes possible long-term memory corruption if encoded placeholder tokens are persisted and reused.

## Summary

Close as ClawHub/plugin scope: this is a new optional privacy dictionary/config surface, current main and the latest release already expose plugin seams for provider text transforms, tool-argument rewriting, and pre-persistence message/result hooks, and the same request was already reviewed in https://github.com/openclaw/openclaw/issues/98157.

## What This Changes

The issue requests a user-maintained entity dictionary that masks sensitive names and domains before LLM provider calls and reverses them before chat display, tool/MCP dispatch, and memory writes.

## Best Possible Solution

Publish this as a ClawHub code plugin using current text-transform, before_tool_call, tool_result_persist, and before_message_write hooks; open a narrow plugin-SDK gap only if that implementation proves one.

## Reproduction Assessment

Not applicable: this is a requested privacy/config capability, not a reproducible bug in an existing documented behavior contract. Source review confirms current logging redaction is not provider-bound masking, while the plugin seams exist for external implementation.

## Solution Assessment

No for native core config: adding privacy.entityDictionary to core would create a new optional configuration surface where VISION.md and current hooks point to a ClawHub code plugin first. Core should only change if a real plugin implementation proves a generic SDK gap.
