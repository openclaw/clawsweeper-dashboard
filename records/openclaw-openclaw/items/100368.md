## Summary

Keep open: current main still has a source-proven gap where a substantive `message_tool_only` final can be withheld from the user while remaining an ordinary assistant turn in replay context, and the active recovery PR only partially overlaps the requested delivery-reality invariant.

## What This Changes

The issue asks OpenClaw to mark or replace withheld `message_tool_only` finals so later agent context does not treat them as delivered replies.

## Best Possible Solution

Make delivery reality part of the core replay contract: a withheld `message_tool_only` final should either be replayed with an explicit undelivered marker or replaced by a concise system notice, coordinated with any stranded-final recovery path.
