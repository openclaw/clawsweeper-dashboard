## Summary

Keep open: current main and the latest release still keep substantive `message_tool_only` finals private and warning-only, while Codex records ordinary assistant final messages into later prompt history with no OpenClaw delivery-status marker, so the reported phantom-context desynchronization remains unresolved.

## What This Changes

The issue asks OpenClaw to represent withheld `message_tool_only` assistant finals honestly in later agent context so the model does not treat undelivered text as user-visible history.

## Best Possible Solution

Make delivery reality part of the core replay contract: a withheld `message_tool_only` final should either be replayed with an explicit undelivered marker or replaced by a concise system notice, coordinated with stranded-final recovery work.

Options:

- **Add replay-visible undelivered state (recommended):** Keep or summarize the private assistant text, but make later model context explicitly say the user did not receive that assistant turn.
- **Replace withheld finals in replay:** Remove the private final text from model replay and keep only a short system notice that a final was generated but not delivered.
- **Rely on recovery only:** Treat stranded-final recovery as the product answer and accept that replay context may not separately annotate older withheld turns.
