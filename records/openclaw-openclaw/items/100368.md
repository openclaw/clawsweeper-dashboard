## Label Justifications

- `P1`: A production `message_tool_only` lane can silently withhold user-facing finals and then poison later agent memory, breaking an active agent/channel workflow.
- `impact:message-loss`: The reported final text is intentionally not delivered to the channel, and the user experiences the agent as having lost the reply.
- `impact:session-state`: The core failure is transcript/context drift: later turns replay private assistant text as if it were shared conversation history.

## Summary

Keep open: current main still treats a substantive `message_tool_only` final as private for delivery, but source inspection shows the final can remain a normal assistant transcript/replay turn without a delivery-status marker, so the reported session-state/user-visible desynchronization remains unresolved.

## What This Changes

The issue asks OpenClaw to make withheld `message_tool_only` finals visible as undelivered in agent-facing context so later turns do not treat private text as delivered conversation history.

## Best Possible Solution

Add a canonical delivery-status representation for withheld private finals in model-visible replay, coordinated with stranded-final recovery so private text is not auto-published but later turns can tell the user never saw it.

## Maintainer Decision

Required: true

Kind: product_direction

Question: For `message_tool_only` private finals that are withheld from the source channel, should OpenClaw replay the full text with an undelivered marker, replace it with a short delivery-status notice, or rely only on stranded-final recovery?

Rationale: The runtime can detect the mismatch, but the durable replay shape affects privacy, model behavior, transcript semantics, and how it composes with the open recovery PR.

Likely owner: obviyus

Owner reason: Their recent per-turn delivery-contract work is the closest current owner boundary for deciding how `message_tool_only` turns should appear to the model.

Owner confidence: medium

Options:

- **Annotate withheld replay (recommended):** Keep the private final available for continuity but add a clear model-visible system/status marker that it was not delivered to the user.
- **Replace replayed final:** Remove the withheld text from model-visible history and preserve only a short undelivered notice, reducing phantom-history risk at the cost of losing useful working state.
- **Defer to recovery PR:** Treat active stranded-final recovery as sufficient for now and leave historical withheld finals unmarked, accepting continued desync risk when recovery does not run or predates the fix.

## Reproduction Assessment

Yes, by source inspection rather than a live run: a non-room `message_tool_only` final can be withheld for delivery, persisted/replayed as an ordinary assistant message, and only transcript-only OpenClaw mirror rows are stripped from replay.

## Solution Assessment

Unclear until maintainers choose the replay representation; annotating withheld turns is the narrowest visible fix, while replacing the text is safer for phantom-history prevention but loses working-state continuity.
