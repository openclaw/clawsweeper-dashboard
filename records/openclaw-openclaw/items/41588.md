## Summary

Keep open: current main and the latest release still use a single wall-clock deadline for chat/agent run expiry, while related open PRs only address timeout notices or the narrower subagent LLM-idle heartbeat slice.

## What This Changes

Keep this as the canonical timeout-semantics issue, decide the idle-vs-hard-cap contract, then land one focused core change with tests/docs while treating #89965 and #95536 as partial slice fixes.
