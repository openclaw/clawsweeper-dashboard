## Summary

Keep open: current main still has a single wall-clock gateway and embedded-run deadline, while the latest release and related open PRs only cover mitigations, subagent idle-heartbeat behavior, or timeout notices rather than the requested idle-plus-hard-cap run contract.

## What This Changes

The issue requests activity-aware timeout behavior so active multi-tool agent runs are not killed solely because the total wall-clock run duration exceeded `agents.defaults.timeoutSeconds`.

## Best Possible Solution

Define a core idle-timeout plus hard-cap contract for chat and agent runs, align config/schema/docs/tests around it, then land or close the narrower partial PRs against that agreed contract.
