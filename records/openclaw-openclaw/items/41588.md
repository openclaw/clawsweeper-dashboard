## Summary

Keep open: current main still uses fixed run deadlines for chat/agent aborts and does not define an activity-aware idle-plus-hard-cap timeout contract; related open PRs only cover timeout notices or narrower subagent idle-heartbeat behavior.

## What This Changes

Request activity-aware agent run timeout semantics so active tool/model progress is not killed solely by a flat `agents.defaults.timeoutSeconds` wall-clock budget.

## Best Possible Solution

Keep this as the canonical core timeout-semantics issue, choose an idle-timeout plus hard-cap contract, then land one focused core/docs/test change while coordinating the narrower open PRs.
