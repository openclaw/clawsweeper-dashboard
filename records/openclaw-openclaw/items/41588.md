## Summary

Keep open: current main and v2026.6.11 still enforce configured agent run budgets as wall-clock deadlines, and the open related PRs cover narrower notice, subagent idle-watchdog, or Telegram progress slices rather than the core activity-aware timeout contract.

## What This Changes

Request activity-aware timeout semantics for agent/gateway runs so active multi-tool turns are not killed solely by total elapsed wall-clock time.

## Best Possible Solution

Decide one canonical core timeout model, preferably an idle/activity deadline plus a hard ceiling and visible timeout notice, then use or supersede the narrower open PRs under that design.
