## Summary

Keep open: current main still has a single active-run deadline for chat and agent runs, while the related open PRs cover narrower timeout-notice or subagent-idle slices rather than the requested activity-aware run-budget contract.

## What This Changes

Request activity-aware run timeout semantics so productive multi-tool turns are not killed solely because the original wall-clock `timeoutSeconds` budget elapsed.

## Best Possible Solution

Define an explicit idle-timeout plus hard-cap contract for chat and agent runs, then implement it in the gateway active-run state and embedded-runner progress boundary with focused tests and config/docs alignment.
