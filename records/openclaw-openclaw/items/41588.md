## Summary

Keep open: current main and the latest release still model the chat/agent run budget as one fixed deadline, while the live related PRs only cover narrower timeout-notice and subagent idle-watchdog slices. This remains a product-sensitive core timeout-semantics issue rather than a cleanup-close candidate.

## What This Changes

The issue requests activity-aware timeout semantics so active multi-tool runs are not killed solely by a flat wall-clock `agents.defaults.timeoutSeconds` budget.

## Best Possible Solution

Keep this as the canonical timeout-semantics issue, choose the idle-timeout plus hard-cap contract, then land one focused core change with regression coverage and docs while reviewing the open slice PRs as partial mitigations.
