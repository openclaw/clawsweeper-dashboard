## Summary

Keep open: current main and v2026.6.11 still use a single run deadline for gateway and embedded agent runs, while the related open PRs cover narrower timeout-notice, Telegram-progress, or subagent-idle slices rather than the core activity-aware timeout contract.

## What This Changes

The issue requests activity-aware agent run timeouts so active multi-tool runs are not killed by a flat wall-clock deadline.

## Best Possible Solution

Define one core timeout contract that keeps an absolute safety cap while adding liveness or idle semantics across gateway admission, embedded runner aborts, user-visible timeout reporting, docs, and regression coverage.

- **Keep hard wall clock only:** Land only notice/progress mitigations and keep long active turns controlled by higher configured budgets.
