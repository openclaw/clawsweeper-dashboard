## Summary

Issue #102961 should stay open because current main still forwards Codex native PostToolUse `tool_response` strings into `after_tool_call`, while the structured app-server completion data with status and exit code is suppressed when native relay is enabled; the remaining work is a plugin API contract decision, not a missing small patch.

## What This Changes

Request structured `after_tool_call` results for Codex-native shell/apply_patch tool calls so plugins can observe status, exit code, duration, stdout/stderr, and error semantics instead of raw Codex response strings.

## Best Possible Solution

Adopt one canonical Codex-native `after_tool_call` observation that exposes status, exit code, duration, and output/error text while preventing duplicate native-relay and app-server events.
