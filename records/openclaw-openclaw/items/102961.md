## Label Justifications

- `P2`: The issue breaks Codex-native exec/bash outcome observability for plugin consumers, but it is not a crash loop, security bypass, or first-run blocker.
- `impact:session-state`: Plugins receive incorrect per-tool outcome state for agent runs, causing hook consumers to misclassify command failures as successes.

## Summary

Keep open: current main still forwards Codex native `PostToolUse.tool_response` directly as `after_tool_call.result` and suppresses the structured app-server command-execution observation when the native relay is enabled.

## What This Changes

The issue asks OpenClaw to expose structured status, exit code, duration, and output/error data to plugin `after_tool_call` hooks for Codex-native exec/bash and apply-patch tool calls.

## Best Possible Solution

Define one canonical `after_tool_call` observation for Codex-native shell/apply_patch that exposes structured status, exitCode, duration, and output/error fields while preserving a documented text/output field for display-only consumers.
