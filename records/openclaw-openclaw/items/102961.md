## Label Justifications

- `P2`: The issue breaks plugin observability for Codex-native shell failures with limited blast radius, but it is not a crash loop, security bypass, or first-run blocker.
- `impact:session-state`: Plugins receive incorrect per-tool outcome state for agent runs, causing hook consumers to misclassify command failures as successes.

## Summary

Keep open: current main still has the Codex-native hook payload gap, because the native relay forwards Codex's raw string `tool_response` while the structured app-server observation is suppressed when native `PostToolUse` relay is enabled. The newer operator comment adds real cron/reporting impact and supports the same canonical structured-payload direction.

## What This Changes

Requests that Codex-native exec/bash/apply_patch `after_tool_call` events expose structured tool-result outcome data instead of only a flattened output string.

## Best Possible Solution

Define one canonical Codex-native `after_tool_call` payload for shell/apply_patch that carries status, exitCode, duration, and text/output fields while suppressing duplicate raw-string relay events.
