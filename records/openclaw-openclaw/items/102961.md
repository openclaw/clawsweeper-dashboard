## Label Justifications

- `P2`: The issue breaks plugin observability for Codex-native exec/bash failures with limited blast radius, but it is not a crash loop, security bypass, or first-run blocker.
- `impact:session-state`: Plugins receive incorrect per-tool outcome state for agent runs, causing hook consumers to misclassify command failures as successes.

## Summary

Keep open: current main still forwards Codex-native exec/bash `after_tool_call` results as raw Codex `tool_response` strings while suppressing the structured app-server observation that already carries status and exitCode.

## What This Changes

The issue asks OpenClaw to expose structured Codex-native exec/bash tool outcomes to plugin `after_tool_call` hooks instead of a flattened result string.

## Best Possible Solution

Make one canonical Codex-native `after_tool_call` observation that exposes structured status, exitCode, duration, and text output semantics without emitting a duplicate raw-string event.
