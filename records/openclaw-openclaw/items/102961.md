## Label Justifications

- `P2`: The issue breaks plugin observability for Codex-native exec/bash failures with limited blast radius, but it is not a crash loop, security bypass, or first-run blocker.
- `impact:session-state`: Plugins receive incorrect per-tool outcome state for agent runs, causing hook consumers to misclassify command failures as successes.

## Summary

Keep open: current main still has the reported Codex-native exec/bash `after_tool_call` payload gap, and the operator comment confirms this blocks real plugin decision-making for shell failure workflows.

## What This Changes

The issue asks for `after_tool_call` plugin events for Codex-native exec/bash-family tools to expose structured tool-result status and exit-code data instead of only flattened output text.

## Best Possible Solution

Define one canonical `after_tool_call` observation for Codex-native shell/apply_patch that fires once and exposes structured status, exitCode, duration, and output/error semantics.
