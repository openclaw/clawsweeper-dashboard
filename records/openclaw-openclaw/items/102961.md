## Label Justifications

- `P2`: The issue breaks plugin observability for Codex-native exec/bash failures with limited blast radius, but it is not a crash loop, security bypass, or first-run blocker.
- `impact:session-state`: Plugins receive incorrect per-tool outcome state for agent runs, causing hook consumers to misclassify command failures as successes.

## Summary

Keep open: current main still leaves Codex-native exec/bash `after_tool_call` observations on the raw native `PostToolUse` string path, while the structured app-server command result is intentionally suppressed when that relay is enabled.

## What This Changes

The issue requests that `after_tool_call` expose structured Codex-native exec/bash outcome data such as status, exit code, duration, and output semantics instead of only a flattened result string.

## Best Possible Solution

Make one canonical `after_tool_call` observation for Codex-native shell/apply_patch that exposes structured status, exitCode, duration, and output/error semantics without emitting a duplicate raw-string event.
