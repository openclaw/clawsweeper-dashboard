## Label Justifications

- `P2`: The issue breaks Codex-native exec/bash outcome observability for plugin consumers, but it is not a crash loop, security bypass, or first-run blocker.
- `impact:session-state`: Plugins receive incorrect per-tool outcome state for agent runs, causing hook consumers to misclassify command failures as successes.

## Summary

Keep open: current main still routes Codex native `PostToolUse` `tool_response` directly into `after_tool_call` and suppresses the structured app-server command completion observation, so plugins still cannot reliably distinguish exec/bash failure from success.

## What This Changes

The issue requests structured Codex-native exec/bash `after_tool_call` results with status and exit-code data instead of only a flattened output string.

## Best Possible Solution

Define one canonical Codex-native `after_tool_call` observation that exposes structured status, exitCode, duration, and text output without emitting a duplicate raw-string event.

- **Document raw-string behavior:** Treat Codex `PostToolUse` strings as the intended compatibility contract and direct plugins to another surface for exit-code observability.
