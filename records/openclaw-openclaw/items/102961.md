## Label Justifications

- `P2`: The issue breaks plugin observability for Codex-native exec/bash failures with limited blast radius, but it is not a crash loop, security bypass, or first-run blocker.
- `impact:session-state`: Plugins receive incorrect per-tool outcome state for agent runs, causing hook consumers to misclassify command failures as successes.

## Summary

Keep open: current main still has the reported Codex-native exec/bash hook payload gap, because the native PostToolUse relay forwards Codex's hook-facing output value while the structured app-server command result is suppressed for native-relayed command items.

## What This Changes

The issue asks OpenClaw to expose structured status and exit-code data to `after_tool_call` for Codex-native exec/bash tool results instead of a flattened result string.

## Best Possible Solution

Define one canonical Codex-native `after_tool_call` observation that exposes structured status, exitCode, duration, and output/error text, then suppress the duplicate raw-string native relay for those tool calls.
