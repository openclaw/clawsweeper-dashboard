## Label Justifications

- `P2`: The issue breaks plugin observability for Codex-native exec/bash failures with limited blast radius, but it is not a crash loop, security bypass, or first-run blocker.
- `impact:session-state`: Plugins receive incorrect per-tool outcome state for agent runs, causing hook consumers to misclassify command failures as successes.

## Summary

Keep open: current main still forwards Codex native PostToolUse tool_response unchanged and suppresses the structured app-server observation for commandExecution/fileChange/MCP items, so Codex-native exec/bash failures can still reach plugins as indistinguishable bare strings.

## What This Changes

The issue requests that Codex-native exec/bash after_tool_call hooks receive structured result status and exit-code data instead of only flattened output text.

## Best Possible Solution

Define one canonical Codex-native after_tool_call observation that exposes structured status, exitCode, duration, and output/error semantics while preserving a documented text field for display-only consumers.
