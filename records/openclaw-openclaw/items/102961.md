## Label Justifications

- `P2`: The issue breaks plugin observability for Codex-native exec/bash failures with limited blast radius, but it is not a crash loop, security bypass, or first-run blocker.
- `impact:session-state`: Plugins receive incorrect per-tool outcome state for agent runs, causing hook consumers to misclassify command failures as successes.

## Summary

Keep open: current main still forwards Codex-native shell/apply_patch `PostToolUse` responses into `after_tool_call` as the raw Codex `tool_response`, while the structured app-server projection that has status, exitCode, and duration is suppressed for those same native items.

## What This Changes

Expose structured status/exit-code information to plugins observing Codex-native exec/bash-family calls through `after_tool_call`.

## Best Possible Solution

Define one canonical Codex-native `after_tool_call` observation that exposes status, exitCode, duration, and output text without emitting a duplicate raw-string event.
