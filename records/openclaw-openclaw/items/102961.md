## Label Justifications

- `P2`: The issue breaks plugin observability for Codex-native exec/bash failures with limited blast radius, but it is not a crash loop, security bypass, or first-run blocker.

## Summary

Keep open: current main still forwards Codex native PostToolUse output as the plugin-visible after_tool_call result, while the structured app-server command result path that has status, exitCode, and duration is suppressed when the native relay is enabled. The later operator comment adds real workflow impact and supports the same canonical structured-observation direction.

## What This Changes

The issue requests that Codex-native exec/bash after_tool_call events preserve structured ToolResult data such as status and exitCode instead of forwarding only flattened output text.

## Best Possible Solution

Define one canonical Codex-native after_tool_call observation that exposes structured status, exitCode, duration, and output/error text for shell/apply_patch while firing once per tool call and documenting the text-output compatibility field.

No complete fix exists yet. The best fix is to define one structured Codex-native after_tool_call payload path, preserve a text/output compatibility field, and add regression coverage that failing exec exposes exitCode/status instead of only output text.
