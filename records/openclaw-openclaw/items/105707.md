## Summary

The implementation and live proof credibly show the requested event-to-transcript correlation for embedded and CLI-backed runs, but merging intentionally exposes transcript row IDs as a client-facing, compatibility-sensitive Gateway contract.

## What This Changes

Adds an optional `messageId` for the assistant transcript row produced by a chat run to Gateway `final` and `aborted` events, including embedded and CLI-backed agent paths.

## System Context

Gateway chat clients receive lifecycle terminal events after an agent run. This PR carries the persisted assistant transcript row ID from embedded or CLI execution through the lifecycle layer to the WebSocket event so clients can identify the precise produced message.

  F --> G[Deduplication and message lookup]

## Best Possible Solution

Have Gateway owners explicitly adopt the optional field as a stable public identifier, with documented lifetime and compatibility expectations, or choose an opaque produced-message reference before merging.
