## Summary

Keep open: current main and the latest release still leave unconfigured periodic memory sync disabled and the interval timer still calls sync without forcing a memory-file rescan, while an open linked PR is the active candidate fix rather than a reason to close this issue.

## What This Changes

The issue reports that memory_search can return stale results when memory file watcher events stop and no periodic fallback reindexes modified memory files.

## Best Possible Solution

Land or replace the open candidate with a memory-core fix that makes interval sync a real catch-up path after missed watcher events, while explicitly deciding the upgrade behavior for any non-zero default interval.

## Reproduction Assessment

Yes at source level, but not from a live multi-hour run in this review: current main still resolves unconfigured intervalMinutes to 0 and the interval callback does not force a memory rescan after missed watcher events.

## Solution Assessment

Unclear as final product policy: the interval fallback path is the right repair surface, but maintainers need to decide whether changing the default from opt-in to a 30-minute background sync is acceptable.
