## Summary

Keep open: current main and the latest release still leave the default periodic memory sync disabled, and an interval tick would still call sync without first marking memory dirty, so a silent watcher failure can leave the index stale. The open closing PR is the right active fix candidate, but it is not merged and is currently conflicting/waiting on author.

## What This Changes

The issue asks for memory_search resilience when file-watch events stop, so changed memory files are reindexed instead of leaving stale SQLite index state.

## Best Possible Solution

Land or replace the linked fix with a maintainer-approved periodic fallback that marks memory dirty before interval sync, preserves explicit `intervalMinutes: 0` opt-out, updates config docs/schema labels, and proves fresh-install plus upgrade behavior before closing this issue.
