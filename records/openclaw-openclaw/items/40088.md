## Summary

Keep open: current main and v2026.6.11 still leave the central stale-index failure possible because periodic sync defaults to disabled and interval sync does not force a memory rescan when watcher events were missed. Current main has useful watcher hardening, and the open closing PR now owns the product-sensitive fallback fix.

## What This Changes

The issue reports that memory_search can serve a stale SQLite index after the memory file watcher stops firing, leaving modified memory files unindexed.

## Best Possible Solution

Land a focused watcher-independent rescan fallback, preferably by resolving https://github.com/openclaw/openclaw/pull/90019 or an equivalent change that preserves explicit interval opt-out, updates docs/schema, and proves fresh-install plus upgrade behavior.
