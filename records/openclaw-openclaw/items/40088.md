## Summary

Keep open: current main and the latest release still leave `memorySearch.sync.intervalMinutes` disabled by default, and the interval path still calls sync without forcing a memory rescan when watcher events are missed. The open linked PR is the active candidate fix, but it still needs maintainer/product review because changing the default fallback affects existing users.

## What This Changes

The issue reports that missed or stopped chokidar watcher events leave the memory search index stale and asks for watcher health/fallback sync/logging so `memory_search` finds recently changed files.

## Best Possible Solution

End with a maintainer-approved memory freshness fallback that rescans changed memory files after missed watcher events without surprising existing users, with config docs and regression tests aligned.
