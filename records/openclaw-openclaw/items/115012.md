## What This Changes

Count a successfully routed `/new` or `/reset` hook acknowledgement as visible delivery so dispatch does not also send the generic no-reply fallback.

## System Context

Auto-reply dispatch handles an incoming channel turn, runs reset hooks, and finalizes the turn by deciding whether a visible response was delivered. Reset hooks can route acknowledgements directly to the channel; the finalizer uses observed delivery to decide whether to emit the generic fallback.

## Architecture Diagram

flowchart LR
  A[Incoming channel command] --> B[Reset or new command handling]
  B --> C[Internal reset hooks]
  C --> D[Direct acknowledgement routing]
  D --> E[Observed delivery signal]
  E --> F[Dispatch finalization]
  F --> G[Normal acknowledgement or no-reply fallback]

## Best Possible Solution

Land a narrowly tested fix that reports only concrete reset-hook message delivery through the existing observed-delivery contract, then verify one real routable channel reset with a message-emitting hook produces exactly the acknowledgement and no generic fallback.
