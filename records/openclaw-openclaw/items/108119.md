## Summary

Keep this PR open for revision: the reported reset bug is valid, but cache eviction alone does not prove recovery while the timed-out ACP operation can still occupy the session actor, and the submitted simulation bypasses the changed timeout path.

## What This Changes

The PR adds a manager method for clearing a cached ACP runtime handle and makes cancel or close timeouts evict that handle before continuing ACP reset-state cleanup.

## Best Possible Solution

Use a manager-owned, identity-safe force-discard operation that atomically detaches the stale handle, best-effort terminates the underlying runtime outside the occupied actor, and proves a post-timeout turn reaches a fresh ACP session without late cleanup corrupting it.
