## Summary

Keep open: the report is valid, but this patch does not guarantee recovery because deleting the cached handle does not release a timed-out operation that still owns the session actor queue; a subsequent turn can remain blocked rather than creating a fresh runtime.

## What This Changes

The PR adds a manager method to evict one cached ACP runtime handle and calls it after cancel or close cleanup timeouts before resetting ACP session metadata.

## Best Possible Solution

Implement one canonical manager-owned recovery primitive that detaches the stale runtime and advances or replaces the poisoned actor generation, then prove both cancel-timeout and close-timeout paths complete a subsequent turn with a newly ensured runtime.
