## Label Justifications

- `P1`: The valid bug leaves ACP-backed user sessions unrecoverable through /reset and currently requires a gateway restart, while this patch still does not guarantee recovery.
- `merge-risk: 🚨 session-state`: The patch can reset persisted ACP metadata while the old serialized cleanup operation remains active, creating disagreement between metadata, cache, and runtime state.
- `merge-risk: 🚨 availability`: Cache-only eviction can leave a hung actor queue or orphaned backend process, so repeated recovery attempts may continue blocking the session or consume runtime resources.

## Summary

The underlying bug is valid, but this PR does not yet guarantee recovery: cache-only eviction does not release a timed-out operation that still owns the per-session actor queue, so the next turn can remain blocked. The open sibling PR is not a safe superseding close target because its proof is also test-only and currently marked as needing proof.

## What This Changes

The PR adds an ACP manager cache-eviction method and changes both session-reset cleanup timeout branches to evict the cached runtime handle, continue resetting ACP metadata, and allow a later message to initialize a fresh runtime.

## Best Possible Solution

Add a manager-owned force-discard operation that atomically detaches the exact cached handle outside the session actor queue, starts bounded or fire-and-forget cleanup without awaiting another hang, resets ACP metadata, and proves both timeout branches by sending a subsequent turn through a newly ensured runtime.
