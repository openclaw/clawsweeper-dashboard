## Label Justifications

- `P2`: A deterministic trajectory-export defect makes shared diagnostics unreadable but has no evidence of an emergency core-runtime outage.
- `impact:security`: The broken boundary is secret redaction for diagnostic bundles that users may share outside their local environment.
- `impact:data-loss`: The issue reports generated diagnostic JSON and JSONL being structurally corrupted and unusable by consumers.

## Summary

Keep open. Current-main evidence shows trajectory export applies a string redactor after JSON/JSONL serialization, so a match that spans serialized syntax can make the exported diagnostic bundle unparsable. This is a narrow regression in a security-sensitive export path, not a feature request or an obsolete report.

## What This Changes

Fix trajectory export so secret masking cannot corrupt serialized JSON or JSONL diagnostic files.

## System Context

Trajectory export collects session and runtime diagnostics, sanitizes sensitive fields, serializes them into a shareable support bundle, and writes the bundle files to disk. The reported defect is at the final redaction boundary after serialization, where a text replacement can alter JSON structure rather than only data values.

## Architecture Diagram

flowchart LR
  A[Session and runtime diagnostics] --> B[Structured path and secret redaction]
  B --> C[JSON and JSONL serialization]
  C --> D[Final text redaction]
  D --> E[Trajectory support bundle]
  E --> F[User or support consumer]
  D -. can alter syntax .-> G[Invalid JSON or JSONL]

## Best Possible Solution

Keep structured redaction as the sole redaction boundary for trajectory-export values, remove the post-serialization raw-text rewrite if coverage remains equivalent, and add a focused regression that parses every JSON file and each non-empty JSONL line while proving synthetic secrets are absent.
