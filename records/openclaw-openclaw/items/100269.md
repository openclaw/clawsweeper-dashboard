## Label Justifications

- `P1`: The report describes a broken agent/channel delivery path where scheduled or agent-initiated messages can fail before reaching the user.
- `impact:message-loss`: The central impact is silent failure to deliver Telegram messages when optional reply/thread routing params are emitted as blank strings.

## Summary

Keep open: current main and the latest release still reject blank optional integer params, and the linked open fix PR is the candidate implementation path. This issue should remain open until https://github.com/openclaw/openclaw/pull/100273 lands or maintainers choose a replacement fix.

## What This Changes

Treat blank optional Telegram reply/thread integer tool parameters as unset so message sends do not fail when models emit empty defaults.

## Best Possible Solution

Land the linked shared-reader fix, or an equivalent narrow change, so blank optional integer params are absent while real invalid values remain rejected.

## Maintainer Decision

## Reproduction Assessment

Yes. A minimal source reproduction is `readPositiveIntegerParam({ replyTo: "" }, "replyTo")`: blank strings are ignored by `readNumberParam`, then the wrapper throws because the raw param is non-null.

## Solution Assessment

Yes. Fixing the shared optional integer readers is the best narrow shape because Telegram and other tool params share this parsing contract, while channel-local sanitizers would duplicate the invariant.
