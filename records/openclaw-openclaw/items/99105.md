## Summary

Keep open. This PR is a focused candidate for the source-proven Active Memory recall-lane serialization problem; I found no blocking code defect, but merge should wait for inspectable after-fix real behavior proof and maintainer acceptance of the higher multi-agent recall concurrency.

## What This Changes

The PR changes Active Memory embedded recall to enqueue on `active-memory:<agentId>` instead of the single `active-memory` lane and updates the lane assertion test.

## Best Possible Solution

Land the per-agent lane fix once redacted multi-agent proof is posted and maintainers accept the default concurrency change; otherwise move the same fix behind an explicit concurrency design in the canonical reliability issue.

## Reproduction Assessment

Yes, from source inspection rather than a live run: current main passes a fixed `active-memory` lane to `runEmbeddedAgent`, the embedded runner enqueues global work on that lane, and new lanes default to one active task.

## Solution Assessment

Yes with maintainer acceptance: changing the lane at the Active Memory recall call site is the narrowest fix for cross-agent serialization; a configurable concurrency knob is the safer alternative if maintainers want to preserve a global throttle.
