## Summary

Keep open: current main and v2026.6.11 still lack label-backed subagent role-file lookup, frontmatter parsing, role-file prompt injection, or role-file model/tool semantics. This remains a real feature gap, but it needs maintainer product and security direction before implementation.

## What This Changes

The issue requests lightweight per-role markdown instruction files for ephemeral `sessions_spawn` subagents, with optional frontmatter for model/tool settings and automatic prompt injection by label.

## Best Possible Solution

Define a maintainer-approved subagent role-profile contract covering lookup precedence, explicit spawn argument overrides, narrowing-only tool policy, model/provider limits, memory ownership, and loaded-file audit metadata before implementation.

## Reproduction Assessment

Yes, at source level. Current `main` and v2026.6.11 accept a `label` but have no path that resolves `subagents/<label>.md`, parses frontmatter, applies role defaults, or injects the role-file body into the child prompt.

## Solution Assessment

Unclear until maintainers choose the product and security boundary. The proposed file convention is plausible, but prompt authority, tool narrowing, model overrides, memory, and audit semantics must be settled first.
