## Summary

Keep open: current main and v2026.6.11 still do not implement label-backed subagent role-file lookup, YAML frontmatter parsing, role-file prompt injection, or role/memory audit metadata. The request is a real source-verifiable feature gap, but it adds a trusted prompt/model/tool-policy surface and needs maintainer product and security direction before implementation.

## What This Changes

Requested support for persistent per-role Markdown instruction files loaded by `sessions_spawn(label=...)`, with optional model/tools frontmatter and workspace-over-user precedence.

## Best Possible Solution

Define a maintainer-approved subagent role-profile contract covering lookup precedence, explicit spawn-argument overrides, narrowing-only tool policy, model/provider limits, memory/writeback ownership, and loaded-file audit metadata before implementing the file convention.

## Reproduction Assessment

Yes, for source-level verification of the missing capability. Current main accepts `label` but has no path that resolves `subagents/<label>.md`, parses frontmatter, applies role defaults, or injects a role-file body before the child run starts.

## Solution Assessment

Unclear until maintainers choose the product and security boundary. The proposed file convention is plausible, but the safest solution needs one coherent contract across role files, promptMode, per-spawn tools, model overrides, memory, and audit metadata.
