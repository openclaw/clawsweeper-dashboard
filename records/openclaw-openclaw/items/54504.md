## Label Justifications

- `P2`: This is a meaningful multi-agent ergonomics and policy feature with source-level evidence, but it is not an outage or urgent shipped regression.
- `impact:session-state`: The requested role and memory files would change persistent context, persona, and writeback behavior for spawned subagent sessions.

- `impact:auth-provider`: The proposed `model` frontmatter can change provider/model routing for spawned subagent sessions.

## Summary

Keep open: current main and v2026.6.11 still do not implement label-backed subagent role files, frontmatter parsing, role-body prompt injection, or loaded-file audit metadata; the issue is still a valid feature request that needs product and security direction.

## What This Changes

Request persistent per-role Markdown instruction files for `sessions_spawn` native subagents, keyed by `label`, with optional model/tool frontmatter and workspace/user lookup precedence.

## Best Possible Solution

Define a maintainer-approved subagent role-profile contract covering lookup precedence, explicit-argument overrides, narrowing-only tool/model semantics, memory/writeback ownership, and loaded-file audit metadata before implementation.
