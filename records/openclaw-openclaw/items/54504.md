## Label Justifications

- `impact:auth-provider`: The proposed frontmatter can select models, which touches provider/model routing semantics for subagent sessions.

## Summary

Keep open: current main and v2026.6.11 still lack label-backed subagent role-file lookup, frontmatter parsing, prompt injection from `subagents/<label>.md`, or loaded-file audit metadata, and the June workflow comment shows this remains a live multi-agent ergonomics gap that needs product and security direction.

## What This Changes

The issue requests lightweight per-role subagent instruction files that `sessions_spawn` can auto-load by label, including prompt body and optional frontmatter for model/tool overrides.

## Best Possible Solution

Define a maintainer-approved core contract for label-backed subagent role files, including lookup precedence, capability-narrowing rules, explicit-argument precedence, loaded-file audit metadata, docs, and focused tests; otherwise add a generic plugin/API seam before moving this to ClawHub.

Yes for the feature gap: current `sessions_spawn` source and docs show no label-backed role-file lookup, no role-file frontmatter parsing, and no loaded-file audit output. The existing `label` and `taskName` paths only provide metadata/targeting, not persistent role instructions.

## Solution Assessment

Unclear: label-backed role files are a plausible narrow user-facing shape, but the model/tool frontmatter and file precedence need maintainer security and product design before implementation. A plugin seam may be the better end state if maintainers want the convention outside core.
