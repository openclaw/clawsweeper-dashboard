## Summary

Keep open: current main and v2026.6.11 still lack label-backed subagent role-file lookup, frontmatter parsing, role-file prompt injection, or role-file audit metadata. This is a real multi-agent ergonomics gap, but it needs maintainer product and security direction before implementation.

## What This Changes

The issue requests markdown-backed, per-role subagent instruction files that auto-load for `sessions_spawn` labels without requiring full configured agents.

## Best Possible Solution

Define a maintainer-approved subagent role-profile contract covering lookup precedence, explicit-argument overrides, narrowing-only tool policy, model/provider limits, memory ownership, loaded-file audit metadata, and docs before implementation.

## Reproduction Assessment

Yes, at source level. Current main accepts `label` but has no path that resolves `subagents/<label>.md`, parses frontmatter, applies role defaults, or injects a role-file body before the child run starts.

## Solution Assessment

Unclear until maintainers choose the product and security boundary. The proposed file convention is plausible, but prompt authority, tool narrowing, model overrides, memory, and audit semantics must be settled first.
