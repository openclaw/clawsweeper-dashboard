## Summary

Keep open: current main still lacks label-backed subagent role-file discovery, frontmatter parsing, and automatic prompt injection for ephemeral `sessions_spawn` workers; the request is a real feature gap, but the trusted prompt/model/tool-policy surface needs maintainer product and security direction before implementation.

## What This Changes

The issue requests persistent per-role markdown instruction files for ephemeral `sessions_spawn` subagents, keyed by spawn label, with optional model and tool frontmatter.

## Best Possible Solution

Define the supported role-file contract first: discovery paths, precedence with explicit spawn args, allowed frontmatter, tool narrowing without expansion, model allowlists, audit/provenance output, docs, and tests.

## Reproduction Assessment

Yes, from source: `sessions_spawn` accepts and forwards `label`, but current main only renders that label as prompt metadata and has no role-file lookup or frontmatter application path.

## Solution Assessment

Unclear: the role-file UX is plausible and aligns with the reported workflow, but the best implementation requires maintainer decisions on security, precedence, provider/model constraints, and whether memory write-back belongs in the same contract.
