## Summary

Keep open: current main only covers the empty-receipt accounting slice, while Weixin still can return a non-empty local client messageId that OpenClaw treats as sent even when recent production reports show user-visible delivery loss.

## What This Changes

The issue requests reliable Weixin proactive/direct delivery semantics so OpenClaw does not report local message IDs as final success when user-visible delivery fails.

## Best Possible Solution

Keep this as the canonical Weixin delivery-status thread and define a core/plugin contract where Weixin can report failed, accepted/unknown, or pending instead of final delivered when recipient visibility is not confirmed.

## Reproduction Assessment

No high-confidence current-main live Weixin reproduction was run here. Source inspection and recent comments support the false-confidence path, but proving the user-visible fallback still needs live iLink/Weixin validation.

## Solution Assessment

Unclear as a concrete implementation. The maintainable solution is a maintainer-approved core/plugin delivery-status contract plus external-plugin behavior and live proof, not only the already-merged empty-receipt accounting fix.
