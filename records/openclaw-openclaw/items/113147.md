## Summary

Current OpenClaw documentation already describes a last-mile `reply_payload_sending` plugin hook that can rewrite outbound agent replies, so a separate core `beforeReply` hook is not yet justified. This issue remains open because the requested model, harness, surface, and per-thread metadata contract has not been shown to be available through that existing hook; a maintainer should decide whether that gap warrants a narrowly scoped plugin API addition rather than a new core reply-suffix setting.

## What This Changes

Request a deterministic per-agent reply signature through a template-based config setting or a plugin hook that can inspect runtime reply metadata before delivery.

## System Context

Agent replies are assembled by the agent loop and then handed to channel delivery adapters. Plugin lifecycle hooks can observe or replace the outgoing reply payload just before it reaches Slack or another configured transport.

## Architecture Diagram

flowchart LR
  A[Agent run] --> B[Assembled reply payload]
  B --> C[Plugin outbound hook]
  C --> D[Channel delivery adapter]
  D --> E[Slack or other surface]
  C --> F[Per-thread signature state]

## Best Possible Solution

First prove whether a ClawHub plugin using the existing outbound payload hook can implement the signature with stable per-thread state; add only the smallest documented plugin-context metadata that is demonstrably missing, rather than a new core reply-suffix configuration system.
