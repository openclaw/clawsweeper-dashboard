## Summary

Keep this open. Current main still records Responses token usage only on `response.completed`, while the linked fix PR is open and uses closing syntax for this issue, so the issue should remain the canonical tracker until that PR merges or is rejected.

## What This Changes

The issue asks OpenClaw to preserve Azure/OpenAI Responses token usage during early-abort streams instead of reporting zero usage when no `response.completed` event arrives.

## Best Possible Solution

Review and land or close https://github.com/openclaw/openclaw/pull/101608; once an equivalent fix is merged, close this issue against the merge commit and proof.

## Reproduction Assessment

Yes at source-contract level: current main records Responses usage only on `response.completed`, while the OpenAI SDK contract shows `response.incomplete` can carry a `Response.usage`. I did not verify this with a live Azure stream transcript.

## Solution Assessment

Yes, the narrow maintainable fix is to record terminal usage and cost for `response.incomplete` in the Responses processors. The open linked PR is the current candidate, so this issue should not spawn a second fix lane.
