## Summary

Keep open: current main and latest stable release still lack a shared path-scoped RWX permission map for file tools and exec; the direct implementation PRs are closed unmerged, and the remaining work needs security/product ownership.

## What This Changes

The issue requests a path-keyed read/write/execute permission policy applied consistently to exec plus read/write/edit/apply_patch tools while preserving existing exec allowlist compatibility.

## Best Possible Solution

Settle an owner-approved path permission contract first, including canonical config shape, migration/doctor behavior, file-tool and exec enforcement semantics, OS sandbox role, docs, and focused tests, then land one focused security-hardening implementation.

## Reproduction Assessment

Yes. Source inspection on current main and v2026.6.11 shows only boolean workspace-only filesystem policy plus exec approval/sandbox guardrails, not a path-scoped RWX policy shared across file tools and exec.

## Solution Assessment

No as an automated one-shot fix. The RWX direction fits the security gap, but maintainers need to settle the config, migration, threat model, and enforcement contract before implementation.
