## What This Changes

This PR replaces Control UI query-based session selection with readable `/chat/...` and `/dashboard/...` paths, adds session-path parsing and resolution, and updates Control UI and ClickClack link producers.

## System Context

Control UI link producers turn session keys into URLs, while the browser router resolves those URLs into chat or dashboard session state. ClickClack also publishes Control UI links for managed discussion channels, so both surfaces must preserve the same URL contract.

## Architecture Diagram

flowchart LR

  B --> C[Control UI session path]
  C --> D[Browser route loader]
  D --> E[Resolved session]
  E --> F[Chat or dashboard view]
  B --> G[ClickClack discussion link]

## Best Possible Solution

Define one maintainable session-URL contract that ClickClack can consume through its supported dependency boundary, and preserve or explicitly approve a migration path for released query-form deep links before making path URLs canonical.
