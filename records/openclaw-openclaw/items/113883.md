## Summary

Keep this PR open for revision. The readable-path direction is useful, but the current patch intentionally breaks released query-form session links and still duplicates the URL-building grammar inside ClickClack rather than giving both consumers one executable contract. ## What This Changes

This PR replaces Control UI query-based session links with readable chat and dashboard paths, adds route parsing and resolution, and updates UI navigation, native route memory, ClickClack links, tests, and documentation.

## System Context

Control UI navigation turns a selected session into a browser URL, then resolves that URL through the Gateway session list into the chat or dashboard view. ClickClack also publishes Control UI links into managed discussion channels, so its generated URLs must stay compatible with the UI route parser.

Preserve query-form deep links as a bounded migration reader that replaces them with the canonical path, and make the session URL package consumable by ClickClack rather than maintaining a copied grammar; then add redacted live browser or terminal proof of path resolution, canonicalization, and legacy-link migration.
