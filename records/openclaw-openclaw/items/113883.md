## Summary

Keep this draft PR open for maintainer review. The path-based session model is a coherent feature direction, but the branch deliberately stops resolving released `?session=` and `?face=` links, including links previously emitted into ClickClack discussion history; that is an upgrade-breaking public URL contract change and needs an explicit compatibility decision before merge.

## What This Changes

This PR moves Control UI session identity from query parameters into readable `/chat/...` and `/dashboard/...` paths, adds a shared session-URL contract package, and updates Control UI and ClickClack links to use it.

## System Context

The Control UI turns a browser location into a session selection and renders either its chat or dashboard face. Session links are also emitted by UI navigation and the ClickClack plugin, so the route parser must preserve a stable public link contract across browser, native-shell, and plugin entry points.

## Architecture Diagram

flowchart LR

  C --> D{Short ID or literal key}
  D --> E[Session lookup]
  E --> F[Chat session view]
  E --> G[Dashboard session view]
  F --> H[Canonical browser URL]
  G --> H

## Best Possible Solution

Retain the readable path format as the canonical URL, but add a narrow one-way migration at the Control UI route boundary that resolves released `?session=`/`?face=` links once and replaces them with the canonical path; cover both normal browser and native-route restore upgrades.
