## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.99

Full review comments:

- **[P1] Keep emission authority out of the public SDK:** `src/plugin-sdk/diagnostic-runtime.ts:34`
  - body: `diagnostic-runtime` publicly exports `emitPluginSafetyEvent`, whose interface accepts caller-supplied `pluginId`, `trusted`, and declared event types. A plugin can therefore import it directly, set `trusted: true`, and bypass the manifest policy that the service-context wrapper is meant to enforce. Keep this helper core-internal and expose only a host-bound closure derived from loader-known identity and manifest state.
  - confidence: 0.99
- **[P1] Construct the service-context emitter at runtime:** `src/plugins/types.ts:2464-2469`
  - body: This adds `emitSafetyEvent` only to the `OpenClawPluginServiceContext` type; none of the loader, registry, or service-context construction paths are changed to provide it. Plugin services will therefore receive `undefined`, so the advertised API cannot be used. Build the closure where the host already knows the plugin record and manifest.
  - confidence: 0.99
- **[P1] Parse and validate the manifest permission field:** `src/plugins/manifest.ts:405-414`
  - body: Adding `safetyEventTypes` to the TypeScript interface does not make it survive `openclaw.plugin.json` loading: the manifest loader explicitly normalizes supported fields, and this PR does not add a normalization or validation path. External plugin declarations will be absent at runtime and valid emissions will be rejected. Normalize the array against the canonical event-type set and cover malformed manifests.
  - confidence: 0.99
- **[P1] Validate complete event payloads before dispatch:** `src/plugins/safety-event-emission.ts:78-94`
  - body: The wrapper validates only the event discriminant before forwarding the object. Published plugins execute as JavaScript and can pass missing required fields, invalid enum strings, non-finite scores, or unhashed privacy fields despite the TypeScript union. Add runtime validation for each event shape and reject malformed events before they reach diagnostics or exporters.
  - confidence: 0.98
- **[P1] Wire the browser example through a reachable capability:** `extensions/browser/src/browser-tool.ts:407-420`
  - body: The browser tool accepts an optional emitter, but the PR changes no production caller to supply it. The normal browser tool therefore continues navigating without emitting anything, so this is not a working reference integration. Pass a host-bound capability at the actual construction boundary or use an existing reachable hook owned by the browser plugin.
  - confidence: 0.98
- **[P2] Use host-owned diagnostic session identity:** `extensions/browser/src/browser-tool.ts:898-904`
  - body: The browser event copies `agentSessionKey` into `sessionId` and falls back to the shared literal `unknown`. A routing session key is not necessarily the diagnostic session identifier, and the fallback merges unrelated events into one session bucket. Bind the active diagnostic session context in the host-provided emitter instead of asking the tool to synthesize it.
  - confidence: 0.96
