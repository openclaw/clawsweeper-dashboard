Full review comments:

- **[P1] Bind emission authority to host-known plugin identity:** `src/plugins/safety-event-emission.ts:56`
  - body: `emitPluginSafetyEvent` is publicly exported while accepting `pluginId`, `trusted`, and declared permissions from its caller. Any plugin can therefore pass `trusted: true` or claim an allowlist and bypass the policy. Keep this helper core-private and expose only a closure the host constructs from the loaded plugin record and normalized manifest.
  - confidence: 0.99
- **[P1] Construct the service-context emitter at runtime:** `src/plugins/types.ts:2472`
  - body: This adds only an optional context type; no changed loader or service-registration path constructs `emitSafetyEvent`. A real plugin therefore receives `undefined`, so the advertised API cannot work outside direct helper tests. Bind the host-created emitter when constructing each plugin service context and cover that path with an installed-plugin test.
  - confidence: 0.99
- **[P1] Parse and validate the manifest permission field:** `src/plugins/manifest.ts:415`
  - body: Adding `safetyEventTypes` to `PluginManifest` does not make the manifest loader read or validate the raw JSON field. The declaration is consequently unavailable to the host authorization path. Normalize it through the manifest parser, reject unknown or malformed entries, and add manifest-loading contract tests.
  - confidence: 0.99
- **[P1] Validate complete event payloads before dispatch:** `src/plugins/safety-event-emission.ts:77`
  - body: The helper checks only the `type` string and relies on TypeScript for every required field and enum value. JavaScript plugins or unsafe casts can send malformed operator-facing events into the dispatcher. Apply per-event runtime schema validation and return a logged rejection before either trusted emitter is called.
  - confidence: 0.98
- **[P1] Wire the browser example through a reachable capability:** `extensions/browser/src/browser-tool.ts:899`
  - body: Navigation invokes an optional `opts.emitSafetyEvent`, but no browser registration or caller in this PR passes that option. The claimed reference implementation therefore emits nothing in production. Wire the actual browser plugin registration to a supported host capability or remove the example until that capability exists.
  - confidence: 0.98
- **[P2] Use host-owned diagnostic session identity:** `extensions/browser/src/browser-tool.ts:901`
  - body: The browser event records `agentSessionKey` or `unknown`, and the generic plugin input lets callers provide any `sessionId`; neither guarantees the active diagnostic session. This can mis-associate safety telemetry across sessions. Have the host-bound emitter stamp the active diagnostic session and plugin provenance instead of accepting them from event input.
  - confidence: 0.97
