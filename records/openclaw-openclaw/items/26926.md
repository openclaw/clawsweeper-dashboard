## Summary

Keep open: current main and the latest release still handle Synology Chat inbound webhooks as text-only, while the requested image, CSV, and PDF attachment path remains missing and security-sensitive.

## What This Changes

The issue requests inbound image, CSV, and PDF attachment support for the Synology Chat plugin.

## Best Possible Solution

Confirm Synology's attachment webhook and retrieval contract, then add plugin-local bounded inbound media parsing and staging that feeds the existing generic media context fields, with docs and focused tests.

## Reproduction Assessment

Yes, at source level: an attachment-only Synology webhook cannot pass the required-text parser, and the delivery/context path has no media fields. A real NAS attachment webhook payload is still missing, so the external API shape is not fully reproduced.

## Solution Assessment

Unclear as a minor code extension until Synology's attachment event and retrieval contract are confirmed. If that contract supports the feature, plugin-local bounded retrieval/staging plus generic media-context population is the narrowest maintainable direction.
