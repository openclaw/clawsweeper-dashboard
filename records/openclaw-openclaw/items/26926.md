## Summary

Keep open: current main and v2026.6.11 still treat Synology Chat inbound webhooks as required-text messages; generic inbound media context exists, but Synology-specific attachment parsing, retrieval, and staging are still missing.

## What This Changes

Request support for inbound images, CSV files, and PDFs in the bundled Synology Chat plugin.

## Best Possible Solution

Confirm Synology's attachment webhook/retrieval contract, then implement plugin-local bounded parsing and safe retrieval/staging into the existing inbound media context with docs and focused tests.

## Reproduction Assessment

Yes, source-level: an attachment-only Synology webhook cannot pass parsePayload because token, user_id, and text are required, and the dispatch path only builds text context. A real NAS attachment webhook payload is not in the issue, so the external API shape is not fully reproduced.

## Solution Assessment

Unclear until Synology's attachment event/retrieval contract and safe download policy are confirmed. If confirmed, plugin-local bounded retrieval/staging into existing inbound media context is the narrowest maintainable direction.
