Keep open: current main and the latest release still parse Synology Chat inbound webhooks as text-only, and the existing outbound `file_url` media path does not solve inbound image, CSV, or PDF attachment delivery. ## What This Changes

Request to support inbound images, CSV files, and PDFs in Synology Chat instead of text-only inbound messages.

## Best Possible Solution

Confirm Synology's outgoing-webhook attachment and retrieval contract, then implement plugin-local bounded inbound media parsing, safe retrieval/staging, generic media-context population, docs, and focused tests.
