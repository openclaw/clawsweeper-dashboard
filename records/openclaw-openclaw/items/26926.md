## Summary

Keep open: current main and v2026.6.11 still handle Synology Chat inbound webhooks as required-text messages, while media support remains outbound URL delivery only. The remaining work is real, but it needs Synology attachment-contract confirmation plus a safe retrieval/staging policy before implementation.

## What This Changes

Request support for inbound images, CSV files, and PDFs in the bundled Synology Chat plugin.

## Best Possible Solution

Confirm Synology's attachment webhook/retrieval contract, then implement plugin-local bounded inbound media parsing, safe staging, generic media-context population, docs, and focused tests.

## Reproduction Assessment

Yes, at source level: an attachment-only Synology webhook cannot pass the required-text parser and the delivery/context path has no media fields. The exact live Synology attachment payload still needs external contract proof.

## Solution Assessment

Unclear until Synology's attachment event and retrieval contract are confirmed. If that contract supports the feature, a plugin-local implementation using existing generic media context is the narrowest maintainable direction.
