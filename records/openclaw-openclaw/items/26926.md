## Summary

Keep open: current main and v2026.6.11 still require text in Synology Chat inbound webhooks and document media only as outbound URL delivery; the remaining work is the Synology-specific attachment contract plus safe retrieval/staging policy.

## What This Changes

Request support for images, CSV files, and PDFs sent through the existing Synology Chat plugin into OpenClaw.

## Best Possible Solution

Confirm Synology's attachment webhook/retrieval contract, then add bounded plugin-local inbound attachment parsing, safe staging, generic media-context population, docs, and focused tests.

## Reproduction Assessment

Yes, at source level: an attachment-only Synology webhook cannot pass the required-text parser, and the delivery/context path has no media fields. A real NAS attachment webhook payload is still missing, so the external API shape is not fully reproduced.

## Solution Assessment

Unclear until Synology's attachment event and retrieval contract are confirmed. If that contract supports the feature, plugin-local bounded retrieval/staging plus existing media-context population is the narrowest maintainable direction.
