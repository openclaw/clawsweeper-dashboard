## Summary

Keep open: current main and v2026.6.11 still handle Synology Chat inbound webhooks as required-text messages, while media support remains outbound URL delivery only. The request is valid, but implementation should wait for maintainer-confirmed Synology attachment retrieval details and safe file-staging policy.

## What This Changes

The issue requests inbound image, CSV, and PDF attachment support for the Synology Chat channel plugin.

## Best Possible Solution

Confirm Synology's user-upload attachment webhook and retrieval contract, then implement plugin-local bounded inbound media parsing, safe retrieval/staging, generic media-context population, docs, and focused tests.

## Reproduction Assessment

Yes, at source level: an attachment-only Synology webhook cannot pass the required-text parser, and the Synology delivery/context path has no media fields. A real NAS attachment payload is still missing, so the external API shape is not fully reproduced.

## Solution Assessment

Unclear until Synology's attachment event and retrieval contract are confirmed. If that contract supports the feature, plugin-local bounded retrieval/staging plus generic media-context population is the narrowest maintainable direction.
