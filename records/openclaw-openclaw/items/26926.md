## Summary

Keep open: current main and the latest release still keep Synology Chat inbound webhooks on a required-text path, while attachment/media support is only outbound URL delivery. The remaining work is real, but it needs Synology attachment-contract confirmation plus a security-reviewed retrieval and staging policy before an implementation worker should run.

## What This Changes

The issue requests inbound Synology Chat attachment support for images, CSV files, and PDFs.

## Best Possible Solution

Confirm Synology's attachment webhook and retrieval contract, then implement plugin-local bounded inbound media parsing, safe retrieval/staging, generic media-context population, docs, and focused tests.

## Reproduction Assessment

Yes, at source level: an attachment-only Synology webhook cannot pass the required-text parser, and the delivery/context path has no media fields. A real NAS attachment webhook payload is still missing, so the external API shape is not fully reproduced.

## Solution Assessment

Unclear as a minor code extension until Synology's attachment event and retrieval contract are confirmed. If that contract supports the feature, plugin-local bounded retrieval/staging plus generic media-context population is the narrowest maintainable direction.
