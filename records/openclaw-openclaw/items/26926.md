## Summary

Keep open: current main and v2026.6.11 still require text in Synology inbound webhooks and do not propagate attachment/media context; related Synology work covers ACK/HEAD behavior or outbound URL validation, so this remains the canonical attachment feature pending maintainer security/product direction.

## What This Changes

The issue requests inbound Synology Chat support for images, CSV files, and PDFs instead of limiting the plugin to text and outbound URL-based media.

## Best Possible Solution

Confirm Synology's attachment payload and retrieval contract, then implement bounded plugin-local parsing, safe retrieval/staging, generic inbound media-context population, docs, and focused tests; if the security cost is too high, document Synology Chat as text/outbound-file-only.
