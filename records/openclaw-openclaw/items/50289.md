## Summary

Keep open: current main and the latest release still normalize large `commands.ownerAllowFrom` arrays and perform linear sender membership checks during command authorization, and both linked fix attempts are closed unmerged.

## What This Changes

The issue asks OpenClaw to make large `commands.ownerAllowFrom` command-authorization checks scale through cached or compiled lookups instead of repeated linear scans.

## Best Possible Solution

Add a narrow command-auth fix that caches or compiles provider/account-scoped owner allowlists and uses O(1) sender membership while preserving wildcard, provider-prefix, plugin formatting, context override, and config-reload semantics.

Yes, at source level: current main still walks the raw owner allowlist, resolves it twice per authorization pass, and uses linear `includes` membership checks. I did not run a live 9,000-entry Docker/Gateway benchmark in this read-only review.

## Solution Assessment

Yes for keeping this issue open and queuing a narrow repair: the maintainable fix belongs in command-auth lookup state, not in a new config workaround or broader access-control redesign.
