## Summary

Keep open: current main and v2026.6.11 still rebuild and scan the owner allowlist in command authorization, and both linked fix PRs are closed unmerged, so the central slowdown remains actionable.

## What This Changes

The issue reports severe gateway latency when commands.ownerAllowFrom contains thousands of entries because owner authorization still does linear list processing during message command handling.

## Best Possible Solution

Add a focused command-auth fix that compiles or memoizes provider-scoped owner allowlists from the stable config snapshot, uses Set membership for repeated checks, and preserves current ownerAllowFrom semantics.

## Reproduction Assessment

Yes at source level: current main still walks ownerAllowFrom arrays and uses Array.includes for owner membership in resolveCommandAuthorization. I did not run a live 9,000-entry gateway benchmark.

## Solution Assessment

No, current main is not the best state because it preserves the O(n) hot path. The maintainable fix is a narrow compiled or memoized authorization lookup that keeps existing config semantics and adds regression coverage for provider scoping and reload invalidation.
