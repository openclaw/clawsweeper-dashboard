## Summary

Keep open: current main and the latest release still reprocess large `commands.ownerAllowFrom` arrays and use linear membership checks during command authorization, and every linked fix PR is closed unmerged.

## What This Changes

Reported behavior: Gateway message handling slows severely when `commands.ownerAllowFrom` contains thousands of user IDs because command authorization repeatedly normalizes and searches that list.

## Best Possible Solution

Land a narrow command-auth optimization that compiles or caches normalized owner authorization state and membership Sets per stable config snapshot/provider while preserving the existing `commands.ownerAllowFrom` schema and semantics.
