## Summary

Keep open: current main and v2026.6.11 still normalize and scan large `commands.ownerAllowFrom` arrays during command authorization, and the focused linked fix PR is now closed unmerged with no replacement found.

## What This Changes

The issue reports severe gateway latency when `commands.ownerAllowFrom` contains about 9000 entries because authorization repeatedly normalizes and searches large allowlists.

## Best Possible Solution

Preserve the current command-owner authorization semantics while caching normalized owner allowlists and using constant-time membership checks on the hot path.

## Reproduction Assessment

Yes, by source inspection: a large `commands.ownerAllowFrom` list still forces per-authorization list walking and linear membership checks in the current command authorization path. I did not run a live 9000-entry Docker repro because this review is read-only and source proof is enough to keep the item open.

## Solution Assessment

Yes, a narrow hot-path optimization in `src/auto-reply/command-auth.ts` is the best shape. It should keep the existing config contract and owner semantics while caching normalized results per config/list/provider context and avoiding repeated linear membership scans.
