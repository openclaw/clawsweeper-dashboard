## Summary

This is a credible current-release configuration-reload bug, not an obsolete compaction request: the report identifies a specific no-op classification that leaves a process-captured setting unchanged while the operator sees only a generic reload-evaluation log. Keep it open for a maintainer choice on the supported reload contract, then make the narrow gateway/runtime fix with regression coverage.

## What This Changes

Make edits to `agents.defaults.compaction.*` either take effect through supported hot reload or clearly require a gateway restart instead of being silently treated as no-ops.

## System Context

OpenClaw watches its canonical configuration and the Gateway decides whether a changed path is hot-reloadable, restart-required, or inert. Those settings then feed agent-turn compaction, which chooses compaction behavior and models while sessions run.
