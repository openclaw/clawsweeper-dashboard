## Summary

Keep open for a maintainer product decision. Current `before_prompt_build` exposes only the user prompt and prepared session messages while allowing a whole-system-prompt replacement, so the requested inspection gap remains; however, publishing prompt components would create a broad, security- and compatibility-sensitive Plugin SDK contract. Likely related people: Kaspre is a low-confidence recent contributor to the hook runner; an SDK/prompt-pipeline owner should make the direction call.

## What This Changes

Add read-only access to the composed system prompt, and potentially its structured inputs, in the modifying `before_prompt_build` plugin hook so prompt-optimisation plugins can make informed changes.

## System Context

OpenClaw loads a session and assembles a system prompt from core guidance, context, tools, skills, and run-specific inputs before submitting a model call. Plugins can participate through typed hooks, where `before_prompt_build` can add or replace prompt text and `before_agent_run` can inspect the final prompt only to allow or block the run.

## Architecture Diagram

flowchart LR
  A[Session and user input] --> B[Prompt assembly]
  C[Tools, skills, and context] --> B
  B --> D[before_prompt_build hook]
  D --> E[Final system prompt]
  E --> F[before_agent_run gate]
  F --> G[Model submission]

## Best Possible Solution

Adopt the smallest stable SDK seam first: an immutable read-only current system-prompt snapshot on `before_prompt_build`, guarded by the agreed trusted-plugin policy; defer component identities and component-level mutation until a concrete cross-harness contract and use cases justify them.
