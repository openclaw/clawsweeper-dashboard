## Summary

Keep this PR open for owner review. It targets a high-impact, reproducible Codex relay exhaustion path, but it replaces the default hook execution route with a new packaged runtime entry while two architecture/dependency checks are failing and the required direct Codex contract inspection is not yet complete.

## What This Changes

This PR adds a lightweight Codex native-hook relay process, bounded per-relay admission and cancellation handling, and overload responses so hook traffic no longer repeatedly launches the full OpenClaw CLI.

## System Context

Codex hook commands are launched during agent tool and approval events, then relay requests to the long-lived OpenClaw Gateway for policy decisions. This PR changes the local command path before the Gateway receives those requests, affecting hook availability, approval outcomes, and process resource use.

## Architecture Diagram

  F --> G[Codex allow deny or noop response]

## Best Possible Solution

Keep Gateway policy ownership unchanged, land a minimal relay only after the packaging/topology gates and a direct Codex hook-contract review prove that normal, overload, disconnect, stale-registration, and explicit `OPENCLAW_CLI_PATH` override behavior remain compatible.
