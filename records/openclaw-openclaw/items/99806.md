## Summary

Keep open: the reported bug is valid and this PR has useful proof, but the direct `cancelled` finalization can freeze the task row before current late-completion recovery updates the subagent run to successful, so the patch needs changes before merge.

## What This Changes

The branch finalizes killed subagent task rows as `cancelled` in the shared subagent termination primitive and adds focused subagent-control tests for kill paths.

## Best Possible Solution

Preserve current late-completion recovery by deferring kill-task terminalization to a reconciliation path, or add explicit transition semantics and regression coverage that keep task rows and subagent run state consistent.

## Reproduction Assessment

Yes, source-level: current completion code deliberately recovers a subagent run when a COMPLETE arrives after a kill marker, while current task status rules will not let this PR's new `cancelled` task row become `succeeded`. I did not run a live race reproduction in this read-only review.

## Solution Assessment

No, not as-is. Finalizing killed rows in the shared primitive is the right owner boundary, but immediate `cancelled` status is not the safest implementation because it conflicts with the existing kill-vs-complete recovery path.
