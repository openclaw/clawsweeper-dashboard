## Summary

This remains a useful, focused reliability fix: current `main` still eagerly starts one Web Push send per subscription, while the branch converts broadcast fan-out to bounded lazy tasks and avoids shared mutable VAPID state. The code path and existing tests look sound, but the only live transport transcript is for `03969a69f27682e69c23a32677d75cadca42ea50`, not the current head `40f03487f465b4e4416bc95d6e6d6ac8e9d120fd` after its final merge; obtain exact-head proof before merge.

## What This Changes

The branch caps Web Push broadcast fan-out at 12 concurrent sends, passes VAPID details per request, safely clears expired subscriptions, and adds focused regression tests.

Rebase onto current `main` if required, retain the shared lazy concurrency worker and per-send VAPID options, then publish a redacted exact-head loopback HTTPS or equivalent real transport transcript covering more than 12 subscriptions, mixed 201/404/410 outcomes, and retained-state cleanup.
