## What This Changes

The issue asks OpenClaw to clean up Codex missing-thread bound-turn recovery so a newly spawned replacement thread is not stranded if the retry fails.

## Best Possible Solution

Define the intended bound-thread subscription lifecycle, then implement retry-failure cleanup that preserves consecutive bound-turn delivery with focused regression coverage.

## Reproduction Assessment

Yes at source level: current main can enter missing-thread recovery, create a replacement Codex thread, and retry the turn without replacement-thread cleanup. No live hosted Codex orphan-count reproduction was provided or run.

## Solution Assessment

No linked solution is clearly best yet: the cleanup primitive exists, but unconditional per-turn unsubscribe risks breaking later bound-turn delivery. The safer repair needs an explicit persistent-subscription or reattach-before-turn lifecycle decision.
