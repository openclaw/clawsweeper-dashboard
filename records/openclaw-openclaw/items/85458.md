## What This Changes

The issue reports a possible Codex app-server bound conversation thread leak when missing-thread recovery creates a replacement thread and the retry rejects.

## Best Possible Solution

Define the intended bound-thread subscription lifecycle, then implement cleanup that covers retry rejection while preserving consecutive bound-turn delivery with focused regression coverage.

## Reproduction Assessment

Yes, at source level: current main can enter missing-thread recovery, create a replacement Codex thread, and retry the turn without cleanup around that replacement-thread retry. No live hosted Codex orphan-count reproduction was provided or run.

## Solution Assessment

No current linked solution is clearly best: the cleanup primitive exists, but unconditional per-turn unsubscribe was already shown to risk later bound-turn delivery. The safer solution needs an explicit persistent-subscription versus reattach-before-turn decision.
