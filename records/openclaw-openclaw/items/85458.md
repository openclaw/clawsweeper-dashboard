## What This Changes

The issue reports a potential Codex app-server bound-conversation resource leak when missing-thread recovery creates a replacement thread and the retry then rejects without cleanup.

## Best Possible Solution

Define the intended bound-thread subscription lifecycle, then implement either narrow cleanup for the replacement-thread retry failure path or explicit reattach-before-turn semantics with per-turn unsubscribe, covered by retry-rejection and consecutive-turn tests.
