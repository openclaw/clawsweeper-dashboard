## What This Changes

Fix a source-level Codex app-server bound conversation leak where missing-thread recovery creates a replacement thread and then retries the bound turn without cleanup if that retry rejects.

## Best Possible Solution

Define the intended bound-thread subscription lifecycle, then implement cleanup that covers retry rejection while preserving consecutive bound-turn delivery with focused regression coverage.

## Solution Assessment

No current linked solution is clearly best: the cleanup primitive is available, but unconditional per-turn unsubscribe was already shown to risk later bound-turn delivery. The safer solution needs an explicit persistent-subscription versus reattach-before-turn decision.
