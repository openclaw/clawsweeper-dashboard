## Summary

Keep open: current main and v2026.6.11 still provide fixed same-key inbound debounce only, while adaptive/count/typing-aware timing remains an unresolved product and config decision.

## What This Changes

Request an incremental inbound debounce policy where later messages in a burst extend the wait up to a cap instead of reusing one fixed delay.

## Best Possible Solution

Design one opt-in generic inbound debounce policy that keeps the current fixed-window default, defines transcript/session semantics, and updates schema, docs, and tests only after the timing policy is chosen.
