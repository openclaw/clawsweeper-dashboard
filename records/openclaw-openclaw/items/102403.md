## Summary

The PR appears to be a correct and well-proven security hardening for newly created backup archives, but it intentionally changes the shipped backup artifact permission default and should stay open for maintainer/security acceptance before merge.

## What This Changes

The branch changes the backup archive writer to create temp archives with `0o600` permissions and adds a regression test asserting the published archive is owner-only.

## Best Possible Solution

Ship the owner-only archive default after maintainer/security acceptance, with PR or release context telling operators who intentionally share backup artifacts to chmod or copy them explicitly after creation.
