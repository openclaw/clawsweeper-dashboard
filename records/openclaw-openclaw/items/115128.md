## Summary

Keep open for maintainer product review. Current documentation confirms that Codex native tool calls can be inspected but their arguments cannot yet be safely rewritten, so the requested invariant is not available through the existing hook path; however, the issue proposes a cross-runtime/plugin contract rather than a narrow bug fix.

## What This Changes

Request a generic immutable inbound-event context and current-target reply/reaction capability that Codex native runs can use without reconstructing channel routing identifiers.

## System Context

Inbound channel adapters authenticate and normalize an event before OpenClaw starts an agent run. Codex native tools then execute within that run, but plugin hooks currently provide inspection and rejection rather than a trusted run-bound destination capability for replies or reactions.

## Architecture Diagram

flowchart LR
  A[Inbound channel event] --> B[Authenticated channel adapter]
  B --> C[Agent run creation]
  C --> D[Run-bound inbound context]
  D --> E[Codex native tool bridge]
  E --> F[Current-target reply or reaction]
  F --> G[Channel transport delivery]

## Best Possible Solution

Define one generic plugin/runtime contract that binds an authenticated inbound event to a single accepted run and exposes typed, authorization-checked current-target reply and reaction operations with an event idempotency key; adapt Codex native tools through that contract rather than exposing raw room or message identifiers to the model.
