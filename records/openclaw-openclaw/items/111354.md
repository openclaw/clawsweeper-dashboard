## Summary

Keep open for maintainer product direction. This is a broad core/plugin-SDK architecture proposal, not an optional vendor integration that can be redirected to ClawHub: it would define a shared contract across provider registration, onboarding, catalogs, auth, and multiple typed capability families. Current provider guidance already supplies incremental shared helpers, so the RFC should first be narrowed to a concrete provider family and a pilot that proves a missing common seam.

Likely related people: steipete is the best available routing candidate for current plugin-scope direction and provider-SDK product boundaries (medium confidence).

## What This Changes

The issue proposes a declarative provider-manifest runtime to replace repeated vendor lifecycle implementations for provider setup, catalogs, auth, health checks, and capability registration.

## Best Possible Solution

Sponsor one bounded pilot for a clearly homogeneous provider family, measure the duplicated lifecycle it removes, retain code hooks for non-declarative behavior, and propose only the smallest stable SDK contract the pilot proves necessary.
