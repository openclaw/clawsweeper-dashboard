## Summary

Keep this PR open for revision. It correctly identifies the current-main fast-exit race, but the eager promise can reject before it is awaited, causing an immediate recorder spawn failure to terminate Node as an unhandled rejection rather than produce the intended controlled error.

## What This Changes

The PR replaces the delayed child-exit wait with an immediately registered exit/error promise for the Telegram Crabbox proof recorder.

## Best Possible Solution

Capture child termination immediately as a non-rejecting closed result, inspect and throw any captured error when the operation consumes that result, and cover both fast exit and immediate spawn failure.
