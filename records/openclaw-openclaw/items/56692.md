- `P2`: The issue describes a normal-priority Telegram group-context correctness gap with real routing impact but no data-loss, security, crash, or release-blocking evidence.
- `impact:message-loss`: The reported ambiguity can cause an agent to answer messages meant for another bot or miss the intended response path.
- `impact:session-state`: The issue is about shared group history and reply context being interpreted under the wrong active agent in multi-agent chats.

## Summary

Keep open: current main still records and injects Telegram group history as flat sender/body/timestamp/message entries; only the current inbound message gets explicit mention metadata, while the requested per-history addressed-to/current-agent/other-bot/ambient contract is still absent and related implementation PRs are closed unmerged.

## What This Changes

Request per-message target/context attribution in shared group-chat history so a multi-agent Telegram bot can distinguish messages addressed to itself, another bot, or ambient room context.

## Best Possible Solution

Define a maintainer-approved optional target-attribution model, populate it for Telegram history/reply context first, add regression coverage, and validate with redacted two-bot Telegram proof.
