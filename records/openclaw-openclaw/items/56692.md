## Label Justifications

- `P2`: This is a normal-priority Telegram group-context correctness gap with meaningful routing impact but no emergency data-loss, security, or crash signal.
- `impact:session-state`: The issue is about group history and reply context being associated ambiguously with the current agent versus other agents.
- `impact:message-loss`: The ambiguity can cause agents to answer messages meant for another bot or suppress the intended response path.

## Summary

Keep open: current main and v2026.6.11 still carry Telegram group history as flat sender/body/timestamp entries without per-message current-agent versus other-bot target attribution. The external workaround projects linked in the discussion are useful, but they do not remove the remaining OpenClaw core/plugin context contract question.

## What This Changes

The issue requests clearer per-message target and reply-chain context for multi-agent Telegram group chats so the current agent can distinguish messages meant for itself, another agent, or ambient room context.

## Best Possible Solution

Land a maintainer-approved target-aware history/reply metadata contract in core and Telegram, with focused tests and redacted two-bot Telegram proof; keep external triage-gate or multi-agent-kit projects as optional workarounds rather than treating them as the core fix.

## Reproduction Assessment

Yes at source level, but not as a live Telegram run. Current main stores and renders flat Telegram group history without fields that say whether each prior message targeted this bot, another bot, or ambient context.

## Solution Assessment

Unclear as a final product solution. Per-message metadata is the right layer, but sibling-bot identity discovery, null/unknown semantics, and any history filtering default need maintainer direction before implementation.
