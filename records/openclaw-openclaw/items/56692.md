- `impact:session-state`: The issue is about group history and reply context being associated with the wrong active agent in multi-agent chats.

## Summary

Keep open: current main and v2026.6.11 still carry Telegram group history as flat sender/body entries without per-message current-agent versus other-bot target attribution, and the related PRs are closed or only prompt-level partial mitigations.

## What This Changes

The issue requests clearer per-message target and reply-chain metadata in multi-agent group chats so the current agent can distinguish messages addressed to it, other agents, or ambient context.

## Best Possible Solution

Keep this issue open until an approved core plus Telegram contract lands target-aware history/reply metadata, focused regression tests, docs as needed, and redacted two-bot Telegram proof.

## Reproduction Assessment

Yes at source level, but not as a live Telegram run. Current main stores and renders flat group history without a field that says whether each prior message was addressed to this bot, another bot, or ambient.

## Solution Assessment

Unclear as a final product solution. Per-message metadata is the right layer, but the permanent sibling-bot identity source, unknown/ambient semantics, and live Telegram proof still need maintainer direction.
