## Summary

Keep open: current main and v2026.6.11 still store and render Telegram group history as flat sender/body/timestamp/messageId entries, so current-agent versus other-bot targeting is not available in prior-message context. The merged sender-bot-status work and the open prompt-only mitigation are useful adjacent steps, but neither implements the requested per-message target attribution.

## What This Changes

Requests target-aware Telegram group history and reply context so agents can distinguish messages addressed to the current bot, another bot, or ambient group context.

## Best Possible Solution

Land a maintainer-approved core/channel context contract that carries per-message target metadata and reply-target bot information, then prove it with focused tests and redacted two-bot Telegram behavior evidence.

## Reproduction Assessment

Yes at source level, but not as a live Telegram run. Current main can be traced from Telegram group-history recording to the InboundHistory prompt payload, and that payload lacks target metadata for current-bot, other-bot, or ambient messages.

## Solution Assessment

Unclear as a final product path. Per-message target metadata is likely the right layer, but maintainers still need to settle sibling-bot identity, unknown/ambient semantics, and whether prompt-only mitigation should land separately.
