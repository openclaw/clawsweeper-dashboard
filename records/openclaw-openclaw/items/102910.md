## Summary

Keep open. Current main still has the reported Telegram HTML tag-overhead throw, and at least one direct outbound chunking path calls the splitter without the plain-text fallback used by the main send/rich-message funnels.

## What This Changes

The issue asks for Telegram HTML chunking to degrade gracefully instead of failing complete outbound delivery when tag overhead consumes the chunk budget.

## Best Possible Solution

Add a narrow Telegram HTML chunk planning fallback so explicit HTML outbound chunking degrades to readable plain text or safe sanitized chunks, matching the existing `send.ts` and rich-message recovery behavior.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, source-level. Current tests assert the tag-overhead throw, and current outbound planning can invoke the same HTML chunker without the fallback present in `send.ts`; I did not run tests because this cleanup review is read-only.

## Solution Assessment

No, the current behavior is not the best end state. The maintainable fix is to keep Telegram chunking loud where needed but ensure every delivery-facing HTML chunker path has the same plain-text degradation policy.
