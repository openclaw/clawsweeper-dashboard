## Summary

Keep open: current main still has a source-level Telegram HTML chunk-planning failure path where tag overhead can throw before delivery, and not every outbound caller has the plain-text fallback that durable send already uses.

## What This Changes

The issue asks OpenClaw to prevent Telegram HTML chunk splitting from throwing on tag overhead and aborting outgoing message delivery.

## Best Possible Solution

Use one Telegram-owned safe HTML chunk-planning path for all outbound/durable/rich delivery callers that falls back to plain text when tag overhead makes a valid HTML chunk impossible, while keeping fatal routing/auth/topic errors loud.

## Solution Assessment

No as phrased if it means making the low-level splitter silently drop tags everywhere. The best fix is a shared Telegram fallback path so delivery callers degrade to plain text when HTML planning cannot preserve a sendable chunk.
