## What This Changes

This PR replaces the 2,045-line cron service operations implementation with focused lifecycle, read, mutation, and manual-run modules while preserving `ops.ts` as the public operations facade.

## System Context

The cron service is OpenClaw’s scheduler layer: callers manage jobs through its public operations facade, which loads persisted jobs, controls the scheduler lifecycle, and admits manual or timed runs. The split moves those internal responsibilities into separate modules while retaining the facade used by the rest of the product.

  Facade --> Runs[Manual run operations]
  Lifecycle --> Store[SQLite cron store]
