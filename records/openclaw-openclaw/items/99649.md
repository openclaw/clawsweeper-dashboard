## What This Changes

The PR centralizes Crabline recorder JSONL line handling in QA Lab, defers only active unterminated tails during polling/reset, and adds regression tests for partial, malformed, and permanently truncated recorder rows.

## Best Possible Solution

Land the focused recorder-reader fix with its regression coverage after the normal maintainer and CI gates complete.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: current main parses every non-empty recorder fragment, so a split final JSONL write followed by reset can throw before the terminating newline arrives. The linked issue also documents the exact split-write scenario and observed parser error.

## Solution Assessment

Yes, this is the best fix shape: the reader now treats newline as the completed-record boundary during live polling but remains strict after the Crabline writer is closed. A broader catch-and-ignore JSON.parse approach would risk hiding completed corrupt records.
