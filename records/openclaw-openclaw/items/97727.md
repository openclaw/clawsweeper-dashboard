## Summary

Keep open for normal merge gating: current main drops Slack thread starter/history messages when top-level text is blank but visible content is in attachments or blocks, and this PR fixes that in the Slack plugin with focused tests and live Slack proof. I found no blocking review findings.

## What This Changes

The PR adds a shared Slack Block Kit text extractor and uses it in Slack thread starter/history context so attachment-only or block-only messages contribute text instead of being dropped.

## Best Possible Solution

Land the Slack-plugin patch after current-head CI finishes, keeping the shared extractor and regression tests in the Slack owner boundary.

## Reproduction Assessment

Yes, at source level: current main only accepts `message.text` or files for Slack thread starter/history, so attachment-only or block-only Slack thread messages with blank top-level text are omitted from context. I did not run a live Slack repro in this read-only pass.

## Solution Assessment

Yes, this is the best fix shape I found: it stays inside the Slack plugin, reuses one Block Kit extractor for inbound and thread-context paths, and avoids a core/channel API change. The rejected alternative is keeping a separate thread-only parser, which would recreate drift with normal inbound parsing.
