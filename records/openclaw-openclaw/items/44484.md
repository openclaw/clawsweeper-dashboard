## Summary

Keep this open: current main has session-scoped effective inventory, an internal capability profile, and policy-removal audit logs, but it still lacks the requested strict inheritance mode, declared-vs-effective diff, and structured per-tool clipping reason contract.

## What This Changes

The issue requests strict tool inheritance plus per-session visibility into declared, effective, removed, and blocked tools with reason metadata.

## Best Possible Solution

Keep lower runtime clipping authoritative by default, expose declared/effective/removed tool diagnostics with structured reasons, and add strict parity only as an explicit fail-closed opt-in after security review.
