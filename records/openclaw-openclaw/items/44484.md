## Summary

Keep open: current main has session-scoped effective inventory, capability-profile policy inputs, sandbox block messages, and policy-removal audit logs, but it still lacks the requested strict inheritance mode, declared-vs-effective diff, and structured per-tool clipping reason contract.

## What This Changes

Request strict tool inheritance or clear session diagnostics when declared agent tool permissions differ from effective runtime tools.

## Best Possible Solution

Keep lower runtime clipping authoritative by default, expose declared/effective/removed tool diagnostics with structured reasons, and add strict parity only as an explicit fail-closed opt-in after security review.

## Solution Assessment

No for unconditional strict inheritance: the safer first step is a maintainer-approved diagnostics contract, with strict parity only as a fail-closed opt-in if maintainers choose that security boundary.
