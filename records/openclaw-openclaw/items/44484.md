## Summary

Keep this open: current main has a session-scoped `tools.effective` API and policy-removal audit logs, but the central request still remains because there is no strict inheritance mode, declared-vs-effective diff, or structured per-tool clipping/unavailability reason contract.

## What This Changes

The issue requests strict tool inheritance, effective session tool visibility, and structured reasons when runtime/session layers reduce tools declared in agent config.

## Best Possible Solution

Keep runtime clipping authoritative by default, add a maintainer-approved diagnostics contract for declared/effective/removed tools and reasons, and only add strict parity as an explicit fail-closed opt-in after security review.
