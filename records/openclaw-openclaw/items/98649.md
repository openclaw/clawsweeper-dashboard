## Summary

This PR should close because the merged Tailscale JSON resilience path already settled the malformed Funnel-status behavior in the opposite direction: malformed `tailscale funnel status --json` must not become a confirmed missing route, and this branch would reintroduce that unsafe fallback.

## What This Changes

The branch changes `hasTailscaleFunnelRouteForPort` so malformed parsed Funnel status resolves `false` instead of rejecting, and updates the focused unit test to match.

## Best Possible Solution

Keep the merged fail-closed malformed-status behavior from https://github.com/openclaw/openclaw/pull/92849; if maintainers want a non-throwing helper later, use a typed result that distinguishes exec failure, malformed status, and confirmed missing route.

## Reproduction Assessment

Yes, at source level: current main has a focused test expecting malformed Funnel status to reject, and the preserve-Funnel caller catches that rejection before re-applying Serve. I did not run a live Tailscale daemon repro in this read-only review.

## Solution Assessment

No. Returning false is not the best fix because it reverses the merged fail-closed invariant; a typed status result would be the safer future direction if maintainers want to remove helper-level rejection.
