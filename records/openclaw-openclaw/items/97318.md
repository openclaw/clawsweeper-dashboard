## Label Justifications

- `P2`: The issue affects scheduled agent/exec workflows with limited blast radius, but it is not a crash loop, security bypass, or first-run blocker.
- `impact:message-loss`: The reported cron workflow can suppress the intended stdout/report delivery when a semantic nonzero exit is promoted to tool failure.
- `impact:session-state`: The same misclassification can mark agent/cron tool state and run history as failed even though the exec result was completed with output.

## Summary

Keep open: current main preserves nonzero exec output at the lower exec-runner layer, but the shared agent result classifier still marks completed nonzero exec results as tool errors, which can still feed failed tool state and cron fatal/error handling.

## What This Changes

The issue asks OpenClaw to preserve stdout and semantic exit-code handling for agent exec calls instead of treating every nonzero subprocess exit as a failed tool call.

## Best Possible Solution

Treat normal completed exec results with nonzero exit codes as nonfatal results through embedded-agent and cron classification, while preserving true tool failures for spawn errors, denials, timeouts, signals, and shell 126/127.

- **Keep failure semantics:** Document wrapper-based workarounds and close the bug as intentional, accepting that cron jobs using exit codes semantically will keep failing unless they force exit 0.
