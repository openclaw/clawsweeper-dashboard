## Summary

Keep open: current main still lets ordinary nonzero exec exits become tool-error state downstream, so the reported cron alert/message-delivery failure remains unresolved.

## What This Changes

The issue asks OpenClaw to expose ordinary nonzero exec subprocess exits to the agent as normal stdout/stderr/exit-code results, or to provide/document an explicit opt-in for that behavior.

## Best Possible Solution

Maintainers should choose the exec result contract, then align the shared tool-result classifier, cron fatal-error handling, tests, and docs so completed subprocess exits expose stdout/stderr/exitCode without masking spawn, timeout, signal, and shell 126/127 failures.

Options:

- **Default normal completed exits (recommended):** Treat normal process exits as successful tool transport regardless of exit code, while preserving failures for spawn/runtime errors, timeouts, signals, and shell 126/127.
- **Add explicit accepted exit codes:** Keep the current default failure classification and add an opt-in tool option such as acceptedExitCodes or allowNonzeroExit for semantic scripts.
- **Document wrapper-only behavior:** Keep current behavior and document the always-exit-zero wrapper pattern for semantic exit-code workflows.
