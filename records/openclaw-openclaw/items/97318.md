## Label Justifications

- `P2`: The bug affects scheduled agent/exec workflows with limited blast radius, but it is not a crash loop, security bypass, or first-run blocker.
- `impact:session-state`: Completed exec results with nonzero exit codes can still become failed tool state and cron run error state.
- `impact:message-loss`: The reported cron workflow can suppress the intended stdout/report delivery when a semantic nonzero exit is promoted to tool failure.

## Summary

Keep open: current main preserves normal nonzero exec output at the lower exec layer, but the shared agent result classifier still marks completed nonzero exit codes as tool errors, so cron and embedded-agent consumers can still record failed tool state and suppress intended output.

## What This Changes

The issue asks for exec subprocess nonzero exits to return stdout, stderr, and exitCode as normal agent-visible results instead of framework-level tool failures.

## Best Possible Solution

Treat normal completed exec results with nonzero exit codes as nonfatal agent-visible results through embedded-agent and cron classification, while preserving true tool failures for spawn errors, denials, timeouts, signals, and shell 126/127.

Unclear until maintainers choose the product boundary; the shipped lower-layer exec change is necessary but insufficient, and the best remaining fix belongs at the shared tool-result classification boundary plus focused embedded-agent and cron coverage.
