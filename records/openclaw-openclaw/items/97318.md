## Summary

Keep open: current main still has conflicting exec semantics, with the exec runner preserving normal nonzero exits as completed output while shared agent result classification promotes completed nonzero exit codes back into tool-error state that cron can treat as fatal.

## What This Changes

The issue asks OpenClaw to stop treating semantic nonzero subprocess exits from the exec tool as framework-level tool failures that mask stdout, stderr, and exit-code handling.

## Best Possible Solution

Treat completed exec results with ordinary nonzero exit codes as nonfatal agent-visible results across embedded-agent and cron paths, while preserving failures for spawn errors, denials, timeouts, signals, and shell 126/127.

Rationale: Current code has two competing semantics: the exec runner intentionally returns nonzero exits as completed output, while shared result classification still turns any nonzero exitCode into a tool error that can affect cron and diagnostics.

Owner confidence: medium

Options:

- **Make normal nonzero exec exits nonfatal (recommended):** Update the shared classifier and cron/embedded-agent coverage so stdout, stderr, and exitCode remain available without setting tool-failure state for ordinary completed exec exits.
- **Add an explicit accepted-exit policy:** Keep the current default but add a documented acceptedExitCodes or allowNonzeroExit surface, accepting new configuration and upgrade complexity.
- **Document current failure semantics:** Keep nonzero exits as tool failures and document wrapper-based workarounds, accepting that semantic exit-code cron jobs must force exit 0.

## Reproduction Assessment

Yes, from source: current main returns completed exec details for exitCode 1 at the runner layer, but the shared classifier still treats completed exitCode 1 as an error and embedded-agent/cron paths consume that error state. I did not run a live isolated cron reproduction in this read-only review.

No complete fix is present yet. The narrow maintainable path is to resolve the shared exec result-classification boundary, with focused embedded-agent and isolated-cron coverage, rather than adding wrapper guidance as the primary answer.
