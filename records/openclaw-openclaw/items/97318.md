## Label Justifications

- `P2`: The issue affects scheduled exec/agent workflows and can suppress expected alerts, but it is not a crash loop, security bypass, or first-run blocker.
- `impact:message-loss`: The reported cron workflow can fail to post the intended stdout alert when a semantic nonzero exit is promoted to tool failure.
- `impact:session-state`: The same classification can mark completed exec results and cron run history as failed even though the subprocess returned usable output.

## Summary

Keep open: current main preserves normal nonzero exec exits at the lower runner layer, but the shared agent error classifier still treats any finite nonzero exitCode as a tool-result error, so embedded-agent and cron paths can still turn completed exec output into failed tool state.

## What This Changes

The issue asks OpenClaw to preserve stdout/stderr and exit-code semantics for normal nonzero exec subprocess exits instead of surfacing them as framework tool failures.

## Best Possible Solution

Decide the default nonzero-exec boundary, then update shared tool-result classification and cron/embedded-agent coverage so normal completed exec exits remain nonfatal while true execution failures still surface.

Options:

- **Make normal exec nonzero nonfatal (recommended):** Update the shared classifier and cron/embedded-agent tests so completed exec exit codes preserve output and diagnostics without setting tool failure state.
- **Add explicit accepted-exit policy:** Keep current default failure semantics but add a documented accepted-exit or nonfatal-exit policy surface, accepting added config and upgrade complexity.
- **Keep failure semantics:** Document wrapper-based workarounds and accept that cron jobs using exit codes semantically must force exit 0 to avoid failed tool state.

Yes. Current main is source-reproducible: completed exec details can carry exitCode 1, and isToolResultError still classifies that result as an error that embedded-agent/cron consumers can propagate.

## Solution Assessment

No current implementation fully solves it. The lower-layer exec fix is necessary but incomplete; the maintainable remaining fix belongs at the shared tool-result classification boundary with focused embedded-agent and cron coverage.
