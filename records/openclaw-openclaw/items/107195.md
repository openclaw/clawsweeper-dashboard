## Summary

The prior P1 blocker remains on the unchanged reviewed head: the resolver is also used to configure Bolt’s shared, mutation-capable `App.client`, so the new deadline can turn an accepted Slack mutation into a reported timeout and retry. The supplied live proof exercises separately resolved read and write clients, not that shared Bolt path.

## What This Changes

The PR adds a default 30-second timeout to Slack read and lookup WebClient option resolution, preserves explicit timeout overrides, and leaves the dedicated write resolver unchanged.

## Best Possible Solution

Keep Bolt’s shared mutation-capable client free of the read deadline, introduce or reuse a genuinely read-only client boundary for bounded API reads, and prove both a slow read timeout and a delayed mutation through the actual monitor path without duplicate delivery.
