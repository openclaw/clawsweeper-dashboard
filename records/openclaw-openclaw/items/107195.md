## Summary

Keep this PR open, but do not merge the current patch: bounding Slack reads is reasonable, while applying the same default to every mutating WebClient introduces an ambiguous-delivery failure mode that the supplied live proof does not exercise.

## What This Changes

The PR adds a 30-second default timeout to Slack read and write WebClient options while preserving explicit timeout overrides, with focused option-resolution tests.

## Best Possible Solution

Use one shared 30-second default for non-mutating Slack clients, then define write deadlines per operation with explicit ambiguous-result handling or idempotency before changing the generic mutating client.
