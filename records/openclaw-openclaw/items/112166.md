## Label Justifications

- `P1`: A race can incorrectly terminalize a replacement session and disrupt the next message for an affected user.
- `merge-risk: 🚨 session-state`: The PR adds a persisted terminal-state update whose current identity guard is not atomic with its write.

## Summary

Keep this PR open for one P1 repair: the new session-ID guard is checked in a separate read before the later update, so a replacement session can still claim the same key in the gap and then be marked `killed`. The prior review finding is addressed only for replacements that already exist before the helper reads; it does not make the compare-and-write atomic.

## What This Changes

The branch persists a `killed` terminal state for a forcibly cleared embedded-agent run and adds tests for persistence plus fast recovery of the next reply.

## System Context

OpenClaw’s embedded-agent runner tracks live work in memory while the session store records the durable state shown to later dispatches and session listings. Heartbeat and timeout recovery can force-clear a stalled run; the next incoming reply uses the saved terminal status to decide whether it can reclaim and continue the session.

## Architecture Diagram

flowchart LR
  A[Incoming message] --> B[Embedded agent run]
  B --> C[Heartbeat or timeout recovery]
  C --> D[Force-clear stalled run]
  D --> E[Session-store mutation]
  E --> F[Next reply admission]
  F --> G[Fast recovery and dispatch]

## Best Possible Solution

Move the session-ID comparison into a single serialized session-store mutation that conditionally patches only the currently matching entry, then add a barrier-based regression test that replaces the entry after the stale recovery has readied its write.

Yes, at source level: let a force-clear pass the session-ID check, replace the session entry under the same key before its later update executes, and observe the replacement receive the stale `killed` patch. The current test covers replacement-before-read, not this interleaving.

## Solution Assessment

No. Persisting terminal state at the shared force-clear boundary is the right ownership direction, but a separate load and update cannot protect a replacement session; the compare-and-patch must be one serialized store operation.
