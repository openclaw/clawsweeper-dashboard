## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Exclude Wear identity files from backups:** `apps/android/wear/src/main/res/xml/data_extraction_rules.xml:4`
  - body: The Wear backup and data-extraction rules include the entire app files domain, while `GatewayDeviceIdentityStore` writes `openclaw/identity/device.json` under `context.filesDir` with `privateKeyPkcs8Base64`. On Android 12+ and backup-enabled devices this can copy the watch's gateway signing identity through cloud backup or device transfer, so exclude that path or store it under no-backup storage before merge.
  - confidence: 0.91
- **[P1] Wire the Wear module into Android gates:** `apps/android/settings.gradle.kts:21`
  - body: This branch adds `include(":wear")`, but the CI Android matrix still runs only `:app:testPlayDebugUnitTest`, `:app:testThirdPartyDebugUnitTest`, and `:app:assemblePlayDebug`; CodeQL likewise assembles only `:app`. As a result the new Wear app, resources, manifest, and tests can be broken while required checks stay green, so add focused Wear/shared build, test, lint, scan, and release/package coverage or keep the module out of the shipped build.
  - confidence: 0.89
- **[P2] Clear bootstrap auth when direct auth changes:** `apps/android/wear/src/main/java/ai/openclaw/wear/ui/ConnectionSettingsScreen.kt:47-51`
  - body: Editing the watch token or password copies only that field, leaving any existing `bootstrapToken` intact. `buildWearConnectParams` then prefers `bootstrapToken` over `password`, so a user who switches from synced/bootstrap auth to password auth can keep sending stale bootstrap credentials with no screen field to clear them. Clear bootstrap auth when direct token/password/host auth is edited, or make the precedence and reset path explicit.
  - confidence: 0.86
