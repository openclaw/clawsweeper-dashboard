Full review comments:

- **[P1] Exclude Wear identity files from backups:** `apps/android/wear/src/main/AndroidManifest.xml:10-12`
  - body: The Wear app enables backup and includes the whole file domain, but the shared identity store writes the gateway device private key to `files/openclaw/identity/device.json`. A cloud or device-transfer restore can copy that private identity onto another watch and reuse gateway trust outside the intended pairing boundary; disable backup for the Wear app or explicitly exclude identity/auth artifacts.
  - confidence: 0.93

  - body: Adding `:wear` here creates a new app module, but the Android CI matrix and package scripts still invoke only `:app` test/build tasks.   - confidence: 0.9
- **[P2] Clear bootstrap auth when editing direct credentials:** `apps/android/wear/src/main/java/ai/openclaw/wear/ui/ConnectionSettingsScreen.kt:47-51`
  - body: Editing the direct token or password preserves any existing `bootstrapToken`, and `buildWearConnectParams` still prefers `bootstrapToken` before password. If fallback sync previously stored bootstrap auth, a user switching to password auth can keep sending the stale bootstrap token with no field in this screen to clear it.
  - confidence: 0.86
- **[P2] Update Android license notices for new dependencies:** `apps/android/wear/build.gradle.kts:72`
  - body: This module adds new AndroidX/Wear/Google Play Services dependencies, but the PR changes no bundled license notice files. `apps/android/AGENTS.md` requires auditing `apps/android/THIRD_PARTY_LICENSES/openclaw/licenses/` when Android dependencies change, so the Settings Licenses screen can become incomplete.
  - confidence: 0.84
