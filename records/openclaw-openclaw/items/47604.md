## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Exclude Wear identity files from backup:** `apps/android/wear/src/main/res/xml/backup_rules.xml:3`
  - body: The Wear manifest enables backup and `backup_rules.xml` includes the whole file domain, but the shared identity store writes `privateKeyPkcs8Base64` to `openclaw/identity/device.json` under `filesDir`. That can put the watch's direct-auth signing key into cloud backup/device transfer; exclude that path or disable backup for the Wear app before merge.
  - confidence: 0.92
- **[P1] Wire the Wear module into Android gates:** `apps/android/settings.gradle.kts:21`
  - body: Adding `include(":wear")` creates a new shippable app target, but the existing Android CI, CodeQL, package scripts, and Fastlane release paths still build/test only `:app`. Green checks would not compile, analyze, package, or release the Wear module, so add explicit :wear test/build/lint/CodeQL/release coverage or keep it out of the main Android project.
  - confidence: 0.9
- **[P2] Clear bootstrap auth when password changes:** `apps/android/wear/src/main/java/ai/openclaw/wear/ui/ConnectionSettingsScreen.kt:51`
  - body: The password input saves `config.copy(password = value)` without clearing `bootstrapToken`, and `buildWearConnectParams` prefers `bootstrapToken` over `password` when no token is set. A user switching from synced bootstrap auth to password auth can keep sending the stale bootstrap token and never actually exercise the password they entered.
  - confidence: 0.86
- **[P2] Use shared Android versioning for Wear:** `apps/android/wear/build.gradle.kts:17-18`
  - body: The Wear module hardcodes `versionCode = 2026042600` and `versionName = "2026.4.26"`, while the existing Android release model reads version metadata from `apps/android/version.json` through `Config/Version.properties`. Release/version-sync commands would leave Wear on a stale version and make phone/Wear artifacts drift.
  - confidence: 0.84
