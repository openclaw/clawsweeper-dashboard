Full review comments:

- **[P1] Exclude Wear identity files from backups:** `apps/android/wear/src/main/AndroidManifest.xml:10-12`
  - body: The Wear app enables backup while the shared identity store writes the gateway device private key under filesDir. With backup/data-extraction rules including the whole file domain, restoring a backup can copy the watch's gateway signing identity; disable backup for Wear or exclude the identity path before merge.
  - confidence: 0.94
- **[P1] Wire the Wear module into Android gates:** `apps/android/settings.gradle.kts:21`
  - body: Adding include(":wear") creates a new shippable module, but the existing Android CI matrix only runs :app Play/third-party tests and the :app Play build. A green PR can therefore miss Wear compilation, lint, and unit-test failures; add focused :wear build/test/lint coverage before relying on CI.
  - confidence: 0.93
- **[P2] Clear bootstrap auth when password changes:** `apps/android/wear/src/main/java/ai/openclaw/wear/ui/ConnectionSettingsScreen.kt:50-52`
  - body: The password editor saves config.copy(password = value) but leaves any synced bootstrapToken in place. buildWearConnectParams checks bootstrapToken before password, so a user switching direct mode to password auth can keep sending stale bootstrap auth and fail until config is reset; clear bootstrapToken when direct credentials are edited.
  - confidence: 0.9
- **[P2] Remove the deprecated Wear BIND_LISTENER action:** `apps/android/app/src/main/AndroidManifest.xml:97`
  - body: Late catch on unchanged code since the last ClawSweeper review: the phone proxy service now registers both MESSAGE_RECEIVED and BIND_LISTENER. Android's WearableBindListener lint contract treats BIND_LISTENER as deprecated/fatal and inefficient, so the service should rely on the fine-grained MESSAGE_RECEIVED path filter plus live listeners instead.
  - late: true
  - confidence: 0.86
