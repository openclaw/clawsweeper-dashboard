## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Exclude Wear identity files from backups:** `apps/android/wear/src/main/res/xml/backup_rules.xml:3`
  - body: The Wear app enables backup/transfer and includes the entire file domain, but the shared identity store writes `openclaw/identity/device.json` with `privateKeyPkcs8Base64`. That can clone the watch's gateway device identity through cloud backup or device transfer; match the current phone app's exclude-by-default backup policy or explicitly exclude the identity and secret paths.
  - confidence: 0.92
- **[P1] Wire the Wear module into Android gates:** `apps/android/settings.gradle.kts:21`
  - body: Adding `:wear` to settings makes it a real release module, but the existing Android package scripts and CI still run only `:app` and `:benchmark` tasks. A PR can go green while the Wear app never assembles, lints, or runs unit tests; add the Wear assemble/test/lint tasks to the Android scripts and CI matrix.
  - confidence: 0.9
- **[P2] Clear stale bootstrap auth on credential edits:** `apps/android/wear/src/main/java/ai/openclaw/wear/ui/ConnectionSettingsScreen.kt:47-51`
  - body: Editing the direct token or password copies only that field and leaves any saved `bootstrapToken`; `buildWearConnectParams` prefers `bootstrapToken` before password. A watch that previously synced bootstrap auth can keep sending stale bootstrap credentials even after the user enters a password, so clear bootstrap auth when token/password changes.
  - confidence: 0.86
- **[P2] Add license notices for new Android dependencies:** `apps/android/wear/build.gradle.kts:72-75`
  - body: The Wear module adds Play Services Wearable and multiple AndroidX Wear/Tile/Protolayout dependencies, while the bundled Android license directory has no corresponding new `.txt` notices. The Settings Licenses screen is generated from that directory, so these dependencies will be omitted from the user-visible notices.
  - confidence: 0.82
