- **[P1] Exclude Wear identity files from backup:** `apps/android/wear/src/main/res/xml/backup_rules.xml:3`
  - body: The Wear app enables backup and includes the full file domain, but the shared identity store writes an Ed25519 private key under `filesDir/openclaw/identity/device.json`. Android backs up internal app files unless they are excluded, so this can transfer a watch identity to cloud/D2D backup; move identity material to a no-backup location or exclude it from both backup rule files. ([developer.android.com](https://developer.android.com/identity/data/autobackup?utm_source=openai))
  - confidence: 0.93

  - body: Adding `include(":wear")` creates a new app module with its own tests and build output, but the current package scripts and CI Android matrix still run only `:app` tasks. This lets Wear code merge without routine build/test/lint coverage; add the Wear assemble/test/lint tasks to the Android gates before merge.
  - confidence: 0.91
- **[P2] Clear bootstrap auth when editing direct credentials:** `apps/android/wear/src/main/java/ai/openclaw/wear/ui/ConnectionSettingsScreen.kt:51`
  - body: The token/password editors preserve any existing `bootstrapToken`, and `buildWearConnectParams` chooses `bootstrapToken` before `password` when token is blank. A user switching from fallback bootstrap auth to password auth can keep sending stale bootstrap credentials, so clear `bootstrapToken` when direct token or password is edited.
  - confidence: 0.89

([googlesamples.github.io](https://googlesamples.github.io/android-custom-lint-rules/checks/WearableBindListener.md.html?utm_source=openai))
  - late: true
  - confidence: 0.86

  - body: Late discovery: this dependency block was present at the previously reviewed head.
