- **[P1] Exclude Wear identity files from backups:** `apps/android/wear/src/main/res/xml/backup_rules.xml:3`
  - body: The Wear app enables backup and includes the whole file domain, while `GatewayDeviceIdentityStore` writes `privateKeyPkcs8Base64` to `filesDir/openclaw/identity/device.json`. That can carry the direct-auth private key through cloud backup or device transfer; add explicit excludes for `openclaw/identity/**` in both backup rule files or disable backup for this app.
  - confidence: 0.93
- **[P1] Wire the Wear module into Android gates:** `apps/android/settings.gradle.kts:21`
  - body: Adding `:wear` creates a standalone app, but the current Android CI/package/release paths still run phone-app tasks such as `:app:testPlayDebugUnitTest`, `:app:assemblePlayDebug`, and `:app:bundlePlayRelease`. A Wear compile/test/release failure can stay hidden behind green Android checks, so the module needs explicit `:wear` assemble/test and release artifact coverage before merge.
  - confidence: 0.89
- **[P2] Clear stale bootstrap auth when password changes:** `apps/android/wear/src/main/java/ai/openclaw/wear/ui/ConnectionSettingsScreen.kt:50-51`
  - body: The password editor keeps `config.bootstrapToken`, and `buildWearConnectParams` tries `bootstrapToken` before `password`. If phone fallback sync stored a bootstrap token, a user entering a password still sends bootstrap auth and cannot recover from this settings screen; clear bootstrap auth when token/password changes or make precedence match the visible credential.
  - confidence: 0.83
- **[P2] Use shared Android versioning for Wear:** `apps/android/wear/build.gradle.kts:17-18`
  - body: The Wear app hard-codes `versionCode` and `versionName` instead of deriving from the Android version source used by the phone release flow. That can publish or test a stale watch version independently of the Android release train; wire the Wear module to the shared version metadata before release.
  - confidence: 0.78
