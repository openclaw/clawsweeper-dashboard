## Summary

Keep open: current main and v2026.6.11 still derive and register an HTTP Mattermost slash-command callback when `commands.callbackUrl` is omitted. The cross-command token replay part is already hardened, but the remaining transport policy is tracked by an open linked PR that still needs security and compatibility review.

## What This Changes

The issue asks OpenClaw to stop exposing Mattermost slash-command callback tokens over cleartext callbacks and to prevent reusable token replay across slash triggers.

## Best Possible Solution

Review and land or replace the linked Mattermost PR with a narrow HTTPS fail-closed transport gate that preserves current per-command token validation and documents the upgrade path.

Yes, source-reproducible. Current main derives `http://` when Mattermost `commands.callbackUrl` is omitted and passes that URL into slash-command registration; I did not run a live Mattermost network capture.

Unclear until maintainers accept the compatibility tradeoff. A narrow Mattermost registration-path HTTPS gate appears to be the right technical boundary if fail-closed callback transport is the desired policy.
