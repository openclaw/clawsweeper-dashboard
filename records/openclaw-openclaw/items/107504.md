## Summary

Keep open, but narrow the report to a startup-contract bug rather than a demonstrated security bypass: current main intentionally falls back from an unavailable `tailnet` address to loopback, despite public docs describing `tailnet` as Tailscale-IP-only. A successful specific-interface bind already includes a loopback listener, so the fallback does not itself create the claimed new local exposure. ([github.com](https://github.com/openclaw/openclaw/blob/main/src/gateway/net.ts))

Likely related people: `steipete` and `stakeswky` have medium-confidence adjacent history around fail-closed non-loopback gateway startup behavior.

## What This Changes

Make gateway startup report or reject an unavailable explicit `tailnet` bind instead of silently starting loopback-only.

## Best Possible Solution

For an explicitly configured `gateway.bind: "tailnet"`, fail startup with an actionable Tailscale-address error when no bindable tailnet IPv4 exists, and add focused resolver/runtime tests; leave automatic and Tailscale Serve loopback behavior unchanged.
