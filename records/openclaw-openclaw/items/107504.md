## Label Justifications

- `P2`: The explicit Tailnet-only contract is violated, but the fallback remains host-local and the gateway continues operating.
- `impact:ux-friction`: Operators can believe Tailnet-only access is active while the gateway has silently become reachable only from the local host.

## Summary

Current `main` still degrades an explicit Tailnet-only bind to loopback when no usable Tailnet IPv4 is available, contrary to the documented bind contract. The fallback does not create the reported unauthenticated network exposure because it is host-local and does not disable configured gateway authentication, but changing it to fatal startup is compatibility-sensitive and needs an explicit gateway-owner decision.

## What This Changes

Make an explicit `gateway.bind: "tailnet"` startup fail when no bindable Tailnet IPv4 exists instead of silently degrading to loopback.

## Best Possible Solution

Treat an explicit `tailnet` bind as operator intent: fail startup with a clear diagnostic and recovery guidance when no bindable Tailnet IPv4 exists, while adding focused tests and documenting the upgrade-visible availability change.
