## Summary

Keep this open for a gateway-owner decision. Current `main` can silently convert an explicit Tailnet-only request into a loopback listener, violating the documented reachability contract, but the fallback narrows network exposure rather than creating the reported unauthenticated Tailnet access. Likely related people: steipete and RenzoMXD, both with medium-confidence routing from the issue timeline.

## What This Changes

Make gateway startup fail non-zero instead of silently binding to loopback when an explicitly requested Tailnet address cannot be resolved.

## Best Possible Solution

Treat explicit `gateway.bind="tailnet"` as strict: fail startup with an actionable Tailscale diagnostic when no Tailnet IPv4 resolves, preserve loopback fallback for `auto`, and test valid Tailnet, missing Tailnet, and automatic fallback paths.
