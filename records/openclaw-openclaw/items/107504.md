## Summary

Current `main` still appears to resolve an explicit `tailnet` bind request to loopback when no Tailscale IPv4 address is available, conflicting with the documented “Tailscale IP only” contract. The fallback does not establish the reported remote unauthenticated bypass, but it silently changes the operator’s requested network policy, so this issue should remain open for an upgrade-sensitive gateway/security decision.

## What This Changes

Make an explicit Tailscale-only gateway bind fail startup rather than silently falling back to loopback when no Tailscale IPv4 address is available.

## Best Possible Solution

For explicit `gateway.bind="tailnet"`, fail startup with an actionable error when no Tailscale IPv4 address is available; retain best-effort fallback only for `auto`, and add focused resolver/runtime tests plus operator guidance for Tailscale Serve or loopback.
