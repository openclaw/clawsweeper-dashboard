## Summary

Current `main` disproves the reported remote network fail-open: an unavailable explicit `tailnet` bind resolves only to loopback, and separate startup checks reject unsafe non-loopback or unauthenticated Tailscale exposure. However, it still silently replaces operator-selected Tailnet reachability with local-only service, so the issue remains valid pending an explicit security-versus-availability decision. citeturn712661view0turn355195view0

**Likely related people**

## What This Changes

Make gateway startup visibly fail rather than silently falling back to loopback when an explicitly selected Tailnet bind cannot be established.

## Best Possible Solution

For explicit `gateway.bind=tailnet`, either fail startup with an actionable Tailscale diagnostic or define a supported degraded-loopback state that is authenticated and unmistakably reported in startup output, readiness, and status surfaces; do not silently replace operator intent.
