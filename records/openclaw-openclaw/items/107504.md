## Summary

Current `main` still treats an explicit `tailnet` bind as a degraded loopback start when no usable Tailnet address is available, conflicting with the documented “Tailscale IP only” contract. Loopback is host-local and gateway authentication remains configured, so the reported unauthenticated network exposure is not supported; the issue should remain open for the compatibility-sensitive choice between availability and strict operator intent. citeturn10search0turn10search1turn15search0

## What This Changes

Make gateway startup fail with a non-zero exit when an explicitly requested Tailnet bind cannot be established.

## Best Possible Solution

Make explicit `gateway.bind: "tailnet"` strict: fail startup with an actionable error when no usable Tailnet IPv4 address exists, keep fallback semantics under `auto`, and add focused resolver/startup coverage plus guidance to restore Tailscale or choose `auto` or `loopback`.
