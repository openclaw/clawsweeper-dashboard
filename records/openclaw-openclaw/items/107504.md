## Summary

Current `main` does not reproduce the claimed network fail-open: an unavailable explicit `tailnet` bind narrows to loopback, while non-loopback startup is separately guarded by authentication and Control UI origin checks. The silent loss of operator-selected Tailnet reachability remains a valid bug, but fail-closed startup versus a visibly degraded loopback mode requires an explicit gateway security and availability decision. ([github.com](https://github.com/openclaw/openclaw/blob/main/src/gateway/net.ts))

## What This Changes

Make an explicit `gateway.bind: "tailnet"` startup fail visibly rather than silently narrowing to loopback when the Tailscale address is unavailable or unbindable.

## Best Possible Solution

Treat explicit `tailnet` as an operator-intent contract: either fail startup with precise remediation or introduce a formally supported degraded-loopback state that is prominent in logs and status and is never advertised as Tailnet-reachable, with focused tests for the selected behavior.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: When an explicitly configured `gateway.bind: "tailnet"` cannot bind its Tailscale address, must gateway startup fail, or may it continue on loopback in a prominently reported degraded state?

Rationale: Fail-closed behavior preserves the explicit reachability boundary, while loopback degradation preserves local availability during transient Tailscale failures; current source and documentation do not settle that tradeoff.

Likely owner: steipete

Owner reason: The strongest routing evidence connects this account to current gateway remote-access and security-policy documentation and this issue's discussion.

Owner confidence: medium

Options:

- **Fail explicit tailnet startup (recommended):** Reject startup with a non-zero exit and actionable Tailscale diagnostics whenever the selected Tailnet address is missing or unbindable.
- **Visible loopback degradation:** Continue on loopback only with an explicit degraded runtime state, high-visibility logs and status, and no Tailnet advertisement or success messaging.

## Reproduction Assessment

Yes for the narrowed behavior: current source deterministically falls back from an unavailable or unbindable explicit Tailnet address to loopback. No high-confidence reproduction supports the stronger claim of new unauthenticated network exposure because the resulting listener is host-local and current startup guards remain active.

## Solution Assessment

Unclear until maintainers select the availability contract. Fatal startup is the cleanest expression of explicit `tailnet` intent, but a deliberately visible degraded-loopback mode may be preferable if transient Tailscale outages must not eliminate local gateway availability.
