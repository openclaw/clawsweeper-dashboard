## Summary

Current `main` still appears to violate the documented explicit `tailnet` bind contract by selecting loopback when no usable Tailscale IPv4 is available. The fallback is host-local and does not itself disable normal gateway authentication, so the reported unauthenticated exposure is overstated; however, whether startup should fail closed is a compatibility-sensitive gateway product decision. citeturn6search1turn6search2

## What This Changes

Require gateway startup to fail with a non-zero exit when an explicitly requested Tailscale bind address cannot be resolved.

## Best Possible Solution

Make an explicit `gateway.bind: "tailnet"` request fail startup with an actionable Tailscale diagnostic when no Tailnet IPv4 exists, retain compatibility fallback only for non-explicit auto-selection, and cover both paths in focused gateway resolver and startup tests.
