## Summary

Keep this open for a gateway-owner decision. Current main intentionally degrades an unavailable Tailnet address to loopback, which prevents the claimed remote exposure but can silently remove requested Tailnet reachability. Likely related people: openperf for recent gateway bind work, with steipete and RenzoMXD as lower-confidence routing contacts from the issue timeline.

## What This Changes

Decide whether an explicit Tailnet bind that cannot be established should abort gateway startup instead of degrading to loopback.

## Best Possible Solution

Adopt one explicit contract: preferably retain safe loopback degradation while emitting an unmistakable startup warning and degraded-health status that names the requested Tailnet bind failure; choose fatal startup only if maintainers intentionally accept the compatibility impact.
