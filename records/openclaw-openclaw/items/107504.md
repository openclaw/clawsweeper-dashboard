## Summary

Current `main` still appears to downgrade an explicit `tailnet` bind request to loopback when no usable Tailscale IPv4 address is found, despite the documented tailnet-only contract. The report overstates this as a demonstrated remote unauthenticated bypass, but the silent policy change is a valid gateway security and operator-expectation issue that needs a fail-closed versus availability decision.

**Likely related people**
- `openperf` — medium confidence; recently changed the central gateway bind-resolution and startup configuration paths in merged commit `c9e4b86c7ede89c11a08e62d420ec835a9cddf55`.

## What This Changes

Make an explicitly configured Tailscale gateway bind fail startup visibly instead of silently falling back to loopback when the Tailscale address cannot be used.

## Best Possible Solution

Reserve fallback behavior for `auto`; make explicit `tailnet` startup fail with an actionable error when no usable Tailscale IPv4 listener can be established, and cover both address absence and listener-bind rejection without changing unrelated bind modes.
