## Summary

Keep this PR open for repair: the prior P1 blocker remains on the unchanged reviewed head because the new check validates the raw MCP arguments, while the wrapped tool can subsequently replace those arguments through `before_tool_call` and execute a different, unchecked object. Current `main` still lacks the requested MCP argument validation, so the contribution remains useful but is not merge-ready.

## What This Changes

The PR precompiles TypeBox validators for exposed plugin tools, rejects invalid MCP `callTool` arguments before execution, and adds regression tests for schema constraints.

## Best Possible Solution

Use one canonical pipeline that applies the before-tool hook and argument preparation, validates or parses the resulting object, and passes that exact validated object to execution, with regressions for hooks that repair and invalidate arguments.
