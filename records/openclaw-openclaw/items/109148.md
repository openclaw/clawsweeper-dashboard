## Summary

This is a valid MCP error-handling bug, but the PR is not merge-ready because it adds a second, incomplete JSON Schema validator that still executes arguments violating types, enums, patterns, arrays, and nested constraints; tests are the only supplied proof.

## What This Changes

The PR adds pre-execution checks for required and unexpected MCP plugin-tool arguments plus a missing-required-property regression test.

## Best Possible Solution

Route MCP calls through the canonical full-schema tool-argument validator, translate validation failures into the MCP `isError` result envelope, cover wrong types and nested constraints as well as missing and extra fields, and demonstrate the result with a redacted real MCP client transcript.

## Solution Assessment

No. Pre-execution validation is the right boundary, but a new two-keyword validator is not the best fix when the repository already exports a complete canonical validator that can be adapted to the MCP error envelope.
