## Summary

The PR remains necessary because current `main` has no separate operational-notice policy, but the current head is not merge-ready: heartbeat failure paths can permanently consume an undelivered `once` notice, the durable dedupe state is an unbounded file-backed session array, and maintainers still need to approve the new public config/plugin contract and fail-closed redirect semantics.

## What This Changes

Adds a global operational-notice delivery policy with `always`, `once`, `redirect`, and `silent` modes across direct replies, ACP, follow-ups, heartbeat delivery, configuration, plugin hooks, tests, and documentation.

## Best Possible Solution

Reserve `once` state immediately around actual delivery with guaranteed rollback on every non-delivery path, store dedupe in a bounded canonical SQLite table keyed by source session and notice fingerprint, and land the public config/plugin contract only after an owner approves the fail-closed redirect behavior.

Full review comments:

- **[P1] Release heartbeat once reservations on every failed send path:** `src/infra/heartbeat-runner.ts:2309`
  - body: The loop reserves each `once` fingerprint before `checkReady` and before durable sending. If readiness returns false or sending throws, the function exits without `markOperationalReplyPolicyDelivered(..., false)`, so a notice that never reached the channel stays persisted and later heartbeats suppress it. Defer reservation until delivery or release all collected reservations in every early-return and catch path.
  - confidence: 0.99
- **[P2] Store once-policy state in bounded SQLite storage:** `src/auto-reply/reply/operational-reply-policy.ts:221`
  - body: Successful unique notices append fingerprints to the file-backed session entry forever, so long-lived sessions grow without cleanup and each session-store rewrite carries the accumulated array. Runtime dedupe state belongs in a bounded canonical SQLite owner rather than `SessionEntry`.
