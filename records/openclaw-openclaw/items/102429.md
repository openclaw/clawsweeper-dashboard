## Summary

This PR addresses the canonical external-channel fallback-notice leak with a coherent shared policy, but it is not merge-ready: `once` can deliver duplicates during overlapping dispatches, the latest head conflicts with current main, real external-channel proof is still missing, and maintainers must confirm the permanent global config/plugin contract.

## What This Changes

Adds `messages.operationalReplies` with always, silent, once, and redirect modes across direct dispatch, ACP, follow-ups, heartbeat delivery, persisted session state, plugin hook metadata, tests, and docs.

## Best Possible Solution

Adopt one shared operator-controlled operational-notice policy only after making `once` atomically reserve each source-session fingerprint before delivery, releasing failed reservations, persisting successful claims through session-accessor APIs, and proving concurrent, restart, live source-chat, redirect, fresh-install, and upgrade behavior on a clean current-main head.
