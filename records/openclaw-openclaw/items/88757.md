## Summary

Keep open: the isolated-agent cron slice was addressed by the merged work cited in the discussion, but a July 19, 2026 reproduction identifies a separate model-free command-cron announce path with no destination session identifiers. That path can still deliver a visible Telegram message while the next user turn lacks the message context, so the central desynchronization problem remains unresolved.

## What This Changes

Ensure successful proactive channel deliveries, including command cron announcements, are represented safely in the destination session context so later user replies are interpreted against what they saw.

## Best Possible Solution

Define one session-safe post-delivery contract for successful proactive output, then extend the existing destination-resolution and awareness mechanism to command cron announcements without writing failed deliveries or taking over an active user turn.
