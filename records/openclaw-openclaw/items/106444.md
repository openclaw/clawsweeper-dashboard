## Summary

Keep this issue open for a maintainer-defined delivery contract and a redacted current-main trace. Current main already suppresses equivalent same-route message-tool/final payloads while deliberately preserving distinct follow-ups, so the broad cross-retry/resume failure is not yet reproduced and a blanket turn-level suppression rule could hide intentional output.

## What This Changes

Ensure one logical Telegram result is not delivered repeatedly across message-tool sends, final replies, delivery mirrors, retries, and resumed turns.

## Best Possible Solution

Keep the existing route- and content-aware same-turn dedupe, obtain a redacted current-main trace that identifies the escaping delivery surface, and then add the narrowest durable delivery evidence or recovery rule that blocks that proven duplicate without suppressing distinct follow-ups.

- **Design durable logical-result receipts:** Introduce persisted cross-run delivery identity only after maintainers define result identity, lifecycle, retention, migration, and intentional-follow-up semantics.

## Solution Assessment

No. A global receipt keyed by hashes or semantic result IDs is premature; the safer solution is to identify the concrete bypass and preserve intentional distinct follow-ups while deduping only proven equivalent delivery.
