## Summary

Keep this issue open: current main has targeted guards for canonical final payloads, message-tool-only source delivery, transcript mirrors, and uncertain queue recovery, but the report does not isolate a remaining current-main failure path and requests broader automatic-mode semantics that require maintainer intent.

## What This Changes

Request a cross-path invariant preventing equivalent Telegram output from being visibly delivered more than once across explicit sends, final replies, delivery mirrors, retries, and resumed turns.

## Best Possible Solution

Preserve mode-scoped source-reply semantics, carry stable delivery identity through outbox and recovery paths, and add a focused suppression guard only for a demonstrated remaining retry, resume, mirror, or final-delivery path rather than introducing global content-hash dedupe.

Options:

- **Keep mode-scoped semantics (recommended):** Retain automatic final delivery, use message-tool-only mode when explicit sends replace finals, and repair only concretely reproduced retry or resume replay defects.

- **Add global receipt dedupe:** Persist a logical-result receipt shared across send, final, mirror, retry, and resume paths, accepting a larger state model and false-suppression risk.
