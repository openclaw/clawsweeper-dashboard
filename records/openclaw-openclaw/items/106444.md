## Label Justifications

- `P2`: The issue describes meaningful Telegram delivery corruption, but it does not yet isolate a reproducible current-main path or demonstrate broad service unavailability.
- `impact:message-loss`: One logical result can be delivered more than once, while an overly strict suppression policy could also drop an ambiguously delivered reply.
- `impact:session-state`: Delivery-mirror and resumed-turn handling can leave persisted session history inconsistent with what was already shown to the user.

## Summary

Keep this issue open because current main contains targeted guards for several named duplicate-delivery paths, but the reported 2026.6.11 occurrence is not specific enough to determine whether a distinct current bug remains or whether it is the recovery case already tracked elsewhere.

## What This Changes

Request once-only Telegram delivery across explicit tool sends, final replies, delivery mirrors, retries, and resumed turns.

## Best Possible Solution

Use the existing server-owned turn and outbox identity as the canonical delivery receipt across final delivery, transcript mirroring, and resumed turns, with an explicit policy for ambiguous Telegram send outcomes and no parallel semantic-hash store.

Options:

- **Receipt-Backed Suppression (recommended):** Suppress later delivery only when a server-owned turn, outbox, transport, or transcript receipt proves that the visible result was delivered; quarantine ambiguous recovery separately.
- **Prefer Delivery Retry:** Retain at-least-once recovery semantics and accept that an ambiguous Telegram failure may occasionally produce a duplicate.
- **Prefer No Duplicates:** Never replay ambiguous Telegram sends and accept that some generated replies may be lost when delivery success cannot be confirmed.

## Solution Assessment

Unclear. A shared server-owned delivery receipt is directionally correct, but semantic output hashes or unconditional at-most-once suppression would be unsafe until maintainers choose the ambiguous-send reliability policy.
