## Summary

Keep this PR open: the Android reconnect trigger is a plausible improvement, but the proposed monitor treats a per-network `onLost` callback as device-wide offline, so multi-network handoffs can defeat the dedupe guarantee before merge.

## What This Changes

The PR adds an Android `NetworkMonitor` that registers a `ConnectivityManager` callback and calls `NodeRuntime`'s preferred-gateway reconnect path when a validated network becomes available, plus pure JUnit state-machine tests and native i18n line sync.

## Best Possible Solution

Keep the network-return trigger, but make the online/offline state reflect the default network or a tracked set of validated networks, then prove the behavior with a real Android network drop/restore run.

  - body: `registerNetworkCallback` reports all networks matching the request, so `onLost` can fire for Wi-Fi while cellular or a VPN remains validated.
