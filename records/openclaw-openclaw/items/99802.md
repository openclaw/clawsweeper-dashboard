## Summary

Keep open: the reported crash class is valid, but this patch installs the stdout/stderr guards only after output callbacks are registered, so an early stream error can still be unhandled; the PR also still has mocked-only proof.

## What This Changes

The PR adds no-op error handlers for supervised child stdout/stderr streams and a regression test that emits stream errors through stubbed streams.

## Best Possible Solution

Attach stdout/stderr error containment once during child-adapter initialization, cover an error emitted before output callback registration, and require redacted real supervised-child proof before merge.

## Reproduction Assessment

Yes at source level: current main lacks stdout/stderr error listeners in the child adapter, and Node stream/EventEmitter error semantics make an unhandled error event throw. I did not establish a real supervised child process reproduction.

## Solution Assessment

No; the child adapter is the right owner boundary, but placing the guards inside onStdout/onStderr leaves an early-error window before callback registration.
