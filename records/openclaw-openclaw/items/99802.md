## What This Changes

The PR installs one child stdout/stderr stream error guard during child-adapter setup and adds regression coverage for pre-subscriber stream errors plus Windows close-driven wait settlement.

## Best Possible Solution

Land the narrow child-adapter lifecycle guard after normal CI and maintainer merge gates, keeping decoder flush and Windows drain settlement owned by the existing close handlers.

## Reproduction Assessment

Yes at source level: current main has no child stdout/stderr error listener during adapter construction, while the supervisor registers output subscribers only after createChildAdapter returns. A Node probe also confirms unhandled error events throw unless an error listener is installed.

## Solution Assessment

Yes: the child adapter is the right owner boundary because it owns the child streams from spawn through wait/dispose, and installing one guard at construction closes the timing gap. Subscriber-level guards were too late, and the PTY sibling is unaffected because it does not expose separate stdout/stderr streams.
