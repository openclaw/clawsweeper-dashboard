## Summary

Keep open: the PR targets a real supervisor crash class, but the proposed handler placement still leaves early stdout/stderr stream errors unhandled and the external PR lacks real behavior proof from a supervised child run.

## What This Changes

The branch adds no-op error listeners for supervised child stdout/stderr streams and a regression test that emits stream errors after output listeners are registered.

## Best Possible Solution

Install stdout/stderr error containment once during child-adapter initialization, cover the pre-registration case in the regression test, and add redacted real supervised-child proof before merge.

## Reproduction Assessment

Yes at source level: current main lacks stdout/stderr `error` listeners in the child adapter, and Node's EventEmitter implementation throws an unhandled `error` event without a listener. I did not establish real after-fix behavior from an actual supervised child process.

## Solution Assessment

No; the child adapter is the right owner boundary, but installing the guards inside `onStdout` and `onStderr` is too late for early stream errors. The narrower maintainable fix is to attach one stdout/stderr guard immediately after the child is captured.
