## Summary

Keep open: current main and v2026.6.11 do not include the LINE busy-reply guard, but this PR is not merge-ready because it can collapse senderless group or room postbacks into one `unknown` key, lacks real LINE behavior proof, changes default LINE delivery semantics, and is currently dirty/conflicting against main.

## What This Changes

Adds a process-local per-user in-flight guard to LINE message and postback webhook handling, wires it into the default LINE bot runtime, and adds handler tests.

## Best Possible Solution

Keep the guard in the LINE plugin only after senderless postbacks are handled or explicitly defined, default skip-vs-queue semantics are accepted, the branch is refreshed, and real LINE proof is supplied.

## Reproduction Assessment

Yes for the introduced patch defect: PR head keys missing sender IDs as `unknown`, and the pinned LINE SDK source says group and room `userId` is optional and only included in message events. The original rapid-message timeout symptom is not reproduced with real LINE evidence in the PR body.

## Solution Assessment

No. The LINE plugin is the right owner boundary, but default-on drop behavior across messages and postbacks is not the best merge shape until senderless postbacks, skip-vs-queue semantics, conflicts, and real LINE proof are resolved.
