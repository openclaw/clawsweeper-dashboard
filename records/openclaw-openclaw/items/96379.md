## Summary

Keep open: this is a focused LINE UX change, but it is not merge-ready because the default-on guard can suppress unrelated senderless group/room postbacks and the contributor still has not added real LINE behavior proof.

## What This Changes

Adds a process-local LINE in-flight guard that replies busy and skips overlapping message/postback events, wires it into `createLineBot`, and adds handler tests.

## Best Possible Solution

Keep the fix in the LINE plugin, but merge only after senderless postback suppression is avoided or explicitly accepted, drop-vs-queue semantics are maintainer-approved, and redacted real LINE proof is added.

## Reproduction Assessment

Yes, source-reproducible for the introduced defect: PR head keys postbacks with missing `userId` as `unknown`, while the LINE SDK says group/room `userId` is optional and only included in message events. The original rapid-message timeout claim still lacks real LINE proof.

## Solution Assessment

No. The LINE plugin is the right owner boundary, but a default-on skip guard across messages and postbacks is not the best merge shape until senderless postbacks and skip-vs-queue semantics are settled.

- **[P1] Preserve sender identity before guarding postbacks:** `extensions/line/src/bot-handlers.ts:650-653`
  - body: This applies the guard to postbacks even when `getLineSourceInfo(event.source)` has no stable sender. Skip the guard without a stable sender, or make conversation-level postback throttling explicit with focused coverage.
