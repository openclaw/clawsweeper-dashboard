## What This Changes

The PR adds a process-local LINE in-flight guard that sends a busy reply and skips overlapping message or postback events for the same account/conversation/user key.

## Best Possible Solution

A landable version should keep this in the LINE plugin only after stable sender identity or intentional conversation-level throttling is defined, with real LINE proof for busy replies, guard release, and same-group isolation.

## Reproduction Assessment

Yes for the introduced patch defect: PR head keys missing sender IDs as `unknown`, and the pinned LINE SDK source says group and room `userId` is optional and only included in message events. The original rapid-message timeout symptom is not reproduced with real LINE evidence in the PR body.

## Solution Assessment

No. The LINE plugin is the right owner boundary, but default-on skip behavior across messages and postbacks is not the best merge shape until senderless postbacks, skip-vs-queue semantics, branch conflicts, and real LINE proof are resolved.
