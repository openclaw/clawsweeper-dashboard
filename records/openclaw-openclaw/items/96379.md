## Summary

Keep open: the LINE plugin mitigation is focused, but it still lacks real LINE behavior proof and has a blocking senderless group/room postback delivery bug; current main does not implement this guard and the branch is dirty against main.

## What This Changes

Adds a process-local per-user in-flight guard to LINE message and postback handling, wires it into the default LINE bot runtime, and adds handler tests.

## Best Possible Solution

Keep the guard in the LINE plugin only after senderless postbacks are handled or explicitly defined, the branch is refreshed, and maintainers have real LINE proof for the delivery behavior.

## Reproduction Assessment

Yes for the introduced patch defect: PR head keys missing sender IDs as unknown, and the pinned LINE SDK source says group and room userId is optional and only included in message events. The original rapid-message timeout symptom is not real-environment reproduced in the PR body.

## Solution Assessment

No. The LINE plugin is the right owner boundary, but default-on drop behavior across messages and postbacks is not the best merge shape until senderless postbacks, skip-vs-queue semantics, branch conflicts, and real LINE proof are resolved.
