## What This Changes

Adds a LINE webhook-level per-user in-flight guard that sends a busy reply for overlapping message/postback events, wires it into createLineBot, and adds handler tests.

## Best Possible Solution

Keep the LINE-owned mitigation only after it preserves stable sender identity, intentionally defines the skip-vs-queue/default behavior, rebases over current media filename handling, and includes redacted real LINE proof.

## Reproduction Assessment

Yes, source-level for the introduced defect: PR head guards postbacks using `userId ?? "unknown"`, while the pinned LINE SDK source says group/room `userId` is optional and only included in message events. The original rapid-message symptom still lacks live LINE reproduction in the PR body.

## Solution Assessment

No. The LINE plugin is the right owner boundary, but a default-on skip guard across messages and postbacks is not the best merge shape until senderless postbacks, skip-vs-queue semantics, rebase conflicts, and real proof are settled.
