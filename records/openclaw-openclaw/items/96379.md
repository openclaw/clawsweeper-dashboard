## Summary

Keep open: the LINE-owned mitigation is useful, but this PR is not merge-ready because it lacks real LINE proof, the branch is conflicting, and the diff can suppress distinct LINE events through senderless postback keys and default-on busy-drop behavior.

## What This Changes

Adds a process-local LINE per-user in-flight guard, wires it into the default LINE bot runtime, sends a busy reply for concurrent events, and adds handler tests.

## Best Possible Solution

Keep the guard in the LINE plugin only after sender identity handling, default skip semantics, branch conflicts, and real LINE proof are resolved; otherwise prefer a queue or active-turn feedback path that does not drop distinct user actions.

## Reproduction Assessment

Yes for the introduced patch defects: PR head keys missing sender IDs as unknown, and the pinned LINE SDK source says group and room userId is optional and only included in message events. The original rapid-message timeout symptom is not reproduced with real LINE evidence in the PR body.

## Solution Assessment

No. The LINE plugin is the right owner boundary, but default-on skip behavior across messages and postbacks is not the best merge shape until senderless postbacks, skip-vs-queue semantics, branch conflicts, and real LINE proof are resolved.
