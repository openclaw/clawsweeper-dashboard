Keep open: current main still has no LINE user in-flight guard, and this PR remains useful but not merge-ready because the prior senderless group/room postback blocker still applies, real LINE proof is absent, and GitHub reports the branch as dirty against main.

## What This Changes

The branch adds a process-local per-user in-flight guard to LINE message and postback handling, sends a busy reply when the guard is held, wires it into the default LINE bot runtime, and adds handler tests.

## Best Possible Solution

Keep the guard in the LINE plugin only after stable sender-key semantics are fixed or explicitly product-approved, the branch is refreshed, and real LINE proof demonstrates busy reply, release, and group isolation.

## Reproduction Assessment

Yes for the introduced patch defect from source inspection: PR head keys missing group/room sender IDs as unknown, and the pinned LINE SDK marks those user IDs optional outside message events. No live LINE reproduction is provided for the original rapid-message timeout symptom.

## Solution Assessment

No. The LINE plugin is the right owner boundary, but default-on skip-with-busy behavior across messages and postbacks is not the best merge shape until senderless postbacks, branch conflicts, and real LINE proof are resolved.
