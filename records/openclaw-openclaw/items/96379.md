## What This Changes

## Best Possible Solution

Keep the guard in the LINE plugin only after senderless postbacks are handled or explicitly defined, the branch is refreshed, and redacted real LINE proof demonstrates the intended delivery behavior.

## Reproduction Assessment

Yes for the introduced patch defect: PR head guards postbacks using LINE sourceInfo, and @line/bot-sdk 11.0.1 marks group/room userId optional and only included in message events. The original rapid-message timeout claim is not reproduced outside tests in the PR body.

## Solution Assessment

No. The LINE plugin is the right owner boundary, but default-on skip behavior should first preserve sender identity or explicitly define conversation-level postback throttling, then be proven with real LINE evidence.
