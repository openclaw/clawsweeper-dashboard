## What This Changes

Adds a process-local per-user in-flight guard to LINE message and postback webhook handling, wires it into the default LINE bot runtime, and adds handler tests for busy replies and guard release.

## Best Possible Solution

Keep the guard in the LINE plugin only after senderless postbacks are handled or explicitly defined, the branch is refreshed, and maintainers have real LINE proof for the delivery behavior.

## Reproduction Assessment

## Solution Assessment

No. The LINE plugin is the right owner boundary, but default-on skip behavior across messages and postbacks is not the best merge shape until senderless postbacks, skip-vs-queue semantics, branch conflicts, and real LINE proof are resolved.
