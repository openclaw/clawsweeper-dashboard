## Summary

Keep open: the LINE guard is a focused user-facing improvement, but the PR is not merge-ready because real LINE proof is missing, the branch currently conflicts with main, and the postback guard can collapse senderless group or room postbacks into an `unknown` sender key and drop unrelated taps.

## What This Changes

Adds a process-local LINE per-user in-flight guard, wires it into the default LINE bot runtime, sends busy replies, and adds handler tests.

## Best Possible Solution

Keep the guard in the LINE plugin only after senderless postbacks are handled or explicitly defined, the branch is refreshed, and maintainers have real LINE proof for the delivery behavior.

## Reproduction Assessment

Yes for the introduced patch defect: PR head maps missing sender IDs to `unknown`, and the pinned LINE SDK source says group and room `userId` is optional and only included in message events. The original rapid-message timeout symptom is not real-environment reproduced in the PR body.

## Solution Assessment

No. The LINE plugin is the right owner boundary, but default-on drop behavior across messages and postbacks is not the best merge shape until senderless postbacks, skip-vs-queue semantics, branch conflicts, and real LINE proof are resolved.
