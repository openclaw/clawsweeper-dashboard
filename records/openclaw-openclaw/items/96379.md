## Summary

Keep open: the PR has a useful LINE mitigation direction, but current head is not merge-ready because senderless group/room postbacks can be throttled under an unknown-user key, real LINE proof is missing, and the branch is conflicting.

## What This Changes

The PR adds a process-local LINE per-user in-flight guard, wires it into createLineBot, sends busy replies for duplicate in-flight events, and adds handler tests.

## Best Possible Solution

Keep the guard in the LINE plugin only after senderless postbacks are handled or explicitly defined, default skip-vs-queue semantics are accepted, the branch is refreshed, and real LINE proof shows the delivery behavior.

## Reproduction Assessment

Yes for the introduced patch defect: PR head keys missing sender IDs as unknown for guarded postbacks, and @line/bot-sdk 11.0.1 says group and room userId is optional and only included in message events. The original rapid-message timeout symptom is not reproduced with real LINE evidence in the PR body.

## Solution Assessment

No. The LINE plugin is the right owner boundary, but default-on skip behavior across messages and postbacks is not the best merge shape until senderless postbacks, skip-vs-queue semantics, branch conflicts, and real LINE proof are resolved.
