## Summary

Keep open: the PR still lacks real LINE behavior proof and the current head still guards postbacks with sender IDs that LINE may omit, so unrelated group or room postbacks can be dropped with a busy reply. The LINE plugin is the right owner boundary, but this branch is not merge-ready while the delivery semantics, proof gap, and dirty merge state remain unresolved.

## What This Changes

Adds a process-local per-user in-flight guard to LINE message and postback handling, wires it into the default LINE bot runtime, and adds handler tests for busy replies and guard release.

## Best Possible Solution

Keep the guard in the LINE plugin only after senderless postbacks are handled or explicitly defined, the branch is refreshed, and maintainers have real LINE proof for the delivery behavior.

## Reproduction Assessment

Yes for the introduced patch defect: PR head keys missing sender IDs as unknown, and LINE's webhook source docs say group and room userId is not always present and only included in message events. The original rapid-message timeout symptom is not reproduced with real LINE proof in the PR body.

## Solution Assessment

No. The LINE plugin is the right owner boundary, but default-on skip-with-busy-reply behavior across messages and postbacks is too broad until senderless postbacks, skip-vs-queue semantics, branch conflicts, and real LINE proof are resolved.
