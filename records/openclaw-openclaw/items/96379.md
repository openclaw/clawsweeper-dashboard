## What This Changes

The PR adds a LINE webhook in-flight guard that replies with a busy message and skips processing when the same LINE user sends another message or postback while a prior event is still running.

## Best Possible Solution

Keep the guard in the LINE plugin only after senderless postbacks are handled or intentionally defined, the branch is refreshed, and real LINE proof demonstrates the busy reply, release behavior, and same-group isolation.

## Reproduction Assessment

Yes for the introduced patch defect: PR head keys postbacks from optional sender identity, and the LINE SDK source allows group and room userId to be absent. The original rapid-message timeout symptom is not reproduced with a real LINE setup in the PR body.

## Solution Assessment

No. The LINE plugin is the right owner boundary, but default-on skip behavior across messages and postbacks is not the best merge shape until senderless postbacks, skip-vs-queue semantics, branch conflicts, and real LINE proof are resolved.
