## Best Possible Solution

Preserve LINE's existing queue and steering semantics, add busy feedback only in a way that does not drop queued user input, define senderless postback behavior, refresh the branch, and prove the result with a real LINE run.

## Solution Assessment

No. The LINE plugin is the right owner boundary, but the current fix is not the best shape because it drops events ahead of the existing queue contract and does not safely define senderless postback behavior.

Skip the per-user guard without a sender ID, or explicitly define and test conversation-level throttling.
