## Summary

Keep open: the LINE plugin is a plausible owner for the busy-reply mitigation, but the current PR is not merge-ready because it can drop senderless group or room postbacks, changes default LINE delivery semantics, and still has only test proof rather than redacted real LINE behavior proof.

## What This Changes

Adds a process-local per-user in-flight guard to LINE message and postback handling, wires it into the default LINE bot runtime, and adds handler tests for busy replies, release, no-guard behavior, and group user isolation.

## Best Possible Solution

Keep the guard in the LINE plugin only after senderless postbacks are handled or explicitly defined, default delivery semantics are accepted by maintainers, the branch is refreshed, and real LINE proof is supplied.

## Reproduction Assessment

Yes for the introduced patch defect: PR head keys missing sender IDs as unknown, and @line/bot-sdk 11.0.1 marks group and room userId optional and only included in message events. The original rapid-message timeout symptom is not reproduced with real LINE evidence in the PR body.

## Solution Assessment

No. The LINE plugin is the right owner boundary, but default-on skip behavior across messages and postbacks is not the best merge shape until senderless postbacks, skip-vs-queue semantics, branch conflicts, and real LINE proof are resolved.
