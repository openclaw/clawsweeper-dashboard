## What This Changes

The branch adds a process-local LINE per-user in-flight guard, wires it into the default LINE bot runtime, and adds handler tests for busy replies, guard release, and group user isolation.

## Best Possible Solution

Keep the guard in the LINE plugin only after stable sender identity semantics for postbacks are fixed or explicitly defined, real LINE proof is added, and the branch is refreshed against current main.

## Reproduction Assessment

Yes for the introduced patch defect: PR head keys missing sender IDs as unknown, and the pinned LINE SDK types mark group/room userId optional and only included in message events. The original rapid-message timeout symptom is not proven in a real LINE environment.

## Solution Assessment

No. The LINE plugin is the right owner boundary, but skip-with-busy-reply should not apply to senderless group/room postbacks without explicit semantics; guarding only stable sender IDs or designing queueing is safer.
