## Summary

Keep open: current main and the latest release still accept remote avatar values in agent identity config, but the Control UI deliberately refuses to render remote http(s) images under its same-origin avatar policy, so the reported broken-avatar behavior remains a real config/UI contract mismatch that needs owner direction.

## What This Changes

The issue asks for Control UI to render agent identity avatars set with `openclaw agents set-identity --avatar`, including remote URLs and workspace-local paths.

## Best Possible Solution

Preserve the same-origin browser policy and either add a bounded gateway-mediated remote-avatar path or clearly mark remote Control UI avatars unsupported across CLI docs, metadata, and UI status; align `/avatar`, `agents.list`, and `agent.identity.get` while doing it.
