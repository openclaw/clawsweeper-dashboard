## Summary

Keep open: current main and the latest release still accept remote avatar values in agent identity/config, but Control UI intentionally blocks remote image rendering under its CSP and frontend render gate, so the broken-avatar report remains a real product/security contract mismatch.

## What This Changes

The issue asks for avatars configured with `openclaw agents set-identity --avatar <url/path>` to render correctly in the Control UI instead of showing a broken image.

## Best Possible Solution

Maintainers should choose one Control UI avatar contract: either controlled same-origin remote-avatar proxy/cache support, or an explicit local/data-only Control UI policy with aligned CLI/docs/validation and clear diagnostics.
