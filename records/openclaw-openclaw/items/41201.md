## Summary

Keep open: current main and the latest release still accept `http(s)` avatar values in the identity contract, but Control UI deliberately strips remote image rendering for CSP/privacy reasons, so the broken-avatar report remains a real contract mismatch that needs maintainer direction.

## What This Changes

The issue asks for avatars set with `openclaw agents set-identity --avatar <url/path>` to render in Control UI instead of showing broken images.

## Best Possible Solution

Maintainers should choose one Control UI avatar contract: either support remote avatars through a controlled same-origin proxy/cache, or explicitly keep Control UI local/data-only and align CLI help, config docs, validation, and UI diagnostics to that policy.
