## Summary

Keep open: current main and v2026.6.11 still accept remote avatar values through CLI/config, but Control UI deliberately blocks remote image rendering, so this remains a real Control UI avatar contract mismatch that needs maintainer direction.

## What This Changes

The issue asks Control UI to render agent avatars set via CLI/config, including remote URLs and local workspace paths, instead of showing broken images.

## Best Possible Solution

Maintainers should choose one Control UI avatar contract: a controlled same-origin remote-avatar proxy/cache, or an explicit local/data-only policy with aligned CLI/docs/validation and clear diagnostics.
