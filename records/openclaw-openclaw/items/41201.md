## Summary

Keep open: current main still accepts remote avatar values and exposes remote avatar metadata, while Control UI deliberately strips remote image URLs under a same-origin/data/blob CSP, so the central request remains a security and product contract decision rather than implemented cleanup.

## What This Changes

The issue requests that Control UI render avatars configured through agent identity, including remote URL and local workspace avatar values, instead of showing a broken or missing image.

## Best Possible Solution

Adopt one explicit Control UI avatar contract: either a controlled same-origin remote-avatar proxy/cache, or a local/data-only policy with aligned CLI/docs/validation and clear UI diagnostics.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Control UI support remote `http(s)` agent avatars, or should remote avatar inputs remain unsupported for Control UI and be documented or validated that way?

Rationale: The remaining change affects CSP, browser network fetching, privacy expectations, authenticated avatar reads, and the public avatar configuration contract, so automation should not silently choose the policy.

Likely owner: steipete

Owner reason: steipete has the strongest history across original avatar support, avatar safety hardening, and Control UI security policy.

Owner confidence: high

Options:

- **Keep local/data-only Control UI avatars (recommended):** Preserve the merged CSP posture and align CLI help, docs, validation, and diagnostics so remote avatars are not presented as renderable in Control UI.
- **Build a same-origin remote-avatar proxy:** Support remote avatars through a gateway-owned proxy or cache with explicit MIME, size, auth, caching, privacy, and network rules.
- **Allow direct remote image fetches:** Let the browser load arbitrary remote avatar URLs directly, accepting the CSP and operator-browser privacy tradeoff.

Yes, at source level: configure an `http(s)` avatar, the resolver returns remote metadata, and Control UI rejects that URL under the renderability gate and CSP. I did not run a live Railway/browser reproduction.

## Solution Assessment

Unclear until maintainers decide the security boundary. The narrow maintainable outcome is either a same-origin proxy/cache for remote avatars or an explicit local/data-only contract with aligned diagnostics and documentation.
