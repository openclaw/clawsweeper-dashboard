## Summary

Keep open: current main and v2026.6.11 still have a split contract where CLI/config accept remote avatar values, but Control UI deliberately blocks remote image rendering for CSP/privacy reasons, so this remains a maintainer security/product decision rather than completed cleanup.

## What This Changes

The issue asks for avatars configured with `openclaw agents set-identity --avatar` from remote URLs or workspace paths to render in Control UI instead of showing broken images.

## Best Possible Solution

Adopt one explicit Control UI avatar contract: either a controlled same-origin remote-avatar proxy/cache, or a local/data-only policy with aligned CLI/docs/validation and clear UI diagnostics.
