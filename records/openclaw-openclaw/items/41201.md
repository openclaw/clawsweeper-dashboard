## Summary

Keep open: current main and the latest release still accept remote avatar values, but Control UI intentionally blocks remote image rendering, so this remains a real avatar contract/security decision rather than an implemented bug fix.

## What This Changes

The issue reports that avatars configured through `openclaw agents set-identity --avatar` render as broken images in the Control UI.

## Best Possible Solution

Adopt one explicit Control UI avatar contract: either support remote avatars through a controlled same-origin proxy/cache, or keep Control UI local/data-only and align CLI/docs/validation/UI diagnostics.

## Maintainer Decision

Kind: product_direction

Question: Should Control UI support remote `http(s)` avatars, or should remote avatar inputs remain blocked and documented/validated as unsupported for Control UI rendering?

Rationale: The remaining behavior affects CSP, privacy, browser network fetching, avatar route auth, and the public avatar configuration contract, so automation should not choose the policy silently.

Likely owner: steipete

Owner reason: This handle has the strongest history signal across the avatar resolver, route, docs, and Control UI security boundary.

Owner confidence: high

Options:

- **Keep local/data-only avatars (recommended):** Preserve the current CSP posture and align CLI/docs/validation/UI diagnostics so remote avatars are not presented as renderable in Control UI.
- **Build a same-origin proxy/cache:** Support remote avatars through a gateway-owned proxy/cache with explicit MIME, size, auth, caching, privacy, and failure-feedback behavior.
- **Allow direct remote fetches:** Let browsers load configured remote avatar URLs directly and accept the associated CSP and operator-browser privacy tradeoff.

## Reproduction Assessment

Yes. Source inspection reproduces the remote-avatar path: configure an `http(s)` avatar, the gateway resolves it as remote metadata, and the Control UI renderability gate rejects that URL and clears the avatar.

## Solution Assessment

Unclear until maintainers choose the security boundary. The narrow maintainable outcome is either a same-origin proxy/cache for remote avatars or an explicit local/data-only contract with aligned diagnostics, not a silent direct browser fetch.
