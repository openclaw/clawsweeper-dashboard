## Summary

Keep open: current main still accepts remote avatar values through CLI/config, but Control UI deliberately rejects remote image rendering through its render gate and CSP, so this remains a real contract mismatch requiring maintainer product/security direction.

## What This Changes

The issue reports that avatars configured with `openclaw agents set-identity --avatar <url/path>` show as broken images in the Control UI.

## Best Possible Solution

Maintainers should choose one Control UI avatar contract: support remote avatars through a same-origin proxy/cache with explicit MIME, size, caching, auth, privacy, and diagnostics, or make Control UI local/data-only and align CLI/docs/validation with that policy.
