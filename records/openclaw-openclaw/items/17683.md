## Summary

Keep open: current main and the latest release still have useful cron, hook, command, tool allow-list, light-context, timeout, model/fallback, and usage-reporting primitives, but not the requested first-class scoped/script-limited mode with shared script registry, dry-run/cost preview, per-job token/spend ceilings, daily budget aborts, and planned-vs-actual run receipts.

## What This Changes

The issue requests a scoped/script-limited agent mode for predictable cron-first automation with whitelisted scripts, bounded tools, hard token/spend controls, minimal context, dry-run previews, and structured run transparency.

## Best Possible Solution

Keep this as the umbrella scoped-automation tracker and design shared primitives across cron, hooks, command jobs, tool policy, budget admission, context handling, run receipts, docs, and tests.

## Reproduction Assessment

Yes, as source-level feature-gap proof rather than a bug reproduction: current main has partial cron, hook, command, tool, context, and usage primitives but no first-class scoped/script-limited mode contract.

## Solution Assessment

Unclear until maintainers choose the product and security contract; the maintainable path is to extend existing cron, hook, command, tool-policy, accounting, and run-log primitives rather than adding a parallel mode with separate semantics.
