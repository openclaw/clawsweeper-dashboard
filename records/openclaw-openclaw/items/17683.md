## Summary

Keep open for maintainer product and security design. Current main now covers much of the practical request through deterministic command cron jobs, isolated agent turns, light context, tool allow-lists, timeouts, context limits, and per-run spend caps, but it still lacks a unified scoped-mode contract with an admin-controlled script registry, daily budget enforcement, preflight cost/dry-run previews, and planned-versus-actual run accounting. The narrower related issues cover individual components but do not replace this broader coordination tracker.

## What This Changes

Requests a first-class scoped automation mode with approved-script execution, deterministic cron triggers, isolated context, hard token and spending limits, dry-run previews, and structured run transparency.

## Best Possible Solution

Define one composable cron execution-policy contract shared by command and isolated agent jobs: immutable operator-owned script references and argument rules, explicit context and tool policy, pre-dispatch token/spend checks backed by canonical accounting, side-effect-free preview output, and structured planned-versus-actual results, while reusing the narrower budget and dry-run work instead of creating parallel enforcement paths.
