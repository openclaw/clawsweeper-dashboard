## Summary

Keep open: current main still has only partial cron, hook, command, tool allow-list, context, and post-run usage primitives, while the requested first-class scoped/script-limited mode remains a product and security design item.

## What This Changes

Request a scoped/script-limited agent mode with admin-defined scripts, cron-first execution, token and spend ceilings, fresh context, dry-run/cost preview, and structured run logs.

## Best Possible Solution

Keep this as the umbrella product/API tracker and design shared scoped-automation primitives across cron, hooks, command jobs, tool policy, budget admission, context handling, run receipts, docs, and tests.

## Reproduction Assessment

Not applicable as a bug reproduction; current-main source inspection gives high confidence that the requested native mode is still missing. The observable gap is the absence of first-class script registry, budget admission, dry-run/cost preview, and planned-vs-actual run contracts.

## Solution Assessment

Unclear until maintainers choose the product and security shape. The maintainable path is shared primitives on the existing cron, hook, command, tool-policy, accounting, and logging paths rather than a parallel mode with separate semantics.
