## Label Justifications

- `P2`: This is meaningful operator safety and cost-control work, but it is a broad product/API design item rather than an emergency regression or outage.
- `impact:session-state`: The requested mode changes fresh per-job context, persistent context accumulation, explicit state persistence, and planned run accounting.
- `impact:security`: Admin-defined script execution, tool limits, dry-run behavior, and scoped execution define a user-trusted authority boundary.
- `impact:auth-provider`: Token ceilings, spend ceilings, rate-limit pressure, and model/fallback selection are tied to metered provider dispatch and credentials.

## Summary

Keep open: current main and the latest stable release still provide partial cron, hook, command-job, timeout, light-context, tool allow-list, and post-run usage primitives, but not the requested first-class scoped/script-limited mode with an admin script registry, dry-run/cost preview, budget admission, daily ceilings, and structured planned-vs-actual run receipts.

## What This Changes

The issue requests a first-class scoped/script-limited agent mode with admin-defined scripts, deterministic cron-style triggers, token/spend ceilings, minimal context, dry-run previews, and structured execution logs.

## Best Possible Solution

Keep this as the umbrella product/API tracker and design shared scoped-automation primitives across cron, hooks, command jobs, tool policy, budget admission, context handling, run receipts, docs, and tests.
