## Summary

Keep open. Current main still has useful cron primitives, command jobs, per-job tool allow-lists, hook-triggered isolated runs, lightweight context, and post-run cost/usage accounting, but not the requested first-class scoped/script-limited mode with script registry, dry-run cost preview, token/spend ceilings, daily budget aborts, and planned-vs-actual run receipts.

## What This Changes

The issue requests a scoped/script-limited agent mode for predictable cron-first automation with admin-defined scripts, strict tool/script scope, token and spend ceilings, fresh-context runs, dry-run previews, and structured execution transparency.

## Best Possible Solution

Keep this as the umbrella scoped-automation product/API tracker and design shared primitives across cron payload/schema, hooks, command jobs, tool policy, budget admission, context handling, run receipts, docs, and tests.

## Reproduction Assessment

Yes at source level: current main has partial cron, hook, command, tool, context, and usage primitives, but no first-class scoped/script-limited mode contract. This is feature-gap proof, not a failing bug reproduction.

## Solution Assessment

Unclear until maintainers choose the product and security shape. The maintainable path is shared primitives on existing cron, hook, command, tool-policy, accounting, and logging paths rather than a parallel mode with separate semantics.
