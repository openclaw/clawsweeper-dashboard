## What This Changes

The issue reports that the Chat tab Session Workspace files panel Copy path action does nothing because the current app-level callback calls the Clipboard API directly instead of the shared clipboard fallback helper.

## Best Possible Solution

Review and land one of the open fix candidates, preferably https://github.com/openclaw/openclaw/pull/98764 if it remains the stronger proof path, then close this issue once the fix is merged.

## Reproduction Assessment

Yes, at source level: current main routes the Copy path button to copyChatWorkspacePath, and that callback only optional-calls navigator.clipboard.writeText. I did not run the browser flow or rebuild the minified bundle in this read-only review.

## Solution Assessment

Yes: reusing the existing copyToClipboard helper at the app-level workspace callback is the narrow maintainable fix. The open linked PRs are implementation candidates, not a reason to close the issue before merge.
