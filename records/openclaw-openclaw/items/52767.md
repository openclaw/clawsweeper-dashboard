## Summary

Keep open: current main still runs a non-empty BOOT.md on each gateway-startup hook event, and the latest release has the same central behavior. Related work fixed readiness blocking and boot-session isolation, but the requested cross-restart run-once lifecycle still needs a maintainer product/state decision.

## What This Changes

Request that the bundled boot-md hook stop re-running BOOT.md on every gateway restart and instead make BOOT.md idempotent or run-once.

## Best Possible Solution

Maintainers should decide the BOOT.md lifecycle first; if run-once wins, persist completion/reset state in canonical OpenClaw state, keep isolated boot sessions, and update docs plus restart regression tests.

## Reproduction Assessment

Yes at source level: each gateway:startup event schedules boot-md, the handler calls runBootOnce, and runBootOnce only skips missing or empty BOOT.md before agentCommand. I did not run a live restart freeze/channel-stall reproduction in this read-only review.

## Solution Assessment

No for the suggested flag-file shape: it addresses the symptom but adds ad hoc state and leaves reset, upgrade, and current per-startup semantics unsettled. The safer path is a maintainer-approved lifecycle contract backed by canonical state ownership and tests.
