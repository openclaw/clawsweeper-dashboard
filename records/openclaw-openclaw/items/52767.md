## Summary

Keep open: current main and the latest release still run BOOT.md whenever the boot-md gateway-startup hook fires and BOOT.md exists. Same-workspace duplicate runs and boot-session pollution have been fixed, but persistent cross-restart run-once semantics remains a maintainer product/state decision rather than implemented behavior.

## What This Changes

Review whether boot-md should stop re-running BOOT.md on every gateway restart and instead behave as a one-time or otherwise idempotent startup initializer.

## Best Possible Solution

Maintainers should decide the BOOT.md lifecycle contract first; if run-once wins, persist completion/reset state in the canonical runtime state owner, keep the isolated boot-session behavior, and update docs/tests to distinguish BOOT.md from BOOTSTRAP.md.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 both queue runBootOnce from the gateway-startup hook and skip only missing or empty BOOT.md before running the agent command. I did not run a live gateway restart because this review is read-only.

## Solution Assessment

No for the suggested flag-file shape: it would stop repeats, but it adds ad hoc state and leaves reset, upgrade, and documented startup semantics unsettled. The maintainable fix is a maintainer-approved lifecycle contract with canonical state ownership if BOOT.md becomes run-once.
