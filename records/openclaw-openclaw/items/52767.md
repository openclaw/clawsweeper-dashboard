## Summary

Keep open: current main and the latest release still execute BOOT.md on each gateway startup when the file is present. Related merged work reduced duplicate workspace runs, boot-session pollution, and startup blocking, but persistent run-once semantics still needs a maintainer product and state-ownership decision.

## What This Changes

Request to make the bundled boot-md hook stop rerunning BOOT.md on every gateway restart, likely by adding idempotency/completion state or redesigning the startup hook.

## Best Possible Solution

Maintainers should decide whether BOOT.md is per-restart or run-once; if run-once wins, store completion/reset state in the canonical OpenClaw state owner, keep isolated boot sessions, and update docs plus regression coverage.

## Reproduction Assessment

Yes, source-level: the boot-md handler queues runBootOnce on gateway:startup, and runBootOnce skips only missing or empty BOOT.md before agentCommand. I did not run a live gateway restart in this read-only review.

## Solution Assessment

No for the suggested flag-file guard: it would add ad hoc state while docs currently describe per-startup behavior. The safer path is a maintainer-approved BOOT.md contract plus canonical completion/reset state ownership if run-once behavior is desired.
