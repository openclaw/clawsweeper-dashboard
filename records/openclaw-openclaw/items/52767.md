## Summary

Keep open: current main and the latest release still run BOOT.md whenever the boot-md gateway-startup hook fires and BOOT.md exists. Merged work mitigated same-workspace duplicates, main-session pollution, and startup-readiness blocking, but it has not implemented persistent cross-restart run-once semantics, and changing that lifecycle needs maintainer product/state ownership.

## What This Changes

The issue asks for boot-md/BOOT.md to behave as one-time initialization instead of re-running on every gateway restart.

## Best Possible Solution

Maintainers should decide the BOOT.md lifecycle contract first; if run-once behavior wins, store completion/reset state in the canonical OpenClaw state owner, preserve isolated boot sessions, and update docs/tests to distinguish BOOT.md from BOOTSTRAP.md semantics.

## Reproduction Assessment

Yes, at source level: the boot-md handler queues runBootOnce on gateway startup, and runBootOnce skips only missing or empty BOOT.md before agentCommand. I did not run a live gateway restart in this read-only review.

## Solution Assessment

No for the proposed flag-file shape as-is: it would solve the symptom but adds ad hoc state and leaves reset/upgrade semantics unsettled. A maintainer-approved lifecycle contract plus canonical state ownership is the safer fix if run-once behavior wins.
