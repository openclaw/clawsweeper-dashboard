## Summary

Keep open: current main and v2026.6.11 still run BOOT.md whenever the enabled boot-md gateway-startup hook fires and BOOT.md exists, while the remaining run-once behavior would change the documented lifecycle and needs maintainer direction.

## What This Changes

The issue requests changing boot-md so BOOT.md does not re-run on every gateway restart and instead has an idempotent or first-run-only lifecycle.

## Best Possible Solution

Maintainers should decide the BOOT.md lifecycle first; if run-once wins, store completion/reset state in canonical OpenClaw state, keep isolated boot sessions, and update docs plus regression tests.

## Maintainer Decision

Rationale: Current code and docs intentionally describe per-startup execution, while the requested fix would add persistent state and change existing user-visible hook behavior.

Likely owner: ngutman

Owner confidence: medium

Options:

- **Keep per-startup BOOT.md:** Document the current contract as intentional and close or redirect run-once initialization to a separate setup/onboarding surface.
- **Adopt canonical run-once lifecycle (recommended):** Change boot-md to record completion/reset state in canonical OpenClaw state, preserve boot-session isolation, and update docs/tests for upgrade-safe behavior.
- **Add explicit opt-in mode:** Keep per-startup as the default and add a maintainer-approved run-once mode only if the extra configuration surface is worth the compatibility cost.

## Reproduction Assessment

Yes for the central behavior at source level: the handler queues runBootOnce on each gateway startup event, and runBootOnce skips only missing or empty BOOT.md before agentCommand. A live restart freeze/channel-stall reproduction was not run in this read-only review.

## Solution Assessment

No for the suggested ad hoc flag-file shape: it addresses the symptom but adds sidecar state and leaves reset, upgrade, and documented per-startup semantics unsettled. The safer path is a maintainer-approved lifecycle contract backed by canonical state ownership and tests.
