## Summary

Keep open: current main and v2026.6.11 still run BOOT.md whenever the boot-md gateway-startup hook fires and BOOT.md exists. Related merged work reduced duplicate same-workspace runs and isolated boot sessions, but the requested cross-restart run-once lifecycle remains a maintainer product/state decision.

## What This Changes

The issue asks for boot-md to stop re-running BOOT.md on every gateway restart and instead make BOOT.md idempotent or first-run-only.

## Best Possible Solution

Maintainers should define the BOOT.md lifecycle first; if run-once wins, store completion/reset state in canonical OpenClaw state, keep isolated boot sessions, and update docs plus regression tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should boot-md keep the documented per-gateway-startup BOOT.md behavior, switch to run-once per workspace/config generation, or split startup checks from first-run initialization?

Rationale: Current source, tests, and docs implement per-startup behavior, while the issue asks for a lifecycle change that needs canonical state ownership and reset semantics before code should change.

Likely owner: ngutman

Owner reason: ngutman introduced the boot-md startup hook and is the clearest history-backed owner for deciding whether its original lifecycle should change.

Owner confidence: medium

Options:

- **Make BOOT.md run-once with canonical state (recommended):** Store completion/reset state in OpenClaw-owned state, keep boot sessions isolated, and update docs/tests so heavy first-run work cannot repeat on every restart.
- **Keep per-startup semantics:** Document BOOT.md as a startup checklist and steer users toward idempotent content or disabling boot-md when repeated work is harmful.
- **Split first-run and startup hooks:** Introduce a separate first-run initialization surface while leaving BOOT.md as the existing per-startup hook, at the cost of a broader design change.

## Reproduction Assessment

Yes at source level: the handler queues runBootOnce on each gateway startup event, and runBootOnce skips only missing or empty BOOT.md before agentCommand. A live restart freeze or channel-stall reproduction was not run in this read-only review.

## Solution Assessment

No for the suggested flag-file shape: it would address the symptom, but it adds ad hoc state and leaves reset, upgrade, and current per-startup semantics unsettled. The safer path is a maintainer-approved lifecycle contract backed by canonical state ownership and tests.
