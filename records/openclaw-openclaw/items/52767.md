## Summary

Keep open: current main and v2026.6.11 still run BOOT.md whenever the enabled boot-md gateway-startup hook fires and BOOT.md exists. Several related hazards were reduced by per-workspace dedupe and boot-session isolation, but the remaining cross-restart run-once behavior needs maintainer lifecycle/state direction.

## What This Changes

The issue asks OpenClaw to stop re-running BOOT.md on every gateway restart and make boot-md behave like one-time initialization or another idempotent lifecycle.

## Best Possible Solution

Maintainers should decide the BOOT.md lifecycle contract first; if run-once wins, store completion/reset state in canonical OpenClaw state, preserve isolated boot sessions, and update docs plus regression tests to distinguish startup checks from first-run initialization.

## Reproduction Assessment

Yes for the central behavior at source level: the handler queues runBootOnce on each gateway startup event, and runBootOnce skips only missing or empty BOOT.md before agentCommand. A live restart freeze/channel-stall reproduction was not run in this read-only review.

## Solution Assessment

No for the suggested flag-file shape: it would address the symptom, but it adds ad hoc state and leaves reset, upgrade, and current per-startup semantics unsettled. The safer path is a maintainer-approved BOOT.md lifecycle contract backed by canonical state ownership and tests.
