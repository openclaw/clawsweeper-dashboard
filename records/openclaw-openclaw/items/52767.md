## Summary

Keep open: current main still executes BOOT.md whenever the boot-md gateway startup hook fires and the file exists. Related merged work fixed duplicate same-workspace runs, session pollution, and startup blocking, but the cross-restart run-once contract remains a maintainer product and state-ownership decision.

## What This Changes

The issue asks OpenClaw to stop re-running bundled boot-md/BOOT.md on every gateway restart and make that startup work idempotent or run-once.

## Best Possible Solution

Maintainers should decide whether BOOT.md remains per-restart startup automation or becomes run-once; if run-once wins, implement canonical state-backed completion/reset semantics with docs and regression coverage while preserving isolated boot sessions.

## Reproduction Assessment

Yes, at source level: current main queues runBootOnce for each unique workspace on gateway startup, and runBootOnce skips only missing or empty BOOT.md before invoking agentCommand. I did not run a live gateway restart in this read-only review.

## Solution Assessment

No, the suggested flag-file guard is not the best repo-shaped solution because it adds ad hoc state and leaves reset/upgrade semantics unsettled. A maintainer-approved BOOT.md contract plus canonical state ownership is the safer path if run-once behavior wins.
