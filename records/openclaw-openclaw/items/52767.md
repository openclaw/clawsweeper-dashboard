## Summary

Keep open: current main and the latest release still run BOOT.md whenever the boot-md gateway-startup hook fires and BOOT.md exists. Existing merged work reduced same-startup duplication and isolated boot sessions, but the requested cross-restart run-once lifecycle remains a maintainer product/state decision.

## What This Changes

The issue requests changing boot-md so BOOT.md does not rerun on every gateway restart and cannot repeatedly affect startup sessions or channel readiness.

## Best Possible Solution

Maintainers should define the BOOT.md lifecycle first; if run-once wins, store completion/reset state in canonical OpenClaw state, keep isolated boot sessions, and update docs plus regression tests.

Options:

- **Make BOOT.md Run-Once (recommended):** Store completion/reset state in OpenClaw-owned state, keep boot sessions isolated, and update docs/tests so heavy first-run work cannot repeat on every restart.
- **Keep Per-Startup Semantics:** Document BOOT.md as a startup checklist and steer users toward idempotent content or disabling boot-md when repeated work is harmful.
- **Split First-Run And Startup Hooks:** Introduce a separate first-run initialization surface while leaving BOOT.md as the existing per-startup hook, at the cost of a broader design change.
