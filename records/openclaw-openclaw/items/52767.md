## Summary

Keep open: current main and v2026.6.11 still run BOOT.md whenever the boot-md gateway-startup hook fires and BOOT.md exists. Related fixes addressed same-workspace duplicates, startup-readiness blocking, and boot-session isolation, but the requested cross-restart run-once lifecycle remains an unresolved product/state decision.

## What This Changes

The issue asks for boot-md to stop re-running BOOT.md on every gateway restart and instead use a run-once or idempotent lifecycle.

## Best Possible Solution

Maintainers should first define the BOOT.md lifecycle contract; if run-once wins, store completion/reset state in canonical OpenClaw state, preserve isolated boot sessions, and update docs plus regression tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should boot-md remain a documented per-gateway-startup check, or should BOOT.md become a run-once per workspace/config-generation lifecycle with an explicit reset path?

Rationale: Current docs and tests support recurring startup behavior, while the issue and production comment report real harm from repeated runs; choosing storage/reset semantics is product direction, not a safe automatic sentinel-file patch.

Likely owner: ngutman

Owner confidence: medium

Options:

- **Define run-once lifecycle (recommended):** Make BOOT.md run once per chosen workspace/config lifecycle, with canonical state, reset behavior, docs, and regression tests before implementation.
- **Preserve recurring startup checks:** Keep current documented per-startup behavior and close or re-scope this issue to narrower performance/session bugs only.
- **Split the concepts:** Keep boot-md as the recurring startup-check hook and create a separate first-run initialization surface if maintainers want both behaviors.

Yes at source level: the handler queues runBootOnce on each gateway startup event, and runBootOnce skips only missing or empty BOOT.md before agentCommand. I did not run a live restart to reproduce the reported freeze or channel stalls.

## Solution Assessment
