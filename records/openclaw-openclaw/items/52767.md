## Summary

Keep open: current main and the latest release still run BOOT.md whenever the boot-md gateway startup hook fires and the file exists. Related merged work fixed same-workspace duplicates, boot-session pollution, and startup readiness, but persistent run-once semantics remains a maintainer product/state decision.

## What This Changes

The issue asks OpenClaw to stop re-running BOOT.md on every gateway restart and make boot-md idempotent or no longer a normal startup hook.

## Best Possible Solution

Maintainers should decide whether BOOT.md is per-restart or run-once; if run-once wins, store completion/reset state in the canonical state owner, update docs, and keep the isolated boot-session and detached-startup behavior.

## Reproduction Assessment

Yes, at source level: the boot-md handler queues runBootOnce on gateway startup, and runBootOnce skips only missing or empty BOOT.md before agentCommand. I did not run a live gateway restart in this read-only review.

## Solution Assessment

No, the suggested flag-file guard is not the best repo-shaped solution because it adds ad hoc state and leaves reset/upgrade semantics unsettled. A maintainer-approved BOOT.md contract plus canonical state ownership is the safer path if run-once behavior wins.
