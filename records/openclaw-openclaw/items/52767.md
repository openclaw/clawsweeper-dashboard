## Summary

Keep open: current main and v2026.6.11 still run BOOT.md whenever the enabled gateway-startup hook fires and BOOT.md exists. Adjacent fixes landed for shared-workspace dedupe, boot-session isolation, and session-mapping cleanup, but the requested cross-restart run-once lifecycle remains a maintainer product/state decision.

## What This Changes

The issue asks OpenClaw to stop re-running BOOT.md on every gateway restart and make boot-md idempotent across restarts.

## Best Possible Solution

Maintainers should decide the BOOT.md lifecycle first; if run-once wins, store completion and reset state in canonical OpenClaw-owned state, keep isolated boot sessions, and update docs plus regression tests to distinguish startup checks from first-run initialization.
