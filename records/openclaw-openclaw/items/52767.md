## Summary

Keep open: current main and v2026.6.11 still run BOOT.md on each gateway startup when the file exists and has content. Related fixes addressed shared-workspace duplicates, startup readiness blocking, and boot-session isolation, but the requested cross-restart run-once lifecycle still needs a maintainer product/state decision.

## What This Changes

The issue asks for boot-md to stop re-executing BOOT.md on every gateway restart by making the boot flow run once or otherwise idempotent.

## Best Possible Solution

Define the BOOT.md lifecycle contract first; if run-once wins, store completion/reset state in canonical OpenClaw state, preserve isolated boot sessions, and update docs plus regression tests for restart and reset behavior.

Options:

- **Add an explicit mode:** Keep the compatibility default and add a reviewed opt-in run-once mode only if maintainers accept the added configuration surface.

## Reproduction Assessment

Yes for the central behavior at source level: gateway startup dispatch reaches runBootOnce, and runBootOnce skips only missing or empty BOOT.md before running the agent command. The reported freeze and channel stalls were not live-reproduced in this read-only review.

## Solution Assessment

No for the suggested flag-file shape: it would address the symptom, but it adds ad hoc state and leaves reset, upgrade, and the currently documented per-startup contract unsettled. The maintainable solution is a maintainer-approved lifecycle contract backed by canonical state and tests.
