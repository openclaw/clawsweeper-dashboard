## Summary

Keep open: current main and v2026.6.11 still execute BOOT.md whenever the boot-md gateway-startup hook fires and BOOT.md is present. Recent merged work fixed related session-isolation, shared-workspace duplicate, and startup-readiness problems, but the requested cross-restart run-once lifecycle remains a maintainer product/state decision rather than implemented behavior.

## What This Changes

The issue requests changing boot-md so BOOT.md does not re-run on every gateway restart.

## Best Possible Solution

Maintainers should decide the BOOT.md lifecycle contract first; if run-once wins, store completion/reset state in canonical OpenClaw state, keep the isolated boot session path, and update docs plus regression tests to distinguish startup checks from first-run initialization.

## Reproduction Assessment

Yes for the central source behavior: the handler queues runBootOnce on each gateway startup event and runBootOnce skips only missing or empty BOOT.md before agentCommand. No live restart freeze or channel-stall reproduction was run in this read-only review.

## Solution Assessment

No for the suggested flag-file shape: it would address the symptom but conflicts with OpenClaw's canonical-state direction and leaves reset, upgrade, and documented per-startup semantics unsettled. The safer path is a maintainer-approved BOOT.md lifecycle contract with canonical state and tests.
