## Summary

Keep open: current main still runs BOOT.md whenever the boot-md gateway-startup hook fires and BOOT.md exists. Merged work has reduced same-workspace duplicates, main-session pollution, and startup-readiness blocking, but persistent cross-restart run-once semantics remains a maintainer product/state decision rather than implemented behavior.

## What This Changes

The issue requests idempotent or run-once boot-md behavior so BOOT.md is not executed on every gateway restart.

## Best Possible Solution

Maintainers should decide the BOOT.md lifecycle first; if run-once wins, store completion and reset state in the canonical OpenClaw runtime state owner, keep isolated boot sessions, and update docs/tests to separate BOOT.md from BOOTSTRAP.md semantics.

## Reproduction Assessment

Yes, at source level: the boot-md handler queues runBootOnce on gateway startup, and runBootOnce skips only missing or empty BOOT.md before agentCommand. I did not run a live gateway restart in this read-only review.

## Solution Assessment

No for the suggested flag-file shape: it would solve the symptom, but it adds ad hoc state and leaves reset/upgrade semantics unsettled. A maintainer-approved BOOT.md contract plus canonical state ownership is the safer path if run-once behavior wins.
