## Summary

Keep open: current main and v2026.6.11 still run BOOT.md whenever the boot-md gateway startup hook fires and BOOT.md exists. Related merged work reduced duplicate workspace runs, main-session pollution, and startup-readiness risk, but persistent run-once semantics still needs a maintainer decision about the BOOT.md contract and state ownership.

## What This Changes

The issue asks OpenClaw to stop re-running BOOT.md on every gateway restart and make boot-md idempotent across restarts.

## Best Possible Solution

Maintainers should decide whether BOOT.md is a per-restart hook or a run-once workspace initializer; if run-once wins, persist completion/reset state in the canonical state owner, update the docs, and keep the isolated boot-session behavior.

## Reproduction Assessment

Yes, at source level: gateway startup still queues runBootOnce, and runBootOnce skips only missing or empty BOOT.md before running the agent command. I did not run a live gateway restart in this read-only review.

## Solution Assessment

Unclear as a product decision: the reported flag-file guard would stop repeats, but it is not the best repo-shaped solution because it creates sidecar state and leaves reset, docs, and upgrade semantics unsettled.
