## Summary

Keep open: current main still runs BOOT.md whenever the enabled boot-md gateway-startup hook fires and BOOT.md exists, while current docs now describe that as the supported per-startup behavior. Changing it to run once per workspace/config lifecycle needs a maintainer decision about lifecycle, reset behavior, and canonical state ownership.

## What This Changes

Request to make the bundled boot-md startup hook run BOOT.md only once per workspace/config lifecycle instead of on every gateway restart.

## Best Possible Solution

Maintainers should decide the BOOT.md lifecycle first; if run-once is desired, persist completion/reset state in canonical OpenClaw state, keep boot sessions isolated, and update docs plus regression tests for startup versus first-run behavior.

## Reproduction Assessment

Yes for the central source behavior: the gateway startup handler queues runBootOnce whenever boot-md fires, and runBootOnce skips only missing or empty BOOT.md before agentCommand. No live restart freeze/channel-stall reproduction was run in this read-only review.

## Solution Assessment

No for the suggested flag-file guard as an automatic fix: it addresses the symptom but would add ad hoc state and leave reset, upgrade, and current per-startup semantics unsettled. The maintainable path is a maintainer-approved BOOT.md lifecycle contract backed by canonical state ownership and tests.
