## Summary

Keep open: current main still runs BOOT.md on each gateway startup whenever the file exists. Merged boot-md work fixed same-workspace duplicates and boot-session pollution, but it did not add durable cross-restart run-once semantics, and changing that behavior needs a maintainer product/state decision.

## What This Changes

The issue requests boot-md to stop re-executing BOOT.md on every gateway restart and behave more like a first-run or explicitly reset initializer.

## Best Possible Solution

Maintainers should decide the BOOT.md lifecycle contract first; if run-once wins, store completion/reset state in a canonical OpenClaw state owner, keep the isolated boot session path, and update docs/tests to distinguish BOOT.md from BOOTSTRAP.md semantics.

## Reproduction Assessment

Yes. Source-level path: each gateway startup dispatches `gateway:startup`, the boot-md handler calls `runBootOnce` for each distinct workspace, and `runBootOnce` reruns whenever BOOT.md exists because it only skips missing or empty files. I did not run a live gateway restart in this read-only review.

## Solution Assessment

No for the suggested flag-file shape. It would address the symptom, but current docs define BOOT.md as restart/startup behavior and repository policy argues for a maintainer-approved lifecycle contract with canonical state ownership instead of ad hoc sidecar state.
