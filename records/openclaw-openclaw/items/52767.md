## Summary

Keep open: current main still executes BOOT.md on each gateway-startup event when the file exists, while current docs now define BOOT.md as startup behavior rather than first-run-only behavior. Changing it to run once needs a maintainer lifecycle and state-ownership decision.

## What This Changes

The issue requests changing the bundled boot-md hook so BOOT.md is not re-executed on every gateway restart.

## Best Possible Solution

Maintainers should decide the BOOT.md lifecycle first; if run-once wins, store completion and reset state in canonical runtime state, keep isolated boot sessions, and update docs/tests to separate BOOT.md from BOOTSTRAP.md semantics.

## Reproduction Assessment

Yes, at source level: the boot-md handler queues runBootOnce on gateway startup, and runBootOnce skips only missing or empty BOOT.md before agentCommand. I did not run a live gateway restart in this read-only review.

## Solution Assessment

No for the suggested flag-file shape: it would stop reruns, but it adds ad hoc state and conflicts with the current docs unless maintainers first change the BOOT.md lifecycle contract. A canonical state owner plus reset semantics is the safer path if run-once behavior wins.
