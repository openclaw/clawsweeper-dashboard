## Summary

Keep open: current main and latest release still run BOOT.md whenever the boot-md gateway-startup hook fires and the file exists. Related merged work mitigated same-workspace duplication and main-session pollution, but persistent run-once semantics still needs a maintainer product and state-ownership decision.

## What This Changes

The issue requests changing boot-md so BOOT.md runs only once per workspace or config generation instead of on every gateway restart.

## Best Possible Solution

Maintainers should decide the BOOT.md contract; if run-once behavior wins, store completion/reset state in the canonical state owner, update docs, and preserve isolated boot sessions.

## Reproduction Assessment

Yes, at source level: the boot-md handler queues runBootOnce on gateway startup, and runBootOnce skips only missing or empty BOOT.md before agentCommand. I did not run a live gateway restart in this read-only review.

## Solution Assessment

No, the suggested flag-file guard is not the best repo-shaped solution because it adds ad hoc state and leaves reset and upgrade semantics unsettled. A maintainer-approved BOOT.md contract plus canonical state ownership is safer if run-once behavior wins.
