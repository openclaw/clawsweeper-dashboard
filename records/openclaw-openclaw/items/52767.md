## Summary

Keep open: current main and the latest release still run BOOT.md whenever the boot-md gateway-startup hook fires and BOOT.md exists. Related merged work fixed same-workspace duplicates, startup-readiness blocking, and boot-session isolation, but the requested cross-restart run-once lifecycle is still a product/state decision.

## What This Changes

The issue asks for boot-md to stop re-running BOOT.md on every gateway restart and instead make BOOT.md first-run or otherwise idempotent.

## Best Possible Solution

Maintainers should decide the BOOT.md lifecycle first; if run-once wins, store completion/reset state in canonical OpenClaw state, keep isolated boot sessions, and update docs plus regression tests to distinguish startup checks from first-run initialization.

## Reproduction Assessment

Yes for the central behavior at source level: the handler queues runBootOnce on each gateway startup event, and runBootOnce skips only missing or empty BOOT.md before agentCommand. A live restart freeze/channel-stall reproduction was not run in this read-only review.

## Solution Assessment

No for the suggested flag-file shape: it would address the symptom, but it adds ad hoc state and leaves reset, upgrade, and current per-startup semantics unsettled. The safer path is a maintainer-approved BOOT.md lifecycle contract backed by canonical state ownership and tests.
