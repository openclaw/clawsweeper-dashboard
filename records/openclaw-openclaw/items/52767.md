## Summary

Keep open: current main and latest v2026.6.11 still run non-empty BOOT.md whenever the bundled boot-md gateway startup hook fires. Related merged work fixed same-workspace duplicates, startup blocking, prompt persistence, and boot session isolation, but the requested cross-restart run-once/idempotency contract is still a maintainer product and state-ownership decision.

## What This Changes

Request that the bundled boot-md hook stop re-running BOOT.md on every gateway restart and instead become idempotent or run-once.

## Best Possible Solution

Maintainers should first define the BOOT.md contract; if run-once behavior wins, persist completion/reset state in the canonical state owner, update docs and regression tests, and keep the existing boot-session isolation and detached startup dispatch.

## Reproduction Assessment

Yes, source-reproducible: current main dispatches boot-md on gateway startup and runBootOnce skips only missing or empty BOOT.md before executing the boot agent run. I did not run a live gateway restart in this read-only review.

## Solution Assessment

No, the suggested flag-file guard is not the best repo-shaped fix because it adds ad hoc state and leaves reset/upgrade semantics unsettled. The better path is a maintainer-approved BOOT.md contract with canonical completion/reset state if run-once behavior is desired.
