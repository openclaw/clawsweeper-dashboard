## Summary

Keep open: current main and the latest release still run BOOT.md whenever the boot-md gateway-startup hook fires and BOOT.md exists. Same-workspace dedupe, boot-session isolation, and echo-suppression fixes reduced adjacent damage, but persistent cross-restart run-once semantics remains a maintainer product/state decision rather than implemented behavior.

## What This Changes

Request to make boot-md idempotent so BOOT.md does not execute on every gateway restart.

## Best Possible Solution

Maintainers should decide the BOOT.md lifecycle first; if run-once wins, store completion/reset state in canonical OpenClaw runtime state, preserve isolated boot sessions, and update docs/tests to separate BOOT.md from BOOTSTRAP.md semantics.

## Reproduction Assessment

Yes at source level: the boot-md handler queues runBootOnce on gateway startup, and runBootOnce skips only missing or empty BOOT.md before agentCommand. I did not run a live gateway restart in this read-only review.

## Solution Assessment

No for the suggested flag-file shape: it would solve the symptom, but it adds ad hoc state and leaves reset, upgrade, and documented startup-check semantics unsettled. A maintainer-approved BOOT.md contract plus canonical state ownership is the safer path if run-once behavior wins.
