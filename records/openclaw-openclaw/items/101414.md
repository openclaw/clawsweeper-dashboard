## Summary

Keep this PR open, but do not merge the current head: the central fallback fix is well-supported and proven, while the latest head still suppresses the established `schema` runtime diagnostic for every structured invalid-request payload, and the intentionally broader failover behavior needs owner confirmation.

## What This Changes

The PR classifies structured `invalid_request_error` provider payloads as format failures, admits returned format-error payloads into model fallback, and adds classifier, formatter, result-level, and fallback integration coverage.

## Best Possible Solution

Keep the structured error-type mapping to the existing `format` fallback reason, but decouple failover eligibility from formatter/runtime diagnostics so these payloads still produce `providerRuntimeFailureKind: "schema"` and retain internal provider detail; then obtain explicit owner approval for applying that fallback behavior to all structured invalid requests.
