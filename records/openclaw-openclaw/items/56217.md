## What This Changes

The issue requests a gateway startup policy that prevents exec-backed SecretRef failures under supervised restarts from repeatedly invoking external secret providers and exhausting 1Password limits.

## Best Possible Solution

Adopt a maintainer-approved generic SecretRef startup failure policy that avoids repeated side-effecting provider calls while keeping the control plane repairable, with backend-specific batching or caching handled by resolver plugins/docs where current seams are sufficient.
