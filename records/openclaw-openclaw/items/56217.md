## Summary

Keep open: current main and the latest release still fail fast on required SecretRef startup activation failures, while exec provider failures still propagate immediately without startup backoff, circuit breaking, or rate-limit-aware behavior. The Varlock 1Password plugin linked in discussion is useful external batching/caching workaround context, but it does not resolve OpenClaw core's startup failure policy.

## What This Changes

The issue asks OpenClaw to prevent exec SecretRef provider failures from crash-looping under supervisors and exhausting 1Password service-account rate limits.

## Best Possible Solution

Define a generic core SecretRef startup failure policy that limits repeated side-effecting provider calls and preserves operator repair access, while keeping provider-specific batching or caching in external resolver/plugin patterns unless a missing core API is proven.
