## Summary

Keep open: current main and v2026.6.11 still fail startup when required SecretRef activation fails, while exec providers still fail immediately on timeout, no-output timeout, or nonzero exit without startup backoff, circuit breaking, or rate-limit-aware behavior. The Varlock 1Password plugin and the closed external-provider batching discussion are useful workaround/plugin context, but they do not resolve OpenClaw core's startup failure policy.

## What This Changes

The issue reports that exec-backed SecretRef resolution failures during supervised gateway startup can repeatedly invoke 1Password CLI reads and exhaust account-wide rate limits.

## Best Possible Solution

Keep this as the canonical core tracker for a generic startup SecretRef failure policy, while backend-specific batching/caching stays in ClawHub/plugin resolvers unless a missing core API is proven.
