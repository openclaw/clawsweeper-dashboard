## Summary

Keep open: current main and the latest release still fail gateway startup when active SecretRef resolution fails, and exec provider errors still propagate without startup backoff or circuit-breaking. The Varlock 1Password plugin linked in discussion is useful backend batching/caching context, but it does not resolve OpenClaw core's startup failure policy.

## What This Changes

The issue requests safer gateway behavior when exec SecretRef providers such as 1Password fail, so supervisor restarts do not repeatedly invoke secret resolution and exhaust external rate limits.

## Best Possible Solution

Keep this as the canonical OpenClaw tracker for a generic startup SecretRef failure policy, likely bounded retry/degraded behavior with clear operator diagnostics, while backend-specific batching and caching stay in resolver plugins or ClawHub when existing exec/pluginIntegration seams are enough.
