## Summary

Keep open: current main and v2026.6.11 still eagerly resolve active SecretRefs during startup, exec-provider failures still throw through the startup path, and the remaining fix needs maintainer/security policy rather than cleanup closure.

## What This Changes

The issue asks OpenClaw to prevent exec SecretRef startup failures from becoming supervisor-driven 1Password rate-limit exhaustion through backoff, circuit breaking, batching, or rate-limit-aware behavior.

## Best Possible Solution

Keep this as the canonical tracker for a generic, owner-approved startup SecretRef failure policy that limits supervisor retry storms while leaving backend-specific batching or caching to shared providers, plugins, or resolver tools unless a core API gap is proven.

Rationale: The current behavior is documented fail-fast startup, but this report shows a security-sensitive external rate-limit amplification; choosing retry, degraded startup, circuit breaking, config surface, or plugin-only delegation needs maintainer intent.

Options:

- **Generic bounded startup policy (recommended):** Add a provider-agnostic bounded retry/backoff and operator-visible diagnostic path for startup SecretRef failures without hardcoding 1Password behavior in core.
- **Configurable circuit/cache design:** Design a broader `secrets` policy surface for retry, circuit breaking, and delegated or persistent caching, accepting the extra config and migration review cost.
- **Plugin/delegated resolver only:** Keep core fail-fast and document shared external resolvers such as the Varlock 1Password plugin for batching and caching, with no core startup behavior change.

## Reproduction Assessment

Yes at source level: current main still eagerly resolves active SecretRefs, exec failures throw, and startup wraps them as fatal errors. I did not live-reproduce launchd plus 1Password quota exhaustion.

## Solution Assessment

Unclear until maintainers choose the startup policy. A generic bounded retry/backoff with operator-visible diagnostics looks like the narrowest core direction, while circuit breakers, config knobs, persistent caching, and `op`-specific behavior need product/security approval.
