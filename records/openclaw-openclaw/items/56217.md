## Summary

Keep open: current main and v2026.6.11 still fail gateway startup when required SecretRef activation fails, and exec provider failures still propagate without startup backoff, circuit breaking, or rate-limit-aware handling. The linked Varlock 1Password plugin is useful external workaround context, but it does not resolve OpenClaw core's startup failure policy.

## What This Changes

The issue asks OpenClaw to prevent exec SecretRef startup failures from crash-looping under supervisors and exhausting 1Password service-account rate limits.

## Best Possible Solution

Keep this as the canonical tracker for a generic startup SecretRef failure policy, while backend-specific batching or caching remains in resolver plugins or ClawHub packages when current extension seams are sufficient.
