## Summary

Keep open: current main and v2026.6.11 still eagerly resolve active SecretRefs during gateway startup and turn startup resolution failures into fatal startup errors, while exec provider failures still have timeout bounds but no retry, backoff, circuit breaker, or rate-limit-aware policy. The Varlock 1Password plugin linked in discussion is useful external batching/caching mitigation, but it does not resolve OpenClaw core's startup failure policy.

## What This Changes

The issue requests safer startup handling for exec-backed SecretRef failures so supervisor restart loops do not exhaust 1Password service-account rate limits.

## Best Possible Solution

Adopt an owner-approved generic startup SecretRef failure policy that bounds repeated side-effecting provider calls and gives clear operator recovery, while keeping backend-specific batching/caching in plugins or external resolvers unless a missing core API is identified.
