## Summary

Keep open: current main and v2026.6.11 still fail gateway startup when required SecretRef activation fails, and exec-provider failures still propagate without startup retry/backoff or rate-limit-aware behavior. The Varlock 1Password plugin linked in discussion is useful batching/caching workaround context, but it does not resolve OpenClaw core's startup failure policy.

## What This Changes

Request bounded startup SecretRef retry/backoff, circuit breaking, batching, or rate-limit handling so exec-backed 1Password failures do not crash-loop under supervisors and exhaust account-wide limits.

## Best Possible Solution

Choose a generic startup SecretRef failure policy that reduces supervisor-driven retry amplification while preserving fail-closed secret semantics; backend-specific batching/caching can stay in resolver plugins or external tools when current seams are sufficient.

## Solution Assessment

Unclear until maintainers choose the startup policy. A bounded generic startup retry is plausible, but the requested retryPolicy config, circuit breaker, batching, and rate-limit awareness have different compatibility and security tradeoffs.
