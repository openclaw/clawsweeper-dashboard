## Summary

Keep open: current main still resolves active SecretRefs eagerly during startup and still turns startup secret activation failures into fatal startup errors, while the newer crash-loop breaker suppresses channel/provider autostart only after repeated unclean boots and does not provide SecretRef retry/backoff, rate-limit handling, or a secret-resolution safe mode.

## What This Changes

The issue requests protection against supervisor-amplified exec SecretRef failures exhausting 1Password service-account rate limits during gateway startup.

## Best Possible Solution

Keep this issue as the canonical tracker and choose a generic startup SecretRef resilience policy that prevents repeated side-effecting exec calls without hardcoding 1Password into core; then repair or replace the linked PR with focused tests, docs, and upgrade proof.
