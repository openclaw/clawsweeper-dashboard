## Summary

Keep open: current main and v2026.6.11 still fail fast when required SecretRef activation fails at startup, and exec provider failures still propagate without startup backoff, circuit breaking, or rate-limit-aware handling. The Varlock 1Password plugin mentioned in discussion is useful batching/caching workaround context, but it does not resolve OpenClaw's generic startup SecretRef failure policy.

## What This Changes

The issue requests a SecretRef startup failure policy that prevents exec-backed providers such as 1Password from being retried into rate-limit exhaustion under process-manager restarts.

## Best Possible Solution

Keep this as the canonical tracker for a generic startup SecretRef failure policy, with maintainers choosing a bounded default backoff/degraded-startup or circuit-breaker strategy before adding any config surface.

## Reproduction Assessment

Yes for the fatal startup path at source/test level: current main still throws when required SecretRef startup activation fails, and exec provider errors propagate into that path. No live 1Password quota-exhaustion run was performed.

## Solution Assessment

Unclear until maintainers choose the startup policy. A bounded generic startup retry or degraded-startup strategy is plausible, but the requested retryPolicy config, circuit breaker, batching, and rate-limit awareness have different compatibility and security tradeoffs.
