## Summary

Keep open: current main and v2026.6.11 still eagerly resolve active SecretRefs and fail gateway startup on provider failures without startup backoff, circuit breaking, or rate-limit-aware behavior. The closed duplicate at https://github.com/openclaw/openclaw/issues/100073 and the Varlock 1Password plugin linked in discussion are useful context, but they do not resolve OpenClaw core's startup failure policy.

## What This Changes

The issue asks OpenClaw to prevent exec/1Password SecretRef startup failures from crash-looping under process supervisors and exhausting provider rate limits.

## Best Possible Solution

Keep this as the canonical tracker for a generic core startup SecretRef failure policy, document supervisor restart-storm guidance, and leave backend-specific batching/caching to resolvers or plugins such as Varlock unless core lacks the needed seam.
