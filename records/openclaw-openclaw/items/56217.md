## Summary

Keep open: current main and v2026.6.11 still fail gateway startup when required SecretRef activation fails, and exec-provider failures still propagate without startup retry, circuit breaking, or rate-limit-aware behavior. The linked Varlock 1Password plugin is useful workaround context, but it does not resolve OpenClaw core's startup failure policy.

## What This Changes

The issue asks OpenClaw to prevent exec-backed SecretRef startup failures from crash-looping under launchd/systemd and exhausting external secret-provider rate limits.

## Best Possible Solution

Keep this as the canonical tracker for a generic startup SecretRef failure policy: review, replace, or close the linked stale fork PR, then land an owner-approved provider-agnostic fix with docs and regression coverage.

Unclear until maintainers choose the startup policy. A bounded generic startup retry or degraded-startup strategy is plausible, but retryPolicy config, circuit breaking, batching, and rate-limit awareness have different compatibility and security tradeoffs.
