## Summary

Keep open: current main and v2026.6.11 still resolve active SecretRefs eagerly and fail fast on startup secret-provider errors, so the reported supervisor restart-loop risk remains. The Varlock 1Password plugin linked in discussion is useful external batching/caching context, but this issue remains the canonical core startup-policy tracker.

## What This Changes

The issue requests startup backoff, circuit-breaking, batching, or rate-limit-aware handling for exec SecretRef provider failures so supervised gateway restarts do not exhaust 1Password limits.

## Best Possible Solution

Land a maintainer-approved generic startup SecretRef failure policy that limits side-effecting exec-provider retry storms under supervisors, with backend-specific batching/caching left to resolver plugins when current extension seams are enough.
