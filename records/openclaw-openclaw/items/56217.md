## Summary

Keep open: current main and v2026.6.11 still eagerly resolve active SecretRefs, fail gateway startup on required secret activation errors, and propagate exec-provider failures without startup backoff or rate-limit-aware handling. The linked Varlock 1Password plugin is useful external workaround context, but it does not settle OpenClaw's core startup failure policy.

## What This Changes

The issue requests protection against exec SecretRef provider restart storms, especially 1Password `op` failures under launchd/systemd, through startup backoff, circuit breaking, batching, or rate-limit-aware behavior.

## Best Possible Solution

Choose a maintainer-approved generic SecretRef startup failure policy, likely bounded in-process retry/backoff plus operator guidance, while keeping required-secret failures fail-closed unless maintainers explicitly approve degraded mode.
