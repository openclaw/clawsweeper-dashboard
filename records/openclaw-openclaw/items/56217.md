## Summary

Keep open: current main and v2026.6.11 still eagerly resolve active SecretRefs and throw fatal startup errors when exec provider resolution fails, with no startup retry, circuit breaker, or rate-limit-aware policy. The same-repo fix PR was closed as superseded, and the still-open fork PR is conflicting and not a viable canonical landing path.

## What This Changes

The issue asks for SecretRef exec-provider startup failure handling so 1Password-backed providers do not crash-loop under process managers and exhaust service-account rate limits.

## Best Possible Solution

Keep this as the canonical tracker for a generic startup SecretRef failure policy, with backend-specific batching or caching left to plugins/ClawHub when current extension seams are sufficient.
