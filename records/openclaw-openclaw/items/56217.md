## Summary

Keep open: current main and v2026.6.11 still fail gateway startup when active SecretRef resolution fails, and exec providers still have timeout limits but no startup backoff, circuit breaker, or rate-limit-aware policy. The Varlock 1Password plugin linked in discussion is useful external batching/caching workaround context, but it does not resolve OpenClaw core's startup failure policy.

## What This Changes

The issue requests protection against supervisor-driven SecretRef exec-provider crash loops that can exhaust 1Password service-account rate limits.

## Best Possible Solution

Adopt a maintainer-approved generic startup SecretRef failure policy that prevents supervisor restart storms while preserving secure fail-closed semantics; leave backend-specific batching/caching to resolver plugins or clear docs when current plugin seams are sufficient.
