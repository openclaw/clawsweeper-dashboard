## Summary

Keep open: current main and the latest stable release still fail gateway startup when required SecretRef activation fails, and exec-provider timeouts or nonzero exits still propagate without startup retry, circuit breaking, or rate-limit-aware behavior. The Varlock 1Password plugin linked in discussion is useful batching/caching workaround context, but it does not resolve OpenClaw core's supervised startup failure policy.

## What This Changes

The issue asks OpenClaw to prevent supervised gateway startup failures from repeatedly invoking exec-based SecretRef providers and exhausting 1Password service-account rate limits.

## Best Possible Solution

Adopt a maintainer-approved, source-agnostic startup SecretRef failure policy that reduces supervisor-amplified exec-provider calls, preserves secure fail-closed credential semantics, and documents operator recovery guidance.

- **Docs and supervisor guidance only:** Keep runtime fail-fast semantics and document launchd/systemd throttling plus external resolver caching, accepting that OpenClaw will not directly reduce provider calls during restart storms.
- **Configurable retry/circuit breaker:** Add a new retry or circuit-breaker config surface, accepting higher config, migration, documentation, and upgrade-review cost.
