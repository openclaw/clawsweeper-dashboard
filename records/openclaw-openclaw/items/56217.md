## Summary

Keep open: current main and v2026.6.11 still fail gateway startup when required SecretRef activation fails, and exec provider failures still propagate without startup backoff, circuit breaking, or rate-limit-aware behavior. The Varlock 1Password plugin linked in discussion is useful batching/caching workaround context, but it does not resolve OpenClaw core's startup failure policy.

## What This Changes

The issue asks OpenClaw to prevent failing exec-backed SecretRef resolution from entering supervisor restart loops that exhaust 1Password service-account limits.

## Best Possible Solution

Keep this as the canonical tracker for an owner-approved generic startup SecretRef failure policy, with bounded retry/degrade behavior in core and backend-specific batching or caching left to resolver plugins such as the linked Varlock path when current seams are sufficient.
