## Summary

Keep open: current main and the latest release still fail gateway startup when required SecretRef activation fails, and exec providers still lack startup backoff, circuit breaking, or rate-limit-aware behavior. The Varlock 1Password plugin linked in discussion is useful batching/caching workaround context, but it does not resolve OpenClaw core's startup failure policy.

## What This Changes

The issue asks OpenClaw to prevent exec-backed SecretRef startup failures, especially 1Password `op read` failures, from being amplified by launchd/systemd restart loops into external secret-provider rate-limit exhaustion.

## Best Possible Solution

Keep this as the canonical tracker for a generic startup SecretRef failure policy, while backend-specific batching or caching remains external/plugin-owned when current seams are sufficient.
