## Summary

Keep open. The report describes a credible user-facing Codex turn-lifecycle bug, and current main still propagates terminating dynamic-tool results into the Codex bridge; however, the evidence does not yet establish whether the `message` tool, result middleware, or terminal-release containment path should own the distinction between progress and final sends.

## What This Changes

Prevent an intermediate Telegram `message(action=send)` from prematurely ending a Codex turn when source replies use `message_tool_only` delivery.

## Best Possible Solution

Define one shared message-tool result intent for progress versus final delivery, preserve terminal handling only for explicit final sends, and add parity coverage proving progress continues while final Telegram delivery still closes cleanly in both Pi and Codex runtimes.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should `message(action=send)` remain terminal by default in `message_tool_only` mode, or should termination require explicit final-delivery intent?

Rationale: The runtime cannot reliably infer from a successful send alone whether the assistant intended a progress update or its final source reply, while changing either default affects turn completion and stuck-turn containment.

Likely owner: vincentkoc

Owner reason: The terminal-release containment behavior and Codex dynamic-tool lifecycle are most directly connected to this person's recent work.

Owner confidence: medium

Options:

- **Add explicit delivery intent (recommended):** Introduce shared internal progress/final result metadata, continue after progress sends, and retain terminal release for explicit final sends.
- **Never terminalize message sends:** Treat every successful message send as non-terminal and rely on normal Codex `turn/completed`, accepting possible final-turn liveness regressions.
- **Keep terminal-by-default semantics:** Retain the current behavior and document that source-channel progress updates must not use the message tool during an active Codex turn.

## Reproduction Assessment

No high-confidence current-main live reproduction is established yet. The release logs and current termination propagation make the failure source-reproducible, but a focused test must prove that a Telegram message send produces terminal metadata and releases before a subsequent tool call.

## Solution Assessment

Unclear. A narrow shared progress-versus-final intent contract is safer than disabling release globally or adding a Telegram-only exception, but maintainers must confirm the permanent message-tool semantics.
