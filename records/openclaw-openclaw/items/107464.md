## Summary

Keep open. The report identifies a credible regression at the message-tool/Codex lifecycle boundary: the shipped terminal-release behavior solves stuck final replies, but it does not distinguish a final source reply from an intermediate visible update. Current evidence supports the bug, but maintainers must choose the permanent progress-versus-final result contract before implementation.

## What This Changes

Prevent intermediate Telegram `message(action=send)` calls from prematurely ending Codex turns in `message_tool_only` delivery mode.

## Best Possible Solution

Define one typed, harness-neutral message result disposition that distinguishes an intermediate visible update from the final source reply; preserve terminal release for final sends, keep progress sends non-terminal, and cover Pi/Codex parity plus a live Telegram multi-tool turn.
