## What This Changes

The PR prevents cron jobs from being dispatched twice after an in-flight disable/re-enable cycle by consulting the active-job registry, retaining the persisted run marker, and adding regression coverage.

## Best Possible Solution

Keep the process-local active-job check and persisted `runningAtMs` reservation aligned as complementary concurrency guards, with the regression covering update, timer selection, completion, and marker cleanup.

## Reproduction Assessment

Yes. A force run can be held in flight, followed by disable, re-enable, and one timer tick; current-main state transitions then permit a second dispatch because the persisted marker is cleared while the active registry remains set.

## Solution Assessment

Yes. Checking the existing active-job registry at shared due selection fixes the immediate race, while retaining the persisted marker through disabled maintenance preserves the same invariant across store reloads.
