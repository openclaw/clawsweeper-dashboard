## Summary

Keep open. Current main has flat API-key rotation and bounded auth-profile retry/backoff, but it still lacks the requested quota-bucket/project grouping and bucket-level cooldown needed to prevent Gemini project/account retry storms; related work only partially overlaps rather than safely replacing this issue.

## What This Changes

Request native provider key pools with bucket-aware cooldown/backoff so Gemini project-level quota failures stop retrying equivalent keys or sibling models.

## Best Possible Solution

Define an additive generic provider/auth quota-bucket contract that preserves flat rotation defaults, lets provider profiles expose shared quota buckets, documents upgrade/status behavior, and uses Gemini as the first consumer after maintainer scoping.
