## Summary

Keep open: current main covers flat provider API-key rotation, same-provider auth-profile rotation, and profile/model cooldowns, but it still has no quota-bucket or Gemini project grouping contract. The remaining work is a provider/auth product decision rather than a narrow bug fix.

## What This Changes

The issue requests provider API-key pools with rate-limit cooldown/backoff and Gemini project or quota-bucket grouping so OpenClaw can avoid retrying the same exhausted quota bucket.

## Best Possible Solution

Define an explicit provider/auth quota-bucket contract, likely alongside the provider-profile routing design, with bucket metadata, bucket-level cooldown state, docs, upgrade-safe config, and live Gemini proof; avoid log-tailing auth.json rewrites as the long-term product path.
