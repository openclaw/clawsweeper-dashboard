## Summary

Keep open: current main and the latest release support flat API-key rotation, model/profile cooldowns, and bounded same-provider rate-limit retries, but they still do not provide a provider/auth quota-bucket contract that can cool down all keys sharing an exhausted Gemini project. The linked Keymanager sidecar and public fork are useful prior art, but they do not make this OpenClaw core/provider behavior implemented.

## What This Changes

Request first-class provider key pools with quota-bucket-aware cooldown/backoff for 429 and RESOURCE_EXHAUSTED failures, especially Gemini project buckets, to avoid retry storms.

## Best Possible Solution

Define an additive provider/auth quota-bucket contract that preserves flat key rotation by default, lets Google/Gemini credentials expose shared project buckets, records observable cooldown state, and documents status, doctor, and upgrade behavior before implementation.
