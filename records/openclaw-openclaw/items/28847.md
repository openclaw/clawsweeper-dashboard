## Summary

Keep open: current main and the latest release cover flat API-key rotation plus auth-profile/model cooldowns, but they do not define Gemini project/quota-bucket grouping or bucket-level cooldown semantics.

## What This Changes

The issue requests provider key pools with quota-bucket-aware cooldown/backoff so Gemini project-scoped 429s rotate away from the exhausted quota bucket without retry storms.

## Best Possible Solution

Define an additive provider/auth quota-bucket contract that preserves flat rotation defaults, lets provider plugins expose shared quota groups, and documents status output, upgrade behavior, and Gemini proof before implementation.

- **Keep outside core:** Require provider plugins or sidecars to handle project-aware suppression if maintainers decide current seams are sufficient.
