## Summary

Keep open: current main and the latest release cover flat API-key rotation plus auth-profile/model cooldowns, but they still do not define Gemini project/quota-bucket grouping or bucket-level cooldown semantics.

## What This Changes

The issue requests provider key pools with quota-signal backoff and Gemini project/bucket-aware cooldown so 429s avoid retrying keys that share the same quota bucket.

## Best Possible Solution

Define an additive provider/auth quota-bucket contract that preserves flat rotation defaults, lets provider plugins expose shared quota groups, and documents status output, upgrade behavior, and Gemini proof before implementation.
