## Summary

Keep open: current main and v2026.6.11 cover flat API-key rotation plus profile/model cooldowns, but they still do not model shared Gemini project/quota buckets or a native key-pool routing contract. The linked Keymanager sidecar is useful evidence, and the remaining choice is a provider/auth product decision rather than conservative cleanup.

## What This Changes

The issue requests native provider key pools with bucket-aware cooldown/backoff for quota signals, especially Gemini project-level 429 handling.

## Best Possible Solution

Define one additive generic provider/auth quota-bucket contract that preserves today’s defaults, lets providers or profiles expose shared quota buckets, and documents migration/status behavior before implementing Gemini-specific policy.
