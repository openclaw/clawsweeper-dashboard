## Summary

Keep open: current main and v2026.6.11 support flat API-key rotation and bounded auth-profile cooldown/rotation, but they still do not model Gemini project/quota buckets or bucket-level cooldown state. The remaining work is a compatibility-sensitive provider/auth product decision, not conservative cleanup-close material.

## What This Changes

Request native provider key pools with 429 backoff and Gemini project-bucket-aware cooldown/rotation to avoid retry storms.

## Best Possible Solution

Define one additive generic provider/auth quota-bucket contract that preserves current flat rotation defaults, lets providers or profiles expose shared quota buckets, and documents migration/status behavior before adding Gemini-specific policy.
