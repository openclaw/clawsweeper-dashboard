## Summary

Keep open: current main and v2026.6.11 cover flat API-key rotation plus per-profile/model cooldowns, but they still do not model shared Gemini project/quota buckets or bucket-level cooldown state. The remaining work is a provider/auth product contract decision, not a cleanup-close candidate.

## What This Changes

The issue requests provider API-key pools with Gemini project bucket-aware cooldown/backoff and hot rotation on 429/RESOURCE_EXHAUSTED responses.

## Best Possible Solution

Define one maintainer-approved provider-pool contract that preserves current flat key/profile defaults, adds explicit quota-bucket metadata only where needed, and documents Gemini project-scoped behavior with upgrade-safe config or plugin seams.
