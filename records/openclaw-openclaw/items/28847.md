## Summary

Keep open: current main supports flat API-key rotation and bounded same-provider auth-profile rotation, but it still has no quota-bucket/project grouping or bucket-level cooldown state for Gemini-style shared project quotas. The remaining work is a provider/auth product contract decision, not a safe cleanup close.

## What This Changes

Request provider key pools with bucket-aware cooldown/backoff on 429 or RESOURCE_EXHAUSTED signals, especially for Gemini keys grouped by Google project quota.

## Best Possible Solution

Define one additive generic provider/auth quota-bucket contract that preserves current flat rotation defaults, lets providers or profiles expose shared quota buckets, and documents status, migration, and fallback behavior before adding Gemini-specific policy.
