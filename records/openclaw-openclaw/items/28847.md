## Summary

Keep open: current main only has flat API-key rotation and bounded auth-profile rotation, while the requested Gemini-style quota bucket/project grouping and bucket-level cooldown contract is still missing; the linked sidecar and fork comments are useful evidence, but they do not replace a native product decision.

## What This Changes

The issue requests native provider key pools with bucket-aware cooldown/backoff for 429 and RESOURCE_EXHAUSTED failures, especially for Gemini project-scoped quotas.

## Best Possible Solution

Define one additive generic provider/auth quota-bucket contract that preserves current flat rotation defaults, lets providers or profiles expose shared quota buckets, and documents status, migration, and live-proof expectations before adding Gemini-specific policy.
