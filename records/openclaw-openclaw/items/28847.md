## Summary

Keep open: current main now covers flat Gemini API-key rotation for the Google LLM stream path, generic key rotation, profile/model cooldowns, and bounded rate-limit retries, but it still does not provide the requested quota-bucket/project grouping or bucket-wide cooldown model. The remaining work is a compatibility-sensitive provider/auth product design, not a safe cleanup close.

## What This Changes

Request first-class provider key pools with 429 backoff and Gemini project or quota-bucket-aware cooldown so retries avoid storming the same quota bucket.

## Best Possible Solution

Define an opt-in provider/auth bucket model that groups credentials by quota bucket or project, applies bucket-wide cooldowns for new requests without changing single-key defaults, and ships with docs, focused tests, and any required doctor/config migration.

## Reproduction Assessment

Yes at source level: current main has flat key rotation, profile/model cooldowns, and same-provider failover caps, but no bucket/project metadata or bucket-wide cooldown state. I did not run a live exhausted Gemini project.

## Solution Assessment

Unclear as proposed: the sidecar is useful evidence, but the maintainable fix should be a maintainer-approved core/provider-auth design rather than log tailing plus auth-state rewrites.
