## Summary

Keep open: current main has flat API-key rotation, per-profile/model cooldowns, and the new ClawRouter managed-proxy plugin, but it still lacks a native provider key-pool quota identity that can cool down all Gemini keys from the same project or bucket.

## What This Changes

The issue requests provider key pools with bucket-aware cooldown/backoff for Gemini project quota groups to avoid retry storms after 429 or RESOURCE_EXHAUSTED responses.

## Best Possible Solution

Define an additive provider-owned quota-scope identity on key/auth candidates, route 429 cooldown through that scope, preserve current defaults, and reconcile the API shape with the broader provider-profile routing design before implementation.

## Reproduction Assessment

Yes at source level: current main exposes flat key rotation and per-profile/model cooldowns, while no shared quota-bucket identity exists in key collection, auth-profile state, or Google provider docs. I did not run a live exhausted Gemini multi-project account in this read-only review.

## Solution Assessment

Partly: native bucket-aware provider behavior targets the right gap, but the sidecar log-watcher/auth-file rewrite should stay a workaround rather than the core design. The best fix needs a typed provider/auth quota identity and maintainer-approved config or plugin API shape.
