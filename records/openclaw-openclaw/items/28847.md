## Summary

Keep open: current main has flat API-key rotation and same-provider auth-profile cooldown/rotation, but it still lacks a native quota-bucket or Gemini project-level cooldown contract, and the related open items do not replace this specific bucket-aware request.

## What This Changes

The issue requests native provider key pools with 429 cooldown/backoff and Gemini project or quota-bucket grouping so retries avoid exhausted quota buckets without a gateway restart.

## Best Possible Solution

Define one additive generic provider/auth quota-bucket contract that preserves current flat rotation defaults, lets providers or profiles expose shared quota buckets, and documents migration/status behavior before adding Gemini-specific policy.
