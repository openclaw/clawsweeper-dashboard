## Summary

Keep open: current main and the latest release already have generic API-key rotation and auth-profile cooldowns, but they still do not implement Gemini/project quota-bucket state or an explicit provider key-pool routing contract, and the remaining design is compatibility-sensitive.

## What This Changes

Request provider API-key pools with quota-bucket cooldown/backoff for Gemini project-scoped 429s and no-restart key rotation.

## Best Possible Solution

Define an additive provider/auth pool routing contract that preserves current defaults while supporting provider-owned quota-bucket metadata, cooldown state, status visibility, and focused docs/tests for Gemini-style project-scoped limits.

- **Defer To External Sidecar Or Plugin:** Document the current sidecar/plugin path and do not add native bucket-aware key routing until maintainers decide the core state/config cost is justified.
