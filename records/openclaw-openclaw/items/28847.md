## Summary

Keep open: current main and the latest stable release have flat API-key rotation plus auth-profile cooldown/rotation, but they still do not model Gemini project or billing-account quota buckets. The remaining work is a compatibility-sensitive provider/auth product contract, not a conservative cleanup close.

## What This Changes

The issue requests provider key pools with bucket-aware cooldown/backoff on 429-style quota failures, especially for Gemini projects that share quota across keys.

## Best Possible Solution

Define one additive generic provider/auth quota-bucket contract that preserves current flat rotation defaults, lets providers or profiles expose shared quota buckets, and documents migration/status behavior before adding Gemini-specific policy.
