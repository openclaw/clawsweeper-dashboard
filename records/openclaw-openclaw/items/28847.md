## Summary

Keep open: current main supports flat API-key rotation, bounded same-provider auth-profile rotation, and short-window same-model rate-limit retry, but it still lacks native quota-bucket/project grouping or bucket-level cooldown state for Gemini-style project quotas.

## What This Changes

The issue requests native provider API-key pools with quota-bucket-aware 429 cooldown/backoff, especially for Gemini project-level quotas, to avoid retry storms and allow hot key rotation without gateway restart.

## Best Possible Solution

Define an additive generic provider/auth quota-bucket contract that preserves current flat rotation defaults, lets providers or profiles expose shared quota buckets, and documents migration/status behavior before adding Gemini-specific policy.
