## Summary

Keep open: current main covers flat provider API-key rotation, bounded same-provider auth-profile rotation, and rate-limit cooldown handling, but it still lacks first-class Gemini project/quota-bucket grouping and a native key-pool routing contract. The remaining work is a compatibility-sensitive provider/auth product decision, not conservative cleanup.

## What This Changes

The issue requests native provider API-key pools with rate-limit cooldown, Gemini project bucket grouping, and hot key rotation to avoid repeated 429 retry storms.

## Best Possible Solution

Define an additive generic provider/auth pool contract that can represent project or quota buckets while preserving current session-sticky defaults and flat key rotation for existing users.
