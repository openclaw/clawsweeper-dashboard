## Summary

Keep open: current main and v2026.6.11 support flat API-key rotation plus bounded auth-profile cooldown/rotation, but they still do not provide native quota-bucket or Gemini project-level cooldown state. The remaining work is a compatibility-sensitive provider/auth product decision, not conservative cleanup.

## What This Changes

The issue requests provider key pools with bucket-aware cooldown/backoff so Gemini keys sharing a Google project quota are cooled down together and rotation picks another quota bucket.

## Best Possible Solution

Define one additive generic provider/auth quota-bucket contract that preserves current flat rotation defaults, lets providers or profiles expose shared quota buckets, and documents status, migration, and tests before adding Gemini-specific policy.
