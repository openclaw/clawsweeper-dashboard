## Summary

Keep open: current main covers flat API-key rotation and bounded same-provider auth-profile cooldown/rotation, but it still does not provide native Gemini project/bucket grouping or bucket-level cooldown semantics.

## What This Changes

The issue requests provider key pools with bucket-aware cooldown/backoff for Gemini-style 429 or RESOURCE_EXHAUSTED quota failures.

## Best Possible Solution

Define a maintainer-approved provider-pool/bucket contract that reuses auth-profile cooldown state, records Gemini project or quota-bucket identity, and rotates without log tailing or auth-file rewriting.
