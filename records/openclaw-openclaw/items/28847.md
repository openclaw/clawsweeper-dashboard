## Summary

Keep open: current main and the latest release implement flat API-key rotation plus same-provider auth-profile cooldown/rotation, but they still do not model Gemini project or quota-bucket identity for bucket-wide cooldown. The remaining work is a compatibility-sensitive provider/auth product decision, not a safe cleanup close.

## What This Changes

Add provider key pools with bucket-aware cooldown/backoff so Gemini project-level 429/RESOURCE_EXHAUSTED failures stop retrying keys from the same exhausted quota bucket.

## Best Possible Solution

Define an additive provider/auth pool contract that groups credentials by quota bucket or project, applies bucket-wide cooldowns for new requests while preserving single-key defaults, and ships with docs, focused tests, and any needed doctor/config migration.

## Reproduction Assessment

Partly. Source inspection shows current main has flat key/profile cooldown paths but no bucket metadata or bucket-wide cooldown, while a live exhausted Gemini project was not replayed in this read-only review.

## Solution Assessment

Unclear as proposed. The sidecar proves demand, but the maintainable solution should be a maintainer-approved provider/auth design rather than log tailing and auth-state rewrites.
