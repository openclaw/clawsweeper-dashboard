## Summary

Keep open: current main and the latest release still implement flat Google/Gemini key rotation and profile/model cooldowns, but no provider/auth quota-bucket contract that can avoid retrying sibling keys or models sharing an exhausted Gemini project or billing account.

## What This Changes

The issue requests quota-bucket-aware provider/auth failover so Gemini keys or sibling models sharing an exhausted project/account are skipped instead of retried flatly.

## Best Possible Solution

Define an additive generic provider/auth quota-bucket contract that preserves flat rotation defaults, lets provider profiles expose shared quota buckets, documents upgrade/status behavior, and uses Gemini as the first consumer after maintainer scoping.

- **Keep outside core:** Require provider plugins or sidecars to handle project-aware suppression if maintainers decide current seams are sufficient.

## Solution Assessment

Unclear until maintainers choose the contract; a generic additive provider/auth bucket seam is safer than hardcoding Gemini project rules or adopting sidecar behavior as core policy.
