## Summary

Keep open: current main and the latest release support flat provider API-key rotation and auth-profile cooldowns, but there is still no quota-bucket/project grouping contract for Gemini keys that share a Google quota source. The broader provider-pool routing issue overlaps, but this issue preserves a narrower Gemini bucket/backoff acceptance case that is not safely closed as implemented or duplicate.

## What This Changes

Add provider key pools with Gemini project/bucket-aware cooldown and backoff on 429 or RESOURCE_EXHAUSTED responses so OpenClaw avoids retry storms against keys sharing one quota source.

## Best Possible Solution

Define an additive, default-compatible provider/auth quota-bucket contract that lets provider plugins expose shared quota groups and makes status/docs show when a Gemini project bucket is cooled down.
