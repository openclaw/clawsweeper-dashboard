## Summary

Keep open: current main and v2026.6.11 still route ordinary Feishu same-chat messages through the full sequential handler before shared active-run queue admission, and the linked fixing PR is still open rather than merged.

## What This Changes

The issue reports that Feishu's per-chat serial queue prevents existing `messages.queue.mode = "collect"` behavior from batching follow-up messages sent during an active run.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/92962 so ordinary Feishu same-chat follow-ups reach shared active-run queue admission while preserving control and `/btw` lane ordering.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Source inspection shows Feishu still awaits the same-key sequential task around the full message handler, and the shared queue only batches followups when they arrive while `isActive` is true; I did not run a live Feishu tenant reproduction.

## Solution Assessment

Yes. The narrow maintainable fix belongs at the Feishu receive/sequential-queue boundary because the shared queue policy already handles collect/steer once messages reach it during an active run.
