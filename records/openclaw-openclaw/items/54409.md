## What This Changes

The issue asks Feishu ordinary same-chat messages to reach the shared active-run queue during `messages.queue.mode = "collect"` instead of being serialized until the prior agent turn finishes.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/92962 after resolving conflicts, preserving Feishu dedupe/self-filter behavior, and proving live Feishu collect or steer delivery.

## Reproduction Assessment

Yes, source-level: current main still awaits the Feishu same-key sequential queue around the full handler, while the shared queue only collects followups that arrive while a run is active. I did not run a live Feishu tenant reproduction in this read-only review.

## Solution Assessment
