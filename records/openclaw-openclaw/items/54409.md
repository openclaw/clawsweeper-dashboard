## Summary

Keep open: current main and the latest release still await Feishu same-key serialization around the full message handler, so active-run collect/steer followups can arrive too late for the shared queue, and the linked fixing PR is still open and conflicting.

## What This Changes

The issue requests fixing Feishu collect-mode active followups so ordinary same-chat messages sent during an active run can reach the shared queue and batch into one followup turn.

## Best Possible Solution

Review, refresh, and land or replace https://github.com/openclaw/openclaw/pull/92962 so ordinary Feishu same-chat followups bypass only when an ordinary key is actually running while control and `/btw` lanes stay serialized.

## Reproduction Assessment

Yes, source-reproducible: Feishu still awaits same-key sequential enqueue around the full handler, while the shared queue admits collect followups only if they arrive while a run is active. I did not run a live Feishu tenant reproduction.

## Solution Assessment

Yes, the best repair belongs at the Feishu receive/sequential-queue boundary because shared queue policy already handles active arrivals; the open linked PR is the candidate but needs refresh and proof before landing.
