## Summary

Keep open: current main and v2026.6.11 still serialize Feishu same-chat work around the full message handler, so collect/steer follow-ups can still reach the shared queue after the active run has ended; the linked fix candidate is open and not merged.

## What This Changes

The issue reports that Feishu same-chat serial dispatch prevents `messages.queue.mode = "collect"` follow-up messages from batching while an agent run is active.

## Best Possible Solution

Land or replace the linked Feishu follow-up delivery fix so ordinary same-chat follow-ups can reach the shared queue while preserving control, `/btw`, dedupe, and ordering guarantees.

## Reproduction Assessment

Yes from source inspection: current main still awaits the same-key Feishu sequential queue around the full handler before the shared queue can observe active-run state. I did not run a live Feishu tenant reproduction in this read-only review.

## Solution Assessment

Yes: the remaining fix belongs at the Feishu receive/sequential-queue boundary because shared queue policy already handles collect/follow-up admission when messages arrive during an active run. The linked PR is the current implementation candidate, but it still needs review and merge before this issue can close.
