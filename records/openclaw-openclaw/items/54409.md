## Summary

Keep open: current main and the latest release still route ordinary Feishu same-chat messages through the full sequential handler before shared active-run queue admission, and the open fixing PR is not merged.

## What This Changes

The issue reports that Feishu same-chat serialization prevents `messages.queue.mode = "collect"` from batching follow-up messages while a prior Feishu run is active.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/92962 so ordinary Feishu same-chat follow-ups can reach shared active-run queue admission while preserving control and `/btw` lane ordering.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Source inspection shows Feishu still awaits the same-key sequential task around the full message handler, and the shared queue only enqueues followups when they arrive while `isActive` is true.

## Solution Assessment

Yes. The narrow maintainable fix belongs at the Feishu receive/sequential-queue boundary because the shared queue policy already handles active followups once they reach it at the right time.
