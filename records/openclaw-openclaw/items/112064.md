## Summary

This issue remains necessary: the officially released App Store iOS app is documented as a gateway node, while current node policy distinguishes iOS and macOS metadata. Treating an Apple-Silicon compatibility run as macOS without an explicit decision could change its default command allowlist, so the safe fix is to preserve iOS policy semantics while making the Mac-hosted compatibility context clear in display or additive metadata.

## What This Changes

Report and correct the iOS App Store app’s node identity when it runs in Apple Silicon macOS compatibility mode so it does not appear to be a physical iPad.

## Best Possible Solution

Detect the iOS-on-Mac runtime in the iOS client, retain the existing iOS capability and command-policy classification, and publish an explicit Mac-compatibility display/context marker that prevents operators from mistaking the node for physical iPad hardware.
