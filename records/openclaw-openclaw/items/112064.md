## Summary

This appears to be a current, bounded iOS-node metadata bug rather than a phantom pairing or APNs failure. Current documentation treats iOS nodes and macOS companion apps as distinct surfaces, while the iOS app’s node model still derives display identity from `UIDevice.current.userInterfaceIdiom`; an Apple-Silicon compatibility run needs a distinct runtime classification without claiming macOS-node capabilities.

## What This Changes

Identify an App Store iOS build running under Apple-Silicon macOS compatibility as a compatibility app in gateway node metadata instead of presenting it as a physical iPad.

## Best Possible Solution

Add a narrowly defined iOS-on-macOS runtime descriptor at the iOS client identity boundary, display it distinctly in node inventory, and retain the existing iOS node client id, capabilities, pairing identity, and push semantics.
