## Label Justifications

- `P0`: The reported default behavior can automatically disclose persistent private context across users in a shared conversation.
- `impact:security`: The issue concerns unintended sensitive-context disclosure across user and channel trust boundaries.
- `impact:session-state`: Private long-term agent memory is being associated with and injected into a distinct shared group session.

## Summary

Current `main` still admits the full bootstrap set for every session that is neither subagent nor cron, while current documentation defines `MEMORY.md` as private-session-only. This remains a core cross-session privacy defect; the older related report was closed without resolving the implementation mismatch.

## What This Changes

Prevent `MEMORY.md` from being automatically injected into Telegram group sessions where private long-term memory may be exposed to other participants.

## Best Possible Solution

Enforce a channel-agnostic private-session boundary for `MEMORY.md` in core prompt construction, preserve it for true private or DM sessions, and add table-driven coverage for Telegram groups, other shared channel keys, DMs, subagents, cron, and hook overrides.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Current source loads `MEMORY.md`, the filter returns all files for ordinary channel sessions, and the existing test explicitly expects that behavior; the reporter and https://github.com/openclaw/openclaw/issues/24404 also provide canary-based group reproductions.

## Solution Assessment

No, a Telegram-specific allowlist or new config knob is not the best primary fix. The documented contract is already private-session-only, so core should enforce that invariant generically across shared channel session shapes without adding configuration surface.
