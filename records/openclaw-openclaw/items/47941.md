## Summary

Keep open: current main and the latest release still let the shared bootstrap report carry `file.name` through to `/context`, so a path-only virtual bootstrap file can still display as `undefined`; an open linked fork PR proposes the narrow fix but has not landed in the target repo.

## What This Changes

The issue asks for `/context` reporting to label virtual bootstrap files with a name/path/basename fallback instead of rendering literal `undefined` when hook entries omit `name`.

## Best Possible Solution

Land or replace the linked candidate with a small shared-helper fix that normalizes `name -> path/basename -> placeholder` and adds regression coverage for path-only virtual bootstrap files.
