## Summary

Keep open: current main and v2026.6.11 still let the shared bootstrap stats path return `file.name` for path-only virtual bootstrap files, and `/context` renders that value directly. An open external fork PR proposes the narrow fix, so maintainers should review, adopt, or replace that candidate instead of closing this issue now.

## What This Changes

The issue requests that `/context` reporting label path-only virtual bootstrap files from `name`, `path`, basename, or a placeholder instead of rendering literal `undefined`.

## Best Possible Solution

Normalize the bootstrap display label once in `buildBootstrapInjectionStats` with a name/path/basename/placeholder fallback, add regression coverage for path-only hook files, and land it through the existing fork PR or an equivalent narrow upstream PR.
