## Summary

Keep open: current main and latest release v2026.6.11 still copy the raw bootstrap `file.name` into context report rows, so path-only virtual bootstrap files can still render as `undefined`. A linked fork PR is a narrow candidate fix, but it has not landed.

## What This Changes

The issue asks for `/context` bootstrap file labels to fall back to path or basename instead of rendering `undefined` for virtual files without `name`.

## Best Possible Solution

Normalize the label in the shared bootstrap stats/reporting path with `name -> path -> basename -> placeholder`, add regression coverage for path-only virtual files, and land or replace the linked candidate fix.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: a hook-adjusted bootstrap file with `path` and content but no `name` can reach `buildBootstrapInjectionStats`, which returns `name: file.name`, and `/context` renders that value directly.

## Solution Assessment

Yes. The best fix belongs in the shared bootstrap stats/reporting layer rather than only the command renderer, because run reports, estimate reports, JSON output, and rendered `/context` rows all consume `injectedWorkspaceFiles`.
