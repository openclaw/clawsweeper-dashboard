- `impact:ux-friction`: The `/context` report can show a confusing literal `undefined` label even though the virtual bootstrap content is present and counted.

## Summary

Keep open: current main and v2026.6.11 still let a path-only virtual bootstrap file flow into the shared context stats as `name: file.name`, and `/context` renders that value directly. An open external fork PR already references this issue, so maintainers should review, adopt, or replace that candidate rather than close this issue or queue duplicate automation.

## What This Changes

The issue asks OpenClaw to stop rendering literal `undefined` for virtual bootstrap file labels in `/context` reports by falling back to path, basename, or a stable placeholder.

## Best Possible Solution

Normalize bootstrap report labels centrally in `buildBootstrapInjectionStats` with a non-empty name, path basename, and placeholder fallback, then add regression coverage for path-only hook-injected bootstrap files.
