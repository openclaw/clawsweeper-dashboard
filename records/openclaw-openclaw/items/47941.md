## Summary

Keep open: current main and the latest tagged release still let a path-only virtual bootstrap file produce `name: file.name` in shared context stats, and `/context` renders that value directly. An open external fork PR already references this issue, so maintainers should review, adopt, or replace that candidate instead of closing this issue or queueing a duplicate fix.

## What This Changes

Normalize `/context` bootstrap file labels so path-only virtual bootstrap files do not render as literal `undefined`.

## Best Possible Solution

Normalize bootstrap report labels centrally in `buildBootstrapInjectionStats` with non-empty name, path basename, and placeholder fallback, then add regression coverage for path-only hook-injected bootstrap files.
