## Summary

Keep open: current main and v2026.6.11 still let the shared bootstrap stats path return `file.name` for a path-only virtual bootstrap file, and `/context` renders that value directly. The only active fix is an open external fork PR that maintainers need to review, adopt, or replace before this issue can close.

## What This Changes

The issue requests that `/context` bootstrap-file reporting fall back from a missing name to path or basename instead of rendering literal `undefined`.

## Best Possible Solution

Normalize bootstrap report labels centrally in `buildBootstrapInjectionStats` with a name/path/basename/fallback chain, add regression coverage for path-only hook files, and land that through the existing fork PR or an equivalent narrow upstream PR.
