## Summary

Keep open: current main and latest release v2026.6.11 still copy `file.name` into bootstrap context report rows and `/context` renders that value directly, so path-only virtual bootstrap files can still display as `undefined`. The open fork PR at https://github.com/BingqingLyu/openclaw/pull/829 is a narrow candidate fix, but it has not landed.

## What This Changes

Ensure `/context` bootstrap breakdown rows for virtual/path-only bootstrap files fall back to path or basename instead of rendering `undefined`.

## Best Possible Solution

Normalize the label in the shared bootstrap stats/reporting path with `name -> path -> basename -> placeholder`, add regression coverage for path-only virtual files, and land or replace the open candidate fix.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: a hook-adjusted bootstrap file with `path` and content but no `name` can reach `buildBootstrapInjectionStats`, which returns `name: file.name`, and `/context` renders that value directly.

## Solution Assessment

Yes. The best fix belongs in the shared bootstrap stats/reporting layer rather than only the command renderer, because run reports, estimate reports, JSON output, and rendered rows all consume `injectedWorkspaceFiles`.
