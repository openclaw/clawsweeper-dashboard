## Summary

Keep open: current main and v2026.6.11 still let the shared bootstrap report return `name: file.name`, so a path-only virtual bootstrap file can still be rendered as `undefined`; the merged Codex-specific fix is adjacent, and an open fork PR remains the candidate fix path rather than proof this issue is done.

## What This Changes

The issue asks for `/context` reporting to fall back to a file path, basename, or placeholder when a virtual bootstrap file has content and `path` but no `name`.

## Best Possible Solution

Land or replace the linked candidate with a small shared-helper fix that derives the display label from `name`, then path/basename, then a placeholder, with regression coverage for path-only hook-injected bootstrap files.
