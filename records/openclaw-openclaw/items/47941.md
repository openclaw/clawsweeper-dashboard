## Summary

Keep open: current main and v2026.6.11 still let a path-only virtual bootstrap file flow into context stats as `name: file.name`, and `/context` renders that value directly. An open external fork PR already carries the narrow patch shape, so maintainers should review, adopt, or replace that candidate instead of closing this issue or queueing duplicate automation.

## What This Changes

The issue requests that context reporting never render literal `undefined` for path-only virtual bootstrap files and instead fall back to a stable path, basename, or placeholder label.

## Best Possible Solution

Normalize bootstrap report labels centrally in `buildBootstrapInjectionStats` with a non-empty name, path basename, and placeholder fallback, then land the existing candidate or a same-repository replacement with regression coverage.
