## Summary

Keep open: current main and the latest release still propagate `file.name` into the shared bootstrap context report row without a path/basename fallback, and an open linked fork PR already owns the narrow candidate fix but has not landed.

## What This Changes

The issue asks for `/context` reporting to label path-only virtual bootstrap files with a stable path or basename instead of literal `undefined`.

## Best Possible Solution

Normalize the label in the shared bootstrap stats/reporting path with `name -> path -> basename -> placeholder`, add regression coverage for path-only virtual files, and land or replace the open candidate fix.
