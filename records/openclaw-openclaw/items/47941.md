## Summary

Keep open: current main and v2026.6.11 still copy `file.name` into context report rows and `/context` renders that value directly, so a hook-supplied bootstrap file with `path` and content but no `name` can still display as `undefined`. The open fork PR at https://github.com/BingqingLyu/openclaw/pull/829 is the narrow candidate fix, but it has not landed.

## What This Changes

Context reporting should fall back from a missing virtual bootstrap file name to the path, basename, or a placeholder instead of rendering literal `undefined`.

## Best Possible Solution

Normalize the bootstrap report label in the shared stats/reporting path with `name -> path -> basename -> placeholder`, add regression coverage for a path-only hook file, then land or replace the linked fork PR.

## Reproduction Assessment

Yes. Source inspection shows a hook-adjusted bootstrap file with `path` and content but no `name` can pass into `buildBootstrapInjectionStats`, which returns `name: file.name`, and `/context` renders that value directly.

## Solution Assessment

Yes. The best fix belongs in the shared bootstrap stats/reporting layer rather than only the command renderer, because run reports, estimate reports, JSON output, and `/context` rows all consume `injectedWorkspaceFiles`.
