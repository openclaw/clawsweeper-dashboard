## Summary

Keep open: current `origin/main` and latest release `v2026.6.11` still let the shared bootstrap stats path return `file.name` for a path-only virtual bootstrap file, and `/context` renders that value directly. The active fix path is the open external fork PR, so maintainers should review, adopt, or replace that patch rather than closing this issue now.

## What This Changes

The issue requests that context reporting label hook-injected virtual bootstrap files from `name`, `path`, basename, or a placeholder instead of rendering `undefined`.

## Best Possible Solution

Land a narrow shared-helper fix that normalizes bootstrap stat labels with a `name` -> `path` -> basename -> placeholder chain and adds regression coverage for path-only hook files.
