## Label Justifications

- `P1`: On affected builds, long-running agents can no longer consume fresh tool output and become unable to complete normal workflows.
- `impact:session-state`: The failure is caused by prompt-projection state retaining frozen history while mishandling fresh tool-result context.

## Summary

Current main and the shipped v2026.7.1 release already protect fresh tool-result text when aggregate history is saturated, covering the reported long-session failure mode.

## What This Changes

The issue requests preventing aggregate tool-result truncation from clearing newly produced tool outputs after frozen historical output exceeds the aggregate budget.

## Best Possible Solution

Keep the v2026.7.1 aggregate-cap fix; reopen only with a reproduction on a build containing the released fix.
