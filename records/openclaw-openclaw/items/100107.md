## Summary

Keep open: the underlying provider-settings fix is valid, but this patch makes provider onboarding patches additive in a way that can restore auth fields a caller intentionally removed, and the external PR still lacks real behavior proof.

## What This Changes

The PR changes the provider onboarding config helper to preserve existing provider entries/settings while applying onboarding provider patches, and adds a regression test for provider-level timeoutSeconds preservation.

## Best Possible Solution

Preserve user-owned provider settings during onboarding while still honoring explicit provider-field removal or normalization, with regression coverage for both timeoutSeconds preservation and omitted apiKey/sentinel behavior plus real behavior proof.

## Reproduction Assessment

Yes, from source inspection: current main replaces models.providers with params.providers in the shared onboarding helper, so a partial patch can drop timeoutSeconds. The PR's new regression test encodes that path, though I did not run it in this read-only review.

## Solution Assessment

No. Preserving provider settings is the right direction, but the proposed shallow merge is too broad because it also preserves fields that provider-specific callers intentionally omit to clear or normalize auth/config state.
