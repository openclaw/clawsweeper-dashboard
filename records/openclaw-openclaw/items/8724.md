## Summary

Keep open: current main and v2026.6.11 still lack the requested typed global/per-model non-resetting generation timeout, while existing provider request and idle/first-event watchdogs only cover adjacent timeout cases.

## What This Changes

The issue requests configurable global and per-model generation timeouts so slow or looping models can be bounded independently of provider request timeouts.

## Best Possible Solution

Approve and document a canonical timeout hierarchy, then implement a typed per-model/global non-resetting generation budget with schema, docs, runtime enforcement, fallback classification, and regression coverage.

## Reproduction Assessment

Yes at source level: current main still lacks the requested typed per-model timeout config under agents.defaults.models, and the active watchdogs are provider/request-idle oriented rather than a non-resetting generation budget. I did not live-reproduce the original Gemini infinite thinking loop.

## Solution Assessment

Unclear pending product direction: a per-model generation timeout is plausible, but maintainers should first decide whether the canonical control belongs under agents.defaults.models, models.providers.<id>.timeoutSeconds, or another timeout hierarchy.
