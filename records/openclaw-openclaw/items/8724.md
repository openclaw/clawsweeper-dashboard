## Summary

Keep open: current main has adjacent provider request and idle-timeout controls, but it still lacks the requested typed per-model non-resetting generation-timeout contract under `agents.defaults.models`. The issue already has maintainer/product-decision signals, so the remaining work needs human timeout semantics review rather than conservative cleanup closure.

## What This Changes

The issue requests global and per-model generation timeout configuration so slow or looping model generations can be aborted, logged, and possibly routed to fallbacks without relying only on provider-level request timeouts or reset-on-chunk idle timers.

## Best Possible Solution

Keep this as the canonical maintainer-reviewed timeout contract, then design explicit schema/docs/runtime behavior with per-selected-model precedence, non-resetting enforcement, fallback classification, and regression coverage.

## Reproduction Assessment

Yes, for the missing config/runtime contract: current main still rejects the proposed per-model timeout keys and only wires provider request timeout into idle/first-event watchdog paths. I did not run a live hung-model reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product contract. A typed per-model generation budget is plausible, but the best fix must define precedence against provider request timeout, run timeout, first-event behavior, and the idle watchdog.
