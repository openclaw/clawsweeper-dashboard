## What This Changes

The issue requests configurable global and per-model generation timeouts so long-running or looping model generations can be aborted, logged, and optionally routed through fallback.

## Best Possible Solution

Keep this as the canonical maintainer-reviewed timeout contract, then implement an explicit schema/docs/runtime design with per-selected-model precedence, non-resetting enforcement, fallback classification, and tests for both fresh and upgrade behavior.

## Reproduction Assessment

Yes for the missing config/runtime contract: current main still rejects the proposed per-model timeout keys and only wires provider request timeout into idle/first-event watchdog behavior. I did not run a live looping-model reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product contract. A typed per-model generation budget is plausible, but the best fix must define precedence against provider request timeout, run timeout, first-event behavior, and the idle watchdog.
