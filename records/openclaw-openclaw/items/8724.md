## Summary

Keep open: current main still has adjacent provider request, first-event, and reset-on-progress idle timeout controls, but not the requested typed global/per-model non-resetting generation timeout under agent model config.

## What This Changes

Request adds global and per-model generation timeout configuration so runaway or model-specific long generation can be aborted and optionally routed through fallback.

## Best Possible Solution

Keep this as the canonical timeout-contract issue, then define and implement one typed generation budget with clear precedence, docs/schema coverage, per-selected-candidate enforcement, timeout classification, logging, and fallback semantics.

## Reproduction Assessment

Yes at source level: current main still excludes generationTimeout/requestTimeoutMs from strict agents.defaults.models entries, and the existing idle watchdog resets on each yielded chunk. I did not run a live hung-model reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product contract. A typed per-model generation budget is plausible, but the best fix must define precedence against provider request timeout, run timeout, first-event behavior, and the idle watchdog.
