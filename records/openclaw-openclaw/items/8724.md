## Summary

Keep open: current main and v2026.6.11 still provide adjacent provider/run/first-event timeout behavior, but not the requested typed global/per-model non-resetting generation timeout contract.

## What This Changes

Request a global and per-model generation timeout so operators can bound runaway model generations differently by model.

## Best Possible Solution

Define one maintainer-approved timeout contract for agent defaults and per-model entries, enforce it as a non-resetting generation budget per selected fallback candidate, and keep first-token, provider request timeout, and repetition safeguards as separate surfaces.

## Reproduction Assessment

Yes at source level: the requested per-model timeout key is absent from the strict agents.defaults.models schema, and current timeout enforcement is provider/run/idle based. I did not run a live Gemini runaway-generation repro.

## Solution Assessment

Unclear until maintainers choose the public timeout contract. The current provider timeout path is useful but is not the best complete solution for the issue's non-resetting per-model generation budget.
