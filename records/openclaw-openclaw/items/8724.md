## Summary

Keep open: current main and v2026.6.11 still lack a typed agent global/per-model non-resetting generation timeout; the existing provider request, first-event, and reset-on-chunk idle watchdogs only cover adjacent failure modes.

## What This Changes

The issue requests configurable global and per-model generation timeouts so operators can bound runaway model thinking or streaming loops per model.

## Best Possible Solution

Define one maintainer-approved timeout contract, then implement a typed global/per-model non-resetting generation budget with clear precedence against provider request, first-event, idle, run, and fallback timeouts.

## Reproduction Assessment

Yes at source level: current main still rejects the proposed agent-model timeout keys and only applies provider-derived idle/first-event timeouts. I did not run a live Gemini loop reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public timeout hierarchy. The requested config surface is plausible, but it must be reconciled with the existing provider timeout and watchdog behavior first.
