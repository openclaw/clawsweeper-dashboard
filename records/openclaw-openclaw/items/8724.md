## Summary

Keep open: current main and v2026.6.11 still lack the requested typed global/per-model non-resetting generation timeout under agent model config, while existing provider request timeout, first-event timeout, and reset-on-chunk idle watchdog behavior only partially overlap.

## What This Changes

The issue requests global and per-model generation timeout configuration so slow or looping model generations can be aborted and routed without relying only on provider/request or idle timeouts.

## Best Possible Solution

Keep this as the canonical product/config decision: either approve a typed non-resetting generation budget with schema, docs, runtime enforcement, and fallback tests, or explicitly document the existing provider timeout hierarchy as the supported answer and close the feature later.

## Reproduction Assessment

Yes at source level: current main still lacks the requested typed per-model timeout config under agents.defaults.models, and the active watchdogs are provider/request-idle oriented rather than a non-resetting generation budget. I did not live-reproduce the original Gemini infinite thinking loop.

## Solution Assessment

Unclear. A per-model generation timeout is plausible, but maintainers should first decide whether the canonical control belongs under agents.defaults.models, models.providers.<id>.timeoutSeconds, or another timeout hierarchy.
