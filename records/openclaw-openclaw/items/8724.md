## Summary

Keep open: current main has adjacent provider request and idle/first-event timeout controls, but it still does not expose the requested global/per-model total-generation timeout contract under `agents.defaults.models`, and the remaining config/fallback semantics need maintainer product direction.

## What This Changes

The issue requests global and per-model generation timeout configuration so looping or long-running model generations can be aborted and optionally routed through fallback without relying only on the existing run timeout.

## Best Possible Solution

Maintainers should decide the timeout ownership model first; if approved, add a typed global/per-model generation budget, resolve it per selected fallback candidate, enforce it as a non-resetting total-generation timer, document precedence with provider/run timeouts, and keep first-token and semantic repetition detection as separate issues.

## Reproduction Assessment

Yes. Source inspection shows the requested per-model timeout key is absent from the strict model-entry schema while adjacent provider timeout behavior exists; I did not run a config validation or live model loop because this review is read-only.

## Solution Assessment

Unclear. A per-model total-generation timeout is a plausible core fix, but the best public key and precedence against provider, run, idle, and first-event timeouts need maintainer product judgment before implementation.
