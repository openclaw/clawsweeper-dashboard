## Summary

Keep open: current main and v2026.6.11 still lack the requested typed per-agent/per-model total generation timeout config; existing provider, run, idle, and first-event timeout paths are adjacent controls rather than the requested public config contract.

## What This Changes

The issue requests a global and per-model generation timeout so operators can bound long-running or looping model generations differently per model.

## Best Possible Solution

Decide the canonical timeout contract first; if accepted, add typed agent/default and per-model generation timeout fields with schema, docs, precedence tests, fallback/abort classification, and keep first-token and repetition safeguards separate.
