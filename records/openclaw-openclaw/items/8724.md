## Summary

Keep open: current main has adjacent provider/request, idle, and first-event timeout controls, but it still lacks the requested typed global/per-model non-resetting generation timeout under `agents.defaults.models`. The related discussion and open PR cover overlapping timeout failures, not the missing config contract.

## What This Changes

Request adds global and per-model generation timeout configuration so model/fallback attempts can be aborted after an operator-defined total generation budget.

## Best Possible Solution

If maintainers accept the new surface, add a documented global/per-model generation-timeout contract, resolve it per selected fallback candidate, enforce it as a non-resetting total generation budget, and keep first-token and repetition safeguards separate.

## Reproduction Assessment

Yes for the missing config contract: current source shows `agents.defaults.models.*` is strict and does not accept `generationTimeout` or `requestTimeoutMs`. I did not reproduce a live Gemini runaway loop against current main.

## Solution Assessment

Unclear until maintainers choose the public config contract. The requested per-model total generation timeout is a plausible core solution because the existing provider timeout and idle/first-event watchdogs are adjacent but not equivalent.
