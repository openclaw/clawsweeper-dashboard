## Summary

Keep open: current main and v2026.6.11 still lack the requested typed global/per-model total-generation timeout under `agents.defaults.models`; existing provider request, run, idle, and first-event timeouts are adjacent but do not replace the requested per-model generation budget.

## What This Changes

Request to add configurable global and per-model generation timeouts so slow or runaway model generations can abort and optionally fail over by model.

## Best Possible Solution

Maintainers should decide the timeout ownership model, then add a typed global/per-model total-generation budget with documented precedence, fallback classification, schema/docs updates, and focused regression coverage.

## Reproduction Assessment

Yes for the config-surface gap: current source and v2026.6.11 both reject the requested per-model timeout shape while using adjacent provider/run/idle timeout controls. No live long-running Gemini/OpenRouter loop was reproduced in this read-only review.

## Solution Assessment

Unclear. A per-model total-generation timeout is plausible, but the best key name, precedence, and interaction with existing provider request, run, idle, first-event, and repetition safeguards needs maintainer product judgment.
