## Summary

Keep open: current main still lacks the requested typed global/per-model generation timeout config under agent model entries, and the remaining choice is a compatibility-sensitive public config/product decision rather than cleanup-close material.

## What This Changes

Request a global and per-model generation timeout so unreliable or cheaper models can be bounded without shortening slower premium models.

## Best Possible Solution

Define one canonical timeout contract for agent model selection, document its precedence across fallback candidates, enforce it at the embedded attempt boundary without weakening existing provider/run caps, and keep first-token and repetition safeguards separate.
