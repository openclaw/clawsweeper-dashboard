## Summary

Keep open: current main and latest stable release still lack the requested typed global or per-agent-model non-resetting generation timeout, while existing controls cover adjacent provider request, first-event, idle-watchdog, and run-level timeout paths.

## What This Changes

The issue requests a global and per-model generation timeout so different models can have different non-resetting generation budgets and failover behavior.

## Best Possible Solution

Define one canonical timeout contract for agent model selection, document its precedence across fallback candidates, enforce it at the embedded attempt boundary without weakening existing provider/run caps, and keep first-token and repetition safeguards tracked separately.
