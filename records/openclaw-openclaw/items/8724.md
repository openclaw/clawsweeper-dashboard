## Summary

Keep open: current main still lacks the requested typed global or per-agent-model generation timeout, while existing code covers adjacent provider request, first-event, idle-watchdog, and run-level timeout paths.

## What This Changes

The issue requests a typed global and per-model generation timeout so slow or looping models can be aborted or routed differently without relying only on provider or run-level timeouts.

## Best Possible Solution

Define one canonical agent model timeout contract, document precedence across fallback candidates, enforce it at the embedded attempt boundary, and keep first-token and repetition safeguards tracked separately.

## Reproduction Assessment

Yes at source level: current main's strict agent model-entry schema has no generationTimeout/requestTimeoutMs field, and the embedded attempt path uses run/provider timeout inputs rather than a per-agent-model total generation budget.

## Solution Assessment

Unclear until maintainers choose the public config contract. The source boundary is clear, but adding another timeout key competes with existing agents.defaults.timeoutSeconds, models.providers.<id>.timeoutSeconds, first-event timeout, idle watchdog, and separate repetition/thinking fixes.
