## Summary

The issue is still necessary: current main and v2026.6.11 have adjacent provider/run/idle timeout controls, but not the requested typed global or per-model generation timeout contract. This should stay open for maintainer product direction rather than cleanup closure.

## What This Changes

The issue requests global and per-model generation timeout configuration so long or looping model generations can be aborted independently of provider/request timeouts.

## Best Possible Solution

Define one canonical timeout contract for agent model selection, document its precedence across fallback candidates, enforce it at the embedded attempt boundary without weakening existing provider/run caps, and keep first-token and repetition safeguards tracked separately.
