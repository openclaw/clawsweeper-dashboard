## Summary

Keep open: current main and the latest v2026.6.11 release still lack a typed global/per-model non-resetting generation-timeout contract under agent model config. Existing provider request timeout, first-event timeout, and reset-on-progress idle watchdog behavior are adjacent but do not implement the requested public config surface or budget semantics.

## What This Changes

The issue requests a global and per-model generation timeout so slow or looping model generations can be aborted and routed through fallback without relying only on provider request or idle timeouts.

## Best Possible Solution

Add a maintainer-approved config contract and enforcement point for a non-resetting generation budget, while keeping provider request timeout, first-event timeout, and semantic repetition safeguards as separate documented surfaces.

## Reproduction Assessment

Yes from source for the config gap: current strict agent model-entry schema rejects the requested per-model timeout keys, and the runner still uses outer run plus idle/first-event timeouts. The live Gemini loop itself was not reproduced in this read-only pass.

## Solution Assessment

Unclear as a final product shape: a non-resetting generation budget likely belongs in core runtime/config, but the key name, global-versus-per-model hierarchy, and fallback semantics need maintainer approval.
