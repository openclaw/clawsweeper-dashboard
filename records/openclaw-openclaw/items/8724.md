## Summary

Keep open: current main and v2026.6.11 still lack the requested typed global or per-agent-model non-resetting generation timeout, while the shipped timeout controls cover adjacent provider request, first-event, idle-watchdog, and run-level failure modes.

## What This Changes

The issue requests configurable global and per-model generation timeouts so long-running or looping model generations can be aborted and routed through fallback without relying on one global run budget.

## Best Possible Solution

Define one canonical timeout contract for agent model selection, document its precedence across fallback candidates, enforce it at the embedded attempt boundary without weakening existing provider/run caps, and keep first-token and repetition safeguards tracked separately.

## Reproduction Assessment

Unclear until maintainers choose the public config contract. The source boundary is clear, but adding another timeout key competes with existing `agents.defaults.timeoutSeconds`, `models.providers.<id>.timeoutSeconds`, first-event timeout, idle watchdog, and separate repetition/thinking fixes.
