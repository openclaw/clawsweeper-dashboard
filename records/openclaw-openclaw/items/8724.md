## Summary

Keep this issue open. Current main provides a global agent-turn timeout and provider-scoped HTTP timeout controls, but it still does not expose the requested model-specific execution budget; adding that public contract needs a maintainer decision on semantics and compatibility.

## What This Changes

Add a configurable global or per-model deadline that aborts an overlong model generation, reports the timeout, and permits normal fallback handling.

## System Context

Agent model selection resolves a provider/model candidate and starts a streamed provider request. Existing global and provider-level timeout controls bound the agent turn or provider request, while the requested feature would add a distinct model-specific budget before fallback or user-visible failure.

## Best Possible Solution

Retain the documented global and provider controls for common cases, then—if maintainers approve the remaining same-provider use case—add one canonical per-model total request deadline with documented precedence, timeout classification, fallback behavior, schema/docs coverage, and focused upgrade tests.
