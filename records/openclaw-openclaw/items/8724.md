## Summary

Keep open: current main and latest stable still lack a typed per-agent-model total generation timeout, while existing run, provider request, first-event, and idle-watchdog timeouts cover adjacent failure modes only.

## What This Changes

The issue requests a global and per-model generation timeout config so operators can bound runaway or long-running model generations differently per model.

## Best Possible Solution

Define one canonical timeout contract for agent model selection, document its precedence across fallback candidates, enforce a non-resetting generation budget without weakening provider/run caps, and keep first-token and repetition safeguards separate.
