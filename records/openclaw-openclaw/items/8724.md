## Summary

Keep open: current main and the latest release still lack the requested typed global/per-model non-resetting generation timeout; the existing provider request timeout and stream-idle/first-event watchdogs are adjacent but do not provide the requested config contract.

## What This Changes

The issue requests global and per-model generation timeout configuration for model runs, including timeout aborts, logging, and optional fallback behavior.

## Best Possible Solution

Keep this as the canonical maintainer-reviewed timeout contract, then implement an explicit schema/docs/runtime design with per-selected-model precedence, non-resetting enforcement, fallback classification, and tests for both fresh and upgrade behavior.

## Reproduction Assessment

Yes, for the missing config/runtime contract: current main still rejects the proposed per-model timeout keys and only wires provider request timeout into adjacent idle/first-event watchdogs. I did not run a live hung-model reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product contract. A typed per-model generation budget is plausible, but the best fix must define precedence against provider request timeout, run timeout, first-token behavior, and idle watchdog behavior.
