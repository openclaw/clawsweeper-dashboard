## Summary

Keep open: current main and latest release still have adjacent provider request, first-event, and reset-on-progress idle timeout behavior, but not the requested typed global/per-model non-resetting generation timeout under agent model config. This remains a product/config contract decision, not conservative cleanup.

## What This Changes

The issue requests configurable global and per-model generation timeouts so model runs can be aborted after a total generation budget instead of relying only on existing provider or idle timeouts.

## Best Possible Solution

Keep this as the canonical timeout-contract issue, then implement a typed generation budget with explicit precedence, docs/schema coverage, per-selected-candidate enforcement, timeout classification, logging, and fallback semantics.

## Reproduction Assessment

Yes at source level: current main and v2026.6.11 still reject the proposed per-model timeout keys and only wire provider request timeout into request/idle watchdog behavior. I did not run a live hung-model reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product contract. A typed per-model generation budget is plausible, but the best fix must define precedence against provider request timeout, run timeout, first-event behavior, and the idle watchdog.
