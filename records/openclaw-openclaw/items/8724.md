## Summary

Keep open: current main and v2026.6.11 still lack the requested typed global or per-model non-resetting generation timeout under agent model config; existing provider request timeout, first-event timeout, and reset-on-chunk idle watchdogs only cover adjacent failure modes.

## What This Changes

Request adds a global/per-model generation timeout config so operators can cap runaway model generation and trigger error or fallback behavior.

## Best Possible Solution

Define one maintainer-approved timeout contract, then implement a typed global/per-model non-resetting generation budget with explicit precedence against provider request, first-event, idle, run, and fallback timeouts; keep first-token/provider-skip and semantic repetition guards as separate work.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: current main still rejects the proposed agent-model timeout keys and only applies adjacent provider-derived request, first-event, and idle watchdog behavior; I did not run a live Gemini loop reproduction.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainers choose the public timeout hierarchy; the requested config surface is plausible, but it must be reconciled with the existing provider timeout and watchdog behavior first.
