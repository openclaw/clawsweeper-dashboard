## Summary

Keep open: current main has provider-level request, idle, and first-event timeout controls, but it still does not provide the requested typed global/per-model non-resetting generation timeout under agent model config; the remaining work is a product/config contract decision.

## What This Changes

Request to add global and per-model generation timeout configuration so operators can bound runaway model generation differently per selected model.

## Best Possible Solution

Add a backward-compatible per-model generation timeout contract only after maintainers choose the public shape, then wire it into selected fallback candidates as a non-resetting generation budget while keeping first-token/provider-skip behavior separate.

## Reproduction Assessment

Yes at source level: current main strictly rejects the proposed per-model timeout fields and the existing stream watchdog is reset-on-progress rather than a non-resetting total-generation timer. I did not run a live Gemini runaway loop in this read-only review.

## Solution Assessment

Unclear as proposed: per-model timeout control may be the right end state, but maintainers need to choose how it relates to existing `models.providers.<id>.timeoutSeconds`, run timeouts, idle watchdogs, first-event timeouts, and fallback semantics.
