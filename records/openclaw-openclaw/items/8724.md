## Summary

Keep open: current main still lacks the requested typed global/per-model total-generation timeout under `agents.defaults.models`; existing provider request, run, idle, and first-event timeout controls are adjacent but do not replace the requested non-resetting generation budget.

## What This Changes

The issue requests configurable global and per-model generation timeouts so long or looping model generations can be aborted and fallback/debug logging can respond predictably.

## Best Possible Solution

Maintainers should decide the timeout ownership model, then add a typed global/per-model total-generation budget with documented precedence and focused schema, runner, fallback, docs, and regression coverage.

## Reproduction Assessment

Yes. Source inspection can reproduce the config-surface gap: the strict per-model schema lacks the requested timeout key while current runtime timeout controls are provider/run/idle scoped, but no live long-running Gemini loop was reproduced in this read-only review.

## Solution Assessment

Unclear. A per-model total-generation timeout is plausible, but the best key and precedence against existing provider request, run, idle, and first-event timeout controls needs maintainer product judgment.
