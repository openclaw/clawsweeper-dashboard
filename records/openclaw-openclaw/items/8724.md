## Summary

Keep open: current main and v2026.6.11 still lack the requested typed global or per-agent-model non-resetting generation timeout, while existing code only covers adjacent run-level, provider request, first-event, and idle-watchdog timeout paths.

## What This Changes

Request to add global and per-model generation timeout configuration so operators can cap runaway model generations differently by model.

## Best Possible Solution

Define one canonical timeout contract for agent model selection, document precedence across fallback candidates, enforce a non-resetting generation budget at the embedded attempt boundary, and keep first-token and repetition safeguards tracked separately.
