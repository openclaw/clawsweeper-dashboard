## Summary

Keep open: current main and v2026.6.11 still only expose provider/run/idle/first-event timeout controls, not the requested typed global or per-model non-resetting generation timeout under agent model config.

## What This Changes

Request a global and per-model generation timeout config so slower or loop-prone models can use different abort budgets and fallback behavior.

## Best Possible Solution

Define one maintainer-approved timeout hierarchy, then add a typed global/per-model non-resetting generation budget with docs, schema, tests, and clear interaction with provider request, first-event, idle, run, and fallback timeouts.

## Reproduction Assessment

Yes at source level: the proposed per-agent-model timeout keys are rejected by the strict current schema, and no non-resetting per-model generation budget is resolved at the runner; I did not run a live Gemini runaway-loop reproduction.

## Solution Assessment

Unclear until maintainers choose the public timeout hierarchy; the requested config is plausible, but it must be reconciled with existing provider timeout, first-event, idle, run, and fallback semantics.
