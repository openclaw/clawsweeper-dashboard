## Summary

Keep open: current main and the latest inspected release still lack a typed per-agent-model generation/request timeout config; existing provider-level and run-level timeout controls are adjacent workarounds, not the requested model-specific config contract.

## What This Changes

Request a global or per-model generation timeout config so operators can bound long or looping model generations differently by model.

## Best Possible Solution

Decide the canonical timeout contract first; if accepted, add a typed agent/model-level timeout with schema, docs, tests, and explicit precedence against provider, run, first-event, and idle watchdogs.
