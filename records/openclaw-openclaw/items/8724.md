## Summary

Keep this issue open. The latest supplied evidence still describes a missing supported per-model timeout setting, but it conflicts on whether the remaining work is schema exposure alone or a new total-generation budget; that public config and fallback contract requires maintainer direction before implementation.

## What This Changes

Add a per-model timeout configuration that can stop a hung or runaway model attempt and allow fallback routing to continue.

## System Context

Agent defaults select model candidates and their per-model settings before the embedded runner starts an attempt. An attempt timeout aborts the selected model, after which model-fallback can decide whether to try another candidate and report the failure.

## Architecture Diagram

flowchart LR
  A[Agent defaults config] --> B[Selected model candidate]
  B --> C[Embedded agent runner]
  C --> D[Attempt timeout policy]
  D --> E[Abort and classify failure]
  E --> F[Model fallback routing]
  F --> G[User response or final error]

## Best Possible Solution

Choose one canonical per-model timeout contract—preferably extend the existing resolved request-timeout path if it already carries the required semantics—then align schema, generated docs, runner enforcement, fallback classification, and focused regression coverage; keep first-token and repetition safeguards as separate decisions.

Rationale: The issue and comments describe multiple materially different failure modes—hung transport calls, continuously streaming reasoning, and first-token delay—so a public setting cannot be selected safely without defining what it measures and how fallback consumes it.

Likely owner: steipete

Owner confidence: medium

Options:

- **Adopt one per-model request timeout (recommended):** Expose and document a single per-model request/attempt timeout, preserve the existing global run timeout, and make first-token and repetition controls separate work.
- **Add a distinct generation budget:** Introduce a new non-resetting total-generation budget only if maintainers need semantics that the existing request-timeout path cannot represent.
- **Defer the config surface:** Land only narrowly scoped cloud-thinking timeout fixes until a broader timeout policy and migration story are agreed.
