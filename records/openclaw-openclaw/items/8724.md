Keep this open: current main and v2026.6.11 still lack the requested global/per-model generation timeout contract, and the remaining work needs maintainer agreement on config shape and timeout precedence rather than cleanup closure.

## What This Changes

The issue requests configurable global and per-model generation timeouts so long-running model generation loops can abort, log, and optionally fall back.

## Best Possible Solution

Choose one canonical timeout contract, document precedence against existing provider/run/agent timeouts, enforce it per selected fallback candidate where intended, and keep first-token and repetition safeguards as separate scoped work.

Yes, for the missing feature surface: current source shows agents.defaults.models entries still reject or omit any per-model generation/request timeout key. I did not reproduce a live Gemini infinite-generation loop in this read-only review.

## Solution Assessment
