## Summary

The issue requests global and per-model generation timeout configuration that aborts runaway model generation and can feed fallback handling.

## Best Possible Solution

Choose the canonical timeout ownership model, then either add a typed non-resetting generation budget with schema, docs, runner enforcement, fallback classification, and regression coverage, or document provider timeout as the supported answer.

Yes, at source level: current main lacks the requested typed global/per-model generation-timeout config and still relies on run-level plus provider/request/idle timeout paths. I did not live-reproduce the original Gemini loop.

## Solution Assessment
