## Summary

Keep open: current main and v2026.6.11 still lack the requested typed global or per-agent-model non-resetting generation timeout, while existing controls cover adjacent provider request, first-event, idle-watchdog, and run-level timeout paths.

## What This Changes

The issue requests configurable global and per-model generation timeouts so long-running or looping model generations can be aborted and routed through fallback without relying only on provider or idle timeouts.

## Best Possible Solution

Define one canonical timeout contract for agent model selection, document its precedence across fallback candidates, enforce it at the embedded attempt boundary without weakening existing provider/run caps, and keep first-token and repetition safeguards tracked separately.
