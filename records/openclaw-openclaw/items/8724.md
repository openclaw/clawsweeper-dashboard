## Summary

Keep open: current main still lacks the requested typed global/per-model non-resetting generation timeout, while existing provider request timeout, first-event timeout, idle watchdog, and run timeout only cover adjacent failure modes.

## What This Changes

The issue requests global and per-model generation timeout config so long or looping model generations can be aborted and routed without relying only on provider-level or idle timeouts.

## Best Possible Solution

Define one maintainer-approved timeout hierarchy, then add a typed global/per-model non-resetting generation budget with docs, schema, fallback classification, and regression coverage that preserves existing provider and run timeout behavior.

## Reproduction Assessment

Yes at source level: current main still rejects the proposed agent-model timeout keys and only supports adjacent provider/run/idle timeout controls. I did not run a live Gemini runaway-loop reproduction.

## Solution Assessment

Unclear until maintainers choose the public timeout hierarchy. The requested config surface is plausible, but it must be reconciled with existing provider request timeout, first-event timeout, idle watchdog, run timeout, and fallback behavior.
