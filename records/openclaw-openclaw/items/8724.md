## Summary

Keep open: current main and v2026.6.11 still do not provide the requested typed global or per-model non-resetting generation timeout under agent model config; the existing provider timeout, first-event timeout, and reset-on-chunk idle watchdog only cover adjacent failure modes.

## What This Changes

Requests typed global and per-model generation timeout configuration to bound runaway model generation, log timeout aborts, and optionally trigger model failover.

## Best Possible Solution

Define one maintainer-approved timeout contract, then implement a typed global/per-model non-resetting generation budget with clear precedence against provider request, first-event, idle, run, and fallback timeouts.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: current main still rejects the proposed agent-model timeout keys and the runtime only applies provider-derived idle/first-event timeouts; I did not run a live Gemini loop reproduction.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainers choose the public timeout hierarchy; the requested config surface is plausible, but it must be reconciled with the existing provider timeout and watchdog behavior first.
