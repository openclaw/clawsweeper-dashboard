## Summary

Keep open: current main and v2026.6.11 still have provider request/idle timeout controls, but not the requested typed global/per-model non-resetting generation timeout under agent model config; the remaining work is a product/config contract decision.

## What This Changes

Add global and per-model generation timeout configuration so operators can bound long or looping model generations and define fallback behavior.

## Best Possible Solution

Keep this as the canonical timeout-contract issue, then implement a typed generation budget with explicit precedence, docs/schema coverage, per-selected-candidate enforcement, timeout classification, logging, and fallback semantics.

## Reproduction Assessment

Yes at source level: current main still rejects the proposed per-model timeout keys and only wires provider request timeout into request/idle watchdog behavior. I did not run a live hung-model reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product contract. A typed per-model generation budget is plausible, but the best fix must define precedence against provider request timeout, run timeout, first-token behavior, and the idle watchdog.
