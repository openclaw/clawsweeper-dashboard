## Summary

Keep open: current main still has adjacent provider request, idle, and first-event timeout controls, but not the requested typed global/per-model non-resetting generation-timeout contract under agent model defaults.

## What This Changes

The issue requests configurable global and per-model generation timeouts so slow or looping models can be aborted without relying only on provider request timeouts or idle-stream detection.

## Best Possible Solution

Keep this as the canonical maintainer-reviewed timeout contract, then implement a typed generation-budget schema with explicit precedence, docs, tests, non-resetting enforcement per selected model candidate, and clear fallback/logging behavior.

## Reproduction Assessment

Yes at source level for the missing config/runtime contract: current main still rejects the proposed per-model timeout shape and only wires provider request timeout into idle and first-event watchdogs. I did not run a live stuck-model reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product contract. A typed per-model generation budget is plausible, but the best fix must define precedence against provider request timeout, run timeout, first-token behavior, and the idle watchdog.
