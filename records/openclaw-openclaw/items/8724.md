## Summary

Keep open: this is still necessary because current main and v2026.6.11 expose provider/request, first-event, idle-watchdog, and run-level timeout paths, but not the requested typed per-agent-model generation timeout contract.

## What This Changes

The issue requests a global and per-model generation timeout config so operators can bound runaway or slow model generations and trigger abort/fallback behavior.

## Best Possible Solution

Define one canonical timeout contract for agent model selection, document precedence across fallback candidates, enforce it at the embedded attempt boundary, and keep first-token and semantic repetition safeguards tracked separately.

## Maintainer Decision

Rationale: The implementation boundary is source-clear, but adding a timeout/default config surface changes public config, provider routing, fallback, and upgrade behavior, which AGENTS.md treats as maintainer product intent rather than an automatic repair choice.

Owner confidence: high

Options:

- **Define per-model generation timeout (recommended):** Add a typed agent-default and per-model budget with explicit precedence, fallback handling, schema/docs coverage, and tests.
- **Use existing timeout surfaces:** Decline the new key and improve documentation around provider timeout, run timeout, first-event timeout, and idle watchdog behavior.
- **Split by failure mode:** Leave generation timeout out of scope and route thinking stalls and repeated-output loops to their narrower canonical issues and PRs.

## Reproduction Assessment

Yes, at source level: the strict `agents.defaults.models.*` schema still rejects timeout fields, and the embedded attempt path still uses run/provider timeout inputs rather than a per-model generation budget. I did not run a live model-loop reproduction in this read-only cleanup review.

## Solution Assessment

Unclear until maintainers choose the public config contract. The implementation boundary is clear, but adding another timeout key competes with existing run timeout, provider request timeout, first-event timeout, idle watchdog, and separate repetition/thinking fixes.
