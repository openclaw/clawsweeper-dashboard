## Label Justifications

- `P2`: Runaway or mismatched model latency can waste tokens and delay fallback, but the requested behavior is a bounded configuration improvement rather than an emergency regression.
- `impact:auth-provider`: The request directly changes model-specific provider routing budgets and timeout-driven fallback selection.
- `impact:ux-friction`: Affected users can wait many minutes for an unproductive model run before receiving an error or fallback response.

## Summary

Keep open: current main has provider/run and idle-timeout controls, but still lacks a model-specific, non-resetting total-generation deadline; the active Gemini PR addresses a narrower pre-token idle-watchdog failure rather than this requested configuration contract.

## What This Changes

Request a configurable global and per-model total generation timeout that aborts runaway model generation and can trigger fallback.

## Best Possible Solution

Keep the existing global run budget, add one typed per-model non-resetting generation override only if maintainers approve it, resolve that budget for each fallback candidate, and expose distinct timeout classification and logging without folding semantic repetition detection into this change.

Options:

- **Use provider timeouts only:** Keep models.providers.<id>.timeoutSeconds as the only model-call control and document that models sharing a provider cannot receive different budgets.
- **Prioritize repetition detection:** Decline another timeout knob and address continuously streaming loops through the narrower semantic circuit-breaker work in https://github.com/openclaw/openclaw/issues/44965.

## Reproduction Assessment

Yes at source level: the strict per-model config surface lacks the requested field, while the existing watchdog is idle-based rather than a non-resetting generation deadline. No live 30-minute runaway generation was reproduced in this read-only review.

## Solution Assessment

No, not exactly as proposed: adding both a new global key and per-model key would overlap existing run/provider controls. The narrower maintainable design is to reuse the current global run budget and add only a clearly scoped per-model generation override after timeout semantics are approved.
