## Summary

Keep open: current main and latest local release tag still lack the requested typed global/per-model non-resetting generation timeout under agent model config; existing provider request timeout, first-event timeout, and reset-on-chunk idle watchdog only partially overlap.

## What This Changes

The issue requests a configurable global and per-model generation timeout that aborts runaway LLM generation and can trigger fallback.

## Best Possible Solution

Keep this as the canonical product/config decision: approve a typed non-resetting generation budget with schema, docs, runtime enforcement, and fallback tests, or explicitly document the existing timeout hierarchy as the supported answer and close later.

## Reproduction Assessment

Yes at source level: current main still lacks the requested typed per-model timeout config under `agents.defaults.models`, and the active watchdogs are provider/request-idle oriented rather than a non-resetting generation budget.

## Solution Assessment

Unclear: a per-model generation timeout is plausible, but maintainers should first decide whether the canonical control belongs under `agents.defaults.models`, `models.providers.<id>.timeoutSeconds`, or another timeout hierarchy.
