## Summary

Keep open: current main and v2026.6.11 still do not provide the requested typed global or per-model non-resetting generation-timeout config under agent model settings; the existing provider timeout, first-event timeout, and reset-on-chunk idle watchdog cover adjacent failure modes only.

## What This Changes

The issue requests global and per-model generation timeout configuration so slow or runaway model generations can be aborted or failed over without relying only on provider or idle timeouts.

## Best Possible Solution

Define one maintainer-approved timeout contract, then implement a typed global/per-model non-resetting generation budget with clear precedence against provider request, first-event, idle, run, and fallback timeouts.

## Reproduction Assessment

Yes at source level: current main still rejects the proposed agent-model timeout keys and only supports adjacent provider/run/idle timeout controls. I have not run a live Gemini loop reproduction.

## Solution Assessment

Unclear until maintainers choose the public timeout hierarchy; the requested config surface is plausible, but it must be reconciled with existing provider timeout and watchdog behavior first.
