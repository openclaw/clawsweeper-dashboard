## Summary

Keep open: current main and the latest release still do not provide a proven safe path where a Codex-OAuth sibling model can avoid app-server quota contamination and keep working tools through the direct OpenClaw runtime. The linked OpenAI/Codex quota bookkeeping PR is complementary, but it does not implement the Harmony `functions.*` tool-call adapter or prove the app-server 429 root cause.

## What This Changes

Request to prevent Codex-OAuth sibling models with healthy per-model quota from falling through to a non-Codex fallback while preserving working Codex tool calls.

## Best Possible Solution

Extend the existing plain-text/Harmony tool-call repair path to support Codex `functions.*` targets, keep app-server as the default until maintainers prove the 429 root cause, and validate the direct fallback with live Codex OAuth tool-call proof.
