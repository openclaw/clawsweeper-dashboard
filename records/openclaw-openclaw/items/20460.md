## Summary

Keep open: current main and v2026.6.11 still store config backups beside the active config as a numbered `.bak` ring, while the requested dedicated `config-backup/` directory with datetime names remains unimplemented and needs product direction.

The issue requests moving config backup files into a dedicated `config-backup/` directory and naming each backup with a datetime suffix.

## Best Possible Solution

Define one canonical core config-backup layout, then implement directory placement and collision-safe datetime naming with upgrade-safe legacy handling, recovery selection, audit output, doctor docs, and focused tests.
