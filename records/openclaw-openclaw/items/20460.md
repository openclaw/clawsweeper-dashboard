## Summary

Keep open: current main and the latest release still store config backups beside the active config as `.bak` plus numbered `.bak.N` files, while the only direct dedicated-directory implementation is closed unmerged and the open related work covers timestamp suffixes only.

## What This Changes

The issue asks OpenClaw to move config backup files into a dedicated backup directory and use datetime-based backup filenames instead of adjacent numbered `.bak` files.

## Best Possible Solution

Define one canonical core config-backup layout, then implement directory placement and collision-safe datetime naming with upgrade-safe legacy handling, recovery selection, audit output, doctor docs, and focused tests.
