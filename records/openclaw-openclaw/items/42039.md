## Summary

Keep open: current main and v2026.6.11 still have the missed-job max/stagger controls only as internal CronService dependencies, not public cron config. The remaining decision is product/config direction because the requested disable behavior is not identical to the current internal max/stagger semantics.

## What This Changes

The issue requests public cron configuration for missed-job restart catch-up limits and staggering so users can prevent or slow duplicate catch-up deliveries after gateway restarts.

## Best Possible Solution

Maintainers should choose one supported missed-run policy, then wire it through CronConfig, the strict schema, schema help/labels, gateway construction, docs, and restart-catch-up tests while preserving current defaults unless a migration is explicitly approved.
