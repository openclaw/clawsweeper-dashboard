## Summary

Keep open: current main and the latest release still keep the requested cron restart catch-up knobs internal, and exposing them as public config needs a maintainer product/API decision because the current internal zero-limit behavior would defer, not skip, missed jobs.

## What This Changes

The issue requests public cron config for restart catch-up limits/staggering and an optional way to skip catch-up for user-facing jobs.

## Best Possible Solution

Maintainers should choose a supported missed-run policy first, then update CronConfig, strict schema, config help/docs, gateway wiring, and restart-catch-up tests together.
