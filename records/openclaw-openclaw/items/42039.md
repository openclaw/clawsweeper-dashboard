## Summary

Keep open: current main and the latest release still keep the requested cron restart catch-up controls internal, and publishing them as config needs a maintainer product/API decision because the existing zero-limit path defers missed work rather than skipping it.

## What This Changes

Request to expose cron restart catch-up max/stagger controls, and optionally per-job skip behavior, in public cron config to reduce duplicate delayed deliveries after gateway restarts.

## Best Possible Solution

Maintainers should choose a supported missed-run policy first, then update CronConfig, strict schema, config help/docs, gateway wiring, and restart-catch-up tests together while preserving current defaults for upgrades.
