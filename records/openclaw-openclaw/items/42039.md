## Summary

Keep open: current main still has the restart catch-up limit and stagger only as internal CronService dependencies, while public cron config, strict validation, docs, and Gateway construction do not expose or wire the requested fields.

## What This Changes

Request to expose cron restart catch-up controls in public cron config so operators can limit, disable, or stagger missed-job replay after gateway restart.

## Best Possible Solution

Maintainers should choose one supported missed-run policy, then wire it through config types, strict schema, config help, docs, Gateway CronService construction, and restart-catch-up tests while preserving the current default unless a migration is approved.
