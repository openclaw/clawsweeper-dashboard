## Summary

Keep open: current main and the latest release still keep the restart catch-up max/stagger controls as internal CronService dependencies only, with no public cron config, schema, Gateway wiring, docs, or per-job missed-run policy for users to control duplicate restart catch-up messages.

## What This Changes

The issue requests public cron configuration for `maxMissedJobsPerRestart` and `missedJobStaggerMs`, plus an optional per-job catch-up skip policy.

## Best Possible Solution

Maintainers should choose one supported missed-run policy, then wire it through config types, strict schema, Gateway construction, docs, and restart-catch-up tests while preserving the current default unless an explicit migration is approved.
