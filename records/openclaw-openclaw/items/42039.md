## Summary

Keep open: current main and the latest release still keep these cron restart catch-up controls internal, while the public cron config schema/docs omit them and the remaining question is the public missed-run policy.

## What This Changes

Expose cron restart catch-up controls in public config so operators can tune or avoid duplicate/burst missed-job replay after gateway restarts.

## Best Possible Solution

Define the public missed-run policy first, then wire the chosen global or per-job controls through schema, config help/docs, gateway construction, and restart catch-up tests while preserving current defaults for upgrades.
