## What This Changes

Expose cron missed-job catch-up controls in openclaw.json so operators can cap or stagger restart catch-up runs.

## Best Possible Solution

Define a compatibility-safe public missed-run policy first, then wire schema, types, gateway deps, docs, and restart catch-up tests together.

Options:

- **Define public missed-run policy (recommended):** Add a compatible default plus explicit global or per-job policy for skip, defer, stagger, or time-window catch-up before wiring the lower-level values.
- **Expose raw internal limits:** Promote maxMissedJobsPerRestart and missedJobStaggerMs directly to CronConfig if maintainers accept those numbers as the stable public API.
- **Decline new config for now:** Keep catch-up behavior internal and address duplicate or burst delivery through safer scheduler defaults and documentation only.

Yes. Source inspection shows the internal controls exist, while public CronConfig, the strict zod schema, docs, and Gateway wiring still omit them on current main and v2026.6.11.

## Solution Assessment

Unclear. Exposing the raw internals is plausible, but the safer maintainable fix is for maintainers to choose the public missed-run semantics first, especially skip versus defer versus time-window catch-up.
