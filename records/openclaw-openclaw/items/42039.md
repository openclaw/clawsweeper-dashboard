## Summary

Keep open: current main and the latest release still keep `maxMissedJobsPerRestart` and `missedJobStaggerMs` as internal cron service dependencies, and exposing them as public cron config needs maintainer product direction before automation should implement it.

## What This Changes

Expose the internal cron restart catch-up limit and stagger knobs in public `CronConfig` / `openclaw.json` so operators can disable or slow missed-job replay after gateway restart.

## Best Possible Solution

Maintainers should choose one supported restart catch-up policy, then wire it through `CronConfig`, the strict schema, docs/help metadata, gateway `CronService` construction, and focused restart-catch-up tests while preserving current defaults unless an explicit migration says otherwise.
