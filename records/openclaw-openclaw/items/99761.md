## Summary

Keep open: current main has generic Tool Search search/describe/call, directory-mode schema deferral, and MCP server registry/tool filtering, but it does not provide the requested first-class MCP read-only query-registry authoring/runtime/UI pattern. This remains a product/API design question rather than an already-implemented issue or a safe autonomous fix.

## What This Changes

The issue requests a first-class OpenClaw pattern for MCP servers that expose read-only query registries through catalog, describe, and execute-by-id tools.

## Best Possible Solution

Define a narrow MCP/plugin-author pattern that reuses Tool Search and existing MCP catalog execution, or explicitly decide that existing Tool Search plus author docs are the supported path.
