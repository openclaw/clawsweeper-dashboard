## Summary

Current main documents automatic compaction but exposes no supported OpenClaw config field to disable it, so the request remains necessary; however, the exact opt-out semantics require a maintainer product decision because disabling overflow recovery can intentionally make long sessions fail at the context limit.

Likely related people: steipete has high-confidence history in the embedded runtime and compaction integration; Takhoffman has medium-confidence history introducing compaction tuning surfaces.

## What This Changes

Add a supported configuration control that disables automatic compaction while leaving manual `/compact` available.

## Best Possible Solution

Define one canonical OpenClaw compaction policy whose disabled state consistently skips threshold and overflow-recovery compaction, preserves manual `/compact`, surfaces a clear context-limit error, and is covered by schema, docs, fresh-config, and runtime-path tests.

## Maintainer Decision

Question: Should `agents.defaults.compaction` expose an opt-out, and should that opt-out disable both proactive threshold compaction and automatic recovery after a context-overflow error?

Rationale: The internal dependency setting proves feasibility, but repository policy treats new config as compatibility-sensitive and the choice changes whether sessions recover automatically or intentionally fail at their context limit.

Likely owner: steipete

Owner confidence: high

Options:

- **Expose full automatic opt-out (recommended):** Add a canonical boolean that disables all automatic compaction paths while preserving manual `/compact` and returning an explicit context-limit error.
- **Disable proactive compaction only:** Keep overflow recovery enabled for safety while allowing users to disable threshold-based automatic compaction.
- **Fix accounting without a knob:** Resolve the premature-compaction bugs and retain automatic compaction as mandatory core behavior.

## Reproduction Assessment

Yes, at source level: current main's strict compaction type and Zod schema omit both `enabled` and `auto`, while the docs describe automatic compaction as on by default. A live config-parser run was not needed to establish the unsupported surface.

## Solution Assessment

Unclear until maintainers choose the intended semantics; merely adding `enabled` to the schema is not the best fix unless every OpenClaw-owned automatic compaction path honors it consistently.
