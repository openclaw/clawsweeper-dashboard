## Summary

This PR remains necessary because current main contains the newly merged MCP Apps feature but not these follow-up fixes. The patch captures the opening run’s complete effective MCP tool policy before the view outlives the attempt, enforces that allowlist during App discovery and execution, and correctly addresses optional preview backoff, advertised CSP, and restart classification. No actionable correctness or security defect was found; the remaining blocker is exact-head mergeability and validation because GitHub currently reports the branch as conflicting.

## What This Changes

The PR makes MCP App calls obey the originating run’s effective tool policy, prevents optional preview reads from affecting MCP failure backoff, advertises the applied sandbox CSP, and marks `mcp.apps` listener changes as restart-required.

## Best Possible Solution

Land this bounded hardening with one immutable, run-derived App tool allowlist enforced at Gateway discovery and execution, while retaining optional preview failure isolation, accurate CSP capability reporting, and restart-only listener reconfiguration in the refreshed head.

## Reproduction Assessment

Yes. Current-main source permits an App to discover and call every app-visible tool on its server without applying the effective policy of the run that created the view; the branch adds focused regression coverage for the denial path and related reliability failures.

## Solution Assessment

Yes. Capturing the complete effective policy while the attempt owns all layered policy inputs, then enforcing the immutable allowlist on every later App list and call, is safer and less drift-prone than reconstructing mutable session policy in the Gateway.
