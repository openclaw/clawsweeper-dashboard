The issue reports that Control UI approval expiry and resolve callbacks can remove a newer same-id approval prompt instead of checking the pending entry identity.

## Best Possible Solution

Land or replace the linked fix so timer and local resolve removals verify the exact pending approval entry, while external resolved events remain id-based.

## Reproduction Assessment

Yes by source inspection: enqueue a same-id replacement, then let the old timer or async resolve callback complete, and current main dismisses by id only. I did not run tests in this read-only pass.

## Solution Assessment

Yes, the narrow maintainable fix is entry-aware removal for timer and local resolve completion. Keeping external resolved-event removal id-based is appropriate because those events only carry ids.
