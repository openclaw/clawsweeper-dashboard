## Summary

Keep this issue open: current main still has the id-only Control UI approval removal behavior described, and the linked fix candidate is open but not merged. The issue is the canonical report for this bug until https://github.com/openclaw/openclaw/pull/98530 lands or is closed.

## What This Changes

The issue reports stale Control UI exec approval expiry and resolve callbacks removing newer pending approvals that reuse the same id.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/98530 if it proves entry-identity guards for both expiry and async resolve paths; otherwise keep this issue as the canonical bug and replace the fix candidate.

## Reproduction Assessment

Yes, this is source-reproducible on current main: enqueueing a newer approval with a reused id before an older timeout or resolve callback completes still reaches an id-only removal path. I did not run a live UI repro because this review is read-only.

## Solution Assessment

Yes, the narrow maintainable solution is entry-aware removal for local timer and async resolve callbacks while leaving external resolved events id-based because those events only carry ids.
