## Summary

Issue #55694 should stay open because current main still leaves the reported default-path loop surfaces unresolved: rolling tool-loop detection is documented and tested as opt-in, and tool argument validation failures can be returned to the model before the before-tool-call veto path can stop repeated failures.

## What This Changes

The issue requests safeguards so failed tool calls do not cause repeated agent retries and repeated user-visible messages, especially in channel workflows such as Feishu and Telegram.

## Best Possible Solution

Keep this open until core has a maintainer-approved default policy that classifies deterministic tool failures, blocks runaway repeated failures, and emits one structured channel-visible failure summary instead of repeated progress messages.
