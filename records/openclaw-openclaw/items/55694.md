## Summary

Keep open: current main and v2026.6.11 still leave the default-path validation-error loop and repeated visible channel-message spam possible; existing loop detection is partial and mostly opt-in, so the remaining change needs maintainer policy on defaults, validation-error classification, thresholds, and user-visible failure messaging.

## What This Changes

Requests a core guard that stops repeated failed tool calls and suppresses duplicate channel messages when an agent loops after validation or transient tool errors.

## Best Possible Solution

Define a core default policy that treats deterministic tool validation failures as terminal or tightly bounded per turn, suppresses duplicate visible channel messages, and reuses the existing loop-detection surfaces without broad unsafe default churn.
