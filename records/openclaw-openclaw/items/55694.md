## Summary

Keep open: current main still leaves the default-path tool-validation loop and repeated channel-message spam possible because rolling tool-loop detection is off by default and validation errors remain retry guidance rather than a default hard stop.

## What This Changes

The issue asks OpenClaw to prevent agents from blindly retrying failed tool calls and repeatedly sending near-duplicate channel messages after deterministic tool errors.

## Best Possible Solution

Core should provide a default-on safety path for deterministic validation failures and repeated visible sends: classify non-retryable tool errors, cap same-turn identical failures at a maintainer-approved threshold, suppress duplicate interim channel messages, and send one clear terminal failure summary.
