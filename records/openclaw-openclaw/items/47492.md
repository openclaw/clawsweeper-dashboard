## Summary

Keep open: current main has input provenance, before_tool_call policy hooks, plugin approvals, and exec approvals, but it still lacks a verified-human instruction chain and sensitive-target enforcement for exec, gateway mutation, or outbound actions.

## What This Changes

Request a gateway/tool-policy layer that marks sensitive side-effect targets and requires those actions to trace back to a verified human instruction or go through stricter approval.

## Best Possible Solution

Define a maintainer-approved provenance and sensitive-target policy contract, then enforce it at the gateway/tool-policy/approval boundary with schema, docs, upgrade guidance, and focused regression coverage.
