## Summary

Keep open: current main still has coarse input/system provenance, before_tool_call hooks, exec approvals, and outbound policy, but it does not enforce verified-human instruction provenance for sensitive exec, gateway, or messaging targets. This remains a security/product API design item, not conservative cleanup.

## What This Changes

Request to require sensitive side-effect actions to trace back to a verified human instruction or go through a stricter denial or approval flow.

## Best Possible Solution

Define a maintainer-approved provenance and sensitive-target policy contract, then enforce it at the gateway/tool-policy/approval boundary with schema, docs, compatibility guidance, and focused regression coverage.
