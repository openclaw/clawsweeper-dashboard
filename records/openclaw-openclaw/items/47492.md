## Summary

Keep open: current main still has coarse input provenance, before_tool_call policy hooks, and exec approvals, but it does not implement verified-human instruction provenance or sensitive-target enforcement. This remains a security-sensitive product/API design item, not conservative cleanup.

## What This Changes

Request to add a gateway-enforced verified-human instruction provenance policy for sensitive side-effect actions such as SSH/SCP exec targets, gateway mutation, and high-risk outbound actions.

## Best Possible Solution

Define a maintainer-approved provenance and sensitive-target policy contract, then enforce it at the gateway/tool-policy/approval boundary with schema, docs, compatibility guidance, and focused regression coverage.
