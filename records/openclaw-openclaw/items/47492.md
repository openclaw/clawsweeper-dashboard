## Summary

Keep open: current main still lacks gateway-enforced verified-human instruction provenance or sensitive-target enforcement. Existing input provenance, plugin hooks, and exec approvals are useful adjacent primitives, but this remains a security-sensitive product/API design item rather than conservative cleanup.

## What This Changes

The issue requests a policy layer that lets operators mark sensitive exec and side-effect targets and require those actions to trace back to a verified human instruction before execution or stricter approval.

## Best Possible Solution

Define a maintainer-approved provenance and sensitive-target policy contract, then enforce it at the gateway/tool-policy/approval boundary with schema, docs, compatibility guidance, and focused regression coverage.
