## Summary

Keep open: current main has input provenance, exec/plugin approval, external-content marking, and trusted policy primitives, but no verified-human instruction provenance or sensitive-target enforcement. This remains a security-sensitive product/API design item rather than conservative cleanup.

## What This Changes

Request a gateway-enforced verified-human instruction provenance layer for sensitive exec, message, and gateway targets, with denial or stricter approval fallback when no verified human request is traceable.

## Best Possible Solution

Define a maintainer-approved provenance and policy contract that distinguishes direct verified-human instructions from autonomous, inter-session, and internal actions, then enforce it at the gateway/tool-policy/approval boundary with docs, config/schema support, and regression tests.
