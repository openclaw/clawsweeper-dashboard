## Summary

Keep open: current main and the latest release still provide only coarse input provenance, plugin before_tool_call hooks, and exec approval guardrails; they do not implement verified-human instruction provenance or sensitive-target enforcement for side-effect actions. This remains a security-sensitive product/API design item rather than conservative cleanup.

## What This Changes

The issue requests a gateway-enforced policy layer that requires sensitive exec, messaging, and gateway/config side effects to trace back to a verified human instruction.

## Best Possible Solution

Define one maintainer-approved provenance and sensitive-target policy contract, then enforce it at the gateway/tool-policy/approval boundary with schema/docs and regression coverage while coordinating with https://github.com/openclaw/openclaw/issues/48503 and https://github.com/openclaw/openclaw/issues/54508.
