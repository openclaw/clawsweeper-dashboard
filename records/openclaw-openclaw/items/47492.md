## Summary

Keep open: current main has coarse input provenance, before_tool_call/trusted policy hooks, and approval flows, but it still lacks verified-human instruction provenance and sensitive-target enforcement. This remains a security-sensitive product/API boundary decision, not conservative cleanup.

## What This Changes

The issue requests gateway-enforced verified-human instruction provenance for sensitive exec, gateway, messaging, and other side-effect targets.

## Best Possible Solution

Define a generic provenance and intent contract that flows from verified human-originated turns into tool-call policy, then use it to gate sensitive exec, gateway, and outbound targets through explicit approval or challenge paths without weakening existing approvals.
