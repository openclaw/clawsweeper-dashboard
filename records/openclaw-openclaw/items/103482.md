## Summary

This PR should remain open but is not correct as submitted: it normalizes a decoded metadata field that neither Apple model-picker surface renders, so it cannot produce the claimed visible fix. The linked issue and PR both assume the picker displays `name`, while current main and the PR base render the provider-qualified `selectionID`; the intended label contract needs maintainer direction before implementation.

## What This Changes

The PR changes iOS model-choice decoding to store a trimmed nonblank `name` and adds a decoder test case for a padded catalog name.

## Best Possible Solution

Choose the intended shared Apple picker-label contract; if friendly catalog names are desired, normalize and use them in `displayLabel` with a stable fallback while preserving `selectionID` solely for identity and selection tags, then cover both shared picker surfaces.
