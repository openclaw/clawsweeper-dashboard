## What This Changes

Request to expose an immutable Automation job ID, run ID, and scheduler-snapshotted definition revision to plugin hooks for Automation-triggered runs.

## System Context

Automations admit scheduled jobs and launch isolated agent runs that can invoke tools. Plugin lifecycle hooks observe those tool and run effects, so any Automation identity added there becomes a cross-boundary contract for plugins performing audit or authorization decisions.

## Architecture Diagram

flowchart LR
  A[Persisted Automation definition] --> B[Scheduler admits a run]
  B --> C[Immutable run identity snapshot]
  C --> D[Isolated agent execution]
  D --> E[Plugin lifecycle hooks]
  E --> F[Audit and authorization plugins]

## Best Possible Solution

Have the plugin and Automation owners decide whether this identity belongs in the public hook contract; if approved, capture it once at scheduler admission, propagate it through the complete hook path, document its immutable semantics, and cover concurrent edits and non-Automation runs.
