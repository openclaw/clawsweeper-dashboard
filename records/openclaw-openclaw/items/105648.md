Rationale: Current main intentionally strips tabs across workspace paths, identifiers, metadata, approval paths, and framed blocks, while the demonstrated fidelity problem is specific to structured framed data; changing that shared boundary requires owner intent.

Options:

- **Preserve only in framed blocks (recommended):** Keep the strict literal sanitizer and introduce a narrowly scoped layout-preserving path for tagged data blocks with hostile-input regression coverage.
- **Preserve tabs globally:** Change the shared sanitizer contract only after auditing every caller and proving prompt structure remains protected.

## Reproduction Assessment

Yes for tab removal: current source and tests explicitly strip horizontal tabs. No for the claimed wrapped-newline destruction, because the block wrapper normalizes CRLF and CR and rejoins the sanitized lines with LF.

## Solution Assessment

No; globally re-allowing tabs is broader than the demonstrated framed-data fidelity problem, so a narrowly scoped owner-approved path is safer unless every shared-sanitizer caller is audited.
