## Summary

Keep this issue open: current `main` still gives declared attachment MIME and remote response `Content-Type` precedence over byte-based detection, while the linked fix at https://github.com/openclaw/openclaw/pull/107863 remains open rather than merged. The reported filenames are outdated, but the central defect is valid and has a focused implementation candidate. Likely related people: `ZengWen-DT` (high confidence, linked-fix author) and `steipete` (low confidence, explicitly routed into the issue and repository-wide owner).

## What This Changes

Correct media-understanding attachment MIME selection so actual bytes and filename evidence can override conflicting declared or server-provided metadata.

## Best Possible Solution

Land a narrow bytes-first MIME precedence fix in the shared attachment cache, retain declared and response MIME only as fallbacks, add local and remote conflicting-metadata regression tests, and avoid relaxing gateway attachment schemas.
