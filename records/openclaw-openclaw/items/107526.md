## Summary

Current `main` still gives declared or HTTP MIME metadata precedence over content detection in the media-understanding attachment cache. The focused closing fix at https://github.com/openclaw/openclaw/pull/107863 remains open, so this issue should stay open until that PR is reviewed and either merged or rejected.

## What This Changes

Correct media-understanding MIME inference so attachment bytes and filenames take precedence over conflicting declared or response metadata.

## Best Possible Solution

Land a focused cache-level fix that calls the existing `detectMime` contract for both local and remote bytes, passes declared or response MIME only as fallback metadata, and covers conflicting local and remote inputs without changing gateway schemas.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: construct a valid PNG buffer while declaring `application/pdf`; current `MediaAttachmentCache.getBuffer()` retains the declared type before invoking byte detection. The linked PR reports focused before-fix failures for both local and remote variants, though this review did not run untrusted contributor code locally.

## Solution Assessment

Yes. Reusing the existing media-core bytes → filename → header detector at the attachment-cache boundary is narrower and more maintainable than relaxing gateway schemas or adding another MIME inference implementation.
