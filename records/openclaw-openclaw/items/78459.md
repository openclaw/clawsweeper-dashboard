## What This Changes

The PR removes `fastMode: true` from the hidden commitments extraction embedded-agent request and adds a regression assertion that the request omits `fastMode`.

## Best Possible Solution

Resolve commitment extraction fast mode through the shared resolver after selecting the model, pass the resolved mode and auto cutoff into `runEmbeddedAgent`, and cover both default-off MiniMax and configured opt-in cases.

## Reproduction Assessment

Yes, at source level: current main and the latest release send `fastMode: true` from hidden commitment extraction, and the MiniMax wrapper rewrites `MiniMax-M2.7` to `MiniMax-M2.7-highspeed` when fast mode is true. I did not run a live MiniMax non-highspeed token-plan account in this read-only review.

## Solution Assessment

No as submitted. Removing forced `true` is the right direction, but the best fix should use the shared fast-mode resolver so default-off MiniMax plans and explicit configured fast-mode opt-ins both behave as documented.
