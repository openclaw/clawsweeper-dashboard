## Summary

Keep open: the PR fixes the right current-main source-level bug, but the submitted patch omits `fastMode` entirely even though embedded-agent callers must pass the resolved fast-mode state to preserve existing per-agent and per-model opt-ins.

## What This Changes

The PR removes `fastMode: true` from hidden commitment extraction and adds a regression assertion that the embedded-agent payload omits `fastMode`.

## Best Possible Solution

Resolve commitment extraction fast mode through the shared resolver after model selection, pass the resolved mode and auto cutoff into `runEmbeddedAgent`, and cover both default-off MiniMax and explicit opt-in cases.

## Reproduction Assessment

Yes at source level: current main and latest release send `fastMode: true` from hidden commitment extraction, and the MiniMax wrapper rewrites `MiniMax-M2.7` to `MiniMax-M2.7-highspeed` when fast mode is true. I did not run a live MiniMax non-highspeed token-plan account in this read-only review.

## Solution Assessment

No as submitted. Removing forced `true` is the right direction, but the best fix should use the shared fast-mode resolver so default-off MiniMax plans and explicit configured fast-mode opt-ins both behave as documented.
