## What This Changes

The PR removes `fastMode: true` from the commitments extraction embedded-agent request and adds a regression assertion that the request omits `fastMode`.

## Best Possible Solution

Resolve commitment extraction fast mode through the shared resolver after selecting the model, pass `fastMode` and `fastModeAutoOnSeconds`, test default-off plus configured opt-ins, then refresh current-head real behavior proof.

## Reproduction Assessment

Yes. Current main sends `fastMode: true` from hidden commitment extraction, and the MiniMax wrapper rewrites `MiniMax-M2.7` to `MiniMax-M2.7-highspeed` when fast mode is true; I did not run a live MiniMax Coding Plan account in this read-only review.

## Solution Assessment

No. Removing forced `true` is directionally right, but the best fix should use the shared fast-mode resolver so default-off MiniMax plans and explicit configured fast-mode opt-ins both behave as documented.
