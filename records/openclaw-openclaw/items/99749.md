## Summary

Keep open: the PR targets the right linked bug, but the follow-up guard is narrower than the direct reply side-effect contract and can send a false empty-reply error after a deterministic approval prompt or cron side effect already completed. The external proof is also limited to tests and lint, not a real interactive channel run.

## What This Changes

Adds a shared empty-interactive-reply fallback and wires direct replies plus durable follow-ups to emit a visible error payload when an interactive run completes with no deliverable output.

## Best Possible Solution

Keep the shared guard, but make follow-up use the same successful-side-effect contract as direct replies, including deterministic approval prompts and cron adds, then add redacted real channel proof before merge.

## Reproduction Assessment

Yes, at source level. On the PR head, a follow-up run result with `payloads: []` and `didSendDeterministicApprovalPrompt: true` reaches the new empty fallback because the follow-up side-effect evidence omits that flag.

## Solution Assessment

No, not yet. The guard belongs at the reply/follow-up finalization boundary, but the follow-up implementation needs side-effect parity with direct replies before this is the best fix.
