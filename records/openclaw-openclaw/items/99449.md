## Summary

Close as not actionable in the OpenClaw source repo: the observed OpenAI Codex runtime is explained by a session-pinned OpenAI model, and current code/docs show that Codex only claims OpenAI/Codex provider selections, not a clean DeepSeek primary.

## What This Changes

The issue asks OpenClaw to prevent enabling the Codex plugin from overriding a configured DeepSeek primary model or routing ordinary chats through OpenAI Codex.

## Best Possible Solution

Keep the current session-pinned model behavior, direct affected users to `/model default` or explicit `agentRuntime.id: "openclaw"` when they want non-Codex OpenAI execution, and require a fresh unpinned DeepSeek repro before reopening as a code bug.
