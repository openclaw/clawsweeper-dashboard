## Summary

Keep open. Current main explains why an already selected OpenAI model switches from OpenClaw Default to OpenAI Codex once the Codex harness is registered, but the newest discussion makes the original DeepSeek-primary reproduction ambiguous rather than safely closeable.

## What This Changes

The issue reports that enabling the Codex plugin makes ordinary DeepSeek-configured conversations run through OpenAI Codex/GPT-5.4-nano and hit OpenAI TPM limits.

## Best Possible Solution

Confirm a clean current-main repro with no prior /model or persisted OpenAI session state; if it is session-state drift, fold the evidence into https://github.com/openclaw/openclaw/issues/87957, and if it is OpenAI/Codex opt-out policy, fold it into https://github.com/openclaw/openclaw/issues/95131.

## Reproduction Assessment

No. The report has concrete logs and screenshots, but current main only source-explains an OpenAI selected session becoming OpenAI Codex after plugin registration; it does not prove plugin enablement alone promotes a DeepSeek primary, and the latest comment says the conversation was manually switched to an OpenAI model.

## Solution Assessment

Unclear. A direct change to the Codex default would be too broad if selected session state is the cause; the maintainable path is either the shared session model/auth resolver or a maintainer-approved OpenAI/Codex opt-out policy.
