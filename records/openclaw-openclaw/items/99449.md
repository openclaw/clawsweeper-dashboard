## Summary

Keep open. Current `main` still has a plausible selected-session path where an explicit OpenAI `/model` selection becomes `OpenAI Codex` once the Codex harness is enabled, while the original DeepSeek-primary override claim is not proven as a current-main bug after the reporter clarified they manually selected `openai/gpt-5.4-nano`.

## What This Changes

The issue asks that enabling the Codex plugin not change ordinary chat runtime/model selection away from the configured DeepSeek primary unless Codex/OpenAI is explicitly selected.

## Best Possible Solution

Preserve explicit `/model` selections, but prove and fix any path where plugin enablement or hot reload silently promotes a configured DeepSeek-primary session to OpenAI/Codex without an explicit user selection; route broader selected/runtime/auth-state cleanup through the existing resolver tracker.
