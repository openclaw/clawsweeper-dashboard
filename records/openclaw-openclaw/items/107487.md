## Summary

This fresh report remains necessary: current documentation promises that `/acp close` ends the OpenClaw ACP session, and current main still has distinct close, runtime-handle-cache, and ACPX runtime surfaces that plausibly participate in the stale-resume path. However, the report targets v2026.6.11 while v2026.7.1 is current, so a focused current-release reproduction is needed before choosing the repair layer. citeturn819203view1turn523818view0

## What This Changes

Fix `/acp close` so a persistent ACPX session cannot retain stale identity in backend storage or the gateway runtime cache and resume after being closed.

## Best Possible Solution

Make the manager's close operation evict the runtime handle and invoke one canonical backend discard/close contract that durably prevents resume, then add a restart-aware regression proving the next turn uses `session/new` without core code manipulating ACPX-private files.
