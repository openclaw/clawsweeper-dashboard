## Label Justifications

- `P1`: The reported Docker upgrade path can leave configured channel workflows omitted while the gateway reports healthy after an image replacement.
- `impact:message-loss`: Skipped upgrade migrations can leave channel plugins absent after startup, causing inbound messages and replies to be missed.
- `impact:other`: The issue also affects upgrade readiness and migration sequencing, which are maintainer-visible operational impacts outside the narrower message-loss taxonomy.
- `maturity:stable`: The affected gateway runtime and CLI install/update/doctor surfaces are scored M4 stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main still has limited gateway startup preflight and advisory warnings while doctor/update owns full repair and post-core convergence, so direct container-image upgrades can still report a healthy gateway without a versioned migration gate; #98564/#98608 only cover the Mattermost-specific activation example.

## What This Changes

Request gateway startup for direct container image replacements to detect pending OpenClaw version migrations and run or block readiness before reporting healthy.

## Best Possible Solution

Define a maintainer-owned startup upgrade contract that records the last successfully migrated state/config version and either runs pending idempotent migrations under a lock before readiness or fails readiness with actionable doctor guidance.

## Reproduction Assessment

Yes at source level: current main gateway startup runs limited preflight and warnings while full repair/convergence remains explicit doctor/update work, but no fresh live Docker replay was performed here.

## Solution Assessment

Unclear: the issue is valid, but the best fix depends on a maintainer policy choice between automatic startup migration and fail-closed readiness with operator-run repair.
