## Label Justifications

- `P1`: The report describes a release-to-release container upgrade where Gateway reaches ready while a configured Mattermost channel is absent, causing missed inbound messages and failed outbound sends.
- `impact:message-loss`: The configured Mattermost channel does not start after the image replacement, so inbound posts receive no bot reply and outbound sends fail.
- `maturity:stable`: The affected convergence/update class maps to cli.plugin-convergence under the M4 cli-install-update-onboard-doctor maturity surface.

## Summary

Keep open: this is a protected maintainer-labeled regression, and current main still routes configured-plugin package repair through doctor/update convergence while Gateway startup is verify-only; the reported Docker image replacement path can still reach ready with Mattermost absent.

## What This Changes

Container image replacement should preserve or visibly fail configured external official channel plugin convergence before the Gateway reports ready.

## Best Possible Solution

Add an explicit Docker/container upgrade path that either runs bounded configured-plugin convergence before readiness or marks readiness unhealthy with actionable repair guidance when a configured official channel plugin is missing.

## Reproduction Assessment

Yes from source inspection and the reporter's logs, but I did not run a live 2026.6.10 to 2026.6.11 Mattermost container replacement. Current startup does not invoke the doctor configured-plugin repair path, while outbound selection already reports the missing Mattermost plugin.

## Solution Assessment

Unclear until maintainers choose the owner boundary: running package-manager repair during Gateway boot conflicts with current startup policy, so a Docker entrypoint preflight or readiness gate may be safer than putting installs in hot startup.
