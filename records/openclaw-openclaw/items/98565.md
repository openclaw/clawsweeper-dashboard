## Summary

Keep open: current main still has only a guarded legacy-state/config startup preflight, while the full doctor/update migration and version-stamp repair paths remain outside direct container gateway startup; the live Docker repro comment also confirms readiness can go green with pending migrations.

## What This Changes

The issue reports that container image replacement can start the gateway without running pending OpenClaw upgrade migrations before readiness.

## Best Possible Solution

Define a maintainer-owned container startup upgrade contract that records the last successfully migrated state/config version and either runs safe idempotent pending migrations under a lock before readiness or fails readiness with a clear doctor/fix command when migration work is unsafe for startup.

## Reproduction Assessment

Yes. Current source shows direct gateway startup runs the limited legacy-state/config preflight and then starts the server, while the full doctor/update repair and version-stamp paths are separate; the issue discussion also includes a live official-image Docker repro.

## Solution Assessment

Unclear as an implementation decision. The best fix must be maintainer-approved because running migrations during startup, blocking readiness, and preserving explicit doctor/update repair boundaries have different upgrade and operator-control tradeoffs.
