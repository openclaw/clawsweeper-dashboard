## Summary

Keep open: this maintainer-labeled issue remains valid because current main still runs bounded gateway startup state preflight, not a version-transition gate that runs or blocks on the full upgrade/doctor migration set before readiness.

## What This Changes

The issue reports that replacing an OpenClaw container image can start the gateway on preserved state without running or blocking on pending OpenClaw upgrade migrations first.

## Best Possible Solution

Define one startup-owned upgrade contract for mounted state: compare the last successfully migrated OpenClaw version with the running image, run idempotent safe migrations under a lock before readiness, and fail readiness with clear doctor guidance for migrations that cannot safely run automatically.

## Reproduction Assessment

Yes at source level: current main runs bounded startup state preflight and the live issue comment provides an official-image Docker swap where the gateway reached ready with `meta.lastTouchedVersion` still on the old version. I did not rerun Docker proof in this read-only review.

## Solution Assessment

Unclear until maintainers choose the startup policy. A startup readiness gate is the right boundary, but the best fix must separate safe automatic migrations from repairs that should fail closed with operator action.
