## Summary

Keep open: the live Docker image-swap repro plus current main source still show direct container gateway startup running guarded preflight/warnings rather than a version-gated upgrade migration path, and the protected maintainer/product-decision labels require human policy before implementation.

## What This Changes

The issue requests container gateway startup to detect mounted state/config version changes, run or block on pending upgrade migrations before readiness, and record the successfully migrated version.

## Best Possible Solution

Define a maintainer-owned container startup upgrade contract that locks the mounted state/config, compares the last successfully migrated version to the running image, runs only safe idempotent pending migrations or fails readiness with actionable doctor/upgrade guidance, and covers the image-swap path in tests.

## Reproduction Assessment

Yes, with a high-confidence shipped-image repro and current-main source proof. I did not rerun Docker locally, but the July 3 repro uses official images and current main still shows the same startup/doctor split.

## Solution Assessment

Unclear whether auto-running the full repair set at startup is the best policy. The maintainable fix should put the decision at the shared gateway/container startup boundary and either run a narrow safe migration set under lock or fail readiness with explicit operator guidance.
