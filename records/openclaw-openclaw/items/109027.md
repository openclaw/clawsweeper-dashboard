## Summary

The commentary tagging direction is sound and the previous final-answer buffer repair improves the synthetic subscriber test, but the patch still breaks the configured `text_end` delivery boundary for the OpenClaw-owned Chat Completions transport because that transport never emits a `text_end` event. The PR also has only harness evidence, so live provider/channel proof remains required before merge.

## What This Changes

Tags text blocks on Chat Completions tool-use turns as commentary, buffers unclassified Completions deltas in embedded delivery, restores unphased final-answer buffering at `text_end`, and adds transport and subscriber regression coverage.

## Best Possible Solution

Make both Chat Completions implementations honor one event contract: classify tool-use text before terminal delivery, emit a correctly phased `text_end` for completed text blocks or otherwise preserve visible deltas until an equivalent boundary, cover the real transport-to-subscriber event sequence, and provide a redacted live provider/channel transcript.
