## Summary

Keep open. Current main now reconciles eligible official plugins during the supported `openclaw update` flow and exposes actionable drift diagnostics through deep Gateway status and Doctor, but direct package-manager upgrades can still leave persisted official plugins stale and allow channel or provider traffic to fail before the operator runs those diagnostics; the remaining startup/reconciliation policy requires maintainer direction.

## What This Changes

The issue asks OpenClaw to prevent or clearly diagnose official plugin/core version drift after upgrades so channels and provider-backed agent turns do not silently fail.

## Best Possible Solution

Keep coordinated official-plugin reconciliation in `openclaw update`, preserve intentional pins, and add a prominent startup/readiness and affected channel/provider diagnostic that names each stale trusted official plugin and the exact safe repair command before normal traffic is accepted.

## Maintainer Decision

Required: true

Kind: product_direction

Question: For direct package-manager core upgrades that leave trusted official plugins stale, should OpenClaw warn and degrade readiness, automatically reconcile eligible plugins, or refuse Gateway startup?

Rationale: The remaining fix changes upgrade and pin semantics: automatic repair may overwrite intentional pins, while fail-closed startup may create unnecessary outages, so repository intent is required before implementation.

Likely owner: steipete

Owner reason: Recent plugin updater and install-selection history makes this the strongest available owner for choosing the permanent direct-upgrade and pin-policy boundary.

Owner confidence: medium

Options:

- **Warn And Degrade Readiness (recommended):** Emit an actionable startup/readiness warning and surface the same diagnosis in channel/provider failures without changing stored plugin pins automatically.
- **Auto-Reconcile Eligible Official Plugins:** At startup, update only trusted official records that retain default/latest intent while preserving explicit versions, tags, and third-party sources.
- **Refuse Startup On Drift:** Treat trusted official plugin/core mismatch as a startup error until the operator updates or removes the stale plugin.

## Reproduction Assessment

Yes at the source and latest-release level: direct core replacement can preserve a stale managed official plugin, and the July 12 reproduction demonstrated failure followed by recovery after exact-version reconciliation. A current-main live upgrade run has not yet shown whether the failure is now surfaced before traffic.

## Solution Assessment

No single suggested option is automatically the best fix. The narrowest safe direction is to retain supported-updater reconciliation and add startup/readiness plus failure-path diagnostics, rather than silently overwriting pins or unconditionally refusing startup.
