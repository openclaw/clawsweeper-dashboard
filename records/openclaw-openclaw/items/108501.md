## Label Justifications

- `P1`: A deterministic retry path can silently drop both the voice reply and accompanying text after durable delivery has accepted the message.
- `impact:message-loss`: The affected queue path suppresses an outbound message during retry and eventually dead-letters it without delivery.

## Summary

The report identifies a current, deterministic durability bug: automatic TTS supplies producer-owned temporary media to a write-ahead queue whose retry lifecycle outlives that media. The linked pull request remains open and explicitly owns the fix, so this issue should stay open until that candidate is reviewed and merged or replaced.

## What This Changes

Make queued automatic TTS replies retain replayable audio after producer cleanup so retries do not lose the voice message and accompanying text.

## Best Possible Solution

The durable queue should atomically stage authorized short-lived local media into queue-owned storage before publishing a replayable row, preserve copy-free immediate sends, keep sensitive media live-only, and reclaim artifacts only after no pending row references them.

## Reproduction Assessment

Yes at source level. Automatic TTS creates a five-minute temporary file while the durable queue retains its raw path through a substantially longer retry window; the linked pull request also documents a fresh-process before/after reproduction.

## Solution Assessment

Yes in principle: queue ownership of replayable media addresses the durability invariant instead of merely avoiding retries and still losing voice output. The linked implementation needs its own detailed review because artifact lifecycle, authorization, crash ordering, and reclamation span several sensitive paths.
