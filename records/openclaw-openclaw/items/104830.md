## Label Justifications

- `P1`: The patch fixes a restart-safety regression but currently permits duplicate deferral loops in the production config-reload workflow after an inspection error.

## Summary

The fail-closed direction is correct, but the patch changes `onCheckError` from a terminal callback into a retry notification without updating its production caller, which clears the duplicate-loop guard and tells operators a restart is happening immediately.

## What This Changes

The PR changes restart deferral to retry pending-work inspection failures instead of restarting immediately.

## Best Possible Solution

Update the config-reload caller to keep `restartPending` true and log that inspection failed and will be retried, then add caller-level coverage proving repeated config changes cannot create a second poll after an inspection error.
