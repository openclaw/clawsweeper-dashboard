## Summary

Keep open: the previous config-reload guard finding is resolved, but the revised error path can still re-enter the failing inspection through warning or timeout hooks, potentially throwing from the timer callback and preventing the forced-timeout restart.

## What This Changes

The PR makes restart deferral retry pending-work inspection failures, preserves the config-reload deferral guard, updates warning text, and adds regression tests.

## Best Possible Solution

Keep the fail-closed retry behavior, but track failed inspections separately so warning hooks do not re-enter the unavailable count path and timeout emission uses error-tolerant logging; prove both transient recovery and persistent-failure timeout behavior in a real Gateway setup.
