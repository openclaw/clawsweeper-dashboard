## Review Findings

Overall correctness: patch is incorrect

Full review comments:

- **[P1] Preserve registrations without reloading unrelated plugins:** `src/agents/harness/runtime-plugin.ts:208-218`
  - body: Adding every loaded plugin ID to `scopedPluginIds` turns the preservation attempt into another activating load of those plugins. On a cache miss, unrelated `register()` functions run again, which can duplicate hooks/services, repeat expensive initialization, or mutate process-global state; preserve or compose the existing registry and load only the missing harness-owned plugins instead.
  - confidence: 0.98
- **[P1] Apply the complete effective activation policy:** `src/agents/harness/runtime-plugin.ts:208-211`
  - body: This filter only checks a restrictive allowlist. A previously loaded default-off or workspace plugin whose explicit opt-in was removed still enters the widened scope, and `withActivatedPluginIds` later writes `enabled: true` for it unless an explicit `false` remains. Resolve each retained ID through the canonical effective activation decision before adding it so live config changes cannot revive plugin code.
  - confidence: 0.95
