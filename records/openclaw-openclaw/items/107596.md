## Summary

Keep this PR open, but do not merge the current head: the linked plugin-eviction bug is credible, while the prior P1 remains because the patch converts a narrow harness cache miss into a reload of every active plugin rather than preserving existing registry instances. The current head also lacks inspectable after-fix real-runtime proof.

## What This Changes

The PR unions currently loaded plugin IDs into scoped harness activation and adds regression tests for preserving an unrelated CLI backend while respecting a restrictive allowlist.

## Best Possible Solution

Preserve the existing active registry through a request-scoped registry handle or a transactional loader merge that adds only the missing harness owner without rerunning `register()` for already-active plugins, then cover the real loader lifecycle and provide redacted live after-fix output.
