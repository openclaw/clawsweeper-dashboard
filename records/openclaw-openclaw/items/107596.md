## Label Justifications

- `P1`: The underlying bug breaks active CLI-backend agent workflows until gateway restart, while the proposed fix can affect every loaded plugin during harness activation.
- `merge-risk: 🚨 compatibility`: The patch changes scoped activation from loading harness-related plugins to reloading all active plugins, exposing existing plugin registration implementations to a new lifecycle pattern.
- `merge-risk: 🚨 availability`: Side-effectful or slow external register functions may now run during an agent harness cache miss and stall or disrupt agent turns.

## Summary

The reported registry-eviction bug is credible, but this PR should not merge as written: it preserves registry surfaces by adding every active plugin to the scoped load, which can re-run unrelated plugins’ registration logic and recreate the latency and side-effect problems the loader cache was designed to prevent. The PR also lacks observable after-fix evidence from a patched real setup.

## What This Changes

The PR unions already-active plugin IDs into scoped agent-harness loads and adds tests covering preservation and restrictive-allowlist exclusion.

## Best Possible Solution

Preserve or merge the existing active registry while loading only the missing harness-owned plugins, without re-registering unrelated plugins; cover the real loader path, assert unrelated register counts remain unchanged, verify allowlist removal, and provide redacted patched-runtime proof.
