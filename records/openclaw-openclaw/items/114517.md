## Summary

The Feishu adapter still lacks an outbound `deliveryCapabilities` declaration, so this issue remains necessary. However, current Feishu send paths visibly support payload cards and reply/thread routing while no `silent` handling is present, so copying Telegram’s full contract would overstate what Feishu can durably reproduce. Likely related people: gumadeiras (medium), Takhoffman (medium), and steipete (medium).

## What This Changes

Add an accurate durable-delivery capability declaration for the Feishu outbound adapter so retry and persistence paths retain only the message features Feishu actually supports.

## System Context

OpenClaw channels provide outbound adapters to the core delivery layer, which uses each adapter’s declared capabilities to choose durable retry and final-delivery behavior. The Feishu plugin converts text, media, and card payloads into Feishu API sends, including reply and thread targeting where supported.

  B --> C[Feishu outbound adapter]
  C --> D[Declared durable capabilities]
  D --> E[Retry and final delivery choice]
  E --> F[Feishu message and card APIs]

## Best Possible Solution

Audit the core durable-delivery contract and advertise only the Feishu capabilities demonstrated by its outbound paths; implement and prove any missing semantics before marking them durable, especially `silent` and batch behavior.
