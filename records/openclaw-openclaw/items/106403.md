## Summary

Keep this issue open: current main still lets the transcript-mtime reconciliation signal override a reset-policy-fresh main session, matching the reported silent rollover path. The source-level reproduction is strong, but the production writer that advanced the transcript after session completion is not yet identified, and the proposed policy-staleness guard could undo the stale-row recovery added for the earlier wedge.

## What This Changes

Prevent a healthy terminal main session from rolling over solely because its transcript mtime becomes newer than the registry timestamp.

## Best Possible Solution

Replace the raw mtime-only decision with an authoritative transcript mutation marker or semantic cursor maintained by every Gateway-owned writer, preserving genuine stale-row recovery while adding regression coverage for both a fresh terminal session with a late managed append and a truly divergent terminal row.

## Reproduction Assessment

Yes at source level: create a policy-fresh terminal main entry, advance its transcript mtime beyond updatedAt, and send a non-system inbound turn; current admission logic makes freshEntry false and rolls over the session. A live current-main execution was not performed during this read-only review.

## Solution Assessment

No, restricting the gate to policy-stale entries is not yet the best fix because it can defeat the earlier stale-row recovery invariant. The safer direction is an authoritative or semantic divergence marker shared by all transcript writers.
