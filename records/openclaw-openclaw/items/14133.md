## Summary

Keep open: current main still lacks a dedicated Reminders route/UI and the durable cron classification/display contract needed to separate one-shot reminders from ordinary cron jobs. The broader cron tags issue overlaps only on classification, and the earlier opaque metadata PR was closed unmerged after a maintainer asked for an owner-reviewed API slice.

## What This Changes

The issue requests a dedicated Reminders tab in Control UI that hides or separates one-shot reminder cron jobs from generic Cron jobs and shows cleaned reminder text, fire time, channel/recipient, and delete actions.

## Best Possible Solution

Define one additive cron purpose/display metadata contract, have reminder-producing paths set it, expose typed reminder/non-reminder filters, and build a Reminders view with cleaned text, fire time, recipient/channel, and delete actions.
