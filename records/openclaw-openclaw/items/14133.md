## Summary

Keep open: current main still has the generic Cron Control UI and scheduler contracts, but no dedicated Reminders tab, no reminder-specific render branch, and no persisted cron purpose/display field or list filter that can separate one-shot reminders from system cron jobs. The related cron tags/categories issue overlaps on classification but does not cover the dedicated Reminders card UI, cleaned reminder text, recipient/channel display, or Cron-tab visibility policy.

## What This Changes

Request a dedicated Mission Control Reminders tab for one-shot reminder cron jobs, with reminder-friendly cards and Cron-tab filtering based on cron job metadata.

## Best Possible Solution

Define one additive cron purpose/display metadata contract, make reminder-producing paths set it, expose typed reminder/non-reminder filters, and build the Reminders tab and Cron-tab visibility policy on that shared model.

## Reproduction Assessment

Yes for the current capability gap: source inspection shows no Reminders tab/route, no reminder render branch, no reminder-purpose/display fields in cron contracts, and no reminder filter. This is a feature request rather than a failing-runtime bug repro.

## Solution Assessment

Unclear as proposed. A dedicated Reminders UX is reasonable, but tags or payload extraction alone are not the best permanent fix until maintainers choose the shared cron purpose/display contract and Cron-tab visibility policy.
