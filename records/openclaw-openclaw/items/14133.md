## Summary

Keep open: current main still has only the generic Cron/Mission Control surface, with no Reminders tab, no reminder-specific render branch, and no cron purpose/display metadata or filter that can separate one-shot reminders from ordinary cron jobs.

## What This Changes

Request a dedicated Reminders tab in Mission Control with reminder-specific cron metadata/filtering and cleaned card display for one-shot reminder jobs.

## Best Possible Solution

Define one additive cron purpose/display metadata contract, have reminder-producing paths set it, expose typed reminder/non-reminder filters, and build the Reminders tab plus Cron-tab visibility policy on that shared model.

## Reproduction Assessment

Yes. Source inspection reproduces the current capability gap: there is no Reminders tab/route, reminder render branch, cron purpose/display field, or reminder/non-reminder list filter on current main.

## Solution Assessment

Unclear as proposed. A dedicated Reminders UX is reasonable, but tags-only or payload-string extraction should wait until maintainers choose the shared cron purpose/display contract and visibility policy.
