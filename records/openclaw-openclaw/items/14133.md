## Summary

Keep open: current main still lacks the dedicated Reminders tab plus the cron purpose/display metadata needed to separate one-shot reminders from ordinary cron jobs without parsing raw payload text.

## What This Changes

The issue requests a dedicated Mission Control Reminders tab backed by cron reminder classification and display metadata so one-shot reminders are separated from ordinary cron jobs.

## Best Possible Solution

Define an additive cron purpose/display metadata contract, set it from reminder-producing paths, expose typed reminder/non-reminder filters, and build a Reminders view that shows cleaned text, fire time, recipient/channel, and delete actions.

## Reproduction Assessment

Yes for the capability gap: current source has no Reminders tab/route, no reminder render path, and no reminder classifier/filter in cron contracts, service, or UI. This is a feature request rather than a failing-runtime bug reproduction.

## Solution Assessment

Unclear as proposed. A dedicated Reminders view is plausible, but the best fix is a shared typed cron purpose/display metadata contract rather than one-off freeform tags or payload parsing.
