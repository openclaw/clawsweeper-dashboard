## Summary

Keep open: current main still has only the generic Cron/Mission Control surface, with no Reminders navigation or render branch and no cron purpose/display metadata or filter that can separate one-shot reminders from ordinary cron jobs. The related cron tags/categories issue overlaps on classification, but it does not cover the dedicated Reminders tab, cleaned reminder text, recipient/channel card UI, or Cron-tab visibility policy.

## What This Changes

Request to add a dedicated Mission Control Reminders tab that separates one-shot reminder cron jobs from generic cron jobs and renders cleaner reminder cards.

## Best Possible Solution

Define one additive cron purpose/display metadata contract, make reminder-producing paths set it, expose typed reminder/non-reminder filters, and build the Reminders tab and Cron-tab visibility policy on that shared model.

## Reproduction Assessment

Yes for the current capability gap: source inspection shows no Reminders tab/route, no reminder render branch, no reminder-purpose/display fields in cron contracts, and no filter that can exclude reminders from the Cron tab. This is a feature request rather than a failing-runtime bug repro.

## Solution Assessment

Unclear as proposed. A dedicated Reminders UX is reasonable, but tags or payload extraction alone are not the best permanent fix until maintainers choose the shared cron purpose/display contract and Cron-tab visibility policy.
