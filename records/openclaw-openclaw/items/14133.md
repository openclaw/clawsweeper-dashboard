## Summary

Keep open: current main still lacks the dedicated Reminders route/UI and the durable cron classification/display contract needed to separate one-shot reminders from ordinary cron jobs. The broader cron tags issue overlaps only on classification, and the earlier metadata PR was closed unmerged for needing an owner-reviewed API slice.

## What This Changes

The issue requests a dedicated Mission Control Reminders tab that separates one-shot reminder cron jobs from recurring cron jobs and displays user-friendly reminder details.

## Best Possible Solution

Define one additive cron purpose/display metadata contract, have reminder-producing paths set it, expose typed reminder/non-reminder filters, and build a Reminders view with cleaned text, fire time, recipient/channel, and delete actions.
