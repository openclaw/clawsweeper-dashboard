## Summary

Keep open: current main still has only the generic Cron jobs UI and cron list/filter contract, with no Reminders tab, reminder classifier/display metadata, or reminder/non-reminder filtering. The open cron tags issue overlaps on classification, but it does not replace this dedicated reminder UI request.

## What This Changes

The issue requests a dedicated Mission Control Reminders tab that shows cleaned one-shot reminder cards and separates reminder jobs from generic cron jobs.

## Best Possible Solution

Define one additive cron purpose/display metadata contract, set it from reminder-producing paths, expose typed reminder/non-reminder filters, and build a Reminders view with cleaned text, fire time, recipient/channel, and delete actions.

## Reproduction Assessment

Yes for the capability gap: current source has no Reminders tab/route, no reminder render path, and no reminder classifier/filter in cron contracts, service, or UI. This is a feature request rather than a failing-runtime bug repro.

## Solution Assessment

Unclear as proposed. A dedicated Reminders view is plausible, but the best fix should use a shared typed cron purpose/display metadata contract rather than one-off freeform tags or payload parsing.
