## Summary

Keep open: current main still lacks a dedicated Reminders tab, reminder-purpose/display metadata, and reminder-aware cron filtering; the related cron tags issue overlaps but does not cover the dedicated UI or cleaned reminder presentation.

## What This Changes

Request a dedicated Mission Control Reminders tab that separates one-shot reminder cron jobs from generic cron jobs and displays cleaned reminder details.

## Best Possible Solution

Define one additive cron purpose/display metadata contract, have reminder-producing paths set it, expose typed filtering, and build the Reminders tab plus Cron-tab visibility policy on that shared model.

## Reproduction Assessment

Yes. Source inspection on current main reproduces the missing capability: there is no Reminders route/render branch, no reminder-purpose/display fields in cron contracts, and no reminder/non-reminder filter path.

## Solution Assessment

Unclear as proposed. A dedicated Reminders UX is reasonable, but the best fix should first settle the shared cron purpose/display metadata contract and Cron-tab visibility policy.
