## Summary

Keep open: current main still exposes reminders through the generic Cron UI and lacks the durable cron classification, display, and filtering contract needed for a dedicated Reminders tab. The broad cron tags issue overlaps only on classification, and the earlier metadata PR was closed unmerged after maintainer design concerns.

## What This Changes

Request a dedicated Mission Control Reminders tab for one-shot reminder cron jobs, with cleaned reminder cards and Cron-tab filtering based on durable job metadata or classification.

## Best Possible Solution

Define one additive cron purpose/display metadata contract, have reminder-producing paths set it, expose typed reminder/non-reminder filters, and build a Reminders view with cleaned text, fire time, recipient/channel, and delete actions plus protocol/service/UI tests and docs.
