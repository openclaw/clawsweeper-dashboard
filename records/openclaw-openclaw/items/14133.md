## Summary

Keep open: current main and v2026.6.11 still expose reminders as generic cron jobs with no dedicated Reminders tab, reminder display/classification contract, or reminder-aware filtering; https://github.com/openclaw/openclaw/issues/53107 overlaps on cron categorization but does not cover the Reminders UI or Cron-tab visibility policy.

## What This Changes

Add a dedicated Reminders tab in Mission Control that separates one-shot reminder cron jobs from generic cron jobs and shows cleaned reminder details.

## Best Possible Solution

Define one additive cron purpose/display metadata contract, have reminder-producing paths set it, expose typed list filtering, and build the Reminders tab plus Cron-tab visibility policy on that shared model.

## Reproduction Assessment

Yes. Source inspection on current main reproduces the missing capability: there is no Reminders route/render branch, no reminder-purpose/display fields in cron contracts, and no reminder/non-reminder filter path.

## Solution Assessment

Unclear as proposed. A dedicated Reminders UX is reasonable, but the best implementation should first settle the shared cron purpose/display metadata contract and Cron-tab visibility policy.
