## Summary

Keep open: current main still lacks a dedicated Reminders route/view, reminder-purpose/display metadata, and reminder-aware cron filtering. https://github.com/openclaw/openclaw/issues/53107 overlaps on broader cron categorization, and https://github.com/openclaw/openclaw/pull/45991 attempted opaque metadata but closed unmerged, so neither supersedes the dedicated Reminders UI request.

## What This Changes

The issue requests a dedicated Control UI Reminders tab for one-shot cron reminders, with cleaned reminder text, fire time and recipient cards, delete actions, and filtering or hiding reminders from the generic Cron tab.

## Best Possible Solution

Define one additive cron purpose/display metadata contract, have reminder-producing paths set it, expose typed list filtering, and build the Reminders tab plus Cron-tab visibility policy on that shared model.

## Reproduction Assessment

Yes. Source inspection on current main verifies the missing capability: there is no Reminders route/render branch, no reminder-purpose/display fields in cron contracts, and no reminder/non-reminder filter path.

## Solution Assessment

Unclear as proposed. A dedicated Reminders UX is reasonable, but the best fix should first settle the shared cron purpose/display metadata contract and Cron-tab visibility policy.
