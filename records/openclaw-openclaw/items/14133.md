## Summary

Keep open: current main still lacks a Reminders navigation/render path and lacks cron metadata or filtering that can separate one-shot reminders from ordinary cron jobs. The related cron tags/categories issue overlaps on classification, but it does not cover the dedicated Reminders tab, cleaned reminder text, recipient/channel card UI, or Cron-tab visibility policy.

## What This Changes

The issue requests a dedicated Mission Control Reminders tab that separates one-shot reminder cron jobs from recurring cron jobs and displays user-facing reminder details.

## Best Possible Solution

Define one additive cron classification/display metadata contract, make reminder-producing paths set it, expose typed reminder/non-reminder filtering, and build the Reminders tab plus Cron-tab visibility policy on that shared model.

## Reproduction Assessment

Yes for the current capability gap: source inspection shows no Reminders tab/route, no reminder render branch, and no reminder-purpose/display fields or filters in cron contracts. This is a feature request rather than a failing-runtime bug reproduction.

## Solution Assessment

Unclear as proposed. A dedicated Reminders UX is reasonable, but tags or payload extraction alone are not the best permanent fix until maintainers choose the shared cron purpose/display contract and Cron-tab visibility policy.
