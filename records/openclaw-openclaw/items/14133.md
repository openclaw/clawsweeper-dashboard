## Summary

Keep open: current main still has only the generic Cron Control UI and lacks the dedicated Reminders tab plus the cron purpose/display metadata needed to separate one-shot reminders from ordinary scheduled jobs without brittle payload parsing.

## What This Changes

Add a dedicated Reminders tab in Mission Control for one-shot reminder cron jobs, with cleaned reminder text, fire time, channel/recipient, delete action, and filtering out of the generic Cron tab.

## Best Possible Solution

Define one additive cron classification and display metadata contract, have reminder-producing paths set it, add typed reminder/non-reminder list filters, then build the Reminders tab and Cron-tab visibility policy on that shared model.

## Reproduction Assessment

Yes. Source inspection on current main reproduces the missing capability: there is no Reminders route/render branch, no reminder-purpose/display fields in cron contracts, and no filter that can exclude reminders from the Cron tab.

## Solution Assessment

Unclear as proposed. A Reminders UX is reasonable, but tags or payload extraction alone are not the best permanent fix until maintainers choose the shared cron purpose/display contract and Cron-tab visibility policy.
