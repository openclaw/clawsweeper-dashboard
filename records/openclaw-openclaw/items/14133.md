## Summary

Keep open: current main still has only the generic Cron Control UI surface, with no Reminders route, reminder-specific render path, cron purpose/display metadata, or reminder-aware list filtering. The broader cron tags issue overlaps, and the prior opaque metadata PR was closed unmerged, so neither supersedes the dedicated Reminders UI request.

## What This Changes

Request a dedicated Control UI/Mission Control Reminders tab that separates one-shot reminder cron jobs from ordinary cron jobs and shows cleaned reminder text, fire time, recipient/channel, and delete controls.

## Best Possible Solution

Define one additive cron purpose/display metadata contract, have reminder-producing paths set it, expose typed reminder/non-reminder filtering, and build the Reminders tab plus Cron-tab visibility policy on that shared model.

## Reproduction Assessment

Yes. Source inspection on current main reproduces the missing capability: there is no Reminders route/render branch, no reminder-purpose/display fields in cron contracts, and no reminder/non-reminder filter path.

## Solution Assessment

Unclear as proposed. A dedicated Reminders UX is reasonable, but the best fix should first settle the shared cron purpose/display metadata contract and Cron-tab visibility policy.
