## Summary

Keep open: current main still lacks a dedicated Reminders tab, a reminder-purpose/display metadata contract, and reminder-aware cron filtering. https://github.com/openclaw/openclaw/issues/53107 overlaps on cron classification, and https://github.com/openclaw/openclaw/pull/45991 attempted metadata, but neither supersedes the dedicated Reminders UI, cleaned reminder copy, or Cron-tab visibility policy.

## What This Changes

Requests a dedicated Reminders tab in Control UI/Mission Control for one-shot reminder cron jobs, with cleaned display text, fire time, channel/recipient, delete actions, and filtering out of the generic Cron tab.

## Best Possible Solution

Define one additive cron purpose/display metadata contract, have reminder-producing paths set it, expose typed list filtering, and build the Reminders tab plus Cron-tab visibility policy on that shared model.

## Reproduction Assessment

Yes. Source inspection on current main reproduces the missing capability: there is no Reminders route/render branch, no reminder-purpose/display fields in cron contracts, and no reminder/non-reminder filter path.

## Solution Assessment

Unclear as proposed. A dedicated Reminders UX is reasonable, but the best fix should first settle the shared cron purpose/display metadata contract and Cron-tab visibility policy.
