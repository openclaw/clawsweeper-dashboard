## Summary

Keep open: current main and the latest release still expose reminders as ordinary cron jobs, and the related cron tags/categories issue only covers part of the required classifier/filtering work, not the dedicated Reminders tab or cleaned reminder display.

## What This Changes

Request a Mission Control Reminders tab that separates one-shot reminder cron jobs from system cron jobs and displays reminder-focused card details.

## Best Possible Solution

Add a maintainer-approved cron display/classification contract that reminder-producing paths can set, then build the Reminders tab and Cron-tab filtering on that typed metadata instead of name or payload string matching.

## Reproduction Assessment

Yes, from source inspection rather than a live UI run: current main documents reminders as cron jobs and the Control UI only has the generic Cron tab/list path. There is no Reminders route, reminder classifier, or list filter in the inspected source.

## Solution Assessment

Unclear until maintainers choose the cron metadata shape and visibility policy. The best direction is a typed additive cron classifier/display contract shared by reminder producers and the UI, not payload/name heuristics in Mission Control.
