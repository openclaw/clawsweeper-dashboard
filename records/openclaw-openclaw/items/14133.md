## Summary

Keep open: current main still lacks the dedicated Reminders tab, reminder-purpose/display metadata, and reminder/non-reminder cron filtering. The open cron tags/categories issue overlaps on the metadata contract, but it does not cover the Reminders UI, cleaned reminder text, or Cron-tab visibility policy.

## What This Changes

Request for a dedicated Mission Control Reminders tab that separates one-shot reminder cron jobs from ordinary cron jobs.

## Best Possible Solution

Define one additive cron purpose/display metadata contract, have reminder-producing paths set it, add typed list filtering, and build the Reminders tab plus Cron-tab visibility policy on that shared model.

## Reproduction Assessment

Yes. Source inspection on current main reproduces the missing capability: there is no Reminders route/render branch, no reminder-purpose/display fields in cron contracts, and no reminder/non-reminder filter path.

## Solution Assessment

Unclear as proposed. A dedicated Reminders UX is reasonable, but the best fix should first settle the shared cron purpose/display metadata contract and Cron-tab visibility policy.
