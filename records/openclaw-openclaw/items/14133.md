## Summary

Keep open: current main still lacks the dedicated Reminders tab and the shared cron classification/display metadata needed to separate one-shot reminders from ordinary cron jobs. The related cron tags issue overlaps on metadata/filtering, but it does not cover the reminder-specific UI and cleaned reminder display requested here.

## What This Changes

The issue requests a dedicated Mission Control Reminders tab that shows one-shot reminder cron jobs separately from regular cron jobs with user-friendly reminder text, fire time, channel/recipient, and delete actions.

## Best Possible Solution

Define one additive cron classification/display metadata contract, have reminder-producing paths set it, add typed list filtering, hide or filter reminders from the Cron tab, and add a Reminders tab with card UI plus protocol/service/UI tests and docs updates.

## Reproduction Assessment

Yes. Source inspection on current main shows no Reminders tab, no reminder-specific render branch, and no cron classifier/filter field that could separate reminder jobs from ordinary cron jobs.

## Solution Assessment

Partly. A dedicated Reminders tab is a reasonable end state, but the implementation should first settle the shared cron classification/display metadata contract instead of matching reminder names or payload text.
