## Label Justifications

- `P3`: This is useful scheduled-job and Control UI ergonomics work, but it is not an urgent runtime failure.
- `impact:ux-friction`: Reminders remain mixed with system cron jobs and can expose prompt-like payloads, creating avoidable user-facing confusion without blocking use.

## Summary

Keep open: current main still has only the generic Cron Control UI/protocol/listing surface, while the related cron tags issue only partially covers the metadata need and no merged fix implements the dedicated Reminders tab or cleaned reminder display.

## What This Changes

The issue requests a dedicated Mission Control Reminders tab, reminder/non-reminder cron classification, cleaned reminder cards, and filtering reminders out of the generic Cron tab.

## Best Possible Solution

Define one additive cron purpose/display metadata contract, have reminder-producing paths set it, add typed reminder/non-reminder filters, then build the Reminders tab with cleaned text, fire time, channel/recipient, delete actions, and Cron-tab visibility tests.

## Reproduction Assessment

Yes. Source inspection reproduces the missing capability: current main has no Reminders route/render branch, no reminder-purpose/display fields in cron contracts, and no filter that can exclude reminders from the Cron tab.

## Solution Assessment

Unclear as proposed. A dedicated Reminders UX is reasonable, but tags or payload extraction alone are not the best permanent fix until maintainers choose the shared cron purpose/display contract and Cron-tab visibility policy.
