## Summary

Keep open: current main still lacks a dedicated Mission Control Reminders tab and a typed cron purpose/display metadata contract, so one-shot reminder jobs cannot be cleanly separated from ordinary cron jobs without brittle payload or name parsing.

## What This Changes

The issue requests a Mission Control Reminders tab that shows human-readable reminder cards and filters reminder-created one-shot cron jobs out of the generic Cron tab.

## Best Possible Solution

Define an additive cron purpose/display metadata contract, set it from reminder-producing paths, expose typed reminder/non-reminder filters, and build a Reminders view that shows cleaned text, fire time, recipient/channel, and delete actions.

## Reproduction Assessment

Yes for the capability gap: current source has no Reminders tab/route, no reminder render path, and no reminder classifier/filter in cron contracts, service, or UI. This is a feature request rather than a failing-runtime bug repro.

## Solution Assessment

Unclear as proposed. A dedicated Reminders view is plausible, but the best fix is a shared typed cron purpose/display metadata contract rather than one-off freeform tags or payload parsing.
