## Summary

Keep open: current main still has only the generic Cron Control UI and cron list/protocol surfaces, while the requested Reminders tab needs new cron classification/display metadata and a product decision on Cron-tab visibility.

## What This Changes

Request a dedicated Reminders tab in the Control UI that shows cleaned reminder cards and separates one-shot reminder jobs from generic Cron jobs.

## Best Possible Solution

Define one additive cron purpose/display metadata contract, have reminder-producing paths set it, add typed reminder/non-reminder list filters, then build the Reminders tab and Cron-tab policy against that shared model.

## Reproduction Assessment

Yes. Source inspection reproduces the missing capability: current main has no Reminders route/render branch, no reminder-purpose/display fields in cron contracts, and no reminder/non-reminder filter.

## Solution Assessment

Unclear as proposed. A dedicated Reminders UX is reasonable, but tags or payload extraction alone are not the best permanent fix until maintainers choose the shared cron purpose/display contract and visibility policy.
