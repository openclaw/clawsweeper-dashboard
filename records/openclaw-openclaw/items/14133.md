## Summary

Keep open: current main and the latest release still expose reminders only through the generic cron surface, with no Reminders tab, no reminder-specific cron classifier/display metadata, and no reminder/non-reminder list filter. The related cron tags issue is useful overlap, but it does not cover the dedicated UI, cleaned reminder copy, or Cron-tab visibility policy requested here.

## What This Changes

The issue requests a dedicated Mission Control Reminders tab that shows one-shot reminder cron jobs as cleaned, user-facing cards and keeps them separable from generic cron jobs.

## Best Possible Solution

Define one additive cron purpose/display metadata contract, have reminder-producing paths set it, add typed reminder/non-reminder filters, then build the Reminders tab and Cron-tab visibility policy on that shared model.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: current main has no Reminders route/render branch, no reminder-purpose/display fields in cron contracts, and no filter that can exclude reminders from the Cron tab. I did not run a browser session because the missing capability is directly visible in the source contracts and UI routing.

## Solution Assessment

Unclear as proposed. A dedicated Reminders UX is reasonable, but tags or payload extraction alone are not the best permanent fix until maintainers choose the shared cron purpose/display contract and Cron-tab visibility policy.
