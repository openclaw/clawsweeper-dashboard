- `impact:ux-friction`: Reminder jobs are currently surfaced in a generic Cron UI with raw payload details, creating avoidable user-facing confusion without blocking progress.

## Summary

Keep open: current main still lacks the Reminders tab/view and the cron purpose/display metadata needed to separate one-shot reminders from generic cron jobs without brittle payload parsing.

## What This Changes

Requests a dedicated Mission Control Reminders tab that shows cleaned reminder cards and filters reminder one-shot cron jobs out of the generic Cron tab.

## Best Possible Solution

Define one additive cron purpose/display metadata contract, have reminder-producing paths set it, add typed reminder/non-reminder list filters, then build the Reminders tab and Cron-tab visibility policy on that shared model.

## Reproduction Assessment

Yes. Source inspection reproduces the missing capability: current main has no Reminders route/render branch, no reminder-purpose/display fields in cron contracts, and no filter that can exclude reminders from the Cron tab.

## Solution Assessment

Unclear as proposed. A dedicated Reminders UX is reasonable, but tags or payload extraction alone are not the best permanent fix until maintainers choose the shared cron purpose/display contract and Cron-tab visibility policy.
