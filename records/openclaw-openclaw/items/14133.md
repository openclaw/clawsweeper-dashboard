## Summary

Keep open: current main still lacks a dedicated Reminders route/UI and the durable cron classification/display contract needed to separate one-shot reminders from ordinary cron jobs. The broader cron tags issue overlaps on classification only, while the prior opaque metadata PR was closed unmerged for owner-reviewed API design.

## What This Changes

Add a dedicated Reminders tab in Mission Control that shows cleaned reminder cards and filters reminder jobs out of the generic Cron view.

## Best Possible Solution

Define one additive cron purpose/display metadata contract, have reminder-producing paths set it, expose typed reminder/non-reminder filters, and build a Reminders view with cleaned text, fire time, recipient/channel, and delete actions.
