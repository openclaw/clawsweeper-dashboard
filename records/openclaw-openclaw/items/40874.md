Full review comments:

- **[P1] Move the intent consumer onto the current root:** `apps/ios/Sources/RootCanvas.swift:200-208`
  - body: `OpenTalkModeIntent.perform()` only writes a UserDefaults flag, but this branch consumes it from `RootCanvas`; current main mounts `RootTabs()` and no longer has `RootCanvas.swift`. Port the cold/warm launch consumer into the RootTabs-era shell when resolving the conflict, or the Action Button/Siri shortcut can set a flag no mounted view consumes.
  - confidence: 0.95
- **[P2] Filter stale activities before choosing a keeper:** `apps/ios/Sources/LiveActivity/LiveActivityManager.swift:130-132`
  - body: `hydrateCurrentAndPruneDuplicates()` selects the max `startedAt` from every ActivityKit activity without checking that it is active, fresh, and not idle/disconnected. Current main has that stale cleanup invariant; keep it when rebasing or an old terminal Live Activity can be adopted as `currentActivity` and suppress the new connection state.
  - confidence: 0.86
- **[P2] Refresh Live Activity after gateway metadata changes:** `apps/ios/Sources/Model/NodeAppModel.swift:689-694`
  - body: This `refreshIdentity` call only runs when `setSelectedAgentId` is invoked, but reconnect can start the activity before `refreshAgentsFromGateway()` resolves default agent metadata. Because ActivityKit attributes are immutable, metadata arrival can leave the Dynamic Island or lock-screen label/session stuck on fallback identity unless effective identity changes also recreate the activity.
  - confidence: 0.9
- **[P2] Preserve active work when stale HUD timers expire:** `apps/ios/Sources/Model/NodeAppModel.swift:1752-1753`
  - body: Each camera HUD auto-hide task unconditionally clears Live Activity working state after its sleep. If screen recording or another task starts before an older HUD timer fires, that stale cleanup resets the newer Dynamic Island status; track which task set the state and clear only when the same task is still active.
  - confidence: 0.86
