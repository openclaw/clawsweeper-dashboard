Full review comments:

- **[P1] Port the intent consumer to the current RootTabs root:** `apps/ios/Sources/RootCanvas.swift:200-207`
  - body: The PR consumes `pendingTalkMode` in `RootCanvas`, but current main mounts `RootTabs()` as the app root. After resolving the dirty branch, leaving the consumer here would let the Action Button/Siri intent set the flag without any mounted view navigating into Talk Mode.
  - confidence: 0.93
- **[P2] Preserve Live Activity stale filtering during hydration:** `apps/ios/Sources/LiveActivity/LiveActivityManager.swift:130-135`
  - body: This hydration path picks a keeper from every ActivityKit activity by `startedAt`, dropping current main's checks for active, non-idle, non-disconnected, non-stale candidates. With the new working/task states, an old or disconnected activity can be adopted and shown on the lock screen/Dynamic Island.
  - confidence: 0.88
- **[P2] Refresh the activity after gateway agent metadata changes:** `apps/ios/Sources/Model/NodeAppModel.swift:689-694`
  - body: The PR refreshes ActivityKit attributes when `setSelectedAgentId` changes them, but `activeAgentName` and `mainSessionKey` also change when `refreshAgentsFromGateway()` applies the default agent or main key after connect. Because ActivityKit attributes are immutable, the Dynamic Island label can remain stuck on the fallback identity until reconnect or manual agent switching.
  - confidence: 0.84
- **[P2] Tie working-state cleanup to the owning HUD operation:** `apps/ios/Sources/Model/NodeAppModel.swift:1752-1753`
  - body: The camera auto-hide timer always clears Live Activity working state when it fires. A later long-running screen recording sets its own working state without canceling an older camera HUD timer, so the older timer can reset the Dynamic Island back to idle while recording is still active.
  - confidence: 0.82
