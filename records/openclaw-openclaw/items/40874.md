## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Move the intent consumer onto RootTabs:** `apps/ios/Sources/RootCanvas.swift:200-208`
  - body: The PR head observes `OpenTalkModeIntent.pendingTalkModeKey` in `RootCanvas`, but current main no longer mounts that view and `OpenClawApp` now presents `RootTabs`. After rebase, the shortcut can be discoverable while only setting UserDefaults unless the cold/warm pending flag consumption is moved into the current RootTabs navigation path.
  - confidence: 0.94
- **[P2] Filter stale activities before choosing a keeper:** `apps/ios/Sources/LiveActivity/LiveActivityManager.swift:130-132`
  - body: This hydration path picks the max `startedAt` from all `Activity.activities` without checking `activityState`, terminal states, or stale age. Current main filters those candidates first, and dropping that guard can keep an old ActivityKit item with stale agent/session/task data on the Dynamic Island or lock screen.
  - confidence: 0.9
- **[P2] Refresh identity after gateway metadata changes:** `apps/ios/Sources/Model/NodeAppModel.swift:689-694`
  - body: The new identity refresh only runs from `setSelectedAgentId`, but gateway metadata refresh can also change `activeAgentName` or `mainSessionKey` after the Live Activity was started. Since the widget renders `context.attributes.agentName`, the lock-screen label can stay on the fallback or previous agent until the user manually changes selection.
  - confidence: 0.86
- **[P2] Keep old HUD timers from clearing newer work:** `apps/ios/Sources/Model/NodeAppModel.swift:1752-1753`
  - body: Every camera HUD auto-hide calls `handleWorking(task: nil)` after its sleep without checking that the task it started is still current. If a screen recording or another camera task starts before that timer fires, the older timer can incorrectly clear the newer Dynamic Island working state.
  - confidence: 0.88
