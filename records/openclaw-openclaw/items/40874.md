## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Move the intent consumer onto the current root:** `apps/ios/Sources/RootCanvas.swift:200-208`
  - body: `OpenTalkModeIntent.perform()` only writes a UserDefaults flag, but this branch consumes that flag from `RootCanvas`; current main no longer has that root and mounts `RootTabs()`. Port the cold/warm launch consumer into the current shell when rebasing, or the Action Button/Siri shortcut can set a flag no mounted view consumes.
  - confidence: 0.95
- **[P2] Preserve stale-activity filtering when rebasing:** `apps/ios/Sources/LiveActivity/LiveActivityManager.swift:130-132`
  - body: `hydrateCurrentAndPruneDuplicates()` selects the keeper from every ActivityKit activity by `startedAt` before filtering out terminal or stale activities. Current main filters to active, non-idle, non-disconnected, fresh candidates first; keep that invariant or an old terminal Live Activity can be adopted as current and suppress the new connection state.
  - confidence: 0.88
- **[P2] Refresh Live Activity after gateway metadata changes:** `apps/ios/Sources/Model/NodeAppModel.swift:689-694`
  - body: This refresh only runs from `setSelectedAgentId`, but reconnect starts the activity before `refreshAgentsFromGateway()` can resolve default agent metadata. Because ActivityKit attributes are immutable, the Dynamic Island or lock-screen label/session can stay stuck on fallback identity unless metadata-driven effective identity changes also recreate the activity.
  - confidence: 0.86
- **[P2] Guard HUD cleanup by the task it started:** `apps/ios/Sources/Model/NodeAppModel.swift:1753`
  - body: The camera HUD auto-hide task always clears Live Activity working state after its sleep. If another operation, such as screen recording, starts before that timer fires, the old HUD timer can call `handleWorking(task: nil)` and incorrectly reset the Dynamic Island while the newer task is still active.
  - confidence: 0.84
