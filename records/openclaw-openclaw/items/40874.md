Overall correctness: patch is incorrect

Full review comments:

- **[P1] Port the intent consumer to RootTabs:** `apps/ios/Sources/RootCanvas.swift:200-207`
  - body: The PR consumes `talk.pending-talk-mode` only from `RootCanvas`, but current main mounts `RootTabs()` and no longer has `RootCanvas.swift`. After resolving the conflict, leaving this consumer outside RootTabs makes the new Action Button/Siri shortcut set a flag without enabling Talk Mode or navigating to the Talk tab.
  - confidence: 0.94
- **[P2] Preserve Live Activity stale hydration filters:** `apps/ios/Sources/LiveActivity/LiveActivityManager.swift:130-141`
  - body: Current main hydrates only active, non-idle, non-disconnected, non-stale ActivityKit records before selecting a keeper. This branch selects from all active activities by `startedAt`, so an old idle/disconnected record can be kept and then mirrored back to Dynamic Island or the lock screen after restart.
  - confidence: 0.9
- **[P2] Refresh identity after gateway metadata changes:** `apps/ios/Sources/Model/NodeAppModel.swift:689-694`
  - body: The new refresh path only runs from `setSelectedAgentId`, but gateway metadata arrival also changes `gatewayDefaultAgentId`, `gatewayAgents`, and `mainSessionKey` after the Live Activity has already started. Because ActivityKit attributes are immutable, the lock-screen agent/session label can stay on the fallback identity until reconnect or manual agent switching.
  - confidence: 0.86
- **[P2] Tie working cleanup to the owning task:** `apps/ios/Sources/Model/NodeAppModel.swift:1752-1753`
  - body: The auto-hide HUD cleanup always calls `handleWorking(task: nil)` after its timer, even if another operation, such as screen recording, started a different working state meanwhile. A stale camera-success timer can therefore clear the Dynamic Island state for a newer active task.
  - confidence: 0.82
