## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Move the intent consumer onto the current root:** `apps/ios/Sources/RootCanvas.swift:200-208`
  - body: `OpenTalkModeIntent.perform()` only sets a `UserDefaults` flag, and this branch consumes it from `RootCanvas`; current main no longer has that file and mounts `RootTabs()` from `OpenClawApp`, so after rebase the Action Button/Siri shortcut can set the flag without any current root view entering Talk Mode. Port the cold/warm launch consumer into the RootTabs-era shell when resolving the conflict.
  - confidence: 0.95
- **[P2] Refresh Live Activity after metadata changes:** `apps/ios/Sources/Model/NodeAppModel.swift:689-694`
  - body: This new `refreshIdentity` call only runs when `setSelectedAgentId` is invoked, but the reconnect flow starts the activity before `refreshAgentsFromGateway()` resolves `gatewayDefaultAgentId`, `gatewayAgents`, and `mainSessionKey`. Since ActivityKit attributes are immutable, metadata arriving from the gateway can still leave the Dynamic Island/lock-screen label or session key stuck on the fallback identity unless the metadata refresh path also recreates the activity when the effective identity changes.
  - confidence: 0.9
- **[P2] Preserve active work when stale HUD timers expire:** `apps/ios/Sources/Model/NodeAppModel.swift:1752-1753`
  - body: Each camera HUD auto-hide task now unconditionally calls `handleWorking(task: nil)` after its sleep. If a screen recording or another camera task starts before an older HUD timer fires, that stale cleanup will clear the newer Dynamic Island working state; track the task/token that set the state and only clear it when the same task is still active.
  - confidence: 0.86
- **[P2] Filter stale activities before choosing a keeper:** `apps/ios/Sources/LiveActivity/LiveActivityManager.swift:130-132`
  - body: `hydrateCurrentAndPruneDuplicates()` selects the max `startedAt` from every ActivityKit activity without checking that it is active, fresh, and not an idle/disconnected terminal state. Current main has stale cleanup for this surface; keep that invariant when rebasing, otherwise an old disconnected or idle Live Activity can be adopted as `currentActivity` and suppress the new connection state.
  - confidence: 0.82
