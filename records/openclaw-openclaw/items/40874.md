## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Move the intent consumer into RootTabs:** `apps/ios/Sources/RootCanvas.swift:200-208`
  - body: `OpenTalkModeIntent.perform()` only writes the `talk.pending-talk-mode` flag, but this branch consumes that flag in `RootCanvas`. Current main no longer has `RootCanvas` and mounts `RootTabs()`, so a rebase that does not move the cold/warm launch consumer into the active shell can leave the Action Button shortcut setting a flag that no mounted view consumes.
  - confidence: 0.94
- **[P2] Preserve stale activity filtering:** `apps/ios/Sources/LiveActivity/LiveActivityManager.swift:130-132`
  - body: The PR head hydrates by selecting the max `startedAt` activity from all ActivityKit records, but current main first filters to active, non-idle, non-disconnected, fresh candidates. Dropping that filter can re-adopt an old terminal or stale Live Activity and keep the Dynamic Island/lock-screen state wrong after reconnects or app restarts.
  - confidence: 0.9
- **[P2] Refresh activity after gateway metadata changes:** `apps/ios/Sources/Model/NodeAppModel.swift:689-694`
  - body: The new immutable Live Activity attributes are refreshed only from `setSelectedAgentId`, but `activeAgentName` and `mainSessionKey` can also change when gateway agent metadata/default-agent data arrives after the reconnect loop starts the activity. Without recreating the activity on that metadata path, users can keep seeing a fallback or old agent label for the whole activity.
  - confidence: 0.86
- **[P2] Guard HUD cleanup by the task it started:** `apps/ios/Sources/Model/NodeAppModel.swift:1752-1753`
  - body: The camera HUD auto-hide task always calls `handleWorking(task: nil)` after its delay. If screen recording or another longer task starts before that timer fires, the older HUD cleanup can reset the Live Activity back to the prior connection state while the newer task is still running.
  - confidence: 0.82
