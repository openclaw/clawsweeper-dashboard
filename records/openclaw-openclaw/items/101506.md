## Summary

Keep open: the current head preserves the prior retry/hint behavior and includes real managed-Chrome failure proof, but the new bounded stderr helper still stores a `Buffer.subarray()` view after partial trims, so an oversized stderr chunk can keep its full backing store alive and leave the memory-bound fix incomplete.

## What This Changes

The PR changes managed Chrome launch diagnostics to keep a bounded stderr tail, preserve retry/hint markers while stderr streams, render the newest failure slice, and add browser internal regressions.

## Best Possible Solution

The end state should be a Chrome launch diagnostics accumulator that preserves streaming retry/hint facts and newest redacted output while retaining only copied bytes under the 64 KiB cap.
