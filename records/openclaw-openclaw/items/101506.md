## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Preserve recovery markers outside the stderr tail:** `extensions/browser/src/browser/chrome.ts:1095`
  - body: This tail is now the only text used later for stale Singleton-lock recovery and missing-display/profile-lock hints. If Chrome emits one of those markers early and then enough noisy stderr to exceed 64 KiB, the marker is dropped and existing recovery or guidance silently disappears; track those facts while streaming instead of deriving them only from the retained tail.
  - confidence: 0.91
- **[P2] Show the newest failure output:** `extensions/browser/src/browser/chrome.ts:1136`
  - body: After this change `stderrOutput` is already a retained tail, but the existing error builder still displays the first 2000 characters of that 64 KiB window. A terminal Chrome error at the newest end can still be omitted, so the rendered diagnostic should take a newest display tail rather than the start of the retained buffer.
  - confidence: 0.87
- **[P3] Avoid splitting UTF-8 while trimming:** `extensions/browser/src/browser/chrome.ts:147`
  - body: `first.subarray(overflowBytes)` can start the retained buffer in the middle of a multi-byte character, and the later `toString("utf8")` will emit replacement characters in the diagnostic. Use a UTF-8-safe text tail or adjust the byte boundary before decoding.
  - confidence: 0.84
