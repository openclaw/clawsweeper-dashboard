## What This Changes

The PR adds activity-model helpers for running tool entries, re-exports them through the tool-stream module, and uses them in chat abortability/queued abort state so the composer shows active status while tool activity is running.

## Best Possible Solution

Land this narrow UI bridge after normal maintainer review so the composer and Activity panel use the same active tool-execution signal for visible run status and Stop controls.

## Reproduction Assessment

Yes. Current main shows a source-reproducible split where composer status comes from chatRunId/session rows while running tool activity is stored in activityEntries, and the linked issue plus PR comment include before/after screenshots.

## Solution Assessment

Yes. Reusing the existing session-scoped activity stream inside the existing abortability path is the narrowest maintainable fix; adding protocol, config, or a parallel composer state machine would be heavier and less direct.
