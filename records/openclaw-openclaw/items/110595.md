## Label Justifications

- `P1`: A gateway-close timeout can leave the interactive `openclaw tui` process and terminal active after the user requests quit.
- `merge-risk: 🚨 availability`: The changed shutdown contract can bypass the terminal teardown and cancel the forced-exit fallback when gateway transport close rejects.

## Summary

The proposed await fixes the normal transport-close ordering, but it introduces a P1 shutdown failure path: a `stopAndWait()` timeout rejects before terminal cleanup runs and clears the hard-exit timer. Keep this PR open for that narrow repair and inspectable after-fix terminal proof.

## What This Changes

The PR changes `GatewayChatClient.stop()` to await gateway transport teardown and adds TUI tests for the stop contract and process-exit watchdog.

## Best Possible Solution

Keep the ordered transport wait, but run `drainAndStopTuiSafely(tui)` unconditionally after the stop attempt, retain the shutdown error for logging, and add a regression test for a rejecting backend stop before merge.
