## Summary

The functional patch remains necessary, and the structured failover changes align with the existing typed-reason design, but the new auth-parity guard passes when a manifest provider has no matching runtime provider. That prevents the central regression test from distinguishing intentional capability-only plugins from the provider-id drift it is meant to catch; the external PR also lacks after-fix real behavior proof.

## What This Changes

The PR centralizes the built-in model API set, adds bundled-provider manifest/runtime auth parity coverage, and classifies typed context-overflow and transient failover reasons in the terminal catch path.

## Best Possible Solution

Keep the production consolidation and structured failover logic, but explicitly classify capability-only manifest choices and require every text-provider choice to resolve a runtime provider and auth method before asserting option-key, CLI-flag, and environment-variable parity.
