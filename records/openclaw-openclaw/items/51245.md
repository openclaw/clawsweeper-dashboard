## Summary

Keep this open: current main and the latest release still source-reproduce the `openclaw sandbox explain --session telegram:slash:<id>` channel-unknown path. Current Telegram native command runtime now carries `Provider: "telegram"` and records metadata on the target session, but that does not make the documented bare Telegram slash session key resolve correctly in sandbox/elevated diagnostics.

## What This Changes

The issue asks OpenClaw to resolve Telegram native slash session keys as `telegram` so elevated `tools.elevated.allowFrom.telegram` diagnostics and checks do not fail as `channel: (unknown)`.

## Best Possible Solution

Port or write a narrow fix that makes `sandbox explain` and elevated diagnostics resolve documented Telegram native slash keys to the target channel without broadening runtime authorization, then add regression coverage and Telegram/elevated proof.
