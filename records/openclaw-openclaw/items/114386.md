## Summary

This PR addresses a confirmed current-main compaction bug and is still necessary: current `main` estimates the retained transcript tail with raw UTF-16 length divided by four, while the proposed branch applies a shared CJK-aware estimate across that decision path. The patch follows the repository’s owner-boundary direction by placing the reusable heuristic in Normalization Core, and the supplied real-tokenizer and focused Testbox evidence supports the behavior change. It should remain open for maintainer landing review and exact merge-result verification, not be closed as obsolete.

## What This Changes

The PR moves CJK-aware character weighting into Normalization Core and uses it when Agent Core estimates transcript tokens for compaction triggering and retained-tail selection.

## System Context

Agent Core compaction estimates the token size of session messages, decides whether context is too large, and selects the recent transcript tail to retain while older content is summarized. This PR changes the shared text-size heuristic that feeds those compaction decisions for CJK-heavy user, assistant, tool, and summary content.

## Best Possible Solution

Keep one canonical CJK-aware estimator in `packages/normalization-core`, route all compaction message-text accounting through it, and land only after exact merge-result validation confirms both CJK tail budgeting and unchanged Latin/image behavior.
