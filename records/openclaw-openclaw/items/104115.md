## Summary

The current head still has a blocking helper-lifecycle defect: successful remote helper installation does not refresh the connected Mac node, so it can continue advertising without `system.run.prepare` until an unrelated reconnect. The updated live proof does not clear this because it used a build containing a separate macOS restart repair that could supply the missing reconnect.

## What This Changes

The PR adds macOS app-node `system.run.prepare` through a validated same-version local CLI helper, extends remote onboarding to install that helper, and extracts shared TypeScript preparation logic.

## Best Possible Solution

Refresh or reconnect the Mac node whenever helper installation or validation state changes, retain the extracted preparation helper as the single policy implementation, and prove the exact head through remote install, refreshed advertisement, and routed execution.
