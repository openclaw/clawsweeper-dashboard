## Summary

Current main and the latest release still only deny unauthorized WhatsApp group traffic; they do not leave unapproved groups, emit a group-join notification/event, or expose a leave-group action. The pinned Baileys API supports the needed operation and events, but maintainers must first define a security-safe policy because WhatsApp group admission and sender authorization are separate existing concepts.

## What This Changes

Add opt-in WhatsApp handling to leave unauthorized groups, report group joins, and expose an authorized manual group-leave operation.

## Best Possible Solution

Implement one WhatsApp-plugin-owned unknown-group policy keyed to `channels.whatsapp.groups`, with explicit ignore, notify, or leave outcomes and a group-specific authorized manual leave action that shares the same account/target primitive.

- **Notification only:** Emit a sanitized owner notification for newly observed unconfigured groups but keep departure outside OpenClaw.
- **Keep filtering only:** Retain current traffic denial and document manual WhatsApp group removal as the supported membership-control path.

## Reproduction Assessment

Yes at source level: current main and `v2026.6.11` drop groups outside `channels.whatsapp.groups` and deny unauthorized senders without leaving the group, and adjacent tests assert the drop behavior. No live WhatsApp group-add scenario was run.

## Solution Assessment

No, the three independent proposed mechanisms and a `groupAllowFrom` departure trigger are not the best final design; one group-admission policy plus a shared group-specific leave authorization primitive is narrower and safer.
