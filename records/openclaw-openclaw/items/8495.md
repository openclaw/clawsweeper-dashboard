## Summary

Keep open: current main and v2026.6.11 still block or drop unauthorized WhatsApp group traffic, but they do not auto-leave unapproved groups, emit a WhatsApp group-join hook/event, or expose a WhatsApp leave-group action. The overlapping group-pairing and Telegram items are still open and do not supersede this WhatsApp-specific security feature.

## What This Changes

Request an opt-in WhatsApp security feature that auto-leaves unauthorized groups, exposes a group-join hook/event, and optionally adds a manual WhatsApp leave-group message action.

## Best Possible Solution

Keep this as a product/security-reviewed WhatsApp plugin feature: define opt-in group admission and leave semantics, add schema/docs/tests, authorize any destructive leave action per account and target, and coordinate owner notification with the broader group-pairing design.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes, from source inspection: current main and v2026.6.11 drop or block unauthorized WhatsApp group traffic without leaving, notifying, or exposing a leave action; this is a feature request rather than a broken existing contract.

## Solution Assessment

Is this the best way to solve the issue? Not yet as written: the maintainable path should first define group-admission versus sender-allowlist semantics and authorization/audit behavior for destructive leave operations, then implement the chosen WhatsApp plugin surface.
