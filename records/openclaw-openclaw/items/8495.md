## Summary

Keep open: current main still rejects unauthorized WhatsApp group traffic without leaving the group or exposing a join-specific event/action. The request is feasible in the bundled WhatsApp plugin, but the proposal conflates group admission with sender authorization, and destructive departure plus privacy-sensitive notification behavior requires explicit product and security direction.

## What This Changes

Add opt-in unauthorized-group departure, a WhatsApp group-join notification/event, and an authorized manual group-leave action.

## Best Possible Solution

Implement an optional WhatsApp-plugin-owned unknown-group policy keyed to the effective channels.whatsapp.groups admission decision, defaulting to ignore, with deterministic notify/leave choices, a minimized owner-only join event, and a separately authorized explicit leave action; do not let untrusted group content or an agent autonomously choose the security policy.

## Risks / Open Questions

- Using groupAllowFrom as the departure trigger would confuse sender authorization with group-JID admission and could make the account leave an approved group because one participant is unauthorized.
- A join notification can expose group names, participant identifiers, and inviter phone numbers to logs or agent sessions; payload minimization, redaction, and recipient authorization need an explicit contract.
- Automatic departure is destructive and may be triggered by incomplete or reordered participant events, reconnect synchronization, multi-account inheritance, or configuration mistakes, so idempotency and fresh-install/upgrade defaults need live WhatsApp proof.
