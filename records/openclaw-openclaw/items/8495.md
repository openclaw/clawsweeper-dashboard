## Summary

Keep open: neither current main nor v2026.6.11 manages unauthorized WhatsApp group membership, and no related item owns this WhatsApp-specific behavior. The pinned Baileys dependency supports the mechanics, but maintainers must define the group-identity authorization source and whether agents may receive destructive leave authority.

## What This Changes

Add opt-in WhatsApp departure from unauthorized groups, notification of group joins, and optionally a manual group-leave message action.

## Best Possible Solution

Add a bundled WhatsApp plugin policy that detects a Baileys self-add event, evaluates an explicitly approved group-JID source of truth, optionally calls `groupLeave`, and emits an owner-visible audit notification; keep a generic hook and agent leave action out of the initial scope unless separately approved with authorization contracts and real paired-account proof.
