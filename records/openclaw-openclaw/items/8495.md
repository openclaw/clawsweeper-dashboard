## Summary

Keep this issue open for a maintainer product and security decision. The supplied current discussion and related work show that WhatsApp already denies unconfigured group traffic and now gives operators a warning, but neither the merged diagnostic change nor the closed per-group sender-authorization proposal implements leaving a group, a group-join event, or a WhatsApp leave action. The broader cross-channel pairing proposal remains open and overlaps, but does not yet own this WhatsApp-specific membership policy.

## What This Changes

Add an opt-in WhatsApp policy for newly added unapproved groups, with a possible automatic leave, owner notification/event, or manual leave action.

## System Context

The bundled WhatsApp plugin receives group traffic, applies group admission and sender authorization before agent execution, then either drops the traffic or passes it to the reply flow. This request would add a deliberate membership-management response after a group is rejected, affecting both the connected WhatsApp account and operator visibility.

## Architecture Diagram

flowchart LR

  B --> C[Group admission policy]
  C -->|Approved group| D[Agent reply flow]
  C -->|Unconfigured group| E[Drop and operator diagnostic]
  E --> F[Proposed opt-in membership action]
  F --> G[Leave group or notify owner]

## Best Possible Solution

Define one WhatsApp-plugin-owned, opt-in unknown-group action tied to `channels.whatsapp.groups` admission, disabled by default; initially limit it to a narrow leave-or-notify policy with documented authorization, focused tests, and a real paired-account group-add proof, while coordinating any reusable pairing event with the broader proposal.
