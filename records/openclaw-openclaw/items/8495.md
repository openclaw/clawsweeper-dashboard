## Summary

Keep open: current main and the latest release still block or drop unauthorized WhatsApp group traffic, but they do not leave unapproved groups, emit a WhatsApp group-join hook/event, or expose a WhatsApp group-leave message action. The related group-pairing, Telegram, and per-group sender-allowlist items overlap but do not supersede this WhatsApp-specific security feature.

## What This Changes

The issue requests opt-in WhatsApp behavior to leave unauthorized groups, expose a group-join hook/event, and possibly add a manual WhatsApp leave action.

## Best Possible Solution

Keep this open for a product/security-reviewed WhatsApp plugin design that separates group admission from sender allowlists, adds opt-in auto-leave and owner notification semantics, and exposes any leave action only after authorization and audit behavior are defined.

## Reproduction Assessment

Yes, from source inspection: current main and v2026.6.11 block or drop unauthorized WhatsApp group traffic without leaving, notifying, or exposing a leave action. This is a feature request rather than a broken existing behavior reproduction.

## Solution Assessment

No current implementation is best yet. The maintainable path should distinguish chat-level group admission from sender allowlists and design destructive leave authorization plus owner notification before adding config, hooks, or message actions.
