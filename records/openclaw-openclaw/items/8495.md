## Summary

Keep open for maintainer product and security direction. This is a WhatsApp-specific capability request, not an established-behavior bug: the supplied prior source review found that denied groups are skipped rather than left, while the requested destructive membership action, join-event privacy contract, and message-tool semantics remain unresolved. The active broader group-pairing proposal overlaps but does not replace this request.

## What This Changes

Add an opt-in WhatsApp policy for unauthorized groups to leave automatically, notify the owner through a join event, or allow an authorized manual leave action.

## System Context

The bundled WhatsApp plugin receives group messages, resolves group and sender admission rules from channel configuration, and then either drops or forwards traffic into the agent runtime. This request would extend that preflight boundary from passive denial into membership-changing actions and owner-facing event delivery.

## Architecture Diagram

flowchart LR
  A[WhatsApp group update or message] --> B[WhatsApp plugin]
  B --> C[Group and sender admission policy]
  C -->|approved| D[Agent session]
  C -->|denied today| E[Drop and diagnostic log]
  C -->|proposed opt-in| F[Leave group or notify owner]
  F --> G[Authorized operator action]

## Best Possible Solution

Define one opt-in WhatsApp owner-plugin policy that separates admission denial from a verified leave operation, specifies privacy-safe owner notification, and reuses a typed authorized action rather than adding an ambiguous hook or raw message action; then implement it with live WhatsApp group-add proof and focused compatibility tests.
