## Summary

Keep open: current main and v2026.6.11 still block or drop unauthorized WhatsApp group traffic, but they do not auto-leave unapproved groups, emit a WhatsApp group-join hook/event, or expose a WhatsApp leave-group action. The related group-pairing, Telegram, and per-group WhatsApp allowlist items overlap but do not supersede this WhatsApp-specific security feature.

## What This Changes

Request to add WhatsApp unauthorized-group auto-leave, a group-join hook/event, and a manual leave action for allowlist-based deployments.

## Best Possible Solution

Define a product/security-reviewed WhatsApp plugin contract that separates group admission from sender authorization, adds opt-in schema/docs/tests, authorizes any destructive leave action per account and target, and coordinates owner notification with the broader group-pairing design.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 drop or block unauthorized WhatsApp group traffic without leaving the group, notifying the owner, or exposing a leave action. This is a missing feature rather than a broken existing-behavior bug reproduction.

## Solution Assessment

Not yet as written: the maintainable path should define group-admission versus sender-allowlist semantics and authorization/audit behavior for destructive leave operations before implementation. A direct groupAllowFrom-driven auto-leave would be too risky without that contract.
