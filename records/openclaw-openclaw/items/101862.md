## Summary

Keep open: current main protects the explicit `yielded: true` path, but the reported live runs and source fallback still make the required-completion blocked finalization path credible when that marker is lost or races.

## What This Changes

The issue reports that a required-completion `sessions_spawn(mode:"run")` child that first ends via `sessions_yield` can finalize its task as blocked before its real final reply is produced.

## Best Possible Solution

Keep this open and harden the subagent lifecycle so a required-completion run that ended by `sessions_yield` cannot finalize until its resumed run produces the real final assistant reply.
