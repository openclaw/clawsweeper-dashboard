## Summary

Keep open: current main has explicit protection when a terminal event carries `yielded: true`, but the required-completion path still produces the reported blocked terminal state if the yield marker is absent or loses the race. The reporter’s release evidence and the source fallback are credible, but the exact live loss site still needs maintainer/live-repro review before an automated fix branch.

## What This Changes

The issue reports that a required-completion spawned run ending its first turn with `sessions_yield` can be finalized as blocked before its later real final reply is announced.

## Best Possible Solution

Keep this issue open and, after live current-main proof or maintainer acceptance of the source-level evidence, harden required-completion subagent finalization so a first-turn `sessions_yield` cannot publish a blocked task result before the resumed run’s real final deliverable is captured.
