## Label Justifications

- `P1`: Incorrect context saturation can trigger premature compaction and degrade active agent sessions for users of providers or proxies with incomplete usage payloads.
- `impact:session-state`: The issue concerns stale or misclassified token metadata that affects context state, status reporting, and compaction decisions.
- `impact:ux-friction`: Users receive alarming false context-full indications and must inspect session files manually to determine actual usage.

## Summary

The report remains necessary: current session persistence can retain a model-limit value in `contextTokens` while usage freshness is absent, and two open pull requests currently compete to fix the same source-backed bug.

## What This Changes

Prevent session metadata and status surfaces from presenting a configured model context window as fresh context usage when the provider supplies no usable usage snapshot.

## Best Possible Solution

Select one canonical pull request that preserves the last valid session value—or leaves usage unknown—unless a fresh usage or compaction snapshot exists, and retain focused regression coverage for both stale-usage and model-only update paths.
