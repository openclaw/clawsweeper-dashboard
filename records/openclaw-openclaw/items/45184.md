## Label Justifications

- `P2`: The issue affects Matrix multi-account message dispatch in a bounded channel-specific path and needs normal maintainer prioritization.
- `impact:message-loss`: Messages explicitly aimed at one configured Matrix account can currently be dispatched by other accounts or burn a turn before being suppressed, which is a channel delivery/routing problem.

## Summary

Keep open: current main still has no Matrix opt-in gate that drops ambient room dispatch when a human message explicitly mentions a different configured Matrix account, and the remaining behavior is a channel/config product decision rather than a stale or already-implemented bug fix.

## What This Changes

Request an opt-in Matrix room policy that skips dispatch for non-mentioned accounts when a message explicitly mentions a different configured Matrix bot account.

## Best Possible Solution

Define a Matrix-owned, opt-in sibling-mention dispatch policy at the plugin boundary, add schema/types/docs, and cover the handler path before typing and LLM dispatch while preserving existing ambient-room behavior by default.

## Reproduction Assessment

Yes, as a source-level reproduction of the missing capability. A human room message that mentions Bot A while Bot B has `requireMention: false` is not filtered by the current Matrix handler because mention resolution is scoped to Bot B and the only other mention gate applies to configured bot senders.

## Solution Assessment

Unclear until maintainers choose the config shape. A narrow Matrix plugin gate before typing and dispatch is likely the right layer, but adding it as a new default or broad AI participation system would be too compatibility-sensitive without product approval.
