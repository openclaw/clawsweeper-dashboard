## Summary

Keep open: current main and v2026.6.11 still lack an opt-in Matrix gate that drops ambient room dispatch when a human message explicitly targets another configured Matrix account; the existing Matrix `allowBots` path only gates configured-bot senders.

## What This Changes

The issue requests an opt-in Matrix dispatch policy that skips non-mentioned Matrix bot accounts when a room message explicitly mentions a different configured account.

## Best Possible Solution

Add a Matrix-owned, default-off equivalent to `ignoreOtherMentions` for configured sibling-account targets, with schema/types/docs and handler tests, or explicitly document that Matrix ambient rooms intentionally keep dispatching on other-target mentions.

## Reproduction Assessment

Yes, source-level: current Matrix code dispatches unconfigured human room messages when `requireMention` is false and only reports whether the current bot was mentioned. I did not run a live Matrix room, but the handler, resolver, docs, release tag, and tests make the gap reproducible from source.

## Solution Assessment

Unclear: an opt-in Matrix-owned gate is plausible and matches existing Discord precedent, but the exact config name, default, and target-detection scope need maintainer product direction first.
