## Summary

Keep open: current main and v2026.6.11 still lack a Matrix gate that skips dispatch when a human room message explicitly mentions a different configured Matrix account while this bot does not require a mention. The source gap is real, but adding it is a Matrix channel config and routing product decision rather than a strict bug fix.

## What This Changes

Request an opt-in Matrix dispatch gate that skips non-mentioned bot accounts when a room message explicitly mentions a different configured bot account.

## Best Possible Solution

Add a Matrix-owned, opt-in pre-dispatch other-mention gate with unchanged defaults, typed config/schema/docs/tests, pending-history behavior, and an explicit decision about how it interacts with sibling Matrix mention rendering.

Options:

- **Fold into broader routing policy:** Defer this issue until a shared multi-bot routing policy covers Matrix, Discord, Slack, reply targets, and default owners consistently.
- **Keep current Matrix controls only:** Leave users on requireMention/allowBots/systemPrompt workarounds and document that Matrix has no non-mentioned-account suppression mode.

## Reproduction Assessment

Yes, at source level: configure two Matrix accounts in one room, set the non-target account's room requireMention to false, and send a human Matrix message whose m.mentions targets the other configured account. Current handler code only asks whether the current bot was mentioned, so the non-target bot can proceed to dispatch.

## Solution Assessment

Unclear until maintainers choose the Matrix product shape. The Slack/Discord ignoreOtherMentions pattern looks like the narrowest precedent, but Matrix needs an explicit decision for m.mentions, configured-account roster lookup, and pending-history behavior.
