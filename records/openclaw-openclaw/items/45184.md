## Summary

Keep open: current main and v2026.6.11 still only determine whether this Matrix account was mentioned and do not suppress `requireMention: false` dispatch when a human message explicitly targets a different configured Matrix account; the remaining work is a compatibility-sensitive Matrix config decision.

## What This Changes

Add an opt-in Matrix dispatch gate so non-mentioned Matrix accounts skip ambient room messages that explicitly mention another configured account.

## Best Possible Solution

Add a Matrix-owned, default-off `ignoreOtherMentions`-style per-account/per-room gate before typing and LLM dispatch, preserve skipped messages as pending context where appropriate, and document/test unchanged default behavior.

## Reproduction Assessment

Yes, source-reproducible: Matrix currently resolves mentions for `selfUserId` only, then only mention-gates when `requireMention` is true. In a `requireMention: false` room, there is no current-main branch that drops a human message whose `m.mentions.user_ids` targets a sibling configured account instead.

## Solution Assessment

Unclear until maintainers choose the API contract. A narrow default-off Matrix gate aligned with Slack/Discord is likely the cleanest layer; the closed broad participation PR is not a safe canonical fix.
