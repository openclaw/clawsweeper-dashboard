## Summary

Keep open: current main and v2026.6.11 still only decide whether the current Matrix account was mentioned; they do not provide an opt-in Matrix gate that skips ambient dispatch when a human room message explicitly mentions a different configured bot account.

## What This Changes

Request an opt-in Matrix policy that skips dispatch for ambient room messages explicitly mentioning a different configured bot account.

## Best Possible Solution

Add a Matrix-owned, default-off sibling-mention suppression policy before typing and LLM dispatch, with schema/types/docs/tests and a tightly defined configured-account target scope.

## Reproduction Assessment

Yes, as a source-level reproduction of the missing capability. A human room message that mentions Bot A while Bot B has `requireMention: false` is not filtered by the current Matrix handler because mention resolution is scoped to Bot B and the only other mention gate applies to configured bot senders.

## Solution Assessment

Unclear: an opt-in Matrix-owned gate is plausible and has channel precedent, but maintainers still need to choose the exact config name, target scope, and default behavior before implementation.
