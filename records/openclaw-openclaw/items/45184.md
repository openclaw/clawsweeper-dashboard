## Summary

Keep open: current `main` and v2026.6.11 still lack a Matrix gate that skips dispatch when a human room message explicitly mentions a different configured Matrix account, and the remaining work needs a Matrix config/product decision.

## What This Changes

Request an opt-in Matrix dispatch-suppression policy for messages that explicitly mention another configured OpenClaw bot account.

## Best Possible Solution

Add a Matrix-owned, default-off other-mention dispatch gate before typing and LLM dispatch, with schema/docs alignment, handler tests, and proof that current ambient-room behavior remains the default.

Yes. Source inspection shows Matrix resolves whether the current account was mentioned and, when `requireMention` is false, proceeds toward dispatch with no filter for explicit mentions of another configured account.

## Solution Assessment

Unclear until maintainers choose the config shape. A narrow Matrix plugin gate before typing and dispatch is the likely right layer; the closed broad Matrix participation PR was too large and is not a viable current fix.
