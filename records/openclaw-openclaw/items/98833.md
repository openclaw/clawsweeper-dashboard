## Summary

Keep this PR open: it is a focused MS Teams security/availability hardening patch and current main still has the two raw Graph JSON reads, but the branch still needs real or loopback behavior proof for the 256 KiB cap before merge.

## What This Changes

The PR changes `extensions/msteams/src/attachments/graph.ts` to read the MS Teams Graph hostedContents collection and main message JSON through `readResponseWithLimit` with a 256 KiB cap.

## Best Possible Solution

Land the bounded-reader fix after a maintainer accepts the 256 KiB cap and mixed overflow behavior, with redacted live or loopback proof plus focused oversized-response regression coverage for both changed reads.

## Reproduction Assessment

Yes, source-level: current main still uses native `response.json()` for both the hostedContents collection and main Graph message reads. I did not run a streaming reproduction because this review is read-only.

## Solution Assessment

Mostly yes: the MS Teams plugin is the right owner boundary and the shared bounded reader is the right primitive. It is not merge-ready until the 256 KiB cap and overflow behavior are proven against normal and oversized responses.
