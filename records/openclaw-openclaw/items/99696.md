## Label Justifications

- `P1`: The issue describes active CLI session-resume churn that breaks continuity and warm-up reuse in a common group-chat workflow.
- `impact:session-state`: The affected behavior is CLI session binding reuse and continuity across turns.

## Summary

Keep open: current main still lets current-message mention state and conditional group-intro text reach the CLI session-stable `extraSystemPromptHash`, so the reported session-reuse churn remains source-reproducible. The protected `maintainer` label also requires explicit maintainer handling rather than cleanup close or autonomous repair routing.

## What This Changes

The issue reports CLI session binding churn when group turns toggle between explicitly mentioning the bot and not mentioning it, because per-turn group prompt facts are included in `extraSystemPromptStatic`.

## Best Possible Solution

Keep the issue open and fix the prompt boundary: move explicit-mention guidance into per-turn inbound context, make group-intro handling stable or excluded from binding facts, and add a regression proving `extraSystemPromptHash` stays stable across mention, no-mention, and mention turns.

## Reproduction Assessment

Yes, at source level. Current main still lets `ExplicitlyMentionedBot` change `groupChatContext`, includes that context in `extraSystemPromptStatic`, hashes it as `extraSystemPromptHash`, and invalidates CLI reuse when the hash changes.

## Solution Assessment

Yes, the requested direction is the narrow maintainable fix: keep per-message mention facts in per-turn inbound context and keep `cliSessionBindingFacts` limited to session-stable text. The group-intro piece should be handled with a clear stable/excluded contract rather than left conditional inside the binding hash.
