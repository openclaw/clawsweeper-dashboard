## Summary

Keep open: current main and the latest release still let explicit mention state change the static CLI session prompt hash, and the protected `maintainer` label means this should stay with explicit maintainer handling rather than cleanup closure or unattended repair.

## What This Changes

The issue requests keeping CLI session binding facts stable when group messages toggle explicit bot mention state.

## Best Possible Solution

Move explicit mention notice to per-turn inbound context, keep `extraSystemPromptStatic` stable across mention toggles, and coordinate the separate groupIntro hash drift with the canonical false-invalidation tracker.

## Reproduction Assessment

Yes at source level: current main still appends explicit mention guidance inside group context and includes that context in the static CLI binding prompt hash. I did not run a live Telegram/claude-cli reproduction in this read-only review.

## Solution Assessment

Yes directionally: per-message mention state belongs in per-turn inbound context or another non-binding prompt path, not in session-stable CLI binding facts. The groupIntro piece should be fixed separately or coordinated with the existing canonical tracker.
