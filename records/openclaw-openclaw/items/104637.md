## Summary

The active launchd handoff is well-targeted and strongly proven, but its new caller trusts a synchronous success result that does not cover Node’s asynchronous child-spawn failure contract, so the gateway can still exit without an established relaunch helper.

## What This Changes

The PR adds a PID-gated launchd restart handoff that yields to a healthy KeepAlive replacement and kickstarts only when no live replacement appears.

## Best Possible Solution

Require a valid detached-child PID before reporting successful scheduling, attach safe child-error handling, and preserve the existing in-process restart fallback whenever the handoff was not established.
