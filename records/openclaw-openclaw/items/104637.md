## Label Justifications

- `merge-risk: 🚨 availability`: A stopped launchd service can be misclassified as a healthy replacement, suppressing the only scheduled recovery path.

## Summary

The revised head resolves the earlier healthy-replacement race, but it can still treat a stopped launchd job as successfully relaunched and skip recovery, so it is not safe to merge yet.

## What This Changes

The PR adds a PID-gated launchd restart handoff to supervised gateway restarts and expands focused process-respawn tests.

## Best Possible Solution

Yield only when launchd reports a genuinely running replacement, require any parsed PID to be greater than one, and directly test that zero or absent PIDs execute the established enable/kickstart/bootstrap recovery.
