## Summary

The PR addresses a real P0 gateway outage and its current head fixes the prior test-mock typing finding, but the original P1 availability blocker remains: the automatic supervisor path uses explicit `kickstart -k`, which can kill a healthy replacement that launchd already started after the old PID exits.

## What This Changes

The PR changes launchd-supervised gateway restarts to schedule a detached `kickstart` handoff before exit and adds regression tests for launchd detection and handoff scheduling failure.

## Best Possible Solution

Use the existing `start-after-exit` ensure-running mode with `waitForPid`, preserve the scheduling-failure in-process fallback, and prove both inert-KeepAlive recovery and healthy-KeepAlive preservation.
