## Label Justifications

- `P1`: The PR addresses an active runaway agent-loop regression that can continue provider calls for hours after a safety block.
- `merge-risk: 🚨 session-state`: The new stop point changes run termination ordering relative to queued steering/follow-up state without a settled recovery contract.
- `merge-risk: 🚨 message-delivery`: Already accepted user input may be stranded, replayed later, or discarded depending on unresolved queue semantics and runtime wiring.

## Summary

The dual-layer termination mechanism is appropriate, but the branch still wires mixed-batch stopping into a sibling session factory instead of the embedded production Agent used for user runs. The prior P1 remains, and accepted queued-input behavior still needs an explicit owner decision.

## What This Changes

The PR marks critical tool-loop veto results as terminating, adds an agent-core post-turn stop hook for mixed batches, wires that hook into one session factory, and adds regression tests, docs, and a standalone terminal proof script.

## Best Possible Solution

Use one typed critical-veto predicate at the shared production Agent boundary, preserve accepted queued input through a clearly defined next-run recovery path, and prove the embedded runtime completes sibling tools without making a second provider request.
