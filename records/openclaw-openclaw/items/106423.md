## Label Justifications

- `P1`: Critical loop detection can otherwise leave real agent workflows issuing provider turns and consuming resources for hours.
- `merge-risk: 🚨 session-state`: The PR changes when a run reaches agent_end and bypasses queued-message polling after a critical veto, making terminal transcript and queued-input behavior merge-sensitive.

## Summary

Keep this PR open, but do not merge it yet: the built-in PI path is plausibly repaired, while the documented Copilot runtime shares the loop-detection wrapper but owns a separate low-level loop that this PI-only stop hook does not terminate; the supplied validation also remains test/direct-invocation proof rather than a real runtime demonstration.

## What This Changes

The PR marks critical tool-loop veto results as terminating, adds a post-turn stop hook for mixed PI tool batches, expands regression coverage, and documents critical-veto termination.

## Best Possible Solution

Carry a portable critical-veto stop signal through every runtime that uses the shared loop detector, or explicitly scope the behavior and documentation to PI with a canonical follow-up for other harnesses; then prove a mixed real run completes the normal sibling, records the veto, emits a coherent terminal outcome, and makes no next provider request.
