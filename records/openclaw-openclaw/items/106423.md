## Summary

Keep this PR open, but do not merge yet: the prior P1 remains because the reported safety behavior is presented as runtime-wide while the patch and proof cover only the agent-core session path; pending-message loss also needs explicit maintainer acceptance or repair.

## What This Changes

The PR makes critical tool-loop veto results terminating and adds a post-turn hook so mixed tool-call batches finish ordinary sibling tools but stop before another provider turn.

## Best Possible Solution

Define one critical-loop terminal outcome at the shared tool/harness boundary, consume it in every supported runtime while allowing ordinary sibling tools to finish, and preserve or explicitly transfer queued user input before documenting universal termination.
