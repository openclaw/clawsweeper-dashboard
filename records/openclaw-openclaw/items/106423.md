## Summary

Keep open: the underlying runaway-loop bug is valid, but this head still does not terminate every production runtime receiving the shared critical veto, and it intentionally discards accepted queued input without maintainer-approved session semantics.

## What This Changes

The PR marks critical tool-loop veto results as terminating, adds a post-turn agent-core stop hook for mixed batches, wires that hook into one session factory, and adds tests, documentation, and a standalone proof script.

## Best Possible Solution

Use one canonical runtime-owned critical-veto outcome across every affected agent harness: finish already-started sibling tools, stop further provider turns, preserve accepted steering/follow-up input for a fresh turn, and prove the composed production session path with redacted live runtime output.
