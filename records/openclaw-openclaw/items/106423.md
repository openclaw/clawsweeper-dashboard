## Label Justifications

- `P1`: The underlying agent workflow can continue making model requests and consuming resources for hours after its critical loop breaker fires.

## Summary

Keep this PR open for revision: the proposed flag follows a real Pi agent-core contract, but that contract terminates only when every result in the tool batch is terminating, so the reported runaway remains possible when a critical loop veto shares a batch with any normal tool result.

## What This Changes

The PR adds `terminate: true` to critical tool-loop blocked results, adds focused and end-to-end assertions, and documents critical loop blocks as terminating the agent run.

## Best Possible Solution

Stop the completed turn whenever any finalized result is a critical `tool-loop` veto—using Pi's post-turn stop hook or an equivalent run-owned latch—and cover both single-call and mixed blocked/nonblocked batches.

Required: false

## Reproduction Assessment

Yes at source level: an assistant response containing one critical loop-blocked tool and one normal tool produces a mixed batch that Pi does not terminate, causing another model turn.

## Solution Assessment

No; setting the flag on only the blocked result is insufficient under Pi's all-results termination rule, while a post-turn stop decision correctly handles every batch shape.
