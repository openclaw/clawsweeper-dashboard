## Summary

This remains a valid performance/product request rather than a duplicate of the closed acceleration-observability work. Current main already prefers configured provider transcription and a ready CPU `sherpa-onnx-offline` fallback before Python Whisper, but it still falls back to Python Whisper `turbo` when no faster ready backend exists; selecting, packaging, or downloading a different default requires an explicit quality, privacy, and setup decision.

## What This Changes

Request a faster default inbound speech-to-text path for CPU-only hosts so short Telegram media does not wait behind slow local Whisper transcription.

## System Context

Inbound media understanding prepares Telegram and other channel attachments before agent routing. It selects a configured provider or local transcription CLI, writes the resulting transcript into the message body, then hands the enriched message to command parsing and the agent reply flow.
