## Summary

Keep open: current main and v2026.6.11 still expose WhatsApp outbound `react` plus approval-specific reaction handling, but not the generic WhatsApp `message reactions` query, historical reaction retrieval, or ordinary reaction add/remove event exposure. The related open hook issue covers only a narrower slice, and the related implementation PRs are closed unmerged.

## What This Changes

Request to add WhatsApp support for querying, storing, or otherwise surfacing message reactions so agents can use reaction feedback.

## Best Possible Solution

Define a privacy-gated WhatsApp reaction read/event contract, then implement the generic `reactions` action, reaction persistence or provider retrieval, plugin/agent event exposure, focused tests, docs, and live WhatsApp proof inside the WhatsApp plugin boundary.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should WhatsApp reaction support be implemented as a complete read/event contract with generic `message reactions` queries and persistence, as a narrower plugin hook-only surface, or as live system-event delivery without historical querying?

Rationale: The issue is valid, but the implementation shape affects public action semantics, stored reaction data, hook payload privacy, access-control gating, and whether reactions become visible to agents or only plugins.

Likely owner: vincentkoc

Owner reason: This decision is closest to the existing WhatsApp hook contract surface they authored, while still needing input from adjacent reaction and approval owners.

Owner confidence: medium

Options:

- **Complete Read/Event Contract (recommended):** Define one WhatsApp-owned contract covering `message reactions`, historical or persisted reaction data, ordinary add/remove events, privacy gates, docs, and live proof.
- **Hook-Only First:** Implement only a `reaction_received`/`reaction_removed` plugin hook first, leaving generic CLI/action querying and historical retrieval tracked here or in a follow-up.
- **Defer Broad Exposure:** Keep WhatsApp reactions limited to outbound and approval-specific flows until maintainers are ready to expose reaction data more broadly.

## Reproduction Assessment

Yes, at source level: current WhatsApp action discovery and dispatch omit the generic `reactions` action, and ordinary reaction events are not exposed beyond approval-target handling. I did not run a live WhatsApp account in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public reaction read model. The maintainable path should settle query, persistence, hook, privacy, access-control, and agent-visibility semantics before surfacing reactions broadly.
