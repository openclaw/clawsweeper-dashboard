## Summary

Keep open. Current main and v2026.7.1 still lack WhatsApp reaction listing, inbound reaction handling, and historical reaction storage; the remaining work requires a maintainer-defined privacy, routing, retention, and agent-turn contract rather than another partial event-only implementation. ([github.com](https://github.com/openclaw/openclaw/blob/main/extensions/whatsapp/src/channel.ts))

## What This Changes

Request WhatsApp support for listing, storing, and surfacing inbound and historical message reactions.

## Best Possible Solution

Define one WhatsApp-owned add/remove reaction envelope, pass it through existing authorization and plugin-hook privacy gates, persist a bounded canonical SQLite index only if maintainers approve historical retention, and implement the generic `reactions` action against that store without automatically triggering agent turns.

Options:

- **Events plus bounded history (recommended):** Emit privacy-gated passive add/remove events and maintain a bounded SQLite reaction index for generic queries without waking agents by default.
- **Passive hooks only:** Implement the narrower contract tracked at https://github.com/openclaw/openclaw/issues/79996 and leave historical queries separately open.
- **Agent-visible events only:** Route reactions into agent sessions without creating a plugin hook or durable historical query surface.
