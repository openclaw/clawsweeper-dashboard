## Summary

Current source still has the same central gap: WhatsApp advertises and handles outbound `react`, and approval reactions are read for approval resolution, but the generic `reactions` query and ordinary reaction event/history path are absent. The linked implementation PRs are now closed unmerged, so there is no safe merged candidate to close against.

## What This Changes

The issue requests WhatsApp support for querying, storing, and surfacing message reactions so agents can use emoji feedback.

## Best Possible Solution

Define a privacy-gated WhatsApp reaction read/event model, then implement the generic `reactions` action, persistence or provider retrieval, and observation hooks inside the official WhatsApp plugin with focused tests, docs, and live proof.

## Reproduction Assessment

Yes, at source level: WhatsApp action discovery and dispatch still omit the generic `reactions` action, and ordinary reaction events are not exposed beyond approval-target handling. No live WhatsApp account was exercised in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public reaction read model. A maintainable fix should settle query, persistence, hook, privacy, access-control, and agent-turn semantics before exposing reactions broadly.
