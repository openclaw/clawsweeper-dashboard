## Summary

Keep open. Current main consumes WhatsApp reactions only for narrowly registered approval prompts; it still does not expose the generic reaction-list action, ordinary add/remove events, or historical reaction retrieval. The channel-owned socket provides a viable implementation seam, but maintainers must first choose the public event, privacy, session, and persistence contract.

## What This Changes

Add WhatsApp support for listing message reactions, observing reaction add/remove events, and retrieving historical reaction state.

## Best Possible Solution

Define one channel-owned reaction event model with authorized add/remove delivery, then expose generic reaction listing from a canonical SQLite-backed state store only if maintainers approve its retention and completeness semantics; keep agent-turn triggering separately opt-in under https://github.com/openclaw/openclaw/issues/17840.

## Reproduction Assessment

Yes at source level: current main advertises and handles outbound react but not generic reactions listing, and current inbound coverage is limited to registered approval reactions. No live WhatsApp account was exercised during this read-only review.

## Solution Assessment

Unclear until maintainers select the contract. Adding direct historical storage immediately is not yet the best proven path; a channel-owned passive event seam followed by explicitly designed SQLite persistence is safer and avoids coupling ordinary reactions to agent turns.
