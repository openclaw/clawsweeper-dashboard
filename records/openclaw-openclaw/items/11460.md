## What This Changes

Add a WhatsApp reaction read capability so agents or tools can observe incoming reactions and, if supported, retrieve reaction history for a message.

## System Context

The bundled WhatsApp plugin converts Baileys socket activity into OpenClaw channel messages and message actions. Reaction data would need to travel from WhatsApp inbound events through the channel’s access and routing boundary into a safe agent-, hook-, or query-facing representation.

## Architecture Diagram

flowchart LR
  A[WhatsApp user reaction] --> B[Baileys socket event]
  B --> C[WhatsApp plugin inbound monitor]
  C --> D{Approved reaction contract}
  D --> E[Passive plugin hook or event]
  D --> F[Durable reaction store]
  F --> G[Scoped message query]
  E --> H[Agent automation without forced turn]

## Best Possible Solution

Define one bundled-WhatsApp reaction contract: emit scoped passive add/remove events first, then add durable SQLite-backed history and a `reactions` query only if maintainers approve the retention, access-control, and upgrade semantics.

- **Keep outbound-only reactions:** Retain the present send-only behavior if maintainers do not want reaction feedback as a supported WhatsApp surface.
