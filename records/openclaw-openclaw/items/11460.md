## Summary

Keep open. Current main still lacks the general WhatsApp reaction-read capability: WhatsApp advertises and dispatches outbound `react`, but not the generic reaction-list action or a historical reaction index. The closed implementation PRs covered only parts of the request and did not establish a safe canonical event, routing, privacy, retention, and persistence contract.

## What This Changes

Add WhatsApp support for receiving, storing, and querying message reactions, including historical reaction state where feasible.

## Best Possible Solution

Implement a plugin-owned, access-controlled reaction event contract and SQLite-backed observed-reaction index, expose it through the generic reaction-list action, and keep reaction-triggered agent turns in the separate opt-in design tracked at https://github.com/openclaw/openclaw/issues/17840.

- **Ship hook-only observation:** Limit this issue to a plugin reaction hook through https://github.com/openclaw/openclaw/issues/79996 and track historical storage and querying separately.
- **Keep outbound-only scope:** Retain the current outbound and approval-specific behavior and document that arbitrary WhatsApp reaction history is unsupported.

## Solution Assessment

No single proposal in the issue is yet the best complete fix; the maintainable path is an owner-plugin event and SQLite persistence contract first, followed by generic querying without automatically waking an agent.
