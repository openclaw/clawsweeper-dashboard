## Summary

Keep open: current main and v2026.6.11 still support outbound WhatsApp `react` and approval-specific reaction handling, but not generic WhatsApp reaction queries, historical reaction retrieval, or ordinary reaction event exposure.

## What This Changes

The issue requests WhatsApp support for reading/querying message reactions, exposing inbound reaction events, and retrieving historical reaction signals for agents.

## Best Possible Solution

Define a privacy-gated WhatsApp reaction read/event contract, then implement the generic `reactions` action, reaction persistence or retrieval, plugin/agent event exposure, focused tests, docs, and live WhatsApp proof inside the WhatsApp plugin boundary.

## Reproduction Assessment

Yes, at source level: WhatsApp action discovery, dispatch, runtime handling, docs, hook catalog, and inbound monitor paths still omit general reaction query/event support. No live WhatsApp account was exercised in this read-only review.

## Solution Assessment

Unclear until maintainers choose the reaction read model. A maintainable fix needs query, persistence/history, hook/event exposure, privacy, and access-control semantics rather than only surfacing one event path.
