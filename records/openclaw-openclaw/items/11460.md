## Summary

Keep this issue open: current behavior still lacks a general WhatsApp reaction-read/query contract, historical retrieval, and a supported passive reaction-event surface; the remaining design needs maintainer decisions on authority, retention, privacy, routing, and whether reactions may trigger agent work.

## What This Changes

The issue requests WhatsApp support for querying message reactions, retaining historical reactions, and exposing inbound reaction feedback to agents.

## Best Possible Solution

Define one bundled WhatsApp-plugin contract that separates passive reaction observation from historical querying, uses an authoritative stored/read source, applies existing channel access controls, represents removals, and makes agent turns opt-in rather than implicit.

No—the earlier proposals address only parts of the request. A maintainer-approved split between passive events and authoritative historical querying is safer than routing every reaction directly into an agent session.
