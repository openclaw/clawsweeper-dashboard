## Summary

Keep open: current `main` and the latest release still support WhatsApp outbound `react` plus approval/status reaction plumbing, but not the generic `message reactions` query, historical reaction retrieval, or ordinary reaction-event exposure requested here.

## What This Changes

The issue requests WhatsApp support for listing/querying message reactions and making reaction events/history available to agents or plugins.

## Best Possible Solution

Define a privacy-gated WhatsApp reaction read model, then implement the generic `reactions` action, reaction persistence or retrieval, and observation hooks inside the WhatsApp plugin with focused tests, docs, and live proof.

## Reproduction Assessment

Yes. Source inspection shows `openclaw message reactions --channel whatsapp` still routes to a plugin action that WhatsApp does not advertise or support, while ordinary inbound reaction events are only handled for approval targets.

## Solution Assessment

Unclear until maintainers choose the public reaction read model. A maintainable fix should define query, persistence/history, hook, privacy, access-control, and agent-turn semantics before surfacing reactions broadly.
