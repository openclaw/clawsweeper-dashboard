## Summary

Keep open: current main and v2026.6.11 still support WhatsApp outbound `react` and approval-specific reaction handling, but not generic WhatsApp reaction queries, historical reaction retrieval, or ordinary reaction add/remove event exposure; related implementation PRs are closed unmerged and narrower hook/wake issues do not replace this broader tracker.

## What This Changes

Request to add WhatsApp support for querying message reactions, retrieving historical reaction data, and exposing reaction events to agents or plugins.

## Best Possible Solution

Define a privacy-gated WhatsApp reaction read/event contract, then implement generic `reactions` action support, reaction persistence or provider retrieval, plugin/agent event exposure, focused WhatsApp tests, docs, and live WhatsApp proof inside the plugin boundary.

Options:

- **Complete Read/Event Contract (recommended):** Define one WhatsApp-owned contract covering `message reactions`, historical or persisted reaction data, ordinary add/remove events, privacy gates, docs, and live proof.
- **Hook-Only First:** Implement only a `reaction_received`/`reaction_removed` plugin hook first and leave generic CLI/action querying plus historical retrieval tracked separately.
- **Defer Broad Exposure:** Keep WhatsApp reactions limited to outbound and approval-specific flows until maintainers are ready to expose reaction data more broadly.

## Solution Assessment
