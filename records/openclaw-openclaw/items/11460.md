## Summary

Keep open: current main still supports WhatsApp outbound `react` and approval-specific reaction handling, but it does not implement the requested generic WhatsApp reaction query/history/event surface; the related implementation PRs are closed unmerged and the remaining open hook issue is narrower.

## What This Changes

Add a WhatsApp reaction read/query path so CLI, agents, or plugins can access message reactions and related reaction events where feasible.

## Best Possible Solution

Define a privacy-gated WhatsApp reaction read/event contract, then implement generic `reactions` support, persistence or retrieval, hook/agent exposure, focused tests, docs, and live WhatsApp proof inside the WhatsApp plugin boundary.
