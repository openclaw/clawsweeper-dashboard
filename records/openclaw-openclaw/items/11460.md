## Summary

Keep open: current main and v2026.6.11 still only support outbound WhatsApp reaction sends plus approval-specific reaction handling, while generic reaction queries, historical retrieval, and ordinary add/remove reaction event exposure remain missing.

## What This Changes

Add WhatsApp support for listing/querying message reactions, exposing reaction events, and retrieving historical reaction feedback for agents or plugins.

## Best Possible Solution

Define a privacy-gated WhatsApp reaction read/event contract, then implement generic `reactions` action support, reaction persistence or provider retrieval, plugin/agent event exposure, focused tests, docs, and live WhatsApp proof inside the plugin boundary.

- **Hook-Only First:** Implement only a `reaction_received`/`reaction_removed` plugin hook first and leave generic CLI/action querying plus historical retrieval tracked separately.
- **Defer Broad Exposure:** Keep WhatsApp reactions limited to outbound and approval-specific flows until maintainers are ready to expose reaction data more broadly.

Yes, at source level: current WhatsApp action discovery and dispatch omit the generic `reactions` action, and ordinary reaction events are not exposed beyond approval-target handling. I did not run a live WhatsApp account in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public reaction read model. The maintainable path should settle query, persistence or provider retrieval, hook privacy gates, access control, and agent visibility before implementation.
