Keep open: WhatsApp still needs a defined reaction-read and inbound-event contract. The referenced forwarding PRs were closed unmerged, while the open related issues cover narrower, distinct pieces of the requested behavior.

## What This Changes

The issue requests WhatsApp support for reading historical message reactions and exposing inbound reaction events to agents or searchable storage.

## Best Possible Solution

Define a passive, access-controlled WhatsApp reaction-event contract in the WhatsApp plugin first, with no automatic agent turn; decide separately whether a retained SQLite-backed query surface is warranted and, if so, ship one documented migration and generic read contract.
