## Summary

Keep open: current main and latest release still support outbound WhatsApp `react` plus approval-specific reaction handling, but not the generic `message reactions` query, historical reaction retrieval, or ordinary reaction event exposure. The related implementation PRs are closed unmerged or only cover adjacent listen-only hooks, so no safe close reason applies.

## What This Changes

Issue requests WhatsApp support for querying, storing, and surfacing message reactions so agents/plugins can use reaction feedback.

## Best Possible Solution

Define a privacy-gated WhatsApp reaction read model, then implement the generic `reactions` action, reaction persistence or retrieval, and observation hooks inside the WhatsApp plugin with focused tests, docs, and live proof.

## Reproduction Assessment

Yes, at source level: current main does not advertise or dispatch the generic WhatsApp `reactions` action, and the inbound monitor has no general reaction-event path beyond approval handling. No live WhatsApp account was exercised in this read-only review.

## Solution Assessment

Unclear until maintainers choose the reaction read model. A maintainable fix should define query, persistence, hook, privacy, access-control, and agent-turn semantics before surfacing reactions broadly.
