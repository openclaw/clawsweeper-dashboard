## Summary

Keep open: current main and v2026.6.11 still support outbound WhatsApp `react` and approval-specific reaction handling, but not the requested generic reaction query, historical reaction retrieval, or ordinary inbound reaction event exposure.

## What This Changes

Requests WhatsApp support for listing/querying message reactions, retrieving or storing historical reaction state, and exposing inbound reaction events to agents or plugins.

## Best Possible Solution

Define a privacy-gated WhatsApp reaction read model, then implement the generic `reactions` action, persistence or retrieval for historical reactions, and ordinary inbound reaction hooks/events inside the WhatsApp plugin with focused tests, docs, and live WhatsApp proof.

## Reproduction Assessment

Yes, at source level: `message reactions` routes to the generic `reactions` action, while the WhatsApp plugin advertises and handles only outbound `react` plus `upload-file`. No live WhatsApp account was exercised.

## Solution Assessment

Unclear until maintainers choose the product/API model. The maintainable solution should cover query/history storage or retrieval, hook payloads, privacy gates, access control, and agent-turn semantics rather than only forwarding a single event shape.
