## Summary

The implementation follows the right transport-to-session path, but it has a blocking long-cooldown error: Retry-After values above 60 seconds are truncated and retried early, which can exhaust retries while the server still rejects requests. The PR also lacks after-fix real behavior proof; its evidence is focused mocked tests only.

## What This Changes

The PR adds HTTP status and Retry-After metadata to assistant errors and uses the server delay as a capped lower bound for Anthropic session auto-retries.

## Best Possible Solution

Keep the generic metadata plumbing, but for Retry-After values above the established 60-second policy threshold, skip session auto-retry and surface the error for fallback instead of truncating the delay; cover short, longer-than-backoff, and over-threshold cases and prove the final delay with a real local HTTP stub.
