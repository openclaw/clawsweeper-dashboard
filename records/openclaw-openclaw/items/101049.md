## Summary

This issue should stay open: current source can report missing plugin dependencies in status surfaces, but the managed npm install path still does not fail or rebuild when a present plugin package is missing its declared runtime dependencies, and doctor repair covers missing records/payloads rather than a present-but-incomplete dependency tree.

## What This Changes

The issue asks OpenClaw to detect and repair managed npm plugin installs whose declared runtime dependencies are missing after a nominally successful MS Teams plugin install.

## Best Possible Solution

Fix https://github.com/openclaw/openclaw/issues/101049 by adding a generic managed npm plugin dependency verification and repair path. After a successful managed npm install, verify every declared required runtime dependency from the installed plugin package resolves from the package root or managed project root; if required dependencies are missing, fail the install and roll back or rebuild with a clear error naming the packages. Extend doctor/configured-plugin install repair so an existing present package with missing declared dependencies is detected and repaired by rerunning the managed npm install, without requiring users to enter the generated npm project manually. Keep the fix generic; do not hardcode MS Teams package ids except in tests if using a fixture.
