## Summary

Keep open for maintainer direction. The merged Claude CLI work now establishes that current non-interactive Claude CLI releases do not provide readable thinking text to forward, while the Gateway HTTP projection still lacks an agreed, privacy-gated contract for embedded-runtime reasoning; the recent production report shows that narrower path remains useful.

## What This Changes

Add an opt-in OpenAI-compatible HTTP representation for reasoning emitted by Claude CLI-backed or embedded OpenClaw agents on `/v1/responses` and `/v1/chat/completions`.

## System Context

Agent runtimes emit assistant and, when available, thinking events onto OpenClaw’s internal event flow. The Gateway’s OpenResponses and Chat Completions adapters convert those events into HTTP JSON or SSE for external clients, where an explicit reasoning-visibility policy must protect sensitive model output.

## Architecture Diagram

flowchart LR
  A[Agent runtime] --> B[CLI or embedded event stream]
  B --> C[Reasoning and assistant events]
  C --> D[Visibility and privacy gate]
  D --> E[Gateway HTTP projection]
  E --> F[Responses SSE or JSON]
  E --> G[Chat Completions SSE or JSON]
  F --> H[HTTP clients]
  G --> H

## Best Possible Solution

Define one Gateway-owned, explicitly opt-in reasoning-output contract for HTTP clients; project real embedded reasoning through it, expose Claude CLI token progress only when accurately represented, and defer readable Claude CLI text unless the upstream wire restores it.
