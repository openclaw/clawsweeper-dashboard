## Summary

Keep open. Merged work now parses Claude CLI thinking and exposes token-progress telemetry, but the requested Gateway HTTP projection remains unresolved; the latest production report also identifies the same projection gap for embedded agents. A maintainer must choose the public privacy and API contract before a fix can land.

## What This Changes

Expose opt-in structured reasoning or available thinking progress from Claude CLI and embedded agents through the Gateway’s OpenAI-compatible `/v1/responses` and `/v1/chat/completions` APIs.

## System Context

Agent runtimes publish assistant and thinking events to OpenClaw’s internal event bus. The Gateway HTTP adapters translate selected events into OpenAI-compatible Responses and Chat Completions payloads for external clients.

## Architecture Diagram

flowchart LR
  A[Claude CLI or embedded agent] --> B[Agent event bus]
  B --> C[Reasoning policy gate]
  C --> D[Gateway HTTP adapters]
  D --> E[Responses API]
  D --> F[Chat Completions API]
  E --> G[HTTP clients]
  F --> G

## Best Possible Solution

Adopt one documented, privacy-preserving HTTP reasoning contract that reuses the established reasoning policy, projects readable embedded thinking when available, represents Claude CLI token estimates as progress without synthesizing text, and covers streaming and completed Responses and Chat Completions payloads.
