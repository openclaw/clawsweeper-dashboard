## Summary

Keep open: current main and v2026.6.11 still use the x11vnc/Xvfb noVNC stack, upstream noVNC falls back to Latin-1 clipboard transfer when Extended Clipboard is unavailable, and the only linked TigerVNC fix PR closed unmerged after security review concerns.

## Best Possible Solution

Keep this as the canonical open sandbox-browser UTF-8 clipboard bug until a maintainer-sponsored VNC-server fix preserves the observer security contract and proves non-Latin paste in a real Docker/noVNC flow.
