- `impact:ux-friction`: The TUI help and usage text omit the accepted `stream` mode, leaving users to rely on support comments or guesswork.

## Summary

Keep open: current main still accepts and documents `reasoningLevel: "stream"`, but the TUI only advertises `on|off` and has no user-visible handling for `agent` thinking-stream events; the remaining choice is where that live reasoning should appear.

## What This Changes

The issue asks for OpenAI/Grok-style live reasoning updates in OpenClaw TUI, including line-rewrite or footer/status presentation while a run is thinking.

## Best Possible Solution

Choose the TUI live-reasoning presentation contract, then align `/reasoning stream` help/completions, thinking-event rendering, cleanup on finalization, and focused TUI/Gateway proof.

Options:

- **Transient Chat Reasoning (recommended):** Render `agent stream=thinking` as a temporary chat entry that updates during the run and clears or collapses when the final answer arrives.
- **Footer Status Reasoning:** Show the latest reasoning delta in the footer/activity status line, matching the later request but competing with existing run-state text.
- **History Only:** Do not add live TUI reasoning presentation; fix copy so users rely on `/reasoning on` plus Show thinking for retained thinking blocks.

Yes. Source inspection on current main shows `stream` is accepted and documented, while TUI help/completion omit it and `handleAgentEvent` has no `thinking` rendering branch.

## Solution Assessment

Unclear until maintainers choose the UX. A narrow TUI patch is likely the right implementation once the presentation target is decided, but chat-row versus footer behavior is a product choice.
