## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Exclude the default-plugin marker from runtime selectors:** `src/agents/tool-policy.ts:74-75`
  - body: `collectExplicitAllowlist()` emits the internal `__openclaw_default_plugin_tools__` marker for alsoAllow-only policies, and this condition treats any `__` value as an MCP-style runtime selector. That marker can then be stored in a spawned child's inherited allowlist; the embedded runtime startup code also treats separator-form entries as bundle-MCP capable, so an unrelated `tools.alsoAllow` can start MCP runtime materialization. Please explicitly reject `DEFAULT_PLUGIN_TOOLS_ALLOWLIST_ENTRY` before classifying separator names.
  - confidence: 0.9
- **[P1] Filter preserved selectors through gateway denies:** `src/gateway/tool-resolution.ts:195-205`
  - body: The gateway path computes preserved runtime tokens from profile/agent/group/subagent/inherited policies, but current gateway behavior removes `gateway.tools.deny`, owner-only/default HTTP denies, and exclusions before copying the effective parent surface. With this patch, a gateway-level deny such as `gateway.tools.deny: ["bundle-mcp"]` can remove the concrete parent tool while `bundle-mcp` is still preserved into the child allowlist, which is the opposite of the stated no-escalation guarantee. Include the gateway deny layer in the preserved-token filter before passing it to `replaceWithEffectiveToolAllowlist()`.
  - confidence: 0.88
