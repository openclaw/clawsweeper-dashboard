## Summary

The prior zero-padding finding is fixed, but the body-less fallback is still not actually bounded when Content-Length is missing or understated: it calls arrayBuffer() before checking the materialized size, so a hostile response can retain the OOM path. The supplied evidence is also mock/test-only rather than after-fix proof from a real non-standard Response setup.

## What This Changes

The PR adds a Content-Length precheck for body-less proxy-capture response reads and focused regression coverage for oversized, non-safe, zero-padded, within-cap, and missing lengths.

## Best Possible Solution

Make the body-less branch fail closed without materializing an untrusted body unless a genuinely bounded read mechanism is available, preserve explicitly safe empty-body behavior, and cover missing and understated Content-Length cases with regression tests plus real-runtime proof or a maintainer proof override.

## Solution Assessment

No. The header precheck is a useful optimization for honestly declared oversized bodies, but it cannot satisfy a bounded-read contract because Content-Length may be absent or false; the fallback should avoid unbounded materialization entirely.
