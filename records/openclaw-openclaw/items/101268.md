## Summary

Keep open: current main still has the body-less fallback OOM gap, and this PR fixes the prior non-safe Content-Length bypass, but the new raw digit-count guard can falsely truncate valid zero-padded under-cap lengths in the fallback path.

## What This Changes

The PR exports `readCapturedResponseBodyBounded`, adds a Content-Length precheck before body-less `arrayBuffer()` reads, and adds focused fallback regression tests.

## Best Possible Solution

Keep the helper-level fallback guard, but normalize digit strings before the raw length/cap comparison so huge values still skip `arrayBuffer()` while valid padded under-cap values read normally.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Current main's body-less fallback calls `arrayBuffer()` before checking the cap, and the PR proof plus source inspection exercise that helper branch with `body: null` clones.

## Solution Assessment

Mostly yes. The helper is the right layer because proxy capture entry points route through it, but the Content-Length parser should handle leading zeroes before the PR is fully polished.
