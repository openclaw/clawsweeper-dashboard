## Summary

Keep open for normal PR review: the latest head fixes the previous non-safe numeric Content-Length bypass, but the new digit-count shortcut still has a low-priority parser edge for zero-padded under-cap lengths.

## What This Changes

The PR adds a Content-Length precheck for the body-less proxy-capture response reader fallback and adds regression tests for oversized, malformed, and normal body reads.

## Best Possible Solution

Keep the helper-level allocation guard, but compare declared lengths after leading-zero normalization or safe parsing so oversized/non-safe values skip allocation while valid under-cap lengths still read normally.

## Reproduction Assessment

Yes. The current-main fallback reads arrayBuffer before enforcing the cap, and the remaining PR-head edge is source-reproducible because a long zero-padded digit string parses to an under-cap safe integer while the new length shortcut still returns oversized.

## Solution Assessment

Mostly yes. The helper-level guard is the right narrow fix, but the declared-length comparison should preserve valid leading-zero under-cap values before this is fully polished.
