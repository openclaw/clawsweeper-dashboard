## Summary

Keep this PR open, but it needs one blocking repair before merge: the new stuck-recovery reply-run abort path preserves the abort reason, but skips the terminal-settle cleanup fallback that existing user/restart abort paths use to release retained running operations.

## What This Changes

The PR preserves `stuck_recovery` through diagnostic embedded/reply abort paths and classifies stuck recovery as model idle timeout, tool execution timeout, or external abort from active model/tool state.

## Best Possible Solution

Keep the phase-safe classification approach, but merge only after stuck-recovery reply aborts use the same queued/non-queued cleanup pattern as existing reply abort paths.
