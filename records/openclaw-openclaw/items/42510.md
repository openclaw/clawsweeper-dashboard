## Label Justifications

- `P1`: This breaks an existing Google Chat channel workflow for users who configured off mode to avoid threaded replies.

## Summary

Keep open: current main and the latest release still allow Google Chat off-mode replies to leak threaded typing or thread targets, and https://github.com/openclaw/openclaw/pull/89790 is the open closing fix candidate.

## What This Changes

The issue requests that Google Chat honor `channels.googlechat.replyToMode: "off"` by suppressing automatic threaded replies.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/89790 or a maintainer-equivalent narrow Google Chat plugin fix, then close this issue once the fix reaches main.

## Reproduction Assessment

Yes. Source inspection shows a Google Chat group message with `message.thread.name` can seed a threaded typing placeholder and direct thread target while `replyToMode: "off"` only strips the final payload reply id.

## Solution Assessment

Yes. The best current path is the existing closing PR or an equivalent narrow Google Chat plugin fix that prevents stale typing, durable delivery, and outbound thread metadata from bypassing the shared reply-mode filter.
