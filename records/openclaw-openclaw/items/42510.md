## Label Justifications

- `P1`: This breaks an existing Google Chat channel workflow for users who configured off mode to avoid threaded replies.
- `impact:message-loss`: Replies can be routed into unintended Google Chat threads instead of the configured flat conversation, which is message misrouting.
- `impact:ux-friction`: A user reported the forced threading as a blocker to recommending Google Chat because normal conversation flow becomes disconnected.

## Summary

Keep open: current main and the latest release still let Google Chat thread metadata reach outbound delivery despite `replyToMode: "off"`, and https://github.com/openclaw/openclaw/pull/89790 is the open closing fix candidate.

## What This Changes

The issue reports that Google Chat ignores `channels.googlechat.replyToMode: "off"` and still sends replies as thread replies.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/89790 or a maintainer-equivalent Google Chat plugin fix, then close this issue once the fix reaches main.

Required: false

## Reproduction Assessment

Yes. Source inspection shows a Google Chat group message with `message.thread.name` can seed threaded typing/reply metadata while `replyToMode: "off"` only strips some final payload reply ids, leaving stale thread paths in current delivery.

## Solution Assessment

Yes. The best current path is the existing closing PR or an equivalent narrow Google Chat plugin fix that prevents stale typing, durable delivery, and outbound thread metadata from bypassing the shared reply-mode filter.
