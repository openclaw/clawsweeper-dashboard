The PR changes `truncateLine` to clamp the limit, trim trailing whitespace before the length check, reserve space for the `...` marker, and updates focused formatter/list tests.

## Best Possible Solution

Land the focused shared-helper and test fix after ordinary maintainer review; the linked canonical issue should close after merge.

## Reproduction Assessment

Yes, source-reproducible: current main appends `...` after the full `maxLength` slice, and the linked issue documents `truncateLine("abcdefghij", 5)` returning an eight-character result. I did not run local tests because this review was read-only.

## Solution Assessment

Yes. The shared `truncateLine` helper is the right boundary because both label and task callers use it through `buildSubagentList`, and caller-side fixes would duplicate the invariant.
