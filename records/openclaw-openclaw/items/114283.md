## Summary

The enabled-plugin guard addressed the prior review finding, but the current patch still only suppresses the inactive-surface warning for standalone-tool providers. It does not resolve and write their SecretRef into the runtime snapshot, so the reported standalone tool can retain the unresolved-credential failure; keep this PR open for a focused repair and real gateway proof.

## What This Changes

The PR exempts enabled web-provider plugins that declare standalone tools from inactive-credential handling when another provider is selected for generic web search or fetch.

## System Context

At gateway startup, the secrets subsystem converts configured credential references into a resolved runtime configuration. The web-tool resolver selects generic search or fetch providers while plugin-owned standalone tools consume credentials from that same runtime snapshot.

## Best Possible Solution

Resolve and assign SecretRefs for enabled, loadable standalone-tool providers through the same runtime-snapshot path as selected providers, while keeping disabled, unavailable, and unrelated provider credentials inactive.
