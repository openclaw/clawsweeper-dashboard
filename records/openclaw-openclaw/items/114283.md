## Summary

Keep this PR open. It addresses the linked active bug, but the current implementation still keeps credentials active from static manifest metadata rather than from the runtime-effective standalone tools, and the PR has only test output rather than an after-fix gateway run.

## What This Changes

The PR changes gateway secret resolution so a web-provider credential remains active when its plugin declares standalone tools, even when another provider is selected for generic web search or fetch.

## System Context

Gateway startup resolves configured SecretRefs for web-search and web-fetch providers, then passes the resolved configuration to provider plugins and their tools. The inactive-surface optimization avoids resolving unused credentials, so it must distinguish a selected generic provider from a separately enabled standalone plugin tool that needs the same credential.
