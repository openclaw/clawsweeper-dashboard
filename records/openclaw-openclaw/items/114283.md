## Summary

This PR is still necessary: current main retains the selected-provider-only SecretRef policy, while the linked report shows enabled standalone Tavily tools need their own credential even when Brave serves generic web search. The implementation has credible live gateway proof, but it intentionally expands the active-secret boundary and conflicts with the documented inactive-provider contract; that policy exception needs maintainer confirmation and documentation before merge.

Likely related people: `steipete` is a medium-confidence routing candidate as the recent contributor shown on the SecretRef contract documentation; the source-history trail for the runtime implementation could not be completed in this read-only environment.

## What This Changes

The PR keeps SecretRefs for effectively enabled plugins with standalone web tools resolved in the gateway runtime snapshot even when another provider is selected for generic web search or fetch.

## System Context

The gateway secret resolver converts configured SecretRefs into an in-memory runtime snapshot before web search and web fetch tools run. Provider selection normally limits that snapshot to the selected generic provider; this PR adds an exception for enabled plugins whose standalone tools need the same credential.

Adopt a documented, narrow active-surface exception for effectively enabled plugins whose declared standalone tools require the provider credential, and add coverage for valid credentials, disabled plugins, and missing or invalid SecretRefs during startup and reload.
