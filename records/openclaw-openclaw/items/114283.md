## Summary

Keep this PR open for maintainer review. The reported standalone-tool failure has credible after-fix gateway proof, but the branch expands the active-secret boundary from the selected web provider to every effectively enabled plugin whose manifest has a non-empty generic `contracts.tools` declaration; a secrets/plugin-contract owner should confirm that this metadata is sufficiently specific before merge.

## What This Changes

The PR resolves SecretRef credentials for enabled web-provider plugins with standalone tools even when a different provider is selected for generic web search or fetch.

## System Context

Gateway startup resolves configured SecretRefs into a runtime configuration snapshot before web-search, web-fetch, and plugin-provided tools run. The changed path decides which provider credentials are active, then supplies the resolved snapshot to the selected generic provider and standalone plugin tools.

## Best Possible Solution

Retain the targeted fix, but make active standalone credential eligibility explicit at the web-provider contract boundary (or prove that `contracts.tools` is already that exact contract), with integration coverage for unrelated tool plugins, disabled plugins, and both search and fetch selection.
