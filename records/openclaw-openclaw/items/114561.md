## What This Changes

Fix Telegram isolated polling so updates spooled after startup are dispatched rather than being acknowledged and silently stranded.

## System Context

Telegram isolated ingress receives Bot API updates, persists them in a durable spool, and advances the polling offset before the spool consumer dispatches work into the agent/channel turn pipeline. A consumer wake-up or lifecycle failure after persistence can therefore turn an acknowledged inbound message into a user-visible non-response.

  E --> F[Telegram message handler]
  F --> G[Agent turn and reply]

## Best Possible Solution

Reproduce the two-update scenario against current main, then make the durable ingress lifecycle reliably wake or continuously observe the Telegram spool after every successful append, with regression coverage proving both startup-spooled and post-startup updates reach exactly one handler dispatch.
