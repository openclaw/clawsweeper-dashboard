## Summary

Keep open: current main still keeps completed-call usage/cost accounting separate from resolved auth-profile routing, so users cannot see which profile paid for each call or aggregate cost by profile. burn0, the closed tokenomics plugin PR, and the open provider-scoped model-usage PR are useful adjacent work, but they do not provide native resolved-profile attribution.

## What This Changes

Request native per-call cost tracking that attributes actual billed model calls to the resolved auth profile, with per-profile status breakdown and fallback/profile-change events.

## Best Possible Solution

Define one additive, privacy-safe completed-model-call attribution contract that records resolved authProfileId and cost metadata, then derive transcript, status, gateway/API/UI, diagnostics, and plugin views from that source.

## Reproduction Assessment

Yes, at source level: current main has completed-call usage/cost summaries and separate auth-profile routing, but the accounting contracts do not join those facts with a resolved authProfileId.

## Solution Assessment

No current implementation fully solves it; the maintainable path is a single canonical completed-call attribution contract rather than a cost-only plugin, diagnostics-only hook, or status-only field.
