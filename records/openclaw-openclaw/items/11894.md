## Summary

Keep open: current main still has completed-call usage and cost accounting, and separate auth-profile routing, but no native contract that attributes a paid model call to the resolved auth profile that supplied the credential.

## What This Changes

Request native per-call cost tracking with auth-profile attribution, including per-profile cost summaries and a fallback/profile-use signal.

## Best Possible Solution

Define one additive, privacy-safe completed-model-call attribution contract that records resolved authProfileId and cost metadata, then derive transcript, status, gateway/API/UI, diagnostics, and plugin views from it.

## Reproduction Assessment

Yes, at source level: current main has completed-call usage/cost summaries and separate auth-profile routing, but the accounting contracts do not join those facts with a resolved authProfileId.

## Solution Assessment

No current implementation fully solves it; the maintainable path is a single canonical completed-call attribution contract rather than a cost-only plugin, status-only field, or hook-only field.
