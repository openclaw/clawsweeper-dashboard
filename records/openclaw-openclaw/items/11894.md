## Summary

Keep open: current main still separates completed-call usage/cost data from resolved auth-profile routing, so users cannot attribute a paid model call to the profile that supplied the credential. burn0 and the closed tokenomics PR are useful adjacent cost-visibility work, but neither is a native OpenClaw auth-profile attribution contract.

## What This Changes

Request native per-call cost tracking with resolved auth-profile attribution and fallback/profile-rotation visibility.

## Best Possible Solution

Define one additive, privacy-safe completed-model-call attribution contract that records resolved authProfileId and cost metadata, then derive transcript, session status, gateway/API/UI, diagnostics, and plugin views from it.

## Reproduction Assessment

Yes, at source level: current main has completed-call usage/cost summaries and separate auth-profile routing, but the accounting contracts do not join those facts with a resolved authProfileId.

## Solution Assessment

No current implementation fully solves it; the maintainable path is a single canonical completed-call attribution contract rather than a cost-only plugin, status-only field, or hook-only field.
