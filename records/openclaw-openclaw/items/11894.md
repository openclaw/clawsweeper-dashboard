## Summary

Keep open: current main and v2026.6.11 still expose usage and cost by provider/model/session, while auth-profile routing exists separately; the missing product decision is how to safely persist and expose the resolved auth profile that paid for each completed call.

## What This Changes

Request native per-call cost tracking with attribution to the resolved auth profile, especially when fallback auth profiles are used.

## Best Possible Solution

Define one additive, privacy-safe completed-model-call attribution contract that records resolved authProfileId and cost metadata, then derive transcript, status, gateway/API/UI, diagnostics, and plugin views from that source.

Options:

- **Design canonical attribution contract (recommended):** Record resolved authProfileId and cost at the normalized completed-call seam, expose redacted/additive readers, and make this the source for status, usage, diagnostics, and plugin views.
- **Limit to plugin or diagnostics first:** Keep native status/usage unchanged for now and expose safe usage metadata through an explicit maintainer-approved plugin observer capability.
- **Defer native attribution:** Keep current provider/model cost summaries and external workarounds until maintainers are ready to design credential-adjacent accounting metadata.

## Reproduction Assessment

Yes, at source level: current main has completed-call usage/cost summaries and separate auth-profile routing, but the accounting contracts do not join those facts with a resolved authProfileId. I did not run a live multi-profile Anthropic fallback scenario in this read-only review.

## Solution Assessment

No current implementation fully solves it. The maintainable path is a single canonical completed-call attribution contract rather than a cost-only plugin, diagnostics-only hook, or status-only field.
