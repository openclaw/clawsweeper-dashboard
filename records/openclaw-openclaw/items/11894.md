## Summary

Keep open: current main still has cost/usage accounting and auth-profile routing as separate surfaces, but completed model-call accounting is not attributed to the resolved auth profile that paid for the call. The burn0 workaround, broader native usage-ledger issue, and provider-scoped plugin usage PR are adjacent but do not replace native per-call auth-profile attribution and per-profile cost aggregation.

## What This Changes

The issue requests native per-call cost tracking with resolved auth profile attribution, especially when fallback auth profiles are used.

## Best Possible Solution

Define one additive, privacy-safe completed-model-call attribution contract that records resolved authProfileId and cost metadata, then derive transcript, status, gateway/API/UI, diagnostics, and plugin views from that source.
