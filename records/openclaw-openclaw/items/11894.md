## Summary

Keep open: current main and the latest release still expose completed-call cost and usage by provider/model/session, but not by the resolved auth profile that paid for the call. The burn0 workaround and tokenomics/plugin diagnostics discussions are useful adjacent cost-visibility work, but they do not replace native OpenClaw auth-profile attribution.

## What This Changes

Requests native per-call cost tracking plus attribution to the resolved auth profile used during provider fallback or profile rotation.

## Best Possible Solution

Define one additive, privacy-safe completed-model-call attribution contract that records resolved authProfileId with cost/usage, then derive transcript, session status, gateway/API/UI, diagnostics, and plugin views from that single source.

## Reproduction Assessment

Yes, at source level: current main has completed-call usage/cost summaries and separate auth-profile routing, but the accounting and diagnostic contracts do not join those facts with a resolved authProfileId.

## Solution Assessment

No current implementation fully solves it; the maintainable solution is a single canonical completed-call attribution contract rather than a cost-only plugin, status-only field, or hook-only field.
