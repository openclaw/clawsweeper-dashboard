## Summary

Keep open: current main and v2026.6.11 still expose completed-call usage and cost by provider/model/session or diagnostics, but not by the resolved auth profile that paid for each call. The burn0 discussion and provider-cost PRs are useful adjacent workarounds, not native OpenClaw auth-profile attribution.

## What This Changes

The issue requests native per-call cost tracking with resolved auth-profile attribution so users can see when fallback credentials are used and what each call costs.

## Best Possible Solution

Define one additive, privacy-safe completed-model-call attribution contract that records resolved authProfileId and cost metadata, then derive transcript, status, gateway/API/UI, diagnostics, and plugin views from that source.

Options:

- **Design canonical attribution contract (recommended):** Record resolved authProfileId and cost at the normalized completed-call seam, expose only redacted/additive readers, and make this the source for status, usage, diagnostics, UI, and plugin views.
- **Limit exposure to plugin or diagnostics first:** Keep native transcript/status/usage unchanged for now and expose safe model usage metadata only through an explicit maintainer-approved observer capability.
- **Defer native attribution:** Keep current provider/model cost summaries and external workarounds such as burn0 until maintainers are ready to own credential-adjacent attribution metadata.

## Reproduction Assessment

Yes, at source level: current main has completed-call usage/cost summaries and separate auth-profile routing, but the accounting contracts do not join those facts with a resolved authProfileId. I did not run a live multi-profile Anthropic fallback scenario in this read-only review.

## Solution Assessment

No existing implementation fully solves it. The maintainable path is a single canonical completed-call attribution contract rather than a cost-only plugin, provider-history feature, diagnostics-only hook, or status-only field.
