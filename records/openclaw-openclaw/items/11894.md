## Summary

Keep open: current main and v2026.6.11 still attach cost and usage to provider/model/session surfaces, not to the resolved auth profile that paid for each completed call. burn0, the closed tokenomics plugin PR, and the open provider-scoped usage PR are useful adjacent work, but they do not replace native auth-profile attribution.

## What This Changes

Request native per-call cost tracking tied to the resolved auth profile, including fallback-profile visibility in transcripts, session status, or system events.

## Best Possible Solution

Record a safe resolved authProfileId or redacted profile label for each completed model call, expose per-profile cost aggregates through the supported usage/status surfaces, and emit a clear fallback/profile-rotation event without leaking credentials.

Question: What safe public contract should OpenClaw use for resolved auth-profile attribution on completed model calls?

Rationale: The missing behavior is real, but the fix would add credential-adjacent persisted metadata and gateway/plugin/UI exposure, so automation should not choose the privacy and API contract alone.

Likely owner: steipete

Owner reason: Peter has the strongest current-history ownership of the usage/status/diagnostic surfaces that need the exposure-boundary decision.

Owner confidence: high

Options:

- **Persist safe profile ids (recommended):** Store a stable non-secret authProfileId or display label on completed call metadata and aggregate usage/cost by that value in status and usage APIs.
- **Expose diagnostics only:** Emit resolved-profile fallback events and diagnostics without persisting profile attribution into long-lived transcripts or usage summaries.
- **Defer to plugin seam:** Keep core metadata unchanged and let a provider-owned usage plugin consume model usage once an approved profile-safe plugin contract exists.

Unclear until maintainers choose the privacy/API contract. The best implementation should be native and profile-safe; burn0 and tokenomics-style cost ledgers help with cost visibility but do not solve OpenClaw-level resolved auth-profile attribution.
