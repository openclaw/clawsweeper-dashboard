## Summary

Current main appears to prevent the reported phantom-path update by deriving the npm target from the running package root before considering command-reported global roots. Keep this issue open conservatively because the exact introducing commit, timestamp, and release containment required for an implemented-on-main close have not been established; the latest release remains the reporter’s affected version.

## What This Changes

Make `openclaw update` reject or bypass npm-redacted global-root output so it updates the live installation instead of a literal `***` directory tree.

## Best Possible Solution

Keep the running npm package root as the canonical update destination, add or retain a direct regression case where `npm root -g` returns a literal `***` path, and ship that behavior in the next release.
