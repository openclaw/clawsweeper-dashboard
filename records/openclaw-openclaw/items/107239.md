## Summary

This issue remains necessary: current `main` still accepts successful `npm root -g` stdout as the authoritative global root, and the updater subsequently creates and mutates that path. The detailed npm 11.9.0 reproduction provides strong evidence that UUID redaction can therefore produce a false-success update.

Likely related people: `wdeveloper16` for adjacent updater-flow history (medium confidence), and `SL4N` for reproducing and validating this exact failure (high confidence).

## What This Changes

Fix `openclaw update` so npm-redacted global-root output cannot redirect staging and swapping into a phantom literal `***` directory tree.

## Best Possible Solution

Make the valid running package root authoritative for self-update, defensively reject unusable package-manager root results, and add regression coverage for UUID-redacted npm output and global-manager detection without adding configuration.
