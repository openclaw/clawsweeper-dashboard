## What This Changes

Request to reduce fixed per-session token overhead from always-injected tool schemas, broad message-tool parameters, long tool descriptions, and duplicated tool-list prompt text.

## Best Possible Solution

Keep this issue as the canonical tracker and land incremental, compatibility-preserving reductions: remove duplicated Tooling text where safe, prune message schemas by channel/capability without breaking cross-channel jobs, shorten long descriptions, and design any lazy/slim schema mode behind an explicit maintainer-approved contract.
