## Summary

Keep open. Current main has partial mitigations, including policy filtering, Tool Search, and nested-schema compaction, but policy-visible tools still incur structured-definition overhead and the system prompt still duplicates tool summaries. The narrower open issues cover individual slices rather than superseding this canonical performance tracker.

## What This Changes

Reduce fixed per-session context consumed by broad always-sent tool schemas through capability-aware pruning, shorter descriptions, focused tools, or deferred schema loading.

## Best Possible Solution

Keep this as the canonical performance tracker and land measured, reversible changes in sequence: remove duplicate Tooling text, omit empty definition payloads, shorten descriptions, prune only capability-proven fields, then define an additive deferred-schema contract for large core and plugin catalogs.

## Solution Assessment

No, the original proposals should not land as one broad change. Compatibility-preserving prompt deduplication and capability-aware pruning are the safest first steps, followed by an explicitly designed deferred-schema contract.
