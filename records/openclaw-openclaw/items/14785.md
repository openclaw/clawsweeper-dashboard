## Summary

Keep open. Current main still has the central fixed tool-schema overhead: message schema construction still carries broad cross-channel parameters, ordinary effective tools still become full model-facing custom tool definitions, the system prompt still emits Tooling text, and cron still has long always-sent guidance; related open issues are narrower subtrackers, not replacements.

## What This Changes

The issue asks to reduce fixed per-session tool schema prompt overhead through channel-aware pruning, lazy schema loading, shorter descriptions, and related prompt/tool definition changes.

## Best Possible Solution

Keep this issue as the canonical tracker and pursue maintainer-sequenced, incremental changes: remove duplicated Tooling text, avoid sending definitions when no effective tools exist, prune message schemas by active channel/capability without breaking cross-channel cron or isolated runs, shorten long descriptions, and design any lazy/slim schema mode as a compatible tool contract.
