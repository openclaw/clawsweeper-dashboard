## Summary

Keep this PR open for maintainer review rather than cleanup: it addresses a real stale-lock regression with credible real Git-worktree proof, but its new acquire-side reclaim repeats the known observe-then-unlock race that can leave two processes believing they exclusively own one worktree. The linked follow-up identifies the cross-call-site guard needed to make reclamation safe, and the `maintainer` label requires explicit human handling.

## What This Changes

This PR retries Git worktree locking after reclaiming a lock owned by a definitely dead OpenClaw process, with integration tests covering dead, live, foreign, and self-owned locks.

## System Context

Managed agent worktrees give concurrent agent runs isolated Git checkouts. A run lease acquires a Git worktree lock before work begins, so stale-lock recovery must restore availability without allowing two runs to mutate the same checkout concurrently.

## Best Possible Solution
