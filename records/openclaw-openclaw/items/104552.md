The prior streamed-overflow blocker is fixed on the current head, and no new correctness or security finding remains. This PR should stay open for normal maintainer review; likely related people are liorb-mountapps and steipete based on the merged feature history.

## What This Changes

The PR rejects oversized declared Admin HTTP RPC bodies early and closes streamed-overflow requests after returning a structured HTTP 413 response.

## Best Possible Solution

Keep the plugin-local 1 MiB guard, preserve the 413 until the response finishes, then terminate only the oversized request connection with real-client coverage for declared and streamed overflow.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source and dependency contracts: current main exits the default request async iterator on overflow, which destroys the stream before the handler sends its structured response. The PR's real HTTP client path exercises the observable failure boundary.

## Solution Assessment

Yes. Disabling iterator destruction only for the overflow return, sending the structured 413, and destroying after response finish is narrower and safer than draining an attacker-controlled body or moving plugin-specific policy into core.
