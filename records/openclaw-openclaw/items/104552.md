## Summary

Keep this PR open for a focused repair: the overall boundary and streamed-overflow handling are sound, but the new declared-length guard misses valid decimal values above JavaScript’s safe-integer range, so it does not yet reject every oversized declaration immediately.

## What This Changes

The PR adds early HTTP 413 rejection for oversized Admin HTTP RPC Content-Length declarations and closes streamed-overflow requests after sending the structured error response.

## Best Possible Solution

Validate Content-Length as decimal digits and compare it without lossy Number conversion—using BigInt or normalized digit-string comparison—then cover maxBytes, maxBytes+1, and a value above Number.MAX_SAFE_INTEGER while retaining the current streamed-overflow cleanup.
