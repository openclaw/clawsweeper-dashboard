## Summary

Keep open. Current main and v2026.6.11 still have adjacent agent, plan, item, tool, chat, lifecycle, session.tool, history SSE, and diagnostics streams, but not the requested session-level process/step event contract with stable step identity, replay/reload semantics, and a redaction/authorization design.

## What This Changes

The issue requests a new session-level structured process/step event stream so clients can render progress from stable events instead of parsing assistant text.

## Best Possible Solution

Define one maintainer-approved session process event contract in the gateway/session owner boundary, persist it with sequence and replay semantics, and map existing runtime progress into that contract without exposing private reasoning or sensitive tool data.
