## Summary

Keep open. Current main still has adjacent agent lifecycle/tool/item/plan streams, `session.tool` mirroring, and `agent.wait`, but not the requested session-level `process.*` / `step.*` contract with stable step identity, replay/reload semantics, and explicit related ids.

## What This Changes

The issue requests stable session-level structured process and step events so clients can render progress without parsing assistant text.

## Best Possible Solution

Define one additive, permission-checked process-event contract with stable step identity, bounded persistence/replay, ordering guarantees, redaction rules, and mappings from existing item, plan, tool, lifecycle, task, and artifact streams.

## Reproduction Assessment

Yes, at source level. Current main exposes adjacent generic streams, but source and docs inspection do not show the requested `process.*` / `step.*` taxonomy, stable step identity, or replayable process-event API.

## Solution Assessment

Unclear until maintainers choose the contract. Structured process events are a plausible right layer, but taxonomy, persistence/replay, authorization, redaction, and compatibility with existing progress streams need product and security design first.
