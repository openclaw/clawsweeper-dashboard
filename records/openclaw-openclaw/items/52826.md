## Summary

Keep open. Current main has adjacent agent, item, tool, lifecycle, and session.tool event streams, but it still lacks the requested session-level process/step contract with stable step identity, replay/reload semantics, and security-reviewed observer rules.

## What This Changes

Add session-level structured process and step events with stable IDs and related tool/message/artifact links so clients can render progress as source of truth.

## Best Possible Solution

Define one additive, permission-checked process-event contract with bounded persistence/replay, redaction, ordering, and mappings from existing agent item, plan, tool, task, and lifecycle streams.

## Solution Assessment

Unclear. Structured process events are likely the right layer, but maintainers need to decide taxonomy, persistence/replay, authorization, and how to avoid duplicating existing progress streams.
