## Summary

Keep open. Current main and v2026.6.11 still have adjacent agent/item/tool/session.tool events, but not the requested session-level process/step contract with stable step identity and replay/reload semantics.

## What This Changes

The issue requests structured session process and step events with stable IDs, sequencing, timestamps, and related tool/message/artifact links so clients can render progress without parsing assistant text.

## Best Possible Solution

Define one additive, permission-checked process-event contract with stable step identity, bounded persistence/replay, redaction rules, and mappings from existing agent item, plan, tool, and task streams.

Unclear. Structured process events are a plausible right layer, but maintainers still need to decide taxonomy, persistence, authorization, redaction, and how this relates to existing progress streams.
