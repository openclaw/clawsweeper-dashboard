## Summary

Keep open. Current main and v2026.6.11 still provide adjacent agent, item, plan, tool, session.tool, and lifecycle streams, but not the requested session-level `process.*` / `step.*` contract with stable step identity, durable ordering, reload/reconnect semantics, authorization, and redaction.

## What This Changes

The issue requests a new structured session process-event API with stable process and step events so clients can render progress without parsing assistant text.

## Best Possible Solution

Define one additive, permission-checked process-event contract with stable step identity, bounded persistence/replay, redaction rules, and mappings from existing agent item, plan, tool, task, and lifecycle streams.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 have adjacent generic event streams, but source inspection does not show the requested `process.*` and `step.*` taxonomy, stable step identity, or replayable process-event API.

## Solution Assessment

Unclear. Structured process events are a plausible right layer, but maintainers still need to decide taxonomy, persistence, authorization, redaction, replay, and how this relates to existing progress streams.
