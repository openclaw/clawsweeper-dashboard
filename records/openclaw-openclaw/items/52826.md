## Summary

Keep open. Current main and v2026.6.11 still expose adjacent agent, item, tool, session.tool, session.message, and agent.wait streams, but not the requested durable session-level process/step event contract with stable step identity and replay/reload semantics.

## What This Changes

The issue requests structured session process and step events with stable IDs, ordering, timestamps, and related tool/message/artifact references so clients do not infer progress from assistant text.

## Best Possible Solution

Define one additive, permission-checked process-event contract with stable step identity, bounded persistence/replay, redaction rules, and mappings from existing agent item, plan, tool, task, and session streams.
