## Summary

Keep open. Current main and the latest release have adjacent agent, item, plan, lifecycle, session.message, session.operation, and session.tool events, but they still lack the requested session-level process.* and step.* contract with stable step identity and replay/reload semantics.

## What This Changes

Add session-level structured process and step events with stable step identity, ordering metadata, and related tool/message/artifact references.

## Best Possible Solution

Define one additive, permission-checked process-event contract with stable step identity, bounded replay, ordering guarantees, redaction rules, and mappings from existing progress streams.

## Maintainer Decision

Rationale: This would become a public gateway/session event contract and may expose intermediate run state, so automation should not choose the taxonomy, persistence, or authorization boundary alone.

Owner confidence: high

Options:

- **Design the core event contract (recommended):** Approve a scoped process/step event design with redaction, permissions, replay, ordering, and migration from existing progress streams before implementation.
- **Extend existing streams:** Keep the current event families and narrow the work to filling gaps in item, plan, session.tool, and session.operation payloads without a new process.* taxonomy.
- **Defer to narrower consumers:** Leave this broad contract deferred while solving narrower progress surfaces such as sessions_send, Control UI runtime progress, or CLI JSON streaming independently.

## Solution Assessment
