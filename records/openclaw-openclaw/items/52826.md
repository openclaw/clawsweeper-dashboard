## Summary

Keep open. Current main and v2026.6.11 still have adjacent agent, item, plan, tool, session.tool, plugin hook, and task progress surfaces, but not the requested session-level `process.*` / `step.*` contract with stable step identity, durable replay/reload semantics, and explicit security boundaries.

## What This Changes

The issue requests stable, session-level process and step events with identity and linkage metadata so clients can render progress without parsing assistant text.

## Best Possible Solution

Define one additive, permission-checked process-event contract with stable step identity, bounded persistence/replay, redaction rules, and mappings from existing agent item, plan, tool, task, and transcript streams.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 expose adjacent generic event streams, but source and docs inspection do not show the requested `process.*` / `step.*` taxonomy, stable step identity, or replayable process-event API.

## Solution Assessment

Unclear as an implementation direction. Structured process events are a plausible right layer, but maintainers still need to choose taxonomy, persistence, observer permissions, redaction, retention, and how this relates to existing progress streams.
