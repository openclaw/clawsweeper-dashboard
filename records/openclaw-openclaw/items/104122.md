## Summary

The PR addresses a real Signal REST body-stall defect and includes credible current-head proof, but the proposed whole-request timer is not the safest fix because it also aborts healthy responses that continue making progress beyond the configured timeout. OpenClaw already has a shared progress-aware response reader used by sibling integrations, so this should be repaired before merge rather than accepted as a compatibility change.

## What This Changes

Keeps Signal container REST abort timers active until response bodies are consumed or released, with a regression test for a headers-then-stalled body.

## Best Possible Solution

Keep the existing fetch/header timeout and apply the shared progress-aware idle timeout while reading Signal JSON, error, and attachment bodies, with tests showing that a stalled body fails but a slow body producing regular chunks succeeds.

## Solution Assessment

No. Extending one AbortController deadline through the complete body fixes the hang, but OpenClaw's existing chunk idle-timeout reader is narrower and avoids failing slow responses that continue making progress.
