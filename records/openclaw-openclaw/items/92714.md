## Summary

Keep this PR open: it adds a new gateway configuration surface, but the unchanged head still lacks strict config-contract coverage and does not carry the resolved `exec host=node` deadline into the gateway `node.invoke` parameters. Its supplied harness is useful supplemental evidence, not end-to-end proof with a real connected node.

## What This Changes

Adds `gateway.nodes.invokeTimeoutMs` as a configurable fallback for gateway-to-node `node.invoke` calls, with registry tests and node documentation.

## Best Possible Solution

Choose the timeout product boundary first, then land one current-main patch that registers the setting in the canonical config contract, preserves normalized Gateway/node timeout semantics, forwards explicit node-exec deadlines, and proves a real connected-node command across the former 30-second boundary.
