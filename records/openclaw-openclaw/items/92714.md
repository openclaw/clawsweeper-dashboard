## Summary

Keep this PR open, but it is not merge-ready: the configurable timeout idea is useful, yet the branch still leaves the new `openclaw.json` key outside the strict config contract and does not align the gateway wait budget with the `node.invoke` request payload for real `exec host=node` calls.

## What This Changes

The PR adds `gateway.nodes.invokeTimeoutMs` as a configurable fallback for `node.invoke`, wires it into gateway startup and `NodeRegistry`, adds registry tests, and documents the node setting.

## Best Possible Solution

Land this only if maintainers sponsor the config knob, with the full config contract updated, one resolved timeout propagated as top-level `node.invoke.timeoutMs`, focused regression coverage, and real configured gateway-node proof.

## Reproduction Assessment

Yes, the remaining blockers are source-reproducible: `gateway.nodes` is strict without `invokeTimeoutMs`, and `exec host=node` puts the long timeout in the outer gateway call option rather than the top-level `node.invoke` payload. I did not run live gateway-node proof in this read-only review.

## Solution Assessment

No, not as submitted. The PR is a plausible slice, but the maintainable fix needs a complete config contract and one resolved timeout value shared by the gateway wait timer and node request payload.
