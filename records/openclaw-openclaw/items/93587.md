## Summary

This PR remains useful because current main has no named-new-session command, and its explicit Control UI-only syntax is narrower than the overlapping shared-command proposal. The session creation and route-adoption design is well tested and uses the existing label contract, but the current head introduces a blocking adapter bug: `renderChat` discards the asynchronous send promise that the composer needs to restore a rejected command draft. After that mechanical repair, maintainers still need to confirm the new public `/new --name <title>` command contract.

## What This Changes

Adds Control UI support for creating labeled dashboard sessions with `/new --name <title>`, adopts the returned session route before list refresh, restores failed asynchronous command drafts, and documents and tests the behavior.

## Best Possible Solution

Preserve the `onSend` promise through `renderChat`, keep naming restricted to explicit Control UI `/new --name <title>` while all other `/new <text>` forms remain anonymous, retain the existing Gateway `label` contract and early route adoption, and obtain Control UI/session owner approval for the public syntax before merge.
