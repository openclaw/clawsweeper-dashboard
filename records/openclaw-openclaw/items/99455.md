## Summary

Keep open: current main still lets long `camera_clip` and `screen_record` calls use 30-second Gateway and node-invoke timers, while this PR uses the existing timeout contract, adds focused coverage, and includes exact-head Android proof. I found no blocking defect.

## What This Changes

The PR derives separate node-invoke and Gateway transport timeout budgets for `camera_clip` and `screen_record` and updates nodes tool coverage.

## Best Possible Solution

Merge the focused timeout-budget helper once required checks are green, keeping explicit transport and invoke timeout overrides independent.

## Reproduction Assessment

Yes. Current main source allows recording durations up to 300,000ms while the agent transport and node invoke timers default to 30,000ms; I did not run a local repro, but the PR body provides exact-head Android proof crossing that boundary.

## Solution Assessment

Yes. The dedicated node media tool is the narrow owner for recording wait budgets, and using the existing `node.invoke.timeoutMs` contract is safer than changing generic Gateway defaults or adding a new API.
