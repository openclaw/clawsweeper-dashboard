## Summary

Keep open: current main still binds operator terminal PTYs to the owning WebSocket and kills them on disconnect, with no attach/list/text or replay-buffer protocol. The protected maintainer label plus new protocol, config, admin-PTY lifetime, and retained-output security questions make this unsuitable for conservative cleanup close or an automated fix lane.

## What This Changes

Request to add operator terminal detach/reattach with bounded output replay, attach/list/text RPCs, UI reconnect persistence, and a detached-session timeout setting.

## Best Possible Solution

Define a maintainer-approved gateway terminal detachment contract with admin-only attach/list/text methods, bounded replay/plain-text buffers, reaper and detached-session caps, shutdown cleanup, UI session-id persistence, and focused disconnect/reattach/security tests.

## Reproduction Assessment

Yes for the current limitation: source inspection shows WebSocket disconnect calls `closeForConn()`, which finalizes and kills owned PTYs. The active protocol and config surfaces have no attach/list/text methods, replay buffer, or detached-session timeout.

## Solution Assessment

Unclear as a final product design: detach/reattach belongs at the gateway terminal/protocol/UI boundary, but timeout defaults, opt-in behavior, plaintext buffer security, and interaction with terminal hardening need maintainer decisions first.
