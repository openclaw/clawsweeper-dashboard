## Summary

Keep this PR open, but do not merge it as written: its timeout still relies on `spawnSync`’s default `SIGTERM`, so a subprocess that ignores or traps that signal can leave the workflow check blocked indefinitely. ([nodejs.org](https://nodejs.org/api/child_process.html?utm_source=openai))

## What This Changes

The PR adds a five-minute, environment-overridable timeout and timeout diagnostics to `scripts/check-workflows.mjs`, plus a regression test for a hanging `actionlint` scan.

## Best Possible Solution

Make the subprocess boundary genuinely finite for non-cooperative children, then add a focused ignored-`SIGTERM` regression fixture and rerun the real entrypoint proof.
