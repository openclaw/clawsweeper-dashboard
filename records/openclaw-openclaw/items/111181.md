## Summary

Keep this PR open for maintainer review. The Canvas reader is bounded at both CLI and tool entry points, and the supplied live Gateway transcript demonstrates a successful 9.4 MiB delivery plus local rejection of an encoded request above the authenticated Gateway limit; however, the shared Gateway-client behavior now applies to every request, so a maintainer should explicitly accept that compatibility boundary before merge.

## What This Changes

The PR makes Canvas read A2UI JSONL files through one 16 MiB bounded reader and makes the shared Gateway client reject serialized requests larger than the server-advertised payload policy before sending them.

## System Context

Canvas accepts A2UI JSONL from either the `nodes canvas a2ui push` CLI command or an agent tool, validates it, and invokes a paired Canvas node through the Gateway. The shared Gateway client serializes requests after authentication, where the server supplies the maximum permitted payload size.

## Best Possible Solution

Keep the single bounded Canvas reader, and merge only after an owner confirms that all Gateway-client requests should be rejected locally against the latest authenticated Gateway payload policy; retain the focused request-cleanup and Canvas pre-invocation tests as the contract proof.
