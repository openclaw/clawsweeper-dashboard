## Summary

Keep open: the bounded-reader direction is appropriate, but this branch still accepts raw JSONL that can exceed the Gateway frame once the request is JSON-serialized, and its new tool test contradicts the current execution order. The posted terminal proof also stops at an intentionally unreachable Gateway, so it does not show a successful Canvas node invocation.

**Likely related people**
- RileyJJY — transport-budget contributor on the current PR head; medium confidence.

## What This Changes

The branch adds a shared 20 MiB bounded A2UI JSONL reader and uses it from the Canvas CLI and agent tool, with coverage for oversized files and a payload above 8 MiB.

## Best Possible Solution

Keep one Canvas-owned bounded reader, but enforce the limit against the exact serialized `node.invoke` request size (or a formally safe worst-case encoding bound), defer node resolution until after local A2UI input validation if that is the intended early-failure contract, and add redacted live paired-node proof for a large escaped payload that succeeds end to end.
