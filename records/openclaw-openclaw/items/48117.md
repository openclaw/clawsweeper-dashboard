## Summary

Keep open: current main and v2026.6.11 still send the reported Windows PowerShell npm certificate failure through the generic npm-install failure path, while the direct Windows fix attempt closed unmerged because TLS recovery is security-sensitive.

## What This Changes

The issue asks for the Windows PowerShell installer to recover from or clearly handle `npm` `UNABLE_TO_VERIFY_LEAF_SIGNATURE` failures during `openclaw@latest` installation.

## Best Possible Solution

Land a security-reviewed Windows installer diagnostic/recovery path that keeps strict TLS verification as the default and offers explicit CA or operator-approved remediation without silently bypassing certificate checks.

## Reproduction Assessment

Yes, at source level: the reported npm leaf-signature failure maps to the current `Install-OpenClaw` nonzero npm path, which only emits generic failure guidance. A live Windows TLS-mismatch environment was not run in this review.

## Solution Assessment

No, the closed direct `--strict-ssl=false` retry is not the best default because it changes installer TLS trust. The better fix is an explicit, security-reviewed CA/trust remediation flow.
