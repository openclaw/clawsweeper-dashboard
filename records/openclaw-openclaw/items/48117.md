## Summary

Keep open: current main and v2026.6.11 still route the reported Windows PowerShell installer npm certificate failure through generic npm-install failure handling. The direct fix attempt at https://github.com/openclaw/openclaw/pull/48416 closed unmerged after TLS-bypass concerns, while the merged Linux/nvm CA work at https://github.com/openclaw/openclaw/pull/51146 is adjacent and does not cover Windows installer recovery.

## What This Changes

The issue reports that the Windows PowerShell installer fails during global npm install with `UNABLE_TO_VERIFY_LEAF_SIGNATURE`.

## Best Possible Solution

Land a security-reviewed Windows installer recovery that keeps strict TLS verification as the default, detects npm certificate failures, and guides explicit CA or operator-approved remediation without silently bypassing certificate checks.

## Reproduction Assessment

Yes at source level: the reported command reaches `Install-OpenClaw`, and current main still sends npm certificate failures through the generic npm install failure path. I did not run a live Windows TLS-mismatch environment in this read-only review.

## Solution Assessment

Unclear until maintainers choose the trust boundary. The closed direct `--strict-ssl=false` retry is not the best default; a safer fix should diagnose the mismatch and use explicit CA or operator-approved remediation.
