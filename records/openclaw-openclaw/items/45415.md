## Summary

Keep open: current main and v2026.6.11 have bootstrap truncation diagnostics, repeated prompt warnings, `/context` visibility, doctor near-limit checks, and docs, but they still do not implement the requested Control UI budget meter, save-time warning/blocking, or archive workflow. The remaining behavior changes the workspace-file editing and memory lifecycle boundary, so it needs maintainer product direction before another fix lane starts.

## What This Changes

The issue asks for MEMORY.md size visibility, warning thresholds, save-time limit enforcement, session-start warnings, and optional archival for oversized workspace memory files.

## Best Possible Solution

Define a bounded product scope that reuses the existing bootstrap budget analyzer for a Control UI meter and save-time warning or blocking, while routing archive automation or first-class bounded memory writes through the broader memory lifecycle design.
