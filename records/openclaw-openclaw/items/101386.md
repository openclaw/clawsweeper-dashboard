## Summary

Keep open: current main still has the ingredients for a non-fatal protected gateway tool rejection to surface as a failed Gateway tool-progress item in Telegram, and I found no merged fix or canonical replacement. The issue likely points at the wrong owner path, though: current polling liveness reports `Polling stall detected`, while the visible `Gateway failed` wording appears to come from generic tool-progress rendering.

## What This Changes

The issue asks OpenClaw to stop presenting intentional gateway tool-call rejections in Telegram as gateway outages, optionally add alert severity filtering, and include the underlying rejection context.

## Best Possible Solution

Fix the default Telegram-visible classification so expected gateway tool rejections show non-fatal rejection context without implying a gateway outage, and add severity filtering only if maintainers explicitly approve that new config surface.
