## Summary

Keep this PR open, but it is not merge-ready: the central collapsed-rail gap fix is valid and well proven, yet the branch positions the new floating expand control against the whole workbench's top-right corner, which conflicts with the preview/sidebar header controls when that sibling surface is open.

## What This Changes

The PR changes the Control UI chat workspace rail so collapsed mode removes the reserved rail column, floats the expand toggle, removes the decorative collapsed file icon, and updates matching chat tests.

## Best Possible Solution

Keep the single-column collapsed rail behavior, but anchor or offset the floating expand toggle to the chat column when a preview/sidebar is open and add focused coverage for collapsed workspace plus open sidebar.

## Reproduction Assessment

Yes, source-level: current main reserves a `52px` collapsed workspace column and the PR screenshots show the before/after gap behavior. The remaining blocker is also source-reproducible because the PR anchors the floating rail to the same workbench corner used by the preview/sidebar close control.

## Solution Assessment

No, not yet: dropping the collapsed grid column is the right narrow direction, but anchoring the toggle to the whole workbench is too broad for the chat-plus-preview layout. The best fix should constrain or offset the toggle so the sidebar header remains usable while the workspace stays expandable.
