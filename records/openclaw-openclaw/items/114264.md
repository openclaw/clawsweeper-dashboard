## Summary

This request is still necessary: current main has a configured primary model and ordered error fallbacks, plus catalog modality metadata, but no evidenced per-turn policy that selects a model from incoming message type. It partially overlaps the broader multimodal-fallback proposal at https://github.com/openclaw/openclaw/issues/87277, but that issue does not settle generic text/audio/TTS routing semantics. 

Likely related people: `Serein236` framed the requested routing policy; `0mlkrizzz655335v` documented the adjacent multimodal-fallback use case. Both are low-confidence routing contacts rather than established code owners.

## What This Changes

Request an opt-in policy that chooses a model for each incoming turn based on text, attachments, audio, or TTS-related intent instead of relying on a session-level manual model override.

## System Context

OpenClaw resolves an agent's configured primary model and failover list before executing an agent turn. Model catalog entries already describe supported input modalities, but a new routing layer would need to combine the incoming message, catalog capability, provider access, and session-history rules before dispatch.

## Architecture Diagram

flowchart LR
  A[Incoming channel message] --> B[Attachment and intent classification]
  B --> C[Per-turn routing policy]
  C --> D[Configured model and catalog lookup]
  D --> E[Provider-backed agent turn]
  E --> F[Session transcript and channel response]

## Best Possible Solution

Choose a provider-agnostic, explicitly opt-in turn-selection contract that first handles declared input capability for attachments, keeps TTS/output-provider routing separate unless a shared contract proves otherwise, and preserves a single canonical session/transcript model across model changes.
