## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P1] Drop all preserved chunks for suppressed finals:** `src/tui/components/chat-log.ts:102`
  - body: In preserve mode, each delta appends a component but `streamingRuns` only remembers the latest one. When the current final-event path intentionally calls `dropAssistant` for a final with no message or suppressed `(no output)`, only that latest component is removed and older partial chunks remain as misleading assistant text; track all preserved chunks for the run or otherwise remove the full run when output is suppressed.
  - confidence: 0.91
- **[P2] Avoid duplicate unchanged final chunks:** `src/tui/components/chat-log.ts:117`
  - body: `finalizeAssistant` always appends another preserved component, even when the final text is identical to the latest streamed text. Normal streams often repeat the final snapshot, so this shows duplicate assistant output and burns the chat-log budget; reuse or replace the latest preserved component when the final text did not change.
  - confidence: 0.82
- **[P2] Bound preserved stream snapshots before exposing the flag:** `src/tui/components/chat-log.ts:99-103`
  - body: Every displayable delta becomes a full chat-log component under this flag. A verbose stream can quickly consume the global 180-component cap and evict prior conversation rows, so preserve mode needs a per-run cap/coalescing policy plus a regression test and user-facing docs for the tradeoff.
  - confidence: 0.84
- **[P3] List the flag in the current options table:** `docs/cli/tui.md:29`
  - body: Current `docs/cli/tui.md` has a formal options table, but this branch only adds an example from the older doc shape. After rebasing, add `--preserve-intermediate` to the options table as well so the CLI reference and command help stay aligned.
  - confidence: 0.79
