## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Drop every preserved chunk for suppressed finals:** `src/tui/components/chat-log.ts:141-143`
  - body: When a final event has no message or suppresses `(no output)`, current TUI handling calls `dropAssistant` to remove the in-progress assistant output. In preserve mode this code only knows about the latest appended component, so older partial chunks remain visible as phantom assistant replies even though the run produced no displayable final output.
  - confidence: 0.91
- **[P2] Avoid duplicating unchanged final snapshots:** `src/tui/components/chat-log.ts:116`
  - body: `finalizeAssistant` always appends another preserved component, even when the final text is identical to the latest streamed display text. Normal streams often repeat the terminal snapshot, so this can show duplicate assistant output and consume the fixed chat-log budget faster.
  - confidence: 0.83
- **[P2] Bound preserved snapshots before exposing the flag:** `src/tui/components/chat-log.ts:100-102`
  - body: Every changed display text from the stream assembler becomes a full chat-log component under this flag. A verbose response can quickly spend the global 180-component cap on one run and evict earlier conversation rows, so preserve mode needs a per-run cap or coalescing policy plus coverage for that tradeoff.
  - confidence: 0.84
