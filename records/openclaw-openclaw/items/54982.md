## Summary

Keep open: current main and the latest release still lack the requested TUI preservation option, and this PR is the canonical implementation candidate for the closed feature request. The branch is not merge-ready because preserve mode can leave stale assistant fragments visible after no-output finals and can consume the fixed chat-log budget one streamed update at a time.

## What This Changes

The PR adds a default-off `openclaw tui --preserve-intermediate` flag that appends streamed assistant updates as separate TUI entries, with CLI wiring, focused tests, and a docs example.

## Best Possible Solution

Land the opt-in TUI preservation flag only after preserved assistant chunks are tracked per run, suppressed finals clear all chunks for that run, and the scrollback cap behavior is covered in docs and tests.

## Reproduction Assessment

Yes for the review blockers. Source inspection shows TUI event handling calls `updateAssistant` for each displayable delta and `dropAssistant` for no-message or suppressed finals, while the PR stores each preserved delta separately but drops only the latest tracked component.

## Solution Assessment

No. The opt-in flag is a plausible solution, but the best fix needs current-main integration, run-level ownership for preserved chunks, complete suppressed-final cleanup, and explicit scrollback cap behavior in docs/tests.
