## Summary

Keep open: current main still lacks the requested opt-in TUI preservation behavior, and the closed feature request points remaining work to this PR. The patch is useful but not merge-ready because preserve mode can leave stale partial assistant chunks visible after no-output finals and can consume the fixed chat-log budget without tested/documented bounds.

## What This Changes

Adds an opt-in `--preserve-intermediate` TUI CLI flag, threads it into `ChatLog`, preserves streaming assistant updates as separate log entries, and adds focused tests/docs.

## Best Possible Solution

Keep the opt-in flag direction, but make preserved assistant chunks run-owned, define the scrollback budget behavior, refresh the docs/tests on current main, and then re-review the branch.

## Reproduction Assessment

Yes for the review blockers: source inspection shows current event handling calls `updateAssistant` for deltas and `dropAssistant` for empty or suppressed finals, while the PR stores each preserved delta separately but only tracks the latest one. I did not run a live TUI repro in this read-only review.

## Solution Assessment

No. The opt-in flag is a plausible solution, but the best fix needs current-main integration, run-level ownership for preserved chunks, complete suppressed-final cleanup, and explicit scrollback cap behavior in docs/tests.
