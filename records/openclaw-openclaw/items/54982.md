  - body: With preservation enabled, every displayed delta becomes its own component, but `streamingRuns` only remembers the newest one.   - body: `finalizeAssistant` always appends another preserved component, even when the final text matches the latest streamed display text. That shows duplicate terminal assistant output and spends the fixed chat-log budget without preserving new information.
  - confidence: 0.84

  - body: Every changed display text from the stream assembler becomes a full chat-log component under this flag. A verbose response can spend the shared component cap on one run and evict earlier conversation rows, so preserve mode needs a per-run cap or compaction policy.
  - confidence: 0.86
