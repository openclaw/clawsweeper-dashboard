## Summary

Keep open. The report contains a credible real-user 45-second feedback gap, but its follow-up changes the needed remedy from an early typing reaction to an early empty streaming card; that lifecycle directly overlaps the unresolved permanent-empty-card failure tracked in https://github.com/openclaw/openclaw/issues/91195 and needs a maintainer decision before implementation.

## What This Changes

Show reliable Feishu processing feedback immediately after an inbound turn is accepted rather than waiting for the first outbound reply payload.

## System Context

The Feishu channel accepts an inbound chat turn and hands it to OpenClaw’s generic channel runner. Its reply dispatcher then creates typing reactions and streaming cards while outbound content is delivered, so moving visible feedback earlier changes the boundary between inbound dispatch and reply presentation.

## Architecture Diagram

flowchart LR
  A[Inbound Feishu message] --> B[Authorization and deduplication]
  B --> C[Accepted channel turn]
  C --> D[Feishu feedback lifecycle]
  D --> E[Core agent execution]
  E --> F[Reply payload delivery]
  F --> G[Streaming card or final message]
  E --> H[Settled cleanup]

## Best Possible Solution

Define one Feishu pre-reply feedback lifecycle that starts only after acceptance, reuses the first visible response surface, and deterministically discards or settles it on every terminal path; add focused lifecycle coverage for create/stop races and no-content turns.
