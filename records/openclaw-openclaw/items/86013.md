## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P2] Preserve repeated pipes in normal LINE text:** `extensions/line/src/markdown-to-line.ts:413`
  - body: This cleanup says it only removes table-edge remnants, but the second replace removes any doubled pipe sequence anywhere in ordinary text. A LINE reply like `cmd || echo failed` is no table artifact and currently survives markdown stripping, but this PR turns it into `cmd  echo failed`, corrupting user-visible message content.
  - confidence: 0.93
- **[P2] Use LINE's 30 KB bubble limit for markdown Flex:** `extensions/line/src/auto-reply-delivery.ts:132`
  - body: The markdown path creates Flex bubbles, and the LINE reference limits bubble JSON to 30 KB, while this guard permits contents up to 32,568 bytes and even comments that 50 KB applies. A generated table/code bubble between those sizes can still be sent and rejected, so the silent-loss class remains for exactly the path this guard is meant to protect.
  - confidence: 0.9
- **[P2] Use LINE's 30 KB bubble limit for directive Flex:** `extensions/line/src/reply-payload-transform.ts:312`
  - body: The directive path also builds single-bubble cards, but this new guard only falls back after `contents` exceeds 32,768 bytes. That leaves 30-32 KB event/device/agenda bubbles eligible to reach LINE and fail validation instead of falling back to text.
  - confidence: 0.88
- **[P2] Keep the oversized Flex fixture typed as a Flex bubble:** `extensions/line/src/auto-reply-delivery.test.ts:253`
  - body: `largeContents` is inferred with widened `string` fields, so the new `processLineMessage` override is not assignable to `ProcessedLineMessage` and CI's `check-test-types` fails. Type the fixture as a Flex bubble/container or use `as const` so the test suite type-checks.
  - confidence: 0.98
