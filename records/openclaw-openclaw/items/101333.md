## Summary

Keep this PR open: current main still lacks layered Tailscale-plus-shared-secret authentication, and the proposed Gateway boundary is directionally appropriate, but the current config contract can silently ignore the security requirement for unsupported auth modes and still needs explicit security-owner approval.

## What This Changes

The PR adds an opt-in `gateway.auth.requireTailscaleSharedSecret` setting, related config metadata and documentation, layered Tailscale-plus-token/password WebSocket authentication, and session invalidation when that policy changes.

## Best Possible Solution

Keep layered authentication in the Gateway auth owner, but fail closed unless the option is paired with `token` or `password` and a resolved secret, explicitly decide the session-generation coupling, and prove the final exact head through a real Gateway WebSocket and runtime-toggle flow.
