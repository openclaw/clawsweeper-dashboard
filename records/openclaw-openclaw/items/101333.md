## What This Changes

Adds an opt-in Gateway auth setting that layers token/password authentication over verified Tailscale Serve identity, rotates affected session generations, validates configuration, documents the setting, and adds Gateway tests.

## Best Possible Solution

Define the setting as a strict boundary: require verified Tailscale identity and token/password on every applicable WebSocket connection, suppress or layer-check device-token fallback, reject an effective `allowTailscale: false`, preserve the default-off behavior, align all security docs, and provide current-head live Gateway proof for initial connection, reconnect, and hot-toggle invalidation.
