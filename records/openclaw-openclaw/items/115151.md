## What This Changes

Stop Doctor from repeatedly reporting an already-preserved inferred `plugins.bundledDiscovery = "compat"` SQLite value as a fresh migration on separate beta CLI processes.

## System Context

Doctor preflight derives machine-state candidates from canonical configuration and imports them into shared SQLite state before CLI commands run. Its result is then rendered as migration and Doctor-change output for commands such as `status --deep` and gateway restart.

## Architecture Diagram

flowchart LR
  A[CLI command starts] --> B[Doctor preflight]
  B --> C[Config and version metadata]
  C --> D[Bundled discovery candidate]
  D --> E[Shared SQLite machine state]
  E --> F[Import result classification]
  F --> G[Doctor changes output]
  G --> H[Status or gateway command]

## Best Possible Solution

Preserve the existing inferred compatibility value, but make the migration result converge: report only actual imports as Doctor changes, or suppress `kept` results for inferred candidates that have no explicit retired raw-config field; cover the second independent process/pass with a regression test.
