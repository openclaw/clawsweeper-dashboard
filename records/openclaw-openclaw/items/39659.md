## Summary

Keep open. Current main and v2026.6.11 still provide manual profile, env, Docker Compose, and ClawDock primitives, but not the requested first-class Docker instance create/list/delete/update lifecycle; related open work covers narrower sandbox, schema, or profile-targeting overlap.

## What This Changes

Request first-class Docker multi-instance lifecycle commands for create/list/delete/update with isolated persistence, Compose/container names, ports, config/workspace dirs, update, and cleanup.

## Best Possible Solution

Define a maintainer-approved minimal Docker instance lifecycle that keeps security choices explicit and standardizes instance identity, ports, persistence, update/delete, docs, and sandbox coordination.

Options:

- **Approve a minimal core lifecycle (recommended):** Design a narrow core-owned instance command set with explicit persistence, port, Compose project, update/delete, doctor, and sandbox semantics before implementation.

- **Route to external helper or plugin:** Let a maintained ClawDock-style helper own orchestration while core only adds missing APIs if the helper cannot express a safe workflow.
