## Summary

Keep open: current main still ignores the OpenAI Chat Completions `refusal` field in both completions stream assemblers, while the OpenAI types and existing Responses paths treat refusals as user-visible output; no merged related item owns this exact chat-completions drop.

## What This Changes

The issue asks OpenClaw to surface OpenAI Chat Completions refusal-only responses instead of resolving the assistant turn to empty content.

## Best Possible Solution

Teach both chat-completions assemblers to route `delta.refusal` and aggregated `message.refusal` through the visible text path, with focused regression coverage for streaming and aggregated refusal-only responses.
