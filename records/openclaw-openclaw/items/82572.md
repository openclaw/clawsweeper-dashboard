## Summary

This PR addresses a real current-main gap, but it is not ready to merge as an exactly-once restart-recovery change. The added SQLite acknowledgement occurs after the external follow-up execution, so a crash in that interval can restore and repeat an already delivered message; the current PR proof also does not match the latest head `cfdaabbd4f6a0810be772b346da5b2367a8b1101`.

## What This Changes

The branch stores active follow-up queues in shared SQLite, migrates the retired JSON sidecar with Doctor, restores queues at gateway startup, and wakes affected sessions so queued messages can resume draining.

## System Context

Follow-up queues hold additional inbound messages while an agent turn is active. This change moves those pending queue entries from process memory into OpenClaw's shared state database, then routes restored entries back through gateway wake and normal queue-drain behavior after restart.
