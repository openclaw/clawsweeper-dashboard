## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Persist reply-to mode for restored queued runs:** `src/auto-reply/reply/queue/persist.ts:150-168`
  - body: `PersistedFollowupRun` keeps `originatingReplyToId` but not `originatingReplyToMode`. After a restart, a queued item from a route configured with `replyToMode: "off"` restores with the reply target but without the mode, so the followup delivery path can quote/thread the response even though the original turn explicitly disabled native replies. Please persist and round-trip `originatingReplyToMode` with a restart test.
  - confidence: 0.91
- **[P1] Persist chat type with the restored run context:** `src/auto-reply/reply/queue/persist.ts:94-104`
  - body: The persisted run descriptor skips `run.chatType`, but restored followups pass `run.chatType` into `runEmbeddedAgent` and include it in delivery-context grouping. A group/channel followup queued before restart can resume as an unknown chat type, changing prompt/tool capability context and batching behavior. Add `chatType` to the run allowlist and cover group/channel restore.
  - confidence: 0.86
