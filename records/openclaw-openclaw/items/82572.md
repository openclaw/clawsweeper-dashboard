## Summary

This is a credible, proof-backed restart-durability feature, but it should remain open for maintainer review: its crash boundary is intentionally at-least-once rather than exactly-once, and the legacy-sidecar migration needs a shipped-contract decision before landing.

## What This Changes

This PR stores follow-up messages queued during active agent turns in shared SQLite, migrates an old JSON sidecar through Doctor, and wakes restored sessions after gateway startup so queued work can resume delivery.

## System Context

Follow-up queues buffer messages that arrive while an agent turn is active. This change persists that buffer in the shared state database, then uses the gateway’s startup and heartbeat path to restore a route and let its normal agent callback resume delivery.

## Architecture Diagram

  Queue --> State[Shared SQLite state]
  State --> Restore[Gateway startup restore]
  Restore --> Wake[Targeted recovery wake]
  Wake --> Runner[Normal agent turn callback]
  Runner --> Delivery[Channel message delivery]

## Best Possible Solution

Rebase onto current main, retain SQLite as the sole runtime state path, remove the JSON-sidecar migration unless a tagged released contract proves it is needed, and merge only after maintainers explicitly accept the documented at-least-once crash/replay boundary.
