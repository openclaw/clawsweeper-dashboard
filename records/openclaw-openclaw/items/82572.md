## What This Changes

This PR persists followup queues in shared SQLite, migrates a legacy JSON sidecar through Doctor, restores queued state after gateway restart, and wakes affected sessions so queued messages can drain.

## System Context

Followup queues hold messages received while an agent turn is active. This change moves that transient queue state into OpenClaw's shared SQLite database, then has gateway startup restore entries and trigger the normal session/heartbeat path that eventually drains them to the originating channel.
