## Summary

This is a substantive restart-recovery feature with credible exact-head Telegram proof, but it changes persistent queue semantics, gateway wake behavior, Doctor migration, and SQLite state ownership. The remaining question is maintainer product and upgrade acceptance—not a safely automatic cleanup or close.

## What This Changes

The PR stores pending follow-up queues in the shared SQLite state database, imports the retired JSON queue sidecar through Doctor, and wakes restored routes after gateway startup so their queued work can resume.

## System Context

Follow-up queues hold messages received while an agent turn is active. This change moves their pending state from process memory into the shared state database, then uses gateway recovery and heartbeat wake-up paths to cause normal route-specific draining after a restart.

## Architecture Diagram
