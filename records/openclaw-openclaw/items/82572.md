## What This Changes

This PR stores pending follow-up queues in OpenClaw’s shared SQLite state database, migrates the retired JSON sidecar through Doctor, restores queues after gateway startup, and wakes affected sessions so normal queue draining can resume.

## System Context

Follow-up messages enter an in-memory queue while an agent turn is active. This change makes that queue durable across a gateway restart, then routes restored work back through the gateway heartbeat and normal follow-up drain path for delivery to the original channel.
