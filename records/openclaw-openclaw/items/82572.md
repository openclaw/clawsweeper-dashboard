## Summary

This PR addresses a real restart-recovery gap and includes exact-head Telegram delivery evidence, but it still has the previous P2 state-directory bug: the Doctor migration can delete a custom state directory’s legacy sidecar after writing its queue entries to the default shared database. Keep it open for that narrow repair before merge.

Likely related people: `steipete` and `vincentkoc` were both explicitly brought into the PR discussion; this is low-confidence routing evidence rather than ownership attribution.

## What This Changes

This PR stores pending follow-up queues in shared SQLite, migrates the retired JSON sidecar through Doctor, and schedules gateway recovery wakes so restored routes can drain after restart.

## System Context

Follow-up queues hold messages received while an agent turn is active. The gateway persists those queues before process loss, restores them from shared state on startup, then wakes the affected session so the ordinary follow-up drain path can deliver the retained message.

## Best Possible Solution

Open the shared-state write transaction with the same state-directory options used by queue reads, then add a regression that migrates a sidecar from a custom state directory and verifies both the destination database and sidecar removal occur in that same directory.
