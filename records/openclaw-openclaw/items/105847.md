## Label Justifications

- `impact:session-state`: The invalid image item is persisted in the native Codex rollout and requires binding cleanup to avoid continued poisoned-thread behavior.

## Summary

Keep open: current main sanitizes OpenClaw-originated structured images and mirrored Codex history, but the reported invalid item is created inside the current Codex code-mode cell before OpenClaw regains control; the merged replay sanitizer does not solve that boundary.

## What This Changes

Prevent Codex code mode from converting a browser screenshot’s textual share hint into an invalid `input_image.image_url` that triggers provider rejection and model fallback.

## Best Possible Solution

Fix `normalize_output_image()` upstream to accept only validated supported image data or structured MCP image blocks, then update OpenClaw’s managed Codex version and add an end-to-end regression proving browser share-hint text never reaches the provider as an image; retain OpenClaw sanitization as defense in depth rather than relying on fallback recovery.
