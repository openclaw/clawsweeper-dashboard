## Summary

Keep open for a maintainer contract decision. Available current-main documentation and source evidence still describe the runtime workspace as `/home/node/.openclaw/workspace`, while `/workspace` is used by the sandbox; the request is a plausible container ergonomics improvement, but choosing an image alias or a second mount changes that boundary and should not be inferred from an unmerged prior PR.

## What This Changes

Add a `/workspace` alias in OpenClaw Docker and Podman runtime containers so paths commonly used in agent instructions resolve to the persisted agent workspace.

## System Context

OpenClaw’s Docker and Podman deployment paths mount persistent host state into the gateway and CLI containers, while sandbox containers use a separate `/workspace` work directory. Agent instructions and workspace tools consume the runtime workspace path, so an alias must preserve persistence, ownership, and the distinct sandbox contract.

## Architecture Diagram

## Best Possible Solution

Choose and document one supported distinction: either retain `/home/node/.openclaw/workspace` as the sole runtime path and remove ambiguous runtime references, or add a deliberately tested alias across Docker, generated setup, Podman, Quadlet, and container smoke coverage without changing sandbox host-bind behavior.
