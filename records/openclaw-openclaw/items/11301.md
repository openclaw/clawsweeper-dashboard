## Summary

Keep open. Current main and latest release still expose Docker/Podman runtime workspaces at `/home/node/.openclaw/workspace` without a runtime `/workspace` alias, and the direct fixing PR was closed unmerged.

## What This Changes

The issue requests a `/workspace` alias in container configuration so documented agent workspace paths do not require `/home/node/.openclaw/workspace`.

## Best Possible Solution

Maintainers should choose the runtime workspace contract, then either implement `/workspace` consistently across Dockerfile, Compose, Docker setup, Podman/Quadlet, docs, and smoke coverage, or document `/workspace` as sandbox-only.

## Reproduction Assessment

Yes, at source level: current Dockerfile, Compose, Docker setup, Podman, and Quadlet runtime paths still point to `/home/node/.openclaw/workspace` with no runtime `/workspace` alias. I did not run a live container in this read-only review.

## Solution Assessment

Unclear. The one-line symlink is plausible prior art, but the best solution needs a maintainer choice between image symlink, parallel bind mount, or documenting `/workspace` as sandbox-only.
