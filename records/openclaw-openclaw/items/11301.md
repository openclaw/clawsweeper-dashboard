## Summary

Keep open. Current main and latest release still expose Docker/Podman runtime workspaces at `/home/node/.openclaw/workspace` without a `/workspace` alias, the direct related PR was closed unmerged, and the adjacent Docker-out-of-Docker sandbox issue does not replace this runtime-container alias decision.

## What This Changes

The issue requests a `/workspace` alias in OpenClaw container environments so documented agent paths do not require `/home/node/.openclaw/workspace`.

## Best Possible Solution

Maintainers should choose the runtime workspace contract, then either implement `/workspace` consistently across Dockerfile, Compose, Docker setup, Podman/Quadlet, docs, and smoke coverage, or document `/workspace` as sandbox-only.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 still show Docker, Compose, Docker setup, Podman, and Quadlet runtime workspace paths at `/home/node/.openclaw/workspace` with no `/workspace` alias; I did not run a live container in this read-only review.

## Solution Assessment

Unclear. The one-line symlink from the closed prior PR is plausible prior art, but the best fix needs a maintainer decision on image symlink versus parallel bind mount versus documenting `/workspace` as sandbox-only.
