## Summary

Keep open. Current main and v2026.6.11 still expose Docker and Podman runtime workspaces only at `/home/node/.openclaw/workspace`, while `/workspace` remains a sandbox convention, so this still needs a maintainer workspace-contract decision.

## What This Changes

The issue asks OpenClaw container runtimes to expose `/workspace` as an alias to `/home/node/.openclaw/workspace` so documented agent paths work in Docker and Podman containers.

## Best Possible Solution

Maintainers should choose one runtime-container workspace contract, then either implement `/workspace` consistently across Dockerfile, Compose, Docker setup, Podman/Quadlet, docs, and smoke proof, or document `/workspace` as sandbox-only.
