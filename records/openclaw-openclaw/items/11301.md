## Summary

Keep open. Current main and the latest shipped release still expose Docker and Podman runtime workspaces only at `/home/node/.openclaw/workspace`, while `/workspace` remains a sandbox-container convention and the direct symlink PR was closed unmerged.

## What This Changes

Request to expose the OpenClaw container workspace at `/workspace`, for example as an alias to `/home/node/.openclaw/workspace`, so agent workspace paths work consistently in Docker/Podman containers.

## Best Possible Solution

Maintainers should choose one runtime container workspace contract, then either implement `/workspace` consistently across Dockerfile, Compose, Docker setup, Podman/Quadlet, docs, and smoke proof, or document `/workspace` as sandbox-only.
