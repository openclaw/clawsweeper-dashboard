## Summary

Keep open: current main still exposes gateway and CLI container workspaces at `/home/node/.openclaw/workspace`, while `/workspace` remains the sandbox-container convention; the earlier direct symlink PR closed unmerged, and maintainers still need to choose whether the alias becomes a supported runtime-container contract. ([github.com](https://github.com/openclaw/openclaw/blob/main/Dockerfile))

## What This Changes

Add a `/workspace` compatibility alias for the canonical workspace inside OpenClaw gateway and CLI containers.

## Best Possible Solution

Keep `/home/node/.openclaw/workspace` as the canonical configured path, add a tested image-level `/workspace` compatibility symlink for official gateway and CLI images if maintainers approve the contract, and document clearly that nested sandbox containers independently mount their own workspace at `/workspace`.
