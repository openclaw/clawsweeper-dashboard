## Summary

Current main and v2026.6.11 still distinguish runtime-container workspaces at `/home/node/.openclaw/workspace` from sandbox workspaces at `/workspace`; the requested alias remains a valid but non-blocking product choice, and no merged PR or canonical issue supersedes it.

## What This Changes

Add `/workspace` as an alias for `/home/node/.openclaw/workspace` in OpenClaw runtime containers.

## Best Possible Solution

Keep one documented canonical runtime workspace path unless maintainers explicitly adopt `/workspace`; if they do, implement and test the alias consistently across Docker and Podman runtime flows, otherwise correct any specific prompt or documentation that implies `/workspace` outside sandboxes.
