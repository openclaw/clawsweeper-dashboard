## Summary

Current main and v2026.6.11 still distinguish runtime-container workspaces at `/home/node/.openclaw/workspace` from sandbox workspaces at `/workspace`. The direct symlink PR closed unmerged, no replacement owns this exact request, and maintainers must decide whether the alias should become a supported cross-runtime contract.

## What This Changes

Add a `/workspace` alias inside OpenClaw runtime containers that points to the configured workspace.

## Best Possible Solution

Keep `/home/node/.openclaw/workspace` canonical, then either expose `/workspace` consistently across Docker and Podman runtime containers with ownership and smoke proof, or preserve sandbox-only semantics and remove ambiguous runtime-facing `/workspace` references.
