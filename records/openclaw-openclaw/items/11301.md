## Summary

Keep open. Current main still uses `/home/node/.openclaw/workspace` for gateway and CLI runtime containers, while `/workspace` remains the sandbox-container convention; the earlier direct-symlink PR closed unmerged, leaving a genuine product-contract decision rather than an implemented fix.

## What This Changes

Add a `/workspace` alias in OpenClaw runtime containers that resolves to the canonical `/home/node/.openclaw/workspace` directory.

## Best Possible Solution

Define `/workspace` as a tested runtime-container compatibility alias while retaining `/home/node/.openclaw/workspace` as canonical, document its distinction from sandbox mounts, and cover packaged Docker and Podman behavior.
