## Summary

Keep open for product direction. Current main still gives gateway and CLI containers the canonical path `/home/node/.openclaw/workspace`, while `/workspace` remains an explicit sandbox workdir and reserved mount target; the earlier direct-symlink PR closed unmerged, and the recent maintainer-side review also kept this distinction unresolved. ([github.com](https://github.com/openclaw/openclaw/blob/main/docker-compose.yml?utm_source=openai))

## What This Changes

Requests a `/workspace` alias in runtime Docker and Podman containers that points to `/home/node/.openclaw/workspace`.

## Best Possible Solution

Choose one explicit contract: preferably keep `/workspace` sandbox-only and remove or qualify ambiguous runtime-container references; if maintainers instead support the alias, implement and document it consistently across Docker, Compose/setup, Podman/Quadlet, and container smoke coverage while preserving sandbox and multi-agent semantics.
