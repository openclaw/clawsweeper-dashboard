## Summary

Keep open. Current main and latest release v2026.6.11 still expose Docker and Podman runtime workspaces at `/home/node/.openclaw/workspace` without a `/workspace` alias, while https://github.com/openclaw/openclaw/pull/12764 was closed unmerged and https://github.com/openclaw/openclaw/issues/31331 tracks an adjacent Docker-out-of-Docker sandbox bind-source problem rather than this runtime alias contract.

## What This Changes

The issue requests a container-level `/workspace` alias to `/home/node/.openclaw/workspace` so agent-facing documentation paths work inside Docker/Podman runtime containers.

## Best Possible Solution

Maintainers should choose the runtime workspace contract, then either implement `/workspace` consistently across Dockerfile, Compose, Docker setup, Podman/Quadlet, docs, and smoke coverage, or document `/workspace` as sandbox-only.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 still show Docker, Compose, Docker setup, Podman, and Quadlet runtime workspace paths at `/home/node/.openclaw/workspace` with no `/workspace` alias; I did not run a live container in this read-only review.

## Solution Assessment

Unclear. The one-line Dockerfile symlink from the closed prior PR is useful prior art, but the best fix needs a maintainer decision on image symlink versus parallel bind mount versus documenting `/workspace` as sandbox-only.
