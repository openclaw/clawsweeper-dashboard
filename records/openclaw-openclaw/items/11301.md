## Summary

Keep open. Current main and v2026.6.11 still expose Docker and Podman runtime workspaces at `/home/node/.openclaw/workspace` without a runtime-container `/workspace` alias, while the direct fix PR was closed unmerged and the open Docker-out-of-Docker report tracks an adjacent sandbox bind-source problem rather than this alias contract.

Requested adding a `/workspace` alias in container configuration so documented agent paths match runtime containers.

## Best Possible Solution

Maintainers should choose the runtime workspace contract, then either implement `/workspace` consistently across Dockerfile, Compose, Docker setup, Podman/Quadlet, docs, and smoke coverage, or document `/workspace` as sandbox-only.

## Solution Assessment

Unclear. The proposed one-line symlink is plausible prior art, but the best fix needs a maintainer decision on image symlink versus parallel bind mount versus documenting `/workspace` as sandbox-only, followed by matching docs and smoke coverage.
