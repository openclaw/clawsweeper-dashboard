## Summary

Keep open. Current main and v2026.6.11 still expose runtime Docker/Podman container workspaces only at `/home/node/.openclaw/workspace`, the direct symlink pull request was closed unmerged, and the remaining choice is a maintainer product decision about whether `/workspace` should be a runtime-container alias or stay sandbox-only.

## What This Changes

Request to expose the agent workspace at `/workspace` in containerized OpenClaw runtime environments, likely via a symlink or equivalent mount contract.

## Best Possible Solution

Maintainers should choose one container workspace contract, then either implement `/workspace` consistently across Dockerfile, Compose, Docker setup, Podman/Quadlet, docs, and smoke coverage, or document `/workspace` as sandbox-only and remove runtime ambiguity.
