Keep open. Current main and v2026.6.11 still expose runtime Docker/Podman workspaces at `/home/node/.openclaw/workspace` while `/workspace` remains a sandbox-container convention, so the issue still needs a maintainer decision on the container workspace contract.

## What This Changes

The issue requests adding a `/workspace` alias in OpenClaw container configuration so documented agent paths work without using `/home/node/.openclaw/workspace`.

## Best Possible Solution

Maintainers should choose one container workspace contract, then either implement `/workspace` consistently across Dockerfile, Compose, Docker setup, Podman/Quadlet, docs, and smoke coverage, or document `/workspace` as sandbox-only.
