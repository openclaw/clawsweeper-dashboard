## Summary

Keep open for a maintainer product decision. Current main still provides no runtime-container `/workspace` alias, while Docker persistence deliberately uses `/home/node/.openclaw/workspace` and sandbox containers use `/workspace`; the request is plausible ergonomics work but needs an explicit supported-path contract before implementation.

## What This Changes

Add a `/workspace` alias in Docker/Podman runtime containers for the persisted OpenClaw workspace path.

## Best Possible Solution

Choose one documented contract: retain `/home/node/.openclaw/workspace` as the only runtime-container path, or add a tested compatibility alias across supported container launchers while explicitly limiting its meaning to the default persisted runtime workspace.
