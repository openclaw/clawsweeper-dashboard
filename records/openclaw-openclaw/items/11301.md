## Summary

Keep open. Current main and v2026.6.11 still do not provide a runtime-container `/workspace` alias; the direct symlink PR is closed unmerged, and the related Docker sandbox report is adjacent rather than a replacement.

## What This Changes

Request to add a `/workspace` alias or equivalent container configuration so documented workspace paths work inside agent/runtime containers.

## Best Possible Solution

Maintainers should choose the runtime workspace contract, then either implement `/workspace` consistently across Dockerfile, Compose, Docker setup, Podman/Quadlet, docs, and smoke coverage, or document `/workspace` as sandbox-only.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 show runtime container workspaces mounted under `/home/node/.openclaw/workspace` with no `/workspace` alias; I did not run a live container in this read-only review.

## Solution Assessment

Unclear. The one-line symlink is plausible prior art, but the best fix needs a maintainer decision on image symlink versus parallel bind mount versus documenting `/workspace` as sandbox-only.
