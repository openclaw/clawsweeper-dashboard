## Summary

Keep open. Current main and the latest release still expose Docker/Podman runtime container workspaces at `/home/node/.openclaw/workspace` without a `/workspace` alias, while the prior direct fix PR was closed unmerged and the related open Docker sandbox issue tracks a different bind-source problem.

## What This Changes

The issue requests a runtime container `/workspace` alias to `/home/node/.openclaw/workspace` so documented agent paths work without using the full home path.

## Best Possible Solution

Maintainers should choose the runtime workspace contract, then either implement `/workspace` consistently across Dockerfile, Compose, Docker setup, Podman/Quadlet, docs, and smoke coverage, or document `/workspace` as sandbox-only.

## Reproduction Assessment

Yes, at source level. Current main and `v2026.6.11` still show Docker, Compose, Docker setup, Podman, and Quadlet runtime workspace paths at `/home/node/.openclaw/workspace` with no `/workspace` alias.

## Solution Assessment

Unclear. The one-line symlink from the closed prior PR is plausible prior art, but the best solution needs a maintainer decision on image symlink versus parallel bind mount versus documenting `/workspace` as sandbox-only.
