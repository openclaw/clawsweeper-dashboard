## Summary

Keep open. Current main and v2026.6.11 still expose Docker/Podman runtime workspaces at `/home/node/.openclaw/workspace` while `/workspace` remains a sandbox-container convention; the direct symlink pull request was closed unmerged and the related Docker-out-of-Docker report tracks a different host-path failure.

## What This Changes

The issue asks OpenClaw to expose the agent workspace at `/workspace` inside Docker/Podman runtime containers instead of only at `/home/node/.openclaw/workspace`.

## Best Possible Solution

Maintainers should choose one container workspace contract, then either implement `/workspace` consistently across Dockerfile, Compose, Docker setup, Podman/Quadlet, docs, and smoke coverage, or document `/workspace` as sandbox-only.
