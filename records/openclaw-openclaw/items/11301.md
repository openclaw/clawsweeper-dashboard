## Summary

Keep open. Current main and v2026.6.11 still expose runtime Docker/Podman workspaces only at `/home/node/.openclaw/workspace`; `/workspace` remains sandbox-specific, and the direct symlink PR was closed unmerged.

## What This Changes

The issue requests a runtime container `/workspace` symlink or alias so agents do not need to use `/home/node/.openclaw/workspace` directly.

## Best Possible Solution

Maintainers should choose the runtime container workspace contract, then either implement `/workspace` consistently across Dockerfile, Compose, Docker setup, Podman/Quadlet, docs, and smoke coverage, or document `/workspace` as sandbox-only.
