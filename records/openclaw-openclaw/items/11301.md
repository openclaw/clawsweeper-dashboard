## Summary

Keep open. Current main and v2026.6.11 still expose Docker and Podman runtime container workspaces only at `/home/node/.openclaw/workspace`, while `/workspace` is still a sandbox-container convention, so this remains a maintainer workspace-contract decision rather than cleanup closure.

## What This Changes

The issue requests a `/workspace` alias or symlink in runtime container configuration so documented workspace paths work without using `/home/node/.openclaw/workspace`.

## Best Possible Solution

Maintainers should choose one runtime container workspace contract, then either implement `/workspace` consistently across Dockerfile, Compose, Docker setup, Podman/Quadlet, docs, and smoke proof, or document `/workspace` as sandbox-only.
