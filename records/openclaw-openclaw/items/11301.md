## Summary

Keep open. Current main and v2026.6.11 still expose Docker and Podman runtime container workspaces only at `/home/node/.openclaw/workspace`, while `/workspace` remains a sandbox-container convention, so this still needs a maintainer workspace-contract decision rather than cleanup closure.

## What This Changes

Request to expose the container agent workspace at `/workspace`, likely by aliasing it to `/home/node/.openclaw/workspace`, so container paths match the expected agent workspace shortcut.

## Best Possible Solution

Maintainers should choose one runtime container workspace contract, then either implement `/workspace` consistently across Dockerfile, Compose, Docker setup, Podman/Quadlet, docs, and smoke proof, or document `/workspace` as sandbox-only.
