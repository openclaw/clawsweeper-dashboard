## Summary

Keep open: current main still hardwires macOS Push-to-Talk transcription to Apple Speech, while `tools.media.audio` is a separate batch media-understanding path. The broader custom ASR issue overlaps, but this issue preserves a useful PTT-specific product/security slice that maintainers still need to decide.

## What This Changes

Request a pluggable STT backend for native macOS Push-to-Talk, with Apple Speech remaining the default and an optional batch path through Gateway media-audio or a private/local ASR backend.

## Best Possible Solution

Define a narrow batch-only native PTT STT boundary that keeps Apple Speech as the default, reuses existing media-audio/provider security contracts where chosen, and documents credential, network, fallback, and overlay-state behavior before implementation.
