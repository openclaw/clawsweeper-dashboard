## Label Justifications

- `impact:security`: The requested backend would route microphone audio and possibly credentials or private endpoint URLs to configurable STT infrastructure.

## Summary

Keep open: current main still hardwires native macOS Push-to-Talk to Apple Speech and only forwards finalized text, while `tools.media.audio` remains a separate Gateway media-understanding path. The request is valid, but it needs maintainer product and security direction before implementation.

## What This Changes

Request to let native macOS Push-to-Talk use a selectable STT backend, including Gateway `tools.media.audio` or local/private ASR, while preserving Apple Speech as the default.

## Best Possible Solution

Design a narrow batch-only native PTT STT seam that keeps Apple Speech as the default, bridges to existing Gateway media-audio/provider security contracts for the first selectable backend, and documents credential, network, fallback, and overlay-state behavior before implementation.
