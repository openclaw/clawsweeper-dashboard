## Summary

Keep open: current main and v2026.6.11 still use Apple Speech for native macOS Push-to-Talk, while `tools.media.audio` and Talk transcription are separate Gateway/provider surfaces. The request remains valid but needs maintainer product/API/security design before implementation.

## What This Changes

Request to let native macOS Push-to-Talk use a configurable STT backend instead of always transcribing through Apple Speech.

## Best Possible Solution

Define a narrow native PTT STT boundary that preserves Apple Speech as the default, reuses existing provider/media contracts where maintainers choose, and documents credential, network, fallback, permission, and overlay-state behavior before implementation.
