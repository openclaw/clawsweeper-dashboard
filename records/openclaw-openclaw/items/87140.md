## Summary

Keep open: current main and the latest release still route native macOS Push-to-Talk through Apple Speech, while `tools.media.audio` is a separate media-understanding path. The request remains a valid feature/design item that needs maintainer product and security decisions before implementation.

## What This Changes

Requests a configurable speech-to-text backend boundary for native macOS Push-to-Talk, keeping Apple Speech as the default while allowing batch PTT to use Gateway media audio or local/private ASR.

## Best Possible Solution

Design a narrow native PTT batch-transcription contract that preserves Apple Speech as the default, reuses existing Gateway/media-provider security contracts where appropriate, and makes provider capability, credentials, fallback, and overlay error states explicit before implementation.
