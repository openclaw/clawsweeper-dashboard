## Summary

Keep open: current main and the latest release still keep native macOS Push-to-Talk on Apple Speech, while existing `tools.media.audio` transcription is a separate Gateway/media path. The broader custom-ASR issue is a useful canonical parent, but this issue has a distinct native PTT batch/backend boundary that still needs maintainer product and security design.

## What This Changes

Request a configurable native macOS Push-to-Talk speech-to-text backend that can use Gateway media-audio or private/local ASR instead of only Apple Speech.

## Best Possible Solution

Define a narrow native macOS PTT STT boundary that keeps Apple Speech as the default, supports a batch final-text backend through approved Gateway media-audio/provider contracts, and documents credential, network, fallback, permission, and overlay-state behavior before implementation.
