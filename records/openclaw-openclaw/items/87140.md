## Summary

Keep open: current main and v2026.6.11 still route native macOS Push-to-Talk through Apple Speech, while `tools.media.audio` remains a separate media-understanding surface. This is still a valid feature request, but it needs maintainer product/API/security direction before implementation.

## What This Changes

Request to add a configurable native macOS Push-to-Talk STT backend while preserving Apple Speech as the default and optionally bridging batch audio to Gateway media-audio or local/private ASR.

## Best Possible Solution

Define a narrow native macOS PTT STT boundary that keeps Apple Speech as the default, supports an opt-in batch backend, and reuses existing media-audio/provider security contracts where maintainers choose that owner boundary.

Owner confidence: high

Options:

- **Design PTT batch backend seam (recommended):** Keep Apple Speech as the default, add a final-text batch backend boundary for PTT, and align credentials/network/fallback behavior with existing provider and media-audio controls.
- **Fold into broader custom ASR design:** Treat this issue as a child of https://github.com/openclaw/openclaw/issues/46661 and wait for one native ASR/STT contract that covers multiple platform voice flows.
- **Defer native custom STT:** Keep native PTT Apple Speech-only until maintainers decide configurable ASR endpoints are supportable for the macOS app.
