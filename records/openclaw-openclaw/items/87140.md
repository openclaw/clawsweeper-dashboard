## Summary

Keep open: current main and v2026.6.11 still run native macOS Push-to-Talk through Apple Speech, while the existing OpenAI-compatible `tools.media.audio` path is a separate media-understanding surface. The request remains useful, but it needs maintainer product and security design before implementation because it would add native STT backend selection, credential handling, private-network policy, and fallback behavior.

## What This Changes

Request to let native macOS Push-to-Talk use a configurable speech-to-text backend, such as Gateway `tools.media.audio` or a local/private ASR service, while keeping Apple Speech as the default.

## Best Possible Solution

Design a narrow native PTT STT boundary that preserves Apple Speech as the default, starts with final-text batch mode, and reuses existing Gateway media/provider security contracts where maintainers choose that owner boundary.

Options:

- **Defer native backend selection:** Keep native PTT on Apple Speech until the team has a broader native ASR plan across PTT, Talk, wake-word, and mobile surfaces.
- **Route only through external/plugin surfaces:** Close or narrow the core request if maintainers decide sidecars or plugin/provider paths are sufficient and native capture should not gain a backend seam.
