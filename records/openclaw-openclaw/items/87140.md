## Summary

Keep open: current main and v2026.6.11 still route native macOS Push-to-Talk through Apple Speech, while `tools.media.audio` is a separate Gateway media-understanding path. This remains a valid feature request that needs product and security design before implementation.

## What This Changes

Request a configurable STT backend for native macOS Push-to-Talk, preserving Apple Speech by default and optionally routing batch audio through Gateway media audio or local/private ASR.

## Best Possible Solution

Define a narrow batch PTT STT boundary that keeps Apple Speech as the default, aligns with existing provider/media-audio security contracts, and makes credential, private-network, fallback, and overlay-state behavior explicit before implementation.
