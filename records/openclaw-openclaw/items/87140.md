## Summary

Keep open: current main and v2026.6.11 still hardwire native macOS Push-to-Talk transcription to Apple Speech, while `tools.media.audio` remains a separate Gateway media-understanding path. The request is valid but needs maintainer product and security design before implementation.

## What This Changes

The issue requests a configurable native macOS Push-to-Talk speech-to-text backend so Apple Speech remains the default while batch PTT can route through Gateway media audio or trusted private/local ASR.

## Best Possible Solution

Design a narrow batch-only native PTT STT boundary that keeps Apple Speech as the default, reuses existing Gateway media-audio/provider security contracts where chosen, and documents backend selection, credential isolation, network policy, fallback, and overlay-state behavior before implementation.
