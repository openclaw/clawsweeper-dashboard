## Summary

Keep open: current main and the latest release still wire native macOS Push-to-Talk directly to Apple Speech, while `tools.media.audio` is a separate Gateway media-understanding path. The request is valid but needs maintainer product and security design before implementation.

## What This Changes

Request a configurable STT backend for native macOS Push-to-Talk, preserving Apple Speech as the default while allowing a batch backend such as `tools.media.audio` or a local/private ASR service.

## Best Possible Solution

Design a narrow native macOS PTT STT boundary that keeps Apple Speech as the default, adds an opt-in batch backend, and reuses existing media-audio/provider security contracts where maintainers choose that owner boundary.
