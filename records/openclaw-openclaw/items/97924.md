## Summary

Keep open: current main has typed plugin `session_end` hooks and cron schedule forms, but it still lacks a cron-subscribable session archive/rotation event. The remaining work is choosing the public lifecycle automation contract and its security boundary.

## What This Changes

Add a session archive/rotation lifecycle trigger that can run cron or agent-turn automation once when a session is archived.

## Best Possible Solution

Define one maintained lifecycle automation contract: preferably plugin `session_end` plus the smallest SDK scheduling/event seam external plugins need, or explicitly add core cron event schedules with scoped metadata, permissions, durable trace, docs, and upgrade tests.

## Maintainer Decision

Question: Should session archive/rotation automation be supported as a core cron event schedule, as a plugin `session_end` workflow with a narrow missing SDK seam, or not as a new OpenClaw core surface?

Rationale: Current main has the lifecycle hook primitive but not the requested cron subscription surface, and the permanent shape affects public cron config, plugin API boundaries, archived transcript metadata, and security review.

Likely owner: vincentkoc

Owner confidence: high

Options:

- **Use plugin lifecycle plus narrow SDK seam (recommended):** Bless plugin `session_end` as the session-boundary signal and add only the smallest SDK scheduling or event-dispatch capability external plugins need to run this workflow safely.
- **Add core cron lifecycle schedules:** Define `schedule.kind: event` for session archive/rotation in the Gateway protocol with scoped metadata, permissions, persistence, docs, and upgrade tests.
- **Decline new core surface:** If maintainers decide current plugin hooks already cover the use case, route the self-improving memory workflow to a ClawHub/plugin pattern and document that support boundary.

## Reproduction Assessment

Yes, at source level. Current cron schemas/types/docs expose only `at`, `every`, `cron`, and `on-exit`, while session archive/reset currently emits only plugin `session_end` hooks.

## Solution Assessment

Unclear until maintainers choose ownership. The plugin `session_end` path is the leaner VISION-aligned starting point, while core cron event schedules are plausible but broader and security-sensitive.
