## Summary

Keep open: current main has adjacent typed plugin session lifecycle hooks and cron `on-exit`, but it still does not provide a durable session archive/rotation event that cron jobs can subscribe to. The remaining work is a product/API/security decision about the permanent lifecycle automation contract.

## What This Changes

The issue requests an event-driven session archive or rotation lifecycle trigger that cron jobs or agent turns can subscribe to.

## Best Possible Solution

Define one supported lifecycle automation contract: preferably use the existing plugin `session_end` hook plus the smallest external SDK scheduling/event seam needed for safe plugin workflows, or intentionally add core cron event schedules with scoped metadata, permissions, persistence, docs, and tests.
