## Summary

Keep open: current main has adjacent typed plugin `session_end` hooks and cron `on-exit`, but it still does not expose a session archive/rotation event that cron jobs can subscribe to. The remaining work is a product and security decision about the public lifecycle automation contract.

## What This Changes

The issue requests a session archive or rotation lifecycle event that can trigger cron job or agent-turn automation at session boundaries.

## Best Possible Solution

Define one maintained lifecycle automation contract: prefer the existing plugin `session_end` hook plus a narrow SDK scheduling/event seam if external plugins cannot implement the workflow, or explicitly add core cron event schedules with scoped metadata, permissions, persistence, and trace.

Options:

- **Use plugin lifecycle plus narrow SDK seam (recommended):** Bless plugin `session_end` as the session-boundary signal and add only the smallest SDK scheduling or event-dispatch capability that external plugins need to run this workflow safely.
- **Add core cron lifecycle schedules:** Define `schedule.kind: event` for session archive/rotation in the Gateway protocol, with scoped metadata, permissions, persistence, docs, and upgrade tests.
- **Route to plugin or ClawHub:** If current plugin hooks already cover the use case, document the supported plugin pattern and leave the self-improving memory workflow outside core.
