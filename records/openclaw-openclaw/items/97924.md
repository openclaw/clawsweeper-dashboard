## Summary

Keep open: current main still has only adjacent `session_end` plugin hooks and Cron `on-exit`, not a session archive/rotation event schedule that Cron jobs can subscribe to. The remaining work is a product and security decision about the public lifecycle automation contract, not stale cleanup.

## What This Changes

Request to add a session archive/rotation lifecycle trigger that can launch a Cron-backed agent turn or equivalent hook when a session is archived.

## Best Possible Solution

Define one maintained lifecycle automation contract: prefer the existing plugin `session_end` hook plus a narrow SDK scheduling/event seam if external plugins cannot implement this safely, or explicitly add core Cron event schedules with scoped metadata, permissions, persistence, docs, and trace semantics.
