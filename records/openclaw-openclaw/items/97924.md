- `impact:session-state`: The requested trigger is specifically tied to session archive/rotation boundaries and post-session memory analysis.

## Summary

Keep open: current main has adjacent plugin session hooks, compaction rotation behavior, and cron `on-exit`, but it still lacks a durable session archive/rotation event that cron can subscribe to. The remaining decision is where to put that public lifecycle automation contract and how to scope archived-session metadata safely.

## What This Changes

The issue requests a `sessionArchived` or `sessionRotated` lifecycle event that can trigger cron jobs or isolated agent turns when a session is archived or rotated.

## Best Possible Solution

Define one maintained lifecycle automation contract, preferably through the existing plugin `session_end` or compaction hook boundary plus a narrow SDK seam if external plugins cannot implement it, and only add core cron event schedules if maintainers choose that as the product API.
