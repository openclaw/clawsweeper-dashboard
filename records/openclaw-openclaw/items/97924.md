## Summary

Keep open: current main has typed plugin `session_end` lifecycle hooks and cron `on-exit`, but it still does not expose a session archive/rotation event schedule that cron can subscribe to. The remaining work is a product and security decision about whether this belongs in core cron config, a narrow plugin SDK seam, or a plugin-owned workflow.

## What This Changes

The issue requests a session archive/rotation lifecycle trigger that can run cron or agent-turn payloads once per archived session with scoped session metadata.

## Best Possible Solution

Define one maintained lifecycle automation contract: prefer the existing plugin `session_end` hook plus a narrow SDK scheduling/event seam if external plugins cannot implement the workflow, or explicitly add core cron event schedules with scoped metadata, permissions, and durable trace semantics.

Options:

- **Use plugin lifecycle plus narrow SDK seam (recommended):** Bless plugin `session_end` as the session-boundary signal and add only the smallest SDK scheduling or event-dispatch capability that external plugins need to run this workflow safely.
- **Add core cron lifecycle schedules:** Define `schedule.kind: event` for session archive/rotation in the Gateway protocol, with scoped metadata, permissions, persistence, docs, and upgrade tests.
- **Close as plugin-owned workflow:** If maintainers decide current plugin hooks already cover the use case, route the self-improving memory workflow to a ClawHub plugin and close this core request after documenting the supported pattern.
