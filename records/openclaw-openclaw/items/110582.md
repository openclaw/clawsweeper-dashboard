## Summary

Keep this PR open for security/compatibility review: its pre-upgrade gate applies the Control UI origin policy to every Origin-bearing gateway connection, while current main applies that policy only after parsing the client's connect identity for browser UI, webchat, or an explicit all-client enforcement case. The proposed behavior can reject existing non-UI browser clients before protocol authentication, so it is not a transparent relocation of the existing check.

## What This Changes

The PR adds a `verifyClient` callback to reject WebSocket upgrades with disallowed browser Origins before HTTP 101, documents the gate, and adds focused helper tests.

## Best Possible Solution

Preserve the existing client-aware origin-policy boundary unless gateway owners explicitly choose an all-Origin pre-upgrade policy; any approved broader policy needs compatibility coverage for non-UI browser clients and trusted-proxy deployments.
