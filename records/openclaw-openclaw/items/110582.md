## Summary

Keep this PR open, but it is not ready to merge: the new pre-upgrade check applies the Control UI origin policy to every connection with an `Origin` header before the protocol can identify its client type, while current admission only applies that policy to browser/operator/webchat clients or the explicitly broader browser-security case. The earlier P1 blocker therefore remains, and the supplied raw-socket proof is for an older head and does not cover the compatibility-sensitive paths.

## What This Changes

The PR adds a `WebSocketServer.verifyClient` origin gate before the HTTP 101 response, with focused tests and gateway-security documentation.

## Best Possible Solution

Keep origin enforcement client-aware: either retain the existing post-connect decision for non-browser clients or introduce a maintainer-approved pre-upgrade classifier with explicit compatibility tests before rejecting all origin-bearing upgrades.
