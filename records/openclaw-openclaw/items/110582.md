## Label Justifications

- `P1`: The patch changes Gateway WebSocket admission before authentication and can break active Origin-bearing client workflows.
- `merge-risk: 🚨 compatibility`: The new unconditional Origin gate can convert previously admitted non-UI WebSocket upgrades into `403` responses.

## Summary

Keep this PR open for gateway-owner review. The current patch applies the Control UI origin policy to every Origin-bearing WebSocket before protocol/client classification, so it can intentionally or accidentally change compatibility for non-UI clients; the updated PR body also lacks current-head, end-to-end proof for that broader admission path.

## What This Changes

The PR adds a `WebSocketServer.verifyClient` origin gate before the HTTP 101 upgrade, plus helper tests and gateway-security documentation.

## Best Possible Solution

Preserve the existing client-aware origin-policy boundary: add a pre-handshake eligibility predicate that is demonstrably equivalent to the current Control UI scope, or retain post-handshake enforcement for clients that cannot be classified safely before upgrade; then add current-head raw-upgrade proof for direct, proxied, and non-UI Origin-bearing clients.
