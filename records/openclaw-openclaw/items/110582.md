## Summary

Keep open: the pre-upgrade gate is a worthwhile hardening change, but it truncates the untrusted Origin before evaluating the shared policy, so a long Origin with an allowed 256-character prefix can evade this new gate and still complete HTTP 101.

## What This Changes

Adds a Gateway WebSocket `verifyClient` origin check before upgrade, plus focused tests and security documentation.

## Best Possible Solution

Pass the complete Origin header to `checkBrowserOrigin` and add a regression case proving that an overlong Origin sharing an allowed prefix is rejected before HTTP 101.
