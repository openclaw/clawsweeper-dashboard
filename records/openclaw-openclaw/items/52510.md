## Summary

Keep open: current main still emits canonical gateway cleanup commands whenever doctor finds any extra gateway-like service, and the linked closing PR is still open and conflicting. The LaunchAgent detector has been tightened and the SecretRef side has current docs/coverage, but the central cleanup-hint footgun is not implemented on main or in the latest release.

## What This Changes

The issue requests that `openclaw doctor` stop suggesting removal of the active macOS gateway LaunchAgent and handle runtime-resolved `exec:` SecretRefs without a hard doctor failure.

## Best Possible Solution

Land a focused doctor/status fix that suppresses cleanup hints for the active current gateway, renders any cleanup guidance from the detected stale or legacy service metadata, preserves strict runtime SecretRef semantics, and adds macOS LaunchAgent plus SecretRef regression coverage.

## Reproduction Assessment

Yes at source level: any non-empty extra gateway service list reaches a no-argument cleanup-hint helper that still returns canonical profile removal commands. I did not run a live macOS launchd repro in this read-only review.
