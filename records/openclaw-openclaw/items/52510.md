## Summary

Keep open: current main and v2026.6.11 still emit canonical gateway cleanup commands whenever an extra gateway-like service is detected, so the LaunchAgent cleanup footgun remains. Current main has narrowed some launchd false positives and has improved SecretRef doctor handling, but https://github.com/openclaw/openclaw/pull/52515 remains the open, conflicting fix candidate.

## What This Changes

The issue asks doctor/status to stop suggesting removal of the active macOS gateway LaunchAgent and to treat exec-backed SecretRef doctor checks as non-fatal.

## Best Possible Solution

Doctor/status should render cleanup only for the detected stale service or suppress it for the active/current gateway, with focused macOS launchd and SecretRef regression coverage.

## Reproduction Assessment

Yes. Source inspection shows a custom LaunchAgent that executes `openclaw gateway` is reported as extra, then doctor/status unconditionally print cleanup hints for the canonical gateway service; I did not run a live macOS launchd repro in this read-only review.

## Solution Assessment

No. Current main is only a partial fix; the maintainable solution is to make cleanup hints target only detected stale services or suppress them for the active/current gateway, while preserving the safer read-only SecretRef behavior already added.
