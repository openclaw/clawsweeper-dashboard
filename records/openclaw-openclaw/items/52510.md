## Summary

Keep open: current main still emits canonical gateway cleanup commands whenever doctor or status reports any extra gateway-like service, while the linked closing PR remains open and conflicting. The LaunchAgent detector and exec SecretRef handling have improved, but the central cleanup-hint footgun is not fixed on main or in the latest release.

## What This Changes

Doctor should avoid cleanup hints that remove the active macOS gateway LaunchAgent and handle runtime-only exec SecretRefs without a hard doctor failure.

## Best Possible Solution

Land a focused fix that renders cleanup hints from the detected stale or legacy service metadata in both doctor and status, suppresses active current-gateway removal hints, preserves strict runtime SecretRef semantics, and keeps macOS LaunchAgent plus exec SecretRef regression coverage.

## Reproduction Assessment

Yes at source level: any non-empty extra gateway service list reaches a no-argument cleanup-hint helper that still returns canonical active-profile removal commands. I did not run a live macOS launchd repro in this read-only review.

## Solution Assessment

No, current main is not the complete solution; detector and SecretRef behavior are partially improved, but cleanup hints still target the profile service instead of the detected stale service. The best path is to repair, land, close, or replace the linked PR rather than close this issue now.
