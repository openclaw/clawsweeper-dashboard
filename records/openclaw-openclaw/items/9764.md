## Summary

Keep open: current main and v2026.6.11 still have Google Chat wired to service-account credentials and `chat.bot` only, while the related media-fallback work mitigates one symptom without adding user OAuth for reactions, uploads, or proactive DMs.

## What This Changes

The issue requests optional Google Chat user OAuth support for outbound reactions, media uploads, and proactive DMs while preserving service-account webhook and bot-send behavior.

## Best Possible Solution

Keep this as the canonical Google Chat user-OAuth design item until maintainers approve a plugin-local credential model and scoped routing for user-only operations, with docs and fallback behavior aligned to existing service-account setups.

## Reproduction Assessment

Yes for source-level reproduction: current main has only service-account credential resolution and a fixed `chat.bot` auth scope, while the affected reaction/upload/DM helpers share that token path. ## Solution Assessment

Unclear as a final implementation shape: optional user OAuth is the right problem boundary, but the exact config, SecretRef, token-refresh, fallback, and docs behavior need maintainer/security approval before implementation.
