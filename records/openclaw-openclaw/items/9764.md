## Summary

Keep open. Current main and the latest release still route Google Chat through service-account credentials and the `chat.bot` scope only; related media-fallback work covers one symptom but not the requested user OAuth credential model.

## What This Changes

The issue requests optional Google Chat user OAuth support so reactions, media uploads, and proactive DMs can use user-level scopes alongside existing service-account app auth.

## Best Possible Solution

Add a plugin-owned, secret-aware Google user OAuth credential model and scoped OAuth client routing for only the operations that require user auth, while keeping service-account auth for webhook verification and existing bot sends.

## Reproduction Assessment

Yes at source level: current main only accepts service-account credentials and always requests `chat.bot` for Google Chat API calls. I did not run a live Google Workspace repro in this read-only cleanup pass.

## Solution Assessment

Unclear until maintainer/security direction is set; user OAuth is the plausible product path, but the durable fix needs the right SecretRef, scope, fallback, and documentation shape rather than a quick config sketch.
