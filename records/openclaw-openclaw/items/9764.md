- `P2`: This is a normal-priority Google Chat capability gap with real channel impact, but it is a new auth/config feature rather than an urgent core-runtime outage.
- `impact:security`: The requested fix would add OAuth client secrets, refresh tokens, scopes, and credential routing to the Google Chat channel.

## Summary

Keep open. Current main and the latest release still have service-account-only Google Chat auth with the `chat.bot` scope and no user OAuth schema, credential resolution, or operation-level OAuth routing; the related media-fallback work only covers one symptom.

## What This Changes

Add optional user OAuth credentials and routing to Google Chat for reactions, attachment uploads, reaction typing, and proactive DM operations while keeping service-account auth for webhook and bot paths.

## Best Possible Solution

Implement a plugin-owned OAuth model with SecretRef/redaction support, scoped token clients, operation-level auth selection, fallback warnings, docs, and live Google Workspace proof before landing.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes for source-level reproduction: current main accepts only service-account credentials, validates service-account JSON, and always requests `chat.bot` for Google Chat API calls; no live Google Workspace OAuth repro was run.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainer and security direction is set; user OAuth is the plausible product path, but the durable fix needs the right SecretRef, scope, fallback, and documentation shape rather than the issue's config sketch alone.
