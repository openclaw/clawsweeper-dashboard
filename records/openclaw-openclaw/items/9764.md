## Summary

Keep open. Current main and v2026.6.11 still expose Google Chat as a service-account `chat.bot` channel, while the related media fallback work only mitigates one symptom and does not add the requested user OAuth credential/routing model.

## What This Changes

The issue requests optional Google Chat user OAuth support for reactions, media uploads, reaction typing, and proactive DMs while preserving service-account auth for webhook and bot-level behavior.

## Best Possible Solution

Add a plugin-owned, secret-aware Google Chat user OAuth credential model and scoped OAuth client routing for only the operations that require user auth, while keeping service-account auth for webhook verification and current bot sends.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: current main only accepts service-account Google Chat credentials and always requests `chat.bot` for Chat API calls; I did not run a live Google Workspace OAuth repro in this read-only review.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainer/security direction is set; user OAuth is the plausible product path per the Google API contract, but the durable fix needs the right SecretRef, scope, fallback, docs, and validation shape rather than only the issue's config sketch.
