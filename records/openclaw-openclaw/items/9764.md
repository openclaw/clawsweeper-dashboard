## Summary

Keep open: current main and v2026.6.11 still lack Google Chat user OAuth config, refresh-token credential resolution, and scoped user-auth routing; the related media-fallback PRs mitigate one upload symptom but do not implement the requested credential model.

## What This Changes

Request optional Google Chat user OAuth support for reactions, attachment uploads, reaction typing, and proactive DM/email lookup while preserving service-account webhook and bot operations.

## Best Possible Solution

Add a Google Chat plugin-owned, secret-aware user OAuth credential model and route only user-scope-required operations through that client while preserving service-account webhook verification and bot-level sends.

## Reproduction Assessment

Yes, from source inspection: current main accepts only service-account Google Chat credentials and uses one chat.bot auth path for upload, reaction, and direct-message helpers. I did not run a live Google Chat workspace repro in this read-only review.

## Solution Assessment

Unclear at implementation level: the plugin-owned OAuth direction is plausible, but the exact config, SecretRef, token-refresh, scope-routing, and fallback semantics need maintainer product and security decisions before code work.
