## Summary

Keep open. Current main and the latest release still only expose Google Chat service-account credentials and a single `chat.bot` auth scope, while the requested user OAuth model for reactions, attachment upload, and proactive DM/email-alias lookup remains missing.

## What This Changes

The issue requests optional Google Chat user OAuth support for outbound reactions, media uploads, and proactive DMs while keeping service-account auth for app/webhook behavior.

## Best Possible Solution

Keep this open until the bundled Google Chat plugin has a maintainer-approved, secret-aware user OAuth credential model with scoped routing for reactions, attachments, reaction typing, and proactive DM lookup, plus documented fallback behavior when user OAuth is absent.

## Reproduction Assessment

## Solution Assessment

No, not as an automatic fix: the config sketch is directionally useful, but the best solution needs maintainer-approved secret handling, refresh-token storage/redaction, scoped client routing, docs, and live Google Chat proof.
