## Summary

Keep open. Current main still has no Google Chat user OAuth credential model or scoped token routing, and the related media-fallback work only mitigates one service-account symptom rather than solving outbound reactions, native upload, reaction typing, or proactive DM lookup.

## What This Changes

The issue requests optional Google Chat user OAuth credentials for reactions, attachment uploads, and proactive DM/email-alias operations while keeping service-account auth for bot/webhook paths.

## Best Possible Solution

Add a plugin-owned, secret-aware user OAuth credential model and scoped OAuth client routing only for Google Chat operations that require user auth, while preserving service-account auth for webhooks and existing bot sends.

## Reproduction Assessment

Yes, at source level: current main only accepts service-account credentials and always requests chat.bot for Google Chat API calls. I did not run a live Google Workspace OAuth repro in this read-only review.

## Solution Assessment

Unclear as a final design until maintainers approve the OAuth credential, scope, fallback, and documentation shape. User OAuth is the plausible product path, but the issue's config sketch is not enough by itself for a safe implementation.
