## Summary

Keep open. Current main and v2026.6.11 still only support service-account `chat.bot` auth for Google Chat API calls; the open media-fallback PRs mitigate one media-loss symptom but do not add the requested user OAuth credential and routing model for reactions, uploads, reaction typing, or email-alias DMs.

## What This Changes

Request optional Google Chat user OAuth credentials and user-scoped routing for reactions, media uploads, reaction typing, and proactive DM lookup while keeping service-account webhook and bot behavior.

## Best Possible Solution

Add a plugin-owned, SecretRef-aware Google user OAuth credential model and scoped user-client routing for only the operations that require user auth, while retaining service-account auth for webhook verification and existing bot sends with documented fallback behavior.

## Reproduction Assessment

Yes, at source level: current main only accepts service-account credentials and always requests `chat.bot` for Google Chat API calls. I did not run a live Google Workspace repro, so this is source-reproducible rather than live-reproduced.

## Solution Assessment

Unclear until maintainer and security direction is set; user OAuth is the plausible product path, but the durable fix needs the right SecretRef, scope, fallback, and documentation shape rather than only the config sketch from the report.
