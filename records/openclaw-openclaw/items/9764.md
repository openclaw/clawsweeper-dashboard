## Summary

Keep open. Current main and v2026.6.11 still route Google Chat through service-account credentials and the `chat.bot` scope only; the open media-fallback PRs cover one 403 symptom, not the requested user OAuth credential model for reactions, uploads, and email-alias DMs.

## What This Changes

The issue requests optional Google Chat user OAuth credentials so reactions, attachment uploads, and proactive DMs can use user-level Chat API scopes while existing service-account behavior remains available.

## Best Possible Solution

Keep this issue open for a Google Chat plugin-owned, secret-aware user OAuth model that routes only user-scope operations through a scoped OAuth client while preserving service-account webhook verification and bot-level sends.

## Reproduction Assessment

Yes from source inspection: current main has service-account credential resolution and one `chat.bot` auth path, while upload, reaction, and direct-message lookup helpers all reuse that token. I did not run a live Google Chat workspace repro in this read-only review.

## Solution Assessment

Not yet. OAuth belongs in the Google Chat plugin boundary, but the exact config, SecretRef, token-refresh, fallback, and scope model needs maintainer product/security review before implementation.
