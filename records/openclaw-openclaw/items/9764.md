## Summary

Keep open. Current main and v2026.6.11 still wire Google Chat through service-account credentials and the `chat.bot` scope only; the related media-fallback PRs address one upload-loss symptom, not the requested user OAuth credential model.

## What This Changes

The issue requests optional Google Chat user OAuth support for reactions, attachment uploads, reaction typing, and proactive DM/email-alias lookup while keeping service-account auth for webhook and bot operations.

## Best Possible Solution

Keep this as the canonical Google Chat user OAuth design issue and implement a plugin-owned, security-reviewed credential model with scoped routing, absent-OAuth fallback semantics, docs, and focused tests before enabling the new capability.
