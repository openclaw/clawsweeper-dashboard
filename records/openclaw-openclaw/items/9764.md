## Summary

Keep open: current main and v2026.6.11 still support Google Chat with service-account credentials and the `chat.bot` scope only, while the requested user OAuth path for reactions, media upload, and email-alias DM lookup is still absent.

## What This Changes

The issue requests optional Google Chat user OAuth support for reactions, media uploads, and proactive DMs while preserving service-account auth for existing bot/webhook behavior.

## Best Possible Solution

Add Google Chat user OAuth inside the Google Chat plugin with a strict secret-aware credential model, scoped user-auth clients only for operations that require them, service-account auth preserved for webhook verification and bot-level sends, and documented fallback behavior when user OAuth is absent.

## Reproduction Assessment

Yes for source-level reproduction: current main has service-account config and `chat.bot` auth only, while the requested `userOAuth` credential model and scoped user-auth routing are absent. I did not run a live Google Workspace OAuth flow in this read-only review.

## Solution Assessment

Yes directionally: optional user OAuth in the Google Chat plugin is the right owner boundary for reactions, native media upload, and user-auth DM lookup. The exact config shape, secret storage, and fallback policy need maintainer product and security review before implementation.
