## Summary

Keep open. Current main and the latest release still wire Google Chat to service-account credentials with the `chat.bot` scope only, while the related media fallback work covers one symptom rather than the requested user OAuth model.

## What This Changes

Request optional Google Chat user OAuth credentials for outbound reactions, media uploads, reaction typing indicators, and proactive DMs while preserving service-account webhook and bot operations.

## Best Possible Solution

Add a plugin-owned, secret-aware Google user OAuth credential model and scoped OAuth client routing for only the operations that require user auth, while keeping service-account auth for webhook verification and existing bot sends.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? No live Google Workspace repro was run, but source inspection gives a high-confidence source reproduction: current main only accepts service-account credentials and always requests `chat.bot` for Google Chat API calls.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainer/security direction is set; user OAuth is the plausible product path, but the durable fix needs the right SecretRef, scope, fallback, and documentation shape rather than a quick config sketch.
