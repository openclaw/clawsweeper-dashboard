## Label Justifications

- `P2`: This is a meaningful Google Chat channel capability gap with real delivery/auth impact, but it is a new auth/config feature requiring design rather than an emergency core outage.
- `impact:security`: The requested fix would add OAuth client secrets, refresh tokens, user scopes, and credential routing to the Google Chat surface.
- `impact:message-loss`: Current service-account-only routing can leave media uploads and reaction-style feedback undelivered or failing for users expecting those Google Chat operations.
- `impact:auth-provider`: The issue is specifically about choosing service-account versus user OAuth credentials and scopes for Google Chat operations.

## Summary

Keep open. Current main and the latest release still implement Google Chat with service-account credentials and the `chat.bot` scope only; the open media-fallback PRs cover dropped media links under app auth but do not add the requested user OAuth credential model for native uploads, outbound reactions, reaction typing, or email-alias direct-message lookup.

## What This Changes

The issue requests optional Google Chat user OAuth support for reactions, media uploads, and proactive direct messages while keeping service-account auth for existing bot operations.

## Best Possible Solution

Add a plugin-owned, secret-aware Google user OAuth credential model and scoped OAuth client routing for only the operations that require user auth, while keeping service-account auth for webhook verification and existing bot sends.

## Reproduction Assessment

Yes, at source level. Current main only accepts service-account Google Chat credentials, always requests `chat.bot`, and uses that same token path for upload, reaction, and direct-message lookup operations.

## Solution Assessment

Unclear until maintainer/security direction is set. User OAuth is the plausible product path because the official Chat API requires user auth for reaction creation and media upload, but the durable fix needs the right SecretRef, scope, fallback, and documentation shape rather than a quick config sketch.
