## Summary

Keep open: current main still routes Google Chat through service-account app auth only, so the requested user OAuth path for outbound reactions, native media uploads, reaction typing, and email-alias DM lookup remains missing. The related open media-fallback PRs are useful partial mitigations for link delivery, but they do not add OAuth credentials or scoped user-token routing.

## What This Changes

The issue requests optional Google Chat user OAuth support for reactions, media uploads, reaction typing, and email-alias proactive DMs alongside existing service-account authentication.

## Best Possible Solution

Keep the issue open and implement a plugin-owned, secret-aware Google Chat user OAuth credential path with scoped user clients for reactions, native uploads, reaction typing, and email-alias DM lookup while preserving service-account auth for webhooks and app sends.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: current main has no accepted `userOAuth` config and all outbound Google Chat API helpers use the `chat.bot` service-account token path. I did not run a live Google Workspace OAuth repro, but the code and Google API docs are enough to prove the missing capability.

## Solution Assessment

Yes, the requested direction is the right feature boundary, but it is not a narrow automated bug fix. The maintainable solution needs a Google Chat plugin-owned OAuth credential model, secret handling, scoped routing, docs, and fallback behavior rather than a one-off upload or reaction patch.
