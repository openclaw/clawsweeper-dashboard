## Summary

Keep this issue open for maintainer product and security direction. The supplied prior source review found the Google Chat plugin limited to service-account `chat.bot` credentials, while the open media-link fallback work only preserves delivery after an upload denial and does not provide the requested user-authorized reactions, native uploads, or email-alias DM lookup.

## What This Changes

Add optional Google Chat user OAuth so reactions, native media uploads, and email-alias proactive DMs can use scopes unavailable to service-account app authentication.

## System Context

The bundled Google Chat plugin receives webhooks and sends channel responses through Google Chat API clients. Its account/config layer selects credentials before outbound reactions, attachment uploads, typing indicators, and direct-message lookup use those clients.

## Architecture Diagram

flowchart LR
  A[Google Chat webhook and channel config] --> B[Google Chat account credentials]
  B --> C[Authentication client selection]
  C --> D[Outbound channel operations]
  D --> E[Messages and replies]
  D --> F[Reactions and typing]
  D --> G[Media uploads and proactive DMs]

## Best Possible Solution

Choose and document a Google Chat delegated-identity contract first, then add a plugin-owned, secret-aware OAuth credential path with explicit operation routing, safe no-OAuth behavior, focused upgrade coverage, and live Google Chat proof.
