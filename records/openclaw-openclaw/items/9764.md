## Summary

Keep open. Current main still has Google Chat wired to service-account credentials and the `chat.bot` scope only; the related media-fallback work covers one symptom, not the requested user OAuth credential model for reactions, attachment upload, and proactive DM/email-alias lookup.

## What This Changes

The issue requests optional Google Chat user OAuth support for outbound reactions, media uploads, and proactive direct messages while retaining service-account auth for existing bot/webhook operations.

## Best Possible Solution

Add a plugin-owned, secret-aware Google user OAuth credential model and scoped OAuth client routing only for operations that require user auth, while keeping service-account auth for webhook verification and existing bot sends.

## Reproduction Assessment

Yes, at source level. Current main exposes the affected actions but has only service-account credential resolution and one `chat.bot` auth scope, so the requested user-OAuth path cannot be configured or selected.

## Solution Assessment

Partly. User OAuth is the right product direction for the Google operations that require user authentication, but the issue's config sketch is not enough; maintainers still need to approve the SecretRef, scope, fallback, docs, and live-proof shape.
