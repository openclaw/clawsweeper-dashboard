## Summary

Keep open. Current main and the latest release still use service-account Google Chat credentials with a fixed `chat.bot` scope; related media-fallback work covers one symptom but not the requested user OAuth model for reactions, native uploads, reaction typing, or proactive DM lookup.

## What This Changes

The issue requests optional Google Chat user OAuth support for reactions, media uploads, reaction typing, and proactive DMs while keeping service-account auth for webhook/bot operations.

## Best Possible Solution

Add a plugin-owned, secret-aware Google user OAuth credential model and scoped client routing only for operations that require user auth, while keeping service-account auth for webhook verification and ordinary bot sends.

## Reproduction Assessment

Yes for source reproduction: current main has no userOAuth config/schema path and always obtains Google Chat API tokens through the service-account chat.bot flow. No live Google Workspace OAuth repro was run in this read-only review.

## Solution Assessment

Unclear until maintainer/security direction is set; user OAuth is the plausible product path, but the durable solution must define SecretRef storage, scope boundaries, fallback behavior, and docs rather than land the sketch as-is.
