## Summary

Keep open. Current main and v2026.6.11 remain service-account-only, while Google’s current API contracts require user authentication for reaction creation, attachment uploads, and email-alias direct-message lookup; the related open PRs only provide degraded media-link fallback and do not implement the requested OAuth capability. citeturn836763search1turn836763search4turn836763search7

## What This Changes

Add optional Google Chat user authentication for reactions, native media uploads, and proactive direct-message lookup while retaining service-account authentication for existing app operations.

## Best Possible Solution

Implement a plugin-owned, SecretRef-aware user credential mode with explicit least-privilege scopes and consent/setup, route only user-required operations through it, preserve service-account authentication as the default, and retain safe degraded behavior when user auth is absent.
