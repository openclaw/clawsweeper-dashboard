## Summary

Keep open. Current main and the latest release still lack a Google Chat user OAuth credential path; related media-fallback PRs only address link delivery for one app-auth symptom, not native user-scoped reactions, attachment upload, reaction typing, or email-alias proactive DMs.

## What This Changes

Request optional Google Chat user OAuth credentials and scoped routing for reactions, media uploads, reaction typing, and proactive DMs while keeping service-account auth for webhooks and bot sends.

## Best Possible Solution

Add a plugin-owned, secret-aware Google Chat user OAuth credential model and scoped OAuth client routing only for operations that require user auth, while retaining service-account auth for webhook verification and current bot sends.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes for source-level reproduction: current main only accepts service-account credentials and always requests the chat.bot scope for Google Chat API calls; no live Google Workspace OAuth repro was run.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainer security/product direction is set; user OAuth is the plausible durable path, but the implementation must use the right SecretRef, scope, fallback, docs, and live-proof shape rather than the initial config sketch alone.
