## Label Justifications

- `P2`: This is a clear Google Chat capability and auth gap with real user impact, but it is scoped to one channel and requires design/security review rather than emergency cleanup.
- `impact:security`: The requested implementation would add OAuth client-secret, refresh-token, scope, token-refresh, and credential-redaction behavior.
- `impact:message-loss`: Unsupported native uploads and reaction operations can cause expected Google Chat media/action delivery to fail or be skipped.
- `impact:auth-provider`: The central gap is Google Chat auth routing between current service-account `chat.bot` credentials and missing user OAuth credentials.

## Summary

Keep open. Current main and v2026.6.11 still expose Google Chat through service-account credentials and the `chat.bot` scope only; the open media-fallback PRs mitigate one upload-loss symptom but do not add the requested user OAuth credential model.

## What This Changes

The issue requests optional Google Chat user OAuth support for reactions, media uploads, reaction typing, and proactive DMs while retaining service-account behavior for bot/webhook operations.

## Best Possible Solution

Keep this as the canonical Google Chat user OAuth design issue and implement a plugin-owned, security-reviewed credential model with scoped routing, absent-OAuth fallback semantics, docs, and focused tests before enabling the new capability.
