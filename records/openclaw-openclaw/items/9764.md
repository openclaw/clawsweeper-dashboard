## Summary

Keep this issue open. Current main and the latest release still wire Google Chat to service-account credentials and the `chat.bot` scope only, while the requested reactions, media upload, and email-alias DM behavior need user-OAuth-capable credential and routing work.

## What This Changes

The issue requests optional Google Chat user OAuth support for reactions, attachment uploads, and proactive direct messages while preserving service-account auth for existing bot flows.

## Best Possible Solution

Keep this issue as the canonical maintainer-reviewed Google Chat user OAuth tracker, with a strict secret-aware credential model and scoped user-token routing for reactions, attachment uploads, reaction typing, and proactive DM/email-alias lookup.

## Reproduction Assessment

Yes. Source inspection on current main shows the Google Chat config, credential resolver, and auth helper only support service-account credentials with the `chat.bot` scope, while the requested user OAuth config path is absent.

## Solution Assessment

Unclear as a final implementation shape. User OAuth is the right capability direction, but the exact config, SecretRef, redaction, setup, and operation-routing model needs maintainer product and security review before implementation.
