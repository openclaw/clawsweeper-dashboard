## Summary

Keep open. Current main and v2026.6.11 still wire Google Chat API calls through service-account credentials with the `chat.bot` scope only, while the related media-fallback issues and PRs cover one delivery symptom rather than the requested user OAuth credential and routing model.

## What This Changes

Add optional Google Chat user OAuth credentials and scoped routing for reactions, attachment uploads, and proactive DMs while keeping service-account auth for webhook and bot-level operations.

## Best Possible Solution

Add a plugin-owned, secret-aware Google Chat user OAuth credential model with scoped OAuth clients for only user-auth-required operations, keep service-account auth for webhook verification and current bot sends, and document/validate fallback behavior when user OAuth is absent.

## Reproduction Assessment

No live Google Workspace repro was run, but current-main source inspection gives a high-confidence source reproduction: Google Chat accepts service-account credentials only and always requests the `chat.bot` scope for API calls.

## Solution Assessment

Unclear until maintainer/security direction is set; user OAuth is the plausible product path, but the durable fix needs the right SecretRef, scope, fallback, and documentation shape rather than a quick config sketch.
