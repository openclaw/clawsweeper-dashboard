## Summary

Keep open. Current main and v2026.6.11 still implement Google Chat with service-account credentials and the `chat.bot` scope only; the related media-link PRs mitigate one media-delivery symptom but do not add the requested user OAuth model for reactions, uploads, or proactive DM lookup.

## What This Changes

Request optional Google Chat user OAuth credentials and scoped routing for reactions, media uploads, and proactive DM lookup while keeping service-account webhook and bot behavior.

## Best Possible Solution

Add a plugin-owned, secret-aware Google user OAuth credential model and scoped user-auth routing only for operations that require it, while keeping service-account auth for webhook verification and existing bot sends.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: current main only accepts/validates service-account credentials and uses `chat.bot` for Google Chat API access; no live Google Workspace OAuth run was performed.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainer/security direction is set; user OAuth is the plausible durable path, while media-link fallback work is only a partial mitigation for one symptom.
