## Summary

Keep open. Current main and the latest release still use service-account `chat.bot` auth only for Google Chat, while the related media-fallback items cover one upload-loss symptom rather than the requested user OAuth credential model.

## What This Changes

The issue requests optional Google Chat user OAuth credentials and scoped routing for reactions, media uploads, reaction typing, and proactive DM lookup while keeping service-account auth for webhook and bot-level operations.

## Best Possible Solution

Keep this as the canonical Google Chat OAuth design item and implement a plugin-owned, secret-aware user OAuth model with scoped clients, absence-of-OAuth fallback behavior, docs, and security review before enabling the new capability.
