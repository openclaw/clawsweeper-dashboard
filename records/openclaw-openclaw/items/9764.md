## Summary

Keep open: current main still does not provide Google Chat user OAuth for outbound reactions, native attachment uploads, or email-alias proactive DMs, and the requested credential and consent model needs maintainer and security approval before implementation.

## What This Changes

Add optional Google Chat user OAuth alongside service-account authentication so the channel can perform OAuth-gated reactions, attachment uploads, and proactive DM lookup.

## Best Possible Solution

Approve a plugin-owned delegated OAuth contract using existing secret-aware configuration patterns, route only OAuth-required calls through scoped user credentials, retain service-account handling for webhook and app-auth operations, and define visible fallback behavior when delegated credentials are absent.
