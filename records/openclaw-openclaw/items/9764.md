## Summary

Keep this issue open. Current main and the latest release still only support Google Chat service-account credentials with the `chat.bot` scope; the related media-link fallback work only mitigates one failure mode and does not add user OAuth for reactions, native uploads, or email-alias proactive DMs.

## What This Changes

Request to add optional Google Chat user OAuth credentials for reactions, attachment uploads, and email-alias proactive DMs alongside existing service-account auth.

## Best Possible Solution

Add a secret-aware optional Google Chat user OAuth credential path in the bundled plugin, route only user-scope operations through that client, preserve service-account webhook/bot behavior, and document the fallback behavior when user OAuth is absent.

## Reproduction Assessment

Yes. Source inspection shows the strict Google Chat config, account resolver, and auth helper only support service-account credentials with the chat.bot scope; I did not run a live Google Chat workspace test.

## Solution Assessment

Unclear as a ready implementation path. Optional user OAuth is likely the right product direction for the requested operations, but the best fix needs a maintainer-approved credential model and security review rather than a narrow automated patch.
