## Summary

Keep open. Current main and v2026.6.11 still wire Google Chat API calls through service-account credentials with the `chat.bot` scope only, and the related media-fallback work does not add the requested user OAuth model for reactions, native uploads, reaction typing, or email-alias DM lookup.

## What This Changes

The issue requests optional Google Chat user OAuth support for reactions, attachment uploads, and proactive DMs while keeping service-account auth for bot operations.

## Best Possible Solution

Add a plugin-owned, secret-aware Google user OAuth credential model and scoped OAuth client routing for operations that need user auth, while keeping service-account auth for webhook verification and current bot sends.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? No live Google Workspace repro was run, but current source gives a high-confidence source reproduction: Google Chat only resolves service-account credentials and requests only `chat.bot` for API calls.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainer/security direction is set; user OAuth is the plausible product path, but the durable fix needs the right SecretRef, scope, fallback, and documentation shape rather than the issue's config sketch alone.
