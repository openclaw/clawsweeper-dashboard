## Summary

Keep open. Current main and the latest release still only expose service-account Google Chat credentials and a `chat.bot` auth scope, while related media-fallback work covers one symptom rather than the requested user OAuth credential model.

## What This Changes

Add optional Google Chat user OAuth support for outbound reactions, attachment uploads, reaction typing, and proactive DM lookup while keeping existing service-account behavior.

## Best Possible Solution

Add a plugin-owned, secret-aware Google user OAuth credential model and scoped OAuth client routing for only the operations that require user auth, while preserving service-account auth for webhook verification and existing bot sends.

## Reproduction Assessment

Yes at source level: current main only accepts service-account Google Chat credentials and always requests `chat.bot` for Google Chat API calls. I did not run a live Google Workspace OAuth repro in this read-only review.

## Solution Assessment

Unclear until maintainer and security direction is set; user OAuth is the plausible product path, but the durable fix needs the right SecretRef, scope, fallback, and documentation shape rather than only the proposed config sketch.
