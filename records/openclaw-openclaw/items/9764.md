## Summary

Keep open. Current main and the latest release still route Google Chat through service-account credentials and the `chat.bot` scope only, while the linked media-fallback work covers one symptom rather than the requested user OAuth model for reactions, native uploads, reaction typing, and proactive DM lookup.

## What This Changes

Add optional Google Chat user OAuth credentials and use them for operations that require user-level scopes while preserving service-account auth for existing bot/webhook paths.

## Best Possible Solution

Add a plugin-owned, secret-aware Google user OAuth credential model and scoped OAuth client routing for only the operations that require user auth, while keeping service-account auth for webhook verification and existing bot sends.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction: current main only accepts service-account credentials and always requests `chat.bot` for Google Chat API calls. No live Google Workspace OAuth repro was run in this read-only review.

## Solution Assessment

Unclear until maintainer and security direction is set. User OAuth is the plausible product path, but the maintainable fix must choose the SecretRef, scope, fallback, redaction, and documentation shape deliberately rather than landing the config sketch as-is.
