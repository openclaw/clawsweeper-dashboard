## Summary

Keep open. Current main and v2026.6.11 still wire Google Chat to service-account credentials and the `chat.bot` scope only; related media-link fallback work covers one symptom, not the requested user OAuth model.

## What This Changes

Request optional Google Chat user OAuth support for outbound reactions, media uploads, reaction typing, and proactive DM/email-alias lookup while keeping service-account auth for existing bot/webhook flows.

## Best Possible Solution

Add a plugin-owned, secret-aware Google user OAuth credential model and scoped OAuth client routing for only operations that require user auth, while keeping service-account auth for webhook verification and existing bot sends.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: current main only accepts service-account credentials and always requests `chat.bot` for Google Chat API calls; no live Google Workspace repro was run in this read-only review.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainer/security direction is set; user OAuth is the plausible product path, but the durable fix needs the right SecretRef, scope, fallback, and documentation shape rather than only the sketched config.
