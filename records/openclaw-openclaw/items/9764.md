## Label Justifications

- `P2`: This is a concrete Google Chat channel/auth improvement with real delivery impact, but it is not an emergency because text sends and webhook receiving still work.
- `impact:security`: The requested fix would add user OAuth client secrets, refresh tokens, scopes, and credential routing to the Google Chat plugin.
- `impact:message-loss`: Without user OAuth or a separate fallback, media upload failures and unsupported reaction operations can prevent intended Google Chat responses or acknowledgements from reaching users.
- `impact:auth-provider`: The central gap is provider/channel auth routing: current Google Chat auth only uses service-account `chat.bot` credentials while the requested operations require user-scoped OAuth.

## Summary

Keep open. Current main and v2026.6.11 still implement Google Chat with service-account credentials and the `chat.bot` scope only; related media-fallback PRs address one delivery-loss symptom, not the requested user OAuth credential model for reactions, attachment uploads, or user-auth DM lookup.

## What This Changes

The issue asks for optional Google Chat user OAuth credentials alongside service-account auth so reactions, media uploads, reaction typing, and proactive DMs can use user-scoped Google Chat APIs.

## Best Possible Solution

Keep this issue open until maintainers either sponsor a strict Google Chat user OAuth design in the plugin or deliberately scope the bundled plugin to service-account auth plus narrower fallback mitigations.
