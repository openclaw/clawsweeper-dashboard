## Summary

Keep open. Current main and the latest release still use service-account Google Chat credentials with the `chat.bot` scope only; the related media-fallback PRs mitigate one upload-failure symptom but do not add the requested user OAuth credential model for reactions, native uploads, or proactive DM alias lookup.

## What This Changes

The issue requests optional user OAuth credentials for the bundled Google Chat plugin so user-scoped operations can work alongside existing service-account bot auth.

## Best Possible Solution

Add a plugin-owned, secret-aware Google Chat user OAuth credential model and scoped OAuth client routing for only the operations that require user auth, while preserving service-account webhook verification and existing bot sends.

## Reproduction Assessment

Yes at source level: current main only accepts service-account Google Chat credentials and always requests `chat.bot` for Chat API calls. No live Google Workspace repro was run in this read-only review.

## Solution Assessment

Unclear until maintainer and security direction is set; user OAuth is the likely durable path for operations Google requires user auth for, but the config, SecretRef, scope routing, and fallback shape need deliberate design.
