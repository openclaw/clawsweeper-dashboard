## Summary

Keep open for a maintainer product and security decision. The request adds a new delegated Google Workspace identity and secret-bearing OAuth lifecycle to the bundled Google Chat plugin; the open media-link fallback work addresses a narrower delivery failure but does not establish user-authenticated reactions or proactive email-alias DMs.

## What This Changes

Add optional Google Chat user OAuth so the channel can create reactions, upload media, and resolve proactive direct-message recipients where service-account authentication is insufficient.

## System Context

The Google Chat plugin receives webhook events and sends channel actions through Google Chat API clients. This request would add a second, user-authorized credential path for operations that app/service-account authentication cannot perform, while preserving the existing bot-authenticated webhook and reply flow.

## Best Possible Solution

Define one documented Google Chat delegated-identity contract in the plugin, using existing secret-aware credential storage and explicit operation routing; retain service-account behavior by default, provide clear unsupported-operation feedback when no delegated identity exists, and validate it against a real Workspace setup.
