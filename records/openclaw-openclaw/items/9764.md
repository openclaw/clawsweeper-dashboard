## Summary

Keep open. Current main and the latest release still implement Google Chat with service-account credentials and a single `chat.bot` auth path; the open media-fallback PRs mitigate one upload symptom but do not add the requested user OAuth credential model for reactions, uploads, and email-alias direct-message lookup.

## What This Changes

Requests optional Google Chat user OAuth credentials for reactions, media uploads, and proactive direct-message lookup alongside existing service-account authentication.

## Best Possible Solution

Add a Google Chat plugin-owned, secret-aware user OAuth credential model and route only user-scope operations through it while preserving service-account webhook verification and bot-level sends.

## Reproduction Assessment

Yes, at source level: current main has only service-account credential resolution and one `chat.bot` access-token path, while upload, reaction, and direct-message helpers all reuse that token. I did not run a live Google Chat workspace repro in this read-only review.

## Solution Assessment

Unclear as an implementation plan. The issue belongs in the Google Chat plugin boundary, but the exact OAuth config, SecretRef, refresh-token, scope, and fallback policy needs maintainer product/security review before a fix PR.
