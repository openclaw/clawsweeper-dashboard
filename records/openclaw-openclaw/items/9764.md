## Summary

Keep open. Current main and v2026.6.11 still wire Google Chat to service-account credentials with the chat.bot scope only; related media-fallback and ADC work cover narrower symptoms, not the requested user OAuth model.

## What This Changes

Add optional Google Chat user OAuth credentials and scoped routing for reactions, media uploads, reaction typing, and proactive DM lookup while preserving service-account webhook and bot-send behavior.

## Best Possible Solution

Add a plugin-owned, secret-aware Google Chat user OAuth credential model with scoped OAuth clients only for user-auth-required operations, while keeping service-account auth for webhook verification and existing bot sends.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: current main only accepts service-account credentials, always requests chat.bot for Google Chat API calls, and has no user OAuth branch for the reported operations.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainer/security direction is set; user OAuth is the plausible product path, but the durable fix must define SecretRef, scope, fallback, docs, and live-proof requirements rather than copying the config sketch directly.
