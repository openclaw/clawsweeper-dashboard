## Summary

Keep open. Current main still wires Google Chat through service-account credentials and the `chat.bot` scope only, while the open media-fallback PRs address one upload-loss symptom rather than the requested user OAuth credential model.

## What This Changes

The issue requests optional Google Chat user OAuth credentials for reactions, media uploads, reaction typing, and proactive direct-message lookup while retaining service-account auth for bot/webhook behavior.

## Best Possible Solution

Add a maintainer-approved, secret-aware Google Chat user OAuth model in the bundled plugin, route only user-scope-required operations through it, keep service-account auth for webhook and bot-level behavior, and document fallback behavior when user OAuth is absent.
