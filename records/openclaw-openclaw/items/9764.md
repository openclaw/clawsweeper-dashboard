## Summary

Keep open: current main and the latest release still have Google Chat wired to service-account app auth only, so delegated user OAuth for reactions, native media uploads, reaction typing, and email-alias DM lookup remains missing.

## What This Changes

The issue requests optional Google Chat user OAuth credentials and scoped token routing alongside the existing service-account setup.

## Best Possible Solution

Implement plugin-owned, secret-aware Google Chat user OAuth credentials with scoped user clients for reactions, native uploads, reaction typing, and email-alias DM lookup while preserving service-account auth for webhook verification and app sends.

## Reproduction Assessment

Yes, source-level reproduction is high confidence because current main accepts no `userOAuth` config and all affected Google Chat helpers share the chat.bot service-account token path.

## Solution Assessment

Yes, the issue identifies the right feature boundary, but the implementation needs a deliberate OAuth credential, scope-routing, docs, setup, and fallback design rather than a narrow upload or reaction patch.
