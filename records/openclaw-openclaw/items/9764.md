## Summary

Keep open. Current main and the latest release still route Google Chat through service-account credentials and the `chat.bot` scope only; the open media-link fallback PRs address one dropped-media symptom but do not add the requested user OAuth model for reactions, native attachment upload, reaction typing, or email-alias DM lookup.

## What This Changes

Add optional Google Chat user OAuth credentials and use them for user-scoped reactions, attachment uploads, reaction typing, and proactive DM lookup while keeping service-account auth for webhook and bot operations.

## Best Possible Solution

Add a plugin-owned, SecretRef/redaction-aware Google Chat user OAuth credential model and route only user-scoped operations through it, while retaining service-account auth for webhook verification and bot-level sends.

## Reproduction Assessment

Yes, there is a high-confidence source-level reproduction: current main only accepts Google Chat service-account credentials and always requests `chat.bot`. I did not run a live Google Workspace repro for the full OAuth workflow.

## Solution Assessment

Unclear. User OAuth is the likely direction for operations Google requires to be user-authenticated, but the config sketch is not enough without SecretRef/redaction, scope boundaries, fallback behavior, docs, tests, and live workspace proof.
