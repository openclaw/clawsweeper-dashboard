## Summary

Keep this issue open: current main and the latest release still expose Google Chat as service-account/app-auth only, while the requested user OAuth credential model and scoped routing for reactions, attachment upload, and email-alias DM lookup are still missing.

## What This Changes

The issue requests optional Google Chat user OAuth support for outbound reactions, media upload, and proactive DM/email-alias flows while retaining service-account auth for existing bot operations.

## Best Possible Solution

Keep the issue open and design the Google Chat plugin change as a maintainer-approved, secret-aware OAuth capability: add strict config/schema/docs, support SecretRef or equivalent protected token storage, route only user-scope-required operations through a scoped OAuth client, keep service-account auth for webhook verification and existing bot sends, and add focused tests plus live Google Chat proof.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction of the missing capability: current main has no accepted userOAuth config, validates only service-account credentials, and builds tokens with the chat.bot scope. I did not run a live Google Chat workspace test.

## Solution Assessment

Not yet as sketched. The requested direction is valid, but the best implementation needs a maintainer-approved secret model, strict schema/docs, scoped OAuth client routing, fallback policy, and security review rather than only adding raw clientId/clientSecret/refreshToken fields.
