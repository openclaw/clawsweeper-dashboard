## Summary

Keep open. Current main and the latest release still use Google Chat service-account credentials with the `chat.bot` scope only, while the requested user OAuth path would add new secret-bearing auth/config behavior that needs maintainer product and security review.

## What This Changes

Request optional Google Chat user OAuth support for reactions, media uploads, reaction typing, and proactive DM/email-alias operations alongside existing service-account auth.

## Best Possible Solution

Design and implement a maintainer-approved, secret-aware Google Chat user OAuth model inside the bundled Google Chat plugin, keeping service-account auth for webhooks/bot sends and routing only user-scope-required operations through scoped OAuth clients with documented fallback behavior.

## Reproduction Assessment

Yes, at source level: current main only resolves Google Chat service-account credentials and scopes `GoogleAuth` to `chat.bot`, while the requested reaction/upload/user-DM paths require user OAuth behavior. I did not run a live Google Chat workspace with credentials during this read-only review.

## Solution Assessment

Unclear as an implementation plan: optional user OAuth alongside service-account auth is the likely product direction, but the exact config shape, SecretRef model, scopes, fallback policy, and security review need maintainer approval before coding.
