## Summary

Keep open: current main still has Google Chat wired to service-account app auth only, so the requested user OAuth path for reactions, native attachment upload, reaction typing, and email-alias DM lookup remains missing. Related media-fallback issues and PRs are useful mitigations for one message-loss case, but they do not add OAuth credential modeling or scoped user-token routing.

## What This Changes

The issue requests optional Google Chat user OAuth credentials alongside service-account auth for reactions, media uploads, and proactive DM lookup.

## Best Possible Solution

Implement a plugin-owned, secret-aware Google Chat user OAuth credential path with scoped user clients for reactions, native uploads, reaction typing, and email-alias DM lookup while preserving service-account auth for webhook verification and app sends.

## Reproduction Assessment

Yes. Source-level reproduction is high confidence: current main has no accepted `userOAuth` config and all outbound Google Chat API helpers use the `chat.bot` service-account token path.

## Solution Assessment

Yes as a direction, but it is not a narrow automated bug fix. The maintainable solution needs a Google Chat plugin-owned OAuth credential model, secret handling, scoped routing, docs, and fallback behavior rather than a one-off upload or reaction patch.
