## Summary

Keep open. Current main still wires Google Chat to service-account credentials and the `chat.bot` scope only; the open media-fallback work reduces one message-loss symptom but does not add the requested user OAuth credential model or scoped routing for reactions, uploads, reaction typing, and proactive DMs.

## What This Changes

The issue requests optional Google Chat user OAuth support for reactions, attachment uploads, reaction typing, and proactive DMs while keeping service-account auth for webhook verification and bot-level operations.

## Best Possible Solution

Add a plugin-owned, secret-aware Google user OAuth credential model and scoped OAuth client routing for only operations that require user auth, while preserving service-account auth for webhook verification and existing bot sends.

## Reproduction Assessment

Yes from source, not from a live workspace in this review: current main only accepts service-account credentials and always requests `chat.bot` for Google Chat API calls. The requested `userOAuth` config shape is absent and the strict schema would reject it.

## Solution Assessment

Unclear until maintainer and security direction is set. User OAuth is the plausible product path, but the durable fix needs the right SecretRef, scope, fallback, setup, and documentation shape rather than a quick config sketch.
