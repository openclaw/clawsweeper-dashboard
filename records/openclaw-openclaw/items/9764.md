## Summary

Keep open. Current main and the latest release still use service-account Google Chat credentials with the `chat.bot` scope only, while the related media-fallback PRs address one symptom and do not add the requested user OAuth credential model.

## What This Changes

Request to add optional Google Chat user OAuth credentials and route reactions, attachment uploads, and proactive DM lookup through user-scoped tokens while keeping service-account auth for bot/webhook operations.

## Best Possible Solution

Add a plugin-owned, secret-aware Google user OAuth credential model and scoped OAuth client routing for only the operations that require user auth, while keeping service-account auth for webhook verification and existing bot sends.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: current main only accepts service-account Google Chat credentials and always requests `chat.bot` for Chat API calls. No live Google Workspace repro was run in this read-only review.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainer/security direction is set; user OAuth is the likely durable path for operations Google requires user auth for, but the config, SecretRef, scope routing, and fallback shape need deliberate design.
