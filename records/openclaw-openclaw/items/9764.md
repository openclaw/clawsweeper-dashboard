## Summary

Keep open. Current main and the latest release still use service-account Google Chat auth with the `chat.bot` scope only, while the requested user OAuth credential model remains a product/security-sensitive feature gap.

## What This Changes

Add optional Google Chat user OAuth support for reactions, media uploads, and proactive direct messages while keeping existing service-account behavior.

## Best Possible Solution

Implement a Google Chat plugin-owned, secret-aware user OAuth credential model and route only user-scope operations through it, while preserving service-account webhook verification and bot-level sends with documented fallback behavior.

## Reproduction Assessment

Yes. Source inspection shows current main has only service-account credential resolution and one `chat.bot` token path, while upload, reaction, and direct-message lookup helpers all reuse that token.

## Solution Assessment

Unclear as an implementation direction until maintainers decide the security and config shape. The right boundary is the Google Chat plugin, but the exact OAuth credential, SecretRef, refresh, scope, and fallback model needs product/security review.
