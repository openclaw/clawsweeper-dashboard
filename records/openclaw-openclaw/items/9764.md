## Summary

Keep open. Current main and v2026.6.11 still wire Google Chat through service-account credentials and the `chat.bot` scope only, while the related media-fallback PRs address one upload-loss symptom rather than the requested user OAuth credential model.

## What This Changes

Add optional Google Chat user OAuth support for reactions, attachment uploads, reaction typing, and proactive DM/email-alias lookup while keeping service-account auth for existing webhook/bot flows.

## Best Possible Solution

Keep this as the canonical Google Chat OAuth design issue and implement a plugin-owned, secret-aware user OAuth model with scoped routing, docs, fallback semantics, and security review before enabling the new capability.
