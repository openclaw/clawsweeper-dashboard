## Summary

Keep open. Current main and the latest release still only support Google Chat service-account credentials with the `chat.bot` scope, so the requested user OAuth path for outbound reactions, native media uploads, and proactive DM lookup remains missing.

## What This Changes

The issue requests optional Google Chat user OAuth support alongside service-account auth for reactions, media uploads, reaction typing, and proactive DMs.

## Best Possible Solution

Add a Google Chat plugin-owned, SecretRef-aware user OAuth credential model and scoped OAuth client routing only for operations that require user auth, while preserving service-account auth for webhook verification and existing bot sends.

## Reproduction Assessment

Yes for source-level reproduction: current main only accepts service-account Google Chat credentials and always requests the `chat.bot` scope. I did not run a live Google Workspace OAuth repro.

## Solution Assessment

Unclear until maintainer/security direction is set; the user OAuth direction is plausible, but the config sketch is not enough by itself. The maintainable fix needs a plugin-owned SecretRef/redaction model, scoped token routing, fallback behavior, docs, and live workspace proof.
