## Summary

Keep open: current main and the latest release still wire Google Chat to service-account credentials and the fixed `chat.bot` scope only, while the related media-fallback PRs mitigate one upload symptom without adding user OAuth for reactions, attachment upload, reaction typing, or proactive DM lookup.

## What This Changes

Request to add optional Google Chat user OAuth credentials and route reactions, media uploads, and proactive DM lookup through user-scoped tokens while retaining service-account webhook and bot operations.

## Best Possible Solution

Keep this as the canonical Google Chat user-OAuth design item until maintainers approve a plugin-local credential model, scoped user-auth routing, fallback behavior, tests, and docs that preserve service-account webhook setups.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: current main has only service-account credential resolution and a fixed `chat.bot` auth scope, while the affected reaction/upload/DM helpers share that token path. I did not run a live Google Chat workspace because this read-only review already proves the missing OpenClaw capability from source and release checks.

## Solution Assessment

Unclear as a final implementation shape: optional user OAuth is the right problem boundary, but the exact config, SecretRef, token-refresh, scope-routing, and fallback policy need maintainer/security approval first. The open media-link fallback PRs are useful mitigations, not the complete solution for this issue.
