## Summary

Keep open. Current main and the latest release still have Google Chat wired to service-account auth and `chat.bot` only; the related media-fallback PRs cover one symptom, not the requested user OAuth credential model.

## What This Changes

The issue requests optional Google Chat user OAuth credentials so reactions, attachment uploads, reaction typing, and proactive DM/email-alias lookup can use user-level scopes while service-account auth remains for bot/webhook operations.

## Best Possible Solution

Add a Google Chat plugin-owned, secret-aware user OAuth credential model and route only operations requiring user scopes through that client, while preserving service-account webhook verification and bot-level sends.

## Reproduction Assessment

Yes from source inspection: current main has service-account credential resolution and one `chat.bot` auth path, while upload, reaction, and direct-message lookup helpers all reuse that token. I did not run a live Google Chat workspace repro in this read-only review.

## Solution Assessment

Not yet. OAuth belongs in the Google Chat plugin boundary, but the exact config, SecretRef, token-refresh, fallback, and scope model needs maintainer product/security review before implementation.
