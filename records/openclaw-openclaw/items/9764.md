## Label Justifications

- `P2`: This is a normal-priority channel/auth enhancement with real Google Chat delivery gaps, but it needs product and security design before implementation.
- `impact:security`: The requested solution would add OAuth refresh-token credentials and scoped Google user access to the Google Chat plugin.

## Summary

Keep open: current main and v2026.6.11 still expose only service-account Google Chat auth, while official Chat API docs require user auth for reaction creation and media upload, so the requested OAuth path remains missing. ([developers.google.com](https://developers.google.com/workspace/chat/api/reference/rest/v1/spaces.messages.reactions/create?utm_source=openai))

## What This Changes

Request adds optional Google Chat user OAuth credentials and uses them for reactions, attachment uploads, reaction typing, and proactive DM lookup while retaining service-account auth for webhook and bot operations.

## Best Possible Solution

Add a strict, secret-aware Google Chat user-auth credential model in the plugin, route only user-scope-required operations through it, keep service-account auth for webhook and app sends, and document/test the fallback behavior when user OAuth is absent.

## Reproduction Assessment

Yes, source-reproducible: current main only resolves service-account Google Chat credentials and uses the `chat.bot` scope while the requested operations require user-authenticated Chat scopes. I did not run a live Google Workspace OAuth flow in this read-only review.

## Solution Assessment

Yes with guardrails: adding user OAuth is the right capability, but the safe implementation must use existing secret/config patterns, explicit scope routing, and documented fallback behavior rather than the raw config sketch alone.
