## Summary

Keep open: current main still has Google Chat wired to service-account credentials and the `chat.bot` scope only, while the requested user OAuth credential model and routing for reactions, attachment upload, and email-alias proactive DMs remain absent.

## What This Changes

The issue requests optional Google Chat user OAuth support for reactions, media uploads, and proactive DMs while retaining service-account webhook and bot-send behavior.

## Best Possible Solution

Implement a plugin-local, secret-aware Google Chat user OAuth credential model using existing SecretRef/auth patterns, route only user-scope operations through it, keep service-account auth for webhook verification and bot operations, and document/test absent-OAuth fallbacks.

## Reproduction Assessment

Yes at source level: current main has no accepted user OAuth config, resolves only service-account credentials, and requests only the `chat.bot` scope. I did not run a live Google Chat workspace repro in this read-only pass.

## Solution Assessment

Unclear as a final product design: the requested direction is plausible, but the best implementation needs maintainer-approved OAuth scope, secret storage, token refresh, and fallback semantics before code work starts.
