## Summary

Keep open. Current main and the latest release still implement Google Chat with service-account credentials and the `chat.bot` scope only; the open media-fallback work covers one app-auth 403 symptom, not the requested user OAuth credential model or scoped user-auth routing.

## What This Changes

The issue requests optional Google Chat user OAuth support for reactions, media uploads, and proactive DMs while preserving service-account behavior.

## Best Possible Solution

Keep this issue open for a maintainer-sponsored Google Chat OAuth design that adds plugin-owned, secret-aware user credentials, scoped user-client routing for user-auth-only operations, and documented fallback behavior when user OAuth is absent.

## Reproduction Assessment

Yes from source inspection: current main has bot-scope service-account auth only, strict config without userOAuth, and upload/reaction/proactive-DM calls all use the same account token path. I did not run a live Google Chat OAuth workspace repro in this read-only cleanup review.

## Solution Assessment

Unclear as a final design: user OAuth is the likely capability boundary, but maintainers still need to choose the secret/config model, scope split, fallback behavior, and whether a symptom-level media fallback should land first.
