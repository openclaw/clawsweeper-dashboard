## Summary

Keep open. Current main and v2026.6.11 still only expose Google Chat service-account credentials and the `chat.bot` auth path; the related media-fallback items reduce one 403 symptom but do not add the requested user OAuth credential model for reactions, native uploads, or proactive DM lookup.

## What This Changes

The issue requests optional Google Chat user OAuth credentials for reactions, media uploads, reaction typing, and proactive DM lookup while preserving service-account webhook behavior.

## Best Possible Solution

Add a plugin-owned, secret-aware Google user OAuth credential model and scoped OAuth client routing for only the operations that require user auth, while keeping service-account auth for webhook verification and existing bot sends.

## Reproduction Assessment

Yes, at source level. Current main only accepts service-account credentials, always requests `chat.bot`, and has no user OAuth config branch, though no live Google Workspace repro was run in this read-only review.

## Solution Assessment

Unclear until maintainer/security direction is set. User OAuth is the plausible product path, but the durable fix needs the right SecretRef, scope, fallback, docs, and live-proof shape rather than only the issue's config sketch.
