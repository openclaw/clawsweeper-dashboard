## Summary

Keep open. Current main and the latest release still implement Google Chat around service-account credentials and the `chat.bot` scope only, while the linked media-fallback work addresses one delivery symptom without adding the requested user OAuth model.

## What This Changes

The issue requests optional Google Chat user OAuth support for outbound reactions, native media uploads, reaction typing, and proactive DM/email-alias lookup.

## Best Possible Solution

Add a plugin-owned, secret-aware Google user OAuth credential model and scoped OAuth client routing for only the operations that require user auth, while keeping service-account auth for webhook verification and existing bot sends.

## Reproduction Assessment

Yes, source-level reproduction is high-confidence: current main accepts service-account credentials only and always requests the `chat.bot` scope for Google Chat API calls. I did not run a live Google Workspace OAuth repro.

## Solution Assessment

Unclear until maintainer/security direction is set; user OAuth is the plausible durable path, but the issue's config sketch is not enough without SecretRef, redaction, scoped-token routing, fallback, docs, and live proof.
