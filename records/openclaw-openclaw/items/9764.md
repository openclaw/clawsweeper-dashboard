## Summary

Keep open. Current main still supports only service-account/app authentication for Google Chat and explicitly withholds reactions and outbound attachments, so the requested user-auth capabilities remain unimplemented. The related media-link fallback work mitigates one delivery failure but does not provide native uploads, reactions, or email-address DM lookup; the remaining direction needs maintainer and security approval. ([github.com](https://github.com/openclaw/openclaw/blob/main/extensions/googlechat/src/auth.ts))

## What This Changes

Add optional Google Chat user authentication for reactions, native media uploads, reaction typing indicators, and proactive direct-message lookup while retaining service-account authentication for app operations and webhook verification.

## Best Possible Solution

Define a plugin-owned Google Chat user-auth profile and onboarding flow—using the existing secrets/auth-storage conventions rather than raw refresh tokens in ordinary config—then route only user-required operations through least-privilege user credentials, preserve app auth for webhook and bot operations, expose capabilities only when usable credentials exist, and prove fresh setup, upgrade fallback, revocation, multi-account isolation, and live Google Chat behavior.
