## Summary

Keep this PR open for maintainer review. The patch is a focused fix for a source-reproducible auto-reply deadlock, and I did not find a concrete correctness or security defect, but the session-state ordering change still needs explicit maintainer acceptance before merge.

## What This Changes

The PR detaches delivered transcript mirroring from final reply completion and adds regression tests for unresolved or rejecting dispatcher-idle waits.

## Best Possible Solution

Land this narrow fix after maintainers accept delivered transcript mirroring as post-delivery bookkeeping; if that ordering is not acceptable, replace the awaited call with a dedicated post-completion mirror queue that does not block operation completion.

## Reproduction Assessment

Yes. Current main source shows final reply completion awaiting a mirror helper that first waits for dispatcher idle, while the reply operation is only completed after final payload dispatch returns.

## Solution Assessment

Yes, with an ordering caveat. Detaching only the post-delivery mirror is the narrowest fix for the completion-to-idle cycle; a broader mirror queue is only needed if maintainers require mirror durability before next-turn admission.
