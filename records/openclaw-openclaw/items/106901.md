## Summary

Keep open for protected maintainer review. The patch appears to correctly close the Control UI connection-lease gap left by the merged session-transaction work: queued settings now enter the session capability immediately, retain the original Gateway connection, and decline stale dispatch after reconnect.

## What This Changes

The PR moves queued-wait ownership into the Control UI session capability so session-setting patches retain the Gateway connection captured when the user action began.

## Best Possible Solution

Keep route capture, queue waiting, stale-connection rejection, and optimistic rollback inside the session capability, then land the focused patch after normal protected maintainer review and exact-head checks complete.

## Reproduction Assessment

Yes at source level: queue a settings patch behind an unresolved tail, replace the Gateway connection, and then release the tail; current main enters the session capability only after the wait and can therefore bind the replacement connection.

## Solution Assessment

Yes. Moving the wait into the session capability is the narrowest maintainable fix because that owner can synchronously capture the route, preserve optimistic-update behavior, and reject stale dispatch without duplicating connection policy in chat callers.
