## Summary

Keep open. Current OpenClaw gateway behavior matches its metadata-pinning contract, but the shipped Windows Hub operator client path still appears able to omit `client.deviceFamily`, so the reported restart pairing loop is a real Windows companion/release issue rather than stale core noise.

## What This Changes

The issue reports that Windows Hub/Tray reconnects without `deviceFamily`, causing repeated gateway `metadata-upgrade` pairing after restart.

## Best Possible Solution

Fix the Windows Hub operator gateway client to send canonical `client.deviceFamily` in the connect payload, align v3 signed metadata with that value, add operator-client regression coverage, and promote a signed Windows Hub release through the OpenClaw release asset workflow.
