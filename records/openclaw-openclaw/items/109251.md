## Summary

Keep open: the prior checkout-trust finding is addressed, but the new retry-ownership mechanism persists security-sensitive state outside the required SQLite store, and the intentional existing-path compatibility break needs owner confirmation.

## What This Changes

## Best Possible Solution

Keep the fresh-checkout, sanitized-Git boundary, but persist conversion ownership transactionally in the shared SQLite state database, retain only the minimum checkout attestation needed for safe matching, and cover crash/retry cleanup plus the intentional existing-path refusal in upgrade proof.

- **[P1] Store retry ownership in the shared SQLite state DB:** `src/cli/update-cli/shared.ts:66`
  - body: Do not add the `update-checkouts/*.token` sidecar as persistent OpenClaw state. This token participates in deciding whether a later run may stop the service and replace the checkout, but coordinating it with the `.git` marker and directory swap is not transactional and can leave stale or partial authorization state after failures. Store the ownership record in the shared state database and add focused crash/retry cleanup coverage.
