## Label Justifications

- `P0`: The reported update path can fetch, build, and install attacker-selected code, which is a direct code-execution and software-supply-chain boundary failure.
- `merge-risk: 🚨 security-boundary`: The patch may imply an adopted checkout is trusted even though its Git configuration can still execute commands or redirect the fetched source.
- `merge-risk: 🚨 compatibility`: The all-remotes rule intentionally rejects existing fork-plus-upstream checkout layouts that the current dev-channel switch silently adopts.

## Summary

Keep open: the underlying bug is valid and the before/after proof is strong, but checking remote URL strings does not make an already-existing checkout trustworthy. Repository-local Git configuration can still execute commands or redirect transport before OpenClaw builds the checkout, and the new all-remotes rule also intentionally blocks common fork-plus-upstream layouts, so the trust boundary needs an explicit maintainer decision before merge.

## What This Changes

The PR verifies every effective Git remote and accepted transport before a package installation adopts an existing checkout for dev-channel updates, with real-repository regression tests.

## Best Possible Solution

On package-to-dev transitions, create or reuse only an explicitly OpenClaw-managed checkout and refuse any preexisting unmanaged directory; keep in-place updates available only when the running installation is already proven to originate from that checkout.

Full review comments:

- **[P1] Do not trust a checkout based only on its remote URLs:** `src/cli/update-cli/shared.ts:183`
  - body: A preexisting directory that passes this canonical-URL predicate still controls repository Git configuration. For example, `core.fsmonitor`, `core.hooksPath`, or `core.sshCommand` can execute attacker-selected commands, and proxy/TLS configuration can redirect fetches while the displayed remote stays canonical. Because the updater later runs Git and builds in this directory, the patch does not establish the provenance boundary it claims. Refuse unmanaged preexisting checkouts and use a fresh OpenClaw-owned clone instead.
