## Label Justifications

## Summary

The previous security blocker remains on the exact same reviewed head: the Git sanitizer still inherits `GIT_TEMPLATE_DIR`, allowing a fresh clone to copy and execute an ambient hook before the checkout is trusted. The refreshed proof is strong, but merge also needs explicit updater-owner approval for the intentional existing-path compatibility break.

## What This Changes

The PR makes package-to-dev conversion create a fresh Git-config-sanitized checkout at an unused path, stores interrupted-conversion ownership in shared SQLite state, and aligns the CLI, wizard, tests, and docs with that flow.

## Best Possible Solution

Force clone to use a trusted empty template so no ambient hooks can be copied, add a hostile executable-hook regression test, then land the fresh-checkout design only after an updater owner explicitly approves the documented unused-path migration policy.
