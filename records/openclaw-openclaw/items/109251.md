## Summary

Keep open: the PR convincingly blocks foreign Git remotes, but it still treats a pre-existing directory as trustworthy when a canonical remote is present; attacker-controlled Git configuration such as `core.fsmonitor` can then execute code during the updater’s subsequent Git operations. The durable trust boundary requires maintainer direction before merge.

## What This Changes

The PR verifies every effective remote URL and transport before adopting an existing checkout for package-to-dev channel updates, and adds real-Git regression coverage.

## Best Possible Solution

Keep in-place updates for users already running a source checkout, but make package-to-dev switching create and use a fresh OpenClaw-owned checkout; refuse pre-existing directories unless OpenClaw has a durable, verifiable ownership marker and safe Git configuration contract.
