## Summary

Keep open: current main still lacks a TUI viewport anchor/follow policy and still routes streaming assistant markdown through pi-tui’s renderer path that can full-redraw and clear scrollback. The merged WebChat setting at https://github.com/openclaw/openclaw/pull/81629 is a separate browser surface, and the narrower open scrollback-loss issue at https://github.com/openclaw/openclaw/issues/78017 only partially overlaps this broader TUI viewport-jump tracker.

## What This Changes

The issue asks for stable TUI viewport and auto-scroll behavior during active chat so new messages and streaming output do not disrupt the user’s reading position.

## Best Possible Solution

Resolve this with live-proven TUI behavior that preserves scrollback and viewport anchoring, coordinates with https://github.com/openclaw/openclaw/issues/78017, and does not treat the WebChat setting as a terminal fix.
