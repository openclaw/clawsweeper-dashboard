## Summary

Keep open: current main still has the TUI streaming path that can trigger disruptive renderer behavior, the WebChat auto-scroll setting is a separate browser surface, and the related TUI PRs/issues do not provide a merged or safe canonical replacement.

## What This Changes

The issue asks for stable TUI viewport or auto-follow behavior so terminal chat does not jump disruptively when messages are sent or streamed.

## Best Possible Solution

Define TUI-owned viewport anchoring semantics, keep the WebChat setting separate, and validate with PTY or real-terminal proof that streaming and follow-up sends do not jump or erase scrollback.
