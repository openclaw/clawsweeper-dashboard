## Summary

Keep open: current main still routes TUI streaming updates through ChatLog into pi-tui Markdown without a TUI-owned viewport anchor or auto-follow setting, and the pinned pi-tui renderer still has a content-driven full-redraw path that can clear scrollback. The merged WebChat auto-scroll setting is browser-only, while the narrower open pi-tui scrollback issue overlaps but does not replace this broader TUI viewport-jump tracker.

## What This Changes

The issue requests stable TUI viewport behavior during chat sends and streaming, potentially via better anchoring, controlled auto-follow, or an explicit TUI auto-scroll control.

## Best Possible Solution

Keep this as the broader TUI viewport-jump tracker and resolve it with a live-proven TUI/pi-tui anchoring or follow policy coordinated with the narrower pi-tui scrollback-clearing issue.

## Reproduction Assessment

Yes at source level, but not with high-confidence live proof: current main still streams TUI assistant deltas through Markdown rendering and the pinned renderer can full-redraw above the viewport. A live PTY capture with PI_DEBUG_REDRAW=1 is still needed for the exact current-main visual jump.
