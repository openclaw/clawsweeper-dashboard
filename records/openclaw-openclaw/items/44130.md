## Summary

Keep open: the WebChat auto-scroll fix is explicitly separate, and current main still routes TUI streaming text through the same ChatLog/Markdown/pi-tui rendering path that can redraw above the viewport without a TUI-owned anchor or auto-follow policy.

The issue asks OpenClaw to stop disruptive TUI scroll jumps during normal chat by preserving viewport behavior or adding a TUI auto-scroll control.

## Best Possible Solution

Keep this as the TUI-specific tracker, reproduce it in a real or PTY TUI session, then fix default viewport anchoring so new content follows only when the user is already at the bottom; add a TUI preference only if maintainers choose that product surface.
