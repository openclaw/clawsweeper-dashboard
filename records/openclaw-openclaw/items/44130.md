## Summary

Keep open: current main still lacks a TUI-owned viewport anchor, auto-follow mode, or auto-scroll preference, and the current pi-tui renderer still has a source-visible full-redraw path that can clear scrollback. The merged WebChat selector is a separate browser surface, while https://github.com/openclaw/openclaw/issues/78017 is a narrower overlapping TUI renderer bug rather than a full replacement for this broader TUI tracking issue.

## What This Changes

The issue asks OpenClaw to make `openclaw tui` preserve a stable chat viewport or controlled auto-follow behavior when new messages and streamed output arrive.

## Best Possible Solution

Define and land one TUI-owned default behavior that keeps reading position stable while preserving a predictable follow-latest path, then prove it in the TUI PTY lane and with a real terminal or Crabbox recording.
