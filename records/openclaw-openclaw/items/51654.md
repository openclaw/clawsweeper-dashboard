## Label Justifications

- `P2`: This is a real ACP feature/API gap with security implications, but it requires product/security design rather than urgent runtime repair.
- `impact:session-state`: The requested env map would make ACP subprocess environment state session-scoped and affect isolation, reuse, and initialization semantics.
- `impact:security`: The request explicitly includes API keys and endpoint overrides passed into host ACP harness processes.
- `impact:auth-provider`: The main use cases involve per-session provider credentials, base URLs, model/provider isolation, and auth routing.

## Summary

Keep open: current main and v2026.6.11 still do not expose a public `sessions_spawn.env` ACP path, while related work covers configured per-agent env, sandbox-env headers, or credential scrubbing rather than this per-spawn ACP API. The request is coherent but needs maintainer product/security review because it would pass credential-like values into host ACP subprocess environments.

## What This Changes

Request adding an optional per-spawn environment map to `sessions_spawn` for ACP sessions so callers can override or merge env vars for ACP subprocesses.

## Best Possible Solution

Define one credential-safe ACP session env contract, then wire the tool schema, ACP spawn params, manager initialization, ACPX delegate options, validation/redaction, docs, and focused tests through that contract.

## Reproduction Assessment

Not applicable as a bug reproduction; yes for source-level absence. Current main and v2026.6.11 expose no `sessions_spawn.env` parameter and do not forward env through ACP spawn, manager initialization, or ACPX session options.

## Solution Assessment

No, not as a raw env-map patch alone. The maintainable path needs a maintainer-approved credential boundary for validation, redaction, allowed sources, persistence, and interaction with inherited-env scrubbing.
