## Summary

Keep open: current main and v2026.6.11 still lack a public `sessions_spawn.env` path for ACP sessions, while related env work covers per-agent env, per-call sandbox env, or ACP credential scrubbing rather than this per-spawn ACP API.

## What This Changes

The issue requests an optional `sessions_spawn.env` map for ACP spawns so each ACP session can receive per-spawn environment variables.

## Best Possible Solution

Define one credential-safe ACP session env contract, then wire tool schema, ACP spawn, manager initialization, ACPX session options, validation, redaction, docs, and focused tests through that contract.

## Maintainer Decision

Question: Should OpenClaw expose per-spawn ACP session environment injection, and what credential-safe boundary should it use?

Rationale: The requested API can move credential-like values from a model-callable tool input into host ACP harness processes, so automation should not choose the trust, redaction, persistence, and precedence policy.

Likely owner: osolmaz

Owner confidence: high

Options:

- **Design a scoped ACP env contract first (recommended):** Approve the capability only behind explicit validation, redaction, source-of-trust, persistence, and ACPX/session-reuse rules before implementation.
- **Defer to per-agent or per-call env work:** Keep this issue open until https://github.com/openclaw/openclaw/issues/93425 and https://github.com/openclaw/openclaw/issues/80329 clarify the permanent env-source model.
- **Reject model-callable env maps:** Decline raw `sessions_spawn.env` and require operators to use configured SecretRef or plugin-owned auth surfaces instead.

Yes. Source inspection of current main and v2026.6.11 shows no `sessions_spawn.env` parameter and no env forwarding through ACP spawn, manager initialization, or ACPX session options.
