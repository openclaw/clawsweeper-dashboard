## Summary

Keep open: current main and the latest release still do not expose a model-callable `sessions_spawn.env` path for ACP sessions, and the remaining work is a credential-bearing ACP API/security design rather than conservative cleanup.

## What This Changes

Request to add a per-session `env` map to `sessions_spawn` so ACP sessions can receive scoped environment variables instead of only inheriting the gateway process environment.

## Best Possible Solution

Define a credential-safe ACP session env contract, then wire schema, spawn, manager, ACPX/backend behavior, redaction, docs, and tests through that contract before closing this issue.

## Reproduction Assessment

Yes, source-level. Current schema, ACP spawn params, manager initialization, and latest-release code still omit a public `sessions_spawn.env` path even though the lower-level ACP type has an env slot.

## Solution Assessment

No for the raw shape as written. A plain model-callable env map is not the best boundary until maintainers define validation, redaction, trusted sources, and interaction with credential scrubbing.
