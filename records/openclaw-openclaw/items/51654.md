## Summary

Keep open: current main and v2026.6.11 still lack a public `sessions_spawn.env` path for ACP sessions. Related env work covers per-agent subprocess env, per-call sandbox env, or ACP credential scrubbing rather than this per-spawn ACP API, so the remaining work needs maintainer product/security direction.

## What This Changes

The issue requests an optional `env` map on `sessions_spawn` for ACP sessions so individual spawned ACP sessions can receive per-session environment variables.

## Best Possible Solution

Define one credential-safe ACP session env contract, including allowed callers, blocked keys, redaction, precedence, persistence/session-reuse rules, and interaction with ACP credential scrubbing before wiring the tool and adapter path.

Options:

- **Design guarded ACP session env (recommended):** Add `sessions_spawn.env` only with explicit trusted-caller rules, blocked-key validation, redaction, precedence, non-persistence or reuse behavior, docs, and focused ACP tests.

- **Reject request-time ACP env:** Keep ACP subprocess env controlled by configured runtimes and documented setup paths, and document that per-session credential overrides are intentionally unsupported.
