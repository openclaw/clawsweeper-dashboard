## Summary

Keep open: current main and v2026.6.11 still lack a model-callable `sessions_spawn.env` ACP path, while the requested credential-bearing env surface needs maintainer product/security design before implementation.

## What This Changes

The issue requests an optional session-level `env` map on `sessions_spawn(runtime: "acp")` that would be injected into spawned ACP/acpx subprocess environments.

## Best Possible Solution

Define one credential-safe ACP session env contract, then wire `sessions_spawn`, ACP spawn, manager initialization, ACPX/backend handling, redaction, docs, and tests through that contract.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 expose no `sessions_spawn.env` field and do not forward env through ACP spawn or manager initialization.

## Solution Assessment

No for the raw shape as written: a plain model-callable env map is not the best boundary until maintainers define validation, redaction, allowed sources, and interaction with credential scrubbing.
