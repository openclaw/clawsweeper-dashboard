## Summary

Keep open: current main and latest release still lack a model-callable `sessions_spawn.env` ACP path, and the overlapping per-agent/per-call env work does not close this exact per-spawn ACP request. The remaining work is product/security design for a credential-bearing subprocess env contract, not conservative cleanup.

## What This Changes

The issue requests session-scoped environment variables for ACP `sessions_spawn` calls so per-session credentials or endpoints can be passed to ACP harnesses.

## Best Possible Solution

Define one credential-safe ACP env contract, then wire schema, spawn, manager, ACPX/backend behavior, redaction, docs, and tests through that contract, or explicitly decide that configured per-agent env is the supported boundary instead of per-spawn env.

## Reproduction Assessment

Yes, source-level. Current main’s `sessions_spawn` schema, ACP spawn params, manager ensure call, and public ACP docs all omit an `env` path, so a live ACP run is not needed to prove the requested surface is absent.

## Solution Assessment

No for the raw shape as written. A plain model-callable env map is not the best boundary until maintainers define validation, redaction, trusted caller/source rules, and interaction with existing credential scrubbing.
