## Summary

Current main and the latest checked release still lack a session-level env parameter on `sessions_spawn` for ACP sessions, and the related env/scrubbing work only covers adjacent per-agent or credential-isolation paths. Keep this open for maintainer product and security design rather than closing as fixed or superseded.

## What This Changes

Request to support session-level environment variables for ACP sessions, especially an `env` map passed through `sessions_spawn` into ACP runtime session startup.

## Best Possible Solution

Keep the issue open until maintainers choose one env contract that covers ACP session startup, plugin ownership, redaction, and upgrade behavior without bypassing existing credential-scrubbing protections.

## Reproduction Assessment

Yes: source inspection shows there is no current `sessions_spawn.env` input or ACP manager forwarding path, so callers cannot request session-level ACP env through the existing tool.

## Solution Assessment

Unclear: adding a raw `env` map is plausible because lower ACP runtime types have an env slot, but the best fix needs maintainer security/product design across per-call, per-agent, and ACPX env work.
