## Summary

Keep open: current main has a lower-level ACP runtime `env` slot, but `sessions_spawn`, ACP spawn, manager initialization, and ACPX behavior still do not expose a safe per-session env path. The requested credential-bearing surface needs maintainer product/security design, not conservative cleanup.

## What This Changes

The issue requests an optional per-session environment map for ACP `sessions_spawn` calls so ACP subprocesses can receive session-specific values.

## Best Possible Solution

Define one credential-safe ACP session env contract, then wire schema, spawn, manager initialization, ACPX/backend behavior, redaction, docs, and tests through that contract before closing this issue.

## Reproduction Assessment

Yes. Source inspection shows the lower ACP runtime contract has an `env` slot, but the model-callable `sessions_spawn` schema, ACP spawn params, and manager initialize path do not accept or forward per-session env.

## Solution Assessment

Unclear. Wiring the existing lower-level env slot may be part of the solution, but a raw model-callable env map is not the best boundary until maintainers define trust source, validation, redaction, and interaction with credential scrubbing.
