## Label Justifications

- `impact:session-state`: The requested env would become part of ACP session launch state and must have clear reuse and persistence semantics.

## Summary

Keep open: current main and the latest checked release still do not expose or forward a per-spawn `sessions_spawn.env` contract for ACP sessions. The remaining work is a credential-bearing ACP API design question, not an obsolete duplicate of adjacent per-agent env or provider-env scrubbing work.

## What This Changes

Request optional per-spawn environment variables for ACP sessions launched through `sessions_spawn`.

## Best Possible Solution

Define a maintainer-approved, credential-safe ACP session env contract, then wire it through `sessions_spawn`, ACP spawn/manager initialization, ACPX `sessionOptions.env`, docs, and focused tests.

## Reproduction Assessment

Yes: source inspection of current main and v2026.6.11 shows no public `sessions_spawn.env` parameter and no env forwarding through the ACP spawn, manager, or ACPX adapter paths; no live failing run was needed to establish the missing surface.

## Solution Assessment

No for a raw pass-through: the best fix needs a credential-safe API contract that uses the existing ACPX `sessionOptions.env` shape only after OpenClaw-owned validation, redaction, documentation, and session lifecycle rules are settled.
