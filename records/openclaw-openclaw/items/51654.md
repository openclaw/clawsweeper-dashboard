## Summary

Keep open: current main and v2026.6.11 still lack a public `sessions_spawn.env` ACP path, and the related open work covers per-agent env, sandbox env headers, or credential scrubbing rather than this per-spawn ACP API. The request is coherent and source-reproducible, but it needs maintainer product/security direction before implementation because it would pass credential-like values into host ACP subprocess environments.

## What This Changes

The issue requests an `env` map on `sessions_spawn` so ACP sessions can receive per-session environment variables at spawn time.

## Best Possible Solution

Define one credential-safe ACP session env contract, then wire the tool/schema, ACP spawn, manager initialization, ACPX session options, validation, redaction, docs, and focused tests through that contract.

## Reproduction Assessment

Yes for source-level absence: current main and v2026.6.11 lack a public `sessions_spawn.env` parameter and env forwarding through ACP spawn, manager initialization, and ACPX session options.

## Solution Assessment

No, not as a raw env-map patch alone. The maintainable path needs a maintainer-approved credential boundary for validation, redaction, allowed sources, persistence, and interaction with inherited-env scrubbing.
