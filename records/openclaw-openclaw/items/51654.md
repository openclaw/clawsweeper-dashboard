## Summary

Keep open: current main, the latest prerelease, and the latest stable release still lack a public `sessions_spawn.env` ACP path, and related work only covers per-agent env, sandbox env headers, or credential scrubbing. The request is coherent, but it needs maintainer product/security direction before implementation because it would pass credential-like values into host ACP subprocesses.

## What This Changes

Request an optional `env` map on ACP `sessions_spawn` calls so spawned ACP sessions can receive session-specific environment variables.

## Best Possible Solution

Define one credential-safe ACP session env contract, then wire tool schema, ACP spawn, manager initialization, ACPX `sessionOptions.env`, validation, redaction, docs, and focused tests through that contract.

## Reproduction Assessment

Yes. Source inspection of current main shows no `sessions_spawn.env` parameter and no env forwarding through ACP spawn, manager initialization, or ACPX session options.

## Solution Assessment

No, not as a raw env-map patch alone. The maintainable path needs maintainer-approved validation, redaction, allowed sources, persistence behavior, and interaction with inherited-env scrubbing.
