## Label Justifications

- `P2`: This is a real ACP feature/API gap with security implications, but it needs product/security design rather than urgent runtime repair.
- `impact:session-state`: The request would make ACP subprocess environment state session-scoped and affect isolation, reuse, and session initialization semantics.
- `impact:security`: The requested examples explicitly pass API keys and endpoint overrides into host ACP harness processes.
- `impact:auth-provider`: The main use cases involve per-session provider credentials, base URLs, model/provider isolation, and auth routing.

## Summary

Keep open: current main and the latest release still do not expose or forward a per-spawn `sessions_spawn.env` ACP contract, and the related open work only partially overlaps with static per-agent env, sandbox header env, or credential scrubbing.

## What This Changes

Request session-level environment variable injection for ACP `sessions_spawn` calls so per-session provider credentials or endpoints can differ from the gateway process environment.

## Best Possible Solution

Define one credential-safe ACP session env contract, then wire tool/schema, manager, ACPX `sessionOptions.env`, validation, redaction, docs, and focused tests through that contract.

## Reproduction Assessment

Yes, source-level. Current main and `v2026.6.11` omit a `sessions_spawn.env` parameter and do not forward env through ACP spawn or manager initialization.

## Solution Assessment

No, not as the raw map shape alone. A maintainable fix needs a maintainer-approved credential boundary for validation, redaction, allowed sources, and interaction with inherited-env scrubbing.
