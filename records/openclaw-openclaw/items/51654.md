## Label Justifications

- `P2`: This is a normal-priority ACP feature/API gap with credential-boundary implications, not an urgent broken runtime path.
- `impact:session-state`: The request changes ACP subprocess environment state at session or spawn scope, affecting isolation and reuse semantics.
- `impact:security`: The requested examples explicitly pass API keys and endpoint variables into host ACP harness subprocesses.
- `impact:auth-provider`: The primary use cases involve per-session provider credentials, endpoint selection, and auth/model isolation.

## Summary

Keep open: current main and v2026.6.11 still lack a public `sessions_spawn.env` path for ACP sessions. Upstream ACPX can carry session env, but OpenClaw still needs a maintainer-approved product and security contract before exposing model-callable credential injection into host ACP subprocesses.

## What This Changes

Support per-session or per-spawn environment variables for ACP sessions via an optional `env` payload on `sessions_spawn` for ACP runtime sessions.

## Best Possible Solution

Define one credential-safe ACP session env contract, then wire tool schema, ACP spawn, manager initialization, ACPX session options, validation, redaction, docs, and focused tests through that contract.

Rationale: The request is useful and upstream ACPX can carry session env, but it creates a model-callable credential-to-host-subprocess boundary, so automation should not choose the trust model, allowed keys, redaction, or reuse semantics.

Likely owner: vincentkoc

Owner confidence: medium

Options:

- **Design a safe per-spawn env contract (recommended):** Approve `sessions_spawn.env` only with validation, redaction, blocked-key or SecretRef-style handling, session freshness semantics, and focused tests across tool, manager, and ACPX paths.
- **Route to configured agent env:** Keep this issue open or later close it as superseded only if maintainers decide a configured `agents.list[].env` path is the supported solution for these use cases.
- **Reject per-spawn env:** Close the request if maintainers decide model-callable ACP environment injection is too broad for OpenClaw's security boundary.

## Reproduction Assessment

Yes for source-level absence: current main has no `sessions_spawn.env` schema field and no env forwarding through ACP spawn, manager initialization, runtime option validation, or current docs. This is a feature request rather than a failing behavior reproduction.

## Solution Assessment

No for a raw `env` map alone; upstream ACPX can accept session env, but the safer OpenClaw solution must first settle validation, redaction, allowed keys or SecretRef handling, and interaction with configured env and inherited-env scrubbing.
