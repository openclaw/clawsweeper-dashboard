## Label Justifications

- `P2`: The issue is a meaningful ACP runtime capability and credential-boundary design gap, but it is not a current first-run blocker or urgent regression.
- `impact:session-state`: The requested env would be session-scoped ACP runtime state and must interact with session creation, resume, and persistent ACPX reuse.
- `impact:security`: The proposed API can carry secrets or process-control environment variables into host subprocesses.
- `impact:auth-provider`: ACP harness authentication and provider credential scrubbing are directly adjacent to this requested env injection surface.

## Summary

Keep open: current main still lacks a public `sessions_spawn` session-level env parameter and does not forward env through the ACP spawn, manager, or ACPX runtime path, while related per-agent and sandbox-env work only partially overlaps this request.

## What This Changes

The issue requests an ACP `sessions_spawn`-level environment-variable contract so a caller can pass session-specific env into spawned ACP subprocesses.

## Best Possible Solution

Define one credential-safe ACP session env contract with maintainer-approved validation, redaction, session-reuse semantics, docs, and tests before wiring the tool schema through ACP spawn, manager initialization, and ACPX.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose per-spawn ACP session env, and what credential boundary should that API enforce?

Rationale: The requested surface can carry credentials and process-control values into host ACP subprocesses, so automation cannot safely choose between raw env injection, SecretRef-style indirection, trusted-caller gating, or deferring to per-agent env.

Likely owner: osolmaz

Owner reason: The decision centers on the ACP spawn/session API boundary introduced in the ACP thread-bound agents work.

Owner confidence: high

Options:

- **Add restricted session env (recommended):** Expose session-level ACP env only through a validated and redacted contract that defines allowed sources, blocked keys, SecretRef handling, and persistent-session reuse behavior.
- **Prefer configured per-agent env:** Close or defer this per-call API in favor of the safer configured `agents.list[].env` direction tracked by https://github.com/openclaw/openclaw/pull/96229 and https://github.com/openclaw/openclaw/issues/93425.
- **Reject tool-callable env:** Keep ACP subprocess environment controlled only by host configuration and existing auth mechanisms to avoid model-controlled credential or process mutation.

## Reproduction Assessment

Yes. Source inspection on current main and release `v2026.6.11` shows no `sessions_spawn.env` schema field and no env forwarding through ACP spawn, manager initialization, or ACPX session options.

## Solution Assessment

Unclear. The raw requested behavior is useful but not yet the best fix until maintainers choose a credential-safe boundary and align it with per-agent env, provider scrubbing, and persistent session semantics.
