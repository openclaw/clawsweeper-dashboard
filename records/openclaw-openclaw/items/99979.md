## Summary

Keep open: current main still lets `truncateLine` append an ellipsis after taking up to `maxLength` characters, so the helper can exceed the caller's requested display width; no duplicate or open fix PR owns the length invariant.

## What This Changes

The issue asks for `truncateLine` to keep truncated strings within `maxLength` so subagent label and task display widths remain aligned.

## Best Possible Solution

Make `truncateLine` enforce `output.length <= maxLength` in the shared helper while preserving UTF-16-safe slicing, then update the focused formatter tests; the subagent callers should not compensate individually.

## Reproduction Assessment

Yes. Source inspection of current main shows the helper appends `...` after slicing to `maxLength`, so the reported `truncateLine("abcdefghij", 5)` path deterministically returns an 8-character string.

## Solution Assessment

Yes. The best fix is a narrow shared-helper change that reserves suffix width while keeping surrogate-safe truncation; changing only subagent callers would duplicate the invariant and miss tests for the reusable helper.
