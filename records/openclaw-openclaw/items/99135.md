## Summary

Keep this PR open, but do not merge it yet. The exact-head layout still budgets page content from a minimum 752-point window, so at the reported 690-point height the hero and page consume nearly the entire window before the navigation bar, leaving the target bottom action at risk of remaining clipped. The PR also lacks native after-fix proof that would settle the SwiftUI behavior.

## What This Changes

The branch clamps the macOS onboarding window to the active visible screen, lowers its minimum content height to 640 points, updates centered placement behavior and native i18n metadata, and adds short- and tall-screen placement tests.

## Best Possible Solution

Keep the shared visible-frame placement clamp, but budget hero, page, and navigation space from the actual constrained window height and provide bounded scrolling for pages that cannot shrink, while preserving the preferred 752-point and taller-window behavior.
