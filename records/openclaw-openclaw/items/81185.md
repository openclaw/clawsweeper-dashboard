## Summary

This is a well-proven security fix at the correct execution-result boundary, but it expands agent-visible implicit redaction without addressing the documented risk that agents may write masked credentials back into configuration; the PR should remain open for a maintainer/security decision and a redaction signal contract.

## What This Changes

The PR redacts secret-shaped foreground exec, background process, node-host, live-update, and active-process context payloads before returning them to the agent.

## Best Possible Solution

Keep redaction at every execution-result emitter, but add a stable machine-readable redaction indicator and agent-visible warning across text and structured result surfaces, test safe config-read/write behavior, and design any raw-output reveal as a separate explicit privileged path.
