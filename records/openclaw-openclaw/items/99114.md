## Summary

Keep open: current main still corrupts sibling home-prefix paths in session-memory log display, and this PR uses the established boundary-aware helper with focused proof. I found no blocking code or security finding.

## What This Changes

The branch replaces two session-memory log path displays with `shortenHomePath()`, adds sibling-prefix regression coverage, and carries an SDK budget catch-up hunk already present on current main.

## Best Possible Solution

Land the narrow session-memory helper swap once required checks and mergeability are clean, while keeping browser and terminal home-prefix fixes in their own PRs.

## Reproduction Assessment

Yes, source-reproducible. Current main uses unbounded home-string replacement at both session-memory log display sites, so `/home/user2/...` displays as `~2/...` when `HOME=/home/user`; I did not run tests in this read-only review.

## Solution Assessment

Yes. Reusing `shortenHomePath()` is the narrowest maintainable fix for standalone filesystem paths; a hook-local helper would duplicate policy and `shortenHomeInString()` is broader than needed for a single path value.
