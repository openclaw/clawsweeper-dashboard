Overall correctness: patch is incorrect

Full review comments:

- **[P1] Preserve legacy numbered backups during migration:** `src/config/backup-rotation.ts:146-149`
  - body: This branch classifies every non-datetime `.bak.*` file as an orphan and unlinks it, including shipped `.bak.1`-`.bak.4` recovery slots. On the first post-upgrade config write, a user with a full current backup ring can lose four rollback snapshots before the datetime ring is populated, collapsing retention from the shipped five-deep history to `.bak` plus one timestamped backup. Please migrate or retain legacy slots until the new retention set is full.
  - confidence: 0.94
- **[P2] Add a collision fallback before renaming backups:** `src/config/backup-rotation.ts:53-56`
  - body: `rotateConfigBackups` still writes every rotation for a given millisecond to the same `.bak.<timestamp>` path. The comment documents that POSIX can silently overwrite the previous backup, but the code still drops that recovery point; add a deterministic suffix or existence check so burst writes cannot reduce retention.
  - confidence: 0.86
