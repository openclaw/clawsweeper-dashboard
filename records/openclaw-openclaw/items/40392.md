## Summary

Keep open: the timestamped-backup direction is useful, but this PR is not merge-ready because it deletes existing numbered rollback backups on upgrade, still has a timestamp collision loss case, and has no real behavior proof.

## What This Changes

This PR changes config backup rotation from `.bak.1`-style numeric slots to UTC datetime-stamped `.bak.<timestamp>` files and updates focused backup-rotation tests.

## Best Possible Solution

Land or replace this with a migration-safe timestamped backup implementation that preserves or converts legacy numbered backups, chooses unique collision-free targets, keeps bounded retention and permissions, updates docs if the contract changes, and includes real upgrade proof.

  - body: Current main treats `.bak.1`-`.bak.4` as managed rollback slots, but this branch deletes every non-datetime suffix during cleanup.   - confidence: 0.84
