- **[P1] Preserve legacy backups during timestamp migration:** `src/config/backup-rotation.ts:145-147`
  - body: On upgrade, existing `openclaw.json.bak.1` through `.bak.4` files now enter the non-datetime branch and are unlinked on the first cleanup cycle. That collapses shipped rollback retention before the new datetime set is populated, so the migration needs to preserve or convert those files instead of deleting them as ordinary orphans.
  - confidence: 0.92
- **[P2] Harden legacy backups before best-effort cleanup:** `src/config/backup-rotation.ts:97-100`
  - body: `hardenBackupPermissions` now skips every non-datetime suffix, including existing numbered backups. Since the later unlink is best-effort, a failed cleanup can leave sensitive config backups with their old permissions, whereas current main chmods the numbered slots first.
  - confidence: 0.82
- **[P2] Avoid same-millisecond backup name collisions:** `src/config/backup-rotation.ts:52-55`
  - body: `rotateConfigBackups` still uses a single millisecond timestamp as the destination. Two rotations with the same timestamp overwrite the previous backup on POSIX, or fail and get swallowed on Windows, so burst writes can silently lose a recovery point without a collision fallback.
  - confidence: 0.78
