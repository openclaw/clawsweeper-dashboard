  - body: On upgrade, released users can already have `.bak.1` through `.bak.4` recovery files. This cleanup path treats every non-datetime suffix as an orphan and unlinks it after only one datetime backup can exist, so the first config write collapses retention and can permanently remove rollback points.   - confidence: 0.94
- **[P2] Allocate collision-safe backup names:** `src/config/backup-rotation.ts:53`
  - body: The timestamp is the entire destination filename, so two rotations in the same millisecond target the same `.bak.<timestamp>` path. On POSIX that can replace the previous backup, and on Windows it can fail and be swallowed, reducing retained history. Probe for an available suffix or otherwise guarantee unique targets before renaming.
  - confidence: 0.86
- **[P2] Keep legacy backups in the chmod scan:** `src/config/backup-rotation.ts:97`
  - body: The new hardening loop skips `.bak.N` files, and cleanup deletion is best-effort. If an existing legacy config backup cannot be unlinked, it can remain on disk without the owner-only chmod that current main applies. Continue hardening legacy backups until migration/deletion is proven safe.
  - confidence: 0.87
