- **[P1] Preserve legacy backup slots during upgrade:** `src/config/backup-rotation.ts:146-147`
  - body: This branch treats every non-datetime `.bak.*` file as an orphan, so a first config write after upgrade deletes existing `.bak.1` through `.bak.4` recovery points before the datetime ring is populated. Preserve or migrate those legacy slots until replacement backups exist, otherwise users lose rollback snapshots during the upgrade.
  - confidence: 0.94
- **[P2] Generate collision-free timestamp backup names:** `src/config/backup-rotation.ts:53`
  - body: `rotateConfigBackups` writes to one millisecond timestamp name, and the comment now documents that same-ms writes can overwrite on POSIX or be swallowed on Windows. Add a suffix/probe or monotonic fallback so burst config writes do not silently lose a backup snapshot.
  - confidence: 0.88
- **[P2] Harden legacy backups before cleanup:** `src/config/backup-rotation.ts:97-98`
  - body: The new chmod scan skips non-datetime `.bak.N` files, while cleanup deletes those files best-effort. If unlink fails, old config backups that may contain secrets no longer receive the owner-only chmod current main applies to numbered slots, so include legacy managed backups in the hardening or migration path.
  - confidence: 0.8
