Full review comments:

- **[P1] Preserve legacy backup slots during upgrade:** `src/config/backup-rotation.ts:145-148`
  - body: On the first config write after this change, `cleanOrphanBackups` treats existing `.bak.1`-`.bak.4` files as non-datetime orphans and deletes them, leaving only the current `.bak` plus one datetime backup. That drops shipped recovery points users may still need; keep or migrate those numbered backups until equivalent datetime backups exist.
  - confidence: 0.96
- **[P2] Handle timestamp collisions instead of overwriting backups:** `src/config/backup-rotation.ts:53-56`
  - body: `rotateConfigBackups` renames the primary backup directly to `.bak.<timestamp>`, and the current comment acknowledges that a same-millisecond collision can overwrite an existing backup on POSIX. The linked issue explicitly called for collision handling; add an exclusive fallback suffix or equivalent so burst writes do not silently lose a recovery point.
  - confidence: 0.88
- **[P2] Update the documented backup naming contract:** `src/config/backup-rotation.ts:170-180`
  - body: Current doctor docs still tell users that config writes rotate `openclaw.json.bak` through a numbered `.bak.1` to `.bak.4` ring. If this runtime behavior changes to timestamped files, update `docs/cli/doctor.md` so recovery instructions match the files users will see.
  - confidence: 0.86
