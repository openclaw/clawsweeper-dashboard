## Summary

Keep open: the patch changes an established plugin-facing callback from the key-rotation position to a separate per-key execution counter. History confirms these counters have different meanings, so the PR needs compatibility-aware API direction before merge.

## What This Changes

The PR changes key-rotation callbacks from receiving the zero-based API-key rotation position to receiving the current key’s 1-based execution attempt.

## Best Possible Solution

Preserve the current rotation-attempt behavior; if plugins also need same-key retry information, introduce clearly named `apiKeyIndex` and `attemptNumber` fields with maintainer-approved compatibility handling and focused tests.
