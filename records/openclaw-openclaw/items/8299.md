## Summary

Keep open: current main still lacks a documented `sessions_spawn` parameter or `agents.defaults.subagents` config key for deterministic sub-agent announce suppression, and the latest discussion adds production evidence that sentinel-token suppression remains unreliable.

## What This Changes

Request a framework-level sub-agent announce suppression control, either as config under `agents.defaults.subagents` or as a per-call `sessions_spawn` parameter.

## Best Possible Solution

Add a maintainer-approved, backward-compatible announce suppression contract that keeps current behavior by default, treats intentional suppression as successful lifecycle cleanup, and coordinates naming with parent-routing and per-channel policy work.

## Reproduction Assessment

Yes. Source inspection on current main shows no public `sessions_spawn` announce/silent parameter and no `agents.defaults.subagents.announcePolicy`, while announce suppression remains tied to sentinel-token output.

## Solution Assessment

Unclear. A per-spawn skip control appears to be the narrowest implementation, but maintainers should settle how it composes with global defaults, per-channel suppression, and parent routing before implementation is queued.
