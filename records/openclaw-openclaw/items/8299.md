## Summary

Keep open: current main and the latest release still lack a documented `sessions_spawn` parameter or `agents.defaults.subagents` config key that deterministically suppresses sub-agent completion announces; the remaining work is a real product/API decision, not stale cleanup.

## What This Changes

The issue requests a framework-level config option or per-spawn `sessions_spawn` parameter to suppress sub-agent completion announcements without relying on `ANNOUNCE_SKIP`.

## Best Possible Solution

Maintainers should choose one explicit announce-control shape, then add a documented opt-in policy that threads through `sessions_spawn`, subagent registry/lifecycle delivery, config schema/help, and subagent docs with regression tests for deterministic skip behavior.

## Reproduction Assessment

Yes for the missing capability: current source and docs show no public config key or `sessions_spawn` parameter for deterministic announce suppression, and the implemented suppression path still depends on exact sentinel replies. I did not run a live Telegram repro because the open item is a feature/API request and this review is read-only.

## Solution Assessment

Unclear whether the exact proposed `announcePolicy` shape is the best permanent API, because related open issues ask for per-channel suppression and parent-session routing. The best fix is a maintainer-selected unified policy surface, not a one-off automated config key.
