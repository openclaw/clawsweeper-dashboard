## Summary

Keep open: current main and the latest release still lack a documented config key or public `sessions_spawn` parameter for deterministic sub-agent announce suppression, and the remaining work is a product/API decision rather than stale cleanup.

## What This Changes

The issue requests a deterministic framework-level way to suppress sub-agent completion announcements, either through config under agent defaults or a `sessions_spawn` parameter.

## Best Possible Solution

Maintainers should choose one backward-compatible announce-control contract that can express current behavior plus deterministic skip, then thread it through `sessions_spawn`, config/schema/help, registry lifecycle, delivery paths, docs, and regression tests.

Options:

- **Unified announce policy (recommended):** Add one opt-in policy surface that preserves current behavior by default while supporting deterministic skip and staying compatible with broader parent/per-channel routing work.
- **Per-spawn skip only:** Expose only a `sessions_spawn` skip flag now, reducing config blast radius but leaving repeated boilerplate and per-channel defaults for later.
- **Defer to broader routing design:** Keep this parked behind announceTarget/per-channel design so one future contract covers skip, channel suppression, and parent routing together.

## Reproduction Assessment

Yes for the missing capability: current source and docs show no public config key or `sessions_spawn` parameter for deterministic announce suppression, and suppression still depends on exact sentinel replies or internal-only plumbing. ## Solution Assessment

Unclear as a final API choice. A deterministic skip control is justified, but maintainers should choose a unified policy shape that composes with per-channel suppression and parent-session routing instead of adding a one-off knob.
