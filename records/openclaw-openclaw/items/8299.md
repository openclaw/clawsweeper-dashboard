## Summary

Issue #8299 is still necessary because current main and the latest checked release still rely on model/token output for sub-agent announce suppression; the only deterministic skip path is internal plumbing, not a documented public config or `sessions_spawn` parameter. Keep it open as the canonical product/API decision for deterministic sub-agent announce suppression, with narrower routing/per-channel issues tracked separately.

## What This Changes

Request a deterministic framework-level way to suppress sub-agent completion announcements, globally and/or per `sessions_spawn`, instead of relying on exact model replies like `ANNOUNCE_SKIP` or `NO_REPLY`.

## Best Possible Solution

Keep #8299 open as the canonical suppression decision and design one additive announce-control surface that preserves current channel delivery by default while supporting deterministic skip/suppression.
