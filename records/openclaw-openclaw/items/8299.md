## Summary

Keep open: current main and v2026.6.11 still lack a public config key or `sessions_spawn` parameter for deterministic sub-agent announce suppression, and the remaining work is a product/API decision rather than a stale or implemented request.

## What This Changes

The issue requests a framework-level config option or `sessions_spawn` parameter to deterministically suppress sub-agent completion announces.

## Best Possible Solution

Define one backward-compatible completion-delivery policy that defaults to current behavior, supports deterministic suppression, treats intentional suppression as successful lifecycle cleanup, and coordinates with parent-routing and per-channel policy work.

## Reproduction Assessment

Yes for the missing capability. Source inspection shows no public `sessions_spawn` announce/silent parameter and no `agents.defaults.subagents.announcePolicy`, while docs still describe only sentinel-token suppression.

## Solution Assessment

Unclear as a final product choice. A per-spawn skip control appears to be the narrowest implementation, but maintainers should decide how it composes with a global default, per-channel suppression, and parent routing before code is queued.
