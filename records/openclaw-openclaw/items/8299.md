## Summary

Keep open: current main and latest release still lack a public config key or `sessions_spawn` parameter for deterministic sub-agent announce suppression, while the live discussion adds recent production evidence that token-only suppression remains unreliable.

## What This Changes

The issue requests a framework-level config option or `sessions_spawn` parameter to suppress sub-agent completion announces instead of relying on the model to emit `ANNOUNCE_SKIP`.

## Best Possible Solution

Add a maintainer-approved, backward-compatible announce suppression contract that preserves current behavior by default, treats intentional suppression as successful lifecycle cleanup, and coordinates naming with parent-routing and per-channel policy work.

## Reproduction Assessment

Yes. Source inspection on current main shows no public `sessions_spawn` announce/silent parameter and no `agents.defaults.subagents.announcePolicy`, while announce suppression remains tied to sentinel-token output or an internal-only boolean.

## Solution Assessment

Unclear. A per-spawn skip control appears to be the narrowest implementation, but maintainers should settle how it composes with a global default, per-channel suppression, and parent routing before code is queued.
