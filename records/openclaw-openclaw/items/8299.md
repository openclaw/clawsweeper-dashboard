## Summary

Keep open for a maintainer product decision. Current main has changed completion handling so child results are formed as internal parent-session events and the parent decides whether to send a user-facing update, addressing the original unreviewed-direct-post concern; however, it still provides no documented deterministic per-spawn or config policy that guarantees no completion-triggered user update at all.

## What This Changes

Request a framework-enforced sub-agent completion suppression policy, via sub-agent defaults or a public `sessions_spawn` parameter, instead of relying on `ANNOUNCE_SKIP`.

## Best Possible Solution

Keep the current parent-gated completion architecture, then decide whether OpenClaw also needs an explicit opt-in `sessions_spawn` completion-delivery policy that preserves the internal parent event while guaranteeing no external user-facing update.
