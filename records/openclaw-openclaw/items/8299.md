## Summary

Keep open: current main and the latest release still lack a documented config key or public `sessions_spawn` parameter for deterministic sub-agent announce suppression, and the related implementation PRs were closed unmerged while broader routing/per-channel issues remain separate.

## What This Changes

Request deterministic framework-level suppression for sub-agent completion announcements, via `agents.defaults.subagents` config and/or a `sessions_spawn` parameter, instead of relying on `ANNOUNCE_SKIP` or `NO_REPLY`.

## Best Possible Solution

Add a documented, default-preserving sub-agent announce policy at the chosen core boundary, with schema/types/help/docs and regression coverage for deterministic skip behavior that does not depend on model output tokens.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: the public tool schema and strict config schema lack the requested controls, and the announce flow only suppresses exact sentinel replies. I did not run a live Telegram sub-agent scenario in this read-only review.

## Solution Assessment

Unclear as an implementation shape: deterministic suppression is the right product goal, but maintainers still need to choose the permanent public surface across per-spawn, global config, per-channel policy, and parent-routing work.
