## Summary

Keep open: current main and v2026.6.11 still lack a documented config key or public `sessions_spawn` parameter for deterministic sub-agent announce suppression. The newer requester-agent handoff mitigates direct raw child-output delivery, but it does not provide the requested framework-level skip/no-announce control and still relies on sentinel tokens or internal-only state for suppression.

## What This Changes

Add a public config or per-spawn control to deterministically suppress sub-agent completion announces instead of relying on `ANNOUNCE_SKIP` / `NO_REPLY`.

## Best Possible Solution

Add a backward-compatible public suppression contract, likely a narrow per-spawn skip control plus an optional config default only if maintainers approve the product/API shape, and treat intentional suppression as successful cleanup across lifecycle and delivery paths.

## Reproduction Assessment

Yes. Source inspection is sufficient here: current main exposes no public `sessions_spawn` announce/silent parameter and no `agents.defaults.subagents.announcePolicy`, while deterministic suppression is limited to internal state or exact sentinel tokens.

## Solution Assessment

Unclear. A per-spawn skip control looks like the narrowest implementation, but maintainers should decide how it composes with global defaults, per-channel policy, and parent-routing proposals before code is queued.
