## Summary

Current main reduces the original direct-to-user bypass by routing nested completions through the parent announce chain and asking top-level requester turns to review results, but it still exposes no deterministic public suppression control. Recent production evidence and two closed, unmerged implementation attempts leave a real product/API decision unresolved.

## What This Changes

Add framework-level and/or per-spawn control to deterministically suppress sub-agent completion announcements without relying on model-emitted sentinel text.

## Best Possible Solution

Adopt one typed announce policy shared by registry and lifecycle delivery, with an explicit per-spawn skip mode and a global default only if maintainers accept the config cost; preserve current behavior by default, model intentional suppression as successful cleanup, and document and test every completion path.

Options:

- **One typed policy (recommended):** Add a shared enum used by `sessions_spawn` and optionally `agents.defaults.subagents`, preserving current behavior by default and including an explicit skip outcome.
- **Per-spawn only:** Expose a narrow `sessions_spawn` suppression parameter and defer persistent or per-channel defaults to avoid expanding configuration now.
- **Keep token control:** Treat parent-review routing plus `ANNOUNCE_SKIP` and `NO_REPLY` as sufficient and close the suppression requests without a framework control.

## Reproduction Assessment

Yes at source level: current main's public tool schema and strict config schema contain no deterministic suppression control, while documentation and runtime still rely on exact sentinel output. A live Telegram run was not needed to establish the missing public capability.

## Solution Assessment

Unclear until maintainers choose the permanent API shape; a single typed policy is preferable to independent `silent`, `suppressAnnounce`, channel-deny, and `announceTarget` controls that could drift.
