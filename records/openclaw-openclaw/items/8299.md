## Summary

Current main mitigates the original direct-to-user bypass by routing nested completions through the parent announce chain, but it still lacks deterministic public suppression. Recent production evidence confirms the token-only mechanism remains unreliable, while the permanent API/config shape requires maintainer direction.

## What This Changes

Add framework-level completion control so a native sub-agent run can deterministically suppress its announcement without relying on `ANNOUNCE_SKIP` or `NO_REPLY`.

## Best Possible Solution

Define one typed per-spawn completion target such as `parent | channel | none` at the `sessions_spawn`/registry boundary, preserve current behavior by default, and add a persistent sub-agent default only if maintainers explicitly approve the additional config surface; cover nested, cleanup, retry, and documentation behavior together.

## Solution Assessment

No, the original separate boolean and config sketches are not yet the best permanent shape. One typed completion-routing contract is narrower and less likely to drift, with persistent config gated by maintainer approval.
