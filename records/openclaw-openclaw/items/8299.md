## Summary

Keep this issue open. Current main now routes native sub-agent completions through a requester-agent handoff so the parent can review and decide whether to emit a visible update, materially reducing the original direct-to-user bypass. However, the public schema and docs still expose no deterministic control that suppresses the completion handoff entirely, and recent production evidence confirms the remaining need is token-independent silence rather than merely parent-mediated delivery.

## What This Changes

Add a framework-enforced global and/or per-spawn control that deterministically suppresses sub-agent completion announcements without relying on `ANNOUNCE_SKIP` or `NO_REPLY`.

## Best Possible Solution

Add one structured per-spawn completion policy with the current parent-review handoff as the default and an explicit `skip` mode that bypasses the handoff while completing cleanup successfully; add a persistent default only if maintainers approve the extra config surface, and align naming with the broader routing work.
