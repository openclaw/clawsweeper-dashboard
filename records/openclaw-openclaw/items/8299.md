## Summary

Keep open: current main now routes native sub-agent completions back through the requester agent for review, solving the original direct child-to-user bypass, but it still exposes no deterministic public control to suppress the completion handoff itself. The remaining request is a compatibility-sensitive product decision about adding a new `sessions_spawn` mode and, separately, whether a persistent config default is justified.

## What This Changes

Request a deterministic framework-level option that suppresses `sessions_spawn` sub-agent completion announcements instead of relying on child-model `ANNOUNCE_SKIP` output.

## Best Possible Solution

Keep parent-mediated completion handoff as the default, then—if maintainers want deterministic no-callback work—add one explicit per-spawn silent completion mode that bypasses the announce handoff while preserving terminal cleanup; add a persistent default only after a separate demonstrated need.
