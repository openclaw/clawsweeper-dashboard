## Label Justifications

- `P2`: This is a meaningful but bounded multi-agent workflow improvement with established workarounds and limited general-user blast radius.
- `impact:session-state`: Mandatory completion handoffs insert child output into the parent/requester transcript even when the orchestrator intentionally wants no completion context.

- `impact:ux-friction`: Users currently rely on unreliable magic-token prompting, polling, files, or downstream patches to obtain deterministic silence.

## Summary

Keep open: current main now routes sub-agent completions through the parent/requester agent for review, mitigating the original direct-to-user safety concern, but it still provides no deterministic public skip control; recent production evidence also shows that unwanted parent-context injection remains a real use case requiring maintainer product direction.

## What This Changes

Requests a deterministic framework-level config or per-spawn control to suppress sub-agent completion announcements.

## Best Possible Solution

Preserve parent-review delivery as the default, add a narrow per-spawn completion policy with explicit parent and skip modes, and treat skip as successful lifecycle completion; add global or channel defaults only if maintainers explicitly want persistent policy, with aligned schema, docs, and regression coverage.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should sessions_spawn expose a permanent deterministic skip mode, and if so should it be per-spawn only or also configurable as a persistent default?

Rationale: Current main intentionally guarantees parent-facing completion handoff, while the request asks to suppress that handoff entirely; naming, precedence, and whether to add another config surface are product/API choices rather than a mechanical bug fix.

Likely owner: tyler6204

Owner reason: They own the merged deterministic announce and descendant-gating architecture that the decision would extend.

Owner confidence: high

Options:

- **Add per-spawn completion policy (recommended):** Expose a narrow parent-or-skip parameter, preserve parent handoff as the default, and avoid adding global config until persistent demand is separately confirmed.
- **Add config and per-spawn policy:** Support a default sub-agent completion policy plus a per-call override, accepting the larger configuration and precedence contract.
- **Keep mandatory parent handoff:** Decline deterministic suppression because completion evidence should always return to the requester agent, leaving model tokens as the only silent path.

## Reproduction Assessment

Yes at source level: current docs and configuration types expose no deterministic skip control, while the documented suppression paths depend on exact model output tokens. A live failing run was not performed during this read-only review.

## Solution Assessment

No, the original three-mode config proposal is not yet proven to be the best shape; a narrow per-spawn parent-or-skip policy better satisfies the concrete need while respecting OpenClaw's high bar for additional global configuration.
