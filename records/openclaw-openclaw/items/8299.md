## Summary

Keep open: current main and v2026.6.11 still lack a documented config key or public `sessions_spawn` parameter for deterministic sub-agent announce suppression, and the remaining work is a public API/product decision rather than stale cleanup.

## What This Changes

Request a config option and/or per-spawn parameter to deterministically suppress sub-agent completion announcements without relying on `ANNOUNCE_SKIP`.

## Best Possible Solution

Maintainers should choose one backward-compatible announce-control contract that preserves current behavior by default, supports deterministic skip, and composes with parent-routing and per-channel suppression work.

Question: What public sub-agent completion-announcement control should OpenClaw support for deterministic skip/suppression?

Rationale: The missing behavior is source-proven, but adding public tool/config surface overlaps per-spawn skip, global defaults, per-channel suppression, and parent-session routing, so automation should not choose the durable API shape alone.

Likely owner: steipete

Owner confidence: high

Options:

- **Unified announce policy (recommended):** Add one opt-in policy surface that preserves current behavior by default while supporting deterministic skip and staying compatible with broader parent/per-channel routing work.
- **Per-spawn skip only:** Expose only a `sessions_spawn` skip flag now, reducing config blast radius but leaving repeated boilerplate and per-channel defaults for later.
- **Defer to broader routing design:** Keep this parked behind announceTarget/per-channel design so one future contract covers skip, channel suppression, and parent routing together.

## Reproduction Assessment

Yes for the missing capability: current source and docs show no public config key or `sessions_spawn` parameter for deterministic announce suppression, and suppression still depends on exact sentinel replies or internal-only plumbing.

## Solution Assessment

Unclear as a final API choice. A deterministic skip control is justified, but maintainers should choose a unified policy shape that composes with per-channel suppression and parent-session routing instead of adding a one-off knob.
