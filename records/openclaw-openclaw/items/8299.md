## Summary

Keep open: current main and the latest release still lack a public config key or `sessions_spawn` parameter for deterministic sub-agent announce suppression, and recent discussion adds production evidence that token-only suppression remains unreliable.

## What This Changes

The issue requests framework-level control, via config and/or a `sessions_spawn` parameter, to suppress sub-agent completion announces without relying on model-emitted sentinel tokens.

## Best Possible Solution

Add a maintainer-approved, backward-compatible deterministic announce suppression contract that preserves current behavior by default and treats intentional suppression as successful lifecycle cleanup.

## Reproduction Assessment

Yes. Source inspection on current main shows no public `sessions_spawn` announce/silent parameter and no `agents.defaults.subagents.announcePolicy`, while announce suppression remains tied to sentinel-token output or an internal-only flag.

## Solution Assessment

Unclear. A per-spawn skip control appears to be the narrowest implementation, but maintainers should settle how it composes with a global default, per-channel suppression, and parent routing before code is queued.
