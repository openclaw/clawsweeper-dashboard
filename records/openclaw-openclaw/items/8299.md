## Summary

Keep open: current main and v2026.6.11 still lack a documented config key or public sessions_spawn parameter that deterministically suppresses sub-agent completion announcements, and the remaining choice is product/API shape rather than stale cleanup.

## What This Changes

Request a framework-level config option or per-spawn parameter to suppress sub-agent completion announcements without relying on the model emitting ANNOUNCE_SKIP.

## Best Possible Solution

Maintainers should choose one backward-compatible announce-control contract, then thread deterministic skip through sessions_spawn, config/schema/help, registry lifecycle, delivery paths, docs, and regression tests.

Options:

- **Unified announce policy (recommended):** Add one opt-in policy surface that can express current behavior plus deterministic skip and remains compatible with broader routing work.
- **Per-spawn only:** Add only a sessions_spawn skip flag and leave global/per-channel defaults for later, reducing schema blast radius but leaving repeated boilerplate.
- **Defer to routing design:** Keep this issue parked behind the broader announceTarget/per-channel design, avoiding duplicate API surface at the cost of continued workarounds.

## Reproduction Assessment

Yes for the missing capability: current source and docs show no public config key or sessions_spawn parameter for deterministic announce suppression, and suppression still depends on exact sentinel replies or internal-only plumbing. I did not run a live Telegram/model repro in this read-only review.

## Solution Assessment

Unclear as an API choice. A deterministic skip control is justified, but maintainers should choose a unified policy shape that composes with per-channel suppression and parent-session routing instead of adding a one-off knob.
