## Summary

Keep open: current main and v2026.6.11 still lack a public config key or `sessions_spawn` parameter for deterministic sub-agent announce suppression, while the discussion has recent production evidence that sentinel-token suppression remains unreliable.

## What This Changes

Request a framework-level sub-agent announce suppression control, either through `agents.defaults.subagents` config or a public `sessions_spawn` parameter.

## Best Possible Solution

Add a maintainer-approved, backward-compatible announce suppression contract that defaults to current behavior, treats intentional suppression as successful lifecycle cleanup, and composes with parent-routing and per-channel policy work.

## Reproduction Assessment

Yes. Source inspection on current main reproduces the missing capability: there is no public `sessions_spawn` announce/silent parameter and no `agents.defaults.subagents.announcePolicy`, while suppression remains sentinel-token driven.

## Solution Assessment

Unclear. A per-spawn skip control looks like the narrowest useful path, but maintainers should settle how it composes with a global default, per-channel suppression, and parent routing before implementation.
