## Summary

This issue still tracks a missing, deterministic control: the documented and previously reviewed completion flow relies on child-model output tokens to suppress an announce, rather than a framework-enforced spawn policy. The related parent-routing request is broader and does not replace the narrower requirement to skip delivery entirely, so this needs a maintainer decision on the public contract before implementation.

## What This Changes

Add a deterministic way to suppress a `sessions_spawn` sub-agent completion announcement so the requester chat never receives unreviewed child output.

## System Context

`sessions_spawn` creates a child agent run from a requester session. When that run ends, the sub-agent announce pipeline formats and delivers a completion message back toward the requester; this request adds a policy decision before that delivery occurs.

## Architecture Diagram

flowchart LR
  A[Requester session] --> B[Spawn sub-agent]
  B --> C[Child run completes]
  C --> D[Resolve announce policy]
  D -->|deliver| E[Format completion]
  E --> F[Requester chat]
  D -->|skip| G[Record completion without chat delivery]

## Best Possible Solution

Define one canonical resolved announce mode with an opt-in per-spawn `skip` override first; if maintainers also want a persistent default, add it under `agents.defaults.subagents` with the existing delivery behavior preserved by default, schema/help/docs alignment, and lifecycle tests for skip versus delivery.
