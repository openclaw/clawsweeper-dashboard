## Summary

Keep open: current main and v2026.6.11 still lack a public `sessions_spawn` or `agents.defaults.subagents` suppression policy, while the discussion adds production evidence that token-only announce suppression remains unreliable.

## What This Changes

Request a config default and/or per-spawn option to deterministically suppress sub-agent completion announces instead of relying on `ANNOUNCE_SKIP`.

## Best Possible Solution

Define a maintainer-approved, backward-compatible suppression contract that preserves current behavior by default, treats intentional suppression as successful cleanup, and coordinates naming with parent routing and per-channel policy work.

## Reproduction Assessment

Yes. Source inspection on current main shows no public `sessions_spawn` announce/silent parameter and no `agents.defaults.subagents.announcePolicy`, while suppression remains tied to sentinel-token output or an internal-only flag.

## Solution Assessment

Unclear. A per-spawn skip control appears to be the narrowest low-config implementation, but maintainers should settle how it composes with a global default, per-channel suppression, and parent routing before code is queued.
