## Summary

Keep open: current main and the latest release still lack a documented config key or public `sessions_spawn` parameter that deterministically suppresses native sub-agent completion announcements, and the remaining decision is the public API/config shape rather than stale cleanup.

## What This Changes

The issue asks for a framework-level config option and/or `sessions_spawn` parameter to suppress sub-agent completion announcements without relying on `ANNOUNCE_SKIP`.

## Best Possible Solution

Adopt one backward-compatible announce-control contract that defaults to current behavior, expresses deterministic skip, composes with parent/per-channel routing work, and is threaded through schema, spawn, registry lifecycle, delivery, docs, and regression tests.

- **Per-spawn skip only:** Add only a `sessions_spawn` skip flag, minimizing config blast radius but leaving repeated boilerplate and channel defaults for later work.
- **Defer to routing design:** Hold this issue behind the broader announceTarget/per-channel design to avoid duplicate API surface, at the cost of continued workarounds.

Yes for the missing capability: current source and docs show no public config key or `sessions_spawn` parameter for deterministic announce suppression, while suppression still depends on sentinel replies or internal-only plumbing. I did not run a live Telegram/model repro in this read-only review.

## Solution Assessment

Unclear as a final API choice. Deterministic skip is justified, but maintainers should choose a unified policy shape that composes with per-channel suppression and parent-session routing rather than adding a one-off knob.
