## Summary

Keep open: current main and the latest release still lack a documented config key or public `sessions_spawn` parameter for deterministic sub-agent announce suppression, while related open work only covers broader routing or token-parser hardening.

## What This Changes

Request a framework-level way to suppress sub-agent completion announces, either through `agents.defaults.subagents.announcePolicy` or a per-spawn `sessions_spawn` option.

## Best Possible Solution

Add a maintainer-approved, backward-compatible announce suppression contract that preserves current behavior by default, treats intentional suppression as successful lifecycle cleanup, and coordinates naming with parent-routing and per-channel policy work.

## Reproduction Assessment

Yes. Source inspection on current main shows no public `sessions_spawn` announce/silent parameter and no `agents.defaults.subagents.announcePolicy`, while announce suppression remains tied to sentinel-token output or an internal-only boolean.

## Solution Assessment

Unclear. A per-spawn skip control appears to be the narrowest surface, but maintainers should settle how it composes with a global default, per-channel suppression, and parent routing before code is queued.
