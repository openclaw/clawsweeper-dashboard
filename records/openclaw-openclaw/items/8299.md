## Summary

Keep open: current main and the latest release still lack a documented `sessions_spawn` parameter or `agents.defaults.subagents` policy that deterministically suppresses sub-agent completion announces, so this remains a real product/API decision rather than cleanup.

## What This Changes

The issue requests a framework-level configuration or per-spawn option to suppress sub-agent completion announces without relying on the model emitting `ANNOUNCE_SKIP`.

## Best Possible Solution

Maintainers should choose one explicit announce-control shape, then add an opt-in deterministic skip/routing policy through `sessions_spawn`, subagent lifecycle delivery, config/schema/help, docs, and regression tests.

## Reproduction Assessment

Yes for the missing capability: current source and docs show no public config key or `sessions_spawn` parameter for deterministic announce suppression, and the implemented suppression path still depends on exact sentinel replies. This is a feature/API request, so I did not run a live Telegram repro in the read-only review.

## Solution Assessment

Unclear whether the exact proposed `announcePolicy` shape is the best permanent API because related open items ask for per-channel suppression and parent-session routing. The best fix is a maintainer-selected unified policy surface rather than an automated one-off config key.
