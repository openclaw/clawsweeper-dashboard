## Summary

Keep open: current main and the latest release still lack a documented `sessions_spawn` parameter or `agents.defaults.subagents` policy that deterministically suppresses sub-agent completion announces, and related open items cover broader routing/per-channel behavior rather than replacing this narrower request.

## What This Changes

Request a framework-level sub-agent announce suppression control, either as config under `agents.defaults.subagents` or as a per-`sessions_spawn` parameter, so suppression does not depend on model output tokens.

## Best Possible Solution

Maintainers should choose one explicit announce-control shape, then add an opt-in deterministic skip/routing policy through `sessions_spawn`, subagent lifecycle delivery, config/schema/help, docs, and regression tests without relying on `ANNOUNCE_SKIP` or `NO_REPLY`.

## Reproduction Assessment

Yes for the missing capability: current source and docs show no public config key or `sessions_spawn` parameter for deterministic announce suppression, and the implemented suppression path still depends on exact sentinel replies. This is a feature/API request, so I did not run a live Telegram repro in the read-only review.

## Solution Assessment

Unclear whether the exact proposed `announcePolicy` shape is the best permanent API because related open items ask for per-channel suppression and parent-session routing. The best fix is a maintainer-selected unified policy surface rather than an automated one-off config key.
