## Label Justifications

- `P1`: Native memory search can repeatedly return unreadable citations for indexed project knowledge, breaking a core agent recall workflow for affected users.
- `impact:session-state`: The QMD index and returned memory paths disagree with the canonical files, causing durable recall state to reference nonexistent documents.

## Summary

Keep this issue open: current main has earlier slug-recovery logic, but it still trusts an exact active QMD row and constructs a result path without verifying or recovering the real indexed filesystem path. The existing regression coverage models a slugified query hint paired with an active real path, not the reported state where the real underscore path is inactive and the nonexistent hyphenated path is active. ([github.com](https://github.com/openclaw/openclaw/raw/refs/heads/main/extensions/memory-core/src/memory/qmd-manager.ts))

## What This Changes

Fix native QMD searches that return active slugified document paths instead of the corresponding real files on disk.

## Best Possible Solution

Build a deterministic, collision-safe mapping from QMD result identities to canonical collection paths during indexing or synchronization, then return only uniquely mapped real source paths at search time without adding broad filesystem discovery or freshness polling to the request hot path.
