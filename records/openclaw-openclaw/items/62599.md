## Label Justifications

- `P2`: The issue is a normal-priority diagnostic correctness bug with misleading memory/vector output and plugin side-effect risk, but no crash or data-loss evidence.
- `impact:session-state`: The issue concerns memory/vector runtime state being reported from a different process context than the live gateway.
- `impact:ux-friction`: Misleading status output can send users and operators into unnecessary plugin troubleshooting even when the live gateway is healthy.
- `maturity:stable`: The affected CLI status snapshot surface maps to `cli-install-update-onboard-doctor` / CLI Observability, which is scored M4 Stable.

## Summary

Keep open. Current main mitigates plain fast status by skipping memory inspection, but full memory-reporting status paths still instantiate the selected memory plugin in the CLI process and probe local manager state, so the live-gateway mismatch and side-effect boundary remain unresolved.

## What This Changes

The issue asks for `openclaw status` to avoid initializing memory plugins locally and to avoid reporting vector state from a CLI-local runtime instead of the live gateway.

## Best Possible Solution

Define one status contract where memory reporting is read-only, either reflects live gateway memory-runtime health or uses a truly passive plugin status API, and has regression coverage for third-party memory plugins with startup side effects.

Options:

- **Use live gateway truth (recommended):** Status memory details should prefer the running gateway's memory runtime health and avoid local plugin startup for plugin-owned memory state.
- **Define passive local status:** Keep local status reporting but require a narrow plugin status API that cannot run embedder, backfill, or vector startup work.
- **Do not report plugin vector state:** Treat plugin memory vector readiness as unavailable to CLI status and direct users to plugin-owned diagnostics instead.

Unclear: the plugin-local passive guard described in the issue is only a mitigation. The best core solution needs a maintainer decision between live gateway health and a passive plugin status contract.
