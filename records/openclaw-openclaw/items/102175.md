## Summary

Keep open: current main and v2026.6.11 still force non-internal room_event turns to message_tool_only before the automatic visible-reply setting can apply, and the prompt path still uses that actual delivery mode in cache-sensitive prompt sections. Current docs and tests also make strict ambient-room delivery intentional, so the remaining choice needs maintainer direction rather than cleanup closure.

## What This Changes

The issue asks OpenClaw to stop room_event turns from overriding groupChat.visibleReplies automatic and changing the system-prompt/cache contract, or to add/document a separate room-event delivery policy.

## Best Possible Solution

Preserve ambient-room privacy by default while maintainers choose whether to stabilize the session prompt separately from delivery, add an explicit room-event delivery knob, or document the strict prompt/cache tradeoff.
