## Summary

Keep open: current main and the latest release still route active transcripts through whole-file repair/open paths and still append the full-bootstrap marker without a cap, while the linked PR only attempts a partial bootstrap-marker mitigation and remains open.

## What This Changes

The issue requests a recovery guard for oversized session transcripts that can be reloaded after crashes, append bootstrap markers repeatedly, and OOM the gateway in a restart loop.

## Best Possible Solution

Implement a maintainer-approved pre-open recovery boundary that preserves or quarantines oversized active transcripts before repair/open and prevents repeated bootstrap-marker growth without silently losing user history.

Options:

- **Quarantine and Degrade by Default (recommended):** Preserve the oversized transcript, skip loading it on restart, mark the session degraded, and keep the gateway available while doctor/manual recovery remains possible.
- **Truncate Oldest History Automatically:** Rewrite the active transcript to a bounded tail so the session remains usable, accepting automatic loss of older context.
- **Require Manual Doctor Repair:** Fail with a clear recovery path and no automatic rewrite, preserving all data but leaving unattended services down until operator action.
