## Summary

Keep open: current main and v2026.6.11 still lack a default quarantine, skip, or truncate boundary before oversized active session JSONL reaches whole-file repair/open, while the open bootstrap-marker PR only addresses one growth amplifier.

## What This Changes

The issue reports a gateway crash-restart loop where large session transcripts and repeated bootstrap-context appends inflate session state until the gateway OOMs.

## Best Possible Solution

Choose and implement a core session recovery policy that prevents pathological active transcripts from reaching unbounded repair/open on restart, then land the bootstrap append cap or an equivalent guard as part of that boundary.

Options:

- **Quarantine before open (recommended):** Detect pathological active transcripts before repair/open, move or mark them as degraded, and give users a doctor/fix path to recover or inspect the transcript.
- **Auto-compact and rotate:** Run a bounded compaction/rotation recovery path before normal open so the active transcript shrinks while the old JSONL remains archived.
- **Bootstrap cap only:** Land the open bootstrap marker circuit breaker as a partial mitigation and keep the broader transcript recovery behavior tracked here.

## Reproduction Assessment

Partially: source inspection shows current main still routes oversized active transcripts through whole-file repair and `SessionManager.open()` before any default quarantine, and issue comments report matching macOS/Linux crash loops. I did not run a live 31 MB OOM restart-loop reproduction.

## Solution Assessment

No: the open bootstrap-marker PR is a useful partial mitigation, but it is not the complete fix because it leaves the full transcript reload/recovery boundary unchanged. The best fix is a maintainer-approved bounded recovery path before unbounded repair/open, with regression coverage for restart behavior.
