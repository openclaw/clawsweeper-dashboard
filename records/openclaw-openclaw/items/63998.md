Rationale: The fix may preserve, truncate, quarantine, skip, reset, or migrate user transcripts, and that choice affects unattended availability, user data preservation, and recovery UX.

Owner confidence: high

Options:

- **Quarantine and degrade by default (recommended):** Skip the oversized active transcript on startup, preserve it for doctor/manual recovery, and let the gateway continue without re-entering the crash loop.
- **Truncate oldest history automatically:** Rewrite the session to a bounded tail so it remains usable, accepting automatic loss of older transcript context.
- **Require manual operator repair:** Fail with a clear doctor command and no automatic rewrite, preserving data but leaving unattended services down until action is taken.
