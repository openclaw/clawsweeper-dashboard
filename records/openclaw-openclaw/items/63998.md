## Summary

Keep open: current main and v2026.6.11 still route oversized active session JSONL through whole-file repair/open before any default quarantine, skip, or truncate boundary, and the open bootstrap-marker PR only addresses one amplifier.

## What This Changes

The issue reports an unrecoverable gateway crash-restart loop caused by oversized session transcripts, repeated bootstrap-context appends, duplicated media payloads, and missing degraded-session recovery.

## Best Possible Solution

Add a maintainer-approved default pre-open recovery boundary that classifies oversized active transcripts before repair/open, records a recoverable degraded state, and exposes a doctor/fix recovery path; treat the bootstrap-marker cap as only a partial mitigation.

Rationale: The code-level problem is real, but choosing between quarantine, truncation, skip/reset, media dedupe, and doctor-assisted recovery affects persistent user transcript data and upgrade behavior.

Owner confidence: high

Options:

- **Default Quarantine With Doctor Recovery (recommended):** Mark the session degraded before whole-file repair/open, skip it for automatic restart recovery, and provide `openclaw doctor --fix` or an equivalent visible recovery path to archive, trim, or reset it.
- **Bounded Automatic Truncation:** Automatically retain the newest safe transcript window and compact/archive older content, accepting a stronger data-retention tradeoff for hands-free recovery.
- **Bootstrap-Only Mitigation First:** Land only the bootstrap-marker cap now and leave transcript-size and media recovery to later, accepting that the main crash loop can still recur on oversized files.
