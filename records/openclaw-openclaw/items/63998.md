## Summary

Keep open: current main and the latest release still route oversized active transcripts through whole-file repair and session open before any default quarantine, skip, or truncate boundary; the linked bootstrap-marker PR is open and only addresses one growth amplifier.

## What This Changes

Issue requests bounded recovery for oversized session transcripts that can crash-loop the gateway during restart and grow via repeated bootstrap-context entries.

## Best Possible Solution

Keep this as the canonical issue and choose a default oversized-transcript recovery policy that prevents gateway restart loops while preserving recoverable transcript data.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What default recovery behavior should OpenClaw use when an active session transcript is too large or repeatedly crashes the gateway on reload?

Rationale: The code fix may quarantine, truncate, skip, reset, or migrate user transcripts, and that affects data preservation, unattended service availability, and operator recovery UX.

Likely owner: steipete

Owner reason: steipete has the strongest recent history across the current embedded-runner, bootstrap, and internalized agent-runtime architecture where the default recovery policy belongs.

Owner confidence: high

Options:

- **Quarantine and Degrade by Default (recommended):** Preserve the oversized transcript for doctor/manual recovery, skip it during startup, and let the gateway continue serving other sessions.
- **Auto-Truncate Old History:** Rewrite to a bounded tail or compacted successor automatically, improving continuity but accepting automatic loss of older transcript context.
- **Require Operator Repair:** Fail with a clear doctor command and leave all data untouched, preserving state but keeping unattended services down until intervention.

## Reproduction Assessment

Yes at source level: field reports plus current path inspection show active transcripts still reach full-file repair and `SessionManager.open()` during restart. I did not run a live long-duration OOM reproduction.

## Solution Assessment

No current implementation is sufficient: the opt-in compaction rotation settings do not protect default startup, and the open bootstrap-marker PR only covers one amplifier.
