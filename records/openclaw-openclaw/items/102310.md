## Label Justifications

- `P1`: The PR targets a broken subagent tool workflow and currently introduces a blocking regression in core agent tool availability if merged.
- `merge-risk: 🚨 compatibility`: The diff changes how existing subagent session tool policy is persisted and can remove ordinary child tools in existing configurations.
- `merge-risk: 🚨 security-boundary`: The changed field is an authorization boundary for child session tools and now unions extra grants without proof that parent/session restrictions still hold.

## Summary

Keep open: the reported bug is plausible, but this patch is not merge-ready because it can turn target/global `alsoAllow` into the only inherited allowlist and drop normal child tools when the parent has no inherited allowlist.

## What This Changes

The PR changes subagent session creation to persist caller, global subagent, and target-agent `tools.alsoAllow` entries in `inheritedToolAllow`, with regression tests for the persisted patch.

## Best Possible Solution

Preserve target-agent extras without turning absence of a parent inherited allowlist into a restrictive child policy, then prove the actual spawned child tool surface for both restricted and unrestricted parents.
