## Summary

Keep open: this PR targets a real subagent tool-inheritance pain point, but the current patch is not mergeable because it both weakens the inherited parent allowlist boundary and can accidentally clamp unrestricted children to only `alsoAllow` tools.

## What This Changes

The branch changes native `sessions_spawn` child-session patching to persist global subagent `tools.alsoAllow` and target-agent `tools.alsoAllow` entries in `inheritedToolAllow`, with regression tests.

## Best Possible Solution

Keep inherited tool policy monotonic by default; if target-only delegation should exceed the requester surface, route it through an explicit delegate-only/self-deny design with documented deny-wins semantics and regression coverage.

  - body: This adds target/global `alsoAllow` entries to the child's stored inherited allowlist even when the requester inherited allowlist did not include them.   - confidence: 0.92

Because that stored value is later applied as an allow-only policy, an otherwise unrestricted child can be reduced to only the `alsoAllow` tools and lose normal tools like `read` or `sessions_spawn`; the new tests only cover cases where an inherited allowlist already exists.
