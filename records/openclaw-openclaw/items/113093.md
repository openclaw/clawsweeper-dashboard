## Summary

Keep this issue open as the canonical report. The same reporter filed an exact duplicate shortly afterward at https://github.com/openclaw/openclaw/issues/113095, but this earlier report still describes an unresolved release regression: a full tool profile can make every request to the affected llama.cpp OpenAI-compatible endpoint fail. Current documentation confirms that custom OpenAI-completions endpoints remain supported and that tool-schema normalization is an intended provider-owned extension point; it does not establish a current-main fix for this server/model combination.

## What This Changes

Fix the regression where a llama.cpp MTP server rejects the full OpenAI-compatible tool payload after upgrading, while smaller tool profiles continue to work.

## System Context

OpenClaw builds an agent tool set from the configured tool profile and sends it through a model provider or custom OpenAI-compatible endpoint. The endpoint parses that request schema before generation, so incompatible tool schemas prevent the agent run from reaching the model response stage.
