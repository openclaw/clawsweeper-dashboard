## Label Justifications

- `P2`: This is a normal-priority plugin API gap with real but bounded impact on production subagent workflows.
- `impact:session-state`: The request centers on child completion state, subagent session history, post-run artifacts, and parent-session completion context.

- `impact:message-loss`: The discussion ties the missing hook to detecting or recovering failed subagent completion announcements in channel workflows.

## Summary

Keep open: current main and v2026.6.11 still expose adjacent subagent lifecycle and delivery-routing hooks, but not the requested post-subagent-completion/pre-announcement extension point with child output/history access, delivery-result visibility, or announcement mutation semantics.

## What This Changes

Request a public extension hook after a spawned subagent completes and before its completion announcement is delivered, so plugins can inspect output, persist artifacts, enrich/filter announcements, or react to delivery failures.

## Best Possible Solution

Approve one typed plugin lifecycle or delivery boundary, or an equivalent canonical delivery contract, with bounded metadata, safe child-output access, explicit delivery-status visibility, return semantics, docs, and focused ordering/security regression tests.

- **Observation-Only Event:** Expose only a non-mutating completion event and leave announcement mutation or suppression to separate delivery-policy work such as https://github.com/openclaw/openclaw/issues/13911.
