## Summary

Keep open: current main and v2026.6.11 still expose only adjacent subagent observation/routing hooks, not the requested mutable post-completion/pre-announcement plugin API; the closest implementation PR is still open and review-blocked, so no close reason is safe.

## What This Changes

Request a plugin extension hook that fires after a spawned subagent finishes and before completion announcement delivery so plugins can inspect, persist, enrich, filter, or suppress completion output.

## Best Possible Solution

Keep this as the narrow canonical design item, then land either a bounded typed plugin hook at the post-subagent-completion/pre-announcement seam or a broader lifecycle/delivery API that covers safe child metadata, output access, delivery-result visibility, and announcement mutation semantics.

## Reproduction Assessment

Yes, at source level: current main exposes adjacent subagent observation/routing hooks but no mutable post-completion/pre-announcement hook. This is a missing feature/API surface, not broken documented behavior.

## Solution Assessment

Unclear pending maintainer API and security design. A typed plugin hook at this seam is plausible, but the best solution must settle payload bounds, delivery-result visibility, mutation semantics, and overlap with broader lifecycle hook work.
