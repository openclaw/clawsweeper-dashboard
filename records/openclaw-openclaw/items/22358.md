## Label Justifications

- `P2`: This is a normal-priority plugin API gap with real but bounded impact on production subagent workflows.
- `impact:session-state`: The request centers on child completion state, subagent session history, post-run artifacts, and parent-session completion context.
- `impact:security`: The proposed hook may expose child output/history and allow plugins to rewrite or suppress completion delivery.
- `impact:message-loss`: The discussion ties the missing hook to detecting or recovering failed subagent completion announcements in channel workflows.

## Summary

Keep open: current main and v2026.6.11 still expose adjacent subagent lifecycle and routing hooks only, not the requested post-subagent-completion/pre-announcement hook that can inspect, enrich, suppress, or observe delivery. The closed guard-hook PR at https://github.com/openclaw/openclaw/pull/56904 confirms a subagent-only rewrite seam was not accepted as-is, so the remaining work needs maintainer API and security design rather than cleanup closure.

## What This Changes

The issue requests a public extension hook after a spawned subagent finishes and before the completion announcement is sent, with access to completion context and optional announcement mutation or filtering.

## Best Possible Solution

Approve one bounded plugin lifecycle or delivery contract, or an equivalent canonical lifecycle design, with safe output access, delivery-status visibility where appropriate, explicit return semantics, docs, and focused ordering/regression tests.
