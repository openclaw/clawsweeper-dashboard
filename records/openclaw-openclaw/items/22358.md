## Label Justifications

- `P2`: This is a normal-priority plugin API and delivery lifecycle gap with real production subagent workflow impact but no emergency outage.
- `impact:session-state`: The request centers on child run completion state, subagent session history, post-run artifacts, and parent-session completion context.
- `impact:security`: The proposed hook could expose child output/history and let plugin code rewrite or suppress completion delivery.
- `impact:message-loss`: The discussion ties the missing hook to detecting or recovering failed subagent completion announcements in channel workflows.

## Summary

Keep open: current main and v2026.6.11 still lack the requested post-subagent-completion/pre-announcement extension point, and the recently closed guard-hook PR is not a safe supersession path.

## What This Changes

Request to add a plugin extension hook after a spawned subagent finishes and before its completion announcement is surfaced, allowing inspection, persistence, enrichment, suppression, or delivery-failure handling.

## Best Possible Solution

Settle a maintainer-approved typed lifecycle or delivery contract that exposes only bounded completion metadata, has explicit mutation/suppression semantics, documents the security boundary, and includes focused ordering and delivery regression tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: What post-subagent completion contract, if any, should OpenClaw expose for plugins, and should it allow observation only, announcement mutation/suppression, delivery-status visibility, or a broader generic delivery boundary?

Rationale: The missing source surface is clear, but the payload, child-history access, plugin authority, timeout/error behavior, delivery audit trail, and relationship to the rejected guard-hook PR are public API and security choices that automation should not lock in.

Likely owner: steipete

Owner reason: The latest maintainer review on the overlapping guard-hook PR provides the strongest current product/security direction for this boundary.

Owner confidence: high

Options:

- **Generic Typed Delivery Boundary (recommended):** Define one bounded hook or lifecycle contract for completion metadata and delivery decisions, avoiding the rejected PR's subagent-only guard-hook shape while preserving explicit security and audit semantics.
- **Observation-Only Completion Event:** Expose a non-mutating subagent completion event for metrics, trajectories, and indexing, while leaving suppression or routing to separate delivery-policy work.
- **Fold Into Broader Lifecycle Hooks:** Keep this issue open but defer implementation until https://github.com/openclaw/openclaw/issues/43454 settles a unified lifecycle hook model across subagents, turns, and thresholds.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 expose only adjacent observation/routing hooks, while the announce path has no public post-completion/pre-announcement interception point.

## Solution Assessment

Unclear pending maintainer design. A typed plugin lifecycle or delivery boundary is the right layer, but the exact subagent-only hook proposed here is not clearly the best shape after the overlapping guard-hook PR was closed as not planned.
