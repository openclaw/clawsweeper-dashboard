## Summary

Keep open: current main and v2026.6.11 still expose adjacent subagent lifecycle/routing hooks only, not a post-subagent-completion/pre-announcement extension point with result/history access, delivery-result visibility, and announcement mutation semantics. Related delivery fixes improved user symptoms, and the related guard-hook PR was closed as the wrong permanent API shape, so this remains a maintainer API/security-boundary decision.

## What This Changes

The issue requests a public hook after a spawned subagent finishes and before its completion announcement is sent, allowing plugins to inspect the child run and enrich, suppress, filter, or persist the announcement.

## Best Possible Solution

Define a maintainer-approved typed output/delivery lifecycle contract that covers post-subagent completion with minimized payloads, explicit delivery-result visibility, and clear mutation/suppression semantics before adding public plugin API.
