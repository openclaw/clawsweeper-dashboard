## Summary

Keep open: current main and v2026.6.11 still expose only adjacent subagent observation/routing hooks, while this request needs a mutable post-completion/pre-announcement plugin API. The overlapping implementation PR is open and review-blocked, so it is not a safe superseding fix yet.

## What This Changes

The issue requests a plugin extension hook that fires after a subagent completes and before the completion announcement is sent, allowing inspection, persistence, filtering, enrichment, or fallback delivery behavior.

## Best Possible Solution

Keep this as the narrow canonical design item, then land either a bounded typed plugin hook at the post-subagent-completion/pre-announcement seam or a broader lifecycle/delivery API that explicitly covers safe child metadata, output access, delivery-result visibility, and announcement mutation semantics.

## Reproduction Assessment

## Solution Assessment

Unclear pending maintainer API and security design. A typed plugin hook at this seam is plausible, but the best solution must settle payload bounds, delivery-result visibility, mutation semantics, and overlap with broader lifecycle hook work.
