## Summary

Keep open: current main and v2026.6.11 still expose only adjacent subagent observation/routing hooks, not the requested post-completion/pre-announcement hook that can inspect child output, observe delivery status, or mutate/suppress the announcement.

## What This Changes

The issue requests a public extension hook that runs after a spawned subagent completes and before its completion announcement is sent upstream.

## Best Possible Solution

Define a maintainer-approved typed plugin lifecycle or delivery boundary that covers post-child-result/pre-announcement processing with bounded metadata, safe output access, delivery-status visibility where appropriate, explicit mutation or suppression semantics, docs, and focused ordering/regression tests.

Required: true

Kind: product_direction

Question: What post-subagent completion or generic delivery/output hook contract should OpenClaw support, and what authority should plugins have to inspect child output, observe delivery, or mutate/suppress the announcement?

Rationale: The source gap is clear, but choosing payload fields, redaction, ordering, timeout/error behavior, auditability, and mutation authority creates a public plugin API and security boundary that automation should not lock in.

Likely owner: steipete

Owner reason: The strongest current product/API signal is the review closing the overlapping guard-hook PR, and recent commits touch the same subagent binding and delivery surface.

Owner confidence: high

Options:

- **Generic Typed Delivery Boundary (recommended):** Define one product-driven hook boundary for completion/output delivery, then make subagent completion use it with explicit redaction, fallback, timeout, and audit semantics.
- **Narrow Subagent Completion Hook:** Add a subagent-specific hook at the pre-announcement seam, accepting that a later generic delivery model may need to supersede it.
- **Observation-Only Event:** Expose only non-mutating completion metadata now and leave enrichment, suppression, and delivery-status recovery to separate delivery-policy work.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 expose only adjacent observation/routing hooks, while the announce path builds and delivers the completion without a public pre-delivery interception point.

## Solution Assessment

Unclear pending maintainer API and security design. A typed plugin hook or equivalent delivery/lifecycle boundary is the right layer, but the exact payload, mutation, suppression, and delivery-status semantics need approval.
