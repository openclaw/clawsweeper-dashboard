## Label Justifications

## Summary

Keep open: current main and v2026.6.11 still lack a post-subagent-completion/pre-announcement hook that can inspect child output, alter/suppress the announcement, or observe delivery status, and the related guard-hook PR was closed unmerged as the wrong API shape rather than as a fix.

## What This Changes

The issue requests a new plugin extension hook that fires after a subagent finishes and before its completion announcement is sent, with access to completion metadata and return semantics for enrichment, filtering, or suppression.

## Best Possible Solution

Define a maintainer-approved typed plugin lifecycle or delivery boundary that covers post-child-result/pre-announcement processing with bounded metadata, safe output access, delivery-status visibility where appropriate, explicit mutation/suppression semantics, docs, and focused ordering/regression tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What post-subagent completion or generic delivery/output hook contract should OpenClaw support, and what authority should plugins have to inspect child output, observe delivery, or mutate/suppress the announcement?

Rationale: The source gap is clear, but choosing payload fields, redaction, ordering, timeout/error behavior, auditability, and mutation authority would create a public plugin API and security boundary that automation should not lock in.

Likely owner: steipete

Owner reason: The most recent maintainer-facing signal on the overlapping hook PR came from steipete, and their recent subagent binding work touches the same API boundary.

Owner confidence: high

Options:

- **Generic Typed Delivery Boundary (recommended):** Define one product-driven hook boundary for completion/output delivery, then make subagent completion use it with explicit redaction, fallback, timeout, and audit semantics.
- **Narrow Subagent Completion Hook:** Add a subagent-specific hook at the pre-announcement seam, accepting the risk that a later generic delivery model may need to supersede it.
- **Observation-Only Event:** Expose only non-mutating completion metadata now and leave enrichment, suppression, and delivery-status recovery to separate delivery-policy work.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 expose only adjacent observation/routing hooks, while the announce path builds and delivers the completion without a public pre-delivery interception point.

## Solution Assessment

Unclear pending maintainer API and security design. A typed plugin hook or equivalent delivery/lifecycle boundary is the right layer, but the exact payload, mutation, suppression, and delivery-status semantics need approval.
