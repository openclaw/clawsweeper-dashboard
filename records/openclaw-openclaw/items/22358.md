## Summary

Keep open: current main and the latest release still expose only adjacent subagent observation/routing hooks, while this issue requests a mutable post-completion/pre-announcement plugin API; the overlapping implementation PR is open and review-blocked, so it is not a safe superseding fix.

## What This Changes

Request a public plugin hook after subagent completion and before the parent completion announcement so plugins can inspect child output, persist artifacts, and enrich, filter, or suppress the announcement.

## Best Possible Solution

Keep this as the canonical API design item, then land either a bounded typed plugin hook at the post-subagent-completion/pre-announcement seam or a broader lifecycle/delivery API that explicitly covers safe child metadata, output access, delivery-result visibility, and announcement mutation semantics.

## Reproduction Assessment

Yes, at source level: current main exposes adjacent subagent observation/routing hooks but no mutable post-completion/pre-announcement hook. This is a missing feature/API surface, not broken documented behavior.

## Solution Assessment

Unclear pending maintainer API and security design. A typed plugin hook at this seam is plausible, but the best solution must settle payload bounds, delivery-result visibility, mutation semantics, and overlap with broader lifecycle hook work.
