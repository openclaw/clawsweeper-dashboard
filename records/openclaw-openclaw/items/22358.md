- `impact:session-state`: The requested hook observes finished child sessions and could persist or transform subagent run state, completion output, and trajectory data.
- `impact:security`: The requested hook may expose child history, completion output, delivery metadata, and announcement mutation authority to plugins.
- `impact:message-loss`: A central use case is detecting failed completion delivery and optionally suppressing, enriching, or replacing user-facing subagent announcements.

## Summary

Keep open. Current main and the latest release still expose only adjacent subagent hooks; the requested post-completion/pre-announcement plugin interception point is missing, and the overlapping open PR is not a safe canonical replacement yet.

## What This Changes

The issue requests a public post-subagent-completion hook that can inspect a finished child run and optionally enrich, suppress, filter, or react to the parent completion announcement.

## Best Possible Solution

Keep this open for maintainer API design: either add a typed public plugin hook at the post-subagent-completion/pre-announcement boundary, or fold the same bounded payload, delivery-result visibility, ordering, timeout, and announcement mutation semantics into a broader lifecycle/delivery hook design with docs and regression coverage.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 lack a post-subagent-completion/pre-announcement modifying hook, while existing subagent_ended and subagent_delivery_target hooks are observation/routing-only.

## Solution Assessment

Unclear pending maintainer API and security design. A typed hook at the announce boundary is plausible, but the best solution must settle payload bounds, delivery-status visibility, mutation/suppression semantics, timeout behavior, and overlap with broader lifecycle hook work.
