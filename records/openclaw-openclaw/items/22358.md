## Summary

Keep open: current main and v2026.6.11 still expose only adjacent subagent lifecycle, delivery-target, and message hooks, not a post-subagent-completion/pre-announcement hook that can inspect child output/history, observe delivery status, or enrich/suppress the completion announcement. The rejected guard-hook PR is useful context but is closed unmerged, so it does not supersede this API-design gap.

## What This Changes

Request a public extension hook after a subagent completes and before its completion announcement is sent, with access for post-processing, trajectory persistence, announcement enrichment, suppression, and delivery-failure handling.

## Best Possible Solution

Approve one typed plugin lifecycle or delivery boundary, or an equivalent canonical delivery contract, with bounded metadata, safe child-output access, explicit delivery-status visibility, return semantics, docs, and focused ordering/security regression tests.
