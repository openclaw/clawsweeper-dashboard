## Summary

Keep open: current main and v2026.6.11 still expose only adjacent subagent observation/routing hooks, while this issue asks for a mutable post-completion/pre-announcement plugin hook with delivery/result visibility. The nearest implementation PR is open, conflicting, and review-blocked, so it is not a safe superseding fix.

## What This Changes

The issue requests a plugin extension hook after a subagent finishes and before its completion announcement is delivered, with access to result/history and ability to enrich, filter, or suppress the announcement.

## Best Possible Solution

Keep this open for maintainer API/security design and land a typed, documented plugin hook only after payload minimization, ordering, delivery-result visibility, mutation semantics, and regression tests are settled.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 list only adjacent subagent hooks, and the announce path builds/delivers completion events without a public pre-announcement interception point.

## Solution Assessment

Unclear pending maintainer API and security design. A typed plugin hook at the post-completion/pre-announcement boundary is plausible, but the final contract must settle payload bounds, delivery status exposure, mutation semantics, and ordering against broader lifecycle hook work.
