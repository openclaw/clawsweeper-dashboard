- `impact:message-loss`: The issue discussion ties the hook to detecting and recovering from failed subagent completion announcements.
- `impact:session-state`: The requested event would expose child session/run completion state and correlate it with the parent session announcement.
- `impact:security`: The hook could expose child output, transcript, or delivery metadata to plugins, so it needs an explicit security boundary.

## Summary

Keep open. Current main and the latest release still expose only adjacent observation/routing hooks; they do not provide the requested post-child-result, pre-announcement plugin hook that can inspect completion data and enrich, suppress, or observe delivery outcome.

## What This Changes

Request a public post-subagent-completion hook for plugins to inspect the finished child run and optionally enrich, filter, or suppress the parent completion announcement.

## Best Possible Solution

Keep this open for maintainer API design, either by repairing/reviewing the related guard-hook PR or by designing an equivalent typed plugin hook with bounded child metadata, approved output/history access, delivery status visibility where appropriate, and clear announcement mutation semantics.

## Reproduction Assessment

Yes. Source inspection reproduces the gap: current main exposes adjacent observation and routing hooks, but no public post-child-result, pre-announcement hook that can inspect completion data and modify or suppress the announcement.

## Solution Assessment

Unclear. The requested hook shape is plausible, and the related guard-delivery PR may be a better vehicle, but maintainers still need to choose the API boundary, ordering, and security model.
