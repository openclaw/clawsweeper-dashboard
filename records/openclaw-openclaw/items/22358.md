## Summary

Keep open: current main and the latest release still expose only adjacent subagent observation/routing hooks, while this request asks for a mutable post-completion/pre-announcement plugin API with security-sensitive payload and delivery semantics.

## What This Changes

The issue requests a public plugin extension hook after a subagent completes and before the completion announcement is delivered, with access to completion metadata and optional announcement mutation.

## Best Possible Solution

Keep this as the narrow canonical design item, then land either a bounded typed plugin hook at the post-subagent-completion/pre-announcement seam or a broader lifecycle/delivery API that explicitly covers safe child metadata, output access, delivery-result visibility, and announcement mutation semantics.

## Reproduction Assessment

Yes, at source level: current main exposes adjacent subagent observation/routing hooks but no mutable post-completion/pre-announcement hook. This is a missing feature/API surface, not broken documented behavior.

## Solution Assessment

Unclear pending maintainer API and security design. A typed plugin hook at this seam is plausible, but the best solution must settle payload bounds, delivery-result visibility, mutation semantics, and overlap with broader lifecycle hook work.
