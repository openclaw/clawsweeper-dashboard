## Label Justifications

- `P2`: This is a normal-priority plugin/API feature gap with repeated production subagent workflow impact, but it is not an emergency runtime outage.
- `impact:session-state`: The request centers on subagent completion state, child session history/output, and post-run artifacts before the parent session receives completion context.
- `impact:security`: The proposed hook can expose child output/history and allow plugins to rewrite or suppress parent-visible completion delivery.
- `impact:message-loss`: The discussion explicitly connects the missing hook to detecting failed subagent completion announcements and triggering fallback notification.

## Summary

Keep open. Current main and v2026.6.11 still expose only adjacent subagent lifecycle/routing hooks; the requested post-completion/pre-announcement hook remains a security-sensitive plugin API decision, and the overlapping implementation PR is open/conflicting rather than a safe superseding fix.

## What This Changes

Requests a plugin extension hook after spawned subagent completion and before parent announcement delivery so plugins can inspect output, persist artifacts, detect delivery failure, and enrich or suppress the announcement.

## Best Possible Solution

Approve a typed plugin or lifecycle delivery contract that covers post-child-result/pre-announcement inspection with bounded metadata, safe output access, delivery-status visibility where appropriate, and explicit enrichment/suppression semantics.

## Reproduction Assessment

Yes, by source inspection. Current main lacks the requested post-completion/pre-announcement hook, and the existing subagent hooks cannot inspect child output, modify announcements, or observe final delivery result.

## Solution Assessment

Unclear until maintainers settle the API and security model. The right direction is a typed plugin hook or equivalent lifecycle/delivery contract, not an ad hoc model-facing script hook or one-off delivery workaround.
