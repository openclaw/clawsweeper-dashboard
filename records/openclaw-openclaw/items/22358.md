## Summary

Keep open. Current main and v2026.6.11 still expose adjacent subagent lifecycle/routing hooks only; they do not provide the requested post-subagent-completion/pre-announcement hook that can inspect, enrich, suppress, or observe completion delivery, and the overlapping open PR is only a candidate implementation that still needs API/security judgment.

## What This Changes

Add a typed extension hook after subagent completion and before the parent completion announcement so plugins can inspect, persist, enrich, suppress, or react to completion data.

## Best Possible Solution

Approve one typed plugin lifecycle or delivery hook, or equivalent canonical lifecycle contract, that covers post-child-result/pre-announcement inspection with bounded metadata, safe output access, delivery-status visibility where appropriate, explicit return semantics, docs, and focused ordering/regression tests.
