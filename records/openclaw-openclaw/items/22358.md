## Summary

Keep open: current main and the latest release still only provide adjacent subagent observation/routing hooks, not the requested post-completion/pre-announcement extension point with child result access and announcement mutation semantics.

## What This Changes

The issue requests a public hook that runs after a subagent finishes and before its completion announcement is sent, allowing plugins to inspect results, persist artifacts, and enrich, filter, or suppress the announcement.

## Best Possible Solution

Keep this as the canonical post-subagent-completion hook design item and settle a typed plugin/lifecycle contract with bounded payloads, safe child-result access, delivery-status visibility, return semantics, docs, and focused ordering/regression tests.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 expose only adjacent subagent observation/routing hooks, while the announce flow still builds and delivers completion events without a public pre-delivery interception point.

## Solution Assessment

Unclear pending maintainer API and security design. A post-completion/pre-announcement hook is a plausible solution, but the best design must settle payload bounds, child-history access, delivery-result visibility, ordering, timeout behavior, and announcement mutation semantics.
