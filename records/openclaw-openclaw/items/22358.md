## Summary

Keep open. Current main and v2026.6.11 still expose only adjacent subagent lifecycle/routing hooks, not the requested post-subagent-completion/pre-announcement hook that can inspect, enrich, suppress, or observe completion delivery; the overlapping open PR is conflicting and still blocked on API/security review.

## What This Changes

Request a public extension hook that fires after a subagent finishes and before its completion announcement is delivered, with access to completion context and announcement mutation/filtering semantics.

## Best Possible Solution

Approve a typed plugin lifecycle or delivery hook, or equivalent canonical lifecycle contract, that covers post-child-result/pre-announcement inspection with bounded metadata, safe output access, delivery-status visibility where appropriate, explicit return semantics, docs, and focused ordering/regression tests.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 lack the requested post-completion/pre-announcement hook, while the adjacent subagent hooks cannot inspect or modify the final announcement result.

## Solution Assessment

Unclear pending maintainer API and security design. A typed plugin hook or equivalent lifecycle/delivery contract is the right layer, but the exact payload, ordering, suppression, and delivery-status semantics still need approval.
