## Summary

Keep open: current main and v2026.6.11 still lack the requested post-subagent-completion/pre-announcement extension point; adjacent hooks are observation- or routing-only, and the safe API shape needs maintainer product/security direction.

## What This Changes

Request a plugin/extension hook that runs after subagent completion and before the parent completion announcement so plugins can inspect, persist, filter, suppress, or enrich the result.

## Best Possible Solution

Define a maintainer-approved delivery/lifecycle extension contract, preferably a minimized typed post-completion/pre-delivery seam or a generic output-delivery boundary with explicit payload, mutation, suppression, security, and ordering rules.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose a public post-subagent-completion/pre-announcement hook, and if so should it be a narrow subagent hook or part of a generic output/delivery boundary?

Rationale: The missing hook is source-proven, but exposing child results and allowing announcement mutation or suppression changes plugin API, message delivery, session-state, and sensitive-data boundaries that automation should not choose.

Likely owner: vincentkoc

Owner reason: Recent hook contract and security-sensitive plugin API history makes this the strongest available owner for the payload and authority decision.

Owner confidence: high

Options:

- **Design Generic Delivery Boundary (recommended):** Define one minimized output/delivery interception seam that covers subagent completions and other guarded delivery needs before adding public hook names.
- **Add Narrow Subagent Hook:** Add a typed post-subagent-completion/pre-announcement hook with tightly scoped event fields, explicit return semantics, docs, and regression tests.
- **Keep Observation-Only Hooks:** Keep subagent_ended observation-only and solve fallback notification, suppression, and filtering through separate delivery-policy issues.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 expose only adjacent subagent hooks and the announce flow has no public post-completion/pre-announcement interception point. This is a feature/API gap rather than a failing current-main bug reproduction.

## Solution Assessment

Unclear as proposed: a post-completion seam is plausible, but the best maintainable solution may be a generic output/delivery boundary rather than a subagent-only mutable hook. The payload, authority, ordering, and fallback semantics need maintainer direction first.
