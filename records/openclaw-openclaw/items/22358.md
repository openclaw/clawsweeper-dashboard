## Summary

Keep open. Current main and v2026.6.11 still provide adjacent subagent observation/routing hooks, but not the requested post-subagent-completion/pre-announcement extension point; the related open guard-hook PR is only a candidate and still needs API/security judgment.

## What This Changes

Request a public post-subagent-completion hook that can inspect child run output/state and optionally enrich, suppress, or filter the completion announcement.

## Best Possible Solution

Approve one typed plugin lifecycle or delivery hook, or equivalent canonical lifecycle contract, with bounded metadata, safe output access, delivery-status visibility where appropriate, explicit return semantics, docs, and focused ordering/regression tests.

## Maintainer Decision

Question: What post-subagent completion hook contract should OpenClaw support, and what child-output, delivery-status, and announcement mutation authority should plugins get?

Rationale: The source gap is clear, but payload fields, privacy boundaries, hook ordering, timeout/error behavior, delivery-result visibility, and mutation/suppression authority are product and security API choices that automation should not freeze.

Likely owner: steipete

Owner confidence: high

Options:

- **Typed bounded plugin hook (recommended):** Add a public typed hook at the post-child-result/pre-announcement seam with explicit metadata, redaction, timeout, audit, and return semantics for enrichment or suppression.
- **Fold into broader lifecycle design:** Hold this specific API until https://github.com/openclaw/openclaw/issues/43454 settles one lifecycle event model across subagents, turns, and thresholds.
- **Observation-only event first:** Expose only non-mutating completion observation now and leave announcement suppression or delivery policy to separate work such as https://github.com/openclaw/openclaw/issues/13911.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 lack a post-completion/pre-announcement hook, and the adjacent subagent hooks cannot inspect or modify the final announcement result.

## Solution Assessment

Unclear pending maintainer API and security design. A typed plugin hook or equivalent lifecycle/delivery contract is the right layer, but payload, ordering, suppression, and delivery-status semantics still need approval.
