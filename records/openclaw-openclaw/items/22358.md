## Label Justifications

- `P2`: This is a normal-priority plugin API gap with real but bounded impact on production subagent workflows.
- `impact:session-state`: The request centers on child completion state, subagent session history, post-run artifacts, and parent-session completion context.

## Summary

Keep open: current main and v2026.6.11 still expose only adjacent subagent lifecycle/routing hooks, not the requested post-subagent-completion/pre-announcement hook with child output/history access, delivery-result visibility, or announcement mutation semantics.

## What This Changes

The issue requests a new plugin extension hook after a subagent finishes and before its completion announcement is delivered, allowing deterministic post-run processing and announcement enrichment/filtering.

## Best Possible Solution

Approve one typed plugin lifecycle or delivery boundary, or an equivalent canonical delivery contract, with bounded metadata, safe child-output access, delivery-status visibility, return semantics, docs, and focused ordering/security regression tests.
