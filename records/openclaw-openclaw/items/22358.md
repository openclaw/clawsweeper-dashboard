## Summary

Keep open: current main and v2026.6.11 still expose only adjacent subagent lifecycle/routing hooks, while the requested post-completion/pre-announcement plugin interception point remains missing and needs maintainer API/security design.

## What This Changes

The issue requests a public extension hook after subagent completion and before parent-session announcement delivery so plugins can inspect, persist, enrich, suppress, or react to subagent completion results.

## Best Possible Solution

Keep this open for maintainer API/security design: a typed plugin hook or canonical lifecycle/delivery contract should expose bounded child/run metadata, safe completion output access, delivery-status visibility where appropriate, and clear enrichment/suppression semantics with docs and regression tests.

## Reproduction Assessment

Yes, at source level. Current main’s public hook catalog and subagent announce flow lack a post-completion/pre-announcement hook, while existing adjacent hooks are either void observation or routing-only.

## Solution Assessment

Unclear pending maintainer design. A typed hook is plausible, but the best solution must settle the public plugin contract, payload bounds, delivery mutation semantics, and security review before implementation.
