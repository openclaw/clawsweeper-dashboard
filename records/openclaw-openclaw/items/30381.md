## Summary

Keep open. Current main and the latest release still reject a generic body model after a valid agent header, and the public docs intentionally define the body model as an OpenClaw agent target, so this remains a maintainer API-contract decision rather than cleanup-close material.

## What This Changes

The issue asks the OpenAI-compatible chat completions gateway to ignore the request body model when a valid x-openclaw-agent-id header targets an agent.

## Best Possible Solution

Maintainers should define one shared OpenAI-compatible precedence rule; if header-selected agents should make the body model compatibility metadata, update the shared helper, chat/responses coverage, and public docs together while keeping x-openclaw-model as the backend override surface.

## Reproduction Assessment

Yes, source-level. A valid x-openclaw-agent-id can select the agent, but the handler still passes the original body model into resolveOpenAiCompatModelOverride, which rejects generic provider model ids before dispatch; no live gateway was run in this read-only review.

## Solution Assessment

Unclear. The requested behavior is plausible for OpenAI SDK compatibility, but it changes the documented agent-first model contract and should be decided across all OpenAI-compatible endpoints instead of patched only in chat completions.
