## Summary

Keep open. Current main and the latest release still reject a generic request-body `model` after a valid `x-openclaw-agent-id`, and changing that behavior needs a Gateway API precedence decision across the OpenAI-compatible HTTP surfaces.

## What This Changes

The issue requests that `/v1/chat/completions` ignore the request body `model` and use the selected agent configuration when `x-openclaw-agent-id` resolves to a valid agent.

## Best Possible Solution

Gateway owners should define one shared precedence rule for agent header versus body model, then implement that rule in the shared resolver with docs and focused tests for the chosen endpoint set.
