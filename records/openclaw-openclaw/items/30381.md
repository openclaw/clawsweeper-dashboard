## Summary

Keep open. Current main and the latest release still reject generic request-body `model` values through the documented agent-target validation, and changing that header/model precedence is a public Gateway API decision rather than conservative cleanup.

## What This Changes

The issue requests that `/v1/chat/completions` ignore a generic request-body `model` value and use the configured agent model when `x-openclaw-agent-id` selects a valid agent.

## Best Possible Solution

Define one explicit Gateway precedence contract: either approve a narrow valid-agent-header compatibility exception and document/test it across OpenAI-compatible endpoints, or keep the current agent-target `model` contract and close with the supported `openclaw/default` plus `x-openclaw-model` path.

Unclear until maintainers choose the contract. A narrow header-precedence exception is plausible for SDK compatibility, but current docs/tests intentionally define `model` as an agent target and `x-openclaw-model` as the backend model override.
