## Summary

Keep open. Current `main` and `v2026.6.11` still reject generic request-body `model` values through the documented OpenAI-compatible agent-target validation, and relaxing that when `x-openclaw-agent-id` is valid is a public Gateway API precedence decision rather than conservative cleanup.

## What This Changes

The issue asks `/v1/chat/completions` to ignore the request body `model` and use the targeted agent's configured model when `x-openclaw-agent-id` resolves to a valid agent.

## Best Possible Solution

Define one explicit Gateway precedence contract: either approve a narrow valid-agent-header compatibility exception and document/test it across OpenAI-compatible endpoints, or keep the current agent-target `model` contract and direct integrations to `openclaw/default` plus `x-openclaw-model`.
