## Summary

Keep open. Current main and v2026.6.11 still validate a generic body `model` after a valid `x-openclaw-agent-id`, and changing that behavior would alter the documented agent-first Gateway API contract.

## What This Changes

Allow `/v1/chat/completions` requests with a valid `x-openclaw-agent-id` to tolerate or ignore a generic body `model` and use the selected agent's configured model.

## Best Possible Solution

Gateway owners should define and document one shared precedence rule for agent header versus body model; if header precedence is adopted, update the shared resolver plus Chat Completions, Responses, and embeddings tests/docs together.

Options:

- **Adopt Shared Header Precedence (recommended):** Treat body `model` as compatibility metadata whenever a valid agent header selects the agent, and update shared resolver behavior, docs, and endpoint tests together.
- **Preserve Agent-First Body Model:** Keep requiring `model` to be `openclaw`, `openclaw/default`, or `openclaw/<agentId>` and document SDK integrations around those values plus optional `x-openclaw-model`.
- **Scope Only To Chat Completions:** Allow the requested behavior only on `/v1/chat/completions`, accepting intentional divergence from Responses and embeddings.

## Reproduction Assessment

Yes, source-level. A request with a valid `x-openclaw-agent-id` and generic body model reaches `resolveOpenAiCompatModelOverride`, which rejects non-agent-target model strings before dispatch.

## Solution Assessment

Unclear until maintainers decide the API contract. The maintainable fix is not a one-line chat handler exception; it should encode a shared precedence rule across the OpenAI-compatible HTTP surface.
