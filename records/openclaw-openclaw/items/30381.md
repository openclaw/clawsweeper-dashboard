## Summary

Keep open. Current main and the latest release still reject a generic request-body `model` after a valid `x-openclaw-agent-id`, and the documented agent-first model contract makes this a Gateway API precedence decision rather than cleanup closure.

## What This Changes

The issue asks `/v1/chat/completions` to ignore the request body model and use the targeted agent's configured model when `x-openclaw-agent-id` resolves to a valid agent.

## Best Possible Solution

Define one shared OpenAI-compatible precedence rule for agent header versus body model, then update the shared resolver, docs, and chat/responses/embeddings coverage to match.
