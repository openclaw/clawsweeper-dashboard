## Summary

Keep open. Current main and the latest release still resolve a valid `x-openclaw-agent-id` first, then reject a generic non-agent `model` before dispatch; the docs now define an agent-first model contract, so the remaining question is maintainer API-precedence direction rather than cleanup closure.

## What This Changes

Request that `/v1/chat/completions` ignore the request body `model` when a valid `x-openclaw-agent-id` header selects an agent, so the agent's configured model is used.

## Best Possible Solution

Define one explicit gateway precedence contract in docs and code, then add regression coverage for chat completions and any sibling OpenAI-compatible endpoints included in that contract.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should a valid `x-openclaw-agent-id` on `/v1/chat/completions` suppress validation of non-agent request-body `model` values for OpenAI SDK compatibility, or should the documented agent-first `model` contract keep rejecting them?

Rationale: Both outcomes are plausible: accepting header precedence improves SDK compatibility, while rejecting generic models preserves the current stable Gateway HTTP contract and the `x-openclaw-model` override boundary.

Likely owner: vincentkoc

Owner reason: He authored the current agent-first Gateway HTTP contract and the related endpoint expansion.

Owner confidence: high

Options:

- **Adopt header precedence (recommended):** When the header resolves to a configured agent, ignore a non-agent request `model` for chat completions, document the precedence, and add focused tests.
- **Keep agent-first model contract:** Continue requiring `model` to be `openclaw` or an OpenClaw agent target, and close this as a documented integration constraint.
- **Broaden across compat endpoints:** Apply the same chosen precedence consistently to chat completions, responses, and embeddings if maintainers want one OpenAI-compatible rule.

## Solution Assessment

Unclear until maintainers choose the public precedence rule. If accepted, the maintainable fix is to encode the precedence in the shared OpenAI-compatible request helper with docs and regression tests, not a one-off chat-handler bypass.
