## Summary

Keep open. Current main and the latest release still reject a generic request body `model` after a valid `x-openclaw-agent-id`, while the live issue comments confirm production integration pressure; because the docs define `model` as an OpenClaw agent target, this needs a maintainer API-contract decision rather than cleanup closure.

## What This Changes

The issue asks OpenAI-compatible chat completions to ignore the request body `model` when `x-openclaw-agent-id` selects a valid agent, using the agent's configured model instead.

## Best Possible Solution

Have maintainers define one OpenAI-compatible precedence rule across chat, responses, embeddings, and docs; if valid agent headers should make body `model` compatibility metadata, change the shared helper and coverage together.

## Reproduction Assessment

Yes, source-level. A valid `x-openclaw-agent-id` can select the agent, then the shared OpenAI-compatible model override validator still rejects a generic body `model` before dispatch; no live Gateway was run in this read-only review.

## Solution Assessment

Unclear. The requested behavior is plausible for OpenAI SDK compatibility, but it changes the documented agent-first model contract and should be decided across all OpenAI-compatible endpoints.
