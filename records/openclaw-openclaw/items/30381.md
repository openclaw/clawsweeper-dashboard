## Summary

Keep open. Current main and the latest release still validate the request-body `model` as an OpenClaw agent target even after a valid `x-openclaw-agent-id`, and relaxing that public Gateway precedence rule needs maintainer API direction rather than cleanup closure.

## What This Changes

Request that `/v1/chat/completions` ignore a generic request-body `model` when `x-openclaw-agent-id` selects a valid agent, using the agent's configured model instead.

## Best Possible Solution

Define one Gateway OpenAI-compatible precedence rule for agent header versus body model, then update the shared resolver, docs, and chat/responses/embeddings tests to match.
