## Summary

Keep open. Current main and the latest release still reject a generic body `model` after a valid agent header, while public docs define the body `model` as an OpenClaw agent target, so this remains a maintainer API-contract decision rather than a cleanup close.

## What This Changes

The issue requests that `/v1/chat/completions` ignore the request body `model` when a valid `x-openclaw-agent-id` header selects an agent.

## Best Possible Solution

Define one shared OpenAI-compatible precedence rule; if valid agent headers should make the body model compatibility metadata, update the shared helper, Chat Completions/Responses coverage, and public docs together while keeping `x-openclaw-model` as the backend override surface.
