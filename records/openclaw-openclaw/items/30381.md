## Summary

Keep open. Current main and v2026.6.11 still validate the request body `model` after resolving a valid `x-openclaw-agent-id`, while the docs define `model` as an OpenClaw agent target, so this remains a Gateway API-contract decision rather than cleanup-close material.

## What This Changes

The issue requests that `/v1/chat/completions` ignore a generic request body `model` when `x-openclaw-agent-id` selects a valid agent and use that agent's configured model instead.

## Best Possible Solution

Define the OpenAI-compatible precedence contract, then either document the current requirement clearly or update the shared Gateway helper, chat completions/Responses handlers, and focused tests so valid agent headers consistently bypass body agent-target validation.

## Reproduction Assessment

Yes, source-level. The chat completions handler resolves the header-selected agent and then still validates the body `model` through `resolveOpenAiCompatModelOverride`, which rejects generic model ids.

## Solution Assessment

Unclear until maintainers decide the API contract. Ignoring body `model` when a valid agent header is present would improve OpenAI SDK compatibility, but current docs intentionally define `model` as an OpenClaw agent target and use `x-openclaw-model` for backend overrides.
