## Summary

Keep open. Current main and the latest release still reject a generic body `model` after a valid `x-openclaw-agent-id`, while the docs define the body `model` as an agent target, so this remains a Gateway API-precedence product decision rather than cleanup closure.

## What This Changes

Request to make `/v1/chat/completions` tolerate or ignore a generic request-body `model` when `x-openclaw-agent-id` selects a valid agent.

## Best Possible Solution

Gateway owners should choose one shared precedence rule for agent header versus body model; if header precedence is adopted, implement it in the shared resolver with docs and focused tests for the chosen endpoint set.
