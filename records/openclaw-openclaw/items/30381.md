## Summary

Keep open. Current main and the latest release still validate the request body `model` after a valid agent header, while the public docs define that field as an OpenClaw agent target; this needs maintainer API-precedence direction rather than cleanup closure.

## What This Changes

The issue requests that `/v1/chat/completions` ignore the request body `model` when `x-openclaw-agent-id` targets a configured agent, using that agent's configured model instead.

## Best Possible Solution

Choose one documented gateway contract, then update the shared helper, chat-completions and sibling tests, and public docs so valid agent headers either intentionally bypass generic body-model validation or explicitly continue to reject non-OpenClaw model values.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should a valid `x-openclaw-agent-id` make OpenAI-compatible HTTP requests ignore a generic body `model`, or should the body `model` remain a validated OpenClaw agent-target field even when the header selects an agent?

Rationale: The source fix is narrow, but it changes public model/header precedence for OpenAI-compatible clients and may need to apply consistently across sibling gateway endpoints.

Likely owner: vincentkoc

Owner reason: `vincentkoc` is the strongest available history signal for the OpenAI-compatible endpoint contract and latest shipped release containing this behavior.

Owner confidence: high

Options:

- **Agent header wins (recommended):** Treat the body `model` as SDK compatibility filler when a valid agent header is present, and run the selected agent's configured model unless `x-openclaw-model` is explicitly authorized.
- **Keep current validation:** Continue requiring the body `model` to be omitted or use an OpenClaw agent target even when `x-openclaw-agent-id` is present, and document that contract more explicitly.
- **Add explicit compatibility mode:** Preserve current default behavior and add a documented opt-in compatibility surface for SDKs that must send generic OpenAI model ids with agent headers.

## Reproduction Assessment

Yes, source-reproducible. With a configured agent header and body `model: "gpt-4"`, the source resolves the agent from the header and then returns `Invalid model` because the body model is not an OpenClaw agent target.

## Solution Assessment

Unclear until maintainer direction is set. A helper-level change is plausible, but the best solution must first decide the public model/header precedence contract and apply it consistently to sibling OpenAI-compatible paths.
