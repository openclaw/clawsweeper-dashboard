## Summary

Keep open. Current main and the latest release still reject a non-OpenClaw request body `model` on `/v1/chat/completions` even after a valid `x-openclaw-agent-id` selects the agent, and changing that behavior is a public API-precedence decision rather than conservative cleanup.

## What This Changes

Requests that `/v1/chat/completions` ignore or tolerate the request body `model` when a valid `x-openclaw-agent-id` selects the target agent.

## Best Possible Solution

Gateway owners should choose the model/header precedence contract, then update the shared resolver, docs, and focused tests consistently for Chat Completions and any sibling OpenAI-compatible endpoints they want covered.
