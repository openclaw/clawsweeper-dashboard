## Summary

Keep open. Current main and the latest release still reject a generic request-body `model` after a valid `x-openclaw-agent-id`, while the docs define the body `model` as an agent target, so this needs a Gateway API precedence decision rather than conservative cleanup closure.

## What This Changes

The issue requests changing OpenAI-compatible chat completions so a valid `x-openclaw-agent-id` header makes the gateway ignore the request body `model` and use the selected agent's configured model.

## Best Possible Solution

Gateway owners should define one shared precedence rule for agent header versus body model, then implement that rule in the shared resolver with docs and focused tests for the chosen endpoint set.
