## Summary

Keep open. Current main and the latest release still reject generic request-body model values after resolving a valid agent-id header, and changing that precedence would alter the documented Gateway OpenAI-compatible model contract.

## What This Changes

The issue asks the OpenAI-compatible chat completions handler to ignore a generic request-body model when a valid x-openclaw-agent-id header targets a configured agent.

## Best Possible Solution

Make an explicit Gateway API decision, then either keep the current agent-first contract with clearer SDK guidance or implement header precedence in the shared model-resolution path with matching docs and regression coverage.
