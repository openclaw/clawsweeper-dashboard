## Summary

Keep open. Current main and the latest release still validate the request-body model after resolving a valid agent header, while the public docs define an agent-first model contract; this needs a maintainer API-precedence decision rather than cleanup closure.

## What This Changes

Issue asks the OpenAI-compatible chat completions gateway to ignore the request-body model when a valid agent header is present and use the selected agent configuration instead.

## Best Possible Solution

Gateway owners should choose one model/header precedence rule, then update the shared resolver, public docs, and focused endpoint tests consistently for Chat Completions and any sibling OpenAI-compatible endpoints they want covered.
