## Summary

Keep open. Current main and v2026.6.11 still validate the original OpenAI body `model` after resolving `x-openclaw-agent-id`, while the public docs intentionally define `model` as an OpenClaw agent target, so this remains a Gateway API-contract decision rather than cleanup-close material.

## What This Changes

The issue requests that `/v1/chat/completions` ignore the request body `model` when a valid `x-openclaw-agent-id` selects the agent.

## Best Possible Solution

Have maintainers define one shared OpenAI-compatible precedence rule; if header-selected agents should treat body `model` as compatibility metadata, update the shared helper, chat/responses/embeddings coverage, and public docs together.

## Reproduction Assessment

Yes, source-level. A valid `x-openclaw-agent-id` can select the agent, then `resolveOpenAiCompatModelOverride` still rejects a generic body `model` before dispatch; no live gateway was run in this read-only review.

## Solution Assessment

Unclear. The requested behavior is plausible for OpenAI SDK compatibility, but it changes the documented agent-first model contract and should be decided across the shared OpenAI-compatible endpoints.
