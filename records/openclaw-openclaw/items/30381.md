## Summary

Keep open. Current main and the latest release still reject a generic body model after a valid agent header, while the docs define the body model as an OpenClaw agent selector, so this remains a Gateway API contract decision rather than cleanup-close material.

## What This Changes

Request to make `/v1/chat/completions` ignore the request body `model` and use the targeted agent's configured model when `x-openclaw-agent-id` is present.

## Best Possible Solution

Have maintainers define one shared OpenAI-compatible agent/model precedence rule; if header-selected agents make body `model` compatibility metadata, update the shared helper, endpoint tests, and public docs together.

## Reproduction Assessment

Yes, source-level. A valid `x-openclaw-agent-id` can select the agent, then `resolveOpenAiCompatModelOverride` still rejects a generic body `model` before dispatch.

## Solution Assessment

Unclear. Ignoring the body model when an agent header is present is plausible for SDK compatibility, but the best fix needs a shared contract across OpenAI-compatible endpoints.
