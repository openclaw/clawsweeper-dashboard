## Summary

Keep open. Current main and the latest release still reject generic request-body model values after resolving a valid agent header, and the exact linked test PR was closed unmerged, so this remains a live Gateway API precedence decision.

## What This Changes

Request that `/v1/chat/completions` ignore an unrecognized request-body `model` when a valid `x-openclaw-agent-id` header targets an agent, using the agent's configured model instead.

## Best Possible Solution

Define one explicit Gateway precedence contract: either add a documented and tested valid-agent-header compatibility exception across OpenAI-compatible endpoints, or keep the current agent-target `model` contract and close with the supported `openclaw/default` plus `x-openclaw-model` path.

## Reproduction Assessment

Yes, for the current behavior at source level. A generic body model cannot resolve as an OpenClaw agent target, so `resolveOpenAiCompatModelOverride` returns HTTP 400 even after `resolveGatewayRequestContext` can select the header agent.

## Solution Assessment

Unclear until maintainers choose the contract. A narrow valid-agent-header exception is plausible for SDK compatibility, but current docs and tests intentionally define `model` as an agent target and `x-openclaw-model` as the backend override.
