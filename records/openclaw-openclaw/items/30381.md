## Summary

Keep open. Current main and v2026.6.11 still reject a generic body `model` after a valid agent header, and the requested behavior changes the documented OpenAI-compatible model/header precedence contract rather than being conservative cleanup.

## What This Changes

Allow `/v1/chat/completions` requests with a valid `x-openclaw-agent-id` header to ignore or tolerate the body `model` and use the selected agent's configured model.

## Best Possible Solution

Have Gateway owners choose the shared model/header precedence rule, then update the shared resolver, Chat Completions and Responses tests, and public Gateway docs consistently.
