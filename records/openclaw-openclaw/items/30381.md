## Summary

Keep open. Current main and the latest release still reject a generic body model after a valid agent header, and changing that behavior would alter the documented OpenAI-compatible model/header precedence contract.

## What This Changes

The issue requests that OpenAI-compatible chat completions ignore the request body model when a valid x-openclaw-agent-id header targets a configured agent.

## Best Possible Solution

Gateway owners should choose one shared OpenAI-compatible model/header precedence rule, then update the shared resolver, Chat/Responses/Embeddings tests as applicable, and public Gateway docs consistently.

Options:

- **Decide shared endpoint semantics first (recommended):** Keep this open until maintainers choose one precedence rule for the OpenAI-compatible endpoint family, then implement it once.
- **Adopt header precedence:** Treat body model as client compatibility metadata when a valid agent header selects the agent, with docs and tests for every endpoint maintainers want covered.
- **Preserve agent-first model contract:** Keep requiring model to be openclaw, openclaw/default, or an agent-target model and document SDK integrations to send that value plus optional x-openclaw-model.

## Reproduction Assessment

Yes, source-level. A /v1/chat/completions request with a valid x-openclaw-agent-id and body model like gpt-4 resolves the header agent, then rejects the non-OpenClaw body model before dispatch.

## Solution Assessment

Unclear until maintainers decide the public API contract. The mechanical change is small, but the maintainable fix needs an explicit precedence rule and sibling-endpoint parity decision.
