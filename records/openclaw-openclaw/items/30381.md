## Summary

Keep open. Current main and the latest release still reject a generic request body `model` after a valid `x-openclaw-agent-id`, and changing that behavior needs a Gateway API precedence decision rather than cleanup closure.

## What This Changes

The issue asks `/v1/chat/completions` to ignore the request body `model` and use the selected agent configuration when `x-openclaw-agent-id` is present.

## Best Possible Solution

Have Gateway owners define the model/header precedence contract, then update the shared resolver, docs, and focused tests consistently for Chat Completions and any sibling OpenAI-compatible endpoints they choose to cover.
