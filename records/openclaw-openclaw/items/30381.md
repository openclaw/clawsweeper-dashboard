## Summary

Keep open. Current main and v2026.6.11 still reject a generic body `model` after a valid `x-openclaw-agent-id`, and the documented agent-first model contract makes the requested behavior a maintainer API-precedence decision rather than cleanup closure.

## What This Changes

The issue requests that `/v1/chat/completions` ignore or tolerate the request body `model` when a valid `x-openclaw-agent-id` selects the target agent.

## Best Possible Solution

Have Gateway owners explicitly define the model/header precedence contract, then implement it in the shared resolver, docs, and focused tests across Chat Completions and any sibling endpoints selected.
