## Summary

Keep open. Current main and the latest release still enforce OpenClaw agent-target `model` validation after `x-openclaw-agent-id` selection, and changing that is a Gateway OpenAI-compatible API contract decision rather than cleanup-close material.

## What This Changes

Requests that `/v1/chat/completions` ignore the request body `model` and use the selected agent's configured model when a valid `x-openclaw-agent-id` header is present.

## Best Possible Solution

Maintainers should choose one shared precedence rule for OpenAI-compatible endpoints, then update the shared helper, chat/responses/embeddings coverage, and public docs together.

## Reproduction Assessment

Yes, source-level. A valid `x-openclaw-agent-id` can select the agent, then `resolveOpenAiCompatModelOverride` still rejects a generic body `model` before dispatch; no live gateway was run in this read-only review.

## Solution Assessment

Unclear. The requested behavior is plausible for OpenAI SDK compatibility, but current docs and tests deliberately make the body `model` an agent selector and sibling endpoints share that helper.
