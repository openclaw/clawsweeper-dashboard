## Summary

Keep open. Current main and the latest release still validate the original request body `model` after a valid `x-openclaw-agent-id`, so the requested OpenAI SDK compatibility behavior is not implemented and needs a maintainer-owned API precedence decision.

## What This Changes

The issue requests that `/v1/chat/completions` ignore a generic request body `model` when a valid `x-openclaw-agent-id` header selects the target agent.

## Best Possible Solution

Set one shared OpenAI-compatible precedence contract: either a valid agent header wins and suppresses body-model target validation, or the docs should explicitly require an OpenClaw agent-target model even with the header.

Question: Should a valid `x-openclaw-agent-id` header make OpenAI-compatible HTTP handlers ignore a generic body `model` for agent-target validation?

Rationale: Both choices are defensible compatibility contracts, and changing the current validation semantics affects public OpenAI-compatible clients.

Likely owner: vincentkoc

Owner reason: vincentkoc authored the agent-first OpenAI-compatible contract and endpoint expansion now governing this behavior.

Owner confidence: high

Options:

- **Header wins (recommended):** Treat a valid agent header as the selected agent, ignore the body `model` for agent-target validation, and keep `x-openclaw-model` as the explicit backend override.
- **Body model remains required:** Keep current validation and update docs/examples to say SDK callers must send `openclaw`, `openclaw/default`, or `openclaw/<agentId>` even when using the header.
- **Defer to a broader API design:** Pause implementation until maintainers decide the same precedence for chat completions, Responses, and embeddings together.

## Solution Assessment

Unclear until maintainers choose the API precedence contract. The narrowest maintainable implementation would update the shared OpenAI-compatible helper and parity tests rather than adding a one-off chat completions branch.
