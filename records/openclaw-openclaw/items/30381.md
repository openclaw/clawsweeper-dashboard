## Summary

Keep open. Current main and the latest release still reject a generic OpenAI body model after a valid agent header, and changing that behavior is a public OpenAI-compatible API precedence decision rather than a cleanup close.

## What This Changes

The issue requests that the chat completions endpoint ignore the request body model and use the targeted agent's configured model when x-openclaw-agent-id names a valid agent.

## Best Possible Solution

Have Gateway owners choose the model/header precedence contract, then update the shared resolver, public docs, and focused tests consistently for Chat Completions and any sibling OpenAI-compatible endpoints they want covered.
