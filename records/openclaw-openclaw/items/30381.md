## Summary

Keep open. Current main and the latest release still validate a generic body model after a valid agent header, but the public OpenAI-compatible docs define the body model as an OpenClaw agent target, so this needs a maintainer API-contract decision rather than cleanup closure.

## What This Changes

The issue requests that `/v1/chat/completions` ignore a generic OpenAI request body `model` when a valid `x-openclaw-agent-id` header selects the target agent.

## Best Possible Solution

Define one shared OpenAI-compatible precedence rule; if header-selected agents make the body model compatibility metadata, update the shared helper, chat/responses tests, and public docs while keeping `x-openclaw-model` as the backend override surface.

## Reproduction Assessment

Yes, source-level. Current main resolves the valid agent header first, but then validates the original body model through `resolveOpenAiCompatModelOverride`, which rejects generic provider model ids before dispatch; no live gateway was run in this read-only review.

## Solution Assessment

Unclear. The requested behavior is plausible for OpenAI SDK compatibility, but it changes the documented agent-first model contract and should be decided across the shared OpenAI-compatible helper and sibling endpoints rather than patched only in chat completions.
