## Summary

Keep open. Current main and the latest release still enforce the documented agent-first body model contract even after a valid agent header; changing that would alter public OpenAI-compatible API semantics and needs maintainer product direction, not cleanup closure.

## What This Changes

The issue requests that Chat Completions ignore a generic request body model when a valid `x-openclaw-agent-id` header selects an agent.

## Best Possible Solution

Have Gateway owners choose a shared model/header precedence contract, then update the shared resolver, docs, and focused tests across Chat Completions and the sibling OpenAI-compatible endpoints they want covered.

Yes, source-level. A Chat Completions request with a valid `x-openclaw-agent-id` and a generic body model resolves the agent first, then passes the original model to `resolveOpenAiCompatModelOverride`, which rejects non-OpenClaw model strings before dispatch.
