## Summary

Keep open. Current main and the latest release still reject a generic request-body `model` after a valid `x-openclaw-agent-id`, and changing that precedence is a Gateway OpenAI-compatible API decision rather than conservative cleanup closure.

## What This Changes

Requests that `/v1/chat/completions` ignore a generic OpenAI request-body `model` when a valid `x-openclaw-agent-id` selects the target agent.

## Best Possible Solution

Define one shared Gateway OpenAI-compatible precedence rule for agent header versus body model, then update the shared resolver, docs, and chat/responses/embeddings tests to match.
