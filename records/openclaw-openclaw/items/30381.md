## Summary

Keep open. Current main and the latest release still reject a generic body model after resolving a valid agent header, but the documented OpenAI-compatible contract intentionally treats the body model as an OpenClaw agent target, so this needs a maintainer API-contract decision rather than cleanup closure.

## What This Changes

The issue requests that `/v1/chat/completions` ignore a generic request body `model` when `x-openclaw-agent-id` targets a valid agent, using that agent's configured model instead.

## Best Possible Solution

Maintainers should choose one shared OpenAI-compatible precedence rule; if header-selected agents should make the body model compatibility metadata, update the shared helper, chat/responses coverage, and public docs together while keeping `x-openclaw-model` as the backend override surface.

## Reproduction Assessment

Yes, source-level. A valid `x-openclaw-agent-id` can select the agent, but the handler still passes the original body model into `resolveOpenAiCompatModelOverride`, which rejects generic provider model ids before dispatch; I did not run a live gateway in this read-only review.

## Solution Assessment

Unclear. The requested behavior is plausible for OpenAI SDK compatibility, but a chat-only fix is too narrow because the current docs and `/v1/responses` path share the same agent-first body-model contract.
