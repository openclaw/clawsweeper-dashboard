## Summary

Keep open. Current main and v2026.6.11 still reject a non-OpenClaw body `model` after a valid agent header, and the documented agent-first contract makes this a maintainer API-precedence decision rather than cleanup closure.

## What This Changes

The issue requests that `/v1/chat/completions` ignore the request body `model` and use the selected agent configuration when `x-openclaw-agent-id` resolves to a valid agent.

## Best Possible Solution

Have Gateway owners choose the model/header precedence contract, then update the shared resolver, docs, and focused tests consistently for Chat Completions and any sibling OpenAI-compatible endpoints they want covered.
