## Summary

Keep open. Current main and the latest release still reject generic request-body `model` values even when a valid agent header selects the target agent, and relaxing that behavior is a documented Gateway API precedence decision rather than conservative cleanup.

## What This Changes

Request `/v1/chat/completions` to ignore the request-body `model` when `x-openclaw-agent-id` selects a valid agent and use that agent's configured model.

## Best Possible Solution

Maintainers should choose and document one Gateway precedence contract; if approved, implement a narrow valid-agent-header exception with regression coverage, otherwise keep the documented `openclaw/default` plus `x-openclaw-model` path.

## Solution Assessment

Unclear until maintainers choose the contract. A narrow valid-header precedence exception is plausible for SDK compatibility, but current docs and tests intentionally define `model` as an agent target and `x-openclaw-model` as the backend model override.
