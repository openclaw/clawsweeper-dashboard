## Summary

Keep open. Current main and the latest release still reject a generic body `model` after a valid agent header, while docs currently define `model` as an OpenClaw agent target, so this needs a maintainer API-contract decision rather than cleanup closure.

## What This Changes

Request that `/v1/chat/completions` ignore the body `model` value and use the selected agent's configured model when `x-openclaw-agent-id` resolves to a valid agent.

## Best Possible Solution

Define one shared OpenAI-compatible precedence rule; if valid agent headers should make the body model compatibility metadata, update the shared helper, Chat Completions/Responses coverage, and public docs together while keeping `x-openclaw-model` as the backend override surface.

Unclear. The requested behavior is plausible for OpenAI SDK compatibility, but it changes the documented agent-first model contract and should be decided across shared OpenAI-compatible endpoints rather than patched only in Chat Completions.
