## Summary

Keep open. Current main and v2026.6.11 still reject generic request-body models after a valid `x-openclaw-agent-id`, and changing that is a public Gateway model/header precedence decision rather than safe cleanup.

## What This Changes

The issue asks the Gateway Chat Completions endpoint to ignore the request-body `model` when a valid `x-openclaw-agent-id` selects an agent.

## Best Possible Solution

Gateway owners should define a consistent model/header precedence contract, then update the shared resolver, chosen sibling endpoints, docs, and focused tests together.

- **Preserve agent-first model contract:** Keep requiring body `model` to be `openclaw`, `openclaw/default`, or `openclaw/<agentId>`, and document SDK clients to send that value with optional `x-openclaw-model`.
- **Hold for broader Gateway API review:** Leave this open until maintainers decide one shared OpenAI-compatible precedence rule across Chat Completions, Responses, and embeddings.
