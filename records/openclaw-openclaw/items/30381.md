## Summary

Keep open. Current main and the latest release still reject a generic body `model` after a valid agent header, and accepting it would change the public OpenAI-compatible model/header precedence contract, so this needs maintainer product direction rather than cleanup closure.

## What This Changes

The request is to let `/v1/chat/completions` ignore a generic request `model` and use the configured agent model when a valid `x-openclaw-agent-id` header is present.

## Best Possible Solution

Choose one documented gateway contract for model/header precedence, then update the shared helper, chat/responses behavior, focused tests, and public docs consistently.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should a valid `x-openclaw-agent-id` make OpenAI-compatible HTTP requests ignore a generic body `model`, or should the body `model` remain a validated OpenClaw agent-target field even when the header selects an agent?

Rationale: The source path is narrow, but the behavior is a public API precedence contract that affects model routing and sibling OpenAI-compatible endpoints.

Likely owner: vincentkoc

Owner reason: Vincent introduced both the OpenAI-compatible endpoint expansion and the current agent-first model contract.

Owner confidence: high

Options:

- **Agent header wins (recommended):** Treat the body `model` as SDK compatibility filler when a valid agent header is present, and run the selected agent's configured model unless `x-openclaw-model` is explicitly authorized.
- **Keep current validation:** Continue requiring the body `model` to be omitted or use an OpenClaw agent target even when `x-openclaw-agent-id` is present, and document that contract more explicitly.
- **Add explicit compatibility mode:** Preserve current default behavior and add a documented opt-in compatibility surface for SDKs that must send generic OpenAI model ids with agent headers.

## Reproduction Assessment

Yes, source-reproducible. With a valid agent header and body `model: "gpt-4"`, current source selects the agent from the header and then rejects the body model because it is not an OpenClaw agent target.

## Solution Assessment

Unclear until maintainer direction is set. A helper-level change is plausible, but the best fix must first decide the public precedence contract and apply it consistently to sibling OpenAI-compatible paths.
