## Summary

Keep open. Current main still creates the default diagnostics-otel model-call span without an explicit span kind, and tool-execution spans also omit kind, so the central observability problem remains; no merged PR or canonical open item owns this exact span-kind fix.

## What This Changes

The issue asks OpenClaw to classify external model-call and tool-execution telemetry spans with OpenTelemetry client-style kinds instead of leaving them as internal/default spans.

## Best Possible Solution

Set explicit span-kind mapping in diagnostics-otel while preserving existing span names and the GenAI opt-in naming behavior, then update tests and docs so model-call and externally dispatched tool spans are no longer silently default-internal.
