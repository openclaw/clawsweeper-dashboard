## Summary

Keep this PR open, but it is not ready to merge: the proposed detached-error handler bypasses the Gateway-owned cron state path and writes through the legacy cron-store helpers, while current cron state is documented as shared SQLite runtime state. That can leave the active scheduler and the persisted record out of sync; the mocked regression test does not exercise the production owner boundary. Real after-fix behavior proof is also still missing.

## What This Changes

This PR attempts to mark the cron job that initiated detached media generation as failed when that later background generation throws, with regression coverage for the propagation path.

## System Context

Detached image, music, and video generation is recorded as a background task after an agent turn returns. Cron is the Gateway scheduler that owns job state and run history, so a later media failure must update the scheduler through its canonical state owner for health checks and retry logic to observe it.

## Best Possible Solution

Expose or use a narrow Gateway-owned cron outcome update that accepts the originating run identity already carried by the detached task, records the late failure in canonical cron state/history without replacing unrelated job data, and prove the result with a real detached media failure plus focused regression coverage.
