## Summary

Keep open: the new late-error helper still reads and rewrites cron storage directly instead of using the cron subsystem’s serialized state owner, so it can race scheduler or job-edit updates and overwrite newer cron data. The PR also has no after-fix real-behavior artifact showing that a detached provider failure changes the initiating cron run to failed.

## What This Changes

This PR makes a detached media-generation error attempt to mark the cron run that initiated it as failed, with regression coverage for the propagation path.

## System Context

A cron run can schedule media generation that completes after the initiating agent turn ends. Cron state then feeds job history, health checks, and heartbeat auditing, so late errors need to reach the cron subsystem through its canonical state-update path.
