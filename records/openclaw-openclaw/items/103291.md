## Label Justifications

- `P2`: The bug blocks Google Veo generation for commonly configured provider-qualified model IDs, but its blast radius is limited to one media provider path.
- `impact:auth-provider`: Incorrect provider/model normalization surfaces as an invalid API-key or model-path response.

## Summary

This is a valid remaining Google provider bug, not the already-fixed endpoint issue: current main includes the shipped `predictLongRunning` fallback but still passes provider-qualified model IDs unchanged into the SDK. The linked fix pull request remains open, so this issue should stay open until that candidate is reviewed and merged or rejected.

## What This Changes

Normalize Google Veo model identifiers so provider-qualified, resource-qualified, and bare forms consistently reach the existing video-generation paths.

## Best Possible Solution

Keep the existing SDK-first and text-only REST fallback design, normalize the Veo model once at the Google plugin boundary for both paths, and require regression coverage plus a redacted live run using at least one provider-qualified model ID.
