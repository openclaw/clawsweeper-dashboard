## Summary

Keep open: the linked gateway/channel startup bug still appears valid, but this PR is not safe to merge because it starts channels before the loaded channel registry is pinned and then suppresses the later real channel-start path.

## What This Changes

The PR moves `startChannels()` to the top of `startGatewayPostAttachRuntime` and passes an await-only wrapper into `startGatewaySidecars` to overlap channel startup with runtime plugin loading.

## Best Possible Solution

Rework the startup boundary so channel plugins are loaded and pinned before channel startup begins, while ACPX-dependent runtime work continues in the background with focused lifecycle tests and live channel proof.

## Reproduction Assessment

Yes, at source level. The PR calls `startChannels()` before the runtime plugin load that pins the loaded channel registry, and `startChannels()` enumerates that registry.

## Solution Assessment

No. The requested dependency-driven startup direction is right, but this implementation moves channel startup before the registry is guaranteed to contain loaded channel plugins.
