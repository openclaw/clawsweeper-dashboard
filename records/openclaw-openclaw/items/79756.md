## Summary

Keep open: the goal is valid, but this PR is not merge-ready because it starts channels before the loaded channel registry is pinned, so configured channels can be skipped and the later sidecar path only awaits that no-op promise.

## What This Changes

The PR moves gateway channel startup into an early promise before plugin runtime post-bind and makes later sidecar startup await that promise.

## Best Possible Solution

Rework or replace this branch with a dependency-aware startup seam that pins or loads the channel registry before channel startup, keeps ACPX-dependent work on its own readiness path, and proves a real configured channel starts while post-bind work continues.

## Reproduction Assessment

Yes, at source level. The PR calls `startChannels()` before `loadStartupPluginsIfNeeded()`, while channel startup enumerates `listChannelPlugins()` from the loaded registry pinned during runtime plugin loading.

## Solution Assessment

No. The direction is valid, but moving the call earlier without a registry-ready or split-loading seam is not the best fix and can turn channel startup into a no-op.
