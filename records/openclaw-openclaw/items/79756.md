## Summary

Keep open for maintainer design/rework: the linked startup bug still appears valid, but this patch can start channels before the loaded channel registry is pinned, turning channel startup into a no-op and suppressing the later real sidecar start.

## What This Changes

The branch starts channels at the top of `startGatewayPostAttachRuntime` before `plugins.runtime-post-bind` and passes sidecars an awaiter for that early promise.

## Best Possible Solution

Replace this reorder with a dependency-aware gateway startup seam that loads and pins channel plugins before channel start while ACPX-dependent runtime work continues independently, then prove a real channel connects before ACPX completion.

## Reproduction Assessment

Yes, at source level. The PR calls `startChannels()` before the runtime plugin load that pins the loaded channel registry, and `startChannels()` enumerates that registry before the later sidecar phase is replaced with an awaiter.

## Solution Assessment

No. The dependency-driven startup direction is right, but this specific reorder is not the best fix because it does not guarantee that the channel registry is populated before channel enumeration.
