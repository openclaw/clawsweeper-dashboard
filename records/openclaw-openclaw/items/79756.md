## Summary

Keep open: the linked gateway startup bug remains real, but this PR is not merge-ready because it starts channels before runtime plugin loading pins the channel registry, so the early channel pass can enumerate zero configured channels and the later sidecar path skips the real start.

## What This Changes

The PR moves gateway channel startup into an early promise before `plugins.runtime-post-bind` and makes later sidecar startup await that promise.

## Best Possible Solution

Rework or replace this branch with a dependency-aware startup path that establishes loaded channel registry state before `startChannels()`, keeps ACPX-dependent work separate, and proves a real configured channel starts while ACPX/post-bind work continues.
