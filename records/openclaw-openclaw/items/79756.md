## Label Justifications

- `P1`: The PR targets an urgent gateway startup/channel availability bug and the current patch can break channel startup if merged.
- `merge-risk: 🚨 message-delivery`: Configured channel plugins can be skipped at startup, which can suppress Discord or Telegram message handling after gateway boot.
- `merge-risk: 🚨 availability`: The gateway can report sidecars ready while channel sidecars never actually started, creating a startup availability regression.

## Summary

Keep open, but this branch is not merge-ready: it starts channels before the loaded channel registry is pinned, so configured channels can enumerate as empty and the later real channel-start path is replaced by an await-only wrapper.

## What This Changes

The PR starts channel sidecars at the beginning of `startGatewayPostAttachRuntime` and passes a wrapper into `startGatewaySidecars` to await that early start.

## Best Possible Solution

Rework the fix so loaded channel registry state is pinned before channel startup, then prove a configured channel starts before ACPX runtime-post-bind completes while ACPX-dependent work stays on its readiness path.

## Reproduction Assessment

Yes, at source level. The branch calls `startChannels()` before runtime plugin loading pins the channel registry, and `startChannels()` enumerates `listChannelPlugins()` from that registry.

## Solution Assessment

No. The direction is valid, but this implementation is not the best fix because it moves channel start ahead of the registry dependency instead of making registry readiness an explicit earlier phase.
