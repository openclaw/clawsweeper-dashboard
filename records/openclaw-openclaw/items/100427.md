## Label Justifications

- `P1`: The report describes a real confidentiality policy failing open on model routing, with a narrow but security-relevant provider/model hook gap.
- `impact:security`: The affected behavior can let a policy plugin miss that a confidential turn is about to leave the intended trust boundary.
- `impact:auth-provider`: The missing hook metadata is provider/model identity used for routing and model-choice enforcement.

## Summary

Keep open: current main already carries provider/model identity in the public hook context and embedded `before_agent_run` path, and `model_call_ended` has served provider/model metadata, but the CLI-backed `before_agent_run` path still drops `modelProviderId` and `modelId` before passing context to policy hooks.

## What This Changes

The issue asks for policy plugins to receive resolved provider/model identity at a blocking-capable hook so per-turn model-routing policy can fail closed.

## Best Possible Solution

Populate the existing `PluginHookAgentContext` model identity fields consistently for every `before_agent_run` path, document that as the pre-submission policy surface, and avoid adding a parallel raw pre-model-call hook unless maintainers explicitly choose a new SDK contract.

## Repair Work Prompt

Fix the blocking policy hook model-identity gap from https://github.com/openclaw/openclaw/issues/100427. Keep the solution narrow: do not add a new public hook or config option. Ensure every `before_agent_run` path passes the existing `PluginHookAgentContext.modelProviderId` and `modelId` fields with the resolved serving provider/model before the model reads the prompt. Current embedded runner already does this in `src/agents/embedded-agent-runner/run/attempt.ts`; the CLI-backed path in `src/agents/cli-runner.ts` builds `hookContext` without `modelProviderId: params.provider` and `modelId: context.modelId` before `runBeforeAgentRun`. Add focused regression coverage for CLI `before_agent_run` context, consider extending existing channel identity tests, and update `docs/plugins/hooks.md` to state that policy plugins should read `ctx.modelProviderId` / `ctx.modelId` for pre-submission routing decisions while `model_call_started` / `model_call_ended` remain post-hoc telemetry. Confirm `model_call_ended` behavior stays unchanged. Do not implement the longer-term provider hook pair unless maintainers separately approve that SDK surface.
