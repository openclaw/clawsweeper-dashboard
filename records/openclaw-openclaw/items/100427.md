## Label Justifications

- `P1`: A user reports a real confidentiality policy failed open because blocking plugin hooks lack enforceable provider/model identity.
- `impact:security`: The report concerns confidential prompts being served by an external provider when a plugin could not enforce the intended boundary.
- `impact:auth-provider`: The missing signal is provider/model identity at model routing and plugin hook boundaries.

## Summary

This issue remains necessary: current main confirms post-hoc model-call telemetry carries provider/model identity, but no documented blocking hook consistently exposes the resolved or served provider/model identity needed for pre-dispatch policy enforcement.

## What This Changes

Request resolved or served provider/model identity on a blocking-capable plugin hook and longer-term read-only provider hook exposure for serving attribution.

## Best Possible Solution

Add a documented read-only resolved/served provider and model identity to a blocking hook across embedded and CLI paths, with fallback semantics and tests; keep raw provider hook exposure separate unless maintainers approve that wider API.

Options:

- **Extend before_agent_run (recommended):** Add read-only provider/model identity to before_agent_run event or documented context consistently across CLI and embedded paths, with clear fallback semantics.
- **Add pre-dispatch hook:** Create a new blocking hook after model resolution and before provider dispatch so policy plugins can enforce against the selected serving candidate.
- **Document current workaround:** Keep enforcement based on configured agent-chain eligibility and document model_call hooks as observe-only audit signals, leaving per-turn served-model policy unsupported.

## Reproduction Assessment

Yes, at source level: the typed hook list omits the provider hook pair, before_model_resolve lacks model identity, before_agent_run lacks provider/model in the event, and CLI context does not supply modelProviderId/modelId. I did not run a live confidential-routing plugin repro.

## Solution Assessment

Unclear until maintainers choose the API contract. The narrowest maintainable direction is a consistent read-only resolved or served provider/model field on a blocking hook, rather than exposing raw provider request/response hooks by default.
