- `impact:security`: The report describes confidential turns being served outside the intended boundary because a policy plugin lacked pre-call model identity.

## Summary

Keep open. Current main still does not provide a consistent blocking-hook model identity contract across runner paths: embedded runs pass `modelProviderId`/`modelId` through hook context, but CLI-backed runs omit those fields, and the broader served-model/proxy attribution question remains open.

## What This Changes

The issue requests resolved or served provider/model identity on a blocking-capable plugin hook so policy plugins can enforce confidentiality before model submission.

## Best Possible Solution

Define one additive model identity contract for blocking hooks, apply it consistently across embedded, CLI, and Codex-style runner paths, document it in the plugin hook guide, and keep proxy/actual-upstream attribution aligned with the resolved-backend metadata work.

## Reproduction Assessment

Yes, from source inspection: the CLI runner builds `hookContext` without `modelProviderId` or `modelId` before calling `runBeforeAgentRun`, while the embedded runner includes those fields. I did not run a live plugin, so this is source-reproducible rather than runtime-reproduced.

## Solution Assessment

Unclear until maintainers choose the API shape. The narrowest repair appears to be documenting and consistently populating the existing hook context fields, but a new post-resolve hook would be a larger product/security decision.
