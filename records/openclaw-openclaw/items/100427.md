## Label Justifications

- `P1`: A reported confidentiality-routing guard can fail open for real users because a blocking plugin path lacks reliable served-model identity across runners.
- `impact:security`: The issue is about enforcing confidentiality boundaries before a prompt can be sent to an out-of-boundary model provider.
- `impact:auth-provider`: The missing data is resolved provider/model routing identity, which affects provider selection and model-policy enforcement.

## Summary

Keep open: current main confirms the issue is only partially covered. `model_call_ended` carries provider/model for audit and the embedded runner passes model identity in hook context, but the CLI `before_agent_run` path still builds context without model identity and the provider request/response hook pair is still not a registerable typed plugin hook.

## What This Changes

The issue asks OpenClaw to expose resolved provider/model identity to blocking-capable policy plugins and to clarify served-model audit metadata.

## Best Possible Solution

Define one supported pre-submission policy contract that exposes resolved provider/model consistently across CLI and embedded runs, document it for plugin authors, and handle raw provider request/response hooks as a separate explicit SDK design decision.

## Solution Assessment

Unclear until maintainers choose the public API shape. The narrowest maintainable fix appears to be filling and documenting the existing hook context consistently before considering a new post-resolve hook or raw provider hook pair.
