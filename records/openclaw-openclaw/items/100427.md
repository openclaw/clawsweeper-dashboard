## Label Justifications

- `P0`: The report describes a confidentiality policy failing open and sending confidential-marked content to an external model provider before a plugin could block it.
- `impact:security`: The missing hook visibility affects a security boundary for sensitive prompt routing and plugin-enforced confidentiality policy.
- `impact:auth-provider`: The affected decision depends on resolved provider/model routing, which is part of provider/model choice and auth-provider behavior.

## Summary

Keep open. Current main and v2026.6.11 still have the exact API gap: `before_agent_run` can block but does not expose resolved provider/model, while `model_call_started` and `model_call_ended` expose provider/model only as observe-only telemetry after the call path has begun.

## What This Changes

The issue asks OpenClaw to expose resolved provider/model identity to a blocking-capable plugin hook, confirm model-call attribution, and consider provider hook exposure for plugin authors.

## Best Possible Solution

Add a narrow, documented SDK contract that exposes read-only resolved provider/model identity to a pre-submission blocking hook, with focused tests for both embedded and CLI paths and without exposing raw provider payloads by default.

Options:

- **Add identity to existing gate (recommended):** Expose read-only resolved provider/model on `before_agent_run` or its context so existing block semantics can enforce per-turn model policy with the smallest new surface.
- **Add a post-resolve gate:** Create a new blocking hook after model resolution and before provider submission, which is cleaner phase separation but adds another lifecycle hook contract.
- **Fold into guardrails design:** Treat this as part of the broader guardrail-provider interface in https://github.com/openclaw/openclaw/issues/72741, accepting that the specific confidentiality gap stays unresolved until that design lands.

Yes, from source for the API gap: current main has a blocking `before_agent_run` path but its event payload and call site omit provider/model. I did not run the reporter’s confidential-routing plugin or reproduce the external-provider disclosure end to end.

## Solution Assessment

Unclear until maintainers choose the API shape. The narrowest safe direction appears to be read-only resolved model identity on the existing blocking gate, while raw provider request hooks need separate trust and redaction review.
