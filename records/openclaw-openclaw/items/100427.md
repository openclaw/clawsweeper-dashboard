## Summary

Close: current main and v2026.6.11 already expose resolved provider/model identity to the blocking `before_agent_run` hook through the second handler context argument, and `model_call_ended` carries sanitized served-model identity for audit.

## What This Changes

The issue asks for plugin policy hooks to expose resolved/served provider and model identity before or during model serving, including blocking enforcement and post-hoc attribution.

## Best Possible Solution

Keep the shipped `before_agent_run` context as the blocking policy surface and use sanitized `model_call_*` hooks for audit; track any docs or CLI parity gap separately instead of exposing raw provider hooks broadly.

The narrower claims that the event payload lacks model fields and provider hook names are not registerable are source-confirmed, but they do not remove the blocking policy surface.

## Solution Assessment

Yes: using `ctx.modelProviderId` and `ctx.modelId` on `before_agent_run` is the narrowest shipped enforcement path, with `model_call_ended` for post-hoc attribution. Exposing raw provider hooks would be a separate public SDK/security decision and is not needed to solve the reported gate.
