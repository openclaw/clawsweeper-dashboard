## Summary

Keep open: current dispatch still has a zero-payload early-abort result, while the documented dead-letter path covers queue entries that exhaust retry; neither establishes recovery for a visible turn that returns empty before a run is committed. The related reports share the warning surface but describe different failures, so this is not a safe duplicate close.

## What This Changes

The issue requests branch-level diagnostics and durable recovery for visible inbound channel turns that complete with zero reply payloads and no persisted agent run.

## Best Possible Solution

Add a typed terminal reason from dispatch through the channel-turn kernel, then recover only visible turns whose durable claimant has neither completed nor retained the inbound event; cover iMessage catchup/restart and generic channel dispatch without retrying known duplicates or intentional aborts.
