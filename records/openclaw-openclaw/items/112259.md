## Label Justifications

- `P1`: Visible inbound messages can complete without a reply or durable transcript record, breaking a core channel workflow for affected turns.
- `impact:message-loss`: The reported consequence is a user message or generated reply that never reaches the sender, often without any user-visible failure.

## Summary

Keep this issue open. The supplied incidents establish a real P1 silent-message-loss class, while the reported zero-payload result still conflates distinct causes such as intentional suppression, dedupe/in-flight handling, admission, provider failure, and payload construction; the recent merged provider-503 repair covers one adjacent trigger but not the requested general diagnostic and recovery contract.

## What This Changes

Add reliable attribution and safe recovery for visible inbound channel turns that complete with no queued reply payload, preventing user messages from appearing to be silently ignored.

## System Context

Channel adapters pass accepted inbound messages into the shared turn kernel, which dispatches an agent run and collects outbound reply payloads for channel delivery. A zero-payload completion currently reaches the channel-level warning path after the underlying decision, leaving operators unable to distinguish benign suppression from a lost visible turn.

## Best Possible Solution

Define a structured zero-payload outcome reason at the dispatch/payload boundary, add focused regressions for each real loss mode, and recover only from cases with authoritative evidence that a visible user turn was accepted but neither intentionally suppressed nor already delivered.
