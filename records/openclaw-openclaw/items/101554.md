## Summary

Keep open: current main still performs the cited synchronous JSON serialization and SHA-256 hashing in the CLI bundled-MCP preparation path, but the report needs owner triage because that path hashes MCP server configuration, not tool schemas returned by an MCP server.

## What This Changes

The issue asks OpenClaw to avoid synchronous bundled-MCP hashing that can block the Node.js event loop and affect Gateway responsiveness.

## Best Possible Solution

Benchmark the current CLI bundled-MCP fingerprint path with large saved or bundle-provided MCP configs, then cache or move expensive config serialization/fingerprinting off the Gateway hot path while tracking actual tool-schema materialization in the existing MCP performance issues.

Partial, not yet high-confidence for the full user impact. Current main clearly has synchronous stringify/hash work and an equivalent no-write Node probe showed event-loop lag, but I did not reproduce Gateway heartbeat timeouts and the cited path hashes MCP config rather than returned schemas.

## Solution Assessment

Unclear. Removing only the synchronous hash is too narrow because serialization and resume canonicalization also block; the maintainable fix should be benchmarked against the real preparation path and coordinated with existing bundled-MCP performance work.
