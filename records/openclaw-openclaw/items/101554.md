## Summary

Keep open: current main and latest release still compute bundle-MCP config hashes synchronously during CLI runner preparation. Source inspection and a Node runtime probe support the event-loop blocking concern for large input, though the full Gateway heartbeat timeout symptom has not been end-to-end reproduced.

## What This Changes

The issue reports that bundle-MCP CLI preparation synchronously SHA-256 hashes large serialized MCP configuration on the Node.js main thread, potentially freezing the Gateway.

## Best Possible Solution

Move or bound bundle-MCP config fingerprint generation off the main event-loop hot path while preserving exact mcpConfigHash/mcpResumeHash semantics, loopback canonicalization, generated config contents, and existing session reuse behavior.

## Maintainer Decision

Required: false

## Reproduction Assessment

No high-confidence end-to-end Gateway reproduction yet. Source inspection and a lightweight Node probe confirm the synchronous hash can block the event loop, but the reported heartbeat timeout path still needs a real large-config Gateway run or focused regression harness.

## Solution Assessment

Unclear that changing only crypto.createHash is the best fix. The safer repair should treat serialization, resume canonicalization, and both hashes as one large-config hot path while preserving existing hash contracts.
