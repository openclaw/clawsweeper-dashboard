## Summary

Keep open: current main and the latest release still propagate OpenClaw's `path-to-regexp` 8.4.0 override into managed npm plugin roots, which conflicts with Express 4.x plugins such as `@askjo/camofox-browser`. The fix needs maintainer direction on managed-root override policy rather than a blanket downgrade that could break OpenClaw's Express 5/router stack.

## What This Changes

Ensure managed npm plugin installs do not force OpenClaw's `path-to-regexp` 8.x override into Express 4.x plugin dependency graphs, or at least diagnose the mismatch clearly.

## Best Possible Solution

Define a scoped managed-npm-root policy that preserves plugin-owned Express 4 dependency graphs without downgrading OpenClaw's Express 5/router path, with regression coverage and actionable diagnostics for install/update behavior.

Rationale: The source-level conflict is clear, but the permanent boundary is a maintainer policy choice because security override propagation protects OpenClaw installs while this specific override breaks valid Express 4.x plugin packages.

Owner confidence: medium

Options:

- **Scope Managed Overrides (recommended):** Filter or namespace host overrides for managed plugin roots so core security pins do not override plugin-owned dependency contracts when the plugin graph requires a different major version.
- **Diagnostic Only:** Keep current override propagation and add Express 4/path-to-regexp validation that tells plugin authors to add a package-local override or migrate to Express 5.
- **Keep Current Policy:** Treat this as plugin package ownership and require affected plugins such as camofox-browser to ship their own override or migrate off Express 4.

## Reproduction Assessment

Yes, source-level reproduction is high-confidence: managed npm installs copy the host `path-to-regexp` 8.4.0 override into plugin roots, while Express 4.x package metadata requires `path-to-regexp` 0.1.12. I did not run a live install in this read-only review.

## Solution Assessment

No, the issue's preferred blanket downgrade is not the best fix because OpenClaw's Express 5/router stack depends on `path-to-regexp` 8.x. The safer direction is a maintainer-approved scoped managed-root override policy, with diagnostics as a fallback or supplement.
