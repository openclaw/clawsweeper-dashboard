## Label Justifications

- `P2`: The issue reports a confirmed current-release crash path for Express 4.x plugins installed through managed npm roots, with limited blast radius to that plugin class.
- `impact:crash-loop`: Affected plugins can fail their HTTP route startup path when `path-to-regexp` 8.x is forced into an Express 4 dependency graph.
- `impact:ux-friction`: The visible tool-call symptom is a generic internal server error, while diagnosis and workaround require server logs and manual package override edits.

## Summary

Keep open: current main still propagates host workspace overrides into managed npm plugin roots, and dependency contracts show Express 4 plugins such as `@askjo/camofox-browser` need `path-to-regexp` 0.1.x while OpenClaw's Express 5/router stack needs 8.x.

## What This Changes

Request core plugin install handling so Express 4.x plugins do not inherit OpenClaw's `path-to-regexp` 8.x override and crash without per-plugin overrides.

## Best Possible Solution

Adopt a maintainer-approved scoped managed-npm dependency policy that preserves plugin-owned Express 4 dependency graphs without globally downgrading OpenClaw's Express 5/router path, with docs and regression coverage for install/update behavior.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should managed npm plugin installs stop inheriting host workspace overrides such as `path-to-regexp`, or should OpenClaw keep propagation and add targeted validation/guidance for incompatible plugin graphs?

Rationale: The source fix is not just mechanical: changing override propagation affects third-party plugin dependency ownership, security pinning, and OpenClaw's own Express 5 dependency policy.

Likely owner: vincentkoc

Owner reason: Most directly connected to the managed npm override propagation and recent plugin install dependency policy history.

Owner confidence: high

Options:

- **Scope host overrides away from plugin-owned graphs (recommended):** Preserve OpenClaw-owned override policy for core/bundled packages while letting third-party plugin package ranges or shrinkwraps resolve inside their managed project root, backed by Express 4 and Express 5 regression tests.
- **Add validator-only detection:** Detect Express 4 plus forced `path-to-regexp` 8.x during install and fail with an actionable message, leaving plugin authors responsible for package-local overrides or Express 5 migration.
- **Keep current propagation:** Require conflicting third-party plugins to ship their own overrides or migrate dependencies, accepting the current runtime failure mode until those packages update.

## Reproduction Assessment

Yes. Source-level reproduction is high-confidence: managed npm installs inherit host overrides, while npm metadata shows affected Express 4 plugins require `path-to-regexp` 0.1.12; I did not run a live plugin install in this read-only cleanup review.

## Solution Assessment

No, the issue's preferred blanket override/downgrade is not the best fix because OpenClaw's Express 5/router stack depends on `path-to-regexp` 8.x. The safer direction is a scoped managed-root override policy or explicit validator chosen by maintainers.
