## Summary

Keep open: current main still propagates the host path-to-regexp 8.4.0 override into managed npm plugin roots, and the latest issue comment confirms the problem still affects OpenClaw 2026.6.11 with @askjo/camofox-browser. The remaining decision is the dependency-ownership boundary for managed plugin installs, not conservative cleanup.

## What This Changes

The issue asks OpenClaw to stop Express 4.x plugins from inheriting a host path-to-regexp 8.x override that crashes their routes after managed npm install.

## Best Possible Solution

Adopt a maintainer-approved managed npm dependency policy that prevents host security overrides from breaking plugin-owned Express 4 graphs and surfaces an install or Doctor recovery path without requiring users to inspect logs or edit package files.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should managed npm plugin roots inherit OpenClaw host overrides such as path-to-regexp, or should OpenClaw scope those overrides away from plugin-owned dependency graphs and add targeted validation or Doctor recovery?

Rationale: Both directions change a compatibility and supply-chain boundary: host overrides protect OpenClaw's reviewed dependency graph, but applying them to third-party plugin roots can break valid plugin-owned dependency ranges.

Likely owner: vincentkoc

Owner reason: The current managed npm override propagation and workspace override lines route most directly through this recent area history.

Owner confidence: high

Options:

- **Scope Managed-Root Overrides (recommended):** Change managed npm roots so OpenClaw host overrides do not override plugin-owned dependencies unless explicitly safe, and add regression coverage for Express 4 and Express 5 graphs.
- **Add Validator Only:** Keep current override propagation but detect Express 4/path-to-regexp conflicts during install or Doctor and fail with a clear recovery message.
- **Keep Plugin-Owned Workaround:** Document that Express 4 plugins must ship their own override or migrate to Express 5, accepting that users can still hit runtime-only failures.
