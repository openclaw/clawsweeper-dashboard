## Summary

Keep open: current main still propagates OpenClaw's host path-to-regexp 8.4.0 override into managed npm plugin roots, while the reported Express 4 plugin graph requires path-to-regexp 0.1.12 and the proposed blanket downgrade would conflict with OpenClaw's Express 5/router stack.

## What This Changes

The issue asks OpenClaw to centralize managed plugin dependency override handling so Express 4.x plugins do not crash when host overrides force path-to-regexp 8.x.

## Best Possible Solution

Define a maintainer-approved scoped managed-npm-root override policy that preserves plugin-owned dependency graphs without downgrading OpenClaw's Express 5 path, and cover it with dependency-resolution docs plus regression tests.

## Maintainer Decision

Question: Should OpenClaw stop propagating all root pnpm overrides into third-party managed npm plugin roots, add conflict validation only, or keep requiring Express 4 plugin packages to ship their own override?

Rationale: The code change is not a narrow mechanical bug fix because the current override propagation is also a supply-chain and security policy surface for managed plugin installs.

Likely owner: vincentkoc

Owner reason: This login is most directly connected to the current managed override propagation and recent plugin install security work.

Owner confidence: medium

Options:

- **Scope host overrides in managed roots (recommended):** Preserve only maintainer-approved compatible host overrides in plugin npm projects, add an Express 4/path-to-regexp regression test, and document the boundary.
- **Add validator-only diagnostics:** Detect the Express 4/path-to-regexp conflict during install or startup and emit an actionable error while leaving package ownership unchanged.
- **Keep plugin-owned workaround:** Require affected plugin packages to ship their own override or migrate to Express 5, and close the OpenClaw-side policy change as not planned.

Yes, source-level reproduction is high-confidence: current managed npm installs inherit the host path-to-regexp 8.4.0 override, while Express 4 metadata requires path-to-regexp 0.1.12. I did not run a live plugin install because this cleanup review is read-only.

## Solution Assessment

No, the issue's preferred blanket central override is not the best fix because OpenClaw's current Express 5/router stack depends on path-to-regexp 8.x. The safer direction is a scoped managed-root policy or explicit validator chosen by maintainers.
