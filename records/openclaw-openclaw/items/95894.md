## Summary

Keep open: current main and the latest release still propagate OpenClaw's path-to-regexp 8.4.0 workspace override into managed npm plugin roots, which conflicts with Express 4.x plugin dependency graphs; the remaining question is the dependency-ownership policy, not whether the report is real.

## What This Changes

The issue asks OpenClaw core to prevent Express 4.x plugin installs from resolving path-to-regexp 8.x, or at least validate and explain that incompatibility.

## Best Possible Solution

Define a narrow managed-npm-root dependency policy that preserves plugin-owned Express 4 dependency graphs without globally downgrading OpenClaw's Express 5/router path, with docs and regression coverage for install and force-reinstall behavior.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should managed npm plugin roots inherit OpenClaw workspace overrides like path-to-regexp, or should OpenClaw scope/exempt those overrides so plugin-owned dependency graphs can resolve their own router stack?

Rationale: The source-level bug is clear, but the fix changes a dependency ownership and supply-chain boundary for all npm-installed plugins, and the obvious blanket downgrade conflicts with OpenClaw's own Express 5 stack.

Likely owner: Vincent Koc

Owner reason: This person has the strongest current-history connection to managed npm install and override propagation.

Owner confidence: medium

Options:

- **Scope managed-root overrides (recommended):** Keep security-critical host override support, but add a maintainer-approved exception or scoped policy so Express 4 plugin trees can resolve path-to-regexp 0.1.x while core keeps 8.x.
- **Validator-only guidance:** Detect Express 4 plus a conflicting path-to-regexp resolution during install/update and fail with a clear override or upgrade message, accepting that plugin authors still own the package fix.
- **Plugin-owned only:** Keep current override propagation and document that affected plugin packages must ship their own overrides or migrate to Express 5, leaving this class outside core repair.

## Reproduction Assessment

Yes. Source-level reproduction is high-confidence: current managed npm installs inherit the host path-to-regexp 8.4.0 override, while Express 4.x package metadata requires path-to-regexp 0.1.x; I did not run a live plugin install because this review is read-only.

## Solution Assessment

No, the issue's preferred blanket override is not the best fix because OpenClaw's current Express 5/router stack depends on path-to-regexp 8.x. The safer direction is a maintainer-approved scoped managed-root policy or validator that preserves plugin dependency ownership without breaking core.
