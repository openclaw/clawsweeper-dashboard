## Summary

Keep open: current main and the latest release still propagate the host path-to-regexp 8.4.0 override into managed npm plugin roots, while Express 4.x plugin graphs require path-to-regexp 0.1.x and can crash at startup.

## What This Changes

The issue requests a core/plugin install dependency policy so Express 4.x plugins do not inherit OpenClaw's path-to-regexp 8.x override and crash at runtime.

## Best Possible Solution

Define a scoped managed-npm-root override policy that lets plugin dependency graphs resolve their own path-to-regexp while preserving OpenClaw's Express 5/router 8.x path, plus docs, regression coverage, and actionable install/startup diagnostics.

Yes. Source inspection shows managed npm installs inherit the host path-to-regexp 8.4.0 override, and npm metadata confirms Express 4.x expects path-to-regexp 0.1.x; I did not execute a live install because this review is read-only.

No, the issue's preferred blanket central override is not the best proven fix because OpenClaw's current Express 5/router stack depends on path-to-regexp 8.x. The better direction is a maintainer-approved scoped managed-root policy or diagnostic that preserves plugin dependency ownership without breaking core.
