## Summary

Keep open: current main still propagates OpenClaw workspace overrides into managed npm plugin roots, including the path-to-regexp 8.4.0 override, while Express 4.x plugin packages require path-to-regexp 0.1.x; the remaining decision is the managed plugin dependency ownership policy, not whether the symptom is real.

## What This Changes

The issue asks OpenClaw to prevent Express 4.x-based plugins from crashing when managed npm plugin installs inherit a host path-to-regexp 8.x override.

## Best Possible Solution

Define a maintainer-approved managed npm root policy that preserves plugin-owned dependency graphs without globally downgrading OpenClaw's Express 5/router dependency path, then add focused install/update regression coverage and diagnostics.

- **Plugin-local ownership only:** Leave core unchanged and require affected plugin packages to publish their own shrinkwrap or override until they migrate away from Express 4.

## Reproduction Assessment

Yes. Source inspection shows current managed npm installs read OpenClaw workspace overrides into plugin roots, and registry metadata confirms Express 4.21.2 requires path-to-regexp 0.1.12 while OpenClaw currently overrides path-to-regexp to 8.4.0; I did not run a live plugin install because this cleanup review is read-only.

## Solution Assessment

No for the proposed blanket downgrade. OpenClaw's Express 5/router stack depends on path-to-regexp 8.x, so the better solution is a scoped managed-root policy or diagnostic path after maintainers choose the dependency ownership boundary.
