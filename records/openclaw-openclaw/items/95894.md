## Label Justifications

- `P2`: The issue reports a real plugin startup/runtime crash path with limited blast radius to Express 4.x plugins installed through managed npm roots.
- `impact:crash-loop`: Affected plugins can fail their HTTP route startup path when `path-to-regexp` 8.x is forced into an Express 4 dependency graph.
- `impact:ux-friction`: The reporter confirmed the user-visible tool calls return only internal server errors, leaving diagnosis to server-side logs and a fragile reinstall workaround.

## Summary

Keep open: current main and v2026.6.11 still propagate OpenClaw's host `path-to-regexp` 8.4.0 override into managed npm plugin roots, while Express 4 plugins need the 0.1.x dependency line.

## What This Changes

The issue asks OpenClaw to prevent Express 4.x npm plugins from inheriting an incompatible `path-to-regexp@8.x`, either through scoped dependency policy or install-time validation.

## Best Possible Solution

Define a scoped managed-npm-root dependency policy that preserves plugin-owned Express 4 graphs without globally downgrading OpenClaw's Express 5/router path, with clear diagnostics and regression coverage.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should managed npm plugin roots inherit OpenClaw host pnpm overrides unchanged, filter/scoped-propagate overrides such as `path-to-regexp`, or only validate and error for known plugin dependency conflicts?

Rationale: The right fix changes the dependency ownership boundary for third-party plugin installs and the security override policy, so automation should not choose it without maintainer intent.

Likely owner: vincentkoc

Owner reason: This login is the strongest current-history owner for managed npm root override propagation and plugin dependency docs.

Owner confidence: high

Options:

- **Scope managed-root overrides (recommended):** Preserve security-critical host override propagation where needed while excluding or namespacing overrides that conflict with plugin-owned runtime dependency graphs.
- **Validator-only diagnostic:** Detect Express 4 plus incompatible `path-to-regexp` during install/update and fail with a clear remediation message, leaving package authors responsible for overrides or shrinkwrap.
- **Keep plugin-owned workaround:** Document that Express 4 plugin packages must ship their own override or shrinkwrap and leave managed roots inheriting host overrides unchanged.

## Reproduction Assessment

Yes, there is a high-confidence source-level reproduction: managed npm installs read host overrides, current main and v2026.6.11 pin `path-to-regexp` 8.4.0, and Express 4.x metadata requires 0.1.x. I did not run a live plugin install in this read-only review.

## Solution Assessment

No, the issue's preferred blanket central override is not clearly the best fix because OpenClaw's Express 5/router stack depends on `path-to-regexp` 8.x. The safer direction is a maintainer-approved scoped managed-root policy or validator.
