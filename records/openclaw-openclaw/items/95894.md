## Summary

Keep open: current main still propagates host workspace overrides into managed npm plugin roots, including the path-to-regexp 8.4.0 pin, while Express 4.x still depends on path-to-regexp 0.1.12. The latest reporter confirmation says OpenClaw 2026.6.11 remains affected, and the fix needs a maintainer choice about managed-plugin dependency ownership rather than cleanup closure.

## What This Changes

The issue asks OpenClaw to prevent managed npm plugin installs from forcing the core path-to-regexp 8.x override into Express 4.x plugin dependency trees.

## Best Possible Solution

Define a narrow managed-npm-root dependency policy that preserves plugin-owned dependency graphs for third-party packages without breaking OpenClaw's Express 5/router security pins, then add docs and regression coverage for install/update behavior.

Options:

- **Scoped managed-root override policy (recommended):** Filter or scope host overrides so managed plugin roots preserve plugin-owned dependency ranges like Express 4's path-to-regexp 0.1.x while retaining explicitly approved OpenClaw security/peer pins.
- **Validator and diagnostic only:** Keep override propagation as-is but detect Express 4/path-to-regexp conflicts during install or doctor and produce an actionable error for plugin publishers and users.
- **Keep plugin-owned workaround:** Document that third-party Express 4 plugins must ship their own override or migrate to Express 5, accepting that OpenClaw-managed installs can still fail until publishers update.

## Reproduction Assessment

Yes. Source inspection shows managed npm plugin installs copy host workspace overrides into per-plugin roots, and dependency metadata shows Express 4.x needs path-to-regexp 0.1.12 while current OpenClaw pins 8.4.0; the reporter also confirmed the failure on OpenClaw 2026.6.11.

## Solution Assessment

Unclear until maintainers choose the dependency boundary. The issue's blanket override proposal is too risky for OpenClaw's Express 5/router path, so the best direction is a scoped managed-root policy or explicit validator chosen by maintainers.
