## Summary

Keep open: current main and the latest release still propagate OpenClaw's host `path-to-regexp` 8.4.0 override into managed npm plugin roots, while Express 4.x dependency metadata requires `path-to-regexp` 0.1.x. The reporter's new camofox-browser confirmation and the upstream issue at https://github.com/jo-inc/camofox-browser/issues/7734 are useful corroboration, but the OpenClaw-side dependency ownership policy still needs a maintainer decision.

## What This Changes

The issue requests a core plugin-install fix so Express 4.x plugins do not inherit OpenClaw's `path-to-regexp` 8.x override and crash at runtime.

## Best Possible Solution

Define a generic managed-npm-root dependency policy that preserves plugin-owned dependency graphs without globally downgrading OpenClaw's Express 5/router stack, then add docs and regression coverage for install/update behavior.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw stop propagating broad host workspace overrides such as `path-to-regexp` into third-party managed npm plugin roots, or should it keep the current override propagation and only detect/report Express 4 conflicts?

Rationale: Both paths affect the plugin dependency ownership contract and security override policy: preserving plugin dependency graphs may reduce central security pin reach, while keeping propagation can break third-party plugins at runtime.

Likely owner: vincentkoc

Owner reason: The current managed npm override code and related lockfile/workspace override lines are in this person's recent authored history.

Owner confidence: medium

Options:

- **Scope managed-root overrides (recommended):** Adjust managed npm roots so plugin-owned dependency ranges are not overridden by unrelated host pins such as `path-to-regexp`, while preserving explicit security pins that are safe for plugin graphs.
- **Add detection only:** Keep host override propagation but detect Express 4 plus incompatible `path-to-regexp` resolution during install/update and fail with an actionable error.
- **Document plugin-owned workaround:** Declare that third-party Express 4 plugins must ship their own override or migrate to Express 5, and update docs without changing core install behavior.

## Reproduction Assessment

Yes, source-level reproduction is high-confidence: current main and `v2026.6.11` still read host overrides into managed plugin npm roots, while npm metadata shows Express 4.21.2 requires `path-to-regexp` 0.1.12. I did not run a live plugin install in this read-only cleanup review.

## Solution Assessment

No, the issue's preferred blanket central downgrade is not the best fix because OpenClaw's Express 5/router stack requires `path-to-regexp` 8.x. The best direction is a maintainer-approved scoped managed-root policy or, if maintainers choose not to change dependency ownership, an actionable validator and docs path.
