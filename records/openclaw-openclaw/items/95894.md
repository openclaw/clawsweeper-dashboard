## Label Justifications

- `P2`: The issue reports a real plugin startup/runtime crash path with limited blast radius to Express 4.x plugins installed through managed npm roots.
- `impact:crash-loop`: Affected plugins can fail their HTTP route startup path when `path-to-regexp` 8.x is forced into an Express 4 dependency graph.

## Summary

Keep open: current main and the latest release still propagate OpenClaw's host `path-to-regexp` 8.4.0 override into managed npm plugin roots, while Express 4.x plugins need `path-to-regexp` 0.1.x; this remains a real plugin-install/runtime crash path that needs maintainer policy direction.

## What This Changes

The issue asks OpenClaw core to prevent Express 4.x plugin installs from inheriting the host `path-to-regexp` 8.x override, or at least fail with clear validation instead of a runtime route crash.

## Best Possible Solution

Define a maintainer-approved scoped managed npm dependency policy that preserves plugin-owned dependency graphs without globally downgrading OpenClaw's Express 5/router path, and add install/update regression coverage plus docs for the chosen behavior.

## Solution Assessment

No, the issue's preferred blanket root override is not the safest fix because OpenClaw's Express 5/router stack needs `path-to-regexp` 8.x. The best path is a maintainer-approved scoped managed-root policy or targeted validator that preserves plugin dependency ownership.
