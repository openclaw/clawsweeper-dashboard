## Summary

Keep open: current main still applies workspace overrides, including path-to-regexp 8.4.0, into managed npm plugin roots, while Express 4.x plugins require path-to-regexp 0.1.x and the reporter re-confirmed the failure on v2026.6.11. This needs maintainer dependency-policy direction because a blanket downgrade would conflict with OpenClaw's Express 5/router dependency path.

## What This Changes

The issue asks OpenClaw core to stop Express 4.x plugin installs from inheriting an incompatible path-to-regexp 8.x resolution or to surface a clear validator error.

## Best Possible Solution

Define a maintainer-approved managed-npm override policy that preserves intentional host security pins, respects plugin-owned dependency ranges, and emits actionable install/update diagnostics with regression coverage.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should managed npm plugin installs continue inheriting all host package overrides, or should OpenClaw scope or filter those overrides so third-party Express 4 dependency graphs remain plugin-owned?

Rationale: The current behavior is documented and tested as a host security-pin mechanism, but it can break legitimate plugin dependency graphs; changing it is a policy boundary, not a narrow mechanical bug fix.

Likely owner: Vincent Koc

Owner reason: This handle is the strongest current-history owner for managed npm root override propagation and related plugin install policy code.

Owner confidence: high

Options:

- **Design scoped override policy (recommended):** Preserve security-critical host pins only where explicitly intended and add conflict detection for plugin dependency ranges before install/update proceeds.
- **Validator-only warning:** Keep inherited overrides unchanged but detect Express 4/path-to-regexp conflicts and fail with a clear plugin-author action.
- **Keep plugin-owned workaround:** Require affected plugin packages to publish their own compatible dependency graph or migrate to Express 5, documenting OpenClaw's inherited override behavior as intentional.

## Reproduction Assessment

Yes. Source-level reproduction is high-confidence: current managed npm installs inherit the workspace path-to-regexp 8.4.0 override, Express 4.x requires path-to-regexp 0.1.12, and the affected camofox package depends on Express 4.x without an override; I did not run a live install because this cleanup review is read-only.

## Solution Assessment

No, the issue's preferred blanket central downgrade is not the best fix because OpenClaw's Express 5/router stack depends on path-to-regexp 8.x. The safer direction is a scoped managed-root override policy or explicit conflict validator chosen by maintainers.
