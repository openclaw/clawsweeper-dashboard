## Label Justifications

- `P2`: The issue reports a real managed-plugin startup/runtime crash path with limited blast radius to Express 4.x plugins.
- `impact:crash-loop`: Affected plugins can fail their HTTP route startup path when path-to-regexp 8.x is forced into an Express 4 dependency graph.

## Summary

Keep open: current main and the latest release still propagate the host path-to-regexp 8.4.0 override into managed npm plugin roots, which conflicts with Express 4.x plugin dependency graphs; this needs a maintainer decision on the managed-root override boundary before a fix is safe.

## What This Changes

The issue requests that OpenClaw prevent Express 4.x plugins from crashing under the host path-to-regexp 8.x override without requiring each plugin to carry its own override.

## Best Possible Solution

Define a scoped managed-npm-root dependency policy that lets plugin-owned Express 4 dependency ranges or plugin shrinkwraps win without globally downgrading OpenClaw's Express 5 path, then cover install/update behavior with focused tests and docs.

Options:

- **Scope managed-root overrides (recommended):** Filter or namespace host overrides so OpenClaw security pins do not force incompatible transitive versions into plugin-owned dependency graphs, with regression coverage for Express 4 and core Express 5.
- **Validator-only warning:** Keep host override propagation but detect Express 4/path-to-regexp conflicts during install and fail with a clear remediation message for plugin authors or operators.
- **Leave to plugin packages:** Treat the issue as downstream-owned and require affected plugins to ship their own overrides or migrate to Express 5, accepting fragile user workarounds after forced reinstalls.

## Reproduction Assessment

Yes. Source inspection shows managed npm plugin installs inherit the host path-to-regexp 8.4.0 override, and dependency metadata shows Express 4.x requires path-to-regexp 0.1.12; I did not run a live plugin install because this review is read-only.

## Solution Assessment

No, the issue's preferred blanket top-level downgrade is not the best fix because OpenClaw's current Express 5/router stack depends on path-to-regexp 8.x. The safer direction is a maintainer-approved scoped managed-root override policy or validator that preserves plugin dependency ownership without breaking core.
