## Summary

Keep open: current main still carries OpenClaw's `path-to-regexp` 8.4.0 override into managed npm plugin roots, while Express 4.21.2 requires `path-to-regexp` 0.1.12 and the reporter reconfirmed the failure on v2026.6.11.

## What This Changes

The issue asks OpenClaw core to prevent Express 4.x-based npm plugins from crashing under the host `path-to-regexp` 8.x override, either by central dependency policy or a validator.

## Best Possible Solution

Define a maintainer-approved scoped managed-npm dependency policy that preserves plugin-owned dependency graphs, including Express 4's `path-to-regexp` 0.1.x edge, without weakening OpenClaw's core Express 5/router pins.

Rationale: Both plausible fixes change the plugin dependency ownership boundary: filtering overrides affects security/reproducibility policy, while a central downgrade conflicts with core's Express 5/router stack.

Options:

- **Scope Managed Overrides (recommended):** Preserve OpenClaw root pins for core, filter or namespace managed-root overrides for third-party plugin projects, and add regression coverage for an Express 4 plugin install.
- **Validator Only:** Keep override propagation unchanged but detect Express 4/path-to-regexp conflicts and fail with an actionable plugin-author message.
- **Plugin-Owned Fix Only:** Leave OpenClaw core unchanged and require affected plugins to ship their own override, shrinkwrap, bundled dependency, or Express 5 migration.

## Reproduction Assessment

Yes. Source inspection shows managed npm plugin installs inherit the host `path-to-regexp` 8.4.0 override, and Express 4.21.2 metadata requires `path-to-regexp` 0.1.12; I did not run a live install because this review is read-only.

## Solution Assessment

No. The issue's preferred blanket central downgrade is not the best fix because OpenClaw's current Express 5/router stack depends on `path-to-regexp` 8.x; the better path is a scoped managed-root policy or explicit validator chosen by maintainers.
