## Label Justifications

- `P2`: The issue reports a real startup/runtime crash path with limited blast radius to Express 4.x plugins installed through managed npm roots.
- `impact:crash-loop`: Affected plugins can throw during HTTP route startup when path-to-regexp 8.x is forced into an Express 4 dependency graph.

## Summary

Keep open: current main and the latest release still propagate OpenClaw's path-to-regexp 8.4.0 override into managed npm plugin roots, which conflicts with Express 4.x plugin dependency metadata and still needs a maintainer-owned dependency-boundary decision.

## What This Changes

The issue reports Express 4.x plugin HTTP route crashes when managed plugin installs inherit OpenClaw's path-to-regexp 8.x override instead of Express 4's 0.1.x dependency.

## Best Possible Solution

Define a scoped managed-npm dependency policy that preserves plugin-owned Express 4 dependency graphs without globally downgrading OpenClaw's Express 5/router path, then add install/update regression coverage and actionable diagnostics.

## Maintainer Decision

Required: true

Question: Should OpenClaw change managed npm override propagation for third-party plugin roots, add Express 4-specific install validation, or keep the current policy that plugin packages must pin their own conflicting dependency graph?

Rationale: This choice affects the security/reproducibility purpose of host overrides, third-party plugin dependency ownership, and whether OpenClaw should repair or only diagnose dependency conflicts outside core.

Options:

- **Scope managed overrides (recommended):** Filter or scope host overrides so plugin-owned dependency graphs can satisfy Express 4 while OpenClaw keeps path-to-regexp 8.x for its own Express 5/router stack.
- **Add validator only:** Detect Express 4 plus missing path-to-regexp 0.1.x compatibility during install and fail with a clear operator/plugin-author action, without changing override propagation.
- **Leave to plugin authors:** Keep current managed-root override behavior and require affected plugin packages to ship their own override or migrate to Express 5.

## Reproduction Assessment

Yes. Source inspection shows managed plugin installs inherit the host path-to-regexp 8.4.0 override, dependency metadata shows Express 4.x needs path-to-regexp 0.1.x, and the reporter confirmed the same failure on v2026.6.11.

## Solution Assessment

No for the preferred blanket downgrade. The maintainable fix needs a scoped managed-root policy or validator that protects plugin dependency ownership without breaking OpenClaw's Express 5/router dependency path.
