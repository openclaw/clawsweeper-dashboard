## Summary

Keep open: current main still propagates the host path-to-regexp 8.4.0 override into managed plugin npm projects, which conflicts with Express 4.x plugin dependency graphs; the remaining work needs a maintainer dependency-boundary decision rather than cleanup closure.

## What This Changes

Issue requests a central OpenClaw fix for Express 4.x plugin installs that inherit an incompatible path-to-regexp version and crash at route startup.

## Best Possible Solution

Define a narrow managed npm project dependency policy that preserves plugin-owned Express 4 dependency graphs without globally downgrading OpenClaw's Express 5/router path, with docs and regression coverage for install/update behavior.

Options:

- **Scope host overrides away from plugin-owned deps (recommended):** Adjust managed npm project override propagation so OpenClaw security overrides do not replace a plugin package's Express 4-compatible path-to-regexp graph while preserving core Express 5/router resolution.
- **Add validator and keep plugin-owned pinning:** Detect Express 4 plugins resolved with path-to-regexp 8.x and fail with an actionable install/startup error while requiring plugin publishers to ship their own override or Express 5 migration.

Yes. Source inspection shows managed plugin installs still inherit the host path-to-regexp 8.4.0 override, and upstream Express 4.21.2 metadata requires path-to-regexp 0.1.12; the reporter also reproduced it on OpenClaw 2026.6.11 with camofox-browser.

## Solution Assessment

No. A blanket downgrade is not the best fix because OpenClaw's current Express 5/router stack depends on path-to-regexp 8.x; the maintainable fix needs a scoped managed-root policy or validator that preserves the core/plugin dependency boundary.
