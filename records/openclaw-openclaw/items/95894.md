## Summary

Keep open: current main still propagates the host workspace path-to-regexp 8.4.0 override into managed npm plugin roots, and dependency metadata confirms that can break Express 4.x plugin packages such as camofox-browser. This needs a maintainer decision because the fix changes the boundary between OpenClaw's security/reproducibility overrides and third-party plugin-owned dependency graphs.

## What This Changes

The issue requests preventing OpenClaw-managed npm plugin installs from inheriting a path-to-regexp 8.x override that breaks Express 4.x plugin routes.

## Best Possible Solution

Define a scoped managed-npm dependency policy that preserves plugin-owned transitive dependencies while retaining explicitly approved security pins for managed roots, then cover install/update behavior with regression tests and docs.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw stop applying the full root workspace override set to third-party managed npm plugin projects, or keep that policy and only add diagnostics for Express 4/path-to-regexp conflicts?

Rationale: Changing override propagation affects third-party plugin install compatibility and OpenClaw's security/reproducibility policy, so automation should not choose the permanent dependency-ownership boundary alone.

Likely owner: vincentkoc

Owner confidence: low

Options:

- **Scope propagated overrides (recommended):** Filter or namespace root workspace overrides before applying them to third-party plugin projects, preserving only explicitly approved managed-root security pins and adding Express 4 regression proof.
- **Add validator only:** Keep current override propagation but detect Express 4/path-to-regexp conflicts and fail with actionable reinstall or package-owner guidance.
- **Require plugin-owned fixes:** Leave OpenClaw installer behavior unchanged and document that affected plugins must pin path-to-regexp or upgrade to Express 5, accepting current runtime failures in managed installs.

## Reproduction Assessment

Yes for source-level reproduction: current main applies host workspace overrides to managed npm plugin roots, while Express 4.x package metadata requires path-to-regexp 0.1.x. I did not run a live plugin install because this cleanup review is read-only.

## Solution Assessment

No for the issue's preferred blanket override: globally downgrading path-to-regexp would conflict with OpenClaw's Express 5/router dependency path. The maintainable fix is a scoped managed-root override policy or an explicit validator chosen by maintainers.
