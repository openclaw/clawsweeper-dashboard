## Label Justifications

- `P2`: The issue reports a real plugin startup/runtime crash path with limited blast radius to Express 4.x plugins installed through managed npm roots.
- `impact:crash-loop`: Affected Express 4 plugins can fail their HTTP route startup path when path-to-regexp 8.x is forced into their dependency graph.
- `impact:ux-friction`: The reporter confirmed affected tool calls surface only generic internal errors, leaving most users to inspect server logs to find the dependency conflict.

## Summary

Keep open: current main still propagates the host path-to-regexp 8.4.0 override into managed npm plugin roots, while Express 4.x plugin graphs require path-to-regexp 0.1.x; the remaining fix needs a maintainer decision about managed-root override policy rather than a blanket downgrade.

## What This Changes

The issue asks OpenClaw core to stop managed plugin installs from forcing an incompatible path-to-regexp 8.x override into Express 4.x plugin dependency trees.

## Best Possible Solution

Define a scoped managed-npm-root dependency policy that preserves plugin-owned Express 4 dependency graphs without breaking OpenClaw's Express 5/router path, with a clear install-time or doctor diagnostic when a plugin package needs its own override.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should managed npm plugin roots inherit all host workspace overrides, or should OpenClaw scope/filter overrides such as path-to-regexp when they conflict with a plugin-owned dependency graph?

Rationale: Both choices affect plugin dependency ownership and security override policy, so automation should not choose the permanent boundary without maintainer intent.

Likely owner: amknight

Owner reason: This choice centers on the managed npm-root override reconciliation area that amknight most recently changed.

Owner confidence: medium

Options:

- **Scope managed-root overrides (recommended):** Filter or condition host overrides so plugin-owned Express 4 dependency graphs can resolve path-to-regexp 0.1.x while core keeps Express 5/router on 8.x, then add regression coverage.
- **Add validator only:** Keep current override propagation but fail or warn clearly for Express 4 plugins that lack their own package override, accepting that plugin authors must repair their packages.
- **Require plugin-owned fix:** Treat this as external plugin packaging responsibility and leave OpenClaw behavior unchanged, pointing affected plugins to add an override or move to Express 5.

## Reproduction Assessment

Yes. Source-level reproduction is high-confidence: current main propagates host workspace overrides into managed plugin roots, the host override pins path-to-regexp 8.4.0, and Express 4.21.2 metadata requires path-to-regexp 0.1.12; I did not run a live plugin install in this read-only review.

## Solution Assessment

No. The issue's preferred blanket central override is not the best fix because Express 5/router needs path-to-regexp 8.x; the better direction is a scoped managed-root policy or validator chosen by maintainers.
