## Summary

Keep open: current main and v2026.6.11 still propagate OpenClaw's path-to-regexp 8.x workspace override into managed npm plugin roots, while Express 4.x dependency metadata requires path-to-regexp 0.1.x. The report is valid, but the fix needs a maintainer decision because a blanket downgrade would conflict with OpenClaw's Express 5/router 2.x stack and the existing security override policy.

## What This Changes

The issue asks OpenClaw to prevent managed npm plugin installs from forcing path-to-regexp 8.x into Express 4.x plugin dependency trees, either through central override policy or validation.

## Best Possible Solution

Define a maintainer-approved managed-npm-root dependency policy that preserves plugin-owned Express 4 dependency graphs or fails with a targeted diagnostic, without downgrading OpenClaw's Express 5/router path; cover it with install/update tests and dependency-resolution docs.

No. The issue's preferred blanket top-level downgrade is not the best fix because OpenClaw's Express 5/router stack depends on path-to-regexp 8.x; the safer direction is a scoped managed-root policy or targeted validator chosen by maintainers.
