## Summary

Keep open: current main and the latest v2026.6.11 release still propagate OpenClaw's host path-to-regexp 8.4.0 override into managed npm plugin roots, while Express 4 plugins require the 0.1.x line; this needs a maintainer decision on the managed-plugin dependency boundary rather than cleanup closure.

## What This Changes

The issue asks OpenClaw to prevent Express 4.x-based managed npm plugins from crashing when host-level path-to-regexp 8.x overrides are applied to their install roots.

## Best Possible Solution

Define a maintainer-approved managed npm root override policy that preserves security/reproducibility overrides without forcing incompatible host transitive pins into plugin-owned dependency ranges, with focused install/update tests and docs.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should managed npm plugin roots continue inheriting all host pnpm overrides, or should OpenClaw scope/filter managed overrides so plugin-owned Express 4 dependency graphs keep their package-selected path-to-regexp line?

Rationale: Both directions have product and security tradeoffs: host overrides protect OpenClaw's reviewed dependency boundary, but unscoped propagation can break third-party plugin dependency ownership and route startup.

Likely owner: vincentkoc

Owner reason: This is the clearest current owner signal for the managed npm root install and override propagation path.

Owner confidence: medium

Options:

- **Scope managed overrides (recommended):** Filter or narrow host override propagation for managed plugin roots, preserving necessary OpenClaw security overrides without overriding incompatible plugin-owned transitive ranges; this best matches the plugin dependency ownership docs.
- **Validator-first only:** Keep override propagation unchanged and add install/startup diagnostics that detect Express 4 plus incompatible path-to-regexp, accepting that plugin authors still need to repair their package metadata.
- **Keep plugin-owned workaround:** Leave core unchanged and rely on affected plugin packages, such as camofox-browser, to migrate to Express 5 or publish their own shrinkwrap/override.

## Reproduction Assessment

Yes. Source inspection shows managed plugin installs still inherit host overrides, current release/main still pin path-to-regexp 8.4.0, and dependency metadata shows Express 4 expects the 0.1.x line while the current Express 5/router path expects 8.x.

## Solution Assessment

No, the issue's preferred blanket top-level override is not clearly the best fix because it can conflict with OpenClaw's own Express 5/router stack. The better direction is a scoped managed-root dependency policy or explicit validator chosen by maintainers.
