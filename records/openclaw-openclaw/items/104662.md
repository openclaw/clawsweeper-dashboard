## Summary

The patch is a focused and technically sound fix for a real current-main hang: the WebRTC SDP answer body can remain pending indefinitely after response headers arrive. No blocking code or security defect was found, but the external PR's real-browser proof predates two current-head lifecycle amendments, so the current head still needs after-fix runtime proof before merge.

## What This Changes

The PR adds a 30-second AbortController deadline around the Control UI WebRTC SDP offer fetch and answer-body read, aborts an in-flight offer when the transport stops, and adds timeout, cancellation, and timer-cleanup regression tests.

## Best Possible Solution

Keep the timeout transport-local and internal, spanning both the SDP POST and answer-body read, with immediate stop cancellation and one exact-head browser proof covering stalled timeout and user-stop cleanup before merge.
