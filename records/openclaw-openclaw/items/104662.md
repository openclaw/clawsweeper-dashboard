## Summary

Current main still leaves the successful SDP response-body read unbounded, while the current PR fixes that path without a blocking correctness or security finding. The PR remains necessary and should stay open for normal merge after the exact-head lint failure is resolved.

## What This Changes

The PR adds a 30-second abort deadline for the Control UI WebRTC SDP offer exchange, cancels pending offer reads on stop, and adds regression tests for timeout and cleanup behavior.

## Best Possible Solution

Keep one transport-owned AbortController active across both the SDP fetch and body read, abort it on stop, clear it after success, and retain focused coverage for timeout and cleanup behavior.
