## Summary

Keep open: current main and the latest release still carry session identity into the macOS exec approval path, but the native popup does not display the existing session key, and richer requester context still needs a maintainer privacy/security decision.

## What This Changes

The issue requests that the macOS native exec approval popup show the existing session key and consider richer requester/channel context.

## Best Possible Solution

Stage the work by adding a trimmed non-empty Session row to the macOS native prompt first, then add only maintainer-approved and redacted requester/channel fields to the Swift request model and display path.
