## Summary

Keep open: current main and v2026.6.11 still omit session identity from the native macOS approval popup, while the linked channel-prompt PR explicitly excludes this surface. The request remains useful, but displaying raw session, sender, or channel identifiers in a security decision requires an intentional disclosure and redaction contract.

## What This Changes

Show the originating session and safe requester context in the native macOS exec approval popup.

## Best Possible Solution

Use one shared, bounded approval-identity contract that displays a sanitized session label plus authoritative channel/thread context when available, clearly separates any untrusted explanatory text, omits raw sender identifiers by default, and applies length, privacy, accessibility, and empty-value rules consistently across native and channel prompts.
