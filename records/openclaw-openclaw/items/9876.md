## Summary

Keep open: current main and the latest release still carry session metadata into the macOS exec approval request, but the native popup does not render the existing session key or any higher-level requester context. The related open PR only covers channel/chat approval prompt text and explicitly leaves this macOS native popup out of scope.

## What This Changes

Show session identity and safe requester/channel context in the macOS native exec approval popup.

## Best Possible Solution

Stage the work by adding a trimmed non-empty Session row to the macOS native prompt first, then add only maintainer-approved and redacted requester/channel fields to the Swift request model and display path.
