## Summary

Keep this issue open. Current main still carries `sessionKey` into the macOS approval request but omits it from the native popup, while requester identity/source disclosure needs an explicit privacy and security contract before extending the gateway-to-macOS payload.

## What This Changes

Add session and safely scoped requester context to the macOS exec-approval popup.

## Best Possible Solution

Add a non-empty Session row now for parity, then implement only maintainer-approved, UI-safe origin metadata through the existing approval request contract with focused macOS presentation and protocol compatibility coverage.
