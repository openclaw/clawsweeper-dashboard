## Summary

Keep open: current main and the latest release still pass `sessionKey` into the macOS exec approval request path but the native popup does not render it, and the open related PR explicitly fixes channel/chat approval prompts rather than this macOS surface.

## What This Changes

The issue requests that the macOS exec approval popup show the existing session key and, if product-approved, higher-level requester context such as channel and sender.

## Best Possible Solution

Stage the work: first render a trimmed non-empty Session row in the macOS native prompt, then add only maintainer-approved requester/channel fields with explicit privacy and redaction coverage.

## Reproduction Assessment

Yes. Source inspection on current main shows `sessionKey` is decoded and passed into the native prompt, but `buildAccessoryView` does not render it; I did not run a live macOS NSAlert.

## Solution Assessment

Unclear for the full request. The Session row is the narrow maintainable first fix, while channel/sender/requester fields need a privacy and security decision before implementation.
