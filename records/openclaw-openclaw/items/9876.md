## Summary

Keep open: current main still carries session identity into the macOS exec approval request, but the native popup does not render it, and the richer requester-context part still needs privacy and security direction. The related open PR is useful partial overlap for channel prompt text, but it explicitly leaves the macOS native popup out of scope.

## What This Changes

The issue asks for the macOS exec approval popup to show the triggering session and higher-level requester context such as channel or sender.

## Best Possible Solution

Stage the fix: render a trimmed non-empty Session row in the macOS prompt, then add only maintainer-approved and redacted requester/channel fields to the native request model and display path.

## Reproduction Assessment

Yes. Source inspection reproduces the gap: an `ExecApprovalPromptRequest` can carry `sessionKey`, but `ExecApprovalsPromptPresenter.buildAccessoryView` has no Session row.

## Solution Assessment

Unclear for the full issue as written. The Session row is the narrow maintainable first fix, but channel/sender/requester display should wait for a privacy and security decision on safe fields and redaction.
