## Summary

Keep open: current main and the latest release still carry `sessionKey` into the macOS exec approval request, but the native popup does not render it. The related open PR is useful partial overlap for channel prompt text, but it explicitly leaves this macOS native popup request out of scope.

## What This Changes

Request to show the originating session and safe requester/channel context in the macOS native exec approval popup.

## Best Possible Solution

Stage the fix: first render a trimmed non-empty Session row in the macOS prompt, then add only maintainer-approved and redacted requester/channel fields to the native request model and display path.

## Reproduction Assessment

Yes at source level. `ExecApprovalPromptRequest` can carry `sessionKey`, but `ExecApprovalsPromptPresenter.buildAccessoryView` has no Session row, and no live macOS popup run was performed in this read-only review.

## Solution Assessment

Unclear for the full issue as written. The Session row is the narrow maintainable first fix, but channel/sender/requester display should wait for a privacy and security decision on safe fields and redaction.
