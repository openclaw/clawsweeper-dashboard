## Summary

Keep open: current main still carries session identity into the macOS exec approval request, but the native popup does not render it, and the broader requester/channel/sender display needs maintainer privacy and security direction before implementation.

## What This Changes

The issue requests that the macOS exec approval popup show session and requester context so users can distinguish which session or channel triggered an approval.

## Best Possible Solution

Stage the fix: render a trimmed non-empty Session row in the macOS prompt now, then add only maintainer-approved and redacted requester/channel fields to the native request model and display path.

## Reproduction Assessment

Yes, source-reproducible: construct an ExecApprovalPromptRequest with sessionKey and buildAccessoryView still renders no Session row. I did not run a live macOS NSAlert in this read-only review.

## Solution Assessment

Unclear for the full issue as written: the Session row is the narrow maintainable first fix, but adding channel/sender/requester fields should wait for a privacy and security decision on which identifiers are safe to show.
