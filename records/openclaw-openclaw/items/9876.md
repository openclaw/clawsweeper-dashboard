## Summary

Keep this issue open. Current main still transports `sessionKey` to the macOS approval-request model, but the native presenter does not render it; deciding which requester metadata is safe and useful to disclose in a local approval dialog remains a maintainer product/security choice. The open channel-prompt PR is related but explicitly excludes this macOS surface.

## What This Changes

Add session identity and, subject to a disclosure policy, requester/channel context to the macOS exec-approval popup.

## Best Possible Solution

Keep the existing approval transport intact, add a non-empty Session row to the native popup, and define a redacted allowlist of requester fields before extending the Swift payload and presentation.
