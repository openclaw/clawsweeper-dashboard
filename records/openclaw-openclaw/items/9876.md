## Summary

Keep open: current main and v2026.6.11 still carry `sessionKey` into the macOS native exec approval request but do not render it, and the related open PR is scoped to channel/chat prompts rather than the native macOS popup.

## What This Changes

The issue asks the macOS exec approval popup to show the originating session and, if approved by maintainers, safe requester/channel context.

## Best Possible Solution

Stage the native macOS fix by rendering a trimmed non-empty Session row first, then add only maintainer-approved and redacted requester/channel fields to the Swift request model and popup.
