## Summary

Keep open: current main and v2026.6.11 still pass session data through exec approval paths, but the native macOS popup does not render a Session row. The linked channel-prompt PR is useful adjacent work, but it explicitly leaves the macOS native popup out of scope.

## What This Changes

The issue asks for the macOS native exec approval popup to show the existing session key and, with maintainer-approved privacy rules, richer requester/channel context.

## Best Possible Solution

Render a trimmed non-empty Session row from the existing sessionKey, then add channel/sender/thread context only through a maintainer-approved safe display and redaction contract with focused macOS prompt coverage.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 decode and pass sessionKey into macOS exec approval prompts, but buildAccessoryView does not add a Session row. The richer requester-context portion is also source-visible because TypeScript/protocol payload fields exist while Swift has no native fields for them.

## Solution Assessment

Partly: rendering the existing session key is the narrowest maintainable parity fix. The requester/channel/sender portion needs a privacy and security contract before new native UI fields should be added.
