- `impact:session-state`: The ambiguity is specifically about distinguishing which active session triggered a native macOS approval request.

- `impact:ux-friction`: Operators can still approve or deny, but multiple sessions or channels make the native popup unnecessarily ambiguous.

## Summary

Keep open: current main still carries session identity into the macOS exec approval prompt path, but the native popup does not display the existing session key and richer requester context still needs maintainer product/security direction.

## What This Changes

The issue requests session identity and optional requester/channel context in the macOS native exec approval popup so users can distinguish concurrent approval requests.

## Best Possible Solution

Stage the work by adding a trimmed non-empty Session row to the macOS native prompt first, then add only maintainer-approved and redacted requester/channel fields to the Swift request model and display path.
