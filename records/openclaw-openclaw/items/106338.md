## Summary

Keep this PR open for revision: the existing review blocker remains on the current head because profile identity is still discarded before the newly profile-aware picker key runs, so the intended account-specific choices do not reliably reach the picker.

## What This Changes

The PR makes model-catalog deduplication and picker option keys profile-aware so identical provider/model rows discovered through different auth profiles can remain distinct.

## Best Possible Solution

Make profileId part of the canonical logical catalog identity and projection, then use that preserved identity consistently through picker selection and runtime auth routing while retaining the existing provider/model form for entries without a profile.
