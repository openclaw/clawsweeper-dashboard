## What This Changes

The PR gives existing Control UI chats the same abortable attachment-read lifecycle as new-session composition, preventing incomplete files from being omitted on send or transferred after a rapid chat switch.

## System Context

The Control UI composer converts pasted, picked, or dropped browser files into in-memory attachment payloads before a `chat.send` request. The changed lifecycle owns those reads at the chat-session level, blocks submission until a batch settles, and aborts reads when the pane changes session or disconnects.

## Architecture Diagram

flowchart LR
  A[Browser file input] --> B[Attachment read lifecycle]
  B --> C[Session-owned abort signal]
  C --> D[Composer pending-read gate]
  D --> E[Chat send payload]
  C --> F[Session switch or disconnect]
  F --> G[Abort reads and release payloads]
