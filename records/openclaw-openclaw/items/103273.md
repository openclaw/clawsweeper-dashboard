## Summary

The patch addresses a real current-main delivery hazard: Android automatically requeues persisted in-flight commands, while gateway chat deduplication is process-local and expires, so an accepted command can be replayed after interruption. The focused implementation is sound and CI is green, but this external PR still needs after-fix Android lifecycle proof before merge.

## What This Changes

The PR changes Android startup recovery so outbox commands left in `sending` become visible delivery-unconfirmed failures that can only be replayed through the existing user Retry action.

## Best Possible Solution

Keep the focused delivery-unconfirmed failed state, preserve the original idempotency key, and merge only after a redacted Android device or emulator run proves restart does not replay the command and explicit Retry sends it exactly once.

## Solution Assessment

Yes. Reusing the existing failed-row Retry/Delete UX is narrower and safer than adding another state or config option, and it correctly requires fresh user intent when delivery cannot be confirmed.
