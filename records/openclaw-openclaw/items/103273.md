## Summary

The exact-head implementation correctly aligns durable-outbox behavior with Android’s existing direct-send ambiguity rule, but the release-owned changelog edit should be removed and this external PR still needs after-fix proof from a real Android lifecycle run before merge.

## What This Changes

The PR changes Android outbox recovery and send classification so interrupted or possibly dispatched commands become visible delivery-unconfirmed failures requiring explicit Retry, while requests proven not enqueued remain automatically retryable.

## Best Possible Solution

Remove the PR-owned changelog entry, use one canonical Android rule that automatically retries only requests proven not to have entered the socket queue, keep every possibly dispatched command visible as delivery-unconfirmed, and merge after a redacted device or emulator lifecycle run proves the behavior.
