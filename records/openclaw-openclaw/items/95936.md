## Summary

Keep open: current main still uses per-agent memory SQLite stores, so the PR is not obsolete, but this branch is not safe to merge because the same reviewed head still changes persistent memory-store identity without an upgrade path, shares session-source state without an accepted visibility model, and exposes unsettled memory-host SDK registry APIs.

## What This Changes

This PR redirects memory-source agents to a workspace-hashed shared SQLite store, removes `extraPaths` from the memory index identity hash, and exports shared-store registry helpers through the memory-host SDK.

## Best Possible Solution

Land a shared-memory design only after store identity, index identity, upgrade behavior, session visibility, and SDK/registry API ownership are accepted together and covered by focused upgrade and search-path proof.
