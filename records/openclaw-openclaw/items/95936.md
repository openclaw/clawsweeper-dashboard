## Label Justifications

- `P2`: The PR targets real duplicated memory-index cost for multi-agent users, but it is a normal-priority storage design change rather than an emergency runtime outage.
- `merge-risk: 🚨 compatibility`: The diff changes the default persistent memory database path for existing enabled memory-source agents and adds plugin-visible SDK helpers.
- `merge-risk: 🚨 session-state`: Sharing the memory database can mis-associate agent/session-indexed state unless the final design preserves the intended per-agent/session scope.
- `merge-risk: 🚨 security-boundary`: Session transcript chunks in a shared database can cross agent visibility boundaries if all search paths do not enforce the same filters.

## Summary

Keep open: the patch is not merge-ready because previous storage, migration, session-visibility, and SDK-surface blockers remain, and the shared database path still leaves manager lifecycle keyed per agent rather than per shared store.

## What This Changes

The PR changes builtin memory to use a workspace-hash shared SQLite path, removes extraPaths from index identity, and exposes shared-store hash/registry helpers through memory-host SDK facades.

## Best Possible Solution

Land a shared-memory design only after store identity, manager lifecycle, upgrade behavior, session visibility, and plugin SDK/registry contracts are accepted together and proven on latest head.
