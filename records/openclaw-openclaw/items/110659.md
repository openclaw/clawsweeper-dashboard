## Summary

Keep this PR open for a targeted correction and maintainer confirmation. The reported current-main positional restore bug is concrete, and the proposed identity approach addresses ordinary deletion and reordering, but it cannot distinguish deleting an original row from renaming a different row to that deleted row’s former id; that collision can still silently bind a placeholder to the wrong original value. The PR body also describes real Control UI runs but does not provide inspectable after-fix media, logs, or live output.

## What This Changes

The branch adds identity-based restoration for redacted values in object arrays, plus regression coverage for deleting, reordering, inserting, and changing array entries.

## Best Possible Solution

Preserve the deletion/reorder fix while carrying an immutable row identity through the Control UI snapshot, or explicitly define `id` as immutable for redacted rows and require a clear re-entry flow whenever it changes, then add coverage for rename-to-removed-id collisions.
