This PR remains necessary because current main still removes protocol-valid zero components from normalized event IDs; the proposed behavior matches the gateway schema and in-repo dedupe semantics, with no concrete correctness or security defect found.

## What This Changes

The PR changes SDK gateway-event ID normalization to retain numeric zero components and adds regression coverage for zero sequence and timestamp values.

## Best Possible Solution

Preserve protocol-valid zero components at the normalization boundary, keep normalized IDs documented and consumed as opaque keys, and retain focused regression coverage; if persisted cross-version IDs are considered supported, add an explicit upgrade note or compatibility assertion before release.
