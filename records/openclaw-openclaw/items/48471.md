## Summary

Keep open: current main has several building blocks, including non-interactive gateway setup, tokenized dashboard launch, Telegram allowlist setup, and a Telegram username resolver, but it still does not provide the requested single supported bootstrap path that configures daemon, dashboard auth, Telegram bot, and intended owner access together. The Sentinel Stack and Keep My Claw comments are useful external references, but they do not replace an official OpenClaw setup contract.

## What This Changes

Requested one-line local bootstrap that installs or refreshes the daemon, opens authenticated dashboard access, configures Telegram, and pre-authorizes the intended Telegram owner.

## Best Possible Solution

A maintainer-approved bootstrap surface should compose the existing non-interactive gateway/dashboard pieces with a Telegram-owned numeric owner allowlist or preapproval path, keeping explicit risk acknowledgement and clear docs that DM pairing remains a separate trust flow.
