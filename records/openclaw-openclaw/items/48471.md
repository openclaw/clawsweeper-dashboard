## Summary

Keep open: current main and the latest checked release have the installer, non-interactive onboarding, dashboard token URL, Telegram token setup, numeric allowlists, and Telegram username resolution as separate pieces, but they still do not provide a supported one-command local bootstrap that configures daemon, dashboard auth, and Telegram owner access together. The external sentinel-stack-public prompt is useful reference material for an allowlist-preseed workaround, but it is not an OpenClaw core implementation.

## What This Changes

Request a supported one-line local bootstrap path that installs or refreshes OpenClaw, starts the daemonized gateway, emits a usable dashboard auth URL, and configures Telegram bot owner access non-interactively.

## Best Possible Solution

Define an additive maintainer-approved bootstrap or onboard path that composes the existing daemon, dashboard token URL, Telegram token, and numeric-owner allowlist pieces without silently approving pairing.
