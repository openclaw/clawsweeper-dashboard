## Summary

Keep open: current main has several prerequisite pieces, including non-interactive gateway setup, tokenized dashboard opening, and a Telegram target resolver, but it still lacks the requested first-class one-line localhost + Telegram owner bootstrap surface.

## What This Changes

Issue requests a supported one-line local bootstrap flow covering daemonized gateway setup, dashboard auth, Telegram bot configuration, and non-interactive Telegram owner access.

## Best Possible Solution

Add an explicit documented bootstrap path that preconfigures Telegram via allowlist/preapproval, prints or opens the dashboard auth URL, and clearly states that unattended DM pairing is not the security model.
