## Summary

Keep open: current main and the latest release provide separate pieces for non-interactive local setup, daemon install, dashboard token URLs, Telegram token setup, numeric allowlists, and Telegram username resolution, but they still do not provide one supported one-line local bootstrap that also configures Telegram owner access. The discussion usefully points to an external sentinel-stack prompt/workaround and to allowlist preseed as a secure direction, but that is reference material rather than an OpenClaw core implementation.

## What This Changes

Request a supported one-line local bootstrap path for install/start, authenticated localhost dashboard access, Telegram bot setup, and Telegram owner preauthorization.

## Best Possible Solution

Add a maintainer-approved bootstrap surface that composes existing local onboarding, daemon install, dashboard URL delivery, Telegram token setup, and numeric owner allowlist/preapproval while explicitly preserving the pairing security model and documenting unresolved-owner fallbacks.

## Reproduction Assessment

Yes for the missing-capability claim by source inspection: current main and v2026.6.11 have the individual command surfaces but no supported one-line path that configures Telegram owner access. This is not a broken existing contract; it is a missing feature surface.

## Solution Assessment

Unclear until maintainers choose the product/security shape. The best direction appears to be an additive wrapper or onboard flags using numeric allowlist/preapproval, not unattended pairing approval or a runtime security shortcut.
