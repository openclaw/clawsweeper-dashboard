## Summary

Keep open: current main now has a Telegram resolver plus separate daemon, dashboard, and Telegram setup pieces, but it still lacks the requested supported one-line local bootstrap that composes those pieces into non-interactive owner setup without weakening Telegram DM trust.

## What This Changes

Request a supported one-line local bootstrap that installs or refreshes OpenClaw, configures the local gateway daemon and dashboard auth URL, configures Telegram, and pre-authorizes the intended owner.

## Best Possible Solution

Add an additive bootstrap/onboard path that configures daemon startup, dashboard auth delivery, Telegram token, numeric owner allowlist, and `commands.ownerAllowFrom` without silently approving pairing.
