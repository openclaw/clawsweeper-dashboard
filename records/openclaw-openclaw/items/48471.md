## Summary

Keep open: current main still has separate installer/onboarding, daemon install, dashboard token URL, channel setup, Telegram numeric allowlist setup, resolver, doctor, and pairing pieces, but no supported one-line local bootstrap that safely completes daemon, dashboard auth, Telegram bot setup, and owner preauthorization together. This remains a product/security decision, not a conservative cleanup close.

## What This Changes

Request a supported one-line local setup path that installs/starts the gateway, opens an authenticated local dashboard, configures Telegram, and preauthorizes the intended Telegram owner without weakening pairing semantics.

## Best Possible Solution

Define a maintainer-approved local bootstrap contract that composes the existing setup pieces while preserving explicit numeric Telegram owner allowlists or another verified preapproval flow, then document and test it end to end.
