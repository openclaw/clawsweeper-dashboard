## Summary

Keep this PR open, but do not merge yet: the current head still uses filename extensions to distinguish a spaced local path from multiple media sources, so valid one-file paths such as `/tmp/album.v1/photo.png copy.png` remain split into two attachments. This is the same unresolved P2 concern from the latest completed ClawSweeper review cycle, not a new concern.

## What This Changes

This PR changes `MEDIA:` reply-directive parsing so an unquoted absolute local path containing spaces can remain one media attachment while separately listed media sources stay separate.

## System Context

Agent reply text may contain `MEDIA:` directives that are parsed into attachment sources before local or remote media resolution and message delivery. The changed parser decides whether whitespace denotes multiple attachments or belongs inside one local path.

## Best Possible Solution

Replace the extension-based ambiguity rule with the existing local-source resolution contract or another source-validity discriminator that preserves both one-file spaced paths and genuine mixed media lists, then add the dotted-directory regression case.
