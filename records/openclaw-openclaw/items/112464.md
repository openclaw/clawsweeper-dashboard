## Summary

Keep this PR open: it fixes the reported absolute-path case, but its new collapse rule turns valid unquoted relative multi-media directives into one invalid filename, dropping both attachments.

## What This Changes

Updates the reply `MEDIA:` parser so an unquoted local path containing spaces is treated as one media item while preserving separately rooted media entries.

## System Context

Agent and tool output may contain `MEDIA:` directives that the media parser turns into attachment sources for later loading and delivery. This change sits at the parser boundary, before path resolution and sending, so misclassification can suppress otherwise valid attachments.

## Best Possible Solution

Preserve the spaced-path repair only for an unambiguous whole-path form, or move ambiguity resolution to the later path-resolution layer; add regression coverage for valid relative multi-media directives before merge.
