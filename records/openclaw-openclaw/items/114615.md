## Summary

## What This Changes

Avoid eager plugin-manifest registry initialization for gateway-only CLI RPC commands when their command policy says plugins are never needed.

## System Context

The CLI resolves command policy, reads the configuration needed to locate and authenticate to the Gateway, then opens a local WebSocket RPC connection. Plugin configuration validation currently appears capable of pulling plugin metadata into that otherwise thin client path, adding startup work before the Gateway receives the request.

## Architecture Diagram

flowchart LR
  A[CLI command] --> B[Command policy]
  B --> C[Config and credential read]
  C --> D[Plugin validation decision]
  D --> E[Gateway RPC client]
  E --> F[Local Gateway]
  F --> G[RPC result]
  D --> H[Plugin manifest registry]

## Best Possible Solution

Implement a command-scoped minimal configuration path for gateway RPC commands that avoids plugin-manifest work while preserving gateway connection, credential, dotenv, and invalid-config behavior; add a regression timing/import test for both fresh and existing plugin-bearing configuration.
