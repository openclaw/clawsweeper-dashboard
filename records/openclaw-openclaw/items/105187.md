- `P2`: The issue deterministically breaks sandbox missing-file checks in localized containers, but its blast radius is limited to affected filesystem workflows.
- `impact:other`: Localized sandbox file checks throw unexpectedly, which is meaningful maintainer-visible impact outside the narrower owned categories.

## Summary

Keep open: current main and the latest release both contain the locale-sensitive error check, and no duplicate or open fix PR owns the work. The bug has a narrow implementation and regression-test boundary suitable for a focused repair.

## What This Changes

Make sandbox stat return null for a missing file without relying on English stderr text from the container.

## Best Possible Solution

Have the stat command plan emit a reserved locale-independent result when the anchored basename is absent, map only that result to null, and preserve permission, backend, path-safety, and malformed-output failures as errors.

## Maintainer Decision

## Reproduction Assessment

Yes at source level. Current main explicitly recognizes only one English missing-file phrase, so an equivalent localized stderr message deterministically bypasses the null branch and throws; this read-only review did not execute a localized container.

## Solution Assessment

Yes, provided the repair uses a structured command-level missing-path result. Treating every nonzero stat exit as a missing file would be unsafe because it would conceal unrelated failures.
