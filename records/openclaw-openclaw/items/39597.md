## Summary

Keep open. Current main has Gateway connection-level client identity for logs and presence, but agent-facing WebChat `chat.send` context and the runtime prompt still do not expose a Mac-app-versus-browser client type; the remaining work needs a maintainer product/security decision on trusted client metadata.

## What This Changes

The issue asks for WebChat to distinguish client types such as native Mac app, browser, and mobile web in agent/runtime context.

## Best Possible Solution

Define a typed, maintainer-approved client metadata contract that exposes only trusted Gateway connect identity to agents, with untrusted browser/app hints kept diagnostic-only.

- **Allow explicit caller hints:** Add a client-supplied metadata field or header documented as untrusted and excluded from security or policy decisions.
