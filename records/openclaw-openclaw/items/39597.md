## Summary

Keep open. Current main distinguishes Gateway WebSocket clients during connection setup, but the requested agent-facing WebChat client subtype still does not reach chat.send/runtime context and needs maintainer security/product direction.

## What This Changes

The issue requests exposing WebChat client type, such as native Mac app versus browser or mobile web, to agents at runtime.

## Best Possible Solution

Define one additive Gateway-owned client metadata contract with explicit trusted/untrusted semantics, then propagate it through WebChat/native chat.send paths into agent runtime metadata with focused protocol, prompt, and security tests.
