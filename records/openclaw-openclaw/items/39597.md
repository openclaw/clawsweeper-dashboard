## Summary

Keep open. Current main and v2026.6.11 already carry client identity during Gateway WebSocket connect, but WebChat/native `chat.send` turns and the agent runtime line still do not expose a trusted client-type field to agents; the remaining work needs product/security agreement on trust semantics.

## What This Changes

The issue requests agent-visible WebChat client-type metadata so native Mac app, browser, and mobile web clients can be distinguished at runtime.

## Best Possible Solution

Define one additive Gateway-owned client metadata contract with explicit trusted versus untrusted semantics, then propagate it through WebChat/native send paths into runtime metadata with focused tests and docs.

## Reproduction Assessment

Yes, as a source-level reproduction. Current main carries client metadata in the WebSocket connect frame, but `chat.send`, WebChat `MsgContext`, and the runtime prompt still lack an explicit agent-facing client-type field.

## Solution Assessment

Unclear. The suggested custom header or config flag is plausible, but the maintainable path is to reuse or extend the Gateway client metadata contract with explicit trust semantics rather than adding a WebChat-only side channel.
