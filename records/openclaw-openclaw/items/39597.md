## Summary

Keep open. Current main and v2026.6.11 still distinguish WebChat clients during Gateway connect, but agent-facing `chat.send` context and the runtime line still expose only the WebChat channel; the remaining work needs a maintainer security/product decision on trusted versus untrusted client metadata.

## What This Changes

Expose a way for agents to distinguish WebChat client types such as native Mac app, browser, and mobile web instead of seeing only `channel=webchat`.

## Best Possible Solution

Define one additive Gateway-owned client metadata contract with explicit trusted/untrusted semantics, then propagate it through WebChat/native `chat.send` paths into runtime metadata with focused tests and docs.
