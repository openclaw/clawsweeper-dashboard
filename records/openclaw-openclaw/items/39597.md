## Summary

Keep open. Current main and v2026.6.11 already carry client identity in the Gateway connect frame for browser/control UI and native Mac clients, but that identity is not exposed as a clear agent-facing WebChat runtime client-type field; the remaining work needs a security/product decision about trust semantics.

## What This Changes

Expose a WebChat client-type signal so agents can distinguish native Mac app, browser, and mobile web contexts.

## Best Possible Solution

Define one additive Gateway-owned client metadata contract with explicit trusted/untrusted semantics, then propagate the approved fields through WebChat/native chat.send paths into runtime metadata with focused protocol, prompt, and security tests.
