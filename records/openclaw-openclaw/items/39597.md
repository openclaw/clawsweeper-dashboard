## Summary

Keep open. Current main and v2026.6.11 still have Gateway client identity at WebSocket connect time, but the agent-facing WebChat turn context and runtime line do not expose a clear Mac-app-versus-browser client type, and the remaining work needs a maintainer security/product decision.

## What This Changes

Expose WebChat client type, such as native Mac app versus browser/mobile web, to agents or runtime context.

## Best Possible Solution

Define one additive Gateway-owned client metadata contract with explicit trusted/untrusted semantics, then propagate it through WebChat/native chat.send paths into runtime metadata with focused tests and docs.
