## Summary

Keep open. Current main and v2026.6.11 already carry typed Gateway client identity for browser/native clients, but the agent-facing runtime line still exposes only the channel, and Control UI/WebChat sender identity is explicitly suppressed; exposing client type to agents needs a maintainer-owned trust-boundary decision.

## What This Changes

Expose WebChat client type, such as macOS app versus browser or mobile web, to agent runtime context.

## Best Possible Solution

Define a typed agent-facing WebChat client metadata contract derived from validated Gateway connect identity, with spoofable header or browser hints kept diagnostic-only and explicitly untrusted.
