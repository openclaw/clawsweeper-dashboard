## Summary

Keep open. Current main has a Gateway connect-time client identity contract, but direct WebChat turns still do not expose a trusted agent-visible client type that distinguishes native Mac app, browser, or mobile WebChat; the remaining work needs a product/security decision on trust semantics.

## What This Changes

The issue asks OpenClaw to identify WebChat client types such as native Mac app, desktop browser, and mobile browser and expose that identity to agent/runtime context.

## Best Possible Solution

Define one additive Gateway-owned WebChat client metadata contract with explicit trusted/untrusted semantics, then propagate it through `chat.send` and runtime prompt context with focused protocol, WebChat, prompt, docs, and spoofing tests.
