## Summary

Keep open. Current main already distinguishes Gateway clients in the WebSocket connect metadata and post-connect logs, but `chat.send` and `MsgContext` still expose the turn as internal `webchat` without an agent-facing Mac-app versus browser client type; exposing that metadata needs a maintainer security/product decision.

## What This Changes

Expose distinct WebChat client-type metadata, such as Mac app versus browser or mobile web, to agent/runtime context.

## Best Possible Solution

Define one additive Gateway-owned client metadata contract with explicit trusted/untrusted semantics, then propagate it through WebChat and native chat-send paths into agent runtime metadata with focused protocol, prompt, and security coverage.
