## Summary

Keep open. Current main and v2026.6.11 already distinguish browser/WebChat and native Mac clients at the Gateway WebSocket connect layer, but that client identity is still not exposed as an agent-facing WebChat client type in chat.send context or the runtime prompt; the remaining work needs a security/product decision on trusted versus untrusted client metadata.

## What This Changes

Request to expose WebChat client type, such as native Mac app versus browser or mobile web, to agents through gateway/runtime context.

## Best Possible Solution

Define one additive Gateway-owned client metadata contract with explicit trusted/untrusted semantics, then propagate it through native/browser WebChat chat.send paths into agent runtime metadata with focused protocol, prompt, and security tests.
