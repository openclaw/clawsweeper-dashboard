## Summary

Keep open. Current main and v2026.6.11 already distinguish browser/native clients during Gateway connect, but agent-visible WebChat runtime context still has no client type, and exposing it requires a maintainer security/product decision on trust semantics.

## What This Changes

Request to expose WebChat client type, such as native macOS app versus browser or mobile web, in agent runtime context.

## Best Possible Solution

Define one additive Gateway-owned client metadata contract with explicit trusted/untrusted semantics, then propagate it through WebChat/native chat.send paths into runtime metadata with focused tests and docs.
