## Summary

Keep open. Current main and v2026.6.11 already carry distinct WebSocket connect client IDs for browser/WebChat and native Mac clients, but that identity is not exposed as an agent-facing WebChat client type in chat.send context or the runtime prompt line; the remaining work needs a security/product decision on trusted versus untrusted client metadata.

## What This Changes

The issue asks OpenClaw to distinguish WebChat client types such as native Mac app, browser, and mobile web in agent/runtime context.

## Best Possible Solution

Define one additive Gateway-owned client metadata contract with explicit trusted/untrusted semantics, then propagate it through native/browser WebChat chat.send paths into agent runtime metadata with focused protocol, prompt, and security tests.
