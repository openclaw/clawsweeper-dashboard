## Summary

Keep open. Current main and v2026.6.11 already carry WebChat/native client identity during the Gateway connect handshake, but agent-facing runtime context still has no explicit trusted client-type field; the remaining work is a security/product contract decision, not conservative cleanup.

## What This Changes

The issue requests agent-visible WebChat client-type metadata so native Mac app, browser, and mobile web clients can be distinguished at runtime.

## Best Possible Solution

Define one additive Gateway-owned client metadata contract with explicit trusted/untrusted semantics, then propagate it through WebChat/native chat.send paths into runtime metadata with protocol, prompt, and security tests.
