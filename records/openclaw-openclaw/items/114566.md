## Summary

This remains a plausible Feishu feature request, but it needs owner product direction before implementation: a Card Kit poll is not only outbound rendering, it introduces callback authorization, vote-state durability, deduplication, and update semantics. The related open callback request means the claimed prerequisite is not yet proven on current main, so this should not be closed or auto-dispatched as a narrow repair.

## What This Changes

Add Feishu poll creation through Card Kit buttons so the cross-channel poll tool can render, collect votes, update tallies, and close a poll in Feishu group chats.

## System Context

OpenClaw routes portable channel actions through channel-plugin adapters; the Feishu plugin turns those actions into Feishu messages and receives platform events back into the Gateway. A poll implementation would add a stateful interactive Card Kit loop between the agent's poll request and group members' vote callbacks.

## Architecture Diagram

flowchart LR
  A[Agent poll request] --> B[Portable channel poll action]
  B --> C[Feishu channel plugin]
  C --> D[Feishu Card Kit poll card]
  D --> E[Group member button click]
  E --> F[Validated vote callback]
  F --> G[Poll state and tally]
  G --> H[Updated card and final result]

## Best Possible Solution

Have the Feishu plugin owner approve the poll contract, then implement it in the Feishu package with a documented Card Kit setup path, authenticated callback handling, durable per-poll vote state, and end-to-end Feishu proof before enabling the portable poll capability.
