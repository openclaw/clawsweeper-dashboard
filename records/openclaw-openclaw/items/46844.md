## Summary

Keep open: current main and v2026.6.11 still lack a between-turn Talk idle timeout or public Talk idle-timeout config, so this remains valid product work rather than cleanup-close material.

## What This Changes

The issue requests a configurable Talk Mode idle timeout after Voice Wake activation so the voice pipeline deactivates after inactivity instead of staying active until manual stop or the hard session cap.

## Best Possible Solution

Define one additive Talk idle-timeout contract, expose it through config and talk.config/protocol/docs, and implement macOS Talk so inactive sessions return to wake-word waiting without changing silenceTimeoutMs semantics.

- **Defer to broader voice lifecycle design:** Keep this open until maintainers design a larger Talk and Voice Wake lifecycle policy that also covers realtime and mobile behavior.
