## Summary

Keep open: current main and v2026.6.11 still lack a between-turn Talk idle timeout or public Talk idle-timeout config, so the Voice Wake-triggered Talk deactivation request remains valid product work.

## What This Changes

The issue requests a configurable idle timeout that automatically deactivates Talk Mode after Voice Wake starts it and the user stops interacting.

## Best Possible Solution

Define one additive Talk idle-timeout contract, expose it through config and talk.config, document it publicly, and implement macOS Talk so inactive sessions return to wake-word waiting without changing silenceTimeoutMs semantics.
