## Summary

Keep open: current main and v2026.6.11 still only implement intra-turn Talk silence handling, so the requested between-turn auto-deactivation remains missing and needs maintainer product direction.

## What This Changes

Requests a configurable Talk Mode idle timeout that auto-deactivates Voice Wake-started Talk sessions after no user interaction.

## Best Possible Solution

Define one additive Talk idle-timeout contract, expose it through config and talk.config/protocol/docs, and implement macOS Talk so inactive sessions return to wake-word waiting without changing silenceTimeoutMs semantics.
