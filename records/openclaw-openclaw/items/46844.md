## Summary

Keep open: current main and v2026.6.11 still lack a between-turn Talk idle timeout or public Talk idle-timeout config, so this remains valid product work rather than cleanup-close material.

## What This Changes

Add a configurable idle timeout that deactivates Talk Mode after Voice Wake starts it and no user or assistant interaction occurs for a chosen period.

## Best Possible Solution

Define one additive Talk idle-timeout contract, expose it through config and talk.config/protocol/docs, and implement macOS Talk so inactive sessions return to wake-word waiting without changing silenceTimeoutMs semantics.
