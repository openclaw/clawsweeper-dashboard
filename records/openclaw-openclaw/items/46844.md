## Summary

Keep open: current main and the latest release still lack a between-turn Talk idle timeout or public Talk idle-timeout config, so the Voice Wake-triggered Talk deactivation request remains valid product work.

## What This Changes

Requests a configurable Talk Mode idle timeout that deactivates Talk after Voice Wake starts it and no user interaction occurs for a chosen interval.

## Best Possible Solution

Define one additive Talk idle-timeout contract, expose it through config and talk.config/protocol/docs, and implement macOS Talk so inactive sessions return to wake-word waiting without changing silenceTimeoutMs semantics.
