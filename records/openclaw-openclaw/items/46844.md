## Summary

Keep open: current main and v2026.6.11 still do not expose or enforce a between-turn Talk Mode idle timeout, so the reported token/session-lifecycle problem remains real product work rather than cleanup-close material.

## What This Changes

Requests a configurable Talk Mode idle timeout that deactivates Voice Wake-started Talk sessions after inactivity and returns to wake-word waiting.

## Best Possible Solution

Define one additive Talk idle-timeout contract, expose it through config and talk.config/protocol/docs, and implement macOS Talk so inactive sessions return to wake-word waiting without changing silenceTimeoutMs semantics.

- **Defer to broader voice lifecycle design:** Keep this open until maintainers design a larger Talk and Voice Wake lifecycle policy that also covers realtime and mobile behavior.
