## Summary

Keep open: current main still lacks a between-turn Talk idle timeout or public idle-timeout config, so the Voice Wake-triggered Talk auto-deactivation request remains valid product work.

## What This Changes

The issue requests a configurable Talk Mode idle timeout after Voice Wake activation so the audio pipeline deactivates after inactivity and waits for the next wake word.

## Best Possible Solution

Define one additive Talk idle-timeout contract, expose it through config and talk.config, document it publicly, and implement macOS Talk so inactive sessions return to wake-word waiting without changing silenceTimeoutMs semantics.
