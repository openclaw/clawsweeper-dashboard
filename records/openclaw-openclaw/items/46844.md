## Summary

Keep open: current main and the latest release still lack a between-turn Talk idle timeout or public Talk idle-timeout config, so the Voice Wake-triggered Talk deactivation request remains valid product work.

## What This Changes

The issue requests a configurable Talk idle timeout that auto-deactivates Voice Wake-started Talk sessions after inactivity and returns to wake-word waiting.

## Best Possible Solution

Define one additive Talk idle-timeout contract, expose it through config and talk.config, document it publicly, and implement macOS Talk so inactive sessions return to wake-word waiting without changing silenceTimeoutMs semantics.
