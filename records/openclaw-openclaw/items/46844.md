## Summary

Keep open: current main and v2026.6.11 still lack a between-turn Talk idle timeout or public Talk idle-timeout config, so the requested Voice Wake-triggered Talk deactivation remains product work.

## What This Changes

The issue requests a configurable Talk Mode idle timeout that automatically deactivates voice wake-triggered Talk sessions after inactivity.

## Best Possible Solution

Define one additive Talk idle-timeout contract, expose it through config and talk.config, document it publicly, and implement macOS Talk so inactive sessions return to wake-word waiting without changing silenceTimeoutMs semantics.
