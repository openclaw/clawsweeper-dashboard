## Summary

Keep open: current main and v2026.6.11 still lack a between-turn Talk idle timeout or public Talk idle-timeout config, so this remains valid product work that needs a Talk lifecycle/config decision before implementation.

## What This Changes

The issue requests a configurable Talk Mode idle timeout that auto-deactivates after Voice Wake starts Talk Mode and no further user interaction occurs.

## Best Possible Solution

Define one additive Talk idle-timeout contract, expose it through config and `talk.config`, document it publicly, and implement macOS Talk so inactive sessions return to wake listening while keeping `silenceTimeoutMs` scoped to transcript-finalization pauses.
