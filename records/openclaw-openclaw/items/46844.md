## Summary

Keep open: current main and the latest release still lack between-turn Talk idle deactivation after Voice Wake starts Talk Mode, and the remaining work is a public lifecycle/config product decision rather than a closeable stale request.

## What This Changes

Request an idle timeout for Voice Wake-triggered Talk Mode so inactive voice sessions automatically deactivate and return to wake-word listening.

## Best Possible Solution

Keep this as the canonical Talk idle-deactivation tracker, approve one additive public lifecycle/config contract, then implement it through config validation, Talk config response/protocol, macOS Talk runtime, docs, and focused tests.

Options:

- **Approve additive Talk idle timeout (recommended):** Add a canonical `talk` idle-timeout setting with explicit units, bounds, reset events, and disabled value, then apply it to the approved Talk session scope.
- **Scope only to Voice Wake-triggered Talk:** Implement idle deactivation only for sessions started by Voice Wake, preserving manual Talk Mode behavior until a broader lifecycle policy is approved.
- **Keep current manual exit behavior:** Decline a new setting for now and leave Talk Mode active until the user exits or existing hard-stop behavior applies.

## Reproduction Assessment

Yes, at source level. Current main can enable Talk Mode from Voice Wake, but the Talk silence monitor ignores empty between-turn silence and the runtime resumes listening after replies or failures instead of deactivating.

## Solution Assessment

Unclear as an implementation choice. The requested direction is valid, but maintainers still need to choose the public config/lifecycle contract before a fix PR should implement it.
