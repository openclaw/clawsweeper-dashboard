## Summary

Keep open. Current main and the latest release still support Voice Wake-to-Talk activation and intra-turn Talk silence handling, but they do not expose or honor a between-turn idle deactivation contract for inactive Talk sessions.

## What This Changes

The issue requests a configurable Talk Mode idle timeout that turns Talk off after Voice Wake starts it and the user stops interacting.

## Best Possible Solution

Define one additive Talk idle-timeout contract, expose it through config and talk.config, document it publicly, and implement the native Talk lifecycle so inactive sessions return to wake-word waiting without changing silenceTimeoutMs semantics.

Likely owner: steipete

Owner confidence: high

Options:

- **Approve additive Talk idle timeout (recommended):** Add a canonical Talk config field with explicit units, limits, disabled behavior, and reset events, then wire it through config, protocol, docs, and native Talk runtime.
- **Scope only to Voice Wake sessions:** Track activation source and auto-deactivate only Talk sessions started from Voice Wake, leaving manually started Talk sessions unchanged.
- **Defer to broader voice lifecycle work:** Keep this issue open but wait for a wider Talk and Voice Wake lifecycle design that also covers realtime and mobile behavior.

## Reproduction Assessment

Yes. Source inspection shows Voice Wake can enable Talk Mode, while Talk only finalizes non-empty transcripts after silence and then resumes listening after replies or failures.

## Solution Assessment

Unclear as an implementation choice. The requested behavior is valid and bounded, but maintainers still need to choose the public config shape, scope, default, limits, reset events, and disabled behavior before a fix PR should implement it.
