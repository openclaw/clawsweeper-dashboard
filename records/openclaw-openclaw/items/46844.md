## Summary

Keep open: current main and the latest release still lack a between-turn Talk idle timeout or public Talk idle-timeout config, so this remains valid but product-sensitive Talk lifecycle work.

## What This Changes

Add a configurable Talk idle timeout that automatically deactivates Voice Wake-started Talk Mode after inactivity and returns to wake-word waiting.

## Best Possible Solution

Define one additive Talk idle-timeout contract, expose it through config and talk.config, document it publicly, and implement macOS Talk so inactive sessions return to wake-word waiting without changing silenceTimeoutMs semantics.

- **Defer to broader Talk lifecycle design:** Keep this open until maintainers design a wider Talk and Voice Wake lifecycle policy that also covers realtime and mobile behavior.
