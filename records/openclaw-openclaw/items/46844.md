## Summary

Keep open. Current main and v2026.6.11 still expose Voice Wake-to-Talk activation and intra-turn Talk silence handling, but they do not provide a between-turn Talk idle deactivation or public idle-timeout config contract.

## What This Changes

The issue requests a configurable Talk Mode idle timeout that deactivates Voice Wake-started Talk sessions after a period with no user interaction.

## Best Possible Solution

Define one additive Talk idle-timeout contract, expose it through config and `talk.config`, document it publicly, and implement macOS Talk deactivation without changing `silenceTimeoutMs` transcript-finalization semantics.

- **Scope only to Voice Wake-started Talk:** Track activation source and auto-deactivate only sessions started from Voice Wake, leaving manually started Talk sessions unchanged.
- **Defer to broader voice lifecycle design:** Keep this issue open while maintainers design a larger Talk/Voice Wake lifecycle that also covers realtime sessions and mobile behavior.

## Reproduction Assessment

Yes. Source inspection shows Voice Wake can enable Talk Mode, but the Talk runtime only finalizes non-empty transcripts after the short silence window and then resumes listening after replies or failures.

## Solution Assessment

Unclear as an implementation contract. The requested idle timeout is a plausible solution, but maintainers need to choose the public config scope and lifecycle semantics before a fix PR should implement it.
