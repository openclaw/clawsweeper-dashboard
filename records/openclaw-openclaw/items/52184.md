## Label Justifications

- `P2`: The issue affects macOS gateway service stability for Volta-managed Node users but is bounded to daemon runtime path selection and needs policy review rather than emergency handling.
- `impact:crash-loop`: A LaunchAgent pinned to a removed Volta tools/image Node executable can leave the managed gateway unable to start after a Node upgrade.
- `maturity:stable`: The affected macOS Gateway host surface is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main and v2026.6.11 still only stabilize Homebrew Cellar Node paths, while the Volta shim fallback remains an unmerged product decision with a closed same-repo candidate and an open fork candidate.

## What This Changes

Request that macOS gateway LaunchAgent generation prefer a stable Volta shim path over a version-pinned Volta tools/image Node path when no better system Node is available.

## Best Possible Solution

Decide the managed-service runtime policy, then either land a refreshed, tested resolver-level Volta shim fallback with live macOS LaunchAgent proof or document that supported system Node is the only supported way to avoid version-manager fragility.

## Reproduction Assessment

No high-confidence live launchd reproduction was run. Source inspection gives a medium-confidence path: a supported Volta tools/image `process.execPath` falls through `resolveStableNodePath` unchanged when no supported system Node is selected first.

## Solution Assessment

Unclear. Extending `resolveStableNodePath` is the likely narrow code boundary, but maintainers need to decide whether Volta shim fallback is supported versus the current system-Node preference and version-manager warnings.
