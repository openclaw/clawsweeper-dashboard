## Label Justifications

- `P2`: The issue affects macOS gateway LaunchAgent stability for Volta-managed Node installs but has a bounded service-install surface and an existing candidate fix path.
- `impact:crash-loop`: A version-pinned Volta Node executable in the LaunchAgent can leave the managed gateway unable to start after Node upgrades.
- `maturity:stable`: The affected macOS Gateway host surface is M4 Stable and explicitly includes version-manager drift plus Gateway LaunchAgent lifecycle.

## Summary

Keep open: current main and the latest release still leave Volta tools/image Node paths unchanged, and the linked open candidate is not merged. The remaining decision is whether OpenClaw should support Volta shim fallback when no supported system Node is available.

## What This Changes

The issue requests that macOS gateway LaunchAgent generation prefer a stable Volta shim over a version-pinned Volta tools/image Node binary.

## Best Possible Solution

Review or replace the narrow Volta normalization candidate against current daemon runtime policy, then land a helper-level fix with tests and live macOS LaunchAgent proof only if maintainers accept Volta shim fallback as supported behavior.

## Reproduction Assessment

No live high-confidence reproduction was run in this read-only review. Source inspection gives a medium-confidence path: a supported Volta tools/image process.execPath falls through resolveStableNodePath unchanged when no supported system Node is selected first.

## Solution Assessment

Unclear. Extending resolveStableNodePath is the narrowest implementation boundary, but maintainers still need to accept or reject Volta shim fallback versus the current documented preference for system Node in managed services.
