## Summary

Keep open: current main and v2026.6.11 still leave Volta tools/image Node paths unchanged, and the remaining decision is whether OpenClaw should support the Volta shim as a managed-service fallback despite the current system-Node preference.

## What This Changes

Request to prefer a stable Volta shim path over a version-pinned Volta tools/image Node path when generating the macOS gateway LaunchAgent.

## Best Possible Solution

Decide the Volta service-runtime policy, then either land a helper-level Volta tools/image normalization with focused tests and live macOS LaunchAgent proof, or document that system Node remains the supported managed-service path.

Options:

- **Review a proof-backed Volta fallback (recommended):** Keep this issue open and require the candidate or replacement PR to prove an actual macOS LaunchAgent install/reinstall under Volta before accepting the policy change.
- **Reject Volta service shim fallback:** Keep the current system-Node policy, document that Volta-managed service runtimes remain warned/unsupported, and close this issue after that maintainer decision.
- **Adopt the helper change without live proof:** Accept the narrow resolver/test change now, but own the risk that Volta shims may behave differently in launchd than in an interactive shell.

No live high-confidence reproduction was established in this read-only review. Source inspection gives a clear path: a supported Volta tools/image `process.execPath` is returned unchanged when no supported system Node is selected first.

## Solution Assessment

Unclear. Extending `resolveStableNodePath` is the narrowest code boundary, but it is only the best fix if maintainers accept Volta shim fallback as supported managed-service behavior and require live LaunchAgent proof.
