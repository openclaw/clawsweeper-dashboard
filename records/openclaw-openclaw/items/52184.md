## Summary

Keep open: current main and the latest release still leave the reported Volta tools/image Node path unchanged, and the linked Volta normalization candidate is open rather than merged or shipped. The issue remains a bounded gateway service stability request, but the Volta-shim fallback policy needs maintainer review before another repair lane is queued.

## What This Changes

The issue requests that macOS gateway LaunchAgent generation prefer the stable Volta shim path over a version-specific Volta Node image path when Volta-managed Node is detected.

## Best Possible Solution

Keep this issue open while maintainers decide the Volta shim fallback policy, then land or reject the existing narrow normalization candidate with focused helper tests and live macOS LaunchAgent proof if accepted.

## Reproduction Assessment

Yes from source, but not from a live macOS Volta setup in this review. A supported Volta tools/image `execPath` flows through `resolveStableNodePath`; with no supported system Node selected first, current main returns the version-pinned path unchanged.

## Solution Assessment

Unclear. Extending `resolveStableNodePath` is the narrowest implementation boundary, but maintainers still need to accept Volta shim fallback as supported managed-service behavior before treating the candidate as the best fix.
