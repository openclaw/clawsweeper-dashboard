## Label Justifications

- `P2`: The issue affects macOS gateway service stability for Volta-managed installs, but it is bounded to runtime path selection and needs policy review rather than emergency handling.
- `impact:crash-loop`: A LaunchAgent pinned to a removed Volta tools/image Node executable can leave the managed gateway unable to start after Node upgrades.
- `maturity:stable`: The affected macOS Gateway host surface is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main and the latest release still leave Volta tools/image Node paths unchanged, and the remaining work is a gateway service runtime policy decision with open candidate implementation paths rather than conservative cleanup.

## What This Changes

Request that macOS gateway LaunchAgent generation prefer the stable Volta shim path over a version-pinned Volta tools/image Node binary when Volta is the selected Node manager.

## Best Possible Solution

Decide the Volta managed-service runtime policy, then either land Volta tools/image-to-shim normalization with focused tests and live macOS launchd proof, or document that system Node or an explicit runtime-pin path is the supported managed-service answer.

Unclear until maintainers decide policy. Extending `resolveStableNodePath` is the narrow technical seam, but it is only the best solution if Volta shims are accepted as a supported gateway service runtime path.
