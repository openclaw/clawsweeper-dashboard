## Summary

Keep open: current main and the latest release still leave Volta tools/image Node paths unchanged when no supported system Node is selected, and accepting a Volta shim fallback remains a managed-service runtime policy choice.

## What This Changes

The issue asks macOS gateway LaunchAgent generation to prefer a stable Volta shim path over a version-pinned Volta Node image path.

## Best Possible Solution

Settle the managed-service runtime policy, then either land a helper-level Volta normalization with focused tests and live macOS LaunchAgent proof or keep system/bundled/pinned Node as the supported path and document that choice.

Rationale: The code change is narrow, but it changes daemon runtime policy from warning about version-manager paths toward supporting a specific Volta shim fallback under launchd.
