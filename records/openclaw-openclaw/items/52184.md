## Label Justifications

- `P2`: The issue affects macOS gateway service stability for Volta-managed Node installs, but the blast radius is bounded to service runtime path selection.
- `impact:crash-loop`: A LaunchAgent pinned to a removed Volta tools/image Node executable can leave the managed gateway unable to start after Node upgrades.
- `maturity:stable`: The affected `macos-gateway-host` surface is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main and the latest release still leave Volta tools/image Node paths unchanged, and the remaining decision is whether managed gateway services should support a Volta shim fallback despite the current system-Node preference.

## What This Changes

Request macOS gateway LaunchAgent generation to prefer the stable Volta shim path over version-pinned Volta tools/image Node paths when no supported system Node is selected.

## Best Possible Solution

Decide the Volta fallback policy, then either land helper-level Volta tools/image normalization with focused tests and live macOS LaunchAgent proof, or document that system Node remains the supported managed-service path.

## Maintainer Decision

Required: true

Question: Should OpenClaw support an accessible Volta shim as the fallback LaunchAgent Node executable when no supported system Node is available?

Rationale: The code change is small, but it changes the managed-service runtime policy in an area where current docs and audit checks intentionally warn against version-manager Node paths.

Likely owner: steipete

Owner reason: The current system-Node preference and Homebrew stable-path precedent both route through this maintainer’s runtime-selection history.

Owner confidence: high

Options:

- **Support narrow Volta fallback (recommended):** Keep supported system Node first, then normalize Volta tools/image Node paths to an accessible Volta shim with regression tests and live macOS LaunchAgent proof.
- **Keep system Node only:** Reject the Volta fallback and document that managed gateway services should use a supported system/Homebrew Node to clear the warning.
- **Defer to broader runtime pin policy:** Route the Volta request into the broader version-manager runtime-pin decision tracked by the related warning issue instead of landing a Volta-specific fallback first.

## Solution Assessment
