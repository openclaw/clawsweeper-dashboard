## Summary

Keep open: current main and v2026.6.11 still normalize Homebrew Cellar Node paths only, so a supported Volta tools/image executable still falls back to the version-pinned path when no supported system Node is selected first. The remaining question is whether maintainers want to support Volta shim fallback for managed services despite the current docs warning on version-manager service runtimes.

## What This Changes

The issue requests macOS gateway LaunchAgent generation to prefer the stable Volta shim path over a version-pinned Volta tools/image Node executable.

## Best Possible Solution

Decide the daemon runtime policy first, then either land a focused resolver-level Volta shim fallback with macOS service proof or document that supported system Node remains the only supported stable service runtime.

## Reproduction Assessment

No live high-confidence macOS LaunchAgent reproduction was run. Source inspection shows the path clearly: a supported Volta tools/image `process.execPath` falls through the Homebrew-only stable resolver unchanged when no supported system Node wins first.

## Solution Assessment

Unclear. Extending `resolveStableNodePath` is the narrowest code boundary, but maintainers need to confirm whether Volta shim fallback is an accepted service-runtime policy before treating that as the best fix.
