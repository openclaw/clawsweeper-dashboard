## Label Justifications

- `P2`: The issue affects macOS LaunchAgent stability for Volta-managed Node installs, but the blast radius is limited to gateway service runtime path selection.
- `impact:crash-loop`: A LaunchAgent pinned to a removed Volta tools/image Node executable can leave the managed gateway unable to start after a Node upgrade.
- `maturity:stable`: The affected macOS Gateway host surface is `macos-gateway-host`, scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main and v2026.6.11 still return Volta tools/image Node paths unchanged when no supported system Node is selected, so the requested macOS LaunchAgent behavior is not implemented. The remaining question is a product/runtime policy choice, not cleanup-safe closure.

## What This Changes

Request that macOS gateway LaunchAgent generation prefer an accessible Volta shim path over a version-pinned Volta tools/image Node executable.

## Best Possible Solution

Decide the Volta fallback policy first, then either land narrow resolver coverage plus live macOS LaunchAgent proof or document that supported system/Homebrew Node remains the managed-service path.

- **Defer To Broader Runtime Policy:** Hold this issue until the broader version-manager warning/config question in https://github.com/openclaw/openclaw/issues/60612 is decided.
