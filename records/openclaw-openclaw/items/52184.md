## Label Justifications

- `P2`: The issue affects macOS gateway service stability for Volta-managed Node installs but is bounded to daemon install/runtime path selection.
- `impact:crash-loop`: A LaunchAgent pinned to a removed Volta tools/image Node binary can leave the managed gateway unable to start after Node upgrades.
- `maturity:stable`: The affected `macos-gateway-host` surface is scored M4 Stable and explicitly covers shell PATH/version-manager drift plus LaunchAgent service lifecycle.

## Summary

Keep open: current main and the latest release still lack Volta tools/image path normalization, and the remaining work is tied to an open unmerged candidate plus a maintainer product decision about supporting Volta shim fallback for managed services.

## What This Changes

Request to make macOS gateway LaunchAgent generation prefer a stable Volta shim Node path over a version-pinned Volta tools/image Node path.

## Best Possible Solution

Decide the managed-service policy for Volta shim fallback, then either land or replace the narrow resolver-level candidate with tests and live macOS LaunchAgent proof, or explicitly document that system Node remains the only supported repair path.

## Reproduction Assessment

No live high-confidence reproduction was run in this read-only review. Source inspection gives a clear medium-confidence path: a supported Volta tools/image `process.execPath` falls through `resolveStableNodePath` unchanged when no supported system Node is selected first.

## Solution Assessment

Unclear. Extending `resolveStableNodePath` is the narrowest implementation boundary, but maintainers still need to accept or reject Volta shim fallback versus the current documented preference for system Node in managed services.
