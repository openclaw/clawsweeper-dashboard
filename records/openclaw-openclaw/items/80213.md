## Summary

Keep open: current main still lacks a skill-authored `setup.script` metadata contract and automatic install/update setup execution, while the published ClawHub plugin is useful prior art but explicitly manual and admin-invoked.

## What This Changes

Request to add a SKILL.md `setup.script` contract that runs skill-supplied setup scripts after install/update with defined environment and failure semantics.

## Best Possible Solution

Choose one reviewed setup execution boundary, then implement either a core install/update lifecycle hook or a documented external plugin path backed by stable SDK helpers.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw run skill-authored setup scripts automatically during install/update, keep setup as an explicit admin plugin/RPC action, or first settle the installed-skill Plugin SDK helper surface for external setup plugins?

Rationale: Running skill-supplied scripts with selected env values changes the host execution and credential trust boundary, and automation cannot choose the consent, path, env, timeout, logging, ordering, and failure semantics safely.

Likely owner: steipete

Owner reason: The decision crosses skill install metadata, ClawHub install flows, and install security-gate behavior where steipete has the strongest relevant history.

Owner confidence: high

Options:

- **Design core lifecycle hook first (recommended):** Approve a core install/update setup hook only after maintainers define the prompt/consent, script path containment, env sanitizer, timeout, logging/redaction, and failure semantics.
- **Keep explicit plugin RPC:** Treat the ClawHub plugin as the supported manual admin setup path and narrow or reject automatic install/update execution.
- **SDK-first external path:** Prioritize the installed-skill SDK helper issue so external setup plugins can share OpenClaw parsing, path, config, and env behavior before any lifecycle hook lands.

## Reproduction Assessment

Yes at source level: current main lacks a `setup.script` metadata field, parsing for it, post-install/update setup execution, and a core `skills.setup` method.

## Solution Assessment

Unclear until maintainer decision: `setup.script` is plausible, but the permanent boundary could be a core lifecycle hook or an explicit ClawHub plugin path backed by stable SDK helpers.
