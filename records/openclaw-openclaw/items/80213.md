## Summary

Keep open: current main and v2026.6.11 still lack the requested skill-authored `setup.script` metadata contract, automatic post-install/update execution, or a core `skills.setup` method. The published ClawHub plugin is useful prior art, but it is a manual admin RPC and does not replace the lifecycle hook decision.

## What This Changes

Request to add a SKILL.md `metadata.openclaw.setup.script` hook that runs after skill install/update with a defined environment contract.

## Best Possible Solution

Choose one reviewed setup execution boundary: a native install/update lifecycle hook with explicit path/env/timeout/logging semantics, or an external ClawHub plugin path backed by stable SDK helpers and documented operator expectations.

Options:

- **Design native lifecycle hook (recommended):** Add a security-reviewed `setup.script` lifecycle contract for install/update with explicit consent, path containment, timeout ownership, redacted output, and env sanitizer behavior.
- **Use ClawHub plugin path:** Declare the published `skills-setup` plugin plus stable SDK helpers as the supported route, and document that setup is an explicit admin action rather than automatic lifecycle execution.
- **Decline setup execution:** Reject skill-supplied setup execution in OpenClaw and keep wrappers or external operator workflows as the supported pattern.
