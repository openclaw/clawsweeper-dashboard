## Summary

This PR should remain open for maintainer review, but the current blanket exemption is not safe to merge: it changes the established best-effort case from suppressing an unchanged interim acknowledgement while descendants are active to sending it, which can create the duplicate/interim delivery the guard is designed to avoid. The contributor’s trace usefully proves that the new branch reaches outbound delivery; it does not establish that an active-descendant suppression is wrong rather than that stale registry state needs a narrower fix.

## What This Changes

The branch adds `!params.deliveryBestEffort` to the isolated-cron interim-message suppression guard and changes the focused test to expect outbound delivery when descendants are reported active.

## Best Possible Solution

Keep interim suppression for genuinely active descendants, then either repair stale descendant-state detection at its owner boundary or add a narrowly evidenced condition that bypasses suppression only when no current descendant work can still produce the final delivery.
