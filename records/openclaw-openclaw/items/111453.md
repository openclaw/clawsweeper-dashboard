## Summary

This PR is not ready to merge as a bug fix: current main deliberately tests that `deliveryBestEffort` still suppresses stale interim text while descendants are present, while the helper’s contract defines best-effort as tolerating outbound send failures. A maintainer needs to decide whether that existing suppression policy should be widened before changing it.

## What This Changes

The branch adds `!params.deliveryBestEffort` to the stale interim-message suppression guard for isolated cron delivery and reverses the matching regression-test expectation.

## Best Possible Solution

Keep stale-interim suppression as-is unless the cron-delivery owner explicitly expands `deliveryBestEffort` from send-failure tolerance to an instruction to deliver interim control text; if expanded, document the contract and add coverage for both intended delivery and duplicate/noisy-message boundaries.
