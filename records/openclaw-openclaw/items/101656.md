## Summary

Keep open: current main has deterministic task state, on-demand status, and terminal-task delivery machinery, but it still lacks a Telegram-visible detached-subagent liveness contract and the terminal handoff gap is only partly covered by an open candidate PR.

## What This Changes

The issue requests Telegram-visible liveness, status, and terminal-notification behavior for detached subagent work spawned from Telegram-originated turns.

## Best Possible Solution

Define one Telegram-visible detached-subagent contract that reuses the existing task/subagent state source, sends sparse non-sensitive liveness only under an approved policy, and guarantees terminal delivery through the owning Telegram chat/topic.
