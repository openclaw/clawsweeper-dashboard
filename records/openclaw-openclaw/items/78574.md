## Summary

The exact-head implementation is technically sound and well proven: it reuses the existing native-search capability and tool-policy seams, keeps Copilot-specific capability, catalog, and transport behavior inside the plugin, and falls back to managed search when eligibility is absent. The PR remains necessary because current main has no equivalent Copilot native-search path, but merge should wait for a Copilot owner to confirm the intentional automatic default-routing change for eligible existing users.

## What This Changes

The PR queries the Copilot account preview capability during live catalog loading, marks nine verified Responses models for native search, rewrites eligible managed `web_search` function payloads to the native Responses tool, and updates focused tests and web-search documentation.

## Best Possible Solution

Keep capability detection and payload adaptation in the GitHub Copilot plugin, continue using the existing shared native-search and tool-policy contracts, and merge only after a Copilot owner explicitly accepts automatic capability-gated routing as the provider default when no managed provider is pinned.
