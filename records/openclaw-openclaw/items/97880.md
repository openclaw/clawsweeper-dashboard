## Summary

Keep open for maintainer judgment: current main and the latest release keep key-free managed web_search providers explicit, while current main has only partially addressed the report by adding a cron warning when no provider is selected. The linked implementation candidate is still open and reverses a provider-routing/security-boundary policy, so this issue should stay open until maintainers decide that direction.

## What This Changes

The issue requests that enabled keyless DuckDuckGo web_search be auto-selected for cron/tool runs without `tools.web.search.provider`, or at least surface an actionable configuration warning.

## Best Possible Solution

Keep key-free managed web_search providers explicit unless maintainers approve a full policy reversal; if they do, align runtime metadata, setup, docs, tests, and real behavior proof together.
