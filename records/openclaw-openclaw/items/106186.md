## Summary

Keep this issue open because the linked implementation PR remains open and the protected `maintainer` label requires explicit handling. The UX concern is well supported, but current Android documentation makes the Connect tab the canonical pairing surface, so maintainers must resolve that ownership boundary before landing the proposed Settings expansion.

## What This Changes

Make Android gateway pairing easier to discover by consolidating duplicate Settings controls, surfacing QR and setup-code actions, listing discovered gateways, adding diagnostics and facts, and adding deterministic screenshot coverage.

## Best Possible Solution

Keep one canonical Android pairing workflow: either preserve Connect as the owner and make Settings a prominent shared CTA plus status, facts, and diagnostics surface, or deliberately move pairing ownership to Settings while removing the competing Connect implementation and updating documentation and tests.
