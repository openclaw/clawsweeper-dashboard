## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P2] Recompute shared runtime TTL after detach:** `src/agents/agent-bundle-mcp-runtime.ts:1184-1187`
  - body: When a shared runtime has one session with `sessionIdleTtlMs: 0` and another with a finite TTL, detaching the unbounded session returns here while `idleTtlMsByRuntimeKey` stays at `0`. The remaining finite-TTL session then keeps an unbounded runtime until final detach; track TTL per attached session and recompute from the remaining sessions before returning.
  - confidence: 0.88
- **[P2] Redact workspace paths from shared runtime ids:** `src/agents/agent-bundle-mcp-runtime.ts:493-497`
  - body: `buildSharedRuntimeKey` embeds the raw `workspaceDir`, and shared mode passes that key as the runtime `sessionId`, so disposal errors and runtime-session diagnostics can expose local workspace paths and config fingerprints. Use a stable redacted/hash key for the synthetic runtime id while keeping the raw workspace only in internal comparisons.
  - confidence: 0.83
- **[P2] Warn config readers about shared MCP isolation:** `docs/gateway/configuration-reference.md:179-184`
  - body: The primary configuration reference introduces `"shared"` without saying it is for trusted single-tenant deployments or that MCP clients, child processes, catalog state, server-side state, and failure/backoff state can cross sessions. Add that warning here so operators see the isolation boundary before enabling the new config.
  - confidence: 0.85
