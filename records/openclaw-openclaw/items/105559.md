## Summary

Keep open: the reported bug is real, but this implementation can create a `.pre-update` file from already-mutated config after the first attempt fails, and the external PR still lacks real update-flow proof.

## What This Changes

The PR records pre-update snapshot completion only after a successful backup write and adds a test that retries after a transient read failure.

## Best Possible Solution

Use once-on-success per-path coordination with bounded immediate read retries and retained first-read bytes for write retries, ensuring `.pre-update` always represents the original pre-mutation config.

## Reproduction Assessment

Yes. Current main marks the path before caught I/O, so a second same-process call deterministically skips after the first failure; the PR's remaining failure follows by modifying config between its failed and successful calls.

## Solution Assessment

No. Success-only marking restores retries, but rereading during a later update phase does not preserve the original pre-update state after intervening mutations.
