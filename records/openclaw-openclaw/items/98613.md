## Summary

Keep open: this PR fixes a real public SDK parser edge case that current main still has. I found no code-level defect in the patch, but the exported SDK behavior change, test-only proof, and one unrelated failing CI shard still need normal maintainer handling before merge.

## What This Changes

The branch wraps `parseFfprobeVideoDimensions` JSON parsing in a try/catch so malformed ffprobe stdout returns `undefined`, with a regression test for malformed JSON.

## Best Possible Solution

Land the narrow parser guard after maintainer acceptance of the SDK contract, direct runtime proof from the contributor, and green required checks, while keeping the existing SDK export path unchanged.

## Reproduction Assessment

Yes from source: current main calls `JSON.parse(stdout)` in `parseFfprobeVideoDimensions` without a guard, so malformed JSON will throw before returning `undefined`. I did not execute the function locally in this read-only review, so this is source-reproducible rather than tool-reproduced.

## Solution Assessment

Yes, the parser boundary is the right layer because direct SDK callers otherwise have to duplicate the fallback that `probeVideoDimensions` already owns. A broader caller-side try/catch would leave the exported helper surprising and inconsistent.
