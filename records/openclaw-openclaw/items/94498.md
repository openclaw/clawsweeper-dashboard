## What This Changes

The PR reorders `secrets apply` writes so provider additions commit first, satellite/auth-store writes commit next, and the final config write with target migrations/provider deletes commits last.

## Best Possible Solution

Land this dependency-ordered mitigation after `openclaw-secops` accepts the residual fault windows, or replace it with a broader journaled transaction design if owners require true cross-store atomicity.

## Reproduction Assessment

Yes. Current main commits config before satellite/auth-store writes and then uses best-effort rollback, matching the injected write-fault split state; the PR body supplies before/after live output for the central SQLite auth-store fault.

## Solution Assessment

Yes, with owner acceptance. The dependency-ordered mitigation is narrower than a cross-store journal, and the branch addresses provider-upsert, provider-delete, and config-CAS edge cases surfaced during review.
