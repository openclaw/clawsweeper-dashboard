## Summary

Keep open: this PR is still the active candidate fix for the linked secrets-apply half-migration bug, and current main still has the config-first commit path. I found no discrete blocking code defect in the current branch, but merge still needs secops/maintainer acceptance because the patch intentionally changes credential persistence behavior during write faults.

## What This Changes

This PR reorders `secrets apply` commits so provider additions persist before auth-store writes, satellite/auth-store artifacts commit next, and the full config write lands last, with regression coverage for write-fault ordering and config CAS behavior.

## Best Possible Solution

Land this dependency-ordered mitigation after `openclaw-secops` accepts the residual fault windows, or replace it with a broader journaled transaction design if owners require true cross-store atomicity.

## Reproduction Assessment

Yes. Current main source shows config commits before later auth/env/auth-store writes with best-effort rollback only, and the PR body supplies before/after live Node 24 output for the central SQLite auth-store fault path.

## Solution Assessment

Yes, with owner acceptance. The dependency-ordered mitigation is narrower than a cross-store journal and the branch covers provider-upsert, provider-delete, and config-CAS edge cases; true crash atomicity would be a larger design.
