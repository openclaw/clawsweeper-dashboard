## What This Changes

The PR changes the tools-manager fd/ripgrep GitHub latest-release lookup to use `readResponseWithLimit`, validate `tag_name`, surface silent download failures, and add focused regression tests.

## Best Possible Solution

Land one canonical bounded-read fix for tools-manager after maintainer acceptance of the 1 MiB fail-closed policy, then close or supersede the overlapping open PR.

## Reproduction Assessment

Yes from source: current `getLatestVersion` calls `response.json()` on GitHub release metadata, so an oversized streamed body can be buffered before parsing. I did not run local tests because this review is read-only, but the PR body and added tests exercise the `ensureTool` path.

## Solution Assessment

Yes, if maintainers accept the cap: putting `readResponseWithLimit` at the `getLatestVersion` owner boundary is narrower than a global response policy and avoids a header-only check that would miss chunked bodies. The compatibility choice is the 1 MiB fail-closed threshold and silent-caller error surfacing.
