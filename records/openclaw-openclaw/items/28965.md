## Summary

Keep open: current main and v2026.6.11 still lack the requested `openclaw models reconcile` and bulk `openclaw sessions model-reset` surfaces. Current main has narrower pieces, including `models set`, `/model default`, `sessions.reset`, status hints for pinned sessions, and doctor cleanup for auto-created stale route state, but the broader reconcile/reset workflow remains compatibility-sensitive product work.

## What This Changes

The issue proposes a single-source model configuration reconcile command, a bulk session model override reset command, and clearer model-source observability.

## Best Possible Solution

Keep this as an umbrella product/design item until maintainers choose a source-aware resolver and reconcile/reset contract that preserves intentional pins, makes shadowing visible, and aligns CLI, doctor, status, session, provider, and registry behavior.

## Reproduction Assessment

Not applicable as a strict bug reproduction: this is a proposal for new reconcile/reset CLI surfaces and product semantics. Source inspection does confirm the current layered state and the absence of the requested bulk commands on current main.

## Solution Assessment

Unclear as a final implementation: the requested commands are plausible, but the safest solution is likely a maintainer-approved shared resolver plus explicit scoped reset/reconcile behavior rather than a broad hidden precedence flip.
