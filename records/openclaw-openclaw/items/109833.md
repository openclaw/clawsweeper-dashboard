## Summary

Keep this issue open: it provides a concrete upgrade regression and deterministic filesystem reproduction, while the plugin-specific EACCES classification and readiness policy remain distinct from the related migration and teardown reports.

## What This Changes

Correct startup handling when an unreadable optional plugin package is reported as a migration failure and prevents gateway readiness.

## Best Possible Solution

Treat payload validation as a plugin-readiness result: fail closed with a direct permission diagnosis only for configured or required plugins, quarantine unused failing plugins with a loud warning, and expose a Doctor/Fix surface that detects ownership problems and presents a safe recovery action.
