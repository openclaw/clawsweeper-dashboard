## Summary

Keep this PR open: it correctly targets a real MCP probe gap, but the new probe-only default overrides the documented `connectTimeout` alias, so the promised operator timeout is still not honored. The protected `maintainer` label also requires explicit maintainer handling.

## What This Changes

The PR bounds MCP initialization during CLI probing, applies a probe-time default timeout, and adds CLI/runtime regression coverage for timeout and MCP-result truncation behavior.

## Best Possible Solution

Recognize both `connectionTimeoutMs` and `connectTimeout` before adding the 5-second probe default, then retain a focused regression assertion that a hung initialization with `--connect-timeout 2` fails near two seconds without changing the persisted config.
