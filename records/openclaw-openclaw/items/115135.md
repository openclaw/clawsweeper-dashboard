## Summary

The IPv6 reconstruction defect remains on current `main`, and this is a narrow, apparently correct repair. The patch preserves the existing forwarding-trust decision while separating canonical host comparison from URL-authority formatting; however, an external PR still needs redacted after-fix behavior evidence from a running Voice Call webhook setup before merge.

## What This Changes

The PR validates bracketed IPv6 webhook hosts, canonicalizes them for allowlist checks, and restores brackets when reconstructing the URL used for provider signature verification.

## System Context

Voice Call receives webhook requests from telephony providers and reconstructs the public request URL before validating Twilio or Plivo signatures. Trusted direct or forwarded Host headers feed hostname validation and allowlist comparison, then the reconstructed URL feeds signature and replay handling.

## Best Possible Solution

Keep the small normalization/serialization split, retain the existing forwarding-trust policy, and add redacted live runtime evidence that a configured Voice Call webhook reconstructs and verifies a bracketed IPv6 public URL without changing fallback behavior.
