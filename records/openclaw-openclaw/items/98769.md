## Summary

Keep open. The patch is focused and has real Telegram proof for the streamed-preview final path, but it does not yet cover supported durable/non-preview Telegram sends, so the linked context-duplication bug can still remain for `streamMode: "off"` or other `send.ts` paths.

## What This Changes

The PR carries the current assistant transcript timestamp through Telegram streamed-final outbound prompt-context cache entries and teaches the message cache to prefer that timestamp for prompt-context ordering and dedupe.

## Best Possible Solution

Align outbound prompt-context timestamps with the matching assistant transcript row for every Telegram assistant final that can also appear in direct-session transcript context, with focused coverage for both default streaming and `streamMode: "off"`.

## Reproduction Assessment

Yes, at source level. Current main combines session transcript rows with Telegram cache rows and dedupes them by exact `timestamp_ms` plus body while outbound cache rows use delivery/cache time.

## Solution Assessment

No. The PR is the right narrow shape for streamed preview-finalized replies, but it is incomplete while durable Telegram send paths keep recording cache-time timestamps.
