## Summary

This PR fixes the Matrix case-distinct DM collision, but its final `@`-label workaround silently rewrites already-valid `session.identityLinks` canonical labels and can merge them with a separate `person` label. The privacy-sensitive session-key repair needs a collision-safe identity-link representation or explicit migration decision before merge. Likely related people: `lukeboyett` (high confidence, prior session-key registry work) and `fuller-stack-dev` (medium confidence, recent reviewer of this contract).

## What This Changes

The branch preserves Matrix MXID case for channel-bearing DM session keys, strengthens folded legacy-alias checks, and strips leading `@` characters from identity-link canonical labels before constructing DM keys.

## Best Possible Solution

Keep native-MXID provenance distinct from opaque identity-link labels without lossy rewriting, then add upgrade coverage proving that all previously accepted canonical labels retain separate sessions or are migrated explicitly and safely.
