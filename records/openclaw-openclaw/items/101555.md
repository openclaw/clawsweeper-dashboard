## Summary

Current main and the latest release already handle the reported malformed credential parsing path: the cited `JSON.parse(payloadRaw)` is inside a catch block, malformed JSON credential files are loaded through a tolerant helper, and callers treat missing external CLI credentials as absence rather than an unhandled startup exception.

## What This Changes

The issue reports that malformed credential JSON can throw during agent startup instead of being handled as a recoverable credential-cache corruption case.

## Best Possible Solution

Keep the shipped tolerant credential parsing behavior; if a different credential store still crashes on malformed JSON, open a new focused report with the exact file, command, version, and stack trace.
