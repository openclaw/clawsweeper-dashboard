## Summary

Keep this open: current main has in-process followup queues, queued-turn cancellation state, provider cooldowns, and quota-suspension metadata, but not the durable provider-capacity prompt queue with visible waiting and automatic replay requested here.

## What This Changes

Queue prompts when API limits prevent all configured models from responding, make the waiting state visible, and resume the prompt once capacity returns.

## Best Possible Solution

Adopt a maintainer-approved SQLite-backed capacity-wait queue that stores pending prompt/run intent, integrates with provider cooldown timing, exposes a waiting state, and replays exactly once when capacity returns.
