## Summary

Keep open: current main has process-local followup queues plus provider cooldown/session suspension, but it still does not provide a durable capacity-wait prompt queue with visible waiting state and automatic replay after all usable models are API-limited. Related PRs are open partial slices, not merged canonical fixes.

## What This Changes

The issue asks OpenClaw to preserve prompts that cannot run because provider/API limits exhausted all usable models, show them as waiting, and resume them automatically when capacity returns.

## Best Possible Solution

Design a SQLite-backed capacity-wait queue integrated with provider cooldown/retry metadata, visible waiting status, and exactly-once replay; land or replace related PR slices only when they fit that design.

## Reproduction Assessment

Source inspection gives a medium-confidence reproduction path: exhaust all fallback candidates through rate-limit/cooldown handling and current main returns cooldown guidance or session suspension rather than persisting the prompt for replay. No live provider-limit reproduction was run in this read-only review.

## Solution Assessment

Unclear pending maintainer design. A durable capacity-wait queue is the right direction, but the best solution should be SQLite-backed and integrated with provider cooldowns/status rather than a JSONL sidecar or isolated cooldown tweak.
