## Summary

Current main still lacks the durable capacity-wait prompt queue requested here, while the related open PRs cover narrower followup-restart or provider-cooldown slices. This should stay open as the canonical maintainer design item for preserving and replaying provider-limit-blocked work.

## What This Changes

The issue requests queueing, visible waiting state, and automatic replay for prompts that cannot run immediately because all current and fallback models are API-limited.

## Best Possible Solution

Adopt a maintainer-approved SQLite-backed capacity-wait queue that stores pending prompt/run intent, integrates with provider cooldown timing, exposes waiting state, and replays exactly once when capacity returns.
