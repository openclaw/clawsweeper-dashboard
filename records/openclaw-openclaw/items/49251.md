## Summary

Keep open: current main has in-process follow-up queues, short same-model retries, and persisted provider/session suspension, but it still lacks the central durable capacity-wait prompt queue with visible waiting state and automatic prompt replay once provider capacity returns.

## What This Changes

Request durable queuing, visible waiting status, and automatic resume for prompts blocked after current and fallback providers or models cannot respond.

## Best Possible Solution

Define one core-owned SQLite-backed capacity queue that connects provider cooldown/session suspension to message replay and user-visible waiting status, then converge or close the partial PRs against that design.
