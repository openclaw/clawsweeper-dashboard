## Summary

Keep this open: current main has in-process followup queueing, bounded rate-limit retry/fallback, and quota suspension, but not the requested durable capacity-wait prompt queue with visible waiting state and automatic replay after provider capacity returns.

## What This Changes

The issue asks OpenClaw to queue API-limit-blocked prompts, show them as waiting, and automatically resume them once provider capacity returns.

## Best Possible Solution

Design one core-owned SQLite-backed capacity-wait queue that coordinates provider cooldown/session suspension, visible waiting status, restart recovery, and exactly-once replay, then converge or close the partial PRs against that design.
