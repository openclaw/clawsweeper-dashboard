## Summary

Keep this open: current main still has process-local follow-up queueing plus bounded provider cooldown/fallback/error-surfacing paths, but not the requested durable capacity-wait prompt queue with visible waiting state and automatic replay after provider capacity returns.

## What This Changes

Requested behavior: preserve prompts when provider/API limits prevent an immediate response, show that they are waiting, and resume them automatically when capacity returns.

## Best Possible Solution

Design one core-owned SQLite-backed capacity-wait queue that coordinates provider cooldown/session suspension, visible waiting status, restart recovery, and exactly-once replay, then converge or close the partial PRs against that design.
