## Summary

Keep open: current main has model fallback, cooldown summaries, and session suspension metadata, but it still does not persist a blocked prompt as a visible capacity-wait queue item that can replay automatically after all usable models are API-limited. The overlapping PRs are open partial slices rather than merged canonical fixes.

## What This Changes

The issue requests durable queuing, user-visible waiting state, and automatic resume for prompts that cannot run immediately because all usable models are API-limited.

## Best Possible Solution

Design one SQLite-backed capacity-wait queue integrated with provider cooldown metadata, visible waiting status, and exactly-once replay, then land or replace related PR slices only when they fit that unified design.
