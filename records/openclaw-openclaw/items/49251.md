## Summary

Keep this open: current main has provider cooldown, quota-suspension, queued-turn identity, and SQLite-backed session-delivery recovery, but it still does not implement the durable provider-capacity prompt queue requested here. The issue remains the canonical product/storage design item rather than something the adjacent unmerged PRs or current restart-continuation queue fully solve.

## What This Changes

Request to keep prompts queued, visible, and automatically resumed when provider/API limits prevent current or fallback models from responding.

## Best Possible Solution

Design a maintainer-approved SQLite-backed capacity-wait queue that stores pending prompt/run intent, integrates with provider cooldown and retry timing, exposes a clear waiting state, and replays exactly once after capacity returns.
