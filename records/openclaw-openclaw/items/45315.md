- **[P1] Carry prefix context into routed abort delivery:** `src/channels/reply-prefix.ts:51-56`
  - body: The added pre-seeded context only reaches dispatcher normalization, but the fast-abort path first calls `routeReplyToOriginating()` when an originating route is present. `routeReply()` resolves `responsePrefix` and normalizes without any `responsePrefixContext`, so routed abort replies can still leak raw `{model}` or `{thinkingLevel}` tokens; thread the context into routed delivery and add a routed-abort regression test.
  - confidence: 0.87
- **[P2] Derive abort prefixes from active model state:** `src/channels/reply-prefix.ts:44-56`
  - body: These defaults come from `resolveDefaultModelForAgent()`, while normal turns can use session `/model` overrides, `channels.modelByChannel`, fallback runtime state, and runtime catalog thinking defaults before `onModelSelected()` fires. Fast abort skips that callback, so this can display a config-default model or thinking value instead of the actual selected value.
  - confidence: 0.84
