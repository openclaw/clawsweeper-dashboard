## Summary

Keep open: this fixes a real early-abort responsePrefix placeholder bug, but the current head still leaves routed abort delivery without prefix context and seeds abort prefixes from config defaults instead of active session/channel/catalog model state.

## What This Changes

The branch pre-seeds `createReplyPrefixContext` with config-default provider/model/thinking values and adds tests for default seeding plus runtime overwrite behavior.

## Best Possible Solution

Carry a populated response-prefix context through both direct and routed fast-abort delivery, deriving model/thinking from active session, channel, and catalog state where available and falling back to config defaults only last.

## Reproduction Assessment

Yes. Source inspection shows a templated `messages.responsePrefix` can be normalized during fast abort before the normal model-selection callback supplies provider/model/thinking context, and missing context leaves template tokens literal.

## Solution Assessment

No. Pre-seeding config defaults is a useful fallback, but the maintainable fix should also pass prefix context through routed abort delivery and use active session/channel/catalog model state where available.
