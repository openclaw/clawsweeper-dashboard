## Summary

Keep open: the patch improves the basic abort reply path, but the same PR head still misses routed abort delivery and active session/channel/catalog model state, so it can still produce raw or stale responsePrefix values in real configured flows.

## What This Changes

The branch pre-seeds reply-prefix context with config-default provider, model, and thinking values and adds tests for default seeding plus runtime overwrite behavior.

## Best Possible Solution

Carry a populated response-prefix context through both direct and routed fast-abort delivery, deriving model/thinking from active session, channel, and catalog state when available and using config defaults only as fallback.

## Reproduction Assessment

Yes. Source inspection shows a templated messages.responsePrefix can be normalized during fast abort before the normal model-selection callback supplies provider/model/thinking context, and missing context leaves template tokens literal.

## Solution Assessment

No. Pre-seeding config defaults is a useful fallback, but the maintainable fix should also pass prefix context through routed abort delivery and use active session/channel/catalog model state where available.
