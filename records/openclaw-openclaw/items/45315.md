## Summary

Keep open: the PR is a useful candidate for the linked abort-prefix bug, but the current patch only seeds config-default prefix context and still misses routed abort delivery plus active session/channel model state.

## What This Changes

The PR pre-seeds reply-prefix context with default provider, model, and thinking values so early abort replies do not show raw responsePrefix template placeholders.

## Best Possible Solution

Carry a populated response-prefix context through both direct and routed fast-abort delivery, deriving model/thinking from active session, channel, and catalog state where available and using config defaults only as fallback.

## Reproduction Assessment

Yes. Source inspection shows `tryFastAbortFromMessage` can format and send an abort payload before the normal model-selection callback populates prefix context, and the template resolver leaves missing `{model}` or `{thinkingLevel}` values literal.

## Solution Assessment

No. Pre-seeding config defaults is a useful fallback, but the best fix should also pass prefix context through routed abort delivery and use active session/channel/catalog model state where available.
