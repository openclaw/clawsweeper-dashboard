No: pre-seeding config defaults is only a plausible mitigation. The maintainable fix needs active prefix context from the same state normal model selection uses, and it must carry that context into routed abort delivery too.

Full review comments:

- **[P1] Carry prefix context into routed abort delivery:** `src/channels/reply-prefix.ts:44`
  - body: `createReplyPrefixContext` only feeds the dispatcher path, but the fast-abort branch routes cross-surface replies through `routeReply` directly, and PR-head `routeReply` calls `normalizeReplyPayload` with `responsePrefix` but no `responsePrefixContext`. A `/stop` reply routed back to WhatsApp or Telegram can still prepend `{model} - {thinkingLevel}` literally, so the fix needs to pass populated context through routed abort delivery or normalize with it before routing.
  - confidence: 0.91
- **[P2] Seed abort prefixes from active model state:** `src/channels/reply-prefix.ts:44-49`
  - body: The new seed uses config defaults via `resolveDefaultModelForAgent`, but normal reply selection can use session `/model` overrides, parent-session overrides, and `channels.modelByChannel` before firing `onModelSelected`. Because fast abort returns before that callback, abort replies after a model switch or channel override will show the default model/thinking instead of the active run state; derive the seed from session/channel/runtime state where available and cover that path.
  - confidence: 0.88
