Full review comments:

- **[P1] Carry prefix context into routed abort delivery:** `src/channels/reply-prefix.ts:51-56`
  - body: The new seed only helps callers that normalize through the dispatcher. Fast abort first calls `routeReplyToOriginating(payload)` when an originating channel is set, and `routeReply()` resolves `responsePrefix` without any `responsePrefixContext`, so routed abort replies can still deliver `{model}` or `{thinkingLevel}` literally. This remains from the prior review cycle at this head.
  - confidence: 0.9
- **[P2] Seed abort prefixes from active model state:** `src/channels/reply-prefix.ts:44-56`
  - body: This seeds `{model}` and `{thinkingLevel}` from config defaults, but normal reply selection honors stored session overrides and `channels.modelByChannel` before the run. Because fast abort returns before that selection and before `onModelSelected`, sessions that switched models can get stale default model/thinking text in abort replies. This remains from the prior review cycle at this head.
  - confidence: 0.88
