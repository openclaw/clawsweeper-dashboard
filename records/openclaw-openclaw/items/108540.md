## Summary

The revised head resolves the prior hidden-message finding by separating an explicit acknowledgment, but it still suppresses that acknowledgment in the reported spawn-and-yield case and exposes an inconsistent contract to Copilot. This PR also provides only mocked/harness evidence, while the competing implementation’s live gateway proof demonstrates the accepted-spawn guard problem.

## What This Changes

The PR adds an optional `sessions_yield.acknowledgment` tool field, carries it through the embedded and Codex attempt results, and synthesizes a reply for otherwise empty eligible turns.

## Best Possible Solution

Keep `message` as hidden continuation context, consistently support an explicit acknowledgment across every harness that advertises it, and gate delivery only on genuinely user-visible output rather than accepted spawn or cron side effects.
