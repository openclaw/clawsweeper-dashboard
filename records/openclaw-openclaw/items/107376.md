## Summary

Keep this PR open for an IRC owner decision: the memory bound is well-supported, but making every oversized record a fatal disconnect changes interoperability and may turn a hostile or incompatible server into a supervised reconnect loop.

## What This Changes

Adds UTF-8 byte-length enforcement for complete and pending inbound IRC records, closes the socket on a 512-byte limit violation, and adds real TCP boundary and rejection coverage.

## Best Possible Solution

Adopt an IRC-owner-approved framing policy that always bounds pending memory, explicitly defines IRCv3 tag limits, and proves that fatal protocol violations cannot create an uncontrolled reconnect cycle.
