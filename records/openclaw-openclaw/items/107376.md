## Summary

The parser hardening is technically sound and well proven, with no actionable code defect found, but an IRC owner should confirm whether a protocol-limit violation must trigger supervised reconnect, terminal disconnection, or another recovery policy before merge.

## What This Changes

The PR rejects complete or pending IRC records exceeding the 512-byte wire limit, closes the socket, and adds real TCP boundary, fragmentation, and UTF-8 regression coverage.

## Best Possible Solution

Keep the byte-bounded fail-close parser, but pair it with a documented and tested supervised reconnect/backoff path plus a visible unhealthy status when the same server repeatedly violates the limit.
