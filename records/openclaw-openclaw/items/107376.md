## Summary

This is a necessary, well-proven IRC memory-safety fix with no discrete blocking code defect found. It still needs an IRC owner to choose the post-violation recovery contract because the new fail-closed path can leave a previously ready account disconnected without an explicit lifecycle recovery path.

## What This Changes

Adds 512-byte inbound IRC record limits for complete and pending lines, closes the socket on violations, and adds real TCP boundary, fragmentation, and UTF-8 regression coverage.

## Best Possible Solution

Keep the pre-parse memory bound, but make the selected violation policy complete: either discard oversized records with bounded state or surface socket termination to the account supervisor with tested status, reconnect, and backoff behavior.
