## Summary

Keep this PR open for IRC owner review. The memory-exhaustion fix and real TCP proof are strong, but the proposed fatal 512-byte whole-line policy remains compatibility- and availability-sensitive because IRCv3 permits a separate 8,191-byte message-tag section while retaining the 512-byte limit for the rest of the message. ([ircv3.net](https://ircv3.net/specs/extensions/message-tags.html?utm_source=openai))

## What This Changes

Adds UTF-8 byte-length enforcement for complete and pending inbound IRC records, closes the socket on a limit violation, and adds real TCP boundary and rejection coverage.

## Best Possible Solution

Bound inbound buffering with protocol-aware limits, preserve valid IRCv3 tagged records when supported, and define a tested overflow policy that cannot create an uncontrolled reconnect loop.
