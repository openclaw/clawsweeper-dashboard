## Summary

Keep this PR open: it makes a narrow, source-consistent repair for the restart-orphaned session claim described in the linked report, but the external contribution still needs redacted real gateway/channel restart evidence before merge.

## What This Changes

The branch lets a persisted `running` session claim be adopted after a gateway restart when no reply run is live in the new process, and adds a focused regression test.

## System Context

Channel messages enter auto-reply turn admission, which reads the persisted session entry and its restart-recovery delivery claim before starting a reply. The in-memory reply-run registry distinguishes a genuinely active run from a stale claim left by a previous gateway process.
