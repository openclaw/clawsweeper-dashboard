## Summary

Keep open: current main fixed the companion CLI recovery path, but Slack DM text recovery commands still appear to separate open-DM admission from command authorization and can leave `/compact`, `/new`, and `/stop` without execution or a visible recovery response.

## What This Changes

The issue asks Slack DMs to execute or visibly reject text `/compact`, `/new`, and `/stop` recovery commands instead of leaving them inert as user text or silent no-op turns.

## Best Possible Solution

Choose the Slack DM command authorization boundary, then make `/compact`, `/new`, and `/stop` either execute for authorized Slack DM senders or return a visible in-channel denial/recovery path, with focused Slack tests and live Slack proof.
