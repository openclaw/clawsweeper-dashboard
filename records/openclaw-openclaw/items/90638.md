## Summary

Keep open: the CLI recovery gap was fixed by the merged sessions compact PR, but the Slack DM slash-command path still lacks source or live proof that `/compact`, `/new`, and `/stop` execute with visible replies under the reported Slack setup. Current source still separates open DM admission from command authorization, so the remaining work needs a maintainer decision on Slack DM command authority before repair.

## What This Changes

The issue asks for Slack DM text slash commands such as `/compact`, `/new`, and `/stop` to be handled as recovery/control commands instead of being silently sent to the agent or ignored.

## Best Possible Solution

Choose and document the Slack DM command-authorization boundary, then make authorized Slack DM text recovery commands execute with visible replies and unauthorized ones visibly deny, with focused Slack plugin tests and live Slack proof.

Options:

- **Owner-only with visible denial (recommended):** Keep recovery commands restricted to command-authorized senders and send a clear Slack reply when an admitted DM sender tries an unauthorized recovery command.
- **Admitted DM recovery commands:** Allow admitted Slack DM senders to run a narrow set of session recovery commands while keeping broader owner-only commands restricted.
- **Redirect Slack text commands:** Disable Slack DM text recovery command execution and reply with the supported native command or CLI recovery path.
