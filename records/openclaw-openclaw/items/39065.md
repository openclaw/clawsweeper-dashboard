  - body: `buildPairingReply` is exported through the plugin runtime/API surfaces, so changing it from always returning text to returning `null` makes existing plugin callers responsible for a new nullable contract.   - body: This adds `unpairedResponse` to Discord's public config type, but the strict Discord schema owner does not accept the field, and the same split appears in sibling channel config owners.   - confidence: 0.9
- **[P2] Honor silent mode for pending Discord pairings:** `src/discord/monitor/agent-components.ts:531-539`
  - body: The component path applies `unpairedResponse` only when a pairing row is first created, then sends the hardcoded pending-pairing reply when `created` is false. A user who already requested pairing still gets a reply in `silent` mode, so the suppression guarantee depends on which Discord DM surface they hit.
  - confidence: 0.86
