- **[P1] Keep suppression out of the exported formatter:** `src/pairing/pairing-messages.ts:10`
  - body: `buildPairingReply` is exported through plugin runtime surfaces, so changing it to return `null` makes existing plugin callers handle a new nullable contract or accidentally pass non-text into send APIs. Keep the formatter string-returning and put the silent decision in the challenge/send owner, or explicitly version the SDK contract with compatibility tests.
  - confidence: 0.9
- **[P1] Wire advertised config through strict schemas:** `src/config/types.discord.ts:224`
  - body: This adds `unpairedResponse` to public config types/help, but branch grep shows strict schemas for Discord, Slack, and LINE do not accept the key, and IRC/BlueBubbles still have plugin-local schemas without it. Operators can configure an advertised key and then fail validation/startup instead of getting the new behavior.
  - confidence: 0.91
- **[P1] Pass the response mode into plugin pairing replies:** `extensions/irc/src/inbound.ts:217-221`
  - body: IRC and BlueBubbles guard the nullable reply, but they still call `buildPairingReply` without passing the configured mode, so `silent` and `code-only` would be ignored and the branded reply would still be sent. Either wire the mode through those account configs or stop advertising the option for those channels.
  - confidence: 0.88
- **[P2] Honor silent mode for pending Discord pairings:** `src/discord/monitor/agent-components.ts:533-540`
  - body: The `created === false` branch still sends the hardcoded pending-pairing text, so a sender who already has a pending pairing request receives a reply even when `unpairedResponse` is `silent`. Gate that fallback on the same response mode or route the component path through the shared Discord DM decision helper.
  - confidence: 0.91
- **[P3] Record outbound activity only after sending:** `extensions/nextcloud-talk/src/inbound.ts:187-192`
  - body: `statusSink` is updated even when `replyText` is empty in silent mode, so Nextcloud-Talk can report outbound activity without sending a message. Move the status update inside the send guard, matching the Google Chat path.
