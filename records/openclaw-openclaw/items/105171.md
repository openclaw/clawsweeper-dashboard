## Summary

Keep open for a provider-runtime decision: the indefinite-hang bug is valid and the implementation is well-proven, but the proposed batch deadline conflicts with the provider’s existing 10-minute inline batch budget and could break slow self-hosted endpoints.

## What This Changes

The PR adds 60-second query and 120-second batch transport timeouts for OpenAI-compatible embedding requests without a caller AbortSignal, preserves caller-provided signals, and adds hung-socket regression coverage.

## Best Possible Solution

Keep the guarded-fetch transport backstop, but have the provider owner choose and centralize one canonical query/batch timeout contract; preserve the existing 10-minute batch allowance unless maintainers explicitly approve and document a shorter upgrade behavior.
