## Summary

Keep this PR open for a maintainer compatibility decision. The implementation is coherent and has convincing real-runtime proof, but it turns previously unbounded OpenAI-compatible requests into hard 60-second and 120-second failures; existing reports that 120 seconds can be too short for local embedding workloads make the exact cutoff an upgrade-sensitive policy choice. citeturn22search0

## What This Changes

The PR adds 60-second query and 120-second batch fallback timeouts to unsignaled OpenAI-compatible embedding requests, preserves caller-provided abort signals, and adds hung-server regression coverage.

## Best Possible Solution

Use one shared fallback timeout for truly unsignaled transport calls, but ship it only after a provider owner approves query and batch ceilings against slow self-hosted workloads; preserve caller-owned signals and avoid adding configuration unless existing operation policy cannot safely cover those workloads.
