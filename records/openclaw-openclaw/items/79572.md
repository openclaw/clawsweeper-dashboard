## Summary

Keep this PR open: current `main` and `v2026.6.11` still send Google realtime voice tool schemas as `parametersJsonSchema`, while this branch has a narrow fix plus real Google Live logs showing the reported consult-tool failure is addressed. The remaining blocker is maintainer compatibility signoff because the field switch affects every Google realtime voice tool declaration, including custom `realtime.tools`.

## What This Changes

This PR changes Google realtime voice FunctionDeclarations to send tool schemas in `parameters` instead of `parametersJsonSchema` and updates the provider unit assertion.

## Best Possible Solution

Land the narrow Google realtime field switch after maintainer compatibility signoff, or fold it into the active Google schema-hardening work if maintainers want stronger custom-tool normalization first.
