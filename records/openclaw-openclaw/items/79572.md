## Label Justifications

- `P1`: The PR fixes a broken Google Live realtime tool-calling path where consult calls can fail and leave voice callers without a tool-backed answer.
- `merge-risk: 🚨 compatibility`: The diff changes the schema field sent for every Google realtime voice tool, including custom configured tools, so provider-side schema interpretation can change on upgrade.

## Summary

Keep this PR open: current main and the latest release still send Google realtime voice tool schemas as `parametersJsonSchema`, while the PR supplies focused code, test coverage, and live log proof for switching the Google Live path to `parameters`. The remaining blocker is maintainer acceptance of the compatibility risk for custom realtime tools, not a concrete patch defect.

## What This Changes

The PR changes Google Gemini Live realtime voice FunctionDeclarations to send tool schemas via `parameters` instead of `parametersJsonSchema`, with matching test expectations.

## Best Possible Solution

Land the narrow Google realtime field switch after maintainer compatibility signoff, or intentionally fold this behavior into a broader Google schema-normalization PR that also fixes the preview native-audio Live path.

## Reproduction Assessment

Yes. Current main sends Google realtime voice tool declarations through `parametersJsonSchema`, and the PR body provides live before/after logs where the preview native-audio model used invented argument names before the patch and the declared `question` field after it.

## Solution Assessment

Yes, with maintainer compatibility signoff. The patch changes the Google provider translation point that builds `LiveConnectConfig`; broader schema normalization is only preferable if maintainers want to reduce custom-tool upgrade risk first.
