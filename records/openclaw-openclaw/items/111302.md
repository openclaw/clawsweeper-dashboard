- `merge-risk: 🚨 message-delivery`: Moving the terminal-state reset changes whether a post-close Feishu final is dropped or rendered as a new card.

## Summary

Keep this PR open: resetting the closed-streaming flags on every `onReplyStart` reopens the terminal state during the repeated reply-start keepalives that the existing lifecycle guard intentionally preserves, so a stale late final can again create a second Feishu card.

## What This Changes

The PR resets Feishu streaming-card closed-state flags at each reply start and adds a regression test for delivering a recovered final after an error card closes.

## Best Possible Solution

Preserve closed-card suppression for the whole reply lifecycle and add a distinct, owner-defined boundary for a genuinely recovered reply run; reset the flags only at that boundary, with coverage for both a recovered second card and a post-close keepalive that must still suppress a late final.

## Solution Assessment
