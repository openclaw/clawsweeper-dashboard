## Summary

Keep this PR open: the runtime change is a plausible narrow repair for the Feishu answer-delivery bug, but its new regression test does not model the production close result and therefore does not exercise the suppressed-final branch; the live evidence also does not reproduce the exact close-then-recovery sequence.

## What This Changes

The PR resets Feishu streaming-card closed-state flags on every reply start and adds a test for delivering a recovered final answer after a tool-failure card close.

## Best Possible Solution

Keep the per-reply reset limited to the two terminal streaming flags, correct the regression double so a visible close returns true, and add redacted proof of the exact error-close → new reply start → recovered final sequence.
