## Label Justifications

- `P1`: The issue describes repeated unexpected compaction in real subagent-heavy workflows, affecting active session continuity, auditability, and cost.
- `impact:session-state`: The affected behavior is yielded-parent branch state, context accounting, and compaction placement in session transcripts.

## Summary

Keep open: current main includes a partial context-usage fix from #99864, but the successful-turn overflow path still trusts raw `input + cacheRead` when no `contextUsage` snapshot exists, OpenAI-compatible providers still emit usage without `contextUsage`, and compaction records still cannot persist the requested trigger/cause metadata.

## What This Changes

The issue requests that `sessions_yield`/subagent wake handling stop compacting parent branches at low real context usage and persist a compaction trigger reason for future triage.

## Best Possible Solution

Make auto-compaction use only trustworthy current-context usage for successful turns, add provider-aware guards for missing or inconsistent `contextUsage`, persist a closed compaction trigger reason, and prove the subagent-yield wake path on current main.
