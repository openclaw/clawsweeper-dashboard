## Summary

Keep open: the latest release still has the reported successful-turn overflow predicate, and current main only partially hardens the path while compaction transcript entries still lack trigger/cause metadata.

## What This Changes

This issue reports that a subagent completion/direct-announce wake after `sessions_yield` can spuriously compact a low-context parent branch and asks for reliable compaction trigger attribution.

## Best Possible Solution

Use sanity-checked last-call/context usage for parent-wake overflow decisions, persist a closed compaction trigger reason on transcript entries, and prove the subagent-yield wake flow with live regression evidence before closing.

Question: Should successful-turn usage-based overflow still trigger auto-compaction when provider usage is internally inconsistent or lacks a trusted context snapshot?

Rationale: The safe fix must balance false-positive compactions against silent-overflow recovery for providers that do not hard-fail, and it also changes persisted compaction attribution.

Likely owner: Peter Steinberger

Owner confidence: medium

Options:

- **Sanity-check usage and persist trigger (recommended):** Keep successful-turn overflow recovery only for trusted context snapshots or internally consistent usage, add a closed trigger field, and require live subagent-yield proof.
- **Disable successful-turn overflow recovery:** Avoid this false-compaction class by relying on explicit provider overflow errors, at the cost of weaker silent-overflow recovery.
- **Keep the predicate unchanged:** Preserve current silent-overflow behavior but leave the reported low-context compaction class and weak attribution unresolved.

## Reproduction Assessment

Yes at source level: current main can still route a successful assistant message through usage-based overflow compaction when no trusted `contextUsage` is available, and the issue comments provide live low-context subagent-wait examples. I did not run a live current-main subagent-yield reproduction.

## Solution Assessment

Unclear for automation: the requested guard and trigger metadata are plausible, but maintainers need to decide how to preserve silent-overflow recovery while refusing corrupt usage. A narrow code-only fix without that policy choice could break providers that rely on successful-turn overflow detection.
