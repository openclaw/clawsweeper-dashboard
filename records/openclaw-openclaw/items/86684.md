## Summary

Keep open: current main has a newer context-usage-aware overflow helper, but the reported problem is not proven fixed because successful-turn compaction still falls back to aggregate `input + cacheRead` when no trustworthy context snapshot exists, and compaction entries still lack trigger/cause metadata.

## What This Changes

The issue reports that `sessions_yield`/subagent wake handling can compact a parent session at low visible context usage, losing exact parent-session history and increasing token cost.

## Best Possible Solution

Use a trustworthy last-call/context snapshot or sanity-checked successful-turn usage for parent-wake compaction decisions, persist a closed compaction trigger cause, and prove the subagent-yield wake path on current main.
