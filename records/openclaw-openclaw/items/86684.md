## Summary

Keep open: current main only partially mitigates inflated successful-turn usage by honoring `contextUsage`, but OpenAI-compatible completions still produce usage without that snapshot and persisted compaction entries still lack trigger/cause metadata; latest release v2026.6.11 still has the older aggregate `input + cacheRead` overflow predicate.

## What This Changes

Prevent subagent `sessions_yield` wake/direct-announce handling from compacting the parent branch at low context usage and persist compaction trigger metadata.

## Best Possible Solution

Add a narrow persisted compaction trigger/cause contract and make subagent-wake overflow decisions use a trustworthy last-call/context snapshot or explicit unavailable state, then prove the current-main subagent-yield wake path live.
