## Summary

The patch appears correct, narrowly owned, and still necessary on current main, but this external Telegram streaming PR needs real Telegram behavior proof before merge; the supplied wall-clock harness uses a stubbed Bot API rather than a live Telegram setup.

## What This Changes

Makes Telegram draft-stream final-flush retry waits abort promptly when the stream is discarded, while re-arming the wait signal for later messages and adding regression coverage.

## Best Possible Solution

Keep the per-stream abort-controller design, then land it after redacted live Telegram logs or terminal output demonstrate both prompt discard cancellation during a real retry_after window and unchanged graceful waiting.
