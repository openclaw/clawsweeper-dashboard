## Summary

Keep open: current main and the latest release still only support broad Discord `allowBots` modes, with no trusted webhook allowlist or webhook-to-user mapping contract. The remaining work is a maintainer product/security decision rather than stale cleanup.

## What This Changes

Request adding guild-scoped Discord `trustedWebhooks` config so selected webhook-authored messages can bypass the default bot-message drop and optionally map to a user.

## Best Possible Solution

Define the Discord trusted-webhook trust model first; if accepted, implement it inside the Discord plugin with strict schema validation, explicit identity-mapping rules, docs, and preflight tests while preserving the default bot-message safety policy.

Rationale: The request is narrower than `allowBots: true`, but it creates a new inbound authority surface and the proposed user mapping crosses authorization and session-identity boundaries.

Options:

- **Approve allowlist without user mapping (recommended):** Allow selected Discord webhook IDs to pass the bot-message gate while keeping sender identity as the webhook/bot identity until a separate mapping contract is approved.
- **Approve webhook-to-user mapping:** Permit `mapToUser` only with strict validation against configured guild users, clear audit behavior, and tests proving it cannot bypass sender authorization or session isolation.
- **Decline Discord-specific trusted ingress:** Keep Discord bot-message policy unchanged and direct external automation to the authenticated webhooks plugin or a separate plugin design.

## Reproduction Assessment

Yes. At source level, current Discord preflight resolves the webhook id and then drops non-PluralKit bot-authored messages when `allowBots` is off; I did not run a live Discord webhook scenario in this read-only review.

## Solution Assessment

Unclear. A webhook-ID allowlist is plausible and narrower than `allowBots: true`, but `mapToUser` changes authorization and session identity semantics, so maintainers should approve the trust contract before implementation.
