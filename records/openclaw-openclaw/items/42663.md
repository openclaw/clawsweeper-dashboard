## Summary

Keep open: current main and v2026.6.11 still lack a Discord trusted-webhook admission path, and the requested allowlist plus optional identity mapping is a security/product decision rather than conservative cleanup.

## What This Changes

Add guild-scoped Discord `trustedWebhooks` config so selected webhook-authored messages can trigger agent responses without enabling all bot-authored messages.

## Best Possible Solution

Define the Discord trusted-webhook trust model first; if accepted, implement it inside the Discord plugin with strict schema validation, explicit identity-mapping rules, docs, and preflight tests while preserving the default bot-message safety policy.

Options:

- **Approve Allowlist Without User Mapping (recommended):** Allow selected Discord webhook IDs to pass the bot-message gate while keeping sender identity as the webhook or bot identity until a separate identity-mapping contract is approved.
- **Approve Webhook-To-User Mapping:** Permit user mapping only with strict validation against configured guild users or identity links, clear audit behavior, and tests proving it cannot bypass sender authorization or session isolation.
- **Decline Discord-Native Trusted Ingress:** Keep Discord bot-message policy unchanged and direct external automation to generic hooks, plugin, or channel-extension designs instead of adding this trust surface.
