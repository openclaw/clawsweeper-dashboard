## Summary

Keep open: current main and the latest release still drop non-PluralKit Discord webhook/bot messages when `allowBots` is off, and there is no `trustedWebhooks` schema, docs, or identity-mapping contract. The remaining blocker is maintainer approval of the security model for a new trusted inbound Discord webhook authority surface.

## What This Changes

The issue requests a guild-scoped Discord `trustedWebhooks` allowlist so selected webhook messages can trigger agent responses without enabling all bot messages.

## Best Possible Solution

Have maintainers define the Discord trusted-webhook security model first; if accepted, implement it inside the Discord plugin with strict schema validation, explicit mapping rules, docs, and focused preflight tests without broadening the default bot-message policy.
