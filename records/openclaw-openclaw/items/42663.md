## Summary

Keep open: current main and the latest release still lack a Discord `trustedWebhooks` config surface, and the existing preflight path still drops non-PluralKit webhook/bot messages when `allowBots` is off. The remaining blocker is maintainer approval of the new Discord inbound trust and identity-mapping security model.

## What This Changes

The issue requests a guild-level Discord trusted webhook allowlist so selected webhook messages can trigger agent responses without enabling all bot messages.

## Best Possible Solution

Have maintainers define the Discord trusted-webhook security model first; if accepted, implement it inside the Discord plugin with strict schema validation, explicit mapping rules, docs, and focused preflight tests without broadening the default bot-message policy.
