## Summary

Keep open: current main and v2026.6.11 still do not implement Discord trusted webhook admission. The source still drops non-PluralKit webhook/bot messages when `allowBots` is off, and the requested `trustedWebhooks` plus optional `mapToUser` behavior needs a maintainer security/product decision before implementation.

## What This Changes

Request to add a guild-scoped Discord `trustedWebhooks` allowlist, with optional webhook-to-user mapping, so selected Discord webhook messages can trigger agent responses without broad `allowBots`.

## Best Possible Solution

Define the Discord trusted-webhook trust model first; if accepted, implement it inside the Discord plugin with strict schema validation, explicit identity-mapping rules, docs, and preflight tests while preserving the default bot-message safety policy.
