## Summary

Keep open: current main and v2026.6.11 still lack Discord trusted webhook admission, and the requested allowlist plus optional user mapping is a security/product decision rather than a conservative cleanup close.

## What This Changes

The issue requests guild-scoped Discord trusted webhook configuration so selected webhook-authored messages can trigger agent responses without enabling all bot messages.

## Best Possible Solution

Define the Discord trusted-webhook trust model first; if accepted, implement it in the Discord plugin with explicit schema, default-off admission, identityLinks-backed or no user mapping, docs, and preflight tests.
