## Summary

Keep open: current main and latest release still have no Discord `trustedWebhooks` or webhook-to-user mapping contract, and Discord preflight still drops non-PluralKit webhook/bot messages when `allowBots` is off. The request is useful but security-sensitive because it would add a new trusted inbound Discord webhook authority surface.

## What This Changes

Request adding a Discord guild-level `trustedWebhooks` allowlist so selected webhook-authored messages can trigger agent replies and optionally map to a configured user.

## Best Possible Solution

Have maintainers define the Discord trusted-webhook security model first; if accepted, implement it inside the Discord plugin with strict schema validation, explicit mapping rules, docs, and focused preflight tests without broadening the default bot-message policy.

## Reproduction Assessment

Yes, at source level: current preflight resolves `webhookId` but still drops non-PluralKit bot-authored messages when `allowBots` is off, and `v2026.6.11` has the same behavior. I did not run a live Discord webhook scenario because this review is read-only.

## Solution Assessment

Unclear. A webhook-id allowlist is plausible and narrower than `allowBots: true`, but `mapToUser` crosses authorization and session boundaries, so maintainers should approve the trust contract before implementation.
