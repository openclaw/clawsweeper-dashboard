## Summary

Keep open: current main and v2026.6.11 still do not implement trusted Discord webhook admission. Source shows Discord webhook IDs are resolved, but default bot-message filtering still drops non-PluralKit bot/webhook messages unless broad `allowBots` modes are enabled, so the remaining work needs a maintainer security/product decision.

## What This Changes

Request to add a Discord guild-level trusted webhook allowlist, optionally mapping webhook messages to a configured user, so selected Discord webhooks can trigger agent replies without enabling all bot messages.

## Best Possible Solution

Define the Discord trusted-webhook trust model first; if accepted, implement it inside the Discord plugin with strict schema validation, explicit identity-mapping rules, docs, and preflight tests while preserving the default bot-message safety policy.

Options:

- **Approve allowlist without user mapping (recommended):** Allow selected Discord webhook IDs to pass the bot-message gate while keeping sender identity as the webhook or bot identity until a separate identity-mapping contract is approved.
- **Approve webhook-to-user mapping:** Permit user mapping only with strict validation against configured guild users or identity links, clear audit behavior, and tests proving it cannot bypass sender authorization or session isolation.
- **Decline Discord-specific trusted ingress:** Keep Discord bot-message policy unchanged and direct external automation to generic webhook/plugin designs instead of adding this channel-specific trust surface.
