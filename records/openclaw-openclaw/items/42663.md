## Summary

Keep open: current main and v2026.6.11 still do not implement Discord `trustedWebhooks` or webhook-to-user mapping, and non-PluralKit Discord webhook authors are still dropped when `allowBots` is off. The remaining blocker is a maintainer security/product decision about whether a Discord webhook ID may become an inbound authority and whether it may map onto a user identity.

## What This Changes

The issue requests a Discord guild-scoped `trustedWebhooks` allowlist so selected webhook messages can trigger agent responses without enabling all bot-authored messages.

## Best Possible Solution

Have maintainers define the Discord trusted-webhook contract first; if accepted, implement it inside the Discord plugin with strict schema validation, conservative defaults, explicit identity-mapping rules, docs, and focused preflight/security tests.
