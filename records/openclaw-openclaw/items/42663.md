## Summary

Keep open: current main and the latest release still drop non-PluralKit Discord webhook messages when `allowBots` is off, and there is no `trustedWebhooks` schema, docs, or identity-mapping contract. This remains a useful feature request, but it needs maintainer security/product approval before implementation.

## What This Changes

The issue requests a Discord trusted webhook allowlist so selected webhook-authored messages can trigger agent responses without enabling all bot messages.

## Best Possible Solution

Have maintainers define the Discord trusted-webhook security model first; if accepted, implement it inside the Discord plugin with strict schema validation, explicit mapping rules, docs, and focused preflight tests without broadening the default bot-message policy.
