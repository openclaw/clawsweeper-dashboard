## Summary

Keep open: current main and v2026.6.11 still do not implement Discord trusted webhook admission, and the requested webhook allowlist plus optional user mapping needs maintainer security/product review before code should land.

## What This Changes

The issue requests a guild-scoped Discord `trustedWebhooks` config surface so selected Discord webhook messages can trigger agent responses without enabling all bot-authored messages.

## Best Possible Solution

Define the Discord trusted-webhook trust model first; if accepted, implement it inside the Discord plugin with strict schema validation, explicit identity-mapping rules, docs, and preflight tests while preserving the default bot-message safety policy.
