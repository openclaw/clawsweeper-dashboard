## Summary

Keep open: current main and v2026.6.11 still have no Discord `trustedWebhooks` or webhook-to-user mapping, and non-PluralKit Discord webhook/bot messages are dropped when `allowBots` is off. The remaining blocker is maintainer approval of the new Discord inbound authority and identity-mapping contract.

## What This Changes

The issue requests a guild-scoped Discord `trustedWebhooks` config that lets selected Discord webhooks trigger agent responses, optionally mapped to a configured user.

## Best Possible Solution

Have maintainers define the Discord trusted-webhook contract first; if accepted, implement it inside the Discord plugin with strict schema validation, explicit identity-mapping rules, docs, and focused preflight/security tests while keeping the default bot-message policy conservative.
