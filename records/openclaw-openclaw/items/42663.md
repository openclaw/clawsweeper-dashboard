## Summary

Keep open: current main and v2026.6.11 still lack a Discord trusted-webhook admission path, and the requested allowlist plus optional user mapping is a security/product decision rather than conservative cleanup.

## What This Changes

Request to add guild-scoped Discord `trustedWebhooks` so selected Discord webhook messages can trigger agent responses without enabling all bot-authored messages.

## Best Possible Solution

Define the Discord trusted-webhook trust model first; if accepted, implement it inside the Discord plugin with strict schema validation, explicit identity-mapping rules, docs, and preflight tests while preserving the default bot-message safety policy.
