## Summary

Keep open: current main and the latest release still drop non-PluralKit Discord webhook/bot messages when `allowBots` is off, and there is still no `trustedWebhooks` schema, docs, or webhook-to-user mapping contract. The remaining blocker is maintainer approval of the security model for this new trusted inbound Discord authority surface.

## What This Changes

The issue requests a guild-scoped Discord `trustedWebhooks` allowlist, with optional webhook-to-user mapping, so selected Discord webhooks can trigger agent replies without enabling all bot-authored messages.

## Best Possible Solution

Define a narrow Discord-plugin trust contract first: an explicit webhook-ID allowlist that can pass the bot gate, with webhook-to-user mapping either deferred or constrained by documented authorization and session semantics.

- **Decline Discord-specific ingress:** Keep Discord bot-message policy unchanged and direct external automation to the authenticated webhooks plugin or a separate integration instead of adding another Discord config surface.
