## Summary

Keep open: current main and v2026.6.11 still do not implement Discord trusted-webhook admission. The source resolves Discord webhook IDs, but non-PluralKit webhook/bot-authored messages are still dropped by default unless broad `allowBots` modes are enabled, so the remaining work needs a maintainer security/product decision.

## What This Changes

Request to add a Discord `trustedWebhooks` allowlist, optionally mapping webhook messages to a configured user, so selected webhook-authored messages can trigger agent responses without enabling all bot messages.

## Best Possible Solution

Define the Discord trusted-webhook trust model first; if accepted, implement it inside the Discord plugin with strict schema validation, explicit identity-mapping rules, docs, and preflight tests while preserving the default bot-message safety policy.
