## Summary

Keep open: current main and v2026.6.11 still only support broad Discord `allowBots` modes, PluralKit identity handling, and bound-thread webhook echo suppression; there is no Discord trusted-webhook allowlist or webhook-to-user mapping. The remaining work is a security/product decision, not a stale cleanup close.

## What This Changes

The issue requests a guild-scoped Discord `trustedWebhooks` config that lets selected webhook-authored messages trigger agent responses and optionally map to a configured user identity.

## Best Possible Solution

Define the Discord trusted-webhook trust model first; if accepted, implement it inside the Discord plugin with strict schema validation, explicit identity-mapping rules, docs, and preflight tests while preserving the default bot-message safety policy.

Options:

- **Approve allowlist without user mapping (recommended):** Allow selected Discord webhook IDs to pass the bot-message gate while keeping sender identity as the webhook or bot identity until a separate identity-mapping contract is approved.
- **Approve webhook-to-user mapping:** Permit user mapping only with strict validation against configured guild users or identity links, clear audit behavior, and tests proving it cannot bypass sender authorization or session isolation.
- **Decline Discord-specific trusted ingress:** Keep Discord bot-message policy unchanged and direct external automation to the generic Webhooks plugin or a separate plugin design.
