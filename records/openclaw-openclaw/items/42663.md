## Summary

Keep open: current main and v2026.6.11 still only support broad Discord bot-message modes, not a guild-scoped trusted webhook allowlist or webhook-to-user mapping. The remaining work is a security/product decision because it would add a new trusted inbound authority surface.

## What This Changes

Request to add guild-scoped Discord trusted webhook configuration so selected webhook-authored messages can trigger agent responses, optionally mapped to a configured user.

## Best Possible Solution

Define the Discord trusted-webhook security model first; if accepted, implement it in the Discord plugin with strict schema validation, explicit identity-mapping rules, docs, preflight tests, and preserved default bot-message safety.

Options:

- **Approve allowlist without user mapping (recommended):** Allow selected Discord webhook IDs to pass the bot-message gate while preserving webhook/bot sender identity until a separate mapping contract is approved.
- **Approve allowlist plus user mapping:** Permit `mapToUser` only with strict validation against configured guild users, clear audit behavior, and tests proving it cannot bypass sender authorization or session isolation.
- **Decline new trusted ingress:** Keep Discord bot-message policy unchanged and direct webhook automations to `allowBots: "mentions"`, authenticated Gateway hooks, or a separate ClawHub integration.

Unclear as proposed. A webhook-id allowlist is plausible and narrower than `allowBots: true`, but `mapToUser` changes authorization and session identity semantics, so maintainers should approve the trust contract before implementation.
