## Summary

Keep open: current main and v2026.6.11 still lack a Discord `trustedWebhooks` allowlist or webhook-to-user mapping, and the remaining work is a security/product decision about letting Discord webhook possession trigger agent turns.

## What This Changes

The issue requests a guild-scoped Discord `trustedWebhooks` config option so selected Discord webhook messages can bypass the default bot-message drop and optionally map to a user identity.

## Best Possible Solution

Have maintainers define the Discord trusted-webhook authority first; if accepted, implement it inside the Discord plugin with strict schema validation, conservative defaults, explicit identity-mapping rules, docs, focused preflight/security tests, and live Discord proof.

Options:

- **Approve Narrow Trusted Webhooks (recommended):** Allow a webhook-id allowlist to pass the bot-message gate, but keep user mapping disallowed or separately constrained until its authorization semantics are defined.
- **Approve Webhook-To-User Mapping:** Permit `mapToUser` only with strict validation against configured guild users, audit behavior, and tests proving it cannot bypass sender authorization or session isolation.
- **Use Generic Hook Ingress:** Decline a Discord-specific surface and direct external automation to authenticated Gateway hooks when same-channel Discord replies are not required.
