## Summary

Keep open: current main and v2026.6.11 still drop Discord webhook-authored messages under the default bot gate, and the proposed allowlist plus user mapping is a security/product decision rather than conservative cleanup.

## What This Changes

The issue requests a guild-scoped Discord `trustedWebhooks` allowlist with optional webhook-to-user mapping so selected Discord webhook messages can trigger agent responses without enabling all bot messages.

## Best Possible Solution

Define the Discord trusted-webhook trust model first; if accepted, implement it in the Discord plugin with strict schema validation, no implicit user impersonation, explicit identity-link rules if mapping is allowed, docs, and preflight regression coverage.

- **Decline Discord-Native Trusted Ingress:** Keep Discord bot-message policy unchanged and direct external automation to generic hooks or a separate plugin/API design instead of adding this channel trust surface.
