## Summary

Keep open: current main and v2026.6.11 still have only broad Discord bot-message modes, while the requested trusted webhook allowlist and optional identity mapping remain unimplemented and security-sensitive.

## What This Changes

Request to add a guild-scoped Discord trusted webhook allowlist with optional webhook-to-user mapping for Discord inbound messages.

## Best Possible Solution

Have maintainers define the Discord trusted-webhook security model first; if accepted, implement it in the Discord plugin with strict schema validation, explicit mapping rules, docs, and focused preflight tests without broadening the default bot-message policy.

Rationale: The requested allowlist is narrower than allowBots=true, but it gives Discord webhook possession authority to enter agent sessions and the proposed mapToUser option crosses authorization and session-identity boundaries.

Owner confidence: high

Options:

- **Approve allowlist without identity mapping (recommended):** Permit a strict webhook-id allowlist to pass the bot-message gate while keeping user impersonation out until a separate authorization contract is approved.
- **Approve webhook-to-user mapping:** Allow mapToUser only with validation against configured guild users, audit/logging behavior, and tests proving it cannot bypass sender authorization or session isolation.
- **Decline Discord-specific webhook ingress:** Keep Discord bot-message policy unchanged and direct external automation to authenticated Gateway hooks or a ClawHub integration instead.

## Solution Assessment

Unclear. A webhook-id allowlist is plausible and narrower than allowBots=true, but mapToUser crosses authorization and session boundaries, so maintainers should approve the trust contract before implementation.
