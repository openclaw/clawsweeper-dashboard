## Summary

Keep open: current main and v2026.6.11 still lack a Discord trusted-webhook admission path, and the requested allowlist plus optional user mapping is a security/product decision rather than conservative cleanup.

## What This Changes

The issue requests a Discord trusted-webhook allowlist with optional user mapping so selected webhook messages can trigger agent responses without enabling all bot messages.

## Best Possible Solution

Define the Discord trusted-webhook trust model first; if accepted, implement it inside the Discord plugin with strict schema validation, explicit identity-mapping rules, docs, and preflight tests while preserving the default bot-message safety policy.

Rationale: The allowlist is narrower than `allowBots: true`, but it creates a new inbound authority surface and the proposed user mapping crosses sender authorization and session-identity boundaries.

Likely owner: steipete

Owner confidence: medium

Options:

- **Approve Allowlist Without User Mapping (recommended):** Allow selected Discord webhook IDs to pass the bot-message gate while keeping sender identity as the webhook or bot identity until a separate identity-mapping contract is approved.
- **Approve Webhook-To-User Mapping:** Permit user mapping only with strict validation against configured guild users or identity links, clear audit behavior, and tests proving it cannot bypass sender authorization or session isolation.
- **Decline Discord-Native Trusted Ingress:** Keep Discord bot-message policy unchanged and direct external automation to generic hooks, plugin, or channel-extension designs instead of adding this trust surface.

Yes, at source level. Current Discord preflight resolves a webhook ID, then drops non-PluralKit bot-authored messages when `allowBots` is off; no live Discord webhook scenario was run in this read-only review.

## Solution Assessment

Unclear. A webhook-ID allowlist is plausible and narrower than `allowBots: true`, but the proposed `mapToUser` behavior is not safe to accept without a maintainer-approved identity and authorization contract.
