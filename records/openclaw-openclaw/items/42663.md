## Summary

Keep open: current main and v2026.6.11 still have no Discord `trustedWebhooks` config or webhook-to-user mapping, and ordinary non-PluralKit webhook/bot authors are dropped when `allowBots` is off. The remaining blocker is maintainer approval of a new Discord inbound authority and identity-mapping contract.

## What This Changes

The issue requests a Discord `trustedWebhooks` allowlist with optional webhook-to-user mapping so selected Discord webhook messages can trigger agent replies without enabling all bot authors.

## Best Possible Solution

Have maintainers define the Discord trusted-webhook contract first; if accepted, implement it inside the Discord plugin with strict schema validation, explicit identity-mapping rules, docs, and focused preflight/security tests while leaving the default bot-message policy conservative.

Options:

- **Approve Narrow Trusted Webhooks (recommended):** Allow a webhook-id allowlist to pass the bot-message gate, but keep user mapping disallowed or separately constrained until its authorization semantics are defined.
- **Approve Webhook-To-User Mapping:** Permit `mapToUser` only with strict validation against configured guild users, audit/logging behavior, and tests proving it cannot bypass sender authorization or session isolation.
- **Use Generic Webhook Ingress Instead:** Decline a Discord-specific config surface and direct external automation to authenticated OpenClaw webhook routes when same-channel Discord replies are not required.
