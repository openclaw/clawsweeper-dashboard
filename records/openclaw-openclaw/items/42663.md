## Summary

Keep open: current main and v2026.6.11 still only support broad Discord `allowBots` modes plus PluralKit and bound-thread webhook echo handling, not a guild-scoped trusted Discord webhook allowlist or webhook-to-user mapping. The remaining decision is a Discord security/config product call, not conservative cleanup.

## What This Changes

Request to add guild-scoped Discord `trustedWebhooks` so selected Discord webhook-authored messages can trigger agent replies without enabling all bot messages.

## Best Possible Solution

Define the Discord trusted-webhook trust model first; if accepted, implement it inside the Discord plugin with strict schema validation, explicit identity-mapping rules, docs, and preflight tests while preserving the default bot-message safety policy.
