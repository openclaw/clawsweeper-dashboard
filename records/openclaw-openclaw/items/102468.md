## Label Justifications

- `P1`: Default Telegram long turns can leave a group unresponsive and then abort otherwise healthy reply work at the spooled handler timeout.
- `impact:message-loss`: Same-lane inbound Telegram messages are held upstream of session admission, and timeout recovery can fail the active spooled update rather than deliver a normal reply path.
- `impact:session-state`: The transport lane prevents mid-turn Telegram messages from entering the active session queue or steering admission while a reply operation is running.

## Summary

Keep open: current main still couples the Telegram isolated-ingress lane to the full agent turn, and the protected maintainer label plus replay/ordering blast radius make this an owner design decision rather than a cleanup close.

## What This Changes

The issue requests redesigning Telegram isolated ingress so a per-chat/topic spool lane completes after durable handoff to session admission instead of after the full agent turn.

## Best Possible Solution

Define a Telegram ingress handoff design that releases the spooled lane after durable session-admission handoff while preserving replay safety, control-lane escapes, reply-fence cleanup, restart behavior, and live Telegram proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Telegram isolated ingress release the per-chat/topic spool lane after durable handoff to session admission instead of after the full agent turn completes?

Rationale: The source-level defect is clear, but the durable fix changes Telegram transport ordering, timeout semantics, duplicate/replay safety, and downstream session-admission ownership, so maintainers need to choose the contract before code repair.

Likely owner: obviyus

Owner reason: They are assigned and have the most direct recent history across the related run-lifecycle and Telegram spooled-update work.

Owner confidence: high

Options:

- **Detach After Durable Handoff (recommended):** Move the Telegram spool lane lifetime to ingestion/classification plus durable session handoff, then let session admission own active-run ordering and steering.
- **Keep Lane Ownership And Tune Timeout:** Preserve the current one-handler-per-lane model and only adjust timeout or user feedback, accepting that ordinary same-lane messages still cannot reach steering during a long turn.
- **Split Narrow Follow-Ups:** Handle timeout visibility and collect starvation separately while leaving this issue as the owner decision for Telegram lane ownership.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: current main awaits the full Telegram update handler while marking the lane active, blocks later same-lane spooled updates, and has timeout behavior covered in tests. I did not run a live Telegram long-turn reproduction in this read-only review.

## Solution Assessment

Unclear until maintainer design review. Detaching after durable handoff appears to be the right ownership direction, but it must preserve Telegram replay, tombstone, ordering, control-lane, and reply-fence contracts.
