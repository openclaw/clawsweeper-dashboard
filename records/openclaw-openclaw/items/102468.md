## Label Justifications

- `P1`: Default Telegram long turns can leave a group unresponsive and then abort otherwise healthy reply work after the 25-minute spooled handler timeout.
- `impact:message-loss`: Same-lane inbound Telegram messages remain upstream of session admission during an active turn, and timeout recovery can fail the active spooled update rather than deliver a normal reply path.
- `impact:session-state`: The transport lane prevents mid-turn Telegram messages from entering the active session queue or steering admission while a reply operation is running.

## Summary

Keep open: current main still holds the Telegram isolated-ingress per-chat/topic lane while awaiting the full Telegram update and downstream agent turn, and the protected `maintainer` label plus replay/ordering blast radius make this an owner design item rather than conservative cleanup closure.

## What This Changes

The issue requests decoupling Telegram isolated-ingress lane ownership from full agent-turn execution so same-chat messages can reach session admission during long turns.

## Best Possible Solution

Define a Telegram ingress handoff contract that releases the spooled lane after durable handoff to session admission while preserving replay safety, reply-fence cleanup, crash/restart behavior, and live Telegram proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Telegram isolated ingress release the per-chat/topic spool lane after durable handoff to session admission instead of after the full agent turn completes?

Rationale: The source-level bug is clear, but the permanent fix changes Telegram transport ordering, duplicate/replay safety, timeout semantics, and downstream session admission ownership, so maintainer intent is required before automation edits code.

Likely owner: obviyus

Owner reason: They are assigned to this issue and authored the related run-lifecycle work that defines the downstream invariant being blocked by Telegram ingress.

Owner confidence: high

Options:

- **Detach After Durable Handoff (recommended):** Move the Telegram spool lane lifetime to ingestion/classification plus durable session handoff, then let session admission own active-run ordering and steering.
- **Keep Lane Ownership And Tune Timeout:** Preserve the current one-handler-per-lane model and only adjust watchdog/user feedback, accepting that same-lane messages still cannot reach steering during a long turn.
- **Split Narrow Follow-Ups:** Track handler-timeout visibility and collect starvation separately while leaving this issue as the umbrella design decision for lane ownership.

## Reproduction Assessment

Yes, at source level: current main awaits the full Telegram update handler while marking the lane active, blocks later same-lane spooled updates, and has timeout recovery that fails the active claim. I did not run a live Telegram long-turn reproduction in this read-only review.

## Solution Assessment

Unclear until maintainer design review: detaching after durable handoff appears to be the right ownership direction, but it must preserve Telegram replay, tombstone, ordering, and reply-fence contracts.
