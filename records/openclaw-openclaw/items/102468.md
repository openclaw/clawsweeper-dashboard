## Label Justifications

- `P1`: Default Telegram long turns can leave a group unresponsive and then abort otherwise healthy reply work after the 25-minute spooled-handler timeout.
- `impact:message-loss`: Same-lane Telegram inbound messages are held upstream of session admission, and timeout recovery can fail the active spooled update rather than deliver a normal reply path.
- `impact:session-state`: The transport lane prevents mid-turn Telegram messages from entering the active session queue or steering admission while a reply operation is running.

## Summary

Keep open: current main and the latest release still hold a Telegram isolated-ingress lane while the full agent turn runs, and the protected `maintainer` label plus Telegram replay/ordering blast radius make this an owner design item rather than cleanup closure.

## What This Changes

Request to redesign Telegram isolated polling so each per-chat/topic ingress lane is held only through durable dispatch handoff instead of the entire agent turn.

## Best Possible Solution

Define and land a Telegram ingress handoff design that completes the spool lane after durable session handoff, preserves replay and ordering contracts, and proves a long Telegram turn with same-lane follow-up traffic.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Telegram isolated ingress release the per-chat/topic spool lane after durable handoff to session admission instead of after the full agent turn completes?

Rationale: The source-level failure is clear, but the permanent fix chooses ownership for Telegram ordering, replay, timeout, and session steering semantics, which should be an explicit maintainer design decision before implementation.

Likely owner: obviyus

Owner reason: They are assigned and authored the related run-lifecycle work that exposed the next Telegram transport ownership gap.

Owner confidence: high

Options:

- **Detach After Durable Handoff (recommended):** Move lane lifetime to ingestion/classification plus durable session handoff, then let session admission own active-run ordering and steering.
- **Keep Lane Ownership And Tune Timeout:** Preserve one-handler-per-lane transport ownership and improve timeout/user feedback, accepting that mid-turn same-lane messages remain invisible to steering.
- **Split Follow-Ups First:** Handle timeout visibility and progress feedback separately while leaving lane detachment as a larger design item.

## Reproduction Assessment

Yes, at source level: current main awaits the full Telegram update handler while marking the lane active, blocks later same-lane spooled updates, and retains the timeout-fail branch. I did not run a live Telegram long-turn reproduction in this read-only review.

## Solution Assessment

Unclear until maintainer design review: detaching after durable handoff appears to be the right ownership direction, but it must preserve Telegram replay, tombstone, ordering, and reply-fence contracts.
