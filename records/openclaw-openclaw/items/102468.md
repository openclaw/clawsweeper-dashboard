## Label Justifications

- `P1`: Default Telegram long turns can leave a group unresponsive and then abort otherwise healthy reply work at the spooled handler timeout.
- `impact:message-loss`: Same-lane inbound messages are held upstream of session admission, and the timeout path can fail the active spooled update instead of delivering a normal reply path.
- `impact:session-state`: The transport lane prevents mid-turn Telegram messages from entering the active session queue or steering admission while a reply operation is running.

## Summary

Keep open: current main still couples Telegram isolated-ingress lane lifetime to the full update handler and can keep same-lane messages upstream of session admission until the 25-minute handler timeout, while the protected maintainer label and replay/ordering blast radius require owner design review.

## What This Changes

The issue requests a Telegram isolated-polling design change so the per-chat/topic ingress lane completes after durable handoff to session turn admission instead of after the whole agent turn settles.

## Best Possible Solution

Define and land a Telegram ingress handoff contract that completes the spooled lane after durable session-admission handoff while preserving replay safety, reply-fence cleanup, control-lane escapes, crash/restart behavior, and live Telegram proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Telegram isolated polling release a per-chat/topic spool lane after durable session-admission handoff instead of keeping it active until the full agent turn settles?

Rationale: The source-level failure is clear, but the permanent fix changes Telegram transport ordering, duplicate/replay safety, timeout semantics, and session-admission ownership, which needs maintainer intent before automation edits code.

Likely owner: obviyus

Owner reason: They are assigned to this issue and have the strongest recent history across the Telegram spool and related run-lifecycle surfaces.

Owner confidence: high

Options:

- **Detach After Durable Handoff (recommended):** Move the spool lane lifetime to ingestion/classification plus durable handoff, then let session admission own active-run ordering and steering.
- **Keep Transport Lane Ownership:** Preserve one active handler per lane and only tune timeout, recovery, or progress feedback, accepting that same-lane messages still cannot reach admission during a long turn.
- **Split Narrow Follow-Ups:** Track handler-timeout visibility, timeout recovery, progress feedback, and claude-cli live injection separately while keeping this issue as the lane-ownership design item.

## Reproduction Assessment

Yes, source-reproducible: current main awaits the full Telegram update handler while the lane is active, blocks later same-lane spooled updates, and has tests preserving timeout recovery behavior. I did not run a live 25-minute Telegram reproduction in this read-only review.

## Solution Assessment

Unclear until maintainer design review: detaching after durable handoff appears to be the right ownership boundary, but it must preserve Telegram replay, tombstone, ordering, and reply-fence contracts.
