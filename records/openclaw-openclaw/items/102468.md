## Label Justifications

- `P1`: Default Telegram long turns can leave a group unresponsive and then abort otherwise healthy reply work after the spooled handler timeout.
- `impact:message-loss`: Same-lane inbound messages are held upstream of session admission, and timeout recovery can fail active spooled work instead of delivering through the normal reply path.
- `impact:session-state`: The transport lane prevents mid-turn Telegram messages from entering the active session queue or steering admission while a reply operation is running.

## Summary

Keep open: current main still couples Telegram isolated-ingress lane ownership to the full agent turn, and the live issue is protected with the maintainer label. The source-level problem is well supported, but the fix changes Telegram replay, ordering, timeout, and session-admission ownership, so it needs maintainer design review rather than cleanup closure.

## What This Changes

Requested design change to decouple Telegram isolated-ingress per-chat/topic lane lifetime from full agent turns so long turns do not block same-lane messages or hit the 25-minute handler timeout.

## Best Possible Solution

Define and land a Telegram ingress handoff design that completes the spooled lane claim after durable session-admission handoff while preserving replay safety, reply-fence cleanup, control-lane escapes, crash/restart behavior, and live Telegram proof.

## Maintainer Decision

Kind: product_direction

Question: Should Telegram isolated ingress release the per-chat/topic spool lane after durable handoff to session admission instead of after the full agent turn completes?

Rationale: The source-level problem is clear, but the permanent fix changes the contract between Telegram transport ordering, duplicate/replay safety, timeout handling, and session admission ownership.

Likely owner: obviyus

Owner reason: They are assigned to this issue and have the strongest recent history across the Telegram spool lifecycle and the related run-lifecycle design work.

Owner confidence: high

Options:

- **Detach After Durable Handoff (recommended):** Move Telegram spool lane lifetime to ingestion/classification plus durable session handoff, then let session admission own active-run ordering and steering.
- **Keep Lane Ownership And Tune Timeout:** Preserve the current one-handler-per-lane model and adjust watchdog or user feedback, accepting that same-lane messages still cannot reach steering during a long turn.
- **Split Narrow Follow-Ups:** Track handler-timeout visibility and collect starvation separately while leaving this issue as the umbrella design decision for lane ownership.

## Reproduction Assessment

Yes, at source level: current main awaits the full Telegram update handler while marking the lane active, blocks later same-lane spooled updates, and has tests covering the current timeout/failure behavior. I did not run a live Telegram long-turn reproduction in this read-only review.

## Solution Assessment

Unclear until maintainer design review: detaching after durable handoff appears to be the right ownership direction, but it must preserve Telegram replay, tombstone, ordering, and reply-fence contracts.
