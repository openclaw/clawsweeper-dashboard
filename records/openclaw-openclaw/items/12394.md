## Label Justifications

- `P3`: This is useful WhatsApp heartbeat ergonomics with an existing workaround of disabling visible OK acknowledgments.
- `impact:message-loss`: The issue concerns visible heartbeat OK messages being misrouted to every allowed WhatsApp recipient while preserving alert delivery.

## Summary

Keep open: current main and the latest release still lack an OK-only WhatsApp heartbeat recipient contract. The existing channel heartbeat config only controls visibility, and visible `HEARTBEAT_OK` acknowledgments still use the same resolved heartbeat delivery target as alert/content delivery.

## What This Changes

The issue requests optional WhatsApp channel heartbeat recipients so visible `HEARTBEAT_OK` acknowledgments can go only to selected admin users while alert routing stays unchanged.

## Best Possible Solution

Define one additive OK-acknowledgment recipient contract, validate recipients against WhatsApp account and allowlist policy, and keep alert/content delivery on the existing relevant-user route.

## Reproduction Assessment

Yes. Current main rejects `target`/`targets` in strict channel heartbeat config and sends OK acknowledgments through the same resolved heartbeat delivery target; I did not run a live WhatsApp heartbeat.

## Solution Assessment

Unclear pending maintainer product direction. Splitting OK acknowledgment recipients from alert/content routing is the right behavioral boundary, but the permanent config shape and validation rules need owner approval.
