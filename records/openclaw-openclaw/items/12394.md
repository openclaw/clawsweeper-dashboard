## Label Justifications

- `P3`: This is a useful but non-urgent WhatsApp heartbeat ergonomics feature with an existing workaround of disabling visible OK acknowledgments.
- `impact:message-loss`: The issue is about heartbeat OK messages being routed to every allowed WhatsApp recipient instead of only the intended admin recipients while preserving alert delivery.

## Summary

Keep open: current main still has visibility-only channel heartbeat config and sends visible HEARTBEAT_OK acknowledgments through the same resolved heartbeat delivery target, so the requested admin-only WhatsApp OK routing remains unimplemented and needs a maintainer product/config decision.

## What This Changes

Request adds optional channel/WhatsApp heartbeat recipient targeting so visible HEARTBEAT_OK acknowledgments go only to selected admins instead of every allowFrom recipient.

## Best Possible Solution

Define an additive channel-owned WhatsApp OK-ack recipient contract, validate recipients against account and allowFrom policy, apply it only to visible HEARTBEAT_OK delivery, and preserve existing alert routing plus omitted-config compatibility.

## Reproduction Assessment

Yes, at source level: current main rejects target/targets in strict channel heartbeat config, resolves only visibility booleans, and sends OK acknowledgments through the same resolved heartbeat delivery target. I did not run a live WhatsApp heartbeat.

## Solution Assessment

Unclear pending maintainer product direction. Splitting OK acknowledgment recipients from alert/content routing is the right behavioral boundary, but the final config shape and validation rules need owner approval.
