## Label Justifications

- `P3`: The issue is a useful but non-urgent WhatsApp heartbeat ergonomics/config feature with an existing workaround of disabling visible OK acknowledgments.
- `impact:message-loss`: The reported problem is heartbeat OK messages being misrouted to every allowed WhatsApp recipient while preserving relevant alert delivery.

## Summary

Keep open: current main still exposes only channel heartbeat visibility booleans and sends visible HEARTBEAT_OK acknowledgments through the same resolved heartbeat delivery target, so the requested admin-only OK routing remains missing and needs a config/product decision.

## What This Changes

Issue requests optional per-user or per-admin routing for WhatsApp channel heartbeat OK messages so non-admin allowlisted users are not spammed.

## Best Possible Solution

Define one additive OK-acknowledgment recipient contract, validate recipients through WhatsApp account and allowlist policy, apply it only to visible HEARTBEAT_OK delivery, and preserve existing alert/content routing plus omitted-config compatibility.

## Reproduction Assessment

Yes, at source level: current main rejects target/targets in strict channel heartbeat config, resolves only visibility booleans, and sends OK acknowledgments through the same resolved heartbeat delivery target. I did not run a live WhatsApp heartbeat.

## Solution Assessment

Unclear pending maintainer product direction. Splitting OK acknowledgment recipients from alert/content routing is the right behavioral boundary, but the final config shape and validation rules need owner approval.
