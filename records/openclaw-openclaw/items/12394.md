- `impact:message-loss`: The issue is about heartbeat OK messages being over-broadcast or misrouted to every allowed WhatsApp recipient while preserving relevant alert delivery.

## Summary

Keep open: current main still has visibility-only channel heartbeat config and one shared heartbeat delivery target, so the requested WhatsApp admin-only `HEARTBEAT_OK` routing remains unimplemented and needs maintainer product/config direction.

## What This Changes

The issue requests optional WhatsApp/channel heartbeat recipient fields so visible `HEARTBEAT_OK` messages can go only to selected admin users instead of every allowed user.

## Best Possible Solution

Define one additive OK-acknowledgment recipient contract, validate recipients through the WhatsApp account and allowlist/pairing policy, apply it only to visible `HEARTBEAT_OK` delivery, and preserve existing alert/content routing plus omitted-config compatibility.

## Reproduction Assessment

Yes, at source level: current main rejects `target`/`targets` in strict channel heartbeat config, resolves only visibility booleans, and sends OK acknowledgments through the same resolved heartbeat delivery target. I did not run a live WhatsApp heartbeat.

## Solution Assessment

Unclear pending maintainer product direction. Splitting OK acknowledgment recipients from alert/content routing is the right behavioral boundary, but the final config shape and validation rules need owner approval.
