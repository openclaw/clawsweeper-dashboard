## Summary

Keep open: current main still does not provide a channel-level WhatsApp heartbeat recipient contract for OK-only admin routing. The existing implementation supports visibility toggles and global/default heartbeat `target`/`to` routing, but WhatsApp channel heartbeat config remains visibility-only and OK acknowledgments still send to the resolved heartbeat delivery target.

## What This Changes

The issue requests optional WhatsApp channel heartbeat `target` or `targets` config so `HEARTBEAT_OK` messages can be routed only to admin recipients without changing alert routing for other users.

## Best Possible Solution

Keep the issue open for a maintainer decision on an additive WhatsApp channel heartbeat recipient contract that applies only to OK heartbeat messages, preserves alert/content routing, and includes schema/types/docs plus compatibility and invalid-target coverage.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: adding `channels.whatsapp.heartbeat.target` or `targets` is outside the strict channel heartbeat schema and the OK acknowledgment sender uses the shared resolved heartbeat delivery target. I did not run a live WhatsApp heartbeat in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product contract. The requested additive config is plausible and backward-compatible in shape, but the best implementation needs an explicit decision on field name, per-account precedence, allowlist validation, and OK-only routing semantics.
