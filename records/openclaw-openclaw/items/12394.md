- `impact:message-loss`: The requested recipient contract controls which WhatsApp users receive heartbeat status messages and must avoid misrouting OKs or suppressing alerts.

## Summary

Keep open: current main and the latest release still expose channel heartbeat config as visibility-only and route visible OK acknowledgments through the same resolved delivery target, so admin-only WhatsApp `HEARTBEAT_OK` routing remains missing and needs maintainer product direction.

## What This Changes

Request optional WhatsApp/channel heartbeat recipient config so visible `HEARTBEAT_OK` acknowledgments can go only to admin recipients while alert delivery keeps its normal routing.

## Best Possible Solution

Define an additive WhatsApp/channel heartbeat recipient contract for OK acknowledgments only, validate recipients against account and allowlist policy, preserve alert delivery semantics, and update schema, docs, and focused tests together.

Unclear until maintainers choose the product contract. The requested additive config is plausible, but the best fix needs an explicit decision on field shape, account precedence, allowlist validation, and OK-only semantics.
