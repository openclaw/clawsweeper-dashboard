## Label Justifications

- `P3`: This is a useful but non-urgent WhatsApp heartbeat ergonomics feature with an existing workaround of disabling visible OK acknowledgments.
- `impact:message-loss`: The issue is about heartbeat OK messages being routed to unintended WhatsApp recipients while preserving alert delivery to relevant users.
- `impact:ux-friction`: Non-admin users can continue using the channel but receive avoidable technical heartbeat noise in shared WhatsApp setups.

## Summary

Keep open: current main and the latest release still expose only heartbeat visibility flags and use one resolved heartbeat delivery target for both OK acknowledgments and alert/content payloads, so the requested admin-only HEARTBEAT_OK routing remains unimplemented.

## What This Changes

Request optional per-user target or targets for WhatsApp/channel HEARTBEAT_OK messages so admins can receive health acknowledgments without broadcasting them to every allowed user.

## Best Possible Solution

Define an additive OK-acknowledgment recipient contract, validate recipients through WhatsApp account and allowlist policy, apply it only to visible HEARTBEAT_OK delivery, and preserve existing alert/content routing plus omitted-config compatibility.

## Reproduction Assessment

Yes, at source level: current main rejects target/targets in strict channel heartbeat config, resolves only visibility booleans, and sends OK acknowledgments through the same resolved heartbeat delivery target. I did not run a live WhatsApp heartbeat.

## Solution Assessment

Unclear pending maintainer product direction. Splitting OK acknowledgment recipients from alert/content routing is the right behavioral boundary, but the final config shape and validation rules need owner approval.
