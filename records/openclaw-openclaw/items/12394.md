## Summary

Keep open: current main still lacks a WhatsApp channel-level heartbeat recipient contract for OK-only admin routing, and implementing it would add compatibility-sensitive config/routing behavior that needs maintainer product direction.

## What This Changes

The issue requests optional channel-level WhatsApp heartbeat recipient fields so `HEARTBEAT_OK` messages can go only to one or more admin targets while alert routing remains user-specific.

## Best Possible Solution

Add a maintainer-approved WhatsApp channel heartbeat recipient contract that validates configured recipients, applies only to visible `HEARTBEAT_OK` acknowledgments, preserves alert/content routing, and updates schema, types, docs, and focused compatibility tests.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: `channels.whatsapp.heartbeat.target` or `targets` is outside the strict schema, and OK acknowledgment delivery uses the shared resolved heartbeat target rather than a channel-level admin recipient list.

## Solution Assessment

Unclear until maintainers choose the product contract. The additive config direction is plausible, but the maintainable fix needs explicit field naming, precedence, validation, and OK-only semantics before implementation.
