## Label Justifications

- `P3`: This is a useful but non-urgent WhatsApp heartbeat ergonomics feature with an existing workaround of disabling visible OK acknowledgments.
- `impact:message-loss`: The issue concerns heartbeat OK messages being routed to every allowed WhatsApp recipient instead of the intended admin recipient set.
- `impact:ux-friction`: Multi-user WhatsApp setups can receive avoidable technical heartbeat noise, but users are not fully blocked because `showOk: false` suppresses the noise.

## Summary

Keep open: current main and v2026.6.11 still model channel heartbeat config as visibility-only, and visible OK acknowledgments use the same resolved delivery target as alert/content delivery. The requested admin-only WhatsApp `HEARTBEAT_OK` routing remains a new, compatibility-sensitive config/product decision.

## What This Changes

Request adds per-user routing for visible WhatsApp channel heartbeat OK messages while preserving existing alert routing.

## Best Possible Solution

Define one additive WhatsApp/channel heartbeat OK-recipient contract, validate recipients against account and allowlist policy, and keep alert/content delivery on the existing relevant-user route.

## Reproduction Assessment

Yes, at source level: current main rejects `target`/`targets` in strict channel heartbeat config and sends visible OK acknowledgments through the same resolved heartbeat delivery target. I did not run a live WhatsApp heartbeat.

## Solution Assessment

Unclear pending maintainer product direction; splitting OK acknowledgment recipients from alert/content routing is the right behavioral boundary, but the permanent config shape and validation rules need owner approval.
