## Label Justifications

- `P3`: This is a useful but non-urgent WhatsApp heartbeat ergonomics feature with an existing workaround of disabling visible OK acknowledgments.
- `impact:message-loss`: The issue concerns visible heartbeat OK messages being routed to every allowed WhatsApp recipient instead of only the intended admin recipients.

## Summary

Keep open: current main still lacks an OK-only per-user WhatsApp heartbeat recipient contract. The existing channel heartbeat config is visibility-only, and visible OK acknowledgments still use the same resolved delivery target as heartbeat alert/content delivery.

## What This Changes

Request adds optional WhatsApp channel heartbeat recipient target(s) so visible `HEARTBEAT_OK` acknowledgments can go only to admins while alert routing remains unchanged.

## Best Possible Solution

Define one additive OK-acknowledgment recipient contract, validate recipients against WhatsApp account/allowlist policy, and keep alert/content delivery on the existing relevant-user route.

## Reproduction Assessment

Yes, at source level: current main rejects `target`/`targets` in strict channel heartbeat config and visible OK sends use the same `delivery.to` route. I did not run a live WhatsApp heartbeat.

## Solution Assessment

Unclear pending maintainer product direction; splitting OK acknowledgment recipients from alert/content routing is the right behavioral boundary, but the permanent config shape and validation rules need owner approval.
