- `P3`: This is a useful but non-urgent WhatsApp heartbeat ergonomics feature with an existing workaround of disabling visible OK acknowledgments.
- `impact:message-loss`: The issue is about heartbeat OK messages being misrouted to every allowed WhatsApp recipient while preserving relevant alert delivery.

## Summary

Keep open: current main and the latest release still expose channel heartbeat config as visibility-only and send visible OK acknowledgments through the same resolved delivery target as alert content, so admin-only WhatsApp HEARTBEAT_OK routing remains unimplemented and needs a product/config decision.

## What This Changes

Request adds optional WhatsApp/channel heartbeat recipient fields so visible HEARTBEAT_OK messages can go only to selected admins while alert messages keep normal routing.

## Best Possible Solution

Define a maintainer-approved additive OK-acknowledgment recipient contract, validate recipients through WhatsApp account and allowlist policy, apply it only to visible HEARTBEAT_OK delivery, and preserve current alert/content routing plus omitted-config compatibility.

## Reproduction Assessment

Yes, at source level: current main rejects channel heartbeat target/targets in strict config, resolves only visibility booleans, and sends OK acknowledgments through the same resolved heartbeat delivery target as alerts. I did not run a live WhatsApp heartbeat.

## Solution Assessment

Unclear pending maintainer product direction. Splitting OK acknowledgment recipients from alert/content routing is the right behavioral boundary, but the final config shape and validation rules need owner approval.
