## Summary

Keep open: current main still lacks the requested channel-level or WhatsApp-account-level heartbeat `target`/`targets` contract for routing OK acknowledgments to selected admins while preserving normal alert routing. The existing source only supports visibility flags at `channels.*.heartbeat`; actual heartbeat delivery still comes from `agents.*.heartbeat.target`/`to`, which is a broader delivery destination, not an OK-only recipient override.

## What This Changes

Request to add optional WhatsApp channel heartbeat `target` or `targets` routing so `HEARTBEAT_OK` messages go only to selected admins while alert messages keep their normal recipient routing.

## Best Possible Solution

Keep this open until maintainers either approve or reject an additive heartbeat recipient contract; if accepted, implement it as a narrow channel/account config surface that applies only to OK acknowledgments, validates recipients through the existing outbound target and WhatsApp allowlist/account rules, preserves alert and commitment routing, and updates schema, generated metadata, docs, and focused tests.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction of the missing capability: `channels.whatsapp.heartbeat` is strict visibility-only config and the runner resolves delivery from `agents.*.heartbeat.target`/`to`, not channel-level OK recipients. I did not run a live WhatsApp heartbeat.

## Solution Assessment

Unclear until maintainers choose the product contract. An additive channel/account-level recipient field is plausible, but the best fix must avoid duplicating the broader agent heartbeat target surface and must preserve alert and commitment routing semantics.
