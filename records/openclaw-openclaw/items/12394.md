## Label Justifications

- `P3`: This is a useful but non-urgent WhatsApp heartbeat ergonomics feature with an existing workaround of disabling visible OK acknowledgments.
- `impact:message-loss`: The issue is about misrouted heartbeat OK messages going to every allowed WhatsApp recipient while relevant alert delivery must remain intact.

## Summary

Keep open: current main still has only visibility-level heartbeat config and sends visible HEARTBEAT_OK acknowledgments to the same resolved heartbeat delivery target, so admin-only WhatsApp OK routing remains a real feature gap that needs maintainer product/config direction.

## What This Changes

The issue requests optional WhatsApp channel heartbeat target/targets config so visible HEARTBEAT_OK acknowledgments can go only to selected admin recipients instead of every allowFrom user.

## Best Possible Solution

Define one additive OK-acknowledgment recipient contract, validate WhatsApp recipients against account and allowlist policy, apply it only to visible HEARTBEAT_OK delivery, and preserve alert/content routing plus omitted-config compatibility.

## Reproduction Assessment

Yes, at source level: current main rejects target/targets in strict channel heartbeat config, resolves only visibility booleans, and sends OK acknowledgments through delivery.to. I did not run a live WhatsApp heartbeat.

## Solution Assessment

Unclear pending maintainer product direction. Splitting OK acknowledgment recipients from alert/content routing is the right behavioral boundary, but the final config shape and validation rules need owner approval.
