## Summary

Keep open: current main and the latest release still expose channel heartbeat config as visibility-only, so WhatsApp has no OK-only per-user recipient contract. This remains a compatibility-sensitive feature/config decision rather than an already-implemented cleanup item.

## What This Changes

The issue requests optional WhatsApp/channel heartbeat recipients so `HEARTBEAT_OK` status messages can go only to admin users while alerts keep their normal routing.

## Best Possible Solution

Keep this issue open until maintainers accept or reject an additive WhatsApp OK-recipient contract with schema, docs, validation against account/allowlist policy, and tests that preserve alert routing.

Options:

- **Define Additive OK Recipients (recommended):** Add a backwards-compatible WhatsApp heartbeat recipient shape for OK acknowledgments only, with account precedence and allowlist validation.
- **Reject Channel OK Recipients:** Keep heartbeat routing on the existing agent-level `target` and `to` fields and avoid adding another channel config surface.
- **Defer To Cross-Channel Routing:** Leave this open under a broader channel heartbeat routing design if maintainers want one contract across WhatsApp and other channels.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: `channels.whatsapp.heartbeat.target` or `targets` is outside the strict channel heartbeat schema, and OK acknowledgments use the same resolved delivery target as alert delivery.

## Solution Assessment

Unclear until maintainers choose the product contract. The requested additive config is plausible, but the best fix needs explicit decisions on field shape, per-account precedence, allowlist validation, and OK-only semantics.
