## Label Justifications

- `P3`: This is a low-urgency enhancement to reduce heartbeat notification noise in shared WhatsApp setups, not a regression or blocked setup path.
- `impact:message-loss`: The requested behavior changes which channel recipients receive heartbeat status messages and must avoid misrouting or suppressing alert delivery.
- `impact:ux-friction`: Shared WhatsApp users currently have to choose between disabling OK visibility entirely or accepting routine technical heartbeat noise for non-admin users.

## Summary

Keep open: current main still lacks OK-only per-user WhatsApp heartbeat routing, and the existing agent-level heartbeat target settings route the whole heartbeat delivery path rather than only healthy acknowledgments.

## What This Changes

Request adds channel/account-level heartbeat recipient targeting so WhatsApp `HEARTBEAT_OK` acknowledgments can go only to selected admins while preserving alert routing.

## Best Possible Solution

Define or reject a narrow WhatsApp/channel heartbeat OK-recipient contract; if accepted, validate targets against account/allowlist policy, apply it only to OK acknowledgments, and update schema, docs, generated metadata, and tests.

Yes. Source inspection shows proposed `channels.whatsapp.heartbeat.target` or `targets` fields are outside the strict channel heartbeat schema, and `HEARTBEAT_OK` delivery uses the same resolved target as alert/content delivery.

## Solution Assessment

Unclear until maintainers choose the product contract. Additive channel/account recipient config is plausible, but it must not redirect alert delivery or duplicate agent-level heartbeat target semantics.
