## Summary

Keep open: current main and the latest release still expose channel heartbeat config as visibility-only, and WhatsApp HEARTBEAT_OK acknowledgments still use the resolved heartbeat delivery target rather than a per-admin OK-recipient list.

## What This Changes

The issue requests an additive WhatsApp/channel heartbeat config field for routing visible HEARTBEAT_OK acknowledgments to selected admin recipients while preserving alert delivery to relevant users.

## Best Possible Solution

Define one additive OK-acknowledgment recipient contract, validate recipients through WhatsApp account and allowlist policy, apply it only to visible HEARTBEAT_OK delivery, and preserve existing alert/content routing plus omitted-config compatibility.

## Reproduction Assessment

Yes, at source level: current main rejects target/targets in strict channel heartbeat config, resolves only visibility booleans, and sends OK acknowledgments through one resolved heartbeat delivery target. I did not run a live WhatsApp heartbeat.

## Solution Assessment

Unclear pending maintainer product direction. Splitting OK acknowledgment recipients from alert/content routing is the right behavioral boundary, but the final config shape and validation rules need owner approval.
