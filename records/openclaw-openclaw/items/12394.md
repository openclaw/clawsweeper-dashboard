## Summary

Keep open: current main still lacks per-user or per-target WhatsApp channel heartbeat OK routing. The existing channel heartbeat surface is visibility-only, while `agents.defaults.heartbeat.target` and `to` choose the whole heartbeat delivery destination rather than routing only OK acknowledgments to admins while preserving alert routing.

## What This Changes

Request to add optional channel-level WhatsApp heartbeat recipient routing so `HEARTBEAT_OK` acknowledgments can go only to selected admin targets instead of every allowed user.

## Best Possible Solution

Keep this issue open until maintainers accept or reject an additive WhatsApp channel heartbeat recipient contract that applies only to OK acknowledgments, preserves alert routing, and includes schema, docs, and focused compatibility coverage.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: `channels.whatsapp.heartbeat.target` or `targets` is outside the strict channel heartbeat schema, and OK acknowledgments use the same resolved heartbeat delivery target as alert delivery.

## Solution Assessment

Unclear until maintainers choose the product contract. The requested additive config is plausible and backward-compatible in shape, but the best fix needs an explicit decision on field name, per-account precedence, allowlist validation, and OK-only semantics.
