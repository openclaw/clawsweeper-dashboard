## Label Justifications

- `P3`: This is a useful but non-urgent WhatsApp heartbeat ergonomics feature with an existing workaround of disabling visible OK acknowledgments.
- `impact:message-loss`: The issue is about channel heartbeat messages being routed to unintended WhatsApp recipients while preserving relevant alert delivery.

## Summary

Keep open: current main still has only visibility controls for channel heartbeat config, and visible WhatsApp HEARTBEAT_OK acknowledgments still use the same resolved heartbeat delivery target as alert/content delivery, so the requested admin-only OK routing remains necessary.

## What This Changes

Request an additive channel or WhatsApp heartbeat setting that routes visible HEARTBEAT_OK messages to selected users without changing alert delivery.

## Best Possible Solution

Maintain current behavior until maintainers choose an additive OK-only recipient contract, then implement it across config/schema/types, WhatsApp validation, heartbeat delivery, docs, and regression tests without changing alert routing.

## Reproduction Assessment

Yes, at source level: current main rejects target/targets in strict channel heartbeat config, resolves only visibility booleans, and sends OK acknowledgments through the same resolved heartbeat delivery target used for alerts. I did not run a live WhatsApp heartbeat.

## Solution Assessment

Unclear pending maintainer product direction. Splitting OK acknowledgment recipients from alert/content routing is the right behavioral boundary, but the final config shape and validation rules need owner approval.
