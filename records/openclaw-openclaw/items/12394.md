## Label Justifications

- `P3`: This is a useful but non-urgent WhatsApp heartbeat ergonomics feature with an existing workaround of disabling visible OK acknowledgments.
- `impact:message-loss`: The issue concerns heartbeat OK messages being misrouted to every allowed WhatsApp recipient while preserving alert delivery.

## Summary

Keep open: current main and the latest release still lack an OK-only WhatsApp heartbeat recipient contract. Channel heartbeat config only controls visibility, while `target`/`to` applies to the whole heartbeat delivery route, so admin-only visible `HEARTBEAT_OK` routing remains a product/config decision.

## What This Changes

The issue requests optional channel-level heartbeat recipient fields so WhatsApp `HEARTBEAT_OK` messages can go only to admin targets instead of every allowed user.

## Best Possible Solution

Define one additive OK-acknowledgment recipient contract, validate recipients against WhatsApp account/allowlist policy, and keep alert/content delivery on the existing relevant-user route.

## Reproduction Assessment

Yes, at source level: current main rejects `target`/`targets` in strict channel heartbeat config and sends OK acknowledgments through the same resolved heartbeat delivery target. I did not run a live WhatsApp heartbeat.

## Solution Assessment

Unclear pending maintainer product direction; splitting OK acknowledgment recipients from alert/content routing is the right behavioral boundary, but the permanent config shape and validation rules need owner approval.
