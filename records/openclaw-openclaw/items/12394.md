## Summary

Keep open: current main still lacks an OK-only WhatsApp heartbeat recipient contract. The existing channel heartbeat config is visibility-only, and `HEARTBEAT_OK` delivery still uses the same resolved heartbeat delivery target as the rest of heartbeat output.

## What This Changes

Request to add optional WhatsApp channel-level heartbeat recipient targeting so `HEARTBEAT_OK` acknowledgments can go only to admins while alerts keep existing routing.

## Best Possible Solution

Define an additive WhatsApp channel heartbeat recipient contract that applies only to OK acknowledgments, validates recipients against the chosen WhatsApp account policy, preserves alert routing, and updates schema, types, docs, and focused tests together.

## Reproduction Assessment

Yes. Source inspection shows `channels.whatsapp.heartbeat.target` or `targets` is rejected by the strict channel heartbeat schema, and OK acknowledgments are sent to the shared resolved heartbeat delivery target.

## Solution Assessment

Unclear until maintainers choose the product contract. The requested additive config is plausible, but the best fix must settle field naming, per-account precedence, validation policy, and OK-only routing semantics.
