## Summary

Keep this issue open, but narrow it to an unverified destructive-path safety bug rather than a demonstrated security vulnerability: the overlap guard does fail open when canonicalization fails, while the reported leaf-symlink example does not yet prove that the later trash operation deletes the symlink target.

## What This Changes

The issue reports that agent workspace deletion can miss shared directories when real-path canonicalization fails and lexical paths are compared instead.

## Best Possible Solution

Canonicalize through the deepest existing ancestor for missing paths, abort deletion on permission, symlink-loop, or other unsafe canonicalization errors, and add an end-to-end regression matrix covering leaf symlinks, symlinked parents, nonexistent workspaces, access failures, and the actual trash target.
