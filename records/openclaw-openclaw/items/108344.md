## What This Changes

The issue requests that session-store capping not evict an isolated cron entry between run-preparation writes when protected entries already exceed `maxEntries`.

## Best Possible Solution

Make `capEntryCount` non-destructive when preserved entries already exhaust the configured budget, preserve active lifecycle entries through all cron writes, and add focused isolated-cron regressions while keeping durable-pointer retention policy in https://github.com/openclaw/openclaw/issues/107750.
