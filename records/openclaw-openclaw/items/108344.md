## Label Justifications

- `P1`: A deterministic session-lifecycle failure can stop every scheduled job on an affected released configuration, making a core automation workflow unreliable for active users.
- `impact:session-state`: Maintenance removes the cron session entry or lifecycle revision while the run still depends on it, causing session ownership and persistence state to drift.

## Summary

Keep open: the released failure is valid, and current main still leaves the underlying protected-entry oversubscription unresolved; the merged retry-policy change addresses only one consequence, while the related post-run report shows that retrying every lifecycle conflict can duplicate completed work.

## What This Changes

Prevent session maintenance from evicting an in-flight cron lifecycle entry during run preparation and ensure lifecycle conflicts receive stage-appropriate retry handling.

## Best Possible Solution

Make maintenance tolerate protected-entry oversubscription without wiping every removable entry, carry explicit in-flight lifecycle protection through the complete cron preparation/finalization transaction, and distinguish pre-work claim conflicts from post-work persistence conflicts so only side-effect-free attempts are retried.

## Solution Assessment

No—the retry-message change alone is not the best fix because it leaves eviction intact and cannot distinguish safe pre-work retries from unsafe post-work retries. The narrow maintainable solution must fix maintenance ownership and carry execution-stage information to the retry boundary.
