## Summary

Keep this PR open for a repair: the fatal-decoder fallback can lose or rethrow buffered partial UTF-8 when corruption arrives in a later chunk, so the proposed best-effort capture path is not safe yet. The contributor’s terminal transcript is useful real-behavior evidence, but it does not cover that streaming boundary.

## What This Changes

The PR replaces the accumulator’s forgiving UTF-8 decoder with fatal decoding plus a binary-data flag and adds malformed-byte tests.

## Best Possible Solution

If maintainers want binary detection here, keep a permissive streaming decoder for displayed output and use an independent fatal decoder only as a detector, then add split-boundary coverage and decide whether the tool-result boundary should surface the flag.
