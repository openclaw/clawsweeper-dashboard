## Summary

Keep open: the reported startup blind spot is valid, but this patch’s first check commonly occurs while a newly started channel is still protected by the longer channel-connect grace, so failed starts with a recent `lastStartAt` can still wait until the five-minute interval. The supplied proof avoids that path by setting channel-connect grace to zero.

## What This Changes

Adds a one-shot channel-health evaluation at startup-grace expiry, centralizes one-shot and interval cleanup, and adds scheduler tests.

## Best Possible Solution

Use a lifecycle-owned schedule that guarantees re-evaluation at the first actionable point after global and per-channel startup grace, then continues the normal cadence while preserving single-flight and stop/abort cleanup.
