## Summary

The linked startup-delay bug remains on current main, and the PR is directionally sound with strong real-process proof. However, independently arming the grace timer and interval permits two back-to-back evaluations when configured values are close, so the scheduler should be phased from the grace-expiry check before merge.

## What This Changes

Adds a one-shot channel-health evaluation at startup-grace expiry alongside periodic checks, centralizes timer cleanup, and adds focused scheduler regression tests.

## Best Possible Solution

Run the first evaluation at grace expiry, then establish the periodic cadence from that lifecycle point so every later evaluation remains one full interval apart, with stop and abort still clearing the complete schedule.
