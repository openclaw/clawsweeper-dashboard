## Summary

## What This Changes

The PR detects Telegram getUpdates requests, applies dispatcher-level undici header/body timeouts within the existing transport-attempt loop, and classifies those timeout errors for transport fallback.

## Best Possible Solution

Keep getUpdates inside the existing transport-attempt lifecycle, choose a socket timeout safely above Telegram's normal 30-second long poll but below the 45-second request abort, add focused ordering/fallback coverage, and demonstrate socket teardown plus resumed polling during a controlled network-path change.
