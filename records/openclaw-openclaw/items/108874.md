## Summary

The revised PR preserves the Telegram transport-attempt loop, but its central recovery path remains ineffective because the existing 45-second request abort fires before the new 60-second headers timeout or 90-second body timeout; after-fix network-flap proof is also still missing.

## What This Changes

The PR adds getUpdates-specific undici headers/body timeouts, routes timeout errors into Telegram transport fallback, and extends dispatcher creation to accept timeout options.

## Best Possible Solution

Keep getUpdates inside the existing transport-attempt machinery, make the relevant socket timeout fire before the 45-second request abort, add focused coverage for timeout-code fallback and dispatcher reuse, then demonstrate redacted live network-flap recovery with polling resuming.
