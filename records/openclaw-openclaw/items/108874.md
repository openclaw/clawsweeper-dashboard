## Summary

Keep this PR open, but do not merge the current patch: the dedicated `getUpdates` path bypasses Telegram’s existing transport-fallback loop, so the same proxy, VPN, DNS, or IPv6 failures targeted by the fix can leave polling unavailable. The PR also lacks after-fix real-network proof. Likely related people: pkuGeo for polling transport recovery, steipete for recent Telegram fetch/test maintenance, and Takhoffman for fallback coverage.

## What This Changes

The PR adds headers and body timeouts to a dedicated Undici dispatcher used only for Telegram `getUpdates` requests.

## Best Possible Solution

Apply the polling-specific Undici timeouts to each existing Telegram transport attempt while preserving sticky fallback selection, HTTP capture, caller-provided dispatcher behavior, and shared dispatcher destruction; add focused routing/lifecycle tests and redacted live network-failure proof.
