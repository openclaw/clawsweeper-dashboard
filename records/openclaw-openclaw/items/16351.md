## Summary

Current main implements validation, guarded writes, environment-reference restoration, SecretRef builders, and non-TTY protection, but interactive bare `openclaw config` still intentionally opens the configure wizard. The remaining root-command and plaintext-secret policy choices need maintainer product and security direction.

## What This Changes

Make bare `openclaw config` non-surprising, add explicit schema validation, and prevent resolved environment secrets from being persisted as plaintext.

## Best Possible Solution

Keep `openclaw configure` as the explicit wizard, make bare `openclaw config` help-first only after a compatibility decision, and steer secret-capable writes to SecretRef builders with a deliberate warning or opt-in strict refusal rather than silently persisting resolved credentials.

Options:

- **Help-first plus warnings (recommended):** Show help for bare `openclaw config`, retain `openclaw configure` and `config --section` as explicit wizard paths, and warn before literal writes to recognized credential paths while recommending SecretRefs.
- **Keep wizard alias:** Preserve current root behavior and improve help text and secret-safe examples without changing compatibility or plaintext-write policy.
- **Strict credential writes:** Require SecretRefs for recognized credential paths unless an explicit unsafe override is supplied, accepting script and upgrade compatibility costs.

## Reproduction Assessment

Yes at source level: interactive no-subcommand config still reaches the full wizard, while a new literal value on a secret-capable path remains possible unless the user selects the existing SecretRef builder path. The historical lack of validation and ordinary placeholder round-trip loss are already fixed.

## Solution Assessment

No single proposed change is automatically best: validation and placeholder preservation are already solved, while root-command behavior and literal-secret policy require a compatibility-conscious product choice. A help-first root plus explicit wizard path and credential warnings is the narrowest balanced direction.
