## What This Changes

Request to make QA coverage own canonical scenario IDs across YAML and live transport catalogs, and to distinguish primary from secondary coverage evidence.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99628, or replace it with an equivalent focused change that keeps qa coverage as the single owner inventory and preserves the existing shared QA host aliases.

## Reproduction Assessment

Yes at source level: current main validates YAML scenario IDs inside the YAML pack and appends live transport lane summaries separately in the coverage inventory, so no unified owner map rejects cross-catalog duplicate scenario IDs.

## Solution Assessment

Yes: extending the existing qa coverage inventory is the best owner boundary because it already reads YAML metadata, scorecard taxonomy, scenario packs, and live lane summaries; a separate registry would duplicate that seam.
