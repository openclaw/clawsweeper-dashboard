## What This Changes

The issue requests QA coverage to reject duplicate scenario IDs across canonical YAML scenarios and legacy live transport catalogs, while allowing supporting-only coverage metadata.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99628, or replace it with an equivalent focused change that keeps `qa coverage` as the single scenario ownership validation path.

## Reproduction Assessment

Yes, at source level: current main validates duplicate IDs inside the YAML scenario pack and appends live transport lane summaries separately, so there is no single owner map spanning both sources.

## Solution Assessment

Yes: extending `qa coverage` is the best owner boundary because the current report path already owns scenario inventory and coverage metadata; a separate registry would duplicate that loader/reporting seam.
