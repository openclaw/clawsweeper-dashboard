- `merge-risk: 🚨 compatibility`: The branch changes existing reconnect semantics from a recoverable failure sequence to cumulative session-lifetime attempts for stable long-lived sessions.

## Summary

Keep open: the PR addresses the flapping-after-ready reconnect storm, but the current patch overcorrects by making `maxReconnectAttempts` a lifetime counter for the session, so a long-lived stable transcription session can stop reconnecting after enough unrelated drops.

## What This Changes

The PR removes the realtime transcription websocket raw-open `reconnectAttempts` reset and adds a focused local `ws` regression test for ready-then-close flapping.

## Best Possible Solution

Keep the shared-helper fix, but reset the reconnect budget only after a connection has stayed ready/stable long enough, with tests for both flap exhaustion and stable recovery past the cap.

Yes. Source inspection plus the PR and linked issue proof show the current raw-open reset defeats the cap/backoff, and the PR head source shows the new lifetime-counter behavior without executing the harness in this read-only review.

## Solution Assessment

No. Deleting the raw-open reset is a plausible mitigation for flapping, but the best fix preserves a reset after a genuinely stable ready recovery so healthy long-lived sessions are not penalized.
