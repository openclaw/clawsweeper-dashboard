## Summary

Keep open: current main and the latest release still allow the fd-backed find tool to return partial stdout after a non-zero fd exit, while this PR is a focused fix with regression coverage and no actionable code-review finding. The only remaining blocker I found is the live QA smoke failure, which needs resolution or rerun before merge.

## What This Changes

The PR makes the fd-backed session find tool reject on any non-zero fd exit, preserves stderr or exit-code errors, adds a fake-fd regression test, and routes that test through the agents test project expectation.

## Best Possible Solution

Land this focused fd close-handler fix after maintainer review and green required checks; keep custom FindOperations behavior and result-limit formatting unchanged.

## Reproduction Assessment

Yes from source: current main rejects non-zero fd exits only when stdout is empty, so a non-zero fd that emitted partial output can resolve successfully. I did not run the reproduction because this review was read-only, but the PR body includes before/after terminal proof.

## Solution Assessment

Yes. Rejecting every non-zero fd close before no-match or result formatting is the narrowest maintainable fix, matches the nearby grep child-process failure invariant, and does not change custom FindOperations behavior.
