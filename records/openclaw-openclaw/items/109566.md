## Summary

The report identifies a credible current-main availability and resource-bounding gap: this provider constructs its WebSocket without explicit handshake or inbound-frame limits. The issue should remain open pending confirmation of limits appropriate for the OpenAI Responses protocol rather than copying values without provider-contract proof.

## What This Changes

Add explicit WebSocket handshake and inbound-frame size bounds to the OpenAI ChatGPT Responses provider.

## Best Possible Solution

Define shared, justified WebSocket limits for this provider, pass them through the constructor, and add focused tests for stalled-handshake termination, oversized-message handling, abort cleanup, and normal streaming.
