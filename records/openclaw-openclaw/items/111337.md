## Summary

Keep this PR open for maintainer review. It introduces a new public plugin SDK and gateway protocol seam, and the current branch still leaves its process-global provider outside the plugin loader’s transactional activation and cleanup lifecycle, so an inactive or failed plugin load can remain registered.

## What This Changes

The branch adds a singleton plugin SDK provider for per-session discussions, two gateway methods and protocol models, plus a Control UI discussion side panel that can embed or externally open a provider URL.

## Best Possible Solution

Adopt the seam only if maintainers want this as a durable generic plugin contract, and make provider registration participate in plugin activation snapshot, restore, and cleanup so only an active plugin can serve discussion requests.
