## Summary

This PR remains necessary: current `main` still uses forgiving UTF-8 decoding in the Anthropic OAuth response path, while the proposed one-line change rejects corrupted token and error bodies before they can be parsed or surfaced. The patch is narrowly scoped, has no discrete correctness or supply-chain concern, and the PR’s terminal before/after evidence is sufficient; normal maintainer review can proceed once the in-progress merge checks settle.

## What This Changes

Changes `src/llm/utils/oauth/anthropic.ts` so Anthropic OAuth HTTP response bytes are decoded with a fatal UTF-8 `TextDecoder`, rejecting malformed response bodies instead of substituting U+FFFD.

## Best Possible Solution

Merge the focused fatal-decoder change after required checks pass, retaining the existing bounded-read path and OAuth caller error handling rather than adding a separate parsing or retry path.

## Reproduction Assessment

Yes from source and supplied live terminal evidence: injecting an invalid `0xFF` byte into the bounded Anthropic OAuth response body reaches the decoder and currently yields U+FFFD rather than a decoding failure. I did not execute the contributor branch in this read-only review.

## Solution Assessment

Yes. Making the existing decoder fatal at the single shared `postJson` boundary is the narrowest maintainable fix because it covers both successful and non-OK OAuth bodies before either path consumes corrupted text.
