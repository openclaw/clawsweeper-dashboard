## Summary

Keep open: current main and v2026.6.11 still lack a selective shared-session config for chosen group/channel/thread chats, and the related open work covers narrower or adjacent routing models rather than superseding this canonical product/security decision.

## What This Changes

Request an opt-in configuration for selected Discord/Slack channel and thread chats to share one agent session while preserving reply origin and isolated defaults.

## Best Possible Solution

Keep this as the broader selective shared-session tracker until maintainers choose one additive, opt-in contract covering explicit channel/thread membership, grouped queue serialization, origin-preserving replies, docs, tests, and security guidance.

## Reproduction Assessment

No runtime bug reproduction is required because this is a feature request; source inspection gives a high-confidence missing-capability reproduction. Non-direct peers still derive isolated keys and strict config cannot express selected channel/thread groups.

## Solution Assessment

Unclear as a final design. `channelGroups` is plausible, but maintainers should reconcile groupScope, named inbound, identity-anchor, and topic-family proposals into one opt-in routing contract before implementation.
