## Summary

Keep open: current main and v2026.6.11 still do not provide an opt-in way to share selected group/channel/thread sessions, and the related open PR only covers narrower group-to-main behavior rather than this broader selected shared-session request.

## What This Changes

Request an opt-in config surface that maps selected Discord/Slack channels or threads to one shared agent session while preserving isolated defaults and origin-specific replies.

## Best Possible Solution

Keep this as the broader selected shared-session tracker until maintainers choose one additive opt-in contract covering selected channels/threads, queue serialization, origin-preserving replies, security guidance, docs, and regression coverage.

## Reproduction Assessment

No bug reproduction is needed for this feature request, but source inspection gives a high-confidence reproduction of the missing capability: non-direct peers still derive isolated keys and strict config cannot express selected channel/thread groups.

## Solution Assessment

Unclear as proposed. session.channelGroups is plausible, but the best solution should reconcile the overlapping groupScope, named inbound session, and identity-routing proposals into one maintainable opt-in contract.
