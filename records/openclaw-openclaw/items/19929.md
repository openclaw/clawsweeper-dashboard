## Summary

Keep open: current main and v2026.6.11 still isolate selected group/channel/thread chats, the strict config surface has no channelGroups-style shared-session option, and the only live implementation candidate is a narrower group-to-main PR that is open and conflicting.

## What This Changes

The issue requests an opt-in configuration that maps selected Discord/Slack channels or threads to one shared session key while preserving isolated defaults and origin-channel replies.

## Best Possible Solution

Keep this as the broader selective shared-session tracker until maintainers choose one opt-in contract covering selected channels/threads, queue serialization, origin-preserving replies, docs, tests, and security guidance.

## Reproduction Assessment

Yes, at source level. Current main deterministically derives isolated keys for non-direct peers and the strict schemas cannot express selected channel/thread groups.

## Solution Assessment

Unclear as proposed. A channelGroups-style config is plausible, but the best solution needs maintainer alignment across groupScope, routeInboundTo, identity-anchor, and topic-family proposals so session routing has one coherent contract.
