## Summary

Keep open: current main and the latest release still lack selective shared sessions for chosen group/channel/thread chats, and the related open groupScope PR is narrower than this request and not a safe canonical replacement.

## What This Changes

Requested an opt-in config surface that maps selected Discord/Slack channels or threads to one shared agent session while preserving reply routing to the originating chat.

## Best Possible Solution

Keep this as the canonical design tracker and land an additive, isolated-by-default session grouping contract only after maintainers settle membership syntax, thread inheritance, sandbox/security behavior, origin reply routing, and regression coverage.

## Reproduction Assessment

Yes, from source inspection rather than a live run: non-direct peers still resolve to isolated channel/group keys, Slack threads still suffix by thread id, and strict session config cannot express selected shared channel/thread groups.

Unclear as proposed: channelGroups is plausible, but the best fix needs a maintainer-approved product/security contract rather than a one-off config field copied from the closed PR.
