## Summary

Keep open: current main and the latest release still lack a selective shared-session contract for chosen group/channel/thread chats, and the related open groupScope PR is narrower, unmerged, conflicting, and not a safe canonical replacement.

## What This Changes

The issue requests an opt-in configuration that maps selected group, channel, and thread chats to a shared session key while leaving unrelated chats isolated.

## Best Possible Solution

Use this issue as the broader product/security tracker for one opt-in shared-session routing contract covering selected channels/threads, isolated defaults, queue serialization, origin-preserving replies, docs, diagnostics, and regression coverage.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: non-direct peers still derive isolated keys, Slack room threads still suffix by thread id, and strict config cannot express selected channel/thread groups. This is a missing feature rather than a broken existing contract.

## Solution Assessment

Unclear as proposed. A channelGroups-style config is plausible, but the best fix should reconcile groupScope, named inbound routing, runtime conversation bindings, and identity-routing proposals into one explicit and secure contract.
