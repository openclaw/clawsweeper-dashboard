## Summary

The early `HEAD` checks are a focused, plausible repair across the three installer entry points, but the submitted real-behavior evidence directly covers the POSIX and CLI paths only; before merge, add redacted PowerShell runtime proof showing an incomplete checkout fails before the update/build flow while a valid existing checkout still succeeds.

## What This Changes

This PR makes the POSIX, CLI, and PowerShell Git installers reject an existing `.git` directory that has no resolvable commit, preventing later checkout and build failures from masking the invalid checkout state.

## System Context

OpenClaw’s Git installers choose between cloning a new repository and updating an existing checkout before installing dependencies and building the CLI. This change validates the existing checkout boundary so an interrupted clone stops with a recovery-preserving message instead of entering the update and build path.
