The PR imports `sliceUtf16Safe` and uses it in node-host `truncateOutput` for tail truncation of exec event output.

## Best Possible Solution

Use UTF-16-safe slicing at every exec-event truncation boundary, especially node-host tail truncation and gateway `compactExecEventOutput`, with a focused regression for the final enqueued event text.

## Reproduction Assessment

Yes, at source level. Current main's node-host tail slice can produce an ill-formed string, and a focused probe shows the PR's safe node-host output can still become ill-formed at the gateway exec-event compaction boundary.

## Solution Assessment

No. Reusing `sliceUtf16Safe` in node-host is correct, but the best fix must also cover the later gateway compaction boundary that shapes the final agent/channel system event.
