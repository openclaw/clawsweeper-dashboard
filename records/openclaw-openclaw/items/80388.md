## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P1] Use a fixed opaque sandbox for plugin entry frames:** `ui/src/pages/plugin/plugin-page.ts:180`
  - body: This reuses `embedSandboxMode` for plugin entry iframes. When operators set the existing embed mode to `trusted`, `resolveEmbedSandbox` returns `allow-scripts allow-same-origin`, so plugin-owned app pages lose the opaque-origin isolation described by the PR's security model; entry frames should use a fixed sandbox without `allow-same-origin`, independent of assistant embed settings.
  - confidence: 0.9
- **[P1] Fail closed when in-app entry launch fails:** `ui/src/pages/plugin/plugin-page.ts:157-160`
  - body: The catch path still sets the iframe source to the raw plugin path after launch RPC denial or failure. That bypasses the short-lived launch URL and turns an unavailable entry into a direct protected-route load, masking authorization failures and weakening entry-scoped `requiredScopes`; render an error or empty state instead.
  - confidence: 0.86
- **[P1] Fail closed when sidebar entry launch is unavailable:** `ui/src/components/app-sidebar.ts:1301-1320`
  - body: When there is no Gateway client or the launch RPC fails, this returns `entryPoint.path` and the click handler opens or navigates to it for same/new-window entries. Those modes should not fall back to raw protected plugin routes after the entry-scoped launch path fails; close the reserved window and surface the launch error instead.
  - confidence: 0.84
