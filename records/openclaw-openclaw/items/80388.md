## Summary

Keep open: current main still lacks plugin Control UI entry points, but this PR is not merge-ready because same-window/new-window plugin pages bypass the sandboxed iframe boundary and the live PR is currently dirty/not mergeable.

## What This Changes

The PR adds plugin-registered Control UI app-nav entry points across the plugin SDK, Gateway protocol/RPC launch tokens, Control UI navigation/rendering, docs, Swift models, and tests.

## Best Possible Solution

Expose only sandboxed in-app plugin entries until maintainers approve an isolated-origin or otherwise explicit top-level plugin-page trust model, then rebase and refresh exact-head proof.

## Reproduction Assessment

Yes for the PR-head review findings: source inspection shows the top-level open modes navigate directly to plugin routes on the Control UI origin while the in-app mode uses a sandboxed iframe, and the entry-point Gateway response spreads raw registry objects without result validation.

## Solution Assessment

No. The sandboxed in-app entry path is a plausible v1, but same-window/new-window modes need explicit isolation/security design and entry-point projection should mirror the strict validated descriptor response before this becomes public plugin API.

## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Keep plugin entry pages inside the sandbox:** `ui/src/ui/app-render.helpers.ts:352-362`
  - body: The `same-window` and `new-window` branches navigate directly to `/plugins/<id>/...` on the Control UI origin. Those pages are not the sandboxed iframe from `renderPluginUiEntryPointFrame`, so plugin JavaScript can read same-origin Control UI storage such as gateway token/settings state; keep v1 entries sandboxed or add isolated-origin top-level plugin pages first.
  - confidence: 0.9
- **[P2] Validate entry-point responses before sending:** `src/gateway/server-methods/plugin-host-hooks.ts:139-145`
  - body: `plugins.uiEntryPoints` spreads `entry.entryPoint` and responds without validating against the new protocol result schema. Since registration preserves extra fields with `{ ...entryPoint }`, untyped plugins can leak unsupported fields or invalid shapes to clients; mirror the strict whitelisted projection and result validation used by `plugins.uiDescriptors`.
  - confidence: 0.86
