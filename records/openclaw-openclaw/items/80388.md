## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Keep plugin entry pages in the sandbox:** `src/plugins/registry.ts:1956-1960`
  - body: This new public contract accepts `same-window` and `new-window`, and the sidebar navigates those launch paths as top-level same-origin pages. That bypasses the opaque iframe/MessagePort boundary this feature relies on, so remove these modes or move them behind a separate-origin maintainer-approved design before merge.
  - confidence: 0.93
- **[P1] Use an opaque sandbox for entry frames:** `ui/src/pages/plugin/plugin-page.ts:180`
  - body: Entry frames inherit `context.config.current.embedSandboxMode`; when that setting is `trusted`, `resolveEmbedSandbox` returns `allow-scripts allow-same-origin`. Plugin UI is served from `/plugins/...` on the Control UI origin, so that mode is not opaque and undermines the plugin isolation model; use a fixed entry-frame sandbox instead.
  - confidence: 0.92
- **[P2] Fail closed when entry launch fails:** `ui/src/pages/plugin/plugin-page.ts:157-160`
  - body: If `plugins.uiEntryPointLaunch` rejects because the entry is unavailable, hidden by scopes, or cannot mint a launch token, this catch still loads the raw plugin path. That can fall through to normal plugin auth or a previously minted plugin UI session cookie instead of enforcing the failed launch decision; keep the frame empty and show an error state.
  - confidence: 0.88
