- **[P1] Use a fixed opaque sandbox for entry frames:** `ui/src/pages/plugin/plugin-page.ts:180`
  - body: This still feeds plugin entry iframes through the global embed sandbox mode. In current code, the `trusted` mode resolves to `allow-scripts allow-same-origin`; because plugin entries are same-origin `/plugins/...` pages, that removes the opaque-origin boundary this PR relies on. Use a fixed plugin-entry sandbox such as `allow-scripts` and keep privileged communication on the bridge.
  - confidence: 0.9
- **[P2] Fail closed when launch token minting fails:** `ui/src/pages/plugin/plugin-page.ts:159`
  - body: If `plugins.uiEntryPointLaunch` rejects, this renders the raw plugin route path in the iframe instead of refusing to load the entry. That bypasses the launch/session token path the PR adds and can hide auth failures or use broader ambient gateway auth; the same fail-open fallback exists in the sidebar external-mode helper. Leave the frame/window empty or show an error unless a scoped launch path was minted.
  - confidence: 0.86
