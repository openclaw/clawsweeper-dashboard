## Summary

## What This Changes

The PR adds plugin-registered Control UI app-nav entry points across the Plugin SDK, Gateway protocol/RPC launch tokens, Control UI navigation/rendering, docs, Swift protocol models, and tests.

## Best Possible Solution

Expose only sandboxed in-app plugin entries for v1, or add an explicit isolated-origin/top-level plugin-page trust model before public SDK/Gateway surfaces land.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes for the PR-head blocker: source inspection shows `same-window` and `new-window` navigate directly to same-origin plugin routes while Control UI stores gateway tokens in sessionStorage.

## Solution Assessment

Is this the best way to solve the issue? No. The sandboxed in-app path is an acceptable first shape, but top-level plugin pages need an isolated-origin trust model or explicit maintainer security approval before becoming public plugin API.
