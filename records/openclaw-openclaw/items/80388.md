  - body: The new entry-point metadata lets a plugin set `openMode` to `same-window` or `new-window`, and this handler honors that by navigating the top-level window to the plugin route. That lets plugin-served UI opt out of the iframe sandbox through plugin metadata; keep v1 in-app only or gate top-level launch behind an explicit trusted-plugin contract.
  - confidence: 0.9

  - body: The PR proof relies on sandboxed opaque-origin iframes, but this frame uses the global embed sandbox setting. In `trusted` mode that helper returns `allow-scripts allow-same-origin`, so an operator setting for other embeds removes plugin-entry isolation; use a fixed plugin-entry sandbox such as `allow-scripts` unless a trusted-plugin path is explicitly approved.
  - confidence: 0.88
- **[P2] Fail closed when entry launch fails:** `ui/src/pages/plugin/plugin-page.ts:157-160`
  - body: If the launch RPC throws, the frame falls back to the raw plugin path. On setups where normal gateway HTTP auth succeeds, the plugin route can run outside the narrowed entry-token authority, and on token-only setups it degrades to a 401; render an error or empty state instead of loading the raw path.
  - confidence: 0.78
