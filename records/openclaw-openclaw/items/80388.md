- **[P1] Keep plugin pages inside the sandbox:** `ui/src/components/app-sidebar.ts:1322`
  - body: This still lets a plugin entry choose `same-window` and then navigates the top-level Control UI window to the plugin route. This is the same security-boundary blocker from the previous review cycle; keep entry points in the sandbox unless maintainers explicitly approve a separate top-level plugin-page design.
  - confidence: 0.9

  - body: Entry-point iframes inherit the global embed sandbox mode. When `gateway.controlUi.embedSandbox` is `trusted`, `resolveEmbedSandbox` returns `allow-scripts allow-same-origin`, which removes the opaque-origin protection this feature relies on for plugin-owned pages. Use a fixed plugin-entry sandbox such as `allow-scripts` instead of the generic assistant-embed setting.
  - confidence: 0.88
- **[P2] Fail closed when launch authorization fails:** `ui/src/components/app-sidebar.ts:1277`
  - body: On `plugins.uiEntryPointLaunch` failure this returns the raw plugin path, and the in-app page has the same fallback. If the entry disappeared, scopes changed, or token minting failed, the UI should show an unavailable/error state and close any reserved window, not try the unlaunched route with whatever ambient or stale auth may exist. This re-raises the prior fail-closed blocker.
  - confidence: 0.86
