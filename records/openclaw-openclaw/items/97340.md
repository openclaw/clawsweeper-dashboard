## Risks / Open Questions

- Compatibility: `channels.msteams.accounts` and `defaultAccount` become a new public Teams config contract while legacy root-level singleton config must keep working as the implicit default account.
- Auth/provider: named Teams accounts intentionally require explicit bot identity, credential or federated auth material, and webhook port and do not use env fallback, so existing operator assumptions about root credentials or one listener for every account could fail.
- Session-state: conversation references, polls, sent-message cache, SSO tokens, delegated tokens, Graph actions, and proactive sends now carry account identity, so maintainers need to accept the default-account compatibility and isolation model.
