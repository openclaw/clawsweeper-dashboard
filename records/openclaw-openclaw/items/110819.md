## Summary

The PR remains useful, but it still overwrites caller-supplied `timeout` and `killSignal` values after spreading `options`; preserve explicit caller limits while retaining the new bounded defaults before merge.

## What This Changes

The branch adds a 120-second timeout and `SIGKILL` timeout signal to the synchronous `gh` helpers in `scripts/lib/plain-gh.mjs`.

## Best Possible Solution

Keep the shared 120-second and `SIGKILL` defaults, but apply them only when the caller did not provide that option and add focused coverage for both defaults and explicit overrides.

## Maintainer Decision

## Reproduction Assessment

Yes from source: passing `{ timeout: 500 }` or a different `killSignal` to any exported helper is overwritten by the unconditional properties following `...options`; the submitted blocking-`gh` probe also shows the new default-bound path works.

## Solution Assessment

No; a shared bounded default is the right repair, but unconditional assignments are not the narrowest solution because they silently discard supported caller options. Nullish defaults preserve both the fail-fast baseline and per-call control.
