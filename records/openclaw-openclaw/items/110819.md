## Summary

The prior caller-override blocker remains on the current head: each helper spreads `options` and then unconditionally replaces its `timeout` and `killSignal`. The bounded default is useful, but this branch is not ready to merge until explicit caller process settings are preserved.

## What This Changes

The PR adds a shared 120-second timeout and `SIGKILL` timeout signal to the synchronous `gh` helper calls in `scripts/lib/plain-gh.mjs`.

## Best Possible Solution

Keep the 120-second bounded default, but apply it only when callers did not provide `timeout` or `killSignal`, and cover both defaulting and explicit override behavior in focused helper tests.

## Reproduction Assessment

Yes, at source level: pass explicit `timeout` or `killSignal` values to a helper and observe that the properties written after `...options` replace them. The PR’s blocking-`gh` terminal probe also establishes the default timeout path, though it does not exercise the override contract.

## Solution Assessment

No. A bounded default is the right direction, but unconditional assignment after `...options` is not the narrowest safe solution because it replaces valid caller policy; nullish defaults retain both behaviors.
