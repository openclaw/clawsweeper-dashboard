## Summary

Keep open: current main fixes the iOS side through https://github.com/openclaw/openclaw/pull/100768, but the issue discussion and current macOS source still show no custom-header storage, settings surface, or `extraHeadersProvider` wiring for macOS Gateway connections.

## What This Changes

The issue requests native app support for authenticating reverse-proxy credentials on Gateway WebSocket upgrades, with iOS now landed and macOS parity still remaining.

## Best Possible Solution

Add macOS parity using the landed per-gateway custom-header contract: secure per-gateway storage, TLS-only injection into Gateway sessions, reset/redaction behavior, focused macOS tests, and real reverse-proxy proof.
