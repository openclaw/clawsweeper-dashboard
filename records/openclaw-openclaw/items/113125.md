## Label Justifications

- `P2`: This fixes a bounded but user-visible performance and event-loop responsiveness problem in Anthropic tool-call streaming.
- `merge-risk: 🚨 compatibility`: The diff intentionally changes when parsed partial tool-call arguments refresh during streaming, which existing consumers could observe.

## Summary

The previous compatibility blocker was addressed by removing the new 256 KB cap, and the updated PR now supplies terminal evidence for the real transport path. The remaining decision is normal maintainer review of a deliberate compatibility tradeoff: partial tool-argument previews update at a 4,096-character cadence rather than after every fragment, while final arguments remain authoritatively parsed at block completion.

## What This Changes

The PR coalesces native Anthropic streamed tool-argument parsing to every 4,096 characters of growth, adds a final parse when the tool block stops, yields cooperatively between stream events, and adds regression tests for parsing correctness and uncapped large arguments.

## System Context

Anthropic’s native Messages transport receives streamed server events and accumulates `input_json_delta` fragments for tool calls. It publishes incremental tool-call updates while streaming, then produces final parsed arguments for the agent runtime when the content block completes.

## Architecture Diagram

## Best Possible Solution

Keep the native Anthropic transport uncapped, retain the final authoritative parse, and land the coalescing approach only after maintainers accept the bounded partial-preview freshness tradeoff and required checks pass on a refreshed head.
