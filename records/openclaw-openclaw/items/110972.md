## Summary

This remains a concrete Docker Compose reliability bug: current main keeps a long-running `openclaw-cli` in the gateway’s network namespace while the image-level loopback health check also applies to that sidecar, and the bundled file does not define dependent restart propagation or a CLI-specific health-check override.

## What This Changes

Report that restarting the Docker Compose gateway leaves the long-running CLI sidecar in its former shared network namespace, causing its inherited gateway health check to remain unhealthy.

## Best Possible Solution

Establish one supported restart path for the shared-network sidecar, validate it on Docker Desktop and Docker Engine, then make the Compose health-check and Docker guide match that path—prefer a CLI-specific health-check policy over relying on an implicit inherited gateway probe.
