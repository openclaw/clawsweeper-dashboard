Full review comments:

- **[P1] Normalize presence reasons before persisting state:** `src/gateway/server-node-events.ts:695`
  - body: The PR head still persists `obj.trigger` after only `normalizeOptionalString`, so a compromised or buggy node can write arbitrary or very large reason strings into durable pairing metadata. Use the closed reason normalizer before persistence, as the current merged implementation does.
  - confidence: 0.9
- **[P1] Bound the presence throttle map:** `src/gateway/server-node-events.ts:46`
  - body: `recentNodePresencePersistAt` is a process-wide `Map` with no TTL or size limit, keyed by presence identity. High-cardinality node traffic can grow memory and repeatedly drive metadata lookup work; bound/prune it and avoid recording entries for unpaired identities.
  - confidence: 0.88
- **[P2] Require handled beacon responses before recording success:** `apps/ios/Sources/Model/NodeAppModel.swift:3795-3798`
  - body: The iOS branch ignores the `node.event` response body and treats any successful RPC as a beacon success. Older gateways or unhandled events can then set the local recent-success throttle without durable gateway persistence, suppressing later real beacons.
  - confidence: 0.84
