## Summary

Keep this PR open for maintainer review: it addresses a credible workspace-remapping regression, but its warning-only non-interactive behavior changes the result of an explicit `--workspace` request without giving automation a failure or confirmation path.

## What This Changes

The branch adds a guard across onboarding and setup flows that preserves an existing fleet workspace by default, requires interactive confirmation to move it, and documents the resulting rerun behavior.

## Best Possible Solution

Preserve the existing-fleet safety guard, but make a non-interactive workspace conflict machine-detectable and provide a documented explicit consent path only if maintainers want unattended fleet moves to remain supported.
