## Summary

Keep this PR open: it changes the established `0` timeout behavior from effectively unbounded to a 10-minute cap without proving that zero is invalid or providing an upgrade path, and the submitted test output is not real cron-runtime proof.

## What This Changes

The PR makes non-positive `timeoutSeconds` and `noOutputTimeoutSeconds` fall back to command defaults and adds focused cron command-runner tests.

## Best Possible Solution

Preserve the existing zero-as-unbounded contract unless maintainers explicitly choose to retire it; if retiring it, migrate or reject stored zero values through the appropriate doctor/config path and prove both fresh-install and upgrade behavior.
