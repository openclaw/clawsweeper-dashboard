## What This Changes

Add an optional governance plugin that authorizes tool and shell calls, scans arguments for PII, applies session budgets, and writes structured audit records.

## System Context

Agent runs expose available tools through core policy and sandbox controls, then invoke plugin hooks immediately before a selected tool executes. A governance plugin can evaluate that host-provided tool context, retain per-session accounting, and emit its own audit evidence while core continues to enforce its existing tool and sandbox boundaries.

## Architecture Diagram

flowchart LR
  A[Channel or scheduled run] --> B[Agent selects a tool]
  B --> C[Core tool and sandbox policy]
  C --> D[Governance plugin pre-tool hook]
  D -->|Allow| E[Tool execution]
  D -->|Deny or approval| F[Structured agent response]
  E --> G[Usage and audit events]
  G --> H[Plugin session budget and evidence store]

## Best Possible Solution

Publish a standalone native OpenClaw governance plugin through ClawHub, using typed pre-tool hooks plus plugin-owned session accounting and audit storage; ship explicit observe/monitor/enforce semantics, a strict config schema, redacted evidence output, install/update documentation, example policy, and fresh-install smoke proof. If real implementation shows a specific hook cannot enforce an invariant across supported harnesses, open a narrow core API issue for that missing seam rather than bundling TealTiger policy in core.
