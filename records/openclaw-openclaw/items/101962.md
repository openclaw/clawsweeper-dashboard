## Summary

Keep open. Current main still exposes completed tool-call stream events before response completion, but the core agent loop executes tools only after the final assistant message returns; this is a real latency feature that needs maintainer scheduling and safety design, not conservative cleanup.

## What This Changes

The issue requests an opt-in execute-on-parse mode that starts each fully parsed streaming tool call before the rest of the assistant tool-call batch finishes streaming.

## Best Possible Solution

Design a maintainer-approved core agent-loop mode that starts only completed, safety-declared independent tool calls during streaming while preserving transcript validity, ordering, hooks, approvals, cancellation, and a clear opt-in/default policy.
