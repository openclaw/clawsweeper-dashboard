## Summary

Keep open. Current main still waits for the completed streamed assistant response before dispatching tool calls, so the latency-focused execute-on-parse request remains necessary and needs maintainer design rather than cleanup closure.

## What This Changes

The issue requests an opt-in mode that starts each fully parsed streaming tool call before the rest of the tool-call batch finishes streaming.

## Best Possible Solution

Design a maintainer-approved opt-in core scheduler that overlaps streaming and tool execution only for calls with explicit concurrency-safety and lifecycle semantics, likely coordinated with the tool-classification work in https://github.com/openclaw/openclaw/issues/62962.
