## Summary

Keep open. Current main still exposes completed streaming tool-call events before final response completion, but the agent loop only executes collected tool calls after the final assistant message returns, so this remains a real core performance feature request that needs maintainer design rather than cleanup.

## What This Changes

The issue requests an opt-in execute-on-parse mode that starts independent tool calls as soon as their streamed arguments are complete.

## Best Possible Solution

Design a maintainer-approved core agent-loop mode that can start only safe completed tool calls during streaming while preserving transcript validity, ordering, hooks, approvals, cancellation, and a clear opt-in/default policy.
