## Summary

Keep open. Current main still only starts tool execution after the streamed assistant response has finalized; execute-on-parse remains a core agent-loop performance feature that needs maintainer design rather than conservative cleanup.

## What This Changes

Requested opt-in execute-on-parse mode so fully parsed streaming tool calls can start before the full streamed assistant response completes.

## Best Possible Solution

Design a maintainer-approved core agent-loop mode that starts only eligible completed tool calls during streaming while preserving transcript validity, hook ordering, approvals, cancellation, progress, and a clear opt-in/default policy.

Unclear. Execute-on-parse is plausible, but the best fix is not a parser-only listener; it needs a designed core scheduling mode with safety, transcript, hook, approval, cancellation, and opt-in semantics.
