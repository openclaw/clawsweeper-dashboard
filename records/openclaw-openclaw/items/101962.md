## Summary

Keep open. Current main still exposes completed streamed tool-call events before response completion, but the core loop only starts tool execution after the final assistant response is returned; this is a real latency feature request that needs maintainer product and safety design rather than cleanup closure.

## What This Changes

The issue requests an opt-in execute-on-parse mode that starts each fully parsed streamed tool call before the rest of the assistant tool-call batch finishes streaming.

## Best Possible Solution

Design a maintainer-approved core scheduling mode that can start only safe completed tool calls during streaming while preserving transcript validity, source-order result artifacts, hooks, approvals, cancellation, and an explicit default or opt-in policy.
