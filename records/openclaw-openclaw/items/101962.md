## Summary

Keep open. Current main still exposes completed streaming tool-call events before response completion, but the agent loop waits for the final assistant message before executing any tools, so the requested latency improvement remains real and needs maintainer design rather than cleanup closure.

## What This Changes

The issue requests an opt-in execute-on-parse mode that starts independent tool calls as soon as their streamed arguments are fully parsed instead of waiting for the whole assistant response to finish.

## Best Possible Solution

Design a maintainer-approved opt-in core agent-loop mode that starts only safe completed tool calls during streaming while preserving transcript validity, event ordering, hooks, approvals, cancellation, and default compatibility.
