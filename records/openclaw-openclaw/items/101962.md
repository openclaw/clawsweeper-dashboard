## Summary

Keep open. Current main still treats completed streaming tool-call events as assistant-message updates and only dispatches tools after the final streamed assistant response returns, so the central latency request remains real but needs maintainer product and safety design rather than conservative cleanup.

## What This Changes

The issue requests an opt-in mode that starts independent tool calls as soon as each streamed tool-call argument object is complete, instead of waiting for the full streamed assistant response to finish.

## Best Possible Solution

Keep this open for a maintainer-approved, default-safe agent-core design that starts only explicitly safe completed tool calls during streaming and proves transcript ordering, hooks, approvals, cancellation, and provider-stream behavior.
