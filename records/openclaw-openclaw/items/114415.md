## Summary

Keep this PR open for a corrected route-identity fix. The reported reconnect draft loss is credible, but the new same-route rule cannot distinguish a user navigating between two unresolved agents in the same catalog, so it can retain a draft for the wrong destination; the protected `maintainer` label also requires human handling.

## What This Changes

This PR changes new-session route tracking so a catalog agent resolving after Gateway reconnection does not clear the composer draft and can replace a temporary fallback agent.

## System Context

The web UI’s new-session page derives a draft identity from URL-selected agent and catalog fields while the Gateway supplies catalog and agent metadata. That identity controls whether the composer is reset or retained as connection state changes.

## Architecture Diagram

## Best Possible Solution

Keep the requested URL agent identity separate from the Gateway-resolved agent identity, and reset the draft whenever the requested agent or catalog changes even if both agents are currently unresolved.

## Solution Assessment

No. Treating an empty resolved agent as interchangeable with any later agent in the same catalog loses the requested URL identity; the route loader or route data should preserve that identity separately and compare it before retaining a draft.
