## Label Justifications

- `P1`: Affected subscription-only Claude CLI users lose active-memory recall on every eligible turn or incur unexpected metered usage in a normal configured workflow.
- `impact:auth-provider`: The defect routes Claude subscription OAuth credentials through the direct Anthropic API path instead of the configured Claude CLI runtime.
- `impact:session-state`: Failed recall suppresses relevant memory context on each affected turn, causing the agent’s effective conversational state to omit configured active memory.

## Summary

Keep this issue open: the documented Claude CLI runtime contract and the reporter’s current-main logs support a real runtime-routing defect, and the linked fix remains open and unmerged. The issue should stay paired with that implementation candidate rather than spawning a competing repair.

## What This Changes

Ensure active-memory recall and similar embedded helper runs honor a session’s configured Claude CLI runtime instead of sending subscription OAuth credentials through the direct Anthropic API path.

## Best Possible Solution

Use one shared runtime-owned dispatch seam so subscription-authenticated embedded helpers execute through the configured Claude CLI backend while preserving strict tool grants, transcript and abort contracts, and API-key behavior; validate active memory and the known sibling helper paths before landing the linked PR.

## Reproduction Assessment

Yes. The report gives an exact current-main configuration and real logs/transcripts showing active-memory recall selecting `anthropic-messages` under provider `claude-cli`, followed by the deterministic subscription billing rejection.

## Solution Assessment

The desired runtime consistency is the correct fix, but it is not yet clear that an active-memory-specific opt-in is the best implementation. A shared helper dispatch seam covering the known sibling paths would be narrower architecturally and less likely to drift.
