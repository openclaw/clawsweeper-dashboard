## Summary

Keep this PR open for revision: it improves the obvious unbounded-read paths, but the `statSync`-then-`readFileSync` sequence does not actually enforce the advertised memory bound against a file that grows or is replaced between operations, and the new 1 MiB rejection changes existing AGENTS.md behavior without an explicit compatibility decision.

## What This Changes

The branch adds 1 MiB and 10 MiB caps to session context and command-line prompt-input file reads, with tests for oversized and normal files.

## Best Possible Solution

Use a descriptor-based bounded read that reads at most the configured limit plus a sentinel byte, then land only after maintainers choose and document the compatibility behavior for existing oversized project-context files and the contributor supplies a redacted real-run proof.
