## Summary

Keep open: current main has explicit manual ClawHub skill/plugin update commands and a separate package auto-updater, but not the requested unattended update flow for installed skills and plugins. This remains a product and supply-chain policy decision, not a conservative cleanup close.

## What This Changes

Requested opt-in unattended updates for installed ClawHub skills and OpenClaw plugins, likely on gateway startup or an interval.

## Best Possible Solution

A maintainer-owned opt-in design should reuse the explicit skill/plugin update primitives while preserving ClawHub trust checks, security.installPolicy, provenance, pinning, rollback, audit, and clear failure behavior.

## Reproduction Assessment

Not applicable: this is a feature request, not a broken existing behavior report. Source, docs, and tests confirm explicit manual update commands and package-only auto-update, but not unattended skill/plugin updates.

## Solution Assessment

Unclear as proposed: native background updates may be useful, but adding simple booleans under skills and plugins is not enough without a maintainer-approved trust and lifecycle design.
