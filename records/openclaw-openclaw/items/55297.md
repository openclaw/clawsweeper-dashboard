## Summary

Keep open: current main and the latest release still provide explicit skill/plugin update commands and core package auto-update, but not the requested unattended auto-update flow for installed skills and plugins. The remaining work needs maintainer product and supply-chain policy decisions before it is safe to implement.

## What This Changes

Request an opt-in background auto-update mechanism for ClawHub-installed skills and OpenClaw plugins, likely through config and gateway start or interval checks.

## Best Possible Solution

Keep this open for a maintainer-owned opt-in design that composes the existing explicit update primitives with ClawHub trust data, installPolicy, provenance, pinning, rollback, audit logging, restart behavior, and clear failure semantics.

## Reproduction Assessment

Not applicable: this is a feature request, not a broken existing behavior report. Source and docs confirm manual skill/plugin update commands and package-only auto-update, with no current skill/plugin auto-update config surface.

## Solution Assessment

Unclear as proposed: the user problem is real, but adding simple booleans under skills/plugins is not enough for a safe maintainer-approved lifecycle. The best path is a trust-aware opt-in updater design rather than a narrow config-only patch.
