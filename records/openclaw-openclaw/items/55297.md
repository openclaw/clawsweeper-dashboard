- `impact:security`: The requested auto-update behavior directly affects the supply-chain boundary for executable skills and plugins fetched from ClawHub/npm.
- `impact:ux-friction`: Existing users must manually run documented update commands or set up their own scheduler to receive plugin and skill fixes.

## Summary

Keep open: current main has manual plugin and skill update commands plus core package auto-update, but no background auto-update for installed skills/plugins. Because that would auto-fetch executable third-party code, the remaining work needs maintainer product and security direction.

## What This Changes

Request adds opt-in auto-update for installed ClawHub skills and managed plugins, likely via config plus gateway startup or interval scheduling.

## Best Possible Solution

Design a maintainer-approved updater that keeps manual commands as the baseline and adds an explicit opt-in path with trust checks, version pinning behavior, rollback/status reporting, and visible recovery for failed updates.
