## Summary

Keep open: current main and the latest release still provide OpenClaw package auto-update plus explicit skill/plugin update commands, but not the requested unattended ClawHub skill/plugin updater. The remaining work is a product and supply-chain security decision, not a narrow bug fix.

## What This Changes

The issue requests an opt-in unattended auto-update mechanism for ClawHub skills and OpenClaw plugins.

## Best Possible Solution

A maintainer-owned, default-off design should reuse the existing explicit update primitives while defining provenance, installPolicy, pinning, rollback, audit, and failure behavior before adding config or startup automation.

Options:

- **Design gated opt-in updater (recommended):** Add the feature only after maintainers define a default-off policy covering ClawHub trust/provenance, security.installPolicy, pinning, rollback, audit logs, and failure handling.
- **Keep explicit updates only:** Leave openclaw skills update and openclaw plugins update as the supported path and document external scheduling for operators who accept that risk.
- **Split prerequisites first:** Track signing, rollback, provenance, and scorecard work before deciding whether background automation is acceptable.

## Solution Assessment

Unclear as proposed: native background updates may be useful, but adding booleans under skills/plugins is not enough without a maintainer-approved trust and lifecycle design. The safer end state is a gated, default-off updater built on the existing explicit update primitives.
