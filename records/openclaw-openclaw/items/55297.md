## Summary

Keep open: current main and the latest release still lack the requested unattended skill/plugin updater. Existing code covers manual skill/plugin update commands plus package auto-update and post-core plugin sync, and the remaining work needs maintainer product and security design because it would apply third-party code automatically.

## What This Changes

Request to add opt-in automatic updates for installed ClawHub skills and OpenClaw plugins, likely through new configuration and gateway startup or interval behavior.

## Best Possible Solution

Keep this open for a maintainer-owned opt-in design that reuses the existing explicit update primitives only after ClawHub trust, provenance, pinning, rollback, audit, install-policy, and failure semantics are defined.

## Reproduction Assessment

Not applicable: this is a feature request, not a broken existing behavior report. Source and docs confirm manual skill/plugin update paths and package-only auto-update, so the requested unattended skill/plugin updater is absent.

## Solution Assessment

Unclear as proposed: native background updates may be useful, but booleans under `skills` and `plugins` are not enough without a maintainer-approved trust and lifecycle design. A safer direction is an explicit opt-in updater that composes existing update commands with ClawHub policy, pinning, rollback, and audit semantics.
