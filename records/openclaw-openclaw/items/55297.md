## Label Justifications

- `P2`: This is a normal-priority ecosystem feature with real update friction, but it is not a broken existing workflow or release blocker.
- `impact:security`: The requested behavior would automatically fetch and apply third-party skill/plugin code after installation.
- `impact:ux-friction`: Users and plugin/skill authors currently need manual update commands or external scheduling for installed package fixes to propagate.

## Summary

Keep open: current main and the latest release still provide explicit skill/plugin update commands and package auto-update, but not the requested unattended auto-update mechanism for installed ClawHub skills and plugins. The remaining work is a product and supply-chain policy decision because it would introduce background third-party code updates, likely new config, and startup/update lifecycle behavior.

## What This Changes

The issue requests an opt-in auto-update mechanism for installed ClawHub skills and OpenClaw plugins so published fixes reach existing installations without manual update commands.

## Best Possible Solution

Keep this open for a maintainer-owned design that composes the existing explicit update primitives with ClawHub trust checks, install-policy enforcement, provenance, pinning, rollback, audit, scheduling, and clear user-visible status.

## Reproduction Assessment

Not applicable as a bug reproduction: this is a feature request for unattended updates. Current source and docs give a high-confidence behavior check showing only explicit manual skill/plugin update commands plus separate package auto-update.

## Solution Assessment

Unclear as proposed: an opt-in updater may be the right product direction, but adding booleans under `skills` and `plugins` is not enough without a maintainer-approved trust, rollback, scheduling, and startup policy.
