## Summary

Keep this PR open for revision. It targets a credible loop-detection gap, but the new generic heuristic can veto legitimate repeated work whenever two or more argument variants each return stable results; the supplied tests do not establish that this is a safe definition of no progress, and the PR body confirms that no direct after-fix runtime behavior was captured.

## What This Changes

This PR adds same-tool argument-churn detection so the existing global loop circuit breaker can stop runs that rotate among a small set of stable tool-call argument variants.

## System Context

Agent tools record each completed call in per-run diagnostic history, then the before-tool-call boundary asks loop detection whether the next call should execute. A critical loop result vetoes that call and emits diagnostic evidence instead of letting the agent continue spending tokens.

## Best Possible Solution

Keep the existing exact-repeat breaker and refine any cross-argument rule so it has a defensible semantic no-progress signal rather than per-variant repeatability alone, then demonstrate the revised boundary in a redacted real agent run.
