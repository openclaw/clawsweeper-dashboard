## Summary

Keep open: current main still allows overlapping WhatsApp Web `sendMessage` calls, and this PR is a focused candidate fix, but it needs after-fix real behavior proof before merge.

## What This Changes

The PR adds per-facade and per-Baileys-socket FIFO serialization for WhatsApp Web outbound `sendMessage` calls and adds focused regression tests.

## Best Possible Solution

Land the serialization only after redacted real WhatsApp or QA transport proof confirms overlapping sends serialize without breaking delivery, and keep the linked issue open until that fix merges.

## Reproduction Assessment

Yes from source inspection: current main calls raw `sock.sendMessage` immediately in both the Web send facade and timeout adapter, so two pending sends can overlap. I did not execute tests because this review is read-only.

## Solution Assessment

Yes, this is the right maintainable boundary: the socket WeakMap queue coordinates sibling timeout adapters, while the facade queue covers direct `createWebSendApi` use and leaves presence outside the queue. The remaining blocker is proof, not code shape.
