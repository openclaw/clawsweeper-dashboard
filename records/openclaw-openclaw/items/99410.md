## Summary

Keep open for maintainer merge review: current main and the latest release still have the controller-first list filter, while this PR changes the shared read boundary used by both subagent list surfaces and backs it with focused proof and regression coverage.

## What This Changes

The PR changes subagent list filtering to include runs whose `controllerSessionKey` or `requesterSessionKey` matches the caller and adds table-driven regression coverage for controller-owner, completion-owner, and unrelated-session cases.

## Best Possible Solution

Land the narrow read-predicate fix with the added regression tests if maintainers accept requester-key visibility; keep mutation ownership controller-gated unless a separate issue proves it should change.

## Reproduction Assessment

Yes, at source level: current main and `v2026.6.11` can store split controller/requester keys while the list filter only matches the controller fallback. I did not run local tests in this read-only review, but the PR includes after-fix live output and Telegram Desktop proof.

## Solution Assessment

Yes, this is the best narrow fix for the reported list/read bug because both affected list surfaces converge on `listControlledSubagentRuns`. Broader key canonicalization or mutation-gate changes would touch more ownership semantics than this PR needs.
