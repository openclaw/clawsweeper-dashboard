## Summary

Keep open: this PR is still necessary, appears correct for the linked list/read bug, and has enough real behavior proof, but merging should remain a maintainer decision because it deliberately widens subagent run visibility from a controller-key-only predicate to either controller or requester key.

## What This Changes

The PR changes subagent list filtering to return runs when either `controllerSessionKey` or `requesterSessionKey` matches, and adds regression tests for controller match, requester match, and unrelated-key isolation.

## Best Possible Solution

Land the narrow list predicate fix with the added regression tests and Telegram proof, while leaving broader mutating control semantics unchanged unless a separate issue proves they need the same ownership expansion.

## Reproduction Assessment

Yes, at source level: current main can persist different controller and requester keys, while the current list filter checks only the controller fallback. The PR body and inspected Mantis Telegram screenshot provide after-fix evidence that the requester-key case lists the active child.

## Solution Assessment

Yes, this is the best narrow fix for the reported list/read bug because both affected list surfaces already converge on `listControlledSubagentRuns`. A broader owner-key canonicalization or mutating control change would touch more semantics than this PR needs.
