## Summary

Keep open: current main has added some adjacent hardening, including guarded OpenAI Responses fetch and redacted provider HTTP bodies, but provider/network exception messages are still copied into model-fetch logs and stream error output without the shared redaction helper.

## What This Changes

The issue requests redaction of API keys, Authorization headers, and credential-bearing URLs from custom-provider network/fetch error messages when a provider base URL is unreachable.

## Best Possible Solution

Centralize redaction for provider transport exception messages before they reach logs, stream error payloads, agent/session state, or operator diagnostics, then add regression tests that inject Authorization and query-key secrets into thrown network errors.
