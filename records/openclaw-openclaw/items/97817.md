## Summary

Keep open: current main still has raw provider error-message storage and a packaged OpenAI Responses path without the guarded fetch override; adjacent redaction fixes cover related leak classes but do not close this custom-provider network-failure issue.

## What This Changes

The issue asks OpenClaw to redact API keys, credential-bearing URLs, and Authorization-style headers from custom-provider network/fetch error messages before they reach logs, dashboards, agent sessions, or previews.

## Best Possible Solution

Add a shared provider/network error sanitation boundary before error text enters session state, retry diagnostics, logs, or UI payloads, and cover URL query credentials, URL userinfo, Authorization-style headers, and package provider clients with focused regression tests.
