  - body: This drains and routes hook messages immediately after triggerInternalHook, before current sendPolicy/source-reply visibility checks that suppress automatic user delivery.   - confidence: 0.9

  - body: The fallback target uses ctx.To before ctx.From; on direct inbound turns To is commonly the bot/account address, not the user. The new test asserts that bot address, so direct-channel hook replies can be misrouted instead of going back to the inbound sender.
  - confidence: 0.92
- **[P1] Update the helper for current routeReply metadata:** `src/auto-reply/reply/internal-hook-replies.ts:48-58`
  - body: Current main's routeReply contract requires replyKind and carries policy/delivery metadata used by reply hooks. This helper calls routeReply with the older shape, so a rebase must thread the current reply kind and delivery context through the hook reply path rather than bypassing that classification.
  - confidence: 0.86
- **[P2] Validate hook messages before trimming:** `src/auto-reply/reply/internal-hook-replies.ts:28`
  - body: Internal hook handlers are runtime JavaScript and can accidentally push non-string values into event.messages. Calling .trim() directly will throw, and the command hook path awaits this helper, so a malformed hook reply can abort command processing.
  - confidence: 0.84
