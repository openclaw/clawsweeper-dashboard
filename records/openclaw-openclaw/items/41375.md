## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Honor outbound suppression before hook replies:** `src/auto-reply/reply/dispatch-from-config.ts:213-218`
  - body: This sends hook-controlled text immediately after `triggerInternalHook`, before the current `sendPolicy` and source-reply visibility policy are applied. Sessions configured to deny automatic sends or require message-tool-only delivery can still emit hook replies, so gate this delivery with the same policy decision and add deny/message-tool coverage.
  - confidence: 0.91
- **[P1] Route direct hook replies to the sender:** `src/auto-reply/reply/dispatch-from-config.ts:218`
  - body: When `OriginatingTo` is absent, this fallback chooses `ctx.To` before `ctx.From`, but direct inbound turns commonly put the bot/account address in `ctx.To` and the user in `ctx.From`. The new test asserts the bot address, so fix the fallback and assertion to target the sender.
  - confidence: 0.93
- **[P1] Include current routeReply metadata:** `src/auto-reply/reply/internal-hook-replies.ts:48-58`
  - body: Current main's `routeReply` contract requires `replyKind`, and nearby routed paths also pass requester and policy metadata. This helper omits that metadata, so the rebased branch can fail typecheck or send hook-generated replies outside the metadata contract reply hooks and policies expect.
  - confidence: 0.88
- **[P2] Validate hook messages before trimming:** `src/auto-reply/reply/internal-hook-replies.ts:28`
  - body: Internal hooks are runtime-loaded JavaScript, so a hook can accidentally push a non-string into `event.messages`. Calling `.trim()` directly on every entry lets one bad hook value throw out of command or message hook delivery instead of skipping invalid entries and preserving the turn.
  - confidence: 0.76
