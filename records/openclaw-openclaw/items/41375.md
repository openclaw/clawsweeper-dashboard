  - body: Current main requires every `routeReply` call to provide `replyKind` so reply hook lifecycle classification stays intact. This new helper calls `routeReply` without that field, so a repaired/rebased branch must pass the appropriate kind instead of bypassing the current delivery contract.
  - confidence: 0.93

  - body: This sends hook-controlled `event.messages` immediately after `triggerInternalHook`, before the dispatch path resolves send policy and source-delivery suppression.   - confidence: 0.91
- **[P2] Route direct hook replies to the inbound sender:** `src/auto-reply/reply/dispatch-from-config.ts:218`
  - body: When `OriginatingTo` is absent, this fallback prefers `ctx.To` before `ctx.From`; for direct inbound channel turns, `To` is commonly the bot/account address and `From` is the user. That can send the hook reply to the wrong identity, and the new test asserts the bot-side target.
  - confidence: 0.87
- **[P2] Validate hook messages before trimming them:** `src/auto-reply/reply/internal-hook-replies.ts:28`
  - body: Internal hook handlers are runtime-loaded JavaScript, so `event.messages` can contain non-string values despite the TypeScript type. Calling `.trim()` directly on each value can throw and disrupt command or inbound hook processing; filter to strings before trimming.
  - confidence: 0.86
