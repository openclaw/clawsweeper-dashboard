## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P1] Honor send policy before routing hook replies:** `src/auto-reply/reply/dispatch-from-config.ts:213-226`
  - body: The new `message:received` hook delivery runs immediately after `triggerInternalHook`, before the branch's send-policy gate and outside current main's source-delivery suppression decisions. A hook can therefore emit outbound text from sessions configured as `sendPolicy: deny` or message-tool-only; the repaired path needs to gate hook replies through the same delivery policy used for normal replies.
  - confidence: 0.93
- **[P1] Route direct hook replies to the inbound sender:** `src/auto-reply/reply/dispatch-from-config.ts:218`
  - body: For a direct inbound turn without `OriginatingTo`, `ctx.To` is commonly the bot/account address and `ctx.From` is the user. This PR uses `ctx.To` before `ctx.From`, and its test asserts the bot address, so direct-channel hook replies can be sent to the wrong target.
  - confidence: 0.92
- **[P1] Pass replyKind through hook delivery:** `src/auto-reply/reply/internal-hook-replies.ts:48-58`
  - body: Current main's `routeReply` requires `replyKind` so `reply_payload_sending` hooks receive the correct lane. The new helper calls `routeReply` without that contract, so a rebased branch would either fail the current type contract or bypass reply-payload hook semantics for hook replies.
  - confidence: 0.86
- **[P2] Validate hook messages before trimming them:** `src/auto-reply/reply/internal-hook-replies.ts:28`
  - body: Runtime hook handlers are user/plugin code, so `event.messages` can contain malformed values despite the TypeScript type. Calling `.trim()` on every element can throw and abort command or inbound hook processing; filter to strings and drop/log invalid entries before joining.
  - confidence: 0.87
