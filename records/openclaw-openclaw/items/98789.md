## Summary

Keep open: the PR appears to be a focused and likely-correct fix for a real Telegram default-account routing bug that is still present on current main, but it changes compatibility-sensitive bot-token precedence and still needs real Telegram proof before merge.

## What This Changes

The branch pre-resolves omitted Telegram account IDs through the configured default account in `resolveTelegramAccount` and `resolveTelegramToken`, with account, token, and action-runtime regression tests.

## Best Possible Solution

Land the resolver-level fix after redacted live Telegram proof shows omitted sends and at least one message action use the configured default bot while explicit-account and no-default compatibility cases still behave as intended.

## Reproduction Assessment

Yes for a source-level path: current main resolves omitted Telegram account IDs to the implicit default in the account and token resolver paths before consulting `defaultAccount`, so a credentialed stale default can shadow the configured default. ## Solution Assessment

Yes for the code shape: resolving the configured default at the two canonical optional-account entry points avoids duplicating policy across every action call site. The remaining blocker is real Telegram proof and maintainer acceptance of the compatibility-sensitive precedence change.
