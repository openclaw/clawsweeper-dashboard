## Summary

Keep open: the patch targets a real current-main Telegram default-account routing bug and the code shape looks sound, but this external PR still needs stronger real Telegram proof and maintainer acceptance of the compatibility-sensitive token precedence change before merge.

## What This Changes

The PR changes Telegram account and token resolution so omitted account IDs use the configured default account before the implicit default, with account, token, and action-runtime regression tests.

## Best Possible Solution

Land the resolver-level fix after redacted live Telegram proof shows omitted sends and at least one message action use the configured default bot while explicit-account and no-default compatibility cases still behave as intended.

## Reproduction Assessment

Yes for a source-level path: current main resolves omitted Telegram account IDs to the implicit default in the account and token resolver paths before consulting configured defaultAccount, so a credentialed stale default can shadow the configured default. I did not run a live Telegram reproduction in this read-only review.

## Solution Assessment

Yes for the code shape: resolving the configured default at the two canonical optional-account entry points avoids duplicating policy across every action call site. The remaining blocker is real Telegram proof and maintainer acceptance of the precedence change, not a different implementation layer.
