## Summary

Keep open: the patch is a strong resolver-level fix for the Telegram default-account routing bug, but it changes compatibility-sensitive bot-token precedence and still lacks real Telegram transport proof.

## What This Changes

The PR changes Telegram account and token resolution so omitted account IDs use the configured default account before the implicit default, with account, token, and action-runtime regression tests.

## Best Possible Solution

Land the resolver-level fix after redacted live Telegram proof shows omitted sends and actions use the configured default bot while explicit-account and no-default compatibility cases still behave as intended.

## Reproduction Assessment

Yes for a source-level reproduction: current main normalizes omitted Telegram account IDs to the implicit default in both resolveTelegramAccount and resolveTelegramToken, so a credentialed stale default token can shadow the configured default. I did not run live Telegram or local tests in this read-only review.

## Solution Assessment

Yes for the code shape: resolving the configured default at the two canonical optional-account entry points avoids duplicating policy across action call sites. The remaining blocker is real Telegram proof and maintainer acceptance of the precedence change, not a different implementation layer.
