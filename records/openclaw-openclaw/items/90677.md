## Summary

Keep open: current main and v2026.6.11 still depend on Google Chat delivering a `MESSAGE` event before `allowBots` or bot-loop protection can run, and the docs still do not warn about the reported peer Chat-app delivery gap. The remaining work needs maintainer product direction: a narrow docs clarification is straightforward, while an automatic channel-independent bridge would change A2A routing semantics.

## What This Changes

The issue asks OpenClaw to document Google Chat bot-to-bot delivery limitations and/or add a channel-independent agent-to-agent routing bridge.

## Best Possible Solution

Document the Google Chat app-to-app delivery caveat now, and evaluate any automatic bridge as an opt-in generic A2A design that reuses existing `tools.agentToAgent` and `sessions_send` safety boundaries.
