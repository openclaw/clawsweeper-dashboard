## Summary

Keep open: current main and v2026.6.11 still process Google Chat bot-loop protection only after a delivered `MESSAGE` webhook exists, current docs still do not warn about Chat-app-to-Chat-app non-delivery, and the existing A2A path is explicit `sessions_send` routing rather than an automatic Google Chat bridge.

## What This Changes

Request to document Google Chat app-to-app delivery limits and optionally add a channel-independent internal A2A bridge for multi-agent conversations.

## Best Possible Solution

Document the Google Chat app-to-app delivery limitation now, then treat any automatic bridge as a separate opt-in A2A design that reuses existing `sessions_send` safety boundaries.
