## Summary

Keep open. Current main still routes main-session cron systemEvent reminders through the heartbeat cron-event prompt and model-backed reply path; command cron now offers a no-model path for deterministic scripted output, but it does not settle which existing systemEvent reminders may bypass the model.

## What This Changes

Request deterministic, low-cost handling for simple cron reminder formatting so repeated scheduled alerts do not spend ChatGPT/OpenAI calls as a string formatter.

## Best Possible Solution

Make command cron or a maintainer-approved literal notification contract the explicit no-model path, while keeping complex systemEvent cron reminders on the existing model-backed heartbeat route.

## Reproduction Assessment

Yes, at source level. A main-session cron job with non-empty systemEvent text enters heartbeat, becomes a cron-event prompt, and calls getReplyFromConfig; I did not repeat the reporter's live OpenAI logging.

## Solution Assessment

No, not as a blanket string-formatting bypass. The maintainable direction is an explicit no-model path for deterministic notifications or clear guidance to command cron, while preserving the model-backed route for reasoning-dependent cron events.
