## Summary

Keep open. Current main and the latest release provide command cron as a no-model path for explicit scripts, but the reported main-session systemEvent reminder path still routes through heartbeat's cron-event prompt and getReplyFromConfig.

## What This Changes

Request a low-cost deterministic path so simple repeated cron or watcher reminders do not spend OpenAI/ChatGPT model calls for formatting.

## Best Possible Solution

Define a narrow literal-notification or simple-reminder cron contract while keeping systemEvent on the model-backed heartbeat path for reasoning-dependent events and directing scripted jobs to command cron.

## Maintainer Decision

Question: Should main-session cron systemEvent reminders get an explicit literal/simple-reminder bypass, or should deterministic users be expected to move this class of work to command cron?

Rationale: Both choices are plausible: bypassing the model reduces cost for simple reminders, but changing systemEvent semantics can break cron events that intentionally rely on model reasoning, tools, summarization, or internal-only handling.

Owner confidence: high

Options:

- **Add a narrow literal reminder mode (recommended):** Add an explicit cron payload, flag, or conservative simple-reminder boundary for trusted text that should be delivered without a model call, and document that systemEvent remains model-backed.
- **Keep command cron as the only no-model path:** Document that zero-token scheduled delivery should use command cron stdout and close the remaining systemEvent bypass direction.
- **Auto-detect simple systemEvents:** Bypass the model when an event appears simple, accepting higher ambiguity and regression risk around reminders that need reasoning or internal handling.

## Reproduction Assessment

Yes, at source level. A main-session cron job with non-empty systemEvent text is enqueued with a cron context key, selected as a cron event by heartbeat, and sent through getReplyFromConfig; I did not repeat the reporter's live OpenAI logging.

## Solution Assessment

No, not as a blanket string-formatting bypass. The maintainable solution is a narrow explicit literal-notification mode or conservative simple-reminder boundary, with command cron remaining the supported model-free path for scripted jobs.
