## Summary

Keep open. Current main still routes main-session cron `systemEvent` reminders through heartbeat cron-event prompt assembly and a model-backed reply path; merged command cron gives users a model-free path for explicit scripted output, but it does not replace the existing watcher/reminder flow reported here.

## What This Changes

The issue asks for a lower-cost cron/reminder path so OpenClaw does not use ChatGPT/OpenAI model calls for simple reminder string formatting.

## Best Possible Solution

Define a narrow deterministic delivery boundary for simple main-session cron reminders, or an explicit cron delivery mode/payload, while keeping the heartbeat model path for complex or reasoning-dependent cron events.

## Reproduction Assessment

Yes. Source inspection shows a main-session cron `systemEvent` still queues a `cron:<job>` event and routes it through heartbeat, whose cron-event prompt asks the model to relay the reminder; I did not run a live cron job in this read-only review.

## Solution Assessment

No, current main is not the complete solution for this issue. Command cron is a good model-free path for explicit scripted output, but the reported main-session watcher/reminder path still needs a product-defined simple-reminder bypass or delivery contract.
