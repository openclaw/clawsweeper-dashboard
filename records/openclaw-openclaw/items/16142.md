## Summary

Keep open: current main and the latest release still route main-session cron `systemEvent` reminders through the heartbeat cron-event prompt and `getReplyFromConfig`, so the API-cost/model-as-formatter concern remains after the related duplicate-input fix.

## What This Changes

The issue requests a lower-cost deterministic path for simple cron reminder text instead of using the OpenAI/ChatGPT model to format repeated scheduled notifications.

## Best Possible Solution

Add an explicit literal-notification cron payload or delivery mode for trusted simple reminders, while preserving `systemEvent` as the model-backed heartbeat path for reasoning-dependent cron events.

## Reproduction Assessment

Yes, at source level. A main-session cron job with non-empty `systemEvent` text is enqueued as a `cron:` event, becomes a heartbeat cron-event prompt, and calls `getReplyFromConfig`; I did not repeat the reporter's live OpenAI logging.

## Solution Assessment

No, not as a blanket string-formatting bypass. The maintainable solution is a narrow explicit literal-notification mode or conservative simple-reminder boundary, leaving complex cron events on the existing model-backed heartbeat path.
