## Summary

Keep open: current main and the latest release still route main-session cron `systemEvent` reminders through the heartbeat cron-event prompt and `getReplyFromConfig`, so the API-cost/rate-limit concern remains. The merged duplicate-input fix only removed the extra raw `System:` surfacing; it did not add a low-cost deterministic reminder delivery path.

## What This Changes

Request to reduce OpenAI/ChatGPT API usage for frequent main-session cron reminders by formatting simple reminder output deterministically instead of invoking the model.

## Best Possible Solution

Add an explicit literal-notification cron payload or delivery mode for trusted simple reminders, while preserving `systemEvent` as the model-backed heartbeat path for reasoning-dependent cron events and updating cron/heartbeat docs plus focused tests.

## Reproduction Assessment

Yes, at source level. A main-session cron job with non-empty `systemEvent` text is enqueued as a `cron:` event, becomes a heartbeat cron-event prompt, and calls `getReplyFromConfig`; I did not repeat the reporter's live OpenAI logging.

## Solution Assessment

No, not as a blanket string-formatting bypass. The maintainable solution is a narrow explicit literal-notification mode or conservative simple-reminder boundary, leaving complex cron events on the existing model-backed heartbeat path.
