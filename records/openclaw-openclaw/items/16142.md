## Summary

Keep open. Current main and v2026.6.11 still route main-session cron systemEvent reminders through the heartbeat cron-event prompt and model-backed reply path; command cron solves deterministic script jobs but does not replace the watcher/reminder behavior reported here.

## What This Changes

The issue requests a no-model cron reminder path so simple scheduled watcher output can be formatted or delivered without repeated OpenAI calls.

## Best Possible Solution

Define an explicit literal/simple-reminder main-session cron contract that bypasses the model for trusted text while preserving model-backed systemEvent behavior for reasoning-oriented reminders and command cron for scripts.

Rationale: The current code intentionally uses heartbeat/model semantics for main-session systemEvents, and changing that behavior affects cron, delivery, session context, and cost policy rather than being a mechanical bug fix.

Options:

- **Add a literal reminder mode (recommended):** Add a narrow opt-in payload or mode for trusted literal reminder delivery that avoids model calls and leaves existing systemEvent semantics unchanged.

- **Auto-bypass simple systemEvents:** Try to infer simple reminders automatically, accepting higher risk of inconsistent behavior and skipped model handling for ambiguous events.
