## Summary

Keep open: current main still routes main-session cron systemEvent reminders through the heartbeat cron-event prompt and model-backed reply path, so the API-cost/model-as-formatter problem remains. The related merged PR fixed duplicate prompt surfacing, but it intentionally left one model-backed cron reminder surface in place.

## What This Changes

The issue requests a lower-cost deterministic path for simple cron reminder formatting instead of repeatedly sending reminder text through ChatGPT/OpenAI as a formatter.

## Best Possible Solution

Add an explicit literal-notification cron payload or delivery mode for trusted simple reminders, while preserving systemEvent as the model-backed heartbeat path for reasoning-dependent cron events.

## Reproduction Assessment

Yes, at source level. A main-session cron job with non-empty systemEvent text is enqueued as a cron-tagged event, becomes a heartbeat cron-event prompt, and calls getReplyFromConfig; I did not repeat the reporter's live OpenAI logging.

## Solution Assessment

No, not as a blanket string-formatting bypass. The maintainable solution is a narrow explicit literal-notification mode or conservative simple-reminder boundary, leaving complex cron events on the existing model-backed heartbeat path.
