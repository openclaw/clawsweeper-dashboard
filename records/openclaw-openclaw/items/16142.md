## Summary

Keep open. Current main and v2026.6.11 still route main-session cron `systemEvent` reminders through the heartbeat cron-event prompt and model-backed reply path; command cron covers model-free scripts, but it does not replace the requested low-cost deterministic path for existing simple reminder events.

## What This Changes

The issue requests deterministic, lower-cost formatting or delivery for repetitive cron reminders instead of sending simple reminder text through ChatGPT/OpenAI as a model-backed formatter.

## Best Possible Solution

Add an explicit literal-notification cron payload or delivery mode for trusted simple reminders, while preserving `systemEvent` as the model-backed heartbeat path for reasoning-dependent events.

## Reproduction Assessment

Yes, at source level. A main-session cron job with non-empty `systemEvent` text enqueues a cron-tagged event, heartbeat builds a cron-event prompt, and the run calls `getReplyFromConfig`; I did not repeat the reporter's live OpenAI logging.

## Solution Assessment

No, not as a blanket string-formatting bypass. The maintainable solution is a narrow explicit literal-notification mode or conservative simple-reminder boundary, leaving complex cron events on the existing model-backed heartbeat path.
