## Summary

Keep open: current main and the latest release still send main-session cron systemEvent reminders through the heartbeat cron-event prompt and model-backed getReplyFromConfig path, so the API-cost concern remains after the related duplicate-input fix.

## What This Changes

Requests a low-cost deterministic cron reminder delivery path so simple scheduled notifications do not consume OpenAI/ChatGPT model calls every run.

## Best Possible Solution

Add an explicit literal-notification cron payload or delivery mode for trusted simple reminders, while preserving systemEvent as the model-backed heartbeat path for reasoning-dependent cron events.

## Reproduction Assessment

Yes, at source level. A main-session cron job with non-empty systemEvent text is enqueued as a cron event, becomes a heartbeat cron-event prompt, and calls getReplyFromConfig; I did not repeat the reporter's live OpenAI logging.

## Solution Assessment

No, not as a blanket string-formatting bypass. The maintainable path is a narrow explicit literal-notification mode or conservative simple-reminder boundary, leaving complex cron events on the existing model-backed heartbeat path.
