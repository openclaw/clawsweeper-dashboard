## Summary

Keep open. Current main still routes main-session cron systemEvent reminders through the heartbeat cron-event prompt and model-backed reply path; command cron now covers explicit model-free scripts, but it does not replace the existing watcher/systemEvent reminder path that this issue reports.

## What This Changes

The issue requests a deterministic, lower-cost cron reminder path so OpenAI is not used as a formatter for recurring watcher notifications.

## Best Possible Solution

Define a narrow literal-notification or simple-reminder cron path for trusted main-session reminders, while keeping systemEvent on the existing model-backed heartbeat path for reasoning-dependent events and pointing scripted jobs to command cron.

## Reproduction Assessment

Yes, at source level. A main-session cron job with non-empty systemEvent text is enqueued with a cron context key, selected as a cron event by heartbeat, and sent through getReplyFromConfig; I did not repeat the reporter's live OpenAI logging.

## Solution Assessment

No, not as a blanket string-formatting bypass. The maintainable solution is a narrow explicit literal-notification mode or conservative simple-reminder boundary, with command cron remaining the supported model-free path for scripted jobs.
