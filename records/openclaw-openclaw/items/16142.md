## Summary

Keep open. Current main and the latest release still route main-session cron systemEvent reminder text through the heartbeat cron-event prompt and model-backed reply call; the merged duplicate-surfacing fix did not add the requested deterministic low-cost path.

## What This Changes

The issue asks OpenClaw to stop using the model as a formatter for recurring watcher/cron reminder text that could be relayed deterministically.

## Best Possible Solution

Define a narrow literal/simple cron notification path that can format trusted watcher reminders without a model call, while preserving the existing model-backed systemEvent heartbeat path for complex cron events.

## Reproduction Assessment

Yes. At source level, a main-session cron job with non-empty systemEvent text still enqueues a cron-tagged event, builds a cron-event heartbeat prompt, and calls getReplyFromConfig.

## Solution Assessment

No, not as a blanket string-formatting bypass. The maintainable fix needs an explicit literal/simple-reminder boundary so complex cron events remain on the existing model-backed heartbeat path.
