## Summary

Keep open: current main still treats whitespace-only QQBot app IDs as configured, while this PR consistently normalizes those values and adds focused regression coverage with convincing before/after module output.

## What This Changes

The PR normalizes QQBot app IDs before account discovery and default selection so whitespace-only configuration or environment values do not create configured accounts.

## Best Possible Solution

Keep app-ID normalization centralized in the QQBot resolver so discovery, configured-default validation, and account resolution all share the same blank-value semantics.

## Reproduction Assessment

Yes. Importing the current production resolver with whitespace-only top-level, named-account, and environment app IDs produces blank configured accounts, and the supplied before/after transcript demonstrates the corrected branch behavior.

## Solution Assessment

Yes. Reusing the existing string-normalization helper at the QQBot resolver boundary is narrower and more maintainable than filtering blank accounts separately in each caller.
