Full review comments:

- **[P1] Use only string values in the language map:** `extensions/memory-core/src/dreaming-narrative.ts:108-110`
  - body: `LANGUAGE_INSTRUCTIONS` is declared as `ReadonlyMap<string, string>`, but these English locale rows insert `undefined`. Under the repo's strict TypeScript settings the map initializer is not assignable to the declared value type, so remove the no-op rows or make the value type and lookup logic deliberately handle `undefined`.
  - confidence: 0.94
- **[P1] Thread language through the narrative run input:** `extensions/memory-core/src/dreaming-narrative.ts:332`
  - body: `buildLanguageAwarePrompt()` rereads the global runtime config instead of receiving the resolved dreaming config language, while the phase callers pass `language` and `generateAndAppendDreamNarrative` never declares that param. Thread the normalized value through the typed params and use it for both the subagent prompt and fallback/date writes so pluginConfig-driven runs localize reliably and the branch type-checks.
  - confidence: 0.92
- **[P2] Remove the ignored execution-level language path:** `src/memory-host-sdk/dreaming.ts:75`
  - body: Adding `language` to `MemoryDreamingExecutionConfig` creates a second config carrier that is normalized from `execution.*.language`, but the schema/docs expose only top-level `dreaming.language` and the phase runner uses only the top-level value. Keep one top-level contract or fully support, schema, document, and test execution-level overrides.
  - confidence: 0.86
