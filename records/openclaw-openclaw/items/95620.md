  - body: `LANGUAGE_INSTRUCTIONS` is declared as `ReadonlyMap<string, string>`, but the English locale rows insert `undefined`.   - confidence: 0.94
- **[P1] Thread language through the typed narrative API:** `extensions/memory-core/src/dreaming-narrative.ts:1210`
  - body: The phase callers pass `language` and the success path reads `params.language`, but `generateAndAppendDreamNarrative` does not declare that parameter. Add the typed parameter and pass the normalized language through prompt construction, fallback writes, and date formatting instead of leaving this as an excess/undeclared property path.
  - confidence: 0.93
- **[P2] Build the prompt from resolved config:** `extensions/memory-core/src/dreaming-narrative.ts:332`
  - body: `buildLanguageAwarePrompt()` rereads raw runtime config from the hard-coded `memory-core` entry, while the sweep already resolves plugin config and passes `params.config.language` down from the phase runners. Direct `pluginConfig` sweeps or configured memory-slot ownership can then localize dates while keeping the prompt English, so use the resolved language parameter for the system prompt too.
  - confidence: 0.82
- **[P2] Remove the ignored execution-level language path:** `src/memory-host-sdk/dreaming.ts:75`
  - body: Adding `language` to `MemoryDreamingExecutionConfig` creates a second config carrier normalized from `execution.*.language`, but the manifest/docs expose only top-level `dreaming.language` and the phase runners use only top-level `params.config.language`. Keep one top-level contract or fully support, schema, document, and test execution-level overrides.
  - confidence: 0.87
