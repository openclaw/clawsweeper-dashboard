- **[P1] Use only string values in the language map:** `extensions/memory-core/src/dreaming-narrative.ts:108-110`
  - body: `LANGUAGE_INSTRUCTIONS` is declared as `ReadonlyMap<string, string>`, but these English locale rows insert `undefined`, which is not assignable under the repo's strict TypeScript settings. Remove the no-op rows or make the value type and lookup logic handle `undefined` deliberately.
  - confidence: 0.94
- **[P1] Declare language on the narrative params type:** `extensions/memory-core/src/dreaming-narrative.ts:1210`
  - body: The phase callers pass `language` and the success path reads `params.language`, but `generateAndAppendDreamNarrative` does not declare that parameter. Add the typed parameter and thread it into the prompt/fallback paths instead of leaving the branch with a strict TypeScript error.
  - confidence: 0.93
- **[P2] Use the resolved language for the prompt:** `extensions/memory-core/src/dreaming-narrative.ts:332`
  - body: The prompt path rereads raw runtime config through `any` and a hardcoded plugin id while the date path uses the resolved phase config. Build the prompt from the same typed `language` value passed into narrative generation so direct runs, tests, fallback paths, and runtime snapshots cannot drift.
  - confidence: 0.86
- **[P2] Remove the ignored execution-level language carrier:** `src/memory-host-sdk/dreaming.ts:75`
  - body: Adding `language` to `MemoryDreamingExecutionConfig` creates a second config carrier that is normalized from `execution.*.language`, but the phase runners pass only top-level `params.config.language` and the schema/docs expose only top-level `dreaming.language`. Keep one top-level contract or fully support, schema, document, and test execution-level overrides.
  - confidence: 0.85
