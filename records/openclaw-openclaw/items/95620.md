Overall correctness: patch is incorrect

Full review comments:

- **[P1] Use only string values in the language map:** `extensions/memory-core/src/dreaming-narrative.ts:108-110`
  - body: `LANGUAGE_INSTRUCTIONS` is declared as `ReadonlyMap<string, string>`, but the English locale rows insert `undefined`. Under strict TypeScript this map initializer is not assignable to the declared value type, so remove those no-op rows or make the value type and lookup logic intentionally support `undefined`.
  - confidence: 0.94
- **[P1] Thread language through the typed narrative API:** `extensions/memory-core/src/dreaming-narrative.ts:1210`
  - body: The phase callers pass `language` and the success path reads `params.language`, but `generateAndAppendDreamNarrative` does not declare that param, and the system prompt still rereads raw runtime config. Add the typed parameter and build prompt/date behavior from the normalized language value passed by the config resolver.
  - confidence: 0.93
- **[P2] Remove the ignored execution-level language path:** `src/memory-host-sdk/dreaming.ts:75`
  - body: Adding `language` to `MemoryDreamingExecutionConfig` normalizes `execution.*.language`, but the phase runners and docs expose only top-level `dreaming.language`. Keep one top-level contract or fully support, schema, document, and test execution-level overrides so users do not get a silent no-op config path.
  - confidence: 0.86
