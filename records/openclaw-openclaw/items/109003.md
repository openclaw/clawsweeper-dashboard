## Summary

Keep this PR open for revision: bounded curl timeouts are useful, but the two installer pipelines launched through nested `bash -c` shells do not enable `pipefail`, so a curl timeout with empty input can be masked by the downstream shell exiting successfully; the PR also lacks a real container run demonstrating the timeout path.

## What This Changes

The PR adds 10-second connection and 120-second total curl timeouts to four Docker installer download sites and updates one smoke-runner contract assertion.

## Best Possible Solution

Enable pipeline failure propagation in both nested shell commands, add focused coverage for every timeout-bearing command shape, and attach a redacted Docker transcript showing a stalled endpoint exits nonzero within the configured bound.
