## Summary

Keep open: current main and v2026.6.11 still do not implement outbound Telegram album sending with `sendMediaGroup`; they only preserve and fan out multiple media URLs as separate sends, and an open linked external PR with closing syntax remains the implementation candidate for maintainer review.

## What This Changes

Request support for sending Telegram media groups/albums from the message tool instead of delivering related media as separate Telegram messages.

## Best Possible Solution

Review the open external implementation and either port or land a current-main Telegram plugin design that uses `sendMediaGroup` for eligible multi-media payloads while preserving existing single-media, sequential fallback, reply, and docs behavior.

## Maintainer Decision

Kind: product_direction

Question: Should outbound Telegram album support land by extending the existing `mediaUrls` send/reply/outbound paths, by accepting a new explicit `send-media-group` action, or by deferring album grouping for now?

Rationale: The missing behavior is source-backed, but the permanent API shape affects the message tool contract, Telegram plugin action discovery, docs, fallback semantics, and the open external PR’s branch direction.

Likely owner: steipete

Owner reason: This decision spans the visible message tool API, Telegram plugin ownership, and the already-posted cleanup review on this issue.

Owner confidence: medium

Options:

- **Port album support into existing media paths (recommended):** Use `sendMediaGroup` behind the existing `mediaUrls`/attachment payload flow for eligible 2-10 media groups and keep explicit single-media fallback behavior unchanged.
- **Accept a separate album action:** Land or sponsor a dedicated `send-media-group` action after maintainers approve the new message-tool surface and document how it differs from `mediaUrls`.
- **Defer outbound albums:** Keep current sequential fanout as supported behavior and close or narrow the linked implementation if album grouping is not desired now.

## Reproduction Assessment

Yes, at source level: current main preserves multiple `mediaUrls` but sends them sequentially and contains no outbound `sendMediaGroup` implementation. I did not run a live Telegram bot album send.

## Solution Assessment

Unclear until maintainers choose the API shape. A grouped send implementation is plausible, but a separate `send-media-group` action may duplicate the existing `mediaUrls` surface unless maintainers explicitly want that contract.
