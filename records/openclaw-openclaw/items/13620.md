## Summary

Keep open: current main still lacks native outbound Telegram `sendMediaGroup` album sending. The existing `mediaUrls` paths deliver media sequentially, same-repo album PRs are closed unmerged, and the open fork draft needs maintainer API-shape review before a new repair lane is queued.

## What This Changes

The issue requests Telegram album/media-group support so the message tool can send multiple related media items as one grouped Telegram album with a shared caption.

## Best Possible Solution

Choose one Telegram message-tool API shape, preferably reusing existing `send` plus `mediaUrls`, then implement native `sendMediaGroup` grouping for eligible media while preserving sequential fallback and adding focused Telegram tests, docs, and live proof.

- **Accept an explicit album action:** Allow a separate `send-media-group` action only after maintainers approve the new tool surface and require docs plus live Telegram proof.
- **Defer album semantics:** Keep current sequential multi-media delivery and revisit native album grouping when maintainers are ready to own the extra Telegram-specific behavior.

Yes. Source-level reproduction is high confidence: current main has `mediaUrls` plumbing, but the Telegram action, reply delivery, outbound adapter, and durable outbound path all send individual media items and no outbound `sendMediaGroup` branch exists.

## Solution Assessment

Unclear until maintainers choose the API shape. The most maintainable path appears to be album grouping behind the existing `send` plus `mediaUrls` surface rather than landing a competing action without product approval.
