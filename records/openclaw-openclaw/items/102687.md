## Summary

Keep open. Current main still lets Slack always-on room history roll under the “since last reply” framing, while mention-gated Slack turns clear only through the shared finalizer and current docs/tests allow the always-on behavior, so this needs a maintainer invariant decision rather than cleanup closure.

## What This Changes

The issue asks Slack channel/group history to reset after agent replies so the prompt history block contains only messages since the last reply.

## Best Possible Solution

Choose one Slack room-history invariant, then align Slack code, tests, and prompt/docs wording around either clear-after-visible-reply semantics or an explicitly rolling/watermarked context window.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Slack `requireMention: false` room history clear after a confirmed visible reply, or remain a rolling context window with corrected labeling/watermark semantics?

Rationale: Current source, docs, tests, and the prior unmerged Slack history PR support rolling always-on context, while the prompt label and reporter expectation are reply-bounded; automation should not choose that user-visible behavior policy.

Likely owner: steipete

Owner reason: The clearest current-main ownership signal is the blame/path history across Slack prepare, shared channel-turn finalization, history helpers, and group docs.

Owner confidence: high

Options:

- **Clear after visible reply (recommended):** Clear Slack always-on room history only after confirmed visible reply delivery, keeping quiet/no-reply context available until an actual reply boundary.
- **Keep rolling and relabel:** Preserve the current rolling processed-message window but change prompt/docs wording so it no longer claims strict since-last-reply semantics.
- **Use self-watermark semantics:** Record Slack outbound self entries and select history after the last self entry, closer to Telegram’s rolling-window model but with a larger implementation surface.

## Reproduction Assessment

Yes, at source level. Current Slack prepare code and tests show `requireMention: false` room turns retain prior processed messages in `channelHistories`, while mention-gated turns alone pass a history finalizer that the shared turn kernel clears.

## Solution Assessment

Unclear until maintainers choose the invariant. Clearing only after confirmed visible Slack replies looks like the narrowest behavior fix, but current docs/tests also support rolling always-on context, so relabeling or watermarking may be the preferred product path.
