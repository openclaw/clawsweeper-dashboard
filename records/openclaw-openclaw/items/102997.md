Full review comments:

- **[P2] Keep queued Run Now actions pending:** `apps/android/app/src/main/java/ai/openclaw/app/NodeRuntime.kt:1468-1473`
  - body: When `cron.run` returns `{enqueued:true, runId}`, this path reports success and lets the action finish after the refresh, but Gateway `enqueueRun` has only queued work; the job is not marked running until the cron lane later reaches `prepareManualRun`. If that lane is backed up, a second tap can enqueue another execution of the same job. Late finding: this branch was visible in the prior ClawSweeper-reviewed head, but I verified it against the current head and Gateway contract now.
  - late: true
  - confidence: 0.88
- **[P2] Add a locked revision guard before saving cron edits:** `apps/android/app/src/main/java/ai/openclaw/app/NodeRuntime.kt:1528`
  - body: Save builds a patch from the loaded `original` and sends only id/patch, while the current Gateway protocol has no expected `updatedAtMs` field and `cron.update` only revalidates scope/patch under the lock. If another client changes the same job after Android loaded detail but before Save, Android can overwrite that newer same-field edit instead of forcing refresh/revert. Late finding: this was equally visible in the previous ClawSweeper-reviewed head.
  - late: true
  - confidence: 0.9
