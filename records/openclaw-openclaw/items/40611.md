## Label Justifications

- `P1`: The issue reports a regression that can block active channel conversations for minutes during normal heartbeat scheduling.
- `impact:message-loss`: Heartbeat contention can delay or suppress visible Telegram, Feishu, or WebChat replies while users are actively chatting.
- `impact:session-state`: The failure is rooted in heartbeat scheduling, active run detection, and session/run lock contention.

## Summary

Keep open: current main and v2026.6.11 still route `requests-in-flight` heartbeat busy skips through the shared 1 second wake retry path, and https://github.com/openclaw/openclaw/pull/89989 is still an open candidate rather than a merged fix.

## What This Changes

The issue requests a less aggressive heartbeat busy-skip retry so active Telegram, Feishu, and WebChat conversations are not immediately preempted by due heartbeat runs.

## Best Possible Solution

Keep this as the canonical bug until https://github.com/openclaw/openclaw/pull/89989 or an equivalent narrow wake-layer retry fix is reviewed, proven, and merged; keep broader idle-timeout and non-blocking heartbeat redesigns separate.
