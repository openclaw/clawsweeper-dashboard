## Summary

Keep this open: current main and the latest release still retry `requests-in-flight` heartbeat skips through the shared 1 second wake retry path, and the open linked PR is only a candidate fix until reviewed and merged.

## What This Changes

The issue reports that the heartbeat drift fix made `requests-in-flight` skips retry too aggressively, letting heartbeat runs block active Telegram conversations, and asks for a longer retry or idle-aware heartbeat behavior.

## Best Possible Solution

Keep this issue as the canonical bug until https://github.com/openclaw/openclaw/pull/89989 or an equivalent narrow heartbeat wake-layer fix is reviewed, proven, and merged; keep broader non-blocking or idle-timeout heartbeat redesigns separate.

## Solution Assessment

Yes for the near-term direction: separating the `requests-in-flight` retry cadence in the heartbeat wake layer addresses the reported regression without reintroducing the old full-interval drift. The linked PR still needs its own correctness and proof review before it can be the merge vehicle.
