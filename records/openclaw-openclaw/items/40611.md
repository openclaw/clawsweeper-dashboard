## Summary

Keep this open: current main and v2026.6.11 still route `requests-in-flight` heartbeat skips through the shared 1 second wake retry path, and the open linked fix PR is the right place to resolve the narrow bug before closing this issue.

## What This Changes

Reports that the heartbeat drift fix made `requests-in-flight` heartbeat skips retry through a 1 second wake delay, causing heartbeat runs to grab session work immediately after active Telegram conversations.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/89989 or an equivalent narrow wake-layer fix that gives `requests-in-flight` heartbeat skips a longer retry cadence without reintroducing full-interval drift; keep broader activity-based and non-blocking heartbeat redesigns separate.

## Solution Assessment
