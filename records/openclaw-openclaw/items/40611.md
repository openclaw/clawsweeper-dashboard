## Summary

Keep this open: current main and v2026.6.11 still route `requests-in-flight` heartbeat skips through the shared 1 second wake retry path, and the open linked PR is the candidate fix rather than a reason to close the issue early.

## What This Changes

The issue asks OpenClaw to stop retrying heartbeat `requests-in-flight` skips so aggressively that due heartbeats can block active Telegram and other channel conversations.

## Best Possible Solution

Keep this issue as the canonical bug report until https://github.com/openclaw/openclaw/pull/89989 or an equivalent narrow wake-layer retry fix is reviewed and merged; track broader heartbeat redesigns separately.
