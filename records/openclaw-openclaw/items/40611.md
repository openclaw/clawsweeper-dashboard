## Summary

Keep open: current main and v2026.6.11 still route `requests-in-flight` heartbeat busy skips through the shared 1 second wake retry path, and the linked fix remains an open PR rather than a merged implementation.

## What This Changes

The issue reports a regression where heartbeat busy-skip retries can run immediately after active conversations and block Telegram or other channel replies.

## Best Possible Solution

Keep this as the canonical bug until https://github.com/openclaw/openclaw/pull/89989 or an equivalent narrow wake-layer retry cadence fix is reviewed, proven, and merged; keep broader idle-timeout and non-blocking heartbeat redesigns separate.
