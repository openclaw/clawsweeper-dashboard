## Summary

Keep this open: current main and v2026.6.11 still route requests-in-flight heartbeat busy skips through the shared 1 second wake retry path, and the linked closing PR is open and unmerged.

## What This Changes

The issue reports that the heartbeat drift fix changed requests-in-flight skips into a shared 1 second wake retry, causing heartbeats to contend with active Telegram conversations.

## Best Possible Solution

Keep this issue as the canonical bug report until https://github.com/openclaw/openclaw/pull/89989, or an equivalent narrow wake-layer fix, is repaired, proven, and merged.

## Reproduction Assessment

Yes, source-level: current main returns requests-in-flight for busy heartbeat paths and heartbeat-wake retries retryable busy skips with DEFAULT_RETRY_MS = 1,000 ms. I did not run a live transport reproduction.

## Solution Assessment

Yes for the near-term direction: separating requests-in-flight retry cadence in the wake layer addresses the reported regression without reintroducing full-interval drift. Broader activity-based or non-blocking heartbeat designs should stay separate product work.
