## Summary

Keep this open: current main and v2026.6.11 still route `requests-in-flight` heartbeat skips through the shared 1 second wake retry path, and the open linked PR is the current implementation candidate rather than a reason to close the issue early.

## What This Changes

The issue asks OpenClaw to stop retrying `requests-in-flight` heartbeat skips so aggressively that heartbeat runs block active Telegram and other channel conversations.

## Best Possible Solution

Keep this issue as the canonical bug report until https://github.com/openclaw/openclaw/pull/89989 or an equivalent narrow heartbeat wake-layer fix is reviewed and merged; keep broader activity-based and non-blocking heartbeat work separate.

## Solution Assessment

Yes for the near-term direction: separating the `requests-in-flight` retry cadence in the heartbeat wake layer addresses the reported regression without reintroducing full-interval drift. Broader activity-based or non-blocking heartbeat designs should stay in their own product trackers.
