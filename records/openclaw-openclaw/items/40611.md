## Label Justifications

- `P1`: The issue describes a regression that can block active channel conversations for minutes during normal heartbeat scheduling.
- `impact:session-state`: The failure is rooted in heartbeat scheduling, active run detection, and session/run lock contention.
- `impact:message-loss`: Heartbeat contention can delay or suppress visible channel replies while users are actively chatting.

## Summary

Keep this open: current main and v2026.6.11 still use the shared 1 second heartbeat wake retry for `requests-in-flight` busy skips, and the open linked PR is the candidate fix rather than a reason to close this issue early.

## What This Changes

Debounce `requests-in-flight` heartbeat retries so a due heartbeat does not immediately grab the session after an active conversation turn ends.

## Best Possible Solution

Keep this issue as the canonical bug until https://github.com/openclaw/openclaw/pull/89989 or an equivalent narrow wake-layer fix is reviewed and merged; keep broader activity-based and non-blocking heartbeat designs separate.

Yes for the near-term direction: separating the `requests-in-flight` retry cadence in the heartbeat wake layer addresses the reported regression without reintroducing full-interval drift. The linked PR still needs its own repair/proof review before it can be the merged solution.
