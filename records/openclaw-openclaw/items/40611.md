## Label Justifications

- `P1`: The issue reports a regression that can block active channel conversations for minutes and remains present on current main and the latest release.
- `impact:session-state`: The failure path is heartbeat retry contention with active reply runs, session lanes, and session-lock ownership.
- `impact:message-loss`: The reported Telegram, WebChat, and Feishu symptoms leave user messages delayed, unanswered, or effectively blocked while heartbeat work runs.

## Summary

Keep open: current main and the latest release still retry `requests-in-flight` heartbeat skips after the shared 1 second wake delay, and the linked candidate fix is open but unmerged.

## What This Changes

The issue asks OpenClaw to stop heartbeat busy-skip retries from immediately starting a heartbeat run after an active Telegram or chat turn finishes.

## Best Possible Solution

Review and either land or reject https://github.com/openclaw/openclaw/pull/89989; if it is rejected, keep this issue as the canonical narrow bug and implement an equivalent wake-layer retry-cadence fix without adding public config unless maintainers choose that contract.
