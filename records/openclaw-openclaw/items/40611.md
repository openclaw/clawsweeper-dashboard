## Summary

Keep this open: current main and v2026.6.11 still route `requests-in-flight` heartbeat busy skips through the shared 1 second wake retry path, while the linked fix PR remains open and unmerged rather than proof that the issue is resolved.

## What This Changes

The issue reports a regression where heartbeat `requests-in-flight` skips retry too aggressively after active conversations, blocking Telegram and related channel message handling.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/89989 or an equivalent wake-layer fix that gives `requests-in-flight` its own longer per-target retry cadence without reopening the old full-interval drift bug.
