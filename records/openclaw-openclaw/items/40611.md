## Summary

Keep this open: current main and v2026.6.11 still retry `requests-in-flight` heartbeat skips through the shared 1 second wake retry path, and the linked fix PR remains open rather than merged.

## What This Changes

The issue asks OpenClaw to stop heartbeat `requests-in-flight` skips from retrying aggressively after active conversations, especially on Telegram, without reintroducing the old full-interval drift.

## Best Possible Solution

Keep this issue as the canonical bug until https://github.com/openclaw/openclaw/pull/89989 or an equivalent narrow heartbeat wake-layer fix is reviewed, proven, and merged; keep broader idle-timeout or non-blocking heartbeat redesigns separate.
