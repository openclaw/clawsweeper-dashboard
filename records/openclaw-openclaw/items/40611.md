## Summary

Keep this open: current main and v2026.6.11 still route `requests-in-flight` heartbeat skips through the shared 1 second wake retry path, and https://github.com/openclaw/openclaw/pull/89989 remains the open candidate fix rather than a reason to close this issue early.

## What This Changes

The issue reports that heartbeat retries after active conversation skips fire too aggressively and can block Telegram, WebChat, and Feishu message handling during active conversations.

## Best Possible Solution

Keep this issue as the canonical bug report until https://github.com/openclaw/openclaw/pull/89989 or an equivalent narrow heartbeat wake-layer fix is reviewed and merged; keep broader activity-based or non-blocking heartbeat redesign work separate.
