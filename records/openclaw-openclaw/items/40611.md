## Summary

Keep open: current main and v2026.6.11 still route `requests-in-flight` heartbeat busy skips through the shared 1 second wake retry path, and https://github.com/openclaw/openclaw/pull/89989 is still only an open candidate fix.

## What This Changes

The issue reports that heartbeat busy-skip retries became too aggressive after the no-drift fix, causing heartbeat runs to block active Telegram and other channel conversations.

## Best Possible Solution

Keep this as the canonical bug until https://github.com/openclaw/openclaw/pull/89989 or an equivalent narrow wake-layer retry fix is reviewed, proven, and merged; keep broader idle-timeout and non-blocking heartbeat redesigns separate.

## Solution Assessment

Yes for the near-term direction: separating the `requests-in-flight` retry cadence in the heartbeat wake layer addresses the reported regression without reintroducing the old full-interval drift. The linked PR still needs its own correctness and proof review before it can be the merge vehicle.
