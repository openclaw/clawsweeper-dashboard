## Summary

Keep this issue open: current main still forwards browser open/navigate URL input without rejecting URL username/password userinfo, and https://github.com/openclaw/openclaw/pull/82490 is the open candidate fix rather than merged implementation.

## What This Changes

Request to reject browser open/navigate URLs containing embedded credentials before browser runtime dispatch and redact credential-bearing diagnostics.

## Best Possible Solution

Land or replace the linked browser-plugin guard so credentialed HTTP(S) open/navigate inputs are rejected and redacted before any local, proxy, Playwright, Chrome MCP, or Chromium dispatch, with supported auth alternatives documented.
