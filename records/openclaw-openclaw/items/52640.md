## Summary

Keep open: current main and v2026.6.11 have progress drafts, task records, transient gateway chat lifecycle state, and channel busy snapshots, but they still do not provide the requested persistent per-channel-turn status object with durable done, failed, unknown, or interrupted semantics.

## What This Changes

Request a persistent, editable task-status surface for long-running channel turns, starting with Discord and later generalized across channels.

## Best Possible Solution

Define an additive runtime-owned channel-turn status contract that reuses progress/session/task signals, persists only the ownership needed to fail closed to unknown or interrupted, and projects first to Discord as best-effort transport.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a feature request. Source and docs inspection show current main has adjacent progress drafts, task records, and channel busy snapshots, but not the requested persistent channel-turn status contract.

## Solution Assessment

Unclear as a concrete implementation plan. The one-message status model is plausible, but maintainers need to choose ownership, persistence, restart semantics, and channel rollout behavior before code work is safe.
