## Summary

Keep open: current main has shipped adjacent Discord progress drafts, status reactions, task ledger states, and channel busy tracking, but it still lacks the requested persistent per-channel-turn status surface with explicit terminal and unknown/interrupted semantics after restart or uncertain ownership.

## What This Changes

The issue requests one durable, editable task-status surface for long-running channel turns, starting with Discord, with best-effort transport and explicit lifecycle states.

## Best Possible Solution

Define an additive runtime-owned channel-turn status contract that reuses existing progress, session, and task signals, persists only the ownership needed for truthful reconciliation, and projects first to Discord as best-effort editable status without blocking final delivery.
