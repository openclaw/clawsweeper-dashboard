## Summary

Keep open: current main and v2026.6.11 have progress drafts, task records, and persisted session lifecycle projections, but they still do not provide the requested persistent per-channel-turn status surface with durable done, failed, unknown, or interrupted semantics.

## What This Changes

Request a persistent, editable task-status surface for long-running channel turns, Discord first, with explicit terminal and unknown/interrupted states.

## Best Possible Solution

Define an additive runtime-owned channel-turn status contract that reuses current progress/session/task signals, persists only the ownership needed to fail closed to unknown or interrupted, and projects first to Discord as best-effort transport.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a feature request. Source and docs inspection show adjacent progress drafts, task records, and session lifecycle projections, but not the requested persistent channel-turn status contract.

## Solution Assessment

Unclear as a concrete implementation plan. The one-message status model is plausible, but maintainers need to choose ownership, persistence, restart semantics, and Discord rollout behavior before code work is safe.
