## Summary

Keep open: current main and v2026.6.11 have progress drafts, task records, and channel busy/activity snapshots, but not the requested persistent editable channel-turn status surface with durable done, failed, unknown, or interrupted semantics.

## What This Changes

The issue requests one best-effort, editable status surface for long-running channel turns, Discord first, with explicit lifecycle and restart or disconnect fallback states.

## Best Possible Solution

Define an additive runtime-owned channel-turn status contract that reuses progress, session, and task signals, persists only the ownership needed to fail closed to unknown or interrupted, and projects to Discord through best-effort message transport.

Rationale: The remaining work affects runtime lifecycle semantics, channel message editing, persistence after restart, config policy, and the relationship between progress drafts, task records, and gateway activity APIs; automation cannot safely pick that product boundary.

Likely owner: steipete

Owner reason: Recent Discord/channel draft transport and task/status boundary work makes this the best available routing owner for deciding whether the feature belongs in runtime, channel, gateway, or task surfaces.

Owner confidence: medium

Options:

- **Add Runtime-Owned Status Contract (recommended):** Approve a narrow additive status contract with durable ownership, unknown/interrupted fallback, and Discord-first best-effort transport while keeping final reply delivery independent.
- **Defer Behind Gateway Activity API:** Wait for the broader per-session activity API work to settle, then project that canonical activity state into channel-visible status messages.
- **Keep Progress Drafts Only:** Decline a separate persistent terminal status surface for now and rely on progress drafts, task records, and channel busy snapshots as the supported UX.
