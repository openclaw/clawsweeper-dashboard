## Summary

Keep open: current main has adjacent progress drafts, task records, Discord draft edits, and internal channel busy state, but it still lacks the requested persistent per-channel-turn editable status surface with durable done, failed, unknown, or interrupted semantics.

## What This Changes

Issue #52640 requests a Discord-first persistent task-status surface for long-running channel turns, with one editable status message and explicit terminal or interrupted states.

## Best Possible Solution

Define an additive runtime-owned channel-turn status contract that reuses progress/session/task signals, persists only enough ownership to fail closed after restart or disconnect, and projects first to Discord through best-effort editable transport.

## Reproduction Assessment

Yes, at source level: current main has editable progress drafts and task-record states, but normal interactive channel turns still do not create a durable per-turn status object/message with terminal unknown or interrupted semantics.

## Solution Assessment

Unclear as a concrete implementation: the one-message status model is plausible, but maintainers need to choose owner boundary, persistence, restart semantics, and relationship to progress drafts, tasks, /status, and reactions.
