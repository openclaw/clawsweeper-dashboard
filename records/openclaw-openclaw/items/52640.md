## Summary

Keep open: current main has adjacent Discord/Telegram progress drafts, task ledger state, and gateway session lifecycle projection, but none provide the requested persistent per-channel-turn status surface with durable done/failed/unknown/interrupted semantics.

## What This Changes

The issue requests a persistent editable task-status surface for long-running channel turns, initially Discord, with lifecycle states and best-effort channel delivery that never blocks final replies.

## Best Possible Solution

Design a maintainer-owned run-status model that persists ownership, terminal, and unknown states, then project it through optional channel status transports with send/edit failures best-effort and non-blocking.
