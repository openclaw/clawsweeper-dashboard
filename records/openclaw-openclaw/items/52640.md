## Summary

Keep open: current main has progress drafts, task records, channel busy snapshots, and related UI/status proposals, but those surfaces are transient, background-task scoped, or account-health scoped; they still do not provide the requested persistent per-channel-turn status object with durable done, failed, unknown, or interrupted semantics.

## What This Changes

The issue requests a persistent, editable, per-run task-status surface for long-running channel turns with durable terminal and interrupted/unknown states.

## Best Possible Solution

Define an additive runtime-owned channel-turn status contract that reuses progress/session/task signals, persists only the ownership needed to fail closed to unknown or interrupted, and projects first to Discord through best-effort send/edit transport.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a feature request. Source inspection shows current main has adjacent progress drafts, task records, and channel busy snapshots, but not the requested persistent channel-turn status contract.

## Solution Assessment

Unclear as a concrete implementation plan. The one-message status model is plausible, but maintainers need to choose ownership, persistence, restart semantics, and rollout behavior before code work is safe.
