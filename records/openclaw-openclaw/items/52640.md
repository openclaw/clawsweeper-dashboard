## Summary

Keep open: current main has task-ledger states, typing keepalive, Discord progress drafts, Web UI status reconciliation, and channel busy accounting, but not the requested persistent per-channel-turn status surface with explicit done, failed, unknown, and interrupted semantics.

## What This Changes

Request a first-class persistent, editable status surface for long-running channel turns, starting with Discord and degrading safely after restart or uncertain ownership.

## Best Possible Solution

Define an additive runtime-owned channel-turn status contract that reuses existing run/task/progress facts, persists only the ownership needed for truthful reconciliation, and projects first to Discord as best-effort editable status.
