## Summary

Keep open: current main and v2026.6.11 still provide adjacent progress drafts, task records, and channel busy snapshots, but not a persistent per-turn status object with durable terminal or unknown semantics.

## What This Changes

The issue requests a first-class persistent status surface for long-running channel turns, starting with one editable Discord message and explicit working, done, failed, and unknown states.

## Best Possible Solution

Define an additive runtime-owned channel-turn status contract that reuses progress, session, and task signals, persists only the ownership needed to fail closed to unknown or interrupted, and projects to Discord through best-effort message transport.
