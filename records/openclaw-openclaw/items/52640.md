## Summary

Keep open: current main and the latest stable release have adjacent progress drafts, task-ledger status, session lifecycle projection, Discord reactions, and typing feedback, but they still do not provide the requested persistent per-channel-turn status object with durable done/failed/unknown/interrupted semantics.

## What This Changes

Add a first-class persistent task-status surface for long-running channel turns, starting with Discord, that updates one channel-scoped status message and fails closed when run ownership becomes uncertain.

## Best Possible Solution

Design an additive runtime-owned channel-turn status contract that reuses existing progress/session/task signals, persists only the ownership needed to fail closed, and projects first to Discord through best-effort create/update/finalize transport.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a feature request, and source/docs inspection confirms adjacent progress, task, and session status surfaces exist without the requested persistent channel-turn status contract.

## Solution Assessment

Unclear as an implementation plan until maintainers choose the owner boundary, persistence semantics, restart behavior, Discord rollout, and relationship to progress drafts and task-ledger status.
