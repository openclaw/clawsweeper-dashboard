## Summary

Keep open: current main has adjacent progress drafts, status reactions, task ledger states, and channel busy tracking, but it still does not provide the requested durable per-channel-turn status object with explicit terminal and unknown/interrupted semantics across channel delivery and restart ownership.

## What This Changes

Request a persistent editable status surface for long-running channel turns, Discord first, with explicit terminal and unknown/interrupted states.

## Best Possible Solution

Define an additive runtime-owned channel-turn status contract that reuses progress, session, and task signals, persists only the ownership needed for truthful reconciliation, and projects first to Discord best-effort without blocking final delivery.
