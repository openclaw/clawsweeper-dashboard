## Summary

Keep open: current main has Discord progress drafts, task-ledger terminal states, and Web UI run-status chips, but those are still partial surfaces rather than the requested durable channel-turn status object with terminal unknown/interrupted semantics.

## What This Changes

Request a first-class persistent one-message status surface for long-running channel turns, Discord first, with best-effort edits and explicit terminal or unknown states.

## Best Possible Solution

Define one additive runtime/channel status contract that reuses existing progress, task, and session lifecycle signals, persists only the ownership needed to fail closed, and projects first to Discord as best-effort transport without blocking final reply delivery.
