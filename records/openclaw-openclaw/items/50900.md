Keep open: current main and the latest release still expose one global `session.maintenance.pruneAfter` threshold plus narrow fixed cleanup cases, not ordered per-pattern or per-type retention rules. The issue requests ordered per-pattern or per-type session-maintenance retention rules so ephemeral sessions can prune faster than interactive sessions.

Keep this as the canonical retention-rules design item, then implement one additive typed matcher contract with schema/help/docs, cleanup-preview output, and regression coverage after maintainer approval.
