## Summary

Keep open: current main and v2026.6.11 still lack ordered per-pattern or per-type session-maintenance retention rules, and the open related items only partially overlap this product/config decision.

## What This Changes

Request support for ordered per-pattern or per-type session-maintenance retention rules so ephemeral sessions can be pruned sooner than interactive sessions.

## Best Possible Solution

Keep this as the canonical ordered age-retention design item, then implement one additive typed matcher contract with schema/help/docs, cleanup-preview output, preservation semantics, and regression coverage after maintainer approval.
