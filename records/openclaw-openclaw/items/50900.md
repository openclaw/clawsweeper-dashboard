## Summary

Keep open: current main and the latest release still expose one global session-maintenance age threshold plus narrow cron/model-run special cases, not ordered per-pattern or per-type retention rules. The related open issues cover narrower grouped retention, preservation, and terminology work, so this remains the canonical product/API decision for pattern-based age retention.

## What This Changes

The issue requests ordered `session.maintenance.rules` so different session-key patterns or session types can use different retention windows with global `pruneAfter` as the fallback.

## Best Possible Solution

Keep this as the canonical retention-rules design item, then implement one additive typed matcher contract with schema/help/docs, cleanup-preview output, and regression coverage after maintainer approval.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 expose only global `session.maintenance` retention plus narrow fixed cleanup paths, not ordered per-pattern retention rules. This is a feature-gap reproduction rather than a failing runtime bug repro.

## Solution Assessment

Unclear until maintainer design approval. Ordered retention rules are plausible, but the best solution should use a stable typed matcher and explicit destructive-cleanup safety semantics rather than defaulting to raw key globs.
