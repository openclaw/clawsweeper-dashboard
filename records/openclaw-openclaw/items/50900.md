## Summary

Keep open: current main and the latest release still expose one global session-maintenance age threshold plus narrow fixed cleanup paths, not ordered per-pattern or per-type retention rules. The KeepMyClaw comment is useful backup context, but it does not replace the requested core retention policy decision.

## What This Changes

Request support for ordered per-pattern or per-type session maintenance retention rules so ephemeral cron/subagent sessions can be pruned more aggressively than long-lived interactive sessions.

## Best Possible Solution

Keep this as the canonical product/API design item, then define one additive session-retention policy model that covers global thresholds, built-in ephemeral cleanup, protected sessions, dry-run reporting, and any ordered matcher rules without creating competing cleanup knobs.
