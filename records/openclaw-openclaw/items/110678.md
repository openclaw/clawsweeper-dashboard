## Summary

Keep this PR open for maintainer review: it fixes the narrow expired-access-token symptom, but it still discards a refreshable OAuth profile before background resolution can use its refresh token. The linked broader issue remains the canonical work for aligning background credential selection with profile-aware resolution.

## What This Changes

The PR rejects expired OAuth credentials while building the provider-level agent credential map and adds regression tests that reject an expired profile or select a later valid profile.

## Best Possible Solution

Make background credential resolution select the intended auth profile and refresh OAuth credentials through the profile-aware auth path; only omit a profile after that path establishes it is unusable.
