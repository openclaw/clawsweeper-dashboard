## Label Justifications

- `P1`: The changed path supplies authentication for recurring background operations, where a post-expiry failure can repeatedly block automatic work.
- `merge-risk: 🚨 auth-provider`: The patch changes whether stored OAuth credentials are available to automatic provider resolution after their access token expires.

## Summary

Keep this PR open for revision: it fixes the current main expiry predicate, but it also drops an expired OAuth profile before the profile-aware resolver can refresh it, so an OAuth-only background path can become missing-provider-auth instead of refreshing.

## What This Changes

The branch rejects OAuth credentials whose expiry timestamp has passed when building the provider-level in-memory credential map, and adds regression tests for rejection and fallback to a later valid profile.

## Best Possible Solution

Unify background credential discovery with the profile-aware resolution path so it honors configured order and can refresh OAuth credentials, then retain focused coverage for expired-first and OAuth-only cases.
