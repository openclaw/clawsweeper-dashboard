## What This Changes

Prevent concurrent chat runs that reuse a tool-call ID from merging, removing, or hydrating each other’s live tool cards in the Control UI.

## System Context

The embedded agent publishes tool lifecycle events containing a run identifier and tool-call identifier; the Control UI projects those events into live cards and later reconciles them with persisted chat history. Correct reconciliation must preserve run ownership so terminal or hydrated data from one run cannot alter another active run’s card.

  D[Persisted chat history] --> E[History reconciliation]

  F --> G[Chat transcript display]

## Best Possible Solution

Make the Control UI use one canonical run-scoped tool-card key throughout live event projection, terminal cleanup, and history hydration, then add focused concurrent-run and hydration regressions for equal `toolCallId` values across distinct runs.
