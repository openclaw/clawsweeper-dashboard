## Summary

Keep open: current main and v2026.6.11 have partial installer diagnostics and a few broad or targeted retries, but not the requested cross-platform structured npm error policy; maintainer direction is needed because retry and auto-repair behavior can change setup and security outcomes.

## What This Changes

The issue requests structured installer npm error classification, clearer remediation guidance, and bounded retries for transient failures instead of generic or best-effort shell handling.

## Best Possible Solution

Define a conservative installer error policy first, then implement shared POSIX and Windows diagnostics that retry only clearly transient network failures, give explicit remediation for permission/disk/engine/package errors, and keep certificate/security failures fail-closed unless maintainers approve a safer remediation path.
