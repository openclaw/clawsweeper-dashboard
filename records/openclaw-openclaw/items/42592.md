## Summary

Keep open: current main and v2026.6.11 still provide only partial npm diagnostics and targeted cleanup retries, while the broader installer error classification, retry, and permission-recovery policy remains unresolved.

## What This Changes

The issue requests structured installer error codes, classified npm remediation, bounded retries for transient install failures, and less masked setup errors.

## Best Possible Solution

Define a narrow installer policy: classify known npm failures, retry only idempotent transient network failures, provide inline non-technical recovery or Doctor handoff for permission/disk/engine failures, and keep optional probes best-effort unless maintainers choose stricter setup behavior.
