## Summary

Keep open: current main and v2026.6.11 still only partially handle installer npm failures, and the remaining cross-platform retry/remediation behavior needs maintainer policy direction before implementation.

## What This Changes

Request to add structured npm installer error classification, clearer remediation messages, and smarter retry handling for transient failures across installer scripts.

## Best Possible Solution

Define a conservative installer error policy first, then implement shared POSIX, PowerShell, and install-cli diagnostics that retry only clearly transient network errors and provide explicit remediation for permission, disk, engine, package, and TLS failures.

Question: What cross-platform npm installer failure policy should OpenClaw ship for retries, automatic repair, and fail-closed behavior?

Rationale: The request spans first-run UX, security-sensitive TLS failures, platform-specific permission repair, and optional setup probes, so automation should not choose retry or remediation semantics without maintainer intent.

Likely owner: vincentkoc

Owner reason: Recent history points to vincentkoc as the strongest owner for installer/setup policy across POSIX, Windows, and release-tagged paths.

Owner confidence: high

Options:

- **Conservative diagnostics and transient retries (recommended):** Add structured error extraction and remediation text while retrying only clearly transient network errors and leaving certificate/security and persistent local failures explicit.
- **Broader automatic repair:** Attempt safe permission or prefix repairs after EACCES-style failures and retry when the repair succeeds, with platform-specific tests and rollback behavior.
- **Diagnostics-only first:** Keep install execution behavior mostly unchanged while improving error messages and docs, then revisit retries after specific failures are confirmed.

## Reproduction Assessment

Yes, source-level: current main shows partial diagnostics and ad hoc retries rather than the requested structured npm error-code retry/remediation policy. A live failing npm scenario would still be useful before implementing platform-specific repair behavior.

## Solution Assessment

Unclear until maintainers choose the policy boundary. Structured diagnostics plus conservative transient retries appears safest, while automatic EACCES repair and fail-closed setup behavior need explicit product/security direction.
