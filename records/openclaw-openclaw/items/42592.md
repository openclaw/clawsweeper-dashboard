## Summary

Keep open: current main and v2026.6.11 partially improve installer diagnostics, but the broader request for classifier-driven retry, clearer remediation, and permission-recovery policy is still not fully implemented; the closed macOS EACCES report was explicitly folded into this issue as the canonical tracker.

## What This Changes

The issue requests structured installer error classification, clearer npm failure guidance, and smarter retry behavior for transient or permission-related install failures.

## Best Possible Solution

Define a bounded installer error policy in the existing shell and PowerShell installer paths: retry only classified transient network failures, provide explicit non-retryable guidance for permission/disk/engine/package errors, keep config-get absence semantics intentional, and cover it with focused installer tests plus package-install smoke proof.
