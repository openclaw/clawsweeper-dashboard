## Summary

Keep open: current main and the latest release still contain the shared JSON repair heuristic that can misclassify code-like colon tails, and an open candidate PR exists but has not merged.

## What This Changes

The issue reports that write and exec heredoc tool-call payloads can turn intended physical newlines after code-like colon blocks into literal backslash-n bytes, corrupting generated scripts.

## Best Possible Solution

Land one shared parser fix, likely by repairing or replacing https://github.com/openclaw/openclaw/pull/95982 and coordinating with https://github.com/openclaw/openclaw/pull/96748, with focused regressions plus real OpenClaw tool-run proof.
