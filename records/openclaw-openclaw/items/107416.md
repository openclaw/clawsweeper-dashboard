## Summary

Keep open: current main still generates the Windows gateway launch scripts as UTF-8, matching the reported CJK-path failure mechanism, while existing coverage does not exercise non-ASCII profile paths.

Likely related people:
- @steipete — adjacent core/Windows daemon owner candidate; medium confidence.

## What This Changes

Make the generated Windows gateway launchers work when the user profile or OpenClaw state path contains CJK characters.

## Best Possible Solution

Use one explicit, internally consistent launcher encoding strategy that preserves Unicode paths across WScript, cmd, OpenClaw inspection, and Startup-folder fallback; regenerate broken launchers through install/doctor and verify gateway startup automatically so users do not need manual file edits.

## Maintainer Decision

## Reproduction Assessment

Yes at source level: install the native Windows gateway under a CJK user profile and the generated UTF-8 VBS/CMD launchers embed that path. A live Windows VM run is still needed for final repair proof.

## Solution Assessment

No, not exactly as proposed: changing gateway.cmd to the system ANSI codepage alone would conflict with the existing UTF-8 reader and remain locale-sensitive. The fix should define one writer/reader contract for every Windows launcher path and prove it across locales.
