## Summary

Keep open: current main still accepts and later materializes Workboard worktree source paths through a write-scoped card path, while the sibling Gateway worktree and explicit session cwd paths are admin-scoped. No merged or open related item was found that owns this specific per-card authorization gap.

## What This Changes

The issue asks OpenClaw to prevent write-only Workboard card authors from causing later admin dispatch to materialize arbitrary host git checkouts as managed worktrees.

## Best Possible Solution

Add a security-reviewed fix that records or enforces an admin-validated Workboard worktree origin before materialization, covers create/update plus dispatch with regression tests, and aligns the Workboard docs with the managed-worktree admin boundary.

## Reproduction Assessment

Yes, from source inspection and the reporter's supplied real-behavior proof: current main stores arbitrary absolute worktree sourcePath metadata through a write-scoped Workboard path, then later uses it as repoRoot when an admin dispatch materializes the card. I did not run a live Gateway transport repro in this read-only review.

## Solution Assessment

No, the current implementation is not the best way to solve the issue because the admin check is applied only to the dispatcher, not to the card workspace origin being materialized. The safer fix is to validate or mark the workspace origin at create/update time and refuse untrusted stored worktree source paths during dispatch.
