- `impact:security`: The affected path crosses an authorization boundary and can move .worktreeinclude-selected sensitive files into a managed agent worktree.

## Summary

Keep open: current main still has the Workboard write-scope acceptance path and later admin-dispatch materialization chain, while the related June scope-resolver fixes addressed a different opposite failure mode.

## What This Changes

The issue reports that Workboard can store an arbitrary worktree source path through an operator.write card mutation and later materialize it during an operator.admin dispatch without checking the card author's admin authority.

## Best Possible Solution

Keep this open and patch Workboard so arbitrary host worktree source paths are either accepted only from operator.admin-authorized mutations or are constrained to an existing workspace-anchored contract, with regression coverage for write-only card creation followed by admin dispatch.
