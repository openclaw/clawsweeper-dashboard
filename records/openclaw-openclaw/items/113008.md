## Summary

This is a valid Workboard usability feature, but it needs maintainer product direction before implementation: the request mixes a view filter with optional persisted preference behavior, and the current issue does not establish which Workboard scope or persistence contract should own that choice.

## What This Changes

Add a Workboard dropdown that filters visible tickets to one selected board or all boards, with optional persistence of the user’s selection.

## System Context

Workboard is OpenClaw’s task-oriented UI surface, presenting tickets and their lifecycle state to users. A board selector would sit between the available ticket data and the rendered board view, affecting what users can browse and act on without changing the underlying tickets.

## Architecture Diagram

flowchart LR

  C[User board selection] --> D[Board filter]
  B --> D
  D --> E[Filtered ticket columns]
  E --> F[User actions on tickets]
  C --> G[Optional saved preference]
  G --> D

## Best Possible Solution

Define a presentation-only Workboard filter with an explicit All Boards default, then decide whether a durable per-user preference is warranted and, if so, place it in the existing canonical UI/state owner with focused filter and persistence coverage.
