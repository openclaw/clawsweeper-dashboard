## Summary

This PR should remain open because its authority narrowing regresses the established create-then-dispatch flow for agents with sandboxing disabled: a plain card is converted to restricted access, then rejected before its worker can start. The prior P1 finding still applies unchanged at the current head, and the PR has no visible after-fix runtime proof.

## What This Changes

This PR changes Workboard card creation and dispatch so plain or scratch cards no longer inherit unrestricted workspace authority from the gateway caller.

## System Context

Workboard accepts card-creation requests through the Gateway, stores workspace authority with each card, and later starts an agent worker for eligible cards. The dispatch resolver turns stored or caller-derived authority into a target workspace scope, which is then validated against the selected agent before startup.

## Best Possible Solution

Keep plain cards free of displayable unrestricted metadata while preserving the caller’s effective ability to dispatch to an unsandboxed agent, or explicitly establish and prove a supported migration to sandboxed dispatch before changing that contract.
