## Summary

Keep open: current main still uses the loaded-plugin-only fast parser in the `sessions_send` guard, so the reported Telegram `:topic:` child-session bypass remains until one of the open closing PRs lands.

## What This Changes

Reject Telegram topic child session keys in `sessions_send` before dispatch, even when the Telegram channel plugin is not loaded in the current process.

## Best Possible Solution

Land one plugin-aware `sessions_send` guard fix that uses the lightweight session-key resolver, then close the duplicate candidate PRs and this issue after merge.

## Reproduction Assessment

Yes, source-level. Current main calls the loaded-plugin-only fast parser before dispatch, while the full plugin-aware resolver and Telegram session-key API already classify `:topic:` keys as threaded.

## Solution Assessment

Yes. The best fix is to reuse the existing plugin-owned lightweight session-key resolver for the `sessions_send` guard, not to add Telegram literals to generic core parsing.
