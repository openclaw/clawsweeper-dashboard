## Label Justifications

- `P2`: This is a deterministic, source-reproducible runtime guard bug with limited blast radius in `sessions_send` Telegram topic targeting.
- `impact:message-loss`: The bypass can misroute inter-agent coordination into a Telegram topic child session instead of rejecting with parent-session guidance.
- `impact:session-state`: The affected key changes the session scope from the intended parent channel session to a Telegram topic child session.

## Summary

Keep open: current main still routes the `sessions_send` direct-target guard through the loaded-plugin-only fast parser, so Telegram `:topic:` child session keys can still bypass the intended rejection before the Telegram plugin is loaded. The issue is already paired with open closing PRs, so it should remain the canonical tracker until one fix lands.

## What This Changes

The issue reports that `sessions_send` can accept Telegram `:topic:` child session keys before the Telegram channel plugin is loaded, bypassing the existing thread-session rejection.

## Best Possible Solution

Land one canonical fix that makes the `sessions_send` direct-target guard use the plugin-aware session thread resolver before dispatch, with regression coverage for an unloaded Telegram registry and without adding Telegram-specific parsing to the generic suffix parser.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: call `sessions_send` with `agent:main:telegram:group:-100123:topic:77` before Telegram is loaded, where the current fast parser falls through to generic `:thread:` parsing and misses the Telegram topic child session.

## Solution Assessment

Yes. The narrowest maintainable fix is to have `sessions_send` consult the full plugin-aware session thread parser before dispatch while keeping Telegram topic grammar owned by the Telegram session-key API.
