## Label Justifications

- `P2`: This is a normal-priority, source-reproducible misrouting bug in a bounded `sessions_send` plus Telegram topic path.
- `impact:message-loss`: The reported failure can route inter-agent coordination into the wrong Telegram topic child session instead of rejecting with the parent-session guidance.
- `impact:session-state`: The bug can start a nested run against the wrong session scope, causing session context and transcript state to drift from the intended parent session.

## Summary

Keep open: current main has the intended `sessions_send` thread-target guard, but the guard still uses the loaded-plugin-only fast parser, so a Telegram `:topic:` child key can avoid the guard before the Telegram plugin is loaded.

## What This Changes

Make `sessions_send` reject Telegram topic child session keys before dispatch, even when the Telegram channel plugin has not been loaded in the current process.

## Best Possible Solution

Use the existing plugin-owned session-key resolver path for the `sessions_send` direct-target guard so Telegram topic child sessions reject like other thread sessions, while preserving disabled-plugin behavior and thread-aware announce delivery.

## Reproduction Assessment

Yes, source-level. Current main routes the guard through `parseSessionThreadInfoFast`, and that path cannot classify Telegram `:topic:` keys unless the Telegram plugin hook is already loaded.

## Solution Assessment

Yes. The narrowest maintainable fix is to make the existing `sessions_send` guard use the plugin-owned lightweight session-key resolver path rather than adding Telegram literals to core or loading the full channel runtime.
