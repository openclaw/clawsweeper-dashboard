## Summary

Keep open: current `main` and latest release still route the `sessions_send` direct-target guard through the loaded-plugin-only fast parser, so Telegram `:topic:` child keys can still miss the existing thread-target rejection before the Telegram plugin is loaded. The issue already has open closing PRs, so maintainers should review and land one candidate instead of queueing another fix.

## What This Changes

The issue reports that `sessions_send` can accept Telegram topic child session keys before the Telegram channel plugin is loaded, bypassing the existing thread-target rejection.

## Best Possible Solution

Land one focused PR that changes the `sessions_send` guard to use the plugin-owned lightweight session conversation resolver, then let the merged PR close this issue and close the other candidate PRs as superseded.

## Reproduction Assessment

Yes, source inspection gives a high-confidence path: `sessions_send` checks the fast loaded-plugin parser, and when Telegram is not loaded that path falls through to generic `:thread:` parsing that does not recognize `:topic:`. I did not run a local repro because this review is read-only and must not create test artifacts.

## Solution Assessment

Yes. The narrow maintainable fix is to keep Telegram topic grammar at the plugin session-key boundary and make the `sessions_send` guard consult the full lightweight resolver path before dispatch.
