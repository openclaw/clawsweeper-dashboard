## Summary

Keep open: current main still has the reported `sessions_send` gap, and two open PRs use closing syntax for this issue, so the issue should remain open until one fix lands.

## What This Changes

The issue reports that `sessions_send` can accept Telegram topic child session keys before the Telegram channel plugin is loaded, bypassing the existing thread-target guard.

## Best Possible Solution

Land one plugin-aware `sessions_send` guard fix, then close this issue and supersede the duplicate candidate PRs after merge.

## Reproduction Assessment

Yes. Source inspection on current main shows `sessions_send` calls `parseSessionThreadInfoFast`, and that fast path falls back only to generic `:thread:` parsing when Telegram is not loaded.

## Solution Assessment

Yes. The best fix is to reuse the existing plugin-aware session-thread resolver or its lightweight `session-key-api` fallback before dispatch, rather than adding Telegram `:topic:` semantics to generic core parsing.
