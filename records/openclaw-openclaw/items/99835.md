## Summary

Keep open: current main and the latest release still route the `sessions_send` thread-target guard through the loaded-plugin-only fast parser, so Telegram `:topic:` child keys can still miss the guard before the Telegram plugin is loaded. Two open mergeable PRs already claim this issue as the candidate fix path, so this issue should remain the canonical tracker until one lands.

## What This Changes

The issue reports that `sessions_send` can accept Telegram topic child session keys before the Telegram channel plugin is loaded, bypassing the intended thread-target rejection.

## Best Possible Solution

Land the best owner-boundary fix from the open implementation PRs so `sessions_send` uses the plugin-aware session conversation resolver for this guard without teaching the generic core suffix parser that every `:topic:` is a thread.

## Reproduction Assessment

Yes for a source-level reproduction: current main calls `parseSessionThreadInfoFast` in `sessions_send`, and that fast path cannot classify Telegram `:topic:` keys when the Telegram plugin is not loaded. I did not run a live tool invocation because this review is read-only, but the source path is direct and existing tests encode the full resolver's Telegram invariant.

## Solution Assessment

Yes. The narrowest maintainable fix is to make this guard use the existing plugin-aware lightweight session conversation resolver, while avoiding a generic core `:topic:` suffix rule that could collide with other channel grammars.
