## Summary

Keep open: the report matches a real current-main gap between documented Control UI Tailscale Serve identity support and the HTTP read auth path used by config, avatar, and assistant-media endpoints.

## What This Changes

The issue asks for Control UI config, avatar, and local media preview endpoints to authenticate consistently over a Tailscale Serve origin that is allowed for the dashboard.

## Best Possible Solution

Add a narrow, documented Control UI HTTP-read auth path for verified Tailscale Serve identity on config, avatar, and assistant-media routes only, with origin/rate-limit tests and secops review; keep general HTTP APIs on their existing token/password or trusted-proxy contracts.
