## Summary

Keep open: current main and v2026.6.11 still keep Tailscale identity on the Control UI WebSocket auth surface while config, avatar, and assistant-media HTTP reads use the plain HTTP auth surface, and https://github.com/openclaw/openclaw/pull/102302 is the active security-reviewed fix candidate.

## What This Changes

The issue reports that Control UI config, avatar, and local media preview HTTP reads return 401 over Tailscale Serve even though loopback and Cloudflare Tunnel access work with the same gateway config.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/102302, or an equivalent security-reviewed fix, so verified Tailscale Serve identity can authorize only the Control UI bootstrap, avatar, and assistant-media read routes with whois and browser-origin guardrails while ordinary HTTP APIs remain unchanged.
