## Summary

Keep this PR open: it has a real core-boundary defect and still lacks real end-to-end behavior proof. The marker is a useful Workboard idea, but the current patch adds Workboard-specific state to the shared reply payload and can delete a legitimate first line beginning with `Workboard:` while an active card is claimed.

## What This Changes

This PR preserves parent-agent routing for dashboard-created sessions, binds Workboard card claims to a session, and prefixes eligible replies with the active card ID.

## System Context

Dashboard session creation selects the agent and session key used by an agent run. The Workboard plugin records that session on a claimed card, then its reply hook inspects the final reply payload before OpenClaw delivers it to the user.

## Architecture Diagram

  D --> E[Marker decision]

## Best Possible Solution

Keep the marker implementation in the Workboard plugin boundary, preserve arbitrary reply text, and prove the approved design with a real dashboard-session-to-user-visible-reply run before merge.
