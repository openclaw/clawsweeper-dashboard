## Summary

Keep open: current main and the latest release still do not expose a permission-aware sibling-agent roster with role/theme context in either the session prompt or an equivalent discovery tool. Related open work covers configured descriptions and per-agent A2A/session scoping separately, but neither closes this broader roster-and-exposure decision.

## What This Changes

The issue requests adding sibling-agent roster context to each agent session prompt or a discoverable tool, including identity/theme metadata and whether agent-to-agent communication is allowed.

## Best Possible Solution

Define a maintainer-approved, policy-gated roster discovery contract, preferably by extending the existing allowlist-aware agents_list path before considering always-on prompt injection.
