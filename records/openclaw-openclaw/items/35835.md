## Summary

Keep open: current main and v2026.6.11 still make the read tool text/image-only, and native audio needs a shared content/provider/session/security contract before a narrow implementation is safe.

## What This Changes

The issue requests read-tool support for audio files as native multimodal attachments instead of decoding them as text.

## Best Possible Solution

Define a shared typed native-audio attachment contract for read results, provider serialization, model-capability checks, payload limits, unsupported-model behavior, raw-media egress policy, and session/audit semantics before wiring audio into the read tool.
