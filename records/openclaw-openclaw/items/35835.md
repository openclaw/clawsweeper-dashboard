## Summary

Keep open: current main and v2026.6.11 still make the read tool text/image-only, and the nearest native-audio PR is blocked rather than a landed or safe canonical fix.

## What This Changes

The issue requests native audio-file attachment support in the read tool so audio files are sent to capable multimodal models instead of read as raw binary text.

## Best Possible Solution

Define a shared typed native-audio attachment contract for read results, provider serialization, model-capability checks, payload limits, unsupported-model behavior, raw-media egress policy, and session/audit semantics before wiring audio into the read tool.
