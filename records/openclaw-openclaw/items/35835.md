## Summary

Keep open: current main and v2026.6.11 still make the read tool text/image-only, and native audio needs an explicit raw-media/provider/session/security contract before implementation is safe. The closest related PR is open, conflicting, and broader than this read-tool request, so it is useful input but not a landed or safe canonical fix.

## What This Changes

The issue requests native audio-file handling in the read tool so audio files are sent as multimodal model attachments instead of being decoded as raw text.

## Best Possible Solution

Define a typed native-audio attachment contract covering read-tool output, provider serialization, model capability checks, raw-media egress policy, payload limits, unsupported-model fallback, and session/audit semantics before wiring audio into the read tool.
