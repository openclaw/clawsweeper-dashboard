## Summary

Keep open: current main and the latest release still keep the read tool text/image-only, and native audio support needs a maintainer-owned product/security contract before implementation.

## What This Changes

The issue requests native audio-file handling in the read tool so supported models can receive audio as multimodal attachments instead of raw binary text.

## Best Possible Solution

Define a shared opt-in native-audio attachment contract for read results, provider serialization, capability checks, payload limits, fallback behavior, and transcript/audit semantics before wiring audio into the read tool.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw add native audio attachments to the core read-tool contract, and what raw-media egress, fallback, and session/audit policy should govern that path?

Rationale: The source gap is clear, but the solution changes sensitive local media forwarding, provider capability routing, normalized model content, and session transcript semantics that automation cannot choose safely.

Likely owner: steipete

Owner confidence: high

Options:

- **Design native-audio contract first (recommended):** Settle typed audio blocks, provider transport, explicit raw-media egress, payload limits, unsupported-model behavior, and transcript/audit metadata before implementation.
- **Keep audio transcription-only for now:** Leave raw audio out of the read tool and direct users to existing STT/media-understanding paths until maintainers are ready to own native audio egress.
- **Fold into broader native-audio design:** Treat this read-tool request as a subcase of the broader native-audio tracker if maintainers want one product design thread.

## Reproduction Assessment

Yes, source-level. Current main only detects image MIME in the read tool before falling back to text decoding, and normalized message/tool-result contracts support text/image blocks rather than audio.

## Solution Assessment

No for a simple read-tool extension-list patch. The maintainable path needs a shared native-audio content/provider contract plus security, fallback, payload-limit, and session/audit policy first.
