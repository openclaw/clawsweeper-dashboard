## Label Justifications

- `P2`: This is a clear multimodal feature gap with real user value, but it is not an urgent regression, outage, crash loop, or data-loss event.
- `impact:session-state`: Native audio attachments would change what the session transcript, restore path, replay path, and audit trail can represent.
- `impact:security`: The requested behavior would forward original local audio bytes to model providers and needs explicit egress, retention, and audit boundaries.
- `impact:auth-provider`: The feature depends on model capability routing and provider-specific native audio serialization.

## Summary

Keep open: current main and the latest release still keep the read tool text/image-only, and native audio support needs maintainer decisions on typed audio content, provider egress, fallback behavior, and session audit semantics before implementation.

## What This Changes

The issue requests native audio-file handling in the read tool so audio files are sent as multimodal model attachments instead of decoded as text.

## Best Possible Solution

Define a shared, opt-in native-audio attachment contract for read results, model/provider capability checks, provider serialization, payload limits, fallback behavior, and transcript/audit semantics before wiring audio into the read tool.

Yes, source-level. Current main only detects image MIME in the read tool before falling back to text decoding, and normalized model/tool-result contracts support text/image blocks rather than audio.

## Solution Assessment

No for a simple read-tool extension-list patch. The maintainable path needs a shared native-audio content/provider contract plus security, fallback, payload-limit, config, and session/audit policy first.
