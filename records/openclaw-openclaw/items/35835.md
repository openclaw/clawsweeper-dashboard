## Summary

Keep open: current main and v2026.6.11 still route read-tool files through text or image-only content, and the broader native-audio tracker does not fully cover this local read-tool parity request.

## What This Changes

The issue requests native audio-file handling in the read tool so local audio is sent as a model attachment rather than decoded as raw text.

## Best Possible Solution

Define a typed native-audio content contract across read, llm-core, provider adapters, transcript/audit handling, and unsupported-model behavior before implementing the read-tool extension.
