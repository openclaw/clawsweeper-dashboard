## Summary

Keep open: current main and the latest release still keep read/tool-result media text/image-only, and native audio support needs maintainer decisions on typed audio content, provider egress, fallback behavior, and session/audit semantics before implementation.

## What This Changes

Request native audio-file support in the read tool so audio files are sent to capable models as multimodal attachments instead of decoded as text.

## Best Possible Solution

Define a shared, opt-in native-audio attachment contract for read results, provider serialization, capability checks, payload limits, fallback behavior, and transcript/audit semantics before wiring audio into the read tool.
