## Summary

Keep open: current main and the latest checked release still keep the read tool on text/image output, while the related native-audio PRs are closed unmerged and the broader tracker does not fully own local read-tool audio parity.

## What This Changes

Request audio files read by the built-in read tool be detected and passed as native multimodal attachments, with clear unsupported-model handling.

## Best Possible Solution

Define an opt-in typed native-audio contract across read, LLM content, provider serialization, payload/security limits, transcript persistence, and fallback behavior before implementing read-tool audio parity.
