## Summary

Keep open: current main and the latest stable release still limit the read tool and LLM tool-result contract to text/images, while the related native-audio issues and PRs are partial, open, or closed unmerged rather than a landed read-tool audio fix.

## What This Changes

Request audio file support in the read tool so local audio files are sent to capable models as multimodal attachments instead of decoded as text.

## Best Possible Solution

Define a first-class audio content/tool-result contract with provider capability gates, payload limits, raw-media egress policy, transcript/audit behavior, and fallback/error semantics before adding read-tool audio attachments.
