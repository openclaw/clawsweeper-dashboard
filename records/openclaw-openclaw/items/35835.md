## What This Changes

The issue requests native audio attachment support for the read tool so local audio files are sent to capable models instead of decoded as text.

## Best Possible Solution

Define a typed native-audio content contract across read, LLM core, provider adapters, payload limits, egress policy, and transcript/session handling, then implement read-tool audio parity on that contract or explicitly document audio as a media-understanding workflow.
