## Summary

Keep open: current main and v2026.6.11 still keep the read tool text/image-only, and the related native-media PR was closed unmerged rather than landing a safe read-tool audio contract.

## What This Changes

The issue requests native audio-file handling in the read tool so audio files are passed to capable models as multimodal attachments instead of raw text.

## Best Possible Solution

Define a typed native-audio attachment contract for read results, provider serialization, model-capability checks, unsupported-model behavior, payload limits, raw-media egress policy, and session/audit semantics before wiring audio into the read tool.
