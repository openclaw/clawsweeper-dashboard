## Summary

Keep open: current main and v2026.6.11 still keep the read tool text/image-only, and native audio support needs maintainer decisions on typed audio content, provider egress, fallback behavior, and session audit semantics before implementation.

## What This Changes

Request native audio-file handling in the read tool so audio files can be sent as model attachments instead of decoded as raw text.

## Best Possible Solution

Define a shared, opt-in native-audio attachment contract for read results, provider serialization, capability checks, payload limits, fallback behavior, and transcript/audit semantics before wiring audio into the read tool.
