## Summary

Keep open: current main and v2026.6.11 still keep the read/tool-result path text-and-image only, and native audio support needs a maintainer product/security decision before implementation.

## What This Changes

Request to make the read tool detect audio files and pass them as native multimodal model attachments instead of text-decoding bytes.

## Best Possible Solution

Define a shared opt-in native-audio attachment contract covering typed content, provider serialization, capability checks, byte limits, fallback behavior, and transcript/audit metadata before wiring audio into read.
