## Summary

Keep open: current main and v2026.6.11 still keep the read tool text/image-only, while native audio attachments require maintainer decisions on raw-media egress, provider capability routing, fallback behavior, and session/audit semantics.

## What This Changes

The issue requests extending the read tool so audio files are sent as multimodal model attachments instead of decoded as raw binary text.

## Best Possible Solution

Define an opt-in native-audio attachment contract covering read results, provider serialization, capability checks, payload limits, fallback behavior, and transcript/audit metadata before wiring audio into the read tool.
