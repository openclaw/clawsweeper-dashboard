## Summary

Keep open: current main and the latest release still make the read tool text/image-only, and native audio file attachment support needs a shared content, provider, session, and security contract before implementation is safe.

## What This Changes

The issue requests native audio-file handling in the read tool so audio files are passed as multimodal model attachments instead of decoded as raw text.

## Best Possible Solution

Define a typed native-audio attachment contract for read results, provider serialization, model-capability checks, payload limits, unsupported-model behavior, raw-media egress policy, and session/audit semantics before wiring audio into the read tool.
