## Summary

Keep open: current main and the latest release still make `read()` text/image-only for model-facing content, while audio remains routed through transcription/media-understanding paths or adjacent unmerged/closed work.

## What This Changes

Request native audio-file support in the read tool so audio files are sent to capable models as multimodal attachments instead of decoded as text.

## Best Possible Solution

Define a first-class audio content contract for read/tool results with provider capability gates, raw-media egress controls, payload limits, transcript/audit behavior, and explicit transcription fallback semantics.

- Existing transcription/media-understanding paths already define audio as derived text, so adding native audio to `read()` without a typed contract could create conflicting session semantics.
