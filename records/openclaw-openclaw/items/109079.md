## Summary

Keep this issue open. The two transcript examples strongly support a real usage-accounting defect, and current main still distinguishes aggregate attempt usage from per-call/context usage, so the reported cache-inclusive propagation is not proven fixed. The report overlaps the broader accounting work in https://github.com/openclaw/openclaw/issues/86684 and the display symptom in https://github.com/openclaw/openclaw/issues/108215, but its exact cache-inclusive values are useful regression evidence.

## What This Changes

Prevent cache-inclusive or cumulative provider usage from being treated as active session context occupancy or compaction input.

## Best Possible Solution

Create one typed, canonical active-prompt measurement and use it consistently for successful-turn overflow checks, compaction `tokensBefore`, and session occupancy; retain cache-inclusive and cumulative usage only for billing or diagnostics, with regression fixtures covering both reported values and sibling status paths.
