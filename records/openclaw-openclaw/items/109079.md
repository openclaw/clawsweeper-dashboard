## Label Justifications

- `P1`: The defect can make ordinary multi-call sessions appear over the context limit and trigger premature compaction in active agent workflows.
- `impact:session-state`: The reported incorrect value is persisted and surfaced as session context and compaction metadata.
- `impact:data-loss`: Premature compaction driven by an inflated context snapshot can discard detailed session history.

## Summary

Close as implemented on current main. The merged fix now preserves an exact last-call usage snapshot and prevents aggregate cache-inclusive run usage from becoming persisted session context; the latest shipped release predates that merge.

## What This Changes

The issue requests that cumulative multi-call, cache-inclusive usage never be persisted or displayed as current session context or compaction token snapshots.

## Best Possible Solution

Keep the exact-snapshot implementation on main, ship it in the next release, and track any remaining precheck-estimator behavior separately in https://github.com/openclaw/openclaw/issues/101929.

No on current main: the merged fix’s released-version Gateway scenario specifically reproduced cumulative cached usage after an aborted multi-call run, then demonstrated persisted context using the final-call snapshot instead.

## Solution Assessment

Yes. Carrying an exact per-call snapshot through subscription, settlement, and session persistence is narrower and safer than interpreting aggregate billing totals as active context; unknown remains preferable when no trustworthy snapshot exists.
