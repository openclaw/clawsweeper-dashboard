## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Require owner auth before serving document bytes:** `src/gateway/managed-document-attachments.ts:843-845`
  - body: The new document route treats device-token/trusted-scope requests as privileged and otherwise trusts a client-declared requester-session header before reading `record.original.path`. Current managed images require authenticated owner/admin context for byte fetches because requester-session headers are not an authorization boundary, so this endpoint needs the same owner check and safe file-read behavior before serving documents.
  - confidence: 0.92
- **[P1] Preserve outgoing-doc URLs in WebChat:** `src/gateway/server-methods/chat.ts:460-470`
  - body: This call emits `/api/chat/media/outgoing-doc/...` attachment URLs, but current WebChat only preserves `/api/chat/media/outgoing/` image URLs and treats `outgoing-doc` as a local absolute path. The link can therefore be wrapped through `/__openclaw__/assistant-media`, losing the managed route's attachment headers and user-visible fix.
  - confidence: 0.9
- **[P1] Strip document blocks when transcript append fails:** `src/gateway/server-methods/chat.ts:460-470`
  - body: The PR creates document attachment blocks, but the existing append-failure fallback strips only managed image blocks. If transcript append fails, WebChat can broadcast document links whose records were never promoted to history retention, leaving users with 404 download links after cleanup.
  - confidence: 0.87
- **[P2] Update the media-core import for current main:** `src/gateway/managed-document-attachments.ts:27`
  - body: Current main moved media constants to `@openclaw/media-core/constants`, so this new `../media/constants.js` import is stale and the PR is already conflicting against the current dependency layout. Rebase and use the current media-core import path before review can trust the branch.
  - confidence: 0.96
- **[P2] Encode non-ASCII download filenames:** `src/gateway/managed-document-attachments.ts:927-929`
  - body: Interpolating the sanitized Unicode filename directly into `filename="..."` can make Node reject non-ASCII header values and does not give browsers an RFC 5987 `filename*` value. Use an ASCII fallback plus `filename*` so international document names download reliably.
  - confidence: 0.84
