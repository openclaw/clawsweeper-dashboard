## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Require owner auth before serving document bytes:** `src/gateway/managed-document-attachments.ts:843-845`
  - body: The new document route treats device-token/trusted-scope access as privileged and otherwise trusts a client-declared requester-session header before reading `record.original.path`. Current managed-image downloads require authenticated owner/admin context and safe file reads because requester-session headers are not an authorization boundary, so this endpoint needs the same protection before serving local documents.
  - confidence: 0.93
- **[P1] Preserve outgoing-doc URLs in WebChat:** `src/gateway/managed-document-attachments.ts:447`
  - body: This emits `/api/chat/media/outgoing-doc/...` attachment URLs, but current WebChat only exempts `/api/chat/media/outgoing/` from local-source wrapping. These document URLs can be routed through `/__openclaw__/assistant-media`, losing the new route's attachment headers or failing to download at all.
  - confidence: 0.9
- **[P1] Strip document blocks when transcript append fails:** `src/gateway/server-methods/chat.ts:460-470`
  - body: The PR adds document managed blocks to assistant content, but the append-failure fallback strips only managed-image URLs. If append fails, the broadcast can still include document links whose records remain transient and can be cleaned up, leaving users with dead download links.
  - confidence: 0.86
- **[P2] Update the media-core import for current main:** `src/gateway/managed-document-attachments.ts:27`
  - body: Current main moved media constants to `@openclaw/media-core/constants`, so `../media/constants.js` no longer exists. The new module must use the current import path before the branch can build or be safely loaded.
  - confidence: 0.91
- **[P2] Guard the document route before importing it:** `src/gateway/server-http.ts:750-753`
  - body: The image route is only added when the scoped path matches, but this PR adds the document stage for every HTTP request before Control UI handling. That makes unrelated requests import the new document module and magnifies any module-load failure into a broader gateway availability problem.
  - confidence: 0.84
- **[P3] Remove the normal-PR changelog edit:** `CHANGELOG.md:149`
  - body: `CHANGELOG.md` is release-owned in this repository, so normal feature/fix PRs should carry release-note context in the PR body or squash message instead of editing the generated changelog directly.
  - confidence: 0.82
