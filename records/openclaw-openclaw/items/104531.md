## Summary

This PR is still necessary because current main retains long process output with raw UTF-16 slicing and can return a dangling surrogate at the tail boundary. The proposed fix is correctly placed at the shared capture owner, reuses the established normalization helper, preserves streaming and length limits, and has focused regression coverage plus credible live proof through the real cron on-exit history path.

## What This Changes

The PR changes retained process stdout and stderr tail truncation to use the shared UTF-16-safe slicer and adds a regression test for emoji split at the capture boundary.

## Best Possible Solution

Merge the centralized surrogate-safe tail slice and regression test after the exact PR head completes normal required checks; downstream consumers should continue receiving already-valid retained output without their own cleanup.
