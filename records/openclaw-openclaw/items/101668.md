## Summary

Keep open. The linked cron bug is real, but this PR is not merge-ready because it converts skipped/failed main-session wake attempts into successful cron runs, bypassing existing one-shot retry persistence and leaving delivery dependent on an ephemeral queue plus an unproven deferred heartbeat path.

## What This Changes

The PR changes main-session cron wake-now skipped/failed heartbeat results to keep the queued system event, request a heartbeat, return `ok`, and updates one-shot tests to expect queued events to remain.

## Best Possible Solution

Fix the disabled main-session cron wake at the heartbeat/gateway owner boundary or otherwise prove the deferred heartbeat will run, while preserving the one-shot retry semantics from https://github.com/openclaw/openclaw/pull/92225 and adding recurring default-wake regression proof.

- **[P1] Preserve retry until the wake actually runs:** `src/cron/service/timer.ts:2077`
  - body: This branch now returns `ok` for skipped and failed immediate heartbeats. Cron finalization deletes `deleteAfterRun` one-shots on `ok`, and system events are an in-memory queue, so a disabled one-shot can be deleted while its event is only waiting in process memory and can still be lost on restart. For recurring jobs this also records success without proving the queued heartbeat can get past the same disabled gate. Keep the disabled/failed run retryable, or fix the heartbeat gate so `ok` means the event is actually deliverable.
