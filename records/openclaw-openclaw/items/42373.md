Keep open: current main still lacks a costCurrency contract and keeps local model-cost estimates USD-shaped; related cost/billing work is adjacent, not a replacement, so this needs maintainer product/config direction.

## What This Changes

The issue requests a configurable currency for model-cost displays so local pricing values can be shown as CNY, EUR, USD, or another currency instead of always using dollars.

## Best Possible Solution

Define one currency contract before implementation: scope, ISO validation, mixed-currency aggregation, display-versus-accounting semantics, persisted field naming, doctor/docs behavior, and focused regression coverage.
