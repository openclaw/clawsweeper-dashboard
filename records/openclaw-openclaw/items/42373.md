## Summary

Keep open: current `main` and the latest release still treat configured model costs as USD-only, but adding `costCurrency` is a product/config contract decision rather than a narrow bug fix.

## What This Changes

Requested support for a `costCurrency` configuration option so model-cost displays can use symbols such as `¥` or `€` instead of always showing USD-style `$`.

## Best Possible Solution

Define a single currency contract before implementation, ideally reusing `Intl.NumberFormat` and the existing provider-usage unit semantics while keeping mixed-provider aggregation and USD-named telemetry/API fields coherent.
