## Summary

Keep open: current main and v2026.6.11 still use a USD-only model-cost and session-display contract with no `costCurrency` surface, and adding one is a new config/accounting product decision rather than a narrow bug fix.

## What This Changes

The issue requests a `costCurrency` configuration option so configured model costs can display as CNY, EUR, USD, or another local currency instead of always dollars.

## Best Possible Solution

Define one currency contract first, including scope, ISO-code versus symbol behavior, mixed-currency aggregation, and display-only versus accounting semantics, then update schema, types, docs, status, usage, UI, and persisted/API names together if maintainers accept it.
