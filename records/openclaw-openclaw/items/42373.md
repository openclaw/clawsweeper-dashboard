## Summary

Keep open: current main still has no `costCurrency` or non-USD contract for configured local model-cost estimates. Recent provider usage work supports provider-reported currency balances separately, but the local pricing config, persisted/session fields, docs, and display formatters remain USD-shaped.

## What This Changes

The issue requests a `costCurrency` configuration option so local model-cost estimates can display currencies such as CNY or EUR instead of always showing dollars.

## Best Possible Solution

Define a durable local model-cost currency contract before implementation: scope, ISO validation, display versus accounting semantics, mixed-currency aggregation, persisted field naming, docs, and focused regression coverage.
