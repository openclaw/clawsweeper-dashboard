## Summary

Keep open: current main and the latest release still define configured model costs as USD and render session/UI cost estimates through dollar-only or USD-named fields, while `costCurrency` would add a new public config and accounting/display contract that needs maintainer direction.

## What This Changes

The issue requests a `costCurrency` option so configured model costs for non-USD providers can display with the appropriate currency symbol.

## Best Possible Solution

Define one currency contract first, including scope, ISO-code handling, mixed-currency aggregation, and display-only versus accounting semantics, then update schema, docs, UI, status, and telemetry consistently.
