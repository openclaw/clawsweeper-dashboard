## Summary

Keep open: current main and v2026.6.11 still define configured model costs as USD and render local/session cost estimates with dollar-only helpers; the recently added provider billing currency handling is separate and does not implement the requested `costCurrency` config surface. This remains a product/config decision rather than a conservative cleanup close.

## What This Changes

Request to add a `costCurrency` configuration option so configured model cost estimates can display in local currencies instead of always using USD-style dollar output.

## Best Possible Solution

Define one currency contract first: scope, ISO-code versus symbol behavior, mixed-currency aggregation, display-only versus accounting semantics, and how USD-named stored/API/telemetry fields evolve, then update schema, docs, status, usage, and UI surfaces together.

- **Keep local estimates USD-only:** Leave configured `cost` as USD per million tokens and treat non-USD provider prices as unsupported until maintainers want a broader accounting model.
- **Add display-only preference:** Allow a narrow symbol/ISO display preference while explicitly keeping stored values and telemetry USD-like estimates, accepting mixed-currency ambiguity.
