## Summary

Keep open: current main and v2026.6.11 still keep local model-cost estimates as USD/dollar-only, while newer provider-billing surfaces support currency units separately; the remaining work is a product/config decision, not a conservative cleanup close.

## What This Changes

The issue requests a `costCurrency` configuration option so configured model costs can display non-USD currencies such as CNY or EUR.

## Best Possible Solution

Define a single ISO/unit currency contract for model-cost estimates first, including scope, aggregation, conversion versus display-only behavior, and reuse of the existing provider-billing formatter pattern before updating schema, docs, status, session, Usage UI, and telemetry together.

## Solution Assessment

No: a provider-level `costCurrency` knob is plausible, but it is not proven best until maintainers decide currency scope and mixed-currency aggregation semantics. The existing provider-billing `unit` and `Intl.NumberFormat` path is the safer pattern to reuse if the feature proceeds.
