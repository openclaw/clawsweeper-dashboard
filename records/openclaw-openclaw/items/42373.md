## Summary

Keep open: current main and the latest release still have a USD-only model cost/display contract and no `costCurrency` surface, but adding one is new cross-surface config and accounting behavior that needs maintainer product direction before implementation.

## What This Changes

The issue requests a `costCurrency` configuration option so configured model costs can be displayed in currencies other than USD.

## Best Possible Solution

Define one currency contract first, including scope, ISO-code versus symbol behavior, mixed-provider aggregation, and display-only versus accounting semantics, then update schema, types, docs, status, usage, UI, and telemetry surfaces together.
