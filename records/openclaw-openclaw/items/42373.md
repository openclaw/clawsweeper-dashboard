## Summary

Keep open: current main still has a USD-only local model cost contract and no `costCurrency` config surface, but adding one is a new cross-surface accounting/config decision rather than a narrow bug fix.

## What This Changes

Request to add a `costCurrency` configuration option so locally configured model-cost estimates can render non-USD currency symbols such as CNY or EUR.

## Best Possible Solution

Define one currency/accounting contract first, including scope, ISO-code handling, mixed-currency aggregation, display-only versus stored semantics, and how provider-reported billing remains separate from local estimates.
