## Summary

Keep open: current main and v2026.6.11 still treat configured model costs as USD estimates, and adding non-USD display requires a public config and accounting contract rather than a narrow bug fix.

## What This Changes

Request adding a public `costCurrency` config field so configured model-cost estimates can render CNY/EUR/USD instead of always dollar-denominated.

## Best Possible Solution

Define one cost-currency contract first: scope, ISO-code validation, mixed-currency aggregation, display-only versus accounting semantics, persisted USD fields, docs, and focused regression coverage.
