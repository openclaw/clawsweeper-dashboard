## Summary

Keep open: current main and the latest release still lack a `costCurrency` contract, while adjacent cost/billing work only covers USD-shaped local estimates or provider-reported billing units. This needs maintainer product/config direction before an implementation PR.

## What This Changes

The issue requests a configurable currency for local model-cost display so CNY/EUR-priced provider costs are not shown with a USD symbol.

## Best Possible Solution

Define one durable currency contract first: scope, ISO validation, mixed-currency aggregation, display-versus-accounting semantics, persisted field naming, docs, and regression coverage.
