## Summary

Keep open: current main and v2026.6.11 still have a USD-only cost contract with no `costCurrency` surface, and adding one needs a maintainer product/config decision rather than conservative cleanup.

## What This Changes

The issue requests a `costCurrency` config option so configured model costs can display local currency symbols instead of always using dollar-formatted output.

## Best Possible Solution

Define one currency contract first, including scope, ISO-code versus symbol behavior, mixed-currency aggregation, and display-only versus accounting semantics, then update schema, docs, status, usage, UI, and persisted/API naming consistently if maintainers accept the feature.

- **Add Display-Only Override:** Allow a symbol/ISO display override while explicitly preserving USD-like stored totals and accepting that it is not billing-grade accounting.

No, not yet. A provider-level `costCurrency` option is plausible, but maintainers need to decide the currency scope and mixed-currency behavior before this becomes the narrowest maintainable solution.
