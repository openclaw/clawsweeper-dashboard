## Summary

Keep open: current main and the latest release still have a USD-only cost accounting/display contract and no `costCurrency` config surface, but adding one is new config/product behavior that needs maintainer direction before implementation.

## What This Changes

Request adding a `costCurrency` configuration option so configured model cost estimates can display non-USD currency symbols such as CNY or EUR.

## Best Possible Solution

Have maintainers define one currency contract first: scope, ISO-code vs symbol behavior, mixed-provider aggregation, and whether this is display-only or changes cost accounting, then update config/schema/docs and every cost formatter together.
