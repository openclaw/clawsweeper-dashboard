## Summary

Keep open: current main and v2026.6.11 still expose model pricing as USD-only and render model-cost summaries with dollar formatting, while the requested non-USD currency behavior is a new public config/accounting contract that needs maintainer product direction.

## What This Changes

Request adding a costCurrency configuration option so model-cost displays can use non-USD symbols such as CNY/RMB or EUR instead of always `$`.

## Best Possible Solution

Define one currency contract first, including scope, ISO-code versus symbol behavior, display-only versus accounting semantics, and mixed-currency aggregation, then update schema, types, docs, status, usage, UI, and telemetry surfaces together.
