## Summary

Keep open: current main still treats configured model-cost estimates as USD and has no `costCurrency` contract; the request remains valid but needs maintainer product direction because it would add public config and cost-accounting semantics.

## What This Changes

The issue requests a `costCurrency` configuration option so local model-cost estimates can render CNY/EUR/etc. instead of always `$`.

## Best Possible Solution

If accepted, define currency-aware local pricing metadata and propagate it through estimate storage/API fields, status text, docs, and UI formatting while keeping provider-reported billing units separate.
