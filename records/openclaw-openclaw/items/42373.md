## Summary

Keep open: current main and the latest release still have no `costCurrency` path, while model pricing, status output, CLI/chat summaries, Control UI cost formatting, persisted fields, and telemetry are USD-shaped. The request is useful ergonomics, but it needs a maintainer product/accounting decision before implementation.

## What This Changes

The issue requests a new `costCurrency` configuration option so model cost displays can use non-USD currency symbols such as CNY or EUR.

## Best Possible Solution

Define one currency contract first: scope, ISO-code validation, mixed-currency behavior, display-only versus accounting semantics, persisted USD field treatment, docs, and tests; then implement the chosen schema/UI/status path consistently.
