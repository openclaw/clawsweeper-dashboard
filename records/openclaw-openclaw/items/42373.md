Keep open: current main still treats configured model costs as USD-only and the requested non-USD display requires a product/config contract rather than conservative cleanup.

## What This Changes

The issue requests a `costCurrency` configuration option so locally configured model-cost estimates can render in non-USD currencies.

Define one currency contract first: scope, ISO validation, mixed-currency aggregation behavior, display-only versus accounting semantics, persisted field naming, docs, and focused regression coverage.
