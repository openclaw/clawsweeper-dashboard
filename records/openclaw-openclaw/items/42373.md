## Summary

Keep open: current main and v2026.6.11 still treat configured model pricing and session cost displays as USD-only, and adding configurable currency is a product/config contract decision rather than a cleanup close.

## What This Changes

The issue requests a new `costCurrency` config option so model cost estimates can display non-USD currency symbols.

## Best Possible Solution

Define one explicit currency contract first, including scope, ISO-code versus symbol behavior, mixed-currency aggregation, and whether stored/API totals remain USD-only.

Options:

- **Define currency contract first (recommended):** Choose the scope and accounting/display semantics before implementation so mixed-provider totals and existing USD fields stay honest.
- **Keep model costs USD-only:** Leave the current contract intact and treat non-USD configured price tables as unsupported until maintainers want a larger accounting change.
- **Add display-only preference:** Allow a narrow symbol or ISO-code display preference while explicitly preserving USD-like stored totals and documenting the ambiguity.

## Solution Assessment

No: a provider-level `costCurrency` option is plausible, but it is not proven best until maintainers decide currency scope, aggregation behavior, and whether stored/API cost fields remain USD-only.
