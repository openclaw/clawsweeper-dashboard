## Summary

Keep open: current main and v2026.6.11 still define configured model costs as USD and do not provide a `costCurrency` path, so this needs a maintainer product/config decision rather than cleanup closure.

## What This Changes

The issue requests a `costCurrency` configuration option so configured model-cost estimates can display local currency symbols such as CNY or EUR instead of always dollars.

## Best Possible Solution

Define one cost-currency contract first, including scope, ISO-code validation, mixed-currency behavior, display-only versus accounting semantics, persisted USD field treatment, docs, and regression coverage.

Unclear until maintainers choose the contract. A provider-level `costCurrency` is plausible, but a formatter-only change would be too narrow because stored fields, telemetry, docs, and mixed-provider totals currently encode USD semantics.
