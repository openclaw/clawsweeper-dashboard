## Summary

Keep open: current main and v2026.6.11 still do not implement `costCurrency`, and the request adds a public config plus cost-accounting/display contract that needs maintainer product direction before implementation.

## What This Changes

The issue requests a `costCurrency` configuration option so configured model costs can display as currencies such as CNY or EUR instead of always USD.

## Best Possible Solution

Define one cost-currency contract first: scope, ISO-code validation, mixed-currency behavior, display-only versus accounting semantics, persisted USD field treatment, docs, and regression coverage.
