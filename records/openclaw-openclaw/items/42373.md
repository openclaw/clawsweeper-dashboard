## Summary

Keep open: current main and v2026.6.11 still expose model pricing as USD-only and have no `costCurrency` config surface, but adding currency semantics is a product/config decision rather than a narrow bug fix.

## What This Changes

The issue requests a new `costCurrency` option so configured model costs can display as currencies such as CNY, EUR, or USD instead of always using dollars.

## Best Possible Solution

Define one currency contract first, including scope, ISO-code versus symbol behavior, mixed-provider aggregation, display-only versus accounting semantics, and how it maps to stored/API/telemetry fields.

Existing provider-usage billing already carries exact currency units for provider-reported balances, so any model-cost currency option should align with that path.
