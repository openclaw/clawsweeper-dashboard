## Summary

Keep open: current main and the latest release still have no configurable currency for local model-cost estimates, and the request needs a product/config contract before implementation.

## What This Changes

Add a `costCurrency` configuration option so locally configured model costs can display as CNY, EUR, USD, or another chosen currency instead of always using `$`.

## Best Possible Solution

Define one cost-currency contract first: scope, ISO/unit validation, mixed-currency aggregation behavior, display-only versus accounting semantics, persisted field naming, docs, and focused regression coverage.
