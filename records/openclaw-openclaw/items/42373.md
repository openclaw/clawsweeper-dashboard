## Summary

Keep open: current main and the latest release still have no `costCurrency` path, and model cost accounting is explicitly USD-shaped across schema, status output, UI formatting, persisted session fields, and telemetry docs. This needs a maintainer product/accounting decision before implementation.

## What This Changes

The issue requests a new `costCurrency` configuration option so configured model costs can display in currencies such as CNY or EUR instead of always using `$`.

## Best Possible Solution

Define one currency contract first, including scope, ISO-code handling, mixed-currency aggregation, display-only versus accounting semantics, persisted USD field treatment, docs, and tests; then implement the chosen schema/UI/status path consistently.
