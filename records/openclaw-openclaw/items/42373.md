## Summary

Keep this issue open: current main still treats model/session estimated costs as USD and hard-codes dollar display, but adding `costCurrency` would create a new config and model-cost contract that needs maintainer product direction first.

## What This Changes

The issue requests a `costCurrency` config option so model/session cost displays can use symbols such as `¥` or `€` instead of always showing `$`.

## Best Possible Solution

Define one canonical currency contract for model-cost estimates, keep USD as the default, then propagate it through config/schema, model catalog, session/usage UI, docs, and focused fresh-config tests.
