## Summary

Keep open: current main and v2026.6.11 still have no `costCurrency` path, and the request changes public configuration plus accounting/display semantics rather than fixing a narrow broken behavior.

## What This Changes

Request a `costCurrency` configuration option so locally configured model costs can display in CNY, EUR, USD, or another chosen currency instead of always using `$`.

## Best Possible Solution

Define one currency contract first: scope, ISO-code validation, mixed-currency behavior, display-only versus accounting semantics, persisted USD field treatment, docs, and regression coverage; then implement the chosen schema/UI/status path consistently.
