## Summary

Keep open: current main still lacks a `costCurrency` or other non-USD contract for configured local model-cost estimates, while recent cost and billing work keeps local estimates USD-shaped and handles provider-reported billing units separately.

## What This Changes

The issue requests a `costCurrency` configuration option so locally configured model-cost estimates can display a non-USD currency symbol.

## Best Possible Solution

Define one maintainer-approved currency contract for local estimated model costs, then update schema, types, persistence/protocol naming, status output, Control UI formatting, and docs together.
