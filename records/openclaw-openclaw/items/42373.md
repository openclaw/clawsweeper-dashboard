## Summary

Keep open: current main still lacks a local model-cost currency contract, and the existing provider-reported billing currency path does not solve user-configured cost estimates that are stored and displayed as USD-shaped values.

## What This Changes

The issue requests a costCurrency configuration option so locally configured model costs can be displayed with non-USD currency symbols.

## Best Possible Solution

Define a durable local model-cost currency contract before implementation, including scope, ISO validation, display versus accounting semantics, mixed-currency aggregation, docs, and regression coverage.
