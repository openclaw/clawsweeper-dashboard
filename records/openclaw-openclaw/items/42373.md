## Summary

Keep open: current main and the latest release still have a USD-only configured model-cost contract with no `costCurrency` surface, but adding one is a config/accounting product decision rather than a narrow bug fix.

## What This Changes

The issue requests a configurable currency for model-cost display so non-USD provider costs are not shown with a dollar sign.

## Best Possible Solution

Define one currency contract first, including scope, ISO-code handling, mixed-currency aggregation, and display-only versus accounting semantics, then update schema, types, docs, status, usage, UI, and persisted/API names consistently if maintainers accept the feature.
