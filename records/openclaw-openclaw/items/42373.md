## Summary

Keep open: current main and v2026.6.11 still treat configured model costs as USD and render local cost estimates with dollar/USD-named fields; adding `costCurrency` would be a new public config and accounting contract that needs maintainer direction.

## What This Changes

The issue requests a `costCurrency` config option so configured model-cost estimates can display non-USD currencies such as CNY or EUR.

## Best Possible Solution

Define one currency contract first, including scope, ISO-code handling, mixed-currency aggregation, and display-only versus accounting semantics, then update schema, docs, status, UI, and telemetry consistently.
