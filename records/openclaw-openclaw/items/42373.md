## Summary

Keep open: current main and the latest release still treat usage costs as USD and render dollar-prefixed values, but adding a currency selector is a new config and accounting product surface that needs maintainer direction before implementation.

## What This Changes

The issue requests a configurable currency for cost display so providers with non-USD pricing can show symbols such as CNY or EUR instead of hardcoded dollar output.

## Best Possible Solution

Decide the accounting model first, then add a canonical currency field only if it can be applied consistently across config schema/help, pricing lookup, status/response usage, Control UI, docs, and any required doctor migration.

- **Design currency metadata first (recommended):** Add a canonical currency contract to pricing metadata and update all cost renderers only after the owner boundary, validation, docs, and migration behavior are decided.
- **Keep USD-only accounting:** Leave cost estimates as USD and document that users should convert non-USD provider rates before entering them.
- **Add display-only preference:** Add a global symbol preference for ergonomics while explicitly accepting that it may not represent mixed-provider accounting.

## Reproduction Assessment

Yes, source-level only: current main has no `costCurrency` config field, cost metadata is documented as USD, and the shared UI/status formatters emit `$`. I did not run a live UI because the issue is a feature request and the relevant behavior is directly visible in source.

## Solution Assessment

Unclear until maintainer direction: the proposed per-provider `costCurrency` is plausible, but model-level pricing currency or a global display preference would solve different product semantics. The narrowest maintainable fix depends on whether OpenClaw wants currency-aware accounting or only display customization.
