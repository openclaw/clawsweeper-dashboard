## Summary

Keep open: current main and the latest release still define configured model costs as USD-only and render session/usage costs with dollar formatting, while adding `costCurrency` would be a new cross-surface config and accounting decision rather than a narrow bug fix.

## What This Changes

The issue requests a `costCurrency` configuration option so model-cost displays can use non-USD currency symbols.

## Best Possible Solution

Define the currency contract first, including scope, ISO-code versus symbol behavior, mixed-currency aggregation, display-only versus accounting semantics, then update schema, types, docs, status, usage, UI, tests, and any persisted/API naming together.
