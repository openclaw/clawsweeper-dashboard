## Summary

Keep this open: current main still treats model/session estimated costs as USD/dollar-only, but adding `costCurrency` is a new model-cost/config contract that needs maintainer product direction before implementation.

## What This Changes

Add a configurable currency for model cost values so cost displays can use symbols such as ¥ or € instead of always showing dollars.

## Best Possible Solution

Define one canonical model-cost currency contract with USD default, then propagate it through config/schema, model registry, status/chat/usage displays, docs, and focused tests.
