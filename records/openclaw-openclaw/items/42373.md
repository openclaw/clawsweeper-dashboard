## Summary

Keep open: current main still has a USD-only local model-cost contract and no `costCurrency` surface, while adjacent provider-billing currency support is intentionally separate from session-derived estimated costs.

## What This Changes

The issue requests a `costCurrency` configuration option so model cost displays can show CNY/EUR/USD symbols instead of always showing USD-style dollars.

## Best Possible Solution

Define one local-cost currency contract first, including scope, ISO-code versus symbol behavior, mixed-provider aggregation, and whether stored/session estimates remain USD-only or become unit-aware, then update schema, types, docs, status, usage, and UI together.
