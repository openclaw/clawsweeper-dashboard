## Summary

Keep open: current main and the latest release still have a USD-only model-cost contract and dollar-only model cost display, while adding configurable currency would be a new cross-surface config/accounting decision rather than a narrow bug fix.

## What This Changes

Requests a new `costCurrency` configuration option so configured model cost estimates can display in a local/provider currency instead of always using dollars.

## Best Possible Solution

Define one currency contract first, including scope, ISO-code versus symbol behavior, mixed-currency aggregation, and display-only versus accounting semantics, then update schema, types, docs, status, usage, UI, tests, and any persisted/API names together.
