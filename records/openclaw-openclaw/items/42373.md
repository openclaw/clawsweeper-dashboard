## Summary

Keep open: current main and the latest release still treat configured model pricing as USD-only with no `costCurrency` config surface, but adding non-USD currency semantics is a product/config decision rather than a narrow bug fix.

## What This Changes

The issue asks for a `costCurrency` option so configured model costs can display as currencies such as CNY or EUR instead of always showing dollars.

## Best Possible Solution

Define one currency contract first: scope, ISO-code versus symbol display, mixed-currency aggregation, and how USD-named storage/API fields behave.
