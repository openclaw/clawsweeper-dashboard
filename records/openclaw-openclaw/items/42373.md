## Summary

Keep open: current main and v2026.6.11 still define configured model costs as USD estimates, and supporting non-USD display needs a public currency/accounting contract rather than cleanup closure.

## What This Changes

Request to add a `costCurrency` config option so locally configured model-cost estimates can display currencies such as CNY, RMB, or EUR instead of always `$`.

## Best Possible Solution

Define one local cost-currency contract first: scope, ISO-code validation, mixed-currency aggregation, display-only versus accounting semantics, persisted USD fields, docs, and focused regression coverage.
