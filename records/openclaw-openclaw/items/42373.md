## Summary

Keep this issue open: current main still treats model/session cost estimates as USD and renders dollar-only labels, but adding configurable currency is new config and pricing-contract surface that needs maintainer product direction.

## What This Changes

Request to add a `costCurrency` config option so model/session cost estimates can render in currencies such as CNY or EUR instead of hard-coded dollars.

## Best Possible Solution

Define one canonical model-cost currency contract with USD as the default, then propagate it through config/schema, model registry, status/usage UI, docs, and focused fresh-config tests.
