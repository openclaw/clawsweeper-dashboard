## Summary

Keep open: current main and v2026.6.11 still lack a `costCurrency` path, and the request changes public configuration plus cost-accounting semantics rather than fixing a narrow broken behavior.

## What This Changes

The issue requests a `costCurrency` config option so configured model/session cost displays can show non-USD currencies such as CNY or EUR.

## Best Possible Solution

Define one cost-currency contract first, including scope, ISO-code validation, mixed-currency behavior, display-only versus accounting semantics, persisted USD field treatment, docs, and regression coverage.
