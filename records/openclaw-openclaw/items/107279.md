## Summary

Keep this PR open for a narrow repair. The provider-level behavior is well targeted and convincingly proven, but the current head preserves the required-source callback type only by casting it to a source-less function and then invoking it without a source for orphan results. Because `transformMessages` is plugin-SDK surface, that remains a concrete runtime contract violation rather than a complete resolution of the prior finding.

## What This Changes

The PR adds opt-in target-safe tool-call ID normalization for Anthropic and Google replay paths, including orphaned results and same-model-tagged calls, with regression and SDK compatibility coverage.

## Best Possible Solution

Keep normalization at the shared transform boundary, but route target-safe handling through a separately typed internal helper or a discriminated overload that explicitly requires a source-independent normalizer, while leaving the existing three-argument plugin SDK contract unchanged.
