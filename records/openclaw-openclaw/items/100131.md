## Summary

The PR targets an open canonical coverage-gate request, but its new CI job invokes a command that current docs explicitly describe as informational with no enforced thresholds. It therefore adds cost and artifacts without delivering the claimed regression gate; it also still lacks a trusted after-fix execution showing the job enforces a failure condition and uploads its report.

## What This Changes

Adds a trusted main/manual-only `coverage-threshold` CI job, coverage-artifact upload, preflight routing output, and a workflow guard test.

## Best Possible Solution

Agree the unit-lane coverage policy, implement actual threshold semantics in the owned Vitest configuration, retain the workflow job as the trusted rollout lane, document its scope, and attach a trusted run proving both enforcement and artifact upload.
