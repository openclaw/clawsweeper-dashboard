## Summary

This PR fixes the reported user-driven edit loss and has strong exact-head proof, but it does not fully freeze the submitted draft: pending branch discovery can still change the worktree base while creation is in flight, causing a failed request to restore different retry state.

## What This Changes

The PR locks the Control UI New Session message, target controls, suggestions, and recent-session actions while `sessions.create` is pending, restores them after failure, and adds mocked Gateway E2E coverage.

## Best Possible Solution

Invalidate or snapshot pending branch discovery when submission begins so the visible draft and every retry parameter remain identical to the submitted request, with regression coverage for branch resolution during a failed create.
