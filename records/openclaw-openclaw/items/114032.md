## What This Changes

This PR introduces an optimistic, history-free Control UI route for a new thread so chat appears before `sessions.create` returns, then either commits the canonical route or restores the complete New session draft after failure or Gateway identity changes.

## System Context

The Control UI New session page gathers the first-message draft and asks the Gateway to create a persistent session. The changed route handoff lets the UI render a temporary chat view immediately, while later success commits the canonical session URL and failure restores the original draft state.
