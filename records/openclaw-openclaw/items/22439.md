## Summary

Keep open: the branch is useful but not merge-ready because it preserves legacy no-override bootstrap behavior while the new resolver and config comments describe omitted config as if it selected real `minimal` or `standard` tiers. That mismatch can make explicit `standard` silently drop hook-loaded context that omitted config still keeps, so the public config contract needs maintainer confirmation and a small repair before merge.

## What This Changes

The branch adds `agents.defaults.bootstrapTier` with `minimal`/`standard`/`full` bootstrap filtering, source tagging for root versus hook-loaded bootstrap files, and schema/help/tests for tiered context loading.

## Best Possible Solution

Keep omitted `bootstrapTier` as a documented legacy/default compatibility mode if that is the intended direction, then make the resolver, type/help text, public docs, and tests explicitly distinguish omitted config from explicit `minimal`, `standard`, and `full`.
