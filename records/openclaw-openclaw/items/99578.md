## Summary

Keep open: the replay cap is still a useful fix for the linked Codex worker runaway, but the current head retains every streamed echo text and still lacks real behavior proof from a live app-server run.

## What This Changes

This PR changes the Codex app-server event projector and tests to cap native tool output at 10,000 characters across replay, transcript, progress, trajectory, and raw-echo suppression paths.

## Best Possible Solution

Keep the projector-side cap, but store one stable bounded echo identifier per tool item instead of per-delta text and add redacted real app-server proof before merge.

## Reproduction Assessment

## Solution Assessment

No: the cap location is plausible, but the echo-suppression state should be bounded per item or by stable hash/prefix rather than retaining changing per-delta display strings.
