## Summary

Keep open. Current main and the latest release still preserve WhatsApp `messageTimestamp` as metadata but batch inbound WhatsApp text through receive-time debounce, so the requested server-timestamp coalescing behavior remains unresolved and needs a maintainer product/config choice.

## What This Changes

Request batching WhatsApp inbound messages by WhatsApp server `messageTimestamp` so delayed forward-plus-comment or rapid-fire messages can reach the agent as one turn.

## Best Possible Solution

Add a WhatsApp-owned, backwards-compatible timestamp coalescing mode for text-only messages from the same account, conversation, and sender, with a small documented tolerance and tests that preserve media, location, quote, control-command, read-receipt, and shutdown-drain behavior.

## Reproduction Assessment

Yes, at source level. Current WhatsApp inbound delivery uses a receive-time debouncer keyed by account, conversation, and sender while `messageTimestamp` is only stored on the emitted message, so delayed same-timestamp Baileys deliveries can miss the existing debounce window.

## Solution Assessment

Unclear as a final product choice. Timestamp coalescing is the right implementation family for the reported WhatsApp behavior, but maintainers still need to choose the default, tolerance, and config shape.
