## Summary

The requested behavior remains missing on current main and in v2026.6.11: WhatsApp server timestamps order messages only after receive-time debounce has already grouped them. The issue should stay open, but implementation should pause for a maintainer decision because the proposed 50–100 ms flush cannot bridge the reported 5–10 second delivery gap, while a long timestamp hold changes latency and can merge unrelated same-second messages.

## What This Changes

Add WhatsApp inbound coalescing that groups messages by WhatsApp server timestamp rather than only receive-time debounce.

## Best Possible Solution

Add an opt-in WhatsApp-owned coalescing mode only after defining a bounded multi-second hold, strict account/conversation/sender and eligible-message grouping, immediate flush boundaries for commands and non-text events, and live proof that delayed forward-plus-comment messages combine without merging unrelated same-second traffic.
