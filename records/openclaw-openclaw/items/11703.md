## Summary

Keep open. Current main and v2026.6.11 still preserve WhatsApp `messageTimestamp`, but inbound batching is keyed by account, conversation, and sender with a receive-time timer; the remaining timestamp tolerance, default behavior, and config shape need maintainer product direction.

## What This Changes

Request to batch simultaneous WhatsApp messages by Baileys/WhatsApp server `messageTimestamp` so delayed forward-plus-comment messages land in one agent turn.

## Best Possible Solution

Add a WhatsApp-owned, backwards-compatible timestamp coalescing mode or narrow default for text-only same-account, same-conversation, same-sender messages, while preserving existing media, location, reply-context, access-control, self-message, and control-command bypasses.

## Reproduction Assessment

Yes, at source level: current main parses and forwards WhatsApp `messageTimestamp`, but the debounce key/timer path does not use it for coalescing. I did not run a live WhatsApp/Baileys delayed-delivery reproduction.

## Solution Assessment

Unclear until maintainers choose the product semantics. Timestamp coalescing is plausible, but the default, tolerance, and config contract need owner review to avoid over-batching and compatibility surprises.
