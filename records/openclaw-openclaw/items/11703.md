## Summary

Keep open. Current main and v2026.6.11 still preserve WhatsApp `messageTimestamp` as message metadata, but inbound batching is keyed only by account, conversation, and sender with a receive-time debounce timer; the remaining timestamp tolerance/default/config semantics need maintainer product direction.

## What This Changes

The issue requests batching WhatsApp messages by WhatsApp server `messageTimestamp` instead of receive time so forwarded/commented messages can reach the agent in one turn.

## Best Possible Solution

Add a WhatsApp-owned, backwards-compatible timestamp coalescing mode or narrow default for text-only same account/conversation/sender messages, preserving existing media/location/quote/control-command bypasses and documenting any config surface.

## Reproduction Assessment

Yes at source level: current main parses and forwards WhatsApp `messageTimestamp`, but the debounce key/timer path does not use it for coalescing. This review did not run a live WhatsApp/Baileys delayed-delivery reproduction.

## Solution Assessment

Unclear until maintainers choose the product semantics: the timestamp-coalescing direction is plausible, but the proposed config/default/tolerance needs ownership review to avoid over-batching and compatibility surprises.
