## Summary

Keep open. Current main and v2026.6.11 still preserve WhatsApp `messageTimestamp` as metadata, but inbound batching remains the receive-time debounce path keyed by account, conversation, and sender; the timestamp tolerance/default/config semantics still need maintainer direction.

## What This Changes

Requests WhatsApp text-message batching by WhatsApp server `messageTimestamp` so delayed same-action messages arrive as one agent turn instead of separate receive-time debounce turns.

## Best Possible Solution

Choose a WhatsApp-owned timestamp coalescing contract for text-only same account/conversation/sender messages, then implement it with focused regression tests and docs while preserving media, location, quote, access-control, self-message, and control-command bypass behavior.

## Reproduction Assessment

Yes, at source level: current main parses and forwards WhatsApp `messageTimestamp`, but the debounce key and timer path do not use it for coalescing. I did not run a live WhatsApp/Baileys delayed-delivery reproduction.

## Solution Assessment

Unclear until maintainers choose the product semantics. Timestamp coalescing is plausible, but the default, tolerance, and config shape need ownership review to avoid over-batching and compatibility surprises.
