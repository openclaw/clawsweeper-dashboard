## Summary

Keep open. Current main and v2026.6.11 still preserve WhatsApp `messageTimestamp` but batch only through the account/conversation/sender receive-time debounce path; the timestamp tolerance, default behavior, and config shape still need maintainer product direction.

## What This Changes

The issue asks for WhatsApp inbound batching to use Baileys `messageTimestamp` so simultaneously sent messages are grouped even when decrypted and delivered several seconds apart.

## Best Possible Solution

Add a WhatsApp-owned, backwards-compatible timestamp coalescing mode or narrow default for text-only same account/conversation/sender messages, preserving existing media/location/quote/control-command bypasses and documenting any config surface.

## Reproduction Assessment

Yes, at source level: current main parses and carries WhatsApp message timestamps, but the debounce key and timer do not group by that timestamp. No live WhatsApp delayed-delivery repro was run in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product semantics. Timestamp coalescing is plausible, but the tolerance, default behavior, and config shape need ownership review to avoid over-batching and compatibility surprises.
