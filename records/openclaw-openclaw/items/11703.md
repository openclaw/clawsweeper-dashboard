## Summary

Keep open. Current main still preserves WhatsApp `messageTimestamp` as inbound metadata and sort input, but batching is still keyed and timed by receive-time debounce; the remaining tolerance, default behavior, and config precedence need maintainer direction.

## What This Changes

The issue requests batching WhatsApp inbound text messages by Baileys `messageTimestamp` instead of only by receive-time debounce.

## Best Possible Solution

Add a WhatsApp-owned timestamp coalescing mode for text-only same account/conversation/sender messages after maintainers choose the default, tolerance, and config shape; preserve current media, location, reply-context, access-control, self-message, control-command, and shutdown-drain behavior.

## Reproduction Assessment

Yes, at source level: current main parses and forwards WhatsApp `messageTimestamp`, but the debounce key and timer path does not use it for coalescing. I did not run a live WhatsApp/Baileys delayed-delivery reproduction.

## Solution Assessment

Unclear until maintainers choose the product semantics. Timestamp coalescing is plausible, but default behavior, tolerance, and config precedence need ownership review to avoid over-batching and compatibility surprises.
