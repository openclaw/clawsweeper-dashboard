## Summary

Keep open. Current main and v2026.6.11 still use WhatsApp server timestamps only as metadata/ordering input while batching is driven by receive-time debounce timers, so the requested timestamp coalescing remains unimplemented and needs maintainer direction.

## What This Changes

Batch same- or near-same WhatsApp server-timestamp text messages into one inbound agent turn instead of relying only on receive-time debounce.

## Best Possible Solution

Add a WhatsApp-owned, backwards-compatible timestamp coalescing mode for text-only same account/conversation/sender messages after maintainers choose tolerance, default, and config precedence, while preserving current media, command-bypass, access-control, reply-context, and self-message behavior.

## Reproduction Assessment

Yes, at source level: current main parses and forwards WhatsApp messageTimestamp, but the debounce key and timer path do not use it for coalescing. I did not run a live WhatsApp/Baileys delayed-delivery reproduction.

## Solution Assessment

Unclear until maintainers choose the product semantics: the timestamp-coalescing direction is plausible, but the proposed config/default/tolerance needs ownership review to avoid over-batching and compatibility surprises.
