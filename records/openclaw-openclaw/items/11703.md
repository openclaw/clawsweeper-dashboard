## Summary

Keep open. Current main and the latest release still preserve WhatsApp `messageTimestamp` as inbound metadata, but batching is still driven by receive-time debounce keys/timers; the remaining timestamp tolerance, default behavior, and config precedence need maintainer direction before implementation.

## What This Changes

Request timestamp-based batching for WhatsApp inbound text messages so delayed same-action messages arrive in one agent turn.

## Best Possible Solution

Add a WhatsApp-owned timestamp coalescing mode for text-only same account/conversation/sender messages after maintainers choose the default, tolerance, and config shape; preserve current media, location, reply-context, access-control, self-message, and control-command behavior.

## Reproduction Assessment

Yes, at source level: current main parses and forwards WhatsApp `messageTimestamp`, but the debounce key and timer path does not use it for coalescing. I did not run a live WhatsApp/Baileys delayed-delivery reproduction.

## Solution Assessment

Unclear until maintainers choose the product semantics. Timestamp coalescing is plausible, but default behavior, tolerance, and config precedence need ownership review to avoid over-batching and compatibility surprises.
