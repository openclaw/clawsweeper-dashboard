## Summary

Keep open. Current main and the latest release still preserve WhatsApp `messageTimestamp` as metadata while inbound batching is keyed and timed by receive-time debounce, so the requested timestamp coalescing remains unimplemented and needs maintainer direction.

## What This Changes

Request timestamp-based WhatsApp inbound message coalescing so simultaneously sent messages can arrive in one agent turn despite delayed Baileys delivery.

## Best Possible Solution

Add a WhatsApp-owned timestamp coalescing mode for text-only same-account, same-conversation, same-sender messages after maintainers choose tolerance, default behavior, and config precedence.

## Reproduction Assessment

Yes, at source level: current main parses and forwards WhatsApp `messageTimestamp`, but the debounce key and timer path do not use it for coalescing. I did not run a live WhatsApp delayed-delivery reproduction.

## Solution Assessment

Unclear until maintainers choose product semantics. Timestamp coalescing is plausible, but default behavior, tolerance, and config precedence need ownership review to avoid over-batching and compatibility surprises.
