## Summary

Current main and v2026.6.11 still batch WhatsApp text by account, conversation, sender, and receive-time timeout; the platform timestamp only orders messages already captured in one buffer, so the requested delayed-delivery coalescing remains missing. This is a valid feature request, but its grouping tolerance, maximum hold, default behavior, and config precedence require maintainer product judgment before implementation.

## What This Changes

Add WhatsApp server-timestamp-aware coalescing so related text messages delivered several seconds apart can reach the agent as one turn.

## Best Possible Solution

Implement a WhatsApp-owned, opt-in coalescing policy around the existing generic debouncer, keyed by account, conversation, sender, and bounded server-time criteria, with a maximum receive-time hold, preserved immediate flushes for non-combinable content, focused fake-timer coverage, and a redacted live delayed-delivery trace.
