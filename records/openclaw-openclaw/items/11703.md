## Summary

Keep open. Current main and the latest release still preserve WhatsApp server timestamps as metadata, but inbound batching remains keyed by account, conversation, and sender with a receive-time debounce timer; the remaining tolerance/default/config semantics need maintainer product direction.

## What This Changes

The issue requests batching related WhatsApp inbound messages by WhatsApp `messageTimestamp` instead of only by receive-time debounce.

## Best Possible Solution

Add a WhatsApp-owned, backwards-compatible timestamp coalescing mode or narrow default for text-only same account/conversation/sender messages, preserving existing media, location, quote, access-control, self-message, and control-command flushing behavior.

## Reproduction Assessment

Yes at source level: current main parses and forwards WhatsApp `messageTimestamp`, but the debounce key/timer path does not use it for coalescing. This review did not run a live WhatsApp/Baileys delayed-delivery reproduction.

## Solution Assessment

Unclear until maintainers choose the product semantics: timestamp coalescing is plausible, but the proposed config/default/tolerance needs ownership review to avoid over-batching and compatibility surprises.
