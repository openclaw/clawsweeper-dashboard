## Summary

Keep open. Current main and v2026.6.11 still preserve WhatsApp `messageTimestamp` only as inbound metadata while batching is driven by receive-time debounce keys and timers, so the requested timestamp coalescing remains unimplemented and needs maintainer product direction.

## What This Changes

The issue requests WhatsApp inbound batching that groups messages by WhatsApp server `messageTimestamp` rather than only by local receive-time debounce.

## Best Possible Solution

Add a WhatsApp-owned timestamp coalescing mode for text-only same account, conversation, and sender messages after maintainers choose the tolerance, default, and config precedence, preserving media, location, reply-context, access-control, command-bypass, and self-message behavior.

## Reproduction Assessment

Yes, at source level: current main parses and forwards WhatsApp `messageTimestamp`, but the debounce key and timer path do not use it for coalescing. I did not run a live WhatsApp/Baileys delayed-delivery reproduction.

## Solution Assessment

Unclear until maintainers choose product semantics. Timestamp coalescing is plausible, but default behavior, tolerance, and config precedence need ownership review to avoid over-batching and compatibility surprises.
