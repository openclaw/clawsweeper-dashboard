## Summary

Keep open. Current main and v2026.6.11 still preserve WhatsApp `messageTimestamp`, but batching is still keyed by account/conversation/sender and flushed by receive-time debounce; the remaining timestamp tolerance, default behavior, and config shape need maintainer direction before repair automation.

## What This Changes

Request to batch delayed WhatsApp text messages by WhatsApp server `messageTimestamp` instead of relying only on receive-time debounce.

## Best Possible Solution

Approve a WhatsApp-owned, backward-compatible timestamp coalescing mode or narrow default for text-only same account/conversation/sender messages, preserving media/location/quote/control-command bypasses with docs, focused fake-timer coverage, and live WhatsApp proof before landing.

## Reproduction Assessment

Yes, at source level. Current main parses and carries WhatsApp `messageTimestamp`, but the debounce key and timer do not use it for coalescing delayed same-timestamp deliveries.

## Solution Assessment

Unclear until maintainers choose the product semantics. Timestamp coalescing is plausible, but tolerance, default behavior, and config precedence need ownership review to avoid over-batching and compatibility surprises.
