## Summary

Keep open. Current main and the latest release still preserve WhatsApp `messageTimestamp` as metadata, but batching is still keyed by account, conversation, and sender with a receive-time timer; the timestamp tolerance, default behavior, and config shape remain maintainer product decisions.

## What This Changes

Request to batch WhatsApp text messages from the same chat and sender using the WhatsApp server `messageTimestamp` rather than only receive-time debounce.

## Best Possible Solution

Add a WhatsApp-owned, backwards-compatible timestamp coalescing path for text-only inbound messages from the same account, conversation, and sender, with a documented tolerance/default and tests that preserve media, control-command, access-control, and reply-context behavior.

## Reproduction Assessment

Yes at source level: current main parses `messageTimestamp` but batches only by receive-time debounce key and timer. I did not run a live WhatsApp/Baileys timing reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product shape. The narrow owner-boundary fix is WhatsApp-local timestamp coalescing, but the tolerance, default, and config contract should be decided before implementation.
