## Summary

Keep open. Current main and v2026.6.11 still preserve WhatsApp `messageTimestamp` as inbound metadata, but batching is still keyed by account, conversation, and sender with receive-time debounce timers; timestamp tolerance, default behavior, and config precedence remain maintainer product decisions.

## What This Changes

Request timestamp-based WhatsApp inbound coalescing so simultaneously sent messages with the same or nearby WhatsApp server timestamp arrive as one agent turn instead of separate receive-time-debounced turns.

## Best Possible Solution

Add a WhatsApp-owned, backwards-compatible timestamp coalescing mode for text-only same account/conversation/sender messages after maintainers choose the default, tolerance, and config shape; preserve current media, location, reply-context, access-control, self-message, and control-command behavior.

## Reproduction Assessment

Yes, at source level: current main parses and forwards WhatsApp `messageTimestamp`, but the debounce key/timer path does not use it for coalescing. I did not run a live WhatsApp/Baileys delayed-delivery reproduction.

## Solution Assessment

Unclear until maintainers choose the product semantics. Timestamp coalescing is plausible, but default behavior, tolerance, and config precedence need ownership review to avoid over-batching and compatibility surprises.
