## Summary

Keep open. Current main and the latest tagged release still preserve WhatsApp `messageTimestamp` as metadata, but inbound batching remains keyed by account, conversation, and sender with a receive-time debounce timer; the remaining timestamp tolerance, default behavior, and config shape need maintainer product direction.

## What This Changes

Issue requests batching simultaneous WhatsApp messages by Baileys `messageTimestamp` so forwarded content plus comments arrive in one agent turn.

## Best Possible Solution

Add a WhatsApp-owned, backwards-compatible timestamp coalescing mode or conservative default for text-only same account/conversation/sender messages, while preserving current media, location, quote, access-control, self-message, and control-command bypass behavior and documenting any new config surface.

## Reproduction Assessment

Yes at source level: current main parses and forwards WhatsApp `messageTimestamp`, but the debounce key and timer path do not use it for coalescing. I did not run a live WhatsApp/Baileys delayed-delivery reproduction.

## Solution Assessment

Unclear until maintainers choose the product semantics: timestamp coalescing is a plausible direction, but the tolerance, default behavior, and config shape need ownership review to avoid over-batching and upgrade surprises.
