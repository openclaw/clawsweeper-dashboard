## Label Justifications

- `merge-risk: 🚨 session-state`: An aborted classified attempt can be returned as completed, causing the recorded fallback outcome to disagree with the caller's terminal cancellation state.

## Summary

Keep this PR open: the linked duplicate-response bug is credible, but the proposed early-success guard can swallow terminal cancellation, and the submitted evidence does not demonstrate the fix in a real configured fallback chain.

## What This Changes

The PR adds an optional result-success callback that treats delivery or visible-output evidence as successful and stops further model fallback attempts despite a non-null fallback classification.

## Best Possible Solution

Keep one canonical success/failure decision in the embedded result classifier or shared terminal-outcome normalization, preserve abort precedence, add regression coverage using real embedded result shapes, and prove the fix with a configured two-model run plus redacted trajectory or runtime logs.

Yes—the linked issue provides a concrete v2026.7.1 fallback configuration and trajectory-log inspection path, and the current source path can classify a completed result before deciding whether to advance. This read-only review did not execute the live reproduction.

## Solution Assessment

No—the duplicate-delivery problem should be fixed, but a generic success callback before abort handling is not the safest owner boundary. The classifier or shared terminal-outcome path should make the decision once while preserving cancellation precedence.
