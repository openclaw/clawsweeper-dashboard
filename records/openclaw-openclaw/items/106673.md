## Summary

Keep this open for a maintainer product decision: current main deliberately preserves a loopback-only recovery path when direct Tailnet binding is unavailable, while Serve/Funnel setup failures are warning-only; the reported public-exposure consequence is unsupported, but the degraded startup state could be surfaced more clearly.

## What This Changes

Change explicitly requested Tailscale gateway startup failures from warning-only degradation to a fatal startup error.

## Best Possible Solution

Return a structured Tailscale exposure result, record it in Gateway startup outcomes/readiness/status, and prominently report degraded remote exposure while retaining the safe loopback recovery path unless maintainers explicitly choose fail-closed startup semantics.
