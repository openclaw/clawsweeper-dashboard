## Summary

Keep open: current main and the latest release still build Skill Workshop lifecycle approvals from static text, expose no Skill Workshop approval-timeout config, and render no proposal metadata in the approval message. The open timeout PRs cover only part of the report, while the proposal-detail and timeout-policy shape still needs maintainer security/product review.

## What This Changes

The issue requests richer Skill Workshop apply approval details and a longer or configurable approval timeout for reviewing proposals.

## Best Possible Solution

Design one security-reviewed Skill Workshop approval request shape that shows minimal proposal context and a safe inspect path, then choose either a maintainer-approved apply timeout default or a documented config surface that preserves fail-closed lifecycle approval.

## Reproduction Assessment

Yes. Source inspection reproduces the central behavior: Skill Workshop lifecycle approval requests are built from static text, omit proposal details, and do not set a timeout override; comments add real-world Telegram evidence that the fixed 120s window is still painful.

## Solution Assessment

Unclear as an immediate implementation. Richer approval details look like the right owner-boundary fix, but timeout configurability or a longer default needs maintainer security/product approval and coordination with the open timeout PRs.
