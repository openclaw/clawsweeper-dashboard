## Summary

Keep open: current main and v2026.6.11 still build Skill Workshop lifecycle approvals from static action text, with no proposal metadata and no Skill Workshop-specific timeout setting. The open related PRs only cover parts of the timeout problem, and the new Telegram operator report reinforces that the visible approval card still lacks enough context and expires too quickly for async operators.

## What This Changes

The issue requests richer Skill Workshop apply approval details and a longer or configurable approval timeout.

## Best Possible Solution

Define a bounded Skill Workshop approval-detail contract for proposal id, target skill, capped description, safe preview, and inspect affordance, then choose one coherent approval-timeout policy and update docs/tests around that contract.

## Reproduction Assessment

Yes. Source inspection reproduces the reported prompt shape because the policy returns only static action text and no proposal metadata or Skill Workshop timeout override; the July 3 Telegram comment also reports the 120s hardcoded expiry and missing proposal details in a real approval card.

## Solution Assessment

Unclear as an implementation choice. Enriching approval context is directionally right, but the exact preview fields, inspect/deep-link behavior, and timeout config/default policy need maintainer security and UX direction before an autonomous fix is safe.
