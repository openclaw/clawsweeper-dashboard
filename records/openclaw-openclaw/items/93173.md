## Summary

Keep open: current main and the latest release still use action-only Skill Workshop approval text with the generic 120s plugin approval default, and the remaining fix needs maintainer UX/security direction rather than cleanup closure.

## What This Changes

The issue asks for Skill Workshop apply approval prompts to include proposal metadata and for the approval timeout to be longer or configurable.

## Best Possible Solution

Define a bounded Skill Workshop approval-detail contract for proposal id, target, short description, safe preview, and inspect affordance, then choose one maintainer-approved approval-timeout policy.

## Reproduction Assessment

Yes, at source level: current main and the latest release still build Skill Workshop lifecycle approval from static action text with no proposal lookup and no timeout override. The July 3 Telegram comment adds real-world evidence that the generic 120s approval card still lacks enough context for async operators.

## Solution Assessment

Unclear as a final implementation: enriching proposal details in the Skill Workshop approval request is likely the right boundary, but the exact payload fields and fixed-default-versus-configurable timeout policy need maintainer UX/security direction.
