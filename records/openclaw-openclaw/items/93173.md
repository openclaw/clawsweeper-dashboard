## Summary

Keep open: current main still builds Skill Workshop lifecycle approvals from action-only text, does not carry proposal metadata or an inspect action, and falls back to the generic 120s plugin approval timeout; the remaining fix is security/product-sensitive rather than cleanup-closeable.

## What This Changes

The issue requests richer Skill Workshop apply approval details plus a longer or configurable approval timeout for proposal review.

## Best Possible Solution

Define a bounded Skill Workshop approval-detail contract for proposal id, target, short description, safe preview, and inspect action, then choose one coherent approval-timeout policy that preserves pending approval safety.

## Reproduction Assessment

Yes, at source level: current Skill Workshop lifecycle approval code emits only static title/description/severity and does not set timeoutMs. I did not run a live approval popup flow in this read-only review, but the July 3 Telegram comment gives fresh real-world confirmation of the visible behavior.

## Solution Assessment

Unclear as a final implementation: enriching the popup is likely the right direction, but the exact preview bounds, inspect action/deep-link model, redaction rules, and fixed-versus-configurable timeout policy need maintainer UX and security direction first.
