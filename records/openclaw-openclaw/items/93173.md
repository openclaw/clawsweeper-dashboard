## Summary

Keep open: current main and v2026.6.11 still use static Skill Workshop lifecycle approval text, no Skill Workshop approval timeout config exists, and the open related PRs only address timeout layers rather than the missing proposal details.

## What This Changes

The issue requests richer Skill Workshop apply approval details plus a longer or configurable approval timeout for reviewing generated skill proposals.

## Best Possible Solution

Define a bounded Skill Workshop approval-detail contract for proposal id, target skill, short description, safe preview, and inspect action, then choose one coherent approval-timeout policy across the core approval TTL and Codex watchdogs.

## Reproduction Assessment

Yes, at source level: current main emits only static title/description/severity for Skill Workshop lifecycle approvals and does not pass `timeoutMs` from the Skill Workshop policy. The July 3, 2026 comment adds a real Telegram operator example of the same missing context and fixed 120s expiry.

## Solution Assessment

Unclear as a final implementation: enriching the popup is likely the right direction, but preview fields, deep-link/action shape, channel exposure, and whether to add a config key need maintainer security and UX direction first.
