## Summary

Keep open: current main still uses a generic native Slack assistant-thread status and does not update `assistant.threads.setStatus` with the active tool name. The merged loading-message work improves the adjacent waiting indicator, but the requested per-tool native status remains a Slack UX/product decision.

## What This Changes

Request Slack assistant thread status to update dynamically with human-readable active-tool labels during agent execution.

## Best Possible Solution

Choose one Slack-owned progress/status UX: either map sanitized shared progress labels into `assistant.threads.setStatus` with dedupe and live Slack proof, or explicitly keep native status generic and rely on existing draft/reaction progress.

## Reproduction Assessment

Yes. Source inspection shows reply start sets `assistant.threads.setStatus` to `is typing...` with fixed loading messages, while `onToolStart` only updates reactions and draft progress.

## Solution Assessment

Unclear. Native per-tool status is plausible, but main already has fixed loading messages plus draft/reaction progress, so maintainers should choose the intended Slack UX before another implementation attempt.
