## Summary

Keep open: current main and v2026.6.11 still start Slack assistant thread status with a generic `is typing...` value and tool-start events only update reactions and draft/progress previews. The request remains valid, but it needs maintainer product direction because per-tool Slack-visible status overlaps Slack-safe visibility and configurable status/loading-message work.

## What This Changes

The issue requests Slack assistant thread status text that updates to human-readable tool labels during agent tool execution instead of staying on a generic typing status.

## Best Possible Solution

Keep this as the canonical automatic per-tool Slack assistant-status request, then implement Slack-owned safe/coarse labels after maintainers choose the visibility and status customization contract, with focused tests, docs, and redacted live Slack proof.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes, as a source-level feature gap: current main starts Slack assistant status with `is typing...` and clears it, while tool events only update reactions and draft/progress previews; no live Slack workspace was used in this read-only review.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainers choose the product contract; the Slack plugin is the right owner boundary, but a one-off tool-name status map should wait for the Slack-safe visibility and custom status/loading-message decisions.
