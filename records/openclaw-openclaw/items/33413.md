## Summary

Keep open: current main and v2026.6.11 still use a generic Slack assistant-thread status while tool-start events update reactions and draft/progress previews only. The requested native per-tool Slack status remains a valid feature, but it needs maintainer/product direction because it overlaps Slack-safe progress visibility, configurable loading messages, and fixed loading-message work.

## What This Changes

Request to show human-readable per-tool progress labels in Slack assistant thread status instead of the static `is typing...` text.

## Best Possible Solution

Choose one Slack-owned assistant status/progress contract, then implement safe per-tool native status labels with focused Slack tests, docs, and redacted live Slack proof.

## Reproduction Assessment

Yes as a source-level feature gap: current main and v2026.6.11 hardcode native Slack status to `is typing...`, while tool-start events only drive reactions and draft/progress previews. I did not run a live Slack workspace reproduction.

## Solution Assessment

Unclear: directly wiring `onToolStart` to `setSlackThreadStatus` is plausible, but not yet the best fix until maintainers choose the safe visibility, default, and config relationship with adjacent Slack status work.
