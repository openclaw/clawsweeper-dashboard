## Summary

Keep open: current main still uses a generic native Slack assistant-thread status at reply start and routes tool-start activity to preview/reaction progress, not per-tool native status text. The issue remains valid, but the next step is a maintainer product/disclosure decision because Slack already has rotating loading messages, draft-preview progress, and opt-in status reactions.

## What This Changes

The issue requests Slack assistant thread status text that changes per active tool during an agent run instead of staying on a generic typing status.

## Best Possible Solution

Choose one Slack-owned progress/status UX: either derive sanitized shared progress labels into native assistant status with dedupe, clear behavior, tests, and live Slack proof, or explicitly keep native status generic and rely on existing loading-message, draft-preview, reaction, and task-card surfaces.
