## Summary

Keep open: current main and v2026.6.11 still set Slack assistant-thread status to the generic `is typing...` text and clear it at the end, while tool-start events feed reactions and draft/progress previews rather than native per-tool `assistant.threads.setStatus` labels. The request remains valid, but it should stay in maintainer/product review because it overlaps Slack-safe progress visibility and Slack status/loading-message contract decisions.

## What This Changes

Request to update Slack assistant-thread status text dynamically per running tool instead of showing one generic processing status.

## Best Possible Solution

Keep this issue as the canonical tool-level Slack assistant-status request, then implement Slack-owned safe status labels only after maintainers choose the visibility, configurability, and proof requirements for Slack status text.

## Reproduction Assessment

Yes, at source level. Current main starts Slack assistant thread status with `is typing...` and clears it at the end, while `onToolStart` only updates reactions and progress previews; no live Slack workspace reproduction was run in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product contract. The Slack plugin is the right owner boundary, but a one-off tool-name-to-status map should not land before the Slack-safe visibility and custom status/loading-message decisions are reconciled.
