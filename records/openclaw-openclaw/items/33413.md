## Summary

Keep open: current main and v2026.6.11 still use a generic Slack assistant-thread status while tool-start events update reactions and draft/progress previews only. The request remains valid, but should stay in maintainer/product review because per-tool Slack-visible text overlaps the open Slack-safe progress visibility and custom status/loading-message decisions.

## What This Changes

Request to update Slack assistant thread status dynamically with per-tool progress labels instead of a static `is typing...` message.

## Best Possible Solution

Keep this issue as the canonical tool-level Slack assistant-status request, then implement Slack-owned safe status labels only after maintainers choose the Slack visibility and status customization contract, with docs, focused tests, and redacted live Slack proof.

## Reproduction Assessment

Yes, at source level. Current main starts Slack assistant thread status with `is typing...` and clears it at the end, while `onToolStart` only updates reactions and progress previews; no live Slack workspace reproduction was run in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product contract. The Slack plugin is the right owner boundary, but a one-off tool-name-to-status map should not land before the Slack-safe visibility and custom status/loading-message decisions are reconciled.
