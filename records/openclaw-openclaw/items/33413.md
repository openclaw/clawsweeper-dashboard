## Summary

Keep open: current main adds fixed Slack loading messages and already routes tool-start events into reactions and preview progress, but it still does not update `assistant.threads.setStatus` with the current tool name. The remaining blocker is Slack product/safety direction, not source uncertainty.

## What This Changes

Requests Slack assistant thread status text to show the currently running tool instead of a generic typing indicator.

## Best Possible Solution

Keep this as the canonical Slack assistant-thread per-tool status request until maintainers choose the Slack visibility/status contract, then implement Slack-owned status labels from the shared progress display model with deduped status writes, focused tests, docs, and live Slack proof.

## Reproduction Assessment

Yes. Source inspection shows Slack starts assistant-thread status with `is typing...` plus fixed loading messages, while `onToolStart` only updates reactions and draft/progress previews; no live Slack workspace reproduction was run in this read-only review.

## Solution Assessment

Unclear. The Slack plugin is the right owner boundary, but a one-off tool-name-to-status map should not land before maintainers reconcile Slack-safe visibility, fixed loading messages, and configurable status semantics.
