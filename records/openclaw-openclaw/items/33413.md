## Summary

Keep open: current main still does not update Slack `assistant.threads.setStatus` with the active tool name. The merged loading-message work in https://github.com/openclaw/openclaw/pull/85507 is useful adjacent progress UX, but it preserves the generic `is typing...` status while tool-start events update reactions and draft progress instead of the native assistant-thread status.

## What This Changes

Show active tool-level progress labels in Slack assistant thread status instead of a generic typing indicator.

## Best Possible Solution

Choose one Slack-owned progress/status UX: map sanitized shared progress labels into native assistant status with dedupe, clear behavior, docs, tests, and live Slack proof, or explicitly keep native status generic and rely on existing draft/reaction progress surfaces.

## Reproduction Assessment

Yes, as a source-reproducible feature gap: current main sets native Slack status to `is typing...` at reply start, while tool-start events only update reactions and draft progress.

## Solution Assessment

Unclear. Native per-tool status is plausible, but maintainers should first decide the intended Slack UX and safe-disclosure policy because current main already has fixed loading messages plus draft/reaction progress surfaces.
