## Summary

Keep open: current main and v2026.6.11 still only set a generic Slack assistant thread status, while tool callbacks feed reactions/previews rather than assistant-thread status text. Related open items are adjacent product constraints, not merged fixes for this request.

## What This Changes

Request Slack assistant thread status to show per-tool progress labels instead of one generic `is typing...` status during agent runs.

## Best Possible Solution

Keep this as the canonical Slack assistant-thread per-tool status request until maintainers choose the Slack visibility/status contract, then implement Slack-owned status labels from the shared progress display model with deduped status writes, focused tests, docs, and live Slack proof.

## Solution Assessment

Unclear until maintainers choose the product contract. The Slack plugin is the right owner boundary, but a one-off tool-name-to-status map should not land before the Slack-safe visibility and custom status/loading-message decisions are reconciled.
