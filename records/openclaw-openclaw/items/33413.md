## Summary

Keep open: current main still starts Slack native assistant-thread status with generic `is typing...` text and does not update `assistant.threads.setStatus` from active tool events. The request remains valid, but it needs maintainer product/disclosure direction because main now has overlapping Slack progress surfaces: fixed loading messages, preview progress, and status reactions.

## What This Changes

The issue requests Slack assistant thread status updates that reflect the active tool during agent execution instead of a static typing status.

## Best Possible Solution

Choose one Slack-owned progress/status UX: either derive sanitized shared progress labels into native `assistant.threads.setStatus` with dedupe, clear behavior, tests, and live Slack proof, or explicitly keep native status generic and rely on existing loading-message, draft-preview, and reaction progress surfaces.
