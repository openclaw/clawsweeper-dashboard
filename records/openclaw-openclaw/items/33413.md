## Summary

Keep open: current main and v2026.6.11 still use a static Slack assistant-thread status, while tool-start events only feed status reactions and preview/progress drafts. The request remains valid, but it needs maintainer product review because it overlaps open Slack status/loading-message and Slack-safe progress-visibility decisions.

## What This Changes

The issue requests Slack assistant thread status text to update per tool call instead of remaining a generic typing/status indicator.

## Best Possible Solution

Choose one Slack-owned progress/status model that coordinates native assistant status text, optional loading messages, status reactions, preview/progress drafts, and Slack-safe visibility; then implement it with focused Slack tests, docs, and redacted live Slack proof.

## Reproduction Assessment

Yes as a source-level feature gap, not as a strict bug repro. Current main and v2026.6.11 still set native Slack assistant status to `is typing...`, while tool-start events update other progress surfaces instead.

## Solution Assessment

Unclear as proposed: per-tool status wiring is plausible, but it is not clearly the best final fix until maintainers reconcile it with https://github.com/openclaw/openclaw/issues/67129, https://github.com/openclaw/openclaw/pull/85507, and https://github.com/openclaw/openclaw/issues/92085.
