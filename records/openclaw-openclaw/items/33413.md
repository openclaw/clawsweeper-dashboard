## Summary

Keep open: current main adds fixed Slack loading messages and already routes tool events to reactions/preview drafts, but it still does not update `assistant.threads.setStatus` with tool-specific text during each tool call. The remaining work is a Slack product/safety decision because per-tool native status could overlap configurable status work and Slack-safe progress visibility.

## What This Changes

Request to show tool-specific progress text in Slack assistant thread status during agent runs.

## Best Possible Solution

Keep this as the canonical Slack assistant-thread per-tool status request until maintainers choose the Slack status/visibility contract, then implement Slack-owned labels from the shared progress display model with deduped status writes, focused tests, docs, and live Slack proof.

## Reproduction Assessment

Yes, at source level. Current main starts Slack assistant thread status with `is typing...` and fixed `loading_messages`, then clears it at the end, while `onToolStart` updates reactions and preview progress instead of calling `assistant.threads.setStatus` per tool.

## Solution Assessment

Unclear until maintainers choose the product contract. The Slack plugin is the right owner boundary, but a one-off tool-name-to-status map should be reconciled with Slack-safe visibility and custom status/loading-message decisions first.
