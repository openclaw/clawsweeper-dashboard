## Summary

Keep open: current main and the latest release still keep Slack assistant-thread status at the generic start/clear text, while tool-start events update reactions and draft/progress previews only. The request is valid, but it should stay in maintainer/product review because per-tool native Slack status overlaps Slack-safe progress visibility and configurable status/loading-message decisions.

## What This Changes

The issue requests Slack assistant-thread status text that changes per tool during agent execution instead of staying at a generic typing status.

## Best Possible Solution

Keep this as the canonical per-tool Slack assistant-status request, then implement a Slack-owned safe status-label path after maintainers choose how it should interact with safe progress visibility and configurable loading/status text.

## Reproduction Assessment

Yes at source level. Current main starts Slack assistant thread status with `is typing...` and clears it later, while `onToolStart` only drives reactions and draft/progress previews.

## Solution Assessment

Unclear until maintainers choose the Slack product contract. The Slack plugin is the right owner boundary, but a one-off tool-name-to-status map should be reconciled with safe progress visibility and configurable status/loading messages first.
