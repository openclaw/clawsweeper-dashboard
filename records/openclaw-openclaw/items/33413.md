## Summary

Keep open: current main and v2026.6.11 still use a generic Slack assistant-thread status during a run, while tool-start events update reactions and draft/progress previews rather than native `assistant.threads.setStatus` text. The request remains valid but needs maintainer product/safety direction before another implementation attempt.

## What This Changes

Request Slack `assistant.threads.setStatus` to show human-readable current-tool progress during agent runs instead of only a generic typing status.

## Best Possible Solution

Keep this as the canonical tool-level Slack assistant-status request, then implement Slack-owned safe status wiring after maintainers choose the visibility and status customization contract.

## Reproduction Assessment

Yes, at source level. Current Slack dispatch sets native assistant thread status to `is typing...` on reply start and clears it at the end, while `onToolStart` only updates reactions and progress previews.

## Solution Assessment

Unclear until maintainers choose the product contract. The Slack plugin is the right owner boundary, but a direct one-off tool-label map should wait for the Slack-safe visibility and custom status/loading-message decisions.
