## Summary

Keep open: current main has improved Slack native status with fixed rotating loading messages, but it still does not update `assistant.threads.setStatus` from active tool events. The remaining work is a valid Slack UX request, but it needs maintainer product direction because native per-tool labels would overlap with loading messages, draft-preview progress, status reactions, native task cards, and the open Slack-safe visibility policy.

## What This Changes

Request Slack assistant-thread status text that reflects the currently running tool instead of only a generic typing/loading state.

## Best Possible Solution

Choose one Slack-owned progress/status UX: either derive sanitized shared progress labels into native `assistant.threads.setStatus` with dedupe, clear behavior, tests, and live Slack proof, or explicitly keep native status generic and rely on loading messages, draft previews, reactions, and task cards.
