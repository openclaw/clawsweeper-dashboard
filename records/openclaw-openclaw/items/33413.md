## Summary

Keep open: current main still starts Slack native assistant-thread status with generic text and fixed loading messages, while active tool events feed reactions and draft-preview progress rather than `assistant.threads.setStatus`. The request remains valid, but the remaining choice is Slack product/disclosure policy rather than a narrow cleanup close.

## What This Changes

Request Slack assistant-thread status text to update with human-readable per-tool progress during long agent runs.

## Best Possible Solution

Choose one Slack-owned progress/status UX: either derive sanitized shared progress labels into native `assistant.threads.setStatus` with dedupe, clear behavior, tests, and live Slack proof, or explicitly keep native status generic and rely on loading messages, draft previews, and reactions.
