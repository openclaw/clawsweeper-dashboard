## Summary

Keep open: current main and v2026.6.11 still keep Slack native assistant thread status on the generic start/clear path, while tool-start events update reactions and draft/native progress previews only. The source gap is clear, but the fix should stay in maintainer/product review because it overlaps Slack-safe progress visibility, custom loading messages, and status-reaction behavior.

## What This Changes

The issue asks for Slack native assistant thread status text to change per tool during agent runs instead of staying on a generic typing status.

## Best Possible Solution

Choose one Slack-owned progress/status policy, then implement native assistant status updates only as part of that coherent surface with focused dispatch tests, docs, and live Slack proof.

## Reproduction Assessment

Yes. Source inspection shows current Slack dispatch starts native status with `is typing...`, routes tool starts to reactions and progress previews, and never updates native assistant status per tool.

## Solution Assessment

Unclear. Direct `onToolStart` to `setSlackThreadStatus` wiring is plausible, but the best fix needs maintainer direction so native status, draft progress, loading messages, and reactions do not create competing Slack progress surfaces.
