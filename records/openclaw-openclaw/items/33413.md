## Summary

Keep open: current main now sends fixed Slack loading messages at reply start, but it still does not update Slack assistant thread status with the currently running tool. The merged loading-message work and open Slack-safe/configurable status items are adjacent, while closed implementation PRs for this exact request were not merged.

## What This Changes

The issue requests Slack assistant thread status text that reflects the currently running tool during agent execution.

## Best Possible Solution

Keep this as the canonical per-tool Slack assistant-status request; implement Slack-owned labels from the shared progress display model only after maintainers choose the visibility contract, dedupe status writes, update focused tests/docs, and gather live Slack proof.

## Reproduction Assessment

Yes, at source level. Current main starts Slack assistant thread status with `is typing...` plus fixed loading messages and clears it at the end, while `onToolStart` updates reactions/previews only and never writes a tool-specific assistant status.

## Solution Assessment

Unclear until maintainers choose the Slack status and visibility contract. The Slack plugin `onToolStart` seam and shared progress display model look like the right boundary, but a one-off tool-name map or unconditional detailed status updates would be the wrong shape.
