## Summary

Keep open: current main has fixed Slack `loading_messages` for the start of a reply, but it still does not update `assistant.threads.setStatus` from `onToolStart` with per-tool labels. The remaining work is a Slack product/visibility decision, not a cleanup close.

## What This Changes

Request Slack assistant thread status text to show human-readable tool-level progress during long agent runs instead of only a generic typing status.

## Best Possible Solution

Keep this as the canonical per-tool Slack assistant-thread status request, then implement it in the Slack plugin only after maintainers choose the safe visibility/status contract and reconcile it with configurable loading-message work.

## Reproduction Assessment

Yes, at source level. Current main starts Slack assistant thread status with `is typing...` plus fixed loading messages, while `onToolStart` only feeds reactions and preview drafts instead of per-tool assistant status text.

## Solution Assessment

No, not as a one-off tool-name map yet. The Slack plugin is the right owner boundary, but maintainers should first choose how assistant-thread status labels interact with Slack-safe visibility and configurable loading-message/status work.
