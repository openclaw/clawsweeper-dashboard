## Summary

Keep open: current main still does not update Slack native assistant-thread status with per-tool labels. It now sends fixed rotating loading messages and makes lifecycle status reactions opt-in, but tool-start events still feed preview/status-reaction surfaces rather than `assistant.threads.setStatus`, so this remains a Slack UX and disclosure-policy decision.

## What This Changes

Request Slack `assistant.threads.setStatus` to show human-readable per-tool progress during agent runs instead of only generic typing/loading text.

## Best Possible Solution

Choose the Slack native-status disclosure policy first, then either implement sanitized per-tool native status with focused tests and live Slack proof or explicitly keep native status generic while existing progress surfaces carry tool detail.
