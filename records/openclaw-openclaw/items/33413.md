## Summary

Keep open: current main sends generic Slack native loading messages at typing start and routes active tool events to draft previews/status reactions, but it still does not update native `assistant.threads.setStatus` with sanitized per-tool text. The remaining work needs a Slack product/safety decision before another fix PR.

## What This Changes

Request dynamic Slack `assistant.threads.setStatus` text that reflects the currently running agent tool instead of only generic typing/loading status.

## Best Possible Solution

Define the Slack disclosure policy first, then wire native assistant status from existing `onToolStart` events only with sanitized tool-family labels and focused Slack dispatch/docs tests.
