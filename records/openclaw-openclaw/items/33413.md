## Summary

Keep open: current main improves Slack native assistant-thread status with generic rotating loading messages, but it still does not update `assistant.threads.setStatus` from active tool events. The remaining request is a valid Slack UX feature, but it needs maintainer product direction because per-tool native status can duplicate existing progress surfaces and must align with Slack-safe visibility policy.

## What This Changes

Request to make Slack assistant thread status show the current tool or tool class during agent execution instead of only a generic typing/loading status.

## Best Possible Solution

Define a Slack-owned, safe per-tool native status policy that reuses existing tool lifecycle/progress signals, is gated by the approved Slack visibility/defaults decision, and has focused dispatch/context tests plus live Slack proof.
