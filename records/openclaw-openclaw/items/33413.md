The issue requests Slack assistant thread status updates that show which tool is running during agent execution.

## Best Possible Solution

Keep this as the canonical per-tool Slack assistant-thread status request, then implement Slack-owned status labels from an approved safe display policy with deduped status writes, focused tests, docs, and live Slack proof.

Yes, at source level. Current main starts Slack assistant thread status with `is typing...` plus generic loading messages and clears it at the end, while `onToolStart` only updates reactions and draft/progress previews.
