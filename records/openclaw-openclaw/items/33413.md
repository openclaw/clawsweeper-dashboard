## Summary

Keep open: current main still does not update Slack native assistant-thread status with the active tool. Slack now has fixed loading messages, but tool-start events feed status reactions and draft-preview progress rather than `assistant.threads.setStatus`, so this remains a Slack UX and disclosure-policy decision.

## What This Changes

The issue requests Slack assistant thread status text to update with a human-readable active-tool label during agent execution.

## Best Possible Solution

Choose the Slack native-status disclosure policy first, then either implement sanitized per-tool native status with focused tests and live Slack proof or explicitly keep native status generic while existing progress surfaces carry tool detail.
