## Summary

Keep open: current main partially improves Slack assistant status with fixed rotating loading messages, but it still does not update `assistant.threads.setStatus` with per-tool labels during tool execution. The remaining work overlaps Slack-safe visibility and custom status product decisions, so it should stay in maintainer review rather than be closed or queued automatically.

## What This Changes

The issue requests Slack assistant thread status text to change from a static typing status to human-readable tool-level progress during agent tool execution.

## Best Possible Solution

Keep this as the canonical per-tool Slack assistant-thread status request, then implement Slack-owned labels from a sanitized shared progress display model with deduped status writes, focused tests, docs, and live Slack proof after the visibility/status contract is chosen.

## Reproduction Assessment

Yes, at source level. Current main emits tool names through `onToolStart`, but Slack uses them for reactions and progress previews rather than per-tool `assistant.threads.setStatus` updates; no live Slack workspace reproduction was run in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product contract. The Slack plugin is the right owner boundary, but a one-off tool-name-to-status map should be reconciled with Slack-safe visibility and custom loading-message/status work first.
