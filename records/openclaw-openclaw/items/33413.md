## Summary

Keep open: current main still does not update Slack native assistant-thread status with the active tool. Slack now has generic native status plus fixed rotating loading messages, but tool-start events still feed status reactions and preview/native progress surfaces rather than `assistant.threads.setStatus`, so the remaining work is a Slack UX and disclosure policy decision.

## What This Changes

The issue requests dynamic Slack assistant-thread status text that reflects the currently running tool instead of a static processing message.

## Best Possible Solution

Choose the Slack native-status disclosure policy first, then either implement sanitized per-tool native status using shared progress display labels with deduped writes and live Slack proof, or explicitly keep native status generic while existing progress surfaces carry tool detail.
