## Summary

Keep open: current main still starts Slack native assistant-thread status with the generic status text and does not update `assistant.threads.setStatus` from active tool events. The issue remains a valid Slack UX request, but the remaining work needs maintainer product direction because current main already has fixed loading messages, draft-preview tool progress, and status reactions, while the Slack-safe visibility policy in a related issue may constrain any per-tool native status labels.

## What This Changes

The issue requests Slack assistant thread status text that changes to a human-readable label for the active tool during agent execution.

## Best Possible Solution

Choose one Slack-owned progress/status UX: either derive sanitized shared progress labels into native `assistant.threads.setStatus` with dedupe, clear behavior, tests, and live Slack proof, or explicitly keep native status generic and rely on the existing loading-message, draft-preview, and reaction progress surfaces.
