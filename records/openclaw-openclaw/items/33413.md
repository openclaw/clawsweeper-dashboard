## Summary

Keep open: current main now adds generic Slack `loading_messages` through https://github.com/openclaw/openclaw/pull/85507, but tool-start events still update status reactions and draft/progress previews rather than per-tool `assistant.threads.setStatus` text. The remaining decision is the Slack visibility/status contract, especially because per-tool labels can expose operational details in shared Slack threads and overlaps with the open Slack-safe progress policy work.

## What This Changes

Request Slack assistant thread status to show tool-level progress labels during agent execution instead of only a generic in-progress status.

## Best Possible Solution

Define the Slack-owned assistant-status contract first, then implement tool-derived labels from the shared progress display model with safe defaults, deduped status writes, focused Slack tests, docs, and live Slack proof.

## Reproduction Assessment

Yes, at source level. Current main emits tool-start callbacks but Slack maps them to reactions and progress drafts, while assistant thread status remains a generic `is typing...` plus generic loading messages.

## Solution Assessment

Unclear until maintainers choose the product contract. The Slack plugin is the right owner boundary, but a one-off tool-name map should wait for the safe visibility and custom status/loading-message decisions to be reconciled.
