## Summary

Keep open: current main still does not update Slack `assistant.threads.setStatus` with the active tool name. The merged loading-message work improves the generic status spinner, but it does not implement the requested per-tool assistant-thread status behavior, and the direct implementation PRs are closed unmerged.

## What This Changes

The issue requests Slack assistant thread status text that updates during an agent run to show the currently executing tool.

## Best Possible Solution

Implement Slack-owned tool-specific assistant status from the shared progress display model, dedupe unchanged Slack status writes, coordinate with the safe visibility and custom status issues, and require redacted live Slack proof of transitions and final clearing.

## Reproduction Assessment

Yes. Source inspection shows Slack starts and clears only generic assistant thread status, while `onToolStart` feeds reactions and preview progress instead of tool-specific `assistant.threads.setStatus` text.

## Solution Assessment

No, not as a simple Slack-local label map. The maintainable fix should reuse shared progress display metadata, dedupe unchanged status writes, and prove the visible Slack behavior in a real workspace.
