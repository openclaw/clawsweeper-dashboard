## Summary

Keep open: current main still does not update Slack `assistant.threads.setStatus` with active tool names. Main now has fixed loading messages plus draft/reaction tool progress, but the exact native assistant-thread status behavior remains a Slack UX/product decision.

## What This Changes

Requested behavior is for Slack assistant-thread status text to show active tool-level progress during agent execution instead of only a generic typing/loading indicator.

## Best Possible Solution

Choose one Slack-owned progress/status UX: either derive sanitized shared progress labels into `assistant.threads.setStatus` with dedupe, clear behavior, focused tests, and live Slack proof, or explicitly keep native status generic and rely on existing loading/draft/reaction progress.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: reply start sets native Slack status to `is typing...`, while tool-start events only update reactions and preview progress.

## Solution Assessment

Unclear. Native per-tool status is plausible, but current main already has loading messages and draft/reaction progress, so maintainers should choose the intended Slack UX surface before another implementation attempt.
