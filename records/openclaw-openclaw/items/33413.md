## Summary

Keep open: current main and v2026.6.11 still do not update Slack `assistant.threads.setStatus` from tool-start events. Related implementation PRs are closed unmerged, and the remaining open Slack status/progress items cover loading messages or safe visibility policy rather than replacing this per-tool status request.

## What This Changes

Show Slack assistant thread status text that reflects the currently running tool instead of only the generic typing status.

## Best Possible Solution

Implement Slack-owned assistant status updates from the shared progress display labels, skip unchanged status writes, preserve the existing final clear path, and align the visible labels with Slack-safe progress policy before landing.

## Reproduction Assessment

Yes, source-level. Current main sets Slack assistant status only to `is typing...` at typing start and clears it at stop, while `onToolStart` updates reactions and progress previews but not Slack assistant status; I did not run a live Slack workspace reproduction.

## Solution Assessment

Unclear as final product direction. The `onToolStart` seam is appropriate, but the durable fix should derive labels from shared progress display, dedupe status writes, and fit the Slack-safe visibility policy rather than adding a standalone label table.
