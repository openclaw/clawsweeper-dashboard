## Summary

Keep this PR open. The earlier owner-path finding is resolved and most safety wording is well-scoped, but the new `gog --no-input` prohibition conflicts with the CLI’s documented noninteractive contract and should be corrected before maintainers decide whether every resolved mutation requires a separate approval round trip.

Likely related people: `steipete` for the three bundled CLI skills and their upstream tools, `omarshahine` for the recent iMessage skill rewrite, and `vincentkoc` for the plugin-owned skill relocation.

## What This Changes

The PR changes five active skill guides so agents preview resolved recipients, order details, email or event content, and selected files before obtaining approval for side-effecting commands.

## Best Possible Solution

Preserve `gog --no-input` as the safe noninteractive execution mode after resolved-preview approval, warn against bypass flags such as `--force`, and then apply one owner-approved confirmation policy consistently across the five active skill paths.
