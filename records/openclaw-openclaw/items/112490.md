## Summary

This PR addresses the reported silent media-loss path with a focused shared resolver and passing CI, and it remains necessary because current `main` does not normalize canonical attachment aliases before gateway `message.action` dispatch. The patch appears correct from the reviewed source and tests, but it needs redacted after-fix Feishu behavior proof before merge because the PR changes real message delivery and deliberate fail-closed outcomes.

## What This Changes

The branch normalizes canonical media attachment aliases for gateway `message.action` sends, shares that resolution with the outbound runner, and makes Feishu reject unsupported, multi-media, or media-bearing thread-reply sends instead of falsely reporting success.

## System Context

Gateway `message.action` invokes a channel plugin directly, while the outbound runner first prepares send parameters and media references. This PR brings gateway send dispatch onto the same canonical-media interpretation so channel adapters receive usable media fields rather than silently falling back to text-only delivery.
