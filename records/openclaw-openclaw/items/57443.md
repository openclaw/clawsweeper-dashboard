## Summary

Keep open: current main still leaves BytePlus/Ark tool schemas without a `patternProperties` compatibility patch, and the same-repo fix attempts are closed unmerged while the open closing reference is only in a fork.

## What This Changes

The issue requests provider-compatible cleaning of unsupported tool JSON Schema keywords so BytePlus Ark/doubao tool calls do not fail on `patternProperties`.

## Best Possible Solution

Add provider-owned schema compatibility for BytePlus/Ark models that strips `patternProperties`, with focused regression tests and live Ark proof; use a global non-Anthropic scrubber only if maintainers explicitly choose that policy.

## Reproduction Assessment

Yes, source-level: BytePlus Ark models are OpenAI-compatible routes without model compat metadata, and the normalizer strips `patternProperties` only through Gemini cleaning or explicit unsupported-keyword metadata. I did not run a live BytePlus Ark request in this read-only review.

## Solution Assessment

No for the universal approach as stated; it is compatibility-sensitive and not clearly the best owner-boundary fix. The narrower maintainable path is provider-owned compatibility metadata for BytePlus/Ark unless maintainers approve a broader policy.
