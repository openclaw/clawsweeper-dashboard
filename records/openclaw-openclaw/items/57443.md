## Summary

Keep open: current main and the latest checked release still leave BytePlus/Ark tool schemas without `patternProperties` compatibility, while the same-repo fix attempts are closed and the remaining fork PR is conflicting against obsolete `pi-tools` paths.

## What This Changes

The issue asks OpenClaw to strip unsupported JSON Schema keywords such as `patternProperties` for BytePlus Ark and similar OpenAI-compatible providers so tool-bearing requests do not fail with HTTP 400.

## Best Possible Solution

Add provider-owned schema compatibility for BytePlus/BytePlus Plan Ark routes, and decide whether Volcengine Ark should share the same `patternProperties` patch, with focused regression tests and live Ark proof; use a global non-Anthropic scrubber only after explicit maintainer policy approval.

## Reproduction Assessment

Yes, source-level: BytePlus exposes Ark OpenAI-compatible routes without schema-compat metadata, while the active normalizer leaves `patternProperties` intact unless Gemini cleanup or explicit unsupported-keyword compat applies. I did not run a live BytePlus Ark request in this read-only review.

## Solution Assessment

No for the universal default proposed in the title; that is broader than the current provider-owned compatibility pattern and could alter unrelated providers. The narrower maintainable fix is BytePlus/Ark compat metadata or a shared provider-family helper if maintainers decide Ark providers share the contract.
