## Summary

Keep open: current main and the latest release still do not add BytePlus/Ark `patternProperties` compatibility, and same-repository fix attempts are closed unmerged while the broad universal-cleaning direction remains compatibility-sensitive.

## What This Changes

The issue requests schema normalization that prevents BytePlus Ark/OpenAI-compatible tool calls from failing when tool parameter schemas contain `patternProperties`.

## Best Possible Solution

Add provider-owned BytePlus/Ark tool-schema compatibility through the existing modelCompat/provider hook seam, with focused schema coverage and live Ark proof; broaden to a global scrubber only if maintainers explicitly choose that policy.

Rationale: Both approaches can fix the reported 400s, but the global scrubber changes model-facing schemas for many providers and is a compatibility policy decision rather than a mechanical bug fix.

Options:

- **Provider-Owned Ark Compat (recommended):** Add BytePlus/Ark-specific compat metadata or a normalizeResolvedModel hook that strips the proven unsupported keywords for those providers only, then require targeted tests and live Ark proof.
- **Global Non-Anthropic Scrubber:** Make schema keyword cleaning the default for non-Anthropic OpenAI-compatible providers, accepting the broader provider compatibility risk as intentional product policy.
- **Configurable Opt-In:** Expose or document a strict-schema compat flag/profile so BytePlus users can opt in without changing other providers by default.

## Reproduction Assessment

Yes, source-level: BytePlus registers Ark OpenAI-compatible providers without schema-compat metadata, while the normalizer leaves `patternProperties` intact unless Gemini cleanup or explicit unsupported-keyword compat applies. I did not run a live BytePlus Ark request in this read-only review.

## Solution Assessment

No, the requested universal scrubber is not clearly the best fix because it changes schemas for many providers. The narrower maintainable path is provider-owned BytePlus/Ark compatibility unless maintainers approve the broader policy.
