## Summary

Keep open: current main still leaves BytePlus/Ark tool schemas without a `patternProperties` compatibility path, and the same-repo fix attempts are closed unmerged while the remaining open fork PR is conflicting and targets obsolete `pi-tools` files.

## What This Changes

The issue asks OpenClaw to prevent BytePlus/Ark tool-bearing requests from sending `patternProperties` in tool parameter schemas, preferably through universal or configurable schema cleaning.

## Best Possible Solution

Add provider-owned BytePlus/Ark schema compatibility that strips `patternProperties` through the active model/tool-schema seam, with focused regression tests and a redacted live Ark tool-call proof; use universal cleaning only if maintainers explicitly choose that policy.

## Reproduction Assessment

Yes, source-level: BytePlus uses Ark OpenAI-compatible routes, the exec schema still includes a record-shaped `env`, and current normalization does not strip `patternProperties` for BytePlus by default. I did not run a live BytePlus Ark request.

## Solution Assessment

No, the requested universal cleanup is not yet proven to be the best fix because it changes all non-Anthropic provider schemas. The safer maintainable path is provider-owned BytePlus/Ark compatibility unless maintainers approve broader policy.
