## Summary

Keep open: current main and the latest release still leave BytePlus/Ark tool schemas without `patternProperties` compatibility, while the linked OpenClaw PRs are closed unmerged and the remaining open fork PR at https://github.com/BingqingLyu/openclaw/pull/1664 is stale, conflicting, and targets the old `pi-tools` surface.

## What This Changes

The issue asks for BytePlus/Ark OpenAI-compatible tool schemas to strip unsupported JSON Schema keywords, especially `patternProperties`, so tool-bearing requests do not fail with HTTP 400.

## Best Possible Solution

Add provider-owned schema compatibility for BytePlus and Volcengine Ark models that declares `patternProperties` unsupported, with focused regression tests and live Ark proof; only broaden to universal schema cleaning if maintainers explicitly choose that policy.

## Reproduction Assessment

Yes, source-level: `exec` still has a record-shaped `env` schema, BytePlus routes through Ark OpenAI-compatible endpoints without schema-compat metadata, and the active normalizer only strips Gemini or explicitly declared unsupported keywords. I did not run a live BytePlus request.

## Solution Assessment

No for the requested universal scrubber: it may be too broad for all non-Anthropic providers. The safer current-main fix is provider-owned BytePlus/Volcengine compat metadata unless maintainers approve a wider policy.
