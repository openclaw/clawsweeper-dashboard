## Summary

Keep open: current main and the latest release still route BytePlus Ark tool schemas through the non-Gemini path, so `patternProperties` from the exec tool can still reach the provider; the linked fix attempts are closed unmerged or live only as a conflicting fork PR.

## What This Changes

The issue asks OpenClaw to prevent BytePlus Ark/doubao tool calls from sending unsupported JSON Schema keywords such as `patternProperties`, preferably without provider-by-provider patches.

## Best Possible Solution

Add provider-owned BytePlus/Ark tool-schema compatibility with focused tests and live Ark proof; use a universal non-Anthropic scrubber only if maintainers explicitly choose that broader policy.

## Reproduction Assessment

Yes, source-level: BytePlus exposes Ark OpenAI-compatible routes without schema-compat metadata, the exec tool still has an `env` record schema, and the normalizer leaves `patternProperties` intact unless Gemini cleanup or explicit unsupported-keyword compat applies. I did not run a live BytePlus Ark API request in this read-only review.

## Solution Assessment

No, the requested universal cleaning is not proven to be the best fix because it changes schemas for all non-Anthropic providers. The narrower maintainable path is provider-owned BytePlus/Ark compatibility unless maintainers approve a broader schema-cleaning policy.
