## Summary

Keep open: current main and v2026.6.11 handle fresh or forced systemd installs better, and literal shell-reference env values are filtered, but update-mode Linux systemd repair still leaves live units unchanged, so a legacy or drifted unit missing the needed EnvironmentFile can survive an update-triggered restart.

## What This Changes

The issue requests reliable Linux systemd gateway restart behavior when `gateway.auth.token` is env-backed and the token lives in an OpenClaw env file.

## Best Possible Solution

Keep fail-closed SecretRef auth and generated env-file protections, then land a maintainer-approved Linux systemd update repair path that auto-updates only provably OpenClaw-generated units and gives safe suggested artifacts for legacy or modified units.
