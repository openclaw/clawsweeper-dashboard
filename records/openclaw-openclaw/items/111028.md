## Summary

Keep this PR open for a security-boundary correction and current-head proof. Its nonce approach addresses the reported VirtioFS release failure, but the shared re-entrancy map remains visible while an async lock callback is awaited, so unrelated synchronous reads can be treated as nested and bypass the fail-closed on-disk contention boundary; the competing hardened PR documents this exact async-boundary requirement but is not proof-positive enough to supersede this PR safely.

## What This Changes

The branch replaces the exec-approvals asynchronous shared file lock with a local nonce-owned lock shared with the synchronous path and adds lifecycle, interleaving, and re-entrancy tests.

## Best Possible Solution

Keep a single nonce-owned exec-approvals lock implementation, clear process-local re-entrancy visibility before awaiting a callback while retaining the on-disk sidecar, add regression coverage for that yield boundary, and obtain redacted current-head VirtioFS or equivalent live approval-flow proof before merge.
