## Summary

Keep this PR open: the new descriptor-bound `stat()` removes pathname replacement, but each helper still calls unbounded `FileHandle.readFile()` after the size snapshot, so another writer holding the same inode can extend it before or during the read and Doctor can still consume more than the 10 MiB cap. The prior P1 findings are therefore not fully resolved, and the PR body still supplies test-only rather than real Doctor-migration proof.

## What This Changes

The PR changes legacy Doctor migration reads in Reef, Active Memory, and Device Pair to open a file handle, validate it, read its JSON, and report oversized-file warnings.

## Best Possible Solution

Read no more than the validated byte limit from the opened descriptor, preserve the existing warning behavior in all three plugin contracts, add focused concurrent-growth regression coverage, and attach redacted real `openclaw doctor` evidence for a successful migration and an oversized-file warning.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source inspection: open a legacy regular file below 10 MiB, keep a writer descriptor for that inode, grow it after `FileHandle.stat()`, and the subsequent unbounded `FileHandle.readFile()` can consume beyond the checked size. A runtime reproduction was not supplied.

## Solution Assessment

No. Using one descriptor is necessary to avoid pathname substitution, but the proposed unbounded read does not enforce the stated maximum; a bounded descriptor-level read is the narrower complete fix.
