## Summary

Keep this PR open: it improves oversized-file reporting, but each helper still checks a pathname and then performs an unbounded second pathname read, so a replacement or growth between those operations can still bypass the intended Doctor OOM protection.

## What This Changes

The PR adds 10 MiB legacy-state checks and migration warnings to the Reef, Active Memory, and Device Pair plugin Doctor contracts.

## Best Possible Solution

Open each legacy source once, validate the opened handle, read it with an explicit bounded byte limit, add focused regression coverage for oversized and swapped/growing inputs, then attach redacted terminal proof of normal migration and oversized-file rejection.

Yes—source-reproducible. A process can replace or grow a checked legacy path after statSync and before fs.readFile resolves it again, leaving an unbounded allocation path.

## Solution Assessment

No. The current approach is a plausible first step, but it is not the best fix because validation is not bound to the bytes read; a single opened handle with an explicit bounded read is narrower and actually enforces the contract.
