## Summary

Keep this PR open: the current descriptor-bound reads remove pathname substitution, but each `FileHandle.readFile()` can still consume more than the validated 10 MiB if the already-open file grows after `file.stat()`. The previous P1 concern therefore remains at the rebased head, and the PR body supplies test output rather than inspectable after-fix Doctor behavior proof.

## What This Changes

The PR replaces three plugin Doctor legacy-state reads with descriptor-bound validation and adds warnings when oversized migration files are skipped.

## Best Possible Solution

Replace each unbounded descriptor `readFile` with a descriptor read into a buffer bounded by the validated maximum/initial size, add regression coverage for growth after validation, and publish redacted `openclaw doctor` output for valid and oversized legacy-state cases.
