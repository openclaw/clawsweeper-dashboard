## Summary

Keep this PR open: the latest descriptor-bound implementation removes the path-swap race but still performs an unbounded `FileHandle.readFile()` after a point-in-time size check, so the same legacy file can grow before or during the read. The prior blocker therefore remains unresolved, and the PR also still needs redacted real Doctor behavior proof rather than test-output claims alone.

## What This Changes

The PR changes legacy-state reads in the Reef, Active Memory, and Device Pair Doctor migration contracts to use file-handle stat/read operations and emit warnings for oversized files.

## Best Possible Solution

Replace each unrestricted descriptor `readFile()` with a bounded descriptor read that allocates and reads no more than the accepted maximum, preserves the existing parse/error behavior, adds focused growth-race coverage where feasible, and attach redacted real Doctor output for normal and oversized legacy state.

## Solution Assessment

No. Descriptor binding is necessary to avoid path replacement, but it is not sufficient for the stated memory bound; the read itself must be length-bounded on that descriptor.
