## Summary

This PR is still necessary, but it remains incorrect: descriptor binding prevents pathname substitution, not concurrent growth of the same file, so each helper can still read more than its 10 MiB limit. It also needs redacted after-fix Doctor migration output before merge.

## What This Changes

The branch changes legacy Doctor migration reads in Reef, Active Memory, and Device Pair to use file handles, checks for oversized regular files, and surfaces oversized-file warnings.

## Best Possible Solution

Use a reusable bounded read on each opened descriptor that reads at most the cap plus one byte, rejects overflow, preserves the existing warning behavior, and prove normal and oversized migrations through `openclaw doctor`.

## Solution Assessment

No. Using one descriptor removes pathname substitution, but a bounded descriptor read is required to enforce the advertised memory limit when the already-open file grows concurrently.
