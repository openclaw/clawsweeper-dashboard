## Label Justifications

- `P1`: Running doctor on an existing oversized persistent plugin-state file can cause user-visible session or channel state to stop being imported.
- `merge-risk: 🚨 compatibility`: The patch changes the upgrade behavior for pre-existing legacy state by replacing a retained source with an unrecognized archive path.
- `merge-risk: 🚨 session-state`: Active Memory session toggles and related plugin state can be removed from the active migration path without being written to canonical storage.

## Summary

The descriptor-bound readers address the read-bound race, but the final patch now renames oversized persistent legacy state to `.migrated` without importing it into canonical plugin state; this is a user-data migration regression and this PR should remain open for a maintainer-approved recovery path.

## What This Changes

The PR replaces path-based legacy-file reads in three plugin doctor migrations with descriptor-bound 10 MiB reads, adds oversized-file warnings/tests, and archives oversized sources during migration.

## Best Possible Solution

Keep oversized legacy sources recoverable until doctor can either migrate them with bounded parsing or present an explicit non-destructive recovery path; do not rename them to `.migrated` merely because the size cap rejected their contents.
