## Label Justifications

## Summary

The patch still leaves the 10 MiB cap bypassable: each helper validates a descriptor’s size, then calls unbounded `FileHandle.readFile()` on that descriptor. An append after `stat()` can therefore make Doctor read beyond the cap; the three prior blockers remain on the current head. The PR body also provides test output rather than inspectable after-fix `openclaw doctor` evidence.

## What This Changes

The PR changes Active Memory, Device Pair, and Reef Doctor migration readers to validate an opened legacy-state file and surface oversized-file warnings.

## Best Possible Solution

Replace each post-stat `FileHandle.readFile()` with a descriptor-bound, caller-sized read capped at 10 MiB, then show redacted terminal evidence for both a normal legacy migration and an oversized-file warning.

Yes from source: open a legacy file below 10 MiB, append data after `FileHandle.stat()` and before or during `FileHandle.readFile()`, and the current helpers have no consumption-time byte bound.

## Solution Assessment

No: descriptor ownership fixes pathname substitution, but `FileHandle.readFile()` does not enforce the checked size. A bounded read from that same handle is the narrow maintainable fix.
