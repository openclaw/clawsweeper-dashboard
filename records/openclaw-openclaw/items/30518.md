## Summary

Keep open: current main and the latest release still lack standalone Telegram `pin` and `unpin` message actions for existing messages; existing support only pins messages OpenClaw just sent, so this needs maintainer product/security direction before implementation.

## What This Changes

Request to expose Telegram `pin` and `unpin` as message-tool actions for agents managing pinned status/dashboard messages.

## Best Possible Solution

Add Telegram-plugin-owned `pin` and `unpin` actions with explicit target semantics, a maintainer-approved action gate/default, docs, focused tests, and live Telegram proof.

- **Request a design note first:** Ask for a short design covering admin-right expectations, per-account gating, implicit unpin behavior, forum-topic semantics, and live-proof requirements before implementation.

Yes. Source inspection on current main shows Telegram discovery and dispatch omit standalone `pin` and `unpin`, while the existing helpers are only wired through delivery pinning for newly sent messages.

## Solution Assessment

Unclear until maintainers choose the privileged action contract. The likely best fix is a Telegram-plugin-owned action surface with a dedicated gate and conservative explicit target semantics, not a core workaround or delivery-pin-only behavior.
