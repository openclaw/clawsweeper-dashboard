## Summary

Keep open: current main and v2026.6.11 still do not expose standalone Telegram `pin` or `unpin` message actions. The remaining work is real, but it needs maintainer product/security direction because it would let agents mutate persistent Telegram chat state through bot credentials.

## What This Changes

Expose Telegram message-tool `pin` and `unpin` actions so agents can programmatically manage pinned Telegram messages.

## Best Possible Solution

Add Telegram-plugin-owned `pin` and `unpin` message actions with explicit target semantics, a maintainer-approved action gate/default, docs, focused tests, and live Telegram proof.

Yes, at source level. Current Telegram discovery, dispatch, action aliases, docs, and tests omit standalone `pin` and `unpin`, while lower-level pin helpers and delivery-pin support exist.

## Solution Assessment

Unclear until maintainers choose the privileged action contract. The likely best fix is a Telegram-plugin-owned gated action surface, not a core workaround or delivery-pin-only behavior.
