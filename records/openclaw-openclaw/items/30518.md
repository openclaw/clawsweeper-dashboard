## Summary

Keep open: current main and v2026.6.11 still do not expose standalone Telegram `pin` or `unpin` message actions, even though lower-level Telegram pin helpers and delivery-pin support exist. The remaining work is real, but it needs maintainer product/security direction because it would let agents mutate persistent pinned chat state through bot credentials.

## What This Changes

Request to expose Telegram `pin` and `unpin` as message-tool actions so agents can manage pinned status messages programmatically.

## Best Possible Solution

Add Telegram-plugin-owned `pin` and `unpin` message actions with explicit message target semantics, a maintainer-approved action gate/default, docs, focused tests, and live Telegram proof; keep pinned-message reads tracked separately.
