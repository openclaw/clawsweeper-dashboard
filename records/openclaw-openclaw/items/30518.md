## Summary

Keep open: current main and v2026.6.11 still expose Telegram delivery pinning for newly sent messages but not standalone `pin` or `unpin` message-tool actions for existing Telegram messages. The remaining work is clear, but it needs maintainer product/security direction before implementation because it would let agents mutate persistent Telegram chat state through bot credentials.

## What This Changes

The issue requests standalone Telegram message-tool actions for pinning and unpinning existing messages.

## Best Possible Solution

Add Telegram-plugin-owned `pin` and `unpin` actions with explicit target semantics, a maintainer-approved action gate/default, docs, focused tests, and live Telegram proof.
