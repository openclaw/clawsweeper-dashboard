## Summary

Keep open: current main and v2026.6.11 still support Telegram delivery pinning but do not expose standalone Telegram message-tool `pin` or `unpin` actions. The remaining request is source-reproducible, but it should stay maintainer-owned because it adds privileged Telegram chat-state mutation and likely a new action gate.

## What This Changes

Request to expose Telegram `pin` and `unpin` as message-tool actions so agents can programmatically manage pinned Telegram status messages.

## Best Possible Solution

Add Telegram-plugin-owned `pin` and `unpin` message actions with explicit message target semantics, a maintainer-approved action gate, docs, focused tests, and live Telegram proof while keeping delivery pinning distinct.

## Reproduction Assessment

Yes. At source level, current Telegram discovery, action mapping, runtime aliases, contract tests, and docs omit standalone `pin` and `unpin`, while lower-level helpers and send-time delivery pinning exist.

## Solution Assessment

Unclear until maintainers choose the privileged action contract. The likely best fix is a Telegram-plugin-owned action surface with a dedicated gate and conservative explicit unpin semantics, not a core workaround or delivery-pin-only behavior.
