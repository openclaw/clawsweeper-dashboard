## Summary

Keep open: current main and v2026.6.11 still do not expose standalone Telegram `pin` or `unpin` message actions. The request is source-reproducible, but the next step needs maintainer product/security direction because this would expose privileged persistent chat-state mutation through Telegram bot credentials.

## What This Changes

The issue requests Telegram message-tool support for pinning and unpinning Telegram messages via Bot API actions.

## Best Possible Solution

Expose Telegram-plugin-owned `pin` and `unpin` message actions only after maintainers approve explicit target semantics and a conservative action gate; keep send-time `delivery.pin` as the existing supported path meanwhile.

Yes, at source level. Current Telegram discovery, message-action mapping, and runtime aliases omit standalone `pin` and `unpin`, while send-time delivery pinning and lower-level helpers already exist.

## Solution Assessment

Unclear until maintainers choose the privileged action contract. The maintainable path is a Telegram-plugin-owned action surface with explicit target handling and a conservative gate, not a core workaround or delivery-pin-only interpretation.
