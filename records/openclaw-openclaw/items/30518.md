## Summary

Keep open: current main and v2026.6.11 support delivery pinning for messages OpenClaw sends, but Telegram still does not advertise or dispatch standalone `pin` and `unpin` message actions. The remaining work needs maintainer product/security direction because it exposes persistent Telegram pinned-message mutation through bot credentials.

## What This Changes

Request to expose Telegram `pin` and `unpin` message-tool actions so agents can programmatically manage pinned Telegram chat messages.

## Best Possible Solution

Add Telegram-plugin-owned `pin` and `unpin` message actions only after maintainers approve the per-account gate, target/messageId semantics, docs, regression tests, and live Telegram proof.

- **Request design first:** Ask for a short design note covering admin-right expectations, per-account gating, implicit unpin behavior, and forum-topic semantics before implementation.

Yes, at source level. Current Telegram discovery, action mapping, and runtime aliases omit standalone `pin` and `unpin`, while lower-level helpers and delivery-pin support exist.

## Solution Assessment

Unclear until maintainers choose the privileged action contract. The likely best fix is a Telegram-plugin-owned action surface with a dedicated gate and conservative explicit unpin semantics, not a core workaround or delivery-pin-only behavior.
