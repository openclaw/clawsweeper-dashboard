## Summary

Keep open: current main and the latest release have Telegram Bot API pin helpers and delivery-pin support, but Telegram message-tool discovery and dispatch still omit standalone `pin` and `unpin` actions. The remaining request is real, but privileged Telegram chat-state mutation needs maintainer product/security direction before implementation.

## What This Changes

Request to expose Telegram `pin` and `unpin` as message-tool actions so agents can pin or unpin existing Telegram messages programmatically.

## Best Possible Solution

Add Telegram-plugin-owned `pin` and `unpin` message actions with explicit target semantics, a maintainer-approved action gate, docs, focused tests, and live Telegram proof.

## Reproduction Assessment

Yes. At source level, current Telegram discovery, action mapping, and runtime aliases omit standalone `pin` and `unpin`, while lower-level helpers and send-time delivery pinning exist.

## Solution Assessment

Unclear until maintainers choose the privileged action contract. The likely best fix is a Telegram-plugin-owned action surface with a dedicated gate and conservative explicit unpin semantics, not a core workaround or delivery-pin-only behavior.
