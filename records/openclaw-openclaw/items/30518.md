## Summary

Keep open: current main and the latest release still do not expose standalone Telegram `pin` or `unpin` message actions, even though Telegram now has lower-level pin helpers and delivery-pin support for newly sent messages. The remaining work is real, but it needs maintainer product/security direction before implementation because it would expose persistent Telegram chat-state mutation to agents.

## What This Changes

Expose Telegram message-tool `pin` and `unpin` actions so agents can programmatically manage pinned Telegram messages.

## Best Possible Solution

Add Telegram-plugin-owned `pin` and `unpin` message actions with explicit target semantics, a maintainer-approved action gate, docs, focused tests, and live Telegram proof.

## Solution Assessment

Unclear until maintainers choose the privileged action contract. The likely best fix is a Telegram-plugin-owned action surface with a dedicated gate and conservative explicit unpin semantics, not a core workaround or delivery-pin-only behavior.
