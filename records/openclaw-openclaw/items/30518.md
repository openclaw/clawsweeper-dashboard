## Summary

Keep open: current main and the latest release still do not expose standalone Telegram `pin` or `unpin` message actions. The gap is source-reproducible, but the next step needs maintainer product/security direction because this would let agents mutate persistent Telegram chat state through bot credentials.

## What This Changes

The issue requests Telegram message-tool actions that let agents pin and unpin Telegram messages through the Bot API.

## Best Possible Solution

Add Telegram-plugin-owned `pin` and `unpin` message actions with explicit target semantics, a maintainer-approved action gate, docs, focused tests, and live Telegram proof.

## Reproduction Assessment

Yes, at source level. Current Telegram discovery, action mapping, and runtime aliases omit standalone `pin` and `unpin`, while lower-level helpers and delivery-pin support exist.

## Solution Assessment

Unclear until maintainers choose the privileged action contract. The likely best fix is a Telegram-plugin-owned action surface with a dedicated gate and conservative explicit unpin semantics, not a core workaround or delivery-pin-only behavior.
