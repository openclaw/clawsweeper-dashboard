## Summary

Keep open: current main and the latest release still have Telegram delivery-pin support and lower-level Bot API helpers, but they do not expose standalone Telegram `pin`/`unpin` message actions through discovery or dispatch. The remaining request is real and bounded, but it needs maintainer product/security direction because it gives agents a persistent chat-state mutation capability.

## What This Changes

Expose Telegram Bot API `pinChatMessage` and `unpinChatMessage` as standalone OpenClaw message tool actions.

## Best Possible Solution

Add Telegram-plugin-owned `pin` and `unpin` message actions with an explicit action gate, conservative explicit-target semantics, docs, focused tests, and live Telegram proof after maintainer product/security approval.

## Reproduction Assessment

Yes, at source level: current Telegram discovery, message-action mapping, and runtime aliases omit standalone `pin` and `unpin`, while lower-level helpers and send-time delivery pinning exist.

## Solution Assessment

Unclear until maintainers choose the privileged action contract. The likely best fix is a Telegram-plugin-owned action surface with a dedicated gate and conservative explicit unpin semantics, not a core workaround or delivery-pin-only behavior.
