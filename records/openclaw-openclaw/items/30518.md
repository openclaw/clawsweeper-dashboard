## Summary

Keep open: current main and v2026.6.11 have lower-level Telegram pin/unpin helpers and delivery-time pinning, but the Telegram message-tool discovery, dispatch map, and runtime aliases still do not expose standalone `pin` or `unpin` actions for existing messages. The remaining work is clear but needs maintainer product/security direction before implementation because it would give agents persistent Telegram chat-state mutation power through bot credentials.

## What This Changes

The issue requests Telegram message-tool actions that let agents pin and unpin existing Telegram messages through the Bot API.

## Best Possible Solution

Add Telegram-plugin-owned `pin` and `unpin` actions with explicit target semantics, a maintainer-approved action gate/default, focused tests, docs, and live Telegram proof.
