## Summary

Keep open: current main and the latest release still expose Telegram pinning only as lower-level helpers and delivery-pin behavior, not as standalone Telegram `pin`/`unpin` message actions. The requested capability is real, but privileged Telegram chat-state mutation needs maintainer product/security direction before implementation.

## What This Changes

Request to expose Telegram Bot API pinChatMessage and unpinChatMessage as Telegram message-tool `pin` and `unpin` actions.

## Best Possible Solution

Add Telegram-plugin-owned `pin` and `unpin` message actions only after maintainer product/security approval, reusing the existing Bot API helpers with explicit gating, conservative unpin semantics, docs, focused tests, and live Telegram proof.

## Reproduction Assessment

Yes, at source level: Telegram action discovery and dispatch omit `pin` and `unpin`, while only lower-level Bot API helpers and delivery-pin support exist on current main and v2026.6.11. I did not run a live Telegram probe because there is no standalone action surface to exercise yet.

## Solution Assessment

Unclear until maintainers choose the privileged action contract. The likely best fix is a Telegram-plugin-owned action surface with an explicit gate and conservative unpin semantics, not a core workaround or delivery-pin-only behavior.
