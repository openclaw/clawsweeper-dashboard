## Summary

Keep open: current main has Telegram delivery-pin support for messages OpenClaw just sent, but it still does not advertise or dispatch standalone Telegram `pin`/`unpin` message actions for existing messages. The gap is source-reproducible, and the remaining blocker is maintainer product/security direction for a privileged chat-state mutation surface.

## What This Changes

The issue requests standalone Telegram message-tool actions to pin and unpin existing messages.

## Best Possible Solution

Implement this in the Telegram plugin only after maintainer approval, with explicit `pin`/`unpin` target semantics, a dedicated action gate, docs, focused tests, and live Telegram proof.

Rationale: The code gap is clear, but exposing these actions grants persistent Telegram pinned-message mutation through configured bot credentials, and the current config has no pin-specific policy gate or approved implicit-unpin contract.

- **Request design first:** Ask for a short design covering admin-right expectations, per-account gating, implicit unpin behavior, and forum-topic semantics before implementation.

## Solution Assessment

Unclear until maintainers choose the privileged action contract. The likely best fix is a Telegram-plugin-owned action surface with a dedicated gate and conservative explicit unpin semantics, not a core workaround or delivery-pin-only behavior.
