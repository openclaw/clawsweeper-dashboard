## Summary

Keep open: current main now covers command-triggered mechanical session-memory capture and bare-reset startup loading, and the linked world-model MCP shows that some workflows can live outside core. The requested structured synthesis, durable-fact filtering, transcript anchoring, and security/product policy for automatic reset/startup memory remain unresolved.

## What This Changes

The issue requests automatic session handoff that preserves prior session state, links full transcripts, synthesizes durable memory, and hydrates the next session after `/new`.

## Best Possible Solution

Define a maintainer-approved memory-continuity contract that keeps core lean: use plugin/MCP memory where sufficient, and only add explicit opt-in core reset/startup synthesis or lifecycle APIs with redaction, retention, dedupe, audit, and focused tests.
