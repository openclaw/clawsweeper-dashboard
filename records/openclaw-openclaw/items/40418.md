## Summary

Keep open: current main has partial reset continuity through sanitized recent-message capture, startup loading of recent memory files, plugin reset hooks, and pre-compaction agentic memory flushes, but the requested reset-time synthesis, dedupe, anchored transcript package, and privacy-safe lifecycle policy are still unsettled.

## What This Changes

The issue requests automatic preservation, export, and synthesis of session memory when `/new` resets a session.

## Best Possible Solution

Define a maintainer-approved reset/session memory lifecycle contract that preserves a small, sanitized continuation package with provenance, retention, redaction, and transcript-link rules, preferably through the memory plugin boundary unless core needs a missing generic seam.

## Reproduction Assessment

Yes, at source level: current main captures sanitized recent messages on `/new` and `/reset`, loads bounded memory notes at startup, and runs agentic memory flush only from the reply/compaction path. The requested synthesized reset handoff with dedupe and transcript anchors is not present.

## Solution Assessment

Unclear: the broad goal is valid, but the exact proposal to auto-save state and transcript files on reset is not clearly the safest product shape. A memory-plugin or reset-lifecycle contract with explicit privacy and retention controls is safer than adding another default core persistence path.
