## Summary

Keep open: current main and v2026.6.11 provide partial reset continuity through command-scoped session-memory files, startup memory loading, plugin reset hooks, and post-turn memory flushes, but reset-time synthesis, dedupe, transcript anchors, privacy defaults, and lifecycle ownership remain unresolved. External projects like world-model-mcp and Agent Capsule are useful proof that plugin/external paths can cover parts of the need, but they do not settle the missing OpenClaw lifecycle/API decision.

## What This Changes

Request to automatically preserve, synthesize, and rehydrate session memory across `/new` resets, with links back to full transcript context.

## Best Possible Solution

Define a maintainer-approved reset/session memory lifecycle contract that preserves a small sanitized continuation package with provenance, retention, redaction, and transcript-link rules, preferably through the memory plugin boundary unless core needs a missing generic seam.

## Maintainer Decision

Question: Should reset-time memory preservation and synthesis be owned as bundled OpenClaw behavior, exposed as a memory-plugin lifecycle contract, or deferred to external ClawHub/MCP packages?

Rationale: The source shows partial hooks and memory loading already exist, but choosing automatic provider-backed synthesis and durable transcript-derived storage changes privacy, retention, config, and plugin API policy beyond a safe autonomous fix.

Owner confidence: high

Options:

- **Define a memory-plugin lifecycle contract (recommended):** Expose or refine the reset/session-end contract so a memory plugin can do bounded, sanitized synthesis while core owns only the generic lifecycle and safety rules.
- **Bundle reset synthesis in core:** Add a first-party reset-time synthesis path, but accept that core must own provider execution, retention, redaction, config, and upgrade behavior.
- **Defer to ClawHub/MCP packages:** Keep core unchanged and point users to packages such as world-model-mcp or Agent Capsule, leaving any missing OpenClaw seam to be filed separately.

## Reproduction Assessment

Yes, at source level. Current main captures sanitized recent messages on `/new` and `/reset`, loads bounded memory notes at startup, and runs agentic memory flush only from the reply/compaction path; the requested synthesized reset handoff with dedupe and transcript anchors is not present.

## Solution Assessment

Unclear as proposed. The broad goal is valid, but auto-saving state/transcript files on reset is not clearly the safest product shape; a memory-plugin lifecycle contract with explicit privacy and retention controls is safer than adding another default core persistence path.
