## Summary

Keep open: current main partially covers reset continuity with sanitized recent-message capture, startup loading of daily and slugged memory notes, and compaction-triggered agentic flushes, but it still does not implement the requested reset-time synthesis, dedupe, anchored transcript package, or maintainer-approved lifecycle policy. Recent comments point to Agent Capsule and world-model-mcp as useful adjacent/plugin-style approaches, but they do not settle the OpenClaw reset lifecycle and security defaults.

## What This Changes

Request automatic session memory preservation and synthesis around `/new` resets, including session-state capture, full transcript export, daily summaries, and links back to source conversations.

## Best Possible Solution

Define a maintainer-approved reset/session memory lifecycle contract that either extends plugin hooks or the existing memory-flush path with explicit privacy, latency, retention, and startup hydration bounds.

## Reproduction Assessment

Yes at source level: current main captures sanitized recent messages on `/new` and `/reset`, loads bounded memory notes at startup, and runs agentic flushes only on the reply/compaction path, leaving the requested synthesized reset handoff absent.

## Solution Assessment

Unclear: reset-time agentic flush is plausible and tracked more narrowly by #45608, while a plugin/ClawHub path may be better for synthesis, anchors, retention policy, and external memory stores.
