## Summary

Keep open: current main only partially covers reset continuity with sanitized `/new`/`/reset` capture, startup memory loading, and compaction-gated agentic flushes; it still lacks the requested reset-time synthesis, dedupe, anchored transcript package, and lifecycle policy.

## What This Changes

Request automatic session preservation across `/new` resets by saving prior session state, exporting transcripts, synthesizing durable summaries, and linking summaries back to full conversation records.

## Best Possible Solution

Define a maintainer-approved reset/session memory lifecycle contract with explicit privacy, latency, retention, startup hydration, and plugin/API boundaries.

## Reproduction Assessment

Yes at source level: current main captures sanitized recent messages on `/new` and `/reset`, loads bounded memory notes at startup, and runs agentic flushes only in the reply/compaction path.

## Solution Assessment

Unclear: reset-time agentic flush is plausible and tracked more narrowly by #45608, while synthesis, anchors, retention policy, and external memory stores may belong behind plugin or ClawHub contracts.
