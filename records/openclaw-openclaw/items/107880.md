## Summary

Keep this PR open for revision: the user problem is concrete, but the patch promotes an undocumented foreign key into the steady-state config schema, preserves it in several conflict cases, and lacks after-fix runtime proof. OpenClaw currently documents `enabled: false` as canonical and routes compatibility repair through Doctor, so maintainers should confirm the desired public contract before merge.

## What This Changes

The PR adds `disabled` to the MCP server schema, maps `disabled: true` to `enabled: false` when `enabled` is absent, and adds focused normalization tests.

## Best Possible Solution

Keep `enabled` as the sole runtime and documented field; if real shipped or imported configs contain `disabled`, add a narrow `openclaw doctor --fix` migration that resolves precedence, writes `enabled`, removes `disabled`, and validates fresh and upgraded configurations.
