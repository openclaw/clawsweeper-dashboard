## Summary

Keep open: current main and the latest release still omit the configured context length on LM Studio embedding preload, and this PR is the active candidate fix for that shipped bug. The code path looks correct with focused regression coverage, but the newly added proof still only shows local resolution output rather than live LM Studio/OpenClaw diagnostics for the actual load request.

## What This Changes

The PR makes the LM Studio embedding provider resolve existing model/provider contextTokens and contextWindow settings and pass the result as requestedContextLength to the LM Studio model-load helper, with new pass-through tests.

## Best Possible Solution

Land the provider-local fix after redacted live LM Studio/OpenClaw diagnostics show the configured context_length reaching /api/v1/models/load, or after a maintainer explicitly accepts that proof gap.

## Reproduction Assessment

Yes. Source-level reproduction is high confidence: current main and v2026.6.11 call the LM Studio embedding load helper without requestedContextLength while the helper defaults upward before sending context_length; I did not reproduce the CUDA OOM live.

## Solution Assessment

Yes for the code shape. Resolving existing LM Studio context config in the provider-owned embedding preload path and passing it to the existing load helper is the narrow maintainable fix; the remaining blocker is live request proof.
