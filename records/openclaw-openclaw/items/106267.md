## Summary

The provider architecture fits the existing Talk gateway-relay seam and has strong live proof, but the existing Codex review blocker remains supported: the xAI bridge queues playback marks even when no mark callback exists, which can prevent later responses from starting on valid `ignore` or callback-less runtimes. The protected `maintainer` label also requires explicit maintainer handling rather than cleanup closure.

Likely related people: @steipete (high confidence, current Talk/xAI replacement and cross-client integration owner) and @TheAngryPit (medium confidence, original xAI realtime implementation and live-proof contributor).

## What This Changes

Adds a bundled xAI realtime voice provider for Talk gateway-relay, including provider WebSocket handling, named playback acknowledgements across web/iOS/Android, gateway protocol changes, documentation, tests, and a runtime `ws` dependency.

## Best Possible Solution

Keep the plugin-owned xAI bridge and additive gateway-relay design, but make mark generation self-draining when no transport callback is installed, add a focused `markStrategy: "ignore"` regression, and confirm mixed-version clients cannot wedge existing realtime sessions before merge.
