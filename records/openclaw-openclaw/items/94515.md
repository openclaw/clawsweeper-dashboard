Keep open: the patch is a focused mitigation for idle/no-work Codex PreToolUse relay subprocesses, but it changes default generated hook behavior and does not prove the linked P1 loop-detection/concurrency fan-out issue is fully resolved.

## What This Changes

## Best Possible Solution

Land this only as a scoped idle-relay mitigation after maintainer sign-off on the default change, and keep or split tracking for issue 91009 before treating that P1 as fully fixed.

## Solution Assessment

Acceptable as a bounded mitigation for idle no-work PreToolUse relays, but unclear as the complete best fix for issue 91009 because explicit loopDetection, concurrency caps, and lightweight relay design remain maintainer decision points.
