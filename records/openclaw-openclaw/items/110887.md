- `impact:ux-friction`: Users see an unsupported-response error in a normal status surface despite a successful provider response, creating avoidable operational confusion.

## Summary

Current `main` still rejects the reported MiniMax payload: the selector requires a nonzero count and the parser does not recognize the current remaining-percent fields. This is a bounded provider-usage bug, while the portal endpoint path should be traced through the MiniMax provider owner rather than hard-coded in the shared fetcher.

## What This Changes

Add support for MiniMax `model_remains` records that expose interval or weekly remaining percentages without nonzero count totals, and ensure usage polling follows the configured portal endpoint.

## Best Possible Solution

Keep the shared MiniMax fetcher additive: select a chat/general record with recognized remaining-percent fields, derive used percent from those fields, add the reported payload as a regression fixture, and have the MiniMax provider registration pass its configured base URL without adding a new user setting.
