## Summary

Current main still exposes the unanchored cron-tool regex rejected by llama.cpp, so this released provider regression remains necessary to track. The narrower root-cause issue should be canonical, and the two open candidate PRs need consolidation; likely related people are vincentkoc, Takhoffman, and steipete based on merged cron-tool and provider-adjacent history.

## What This Changes

Fix OpenClaw tool schemas so llama.cpp-compatible providers do not reject cron tool definitions containing unsupported unanchored regex patterns.

## Best Possible Solution

Use https://github.com/openclaw/openclaw/issues/107449 as the canonical tracker, replace the offending constraint with a llama.cpp-compatible expression that preserves the intended non-whitespace semantics, add generated-schema regression coverage, and require a redacted live llama.cpp request showing tools succeed before landing.
