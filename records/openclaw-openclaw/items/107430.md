## Summary

Current main still contains the exact cron-tool schema pattern rejected by llama.cpp, so this is a valid released regression. Keep this issue open while the linked implementation PRs are resolved; the narrower related issue is the best canonical root-cause report.

## What This Changes

Fix a regression where llama.cpp rejects OpenClaw requests containing the cron tool's unanchored `\S` JSON Schema pattern.

## Best Possible Solution

Remove the redundant `declarationKey` pattern at the cron schema owner, retain the existing runtime nonblank validation, add a focused generated-schema regression test, and verify a real cron-enabled request against current llama.cpp before merging.
