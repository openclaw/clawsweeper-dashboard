## Summary

Keep open: current main still rebuilds dirty session transcript entries from the whole JSONL file and clears that file's existing session chunks before reinserting regenerated chunks. The open related PR is conflicting and still needs maintainer design/proof work, so this issue remains the canonical tracker.

## What This Changes

The issue asks memory-core to avoid rebuilding and re-embedding entire growing session JSONL transcripts during session memory sync.

## Best Possible Solution

Keep this as the canonical tracker and choose a current-schema incremental session indexing design that preserves source-wide batching, chunk overlap, compaction/reset behavior, and upgrade-safe SQLite state.
