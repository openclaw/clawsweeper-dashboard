## Summary

Keep open: current main and latest release v2026.6.11 still rebuild dirty session transcript entries as whole files and clear existing session chunks before reinserting regenerated chunks. The open related implementation at https://github.com/openclaw/openclaw/pull/75179 targets the same problem, but it is conflicting and still marked needs-proof, so this issue remains the canonical tracker.

## What This Changes

The issue requests incremental session transcript memory indexing so growing JSONL sessions avoid full delete/reinsert and re-embedding on each dirty sync.

## Best Possible Solution

Land a fresh bounded memory-core implementation that preserves the current memory_index_* schema, source-wide batching, overlap and compaction behavior, and includes regression plus performance proof for appended session transcripts.
