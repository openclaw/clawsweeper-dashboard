## Summary

Keep open: current main and v2026.6.11 still build full dirty session transcript entries and clear indexed chunks before rewriting them. Existing embedding-cache behavior reduces some re-embedding cost, but the full-entry parse/delete/reinsert pattern remains and the open candidate PR is conflicting and design/proof blocked.

## What This Changes

The issue asks memory-core session transcript indexing to avoid full delete-and-reinsert/full-entry reindexing of growing JSONL session files.

## Best Possible Solution

Keep this issue canonical and land a current memory-core fix that preserves unchanged session chunks across direct and source-wide indexing paths, while proving overlap, compaction, embedding-cache, schema-upgrade, and real-behavior behavior.
