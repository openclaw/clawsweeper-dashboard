## Summary

Keep open: current main and v2026.6.11 still rebuild full session transcript entries for dirty JSONL files and clear existing indexed chunks before reinserting them. The open related PR is still the active candidate, but it is conflicting and needs maintainer design/proof work.

## What This Changes

The issue requests incremental session-memory indexing so growing JSONL transcripts do not force full delete-and-reinsert reindexing on each dirty sync.

## Best Possible Solution

Keep this issue as the canonical tracker until a current memory-core fix preserves unchanged session chunks across direct and source-wide indexing paths with overlap, compaction, schema-upgrade, and real-behavior proof.
