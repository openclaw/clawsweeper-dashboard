- `impact:session-state`: The affected behavior indexes session transcript state for memory recall and can make session-memory maintenance stale or expensive.

## Summary

Keep open: current main and the latest release still rebuild dirty session JSONL files as full session entries and clear existing indexed chunks before reinserting regenerated chunks. Embedding cache and source-wide batching mitigate some provider-call cost, but they do not solve the central full-transcript rebuild/delete-reinsert behavior, and the open candidate PR is still conflicting and proof/design blocked.

## What This Changes

The issue requests incremental session-memory sync so growing session JSONL transcripts do not repeatedly delete and re-index unchanged chunks.

## Best Possible Solution

Keep this issue as the canonical tracker and land a current memory-core fix that preserves unchanged session chunks while proving overlap, compaction, force/full reindex, source-wide batching, and schema-upgrade behavior.
