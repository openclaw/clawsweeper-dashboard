## Summary

Keep this issue open for a focused reproduction and maintainer direction. Current OpenClaw routes native Codex activity through the bundled Codex app-server projector, not the three files named in the report, and Codex completion items carry correlation identifiers; the available evidence does not show results being assigned to the wrong child. Buffering by invocation order would also introduce head-of-line blocking and change completion semantics, so it should not be implemented as a presumed bug fix.

## What This Changes

Investigate whether concurrently completed subagent calls are represented incorrectly in the parent context and, if necessary, make their correlation or ordering deterministic.

## Best Possible Solution

Capture a current-main native Codex run with two deliberately inverted-latency children and inspect the correlated app-server items and model-visible transcript; if identifiers are lost or mis-associated, fix that projection in the bundled Codex plugin without globally delaying correctly correlated completions.
