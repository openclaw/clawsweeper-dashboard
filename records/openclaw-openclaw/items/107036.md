## Summary

Current evidence does not establish a bug: OpenClaw documents subagent completion as push-based events, while tracked runs use explicit identities rather than relying only on transcript position. Keep this open for a maintainer decision on completion-order semantics and a current-main trace demonstrating whether any result is actually associated with the wrong child.

## What This Changes

Request deterministic spawn-order buffering for concurrent subagent completion results before they enter the requester agent’s context.

## Best Possible Solution

Keep immediate identity-bearing completion events as the default unless a live trace proves mis-correlation; if spawn-order synthesis is desired, define an explicit requester-side batch aggregation contract that preserves run identities and does not delay unrelated completed work.
