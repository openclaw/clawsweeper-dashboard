## Summary

Keep open for a narrow product decision, not as a confirmed bug: current behavior intentionally delivers child completions as non-blocking parent-session events, while the report provides no transcript showing a result associated with the wrong child. Spawn-order buffering would create new waiting and failure semantics rather than restore an established contract.

## What This Changes

Determine whether concurrent subagent results should be buffered and delivered in spawn order instead of completion order.

## Best Possible Solution

Preserve push-based completion as the default; if ordered aggregation is desired, add an explicit opt-in join or yield operation keyed by returned child run IDs that produces caller-specified ordering without delaying unrelated completion events.
