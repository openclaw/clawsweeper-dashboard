## Summary

Keep open for a narrow product decision, not as a confirmed bug: current main intentionally delivers identity-bearing child completions as push-based parent-session events, and the report provides no transcript or test showing a result associated with the wrong child. Spawn-order buffering would introduce different waiting and failure semantics rather than restore an established contract.

## What This Changes

Request deterministic spawn-order aggregation of concurrently completing subagent results before they enter the parent agent context.

## Best Possible Solution

Preserve completion-order push as the default; if maintainers want ordered aggregation, add an explicit bounded spawn-group or join primitive that returns identity-bearing results in requested order with defined timeout, cancellation, partial-failure, and nested-child semantics.
