## Summary

Keep open for a narrow product decision rather than as a confirmed bug. Current OpenClaw deliberately treats concurrent subagents as independent, non-blocking runs whose identified completion events become visible when each child finishes; the report supplies no transcript showing a result attached to the wrong child, and globally buffering by spawn order would introduce new latency and failure-blocking semantics.

## What This Changes

Request deterministic spawn-order insertion of concurrent subagent results into the parent agent context.

## Best Possible Solution

Keep identified completion-order events as the default; if users need ordered fan-in, add an explicit requester-owned batch/barrier aggregation primitive with timeout and partial-failure semantics rather than globally reordering the parent transcript.
