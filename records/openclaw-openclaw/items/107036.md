## Summary

Current evidence does not establish broken behavior: OpenClaw intentionally delivers identity-bearing subagent results as push-based completion events, and no transcript or test shows a result being associated with the wrong child. Keep this open for a maintainer decision on whether an additional ordered batch/join mode is desirable.

## What This Changes

Request deterministic launch-order buffering of concurrent subagent completion events before they reach the parent agent.

## Best Possible Solution

Keep identity-bearing events in actual completion order unless maintainers choose an explicit batch/join primitive with defined timeout, cancellation, persistence, and partial-result behavior.
