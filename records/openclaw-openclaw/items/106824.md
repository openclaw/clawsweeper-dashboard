## Summary

Keep this issue open: it describes a concrete regression where the retry classifier no longer recognizes the repository’s own provider-wrapped transient 5xx format, and no merged fix or current-main implementation evidence was provided. The behavior appears to follow directly from the stricter status parsing introduced by https://github.com/openclaw/openclaw/pull/105258.

## What This Changes

Restore session auto-retry for transient 500, 502, 503, and 504 errors emitted in built-in provider wrapper formats.

## Best Possible Solution

Preserve the strict no-arbitrary-substring invariant while recognizing an anchored built-in provider error status—or carrying structured HTTP status metadata—and add shared regression coverage for all three wrapper-producing adapters and permanent-status counterexamples.
