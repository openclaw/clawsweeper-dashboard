## Summary

Keep open. The report identifies a distinct, deterministic accounting defect: after critical loop blocking begins, veto records do not contribute outcomes, so the later global no-progress threshold cannot advance. The related issues and PRs address termination, volatile exec hashes, or cross-tool scope rather than this exact gap.

## What This Changes

Fix tool-loop veto accounting so repeated blocked calls continue no-progress detection and allow the configured global circuit breaker to trigger.

## Best Possible Solution

Represent a tool-loop veto as an explicit no-progress outcome, keep unrelated veto classes distinct, and add threshold-boundary tests proving the global breaker becomes reachable without adding configuration or changing the separately tracked run-termination policy.
