## Summary

Keep open: current main already covers the tool-call argument part, but the remaining GBrain or external memory persistence transform contract is not proven fixed and needs maintainer plugin API direction.

## What This Changes

The issue requests broader `registerTextTransforms` coverage so output transforms also apply before tool execution and before GBrain or memory persistence writes.

## Best Possible Solution

Keep the current tool-argument transform behavior, then define or document a narrow memory/persistence transform contract only if maintainers confirm existing `before_message_write`, `tool_result_persist`, and memory-plugin hooks cannot support external GBrain-style plugins.

## Reproduction Assessment

No high-confidence current-main reproduction covers the whole issue. Source and tests show structured tool-call arguments are already transformed, while the GBrain persistence path is not implemented in this checkout and remains an external/plugin-owned claim.

## Solution Assessment

Unclear for the remaining persistence half: the current tool-call fix is the right narrow solution, but broadening `registerTextTransforms` globally may be too broad compared with a documented memory hook or narrower SDK extension.
