## Label Justifications

- `impact:data-loss`: The issue is about placeholder tokens being persisted into long-term memory and degrading future agent context.

## Summary

Current main already applies registered output text transforms to structured tool-call arguments after tool-call repair, and the durable memory flush path writes through those transformed tool arguments rather than a separate raw GBrain writer; the fix is on main only and has not shipped in v2026.6.11.

## What This Changes

The issue asks for `registerTextTransforms` output transforms to cover tool-call arguments and GBrain/memory persistence writes, or for equivalent plugin hooks to cover those paths.

## Best Possible Solution

Keep the current main implementation and ship it in the next release; open a narrower follow-up only if a concrete memory write path is found that bypasses transformed tool arguments.

## Reproduction Assessment

Yes, from source and release comparison: `v2026.6.11` lacks structured tool-call argument output transforms, while current main has source and test coverage for that path plus memory-flush writes through tool-call `content`. I did not run a live Docker reproduction in this read-only review.

## Solution Assessment

Yes: applying registered output transforms to structured tool-call content after tool-call repair is the narrowest maintainable fix, and it covers the memory flush write route without adding a new core privacy config or a parallel GBrain-specific hook.
