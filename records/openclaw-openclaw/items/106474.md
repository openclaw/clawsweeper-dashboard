## Summary

Keep this PR open for maintainer review. The focused validation patch appears correct and has strong production-path proof, but merging it makes five consecutive malformed `pullAudio` payloads shut down the active bridge under the existing transient-error policy; the owner of that policy should explicitly confirm this availability tradeoff before merge.

## What This Changes

The PR centralizes Google Meet audio-base64 validation and applies it before node-policy forwarding, node-host playback, realtime-provider input, and agent-transcription input, with regression coverage for malformed and valid payloads.

## Best Possible Solution

Keep the centralized validation at every Google Meet audio boundary and explicitly adopt the bounded five-malformed-chunk shutdown policy, with focused coverage showing that one malformed chunk is recoverable, a later valid chunk resets the budget, and repeated malformed input terminates exactly once.
