## Summary

Keep open: current main now covers Codex quota display and explicit `/login codex` private-channel/Web UI pairing, but it still lacks the requested unified typed quota-vs-reauth recovery-state contract and diagnosis-driven brokered reauth action.

## What This Changes

Request native Codex quota/auth diagnosis that separates quota waits from reauth-required failures, displays Codex quota windows, and supports bounded brokered reauth when appropriate.

## Best Possible Solution

Define a provider/Gateway/UI recovery-state contract that distinguishes quota wait from reauth required, using existing usage windows and OAuth classifiers, and keep brokered reauth as an explicit audited operator-controlled seam unless maintainers approve automatic execution.
