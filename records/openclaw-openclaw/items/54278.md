## Summary

Keep open: current main has useful pieces, including Codex quota display and explicit private `/login codex` device-code pairing, but it still lacks the requested native `quota_wait` versus `reauth_required` recovery-state contract and automatic/brokered reauth execution surface.

## What This Changes

Request native OpenAI/Codex quota/auth diagnosis that distinguishes quota wait from reauth required, shows rate-limit windows, and can invoke a bounded reauth adapter.

## Best Possible Solution

Define a typed provider/Gateway/UI recovery-state contract for canonical OpenAI/Codex first, then add brokered reauth only as an explicit, auditable, operator-controlled host or plugin seam.
