## Summary

Keep this PR open, but it is not merge-ready: the bounded read is useful for the direct/proxy fetch path, while the new non-transient overflow classification can replace the documented default-gateway fallback with a Discord startup failure. The submitted evidence also remains test-harness output rather than after-fix proof from a standalone runtime path.

Adds a 4 MiB streaming limit to direct Discord gateway metadata response reads, retains a body-less text fallback, changes overflow error classification, and adds focused loopback regression tests.

## Best Possible Solution
