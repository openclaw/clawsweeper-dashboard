## Summary

This PR addresses a real Telegram message-loss bug, but the current head should not merge: both ordinary and durable delivery can record text different from what Telegram displayed, and the external PR has no after-fix live Telegram proof.

## What This Changes

The PR carries source-derived plain text through Telegram rich-message plans and uses it for HTML parse-error retries while preserving reply, thread, preview, silent-send, and markup options.

## Best Possible Solution

Keep source retry text separate from the normal visible/cache projection, make send helpers report the exact body ultimately delivered, record that body in prompt context, cover rich-success and parse-fallback context behavior, then add redacted live Telegram proof.
