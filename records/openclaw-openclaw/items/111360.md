## Label Justifications

- `P2`: Reliable multi-channel scheduled notifications are currently unavailable, but existing single-target cron delivery remains usable.
- `impact:message-loss`: The requested capability concerns missed secondary-channel notifications when one cron producer must reach multiple destinations.
- `impact:session-state`: Each successful destination needs the established session-awareness behavior so later conversation turns can reference the delivered message.

## Summary

Keep open: this is a still-missing core cron-delivery capability, and the older fan-out PRs were closed unmerged while the current session-mirroring work covers only one required sub-behavior. The remaining decision is the durable public delivery contract, especially whether core should support explicit target lists only or also named configured target sets.

## What This Changes

The issue requests first-class cron fan-out to multiple independently resolved channel targets, with per-target status, idempotency, authorization, and destination-session awareness.

## Best Possible Solution

Define one canonical, backward-compatible cron fan-out contract in core—preferably explicit targets first—then reuse the established outbound resolution and successful-delivery session-awareness path per target; defer named target sets unless maintainers approve their separate configuration lifecycle.

Options:

- **Keep cron single-target:** Decline core fan-out and require operators to use separate jobs or external orchestration despite duplicated producer execution.
