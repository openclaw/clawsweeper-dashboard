## Summary

Keep open: multi-target cron delivery remains a missing core capability, while the session-mirroring work already on main solves only one required downstream invariant. The prior multi-target pull requests were closed unmerged, and the durable delivery/configuration contract still needs a maintainer product decision before another implementation attempt. Likely related people: cavit99 (current cron destination-session path) and mbelinky (recent cron payload/runtime work).

## What This Changes

Add first-class cron announce fan-out to multiple explicitly configured channel targets, with independent routing, delivery accounting, idempotency, and destination-session awareness.

## Best Possible Solution

Design one additive canonical cron delivery-target contract that preserves existing single-target jobs, resolves each target through the normal outbound-session path, records per-target outcomes, and delegates proactive context handling to the existing shared session-aware delivery mechanism.

- **Defer the feature:** Keep the request open but postpone implementation until proactive-context and concurrent session-write policy is settled.
