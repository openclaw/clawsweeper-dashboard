## Label Justifications

- `P2`: This is a substantive but non-emergency cron delivery capability gap affecting operators with multi-channel notification workflows.
- `impact:message-loss`: Without supported fan-out, intended secondary destinations do not receive the scheduled notification.
- `impact:session-state`: Each successful target needs the existing destination-session context contract to avoid a visible-message/transcript mismatch.

## Summary

Keep open: current cron delivery appears to preserve destination-session awareness for one resolved announce target, but the requested one-run, independently auditable multi-target fan-out remains a missing product and configuration contract. The earlier multi-target PRs were closed unmerged, so a maintainer must choose the durable delivery shape before a new implementation attempt.

## What This Changes

Add first-class cron announce fan-out so one command or agent-turn producer result can be delivered independently to multiple explicit channel targets or a configured target set.

## Best Possible Solution

Define one explicit multi-target announce contract owned by the cron delivery layer, reuse normal per-target route/session resolution and delivery tracing, and leave the broader proactive-context policy to the existing canonical work.
