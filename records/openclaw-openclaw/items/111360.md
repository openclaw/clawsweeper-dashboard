## Label Justifications

- `P2`: This is a bounded but cross-channel operational capability gap; single-target cron delivery continues to work.
- `impact:message-loss`: Operators needing the same scheduled notification in secondary configured destinations currently have no first-class cron delivery path for those destinations.
- `impact:session-state`: The requested behavior must preserve destination-session awareness after each successful proactive delivery.

## Summary

Keep open: this is a substantive new cron-delivery capability, not a duplicate of the merged destination-session mirroring work. The older multi-target implementations were closed unmerged, while the remaining design needs an explicit maintainer decision on the durable cron/config contract and safe per-target session handling.

## What This Changes

The issue requests first-class cron fan-out to multiple independently resolved channel targets, with per-target delivery auditing and destination-session awareness.

## Best Possible Solution

Define one canonical cron delivery-target list for explicit routes first, preserve existing single-target jobs unchanged, reuse the existing outbound destination-session path after each successful send, record structured per-target outcomes, and defer operator-managed target sets until maintainers approve their ownership and configuration contract.
