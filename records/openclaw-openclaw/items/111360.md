## Summary

This is a concrete, still-missing core cron capability rather than a duplicate of the prior closed PRs. It needs a maintainer decision on the public delivery contract and upgrade-safe semantics before implementation.

## What This Changes

Add first-class cron delivery fan-out so one command or agent cron run can independently deliver an identical result to multiple configured channel destinations with per-target audit and session-aware handling.

## Best Possible Solution

Approve a narrow generic core fan-out contract for explicit delivery targets first, reuse the existing outbound resolution and session-awareness writer for each successful target, and defer named target sets until their configuration ownership and operator workflow are explicitly designed.

## Risks / Open Questions

- A public target-list or named-target-set contract affects persisted cron job compatibility, gateway protocol/schema validation, CLI/UI editing, and upgrade behavior.
- Fan-out must define idempotency, partial-failure status, receipts, authorization, webhook rejection, and retry semantics per target without accidentally duplicating only a subset of deliveries.
