## Best Possible Solution

Define a maintainer-approved declarative cron import/export or reconcile path that keeps SQLite canonical unless the project explicitly chooses a new storage contract, then update config/schema, doctor, docs, and focused cron store/Gateway tests.

## Reproduction Assessment

Yes, at source level: current main has no `storeDir`, `jobs.d`, or per-job JSON reconcile path, and docs describe SQLite as the active cron store. This is a missing feature rather than a failing existing behavior path.

## Solution Assessment

No for the exact steady-state runtime `jobs.d` store proposal. The safer maintainable path is an explicit import/export or reconcile surface with deliberate SQLite, migration, validation, and path-safety semantics unless maintainers choose to change the storage contract.
