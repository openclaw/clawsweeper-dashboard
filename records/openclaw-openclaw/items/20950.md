## Summary

Keep open: current main and v2026.6.11 still do not support jobs.d/storeDir cron definitions, the prior implementation PR was closed unmerged, and the remaining path requires a maintainer product/storage decision.

## What This Changes

This issue requests a declarative cron jobs.d directory where each JSON file defines one cron job for NixOS/GitOps-style management.

## Best Possible Solution

Choose one supported declarative cron path: either a maintained core import/sync surface that keeps SQLite as the runtime source of truth, or a ClawHub/plugin sync workflow using supported cron APIs.

Yes for the missing capability by source inspection: current main only accepts cron.store and persists cron jobs through SQLite rows, with no storeDir/jobs.d branch in config, Gateway startup, or cron store code. This is a feature gap rather than a failing current-main bug.
