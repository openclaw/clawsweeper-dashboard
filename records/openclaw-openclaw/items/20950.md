## Summary

Keep open: current main and v2026.6.11 still lack jobs.d/storeDir cron support, the prior implementation PR was closed unmerged, and the remaining request requires a maintainer product decision on declarative cron storage.

## What This Changes

The issue requests a jobs.d/storeDir cron declaration workflow with one JSON file per job for NixOS/GitOps management.

## Best Possible Solution

Choose one supported declarative cron path: either a maintained core import/sync surface that keeps SQLite as the runtime source of truth, or a ClawHub/plugin workflow using existing cron APIs after maintainers confirm that boundary.

## Reproduction Assessment

Yes for the missing capability by source inspection: current main only accepts cron.store and persists cron jobs through SQLite rows, with no storeDir/jobs.d branch in config, Gateway startup, or cron store code. This is a feature gap rather than a failing current behavior bug.

## Solution Assessment

Unclear. A direct core storeDir implementation is plausible, but current design treats cron.store as a logical SQLite key and VISION favors lean core/plugin surfaces unless maintainers choose a core storage contract.
