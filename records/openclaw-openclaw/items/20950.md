## Summary

Keep open. Current main and v2026.6.11 still do not provide a `jobs.d`, `storeDir`, or per-job JSON cron source; the old implementation PR is closed unmerged, so this remains the canonical product-design tracker.

## What This Changes

Request support for declarative cron job definitions stored as one JSON file per job for NixOS/GitOps workflows.

## Best Possible Solution

Define a maintainer-approved declarative cron import or reconcile path that keeps SQLite canonical unless the project explicitly chooses a new storage contract, then update config/schema, doctor, docs, and focused cron store/Gateway tests.

## Reproduction Assessment

Yes, at source level: current main has no `storeDir`, `jobs.d`, or per-job JSON reconcile path, and the docs say active cron storage is SQLite-backed. This is a missing feature rather than a failing existing behavior path.

## Solution Assessment

No for the exact steady-state runtime `jobs.d` store proposal. The safer maintainable direction is an explicit import/export or reconcile surface with deliberate SQLite, migration, validation, and path-safety semantics.
