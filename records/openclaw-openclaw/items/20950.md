## Summary

Keep open: current main and v2026.6.11 still lack a jobs.d/storeDir cron directory surface, while current cron storage is SQLite-backed and the only prior implementation PR was closed unmerged as not merge-ready.

## What This Changes

Request support for a cron jobs.d/storeDir directory where each per-job JSON file can be symlinked for declarative NixOS/GitOps management.

## Best Possible Solution

Choose one supported declarative cron path: either a maintained core import/sync surface that keeps SQLite as the runtime source of truth, or a ClawHub plugin using existing cron APIs and declaration keys.

## Reproduction Assessment

Yes for the missing capability by source inspection: current main only accepts cron.store and persists cron jobs through SQLite rows, with no storeDir/jobs.d branch in config, Gateway startup, or cron store code. This is a feature gap rather than a failing current behavior bug.

## Solution Assessment

Unclear. A direct core jobs.d implementation is plausible, but current design treats cron.store as a logical SQLite key and existing declarationKey/plugin/Gateway cron APIs may support a safer ClawHub sync package if maintainers want core to stay lean.
