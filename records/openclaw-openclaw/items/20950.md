## Summary

Keep open. Current main and the latest release still do not provide `jobs.d`, `storeDir`, or another per-job declarative cron file source; the remaining work needs maintainer direction because current cron storage is SQLite-backed under one logical `cron.store` key.

## What This Changes

Request support for declarative per-job cron definition files so NixOS/GitOps users can manage jobs as individual JSON files instead of recreating or merging a single store.

## Best Possible Solution

Define a maintainer-approved declarative cron import or reconcile path that keeps SQLite canonical while making per-job files an explicit, validated, documented artifact/source.

## Reproduction Assessment

Yes, at source level: current main has no `storeDir`, `jobs.d`, or directory reconcile path, and the docs say active cron storage is SQLite-backed. This is a missing feature request rather than a failing existing behavior path.

## Solution Assessment

No for the exact steady-state runtime `jobs.d` store proposal. The safer maintainable path is a maintainer-approved import/reconcile surface or equivalent single-owner design that keeps storage, deletion, and validation semantics explicit.
