## Summary

Keep open: current main and v2026.6.11 still lack jobs.d/storeDir cron support, the previous directory-store PR was closed unmerged, and the remaining request is a real product/storage decision rather than stale cleanup.

## What This Changes

The issue requests one-file-per-cron-job directory support for declarative NixOS/GitOps cron management.

## Best Possible Solution

Choose one supported declarative cron path: either a maintained core import/sync surface that keeps SQLite as the runtime source of truth, or a ClawHub/plugin workflow using existing cron SDK/hooks if maintainers prefer to keep core lean.

## Reproduction Assessment

Yes for the missing capability by source inspection: current main accepts only `cron.store` and persists cron jobs through SQLite rows, with no `storeDir` or `jobs.d` branch in config, Gateway startup, or cron store code. This is a feature gap rather than a failing current behavior bug.

## Solution Assessment

Unclear. A direct core `cron.storeDir` implementation is plausible, but current design treats `cron.store` as a logical SQLite partition/import key and existing plugin hooks/SDK may be enough for a ClawHub directory-sync package if maintainers prefer to keep core lean.
