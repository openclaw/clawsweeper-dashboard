## Summary

Keep open: current main and v2026.6.11 still lack a `jobs.d`, `storeDir`, or per-job JSON cron source, and the only matching implementation PR is closed unmerged.

## What This Changes

Request support for declaring cron jobs as one JSON file per job in a `jobs.d`-style directory for GitOps and NixOS workflows.

## Best Possible Solution

Define a maintainer-approved declarative cron import, export, or reconcile path that keeps SQLite canonical unless the project explicitly chooses a new directory-backed storage contract, then update config/schema, doctor, docs, and focused cron/Gateway tests.

- **Decline Core Storage Mode:** Keep the supported path as CLI/Gateway API plus external user-side merge or import scripts for now.

## Solution Assessment

No for the exact steady-state runtime `jobs.d` proposal as an automatic fix. The safer maintainable path is a maintainer-approved declarative import/export or reconcile surface unless maintainers deliberately choose a new runtime storage contract.
