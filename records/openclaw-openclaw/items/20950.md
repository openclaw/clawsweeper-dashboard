## Summary

Keep open: current main and the latest release still lack jobs.d/storeDir cron support, the previous directory-store PR was closed unmerged, and the remaining choice is a cron storage product decision rather than cleanup-safe stale work.

## What This Changes

The issue requests a declarative cron jobs.d-style directory where each cron job can be managed as its own JSON file for NixOS/GitOps workflows.

## Best Possible Solution

Choose one supported declarative cron path: either a maintained core import/sync surface that keeps SQLite as the runtime source of truth, or a ClawHub/plugin workflow using existing cron SDK/hooks; avoid adding an unreviewed second runtime store.
