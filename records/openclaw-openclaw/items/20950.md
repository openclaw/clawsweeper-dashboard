## Summary

Keep open. Current main and v2026.6.11 still do not provide a `jobs.d`, `storeDir`, or per-job JSON cron source, and the only matching implementation PR is closed unmerged, so this remains a product/storage-direction tracker rather than conservative cleanup.

## What This Changes

The issue requests an optional directory-backed cron job definition store so GitOps/NixOS users can manage one JSON file per scheduled job.

## Best Possible Solution

Define a maintainer-approved declarative cron import/export or reconcile path that keeps SQLite canonical unless the project explicitly adopts a directory runtime store, then update schema/help, doctor, docs, and focused cron store/Gateway tests.

Question: Should OpenClaw support declarative per-job cron files as an import/reconcile artifact feeding SQLite, as a steady-state jobs.d runtime store, or not in core for now?

Rationale: Current code, docs, tests, and repository policy make SQLite the canonical cron runtime store, while the request adds new config/storage behavior with compatibility, identity, deletion, and path-safety implications that automation should not choose unilaterally.

Owner confidence: high

Options:

- **Reconcile Into SQLite (recommended):** Add a documented deterministic import/export or reconcile surface for per-job JSON that validates files and writes canonical SQLite rows without making file polling the runtime store.
- **Runtime Directory Store:** Add a new jobs.d-backed cron store mode with explicit migration, symlink, path-safety, stable filename, and upgrade semantics owned by maintainers.
- **Decline Core Storage Mode:** Keep the supported path as CLI/Gateway API plus external user-side scripts unless stronger demand or a plugin/API gap changes the product direction.

## Reproduction Assessment

Yes, at source level: current main has no `storeDir`, `jobs.d`, or per-job JSON reconcile/runtime source, while the docs and tests confirm SQLite-backed cron storage. This is a missing feature rather than a failing existing behavior path.

## Solution Assessment

No for the exact steady-state runtime `jobs.d` proposal without further direction. The narrower maintainable path is a maintainer-approved declarative import/export or reconcile surface unless maintainers deliberately choose a new runtime storage contract.
