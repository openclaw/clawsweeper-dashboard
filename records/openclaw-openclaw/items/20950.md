## Summary

Keep open. Current main and v2026.6.11 still lack a `jobs.d`, `storeDir`, or per-job JSON cron source; the old implementation PR is closed unmerged and the related duplicate issues point back here, so this remains necessary but needs maintainer product direction.

## What This Changes

The issue requests support for loading cron job definitions from a jobs.d-style directory with one JSON file per job for declarative NixOS/GitOps management.

## Best Possible Solution

Define a maintainer-approved declarative cron import or reconcile contract that keeps SQLite canonical unless the project explicitly chooses a new storage backend, then update config/schema, doctor, docs, and focused cron store/Gateway tests.

## Reproduction Assessment

Yes, at source level: current main has no `storeDir`, `jobs.d`, or per-job JSON reconcile path, and the docs say active cron storage is SQLite-backed. This is a missing feature rather than a failing existing behavior path.

## Solution Assessment

No for the exact steady-state runtime `jobs.d` store proposal. The safer maintainable direction is an explicit import/export or reconcile surface with deliberate SQLite, migration, validation, and path-safety semantics.
