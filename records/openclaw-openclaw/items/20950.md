## Summary

Keep open. Current main and v2026.6.11 still lack a `storeDir`, `jobs.d`, or per-job JSON reconcile path; the duplicate reports are closed and the only implementation PR was closed unmerged, so this remains the canonical tracker but needs maintainer product direction.

## What This Changes

The issue requests a directory-backed cron job definition store so each scheduled job can live in its own JSON file for NixOS/GitOps-style declarative management.

## Best Possible Solution

Define a maintainer-approved declarative cron import or reconcile path that keeps SQLite canonical while making per-job files an explicit, validated, documented artifact/source.

## Reproduction Assessment

Yes, at source level: current main has no `storeDir`, `jobs.d`, or directory-backed cron definition source, and the docs say active cron storage is SQLite-backed. This is a missing feature rather than a broken existing behavior path.

## Solution Assessment

No for the exact steady-state runtime `jobs.d` store proposal. The safer maintainable direction is an explicit import/reconcile surface that keeps SQLite canonical and makes ownership, deletion, validation, and path boundaries deliberate.
