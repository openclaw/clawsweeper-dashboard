## Summary

Keep open: current main and v2026.6.11 still lack jobs.d/storeDir cron support, the prior implementation PR is closed unmerged, and the remaining direction needs maintainer product judgment because cron jobs are now SQLite-backed with only a logical cron.store key.

## What This Changes

Request support for a declarative cron jobs.d directory where each JSON file defines one scheduled job for NixOS/GitOps workflows.

## Best Possible Solution

Choose one supported declarative cron path: either a maintained core import/sync surface that keeps SQLite as the runtime source of truth, or a ClawHub plugin using explicit cron APIs/hooks; avoid adding an unreviewed second runtime store.
