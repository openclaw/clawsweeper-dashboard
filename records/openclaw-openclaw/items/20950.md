## Summary

Close as a ClawHub/plugin handoff: the GitOps cron-directory workflow is useful, but current OpenClaw policy keeps cron runtime state SQLite-backed and the existing plugin startup plus cron-service APIs are sufficient for an external reconciler.

## What This Changes

The issue requests a `jobs.d` or per-job JSON cron directory, with a `cron.storeDir`-style option, so NixOS/GitOps deployments can manage one cron job per file.

## Best Possible Solution

Publish this as a ClawHub code plugin that reconciles a configured jobs.d directory into the SQLite-backed cron service at Gateway startup; include manifest metadata, a strict plugin config schema, directory and deletion semantics, symlink/path-safety notes, install/update docs, example NixOS usage, and smoke proof, and do not have ClawSweeper open a ClawHub issue, PR, tracking item, or publish it for the contributor.
