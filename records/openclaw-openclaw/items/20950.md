## Summary

Keep open. Current main still has no `storeDir`, `jobs.d`, or per-job JSON reconcile path; cron is now SQLite-backed behind one logical `cron.store` key, and the known implementation PRs are closed unmerged.

## What This Changes

Request support for a directory-backed cron definition source where each job can live in its own JSON file for NixOS/GitOps-style declarative management.

## Best Possible Solution

Define a maintainer-approved declarative cron import or reconcile path that keeps SQLite canonical while making per-job files an explicit, validated, documented source artifact.

## Reproduction Assessment

Yes, at source level: current main has no `storeDir`/`jobs.d` config or directory reconcile path, and the docs say active cron storage is SQLite-backed. This is a missing feature, not a failing existing behavior path.

## Solution Assessment

No for the exact steady-state runtime `jobs.d` store proposal. The safer maintainable direction is an explicit import or reconcile surface that keeps SQLite canonical and makes ownership, deletion, validation, and path boundaries deliberate.
