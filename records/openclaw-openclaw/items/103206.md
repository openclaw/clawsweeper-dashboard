## Summary

The reported pre-header hang is valid and the earlier assertion defects are fixed, but the patch imposes a total 15-minute transfer lifetime on both Tlon paths; that can reject continuously progressing transfers and contradicts the stated compatibility behavior. Exact-head CI is green, but after-fix real behavior proof remains missing.

## What This Changes

The PR adds an optional total request timeout to shared web-media loading and applies a 15-minute deadline to Tlon media download and URL-backed image upload fetches.

## Best Possible Solution

Add a shared response-header or pre-body deadline for remote media, preserve Tlon's existing 30-second body-idle and byte limits after headers arrive, and demonstrate both Tlon fallback paths against a controlled endpoint that accepts the request but withholds headers.

## Maintainer Decision

## Reproduction Assessment

Yes. Current source provides a high-confidence path: an endpoint can accept the connection and withhold headers indefinitely because `readIdleTimeoutMs` only governs response-body chunk reads and these callers provide no request deadline.

## Solution Assessment

No. Passing a total request lifetime fixes the hang but is broader than necessary; a response-header deadline is the narrower maintainable fix because Tlon already has body-idle and byte-limit enforcement.
