## Summary

This PR remains necessary: it is the candidate fix for the visible Control UI ordering bug tracked at https://github.com/openclaw/openclaw/issues/112943. The implementation appears to preserve durable transcript order and uses optional run identity to place genuinely live rows within their owning turn, but the PR still needs redacted after-fix proof from a real Control UI plus Gateway run before merge; the supplied evidence is tests and mocked-Gateway E2E only.

## What This Changes

The PR stops globally timestamp-sorting stable Control UI chat rows, then correlates live tool, stream, and question rows to the owning agent run so they render within the correct chat turn.

## System Context

The Control UI combines durable chat history and optimistic browser-local sends with live Gateway events such as streamed output, tool cards, and user-question prompts. The chat projection turns those inputs into ordered visual rows for the active session, including reconnecting runs.

## Best Possible Solution

Keep durable transcript and queued-send rows in canonical insertion order, insert only live rows within the verified owning run/turn, and attach a redacted real Control UI plus Gateway transcript or recording that demonstrates the corrected clock-skew flow and one reconnect or terminal-question path.
