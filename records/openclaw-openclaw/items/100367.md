## Summary

Keep open: current main has a fixed, per-turn `message_tool_only` delivery hint and warning-only suppression for missed tool sends, but I did not find an in-turn reminder refresh or same-turn recovery path for long tool chains that end with a plain private final.

## What This Changes

The issue asks OpenClaw to prevent `message_tool_only` long tool chains from ending in withheld plain assistant finals by refreshing or recovering the delivery contract and stabilizing reminder text.

## Best Possible Solution

Preserve the no-auto-publish privacy contract, keep the reminder fixed-size, and add a maintainer-approved combination of compact in-turn delivery refresh and bounded stranded-final recovery coordinated with the active recovery PR.

## Maintainer Decision

Required: true

Kind: product_direction

Question: For long `message_tool_only` turns that end with a plain private final, should OpenClaw add periodic in-turn delivery reminders, bounded withheld-final recovery, or both?

Rationale: The code shows a one-shot hint and warning-only suppression path, but choosing reminder refresh versus recovery affects prompt traffic, duplicate-delivery risk, queue semantics, and the documented privacy contract.

Likely owner: steipete

Owner reason: This crosses core delivery privacy, prompt-context behavior, and active recovery work, and the current integration history gives this the clearest routing signal.

Owner confidence: medium

Options:

- **Combine Reminder And Recovery (recommended):** Add a fixed-size reminder after bounded tool activity and a one-shot recovery path for substantive private finals, coordinated with the stranded-final recovery PR.
- **Recovery Only:** Rely on the stranded-final recovery path to repair missed finals after the model fails, without increasing prompt traffic during long tool chains.
- **Reminder Only:** Refresh the delivery instruction during long turns but leave withheld-final retry or diagnostics to separate recovery work.

No high-confidence live reproduction of the exact long-chain recency decay is available from this review. Source and QA coverage do reproduce the stranded-final half of the problem: a substantive `message_tool_only` final with no message-tool call is kept private and only warned.

## Solution Assessment

Unclear until maintainer direction. The requested directions are plausible, but the best fix should be chosen between bounded reminder refresh, stranded-final recovery, or both while preserving the no-auto-publish privacy contract.
