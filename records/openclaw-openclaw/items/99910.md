## Summary

Keep open: current main and v2026.6.11 still run memory-core dreaming sweep, recall repair, ranking, promotion, report, and narrative work in the gateway-triggered path, and the reported post-2026.6.9 invalid-recall-store event-loop peg is not proven fixed. ## What This Changes

The issue asks for investigation and bounded recovery when memory-core short-term promotion starts from missing or invalid recall state and monopolizes the gateway.

## Best Possible Solution

Identify the concrete rebuild or state-store hot path, make scheduled dreaming bounded and yield-friendly without adding another config knob, and coordinate interrupted-run state with https://github.com/openclaw/openclaw/issues/97692.

## Reproduction Assessment

No high-confidence current-main live reproduction was established in this read-only review. The reporter provides repeated unmodified 2026.6.9 evidence, and source inspection shows the same central dreaming path remains, but the process samples are needed to isolate the hot frame.

Unclear: capping or chunking is the right direction, but the best fix depends on whether the hot path is session ingestion, recall repair/writeback, plugin-state scanning, or narrative/report work.
