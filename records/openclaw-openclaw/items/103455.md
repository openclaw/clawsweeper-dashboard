## Summary

This issue remains necessary: current main and the latest release deterministically reject iOS pairing when the device wall clock differs from the Gateway by more than two minutes, despite the handshake already carrying Gateway time.

## What This Changes

Fix iOS Gateway pairing when device clock skew causes device-auth signature freshness validation to fail.

## Best Possible Solution

Carry a validated `connect.challenge.ts` through shared challenge handling, sign only after receiving it across affected clients, retain nonce binding and bounded freshness validation, and provide an inline native retry or clock-recovery path when challenge time is missing or invalid.
