## Label Justifications

- `P0`: The PR targets an observed update race that left the core Gateway unavailable and required lengthy manual recovery.
- `merge-risk: 🚨 availability`: The patch changes who schedules the Gateway restart and when future updater launches become eligible across managed-service supervisors.

## Summary

Keep open: the shared single-flight owner is the right architectural boundary, but joined requests can silently lose their accepted post-restart continuation, and the changed supervisor lifecycle still lacks real managed-service proof.

## What This Changes

The PR makes managed service update handoffs single-flight so concurrent manual and automatic callers share one updater while only the owning caller persists restart state and schedules the Gateway restart.

## Best Possible Solution

Keep single-flight coordination in the shared infra helper, but expose joined-call semantics explicitly and preserve or queue every accepted continuation; then demonstrate one updater, one restart, flight release, and healthy Gateway recovery on a real managed supervisor.
