## Summary

Current main and a published package already document the central requester-ownership model: the requester decides user delivery, completion is reviewed as evidence, `sessions_yield` is the wait primitive, polling loops are discouraged, and native children do not receive the message tool. This narrow docs PR would create a duplicate section rather than fill a remaining gap. ([raw.githubusercontent.com](https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/subagents.md))

## What This Changes

This PR adds a requester-ownership accordion to the Spawn section of the subagent documentation.

## System Context

Subagent spawning creates background child runs that return completion context to the requester session. The requester reviews that context, may yield while waiting, and remains responsible for any user-facing response.
