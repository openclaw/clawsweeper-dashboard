## Summary

Keep open: current main still has the compaction auth-profile parity gap, and the linked fixing PR is open but unmerged, so closing this issue would drop the canonical tracker before the fix lands.

## What This Changes

The issue asks compaction to retry same-provider backup auth profiles when an auto-selected profile is rate-limited or in cooldown.

## Best Possible Solution

Land or replace the linked fixing PR with same-provider auto-profile rotation that preserves user-locked profiles and applies exactly one compaction result from a stable transcript snapshot.

## Reproduction Assessment

Yes, at source level: current main's direct compaction path can keep one selected auth profile while normal embedded runs have an explicit profile-candidate rotation controller. I did not run a live provider reproduction in this read-only review.

## Solution Assessment

Yes on direction, with one maintainer-sensitive constraint: the fix should rotate only auto-selected same-provider profiles, keep user-selected profiles locked, and apply one result from a stable transcript snapshot.
