## Summary

Keep open: current main and v2026.6.11 still route compaction through one supplied auth profile, while the direct fixing PR is closed unmerged and the remaining adjacent PR covers a narrower OpenAI Responses auth fallback case.

## What This Changes

The issue requests same-provider auth-profile rotation/failover during compaction when the selected profile is rate-limited or cooling down.

## Best Possible Solution

A maintainer-approved fix should reuse normal auth-profile candidate ordering inside compaction only for auto/inherited profiles and apply exactly one summary to a stable transcript snapshot.
