## Summary

Keep open: current main and the latest release still lack same-provider auth-profile rotation in compaction, and the linked fixing PR is open but unmerged, so this issue remains the canonical tracker.

## What This Changes

Compaction should retry auto-selected backup auth profiles within the same provider when the current profile is rate-limited or cooling down.

## Best Possible Solution

Land or replace the linked fixing PR with same-provider auto-profile rotation that preserves user-locked profiles and applies at most one compaction result from a stable transcript snapshot.

## Reproduction Assessment

Yes at source level: current main passes one authProfileId through compaction while normal embedded runs have explicit profile advancement for retryable failures. I did not run a live provider reproduction in this read-only review.

## Solution Assessment

Yes on direction, but not by closing this issue now. The best path is to review and land the linked PR, or replace it with an equivalent fix that preserves user-locked profiles and one-apply compaction semantics.
