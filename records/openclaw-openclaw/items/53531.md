## Summary

Keep open: current main still preserves a single supplied compaction auth profile instead of rotating through same-provider backup profiles, and the direct fixing PR is closed unmerged rather than landed.

## What This Changes

The issue asks compaction to use same-provider auth-profile rotation/failover when an auto-selected profile is rate-limited or unavailable.

## Best Possible Solution

Define and implement same-provider auto-profile compaction failover that preserves user-locked profiles and applies at most one summary to a stable transcript snapshot.

Yes, at source level: current main preserves a supplied compaction authProfileId for same-provider attempts and resolves that explicit profile directly instead of walking auth.order. I did not run a live long-session/provider reproduction in this read-only review.

## Solution Assessment

Unclear until maintainer direction is confirmed. The likely best shape is bounded same-provider auto-profile rotation with user-lock preservation and stable-snapshot apply-once semantics, not cross-provider compaction.
