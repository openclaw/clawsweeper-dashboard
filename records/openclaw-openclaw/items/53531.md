## Summary

Keep open: current main still uses a single selected auth profile during compaction, while the linked candidate fix is open and unmerged, so this issue remains the canonical tracker.

## What This Changes

The issue requests same-provider auth-profile rotation/failover for compaction when the initially selected profile is rate-limited or unavailable.

## Best Possible Solution

Land or replace the linked fixing PR with same-provider auto-profile rotation that preserves user-locked profiles and applies at most one compaction result from a stable transcript snapshot.

## Reproduction Assessment

Yes, at source level. Current main threads one selected auth profile into compaction, while normal embedded runs have an explicit profile advancement path for retryable auth/provider failures.

## Solution Assessment

Yes on direction, but not ready to close. The durable solution should reuse the normal same-provider profile-rotation semantics while preserving user-locked profiles and enforcing a stable compaction snapshot/apply-once boundary.
