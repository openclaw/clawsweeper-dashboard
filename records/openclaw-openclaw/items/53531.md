## Summary

Keep open: current main and v2026.6.11 still carry one selected auth profile through compaction, while normal runs have same-provider profile advancement. The linked fixing PR at https://github.com/openclaw/openclaw/pull/95650 is open and unmerged, so this issue remains the canonical tracker.

## What This Changes

The issue asks compaction to retry backup auth profiles within the same provider when an auto-selected profile is rate-limited or in cooldown.

## Best Possible Solution

Land or replace the linked fixing PR with same-provider rotation for auto-selected profiles, user-pinned profile preservation, and apply-once compaction from a stable transcript snapshot.

## Reproduction Assessment

Yes at source level: current main uses one selected auth profile for compaction while normal embedded runs have explicit profile advancement on retryable failures. I did not run a live provider reproduction in this read-only review.

## Solution Assessment

Yes on direction, but the final fix needs maintainer-approved idempotency semantics: rotate only auto-selected same-provider profiles, preserve user-locked profiles, and apply one result from a stable transcript snapshot.
