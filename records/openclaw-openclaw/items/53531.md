## Summary

Keep open: current main and the latest release still carry one selected auth profile through compaction instead of retrying same-provider backup profiles, and the linked fixing PR is open but unmerged.

## What This Changes

Compaction should retry same-provider backup auth profiles when an auto-selected profile is rate-limited, while preserving user-selected profile locks and applying only one safe compaction result.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/95650 with same-provider auto-profile rotation that preserves user-locked profiles and applies at most one compaction result from a stable transcript snapshot.

## Reproduction Assessment

Yes at source level: current main still sends compaction through one selected auth profile while the normal run path has explicit profile-candidate rotation and locked-profile handling. I did not run a live provider reproduction in this read-only review.

## Solution Assessment

Yes on direction, but the final implementation needs maintainer-approved idempotency semantics. The safest fix is the linked PR shape: rotate only auto-selected same-provider profiles, preserve user-locked profiles, and apply one result from a stable transcript snapshot.
