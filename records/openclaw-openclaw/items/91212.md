## What This Changes

The issue reports pending Feishu outbound deliveries failing recovery after a gateway restart because recovery can run before the channel transport is ready and retry counts accumulate.

## Best Possible Solution

Keep the shipped budget-deferral fix, then add a Feishu or channel-owned readiness/reconnect-drain path after WebSocket ready/reconnected with focused tests and live restart proof; avoid fixed sleeps or blanket retry resets unless maintainers explicitly choose that policy.
