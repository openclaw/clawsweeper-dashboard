## Summary

Keep open: current main and v2026.6.11 fix the budget-deferral retry inflation, but Feishu still lacks channel-ready or reconnect-triggered draining for the reported gateway-restart message-loss path.

## What This Changes

The issue requests restart-safe outbound delivery recovery for Feishu so queued messages are not retried before the WebSocket transport is ready or exhausted by phantom retry counts.

## Best Possible Solution

Add a Feishu-owned onReady/onReconnected drain using the shared delivery-queue runtime, keep budget deferrals non-counting, and validate with live Feishu gateway-restart proof before changing retry-reset policy.
