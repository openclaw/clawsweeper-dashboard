## Summary

Keep open: current main has fixed the budget-deferral retry-accounting subcase, but the central Feishu gateway-restart/readiness recovery remains unresolved because startup recovery still runs immediately and Feishu does not drain queued deliveries on WebSocket ready/reconnect.

## What This Changes

The issue requests fixing gateway-restart outbound delivery recovery so pending Feishu messages wait for or drain after transport readiness without incorrectly consuming retry budget.

## Best Possible Solution

Keep the budget-deferral fix, then add a Feishu-owned reconnect/readiness drain backed by focused tests and live restart proof; avoid fixed sleeps or blanket retry resets.
