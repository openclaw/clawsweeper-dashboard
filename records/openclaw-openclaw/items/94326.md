## Summary

## What This Changes

The PR adds a memory-wiki page-stem helper that disambiguates the compiler-owned `index` stem for synthesis creation and source ingest while leaving shared slug output stable.

## Best Possible Solution

Land one coordinated memory-wiki page-allocation fix that keeps shared slug output stable, reserves only the compiler-owned `index` direct page stem, and preserves the distinct-title collision fix from https://github.com/openclaw/openclaw/pull/93843.

## Reproduction Assessment

Yes. Source inspection shows current main maps `Index` synthesis and ingest titles to generated `syntheses/index.md` or `sources/index.md`, while compile/query/status skip or rewrite `index.md`; the PR body also includes before/after live output.

## Solution Assessment

Yes. The direct page-stem helper is the best boundary because `index.md` is compiler-owned only for bare synthesis/source page allocation; changing global `slugifyWikiSegment` would churn bridge, unsafe-local, and OKF identities, while a source-only fix would miss synthesis.
