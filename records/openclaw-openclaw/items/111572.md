## What This Changes

Fix Telegram channel recovery when an established `getUpdates` request survives stop abort, leaving health-monitor retries permanently wedged on `reason: stopped`.

## Best Possible Solution

Define a channel-owned cancellation contract that conclusively terminates the Telegram polling transport after a bounded stop timeout, then let the shared gateway recovery path restart only after that termination is observable and regression-tested with an established held response.
