## Summary

Keep open: the PR targets a valid Slack metadata bug, but it is not safe to merge as-is because the patch also removes Slack's current-message thread anchor used by message-tool auto-threading for standalone messages.

## What This Changes

The PR changes Slack inbound threading so `replyToId` is only set for genuine Slack thread replies and updates Slack resolver/preparation tests for standalone and self-thread-root messages.

## Best Possible Solution

Suppress self-referential prompt-facing `reply_to_id` without removing Slack's internal current-message thread anchor for message-tool auto-threading, and cover both paths with focused tests.

## Solution Assessment

No. The resolver is the right owner boundary for the reported Slack value, but this patch removes an internal delivery anchor; the safer fix separates prompt-facing `reply_to_id` cleanup from Slack auto-threading state.
