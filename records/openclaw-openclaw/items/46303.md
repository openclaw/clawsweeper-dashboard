## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Count summary backlog before declaring followups drained:** `src/auto-reply/reply/queue/drain-all.ts:21`
  - body: `scheduleFollowupDrain` keeps draining while `queue.droppedCount > 0`, but this new restart waiter only counts `items.length` and `draining`. If a restart hits a queue whose pending work has been compacted into an overflow summary, this helper can return `drained: true` before that summary followup is admitted, letting shutdown continue and dropping the remaining queued message summary.
  - confidence: 0.91
- **[P1] Keep the drain bypass out of the public SDK:** `src/plugin-sdk/channel-lifecycle.core.ts:33-36`
  - body: `ChannelRunQueue` is exported through `openclaw/plugin-sdk/channel-lifecycle` and `channel-outbound`, so adding `enqueueInternal` here gives plugin consumers a public way to bypass the normal gateway-draining rejection boundary. The restart path needs an internal core-owned bypass, not a new third-party SDK capability that can enqueue work during drain.
  - confidence: 0.9
