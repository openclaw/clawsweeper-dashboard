- **[P1] Count summary backlog before declaring followups drained:** `src/auto-reply/reply/queue/drain-all.ts:21`
  - body: `waitForFollowupQueueDrain()` only counts queued items and the active drain sentinel, but the actual drain loop keeps working while `queue.droppedCount > 0` and can deliver summary-only followups. A restart can therefore treat a summary-only queue as drained and continue shutdown before that user-visible followup is delivered.
  - confidence: 0.9
- **[P1] Keep restart-drain bypass out of the public SDK:** `src/plugin-sdk/channel-lifecycle.core.ts:33-36`
  - body: Adding `enqueueInternal` to `ChannelRunQueue` exposes the restart-drain bypass through `openclaw/plugin-sdk/channel-outbound`, and the same bypass is threaded into plugin runtime run params. That turns a core-only shutdown exception into a plugin-facing capability that can bypass gateway-draining admission, so the bypass should stay behind an internal core helper instead of becoming SDK surface.
  - confidence: 0.86
