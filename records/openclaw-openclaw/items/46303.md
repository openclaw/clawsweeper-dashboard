## Best Possible Solution

Keep the restart-drain direction, but make the bypass core-owned/internal, align the drain waiter with the actual followup drain predicate including dropped summary work, and require current-head real restart proof before merge.

## Reproduction Assessment

Yes, source inspection gives a credible reproduction path: current main keeps inbound debounce and followup queue state in process memory, so SIGUSR1 restart can drop buffered work. I did not run a live Signal or Telegram restart reproduction in this read-only review.

## Solution Assessment

No, current head is only a plausible fix. The maintainable shape should keep restart-drain privileges out of public plugin APIs and make the drain waiter mirror the queue drainer's actual pending-work predicate.
