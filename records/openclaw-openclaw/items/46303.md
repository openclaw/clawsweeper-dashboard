## Best Possible Solution

## Reproduction Assessment

Yes, at source level for the PR-introduced dropped-summary case: a followup queue can have droppedCount > 0 while items.length is 0, and the new restart waiter reports that as drained even though the real drain loop keeps processing it.

## Solution Assessment

No. The narrow drain mitigation is plausible, but the current shape is not the best fix until the drain predicate matches the real queue contract and the restart bypass is kept out of public plugin SDK API.
