## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Count overflow summaries before declaring followups drained:** `src/auto-reply/reply/queue/drain-all.ts:21-22`
  - body: `scheduleFollowupDrain` keeps draining while `queue.items.length > 0 || queue.droppedCount > 0`, but this waiter only counts `items.length` plus the active-drain sentinel. During restart, a summarized overflow queue with `droppedCount > 0` and no items will return `drained: true`, so the SIGUSR1 path can close while summary followups remain pending. Mirror the drain loop's pending-work predicate and add a dropped-count/summary regression.
  - confidence: 0.89
- **[P1] Keep the drain bypass out of the public SDK:** `src/plugin-sdk/channel-lifecycle.core.ts:33-36`
  - body: `ChannelRunQueue` is exported through public plugin SDK subpaths, so adding `enqueueInternal` gives plugin authors an explicit way to bypass the gateway-draining admission gate. That turns a restart-only internal exception into a public contract and security boundary; keep the bypass core-owned or encode already-accepted pre-drain work inside the queue without exposing a new public method.
  - confidence: 0.91
