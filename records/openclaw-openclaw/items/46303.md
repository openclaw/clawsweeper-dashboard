Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Count summarized backlog before declaring followups drained:** `src/auto-reply/reply/queue/drain-all.ts:21-22`
  - body: `waitForFollowupQueueDrain()` only counts queued items plus an in-flight sentinel, but `scheduleFollowupDrain()` keeps running while `queue.droppedCount > 0` and can synthesize overflow-summary followups from that state. A restart can therefore see `{drained:true}` while the only remaining user messages are represented by summarized backlog, then continue shutdown and drop them.
  - confidence: 0.93
- **[P1] Keep the drain bypass out of the public SDK:** `src/plugin-sdk/channel-lifecycle.core.ts:33-36`
  - body: `ChannelRunQueue` is exported through `openclaw/plugin-sdk/channel-outbound` and the deprecated `channel-lifecycle` facade, so adding `enqueueInternal` publishes a gateway-drain bypass to third-party plugins. That makes an internal restart trust boundary part of the public SDK contract; keep this helper core-private or get explicit maintainer approval with docs and contract coverage.
  - confidence: 0.91
