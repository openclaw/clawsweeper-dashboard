## Summary

Keep open: the PR targets a real restart-time message-loss path, but the current head still has blocking queue-drain and public SDK/security-boundary issues, and the real behavior proof is for an older head before later runtime changes.

## What This Changes

The PR adds SIGUSR1 restart-time flushing and draining for inbound debouncers, channel run queues, followup queues, and drain-bypass plumbing across core, plugin SDK, Discord queue handling, and tests.

## Best Possible Solution

Keep the restart-drain mitigation, but make the bypass host-private, count the full followup queue drain predicate including summary backlog, rebase cleanly, and require current-head real restart proof; leave durable cross-process replay to the canonical restart message-loss issue/SQLite persistence PR.

Yes, at source level: current main has process-local debounce/followup queues and no global flush/drain helpers, so SIGUSR1 restart can lose buffered work. I did not run a live Signal/Telegram restart in this read-only review.

## Solution Assessment

No, not yet: the in-memory drain approach is plausible, but this patch still undercounts followup summary backlog and exposes the restart bypass through public SDK surfaces. A maintainable fix should keep the bypass internal and prove current-head behavior after rebase.
