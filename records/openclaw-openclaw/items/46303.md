Full review comments:

- **[P1] Run pre-created debounce work under live restart admission:** `src/auto-reply/inbound-debounce.ts:321-325`
  - body: The buffered task is created while the inbound request's root admission is active, and `flushBuffer()` later only releases that existing promise chain. After the request returns, that inherited root is released, so the callback's eventual `enqueueCommandInLane()` still sees admission closed even though the caller is inside `runWithGatewayRestartDrainContinuation()`. Retain or explicitly re-enter only this accepted work, and add a regression that releases the original root before flushing through the real command-enqueue path.
  - confidence: 0.97
- **[P1] Bound the global debounce sweep against live ingress:** `src/auto-reply/inbound-debounce.ts:30-46`
  - body: `flushAllInboundDebouncers()` repeats until an entire pass flushes zero buffers but receives no deadline. Each channel callback can yield while ingress adds another buffer, so sustained traffic can keep restart in this loop until forced exit. Pass the shared absolute restart deadline into the sweep and return drained, remaining, and timeout state to the run loop.
  - confidence: 0.95
