## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P1] Keep external queue work outside drain-internal context:** `src/plugin-sdk/channel-lifecycle.core.ts:167`
  - body: `enqueue()` is the normal channel/plugin admission path, but it passes `true` into `enqueueAccepted`, so every accepted external channel task runs inside `runWithGatewayDrainInternalContext`. That makes followup enqueues and embedded runs inherit the gateway-drain bypass and can let ordinary inbound work continue spawning command-lane work after restart draining starts. Pass `false` for normal `enqueue()` and reserve the bypass for a private internal restart path.
  - confidence: 0.9
- **[P1] Count overflow summaries as pending drain work:** `src/auto-reply/reply/queue/drain-all.ts:21`
  - body: The waiter only counts `items.length` plus a draining sentinel. Followup queues also keep pending overflow-summary work in `droppedCount`/summary state, and the real drain loop continues while `droppedCount > 0`; this helper can therefore report `drained: true` and let restart proceed before summary followups run. Mirror the drain predicate and add coverage for summary-only queues.
  - confidence: 0.88
- **[P1] Keep the drain bypass out of the public SDK:** `src/plugin-sdk/channel-lifecycle.core.ts:33-36`
  - body: `ChannelRunQueue` is exported through the plugin SDK, so adding `enqueueInternal` exposes a privileged restart-drain bypass to plugin consumers as a new public contract. The bypass should stay in core-owned restart plumbing or go through an explicitly approved/documented SDK design with compatibility and security-boundary tests.
  - confidence: 0.82
