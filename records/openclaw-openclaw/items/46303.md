- **[P1] Count summary backlog before declaring followups drained:** `src/auto-reply/reply/queue/drain-all.ts:21`
  - body: `scheduleFollowupDrain` keeps working while `queue.items.length > 0 || queue.droppedCount > 0`, but this new waiter only counts `items` plus a `draining` sentinel. A queue with summarized overflow (`droppedCount > 0`) and no active drain reports `drained: true`, so SIGUSR1 shutdown can continue before the summary followup is delivered and lose queued messages.
  - confidence: 0.91

  - body: `ChannelRunQueue` is exported through `openclaw/plugin-sdk/channel-outbound` and `openclaw/plugin-sdk/channel-lifecycle`, so adding `enqueueInternal` makes the restart-drain bypass a third-party plugin API. That lets plugins intentionally run work after gateway draining starts and turns an internal availability/security exception into a supported contract; keep the bypass private to core-owned restart flushing or get an explicit SDK contract approved.
  - confidence: 0.88
