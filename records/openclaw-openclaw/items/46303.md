Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Count summarized backlog before declaring followups drained:** `src/auto-reply/reply/queue/drain-all.ts:21-22`
  - body: This remains from the previous ClawSweeper finding. `waitForFollowupQueueDrain()` only counts queued items and an active drain sentinel, but the real drain loop keeps running while `droppedCount > 0` to deliver overflow summaries. A capped followup queue with summarized drops and no live items can therefore return `drained: true`, letting SIGUSR1 shutdown proceed while user messages represented by the summary backlog are still pending.
  - confidence: 0.91
- **[P1] Keep the drain bypass out of the public SDK:** `src/plugin-sdk/channel-lifecycle.core.ts:33-36`
  - body: This remains from the previous ClawSweeper finding. `ChannelRunQueue` is exported through `openclaw/plugin-sdk/channel-lifecycle`, so adding `enqueueInternal` makes the restart-drain bypass a third-party plugin method. That weakens the gateway draining boundary and locks an internal restart mechanism into the SDK; keep this capability host-internal or require an explicit maintainer-approved SDK contract.
  - confidence: 0.88
