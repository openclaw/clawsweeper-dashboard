## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P1] Count overflow summaries before declaring queues drained:** `src/auto-reply/reply/queue/drain-all.ts:21-22`
  - body: `scheduleFollowupDrain` keeps draining while `queue.droppedCount > 0`, but this new waiter only counts `items.length` and the active `draining` sentinel. A queue that has only overflow-summary backlog can be reported as drained, so SIGUSR1 shutdown may continue before those summarized followups are processed. Mirror the real drain predicate, including summary backlog, and add a regression case for droppedCount-only queues.
  - confidence: 0.9
- **[P1] Keep restart-drain bypass out of public channel SDK:** `src/plugin-sdk/channel-lifecycle.core.ts:33-36`
  - body: `ChannelRunQueue` is exported through public plugin SDK subpaths, so adding `enqueueInternal` exposes the gateway-drain bypass to plugin code. That lets plugin callers enqueue work around `isGatewayDraining()` and turns an internal restart repair into a new public security/compatibility contract. Keep this bypass behind core-owned restart plumbing or get explicit maintainer approval with SDK docs and compatibility tests.
  - confidence: 0.84
