## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Count summary backlog before declaring followups drained:** `src/auto-reply/reply/queue/drain-all.ts:21-22`
  - body: `waitForFollowupQueueDrain` only counts queued items and active drains, but the actual drain loop continues while `queue.droppedCount > 0` to deliver overflow summaries. A restart can therefore see `{ drained: true }` for a queue whose `items` array is empty while summarized message content still needs a synthetic followup, then proceed to shutdown with that content still in memory. Mirror the drain loop predicate, including summary backlog, and add a timeout test for that state.
  - confidence: 0.93
- **[P1] Keep restart-drain bypass out of the public SDK:** `src/plugin-sdk/channel-lifecycle.core.ts:33-36`
  - body: Adding `enqueueInternal` to exported `ChannelRunQueue` exposes the gateway-drain bypass through `openclaw/plugin-sdk/channel-lifecycle` and `channel-outbound`, so plugin code can call the same path meant only for trusted restart flushing. That weakens the `GatewayDrainingError` boundary and creates a new public API without a documented compatibility/security decision. Keep the bypass in core-owned restart plumbing or a private internal handle, leaving the public queue contract unchanged.
  - confidence: 0.9
