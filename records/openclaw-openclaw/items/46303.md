## Summary

The central restart-drain handoff remains incorrect: buffered callbacks created before the drain do not inherit its admission context when later awaited. Exact-head CI also exposes test-isolation leakage in the new followup drain suite, and the supplied proof does not cover the real pre-restart buffered-message path.

## What This Changes

This PR adds coordinated restart draining for inbound debounce buffers, channel worker queues, active work, and followup queues before SIGUSR1 reload.

## Best Possible Solution

Transfer each preexisting debounced dispatch into an explicit drain-owned admission scope before invoking its normal callback, preserve same-key serialization and private SDK boundaries, and isolate followup drain tests before every case.

- **[P1] Transfer preexisting debounce tasks into drain admission:** `src/cli/gateway-cli/run-loop.ts:533-534`
  - body: `flushAllInboundDebouncers()` only releases debounce tasks created when each message originally arrived. For channel ingress without a current gateway root, the callback still reaches `enqueueCommandInLane()` after admission closes and can throw `GatewayDrainingError`, dropping the buffered message.
