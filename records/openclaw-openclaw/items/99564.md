## Summary

Keep open: this focused bug-fix PR is still necessary because current main and the latest release still allow surrogate numeric entities to become lone UTF-16 surrogates in tool-call arguments, while the PR head fixes that boundary with sufficient proof and no blocking findings.

## What This Changes

The PR changes embedded-agent-runner HTML entity decoding to preserve surrogate-range numeric entities as literal text and extends focused decoder tests.

## Best Possible Solution

Land the narrow decoder guard and regression test after normal maintainer review, while keeping the sibling shared web_fetch/syntax decoder hardening in https://github.com/openclaw/openclaw/pull/99580 separate.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 pass surrogate numeric values to String.fromCodePoint, and a focused Node probe shows the resulting lone surrogate can break URI encoding.

## Solution Assessment

Yes. Rejecting surrogate numeric entities in the tool-call argument decoder is the narrowest maintainable fix for this runtime boundary and avoids downstream JSON, URI, transcript, or tool-specific sanitizers masking malformed input later.
