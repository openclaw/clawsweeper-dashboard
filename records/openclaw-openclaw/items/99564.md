## Summary

Keep open for maintainer landing: current main still has the malformed-surrogate decoder gap, while this PR is a focused fix with sufficient terminal proof, green relevant checks, and no actionable review findings.

## What This Changes

The PR tightens tool-call argument HTML numeric entity decoding so surrogate code points remain literal entities while valid numeric and named entities still decode.

## Best Possible Solution

Land the scalar-value guard at the existing provider-to-tool argument decoder boundary, preserving current valid entity decoding and avoiding later lossy sanitization.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, source-reproducible: current main passes surrogate-range numeric entities to String.fromCodePoint in the active tool-call argument decoder, and a Node probe confirms that value creates a lone surrogate that breaks URI encoding. I did not run a full failing tool-execution scenario in this read-only review.

## Solution Assessment

Yes. This is the best fix because it enforces Unicode scalar validity at the existing decoder boundary and matches sibling HTML decoders, while later sanitization would be lossy and a full parser would broaden semantics unnecessarily.
