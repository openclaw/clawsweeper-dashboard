Keep open: current main and the latest release still allow surrogate numeric entities through the tool-call argument decoder, while this PR makes the narrow decoder-side fix with focused regression coverage and sufficient local provider-boundary proof.

## What This Changes

The PR updates embedded-agent-runner tool-call argument HTML entity decoding to preserve surrogate numeric entities while continuing to decode valid entities, with focused tests.

## Best Possible Solution

Land the narrow decoder guard and regression test after remaining CI completes, while keeping the sibling web_fetch/syntax helper hardening in its separate PR.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 pass surrogate numeric values to String.fromCodePoint, and a focused Node probe shows the resulting lone surrogate can break URI encoding.

## Solution Assessment

Yes. Rejecting surrogate numeric entities in the tool-call argument decoder is the narrowest maintainable fix for this runtime boundary and avoids downstream JSON, URI, transcript, or tool-specific sanitizers masking malformed input later.
