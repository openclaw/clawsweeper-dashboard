## Summary

Keep open: this PR is still necessary because current main and the latest release still decode surrogate numeric entities into lone UTF-16 surrogates in the tool-call argument wrapper, and the related surrogate-entity PR covers a separate web_fetch/syntax-highlight decoder rather than superseding this path. The patch is focused, has real behavior proof in the PR body, and I found no blocking correctness findings.

## What This Changes

The PR tightens the embedded-agent-runner HTML-entity tool-call argument decoder so surrogate numeric entities stay literal while valid numeric entities still decode, and extends focused regression tests.

## Best Possible Solution

Land this focused decoder guard and regression test after maintainers accept the local provider-boundary proof and required checks, while keeping the sibling web_fetch/syntax-highlight hardening separate.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 pass surrogate numeric values to String.fromCodePoint, and a focused Node probe confirms the resulting lone surrogate breaks URI encoding; I did not run a full OpenClaw E2E repro in this read-only review.

## Solution Assessment

Yes. Rejecting surrogate code points in the tool-call argument decoder is the narrowest maintainable fix for this runtime boundary and preserves the existing invalid-entity fallback behavior without provider-specific policy or config.
