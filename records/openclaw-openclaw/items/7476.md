## Summary

Keep this issue open. Current main and v2026.6.11 contain a tested low-level WhatsApp sticker sender, but only the QA driver uses it; the ordinary listener contract, message-tool action discovery, and channel dispatcher still cannot send native stickers. The remaining blocker is a maintainer product choice between transporting sticker-ready WebP and promising conversion of arbitrary static or animated media.

## What This Changes

Add first-class outbound WhatsApp sticker sending through the supported message interface.

## Best Possible Solution

Add a plugin-owned typed `sticker` action that reuses the shipped `sendSticker` helper and initially accepts validated sticker-ready WebP; treat arbitrary static or animated image conversion as a separately sponsored capability after its encoding contract is defined.

## Reproduction Assessment

Yes at source level: the native WhatsApp sticker sender exists and is tested, but the ordinary listener, message-tool descriptor, and channel dispatcher have no sticker entry, so supported callers cannot reach it.

## Solution Assessment

The best narrow solution is an explicit typed WhatsApp sticker action backed by the existing sender. Automatic inference from WebP format, file size, or an empty caption is not the best fix because it creates ambiguous routing and does not establish valid sticker encoding.
