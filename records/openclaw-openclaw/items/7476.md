- `impact:message-loss`: Outbound sticker semantics are lost because the user-facing WhatsApp path can deliver WebP only as generic image media, not as a native sticker payload.

## Summary

Keep open: current main and the latest release still do not expose user-facing outbound WhatsApp sticker sends. A lower-level Baileys sticker helper exists, but normal WhatsApp message sends still route WebP through the generic image path and the WhatsApp action surface does not advertise or handle the shared sticker action.

## What This Changes

Add user-facing WhatsApp sticker sending so sticker media can be delivered as native WhatsApp stickers instead of generic image attachments.

## Best Possible Solution

Have maintainers choose an explicit WhatsApp sticker contract, then implement it in the bundled WhatsApp plugin with Baileys sticker routing, scoped media preservation or encoding, focused docs, and tests.

## Reproduction Assessment

Yes, at source level: current main rejects the WhatsApp sticker action and routes WebP image media through the generic image branch. I did not perform a live WhatsApp send in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract. The implementation belongs in the WhatsApp plugin, and explicit sticker intent is safer than silent WebP heuristics alone.
