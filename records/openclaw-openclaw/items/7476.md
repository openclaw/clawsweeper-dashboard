## Summary

Keep open: current main and v2026.6.11 still lack a user-facing WhatsApp sticker send path. A lower-level Baileys sticker helper exists for QA/runtime internals, but normal WhatsApp message sends still route WebP media through the generic image path and the WhatsApp action surface does not expose `sticker`.

## What This Changes

The issue requests outbound WhatsApp sticker send support instead of treating WebP sticker media as a normal image.

## Best Possible Solution

Add first-class WhatsApp plugin sticker sending with explicit user-facing sticker intent, scoped WebP preservation or encoding, Baileys sticker payload routing, focused docs, and tests for action dispatch plus media payload selection.

## Maintainer Decision

Kind: product_direction

Question: Which public WhatsApp sticker send contract should OpenClaw support: shared `action=sticker`, a WhatsApp send option such as `asSticker`, automatic WebP detection, or a combined explicit-plus-detection path?

Rationale: The source gap is clear, but silent WebP detection can change ordinary image sends and the discussion raises encoding-policy concerns beyond the Baileys payload type.

Likely owner: mcaxtr

Owner reason: mcaxtr has the strongest recent history on lower-level structured WhatsApp send support and adjacent media/quote work.

Owner confidence: medium

Options:

- **Use explicit sticker intent (recommended):** Expose `action=sticker` or an explicit WhatsApp send option and only route media as stickers when that intent is present.
- **Use automatic WebP detection:** Treat qualifying WebP media as stickers by heuristic, accepting the risk that ordinary WebP image sends or malformed sticker assets may be misclassified.
- **Defer channel feature:** Keep inbound sticker support only until a broader cross-channel sticker contract is designed.

## Reproduction Assessment

Yes, at source level: current main still rejects the WhatsApp sticker action and routes `image/webp` media through the generic image branch. I did not perform a live WhatsApp send in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract. The implementation belongs in the WhatsApp plugin, and explicit sticker intent plus scoped media handling is safer than silent WebP heuristics alone.
