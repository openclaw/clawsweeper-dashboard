## Summary

Current main implements a tested Baileys sticker transport primitive, but only the WhatsApp QA driver uses it; the supported message-tool action and ordinary outbound pipeline still cannot send native stickers. This issue remains necessary because maintainers still need to choose whether the public capability validates sticker-ready WebP only or also converts ordinary and animated images.

## What This Changes

Expose outbound WhatsApp stickers through a supported message-tool contract and preserve or convert suitable media for native sticker delivery.

## Best Possible Solution

Expose the established typed `sticker` message action in the WhatsApp plugin, route it to the existing `sendSticker` primitive, and initially accept validated sticker-ready WebP unless maintainers explicitly sponsor static or animated conversion; add action discovery, media-access handling, focused tests, docs, and live WhatsApp proof.

## Solution Assessment

No, the proposed automatic captionless-WebP heuristic is not the best contract because it overloads ordinary image delivery. Reusing the existing typed `sticker` action and keeping validation or conversion inside the WhatsApp plugin is the narrowest maintainable direction.
