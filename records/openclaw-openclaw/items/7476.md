## Summary

Keep open: current main and the latest release still do not expose user-facing outbound WhatsApp sticker sends. A lower-level Baileys sticker helper exists for QA/runtime internals, but normal `message action=send` still routes WebP through the generic image branch and WhatsApp does not advertise or handle the shared `sticker` action.

## What This Changes

Request to add outbound WhatsApp sticker sending support through the message tool or an explicit WhatsApp send option.

## Best Possible Solution

Add first-class WhatsApp plugin sticker sending with explicit sticker intent, Baileys `{ sticker: buffer }` routing, scoped media preservation or encoding, and focused docs plus tests.

## Reproduction Assessment

Yes, at source level: current main still rejects the WhatsApp `sticker` action and routes WebP image media through the generic image branch. I did not perform a live WhatsApp send in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract. The implementation belongs in the WhatsApp plugin, and explicit sticker intent is safer than silent WebP heuristics alone.
