## Summary

Keep open: current main and v2026.6.11 still do not expose a user-facing WhatsApp sticker send path. A lower-level Baileys sticker helper exists, but normal WebP sends still route as image media, WhatsApp message actions still omit `sticker`, and the prior implementation PRs are closed unmerged.

## What This Changes

Add outbound WhatsApp sticker sending so sticker media can be sent as native Baileys sticker messages instead of regular image attachments.

## Best Possible Solution

Add first-class WhatsApp plugin sticker sending with explicit sticker intent, scoped media preservation or encoding policy, Baileys `{ sticker: buffer }` routing, action discovery, docs, and focused tests.

## Reproduction Assessment

Yes, at source level: WhatsApp `sticker` actions are not supported and WebP media still flows through the generic image branch. I did not run a live WhatsApp send in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract. The implementation belongs in the WhatsApp plugin, and explicit sticker intent is safer than silent WebP heuristics alone.
