## Summary

Keep this issue open: current main still cannot express outbound WhatsApp sticker intent through the supported message pipeline, both proposed implementation PRs closed unmerged, and maintainers still need to choose sticker-ready transport versus built-in conversion.

## What This Changes

Add first-class outbound WhatsApp sticker sending through an explicit message action or send option, with suitable WebP handling and Baileys delivery.

## Best Possible Solution

Add explicit sticker intent owned by the WhatsApp plugin, initially transport validated sticker-ready WebP through Baileys `{ sticker: buffer }`, preserve that media from generic image optimization, and cover action discovery, payload selection, validation failures, live static/animated proof, and user documentation; treat arbitrary-image conversion as a separately approved capability.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should WhatsApp sticker support initially transport only caller-supplied sticker-ready WebP, or should OpenClaw also convert arbitrary static and animated images into compliant stickers?

Rationale: The two scopes require different dependencies, validation rules, failure behavior, performance costs, and public guarantees; source inspection cannot establish which product contract maintainers want.

Likely owner: steipete

Owner reason: This person has both recent history on the affected send/media paths and prior maintainer-side engagement on the issue.

Owner confidence: high

Options:

- **Sticker-ready transport (recommended):** Add an explicit sticker action or option that validates and sends caller-supplied sticker-ready WebP without promising image conversion.
- **Full conversion pipeline:** Accept ordinary images and animated inputs, then encode compliant WebP plus required metadata before sending.
- **Keep unsupported:** Leave sticker sending outside the supported WhatsApp action surface until conversion and metadata requirements have a clear owner.

## Reproduction Assessment

Yes at source level: the supported WhatsApp send contract has no sticker intent, generic WebP media follows image handling, and action discovery omits stickers. A fresh live current-main send was not performed during this read-only review.

## Solution Assessment

No, automatic WebP detection alone is not the best solution because it conflates file shape with user intent and does not solve sticker encoding or metadata compatibility. An explicit plugin-owned sticker contract is the safer foundation.
