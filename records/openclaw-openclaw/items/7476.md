## Summary

Keep open: current main and the latest release still lack a user-facing WhatsApp sticker send path. A lower-level `sendSticker` helper exists for QA/runtime internals, but normal WhatsApp message sends still route WebP through the generic image branch and the WhatsApp action surface does not expose `sticker`.

## What This Changes

The issue requests outbound WhatsApp sticker support so WebP sticker media can be sent as stickers instead of regular image attachments.

## Best Possible Solution

Add first-class WhatsApp plugin sticker sending with explicit user-facing sticker intent, scoped WebP preservation or encoding, Baileys sticker payload routing, docs, and focused action/media tests.

Options:

- **Explicit sticker intent (recommended):** Expose `action=sticker` or a WhatsApp-specific send option and route media as stickers only when that intent is present.
- **Automatic WebP detection:** Treat qualifying WebP media as stickers by heuristic, accepting possible misclassification of ordinary WebP images or malformed assets.
- **Defer channel feature:** Keep inbound sticker support only until a broader cross-channel sticker contract is designed.

## Reproduction Assessment

Yes, at source level: current main still rejects the WhatsApp sticker action and routes `image/webp` media through the generic image branch. I did not perform a live WhatsApp send in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract. The implementation belongs in the WhatsApp plugin, and explicit sticker intent plus scoped media handling is safer than silent WebP heuristics alone.
