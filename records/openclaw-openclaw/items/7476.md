## Label Justifications

- `P2`: Outbound WhatsApp sticker support is a normal-priority channel capability gap with limited blast radius.
- `impact:message-loss`: The requested native sticker payload cannot currently be delivered through the WhatsApp message action/send surface.

## Summary

Keep open: current main and the latest release still do not expose a user-facing outbound WhatsApp sticker send path. A low-level WhatsApp `sendSticker` helper exists, but normal message sends still route image media through the generic image payload and the WhatsApp action handler rejects `sticker`.

## What This Changes

The issue requests outbound WhatsApp sticker support so WebP sticker media can be sent as a native WhatsApp sticker instead of a regular image attachment.

## Best Possible Solution

Keep this as the canonical WhatsApp plugin work item and have maintainers choose an explicit sticker send contract plus encoding policy before implementation.

## Reproduction Assessment

Yes at source level for the missing capability: the high-level WhatsApp send path can only pass media through `active.sendMessage`, and the WhatsApp action handler rejects `sticker`. I did not run a live WhatsApp send in this read-only review.

## Solution Assessment

No final solution is selected yet: a low-level sticker helper exists, but maintainers still need to choose the public contract and encoding policy before implementation.
