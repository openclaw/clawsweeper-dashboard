## Summary

Keep open: current main and the latest release still lack a user-facing outbound WhatsApp sticker send path. A low-level Baileys sticker helper exists for QA/runtime internals, but normal message sends still route WebP through the generic image payload and WhatsApp does not advertise or handle the shared sticker action.

## What This Changes

Request outbound WhatsApp sticker support via a dedicated action, explicit send option, or WebP sticker detection.

## Best Possible Solution

Implement this in the bundled WhatsApp plugin with an explicit outbound sticker contract, preserve or prepare sticker media before generic image handling, route sends through Baileys sticker payloads, advertise the action or option consistently, and document/test the accepted sticker media policy.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: action=sticker is not supported by the WhatsApp action surface, and image/webp media reaches the generic image branch. I did not perform a live WhatsApp send in this review.

## Solution Assessment

Unclear until maintainers choose the public contract. The narrowest maintainable direction appears to be an explicit sticker action or send option plus focused media preparation, rather than relying only on implicit WebP auto-detection.
