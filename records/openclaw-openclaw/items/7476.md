## Summary

Keep open: current main and v2026.6.11 still do not provide the user-facing WhatsApp sticker send path requested here. Main now has a lower-level Baileys sticker helper for structured/QA sends, but normal message sends still expose no WhatsApp `sticker` action, no sticker intent option, and WebP media still reaches the public send path as image media.

## What This Changes

The issue requests outbound WhatsApp sticker sending support so sticker WebP files can be delivered as WhatsApp stickers instead of regular image attachments.

## Best Possible Solution

Add an explicit WhatsApp sticker send contract in the bundled WhatsApp plugin, wire it to Baileys sticker payloads, preserve or normalize sticker media before generic image handling, and document/test the chosen encoding behavior.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Which user-facing WhatsApp sticker send contract should OpenClaw support before implementation proceeds?

Rationale: The code can send a low-level sticker payload, but the public API choice affects message-tool semantics, media encoding policy, docs, and compatibility with normal image sends.

Likely owner: steipete

Owner reason: The current implementation and recent review context both route through the WhatsApp send/action surfaces he most recently changed.

Owner confidence: high

Options:

- **Add explicit sticker intent (recommended):** Expose a WhatsApp `sticker` action or explicit sticker flag, require callers to opt in, and add validation/encoding behavior around that contract.
- **Auto-detect sticker WebP sends:** Treat qualifying no-caption WebP image sends as stickers, which is convenient but can surprise users who intended a normal image attachment.
- **Keep helper internal for now:** Leave the QA/runtime helper available but do not expose user-facing sticker sends until the channel action model is revisited.

## Reproduction Assessment

Yes, source inspection reproduces the gap: the WhatsApp action surface omits `sticker`, outbound options have no sticker intent, and `image/*` media goes through image payload handling. I did not run a live WhatsApp send because the source path is already decisive for this feature request.

## Solution Assessment

No, the current lower-level helper is not the best complete solution because it is not reachable from the public message tool or reply pipeline. The maintainable path is an explicit plugin-owned sticker contract plus focused media handling, docs, and tests.
