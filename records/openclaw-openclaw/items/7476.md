## Summary

Keep open: current main and v2026.6.11 still lack a user-facing WhatsApp sticker send path. The code has a lower-level Baileys sticker helper for QA/runtime internals, but normal WhatsApp send/action paths still do not expose sticker intent and WebP image media still routes through generic image delivery.

## What This Changes

Request support for sending native WhatsApp stickers from the bundled WhatsApp plugin instead of delivering sticker WebP files as ordinary images.

## Best Possible Solution

Add first-class WhatsApp plugin sticker sending with explicit sticker intent, scoped WebP preservation or encoding, Baileys sticker payload routing, and focused docs plus tests.

## Reproduction Assessment

Yes, at source level: current main still rejects the WhatsApp sticker action and routes WebP image media through the generic image branch. I did not perform a live WhatsApp send in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract. The implementation belongs in the WhatsApp plugin, and explicit sticker intent plus scoped media handling is safer than silent WebP heuristics alone.
