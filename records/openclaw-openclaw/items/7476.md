## Summary

Keep open: the current public WhatsApp contract still does not advertise outbound sticker delivery, while the only linked implementation PR was closed unmerged; maintainers need to choose the supported plugin/action contract before a bounded fix can proceed.

## What This Changes

The issue requests a supported way to send outbound WhatsApp stickers rather than regular WebP image attachments.

## Best Possible Solution

Have the official WhatsApp plugin expose one explicit, typed outbound sticker intent, preserve only that intent through media preparation, send it through Baileys’ sticker payload, and add focused plugin tests, public docs, and redacted live WhatsApp proof for static and rejected/unsupported media cases.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should the official WhatsApp plugin support outbound stickers through a typed public action or media intent, rather than implicit captionless-WebP detection?

Rationale: The current feature is absent, but choosing between a portable action, a plugin-specific explicit option, and automatic detection defines a lasting plugin/API contract and determines how media validation and backward-compatible image behavior should work.

Likely owner: steipete

Owner reason: Recent ownership spans both the WhatsApp send path and the shared media preparation path that the selected contract must coordinate.

Owner confidence: high

Options:

- **Sponsor an explicit sticker intent (recommended):** Add a typed WhatsApp sticker action or explicit media intent, keep ordinary WebP sends as images by default, and validate the selected contract with live plugin proof.
- **Allow automatic WebP routing:** Treat qualifying captionless WebP media as stickers, accepting the semantic ambiguity and maintaining explicit image escape behavior and encoding rules.
- **Decline official support:** Keep the current image-only behavior and leave any custom sticker workflow to a separately distributed integration.

## Reproduction Assessment

No high-confidence live reproduction was performed in this read-only pass. The current public WhatsApp contract and the prior direct source audit provide a clear source-level path: sticker intent is not advertised or propagated through the outbound send path.

## Solution Assessment

No—the closed automatic-WebP proposal is not the best default solution because it overloads existing image behavior and does not settle sticker validity. A typed plugin-owned intent is the narrower maintainable path once maintainers choose the public contract.
