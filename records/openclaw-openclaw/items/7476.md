## Summary

Keep this issue open. Current main now contains and tests a low-level WhatsApp `sendSticker` sender, but the normal outbound media pipeline still routes WebP through the image path, does not carry sticker intent, and does not advertise a `sticker` message action. The remaining blocker is a product decision between transporting sticker-ready WebP and converting arbitrary static or animated media.

Likely related people: `steipete` is the strongest routing candidate from recent WhatsApp send/media work; `mcaxtr` and `scoootscooob` are also connected through outbound-media and plugin-boundary history.

## What This Changes

Add a supported message-tool path for sending outbound WhatsApp stickers instead of ordinary image attachments.

## Best Possible Solution

Expose an explicit WhatsApp-owned `sticker` message action that loads media without generic image optimization, validates sticker-ready WebP with actionable errors, calls the existing `sendSticker` primitive, and treats arbitrary-media conversion as a separately sponsored capability.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should WhatsApp sticker support transport only sticker-ready WebP, or also convert arbitrary static and animated media into compliant stickers?

Rationale: Both choices are technically viable but define different user promises, dependency needs, failure behavior, metadata handling, and validation scope; source inspection cannot choose that product contract safely.

Likely owner: steipete

Owner reason: Recent WhatsApp send/media history and the existing maintainer-side issue review make this person the strongest available owner for choosing the user-facing contract.

Owner confidence: high

Options:

- **Transport sticker-ready WebP (recommended):** Expose a plugin-owned sticker action that validates and sends already-compliant WebP while returning clear errors for invalid media.
- **Build full sticker conversion:** Accept common image and animation formats and add a standards-compliant conversion pipeline covering static and animated WebP plus required metadata.
- **Keep the primitive internal:** Leave `sendSticker` as a private runtime capability and do not expose outbound sticker support through the message tool.

## Reproduction Assessment

Yes at source level: current main advertises no WhatsApp sticker action, the normal media path treats WebP as an image, and the ordinary send options cannot carry sticker intent. A live current-main WhatsApp run was not performed during this read-only review.

## Solution Assessment

No, implicit detection based on `.webp`, size, or an empty caption is not the best long-term contract. An explicit plugin-owned sticker action using the existing low-level sender is narrower and avoids silently changing ordinary WebP image behavior.
