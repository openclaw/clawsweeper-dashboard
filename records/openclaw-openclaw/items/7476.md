## Summary

Current main only partially addresses the request: WhatsApp has a tested internal Baileys sticker sender, but the supported message-tool surface still does not expose it and ordinary WebP media still follows the image path. The issue remains necessary because maintainers must choose whether the public contract validates caller-prepared sticker files or also converts arbitrary images.

## What This Changes

Add first-class outbound WhatsApp sticker support so explicit sticker sends use WhatsApp sticker messages rather than ordinary image attachments.

## Best Possible Solution

Expose one explicit typed sticker action that loads caller-prepared sticker media, validates the supported WhatsApp format, invokes the existing plugin-owned `sendSticker` primitive, and keeps conversion out of scope unless maintainers deliberately sponsor it.

## Solution Assessment
