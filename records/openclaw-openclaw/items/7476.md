## Summary

Keep open. The supplied current review evidence shows that outbound WhatsApp sends still use the generic image path and do not expose a supported sticker intent, while the only linked implementation PR was closed unmerged. This is a bounded plugin feature, but maintainers need to choose the public action contract before implementation.

## What This Changes

Add supported outbound WhatsApp sticker delivery through OpenClaw’s message tool instead of sending WebP files as ordinary images.

## System Context

The message tool passes outbound media and action intent to the bundled WhatsApp plugin, which prepares media and calls Baileys to deliver a WhatsApp message. Sticker support requires the plugin to preserve intended WebP sticker data and select Baileys’ distinct sticker payload rather than the ordinary image payload.

## Best Possible Solution

Define one explicit WhatsApp plugin sticker-send contract, preserve intended sticker media through preparation, route it to Baileys’ sticker payload, document the contract, and prove static and animated delivery on a real WhatsApp account.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Which stable public WhatsApp message-tool contract should request sticker delivery: a dedicated sticker action or an explicit send option?

Rationale: Both routes require changes across the plugin action contract, media pipeline, documentation, and tests; automatic WebP detection would create a competing implicit behavior and is not justified by the current evidence.

Likely owner: steipete

Owner reason: Recent ownership spans both the WhatsApp send path and shared media preparation where the contract must be carried consistently.

Owner confidence: high

Options:

- **Add explicit sticker intent (recommended):** Add a documented WhatsApp-specific sticker action or explicit send option, then route only that intent through Baileys’ sticker payload.
- **Use automatic WebP detection:** Treat qualifying WebP attachments as stickers, accepting ambiguity with ordinary WebP image attachments and a larger validation burden.
- **Defer the capability:** Leave ordinary WebP image delivery unchanged until maintainers want to support a stable sticker contract.

## Solution Assessment

Unclear until maintainers choose the public intent contract. An explicit sticker action or explicit send option is the narrower maintainable solution; automatic WebP heuristics would silently change ordinary attachment behavior.
