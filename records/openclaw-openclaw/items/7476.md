## Summary

Keep open: current main and v2026.6.11 still do not expose a user-facing WhatsApp sticker send path, even though a low-level QA/structured helper can send a Baileys sticker payload.

## What This Changes

Request to add outbound WhatsApp sticker sending so WebP media or an explicit sticker action/option sends a sticker payload instead of a regular image attachment.

## Best Possible Solution

Add first-class WhatsApp plugin sticker sending with explicit sticker intent, scoped media preservation or encoding, Baileys sticker payload routing, docs, and focused send/action tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Which public WhatsApp sticker-send contract and sticker asset policy should OpenClaw support before implementation?

Rationale: The source gap is clear, but choosing action=sticker, an asSticker-style option, automatic WebP detection, and whether to validate or re-encode sticker assets affects user-visible behavior and compatibility for ordinary WebP image sends.

Likely owner: mcaxtr

Owner reason: mcaxtr has the strongest recent history on the structured WhatsApp send helper and QA driver path that already emit sticker payloads.

Owner confidence: high

Options:

- **Use Explicit Sticker Intent (recommended):** Expose action=sticker or a WhatsApp send option and route media as stickers only when that intent is present.
- **Use WebP Heuristics:** Treat qualifying WebP media as stickers automatically, accepting misclassification and encoding-policy risk for normal WebP images.
- **Defer For Cross-Channel Contract:** Keep the low-level helper and inbound sticker handling while waiting for a broader sticker contract across message channels.

## Reproduction Assessment

Yes, at source level: current main still routes normal image media through the generic image branch and the active listener/action contracts do not expose public sticker send intent. I did not run a live WhatsApp send in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract. The maintainable direction is in the WhatsApp plugin, with explicit sticker intent plus scoped media handling rather than silent WebP heuristics alone.
