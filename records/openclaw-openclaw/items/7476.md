## Summary

Current main contains a tested WhatsApp sticker transport primitive only for the QA driver, while the supported message-tool surface still rejects `sticker` and routes WebP through ordinary image delivery. The issue remains necessary because exposing that primitive requires a maintainer choice on accepted media and conversion scope.

## What This Changes

Expose outbound WhatsApp stickers through the supported message-tool interface instead of limiting sticker sending to QA-driver code.

## Best Possible Solution

Expose the existing generic `sticker` action in the WhatsApp plugin, accept an explicit media source, validate a narrowly documented sticker-ready format, and call the existing `sendSticker` primitive; conversion of common or animated inputs should be separate follow-up work unless maintainers explicitly choose that larger scope.
