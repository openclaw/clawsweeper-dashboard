## Summary

Keep open: current main and the latest release still do not expose a user-facing outbound WhatsApp sticker send path. A lower-level Baileys sticker helper exists, but the normal WhatsApp message action and media send surfaces still reject `sticker` and route WebP image media through the generic image branch.

## What This Changes

Request support for outbound WhatsApp native sticker messages from the message tool, via a sticker action, explicit option, or safe WebP sticker detection.

## Best Possible Solution

Add first-class WhatsApp plugin sticker sending with explicit sticker intent, Baileys `{ sticker: buffer }` routing, scoped media preservation or encoding, and focused docs plus tests.

## Reproduction Assessment

Yes. Source inspection on current main shows `message action=sticker` is unsupported for WhatsApp and WebP image media still flows through the generic image send branch; I did not perform a live WhatsApp send in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract. The implementation belongs in the WhatsApp plugin, and explicit sticker intent is safer than silent WebP heuristics alone.
