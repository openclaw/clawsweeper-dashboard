## Summary

Current main and v2026.6.11 still lack a supported outbound WhatsApp sticker action even though a QA-only Baileys sticker sender now exists. The item remains necessary, but maintainers must decide whether the public contract only sends validated sticker-ready WebP or also converts static and animated source images.

## What This Changes

Add native outbound WhatsApp sticker sending through the message tool, using an explicit sticker action or send option rather than delivering WebP as a regular image.

## Best Possible Solution

Expose a typed WhatsApp sticker action or explicit send option that reuses the existing structured sender; initially validate and send caller-supplied sticker-ready WebP, with image conversion considered separately if maintainers choose to own that broader promise.

Options:

- **Sticker-ready WebP only (recommended):** Add typed sticker intent, validate caller-supplied WhatsApp-compatible WebP, and send it without promising conversion.
- **Convert static images:** Accept common static images and own resizing, WebP encoding, sticker metadata, limits, and validation.
- **Convert static and animated:** Also own animated WebP generation and its distinct chunk, metadata, and size requirements.

## Reproduction Assessment

Yes. Current main and v2026.6.11 show a QA-only sticker transport primitive while the active listener, action discovery, ordinary outbound pipeline, tests, and docs omit supported outbound sticker dispatch; this read-only review did not run a live WhatsApp send.

## Solution Assessment

No, the earlier automatic WebP and empty-caption heuristic is not the best fix. An explicit typed plugin-owned sticker intent is narrower, preserves existing WebP image behavior, and lets validation or conversion semantics be documented and tested deliberately.
