## Summary

Keep open: current main and v2026.6.11 still lack a user-facing outbound WhatsApp sticker-send path, even though a low-level `sendSticker` helper now exists for structured QA/runtime use.

## What This Changes

Request outbound WhatsApp sticker sending support so WebP sticker media can be sent as native stickers instead of regular image attachments.

## Best Possible Solution

Add first-class WhatsApp plugin sticker sending with explicit user-facing sticker intent, scoped media preservation or encoding, Baileys sticker payload routing, focused docs, and tests for action dispatch plus media payload selection.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Which public WhatsApp sticker-send contract and encoding policy should OpenClaw support before implementation?

Rationale: The source gap is clear, but the choice between `action=sticker`, an option such as `asSticker`, automatic WebP detection, and sticker asset validation affects user-facing behavior and compatibility.

Likely owner: mcaxtr

Owner reason: mcaxtr has the strongest recent history on the structured WhatsApp send helper that already knows how to emit a Baileys sticker payload.

Owner confidence: high

Options:

- **Use Explicit Sticker Intent (recommended):** Expose `action=sticker` or an explicit WhatsApp send option and route media as stickers only when that intent is present.
- **Use WebP Heuristics:** Treat qualifying WebP media as stickers automatically, accepting misclassification and encoding-policy risk for ordinary WebP image sends.
- **Defer Channel Feature:** Keep the low-level helper and inbound sticker handling only until a broader cross-channel sticker contract is chosen.

## Reproduction Assessment

Yes, at source level: current main still rejects WhatsApp `action=sticker` through the action gate and routes `image/webp` through the generic image branch. I did not run a live WhatsApp send in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract. The implementation belongs in the WhatsApp plugin, and explicit sticker intent plus scoped media handling is safer than silent WebP heuristics alone.
