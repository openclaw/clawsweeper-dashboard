## Summary

Keep open: current main still lacks a user-facing outbound WhatsApp sticker path. A lower-level WhatsApp `sendSticker` helper exists for structured QA/runtime use, but normal `send` still routes `image/webp` through the generic image payload and WhatsApp does not advertise or support the shared `sticker` action.

## What This Changes

Request outbound WhatsApp sticker sending through the bundled WhatsApp plugin, either as a dedicated sticker action, an explicit send option, or safe WebP sticker detection.

## Best Possible Solution

Implement first-class outbound sticker intent inside the WhatsApp plugin, route it through Baileys `{ sticker: buffer }`, preserve or normalize valid WebP sticker media before generic image handling, and document/test the chosen contract.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: `message action=sticker` is not supported by the WhatsApp action surface, and ordinary WebP media still follows the generic image branch. I did not run a live WhatsApp send in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract and encoding policy. The clean direction is an explicit sticker intent rather than relying only on filename/MIME heuristics, with tests for both public dispatch and payload selection.
