## Summary

Keep open: current main and v2026.6.11 still lack a user-facing outbound WhatsApp sticker-send path; the existing low-level helper is only wired for structured QA/runtime use, while normal WebP sends and message actions do not expose sticker intent.

## What This Changes

The issue asks for outbound WhatsApp sticker sending through the message tool, either as a sticker action, explicit send option, or scoped WebP sticker routing.

## Best Possible Solution

Add first-class WhatsApp plugin sticker sending with explicit user-facing sticker intent, scoped media preservation or encoding, Baileys sticker payload routing, focused docs, and tests for action dispatch plus payload selection.

- **Use Explicit Sticker Intent (recommended):** Expose `action=sticker` or an explicit WhatsApp send option and route media as stickers only when that intent is present.

- **Defer Public Feature:** Keep only the low-level helper and inbound sticker handling until a broader cross-channel sticker contract is chosen.

## Solution Assessment

Unclear until maintainers choose the public contract. The implementation belongs in the WhatsApp plugin, and explicit sticker intent plus scoped media handling is safer than silent WebP heuristics alone.
