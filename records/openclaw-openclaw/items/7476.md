Keep this issue open for a maintainer product-contract decision. The supplied prior review found no supported outbound WhatsApp sticker path and the only linked implementation, https://github.com/openclaw/openclaw/pull/7502, was closed unmerged; the proposed automatic WebP detection would also risk changing ordinary image delivery semantics. Likely related people: Peter Steinberger (recent WhatsApp/media-path contributor, medium confidence) and Marcus Castro (recent outbound-media contributor, medium confidence).

## What This Changes

Add an explicit way for the bundled WhatsApp plugin to send a WebP attachment as a native WhatsApp sticker instead of an ordinary image.

## System Context

The WhatsApp plugin accepts tool-driven outbound media, prepares it through shared web-media handling, and passes a Baileys payload to WhatsApp. The missing decision is how an outbound caller declares sticker intent without changing the existing image-send behavior for WebP files.

## Best Possible Solution

Define one explicit opt-in sticker intent on the existing WhatsApp outbound-media contract, keep default WebP sends as images, validate or clearly document accepted sticker encoding, route the intent to Baileys `{ sticker: buffer }`, and add focused media, payload-selection, action-discovery, and documentation coverage.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should WhatsApp sticker delivery use an explicit opt-in field on normal sends, or should OpenClaw introduce a distinct cross-channel sticker action?

Rationale: This is a new public messaging capability, and choosing automatic detection versus an explicit flag/action determines compatibility, tool semantics, validation, and whether other channel adapters must share the contract.

Likely owner: steipete

Owner reason: The available history summary places this person on both the WhatsApp outbound path and the shared media boundary affected by the contract choice.

Owner confidence: medium

Options:

- **Use explicit send intent (recommended):** Add a WhatsApp-owned explicit sticker option so existing WebP image sends remain unchanged while callers deliberately request native sticker delivery.
- **Add a portable action:** Introduce a typed cross-channel sticker action only if maintainers want a shared channel capability with consistent semantics beyond WhatsApp.
- **Decline bundled support:** Keep the plugin image-only and direct this capability to a separately maintained WhatsApp extension if bundled-channel scope should remain narrower.
