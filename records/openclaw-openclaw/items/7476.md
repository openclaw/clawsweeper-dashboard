## Summary

Keep open: current main and v2026.6.11 still lack a public outbound WhatsApp sticker-send path; the low-level helper can build a Baileys sticker payload, but normal WebP sends, action discovery, and docs do not expose sticker delivery.

## What This Changes

Request outbound WhatsApp sticker sending so WebP media or explicit sticker intent is delivered as a WhatsApp sticker instead of a generic image attachment.

## Best Possible Solution

Add first-class WhatsApp plugin sticker sending with explicit user-facing sticker intent, scoped media preservation or re-encoding, Baileys sticker payload routing, docs, and focused action/send-path tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Which public WhatsApp sticker-send contract and sticker asset policy should OpenClaw support before implementation?

Rationale: The source gap is clear, but choosing between `action=sticker`, an explicit send option, automatic WebP detection, and optional re-encoding affects user-visible behavior and compatibility for normal WebP image sends.

Likely owner: mcaxtr

Owner reason: mcaxtr has the strongest recent history on the structured WhatsApp send helper and adjacent outbound media path that would carry the chosen contract.

Owner confidence: medium

Options:

- **Use explicit sticker intent (recommended):** Expose `action=sticker` or an explicit WhatsApp send option and only route media as stickers when that intent is present.
- **Use automatic WebP detection:** Treat qualifying WebP media as stickers by heuristic, accepting the risk that ordinary WebP image sends or malformed sticker assets may be misclassified.
- **Defer channel feature:** Keep inbound sticker support only until a broader cross-channel sticker contract is designed.

## Reproduction Assessment

Yes, at source level: current main still routes normal `image/*` sends through the generic image branch and the public WhatsApp action/listener contracts do not expose sticker sending. I did not run a live WhatsApp device send in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public contract. The implementation belongs in the WhatsApp plugin, and explicit sticker intent plus scoped media handling is safer than silent WebP heuristics alone.
