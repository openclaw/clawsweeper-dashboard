## Summary

Keep open: this targets a real Discord default-account env fallback bug, but the branch is not merge-ready because it changes credential fallback semantics in one runtime resolver while sibling inspect/setup and SecretRef runtime surfaces still treat the same blank default-account token as missing or inactive.

## What This Changes

The PR changes Discord token resolution so a blank `accounts.default.token` falls through to top-level `channels.discord.token` or `DISCORD_BOT_TOKEN`, with five added resolver tests.

## Best Possible Solution

Decide the blank default-account token compatibility rule, then apply it consistently across resolver, inspect/setup, SecretRef runtime assignment, docs/tests, and redacted live gateway or REST proof before merge.
