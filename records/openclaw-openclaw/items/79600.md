## Summary

Keep open: current main and the latest release still have the reported Discord default-account blank-token short-circuit, but this PR is not merge-ready because it changes only the resolver while SecretRef materialization and setup/status inspectors still preserve the old blank-token invariant, and no real gateway proof is provided.

## What This Changes

The PR changes Discord default-account token resolution so blank `accounts.default.token` can fall through to `channels.discord.token` or `DISCORD_BOT_TOKEN`, with resolver tests for that behavior.

## Best Possible Solution

Land one Discord default-account credential invariant across resolver, SecretRef runtime materialization, setup/status/doctor inspection, and tests, with maintainer-approved blank-token upgrade behavior and redacted real behavior proof.

Yes. Source inspection of current main shows `accounts.default.token: ""` returns `missing` before top-level config or `DISCORD_BOT_TOKEN` fallback; I did not run a live gateway in this read-only review.

## Solution Assessment

No. The resolver change is a plausible mitigation, but the best fix needs the same fallback invariant across SecretRef runtime assignment and sibling inspection/status paths plus an explicit compatibility decision for blank default-account tokens.
