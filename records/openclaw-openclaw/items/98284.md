## Summary

This PR should stay open for maintainer/security review. The branch is a focused current-path fix for the managed-browser cookie-loss bug, and I found no new line-level correctness blocker, but defaulting new macOS headless managed profiles to Chromium's mock keychain is a security/session-state product decision that automation should not accept alone.

## What This Changes

The PR adds graceful CDP `Browser.close` shutdown before signal fallback, records a mock-keychain marker for new macOS headless managed profiles, preserves existing profile keychain choices, and updates focused browser tests.

## Best Possible Solution

Land the Chrome-profile-only fix after a browser/security owner accepts the mock-keychain default and the marker-based upgrade behavior, then close the linked cookie-loss issue after merge.
