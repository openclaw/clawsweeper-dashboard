## Summary

Keep open: current main has partial OAuth/status/cooldown mitigations, but it still does not implement the default Codex/OpenAI auth-profile incident behavior requested here, and the latest discussion adds v2026.6.11 evidence that stale shared OAuth profiles can still burn through the fallback chain and lose cron output.

## What This Changes

The issue asks OpenClaw to treat repeated Codex/OpenAI OAuth refresh failures as auth-profile incidents with clearer operator alerting, faster quarantine/rotation, safer profile recovery, and less chance of wedged agents or lost channel/cron output.

## Best Possible Solution

Define a maintainer-approved Codex/OpenAI auth-profile incident model that distinguishes transient refresh slowness from hard token failure, quarantines or rotates broken profiles by default, releases channel/cron state cleanly, and exposes redacted operator status plus a safe profile-removal or reauth path.

## Reproduction Assessment

Yes. Source inspection shows the current Codex app-server refresh path still forces OAuth refresh under an upstream 10s callback deadline, and live issue comments reproduce the broader stale-profile/fallback-chain behavior through v2026.6.11.

## Solution Assessment

No automated one-shot fix is best yet. The remaining behavior crosses auth failure classification, default quarantine duration, redacted status/incident UX, channel/session cleanup, and API-key fallback policy, so maintainers should settle the product contract before implementation.
