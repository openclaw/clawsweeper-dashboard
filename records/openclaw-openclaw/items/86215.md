## Summary

Keep open: current main has useful partial mitigations, including merged PR #99134 and profile cooldown/disable handling, but source and recent issue evidence still show the central Codex/OpenAI OAuth wedging problem is unresolved.

## What This Changes

The issue asks OpenClaw to recover more aggressively and alert more clearly when Codex/OpenAI OAuth refresh failures wedge an agent or profile for extended periods.

## Best Possible Solution

Define one default OpenAI/Codex auth incident model that distinguishes transient refresh failures from hard auth breakage, rotates or quarantines profiles safely, cleans up stuck sessions, and exposes redacted operator guidance through status/doctor surfaces.

## Reproduction Assessment

Yes at source level: current main still forces Codex app-server OAuth refresh and bypasses cached-token reuse, while the default skip cache is disabled; I did not run a live current-main OAuth outage reproduction.

## Solution Assessment

No single automated patch is clearly best yet; maintainers need to choose the permanent auth-quarantine, forced-refresh, fallback, alerting, and cleanup semantics before implementation.
