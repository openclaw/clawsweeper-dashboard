## Label Justifications

- `P1`: Multiple release reports show real agents, cron jobs, and channels losing or delaying replies because OpenAI/Codex auth-profile failures are retried or hidden rather than contained.
- `impact:auth-provider`: The central failure is OpenAI/Codex OAuth profile refresh, auth order, credential selection, cooldown, and fallback routing.
- `impact:message-loss`: The issue includes cron outputs and channel-originated replies failing before delivery when stale profiles consume the fallback chain.
- `impact:session-state`: Several reports describe stuck or wedged agent/channel sessions after auth refresh or fallback failures.

## Summary

Keep open: current main has useful partial fixes for OAuth refresh classification, cooldown ordering, reauth copy, and profile-state skipping, but the latest stable-release evidence still reports repeated expired OpenAI OAuth profiles causing cron/message failures, and current source does not implement the requested durable profile/provider incident policy or operator-visible alerting.

## What This Changes

The issue requests clearer reporting and stronger containment for repeated Codex/OpenAI OAuth refresh or profile failures so affected agents and channels do not keep retrying stale auth paths silently.

## Best Possible Solution

Define an owner-approved auth-profile incident policy that classifies durable refresh failures, persists bounded profile/provider quarantine, rotates to valid profiles, surfaces redacted operator/channel/cron status, and leaves profile removal, channel reauth, and Codex probe details to focused linked work.

## Reproduction Assessment

Yes at source level: current code shows only partial cooldown/order/skip/reply handling, while issue comments through stable 2026.6.11 provide live evidence of repeated stale-profile retries and message failures; I did not run a live OAuth failure reproduction in this read-only pass.

## Solution Assessment

No single automated patch is clearly best yet; PR #99134 is a good partial fix, but the durable solution needs maintainer policy for hard-auth classification, quarantine duration, status redaction, and recovery boundaries across linked issues.
