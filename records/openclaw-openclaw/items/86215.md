## Summary

Keep open: current main has partial OAuth-refresh mitigations, but the central Codex auth-profile wedge remains source-reproducible and the latest 2026.6.11 issue evidence still reports expired profiles exhausting fallback before valid profiles.

## What This Changes

The issue asks OpenClaw to classify repeated Codex OAuth refresh failures as auth-profile incidents, alert operators, quarantine or rotate failed profiles more aggressively, and avoid wedging agent/channel/cron runs.

## Best Possible Solution

Define a maintainer-approved Codex/OpenAI auth-profile incident model that reuses valid tokens where safe, quarantines hard-failed profiles, rotates across valid profiles, clears affected run/session state, and exposes redacted operator status and reauth guidance.

## Reproduction Assessment

Yes. Current source still routes Codex app-server auth refresh through a forced-refresh path while upstream Codex waits only 10 seconds, and recent production comments show the same failure family on 2026.6.11.

## Solution Assessment

No current implementation is complete. PR 99134 fixed a narrower false-green fallback path, but the broader default auth-profile quarantine, operator alerting, profile cleanup, and session recovery behavior still needs maintainer direction.
