## Summary

Keep open: current main has useful partial mitigations, including the merged false-green OAuth refresh fix, but the broader Codex/OpenAI auth-profile incident is still not fully handled across forced Codex app-server refresh, durable profile quarantine/rotation, operator-visible status, session cleanup, and safe recovery paths.

## What This Changes

The issue requests stronger handling for Codex/OpenAI OAuth refresh failures so agents, cron jobs, and channels do not stay wedged silently and can rotate or quarantine failing auth profiles.

## Best Possible Solution

Keep this issue open as the canonical Codex/OpenAI auth incident until OpenClaw has default-safe managed OAuth handling that reuses valid tokens when appropriate, quarantines broken profiles, rotates across usable profiles, releases channel/cron session state, and surfaces redacted operator recovery guidance.

## Reproduction Assessment

Yes, at source level. Current main still sends forced Codex app-server OAuth refreshes through a path whose upstream callback deadline is 10 seconds, and the issue has multiple live reports through v2026.6.11 showing the same auth/profile failure family.

## Solution Assessment

No, the issue is not fully solved yet. Current main contains partial mitigations, but the best fix needs a maintainer-approved auth incident model covering refresh semantics, quarantine/rotation defaults, status surfacing, session cleanup, and recovery commands.
