## Summary

Keep open: current main has useful OAuth refresh failure classification, profile cooldown, and opt-in fallback-skip mitigations, but it still does not provide the requested default hard auth-profile quarantine, aggressive valid-profile rotation, profile removal/recovery UX, or durable operator-visible incident/status path; the July 4 v2026.6.11 report shows the central failure family still affecting cron and shared OpenAI OAuth setups.

## What This Changes

The issue asks OpenClaw to classify repeated Codex/OpenAI OAuth refresh failures as auth-profile incidents, alert operators, quarantine bad profiles/provider paths sooner, and rotate across valid profiles instead of wedging agents or channels for hours.

## Best Possible Solution

Define a maintainer-approved OpenAI/Codex auth-profile incident model that safely reuses valid tokens, distinguishes transient refresh slowness from hard auth failure, quarantines or rotates broken profiles by default, exposes redacted operator status/doctor recovery, and releases channel/cron/session state cleanly.

## Reproduction Assessment

Yes at source level: current code still forces Codex app-server OAuth refresh into Codex's 10-second external-auth deadline, and default fallback suppression remains opt-in and non-primary scoped while recent released-build comments show the same failure family persists.

## Solution Assessment

No current-main solution is complete; existing mitigations are partial, and the best fix needs maintainer decisions on auth quarantine defaults, token reuse, profile cleanup, operator status, and channel/session recovery.
