## Label Justifications

- `P1`: The issue affects real cron and channel agent workflows that can fail before producing replies or silently degrade during OpenAI/Codex auth failures.
- `impact:auth-provider`: The central failure is OpenAI/Codex OAuth refresh, auth profile ordering, stale profile handling, and API-key versus OAuth route selection.
- `impact:session-state`: Reports include wedged or stale running channel sessions and per-agent auth-store drift after refresh failures.
- `impact:message-loss`: Reports include missed cron outputs and Discord, Telegram, and WebChat runs failing or staying silent before a user-visible reply.

## Summary

Keep open: current main has useful mitigations, including longer OAuth refresh timeouts and a merged false-green refresh fix, but the central default quarantine/rotation and operator-visible incident behavior is still missing and fresh v2026.6.11 evidence reports repeated expired OpenAI OAuth profile attempts, cron failure, and missing profile removal.

## What This Changes

The issue asks OpenClaw to classify repeated Codex/OpenAI OAuth refresh failures as auth-profile incidents, alert operators, quarantine or rotate broken profiles, and avoid wedged sessions or missed replies.

## Best Possible Solution

Define a default OpenAI/Codex auth-profile incident model that quarantines hard failures, safely reuses or rotates valid profiles, exposes redacted operator status, and offers an in-product or CLI recovery path for stale profiles.

## Reproduction Assessment

Yes. Source-level reproduction is high confidence because current main still defaults to retrying auth-failed fallback candidates unless an env opt-in is set, and live comments document the same failure family through v2026.6.11.

## Solution Assessment

No automated fix path is best yet; the durable fix crosses auth quarantine defaults, operator incident UX, stale-profile deletion, safe cross-agent token adoption, and API-key fallback policy.
