## Summary

Keep open: current main has partial mitigations and PR #99134 fixed one false-green OAuth fallback path, but the broader Codex/OpenAI auth-profile incident remains reproducible from source and has fresh 2026.6.11 production evidence.

## What This Changes

The issue asks OpenClaw to classify repeated Codex/OpenAI OAuth refresh failures as an operator-visible auth-profile incident, quarantine or rotate broken profiles, and avoid wedged or silent agent/channel failures.

## Best Possible Solution

Keep #86215 open until maintainers define and implement a default OpenAI/Codex auth-profile incident model covering refresh timeout handling, profile quarantine/rotation, visible status, stale-profile cleanup, and session/channel recovery.

## Reproduction Assessment

Yes. Source-level reproduction is high confidence because current main still routes Codex app-server refresh callbacks through forced OAuth refresh while upstream Codex waits only 10 seconds, and recent issue comments show the failure on shipped 2026.6.x builds.

No complete current fix exists. #99134 fixed one stale external-credential false-green path, but the remaining incident model spans auth policy, fallback defaults, status/doctor recovery, stale profile management, and channel/session cleanup.
