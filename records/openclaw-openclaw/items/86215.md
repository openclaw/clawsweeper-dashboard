## Summary

Keep open: the merged OAuth false-green fix addressed one stale external-credential subcase, but current main still lacks the requested default auth-profile quarantine/rotation, clear operator incident/status surfacing, and safe stale-profile cleanup; a July 4, 2026 report against v2026.6.11 still shows expired OpenAI OAuth profiles retried ahead of valid profiles.

## What This Changes

The issue requests aggressive handling for repeated Codex/OpenAI OAuth refresh failures, including auth-profile incident classification, profile quarantine/rotation, operator alerting, session recovery, and stale-profile cleanup.

## Best Possible Solution

Design one maintainer-approved auth-profile incident model that fails visibly, quarantines or rotates invalidated profiles by default, exposes redacted status and cleanup through existing models/doctor surfaces, and coordinates with the open quarantine and auth-remove work.

## Reproduction Assessment

Yes at source level and through recent reports: upstream Codex enforces the 10 second external-auth refresh deadline, current OpenClaw only has partial/default-off skip behavior, and the July 4, 2026 v2026.6.11 report still shows stale OAuth profiles retried before valid ones.

## Solution Assessment

No current fix is complete: PR #99134 is a useful partial repair, but the best fix needs a coordinated auth-profile incident, quarantine, status, and cleanup design rather than another isolated retry tweak.
