## Summary

Keep open. Current main has partial OAuth refresh classification, reauth hints, profile cooldowns, and opt-in retry suppression, but it does not prove the reported Codex/OpenAI auth-profile wedge fixed; fresh 2026.6.11 evidence still shows expired profiles retried before cron/message failure and recovery requiring manual auth ordering or profile cleanup.

## What This Changes

The issue asks OpenClaw to treat repeated Codex/OpenAI OAuth refresh failures as auth-profile incidents with visible operator status, faster profile quarantine/rotation, and clean channel/cron session recovery.

## Best Possible Solution

Define a maintainer-approved Codex/OpenAI auth incident policy that distinguishes transient refresh contention from hard invalidation, quarantines stale profiles by default, exposes redacted status/doctor guidance, and releases affected channel/cron sessions without manual store edits.

## Reproduction Assessment

Yes at source level: current main shows opt-in/session-local repeat-auth suppression plus profile-state-driven cooldown skipping, while live reports through v2026.6.11 show the observable wedge; I did not run a live OAuth failure reproduction in this read-only pass.

## Solution Assessment

No single current implementation fully solves it; the merged reauth-hint fix and open auth-remove/status/circuit-breaker work address subcases, but the durable incident/quarantine/rotation contract still needs maintainer direction.
