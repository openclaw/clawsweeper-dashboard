## Summary

Keep open: current main has meaningful mitigations, including fail-closed external fallback after managed OpenAI refresh failure and profile cooldown skips, but the central Codex/OpenAI OAuth wedge remains live because repeat auth skip is still opt-in/default-off, primary candidates are still attempted, Codex app-server refresh is still forced through a 10s upstream callback, and recent 2026.6.11 issue evidence still reports expired OAuth profiles burning fallback budget and losing cron output.

## What This Changes

The issue requests clearer Codex/OpenAI OAuth refresh failure classification, profile quarantine or removal, aggressive rotation to valid profiles, operator-visible incident/status reporting, and clean recovery from wedged agent/channel sessions.

## Best Possible Solution

Define a maintainer-approved Codex/OpenAI auth incident model that quarantines or removes dead profiles by default, rotates to valid profiles without manual order surgery, surfaces redacted operator status, releases stuck channel/cron sessions, and keeps cost-bearing API-key fallback explicit.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: current main still forces Codex app-server OAuth refresh through the 10s upstream callback and leaves repeat auth suppression default-off, while the issue has current stable-release reports of the same failure family.

## Solution Assessment

No, current main is not the complete fix: #99134 and cooldown/skip paths are useful partial mitigations, but the best solution still requires maintainer-owned default quarantine, rotation, status, session cleanup, and fallback-policy decisions.
