## Summary

This bounded timer-lifecycle repair appears correct and remains necessary because current `main` still uses the timeout promise that is not cancellable after an early wake. The PR has focused waiter and realtime-caller coverage plus direct Node event-loop evidence; it should stay open for the two in-progress required Node check lanes and maintainer merge review.

## What This Changes

The PR gives each pending meeting-audio pull an owned timeout handle and clears it when audio arrival or shutdown wakes the long poll early.

## System Context

Meeting audio transport repeatedly asks a node host for audio using a short long-poll. The node host’s waiter set resolves those polls when data or shutdown arrives, then returns the result to the realtime audio transport.
