## What This Changes

Fix intermittent Telegram inbound-message loss where long polling consumes an update but the user receives no agent dispatch or reply.

## System Context

Telegram long polling receives Bot API updates, hands them to durable ingress storage, then applies replay/deduplication and dispatches eligible messages into an agent session. A failure or unexplained completion at any handoff can make a Telegram message appear sent while never reaching the agent.

  B --> C[Durable ingress handoff]
  C --> D[Offset persistence]
  C --> E[Ingress claim and replay checks]
  E --> F[Agent message dispatch]
  F --> G[Telegram reply]
  E --> H[Skip or failure reason telemetry]

## Best Possible Solution

Keep this issue as the focused tracker for the no-ingress/no-spool signature, land or replace the scoped fixes only with their stated guarantees, and add one bounded regression harness that records a terminal reason for every polled Telegram update from durable handoff through dispatch or skip.
