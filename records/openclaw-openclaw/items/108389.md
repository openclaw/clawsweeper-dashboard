## Summary

Keep open: the reported runaway-loop path is credible, but this patch allows `flush()` to resolve without proving the pending draft was drained, and its test never exercises concurrent refilling or the new limit.

## What This Changes

The PR caps each draft-stream flush at 50 loop iterations and adds a test that performs 100 sequential update-and-flush cycles.

## Best Possible Solution

Serialize draft draining behind one flush promise, yield after a bounded batch, and continue or reschedule until pending text is drained so explicit `flush()` and finalization retain completion semantics.
