## Summary

Keep open: the PR is a useful, focused fix direction with real HTTP proof, but it is not merge-ready because the fallback can persist vectors under a mismatched configured dimension identity and reset-style fetch failures still bypass the new retry path.

## What This Changes

The PR retries OpenAI-compatible embedding requests without `dimensions` after HTTP rejection and extends optional non-local provider degradation to FTS-only fallback after persistent failures.

## Best Possible Solution

Keep the provider-adapter retry shape, but make fallback vectors dimension-consistent or fail/degrade before persistence, and catch thrown reset errors so both stated failure modes use the same one-time no-dimensions retry.
