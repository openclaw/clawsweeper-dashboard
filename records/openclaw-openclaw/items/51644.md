## Summary

Keep open: current main and v2026.6.11 cover fixed same-sender inbound debounce, but semantic long-message splitting and adaptive/user-paced aggregation are still unresolved product and API work.

## What This Changes

The issue requests semantic inbound preprocessing that merges rapid short message bursts, splits or structures long multi-topic inputs, and optionally adapts the aggregation window to user cadence.

## Best Possible Solution

Keep fixed inbound debounce as the baseline, let narrower trackers own adaptive timing and Telegram bundle metadata, and require maintainer-approved generic ingress semantics before semantic topic splitting.
