## Summary

Keep open: current main and v2026.6.11 already provide fixed same-sender inbound debounce, but the requested semantic long-message splitting and adaptive aggregation remain product/API work rather than implemented behavior or a fully covered duplicate.

## What This Changes

The issue requests semantic inbound message preprocessing that can merge rapid short-message bursts, split or structure multi-topic long messages, and eventually adapt the aggregation window to user cadence.

## Best Possible Solution

Keep fixed inbound debounce as the baseline, let maintainers choose one opt-in generic session-ingress design for adaptive timing and any semantic topic handling, and preserve metadata/docs/tests before implementation.
