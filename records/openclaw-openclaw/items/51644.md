## Summary

Keep open: current main and v2026.6.11 implement fixed same-sender inbound batching, but the requested semantic topic splitting and adaptive turn-shaping still need maintainer product/API decisions.

## What This Changes

The issue requests semantic inbound message preprocessing that merges rapid-fire short messages, splits or structures long multi-topic messages, and optionally adapts the aggregation window to user cadence.

## Best Possible Solution

Keep the shipped fixed-window batching baseline, use https://github.com/openclaw/openclaw/issues/57123 for adaptive timing and https://github.com/openclaw/openclaw/issues/87002 for Telegram bundle metadata, and design any semantic topic-splitting as an opt-in generic session-ingress contract before implementation.

## Reproduction Assessment

Not applicable: this is a feature request for new semantic/adaptive preprocessing rather than a bug in documented current behavior. Source, docs, and v2026.6.11 confirm current behavior is fixed same-sender debounce.

## Solution Assessment

No for immediate implementation: fixed same-sender batching is already the baseline for rapid short messages, but semantic splitting and adaptive timing need separate maintainer product/API choices before a maintainable fix can be judged best.
