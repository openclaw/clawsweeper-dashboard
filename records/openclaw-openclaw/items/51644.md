## Summary

Keep open: current main and v2026.6.11 cover fixed same-sender text debounce, but semantic long-message splitting, adaptive timing, and the permanent turn-shaping policy remain unresolved product/API work.

## What This Changes

The issue requests a semantic inbound preprocessing layer that batches rapid short messages, splits or structures multi-topic long messages, and optionally adapts the timing window per user behavior.

## Best Possible Solution

Keep fixed inbound debounce as the baseline, let the narrower adaptive and marker issues own their subproblems, and require a maintainer-approved generic ingress/metadata design before semantic topic splitting is implemented.

- **Move Semantics Behind Plugin/API Seam:** Defer semantic splitting until a typed plugin or channel ingress hook can implement it without growing global message config directly.
