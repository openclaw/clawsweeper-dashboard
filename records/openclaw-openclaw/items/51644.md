## Summary

Keep open: current main and the latest release cover fixed same-sender inbound debounce, but semantic long-message splitting, adaptive timing, and explicit turn-shaping policy remain unresolved product/API work rather than an implemented feature.

## What This Changes

The issue requests a semantic inbound preprocessing layer that batches rapid short messages, splits or structures multi-topic long messages, and optionally adapts timing to user cadence.

## Best Possible Solution

Keep fixed inbound debounce as the baseline, let the narrower adaptive and marker issues own their subproblems, and require a maintainer-approved generic ingress/metadata design before semantic topic splitting is implemented.

- **Move Semantics Behind Plugin/API Seam:** Defer semantic splitting until a typed plugin or channel ingress hook can implement it without growing global message config directly.
