## Summary

Keep open: current main and v2026.6.11 implement fixed same-sender text debounce, but semantic long-message topic splitting and adaptive timing remain unimplemented product/API work.

## What This Changes

Request semantic inbound turn shaping that can merge rapid short message bursts, split or structure long multi-topic messages, and optionally adapt timing per user cadence.

## Best Possible Solution

Keep the fixed inbound debounce baseline, route adaptive timing to https://github.com/openclaw/openclaw/issues/57123, route Telegram bundle metadata to https://github.com/openclaw/openclaw/issues/87002, and decide semantic topic splitting as an opt-in session-ingress/API design before implementation.

## Reproduction Assessment

Not applicable: this is a feature request for new semantic/adaptive preprocessing rather than a bug in documented current behavior. Source and docs confirm current behavior is fixed same-sender debounce.

## Solution Assessment

Unclear for implementation: fixed same-sender batching is already the right baseline for rapid short messages, but semantic splitting and adaptive timing need separate product/API choices before a maintainable fix can be judged best.
