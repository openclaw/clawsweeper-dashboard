## Summary

Keep open: current main and the latest release already cover fixed same-sender inbound debounce, but semantic long-message splitting and adaptive timing remain unresolved product/API work.

## What This Changes

Request semantic preprocessing for inbound chat messages: merge rapid short-message bursts, optionally split multi-topic long messages, and adapt aggregation timing.

## Best Possible Solution

Keep fixed inbound debounce as the baseline, route adaptive timing and Telegram bundle metadata through narrower trackers, and decide semantic topic splitting as an opt-in generic ingress or plugin API contract before implementation.

Not applicable: this is a feature request, not a broken documented behavior. Source, docs, tests, and v2026.6.11 show current OpenClaw has fixed same-sender inbound debounce but not semantic/adaptive preprocessing.
