## Summary

Keep open: current main and the latest release still misclassify provider-prefixed Gemini 2.x model ids as supporting multimodal functionResponse, so the image-turn fallback remains disabled and no open PR owns the fix.

## What This Changes

The issue requests fixing Google/Gemini capability detection so provider-prefixed Gemini 2.x ids keep image tool results out of functionResponse and preserve the separate image-turn fallback.

## Best Possible Solution

Make the Gemini major-version capability check prefix-tolerant in the bundled Google transport and the sibling `packages/ai` converter, then add provider-prefixed Gemini 2.x image tool-result regression coverage.
