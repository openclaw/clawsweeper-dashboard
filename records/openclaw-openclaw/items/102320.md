## Summary

Keep open: current main and the latest release still use an anchored Gemini major-version check, and https://github.com/openclaw/openclaw/pull/102327 is now the active open fix candidate with closing syntax, so this issue should remain open until that PR lands or is replaced.

## What This Changes

The issue asks for provider-prefixed Gemini 2.x ids to be classified like bare Gemini 2.x ids so image tool-results use the separate image-turn fallback instead of multimodal functionResponse parts.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/102327, or a replacement that aligns both Google converters with segment-aware Gemini major-version detection and request-shape proof, then close this issue as implemented.

Yes, source-level. Current main's regex only matches ids starting with `gemini`, while the affected model id can remain `google/gemini-2.5-pro` until URL construction, so image tool results can be embedded in `functionResponse.parts` and the fallback skipped.

## Solution Assessment

Yes for the issue direction, but the fix is not yet on main. The maintainable solution is a segment-aware Gemini major-version parser applied to both Google converter paths with regression/request-shape proof.
