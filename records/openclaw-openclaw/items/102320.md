## Summary

Keep open: current main and the latest release still have the provider-prefixed Gemini 2.x capability bug, but the issue now has open closing PRs, with https://github.com/openclaw/openclaw/pull/102382 the stronger canonical fix candidate.

## What This Changes

The issue reports that provider-prefixed Gemini 2.x ids are misclassified as supporting multimodal functionResponse, causing image tool-result media to be embedded in an unsupported Google request shape instead of using the image-turn fallback.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/102382 as the canonical two-surface fix, then close this issue and retire the weaker duplicate PR.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Source inspection and a read-only regex probe show current main misses `google/` and `models/` prefixed Gemini 2.x ids, and the request builder uses that result to embed image tool results in `functionResponse` instead of emitting the fallback turn.

## Solution Assessment

Yes. The narrowest maintainable fix is a segment-aware Gemini major-version parser applied to both Google conversion paths with request-shape regression tests; https://github.com/openclaw/openclaw/pull/102382 is the best current candidate.
