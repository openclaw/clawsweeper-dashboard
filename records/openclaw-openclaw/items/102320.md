## Summary

Keep open: current main and the latest release still have the provider-prefixed Gemini 2.x capability bug, and the open fixing PR is only a candidate until it merges.

## What This Changes

The issue asks for provider-prefixed Gemini 2.x ids to be classified like bare Gemini 2.x ids so image tool results use the separate image-turn fallback instead of `functionResponse.parts`.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/102327 or an equivalent narrow fix that aligns both Google converters on a segment-aware Gemini version parser with request-shape regression proof.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Source inspection shows `google/gemini-2.5-pro` misses the anchored Gemini parser, so the Google converter embeds image tool-result media in `functionResponse.parts` and skips the separate image turn.

## Solution Assessment

The best fix is a small prefix-aware, segment-bounded Gemini major-version parser applied to both Google converter implementations with focused request-shape coverage; the open PR is the current candidate fix path.
