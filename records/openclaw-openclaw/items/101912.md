## Summary

Keep this PR open, but it is not merge-ready: the new Android management flow writes only provider catalog entries while its refresh path reads the existing configured model view, which current docs and tests say is driven by `agents.defaults.models` when an allowlist exists. Real after-fix Android/Gateway behavior proof is also still missing.

## What This Changes

The PR adds Android Settings UI for viewing, testing, adding, and removing configured provider models plus two Gateway RPCs that write model entries into source config.

## Best Possible Solution

- **Keep provider-catalog-only management:** Keep the new RPCs scoped to `models.providers`, but change the UI/list source so allowlist-backed rows are not presented as removable provider config.

## Reproduction Assessment

Yes, source-reproducible: current docs/tests show `models.list view: "configured"` chooses `agents.defaults.models` when present, while the PR writes only `models.providers`. An allowlist-backed setup can therefore save or remove through Android without changing the refreshed visible model list.

## Solution Assessment

No. The provider-only write path is too narrow for the configured-view caller; the maintainable fix is to align the write target with the source that the screen reads, or explicitly scope the UI to provider catalog rows only.
