## Summary

The PR remains necessary and contains substantial correct rollback/CAS work, but it is not merge-safe as a standalone security fix: both final macOS execution routes still reconstruct the approval snapshot from current policy instead of receiving the policy that authorized the delayed run. The protected maintainer label also requires explicit human handling.

## What This Changes

The PR adds compare-and-swap exec-policy persistence and rollback, introduces a canonical persisted-policy snapshot in the Gateway protocol, and carries that snapshot through CLI, Gateway, node-host, and macOS authorization code.

## Best Possible Solution

Define the approval-time snapshot once in the shared wire contract, transport it through both macOS request types, and require every final privileged execution owner to compare it immediately before commit or spawn; land the complete boundary atomically with redacted live revocation proof.
