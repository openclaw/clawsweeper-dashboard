## Summary

Keep open. Current main fixes the shared outbound, durable message send, and original Telegram direct-reply slices, but Gateway/WebChat/TUI final events and plugin/native self-delivered sends still bypass canonical outbound sent-hook observation, and the open related PRs only cover slices.

## What This Changes

Request consistent `message:sent` and `message_sent` hook coverage across outbound dispatch paths so downstream hooks and plugins observe delivered assistant replies.

## Best Possible Solution

Define one shared exactly-once outbound lifecycle observer/reporting contract, or explicitly split the remaining Gateway/TUI/native-channel slices into canonical issues with parity tests and documented hook semantics.
