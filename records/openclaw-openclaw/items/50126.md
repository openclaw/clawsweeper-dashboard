## Label Justifications

- `P2`: The issue is a real outbound lifecycle-hook correctness bug with audit, delivery-observability, and security implications, but visible message delivery still works and the blast radius is bounded to hook consumers.
- `impact:message-loss`: Affected outbound paths can complete visible sends while dropping the expected sent-hook event that downstream observers consume.
- `impact:session-state`: Conversation-stream, memory, and telemetry consumers can build incomplete outbound session history when sent hooks are skipped.
- `impact:security`: Safety, DLP, audit, or compliance plugins relying on outbound lifecycle hooks can silently miss delivered content on affected paths.

## Summary

Keep open: current main has fixed the original shared-outbound and Telegram direct/streaming slices, but source inspection still shows active sent-hook coverage gaps in configured channel delivery, Gateway/TUI final broadcasts, MS Teams native streaming, and native self-delivered channel sends; several related PRs are still open rather than merged.

## What This Changes

The issue asks OpenClaw to make `message:sent` / `message_sent` hook emission consistent across outbound dispatch paths so downstream hooks and plugins do not miss delivered assistant messages.

## Best Possible Solution

Keep this umbrella as the canonical tracker until maintainers either land a shared exactly-once outbound lifecycle observer or close it by linking merged narrower fixes for the remaining Gateway/TUI, configured-channel, MS Teams, and native self-delivered channel paths.

## Reproduction Assessment

Yes. Source-level reproduction is high confidence: current main still has configured channel, Gateway/TUI, MS Teams, and native self-delivered outbound paths that send or finalize visible assistant output without the same sent-hook coverage as `deliverOutboundPayloads`.

## Solution Assessment

Unclear as one implementation. The right direction is to preserve exactly-once lifecycle semantics, but maintainers need to choose between a shared observer/API seam and a set of narrower merged channel fixes before this broad issue should close.
