## Summary

Keep open: current main has repaired important shared outbound and Telegram direct-reply hook paths, but the umbrella inconsistency still remains across Telegram preview-finalized delivery, plugin-handled sends, Gateway/OpenAI HTTP responses, and chat/TUI final broadcasts; the open related PRs cover slices rather than replacing this canonical issue.

## What This Changes

The issue requests consistent `message:sent` and `message_sent` hook coverage across all outbound message dispatch paths so downstream hook consumers do not miss sent messages.

## Best Possible Solution

Define one canonical outbound delivery observation/reporting contract, then land or replace the open slice fixes only where they preserve documented hook semantics across channel, Gateway, TUI, HTTP, and plugin self-delivery paths.
