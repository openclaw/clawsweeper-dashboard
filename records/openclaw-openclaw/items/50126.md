- `P2`: This is a documented hook-coverage bug with meaningful observability and security impact, but it is not a crash, data-loss emergency, or fully blocked first-run path.

## Summary

Keep open: current main has repaired important shared outbound and Telegram direct-reply sent-hook paths, but the umbrella issue is still valid because preview-finalized Telegram delivery, Gateway HTTP/OpenResponses result surfaces, WebChat/TUI final broadcasts, and plugin-handled/self-delivered paths still have source-visible hook coverage gaps or active narrower PRs.

## What This Changes

The issue requests consistent `message:sent` and `message_sent` hook coverage across outbound dispatch paths so conversation-stream, plugin, audit, and safety consumers do not miss sent messages.

## Best Possible Solution

Define one canonical outbound lifecycle observation/reporting contract, then land narrower channel and surface PRs only where they preserve exactly-once `message_sending`, `message_sent`, and `message:sent` semantics with stable session/run context.
