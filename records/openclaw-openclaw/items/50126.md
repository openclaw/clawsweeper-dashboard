## Summary

The umbrella should stay open: current main has repaired the shared outbound and original Telegram direct-reply slices, but Gateway/WebChat/TUI terminal broadcasts and plugin-handled delivery paths still construct user-visible outbound output without the canonical sent-hook observer path, and the open related PRs only cover slices of the remaining problem.

## What This Changes

The issue requests consistent `message:sent` and `message_sent` hook emission across outbound dispatch paths, with Telegram DM replies as the original confirmed scenario.

## Best Possible Solution

Define one shared exactly-once outbound lifecycle observer/reporting contract, or explicitly split the remaining Gateway/TUI/native-channel slices into canonical issues so every delivery path emits the applicable hooks once with stable session/run context.
