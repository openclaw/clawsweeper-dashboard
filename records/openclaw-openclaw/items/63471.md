## Summary

Keep open: current main and the latest release still require setup or explicit gateway config before a raw Dockge-style Compose gateway start from empty config, while the supported Docker setup helper is a separate bootstrap path. The remaining work is a real but security-sensitive Docker-manager product decision, not conservative cleanup.

## What This Changes

The issue requests a Docker-manager-friendly path where a Compose stack with environment variables can start the OpenClaw gateway without extra CLI setup.

## Best Possible Solution

Define a maintainer-approved setup-time Docker-manager bootstrap that persists `gateway.mode=local`, bind, auth, and Control UI origin policy before the gateway serves a published port, while keeping runtime fail-closed guards intact.

- **Narrow to related issues:** Treat custom origins and trusted-proxy automation as separate smaller items and leave this broader raw-startup request unresolved until those land.

## Reproduction Assessment

Yes, source-level: a raw Docker Compose gateway start with an empty mounted config reaches the missing-config guard because the Compose command does not pass `--allow-unconfigured` or run setup-time config seeding. I did not run Docker in this read-only review.

## Solution Assessment

No, not as proposed: letting the container start unconfigured is not the safest solution for a published Docker gateway. A setup-time bootstrap contract that writes explicit auth, bind, and origin policy before serving is the narrower maintainable path.
