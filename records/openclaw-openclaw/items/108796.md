## Summary

Keep this PR open but do not merge it yet: current main already bounds stalled xAI TTS connections through the application connection timer and CONNECTING-socket cleanup, while the proposed dependency timer creates a second error source at the same deadline. The revised tests address the earlier fixed-30-second concern, but the submitted evidence remains test and mock based rather than showing an after-fix production-path improvement.

## What This Changes

Adds a WebSocket opening-handshake timeout to xAI TTS streaming using the caller-provided timeout budget, with unit and real-TCP loopback tests.

## Best Possible Solution

Retain one canonical connection deadline: keep connectTimer responsible for timeout error normalization and socket cleanup, and add focused proof that closing a CONNECTING ws aborts its pending handshake without introducing another timer or error owner.
