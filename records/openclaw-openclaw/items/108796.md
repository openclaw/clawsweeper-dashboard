## Summary

This PR should not merge as written because current xAI TTS code already schedules a configurable connection deadline immediately after the synchronous WebSocket construction; the proposed fixed deadline duplicates that behavior without demonstrating the claimed OpenClaw hang.

## What This Changes

The PR adds a fixed 30-second WebSocket handshake timeout to xAI TTS streaming and extends its WebSocket mock with an option-plumbing regression test.

## Best Possible Solution

Keep one timeout contract owned by `timeoutMs`; if a library-native handshake deadline is still desired, centralize it with the existing connection timer and add a regression that advances the never-open xAI stream through the actual failure and cleanup path.
