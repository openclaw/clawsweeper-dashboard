## Summary

The claimed indefinite handshake hang does not match the current control flow: `new WebSocket()` returns while the HTTP upgrade remains pending, so the existing connection timer already runs during a stalled handshake. The branch adds a competing hard-coded deadline rather than fixing a missing deadline.

## What This Changes

The PR adds a fixed 30-second handshake timeout to xAI streaming TTS WebSocket creation and verifies the option with a mocked WebSocket test.

## Best Possible Solution

Keep one connection deadline derived from `timeoutMs`; if a ws-native handshake timeout is still desired for cleanup symmetry, pass that same caller-controlled value and prove the actual xAI path rather than adding a separate fixed policy.
