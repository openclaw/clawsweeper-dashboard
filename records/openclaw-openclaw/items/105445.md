## Summary

The report is credible and still necessary: both the affected beta and current main can fall back to static GPT-5.6 OAuth rows when live discovery fails or yields no usable visible models, while Codex CLI derives its discovery version from the installed client. The evidence does not yet show whether Luna was advertised because discovery failed, because `client_version=1.0.0` returned an unusable catalog, or because OpenClaw’s direct Responses request differs from Codex CLI, so closing or globally removing Luna would be premature.

## What This Changes

Investigate why OpenClaw lists `openai/gpt-5.6-luna` even though the ChatGPT Codex Responses endpoint returns a model-not-found response.

## Best Possible Solution

Make OpenClaw model discovery and direct execution share the same account-, client-version-, and transport-aware availability facts, then advertise only models proven valid for the selected OAuth route while retaining a clearly bounded fallback for genuine discovery outages.
