## Summary

Keep open for the linked same-author PR and a maintainer decision on delivery semantics. The original SQLite migration failure has since been addressed through doctor preflight, but this issue also covers whether omitted delivery should remain implicit announce-to-last or become explicit silent delivery; the open PR proposes the latter and has not merged.

## What This Changes

The issue requests safe migration of legacy JSON cron jobs into SQLite and prevents no-channel implicit cron delivery from making an otherwise successful agent turn fail.

## System Context

Cron jobs enter through the CLI or Gateway, are normalized and stored in the scheduler state database, then run an isolated agent turn. The delivery plan decides whether the completed result is announced to a channel and contributes to the recorded run outcome.

## Best Possible Solution

Keep the shipped doctor-preflight migration as the only legacy-state path, then decide whether no explicit delivery should preserve announce-to-last compatibility with fail-soft no-channel handling or become an explicit none default, with focused fresh-install and upgrade coverage before merging the linked PR.

Options:

- **Split policy by creation surface:** Define and document distinct defaults only if CLI and UI user intent can be made unambiguous without adding a competing configuration surface.
