## Summary

This PR still appears necessary: current main and the latest release both keep expired Synology Chat user-list entries in the process Map until the exact key is overwritten or the process exits. The patch is a narrow plugin-local write-side eviction, the added proof addresses the prior blocker, and I found no blocking code or security finding.

## What This Changes

The PR adds a stale-entry sweep before `chatUserCache.set(...)` in the Synology Chat user-list fetch path.

## Best Possible Solution

Land a bounded Synology Chat cache eviction fix that preserves the existing read TTL contract and leaves broader max-size cache policy out of this PR.

## Reproduction Assessment

Yes, by source inspection: current main ignores expired entries on reads but never removes stale keys when writing refreshed Synology Chat user-list cache entries. I did not run executable tests in this read-only review.

## Solution Assessment

Yes, this is the narrow owner-plugin fix: deleting expired entries before the next successful insert preserves the current TTL semantics. A max-size cache would be more defensive, but it would add a new policy beyond the reported leak.
