## Reproduction Assessment

Yes from source inspection: current main ignores expired cache entries on read but never deletes them on successful writes, so rotating unique webhook URLs can leave expired entries resident for the process lifetime. I did not run a live Synology Chat setup.

## Solution Assessment

Yes: evicting expired entries immediately before a successful `chatUserCache.set(...)` is the narrow owner-local fix. A global timer or new size/config policy would add lifecycle surface beyond the stated TTL leak.
