This PR should stay open, but the two unrelated commits introduce regressions: one misidentifies every canonical agent-scoped session key, and the other can defeat the SSH cooldown map’s size bound. The stated doctor guard is not shown to fix an externally reachable crash because the helper is module-local and its primary caller already catches the load failure.

## What This Changes

The branch catches session-snapshot JSON read/parse failures, changes session display-model agent-id extraction, and changes SSH pairing cooldown pruning.

## Best Possible Solution

Split the unrelated fixes, restore segment-aware session-key parsing and a hard cooldown-map bound, then retain the doctor change only if a focused corrupt-store regression proves a real caller-visible gap beyond the existing outer error boundary.
