## Summary

Keep open: current main still relies on initial/manual/optional timer Workboard reads and durable notification-cursor RPCs, but there is no read-authorized `plugin.workboard.changed` Gateway broadcast or Control UI invalidation path. ## What This Changes

Request a live, read-authorized Workboard change event that lets Control UI invalidate and reread canonical Workboard state instead of depending on manual or timer refresh.

## Best Possible Solution

Implement a Workboard-owned mutation revision signal and explicit read-scoped Gateway event, then have Control UI coalesce invalidations and reread canonical Workboard state while preserving manual refresh as recovery.
