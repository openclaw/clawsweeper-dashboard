## Summary

Keep open: current main still lacks a live Workboard change event and Control UI invalidation path, and the protected `maintainer` label plus the new plugin/Gateway event contract make this maintainer-owned feature/API work rather than conservative cleanup closure.

## What This Changes

Request live, read-authorized Workboard invalidation from plugin change events so Control UI rereads canonical Workboard state instead of relying on manual or timer refresh.

## Best Possible Solution

Implement a Workboard-owned mutation revision signal and read-authorized Gateway event, then have Control UI coalesce invalidations and reread canonical Workboard data while keeping manual refresh as recovery.

## Reproduction Assessment

Not applicable as a feature request; source inspection confirms current main still uses initial/manual/optional poll reads and lacks live Workboard invalidation.

## Solution Assessment

Yes if maintainers approve the direction: emitting from the Workboard mutation owner and forcing clients back through canonical reads is the narrowest maintainable shape, but the event contract and polling replacement are product/API decisions.
