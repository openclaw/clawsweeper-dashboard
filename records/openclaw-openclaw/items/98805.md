## Summary

Keep open: current main still relies on initial, manual, and optional timer-based Workboard reads, with no `plugin.workboard.changed` event or Control UI invalidation handler. The protected `maintainer` label and read-authorized plugin Gateway event contract make this a maintainer-owned feature/API decision, not cleanup-close material.

## What This Changes

Request a live read-authorized Workboard change event and Control UI refetch path so canonical Workboard reads stay fresh without routine timer polling.

## Best Possible Solution

Implement a Workboard-owned mutation revision signal, expose a read-authorized Gateway event with reconciliation-only payload, and have the Control UI coalesce events and reread canonical Workboard data while preserving manual refresh.
