## Summary

Keep open: current main and v2026.6.11 still lack a stream-level assistant-text repetition detector, alert/recovery path, or halt/confirm contract, and the only direct implementation PR closed unmerged. The remaining work needs maintainer product direction because default strictness, false-positive tolerance, buffered-output discard, and session cleanup are not settled.

## What This Changes

The issue requests a core streaming safeguard that detects repeated assistant output, halts the stream, alerts the user, and requires approve/cancel confirmation before continuing.

## Best Possible Solution

Define a core stream-content repetition circuit breaker with maintainer-approved thresholds, alert/recovery semantics, buffered-output discard, and session cleanup, while keeping timeout configuration tracked separately.

- **Defer To Timeout Work:** Keep this open but wait for generation-timeout and provider-watchdog decisions before adding semantic stream detection.
