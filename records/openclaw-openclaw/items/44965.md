## Summary

Keep open: current main and the latest release still lack the requested semantic text-stream repetition circuit breaker, and the previous implementation PR was closed unmerged as non-merge-ready. The remaining question is product policy for abort/pause/confirmation semantics, not stale cleanup.

## What This Changes

The issue requests a core stream-level safeguard that detects repeated LLM output, halts the stream, alerts the user, and requires confirmation before continuing.

## Best Possible Solution

Choose a core runtime policy for semantic repetition first, then implement a conservative active-path guard with false-positive tests and explicit channel/session abort or pause messaging.
