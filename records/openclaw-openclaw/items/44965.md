## Summary

Keep open: current main and v2026.6.11 still do not implement a semantic repeated-text stream guard, and the closed implementation PR is not a viable replacement. The remaining threshold, abort/flush cleanup, alert wording, resume/cancel, and session-sanitization behavior needs maintainer product direction before repair work.

## What This Changes

The issue requests a stream-level safeguard that detects repeated generated text, halts the stream, alerts the user, and requires approve/cancel confirmation before continuing.

## Best Possible Solution

Define a core stream-content repetition circuit breaker in the embedded-agent stream path with maintainer-approved thresholds, alert/recovery semantics, buffered-output discard, and session cleanup; keep timeout configuration tracked separately.
