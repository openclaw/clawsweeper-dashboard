## Summary

Keep open: current main and v2026.6.11 still lack a semantic repeated-text stream guard, and this remains the canonical tracker for halt/alert/buffer-discard/session-cleanup behavior that needs maintainer product direction before implementation.

## What This Changes

The issue requests a stream-level repetition safeguard that halts repeated assistant output, alerts the user, and requires confirmation before continuing.

## Best Possible Solution

Design a core stream-content repetition circuit breaker in the embedded-agent stream path with maintainer-approved thresholds, alert/recovery semantics, buffered-output discard, and session cleanup; keep timeout configuration and output-sanitizer cleanup as adjacent separate work.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What product behavior should OpenClaw use when assistant streamed text appears to be repeating: abort-only, pause-and-confirm, or a configurable/opt-in guard?

Rationale: The missing implementation is clear, but the permanent behavior affects false positives, user-visible delivery, session state, and whether an existing run can safely resume after a semantic stream abort.

Likely owner: steipete

Owner reason: steipete is the strongest routing candidate from current blame, prior discussion, and adjacent tool-loop/config history.

Owner confidence: high

Options:

- **Abort and reset the turn (recommended):** Stop the provider stream, discard buffered repeated output, mark the turn as failed or cancelled, and require a new user turn to continue.
- **Pause and ask for confirmation:** Stop streaming, alert the user, and allow an explicit resume/cancel path after maintainers define how to resume safely without replaying poisoned context.
- **Defer to timeout/sanitizer work:** Do not add a semantic stream guard yet; rely on generation-timeout and output-sanitizer issues to reduce symptoms while accepting continued token burn during active repetition.

## Reproduction Assessment

No high-confidence live current-main model-loop reproduction was run. Source inspection shows current main streams and buffers assistant text and has idle/tool-loop guards, but no semantic repeated-text detector or halt/confirm state.

## Solution Assessment

Unclear whether the requested halt-and-confirm flow is the best final shape. A core stream guard is plausible, but maintainers still need to choose threshold/default behavior, buffer discard, session cleanup, and whether confirmation resumes or aborts.
