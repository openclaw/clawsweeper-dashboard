## Summary

Keep open: current main still lacks a stream-content repetition circuit breaker, and the only direct implementation PR closed unmerged. The remaining work needs maintainer product direction because abort thresholds, alerting, resume/cancel behavior, buffered-output discard, and session cleanup are compatibility-sensitive.

## What This Changes

The issue requests a core stream-level repetition safeguard that halts repeated assistant output, alerts the user, and requires resume or cancel confirmation before continuing.

## Best Possible Solution

Define a core stream-content repetition circuit breaker with maintainer-approved thresholds, alert and recovery semantics, buffered-output discard, and session cleanup, while keeping generation-timeout config tracked separately.
