## Summary

Keep open: current main and v2026.6.11 still lack a semantic repeated-text stream guard; idle-timeout, tool-loop, and duplicate-snapshot protections do not halt active repeated assistant plaintext or define alert/confirm recovery. The prior implementation PR closed unmerged and is not a viable canonical fix.

## What This Changes

Request a core stream-level safeguard that detects repeated assistant output, halts the LLM stream, alerts the user, and requires approve/cancel before continuing.

## Best Possible Solution

Define a core stream-content repetition circuit breaker with maintainer-approved thresholds, alert/recovery semantics, buffered-output discard, and session quarantine; keep generation-timeout config tracked separately.
