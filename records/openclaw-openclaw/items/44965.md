## Summary

Keep open: current main and v2026.6.11 still lack a semantic repeated-text stream guard, the prior implementation PR was closed unmerged, and the requested halt/confirm plus session-cleanup behavior still needs maintainer product direction.

## What This Changes

The issue requests a core stream-level safeguard that detects repeated generated text, halts the stream, alerts the user, and requires confirmation before continuing.

## Best Possible Solution

Design a core stream-content repetition circuit breaker in the embedded-agent stream path with replay-safe abort/session cleanup and a maintainer-approved recovery policy, while keeping generation timeout configuration as separate work.

## Reproduction Assessment

No high-confidence live current-main model-loop reproduction was run. Source inspection shows current main has stream emission, idle timeout, and tool-call loop guards but no semantic repeated-text detector; related reports preserve concrete loop examples.

## Solution Assessment

Unclear whether the requested halt-and-confirm flow is the best final shape. A core stream guard is plausible, but maintainers still need to choose thresholds, default behavior, session cleanup semantics, and whether manual confirmation is required.
