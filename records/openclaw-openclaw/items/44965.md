## Summary

Keep open: current main still lacks a semantic repeated assistant-text stream guard, and the closed implementation PR is not a viable landing path. Existing idle-timeout and tool-loop guardrails are adjacent but do not halt active repeated text or define the requested alert/confirm recovery flow.

## What This Changes

Request to add a core stream-level repeated assistant-text detector that halts looping LLM output and asks the user to resume or cancel before more channel output is sent.

## Best Possible Solution

Define a core stream-content repetition circuit breaker in the agent streaming path with maintainer-approved thresholds, alert/recovery semantics, buffered-output discard, and replay/session quarantine; keep generation-timeout configuration tracked separately.
