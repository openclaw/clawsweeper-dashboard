## Summary

Keep open: current main and v2026.6.11 still lack a semantic repeated-text stream guard, and the prior implementation PR closed unmerged without becoming a safe canonical fix.

## What This Changes

The issue requests a core stream-level safeguard that detects repeated LLM output, halts the stream, alerts the user, and requires manual resume or cancel confirmation.

## Best Possible Solution

Define a core stream-content repetition circuit breaker with maintainer-approved thresholds, alert and recovery semantics, buffered-output discard, and session quarantine; keep generation-timeout and sanitizer-specific work separate.
