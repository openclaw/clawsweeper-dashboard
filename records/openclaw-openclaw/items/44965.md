## Summary

Keep open: current main and v2026.6.11 still lack the requested semantic repeated-text stream guard, and the only implementation PR was closed unmerged with proof and merge-risk blockers. The remaining cutoff threshold, alert/recovery flow, buffered-output discard, and session cleanup behavior need maintainer product direction before repair automation.

## What This Changes

The issue requests a core stream-level safeguard that detects repeated assistant output, halts the stream, alerts the user, and requires confirmation before resuming or aborting.

## Best Possible Solution

Define a core stream-content repetition circuit breaker in the embedded-agent stream path with maintainer-approved thresholds, user alert/recovery semantics, buffered-output discard, and session cleanup; keep generation-timeout configuration tracked separately.

- **Reject Resume Semantics:** Allow only abort-and-quarantine behavior for detected repetition, avoiding a manual resume path that may continue poisoned output.
