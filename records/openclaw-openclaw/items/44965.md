## Summary

Keep open: current main and v2026.6.11 still lack a semantic repeated-text stream guard, and the remaining halt/confirm, buffering, and session cleanup behavior needs maintainer product direction before repair automation.

## What This Changes

Request a core streaming safeguard that detects repeated assistant text, halts the stream, alerts the user, and requires explicit resume or cancel.

## Best Possible Solution

Design a core stream-content repetition circuit breaker in the embedded-agent stream path with maintainer-approved thresholds, alert/recovery semantics, buffer discard, and session cleanup; keep timeout configuration tracked separately.

## Reproduction Assessment

No high-confidence live current-main model-loop reproduction was run. Source inspection shows current main has stream emission, idle timeout, and tool-call loop guards but no semantic repeated-text detector; related reports preserve concrete loop examples.

## Solution Assessment

Unclear whether the requested halt-and-confirm flow is the best final shape. A core stream guard is plausible, but maintainers still need to choose threshold/default behavior, session cleanup semantics, and whether manual confirmation is required.
