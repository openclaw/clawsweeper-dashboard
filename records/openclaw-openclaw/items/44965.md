## Summary

Keep open: current main and v2026.6.11 still lack a stream-level assistant text repetition detector, user alert/recovery path, or resume/cancel contract, and the direct implementation PR closed unmerged. The remaining work is real but needs maintainer product direction because thresholds, false positives, buffered-output discard, and session cleanup are compatibility-sensitive.

## What This Changes

Request a core streaming safeguard that detects repeated assistant text, halts the active generation, alerts the user, and requires confirmation or cancellation before continuing.

## Best Possible Solution

Define a core stream-content repetition circuit breaker with maintainer-approved thresholds, alert/recovery semantics, buffered-output discard, and session cleanup, while keeping timeout configuration tracked separately.
