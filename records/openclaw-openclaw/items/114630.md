## Summary

Keep open. The report describes a concrete Amazon Bedrock provider regression with a bounded request-shaping path: a Claude Opus 5 model can be treated as legacy extended-thinking, receive an unsupported payload, and then complete only after OpenClaw retries with thinking off. The upstream Bedrock contract requires adaptive thinking plus a separate effort setting, and the current shared provider barrel already exposes Claude Opus 5 identity support, so the remaining check is the Bedrock plugin’s owner-local policy rather than a new product direction.

## What This Changes

Recognize Claude Opus 5 as an adaptive-thinking Amazon Bedrock model so selected thinking levels produce Bedrock’s adaptive request shape instead of silently falling back to thinking off.

## System Context

OpenClaw’s Amazon Bedrock provider converts an agent’s selected model and thinking level into Bedrock Converse `additionalModelRequestFields`. Provider model-identity policy determines whether the stream runtime uses the legacy token-budget payload or adaptive thinking with a separate effort control before sending the request to AWS.
