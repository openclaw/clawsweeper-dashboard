## Label Justifications

- `P2`: Reply and quote references can be lost or malformed in active Telegram conversations, but ordinary reply handling has recent evidence of working and no emergency availability or security failure is established.
- `impact:session-state`: The issue concerns whether reply-target and quote facts survive from a channel turn into the agent’s active runtime context.
- `impact:message-loss`: When reply or selected-quote context is dropped or rendered incorrectly, the agent loses the user’s intended reference even though the message itself arrives.

## Summary

Keep open. The documented direction appears to be clear—keep `BodyForAgent` limited to the current message and carry reply facts as typed runtime metadata—but the remaining end-to-end contract is still not landed: the relevant runtime-handoff PR is open, selected-quote behavior has separate active reports, and this issue retains the cross-surface acceptance criteria.

## What This Changes

Define a durable, structured Telegram quote/reply-context path from channel ingress through agent runtime context, with regression coverage that prevents reply data from silently disappearing or being treated as trusted prompt text.

## System Context

Telegram turns enter through the channel plugin, which derives the user’s current message plus reply and quote facts. The agent runtime then consumes the current message as prompt text and supplemental inbound facts as hidden structured context, affecting how an agent resolves the user’s reference.

## Architecture Diagram

flowchart LR
  A[Telegram update] --> B[Telegram channel ingress]
  B --> C[Reply and quote facts]
  B --> D[Current message text]
  C --> E[Structured inbound runtime context]
  D --> F[Agent-visible current prompt]
  E --> G[Agent runtime]
  F --> G
  G --> H[Reply-aware agent response]

## Best Possible Solution

Land or replace the active runtime-handoff work with one canonical structured inbound-reply contract, then add Telegram reply and selected-quote fixtures that prove metadata reaches hidden runtime context while quoted text remains untrusted and prompt text remains current-message-only.
