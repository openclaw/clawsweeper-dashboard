## Label Justifications

- `P2`: The issue affects Telegram reply-context reliability with bounded channel/session impact, not a core outage or emergency.

## Summary

Keep open: current main documents the right direction and preserves Telegram reply fields, but the durable structured runtime contract is not landed; https://github.com/openclaw/openclaw/pull/90745 is the open candidate for that handoff and is currently conflicting.

## What This Changes

Request to make Telegram quote/reply context a durable structured inbound/runtime contract with regression coverage instead of relying on BodyForAgent prompt concatenation or local dist patching.

## Best Possible Solution

Land one maintainer-approved structured current-inbound reply metadata path, likely by refreshing https://github.com/openclaw/openclaw/pull/90745, and add a Telegram reply/quote contract fixture that proves the handoff end to end.

## Reproduction Assessment

Yes for a source-level reproduction: main keeps Telegram BodyForAgent as current message text while CurrentInboundPromptContext remains text-only and the runner applies it through prompt text helpers. I did not run a live Telegram reproduction in this read-only review.

## Solution Assessment

Yes on direction, not complete on main: structured reply metadata is the maintainable fix compared with concatenating quote text into BodyForAgent. The best implementation still needs maintainer acceptance or refresh of the open runtime-context PR plus a Telegram reply/quote fixture.
