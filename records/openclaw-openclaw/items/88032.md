## Label Justifications

- `P2`: The issue affects Telegram reply-context reliability with bounded channel/session impact rather than a core outage or emergency.
- `impact:session-state`: The requested contract is about preserving current-turn reply metadata through session and runtime context without drift.
- `impact:message-loss`: When the split regresses, Telegram reply target context can be dropped from the agent-visible turn even though the user replied in Telegram.

## Summary

Keep open: current main and the latest release still have split Telegram reply context, with plain `BodyForAgent`, text-only current inbound context, and no landed structured reply handoff; the open candidate PR remains unmerged and currently conflicting.

## What This Changes

Request to make Telegram quote/reply context a durable structured inbound/runtime contract with regression coverage instead of relying on local `dist/*` patches or concatenated prompt text.

## Best Possible Solution

Review, refresh, and either land or replace https://github.com/openclaw/openclaw/pull/90745, then add Telegram reply/quote contract coverage so `BodyForAgent` remains current-message text while structured reply metadata survives the runtime handoff.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: current main still keeps Telegram reply context in `Body`/structured fields while `BodyForAgent` is plain current text and current inbound context has no structured reply payload. I did not run a live Telegram scenario in this read-only review.

## Solution Assessment

Unclear as a final maintainer choice: the documented direction favors typed structured reply metadata, but the concrete runtime contract still needs maintainer review through https://github.com/openclaw/openclaw/pull/90745 or an equivalent replacement.
