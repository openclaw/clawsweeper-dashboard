## Label Justifications

- `P2`: This is a bounded Telegram/session-context reliability improvement with real user impact but no core outage or emergency.
- `impact:session-state`: The issue is about preserving current-turn reply metadata through session and runtime context without drift.
- `impact:message-loss`: When the split regresses, the agent can lose the Telegram reply target context even though the user replied in the channel.

## Summary

Keep open: current main still has Telegram reply context split between enriched `Body`/`ReplyTo*` fields and a text-only runtime handoff, while the structured reply-context candidate remains open and unmerged.

## What This Changes

Request to make Telegram quote/reply context a durable structured inbound/runtime contract, with regression coverage that prevents reply metadata from drifting away from agent-visible context.

## Best Possible Solution

Land a maintainer-approved structured current-inbound reply contract, then add a Telegram reply/quote channel contract fixture that proves reply metadata survives into the runtime path without changing `BodyForAgent` into quoted prompt text.

## Reproduction Assessment

Yes for a source-level reproduction: current main has reply-aware Telegram `Body` and `ReplyTo*` fields, but `BodyForAgent` remains current text and `CurrentInboundPromptContext` is text-only. I did not run a live Telegram reproduction in this read-only review.

## Solution Assessment

The narrowed structured-runtime-context direction is the right owner-boundary fix; a Telegram-only `BodyForAgent` concatenation would conflict with current docs. The exact PR shape still needs maintainer review because https://github.com/openclaw/openclaw/pull/90745 and https://github.com/openclaw/openclaw/pull/89428 overlap.
