## Label Justifications

- `P2`: The issue affects Telegram reply-context reliability and agent comprehension with bounded channel/session impact rather than a core outage or emergency.
- `impact:session-state`: The requested contract is about preserving current-turn reply metadata through session and runtime context without drift.

## Summary

Keep open: current main still has a text-only current inbound prompt context and Telegram only passes reply facts as separate Body/ReplyTo fields, while the first-class runtime reply metadata contract remains in an open, conflicting PR and the Telegram reply/quote contract fixture is still missing.

## What This Changes

Request to make Telegram quote/reply context a durable first-class inbound/runtime contract with structured metadata and regression coverage instead of relying on split prompt/runtime text handling.

## Best Possible Solution

Land or replace the current reply-metadata runtime-context PR with a maintainer-approved structured current-turn reply contract, then add a Telegram reply/quote fixture that proves the contract end to end.

## Reproduction Assessment

Yes for source-level reproduction: current main keeps Telegram reply facts structured while CurrentInboundPromptContext remains text-only and the embedded runner still prefixes current inbound context into prompt strings. I did not run a live Telegram round trip in this read-only review.

## Solution Assessment

Unclear until maintainers select the exact contract shape. The documented direction favors structured reply metadata over BodyForAgent concatenation, and https://github.com/openclaw/openclaw/pull/90745 is the closest candidate but currently needs maintainer review and conflict resolution.
