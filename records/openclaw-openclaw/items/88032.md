## Summary

Keep open: current main documents `BodyForAgent` as current-message text and reply-to metadata as typed structured fields, but the runtime path still only has a text-shaped `CurrentInboundPromptContext` and still prepends that context into session/model prompt strings. The linked runtime-context PR is the right active path to review, but it is still open and conflicting, so this issue is not implemented on main.

## What This Changes

The issue requests a durable first-class Telegram reply/quote inbound contract so structured reply metadata and agent-visible runtime context cannot drift apart.

## Best Possible Solution

Land a maintainer-approved canonical runtime-context shape, likely via a refreshed successor to https://github.com/openclaw/openclaw/pull/90745, and add a Telegram reply/quote inbound contract fixture before closing this issue as implemented.

## Reproduction Assessment

Yes at source level: current main shows Telegram can populate reply fields, but the agent runtime contract is still text-shaped and joined into prompt strings. I did not run a live Telegram reproduction in this read-only cleanup review.

## Solution Assessment

Yes, the narrowed path is the maintainable solution: keep `BodyForAgent` current-message-only, carry reply facts as structured current-turn runtime metadata, and enforce it with a Telegram reply/quote contract fixture. The existing open PR is a plausible candidate, but maintainers still need to approve and refresh it.
