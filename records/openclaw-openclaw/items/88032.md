## Summary

Keep open: current main documents the intended current-message-only BodyForAgent direction and Telegram already builds reply fields, but the first-class reply metadata handoff through runtime context is still unmerged and currently owned by open PRs.

## What This Changes

The issue requests a durable Telegram quote/reply inbound contract that preserves structured reply metadata from channel ingress through runtime context and agent consumption without local dist patching.

## Best Possible Solution

Land a maintainer-approved structured reply-context contract in runtime context, add a Telegram reply/quote contract fixture, and keep BodyForAgent current-message-only as the docs describe.

## Reproduction Assessment

Yes. Source inspection reproduces the remaining gap: Telegram builds ReplyTo*/ReplyChain facts, while current main's CurrentInboundPromptContext is text-only and embedded runs still prepend current inbound context into prompt strings.

## Solution Assessment

Yes for the narrowed direction, but not yet implemented on main. The documented structured-metadata path is better than concatenating quote text into BodyForAgent; maintainers should review the open runtime-context PRs and require a Telegram reply/quote fixture.
