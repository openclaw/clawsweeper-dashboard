## Summary

Keep open: current main still has a text-only current-inbound runtime context and Telegram still splits reply-aware `Body`/`ReplyTo*` fields from current-message-only `BodyForAgent`; the direct structured reply-metadata PR is open but not merged.

## What This Changes

The issue requests a durable structured Telegram quote/reply inbound contract across channel ingress, runtime context, prompt handoff, and tests.

## Best Possible Solution

Land one maintainer-approved structured current-turn reply metadata contract, keep `BodyForAgent` current-message-only, and add Telegram reply/quote contract coverage so the path cannot drift again.

## Reproduction Assessment

Yes for a source-level path: current main has text-only `CurrentInboundPromptContext` and prompt-joining runtime paths while Telegram reply fields remain separate. I did not run a live Telegram turn in this read-only review.

## Solution Assessment

No, not yet. The open structured reply-metadata PR appears to be the right direction, but it is not merged and maintainers still need to settle the overlap with generic hidden-runtime-context routing.
