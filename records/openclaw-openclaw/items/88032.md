## Summary

Keep open: current main still lacks a first-class structured reply payload in the current inbound runtime contract, and the central remaining work is already represented by open maintainer-review PRs rather than a merged fix.

## What This Changes

Request to make Telegram quote/reply context a durable structured inbound/runtime contract with end-to-end regression coverage instead of relying on split prompt/body behavior.

## Best Possible Solution

Review and either land or deliberately replace https://github.com/openclaw/openclaw/pull/90745, then add a Telegram reply/quote contract fixture so the structured metadata handoff is enforced end to end.

## Reproduction Assessment

Yes, source-level: current main keeps Telegram `BodyForAgent` as current text, carries reply data separately, and has only a text-based `CurrentInboundPromptContext` that is rewrapped into prompt strings. I did not run a live Telegram repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the canonical runtime contract. The structured metadata direction is better than BodyForAgent concatenation, but the exact landing branch and sibling-runtime scope need maintainer review.
