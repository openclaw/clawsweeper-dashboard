## Label Justifications

- `P2`: The issue affects Telegram reply-context reliability with bounded channel/session blast radius and open fix candidates, but it is not a core outage or emergency.
- `impact:session-state`: The requested contract is about preserving current-turn reply metadata through session and runtime context without drift.
- `impact:message-loss`: When this path drifts, the Telegram reply target can be absent from the agent-visible turn even though the user replied to a specific message.

## Summary

Keep open: current main still has a text-only `CurrentInboundPromptContext` and still joins current inbound context back into prompt strings, while the narrowed remaining work is owned by open, conflicting PRs plus a missing Telegram reply/quote contract fixture.

## What This Changes

Request to make Telegram reply/quote context a durable structured inbound/runtime contract with end-to-end coverage instead of relying on split prompt/runtime text handling.

## Best Possible Solution

Land one maintainer-approved structured current-turn reply metadata contract, likely through a refreshed https://github.com/openclaw/openclaw/pull/90745 or a deliberate split with https://github.com/openclaw/openclaw/pull/89428, and add a Telegram reply/quote contract fixture that keeps quoted text untrusted.

## Reproduction Assessment

Yes, at source level. Current main still has text-only current inbound context and joins that context into prompt strings, while the Telegram contract test lacks the reply/quote fixture that would enforce the requested durable path.

## Solution Assessment

Yes directionally, but the exact implementation still needs maintainer selection. The docs support keeping `BodyForAgent` current-message-only and carrying reply context as structured metadata, so local `dist/*` patching or BodyForAgent concatenation is not the best long-term fix.
