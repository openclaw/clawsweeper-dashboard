## Label Justifications

- `P2`: This is a normal-priority Telegram/session-context reliability improvement with bounded channel and runtime impact, not a core outage.
- `impact:session-state`: The issue is about preserving current-turn reply metadata through runtime/session context without prompt/body drift.
- `impact:message-loss`: When the split regresses, Telegram reply target context can be dropped from the agent-visible turn even though the user replied in Telegram.

## Summary

Keep open: current main and the latest release preserve Telegram reply data as Body/ReplyTo fields and document BodyForAgent as current-message-only, but the runtime current-inbound contract is still text-only, the Telegram contract test has no reply/quote fixture, and https://github.com/openclaw/openclaw/pull/90745 remains the open candidate for the structured handoff.

## What This Changes

Make Telegram quote/reply context a durable structured inbound/runtime contract with regression coverage instead of relying on split prompt/body mapping behavior.

## Best Possible Solution

Adopt a maintainer-approved structured current-turn reply contract, likely through https://github.com/openclaw/openclaw/pull/90745 or an equivalent split, and add a Telegram reply/quote contract fixture that keeps BodyForAgent current-message-only while reply metadata stays deterministic.

## Reproduction Assessment

Yes, source-level: current main has reply-aware Telegram Body/ReplyTo fields but CurrentInboundPromptContext remains text-only and the embedded runner wraps that text into prompts. I did not run a live Telegram reproduction in this read-only review.

## Solution Assessment

Unclear as a final maintainer decision: the structured contract direction matches current docs, but the exact landing shape should be reviewed through https://github.com/openclaw/openclaw/pull/90745 plus the missing Telegram fixture.
