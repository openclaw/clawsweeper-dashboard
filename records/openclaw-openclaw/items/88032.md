## Label Justifications

## Summary

Keep open: current main documents `BodyForAgent` as current-message text and has Telegram reply facts in `Body`/`ReplyTo*`, but the durable structured current-turn reply metadata contract is still not landed; the open candidate PRs are still maintainer-review items rather than merged fixes.

## What This Changes

Requests a first-class durable structured inbound reply/quote contract for Telegram/current-turn runtime context, plus regression coverage so reply metadata cannot drift from agent-visible input.

## Best Possible Solution

Land one maintainer-approved structured current-turn reply metadata contract, likely through https://github.com/openclaw/openclaw/pull/90745 after conflict and scope review, then add a Telegram reply/quote inbound contract fixture around that path.

## Reproduction Assessment

Yes for a source-level reproduction: current main documents structured reply metadata as the desired shape, but `CurrentInboundPromptContext` is text-only and Telegram still splits reply-aware `Body` from plain `BodyForAgent`. I did not run a live Telegram round trip in this read-only review.

## Solution Assessment

Unclear until maintainers choose the landing scope: the structured runtime-context direction is better than local `dist/*` patching or concatenating replies into `BodyForAgent`, but https://github.com/openclaw/openclaw/pull/90745 still needs maintainer review and conflict resolution.
