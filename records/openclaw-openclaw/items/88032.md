## Label Justifications

- `P2`: This is a normal-priority Telegram/session-context reliability improvement with meaningful user impact but limited blast radius.
- `impact:session-state`: The issue is about preserving current-turn reply metadata through session and runtime context without drift.
- `impact:message-loss`: When the split regresses, the user's Telegram reply target can be lost from the agent-visible turn even though Telegram carried the reply.

## Summary

Keep open: current main and v2026.6.11 still lack the requested first-class structured reply metadata contract, while open PRs already own the likely runtime-context implementation path.

## What This Changes

Request to make Telegram quote/reply context a durable structured inbound/runtime contract with regression coverage instead of relying on prompt-string and runtime mapping drift.

## Best Possible Solution

Land one maintainer-approved structured current-turn reply metadata contract, likely via https://github.com/openclaw/openclaw/pull/90745 or a smaller accepted split, and add Telegram reply/quote contract coverage so `BodyForAgent` stays current-message-only while reply context remains durable metadata.

## Reproduction Assessment

Yes for source-level reproduction: current main and v2026.6.11 have reply-aware Telegram `Body`/`ReplyTo*` fields but no structured reply payload on `CurrentInboundPromptContext`, and the embedded runner still handles current inbound context as prompt text. I did not run a live Telegram repro in this read-only review.

## Solution Assessment

Yes on direction, but not yet complete: the documented best shape is current-message-only `BodyForAgent` plus structured reply metadata, and the remaining implementation should land through the existing runtime-context PR or an accepted split with Telegram contract coverage.
