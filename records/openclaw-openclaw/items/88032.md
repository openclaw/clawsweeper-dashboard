## Summary

Keep open: current main and the latest release still do not provide the requested first-class structured reply/quote runtime contract, and the central implementation candidate is still an open, conflicting PR awaiting maintainer scope/branch choice.

## What This Changes

Request to make Telegram quote/reply context a durable structured inbound contract, with deterministic runtime handoff and regression coverage instead of relying on split prompt/body behavior.

## Best Possible Solution

Land one maintainer-approved structured current-turn reply metadata contract, likely through https://github.com/openclaw/openclaw/pull/90745 or a smaller selected branch, then add a Telegram reply/quote contract fixture and keep `BodyForAgent` current-message-only.

## Reproduction Assessment

Yes for a source-level reproduction: current main still has reply-aware Telegram Body and ReplyTo fields while CurrentInboundPromptContext is text-only and the embedded runner prefixes that text into prompts. I did not run a live Telegram reproduction in this read-only review.

## Solution Assessment

Unclear as a final implementation path: the docs support structured reply metadata rather than BodyForAgent concatenation, but maintainers still need to select the canonical PR/scope and sibling-runtime handling.
