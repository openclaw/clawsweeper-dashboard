## Label Justifications

- `P2`: This is a normal-priority Telegram reply-context reliability improvement with bounded channel/session impact rather than an outage or emergency.
- `impact:session-state`: The issue is about preserving current-turn reply metadata through session and runtime context without drift.
- `impact:message-loss`: When the split regresses, Telegram reply target context can be dropped from the agent-visible turn even though the user replied in Telegram.

## Summary

Keep open: current main documents `BodyForAgent` as current-message text and supports Telegram reply facts, but the durable structured reply-context handoff is still not implemented and the open runtime-context PR remains the candidate path.

## What This Changes

The issue requests a durable first-class Telegram reply/quote inbound contract so reply metadata reaches the agent through stable structured context instead of fragile prompt/runtime text patching.

## Best Possible Solution

Land or explicitly reject one maintainer-approved structured current-turn reply contract, then add a Telegram reply/quote inbound contract fixture so the chosen path is enforced end to end.

## Reproduction Assessment

Yes, source inspection provides a high-confidence source-level reproduction: current main has reply facts and docs for structured metadata, but `CurrentInboundPromptContext` is text-only and is still prepended into session/model prompts. I did not run a live Telegram reproduction in this read-only sweep.

## Solution Assessment

Yes as a direction, but not yet as a completed implementation: structured reply metadata is more maintainable than enriching `BodyForAgent` or local `dist/*` patching. Maintainers still need to review the open PR shape and add Telegram contract coverage.
