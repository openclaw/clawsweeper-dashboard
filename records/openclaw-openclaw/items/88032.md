## Label Justifications

- `P2`: The issue affects Telegram reply/session context reliability but is bounded to a channel/runtime contract rather than an emergency outage.
- `impact:session-state`: The reported failure is that reply context can be present in channel metadata but absent from the agent-visible runtime/session handoff.

## Summary

Keep open: current main and v2026.6.11 still do not have a first-class structured reply metadata payload in the inbound runtime context, and the remaining work is already represented by an open maintainer-review PR rather than something this cleanup pass should close.

## What This Changes

Request to make Telegram quote/reply context a durable structured inbound/runtime contract, while keeping BodyForAgent focused on current-message text and adding reply/quote regression coverage.

## Best Possible Solution

Land one maintainer-approved structured current-turn reply metadata contract, add a Telegram reply/quote inbound fixture, and document any sibling runtime follow-up explicitly.

## Reproduction Assessment

Yes, source-reproducible: current main can be traced from Telegram ReplyTo/ReplyChain fields into a text-only CurrentInboundPromptContext and embedded prompt prefixing. I did not run a live Telegram current-main reproduction in this read-only review.

## Solution Assessment

Yes as a direction, but not complete on main: the documented structured-metadata approach is the maintainable path, with https://github.com/openclaw/openclaw/pull/90745 as the current candidate and a Telegram reply/quote fixture still needed.
