## Summary

Keep open: the scanner hardening is useful, but the current head finalizes unclosed structured HTML contexts at EOF, so malformed pages can lose visible body text or overstate links. The PR also still has only test/diff-hygiene proof, not real web_fetch behavior proof from a user-like run.

## What This Changes

The PR replaces regex-based web_fetch HTML-to-Markdown fallback conversion with a forward-only scanner and adds focused malformed-markup regression tests.

## Best Possible Solution

Keep the scanner approach, but make unmatched title/anchor contexts fail open as text or close only on safe boundaries, add regression tests for those malformed cases, and include redacted real web_fetch proof before merge.

  - body: The EOF drain closes any remaining render context as if the page supplied the matching end tag. Current main only extracts closed title/anchor pairs and otherwise keeps the stripped text, so this is a regression for malformed pages the PR is trying to harden.
