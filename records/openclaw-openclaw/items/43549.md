## Summary

Keep open: current main still silently treats malformed or empty session-store JSON as an empty store, and the Telegram/status paths do not surface a session-state health warning or backed-up recovery path. The related session-store PR is useful but open, not mergeable as-is, and only partially overlaps this Telegram status/reset request.

## What This Changes

The issue asks for Telegram/status diagnostics and a safe recovery path when persisted session JSON is oversized, malformed, empty, or otherwise wedges channel operation.

## Best Possible Solution

Add a maintainer-approved session-store health diagnostic surfaced through status/channel status/doctor plus a backed-up repair/reset path; use automatic load-time quarantine only if maintainers explicitly accept the session-continuity tradeoff.
