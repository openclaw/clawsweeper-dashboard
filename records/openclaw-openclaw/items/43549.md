## Summary

Keep open: current main and the latest release still treat malformed or empty session-store JSON as an empty store, while Telegram status reports transport/config/audit issues but not the underlying session file health; https://github.com/openclaw/openclaw/pull/79910 is related but only covers generic stale temp-artifact recovery.

## What This Changes

The issue requests diagnostics and safe recovery for malformed, oversized, or poisoned Telegram persisted session JSON that can wedge the Telegram channel.

## Best Possible Solution

Add a read-only Telegram/session-store health diagnostic in channel status and doctor first, then add a guarded backup-and-reset or doctor repair path that never silently destroys session continuity.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should corrupted Telegram/session-store JSON recovery be diagnostic-only, an explicit backed-up reset/doctor repair, or automatic load-time quarantine?

Rationale: The source gap is clear, but the permanent behavior affects persisted session continuity and operator trust, so automation should not choose the destructive recovery policy on its own.

Likely owner: steipete

Owner reason: The choice spans OpenClaw state-storage policy, doctor UX, and Telegram channel status behavior, areas reflected in steipete's recent plugin/channel boundary history.

Owner confidence: medium

Options:

- **Diagnostic plus explicit repair (recommended):** Status and doctor should report file path, size, parse/schema status, and offer a backed-up reset or doctor repair command that the operator explicitly runs.
- **Diagnostic only:** Status and doctor would identify the bad artifact and recovery steps, but leave all mutation to manual operator action.
- **Automatic quarantine:** Gateway load would move invalid state aside and recreate clean state automatically, accepting the risk of surprising session continuity loss.

## Reproduction Assessment

Yes for the source failure mode: current loadSessionStore collapses malformed or empty session-store reads into an empty store, and Telegram status does not inspect file health. I did not run a live corrupted Telegram instance in this read-only review.

## Solution Assessment

Partly: explicit status/doctor detection with a backed-up reset path is the safest maintainable direction. Automatic quarantine or reset on load needs maintainer product approval because it changes persisted session continuity behavior.
