## Summary

Keep open: current main still treats malformed or unreadable session-store JSON as an empty store for normal readers, and Telegram/channel status does not diagnose file size, parse health, schema health, or a backup-first recovery path. The linked Keep My Claw skill is useful backup context, but the comment correctly notes it is not a replacement for first-party status/recovery tooling.

## What This Changes

The issue asks for Telegram/session-store status diagnostics and a safe recovery path when persisted session JSON becomes oversized, malformed, or otherwise wedges Telegram operation.

## Best Possible Solution

Add status or doctor diagnostics that identify malformed or oversized Telegram-related session-store state and point to a backup-first reset path; make automatic quarantine a separate maintainer-approved behavior.

Options:

- **Diagnostic plus explicit reset (recommended):** Status or doctor reports file health and points to a backup-first reset command while keeping destructive action operator-controlled.
- **Diagnostic only:** Status or doctor reports the bad state and safe manual steps, leaving reset automation for a narrower follow-up.
- **Automatic quarantine:** Gateway moves the bad artifact aside and recreates state on load, maximizing recovery but taking the largest data-continuity risk.

## Reproduction Assessment

Yes, source-reproducible: current `loadSessionStore` can collapse malformed or unreadable store JSON into an empty store and the status paths inspected do not surface file-health diagnostics. I did not run a live corrupt Telegram instance in this read-only review.

## Solution Assessment

Yes, the requested diagnostic/recovery direction is valid, but the best first fix is backup-first status or doctor detection plus explicit reset guidance rather than unconditional load-time quarantine.
