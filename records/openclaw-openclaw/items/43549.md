## What This Changes

The issue requests detection and safe recovery guidance for bad persisted Telegram session JSON that can wedge Telegram routing and leave operators deleting internal state manually.

## Best Possible Solution

Add Telegram/session-store health detection that reports oversized, empty, malformed, or unreadable session-store artifacts in status/doctor and routes recovery through a maintainer-approved backup/quarantine reset path.

- **Doctor-Owned Repair:** Implement `openclaw doctor --fix` or a channel repair command that backs up and quarantines the bad store before rebuilding or resetting the affected session state.
- **Startup Quarantine:** Automatically move bad session-store artifacts aside on load and recreate clean state, accepting the stronger compatibility and data-continuity risk.

Unclear until maintainers choose the recovery contract. The safest first step is non-destructive status/doctor diagnostics; automatic quarantine or reset needs explicit product approval.
