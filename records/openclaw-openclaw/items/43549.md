## Summary

Keep open. Current main and v2026.6.11 still silently treat malformed or empty session-store JSON as an empty store, and Telegram/channel status still does not surface a session-state diagnosis or safe backup/reset path; open generic session-store recovery work only partially overlaps the Telegram-facing status and recovery UX requested here.

## What This Changes

Request to diagnose and safely recover corrupted or oversized Telegram/session JSON state through status, doctor, or reset tooling instead of requiring manual file deletion.

## Best Possible Solution

Add shared read-only session-store health diagnostics surfaced through status/doctor and Telegram status first, then add any reset or quarantine path only with explicit backup and confirmation semantics coordinated with the generic session-store recovery work.

## Reproduction Assessment

No high-confidence live Telegram wedge was reproduced, but source inspection confirms malformed or empty session-store JSON currently becomes an empty store without a user-facing status diagnostic.

## Solution Assessment

Non-destructive diagnostics are the best first step; automatic reset, quarantine, or self-heal behavior needs maintainer product review because it changes persisted session continuity and recovery semantics.
