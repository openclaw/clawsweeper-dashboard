- `impact:session-state`: The issue centers on persisted session-store state being unreadable or misleadingly reported as empty.

## Summary

Keep open: current main still collapses unreadable or malformed session-store JSON into an empty session store, and Telegram/status diagnostics do not surface the corrupted local state or a safe recovery path.

## What This Changes

The issue asks OpenClaw to detect corrupted Telegram/session state in status tooling and provide a safer reset or recovery workflow instead of requiring manual file deletion.

## Best Possible Solution

Add status/doctor corruption detection plus a backed-up reset path, then align any automatic recovery with the generic session-store decision in #77783/#79910.

Options:

- **Diagnose and reset explicitly (recommended):** Status/doctor should flag unreadable or zero-byte session state and offer a backed-up reset/quarantine command without mutating runtime state automatically.

- **Fold into generic recovery:** Maintainers could make #77783/#79910 the only recovery track and keep this issue only if Telegram-specific status UX remains after that lands.
