## Summary

Keep open: current main and v2026.6.11 still treat malformed or empty session-store JSON as an empty store, and Telegram/channel status does not diagnose the bad local state or offer a backup-first recovery path.

## What This Changes

Telegram status should detect oversized or malformed persisted session JSON and guide users to safe recovery instead of requiring manual file deletion.

## Best Possible Solution

Add session-store health diagnostics to channel status or doctor and provide a backup-first operator reset path; defer automatic quarantine until the generic session-store recovery direction is settled.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should bad Telegram/session-store JSON recovery be diagnostic-only, explicit backup-first reset, or automatic quarantine on load?

Rationale: All three options can address the outage, but they make different tradeoffs around persisted session continuity, operator control, and overlap with the generic session-store recovery work.

Likely owner: steipete

Owner reason: The decision spans Telegram status UX and channel/plugin reliability, where steipete has the strongest recent history signal.

Owner confidence: high

Options:

- **Diagnostic plus explicit reset (recommended):** Status or doctor reports file health and points to a backup-first reset command, keeping destructive action operator-controlled.
- **Diagnostic only:** Status or doctor reports corrupt or oversized state and safe manual steps, leaving reset automation for later work.
- **Automatic quarantine:** Gateway load moves bad state aside and recreates clean state, maximizing recovery while taking the largest compatibility and data-continuity risk.

## Reproduction Assessment

Yes. Source inspection shows malformed or empty session-store JSON reaches `loadSessionStore`, retries, then returns an empty store, while the Telegram/channel status path does not inspect the underlying file health; no live corrupt Telegram instance was run in this read-only review.

## Solution Assessment

Yes for status/doctor detection plus backup-first reset guidance. Automatic quarantine is not clearly the best first fix because it changes session continuity and overlaps generic recovery semantics.
