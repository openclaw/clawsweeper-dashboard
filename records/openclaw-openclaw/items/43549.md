## Summary

Keep open: current main and the latest release still collapse malformed, empty, or unreadable session-store JSON into an empty store, and Telegram status has no session-state diagnostic or backed-up reset path. Related pull request https://github.com/openclaw/openclaw/pull/79910 only addresses generic stale temp-artifact recovery for the session store, not the Telegram-facing status and recovery UX requested here.

## What This Changes

Detect and guide recovery when Telegram-facing persisted session state is oversized, malformed, unreadable, or otherwise wedging channel operation.

## Best Possible Solution

Add shared read-only session-store health diagnostics surfaced through status/doctor and Telegram channel status first, then implement a maintainer-approved backed-up reset or quarantine flow.
