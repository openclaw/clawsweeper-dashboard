## Best Possible Solution

Add shared, read-only session-store health diagnostics that status/doctor and Telegram status can surface, then define an explicit backed-up reset or quarantine flow after maintainers decide recovery semantics.

No live Telegram repro was run, but source inspection on current main shows malformed, empty, or unreadable top-level session-store JSON is swallowed into an empty store without a diagnostic.

## Solution Assessment

Non-destructive diagnostics are the best first step; automatic reset or quarantine is not yet the best full fix without maintainer-approved backup and restore semantics.
