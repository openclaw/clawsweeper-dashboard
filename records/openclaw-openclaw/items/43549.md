## Summary

Keep open. Current main and v2026.6.11 still treat malformed or empty session-store JSON as an empty store, and Telegram status/doctor surfaces still do not provide Telegram-specific session-state diagnosis or safe reset/quarantine guidance; the open related PRs only partially cover generic recovery and diagnostics.

## What This Changes

The issue requests Telegram status and recovery UX for oversized, malformed, or poisoned persisted Telegram session JSON that can wedge channel operation.

## Best Possible Solution

Add shared read-only session-store health diagnostics surfaced through status/doctor and Telegram status, then add an explicit backup-backed reset or quarantine path coordinated with the generic recovery and diagnostics PRs.

## Reproduction Assessment

No high-confidence live reproduction is available for the exact Telegram wedge or oversized-file trigger. Source inspection does show that malformed or empty session-store JSON is swallowed into an empty store, which prevents status/doctor from reporting the corruption.

## Solution Assessment

Unclear as a complete implementation choice. Non-destructive diagnostics are the right first layer, while reset, quarantine, and self-heal behavior need maintainer direction because they trade service recovery against session continuity.
