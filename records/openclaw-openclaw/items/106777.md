## Label Justifications

- `P1`: A normal multi-exec gateway workload can reportedly disable all host exec and related cron operations until process restart.
- `impact:crash-loop`: The gateway remains alive, but its execution subsystem becomes persistently unavailable and requires restart for recovery.
- `impact:security`: The defect is within the exec authorization persistence boundary and converts lock failure into global fail-closed denial.

## Summary

Current `main` still routes exec-approval persistence through a fail-closed shared lock, and the report provides strong process-identity evidence that a live gateway can retain that lock indefinitely. No merged fix or canonical replacement was found, so this regression remains necessary to investigate and repair.

## What This Changes

Fix a gateway-owned exec-approvals lock that remains held after evaluation and causes later exec and cron operations to fail closed until restart.

## Best Possible Solution

Keep fail-closed authorization semantics, identify which approval transaction or re-entrant lock reference never settles, guarantee bounded release on every terminal path, and add same-process regression proof that sequential exec and cron reads continue after allowlist misses and persistence errors.
