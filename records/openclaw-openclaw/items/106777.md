## Summary

A fresh upstream-main reproduction shows the gateway repeatedly retaining its own exec-approvals lock and failing closed until external deletion. The only same-repository candidate fix closed unmerged, while the open contributor patch still needs maintainer review and mounted-filesystem proof, so this bug remains necessary.

## What This Changes

Fix the exec-approvals lock lifecycle so repeated gateway exec and cron policy accesses do not strand a live-owner sidecar and permanently fail closed.

## Best Possible Solution

Repair acquisition and release ownership at the shared file-lock implementation or its exact leaking caller, preserve fail-closed policy validation and cross-process serialization, add repeated acquire/release plus sync/async regression coverage, and prove the result with a real Docker Desktop VirtioFS gateway run that leaves no stranded sidecar.
