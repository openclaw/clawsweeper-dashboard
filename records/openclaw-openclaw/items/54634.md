## Summary

Keep open: current main still leaves the cross-HOME Linux update path unresolved, and the related open work is adjacent or not merge-ready rather than a merged fix for this specific config-root split.

## What This Changes

The issue reports that updating to 2026.3.24 changed the systemd service HOME from /home/openclaw to /root, causing OpenClaw to abandon the existing config/state and start from a skeletal root config.

## Best Possible Solution

Add a Linux update/service-refresh guard that discovers the previously installed gateway service root before rewriting it, compares HOME, OPENCLAW_HOME, OPENCLAW_STATE_DIR, and OPENCLAW_CONFIG_PATH against the updater environment, and either preserves the prior root when safe or blocks with clear migration guidance.

## Reproduction Assessment

Yes at source level, but not with a live run. The report gives a concrete cross-HOME Linux update path, and current code still resolves config, state, and systemd user-unit discovery from the process environment; this review did not run a live cross-user systemd upgrade.

## Solution Assessment

Unclear until maintainers choose the compatibility and security policy. The best shape should prevent cross-HOME config abandonment without broadly reusing stale service env or exposing sibling-user credential-bearing state.
