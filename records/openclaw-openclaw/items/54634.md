## Summary

Keep open: current main and the latest checked release still leave the reported Linux systemd cross-HOME update path unresolved. Update/service discovery and default config resolution remain anchored to the updater HOME unless explicit OpenClaw path variables are present, while forced reinstall intentionally drops prior HOME and OpenClaw control env, so the fix needs maintainer-approved preserve/block/migrate policy instead of cleanup closure.

## What This Changes

The issue requests update safeguards so a service HOME change does not silently abandon an existing OpenClaw config/state directory and start a skeletal gateway config.

## Best Possible Solution

Add a Linux update/service-refresh guard that identifies the installed gateway service root before rewriting, then blocks with a clear doctor migration path or preserves the prior root only under an explicit, secure owner-approved policy.
