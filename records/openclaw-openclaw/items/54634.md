## Summary

Keep open: current main has adjacent update/service hardening, but the reported HOME-only config split is still not safely handled because update discovery starts from the updater environment and service refresh/reinstall paths still do not preserve, migrate, or block on an installed service HOME change.

## What This Changes

The issue reports that updating to 2026.3.24 changed the managed systemd service HOME from `/home/openclaw` to `/root`, abandoning the existing config/state and starting the gateway from a sparse root-owned config.

## Best Possible Solution

Add a Linux update/service-refresh guard that identifies the installed gateway service HOME/config root before rewriting, then either preserves the prior root when policy-safe or blocks with a clear doctor migration path and backup instead of silently creating a new root config.
