## Summary

Keep open: current main still derives Linux service discovery and default config/state roots from the updater process environment, so the reported cross-HOME update path is not fixed by main or by the related open moltbot recovery PR.

## What This Changes

The issue asks OpenClaw to prevent updates from silently switching a Linux gateway from the existing HOME/config root to a different HOME with a sparse config.

## Best Possible Solution

Add a Linux update/service-refresh guard that compares the previously installed service root with the updater root and preserves, blocks, or directs doctor migration under an explicit security policy with live systemd upgrade proof.

## Reproduction Assessment

Yes at source level: the issue gives concrete upgrade steps and current main still has HOME-keyed service discovery plus reinstall behavior that drops prior control roots, but no live cross-user systemd upgrade was run here.

## Solution Assessment

Unclear until maintainers choose the compatibility and privacy policy; the fix should prevent cross-HOME config abandonment without broadly reusing stale service env or leaking sibling-user state.
