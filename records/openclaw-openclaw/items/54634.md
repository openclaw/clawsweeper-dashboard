## Summary

Keep open: current main and v2026.6.11 still lack a safe cross-HOME Linux service-root guard, and the related open PRs cover adjacent slices or are not safe canonical replacements for this report.

## What This Changes

The issue reports that a 2026.3.24 update rewrote the Linux systemd gateway service under a different HOME, abandoning the existing config/state and breaking the gateway.

## Best Possible Solution

Add a Linux update/service-refresh guard that detects a previously installed gateway under a different HOME or config/state root and then blocks with clear recovery guidance or performs an explicit maintainer-approved migration path.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: When an updater runs under a different HOME than the existing Linux systemd gateway service, should OpenClaw preserve the old service root, block and ask for explicit migration, or automatically migrate config/state into the new root?

Rationale: The implementation choice affects credential-bearing config, Unix user boundaries, and existing hardening that intentionally drops stale service HOME and OPENCLAW_* values on reinstall.

Likely owner: steipete

Owner reason: steipete has recent central history on package-update restart behavior and is the best available owner for the update/service decision.

Owner confidence: high

Options:

- **Block on cross-HOME mismatch (recommended):** Detect the old service root before rewriting and fail closed with a doctor/reinstall migration path unless the operator explicitly opts into migration.
- **Preserve prior service root automatically:** Keep the existing service HOME/config/state when it can be read safely, accepting more compatibility but more risk of reusing stale service env.
- **Defer to broader systemd migration PR:** Wait for a refreshed systemd managed-env PR to settle service-root and drop-in migration behavior together.

## Reproduction Assessment

Yes at source level: the issue gives concrete upgrade steps, and current main still has HOME-keyed systemd lookup plus reinstall behavior that drops prior HOME/OPENCLAW_* roots. A live cross-user systemd upgrade proof is still missing.

## Solution Assessment

Unclear until maintainers choose the cross-user security boundary. The narrowest maintainable solution is a guarded update/service-refresh path, not broadly reusing all stale service environment values.
