  - body: The new transport treats `openai-codex` as a live provider family again. OpenClaw's current provider contract folds Codex into `openai` and treats `openai-codex` only as legacy input for doctor/migration, so adding a new runtime route here can create conflicting auth/provider behavior.
  - confidence: 0.84
- **[P2] Keep the Codex WebSocket beta header:** `src/agents/pi-embedded-runner/codex-proxy-transport.ts:802`
  - body: `buildWebSocketHeaders` sets the required Responses WebSocket beta header, but this line deletes it before opening the socket. The sibling Codex implementation and tests require `OpenAI-Beta: responses_websockets=2026-02-06` on the WebSocket handshake, so this proxy transport will fail or speak the wrong protocol with compliant Codex backends.
  - confidence: 0.88
- **[P2] Normalize UUID links for the selected agent, not only main:** `ui/src/ui/app-settings.ts:51`
  - body: This only strips the `agent:main:` prefix. If a user's default/selected agent is not `main`, a legacy Control UI URL like `agent:work:<uuid>` will keep the prefixed key while the backend now preserves `<uuid>` as the canonical identity, so the same Open WebUI chat can still split or fail to converge in non-main setups.
  - confidence: 0.86
- **[P2] Preserve UUID-shaped main-key aliases:** `src/gateway/session-utils.ts:668`
  - body: Returning bare UUIDs before checking the configured main-key alias changes behavior for any install whose `session.mainKey` is UUID-shaped: that key used to resolve to the global main session, but this patch treats it as an external opaque chat id. Please keep the main-key mapping ahead of the UUID special case or add explicit migration/proof that UUID-shaped main keys are impossible.
  - confidence: 0.78
- **[P2] Keep UUID aliases scoped across combined stores:** `src/gateway/session-utils.ts:643`
  - body: Returning a bare UUID as the resolved store key removes the agent namespace that the combined session store normally uses to route agent-scoped entries. In multi-agent or changed-default-agent installs, list/edit/send round trips can look up the same UUID against the wrong agent store unless the patch carries the originating agent scope through the alias contract.
  - confidence: 0.74
