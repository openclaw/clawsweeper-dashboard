  - confidence: 0.88
- **[P1] Keep UUID sessions scoped in combined-store round trips:** `src/gateway/session-utils.ts:643-645`
  - body: Returning a bare UUID from agent-store canonicalization drops the owning agent when per-agent stores are combined. With multiple agent stores or a changed default agent, later list/get/patch/delete round trips can resolve the UUID under the wrong owner or miss the original row; carry the store agent id or use an explicit alias contract instead.
  - confidence: 0.84
- **[P2] Normalize UUID links for the configured default agent:** `ui/src/ui/app-settings.ts:51-52`
  - body: The URL normalizer only strips `agent:main:<uuid>`, but the default agent can be configured to a different id. Those `agent:<default>:<uuid>` links would stay prefixed in settings and can recreate the split this PR is trying to avoid.
  - confidence: 0.78
- **[P1] Use a WebSocket client with proven header support:** `src/agents/pi-embedded-runner/codex-proxy-transport.ts:809`
  - body: If the Codex proxy remains, constructing `globalThis.WebSocket` with a nonstandard `{ headers }` init does not prove auth and beta headers are sent in every supported runtime. Upstream Codex builds an authenticated websocket request explicitly, so this proxy path needs a proven client or should be removed with the rest of the unrelated transport work.
  - confidence: 0.76
