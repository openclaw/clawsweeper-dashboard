## Summary

Keep open: this focused warning is not merge-ready because it prints before current update restart handling knows whether the Gateway was already restarted and verified, and the contributor proof is test/static only for a linked P1 message-loss regression.

## What This Changes

Adds a success-case update result warning in `src/cli/update-cli/progress.ts` when the before and after package versions differ, telling users to restart the Gateway.

## Best Possible Solution

Keep restart guidance tied to the actual update outcome: warn only when restart is skipped, failed, no service is found, or health remains bad, while the canonical stale-gateway issue stays open until a live-proven fix lands.

## Reproduction Assessment

No live current-main reproduction was run in this read-only review. Source inspection gives a high-confidence reproduction path for the PR defect: `printResult` would emit the warning before later restart handling decides whether the Gateway was restarted and verified.

## Solution Assessment

No, not as written. A warning can be a limited mitigation, but this placement is too broad for current managed update semantics and too narrow to close the linked raw rollback delivery bug.
