## Summary

Keep open: the PR targets a real P1 stale-gateway problem, but this warning is placed before current managed-update restart verification and the contributor proof is only static/test-style, so it is not merge-ready.

## What This Changes

Adds a success-case update result warning in `src/cli/update-cli/progress.ts` when before/after versions differ, telling users to restart the gateway.

## Best Possible Solution

Keep restart guidance tied to the actual update outcome: warn only when restart was skipped, failed, no service was found, or the restarted Gateway remains unhealthy, while keeping the canonical issue open until a live-proven fix lands.

## Reproduction Assessment

No live current-main reproduction was run for the original stale-gateway bug. Source inspection gives a high-confidence reproduction path for the PR defect: the warning would print in `printResult` before `maybeRestartService` decides whether the Gateway was restarted and verified.

## Solution Assessment

No, not as written. A warning can be a limited mitigation, but this placement is too broad for current managed update semantics and too narrow to close the linked raw rollback delivery bug.
