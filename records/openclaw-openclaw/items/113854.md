## Label Justifications

- `P1`: A wedged shared Chrome tab can prevent core browser operations from listing or selecting otherwise healthy tabs in an established connection.
- `merge-risk: 🚨 availability`: The new `/json/version` worker probe can intentionally return 503 for upgraded extensions that previously appeared connected, changing browser connection availability.

## Summary

Keep this PR open for normal merge review. The patch targets the established-connection portion of the reported browser hang and has focused regression coverage, but the external contribution needs inspectable after-fix real behavior proof before merge; the new capability-gated health probe also deserves explicit upgrade-path confirmation because it can turn a connected-but-unresponsive extension into a fast 503 response.

## What This Changes

The PR avoids Runtime-dependent page-title reads during Chrome extension relay enumeration, reuses pending CDP target-info reads, and adds a capability-negotiated extension worker probe for relay health checks.

## System Context

OpenClaw’s browser extension relay exposes shared Chrome tabs to Playwright-based browser tools. Browser commands query the relay for targets, then use the selected target for listing, opening, and snapshots; this change keeps one unresponsive renderer from blocking healthy shared tabs.
