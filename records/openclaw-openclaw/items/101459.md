## Summary

Keep open: current main still has an unresolved OpenAI Responses compatibility/policy gap in the newer @openclaw/ai provider path, and the related proof-positive implementation candidate is open but not merged or product-accepted.

## What This Changes

The issue requests that openai-responses send the system prompt as a developer message for reasoning models when routed through Responses-compatible relays that reject system messages.

## Best Possible Solution

Settle one default-preserving Responses compatibility path, preferably by making @openclaw/ai honor a documented opt-in such as existing supportsDeveloperRole or a maintainer-approved instructions-placement switch, with coverage for both @openclaw/ai and the legacy transport.
