## Summary

Keep open: current main already selects `developer` when the runtime model has `reasoning: true`, but the broader strict-relay failure remains unresolved and the open candidate PR is draft/conflicting and product-gated.

## What This Changes

The issue reports that `openai-responses` sends the system prompt as an `input` message with `role: "system"` for reasoning models, causing strict OpenAI-compatible Responses relays to reject requests.

## Best Possible Solution

Land or replace the open candidate with a default-preserving Responses compatibility path, plus focused proof for the reported config-to-runtime role resolution and strict-relay prompt placement.
