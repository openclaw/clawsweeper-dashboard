## Summary

Keep open: the strict OpenAI-compatible Responses relay failure is still a live provider-compatibility problem, but the safest fix shape is a maintainer-approved default-preserving compatibility path rather than a global switch from `system` to `developer`.

## What This Changes

The issue reports that custom `openai-responses` reasoning models can send the system prompt as an `input` message with `role: "system"`, causing strict OpenAI-compatible relays to reject every request.

## Best Possible Solution

Land or replace the candidate with a default-preserving OpenAI Responses compatibility path, with coverage for strict relays and for providers that reject `developer`.

- **Sponsor default-preserving compat (recommended):** Keep current defaults and accept an opt-in prompt-placement or equivalent compatibility switch with docs, tests, and upgrade-safe validation.
- **Repair only reasoning role propagation:** Treat this as a narrow bug if maintainers want `reasoning: true` custom Responses models to send `developer` without adding a new placement mode.
- **Decline core support for strict relays:** Keep current behavior and direct affected operators to `openai-completions` or provider-specific workarounds until a broader provider policy is designed.

## Solution Assessment

The narrower maintainable solution is a maintainer-approved, default-preserving compatibility path or a focused reasoning propagation repair if live proof confirms that narrower bug.
