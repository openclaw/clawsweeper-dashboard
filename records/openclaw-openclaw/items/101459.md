## Summary

Keep open. Current main and the latest release still use conservative developer-role compatibility detection for non-native OpenAI-compatible Responses endpoints, which can send `role: "system"` for reasoning models through relays like the reported new-api path; no duplicate issue or fixing PR currently owns this case.

## What This Changes

The issue asks OpenClaw to send `role: "developer"` instead of `role: "system"` for `openai-responses` reasoning models routed through OpenAI-compatible relays.

## Best Possible Solution

Define the Responses proxy developer-role policy explicitly: either keep the conservative default with documented and tested `compat.supportsDeveloperRole: true` opt-in, or add a narrowly scoped Responses-only default/detection change with regression coverage for both relay styles.
