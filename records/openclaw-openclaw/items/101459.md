## What This Changes

The issue requests that `openai-responses` send the system prompt as `role: "developer"` for reasoning models, or otherwise avoid strict relay rejection of prompt messages in Responses `input`.

## Best Possible Solution

Land or replace the open candidate with a default-preserving Responses compatibility path that covers strict relays while preserving the existing provider class that rejects `developer`.

- **Flip reasoning Responses to developer:** Make reasoning custom Responses models send `developer` by default, accepting the known regression risk for providers that reject developer role.

## Solution Assessment

No, a global switch to `developer` is too broad by itself because current tests and history protect providers that reject `developer`. A default-preserving opt-in compatibility path is the safer direction if maintainers accept the config surface.
