## Summary

Keep open: current main still defaults custom non-OpenAI Responses endpoints away from `developer`, and the remaining strict-relay behavior needs a maintainer compatibility-policy decision rather than another automatic fix.

## What This Changes

The issue asks OpenClaw to send `developer` instead of `system` for reasoning `openai-responses` custom providers whose relays reject system prompt messages.

## Best Possible Solution

Settle a default-preserving Responses compatibility policy: document or use existing `compat.supportsDeveloperRole` for relays that accept `developer`, and sponsor an opt-in instructions-placement path only if maintainers want core support for relays that reject prompt messages in `input`.
