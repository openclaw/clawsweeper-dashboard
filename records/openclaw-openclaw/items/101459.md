## Summary

Keep open: current main and v2026.6.11 still have unresolved OpenAI Responses compatibility behavior for strict OpenAI-compatible relays, and the active implementation candidate is open, draft, conflicting, and product-gated rather than merged.

## What This Changes

The issue reports that `openai-responses` sends the system prompt as a `system` input message instead of the expected `developer` role or another strict-relay-compatible placement for reasoning models.

## Best Possible Solution

Settle one default-preserving Responses compatibility path in the current `@openclaw/ai` provider, with tests/docs for strict relays and no global role flip unless maintainers explicitly accept that compatibility tradeoff.

- **Decline core support:** Treat this relay class as unsupported in core and point affected users to `openai-completions` or an external relay/plugin-specific workaround.
