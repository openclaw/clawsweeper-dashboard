## Summary

Keep open: the report is credible and current main has not settled the strict OpenAI-compatible Responses relay behavior; an open draft PR already covers the likely compatibility path, but maintainer product direction is still needed before a fix should land.

## What This Changes

The issue reports that `openai-responses` sends the system prompt as an `input` message with `role:"system"` for a reasoning model, causing strict OpenAI-compatible Responses relays to reject the request.

## Best Possible Solution

Settle one default-preserving Responses compatibility path, preferably by reviewing or replacing the linked candidate PR with an opt-in request-shape switch that covers strict relays without changing defaults for existing providers.

- **Decline core support for this relay class:** Document `openai-completions` or relay-specific workarounds and leave strict `/responses` prompt-placement behavior outside OpenClaw core for now.
