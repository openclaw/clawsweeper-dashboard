## Summary

This PR has credible current-head proof and addresses the reported credential-resolution defect, but it intentionally changes the compatibility boundary between an explicit unavailable Ollama SecretRef and ambient `OLLAMA_API_KEY`. A maintainer should confirm that fail-closed behavior is the desired product contract before merge.

## What This Changes

The PR updates the Ollama web-search plugin so an env-backed `models.providers.ollama.apiKey` SecretRef resolves for requests, while unavailable explicit SecretRefs stop before an ambient cloud credential is used.

## System Context

Ollama web search reads provider configuration and environment credentials before constructing guarded HTTP requests. The plugin first tries configured Ollama hosts, then may use a separate ambient cloud credential for fallback requests.

## Best Possible Solution

Confirm the credential-precedence contract, then retain the explicit configured-reference state and its zero-request failure path if fail-closed is intended; otherwise preserve ambient fallback only through an explicitly documented compatibility policy.
