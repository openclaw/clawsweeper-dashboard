## Summary

This PR remains necessary because current main still does not resolve configured Ollama web-search SecretRefs, but the latest head still treats an unavailable configured SecretRef like no configured credential and permits ambient `OLLAMA_API_KEY` fallback. The prior P1 finding therefore remains unresolved, and the earlier loopback proof does not cover the behavior of the current head.

## What This Changes

Routes the configured Ollama web-search API key through the shared credential resolver and adds tests for env-backed SecretRefs and separate configured-versus-ambient credentials.

## Best Possible Solution

Keep shared SecretRef resolution, but preserve whether a credential was explicitly configured so an unavailable configured ref throws before any request while true no-config and mixed configured-key/ambient-key setups retain their intended fallback; cover all states with focused tests and fresh exact-head redacted loopback output.
