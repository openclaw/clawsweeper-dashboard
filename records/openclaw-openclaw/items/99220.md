## Best Possible Solution

Land the narrow onboarding retry fix after normal PR validation because it preserves saved/discovered reconnect semantics and reuses the existing manual auth path.

## Reproduction Assessment

## Solution Assessment

Yes: reusing the onboarding `connectManual()` path for manual/no-record retries is the narrow maintainable fix because that helper already reads the current manual host/port/TLS/token/password state. Moving this into `connectLastKnown()` would also affect settings and root-tab saved reconnect behavior.
