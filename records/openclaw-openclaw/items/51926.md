## What This Changes

The PR changes the agents `nodes` tool `describe` branch to read `node` as optional and call `resolveNodeId(..., true)` so omitted-node calls use default-node resolution.

## Best Possible Solution

Merge or replace this with a narrow nodes-tool fix that explicitly defines omitted-node `describe` behavior, preserves explicit-node requirements for targeted actions, adds focused regression coverage, and includes redacted real behavior proof.

## Reproduction Assessment

Yes, by source inspection. Current main allows `node` to be omitted in the flattened schema while the `describe` branch still reads it as required, so `{ "action": "describe" }` reaches the reported `node required` path before default resolution.

## Solution Assessment

Unclear whether this is the best final fix. The patch is a plausible narrow repair, but maintainers still need to choose between default-node `describe` and list-style discovery semantics before treating it as the settled contract.
