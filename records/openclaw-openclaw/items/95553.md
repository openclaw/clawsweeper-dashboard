## Label Justifications

- `P1`: The issue reports a real large-session workflow where every near-limit turn can spend about a minute in doomed preflight compaction before proceeding un-compacted.
- `impact:session-state`: The affected path mutates transcript/context compaction state before the next agent turn and can leave session context near overflow.
- `impact:crash-loop`: Repeated preflight timeouts and session write-lock contention can keep the session effectively unavailable in a retry-like failure loop.

## Summary

Keep open: current main and the latest stable release still pass the reply-operation abort signal into required budget/preflight compaction, so the configured compaction timeout can still be bypassed; open PR #95590 is the active candidate fix but is not merged.

## What This Changes

Make budget/preflight compaction honor `agents.defaults.compaction.timeoutSeconds`, or provide a preflight-disable config gate for slow compaction deployments.

## Best Possible Solution

Land one canonical cancellation-signal fix, likely #95590 if maintainers accept its contract, preserving explicit user/restart cancellation and handling any config gate separately.
