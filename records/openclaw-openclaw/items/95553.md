## Summary

Keep open: current main and v2026.6.11 still pass the reply-operation abort signal into required budget/preflight compaction, so the reported timeout cap remains unresolved while an open closing PR is the active candidate fix.

## What This Changes

The issue reports that budget/preflight compaction is canceled by the reply operation's roughly 60s abort signal instead of the configured compaction timeout, causing repeated large-session failures and no preflight-specific opt out.
