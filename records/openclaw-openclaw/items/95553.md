## Summary

Keep open: current main and the latest release still pass the raw reply-operation abort signal into required budget/preflight compaction, so the reported timeout race remains. The open linked PR is a candidate fix, not a merged fix, and maintainers still need to choose the exact cancellation contract.

## What This Changes

The issue reports that budget/preflight compaction is canceled by the reply-operation abort signal around the reply lifecycle timeout instead of being governed by `agents.defaults.compaction.timeoutSeconds`, causing slow valid compactions to fail repeatedly.

## Best Possible Solution

Land or replace the narrow linked fix so required preflight compaction is bounded by the compaction timeout while preserving explicit cancellation; avoid adding a new config gate unless maintainers explicitly choose that product surface.
