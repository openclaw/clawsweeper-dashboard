## Summary

Keep open: current main and the latest release still wire the raw reply-operation abort signal into required budget preflight compaction, and the open linked PR is a candidate fix rather than a merged implementation.

## What This Changes

The issue reports that budget-triggered preflight compaction is cancelled by the reply-operation timeout before the configured compaction timeout can take effect.

## Best Possible Solution

Land a narrow fix that gives required budget preflight compaction a scoped cancellation signal which preserves explicit user/restart cancellation while leaving timeout ownership with the configured compaction timeout.

Options:

- **Filter lifecycle timeout only (recommended):** Adopt the linked PR shape so explicit abort/restart still cancels preflight while lifecycle timeout no longer caps compaction below `compaction.timeoutSeconds`.
- **Drop reply abort for preflight:** Make compaction timeout the only owner for required preflight work, accepting slower response to explicit user/restart cancellation.
- **Add an opt-out config gate:** Add a new preflight-disable knob, but this expands config surface and does not fix the default cancellation race by itself.

## Solution Assessment

The best fix appears to be the linked PR's narrow cancellation-signal repair, because it preserves explicit stop/restart cancellation while removing lifecycle timeout ownership from required compaction. A new config gate alone is less suitable because it expands config surface and leaves default behavior broken.
