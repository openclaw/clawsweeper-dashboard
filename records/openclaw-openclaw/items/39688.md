## Summary

Keep open: current main and v2026.6.11 still fire the `message:received` internal hook without retaining or draining `event.messages`, while docs say `message:received` is replyable. The open canonical PR https://github.com/openclaw/openclaw/pull/41375 uses closing syntax for this issue and should remain the fix path.

## What This Changes

The issue reports that internal hook replies pushed into `event.messages` from `message:received` and `message:sent` are not delivered back to users.

## Best Possible Solution

Rebase and repair the canonical fix PR, then land `message:received` hook reply delivery on replyable surfaces while keeping `message:sent` lifecycle-only unless maintainers explicitly broaden that contract.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: register a `message:received` internal hook that pushes text into `event.messages`; current `main` fires the hook without retaining or draining that array, so nothing is routed back.

## Solution Assessment

Yes for the linked maintainer direction, but it is not solved on current `main`. The narrow maintainable fix is to repair and land the canonical PR for `message:received` replyable-surface delivery, not to add new `message:sent` auto-reply behavior without a separate product decision.
