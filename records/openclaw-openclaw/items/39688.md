## Summary

Keep open: current main and the latest release still fire `message:received` internal hooks without retaining or draining `event.messages`, while the docs now describe `message:received` as replyable. The open maintainer PR https://github.com/openclaw/openclaw/pull/41375 is the active fix path, so the issue should stay paired to that PR rather than be closed or sent to a new repair lane.

## What This Changes

The issue reports that internal `message:received` and `message:sent` hook replies accumulated in `event.messages` are not delivered back to users.

## Best Possible Solution

Repair and land https://github.com/openclaw/openclaw/pull/41375, or an equivalent maintainer-owned replacement, so `message:received` hook replies are drained through the normal reply routing and policy gates while `message:sent` remains documented as lifecycle-only unless maintainers choose a new contract.
