## Summary

Keep open. The patch covers the ordinary dead-PID case, but a numeric PID can be reused by an unrelated process after restart; in that case the new liveness check accepts the stale record and the original resume hang can remain. It also needs after-fix runtime evidence rather than only mocked tests.

Likely related people: marin19 — proposed ACPX change committer (low-confidence routing signal from the supplied commit context).

## What This Changes

The PR makes ACPX discard persisted sessions when their recorded wrapper PID or matching lease root PID is no longer alive, with regression tests for live and dead PID cases.

## System Context

ACPX stores session records for ACP wrapper processes so inbound channel messages can resume an existing ACP session. The gateway loads that record before routing the next turn; a stale record must be rejected so a fresh wrapper session can be created instead of contacting a dead process.

## Best Possible Solution

Use a stable wrapper identity or a restart-scoped ownership invariant before resuming persisted ACP state, then demonstrate one real gateway-restart recovery with redacted runtime output.
