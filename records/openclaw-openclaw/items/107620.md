## Summary

This remains a useful, mergeable bug-fix PR: the production Signal container path currently coerces span offsets with `Number(...)`, while the patch moves parsing to the existing strict integer boundary and supplies convincing real-container wire proof. No blocking correctness or security defect was found; normal maintainer review should explicitly accept the small compatibility narrowing before merge.

## What This Changes

The PR makes Signal container text-style span offsets use strict non-negative decimal integer parsing and adds direct parser plus send-path regression coverage.

## Best Possible Solution

Land strict parsing at the Signal container translation boundary while preserving valid decimal behavior and treating rejected malformed spans through the existing drop path.

## Solution Assessment

Yes. Parsing once at the Signal container translation boundary with the existing shared strict-integer helper is narrower and more maintainable than adding downstream bounds or special cases, and it preserves the established malformed-entry drop behavior.
