## Summary

Keep this open: current main and v2026.6.11 already support typed Docker GPU passthrough, but host IPC and generic Docker-argument passthrough remain absent and require a sandbox security-boundary decision.

## What This Changes

The issue requests configurable Docker sandbox flags, especially GPU passthrough and host IPC, for GPU-accelerated workloads inside sandbox containers.

## Best Possible Solution

Keep the shipped typed GPU support, and add host IPC only if maintainers approve a narrow audited break-glass config field with schema, docs, config hashing, Docker create-args support, security-audit coverage, and tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose host IPC for Docker sandboxes, and if yes should it be a narrow `sandbox.docker.ipc` break-glass field instead of generic raw Docker argument passthrough?

Rationale: GPU passthrough is already implemented and shipped, while host IPC/raw args would change the sandbox isolation boundary and public config contract.

Likely owner: steipete

Owner reason: The strongest history signal for namespace-sharing sandbox hardening is steipete's work on blocked container namespace joins and dangerous Docker override handling.

Owner confidence: high

Options:

- **Add narrow IPC break-glass field (recommended):** Expose a typed opt-in IPC setting with validation, docs, config hashing, Docker create args, security-audit coverage, warnings, and tests while keeping raw Docker args unsupported.
- **Reject host IPC in core:** Document GPU passthrough as the supported high-power Docker path and keep host IPC unavailable because it weakens sandbox isolation.
- **Define broader namespace policy first:** Pause implementation until maintainers define one policy for IPC, PID, network namespace joins, capabilities, and other dangerous Docker options.

## Reproduction Assessment

Yes. Source inspection reproduces the current state: typed `sandbox.docker.gpus` is accepted and emitted, while host IPC and raw Docker run arguments are absent from the config type, strict schema, resolver/create-args path, docs, and security-audit surface.

## Solution Assessment

No for generic Docker-flag passthrough. The maintainable solution is either no host IPC support or a narrow typed break-glass setting with maintainer security review and targeted validation.
