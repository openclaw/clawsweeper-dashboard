## Summary

Keep this open: current main and v2026.6.11 already cover the GPU request through typed `sandbox.docker.gpus`, but host IPC or raw Docker flag passthrough is still absent and remains a sandbox security-boundary decision.

## What This Changes

Request support for additional Docker sandbox parameters, especially GPU passthrough and host IPC/raw Docker flags.

## Best Possible Solution

Keep the shipped typed GPU support, and only add a narrow audited host IPC break-glass field if security owners approve the sandbox tradeoff; keep generic raw Docker argument passthrough unsupported.

Rationale: GPU support is already shipped, while the remaining host IPC/raw-args request changes the sandbox isolation boundary and public config contract.

Owner confidence: high

Options:

- **Add narrow host IPC field (recommended):** Add an explicit opt-in IPC setting with schema, docs, config hashing, Docker create args, security-audit coverage, and warnings while keeping raw Docker args unsupported.
- **Reject host IPC in core:** Document that host IPC weakens sandbox isolation and keep GPU passthrough as the supported high-power Docker path.
- **Design broader namespace policy:** Pause implementation until maintainers define one policy for IPC, PID, network namespace joins, capabilities, and other dangerous Docker options.

## Solution Assessment
