## Summary

Keep this open: current main and v2026.6.11 cover the GPU half with typed `sandbox.docker.gpus`, but host IPC or raw Docker flag passthrough is still absent and remains a sandbox security-boundary decision.

## What This Changes

Request to allow Docker sandbox configuration to pass parameters such as `--gpus all` and `--ipc=host`.

## Best Possible Solution

Keep the shipped typed GPU support, and only add host IPC as a narrow audited break-glass setting if security owners approve it; do not add generic raw Docker argument passthrough.

Options:

- **Add narrow host IPC field (recommended):** Add an explicit opt-in IPC setting with schema, docs, config hashing, Docker create-args, security-audit coverage, and warnings while keeping raw Docker args unsupported.
- **Reject host IPC in core:** Document that host IPC weakens sandbox isolation and keep GPU passthrough as the supported high-power Docker path.
- **Design broader namespace policy:** Pause implementation until maintainers define one policy for IPC, PID, network namespace joins, capabilities, and other dangerous Docker options.

## Solution Assessment

No for generic Docker flag passthrough. The maintainable path is either no host IPC support or a narrow typed break-glass setting with security review and targeted coverage.
