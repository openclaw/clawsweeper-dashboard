## Summary

Keep this open: current main and v2026.6.11 already support the GPU half through typed `sandbox.docker.gpus`, but host IPC or generic Docker flag passthrough is still absent and remains a sandbox security-boundary decision.

## What This Changes

The issue requests configurable Docker sandbox parameters for GPU passthrough and host IPC, including values like `--gpus all` and `--ipc=host`.

## Best Possible Solution

Keep the shipped typed GPU support, and only add host IPC as a narrow audited break-glass setting if security owners approve it; do not add generic raw Docker argument passthrough by default.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose host IPC for Docker sandboxes, and if yes should it be a narrow explicit `sandbox.docker.ipc` break-glass field rather than generic raw Docker argument passthrough?

Rationale: Current source and the latest release already cover GPU passthrough, while host IPC changes the sandbox isolation boundary and public config contract.

Likely owner: steipete

Owner reason: The remaining decision is closest to sandbox namespace hardening and secops-routed security policy, where steipete has the strongest current history signal.

Owner confidence: high

Options:

- **Add narrow host IPC field (recommended):** Add an explicit opt-in IPC setting with schema, docs, config hash coverage, Docker arg emission, security-audit handling, and focused tests while keeping raw Docker args unsupported.
- **Reject host IPC in core:** Document that host IPC weakens sandbox isolation and keep GPU passthrough as the supported high-power Docker path.
- **Design broader namespace policy:** Pause implementation until maintainers define one policy for IPC, PID, network namespace joins, capabilities, and other dangerous Docker options.

## Reproduction Assessment

Yes. Source inspection reproduces the remaining gap: typed `sandbox.docker.gpus` exists and emits `--gpus`, while host IPC and raw Docker run arguments are absent from schema, config resolution, docs, and Docker create args.

## Solution Assessment

No for generic Docker flag passthrough. The maintainable path is either no host IPC support or a narrow typed break-glass setting with security review and targeted tests.
