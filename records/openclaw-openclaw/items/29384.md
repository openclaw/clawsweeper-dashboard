## Summary

Keep this open: current main and v2026.6.11 cover the GPU half through typed `sandbox.docker.gpus`, but host IPC and raw Docker-argument passthrough remain absent and security-sensitive.

## What This Changes

Request to let Docker sandbox configuration pass custom Docker run/create flags such as `--gpus all` and `--ipc=host`.

## Best Possible Solution

Keep the shipped typed GPU support; if maintainers approve host IPC, add a narrow audited break-glass config field with schema, docs, security-audit coverage, and Docker argument tests instead of raw Docker flag passthrough.

## Reproduction Assessment

Yes for source-level reproduction: current main and v2026.6.11 expose `sandbox.docker.gpus`, while source, schema, docs, and tests show no host IPC or generic Docker-argument passthrough. This is a feature gap, not a failing existing behavior path.

## Solution Assessment

No for generic Docker flag passthrough; the safer solution is a narrow typed host IPC option only if maintainers approve the sandbox security tradeoff. The current typed GPU implementation is the right shape for the already-solved GPU half.
