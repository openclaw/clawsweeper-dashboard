## Summary

Keep this open: current main implements the GPU passthrough subset, but host IPC and generic raw Docker argument passthrough remain absent and would require a sandbox security-boundary decision.

## What This Changes

The issue requests configurable Docker sandbox flags such as GPU passthrough and host IPC for sandbox containers.

## Best Possible Solution

Keep typed GPU support, and add host IPC only if maintainers approve a narrow audited break-glass config field with schema, docs, config hashing, security-audit coverage, Docker create-args support, and tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose Docker host IPC for agent sandboxes, and if yes should it be a narrow typed break-glass field rather than generic raw Docker argument passthrough?

Rationale: The remaining request changes the sandbox isolation boundary and public config contract; source inspection shows the safe typed GPU subset is already implemented but host IPC/raw args remain absent.

Likely owner: steipete

Owner reason: The decision is closest to the sandbox namespace/security-boundary policy history represented by the container namespace join hardening work.

Owner confidence: high

Options:

- **Add narrow IPC break-glass field (recommended):** Expose a typed opt-in IPC setting with schema, docs, config hashing, security-audit coverage, Docker create-args support, and tests while keeping generic raw args unsupported.
- **Reject host IPC in core:** Keep GPU passthrough as the supported high-power Docker path and leave host IPC unavailable because it weakens sandbox isolation.
- **Define namespace policy first:** Pause implementation until maintainers define one policy for IPC, PID, network namespace joins, capabilities, and other dangerous Docker options.

Yes, source inspection reproduces the current state: typed `sandbox.docker.gpus` is accepted and emitted, while host IPC and raw Docker run arguments are absent from the config type, strict schema, resolver/create-args path, docs, and security-audit surface.

## Solution Assessment

No for generic raw Docker-flag passthrough. The maintainable path is either no host IPC support or a narrow typed break-glass setting with maintainer security review and targeted validation.
