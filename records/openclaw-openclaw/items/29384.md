## Summary

Keep this open: current main and v2026.6.11 cover the GPU passthrough half with typed `sandbox.docker.gpus`, but host IPC or generic Docker argument passthrough is still absent and needs a sandbox security-boundary decision.

## What This Changes

The issue requests config support for Docker sandbox flags such as GPU passthrough and host IPC.

## Best Possible Solution

Keep typed GPU support as shipped, and add host IPC only if maintainers approve a narrow audited break-glass config field with schema, docs, config hashing, Docker create-args support, security-audit coverage, and tests.

Options:

- **Add Narrow IPC Break-Glass Field (recommended):** Expose a typed opt-in IPC setting with schema, docs, config hashing, Docker create args, security-audit coverage, warnings, and tests while keeping raw Docker args unsupported.
- **Reject Host IPC In Core:** Document GPU passthrough as the supported high-power Docker path and keep host IPC unavailable because it weakens sandbox isolation.
- **Define Broader Namespace Policy First:** Pause implementation until maintainers define one policy for IPC, PID, network namespace joins, capabilities, and other dangerous Docker options.

## Solution Assessment

No for generic Docker-flag passthrough. The maintainable path is either no host IPC support or a narrow typed break-glass setting with maintainer security review and targeted validation.
