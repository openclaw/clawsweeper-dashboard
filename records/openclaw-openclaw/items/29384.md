## Summary

Keep this open: current main and v2026.6.11 cover the GPU request through typed `sandbox.docker.gpus`, but host IPC or generic Docker flag passthrough is still absent and remains a sandbox security-boundary product decision.

## What This Changes

The issue requests Docker sandbox support for GPU passthrough and host IPC/raw Docker parameters such as `--gpus all` and `--ipc=host`.

## Best Possible Solution

Keep the shipped typed GPU support, and add host IPC only if maintainers approve a narrow audited break-glass config field with docs, tests, config hashing, and security-audit coverage; do not add generic raw Docker argument passthrough by default.

Options:

- **Reject host IPC in core:** Document GPU passthrough as the supported high-power Docker path and keep host IPC unavailable because it weakens sandbox isolation.
- **Define broader namespace policy first:** Pause implementation until maintainers define a consistent policy for IPC, PID, network namespace joins, capabilities, and other dangerous Docker options.
