## Summary

Keep this open: current main and the latest release support the GPU passthrough part through typed `sandbox.docker.gpus`, but host IPC or generic Docker flag passthrough is still absent and remains a sandbox security-boundary product decision.

## What This Changes

The issue requests configuration support for additional Docker sandbox parameters such as `--gpus all` and `--ipc=host`.

## Best Possible Solution

Keep the shipped typed GPU support, and add host IPC only if maintainers approve a narrow audited break-glass config field with schema, docs, config hashing, Docker create-args support, security-audit coverage, and tests.

## Maintainer Decision

Rationale: The remaining request changes the Docker sandbox isolation boundary and public config contract; source and release evidence show GPU passthrough is already solved, but host IPC/raw args still require maintainer security direction.

Likely owner: steipete

Owner reason: The strongest current-main policy-history signal for namespace-sharing sandbox hardening is steipete's work on container namespace joins and dangerous Docker override handling.

Owner confidence: high

Options:

- **Add narrow IPC break-glass field (recommended):** Expose a typed opt-in IPC setting with schema, docs, config hashing, Docker create args, security-audit coverage, warnings, and tests while keeping raw Docker args unsupported.
- **Reject host IPC in core:** Document GPU passthrough as the supported high-power Docker path and keep host IPC unavailable because it weakens sandbox isolation.
- **Define broader namespace policy first:** Pause implementation until maintainers define one policy for IPC, PID, network namespace joins, capabilities, and other dangerous Docker options.
