## Summary

Keep this open: current main and v2026.6.11 already cover the GPU portion with typed `sandbox.docker.gpus`, but host IPC or generic raw Docker argument passthrough is still absent and needs a sandbox security-boundary decision.

## What This Changes

The issue asks OpenClaw to let Docker sandboxes pass additional Docker run/create parameters such as `--gpus all` and `--ipc=host`.

## Best Possible Solution

Keep the shipped typed GPU support; if maintainers approve host IPC, add a narrow audited break-glass `sandbox.docker.ipc` field with schema, docs, security validation, config hashing, Docker create-args support, and focused tests instead of generic raw argument passthrough.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose host IPC for Docker sandboxes, and if so should it be a narrow explicit `sandbox.docker.ipc` break-glass field rather than generic raw Docker argument passthrough?

Rationale: The remaining request changes Docker sandbox isolation and the public config contract; current main and the latest release only prove typed GPU passthrough is already implemented.

Likely owner: steipete

Owner reason: The most relevant current-main policy history is the namespace-join hardening and dangerous Docker override work.

Owner confidence: high

Options:

- **Add narrow IPC break-glass field (recommended):** Expose a typed opt-in IPC setting with schema, docs, config hashing, Docker create args, security validation or warning coverage, and focused tests while keeping raw Docker args unsupported.
- **Reject host IPC in core:** Document GPU passthrough as the supported high-power Docker path and keep host IPC unavailable because it weakens sandbox isolation.
- **Define broader namespace policy first:** Pause implementation until maintainers define one policy for IPC, PID, network namespace joins, capabilities, and other dangerous Docker options.

This is a feature/config request rather than a broken existing behavior repro.

## Solution Assessment

No for generic Docker-flag passthrough. The maintainable solution is either no host IPC support or a narrow typed break-glass setting with maintainer security review and targeted validation.
