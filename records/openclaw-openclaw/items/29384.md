## Summary

Keep this open: current main and v2026.6.11 already support the GPU half through typed `sandbox.docker.gpus`, but host IPC or generic Docker flag passthrough is still absent and remains a sandbox security-boundary decision.

## What This Changes

The issue requests configurable Docker sandbox parameters such as GPU passthrough and host IPC for AI/ML workloads.

## Best Possible Solution

Keep the shipped typed GPU support, and add host IPC only if maintainers approve a narrow audited break-glass config field with schema, docs, config hashing, Docker create-args support, security-audit coverage, and tests; avoid generic raw Docker argument passthrough by default.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose host IPC for Docker sandboxes, and if yes should it be a narrow explicit `sandbox.docker.ipc` break-glass field instead of generic raw Docker argument passthrough?

Rationale: Current source and release evidence show GPU passthrough is already implemented, while the remaining host IPC/raw-args request changes the sandbox isolation boundary and public config contract.

Likely owner: steipete

Owner reason: The closest current-main policy trail for namespace-sharing sandbox hardening is steipete's work on container namespace joins and dangerous Docker overrides.

Owner confidence: high

Options:

- **Add narrow IPC break-glass field (recommended):** Expose typed opt-in IPC support with schema, docs, config hashing, Docker create args, security-audit visibility, warnings, and focused tests while keeping generic raw Docker args unsupported.
- **Reject host IPC in core:** Document GPU passthrough as the supported high-power Docker path and keep host IPC unavailable because it weakens sandbox isolation.
- **Define namespace policy first:** Pause implementation until maintainers define one policy for IPC, PID, network namespace joins, capabilities, and other dangerous Docker options.

## Reproduction Assessment

Yes. Source inspection reproduces the current state: typed `sandbox.docker.gpus` is accepted and emitted, while host IPC and raw Docker run arguments are absent from the config type, schema, resolver/create-args path, docs, and security-audit surface.

## Solution Assessment

No for generic Docker-flag passthrough. The maintainable solution is either no host IPC support or a narrow typed break-glass setting with maintainer security review and targeted validation.
