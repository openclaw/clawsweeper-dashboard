## Summary

Keep this open: GPU passthrough is implemented on current main and present in v2026.6.11, but host IPC and generic Docker argument passthrough remain absent and are sandbox security-boundary product decisions.

## What This Changes

Request support for additional Docker sandbox parameters, specifically GPU passthrough and host IPC, through OpenClaw sandbox configuration.

## Best Possible Solution

Keep the shipped typed GPU support; add host IPC only if maintainers approve a narrow audited break-glass config field with schema, config hashing, Docker arg emission, security audit coverage, docs, and tests, while avoiding generic raw Docker args.

Options:

- **Add narrow IPC break-glass field (recommended):** Expose a typed opt-in IPC setting with schema, docs, config hashing, Docker create args, security audit coverage, warnings, and focused tests while keeping raw Docker args unsupported.
- **Reject host IPC in core:** Keep GPU passthrough as the supported high-power Docker path and document that host IPC remains unavailable because it weakens sandbox isolation.
- **Define broader namespace policy first:** Pause implementation until maintainers decide one policy for IPC, PID, network namespace joins, capabilities, and other dangerous Docker options.

## Solution Assessment
