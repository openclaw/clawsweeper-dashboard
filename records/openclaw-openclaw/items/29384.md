## Summary

Keep this open: current main and v2026.6.11 cover the GPU half through typed `sandbox.docker.gpus`, but host IPC or generic Docker flag passthrough is still absent and remains a sandbox security-boundary product decision.

## What This Changes

Request to allow Docker sandbox configuration to pass custom Docker parameters such as GPU passthrough and host IPC.

## Best Possible Solution

Keep the shipped typed GPU support, and add host IPC only if maintainers approve a narrow audited break-glass config field with docs, tests, config hashing, and security-audit coverage; avoid generic raw Docker argument passthrough.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose host IPC for Docker sandboxes, and if yes should it be a narrow explicit `sandbox.docker.ipc` break-glass field instead of raw Docker argument passthrough?

Rationale: The remaining request changes the sandbox isolation boundary and public config contract; source and release evidence already cover GPU passthrough, but not host IPC.

Likely owner: steipete

Owner reason: The namespace-join hardening history makes steipete the strongest individual routing signal for this sandbox isolation decision.

Owner confidence: high

Options:

- **Add narrow IPC break-glass field (recommended):** Expose an explicit audited IPC setting with schema, config resolution, Docker create args, docs, security audit coverage, config hashing, and tests while keeping raw Docker args unsupported.
- **Reject host IPC in core:** Keep GPU passthrough as the supported high-power Docker path and document host IPC as unsupported because it weakens sandbox isolation.
- **Define broader namespace policy first:** Pause implementation until maintainers settle a consistent policy for IPC, PID, network namespace joins, capabilities, and related dangerous Docker options.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 accept and emit typed `sandbox.docker.gpus`, while host IPC and raw Docker run arguments are absent from the config type, strict schema, resolver, create-args path, docs, and targeted grep results.

## Solution Assessment

No for generic Docker-flag passthrough. The maintainable path is either no host IPC support or a narrow typed break-glass setting with maintainer security review and targeted validation.
