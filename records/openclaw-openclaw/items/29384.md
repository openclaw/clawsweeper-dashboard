## Summary

Keep this open: current main and v2026.6.11 already cover the GPU half through typed `sandbox.docker.gpus`, but host IPC or raw Docker flag passthrough is still absent and remains a sandbox security-boundary product decision.

## What This Changes

The issue requests configurable sandbox Docker parameters such as `--gpus all` and `--ipc=host` for AI/ML workloads.

## Best Possible Solution

Keep the shipped typed GPU support, and only add a narrow audited host IPC break-glass field if security owners approve the sandbox tradeoff; avoid generic raw Docker argument passthrough.

- **Reject host IPC in core:** Document that host IPC weakens sandbox isolation and keep GPU passthrough as the supported high-power Docker path.
- **Design broader namespace policy:** Pause implementation until maintainers define a consistent policy for IPC, PID, network namespace joins, capabilities, and other dangerous Docker options.

## Solution Assessment

No for the proposed generic Docker-flag passthrough. The maintainable path is either no host IPC support or a narrow typed break-glass setting with security review, docs, audit coverage, config hashing, and focused tests.
