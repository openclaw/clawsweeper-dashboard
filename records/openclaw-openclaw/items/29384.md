## Summary

Keep this open: current main and v2026.6.11 cover the GPU half with typed `sandbox.docker.gpus`, but host IPC or raw Docker flag passthrough is still absent and remains a sandbox security-boundary decision.

## What This Changes

Request to add Docker sandbox configuration for custom Docker run flags, specifically GPU passthrough and host IPC.

## Best Possible Solution

Keep the shipped typed GPU support, and only add host IPC if maintainers approve a narrow, audited, opt-in Docker IPC config surface with docs and security-audit coverage.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw support host IPC for Docker sandboxes, and if so should it be a narrow audited `sandbox.docker.ipc` field rather than raw Docker flag passthrough?

Rationale: Host IPC changes the sandbox namespace boundary and public config contract, so automation cannot safely decide the permanent policy or acceptable API shape.

Likely owner: openclaw/openclaw-secops

Owner reason: CODEOWNERS assigns the affected sandbox and security paths to this team, and the open question is explicitly about sandbox boundary policy.

Owner confidence: high

Options:

- **Approve narrow audited IPC (recommended):** Add a typed opt-in IPC setting with dangerous-mode docs, validation, security-audit findings, and focused Docker argument tests.
- **Reject host IPC in core:** Keep sandbox isolation stricter and tell users to use a custom external runtime path for workloads that require host IPC.
- **Defer behind broader sandbox design:** Leave the issue open until sandbox privilege knobs such as IPC, capabilities, and namespace joins get a shared policy.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a feature request. Source inspection confirms the remaining host IPC/raw Docker flag surface is absent while GPU passthrough is present.

## Solution Assessment

No, raw custom Docker flag passthrough is not the best solution because it would be too broad for a sandbox boundary. The safer direction is a typed, audited config surface only if maintainers accept host IPC.
