## Summary

Keep this open: current main and v2026.6.11 already support the `--gpus` part through typed `sandbox.docker.gpus`, but host IPC or generic Docker argument passthrough is still absent and remains a sandbox security-boundary decision.

## What This Changes

The issue asks for custom Docker sandbox parameters, specifically GPU passthrough and host IPC, to support GPU-accelerated sandbox workloads.

## Best Possible Solution

Keep the shipped typed GPU support, and add host IPC only if maintainers approve a narrow audited break-glass config field with schema, docs, config hashing, Docker create-args support, security-audit coverage, and tests; do not add generic raw Docker argument passthrough by default.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose Docker host IPC for sandbox containers, and if yes should that be a narrow audited break-glass config field rather than raw Docker argument passthrough?

Rationale: Current source and release evidence show GPU passthrough is already implemented, while the remaining host IPC/raw-args request changes the sandbox isolation boundary and public config contract.

Likely owner: steipete

Owner reason: steipete has the strongest policy-history signal for namespace-sharing sandbox hardening and dangerous Docker override handling.

Owner confidence: high

Options:

- **Add narrow IPC break-glass field (recommended):** Expose a typed opt-in IPC setting with schema, docs, config hashing, Docker create args, security-audit coverage, warnings, and tests while keeping raw Docker args unsupported.
- **Reject host IPC in core:** Document GPU passthrough as the supported high-power Docker path and keep host IPC unavailable because it weakens sandbox isolation.
- **Define broader namespace policy first:** Pause implementation until maintainers define one policy for IPC, PID, network namespace joins, capabilities, and other dangerous Docker options.

## Reproduction Assessment

Yes, source inspection reproduces the current state: typed `sandbox.docker.gpus` is accepted, resolved, tested, documented, and emitted, while host IPC and raw Docker run arguments are absent from the config type, schema, resolver/create-args path, docs, and release surface.

## Solution Assessment

No for generic Docker-flag passthrough. The maintainable solution is either no host IPC support or a narrow typed break-glass setting with maintainer security review, audit visibility, docs, and targeted validation.
