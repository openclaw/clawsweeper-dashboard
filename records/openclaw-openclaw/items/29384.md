## Summary

Keep this open: GPU passthrough is already supported on current main and in v2026.6.11 through typed `sandbox.docker.gpus`, but host IPC or raw Docker flag passthrough is still absent and remains a sandbox security-boundary product decision.

## What This Changes

Request support for passing Docker sandbox options such as GPU passthrough and host IPC into OpenClaw sandbox containers.

## Best Possible Solution

Keep the shipped typed GPU support, and add host IPC only if maintainers approve a narrow audited break-glass config field with schema, docs, config hashing, Docker create-args support, security-audit coverage, and tests; do not add generic raw Docker argument passthrough by default.

## Maintainer Decision

Rationale: GPU passthrough is already shipped, but the remaining host IPC/raw-args request changes the sandbox isolation boundary and public config contract.

Likely owner: steipete

Owner confidence: high

Options:

- **Add narrow IPC break-glass field (recommended):** Expose a typed opt-in IPC setting with schema, docs, config hashing, Docker create args, security audit coverage, warnings, and focused tests while keeping raw Docker args unsupported.
- **Reject host IPC in core:** Keep GPU passthrough as the supported high-power Docker path and document that host IPC remains unavailable because it weakens sandbox isolation.
- **Define broader namespace policy first:** Pause implementation until maintainers decide one policy for IPC, PID, network namespace joins, capabilities, and other dangerous Docker options.
