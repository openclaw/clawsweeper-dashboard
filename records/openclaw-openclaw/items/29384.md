## Summary

Keep this open: the GPU subset is implemented and shipped, but host IPC or generic raw Docker argument passthrough is still absent and remains a sandbox security-boundary product decision.

## What This Changes

The issue requests configuration support for custom Docker sandbox parameters such as `--gpus all` and `--ipc=host`.

## Best Possible Solution

Keep the shipped typed GPU support, and add host IPC only if maintainers approve a narrow audited break-glass config field with schema, docs, config hashing, Docker create-args support, security-audit coverage, and tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose Docker host IPC for agent sandboxes, and if yes should it be a narrow typed `sandbox.docker.ipc` break-glass field instead of generic raw Docker argument passthrough?

Rationale: Current main and the latest release solve GPU passthrough, but the remaining host IPC/raw-args request changes the sandbox isolation boundary and public config contract.

Likely owner: steipete

Owner reason: The closest security-boundary history is the namespace-join hardening and dangerous Docker override work tied to steipete.

Owner confidence: high

Options:

- **Add typed IPC break-glass field (recommended):** Expose a default-off `sandbox.docker.ipc` setting with validation, docs, config hashing, security-audit visibility, warnings, and tests while keeping raw Docker args unsupported.
- **Reject host IPC in core:** Document typed GPU passthrough as the supported high-power Docker path and keep host IPC unavailable because it weakens sandbox isolation.
- **Define broader namespace policy first:** Pause implementation until maintainers decide one policy for IPC, PID, network namespace joins, capabilities, and other dangerous Docker options.

## Reproduction Assessment

Yes. Source inspection reproduces the current state: typed `sandbox.docker.gpus` is accepted and emitted, while host IPC and raw Docker run arguments are absent from the config type, strict schema, resolver/create-args path, docs, and security-audit surface.

## Solution Assessment

No for generic Docker-flag passthrough. The maintainable solution is either no host IPC support or a narrow typed break-glass setting with maintainer security review and targeted validation.
