## Summary

Keep this open: current `main` and `v2026.6.11` cover the GPU request through typed `sandbox.docker.gpus`, but host IPC or raw Docker flag passthrough is still absent and remains a security-boundary product decision.

## What This Changes

The issue requests sandbox Docker configuration for GPU access and host IPC/raw Docker flags such as `--gpus all` and `--ipc=host`.

## Best Possible Solution

Keep the shipped typed GPU support, and only add a narrow audited host IPC break-glass field if security owners approve the sandbox tradeoff; avoid generic raw Docker argument passthrough.

- **Design broader namespace policy:** Pause implementation until maintainers define a consistent policy for IPC, PID, network namespace joins, capabilities, and other dangerous Docker options.

## Solution Assessment

No for the proposed generic Docker-flag passthrough. The maintainable path is either no host IPC support or a narrow typed break-glass setting with security review and targeted tests.
