## Summary

Keep this open: current main and v2026.6.11 already cover the GPU subset through typed `sandbox.docker.gpus`, but host IPC or generic Docker argument passthrough is still absent and needs a sandbox security-boundary decision.

## What This Changes

Request support for passing Docker sandbox flags such as `--gpus all` and `--ipc=host` through OpenClaw configuration.

## Best Possible Solution

Keep the shipped typed GPU support; if maintainers approve host IPC, add a narrow audited break-glass `sandbox.docker.ipc` field with schema, Docker create-args support, security audit coverage, docs, config hashing, and tests rather than generic raw argument passthrough.

Owner confidence: high

Options:

- **Add narrow IPC break-glass field (recommended):** Expose typed opt-in IPC support with schema, Docker create args, security-audit coverage, docs, config hashing, and tests while keeping raw Docker args unsupported.
- **Reject host IPC in core:** Document GPU passthrough as the supported high-power Docker path and keep host IPC unavailable because it weakens sandbox isolation.
- **Define broader namespace policy first:** Pause implementation until maintainers define one policy for IPC, PID, network namespace joins, capabilities, and other dangerous Docker options.

## Solution Assessment

No for generic Docker-flag passthrough. The maintainable solution is either no host IPC support or a narrow typed break-glass setting with maintainer security review and targeted validation.
