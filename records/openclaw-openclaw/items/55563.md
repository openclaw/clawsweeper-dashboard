## Summary

Keep open: current main and v2026.6.11 still lack the browser lazy-subcommand parent-option compatibility fix, while the Gateway half is only partly addressed and still overlaps open runtime-path policy work.

## What This Changes

The issue reports two regressions: `openclaw browser tabs --browser-profile remote` no longer parses, and `openclaw doctor --fix` can cycle a Gateway service that points at an unstable version-manager Node path.

## Best Possible Solution

Keep this composite tracker open until the browser parser fix lands or is replaced, and resolve the Gateway runtime-path policy through https://github.com/openclaw/openclaw/issues/60612 and https://github.com/openclaw/openclaw/pull/82290.

## Reproduction Assessment

Yes for the browser half from source inspection: the parent option remains on `browser`, lazy reparse uses root raw argv, and no current helper hoists parent options placed after `tabs`. The Gateway loop was not live-reproduced here, but current service audit and related work show the remaining runtime-path policy surface.

## Solution Assessment

No current-main solution fully solves this issue. The narrow path is a browser parser compatibility fix plus a maintainer decision on daemon runtime pinning or service-repair policy, not another combined automated repair.
