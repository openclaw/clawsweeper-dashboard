## What This Changes

The PR adds trusted inbound decoration fields and updates transcript persistence, UI extraction/normalization, CLI import dedupe, memory export, and historical LLM replay to prefer the trusted bare body over sentinel stripping.

## Best Possible Solution

Land one maintainer-approved additive trusted inbound-decoration contract with legacy fallback and redaction-boundary tests; if top-level fields are not the intended durable shape, revise the same behavior to the approved OpenClaw-owned metadata location before merge.

## Reproduction Assessment

Yes. Source inspection shows current main writes inbound metadata as literal user-message text and strips those same sentinel strings in UI, CLI, memory, and replay consumers, so sentinel-shaped user text can follow the metadata stripping path.

## Solution Assessment

Yes as the solution class: a trusted out-of-band bare body is the maintainable fix for a forgeable text heuristic. The remaining question is whether the top-level field shape is the best durable OpenClaw-owned contract, or whether maintainers want the same behavior under a narrower metadata envelope.
