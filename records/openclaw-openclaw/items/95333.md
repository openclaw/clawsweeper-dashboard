## Summary

This PR addresses a real transcript/session-state bug, but its producer currently marks a fallback transcript string as a trusted bare body. That breaks the stated trust invariant and can make readers preserve decorated content instead of applying the legacy stripper; the exact-head runtime proof also does not demonstrate the corrected producer path. A maintainer should choose the durable ownership shape for this persisted contract before the mechanical repair lands.

## What This Changes

The branch adds marker-gated `bareBody` metadata for decorated inbound user turns and updates transcript, UI, replay, memory, CLI dedupe, and usage-log readers to prefer it over sentinel parsing.

## Best Possible Solution

Persist a trusted bare body only when an authoritative inbound source supplies one; leave all other turns unmarked so legacy stripping remains active, then add an exact-head producer-to-reader proof for both the trusted and fallback paths.
