## Summary

This PR remains necessary for the linked bug, but the current patch does not establish a trusted producer or a safe ownership boundary: it adds generic top-level fields that readers would treat as authoritative, while the PR discussion states no authoritative inbound producer currently sets them. The branch also currently has merge conflicts, so it should not be closed or merged as-is.

## What This Changes

The branch adds `inboundDecorated`/`bareBody` fields to inbound user-turn persistence and updates UI, replay, CLI dedupe, memory export, and session-log readers to prefer those fields over legacy plaintext metadata stripping.

## System Context

OpenClaw adds host-generated context to inbound user text for the active model prompt, then persists that turn for later UI display, replay, imports, memory indexing, and usage reporting. The proposed contract would let those downstream readers use a host-authored bare body rather than infer it from user-controlled sentinel text.

Store the host-authored decoration facts under the existing OpenClaw-owned per-message metadata envelope, write them exactly where host decoration is created, preserve legacy stripping only for unmarked historical rows, and provide a redacted real inbound gateway/channel transcript showing persistence plus one downstream reader result.
