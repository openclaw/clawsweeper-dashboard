## Summary

This PR addresses a real remaining bug tracked by https://github.com/openclaw/openclaw/issues/95279, but it is not merge-ready: its new trusted fields are not populated by the authoritative inbound-decoration path, and the proposed top-level persisted-message contract conflicts with the existing OpenClaw-owned metadata boundary. The recent fallback fix removes one unsafe heuristic, but without a real producer the new reader paths are dormant for ordinary decorated inbound turns.

## What This Changes

The branch adds `inboundDecorated`/`bareBody` fields to inbound context and persisted user messages, then updates UI, replay, memory, CLI dedupe, and usage-log readers to prefer the marked bare body over sentinel stripping.

## Best Possible Solution

Adopt one OpenClaw-owned metadata shape, write it at the actual inbound-decoration producer alongside the bare body, preserve it through transcript persistence and redaction, and update all readers to consume only that canonical internal metadata with legacy stripping for old rows.
