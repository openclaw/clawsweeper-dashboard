## Summary

Keep open: current main still needs the trusted inbound-decoration fix and the PR has useful proof, but this branch is not merge-ready because it makes top-level serialized message fields authoritative across display, replay, memory, and dedupe consumers.

## What This Changes

The PR adds `inboundDecorated`/`bareBody` fields to inbound contexts and persisted user messages, then updates UI, CLI history, memory export, and LLM replay consumers to prefer the trusted bare body.

## Best Possible Solution

Land the fix with trusted bare-body metadata stored and resolved only from an OpenClaw-owned metadata envelope, keep legacy sentinel fallback for unmarked rows, and expose facade helpers only after maintainers accept the final contract.

## Reproduction Assessment

Yes. Source inspection shows current main still decorates inbound user messages as sentinel text and consumers still strip or compare by those literal headers; the PR-introduced trust-boundary issue is also source-reproducible from the merge result.

## Solution Assessment

No. A trusted out-of-band bare body is the right class of fix, but top-level fields are not the safest durable ownership boundary for a value that UI, replay, memory, and dedupe will trust.
