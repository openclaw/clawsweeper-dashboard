## Summary

Keep this PR open, but it is not ready to merge: the branch adds reader-side handling for a trusted inbound body without adding an authoritative in-repository producer, so ordinary decorated turns remain unmarked and continue through the forgeable legacy stripping path. The proposed top-level serialized fields also need an explicit owner decision before they can be treated as trusted state.

## What This Changes

The PR adds `inboundDecorated` and `bareBody` fields for decorated inbound user messages and updates transcript, UI, replay, dedupe, memory, and usage-log readers to prefer the marked bare body over sentinel parsing.

## Best Possible Solution

Define the contract as OpenClaw-owned serialized metadata, populate it once where inbound decoration and the canonical bare body are created, and then retain one shared reader resolver with legacy stripping only for genuinely unmarked historical records.
