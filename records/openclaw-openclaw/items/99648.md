## What This Changes

The issue reports an intermittent QA Lab Crabline JSONL parsing race where an actively appended trailing record is parsed before its newline arrives.

## Best Possible Solution

Land or intentionally close the linked fixing PR; after it merges, this issue can close as implemented by that PR.

## Reproduction Assessment

Yes from source inspection and the issue's CI evidence: current main parses every non-empty recorder fragment immediately, so a read ending inside the final JSONL row can throw before the writer appends its newline. I did not run the full QA smoke scenario in this read-only review.

## Solution Assessment

Yes, the linked PR's approach is the right repair boundary: defer only an actively non-newline-terminated tail while preserving parse failures for completed malformed or permanently truncated records.
