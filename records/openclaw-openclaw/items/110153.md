## Summary

Keep open. The report describes a plausible channel-visible regression introduced by the structured tool-error work, but the proposed fixes mix a narrow read-only-exit classification bug with a broader policy choice about when a later retry clears an earlier failure; current-main source and tests should settle those boundaries before implementation.

## What This Changes

Fix misleading channel tool-error warnings for benign non-zero shell exits and recovered retries after exit-code-based tool-error classification was introduced.

## Best Possible Solution

Keep failed-mutation warnings intact, but classify known read-only shell no-result outcomes before they enter the unresolved-error path; handle recovery only when the successful follow-up can be causally tied to the failed action, with focused Slack payload and terminal-state regression coverage.
