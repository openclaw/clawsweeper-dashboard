## What This Changes

The PR adds a runtime warning-and-skip guard for MCP server configs that set both non-empty `command` and `url`, plus resolver tests for mixed configs, whitespace-only URLs, and warning sanitization.

## Best Possible Solution

Align the mixed `command` plus `url` rejection across runtime and config validation or doctor diagnostics, then merge after redacted real behavior proof shows the new diagnostic in a real OpenClaw run.

## Reproduction Assessment

Yes. Source inspection shows current main resolves a valid `command` as stdio before evaluating `url` or `transport`, so the reported mixed config takes the wrong transport path.

## Solution Assessment

No, not as submitted. The resolver guard is the right runtime layer because it sees both fields before transport construction, but the best fix should also align config validation or doctor diagnostics with the docs-backed rejection contract.
