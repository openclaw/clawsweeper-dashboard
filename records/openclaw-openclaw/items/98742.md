## Label Justifications

- `P2`: The report describes a bounded session-display regression with user-visible confusion but no confirmed data deletion or core runtime outage.
- `impact:session-state`: The issue concerns session metadata appearing to drift from the persisted session label across UI refresh and session-family display paths.
- `maturity:stable`: The affected session-list/display path runs through the Gateway runtime/hosted web surface, which the maturity shortlist reports as M4 Stable.

## Summary

Keep open: current main already protects the main Control UI list and picker paths by projecting persisted `label` into `displayName`, but label precedence is not canonical across all session display consumers and the derived-title path can still hide a manual label.

## What This Changes

The issue requests consistent rendering of persisted manual session labels across Control UI/WebChat session displays after reloads, reconnects, restarts, and session-family rotations.

## Best Possible Solution

Make label precedence a shared session-display contract and add focused regression coverage for label-only sessions in the derived-title/client path before closing this issue.

## Reproduction Assessment

Yes at source level for the derived-title path: `deriveSessionTitle` ignores `entry.label`, while the TUI session picker requests derived titles and displays them before `displayName`. The exact browser symptom has not been live-reproduced, and current Control UI list requests do not request derived titles.

## Solution Assessment

Unclear: a narrow fix could add label precedence to derived-title or client title resolution, but maintainers should avoid creating another competing session-title rule while overlapping Control UI rename work remains open.
