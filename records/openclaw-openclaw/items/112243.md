## Summary

Keep this issue open for a maintainer product decision: current main deliberately preserves an established external delivery route when WebChat accesses the same session, so the requested automatic route switch would reverse an existing reliability safeguard rather than fix an undefined behavior.

## What This Changes

The issue requests an optional session setting that updates persisted `deliveryContext` to the channel of each incoming message.

## Best Possible Solution

Keep the external route stable by default; if maintainers want current-surface delivery, define one explicit route-policy contract with focused coverage for external-channel turns, WebChat turns, inter-session sends, and asynchronous completion delivery.
