## Label Justifications

- `P0`: The PR addresses a command-execution primitive in plugin and skill git source installs, which is a security-boundary issue.

## Summary

Keep open. Current main still passes parsed user-controlled git install URLs to `git clone` without an option terminator, while this PR hardens both plugin and skill git source installs with the correct Git `--` boundary and a shared parser guard; I found no blocking correctness finding.

## What This Changes

The PR rejects dash-leading `git:` clone specs in the shared parser, adds `--` before parsed clone URLs for plugin and skill git installs, and updates focused regression coverage.

## Best Possible Solution

Land a narrow security hardening that rejects dash-leading `git:` specs and terminates every user-derived clone URL before `git clone`, with focused plugin and skill regression coverage.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: current main accepts dash-leading `.git`-ending `git:` bases through the shared parser and passes them to `git clone` before the destination. Git's own usage confirms `--` is the option terminator and `--upload-pack` is a clone option.

## Solution Assessment

Yes, this is the best narrow fix: harden the shared classifier and both user-sourced clone call sites, while leaving unrelated normalized or constant clone paths alone. The alternative of only rejecting in the parser would be weaker defense in depth than also terminating clone options.
