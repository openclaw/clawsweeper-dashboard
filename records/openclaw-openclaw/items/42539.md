## Summary

Keep this open: current main and v2026.6.11 still lack a Telegram TTS delivery selector, while the existing path captions short text on the voice note and only sends separate text on overflow or fallback. The remaining work is a maintainer product decision about the public TTS delivery contract and config owner.

## What This Changes

Requested behavior is a configurable Telegram TTS mode that sends readable text and the voice note as separate Telegram messages instead of captioning text on the voice note.

## Best Possible Solution

Define a backward-compatible TTS text/voice delivery policy, choose whether it lives globally or under Telegram channel/account config, document it, and require Telegram tests plus live proof for both captioned and separate modes.

## Maintainer Decision

Rationale: The source-level gap is clear, but the fix adds public config/channel behavior and overlaps with active captioned-final and voice-only TTS direction, so automation should not choose the permanent contract.

Owner confidence: high

Options:

- **Approve an explicit separate mode (recommended):** Keep captioned delivery as the default and add an opt-in separate text-plus-voice mode with schema, docs, tests, and live Telegram proof.
- **Keep captioned delivery standard:** Document tagged/manual splitting and overflow fallback as supported workarounds instead of adding another TTS delivery mode.
- **Defer until captioned-final settles:** Wait for https://github.com/openclaw/openclaw/pull/83988 or its replacement before deciding whether separate delivery should become first-class.

## Reproduction Assessment

Yes, source-level. Current main has no `messages.tts.delivery` or equivalent selector, successful TTS still produces one audio-bearing payload, and Telegram keeps short text as a voice caption while splitting only overflow.

## Solution Assessment

Unclear as product direction. A delivery-mode option is plausible, but maintainers should first choose the public contract and reconcile it with captioned-final and voice-only TTS proposals.
