## Summary

Keep open: current main and v2026.6.11 still lack a Telegram TTS delivery selector, and the remaining decision is a public config/channel behavior choice rather than a narrow bug fix.

## What This Changes

Request a configurable Telegram TTS mode that sends full-width text and a separate voice note instead of captioning the text on the voice message.

## Best Possible Solution

Define a backward-compatible TTS delivery policy, choose the global versus Telegram/account config scope, keep captioned voice as the default unless maintainers decide otherwise, and require schema, docs, focused tests, and live Telegram proof for both modes.

## Solution Assessment

Unclear as product direction. A delivery-mode option is plausible, but maintainers should first choose the public contract and reconcile it with captioned-final and voice-only TTS proposals.
