## Summary

Keep this open: current main and v2026.6.11 still lack a Telegram TTS delivery selector, and the related open PR targets captioned final-mode delivery rather than the requested separate text-plus-voice mode.

## What This Changes

Request to add a Telegram TTS delivery mode that sends text and voice as separate messages instead of a voice caption.

## Best Possible Solution

Define a backward-compatible TTS delivery policy that names captioned versus separate behavior, chooses global versus channel-specific ownership, and then implement it with Telegram proof and docs.
