## Summary

Keep this open: current main and v2026.6.11 still lack a Telegram TTS separate text-plus-voice delivery selector, while the active related PR targets captioned final-mode churn rather than the requested full-width text plus separate voice note.

## What This Changes

The issue requests a Telegram TTS delivery mode that sends readable full-width text separately from the voice note instead of captioning the voice message.

## Best Possible Solution

Define a backward-compatible TTS text/voice delivery policy, choose whether it lives globally or in Telegram channel/account TTS config, document it, and require Telegram tests plus live proof for both captioned and separate modes.
