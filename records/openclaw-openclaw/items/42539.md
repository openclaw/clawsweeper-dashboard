## Summary

Keep this open: current main and v2026.6.11 still lack a Telegram TTS separate-delivery selector, and the active captioned-final work is a different single-caption policy rather than an implementation of this request.

## What This Changes

The issue requests a Telegram TTS delivery option that sends readable text and the voice note as separate Telegram messages instead of one captioned voice message.

## Best Possible Solution

Keep this as the canonical Telegram separate text-plus-voice product decision, then implement a backward-compatible, documented delivery policy only after maintainers choose how it should coexist with captioned and voice-only TTS modes.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 lack a TTS delivery selector, and Telegram captions media text unless the caption exceeds 1024 characters. I did not run a live Telegram repro in this read-only review.

## Solution Assessment

Unclear as a product direction. A delivery-mode option is plausible, but maintainers should first reconcile it with captioned final-mode TTS and voice-only/text-suppression proposals before adding public config.
