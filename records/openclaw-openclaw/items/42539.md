## Summary

Keep open: current main and v2026.6.11 still lack a Telegram TTS delivery selector, and the open related PR only addresses captioned final-mode churn rather than the requested always-separate full-width text plus voice mode.

## What This Changes

Request to add a configurable Telegram TTS delivery mode that sends normal text separately from a follow-up voice message instead of putting readable text in the voice caption.

## Best Possible Solution

Define a backward-compatible TTS delivery policy, choose global versus Telegram channel/account scope, keep captioned voice as the default unless maintainers decide otherwise, and require schema, docs, focused tests, and live Telegram proof for both modes.

## Reproduction Assessment

Yes, at source level. Current main has no messages.tts.delivery or equivalent selector, successful TTS still produces one audio-bearing payload, and Telegram keeps short text as a voice caption while splitting only overflow or failure fallback.

## Solution Assessment

Unclear as product direction. A delivery-mode option is plausible, but maintainers should first choose the public contract and reconcile it with captioned-final and voice-only TTS proposals.
