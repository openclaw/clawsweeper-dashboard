## Summary

Keep this open: current main still has no Telegram TTS separate-delivery selector, and the active related work targets captioned final-mode delivery rather than the requested full-width text plus separate voice-note mode.

## What This Changes

The issue requests a Telegram TTS delivery mode that sends readable full-width text separately from the voice note instead of bundling text as a voice caption.

## Best Possible Solution

Define a backward-compatible TTS delivery policy that reconciles bundled/captioned, separate text-plus-voice, overflow fallback, final-mode, and voice-only behavior across config, Telegram delivery, docs, and regression tests.
