## Summary

Keep this open: current main and v2026.6.11 still lack a Telegram TTS mode that intentionally sends full-width text separately from the voice note, and the open captioned-final work solves a different churn problem rather than this requested delivery policy.

## What This Changes

Request a configurable Telegram TTS delivery mode that sends readable text as a normal message and the voice note as a separate message instead of using a voice caption by default.

## Best Possible Solution

Define a backward-compatible TTS delivery policy that names captioned/bundled versus separate text-plus-voice behavior, decides whether it is global, channel-level, or capability-driven, then implement it with Telegram tests, docs, and live Telegram proof.
