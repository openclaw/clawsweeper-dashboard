## Summary

Keep open: current main and v2026.6.11 still lack a Telegram TTS delivery selector; successful TTS still builds one voice payload whose short text becomes a Telegram caption, while https://github.com/openclaw/openclaw/pull/83988 is captioned-final churn work and does not implement the requested separate mode.

## What This Changes

The issue requests a configurable Telegram TTS delivery mode that sends readable text and a separate voice note instead of always using a voice caption when TTS succeeds.

## Best Possible Solution

Define a backward-compatible TTS delivery policy, choose global versus Telegram channel/account scope, keep the current captioned behavior as default unless maintainers decide otherwise, and require docs, focused tests, and live Telegram proof for both modes.
