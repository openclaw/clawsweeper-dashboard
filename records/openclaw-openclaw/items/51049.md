## Summary

Keep open. Current main still depends on Baileys `messages.upsert` delivery plus passive liveness and bounded reconnect `append` catch-up, while the issue and follow-up Docker Compose report describe linked, outbound-capable WhatsApp sessions where external inbound never reaches OpenClaw.

## What This Changes

The issue reports WhatsApp inbound messages never reaching the gateway in containerized deployments even though the linked account can send outbound messages.

## Best Possible Solution

Keep this as the broad WhatsApp external-inbound-loss tracker and choose a plugin-owned recovery design covering active liveness, bounded backfill or explicit gap warnings, durable dedupe/read receipts, and live container proof.
