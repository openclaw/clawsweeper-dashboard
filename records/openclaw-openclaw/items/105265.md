## Summary

This is a well-scoped, well-proven Control UI improvement, but two keyboard/accessibility regressions in the new composite menus should be fixed before merge. Current main does not already implement the redesign, and the linked feature issue should remain open until this PR lands.

## What This Changes

The PR replaces inline new-session agent, folder, execution-target, and worktree controls with compact details-based menus and updates the corresponding E2E coverage and responsive CSS.

## Best Possible Solution

Keep the compact trigger-row design, but treat the where panel as a form-capable popover rather than an ARIA menu and restore focus to the folder trigger whenever applying a folder collapses its panel.

## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.94

Full review comments:

- **[P2] Use a form-capable role for the where popover:** `ui/src/pages/new-session/new-session-page.ts:775`
  - body: The `role="menu"` container conditionally includes the base-branch and worktree-name text inputs, but an ARIA menu composite is defined around menuitem roles rather than embedded form fields. Screen readers can enter menu interaction mode and expose those inputs inconsistently; use a dialog/group-style popover for this mixed form, or restructure all content to a valid menu pattern.
  - confidence: 0.93
- **[P2] Restore trigger focus after applying a folder:** `ui/src/pages/new-session/new-session-page.ts:666`
  - body: Clicking “Use this folder” calls `closeBrowser()`, which sets `browserOpen` false and removes the focused button while collapsing the details element, but unlike Escape and ordinary menu selections it never focuses the summary. Keyboard users therefore land on the document after applying a folder instead of continuing from the folder trigger; close through a helper that restores summary focus.
  - confidence: 0.96
