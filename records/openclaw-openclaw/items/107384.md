## Summary

Keep this PR open, but do not merge the current patch: the age-order bug is valid, while the replacement turns every unseen identity at capacity into a 10,000-entry scan and still lacks real full-cap behavior and latency proof.

## What This Changes

The PR changes gateway control-plane rate-limit eviction to select the bucket with the smallest `windowStartMs` rather than the first key in map insertion order.

## Best Possible Solution

Preserve age-correct eviction in constant time by maintaining map order when a bucket begins a new window—such as deleting and reinserting that existing key—then keep first-key eviction and add cap-level correctness and repeated-unseen-key latency coverage.
