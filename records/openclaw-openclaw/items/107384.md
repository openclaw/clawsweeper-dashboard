## Summary

Keep this PR open, but do not merge the current patch: the reported ordering defect is valid, while the replacement makes each saturated new-identity request scan the full 10,000-entry map and still lacks real saturated-path proof.

## What This Changes

The PR changes gateway control-plane rate-limit cap eviction to scan for the bucket with the earliest window start instead of deleting the first inserted map entry.

## Best Possible Solution

When an existing bucket starts a new window, delete and reinsert that key so map order tracks window recency and the existing constant-time head eviction remains correct; cover both eviction ordering and repeated saturated churn.
