## Summary

Keep open: current main still has the reported eviction flaw, but this patch is not mergeable because it turns the saturated rate-limit security path into a repeated linear scan under unique-identity churn and still lacks real runtime proof.

## What This Changes

Changes gateway control-plane rate-limit bucket eviction to select the bucket with the smallest `windowStartMs` instead of the first inserted map entry.

## Best Possible Solution

Maintain age order in constant time by deleting an existing expired bucket before reinserting its reset value, retain first-entry eviction, and add saturation regression coverage plus redacted terminal proof of bounded repeated churn.

## Solution Assessment

No. Selecting the minimum timestamp is semantically plausible, but scanning the entire capped map in the synchronous request path is not the safest fix when map order can instead be updated during the much cheaper window-reset operation.
