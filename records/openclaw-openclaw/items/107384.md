The ordering defect is valid, but the patch leaves the prior P1 blocker unresolved: each new identity at capacity can synchronously scan all 10,000 buckets in gateway dispatch. Keep this PR open for bounded eviction and real full-cap proof.

## What This Changes

Changes gateway control-plane rate-limit eviction from deleting the first map entry to scanning for the bucket with the smallest `windowStartMs`.

## Best Possible Solution

When an existing bucket starts a new window, delete and reinsert it so map insertion order remains aligned with `windowStartMs`; retain constant-time first-entry eviction, add a divergent-order regression test, and provide representative full-cap terminal proof.
