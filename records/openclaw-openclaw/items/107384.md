## Summary

## What This Changes

Changes gateway control-plane rate-limit eviction from the first inserted bucket to the bucket with the smallest `windowStartMs`.

## Best Possible Solution

Refresh an expired existing bucket's Map position with delete-and-reinsert so insertion order tracks current window age while cap eviction remains constant-time, then add deterministic eviction coverage and redacted saturated-map runtime proof.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: insert an early bucket, insert later buckets, reset the early bucket after its window expires, fill the map, and add one new identity; insertion-order eviction removes the recently reset bucket. The existing suite does not currently encode that deterministic case.

## Solution Assessment

No. Selecting the minimum timestamp fixes the ordering criterion but introduces linear request-time work; updating Map order during the existing reset operation is narrower and preserves constant-time eviction.
