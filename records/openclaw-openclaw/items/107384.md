## Summary

Keep open: the reported eviction-order bug is valid, but the current head replaces constant-time cap eviction with repeated synchronous scans of 10,000 buckets on a gateway request path; the prior P1 finding remains, and the supplied validation does not exercise saturated identity churn.

## What This Changes

Changes gateway control-plane rate-limit eviction from deleting the first inserted bucket to scanning for the bucket with the smallest `windowStartMs`.

## Best Possible Solution

Keep eviction constant-time by refreshing a bucket's `Map` position when its rate-limit window resets, so insertion order tracks `windowStartMs`; retain first-key eviction and add regression coverage for reset ordering, cap eviction, and repeated saturated churn.
