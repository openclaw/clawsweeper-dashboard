## Summary

The underlying eviction-order bug is credible, but this implementation moves a security-sensitive gateway path from constant-time eviction to a 10,000-entry scan on every new identity after saturation, and no saturated real-runtime proof is provided.

## What This Changes

The PR changes gateway control-plane rate-limit eviction to scan for the bucket with the earliest window start instead of deleting the first inserted map entry.

## Best Possible Solution

Keep eviction bounded by refreshing map order when a bucket starts a new window—or use another bounded age index—then add a regression that proves the refreshed active bucket survives while the genuinely oldest bucket is evicted.

## Reproduction Assessment

Yes from source inspection: reset windows update existing map entries without moving their insertion position, so insertion order can diverge from window age. No current-main saturated runtime reproduction was supplied.

## Solution Assessment

No. Selecting the true oldest window is correct, but repeatedly scanning the full capped map is not the safest implementation; maintaining age order at reset time preserves correctness without adding churn-dependent linear work.
