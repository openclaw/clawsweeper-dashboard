## Summary

Keep open: the reported correctness gap is real, but the unchanged head replaces a constant-time anti-DoS eviction with a repeatable 10,000-entry request-path scan and still lacks real full-cap behavior proof.

## What This Changes

The branch changes control-plane rate-limit eviction to scan all buckets and delete the entry with the smallest `windowStartMs`.

## Best Possible Solution

Keep eviction constant-time by moving a bucket to the Map tail when its window resets, evict the head at capacity, and add both an ordering-divergence regression test and redacted full-cap latency proof.

No. Selecting the minimum timestamp is semantically plausible, but scanning the entire capped map on an attacker-influenced request path is not the best fix when Map order can be updated during window resets and preserve constant-time eviction.
