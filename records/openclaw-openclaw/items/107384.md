## Summary

## What This Changes

Changes control-plane rate-limit cap eviction to delete the bucket with the smallest `windowStartMs` instead of the first bucket in Map insertion order.

## Best Possible Solution

Preserve constant-time eviction by removing and reinserting an existing bucket when its window resets so Map order tracks current window age, then add a full-cap regression test, a bounded latency check, and redacted real-gateway stress output.

## Reproduction Assessment

Yes at source level: fill the Map, reset the first-inserted bucket after its window expires, then add an unseen identity at capacity; current main evicts the refreshed first bucket rather than the bucket with the oldest window. This review did not execute the scenario, so it is source-reproducible rather than runtime-reproduced.

## Solution Assessment

No. Selecting by minimum `windowStartMs` is semantically correct, but scanning all 10,000 buckets on each saturated new-key request is not the safest implementation; maintaining Map order during window resets preserves the intended eviction rule in constant time.
