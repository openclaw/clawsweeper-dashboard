## Summary

The underlying eviction bug is valid, but this implementation should not merge because it converts a constant-time gateway guard into attacker-repeatable linear work and still lacks after-fix saturated-runtime proof.

## What This Changes

The PR replaces insertion-order eviction in the gateway control-plane rate limiter with a scan selecting the bucket whose `windowStartMs` is smallest.

## Best Possible Solution

Maintain age order in O(1) by deleting and reinserting a bucket when its window resets, retain head-key eviction, add a regression that proves the active reset bucket is preserved, and provide redacted saturated runtime or load output.

## Reproduction Assessment

Yes from source: fill the map, reset the earliest-inserted bucket's window, then add another identity; insertion order and `windowStartMs` order diverge, exposing the original eviction error. The PR does not include or report actually running this regression.

## Solution Assessment

No. Selecting the exact minimum fixes fairness but a full scan is not the safest gateway implementation; maintaining age order during the existing reset operation preserves correct eviction without per-request linear work.
