## Summary

The underlying eviction-order bug is valid, but this implementation replaces a constant-time bounded eviction with a full 10,000-entry scan on every new identity at capacity, creating CPU-amplification risk in a gateway security control; the prior blocking finding remains unfixed, and real saturated-path proof is still absent.

## What This Changes

Changes gateway control-plane rate-limit bucket eviction to scan for the bucket with the smallest `windowStartMs` instead of deleting the first inserted map entry.

## Best Possible Solution

Keep eviction O(1) by deleting and reinserting an existing bucket when its window resets so map insertion order tracks window age, then retain first-key eviction and add regression coverage plus redacted saturated-churn latency proof.
