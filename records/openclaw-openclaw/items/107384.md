## Summary

Keep open: the previously reported P1 blocker remains on the unchanged reviewed head. The age criterion is correct, but repeated full-map scans make the security-sensitive limiter vulnerable to CPU amplification under unseen-identity churn.

## What This Changes

The PR changes gateway control-plane rate-limit eviction from deleting the first map entry to scanning for the bucket with the smallest `windowStartMs`.

## Best Possible Solution

Maintain bucket age order when a window resets—such as deleting and reinserting the existing key—so first-entry eviction remains constant-time, then prove reset-bucket correctness and sustained full-cap latency.
