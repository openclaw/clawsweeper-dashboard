## Summary

Keep open: the insertion-order diagnosis is valid, but the unchanged patch introduces a synchronous 10,000-bucket scan for every unseen identity after the map reaches capacity; the prior P1 finding remains unresolved and full-cap real behavior proof is still absent.

## What This Changes

Changes gateway control-plane rate-limit eviction from deleting the first map entry to scanning for the bucket with the smallest `windowStartMs`.

## Best Possible Solution

Preserve constant-time cap eviction by updating map age order when an existing bucket starts a new window, then add regression coverage and full-cap churn proof for both eviction correctness and latency.

- **[P1] Keep cap eviction constant-time:** `src/gateway/control-plane-rate-limit.ts:58-66`
  - body: At capacity this loop runs for every request from a previously unseen key, not once per 10,000 calls: each call evicts one entry, inserts its replacement, and leaves the map full.
