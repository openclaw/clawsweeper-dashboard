## Summary

Keep open. Current main and v2026.6.11 still force thread/topic cron completions with a resolved `threadId` through direct delivery and expose no opt-in main-agent-turn route, so the remaining work is a cron API and fallback-semantics product decision.

## What This Changes

The issue requests an opt-in cron delivery mode so text-only topic/forum targets can use the main-session announce or agent-turn flow instead of always using direct delivery.

## Best Possible Solution

Define a narrow, default-compatible job-level text routing selector for thread/topic cron delivery, keep structured payloads on direct delivery, and specify failure plus fallback semantics before implementation.
