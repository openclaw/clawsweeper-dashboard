## Summary

Keep open. Current main still forces text-only cron completions with a resolved thread/topic id through direct outbound delivery, and the public cron config/protocol surfaces still expose no opt-in main-session announce or agent-turn route; related merged work only covers target parsing, delivery accounting, and next-turn awareness after direct delivery.

## What This Changes

The issue requests an opt-in cron delivery route or config so text-only isolated cron completions for thread/topic targets can run through the main-session announce/agent-turn path instead of forced direct send.

## Best Possible Solution

Define one explicit job-level text-completion routing enum for thread/topic cron delivery, default it to current direct delivery, keep structured payloads on direct delivery, and specify delivery status plus fallback behavior before implementation.
