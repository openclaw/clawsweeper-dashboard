## Summary

Keep open. Current main still forces resolved thread/topic cron completions through direct outbound delivery, while the cron config/types/docs expose no opt-in route through main-session announce or agent-turn; related merged PRs improved delivery accounting and next-turn awareness but did not implement this requested routing mode.

## What This Changes

The issue asks for an opt-in cron delivery route so text-only isolated cron completions to thread/topic targets can go through main-session announce or agent-turn instead of forced direct send.

## Best Possible Solution

Add a maintainer-approved, backward-compatible per-job cron routing option for text-only thread/topic completions, with direct delivery as the default and explicit fail/fallback semantics plus docs and regression coverage.
