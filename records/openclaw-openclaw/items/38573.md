- `impact:session-state`: The issue is about whether cron completion context is handled by the target/main session or bypasses that agent-turn path.

## Summary

Keep open. Current main and the latest release still force thread/topic cron completion fallback through direct outbound delivery, and the merged related work only fixes delivery accounting, topic parsing, and next-turn target awareness rather than adding the requested opt-in main-agent rewrite/handoff path.

## What This Changes

The issue requests an explicit cron delivery mode or config option so text-only isolated cron completions targeting topic/forum threads can opt into main-session announce/agent-turn handling instead of forced direct delivery.

## Best Possible Solution

Define a narrow opt-in text-only cron delivery contract that keeps direct delivery as the default, specifies fail/fallback behavior, and updates cron schema, CLI/RPC docs, delivery-dispatch tests, and topic/session-awareness coverage together.

## Reproduction Assessment

Yes. Source inspection on current main and v2026.6.11 shows topic/thread cron targets still take the direct-delivery branch, and the cron delivery schema has no opt-in main-agent-turn selector.

## Solution Assessment

Unclear. The requested opt-in is plausible, but the best solution depends on maintainer decisions about public API shape, compatibility default, and explicit failure fallback semantics.
