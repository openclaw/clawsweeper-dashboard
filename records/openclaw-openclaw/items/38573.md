## Summary

Keep open. Current main and the latest release still force text-only thread/topic cron completions through direct outbound delivery, the public cron schemas expose no opt-in main-agent-turn selector, and the merged adjacent work only covers real outbound sending or later target-session awareness rather than a pre-send main-agent rewrite/handoff path.

## What This Changes

Request an explicit config or per-cron option that lets text-only topic/forum cron completions use the main-session announce/agent-turn flow instead of the hardcoded direct-send path.

## Best Possible Solution

Define one explicit job-level text-completion routing enum for thread/topic cron delivery, default it to current direct delivery, keep structured payloads on direct delivery, and specify delivery status plus fallback behavior before implementation.

## Reproduction Assessment

Yes. Source inspection on current main shows dispatchCronDelivery uses direct delivery whenever resolvedDelivery.threadId is present, and the cron type/protocol/config surfaces expose no opt-in main-agent-turn selector; I did not run a live Telegram cron flow.

## Solution Assessment

Unclear. The opt-in direction is plausible, but maintainers still need to choose the durable API shape and silent, failed, partial, and fallback semantics before this becomes a safe implementation task.
