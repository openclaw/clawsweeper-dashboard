## Summary

Keep open. Current main and v2026.6.11 still force thread/topic isolated cron completions through direct outbound delivery, and the related merged work only covers delivery accounting or target-session awareness, not an opt-in main-agent processing route.

## What This Changes

Request an opt-in cron delivery setting that lets text-only isolated cron completions targeting threads/topics route through the main-agent announce/agent-turn flow instead of forced direct sends.

## Best Possible Solution

Define a narrow backward-compatible job-level text-completion route enum for thread/topic cron delivery, keep current direct delivery as the default, keep structured payloads direct-only, and specify delivery status plus fallback semantics before coding it.

- **Keep direct delivery only:** Preserve current thread/topic direct-send behavior and document target-awareness or message-tool patterns as the supported alternatives.
