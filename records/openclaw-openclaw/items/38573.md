## Summary

Keep open. Current main and v2026.6.11 still force text-only cron delivery to thread/topic targets through direct outbound delivery, and the public cron config/protocol surface still has no opt-in main-agent handoff selector; related merged work fixed adjacent delivery accounting, subagent announce, and target awareness but not this requested route.

## What This Changes

The issue requests a config or per-cron option that lets text-only isolated cron completions for thread/topic targets go through a main-agent announce/turn flow instead of always using direct delivery.

## Best Possible Solution

Define one explicit job-level text-completion route enum for thread/topic cron delivery, default it to current direct delivery, keep structured payloads on direct delivery, and specify delivery status plus fallback behavior before implementation.

- Any persisted routing selector would touch cron config/schema, gateway protocol, CLI/docs, delivery status, tests, and upgrade expectations.
