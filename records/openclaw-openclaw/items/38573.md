## Summary

Keep open. Current main and the latest release still force thread/topic isolated cron completions through direct outbound delivery, and related merged work covers delivery accounting or next-turn awareness rather than the requested opt-in main-agent processing route.

## What This Changes

The issue requests a per-cron or config option for text-only topic/forum isolated cron completions to use main-session announce/agent-turn processing instead of always direct delivery.

## Best Possible Solution

Define a narrow, backward-compatible job-level text-completion route selector for thread/topic cron delivery, keep current direct delivery as the default, keep structured payloads direct-only, and specify delivery status plus fallback semantics before coding it.

Options:

- **Add job-level route enum (recommended):** Add a narrow per-job text completion route selector that defaults to direct delivery, applies only to text-only thread/topic completions, and has explicit fail-closed or direct-fallback semantics.

- **Keep direct delivery only:** Preserve current thread/topic direct-send behavior and document target-awareness or message-tool patterns as the supported alternatives.

Unclear until maintainers choose the surface. A job-level opt-in route looks like the narrowest plausible shape, but the API, fallback, timeout, duplicate-delivery, and delivery-status semantics need product direction first.
