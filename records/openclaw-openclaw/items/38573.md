## Summary

Keep open. Current main and the latest release still force text-only cron delivery to thread/topic targets through direct outbound delivery, and the public cron config/protocol surface has no opt-in main-agent handoff selector; related merged work improved adjacent delivery/accounting/context behavior but did not implement this requested route.

## What This Changes

Request an opt-in cron delivery mode or config surface so text-only isolated cron completions to thread/topic targets can use main-session announce/agent-turn routing instead of forced direct delivery.

## Best Possible Solution

Define one explicit job-level text-completion route enum for thread/topic cron delivery, default it to current direct delivery, keep structured payloads on direct delivery, and specify delivery status plus fallback behavior before implementation.
