## Summary

Keep open. Current main and the latest release still have no public cron route selector for opt-in main-agent processing of topic/thread deliveries; related merged and open work improves adjacent topic delivery, delivery proof, and target-session awareness but does not implement this requested API.

## What This Changes

Request an explicit config or per-cron option that lets text-only isolated cron completions to topic/forum targets use a main-session announce or agent-turn route instead of forced direct delivery.

## Best Possible Solution

Define a narrow, backward-compatible job-level text-completion route enum for thread/topic cron delivery, keep current direct delivery as the default, keep structured payloads direct-only, and specify delivery status plus fallback semantics before coding it.

Options:

- **Add job-level route enum (recommended):** Add a narrow per-job text completion route selector that defaults to direct delivery, applies only to text-only thread/topic completions, and has explicit fail-closed or direct-fallback semantics.
- **Add global default plus override:** Add a global cron default with a per-job override, accepting a wider config surface for operators who want consistent topic behavior across many jobs.
- **Keep direct delivery only:** Preserve current thread/topic direct-send behavior and document target-awareness or message-tool patterns as the supported alternatives.

## Reproduction Assessment

Yes. Source inspection on current main shows thread/topic cron targets still force direct outbound delivery, while the type, protocol, config, and docs expose no opt-in main-agent route selector; no live Telegram cron flow was run in this read-only review.

## Solution Assessment

Unclear. A job-level opt-in route looks like the narrowest plausible shape, but current main no longer preserves the older DM-style internal announce route generally, so maintainers need to decide whether to add that route and how fallback should work.
