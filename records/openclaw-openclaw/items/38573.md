## Summary

Keep open. Current main still forces thread/topic cron completions through direct outbound delivery and exposes no config or protocol selector for an opt-in main-agent handoff; related merged PRs improved direct delivery and next-turn awareness but did not add this route.

## What This Changes

The issue requests an opt-in cron delivery route so text-only isolated cron completions targeting threaded/topic chats can use main-session announce or agent-turn handling instead of always direct-sending.

## Best Possible Solution

Define a narrow job-level text-completion routing enum for thread/topic cron delivery, default it to current direct delivery, keep structured payloads on direct delivery, and specify delivery status plus fallback behavior before implementation.
