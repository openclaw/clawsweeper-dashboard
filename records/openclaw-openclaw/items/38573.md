## Summary

Keep open. Current main and the latest release still force text-only cron completions with a resolved thread/topic through direct outbound delivery, and the requested opt-in main-agent announce/turn route would add cron config/protocol and fallback semantics that need maintainer product direction.

## What This Changes

The issue requests a per-job or config option for topic/forum cron completions to use main-session announce/agent-turn delivery instead of always using direct delivery.

## Best Possible Solution

Define one explicit job-level text-completion route enum for thread/topic cron delivery, default it to current direct delivery, keep structured payloads on direct delivery, and specify delivery status plus fallback behavior before implementation.

## Risks / Open Questions
