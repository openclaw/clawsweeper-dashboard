## Summary

Keep open. Current main and v2026.6.11 still force threaded isolated cron completions through direct outbound delivery, and the remaining work is a product/API choice for an opt-in main-agent route rather than conservative cleanup.

## What This Changes

Request adding a backward-compatible per-job or config option that lets text-only thread/topic isolated cron completions use main-session announce/agent-turn processing instead of forced direct send.

## Best Possible Solution

Define a narrow backward-compatible job-level text-completion route enum for thread/topic cron delivery, keep current direct delivery as the default, keep structured payloads direct-only, and specify delivery status plus fallback semantics before coding it.
