## Summary

Keep open. Current main and v2026.6.11 still force thread/topic isolated cron completions through direct outbound delivery, and there is no public cron route selector for opting text-only topic deliveries into main-agent processing.

## What This Changes

The issue requests an opt-in cron delivery mode or config that lets text-only topic/forum isolated cron completions route through the main-agent announce/turn flow instead of forced direct delivery.

## Best Possible Solution

Define a narrow backward-compatible job-level text-completion route enum for thread/topic cron delivery, keep current direct delivery as the default, keep structured payloads direct-only, and specify delivery status plus fallback semantics before coding it.

Options:

- **Add job-level route enum (recommended):** Add a narrow per-job text completion route selector that defaults to direct delivery, applies only to text-only thread/topic completions, and has explicit fail-closed or direct-fallback semantics.
- **Add global default plus override:** Add a global cron default with per-job override for operators who want consistent topic behavior across many jobs, accepting a wider config surface.
- **Keep direct delivery only:** Preserve current thread/topic direct-send behavior and document target-awareness or message-tool patterns as the supported alternatives.

Unclear until maintainers choose the surface. A job-level opt-in route looks like the narrowest plausible shape, but the API, fallback, timeout, duplicate-delivery, and delivery-status semantics need product direction first.
