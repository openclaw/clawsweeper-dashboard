## Summary

Keep open. Current main and v2026.6.11 still force thread/topic cron completions through direct outbound delivery, and the public cron type/protocol/config/docs surfaces still lack the requested opt-in main-agent handoff route; the remaining work needs maintainer product/API direction rather than conservative cleanup.

## What This Changes

The issue requests an opt-in config or cron-job delivery mode so text-only isolated cron completions targeting forum/topic threads can use the main-session announce/agent-turn flow instead of always being delivered directly.

## Best Possible Solution

Define one explicit job-level text-completion route enum for thread/topic cron delivery, default it to current direct delivery, keep structured payloads on direct delivery, and specify delivery status plus fallback behavior before implementation.
