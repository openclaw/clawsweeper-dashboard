## Summary

Keep open. Current main still forces text-only cron completions with a resolved thread/topic id through direct outbound delivery, and the public cron config/protocol surfaces still expose no opt-in main-session announce or agent-turn route; this remains a product/API decision rather than a stale or already-implemented item.

## What This Changes

The issue requests an explicit opt-in route so text-only isolated cron completions for topic/forum targets can go through the main-session announce or agent-turn flow instead of always using direct delivery.

## Best Possible Solution

Define one explicit job-level text-completion routing enum for thread/topic cron delivery, default it to current direct delivery, keep structured payloads on direct delivery, and specify delivery status plus fallback behavior before implementation.
