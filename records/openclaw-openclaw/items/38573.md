## Summary

Keep open. Current main and latest release still force resolved thread/topic cron completions through direct outbound delivery, while related merged work only covers topic parsing, delivery accounting, provider proof, and next-turn awareness rather than the requested opt-in main-agent rewrite/handoff route.

## What This Changes

The issue requests a cron option or config surface that lets text-only topic/forum cron completions use the main-session announce/agent-turn path instead of forced direct channel delivery.

## Best Possible Solution

Define one explicit job-level text-completion route enum for thread/topic cron delivery, default it to current direct delivery, keep structured payloads on direct delivery, and specify delivery status plus fallback behavior before implementation.
