## Summary

Keep open. Current main and the latest release still force resolved thread/topic cron deliveries through direct outbound delivery, and the public cron type, Gateway schema, config schema, CLI docs, and user docs still expose no opt-in main-session announce or agent-turn route; the remaining question is a maintainer product/API decision, not cleanup-safe closure.

## What This Changes

The issue requests a config or per-cron opt-in that lets text-only topic/forum cron completions use the main-session announce or agent-turn flow instead of always direct-sending to the thread.

## Best Possible Solution

Define one explicit job-level text-completion routing selector for thread/topic cron delivery, default it to current direct delivery, keep structured payloads on direct delivery, and specify delivery status plus fallback behavior before implementation.

Options:

- **Add a job-level route enum (recommended):** Add a narrow per-job text completion route selector that defaults to direct delivery, applies only to text-only thread/topic completions, and has explicit fail-closed or direct-fallback semantics.
- **Use a global default plus override:** Add a global cron default with a per-job override, accepting a wider config surface for operators who want consistent topic behavior across many jobs.
- **Keep direct delivery only:** Preserve the current topic/thread direct-send behavior and document command cron or target-awareness patterns as the supported alternatives.
