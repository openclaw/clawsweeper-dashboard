## Summary

Keep open. Current main and v2026.6.11 still force text-only cron delivery with a thread/topic id through direct outbound delivery, and the public cron type, protocol, config, and docs surfaces still have no opt-in main-agent handoff selector; this remains a product/API decision rather than a stale or implemented item.

## What This Changes

The issue requests an opt-in cron delivery mode that lets text-only topic/forum targets use the main-session announce/agent-turn flow instead of always using direct delivery.

## Best Possible Solution

Define one explicit job-level text-completion route selector for thread/topic cron delivery, default it to current direct delivery, keep structured payloads on direct delivery, and specify delivery status plus fallback behavior before implementation.

- **Keep direct delivery only:** Preserve the current topic/thread direct-send behavior and document current/session cron or target-awareness patterns as the supported alternatives.
