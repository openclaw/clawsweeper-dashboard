## Summary

Keep open. Current main and v2026.6.11 still force text-only isolated cron completions for thread/topic targets through direct outbound delivery, and adding an opt-in main-agent processing route remains a cron config/API product decision rather than conservative cleanup.

## What This Changes

The issue requests an opt-in cron delivery mode so thread/topic isolated cron text completions can use main-session announce/agent-turn routing instead of forced direct delivery.

## Best Possible Solution

Define a narrow backward-compatible job-level text-completion route enum for thread/topic cron delivery, keep current direct delivery as the default, keep structured payloads direct-only, and specify delivery status plus fallback semantics before coding it.
