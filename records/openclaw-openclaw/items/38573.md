## Summary

Keep open. Current main and the latest release still force threaded/topic isolated cron completions through direct outbound delivery, and the requested opt-in main-agent route remains a product/API decision rather than conservative cleanup.

## What This Changes

The issue requests a backward-compatible config or per-cron option for text-only topic/forum isolated cron completions to use the main-session announce/agent-turn route instead of forced direct delivery.

## Best Possible Solution

Define a narrow backward-compatible job-level text-completion route enum for thread/topic cron delivery, keep current direct delivery as the default, keep structured payloads direct-only, and specify delivery status plus fallback semantics before coding it.
