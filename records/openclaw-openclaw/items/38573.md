## Summary

Keep open. Current main and v2026.6.11 still force thread/topic cron completions through direct delivery and expose no public opt-in route for main-agent processing, so this remains a product/API decision rather than cleanup-closeable work.

## What This Changes

The issue requests an opt-in cron delivery route so text-only topic/forum cron completions can go through main-session announce or agent-turn processing instead of always using direct delivery.

## Best Possible Solution

Define a narrow, backward-compatible job-level text-completion route enum for thread/topic cron delivery, keep current direct delivery as the default, keep structured payloads direct-only, and specify delivery status plus fallback semantics before coding it.

- **Keep direct delivery only:** Preserve current thread/topic direct-send behavior and document target-awareness or message-tool patterns as the supported alternatives.
