## Summary

The patch is a focused, contract-aligned fix for a current-main updater failure. It separates a late `launchctl bootout` error from authoritative native unload/free-port proof, retries only the transient not-yet-stopped invariant, and preserves suspension resume for every unproven outcome; no actionable correctness or security defect was found.

## What This Changes

The PR updates live-updater shutdown recovery to accept authoritative native unload proof after a late `launchctl bootout` error while retaining suspension resume for unproven stops.

## Best Possible Solution

Land the bounded native-proof recovery while retaining launchd-unloaded plus free-port proof as the only stop-error override and preserving suspension resume for every unproven outcome.

Yes from source with high confidence: on current main, a thrown `launchctl bootout` result enters the shared failure path and resumes suspension even when a subsequent native check could prove the job unloaded and the port free. The focused PR test models that ordering.

## Solution Assessment

Yes. Separating command status from authoritative native state proof is narrower and safer than ignoring bootout errors generally, while the patch retains fail-closed resume behavior for non-native, unexpected, or exhausted proof failures.
