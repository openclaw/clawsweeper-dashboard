- `impact:session-state`: The request is about preserving ACP and subagent session state without relying on channel thread binding.

## Summary

Keep open. Current main and v2026.6.11 still explicitly require `thread: true` for `mode="session"` in both native subagent and ACP spawn paths, and the related open items cover narrower plugin policy, parent-rewrite semantics, or concrete delivery bugs rather than this broader non-thread persistent-session contract.

## What This Changes

The issue requests allowing persistent `mode="session"` ACP/subagent sessions without requiring channel thread binding.

## Best Possible Solution

Define a first-class non-thread persistent-session contract, then update native spawn, ACP spawn, tool schema, follow-up targeting, lifecycle cleanup, docs, and focused tests around that contract.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 still reject both native and ACP `sessions_spawn` calls with `mode="session"` unless `thread: true` is set, and tests/docs preserve that contract.

## Solution Assessment

No, not as a simple guard removal. Decoupling persistence from thread binding is plausible, but the best fix needs an explicit non-thread ownership, delivery, and cleanup contract across ACP and native subagents.
