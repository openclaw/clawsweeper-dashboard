## Summary

Keep open. Current main and the latest release still reject non-thread `mode="session"` in both native subagent and ACP `sessions_spawn`, while the schema and docs preserve the thread-bound contract; the requested decoupling remains a product/session-routing decision rather than conservative cleanup.

## What This Changes

Allow `sessions_spawn` `mode="session"` to create persistent native and ACP sessions without requiring channel thread binding.

## Best Possible Solution

Define a first-class non-thread persistent-session contract, then update native spawn, ACP spawn, model-facing schema, follow-up targeting, cleanup, docs, and focused tests together.

Unclear. Decoupling persistence from thread binding is plausible, but direct guard removal is not the best fix without an explicit non-thread ownership, delivery, targeting, and cleanup contract.
