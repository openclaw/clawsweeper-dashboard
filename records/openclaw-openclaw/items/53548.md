## Summary

Keep open. Current main and v2026.6.11 still explicitly require `thread: true` for `mode="session"` in both native subagent and ACP spawn paths, while the requested non-thread persistent-session behavior needs a maintained routing and lifecycle contract rather than stale cleanup.

## What This Changes

Allow `sessions_spawn` with `mode="session"` to create persistent native and ACP sessions without requiring `thread: true`, so parent agents can continue them with `sessions_send` on non-thread channels.

## Best Possible Solution

Define a first-class non-thread persistent-session contract, then update native spawn, ACP spawn, tool schema, follow-up targeting, lifecycle cleanup, docs, and focused tests around that contract.

## Reproduction Assessment

Yes, source-level. Current main and v2026.6.11 reject both native and ACP `sessions_spawn` calls with `mode="session"` unless `thread: true` is set, and tests/docs preserve that contract.

## Solution Assessment

Unclear as a direct implementation. Decoupling persistence from thread binding is plausible, but the best fix needs an explicit non-thread ownership, delivery, and cleanup contract rather than simply removing the guards.
