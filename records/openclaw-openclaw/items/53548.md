- `impact:session-state`: The issue is about whether spawned child sessions can persist and keep context without a channel thread binding.

## Summary

Keep open: current main and v2026.6.11 still reject `mode="session"` without `thread=true` in both native subagent and ACP spawn paths, and the requested decoupling is a product/runtime contract change rather than conservative cleanup.

## What This Changes

The issue requests allowing persistent `mode="session"` subagent and ACP sessions without requiring channel thread binding.

## Best Possible Solution

Define one maintainer-approved headless persistent-session contract for native and ACP spawns, including parent relay, visibility, ownership/security scope, cleanup, schema/docs, and regression proof while preserving existing thread-bound behavior.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw make `mode="session"` a non-thread persistent session contract, or keep `mode="session"` reserved for thread-bound sessions and add a separate persistence/affinity path?

Rationale: The source repro is clear, but the permanent API controls session ownership, message routing, output visibility, cleanup, and ACP security boundaries; automation should not choose those semantics.

Likely owner: steipete

Owner reason: The recent core thread-binding refactor makes this the best available routing owner for the product/API direction.

Owner confidence: high

Options:

- **Design unified headless sessions (recommended):** Make non-thread persistence a first-class native and ACP contract with explicit parent-relay, session targeting, lifecycle, and safety rules before implementation.
- **Keep session mode thread-bound:** Preserve the current docs/tests/runtime contract and direct users toward `mode="run"`, `sessions_send`, or channel thread support instead.
- **Split ACP affinity first:** Implement the narrower ACP affinity design in https://github.com/openclaw/openclaw/issues/55484 before deciding whether native subagents share the same contract.

## Reproduction Assessment

Yes, at source level. Current main rejects non-thread `mode="session"` in both native and ACP paths, and the schema/docs/tests still encode the thread-bound contract.

## Solution Assessment

Unclear as an implementation path. The requested direction is plausible, but the best maintainable fix is a product-approved session/delivery contract rather than simply removing the guards.
