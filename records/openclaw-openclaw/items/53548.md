## Summary

Keep open. Current main and the latest release still reject `sessions_spawn` with `mode="session"` unless `thread: true` is set in both native subagent and ACP spawn paths; the requested non-thread persistent-session behavior remains a product/runtime contract decision rather than cleanup-closeable.

## What This Changes

The issue requests allowing native and ACP `sessions_spawn` persistent sessions without requiring channel thread binding.

## Best Possible Solution

Define a first-class non-thread persistent-session contract, then update native spawn, ACP spawn, schema exposure, follow-up targeting, lifecycle cleanup, docs, and focused tests around that contract.

- **Define the contract first (recommended):** Approve a generic non-thread persistent-session design covering session creation, `sessions_send` targeting, parent-delivery behavior, cleanup, and docs before implementation.
- **Keep session mode thread-bound:** Keep `mode="session"` as a thread-bound concept and direct users to `mode="run"`, `/acp --bind here`, or narrower affinity work for unthreaded cases.

Unclear. Decoupling persistence from thread binding is plausible, but the best fix needs an explicit non-thread ownership, delivery, targeting, and cleanup contract rather than direct guard removal.
