## Summary

Keep open. Current main and the latest release still reject `mode="session"` without `thread: true` in both native subagent and ACP spawn paths, while the requested unbound persistent-session behavior needs an explicit routing, lifecycle, cleanup, and ownership contract before implementation.

## What This Changes

Request allowing `sessions_spawn` `mode="session"` to create persistent native subagent and ACP sessions without requiring `thread: true`, with parent-delivered output and follow-up through `sessions_send`.

## Best Possible Solution

Define a first-class unbound persistent-session contract in core spawn/session routing, then relax the native and ACP guards with focused docs and regression coverage for parent delivery, `sessions_send` follow-up targeting, cleanup, visibility, and channel capability behavior.

Options:

- **Design unbound persistent sessions (recommended):** Keep this issue open and implement a core contract for unbound persistent sessions before relaxing the guards in native and ACP spawn paths.
- **Keep thread-bound session only:** Leave `mode="session"` tied to thread/current-conversation binding and improve docs/error copy around `mode="run"`, `sessions_send`, and ACP resume workarounds.
- **Scope ACP separately:** Track only ACP non-thread affinity in https://github.com/openclaw/openclaw/issues/55484 and keep native subagent session semantics unchanged for now.

## Solution Assessment

No, simply removing the guards is not the best fix. The maintainable solution needs an explicit unbound persistent-session contract for delivery, follow-up, cleanup, visibility, and security before code changes.
