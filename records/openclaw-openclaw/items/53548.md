## Summary

Keep open. Current main and the latest release still reject `mode="session"` without `thread: true` in both native subagent and ACP spawn paths, and the requested non-thread persistent-session behavior needs an explicit routing, lifecycle, cleanup, and ownership contract before implementation.

## What This Changes

The issue requests allowing `sessions_spawn` `mode="session"` without mandatory `thread: true` so ACP and native child sessions can persist while the parent agent relays follow-ups.

## Best Possible Solution

Define a first-class non-thread persistent-session contract, then update native spawn, ACP spawn, schema exposure, follow-up targeting, lifecycle cleanup, docs, and focused tests around that contract.

## Reproduction Assessment

Yes, source-level. Current main and `v2026.6.11` still reject native and ACP `sessions_spawn` calls with `mode="session"` unless `thread: true` is set, and tests/docs preserve that contract.

## Solution Assessment

Unclear. Decoupling persistence from thread binding is plausible, but the best fix needs an explicit non-thread ownership, delivery, targeting, and cleanup contract rather than direct guard removal.
