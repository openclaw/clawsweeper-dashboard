## Summary

Keep open: current main and v2026.6.11 still require `thread: true` for `mode="session"` in both native and ACP spawn paths, so the requested non-thread persistent-session contract remains unresolved and needs maintainer product review.

## What This Changes

The issue asks for `sessions_spawn` `mode="session"` to create persistent native and ACP child sessions without requiring `thread: true`, with parent-mediated follow-up through `sessions_send`.

## Best Possible Solution

Define a first-class non-thread persistent-session contract, then update native spawn, ACP spawn, tool schema, sessions_send targeting, lifecycle cleanup, docs, and focused tests together.

## Reproduction Assessment

Yes, source-level: current main rejects both native and ACP `sessions_spawn` calls with `mode="session"` unless `thread: true` is set, and the tests/docs preserve that contract. I did not run a live channel reproduction in this read-only review.

## Solution Assessment

Unclear. Decoupling persistence from thread binding is plausible, but direct guard removal is not the best fix until maintainers choose the ownership, delivery, and cleanup semantics for non-thread persistent sessions.
