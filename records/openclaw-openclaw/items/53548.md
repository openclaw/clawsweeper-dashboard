## Summary

Keep open. Current main and the latest release still reject unthreaded `mode="session"` in both native subagent and ACP `sessions_spawn`, while the issue discussion and related items show the remaining work is a broad session-routing product contract rather than an already-implemented fix.

## What This Changes

The issue requests allowing `sessions_spawn` persistent session mode without requiring channel thread binding for native subagent and ACP runtimes.

## Best Possible Solution

Define a first-class non-thread persistent-session contract, then update native spawn, ACP spawn, schema exposure, follow-up targeting, lifecycle cleanup, docs, and focused tests around that contract.

## Reproduction Assessment

Yes. Current source, tests, docs, and `v2026.6.11` all preserve the `mode="session"` plus `thread=true` requirement for native and ACP `sessions_spawn`.

## Solution Assessment

Unclear. Decoupling persistence from thread binding is plausible, but the maintainable fix needs an explicit non-thread ownership, delivery, targeting, and cleanup contract rather than a direct guard removal.
