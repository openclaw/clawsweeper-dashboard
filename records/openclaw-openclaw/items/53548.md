## Summary

Keep open. Current main and the latest release still reject non-thread `mode="session"` in native subagent, ACP spawn, and model-facing `sessions_spawn` surfaces, so the requested decoupling remains a real product/session-routing contract decision rather than cleanup.

## What This Changes

Request allowing `sessions_spawn` `mode="session"` to create persistent native or ACP child sessions without requiring `thread=true`, with parent-mediated follow-up through session targeting.

## Best Possible Solution

Define a first-class unbound persistent-session contract, then update native and ACP spawn, tool schema, delivery planning, docs, and regression coverage together so non-thread channels get durable sessions without ambiguous message routing.

Options:

- **Keep sessions thread-bound:** Retain the current contract and close or retitle related requests after documenting that persistent interactive sessions require a bindable conversation or thread.
- **Split ACP affinity first:** Handle ACP-only cron/orchestrator affinity in a narrower design while leaving native subagent session mode thread-bound for now.

Yes, source-level: current main rejects `mode="session"` without `thread=true` in both native and ACP spawn paths, and existing tests assert the native rejection. I did not run a live channel scenario because this was a read-only cleanup review.

## Solution Assessment

Unclear until maintainers choose the contract. Removing the guards alone is not the best fix because the schema, delivery plan, cleanup behavior, `sessions_send` semantics, docs, and native/ACP parity all need to line up.
