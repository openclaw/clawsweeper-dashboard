## Summary

Keep open: current main and v2026.6.11 still reject non-thread `mode="session"` in both native subagent and ACP spawn paths, and the requested decoupling is a product contract for session ownership, routing, and lifecycle rather than conservative cleanup.

## What This Changes

Allow persistent native subagent and ACP `sessions_spawn` sessions without requiring channel thread binding.

## Best Possible Solution

Define a first-class non-thread persistent-session contract, then update native spawn, ACP spawn, model-facing schema, follow-up targeting, cleanup, docs, and focused tests together.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw support non-thread persistent native and ACP `sessions_spawn` sessions as a first-class contract, and what routing and lifecycle semantics should that contract use?

Rationale: The source-level limitation is clear, but accepting the requested behavior changes session ownership, parent delivery, thread bypass behavior, ACP inline delivery, cleanup, and follow-up targeting policy.

Likely owner: steipete

Owner confidence: high

Options:

- **Define non-thread persistence (recommended):** Approve an explicit unbound persistent-session contract and require one coordinated implementation across runtime, schema, docs, and tests.
- **Keep session thread-bound:** Keep `mode="session"` tied to thread binding and narrow this issue toward docs, current-conversation bindings, or `mode="run"` guidance.
- **Split ACP from native sessions:** Handle ACP non-thread persistence through a separate affinity-style contract while deciding native subagent persistence later.

## Reproduction Assessment

Yes, source-level. Current main and v2026.6.11 still reject native and ACP `sessions_spawn` calls with `mode="session"` unless `thread: true` is set, and tests/docs preserve that contract.

## Solution Assessment

Unclear. Decoupling persistence from thread binding is plausible, but direct guard removal is not the best fix without an explicit non-thread ownership, delivery, targeting, cleanup, and ACP inline-delivery contract.
