The recent native-loading work may reduce the affected compiled-plugin paths, but it does not establish that lazy source-runtime imports recover correctly when a Jiti cache artifact vanishes.

## What This Changes

Investigate whether removal of Jiti’s temporary compiled-module cache during a running gateway can make later lazy imports fail and cause inbound channel messages to be acknowledged without reaching an agent.

## System Context

OpenClaw’s plugin and channel runtime loads compiled or source modules before dispatching inbound events into the reply pipeline. If a lazy-loaded runtime module cannot be read after startup, the channel’s debounce or dispatch path must either recover the load or make the delivery failure observable rather than silently losing the message.

Establish a focused current-main reproduction that removes only the active Jiti cache after gateway startup and then triggers the affected lazy load; if confirmed, make the loader use an owner-controlled durable cache or regenerate on cache-miss, and ensure inbound dispatch records an explicit delivery failure instead of silently dropping the event.
