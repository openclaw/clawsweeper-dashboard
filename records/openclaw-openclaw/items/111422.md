## Summary

Keep this PR open for maintainer review. The previous P1 blocker remains: the patch makes arbitrary final presentation text authoritative for persisted cron failure state, while the existing contract described in the report is structured failure signaling. The resolver-level terminal output is useful, but it does not prove an isolated cron run persists failure status and fires `failureAlert`.

Likely related people: MrNozz supplied the detailed production-facing cron evidence in the linked report (low confidence as a code owner; current-main history attribution was not available in this read-only review environment).

## What This Changes

The PR treats a last non-empty `===DONE_ERR===` line in isolated-agent final text as a fatal cron failure and adds resolver coverage for sentinel variants.

## Best Possible Solution

Keep persistent cron outcome classification on explicit structured failure signals emitted at the execution boundary; if terminal sentinels are to be supported, define and document their producer/consumer contract, scope it deliberately, and prove both fresh behavior and existing-job upgrade effects with a live isolated cron run.
