## Summary

Keep this PR open: the structured-tool direction is materially better than durable parsing of assistant-visible text, but a failed `cron_report_outcome` can still be overwritten by a later `completed` report before terminal resolution. That can recreate the reported false-success outcome, so the current patch is not ready to merge. Likely related people: the current history owner could not be attributed safely from the supplied read-only evidence; routing should stay with the embedded-agent runtime area (low confidence).

## What This Changes

This PR adds a cron-only agent tool for reporting a structured terminal outcome and carries a failed report through the embedded-agent runner so cron jobs record an error and trigger failure alerts without parsing final assistant text.

## System Context

Isolated cron jobs run through the embedded-agent runner, which collects tool events and produces terminal metadata for the cron scheduler. The scheduler converts a fatal failure signal into an error status, persisted failure state, and any configured failure alert.
