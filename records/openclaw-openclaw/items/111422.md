## Summary

The prior P1 remains unresolved: this PR moves parsing of agent-visible text earlier, but still lets an undocumented `===DONE_ERR===` string control durable cron failure state. The linked issue should remain open while a maintainer decides whether that sentinel is a supported terminal-outcome contract or whether cron failures must come only from an explicit structured agent outcome.

## What This Changes

The branch adds a `done_err_sentinel` embedded-run failure signal when a cron-triggered agent’s final visible line starts with `===DONE_ERR===`, causing the isolated cron run to return an error.

## System Context

An embedded agent run produces final visible text plus execution metadata. Isolated cron jobs convert that metadata into run status, then persist error counts and trigger configured failure alerts.

## Architecture Diagram

flowchart LR
  A[Scheduled cron job] --> B[Embedded agent run]
  B --> C[Final text and run metadata]
  C --> D[Failure outcome classification]
  D --> E[Isolated cron status]
  E --> F[Persisted error state]
  F --> G[Failure alert delivery]

## Best Possible Solution

Define a typed terminal outcome at the agent-run boundary, emitted by a trusted execution/result producer rather than inferred from final visible text; if a textual marker must remain supported, document it as an explicit cron-only compatibility contract with false-positive and upgrade behavior approved by the responsible owner.
