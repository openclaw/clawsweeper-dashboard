## Summary

Keep this PR open. The structured outcome direction is materially better than persisting failure state from visible text, but the new handler lets a later `completed` report overwrite an earlier accepted `failed` report, recreating a false-success path for duplicate or conflicting tool calls.

## What This Changes

The PR replaces `===DONE_ERR===` text parsing with a cron-only `cron_report_outcome` tool whose structured result is carried through the embedded-agent runner into cron failure status and alerts.

## System Context

Isolated cron jobs invoke the embedded agent runner, which collects tool-call outcomes and returns a run result to the cron scheduler. The scheduler turns a fatal embedded-run signal into persisted cron status, consecutive-error accounting, and optional failure alerts.

## Architecture Diagram

  B --> C[Outcome report handler]
  C --> D[Embedded run attempt result]
  D --> E[Terminal failure resolution]

  F --> G[Persisted run status and alerts]

## Best Possible Solution

Treat the first accepted fatal cron outcome as terminal, or reject conflicting outcome reports, then prove a real isolated cron run persists an error and triggers its configured failure alert without relying on visible-text parsing.
