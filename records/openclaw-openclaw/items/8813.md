## Summary

Keep open: current main and the latest release still hardcode read-based SKILL.md loading, and the remaining work is a product/plugin contract decision rather than a stale cleanup candidate.

## What This Changes

Request that the Skills system prompt prefer a registered Skill loader tool over read-based SKILL.md loading when that tool is available.

## Best Possible Solution

Define the supported loader-tool capability or naming contract, then update the native Skills prompt to prefer it when present while preserving the read fallback, with focused tests and docs.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 unconditionally emit read-based skill-loading guidance even though registered tool names are available to prompt construction.

## Solution Assessment

Unclear as proposed. Preferring a registered loader tool is plausible, but maintainers should first choose whether the contract is name-based, namespaced, or an explicit skill-loader capability.
