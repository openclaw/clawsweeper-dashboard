## Summary

Keep open: current main and the latest release still emit read-based skill-loading guidance even when registered tool names are available, and the remaining decision is the supported contract for a loader-style Skill tool.

## What This Changes

Request the Skills system-prompt section to prefer invoking a registered Skill loader tool over reading SKILL.md directly when that tool is available.

## Best Possible Solution

Define the supported skill-loader tool capability or naming contract, then update src/agents/system-prompt.ts, focused prompt tests, and system-prompt docs while preserving the current read fallback.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 unconditionally emit read-based skill-loading guidance even though registered tool names are available to prompt construction.

## Solution Assessment

Unclear as proposed. Preferring a registered loader tool is plausible, but maintainers should first choose whether the contract is name-based, namespaced, or an explicit skill-loader capability.
