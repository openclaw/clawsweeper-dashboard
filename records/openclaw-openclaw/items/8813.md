## Summary

Keep open: current main and the latest release still emit read-based skill-loading guidance, while the remaining work is a product/plugin contract decision about whether a registered Skill-style loader tool should receive special prompt authority.

## What This Changes

The issue requests that OpenClaw's skills system prompt prefer a registered Skill-style tool over instructing the model to read SKILL.md directly.

## Best Possible Solution

Define the supported skill-loader tool capability or naming contract, then update src/agents/system-prompt.ts, focused prompt tests, and public docs while preserving the current read fallback.

## Reproduction Assessment

Yes. Source inspection shows current main and the latest release unconditionally emit read-based SKILL.md guidance even though registered tool names are available before prompt construction.

## Solution Assessment

Unclear as proposed. Preferring a registered loader tool is plausible, but maintainers should first choose whether the contract is name-based, namespaced, or an explicit skill-loader capability.
