## Summary

Keep open. Current main and v2026.6.11 still hardcode read-based skill loading, but current Codex source does not support the report’s assumption that an arbitrary Skill tool response is inherently binding; the remaining work needs a maintainer product and security-boundary decision.

## What This Changes

Prefer a registered skill-loading tool over direct SKILL.md reads in the native system prompt when such a tool is available.

## Best Possible Solution

Define one maintainer-approved activation contract: retain direct reads for ordinary filesystem discovery, use deterministic harness injection for explicit activation when approved, and require a typed plugin capability with documented trust semantics for non-filesystem skill resources.
