## Summary

Keep open: current main and the latest release still hardcode read-based skill loading, while registered tool names reach prompt construction; the remaining decision is whether and how OpenClaw should privilege a loader-style Skill tool.

## What This Changes

Issue requests that the Skills system prompt prefer invoking a registered Skill tool over direct SKILL.md reads when such a tool is available.

## Best Possible Solution

Define the supported skill-loader tool contract first, then update src/agents/system-prompt.ts, focused prompt tests, and public system-prompt docs while preserving the current read fallback.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 unconditionally emit read-based skill-loading guidance even though registered tool names are available to prompt construction.

## Solution Assessment

Unclear as proposed. Preferring a registered loader tool is plausible, but maintainers should first choose whether the contract is name-based, namespaced, or an explicit capability.
