## Summary

Keep open: current main and v2026.6.11 still emit read-based skill-loading guidance, while the remaining question is the product/plugin contract for granting a registered Skill-loader tool special prompt authority.

## What This Changes

The issue requests changing the Skills system-prompt section to prefer invoking a registered Skill tool over reading SKILL.md when that tool is available.

## Best Possible Solution

Define the supported skill-loader tool contract first, then update src/agents/system-prompt.ts, focused prompt tests, and public system-prompt docs while preserving the current read fallback.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 unconditionally emit read-based skill-loading guidance even though registered tool names are available to prompt construction.

## Solution Assessment

Unclear as proposed. Preferring a registered loader tool is plausible, but maintainers should first choose whether the contract is name-based, namespaced, or an explicit skill-loader capability.
