## Summary

Keep open: current main still emits read-based SKILL.md guidance even when tool names are available, and the remaining fix needs a maintainer decision about the supported Skill-loader tool contract.

## What This Changes

The issue requests that the system prompt prefer invoking a registered Skill loader tool over telling the model to read SKILL.md directly.

## Best Possible Solution

Define the supported Skill-loader contract, then update src/agents/system-prompt.ts, focused prompt tests, and public docs while preserving the current read fallback when no approved loader tool is available.

## Reproduction Assessment

Yes. Source inspection on current main shows buildSkillsSection always emits read-based SKILL.md guidance and receives no available-tool set, while tool names are normalized before the section is built.

## Solution Assessment

Unclear as proposed. Preferring a registered loader tool is plausible, but maintainers should first choose whether the supported contract is name-based, namespaced, or an explicit skill-loader capability.
