## Summary

Keep open: current main and the latest release still hardcode read-based SKILL.md loading, while the remaining change needs a maintainer decision about the supported skill-loader tool contract.

## What This Changes

Request that the Skills system prompt prefer an available registered Skill loader tool over reading SKILL.md directly when such a tool is present.

## Best Possible Solution

Define the supported loader-tool capability or naming contract, then update the native Skills prompt to prefer that loader when present while preserving the read fallback, with focused tests and docs.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 unconditionally emit read-based skill-loading guidance even though registered tool names are available to prompt construction.

## Solution Assessment

Unclear as proposed. Preferring a registered loader tool is plausible, but maintainers should first choose whether the supported contract is a bare name, a namespace, or an explicit skill-loader capability.
