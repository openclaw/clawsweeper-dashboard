## Summary

Keep open: current main and v2026.6.11 still emit read-based skill-loading guidance, and the remaining change needs a maintainer decision about the supported Skill-loader tool contract rather than conservative cleanup closure.

## What This Changes

The issue requests changing the Skills system prompt so a registered Skill loader tool is preferred over direct SKILL.md reads when that tool is available.

## Best Possible Solution

Define the supported Skill-loader contract, then update src/agents/system-prompt.ts, focused prompt tests, and public docs while preserving the current read fallback when no loader tool is available.

## Reproduction Assessment

Yes, at source level. Current main builds the Skills section with unconditional read-based SKILL.md guidance and does not pass availableTools into that section; I did not run a live model transcript reproduction in this read-only review.

## Solution Assessment

Unclear as proposed. Preferring a registered loader tool is plausible, but maintainers should first choose whether the supported contract is name-based, namespaced, or an explicit skill-loader capability.
