## Summary

Keep open: current main and v2026.6.11 still hardcode read-based SKILL.md loading, while the requested registered Skill-loader path needs a maintainer decision about the supported prompt/tool contract.

## What This Changes

Prefer invoking a registered Skill loader tool in the Skills system prompt when available, falling back to read-based SKILL.md loading otherwise.

## Best Possible Solution

Define the supported skill-loader capability or naming contract, then update the native Skills prompt to prefer that loader when present while preserving the read fallback, with focused tests and docs.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 unconditionally emit read-based skill-loading guidance even though registered tool names are available to prompt construction.

## Solution Assessment

Unclear as proposed. Preferring a registered loader tool is plausible, but maintainers should first choose whether the supported contract is a bare tool name, namespace, or explicit skill-loader capability.
