## Summary

Keep open: current main and v2026.6.11 still emit read-based skill-loading guidance, and the remaining change needs a maintainer decision about the supported Skill-loader tool contract.

## What This Changes

The issue asks OpenClaw to prefer a registered Skill loader tool in the Skills prompt instead of always instructing the model to read SKILL.md files.

## Best Possible Solution

Define the supported Skill-loader tool contract, then update src/agents/system-prompt.ts, focused prompt tests, and public docs while preserving the current read fallback when no loader tool is available.

## Reproduction Assessment

Yes. Source inspection on current main shows buildSkillsSection always emits read-based SKILL.md guidance and receives no available-tool set, while tool names are normalized before the section is built.

## Solution Assessment

Unclear as proposed. Preferring a registered loader tool is plausible, but maintainers should first choose whether the supported contract is name-based, namespaced, or an explicit skill-loader capability.
