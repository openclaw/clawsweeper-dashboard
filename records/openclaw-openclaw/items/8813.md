## Summary

Keep open: current main and the latest release still emit read-based skill-loading guidance, while the remaining change needs a maintainer decision about the supported Skill-loader tool contract.

## What This Changes

Request the Skills system-prompt guidance to invoke a registered Skill-style tool instead of `read` when such a tool is available.

## Best Possible Solution

Define the supported skill-loader tool capability or naming contract, then update `src/agents/system-prompt.ts`, focused prompt tests, and public docs while preserving the current read fallback.

## Reproduction Assessment

Yes. Source inspection on current main shows `buildSkillsSection` always emits read-based SKILL.md guidance and receives no available-tool set, while tool names are normalized before the call.

## Solution Assessment

Unclear as proposed. Preferring a registered loader tool is plausible, but maintainers should first choose whether the contract is name-based, namespaced, or an explicit skill-loader capability.
