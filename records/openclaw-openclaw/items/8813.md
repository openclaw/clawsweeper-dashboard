## Summary

Keep open: current main and the latest release still unconditionally tell the model to read SKILL.md, while the remaining work is a product/plugin contract decision about whether a registered loader tool should get special prompt authority.

## What This Changes

The issue requests changing the Skills section of the agent system prompt so a registered Skill tool is preferred over read-based SKILL.md loading when that tool is available.

## Best Possible Solution

Define the supported skill-loader tool capability or naming contract, then update src/agents/system-prompt.ts, focused prompt tests, and system-prompt docs while preserving the current read fallback.

## Reproduction Assessment

Yes. Source inspection shows that buildAgentSystemPrompt can see normalized tool names, but buildSkillsSection still emits read-based SKILL.md guidance even when a caller could pass a Skill tool name; no tests were run because this review is read-only.

## Solution Assessment

Unclear as proposed. Preferring a registered loader tool is plausible, but maintainers should first choose whether the contract is name-based, namespaced, or an explicit skill-loader capability.
