## Summary

Keep open: current main and the latest release still emit read-based skill-loading guidance, and the remaining work is a maintainer product decision about the supported loader-tool contract.

## What This Changes

The issue asks OpenClaw to prefer a registered Skill loader tool over read-based SKILL.md loading guidance when that tool is available.

## Best Possible Solution

Define the supported skill-loader tool contract, then update src/agents/system-prompt.ts, focused prompt tests, and system-prompt docs while preserving the current read fallback.

## Reproduction Assessment

Yes, at source level. Current main builds the Skills section with unconditional read-based guidance even though available tool names and plugin-registered tools are visible to prompt construction.

## Solution Assessment

Unclear as proposed. Preferring a loader tool is plausible, but maintainers should first choose whether the contract is name-based, namespaced, or an explicit skill-loader capability.
