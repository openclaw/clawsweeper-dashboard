## Summary

## What This Changes

The issue asks OpenClaw to prefer a registered Skill-style loader tool in the system prompt instead of always instructing the model to read SKILL.md directly.

## Best Possible Solution

Define the supported skill-loader tool contract, then update src/agents/system-prompt.ts, focused prompt tests, and public docs while preserving the current read fallback.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 unconditionally emit read-based SKILL.md guidance even though registered tool names are available before prompt assembly.

## Solution Assessment

Unclear as proposed. Preferring a registered loader tool is plausible, but maintainers should first choose whether the contract is name-based, namespaced, or an explicit skill-loader capability.
