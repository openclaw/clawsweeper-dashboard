## Summary

Keep open: current main and the latest release still use read-based skill-loading guidance, while the requested Skill-loader preference remains a product/plugin prompt-authority decision rather than conservative cleanup.

## What This Changes

The issue asks OpenClaw to prefer invoking a registered Skill-style tool in the Skills prompt when that tool is available, while preserving the current read fallback otherwise.

## Best Possible Solution

Define the supported skill-loader tool contract, then update src/agents/system-prompt.ts, focused prompt tests, and system-prompt docs to prefer that loader when registered while preserving the current read fallback.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 still emit read-based Skills guidance even though caller tool names are available before the Skills section is built.

## Solution Assessment

Unclear as proposed. Preferring a registered loader tool is plausible, but maintainers should first choose whether the contract is a literal tool name, a namespaced tool, or an explicit plugin capability marker.
