## Summary

Keep open: current main and the latest release still emit read-based SKILL.md loading guidance even when tool names are available, and the remaining decision is the supported prompt/plugin contract for a Skill-loader tool.

## What This Changes

Request the Skills system prompt to prefer invoking a registered Skill-style tool over read-based SKILL.md loading when that tool is available.

## Best Possible Solution

Define the supported skill-loader contract, then update src/agents/system-prompt.ts, focused prompt tests, and system-prompt docs while preserving the current read fallback.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 unconditionally emit read-based skill-loading guidance even though registered tool names are available to prompt construction.

## Solution Assessment

Unclear as proposed. Preferring a registered loader tool is plausible, but maintainers should first choose whether the contract is name-based, namespaced, or an explicit skill-loader capability.
