## Summary

This PR fixes the reported RPC-rejection case, but it still treats a successful group mutation followed by a failed list refresh as a failed mutation, leaving the persisted collapsed key inconsistent with the Gateway. The external PR also has mock-only proof rather than a real Control UI run.

## What This Changes

Changes Control UI group rename and delete handling so collapsed sidebar keys update only after the session capability resolves, publishes mutation errors, and adds focused Vitest coverage.

## Best Possible Solution

Separate confirmed mutation success from post-mutation refresh failure, update collapsed keys immediately after the RPC is confirmed, report refresh errors independently, and prove both rejection and refresh-after-success cases in a real Control UI setup.
