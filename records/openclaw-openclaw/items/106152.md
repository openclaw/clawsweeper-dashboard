## Summary

The latest head still leaves the prior blocking edge case unresolved: a successful Gateway rename/delete followed by a failed list refresh is reported as mutation failure, so the sidebar does not update the persisted collapsed key even though the authoritative group changed; the supplied behavior proof remains mocked rather than a real Gateway/browser run.

## What This Changes

This PR moves collapsed sidebar-key updates to successful session-group rename/delete completion, publishes group-mutation errors, guards stale connection completions, and adds unit plus mocked-browser regression coverage.

## Best Possible Solution

Separate confirmed RPC mutation success from post-mutation refresh reconciliation, cover successful-request/failed-refresh cases for both rename and delete, then provide redacted live browser or runtime evidence of rejection and disconnect behavior.
