## Summary

The reported LINE limit is real and the PR has credible live provider proof, but the proposed helper applies a UTF-16 code-unit cap to a field that LINE counts in grapheme clusters. That can truncate valid message-action text such as 151 emoji before it reaches LINE, so this needs a narrow correction before merge.

## What This Changes

The PR changes `messageAction()` to cap its outgoing `text` field and adds helper-level plus quick-reply payload tests.

## Best Possible Solution

Keep the shared helper boundary, but cap message-action text at 300 LINE grapheme clusters with a dedicated helper and regressions for 300-versus-301 emoji/grapheme inputs.

## Solution Assessment

No. Centralizing the cap in `messageAction()` is the right boundary, but the current reuse of the UTF-16 action-data helper does not match LINE’s message-action text contract; a message-action-specific grapheme cap is safer.
