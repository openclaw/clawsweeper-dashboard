## Summary

Keep open. Current main and v2026.6.11 still do not provide a user-supplied cost overlay for auto-discovered Amazon Bedrock models; the exact implementation PR was closed unmerged, and the remaining blocker is the config/API shape.

## What This Changes

Request support for attaching per-model cost metadata to Amazon Bedrock models discovered through Bedrock auto-discovery/IAM auth without duplicating an explicit provider model list.

## Best Possible Solution

Choose a maintainer-approved pricing overlay shape, then enrich Bedrock-discovered model definitions without changing model selection or routing and cover it with plugin config, discovery-cache, docs, and usage-display tests.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should user-supplied pricing for discovered Bedrock models live as a Bedrock plugin-local discovery overlay, or as a generic model-cost overlay shared by future discovered providers?

Rationale: The code path is clear, but adding a new user-visible config surface is compatibility-sensitive and the repository policy prefers provider-owned behavior unless a generic core seam is justified.

Likely owner: steipete

Owner reason: The decision is primarily about config surface and provider/plugin ownership, and steipete authored the current plugin-owned discovery config move.

Owner confidence: high

Options:

- **Use Bedrock plugin-local overlay (recommended):** Add a backward-compatible `plugins.entries.amazon-bedrock.config.discovery.costs` map and apply it inside the Bedrock discovery plugin only.
- **Design generic model costs overlay:** Add a top-level provider/model pricing overlay that can patch any discovered provider, but only after maintainers define precedence with explicit provider costs and pricing-cache data.
- **Keep explicit provider models only:** Decline a new overlay and document that exact local pricing requires explicit `models.providers.amazon-bedrock.models[]` entries.

## Reproduction Assessment

Yes, at source level. Current main's Bedrock discovery schema/type/cache/model-definition path exposes no costs map and emits zero DEFAULT_COST for discovered models.

## Solution Assessment

Unclear until maintainers choose the config/API shape. A Bedrock plugin-local overlay is the narrowest owner-boundary fit today; a top-level model-cost overlay needs broader pricing-cache design.
