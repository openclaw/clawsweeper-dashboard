## Summary

Keep open. Current main and v2026.6.11 still build auto-discovered Amazon Bedrock models with zero/default cost metadata and expose no supported discovery pricing overlay; the linked implementation PR is closed unmerged, so the remaining work is the maintainer-approved config/API shape.

## What This Changes

Request to let Bedrock auto-discovered models carry per-model cost metadata without duplicating explicit provider model entries.

## Best Possible Solution

Choose one supported current config shape, preferably plugin-owned discovery pricing unless a general model-cost overlay is approved, then wire it through discovery, cache keys, docs, and focused tests without changing routing.

## Reproduction Assessment

Yes. Source inspection on current main and v2026.6.11 shows discovered Bedrock models use zero/default cost metadata while the strict plugin discovery schema exposes no pricing overlay.

## Solution Assessment

Unclear until maintainers choose the API shape. The old `models.bedrockDiscovery.costs` path is no longer the best exact surface on current main because discovery config is plugin-owned; a generic `models.costs` overlay needs broader config approval.
