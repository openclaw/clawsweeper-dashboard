## Summary

Keep open. Current main and v2026.6.11 still lack a user-supplied pricing overlay for auto-discovered Amazon Bedrock models, and the remaining blocker is choosing the public config/API shape.

## What This Changes

The issue requests cost metadata for Bedrock auto-discovered models without duplicating an explicit provider model list.

## Best Possible Solution

Choose a plugin-owned Bedrock discovery cost overlay under plugins.entries.amazon-bedrock.config.discovery, then update schema, docs, discovery cache keys, model-definition enrichment, and focused tests without changing routing or AWS auth.

Options:

- **Use Bedrock plugin discovery costs (recommended):** Add a costs map under plugins.entries.amazon-bedrock.config.discovery keyed by Bedrock model or profile id, with schema, docs, cache-key, discovery, and regression coverage.
- **Use a generic model-cost overlay:** Add a top-level model-cost overlay that can patch discovered models across providers, accepting the broader config and compatibility review.
- **Keep explicit provider pricing only:** Decline a new overlay and document that users must define explicit provider model entries for local cost estimates.

## Reproduction Assessment

Yes. Source inspection is enough: current Bedrock discovery synthesizes models with zero cost fields and exposes no discovery config path for user-supplied pricing metadata.

## Solution Assessment

Unclear until maintainers choose the API shape. The old models.bedrockDiscovery.costs proposal no longer matches the current plugin-owned config path, and a generic models cost overlay is broader than the proven Bedrock need.
