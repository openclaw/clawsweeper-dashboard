Keep open. Current main and the latest release still lack a user-supplied cost overlay for auto-discovered Amazon Bedrock models, while the direct implementation attempt was closed unmerged; the remaining question is the maintainer-approved config/API shape.

## What This Changes

Request to support user-supplied cost metadata for auto-discovered Amazon Bedrock models without duplicating explicit provider model entries.

## Best Possible Solution

Choose a maintainer-approved pricing overlay, preferably plugin-owned Bedrock discovery config, then update schema, discovery behavior, cache keys, docs, and focused tests without changing AWS auth or routing.

## Maintainer Decision

Kind: product_direction

Question: Which pricing-overlay API should OpenClaw support for auto-discovered Amazon Bedrock models?

Rationale: The fix adds a user-facing provider/config contract, and repository policy sets a high bar for new config surfaces; automation should not choose between a narrow Bedrock plugin-local overlay and a broader generic model-cost overlay.

Likely owner: steipete

Owner reason: The current plugin-owned config and migration boundary traces to this owner path, so this is the clearest decision route.

Owner confidence: high

Options:

- **Use Bedrock plugin discovery costs (recommended):** Add a costs map under plugins.entries.amazon-bedrock.config.discovery keyed by Bedrock model/profile ID, with schema, docs, cache-key, discovery, and regression coverage.
- **Use a generic model cost overlay:** Add a top-level overlay that can patch discovered model pricing across providers, accepting the broader config semantics and compatibility review.
- **Keep explicit provider pricing only:** Decline a new overlay and document that users must define explicit provider model rows for local cost estimates.

## Reproduction Assessment

Yes. Source inspection on current main shows discovered Bedrock models use zero DEFAULT_COST and the strict plugin discovery schema exposes no costs field; live AWS credentials are not needed to observe the missing config path.

## Solution Assessment

Unclear until maintainers choose the API shape. The old models.bedrockDiscovery.costs proposal no longer matches the current plugin-owned discovery config path, while a generic overlay needs broader product approval.
