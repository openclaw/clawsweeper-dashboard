## Summary

Keep open. Current main and v2026.6.11 still lack a pricing overlay for auto-discovered Amazon Bedrock models, and the remaining blocker is the maintainer choice of provider/config API shape.

## What This Changes

Request to add cost metadata for auto-discovered Amazon Bedrock models so IAM/aws-sdk discovery users can see estimated USD usage without duplicating explicit provider model entries.

## Best Possible Solution

Prefer a plugin-owned Bedrock discovery costs overlay under `plugins.entries.amazon-bedrock.config.discovery`, with schema, docs, cache-key, model-definition enrichment, and regression coverage while leaving routing and AWS auth unchanged.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Which pricing-overlay API should OpenClaw support for auto-discovered Amazon Bedrock models?

Rationale: The fix adds a user-facing provider/config contract, and automation should not choose between a narrow Bedrock plugin-local overlay and a broader generic model-cost overlay without maintainer intent.

Likely owner: steipete

Owner reason: The strongest history signal for the config-shape decision is the provider discovery migration into plugin-owned config and provider seam work.

Owner confidence: high

Options:

- **Use Bedrock plugin discovery costs (recommended):** Add a `costs` map under `plugins.entries.amazon-bedrock.config.discovery` keyed by Bedrock model or profile id, with schema, docs, cache-key, discovery, and regression coverage.
- **Use a generic model-cost overlay:** Add a top-level model-cost overlay that can patch discovered models across providers, accepting broader config-surface and compatibility review.
- **Keep explicit provider pricing only:** Decline a new overlay and document that users must define explicit provider model entries for local cost estimates.

## Reproduction Assessment

Yes. Source inspection on current main shows discovered Bedrock models use `DEFAULT_COST` and the strict plugin discovery schema exposes no `costs` field, so live AWS credentials are not needed to verify the missing config path.

## Solution Assessment

Unclear until maintainers choose the permanent API shape. The original `models.bedrockDiscovery.costs` path is now legacy, while the current narrow solution would live under the Amazon Bedrock plugin discovery config.
