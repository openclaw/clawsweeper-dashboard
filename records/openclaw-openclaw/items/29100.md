## Summary

Keep open. Current main and v2026.6.11 still emit auto-discovered Amazon Bedrock models with zero/default cost metadata and expose no supported local pricing overlay for discovery; the remaining decision is the user-facing config/API shape.

## What This Changes

Request to attach cost-per-token metadata to auto-discovered Amazon Bedrock models without duplicating an explicit `models.providers.amazon-bedrock` model list.

## Best Possible Solution

Choose one supported pricing-overlay API, preferably plugin-owned unless maintainers want a broader model-cost overlay, then update schema, discovery cache keys, discovered model metadata, docs, and focused tests together.

## Reproduction Assessment

Yes. Source inspection on current main and v2026.6.11 shows auto-discovered Bedrock models and inference profiles receive zero/default cost metadata while the plugin discovery schema and docs expose no pricing overlay.

## Solution Assessment

Unclear until maintainers choose the API shape. The old legacy `models.bedrockDiscovery.costs` path is not the best exact path on current main because discovery config is now plugin-owned, while a generic `models.costs` overlay would need broader config approval.
