## Summary

Keep open. Current main and the latest release still lack a user-supplied pricing overlay for auto-discovered Amazon Bedrock models; the remaining blocker is the maintainer-owned config/API shape, not source ambiguity.

## What This Changes

Request a user-supplied cost metadata overlay for auto-discovered Amazon Bedrock models so status and usage displays can show USD estimates without duplicating provider model entries.

## Best Possible Solution

Adopt a plugin-owned Bedrock discovery pricing overlay unless maintainers explicitly choose a generic model-cost overlay, then update schema, docs, cache behavior, discovery output, and focused tests without changing routing or AWS auth.

Options:

- **Use Bedrock plugin discovery costs (recommended):** Add a costs map under plugins.entries.amazon-bedrock.config.discovery keyed by Bedrock model or profile ID, with schema, docs, cache-key, discovery, and regression coverage.
- **Use a generic model cost overlay:** Add a top-level model-cost overlay that can patch discovered models across providers, accepting broader config and compatibility review.
- **Keep explicit provider pricing only:** Decline a new overlay and document that users must define explicit provider model entries for local cost estimates.

## Reproduction Assessment

Yes. Source inspection on current main shows Bedrock discovery emits DEFAULT_COST and the strict plugin discovery schema exposes no costs field, so live AWS credentials are not needed to verify the missing config path.

## Solution Assessment

Unclear until maintainers choose the API shape. The legacy models.bedrockDiscovery.costs proposal no longer matches the current plugin-owned config path, while a generic overlay needs broader product approval.
