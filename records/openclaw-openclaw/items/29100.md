## Summary

Keep open. Current main and the latest release still give auto-discovered Bedrock models zero/default cost metadata and expose no supported discovery pricing overlay; the only directly linked implementation pull request is closed unmerged and targeted the old legacy config path.

## What This Changes

Request adding a supported cost metadata overlay for Amazon Bedrock models discovered through Bedrock auto-discovery so status and usage surfaces can estimate USD without duplicating explicit provider model entries.

## Best Possible Solution

Maintainers should choose the pricing overlay contract, preferably plugin-owned Bedrock discovery config unless a general model-cost overlay is approved, then update schema, docs, cache-keying, discovery behavior, and focused tests together.

## Reproduction Assessment

Yes. Source inspection of current main shows discovered foundation models get DEFAULT_COST and inference profiles inherit that zero/default cost, while the plugin discovery schema and docs expose no costs overlay.

## Solution Assessment

Unclear. The gap is real, but the legacy models.bedrockDiscovery.costs proposal is not the best exact path on current main because discovery config has moved to plugins.entries.amazon-bedrock.config.discovery; maintainers need to choose plugin-local versus generic overlay.
