## Summary

Keep open. Current main and v2026.6.11 still do not provide a user-supplied pricing overlay for auto-discovered Amazon Bedrock models; the same-request implementation PR was closed unmerged, so the remaining blocker is the config/API shape.

## What This Changes

Allow local cost metadata overlays for auto-discovered Amazon Bedrock models without duplicating explicit provider model entries.

## Best Possible Solution

Choose the pricing-overlay API, preferably plugin-owned Bedrock discovery config, then update schema, docs, cache keys, discovery behavior, and focused tests without changing routing or AWS auth.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Which pricing-overlay API should OpenClaw support for auto-discovered Amazon Bedrock models?

Rationale: The fix adds a user-facing provider/config contract, and automation should not choose between a narrow Bedrock plugin-local overlay and a broader generic model-cost overlay without maintainer intent.

Likely owner: steipete

Owner reason: The strongest history signal for the current plugin-owned config boundary is the provider-discovery config refactor.

Owner confidence: high

Options:

- **Use Bedrock plugin discovery costs (recommended):** Add a costs map under plugins.entries.amazon-bedrock.config.discovery keyed by Bedrock model or profile id, with schema, docs, cache-key, discovery, and regression coverage.
- **Use a generic model cost overlay:** Add a top-level pricing overlay that can patch discovered models across providers, accepting broader config semantics and compatibility review.
- **Keep explicit provider pricing only:** Decline a new overlay and document that local cost estimates require explicit models.providers entries.

## Reproduction Assessment

Yes. Source inspection on current main shows discovered Bedrock models use zero DEFAULT_COST and the strict plugin discovery schema exposes no costs field, so live AWS credentials are not needed to verify the missing config path.

## Solution Assessment

Unclear until maintainers choose the API shape. The legacy models.bedrockDiscovery.costs proposal no longer matches the current plugin-owned config path, while a generic overlay needs broader product approval.
