## Summary

Keep open. Current main and v2026.6.11 still lack a supported user-supplied pricing overlay for auto-discovered Amazon Bedrock models; the newer explicit-cost display work helps configured provider model entries, but not discovery-managed model definitions.

## What This Changes

Request cost-per-token metadata for automatically discovered Amazon Bedrock models without duplicating explicit provider model entries.

## Best Possible Solution

Adopt a maintainer-approved plugin-owned pricing overlay for Bedrock discovery unless maintainers explicitly want a general model-cost overlay, then update schema, docs, cache keys, discovery behavior, and focused tests together.

Options:

- **Plugin-local discovery overlay (recommended):** Add pricing under plugins.entries.amazon-bedrock.config.discovery so Bedrock owns the provider-specific config surface and core stays lean.
- **General models cost overlay:** Add a broader models-level overlay that can patch any discovered provider model, accepting the larger config/API contract.
- **Keep explicit provider entries only:** Do not add discovery pricing metadata and require users to configure explicit models.providers entries for local cost estimates.

## Solution Assessment

Unclear until maintainers choose the API shape. The old models.bedrockDiscovery.costs path is stale on current main, while a general models cost overlay would need broader config approval.
