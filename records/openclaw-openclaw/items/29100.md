## Summary

Keep open. Current main and v2026.6.11 still do not provide a user-supplied pricing overlay for auto-discovered Amazon Bedrock models; the remaining blocker is choosing the supported config/API shape, not proving the gap.

## What This Changes

Request to attach per-model cost metadata to Amazon Bedrock auto-discovered models without replacing discovery with a duplicate explicit provider model list.

## Best Possible Solution

Add a maintainer-approved pricing overlay that enriches discovered model definitions without changing Bedrock discovery, routing, or auth behavior, preferably in the smallest config surface that can serve future discovered providers too.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should user-supplied costs for discovered models be a Bedrock plugin-local `plugins.entries.amazon-bedrock.config.discovery.costs` map, or a generic model-pricing overlay that can patch any discovered provider/model ref?

Rationale: Both shapes are technically plausible, but the repository has a high bar for new config surfaces and provider-owned behavior, so automation should not choose the public config contract by itself.

Likely owner: Peter Steinberger

Owner reason: The choice is about provider discovery config shape, and Peter authored the current plugin-owned discovery config refactor.

Owner confidence: high

Options:

- **Prefer Generic Pricing Overlay (recommended):** Add one generic model-cost overlay keyed by provider/model ref, then have Bedrock discovery consume the same resolved pricing path as future discovered providers.
- **Keep It Bedrock-Local:** Add `plugins.entries.amazon-bedrock.config.discovery.costs` only, keeping the ownership local to the Bedrock plugin but accepting a provider-specific config shape.
- **Do Not Add Overlay:** Keep the current explicit `models.providers.*.models[].cost` contract and document the redundancy as the supported workaround.

## Reproduction Assessment

Yes, source-level. Current main and v2026.6.11 show Bedrock discovery still emits zero-cost model definitions and exposes no discovery cost overlay in the plugin config schema.

## Solution Assessment

Unclear until maintainers choose the config contract. The requested Bedrock-local `costs` map is plausible, but a generic model-pricing overlay may be the cleaner long-term shape for auto-discovered providers.
