## Summary

Keep open. Current main and v2026.6.11 still have no user-supplied pricing overlay for auto-discovered Amazon Bedrock models; the prior implementation PR was closed unmerged, and the remaining blocker is the config/API shape.

## What This Changes

The issue requests cost-per-token metadata overlays for auto-discovered Amazon Bedrock models without duplicating explicit provider model entries.

## Best Possible Solution

Choose a pricing-overlay API, preferably plugin-owned Bedrock discovery config, then update schema, docs, discovery cache keys, model definition enrichment, and focused tests without changing routing or AWS auth.

Question: Which pricing-overlay API should OpenClaw support for auto-discovered Amazon Bedrock models?

Rationale: The fix adds a user-facing provider/config contract, and automation should not choose between a narrow Bedrock plugin-local overlay and a broader generic model-cost overlay without maintainer intent.

Likely owner: steipete

Owner confidence: high

Options:

- **Use Bedrock plugin discovery costs (recommended):** Add a costs map under plugins.entries.amazon-bedrock.config.discovery keyed by Bedrock model/profile ID, with schema, docs, cache-key, discovery, and regression coverage.
- **Use a generic model-cost overlay:** Add a top-level overlay that can patch discovered models across providers, accepting a broader config surface and compatibility review.
- **Keep explicit provider pricing only:** Decline a new overlay and document that users must define explicit provider model entries for local cost estimates.

## Reproduction Assessment

Yes for the missing capability. Source inspection on current main shows discovered Bedrock models use zero DEFAULT_COST and the strict plugin discovery schema exposes no costs field.

## Solution Assessment

Unclear until maintainers choose the API shape. The legacy models.bedrockDiscovery.costs proposal no longer matches the current plugin-owned config path, while a generic overlay needs broader product approval.
