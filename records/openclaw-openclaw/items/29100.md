## Summary

Keep open. Current main and v2026.6.11 still do not provide a user-supplied pricing overlay for auto-discovered Amazon Bedrock models, and the closed implementation attempt was never merged; the remaining blocker is the maintainer-approved config/API shape.

## What This Changes

The issue requests cost metadata for auto-discovered Amazon Bedrock models so status and usage surfaces can show estimated USD costs without duplicating explicit provider model entries.

## Best Possible Solution

Choose the pricing-overlay API, preferably plugin-owned Bedrock discovery config, then update schema, SDK types, docs, cache keys, discovery behavior, and focused tests without changing routing or AWS auth.

Options:

- **Use Bedrock plugin discovery costs (recommended):** Add a costs map under plugins.entries.amazon-bedrock.config.discovery keyed by Bedrock model/profile ID, with schema, docs, cache-key, discovery, and regression coverage.
- **Use generic model cost overlay:** Add a top-level model-cost overlay that can patch discovered models across providers, accepting a broader config surface and compatibility review.
- **Keep explicit provider pricing only:** Decline a new overlay and document that users must define explicit provider model entries for local cost estimates.

## Reproduction Assessment

Yes. Source inspection on current main shows discovered Bedrock models use zero DEFAULT_COST and the strict plugin discovery schema exposes no costs field; live AWS credentials are not needed to observe that missing config path.

## Solution Assessment

Unclear until maintainers choose the API shape. The old models.bedrockDiscovery.costs proposal no longer matches the current plugin-owned discovery config path, while a generic overlay needs broader product approval.
