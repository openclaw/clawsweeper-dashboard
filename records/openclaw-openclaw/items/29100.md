## Summary

Keep open. Current main and v2026.6.11 still do not provide a user-supplied pricing overlay for auto-discovered Amazon Bedrock models; the same-feature PR was closed unmerged, and the remaining blocker is the maintainer choice of config/API shape.

## What This Changes

Add cost metadata overlay support for auto-discovered Amazon Bedrock models so IAM/aws-sdk discovery users can see estimated costs without duplicating explicit provider model entries.

## Best Possible Solution

Choose the pricing-overlay API, preferably plugin-owned Bedrock discovery config, then align schema, docs, discovery behavior, cache keys, and regression tests without changing Bedrock routing or AWS auth.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Which pricing-overlay API should OpenClaw support for auto-discovered Amazon Bedrock models?

Rationale: The request adds a user-facing provider/config contract, and automation should not choose between a narrow Bedrock plugin-local overlay and a broader generic model-cost overlay without maintainer intent.

Likely owner: steipete

Owner reason: The current plugin-owned config migration and strict discovery schema history make this the strongest routing owner for the API-shape decision.

Owner confidence: high

Options:

- **Use Bedrock plugin discovery costs (recommended):** Add a costs map under plugins.entries.amazon-bedrock.config.discovery keyed by Bedrock model/profile ID, with schema, docs, cache-key, discovery, and regression coverage.
- **Use a generic model cost overlay:** Add a top-level model-cost overlay that can patch discovered models across providers, accepting broader config semantics and compatibility review.
- **Keep explicit provider pricing only:** Decline a new overlay and document that users must define explicit provider model entries for local cost estimates.

## Reproduction Assessment

Yes. Source inspection on current main shows discovered Bedrock models use zero DEFAULT_COST and the strict plugin discovery schema exposes no costs field, so live AWS credentials are not needed to verify the missing config path.

## Solution Assessment

Unclear until maintainers choose the API shape. The legacy models.bedrockDiscovery.costs proposal no longer matches the current plugin-owned config path, while a generic overlay needs broader product approval.
