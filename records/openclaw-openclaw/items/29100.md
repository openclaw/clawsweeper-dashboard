## Summary

Keep open. Current main and v2026.6.11 still lack a user-supplied pricing overlay for auto-discovered Amazon Bedrock models, and the only direct implementation attempt was closed unmerged; the remaining blocker is the maintainer-approved config/API shape.

## What This Changes

The issue requests cost metadata for auto-discovered Amazon Bedrock models without duplicating explicit provider model entries.

## Best Possible Solution

Choose the pricing-overlay API, preferably plugin-owned Bedrock discovery config, then update schema, SDK types, docs, cache keys, discovery behavior, and focused tests without changing routing or AWS auth.

Question: Which pricing-overlay API should OpenClaw support for auto-discovered Amazon Bedrock models?

Rationale: The request adds a new user-facing provider/config contract, and automation should not choose between a narrow Bedrock plugin-local overlay and a broader generic model-cost overlay without maintainer intent.

Likely owner: Peter Steinberger

Owner reason: The current plugin-owned config migration and schema boundary history make this the closest available owner for the config-shape decision.

Owner confidence: high

Options:

- **Use Bedrock plugin discovery costs (recommended):** Add a costs map under plugins.entries.amazon-bedrock.config.discovery keyed by Bedrock model/profile ID, with schema, docs, cache-key, discovery, and regression coverage.
- **Use a generic model cost overlay:** Add a top-level cost overlay that can patch discovered models across providers, accepting broader compatibility and config-surface review.
- **Keep explicit provider pricing only:** Decline a new overlay and document that local cost estimates require explicit provider model entries.

## Reproduction Assessment

Yes. Source inspection on current main shows discovered Bedrock models use zero DEFAULT_COST and the strict plugin discovery schema exposes no costs field; live AWS credentials are not needed to observe that missing config path.

## Solution Assessment

Unclear until maintainers choose the API shape. The old models.bedrockDiscovery.costs proposal no longer matches the current plugin-owned discovery config path, while a generic overlay needs broader product approval.
