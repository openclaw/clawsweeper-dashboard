## Summary

Keep open. Current main and the latest release still lack a supported cost overlay for auto-discovered Amazon Bedrock models, and the only directly related implementation PR was closed unmerged; the remaining blocker is maintainer choice of config/API shape.

## What This Changes

Request support for attaching local token-cost metadata to auto-discovered Amazon Bedrock models without duplicating explicit provider model entries.

## Best Possible Solution

Choose the pricing-overlay API, preferably plugin-owned Bedrock discovery config, then update schema, SDK types, docs, cache keys, discovery behavior, and focused tests without changing routing or AWS auth.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Which pricing-overlay API should OpenClaw support for auto-discovered Amazon Bedrock models?

Rationale: The fix adds a user-facing provider/config contract, and automation should not choose between a narrow Bedrock plugin-local overlay and a broader generic model-cost overlay without maintainer intent.

Likely owner: Peter Steinberger

Owner reason: The current plugin-owned config migration and schema boundary history make this the strongest owner for the config-shape decision.

Owner confidence: high

Options:

- **Use Bedrock plugin discovery costs (recommended):** Add a costs map under plugins.entries.amazon-bedrock.config.discovery keyed by Bedrock model or profile ID, with schema, docs, cache-key, discovery, and regression coverage.
- **Use generic model cost overlay:** Add a top-level model-cost overlay that can patch discovered models across providers, accepting a broader config surface and compatibility review.
- **Keep explicit provider pricing only:** Decline a new overlay and document that users must define explicit provider model entries for local cost estimates.

## Reproduction Assessment

Yes. Source inspection on current main shows discovered Bedrock models use zero DEFAULT_COST and the strict plugin discovery schema exposes no costs field, so live AWS credentials are not needed to verify the missing config path.

## Solution Assessment

Unclear until maintainers choose the API shape. The legacy models.bedrockDiscovery.costs proposal no longer matches the current plugin-owned config path, while a generic overlay needs broader product approval.
