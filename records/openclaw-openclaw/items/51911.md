## Summary

Keep open: current main and v2026.6.11 still have single-agent setup-token/paste-token writes and thin Anthropic setup-token guidance; main-store read-through may mitigate the exact startup failure, but it does not resolve validation or the credential propagation contract.

## What This Changes

The issue asks OpenClaw to make Anthropic setup-token onboarding explain the Claude flow, validate persistence, and work across configured agents without manual credential copying.

## Best Possible Solution

Land a maintainer-approved auth fix that improves setup-token guidance and post-write validation, then either sync only portable static tokens or document main-store inheritance while preserving the OAuth non-copying policy.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: For Anthropic setup-token and manual-token auth, should OpenClaw physically sync portable static token credentials to sibling agent stores, rely on main-store inheritance, or only add validation and guidance?

Rationale: The implementation choice changes where sensitive provider credentials live and prior linked PRs showed that a broad sync helper can accidentally propagate OAuth refresh material.

Likely owner: steipete

Owner reason: steipete has the clearest history across setup-token restoration, Claude CLI preference, and the auth read-through behavior that defines the security boundary.

Owner confidence: high

Options:

- **Sync static tokens only (recommended):** Copy only portable static token credentials for the intended setup-token/manual-token flows, add readback validation and tests, and keep OAuth copying opt-in via the existing portability policy.
- **Use inheritance only:** Keep runtime main-store inheritance as the sharing mechanism and improve prompts, status, doctor, and docs so users understand that sibling files do not need physical copies.
- **Diagnostics only:** Improve the Claude setup-token instructions and post-write validation but leave multi-agent propagation unresolved for now.

## Reproduction Assessment

Partly. Source inspection on current main shows setup-token and paste-token still write only to the selected agent store and the prompt remains thin; the exact gateway startup failure was not live reproduced and may be masked by main-store read-through.

## Solution Assessment

Unclear. Static-token sibling sync is plausible and matches the portability policy, but maintainers should choose sync versus inheritance and ensure OAuth credentials are not broadened before implementation lands.
