## Summary

Keep open: current main and the latest release still write Anthropic setup-token and paste-token profiles to one selected agent store and keep the prompt thin, while runtime main-store read-through only mitigates part of the reported startup failure.

## What This Changes

The issue reports that Anthropic setup-token onboarding can appear successful while leaving credentials missing or unsynchronized across agent contexts.

## Best Possible Solution

Settle the auth-store sharing contract, then land a focused fix that improves setup-token guidance, validates the written SQLite auth profile, and makes portable Anthropic token credentials available to sibling agents without weakening OAuth isolation.

## Maintainer Decision

Question: Should Anthropic setup-token/manual-token credentials be physically copied to sibling agent stores, inherited through main-store read-through, or handled only with validation and clearer setup guidance?

Rationale: This choice affects sensitive credential propagation across per-agent stores and must stay consistent with the current policy that OAuth refresh material is not portable by default.

Likely owner: steipete

Owner reason: The read-through auth-store fix and current credential-sharing boundary route most directly through this owner history.

Owner confidence: high

Options:

- **Narrow static-token availability (recommended):** Make Anthropic token credentials available to sibling agents through an explicit static-token-only sync or inheritance path while keeping OAuth refresh material non-portable.
- **Read-through plus validation only:** Keep the current read-through model, add post-write validation and clearer setup-token guidance, and avoid new physical credential copies.
- **Defer to bulk auth tooling:** Keep this issue open but route cross-agent sync semantics to the broader bulk rotation/sync design in https://github.com/openclaw/openclaw/issues/47684.
