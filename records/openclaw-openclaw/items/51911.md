## Summary

Keep open: current main and the latest release still persist Anthropic setup-token/manual token profiles only to the selected agent store, while runtime main-agent read-through mitigates some missing-profile cases but does not settle the setup UX, write-validation, or credential-sharing contract. Two same-repo fix PRs were closed unmerged after credential-propagation concerns, and the only open closing PR is a conflicted fork, so this remains the canonical maintainer decision item.

## What This Changes

The issue asks for Anthropic setup-token onboarding to avoid misleading instructions, validate token/profile persistence, and make multi-agent auth work without manual credential copying.

## Best Possible Solution

Maintainers should settle the static-token sharing contract, then land or replace a focused fix that improves setup-token guidance, adds write validation, and implements the chosen static-token propagation or inheritance behavior while preserving OAuth isolation.

## Reproduction Assessment

Partly. Source inspection shows setup-token and paste-token flows still persist token profiles to one selected agent store, but I did not establish a live current-main reproduction of the exact gateway startup failure because runtime main-agent read-through may now mask part of it.

## Solution Assessment

Unclear. Sibling sync is plausible for portable static setup tokens, but current main also has main-agent read-through and an explicit OAuth non-copying policy, so maintainers should choose the credential-sharing contract before landing a fix.
