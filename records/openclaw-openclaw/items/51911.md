## Summary

Keep open: current main still has unresolved Anthropic setup-token onboarding gaps, even though runtime main-store read-through likely mitigates the exact missing-sibling startup failure. The open closing PR is a conflicted fork candidate and prior same-repo attempts were closed after credential-propagation security concerns, so this needs maintainer direction rather than cleanup closure.

## What This Changes

The issue asks OpenClaw to make Anthropic setup-token/paste-token onboarding clearer, validate token persistence, and make configured agents able to resolve the credential without manual copying.

## Best Possible Solution

Settle the auth-store sharing contract, then land or replace a focused fix that improves setup-token guidance, adds post-write/readback validation against the SQLite auth store, and implements the chosen static-token inheritance or sync behavior without weakening OAuth isolation.

- **Runtime inheritance only:** Keep credentials in the main store and improve startup/runtime validation so secondary agents resolve inherited profiles without physical copies.
- **Automatic sibling sync:** Copy portable Anthropic token profiles to sibling stores during setup-token/paste-token onboarding, accepting deliberate credential duplication for setup reliability.
