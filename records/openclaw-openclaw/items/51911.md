## Summary

Keep open: current main and the latest release still persist Anthropic setup-token and manual paste-token profiles to one selected agent store, while runtime main-store read-through only mitigates part of the reported failure. The remaining setup-token UX, post-write validation, and credential sharing behavior are security/product-sensitive, and the open linked fork PR is conflicting while prior same-repo fixes were closed unmerged.

## What This Changes

The issue asks OpenClaw to make Anthropic setup-token onboarding reliable by improving prompt guidance, validating token persistence, and resolving multi-agent credential propagation.

## Best Possible Solution

Settle the auth-store sharing contract, then land or replace a narrow fix that improves setup-token guidance, adds immediate persistence validation, and implements the chosen static-token inheritance or copy behavior while keeping OAuth refresh material isolated.

## Reproduction Assessment

Partly/source-only. Current source still shows setup-token and paste-token writes are scoped to one agent store, but I did not establish a live current-main reproduction of the exact gateway startup failure because runtime read-through may mask it.

## Solution Assessment

Unclear. Sibling sync is plausible for portable static setup tokens, but current main also has main-agent read-through and an explicit OAuth non-copying policy, so maintainers should choose the credential-sharing contract before implementation lands.
