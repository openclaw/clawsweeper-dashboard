## Summary

Keep open: current main and v2026.6.11 still persist Anthropic setup-token and paste-token credentials to one selected agent store, while read-through inheritance only mitigates part of the reported multi-agent failure. The remaining prompt clarity, post-write validation, and static-token propagation behavior are credential-boundary work that needs maintainer/security direction, especially with prior same-repo fix PRs closed unmerged and a still-open fork PR referencing this issue.

## What This Changes

The issue requests fixes for Anthropic setup-token onboarding prompt clarity, token persistence validation, and multi-agent auth-profile propagation.

## Best Possible Solution

Settle the auth-store sharing contract, then land or replace a focused fix that improves setup-token guidance, adds post-write validation, and implements the chosen static-token sharing or inheritance behavior while preserving OAuth isolation.

Partly. ## Solution Assessment

Unclear. Sibling sync is plausible for portable static setup tokens, but current main also has main-agent read-through and an explicit OAuth non-copying policy, so maintainers should choose the intended credential-sharing contract before implementation lands.
