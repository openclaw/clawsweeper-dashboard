## Summary

Keep open: current main and latest release v2026.6.11 still persist Anthropic setup-token and paste-token profiles to one resolved agent store, while main-store read-through only partially mitigates missing sibling credentials. The issue also has an open linked fix candidate, but that PR is conflicting and not maintainer-editable, so the remaining credential propagation decision needs human review.

## What This Changes

The issue reports that Anthropic setup-token onboarding can appear successful while leaving credentials missing from sibling agent auth stores, with related UX and post-write validation gaps.

## Best Possible Solution

Keep this issue as the canonical maintainer decision point, then land or replace a narrow fix that defines the credential propagation contract, validates the write path, and updates the Anthropic setup-token UX without adding a new config knob.

## Reproduction Assessment

Yes from source for the remaining write-path gap: current setup-token and paste-token persistence write a profile to one resolved agentDir, while only the OAuth helper exposes explicit sibling sync. I did not run a live Anthropic setup-token flow, so this is source-reproducible rather than fully reproduced.

## Solution Assessment

Unclear; sibling copy is a plausible fix for one class, but the best solution needs maintainer approval because static-token copying, main-store read-through, and doctor/setup validation have different security and upgrade tradeoffs.
