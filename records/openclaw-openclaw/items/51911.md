## Summary

Keep open: current main still stores Anthropic setup-token and paste-token credentials in one selected agent auth store and the user-facing setup-token prompt remains thin; runtime read-through mitigates some multi-agent failures, but the credential-sharing and validation contract still needs maintainer/security judgment.

## What This Changes

The issue asks OpenClaw to make Anthropic setup-token onboarding reliable by clarifying the Claude CLI flow, validating token persistence, and making multi-agent credential resolution work without manual auth-profile copying.

## Best Possible Solution

Settle the auth-store sharing contract, then land or replace a focused fix that improves setup-token guidance, adds post-write validation, and implements the chosen static-token sharing or inheritance behavior while preserving OAuth isolation.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Partly: source inspection confirms setup-token and paste-token still persist to one selected agent store and the prompt remains thin, but I did not establish a live current-main reproduction of the exact gateway startup failure because runtime read-through may now mask it.

## Solution Assessment

Is this the best way to solve the issue? Unclear: sibling sync is plausible for portable static tokens, but current main also has main-agent read-through and an explicit OAuth non-copying policy, so maintainers should choose the intended credential-sharing contract before implementation lands.
