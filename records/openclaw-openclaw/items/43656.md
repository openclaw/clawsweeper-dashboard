Full review comments:

- **[P1] Keep remote session URLs behind the tool allowlist:** `src/agents/tools/sessions-send-tool.ts:87-90`
  - body: This bypass applies to every `peerOpts`, including raw `gatewayUrl` supplied by the model/tool call, so `sessions_send` can now send an explicit token to arbitrary `ws://` or `wss://` hosts instead of the loopback/configured-remote targets enforced by `resolveGatewayOptions`. That defeats the existing SSRF hardening for agent tools; split named peer handling from explicit URL overrides or route explicit URLs through the existing validator.
  - confidence: 0.97
- **[P1] Include idempotencyKey in remote spawn requests:** `src/agents/tools/sessions-spawn-tool.ts:167-179`
  - body: The remote `sessions_spawn` branch forwards to the gateway `agent` method without `idempotencyKey`, but `AgentParamsSchema` requires that field. As written, cross-gateway spawns can be rejected by the remote gateway before any agent run starts.
  - confidence: 0.95
- **[P2] Reject ambiguous remote send targets:** `src/agents/tools/sessions-send-tool.ts:71-80`
  - body: The remote branch only checks that one of `sessionKey` or `label` is present, so a call with both silently prefers `sessionKey`. The local path rejects that combination; keeping different behavior here can route a cross-gateway message to the wrong remote session instead of surfacing an input error.
  - confidence: 0.9
- **[P2] Make peer tokens match gateway auth requirements:** `src/agents/tools/gateway-peer.ts:59-62`
  - body: The helper still returns a configured peer with `gatewayToken: undefined`, and the tests/schema allow tokenless peers, but `callGateway` requires explicit credentials for URL overrides. Either require a token for peer routing or reject tokenless peers before attempting a remote call so the advertised `studio`-style config does not fail at runtime.
  - confidence: 0.86
