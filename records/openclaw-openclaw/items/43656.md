## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Keep gatewayUrl routing behind the tool allowlist:** `src/agents/tools/sessions-send-tool.ts:87-90`
  - body: This fast path takes `gatewayUrl` from model-visible session-tool params and passes it directly to `callGateway`, bypassing the shared `resolveGatewayOptions` guard that other tools use to limit overrides to loopback or configured `gateway.remote.url`. That broadens where operator-write session traffic can be sent; peer support should extend the canonical validator or restrict ad-hoc URLs to an approved config path.
  - confidence: 0.86
- **[P1] Send an idempotencyKey for remote spawns:** `src/agents/tools/sessions-spawn-tool.ts:167-179`
  - body: The remote `sessions_spawn` branch calls the gateway `agent` method without `idempotencyKey`, but the gateway protocol requires `AgentParamsSchema.idempotencyKey`. A cross-gateway spawn will be rejected as invalid params before the remote run starts.
  - confidence: 0.94
- **[P2] Reject or require credentials for tokenless peers:** `src/agents/tools/gateway-peer.ts:59-62`
  - body: `gateway.peers.<name>.token` is optional and the test covers a tokenless `studio` peer, but `callGateway` treats the peer URL as an explicit override and requires explicit credentials. Tokenless peers will fail locally with `gateway url override requires explicit credentials` instead of reaching the remote gateway as described.
  - confidence: 0.88
- **[P2] Preserve sessionKey and label exclusivity on remote sends:** `src/agents/tools/sessions-send-tool.ts:74-80`
  - body: The remote branch only checks that at least one target was provided, while the local path rejects calls that provide both `sessionKey` and `label`. Cross-gateway sends can therefore silently prefer `sessionKey` and ignore the label, which can route a message to a different remote session than the caller intended.
  - confidence: 0.84
