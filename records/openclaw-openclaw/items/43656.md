## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.93

Full review comments:

- **[P1] Keep raw gateway URLs behind the tool allowlist:** `src/agents/tools/gateway-peer.ts:66-67`
  - body: The new explicit `gatewayUrl` path returns an arbitrary URL and the session tools pass it directly to `callGateway`, bypassing the existing agent-tool allowlist that rejects non-loopback or non-configured remote targets. That reopens the URL-override security boundary for model-callable session tools; keep raw URLs behind the existing policy or make this config-only through a maintainer-approved peer contract.
  - confidence: 0.94
- **[P1] Implement remote spawn through a real spawn contract:** `src/agents/tools/sessions-spawn-tool.ts:158-160`
  - body: The remote branch maps `sessions_spawn(agentId=...)` to `sessionKey = agent:<id>:main` and sends a normal `agent` message, so it does not create the isolated child session or return the `childSessionKey` that current sessions_spawn callers and subagent tracking expect. Even after transport fixes, this would turn remote spawn into a send-to-main operation instead of a remote spawn.
  - confidence: 0.92
- **[P1] Include idempotencyKey in remote spawn requests:** `src/agents/tools/sessions-spawn-tool.ts:167-179`
  - body: The remote `agent` call omits `idempotencyKey`, but `AgentParamsSchema` requires it, so the gateway rejects the request before the remote run can start. Add an idempotency key to the forwarded request and cover the end-to-end remote spawn path.
  - confidence: 0.97
- **[P2] Reject mixed sessionKey and label on remote sends:** `src/agents/tools/sessions-send-tool.ts:71-73`
  - body: The remote sessions_send branch accepts both `sessionKey` and `label` and silently prefers `sessionKey`, while the local branch rejects that combination. Keep the same input contract remotely so a caller does not accidentally send to a different remote session than the provided label indicates.
  - confidence: 0.86
