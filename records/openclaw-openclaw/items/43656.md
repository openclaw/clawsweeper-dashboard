  - body: The forwarded `agent` params for remote `sessions_spawn` omit `idempotencyKey`, but the gateway protocol requires that field and the server validates it before handling the request. As written, cross-gateway spawn will be rejected before it starts a remote run.
  - confidence: 0.95
- **[P2] Require or implement tokenless peer auth before advertising it:** `src/agents/tools/gateway-peer.ts:59-62`
  - body: Named peers can resolve to an explicit URL with `gatewayToken` left undefined, and the PR examples make tokens look optional. `callGateway` rejects explicit URL overrides without explicit credentials, so tokenless peers fail locally before any remote gateway request; either require a token here or add an approved credential mode for peer URLs.
  - confidence: 0.88
- **[P2] Reject conflicting remote session targets:** `src/agents/tools/sessions-send-tool.ts:71-80`
  - body: The remote branch only rejects the case where neither `sessionKey` nor `label` is provided, while the local branch rejects supplying both. If both are sent to a remote gateway, this silently prefers `sessionKey` and ignores `label`, which makes cross-gateway routing inconsistent with local `sessions_send` and can target the wrong session.
