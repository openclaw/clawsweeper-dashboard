Full review comments:

- **[P1] Keep remote session URLs behind the gateway allowlist:** `src/agents/tools/gateway-peer.ts:66-67`
  - body: By returning any caller-supplied `gatewayUrl` here, both new session-tool paths bypass `resolveGatewayOptions`, which currently rejects non-loopback and non-configured-remote targets as SSRF hardening. Please route through a named configured peer or extend the shared resolver so raw model-callable URLs cannot send operator-authenticated WebSocket traffic to arbitrary hosts.
  - confidence: 0.93
- **[P1] Include idempotencyKey in remote spawn calls:** `src/agents/tools/sessions-spawn-tool.ts:167-179`
  - body: The remote `sessions_spawn` branch forwards to the gateway `agent` method but does not include `idempotencyKey`. `AgentParamsSchema` requires that field, so cross-gateway spawn requests are rejected as invalid params before the remote run starts.
  - confidence: 0.98
- **[P2] Reject tokenless peers before calling callGateway:** `src/agents/tools/gateway-peer.ts:59-62`
  - body: The helper still returns a peer override when no token is available, and the tests assert that tokenless peers resolve successfully. `callGateway` treats this as an explicit URL override and requires explicit credentials, so those peer entries fail before any remote request is attempted.
  - confidence: 0.9
- **[P2] Preserve sessionKey and label exclusivity remotely:** `src/agents/tools/sessions-send-tool.ts:74-80`
  - body: The remote branch only rejects the case where neither target is provided, while the local branch rejects `sessionKey` plus `label`. With both fields present, cross-gateway sends silently prefer `sessionKey`, which can route a message to an unintended remote session instead of surfacing the same input error.
  - confidence: 0.88
