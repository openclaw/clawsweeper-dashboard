## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.93

Full review comments:

- **[P1] Keep remote session URLs behind approved gateway policy:** `src/agents/tools/sessions-send-tool.ts:98-99`
  - body: The remote path passes `peerOpts.gatewayUrl` directly to `callGateway` while the helper also accepts raw `gatewayUrl` from tool params. That bypasses the existing agent-tool allowlist for loopback or configured remote gateways, so a model-callable session tool can direct backend WebSocket traffic to arbitrary hosts when a token is supplied.
  - confidence: 0.95
- **[P1] Include idempotencyKey in remote sessions_spawn:** `src/agents/tools/sessions-spawn-tool.ts:167-179`
  - body: The remote `agent` request built here omits `idempotencyKey`, but the gateway protocol requires that field for `agent` params. Cross-gateway spawn calls will be rejected as invalid before the remote run starts.
  - confidence: 0.98
- **[P2] Preserve sessionKey and label exclusivity remotely:** `src/agents/tools/sessions-send-tool.ts:74-80`
  - body: The remote branch only rejects the neither-provided case, so when both `sessionKey` and `label` are supplied it silently prefers `sessionKey`. The local path rejects that ambiguous input, and this divergence can send a remote message to the wrong session instead of returning an input error.
  - confidence: 0.9
- **[P2] Reject or explicitly support tokenless peers:** `src/agents/tools/gateway-peer.ts:59-62`
  - body: The helper returns named peers with `gatewayToken: undefined`, and the tests document that as valid, but `callGateway` requires explicit credentials for any URL override. A tokenless peer will fail locally before contacting the remote gateway unless the PR either rejects it up front or adds a reviewed auth-none peer mode.
  - confidence: 0.88
