## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.94

Full review comments:

- **[P1] Preserve the gatewayUrl allowlist for explicit overrides:** `src/agents/tools/gateway-peer.ts:66-67`
  - body: `resolveGatewayPeerOptions` returns any raw `gatewayUrl`, and both new session callers pass that URL directly to `callGateway` after bypassing `resolveGatewayOptions`. Existing agent-tool overrides are limited to loopback or configured `gateway.remote.url`; this change lets model-facing session tools open operator-authenticated WebSocket traffic to arbitrary hosts. Distinguish named configured peers from explicit URL overrides and keep raw `gatewayUrl` on the existing allowlisted path, or add a maintainer-approved peer trust policy.
  - confidence: 0.96
- **[P1] Include idempotencyKey in remote spawn requests:** `src/agents/tools/sessions-spawn-tool.ts:167-179`
  - body: The remote `sessions_spawn` branch forwards method `agent` without `idempotencyKey`, but the gateway protocol requires that field on `AgentParamsSchema`. Cross-gateway spawn calls will be rejected as invalid params before a remote run starts.
  - confidence: 0.98
- **[P2] Reject ambiguous remote session targets:** `src/agents/tools/sessions-send-tool.ts:71-80`
  - body: The remote `sessions_send` branch only rejects the case where neither `sessionKey` nor `label` is provided. If both are present it silently prefers `sessionKey`, unlike the local path, which rejects the ambiguous target and avoids routing to an unintended session.
  - confidence: 0.9
- **[P2] Make peer token optionality match callGateway:** `src/agents/tools/gateway-peer.ts:59-62`
  - body: Named peers can resolve with `gatewayToken: undefined`, and the PR documents tokenless peers as valid, but `callGateway` treats explicit URL overrides as requiring explicit credentials. A peer without a token will fail before the remote request, so either require peer tokens for this surface or design an explicit no-auth peer mode with tests.
  - confidence: 0.88
