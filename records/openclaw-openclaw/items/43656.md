Full review comments:

- **[P1] Keep remote URLs behind the gateway allowlist:** `src/agents/tools/sessions-send-tool.ts:87-90`
  - body: This branch adds model-facing `gatewayUrl` input and then passes `peerOpts.gatewayUrl` directly to `callGateway`, explicitly bypassing the `resolveGatewayOptions` guard that current gateway tools use to restrict overrides to loopback or `gateway.remote.url`. That widens operator-authenticated WebSocket traffic to arbitrary model-supplied hosts; keep raw URLs on the existing allowlist or require an operator-approved peer registry before calling the remote gateway.
  - confidence: 0.96
- **[P1] Include idempotencyKey in remote spawn requests:** `src/agents/tools/sessions-spawn-tool.ts:167-179`
  - body: The remote `sessions_spawn` branch calls the gateway `agent` method with `message`, optional `sessionKey`/`label`, delivery flags, and provenance, but no `idempotencyKey`. `AgentParamsSchema` requires that field, so cross-gateway spawn requests will be rejected as invalid params before the remote run can start.
  - confidence: 0.99
- **[P2] Make tokenless peers fail before routing:** `src/agents/tools/gateway-peer.ts:59-62`
  - body: `resolveGatewayPeerOptions` still returns a peer URL with `gatewayToken: undefined`, and the tests advertise peers without tokens, but `callGateway` requires explicit credentials for URL overrides. A configured tokenless peer will fail with a generic gateway URL override auth error before it reaches the remote gateway; require a token or make the unsupported case explicit in peer resolution.
  - confidence: 0.88
