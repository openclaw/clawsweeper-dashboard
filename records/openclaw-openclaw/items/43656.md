- **[P1] Keep remote session URLs behind the Gateway allowlist:** `src/agents/tools/sessions-send-tool.ts:89-99`
  - body: The new remote path passes `peerOpts.gatewayUrl` directly to `callGateway`, bypassing the current `resolveGatewayOptions` allowlist for loopback or configured `gateway.remote.url`. Because this also exposes raw `gatewayUrl`/`gatewayToken` to model calls, it opens a new operator-authenticated WebSocket target path instead of a maintainer-approved peer boundary.
  - confidence: 0.93
- **[P1] Include an idempotency key for remote spawn requests:** `src/agents/tools/sessions-spawn-tool.ts:167-169`
  - body: The remote `sessions_spawn` branch calls the Gateway `agent` method without `idempotencyKey`, but `AgentParamsSchema` requires it. Cross-gateway spawn requests will be rejected as invalid before the remote run starts.
  - confidence: 0.98
- **[P1] Define the reply extraction helpers before using them:** `src/agents/tools/sessions-send-tool.ts:220-224`
  - body: The remote `sessions_send` history branch calls `stripToolMessages` and `extractAssistantText`, but this patch does not define or import either helper and current main has no such symbols in this module. The TypeScript build will fail on the new remote reply path.
  - confidence: 0.86
- **[P2] Reject tokenless peers before calling overridden URLs:** `src/agents/tools/gateway-peer.ts:59-61`
  - body: The helper returns peer options with `gatewayToken: undefined`, and the tests treat tokenless peers as supported, but `callGateway` requires explicit credentials for URL overrides. A configured peer without a token will fail before the request reaches the remote gateway, so the helper should either require a token for remote peers or implement a documented auth-none path.
  - confidence: 0.9
