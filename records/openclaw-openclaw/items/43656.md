Full review comments:

- **[P1] Keep raw gateway URLs behind the agent-tool allowlist:** `src/agents/tools/gateway-peer.ts:66-67`
  - body: `resolveGatewayPeerOptions` returns caller-supplied `gatewayUrl` directly, and the new session paths pass that URL to `callGateway` instead of `resolveGatewayOptions`. That bypasses the existing SSRF hardening that rejects non-loopback/non-configured remote URLs for agent tools, so a model-facing session tool can open operator-authenticated WebSocket traffic to arbitrary hosts.
  - confidence: 0.96
- **[P1] Forward remote spawn through a valid spawn contract:** `src/agents/tools/sessions-spawn-tool.ts:163-179`
  - body: The remote `sessions_spawn` branch calls the gateway `agent` method with only message/session routing and no `idempotencyKey`. The current `AgentParamsSchema` requires `idempotencyKey`, so this request is rejected before a run starts; even after adding it, this still targets a main session instead of creating/tracking a spawned session, so the remote path collapses `sessions_spawn` into `sessions_send`.
  - confidence: 0.94
- **[P2] Reject tokenless peers before calling overridden gateways:** `src/agents/tools/gateway-peer.ts:59-62`
  - body: The helper returns a peer override with `gatewayToken: undefined` when a configured peer omits a token, but `callGateway` rejects any explicit URL override without explicit credentials. That makes the documented tokenless peer example fail with a lower-level auth error; require a resolved token for peers or reject the config before routing.
  - confidence: 0.9
- **[P2] Preserve sessionKey and label exclusivity remotely:** `src/agents/tools/sessions-send-tool.ts:70-74`
  - body: The remote `sessions_send` path only rejects the neither-provided case, so callers can provide both `sessionKey` and `label` and the branch silently prefers `sessionKey`. The local path rejects that combination to avoid ambiguous targeting; keep the same validation before crossing gateway boundaries.
  - confidence: 0.88
