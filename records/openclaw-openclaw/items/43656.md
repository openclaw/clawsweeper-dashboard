## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.93

Full review comments:

- **[P1] Keep raw gatewayUrl overrides on the existing allowlist:** `src/agents/tools/gateway-peer.ts:66-67`
  - body: The helper returns model-supplied `gatewayUrl` directly, and both new session paths pass that URL to `callGateway` instead of the existing agent-tool `resolveGatewayOptions` allowlist. That reopens arbitrary off-host WebSocket targets for model-callable tools when a `gatewayToken` is supplied, contrary to the current SSRF-hardening tests; keep raw URLs behind the existing allowlist or remove raw URL routing and use only approved configured peers.
  - confidence: 0.96
- **[P1] Include idempotencyKey in remote spawn agent calls:** `src/agents/tools/sessions-spawn-tool.ts:167-179`
  - body: The remote spawn branch calls the gateway `agent` method without `idempotencyKey`, but `AgentParamsSchema` requires that field and the server rejects invalid agent params before starting a run. Any cross-gateway `sessions_spawn` that reaches this call will fail instead of spawning remotely.
  - confidence: 0.97
- **[P2] Reject tokenless peers before calling an explicit URL:** `src/agents/tools/gateway-peer.ts:59-62`
  - body: The helper advertises tokenless peers by returning `gatewayToken: undefined`, but `callGateway` treats any explicit URL as an override and requires explicit credentials before opening the websocket. Either require a resolved peer token in this config path or change the design/tests so tokenless peers do not pass through an explicit URL override that is guaranteed to fail.
  - confidence: 0.9
- **[P2] Keep sessionKey and label mutually exclusive remotely:** `src/agents/tools/sessions-send-tool.ts:70-80`
  - body: The remote send path only rejects the case where neither target is provided, so callers can provide both `sessionKey` and `label` and silently route by `sessionKey`. The local path rejects that combination; the remote path should preserve the same invariant to avoid unintended cross-gateway routing.
  - confidence: 0.88
