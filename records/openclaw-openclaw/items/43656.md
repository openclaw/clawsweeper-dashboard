  - body: The new remote branch passes `peerOpts.gatewayUrl` directly to `callGateway`, bypassing the existing agent-tool `gatewayUrl` allowlist for loopback or configured `gateway.remote.url`.   - confidence: 0.96

  - body: The remote `sessions_spawn` branch calls the Gateway `agent` method without `idempotencyKey`, but `AgentParamsSchema` requires that field. Cross-gateway spawn requests will be rejected as invalid params before the remote run starts.
  - confidence: 0.98
- **[P2] Preserve sessionKey and label exclusivity remotely:** `src/agents/tools/sessions-send-tool.ts:74-80`
  - body: The remote `sessions_send` path only handles the neither-provided case, so providing both `sessionKey` and `label` silently prefers `sessionKey`. The local path rejects this combination, and the remote divergence can send to a different session than the caller intended.
  - confidence: 0.9
- **[P2] Reject tokenless peers before calling the override path:** `src/agents/tools/gateway-peer.ts:59-62`
  - body: `gateway.peers` tokens are documented and tested as optional, but `callGateway` treats an explicit URL as an override and requires explicit credentials. A peer like the tested `studio` entry resolves to `{ gatewayToken: undefined }` and then fails before the remote request is attempted.
  - confidence: 0.88
