## Summary

Keep open. Current main and v2026.6.11 still have the one-shot Control UI mount fallback, and two open PRs now explicitly target this issue, so the best cleanup path is to review and land a correct linked fix rather than close the issue early.

## What This Changes

The issue asks for the Control UI pre-mount fallback to retry the failed app bundle and show gateway-restart-aware recovery copy when the gateway is briefly unavailable.

## Best Possible Solution

Land a narrow static Control UI fallback fix that loads the actual app bundle again, uses gateway-reachability-aware copy, and proves recovery against built assets; keep launchd restart/config changes separate.

## Reproduction Assessment

Yes for the source-level fallback dead end: current main's `Keep waiting` path does not retry a failed module bundle, and existing tests assert that it only re-arms the fallback. The full macOS launchd timing was not live-reproduced.

## Solution Assessment

Yes, the narrow static fallback recovery path is the best first fix. A launchd throttle config knob would add broader configuration surface and should not be bundled into this bug fix without separate maintainer approval.
