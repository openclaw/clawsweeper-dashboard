## Summary

Keep open. Current main still has the reported Control UI startup fallback: the module defines `openclaw-app`, but the static `Keep waiting` action only hides the dialog and re-arms the timer, so it cannot recover from a failed initial module fetch.

## What This Changes

The issue asks Control UI to recover and diagnose correctly when the app bundle fails to load during a brief gateway restart instead of leaving `Keep waiting` as a dead end.

## Best Possible Solution

Add a bounded Control UI bootstrap retry and clearer diagnosis path that re-requests the app module after transient gateway loss, then leave launchd throttle/config policy to a separate maintainer decision if still needed.

## Reproduction Assessment

Yes at source level: current `ui/index.html` shows `Keep waiting` only re-arms the fallback timer while `openclaw-app` registration depends on the failed module evaluating. I did not run a fresh macOS launchd down-window replay.

## Solution Assessment

Yes for the narrow UI bootstrap repair: make the existing recovery affordance retry the module and improve diagnosis. Adding a launchd `ThrottleInterval` config knob is not the best first fix because OpenClaw's config-surface bar is high and the UI can recover without it.
