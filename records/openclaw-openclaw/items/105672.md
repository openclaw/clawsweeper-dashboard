## Summary

Keep open: current main creates pending Skill Workshop proposals only from explicit prospective instructions or reactive corrections; it does not infer techniques from otherwise successful, nontrivial work. The existing governed proposal path is reusable, but the new autonomy threshold and final-reply timing require explicit product direction.

## What This Changes

Add opt-in autonomous review of successful nontrivial agent work so Skill Workshop can create or revise pending reusable-technique proposals without automatically applying them.

## Best Possible Solution

Extend the existing pending-proposal path with a tightly gated successful-run reflection that reuses writable-skill routing and scanning, rejects credentials before persistence, and proves routine or weakly supported runs remain no-ops.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should autonomous Skill Workshop infer reusable techniques from successful trajectories without an explicit correction or `/learn` request, and should that reflection delay the final reply?

Rationale: The request changes agent initiative, turn latency, and the evidence threshold for durable learned behavior; source inspection cannot safely choose those product semantics.

Likely owner: steipete

Owner reason: He opened the narrowed proposal and has recent history on the current agent-end Skill Research integration, making him the strongest available owner for its intended autonomy semantics.

Owner confidence: high

Options:

- **Add gated successful-run reflection (recommended):** Use the existing opt-in and pending-review boundary with strict success, nontriviality, reuse, evidence, secret, and no-op gates before the final reply.
- **Keep explicit learning triggers:** Continue requiring prospective instructions, corrections, or `/learn` to avoid speculative proposals and extra turn latency.
- **Evaluate asynchronous reflection:** Run reflection after delivery and surface proposals later, trading immediate visibility for lower reply latency.
