## Summary

Keep open: current main and v2026.6.11 still have a fixed cross-origin redirect safe-header allowlist, and the requested opt-in custom-header policy changes a credential-forwarding boundary that needs maintainer security/product direction.

## What This Changes

The issue requests an opt-in `security.fetchGuard.additionalSafeHeaders` configuration so selected custom headers can survive fetch-guard cross-origin redirects.

## Best Possible Solution

Keep strict stripping as the default; if maintainers approve the capability, implement a scoped operator policy that validates header names, constrains destination origins, documents the risk, and proves the default remains strict.
