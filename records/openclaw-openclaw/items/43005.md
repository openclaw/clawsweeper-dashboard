## Summary

Keep open: current main and the latest release still use a fixed cross-origin redirect header allowlist, and allowing custom credential-like headers across origins needs maintainer security and product direction before implementation.

## What This Changes

The issue requests an opt-in configuration option to retain selected custom headers during fetch-guard cross-origin redirects.

## Best Possible Solution

Keep strict stripping as the default; if maintainers approve the capability, implement a narrowly scoped operator policy with explicit header-name validation, destination-origin constraints, docs, and regression tests.

## Solution Assessment

Unclear until maintainers choose the trust model. A global header-only allowlist is riskier than a scoped operator policy that constrains both header names and redirect targets.
