## Summary

Keep open: current main and the latest release still use a fixed cross-origin redirect safe-header allowlist, so the requested opt-in custom-header retention remains an unresolved security/config product decision.

## What This Changes

Request adding a `security.fetchGuard.additionalSafeHeaders` config option so selected custom headers can survive fetch-guard cross-origin redirects.

## Best Possible Solution

Keep strict stripping as the default; if maintainers approve the capability, implement a narrow operator policy with explicit header and target-origin guardrails plus tests for default stripping and approved retention.
