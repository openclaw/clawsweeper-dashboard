## Summary

Current documentation still defines Dreaming as one managed sweep whose phases are internal, while only deep performs durable promotion into `MEMORY.md`; the requested supported non-durable production contract therefore remains meaningful and is not owned by another identified item.

## What This Changes

Requests a supported way to run light/REM-style memory reflection without durable promotion into startup memory, via configuration phase controls or a first-class non-durable CLI/API.

## Best Possible Solution

Add a memory-plugin-owned non-durable promotion policy that keeps phase sequencing internal, guarantees no startup-memory or durable-promotion writes, and reports attempted/performed writes plus artifact paths, with protected-file invariant tests.
