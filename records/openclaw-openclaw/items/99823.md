## Summary

Keep open. Current main still parses Slack directive choices with the first colon as the label/value delimiter, so time labels such as `9:00` are truncated and the returned button value is shifted; the related Slack interaction-injection issue is downstream and does not cover this parser bug.

## What This Changes

The issue reports that Slack `[[slack_buttons:]]` entries with colons in the label, such as meeting times, produce truncated labels and wrong action values.

## Best Possible Solution

Update the Slack directive parser in the Slack plugin so the label/value delimiter is the last non-style colon, then add focused regression coverage for time labels and existing style suffix behavior.

## Reproduction Assessment

Yes from source, but not from an executed current-main test in this read-only review. `compileSlackInteractiveReplies` calls `parseChoice`, and `parseChoice` splits at the first colon, so a label like `9:00` becomes label `9` and value starting `00:`.

## Solution Assessment

Yes. The narrowest maintainable fix is in the Slack plugin directive parser: preserve no-colon and single-colon behavior, strip optional button style suffixes deliberately, and split multi-colon entries at the intended label/value boundary.
