## Summary

Current main confirms avoidable whole-registry cloning on a bounded task-list path. The issue remains necessary, has no duplicate or open fix, and is narrow enough for a focused repair; “unbounded history” is slightly overstated because terminal records are time-pruned, but retained record count can still grow with task throughput.

## What This Changes

Avoid deep-cloning the full retained task registry before filtering, ordering, and paginating bounded task-list responses.

## Best Possible Solution

Add a generic internal task-registry page query that evaluates filters and ordering on authoritative records, determines whether another page exists, and clones only the records returned to the gateway, while leaving existing full-list APIs unchanged for other consumers.
