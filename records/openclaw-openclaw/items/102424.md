## Summary

Keep this PR open but do not merge the current head: it now fixes the prior transient reconnect cache reset and has direct screenshot proof for the disconnect state, but the permanent first-connect guard is too broad and can keep stale sidebar sessions visible after an explicit Gateway/client replacement.

## What This Changes

The PR changes `ui/src/components/app-sidebar.ts` to ignore null session snapshots during Gateway disconnects and to clear sidebar session caches only on the first connection.

## Best Possible Solution

Preserve sidebar session rows only for transient disconnect/retry of the same session lineage, while clearing rendered results and per-agent/order caches on explicit Gateway replacement, stop/start, or settings-driven client changes.
