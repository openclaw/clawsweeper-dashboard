## Summary

Current main still keeps Telegram spool-handler lane guards in process-wide state that survives same-process channel restarts, while the shared health monitor only performs channel stop/start recovery. ## Best Possible Solution

Provide bounded recovery that preserves the one-live-handler-per-lane invariant, crosses a demonstrably hard cancellation or supervised process boundary, drains queued updates afterward, and explicitly handles or diagnoses unsupervised installations.
