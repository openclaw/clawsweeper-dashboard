## Summary

The PR remains necessary, but it does not fully close the reported prototype-chain credential path: inherited intermediate config objects can still supply an own `apiKey` that the new terminal checks accept.

The PR changes Brave's terminal `apiKey` presence checks to own-property checks and adds twelve regression tests for plugin and legacy credential readers.

## Best Possible Solution

Make every segment of the plugin and legacy credential paths ownership-aware, preserve valid plugin-first precedence and legacy fallback, and prove both intermediate and terminal inherited properties are rejected.
