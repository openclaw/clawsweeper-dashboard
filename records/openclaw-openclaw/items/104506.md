## Summary

The prior P1 blocker remains on the force-pushed head: the implementation hardens only the terminal `apiKey` fields while ordinary reads still accept inherited intermediate objects, and the posted proof does not exercise that bypass. ## What This Changes

The PR changes Brave plugin and legacy credential readers to require an own terminal `apiKey` property and adds twelve inheritance-focused regression tests.

## Best Possible Solution

Define the supported credential trust boundary, then either apply complete ownership-aware traversal at the shared web-search credential owner with end-to-end proof, or narrow the PR to a clearly documented defense-in-depth change without claiming a persisted-config vulnerability.
