## Summary

Keep open: current main and the latest release still lack the stalled bind-probe timeout, and this PR remains the active candidate for the linked gateway startup hang, but it needs real macOS proof and a rebase before merge.

## What This Changes

The PR adds a default 3000 ms timeout to `canBindToHost` in `src/gateway/net.ts` so stalled bind probes resolve `false` instead of hanging gateway startup.

## Best Possible Solution

Rebase or reapply the timeout on current main, add focused stalled-probe coverage, and land it after redacted macOS 11 startup proof or an explicit maintainer proof override.

## Reproduction Assessment

Yes, source-level: if the IPv6 bind probe never emits `listening` or `error`, current main's helper promise never settles and gateway startup waits in `resolveGatewayListenHosts`. I did not live-reproduce the macOS Big Sur kernel behavior here.

## Solution Assessment

Yes for the fix direction, but not for the current landing state. A bounded generic bind-probe timeout is narrower than a macOS-only skip because it preserves working IPv6 loopback binding, but the branch still needs rebase, proof, and focused coverage.
