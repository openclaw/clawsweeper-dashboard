## Summary

Keep open. Current main has side-reader recovery for truncated assistant history plus JSON/tool/duplicate-message disclosures, but normal long assistant Markdown still renders inline without the requested show-more/show-less collapse; the closest progressive-disclosure PR was closed unmerged.

## What This Changes

The issue requests inline collapsible or foldable assistant messages in the Control UI chat for long responses, with optional collapse-all and expand-all controls.

## Best Possible Solution

Have maintainers choose the Control UI disclosure policy, then implement inline long-message collapse in the chat renderer with focused UI tests and updated user-facing docs if the behavior becomes a documented contract.

## Reproduction Assessment

Not applicable: this is a feature request for a new Control UI interaction pattern, not a broken existing behavior report. Source inspection confirms current main lacks inline long-message collapse for normal assistant Markdown.

## Solution Assessment

Unclear: inline collapse is a plausible solution, but the best thresholds, default-expanded behavior, and global controls need maintainer UX direction. The existing side reader solves truncated-history recovery but does not replace the requested inline collapse.
