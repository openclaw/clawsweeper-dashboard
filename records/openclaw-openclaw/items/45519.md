## Summary

Keep open. Current main has side-reader full-message recovery for truncated assistant history and separate JSON/tool/duplicate disclosure paths, but ordinary long assistant markdown still renders inline without the requested show-more/show-less collapse; the directly matching progressive-disclosure PR closed unmerged.

## What This Changes

The issue requests collapsible or foldable long assistant responses in the Control UI chat, with per-message toggles and optional expand/collapse-all controls.

## Best Possible Solution

Have maintainers define the Control UI disclosure policy, then implement inline long-message collapse in the current chat-message renderer with focused UI tests, CSS, i18n strings, and docs if it becomes a documented user-facing behavior.

## Reproduction Assessment

Not applicable: this is a feature request for a new Control UI interaction pattern, not a broken existing contract. Source inspection confirms current main lacks inline long-message collapse for normal assistant chat bubbles.

## Solution Assessment

Unclear until maintainers choose the UX policy. Inline collapse is a plausible solution, but thresholds, default-expanded behavior, and global controls need product direction before a narrow implementation should be queued.
