## Summary

Keep open: the security hardening goal is relevant, but the patch is not merge-ready because the new Docker command stdin payload is never forwarded into the process supervisor launch path.

## What This Changes

The branch changes Docker sandbox exec construction to return Docker argv plus command stdin, updates direct/backend launch paths to keep stdin open, and rewrites focused unit tests.

## Best Possible Solution

Wire the Docker command through the typed supervisor input path, keep the stdin-based mitigation only if normal and metacharacter Docker sandbox exec cases are proven end to end, and leave unrelated sandbox/provider behavior unchanged.

Yes. Source inspection on the PR head shows `/bin/sh -l` is launched with `stdinMode: pipe-open`, but the command text is attached to `spawnSpec.stdin` and never passed to `supervisor.spawn` as `input`.

## Solution Assessment

No. The mitigation direction is plausible, but the submitted implementation bypasses the existing process-supervisor input contract; the narrow maintainable fix is to thread typed command input into the launch call and prove the Docker path end to end.
