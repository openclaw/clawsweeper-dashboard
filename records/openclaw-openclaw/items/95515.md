## Summary

Keep open: current main and v2026.6.11 still allow the doctor migration to write `groupAllowFrom` when core has no generated schema for an external channel, and the open fix candidate at https://github.com/openclaw/openclaw/pull/95540 uses closing syntax for this issue but has not merged yet.

## What This Changes

The issue requests that upgrade/doctor stop injecting `groupAllowFrom` into external email or channel plugin config that does not declare that field.

## Best Possible Solution

Review and land or explicitly reject https://github.com/openclaw/openclaw/pull/95540; the final fix should make doctor writebacks conservative for external channels without generated schema and keep regression coverage for that path.

## Reproduction Assessment

Yes for source-level reproduction: current main still treats missing generated channel schema as writable and then assigns `groupAllowFrom` into the channel/account record. This review did not rerun the full ClawMail macOS upgrade, but the issue now has repeated live user evidence plus an independent external-plugin reproduction.

## Solution Assessment

Yes, the open PR’s conservative unknown-schema guard is the narrowest maintainable fix for the reported corruption. Broader config-protection work should supersede it only if it lands the same external-channel regression behavior and coverage.
