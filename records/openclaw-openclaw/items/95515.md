## Summary

Keep open: current main and v2026.6.11 still have the permissive missing-schema doctor guard, so the upgrade-time config corruption remains possible. The open, linked fix PR is the right next review target and this issue should close only after that PR or an equivalent fix lands.

## What This Changes

The issue reports that doctor/update copies `groupAllowFrom` into external channel config that cannot validate that key, corrupting persisted config and blocking Gateway startup.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/95540, or replace it with an equivalent focused fix that makes core doctor skip `groupAllowFrom` writes when the target channel schema is unknown.

## Solution Assessment

Yes. The linked PR's conservative schema guard is the narrow maintainable fix because it preserves bundled schema-backed migrations while avoiding core doctor writes into plugin-owned config it cannot validate.
