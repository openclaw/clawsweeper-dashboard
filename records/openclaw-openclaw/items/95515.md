## Summary

Keep open: current main and the latest release still contain the permissive doctor migration path, and the open candidate fix in https://github.com/openclaw/openclaw/pull/95540 uses closing syntax for this issue but has not merged yet.

## What This Changes

The issue reports that update-time doctor repair injects `groupAllowFrom` into strict external channel config, corrupting persisted config and blocking Gateway startup.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/95540 or an equivalent schema-verified doctor guard that skips `groupAllowFrom` writes for external channels whose schema core cannot inspect.

## Reproduction Assessment

Yes for a high-confidence source-level reproduction: current main combines a permissive missing-schema guard, permissive default capabilities, and a write to `groupAllowFrom`. The reporter and a second contributor also supplied live upgrade/plugin reproductions, but this review did not rerun the full packaged macOS ClawMail upgrade.

## Solution Assessment

Yes, the linked PR's fail-closed generated-schema guard is the narrowest maintainable fix for core not knowing an external plugin schema. If maintainers want external plugins to opt into this migration later, that should be a plugin doctor/schema capability rather than an unverified core write.
