## Summary

Keep open: current main and the latest release still allow the doctor migration to write `groupAllowFrom` when bundled schema metadata is missing, matching the reported external email and RCS channel config corruption; https://github.com/openclaw/openclaw/pull/95540 is the open candidate fix and should be reviewed or landed before this issue closes.

## What This Changes

The issue reports that `openclaw update` runs doctor repair and corrupts strict external channel config by injecting `groupAllowFrom` into channel/account schemas that do not accept it.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/95540 or an equivalent conservative doctor schema guard with the external-channel regression test, then close this issue after the fix is on main or shipped.

## Reproduction Assessment

Yes. I did not execute the macOS upgrade live, but current main still has the missing-schema write path and the issue contains repeated upgrade evidence plus an independent strict external-plugin reproduction.

## Solution Assessment

Yes. The narrow best path is the open conservative guard that refuses doctor writes when core cannot verify a channel schema, rather than adding email-specific or cwd-specific special cases.
