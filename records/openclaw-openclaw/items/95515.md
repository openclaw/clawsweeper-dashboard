## Summary

Keep open: current main and latest stable v2026.6.11 still allow the missing-schema doctor write that can inject `groupAllowFrom` into strict external channel config, and https://github.com/openclaw/openclaw/pull/95540 is the active focused fix candidate.

## What This Changes

Prevent `openclaw update`/`doctor --fix` from adding `groupAllowFrom` to external email or channel plugin config when core cannot verify the plugin schema accepts that field.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/95540 or an equivalent schema-verified doctor guard, with update/doctor refusing unverifiable config writes instead of leaving users to recover by editing config manually.

## Reproduction Assessment

Yes for source-level and reporter-backed reproduction: current main still has the permissive missing-schema write path, and the issue now includes repeated email update evidence plus an independent strict-schema external RCS plugin repro. I did not run the full macOS ClawMail package upgrade locally in this read-only review.

## Solution Assessment

Yes, the active PR is the narrow maintainable fix shape: core doctor should fail closed when it cannot verify an external channel schema accepts `groupAllowFrom`. The broader protected-config PR is draft/conflicting and not a safe canonical replacement for this focused regression yet.
