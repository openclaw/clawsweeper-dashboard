## Summary

Keep open: current main and v2026.6.11 still allow the missing-schema doctor migration write that matches the reported config corruption, and https://github.com/openclaw/openclaw/pull/95540 is the open, unmerged fix candidate.

## What This Changes

The issue reports that upgrade-time `doctor --fix` corrupts external channel config by writing `groupAllowFrom` into schema-strict email or other plugin config.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/95540 or an equivalent schema-verified doctor guard, then close this issue with the release or main commit that contains the fix.

## Reproduction Assessment

Yes for source-level reproduction: current main still permits missing-schema writes, then assigns `groupAllowFrom` onto records during doctor repair. The issue and follow-up comments also include live upgrade evidence from email and a separate strict external RCS plugin, but I did not run a packaged upgrade locally in this read-only review.

## Solution Assessment

Yes, the current linked PR is the best narrow fix path: it changes the exact write guard so core does not mutate external plugin config it cannot validate. If maintainers want external channels to receive this migration, the safer alternative is an explicit plugin doctor/schema opt-in rather than permissive core writes.
