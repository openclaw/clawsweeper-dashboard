## Summary

Keep open: current main and v2026.6.11 still allow doctor to write `groupAllowFrom` when core has no bundled schema for an external channel, and https://github.com/openclaw/openclaw/pull/95540 is the open closing candidate rather than a merged fix.

## What This Changes

The issue reports that `openclaw update`/doctor corrupts external email channel config by adding `groupAllowFrom` where the plugin schema rejects it.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/95540 or an equivalent schema-known doctor write guard with regression coverage, keeping external plugin config repairs plugin-owned unless core can validate the target schema.

## Reproduction Assessment

Yes. The reporter and a second commenter provided live upgrade failures, and current source shows doctor can write `groupAllowFrom` for external channels whose schema is absent from bundled metadata; this review did not independently run the macOS ClawMail upgrade.

## Solution Assessment

Yes, the current open PR’s schema-known write guard is the narrowest maintainable core fix for the observed corruption. Broader post-write validation could be useful defense in depth, but it should not replace preventing unvalidated external-plugin writes.
