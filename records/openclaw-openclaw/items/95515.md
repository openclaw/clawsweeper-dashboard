## What This Changes

The issue reports that upgrade-time `doctor --fix` corrupts external channel config by adding an invalid `groupAllowFrom` key, blocking Gateway startup after update.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/95540 or an equivalent conservative schema guard with regression coverage, then close this issue after the fix is merged and released or clearly present on main.

## Reproduction Assessment

Yes, we have a high-confidence source reproduction path: current main permits `groupAllowFrom` writes for channels without bundled schema metadata, and the issue comments provide repeated upgrade evidence plus an independent strict external-plugin reproduction. I did not run a local upgrade because this review was read-only.

## Solution Assessment

Yes, the best known fix is the narrow conservative guard in https://github.com/openclaw/openclaw/pull/95540: core should not write plugin-owned keys when it cannot verify the target schema. That matches the repo policy and avoids adding a new config option or runtime fallback.
