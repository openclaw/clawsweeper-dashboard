## Summary

Keep open: current `main` and latest release `v2026.6.11` still allow the unknown-schema doctor migration path, while the clean linked fix at https://github.com/openclaw/openclaw/pull/95540 is open and should remain the fix candidate.

## What This Changes

The issue reports that `openclaw update` / `doctor --fix` can copy `groupAllowFrom` into external channel configs whose schemas do not allow it, corrupting config and blocking gateway startup.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/95540 or an equivalent conservative schema guard so core doctor never writes plugin-owned config keys without schema proof, then close this issue with the merge/release evidence.

## Reproduction Assessment

Yes by source inspection and issue evidence: current `main` permits writes when no bundled schema exists, and the comments include repeated real upgrade evidence plus an independent external plugin reproduction. I did not run a live upgrade locally in this read-only review.

## Solution Assessment

Yes, the linked fix direction is the narrow maintainable repair: fail closed for actual `groupAllowFrom` writes when core has no schema proof, while leaving bundled-schema migrations intact. Broader post-write validation is useful follow-up, not a prerequisite for fixing this central bug.
