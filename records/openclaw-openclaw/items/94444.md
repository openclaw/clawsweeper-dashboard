## Summary

Keep open: this addresses a real agent filesystem boundary, but it is not merge-ready because the new pass-through classifier still lets a POSIX `C:/../../outside.txt`-style path skip the guard while the write/edit sink resolves it outside the workspace. The PR also still needs non-test real behavior proof and maintainer acceptance of the default-behavior narrowing.

## What This Changes

The PR wraps default non-`workspaceOnly` host write/edit tools to reject relative workspace escapes, exports `expandPath`, wires the wrapper into tool assembly, and adds regression tests.

## Best Possible Solution

Keep the focused relative-only hardening, but make the guard use the same resolver semantics as the sink or validate the post-resolved path, add the POSIX drive-looking-path regression, then land only with real behavior proof and explicit compatibility acceptance.

## Solution Assessment

No as submitted. The wrapper is a plausible layer, but the best fix must share resolver semantics with the sink or guard after resolving before preserving absolute host-write behavior.
