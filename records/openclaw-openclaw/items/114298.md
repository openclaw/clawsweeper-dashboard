## Summary

Keep open. This PR addresses a valid cancellation gap, but the added `signal` is neither declared in the route nor accepted by the profile-context contract, and the regular CDP probe path still discards caller cancellation before reaching its network probes.

## What This Changes

Propagates a passive browser-status request’s abort signal to Chrome-MCP and CDP availability probes, with a regression expectation for the Chrome-MCP transport call.

## System Context

The bundled browser plugin serves passive status requests for configured browser profiles. A status route invokes profile-scoped HTTP and transport reachability probes, then returns readiness fields to the control client.

## Best Possible Solution

Thread `req.signal` through the typed profile-context and lease APIs into abort-capable Chrome-MCP and regular CDP probe implementations, then prove both paths stop promptly after cancellation.
