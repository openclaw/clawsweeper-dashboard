## Label Justifications

- `P1`: An incorrect orphan decision can break an active agent run by deleting its required MCP configuration before the CLI process starts.
- `merge-risk: 🚨 availability`: The new startup sidecar can make a valid queued CLI run fail when another gateway removes its pre-spawn configuration.

## Summary

The reported leak is reproducible and the real-host proof validates the ordinary spawned-process path, but the current head still has the previously identified P1 race: another live gateway can delete a queued run’s prepared configuration before its CLI child exists.

## What This Changes

Adds a cross-platform gateway-startup sidecar that removes aged bundled-MCP temporary directories unless a visible process references their configuration path.

## Best Possible Solution

Associate every directory with a verifiable gateway-generation owner and reclaim it only after both that owner and every dependent CLI process are gone, with fail-closed behavior when ownership cannot be established.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Restarting the gateway during an active bundled-MCP run deterministically leaves its temporary configuration behind, and the report includes production output from OpenClaw v2026.6.11 demonstrating the leak.

## Solution Assessment

No. Startup reclamation is an appropriate boundary, but visible child argv plus a fixed grace period is not sufficient to distinguish a true orphan from a queued run owned by another live gateway.
