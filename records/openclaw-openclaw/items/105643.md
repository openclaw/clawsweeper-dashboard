## Label Justifications

- `P1`: The current deletion rule can break an active queued CLI workflow on multi-gateway or heavily serialized hosts.
- `merge-risk: 🚨 availability`: A startup sweep can remove a configuration still needed by another live gateway, causing the later CLI spawn to fail.

## Summary

Keep this PR open, but do not merge the current head: bundled-MCP configuration is prepared before CLI queue admission, so another live gateway can delete an aged configuration belonging to a queued run that has not spawned a process yet. The live proof and tests establish orphan cleanup and protection for already-spawned children, but they do not cover this owner-without-child interval.

## What This Changes

The PR adds a cross-platform gateway-startup sweep for orphaned bundled-MCP temporary configuration directories and regression coverage for process-referenced and aged directories.

## Best Possible Solution

Give each temporary configuration explicit gateway-generation ownership and remove it only when that owner is no longer live and no surviving CLI process references the path; retain conservative handling for legacy unowned directories.

## Solution Assessment

No. Startup reclamation is appropriate, but age plus child-argv visibility is not the safest ownership test because prepared runs can wait in the queue without a child; explicit gateway ownership is the narrower reliable boundary.
