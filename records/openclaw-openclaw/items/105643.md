## Label Justifications

- `P1`: The proposed startup cleanup can break a real queued agent run by deleting its required MCP configuration before the CLI process starts.
- `merge-risk: 🚨 availability`: A live but not-yet-spawned run can lose its configuration during gateway startup and subsequently fail to launch.

## Summary

This PR remains necessary and has strong leak reproduction and live-host proof, but the unchanged head still has the prior P1 race: another gateway can delete a prepared configuration that has waited more than five minutes but whose CLI child has not spawned yet.

## What This Changes

The PR adds a cross-platform gateway-startup sweep that removes aged bundled-MCP temporary configuration directories unless a visible process references their configuration path.

## Best Possible Solution

Use a generation-owned temporary root with verifiable gateway identity, and reclaim it only after its gateway generation is confirmed dead while still preserving any configuration referenced by a surviving child; avoid persistent sidecar state or a grace period as proof of orphanhood.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source inspection: prepare a bundled-MCP run, leave it queued for more than five minutes without spawning its child, then start another gateway so the sweep sees no argv reference and deletes the directory.

## Solution Assessment

No. Startup reclamation is the right product direction, but process-argv liveness plus a fixed grace period is not sufficient ownership proof for prepared-but-not-spawned runs.
