## Summary

Keep open: the prior P1 lifecycle finding remains unresolved at the current head, because a fixed grace period plus process-argv visibility cannot prove that an aged pre-spawn config is orphaned.

## What This Changes

The PR adds a cross-platform gateway-startup sweep for orphaned bundled-MCP temporary configuration directories while retaining directories referenced by visible processes.

## Best Possible Solution

Give each temporary config generation-owned identity and reclaim it only after its owning gateway generation is proven dead and no dependent CLI process references it, with regression coverage for queued, live-child, concurrent-gateway, and true-orphan states.

## Solution Assessment

No. A startup sweep is an appropriate lifecycle boundary, but process visibility plus a fixed grace is not sufficient ownership proof; deletion must also establish that the creating gateway generation is dead.
