## Summary

This PR remains necessary: it is the open candidate fix for credential-bearing bundle-MCP temporary directories left behind when a gateway exits during a run. The latest head consolidates the Claude path onto the current shared temporary-config writer, retains legacy directories during mixed-version upgrades, and includes exact-head real-host sweep evidence; the remaining action is normal maintainer review and landing of the linked fix.

## What This Changes

The PR makes Claude bundle-MCP temporary directories owner-aware, sweeps directories whose gateway owner is demonstrably gone after gateway startup, and rolls back temporary directories when writing their configuration fails.

## System Context

CLI-backed agents render bundled MCP configuration into a temporary directory before starting or queueing a CLI run. The gateway’s post-ready sidecar later examines those directories, preserving live or legacy directories and removing only owner-encoded directories that no active process can still need.

## Architecture Diagram

  B --> C[Queued or running CLI child]

  E --> F{CLI argv or owner still live?}
  F -->|Yes| G[Keep temporary directory]

  H --> J[Expired credentials are reclaimed]

## Best Possible Solution

Land the owner-aware startup sweep and shared-writer rollback after ordinary maintainer review, keeping the legacy-directory retention policy so mixed-version gateways cannot lose queued configuration files.
