## Label Justifications

- `P1`: The underlying leak retains resolved credentials, while an incorrect sweep can break active CLI-backed agent runs during ordinary gateway restart or multi-gateway operation.
- `merge-risk: 🚨 availability`: Merging the startup sweeper with a best-effort ownership marker can remove the configuration of a live queued run and cause that run to fail when spawning.

## Summary

The exact-head Linux proof now satisfies the prior proof request, and the owner-aware design addresses the previously reported queued-run race. The PR still has one blocking availability defect: owner-marker persistence is intentionally best-effort, so a failed marker write allows a newly prepared queued configuration to re-enter the same deletion race the marker was added to prevent.

## What This Changes

The PR adds a gateway-startup, cross-platform sweep for orphaned bundled-MCP temporary configurations, with process-reference checks, gateway-owner markers, grace periods, and regression tests.

## Best Possible Solution

Make creation of a valid owner marker a required part of preparing a new bundled-MCP configuration—clean up and fail preparation if it cannot be persisted—while retaining conservative legacy-directory reclamation and the existing live-process safeguards.
