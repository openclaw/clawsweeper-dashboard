## Label Justifications

- `P1`: The PR addresses leaked credential-bearing runtime files, but its legacy fallback can break an active queued CLI run during mixed-version operation.
- `merge-risk: 🚨 compatibility`: A newly upgraded gateway can change the treatment of temporary directories created by an older concurrently running gateway.
- `merge-risk: 🚨 availability`: Deleting a queued run's configuration before child spawn can make the CLI invocation fail when it tries to use the missing file.

## Summary

The underlying leak remains reproducible on current main and the exact-head proof is strong, but merge should wait because the legacy-directory fallback can delete a queued configuration created by an older concurrent gateway before any child process references it.

## What This Changes

The PR adds a gateway-startup sweep for orphaned bundled-MCP temporary configuration directories, encodes gateway ownership in new directory names, and adds cleanup and lifecycle regression coverage.

## Best Possible Solution

Automatically reclaim only owner-encoded directories whose owner is provably dead, while routing unowned legacy directories through an explicit doctor or operator cleanup path and retaining the existing live-child, PID-reuse, and fail-closed safeguards.
