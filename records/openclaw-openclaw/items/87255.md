## Summary

Keep open: the PR fixes the fresh `OPENCLAW_HOME=/path/.openclaw` nesting path, but it is not merge-ready because released builds can already have config, credentials, sessions, plugin state, and SQLite state under `$OPENCLAW_HOME/.openclaw`, and this branch switches runtime reads to `$OPENCLAW_HOME` without doctor recovery.

## What This Changes

The PR adds an explicit `OPENCLAW_HOME` state-directory basename guard for state/config resolution, extracts state-dir name helpers, and updates resolver plus mock tests.

## Best Possible Solution

Land the basename guard together with conflict-safe doctor recovery that migrates safe `$OPENCLAW_HOME/.openclaw` layouts, reports conflicts without overwriting, and avoids runtime read-through fallback or dual writes.

## Reproduction Assessment

Yes. Current main and `v2026.6.11` still append `.openclaw` after resolving an explicit `OPENCLAW_HOME=/path/.openclaw`, which reproduces the reported nested path without a live onboarding run.

## Solution Assessment

No. The basename guard is the right fresh-install fix, but the merge-ready solution also needs doctor-owned upgrade recovery for already-written nested state rather than a runtime fallback.
