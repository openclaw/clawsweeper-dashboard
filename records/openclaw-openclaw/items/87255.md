## Summary

Keep open: the PR fixes the fresh `OPENCLAW_HOME=/path/.openclaw` resolver path, but it is not merge-ready because released builds can already have user state under the nested `$OPENCLAW_HOME/.openclaw` root and this branch switches runtime reads to `$OPENCLAW_HOME` without doctor-owned recovery.

## What This Changes

The PR adds an explicit `OPENCLAW_HOME` state-dir basename guard across state/config path resolution, extracts state-dir-name helpers, and updates regression plus mocked tests.

## Best Possible Solution

Land the basename guard together with conflict-safe doctor recovery that migrates safe `$OPENCLAW_HOME/.openclaw` layouts, reports conflicts without overwriting user state, and avoids runtime read-through fallback or dual writes.

## Reproduction Assessment

Yes. Source inspection of current main and `v2026.6.11` shows explicit `OPENCLAW_HOME=/path/.openclaw` still flows through helpers that append another `.openclaw`, matching the linked report without a live onboarding run.

## Solution Assessment

No. The basename guard is the right fresh-install fix, but the merge-ready solution also needs doctor-owned upgrade recovery for already-written nested state rather than a runtime fallback.
