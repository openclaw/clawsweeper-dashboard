## Summary

Current main has a concrete credential-disclosure path in model-status JSON, with no duplicate or linked fix. Keep this issue open and route the repair through the private security process.

## What This Changes

Prevent `openclaw models status --agent <id> --json` from exposing raw authentication credentials in diagnostic output.

## Best Possible Solution

Privately replace secret-bearing auth objects with an explicitly metadata-only status DTO, add whole-payload assertions proving API-key, token, and OAuth sentinel values are absent, validate the affected beta upgrade path, and ship through the security process.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level: make a synthetic-auth provider return a sentinel credential, run model status in JSON mode, and inspect `auth.providers[*].syntheticAuth`; current main preserves the sentinel. A live run with real credentials is neither necessary nor appropriate for review.

## Solution Assessment

The requested redaction goal is correct, but broad key-name filtering should not be the primary fix. An allowlisted metadata-only DTO structurally prevents current and future provider credentials from entering diagnostic output.
