## Review Findings

Overall correctness: patch is incorrect

Full review comments:

- **[P1] Export the collectors through the loaded facade:** `src/security/audit.ts:1412-1420`
  - body: `runSecurityAudit` gets `auditNonDeep` from `audit.nondeep.runtime.js`, but this PR only added the two new exports to `audit-extra.async.ts`. The exact-head type/lint checks already report TS2339 here, and at runtime the audit path would not find either collector. Export these collectors from the facade that `loadAuditNonDeepModule()` actually loads, or load the module that contains them.
  - confidence: 0.98
- **[P2] Respect inactive Gateway auth modes before warning:** `src/secrets/secretref-env-fallback-diagnostics.ts:45-50`
  - body: This helper emits a fallback diagnostic whenever `gateway.auth.token` is a SecretRef and `OPENCLAW_GATEWAY_TOKEN` exists, but `resolveGatewayAuthToken` does not check whether token auth is active. Current doctor/credential planning skips the token surface for `password`, `none`, and `trusted-proxy` modes, so this can claim runtime is using an env fallback for an inactive SecretRef. Reuse the active-surface logic before emitting the warning.
  - confidence: 0.91
- **[P3] Document the new audit check IDs:** `src/security/audit-plugin-load-paths.ts:200-211`
  - body: The PR emits new `plugins.load_paths.*` and `secrets.ref_env_fallback_used` checkIds, while the public audit-checks page is documented as the reference catalog for checkIds. Operators who see these new findings will not find severity or fix guidance there. Add the new IDs to the audit check catalog as part of the behavior change.
  - confidence: 0.88
