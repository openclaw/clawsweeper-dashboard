Keep open: the live ClawHub API and its current source both accept skill-search limits above 100, so the shared clamp would silently regress the existing CLI contract rather than merely harden an unbounded request.

## What This Changes

The PR caps shared ClawHub package and skill search limits at 100, normalizes non-integer and invalid values, and adds request-URL regression tests.

## Best Possible Solution

Keep shared ClawHub transport faithful to the upstream API; enforce any intended resource limit explicitly at the owning Gateway or CLI boundary with validation, documentation, focused tests, and live upgrade proof.
