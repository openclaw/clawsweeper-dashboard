## Summary

Keep this PR open for revision: the resource-bound goal is reasonable, but the current head silently narrows the native CLI contract without maintainer approval and mishandles fractional values below one.

## What This Changes

Adds a 100-result cap and numeric normalization to ClawHub skill searches at the lifecycle caller, while adding tests that preserve verbatim forwarding in the shared transport helpers.

## Best Possible Solution

Keep the Gateway's existing 100-result schema maximum while preserving the native CLI's current range; if maintainers intentionally want a CLI maximum, reject values above 100 visibly in argument parsing, document the contract, and prove the real command against ClawHub.
