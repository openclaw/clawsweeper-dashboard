## Summary

Keep open: current main still has no outbound delivery-queue TTL/expiry policy, no accepted `messages.delivery.*` config surface, and the related implementation attempts are closed unmerged rather than canonical fixes.

## What This Changes

Request adds an opt-in TTL/expiry policy for outbound delivery queue messages to prevent stale queued messages replaying after gateway restart.

## Best Possible Solution

Keep this issue open as the canonical thread, then land a narrow backward-compatible outbound expiry policy across startup recovery and reconnect drain once the config/default/action semantics are chosen.

## Reproduction Assessment

Yes, at source level: seed an old pending outbound entry with `retryCount: 0` and no `lastAttemptAt`, then call `recoverPendingDeliveries`; current main checks max retries/backoff but not queued age.

## Solution Assessment

Unclear until maintainer policy is chosen. The maintainable direction is a narrow expiry policy that covers startup recovery and reconnect drain while preserving backward-compatible config/default semantics.
