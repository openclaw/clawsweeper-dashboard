## Summary

Keep open: current main and the latest release still lack an outbound delivery-queue age/expiry policy, the strict messages config still has no `messages.delivery.*` surface, and the related implementation attempts are closed unmerged rather than canonical fixes.

## What This Changes

The issue requests configurable expiry for persisted outbound delivery queue messages so stale queued entries are not replayed after gateway restarts.

## Best Possible Solution

Keep this as the canonical product/implementation issue, decide the TTL config/default/expire-action policy, then land a narrow current-main outbound expiry change that covers startup recovery and reconnect drain with config schema, docs, and focused tests.

## Reproduction Assessment

Yes, at source level. Seed an old pending outbound entry with `retryCount: 0` and no `lastAttemptAt`, then call `recoverPendingDeliveries`; current main treats it as eligible unless max retries or backoff block it, with no age gate.

## Solution Assessment

Unclear until maintainer policy is chosen. The maintainable fix is a narrow current-main expiry policy that preserves active-claim/re-read behavior and aligns strict config/default semantics with compatibility guidance.
