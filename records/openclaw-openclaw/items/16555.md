## Summary

Keep open: current main still replays pending outbound delivery entries by retry/backoff state without a queued-age expiry policy, the strict messages config still lacks a supported delivery TTL surface, and the related implementation PRs were closed unmerged rather than landing a canonical fix.

## What This Changes

The issue requests configurable TTL/expiry behavior for outbound delivery queue messages to prevent stale restart or reconnect replay.

## Best Possible Solution

Keep this as the canonical issue, decide the TTL key/default/expiry action, then land a narrow current-main outbound expiry policy covering startup recovery and reconnect drain with schema, docs, and focused tests.

## Reproduction Assessment

Yes, at source level: seed an old pending outbound delivery entry with retryCount 0 and no lastAttemptAt, then run recovery; current main treats it as eligible unless max retries or backoff block it, with no age gate.

## Solution Assessment

Unclear until maintainers choose the product policy; the maintainable fix is a narrow outbound expiry policy that preserves current active-claim/re-read safeguards and aligns strict config/default semantics with compatibility guidance.
