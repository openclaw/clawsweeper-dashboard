## Summary

Keep open: current main and v2026.6.11 still lack outbound delivery-queue TTL/expiry, and the fix needs maintainer direction on public config, default behavior, and expired-entry handling.

## What This Changes

Request to add configurable TTL/expiry for outbound delivery queue messages so stale queued replies are not replayed after gateway restart.

## Best Possible Solution

Keep this as the canonical outbound delivery expiry issue, then implement a narrow policy across startup recovery and reconnect drains once maintainers choose the config, default, and expired-entry semantics.

Options:
