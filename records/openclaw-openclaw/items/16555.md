## Summary

Keep open: current main and the latest release still lack an outbound delivery-queue TTL/expiry policy, and the remaining work needs a maintainer decision on public config, default behavior, and expired-entry handling.

## What This Changes

The issue requests configurable TTL/expiry for persisted outbound delivery queue messages so stale entries are not replayed on gateway restart.

## Best Possible Solution

Keep this as the canonical outbound delivery expiry issue, then implement a narrow startup-recovery and reconnect-drain policy after maintainers choose the config, default, and expired-entry semantics.
