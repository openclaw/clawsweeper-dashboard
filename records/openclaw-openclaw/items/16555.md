Keep open: current main and latest release still lack an outbound delivery-queue TTL/expiry policy, and the related implementation attempts are closed unmerged rather than canonical fixes.

## What This Changes

The issue requests an opt-in TTL or expiry policy for stale outbound delivery queue messages so old queued sends are not replayed after gateway restart.

## Best Possible Solution

Keep this as the canonical policy/implementation issue, decide the TTL config/default/expire-action behavior, then land a narrow current-main outbound expiry change covering startup recovery and reconnect drain with schema, docs, and focused tests.

## Reproduction Assessment

Yes, at source level. Seed an old pending outbound entry with `retryCount: 0` and no `lastAttemptAt`, then call `recoverPendingDeliveries`; current main treats it as eligible unless max retries or backoff block it, with no age gate.

## Solution Assessment

Unclear until maintainer policy is chosen. The maintainable fix is a narrow current-main expiry policy that preserves active-claim/re-read behavior and aligns strict config/default semantics with compatibility guidance.
