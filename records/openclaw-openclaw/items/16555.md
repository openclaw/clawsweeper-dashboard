## Summary

Keep open: current main and the latest release still lack an outbound delivery-queue TTL/expiry policy, and the remaining fix needs a maintainer decision on public config, default behavior, and expired-entry handling.

## What This Changes

Request configurable TTL/expiry for outbound delivery queue recovery so stale queued messages are not replayed after gateway restarts.

## Best Possible Solution

Keep this as the canonical outbound delivery expiry issue, then implement a narrow startup-recovery and reconnect-drain policy after maintainers choose the config, default, and expired-entry semantics.
