## Summary

Keep open: current main and the latest release still lack outbound delivery-queue TTL/expiry, while comments and duplicate closures point to this issue as the canonical maintainer thread for the remaining config/default/action decision.

## What This Changes

The issue requests a configurable TTL/expiry policy for persisted outbound delivery queue messages so stale entries are not replayed after gateway restart.

## Best Possible Solution

Keep this issue as the canonical maintainer thread and land a narrow core delivery policy once maintainers choose the public config key, default TTL/no-TTL behavior, and expired-entry action.

Question: Should outbound delivery recovery add an operator-configurable TTL, and if so what default behavior and expired-entry action should be the supported public contract?

Rationale: The fix changes public config/default behavior and persisted queue semantics, and root policy treats config/default and delivery-state changes as compatibility-sensitive.

Likely owner: steipete

Owner confidence: high

Options:

- **Opt-in TTL with failed-entry retention (recommended):** Preserve current no-TTL behavior by default, add a documented `messages.delivery` TTL, and move expired entries to failed/dead-letter state with logging.
- **Bounded default TTL:** Ship a default max age for all users, accepting that upgrades may stop replaying older pending entries without operator opt-in.
- **Fold into broader lifecycle work:** Defer this issue until a larger delivery lifecycle policy owns outbound expiry, inbound freshness, and queue cleanup together.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: seed an old pending outbound delivery row with `retryCount` 0 and no `lastAttemptAt`; current recovery treats it as immediately eligible because age is never checked.

## Solution Assessment

Unclear until maintainer direction is set. The safest likely shape is an opt-in TTL with dead-letter retention and focused recovery/reconnect/config tests, but the exact config key, default, and expired-entry action are product choices.
