## Summary

Keep open: current main and the latest release still lack outbound delivery-queue TTL/expiry, duplicate reports route back here, and the remaining fix needs a maintainer choice on public config, default behavior, and expired-entry handling.

## What This Changes

The issue requests configurable expiry for stale outbound delivery queue messages so gateway restart recovery does not replay old queued messages.

## Best Possible Solution

Keep this as the canonical outbound delivery expiry issue, then implement a bounded startup-recovery and reconnect-drain policy after maintainers choose the config, default, and expired-entry semantics.

Options:

- **Finite Default TTL:** Ship a default max age to prevent stale floods without operator setup, accepting a compatibility-sensitive change to existing recovery behavior.
- **Broader Freshness Design:** Pause the outbound-only fix and design outbound plus inbound message freshness together, reducing policy drift but delaying the known outbound repair.

Unclear until maintainers choose the public config/default/action. The narrow maintainable path is outbound expiry in recovery and reconnect drains; bundling inbound freshness would be a broader product decision.
