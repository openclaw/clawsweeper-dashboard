## Summary

Keep open: current main and the latest release still lack an outbound delivery-queue TTL/expiry policy, while the related implementation PRs are closed unmerged and the remaining config/default behavior still needs maintainer direction.

## What This Changes

The issue requests configurable expiry for stale outbound delivery queue entries so old pending messages are not replayed to channels after gateway restart or reconnect.

## Best Possible Solution

Keep this as the canonical outbound expiry policy issue, decide the default/config semantics, then land a narrow current-main change covering startup recovery, reconnect drain, strict config/schema/docs, and focused tests.

## Reproduction Assessment

Yes, at source level. Seed an old pending outbound delivery with `retryCount: 0` and no `lastAttemptAt`, then call `recoverPendingDeliveries`; current main treats it as eligible unless retry/backoff blocks it, with no queued-age cutoff.

## Solution Assessment

Unclear until maintainer policy is chosen. The maintainable solution is a narrow outbound expiry policy that preserves recent crash recovery and aligns strict config/default semantics with compatibility guidance.
