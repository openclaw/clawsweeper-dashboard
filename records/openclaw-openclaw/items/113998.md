## Summary

This PR addresses a real secret-routing weakness, but it intentionally changes existing deployments from authenticated cron webhook delivery to unauthenticated delivery until an operator adds a new allowlist. The Doctor advisory and runtime warning make the change diagnosable, yet they do not preserve authentication for operators who do not run Doctor; a security owner needs to explicitly choose that fail-closed upgrade policy before merge.

## What This Changes

The PR adds `cron.webhookTokenHosts` and attaches a cron webhook bearer token only when the job-supplied webhook hostname is on that operator-configured allowlist.

## System Context

Cron jobs store webhook destinations that can be created or edited through OpenClaw's cron workflow. When a cron run finishes or fails, the Gateway sends the result to that destination; this change decides whether the operator's bearer credential may accompany the outbound request.

## Best Possible Solution

Approve a clearly documented fail-closed security rollout only if the security owner accepts temporary authentication loss for unconfigured existing installations; otherwise retain existing attachment by default and introduce an explicit strict mode after a separately approved compatibility design.
