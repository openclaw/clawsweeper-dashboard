- `merge-risk: 🚨 compatibility`: The empty allowlist becomes fail-closed for stored job destinations that previously received the configured bearer token.

## Summary

This PR has strong real-behavior evidence and closes the direct token-exfiltration path for new or edited job destinations, but it still deliberately changes existing stored cron webhook destinations from authenticated to unauthenticated unless an operator adds configuration. That is a P1 upgrade and security-policy decision, not a mechanical contributor follow-up; the PR should stay open for an explicit owner decision. A smaller documentation correction is also needed because the Control UI page omits the config-declared failure-alert exception.

## What This Changes

The PR adds `cron.webhookTokenHosts`, validates and normalizes its host entries, and makes Gateway cron webhook delivery attach `cron.webhookToken` only to approved hosts while warning and advising operators about uncovered stored destinations.

## System Context

Cron jobs store webhook destinations that the cron tool can create or edit, then Gateway sends completion and failure notifications to those destinations. This PR adds an operator-owned host decision before Gateway includes the configured bearer credential, while Doctor reports stored webhook hosts that would no longer receive it.
