## Summary

Keep open: current main still has the cron scheduler gap described here. Disabling an in-flight job clears the persisted reservation, re-enabling can restore a past-due one-shot timestamp, and due-job selection still does not consult the in-process active-job registry.

## What This Changes

The issue requests a cron scheduler fix so disabling and re-enabling an in-flight job cannot cause a second concurrent run of the same job.

## Best Possible Solution

Land one focused cron scheduler fix that prevents runnable selection from dispatching a job already active in this process, plus a regression for the manual force-run, disable, re-enable, then timer-tick sequence.
