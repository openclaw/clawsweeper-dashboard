## What This Changes

The PR routes default Telegram Markdown sends through the render-aware chunker and adds regression coverage for preserving word boundaries when rendered HTML exceeds Telegram's message limit.

## Best Possible Solution

Default Telegram Markdown sends should share the existing render-aware Markdown IR chunking path, while explicitly authored HTML continues using the HTML-safe splitter and both paths retain parse-error plain-text fallback behavior.

## Solution Assessment

Yes; reusing the existing render-aware Telegram Markdown chunker is the narrowest maintainable fix and avoids changing the separate contract for caller-authored HTML.
