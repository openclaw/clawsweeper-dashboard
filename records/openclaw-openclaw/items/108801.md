## Summary

The render-aware chunking direction matches the linked bug, but the corrected head still lacks real Telegram proof and introduces a parse-fallback regression that can omit Markdown link destinations.

## What This Changes

The PR routes default Telegram Markdown sends through render-aware source chunking, changes the shared render-aware initial split to retain separator whitespace, and updates focused Telegram and markdown-core tests.

## Best Possible Solution

Keep render-aware Markdown chunking, derive each plain retry from the rendered chunk with the existing HTML-to-plain fallback so link targets survive, add a focused fallback regression, and capture redacted live Telegram boundary proof before merge.
