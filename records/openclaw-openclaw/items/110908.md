## Summary

Keep this PR open. The updated documentation makes `lookup-self` an explicit operator requirement, but the implementation still changes existing valid no-default-policy tokens from ref-scoped ACL handling to a provider-wide outage whenever every requested read and introspection return 403; that compatibility direction needs maintainer approval or a backward-compatible fallback. The stated live proof is not yet inspectable as a redacted runtime artifact.

## What This Changes

The PR classifies shared Vault authentication failures as provider-scoped, aggregates affected-owner Gateway diagnostics, and documents Vault self-token lookup access for no-default-policy tokens.

## Best Possible Solution

Preserve ref-scoped handling when `lookup-self` is denied because that result is inconclusive, while retaining provider-wide aggregation when the resolver can establish a shared outage; then add redacted live Gateway evidence for both branches.
