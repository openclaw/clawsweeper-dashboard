## Summary

This PR forwards an owner-qualified identity, but the documented and reproduced ClawHub bulk endpoint still resolves only bare slug/version pairs, so the observable `skill_not_found` bug remains. The same blocker from the previous review is unresolved on the unchanged head.

## What This Changes

The branch preserves an installed skill's optional `ownerHandle` and adds it to ClawHub bulk security-verdict request items.

## Best Possible Solution

Make the ClawHub bulk endpoint explicitly accept and resolve `ownerHandle`, cover ambiguous slugs in its contract tests, then land the OpenClaw forwarding change with a live gateway round trip; retain the original bulk-only design unless maintainers explicitly approve a per-skill fallback.
