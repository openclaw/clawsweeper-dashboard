  - body: Current main already routes `openclaw migrate` through plugin-registered migration providers, with Hermes owned by `extensions/migrate-hermes`. Adding a parallel core `src/migrations` stack would create competing CLI/docs/safety behavior and maintenance drift.

  - body: This guard only refuses missing `--yes` when stdout is a TTY, so CI, scripts, and piped runs can apply file/config/env migrations without explicit confirmation. Non-dry-run apply should require `--yes` or a real interactive prompt regardless of stdout.
  - confidence: 0.94
- **[P1] Reject unsafe config keys before merging patches:** `src/migrations/config-merge.ts:15-29`
  - body: Hermes YAML-derived provider IDs and MCP names can become object/path keys, but this merge creates plain objects and assigns arbitrary keys. Keys like `__proto__`, `constructor`, or `prototype` need rejection or null-prototype handling before untrusted config is merged.
  - confidence: 0.91
- **[P1] Redact migration reports structurally:** `src/migrations/report.ts:13-15`
  - body: The JSON-string regex redaction misses secret-looking nested keys outside `writeEnv`, and report rows later write reasons verbatim. Migration output should use key-aware recursive redaction for action values, details, reasons, and markdown/JSON reports.
  - confidence: 0.88
- **[P1] Constrain migration archive targets before writing:** `src/migrations/apply.ts:221-229`
  - body: `archiveOnly` joins a plan-controlled archive path to the report directory and then copies with `stat`/`cp` without rejecting traversal, absolute paths, or symlink races. Resolve archive targets under the report root and use symlink-safe copy semantics.
  - confidence: 0.89
- **[P1] Do not import executable MCP servers as live config:** `src/migrations/providers/hermes.ts:547-550`
  - body: This directly merges Hermes MCP server definitions, including stdio command fields, into live OpenClaw config. Imported executable MCP entries should be skipped, quarantined, or explicitly approved before they can be run later.
