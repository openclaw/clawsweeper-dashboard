Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Require explicit approval outside TTYs:** `src/cli/program/register.migrate.ts:129-133`
  - body: This guard only refuses apply without `--yes` when stdout is a TTY, so `openclaw migrate apply` can mutate config, `.env`, and files from CI, cron, or piped scripts without an explicit confirmation flag. Require `--yes` for every non-dry-run non-interactive apply, or actually prompt on stdin before applying.
  - confidence: 0.93
- **[P1] Quarantine executable MCP imports:** `src/migrations/providers/hermes.ts:330-343`
  - body: The importer copies Hermes `command`, `args`, `env`, and `cwd` into live `mcp.servers`, which turns an imported config file into a future local process execution path when OpenClaw connects to that MCP server. Stdio MCP entries from an external home should be manual-review or disabled/quarantined until the operator explicitly trusts each command.
  - confidence: 0.9
- **[P1] Reject unsafe config keys before merging:** `src/migrations/config-merge.ts:27-30`
  - body: Hermes provider IDs, MCP server names, and nested config keys flow into this merge helper and are assigned into plain objects without blocking `__proto__`, `constructor`, or `prototype`. Validate path segments and object keys, or use null-prototype merge targets, before merging untrusted migration config into OpenClaw config objects.
  - confidence: 0.87
- **[P2] Use structural redaction for migration reports:** `src/migrations/report.ts:13-16`
  - body: Redacting `mergeConfig` by stringifying the whole action and applying token regexes misses many key-named secrets, and the Markdown report writes reasons directly. Walk objects by key name and redact report fields before writing `plan.json` or `report.md` so imported tokens, headers, cookies, or credentials are not persisted in support artifacts.
  - confidence: 0.82
