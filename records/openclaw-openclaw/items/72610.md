Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Remove the hard-coded core migration registry:** `src/migrations/registry.ts:1-4`
  - body: Current main resolves migration providers through the plugin registry and already has `extensions/migrate-hermes` declaring the `hermes` provider. Adding this separate core registry would create a competing source of truth and bypass the plugin-owned fixes and contracts that now own migration providers.
  - confidence: 0.92
- **[P1] Require confirmation for noninteractive apply:** `src/cli/program/register.migrate.ts:129`
  - body: This guard only refuses an apply without `--yes` when stdout is a TTY, so scripts and CI with non-TTY stdout can apply a migration without explicit confirmation. Non-dry-run apply should require `--yes` unless an actual interactive prompt has accepted the plan.
  - confidence: 0.95
- **[P1] Do not import executable MCP commands directly:** `src/migrations/providers/hermes.ts:546-551`
  - body: The provider copies Hermes MCP server fields into `mcp.servers`, including command-execution fields collected earlier from YAML. A migration source can therefore persist a stdio MCP command that OpenClaw may later execute, so executable entries need manual/quarantined review instead of direct config merge.
  - confidence: 0.9
- **[P1] Redact migration reports structurally:** `src/migrations/report.ts:13-15`
  - body: Redacting a serialized `mergeConfig` action with token regexes misses nested secret-looking keys and leaves other action/result text such as report reasons unredacted. The report writer can persist imported credentials or headers in `plan.json` or `report.md`, so redaction needs to walk all action/result fields by key and value pattern.
  - confidence: 0.88
- **[P1] Confine migration file copies:** `src/migrations/apply.ts:50-60`
  - body: The apply path copies plan-provided sources to plan-provided targets with `fs.copyFile`/`fs.cp` and no base-directory or symlink checks. A malicious or compromised source tree can copy linked files or escape expected target/report directories, so file and archive writes need path confinement and symlink-safe copying.
  - confidence: 0.86
- **[P1] Reject prototype-polluting config keys:** `src/migrations/config-merge.ts:28-29`
  - body: The merge helper assigns untrusted imported config keys into ordinary objects without rejecting `__proto__`, `constructor`, or `prototype`. Hermes provider IDs, skill names, and MCP server names can become config keys, so the merge path should validate keys or use null-prototype objects before writing config.
  - confidence: 0.84
