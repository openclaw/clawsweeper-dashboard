## Summary

Keep open. Current main has partial route-preservation work, but it still intentionally suppresses implicit external-origin routing for internal WebChat/dashboard turns unless an explicit delivery route is set, and the requested force-origin/fallback policy remains a product and security decision.

## What This Changes

The issue requests guaranteed delivery of final agent replies back to the originating messaging channel, with an optional fallback channel when origin metadata is unclear.

## Best Possible Solution

Define a safe turn-origin delivery invariant that preserves the captured route through dispatch, queue, tool, subagent, and dashboard handoff paths; add fallback or mirroring only as an explicit security-reviewed policy with focused tests and live channel proof.

## Reproduction Assessment

Yes, source-reproducible: current routing code and tests show internal WebChat/dashboard turns with an external origin do not route externally unless ExplicitDeliverRoute is set. I did not run a live transport reproduction in this read-only review.

## Solution Assessment

No, the requested unconditional force/fallback config is not clearly the best fix by itself. The safer solution is a sticky turn-origin invariant plus maintainer-approved fallback or mirroring policy with security coverage.
