## Summary

Keep open: current main preserves some external route state, but it still intentionally gates internal/webchat/UI-originated replies and does not provide the requested force-origin or fallback-channel policy, so the central cross-surface delivery problem remains.

## What This Changes

Request to force normal agent replies back to the originating Telegram, Discord, WhatsApp, or similar channel, with optional fallback delivery when the primary route is unavailable.

## Best Possible Solution

Define a security-reviewed turn-origin delivery contract that captures the original routable channel, target, account, and thread at turn start, preserves it through internal surfaces, and adds any mirroring or fallback behavior only as explicit policy.

## Reproduction Assessment

Yes at source level: current main still contains route gates and tests that intentionally prevent some UI/webchat contexts from inheriting external delivery routes; no live Telegram or Discord run was performed.

## Solution Assessment

Unclear as proposed: forcing all replies or adding broad fallback config is not automatically the safest fix, so maintainers should first settle the turn-origin delivery invariant and cross-channel security policy.
