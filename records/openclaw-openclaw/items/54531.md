## Summary

Keep open. Current main has partial route-preservation work, but it still intentionally blocks internal WebChat/dashboard turns from routing to an external origin unless explicit delivery is set, has no force-origin/fallback config, and the remaining behavior needs a product and security decision rather than stale cleanup.

## What This Changes

Requests an origin-channel delivery policy/config so generated agent replies are always delivered back to the originating messaging channel, with fallback behavior when the origin is unclear.

## Best Possible Solution

Define one origin-delivery contract that captures the trusted inbound route, route freshness, authorization, duplicate suppression, fallback behavior, and failure reporting, then implement the chosen policy with schema/docs and channel proof.

## Reproduction Assessment

Yes, at source level. Current main still has an internal-WebChat/no-explicit-delivery gate and tests that preserve the no-implicit-external behavior, but I did not run a live channel reproduction.

## Solution Assessment

Unclear as proposed. A force/fallback config is plausible, but the best fix must first define the product and security policy for trusted origin routes, stale routes, and cross-surface delivery.
