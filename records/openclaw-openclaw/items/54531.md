## Summary

Keep open: current main has useful route-preservation pieces, but it still has internal-WebChat and same-surface gates, the requested force-origin/fallback policy is absent, and the issue discussion plus related open reports show the delivery-loss class remains active.

## What This Changes

The issue requests reliable delivery of agent replies back to the originating Telegram, Discord, WhatsApp, or similar channel, with proposed force-origin and fallback-channel configuration.

## Best Possible Solution

Define a safe turn-origin delivery invariant that preserves the captured channel, target, account, and thread through agent/tool/queued follow-up paths, and add fallback or mirroring only as an explicit security-reviewed policy.

## Reproduction Assessment

Yes, source-level: current routing still suppresses origin routing for internal WebChat turns and same-surface origins, and the issue discussion plus #90214 show matching channel-delivery symptoms; no live channel repro was run in this read-only review.

## Solution Assessment

No, the proposed unconditional force/fallback config is not clearly the best fix; the safer fix is durable turn-origin routing with any fallback or mirroring added only after product and security review.
