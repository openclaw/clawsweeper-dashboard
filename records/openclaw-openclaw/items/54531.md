## Summary

Keep open. Current main has partial route-preservation work, but it still intentionally blocks implicit internal WebChat/dashboard and same-surface origin routing, the requested force/fallback policy is not implemented, and newer reports show related delivery loss remains active.

## What This Changes

The issue requests reliable delivery of generated agent replies back to the originating messaging channel, with a proposed force-origin/fallback routing configuration.

## Best Possible Solution

Define a security-reviewed turn-origin delivery invariant that preserves the captured channel/target through agent, tool, ACP, queued follow-up, and UI paths, then add any fallback or mirroring as explicit opt-in policy with channel proof.

## Reproduction Assessment

Yes, source-reproducible. The docs promise origin-channel replies, while current code and tests still suppress implicit WebChat-to-external and same-surface origin routing; no live Telegram/Discord/WhatsApp run was performed in this read-only review.

## Solution Assessment

No, the proposed unconditional force/fallback config is not clearly the best fix. The safer direction is a durable turn-origin route plus explicit security-reviewed fallback or mirroring semantics.
