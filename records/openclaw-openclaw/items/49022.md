## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Import the current pi-tui package:** `src/tui/components/inline-image.ts:7`
  - body: This new helper imports `@mariozechner/pi-tui`, but current manifests only depend on `@earendil-works/pi-tui` and npm has no `@mariozechner/pi-tui@0.78.0`, so the added file will fail module resolution after merge. Use the current package name for `Image`, `getCapabilities`, and `getImageDimensions`.
  - confidence: 0.95
- **[P1] Constrain MEDIA reads to trusted media roots:** `src/tui/components/tool-execution.ts:97`
  - body: The TUI parses `MEDIA:` directives from tool-result text and reads any absolute image path on the host when image rendering is available. Tool/model-controlled output should not be able to trigger arbitrary host file reads; render from trusted media records or an allowed media root instead.
  - confidence: 0.82
- **[P2] Make rendered-image dedupe reversible:** `src/tui/components/tool-execution.ts:96`
  - body: The shared `globalRendered` set is append-only, so after a retry, partial update, or pruned component detaches cached images, later results with the same path or fingerprint skip rendering and can show only the `MEDIA:` text or no image. Scope dedupe to the processed result or remove keys when cached images are detached/pruned.
  - confidence: 0.9
- **[P2] Only strip media lines that render as images:** `src/tui/components/tool-execution.ts:86-88`
  - body: `splitMediaFromOutput` extracts all valid `MEDIA:` directives, not just image paths. When one image renders, `cachedTextStripped` drops every extracted media line, so mixed outputs such as audio/video/file MEDIA references can disappear from the TUI; strip only directives that were actually rendered as inline images.
  - confidence: 0.77
