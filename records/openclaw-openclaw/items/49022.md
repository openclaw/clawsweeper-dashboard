## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.87

Full review comments:

- **[P1] Constrain MEDIA reads to trusted media roots:** `src/tui/components/inline-image.ts:44-69`
  - body: `readMediaImageAsBase64` accepts any absolute path parsed from tool output and reads it in the host TUI process. In Docker or remote-gateway setups, a tool/model line such as `MEDIA:/Users/me/Pictures/private.png` can make the TUI render a host-local file that was never an OpenClaw media artifact, so this needs media-store/local-root validation or a base64-only trusted path before merge.
  - confidence: 0.78
- **[P2] Make image dedupe ownership reversible:** `src/tui/components/tool-execution.ts:123-125`
  - body: The shared `globalRendered` set is append-only, but cached image components can be detached by retries, partial results, clearTools, or ChatLog pruning. Once a fingerprint or path is recorded, a later valid result for the same image is skipped even though the earlier component may no longer be visible, so supported terminals can lose the inline image.
  - confidence: 0.88
- **[P2] Strip only MEDIA lines that rendered as images:** `src/tui/components/tool-execution.ts:86-88`
  - body: `splitMediaFromOutput` removes every valid MEDIA directive from the text, and `textStripped` is used whenever at least one image renders. A mixed result containing an image plus audio/video/document MEDIA line would hide the non-image attachment text on image-capable terminals, despite the PR's stated fallback and scope boundary.
  - confidence: 0.76
