## Summary

Keep open. The report gives a concrete, high-impact subagent failure shape, but it has not yet been reproduced on current main or separated from the custom Perplexity provider bridge; current source still advertises real `write` and `exec` tools to subagents, so an empty-argument tool call is not an expected successful outcome.

## What This Changes

Fix a suspected regression where a spawned subagent’s provider tool call is recorded with empty arguments, so host-side tools do nothing while the model reports success.

## System Context

`sessions_spawn` creates an isolated child agent run with a selected model and normal tool set. The provider response is normalized into tool calls, whose decoded arguments are passed to host tools such as `write` and `exec`, then their results return to the child session and its parent.

  F --> G[Completion to parent]

## Best Possible Solution

Capture one failing and one passing subagent run at the provider-normalization boundary, then reject malformed required-argument calls with a structured tool error that the child model can see and retry; keep valid no-argument tools working unchanged.
