## Label Justifications

- `P2`: Windows is delivered and Linux has a usable MVP, but completing the remaining companion-app program is a normal-priority, multi-stage product improvement.
- `impact:security`: Desktop companions handle Gateway credentials, pairing, privileged local service control, Tauri IPC, and potentially agent-invokable device capabilities.

## Summary

Keep open: Windows is now delivered through the official Windows Hub and a Linux companion shell has landed on current main, but the Linux app still lacks important macOS-parity behavior such as remote-Gateway operation and an explicitly separated laptop-node mode. The substantive July 13, 2026 follow-up requests concrete architecture and security decisions, so the old Clawdbot name does not make the remaining platform work obsolete.

## What This Changes

Provide official Linux and Windows companion applications with capabilities approaching the macOS companion experience.

## Best Possible Solution

Retain this as the canonical cross-platform tracker, mark the Windows portion complete, and define focused Linux milestones for local companion hardening, remote operator mode, and separately opt-in node mode with explicit auth, IPC, packaging, upgrade, and real-device proof requirements.

Rationale: The next increment determines credential handoff, privileged IPC isolation, local service behavior, node capability exposure, packaging ownership, and which core CLI contract the desktop may consume; source inspection cannot choose those product and security boundaries safely.

Likely owner: steipete

Options:

- **Remote operator plus opt-in node (recommended):** Keep Control UI connectivity and laptop-node registration independent, add a canonical validated remote target/auth contract, and require two-machine security and failure-state proof.

- **Pause at local MVP:** Treat the current local-Gateway shell as the supported Linux scope and close or split remaining parity requests until app work becomes a higher priority.
