## Label Justifications

- `P2`: Windows is now covered, while the remaining Linux companion is a meaningful but non-emergency roadmap feature below current security and stability priorities.
- `impact:security`: A native companion owns sensitive gateway control, pairing, credentials, execution approvals, platform permissions, packaging, and update boundaries.
- `impact:ux-friction`: Linux users have a supported Gateway but lack the native setup, tray, chat, node, and approval experience available on Windows and macOS.

## Summary

Keep this issue open as the canonical desktop-companion roadmap. Current main and release infrastructure now cover Windows through Windows Hub, but Linux remains explicitly planned, all identified Linux implementation PRs are closed unmerged, and the remaining architecture and ownership require maintainer direction.

## What This Changes

Add official Linux and Windows companion applications with capabilities broadly comparable to the macOS companion.

## Best Possible Solution

Keep Windows Hub as the supported Windows implementation and establish a staged Linux companion program with a named owner, an approved native architecture, a minimal first milestone, and explicit install, pairing, tray, approval, lifecycle, packaging, update, and security acceptance gates.
