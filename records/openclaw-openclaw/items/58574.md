## Summary

Keep this issue open: current main and latest release still log cron timer wakeups with numeric `nextAt` only, while same-repository fix attempts are closed unmerged and the remaining linked implementation candidate is open but conflicting.

## What This Changes

The issue requests human-readable timestamp mirrors for cron `nextAt`/`nextRunAtMs` values, especially the `cron: timer armed` debug log.

## Best Possible Solution

Preserve numeric fields and add additive ISO-readable companion fields in the narrow cron timer/backoff/event logging path, preferably by refreshing the linked PR or landing an equivalent focused replacement.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: arm a cron timer with debug logging and the current payload contains numeric `nextAt` without a readable companion; no live test was run because this review is read-only.

## Solution Assessment

Yes for the requested direction. An additive readable companion is the safest shape because replacing `nextAt` would break numeric consumers, and current docs make persisted `jobs.json` the wrong place to add new runtime state.
