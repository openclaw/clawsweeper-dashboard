## Summary

Keep open: current main still lacks a targeted `/models test-fallback` command, and v2026.6.11 also lacks that command surface. The direct implementation attempts are closed unmerged, while the open configured-model health-check and staged-migration issues overlap but do not replace this fallback-chain probe request.

## What This Changes

Add a `/models test-fallback` diagnostic that intentionally skips the primary model, probes configured fallback models, and reports which fallback responded.

## Best Possible Solution

Define one canonical fallback-chain diagnostic that reuses real model/auth fallback resolution, starts at configured fallback candidates, reports which model answered, supports first-fallback and all-fallback modes, and documents how it differs from broad configured-model health checks.
