## Summary

Current main and v2026.6.11 still lack an ordered fallback-chain diagnostic. The request remains useful, but maintainers should first choose whether the canonical surface is a dedicated command or the broader per-model probe tracked at https://github.com/openclaw/openclaw/issues/63145.

## What This Changes

Add an operator command that deliberately skips the primary model and verifies the first or entire configured fallback chain with live requests.

## Best Possible Solution

Provide one canonical runtime-backed diagnostic that resolves the effective agent fallback order, can start after the primary, tests either the first fallback or every fallback without allowing later candidates to mask a failure, and clearly distinguishes chain validation from auth-only probing.
