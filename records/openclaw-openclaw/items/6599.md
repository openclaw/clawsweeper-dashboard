Keep open: current main and v2026.6.11 still lack a targeted fallback-chain test command, and the remaining choice is the product surface for live model/fallback diagnostics rather than conservative cleanup.

## What This Changes

The issue requests a `/models test-fallback` command that intentionally skips the primary model and probes configured fallback candidates before a real provider failure occurs.

## Best Possible Solution

Ship one canonical fallback validation surface that reuses real model/auth fallback resolution, can intentionally begin at configured fallback candidates, reports which model answered, and documents how it differs from auth-profile probes and broad per-model health checks.
