## Summary

Keep open: current main and the latest release still lack a targeted fallback-chain test command, and the remaining decision is which model diagnostics UX OpenClaw should support rather than conservative cleanup.

## What This Changes

The issue requests a `/models test-fallback` command, with an optional all-fallback mode, to proactively verify configured fallback models and auth before a real provider failure.

## Best Possible Solution

Choose one canonical fallback diagnostics surface that reuses real model/auth fallback resolution, can intentionally start at configured fallback candidates, reports the responding model, and documents how it differs from auth-profile probes and broad per-model health checks.
