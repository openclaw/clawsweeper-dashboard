## Summary

Keep open: current main still lacks a targeted fallback-chain test command, the direct implementation PRs are closed unmerged, and related model-health issues do not replace this primary-skipping fallback probe.

## What This Changes

Request to add a `/models test-fallback` command that proactively verifies configured model fallback chains by skipping the primary model and probing fallback candidates.

## Best Possible Solution

Define one canonical fallback-chain probe that reuses real model/auth fallback resolution, starts at configured fallback candidates, reports the responding model, and documents how it differs from broad model-health probes.

## Reproduction Assessment

Yes, at source level. Current main has no `models test-fallback` CLI command or `/models test-fallback` slash action, and the existing live probe path tests auth/profile reachability rather than intentionally starting at configured fallbacks.

## Solution Assessment

Unclear as an exact product shape. A targeted fallback-chain probe is plausible, but maintainers should reconcile it with broader configured-model health checks and staged model-migration UX before implementation.
