## Summary

Keep open: current main and the latest release still lack the targeted fallback-chain test command, and the remaining decision is product scope because this overlaps auth probes, broader per-model health checks, and staged model-migration UX.

## What This Changes

The issue asks for a `/models test-fallback` command that intentionally skips the primary model and probes configured fallback models, with an optional full-chain mode.

## Best Possible Solution

Ship one canonical fallback validation surface that reuses real model/auth fallback resolution, can intentionally begin at configured fallback candidates, reports which model answered, and documents how it differs from auth probes and broad per-model health checks.
