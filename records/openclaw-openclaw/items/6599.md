Add a `/models test-fallback` style diagnostic that intentionally skips the primary model and probes configured fallback models.

## Best Possible Solution

Define one canonical fallback-chain diagnostic that reuses OpenClaw's real model/auth fallback resolution path, starts from configured fallback candidates, reports which model answered, supports first-fallback and all-fallback modes, and documents how it differs from broad configured-model health checks.
