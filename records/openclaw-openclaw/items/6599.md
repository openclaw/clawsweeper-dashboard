## Summary

Current main and v2026.6.11 still lack an ordered fallback-chain test: the existing live status probe checks provider authentication, while `/models` remains a listing and picker surface. The request remains useful and has explicit maintainer-side engagement, but implementation should wait for a product decision on whether this belongs in the existing status probe or a distinct command.

## What This Changes

Add a model command that deliberately skips the primary model and sends live requests to the first or all configured fallback candidates.

## Best Possible Solution

Extend one canonical runtime-backed model diagnostic with an ordered fallback-chain scope that reuses actual candidate resolution, supports first-candidate and all-candidate modes without allowing later fallbacks to mask failures, and clearly reports selected model, latency, request cost implications, authentication errors, and timeouts.
