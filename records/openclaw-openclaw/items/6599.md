## Summary

Keep open: current main and the latest release still do not provide a targeted fallback-chain test command, and the closest existing probes validate provider/auth reachability rather than intentionally starting at configured fallback candidates.

## What This Changes

The issue requests a `/models test-fallback` command that proactively verifies configured model fallback chains without waiting for a real provider failure.

## Best Possible Solution

Define one maintainer-approved diagnostic path that reuses the real fallback/auth resolution path, can intentionally start at configured fallback candidates, reports which model answered, and documents how it differs from `models status --probe` and broader per-model health checks.

## Reproduction Assessment

Yes for the source gap: current main exposes CLI status/list/fallback management and slash provider/list handling, but no path that intentionally skips the primary and probes fallback candidates. This is a feature absence rather than a failing existing behavior repro.

## Solution Assessment

Unclear: a dedicated command is plausible, but it is not yet clearly the best permanent UX until maintainers decide how it should relate to broader `models status --probe --all` health checks and live-provider cost/redaction policy.
