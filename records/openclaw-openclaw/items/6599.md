## Summary

Keep open. Current main and v2026.7.1 still lack the requested ordered fallback diagnostic, but the exact public surface overlaps with the broader per-model probe tracked by https://github.com/openclaw/openclaw/issues/63145 and its open implementation PR; maintainers should choose one canonical interface before implementation. A prior repository contributor review also explicitly distinguished the two requests and kept this issue open.

## What This Changes

Add a command that proactively tests the configured model fallback chain, optionally checking either the first fallback or every fallback.

## Best Possible Solution

Use one runtime-backed probe engine that resolves the active agent's canonical ordered candidates, supports first-fallback and all-candidate scopes, reports the exact responding model with redacted errors, and powers the existing CLI probe surface; expose a /models wrapper only if maintainers confirm in-chat diagnostics are a supported product surface.
