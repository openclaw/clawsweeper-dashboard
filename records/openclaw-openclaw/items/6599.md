## Summary

Keep open. The supplied latest review found no command that deliberately starts at configured fallbacks, and the directly related implementation PR at https://github.com/openclaw/openclaw/pull/43342 was closed unmerged. The open per-model probe proposal at https://github.com/openclaw/openclaw/issues/63145 overlaps, but it does not yet establish the ordered fallback-chain semantics requested here; a maintainer should select one diagnostics contract before new implementation work starts.

## What This Changes

Add a model diagnostic that intentionally bypasses the primary model and verifies the configured fallback chain, optionally testing every fallback candidate.

## System Context

OpenClaw resolves an agent's configured primary and fallback models when a model run fails. Its model CLI and `/models` surfaces expose configuration and status information to operators, so a fallback diagnostic would need to translate the same runtime selection policy into an explicit, safe probe result.

## Architecture Diagram

flowchart LR
  A[Agent model configuration] --> B[Primary and fallback selection]
  B --> C[Model diagnostics command]
  C --> D[Fallback candidate probe]
  D --> E[Provider authentication and model runtime]
  E --> F[Operator result]
  F --> G[Configuration repair or confidence]

## Best Possible Solution

Choose one canonical operator-facing diagnostic contract, preferably an explicit fallback-chain mode on the existing model status/probe surface that reuses the real resolver while making probe cost, ordering, and partial-failure reporting clear.
