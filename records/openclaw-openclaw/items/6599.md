## Summary

Keep open: current main and the latest release still lack a dedicated fallback-chain test command, and the remaining choice is product surface rather than source uncertainty.

## What This Changes

The issue requests a `/models test-fallback` style command that intentionally skips the primary model and probes one or all configured fallback candidates.

## Best Possible Solution

A maintainer-sponsored design should choose whether fallback-chain verification is a dedicated `/models test-fallback` command or part of the broader models probe/migration workflow, then reuse the real fallback/auth resolution path without mutating config or session state.
