## Summary

Current main still lacks a fallback-chain test command, and the existing live status probe validates provider/profile targets rather than ordered fallback behavior. The request remains useful, but it should stay in maintainer product review because https://github.com/openclaw/openclaw/issues/63145 proposes overlapping all-configured-model probing and the repository favors one canonical diagnostic path.

## What This Changes

Add a proactive model fallback-chain command that can test the first configured fallback or the full ordered chain and report which models respond.

## Best Possible Solution

Create one reusable live model-probe primitive that uses canonical agent/model/auth resolution, then let maintainers expose ordered fallback verification and all-configured-model health through a coherent CLI contract; add a slash surface only if chat-based operation is explicitly desired.
