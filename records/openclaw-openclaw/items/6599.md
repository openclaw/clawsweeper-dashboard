## Summary

Keep open. Current main and v2026.6.11 still lack an ordered fallback-chain diagnostic, and the broader per-model probe request does not fully cover testing actual fallback resolution; maintainers should choose the canonical command surface before implementation.

## What This Changes

Add a diagnostic command that deliberately skips the primary model and verifies the first or entire configured fallback chain with live requests.

## Best Possible Solution

Create one runtime-backed fallback diagnostic that resolves the active agent’s canonical chain, can pin and test the first or every fallback without masking failures, exposes a canonical CLI surface, and uses only a thin slash-command wrapper if chat access is approved.
