## Summary

Keep open. Current main still lacks a diagnostic that deliberately bypasses the primary model and proves the configured ordered fallback path; the open per-model probe request at https://github.com/openclaw/openclaw/issues/63145 overlaps but does not settle that distinct failover semantic. A maintainer should choose one coherent diagnostics contract before implementation.

## What This Changes

Add a `/models test-fallback` command that proactively exercises the configured fallback chain without waiting for a primary-model failure.

## Best Possible Solution

Define one model-diagnostics contract with an explicit ordered fallback-chain mode, reuse the existing status/probe infrastructure where appropriate, and preserve distinct reporting for independent model health versus real failover ordering.
