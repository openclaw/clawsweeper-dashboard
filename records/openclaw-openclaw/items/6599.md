Keep open: current main and the latest release still lack a targeted `/models test-fallback` or equivalent primary-skipping fallback-chain probe, and the direct implementation PR is closed unmerged while related open items cover broader model health or migration UX.

## What This Changes

This issue requests a `/models test-fallback` command that deliberately skips the primary model, probes configured fallback candidates, and reports which fallback model succeeds.

## Best Possible Solution

Define one canonical fallback validation surface that reuses real model/auth fallback resolution, can intentionally start at configured fallback candidates, reports the model that answered, and documents how it differs from auth probes and broad configured-model health checks.
