## What This Changes

The issue requests a `/models test-fallback` command that intentionally skips the primary model and probes configured fallback models before a real provider failure occurs.

## Best Possible Solution

Define one canonical fallback-chain probe that reuses OpenClaw's real model/auth fallback resolution, starts at configured fallback candidates, reports which model answered, supports first-fallback and all-fallback modes, and documents how it differs from broad configured-model health checks.

## Reproduction Assessment

Yes, at source level. Current main has no `models test-fallback` CLI command or `/models test-fallback` action, and the existing live probe path tests auth/profile reachability rather than intentionally starting at configured fallbacks.

## Solution Assessment

Unclear as an exact implementation until maintainers choose the canonical probe UX. A targeted fallback-chain probe is plausible, but it should be reconciled with broader configured-model health checks and staged model-migration UX before implementation is queued.
