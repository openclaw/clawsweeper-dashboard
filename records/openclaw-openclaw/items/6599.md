## Summary

## What This Changes

Add a `/models test-fallback` diagnostic that deliberately bypasses the configured primary model and verifies one or all configured fallback models through OpenClaw’s runtime path.

## System Context

OpenClaw resolves a selected agent model and then walks configured fallback candidates when a provider or model fails. The requested command would expose that recovery path as an intentional operator diagnostic, reporting whether configured fallback models can answer before an outage occurs.

## Architecture Diagram

flowchart LR

  B --> C[Fallback candidate order]
  D[/models diagnostic request] --> E[Intentional primary bypass]
  E --> C
  C --> F[Provider request]
  F --> G[Per-fallback result]
  G --> H[Operator-visible report]

## Best Possible Solution

Define one operator-facing model diagnostic contract, preferably by extending the existing probe surface only if it can explicitly represent ordered fallback testing; then implement it by reusing canonical model and fallback resolution with focused CLI, slash-command, and fallback-runtime coverage.
