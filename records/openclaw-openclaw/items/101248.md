## What This Changes

The PR adds an optional native `sessions_spawn` `announceTarget: "parent"` mode, persists that choice with pending subagent runs, and routes completion through a non-delivering requester-session wakeup.

## Best Possible Solution

First establish a concrete workflow that current main's parent-first handoff and silent-reply behavior cannot support; only then add the narrowest per-spawn strict-silent contract, with restart persistence and explicit failure semantics, rather than a parallel general routing policy.
