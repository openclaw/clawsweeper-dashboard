## Summary

Keep open. Current main and the latest release still route Voice Call realtime telephony through PCMU/8 kHz mu-law, and the shared realtime audio contract has no Opus format, so the requested native Opus support remains missing and needs maintainer product/design direction before implementation.

## What This Changes

Requests native Opus codec support in the Voice Call plugin/realtime audio path so Telnyx/OpenAI-style phone calls are not constrained to G.711 mu-law.

## Best Possible Solution

Keep this as a maintainer-reviewed Voice Call codec capability request; if accepted, extend the realtime audio format/capability design and Telnyx codec handling with focused tests, docs, and live carrier proof while preserving the existing PCMU path.

## Reproduction Assessment

Partly. Source inspection reproduces the missing capability because current main and v2026.6.11 expose PCMU/G.711 mu-law and PCM16 only, but no live Opus-only Telnyx call was run to prove the exact disconnect path.

## Solution Assessment

Unclear. Native Opus may be the right end state, but maintainers should first choose the codec contract and provider negotiation shape rather than adding an ad hoc Telnyx-only flag.
