## Summary

Keep open: current main and v2026.6.11 still route Voice Call Telnyx realtime media as PCMU/G.711 and the realtime voice contract only exposes G.711 u-law or PCM16, so native Opus remains a real feature gap rather than something already implemented.

## What This Changes

Request native Opus codec support for the Voice Call plugin and realtime audio contracts so long-distance telephony providers can use a more packet-loss-tolerant codec.

## Best Possible Solution

Keep this as the Voice Call Opus codec tracker, then design a narrow plugin/SDK codec negotiation path with docs, compatibility handling, and live Telnyx/OpenAI or equivalent carrier proof.

## Reproduction Assessment

Yes as a source-level feature-gap check, but not as a live current-main carrier repro. Current source and v2026.6.11 hardcode the Telnyx realtime stream to PCMU and expose no Opus realtime audio contract.

## Solution Assessment

Unclear as a final implementation. The maintainable fix is not only changing one Telnyx field; it should add an explicit codec/audio-format boundary through Voice Call and realtime provider contracts, then prove it with live carrier audio.
