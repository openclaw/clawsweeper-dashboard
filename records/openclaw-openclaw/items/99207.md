## Summary

Keep open. Current main still routes Voice Call realtime carrier media through PCMU/G.711 mu-law and the realtime provider format union only exposes G.711 mu-law or PCM16, so the requested native Opus path is not implemented or superseded.

## What This Changes

The issue requests native Opus codec support for Voice Call so Telnyx/OpenAI and other voice integrations can tolerate packet loss and jitter on international routes.

## Best Possible Solution

Keep this as the canonical Voice Call codec-capability request and have maintainers choose the plugin/API codec contract before implementation.

## Reproduction Assessment

No high-confidence live reproduction was established. Source inspection does show the requested native Opus path is absent on current main because the Telnyx stream and realtime provider formats are PCMU/G.711 mu-law or PCM16 only.

## Solution Assessment

Unclear as an implementation shape. Native Opus may be the right product direction, but the best fix first needs a maintainer decision on codec negotiation, provider support, and whether this is plugin-local or requires a shared realtime voice API extension.
