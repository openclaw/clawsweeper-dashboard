## Summary

Keep open: current main still exposes Voice Call/Telnyx realtime as PCMU/G.711-oriented, and the shared realtime audio contract has no Opus format, so the requested Opus capability remains real product/API work rather than an implemented cleanup or duplicate.

## What This Changes

Request native Opus codec support and guidance for the Voice Call plugin so telephony providers can use FEC/PLC-capable audio outside PCMU-only paths.

## Best Possible Solution

Define a maintainer-approved Voice Call codec strategy that preserves the PCMU default, adds Opus or wideband support where carrier/model contracts support it, updates SDK/docs/tests, and proves the path with a live Telnyx or comparable carrier setup.

## Reproduction Assessment

Yes for the current limitation: source inspection on current main shows Voice Call/Telnyx fields are PCMU and realtime voice types expose no Opus format. No live Opus-only reproduction was run in this review.

## Solution Assessment

Unclear as an implementation path: adding Opus is plausibly the right end state, but the best fix needs maintainer direction across SDK audio formats, carrier codec negotiation, transcoding dependencies, defaults, docs, and live proof.
