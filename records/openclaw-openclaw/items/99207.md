## Summary

Keep this issue open: current main and the latest release still only expose G.711 mu-law/PCM realtime voice contracts and Telnyx voice-call streaming is hard-coded to PCMU, so native Opus support remains a real feature/product decision rather than something already implemented or safely closeable.

## What This Changes

Request native Opus codec support for the voice-call plugin so Telnyx/OpenAI-style voice calls can tolerate long-distance packet loss better than current G.711 mu-law paths.

## Best Possible Solution

Define the supported Opus telephony/realtime voice contract first, then implement it inside the voice-call plugin and shared realtime voice SDK with focused tests, docs, and live Telnyx/OpenAI proof.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Source inspection gives a high-confidence way to reproduce the missing support: current main and v2026.6.11 only expose g711_ulaw/pcm16 realtime formats and PCMU Telnyx streaming fields. I did not run a live Telnyx Opus-only call, so the carrier disconnect behavior itself remains reporter-provided evidence.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainers choose the codec contract. The maintainable path is not a one-off carrier workaround; it should align the shared realtime voice format types, voice-call provider behavior, docs, and live carrier validation.
