## Summary

Keep open. Current main and v2026.6.11 still hardcode OpenClaw-owned prompt sections and lack a user-editable Safety/template contract; the remaining work is a product and security-boundary decision, not stale cleanup.

## What This Changes

The issue asks for editable OpenClaw-owned system prompt templates, such as overriding the Safety section from workspace files.

## Best Possible Solution

Define one maintainer-approved named-section override contract with explicit trust boundaries, precedence, schema or workspace-file rules, docs, prompt-cache behavior, and regression coverage; if rejected, document existing provider, hook, channel, and bootstrap surfaces as the supported alternatives.
