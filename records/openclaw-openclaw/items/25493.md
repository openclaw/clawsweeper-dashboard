## Summary

Keep open. Current main and v2026.6.11 still keep OpenClaw-owned prompt sections fixed, and the remaining work is a product/security decision about whether users may override Safety and other core prompt text.

## What This Changes

The issue requests making fixed OpenClaw-owned system prompt sections editable, for example through SAFETY.md or template-based overrides.

## Best Possible Solution

Define one maintainer-approved named-section override contract with explicit trust boundaries, precedence, schema or workspace-file rules, docs, prompt-cache behavior, and regression coverage; if rejected, document existing provider, hook, channel, and bootstrap surfaces as the supported alternatives.

Owner confidence: high

Options:

- **Approve Scoped Section Overrides (recommended):** Add a narrow named-section override model with explicit edit authority, precedence, security docs, prompt-cache behavior, and regression tests.
- **Keep Core Sections Fixed:** Reject user-editable core sections and document provider overlays, channel prompts, plugin hooks, and bootstrap files as the supported customization paths.
- **Defer To Narrower Prompt Work:** Let identity-line, config-rules, include, and hook-replacement work proceed independently while leaving broad Safety/template editing unresolved.

## Reproduction Assessment

Yes, at source level rather than as a bug reproduction: current main and v2026.6.11 still have literal core prompt sections and no SAFETY.md-style or named user section override contract.

## Solution Assessment

Unclear until maintainers decide the product and security boundary. The maintainable path is one scoped override model with explicit trust rules, not broad MDX execution, ad hoc file names, or another partial prompt knob.
