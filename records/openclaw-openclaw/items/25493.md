## Summary

Keep open. Current main and the latest release still hardcode OpenClaw-owned prompt sections and expose only narrower provider, hook, bootstrap, or adjacent config surfaces, so the remaining work is a maintainer product and security-boundary decision.

## What This Changes

The issue requests user-editable system prompt templates or section overrides, such as SAFETY.md-style customization for fixed OpenClaw prompt sections.

## Best Possible Solution

Define one maintainer-approved named-section override contract with explicit trust boundaries, precedence, schema or workspace-file rules, docs, and prompt regression coverage; if rejected, document hooks, provider overlays, channel prompts, and bootstrap files as the supported alternatives.
