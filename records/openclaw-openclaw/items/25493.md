## Summary

Keep open: current main and v2026.6.11 still hardcode OpenClaw-owned prompt sections such as Safety, OpenClaw Control, and Self-Update, while the direct workspace-file implementation PR is closed unmerged and related open work is narrower or adjacent.

## What This Changes

Request to make fixed OpenClaw-owned system prompt template sections editable, for example through SAFETY.md or a template mechanism.

## Best Possible Solution

Define one maintainer-approved named-section override contract with explicit trust boundaries, precedence, text-only schema or workspace-file rules, docs, prompt-cache behavior, and regression coverage; if rejected, document the existing provider, hook, channel, and bootstrap surfaces as supported alternatives.
