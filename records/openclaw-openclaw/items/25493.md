Keep open. Current main and v2026.6.11 still hardcode the requested OpenClaw-owned prompt sections, the direct implementation PR is closed unmerged, and the remaining work is a product and security-boundary decision rather than conservative cleanup.

## What This Changes

The issue requests editable OpenClaw system prompt templates, such as SAFETY.md-style overrides or a template language for fixed core prompt sections.

## Best Possible Solution

Define one maintainer-approved named-section override contract with explicit trust boundaries, precedence, schema or workspace-file rules, docs, and prompt regression coverage; if rejected, document hooks, provider overlays, channel prompts, and bootstrap files as the supported alternatives.
