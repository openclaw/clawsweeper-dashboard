## Summary

Keep open: current main and v2026.6.11 still keep the requested OpenClaw-owned prompt sections fixed, while the direct workspace-file PR is closed unmerged and related open work is narrower or adjacent. ## What This Changes

The issue requests editable system prompt templates, including SAFETY.md-style overrides for fixed OpenClaw-owned prompt sections.

## Best Possible Solution

Define one maintainer-approved named-section override contract with explicit trust boundaries, precedence, text-only schema or workspace-file rules, docs, prompt-cache behavior, and regression coverage; if rejected, document the existing provider, hook, channel, and bootstrap surfaces as supported alternatives.

Options:

- **Approve scoped section overrides (recommended):** Add a narrow named-section text override model with explicit edit authority, precedence, security docs, prompt-cache behavior, and regression tests.
- **Keep core sections fixed:** Reject user-editable core sections and document provider overlays, channel prompts, plugin hooks, and bootstrap files as the supported customization paths.
- **Defer to narrower prompt work:** Let identity-line, config-rules, include, and hook-replacement work proceed independently while leaving broad Safety/template editing unresolved.

## Solution Assessment

Unclear until maintainers decide the product and security boundary. The maintainable path is one scoped text-first override model with explicit trust rules, not broad MDX execution, ad hoc file names, or another partial prompt knob.
