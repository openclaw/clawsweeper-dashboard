## Summary

Keep open. Current main and v2026.6.11 still hardcode the requested OpenClaw-owned prompt sections and only expose narrower hook, bootstrap, provider-overlay, and channel prompt surfaces, so the remaining work is a maintainer product and security-boundary decision.

## What This Changes

The issue requests editable templates or workspace-file/config overrides for fixed core system prompt sections such as Safety and OpenClaw guidance.

## Best Possible Solution

Define one maintainer-approved named-section override contract with explicit edit authority, precedence, schema or workspace-file rules, docs, and prompt regression coverage; if rejected, document hooks, provider overlays, channel prompts, and bootstrap files as the supported alternatives.

Unclear until maintainers decide the product and security boundary. A scoped named-section override model is the maintainable shape if approved, while broad MDX execution or ad hoc partial prompt knobs would be riskier than the existing hook/provider/bootstrap surfaces.
