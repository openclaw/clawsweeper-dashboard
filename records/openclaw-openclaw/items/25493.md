## Summary

Keep open. Current main and the latest release still hardcode OpenClaw-owned prompt sections such as Safety, Tool Call Style, OpenClaw Control, and Self-Update, while the supported hook/provider/workspace paths remain narrower than editable core prompt section templates.

## What This Changes

The issue requests making core OpenClaw system prompt template sections editable, for example with a SAFETY.md override or a template mechanism.

## Best Possible Solution

Define one maintainer-approved section override contract with explicit trust boundaries, precedence, docs, schema or workspace-file rules, and regression coverage; if rejected, document provider overlays, bootstrap hooks, and prompt-build hooks as the supported alternatives.

## Reproduction Assessment

Yes for the source-level feature gap, not as a bug reproduction: current main and v2026.6.11 still have literal core prompt sections and no SAFETY.md-style or named user section override contract.

## Solution Assessment

Unclear until maintainers decide the product and security boundary. The narrow maintainable path is one canonical override model, not broad MDX execution, ad hoc file names, or another partial prompt knob.
