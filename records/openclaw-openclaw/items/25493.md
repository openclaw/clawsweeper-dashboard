Keep open. Current main and v2026.6.11 still hardcode OpenClaw-owned prompt sections and do not expose a user-editable Safety/template contract, so this remains a product and security-boundary decision.

## What This Changes

## Best Possible Solution

Define one maintainer-approved named-section override contract with explicit trust boundaries, precedence, schema or workspace-file rules, docs, prompt-cache behavior, and regression coverage; if rejected, document the existing provider, hook, channel, and bootstrap surfaces as the supported alternatives.
