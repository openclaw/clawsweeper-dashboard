## Summary

Keep open: current main and v2026.6.11 still hardcode the requested OpenClaw-owned prompt sections, and the available hook/provider/bootstrap surfaces are either broader escape hatches or narrower adjacent customization paths rather than a first-class editable section template contract.

## What This Changes

The issue requests user-editable OpenClaw system prompt sections, such as Safety, via a template or workspace-file override surface.

## Best Possible Solution

Define one maintainer-approved named-section override contract with explicit trust boundaries, precedence, schema or workspace-file rules, docs, prompt-cache behavior, and regression coverage; if rejected, document existing provider, hook, channel, and bootstrap surfaces as the supported alternatives.
