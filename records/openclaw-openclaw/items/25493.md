## Summary

Keep open. Current main and the latest release still do not expose a SAFETY.md-style or named editable override contract for OpenClaw-owned system prompt sections, so the remaining work is a product and security-boundary decision rather than conservative cleanup.

## What This Changes

Request to make fixed OpenClaw system prompt template sections editable, for example by allowing a SAFETY.md-style override or template language for core prompt sections.

## Best Possible Solution

Define one maintainer-approved named-section override contract with explicit trust boundaries, precedence, schema or workspace-file rules, docs, prompt-cache behavior, and regression coverage; if rejected, document the existing provider, hook, channel, and bootstrap surfaces as the supported alternatives.

Question: Should OpenClaw add a first-class user-editable override contract for OpenClaw-owned system prompt sections such as Safety, Tool Call Style, OpenClaw Control, and Self-Update?

Rationale: The request changes model-facing safety guidance and prompt precedence, while current code intentionally exposes narrower provider, hook, bootstrap, channel, and SDK prompt surfaces; automation cannot choose the permanent product and security boundary.

Likely owner: steipete

Owner reason: steipete has the clearest recent history on provider-owned prompt contributions and the OpenClaw-owned prompt boundary this decision would change.

Owner confidence: high

Options:

- **Approve scoped section overrides (recommended):** Add a narrow named-section override model with explicit edit authority, precedence, security docs, prompt-cache behavior, and regression tests.
- **Keep core sections fixed:** Reject user-editable core sections and document provider overlays, channel prompts, plugin hooks, and bootstrap files as the supported customization paths.
- **Defer to narrower prompt work:** Let identity-line, config-rules, include, and hook-replacement work proceed independently while leaving broad Safety/template editing unresolved.

## Reproduction Assessment

Yes, at source level rather than as a bug reproduction: current main and v2026.6.11 still have literal core prompt sections and no SAFETY.md-style or named user section override contract.

## Solution Assessment

Unclear until maintainers decide the product and security boundary. The maintainable path is one scoped override model with explicit trust rules, not broad MDX execution, ad hoc file names, or another partial prompt knob.
