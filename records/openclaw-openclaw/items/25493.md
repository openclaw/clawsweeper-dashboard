## Summary

Keep open. Current main and v2026.6.11 still hardcode OpenClaw-owned prompt sections such as Safety, Tool Call Style, OpenClaw Control, and Self-Update, while related items are either closed unmerged or narrower than editable core prompt templates.

## What This Changes

The issue requests a user-editable system prompt template or section override mechanism, such as SAFETY.md-style overrides or a template language, for fixed OpenClaw prompt sections.

## Best Possible Solution

Define one maintainer-approved core prompt section override contract with explicit trust boundaries, precedence, schema or workspace-file rules, docs, and regression coverage; if rejected, document provider overlays and prompt hooks as the supported alternatives.

## Reproduction Assessment

Yes, as a source-level feature gap: current main and v2026.6.11 still have literal core prompt sections and no SAFETY.md-style or named user section override contract.

## Solution Assessment

Unclear until maintainers decide the product and security boundary. The narrow maintainable path is one canonical override model, not broad MDX execution, ad hoc file names, or another partial prompt knob.
