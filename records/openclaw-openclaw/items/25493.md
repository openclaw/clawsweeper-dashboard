## Summary

Keep open. Current main and v2026.6.11 still hardcode the requested OpenClaw-owned prompt sections and only expose narrower provider, hook, bootstrap, or channel prompt surfaces, so the remaining work is a maintainer product and security-boundary decision.

## What This Changes

The issue requests editable OpenClaw system prompt template sections, especially hardcoded Safety/system tips text, potentially through files such as SAFETY.md or a template language.

## Best Possible Solution

Define one maintainer-approved named-section override contract with explicit trust boundaries, precedence, schema or workspace-file rules, docs, and prompt regression coverage; if rejected, document hooks, provider overlays, and bootstrap files as the supported alternatives.
