## Summary

Keep open. Current main and v2026.6.11 still hardcode the requested OpenClaw-owned prompt sections, and the remaining work is a product/security-boundary decision rather than an already-implemented cleanup item.

## What This Changes

This issue asks for user-editable OpenClaw-owned system prompt template sections, such as a SAFETY.md-backed Safety override or another template mechanism.

## Best Possible Solution

Define one maintainer-approved named-section override contract with explicit trust boundaries, precedence, schema or workspace-file rules, docs, and prompt regression coverage; if rejected, document hooks, provider overlays, channel prompts, and bootstrap files as the supported alternatives.
