## Summary

Keep open. Current main and v2026.6.11 still hardcode OpenClaw-owned prompt sections such as Safety, OpenClaw Control, and Self-Update, while the existing override surfaces are narrower provider/hook/bootstrap paths; this remains a product and security-boundary decision.

## What This Changes

Request to make fixed OpenClaw system prompt sections user-editable, for example through SAFETY.md-style section files or prompt templates.

## Best Possible Solution

Define one maintainer-approved named-section override contract with explicit trust boundaries, precedence, schema or workspace-file rules, docs, and prompt regression coverage; if rejected, document hooks, provider overlays, channel prompts, and bootstrap files as the supported alternatives.
