## Summary

Keep open. Current main and the latest release still hardcode OpenClaw-owned prompt sections such as Safety and Self-Update, while existing hook, provider, context-engine, workspace, and channel prompt surfaces do not provide the requested section-level system prompt template override.

## What This Changes

The issue requests editable OpenClaw-owned system prompt template sections, such as a SAFETY.md-style override or template surface, for higher prompt customizability.

## Best Possible Solution

Define one canonical, maintainer-approved section override contract with explicit trust boundaries, precedence, docs, schema or workspace-file rules, prompt-cache behavior, and regression coverage; if rejected, document the existing hook/provider/bootstrap/context-engine paths as the supported alternatives.

## Reproduction Assessment

Yes for the source-level feature gap, not as a bug reproduction: current main and v2026.6.11 still have literal core prompt sections and no SAFETY.md-style or named user section override contract.

## Solution Assessment

Unclear until maintainers decide the product/security boundary. The narrow maintainable path is one canonical override model, not broad MDX execution, ad hoc file names, or another partial prompt knob.
