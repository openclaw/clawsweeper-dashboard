## Summary

Keep open. Current main and v2026.6.11 still hardcode OpenClaw-owned prompt sections and do not expose a SAFETY.md-style or named user section override contract; this remains a product and security-boundary decision, not conservative cleanup.

## What This Changes

The issue requests a user-editable or template-based way to override fixed OpenClaw-owned system prompt sections such as Safety, for example through workspace files like SAFETY.md.

## Best Possible Solution

Define one maintainer-approved named-section override contract with explicit trust boundaries, precedence, schema or workspace-file rules, docs, prompt-cache behavior, and regression coverage; if rejected, document existing provider, hook, channel, and bootstrap surfaces as the supported alternatives.
