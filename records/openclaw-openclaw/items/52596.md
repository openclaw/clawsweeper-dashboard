## Summary

Keep open. Current main still has the pre-tool enforcement seam and session lifecycle primitives, but it does not implement a session PIN config, framework-owned authenticated-session state, or trusted non-model verifier; this remains a security/product boundary decision.

## What This Changes

Request a framework-level session PIN gate that blocks tool calls until each new or reset session is authenticated through trusted runtime code.

## Best Possible Solution

Design an approved SecretRef-backed core primitive or explicit plugin API extension that keeps PIN comparison outside model context, stores only authenticated session state, clears it on new/reset sessions, and proves tool blocking plus no transcript leakage.
