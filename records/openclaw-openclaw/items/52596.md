## Summary

Keep open. Current main still has the tool-blocking seam and reset lifecycle, but it does not implement the requested session PIN config, framework-owned authenticated session state, or trusted verifier outside model-controlled context; this remains a security/product design item rather than cleanup closure.

## What This Changes

The issue requests a framework-level session authentication PIN gate that blocks tool calls until a trusted per-session verifier marks the session authenticated.

## Best Possible Solution

Design either a core security primitive or an approved plugin/API extension with SecretRef-backed secret source, authenticated session state cleared on /new and /reset, trusted native verification, and tests for tool blocking plus PIN non-leakage.
