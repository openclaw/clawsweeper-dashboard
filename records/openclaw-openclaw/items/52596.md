## Summary

Keep open. Current main and the latest release still provide the before-tool-call enforcement seam and session reset lifecycle, but they do not implement a core session PIN config, framework-owned authenticated session state, or trusted TypeScript verifier; this is a valid security/product feature request rather than stale cleanup.

## What This Changes

The issue requests an opt-in framework-level session PIN gate that blocks tool calls until a trusted verifier marks a new or reset session authenticated.

## Best Possible Solution

A maintainer-approved security design should define an opt-in core auth gate with a SecretRef-capable secret source, TypeScript-only verifier, session authenticated state, reset clearing, before_tool_call enforcement, docs, and regression coverage.
