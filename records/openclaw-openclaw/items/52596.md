## Summary

Keep open. Current main and v2026.6.11 have the framework-level before-tool-call choke point, session reset lifecycle, and plugin hook surface, but they still lack the requested `session.auth.pin` config, framework-owned authenticated session state, and trusted TypeScript verifier outside model context; this is a security-aligned feature that needs maintainer design, not cleanup closure.

## What This Changes

Add a framework-level session PIN gate that blocks tools for each new or reset session until a trusted verifier authenticates that session.

## Best Possible Solution

Design either a core security primitive or an approved plugin/API extension with a SecretRef-backed secret source, authenticated session state cleared on `/new` and `/reset`, a trusted native verification path, and regression coverage for tool blocking plus no PIN transcript leakage.

- **Defer the PIN gate:** Leave existing allowlists, sandboxing, approvals, and external-content wrapping as the supported mitigation until a stronger step-up-auth design is chosen.

## Solution Assessment

Unclear until maintainers choose the security boundary: the before-tool-call and session-reset layers are plausible, but a raw PIN in config is probably not the best permanent secret shape. A SecretRef-backed verifier or explicit plugin API design is safer than prompt-space comparison.
