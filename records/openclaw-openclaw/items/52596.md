## Summary

Keep open. Current main and v2026.6.11 still have pre-tool hook/trusted-policy primitives and session reset metadata, but no `session.auth.pin` config, durable authenticated-session bit, or trusted non-model verifier; this remains a security-sensitive product/API decision rather than cleanup closure.

## What This Changes

The issue requests a framework-level session PIN gate that blocks tool execution until trusted session authentication succeeds.

## Best Possible Solution

Define a narrow, SecretRef-backed session-auth primitive with trusted non-model verification, explicit reset semantics, audit behavior, and recovery UX, or intentionally route PIN-style gates to a plugin/trusted-policy design if maintainers reject core ownership.
