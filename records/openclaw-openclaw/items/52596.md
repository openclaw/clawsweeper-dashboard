## Summary

Keep open. Current main still has the before_tool_call enforcement seam and session reset lifecycle, but it does not have a core session PIN config, framework-owned authenticated session state, or trusted verifier; the discussion correctly frames this as a security/product design item rather than a narrow bug fix.

## What This Changes

Add an opt-in core session PIN authentication gate that blocks tool execution until a trusted framework verifier marks the session authenticated.

## Best Possible Solution

A maintainer-sponsored security design should define the opt-in secret source, trusted verifier, session-authenticated state, reset behavior, before_tool_call enforcement, docs, and regression coverage before implementation.
