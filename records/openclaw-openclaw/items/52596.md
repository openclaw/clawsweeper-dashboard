## Summary

Keep open. Current main has the before-tool-call enforcement seam, plugin session-extension storage, and reset lifecycle hooks, but it still lacks the requested core `session.auth.pin` config, framework-owned authenticated session state, and trusted TypeScript PIN verifier; the remaining choice is a security/product decision rather than conservative cleanup.

## What This Changes

Request to add a framework-level per-session PIN authentication gate that blocks tool calls until a trusted TypeScript verifier marks the session authenticated.

## Best Possible Solution

Settle the security design first: either define a core session-auth primitive with trusted verification and reset semantics, or explicitly bless a plugin/ClawHub pattern that uses the current hook and session-extension APIs.
