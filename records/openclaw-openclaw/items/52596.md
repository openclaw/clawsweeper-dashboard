## Summary

Keep open. Current main and the latest release still have the framework-level pre-tool hook and session reset lifecycle the issue points to, but they do not have the requested core PIN config, framework-owned authenticated session state, or trusted verifier; the remaining question is a security/product decision, not stale cleanup.

## What This Changes

The issue requests an opt-in core `session.auth.pin` gate that blocks tool calls at the framework level until a session-scoped PIN is verified outside the model context.

## Best Possible Solution

Make an explicit security/product decision: either sponsor a narrow opt-in core session-auth design with a non-model verifier and session-state tests, or document this as a plugin/guardrail pattern until a core API is approved.

Options:

- **Fold it into broader guardrails work:** Use https://github.com/openclaw/openclaw/issues/72741 or a successor design as the canonical owner if maintainers want a general external security-check interface instead of a PIN-specific feature.
