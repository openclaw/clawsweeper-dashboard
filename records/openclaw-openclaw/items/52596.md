## Summary

Keep open. Current main and latest release still provide the before-tool-call choke point, plugin/trusted-policy hooks, and reset/session primitives, but they do not implement a core `session.auth.pin` config, framework-owned authenticated session state, or trusted TypeScript PIN verifier.

## What This Changes

Requests a framework-level session PIN gate that blocks tool calls until a trusted verifier authenticates the current session.

## Best Possible Solution

Keep this as a security/product design item; if accepted, implement a narrow secret-safe verifier, authenticated `SessionEntry` state cleared on new/reset, before-tool-call enforcement, docs, and focused regression coverage.

## Reproduction Assessment

Not applicable as a bug reproduction; this is a feature/security design request. Source inspection confirms the requested core PIN config, trusted verifier, and authenticated session state are absent on current main and v2026.6.11.

## Solution Assessment

Unclear until maintainers choose the security/product boundary. The before-tool-call path is a plausible enforcement layer, but the specific PIN config and verifier contract are new auth, secret-handling, and session-state surface.
