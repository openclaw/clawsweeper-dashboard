## Summary

Keep open: this is a useful iOS slice for the authenticated-proxy mobile header request, but the patch is not merge-ready because it adds credential-bearing headers without a secure-transport guard, reset cleanup, share-extension coverage, or real reverse-proxy proof.

## What This Changes

The PR adds iOS per-gateway custom header storage, an advanced Settings editor, and a URLRequest-based OpenClawKit WebSocket upgrade path that injects sanitized headers on gateway reconnects.

## Best Possible Solution

Land only after the iOS header contract has secure-transport gating, reset/forget cleanup, share-extension coverage or explicit scoping, focused tests, and real authenticated-proxy proof; narrow the feature to typed proxy auth if security review rejects arbitrary headers.

## Review Findings

Full review comments:

- **[P1] Block custom headers on cleartext gateways:** `apps/shared/OpenClawKit/Sources/OpenClawKit/GatewayChannel.swift:392-394`
  - body: These headers are explicitly credential-bearing, but `makeUpgradeRequest()` attaches them for any gateway URL. Manual iOS gateways can still be configured with `Use TLS` off, so a user could send Cloudflare Access service tokens or an `Authorization` value over `ws://`; reject or ignore custom headers on cleartext routes with a visible settings/preflight error.
  - confidence: 0.87
- **[P2] Clear custom header credentials during reset:** `apps/ios/Sources/Gateway/GatewaySettingsStore.swift:288-289`
  - body: The new `customHeaders.<stableID>` Keychain account is separate from the existing credential bundle that Reset Onboarding deletes. After a full reset, those proxy tokens can remain in Keychain and be sent again if the user later reconnects to the same stable ID; add targeted and full-reset cleanup plus regression coverage.
  - confidence: 0.9
- **[P2] Thread headers into share extension gateway sends:** `apps/shared/OpenClawKit/Sources/OpenClawKit/GatewayNodeSession.swift:208`
  - body: Adding `extraHeadersProvider` only to the foreground NodeAppModel leaves the share extension's separate GatewayNodeSession on the default nil provider. A user behind an authenticating proxy may connect in the app but still get proxy 401s when sharing content; persist/pass the headers for that relay config or explicitly scope the feature out of share sends.
  - confidence: 0.82
