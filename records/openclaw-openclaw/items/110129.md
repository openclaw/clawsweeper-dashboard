## What This Changes

This PR changes Telegram group-history watermark comparison so only safe decimal message-ID strings determine ordering when two entries share a timestamp.

## System Context

Telegram inbound messages are normalized into cached history entries and compared with an ambient-transcript watermark before prior group messages are added to an agent prompt. This predicate decides whether equal-timestamp history belongs after that boundary, affecting the context the agent receives.

## Best Possible Solution

Use the shared strict positive-integer parser on the raw message-ID string, then add equal-timestamp regression cases for whitespace-padded and zero values so malformed IDs never order history.
