## Summary

Keep open. Current main and the latest release still do not provide a first-class per-skill writable runtime-data directory; the existing surfaces are managed skill package roots and skill dependency/tool install roots, so this remains a product and storage-boundary decision rather than cleanup-close material.

## What This Changes

The issue requests a standardized per-skill runtime data directory under `~/.openclaw/`, plus optional OpenClaw-native metadata or placeholders for skill authors.

## Best Possible Solution

Maintainers should define one durable skill-state contract, preferably a plugin/skill state API or explicitly documented artifact-directory boundary rooted in OpenClaw-owned storage, then align metadata, install behavior, docs, and doctor expectations around it.
