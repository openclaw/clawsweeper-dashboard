## Summary

Keep open. Current main and v2026.6.11 still do not provide a first-class per-skill writable runtime-data directory; existing paths cover managed skill packages, installer tool artifacts, or structured config, so this remains a product/API storage-boundary decision.

## What This Changes

The issue requests a standardized per-skill writable data directory and metadata convention under the OpenClaw state directory for community skills.

## Best Possible Solution

Define one maintainer-approved generic skill-data contract, then align SKILL.md metadata, install behavior, docs, and migration or doctor expectations without turning optional community skills into core-specific policy.
