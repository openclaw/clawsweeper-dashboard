## Summary

Keep open. Current main and the latest release still have skill package roots and installer tool-artifact roots, but no first-class per-skill writable data directory or native replacement for legacy `configPaths`; this remains a maintainer product/storage-boundary decision.

## What This Changes

Request to standardize a per-skill writable data directory under `~/.openclaw/` and optionally add an OpenClaw-native skill metadata field for it.

## Best Possible Solution

Maintainers should choose one durable skill-owned data contract, then align SKILL.md metadata, install behavior, runtime discovery, docs, and any doctor or migration expectations around that convention.
