## Summary

Keep open. Current main and v2026.6.11 still do not provide a first-class per-skill runtime data directory contract; the existing paths cover managed skill packages, installer tool artifacts, structured per-skill config, or plugin state, so this remains a product/API storage-boundary decision.

## What This Changes

The issue requests a standardized per-skill runtime data directory convention under `~/.openclaw/` and optional OpenClaw-native metadata/runtime support for it.

## Best Possible Solution

Define one durable skill-owned data contract first, then align SKILL.md metadata, install behavior, docs, validation, and any doctor or migration expectations around that chosen storage model.
