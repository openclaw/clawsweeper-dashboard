## Summary

Keep open. Current main still lacks a first-class per-skill writable data-directory contract; existing skill paths cover skill package loading and installer artifacts, so this remains a maintainer product/storage-boundary decision rather than cleanup-close material.

## What This Changes

Request a standard per-skill writable data directory under `~/.openclaw` plus an OpenClaw-native metadata or runtime convention instead of decorative legacy `configPaths`.

## Best Possible Solution

Maintainers should choose one skill-data contract, then align SKILL.md metadata, install/runtime behavior, docs, and any doctor or migration expectations around that decision.
