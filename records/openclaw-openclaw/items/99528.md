## What This Changes

The PR moves the usage-cost cache pricing fingerprint from each file entry to the top-level cache object, bumps the cache version to v5, updates freshness checks, and adds regression tests for rebuild, serialization, checkpoint reload, and pricing invalidation.

## Best Possible Solution

Adopt a compact v5 usage-cost cache with one cache-level fingerprint, preserve pricing-change invalidation and append-only reuse, then land the strongest duplicate fix PR once proof and CI are complete.

## Reproduction Assessment

## Solution Assessment

Yes, the versioned cache rebuild plus one cache-level fingerprint is the narrow maintainable fix for this duplicated metadata. The remaining blocker is proof quality, not a better code layer.
