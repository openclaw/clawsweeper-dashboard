## Summary

Keep open: the fix direction matches the linked cache-bloat bug, but this branch can persist checkpointed version-5 cache files without the new top-level fingerprint, and the PR body only provides test-output proof rather than real behavior proof.

## What This Changes

The PR moves `pricingFingerprint` from each usage-cost cache entry to the top-level cache object, bumps the cache version to 5, and adds a regression test for the serialized cache shape.

## Best Possible Solution

Store the cache-level fingerprint before every cache write, preserve checkpoint forward progress and pricing invalidation, then add focused regression coverage plus real behavior proof on a large or interrupted cache refresh.

## Reproduction Assessment

Yes. Current main stores `pricingFingerprint` on every `UsageCostCacheFileEntry`, and the linked issue provides a concrete large-cache measurement; I did not run a live large-cache replay in this read-only review.

## Solution Assessment

No. Moving the fingerprint to the cache level is the right narrow fix shape, but assigning it only after checkpoint writes leaves an incomplete persisted schema in the interrupted-refresh path.
