## Label Justifications

- `P1`: A normal direct-session workflow can lose first-level subagent delegation after `/new`, blocking a documented agent workflow.
- `impact:session-state`: The fault is caused by persisted session lineage being interpreted as subagent nesting state.

## Summary

This issue remains necessary: current main still resolves missing `spawnDepth` through `spawnedBy ?? parentSessionKey`, while `/new` rollover preserves `parentSessionKey`; that can turn direct-session ancestry into artificial subagent depth. The report has a source-reproducible P1 path, but no current-main interactive run was performed in this read-only review.

## What This Changes

Fix direct `/new` session rollover so ordinary `parentSessionKey` ancestry does not consume `sessions_spawn` subagent depth.

## Best Possible Solution

Keep `parentSessionKey` for session lineage, but make depth resolution follow it only for entries positively identified as subagent children; add regression coverage showing repeated direct TUI and WebChat `/new` sessions remain depth 0 and can spawn a first-level child at `maxSpawnDepth: 1`.
