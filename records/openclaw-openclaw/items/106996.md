## Summary

Keep this issue open for a maintainer product-contract decision. Current main intentionally drops Telegram controls whose callback data exceeds the channel limit and preserves readable fallback text, but the successful outbound result does not disclose that the requested interaction was degraded; that is materially unsafe for approval workflows.

## What This Changes

Report that Telegram inline controls with callback data over 64 bytes are omitted while fallback text delivery still reports success.

## Best Possible Solution

Add a shared machine-readable partial-delivery result that identifies omitted presentation controls while preserving readable fallback text; reserve hard failure for an explicit required-interaction contract if maintainers decide one is needed.
