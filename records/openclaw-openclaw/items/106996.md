## Label Justifications

- `P1`: A deterministic Telegram workflow can silently lose approval controls while reporting success, directly breaking active agent-to-user workflows.
- `impact:message-loss`: The requested interactive control is suppressed in delivery without a caller-visible loss or degradation signal.

## Summary

Keep this issue open for a maintainer product-contract decision. Current main intentionally removes controls that exceed channel limits and delivers their labels as non-interactive fallback text, but the successful outbound result does not tell the caller that the requested interaction was degraded; that gap is material for approval workflows. citeturn920646view0turn601695view1

## What This Changes

Add caller-visible handling when Telegram inline-keyboard callback data exceeds the channel limit instead of silently reporting an apparently complete text-only send.

## Best Possible Solution

Keep safe text fallback, but make presentation adaptation return typed degradation details and propagate them through the message-tool result and diagnostics, with regression coverage for Telegram byte-limit removal and at least one sibling capability-limit path.

## Maintainer Decision

Required: true

Kind: product_direction

Question: When requested presentation controls are removed by channel limits, should the message tool return successful delivery plus structured degradation details, or fail the entire send?

Rationale: Both outcomes are defensible but define different public delivery semantics: preserving useful fallback text favors partial success, while fail-closed behavior favors strict interaction guarantees and may suppress valid text.

Likely owner: steipete

Owner reason: This choice changes the shared message-tool delivery contract across channel implementations, so repository-level product ownership is the best available routing point.

Owner confidence: low

Options:

- **Return structured degradation (recommended):** Deliver the safe fallback text but include machine-readable removed-control reasons so the agent can warn, retry, or choose a shorter action value.
- **Fail the whole send:** Reject any send whose requested controls cannot be represented, guaranteeing all-or-nothing presentation at the cost of losing otherwise deliverable text.
- **Keep silent best effort:** Continue reporting only the successful text delivery, accepting that callers cannot detect missing interaction controls.

## Reproduction Assessment

Yes at source level: a control value above Telegram's byte limit is filtered by presentation capability adaptation, after which the fallback text follows the normal successful send path. A live current-main Telegram run was not independently performed.

## Solution Assessment

No, unconditionally failing the entire message is not clearly the best solution because current behavior deliberately preserves useful fallback text. A typed partial-delivery result is the narrower cross-channel solution, subject to maintainer confirmation of the public contract.
