## Label Justifications

- `P1`: A deterministic Telegram workflow can report success while silently omitting approval controls the agent intended to deliver.
- `impact:message-loss`: The interactive portion of the outbound message is suppressed while its text fallback is delivered and reported successful.

## Summary

Current main appears to reproduce the reported outcome by design: presentation controls exceeding channel limits are removed and rendered as non-interactive fallback text, while the outbound result reports the successful text delivery. The safety concern is valid, but changing that contract requires deciding whether partial presentation should return structured degradation details or fail the entire send.

## What This Changes

Surface partial-delivery information when Telegram inline-keyboard callback data exceeds the platform’s 64-byte limit instead of returning an unqualified successful text-only result.

## Best Possible Solution

Keep safe text fallback, but return structured partial-delivery details identifying each removed control and its limit violation so callers can retry or stop safety-gated workflows.
