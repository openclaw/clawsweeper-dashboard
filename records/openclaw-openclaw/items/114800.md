## What This Changes

Preserve an active execution-backed Workboard session when a user edits unrelated fields on its running card.

## System Context

The Control UI edits Workboard cards through the Gateway, which forwards a patch to the Workboard plugin store. The card’s resolved session link feeds the active-thread selector and must remain intact when unrelated card fields are saved.

## Architecture Diagram

flowchart LR
  A[Running Workboard card] --> B[Control UI edit dialog]
  B --> C[Resolve active session]
  C --> D[Build update patch]
  D --> E[Gateway request]
  E --> F[Workboard plugin store]
  F --> G[Card and execution session link]

## Best Possible Solution

Use the canonical Workboard session resolver when opening the edit dialog and omit `sessionKey` from an unrelated update unless the user explicitly changes the linked thread; add focused UI-to-store regression coverage for execution-only links and explicit unlinking.
