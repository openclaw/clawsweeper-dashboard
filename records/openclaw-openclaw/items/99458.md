## Summary

Keep open: current `main` and the latest release still reject root-level `paperclip` on `agent` params, while the related fix PRs are closed unmerged and no open canonical replacement exists.

## What This Changes

The issue asks OpenClaw Gateway to accept Paperclip adapter metadata in agent params instead of rejecting payloads with an unexpected root-level `paperclip` field.

## Best Possible Solution

Land one additive gateway protocol change in `packages/gateway-protocol` that preserves strict validation for unrelated typos, accepts the chosen metadata shape, updates generated schema/Swift artifacts, and adds focused validator plus handler coverage.

## Reproduction Assessment

Yes, source-level: current `main` validates `agent` params through a strict schema that lacks `paperclip` or `adapterMeta`, and the handler returns the reported `invalid agent params` error before dispatch. I did not run a live Paperclip heartbeat in this read-only review.

## Solution Assessment

Unclear. The bug is real, but the best permanent fix needs maintainer agreement on whether to accept the existing root-level `paperclip` field, introduce a generic metadata namespace, or coordinate a Paperclip-side payload move.
