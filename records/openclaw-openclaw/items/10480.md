## Summary

Keep open: current main and v2026.6.11 still lack a Workers AI model or endpoint selector for the Cloudflare AI Gateway non-interactive onboarding path, and the related broader Cloudflare bridge issues do not replace this onboarding-specific request.

## What This Changes

Add Cloudflare Workers AI model or endpoint selection to `openclaw onboard --non-interactive --auth-choice cloudflare-ai-gateway-api-key`.

## Best Possible Solution

Define a Cloudflare plugin-owned Workers AI endpoint/model-selection contract that generates `@cf/...` OpenAI-compatible provider config while preserving or explicitly migrating the existing Anthropic Gateway behavior.

## Reproduction Assessment

Yes, at source level: the Cloudflare non-interactive auth choice has no Workers AI model or endpoint option and always applies the Anthropic provider config. I did not run a credentialed Cloudflare onboard flow in this read-only review.

## Solution Assessment

Unclear. The user need is valid, but maintainers need to choose between a first-class Workers AI mode, the broader Cloudflare REST bridge, or documenting the generic custom-provider workflow as the supported path.
