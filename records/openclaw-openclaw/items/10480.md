## Summary

Current main still cannot generate a Workers AI model configuration through the Cloudflare non-interactive auth choice, and the broader Cloudflare gateway issue explicitly treats this as a distinct onboarding slice. The issue remains necessary, but implementation should wait for a maintainer decision on the permanent Cloudflare endpoint/model contract.

## What This Changes

Add non-interactive Cloudflare onboarding support for selecting Workers AI endpoints and `@cf/...` models instead of always generating the fixed Anthropic/Claude configuration.

## Best Possible Solution

Define a plugin-owned Cloudflare endpoint/model mode shared with the broader REST gateway design, then generate the appropriate OpenAI-compatible Workers AI provider, selected `@cf/...` model, defaults, docs, upgrade behavior, and focused tests.

## Reproduction Assessment

Yes, at source level. Current main accepts only Cloudflare account ID, gateway ID, and key for this auth choice, then generates a fixed Anthropic endpoint and Claude model with no Workers AI selector.

## Solution Assessment

No, the proposed generic model flag is not sufficient by itself because it does not define the required endpoint, protocol, credential/header, catalog, and compatibility behavior. A plugin-owned endpoint/model mode aligned with the broader Cloudflare contract is the safer solution.
