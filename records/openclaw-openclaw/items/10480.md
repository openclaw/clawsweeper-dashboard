## Summary

Keep open: current main and the latest release still route Cloudflare AI Gateway onboarding to an Anthropic passthrough with one Claude default, with no Workers AI endpoint or `@cf/...` model selector. The broader Cloudflare bridge and REST issues overlap, but they do not replace this issue's non-interactive onboarding acceptance criteria.

## What This Changes

The issue requests Cloudflare Workers AI model selection during `openclaw onboard --non-interactive --auth-choice cloudflare-ai-gateway-api-key`.

## Best Possible Solution

Define a provider-owned Cloudflare endpoint-family and model-selection contract that can generate Workers AI `@cf/...` config while preserving existing Anthropic Gateway behavior, then update docs and focused onboarding tests.

## Reproduction Assessment

Yes. Source inspection shows `openclaw onboard --non-interactive --auth-choice cloudflare-ai-gateway-api-key` has no Workers AI model or endpoint option and always applies the Anthropic provider config.

## Solution Assessment

Unclear. The user need is valid, but maintainers need to choose whether the durable path is a first-class Workers AI mode, the broader Cloudflare REST bridge, or a documented custom-provider workflow.
