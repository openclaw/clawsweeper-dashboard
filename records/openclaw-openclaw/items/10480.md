## Label Justifications

- `P2`: This is a well-defined provider onboarding improvement with meaningful but limited Cloudflare-specific impact and a manual configuration workaround.
- `impact:auth-provider`: The missing path concerns provider selection, endpoint generation, credentials, and model routing during Cloudflare authentication setup.

- `maturity:stable`: The affected CLI onboarding and authentication setup area belongs to the M4 Stable CLI surface.

## Summary

Current main still limits the Cloudflare AI Gateway onboarding path to its Anthropic model and endpoint, so Workers AI selection remains necessary. The broader Cloudflare bridge and REST issues share the root limitation but do not yet provide a merged implementation or clearly replace this concrete onboarding requirement.

## What This Changes

Add a supported non-interactive onboarding path that configures and selects Cloudflare Workers AI models through Cloudflare AI Gateway.

## Best Possible Solution

Add an explicit, additive Cloudflare provider mode in `extensions/cloudflare-ai-gateway` that preserves existing Anthropic setups while generating the chosen current Cloudflare API endpoint, protocol, authentication, model IDs, and catalog metadata for Workers AI; document and test both fresh onboarding and upgrades.
