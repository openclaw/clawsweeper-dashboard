## Summary

Keep open: current main and v2026.6.11 still lack Workers AI model or endpoint selection for the Cloudflare AI Gateway non-interactive auth choice. The related Cloudflare bridge and REST issues overlap, but they do not replace this onboarding-specific acceptance criterion, and the remaining fix needs maintainer product direction.

## What This Changes

Add a way for `openclaw onboard --non-interactive --auth-choice cloudflare-ai-gateway-api-key` to select or generate Cloudflare Workers AI `@cf/...` model configuration.

## Best Possible Solution

Define a Cloudflare plugin-owned endpoint-family and model-selection contract that can generate Workers AI `@cf/...` config while preserving current Anthropic Gateway behavior, then update onboarding docs and focused tests.

## Reproduction Assessment

Yes, at source level: the Cloudflare non-interactive auth choice has no Workers AI model or endpoint option and always applies the Anthropic provider config. I did not run a credentialed Cloudflare onboard flow in this read-only review.

## Solution Assessment

Unclear. The user need is valid, but maintainers need to choose between a first-class Workers AI mode, the broader Cloudflare REST bridge, or documenting the generic custom-provider workflow as the supported path.
