## Summary

Keep open: current main and v2026.6.11 still lack Workers AI model or endpoint selection for the Cloudflare AI Gateway non-interactive onboarding path, and the remaining work needs maintainer product direction across provider setup, model routing, and Cloudflare endpoint semantics.

## What This Changes

The issue requests Workers AI model selection during `openclaw onboard --non-interactive --auth-choice cloudflare-ai-gateway-api-key`.

## Best Possible Solution

Define a provider-owned Cloudflare endpoint-family and model-selection contract that can generate Workers AI `@cf/...` config while preserving current Anthropic Gateway behavior, then update docs and focused onboarding tests.

## Reproduction Assessment

Yes, at source level: the Cloudflare non-interactive auth choice has no Workers AI model or endpoint option and always applies the Anthropic provider config. I did not run a credentialed Cloudflare onboard flow in this read-only review.

## Solution Assessment

Unclear. The user need is valid, but maintainers need to choose whether the best path is a first-class Workers AI mode, the broader Cloudflare REST bridge, or a documented custom-provider workflow.
