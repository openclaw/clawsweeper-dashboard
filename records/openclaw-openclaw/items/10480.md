## Summary

Keep open: current main and the latest release still route the Cloudflare AI Gateway onboarding flow to the Anthropic passthrough with one Claude default, with no Workers AI endpoint or `@cf/...` model selector. The broader Cloudflare bridge and REST issues overlap, but they do not replace this issue's non-interactive onboarding acceptance criteria.

## What This Changes

Add a supported way for non-interactive Cloudflare AI Gateway onboarding to choose Workers AI `@cf/...` models or an endpoint/provider mode instead of the hardcoded Anthropic default.

## Best Possible Solution

Define a provider-owned Cloudflare endpoint-family and model-selection contract that can generate Workers AI `@cf/...` config while preserving current Anthropic Gateway behavior, then update docs and focused onboarding tests.

Yes. Source inspection shows the Cloudflare non-interactive auth choice has no Workers AI model or endpoint option and always applies the Anthropic provider config; I did not run a credentialed Cloudflare onboarding flow in this read-only review.

## Solution Assessment
