## Summary

Keep open: current main and v2026.6.11 still configure the Cloudflare AI Gateway onboarding path as an Anthropic passthrough with one Claude default, while Workers AI model selection remains missing and product-sensitive.

## What This Changes

The issue requests selecting Cloudflare Workers AI `@cf/...` models during non-interactive Cloudflare AI Gateway onboarding instead of accepting the bundled provider default.

## Best Possible Solution

Define the Cloudflare AI Gateway provider-owned bridge/onboarding contract, then either implement Workers AI endpoint/model selection with docs and tests or document the exact custom-provider path as the supported alternative.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should bundled Cloudflare AI Gateway onboarding own a Workers AI endpoint/model selector, or should Workers AI remain a documented custom-provider setup until the broader Cloudflare bridge is designed?

Rationale: The fix changes provider-owned onboarding, model-choice UX, generated config shape, endpoint/auth semantics, and overlap with the broader Cloudflare bridge issues, so automation should not choose the permanent product contract.

Likely owner: steipete

Owner reason: Peter Steinberger introduced the provider setup and did the plugin-boundary refactors most relevant to choosing the owner boundary.

Owner confidence: medium

Options:

- **Fold Into Cloudflare Bridge (recommended):** Use https://github.com/openclaw/openclaw/issues/94554 as the canonical design and keep this issue as the onboarding acceptance criterion for Workers AI support.
- **Add Narrow Workers AI Mode:** Add a provider-owned non-interactive endpoint/model mode that generates `/workers-ai/v1` OpenAI-compatible config for explicit `@cf/...` models without solving the full bridge first.
- **Document Custom Provider Path:** Publish an exact supported `custom-api-key` command/config for Workers AI and close this once the bundled Cloudflare auth choice is intentionally scoped to Anthropic passthrough.

Yes, at source level: current main exposes only Cloudflare account/gateway/API-key inputs and writes an Anthropic Messages provider with one Claude default. I did not run a credentialed Cloudflare request in this read-only review.

## Solution Assessment

Unclear. The requested Workers AI onboarding support is valid, but the best fix depends on whether maintainers want a narrow Workers AI mode, a broader Cloudflare bridge, or a documented custom-provider path.
