## Summary

Keep open: current main and the latest release still trust the persisted Dashboard session row when listing and loading history, so a corrupted Dashboard key to sessionId mapping can still misroute preserved history. The remaining fix needs maintainer policy because automatic relinking from orphan transcript or trajectory evidence could attach a key to the wrong historical content.

## Best Possible Solution
