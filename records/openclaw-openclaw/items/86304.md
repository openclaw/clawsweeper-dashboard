## Summary

Keep open: current main and v2026.6.11 still trust the stored Dashboard/session row, so a corrupted dashboard key to sessionId mapping can still list and load the wrong preserved history. The remaining work needs maintainer-approved repair policy because automatic relinking from orphan trajectory files could attach a Dashboard row to the wrong transcript.

## What This Changes

The issue reports that after upgrading, Dashboard history rows can map a dashboard key to the wrong sessionId while the original trajectory JSONL remains on disk.

## Best Possible Solution

Add a maintainer-approved doctor or diagnostic repair that validates corrupted Dashboard mappings against session-store metadata and transcript/trajectory evidence, refuses ambiguous relinks, and keeps runtime readers on canonical store rows.
