## Summary

Keep open: current main still projects Dashboard history through the stored `sessions.json` row, so a bad Dashboard key to `sessionId` mapping can still list and load the wrong preserved history. The remaining work needs maintainer direction because repairing persisted history automatically could attach a key to the wrong transcript or trajectory file.

## What This Changes

A user reports that after upgrade, a Dashboard history key maps to the wrong session id in `sessions.json`, so the UI opens mismatched preserved history.

## Best Possible Solution

Add a maintainer-approved doctor diagnostic or repair that validates corrupted Dashboard mappings against store metadata, transcript headers, trajectory evidence, and redacted fixtures, and refuses ambiguous relinks.
