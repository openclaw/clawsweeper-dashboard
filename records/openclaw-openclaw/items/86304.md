## Summary

Keep open: current main and the latest release still trust the persisted Dashboard session row when listing and loading history, so the reported corrupted Dashboard key to sessionId mapping can still misroute preserved history.

## What This Changes

The issue reports that after upgrade, Dashboard history can show a preserved old session under the wrong sessionId mapping in sessions.json.

## Best Possible Solution

Add a maintainer-approved diagnostic or doctor repair that validates corrupted Dashboard mappings against store metadata and transcript evidence, and refuses ambiguous relinks.
