## Summary

Keep open: current main still projects and loads Dashboard history from the stored session row, so a corrupted Dashboard key to sessionId mapping can still misroute preserved history. A repair needs maintainer policy because heuristic relinking from preserved transcript or trajectory files could attach a Dashboard entry to the wrong private history.

## Best Possible Solution

Add a maintainer-approved diagnostic or doctor repair that validates corrupted Dashboard mappings against store metadata, transcript headers, trajectory evidence, and redacted fixtures, and refuses ambiguous relinks.
