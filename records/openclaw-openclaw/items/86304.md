## Summary

Keep open: current main still projects Dashboard history from the stored session row, so an upgraded Dashboard key that already points at the wrong sessionId will list and load the wrong preserved history; the merged orphan-key migration and open family-history work do not repair this already-canonical bad mapping.

## What This Changes

The issue asks OpenClaw to repair or prevent upgraded Dashboard history rows whose stored Dashboard key points at the wrong sessionId while the original trajectory remains on disk.

## Best Possible Solution

Add a maintainer-approved diagnostic or doctor repair that validates corrupted Dashboard mappings against store metadata, transcript headers, trajectory evidence, and redacted fixtures, and refuses ambiguous relinks.
