## Summary

Keep open: current main and the latest release still trust the persisted Dashboard session row when listing and loading history, so a corrupted dashboard key to sessionId mapping can still misroute preserved history. A repair needs maintainer policy because automatic relinking from preserved transcript or trajectory evidence could attach a key to the wrong historical content.

## What This Changes

The issue reports that after an upgrade, a Dashboard history key can point at the wrong sessionId in sessions.json while the original trajectory file remains on disk.

## Best Possible Solution

Add a maintainer-approved diagnostic or doctor repair that validates corrupted Dashboard mappings against store metadata, transcript headers, trajectory evidence, and redacted fixtures, and refuses ambiguous relinks.
