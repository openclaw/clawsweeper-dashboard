## Summary

Keep open: current main and the latest release still trust the stored Dashboard session row when listing and loading history, so a corrupted Dashboard key to session id mapping can still route users to the wrong preserved transcript. The remaining fix needs maintainer policy because automatic relinking could attach a Dashboard key to the wrong orphaned transcript or trajectory file.

## What This Changes

The issue reports an upgrade regression where a Dashboard history key points to the wrong stored session id while the intended trajectory file remains on disk.

## Best Possible Solution

Add a maintainer-approved diagnostic or doctor repair that backs up the store, validates corrupted Dashboard mappings against unambiguous metadata/header/trajectory evidence, refuses ambiguous relinks, and is covered by a redacted upgrade fixture.
