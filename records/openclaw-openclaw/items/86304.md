## Summary

Keep open: current main and the latest release still trust the persisted Dashboard session row, so a corrupted Dashboard key to sessionId mapping can still list and load the wrong preserved history. The remaining work needs maintainer policy because automatic relinking from orphan transcript or trajectory evidence can attach a key to the wrong historical content.

## What This Changes

The issue reports that after upgrade, Dashboard history rows can point a preserved Dashboard key at the wrong sessionId even though the original trajectory file remains on disk.

## Best Possible Solution

Add a maintainer-approved diagnostic or doctor repair that validates corrupted Dashboard mappings against store metadata, transcript headers, trajectory evidence, and redacted fixtures, and refuses ambiguous relinks.
