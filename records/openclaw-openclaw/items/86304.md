## Summary

Keep open: current main and the latest release still route Dashboard history through the persisted session row, so a corrupted Dashboard key to sessionId mapping can still load the wrong preserved history; no merged related item directly repairs this wrong-mapping case.

## What This Changes

The issue asks OpenClaw to preserve or repair Dashboard history mappings after upgrade so old Dashboard keys load the correct stored session/trajectory content.

## Best Possible Solution

Add a maintainer-approved doctor/diagnostic repair that validates corrupted Dashboard mappings against store metadata, transcript headers, trajectory evidence, and redacted fixtures, then refuses ambiguous relinks.
