## Summary

Keep open: current main still trusts the stored Dashboard session row, so a canonical Dashboard key whose `sessions.json` entry points at the wrong `sessionId` can still list and load the wrong preserved history. The remaining fix needs maintainer-approved repair policy and a redacted fixture because automatic relinking could attach the key to the wrong transcript or trajectory file.

## What This Changes

The issue reports that after upgrading, Dashboard history rows can point a preserved dashboard key at the wrong session id, so clicking the historical session loads the wrong transcript even though the original trajectory file remains on disk.

## Best Possible Solution

Add a maintainer-approved doctor or diagnostic repair that validates corrupted Dashboard mappings against session-store metadata and transcript/trajectory evidence, refuses ambiguous relinks, and keeps runtime readers on canonical store rows.
