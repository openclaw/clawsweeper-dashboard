## Summary

Keep open: current main still trusts the stored Dashboard session row, so a corrupted `sessions.json` dashboard key can still list and load the wrong preserved history. The related merged fixes cover orphan-key canonicalization and transcript reader identity, but they do not provide a safe repair policy for relinking a Dashboard key to an orphan transcript or trajectory file.

## What This Changes

The issue reports an upgrade regression where Dashboard history can map a dashboard session key to the wrong `sessionId` while the original trajectory file remains on disk.

## Best Possible Solution

Add a maintainer-approved diagnostic or doctor repair that validates corrupted Dashboard mappings against store metadata, transcript headers, trajectory evidence, and redacted fixtures, and refuses ambiguous relinks.
