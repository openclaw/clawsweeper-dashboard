## Summary

Issue #86304 should remain open: current `main` still follows the Dashboard session row stored in `sessions.json`, so a canonical Dashboard key that already points at the wrong `sessionId` can still list and open the wrong preserved history; the merged session-key and transcript-reader work only covers adjacent identity/key cases, not safe repair of a corrupted canonical mapping.

## What This Changes

The issue asks OpenClaw to recover or prevent Dashboard history mappings becoming wrong after upgrade when the stored Dashboard session key points at a different session transcript than the preserved trajectory/history file.

## Best Possible Solution

Add a maintainer-approved doctor or migration diagnostic that verifies corrupted Dashboard rows against transcript headers, `sessionFile` metadata, trajectory evidence, and a redacted fixture, then refuses ambiguous relinks.
