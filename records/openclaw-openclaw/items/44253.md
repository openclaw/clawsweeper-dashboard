## Summary

Keep open: current main and the latest checked release still lack a self-deny or delegate-only tool policy, while existing code and docs deliberately treat inherited tool policy as non-escalating. The request is useful and source-reproducible, but it adds a new config/API surface and changes delegated command/file authorization semantics, so it needs maintainer product and security review before implementation.

## What This Changes

Request an optional per-agent tool policy that hides selected tools from an orchestrator's own model surface while allowing them to remain available to spawned subagents.

## Best Possible Solution

Design a maintainer-approved delegate-only policy that keeps ordinary deny absolute, removes selected tools only from the parent model surface, and makes delegated child access explicit, audited, documented, and covered across native, ACP, gateway, and upgrade tests.
