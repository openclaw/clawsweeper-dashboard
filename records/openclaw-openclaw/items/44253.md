## Summary

Keep open: current main and v2026.6.11 still lack a delegate-only/self-deny tool policy, and adjacent `toolsAllow` work only narrows child tools rather than hiding tools from the requester while preserving delegation.

## What This Changes

Request to add optional per-agent `tools.selfDeny` or delegate-only config so an agent can delegate tools to subagents without receiving those tools in its own model tool list.

## Best Possible Solution

Keep this as the canonical design issue, then implement an additive delegate-only contract after maintainers choose the API name, deny-wins semantics, schema/docs updates, migration posture, and focused policy tests.
