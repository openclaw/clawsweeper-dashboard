## Label Justifications

- `P2`: This is a bounded but security-sensitive multi-agent permissions enhancement with real operator impact, not an active outage or emergency bypass.
- `impact:security`: The issue changes command and file-tool authorization boundaries between an orchestrator/requester and delegated child sessions.

## Summary

Keep open: current main still has no `selfDeny`, `delegateOnly`, or equivalent parent-self-only deny policy, and the existing schema, runtime policy pipeline, docs, and tests continue to make parent restrictions constrain delegated child sessions. The request is valid and security-relevant, but it adds a new config/API authorization semantic for command and file tools, so it needs maintainer product and security direction before implementation.

## What This Changes

The issue requests a per-agent tool policy surface that hides selected tools from an agent's own model-visible tool list while still allowing delegated subagents to receive those tools.

## Best Possible Solution

Design a maintainer-approved delegate-only policy that keeps ordinary deny absolute, removes selected tools only from the parent model surface, and makes delegated child access explicit, audited, documented, and covered by native, ACP, gateway, and upgrade tests.

Options:

- **Keep monotonic inheritance only:** Reject parent-self-only exceptions and keep the current rule that child sessions can only receive equal or fewer capabilities than the requester.
- **Defer to broader tool-policy redesign:** Hold this issue until maintainers design a unified delegated tool-policy model covering per-agent, per-spawn, ACP, gateway, and audit semantics together.

## Reproduction Assessment

Yes, at source level. Current main has no parent-self-only deny/delegate-only config key, and the existing schema, policy resolver, docs, and tests make ordinary parent restrictions flow into child sessions.

## Solution Assessment

Unclear. `selfDeny` is a plausible shape, but the best fix needs maintainer-approved syntax, deny-wins semantics, audit behavior, and native/ACP/gateway inheritance coverage before implementation.
