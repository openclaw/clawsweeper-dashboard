## Summary

Keep open: current main and v2026.6.11 still lack a delegate-only/self-deny config path, and current source/docs preserve monotonic tool filtering where earlier restrictions shape child inherited policy. This is a valid security-boundary feature, but it needs maintainer product/security direction before implementation.

## What This Changes

Add a per-agent delegate-only/self-deny tool policy so a requester can hide tools like exec/write/edit from its own model while allowing eligible subagents to inherit them.

## Best Possible Solution

Keep this as the canonical design issue and implement one additive delegate-only contract after maintainers choose API naming, deny-wins semantics, schema/docs updates, and regression proof.
