## Summary

Keep open: current main and the latest release still do not provide a `selfDeny`, `delegateOnly`, or equivalent parent-hidden/child-inherited tool policy, and the recent peer-mesh comment shows the separation-of-duties need is still active. The related `toolsAllow` PR narrows child tools per spawn, but it is open/conflicting and does not give a parent agent a hidden delegate-only tool pool.

## What This Changes

Request to add a per-agent delegate-only tool policy so an agent can hide tools from its own model surface while preserving them for spawned subagents.

## Best Possible Solution

Add a documented runtime-enforced delegate-only policy, or an equivalent integrated delegated-tool design, with absolute deny precedence, clear diagnostics, and tests covering parent-visible tools, child-inherited tools, ACP/CLI behavior, and existing config compatibility.
