## Summary

Keep open: current main and v2026.6.11 still lack a `tools.selfDeny`/delegate-only policy, and this issue remains the canonical security/product design thread for hiding tools from a requester while allowing controlled subagent inheritance.

## What This Changes

Request to add a per-agent `tools.selfDeny` or delegate-only tool policy so orchestrators can hide dangerous tools from their own model surface while still allowing subagents to inherit them.

## Best Possible Solution

Keep this as the canonical design issue and choose an additive delegate-only/self-deny contract that preserves deny-wins, aligns with per-spawn `toolsAllow`, and updates schema, docs, and focused policy tests after maintainer approval.
