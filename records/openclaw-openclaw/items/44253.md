## Summary

Keep open: current main and v2026.6.11 still lack a `tools.selfDeny` or equivalent delegate-only policy, and the newer peer-mesh comment shows the separation-of-duties need is still active. The related `toolsAllow` work narrows child tools, but it does not solve the requested parent-hidden/child-inherited tool boundary.

## What This Changes

Requests a per-agent delegate-only tool policy so an agent can pass tools to subagents while being runtime-blocked from using those tools itself.

## Best Possible Solution

Add a documented runtime-enforced delegate-only policy, or an equivalent delegated-tool access design, with explicit deny precedence and tests for parent-visible tools, child-inherited tools, ACP/CLI behavior, and current config compatibility.
