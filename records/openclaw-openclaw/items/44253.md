## Summary

Keep open: current main and the latest release still lack `selfDeny`, `delegateOnly`, or an equivalent parent-self-only deny surface. The request remains source-reproducible, but it changes command/file tool authorization semantics and needs maintainer product and security review before implementation.

## What This Changes

Requested `agents.list[].tools.selfDeny` or an equivalent delegate-only tool policy so an orchestrator can withhold tools from its own model surface while still allowing subagents to inherit them.

## Best Possible Solution

Design a maintainer-approved delegate-only policy that keeps ordinary `deny` absolute, removes selected tools only from the parent model surface, and makes delegated child access explicit, audited, documented, and covered by native/ACP/gateway tests.

## Reproduction Assessment

Yes, at source level: current main still has ordinary allow/deny/subagent inherited policy but no self-only deny or delegate-only config key. I did not run a live multi-agent scenario in this read-only cleanup review.

## Solution Assessment

Unclear. `selfDeny` is a plausible shape, but the best fix needs maintainer-approved syntax, deny-wins semantics, audit behavior, and native/ACP/gateway inheritance coverage before implementation.
