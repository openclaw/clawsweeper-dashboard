## Summary

Keep open: current main and v2026.6.11 still lack `selfDeny`, `delegateOnly`, or equivalent parent-self-only tool denial. The newer peer-mesh comment reinforces the same security boundary, but the change adds config/API semantics for delegated command and file tools, so it needs maintainer product and security review before implementation.

## What This Changes

Add per-agent delegate-only tool policy so an agent can hide tools such as `exec`, `write`, and `edit` from its own model surface while still allowing explicitly delegated subagents to inherit them.

## Best Possible Solution

Design a maintainer-approved delegate-only policy that keeps ordinary `deny` absolute, removes selected tools only from the parent model surface, and makes child access explicit, audited, documented, and covered across native, ACP, gateway, release-upgrade, and docs paths.
