## Summary

Keep open: current main still lacks a delegate-only/self-deny tool policy, while the existing inherited allow/deny pipeline proves the requested separation-of-duties gap remains a security-sensitive config/API decision.

## What This Changes

The issue requests a per-agent delegate-only tool policy such as `tools.selfDeny` so an agent can pass tools to subagents while being denied direct use itself.

## Best Possible Solution

Keep this as the canonical design issue and implement one additive delegate-only contract after maintainers choose the public API name, deny-wins semantics, runtime/ACP behavior, schema/docs updates, and regression proof.
