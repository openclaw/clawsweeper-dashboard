## Summary

Keep open: current main still lacks `selfDeny`, `delegateOnly`, or an equivalent parent-self-only deny surface, and the remaining work is a security-sensitive product/config decision rather than a narrow bug fix.

## What This Changes

The issue requests a per-agent tool policy option that hides selected tools from an orchestrator agent while still allowing explicitly delegated subagents to receive them.

## Best Possible Solution

Design a maintainer-approved delegate-only policy that keeps ordinary `deny` absolute, hides selected tools only from the parent model surface, and makes child access explicit, audited, documented, and tested across native and ACP delegation.

## Reproduction Assessment

Yes. Source inspection shows current main rejects the requested config shape and still applies ordinary parent allow/deny restrictions to spawned child sessions through inherited tool policy.

## Solution Assessment

Unclear. `selfDeny` is a plausible shape, but the best fix needs maintainer-approved syntax, deny-wins semantics, audit behavior, and cross-runtime coverage before implementation.
