## Summary

Keep open: current main still lacks `selfDeny`, `delegateOnly`, or any equivalent parent-self-only deny surface, and the existing schema and policy pipeline still treat parent allow/deny policy as inherited child-session authorization. The request is useful and source-reproducible, but it changes security-sensitive tool delegation semantics and needs maintainer product/security direction before implementation.

## What This Changes

Request to add a per-agent `tools.selfDeny` or delegate-only policy so an orchestrator can hide command/file tools from its own model surface while explicitly allowing delegated subagents to use them.

## Best Possible Solution

Design a maintainer-approved delegate-only policy that keeps ordinary `deny` absolute, hides selected tools from the parent model surface, and makes delegated child access explicit, audited, documented, and covered across native, ACP, gateway, upgrade, and regression tests.
