## Summary

Keep open: current main and v2026.6.11 retain a deterministic request-lifetime race that can dispatch dangerous node work after the caller reports timeout or cancellation. The issue is canonical, assigned, security-sensitive, and requires explicit Gateway/security owner approval for the cancellation authority contract.

## What This Changes

Prevent pending plugin-owned node approvals from dispatching after the originating Gateway caller times out, aborts, or disconnects.

## Best Possible Solution

Add an advertised Gateway cancellation capability, retain connection-owned request state on the server, propagate its AbortSignal through plugin approval handling, and atomically claim effecting state immediately before nodeRegistry.invoke.

## Reproduction Assessment

Yes. Hold a dangerous plugin node approval beyond the ordinary 30-second Gateway client timeout, then allow it before the 120-second approval expiry; current main continues through the detached server handler into node dispatch.

## Solution Assessment

Yes in architectural direction: generic, additive Gateway cancellation with one server-owned state machine is the narrowest maintainable fix. Client-only waiter cleanup or a file-transfer-specific abort check would preserve competing request lifetimes and leave sibling plugin policies exposed.
