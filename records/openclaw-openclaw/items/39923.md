## Summary

Keep open: current main still uses the numbered config backup ring, and the open linked implementation PR is the active place to resolve the datetime-suffix behavior and migration policy before this issue can close.

## What This Changes

The issue requests replacing numbered config backup rotation with timestamped backup filenames so recovery can identify backup age without checking file metadata.

## Best Possible Solution

Land or replace the linked implementation with a migration-safe config-backup change that preserves recoverable legacy backups, enforces the same cap, updates permission hardening, and proves upgrade behavior.

Options:

- **Preserve legacy backups during migration (recommended):** Keep .bak.1-.bak.4 as valid legacy recovery files until the cap can be enforced without silently deleting the only known-good backup.
- **Prune legacy backups on first maintenance:** Treat numbered backups as obsolete orphans and rely on the new timestamped set going forward, accepting the upgrade recovery risk.
- **Defer naming change:** Keep numeric rotation until a broader backup-location and retention design is decided with https://github.com/openclaw/openclaw/issues/20460.

## Solution Assessment

Unclear until the migration policy is decided; timestamped names are a maintainable direction, but the best fix must explicitly handle legacy numbered backups rather than deleting recoverable config history by accident.
