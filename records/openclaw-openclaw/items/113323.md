## Summary

Keep this issue open for maintainer diagnosis. The supplied diagnostic was emitted five seconds before the abort but reports `lastProgressAge=117s`, so it does not itself prove OpenClaw was receiving reasoning chunks immediately before the 120-second watchdog fired; however, the report is current, detailed, and describes an affected local OpenAI-compatible provider route whose configured timeout may not be reaching the actual stream path.

## What This Changes

The issue requests that an active reasoning-token stream from a local OpenAI-compatible model count as model activity so the agent idle watchdog does not abort the run.

## System Context

An agent turn uses the embedded runner to call a configured model provider and consumes its streaming response through an LLM idle watchdog. The watchdog decides whether to keep waiting, fail over, or surface a timeout to the originating channel such as Telegram.

## Architecture Diagram

## Best Possible Solution

Trace the OpenAI-compatible reasoning delta from provider parsing through the idle wrapper; count non-empty normalized reasoning or tool-progress chunks as activity if they are currently dropped, otherwise document the provider timeout setting and request a redacted event trace proving received chunks during the final 120 seconds.
