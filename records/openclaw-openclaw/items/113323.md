## Summary

This looks like a current, actionable agent-runtime bug rather than a stale timeout report: the supplied gateway diagnostic records model stream progress shortly before the same run is aborted for 120 seconds of supposed idleness. The related timeout reports describe different failure modes, so no canonical replacement currently owns this reasoning-stream case.

## What This Changes

Fix the model idle watchdog so an OpenAI-compatible local reasoning model that is actively streaming reasoning tokens is not aborted solely because ordinary assistant content has not yet arrived.

## System Context

OpenClaw sends an agent turn through an OpenAI-compatible provider stream, then the agent runtime applies an idle watchdog while it waits for a usable model result. A timeout decision becomes an agent failure and is surfaced through the invoking channel, including Telegram.

## Architecture Diagram

flowchart LR
  A[Agent request] --> B[OpenAI-compatible provider]
  B --> C[Streaming reasoning and content deltas]
  C --> D[Agent stream normalization]
  D --> E[Idle watchdog]

  E -->|idle timeout| G[Surface timeout to channel]

## Best Possible Solution

Make the normalized model stream record validated reasoning, content, and tool-call deltas as progress for the idle watchdog, while retaining timeout coverage for a stream that stops producing usable deltas; add a focused regression test using reasoning-only chunks before content.
