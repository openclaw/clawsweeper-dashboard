## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P2] Load provider status outside the required Usage data promise:** `ui/src/pages/usage/route.ts:62`
  - body: This optional `usage.status` request is still in the same `Promise.all` as the required session and cost requests. Because provider usage fetches can run for the default timeout plus the wrapper timeout, a slow provider can keep the Usage page loading even though the core session/cost data is ready; fetch provider cards independently and render/update them separately.
  - confidence: 0.93
- **[P2] Keep disabled plugins out of usage discovery:** `src/plugins/providers.ts:888-891`
  - body: The enabled-plugin filter is bypassed when `bundledCompatPluginIds` are added back from the include-disabled manifest registry. A bundled provider explicitly disabled in config can still be auto-discovered for usage and polled if credentials exist, so filter this compat path through the same activation decision before returning usage hook contracts.
  - confidence: 0.92
- **[P2] Clear provider cards when operator read access is lost:** `ui/src/pages/usage/usage-page.ts:324`
  - body: After the new `providerUsageSummary` state is populated, the missing-`operator.read` catch path clears session and cost data but leaves provider cards intact. Clear this state with the other operator-read data so a denied refresh cannot keep showing stale plan or billing facts.
  - confidence: 0.9
- **[P2] Canonicalize usage aliases before joining status data:** `src/infra/provider-usage.shared.ts:58`
  - body: Returning arbitrary normalized ids makes stored aliases such as `z-ai` become usage keys, but the Z.ai usage fetch emits snapshots under `zai` and model-auth status joins on `snapshot.provider`. Keep known aliases mapped to their canonical usage provider before allowing custom ids through.
  - confidence: 0.91
- **[P2] Route Usage provider status through the default agent:** `ui/src/pages/usage/route.ts:62`
  - body: Late discovery: this was also visible in the earlier reviewed head. The new Usage page request has no agent/context parameter, and the `usage.status` handler calls `loadProviderUsageSummary()` without the default agent dir; gateways whose default agent stores OAuth/API-key profiles only in the agent-scoped auth store will show empty provider cards even though `models.authStatus` finds the same usage data via `resolveDefaultAgentDir(cfg)`.
  - late: true
  - confidence: 0.91
- **[P2] Remove empty Xiaomi providers from billing discovery:** `extensions/xiaomi/openclaw.plugin.json:132`
  - body: Late discovery: this manifest change was also present in the earlier reviewed head. Declaring Xiaomi usage providers auto-loads hooks that currently return only `windows: []` with no billing, summary, plan, or error, so users with Xiaomi credentials get header-only provider cards/counts instead of useful billing data; leave them undeclared until the hooks return displayable data or an intentional skipped state.
  - late: true
  - confidence: 0.89
