Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P2] Decouple provider usage from Usage page loads:** `ui/src/pages/usage/route.ts:62`
  - body: This optional `usage.status` request is awaited in the same `Promise.all` as required sessions and cost data. The gateway handler waits for provider usage snapshots, whose tasks can run to the default timeout plus one second, so a slow provider can keep the whole Usage page loading even though the session/cost dashboard is ready; fetch provider status separately and update the cards when it resolves.
  - confidence: 0.93
- **[P2] Honor disabled plugins when discovering usage hooks:** `src/plugins/providers.ts:888-891`
  - body: `resolveUsageHookProviderPluginContracts` correctly computes activated usage plugins, but then unions in bundled compat ids resolved from an include-disabled manifest registry. That can re-add an explicitly disabled bundled provider and poll its usage endpoint if credentials exist; filter the compat ids through the same activation check or skip this compat path for usage discovery.
  - confidence: 0.9
- **[P2] Clear provider usage on denied refresh:** `ui/src/pages/usage/usage-page.ts:324`
  - body: After this new state is populated, a later refresh that fails with missing `operator.read` clears session and cost data but leaves `providerUsageSummary` intact. The view renders provider cards alongside the access-denied callout, so clear the provider usage state in the same denied-refresh path.
  - confidence: 0.88
