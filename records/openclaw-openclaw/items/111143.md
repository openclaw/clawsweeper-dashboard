## Summary

This remains a concrete Control UI ergonomics feature: the reported current behavior excludes plugin tabs from the existing pinned-sidebar model, while the related More-discoverability issue addresses a distinct problem. The requested persistence and unavailable-plugin semantics affect a shared core UI surface, so maintainer agreement on the product contract should precede implementation.

## What This Changes

Allow plugin-contributed Control UI tabs to participate in Customize sidebar, persist their pinned order, and avoid duplicating pinned tabs under More.

## Best Possible Solution

Approve a generic serialized plugin-tab sidebar-entry variant keyed by stable plugin and tab identifiers, preserve valid unavailable entries without rendering them, and cover pinning, unpinning, active-state, deduplication, and restoration behavior with focused Control UI tests.
