## Summary

The patch addresses a real yielded-parent lifecycle bug, but the unchanged head still has a P1 fast-child race: if a descendant completes before cron delivery classification, the active count is zero and completed output may never be queried, so a valid handoff is reported as a no-descendant error. The PR also conflicts with current main, mixes in unrelated compatibility carry-alongs, and needs maintainer direction before making `deferred` a permanent public status.

## What This Changes

Adds yielded-parent waiting/deferred semantics across cron delivery and persistence, subagent reconciliation, Discord progress settlement, Gateway protocol, CLI/UI, hooks, Plugin SDK, docs, and adjacent compatibility code.

## Best Possible Solution

Classify yielded parents from durable descendant ownership and aggregate outcome—or always query completed descendant output for yielded runs—then split unrelated carry-alongs, rebase onto current main, and expose a public `deferred` status only if maintainers explicitly accept and document that compatibility contract.
