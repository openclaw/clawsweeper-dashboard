## Summary

The latest head carries a source-message settlement key, but Discord still decides whether to settle from the requester session’s total pending descendants. With overlapping yielded source messages, the first source can be skipped while another source remains active, and no later event consumes the first source’s preserved progress. The PR remains necessary but is not merge-ready; the public `deferred` contract also needs explicit maintainer direction and upgrade proof.

## What This Changes

The PR adds a shared yielded-parent lifecycle classifier, deferred cron status, descendant reconciliation, and source-message-keyed Discord progress settlement across runtime, persistence, protocol, CLI, UI, plugin hooks, and SDK surfaces.

## Best Possible Solution

Count pending descendants by the same yielded source-message ownership key used to register and consume Discord settlement, add an overlapping two-source regression, and keep yielded-parent waiting internal unless maintainers explicitly sponsor the public `deferred` contract with upgrade proof.
