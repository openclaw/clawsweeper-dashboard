## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P1] Reject snapshot directory symlinks before writing:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: `uploadSnapshot` writes under `backup.target/snapshots/<installationId>` through `copyFileAtomic`/`writeFileAtomic`, but those helpers call recursive `mkdir` and then write/rename without rejecting symlinked directory segments inside the backup target. In a shared or synced backup folder, a planted `snapshots` or installation-id symlink can redirect snapshot payload/envelope writes outside the configured backup directory.
  - confidence: 0.89
- **[P1] Check workspace backup roots before mkdir:** `src/commands/workspace-backup.ts:350-351`
  - body: `workspaceBackupRunCommand` creates `backup.target/workspace/mirrors` and `.staging` before proving those target-side paths are real directories, and the later containment check canonicalizes through `realpath`. A symlink under the configured backup target can therefore redirect mirror writes/deletes outside the backup folder before the guard has a chance to reject it.
  - confidence: 0.88
- **[P2] Remove or implement retention config:** `src/config/zod-schema.backup.ts:25`
  - body: The PR accepts `backup.retention` in the public config schema, but the inspected run/list/status/snapshot store paths never prune snapshots or apply those settings. Shipping the key now creates a misleading compatibility contract where users think retention is enforced while snapshots keep accumulating.
  - confidence: 0.82
- **[P2] Restore config when in-state paths differ:** `src/commands/backup-restore.ts:715-721`
  - body: In full-host restore, this condition treats any current config path under the current state dir as covered by the state asset whenever the source config was also state-covered. If the backup used one in-state relative config path and the restore host uses another, replacing state will not create the active config path and restore can report success with stale or missing config.
  - confidence: 0.78
- **[P2] Restore OAuth when in-state paths differ:** `src/commands/backup-restore.ts:741-747`
  - body: The credentials branch uses the same containment-only shortcut as config restore. A backup whose OAuth dir was under state at one relative path restored onto a host using a different in-state OAuth path can skip credentials restoration and leave provider auth missing after a successful full-host restore.
  - confidence: 0.78
