Full review comments:

- **[P1] Reject symlinked snapshot-store parents:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: `fs.mkdir(path.dirname(filePath), { recursive: true })` can follow a symlink planted under the backup target before the payload/envelope write. Validate each existing parent segment under `backup.target` as a real directory before mkdir/rename so a synced folder cannot redirect snapshot writes outside the backup root.
  - confidence: 0.89
- **[P1] Validate restore parents before rollback moves:** `src/commands/backup-restore.ts:443`
  - body: `applyRestoreOperations` moves the existing target to a rollback path before `copySourceToTarget` checks parent path segments. If a restore target parent is symlinked, rollback can move user data outside the intended restore root before the later guard runs.
  - confidence: 0.87
- **[P1] Reject symlinked workspace backup roots before mkdir:** `src/commands/workspace-backup.ts:350-351`
  - body: `workspaceBackupRunCommand` creates `mirrors` and `.staging` before proving those exact target-side paths are not symlinked directories. Check the workspace backup root, mirror root, and staging root parent segments before any mkdir/cp/rm so a cloud-folder attacker cannot redirect writes or stale cleanup.
  - confidence: 0.84
- **[P2] Validate tar entries while writing archives:** `src/infra/backup-create.ts:412-418`
  - body: The export path pre-scans sources, but `tar.c` still trusts entries when they are written. A source can change after the scan, so `onWriteEntry` should reject blocked tar entry types or revalidate entry metadata before remapping it into the archive.
  - confidence: 0.82
- **[P2] Cap archive path depth before parent expansion:** `src/commands/backup-verify.ts:340-343`
  - body: `collectNestedArchiveParents` expands every parent for every normalized entry without a segment-depth cap. A crafted archive with very deep paths can consume excessive CPU/memory during verify/restore even within the total path-byte limit.
  - confidence: 0.8
- **[P2] Compare in-state paths before suppressing restores:** `src/commands/backup-restore.ts:715-716`
  - body: Full-host restore suppresses a standalone config or OAuth restore whenever both source and target are somewhere inside state, but it does not compare their relative paths. If the active in-state config or OAuth path differs from the archived in-state path, restore can report success while leaving the active target stale or missing.
  - confidence: 0.78
