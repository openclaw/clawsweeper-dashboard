Full review comments:

- **[P1] Reject symlinked snapshot-store directories:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: `uploadSnapshot` still writes under `backup.target/snapshots/<installationId>` after `fs.mkdir(..., { recursive: true })` without checking those target-side directory segments. If a synced/shared backup folder contains `snapshots` or an installation directory as a symlink, the payload and envelope writes follow it outside the configured backup target; this is the prior blocker and should be fixed with a no-symlink directory walk/create helper before copying or renaming.
  - confidence: 0.93
- **[P1] Reject symlinked workspace backup target directories:** `src/commands/workspace-backup.ts:350-351`
  - body: Late discovery on the unchanged reviewed head: `workspaceBackupRunCommand` creates `mirrorRoot` and `stagingRoot` before any target-side symlink rejection, and the later containment checks use realpath-style canonicalization that follows the symlink. A cloud-synced attacker can replace `backup.target/workspace` with a symlink and make mirror writes, renames, or stale-mirror removals affect directories outside the backup target.
  - late: true
  - confidence: 0.87
- **[P2] Cap archive path depth before parent expansion:** `src/commands/backup-verify.ts:340-342`
  - body: `collectNestedArchiveParents` expands every parent for every archive entry after only checking total path bytes. A single slash-dense path under the 4 MiB metadata cap can still create a huge parent set and make `backup verify` or restore spend excessive CPU/memory on untrusted archive input; cap segment depth or bound parent expansion directly.
  - confidence: 0.84
- **[P2] Validate tar entries during archive creation:** `src/infra/backup-create.ts:412-417`
  - body: The new export hardening pre-scans sources before calling `tar.c`, but `onWriteEntry` only rewrites paths and does not reject the entry type actually emitted by tar. If a workspace file is swapped to a symlink, FIFO, or other special file after the pre-scan, `backup export` or `backup run` can create an archive that later verification/restore rejects, especially because verification is optional for export and run.
  - confidence: 0.8
