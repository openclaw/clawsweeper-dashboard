## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Reject workspace backup symlinks before creating roots:** `src/commands/workspace-backup.ts:350-351`
  - body: This creates `mirrorRoot` and `.staging` before proving the existing target-side path segments are real directories. In a synced backup target, a planted `backup.target/workspace` or `mirrors` symlink can make the mkdir/cp/rm flow operate outside the backup target, so the no-symlink target walk needs to happen before any filesystem writes.
  - confidence: 0.92
- **[P1] Reject symlinked snapshot-store parents before writes:** `src/backup/snapshot-store/provider-folder.ts:67-85`
  - body: Both atomic writers create destination parents with recursive `mkdir` and then rename through whatever path segments already exist under `targetDir`. A symlinked `snapshots` or installation directory can redirect encrypted payload/envelope writes outside the configured backup target, so snapshot-store parent creation needs the same no-symlink segment guard used for restore parents.
  - confidence: 0.9
- **[P1] Validate restore parents before rollback moves:** `src/commands/backup-restore.ts:425-428`
  - body: `copySourceToTarget` validates the parent, but rollback happens first: `moveTargetToRollbackPath` creates a rollback dir and renames the existing target through `targetParent` before the no-symlink guard runs. If that parent is symlinked or swapped, restore can move live state through the wrong directory before the protected copy path is reached.
  - confidence: 0.86
- **[P2] Validate tar entries while writing archives:** `src/infra/backup-create.ts:406-418`
  - body: The pre-scan rejects symlinks and special files, but `tar.c` still packs the source tree later without an entry-time filter or type check. A writable workspace can be swapped to a symlink, FIFO, or device between the scan and packing, producing archives that verify/restore rejects and that are unsafe if extracted by other tools.
  - confidence: 0.84
- **[P2] Cap archive path depth before parent expansion:** `src/commands/backup-verify.ts:337-344`
  - body: The verifier bounds total path bytes and entry count, but `collectNestedArchiveParents` expands every path segment into a `Set`. A crafted archive can stay under the byte limit while using very deep paths to force excessive parent-string allocation and CPU during verify/restore.
  - confidence: 0.8
- **[P2] Compare in-state restore paths before suppressing copies:** `src/commands/backup-restore.ts:715-741`
  - body: These branches skip standalone config and credentials copies whenever source and target are both under state, but they do not compare the source-relative path with the current target-relative path. Restoring from a host where config or OAuth lived at a different in-state path can report success while leaving the active config or OAuth directory stale or missing.
  - confidence: 0.82
