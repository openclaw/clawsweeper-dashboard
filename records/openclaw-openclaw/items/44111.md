- **[P1] Reject workspace backup symlinks before creating roots:** `src/commands/workspace-backup.ts:350-352`
  - body: This still creates `backup.target/workspace/mirrors` and `.staging` before rejecting target-side symlink segments.   - confidence: 0.93
- **[P1] Reject symlinked snapshot-store parents before writes:** `src/backup/snapshot-store/provider-folder.ts:67-81`
  - body: `writeFileAtomic` and `copyFileAtomic` call recursive mkdir and then write/rename under `backup.target/snapshots/...` without walking existing parent segments. A symlink planted below the backup target can send payload or envelope writes outside the configured target, so the store needs no-symlink parent validation before writes.
  - confidence: 0.92
- **[P1] Validate restore parents before rollback moves:** `src/commands/backup-restore.ts:443-453`
  - body: `applyRestoreOperations` moves an existing target to a rollback path before `copySourceToTarget` validates the target parent. If the parent path is symlinked, rollback creation and rename can act outside the intended restore directory before the later guard runs; validate target parents before any access, mkdtemp, or rename.
  - confidence: 0.9
- **[P2] Validate tar entries while writing archives:** `src/infra/backup-create.ts:412-418`
  - body: The branch pre-scans sources before `tar.c`, but the write step only remaps entries. A source tree can race in a symlink, FIFO, device, or socket after the pre-scan, producing an archive that OpenClaw later refuses to verify/restore; re-check entry types in the tar filter/write path.
  - confidence: 0.88
- **[P2] Cap archive path depth before parent expansion:** `src/commands/backup-verify.ts:337-346`
  - body: `advanceArchiveScanTotals` caps aggregate path bytes, but `collectNestedArchiveParents` still expands every parent prefix for each normalized entry. A single deeply segmented path within the byte cap can allocate a huge number of parent strings; bound per-entry depth or avoid materializing all parents.
  - confidence: 0.87
- **[P2] Compare in-state restore paths before suppressing copies:** `src/commands/backup-restore.ts:715-721`
  - body: When the source config was inside the old state dir and the target config is inside the current state dir, this skips config restore without checking that the relative paths match. Full-host restore can then report success while leaving a different in-state config or OAuth path stale/missing; compare source and target relative paths before suppressing the copy.
  - confidence: 0.86
