Overall confidence: 0.88

Full review comments:

- **[P1] Reject workspace backup symlinks before creating roots:** `src/commands/workspace-backup.ts:350-352`
  - body: `workspaceBackupRunCommand` creates `backup.target/workspace/mirrors` and `.staging` before rejecting target-side symlink segments. If a synced backup folder already contains `workspace` as a symlink, the mkdir/copy/rename flow can write or delete outside the selected backup target before the containment checks run.
  - confidence: 0.92
- **[P1] Reject symlinked snapshot-store parents before writes:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: `writeFileAtomic` and `copyFileAtomic` mkdir the destination parent under `backup.target/snapshots/...` without first walking the target-side path for symlinked segments. A cloud-synced or shared backup folder can redirect payload/envelope writes outside `backup.target` through a symlinked `snapshots` or installation directory.
  - confidence: 0.91
- **[P1] Validate restore parents before rollback moves:** `src/commands/backup-restore.ts:426-428`
  - body: `applyRestoreOperations` calls `moveTargetToRollbackPath` before `copySourceToTarget` validates the target parent with `ensureDirectoryPathWithoutSymlinks`. For an existing restore target reached through a symlinked parent, restore can rename live data into rollback storage outside the intended safe parent before the guard runs.
  - confidence: 0.89
- **[P2] Validate tar entries while writing archives:** `src/infra/backup-create.ts:412-418`
  - body: The source tree is pre-scanned for symlinks and special files, but `tar.c` later reads the same paths and `onWriteEntry` only remaps names. A source can change between the scan and tar read, letting a symlink, FIFO, or other special entry be archived; validate or filter each tar entry as it is written.
  - confidence: 0.85
- **[P2] Cap archive path depth before parent expansion:** `src/commands/backup-verify.ts:337-344`
  - body: `collectNestedArchiveParents` expands every parent of every normalized entry. The byte/count caps still allow a single path with an extreme number of tiny segments, causing large CPU and memory use during verify/restore before the archive is rejected.
  - confidence: 0.84
- **[P2] Compare in-state restore paths before suppressing copies:** `src/commands/backup-restore.ts:715-716`
  - body: This condition treats any current config path inside `stateDir` as covered by the state restore when the source config was covered by source state. If the source and target relative paths differ, full-host restore skips the explicit config copy and leaves the active config missing or stale; the OAuth branch below has the same issue.
  - confidence: 0.86
