## Review Findings

Overall confidence: 0.9

Full review comments:

- **[P1] Reject symlinked snapshot directories before writing:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: `uploadSnapshot` can write through attacker-controlled symlinked directories inside a synced backup target because `writeFileAtomic`/`copyFileAtomic` call recursive `mkdir` and then rename under `targetDir/snapshots/...` without walking existing segments with `lstat`. A pre-created `snapshots` or installation-id symlink can redirect the encrypted payload/envelope outside `backup.target`, so this needs a no-symlink directory traversal before any mkdir/copy/rename.
  - confidence: 0.94
- **[P1] Validate workspace target segments before mkdir:** `src/commands/workspace-backup.ts:350`
  - body: `workspaceBackupRunCommand` creates `backup.target/workspace/mirrors` and `.staging` before rejecting symlinked target-side segments, and the later containment checks canonicalize through the same symlink. If a cloud-synced target already contains `workspace -> <outside path>`, mirror writes, renames, and stale cleanup can operate outside the backup folder.
  - confidence: 0.95
