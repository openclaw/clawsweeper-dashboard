## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Reject snapshot directory symlinks before writing:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: `uploadSnapshot` reaches `copyFileAtomic`, which creates and renames under `${backup.target}/snapshots/<installationId>` without proving those directory segments are real directories. In a synced/shared backup target, a planted `snapshots` or installation-id symlink can redirect encrypted payload writes outside `backup.target`, so the store needs a no-symlink directory walk before mkdir/write/rename and corresponding tests.
  - confidence: 0.92
- **[P1] Validate backup workspace roots before mkdir:** `src/commands/workspace-backup.ts:350-351`
  - body: `workspaceBackupRunCommand` creates `backup.target/workspace/mirrors` and `.staging` before validating that target-side path segments are not symlinks. Because later copy, rename, and stale cleanup paths are under those directories, a shared/cloud target can redirect writes or deletes outside the backup folder; validate/create each segment without following symlinks before these mkdirs.
  - confidence: 0.9
- **[P2] Remove or enforce retention config:** `src/config/zod-schema.backup.ts:5-13`
  - body: The PR adds `backup.retention` to the public config schema, but no command or runtime path reads or enforces those limits. Accepting unused retention settings creates a compatibility promise and makes users believe old encrypted snapshots will be pruned when they are not, so either implement retention with tests/docs or remove it from the schema for this PR.
  - confidence: 0.88
- **[P2] Cap archive path depth before collecting parents:** `src/commands/backup-verify.ts:337-346`
  - body: `backupVerifyCommand` now builds every parent directory for every normalized tar entry. The total path-byte cap does not bound segment count, so a crafted path like `a/a/a/...` can force millions of parent strings within the 4 MiB path budget before restore even extracts; add a per-entry depth/path cap or avoid materializing all parents.
  - confidence: 0.82
