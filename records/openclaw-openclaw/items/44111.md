## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Reject symlinked snapshot-store parents:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: `writeFileAtomic` creates the snapshot parent with recursive `mkdir` and then opens the temp file beneath it. If a synced or shared backup target already contains `snapshots/<installationId>` or another parent component as a symlink, the payload/envelope write follows that link and can write outside `backup.target`; validate each store parent before writing.
  - confidence: 0.89
- **[P2] Validate tar entries while writing archives:** `src/infra/backup-create.ts:406-412`
  - body: The source tree is scanned before `tar.c`, but tar walks the paths again later and only remaps entry paths in `onWriteEntry`. A local race can swap a checked file or directory for a symlink/special file between the pre-scan and archive write, so entry type needs to be rejected during tar traversal or via a staged immutable copy.
  - confidence: 0.86
- **[P2] Cap archive path depth before parent expansion:** `src/commands/backup-verify.ts:337-347`
  - body: `collectNestedArchiveParents` expands every parent path for every normalized archive entry after only a total path-byte cap. A crafted archive with one very deep path can allocate and hash a huge number of parent strings before manifest verification, affecting both `backup verify` and restore.
  - confidence: 0.82
- **[P2] Restore config when in-state target path differs:** `src/commands/backup-restore.ts:715-722`
  - body: This condition assumes any active config path under the current `stateDir` is already restored by the state asset. If the source config was inside the old state dir at a different relative path than the current `OPENCLAW_CONFIG_PATH`, the state restore copies only the old path and skips the active config write, leaving the restored install stale or missing its config.
  - confidence: 0.9
- **[P2] Restore OAuth dir when in-state target path differs:** `src/commands/backup-restore.ts:741-748`
  - body: The credentials branch has the same layout assumption: any current OAuth dir under `stateDir` is treated as covered without comparing source and target relative paths. When the archive's in-state OAuth dir differs from the restore host's in-state `OPENCLAW_OAUTH_DIR`, restore reports success but leaves provider credentials absent from the active auth path.
  - confidence: 0.89

## Security Review

Status: needs_attention
