Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P1] Reject snapshot store directory symlinks before writes:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: `writeFileAtomic` and `copyFileAtomic` create the destination parent with recursive `mkdir` and then rename/write into it without checking each directory segment under `backup.target`. A synced or attacker-writable target can replace `snapshots` or an installation directory with a symlink, causing encrypted payload/envelope writes outside the configured backup folder.
  - confidence: 0.93
- **[P1] Validate workspace backup roots before mkdir:** `src/commands/workspace-backup.ts:350-351`
  - body: `workspaceBackupRunCommand` creates `backup.target/workspace/mirrors` and `.staging` before any target-side symlink rejection, and the later containment check canonicalizes through the same symlinked root. If `backup.target/workspace` is a symlink, the mirror and stale-delete operations can write or remove paths outside the backup target.
  - confidence: 0.94
- **[P1] Validate restore parents before rollback writes:** `src/commands/backup-restore.ts:426-428`
  - body: `moveTargetToRollbackPath` creates a rollback directory under `path.dirname(targetPath)` before the parent path is walked with symlink-safe checks. A restore target whose existing parent contains a symlink segment can therefore create rollback/temp paths and rename through that symlink before the later copy guard runs.
  - confidence: 0.87
- **[P2] Cap archive path depth during verification:** `src/commands/backup-verify.ts:337-346`
  - body: `collectNestedArchiveParents` walks every parent segment for every normalized tar path, but the new scan limits only bound total path bytes. A crafted path with millions of short segments inside the byte budget can still force excessive CPU and Set allocations during `backup verify` or restore-before-verify.
  - confidence: 0.86
- **[P2] Reject special entries during tar packing:** `src/infra/backup-create.ts:412-418`
  - body: The export path pre-scans sources for symlinks and special files, but `tar.c` can still pack a path that is swapped after the pre-scan because `onWriteEntry` only rewrites the path. Re-check the entry type at write time or add a packing filter so `backup export` cannot produce archives that OpenClaw later rejects or external tools may extract unsafely.
  - confidence: 0.81
- **[P2] Remove or enforce backup retention config:** `src/config/zod-schema.backup.ts:25`
  - body: The schema accepts `backup.retention` fields, but the PR does not read them outside type/schema definitions or prune snapshots. Users can configure a retention policy that silently does nothing, which is a misleading backup contract for data-protection behavior.
  - confidence: 0.95

## Security Review

Status: needs_attention

Summary: The diff introduces security-sensitive encrypted backup and restore filesystem writes, and several symlink traversal and archive resource-exhaustion concerns remain.

- **[high] Backup target symlinks can redirect snapshot or workspace writes:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: Snapshot and workspace backup paths create or write under backup.target before validating every target-side directory segment, so a symlink inside a synced backup folder can redirect writes or deletes outside the intended backup tree.
