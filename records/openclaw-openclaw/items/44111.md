Full review comments:

- **[P1] Reject snapshot-store symlink segments before writes:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: `writeFileAtomic` and `copyFileAtomic` create and rename through `path.dirname(...)` without first proving every target-side segment is a real directory. A synced/shared backup target can plant `snapshots` or an installation directory as a symlink and redirect encrypted payload/envelope writes outside `backup.target`.
  - confidence: 0.92
- **[P1] Validate workspace backup roots before mkdir:** `src/commands/workspace-backup.ts:350`
  - body: `workspaceBackupRunCommand` creates `backup.target/workspace/mirrors` and `.staging` before proving those target-side paths are not symlinks. If a cloud folder contains a symlinked `workspace` or `mirrors`, later copy, rename, or stale-cleanup work can operate outside the selected backup target.
  - confidence: 0.9
- **[P1] Validate restore parents before rollback moves:** `src/commands/backup-restore.ts:443`
  - body: `applyRestoreOperations` moves an existing target into a rollback directory before `copySourceToTarget` validates the target parent with `ensureDirectoryPathWithoutSymlinks`. Validate the parent path before `moveTargetToRollbackPath` so rollback creation and rename cannot be redirected through a symlinked parent.
  - confidence: 0.86
- **[P2] Cap archive path depth during verification:** `src/commands/backup-verify.ts:337`
  - body: `advanceArchiveScanTotals` caps total path bytes, but `collectNestedArchiveParents` still materializes every parent for a single very deep path. A crafted `a/a/...` entry within the byte budget can allocate millions of parent strings during verify or restore.
  - confidence: 0.86
- **[P2] Recheck archive entry types while packing:** `src/infra/backup-create.ts:406`
  - body: The source-tree pre-scan can race with `tar.c`; without an archive-time filter or `onWriteEntry` type guard, a source path swapped to a symlink or FIFO after the scan can still be packed. That produces backups that OpenClaw later rejects, or unsafe artifacts for external extractors.
  - confidence: 0.82
- **[P2] Remove or enforce backup retention config:** `src/config/zod-schema.backup.ts:25`
  - body: The schema accepts `backup.retention`, but no command reads or applies it, so users can configure retention and still accumulate snapshots indefinitely. Implement pruning semantics with tests or remove the config surface before merge.
  - confidence: 0.84
