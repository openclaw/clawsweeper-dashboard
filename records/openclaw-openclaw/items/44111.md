Full review comments:

- **[P1] Reject workspace backup symlinks before mkdir:** `src/commands/workspace-backup.ts:350-352`
  - body: `backup.target` can be a shared or synced folder, but this code creates `backup.target/workspace/mirrors` and `.staging` before proving those target-side segments are not symlinks. A planted `workspace` symlink can redirect the later mirror writes and stale cleanup outside the configured backup directory.
  - confidence: 0.93
- **[P1] Reject symlinked snapshot-store parents before writes:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: The folder snapshot store still calls recursive `mkdir` under `targetDir/snapshots/<installationId>` without walking existing parent segments with `lstat`. If a synced backup target contains `snapshots` or the installation directory as a symlink, upload can write encrypted payloads and envelopes outside the backup target.
  - confidence: 0.92
- **[P1] Validate restore parents before rollback moves:** `src/commands/backup-restore.ts:421-428`
  - body: Restore moves an existing target into a rollback directory before `copySourceToTarget` runs the parent safety check. With a symlinked parent component, `mkdtemp` and `rename` can already operate through the symlink before the later validation has a chance to fail.
  - confidence: 0.9
- **[P1] Walk every existing restore parent segment:** `src/commands/backup-restore.ts:330-344`
  - body: `ensureDirectoryPathWithoutSymlinks` checks only the deepest existing probe and newly-created suffixes, so an already-existing intermediate symlink such as `target/link/dir` is not rejected when `dir` exists through the link. Restore needs to lstat each segment from the root before descending.
  - confidence: 0.9
- **[P2] Cap archive path depth before parent expansion:** `src/commands/backup-verify.ts:337-354`
  - body: Verification still builds a set of every parent path for every archive entry. A crafted entry with millions of short segments can stay within the total path-byte cap while forcing large CPU and memory use during `collectNestedArchiveParents`.
  - confidence: 0.86
- **[P2] Compare in-state restore paths before suppressing copies:** `src/commands/backup-restore.ts:710-742`
  - body: Full-host restore suppresses standalone config and OAuth copies whenever both the source and target are inside their state directories. If the source used one in-state relative path and the restore host uses another, the active config or OAuth directory remains missing after a reported successful restore.
  - confidence: 0.83
