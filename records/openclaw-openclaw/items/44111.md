## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Reject snapshot directory symlinks before writing:** `src/backup/snapshot-store/provider-folder.ts:85`
  - body: `copyFileAtomic` and `writeFileAtomic` create `targetDir/snapshots/<installationId>` recursively and then write/rename through whatever directory entries already exist under the user-selected backup target. In a synced or shared backup folder, a symlinked `snapshots` or installation directory can redirect encrypted payload/envelope writes outside `backup.target`; validate each target-side directory segment with `lstat` before writes and downloads.
  - confidence: 0.88
- **[P1] Check workspace backup roots before mkdir:** `src/commands/workspace-backup.ts:350-351`
  - body: `workspaceBackupRunCommand` creates `backup.target/workspace/mirrors` and `.staging` before proving those target-side path segments are real directories. Because the later containment check canonicalizes through `realpath`, a preexisting symlink under the backup target can make `mkdir`, `cp`, `rename`, or stale mirror removal operate outside the configured backup directory.
  - confidence: 0.86
- **[P2] Remove or implement retention config:** `src/config/zod-schema.backup.ts:22-26`
  - body: The schema accepts `backup.retention` (`keepDaily`, `keepWeekly`, `keepMonthly`, `maxSnapshots`), but the snapshot run/list/upload paths never prune or honor those values. That creates a public `openclaw.json` contract that looks supported while snapshots grow indefinitely; either implement pruning with tests/docs or leave retention out of this PR.
  - confidence: 0.91
