## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Reject workspace backup roots before mkdir:** `src/commands/workspace-backup.ts:350-351`
  - body: `workspaceBackupRunCommand` creates `backup.target/workspace/mirrors` and `.staging` before proving those target-side path segments are not symlinks. In a synced/shared backup target, a preexisting `workspace` or `mirrors` symlink can make mkdir/cp/rename/rm operate outside `backup.target`; validate every target-side segment with `lstat` before creating or replacing these roots.
  - confidence: 0.9
- **[P1] Reject snapshot-store symlink parents before writes:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: `writeFileAtomic` and `copyFileAtomic` call recursive `mkdir` and then write/rename under `targetDir/snapshots/...` without rejecting symlinked intermediate directories. A symlinked `snapshots` or installation directory inside a cloud target can redirect payload/envelope writes outside the configured backup target, so add a no-symlink parent walk before mkdir/write/rename.
  - confidence: 0.9
- **[P1] Validate restore parents before rollback moves:** `src/commands/backup-restore.ts:443`
  - body: `applyRestoreOperations` renames an existing target into rollback before `copySourceToTarget` validates the target parent with `ensureDirectoryPathWithoutSymlinks`. If the parent path is a symlink, the rollback directory and rename can already affect paths outside the intended restore root; validate `dirname(targetPath)` before `fs.access` and `moveTargetToRollbackPath`.
  - confidence: 0.88
- **[P2] Validate archive entries during tar creation:** `src/infra/backup-create.ts:412-418`
  - body: `createBackupArchive` pre-scans sources, but the later `tar.c` call only remaps entry paths in `onWriteEntry`. Because node-tar stats and opens entries after the pre-scan, a source tree swapped to a symlink or special file between scan and write can still produce an unsafe archive unless entry type is rejected during write and the archive is verified before publishing or snapshot upload.
  - confidence: 0.82
- **[P2] Cap archive path depth before parent expansion:** `src/commands/backup-verify.ts:337-344`
  - body: `collectNestedArchiveParents` expands every parent directory for each normalized archive entry after only total path bytes are capped. A path near the 4 MiB metadata limit with many tiny segments can allocate a very large parent set during verify/restore; add a segment/depth cap before parent expansion.
  - confidence: 0.83
- **[P2] Compare in-state restore paths before suppressing copies:** `src/commands/backup-restore.ts:714-742`
  - body: Full-host restore skips explicit config/credentials copies when the source and target paths are both under state, but it does not compare their relative paths. If the archive has `state/openclaw.json` and the restore host uses `state/config/openclaw.json`, state restore succeeds while the active config path remains stale or missing; schedule the explicit copy whenever the relative in-state path differs.
  - confidence: 0.86
