Full review comments:

- **[P1] Reject workspace backup symlinks before creating roots:** `src/commands/workspace-backup.ts:350-351`
  - body: This still creates `backup.target/workspace/mirrors` and `.staging` before rejecting target-side symlink segments. If a synced backup folder contains `workspace -> /somewhere/else`, these mkdir/copy/rename/remove operations can run outside the backup target while the later realpath containment checks still pass.
  - confidence: 0.95
- **[P1] Reject symlinked snapshot-store parents before writes:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: `writeFileAtomic` and the sibling payload copy create and write under `targetDir/snapshots/<installationId>` without walking existing path segments with `lstat`. A symlinked `snapshots` or installation directory inside the configured backup target can redirect encrypted payload/envelope writes outside the backup root.
  - confidence: 0.94
- **[P1] Validate restore parents before rollback moves:** `src/commands/backup-restore.ts:443`
  - body: Restore calls `moveTargetToRollbackPath` before `copySourceToTarget` validates the target parent path. That means an existing restore target under a symlinked parent can be renamed into rollback through the symlink before the symlink-safe parent check runs.
  - confidence: 0.9
- **[P2] Validate tar entries while writing archives:** `src/infra/backup-create.ts:406-420`
  - body: The new pre-scan runs before `tar.c`, but the tar writer has no archive-time filter/type guard. A source tree can change after the scan and before packing, producing a backup with symlinks or special entries that verify/restore later reject.
  - confidence: 0.87
- **[P2] Cap archive path depth before parent expansion:** `src/commands/backup-verify.ts:337-346`
  - body: `collectNestedArchiveParents` still materializes every parent for every archive entry. The total path-byte cap does not prevent a single deeply nested path from creating a very large parent set and excessive CPU/memory use during verify or restore.
  - confidence: 0.86
- **[P2] Compare in-state restore paths before suppressing copies:** `src/commands/backup-restore.ts:715-722`
  - body: Full-host restore skips standalone config or OAuth copies whenever the current target is anywhere inside `stateDir`. If the archive's in-state relative path differs from the current in-state target, restore reports success while leaving the active config or OAuth directory stale or missing.
  - confidence: 0.84
