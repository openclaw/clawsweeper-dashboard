## Review Findings

Overall confidence: 0.88

Full review comments:

- **[P1] Reject symlinked workspace backup roots before mkdir:** `src/commands/workspace-backup.ts:350-351`
  - body: The run path creates `backup.target/workspace/mirrors` and `.staging` before proving the target-side `workspace` tree has no symlink segments. A shared backup target can replace `workspace` with a symlink to another directory, making mirror writes, renames, and stale cleanup operate outside `backup.target`.
  - confidence: 0.9
- **[P1] Reject symlinked snapshot-store parents:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: `writeFileAtomic` and `copyFileAtomic` recursively create the snapshot parent and then write or rename below it without proving existing `snapshots` or `snapshots/<installationId>` components are real directories. A synced backup target can contain a symlinked parent and redirect encrypted payload or envelope writes outside `backup.target`.
  - confidence: 0.89
- **[P2] Validate tar entries while writing archives:** `src/infra/backup-create.ts:406-420`
  - body: The source tree is checked before `tar.c`, but tar traverses later and `onWriteEntry` only remaps paths. A local writer can swap a checked path to a symlink or special file after the pre-scan, producing an archive that verify/restore reject or that external tar tools may mishandle.
  - confidence: 0.84
- **[P2] Cap archive path depth before parent expansion:** `src/commands/backup-verify.ts:337-346`
  - body: `collectNestedArchiveParents` expands every parent for each path after only total path-byte and entry-count caps. A crafted path with many slash segments can allocate and hash a large parent set during `backup verify` and restore verification.
  - confidence: 0.86
- **[P2] Walk every restore target parent segment:** `src/commands/backup-restore.ts:330-344`
  - body: `ensureDirectoryPathWithoutSymlinks` stops once the full directory exists, so an existing symlink in a parent component can still route restore copies outside the intended target. Restore hardening needs to check every existing path segment, not just the first existing probe or newly created suffix.
  - confidence: 0.8
- **[P2] Restore config when in-state path changes:** `src/commands/backup-restore.ts:714-722`
  - body: Full-host restore skips config whenever the source config was under old state and the current config path is under current state, without comparing relative paths. If the archive had one in-state config path and the restore host uses another, the active config remains stale or missing after a successful restore.
  - confidence: 0.84
- **[P2] Restore OAuth when in-state path changes:** `src/commands/backup-restore.ts:740-748`
  - body: The same relative-path mismatch affects credentials: any current OAuth directory inside state is treated as covered by the state restore even when the source in-state OAuth path differs. A full-host restore can therefore report success while leaving active credentials absent.
  - confidence: 0.84

## Security Review

- **[high] Workspace mirror target can follow symlinked parents:** `src/commands/workspace-backup.ts:350`
