## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Reject workspace backup symlinks before creating roots:** `src/commands/workspace-backup.ts:350-351`
  - body: `assertWorkspaceBackupSafety` uses realpath-style containment and does not reject a pre-existing `backup.target/workspace` symlink before these `mkdir` calls. In a shared or synced backup target, an attacker can replace `workspace` with a symlink and make backup writes, staging, stale-mirror deletion, and status writes happen outside the configured backup folder.
  - confidence: 0.9
- **[P1] Reject symlinked snapshot-store parents before writes:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: `copyFileAtomic` and `writeFileAtomic` create parent directories under `targetDir` without walking and rejecting symlinked segments such as `snapshots` or `snapshots/<installationId>`. A synced backup target can redirect payload/envelope writes outside the backup folder even though the final file is later treated as trusted snapshot storage.
  - confidence: 0.9
- **[P1] Validate restore parents before rollback moves:** `src/commands/backup-restore.ts:443`
  - body: `applyRestoreOperations` moves an existing live target into rollback before `copySourceToTarget` validates the target parent with `ensureDirectoryPathWithoutSymlinks`. For a destructive restore command, the parent path must be checked before any rename so a symlinked or swapped parent cannot move config/state/OAuth/workspace data through an unsafe path.
  - confidence: 0.88
- **[P2] Validate tar entries while writing archives:** `src/infra/backup-create.ts:412-418`
  - body: The export path pre-scans source trees, but `tar.c` still writes whatever exists when the archive is produced. A source tree can be swapped after the scan, so the writer should reject symlink/special entries during tar creation or force verification before publishing the archive; otherwise `backup export` can create archives that restore later rejects or that include unsafe entry types.
  - confidence: 0.82
- **[P2] Cap archive path depth before parent expansion:** `src/commands/backup-verify.ts:337-345`
  - body: `collectNestedArchiveParents` expands every parent segment for every normalized entry, but verification only caps entry count and total path bytes. A crafted archive with very deep paths can spend excessive CPU/memory building parent sets during `backup verify` and `backup restore`; add a path-depth cap or bounded parent indexing before expanding parents.
  - confidence: 0.78
- **[P2] Compare in-state restore paths before suppressing copies:** `src/commands/backup-restore.ts:715-716`
  - body: Full-host restore suppresses standalone config/OAuth copies whenever the source path is covered by state and the current target is somewhere under `stateDir`. If the backup's in-state relative path differs from the restore host's configured in-state path, restoring only the state asset leaves the active config or OAuth directory missing/stale while reporting success.
  - confidence: 0.84
