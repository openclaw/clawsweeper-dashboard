Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Reject snapshot store directory symlinks before writes:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: `writeFileAtomic` and the sibling payload copy create destination directories under `backup.target` before validating intermediate segments. A symlink planted at `snapshots` or the installation directory can redirect encrypted payload/envelope writes outside the configured backup target, so create/validate those directory segments without following symlinks before `mkdir` or `rename`.
  - confidence: 0.9
- **[P1] Validate workspace backup roots before mkdir:** `src/commands/workspace-backup.ts:350-351`
  - body: `workspaceBackupRunCommand` creates `mirrorRoot` and `.staging` before proving the target-side path is free of symlink segments, and the later containment helper follows `realpath`. A symlinked `backup.target/workspace` can move mkdir/cp/rm operations outside the backup folder, so reject or create the target-side directory chain safely before the first write.
  - confidence: 0.9
- **[P1] Validate restore parents before rollback writes:** `src/commands/backup-restore.ts:442-443`
  - body: `applyRestoreOperations` calls `fs.access` and moves existing targets into rollback paths before `copySourceToTarget` performs its symlink-free parent validation. If a restore target's parent path contains a symlink, the rollback `mkdtemp`/`rename` can already operate outside the intended restore location; validate the target parent before any rollback move.
  - confidence: 0.86
- **[P2] Cap archive path depth during verification:** `src/commands/backup-verify.ts:337-346`
  - body: The total path-byte cap still allows a single very deep archive path, and `collectNestedArchiveParents` then materializes every parent string for that path. Because backup verify and restore process untrusted archives, add a per-entry depth/segment cap or avoid building the full parent set.
  - confidence: 0.84
- **[P2] Reject special entries while packing archives:** `src/infra/backup-create.ts:406-420`
  - body: `createBackupArchive` pre-scans sources, but `tar.c` does not enforce the same no-symlink/no-special-entry policy while writing. A source tree race after the pre-scan can still produce an archive containing symlinks or FIFOs that OpenClaw later rejects, so add a tar filter or entry-type guard at pack time.
  - confidence: 0.82
- **[P2] Remove or enforce backup retention config:** `src/config/zod-schema.backup.ts:25`
  - body: The schema accepts `backup.retention.keepDaily`, `keepWeekly`, `keepMonthly`, and `maxSnapshots`, but the snapshot store and backup commands never consume those settings. Users can configure pruning that does not happen, so either implement tested retention enforcement/status or remove the config surface until it is real.
  - confidence: 0.88
