Overall confidence: 0.92

Full review comments:

- **[P1] Reject workspace backup symlinks before creating roots:** `src/commands/workspace-backup.ts:350-351`
  - body: `workspaceBackupRunCommand` creates `backup.target/workspace/mirrors` and `.staging` before proving those target-side path segments are real directories rather than symlinks. In a cloud-synced or attacker-writable backup target, those `mkdir`/`rename`/`rm` operations can be redirected outside the backup folder before the later containment checks run.
  - confidence: 0.94
- **[P1] Reject symlinked snapshot-store parents before writes:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: `writeFileAtomic` and `copyFileAtomic` create and write through `path.dirname(...)` without checking the `snapshots` or installation-id directories for symlinks. A modified backup target can therefore redirect encrypted payload/envelope writes outside the configured backup directory.
  - confidence: 0.93
- **[P1] Validate restore parents before rollback moves:** `src/commands/backup-restore.ts:442-443`
  - body: `applyRestoreOperations` renames any existing target into a rollback path before `copySourceToTarget` validates that the destination parent is not a symlink or non-directory. That makes the destructive move happen before the new restore safety check can reject an unsafe parent path.
  - confidence: 0.91
- **[P2] Validate tar entries while writing archives:** `src/infra/backup-create.ts:406-420`
  - body: The source tree is pre-scanned for symlinks and special files, but `tar.c` later archives the live paths and `onWriteEntry` only remaps names. A symlink/FIFO swapped in after the pre-scan can still be written into the archive, so the writer needs an entry-time type/source validation or fail-closed filter.
  - confidence: 0.86
- **[P2] Cap archive path depth before parent expansion:** `src/commands/backup-verify.ts:337-345`
  - body: `collectNestedArchiveParents` expands every ancestor of each untrusted archive path, but the byte/count caps do not bound slash depth. A crafted backup archive can force excessive parent-set work during verify/restore before the archive is rejected.
  - confidence: 0.85
- **[P2] Compare in-state restore paths before suppressing copies:** `src/commands/backup-restore.ts:715-742`
  - body: Full-host restore suppresses standalone config/OAuth copies whenever the source and target paths are both under their state dirs, but it does not compare the relative source-vs-target locations. If the restore host uses a different in-state config or OAuth path, restore can report success while leaving the active path missing or stale.
  - confidence: 0.88
