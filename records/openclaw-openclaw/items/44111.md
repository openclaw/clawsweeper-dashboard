## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Reject workspace backup symlink roots before mkdir:** `src/commands/workspace-backup.ts:350-351`
  - body: `workspaceBackupRunCommand` creates `mirrorRoot` and `stagingRoot` before rejecting symlinked target-side path segments. If `backup.target/workspace` or a child is replaced by a symlink, these `mkdir` calls can already write through it before the later containment checks run.
  - confidence: 0.94
- **[P1] Reject symlinked snapshot-store parents before writes:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: The folder snapshot store creates the destination parent and then writes/renames the payload and envelope, but it never rejects symlinked intermediate directories under `backup.target/snapshots`. A synced or shared backup folder can redirect snapshot writes outside the configured target.
  - confidence: 0.93
- **[P1] Validate restore parents before rollback moves:** `src/commands/backup-restore.ts:443`
  - body: `applyRestoreOperations` renames an existing target into rollback storage before `copySourceToTarget` validates the target parent path. That leaves a destructive move ahead of the symlink/non-directory parent guard, so the safety check must happen before rollback is created.
  - confidence: 0.91
- **[P2] Validate tar entries while writing archives:** `src/infra/backup-create.ts:412-418`
  - body: The source tree is pre-scanned, but the actual `tar.c` write remaps entries without rechecking blocked entry types or symlink/special-file state at write time. A source can change between the pre-scan and archive creation, producing an archive that `backup verify` later rejects or that cannot be safely restored.
  - confidence: 0.78
- **[P2] Cap archive path depth before parent expansion:** `src/commands/backup-verify.ts:340-343`
  - body: `collectNestedArchiveParents` expands every parent for every normalized entry, but verification only caps total path bytes and entry count. A crafted archive path with many separators can still drive large parent-set expansion during verify/restore; add a segment/depth cap before this loop.
  - confidence: 0.86
- **[P2] Compare in-state restore paths before suppressing copies:** `src/commands/backup-restore.ts:715`
  - body: Full-host restore skips explicit config/OAuth copies whenever both source and target are inside state, but it does not compare their relative paths. If the backup used one in-state config or OAuth path and the restore host uses another, restore can report success while leaving the active path missing or stale.
  - confidence: 0.9

## Security Review

Status: needs_attention

Summary: The diff still has concrete filesystem safety concerns in backup target writes, snapshot-store writes, archive generation, and restore rollback ordering.

- **[high] Target-side backup writes can follow symlinked parents:** `src/commands/workspace-backup.ts:350`
  - body: Workspace and snapshot backup paths create or write through target-side directories before rejecting symlinked intermediate segments, which can redirect writes outside the selected backup target.
