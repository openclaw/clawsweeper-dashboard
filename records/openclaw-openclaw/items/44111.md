## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Reject snapshot directory symlinks before writes:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: `writeFileAtomic` and `copyFileAtomic` create the destination parent with recursive `mkdir` and then write/rename under it. If a synced/shared backup target contains `snapshots` or an installation directory as a symlink, these writes follow that symlink and place encrypted payloads outside `backup.target`; walk existing path segments with `lstat` and reject symlinks before mkdir and before rename.
  - confidence: 0.91
- **[P1] Validate workspace backup roots before mkdir:** `src/commands/workspace-backup.ts:350-351`
  - body: `backup run` creates `backup.target/workspace/mirrors` and `.staging` before proving those target-side directories are real directories. A symlinked `backup.target/workspace` or child can redirect mirror writes and stale-mirror deletion outside the configured backup folder, so the target/workspace/mirrors/.staging path segments need the same no-symlink guard before any mkdir/cp/rm.
  - confidence: 0.9
- **[P2] Remove or enforce backup retention config:** `src/config/zod-schema.backup.ts:25`
  - body: The schema accepts `backup.retention`, but the backup/snapshot code never reads it to prune snapshots. Users can set `keepDaily`, `keepWeekly`, `keepMonthly`, or `maxSnapshots` and get no retention behavior, so either remove this config surface or implement and test pruning before exposing it.
  - confidence: 0.86
