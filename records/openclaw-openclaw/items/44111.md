Full review comments:

- **[P1] Reject symlinked workspace backup roots before mkdir:** `src/commands/workspace-backup.ts:350-351`
  - body: `workspaceBackupRunCommand` creates `mirrorRoot` and `.staging` before proving target-side backup tree segments are not symlinks. A synced backup folder can contain `backup.target/workspace` or `mirrors` as a symlink, causing later mkdir/cp/rm/rename operations to act outside the configured backup directory.
  - confidence: 0.93
- **[P1] Reject symlinked snapshot-store parents:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: `writeFileAtomic` and `copyFileAtomic` call recursive `mkdir` and then rename/copy under `targetDir/snapshots/...` without walking those directory segments with `lstat`. If `snapshots` or an installation directory is a symlink, snapshot upload can write outside `backup.target`.
  - confidence: 0.93
- **[P1] Validate restore parents before rollback moves:** `src/commands/backup-restore.ts:443`
  - body: `applyRestoreOperations` moves an existing target into rollback before `copySourceToTarget` validates the target parent with `ensureDirectoryPathWithoutSymlinks`. A symlinked parent can make the rollback rename operate outside the intended restore tree before the safety check runs.
  - confidence: 0.88
- **[P2] Validate tar entries while writing archives:** `src/infra/backup-create.ts:412`
  - body: The pre-scan rejects symlinks and special files, but `tar.c()` does not re-check entry type while packing. If a source tree changes after the pre-scan, export can still produce a symlink, FIFO, or device entry that verify/restore later rejects.
  - confidence: 0.86
- **[P2] Cap archive path depth before parent expansion:** `src/commands/backup-verify.ts:337`
  - body: `advanceArchiveScanTotals` caps total path bytes, but `collectNestedArchiveParents` still expands every parent segment for each path. One long path made of many tiny segments can stay under the byte cap while creating a huge parent set during verify/restore.
  - confidence: 0.84
- **[P2] Compare in-state paths before suppressing restores:** `src/commands/backup-restore.ts:715-716`
  - body: Full-host restore skips standalone config/OAuth restore whenever the source path was inside archived state and the current target is inside current state. If the relative path changed, state restore writes the old location while the active config or OAuth path remains missing or stale.
  - confidence: 0.9
