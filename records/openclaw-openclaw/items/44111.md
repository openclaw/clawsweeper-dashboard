- **[P1] Reject snapshot store directory symlinks before writes:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: This repeats a previous ClawSweeper blocker at the same head: `writeFileAtomic` and `copyFileAtomic` create and write under `targetDir/snapshots/<installationId>` without rejecting symlinked directory segments such as `snapshots` or the installation directory. A synced/shared backup target can redirect snapshot payload or envelope writes outside the configured backup root, so validate or create each directory segment as a non-symlink before `mkdir`, temp writes, and `rename`.
  - confidence: 0.91
- **[P1] Validate workspace backup roots before mkdir:** `src/commands/workspace-backup.ts:350-351`
  - body: This repeats a previous ClawSweeper blocker at the same head: `backup run` calls `mkdir` for `backup.target/workspace/mirrors` and `.staging` before proving those target-side components are real directories. If a cloud-synced target already contains `workspace` or `mirrors` as a symlink, later realpath-based containment checks can follow the symlink and the mirror/cleanup writes can operate outside the backup target.
  - confidence: 0.9
- **[P1] Validate restore parents before rollback writes:** `src/commands/backup-restore.ts:426-428`
  - body: This repeats a previous ClawSweeper blocker at the same head: restore moves an existing target into a rollback directory before `copySourceToTarget` checks the target parent with `ensureDirectoryPathWithoutSymlinks`. A symlinked parent can therefore receive rollback temp directories and renames before the later guarded copy path runs; validate the parent path before `mkdtemp` and `rename`.
  - confidence: 0.88
- **[P2] Remove or enforce backup retention config:** `src/config/zod-schema.backup.ts:5-13`
  - body: This repeats a previous ClawSweeper blocker at the same head: the PR adds `backup.retention.keepDaily`, `keepWeekly`, `keepMonthly`, and `maxSnapshots` to the public config schema, but the diff contains no runtime pruning or status behavior that reads those keys. Shipping accepted config that is silently ignored gives users a false retention guarantee for backups, so either implement and test retention or leave the keys out until the behavior exists.
  - confidence: 0.86
