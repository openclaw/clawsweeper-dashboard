## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Reject symlinked workspace backup roots before mkdir:** `src/commands/workspace-backup.ts:350-352`
  - body: `workspaceBackupRunCommand` creates `backup.target/workspace/mirrors` and `.staging` before rejecting target-side symlink segments. If a synced backup folder contains `workspace` as a symlink, the mkdir/cp/rename path can write outside the configured backup target, so the target workspace, mirrors, and staging roots need no-symlink validation before any write.
  - confidence: 0.92
- **[P1] Reject symlinked snapshot-store parents:** `src/backup/snapshot-store/provider-folder.ts:67-68`
  - body: `writeFileAtomic` and `copyFileAtomic` recursively create and then write through `targetDir/snapshots/<installationId>` without validating existing intermediate directories. A symlinked `snapshots` or installation directory in the backup target can redirect payload/envelope writes outside the selected backup folder.
  - confidence: 0.91
- **[P1] Validate restore parents before rollback moves:** `src/commands/backup-restore.ts:443`
  - body: `applyRestoreOperations` moves an existing target to rollback before `copySourceToTarget` checks the target parent with `ensureDirectoryPathWithoutSymlinks`. A restore target under a symlinked parent can therefore mutate outside the intended restore boundary before the safe-path validation runs.
  - confidence: 0.9
- **[P2] Validate tar entries while writing archives:** `src/infra/backup-create.ts:365-366`
  - body: The new pre-scan rejects symlinks and special files before `tar.c`, but the actual archive walk can still race if a source path is swapped after the scan. Add an archive-time entry/type guard so `backup export` and snapshot upload do not create archives that verify/restore later reject or that unsafe external extractors might mishandle.
  - confidence: 0.82
- **[P2] Cap archive path depth before parent expansion:** `src/commands/backup-verify.ts:337-344`
  - body: `collectNestedArchiveParents` builds every parent for every tar entry, while the scanner only caps total path bytes. A single deeply nested path within that byte budget can force excessive CPU and memory during `backup verify` or restore, so verification needs a per-entry depth/length cap or a prefix check that avoids materializing all parents.
  - confidence: 0.86
- **[P2] Compare in-state restore paths before suppressing copies:** `src/commands/backup-restore.ts:715-716`
  - body: This branch suppresses the standalone config copy whenever the source config was under the source state dir and the current config path is under the current state dir, without checking that the relative paths match. If the backup used one in-state config or OAuth path and the restore host uses another, full-host restore can report success while leaving the active path missing or stale.
  - confidence: 0.84
