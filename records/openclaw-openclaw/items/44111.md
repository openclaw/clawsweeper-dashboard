## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Reject workspace backup roots before mkdir:** `src/commands/workspace-backup.ts:350-351`
  - body: `workspaceBackupRunCommand` creates `backup.target/workspace/mirrors` and `.staging` before proving those target-side path segments are real directories. If `backup.target/workspace` is a symlink in a synced/shared backup folder, these `mkdir` calls and later mirror writes operate through the symlink before the containment checks run, so target roots must be lstat-validated before any create/write operation.
  - confidence: 0.91
- **[P1] Reject snapshot-store symlink parents before writes:** `src/backup/snapshot-store/provider-folder.ts:168-175`
  - body: `uploadSnapshot` writes under `targetDir/snapshots/<installationId>` through `copyFileAtomic`/`writeFileAtomic`, but those helpers only `mkdir` the destination parent and never reject symlinked intermediate directories inside `backup.target`. A shared backup folder can therefore redirect payload or envelope writes outside the configured target; validate every existing parent segment before creating or renaming files.
  - confidence: 0.9
- **[P1] Validate restore parents before rollback moves:** `src/commands/backup-restore.ts:442-443`
  - body: `applyRestoreOperations` renames an existing live target to a rollback path before `copySourceToTarget` performs the symlink-safe parent validation. If the target parent is a symlink or otherwise unsafe, restore can move user data through that unsafe parent before the guarded copy path runs; validate the target path and parent before `moveTargetToRollbackPath`.
  - confidence: 0.89
- **[P2] Validate archive entries during tar creation:** `src/infra/backup-create.ts:412-418`
  - body: The export path pre-scans sources for symlinks/special files, then later calls `tar.c` without validating each entry as it is written. A source tree that changes between the pre-scan and tar traversal can still produce an archive containing symlinks or special entries that restore/verify later reject, so the write path needs an `onWriteEntry`-time guard or equivalent fail-fast validation.
  - confidence: 0.82
- **[P2] Cap archive path depth before parent expansion:** `src/commands/backup-verify.ts:337-346`
  - body: `collectNestedArchiveParents` expands every parent for every normalized tar entry, but the earlier metadata cap only bounds total path bytes, not segment depth or parent count. A crafted archive with deeply nested paths can force large parent-set expansion during verify/restore; add a depth or parent-expansion cap before building this set.
  - confidence: 0.8
- **[P2] Compare in-state restore paths before suppressing copies:** `src/commands/backup-restore.ts:710-742`
  - body: Full-host restore suppresses standalone config and OAuth copies whenever both the archived source path and current target path are inside their state dirs, but it never compares their relative paths. If the archive has `state/openclaw.json` and the restore host uses a different in-state `OPENCLAW_CONFIG_PATH` or OAuth path, the state restore succeeds while the active config/credential path remains missing or stale; compare source-vs-target relative paths before treating them as covered by the state asset.
  - confidence: 0.86
