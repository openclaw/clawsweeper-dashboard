## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Reject symlinked workspace backup roots before mkdir:** `src/commands/workspace-backup.ts:350-351`
  - body: `workspaceBackupRunCommand` creates `backup.target/workspace/mirrors` and `.staging` before rejecting symlinked target-side path segments. In a shared or synced backup target, a preexisting symlink under `backup.target/workspace` can make the mkdir/cp/rename/rm operations write outside the backup directory before the later realpath-based containment checks run.
  - confidence: 0.91
- **[P1] Reject symlinked snapshot-store parents:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: The folder snapshot store recursively creates `targetDir/snapshots/<installationId>` parents and then writes temp files there without lstat-walking those parent segments. A symlinked `snapshots` or installation directory inside a cloud-synced target can redirect payload/envelope writes outside the configured backup target.
  - confidence: 0.9
- **[P1] Check restore parents before rollback moves:** `src/commands/backup-restore.ts:426-428`
  - body: `applyRestoreOperations` can call `moveTargetToRollbackPath` before `copySourceToTarget` runs `ensureDirectoryPathWithoutSymlinks`, so an existing target under a symlinked parent is renamed and rollback directories are created through that symlink first. Run the parent-segment guard before any access, mkdtemp, or rename for every restore operation.
  - confidence: 0.86
- **[P2] Validate tar entries while writing archives:** `src/infra/backup-create.ts:412-418`
  - body: The source-tree lstat walk is not atomic with the later `tar.c` call, and `onWriteEntry` currently only remaps paths. If a workspace changes between the pre-scan and tar emission, symlinks or special files can still enter the archive and produce backups that fail later verification or restore; reject blocked entry types as each tar entry is written.
  - confidence: 0.82
- **[P2] Cap archive path depth before parent expansion:** `src/commands/backup-verify.ts:337-345`
  - body: Verification bounds entry count and total path bytes, but `collectNestedArchiveParents` still expands every slash-delimited parent for every normalized entry. A crafted archive with very deep paths can force excessive parent-set growth before manifest checks; cap per-entry depth or avoid full parent expansion.
  - confidence: 0.84
- **[P2] Compare in-state paths before suppressing restores:** `src/commands/backup-restore.ts:715-747`
  - body: Full-host restore skips config and OAuth copy operations whenever both the source path and active target path are inside state, but it never compares their relative paths. If the archive used one in-state config or OAuth location and the restore host uses another, the state restore succeeds while the active config or credentials path remains stale or missing.
  - confidence: 0.86
