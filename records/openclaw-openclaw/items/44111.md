Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Reject workspace backup roots before mkdir:** `src/commands/workspace-backup.ts:350-352`
  - body: `backup.target/workspace` and its child roots are created before any target-side symlink-segment validation. A synced or attacker-writable backup target can pre-place `workspace`, `mirrors`, or `.staging` as a symlink and redirect mirror writes/removals outside the configured backup directory.
  - confidence: 0.91
- **[P1] Reject snapshot-store symlink parents before writes:** `src/backup/snapshot-store/provider-folder.ts:67-85`
  - body: `writeFileAtomic` and `copyFileAtomic` recursively create the destination parent and then write/rename through it without proving `targetDir/snapshots/<installationId>` has no symlink segments. A modified backup target can redirect encrypted payload or envelope writes outside `backup.target`.
  - confidence: 0.9
- **[P1] Validate restore parents before rollback moves:** `src/commands/backup-restore.ts:443`
  - body: `applyRestoreOperations` moves an existing target into rollback before the later copy path validates restore parent segments. If a target parent is or becomes a symlink, the destructive rename can affect data outside the intended restore target before the guard runs.
  - confidence: 0.86
- **[P2] Validate archive entries during tar creation:** `src/infra/backup-create.ts:406-420`
  - body: The source tree is pre-scanned, but the `tar.c` write path does not re-check each entry type as it is packed. A source tree race can still create archives containing symlink or special entries that verify/restore later reject, breaking automated snapshot creation.
  - confidence: 0.82
- **[P2] Cap archive path depth before parent expansion:** `src/commands/backup-verify.ts:337-346`
  - body: Verification builds all parent paths for every archive entry without a per-entry depth cap. A crafted path within the total-byte limit can still allocate huge parent sets and hang or crash `backup verify` and restore, which verifies first.
  - confidence: 0.84
- **[P2] Compare in-state restore paths before suppressing copies:** `src/commands/backup-restore.ts:715-742`
  - body: Full-host restore skips standalone config or OAuth copies whenever the source path is state-covered and the current target is inside state. If the source and target relative paths differ, the state restore will not populate the active config/OAuth location even though the command reports success.
  - confidence: 0.8
