Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Reject symlinked workspace backup roots before mkdir:** `src/commands/workspace-backup.ts:350-351`
  - body: `mirrorRoot` and `stagingRoot` are created before any symlinked path segment is rejected. If `backup.target/workspace` or a child path already points elsewhere, this can make setup/run create, copy, rename, or remove files outside the backup target before the later containment checks run.
  - confidence: 0.9
- **[P1] Reject symlinked snapshot-store parents:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: The folder snapshot store recursively creates the destination parent and then renames/copies into it without lstat-walking the existing parent chain. A symlinked `snapshots` or installation-id directory under the configured target can redirect snapshot writes outside the backup store.
  - confidence: 0.88
- **[P1] Check restore parents before rollback moves:** `src/commands/backup-restore.ts:426-428`
  - body: Restore moves existing target paths into rollback locations before the later copy helper validates destination parents for symlinks. That ordering lets an unsafe parent influence the destructive rollback move before the restore path has proven it is operating inside safe directories.
  - confidence: 0.86
- **[P2] Validate tar entries while writing archives:** `src/infra/backup-create.ts:412-418`
  - body: The pre-scan rejects symlinks and special files before `tar.c`, but the write callback only rewrites names. A file that changes after the scan can still be archived with an unsafe type, so the archive writer should filter or validate each entry at write time too.
  - confidence: 0.83
- **[P2] Cap archive path depth before parent expansion:** `src/commands/backup-verify.ts:337-345`
  - body: `collectNestedArchiveParents` expands every parent component for each archive entry after only checking total path bytes. A crafted archive with very deep paths can force large parent-set growth during verify, so apply a per-entry depth cap before expanding parents.
  - confidence: 0.8
- **[P2] Compare in-state paths before suppressing restores:** `src/commands/backup-restore.ts:715-747`
  - body: Full-host restore suppresses config and OAuth copies whenever source and target are both inside state, without checking that they refer to the same relative location. If an archive contains config or OAuth material at a different in-state path, restore can report success while leaving the active files stale or missing.
  - confidence: 0.82
