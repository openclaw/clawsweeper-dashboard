## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Reject snapshot directory symlinks before writing:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: `writeFileAtomic` and `copyFileAtomic` create and rename files under `backup.target/snapshots/...` without rejecting symlinked directory segments inside the backup target. A synced/shared backup folder can redirect snapshot payload or envelope writes outside the configured target; validate every destination directory segment before mkdir/write/rename.
  - confidence: 0.93
- **[P1] Check workspace backup roots before mkdir:** `src/commands/workspace-backup.ts:350-351`
  - body: `workspaceBackupRunCommand` creates `backup.target/workspace/mirrors` and `.staging` before proving those target-side paths are not symlinks, and the later containment check follows realpaths. A symlinked `backup.target/workspace` can make mirror writes or stale cleanup operate outside the backup target; reject target-side symlink segments before the first mkdir.
  - confidence: 0.92
- **[P2] Remove or implement retention config:** `src/config/zod-schema.backup.ts:25`
  - body: The PR accepts `backup.retention` as public config, but the run/list/status code never prunes or enforces retention. Shipping this creates a misleading compatibility contract for backup retention; either implement pruning with tests/docs or remove the config surface until it exists.
  - confidence: 0.89
- **[P2] Restore config when in-state paths differ:** `src/commands/backup-restore.ts:715-721`
  - body: Full-host restore skips a config operation whenever the source config and current config are both inside their state dirs. If the archive used one relative in-state config path and the restore host uses another, restoring the state tree will not populate the active config path; compare relative paths before treating config as covered by state.
  - confidence: 0.87
- **[P2] Restore OAuth when in-state paths differ:** `src/commands/backup-restore.ts:741-747`
  - body: The credentials branch has the same issue: it assumes any in-state OAuth dir is covered by the restored state asset without checking whether the source and target relative paths match. A host using a different in-state `OPENCLAW_OAUTH_DIR` can report success while leaving the active credentials directory missing.
  - confidence: 0.87
- **[P2] Validate tar entry types during archive write:** `src/infra/backup-create.ts:406-419`
  - body: The new source pre-scan can be invalidated by a file-system race before `tar.c` writes entries, and `onWriteEntry` only remaps paths. Add an archive-time filter/type check so symlinks, hardlinks, FIFOs, devices, or sockets cannot be emitted after the pre-scan passes.
  - confidence: 0.81

## Security Review

Status: needs_attention

Summary: The diff introduces security-sensitive encrypted backup and restore code, and target-side symlink plus archive-race issues still need attention before merge.

Concerns:

- **[medium] Snapshot writes can follow target-side symlinks:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: Snapshot payload/envelope writes create destination directories and rename through them without rejecting symlinked segments inside `backup.target`, so a shared backup folder can redirect writes outside the intended backup directory.
