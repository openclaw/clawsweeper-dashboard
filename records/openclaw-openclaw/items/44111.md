## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P1] Reject snapshot directory symlinks before writes:** `src/backup/snapshot-store/provider-folder.ts:67`
  - body: `uploadSnapshot` reaches `writeFileAtomic`/`copyFileAtomic`, which first creates `path.dirname(...)` under `backup.target/snapshots/<installationId>` and then renames files there. If a synced/shared backup target already contains `snapshots` or an installation directory as a symlink, the payload and envelope writes follow that symlink outside the configured target; walk and lstat target-side directory segments before any mkdir/write/rename.
  - confidence: 0.9
- **[P1] Validate workspace backup roots before mkdir:** `src/commands/workspace-backup.ts:350-351`
  - body: `workspaceBackupRunCommand` creates `mirrorRoot` and `stagingRoot` before proving the target-side `workspace`/`mirrors`/`.staging` path segments are real directories. Since the containment helper follows symlinks, a malicious cloud-sync folder can redirect the later copy, rename, or stale mirror removal outside `backup.target`; reject symlinked target roots before these mkdirs.
  - confidence: 0.88
- **[P2] Remove or enforce backup retention config:** `src/config/zod-schema.backup.ts:25`
  - body: The schema accepts `backup.retention` with daily/weekly/monthly/max snapshot fields, but no snapshot command or store implementation prunes according to it. That exposes a public config contract that silently does nothing, so either remove it from this PR or implement and test retention before merge.
  - confidence: 0.84
