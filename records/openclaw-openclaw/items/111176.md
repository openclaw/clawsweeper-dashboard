## Summary

The latest commit correctly narrows the claim to a best-effort timeout, but the proposed synchronous `spawnSync` path still cannot prevent the test process from waiting indefinitely when `find` is stuck in an uninterruptible filesystem operation. The earlier P1 liveness blocker therefore remains unresolved.

## What This Changes

The PR adds a five-second `SIGKILL` timeout, typed timeout propagation, and delayed-`find` regression coverage to the channel-document test helper.

## Best Possible Solution

Move the fallback enumeration into an isolated asynchronous child boundary whose timeout lets the test runner continue even if the worker cannot be reaped promptly, and retain the no-`readdirSync`-after-timeout behavior.
