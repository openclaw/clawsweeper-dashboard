## Summary

This PR should stay open, but the proposed timeout does not resolve the reported stall: a timed-out `find` returns through the existing `null` path, which immediately invokes synchronous `readdirSync` on the same directory and can block on the same stalled filesystem.

## What This Changes

The PR adds a five-second timeout and `SIGKILL` to the test-only `find` fallback used when Git cannot enumerate channel documentation files.

## Best Possible Solution

Classify an actual `find` timeout separately, fail the test quickly with a diagnostic instead of calling `readdirSync` on that path, and retain the ordinary fallback only for non-timeout command-unavailability cases.

## Solution Assessment

No. Adding the child-process timeout is useful, but returning `null` conflates timeout with ordinary fallback conditions and reintroduces the same blocking filesystem operation.
