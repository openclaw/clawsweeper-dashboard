## What This Changes

The PR treats Node’s `ERR_REQUIRE_ESM_RACE_CONDITION` as an existing source-transform fallback condition so concurrent ESM plugin loading does not leave a Gateway restart unhealthy.

## System Context

OpenClaw’s plugin runtime first attempts a native Node module load, then hands selected ESM-related failures to a source-transform loader. This path feeds activated plugin loading during Gateway startup and restart, so its outcome determines whether the Gateway can become healthy.

## Architecture Diagram

flowchart LR
  A[Gateway restart] --> B[Activated plugin load]
  B --> C[Native Node module load]
  C --> D{Load outcome}
  D -->|ESM race or ESM load error| E[Source-transform loader]
  D -->|Other failure| F[Plugin load error]
  E --> G[Plugin activates]
  G --> H[Gateway becomes healthy]

## Best Possible Solution

Retain the single existing source-transform fallback path, merge this narrowly scoped Node error classification once the plugin/runtime owner accepts the final CI result, and keep the regression test tied to Node’s exact error code.
