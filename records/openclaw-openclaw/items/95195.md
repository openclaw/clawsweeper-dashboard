## Summary

Keep open: current main still accumulates `NodeExecutionEnv.exec` stdout/stderr without a cap, and this PR is a focused, well-proven fix, but the new 16 MiB default capture limit needs maintainer acceptance as a compatibility tradeoff.

## What This Changes

The branch adds a 16 MiB per-stream stdout/stderr capture cap to `NodeExecutionEnv.exec`, exposes `maxOutputBytes` on `ExecutionEnvExecOptions`, and adds focused real-child-process tests.

## Best Possible Solution

Land bounded capture as the harness default once maintainers accept the truncation tradeoff, or revise the default/API so large-output callers have an explicit supported opt-up path before merge.
