## Summary

Keep open: this is a focused, well-proven agent-core availability fix, but the new 16 MiB default changes the stdout/stderr capture contract and should get maintainer acceptance before merge.

## What This Changes

Adds a 16 MiB per-stream stdout/stderr capture cap to `NodeExecutionEnv.exec`, exposes `maxOutputBytes` on `ExecutionEnvExecOptions`, and adds real-child-process regression tests.

## Best Possible Solution

Land the bounded capture path once maintainers accept the 16 MiB per-stream default; otherwise revise the contract so large-output callers have an explicit supported opt-up path.

## Reproduction Assessment

Yes from source inspection: current main appends child stdout/stderr chunks without a byte cap in `NodeExecutionEnv.exec`. The PR body also includes a negative-control terminal run where the same real-child-process proof fails against old code and passes after the fix.

## Solution Assessment

Yes, with a compatibility caveat: bounding capture inside `NodeExecutionEnv.exec` is the narrow owner-boundary fix, and the sibling process exec path already uses a 16 MiB output cap. The remaining decision is whether maintainers accept default truncation for existing large-output harness consumers.
