## Summary

## Best Possible Solution

Land the harness output cap after making cap termination explicit, exposing the override on the shared exec options, truncating by bytes, and adding redacted real after-fix terminal proof.

## Solution Assessment

No. The owner boundary is right, but this implementation should make cap-triggered termination observable, update the shared option contract, and truncate UTF-8 output by bytes rather than UTF-16 code units.

Full review comments:

- **[P2] Record output-cap termination before killing:** `packages/agent-core/src/harness/env/nodejs.ts:372`
  - body: This overflow path only sets `outputTruncated` before killing the child. The close handler still falls through to `ok({ ..., exitCode: code ?? 0 })`, so a signal-killed over-cap command can be reported as success; track this terminal state and return an explicit error or nonzero/signal-aware result.
  - confidence: 0.86
- **[P3] Expose maxOutputBytes on the shared exec options:** `packages/agent-core/src/harness/env/nodejs.ts:274`
  - body: The override is added only to `NodeExecutionEnv.exec`'s inline parameter type. Callers typed as `ExecutionEnv` or `Shell` still use `ExecutionEnvExecOptions`, which omits `maxOutputBytes`, so the advertised override is unavailable without casts.
  - confidence: 0.81
- **[P3] Trim by bytes instead of UTF-16 code units:** `packages/agent-core/src/harness/env/nodejs.ts:368`
  - body: `remaining` is a byte budget from `Buffer.byteLength`, but `chunk.slice(0, remaining)` slices UTF-16 code units. Multibyte UTF-8 output can exceed `maxOutputBytes`; keep buffers or use byte-aware decoding and add multibyte coverage.
  - confidence: 0.78
