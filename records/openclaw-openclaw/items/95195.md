## Summary

Keep open. The OOM mitigation is focused and supported by source/proof, but merging it changes the default public harness exec capture behavior and leaves a root proof helper that should be folded into maintained tests or explicitly accepted.

## What This Changes

The PR caps `NodeExecutionEnv.exec` stdout/stderr capture at 16 MiB per stream with a `maxOutputBytes` option, preserves callbacks, and adds focused tests plus a proof harness.

## Best Possible Solution

Land a maintained in-suite version of the cap after maintainers accept the 16 MiB default truncation contract for harness/plugin-SDK exec output.

## Reproduction Assessment

Yes. Current main source shows unbounded `stdout += chunk` and `stderr += chunk`, and the PR body includes a negative-control run showing truncation assertions fail on `origin/main`.

## Solution Assessment

Yes as a fix shape, with an upgrade caveat. Bounding returned capture while continuing to drain streams and deliver callbacks is the right layer; maintainers still need to accept the default cap as public behavior.
