## What This Changes

The branch adds a 16 MiB per-stream stdout/stderr capture cap to `NodeExecutionEnv.exec`, exposes `maxOutputBytes` on `ExecutionEnvExecOptions`, and adds real-child-process regression coverage.

## Best Possible Solution

Land bounded capture as the new harness contract once maintainers accept the default truncation tradeoff and normal CI is green; otherwise revise the API/default so large-output callers have an explicit supported path.

## Reproduction Assessment

Yes from source inspection: current main appends child stdout/stderr chunks without any byte cap in `NodeExecutionEnv.exec`. The PR body also includes a negative-control terminal run where the same real-child-process proof script fails against old code and passes after the fix.

## Solution Assessment

Yes, with a compatibility caveat: bounding capture inside `NodeExecutionEnv.exec` is the narrow owner-boundary fix, and the sibling `src/process/exec.ts` path already uses a 16 MiB output cap. The remaining question is maintainer acceptance of default truncation for existing large-output harness consumers.
