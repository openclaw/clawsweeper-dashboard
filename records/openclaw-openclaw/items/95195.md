## What This Changes

The branch adds a per-stream 16 MiB stdout/stderr capture cap and `maxOutputBytes` override to `NodeExecutionEnv.exec`, with regression tests for truncation, UTF-8 boundaries, and callback continuation.

## Best Possible Solution

Land bounded capture as the harness contract once maintainers accept the default truncation tradeoff; otherwise revise the default or opt-up API before merge.

## Reproduction Assessment

Yes from source inspection: current main appends child stdout and stderr chunks without any byte cap in `NodeExecutionEnv.exec`. The PR body also includes after-fix and negative-control terminal output from a script driving real child processes through the real harness exec path.

## Solution Assessment

Yes, with a compatibility caveat: the owner-boundary fix belongs in `NodeExecutionEnv.exec`, and the adjacent process exec helper already has a 16 MiB output cap. The unresolved part is maintainer acceptance of default truncation for existing large-output harness consumers.
