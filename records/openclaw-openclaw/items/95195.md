## Summary

Keep open: the PR addresses a real unbounded capture problem that is still present on current main and the latest release, and I found no blocking code-review findings. Maintainer review is still needed because the default 16 MiB truncation changes the exported shell execution return contract for large-output callers.

## What This Changes

The PR caps `NodeExecutionEnv.exec` stdout/stderr capture at 16 MiB per stream, adds `maxOutputBytes` to `ExecutionEnvExecOptions`, and adds real child-process regression tests.

## Best Possible Solution

Land the bounded capture after maintainers accept the 16 MiB per-stream default, or revise the PR so full returned output remains the default and bounding is opt-in or explicitly opt-up.
