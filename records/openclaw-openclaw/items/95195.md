## Summary

Keep this PR open: current main and the latest release still accumulate `NodeExecutionEnv.exec()` stdout/stderr without a byte cap, while the PR adds a focused bounded-capture implementation with no blocking correctness findings. The remaining decision is maintainer acceptance of changing the default capture contract for outputs above 16 MiB.

## What This Changes

The PR adds a 16 MiB per-stream stdout/stderr capture cap to `NodeExecutionEnv.exec()`, exposes `maxOutputBytes` on `ExecutionEnvExecOptions`, and adds real-child-process regression tests.

## Best Possible Solution

Land bounded harness capture once maintainers accept the default truncation tradeoff, with `maxOutputBytes` as the explicit opt-up path for callers that need larger captures.

## Reproduction Assessment

Yes. Current main source shows unbounded stdout/stderr string accumulation in `NodeExecutionEnv.exec`, and the PR body includes a negative-control terminal run where the same real-child-process proof fails before the fix and passes after it.

## Solution Assessment

Yes, with a compatibility caveat. Bounding capture in `NodeExecutionEnv.exec` is the narrow owner-boundary fix, and the remaining question is whether the 16 MiB default is the right harness contract.
