## Summary

Keep open: current main still accumulates `NodeExecutionEnv.exec` stdout/stderr without a byte cap, while this PR is a focused OOM-prevention fix with sufficient terminal proof and no blocking code-review findings. The remaining merge question is maintainer acceptance of changing the default captured-output contract above 16 MiB.

## What This Changes

The PR adds a 16 MiB per-stream stdout/stderr capture cap to `NodeExecutionEnv.exec`, exposes `maxOutputBytes` on `ExecutionEnvExecOptions`, and adds real-child-process regression tests.

## Best Possible Solution

Land bounded capture as the harness contract once maintainers accept the 16 MiB default; otherwise revise the default or opt-up contract before merge.

## Reproduction Assessment

Yes. Source inspection shows current main appends stdout and stderr chunks without a byte cap in NodeExecutionEnv.exec, and the PR body includes a negative-control terminal run where old code fails the same real-child-process proof script.

## Solution Assessment

Yes, with a compatibility caveat. Bounding capture inside NodeExecutionEnv.exec is the narrow owner-boundary fix, and the sibling process exec path already uses a 16 MiB cap; maintainers still need to accept the default truncation tradeoff.
