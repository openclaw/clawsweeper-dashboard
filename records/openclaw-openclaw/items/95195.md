## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.85

Full review comments:

- **[P2] Keep stdout and stderr truncation state separate:** `packages/agent-core/src/harness/env/nodejs.ts:361-362`
  - body: A stdout overflow sets one global `outputTruncated` flag, so later stderr chunks return before the stderr cap or marker path runs. Commands that print a large stdout prefix and then useful stderr diagnostics will return with that stderr silently missing; track truncation per stream or make an explicit combined-output contract and test it.
  - confidence: 0.84
- **[P2] Trim overflow by bytes, not UTF-16 indexes:** `packages/agent-core/src/harness/env/nodejs.ts:368`
  - body: `remaining` is a byte budget from `Buffer.byteLength`, but `chunk.slice(0, remaining)` slices UTF-16 code units. Multibyte output can exceed `maxOutputBytes`, so keep Buffer chunks or use byte-aware decoding and add multibyte coverage.
  - confidence: 0.82
- **[P3] Expose maxOutputBytes through ExecutionEnvExecOptions:** `packages/agent-core/src/harness/env/nodejs.ts:274`
  - body: The override is added only to `NodeExecutionEnv.exec`'s inline parameter type. Callers typed as `ExecutionEnv` or `Shell` still use `ExecutionEnvExecOptions`, so the advertised override is unavailable without casts.
  - confidence: 0.8
