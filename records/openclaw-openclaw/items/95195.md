## Summary

Keep this PR open for maintainer review: the patch addresses a real agent-core availability risk and has strong proof, but the new 16 MiB default changes the returned stdout/stderr contract for large-output `Shell.exec` callers.

## What This Changes

Adds a 16 MiB per-stream stdout/stderr capture cap to `NodeExecutionEnv.exec`, exposes `maxOutputBytes` on `ExecutionEnvExecOptions`, and adds real child-process regression coverage.

## Best Possible Solution

Land the bounded capture only after maintainers accept the 16 MiB per-stream default, or revise the PR so large-output callers retain the intended default contract through an explicit cap opt-in or opt-up path.
