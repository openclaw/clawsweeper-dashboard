## Summary

Keep open: current main still has unbounded `NodeExecutionEnv.exec` stdout/stderr capture, and the PR is a focused, well-proven fix with no blocking code findings. The remaining issue is maintainer acceptance of the compatibility-sensitive default truncation contract.

## What This Changes

The PR adds a default 16 MiB per-stream stdout/stderr capture cap to `NodeExecutionEnv.exec`, exposes `maxOutputBytes`, and adds real-child-process regression tests.

## Best Possible Solution

Land bounded capture once maintainers accept the default truncation contract, with `maxOutputBytes` as the explicit opt-up path for unusually large captures.

## Reproduction Assessment

Yes from source inspection: current main appends child stdout/stderr chunks into strings with no byte cap in `NodeExecutionEnv.exec`. The PR body also includes a negative-control live-output proof where old code fails the cap assertions.

## Solution Assessment

Yes, with a compatibility caveat: bounding capture inside `NodeExecutionEnv.exec` is the owner-boundary fix, and sibling `src/process/exec.ts` already uses a 16 MiB bounded-output pattern. The safer alternative would be an explicit non-default cap only if maintainers consider full returned capture a required contract.
