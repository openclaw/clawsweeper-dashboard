## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.87

Full review comments:

- **[P2] Record output-cap termination before killing the child:** `packages/agent-core/src/harness/env/nodejs.ts:370`
  - body: This new path kills the child when output crosses the cap, but only sets `outputTruncated`. The close handler still falls through to `ok({ ..., exitCode: code ?? 0 })`, so a command killed by the cap can be persisted as a successful exit when no numeric code is available. Track the cap as a terminal state and return an explicit error/nonzero result or preserve the signal.
  - confidence: 0.86
- **[P3] Expose maxOutputBytes on the shared exec options:** `packages/agent-core/src/harness/env/nodejs.ts:274`
  - body: The override is added only to `NodeExecutionEnv.exec`'s inline parameter type. The exported `ExecutionEnvExecOptions` used by `Shell` and `ExecutionEnv` still omits it, so callers typed against the public harness interface cannot use the advertised override without casts.
  - confidence: 0.81
- **[P3] Trim by bytes, not UTF-16 code units:** `packages/agent-core/src/harness/env/nodejs.ts:366`
  - body: `remaining` is a byte budget from `Buffer.byteLength`, but `chunk.slice(0, remaining)` slices UTF-16 code units. Non-ASCII output can retain more than `maxOutputBytes`; use Buffer/TextDecoder-style truncation or track buffers before decoding.
  - confidence: 0.78
