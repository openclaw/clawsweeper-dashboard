## Summary

Keep this PR open: current main and the latest release still accumulate `NodeExecutionEnv.exec` stdout/stderr without a cap, and the patch is a focused availability hardening change with no blocking correctness finding. The remaining merge question is maintainer acceptance of the new default truncation contract for large captured output.

## What This Changes

Adds a default 16 MiB per-stream stdout/stderr capture cap to `NodeExecutionEnv.exec`, exposes `maxOutputBytes` on `ExecutionEnvExecOptions`, and adds real-spawn regression tests.

## Best Possible Solution

Land the bounded capture only after maintainers accept the 16 MiB per-stream default, or revise the PR so large-output callers retain the intended default contract with an explicit cap opt-in or opt-up path.
