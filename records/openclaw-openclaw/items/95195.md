## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Keep exec callbacks flowing after capture truncation:** `packages/agent-core/src/harness/env/nodejs.ts:369-380`
  - body: The truncation path returns before calling `options?.onStdout`, and once `stdoutTruncated` is set later stdout chunks are ignored entirely. That changes the Shell exec callback contract from chunks as produced to chunks until capture fills, so callback-based streaming, parsers, or abort-on-output logic can miss the rest of the child output even though the child keeps running. The stderr branch has the same issue.
  - confidence: 0.92
- **[P2] Align maxOutputBytes with the implemented cap:** `packages/agent-core/src/harness/types.ts:263-264`
  - body: The exported option says it limits combined stdout+stderr bytes, but `NodeExecutionEnv.exec` applies the value independently to stdout and stderr. Callers using the shared Shell contract cannot tell whether `maxOutputBytes: 16 MiB` means total captured output or up to 16 MiB per stream, so either share one budget or document and test the per-stream contract.
  - confidence: 0.9
