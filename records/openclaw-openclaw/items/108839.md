## Summary

Keep this PR open for revision: the timeout hardening is useful, but it leaves a sibling installer download unbounded and lacks a real Docker smoke run demonstrating the new success and failure behavior.

## What This Changes

The PR adds 10-second connection and 300-second total-transfer timeouts to three curl-based installer downloads in the Docker install smoke runner.

## Best Possible Solution

Define one internal installer-fetch timeout policy shared by both Docker smoke scripts, apply it to every installer curl pipeline, retain the outer process timeout as a backstop, and prove both a successful install and a deliberately stalled download.
