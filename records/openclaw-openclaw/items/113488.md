## Summary

This remains a useful candidate fix for the linked CLI-startup regression. The latest commit addresses the earlier cache-boundary review concern by separating schema-preflight caching from the broader legacy-migration latch; the remaining merge blocker is a rebase/review refresh against current `main` because GitHub reports the branch as dirty.

## What This Changes

This PR lets ordinary CLI preflight use a scoped current-schema SQLite integrity check instead of a full database scan, while keeping full verification for Doctor, gateway startup migration checkpoints, quarantined databases, and actual schema migrations.

## System Context

Before a CLI command runs, OpenClaw loads configuration and may invoke state migration repair against the shared SQLite database. This change narrows the integrity work only for routine commands whose database is already current, while Doctor and startup migration paths retain the stronger full-database checks.
