## What This Changes

Add an opt-in Anthropic provider path that delegates long-context compaction to Anthropic’s server-side API while preserving existing local compaction behavior by default.

## System Context

Agent runs assemble provider-specific request payloads from configured model and compaction settings, then stream Anthropic responses back into session history. Server-side compaction would alter that request/response boundary and must preserve Anthropic compaction blocks for later turns.

## Architecture Diagram

flowchart LR
  A[Agent and session history] --> B[Agent compaction settings]
  B --> C[Anthropic provider request builder]
  A --> C
  C --> D[Anthropic Messages API]
  D --> E[Streaming response events]
  E --> F[Compaction blocks and usage]
  F --> G[Persisted next-turn history]

## Best Possible Solution

Adopt a maintainer-approved, opt-in Anthropic provider contract that sends only the current required beta/request fields, round-trips compaction blocks through session history, and leaves existing local compaction unchanged unless explicitly enabled.
