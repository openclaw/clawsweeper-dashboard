## Summary

Current main and v2026.7.1 still lack Anthropic-native server-side compaction, while Anthropic’s current API requires provider-specific request, continuation-block, and usage handling. This remains a valid focused feature tracker, and prior engagement from the project’s listed lead maintainer means it does not qualify for unsponsored-feature cleanup.

## What This Changes

Add opt-in Anthropic server-side compaction with provider request parameters, streamed compaction-block handling, continuation support, logging, tests, and documentation.

## Best Possible Solution

Add a provider-owned, opt-in Anthropic model parameter path that injects the current beta/request shape, round-trips typed compaction blocks, aggregates iteration usage, and explicitly defines coexistence with OpenClaw compaction and transcript maintenance, with focused transport, config, and documentation coverage.

Options:

- **Provider-owned model parameters (recommended):** Add Anthropic-specific opt-in parameters at `agents.defaults.models["anthropic/…"].params`, preserve existing OpenClaw compaction defaults, and define typed continuation and fallback behavior in the Anthropic transport.
- **Global compaction mode:** Add an Anthropic mode under `agents.defaults.compaction`, accepting a broader cross-provider configuration contract and its migration burden.
- **Keep unsupported:** Continue relying on OpenClaw and plugin compaction until a provider-neutral native-compaction abstraction is designed.
