## Summary

Keep this focused tracker open. Current main and v2026.7.1 still lack Anthropic-native server-side compaction, the prior implementation PRs closed unmerged, and Anthropic’s current API contract confirms the capability remains relevant; a maintainer must choose the public configuration owner and continuation semantics before implementation.

## What This Changes

Requests opt-in Anthropic-native server-side compaction with provider request shaping, compaction-block replay, streaming and stop-reason handling, logging, configuration, tests, and documentation.

## Best Possible Solution

Add an explicit opt-in owned by the bundled Anthropic provider for direct Anthropic models, preserving native compaction blocks through provider replay, aggregating iteration usage, and defining deterministic pause/continue behavior; add only the smallest generic core replay seam that the provider cannot express today.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Anthropic server-side compaction be a provider-owned model parameter with defined automatic continuation behavior, or should OpenClaw expose a broader generic context-management passthrough API?

Rationale: Both approaches are technically feasible, but they establish different public configuration contracts, security boundaries, and ownership for transcript continuation and usage accounting.

Likely owner: steipete

Owner reason: The strongest available history signal covers the Anthropic transport, shared compaction configuration, provider docs, and the prior product-review discussion.

Owner confidence: high

Options:

- **Provider-Owned Opt-In (recommended):** Add typed Anthropic model parameters and provider-owned replay/continuation handling, keeping the capability restricted to supported direct Anthropic routes.
- **Generic Passthrough:** Expose validated generic beta headers and context-management payloads, accepting the larger compatibility and security-review surface.
- **Keep Local Compaction Only:** Decline native transport integration and continue using OpenClaw or registered plugin summarization providers.

## Solution Assessment

No, not exactly as proposed. Placing provider-specific transport behavior under the shared compaction object risks mixing ownership; a typed Anthropic-provider opt-in with explicit replay and continuation semantics is the narrower maintainable design.
