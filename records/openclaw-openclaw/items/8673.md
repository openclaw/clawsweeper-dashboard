## Summary

Keep open: current main and v2026.6.11 still make one ordinary OAuth refresh call on the shared auth-profile path, and the only retry-like recovery is the refresh-token-reuse race; the remaining work is a maintainer-owned auth retry policy, not cleanup.

## What This Changes

The issue requests bounded retry handling for transient OAuth token refresh API failures so agent runs do not fail after a single network/API blip.

## Best Possible Solution

Add a bounded transient-error retry policy in the shared OAuth refresh owner path, reusing the existing retry utility and preserving lock, timeout, external-credential adoption, fallback, and refresh-token-reuse recovery behavior.
