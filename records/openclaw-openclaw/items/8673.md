## Summary

Keep open: current main and the latest release still perform a single ordinary shared auth-profile OAuth refresh attempt, while existing recovery covers locking, adoption, and refresh-token-reuse cases rather than generic transient provider or network failures.

## What This Changes

The issue requests bounded retry logic for transient OAuth token refresh failures so a single provider or network blip does not fail agent auth resolution.

## Best Possible Solution

Add a bounded transient-error retry policy in the shared OAuth refresh owner path using the existing retry utility, while preserving lock, timeout, fallback, and refresh-token-reuse behavior.
