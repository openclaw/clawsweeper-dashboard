## Summary

Keep open: current main and the latest release still make one ordinary shared auth-profile OAuth refresh attempt, and existing recovery only handles lock/adoption/fresh-token-reuse cases rather than generic transient provider or network failures.

## What This Changes

The issue requests bounded retry behavior for transient OAuth token refresh API failures so agents do not fail on a single temporary refresh error.

## Best Possible Solution

Add a bounded transient-error retry policy in the shared OAuth refresh owner path, reusing the existing retry utility while preserving lock, timeout, external-credential adoption, fallback, and refresh-token-reuse recovery behavior.
