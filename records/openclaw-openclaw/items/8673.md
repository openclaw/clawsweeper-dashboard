## Summary

Keep this issue open. Current main still makes one provider/plugin refresh call under a timeout and cross-agent lock; ordinary transient failures are not retried, while the existing second attempt is narrowly reserved for a changed credential after a `refresh_token_reused` race. The request fits the stability roadmap, but the retryable-error classifier and total lock-held latency need an auth-owner decision before implementation.

## What This Changes

Add bounded retry handling for transient failures during shared OAuth credential refresh without changing terminal or rotating-token recovery behavior.

## Best Possible Solution

Add one bounded shared retry policy around the refresh adapter only after defining a provider-safe transient-error classifier and a total lock-held retry budget; retain single-attempt behavior for terminal OAuth errors and the existing changed-credential race recovery.
