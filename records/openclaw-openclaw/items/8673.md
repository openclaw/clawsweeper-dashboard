## Summary

Keep open: current main and the latest release still perform one ordinary shared auth-profile OAuth refresh attempt, while the only retry-like recovery remains scoped to refresh-token reuse and adjacent MCP-specific work does not cover this issue.

## What This Changes

The issue requests bounded retry logic for OAuth token refresh so transient API or network failures do not immediately fail provider-backed agent runs.

## Best Possible Solution

Add a bounded transient-error retry policy in the shared OAuth refresh owner path, reusing retryAsync while preserving the global lock, hard timeout, external/main-store adoption, and refresh-token-reuse recovery behavior.

Rationale: The source gap is clear, but retrying auth refresh can mask terminal OAuth failures, change failure timing, and interact with provider-owned refresh hooks, so maintainer intent is needed before encoding policy.

- **Defer for live upstream proof:** Keep the issue open until a maintainer wants live provider failure proof before selecting generic retry behavior.
