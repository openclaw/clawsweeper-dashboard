Keep open: current main and v2026.6.11 still make a single ordinary auth-profile OAuth refresh attempt, while existing recovery only covers lock/adoption/fresh-token-reuse cases rather than generic transient network or provider failures.

## What This Changes

The issue requests bounded retry handling for transient OAuth token refresh failures in the shared auth-profile refresh path.

## Best Possible Solution

Add a bounded transient-error retry policy in the shared OAuth refresh owner path, reusing the existing retry utility while preserving lock, timeout, external-credential adoption, fallback, and refresh-token-reuse recovery behavior.
