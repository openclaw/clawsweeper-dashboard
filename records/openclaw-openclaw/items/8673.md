## Summary

Keep open: current main and the latest release still perform a single ordinary shared auth-profile OAuth refresh attempt, while the existing recovery paths cover lock/adoption and refresh-token-reuse cases rather than generic transient provider or network failures.

## What This Changes

The issue requests bounded retry logic for transient OAuth token refresh failures in the shared auth-profile refresh path.

## Best Possible Solution

Add a bounded transient-error retry policy in the shared OAuth refresh owner path, reusing retryAsync while preserving lock, timeout, adoption, fallback, and refresh-token-reuse behavior.
