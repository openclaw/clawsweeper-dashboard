## Summary

Keep this issue open: the latest release and current main still make one ordinary OAuth refresh attempt, while existing retry-like recovery is limited to changed credentials after a refresh-token-reuse race. The request is valid, but the unconditional retry helper proposed in the issue is unsafe without an auth-owner decision on retryable failures and the total refresh deadline.

## What This Changes

Add bounded retry handling for transient OAuth token refresh failures so a temporary provider or network error does not immediately fail an agent run.

## Best Possible Solution

Implement a bounded policy at the shared OAuth manager boundary using `retryAsync`, an explicit provider-safe transient classifier, and one overall deadline while preserving locking, credential adoption, fallback, and refresh-token-reuse recovery.
