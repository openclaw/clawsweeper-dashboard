## Summary

Keep open: current main and the latest release still perform one ordinary OAuth refresh attempt for transient provider/API failures, while existing recovery only retries the special refresh-token-reuse race and adjacent MCP/Codex work does not cover this shared auth-profile retry gap.

## What This Changes

The issue requests bounded retry behavior for transient OAuth token refresh failures in the auth-profile refresh path.

## Best Possible Solution

Add a bounded transient-error retry policy in the shared OAuth refresh owner path, reusing retryAsync and preserving the existing lock, timeout, provider hooks, adoption/fallback, and refresh-token-reuse recovery behavior.
