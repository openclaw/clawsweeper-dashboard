## Summary

Keep open: current main and the latest release still make one ordinary shared auth-profile OAuth refresh attempt, and existing recovery covers locks, adoption, fail-closed handling, and refresh-token-reuse cases rather than generic transient network, timeout, or 5xx refresh failures.

## What This Changes

Add bounded retry handling for transient OAuth token refresh failures in the shared auth-profile refresh path.

## Best Possible Solution

Add a bounded shared OAuth refresh retry policy using the existing retry utility, with an owner-approved transient classifier and focused auth-profile tests that preserve current lock, timeout, adoption, fallback, and refresh-token-reuse behavior.
