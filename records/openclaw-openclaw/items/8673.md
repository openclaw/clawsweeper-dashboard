## Summary

Keep this issue open. The supplied current-main review and discussion show that ordinary transient OAuth refresh failures still have no generic bounded retry, while the existing recovery retry is limited to a changed credential after a `refresh_token_reused` race; the linked retry PRs were closed unmerged. Likely related people: vincentkoc (high-confidence lifecycle history), visionik (locking/recovery history), and steipete (recent OAuth review).

## What This Changes

Add bounded retry handling for transient failures when OpenClaw refreshes OAuth credentials for agent auth profiles.

## System Context

Agent model requests resolve an auth profile, which may refresh an OAuth access token through a provider before the request proceeds. The refresh manager coordinates locking, timeouts, credential adoption, and fallback behavior, so a retry policy affects provider authentication availability across agents.

## Architecture Diagram

flowchart LR
  A[Agent model request] --> B[Auth profile resolver]
  B --> C[OAuth refresh manager]
  C --> D[Provider token endpoint]
  D --> E[Credential store and recovery]
  E --> F[Provider API request]

## Best Possible Solution

Add a shared, bounded retry policy in the auth-profile refresh manager only for an explicit provider-safe transient-error set, preserving the existing lock, timeout, credential-adoption, fallback, and refresh-token-reused behavior with focused regression tests.
