## Summary

Keep open: current main and the latest release still make the ordinary shared OAuth refresh path a single attempt, and no merged related PR implements bounded transient retry for this auth-profile flow.

## What This Changes

Request bounded retry/backoff for transient failures during OAuth token refresh so agents do not fail on one temporary provider or network error.

## Best Possible Solution

Add bounded transient-error retry in the shared OAuth refresh owner path using the existing retry utility, while preserving locks, timeouts, credential adoption, fallback, and refresh-token-reuse recovery behavior.
