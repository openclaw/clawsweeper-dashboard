## Summary

Keep this issue open. Current main and v2026.6.11 still make one ordinary provider refresh attempt; existing locking, timeout, credential-adoption, fallback, and reused-token recovery do not retry transient network or server failures. The remaining blocker is an auth-owner decision on the shared retry classifier and total latency budget.

## What This Changes

Add bounded retry handling for transient OAuth token refresh failures without retrying terminal OAuth errors.

## Best Possible Solution

Add a shared, bounded retry around the manager-owned refresh attempt using the existing retry utility, with a narrow classifier for transport errors, timeouts, 429, and 5xx responses; preserve locking, credential adoption, reused-token recovery, provider ownership, and final error causes, with focused success-after-retry, exhaustion, and invalid_grant coverage.

Likely owner: vincentkoc

Options:

- **Narrow shared retry (recommended):** Retry recognized transport, timeout, 429, and 5xx failures within a small total budget while leaving terminal and reused-token handling unchanged.
- **Provider-owned classification:** Extend provider refresh hooks to declare retryability and let each provider own its retry policy, accepting a larger compatibility-sensitive API change.
- **Retain single-shot refresh:** Keep the current latency and failure semantics and rely on fallback, restart, or re-authentication after transient refresh failure.

## Reproduction Assessment

Yes, source inspection provides a high-confidence reproduction path: force an expired OAuth credential, make the provider refresh throw a transient network or HTTP 500 error, and the manager performs one timed attempt before entering fallback/error handling. ## Solution Assessment

No, the proposed unconditional local withRetry helper is not the best solution because it would retry terminal OAuth errors and duplicate the repository retry primitive. The narrow maintainable solution is a manager-owned bounded policy with explicit transient classification and preservation tests for existing recovery paths.
