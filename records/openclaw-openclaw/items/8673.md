## Summary

Keep open: current main and the latest release still perform one ordinary shared auth-profile OAuth refresh attempt, and existing recovery is limited to lock/adoption/fallback and refresh-token-reuse cases rather than generic transient provider or network failures.

## What This Changes

Request to add bounded retry handling for transient OAuth token refresh failures in the shared auth-profile refresh path.

## Best Possible Solution

Approve and implement a bounded transient-error retry policy in the shared OAuth refresh owner path using retryAsync, preserving lock, timeout, adoption, fallback, and refresh-token-reuse behavior with focused tests.
