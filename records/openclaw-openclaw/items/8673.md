## Summary

Keep open: current main and v2026.6.11 still make one ordinary shared auth-profile OAuth refresh attempt, with recovery limited to lock/adoption/fresh-token-reuse cases rather than generic transient provider or network failures.

## What This Changes

The issue requests bounded retry/backoff for transient OAuth token-refresh failures in the shared auth-profile refresh path.

## Best Possible Solution

Implement a bounded shared OAuth refresh retry policy with retryAsync and focused tests while preserving the existing lock, timeout, credential adoption, fallback, plugin hook, and refresh-token-reuse behavior.
