## Summary

Keep open: current main and the latest release still perform one ordinary shared auth-profile OAuth refresh attempt, and the existing retry-like recovery is limited to refresh-token-reuse/adoption cases rather than generic transient provider or network failures.

## What This Changes

The issue requests bounded retry behavior for transient OAuth token refresh failures in the shared auth-profile refresh path.

## Best Possible Solution

Add a bounded transient-error retry policy in the shared OAuth refresh owner path, reusing retryAsync while preserving lock, timeout, external-credential adoption, fallback, refresh-token-reuse recovery, and provider-plugin semantics.
