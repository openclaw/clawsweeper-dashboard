## What This Changes

Ensure a newly created worktree-backed Control UI session is classified as Coding immediately and keeps its submitted model while delayed session and catalog metadata reconcile.

## System Context

The Control UI New Session page collects workspace, worktree, and model choices, submits them to the Gateway session controller, then opens the resulting chat. Session-list and catalog updates arrive asynchronously and determine how the new session is presented in the UI.

## Architecture Diagram

  B --> G[Selected model control]

## Best Possible Solution

Preserve the submitted worktree and model facts in the initial session presentation, merge later Gateway/catalog metadata without downgrading those facts, and add a delayed-metadata regression test that verifies the row stays in Coding with the chosen available model.
