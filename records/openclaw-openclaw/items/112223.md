## Summary

Keep this issue open for a maintainer product and permission-boundary decision. Current main documents the message tool as an outbound/channel-action surface and does not establish a portable history-read contract; the related archive-hook request overlaps in goal but does not supply this retrieval API.

## What This Changes

The issue requests a `history` or `list` action on the message tool so agents can retrieve raw channel or topic messages before acting.

## Best Possible Solution

Design a read-only, capability-gated history interface that clearly distinguishes OpenClaw-observed/persisted messages from provider-native retrieval, keeps provider-specific limits in channel plugins, and does not promise unavailable Telegram Bot API history.
