## Summary

Keep this PR open: it still lowers the Gateway call wrapper to 10 seconds for an invalid handshake-timeout environment value even though the shared preauth resolver falls back to the server’s 15-second timeout. The prior P1 contract concern remains unresolved after the branch’s merge-from-main commit, and the supplied evidence is mock/fake-timer coverage rather than after-fix real Gateway behavior proof.

## What This Changes

The PR extracts handshake-timeout environment parsing into a shared helper and changes Gateway call timeout selection so invalid `OPENCLAW_HANDSHAKE_TIMEOUT_MS` values no longer extend the wrapper timeout.

## Best Possible Solution

Keep Gateway call timeout selection aligned with the server’s resolved preauth timeout whenever a handshake timeout source is present, then demonstrate the corrected behavior against a real delayed Gateway connection with redacted terminal or runtime output.
