## Summary

The remaining work is a product and security-boundary decision, not conservative cleanup.

## What This Changes

The issue requests configurable pre-compaction warning events, a structured pre-compaction agent handoff window, and a bounded compaction deferral mechanism.

## Best Possible Solution

Define one maintainer-approved compaction lifecycle contract that reuses existing memoryFlush, notifyUser, hook, and checkpoint boundaries, adding opt-in warning or handoff behavior only with explicit timeout, audit, workspace scope, and approval-expiry rules.

Rationale: The source gap is clear, but handoff and DEFER semantics would add public config plus extra agent authority, workspace-write timing, checkpoint semantics, and possible approval carryover.

Likely owner: Peter Steinberger

Owner confidence: high

Options:

- **Adopt warning and checkpointed handoff first (recommended):** Add opt-in threshold warnings plus a structured handoff/checkpoint path while leaving agent-requested deferral out until authority semantics are settled.
- **Adopt full bounded deferral:** Allow ALLOW/BLOCK/DEFER semantics only with explicit max duration, audit trail, idempotent checkpoint matching, workspace scope, and approval-expiry rules.
- **Decline new lifecycle surface:** Keep memoryFlush, notifyUser, hooks, and checkpoint APIs as the supported compaction surfaces and document the supported recovery patterns.
