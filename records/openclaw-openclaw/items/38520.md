## Summary

Keep open: current main has adjacent pre-compaction memory flushes, opt-in user notices, lifecycle hooks, and compaction checkpoints, but it still lacks the requested configurable pre-threshold warning policy, structured agent handoff turn, and bounded agent-requested deferral. This remains product and security-boundary design work, not conservative cleanup.

## What This Changes

The issue requests pre-compaction warning events, a structured handoff opportunity, and a bounded deferral mechanism for long-running agent workflows.

## Best Possible Solution

Define one maintainer-approved, opt-in compaction lifecycle contract that reuses memoryFlush, notifyUser, hooks, and checkpoints, adding warning or handoff behavior only with explicit timeout, audit, workspace scope, and authorization rules.

Rationale: The request crosses public config, session persistence, lifecycle hooks, and security boundaries because it can grant agents extra write opportunities and carry or block authority across a compaction boundary.

Likely owner: steipete

Owner confidence: medium

Options:

- **Warning and handoff only (recommended):** Add a narrow opt-in warning plus structured handoff/checkpoint path, while deferring agent-requested compaction delays until authority semantics are settled.
- **Full bounded deferral:** Allow warning, handoff, and DEFER only with strict maximum duration, audit trail, idempotent checkpoint matching, approval expiry, and workspace/resource-scope validation.
- **Keep current surfaces:** Decline a new core lifecycle surface and keep memoryFlush, notifyUser, hooks, compaction providers, and checkpoints as the supported extension points.
