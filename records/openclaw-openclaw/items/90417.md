## Summary

Keep this PR open, but it is not merge-ready: the patch still adds an unowned external subprocess to a shared dispatch hot path and runs suppression after channel session recording rather than before the loop event enters OpenClaw state.

## What This Changes

The branch adds a `fleet-loop-guard` subprocess check in the shared provider dispatcher for Telegram, iMessage, and BlueBubbles contexts, plus mocked dispatcher tests and a deprecated migration prompt alias.

## Best Possible Solution

Use an OpenClaw-owned, in-process channel/SDK loop guard that runs during turn admission before session recording, with Telegram/iMessage/BlueBubbles regression coverage and real transport proof.
