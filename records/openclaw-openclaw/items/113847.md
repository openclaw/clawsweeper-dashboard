## Summary

Keep this PR open for a maintainer security-boundary decision. It fixes the reported replay breakage, but the new blanket transcript exception stores raw `token`, `code`, and `signature` query values that the existing redaction rule intentionally recognizes as sensitive; the PR does not establish that retaining every such value in persisted transcripts is an approved storage contract.

## What This Changes

The PR changes agent-transcript redaction to preserve URL query values during persistence while keeping the logging redaction path masked, with regression tests for text and structured tool arguments.

## System Context

Agent messages are redacted before being persisted as transcript state and later reloaded into future agent turns. The shared redaction module also serves logs and tool-display output, so its policy options determine whether a value is retained for replay or masked for safety.

## Best Possible Solution

Keep capability replay working only under an explicit, owner-approved transcript-security contract that distinguishes reusable capabilities from secrets, rather than globally exempting every sensitive query-name value from persistence redaction.
