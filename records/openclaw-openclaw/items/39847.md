Keep open. Current main and v2026.6.11 still parse outbound reply text before inbound metadata stripping, and the open same-repo fix candidate is unmerged and conflicting, so the reported security-sensitive leak remains necessary to track.

## What This Changes

The issue requests stripping OpenClaw inbound metadata from outbound reply payloads before channel delivery so Discord and other channels do not display internal Conversation/Sender context.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/50520 or a narrow replacement that strips leading inbound metadata before the first outbound directive parse while preserving media, reaction, silent-reply, citation-marker, and projection behavior.

## Solution Assessment

Yes in fix shape. The shared outbound payload-plan boundary before directive parsing is the narrow maintainable fix; per-channel compiled-bundle patches would miss sibling delivery paths and drift from source.
