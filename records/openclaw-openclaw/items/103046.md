## Summary

Keep open: the PR targets a real LSP parser memory/DoS boundary, but the patch is not merge-ready because it drops only the oversized header and can keep buffering the advertised body while the submitted proof is only a diff check.

## What This Changes

The PR adds a 10 MB Content-Length cap to the bundled LSP JSON-RPC message parser in `src/agents/agent-bundle-lsp-runtime.ts`.

## Best Possible Solution

Make oversized LSP frames fatal for the session or implement a bounded discard/read state that cannot retain body bytes, then add streaming oversized-frame coverage and redacted terminal proof.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source inspection: current main retains incomplete LSP frames in `session.buffer` and concatenates each stdout chunk, so an oversized declared frame with an ongoing body can grow memory. I did not execute a live repro in this read-only review.

## Solution Assessment

No. A parser/session-level cap is the right area, but skipping only the header is not the best fix; the session should fail or discard under a bounded state so the oversized body cannot accumulate.
