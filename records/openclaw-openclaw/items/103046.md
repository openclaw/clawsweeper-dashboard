## Summary

This PR should remain open: the oversized-frame hardening is useful and fixes the earlier infinite-drain problem, but the current head still rejects a response already parsed before a malformed trailing header, and the claimed proof does not exercise a real LSP subprocess.

## What This Changes

Adds a 10 MB LSP response-frame limit, drains rejected oversized bodies across stdout chunks, fails sessions on unsafe Content-Length values, and adds focused parser and handler tests.

## Best Possible Solution

Represent parsing as a closed outcome containing completed messages plus an optional protocol error, dispatch completed responses first, then fail the remaining session; retain an owner-approved bounded frame limit and prove ordinary and malformed traffic through an actual LSP subprocess.
