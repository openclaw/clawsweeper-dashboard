## Summary

The second commit fixes the earlier header-only drain bug, but the updated implementation creates a persistent denial-of-service state for non-safe `Content-Length` values and still lacks proof through the session handler that owns drain state.

## What This Changes

The PR adds a 10 MB limit to the embedded LSP stdio parser, drains finite oversized bodies across chunks, and adds parser-level regression tests.

## Best Possible Solution

Fail the LSP session before body-length arithmetic for invalid or non-safe lengths, reject pending requests through the existing failure lifecycle, and cover fragmented finite oversized input plus unsafe decimal input through the production incoming-data composition.
