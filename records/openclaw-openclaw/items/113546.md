## Summary

The reported failure is already addressed on current `main`: the backup volatile-path filter now classifies agent runtime `shell_snapshots` as disposable, and the archive layer tolerates a classified volatile entry disappearing before `lstat`. This is the same repair family merged through https://github.com/openclaw/openclaw/pull/98879 for the earlier canonical report.

## What This Changes

Exclude volatile Codex shell-snapshot files from backup traversal so a disappearing snapshot cannot abort backup creation.

## System Context

The backup CLI walks the OpenClaw state tree and packages durable configuration and user state into an archive. A centralized volatile-path filter decides which runtime caches may be skipped, and archive creation uses that decision to avoid failing on disposable files that disappear during traversal.
