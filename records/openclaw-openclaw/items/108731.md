## Summary

This PR remains open because the rebased guard still resolves the stderr failure by skipping every registration after CLI metadata, so the prior P1 concern remains: reduced runtimes lose non-state Codex surfaces that current main deliberately registers without touching state.

## What This Changes

The PR returns from Codex plugin registration after CLI metadata when `api.runtime.state.openSyncKeyedStore` is unavailable.

## Best Possible Solution

Keep registration lazy and complete: preserve all registrations that can bind against lazy stores or runtime getters, guard only the first operation that truly requires `openSyncKeyedStore`, and add a reduced-runtime regression test proving zero registration-time state access without losing expected surfaces.
