## Summary

This PR should remain open for repair: cache eviction closes an agent but does not bound agents owned by still-active fetch wrappers, and the revised implementation replaces the earlier typed SDK proposal with an undocumented cross-boundary symbol contract.

## What This Changes

Bounds the Zalo proxy-fetcher cache at 64 entries, adds eviction-time ProxyAgent disposal metadata to the shared proxy-fetch helper, and adds focused cache and dispatcher tests.

## Best Possible Solution

Give each active Zalo proxy consumer an explicit plugin-owned lifecycle or lease, release it when that consumer stops, and bound only idle reusable entries rather than treating Map eviction as ownership termination.

Yes at source level: a monitor retains the resolved fetch function after cache eviction, and the function can lazily create another ProxyAgent after the eviction hook clears its previous agent. The submitted proof does not exercise that retained-reference path.

## Solution Assessment

No. Bounding Map entries is useful, but disposal must follow the lifetime of active consumers; cache eviction alone is not a safe ownership boundary, and a private Symbol.for handshake is not the narrowest maintainable plugin contract.
