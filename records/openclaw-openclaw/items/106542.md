## Summary

Keep open: the revised branch addresses the prior lifecycle-boundary and proof concerns, but its URL-keyed release operation cannot identify the correct cache-entry generation when the same proxy URL is evicted and recreated while leases overlap.

## What This Changes

The PR bounds Zalo’s proxy-fetcher cache at 64 entries, moves ProxyAgent disposal into the Zalo plugin, leases monitor fetchers, and adds mocked and real-agent lifecycle tests.

## Best Possible Solution

Keep the 64-entry Zalo-local cache, but have acquisition return an opaque lease whose release closure captures the exact entry generation, then prove same-URL generations can be released in either order without closing a live agent or leaking a retired one.
