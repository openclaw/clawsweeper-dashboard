## Summary

Keep this PR open but do not merge the current head: the cache-size fix is useful, yet dispatcher disposal is not tied to consumer lifetime and the implementation creates an untyped private contract across the plugin boundary. The submitted proof demonstrates Map eviction, but not the claimed bound on live ProxyAgent dispatchers.

## What This Changes

Caps the Zalo proxy-fetcher cache at 64 entries, adds a close hook to the shared proxy-fetch wrapper, and adds focused tests plus a standalone production-path proof.

## Best Possible Solution

Use a typed, ownership-aware proxy-fetch handle whose dispatcher is released only after its last consumer stops; either keep that lifecycle Zalo-local or intentionally add and migrate a documented Plugin SDK seam, then prove churn and more than 64 concurrent retained consumers without untracked agents.
