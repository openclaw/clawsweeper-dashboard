## Summary

Keep open: this docs-only PR addresses a real downgrade-support gap, but its unconditional claim that `openclaw update` prevents incompatible downgrades is false for target packages that do not publish schema metadata. The narrow wording correction is needed before merge; the `maintainer` label also requires explicit maintainer handling.

## What This Changes

Adds troubleshooting documentation explaining one-way database migrations from the 2026.7.2 release train, downgrade recovery options, newer-schema startup failures, and quarantine recovery.

## Best Possible Solution

Keep the troubleshooting section, but qualify the updater guard as applying when the target publishes schema-version metadata and state that manual installs—and metadata-less older targets—can still reach the runtime refusal.
