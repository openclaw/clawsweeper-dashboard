## Summary

This PR remains necessary: current `main` still decodes a bounded successful Exa response with the non-fatal default `TextDecoder`, so malformed UTF-8 can become replacement characters before JSON parsing. The branch makes that single boundary reject invalid bytes through the existing malformed-JSON error path, has focused regression coverage, and includes sufficient real runtime proof; the remaining action is ordinary maintainer review after a merge-result refresh against current `main`.

## What This Changes

The PR makes Exa’s bounded successful-search response decoder reject malformed UTF-8 before JSON parsing and adds a regression test for a byte-invalid JSON body.

## System Context

The Exa plugin implements OpenClaw’s `web_search` provider path: tool arguments and configured credentials produce an Exa HTTP request, whose successful response is bounded, decoded, parsed, and returned as search results to the agent. This change sits at the byte-to-text boundary before provider result normalization.
