## Summary

Keep open: current main still lacks static per-binding or per-agent ACP permission defaults, and the remaining work is a security-sensitive public config contract rather than conservative cleanup.

## What This Changes

The issue requests static scoped ACP permission defaults for channel bindings and agent runtime config, falling back to the existing global ACPX plugin permission config.

## Best Possible Solution

Approve a generic scoped ACP permission-profile contract, then implement schema, binding materialization, runtime option propagation, docs, and security-focused regression coverage together.

Owner confidence: high

Options:

- **Use generic permissionProfile defaults (recommended):** Add scoped `permissionProfile` defaults that map through the existing ACP runtime option aliases, keeping ACPX-specific names at the plugin-global layer.
- **Add ACPX-specific scoped keys:** Implement the requested `permissionMode` and optional `nonInteractivePermissions` precedence directly for ACPX-backed sessions.
- **Keep global and session controls only:** Document global ACPX config plus `/acp permissions` as the supported paths and leave static scoped permission defaults out for now.

## Reproduction Assessment

Yes. Source inspection is enough: the strict binding and agent runtime schemas reject the requested scoped keys, binding materialization has no permission field, and ACPX runtime construction consumes only plugin-global permission config.

## Solution Assessment

Unclear. The proposed precedence is plausible, but maintainers should decide whether the durable public surface is generic `permissionProfile` defaults or ACPX-specific `permissionMode` keys.
