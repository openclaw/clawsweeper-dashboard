## Summary

Keep open: current main and the latest release still expose ACPX permission policy only as plugin-global config, while per-binding and per-agent ACP defaults cover agent/backend/mode/cwd but not permission scoping. The request remains a security-sensitive product/config decision, and the related ACP RFC and spawn-policy issue are adjacent rather than replacements.

## What This Changes

Request scoped ACP permission defaults so `bindings[].acp` and `agents.list[].runtime.acp` can override the global ACPX `permissionMode`.

## Best Possible Solution

Define one maintainer-approved scoped ACP permission contract that keeps `approve-reads` as the safe global default, supports binding and per-agent defaults with documented precedence, and adds schema/docs/tests for both fresh config and upgrade behavior.

## Reproduction Assessment

Yes, at source level: current main exposes global ACPX permission config and dynamic session permission profiles, but the typed per-agent and per-binding ACP defaults omit permission fields. No live runtime repro was run because this is a missing configuration capability rather than a regression with a failing command path.

## Solution Assessment

Unclear until maintainers choose the contract: adding scoped defaults is the right product direction, but the safest implementation should decide whether the public field is `permissionMode`, `permissionProfile`, or a broader policy object that also covers non-interactive behavior.
