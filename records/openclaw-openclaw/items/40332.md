## Summary

Keep open: current main and latest release still only support ACPX permission defaults through global plugin config or live session runtime options, while the requested static per-binding and per-agent defaults remain absent and security-sensitive.

## What This Changes

Request scoped ACPX permission defaults at `bindings[].acp` and `agents.list[].runtime.acp`, falling back to the current global `plugins.entries.acpx.config.permissionMode`.

## Best Possible Solution

Approve a generic scoped ACP permission-profile contract, then implement schema, binding materialization, runtime option propagation, docs, and security-focused regression coverage together.

Yes. Source inspection is enough: current main accepts ACPX `permissionMode` only through plugin config or live session runtime options, while persistent binding and agent runtime defaults do not carry the requested static permission fields.

## Solution Assessment

Unclear pending maintainer intent. The requested precedence matches existing ACP binding defaults, but the best durable solution is likely a generic scoped permission-profile contract rather than copying ACPX-specific names into every config layer.
