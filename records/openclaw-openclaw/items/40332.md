## Summary

Keep open: current main and v2026.6.11 still lack static per-binding or per-agent ACP permission defaults, so the security-scoping request remains valid and is not superseded by the newer per-session runtime option controls.

## What This Changes

The issue requests scoped ACP permission policy so configured ACP bindings or per-agent ACP runtime defaults can override the current global ACPX permissionMode fallback.

## Best Possible Solution

Define a maintainer-approved scoped ACP permission-profile contract, then implement schema, binding materialization, runtime option propagation, docs, and security-focused tests together.

## Reproduction Assessment

Yes. As a source-level feature gap, current strict schemas reject the requested scoped keys and the ACPX runtime path consumes only plugin-global permission config.

## Solution Assessment

Unclear. The proposed precedence is plausible, but maintainers should first decide whether the public config should expose generic `permissionProfile` defaults or ACPX-specific `permissionMode` keys.
