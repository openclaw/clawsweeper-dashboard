## Summary

Keep open: current main and latest release v2026.6.11 still lack per-binding or per-agent ACP permission defaults, and the remaining work is a security-sensitive public config contract rather than conservative cleanup.

## What This Changes

The issue requests scoped ACP permission defaults on `bindings[].acp` and `agents.list[].runtime.acp`, with global ACPX plugin config as the fallback.

## Best Possible Solution

Approve a generic scoped ACP permission-profile contract, then update schemas, binding materialization, runtime option propagation, docs, and security-focused regression coverage together.

Options:

- **Use Generic Permission Profiles (recommended):** Add scoped `permissionProfile` defaults that map through the existing ACP runtime option alias layer, keeping ACPX-specific names at plugin-global setup unless explicitly needed.
- **Add ACPX-Specific Scoped Keys:** Implement the requested `permissionMode` and optional `nonInteractivePermissions` precedence directly for ACPX sessions, accepting a backend-specific public config surface.
- **Keep Global Config Only:** Document `/acp permissions` and global ACPX config as the supported paths and leave static scoped permission defaults out for now.

Yes. Source inspection is enough: strict config schemas reject the requested scoped keys, and ACPX runtime construction currently consumes only plugin-global permission config.

## Solution Assessment

Unclear. The requested precedence is plausible, but maintainers should decide whether the durable surface is generic `permissionProfile` defaults or ACPX-specific permission keys.
