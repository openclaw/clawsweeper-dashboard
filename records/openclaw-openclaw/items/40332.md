## Summary

Keep open: current main and latest release still only expose ACPX permission defaults through global plugin config, while per-binding and per-agent ACP permission defaults remain absent and security-sensitive.

## What This Changes

Request scoped ACP permission defaults at the binding and per-agent runtime levels, falling back to global ACPX plugin config.

## Best Possible Solution

Approve one durable scoped ACP permission contract, preferably a generic `permissionProfile` default, then implement schema, binding materialization, runtime option propagation, docs, and security regression coverage together.

Question: Should scoped ACP permission defaults be exposed as a generic `permissionProfile` contract on `bindings[].acp` and `agents.list[].runtime.acp`, or as ACPX-specific `permissionMode` and `nonInteractivePermissions` keys?

Rationale: The source gap is clear, but the durable public config shape controls write and shell authority for non-interactive channel-bound sessions and needs explicit maintainer/security intent.

Likely owner: osolmaz

Owner reason: He owns the ACP runtime/control-plane and ACPX integration history most likely to define the durable permission contract.

Owner confidence: high

Options:

- **Use generic permissionProfile defaults (recommended):** Add scoped `permissionProfile` defaults that map through the existing ACP runtime option alias layer, keeping ACPX-specific names at the plugin-global layer.
- **Add ACPX-specific scoped keys:** Implement the requested `permissionMode` and optional `nonInteractivePermissions` precedence directly for ACPX sessions, accepting a backend-specific config surface.
- **Keep global config only:** Document `/acp permissions` and global ACPX config as the supported paths and leave static scoped permission defaults out for now.

## Reproduction Assessment

Yes. Source inspection is enough: current strict schemas reject the requested scoped keys, and ACPX runtime construction currently consumes only plugin-global permission config.

## Solution Assessment

Unclear. The requested precedence is plausible, but the best maintainable solution likely needs a maintainer decision between generic `permissionProfile` defaults and ACPX-specific scoped keys.
