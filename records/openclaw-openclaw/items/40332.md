## Summary

Keep open: current main and v2026.6.11 still lack static per-binding or per-agent ACP permission defaults, while the requested change affects write/shell authority and needs maintainer-approved config/security direction.

## What This Changes

Add scoped ACP permission defaults for bindings and per-agent ACP runtime config, falling back to the current global ACPX plugin permission config.

## Best Possible Solution

Approve a generic scoped ACP permission-profile contract, then implement schema, binding materialization, runtime option propagation, docs, and security-focused regression coverage together.

Question: Should scoped ACP permission defaults be exposed as generic permissionProfile defaults on bindings[].acp and agents.list[].runtime.acp, as ACPX-specific permissionMode/nonInteractivePermissions keys, or not exposed as static config?

Rationale: The source gap is clear, but the public shape controls write and shell authority for non-interactive ACP sessions and could either align with generic ACP runtime options or create a backend-specific parallel config surface.

Owner confidence: high

Options:

- **Use generic permissionProfile defaults (recommended):** Add scoped permissionProfile defaults that flow through the existing ACP runtime option layer, keeping ACPX-specific permissionMode names at the plugin-global layer.
- **Add ACPX-specific scoped keys:** Implement the requested permissionMode and optional nonInteractivePermissions precedence directly for ACPX sessions, accepting a backend-specific public config surface.
- **Keep global config only:** Document global ACPX config and live ACP runtime controls as the supported paths, leaving static scoped permission defaults out for now.

## Reproduction Assessment

Yes. Source inspection is enough: strict binding and agent runtime schemas reject the requested scoped keys, and current ACPX runtime construction consumes permission policy only from plugin-global config.

## Solution Assessment

Unclear. The requested precedence is plausible, but maintainers should choose whether the durable public surface is generic permissionProfile defaults or ACPX-specific permissionMode keys before code is queued.
