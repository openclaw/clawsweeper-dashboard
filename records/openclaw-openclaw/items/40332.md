## Summary

Keep open: current main and the latest release still lack static per-binding or per-agent ACP permission defaults, and the remaining work is a security-sensitive public config contract rather than conservative cleanup.

## What This Changes

Request scoped ACP permission defaults for ACP sessions at `bindings[].acp` and `agents.list[].runtime.acp`, falling back to global ACPX plugin config.

## Best Possible Solution

Approve a generic scoped ACP permission-profile contract, then add schema, binding materialization, manager runtime-option propagation, docs, and security-focused regression coverage together.

Options:

- **Use generic permissionProfile defaults (recommended):** Add scoped `permissionProfile` defaults that map through the existing ACP runtime option aliases, keeping ACPX-specific names at the plugin-global layer.
- **Add ACPX-specific scoped keys:** Implement the requested `permissionMode` and optional `nonInteractivePermissions` precedence directly for ACPX-backed sessions.
- **Keep global and session controls only:** Document global ACPX config plus `/acp permissions` as the supported paths and leave static scoped permission defaults out for now.

Unclear. The proposed precedence is plausible, but maintainers should decide whether the durable public surface is generic `permissionProfile` defaults or ACPX-specific `permissionMode` keys.
