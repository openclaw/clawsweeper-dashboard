## Summary

Keep open: current main still has only plugin-global ACPX permission defaults plus live per-session tuning, not declarative per-binding or per-agent ACP permission policy, and the requested scoped auto-approval behavior is a security-sensitive config contract.

## What This Changes

The issue requests `permissionMode` and related non-interactive ACP permission policy overrides on ACP bindings and per-agent ACP runtime defaults, falling back to the existing ACPX plugin-level config.

## Best Possible Solution

Define one canonical scoped ACP permission policy at ACP session preparation, with schema/docs/tests for binding, agent-runtime, plugin fallback, and security-audit behavior before implementation.

## Solution Assessment

Unclear until maintainers choose the security contract. The existing `/acp permissions` per-session override is useful but not the same as declarative per-binding or per-agent defaults for new ACP sessions.
