## Summary

The PR addresses a reproduced QQ Bot message-loss bug with strong live-output evidence, but it should not merge yet because the new processing watermark also becomes the heartbeat sequence, conflating two protocol cursors and risking reconnect/replay churn during slow handlers.

## What This Changes

The branch adds a settlement-aware QQ Bot sequence watermark, wires queue completion and intentional drops into it, persists the resumable watermark, and adds focused gateway and watermark regression tests.

## Best Possible Solution

Keep separate `latestReceivedSeq` and `resumeWatermark` state: update the receive cursor for every sequenced frame and use it only for heartbeats, while persistence and RESUME use the settlement-aware watermark; add a regression that holds a handler open and verifies both cursor values.
