## Summary

The prior heartbeat-cursor finding is fixed, but the branch still lets one permanent handler failure pin the connection-wide RESUME watermark, causing later successfully processed QQ Bot events to replay and potentially duplicate after every reconnect or restart.

## What This Changes

Adds a settlement-aware QQ Bot RESUME sequence watermark, separates heartbeat and resume cursors, wires queue terminal states into cursor advancement, and adds focused gateway and watermark tests.

## Best Possible Solution

Keep the settlement watermark and heartbeat separation, but either treat logged handler failures as terminal drops or stop all later sequence processing until the failed sequence succeeds; add a failure-then-success-reconnect regression covering later and cross-peer events.

- **Accept replay amplification:** Land the current behavior knowing one persistent handler failure can replay all later connection-wide events on subsequent reconnects.

## Solution Assessment
