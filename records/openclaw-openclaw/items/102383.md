Full review comments:

- **[P1] Retry declaration convergence after ambiguous adds:** `src/claws/cron.ts:242-245`
  - body: Persisting `failed` after any thrown or unrecognized `cron.add` outcome loses the distinction between definite failure and unknown result. If the Gateway created the declaration but its response was lost, the full add cannot be retried because the agent already exists, while a direct cron retry collides with the persisted primary key. Preserve an ambiguous state and reconcile by `declarationKey` before retrying.
  - confidence: 0.99
- **[P1] Make cron removal retry-safe after local deletion fails:** `src/claws/lifecycle-state.ts:386-394`
  - body: A successful `cron.remove` is followed by `deleteClawCronRef` inside the same catch. If that local write fails, the result reports cleanup failure but retains a complete reference; retry then repeats remote deletion instead of completing local reconciliation. Persist a remote-removed state or otherwise make the retry finish only the remaining local cleanup.
  - confidence: 0.99
- **[P2] Register ownership in the canonical state schema:** `src/claws/cron.ts:53-68`
  - body: Creating `claw_cron_refs` lazily in this feature module bypasses the shared state database schema and generated Kysely types, so fresh and upgraded databases have no centrally versioned contract for this durable table. Add it to the canonical schema and migration owner and use the shared typed helpers.
  - confidence: 0.98
