Keep open. The latest head addresses the earlier ambiguous-add, schema-registration, session-target, and Claw-specific offline-fallback findings, but canonical `agents.delete` still commits the config deletion before cron teardown. A scheduler failure can therefore leave recurring work active after the agent is gone, without a safe retry through the same RPC.

## What This Changes

The PR adds Gateway-managed Claw cron installation, durable ownership records, status/export integration, and cron-aware Claw and agent deletion behavior.

## Best Possible Solution

Make canonical agent deletion either disable all owned cron jobs before committing config mutation or persist a durable retryable deletion record, then prove success, partial failure, and retry against a real Gateway before landing the stack.

Rationale: External scheduler mutation and the config commit cannot share one transaction; maintainers must choose whether deletion fails closed before config mutation or commits a durable retryable teardown state.

- **Fail closed before config deletion (recommended):** List and remove owned cron jobs first, keep the agent configured on any scheduler failure, and add ordering and retry regressions.

## Solution Assessment

No. Gateway-owned scheduler mutation and declaration-key reconciliation are appropriate boundaries, but cron teardown must be ordered or durably checkpointed with canonical agent deletion rather than occurring after the irreversible config commit.
