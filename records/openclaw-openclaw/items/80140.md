## Best Possible Solution

Repair the PR before merge by sending watchdog heartbeats with the supported `WATCHDOG=1` payload, settling default-on versus opt-in supervision, removing the release-owned changelog edit, and proving the behavior on a Linux systemd service.

No live high-confidence hung-gateway reproduction was run. The patch defect is source/dependency-reproducible because the proposed helper sends `systemd-notify --watchdog`, which local systemd 255 rejects, while the service watchdog contract requires `WATCHDOG=1`.

## Solution Assessment

No, not as written. Reusing the existing 30-second maintenance tick is a plausible narrow design, but the implementation must use the supported systemd watchdog payload and be proven on a Linux systemd service before defaulting generated units to watchdog supervision.
