## What This Changes

The issue requests clearer separation between standalone Codex CLI credentials and gateway-managed OpenAI profiles, plus a headless or discoverable recovery path for expired gateway authentication.

## System Context

OpenClaw’s model-auth commands manage credentials used by the gateway’s provider runtime, while the standalone Codex CLI maintains its own OAuth session. When a gateway profile expires, model routing and user-facing recovery guidance determine whether an operator can restore provider access.

## Architecture Diagram

flowchart LR
  A[Standalone Codex CLI login] --> B[Codex CLI credential store]
  C[OpenClaw models auth] --> D[Gateway OpenAI profile store]
  D --> E[Gateway provider routing]
  E --> F[Model request or auth failure]
  F --> G[CLI or chat recovery guidance]

## Best Possible Solution

First establish the current supported OpenAI gateway-profile recovery contract; then make the distinction explicit in `models auth` help and expired-auth guidance, and add a noninteractive/device recovery flow only if the inspected Codex and provider contracts safely support it.
