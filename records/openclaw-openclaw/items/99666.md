## Summary

Keep open: current main and the latest release still give the managed-service helper a 60s parent-exit window while the Gateway restart drain can wait up to 300s, so the reported self-update timeout remains a valid source-reproducible updater bug.

## What This Changes

The issue reports that npm self-update can fail during Gateway restart because the managed-service parent handoff timeout is shorter than the Gateway active-work drain.

## Best Possible Solution

Align the managed-service helper parent-exit timeout with the Gateway restart drain budget plus bounded shutdown overhead, preserving service recovery and sentinel behavior without adding new configuration.

## Reproduction Assessment

Yes, at source level: current main can wait up to 300s for restart drain, but the managed-service helper reports parent timeout after only 60s if the Gateway process is still alive. I did not run a live Windows npm-global update in this read-only review.

## Solution Assessment

Yes in direction: the narrow fix belongs at the managed-service handoff/restart-timeout boundary, not in a new config option or the broader updater architecture work.
