## Summary

Keep open: current main and v2026.6.11 still let the managed-service handoff fail after a fixed 60s parent-exit wait, while the Gateway restart path can legitimately drain active work for up to 300s, so the reported updater failure remains source-reproducible.

## What This Changes

The issue reports that npm/global self-update can fail with `managed-service-handoff-parent-timeout` when the managed helper gives up before the Gateway finishes draining active tasks.

## Best Possible Solution

Align the managed-service helper's parent-exit timeout with the effective Gateway restart drain budget plus shutdown overhead, while preserving existing sentinel, service-recovery, and supervisor-specific behavior without adding a new user-facing setting.

## Reproduction Assessment

Yes, at source level: current main can drain restart work for up to 300s, but the managed-service helper reports parent timeout after only 60s plus restart delay if the Gateway process is still alive. I did not run a live Windows npm-global update in this read-only review.

## Solution Assessment

Yes in direction: the narrow fix belongs at the managed-service handoff and restart-drain budget boundary, not in a new config option or broader updater redesign.
