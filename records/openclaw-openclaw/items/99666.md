## Summary

Keep open: current main and v2026.6.11 still use a fixed 60s managed-service parent-exit grace while Gateway restart draining can run for 300s, and the open closing PR that changes this timeout has not merged.

## What This Changes

The issue asks OpenClaw Gateway self-update handoff to wait long enough for active work to drain instead of failing with `managed-service-handoff-parent-timeout`.

## Best Possible Solution

Review and land or deliberately replace https://github.com/openclaw/openclaw/pull/99695 so the managed-service parent-exit wait matches the Gateway restart drain budget.

## Reproduction Assessment

Yes. Source inspection shows the handoff helper can time out after restart delay plus 60s while the Gateway restart drain budget defaults to 300s; no live Windows npm-global update was run in this read-only review.

## Solution Assessment

Yes in direction. The narrow fix belongs in the managed-service handoff timeout calculation using the existing update timeout/restart-drain contracts, and the linked PR is the current implementation candidate.
