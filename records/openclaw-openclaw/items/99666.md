## Summary

Keep open: current main and v2026.6.11 still use a fixed 60s managed-service parent-exit grace, while the Gateway restart path can drain active work for about 300s plus shutdown time. The linked open PR is the current candidate fix, so this issue should close only after that PR lands or is deliberately replaced.

## What This Changes

Gateway/npm self-update should let the managed-service handoff wait through active-task drain instead of failing with `managed-service-handoff-parent-timeout`.

## Best Possible Solution

Review and land or deliberately replace https://github.com/openclaw/openclaw/pull/99695; then close this issue once main aligns the parent-exit wait with the Gateway restart drain budget.

## Reproduction Assessment

Yes, at source level. Current main can wait only restart delay plus 60s in the handoff helper while the Gateway restart path can drain active work for 300000ms plus shutdown time; no live Windows npm-global update was run in this read-only review.

## Solution Assessment

Yes in direction. The narrow fix belongs in the shared managed-service handoff timeout calculation using the existing timeout and restart-drain contracts, while the issue stays open until the linked implementation lands or is replaced.
