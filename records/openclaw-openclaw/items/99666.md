## Summary

Keep open: current main and the latest release still compute the managed-service parent-exit wait as restart delay plus a fixed 60s grace, while the Gateway restart path can drain active work for 300s plus shutdown time. The linked open PR owns the narrow fix path, so this issue should stay open until that PR lands or is deliberately replaced.

## What This Changes

The issue reports that npm-managed Gateway self-update can fail with `managed-service-handoff-parent-timeout` because the handoff parent-exit wait expires before the Gateway finishes draining active tasks.

## Best Possible Solution

Review and land or deliberately replace https://github.com/openclaw/openclaw/pull/99695 so the managed-service handoff parent-exit wait covers the Gateway restart drain budget plus shutdown reserve.

## Reproduction Assessment

Yes. At source level, current main can drain restart work for 300000ms plus shutdown time while the managed-service helper can report parent timeout after only restart delay plus 60000ms; no live Windows npm-global self-update was run in this read-only review.

## Solution Assessment

Yes in direction. The narrow fix belongs in the shared managed-service handoff timeout calculation using existing timeout and restart-drain contracts, and the issue should remain open while the linked implementation candidate is still unmerged.
