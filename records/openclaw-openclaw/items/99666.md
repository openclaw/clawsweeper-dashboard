## Summary

Keep open: current main and the latest release still compute the managed-service parent-exit wait as restart delay plus a fixed 60s grace, while Gateway restart draining can last 300s plus shutdown time. The issue has an open linked fix PR with closing syntax, so this should remain open until that PR lands or is deliberately replaced.

## What This Changes

The issue reports that npm-managed Gateway self-update can fail with `managed-service-handoff-parent-timeout` because the managed-service helper stops waiting before the Gateway finishes draining active work.

## Best Possible Solution

Review and land or deliberately replace https://github.com/openclaw/openclaw/pull/99695; this issue should close only after current main aligns the parent-exit wait with the Gateway restart drain budget.

## Reproduction Assessment

Yes. At source level, current main can drain restart work for 300000ms plus shutdown time while the managed-service helper can report parent timeout after only restart delay plus 60000ms; no live Windows npm-global self-update was run in this read-only review.

## Solution Assessment

Yes in direction. The narrow fix belongs in the managed-service handoff timeout calculation using existing timeout and restart-drain contracts, and the issue should remain open while the linked implementation candidate is still unmerged.
