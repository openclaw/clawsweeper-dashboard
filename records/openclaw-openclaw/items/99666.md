## Summary

Keep open: current main and the latest release still compute the managed-service parent-exit wait as restart delay plus a fixed 60s grace, while the Gateway restart drain path can wait 300s plus shutdown time. The open linked fix candidate at https://github.com/openclaw/openclaw/pull/99695 uses closing syntax for this issue, so this issue should remain open until that PR lands or is deliberately replaced.

## What This Changes

The issue reports that npm-managed Gateway self-update can abort with `managed-service-handoff-parent-timeout` because the managed-service parent handoff wait is shorter than the active-task drain window.

## Best Possible Solution

Review and land or deliberately replace https://github.com/openclaw/openclaw/pull/99695; this issue should close only after main aligns the parent-exit wait with the Gateway restart drain budget.

## Reproduction Assessment

Yes. At source level, current main can drain restart work for up to 300000ms plus shutdown time while the managed-service helper can report parent timeout after only restart delay plus 60000ms; no live Windows npm-global self-update was run in this read-only review.

## Solution Assessment

Yes in direction. The fix belongs in the shared managed-service handoff timeout calculation using existing timeout inputs and the Gateway drain budget, and the issue should remain open while the linked implementation candidate is still unmerged.
