## Summary

Keep open: current main and the latest release still use a fixed 60s managed-service handoff parent wait, while the Gateway restart path can drain active work for about 300s plus shutdown time. The open linked PR is the right implementation candidate, so this issue should stay open until that PR lands or is deliberately replaced.

## What This Changes

The issue requests that managed-service self-update handoff wait long enough for Gateway active-work drain instead of failing with `managed-service-handoff-parent-timeout`.

## Best Possible Solution
