## Summary

Keep open: current main and the latest release still give the managed-service helper only a 60s parent-exit window, while normal gateway restart draining can wait up to 300s, so the reported `managed-service-handoff-parent-timeout` remains a real updater bug.

## What This Changes

The issue reports that npm-based gateway self-update on Windows fails when the managed-service handoff times out before the gateway finishes draining active work.

## Best Possible Solution

Align the managed-service helper's parent-exit timeout with the Gateway restart drain budget plus shutdown overhead, preserving existing sentinels and service recovery without adding a new user-facing setting.

## Reproduction Assessment

Yes, at source level: current main can wait up to 300s for restart drain, but the managed-service helper reports parent timeout after only 60s if the gateway process is still alive. I did not run a live Windows npm-global update in this read-only review.

## Solution Assessment

Yes in direction: the narrow fix belongs in the managed-service handoff/restart-timeout boundary, not in a new config option or the broader external-updater architecture item.
