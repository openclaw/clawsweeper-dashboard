## Summary

Keep open: current main appears to have fixed the provider-side non-image placeholder conversion, but source inspection still shows the normal exec-like warning path and incomplete-turn fallback can both suppress user-visible recovery when a tool error leaves zero delivered payloads. That remaining behavior needs maintainer intent rather than an automatic cleanup close.

## What This Changes

The issue reports that failed or empty exec/tool results can be converted to `(see attached image)` and leave channel users without a useful model reply after the 2026.6.11 release.

## Best Possible Solution

Keep the current provider placeholder repair, then define a source-level zero-payload tool-error contract in the embedded runner before changing warning or incomplete-turn fallback behavior.
