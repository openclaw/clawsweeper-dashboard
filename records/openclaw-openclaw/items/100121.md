## Summary

Keep open: current main has fixed part of the bogus image-placeholder conversion, but source inspection still shows remaining no-reply/tool-error policy gaps around read-only exec-like failures and incomplete-turn fallback. The issue overlaps several active reports, but it is not a clean duplicate of one canonical item.

## What This Changes

The issue requests that failed exec/tool turns avoid bogus image placeholders, surface an exec failure warning when no reply is delivered, and fall back to an incomplete-turn message when no payloads were sent.

## Best Possible Solution

Unify the terminal tool-error contract so empty non-media tool results never become image placeholders, read-only exec-like failures surface a warning only when no user answer was delivered, and lastToolError does not suppress the only incomplete-turn fallback for a payloadCount=0 user-addressed turn.

## Reproduction Assessment

Partially. Source inspection gives a strong current-main path for the remaining read-only exec-like suppression and lastToolError incomplete-turn suppression, but I did not run a live Discord/Slack/Telegram reproduction in this read-only review.

## Solution Assessment

Unclear. The proposed code-shape is plausible, but current main already fixed part of the placeholder behavior and the warning/fallback semantics overlap active native-exec and incomplete-turn policy issues that need a maintainer-chosen contract.
