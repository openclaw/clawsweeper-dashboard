## What This Changes

Adds an early no-op return for empty key arrays in the browser Chrome profile decoration `setDeep` helper and removes the empty-string fallback assignment.

## Best Possible Solution

Land the narrow guard if maintainers accept empty key arrays as a defensive no-op; otherwise close this PR and leave the linked issue as the canonical record.

## Reproduction Assessment

Yes at the helper/source level: current main's final assignment writes `{"":"value"}` for an empty key array. There is still no production user-flow failure shown because all current callers pass non-empty literal paths.

## Solution Assessment

Yes for the helper-level behavior: an early return is the smallest local fix, and the current TypeScript config does not make the direct last-key index a type problem. A broader caller refactor is not needed because the only callers are local literal paths.
