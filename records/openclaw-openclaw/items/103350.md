## Summary

This PR should remain open but is not merge-ready: its forced flush still cannot send after the pipeline aborts, while flushing from `stop()` can emit partial text during cancellation or error cleanup; it also lacks required real Telegram proof.

## What This Changes

The PR lets forced coalescer flushes bypass the coalescer abort check, makes `stop()` initiate a forced flush, adds verbose discard logging, and adds focused coalescer tests.

## Best Possible Solution

Keep `stop()` as teardown, retain the existing awaited flush for completed turns, and preserve genuinely unsent final content through the pipeline/runner final-payload fallback with timeout, cancellation, and duplicate-suppression regression coverage.
