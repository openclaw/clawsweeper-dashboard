## Summary

The latest head still has both previously reported P1 lifecycle defects: force finalization disables the abort guard for the whole queued send chain, and stop starts a second unawaited delivery after callers already awaited the final flush. The linked bug remains valid, but this implementation is not merge-ready and still lacks after-fix live Telegram proof.

## What This Changes

The PR adds a persistent pipeline finalization mode that permits forced coalescer tail delivery after abort, invokes a force flush from stop, and adds coalescer and pipeline regression tests.

## Best Possible Solution

Make the awaited forced flush the sole drain owner, allow only its canonical buffered tail through a one-shot post-abort exception, keep every other queued or later payload behind the abort guard, and keep stop strictly non-sending teardown.
