## Summary

Keep this PR open: the memory-read and character-cap fixes are pointed at the right helper boundary, but the response-snippet path still decodes byte-truncated UTF-8 with replacement characters before the new UTF-16-safe character truncation can help.

## What This Changes

The PR adds a package-local UTF-16-safe truncation helper for memory-host snippets, applies it to response snippets and single-line memory read excerpts, and adds focused regression tests.

## Best Possible Solution

Keep the package-local UTF-16-safe character truncation for memory excerpts, and extend response snippet handling so byte-limited prefixes decode on a complete UTF-8 boundary before appending the truncation suffix.
