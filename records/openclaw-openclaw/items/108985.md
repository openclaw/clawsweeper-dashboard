## Summary

The bug remains source-reproducible on the reviewed main snapshot, and this PR is the active candidate fix. The implementation appears owner-correct with focused regression coverage and no discrete patch defect, but real Telegram proof is still required before merge and the behind branch needs a current-main refresh.

## What This Changes

The PR carries original Telegram messages through multi-entry debounce flushes, removes inherited forward metadata from the synthetic batch, and formats visible forward origins per segment in the context owner.

## Best Possible Solution

Keep forward-origin formatting in Telegram context construction, feed it the original debounced messages, evaluate visibility independently for every segment, and ensure the synthetic batch carries no misleading single origin.

## Maintainer Decision

Yes, at source level with high confidence: the multi-entry debounce path reduces messages to joined raw text and one synthetic message, while context construction can normalize only that synthetic message's single origin. A live current-main Telegram run was not performed.

## Solution Assessment

Yes, this is the best ownership shape: context construction already owns forward normalization and visibility policy, so carrying original messages there is safer than inserting attribution text in the debounce coalescer; merge readiness still requires live proof and branch refresh.
