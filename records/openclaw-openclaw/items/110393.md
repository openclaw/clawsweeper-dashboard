## Label Justifications

- `P1`: The PR changes a web-fetch extraction guard and still permits malformed fetched HTML to trigger a false fallback or disproportionate preflight work.
- `merge-risk: 🚨 availability`: The new raw-text closing-tag search can repeatedly traverse the remaining document when selected raw-text tags are unclosed.

## Summary

The intended readable-extraction regression is real and the supplied terminal probes show the covered cases improve, but the raw-text skip still resumes normal tag scanning when no matching end tag exists. That leaves malformed raw-text input able to trigger the nesting guard and creates repeated full-tail searches, so this needs one focused repair before merge.

## What This Changes

The PR changes web-readability's estimated HTML nesting-depth preflight to skip pseudo-tags inside selected raw-text/RCDATA elements and adds regressions for quoted tags, legacy raw-text elements, malformed apparent tags, and long start tags.

## Best Possible Solution

Treat a selected raw-text/RCDATA start with no appropriate closing tag as consuming the rest of the input, then add a focused extraction and bounded-runtime regression for that malformed document shape.

## Solution Assessment

No. The bounded closing-tag lookup is a sensible direction, but its no-closing result must model raw-text parsing by consuming the remainder rather than resuming markup scanning.
