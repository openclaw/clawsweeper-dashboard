## Summary

Keep open: current main and the latest release still expose gateway-local session tools, and the open closing PR is a candidate implementation rather than a merged fix. The remaining decision is product/security direction for cross-gateway identity, authorization, delivery, and session ownership.

## What This Changes

The issue requests native cross-gateway `sessions_send` behavior so agents on separate OpenClaw gateways can communicate without SSH workarounds.

## Best Possible Solution

Choose and document a secure gateway-to-gateway session messaging contract, or explicitly route the capability to a plugin/bridge API, with peer identity, scopes, session-history semantics, and live multi-gateway proof before closing this issue.
