- `P1`: The issue blocks a real distributed-agent workflow across gateways and affects session continuity, message delivery, and gateway security design.

- `impact:security`: Cross-gateway messaging requires a new trust, credential, and authorization boundary between Gateway instances.

## Summary

Keep open: current main and the latest release still keep `sessions_send`/`sessions_spawn` gateway-local, while the linked implementation PR is open, conflicting, and still needs maintainer product/security direction before it can close the user problem.

## What This Changes

Request native cross-gateway session messaging so agents on different OpenClaw Gateway instances can send messages or spawn work without SSH or external relay scripts.

## Best Possible Solution

Choose and land a secure gateway-to-gateway session messaging contract, or explicitly route this to a plugin/bridge API, with peer identity, scopes, session history semantics, upgrade behavior, and real multi-gateway proof documented before closing this issue.
