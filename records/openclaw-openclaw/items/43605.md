## Summary

Keep open: current main and the latest stable release still keep session tools gateway-local, and the linked implementation PR plus the broader federation tracker need maintainer product/security direction before this issue can close.

## What This Changes

Request native cross-gateway messaging so `sessions_send` and related session tooling can reach agents on separate gateway instances without SSH workarounds.

## Best Possible Solution

Choose and document a secure gateway-to-gateway session messaging contract, or explicitly route the work to a plugin/API bridge, with peer identity, scopes, session history semantics, and live multi-gateway proof before closing this issue.
