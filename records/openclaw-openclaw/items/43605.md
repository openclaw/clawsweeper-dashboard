## What This Changes

Issue #43605 requests native cross-gateway messaging so sessions_send, and possibly sessions_spawn, can target sessions or agents on another OpenClaw gateway.

## Best Possible Solution

Decide whether this belongs in core or a plugin/API bridge; if core, define peer identity, authorization scopes, replay/idempotency, session visibility/history semantics, and land or replace #43656 with live multi-gateway proof.
