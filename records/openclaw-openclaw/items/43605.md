## Summary

Keep open: current main and the latest release still keep session-tool routing gateway-local, and the remaining work is paired with an open implementation PR plus a broader federation/security design issue that needs maintainer judgment.

## What This Changes

The issue requests native cross-gateway `sessions_send` and related session delegation so agents on separate OpenClaw gateway instances can message each other without SSH or ad hoc relay scripts.

## Best Possible Solution

Land or replace the linked implementation only after maintainers choose a secure cross-gateway contract for peer identity, URL policy, token/scopes, replay/idempotency, session ownership, and operator-controlled routing.

## Reproduction Assessment

Yes, at source level: current `sessions_send` and `sessions_spawn` expose no remote gateway target parameters, and `sessions.resolve` reads the local gateway session store. I did not run a live multi-machine repro because the missing surface is clear from current main and v2026.6.11.

## Solution Assessment

Unclear as a final product shape: the linked `gateway.peers` PR is a plausible candidate, but cross-gateway identity, scopes, URL policy, and session ownership need maintainer approval before it can be called the best fix.
