## Summary

Keep open: current main still has gateway-local `sessions_send` and `sessions_spawn`, and the issue is already paired with an open implementation PR plus a broader federation/security design tracker that need maintainer review before this can safely land.

## What This Changes

Request native cross-gateway session messaging so agents on separate OpenClaw Gateway instances can send, spawn, and preserve session continuity without SSH or ad hoc relays.

## Best Possible Solution

Define a secure peer-routing or federation contract first, then land or replace the linked implementation with tests and real proof for remote send/spawn, auth scopes, session history, and config/upgrade behavior.

## Reproduction Assessment

Yes, at source level: current `sessions_send` and `sessions_spawn` expose no remote gateway target parameters, and `sessions.resolve` reads the local gateway session store. I did not run a live multi-machine repro because the missing surface is clear from current main.

## Solution Assessment

Unclear as a final product shape: the linked `gateway.peers` PR is a plausible implementation candidate, but cross-gateway identity, scopes, replay behavior, and session ownership need maintainer approval before it can be called the best fix.
