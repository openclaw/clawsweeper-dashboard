## Summary

Keep open: current main still has gateway-local session tools, while the linked implementation PR is open and conflicting and the broader federation/security shape still needs maintainer judgment.

## What This Changes

Request native cross-gateway `sessions_send` and related session delegation so agents on separate gateway instances can message or delegate work without SSH scripts.

## Best Possible Solution

Choose and land a secure gateway-to-gateway session messaging contract, or explicitly route this to a plugin/bridge API, with peer identity, scopes, session history semantics, and real multi-gateway proof documented before closing the issue.

Unclear. The linked `gateway.peers` PR is a plausible candidate, but it is not clearly the best permanent fix until maintainers decide the federation, auth, scope, and session-state contract.
