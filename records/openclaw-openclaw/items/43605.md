## What This Changes

The issue requests native cross-gateway session messaging so `sessions_send` or related session tools can target agents behind other gateway instances.

## Best Possible Solution

Choose and land a secure gateway-to-gateway session messaging contract, or explicitly route the capability to a plugin/bridge API, with peer identity, scopes, session-history semantics, and real multi-gateway proof documented before closing this issue.
