## Summary

Keep open: current main and v2026.6.11 still route explicit non-tool skill slash invocations through advisory model text rather than guaranteed SKILL.md injection, and the requested deterministic path needs a maintainer product/security contract first.

## What This Changes

The issue requests deterministic loading of a slash-invoked skill's SKILL.md into model context instead of relying on the model to voluntarily read the skill file from available-skills guidance.

## Best Possible Solution

Define one explicit skill-invocation and trust-boundary contract, then implement deterministic SKILL.md loading for non-tool slash-invoked skills across channel/session entry points with security, prompt, docs, and regression coverage.

## Reproduction Assessment

Yes, at source level: current main recognizes explicit skill slash invocations but rewrites non-tool skills into advisory model text instead of injecting SKILL.md. I did not run a live model transcript reproduction in this read-only review.

Unclear as a final implementation path: deterministic injection is plausible for explicit user intent, but the best fix must first settle instruction isolation, security precedence, and shared channel/session behavior.
