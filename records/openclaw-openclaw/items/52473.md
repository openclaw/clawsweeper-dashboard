## Summary

Keep open: current main and v2026.6.11 still route explicit non-tool skill slash commands by rewriting the request into advisory model text, not by injecting SKILL.md content, and the remaining change needs a maintainer-owned skill instruction authority and security-boundary decision.

## What This Changes

The request is to make explicit skill slash commands deterministically load SKILL.md content into model context instead of relying on the model to choose to read it.

## Best Possible Solution

Define one explicit skill-invocation trust contract, then implement deterministic SKILL.md loading for non-tool explicit skill commands in the shared command/session path with security, prompt, docs, and regression coverage.
