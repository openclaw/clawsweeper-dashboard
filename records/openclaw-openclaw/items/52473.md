## Summary

Keep open: current main and the latest release still route explicit non-tool skill slash commands by rewriting the user request into advisory model text, not by injecting SKILL.md content; the remaining fix needs a maintainer-owned skill instruction authority and security-boundary decision.

## What This Changes

Request deterministic SKILL.md loading into model context when a user explicitly invokes a skill with a slash command, while leaving command-dispatch tool skills unaffected.

## Best Possible Solution

Define one explicit skill-invocation trust contract, then implement deterministic SKILL.md loading for explicit non-tool skill slash commands in the shared command/session path with security, prompt, docs, and regression coverage.
