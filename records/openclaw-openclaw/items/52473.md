## Summary

Keep open: current main and v2026.6.11 still route ordinary explicit skill slash commands by rewriting the user request into advisory model text rather than injecting SKILL.md, and the remaining fix requires a maintainer-owned prompt authority and skill security boundary decision.

## What This Changes

The issue requests deterministic SKILL.md loading when a user explicitly invokes a non-tool skill via `/skill-name` or `/skill <name>`.

## Best Possible Solution

Define one explicit skill-invocation trust contract, then implement deterministic SKILL.md loading for non-tool slash-invoked skills in the shared command/session path with focused security, prompt, docs, and regression coverage.
