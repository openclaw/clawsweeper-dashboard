## Summary

Keep open: current main and v2026.6.11 still rewrite explicit non-tool skill slash commands into advisory model text, while deterministic SKILL.md injection needs a maintainer-owned prompt authority and security contract.

## What This Changes

The issue asks OpenClaw to deterministically load SKILL.md content when a user explicitly invokes a skill through a slash command.

## Best Possible Solution

Define one explicit skill-invocation trust contract, then implement deterministic SKILL.md loading for explicit non-tool slash commands through the shared command/session path with focused security, prompt, docs, and regression coverage.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should explicit non-tool skill slash commands automatically inject SKILL.md into model context, and what instruction-authority boundary must apply before that happens?

Rationale: The requested behavior changes prompt authority for installed or workspace skill content and overlaps open instruction-isolation work, so automation should not choose the permanent trust boundary alone.

Likely owner: steipete

Owner confidence: high

Options:

- **Design the boundary first (recommended):** Define the trusted/untrusted SKILL.md precedence, visibility, and session-context contract, then implement forced slash invocation against that approved design.
- **Keep command-dispatch as the deterministic path:** Preserve the current model-routed default and require skills that need hard activation to use command-dispatch: tool until broader isolation is settled.
- **Prototype behind an explicit opt-in:** Allow a narrow experimental forced-injection mode only after maintainers accept the upgrade and security tradeoff for existing skills.

## Reproduction Assessment

Yes, source-level. Current main resolves /skill and direct skill commands, then rewrites ordinary non-tool invocations into advisory text while the system prompt still asks the model to read SKILL.md voluntarily.

## Solution Assessment

Unclear as a final implementation path. Deterministic injection is plausible for explicit user intent, but the best fix must first settle instruction authority, security boundaries, and shared channel/session behavior.
