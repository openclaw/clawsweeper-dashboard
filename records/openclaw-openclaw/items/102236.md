## Summary

Keep open: current main still stores the startup catch-up deferral exemption only in process-local cron service state, so a fresh gateway process can lose the marker while retaining the persisted staggered slot. Two open PRs now claim this issue, so the issue should stay open until one corrected implementation lands.

## What This Changes

The issue asks for startup overflow cron catch-up deferrals to survive a second gateway restart before the deferred slot fires.

## Best Possible Solution

Persist or derive the pending deferral marker in the SQLite-backed cron runtime state, hydrate it before startup maintenance, and clear it when consumed or invalidated while keeping public cron responses schema-compatible.
