## Summary

Keep open: current main still has the cross-restart gap described here, and the open linked implementation PR formally closes this issue, so it should remain open until that candidate is reviewed and merged or replaced.

## What This Changes

Persist protection for startup-overflow cron catch-up slots so a second gateway restart does not advance a deferred non-agentTurn job to its next natural schedule and silently skip the catch-up run.

## Best Possible Solution

Review and land a single persisted per-job deferral marker that is restored before startup maintenance, clears when the deferred slot is consumed or invalidated, and is covered by a two-service-state regression test against one durable store.

## Reproduction Assessment

Yes, from source: seed more than the missed-job budget of overdue non-agentTurn cron jobs, start once to create a staggered slot, then start a fresh service state against the same durable store before that slot fires. The linked PR includes a focused regression test for this exact path, but this review did not execute it.

## Solution Assessment

Yes, conditionally: storing the deferral alongside the persisted job state and rebuilding the runtime protection before maintenance directly fixes the process-boundary mismatch without disabling ordinary stale-future cron repair.
