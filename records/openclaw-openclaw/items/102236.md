## Summary

Keep open: current main still stores the startup catch-up deferral marker only in process-local cron service state, and the two linked closing PRs are still open rather than merged. The issue should close only after a durable cron-state fix lands.

## What This Changes

The issue reports that startup overflow cron catch-up deferrals persist their staggered `nextRunAtMs` but lose their protection marker across a second restart, silently skipping the catch-up run.

## Best Possible Solution

Land one durable cron-state fix that hydrates the pending startup catch-up deferral before startup maintenance repair, keeps unrelated stale-future repair enabled, and clears the marker when the deferral is consumed or invalidated.
