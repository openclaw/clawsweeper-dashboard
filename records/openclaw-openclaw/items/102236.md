## Summary

Keep open: current main still keeps the startup catch-up deferral exemption in process-local cron service state, so the cross-restart loss reported here remains possible. Two open pull requests already reference this issue with closing syntax, so the right cleanup path is to review or replace those candidate fixes rather than queue another independent fix.

## What This Changes

The issue reports that startup overflow cron catch-up deferral markers are not persisted, allowing a second gateway restart to silently advance a deferred non-agentTurn cron job to its natural slot and skip the catch-up run.

## Best Possible Solution

Land one narrow cron persistence fix that keeps the catch-up deferral marker durable with the deferred `nextRunAtMs`, preserves stale-future repair for unrelated jobs, and includes a regression using two fresh service states against the same store.
