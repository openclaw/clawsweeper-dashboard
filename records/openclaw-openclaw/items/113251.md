## Summary

This issue remains necessary. The merged artifact lightbox preview handles transcript and session-artifact images, while a regular workspace PNG opened through the file browser still follows the separate text-editor route and renders as binary; the maintainer explicitly corrected the earlier implemented-on-main conclusion and reopened the issue. Likely related people: steipete (medium confidence) through the adjacent Control UI image-preview work and the current-path investigation.

## What This Changes

Add a safe image preview for normal workspace image files opened in the Control UI file browser, rather than showing their binary contents in the text editor.

## System Context

The Control UI lets a user browse workspace files through the Gateway session-file API and opens the chosen file in its file viewer. That viewer currently treats the reported PNG as editor text, whereas chat and session-artifact images already use an authorized image-preview/lightbox path.

## Architecture Diagram

flowchart LR
  A[Workspace file selection] --> B[Gateway session-file request]
  B --> C[Control UI file viewer]
  C --> D{Recognized file type}
  D -->|Text| E[Code editor]
  D -->|Image today| F[Binary content shown as text]
  D -->|Image desired| G[Authorized image preview]
  G --> H[Accessible lightbox]

## Best Possible Solution

Extend the regular workspace-file viewer with a narrowly authorized image-preview branch for supported image MIME types, reusing the existing accessible lightbox where its security and lifetime contracts apply while retaining the editor fallback for non-images and failed previews.

- **Design a broader file preview surface:** Define a dedicated preview architecture for images and future non-text workspace files before adding a one-off image branch.
