Full review comments:

- **[P2] Check queued turns before cached chat.send results:** `src/gateway/server-methods/chat.ts:3893-3898`
  - body: A retried `chat.send` hits the terminal `chat:<runId>` cache before the queued-turn branch, so once post-dispatch has cached `{status: "ok"}` the TUI sees the queued prompt as complete even though `chatQueuedTurns` still owns it. Move this check before terminal cache replay, or do not cache/replay terminal `ok` until the queued turn completes, and cover the retry without deleting the dedupe entry.
  - confidence: 0.91
- **[P2] Preserve queued BTW turns during session stops:** `src/gateway/server-methods/chat.ts:4711-4720`
  - body: `registerQueuedChatTurn` drops the computed `turnKind`, and the queued session-abort path runs before the active/pre-registered `preserveSideRuns` filters. That lets Esc or `/stop` for the main session cancel an unrelated queued `/btw` question; carry `turnKind` into `QueuedChatTurnEntry` and filter queued matches when `preserveSideRuns` is set.
  - confidence: 0.89

## Risks / Open Questions

- A lost or retried chat.send ACK can replay cached terminal ok while chatQueuedTurns still contains the queued turn, causing the TUI to clear pending UI before the queued prompt runs.
- Queued `/btw` prompts can be cancelled by a main-session Esc or `/stop` because queued-turn entries do not preserve turnKind and the queued abort path ignores preserveSideRuns.
- The additive chat.abort preserveSideRuns protocol field and generated Swift model change are compatibility-sensitive for mixed-version TUI/Gateway clients.
- Queued-turn abort ownership changes are security-boundary-sensitive because requester, device, and connection authorization must remain correct for both queued and active runs.
