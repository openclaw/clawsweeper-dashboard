## Label Justifications

- `P0`: Before the merged fix, channel-only users with expired model OAuth could be blocked in auth recovery unless an operator used terminal/SSH recovery.
- `impact:ux-release-blocker`: The reported recovery path was not available in-channel and required technical intervention for hosted or Telegram-only users.
- `impact:auth-provider`: The issue is centered on OpenAI/Codex OAuth profile expiry, refresh failure classification, profile selection, and reauth.
- `impact:security`: The implementation had to preserve credential and device-code privacy by sending pairing material only through owner/private contexts.

## Summary

Current main now solves the central channel-only reauth problem: hard OpenAI/Codex OAuth failures point users to `/login codex`, and private channel/Web UI command paths can run the existing device-code auth flow without exposing tokens or public-group codes.

## What This Changes

Request channel-originated hard OpenAI/Codex OAuth failures to guide users through private device-code reauth instead of terminal-only recovery.

## Best Possible Solution

Keep the merged private `/login codex` recovery path as the channel reauth solution; broader auth/quota diagnosis and failover policy should remain in https://github.com/openclaw/openclaw/issues/54278 and https://github.com/openclaw/openclaw/issues/86215.
