## Label Justifications

- `P2`: This was a normal-priority auth/channel UX improvement with a terminal workaround and limited blast radius, now implemented on main.
- `impact:security`: The issue is about delivering auth pairing material safely without exposing OAuth tokens or device codes in public channels.
- `impact:message-loss`: Expired model login failures can stop channel-originated runs from producing useful replies until reauth succeeds.
- `impact:auth-provider`: The affected behavior is OpenAI/Codex OAuth refresh failure and provider auth-profile recovery.

## Summary

Current main already implements the narrow channel-friendly Codex/OpenAI reauth path: failed OpenAI OAuth refresh replies now point channel users to private `/login codex`, and the command starts the device-code pairing flow with owner/admin gating, private delivery, active-flow dedupe, profile persistence, and Telegram no-code group coverage.

## What This Changes

Request a channel-friendly provider reauth flow for hard OpenAI/Codex OAuth failures so channel users can pair a new login without relying only on terminal recovery.

## Best Possible Solution

Keep the merged owner/admin-gated private `/login codex` recovery path for this narrow request; broader quota diagnosis and brokered auth incident policy can continue in https://github.com/openclaw/openclaw/issues/54278 and https://github.com/openclaw/openclaw/issues/86215.
