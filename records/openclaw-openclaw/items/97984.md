## Label Justifications

- `P0`: The reported gap blocked channel-only users from recovering an expired model login without terminal or operator intervention.
- `impact:ux-release-blocker`: The issue describes Telegram/channel-only auth recovery where the only previous path was terminal reauthentication.
- `impact:auth-provider`: The affected behavior is OpenAI/Codex OAuth profile expiry, provider login, and auth profile persistence.
- `impact:security`: The recovery path handles OAuth device codes and must keep credential material out of shared channels and logs.

## Summary

Current main and the beta release now implement the central channel-friendly recovery path: hard OpenAI/Codex OAuth failures point channel users to private `/login codex`, and that command runs a device-code flow through private channel/Web UI delivery with owner/admin gating, dedupe, profile persistence, and Telegram no-code group protection.

## What This Changes

The issue requests a channel-friendly reauthentication flow for expired model logins instead of terminal-only recovery copy.

## Best Possible Solution

Keep the shipped owner/admin-gated private `/login codex` recovery path; broader automatic or brokered reauth policy should stay with https://github.com/openclaw/openclaw/issues/54278 if maintainers want to expand it later.
