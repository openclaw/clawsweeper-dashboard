## Label Justifications

- `P2`: The issue concerns a normal-priority auth recovery UX improvement with limited blast radius now implemented on current main.
- `impact:security`: The channel login flow handles OAuth pairing material and must keep device codes restricted to owner/private contexts.
- `impact:message-loss`: Expired model login previously caused channel-originated runs to fail before a useful reply unless the user recovered out of band.
- `impact:auth-provider`: The reported behavior is provider OAuth expiry and reauthentication for OpenAI/Codex model profiles.

## Summary

Current main now implements the central channel-friendly Codex/OpenAI reauth path: hard OAuth failures point users to private `/login codex`, and that command runs owner-gated OpenAI device-code pairing with private delivery, dedupe, persistence, and stale lockout cleanup. The automatic/brokered reauth variant is broader product/security direction and is already covered by related open auth-recovery issues, so this narrow issue can close as implemented on main.

## What This Changes

Request channel-friendly reauthentication for expired model logins so Telegram/channel users can recover OpenAI/Codex OAuth without a terminal-only command.

## Best Possible Solution

Keep the explicit, owner-gated private `/login codex` implementation on main; broader automatic/brokered auth recovery should stay with the existing product/security follow-up issues rather than keeping this narrow channel-reauth issue open.
