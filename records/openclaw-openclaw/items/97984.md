## Label Justifications

- `P0`: The original report described channel-only users blocked from auth recovery unless someone used terminal/SSH recovery, which matches the UX release-blocker override even though the fix now exists.
- `impact:ux-release-blocker`: Before the merged `/login codex` path, a non-terminal channel user could not recover an expired model login from the channel surface.
- `impact:auth-provider`: The request centers on expired or invalidated OpenAI/Codex OAuth provider credentials and profile reauthentication.
- `impact:message-loss`: The observable failure is a channel-originated run failing before a useful model reply when auth refresh is hard-failed.

## Summary

Close: current main implements the narrow channel-friendly Codex/OpenAI reauth path with private `/login codex` pairing, hard OAuth failure guidance, owner/admin gating, active-flow dedupe, and profile-aware login. The broader brokered/automatic reauth policy remains covered by a separate open auth-direction issue.

## What This Changes

Request channel-only users get provider reauth through private channel or Web UI device-code pairing instead of only terminal CLI instructions.

## Best Possible Solution

Keep the merged explicit, owner/admin-gated private `/login codex` recovery path for this narrow issue, and leave broader quota diagnosis or brokered automatic reauth policy to https://github.com/openclaw/openclaw/issues/54278.
