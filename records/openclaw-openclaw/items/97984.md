## Label Justifications

- `P0`: Before the current-main fix, a channel-only user with an expired OpenAI/Codex login had to recover through terminal/operator access, which is a blocked auth recovery path under the UX override.
- `impact:ux-release-blocker`: The reported recovery path blocked non-terminal channel users from repairing expired model auth without technical/operator intervention.
- `impact:auth-provider`: The issue is about OpenAI/Codex OAuth refresh failures, profile selection, device-code reauth, and credential persistence.
- `impact:security`: The recovery flow sends OAuth pairing codes through user-facing channels and writes refreshed credentials, so authorization and redaction boundaries are central.
- `maturity:stable`: The affected gateway/channel recovery surface maps to `gateway-runtime`, which is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Current main implements the central channel-friendly OpenAI/Codex reauth path: hard auth failures now point channel users to `/login codex`, and private/owner-gated channel command paths send device-code pairing material, dedupe active flows, persist OAuth profiles, clear stale lockouts, and return completion/expiry-style status text. The remaining broader brokered/quota auth policy is already covered by the related open auth diagnosis issue.

## What This Changes

The issue asks for channel-originated recovery from expired model OAuth logins without requiring terminal-only `openclaw models auth login` access.

## Best Possible Solution

Keep the current explicit owner/admin-gated private `/login codex` flow, and leave broader automatic brokered reauth or quota/auth diagnosis policy to https://github.com/openclaw/openclaw/issues/54278.
