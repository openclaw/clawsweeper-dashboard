## Review Findings

Overall confidence: 0.9

Full review comments:

- **[P1] Validate xcode_path before selecting Xcode:** `.github/workflows/build-ios-unsigned.yml:50`
  - body: `xcode_path` is substituted into the generated shell script before bash runs it. A crafted dispatch value can break out of the quoted argument and execute commands on the macOS runner, so pass the input through `env`, validate an allowlisted Xcode path in bash, and then quote the variable.
  - confidence: 0.9
- **[P1] Build build_number arguments after validation:** `.github/workflows/build-ios-unsigned.yml:68`
  - body: The digits-only validation in `scripts/ios-write-version-xcconfig.sh` happens too late because the workflow expands `build_number` into the shell command first. Construct the `--build-number` argument from a validated environment variable instead of interpolating the expression into `run`.
  - confidence: 0.91
- **[P2] Limit the workflow token before running build scripts:** `.github/workflows/build-ios-unsigned.yml:36`
  - body: This workflow checks out the repo and then runs dependency and build scripts, but it has no explicit read-only `permissions` block and `actions/checkout@v4` persists credentials by default. Add `permissions: contents: read` and `persist-credentials: false` like the hardened sibling workflows.
  - confidence: 0.84
