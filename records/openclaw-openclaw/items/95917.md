Full review comments:

- **[P1] Validate xcode_path before selecting Xcode:** `.github/workflows/build-ios-unsigned.yml:50`
  - body: `xcode_path` is interpolated directly into the generated shell command. A manual dispatch value can affect shell parsing before `xcode-select` runs, so pass it through `env`, validate an allowlisted Xcode path in bash, and then quote the variable.
  - confidence: 0.9
- **[P1] Build build_number arguments after validation:** `.github/workflows/build-ios-unsigned.yml:68`
  - body: `build_number` is inserted unquoted into the run command, so a crafted dispatch value can append shell syntax before the version script can enforce digits-only behavior. Pass the raw input through `env` and construct the argument only after validation.
  - confidence: 0.91
- **[P2] Limit the workflow token before running build scripts:** `.github/workflows/build-ios-unsigned.yml:36`
  - body: This workflow runs package install and build scripts after checkout, but it has no explicit read-only `permissions` block and `actions/checkout` persists credentials by default. Add `permissions: contents: read` and `persist-credentials: false` before adding this artifact-producing lane.
  - confidence: 0.86
- **[P2] Pin the workflow action refs:** `.github/workflows/build-ios-unsigned.yml:36-39`
  - body: Late discovery from this review cycle: the PR head is unchanged since the prior review, and the new workflow uses mutable `actions/*@v4` refs while current workflows pin these actions to full SHAs. Pin the action refs, or reuse the repo-local setup action, so this new CI lane does not add a weaker supply-chain path.
  - late: true
  - confidence: 0.84
