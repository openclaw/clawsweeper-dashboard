Full review comments:

- **[P1] Keep approval state out of write-scoped undo:** `extensions/dashboard/src/gateway.ts:747`
  - body: `dashboard.workspace.undo` requires only `operator.write`, but `store.undo()` restores the entire prior document, including `widgetsRegistry.approvedFiles`. After an operator rejects a widget, a write-scoped client or agent tool can undo back to the approved snapshot and make the unauthenticated asset route serve it again without `operator.approvals`; exclude registry approval state from layout snapshots or require the approval scope when restoring it.
  - confidence: 0.99
- **[P1] Revoke the bridge when the widget leaves approved content:** `ui/src/components/dashboard-custom-widget.ts:224-229`
  - body: The message filter only compares `event.source` with the iframe's persistent `contentWindow`. If approved widget code navigates that frame to another page, the new document keeps the same WindowProxy and can still request `prompt:send`; detach or disable the bridge on navigation away from the pinned widget URL, or prevent such navigation.
  - confidence: 0.97
- **[P2] Add an idempotency key to widget prompt sends:** `ui/src/components/dashboard-custom-widget.ts:216-220`
  - body: `ChatSendParamsSchema` requires a non-empty `idempotencyKey`, but the widget bridge sends only `sessionKey`, `message`, and `deliver`. Every confirmed `prompt:send` request is therefore rejected by the gateway; generate a unique key per confirmed request and cover the real client payload.
  - confidence: 0.99
- **[P2] Discard binding results from obsolete cache versions:** `ui/src/pages/plugin/dashboard-view.ts:302-305`
  - body: A pending `resolveBinding` promise writes into `bindingResults` after the cache version may have changed and been cleared. Capture the request key and only store or delete the load if `viewState.bindingVersion` still matches, otherwise an older document or poll result can overwrite current widget data.
  - confidence: 0.98
- **[P2] Show the registered `workspaces` command in onboarding:** `ui/src/i18n/locales/en.ts:1057`
  - body: Core owns `openclaw dashboard`, so this plugin deliberately registers its CLI under `openclaw workspaces`; the onboarding copy still tells users to run `openclaw dashboard tabs create`, which opens the Control UI instead of creating a tab. Update the English source string to the reachable command and regenerate locale output.
  - confidence: 0.99
- **[P3] Remove the release-owned changelog entry:** `CHANGELOG.md:9`
  - body: Repository policy reserves `CHANGELOG.md` for the release process, but this feature branch adds its own release entry. Remove this line and keep release-note context in the PR body or commit messages instead.
  - confidence: 0.99
