## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.98

Full review comments:

- **[P1] Keep approval state out of write-scoped undo:** `extensions/dashboard/src/store.ts:218`
  - body: Approval and rejection mutations snapshot the full workspace document, and `dashboard.workspace.undo` restores that snapshot under only `operator.write`; the agent `dashboard_undo` tool reaches the same store path. After an approved widget is rejected, a caller without `operator.approvals` can undo the rejection and restore `status: "approved"` plus `approvedFiles`. Store approval state outside layout undo or require the approval scope whenever an undo would change it.
  - confidence: 0.99
- **[P1] Revoke bridge access after off-route iframe navigation:** `ui/src/components/dashboard-custom-widget.ts:226-229`
  - body: The message filter accepts any sender using the same `iframe.contentWindow` WindowProxy for the lifetime of the frame. A sandboxed approved widget can navigate itself to other content, and that new document can still request theme data or `prompt:send` through the existing bridge even though its bytes were not approved. Tear down or disable the bridge on navigation away from the approved widget asset, or prevent such navigation.
  - confidence: 0.98
- **[P2] Add an idempotency key to widget prompt sends:** `ui/src/components/dashboard-custom-widget.ts:216-220`
  - body: `chat.send` requires a non-empty `idempotencyKey`, but this bridge request omits it, so confirmed widget prompt sends are rejected by the gateway schema. Generate a stable per-invocation key and include it in the request, with a focused real handler or protocol-validation test.
  - confidence: 1
- **[P2] Request read scope for read-only workspace CLI calls:** `extensions/dashboard/src/cli.ts:132-136`
  - body: Every non-approval CLI request asks for both `operator.write` and `operator.read`, including `dashboard.workspace.get` used by tab and widget lists and layout reads. A device approved only for read access therefore cannot use the read-only CLI even though the gateway method requires only `operator.read`. Select scopes by method and keep write scope off read operations.
  - confidence: 0.99
- **[P2] Use the registered Workspaces command in onboarding:** `ui/src/i18n/locales/en.ts:1059`
  - body: The empty-state copy tells users to run `openclaw dashboard tabs create`, but `dashboard` is the core command that opens the Control UI and the plugin registers `workspaces`. Change the English source to the documented `openclaw workspaces tabs create --title Main` command and regenerate the generated locale bundles.
  - confidence: 1
