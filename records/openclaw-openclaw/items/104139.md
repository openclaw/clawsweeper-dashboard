Full review comments:

- **[P1] Keep approval state out of write-scoped undo:** `extensions/dashboard/src/store.ts:218`
  - body: `store.undo()` restores the full prior `widgetsRegistry`, while both the gateway undo method and agent undo tool remain write-scoped. A writer without `operator.approvals` can therefore resurrect an approved widget after rejection; preserve current approval state across undo or require approval scope for any restore that changes it.
  - confidence: 0.99
- **[P1] Revoke the bridge after off-route iframe navigation:** `ui/src/components/dashboard-custom-widget.ts:224-229`
  - body: The message listener remains attached for the iframe’s lifetime and authorizes only by `contentWindow` identity. A sandboxed widget can navigate that same WindowProxy to external content, which then retains static-data, theme, and prompt bridge grants; prevent off-route navigation or revoke the bridge when the loaded URL is no longer the approved widget asset.
  - confidence: 0.98
- **[P2] Discard binding results from obsolete cache versions:** `ui/src/pages/plugin/dashboard-view.ts:302-305`
  - body: The promise callback writes into `bindingResults` without checking that the captured cache key is still current. A slower request from an older workspace or polling version can overwrite fresh data after the cache is cleared; compare `viewState.bindingVersion` with the request key before storing or deleting load state.
  - confidence: 0.99
- **[P2] Add an idempotency key to widget prompt sends:** `ui/src/components/dashboard-custom-widget.ts:216-220`
  - body: `chat.send` requires an `idempotencyKey`, but the approved-widget bridge sends only `sessionKey`, `message`, and `deliver`. Every confirmed prompt request is rejected by the gateway instead of reaching chat; generate and pass a stable per-send key as the normal composer does.
  - confidence: 0.99
- **[P2] Use read scope for read-only workspace CLI calls:** `extensions/dashboard/src/cli.ts:132-136`
  - body: All non-approval calls request both `operator.write` and `operator.read`, including `dashboard.workspace.get` used by tabs/widgets list and layout get. Devices approved only for read access are rejected for asking for a write-scope superset; select scopes by gateway method or allow the CLI runtime to infer least privilege.
  - confidence: 0.99
- **[P2] Show the registered workspaces command in onboarding:** `ui/src/i18n/locales/en.ts:1057`
  - body: The plugin registers `openclaw workspaces`, but the empty-state copy still tells users to run `openclaw dashboard tabs create ...`; core owns `dashboard`, so that plugin command is skipped and the displayed recovery path fails. Update the English source string and regenerate locales to use the reachable command.
  - confidence: 0.99
