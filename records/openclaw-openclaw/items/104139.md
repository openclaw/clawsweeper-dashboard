- **[P1] Revoke bridge access after iframe navigation:** `ui/src/components/dashboard-custom-widget.ts:226-229`
  - body: The listener authorizes solely by the iframe's persistent `contentWindow` WindowProxy. A sandboxed approved widget can navigate that frame away from the approved asset, and the new document can still send bridge requests for static data, theme values, or confirmed prompts. Revoke the bridge on navigation away from the pinned widget URL or prevent such navigation.
  - confidence: 0.96
- **[P2] Add an idempotency key to widget prompt sends:** `ui/src/components/dashboard-custom-widget.ts:216-220`
  - body: `chat.send` requires a non-empty `idempotencyKey` on current main, but this request omits it, so confirmed custom-widget prompts are rejected by protocol validation instead of sending. Generate and pass a stable per-attempt key and cover the real request payload.
  - confidence: 0.99
- **[P2] Request read scope for read-only CLI operations:** `extensions/dashboard/src/cli.ts:132-136`
  - body: Every non-approval CLI request asks for both `operator.write` and `operator.read`, including `dashboard.workspace.get` used by list and get commands. A device approved only for read access rejects that scope superset, making the advertised read-only commands unusable; choose scopes by method.
  - confidence: 0.98
- **[P2] Show the registered workspaces command in onboarding:** `ui/src/i18n/locales/en.ts:1057`
  - body: The plugin registers `openclaw workspaces` because core already owns and suppresses a plugin `dashboard` command, but this visible onboarding instruction still tells users to run `openclaw dashboard ...`. Replace it with the reachable `openclaw workspaces ...` syntax and regenerate locale output.
  - confidence: 0.99
