## What This Changes

The issue reports that Slack inbound metadata sets `reply_to_id` to the same timestamp as `message_id` for top-level or other non-reply messages.

## Best Possible Solution

Review and land one canonical Slack fix, currently https://github.com/openclaw/openclaw/pull/102462, that omits prompt-facing `reply_to_id` for non-replies while preserving message-tool threading; close this issue after that PR merges.
