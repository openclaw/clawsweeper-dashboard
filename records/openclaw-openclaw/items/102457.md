- `impact:session-state`: The wrong `reply_to_id` can mis-associate current-turn context by making standalone Slack messages look like replies to themselves.

## Summary

Keep open: current main still sets Slack inbound `replyToId` to the message timestamp for non-reply messages, and the related merged Slack thread-context PR preserved that behavior rather than fixing this metadata self-reference.

## What This Changes

The issue asks for Slack inbound prompt metadata to omit `reply_to_id` unless the inbound Slack event is an actual thread reply.

## Best Possible Solution

Gate Slack `replyToId` on `isThreadReply` in the Slack resolver, keep the existing `messageThreadId` rules for reply modes and assistant DM roots, and add focused regression coverage for no `thread_ts`, self-thread roots, and genuine thread replies.
