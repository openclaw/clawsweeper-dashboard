## Summary

Keep open: current main and the latest release still emit self-referencing Slack `reply_to_id` metadata for non-reply messages, and the open fixing PR at https://github.com/openclaw/openclaw/pull/102462 has not merged yet.

## What This Changes

The issue requests that Slack inbound `reply_to_id` be omitted for messages that are not genuine thread replies instead of matching `message_id`.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/102462, or an equivalent Slack-owned patch that gates `replyToId` on genuine thread replies while preserving the current-message anchor for Slack message-tool threading.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level: current main still computes Slack `replyToId` as `incomingThreadTs ?? messageTs`, and the resolver tests still assert self-referencing values for non-reply roots. I did not run a live Slack workspace reproduction in this read-only review.

## Solution Assessment

Yes, the narrow maintainable fix belongs in the Slack resolver, with the Slack tool context preserving a current-message anchor where needed. Filtering `reply_to_id` only in shared inbound metadata would hide the bad channel value rather than fixing its owner boundary.
