## Summary

Keep open: current main and the latest release still set Slack inbound `replyToId` to the message timestamp for non-reply messages, so the reported self-referencing `reply_to_id` remains a valid Slack metadata bug.

## What This Changes

The issue requests Slack inbound metadata omit `reply_to_id` for non-reply messages instead of setting it to the message's own timestamp.

## Best Possible Solution

Gate Slack `replyToId` on `isThreadReply` in the Slack resolver, keep the existing `messageThreadId` rules for reply modes and assistant DM roots, and add regression coverage for no `thread_ts`, self-thread roots, and genuine thread replies.
