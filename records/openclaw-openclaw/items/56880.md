## Summary

Keep open: current main and v2026.6.11 still preserve one active agent run per session, with steering/followup/collect/interrupt as mitigations rather than true same-session parallel or fast-lane turns. The linked fast-lane PR is closed unmerged, the open steering PR covers only a narrower partial slice, and the remaining request needs maintainer scheduler and session-state design.

## What This Changes

The issue requests same-session concurrent or fast-lane agent turn handling so quick follow-up chat messages are not blocked behind long-running turns.

## Best Possible Solution

Keep this open as the design item for same-session fast-lane or parallel turns, resolve narrower steering/fairness candidates separately, and require a maintainer-approved scheduler contract before adding a public mode or config surface.

## Reproduction Assessment

Yes at source level: current main still uses one active session lane task by default and queues active non-heartbeat followups instead of starting parallel same-session turns. I did not run a live Discord long-turn scenario in this read-only cleanup pass.

## Solution Assessment

Unclear. Parallel slots or a heuristic fast lane are plausible, but the best permanent fix needs maintainer decisions around transcript ordering, tool side effects, rate limits, interrupt semantics, and whether this should expose new config.
