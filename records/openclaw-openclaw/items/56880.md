## Summary

Keep open: current main still serializes normal same-session agent turns, and the newer `/btw` side-question path is only a partial explicit workaround, not the requested concurrent inbound-message contract.

## What This Changes

Request to allow normal same-session inbound messages to run concurrently or in a fast lane while an existing agent turn is still active.

## Best Possible Solution

Settle a maintainer-approved session responsiveness contract, then implement either a one-writer steer/yield/interrupt model or an explicit opt-in fast lane with docs, schema, tests, and real channel proof.

Rationale: The source-level bottleneck is real, but changing it crosses transcript ordering, tool side effects, session write ownership, public config shape, and rate-limit policy, so automation cannot safely infer the product contract.

- **Prefer one-writer steer/yield model (recommended):** Preserve one active writer per session and improve admission so urgent or short messages steer, interrupt, yield, or use explicit `/btw` at safe runtime boundaries.

## Reproduction Assessment

Yes, at source level. Start an active same-session run and send another normal prompt; current main routes it through steer/followup/collect/interrupt or waits for the active run rather than starting a second concurrent session turn.

## Solution Assessment

Unclear. Parallel slots or a fast lane are plausible, but the narrowest maintainable path likely needs a maintainer-approved one-writer steer/yield/interrupt model unless maintainers explicitly accept opt-in parallel-turn risk.
