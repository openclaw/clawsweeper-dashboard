## Summary

Keep open: current main and v2026.6.11 still serialize same-session runs, and the merged steering work only mitigates active-run injection rather than adding same-session parallel or fast-lane turns.

## What This Changes

The issue requests concurrent or fast-lane message handling within one session so quick Discord/chat follow-ups are not blocked behind a long-running turn.

## Best Possible Solution

Keep this as a maintainer-owned design item for same-session fast-lane or parallel turns, with a bounded safety model before adding public config or runtime modes.

Yes. Source inspection gives a high-confidence path: start an active same-session run, then send a normal prompt; current main steers, follows up, collects, interrupts, or drops heartbeat traffic, but it does not start a second same-session agent turn.

Unclear. Fast-lane and parallel slots are plausible, but the safest permanent fix needs maintainer choices for transcript ordering, tool side effects, cancellation semantics, and public config shape.
