## Summary

Keep open: current main and v2026.6.11 still intentionally serialize same-session agent turns, with steering/followup/collect/interrupt as mitigations rather than true parallel or fast-lane turns. The request remains a product and session-safety design item, and the open fast-lane PR is conflicting and unmerged.

## What This Changes

Request concurrent same-session message handling so quick follow-ups can be answered or acted on while a long agent turn is still running.

## Best Possible Solution

Keep this open until maintainers choose a bounded same-session fast-lane or concurrency contract, then implement it in the core reply/session scheduler with transcript, tool-safety, and channel proof.

## Reproduction Assessment

Yes, source inspection gives a high-confidence path: start an active same-session run and send another normal prompt; current main steers, queues, collects, or interrupts rather than admitting a second same-session turn.

## Solution Assessment

Unclear. Parallel slots and fast-lane routing are plausible, but the best fix needs maintainer decisions on transcript ordering, tool side effects, rate limits, interrupt semantics, and public config shape.
