## Summary

Keep open: the PR targets a real Android gateway endpoint gap, but the proposed fix drops the IPv6 zone identifier that link-local addresses use to select an interface. OkHttp cannot parse the encoded scope through the current URL-string path, so this needs a different fix and real Android connection proof before merge.

## What This Changes

The PR changes Android gateway endpoint parsing to strip IPv6 zone suffixes before storing hosts and updates resolver tests to expect zone-free display URLs.

## Best Possible Solution

Do not store a bare link-local literal as equivalent to a scoped endpoint; either reject scoped IPv6 gateway URLs as unsupported by the current OkHttp URL path or add a connection path that preserves and resolves the scope explicitly.

## Reproduction Assessment

Yes from source inspection: current main accepts scoped IPv6 endpoint strings, stores the encoded scope in GatewayEndpointConfig.host, then passes a bracketed URL string through OkHttp's parser, which cannot parse the encoded scope. I did not run a live Android gateway connection, so this is source-reproducible rather than live-reproduced.

## Solution Assessment

No. Stripping the scope avoids OkHttp's URL parser failure but loses the interface identifier that scoped link-local IPv6 addresses need, so the safer fix is to reject the unsupported shape or preserve the scope through a dedicated connection path.
