## Summary

Keep open: the current-main bug is source-reproducible, but the PR drops the IPv6 scope that identifies the link-local interface and only has unit-test proof, so it needs a maintainer choice and real Android connection evidence before merge.

## What This Changes

The branch changes Android gateway endpoint parsing to strip percent-encoded IPv6 zone suffixes from parsed hosts and updates two parser tests to expect zone-free display URLs.

## Best Possible Solution

Preserve scoped endpoint semantics by either rejecting scoped IPv6 gateway URLs with clear Android copy or carrying the scope through a connection path that can resolve the interface explicitly.

## Reproduction Assessment

Yes from source inspection: current main accepts scoped IPv6 endpoint strings, stores the encoded scope in GatewayEndpointConfig.host, then builds a WebSocket URL string that OkHttp rejects for scoped host syntax. I did not run a live Android gateway connection.

## Solution Assessment

No. Stripping the scope makes the URL string parser happy but loses the interface identifier, so the safer solution is to reject scoped inputs as unsupported or preserve the scope through a dedicated connection path.
