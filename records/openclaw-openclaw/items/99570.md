## What This Changes

The PR changes Android gateway endpoint parsing to reject scoped IPv6 hosts containing `%`, and updates two parser tests to expect those inputs to be invalid.

## Best Possible Solution

Merge the fail-closed scoped IPv6 rejection after redacted Android behavior proof shows the real validation path and maintainers accept scoped dialing as unsupported for now.

## Reproduction Assessment

Yes, from source and upstream OkHttp inspection: current main stores the scoped host from URI.host, then builds a WebSocket URL string that OkHttp parses by percent-decoding the host and rejecting it as an invalid IPv6 literal. I did not run a live Android connection.

## Solution Assessment

Yes, as an acceptable narrow fail-closed mitigation: rejecting scoped IPv6 hosts avoids silent interface loss and avoids an OkHttp URL parser failure. Full scoped IPv6 connection support would be a broader connection-path design, so maintainer acceptance is still needed.
