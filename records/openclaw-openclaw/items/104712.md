- `merge-risk: 🚨 message-delivery`: One idempotency key can produce multiple agent runs while the first admission result is pending.

## Summary

The PR addresses a real gap where agent hooks can be acknowledged before runner admission, but the current head still breaks idempotency during the new asynchronous wait: concurrent requests with the same key can each dispatch a run before either successful result is cached. The execution-start callback is an appropriate admission boundary, but this P1 race and missing live behavior proof block merge.

## What This Changes

The PR makes agent hook dispatch wait for execution admission, returns pre-start failures as 409, 502, or 503 responses, and caches successful replay IDs after admission.

## Best Possible Solution

Keep the execution-start admission boundary, but use one replay state machine for pending and completed dispatches across direct and mapped hooks: concurrent duplicates share the pending result, failed admissions are evicted for retry, and successful run IDs retain the existing TTL behavior.
