## Summary

The PR addresses a real regression introduced by the new detached hook path, but it should not merge as written: startup HTTP status is inferred from mutable error prose, the 15-second cancel-on-queue policy lacks owner-level coverage, and the external PR has no real gateway proof.

## What This Changes

The branch makes direct and mapped agent hooks await runner entry, returns 409/502/503 for failures before entry, caches idempotency success only after admission, and keeps later failures asynchronous.

## Best Possible Solution

Keep `runner_entered` as the success boundary, but have the isolated-run owner return a closed startup outcome code, explicitly define and test the queue-admission deadline, and map that typed result to documented HTTP retry semantics.
