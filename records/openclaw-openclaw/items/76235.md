## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P2] Regenerate full caches after core-only repairs:** `src/commands/doctor-completion.ts:296-297`
  - body: `ensureCompletionCacheExists` returns `true` for any existing cache file before considering `generationMode`. If doctor/update previously wrote a `core-only` cache, onboarding or another `full` caller will accept that plugin-free file as complete, so plugin commands stay missing from user-facing completion until a manual rebuild. Force regeneration for `full` mode when the existing cache might be core-only, or record cache mode metadata.
  - confidence: 0.9
- **[P2] Generate full caches for prompted installs:** `src/commands/doctor-completion.ts:274`
  - body: The fresh-install branch runs after the user accepts an interactive `Enable ... shell completion` prompt, but it still writes the cache with `core-only`. Since the completion command skips plugin CLI registration under that mode, the newly installed profile points at a cache missing plugin commands; keep `core-only` for automatic repairs and use `full` for explicit install prompts, including the matching update prompt.
  - confidence: 0.91
- **[P2] Scope core-only writes to the checked shell:** `src/commands/doctor-completion.ts:232`
  - body: These `core-only` calls omit `shell`, so the spawned `completion --write-state` writes every shell cache even though the status check only proved the active shell needed repair. Repairing one missing cache can overwrite other shells' existing full caches with plugin-free scripts; pass the resolved shell into the generated cache call for repair writes.
  - confidence: 0.88
- **[P2] Remove the release-owned changelog entry:** `CHANGELOG.md:11`
  - body: This prior ClawSweeper finding is still unfixed: normal PRs should leave `CHANGELOG.md` to release generation. Keep this release-note wording in the PR body or squash message and drop the PR-specific line.
