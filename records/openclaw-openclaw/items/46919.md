## Summary

Keep open. Current main and the latest release already provide narrow tokenless/private-ingress and Tailscale identity paths, but the requested config flag would deliberately weaken Gateway token, HTTPS, Tailscale, device-identity, pairing, and HTTP auth boundaries, so this remains a maintainer security/product decision rather than cleanup.

## What This Changes

Request to add a config flag that disables Gateway URL-token requirements and also relaxes HTTPS, Tailscale, device-identity, pairing, and related auth checks for trusted deployments.

## Best Possible Solution

Keep the current narrow token/password, trusted-proxy, verified Tailscale identity, and break-glass boundaries unless maintainers explicitly sponsor a named dangerous private-ingress or tailnet policy with warnings, audit coverage, docs, startup validation, and focused auth tests.
