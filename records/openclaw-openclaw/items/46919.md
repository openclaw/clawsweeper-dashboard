## Summary

Keep open. Current main and v2026.6.11 still support only narrow tokenless paths while explicitly rejecting broader Tailscale/no-auth exposure, so disabling URL tokens, HTTPS, device identity, and pairing remains a security-sensitive product decision.

## What This Changes

Request to add a config-controlled mode that disables URL-token authentication, HTTPS/MagicDNS requirements, and Control UI token/pairing/device-identity checks for trusted tailnet setups.

## Best Possible Solution

Maintainers should either keep the current token/password/trusted-proxy/Tailscale identity boundaries or explicitly design a named dangerous private-ingress/tailnet policy with warnings, docs, startup validation, audit behavior, and regression coverage.

## Reproduction Assessment

Not applicable as a bug reproduction. Source, tests, docs, and the latest release show the current behavior: only narrow tokenless paths are supported, while the requested blanket bypass is intentionally absent.

## Solution Assessment

No for the exact proposed shape. A urlToken-style blanket bypass is not the safest maintainable solution; if accepted, it should be a deliberate dangerous private-ingress or tailnet policy with warnings, audit behavior, docs, and coverage.
