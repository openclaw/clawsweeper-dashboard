## Summary

Keep open. Current main and the latest release still do not implement the requested blanket token, HTTPS, Tailscale URL, device-identity, and pairing bypass, and the remaining request needs maintainer security/product direction.

## What This Changes

Add a config flag that disables tokenized Gateway URL/auth, HTTPS or Tailscale URL constraints, device identity, and pairing for private or tailnet deployments.

## Best Possible Solution

Keep the current token/password, trusted-proxy, verified Tailscale identity, and break-glass boundaries unless maintainers explicitly sponsor a named dangerous private-ingress or tailnet policy with warnings, audit coverage, docs, startup validation, and focused regression tests.
