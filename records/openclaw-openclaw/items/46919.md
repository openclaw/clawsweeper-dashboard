## Summary

Keep open. Current main and v2026.6.11 provide only narrow tokenless or break-glass paths, while this issue asks for a broader config-driven bypass across Gateway token/password auth, HTTPS/Tailscale URL behavior, device identity, pairing, and HTTP/Control UI auth boundaries.

## What This Changes

Request a config flag or mode to disable tokenized Gateway/Control UI access, HTTPS/Tailscale URL constraints, device identity, and pairing for trusted private or tailnet deployments.

## Best Possible Solution

Keep the current narrow token/password, trusted-proxy, verified Tailscale identity, and break-glass boundaries unless maintainers explicitly sponsor a named dangerous private-ingress or tailnet policy with warnings, audit coverage, docs, startup validation, and focused regression tests.
