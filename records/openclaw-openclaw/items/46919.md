## Summary

Keep open. Current main and the latest release support narrow tokenless paths, but the requested `urlToken=0/1` style bypass would weaken Gateway token, HTTPS, Tailscale, device-identity, pairing, and HTTP auth boundaries, so this remains a maintainer security/product decision.

## What This Changes

The issue requests a config-controlled way to disable URL token, HTTPS forcing, and related Control UI access gates for trusted tailnet or internal deployments.

## Best Possible Solution

Keep the current narrow token/password, trusted-proxy, verified Tailscale identity, and break-glass boundaries unless maintainers explicitly sponsor a named dangerous private-ingress or tailnet policy with warnings, docs, startup validation, and focused regression coverage.
