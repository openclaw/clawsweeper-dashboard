## Summary

Keep open. Current main and the latest release still do not implement the requested blanket token/HTTPS/device-identity/pairing bypass, and the request intentionally changes Gateway auth and Tailscale trust boundaries that require maintainer security/product direction.

## What This Changes

The issue requests a config-controlled mode that disables URL token requirements, HTTPS or Tailscale URL constraints, device identity, and pairing for trusted tailnet/private deployments.

## Best Possible Solution

Keep the current narrow token/password, trusted-proxy, verified Tailscale identity, and break-glass boundaries unless maintainers explicitly sponsor a named dangerous private-ingress or tailnet policy with warnings, audit coverage, docs, startup validation, and focused regression tests.

## Solution Assessment

No for the exact proposed shape. A generic urlToken=0/1 blanket bypass is not the narrowest maintainable solution; if maintainers accept the direction, it should be an explicit dangerous policy with warning, audit, docs, and test coverage.
