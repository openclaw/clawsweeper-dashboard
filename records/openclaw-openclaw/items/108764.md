## Summary

This PR addresses a real first-run macOS Gateway blocker and has strong live proof, but the current head still has one blocking concurrency defect: a caller whose enable request is superseded can receive the newer request’s success result and then wait on its stale port until timeout.

## What This Changes

Serializes macOS managed-Gateway enable requests, validates whether an existing LaunchAgent is reusable, repairs stale services, and adds lifecycle regression coverage.

## Best Possible Solution

Associate completion with each enable request—either report that an older request was superseded and restart readiness against the effective request, or return the effective port—and add a two-port regression proving neither caller falsely times out.
