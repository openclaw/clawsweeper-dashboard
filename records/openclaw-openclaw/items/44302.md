## Summary

Keep open. Current main and v2026.6.11 still intentionally keep implicit WebChat-originated replies local unless explicit external delivery is set, and the requested default-off mirroring config is absent; related PRs are closed unmerged and the broader origin-delivery issue still needs maintainer product/security direction.

## What This Changes

Request to add an opt-in session config that mirrors Control UI/WebChat replies to the session's last established external channel.

## Best Possible Solution

Define a maintainer-approved, default-off cross-surface delivery policy with stale-route, duplicate-delivery, authorization, and privacy rules before implementing this narrow mirroring config or folding it into the broader origin-delivery model.

## Reproduction Assessment

Yes, at source level. Current main keeps implicit WebChat turns internal unless explicit delivery is set, and the requested mirroring config key is absent from the session schema.

## Solution Assessment

Unclear until maintainers choose the policy. A default-off mirror flag is plausible, but the best fix must define route freshness, authorization, duplicate-delivery, and privacy behavior before code changes.
