## Summary

Keep open. Current main and v2026.6.11 still intentionally keep WebChat/Control UI replies internal unless an explicit delivery route is set, and the requested default-off WebChat-to-last-external-channel mirror config is absent; the remaining work is a product and security-boundary decision.

## What This Changes

Request to add an opt-in session configuration that mirrors WebChat/Control UI replies to the session's last established external channel.

## Best Possible Solution

Define one explicit cross-surface delivery policy with stale-route, authorization, duplicate-delivery, and failure-handling rules, then implement either the default-off mirroring config or fold it into the accepted origin-delivery model.
