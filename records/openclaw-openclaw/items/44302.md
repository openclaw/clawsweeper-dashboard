## Summary

Keep open. Current main and v2026.6.11 still preserve external route state but intentionally keep WebChat-originated replies local unless an explicit external delivery route is set; the requested default-off mirroring config remains a product and security decision.

## What This Changes

Request an opt-in config setting that mirrors Control UI/WebChat replies to the session's last active external channel while keeping default behavior unchanged.

## Best Possible Solution

Define a single default-off cross-surface delivery policy with stale-route, no-route, duplicate-delivery, authorization, and privacy rules, then implement this narrow config or fold the workflow into an accepted route-pinning model.

## Reproduction Assessment

Yes, at source level. Current routing and Gateway tests show WebChat-originated turns do not inherit external delivery without explicit delivery, and the requested config key is absent.

## Solution Assessment

Unclear until maintainers choose the delivery policy. A default-off mirror flag is plausible, but the best fix must define route freshness, authorization, duplicate-delivery, and privacy behavior first.
