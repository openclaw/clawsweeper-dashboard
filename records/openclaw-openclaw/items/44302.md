## Summary

Keep open. Current main and v2026.6.11 still intentionally keep ordinary WebChat replies on WebChat and do not provide the requested default-off WebChat-to-last-external-channel mirroring config; the remaining choice is a product/security-boundary decision.

## What This Changes

Request an opt-in session config that mirrors Control UI/WebChat-originated replies to the session's last active external channel when one exists.

## Best Possible Solution

Define one explicit cross-surface delivery policy with stale-route, authorization, duplicate-delivery, and failure-handling rules, then implement either the default-off mirroring config or fold it into the accepted origin-delivery model.
