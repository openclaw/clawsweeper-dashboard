## Summary

Keep open. Current main preserves external route state in related internal/WebChat paths, but it still blocks implicit WebChat-to-external reply routing without explicit delivery and does not expose the requested default-off mirroring config.

## What This Changes

The issue requests an opt-in config path to mirror Control UI WebChat replies to the session's last active external channel for multi-device workflows.

## Best Possible Solution

Have a maintainer choose one explicit cross-surface delivery policy, then implement either this default-off mirror flag or fold the WebChat case into the broader origin-delivery model with security-reviewed safeguards and live channel proof.
