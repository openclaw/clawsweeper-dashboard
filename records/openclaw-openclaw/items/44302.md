## Summary

Keep open. Current main and v2026.6.11 still keep WebChat/Control UI replies internal unless explicitly routed, and the requested opt-in mirroring config is absent; this remains a product and security-boundary decision.

## What This Changes

Request an optional default-off setting that mirrors Control UI/WebChat replies to the session's last active external channel.

## Best Possible Solution

Define one explicit cross-surface delivery policy with stale-route, authorization, duplicate-delivery, and failure-handling rules, then implement either a default-off mirroring config or fold this scenario into the accepted origin-delivery model with live channel proof.
