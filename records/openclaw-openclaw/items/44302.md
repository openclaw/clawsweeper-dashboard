## Label Justifications

- `P2`: This is a medium-impact feature/product decision for a multi-device workflow, not an emergency regression or release blocker.
- `impact:message-loss`: The requested behavior is about whether webchat-originated replies also reach external channels instead of being visible only in Control UI.

## Summary

Keep open. Current main preserves external route metadata and supports explicit delivery, but it does not implement the requested default-off webchat-to-last-external-channel mirroring config; the remaining decision is product/security policy for cross-channel duplication.

## What This Changes

The issue requests an opt-in session setting that mirrors Control UI/webchat replies to the session’s last active external channel for multi-device workflows.

## Best Possible Solution

Keep this as a maintainer-owned product/security design item until the preferred opt-in shape is chosen; any implementation should preserve default webchat-only behavior, define destination authorization and revocation, and add focused Gateway/reply-routing tests and docs.
