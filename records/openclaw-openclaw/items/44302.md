## Summary

Keep open. Current main preserves some external route state, but it still blocks ordinary WebChat/Control UI turns from inheriting or mirroring external delivery unless explicit delivery is requested, and the requested default-off mirroring config does not exist.

## What This Changes

The issue requests an optional config flag to mirror Control UI replies to the session's last active external channel for multi-device workflows.

## Best Possible Solution

Have maintainers define one explicit cross-surface delivery policy, then implement either this default-off mirror flag or fold the WebChat case into the broader origin-delivery model with security-reviewed safeguards and live Discord or Telegram proof.
