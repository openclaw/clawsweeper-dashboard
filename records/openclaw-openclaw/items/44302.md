## Summary

Keep open. Current main still intentionally blocks implicit WebChat-to-external routing unless an explicit delivery route is set, the requested default-off mirroring config is absent, and the remaining choice is a product/security decision rather than a cleanup close.

## What This Changes

Add an optional session config that mirrors Control UI/WebChat replies to the session's last established external channel route.

## Best Possible Solution

Define one explicit cross-surface delivery policy with stale-route, authorization, duplicate-delivery, and failure-handling rules, then implement either the default-off mirroring config or fold it into the accepted origin-delivery model.
