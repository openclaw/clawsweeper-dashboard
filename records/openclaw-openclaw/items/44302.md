## Summary

Keep open. Current main and v2026.6.11 still intentionally keep internal WebChat/Control UI turns from inheriting or mirroring external routes unless explicit delivery is set, and the requested opt-in mirroring config is absent; the remaining work needs maintainer product and security policy before implementation.

## What This Changes

The issue requests an opt-in setting that mirrors Control UI/WebChat replies to the session's last active external channel for multi-device workflows.

## Best Possible Solution

Define one explicit cross-surface delivery policy with stale-route, authorization, duplicate-delivery, and failure-handling rules, then implement the default-off mirroring config or fold it into an accepted origin-delivery model with live channel proof.

## Reproduction Assessment

Yes, source-level reproduction is clear: current main treats internal WebChat turns without explicit delivery as non-routable to the originating external channel, and gateway tests assert that WebChat clients do not inherit external routes. I did not run a live Discord or Telegram reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the policy. A default-off mirror flag is plausible, but the best fix must define route freshness, authorization, duplicate-delivery, privacy, and failure behavior before code changes.
