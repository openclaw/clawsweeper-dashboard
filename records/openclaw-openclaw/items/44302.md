## Summary

Keep open. Current main and v2026.6.11 still lack the requested WebChat-to-last-external mirroring config, and the remaining work needs a maintainer product/security decision because it would intentionally send Control UI output to an external channel selected from session route state.

## What This Changes

The issue requests a default-off config option that mirrors Control UI/WebChat replies to the session's last active external channel for browser-plus-mobile workflows.

## Best Possible Solution

Define one explicit cross-surface delivery policy with stale-route, authorization, duplicate-delivery, and failure-handling rules, then implement either the default-off mirroring config or fold it into the accepted origin-delivery model.
