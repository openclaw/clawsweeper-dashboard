## Summary

Keep open. Current main and v2026.6.11 still block implicit WebChat/Control UI reply routing to external channels and the requested opt-in mirroring config is absent, so this remains a product and security-boundary decision rather than a cleanup close.

## What This Changes

The issue requests an opt-in setting to mirror Control UI/webchat replies to the last active external channel for multi-device workflows.

## Best Possible Solution

Define one explicit cross-surface delivery policy with stale-route, authorization, duplicate-delivery, and failure-handling rules, then implement either a default-off mirroring config or fold this scenario into the accepted origin-delivery model with live channel proof.
