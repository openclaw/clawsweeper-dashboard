## Summary

Keep open. Current main and the latest release still lack the requested opt-in mirroring config, and current routing intentionally prevents implicit WebChat-to-external delivery unless explicit delivery is set; the remaining work needs product and security direction.

## What This Changes

The issue requests an opt-in setting to mirror Control UI/WebChat replies to a session's last active external channel.

## Best Possible Solution

Define one explicit cross-surface delivery policy with authorization, stale-route, duplicate-delivery, and failure semantics, then either implement a default-off mirroring config or fold the behavior into an accepted pin/echo model with live Discord or Telegram proof.
