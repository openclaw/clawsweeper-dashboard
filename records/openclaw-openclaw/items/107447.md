## Summary

Keep open: the documented full-auto contract says exec should skip approval prompts, while the current approval bridge can still let native-relay unavailability produce a decline; the specifically linked closing fix remains open and should be reviewed rather than duplicating the work. ([github.com](https://github.com/openclaw/openclaw/blob/main/docs/tools/exec-approvals.md?utm_source=openai))

## What This Changes

Prevent unavailable or stale native-hook relay state from declining Codex command approvals when the effective runtime policy is full-auto.

## Best Possible Solution

Land a narrowly scoped approval-ordering fix that ignores only relay-unavailability errors under the exact full-auto policy, while preserving explicit denials, fail-closed malformed responses, normal hook execution, and focused regression coverage.
