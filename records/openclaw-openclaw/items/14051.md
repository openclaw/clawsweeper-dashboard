## Summary

Keep open: current main and the latest release still lack activity-based heartbeat idle-timeout config and runtime gating, while related open work only covers narrower missing-HEARTBEAT.md, retry-cadence, or runaway-spend cases.

## What This Changes

Request an activity-based heartbeat idle timeout so periodic heartbeats pause after a configurable window without allowed inbound user activity.

## Best Possible Solution

Keep this issue as the canonical heartbeat activity/idle-timeout tracker, have maintainers choose the public config and activity contract, then implement config/schema/docs plus runtime gating without suppressing event, cron, commitment, active-hours, busy-deferral, isolatedSession, or delivery behavior.

## Reproduction Assessment

Yes, at source level: current heartbeat types/schema/docs lack the proposed key, and the runner/scheduler paths do not consume recent inbound activity before scheduled heartbeat runs. I did not run a live idle-token reproduction in this read-only review.

## Solution Assessment

Unclear as an implementation until maintainers choose the public config name and activity source. The best fix is not another missing-file skip; it is a deliberate activity gate at the heartbeat scheduling or preflight boundary using the chosen user/channel activity contract.
