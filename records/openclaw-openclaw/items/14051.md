## Summary

Keep open: current main and the latest release still lack the requested heartbeat idle-timeout config and runtime gate based on recent allowed inbound activity. The related open PRs cover narrower missing-HEARTBEAT.md token-saving behavior, not this broader heartbeat activity contract.

## What This Changes

Request adds an activity-based heartbeat idle-timeout option so scheduled heartbeats pause after inactivity and resume after the next allowed inbound user message.

## Best Possible Solution

Keep this as the canonical heartbeat activity/idle-timeout tracker, choose the public config and activity source, then implement schema/docs/runtime gating while preserving active-hours, busy deferral, event/cron wakes, due commitments, isolatedSession, lightContext, and delivery behavior.

## Reproduction Assessment

Yes, at source level: current heartbeat types/schema/docs lack the requested key, and the runner/scheduler paths do not consume recent inbound activity before scheduled heartbeat runs. I did not run a live idle-token reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public config name and activity source. The best fix is not another missing-file skip; it is a deliberate heartbeat activity gate at the scheduling or preflight boundary with config/schema/docs coverage.
