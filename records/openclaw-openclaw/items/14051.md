## Summary

Keep open: current main and the latest release still lack the requested activity-based heartbeat idle timeout. The remaining work is not covered by adjacent missing-HEARTBEAT.md or runaway-spend fixes because this issue asks for a public activity/idle contract that gates scheduled heartbeat runs on recent allowed inbound user activity.

## What This Changes

Request adds a configurable heartbeat idle timeout so scheduled heartbeats pause after allowed inbound user inactivity and resume on the next activity.

## Best Possible Solution

Keep this as the canonical heartbeat activity/idle-timeout tracker, choose one public config and activity contract, then implement config/schema/docs plus scheduler or preflight gating without suppressing event, cron, commitment, active-hours, busy-deferral, isolatedSession, or delivery behavior.

## Reproduction Assessment

Yes, at source level: current heartbeat types/schema/docs lack the requested key, and the runner/scheduler paths do not consume recent inbound activity before scheduled heartbeat runs. I did not run a live idle-token reproduction in this read-only review.

## Solution Assessment

Unclear as specified: the requested behavior is in the right owner area, but the exact public config name and activity source need maintainer choice. The best fix is a deliberate activity gate at the heartbeat scheduling or preflight boundary, not another missing-file-only skip.
