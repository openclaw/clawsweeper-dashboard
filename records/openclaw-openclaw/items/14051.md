## Summary

Keep open: current main still lacks a heartbeat idle-timeout config and does not gate scheduled heartbeat runs on recent allowed inbound activity. The remaining work is product-sensitive because it adds public heartbeat configuration and must define the activity source, session boundary, and wake exceptions.

## What This Changes

Add an activity-based idle timeout for heartbeat scheduling so periodic heartbeat runs pause after a configured period without allowed inbound user activity.

## Best Possible Solution

Keep this as the canonical heartbeat activity-idle tracker and have maintainers choose a public config/activity contract before implementation across types, strict schema, docs, runtime gating, and regression coverage.

## Reproduction Assessment

Yes, at source level: current heartbeat types/schema/docs lack the proposed key, and the runner/scheduler paths do not consume recent allowed inbound activity before scheduled heartbeat runs. I did not run a live gateway reproduction because this review is read-only.

## Solution Assessment

No implementation path is ready for automation yet. The maintainable fix needs a maintainer decision on config naming, activity source, allowed-sender scope, and wake exceptions before code changes.
