## Summary

Keep open: current main and v2026.6.11 still do not expose or honor an activity-based heartbeat idle timeout, and related items cover narrower missing-file, cron, retry, voice, or runaway-cost cases rather than replacing this canonical product/config decision.

## What This Changes

The issue requests a public heartbeat idle-timeout setting so scheduled heartbeats pause after allowed-user inactivity and resume on the next inbound activity.

## Best Possible Solution

Keep this as the canonical heartbeat activity idle-timeout tracker until maintainers approve one public config contract, then implement a cohesive schema/types/docs/runtime/test path that gates scheduled heartbeats on recent real activity without regressing manual or event-backed wakes.
