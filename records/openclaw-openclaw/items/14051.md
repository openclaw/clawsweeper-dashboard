## Summary

Keep open: current main and v2026.6.11 still do not expose or honor an activity-based heartbeat idle timeout, and related heartbeat reports cover narrower retry, missing-file, long-idle spend, or voice-mode behavior rather than replacing this canonical product/config decision.

## What This Changes

Request to add public heartbeat configuration that pauses scheduled heartbeats after a configured window without inbound allowed-sender activity and resumes on the next activity.

## Best Possible Solution

Keep this as the canonical heartbeat activity idle-timeout tracker until maintainers approve one public config contract, then implement schema/types/docs/runtime/test coverage that gates scheduled heartbeats on recent real activity without regressing manual or event-backed wakes.
