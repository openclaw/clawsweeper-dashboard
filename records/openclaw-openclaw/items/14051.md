## Summary

Keep open: current main and v2026.6.11 still expose periodic heartbeat, active-hours, busy-deferral, lightweight/isolated-session, and delivery controls, but not an activity-based idle-timeout config or runtime gate based on recent allowed inbound user activity. Related open PRs cover narrower missing-HEARTBEAT.md behavior, and related issues cover retry contention or runaway-spend defenses, so this remains the canonical product/config tracker.

## What This Changes

Request an activity-based heartbeat idle-timeout option that starts heartbeats on allowed inbound user activity and pauses them after a configured inactivity window.

## Best Possible Solution

Keep this issue as the canonical heartbeat activity idle-timeout tracker, have maintainers choose the public config and activity contract, then implement the gate in heartbeat config/schema/docs and runner preflight or scheduling while preserving event, cron, commitment, active-hours, busy-deferral, isolatedSession, and delivery behavior.

## Reproduction Assessment

Yes, at source level: current heartbeat types/schema/docs lack the proposed key, and the runner/scheduler paths do not consume recent allowed inbound activity before scheduled heartbeat runs. I did not run a live idle-token reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public config name and activity source. The best fix is a deliberate activity gate at the heartbeat scheduling or preflight boundary, not another missing-file skip or unrelated retry tweak.
