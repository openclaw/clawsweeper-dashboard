## Summary

Keep open: current main and the latest release still lack the requested activity-based heartbeat idle timeout, while related open work covers narrower missing-file, stale-session, retry-cadence, or runaway-spend cases rather than this public config and activity contract.

## What This Changes

Add a heartbeat idle-timeout option that runs scheduled heartbeats only after recent allowed inbound activity and pauses them after inactivity.

## Best Possible Solution

Keep this as the canonical heartbeat activity/idle-timeout tracker, choose the public config and activity contract, then implement schema/docs/runtime gating without suppressing event, cron, commitment, active-hours, busy-deferral, isolatedSession, or delivery behavior.

## Reproduction Assessment

Yes, at source level: current heartbeat types/schema/docs lack the requested key, and the runner/scheduler paths do not consume recent inbound activity before scheduled heartbeat runs. I did not run a live idle-token reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the public config name and activity source. The best fix is not another missing-file skip; it is a deliberate activity gate at the heartbeat scheduling or preflight boundary using the chosen user/channel activity contract.
