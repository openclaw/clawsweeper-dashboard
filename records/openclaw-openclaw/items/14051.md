## Summary

Keep open: current main still lacks the requested configurable activity-based heartbeat idle window, while the open candidate PR remains unmerged and requires a product decision about activity scope, defaults, and scheduling semantics; the related reports address narrower heartbeat failure modes rather than replacing this canonical request.

## What This Changes

Add an optional heartbeat idle timeout that pauses periodic runs after allowed inbound user activity has been absent for a configured duration.

## Best Possible Solution

Adopt one additive, disabled-by-default heartbeat inactivity window backed by a canonical allowed-inbound-activity timestamp, with schema/help/docs and focused tests covering fresh configuration, existing-user defaults, per-agent overrides, wake events, active hours, busy retries, and reactivation after a new message.
