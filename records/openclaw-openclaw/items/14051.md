## Summary

Keep open: current main and the latest release still lack an activity-based heartbeat idle-timeout config or runtime gate, and related open PRs only cover narrower missing-HEARTBEAT.md behavior rather than this allowed-inbound-activity window.

## What This Changes

The issue requests an activity-based heartbeat idle timeout so periodic heartbeats pause after a configured window with no allowed inbound user activity.

## Best Possible Solution

Keep this issue as the canonical activity-based heartbeat idle-timeout tracker, have maintainers choose the public config/activity contract, then implement the gate in heartbeat config/schema/docs and runner preflight/scheduling without suppressing event, cron, commitment, active-hours, busy-deferral, isolatedSession, or delivery behavior.

## Reproduction Assessment

Yes, at source level: current heartbeat types/schema/docs lack the proposed key, and the runner/scheduler paths do not consume recent inbound activity before scheduled heartbeat runs. I did not run a live idle-token reproduction in this read-only review.

## Solution Assessment

Unclear as an implementation until maintainers choose the public config name and activity source. The best fix is not another missing-file skip; it is a deliberate activity gate at the heartbeat scheduling or preflight boundary using the chosen user/channel activity contract.
