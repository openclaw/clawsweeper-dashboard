## Summary

Keep open: current `main` and the latest release still do not expose or honor an activity-based heartbeat idle timeout, and related items cover narrower heartbeat cost, retry, missing-file, voice, or zombie-session behavior rather than replacing this canonical product/config decision.

## What This Changes

The issue requests a heartbeat idle-timeout option that starts heartbeats after user activity and pauses scheduled heartbeat runs after a configurable period without allowed inbound activity.

## Best Possible Solution

Keep this as the canonical heartbeat activity idle-timeout tracker until maintainers approve one public config contract, then implement a cohesive schema/types/docs/runtime/test path that gates scheduled heartbeats on recent real activity without regressing manual or event-backed wakes.
