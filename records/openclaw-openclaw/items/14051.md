## Summary

Keep open: current main and v2026.6.11 still lack heartbeat idle-timeout config and runtime gating on recent allowed inbound activity. This remains the canonical tracker; adjacent open PRs only address missing-HEARTBEAT.md defaults, and newer related issues cover narrower heartbeat retry or runaway-spend failures.

## What This Changes

Add a heartbeat idle-timeout option that starts heartbeats after user activity and pauses scheduled heartbeat runs after a configurable inactivity window.

## Best Possible Solution

Keep this as the canonical heartbeat activity-idle tracker and have maintainers choose the public config/activity contract before implementation.

## Reproduction Assessment

Yes, at source level: current heartbeat types/schema/docs lack the proposed key, and the runner/scheduler paths do not consume recent inbound activity before scheduled heartbeat runs.

## Solution Assessment

Unclear until maintainers choose the contract; the requested behavior is plausible, but the maintainable fix needs product decisions on config naming, activity source, allowed-sender scope, and wake exceptions.
