## Summary

Keep open: current main still lacks the requested activity-based heartbeat idle timeout, and related open work covers narrower missing-file, retry-cadence, or runaway-spend cases rather than the public config and activity contract requested here.

## What This Changes

Request to add heartbeat configuration that starts heartbeat activity after user conversation and pauses scheduled heartbeat runs after a configurable window with no allowed inbound activity.

## Best Possible Solution

Keep this as the canonical heartbeat activity/idle-timeout tracker, have maintainers choose the public config and activity contract, then implement config/schema/docs plus runtime gating without suppressing event, cron, commitment, active-hours, busy-deferral, isolatedSession, or delivery behavior.

## Reproduction Assessment

Yes, at source level: current heartbeat types/schema/docs lack the requested key, and the runner/scheduler paths do not consume recent inbound activity before scheduled heartbeat runs. I did not run a live idle-token reproduction in this read-only review.

## Solution Assessment

Unclear as an implementation until maintainers choose the public config name and activity source. The best fix is not another missing-file skip; it is a deliberate activity gate at the heartbeat scheduling or preflight boundary using the chosen user/channel activity contract.
