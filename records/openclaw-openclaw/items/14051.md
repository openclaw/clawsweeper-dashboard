## Summary

Keep open: current main and the latest release still expose periodic heartbeat, active-hours, busy-deferral, light-context, and isolated-session controls, but not an activity-based idle-timeout config or runtime gate. The open related PRs address narrower missing-HEARTBEAT.md/default-idle cases and do not replace this canonical heartbeat activity-window decision.

## What This Changes

Request add heartbeat idle-timeout behavior that starts or re-arms on allowed inbound user activity and pauses scheduled heartbeat runs after a configurable idle window.

## Best Possible Solution

Define a maintainer-approved core heartbeat activity model and add one canonical config/schema/docs/runtime path that gates scheduled heartbeats on recent real user/channel activity while preserving explicit wakes and existing cost controls.
