## What This Changes

The PR changes the reply-session initialization concurrency test so the child process writes JSON readiness/result markers to a temporary file and renames them into place atomically.

## Best Possible Solution

Keep this PR open for maintainer handling and land the narrow test-harness atomic publish fix once required checks finish.

## Reproduction Assessment

Yes from source inspection, though not by rerunning locally: current main waits for marker file existence and immediately parses JSON that the child writes directly to the same path.

## Solution Assessment

Yes. A same-directory temp write plus rename is the narrowest maintainable fix because it preserves the existing file-existence synchronization contract while preventing partial JSON reads; a parent-side parse retry would hide the race instead of removing it.
