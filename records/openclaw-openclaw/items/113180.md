## What This Changes

Release the WhatsApp inbound-debounce conversation key once dispatch into the session lane begins, so a later same-chat message can steer an active agent run instead of waiting for the first turn to finish.

## System Context

WhatsApp groups inbound messages by conversation through a debounce layer before dispatching them into OpenClaw’s shared session queue. The session queue then decides whether a follow-up steers an active run or waits as a later turn.

## Best Possible Solution

Rebase the linked fix onto current main, separate key release from in-flight shutdown tracking, and prove that a second WhatsApp message steers an active run while shutdown still drains both deliveries correctly.
