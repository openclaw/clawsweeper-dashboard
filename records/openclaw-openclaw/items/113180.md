## Summary

Keep this issue open: the reported WhatsApp steering regression has a specific open implementation candidate at https://github.com/openclaw/openclaw/pull/113312, so closing before that PR lands would be premature. The issue report and candidate agree on the debounce ownership problem; the remaining gate is review plus real WhatsApp steering and shutdown-drain evidence for the proposed fix.

## What This Changes

Fix WhatsApp inbound debounce so a later message in the same conversation can reach active-run steering instead of waiting for the earlier agent turn to finish.

## System Context

WhatsApp's inbound monitor batches same-conversation messages through the shared keyed inbound debouncer before dispatching them to the agent/session lane. The session lane can steer an active run, but that capability is unreachable when the debounce key remains occupied by the full asynchronous dispatch.
