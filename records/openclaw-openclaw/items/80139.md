## Summary

Keep open for maintainer product review. Current OpenClaw contracts model execution status separately from delivery state, while this PR adds a fourth public `warning` status across Gateway and plugin hooks; that direction needs explicit acceptance before the branch is narrowed and its concrete defects are fixed.

## What This Changes

The branch adds a `warning` cron status for successful isolated agent runs whose final delivery fails, propagating it through scheduler state, Gateway/API, plugin hooks, CLI, Control UI, docs, tests, and run-log handling.

## Best Possible Solution

Keep execution status canonical (`ok` for successful agent execution) and expose delivery failures through `deliveryStatus`, `deliveryError`, and a delivery-specific UI indicator; add a fourth terminal status only if maintainers explicitly want that broader public contract and sponsor the compatibility rollout.
