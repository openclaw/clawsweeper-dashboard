## What This Changes

The PR replaces the closure-based `CanonicalMessageProofHub.withProofDecision` helper with explicit lock/unlock calls and updates `cancelCommand` to keep the proof decision, SQLite commit, and cache cleanup in the same synchronized section.

## Best Possible Solution

Land this focused Swift refactor after exact-head required CI settles, keeping the existing cancellation synchronization contract without the actor-capturing closure.

## Reproduction Assessment

Yes, source-reproducible: current main passes actor-isolated SQLite state and actor methods through the `withProofDecision` closure in `cancelCommand`, which matches the stated Swift 6.2 strict-concurrency diagnostic. I did not run Swift locally in this read-only review.

## Solution Assessment

Yes: explicit lock/unlock is the narrowest maintainable fix because it preserves the proof-decision lock across SQLite commit/cache cleanup while removing the synchronous closure that captures actor-isolated state. Unlocking before commit or moving the work out of the actor would reopen the cancellation/canonical-history race this helper protects.
