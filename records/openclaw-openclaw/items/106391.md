## Summary

This PR remains necessary, but the two previously identified profile-identity defects still block it: the OpenAI logical catalog projection can collapse profile-specific rows before picker-key creation, and picker availability is checked against any usable profile rather than the selected locked profile. It also still needs redacted real multi-profile behavior proof before merge.

## What This Changes

The PR carries optional auth-profile identity through model catalog entries and picker keys so identical provider/model rows can be selected separately by profile.

## System Context

Provider discovery builds model rows from configured authentication profiles, then routing projects those rows into the interactive model picker and the selected model reference is used at runtime. The profile identity must survive both projection and validation so a picker entry represents the same account that will execute it.

## Architecture Diagram

flowchart LR

  B --> C[Prepared model catalog]
  C --> D[Logical route projection]
  D --> E[Model picker options]
  E --> F[Profile-locked runtime selection]

## Best Possible Solution

Preserve profileId through the OpenAI logical route identity and projection, validate each picker row with that same profile as lockedProfileId, add focused regressions for both invariants, then post redacted terminal or runtime evidence from two real profiles through selection and execution.
