## Summary

The current head still has six merge-blocking security and consistency defects: explicit-once and auto-review grants are not fully rebound to current policy in either runtime, and stale conditional saves can recreate deleted approval state before returning a conflict.

## What This Changes

The PR adds cross-process serialization for exec-approval mutations, revalidates execution authorization in Node, Gateway, CLI, and macOS paths, and expands concurrency, revocation, and persistence coverage.

## Best Possible Solution

Capture the evaluated policy for every explicit and auto-review grant, require that snapshot or an equivalent current authorization basis at the locked commit in both runtimes, and perform base-hash validation through non-creating reads before any store initialization or normalization.

No. A shared cross-process transaction is the correct architectural boundary, but the implementation is incomplete until every consumed grant is revalidated and every losing conditional save is side-effect free.
