## Summary

Keep open: current main has provider-specific recovery for iMessage and Telegram pieces, but Slack and Discord still rely on live event handling without startup catch-up or history replay, so the requested cross-channel missed-inbound recovery remains unsolved.

## What This Changes

Request configurable post-startup catch-up or replay of inbound channel messages missed while the gateway was down.

## Best Possible Solution

Define a maintainer-approved provider-owned replay strategy for each affected stable channel, using shared SDK seams only where common and preserving channel policy, idempotency, and rate-limit constraints.

## Reproduction Assessment

Source-level reproduction is clear: Slack and Discord current main register live event listeners and lack startup catch-up/history replay, but no live Slack or Discord restart E2E was run in this review.

## Solution Assessment

Unclear as a single generic implementation; last-outbound-anchor catch-up is plausible, but the best fix should be provider-owned replay or durable receive logic with shared seams only where the contract is actually common.
