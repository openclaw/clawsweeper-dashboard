## Summary

Keep open: current main has iMessage-specific missed-message recovery and partial restart queue mitigations, but the requested Slack/Discord-style provider-history catch-up for inbound messages missed while the gateway or provider is offline is still unresolved.

## What This Changes

The issue requests provider-aware catch-up for inbound messages that arrive while the gateway or channel connection is offline during a restart.

## Best Possible Solution

Keep this as the canonical cross-channel missed-inbound catch-up tracker, choose a provider-owned replay/cursor contract, then land narrow Slack and Discord implementations with durable dedupe, policy parity, upgrade-safe config, and live channel proof.
