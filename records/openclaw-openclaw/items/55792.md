## Summary

Keep open: current main has iMessage-specific missed-message recovery and partial restart/queue mitigations, but the requested cross-channel catch-up for Slack/Discord-style messages missed while the gateway or provider is offline remains unresolved and needs maintainer product direction.

## What This Changes

The request is to add configurable post-startup catch-up for inbound channel messages missed while the gateway or provider was offline, using recent channel history or the last outbound message as a replay anchor.

## Best Possible Solution

Keep this as the cross-channel missed-inbound catch-up tracker, choose a provider-owned replay/cursor contract first, then land narrow Slack/Discord implementations with durable dedupe, policy parity, upgrade-safe config, and live channel proof.
