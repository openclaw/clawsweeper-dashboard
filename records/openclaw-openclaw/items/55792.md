## Summary

Keep open: current main has iMessage-specific downtime recovery and Telegram durable ingress, but Slack and Discord provider-history catch-up for messages missed while the gateway or provider is offline is still missing, and the generic cross-channel shape needs maintainer direction.

## What This Changes

The issue requests configurable post-startup catch-up of inbound channel messages missed during gateway downtime using provider history and idempotent replay.

## Best Possible Solution

Define a provider-owned channel/SDK catch-up contract, then implement bounded Slack and Discord history sweeps that reuse live authorization, durable dedupe, and replay policy with maintainer-approved defaults.
