## Summary

Keep open: current main has iMessage-specific downtime recovery, Telegram-specific durable ingress work, and partial restart queue mitigations, but the requested Slack/Discord-style post-startup provider-history catch-up for inbound messages missed while the gateway is offline is still unresolved.

## What This Changes

The issue requests provider-aware missed inbound message catch-up after gateway restarts, anchored around recent outbound/channel history with configurable replay limits.

## Best Possible Solution

Define a provider-owned, SDK-backed missed-inbound recovery contract with durable cursors/dedupe, live-policy parity, replay limits, and explicit default/config policy before extending Slack and Discord beyond the existing iMessage and Telegram-specific mechanisms.

Owner confidence: medium

Options:

- **Design a shared recovery contract (recommended):** Add a typed SDK/plugin recovery seam first, then implement Slack and Discord with provider-owned cursors, dedupe, policy checks, and replay limits.
- **Narrow to provider-owned opt-ins:** Implement Slack and Discord separately behind explicit per-provider configuration, accepting some duplicated policy until the shape proves itself.
- **Defer provider-history replay:** Keep only current iMessage, Telegram, and queue-drain mitigations until maintainers have live Slack/Discord restart proof and a clearer default policy.

## Reproduction Assessment

Yes at source level for the missing capability: current Slack and Discord paths handle live delivered events without a provider-history catch-up pass, while iMessage has channel-specific downtime replay. I did not run a live Slack/Discord restart reproduction in this read-only review.

## Solution Assessment

No, the issue sketch is plausible but not yet the best complete fix because Slack/Discord replay needs provider-specific history/thread handling, durable idempotency, and live policy parity. The cleaner path is a shared recovery contract with provider-owned implementations rather than ad hoc history scans.
