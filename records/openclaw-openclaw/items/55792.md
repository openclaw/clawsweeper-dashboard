## Summary

Keep open: current main has iMessage-specific downtime recovery and a merged Telegram webhook durability fix, but it still lacks the requested Slack/Discord/cross-channel missed-inbound catch-up after gateway downtime.

## What This Changes

## Best Possible Solution

Keep this as the canonical design tracker and land provider-owned replay or durable ingress paths, using shared SDK/core idempotency and state seams only where required.

## Solution Assessment

Unclear as a single generic implementation; the last-outbound anchor is plausible, but the safer shape is channel-owned recovery with shared durable receive and idempotency seams only where the plugin API needs them.
