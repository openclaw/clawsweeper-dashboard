## Summary

Keep open: current main has iMessage-specific downtime recovery and adjacent queue/dedupe restart fixes in flight, but Slack and Discord still do not fetch provider history after downtime, so the central missed-inbound catch-up request remains unresolved.

## What This Changes

Add provider-owned startup catch-up so inbound channel messages sent while the gateway is offline are fetched from channel history and processed once after reconnect.

## Best Possible Solution

Keep this as the canonical cross-channel missed-inbound catch-up tracker, choose a provider-owned replay/cursor contract, then land narrow Slack and Discord implementations with durable dedupe, policy parity, upgrade-safe config, and live channel proof.
