## Summary

Keep open: current main has iMessage restart recovery and Telegram durable ingress behavior, but Slack and Discord still lack the requested missed-inbound catch-up after gateway downtime, so the central cross-channel problem remains.

## What This Changes

Request cross-channel post-restart inbound catch-up so messages sent while the gateway is down are fetched from channel history, deduped, and processed after reconnect.

## Best Possible Solution

Keep this as the canonical tracker and design provider-owned catch-up or durable-receive paths for Slack and Discord, using shared SDK/core seams only where replay, idempotency, or configuration must be common.

## Reproduction Assessment

Yes at source level: Slack and Discord current-main paths process live events but do not run startup history catch-up, while iMessage shows the provider-specific recovery pattern; no live restart test was run.

## Solution Assessment

Unclear as a single implementation: the last-outbound anchor is plausible, but the best fix likely needs provider-owned replay semantics plus shared durability/idempotency seams where needed.
