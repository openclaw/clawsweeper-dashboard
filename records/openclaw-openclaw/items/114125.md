## Summary

This is a focused, plausible repair for the linked Telegram bug: the existing `linkPreview: false` preference reaches ordinary sends but not the streamed-draft send/edit path. The patch keeps the setting’s existing default behavior and covers both Bot API calls, but it still needs redacted after-fix proof from a real Telegram conversation before merge.

## What This Changes

The PR passes the existing Telegram `linkPreview` preference into streamed draft replies and sends `link_preview_options.is_disabled` on affected text sends and edits.

## System Context

Telegram replies can be emitted as an incrementally updated draft before final delivery. The channel configuration feeds that draft controller, which renders plain or HTML text and calls Telegram’s send and edit APIs to update the visible chat message.
