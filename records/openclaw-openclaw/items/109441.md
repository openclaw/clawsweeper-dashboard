## Summary

Keep open for maintainer handling: the Gateway-owned projection is the right direction and the prior interrupt and split-pane findings appear addressed, but the latest head still presents saved-but-unapplied configuration as the server default and contains a user-doc mismatch. The protected `maintainer` label also rules out automated cleanup.

## What This Changes

The PR makes Control UI active-run follow-ups inherit the Gateway’s effective webchat queue mode unless the browser has an explicit local override.

## Best Possible Solution

Keep the Gateway session projection as the canonical owner, source the Settings and startup fallback from the applied runtime snapshot, add a pending-unapplied-config regression test, describe Gateway-managed modes separately from the browser-local queue, and leave generated locale output to the established refresh workflow before landing.

## Reproduction Assessment

Yes at source level: current main defaults an absent browser preference to `steer` and applies it during active runs without consulting Gateway queue policy. A live current-main Gateway reproduction was not run during this read-only review.

## Solution Assessment

Mostly yes: projecting the effective mode from Gateway-owned session state is the narrowest maintainable fix because it includes session overrides and avoids duplicating queue policy in the browser. The Settings fallback must use applied runtime state, and the docs must distinguish Gateway queue modes from the browser-local outbox.
