## Summary

Keep open: the latest head fixes stale saved-config precedence by projecting the session’s effective queue mode, but it still converts inherited `interrupt` into browser-local queuing instead of honoring Gateway behavior. The submitted proof is limited to synthetic mock-Gateway screenshots and tests.

## What This Changes

The PR makes Control UI active-run follow-ups inherit the effective Gateway webchat queue mode unless the browser has an explicit local steer or queue override.

## Best Possible Solution

When no browser override exists, pass the effective four-state queue mode through `chat.send` and let the Gateway own `steer`, `followup`, `collect`, and `interrupt`; retain the explicit local override, add a versioned legacy-settings migration, and prove fresh-install and upgrade behavior against a real Gateway.
