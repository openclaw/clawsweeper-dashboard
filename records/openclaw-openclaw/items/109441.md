## Summary

Keep open: the server-owned direction is appropriate and earlier review blockers appear addressed, but the latest head still allows a stale projected queue mode to override newly applied Gateway configuration. Real behavior proof also remains mock-only.

## What This Changes

The PR adds an effective queue-mode field to Gateway session responses and makes Control UI active-run follow-ups inherit that policy unless the browser has an explicit local override.

## Best Possible Solution

Make the Gateway-projected effective mode authoritative, distinguish it from a raw session override, and clear or refetch it on an applied config revision before proving inherited and overridden modes against a real Gateway.

## Reproduction Assessment

Yes from source inspection: after an open pane caches an effective mode, applying a different webchat queue configuration leaves that cached value with higher precedence until session or history refresh. A live reproduction was not run.

## Solution Assessment

No, not yet. Server projection is the correct owner boundary, but the UI must not treat a cached resolved value as a permanent session override.
