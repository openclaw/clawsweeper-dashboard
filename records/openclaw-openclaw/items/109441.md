## Summary

Keep this PR open: the direction correctly removes the browser’s independent steering default, but the current head can still choose the wrong delivery path while edited configuration is saved but not applied to the running Gateway.

## What This Changes

Makes Control UI active-run follow-ups inherit the Gateway’s effective webchat queue mode by default while retaining a visible, resettable browser-local override.

## Best Possible Solution

Resolve follow-up behavior from an authoritative applied-runtime queue mode, preserve explicit browser overrides, and add a regression case where saved configuration differs from the running Gateway during an active run.

Question: Which authoritative state should the Control UI use for queue inheritance while saved configuration has not yet been applied to the running Gateway?

Rationale: The current config snapshot is not always the configuration handling chat.send, and choosing between caching the last applied value or exposing runtime-effective state crosses the UI/Gateway ownership boundary.

Likely owner: steipete

Owner confidence: high

Options:

- **Use applied runtime state (recommended):** Expose or retain an authoritative applied queue mode and keep using it until the Gateway applies the newly saved configuration.
- **Disable inheritance while pending:** Fall back to the browser override or a documented conservative mode whenever configNeedsApply indicates that the snapshot is not runtime-effective.
- **Accept transient divergence:** Merge the current behavior and explicitly accept that follow-ups can use a different delivery mode until configuration is applied.

## Reproduction Assessment

Yes. Run the Gateway with one webchat queue mode, save a different mode without applying it, then send a follow-up during an active run; the current source resolves the browser path from the saved snapshot rather than the running policy.

## Solution Assessment

No, not yet. Server inheritance with explicit browser overrides is the right boundary, but the inherited value must come from applied runtime state rather than a possibly pending configuration snapshot.
