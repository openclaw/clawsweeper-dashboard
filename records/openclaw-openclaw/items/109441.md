## Summary

Keep open: the Gateway-authoritative direction fixes the regression, but the current head still permits stale live queue policy and raw legacy session aliases to misroute active-run messages; the submitted evidence is mock-only rather than real behavior proof.

## What This Changes

The PR makes Control UI active-run follow-ups inherit the Gateway's effective queue mode while preserving a visible, resettable browser-local steer or queue override.

## Best Possible Solution

Use one normalized Gateway-owned queue-policy projection across `sessions.list`, `chat.history`, and `sessions.changed`, retain browser selection only as an explicit override, and prove fresh, upgraded, and live-policy-change behavior against a real Control UI and Gateway setup.
