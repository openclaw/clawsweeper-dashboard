## Summary

The owner-boundary direction is sound, but the latest head is not merge-ready: split panes can still lose a session-scoped queue override, the localization fallback artifact violates the Control UI i18n contract and currently fails its check, and the submitted behavior proof is mock-only.

## What This Changes

The PR makes Control UI active-run follow-ups inherit the Gateway’s effective webchat queue mode, exposes an explicit browser override/reset, and forwards inherited queue semantics through `chat.send`.

## Best Possible Solution

Keep the Gateway as the authority, but bind each pane to a stable effective queue mode for its own session, remove recorded i18n fallbacks, align the docs with Gateway-handled modes, and demonstrate the final flow against a real Gateway before merge.

## Solution Assessment

No, not yet. Projecting the canonical Gateway decision is the right design, but the implementation must retain pane-specific session authority and follow the localization workflow before it is the best complete fix.
