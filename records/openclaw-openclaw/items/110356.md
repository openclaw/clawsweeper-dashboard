## Summary

This PR has a focused implementation and credible after-fix CLI evidence, but it intentionally changes the default `openclaw doctor --lint` contract: existing valid configurations that deliberately leave the byte guard inactive would newly produce a warning and nonzero lint result. Current docs explicitly describe that configuration as a disabled guard, so a maintainer should decide whether default lint treats it as misconfiguration before merge.

Likely related people: ownership could not be established confidently from the available read-only review evidence; route the default-Doctor policy choice to the compaction/Doctor area owner (low confidence).

## What This Changes

The branch adds a Doctor health check and tests that warn when a positive `agents.defaults.compaction.maxActiveTranscriptBytes` limit is configured without enabling `truncateAfterCompaction`.

## System Context

The compaction subsystem checks an active session transcript before a new turn and may compact it when the configured byte limit is reached. Doctor reads the same configuration to report conditions that operators should correct before the runtime silently ignores the limit.

## Best Possible Solution

Choose and document one Doctor compatibility contract: either keep the default lint warning and explicitly classify this combination as operator misconfiguration, or make the check opt-in so intentionally disabled guards keep a clean default lint result.
