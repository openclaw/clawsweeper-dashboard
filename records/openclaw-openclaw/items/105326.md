## Summary

Current main still permits the reported race, and no canonical fix exists. New Session retains the previous repository’s base branch while discovery for the newly selected repository is pending, so immediate submission can fail with an invalid Git ref. The protected `maintainer` label requires explicit maintainer handling. Likely related person: `steipete` is the high-confidence recent owner of this Control UI surface.

## What This Changes

Changing repositories in New Session can retain and submit the previous repository’s resolved worktree base ref before branch discovery completes.

## Best Possible Solution

Centralize repository-identity invalidation so every agent, host, or folder transition immediately clears branch results and `baseRef`, then permit submission with the optional ref omitted until only the matching discovery request resolves; add a delayed-Gateway E2E regression for an A-to-B repository switch followed by immediate submission.
