## Summary

This stays open: the report matches a previously identified cross-host exec invariant, while the node contract still supports node-owned working directories. The remaining choice is how to preserve explicit remote workdirs without allowing an inherited Gateway workspace path to reach the paired node. Likely related people: `steipete` (high confidence, node-exec feature history).

## What This Changes

The issue requests that `exec host=node` avoid sending a Gateway-local working directory to a paired node, where it can make the shell spawn fail before the command runs.

## System Context

The exec tool routes an agent command through the Gateway to a paired node's `system.run` command. The Gateway supplies command and working-directory context, and the node host resolves that context before spawning the local shell.

## Best Possible Solution

Keep explicit node-owned working directories, including documented `node://` locators, but prevent an inherited Gateway workspace default from being forwarded to `host=node`; have the node validate its own working directory and return a node-specific missing-directory error.
