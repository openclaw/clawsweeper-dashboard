## What This Changes

Fix repeated SQLite `database is locked` warnings during concurrent session and cron starts, including missed auth-profile success bookkeeping writes.

## System Context

OpenClaw starts agent sessions and cron runs that may migrate legacy per-agent Memory Core state and record provider-profile outcomes. Both paths write SQLite-backed state, so concurrent processes can turn a startup migration or post-run bookkeeping write into repeated lock contention and noisy warnings.

## Architecture Diagram

  F --> G[Warnings or persisted state]
  G --> H[Logs and future runs]

## Best Possible Solution

Add a narrow, authoritative completion/defer mechanism for the Memory Core legacy import, then give auth-profile bookkeeping bounded contention handling with focused real-lock tests; evaluate any shared SQLite policy only after proving both paths use the same safe connection contract.
