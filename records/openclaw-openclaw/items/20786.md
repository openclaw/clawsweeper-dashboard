## Summary

Keep this open as the canonical Telegram Business tracker: current main and v2026.6.11 still do not process Business update payloads or maintain Business reply state, and the same-repo implementation attempt was closed while the fork mirror is open but conflicting.

## What This Changes

Request support for Telegram Business `business_message` and `business_connection` updates so Business-connected personal chats can be received and replied to through the Telegram plugin.

## Best Possible Solution

Ship a refreshed Telegram plugin implementation that handles Business connect/message/edit/delete updates, routes `business_message` through the existing DM authorization and inbound pipeline, updates dedupe/sequential keys, lifecycle-owns account-scoped `business_connection_id` reply state, and adds focused tests plus Telegram docs.

## Reproduction Assessment

Yes, at source level: current main has no Business update handlers and no Business update dedupe/sequential keys, while the official Telegram API and grammY document those payloads. I did not run a live Telegram Business account probe in this read-only review.

## Solution Assessment

No, the minimal `allowed_updates` proposal is not the best fix because current grammY defaults already include the update names. The maintainable solution must wire handlers, access control, account-scoped reply state, tests, and docs.
