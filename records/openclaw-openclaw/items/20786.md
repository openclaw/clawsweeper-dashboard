## Summary

Keep this issue open. Current main and the latest release still allow Telegram Business update names only through grammY defaults, but the Telegram plugin does not register `business_message` or `business_connection` handlers, does not key Business payloads for dedupe/sequencing, and the same-repo implementation attempt was closed unmerged for Telegram-owner direction.

## What This Changes

Request Telegram Business support so connected personal-chat updates are handled, routed through the Telegram inbound pipeline, and replied to with the correct `business_connection_id`.

## Best Possible Solution

Ship a maintainer-approved Telegram plugin implementation that handles Business connect/disconnect state per account, routes `business_message` through the existing DM authorization and inbound pipeline, updates dedupe and sequential keys, applies `business_connection_id` only to supported outbound methods with the correct mapping, and documents setup and access-control behavior.

## Reproduction Assessment

Yes at source level: current main lacks `business_message` and `business_connection` handlers while the Telegram inbound pipeline only handles normal messages and channel posts. I did not run a live Telegram Business account probe in this read-only review.

## Solution Assessment

Unclear until maintainer direction is confirmed. The issue’s desired outcome is sound, but the prior PR showed that a safe implementation must account for per-account Business connection state, disconnects, dedupe/sequencing, and personal-DM access controls.
