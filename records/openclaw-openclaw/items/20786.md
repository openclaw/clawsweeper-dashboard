## Summary

Keep this issue open. Current main and the latest release still only have partial Telegram Business awareness: there is no runtime `business_message` or `business_connection` handler, no Business payload dedupe/sequencing, and no general outbound `business_connection_id` mapping; the same-repo implementation attempt at https://github.com/openclaw/openclaw/pull/53629 was closed unmerged, while the fork mirror is still conflicting.

## What This Changes

The issue requests Telegram Business support so OpenClaw Telegram bots can receive `business_connection` and `business_message` updates and reply through the Business connection.

## Best Possible Solution

Keep this as the canonical Telegram Business tracker until a maintainer-approved Telegram plugin change lands with Business connect/disconnect handling, Business message routing, dedupe/sequential keys, account-scoped outbound mapping, focused tests, and public Telegram docs.

## Reproduction Assessment

Yes, at source level: current main's Telegram handler list omits `business_message` and `business_connection`, while allowed-update coverage can admit those update types. I did not run a live Telegram Business account repro in this read-only review.

## Solution Assessment

No, the originally proposed one-function `allowed_updates` change is not enough. The maintainable fix must wire Business update handlers, state/mapping, dedupe/sequencing, outbound API parameters, tests, and docs inside the Telegram plugin.
