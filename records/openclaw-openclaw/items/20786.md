## Summary

Keep open: current main and the latest release still allow Telegram Business update names through grammY defaults but do not register `business_message` or `business_connection` runtime handlers, do not key Business payloads for dedupe/sequencing, and have no end-to-end Business reply support.

## What This Changes

Request Telegram Business support so OpenClaw bots can receive and respond to `business_message` and `business_connection` updates from Business-connected personal chats.

## Best Possible Solution

Keep this as the canonical tracker until a refreshed Telegram plugin implementation handles Business connect/disconnect state per account, routes `business_message` through the existing inbound pipeline, updates dedupe and sequencing, applies outbound `business_connection_id` safely, and adds focused tests, docs, and live Telegram proof.

## Reproduction Assessment

Yes, at source level: current main has no Business message or connection handler registration, and the update key and sequential-key code omit Business payloads. I did not run a live Telegram Business account, so this is source-reproducible rather than live-reproduced.

## Solution Assessment

No, an allowed-updates-only change is too narrow. The maintainable solution needs runtime handlers, account-scoped connection state, safe outbound `business_connection_id` handling, dedupe/sequencing updates, tests, docs, and live Telegram proof.
