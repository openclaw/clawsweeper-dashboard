## Summary

Keep this issue open as the canonical Telegram Business support tracker. Current main still has no runtime handling for `business_message` or `business_connection`, and the same-repository implementation PR at https://github.com/openclaw/openclaw/pull/53629 was closed while the fork mirror is still open but conflicting.

## What This Changes

Request to support Telegram Business-connected personal chats by processing Business connection/message updates and enabling replies with the correct Business connection context.

## Best Possible Solution

Keep this issue as the canonical tracker until a refreshed Telegram plugin implementation lands with Business handlers, account-scoped durable connection state, outbound reply support, dedupe/sequencing, tests, and docs.

## Reproduction Assessment

Yes, at source level. Current main allows/defaults the Business update names but has no Business handlers or Business update keys, so a delivered Business update has no processing path; no live Telegram probe was run.

## Solution Assessment

No, the narrow allowed-updates-only proposal is not the best fix. The maintainable solution needs Telegram runtime handlers plus account-scoped Business connection state, outbound reply mapping, dedupe/sequencing, access-control review, tests, and docs.
