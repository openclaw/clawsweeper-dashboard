## Summary

Keep open. Current main and the latest release still only allow Telegram Business update names; they do not register Business update handlers, route Business messages, or maintain Business connection IDs for replies, and the same-repo implementation PR was closed unmerged with safety findings.

## What This Changes

Request Telegram Business support in the Telegram plugin so `business_connection` and `business_message` updates are processed and Business replies carry the correct `business_connection_id`.

## Best Possible Solution

Keep this as the canonical tracker and ship an owner-reviewed Telegram plugin implementation with Business connect/disconnect handling, Business message routing, per-account durable connection mapping, outbound reply support, focused tests, docs, and live Telegram proof.

## Reproduction Assessment

Yes at source level: current main subscribes to grammY default Business update types, but the Telegram runtime has no `business_message` or `business_connection` handler and no Business payload keys. I did not run a live Telegram Business bot in this read-only review.

## Solution Assessment

No completed solution exists yet. The requested direction is valid, but the prior implementation candidate was closed with concrete correctness and account-isolation issues, so the best fix is a refreshed owner-reviewed Telegram plugin change rather than closing this tracker.
