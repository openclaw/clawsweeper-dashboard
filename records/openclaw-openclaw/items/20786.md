## Summary

Keep this open as the canonical tracker. Current main and v2026.6.11 still only allow Telegram Business update delivery through grammY defaults; they do not register Business message/connection handlers, model Business payloads in update keys or sequencing, or define the outbound business_connection_id authority model.

## What This Changes

The issue requests Telegram Business Bot support so OpenClaw can receive and reply to Telegram `business_message` updates and handle `business_connection` state.

## Best Possible Solution

Ship a maintainer-approved Telegram plugin implementation that handles Business connect/disconnect state per account, routes `business_message` through existing DM authorization and inbound processing, updates dedupe/sequential keys, applies `business_connection_id` only with correct authority, and documents setup with live Telegram proof.
