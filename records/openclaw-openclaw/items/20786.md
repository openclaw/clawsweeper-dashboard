## Summary

Keep this issue open: current main and the latest release still allow Telegram Business update names only through grammY defaults, but they do not register Business update handlers, route Business messages, or persist/apply `business_connection_id` for outbound replies. The same remaining work is tracked here, while the same-repo implementation PR was closed unmerged and the remaining fork PR is open but conflicting and still needs Telegram-owner review.

## What This Changes

The issue requests Telegram Business Bot support so OpenClaw can receive `business_message` and `business_connection` updates and respond with the required Business connection context.

## Best Possible Solution

Ship a refreshed Telegram plugin implementation that handles Business connect/disconnect state per Telegram account, routes `business_message` through the existing DM authorization and inbound pipeline, updates dedupe/sequential keys, injects `business_connection_id` only for supported outbound methods, and documents Telegram Business setup and access-control behavior.

## Reproduction Assessment

Yes for source reproduction: current main accepts the Business update type names through grammY defaults but has no Business runtime handlers, no Business update keys, and no outbound Business connection mapping. I did not run a live Telegram Business account in this read-only review, so this is source-reproducible rather than live reproduced.

## Solution Assessment

Unclear until maintainer review completes: the right boundary is the Telegram plugin, but the best implementation must cover handler wiring, dedupe/sequencing, durable account-scoped Business connection state, outbound reply injection, docs, and real Telegram proof rather than only adding update names.
