## Summary

Keep open: current main and the latest release still do not register Telegram Business runtime handlers or key Business updates, so Business messages remain unprocessed despite the update names being present in grammY defaults.

## What This Changes

The issue requests Telegram Business support by handling `business_connection` and `business_message` updates in the Telegram plugin.

## Best Possible Solution

Keep this as the canonical tracker until a refreshed Telegram plugin implementation handles Business connection state per account, routes Business messages through the inbound pipeline, updates dedupe/sequencing, applies outbound `business_connection_id` safely, and adds tests, docs, and live Telegram proof.

## Reproduction Assessment

Yes, at source level: current main includes Business update names through grammY defaults but has no Business message or connection handlers, and Business payloads are absent from update keying.

## Solution Assessment

No, an allowed-updates-only change is too narrow. The maintainable solution belongs in the Telegram plugin runtime with account-scoped connection state, inbound routing, dedupe/sequencing, outbound metadata handling, tests, docs, and live proof.
