## Summary

Keep open: current main and v2026.6.11 still allow Telegram Business update names through grammY defaults, but the Telegram plugin does not register Business update handlers or key Business updates for dedupe/sequencing. The remaining work is still necessary and needs Telegram-owner review because it affects personal-DM access and outbound business_connection_id authority.

## What This Changes

Request to add Telegram Business support so OpenClaw can process business_connection and business_message updates and reply in Business-connected personal chats.

## Best Possible Solution

Keep this issue as the canonical tracker and land a refreshed Telegram plugin implementation that handles Business connect/disconnect state per account, routes business_message through the existing inbound pipeline, updates dedupe and sequencing, applies business_connection_id only with correct authority, and includes focused tests, docs, and live Telegram proof.

## Reproduction Assessment

Yes from source: current main registers normal Telegram message/channel handlers but not Business update handlers, and Business payloads are absent from dedupe and sequential key selection. I did not run a live Telegram Business account repro during this read-only review.

## Solution Assessment

No current-main solution exists yet. The best fix is not handler-only; it should be a Telegram-plugin change with per-account Business connection state, outbound authority handling, tests, docs, and live Telegram proof.
