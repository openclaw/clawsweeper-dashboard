## Summary

Keep this open as the canonical Telegram Business tracker: current main and the latest release still expose the update names only through defaults/partial handling, but do not route Business message or connection updates through the Telegram runtime path, and the linked implementation attempts are unmerged or conflicting.

## What This Changes

Add Telegram Business Bot support so OpenClaw can process business_connection/business_message updates and reply correctly in Business-connected personal chats.

## Best Possible Solution

Ship a refreshed Telegram plugin implementation that handles Business connect/message/edit/delete updates, routes business_message through the existing DM authorization and inbound pipeline, updates dedupe/sequential keys, scopes Business reply state per Telegram account, and adds focused tests plus Telegram docs.

## Reproduction Assessment

Yes, at source level: current main has Business update names in the allowed/default set, but no Business update handlers or Business update dedupe/sequential keys. I did not run a live Telegram Business account probe in this read-only review.

## Solution Assessment

No, the issue body's minimal allowed_updates-only fix is too narrow because current main already has those update names through defaults; the durable fix needs handlers, authorization, reply-state handling, tests, and docs.
