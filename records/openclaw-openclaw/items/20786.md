## Summary

Keep open: current main and v2026.6.11 still allow Telegram Business update names only as delivery input, but the Telegram runtime does not process `business_message` or `business_connection`, and the remaining open fork PR is conflicting with the same head as a closed same-repo implementation that had account-isolation and correctness concerns.

## What This Changes

Requested Telegram Business Bot support so OpenClaw can receive and respond to `business_message` and `business_connection` updates from Telegram Business-connected personal chats.

## Best Possible Solution

Keep this as the canonical tracker until a refreshed Telegram plugin implementation handles Business connect/disconnect state per account, routes `business_message` through the inbound pipeline, updates dedupe/sequencing, applies outbound `business_connection_id` safely, and adds focused tests, docs, and live Telegram proof.

## Reproduction Assessment

Yes, at source level: current main permits the Business update names through grammY defaults but has no Business message or connection handlers and no Business payload keying path, so delivered Business updates are not routed into OpenClaw. I did not run a live Telegram Business account repro in this read-only review.

## Solution Assessment

No, the allowed-updates-only shape is too narrow. The maintainable fix needs runtime handlers, account-scoped Business connection state, safe outbound `business_connection_id` handling, dedupe/sequencing updates, tests, docs, and live Telegram proof.
