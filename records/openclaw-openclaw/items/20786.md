## Summary

Keep this open as the canonical Telegram Business support tracker: current main and the latest release still accept the update names only through grammY defaults, but do not process Business message/connection updates or support durable Business reply routing.

## What This Changes

The issue requests Telegram Business Bot support so OpenClaw can receive, route, and reply to `business_connection` and `business_message` updates from Business-connected personal chats.

## Best Possible Solution

Ship a refreshed Telegram plugin implementation that registers Business connect/message/edit/delete handlers, routes `business_message` through the existing DM authorization and inbound pipeline, updates dedupe/sequential keys, persists or otherwise lifecycle-owns per-account `business_connection_id` reply state, and adds focused tests plus Telegram docs.

## Reproduction Assessment

Yes, at source level: current main has no Business update handlers and no Business update dedupe/sequential keys, while official Telegram and grammY types define those update payloads. I did not run a live Telegram Business account probe in this read-only review.

## Solution Assessment

No, the issue body's minimal `allowed_updates` change is too narrow because current grammY defaults already include the update names; the maintainable fix must wire handlers, access control, reply-state handling, tests, and docs.
