## Summary

Keep open. Current main and the latest release still allow Telegram Business update names through grammY defaults, but the Telegram plugin does not route `business_message` or `business_connection` updates, does not key them for dedupe/sequencing, and has no durable `business_connection_id` reply mapping; the open fork PR remains an implementation candidate rather than merged target-repo code.

## What This Changes

Add Telegram Business support so the Telegram plugin can receive, route, and reply to `business_connection` and `business_message` updates from Business-connected personal chats.

## Best Possible Solution

Keep this as the canonical tracker and land a focused Telegram plugin change that handles Business updates, stores connection mappings durably in the approved state path, applies `business_connection_id` to supported outbound replies, and adds targeted tests, docs, and live Telegram proof.

## Reproduction Assessment

Yes at source level, but not by a live Telegram run in this review. Current main lacks Business update handlers and Business fields in dedupe/sequential key code, so delivered `business_message` updates have no processing path.

## Solution Assessment

Partly. Wiring the Telegram plugin is the right owner boundary, but an `allowed_updates`-only change or compiled-bundle patch is not enough; the best fix also needs durable connection mapping, outbound reply support, tests, docs, and maintainer-approved defaults.
