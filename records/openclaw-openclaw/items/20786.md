## Summary

Keep this open as the canonical Telegram Business support tracker: current main and the latest release still accept Business update names through grammY defaults, but OpenClaw does not process Business message/connection updates or provide durable Business reply routing.

## What This Changes

Requested Telegram Business Bot support so the Telegram plugin can receive and reply to `business_message` and `business_connection` updates.

## Best Possible Solution

Ship a refreshed Telegram plugin implementation that registers Business connect/message/edit/delete handling, routes `business_message` through the existing DM authorization and inbound pipeline, updates dedupe/sequential keys, lifecycle-owns per-account `business_connection_id` reply state, and adds focused tests, Telegram docs, security review, and live Telegram proof.

## Reproduction Assessment

Yes, at source level: current main has no Business update handlers and no Business update dedupe/sequential keys, while official Telegram and grammY docs define those update payloads and handler surface. I did not run a live Telegram Business account probe in this read-only review.

## Solution Assessment

No, the issue body's minimal `allowed_updates` change is too narrow because current grammY defaults already include the update names; the maintainable fix must wire handlers, access control, account-scoped reply-state handling, tests, docs, and live proof.
