## Summary

Keep this open as the canonical Telegram Business support tracker. Current main and the latest release still only have partial delivery coverage: Business update names are present through grammY defaults, but OpenClaw does not register Business message/connection handlers, does not model Business updates in dedupe or sequencing, and the same-repo implementation PR was closed unmerged after security and routing blockers.

## What This Changes

Request to support Telegram Business-connected personal chats by handling business_connection, business_message, edited_business_message, and deleted_business_messages updates in the Telegram plugin.

## Best Possible Solution

Ship a maintainer-approved Telegram plugin implementation that handles Business connect/disconnect state per account, routes business_message through existing DM authorization and inbound processing, updates dedupe/sequential keys, applies business_connection_id only with the correct authority, and documents setup plus live Telegram proof.

## Reproduction Assessment

Yes, at source level: current main includes Business update names through grammY defaults, but there are no Business message or connection handlers and no Business-aware dedupe/sequential key logic. I did not run a live Telegram Business account reproduction.

## Solution Assessment

No, the minimal allowed_updates-only proposal is not the best complete fix. The maintainable solution must wire Business updates through the Telegram plugin's authorization, dedupe, sequencing, reply, outbound authority, tests, docs, and live-proof surfaces.
