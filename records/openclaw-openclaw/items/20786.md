## Summary

Keep this open as the canonical Telegram Business support tracker. Current main and v2026.6.11 still have only partial delivery coverage: Business update names are in grammY defaults, but OpenClaw does not register Business message/connection handlers or Business-aware dedupe/sequencing, and the prior implementation PR was closed unmerged after security and routing blockers.

## What This Changes

Request Telegram plugin support for Business-connected personal chats via `business_connection` and `business_message` update handling plus reply routing.

## Best Possible Solution

Ship a refreshed Telegram plugin implementation that registers Business connect/message/edit/delete handling, routes `business_message` through the existing DM authorization pipeline, updates dedupe/sequential keys, lifecycle-owns account-scoped `business_connection_id` reply state, and adds focused tests, docs, and live Telegram proof.

## Reproduction Assessment

Yes, at source level: current main lacks Business update handlers and Business-aware update keys while the locked Telegram/grammY surface defines those payloads. I did not run a live Telegram Business account probe in this read-only review.

## Solution Assessment

No, the issue body's minimal `allowed_updates` change is too narrow because current defaults already include the Business update names. The maintainable fix must cover handlers, authorization, reply-state lifecycle, dedupe/sequencing, tests, docs, and live proof.
