## Summary

Keep this open as the canonical Telegram Business support tracker: current main and v2026.6.11 still do not route Business message/connection updates through the Telegram plugin, and the same-repo implementation PR was closed unmerged after security and correctness findings.

## What This Changes

The issue requests Telegram Business Bot support by handling business_connection and business_message updates in the Telegram plugin.

## Best Possible Solution

Ship a refreshed Telegram plugin implementation that handles Business connect, disconnect, message, edit, and delete updates; routes business_message through the existing DM authorization and inbound pipeline; updates dedupe and sequential keys; lifecycle-owns per-account Business reply state; and adds tests, docs, and real Telegram proof.

## Reproduction Assessment

Yes, at source level: current main has no Business update handlers and no Business update dedupe/sequential keys, while Telegram's API defines those update payloads. I did not run a live Telegram Business account probe in this read-only review.

## Solution Assessment

No, the issue body's minimal allowed_updates change is not the best fix because current grammY defaults already include the update names. The maintainable fix needs handler wiring, access-control behavior, per-account reply-state handling, dedupe/sequential coverage, tests, docs, and live proof.
