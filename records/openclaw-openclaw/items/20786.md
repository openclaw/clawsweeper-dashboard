## Summary

Keep open: current main and the latest checked release still do not route Telegram Business updates into the Telegram runtime, and the same-repo implementation attempt is closed unmerged with correctness and ownership blockers.

## What This Changes

Request support for Telegram Business `business_connection` and `business_message` updates so OpenClaw can process and reply to Business-connected personal chats.

## Best Possible Solution

Ship a refreshed Telegram plugin implementation that handles Business connect/disconnect state per account, routes `business_message` through the existing DM inbound pipeline, updates dedupe/sequencing, applies outbound `business_connection_id` safely, and adds focused tests, docs, and live proof.

## Reproduction Assessment

Yes, at source level. Current main receives the Business update names through grammY defaults, but it registers no `business_message` or `business_connection` handler and does not route those payloads through update keys, sequencing, or the inbound pipeline.

## Solution Assessment

No, the original allowed-updates-only proposal is too narrow. The maintainable fix needs runtime handlers, account-scoped connection state, outbound Business ID handling, dedupe/sequencing updates, docs, and live Telegram proof.
