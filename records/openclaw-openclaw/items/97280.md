## Summary

This PR remains necessary because current main still rejects OAuth for the OpenAI audio-transcription API, while the linked regression remains open. The patch is technically coherent and preserves the API-key fallback/custom-endpoint boundary, but accepting OAuth-backed native batch STT is an explicit provider-auth product contract that needs human approval before merge.

## What This Changes

The branch permits selected OpenAI OAuth credentials for native OpenAI batch audio transcription, preserves environment API-key precedence, restricts OAuth to trusted OpenAI endpoints, and scopes fast auth checks to the active agent store.

## Best Possible Solution

Accept native OpenAI `/v1/audio/transcriptions` OAuth support only as an explicit documented contract, retain API-key-only behavior for custom/OpenAI-compatible endpoints and default environment-key precedence, then land with a current-head redacted CLI proof.
