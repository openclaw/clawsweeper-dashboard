## Summary

Keep open: current main and v2026.6.11 still choose Copilot profile auth from raw stored-profile order in the active plugin/provider-auth paths, and the linked repair remains an open conflicting fork PR.

## What This Changes

The issue reports that GitHub Copilot implicit auth profile selection ignores `auth.order` and uses the first stored profile entry instead.

## Best Possible Solution

Make the active Copilot plugin token discovery and generic provider-auth resolution use `resolveAuthProfileOrder()` with focused regression coverage for config order, stored order, and unresolved tokenRef fallback.
