## Summary

Keep open: current main and v2026.6.11 still use raw GitHub Copilot profile order in the active discovery/provider-auth paths, and the only open linked candidate is still conflicting rather than merged.

## What This Changes

The issue reports that GitHub Copilot implicit provider selection ignores `auth.order` and uses the first stored auth profile instead.

## Best Possible Solution

Refresh, adopt, or replace the linked candidate so Copilot plugin discovery and generic provider-auth resolution both use `resolveAuthProfileOrder()` with regression coverage for configured order and unresolved tokenRef fallback.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, source-level: current main selects `profileIds[0]` in the Copilot helper and the generic provider-auth resolver iterates raw profile order, while a focused test still asserts first-profile behavior. I did not run a live two-account Copilot setup.

## Solution Assessment

Yes. The narrow maintainable fix is to reuse `resolveAuthProfileOrder()` in the active Copilot discovery/provider-auth selection paths, with regression tests for config order and fallback behavior.
