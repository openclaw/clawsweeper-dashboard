## Summary

Keep open: current main and the latest release still select GitHub Copilot profiles from raw stored order instead of `auth.order`, and this issue is already paired with an open but conflicting fork PR that claims to fix it.

## What This Changes

Honor `auth.order` when selecting GitHub Copilot auth profiles instead of always using the first stored profile.

## Best Possible Solution

Land a narrow fix that makes Copilot plugin discovery and provider-auth resolution use `resolveAuthProfileOrder()`, preserving env-token precedence and explicit provider config behavior with regression coverage.

## Solution Assessment

Yes as a fix direction: reusing the existing auth-order resolver in the Copilot and provider-auth paths is the narrow maintainable solution. The linked fork PR still needs maintainer review because it is open and conflicting.
