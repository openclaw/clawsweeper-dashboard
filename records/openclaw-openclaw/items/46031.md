## Summary

Keep open: current main and the latest release still bypass `auth.order` in GitHub Copilot implicit discovery/provider-auth selection, and the only linked fix candidate is an open conflicting fork PR.

## What This Changes

The issue reports that GitHub Copilot auth profile selection ignores `auth.order` and chooses the first stored `auth.profiles` entry.

## Best Possible Solution

Refresh, adopt, or replace the open candidate so Copilot plugin discovery and generic provider-auth resolution both use `resolveAuthProfileOrder()` with regression coverage for configured order and unresolved tokenRef fallback.

Yes, source-level: current main's Copilot helper selects `profileIds[0]`, and the generic provider-auth resolver iterates raw profile order while a focused test still asserts first-profile behavior. I did not run a live two-account Copilot setup.

## Solution Assessment

Yes. The narrow maintainable fix is to reuse `resolveAuthProfileOrder()` in the active Copilot discovery/provider-auth selection paths; stale-order merge policy belongs to separate follow-up work.
