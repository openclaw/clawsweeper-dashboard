## Summary

Keep open: current main still selects GitHub Copilot auth profiles from raw stored-profile order in the active Copilot discovery and provider-auth paths, and the only closing fix candidate is an open conflicting fork PR rather than merged code.

## What This Changes

The issue asks GitHub Copilot auth/profile selection to honor `auth.order` instead of choosing the first stored profile.

## Best Possible Solution

Land or replace a focused fix that routes Copilot discovery and provider-auth selection through `resolveAuthProfileOrder()` while preserving env-token precedence and explicit provider config behavior.

## Maintainer Decision

Required: false

Yes, source-level: current main selects `profileIds[0]` in the Copilot helper and iterates raw `Object.entries(store.profiles)` order in provider-auth resolution. I did not run a live multi-account Copilot repro.

## Solution Assessment

Yes in direction: the narrow maintainable fix is to reuse `resolveAuthProfileOrder()` in the active Copilot discovery/provider-auth selection paths. A new automated fix lane is not the best next step while a closing fork PR remains open and conflicting.
