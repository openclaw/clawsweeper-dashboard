- `impact:auth-provider`: The issue affects provider auth-profile selection and can route Copilot discovery through the wrong stored credential.

## Summary

Keep open: current main and v2026.6.11 still select the first stored GitHub Copilot token profile during catalog discovery, so configured `auth.order` remains ignored in this path; the open linked fork PR should be refreshed, adopted, replaced, or closed before queueing a new fix lane.

## What This Changes

The issue reports that GitHub Copilot implicit provider discovery ignores `auth.order` and selects the first stored auth profile.

## Best Possible Solution

Update the GitHub Copilot provider-owned auth path to choose the first resolvable token profile from `resolveAuthProfileOrder`, preserving env precedence, disabled discovery, explicit auth-order exclusions, and focused regression coverage.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Source inspection on current main shows GitHub Copilot catalog discovery calls `resolveFirstGithubToken`, which lists profiles and selects `profileIds[0]` instead of applying `resolveAuthProfileOrder`.

## Solution Assessment

No fix is on main yet. The maintainable fix should live in the GitHub Copilot provider-owned auth helper or SDK auth seam, not as a broad post-discovery fallback.
