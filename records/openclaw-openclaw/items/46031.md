## Summary

Keep open: current `main` and the latest release still contain first-profile GitHub Copilot auth selection, while the same-repository repair attempts are closed unmerged and the open fork repair PR is still conflicting.

## What This Changes

The issue reports that `auth.order` is ignored for GitHub Copilot profile selection, causing the first stored `auth.profiles` entry to win.

## Best Possible Solution

Refresh, adopt, or replace the linked repair PR so the current GitHub Copilot plugin discovery and generic provider-auth paths use `resolveAuthProfileOrder()` for profile selection, with focused regression coverage for configured order, stored order, and unresolved `tokenRef` fallback.

## Reproduction Assessment

Yes, at source level: current `extensions/github-copilot/auth.ts` selects `profileIds[0]`, and `createProviderAuthResolver()` iterates raw matching profiles instead of `resolveAuthProfileOrder()`. I did not run a live two-account Copilot flow in this read-only review.

## Solution Assessment

Yes, the requested direction is the right fix, but it must target the current plugin-based discovery and provider-auth resolver rather than the obsolete pre-refactor function named in the original report.
