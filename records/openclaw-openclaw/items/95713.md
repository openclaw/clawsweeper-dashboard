## Summary

Keep open: the PR moves timeout/overflow compaction contexts toward the live `/model` selection, but the successful post-compaction retry still continues through the run loop with the old run-start `provider`/`modelId`, so the actual retry can remain on the stale model/provider.

## What This Changes

## Best Possible Solution

After successful timeout or overflow compaction with a pending live selection, hand the next retry to the same live-switch owner path or re-resolve the run-local provider/model/auth state before dispatch, with full run-loop regression coverage.
