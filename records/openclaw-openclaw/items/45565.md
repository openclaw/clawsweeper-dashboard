## Summary

Keep open: current main has partial suppression controls for tool-error warnings and a cron-specific failure destination, but it still does not provide the requested dedicated destination/category router for gateway lifecycle or internal warning messages.

## What This Changes

The issue requests a public config surface to route gateway lifecycle and internal warning messages to a dedicated channel, with optional suppression or category-specific routing.

## Best Possible Solution

Define one canonical, default-compatible internal-warning routing policy, then align schema/help/docs, shared payload/progress delivery, cron-specific notifications, and representative channel tests around it.
