## Summary

Keep open: current main has an opt-in `messages.suppressToolErrors` boolean and a newer progress-delivery guard, but it still has no dedicated destination or category router for gateway lifecycle/internal warning messages, so the remaining work is a product/config decision rather than conservative cleanup.

## What This Changes

Request adds configuration to route gateway lifecycle and internal tool-warning notifications away from active conversation channels to a dedicated channel or suppression path.

## Best Possible Solution

Define one default-compatible internal-warning delivery policy that reuses existing route/target parsing, keeps current delivery as the default, and adds documented catch-all or category routing only after maintainers choose the safety semantics.
