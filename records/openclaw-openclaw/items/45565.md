## Summary

Keep open: current main and v2026.6.11 have suppression and narrower channel-specific fixes, but still no general dedicated target/category router for gateway lifecycle or internal warning messages.

## What This Changes

The issue requests a public config option to route gateway lifecycle and internal warning notifications away from the active conversation channel into a dedicated channel or suppress them by category.

## Best Possible Solution

Define one default-compatible internal-warning routing policy, then align config schema/help/docs, shared warning/progress delivery, cron/session warning behavior, and representative channel tests around that policy.
