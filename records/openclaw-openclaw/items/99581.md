Full review comments:

- **[P2] Add --type-not before inferring ripgrep paths:** `src/infra/exec-control-command-guard.ts:194`
  - body: `rg --type-not rust timeout` from a protected cwd still searches the cwd, but this option set only includes `-T` and not the documented long form. The guard can therefore treat `rust` as the pattern and `timeout` as a narrowed path, allowing the broad protected-root search.
  - confidence: 0.94
- **[P2] Keep piped rg pattern filters on stdin:** `src/infra/exec-control-command-guard.ts:1216-1222`
  - body: When stdin is piped into `rg -e needle`, ripgrep filters stdin rather than walking the current directory. This branch disables the stdin fast-path whenever `-e` or `-f` is present, so a protected-cwd filter can be rejected as a broad filesystem search.
  - confidence: 0.9
- **[P2] Scope wrapper-payload cwd changes to child shells:** `src/infra/exec-control-command-guard.ts:315`
  - body: A `cd` inside `bash -c` or `sh -c` runs in that child shell and cannot change the cwd of later outer commands. Including `wrapper-payload` here lets `bash -lc 'cd /tmp'; rg token` from a protected cwd update the shared analyzer cwd to `/tmp`, so the later outer search is allowed incorrectly.
  - confidence: 0.9
- **[P2] Re-parse static find shell payloads:** `src/infra/exec-control-command-guard.ts:1066-1074`
  - body: `find -exec sh -c 'rg token ~/.codex/sessions' \;` can execute a nested shell search, but this branch only queues the extracted argv with `payloadFromArgv`. It never runs that payload back through the shell-wrapper parser, so the protected nested search can be missed.
  - confidence: 0.88
- **[P2] Do not apply assignments from unexecuted branches:** `src/infra/exec-control-command-guard.ts:1035-1037`
  - body: Assignment-only commands update the tracked environment before the same control-flow checks used for `cd`. An unexecuted branch can overwrite a variable from a protected session path to `/tmp`, causing the later `rg "$SESSION_ROOT"` check to allow the actual protected-root search.
  - confidence: 0.86
- **[P2] Expand variables beyond the first path segment:** `src/infra/exec-control-command-guard.ts:1311-1312`
  - body: Shell variables can appear anywhere in a path operand, but this helper only expands a leading `$VAR` or `${VAR}`. Paths such as `/home/$USER/.codex/sessions` can therefore be checked literally while the shell searches the expanded protected directory.
  - confidence: 0.87
- **[P2] Fail closed on command-substituted search paths:** `src/infra/exec-control-command-guard.ts:1464-1466`
  - body: Command substitution in a search operand is evaluated before `rg` receives paths. When a path like `$(printf %s "$HOME/.codex/sessions")` is resolved literally under the cwd, the guard can allow a command that the shell expands into a protected session search.
  - confidence: 0.82
- **[P2] Protect repo parents by relation, not folder name:** `src/infra/exec-control-command-guard.ts:1427-1432`
  - body: The tool text says repo parents are protected, but this classifier only recognizes a few parent folder names and shapes. A common checkout like `$HOME/src/openclaw` can still search `..`, resolving to `$HOME/src`, which is a repo parent but matches none of these cases.
  - confidence: 0.78
