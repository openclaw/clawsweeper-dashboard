## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P2] Use the sandbox container cwd for guard checks:** `src/agents/bash-tools.exec.ts:1769-1772`
  - body: For sandbox execs this checks the host-mapped `workdir`, but `runExecProcess()` executes inside `containerWorkdir`. A command like `rg timeout ..` from container `/workspace/openclaw` can search `/workspace` while the guard resolves `..` against the host temp path and allows it.
  - confidence: 0.91
- **[P2] Match protected state descendants:** `src/infra/exec-control-command-guard.ts:511-515`
  - body: Protected-root matching only accepts exact roots or their realpaths, so explicit recursive operands under state roots such as `~/.codex/sessions/2026` or `~/.openclaw/logs` are allowed even though they still search protected state subtrees.
  - confidence: 0.9
- **[P2] Honor shell control flow before applying cd:** `src/infra/exec-control-command-guard.ts:325-329`
  - body: The cwd tracker applies every parsed top-level `cd` in source order. In `if false; then cd /tmp; fi; rg timeout` from a protected cwd, the shell never changes directory, but the guard checks the later `rg` against `/tmp` and lets the broad protected search run.
  - confidence: 0.86
- **[P2] Add rg -E to value-taking options:** `src/infra/exec-control-command-guard.ts:144`
  - body: `rg -E utf-8 timeout` uses `-E` as the encoding option, but this set does not consume it. From a protected cwd the guard treats `utf-8` as the pattern and checks `timeout` as a path, missing the implicit recursive search of `.`.
  - confidence: 0.88
- **[P2] Skip find's -- before path operands:** `src/infra/exec-control-command-guard.ts:465-466`
  - body: GNU find accepts `--` before path operands, but this loop treats `--` as the expression boundary. `find -- ~/.codex/sessions -name '*.jsonl'` therefore falls back to checking `.` and allows the protected sessions directory search.
  - confidence: 0.87
- **[P2] Expand tilde against the shell home:** `src/infra/exec-control-command-guard.ts:477-478`
  - body: `expandHomePrefix()` can resolve `~` to OpenClaw's effective home, while the shell expands `~` using the OS login/HOME value. With `OPENCLAW_HOME` elsewhere, `rg timeout ~` can scan the real home while the guard checks the wrong directory.
  - confidence: 0.84
- **[P2] Preserve env --chdir cwd:** `src/infra/exec-control-command-guard.ts:319-321`
  - body: `env -C "$HOME" rg timeout` runs the search from `$HOME`, but the carrier unwrapping keeps the original workdir on the extracted `rg` payload. The guard checks the old cwd and allows the protected-home search.
  - confidence: 0.86
- **[P2] Resolve bash -c positional dispatch wrappers:** `src/infra/exec-control-command-guard.ts:319-321`
  - body: `bash -lc 'exec "$@"' sh rg timeout` runs the positional `rg timeout`, but the detector only inspects the inline `exec "$@"` payload. From a protected cwd that broad search is not checked.
  - confidence: 0.8
- **[P2] Do not block stdin-only rg filters:** `src/infra/exec-control-command-guard.ts:426-428`
  - body: Pathless `rg` reads stdin when it is in a pipeline, so `some_command | rg needle` does not walk the cwd. Returning `['.']` for every pathless `rg` makes the new fail-closed guard reject harmless stream filters from protected directories.
  - confidence: 0.85
