## Summary

This PR correctly closes the creator-policy bypass for new and edited trigger-script cron jobs and preserves the cap across SQLite reload, but it intentionally leaves previously stored trigger-script jobs without a cap until edited. That legacy-job security-versus-compatibility choice requires explicit cron/security ownership before merge.

## What This Changes

Propagates creator-derived tool allowlists to trigger-script system-event and command cron payloads across validation, updates, SQLite persistence, reload, and headless trigger evaluation.

## Best Possible Solution

Keep the end-to-end cap propagation, but make cap-less trigger-script jobs an explicit upgrade state: detect and surface them, then require operator approval or re-save before execution rather than silently granting the full tool surface.

## Solution Assessment
