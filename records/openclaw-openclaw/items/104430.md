## Summary

The updated PR correctly closes the new-job and restart-path privilege bypass, but it intentionally leaves pre-existing trigger-script jobs uncapped because historical creator policy was never stored; that upgrade security and compatibility choice needs explicit maintainer ownership before merge.

## What This Changes

The PR extends creator-derived cron tool caps to trigger-script system-event and command payloads across creation, updates, protocol validation, SQLite persistence, reload, and gateway trigger evaluation.

## Best Possible Solution

Land the single canonical cap path for new and edited jobs, and pair it with an operator-visible doctor or startup audit that identifies legacy trigger-script jobs lacking toolsAllow and requires an explicit keep-unrestricted, assign-cap, or disable decision.
