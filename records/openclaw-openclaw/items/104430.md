## Summary

Keep this PR open: it addresses a real cron authorization bypass, but the new creator cap is discarded by SQLite persistence for both newly supported payload kinds, restoring the unrestricted trigger tool surface after reload.

## What This Changes

The PR adds creator-derived `toolsAllow` caps to trigger-script system-event and command cron payloads and forwards them into headless trigger evaluation.

## Best Possible Solution

Extend the canonical SQLite payload codec to round-trip `toolsAllow` for system-event and command payloads, add store/restart regression tests, and demonstrate that a reloaded trigger cannot access an out-of-cap tool.
