## Label Justifications

- `merge-risk: 🚨 compatibility`: The patch changes validation, update merging, and persisted payload semantics for existing systemEvent and command cron jobs.

## Summary

Keep open for maintainer review: the patch appears correct and well-proven for new or edited jobs, but it intentionally leaves pre-existing uncapped trigger-script jobs unrestricted because their creator tool scope cannot be reconstructed; that upgrade/security policy needs explicit owner acceptance before merge.

## What This Changes

This PR propagates creator-derived tool caps across trigger-script system-event and command cron payloads, protocol validation, updates, SQLite persistence, reload, and headless trigger evaluation.

## Best Possible Solution

Land the cap after defining a legacy-job upgrade policy—prefer preserving existing jobs with a visible startup or doctor audit warning and an operator action to approve or restamp them—while retaining the branch’s canonical SQLite persistence and end-to-end propagation.
