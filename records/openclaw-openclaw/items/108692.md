## Summary

Keep this issue open. The report describes a plausible regression in the reader-managed scrolling behavior shipped in v2026.7.1: opening the keyboard appears to make the viewport look scrolled away even when the user remains at the live edge. No current-main fix or open replacement PR was found, and the related issue likely describes the same scroll-position misclassification.

## What This Changes

Make iOS chat continue following incoming and streaming messages while the keyboard is open unless the user intentionally scrolls away from the latest reply.

## Best Possible Solution

Preserve reader-managed scrolling, but treat keyboard/composer viewport changes as layout changes rather than intentional reader scrolling: continue following streamed content while the user is at the live edge, suppress Jump to latest there, and retain the existing pause behavior after an actual user scroll-away gesture.
