## Summary

Keep open: this is a fresh, specific regression against the newly shipped reader-managed native chat scrolling behavior, and there is no evidence that current main fixes the keyboard-resize case. The screenshot-backed report suggests iOS is treating the keyboard-driven viewport change as an intentional scroll away from the live edge.

## What This Changes

Fix iOS chat so a conversation that was already at the live edge continues following new assistant content while the keyboard is open.

## Best Possible Solution

Keep reader-managed scrolling, but preserve live-edge follow state across keyboard-driven viewport changes and show Jump to latest only after an actual user scroll away from the bottom.
