## Summary

Keep open. The report describes a concrete browser-availability failure: a single unresponsive shared tab can make `tabs`, `open`, and `snapshot` unavailable for the whole profile. The supplied diagnosis identifies two bounded surfaces—runtime-dependent title lookup during enumeration and extension-worker liveness—and no merged or current-main fix is established by the available evidence.

## What This Changes

Prevent one wedged shared Chrome tab or extension worker from blocking browser tab enumeration and dependent browser operations.

## System Context

The Browser tool obtains the set of approved Chrome pages, turns it into a tab list, and uses that list to service snapshot and action requests. Shared Chrome tabs reach OpenClaw through the extension relay, so both per-page metadata collection and relay health affect whether the agent can continue browser automation.

## Architecture Diagram

flowchart TD
  A[Agent browser command] --> B[Browser tool service]
  B --> C[Shared Chrome profile]
  C --> D[CDP target metadata]
  C --> E[Page Runtime title request]
  D --> F[Enumerated tab list]
  E --> G[Potential blocked enumeration]
  F --> H[Snapshot open and action requests]
  C --> I[Extension relay health]

## Best Possible Solution

Make enumeration rely on already-available target metadata rather than a page Runtime title call, then add a bounded capability-negotiated relay worker probe with focused regressions for one wedged tab and for old versus new extension behavior.
