## Summary

Keep this issue open: current main still has fixed memory-search and short-term-promotion path scopes, while the requested include/exclude controls would add a new compatibility-sensitive memory config surface that needs maintainer direction before implementation.

## What This Changes

The issue requests configurable include/exclude path scopes for memory recall eligibility and Memory Search indexing in markdown-first workspaces.

## Best Possible Solution

Define a narrow plugin-owned memory path-scope contract, if maintainers want it, and apply it consistently to builtin indexing, watch/sync diagnostics, QMD/default-memory parity, and short-term promotion without changing defaults for existing users.
