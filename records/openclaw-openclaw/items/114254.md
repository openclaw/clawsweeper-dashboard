## Summary

This PR has strong real-container proof for the same-PID restart case, but the previously reported foreign-PID safety blocker remains: it can reclaim a lock held by a live different process when the wall clock moves forward. Keep this PR open for that narrow correction before merge.

## What This Changes

The PR updates the SQLite usage-cost refresh lock so a restarted gateway can reclaim a stale lock from an earlier process incarnation that reused the same PID, with regression tests for the restart path.

## System Context

Usage-cost refreshes cache per-session rollups in the agent SQLite database. A persisted refresh lock prevents concurrent cache rebuilding; the lock check decides whether a caller may reclaim stale work or must leave an active refresh alone.

## Architecture Diagram

flowchart LR
  A[Gateway refresh request] --> B[Read SQLite refresh lock]
  B --> C[Check process and lock ownership]
  C -->|Active owner| D[Keep refresh locked]
  C -->|Stale owner| E[Reclaim lock]
  E --> F[Rebuild usage-cost rollup]
  F --> G[Write cached totals]

## Best Possible Solution

Keep nonce-based reclamation for the same-PID restart case, but preserve the existing live-PID answer for other PIDs until OpenClaw has a proven cross-platform process-incarnation signal; add focused coverage for the fail-closed foreign-PID case.
