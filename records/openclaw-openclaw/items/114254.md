## Summary

This PR remains necessary: current main is still represented as having PID-only refresh-lock ownership, while the branch adds a process-local nonce check that fixes the concrete same-PID restart case without reclaiming a lock held by a live foreign PID. The prior foreign-PID finding is resolved at the reviewed head; no new discrete correctness or security defect is evident in the final diff.

## What This Changes

The PR makes the usage-cost SQLite refresh lock distinguish a prior crashed gateway incarnation from the current gateway when a supervisor restarts it with the same PID.

## System Context

Usage-cost rollups are cached in each agent’s SQLite database and guarded by a refresh lock so only one refresh updates the rollup at a time. Gateway usage-cost requests and other consumers use the rollup; a stranded lock prevents refreshes and leaves them to recompute from session transcripts.

## Architecture Diagram

  C --> D{Live lock owner?}

  D -->|Known current owner or foreign live PID| F[Preserve exclusive refresh]
  E --> G[Updated cost totals]
  F --> H[Existing rollup remains available]

## Best Possible Solution

Merge the nonce-based same-PID repair after the current merge head completes its required checks, while preserving the fail-closed treatment of live foreign-PID locks unless a future portable process-incarnation contract is designed and proven.
