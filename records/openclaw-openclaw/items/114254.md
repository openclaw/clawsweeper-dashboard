## Summary

This PR addresses a real container restart failure and includes credible after-fix container evidence, but the current non-self PID branch can reclaim a lock held by a live gateway after a sufficiently large forward wall-clock adjustment. The earlier review finding remains unresolved, so this should stay open for a narrow repair before merge.

## What This Changes

The PR updates the usage-cost SQLite refresh lock so a restarted gateway can identify an orphaned same-PID lock by its process-local owner nonce and resume cost-cache refreshes.

## System Context

Usage-cost rollups are stored in each agent’s SQLite cache and guarded by a refresh lock so only one gateway process rebuilds the rollup at a time. Refresh callers read that lock before recomputing transcript totals, then write refreshed rollup rows once ownership is acquired.

## Architecture Diagram

flowchart LR
  A[Gateway refresh request] --> B[Read agent SQLite refresh lock]
  B --> C{Is lock owner alive?}
  C -->|Held| D[Reuse existing rollup]
  C -->|Stale| E[Acquire refresh lock]
  E --> F[Recompute usage-cost rollup]
  F --> G[Write SQLite rollup rows]
  G --> H[Release refresh lock]

## Best Possible Solution

Keep the nonce-based same-PID repair, but preserve the established live-PID answer for other PIDs unless OpenClaw can establish process incarnation safely on every supported platform without relying on a wall-clock-derived boot time.
