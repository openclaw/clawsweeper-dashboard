## What This Changes

Updates usage-cost refresh-lock liveness checks so a lock from an earlier process incarnation is not indefinitely honored merely because its PID has been reused.

## System Context

Usage-cost refreshes persist per-agent rollups and a refresh lock in the agent SQLite database. Gateway and refresh callers consult that lock before rebuilding cached cost totals, so a stale lock can prevent cache updates and force repeated transcript recomputation.

## Architecture Diagram

flowchart TD
  A[Gateway or refresh caller] --> B[Read agent usage-cost lock]
  B --> C[Validate PID and lock start time]
  C -->|Owner alive| D[Keep existing refresh lock]
  C -->|Owner proven stale| E[Reclaim lock]
  D --> F[Use current usage-cost cache]
  E --> G[Refresh rollup and cache]
  G --> F
