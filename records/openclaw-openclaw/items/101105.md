## Label Justifications

- `P1`: The PR targets a shipped macOS identity churn regression that can break pairing and native node continuity for real users.
- `merge-risk: 🚨 compatibility`: The new entitlement gate can switch existing unentitled macOS installs from App Group identity storage to legacy storage during upgrade.
- `merge-risk: 🚨 session-state`: If the storage switch abandons an existing identity, the same Mac can appear as a new node and leave old node state stale.
- `merge-risk: 🚨 auth-provider`: Device identity changes affect pairing tokens and approvals, so the fallback can disrupt existing device auth continuity.

## Summary

Keep open: this is a focused fix for a credible macOS device-identity churn bug, but it is not merge-ready because the new entitlement gate can abandon existing App Group identities on upgrade and the central signed-macOS behavior is not proven.

## What This Changes

The PR changes Swift macOS device identity storage to require an App Groups entitlement before using the App Group container and adds Swift/TypeScript guards and tests that preserve unrecognized identity files instead of overwriting them.

## Best Possible Solution

Keep the entitlement-aware fallback only with upgrade-safe identity preservation or an explicit maintainer-approved one-time re-pair, then prove a signed macOS app relaunch and gateway restart preserve the selected device ID.
