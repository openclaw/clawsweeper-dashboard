## What This Changes

The PR makes macOS device identity storage entitlement-aware, migrates readable App Group identities into legacy storage on fallback, and preserves unrecognized identity files in the Swift and TypeScript loaders.

## Best Possible Solution

Land the entitlement-aware fallback plus valid App Group-to-legacy identity migration after exact-head CI, keeping full signed app relaunch/gateway proof as release validation rather than a contributor blocker.

## Reproduction Assessment

Yes, we have a high-confidence source-backed reproduction path from the linked macOS reports: current main selects the App Group container before legacy storage and can mint a fresh identity when that store is unreadable. I did not independently run a signed macOS app in this read-only review.

## Solution Assessment

Yes, this is the best fix direction: keep App Group storage only when the app is actually entitled, fall back to legacy storage otherwise, and migrate a valid readable App Group identity before creating a new one. Provisioning App Groups is the heavier alternative and does not cover unentitled shipped builds already in the field.
