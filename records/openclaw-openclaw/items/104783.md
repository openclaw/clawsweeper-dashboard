## Summary

Keep open: current main can still reserve Groq’s full advertised 32,768-token output allowance on an ordinary agent request, so the related unreleased TPM-classification fix does not solve the reported provider rejection.

## What This Changes

Prevent ordinary Groq agent requests from reserving enough prompt and completion tokens to exceed the provider account’s TPM limit.

## Best Possible Solution

Separate a model’s maximum output capability from its default per-request reservation, using a conservative request budget or omitting the output field unless explicitly configured, while preserving explicit user overrides and provider-specific caps.
