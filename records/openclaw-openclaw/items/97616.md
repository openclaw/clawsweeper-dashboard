## Label Justifications

- `P1`: Independent recent reports describe cumulative process exhaustion that eventually breaks a long-running gateway and requires service restarts.
- `impact:crash-loop`: Zombie growth causes process and thread exhaustion, gateway instability, and restart-dependent recovery.
- `impact:message-loss`: The exhausted runtime stops processing Slack and Telegram traffic and can no longer spawn required helper work.

## Summary

Keep open: independent users report the failure through v2026.7.1, while current main only contains a narrow completed-relay cleanup; the broader multi-process zombie accumulation still lacks a proven fix, and the linked general reaper PR is not a safe landing path.

## What This Changes

Prevent completed hook, shell, Codex, and browser-helper child processes from accumulating as zombies until the Linux gateway exhausts process resources.

## Best Possible Solution

Keep the completed-relay cleanup already on main, capture current-main PID/PPID/STAT/argv and spawn-owner traces for each remaining process class, then repair the responsible wait or termination boundary and prove stable counts with a packaged Linux/Docker load soak.
