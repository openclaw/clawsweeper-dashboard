## Label Justifications

- `P1`: Production evidence shows a stalled `sessions_spawn` can block an interactive chat session for real users until recovery occurs.
- `impact:session-state`: The issue is about parent and child session state remaining stuck around subagent execution and recovery.
- `impact:message-loss`: Queued Telegram group messages can receive no acknowledgement or reply while the parent session is blocked behind the stalled spawn.

## Summary

Keep open: current main has explicit `runTimeoutSeconds` enforcement and a generic diagnostic active-abort path, but it still lacks the requested subagent-specific two-stage inactivity nudge-then-kill contract and user-visible recovery behavior.

## What This Changes

The issue requests a default-on subagent stall watchdog that nudges after inactivity, kills after continued inactivity, and notifies the parent/channel instead of leaving chat sessions blocked behind a stalled `sessions_spawn`.

## Best Possible Solution

Use one canonical session/subagent activity source, extend the existing timeout/recovery machinery without duplicating watchdogs, and make any automatic abort path produce deterministic parent and channel-visible terminal state.
