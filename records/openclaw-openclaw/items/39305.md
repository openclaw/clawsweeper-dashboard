## Label Justifications

- `P0`: The production report shows a chat conversation blocked for hours behind a stuck `sessions_spawn`, with recovery requiring gateway restart and manual session-file cleanup instead of an in-product path.
- `impact:session-state`: The issue is about subagent run/session state remaining running or processing after progress has stopped.
- `impact:message-loss`: Queued chat messages can sit behind a stuck spawn with no acknowledgement or visible failure to users.
- `impact:ux-release-blocker`: Affected chat users have no in-product recovery path, and the documented workaround requires operator-level logs, restart, and manual session state cleanup.

## Summary

Keep open: current main has hard `runTimeoutSeconds`, stale/lost-context cleanup, manual/admin kill helpers, and ACP no-output notices, but it still lacks the requested automatic last-tool-activity nudge followed by configured kill and parent/channel-visible recovery for ordinary subagent stalls.

## What This Changes

The issue requests two-stage subagent stall recovery based on inactivity since the last tool call, with a nudge before an automatic kill and parent/channel notification.

## Best Possible Solution

Keep this as the canonical product/design item for automatic subagent stall recovery, with a future design that reuses the existing registry, timeout, control, and activity seams and provides a non-terminal recovery path before any forced kill.

## Reproduction Assessment

Yes at source level, but not via a live run in this read-only review. Current main has no stall nudge/kill config or last-tool-activity recovery path, while the issue discussion includes production logs showing `sessions_spawn` stuck in processing with `recovery=none`.

## Solution Assessment

Unclear as a final product design because nudge-then-kill is plausible but not obviously the only best fix. The safer end state is a bounded recovery policy that reuses the existing subagent registry/control/timeout paths and gives users an in-product recovery or visible failure signal instead of requiring manual file cleanup.
