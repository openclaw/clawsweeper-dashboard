## Label Justifications

- `P1`: The issue includes production chat-channel sessions blocked behind stuck sessions_spawn calls for minutes to hours, making the agent appear dead to users in that conversation.
- `impact:session-state`: The requested recovery is about stalled child-run state, parent queue state, timeout/recovery state, and stuck processing sessions.
- `impact:message-loss`: The reported failure queues later group messages behind a dead spawn with no acknowledgement, error, or reply until manual recovery.

## Summary

Keep open: current main has generic stuck-session active-abort diagnostics and internal subagent kill primitives, but it still lacks the requested per-subagent two-stage tool-inactivity watchdog, nudge injection, stall-specific config, and parent/channel-visible nudge-to-kill recovery contract.

## What This Changes

The issue requests default-capable escalating subagent stall recovery based on time since last tool call, with a nudge stage followed by automatic kill and parent notification.

## Best Possible Solution

Define one canonical subagent recovery contract that reuses existing diagnostics, runTimeoutSeconds, and subagent-control primitives while specifying activity tracking, nudge delivery, kill escalation, parent wakeup, and channel-visible recovery behavior.
