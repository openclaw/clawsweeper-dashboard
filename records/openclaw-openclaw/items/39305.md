## Summary

Current main still lacks the requested tool-activity-based two-stage subagent stall recovery: hard run timeouts are enforced now, but there is no default nudge-then-kill policy, no stall config surface, and no model-facing kill/reap action for stuck child runs. The issue should stay open as product/design work rather than a cleanup close.

## What This Changes

The issue requests default subagent stall recovery that detects tool-call inactivity, nudges the child once, then kills the run and notifies the parent/channel if activity does not resume.

## Best Possible Solution

Keep the issue open for a maintainer-owned design that composes hard timeouts, explicit activity state, and internal kill primitives into one bounded recovery policy with documented defaults and upgrade behavior.
