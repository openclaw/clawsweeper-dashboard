## Label Justifications

- `P1`: A production Telegram group session was blocked behind a stuck `sessions_spawn` call for minutes to hours, making the chat workflow appear dead to users.
- `impact:session-state`: The request concerns stalled child-run state, parent queue state, timeout/recovery state, and stuck processing sessions.

## Summary

Keep open: current main and v2026.6.11 still have hard sub-agent run timeouts, diagnostic stall classification, and internal kill primitives, but not the requested tool-inactivity watchdog, nudge injection, automatic escalation, default recovery policy, or user-visible parent/channel recovery semantics.

## What This Changes

The issue requests default-capable two-stage sub-agent stall recovery that nudges a child after tool-call inactivity, then kills it and notifies the parent if it remains stalled.

## Best Possible Solution

Keep this as the canonical automatic subagent stall-recovery design item until maintainers choose one recovery contract that coordinates activity tracking, nudge delivery, kill escalation, parent wakeup, channel notification, and existing timeout/control primitives.
