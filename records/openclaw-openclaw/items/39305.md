## Label Justifications

- `P1`: The issue includes production Telegram group sessions blocked behind stuck sessions_spawn calls for minutes to hours, making the channel appear dead to users.
- `impact:session-state`: The request is about stalled child-run state, parent queue state, timeout/recovery state, and stuck processing sessions.
- `impact:message-loss`: Subsequent group messages can queue behind the dead spawn with no acknowledgement, error, or reply until manual recovery.

## Summary

Keep open: current main has hard subagent run-timeout enforcement, stale-run listing cleanup, and manual/admin kill primitives, but it still lacks the requested tool-inactivity watchdog with nudge injection, automatic kill escalation, default recovery policy, and parent/channel-visible recovery.

## What This Changes

The issue requests default two-stage sub-agent stall recovery based on tool-call inactivity, with a nudge before automatic kill and parent/channel notification if the sub-agent remains stalled.

## Best Possible Solution

Keep this as the canonical design item until maintainers define one recovery contract that reuses existing timeout/control primitives and specifies activity tracking, nudge delivery, kill escalation, parent wakeup, and channel-visible failure behavior.
