## Label Justifications

- `P1`: The report includes real chat-channel sessions blocked for minutes to hours behind a stalled `sessions_spawn`, causing visible user message starvation.
- `impact:session-state`: The affected behavior leaves parent/subagent session state stuck in active or processing states without automatic recovery.
- `impact:message-loss`: Queued chat messages can be effectively suppressed behind the stuck session, making the channel appear unresponsive.

## Summary

Keep open: current main has adjacent explicit `runTimeoutSeconds` enforcement and manual subagent control helpers, but it still lacks the requested tool-inactivity watchdog, nudge injection, automatic kill escalation, per-spawn stall overrides, and parent/channel recovery semantics.

## What This Changes

Issue requests two-stage sub-agent stall recovery based on tool-call inactivity: nudge first, then kill and notify the parent session.

## Best Possible Solution

Keep this open as a maintainer-owned runtime design: define one canonical subagent stall recovery policy that reuses reliable activity tracking, existing timeout/control seams, safe defaults, parent/channel notification behavior, and focused docs/tests.
