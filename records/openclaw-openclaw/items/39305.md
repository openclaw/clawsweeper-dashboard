## Label Justifications

- `P1`: The production report shows a stuck sessions_spawn blocking an interactive Telegram group queue for minutes to hours with no user-visible recovery.
- `impact:session-state`: The request centers on child-run activity, parent queue blocking, and recovery from stuck subagent/session state.
- `impact:message-loss`: When the parent session stays blocked, later channel messages queue silently and users receive no acknowledgement or reply.

## Summary

Keep open: current main has adjacent hard-timeout enforcement, internal kill primitives, and diagnostic abort-drain recovery, but it still lacks the requested activity-based subagent nudge-to-kill policy, per-spawn overrides, and user-visible parent/channel recovery semantics.

## What This Changes

Request to add escalating subagent stall recovery that detects inactivity since the last child tool call, nudges the subagent, then kills it and notifies the parent if it remains stalled.

## Best Possible Solution

Define one maintainer-approved subagent recovery policy that reuses existing timeout, diagnostic activity, and subagent-control primitives without creating a second source of session truth.

## Reproduction Assessment

Yes from source plus production logs, though no live repro was run; current main lacks the requested nudge/kill policy and the reported path is a sessions_spawn that stays active while the parent queue waits.

## Solution Assessment

Unclear; two-stage recovery is plausible, but maintainers still need to decide default-on behavior, config shape, timeout composition, and user-visible notification semantics.
