## Label Justifications

- `P1`: The issue includes production evidence that a stalled sessions_spawn call can block a chat session queue for real users for hours.
- `impact:session-state`: The requested recovery depends on detecting and changing subagent, parent session, active tool, timeout, and terminal state accurately.
- `impact:message-loss`: The reported failure mode leaves subsequent channel messages queued with no acknowledgement, error, or visible terminal update.
- `impact:ux-friction`: Users and operators currently need fragile prompt workarounds or manual gateway/session-file intervention to recover from the silent chat stall.

## Summary

Keep open: current main has hard subagent `runTimeoutSeconds`, stale/lost-context cleanup, and generic diagnostic abort recovery, but it still lacks the requested subagent-specific last-tool-activity nudge, configured kill escalation, per-spawn stall overrides, and parent/channel-visible recovery semantics; the matching implementation PR was closed unmerged.

## What This Changes

Request automatic two-stage subagent stall recovery that nudges a child after tool inactivity, kills it after a second deadline, and notifies the parent session.

## Best Possible Solution

Define one core subagent liveness contract that tracks deterministic activity, nudges once through a safe internal message/steer path, then terminates and delivers a non-sensitive parent/channel terminal signal while staying aligned with session activity and diagnostics recovery.
