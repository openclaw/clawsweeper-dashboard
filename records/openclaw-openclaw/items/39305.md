## Label Justifications

- `P1`: The issue includes production Telegram group sessions blocked behind stuck sessions_spawn calls for minutes to hours, making a real channel workflow appear dead to users.
- `impact:session-state`: The requested recovery policy concerns stalled child-run state, parent session processing state, run timeouts, and queue release semantics.
- `impact:message-loss`: Follow-up group messages can queue behind the dead spawn with no acknowledgement, error, or visible reply until operator recovery.

## Summary

Keep open: current main has session-level diagnostic active-abort mitigation and a broader run-lifecycle reliability design now exists, but the requested subagent-specific two-stage inactivity nudge/kill policy and parent/channel notification contract are still unresolved.

## What This Changes

Add two-stage subagent stall recovery that nudges after tool-call inactivity, then kills and reports the stalled child if inactivity continues.

## Best Possible Solution

Fold the subagent stall case into one maintainer-approved run-lifecycle recovery contract, then explicitly decide whether nudge text, kill escalation, parent wakeup, and channel-visible notices belong as subagent-specific acceptance criteria.
