- `P0`: The reported production Telegram group could remain silent for hours behind a hung `sessions_spawn`, with recovery requiring gateway restart and manual state cleanup rather than an in-product path.
- `impact:session-state`: The issue concerns parent/child subagent run state, blocked session queues, and stale active tool/run bookkeeping.
- `impact:message-loss`: Queued chat messages can sit behind the stuck spawn with no acknowledgement, reply, or terminal notification to users.
- `impact:ux-release-blocker`: A chat-channel user-facing recovery path is blocked unless an operator uses logs, manual state deletion, and gateway restart.
- `maturity:stable`: The affected Gateway runtime surface is M4 Stable in `qa/maturity-scores.yaml`, so regressions in session/runtime reliability affect a stable taxonomy area.

## Summary

Keep open: current main has adjacent `runTimeoutSeconds`, manual/admin kill paths, stale-lane diagnostic recovery, and blocked-tool-call diagnostics, but it still does not implement the requested subagent last-tool-activity nudge to kill contract or parent/channel-visible recovery by default.

## What This Changes

The issue requests automatic two-stage stall recovery for sub-agents based on tool-call inactivity, with a nudge before an enforced kill and parent/channel-visible recovery.

## Best Possible Solution

Define one runtime-owned subagent/session recovery contract with deterministic activity tracking, configurable default behavior, parent-visible terminal delivery, and focused tests/docs aligned with the open sessions.activity and watchdog work.
