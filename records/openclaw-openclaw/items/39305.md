## Label Justifications

- `P1`: The issue includes production evidence that a stalled sessions_spawn call can block a chat session's serial queue for users for hours.
- `impact:session-state`: The requested recovery depends on detecting and changing subagent, parent session, active tool, timeout, and terminal state accurately.
- `impact:message-loss`: The reported failure mode leaves subsequent chat messages queued with no acknowledgement, error, or visible terminal update.

## Summary

Keep open: current main has configurable subagent runTimeoutSeconds, merged timeout enforcement, stale-run cleanup, and generic diagnostics recovery for blocked tool calls, but it still lacks the requested two-stage subagent tool-inactivity nudge, configured kill escalation, default recovery policy, and parent/channel-visible recovery semantics.

## What This Changes

Request adds escalating subagent stall recovery that nudges a child after tool-call inactivity, then kills it and notifies the parent if it remains inactive.

## Best Possible Solution

Define one core subagent liveness contract that reuses existing diagnostic/session activity, adds conservative nudge and abort states with focused tests, and guarantees a non-sensitive parent/channel terminal signal without creating a second source of session truth.
