## Summary

Keep open: current main has hard timeout enforcement, internal kill primitives, and diagnostic abort-drain recovery, but it still lacks the requested default-on two-stage subagent inactivity nudge, kill policy, per-spawn override semantics, and user-visible recovery contract.

## What This Changes

The issue requests escalating subagent stall recovery that nudges an idle child run, then kills it and notifies the parent, with default subagent thresholds and per-spawn overrides.

## Best Possible Solution

Choose one maintainer-owned recovery contract that composes with runTimeoutSeconds, diagnostics.stuckSessionAbortMs, and the manual kill/reap surface before implementing defaults, overrides, docs, and tests.

Yes, source inspection confirms the requested policy is absent and the issue discussion includes a concrete production stuck sessions_spawn case, but I did not establish a live current-main Telegram reproduction and current diagnostic recovery may mitigate some cases.
