## Label Justifications

- `P1`: The issue has production evidence of a stalled `sessions_spawn` blocking a real chat-channel session for users until manual recovery.
- `impact:session-state`: The affected behavior leaves parent and child subagent session state stuck in running/processing instead of reaching a terminal outcome.
- `impact:message-loss`: The reported Telegram group receives no acknowledgement, error, or reply while later messages queue behind the stalled spawn.

## Summary

Keep open: current main still has explicit wall-clock subagent timeout handling and orphan/lost-context cleanup, but it does not implement tool-inactivity nudge/kill escalation, per-spawn stall policy, or a parent/channel-visible recovery contract.

## What This Changes

Request for activity-based sub-agent stall recovery that nudges a stalled child agent and then kills it if tool activity does not resume.

## Best Possible Solution

Define a core subagent recovery contract around a canonical activity signal, then implement bounded nudge/kill escalation with upgrade-safe config, docs, regression tests, and parent/channel-visible completion or error delivery.
