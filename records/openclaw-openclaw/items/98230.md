## Summary

This PR is still needed because current main and the latest release still drop over-limit Telegram model buttons, and the branch has strong Telegram Desktop proof that the long model becomes visible. It should not merge yet because the new index callback resolver uses a different model sort order than the existing `/models <provider>` command-render path, which can make valid indexed buttons refresh instead of selecting for mixed-order model lists.

## What This Changes

The PR adds a tokenized `mdl_idx_*` Telegram model-selection fallback for over-limit callback data, resolves it in the Telegram callback handler, and updates model-button regression tests.

## Best Possible Solution

Keep the tokenized index fallback shape, but make every Telegram-rendered indexed model button and the callback resolver share the same deterministic model ordering before merge.
