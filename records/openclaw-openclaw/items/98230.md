## Summary

Keep open. This is still a useful candidate for #98221, but the current head can falsely reject over-limit model buttons rendered by the `/models <provider>` command because the index resolver uses a different model ordering than that command path.

## What This Changes

The PR adds a tokenized `mdl_idx_{provider}_{index}_{token}` fallback for Telegram model-selection callbacks, resolves it in the callback handler, and updates model-button tests so over-limit model names render instead of being skipped.

## Best Possible Solution

Use one canonical model ordering for every Telegram model keyboard and indexed callback resolver, then land one sibling fix for #98221 after exact-head Telegram QA is acceptable.
