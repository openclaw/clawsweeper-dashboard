## Summary

Keep this open for an explicit architecture decision. Current OpenClaw documentation already describes `packages/agent-core` as a lower-level reusable loop while concrete OpenClaw tool execution remains outside that package, so the report’s proposed files and extraction boundary do not map cleanly onto current main. The active RuntimePlan cleanup RFC overlaps with this concern but does not clearly own a new terminal-driver package.

## What This Changes

Define whether concrete terminal execution should be extracted from agent runtime code into a separate contract-owned package.

## Best Possible Solution

Keep agent-core limited to generic loop and execution contracts, retain concrete execution and security policy with each runtime owner, and approve a separate terminal package only after a dependency and call-graph proposal identifies genuinely shared driver mechanics, all consumers, and compatibility tests.
