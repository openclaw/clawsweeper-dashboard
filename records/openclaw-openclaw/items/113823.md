## Summary

This is a newly filed, concrete Control UI enhancement, and the `maintainer` label requires explicit human handling rather than automated cleanup. The proposal has a bounded browser-local direction, but whether new-session defaults should persist these choices is product/UX policy that needs maintainer confirmation.

## What This Changes

Remember each browser origin’s last valid workspace, optional worktree, and model selections when the Control UI opens a new session.

## System Context

The Control UI gathers workspace, worktree, and model choices before creating a session through the Gateway. The requested change would retain prior browser-local preferences while validating them against the currently available Gateway and agent catalogs before applying them.

## Architecture Diagram

flowchart LR
  Browser[Browser origin] --> NewSession[New-session form]
  NewSession --> Choices[Workspace, worktree, model choices]
  Choices --> LocalPrefs[Browser-local preferences]
  LocalPrefs --> Validation[Current Gateway and agent catalog validation]
  Validation --> Session[New session request]
  Gateway[Gateway catalogs and routes] --> Validation
  Draft[Recovered draft or explicit route target] --> Session

## Best Possible Solution

Adopt a narrowly scoped browser-local preference design only if maintainers want repeated-session convenience, with explicit route state and recovered drafts taking precedence and saved values restored only after current catalog validation.
