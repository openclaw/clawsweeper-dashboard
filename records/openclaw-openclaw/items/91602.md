## Summary

Keep open: current main has useful prompt and reminder-commitment mitigations, but it does not fully settle the reported Telegram action/follow-up behavior or the self-matching `pkill` exec failure, and the mixed issue needs maintainer direction before a safe fix can be shaped.

## What This Changes

The issue asks OpenClaw to stop Telegram agent follow-up chatter after explicit action requests and to make earlier spawned exec processes killable without aborting the controlling shell.

## Best Possible Solution

Split the remaining work into a backed-follow-up policy decision tied to https://github.com/openclaw/openclaw/issues/58450 and a narrower exec/process decision that either teaches or enforces `process(action=kill)` for OpenClaw-managed sessions or safely detects self-matching shell kill commands.
