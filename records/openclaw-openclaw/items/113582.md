## Summary

Keep open for a maintainer product decision. Workboard currently treats `done` as manual operator acceptance and proof as worker-reported evidence, so the requested fail-closed gates would deliberately change the plugin’s lifecycle and authority contract rather than repair a defined regression.

Likely related people
- RomneyDa — medium confidence; recent Workboard lifecycle work is credited in release notes, so they are a useful routing candidate for the existing plugin behavior.

## What This Changes

The issue proposes fail-closed Workboard completion rules requiring structured proof and preventing completion while required child work, dependencies, blockers, or linked pull-request review conditions remain unresolved.

## System Context

Workboard is a bundled, disabled-by-default plugin that links local cards to Gateway task runs, sessions, proof records, and dashboard/CLI controls. Its lifecycle state is shown to operators next to the underlying Gateway execution state, while external systems such as GitHub remain separate authorities.

## Architecture Diagram

flowchart LR

  Gateway[Gateway task or session] --> Execution[Execution metadata]
  Worker[Worker completion] --> Proof[Proof and artifacts]
  Execution --> Lifecycle[Lifecycle decision]
  Proof --> Lifecycle
  Lifecycle --> Surfaces[Dashboard, CLI, and agent tools]
  Lifecycle --> Links[Linked task and session state]

## Best Possible Solution

Keep Workboard’s existing plugin boundary, first define which completion states are operator acceptance versus independently verified execution, then implement only the narrow plugin-level invariants and diagnostics that maintainers explicitly sponsor.
