## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Sanitize runtime batch chunks before provider upload:** `extensions/memory-core/src/memory/manager-embedding-ops.ts:256`
  - body: This adds sanitization only on the inline `provider.embedBatch` path. Current main can route source-wide indexing through `providerRuntime.batchEmbed`, and the OpenAI runtime batch adapter serializes `chunk.text` directly, so malformed Unicode can still reach the provider in batch mode and leave indexing stuck.
  - confidence: 0.9
- **[P1] Sanitize structured text parts too:** `extensions/memory-core/src/memory/manager-embedding-ops.ts:293-296`
  - body: The structured-input branch rewrites only `input.text`. `EmbeddingInput.parts` can also contain provider-facing text, and Gemini request building uses those parts when present, so a lone surrogate inside `parts[].text` still bypasses the new sanitizer.
  - confidence: 0.88
- **[P1] Reuse one shared surrogate sanitizer:** `extensions/memory-core/src/memory/manager-embedding-ops.ts:53-70`
  - body: OpenClaw already exports `sanitizeSurrogates` from `openclaw/plugin-sdk/llm`. Adding a second regex helper here creates a parallel provider-text contract with different replacement semantics, so this should reuse the existing sanitizer or promote one shared memory-specific helper if U+FFFD replacement is required.
  - confidence: 0.82
