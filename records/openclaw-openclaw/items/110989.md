## Summary

Keep this PR open for human product review and repair. It introduces a large, security-adjacent Control UI approval workflow, but the current branch still has approval-session alias, inline-card identity, and constrained-pane reachability defects; its submitted screenshots use a mock gateway rather than a real approval flow.

## What This Changes

This PR changes Control UI approvals to use an oldest-first selectable queue, active-chat inline cards, keyboard decisions, live expiry indicators, and per-agent/session pending-approval badges.

## Best Possible Solution

Keep one stable approval identity per rendered inline card, match sessions through the established UI equivalence helper, make inline cards independently scrollable within constrained panes, reset command/modal scroll position on selection changes, and add redacted proof from a real Control UI approval request before merge.
