## Summary

Keep open: current main and v2026.6.11 still expose only partial spawned-session lineage, so the requested durable root/trace session-chain contract remains unresolved and needs maintainer API direction.

## What This Changes

Add first-class spawned-session chain metadata for parent/root/trace/depth and expose it through Gateway and agent-facing session list surfaces.

## Best Possible Solution

Approve a focused additive core contract that persists optional rootSessionKey and traceId, derives them consistently for native and ACP child sessions, exposes them through Gateway and agent list projections, and leaves traversal/UI work as follow-ups.

## Reproduction Assessment

Yes, at source level. Current main shows the session model, protocol schema, row projections, native spawn path, and ACP spawn path still lack the requested durable root/trace chain metadata.

## Solution Assessment

Unclear until maintainers settle trace semantics. A narrow additive metadata contract is the maintainable direction, but it should not become a broad agent-hierarchy framework or duplicate diagnostic tracing by accident.
