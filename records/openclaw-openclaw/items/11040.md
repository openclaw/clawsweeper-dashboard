## Summary

Keep open for a maintainer product/API decision. Current main persists partial spawn lineage (`spawnedBy`, `parentSessionKey`, and `spawnDepth`) but has no `rootSessionKey` or stable session-chain `traceId`; the merged ACP work only projects the existing partial fields, while the earlier full proposal was closed unmerged. ([github.com](https://github.com/openclaw/openclaw/blob/main/src/config/sessions/types.ts))

Likely related people: `steipete` is the strongest routing candidate for the current session/gateway boundary (high confidence); `tyler6204` appears connected to the earlier nested-subagent lineage work (medium confidence).

## What This Changes

Add a durable core session-lineage contract—parent, root, trace, and depth—so spawned-session chains can be reconstructed consistently through session APIs.

## System Context

OpenClaw spawn paths create child agent sessions and persist session metadata that gateway APIs, agent tools, and ACP clients project to operators. The requested contract would make multi-hop lineage a stable shared fact instead of requiring each consumer to infer it from partial parent/depth data.

## Architecture Diagram

flowchart LR
  A[Parent agent session] --> B[Native and ACP spawn paths]
  B --> C[Persisted session entry]
  C --> D[Gateway session APIs]
  D --> E[Agent tools and ACP clients]
  E --> F[Debugging and topology views]
  C --> G[Canonical lineage semantics]

## Best Possible Solution

Choose a narrowly scoped, versioned core session-lineage contract only if multiple built-in consumers need the same durable facts; define root and trace semantics once, write them in every supported spawn path, expose them through the existing projections, and defer traversal/UI/orchestration behavior to separate proposals.
