## Summary

Keep open: current main still has only partial spawned-session lineage. The persistent model, Gateway protocol/projections, agent-facing `sessions_list` rows, and native/ACP spawn writes still lack the requested root session key and durable session-chain trace id.

## What This Changes

Request to add optional parent/root/trace/depth session-chain metadata to persisted sessions, spawn write paths, and Gateway/agent session-list projections.

## Best Possible Solution

Maintainers should approve a focused additive core contract for optional `rootSessionKey` and durable chain `traceId`, derive it consistently in native and ACP child-session creation, and expose it through Gateway and agent list projections with traversal/UI left as follow-ups.

## Reproduction Assessment

Yes for the source-level gap, though this is a feature request rather than a runtime bug. Current main still lacks `rootSessionKey` and session-chain `traceId` in the model, Gateway/API projections, agent list rows, and spawn writes.

## Solution Assessment

Unclear until maintainers choose trace semantics. A narrow additive metadata contract is the maintainable direction, but it should not duplicate diagnostic trace context or expand into a broader hierarchy framework by accident.
