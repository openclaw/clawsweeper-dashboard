## Summary

Keep open: current main and the latest release still expose only partial spawned-session lineage. The requested persisted root session key and session-chain trace id contract is absent from the session model, Gateway protocol/projections, agent-facing sessions_list rows, and native/ACP spawn writes, while related PRs only cover partial or unmerged slices.

## What This Changes

The issue requests first-class spawned-session chain metadata, including parent/root/trace/depth fields, written during spawn and exposed through session listing APIs.

## Best Possible Solution

Approve a focused additive core session-chain contract that persists optional rootSessionKey and traceId, derives them consistently for native and ACP child sessions, exposes them through Gateway and agent list projections, and leaves traversal/UI features as follow-ups.

## Reproduction Assessment

Yes for the source-level gap: current main can be inspected to show the requested rootSessionKey and session-chain traceId contract is absent from the model, protocol, projections, and spawn writes. This is a feature/API request rather than a runtime bug reproduction.

## Solution Assessment

Unclear until maintainers choose trace semantics. A narrow additive metadata contract is the maintainable direction, but it should not grow into a broader agent-hierarchy framework or duplicate diagnostic trace context accidentally.
