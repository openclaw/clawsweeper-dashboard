## Summary

Keep open: current main and v2026.6.11 still provide only partial spawned-session lineage. The requested persisted rootSessionKey and session-chain traceId contract remains missing, and the issue needs maintainer API/product agreement before another implementation attempt.

## What This Changes

Request to add optional first-class session-chain metadata for parent/root/trace/depth to stored sessions, spawn write paths, and Gateway/agent session-list outputs.

## Best Possible Solution

Approve a focused additive core session-chain contract that persists optional rootSessionKey and traceId, derives them consistently for native and ACP child sessions, exposes them through Gateway and agent list projections, and avoids becoming a broader agent-hierarchy framework.

## Reproduction Assessment

Yes. Source inspection on current main and v2026.6.11 shows the session model, Gateway protocol/projections, sessions_list rows, and native/ACP spawn writes still lack rootSessionKey and a session-chain traceId.

## Solution Assessment

Unclear until maintainers choose trace semantics. A narrow additive metadata contract is the maintainable direction, but it should not duplicate diagnostic trace context or become a broader hierarchy framework.
