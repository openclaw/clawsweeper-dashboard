## Summary

Keep open: current main and the latest release still expose only partial spawned-session lineage, while the requested persisted rootSessionKey and session-chain traceId contract remains missing and needs maintainer API/product agreement.

## What This Changes

Request to add first-class spawned-session chain metadata, including parent/root/trace/depth fields, to session storage, spawn writes, and session listing outputs.

## Best Possible Solution

Approve a focused additive core session-chain contract that persists optional rootSessionKey and traceId, derives them consistently for native and ACP child sessions, exposes them through Gateway and agent list projections, and leaves traversal/UI work as follow-ups.

## Reproduction Assessment

Yes for the missing-contract claim. Source inspection on current main shows the session model, Gateway protocol/projections, sessions_list tool rows, and native/ACP spawn writes still lack rootSessionKey plus a session-chain traceId.

## Solution Assessment

Unclear until maintainers choose trace semantics. A narrow additive metadata contract is the maintainable direction, but it should not become a broader agent-hierarchy framework or accidentally duplicate diagnostic trace context.
