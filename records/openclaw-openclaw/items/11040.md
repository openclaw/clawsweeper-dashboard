## Summary

Keep open: current main and the latest release still expose only partial spawned-session lineage, so the requested parent/root/trace/depth chain contract remains unresolved. The source gap is clear, but trace/root semantics need maintainer API direction before another automated implementation attempt.

## What This Changes

Add first-class spawned-session chain metadata so session APIs can reconstruct parent/root/trace/depth relationships across multi-hop subagent tasks.

## Best Possible Solution

Approve a focused additive core session-chain contract that persists optional rootSessionKey and traceId, derives them consistently for native and ACP child sessions, exposes them through Gateway and agent list projections, and leaves traversal/UI work as follow-ups.

## Reproduction Assessment

Yes, at source level: current main lacks rootSessionKey and session-chain traceId in the session model, Gateway schema/projections, agent-facing sessions_list rows, and native/ACP spawn writes. No live repro was needed because the gap is an absent API contract rather than a runtime failure.

## Solution Assessment

Unclear until maintainers settle trace semantics. A narrow additive metadata contract is the maintainable direction, but it should not become a broader agent-hierarchy framework or duplicate diagnostic trace context by accident.
