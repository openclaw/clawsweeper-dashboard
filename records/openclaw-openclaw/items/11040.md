## Summary

Keep open: current main and the latest release still only provide partial spawned-session lineage. The requested persistent rootSessionKey and durable session-chain traceId contract is still missing, and the issue now needs maintainer API/product agreement before another implementation attempt.

## What This Changes

The issue requests first-class spawned-session chain metadata so parent, root, trace, and depth can be persisted and exposed for deterministic subagent DAG reconstruction.

## Best Possible Solution

Approve a focused additive core session-chain contract that persists optional rootSessionKey and traceId, derives them consistently for native and ACP child sessions, exposes them through Gateway and agent projections, and leaves traversal/UI work as follow-ups.

## Reproduction Assessment

Yes. Source inspection on current main shows the session model, Gateway protocol/projections, sessions_list tool row, and native/ACP spawn writes still lack rootSessionKey plus a durable session-chain traceId.

## Solution Assessment

Unclear until maintainers choose trace semantics. A narrow additive metadata contract is the maintainable direction, but it should avoid becoming a broad agent-hierarchy framework or accidentally duplicating diagnostic trace context.
