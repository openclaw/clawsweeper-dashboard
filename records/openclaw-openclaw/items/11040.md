## Summary

Keep open: current main still has only partial spawned-session lineage, and the requested durable root session key plus session-chain trace contract is not implemented in the session model, Gateway protocol/projections, agent-facing list output, or spawn write paths. The closed exact implementation PR is not a landing path, the merged ACP work only exposes existing lineage fields, and the open resolver-lineage PR is adjacent rather than a replacement.

## What This Changes

The issue requests first-class spawned-session chain metadata, including parent, root, trace, and depth fields exposed through session APIs.

## Best Possible Solution

Decide the public spawned-session chain contract, then land a focused additive implementation that persists optional root/trace metadata, derives it in native and ACP spawn paths, exposes it in Gateway and agent session-list projections, and documents/tests multi-hop reconstruction.
