## Summary

Keep open: current main and v2026.6.11 still expose only partial spawned-session lineage, so the requested durable root/trace session-chain contract remains unresolved and needs maintainer API direction.

## What This Changes

The issue requests first-class parent/root/trace/depth metadata for spawned session chains, persisted on sessions and exposed through Gateway and agent list APIs.

## Best Possible Solution

Approve a focused additive core contract that persists optional rootSessionKey and traceId, derives them consistently in native and ACP child-session creation, exposes them through Gateway and agent list projections, and leaves traversal/UI work as follow-ups.

## Reproduction Assessment

Yes, at source level. Current main shows the session model, Gateway schema/list rows, sessions_list row shape, native spawn path, and ACP spawn path still lack the requested durable root/trace chain metadata.

## Solution Assessment

Unclear until maintainers settle trace semantics. A narrow additive metadata contract is the maintainable direction, but it should not become a broader agent-hierarchy framework or accidentally duplicate diagnostic trace context.
