## Summary

Keep open: current main and the latest release still only provide partial spawned-session lineage. The requested durable root session key and session-chain trace id contract is absent from the persistent model, Gateway schema/projections, agent-facing sessions_list rows, and native/ACP spawn writes; the exact implementation attempt is closed unmerged, and the remaining trace semantics need maintainer product/API agreement.

## What This Changes

Request to add first-class spawned-session chain metadata, including parent/root/trace/depth fields, write-path derivation, and Gateway/tool list exposure.

## Best Possible Solution

Approve a focused additive core session-chain contract that persists optional rootSessionKey and traceId, derives them consistently for native and ACP child sessions, exposes them through Gateway and agent list projections, and leaves traversal/UI work as follow-ups.

## Reproduction Assessment

Yes. Source inspection on current main shows the requested rootSessionKey and session-chain traceId are missing from the session model, Gateway schema/projections, sessions_list tool rows, and native/ACP spawn writes.

## Solution Assessment

Unclear until maintainers choose trace semantics. A narrow additive metadata contract is the maintainable direction, but it should not grow into an agent-hierarchy framework or accidentally duplicate diagnostic tracing.
