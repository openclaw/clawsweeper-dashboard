## Summary

Keep open: current main still has only partial spawned-session lineage. The persistent model, Gateway protocol/projections, agent-facing sessions_list rows, and native/ACP spawn writes still lack the requested first-class rootSessionKey and session-chain traceId contract, while related PRs either merged only adjacent projection work or remain non-canonical.

## What This Changes

The issue requests additive first-class session/task chain metadata so spawned sessions expose parent/root/trace/depth lineage through session APIs.

## Best Possible Solution

Approve a focused additive core session-chain contract that persists optional rootSessionKey and traceId, derives them consistently for native and ACP child sessions, exposes them through Gateway and agent list projections, and leaves traversal/UI work as follow-ups.

## Reproduction Assessment

Yes for the source-level gap: current main lacks rootSessionKey and session-chain traceId in the stored session model, Gateway schema/projections, sessions_list rows, and spawn write paths. This is an additive feature/API contract rather than a failing existing behavior reproduction.

## Solution Assessment

Unclear until maintainers choose trace semantics and terminology. A narrow additive metadata contract looks like the maintainable direction, but it should not become a broader agent-hierarchy framework or accidentally duplicate diagnostic trace context.
