## Summary

Keep open: current main and v2026.6.11 still expose only partial spawned-session lineage. The requested persisted rootSessionKey and session-chain traceId contract is still missing, and the remaining decision is API/product semantics rather than cleanup closure.

## What This Changes

Request adds first-class spawned session chain metadata so parent, root, trace, and depth can be reconstructed from session APIs.

## Best Possible Solution

Approve a focused additive core session-chain contract that persists optional rootSessionKey and traceId, derives them consistently for native and ACP child sessions, exposes them through Gateway and agent list projections, documents the fields, and leaves traversal/UI work as follow-ups.

## Reproduction Assessment

Yes. Source inspection on current main shows the session model, protocol schema, Gateway rows, sessions_list rows, and native/ACP spawn writes still only implement partial parent/depth lineage, not the requested root/trace chain contract.

## Solution Assessment

Unclear until maintainers choose trace semantics. A narrow additive metadata contract is the maintainable direction, but it should not grow into a broader agent-hierarchy framework or duplicate diagnostic trace context accidentally.
