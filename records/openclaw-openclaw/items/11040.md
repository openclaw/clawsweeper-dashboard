## Summary

Keep open: current main and the latest release still provide only partial spawned-session lineage; the requested persisted rootSessionKey and durable session-chain traceId contract is still missing and needs maintainer API/product direction.

## What This Changes

Request to add optional parent/root/trace/depth session-chain metadata for spawned sessions and expose it through Gateway and agent session listing surfaces.

## Best Possible Solution

Approve a focused additive core session-chain contract that persists optional rootSessionKey and traceId, derives them for native and ACP child sessions, exposes them through Gateway and agent list projections, and leaves traversal/UI work as follow-ups.

## Reproduction Assessment

Yes for the missing-contract claim. Source inspection on current main and v2026.6.11 shows the persistent session model, Gateway protocol/projections, agent-facing sessions_list rows, and native/ACP spawn writes still lack rootSessionKey and a session-chain traceId.

## Solution Assessment

Unclear until maintainers choose trace semantics. A narrow additive metadata contract is the maintainable direction, but it should not become a broader agent-hierarchy framework or duplicate diagnostic trace context accidentally.
