## Summary

Keep open: current main and the latest release still only expose partial parent/depth lineage; the requested persisted root session key and durable session-chain trace id are still missing, and the remaining decision is a core API/product choice rather than conservative cleanup.

## What This Changes

Request to add first-class parent/root/trace/depth metadata so spawned session chains can be reconstructed from session APIs.

## Best Possible Solution

Approve a focused additive core session-chain contract that persists optional rootSessionKey and traceId, derives them for native and ACP child sessions, exposes them through Gateway and agent list projections, and leaves traversal/UI work as follow-ups.

## Reproduction Assessment

Yes. Source inspection on current main and v2026.6.11 shows parent/depth lineage exists, but rootSessionKey and a session-chain traceId are absent from the persistent model, protocol, projections, and spawn writes.

## Solution Assessment

Unclear until maintainers choose trace semantics. A narrow additive metadata contract is the maintainable direction, but it should not become a broader agent-hierarchy framework or duplicate diagnostic trace context accidentally.
