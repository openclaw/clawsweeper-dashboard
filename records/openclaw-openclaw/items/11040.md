## Summary

Keep open: current main and the latest release still only provide partial spawned-session lineage, while the requested persisted root session key and durable session-chain trace identifier remain absent from the core session/API contract.

## What This Changes

Request to add optional parent/root/trace/depth metadata for spawned sessions and expose it through Gateway and agent session-listing surfaces.

## Best Possible Solution

Decide the public spawned-session chain contract, then land a focused additive implementation that persists optional root/trace metadata, derives it in native and ACP spawn paths, exposes it in Gateway and agent session-list projections, and documents/tests multi-hop reconstruction.

## Maintainer Decision

Question: Should OpenClaw add public persisted rootSessionKey and session-chain traceId fields for spawned sessions, and should traceId be a new chain identifier or intentionally map to existing diagnostic trace context?

Rationale: The implementation is bounded, but root/trace fields would become durable persisted session and Gateway/tool API contracts whose semantics need maintainer intent before another repair PR is useful.

Likely owner: steipete

Owner confidence: high

Options:

- **Add Minimal Spawn-Chain Contract (recommended):** Add optional parent/root/trace/depth metadata for spawned sessions only, with additive schema, projections, docs, and tests while leaving traversal APIs for later.
- **Align With Resolver Lineage First:** Keep this open until sessions.resolve and rotated-family lineage semantics settle, then align spawned-session metadata with the broader contract.
- **Reject Durable Root/Trace Fields:** Keep current parent/depth behavior and limit future work to tooling or docs if maintainers do not want a new persisted chain identifier.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 expose spawnedBy, parentSessionKey, and spawnDepth in some paths but lack rootSessionKey and durable session-chain traceId in the persistent model, protocol, projections, and spawn writes.

## Solution Assessment

Unclear until maintainer API direction is set. The requested additive metadata is a plausible bounded solution, but trace semantics and overlap with resolver/diagnostic lineage need a product decision first.
