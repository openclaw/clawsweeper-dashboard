## Summary

Keep open: current main and v2026.6.11 still provide only partial spawned-session lineage. `spawnedBy`, `parentSessionKey`, and `spawnDepth` exist in some paths, but the requested persisted `rootSessionKey` and session-chain `traceId` contract is still missing and needs maintainer API/product judgment.

## What This Changes

The issue requests first-class session/task chain metadata so spawned sessions expose parent, root, trace, and depth information through session APIs and agent tooling.

## Best Possible Solution

Approve a focused additive core session-chain contract that persists optional `rootSessionKey` and `traceId`, derives them consistently for native and ACP child sessions, exposes them through Gateway and agent list projections, and leaves traversal/UI work as follow-ups.

## Reproduction Assessment

Yes. Source inspection shows the current session model, Gateway protocol schema, row projections, native spawn, ACP spawn, and adjacent tests still implement only partial parent/depth lineage, not the requested root/trace contract.

## Solution Assessment

Unclear until maintainers choose trace semantics. A narrow additive metadata contract is the maintainable direction, but it should not become a broader agent-hierarchy framework or duplicate diagnostic trace context accidentally.
