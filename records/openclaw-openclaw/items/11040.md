## Summary

Keep open: current main still provides only direct parent/depth lineage and does not expose a durable root or chain identity across multi-hop spawned sessions. The merged ACP work projects existing lineage fields only, while the original implementation PR is closed and unmerged; the newer TaskFlow surface creates an owner-boundary choice rather than fully replacing this request.

## What This Changes

Add durable parent, root, chain-identity, and depth metadata for spawned sessions and expose it through session listing surfaces.

## Best Possible Solution

Add optional rootSessionKey and a distinctly named spawnChainId through one shared lineage-derivation helper used by native and ACP spawn paths, expose parent/root/depth/chain consistently in Gateway and sessions_list rows, and let TaskFlow reference that identity rather than inventing a competing chain.
