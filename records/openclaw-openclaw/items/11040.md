## Summary

Keep open: current main and latest release still expose only partial spawned-session lineage. The requested persisted root session key and session-chain trace id contract remains missing, and the remaining decision is API/product semantics rather than cleanup closure.

## What This Changes

Add first-class spawned-session chain metadata so tools can reconstruct parent/root/trace/depth lineage across multi-hop subagent sessions.

## Best Possible Solution

Approve a focused additive core session-chain contract that persists optional rootSessionKey and traceId, derives them consistently for native and ACP child sessions, exposes them through Gateway and agent list projections, and leaves traversal/UI work as follow-ups.

## Reproduction Assessment

Yes. Source inspection shows the current session model, Gateway protocol schema, row projections, native spawn, ACP spawn, and adjacent tests still only implement partial parent/depth lineage, not the requested root/trace contract.

## Solution Assessment

Unclear until maintainers choose trace semantics. A narrow additive metadata contract is the maintainable direction, but it should not become a broader agent-hierarchy framework or duplicate diagnostic trace context accidentally.
