## Summary

Keep open for a maintainer product decision. Current main has durable parent/depth lineage, and the merged ACP work exposes that existing lineage to ACP clients, but the requested cross-surface root-session and stable trace contract is still absent; the earlier end-to-end implementation attempt was closed unmerged.

## What This Changes

Add optional persisted parent, root, trace, and depth metadata so native and ACP-spawned session chains can be reconstructed consistently through Gateway and agent session-list APIs.

## System Context

OpenClaw records session metadata when native or ACP flows create subagents, then projects those records through Gateway and agent-facing session listings. This request would extend that shared session contract so operational tools can reconstruct multi-hop execution chains rather than infer only direct parentage.

## Architecture Diagram

flowchart TD
  A[Parent session] --> B[Native or ACP spawn]
  B --> C[Child session metadata]
  C --> D[Session store]
  D --> E[Gateway session listings]
  E --> F[Agent tools and ACP clients]
  G[Root and trace contract decision] --> C

## Best Possible Solution

Select and document one additive, persisted lineage contract—root key plus a dedicated chain identifier—then implement it consistently in native and ACP spawn paths, Gateway/agent/ACP projections, and multi-hop regression coverage without reviving the unrelated portions of the closed branch.
