## Summary

Keep open: current main still lacks the requested persistent `rootSessionKey` and session-chain `traceId` contract across the session model, Gateway/tool projections, and native/ACP spawn writes; related work is either closed unmerged, partial ACP projection, or adjacent resolver/listing work.

## What This Changes

Request adds optional parent/root/trace/depth chain metadata for spawned sessions and exposes it through session APIs and tools for DAG reconstruction.

## Best Possible Solution

Approve a focused additive core session-chain contract that persists optional root and trace metadata, derives it in native and ACP child spawns, exposes it through Gateway and agent list projections, and leaves traversal/UI work as follow-ups.

## Reproduction Assessment

Yes. Source inspection on current main shows the session model, Gateway protocol/projections, `sessions_list` tool rows, and native/ACP spawn writes still lack `rootSessionKey` plus a session-chain `traceId`.

## Solution Assessment

Unclear until maintainers choose trace semantics. A narrow additive metadata contract looks like the maintainable direction, but it should not become a broader agent-hierarchy framework or duplicate diagnostic trace context accidentally.
