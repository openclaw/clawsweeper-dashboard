## Summary

The prior one-hour cutoff finding is fixed: the branch now bounds non-advancing Ollama pull streams without imposing a total lifetime on healthy progressing downloads. The patch is technically sound and well proven, but the new default intentionally aborts existing status-only or non-advancing streams after 300 seconds, so the remaining merge step is explicit owner confirmation of that compatibility tradeoff.

## What This Changes

Adds a 300-second semantic no-progress watchdog to Ollama setup model pulls, threads test-only timeout overrides through the pull path, and adds fake-timer and real loopback regression coverage.

## Best Possible Solution

Keep the semantic watchdog in the Ollama plugin and merge it once an Ollama setup owner confirms that 300 seconds without increasing `completed` is the intended default failure contract, while retaining the separate header and byte-idle guards.
