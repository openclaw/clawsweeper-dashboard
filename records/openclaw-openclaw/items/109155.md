## Summary

The current revision fixes the earlier status-finalization blocker, but it still lets arbitrary alternating status strings continually reset the watchdog while `completed` never advances. That leaves the central drip-hang failure mode reachable, so this PR needs one narrow follow-up before merge.

## What This Changes

The PR adds a no-progress watchdog to Ollama setup model pulls, threads test-only timeout overrides through the pull path, and adds fake-timer plus native loopback regressions.

## Best Possible Solution

Keep the no-progress watchdog in the Ollama setup owner, but bound status-only resets to a protocol-defined finalization condition or separate bounded allowance, then add a loopback regression for unchanged `completed` with alternating status values.
