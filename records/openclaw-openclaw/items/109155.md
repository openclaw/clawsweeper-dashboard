## Summary

Keep this PR open for an Ollama setup-owner decision before merge. The semantic watchdog addresses a real post-header drip hang and has strong local loopback evidence, but it makes a new fail-closed compatibility choice that treats lack of increasing `completed` as lack of progress; Ollama’s documented status-only finalization stages do not carry `completed`.

Likely related people: steipete and BruceMacD were explicitly requested as reviewers for this Ollama setup behavior; ownership confidence is low because direct repository-history inspection was unavailable in this read-only runner.

## What This Changes

Adds a no-progress watchdog to Ollama setup model pulls, threads test-only timeout overrides through the pull path, and splits/extends fake-timer and local HTTP loopback regression coverage.

## Best Possible Solution

Define the supported post-download pull-progress contract with the Ollama setup owner, then encode and test the chosen treatment of status-only finalization without reintroducing an unconditional total lifetime cap.
