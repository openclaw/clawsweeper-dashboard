## Summary

The prior cycling-status finding is fixed, but the new first-seen-status rule still lets an Ollama pull stream send an unlimited sequence of distinct status strings without increasing `completed`; that continually renews the watchdog and can again keep setup alive indefinitely. The PR therefore needs one bounded status-only finalization policy before merge.

Likely related people: steipete and BruceMacD were directly mentioned for review on this PR, but feature-history ownership could not be established from the available read-only inspection path (low confidence).

## What This Changes

The PR adds a no-progress watchdog to Ollama model setup pulls, with fake-timer and native-loopback regressions for stalled, advancing, status-only, and cycling NDJSON streams.

## Best Possible Solution

Renew the normal watchdog only for aggregate `completed` growth, and give status-only post-download finalization one explicitly bounded, non-renewable grace budget with regressions for both distinct-status drips and valid finite finalization.
