## Summary

Keep open for a narrow revision: the hang is credible and the loopback evidence is strong, but the proposed timeout contract is not merge-safe for existing Ollama setup behavior.

## What This Changes

The PR adds a one-hour post-header wall-clock deadline to Ollama model pulls, threads test timeout overrides through setup, and adds fake-timer and loopback regression coverage.

## Best Possible Solution

Bound the pull by lack of meaningful Ollama progress rather than total elapsed time, and keep timeout injection behind a private helper so legitimate long downloads and the public plugin contract remain unchanged.
