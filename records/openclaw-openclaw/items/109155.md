## Summary

Keep this PR open: its no-progress watchdog appears to treat `completed` as one monotonically increasing value, but Ollama reports progress per downloaded digest. A valid pull can begin another layer at a lower `completed` value and then be aborted despite making real progress.

## What This Changes

The PR adds a no-progress watchdog to Ollama setup model pulls, refactors setup-test helpers, and adds native loopback coverage for stalled and healthy NDJSON pull streams.

## Best Possible Solution

Track pull progress per Ollama digest, or explicitly reset the progress baseline on a digest transition, and cover a multi-layer pull where the second layer begins below the first layer’s completed byte count.
