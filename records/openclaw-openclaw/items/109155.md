## Label Justifications

## Summary

The drip-hang diagnosis is valid, but the proposed fixed one-hour body deadline also cancels healthy model downloads that continue making real progress, so this PR needs a progress-aware bound before merge.

## What This Changes

Adds a post-header one-hour wall-clock deadline for Ollama setup model pulls, threads test timeout overrides through the pull path, and adds fake-timer and loopback regression coverage.

## Best Possible Solution

Replace the unconditional one-hour cutoff with a deadline for absent semantic progress, retaining a separately justified generous hard maximum only if maintainers explicitly want one.

## Solution Assessment

No. A separate post-header bound is appropriate, but an unconditional one-hour lifetime is broader than the reported drip failure; bounding absent semantic progress is the narrower compatibility-preserving fix.
