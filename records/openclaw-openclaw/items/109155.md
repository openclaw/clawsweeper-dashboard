## Summary

The exact-head patch is technically sound and well-proven, but it intentionally changes Ollama onboarding from indefinitely tolerating active non-advancing streams to failing after 300 seconds. An Ollama setup owner should accept that compatibility boundary before merge.

## What This Changes

The PR adds a semantic no-progress watchdog to Ollama setup model pulls, threads test-only timeout overrides through the pull path, and adds fake-timer plus native loopback regressions.

## Best Possible Solution

Land the semantic watchdog after an Ollama setup owner explicitly accepts 300 seconds without aggregate completed growth as a stalled pull, keeping the existing header and byte-idle budgets and the advancing-progress regressions unchanged.
