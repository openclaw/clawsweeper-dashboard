## What This Changes

Restore one OpenTelemetry parent-child trace from inbound channel or cron processing through harness, run, model/tool, and exec spans.

## System Context

OpenClaw's channel and cron dispatch paths start an agent turn, which emits diagnostic lifecycle events consumed by the diagnostics-otel plugin and exported to an OTLP collector. The resulting trace hierarchy is what operators use to connect message handling, harness work, model/tool calls, and delivery into one request waterfall.

  C --> D[Harness and agent run]
  D --> E[Model, tool, and exec events]

  F --> G[OTLP collector and trace UI]

Reproduce with the packaged 2026.7.1 diagnostics-otel plugin in a clean channel and cron scenario, capture the diagnostic trace context at dispatch, harness, run, and exec boundaries, then repair only the boundary that drops or replaces it and add an OTLP regression test for both paths.
