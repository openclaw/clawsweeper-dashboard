## Summary

Close: current main and v2026.6.11 fix the Monitor-specific failure by disallowing unsupported native Claude Monitor/background Bash callbacks in both fresh and resumed claude-cli runs; the broader long-running background-work lifecycle remains tracked separately.

## What This Changes

The report asks OpenClaw to stop losing completion events from non-persistent native Claude Monitor tasks when a later user turn arrives before the watched condition fires.

## Best Possible Solution

Keep the shipped fail-closed Claude CLI default for unsupported native Monitor callbacks, and handle durable long-running background-work design under the broader tracker.

## Reproduction Assessment

No failing current-main reproduction remains: the native Monitor tool is no longer exposed by default under claude-cli. The old failure is supported by the report and by PR proof showing the pre-fix argv allowed the native affordance while the fixed argv hides it.

## Solution Assessment

Yes for this exact surface: the provider-owned argv denial is the narrowest shipped fix because OpenClaw cannot deliver native Claude Monitor callbacks in this run mode. Broader durable background-work survival remains a separate product/runtime design tracked in https://github.com/openclaw/openclaw/issues/97919.
