## Summary

Keep open. Current main still misclassifies non-throwing soft-error tool results in diagnostics, and the patch looks like the right producer-side fix, but this external PR still lacks real diagnostic/exporter proof from a real setup.

## What This Changes

The PR changes the before-tool-call diagnostics wrapper so returned soft-error tool results emit `tool.execution.error` instead of `tool.execution.completed`, and adds a focused regression test.

## Best Possible Solution

Merge the narrow shared-classifier diagnostics fix after redacted real runtime/exporter proof is added and normal maintainer review remains clear.

## Reproduction Assessment

Yes, source-level. Current main emits `tool.execution.completed` for every non-throwing wrapped tool result while the shared classifier and observer already identify returned soft-error payloads as errors.

## Solution Assessment

Yes, with the proof caveat. Classifying at the before-tool-call diagnostics producer with the existing `isToolResultError` predicate is the narrow owner-boundary fix and avoids a second error classifier.
