## What This Changes

The PR changes the before-tool-call diagnostics producer to emit `tool.execution.error` for returned soft-error tool results using the shared tool-result classifier, and adds a focused regression test.

## Best Possible Solution

Merge the narrow shared-predicate diagnostics fix after the contributor adds redacted real runtime/exporter proof and normal maintainer review remains clear.

## Reproduction Assessment

Yes, source-level. Current main emits `tool.execution.completed` for every non-throwing wrapped tool result while the shared classifier already identifies returned soft-error payloads as errors.

## Solution Assessment

Yes, with the proof caveat. Classifying at the before-tool-call diagnostics producer with the existing `isToolResultError` predicate is the narrow owner-boundary fix, and the status fallback avoids turning success-like statuses into noisy categories.
