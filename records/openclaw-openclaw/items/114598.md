## Summary

Keep this PR open, but it is not ready to merge: the new activity reschedule can cut any existing attempt budget above 120 seconds down to a hard 120-second maximum after progress, and the supplied live transcript does not exercise the reported 26-second timeout race. The underlying report remains a valid P1 reliability issue tracked by https://github.com/openclaw/openclaw/issues/113182.

## What This Changes

The branch changes embedded-agent run budgeting from a fixed deadline to a progress-rescheduled deadline, cancelling the prior timer and clamping the total run lifetime to 120 seconds.

## System Context

The embedded-agent runner creates an attempt with a run budget and streams model/tool progress through its execution lifecycle. This timeout helper aborts attempts that exceed their budget; its result determines whether the final assistant output can be committed to the session transcript.

## Architecture Diagram

flowchart LR

  B --> C[Run-budget timeout helper]
  D[Model and tool progress] --> E[Progress callback]
  E --> C
  C --> F[Abort or continue decision]
  F --> G[Assistant transcript outcome]

## Best Possible Solution

Reschedule only on genuine attempt progress while preserving every pre-existing timeout budget, add a regression case for a budget above the proposed cap, and attach redacted embedded-runner logs or terminal output from a run that crosses the old deadline and commits final assistant text.
