## What This Changes

The issue requests that OpenClaw prevent unattended configuration mutations and reject invalid sandbox-mode values so Docker-less hosts’ cron jobs cannot be silently broken.

## System Context

Memory and cron workflows can invoke agent tool execution, while the sandbox subsystem chooses how those executions are isolated. Configuration updates affect later gateway and cron runs, so an unintended change to sandbox settings can turn a one-time failure into repeated scheduled-job failures.

  F --> G[Later isolated cron jobs]

## Best Possible Solution

Trace and prove every path that can invoke `openclaw config patch` or rewrite canonical configuration, then enforce an explicit authority and audit boundary; separately validate sandbox-mode values at the canonical schema boundary with an upgrade-safe remediation path.
