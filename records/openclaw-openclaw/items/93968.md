## Summary

Keep open: current main and v2026.6.11 still expose actionable sandbox config hints, and the only linked hardening PR is closed unmerged. The `non-main` schema subclaim is stale because it is now documented and schema-valid, but the broader security/config-mutation boundary remains unresolved.

## What This Changes

The issue asks OpenClaw to stop silent config mutations from memory-core cron/error-message auto-fix paths and to harden sandbox config validation and auditability.

## Best Possible Solution

Define and enforce one operator-approved config mutation boundary: assistant-visible errors should not contain protected config assignments, cron/plugin/exec config writes need clear provenance or approval, and `non-main` should remain supported.
