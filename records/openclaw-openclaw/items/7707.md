- `impact:session-state`: The request concerns durable memory/session context that can persist and resurface across future agent sessions.

## Summary

Keep open: current main and v2026.6.11 still expose memory source buckets, citations, Active Memory untrusted framing, Memory Wiki provenance, and external prior art, but they do not implement native durable trust metadata, review/expiration gates, or trust-weighted retrieval across the memory host, memory-core, QMD, SDK, and config surfaces.

## What This Changes

Request durable memory entries be tagged by source trust and have retrieval-time review, expiration, and influence policies to reduce memory poisoning risk.

## Best Possible Solution

Define one host-authored memory trust/provenance contract, then persist and enforce it across memory-core, QMD, session memory, Active Memory, Memory Wiki bridges, SDK/config/docs/UI, with migrations and security review; treat AKF and world-model-mcp as prior art rather than closure.

## Reproduction Assessment

Yes, source-reproducible: current main and v2026.6.11 memory type, schema, config, tool, and retrieval paths lack persisted trust metadata and enforcement, so no live exploit is needed to confirm the requested architecture is absent.

## Solution Assessment

Unclear as proposed: the direction is sound, but maintainers need to choose host-assigned trust authority, durable schema and migrations, SDK compatibility, and retrieval policy before implementation.
