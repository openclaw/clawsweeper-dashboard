## Summary

Current main and v2026.6.11 still lack durable memory trust metadata and trust-based retrieval policy. The canonical provenance issue and open source-actor PR are useful prerequisites, but both stop short of the review, expiration, and influence controls requested here, so this issue remains necessary for maintainer product and security design.

## What This Changes

Add source-derived trust metadata to persistent memory and enforce review, expiration, isolation, and influence policies during retrieval.

## Best Possible Solution

Build on https://github.com/openclaw/openclaw/issues/42647 and https://github.com/openclaw/openclaw/pull/96864, then standardize causal source, independent review state, and influence eligibility in the shared memory contract; keep storage, retention, and ranking policy in the active memory plugin, with migrations and secure operator-controlled overrides.

## Risks / Open Questions

- A shared trust contract changes persisted memory semantics and third-party plugin expectations; implementing before choosing the schema and migration boundary could create incompatible memory formats.
- Trust assignment must come from framework-carried provenance rather than agent-authored labels, or poisoned content could promote itself to a trusted state.
- Operator-curated deployments need an explicit, auditable trusted-source policy without weakening secure defaults for mixed-source agents.
- Expiration, ranking weight, review state, and execution influence are separate policy dimensions; combining them into one numeric trust score would make compatibility and auditing difficult.
