## Summary

Keep this issue open: current main and v2026.6.11 still lack durable memory trust metadata, trust-policy config, review/expiration gates, and trust-weighted retrieval enforcement. The linked AKF and world-model-mcp work are useful prior art, but the verified world-model adapter is MCP-only/experimental and does not close the native memory-core, QMD, Active Memory, or SDK contract gap.

## What This Changes

Add source-based trust tagging for durable memory entries, with trust-aware review, expiration, isolation, and retrieval weighting policies.

## Best Possible Solution

Define one maintainer-approved host-authored durable memory trust contract, then persist and enforce it consistently across memory-core, QMD, session-memory, Active Memory, Memory Wiki/MCP bridge boundaries, SDK/config surfaces, UI/docs, and migrations while evaluating AKF and world-model-mcp as prior art.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 can be checked by reading the memory result type, SQLite schema, config schema, tool schema, and retrieval path, all of which lack durable trust metadata and trust-policy enforcement. This is a feature/security gap rather than a failing command reproduction.

## Solution Assessment

Unclear as a concrete implementation plan: the trust-tagging direction is appropriate, but the proposed config alone is not enough without maintainer decisions on host-assigned provenance, persistence/migration, plugin SDK compatibility, review/expiration semantics, and retrieval policy.
