## Summary

Keep open: current main and v2026.6.11 still lack durable host-authored memory trust metadata, trust-policy config, review/expiration gates, and trust-weighted retrieval enforcement. AKF, Cophy, and world-model-mcp are useful prior art, but they do not close the native memory-core, QMD, Active Memory, Memory Wiki, or SDK contract gap.

## What This Changes

Issue requests source-based trust tagging for persistent memory, including trust metadata, expiration/review policy, and trust-weighted retrieval.

## Best Possible Solution

Define one host-authored durable memory trust contract, then persist and enforce it consistently across memory-core, QMD, session-memory, Active Memory, SDK/config surfaces, UI/docs, and migrations while evaluating AKF and world-model-mcp as prior art.

Yes, at source level: current main and v2026.6.11 can be checked by reading the memory result type, SQLite schema, config schema, tool schema, and retrieval path, all of which lack durable trust metadata and trust-policy enforcement. This is a feature/security gap rather than a failing command reproduction.

## Solution Assessment

Unclear as an implementation plan: source-based trust tagging is the right problem shape, but the proposed config alone is not enough without maintainer decisions on host-assigned provenance, persistence/migration, plugin SDK compatibility, and retrieval policy.
