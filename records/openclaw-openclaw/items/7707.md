## Summary

Keep open: current main and latest stable still expose source labels and adjacent untrusted prompt framing, but not persisted trust metadata, review/expiration gates, or trust-weighted retrieval. The AKF/world-model-mcp discussion and older closed KG/trust PRs are useful prior art, not native memory-core/QMD/SDK closure.

## What This Changes

Issue #7707 requests source-derived trust tiers, review/expiration/isolation policy, and trust-weighted retrieval for durable memory entries.

## Best Possible Solution

Define one host-authored durable memory trust/provenance contract, then persist and enforce it consistently across memory-core, QMD, session-memory, Active Memory, SDK/config surfaces, UI/docs, and migrations while evaluating AKF and world-model-mcp as prior art.

Yes. Current main and v2026.6.11 are source-reproducible by reading the memory result type, SQLite schema, config schema, tool schema, and builtin/QMD retrieval paths, all of which lack durable trust metadata and trust-policy enforcement.

## Solution Assessment

Unclear as an implementation plan: source trust tagging is directionally right, but the proposed config alone is not enough without maintainer decisions on host-assigned provenance, persistence/migration, plugin SDK compatibility, and retrieval policy.
