## Summary

Keep this issue open: current main still has adjacent source labels, session visibility filtering, Active Memory untrusted framing, and external prior art, but it does not persist durable memory trust metadata or enforce trust-policy review, expiration, or retrieval weighting in the native memory paths.

## What This Changes

The issue requests source-based trust metadata for memory entries plus trust-aware expiration, review, isolation, and retrieval policy.

## Best Possible Solution

Define one host-authored durable memory trust/provenance contract, then persist and enforce it consistently across memory-core, QMD, session-memory, Active Memory, SDK/config surfaces, UI/docs, and migrations while evaluating AKF and world-model-mcp as prior art.

## Reproduction Assessment

Yes, at source level: current main can be checked by reading the memory result type, SQLite schema, config schema, tool schema, and retrieval path, all of which lack durable trust metadata and trust-policy enforcement. This is a feature/security gap rather than a failing command reproduction.

## Solution Assessment

Unclear as an implementation plan: the trust-tagging direction is appropriate, but the proposed config alone is not enough without maintainer decisions on host-assigned provenance, persistence/migration, plugin SDK compatibility, and retrieval policy.
