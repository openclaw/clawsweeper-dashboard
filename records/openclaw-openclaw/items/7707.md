## Summary

Keep this issue open: current main and v2026.6.11 still lack durable memory trust metadata, trust-policy config, review/expiration gates, and trust-weighted retrieval enforcement. The new world-model-mcp OpenClaw adapter is useful prior art, but it is MCP-only/experimental and does not close the native memory-core, QMD, Active Memory, or SDK contract gap.

## What This Changes

The request is to tag durable memory by source trust and apply expiration, review/isolation, and retrieval weighting policies to reduce memory poisoning risk.

## Best Possible Solution

Define one host-authored durable memory trust contract, then persist and enforce it consistently across memory-core, QMD, session-memory, Active Memory, SDK/config surfaces, UI/docs, and migrations while evaluating AKF and world-model-mcp as prior art.

Yes, at source level: current main and v2026.6.11 can be checked by reading the memory result type, SQLite schema, config schema, tool schema, and retrieval path, all of which lack durable trust metadata and trust-policy enforcement. Unclear as an implementation plan: the trust-tagging direction is appropriate, but the proposed config alone is not enough without maintainer decisions on host-assigned provenance, persistence/migration, plugin SDK compatibility, and retrieval policy.
