## Summary

Keep open for maintainer product and security design. Current main has adjacent provenance features and external plugin/MCP options, but the default memory contract still cannot preserve or enforce source trust, review state, expiration, or influence policy.

## What This Changes

Requests persistent source-based trust metadata and policies for memory ingestion, retention, review, and retrieval influence.

## Best Possible Solution

Standardize framework-assigned provenance, endorsement, and influence metadata at the public memory-plugin boundary, then enforce it in one recommended backend with migration, audit/review, expiry, and retrieval-gate coverage while allowing external MCP or plugin backends to implement the same contract.

## Reproduction Assessment

Yes, at source level: current main's storage, SDK, configuration, and retrieval contracts have no persistent trust, review, expiry, or influence-enforcement path. This is a missing security capability rather than a regression test failure.

## Solution Assessment

No. Fixed trust tiers derived only from source names are not the best complete solution; trust assignment must be framework-controlled, provenance and endorsement must remain separate, and influence policy must be portable across memory backends.
