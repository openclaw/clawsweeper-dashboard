## Summary

Keep this open: current main and v2026.6.11 still have only coarse memory/session source buckets and adjacent untrusted-context framing, not durable per-memory trust metadata, trust-policy config, review/expiration gates, or trust-weighted retrieval. The AKF and world-model-mcp comments are useful prior art, but they do not close the native memory-core, QMD, Active Memory, and SDK contract gap.

## What This Changes

The issue requests native memory trust tagging by source, with policy-driven expiration, review/isolation, and trust-weighted retrieval to reduce persistent memory poisoning risk.

## Best Possible Solution

Keep this as a maintainer/security design issue and define a framework-assigned provenance/trust contract that spans memory-core, QMD, Active Memory, SDK/API types, migrations, docs, and retrieval-time enforcement.
