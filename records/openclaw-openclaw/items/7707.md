## Summary

Keep open for maintainer product and security design: current main and v2026.6.11 still provide only source/score-based memory retrieval, while the open actor-context work explicitly leaves persisted attribution and enforcement for follow-up. Maintained external implementations are useful prior art and deployment options, but they do not satisfy the missing native cross-backend contract.

## What This Changes

Add framework-derived trust and provenance metadata to persistent memories, with configurable retention, review, isolation, and retrieval-influence policies.

## Best Possible Solution

Choose the recommended memory architecture, reuse lessons from the cited external schemas, land generic framework-controlled provenance plumbing, then add an additive persisted provenance/review contract and explicit retention-versus-influence enforcement with migrations and cross-backend tests.

## Risks / Open Questions

- A one-backend implementation could create incompatible trust semantics across builtin memory, QMD, Active Memory, Memory Wiki, and external memory plugins.
- Adding trust configuration or persistent columns before selecting the recommended memory path could lock in defaults and migrations that are difficult to reverse.
- Trust must be assigned from framework-controlled channel and tool provenance; model-authored memory content must not be able to self-declare a higher trust level.
- The proposed numeric influence weighting may imply stronger causal guarantees than retrieval scores can safely provide, so storage eligibility, review state, and planning authority should remain distinct concepts.
