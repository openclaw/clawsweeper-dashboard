## Label Justifications

- `P2`: This is a normal-priority security/session-state architecture feature with source-level evidence but no confirmed emergency exploit, outage, or first-run blocker.
- `impact:security`: The issue targets memory poisoning from untrusted content becoming durable context that can influence later agent behavior.
- `impact:session-state`: The requested trust metadata would change how persistent memory and recall context carry authority across future sessions.

## Summary

Keep open: current main and the latest stable release still lack durable memory trust metadata, trust-policy config, review/expiration gates, and trust-weighted retrieval; the external world-model-mcp adapter is useful prior art but remains MCP-only and does not close the OpenClaw memory contract gap.

## What This Changes

Request durable source-trust tagging for memory entries, with trust-based expiration, review/isolation policy, retrieval weighting, and UI visibility to reduce memory poisoning risk.

## Best Possible Solution

Keep open for maintainer/security design of a SQLite-backed memory provenance and trust contract across memory-core, QMD, session memory, Active Memory, Memory Wiki, and plugin SDK surfaces, using world-model-mcp and AKF as prior art rather than treating them as shipped core behavior.
