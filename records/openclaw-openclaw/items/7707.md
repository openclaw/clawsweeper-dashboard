## Summary

Keep open for maintainer product and security design. Current main has manual authority guidance, source buckets, provenance-adjacent memory features, and external plugin/MCP alternatives, but the default memory contract still lacks framework-authenticated trust metadata and enforceable retention, review, or influence policy.

## What This Changes

Add source-derived trust and provenance metadata to persistent memory, with configurable review, expiration, isolation, and trust-aware retrieval policies.

## Best Possible Solution

Define a small framework-owned provenance envelope separating causal source, reviewer endorsement, retention state, and influence state; propagate it through the memory host SDK and lifecycle hooks, let memory plugins implement storage and ranking, and enforce security-sensitive influence through policy or approval controls rather than prompt weighting alone.

## Risks / Open Questions

- Trust labels are unsafe if the model or memory writer can self-assert them; provenance must derive from framework-controlled ingestion and tool-call context.
- A new persisted trust model affects SQLite data, plugin SDK contracts, QMD and alternative backends, compaction, promotion, and upgrades, so schema and compatibility direction must be chosen before implementation.
- Prompt downweighting alone is not a hard security boundary; influence policy must integrate with approval, tool policy, sandboxing, and review surfaces where actions are security-sensitive.
- External MCP and plugin implementations may solve optional deployments, but relying on one as the default would leave OpenClaw-owned memory, compaction, and cross-backend contracts inconsistent.
