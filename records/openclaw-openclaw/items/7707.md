## Summary

Keep this issue open: current main and the latest stable release still have adjacent memory source labels, untrusted prompt framing, and Memory Wiki provenance, but they do not implement durable memory trust metadata, trust-policy config, review/expiration gates, or trust-weighted retrieval enforcement.

## What This Changes

Request durable memory entries to carry source-based trust metadata and enforce trust policies during memory storage, review, expiration, retrieval, and context injection.

## Best Possible Solution

Define one host-authored durable memory trust/provenance contract, then persist and enforce it consistently across memory-core, QMD, session-memory, Active Memory, Memory Wiki, SDK/config surfaces, docs/UI, migrations, and optional memory plugins.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 can be checked by reading the memory result type, SQLite schema, config schema, tool schema, and retrieval path, all of which lack durable trust metadata and trust-policy enforcement. This is a feature/security gap rather than a failing command reproduction.

## Solution Assessment

Unclear as a concrete implementation plan: source-based trust tagging is the right direction, but the proposed config alone is not enough without maintainer decisions on host-assigned provenance, persistence/migration, plugin SDK compatibility, and retrieval policy.
