- `P2`: This is a normal-priority security/session-state improvement with clear source-level impact but broad product design work rather than an urgent outage or user blocker.
- `impact:session-state`: The requested trust tags would affect durable memory, session recall, context influence, promotion, and long-lived agent state.
- `impact:security`: The issue targets memory poisoning from untrusted web, tool, and third-party content before it can influence later agent behavior.

## Summary

Keep open: current main still lacks native persisted memory trust metadata, trust-policy config, review/expiration gates, or trust-weighted retrieval for the default memory path, so this remains a security/product design item rather than conservative cleanup.

## What This Changes

Add source-derived trust metadata and policies to durable memory so retrieval can filter, downweight, review, and expire untrusted memories.

## Best Possible Solution

Define a maintainer-approved native memory trust/provenance contract, then implement framework-assigned source trust, persisted metadata, migration/SDK support, retrieval-time policy, review/expiration gates, and focused docs/tests across the default and optional memory paths.
