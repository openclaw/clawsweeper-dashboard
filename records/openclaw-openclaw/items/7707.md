## Summary

Keep this issue open: current main and v2026.6.11 still have only source labels, session visibility filtering, Active Memory untrusted framing, and generic temporal decay, not durable per-memory trust metadata, trust-policy config, review gates, expiration by trust tier, or trust-weighted retrieval. The AKF and world-model-mcp comments are useful prior art, but they do not close the native memory-core, QMD, Active Memory, or SDK contract gap.

## What This Changes

The issue requests source-based trust metadata for durable memory, with trust-aware retention, review/isolation policy, and retrieval weighting to reduce memory poisoning risk.

## Best Possible Solution

Keep this open for maintainer-owned security/product design that defines non-forgeable source provenance, durable trust metadata, review and expiration states, retrieval enforcement, and plugin/MCP interoperability without adding a one-off memory-core-only policy.

## Reproduction Assessment

Yes, at source level: current main exposes only memory/session source labels and relevance/age scoring, with no durable trust metadata or trust-policy enforcement. This is not a single failing user-flow repro because the request is for a new security/data-model capability.

## Solution Assessment

No, the issue body's config sketch is useful but not sufficient as the final solution. The best path is a maintainer/security design that decides non-forgeable trust assignment, schema/migration shape, SDK/API contract, retrieval enforcement, UI/docs, and how to reuse or interoperate with AKF and world-model-mcp prior art.
