## Summary

Keep open: current main still has source labels, session visibility checks, and Active Memory untrusted framing, but no native durable memory trust metadata, trust-policy config, review/expiration gates, or trust-weighted retrieval enforcement.

## What This Changes

Issue #7707 requests source-based trust tagging for durable memory so untrusted web, tool, and third-party content cannot influence later agent behavior as ordinary trusted memory.

## Best Possible Solution

Define one host-authored durable memory trust contract and enforce it consistently across memory backends, SDK/config, docs/UI, and migrations while evaluating AKF, Cophy, and world-model-mcp as prior art.

## Reproduction Assessment

Yes, at source level: current main lacks trust metadata and trust-policy enforcement in the memory result type, SQLite schema, config schema, tool schema, and retrieval path.

## Solution Assessment

Unclear as an implementation plan: the requested direction is aligned, but maintainers still need to decide host-assigned trust, source/review axes, schema/migration strategy, plugin SDK compatibility, and enforcement modes.
