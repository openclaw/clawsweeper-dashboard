## Summary

Keep open for a maintainer-owned security and product decision. Current main still lacks a framework-authenticated provenance and persistent trust-policy contract; the open provenance work is a prerequisite, not a replacement for this issue.

## What This Changes

Add source-derived memory provenance, review state, and influence controls so retained untrusted content can be audited without automatically steering later agent reasoning or actions.

## System Context

OpenClaw memory plugins ingest workspace and session material, store searchable records, and return ranked results to agent tools. A trust feature must preserve framework-assigned origin through ingestion and storage, then apply review or influence policy before results enter agent context.

## Architecture Diagram

flowchart LR

  B --> C[Memory ingestion]
  C --> D[Memory storage]
  D --> E[Memory retrieval]
  E --> F[Trust and review policy]
  F --> G[Agent context and actions]

## Best Possible Solution

First land the narrow, framework-assigned immutable origin contract tracked by https://github.com/openclaw/openclaw/issues/42647; then add a small additive builtin-memory policy that separates retained evidence from review and influence authority, with migration and retrieval coverage before considering expiry, scoring, UI, or cross-backend guarantees.
