## Summary

Keep open: current main and v2026.6.11 still have source buckets, citations, session provenance, manual memory guidance, and external prior art, but no native durable trust metadata, review/expiration policy, or trust-weighted retrieval across the default memory path.

## What This Changes

The issue requests native memory trust tagging by source, with persistent trust metadata, configurable expiration/isolation policies, and trust-aware retrieval to reduce memory poisoning risk.

## Best Possible Solution

Define a maintainer-approved memory trust/provenance model that persists non-forgeable source and review metadata through memory-core, QMD, session memory, Memory Wiki bridges, SDK contracts, and retrieval policy, with config/docs/tests and migrations where stored schemas change.

## Reproduction Assessment

Yes, at the source level: the checked contracts and retrieval path have no durable trust metadata or trust-policy gate. This is not a single failing command reproduction; it is a missing native security capability visible across the memory schema, config, SDK result type, and search pipeline.

## Solution Assessment

Unclear as an implementation, because the issue needs product/security design around who assigns trust and how it survives storage, promotion, retrieval, QMD, and plugin boundaries. The best path is not the proposed config or sidecar sketch alone, but a canonical trust/provenance contract with migrations and tests.
