## Label Justifications

- `P1`: The reported overflow-compaction workflow can repeatedly retry without obtaining a fresh session, affecting active cron and agent runs.
- `merge-risk: 🚨 compatibility`: The PR creates a new exported plugin hook API whose availability and deferred failure semantics become an external compatibility contract.

## Summary

Keep this PR open: the latest head appears to address the previously reported lifecycle, scope, subscription, and model-lock defects, but it still introduces an undocumented public plugin contract that needs owner approval, and the supplied rollout evidence does not demonstrate an actual after-compaction reset followed by a successful fresh-session turn.

## What This Changes

The PR adds a deferred, current-session-scoped `resetSession(reason?)` API to successful, resettable after-compaction hook contexts and threads its queue through embedded run, direct, queued, subscription, and native harness compaction paths.

## Best Possible Solution

Ship one owner-approved post-compaction reset contract—current-session-only, unavailable for failed, aborted, or model-locked compactions—with public plugin documentation, contract coverage, and live proof of deferred session rotation plus a successful next turn.
