Keep this PR open: the latest head still allows completed-run usage and model metadata to be written onto freshly reset sessions in the primary reply, queued follow-up, and isolated cron finalization paths, and the submitted live evidence does not show a latest-head reset commit followed by a successful turn on the new session.

## What This Changes

Adds a deferred, current-session-scoped reset API to after-compaction hooks and propagates reset commits through embedded runs, harnesses, gateway compaction, replies, memory flushes, follow-ups, and isolated cron sessions.

## Best Possible Solution

Expose the API only on successful, resettable `after_compaction` contexts with a caller-owned lifecycle queue, make every reset-aware finalizer suppress or separately account for abandoned-run usage/model data, preserve the fresh durable reset row across direct, follow-up, cron, gateway, and harness paths, and prove a real latest-head reset followed by a successful turn.
