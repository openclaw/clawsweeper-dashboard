## Label Justifications

- `P1`: The current ordering can stall or invalidate session reset during real compaction workflows, and the reported overflow loop affects active agent runs.
- `merge-risk: 🚨 compatibility`: The PR introduces a plugin-facing method with unresolved scope and inconsistent availability across compaction implementations.
- `merge-risk: 🚨 session-state`: Flushing while compaction work or its active handle remains live can reset, archive, or clear state at the wrong generation boundary.

## Summary

This remains useful, but the current head is not merge-ready: the queued reset is flushed before the owning compaction lifecycle has fully exited, and the advertised hook API is absent from native compaction emitters. Maintainer confirmation of the permanent plugin contract and stronger after-fix runtime proof are also still required.

## What This Changes

The PR adds a current-session-scoped deferred `resetSession(reason?)` method to embedded hook contexts, wires reset queues into agent and compaction lifecycles, and adds focused regression tests.

## Best Possible Solution

Define `resetSession` as an after-compaction capability owned by one shared compaction lifecycle, queue it against the current session, flush only after active handles and all native follow-up compaction have completed, thread it through every supported compaction emitter, and prove session rotation plus a successful next turn in a real gateway.

## Solution Assessment

No, not in its current form. A shared after-compaction lifecycle owner that flushes only after active-handle release and all native follow-up work is narrower and safer than partially attaching a generic API across embedded hook contexts.

- **[P1] Flush resets only after the compaction owner fully exits:** `src/agents/embedded-agent-runner/compact.queued.ts:930`
  - body: The new `finally` flush still runs inside the queued compaction operation.   - confidence: 0.98

Plugins will see `resetSession` for direct/context-engine compaction and `undefined` for other successful compactions. Thread the same caller-owned queue through those emitters or narrow the public type and documentation to the paths that are intentionally supported.
