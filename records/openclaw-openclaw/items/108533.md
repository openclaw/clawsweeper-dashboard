## Summary

This PR should remain open: it addresses a real compaction failure and resolves several earlier concerns, but the current head still drains one reset queue before its outer lifecycle finishes, exposes the capability beyond after-compaction hooks, and lacks conclusive after-fix runtime proof.

## What This Changes

Adds a deferred, current-session reset API to embedded after-compaction hook contexts across direct, queued, run-owned, native-harness, and final compaction paths.

## Best Possible Solution

Expose resetSession only on after_compaction contexts, carry requests to the true run or compaction owner, drain them after native follow-up work and active handles have cleared, and verify session rotation plus a successful subsequent turn in a real runtime.
