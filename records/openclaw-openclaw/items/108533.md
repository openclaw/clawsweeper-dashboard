## Summary

Keep this PR open: the underlying workflow gap remains on current main, but the latest head still exposes the reset primitive to non-compaction hooks, and the rollout evidence does not demonstrate a completed post-compaction reset after active-run cleanup followed by a successful next turn.

## What This Changes

Adds a current-session-scoped deferred reset API to embedded hook contexts and threads a run-owned reset queue through direct, queued, native-harness, overflow, timeout, and subscription compaction paths.

## Best Possible Solution

Keep a single run-owned deferred queue, expose `resetSession(reason?)` only on successful `after_compaction` contexts, obtain hook-surface approval for that narrow contract, and prove a real compaction-to-reset-to-next-turn sequence with redacted lifecycle logs.
