## Summary

Keep this PR open: the latest branch appears to address the previously identified lifecycle and session-scope defects, but it adds a compatibility-sensitive plugin hook API that still needs owner approval, and the supplied live evidence does not show a completed deferred reset followed by a successful fresh-session turn.

## What This Changes

Adds a current-session-scoped deferred `resetSession(reason?)` API to successful, unlocked `after_compaction` hook contexts, threads lifecycle-owned reset queues through embedded compaction paths, and adds regression coverage.

## Best Possible Solution

Expose the method only on successful, unlocked `after_compaction` contexts, keep reset execution owned by the outer lifecycle, explicitly document that the return value acknowledges queueing rather than reset completion, and prove session rotation plus the next fresh turn on a real gateway.
