The PR adds a deferred, current-session-scoped reset API to embedded-agent hook contexts and threads reset requests through run, direct-compaction, and context-engine compaction lifecycles.

- **[P1] Scope resetSession to after-compaction hooks:** `src/agents/embedded-agent-runner/run-orchestrator.ts:249-253`
  - body: This shared context is passed to ordinary run hooks, so the API can queue a session reset after hooks such as `before_agent_reply`, not only after successful compaction. This prior blocker remains: restrict the capability to the approved hook type unless maintainers explicitly adopt and document the broader lifecycle contract.
  - confidence: 0.96
- **[P1] Flush after the native follow-up compaction:** `src/agents/embedded-agent-runner/compact.queued.ts:930`
  - body: The context-engine after-hook flush runs before the optional native `compactAfterContextEngine` pass immediately below it. A requested reset can replace the session and clear runtime state before that follow-up finishes, so carry the request outward and drain it after the secondary compaction completes.
  - confidence: 0.97
- **[P1] Flush after the active compaction handle clears:** `src/agents/embedded-agent-runner/compact.queued.ts:930`
  - body: Manual compaction still has an active embedded-run handle when this flush calls the Gateway reset service. Reset cleanup waits for that same handle, which cannot clear until this call returns, so the request can stall or fail as still active; the wrapper must drain only after clearing its handle.
  - confidence: 0.98
- **[P2] Provide resetSession on every supported compaction path:** `src/plugins/hook-types.ts:290-292`
  - body: The new public context type advertises `api.resetSession`, but native harness after-compaction emitters still construct contexts without it. Plugins will therefore see the API on direct/context-engine compactions and lose it on native compactions; wire the same queued API through those emitters or narrow the declared contract.
  - confidence: 0.95
