## Summary

Keep open: the latest head resolves the earlier arbitrary-key, active-run, hook-scope, and asynchronous dispatch findings, but a sibling native-harness path still exposes `resetSession()` for model-locked sessions even though the gateway refuses that reset. The new plugin contract also needs owner approval and public documentation, and the rollout evidence does not yet demonstrate a completed deferred reset and successful next turn.

## What This Changes

The PR adds a current-session-scoped deferred `resetSession(reason?)` API to after-compaction hook contexts and threads reset requests through embedded run, direct, queued, context-engine, native-harness, and subscription compaction paths.

## Best Possible Solution

Expose `resetSession()` only on successful after-compaction contexts whose session is resettable, route every compaction emitter through one lifecycle-owned queue drained after hook completion and active-handle release, document the exact plugin contract, and prove session rotation followed by a successful next turn.
