## Summary

Keep open: the current head still exposes `resetSession` from native-harness compaction contexts without a caller-owned lifecycle queue, allowing the helper to flush against its own active run; the new plugin contract also needs owner approval and final-head behavior proof.

## What This Changes

The PR adds a deferred, current-session-scoped reset API to successful after-compaction hook contexts across embedded, native-harness, Copilot, Codex, manual, preflight, and Gateway compaction paths.

## Best Possible Solution

Expose the reset capability only when core has supplied a canonical session key, a successful unlocked compaction result, and a caller-owned lifecycle queue with a stale-session guard; otherwise omit the API, document the plugin contract, and prove an actual reset plus successful next turn on the final head.
