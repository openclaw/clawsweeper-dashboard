## Summary

Keep this PR open, but it is not merge-ready: the proposed hook calls the normal Gateway reset service from inside the active embedded run, causing that service to abort and wait for the same run that is awaiting the hook; the API also permits resetting an arbitrary session key rather than the current hook session. The focused tests mock the reset service, so they do not exercise either failure. ([formatika.de](https://www.formatika.de/mobile.jsp?content=source&detail=products%2FSources%2Fformale+Sprachen%2FJAVA%2Fopenclaw%2Fsrc%2Fgateway%2Fsession-reset-service.ts))

## What This Changes

The PR adds a `resetSession` API to embedded-agent hook contexts, connects it to the Gateway session-reset service across compaction and run contexts, and adds mocked regression coverage.

## Best Possible Solution

Expose a current-session-bound reset request that is queued until the active embedded run and hook dispatch have fully exited, then execute the normal reset lifecycle with focused self-wait, cross-session isolation, and next-turn regression tests plus redacted live proof.
