## Summary

This PR remains useful because current main does not provide the requested after-compaction reset capability, but it is not merge-ready: the local reset queue can drain before caller-owned compaction bookkeeping finishes, the live proof does not show a completed reset and successful continuation, and the new plugin contract still needs owner confirmation.

## What This Changes

Adds a current-session-scoped `resetSession(reason?)` API to successful after-compaction hook contexts, defers requests through embedded and native compaction lifecycles, and adds regression coverage for queueing, scope, and locked sessions.

## Best Possible Solution

Expose the API only for successful, model-unlocked after-compaction hooks; bind it to the current session; carry the request to the outermost lifecycle owner; drain only after active handles and all caller compaction bookkeeping are complete; then cover the public contract and provide a redacted live reset-and-next-turn transcript.
