## Label Justifications

## Summary

Keep this PR open for a compaction-hook owner decision and stronger lifecycle proof. The latest head appears to resolve the previously reported scope and queue-ordering defects, but it establishes a new public plugin capability that can rotate session state and the supplied rollout evidence does not yet demonstrate an actual deferred reset followed by a successful next turn.

## What This Changes

Adds a current-session-scoped `resetSession(reason?)` API to successful embedded `after_compaction` hook contexts, queues requests until the owning lifecycle exits, and extends coverage across direct, context-engine, overflow, native-harness, and subscription compaction paths.

## Best Possible Solution

Approve and ship a single documented, current-session-only `after_compaction` contract only after proving that a successful real compaction queues exactly one reset, waits for all hook work and active handles to finish, rotates the intended session, and permits the next turn across the supported built-in and native-harness paths.
