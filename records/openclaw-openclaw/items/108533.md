## Summary

This PR addresses a real compaction-recovery use case and resolves several earlier lifecycle-order defects, but it is not merge-ready: the reset capability remains exposed through general embedded-run hook contexts, the queue helper pulls the compaction dependency graph into ordinary turns, and the rollout evidence does not demonstrate an actual deferred session rotation followed by a successful next turn.

## What This Changes

The PR adds a current-session-scoped deferred reset API to embedded hook contexts and threads reset queues through compaction, native-harness, overflow, timeout, and embedded-run lifecycle paths.

## Best Possible Solution

Expose resetSession only on after_compaction contexts, place the API and queue implementation in a small dependency-leaf module, flush through the single owning lifecycle after active handles and native follow-up compaction settle, and prove a real compaction-to-reset-to-next-turn sequence with redacted session identifiers.
