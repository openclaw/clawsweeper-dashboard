## Summary

Keep this PR open: the reported lifecycle gap is credible, but the current head still exposes reset capability outside compaction, can execute multiple resets for one lifecycle, lacks proof of an actual successful deferred reset, and adds a plugin contract that needs owner approval.

## What This Changes

The PR adds a current-session-scoped deferred reset API to embedded hook contexts and threads reset queues through run, direct, queued, context-engine, subscription, and harness compaction paths.

## Best Possible Solution

Expose the capability only on an explicitly approved after-compaction context, coalesce each lifecycle to one current-session reset with defined reason precedence, flush after all owning run and compaction handles clear, and prove session rotation plus a successful next turn.
