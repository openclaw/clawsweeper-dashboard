## Summary

Keep this PR open: it addresses a real compaction failure, but the latest head still exposes the reset capability beyond after-compaction hooks and can flush a standalone compaction reset while that same lifecycle remains registered active. The submitted runtime evidence shows deployment and removal of the old warning, but not a completed reset followed by a successful fresh-session turn.

## What This Changes

The PR adds a current-session-scoped deferred reset API to embedded hook contexts and threads reset queues through embedded run, context-engine, native harness, and final compaction paths.

## Best Possible Solution

Expose resetSession only on explicitly supported after_compaction contexts, make the outermost run or standalone compaction lifecycle own and flush the queue after its active handle is released, and prove a real reset followed by a successful next turn.
