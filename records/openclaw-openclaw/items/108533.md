## Summary

Keep this PR open: it addresses a real compaction-recovery gap and resolves several earlier lifecycle findings, but the latest head still has two blocking implementation defects, its new public plugin contract needs owner approval, and the rollout evidence does not demonstrate an actual successful deferred reset followed by a useful next turn.

## What This Changes

Adds an after-compaction-only, current-session-scoped `ctx.api.resetSession(reason?)` API, queues reset requests until the owning embedded lifecycle exits, threads the queue through direct, context-engine, subscription, and native compaction paths, and adds regression tests.

## Best Possible Solution

Approve a narrow after-compaction-only current-session reset contract, move its queue/API into a dependency-light leaf module, gate every emitter on a resettable lifecycle including model-locked native sessions, add parity coverage, and require a redacted live trace showing reset execution after teardown and a successful next turn.
