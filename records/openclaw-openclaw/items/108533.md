## Summary

Keep open: the earlier arbitrary-session and active-run reset hazards are substantially addressed, but the current head still exposes reset after unsuccessful subscription compactions, adds a heavy compaction dependency to every embedded run, and lacks proof of an actual deferred reset followed by a successful next turn.

## What This Changes

The PR adds a current-session-scoped deferred reset API to embedded after-compaction hook contexts and threads the reset queue through direct, context-engine, native-harness, and subscription compaction paths.

## Best Possible Solution

Approve a narrowly documented after_compaction-only API, expose it only after confirmed successful compaction, move the queue/API into a dependency-light leaf module, preserve run-owned post-exit flushing across every compaction path, and prove session rotation plus a successful next turn on a real gateway.
