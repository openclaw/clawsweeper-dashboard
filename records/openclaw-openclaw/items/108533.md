## Label Justifications

- `P1`: The shared hook exposure can rotate session state after a real agent turn, creating an urgent session-workflow risk if used outside compaction.
- `merge-risk: 🚨 compatibility`: The PR adds a public PluginHookAgentContext method whose permanent phase scope and semantics have not been approved.
- `merge-risk: 🚨 session-state`: A reset requested from a pre-run hook can execute after the turn and replace the session containing newly produced state.

## Summary

Keep this PR open: the revised head resolves the two earlier design blockers, but it exposes session reset through the shared run-hook context, allowing non-compaction hooks to rotate session state after a completed turn. The API scope needs narrowing or explicit maintainer approval, and the contributor still needs real runtime proof.

## What This Changes

The PR adds a current-session-scoped reset API to embedded hook contexts, queues reset requests until lifecycle cleanup, and adds mocked compaction and overflow-path regression coverage.

## Best Possible Solution

Keep the deferred, current-session-bound queue, but expose resetSession only to after_compaction hooks unless maintainers explicitly approve a broader hook contract; then prove a real compaction, deferred reset, and successful fresh-session turn.
