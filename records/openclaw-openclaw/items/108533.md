- `merge-risk: 🚨 session-state`: The new hook method directly rotates persisted session identity from compaction and run callbacks.

- `merge-risk: 🚨 compatibility`: The PR introduces a new shared plugin hook API before its permanent target and execution semantics are confirmed.

## Summary

Keep this draft open, but do not merge the current implementation: the reset bridge is invoked from callbacks running inside the embedded run that the gateway reset service then waits to terminate, so the intended current-session path can stall and fail.

## What This Changes

The PR adds `PluginHookAgentContext.api.resetSession`, connects it to the gateway session-reset service in embedded run and compaction contexts, and adds mocked regression coverage.

## Best Possible Solution

Expose a session-bound reset request that derives its target from trusted hook context, queues the mutation until the active hook/run and session lane have exited, and prove the complete compaction-to-new-session transition in a real embedded-agent run.

## Solution Assessment

No; directly awaiting the gateway reset service inside active-run hooks is lifecycle-incompatible, and a trusted current-session-bound deferred request is narrower and safer.
