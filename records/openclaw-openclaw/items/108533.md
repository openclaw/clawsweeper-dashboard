## Summary

Keep open: the underlying overflow/reset problem is credible, but the current head still exposes an unapproved plugin contract across overly broad hook contexts and drains reset requests before every owning compaction lifecycle has safely exited. The supplied rollout evidence also does not yet demonstrate an actual deferred reset, session rotation, and successful next turn.

## What This Changes

Adds a current-session-scoped `resetSession(reason?)` plugin hook API, queues reset requests for deferred execution across embedded run and compaction paths, and adds regression tests.

## Best Possible Solution

Define one narrowly scoped `after_compaction` reset contract, carry its current-session request to the outermost lifecycle owner, and drain it only after all context-engine, native harness, compaction, and embedded-run handles have exited; then prove session rotation and a successful continuation on a real gateway.
