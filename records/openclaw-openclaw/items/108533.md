## Summary

Keep this PR open: it addresses a real lifecycle gap, but the current head still exposes session reset to non-compaction hooks, adds compaction-module import fanout to every embedded run, and lacks positive live proof that a deferred reset completes after cleanup and permits a successful next turn.

## What This Changes

Adds a current-session-scoped deferred reset API to embedded hook contexts, threads reset queues through compaction and run lifecycles, and adds regression tests for reset ordering and session binding.

## Best Possible Solution

Move the reset API and queue into a small leaf module, expose it only to `after_compaction` contexts, keep one lifecycle-owned queue that flushes after all run/native-compaction cleanup, and demonstrate a real hook-triggered reset followed by a successful fresh-session turn.
