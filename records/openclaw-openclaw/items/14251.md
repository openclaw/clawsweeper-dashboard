## Label Justifications

- `P2`: This is a normal-priority macOS gateway lifecycle gap with real operational impact, limited platform scope, and pending product/security decisions.
- `impact:security`: System LaunchDaemon lifecycle support crosses elevated privilege, root-owned service metadata, execution-user, sudo/operator flow, and durable environment-boundary choices.
- `impact:crash-loop`: A KeepAlive LaunchDaemon outside CLI lifecycle control can keep restarting or holding the gateway port after user-scope commands report success.
- `maturity:stable`: The affected `macos-gateway-host` Gateway Service Lifecycle surface is part of an M4 Stable maturity feature in `qa/maturity-scores.yaml`.

## Summary

Keep open. Current main and v2026.6.11 still manage macOS gateway stop/uninstall through the user LaunchAgent path and `gui/<uid>` launchd domain; `gateway status --deep` can discover extra system services, but it does not make `/Library/LaunchDaemons` the managed lifecycle target, and the open duplicate-manager PRs intentionally cover a narrower install/restart guard.

## What This Changes

Request system-level macOS LaunchDaemon detection and lifecycle handling for gateway stop, uninstall, and status so CLI results match a running `/Library/LaunchDaemons` service.

## Best Possible Solution

Define one explicit macOS launchd user/system scope contract across install, status, stop, uninstall, doctor, docs, and tests, keeping the user LaunchAgent as the safe default and adding only an audited explicit LaunchDaemon path or guidance flow.

## Reproduction Assessment

Yes, at source level. Current main still resolves Darwin gateway lifecycle through the LaunchAgent registry, user LaunchAgents plist path, and `gui/<uid>` launchctl calls; I did not run a live macOS LaunchDaemon scenario in this read-only review.

## Solution Assessment

No, not as a one-off `--system` flag sketch. The maintainable solution is a shared launchd scope model covering privilege, execution user, coexistence, lifecycle, status, doctor, docs, and tests.
