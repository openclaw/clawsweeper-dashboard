## Summary

Keep open. Current main and the latest release still route macOS gateway stop/uninstall through the user LaunchAgent path and GUI launchd domain; system LaunchDaemon discovery exists only as diagnostics, so the lifecycle gap remains and needs maintainer product/security direction.

## What This Changes

The issue requests macOS gateway stop, uninstall, and status lifecycle handling for system-level LaunchDaemons under `/Library/LaunchDaemons`.

## Best Possible Solution

Define one explicit macOS launchd user/system scope contract across install, status, stop, uninstall, doctor, docs, and tests, keeping user LaunchAgent as the safe default and adding only an audited explicit LaunchDaemon path or guidance flow.

## Reproduction Assessment

Yes, at source level. Current main still resolves Darwin gateway lifecycle through the LaunchAgent registry, user LaunchAgents plist path, and `gui/<uid>` launchctl calls; I did not run a live macOS LaunchDaemon scenario in this read-only review.

## Solution Assessment

No, not as a one-off stop/uninstall flag sketch. The maintainable solution is a shared launchd scope model covering privilege, execution user, coexistence, lifecycle, status, doctor, docs, and tests.
