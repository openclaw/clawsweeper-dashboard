## Label Justifications

- `P2`: This is a real macOS gateway lifecycle gap with operational impact, but it is limited to a system LaunchDaemon setup and needs maintainer direction before implementation.
- `impact:security`: System LaunchDaemon support crosses privileged launchd installation/removal, root-owned service metadata, execution-user selection, sudo/operator flow, and durable environment boundaries.
- `impact:crash-loop`: A KeepAlive LaunchDaemon outside CLI lifecycle control can keep restarting or holding the gateway port after user-scope stop/uninstall appears to succeed.
- `maturity:stable`: The affected macos-gateway-host Gateway Service Lifecycle surface is scored M4 Stable in qa/maturity-scores.yaml.

## Summary

Keep open. Current main and the latest release still route macOS gateway stop/uninstall through the user LaunchAgent path and GUI launchd domain; system LaunchDaemon discovery is diagnostic only, so the lifecycle gap remains and needs maintainer product/security direction.

## What This Changes

Request system-level macOS LaunchDaemon detection and lifecycle handling for gateway stop, uninstall, and status so CLI output matches the actual running service.

## Best Possible Solution

Define one explicit macOS launchd user/system scope contract across install, status, stop, uninstall, doctor, docs, and tests, keeping the user LaunchAgent as the safe default and adding only an audited explicit LaunchDaemon path or guidance flow.
