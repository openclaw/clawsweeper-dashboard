## Label Justifications

- `P2`: This is a real macOS gateway lifecycle gap with operational impact, but it is limited to system LaunchDaemon setups and needs maintainer direction before implementation.
- `impact:security`: System LaunchDaemon lifecycle support crosses privileged launchd service ownership, root-owned metadata, execution-user selection, sudo/operator flow, and durable environment boundaries.

- `maturity:stable`: The affected `macos-gateway-host` Gateway Service Lifecycle surface is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open. Current main and v2026.6.11 still target macOS gateway stop/uninstall at the user LaunchAgent/gui domain, while the remaining system LaunchDaemon lifecycle behavior is privilege-sensitive and needs maintainer direction.

## What This Changes

The issue requests macOS gateway stop/uninstall support that detects and handles system-level `/Library/LaunchDaemons` gateway services instead of reporting user LaunchAgent success while a system daemon remains active.

## Best Possible Solution

Define one shared macOS launchd user/system scope contract across install, status, stop, uninstall, doctor, docs, and tests, keeping the user LaunchAgent as the safe default and adding only an audited explicit LaunchDaemon path or guidance flow.
