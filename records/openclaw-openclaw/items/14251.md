- `P2`: This is a real macOS gateway lifecycle gap with operational impact, but it is limited to system LaunchDaemon setups and needs maintainer direction before implementation.
- `impact:security`: System LaunchDaemon support crosses privileged launchd installation/removal, root-owned service metadata, execution-user selection, sudo/operator flow, and durable environment boundaries.

- `maturity:stable`: The affected macos-gateway-host Gateway Service Lifecycle surface is scored M4 Stable in qa/maturity-scores.yaml.

## Summary

Keep open. Current main and the latest release still route macOS gateway stop/uninstall through the user LaunchAgent path and gui launchd domain; system LaunchDaemon discovery is diagnostic only, and the open related PRs address a narrower duplicate-install guard rather than this lifecycle contract.

## What This Changes

The issue asks OpenClaw to make macOS gateway stop, uninstall, and status detect or safely handle system-level LaunchDaemons in addition to user LaunchAgents.

## Best Possible Solution

Define one explicit macOS launchd user/system scope contract across install, status, stop, uninstall, doctor, docs, and tests, keeping the user LaunchAgent as the safe default and adding only an audited explicit LaunchDaemon path or guidance flow.
