## Label Justifications

- `P2`: This is a real macOS gateway lifecycle gap with operational impact, but it is limited to system LaunchDaemon setups and needs maintainer direction before implementation.
- `impact:security`: System LaunchDaemon lifecycle support crosses privileged launchd service ownership, root-owned metadata, execution-user selection, sudo/operator flow, and durable environment boundaries.
- `impact:crash-loop`: A KeepAlive LaunchDaemon outside CLI lifecycle control can keep restarting or holding the gateway port after user-scope stop/uninstall appears to succeed.
- `maturity:stable`: The affected macOS Gateway host Gateway Service Lifecycle surface is scored M4 Stable in qa/maturity-scores.yaml.

## Summary

Keep open. Current main and v2026.6.11 still manage macOS gateway stop/uninstall through the user LaunchAgent path and gui launchd domain; system LaunchDaemon discovery is diagnostic only, and the remaining work needs an explicit privileged-service contract.

## What This Changes

Request to make macOS gateway stop/uninstall detect and safely handle system-level LaunchDaemons instead of only user LaunchAgents.

## Best Possible Solution

Define one explicit macOS launchd user/system scope contract across install, status, stop, uninstall, doctor, docs, and tests, keeping the user LaunchAgent as the safe default and adding only an audited explicit LaunchDaemon path or guidance flow.

Rationale: The remaining work decides sudo/operator UX, root-owned plist mutation, execution user, service environment durability, and coexistence between user LaunchAgents and system LaunchDaemons, so automation should not choose the security boundary alone.

- **Full managed LaunchDaemon mode:** Add first-class install/status/start/stop/uninstall support for LaunchDaemons after owner review accepts the larger privileged-service surface.

No, not as a one-off --system flag sketch. The maintainable solution is a shared launchd scope model covering privilege, execution user, coexistence, lifecycle, status, doctor, docs, and tests.
