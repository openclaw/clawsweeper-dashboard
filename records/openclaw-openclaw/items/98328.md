## Summary

The current head still gives `__openclaw.senderLabel` first precedence even though the merged persistence contract only establishes `senderId`, `senderName`, and `senderUsername`; that keeps the prior P1 identity-trust finding open and requires contract-owner confirmation before merge.

## What This Changes

The PR changes CLI reseed-history rendering to label user turns with sanitized sender metadata from the persisted `__openclaw` envelope and adds fallback, injection, and compatibility tests.

## Best Possible Solution

Render the immutable `User` role with a single-line label derived only from the approved `__openclaw.senderName`, `senderUsername`, and `senderId` contract; add `senderLabel` only through a separately approved producer and trust contract.
