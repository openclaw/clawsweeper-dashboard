## Summary

Keep this PR open: it addresses the still-relevant attribution gap, but its new model-visible label sanitizer permits Unicode line separators that can forge additional transcript lines; after that narrow repair, acceptance of sender identity in reseed context remains a security-boundary decision.

## What This Changes

The PR renders CLI session-history user turns as `User (<sender>): …` by reading `senderName`, `senderUsername`, and `senderId` from the persisted `__openclaw` envelope.

## Best Possible Solution

Broaden the single-line sender-label sanitizer to cover CR, LF, `U+2028`, and `U+2029`, add focused regressions, then have the session-transcript owner explicitly accept this model-visible attribution format.
