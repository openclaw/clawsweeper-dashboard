## Summary

Keep open: current main and the latest release support explicit ordered fallbacks only, while provider-family wildcard/auto fallback remains unimplemented. The open catalog-derived fallback PR is related but only partial, so this needs maintainer product direction rather than cleanup close.

## What This Changes

Request provider-family-aware automatic model fallback such as wildcard or auto model refs, with optional provider-priority lists before cross-provider routers.

## Best Possible Solution

Define one canonical provider-family fallback contract, probably using current provider ids such as `openai/*`, then implement it through the existing model fallback resolver, config schema, docs, and upgrade-safe tests without reviving `openai-codex` as a live provider surface.
