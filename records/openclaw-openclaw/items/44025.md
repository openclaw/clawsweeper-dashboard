## Summary

Keep open: current main and the latest release still only support explicit flat model fallback lists, while provider-family wildcard/auto selection and the commenter-proposed `fallbackFamilies` contract remain absent. The related catalog-derived fallback PR is open, conflicting, and proof-blocked, so it is not a safe superseding implementation.

## What This Changes

This issue requests provider-family wildcard/auto model fallback selection so OpenClaw stays within an intended provider or subscription tier before crossing to generic router models; discussion also proposes explicit `fallbackFamilies` groups.

## Best Possible Solution

Keep this open for a maintainer to choose one canonical provider-family fallback contract, then align schema, docs, runtime fallback resolution, fallback notices, tests, and any doctor/config behavior around that contract using canonical `openai/*` model refs.

## Reproduction Assessment

Yes by source inspection: current main only accepts explicit flat fallback arrays and does not expand provider wildcard, auto, grouped-family, or catalog-derived fallback candidates. This is a feature/config request rather than a broken existing contract reproduction.

## Solution Assessment

Unclear as proposed: wildcard/auto refs, catalog-derived fallback, and explicit fallback families are different public contracts. The best solution needs maintainer selection of one predictable provider-routing model before implementation.
