## Summary

Keep open: current main and the latest local release tag still only support explicit flat model fallback lists, while this asks for a broader provider-family wildcard/auto or grouped fallback contract. The related catalog-derived fallback PR is narrower, open, and conflicting, so it is not a safe canonical replacement.

## What This Changes

Request provider-family automatic model fallback so configured provider or subscription intent is preserved when a model slug changes or fails.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, normalization, runtime candidate construction, fallback gates, docs, and focused tests.
