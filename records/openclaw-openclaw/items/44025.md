## Summary

Keep open: current main and v2026.6.11 still expose only explicit flat model fallback lists, while provider-family wildcard/auto selection and the grouped fallback idea from the issue discussion are absent. The related catalog-derived fallback PR is narrower, open, conflicting, and not a safe superseding implementation, so the remaining work needs maintainer product direction rather than cleanup closure.

## What This Changes

The issue requests provider-family wildcard, auto, or grouped model fallback selection so OpenClaw can stay within the intended provider family before crossing to generic routers.

## Best Possible Solution

Pick one maintainer-approved canonical provider-family fallback contract using current provider refs, then align schema, normalization, runtime fallback resolution, embedded fallback gates, docs, and upgrade tests around that contract.
