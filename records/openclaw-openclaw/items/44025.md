## Label Justifications

- `impact:auth-provider`: The issue changes provider/model selection and failover routing when a configured provider model becomes unavailable or renamed.

## Summary

Keep open: current main and v2026.6.11 still only support explicit flat model fallback lists, while this asks for a broader provider-family wildcard/auto or grouped fallback contract. The related catalog-derived fallback PR is narrower, open, and not a safe canonical replacement, so this remains a maintainer product/config-contract decision.

## What This Changes

The issue requests provider-family model fallback selection through wildcard/auto model refs, optional family priority lists, or grouped fallback semantics so failover stays within a user's intended provider before crossing to router models.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability gates, docs, and regression tests.
