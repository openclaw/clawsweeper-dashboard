## Summary

Keep open: current main and v2026.6.11 still expose only explicit flat model fallback lists, while this request asks for a provider-family wildcard/auto or grouped fallback contract. That remaining behavior is real, but choosing the public config and provider-routing semantics needs maintainer product direction rather than an automated cleanup close.

## What This Changes

Requests provider-family wildcard or auto model fallback selection so OpenClaw stays within a chosen provider family before crossing to generic router models.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability gates, docs, and focused regression tests.
