## Summary

Keep open: current main and the latest release still support only explicit flat model fallbacks, while provider-family wildcard/auto selection and grouped fallback semantics remain absent. The related catalog-derived fallback PR is narrower, open, and currently conflicting, so this still needs maintainer product direction.

## What This Changes

Request provider-family model fallback selection so failover can stay within an intended provider or subscription tier before crossing to other providers.

## Best Possible Solution

Have maintainers choose one canonical provider-family fallback contract, then align schema, config normalization, runtime fallback candidate construction, embedded fallback availability checks, docs, and any needed doctor behavior around that contract.
