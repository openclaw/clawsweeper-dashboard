## Summary

Keep open: current main and v2026.6.11 still expose only explicit flat model fallback lists, while this request asks for a broader provider-family wildcard/auto or grouped fallback contract. The related catalog-derived fallback PR is narrower, open, conflicting, and not a safe canonical replacement, so this remains a maintainer product/config decision.

## What This Changes

Requests provider-family model fallback refs such as provider/auto or provider/*, plus optional priority or grouped lists, so failover stays within the intended provider family before cross-provider routers.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract using canonical openai/* refs, then implement it consistently across schema, config normalization, candidate construction, availability gates, docs, and focused tests.
