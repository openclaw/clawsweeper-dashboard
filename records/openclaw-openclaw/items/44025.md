## Summary

Keep open: current main and v2026.6.11 still only support explicit flat model fallback lists, while wildcard/auto provider-family fallback and the commenter’s `fallbackFamilies` shape remain unimplemented. This is useful, but it needs a maintainer product decision because it changes public model-routing and config semantics.

## What This Changes

The issue requests provider-family model fallback using wildcard or auto model selectors so OpenClaw stays within the user’s intended provider before crossing to generic routers.

## Best Possible Solution

Choose one maintainer-approved fallback contract, implement it through the schema/config help/docs/resolver/tests, preserve existing explicit `fallbacks` behavior, and use canonical `openai/*` provider refs rather than reviving `openai-codex/*` routes.

## Reproduction Assessment

Yes at source level: current main and v2026.6.11 only accept and execute flat explicit fallback arrays. This is a missing feature/config contract rather than a reproducible broken existing contract.

## Solution Assessment

Unclear as proposed: wildcard/auto expansion, catalog-derived fallback, and `fallbackFamilies` are different public contracts. The best solution is the one maintainer-approved contract that keeps explicit fallbacks predictable and upgrade-safe.
