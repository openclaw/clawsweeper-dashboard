## Summary

Keep open: current main and v2026.6.11 still support explicit flat model fallback lists, but not provider-family wildcard/auto selection or grouped fallback families. The related catalog-derived fallback PR is narrower, open, and not a safe canonical replacement for the broader config contract requested here.

## What This Changes

Request provider-family model fallback selection, such as wildcard/auto model refs or ordered provider-family fallback groups, so failover stays within the intended provider before crossing to generic routers.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability gates, docs, and regression tests.
