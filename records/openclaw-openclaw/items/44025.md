## Summary

Keep open: current main and v2026.6.11 still support only explicit flat model fallback lists, while provider-family wildcard/auto selection and the commenter-proposed grouped fallback contract remain absent. The related catalog-derived fallback PR is open, narrower, and not merged, so this needs maintainer product direction rather than cleanup closure.

## What This Changes

The issue requests provider-family wildcard or auto model fallback selection so OpenClaw can stay within the user's intended provider tier when model names rotate.

## Best Possible Solution

Have maintainers choose one public provider-family fallback contract using canonical OpenAI model refs, then align schema, normalization, runtime fallback resolution, embedded fallback availability checks, docs, and any needed doctor behavior around that single contract.
