## Summary

Keep open: current main and v2026.6.11 still support only explicit flat model fallback lists, while provider-family wildcard/auto selection and grouped fallback-family semantics remain absent. The related catalog-derived fallback PR is narrower, open, conflicting, and not a safe superseding implementation.

## What This Changes

Requests provider-family wildcard/auto model fallback selection, optionally with ordered provider priority groups, so failover stays within the intended provider or subscription tier before crossing providers.

## Best Possible Solution

Have maintainers choose one canonical provider-family fallback contract using current openai/* model refs, then align schema, normalization, runtime fallback resolution, embedded-run availability checks, docs, and any needed doctor behavior around that contract.
