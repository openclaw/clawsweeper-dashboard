## Summary

Keep open: current main and latest release still only support explicit flat model fallback lists, while provider-family wildcard/auto selection and the commenter-proposed fallback family contract remain absent. The overlapping catalog-derived fallback PR is still open, conflicting, and only partially overlaps this broader request, so it is not a safe superseding implementation.

## What This Changes

Request provider-family model fallback selection such as `provider/auto`, `provider/*`, optional ordered provider-family lists, or equivalent config so OpenClaw stays inside a user's intended provider tier before crossing to generic routers.

## Best Possible Solution

Keep this issue open until maintainers choose one provider-family fallback contract, then align schema, docs, runtime candidate construction, embedded-run fallback availability, and any needed config/doctor migration around that single contract.

## Reproduction Assessment

Yes by source inspection: current main only accepts explicit flat fallback arrays and does not expand provider wildcard, provider-family, or fallback-family candidates. This is a feature/config absence rather than a broken existing contract reproduction.

## Solution Assessment

Unclear as proposed: wildcard/auto refs, catalog-derived fallbacks, and explicit fallback families are competing public contracts. The best path needs maintainer selection of one predictable provider-routing model before implementation.
