## Summary

Keep open: current main and v2026.6.11 still support only explicit flat model fallback lists, while provider-family wildcard/auto selection and the commenter-proposed fallback family contract remain absent. The overlapping catalog-derived fallback PR is only a partial path and is still open with merge-readiness/proof problems, so it cannot close or supersede this broader design tracker.

## What This Changes

Request provider-family wildcard or auto model fallback selection so OpenClaw stays within an intended provider/subscription family before falling back to generic cross-provider routers.

## Best Possible Solution

Keep this open for a maintainer to choose one public fallback contract, then implement it through the existing schema, config normalization, fallback candidate resolver, docs, and upgrade-proof tests.

## Reproduction Assessment

Yes by source inspection: current main and v2026.6.11 only accept and read explicit flat fallback arrays. This is a feature/config contract gap, not a broken existing behavior reproduction.

## Solution Assessment

Unclear as proposed: wildcard/auto expansion, catalog-derived fallback, and fallbackFamilies are different public contracts. The best solution is for maintainers to choose one predictable provider-routing model before implementation.
