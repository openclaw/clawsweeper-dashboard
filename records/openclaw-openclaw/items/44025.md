## Summary

Keep open: current main and v2026.6.11 still only support explicit flat model fallbacks, while this requests a broader provider-family wildcard/auto or grouped fallback contract. The related catalog-derived fallback PR is narrower, open, conflicting, and not a safe canonical replacement, so this remains a maintainer product/config decision.

## What This Changes

Requests provider-family wildcard/auto model fallback selection that tries models within the intended provider before falling back to cross-provider routers.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, normalization, runtime candidate construction, fallback gates, docs, and regression tests while preserving explicit fallback behavior.
