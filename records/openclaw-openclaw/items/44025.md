## Summary

Keep open: current main and v2026.6.11 still only support explicit flat model fallback lists, while provider-family wildcard/auto selection and the related fallbackFamilies proposal remain absent. The open catalog-derived fallback PR is narrower and conflicting, so this needs maintainer product direction rather than cleanup closure.

## What This Changes

Request a provider-family model fallback contract so provider-specific auto/wildcard refs or ordered fallback groups try intended same-family models before crossing to generic routers.

## Best Possible Solution

Have a maintainer choose one public provider-family fallback contract using canonical openai/* refs, then align schema, config normalization, runtime fallback resolution, docs, and any needed doctor behavior around that single contract.
