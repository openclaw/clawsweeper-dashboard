## Summary

Keep open: current main and the latest release still only support explicit flat fallback lists, while provider-family wildcard/auto fallback and grouped fallback-family selection remain absent. The related catalog-derived fallback PR is narrower, open, conflicting, and proof-blocked, so it is not a safe superseding implementation.

## What This Changes

Request provider-family model fallback selection such as `openai-codex/auto` or grouped priority lists so failover stays within the intended provider/tier before crossing to generic routers.

## Best Possible Solution

Keep this as the canonical product-decision issue until maintainers choose one fallback contract and require schema, docs, runtime, upgrade, and provider-routing tests for that contract.

## Reproduction Assessment

Yes by source inspection: current main accepts and executes only explicit flat fallback arrays, so wildcard/auto and grouped fallback requests are observably unsupported without needing a live provider failure.

## Solution Assessment

Unclear: the issue identifies a real gap, but the best fix requires maintainer choice between wildcard/auto selection, grouped fallback families, catalog-derived fallback, or a narrower provider-owned contract.
