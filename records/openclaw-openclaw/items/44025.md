- `impact:auth-provider`: The issue directly concerns provider/model selection and fallback routing when configured provider models fail, change, or disappear.

## Summary

Keep open: current main and v2026.6.11 still expose only explicit flat model fallback lists, while provider-family wildcard/auto selection and the commenter-proposed grouped fallback contract remain unimplemented; the overlapping open PR covers only a narrower catalog-derived approach and is conflicting/not merge-ready.

## What This Changes

Request provider-family-aware model fallback selection, such as `provider/auto`, `provider/*`, or grouped priority lists, so fallback stays within an intended provider/subscription family before crossing to router models.

## Best Possible Solution

Keep this issue open for maintainers to choose one predictable public fallback contract, then implement it through the existing model fallback resolver, schema/docs, and focused upgrade-safe tests.

## Reproduction Assessment

Yes, by source inspection: current main and v2026.6.11 only read explicit fallback arrays from `agents.defaults.model.fallbacks`, and the strict schema does not accept the proposed fields. This is a feature/config request rather than a broken existing contract reproduction.

## Solution Assessment

Unclear as proposed: wildcard/auto expansion, catalog-derived fallback, and explicit fallback families are each plausible but different public contracts. A maintainer should choose the permanent provider-routing model before implementation.
