## Summary

Keep open: current main and v2026.6.11 still only support explicit flat model fallback lists, while this requests a new provider-family wildcard/auto or grouped fallback contract. The related catalog-derived fallback PR is narrower, open, conflicting, and not a safe canonical replacement, so this remains a maintainer product/config-contract decision.

## What This Changes

Requests provider-family auto/wildcard or grouped model fallback selection so failover stays within the intended provider/model pool before crossing to generic routers.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability gates, docs, and focused tests.
