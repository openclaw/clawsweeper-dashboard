## Summary

Keep open: current main and v2026.6.11 still expose only explicit flat model fallback lists, while this asks for a provider-family wildcard/auto or grouped fallback contract. The related catalog-derived fallback PR is narrower and still open, so this remains a public config and provider-routing product decision rather than a cleanup close.

## What This Changes

Request support for provider-family model fallback selection such as wildcard/auto refs, optional ordered provider-family groups, or priority lists before crossing to unrelated router/provider fallbacks.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability gates, docs, and focused tests.
