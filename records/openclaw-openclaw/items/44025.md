- `impact:auth-provider`: The request changes provider/model selection and failover routing when a configured provider model becomes unavailable or renamed.

## Summary

Keep open: current main and the latest release still only support explicit flat fallback lists, while provider-family wildcard/auto selection and the commenter-proposed grouped fallback contract remain absent. The related catalog-derived fallback PR is open, conflicting, and narrower than this issue, so it is not a safe superseding implementation.

## What This Changes

Add provider-family-aware model fallback selection, such as wildcard/auto model refs or ordered fallback families, so stale provider models stay within the user's intended provider before cross-provider fallback.

## Best Possible Solution

Keep this open for a maintainer to choose one public provider-family fallback contract, then align schema, docs, runtime fallback resolution, embedded-run fallback availability, and any needed doctor/config migration behavior around that single contract.

## Reproduction Assessment

Yes, by source inspection: current main accepts only string or { primary, fallbacks } model config and fallback resolution only iterates that flat list. This is a feature/config request rather than a failing current contract reproduction.

## Solution Assessment

Unclear as proposed: wildcard/auto refs, catalog-derived fallback, and explicit fallbackFamilies are different public contracts. The best fix needs maintainer selection of one predictable provider-routing model before implementation.
