## Summary

Keep open: current main and the latest release still expose explicit flat model fallbacks, not provider-family wildcard/auto selection or grouped fallback families. The production-style `fallbackFamilies` comment adds useful design evidence, but this remains a public config/provider-routing product decision rather than conservative cleanup.

## What This Changes

The issue requests provider-family-aware model fallback, such as wildcard or auto model refs and optional ordered provider-family fallback groups, before crossing to generic router/provider fallbacks.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability gates, docs, and focused tests.
