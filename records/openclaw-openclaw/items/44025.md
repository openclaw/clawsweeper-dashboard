## Summary

Keep open: current main and the latest release still support explicit flat model fallback lists, not provider-family wildcard/auto selection or grouped fallback families. The related catalog-derived fallback PR is narrower, open, and conflicting, so this remains a product/config-contract decision rather than cleanup closure.

## What This Changes

The issue requests provider-family wildcard or auto model fallback selection so OpenClaw can stay within a user's intended provider tier before crossing to unrelated routers.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, availability checks, docs, and regression tests.
