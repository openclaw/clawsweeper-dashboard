## Summary

Keep open: current main and v2026.6.11 still only support explicit flat model fallback lists, while provider-family wildcard/auto selection and the commenter-proposed grouped fallback contract remain absent. The related catalog-derived fallback PR is open, narrower, conflicting, and not a safe superseding implementation, so this needs maintainer product direction rather than cleanup closure.

## What This Changes

Request provider-family model fallback selection such as `openai/auto` or grouped fallback families so failover can stay within an intended provider/subscription tier before crossing providers.

## Best Possible Solution

Have a maintainer choose one public provider-family fallback contract, using canonical `openai/*` refs rather than new `openai-codex` routes, then align schema, config normalization, runtime fallback resolution, embedded fallback availability checks, docs, and any needed doctor behavior around that contract.
