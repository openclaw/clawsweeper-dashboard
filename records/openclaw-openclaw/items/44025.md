## Summary

Keep open: current main and v2026.6.11 still implement explicit flat model fallback lists only, while the requested provider-family wildcard/auto fallback and the commenter’s grouped fallback contract remain absent. The related catalog-derived fallback PR is open but narrower and not merge-ready, so it is not a safe superseding implementation.

## What This Changes

The issue requests provider-family wildcard or auto model fallback so OpenClaw stays within an intended provider/model pool before falling back to cross-provider routers.

## Best Possible Solution

Choose one public provider-family fallback contract, then align the config schema, config normalization, runtime candidate construction, embedded-run fallback availability gate, docs, and focused tests around that single contract without confusing catalog visibility wildcards with fallback execution.

## Reproduction Assessment

Yes, by source inspection: current main accepts only string or { primary, fallbacks } model config and runtime fallback construction iterates that flat list. This is a missing feature/config contract rather than a broken documented behavior.

## Solution Assessment

Unclear as proposed: wildcard/auto refs, catalog-derived fallback, and fallbackFamilies are competing public contracts. The best fix needs maintainer selection of one predictable provider-routing model before implementation.
