## Summary

Keep open: current main and the latest release still only support explicit flat model fallback lists, while this requests a broader provider-family wildcard/auto or grouped fallback contract. The related catalog-derived fallback PR is narrower, open, conflicting, and not a safe canonical replacement, so this remains a maintainer product/config decision.

## What This Changes

Request provider-family wildcard/auto or grouped fallback model selection so failover stays within the intended provider or subscription tier before crossing to generic routers.

## Best Possible Solution

Have maintainers choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability checks, docs, and regression tests using canonical openai/* refs.
