## Summary

Keep open: current main and v2026.6.11 still support explicit flat model fallback lists, but not the requested provider-family wildcard/auto or grouped fallback contract. The related catalog-derived fallback PR is narrower, open, and dirty, so this remains a maintainer product/config-contract decision rather than a cleanup close.

## What This Changes

Request provider-family auto/wildcard or grouped fallback model selection so failover stays within the intended provider family before crossing to generic routers.

## Best Possible Solution

Have maintainers choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability gates, docs, and focused regression tests.
