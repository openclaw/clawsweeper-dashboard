## Summary

Keep open: current main still supports explicit flat model fallback lists, not provider-family wildcard/auto selection or grouped fallback families. The closest implementation thread is narrower, open, conflicting, and proof-blocked, so this remains a maintainer product/config-contract decision rather than cleanup closure.

## What This Changes

The issue requests provider-family-aware model fallback such as wildcard or auto model selection, with optional ordered family groups, so OpenClaw stays within a chosen provider or subscription tier before crossing to generic routers.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability gates, protocol/docs, and regression tests.
