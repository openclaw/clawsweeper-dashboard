- `impact:auth-provider`: The issue changes provider/model selection and failover routing when a configured provider model becomes unavailable or renamed.

## Summary

Keep open: current main and v2026.6.11 still support explicit flat model fallback lists, but not provider-family wildcard/auto selection or grouped fallback families. The open catalog-derived fallback PR is narrower and currently conflicting, so it is not a safe canonical replacement for this broader config-contract request.

## What This Changes

Request provider-family wildcard/auto or grouped model fallback selection so OpenClaw stays within the user's intended provider/model pool before crossing to other providers.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability gates, docs, and focused tests.
