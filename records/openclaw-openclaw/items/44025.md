## Summary

Keep open: current main and v2026.6.11 still only support explicit flat fallback lists, while this asks for a broader provider-family wildcard/auto or grouped fallback contract. The related catalog-derived fallback PR is narrower, open, conflicting, and not a safe canonical replacement.

## What This Changes

Request provider-family model fallback selection such as wildcard/auto model refs, optional provider priority lists, or grouped fallback families before crossing to generic router models.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability gates, docs, and regression tests.
