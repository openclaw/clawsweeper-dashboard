## Summary

Keep open: current main and v2026.6.11 still expose only explicit flat model fallback lists, while this issue asks for a broader provider-family wildcard/auto or grouped fallback contract. The related catalog-derived fallback PR is narrower, open, conflicting, and not a safe canonical replacement, so this remains a maintainer product/config-contract decision.

## What This Changes

The issue requests provider-family wildcard or auto model fallback so OpenClaw can stay within a user's intended provider/model family when a configured model stops working.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability gates, docs, and regression tests.
