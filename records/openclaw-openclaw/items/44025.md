## Summary

Keep open: current main and the latest release still support only explicit flat model fallback lists, while provider-family wildcard/auto selection and the commenter-proposed `fallbackFamilies` contract remain absent. The open overlapping PR is conflicting and not merge-ready, so it cannot close or supersede this design tracker.

## What This Changes

The issue requests provider-family-aware model fallback selection using wildcard or auto model references so users stay within the intended provider before crossing to router models.

## Best Possible Solution

Keep this open for a maintainer to choose one public fallback contract, likely by extending the existing explicit fallback resolver to derive provider-family candidates from configured catalogs only under an intentional opt-in or documented provider/plugin capability.

## Reproduction Assessment

Yes by source inspection: current main and the latest release only read explicit fallback arrays from `agents.defaults.model.fallbacks`, and the strict schema does not accept the proposed fields. This is a feature/config request, not a broken existing contract reproduction.

## Solution Assessment

Unclear as proposed: wildcard/auto expansion, catalog-derived fallback, and explicit fallback families are different public contracts. The best fix needs maintainer selection of one predictable provider-routing model before implementation.
