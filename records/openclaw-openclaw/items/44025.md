## Summary

Keep open: current main and v2026.6.11 still support only explicit flat model fallback lists, while provider-family wildcard/auto selection and the commenter-proposed grouped fallback contract are absent. The open catalog-derived fallback PR is narrower and not a safe superseding implementation, so this remains a maintainer product/config decision.

## What This Changes

Request provider-family wildcard/auto model fallback selection, optionally with ordered fallback families, so failover stays inside the intended provider or subscription tier before crossing routers.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract using current openai/* model refs, then align schema, normalization, runtime candidate construction, fallback availability gates, docs, and any needed doctor behavior around that single contract.
