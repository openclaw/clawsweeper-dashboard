## Summary

Keep open: current main and the latest release still expose only explicit flat model fallback lists, while the requested provider-family wildcard/auto selection and the commenter’s fallbackFamilies shape are absent. The open overlapping PR is narrower, conflicting, and proof-blocked, so it is not a safe superseding implementation.

## What This Changes

The issue requests provider-family wildcard or auto model fallback selection for model config strings such as openai-codex/auto or openai-codex/*.

## Best Possible Solution

Have maintainers choose one public fallback contract, then implement it consistently in schema, fallback candidate construction, fallback availability gates, docs, and upgrade guidance.

## Reproduction Assessment

Yes by source inspection: current main and v2026.6.11 only expose explicit flat fallbacks, while provider-family wildcard/auto behavior is absent. This is a feature/config contract gap rather than a failing existing behavior contract.

## Solution Assessment

Unclear as proposed: wildcard/auto suffixes, catalog-derived fallbacks, and fallbackFamilies all address the pain but encode different public routing contracts. Maintainers should choose one predictable contract before implementation.
