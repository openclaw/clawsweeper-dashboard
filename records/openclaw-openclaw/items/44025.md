## Summary

Keep open: current main and the latest release still support explicit ordered fallbacks, but not provider-family wildcard/auto fallback. The related catalog-derived fallback PR partially overlaps, but it is narrower, open, and currently conflicting, so this remains a product/config-contract decision.

## What This Changes

Request provider-scoped wildcard or auto model fallback so OpenClaw can try models within the intended provider family before cross-provider fallbacks.

## Best Possible Solution

Define one maintainer-approved core model-fallback contract that preserves provider/subscription intent, keeps explicit fallbacks strict, and includes schema, docs, and focused fallback-chain tests.
