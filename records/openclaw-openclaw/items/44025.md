## Summary

Keep open: current main and v2026.6.11 still only support explicit flat model fallback lists, while this issue and the follow-up comment ask for provider-family wildcard/auto selection or grouped fallback semantics. The overlapping catalog-derived fallback PR is still open, conflicting, and proof-blocked, so it is not a safe superseding implementation.

## What This Changes

The issue requests provider-family wildcard or auto model fallback so OpenClaw can stay within the intended provider/model family when configured model names change.

## Best Possible Solution

Keep this open for maintainers to choose one public provider-family fallback contract, then align schema, docs, runtime candidate construction, embedded-run fallback availability, and any doctor/config migration behavior around that contract.

## Reproduction Assessment

Yes, by source inspection: current main only accepts explicit flat fallback arrays and does not expand provider wildcard, auto, catalog-derived, or family fallback candidates. This is a feature/config request rather than a broken existing contract reproduction.

## Solution Assessment

Unclear as proposed: wildcard/auto refs, catalog-derived fallback, and explicit fallback families are different public contracts. The best solution needs maintainer selection of one predictable provider-routing model before implementation.
