## Summary

Keep open: current main and the latest release still expose explicit flat fallback lists only, while provider-family wildcard/auto selection and the commenter-proposed `fallbackFamilies` shape remain absent. The related catalog-derived fallback PR is open, conflicting, and only partially overlaps this broader model-routing design request.

## What This Changes

Request provider-family wildcard or auto model fallback selection, optionally with ordered provider-family fallback groups, so model rotations stay inside the intended provider before cross-provider fallback.

## Best Possible Solution

Keep this as the provider-family fallback design tracker until maintainers choose one canonical config contract, then update schema/types, normalization, fallback candidate construction, docs, and focused fallback tests around that contract.

## Reproduction Assessment

Yes at source level: current `main` only accepts and consumes explicit `fallbacks` arrays, so the requested wildcard/auto and `fallbackFamilies` shapes are absent. I did not run a live provider failure because the missing behavior is visible in the schema and resolver source.

## Solution Assessment

Unclear: the request identifies a real gap, but the best fix needs maintainer choice between wildcard provider expansion, ordered fallback-family groups, deriving from configured model catalogs, or improving doctor/setup guidance.
