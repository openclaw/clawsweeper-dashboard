## Summary

Keep open: current main and the latest release still support only explicit flat model fallback lists, while provider-family wildcard/auto selection and the commenter-proposed grouped fallback contract remain absent. The overlapping catalog-derived fallback PR only covers part of this request and is currently conflicting/proof-blocked, so it is not a safe canonical replacement.

## What This Changes

The issue requests provider-family wildcard or auto model fallback selection so users can stay within an intended provider/subscription family before cross-provider fallback.

## Best Possible Solution

Choose one durable public fallback contract, then implement it across schema, docs, model candidate construction, embedded-run fallback availability, and upgrade/doctor behavior as needed.

## Reproduction Assessment

Yes by source inspection: current schema and runtime only support explicit flat fallback lists. This is a feature/config contract gap rather than a broken existing behavior contract.

## Solution Assessment

Unclear as proposed: wildcard/auto provider expansion, catalog-derived fallback, and explicit fallback families are distinct public contracts, so maintainers need to choose the durable routing model first.
