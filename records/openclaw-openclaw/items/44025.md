## Summary

Keep open: current main and the latest release still implement only explicit flat model fallback lists, while provider-family wildcard/auto selection and the commented `fallbackFamilies` contract remain absent. The overlapping catalog-derived fallback PR is open, conflicting, and only partially covers this broader design request, so it cannot supersede the issue.

## What This Changes

The issue requests provider-family wildcard or auto model fallback selection so OpenClaw can stay within a user's intended provider/model family when a configured model becomes unavailable.

## Best Possible Solution

Keep this as a maintainer-owned design item until one predictable public fallback contract is chosen and applied consistently across schema, config normalization, candidate construction, embedded-run fallback availability, docs, and tests.

## Reproduction Assessment

Yes by source inspection: current main and the latest release accept and execute only explicit flat fallback lists, so the requested wildcard/auto and `fallbackFamilies` shapes are absent. This is a feature/config contract gap rather than a broken existing behavior contract.

## Solution Assessment

Unclear as proposed: wildcard/auto selection, catalog-derived fallbacks, and explicit fallback families are different public contracts. The best fix needs maintainer selection of one predictable routing model before implementation.
