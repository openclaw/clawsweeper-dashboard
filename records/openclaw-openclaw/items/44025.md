## Summary

Keep open: current main and the latest release still support only explicit flat model fallbacks, while provider-family wildcard/auto selection and the commenter-proposed grouped fallback contract remain absent. The related catalog-derived fallback PR is narrower, conflicting, and not proof-positive, so this needs maintainer product direction rather than cleanup closure.

## What This Changes

Request provider-family wildcard/auto model fallback selection so failover can stay within the intended provider or subscription tier before crossing to router or other provider fallbacks.

## Best Possible Solution

Have a maintainer choose one public provider-family fallback contract using canonical openai/* model refs, then align schema, normalization, runtime candidate construction, embedded fallback availability checks, docs, and any needed doctor behavior around that single contract.
