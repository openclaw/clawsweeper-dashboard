## Summary

Keep open: current main and v2026.6.11 still only support explicit flat model fallback lists, while provider-family wildcard/auto selection and the grouped `fallbackFamilies` idea from the discussion remain absent. The related catalog-derived fallback PR is open, conflicting, and narrower than this request, so it is not a safe superseding implementation.

## What This Changes

The issue requests provider-family model fallback selection using wildcard or auto model refs, with provider-local fallback behavior before cross-provider routing.

## Best Possible Solution

Have a maintainer choose one public provider-family fallback contract using canonical `openai/*` refs, then align schema, normalization, runtime fallback resolution, docs, tests, and any needed doctor behavior around that contract.
