## Summary

Keep open: current main and v2026.6.11 still expose explicit flat model fallbacks only, while this issue asks for a provider-family wildcard/auto or grouped fallback contract. The related catalog-derived fallback PR is narrower, currently conflicting, and does not safely supersede the broader product decision.

## What This Changes

The issue requests provider-family-aware model fallback using wildcard/auto model refs, optional ordered provider priority lists, or fallback families before crossing to generic routers.

## Best Possible Solution

Select one canonical family-aware fallback contract, then implement it across schema, config normalization, runtime candidate construction, fallback availability checks, docs, and focused regression tests while preserving explicit flat fallbacks.
