## Summary

Keep open: current main and v2026.6.11 still only support explicit flat model fallback lists, while provider-family wildcard/auto selection and the related grouped fallback-family contract are absent. This should remain a maintainer product decision because the design affects provider routing, auth/profile behavior, and cost or quality expectations.

## What This Changes

Request provider-family model fallback selection, such as wildcard or auto model refs and optional ordered provider-specific fallback groups.

## Best Possible Solution

Have a maintainer choose one public provider-family fallback contract using canonical openai/* model refs, then align schema, normalization, runtime fallback resolution, availability gates, docs, and any needed doctor behavior around that single contract.
