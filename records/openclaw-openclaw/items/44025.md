## Summary

Keep open: current main still supports explicit flat fallback lists and provider wildcard allowlists, but not provider-family wildcard/auto fallback or grouped fallback-family semantics. The related catalog-derived fallback PR overlaps the problem but is narrower, open, conflicting, and previously reviewed as not merge-ready.

## What This Changes

The issue requests provider-family auto or wildcard model fallback so OpenClaw can stay within the intended provider/model family when a configured model changes or fails.

## Best Possible Solution

Keep this as the provider-family fallback design tracker until maintainers choose the canonical contract and land schema, runtime, docs, and focused fallback tests around that contract.

## Reproduction Assessment

Yes. Source inspection shows current code and docs expose explicit flat fallback lists and provider wildcard allowlists, but not provider-family wildcard/auto or grouped fallback semantics; this is a missing feature/config contract rather than a failing bug reproduction.

## Solution Assessment

Unclear as proposed. The goal is valid, but wildcard/auto expansion, explicit fallback families, and catalog-derived fallbacks are distinct public contracts with different provider, cost, auth, and upgrade implications.
