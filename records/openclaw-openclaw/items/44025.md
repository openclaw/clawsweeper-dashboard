## Summary

Keep open: current main and v2026.6.11 still support explicit flat model fallback lists and provider wildcard visibility, but not wildcard/auto fallback expansion or the commented `fallbackFamilies` contract. The related implementation PR only covers one catalog-derived option and is currently conflicting/proof-blocked, so this remains a maintainer product decision.

## What This Changes

Request provider-family-aware model fallback so refs such as `openai/auto` or `openai/*` stay within the intended provider/model pool before cross-provider fallback.

## Best Possible Solution

Have a maintainer choose one durable core contract for provider-family fallback, then implement it across schema/types, config normalization, fallback candidate construction, embedded-run availability checks, docs, and focused regression tests without creating competing fallback sources.

## Reproduction Assessment

Yes, by source inspection: current main accepts only explicit flat `agents.defaults.model.fallbacks` and does not expand provider wildcard, `auto`, or grouped fallback-family candidates. This is a missing feature/config contract rather than a broken existing documented behavior.

## Solution Assessment

Unclear as proposed: wildcard/auto refs, catalog-derived fallback, and explicit fallback families are different public contracts. The best path is a maintainer-selected provider-family fallback model with one source of truth across config, runtime, docs, and tests.
