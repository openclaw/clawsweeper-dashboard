## Summary

Keep open: current main and v2026.6.11 still only support explicit flat model fallback lists, while provider-family wildcard/auto selection and the commenter-proposed fallbackFamilies contract remain absent. The open catalog-derived fallback PR is narrower, currently conflicting, and not a safe superseding implementation, so this needs maintainer product direction rather than cleanup closure.

## What This Changes

Request provider-family model fallback selection so OpenClaw can stay within a user's intended provider or subscription tier when a configured model becomes unavailable or renamed.

## Best Possible Solution

Have maintainers choose one canonical provider-family fallback contract using current openai/* model refs, then align schema, normalization, runtime fallback resolution, embedded fallback gates, docs, and any needed doctor behavior around that single contract.
