## Label Justifications

- `impact:auth-provider`: The request changes provider/model selection and failover routing when a configured provider model becomes unavailable or renamed.

## Summary

Keep open: current main supports explicit flat fallback lists and provider/* catalog visibility, but it does not implement provider-family wildcard/auto or grouped fallback semantics. This remains a product/config-contract decision because the related catalog-derived fallback PR is narrower, open, conflicting, and not a safe canonical replacement.

## What This Changes

Request provider-family automatic model failover via wildcard/auto model refs or ordered fallback families so provider-specific pools are exhausted before cross-provider fallback.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability gates, docs, and focused tests, using canonical openai/* refs for Codex-backed OpenAI routes.
