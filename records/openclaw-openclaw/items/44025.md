## Summary

Keep open: current main and the latest release still expose only explicit flat model fallbacks for agent text runs, while provider-family wildcard/auto selection and the commenter-proposed fallback-family contract are absent. The overlapping catalog-derived fallback PR is still open and uses a different opt-in config shape, so it is not a merged or safe superseding implementation.

## What This Changes

Request provider-family wildcard or auto model fallback selection, such as trying models within an intended provider family before falling back to cross-provider routers.

## Best Possible Solution

Keep this open for a maintainer to choose one provider-family fallback contract, then align schema, docs, runtime fallback resolution, embedded-run availability checks, and any needed doctor/config migration behavior around that single contract.

## Reproduction Assessment

Yes by source inspection: current main accepts only explicit flat fallback arrays and does not expand provider wildcard, auto, or fallback-family candidates. This is a feature/config request rather than a broken existing behavior contract.

## Solution Assessment

Unclear as proposed: wildcard/auto refs, catalog-derived fallback, and explicit fallbackFamilies are different public contracts. The best solution needs maintainer selection of one predictable provider-routing model before implementation.
