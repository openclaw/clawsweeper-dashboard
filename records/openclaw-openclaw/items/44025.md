## Summary

Keep open: current main and v2026.6.11 still only support explicit flat model fallback lists, while this request needs a broader provider-family fallback contract. The related catalog-derived fallback PR is narrower, still open, and not a safe canonical replacement for the wildcard/auto or grouped-family design.

## What This Changes

The issue requests provider-family wildcard or auto model fallback so OpenClaw can stay within a user's intended provider/model pool when a configured model becomes unavailable.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability gates, docs, and regression tests.
