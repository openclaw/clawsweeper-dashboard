## Summary

Keep open: current main and v2026.6.11 still support explicit flat model fallback lists only, while this requests a broader provider-family wildcard/auto or grouped fallback contract. The only open related PR is narrower, conflicting, and not a safe canonical replacement for this product/config decision.

## What This Changes

Request provider-family model fallback selection via wildcard/auto refs or grouped fallback priorities so failover stays within the intended provider or subscription tier before cross-provider routers.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, normalization, fallback candidate construction, fallback availability gates, docs, and regression tests.
