## Summary

Keep open: current main and the latest release still support explicit flat model fallback lists only. Provider-family wildcard/auto fallback and the commenter-proposed `fallbackFamilies` contract are absent, and the overlapping catalog-derived fallback PR is conflicting and proof-blocked rather than a safe resolution for this broader design request.

## What This Changes

The issue requests provider-family wildcard or auto model fallback selection so OpenClaw can stay within a user's intended provider pool when a configured model becomes unavailable.

## Best Possible Solution

Keep this as the design tracker until maintainers choose one durable public fallback contract and align schema, runtime candidate construction, embedded-run fallback gates, docs, and upgrade behavior around it.

## Reproduction Assessment

Yes, by source inspection: current main exposes explicit fallback arrays and provider wildcard catalog entries, but not the requested provider-family auto retry contract. This is a feature/config-contract reproduction, not a failing existing behavior reproduction.

## Solution Assessment

Unclear as proposed: wildcard/auto, `fallbackFamilies`, and catalog-derived fallback are competing public contracts. The best fix needs maintainer selection of one predictable provider-routing model before implementation.
