## Summary

Keep open: current main and v2026.6.11 still support explicit flat model fallbacks only, while this issue requests a broader provider-family wildcard/auto or grouped fallback contract. The related catalog-derived fallback pull request at https://github.com/openclaw/openclaw/pull/60922 is narrower, open, conflicting, and not a safe canonical replacement.

## What This Changes

The issue requests provider-family wildcard or auto model fallback so configured model selection stays within an intended provider before crossing to a generic router.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability gates, docs, and focused regression tests.
