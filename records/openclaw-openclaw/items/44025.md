## Summary

Keep open: current main and v2026.6.11 still expose explicit flat model fallbacks only, while wildcard/auto or grouped provider-family fallback remains a public config and provider-routing product decision. The related catalog-derived fallback PR is narrower, open, and not a safe canonical replacement.

## What This Changes

The issue requests provider-family wildcard or auto model selection so failover stays within the intended provider/subscription family before crossing to generic routers.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability gates, docs, and regression proof.
