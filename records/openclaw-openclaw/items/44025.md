## Summary

Keep open: current main and the latest release still support only explicit flat model fallback lists, while provider-family wildcard/auto selection and the commenter-proposed grouped fallback contract are absent. The related catalog-derived fallback PR is narrower, open, conflicting, and not a safe superseding implementation, so this remains a maintainer product/config decision.

## What This Changes

Request provider-family model fallback selection using wildcard/auto model refs or ordered provider-family groups before crossing to generic router fallbacks.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract using current openai/* model refs, then align schema, types, write normalization, runtime fallback resolution, embedded fallback availability checks, docs, and upgrade behavior around that contract.
