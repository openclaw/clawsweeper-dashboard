## Summary

Keep open: current main and v2026.6.11 still support explicit flat model fallback lists, but not the requested provider-family wildcard/auto or grouped fallback contract. The related catalog-derived fallback PR is narrower, open, conflicting, and not a safe canonical replacement, so this remains a maintainer product/config-contract decision.

## What This Changes

Request provider-family model fallback selection via wildcard/auto refs or grouped fallback priorities so configured provider tiers are exhausted before cross-provider routers.

## Best Possible Solution

A maintainer should choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability gates, docs, and regression proof.
