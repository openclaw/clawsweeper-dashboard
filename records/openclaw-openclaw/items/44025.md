## Summary

Keep open: current main and the latest release still support only explicit flat model fallback lists, while provider-family wildcard/auto selection and the commenter-proposed fallback-family contract remain absent. The related implementation PR is only a partial approach and is open, conflicting, and proof-blocked, so it is not a safe superseding fix.

## What This Changes

Request provider-family wildcard/auto model fallback selection so OpenClaw can stay within a user's intended provider or subscription tier when a configured model becomes unavailable or renamed.

## Best Possible Solution

Choose one public provider-family fallback contract using canonical OpenAI model refs, then align schema, docs, fallback candidate construction, embedded-run fallback availability, config writers, and regression tests around that contract.

## Reproduction Assessment

Yes by source inspection: current main only accepts explicit flat fallback arrays and does not expand provider wildcard, auto, or fallback-family candidates. This is a feature/config gap rather than a broken existing-contract bug reproduction.

## Solution Assessment

Unclear as proposed: wildcard/auto refs, catalog-derived fallback, and explicit fallback families are different public contracts. The best solution needs maintainer selection of one predictable provider-routing model before implementation.
