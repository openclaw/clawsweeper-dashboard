## Summary

Keep open: current main and v2026.6.11 still expose explicit flat model fallback lists, while the requested provider-family wildcard/auto selection and the commenter-proposed grouped fallback contract remain unimplemented. The linked catalog-derived fallback PR is narrower, conflicting, and not a safe canonical replacement for this broader provider/model fallback contract.

## What This Changes

Request automatic provider-family model fallback through wildcard/auto model refs and optional ordered family lists so failover stays within the intended provider before cross-provider routers.

## Best Possible Solution

Have maintainers choose one canonical provider-family fallback contract using current openai/* model refs, then align schema, config normalization, candidate resolution, fallback availability gates, docs, and any doctor behavior around that single contract.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: current schema, helpers, runtime resolution, availability checks, and docs only support explicit flat fallbacks; I did not run a live provider failover because this is a feature/config contract request.

## Solution Assessment

Is this the best way to solve the issue? Unclear as proposed: wildcard/auto refs, catalog-derived fallback, and fallbackFamilies are different public contracts, so maintainers should choose one provider-routing model before implementation.
