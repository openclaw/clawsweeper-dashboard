## Summary

Keep open: current main and v2026.6.11 still only support explicit flat model fallback lists, while provider-family wildcard/auto selection and the grouped fallback contract proposed in discussion remain absent. Related PR #60922 is open, narrower, and not a safe superseding implementation, so this needs maintainer product direction rather than cleanup closure.

## What This Changes

Request provider-family model fallback such as `provider/auto`, `provider/*`, or grouped fallback lists so OpenClaw stays within an intended provider/subscription tier before cross-provider fallback.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract using canonical `openai/*` refs, then update schema, normalization, runtime fallback resolution, docs, and any needed doctor diagnostics together.

Options:

- **Adopt explicit grouped fallbacks (recommended):** Add a `fallbackFamilies`-style explicit ordered contract so operators control family boundaries without relying on implicit provider catalog selection.

- **Limit to catalog-derived fallback or defer:** Treat PR #60922 or existing flat `fallbacks` as the supported path for now and leave wildcard/grouped semantics out of core until the design is clearer.
