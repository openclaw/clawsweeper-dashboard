## Summary

Keep open: current main and v2026.6.11 still support only explicit flat model fallbacks, while provider-family wildcard/auto selection and the commenter-proposed grouped fallback contract remain absent. The related catalog-derived fallback PR is narrower, conflicting, and not a safe canonical implementation for this broader request.

## What This Changes

Requested provider-family wildcard or auto model fallback selection that keeps failover within an intended provider/subscription family before crossing to generic router models.

## Best Possible Solution

Have a maintainer choose one public provider-family fallback contract using canonical openai/* model refs, then align schema, normalization, fallback resolution, availability gates, docs, and any needed doctor behavior around that single contract.
