## Summary

Keep open: current main, latest stable v2026.6.11, and latest prerelease v2026.7.1-beta.2 still only support explicit flat model fallback lists, while this requests a broader provider-family wildcard/auto or grouped fallback contract. The related catalog-derived fallback PR is narrower, open, and not a safe canonical replacement, so this remains a maintainer product/config-contract decision.

## What This Changes

Request provider-family wildcard/auto model fallback so OpenClaw can stay within a configured provider/subscription family before cross-provider fallback.

## Best Possible Solution

Have maintainers choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability gates, docs, and regression tests.
