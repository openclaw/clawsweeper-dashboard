## Summary

Keep open: current main and v2026.6.11 still expose only explicit flat model fallback lists, while this issue asks for a broader provider-family wildcard/auto or grouped fallback contract. The related catalog-derived fallback PR is narrower, open, and conflicting, so it is not a safe canonical replacement.

## What This Changes

Request provider-family model fallback selection such as wildcard/auto refs, optional provider priority lists, or grouped fallback families before crossing to unrelated router models.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability gates, docs, and regression tests.
