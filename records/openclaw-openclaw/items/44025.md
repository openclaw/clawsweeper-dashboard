## Summary

Keep open: current main and the latest release still support explicit flat fallback lists only, while the requested provider-family wildcard/auto selection and the commenter-proposed grouped fallback contract remain unimplemented. The overlapping catalog-derived fallback PR is still open, conflicting, and only partially overlaps this broader design request.

## What This Changes

Request provider-family wildcard or auto model fallback semantics, with optional ordered provider-family fallback lists, so model rotation stays within the intended provider or subscription tier before cross-provider fallback.

## Best Possible Solution

Keep this as a maintainer product decision for one documented provider-family fallback contract, then implement it through the existing model fallback resolver, config schema, docs, and focused regression coverage.

## Reproduction Assessment

Yes by source inspection: current main and v2026.6.11 only accept and resolve explicit flat fallback arrays. This is a feature/config request rather than a broken existing contract reproduction.

## Solution Assessment

Unclear as proposed: wildcard/auto expansion, grouped fallbackFamilies, and catalog-derived fallbacks are different public contracts. The best path is a maintainer-chosen fallback model before implementation, not an automatic narrow bug fix.
