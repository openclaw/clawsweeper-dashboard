- `impact:auth-provider`: The issue changes provider/model selection and failover routing when a configured provider model becomes unavailable or renamed.

## Summary

Keep open: current main and v2026.6.11 still support only explicit flat model fallback lists, while this asks for a new provider-family wildcard/auto or grouped fallback contract. This remains a maintainer product/config decision, and the related catalog-derived fallback PR is narrower, open, conflicting, and not a safe canonical replacement.

## What This Changes

Request provider-family model fallback selection, such as wildcard/auto refs or grouped fallback families, before falling through to cross-provider routers.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it across schema, config normalization, runtime candidate construction, fallback availability gates, docs, and regression tests without reintroducing live openai-codex routes.
