## Summary

Keep open: current main and v2026.6.11 still support explicit flat model fallback lists only, while provider-family wildcard/auto selection and the commenter-proposed grouped fallback contract remain absent. The related catalog-derived fallback PR is open, narrower, and not a merged superseding fix, so this remains a maintainer product/config decision.

## What This Changes

The issue requests provider-family model fallback selection via wildcard or auto model refs, with optional family priority lists before crossing to router models.

## Best Possible Solution

Define one canonical provider-family fallback contract around canonical openai/* model refs, then align schema, normalization, fallback candidate construction, availability gates, docs, and any doctor repair before implementation.
