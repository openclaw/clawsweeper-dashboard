## Summary

Keep open: current main and the latest stable release still expose explicit flat model fallback lists only, while provider-family wildcard/auto selection and the commenter-proposed grouped fallback contract remain absent. The open catalog-derived fallback PR is a narrower partial overlap and is not a safe canonical replacement for this broader product/config decision.

## What This Changes

The issue requests provider-family wildcard or auto model fallback selection so OpenClaw stays within a user's intended provider/subscription family before crossing to generic routers.

## Best Possible Solution

Have a maintainer choose one public provider-family fallback contract using canonical openai/* model refs, then align schema, normalization, runtime fallback resolution, fallback availability gates, docs, and any needed doctor behavior around that single contract.
