## Summary

Keep open: current main and the latest release still support explicit flat model fallbacks only, while provider-family wildcard/auto selection and `fallbackFamilies` remain absent. The overlapping open PR covers a narrower catalog-derived fallback source, is conflicting, and is not a safe canonical resolution for this broader design request.

## What This Changes

Request provider-family-aware model fallback selection using wildcard/auto model refs or ordered fallback groups so users can stay within an intended provider/subscription tier before cross-provider fallback.

## Best Possible Solution

Keep this as the provider-family fallback contract tracker; if maintainers accept the direction, implement one canonical schema/runtime/docs contract using current `openai/*` provider refs, preserving existing flat `fallbacks` behavior and adding focused upgrade-proof tests.

## Reproduction Assessment

Yes by source inspection: current main and `v2026.6.11` only accept and read explicit flat fallback arrays, while the proposed wildcard/auto and fallback-family fields are absent. This is a feature/config-contract gap rather than a broken existing behavior contract.

## Solution Assessment

Unclear as proposed: wildcard/auto refs, catalog-derived fallbacks, and explicit fallback families are different public contracts with different cost/auth behavior. The best solution needs maintainer selection of one predictable provider-routing model before implementation.
