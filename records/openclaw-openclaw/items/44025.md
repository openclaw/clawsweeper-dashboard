## Summary

Keep open: current main and the latest release still only support explicit flat model fallback lists, while provider-family wildcard/auto selection and grouped fallback families remain absent. The related implementation PR is open, conflicting, and only partially overlaps this broader product/config decision.

## What This Changes

Request provider-family wildcard or auto model fallback selection, with optional priority groups, so failover stays within the intended provider or subscription tier before crossing providers.

## Best Possible Solution

Choose one canonical, upgrade-safe fallback contract on the current `openai/*` provider model, then update schema, normalization, resolver behavior, docs, and focused fallback tests together.

## Reproduction Assessment

Yes, by source inspection for the missing capability: current main and the latest release only read explicit flat fallback arrays and reject the proposed grouped fields. This is a feature/config request, not a broken existing-contract reproduction.

## Solution Assessment

Unclear as proposed: wildcard/auto expansion, catalog-derived fallback, and explicit fallback families are different public contracts. The best fix needs a maintainer-selected model-routing contract before implementation.
