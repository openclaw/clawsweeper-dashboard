## Summary

Keep open: current main and v2026.6.11 still expose only explicit flat model fallbacks, while provider-family wildcard/auto selection and the commenter-proposed fallback-family contract remain absent. The related https://github.com/openclaw/openclaw/pull/60922 is only a partial catalog-derived fallback approach and is conflicting/proof-blocked, so it cannot supersede this design tracker.

## What This Changes

Request provider-family wildcard or auto model fallback, optionally with ordered fallback families, so failed or renamed models stay within the intended provider before crossing to router/provider fallbacks.

## Best Possible Solution

Keep this as the design tracker until maintainers choose one public provider-family fallback contract, then update the schema, normalization/write path, fallback resolver, docs, and focused tests together.

## Reproduction Assessment

Yes by source inspection: current schema, docs, and fallback candidate construction only support explicit flat fallbacks. This is a feature/config gap rather than a broken existing behavior contract.

## Solution Assessment

Unclear as proposed: wildcard/auto, fallbackFamilies, and catalog-derived fallback are competing public contracts. The best fix needs a maintainer-selected routing/config shape before implementation.
