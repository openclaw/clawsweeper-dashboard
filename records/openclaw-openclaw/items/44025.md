## Summary

Keep open: current main and v2026.6.11 still support explicit flat model fallback lists only, while this requests a broader provider-family wildcard/auto or grouped fallback contract. The related catalog-derived fallback PR is narrower, currently conflicting, and not a safe replacement for this product/config decision.

## What This Changes

Request provider-family model fallback selection, such as wildcard/auto refs and optional priority lists, before crossing to unrelated router/provider fallbacks.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability gates, docs, and regression tests.
