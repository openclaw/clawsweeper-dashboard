## Summary

Keep open: current main and v2026.6.11 still expose only explicit flat model fallback lists, while provider-family wildcard/auto selection and the commenter-proposed grouped fallback contract remain absent. The related catalog-derived fallback PR is narrower, open, conflicting, and not a safe canonical implementation for this broader config/provider-routing decision.

## What This Changes

Request provider-family model fallback selection so OpenClaw can stay within a chosen provider or fallback group when a configured model is renamed, rotated, or unavailable.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract using current `openai/*` model refs, then align schema, normalization, runtime candidate construction, embedded-run fallback availability, CLI/docs, and any needed doctor behavior around that contract.
