## Summary

Keep open: current main and v2026.6.11 still expose explicit flat model fallback lists, not provider-family wildcard/auto selection or grouped fallback families. The related catalog-derived fallback PR is narrower, open, and conflicting, so this remains a product/config-contract decision rather than cleanup closure.

## What This Changes

The issue requests provider-family-aware automatic model fallback, such as wildcard or auto model refs, so OpenClaw can stay within a user's intended provider family before crossing to generic routers.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract using current provider refs, then update schema, config normalization, fallback candidate construction, availability gates, docs, and regression tests together.
