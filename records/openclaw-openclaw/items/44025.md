## Summary

Keep open: current main and the latest release still only support explicit flat model fallback lists, while provider-family wildcard/auto selection and the commenter-proposed fallback-family contract remain absent. ## What This Changes

The issue requests provider-family wildcard or auto model fallback selection so OpenClaw can stay within a provider family before crossing to generic router models.

## Best Possible Solution

Keep this open for a maintainer to choose one public provider-family fallback contract, then align schema, config normalization, runtime candidate construction, embedded-run availability checks, docs, and any needed doctor behavior around that single contract.

## Reproduction Assessment

Yes by source inspection: current main only accepts explicit flat fallback arrays and does not expand provider wildcard or family fallback candidates. This is a feature/config request rather than a broken existing contract reproduction.

## Solution Assessment

Unclear as proposed: wildcard/auto refs, catalog-derived fallback, and explicit fallback families are different public contracts. The best fix needs maintainer selection of one predictable provider-routing model before implementation.
