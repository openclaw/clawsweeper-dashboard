## Summary

Keep open: current main and the latest release still support only explicit flat model fallback lists, while provider-family wildcard/auto selection and the commenter-proposed grouped fallback contract are still missing. The overlapping open pull request is partial, conflicting, and proof-blocked, so it cannot safely supersede this product/config decision.

## What This Changes

Request provider-family wildcard/auto or priority-list fallback selection so model failover stays within the intended provider or subscription family before crossing to generic router models.

## Best Possible Solution

Keep this as the product/design tracker until maintainers choose one explicit opt-in fallback contract, then implement it in the shared model schema, fallback resolver, docs, and focused regression tests while preserving explicit fallbacks and strict user-selected models.

## Reproduction Assessment

Yes by source inspection: current main and v2026.6.11 only accept and read explicit flat fallback arrays. This is a feature/config contract request rather than a broken existing contract reproduction.

## Solution Assessment

Unclear as proposed: wildcard/auto expansion, grouped fallback families, and catalog-derived fallbacks are competing public contracts. The best fix needs a maintainer-selected provider-routing model before implementation.
