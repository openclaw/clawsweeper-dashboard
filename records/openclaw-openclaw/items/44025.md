## Summary

Keep open: current `main` and v2026.6.11 still only support explicit flat model fallback lists, while this issue asks for a broader provider-family wildcard/auto or grouped fallback contract. The related catalog-derived fallback PR is narrower, still open, and not a safe replacement for the remaining product/config decision.

## What This Changes

The issue requests provider-family model fallback via wildcard/auto model refs, with discussion also proposing grouped fallback families as an alternative contract.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability gates, docs, and regression tests.
