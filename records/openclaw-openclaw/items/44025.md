## Summary

Keep open: current main still supports explicit flat model fallbacks, but not the requested provider-family wildcard/auto or grouped fallback contract. The related catalog-derived fallback PR is narrower, open, conflicting, and proof-blocked, so it is not a safe canonical replacement for this issue.

## What This Changes

The issue requests provider-family wildcard or auto model fallback so OpenClaw stays within the user's intended provider/subscription tier when a configured model name stops working.

## Best Possible Solution

Have a maintainer choose one canonical provider-family fallback contract, then implement it consistently across schema, config normalization, runtime candidate construction, fallback availability gates, docs, and regression tests.
