## Summary

Keep open: current main still supports only explicit flat model fallback lists, while provider-family wildcard/auto selection and the commenter-proposed grouped fallback contract remain absent. The related catalog-derived fallback PR is narrower, open, dirty, and proof-blocked, so it is not a safe superseding implementation.

## What This Changes

The issue requests provider-family wildcard or auto model fallback selection so OpenClaw stays within a chosen provider/subscription family before crossing to generic router fallbacks.

## Best Possible Solution

Choose one core fallback contract that reuses the existing model catalog, allowlist, and fallback-availability gates, then update schema, docs, and focused failover tests together.
