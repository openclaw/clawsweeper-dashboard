## What This Changes

This PR changes file-backed session maintenance so a positive cap already filled by protected sessions retains a bounded newest set of removable entries instead of deleting every removable entry.

## System Context

Session-store maintenance runs after session writes to age out or cap file-backed session entries. Its protected-entry count and removable-entry budget determine which session rows survive, affecting subsequent cron admission and the warning shown when an active session would be capped.

## Architecture Diagram

flowchart LR
  A[Session store write] --> B[Maintenance pass]
  B --> C[Count protected entries]
  C --> D[Resolve removable budget]
  D --> E[Keep newest removable entries]
  E --> F[Delete older removable entries]
  F --> G[Session admission and cap warning]

## Best Possible Solution

Keep one shared budget calculation for eviction and warning behavior, validate the zero-cap and normal-cap paths against the current merge result, and land only after maintainers accept the bounded-retention behavior for protected-over-cap stores.
