## Summary

Keep this PR open for a maintainer decision and a small adjustment before merge. The early return prevents the destructive zero-budget sweep, but it also changes an existing `session.maintenance.maxEntries` setting from “remove synthetic entries under count pressure” to “do not cap synthetic entries at all” whenever protected pointers fill the cap; the documented retention contract and upgrade behavior need an explicit policy. Likely related people: `joshavant` is the strongest routing candidate from the merged active-session-maintenance work (high confidence).

## What This Changes

This PR stops positive session caps from deleting all removable entries when protected entries already fill the cap, updates the active-session cap warning, and adds focused pruning coverage.

## System Context

OpenClaw records session metadata in a per-agent store and runs maintenance after writes. Maintenance first removes stale eligible entries, then applies the configured count cap while preserving durable conversation pointers and runtime-protected sessions.

## Architecture Diagram

flowchart LR
  A[Session store write] --> B[Maintenance pass]
  B --> C[Age-based pruning]
  C --> D[Count-cap evaluation]
  D --> E[Protected pointer count]
  E --> F[Eligible entry retention or eviction]
  F --> G[Session store and run setup]

## Best Possible Solution

Define and document the protected-over-cap retention policy, then implement it consistently in cap enforcement and warnings: either retain eligible entries under a bounded non-destructive policy or explicitly make protected overage suspend count capping and state the resulting age/disk retention behavior.
