## Summary

Keep open: current main and the latest release still block after failed overflow compaction, the MLX threadgroup cause is not proven to be an OpenClaw hardcoded thread setting, and the remaining fix is a maintainer decision about provider-agnostic failed-compaction recovery.

## What This Changes

The issue asks OpenClaw to recover more gracefully when local MLX compaction fails with a Metal threadgroup-size error instead of leaving the session blocked until reset.

## Best Possible Solution

Choose a provider-agnostic failed-compaction recovery contract that preserves replay safety and gives users or operators an in-product recovery surface; use existing extra_body request tuning for MLX unless upstream proof shows OpenClaw needs a new stable config/API field.
