## Summary

Keep open: current main and the latest release have useful warning-only and failed-mutating-tool guardrails, but they still do not verify that Telegram/ACP visible success claims are backed by completed side effects when the model never called the needed tool.

## What This Changes

The issue reports Telegram-surface agent confabulation where the agent claims file writes or message sends completed before the corresponding side effects actually occur.

## Best Possible Solution

Define a maintainer-approved Telegram/ACP source-turn invariant for visible success claims, then implement verification, diagnostics, fallback, or documentation without conflating it with the narrower missing-message-tool-delivery class.
