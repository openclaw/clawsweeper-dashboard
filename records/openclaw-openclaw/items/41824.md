## Label Justifications

- `P1`: The issue reports a real Telegram agent workflow where users can receive false completion reports for actions that did not happen.
- `impact:message-loss`: The reported behavior includes claimed file/message-send actions that did not reach the intended destination.
- `impact:session-state`: The assistant-visible state can diverge from actual tool/session state and require human correction.

## Summary

Keep open: current main still lacks built-in success-claim verification, and the current plugin outbound hook contract says `runId` is not yet plumbed through `message_sending`/`message_sent`, so exact per-turn Telegram/direct side-effect correlation remains a maintainer/plugin-API decision rather than a resolved core issue.

## What This Changes

The issue asks OpenClaw to prevent Telegram-surface agents from reporting file or message side effects as complete unless real tool execution or delivery evidence backs the claim.

## Best Possible Solution

Keep success-claim verification policy in a plugin or ClawHub package, and add only a narrow core outbound `runId` correlation seam if maintainers confirm exact-turn verification is not safe with current hooks.
