## Summary

Keep open: current main covers the narrower message-tool-only stranded-final class with documentation and a metadata warning, but it still does not verify that Telegram/ACP success claims are backed by completed tool side effects; the related recovery work does not supersede this broader trust failure.

## What This Changes

The issue asks OpenClaw to prevent or surface Telegram/ACP agents claiming file-write or message-send actions completed when the corresponding tool side effects did not happen.

## Best Possible Solution

Define the maintainer-approved boundary for Telegram/ACP success claims first, then implement either bounded source-turn diagnostics/fail-closed behavior or a documented plugin/ClawHub claim-verification path while keeping #85714 recovery scoped to stranded message-tool finals.
