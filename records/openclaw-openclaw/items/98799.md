- `P2`: The report concerns channel config being dropped by an installer workflow, which has real but bounded setup impact.
- `impact:data-loss`: The reported workflow removes existing channel config entries when a whole-object write replaces `channels`.

## Summary

The reported destructive write is in the externally hosted mx-claw installer, while OpenClaw already exposes and documents the merge path and this repository's installer does not write channel config.

## What This Changes

The issue reports that an external installer command replaces the full `channels` config object instead of merging a new channel into existing channel configuration.

## Best Possible Solution

Leave OpenClaw's documented replacement-versus-merge config semantics intact and have the mx-claw installer update its external script to use `--merge`, `config patch`, or a narrower nested write.

## Reproduction Assessment

Yes. Source inspection reproduces the risky command shape: the external mx-claw installer constructs a merged whole `channels` object, then calls `openclaw config set channels --json` without `--merge`.

## Solution Assessment

No. An OpenClaw core change is not the best fix for the reported line; the narrow fix belongs in the external installer by using the already-supported merge or patch config path.
