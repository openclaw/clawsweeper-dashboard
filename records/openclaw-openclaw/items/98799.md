## Summary

This should close because the destructive write is in an externally hosted mx-claw installer, while OpenClaw already exposes the needed merge/patch paths and this repository's installer does not write channel config.

## What This Changes

The issue reports that an external mx-claw install script replaces the full channels config instead of merging a new channel into existing channel settings.

## Best Possible Solution

Keep OpenClaw's documented replacement-versus-merge config semantics intact and have the mx-claw installer update its external script to use `--merge`, `config patch`, or a narrower nested write.

## Reproduction Assessment

Yes. ## Solution Assessment

No. Changing OpenClaw core is not the best fix because the CLI already supports and documents merge semantics; the narrow maintainable fix belongs in the external mx-claw installer command.
