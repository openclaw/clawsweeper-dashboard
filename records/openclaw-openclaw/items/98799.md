## Summary

This issue should close because the destructive command is in the externally hosted mx-claw installer, while current and shipped OpenClaw already expose the documented merge path and this repository's installer does not write channel config.

## What This Changes

The issue reports that the external mx-claw installer replaces the entire `channels` config when adding a channel because its `openclaw config set channels --json` call omits `--merge`.

## Best Possible Solution

Leave OpenClaw's merge/replacement config semantics intact and have the external mx-claw installer use `--merge`, `config patch`, or a narrower nested channel write.

## Reproduction Assessment

Yes for the external script: live source inspection shows mx-claw writes the whole `channels` object with `config set ... --json` and no `--merge`. There is not a current-main OpenClaw installer reproduction because this repository's installer does not call `openclaw config set channels`.
