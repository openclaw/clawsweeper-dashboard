## Summary

Keep open: current main still resolves literal inline provider API keys without a cooldown profile identity, while the open linked pull request is the active implementation candidate and has not merged.

## What This Changes

The issue reports that inline `models.providers.<id>.apiKey` providers do not enter billing cooldown on 402 errors, causing repeated retries instead of backoff or provider fallback.

## Best Possible Solution

Land or replace the linked PR with one provider-level inline-key cooldown fix that marks literal/env/SecretRef inline keys on billing/auth failures, gates all auth availability and resolution paths, preserves healthy stored profiles as fallback, and proves the upgrade behavior.
