## Summary

Keep open: current main and the latest release still skip cooldown marking for inline provider API-key credentials, and the only active fix is https://github.com/openclaw/openclaw/pull/88709, which is open and currently conflicting.

## What This Changes

The issue asks OpenClaw to apply billing-error cooldown/backoff to providers configured only with inline `models.providers.<id>.apiKey` credentials.

## Best Possible Solution

Land a maintainer-accepted fix that gives inline provider API keys a provider-scoped cooldown identity across literal, env, and SecretRef paths while preserving healthy auth-profile fallback; close this issue only after that fix merges.
