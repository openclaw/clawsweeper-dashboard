## Summary

Keep open: current `main` and the latest `v2026.6.11` release still resolve inline `models.providers.<id>.apiKey` credentials without a cooldown identity, while the active fix remains the open linked PR https://github.com/openclaw/openclaw/pull/88709.

## What This Changes

The issue requests billing/auth cooldown coverage for providers configured only with inline API keys so repeated 402 failures stop retrying the exhausted provider and can move to fallbacks.

## Best Possible Solution

Review, rebase, and either land https://github.com/openclaw/openclaw/pull/88709 or replace it with an equivalent provider-level inline-key cooldown fix, then close this issue only after merged code proves inline API-key billing failures are recorded and skipped during cooldown.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: configure an inline `models.providers.<id>.apiKey`, trigger a billing/auth failure, and current `main` resolves the key without a `profileId` while the runner failure marker returns when no profile id is present.

## Solution Assessment

Yes for the repair boundary, but not yet as a close condition: provider-level inline-key cooldown state is the maintainable fix because auth-profile cooldowns cannot cover credentials that intentionally have no profile. The linked PR is the active candidate, but maintainers still need to accept the compatibility-sensitive fail-closed behavior and merge a clean head.
