## Summary

Keep open: current main and the latest release still have the exact custom/extension origin allowlist bug, and this PR contains a meaningful focused fix with visible after-fix proof. It is not merge-ready as submitted because the branch is conflicting and the opaque-origin fallback should reject hostless schemes instead of collapsing them to `scheme://` in a Gateway browser-origin authorization helper.

## What This Changes

This PR changes Gateway browser-origin matching to normalize opaque extension origins as `scheme://host`, normalizes configured `allowedOrigins` the same way, and adds unit plus WebSocket handshake coverage.

## Best Possible Solution

Rebase and land one narrow hosted opaque-origin parser fix that requires a non-empty host, preserves current same-origin and host-header fallback behavior, and leaves scheme wildcard policy to the separate open wildcard issue.

## Reproduction Assessment

Yes, source-reproducible. Current main and `v2026.6.11` compare exact allowlist entries against `URL.origin`, and Node reports `chrome-extension://...` as origin `null`, so the configured extension origin cannot match.

## Solution Assessment

Mostly yes, but not as submitted. The parser helper is the right layer and exact matching is the narrow fix, but the fallback should reject hostless opaque origins and the branch must be rebased before merge.
