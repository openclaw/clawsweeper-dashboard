## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Keep configured allowlist entries exact:** `src/gateway/origin-check.ts:47`
  - body: This parses configured `allowedOrigins` through `new URL()` and stores only the resulting origin. That means an existing value such as `https://control.example.com/path` or a default-port spelling that previously failed closed can start authorizing `https://control.example.com` after upgrade. Since this setting is the Gateway browser-origin boundary, keep config entries exact/fail-closed and apply the custom-scheme fallback only without broadening already-configured values.
  - confidence: 0.9
- **[P2] Reject empty-host opaque origins:** `src/gateway/origin-check.ts:17`
  - body: The opaque-origin fallback returns `${url.protocol}//${url.host}` even when `url.host` is empty. For inputs like `file:///tmp/app`, that becomes `file://`, so an allowlist entry for that string would accept all such empty-host values rather than an exact scheme+host origin. Guard the fallback with a non-empty host and keep these origins rejected.
  - confidence: 0.86
