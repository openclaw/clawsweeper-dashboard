Overall correctness: patch is incorrect

Full review comments:

- **[P1] Keep configured allowlist values exact:** `src/gateway/origin-check.ts:63`
  - body: `normalizeAllowedOrigin()` reparses every configured value, so an existing stored entry like `https://trusted.example/path` changes from an inert exact string into `https://trusted.example` and starts authorizing the whole origin. This fix only needs hosted opaque incoming origins to become matchable when explicitly configured, so preserve existing exact configured-string semantics unless maintainers intentionally approve a compatibility change.
  - confidence: 0.88
- **[P2] Reject empty-host opaque origins:** `src/gateway/origin-check.ts:17`
  - body: The fallback returns `${url.protocol}//${url.host}` even when `url.host` is empty, making values like `file://` newly matchable if configured. The reported extension and app origins all have hosts, so gate the opaque fallback on a non-empty host and keep empty-host schemes failing closed.
  - confidence: 0.8
