## Summary

Keep this PR open, but it still needs changes before merge. The exact custom-scheme allowlist bug is real and the screenshots are useful proof, but the patch still broadens Gateway origin authorization by reparsing configured allowlist values and by accepting empty-host opaque fallback strings.

## What This Changes

The PR changes Gateway browser-origin allowlist normalization so exact `chrome-extension://` origins can match and adds focused origin-check and WebSocket handshake tests.

## Best Possible Solution

Land one refreshed Gateway fix that preserves exact configured allowlist strings, reconstructs only hosted opaque incoming origins, rejects empty-host opaque origins, and leaves scheme wildcard policy to https://github.com/openclaw/openclaw/issues/39739.
