- **[P1] Keep configured allowlist values exact:** `src/gateway/origin-check.ts:47`
  - body: This parses configured `allowedOrigins` entries before storing them, so `https://control.example.com/path` or `https://control.example.com:443` starts matching the whole normalized origin even though the config contract is full exact origins. That broadens an existing Gateway authorization setting; keep the allowlist side as trimmed/lowercase exact strings and only normalize the incoming opaque request origin.
  - confidence: 0.92
- **[P2] Reject empty-host opaque origins:** `src/gateway/origin-check.ts:17`
  - body: The opaque-origin fallback returns `scheme://` when `url.host` is empty, so hostless values like `foo://` or `file:///tmp/a` collapse to the same match string if configured. The PR's intended safe boundary is exact `scheme://host` matching; return `null` for `url.origin === "null"` unless both protocol and host are present, and add a rejection test.
  - confidence: 0.86
