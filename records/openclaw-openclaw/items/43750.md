## Summary

Keep open: current main and the latest checked release still route `/new` and `/reset` to the channel/session route, with no explicit user-selected agent target for shared multi-agent channels.

## What This Changes

Request support for explicit agent targeting and safe no-target behavior for `/new` and `/reset` in multi-agent channels.

## Best Possible Solution

Define one shared destructive-command targeting contract, reject or prompt when multi-agent target is ambiguous, and implement it consistently across Discord, Telegram, Slack, and text command paths.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What should the supported destructive-command targeting contract be for `/new` and `/reset` in shared multi-agent channels?

Rationale: The fix changes user-visible command syntax and the safety boundary for destructive session resets across channels, so automation should not choose target parsing or no-target behavior alone.

Likely owner: steipete

Owner reason: They most recently owned the shared native-command target resolver and cross-channel call-site refactor that this contract would change.

Owner confidence: high

Options:

- **Require explicit target when ambiguous (recommended):** Support an explicit agent target in native/text command handling and reject or prompt for `/new` and `/reset` when a shared channel has multiple possible agents.
- **Prompt chooser on omission:** Support explicit targets but open an in-channel or native chooser when no target is provided in an ambiguous multi-agent channel.
- **Keep route-derived behavior:** Preserve current route-derived reset behavior and document channel isolation or per-agent command naming as the supported deployment pattern.

## Reproduction Assessment

Yes from source inspection: native and text command paths still resolve `/new` and `/reset` through the current route/session key rather than a user-selected agent target.

## Solution Assessment

Unclear until maintainers choose the targeting contract; explicit target support plus safe ambiguous-target rejection is the strongest supported direction, but the syntax and prompt behavior are product decisions.
