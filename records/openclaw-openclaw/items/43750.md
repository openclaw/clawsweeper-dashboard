## Summary

Keep open: current main still has route-derived native command targets and text slash commands are intentionally kept on the inbound session key, so `/new @agent` and `/reset @agent` targeting is not implemented. The remaining work is product/security-sensitive because maintainers need to choose target syntax, no-target behavior, and cross-agent authorization before implementation.

## What This Changes

The issue asks for `/new` and `/reset` to support explicit agent targeting and safer defaults in shared multi-agent channels.

## Best Possible Solution

Define one shared destructive-command targeting contract, then implement explicit target selection, ambiguous-target handling, authorization checks, docs, and cross-channel regression coverage together.

## Reproduction Assessment

Yes at source level: current main derives native command targets from route/binding state, and text slash commands ignore `CommandTargetSessionKey`, so there is no `/new @agent` or `/reset @agent` target path. I did not run a live multi-agent channel replay in this read-only review.

## Solution Assessment

No, not as a narrow parser patch. Explicit targeting is the right direction, but the best fix needs a shared target and authorization contract before changing destructive session commands.
