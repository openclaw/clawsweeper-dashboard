## Summary

Keep open: current main has native-command route/session target plumbing, but it still lacks explicit `@agent` or native slash-parameter targeting for `/new` and `/reset`, and the safe default for ambiguous multi-agent resets is a product/security decision.

## What This Changes

The issue requests explicit agent targeting and safer default behavior for `/new` and `/reset` in multi-agent channels.

## Best Possible Solution

Define one explicit target contract for destructive session commands, reuse the existing `CommandTargetSessionKey` routing plumbing, and fail closed or prompt when a multi-agent channel has no unambiguous target.

Question: What should `/new` and `/reset` do in a multi-agent channel when no explicit agent target is supplied?

Rationale: Current code can carry native command target sessions, but choosing `@agent` syntax, native `agent:` parameters, and the ambiguous no-target behavior affects session-state safety and command authorization semantics.

Owner confidence: high

Options:

- **Require Explicit Target In Multi-Agent Rooms (recommended):** Add text and native-command agent targeting, and make ambiguous destructive commands prompt or no-op instead of resetting a guessed agent.
- **Route First, Target Optional:** Keep current route/binding behavior as the default and add `@agent` or native `agent:` only as an override.
- **Document Channel Isolation Only:** Leave runtime unchanged and document dedicated channels, bindings, or per-account command naming as the supported multi-agent workaround.

## Reproduction Assessment

Yes, source-level: current main parses `/new` and `/reset` without an agent target field, treats trailing text as command tail input, and native Discord targets only the resolved route or bound session. I did not run a live multi-agent channel reproduction.

## Solution Assessment

Unclear until maintainers choose the product contract. The safest direction appears to be explicit agent targeting plus fail-closed or prompt-on-ambiguity behavior, implemented on top of existing native command target plumbing.
