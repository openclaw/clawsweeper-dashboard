- `impact:session-state`: Ambiguous `/new` or `/reset` handling can rotate or clear the wrong agent's conversation context in shared channels.
- `impact:security`: The command target rule controls whether a shared-channel user can mutate another agent's session state without explicit targeting.
- `maturity:stable`: The issue affects Discord native command/session behavior, and Discord is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main and v2026.6.11 still derive `/new` and `/reset` targets from the routed session or binding, not from an explicit user-selected agent target, and the overlapping related issues do not replace this destructive-command targeting contract.

## What This Changes

Request that `/new` and `/reset` support explicit agent targeting and safe no-target behavior in multi-agent shared channels.

## Best Possible Solution

Define one cross-channel destructive-command targeting contract, then implement explicit target selection, safe ambiguous-target handling, authorization checks, and regression coverage across shared command/session routing.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What should `/new` and `/reset` do in a multi-agent channel when the sender does not specify an agent target, and what target syntax should be supported across text and native slash commands?

Rationale: The source-level gap is clear, but the safe default and authorization model affect destructive session state, command UX, and channel-specific native command registration.

Likely owner: steipete

Owner reason: steipete has the strongest history signal on the shared native command/session target resolver that this decision would change.

Owner confidence: high

Options:

- **Require Explicit Target (recommended):** Require an explicit agent/account target in ambiguous multi-agent rooms and return a chooser or refusal when no target is provided.
- **Choose Active Agent:** Pick the active or highest-context agent for no-target commands, improving convenience while accepting surprise-reset risk.
- **Reset Active Participants:** Reset all agents participating in the current thread, preserving group-room semantics but making broad reset behavior explicit.

## Reproduction Assessment

Yes, source-reproducible: reset command tails are not parsed as agent targets, and native command targets are route-derived. I did not run a live multi-agent Discord or Telegram replay.

## Solution Assessment

Unclear until maintainers choose the contract. Explicit targeting is the right direction, but the maintainable fix needs shared target and authorization semantics instead of a one-channel patch.
