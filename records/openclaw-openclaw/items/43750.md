## Summary

Keep open: current main still routes native `/new` and `/reset` through the interaction's resolved route/session, but it does not provide an explicit `@agent` or native `agent:` target selector or a maintainer-approved policy for ambiguous destructive resets in multi-agent channels.

## What This Changes

The issue requests targeted `/new` and `/reset` behavior so multi-agent channels can reset a specific mentioned agent instead of ambiguously mutating the wrong session.

## Best Possible Solution

Define a typed native command target contract for `/new` and `/reset` that only resets an explicitly selected or unambiguously routed agent/session, then document and prove it with Discord native-command tests and live multi-agent proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What target-selection contract should native `/new` and `/reset` use in multi-agent channels, and what should happen when no target is explicit?

Rationale: The source gap is clear, but choosing between a native `agent:` option, `@agent` parsing, a selector prompt, or fail-closed behavior changes destructive command UX and security expectations.

Likely owner: steipete

Owner reason: The shared native command session target helper introduced by steipete is the narrowest current seam for a cross-channel target contract.

Owner confidence: high

Options:

- **Typed target selector (recommended):** Add a native Discord `agent` selector or equivalent typed action and allow destructive resets only when the target is explicit or the existing route is unambiguous.
- **Mention parsing:** Accept `@agent` text in command arguments, matching the report wording but with more transport-specific parsing risk.
- **Defer broad controls:** Keep current routed-session behavior and leave multi-agent destructive command targeting to a larger command-targeting design.

## Reproduction Assessment

Yes, at source level: current registry, Discord native dispatch, and reset handling have no explicit agent target input, so a multi-agent channel cannot request `/new @agent` or `/reset @agent` natively. I did not run a live Discord multi-agent replay.

## Solution Assessment

Unclear until maintainers choose the target contract. The explicit-targeting direction is appropriate, but a typed native target selector is safer than a one-off reset-tail parser because it keeps destructive routing distinguishable before channel encoding.
