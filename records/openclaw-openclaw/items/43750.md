## Summary

Keep open: current `main` and v2026.6.11 still route `/new` and `/reset` through the selected channel/session route, not an explicit user-selected agent target, so the shared-channel session safety problem remains.

## What This Changes

The issue asks for `/new` and `/reset` to target a specific agent in multi-agent channels and avoid resetting the wrong agent when no target is specified.

## Best Possible Solution

Define one cross-channel destructive-command targeting contract, then implement explicit target selection, safe ambiguous-target handling, authorization checks, and regression coverage across shared command/session routing.

Options:

- **Require Explicit Target (recommended):** Require an explicit agent/account target in ambiguous multi-agent rooms and return a chooser or refusal when no target is provided.
- **Choose Active Agent:** Pick an active/highest-context agent for no-target commands, improving convenience but risking surprising resets.
- **Reset Active Participants:** Reset all agents participating in the current thread, preserving group-room semantics but making broad reset behavior intentional.

Unclear until maintainers choose the contract. Explicit targeting is the right direction, but the best implementation needs shared target and authorization semantics instead of a one-channel patch.
