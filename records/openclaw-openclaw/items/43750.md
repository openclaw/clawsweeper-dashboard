## Summary

Keep open: current main routes Discord native `/new` and `/reset` through the interaction's resolved route/session, but still has no explicit `@agent` or native `agent:` target selector and no maintainer-approved policy for ambiguous destructive resets in multi-agent channels.

## What This Changes

Request native `/new` and `/reset` support for explicit agent targeting and safer no-target behavior in multi-agent channels.

## Best Possible Solution

Define a typed native command target contract for `/new` and `/reset` that only resets an explicitly selected or unambiguously routed agent/session, then document and prove it with Discord native-command tests and live multi-agent proof.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What target-selection contract should Discord native `/new` and `/reset` use in multi-agent channels, and what should happen when no target is explicit?

Rationale: The source gap is clear, but choosing between native `agent:` options, `@agent` mention parsing, a selector prompt, or fail-closed no-target behavior changes destructive command UX and security expectations.

Likely owner: steipete

Owner reason: Their history anchors the shared native command session target helper that would likely need the product contract change.

Owner confidence: medium

Options:

- **Typed target selector (recommended):** Add a native Discord `agent` selector or equivalent typed action and allow `/new` or `/reset` only when the target is explicit or the existing route is unambiguous.
- **Mention parsing:** Accept `@agent` text in command arguments, which matches the issue wording but risks weaker validation and transport-specific parsing drift.
- **Defer broad multi-agent controls:** Keep current routed-session behavior and leave explicit multi-agent destructive controls to a larger command-targeting design.

## Reproduction Assessment

Yes at source level: current registry, Discord native dispatch, and reset handling have no explicit agent target input, so a multi-agent channel cannot request `/new @agent` or `/reset @agent` natively; I did not run a live Discord multi-agent replay.

## Solution Assessment

The explicit-targeting direction is appropriate, but a typed native target contract is safer than a one-off reset-tail parser because it keeps destructive command routing distinguishable before channel encoding.
