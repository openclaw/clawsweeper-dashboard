## Summary

Keep open: current main and latest v2026.6.11 still route `/new` and `/reset` through the resolved channel/session route, not an explicit user-selected agent target, so the shared-channel session safety problem remains.

## What This Changes

Request explicit agent targeting and safer default behavior for `/new` and `/reset` in shared multi-agent channels.

## Best Possible Solution

Define one shared destructive-command targeting contract, then implement explicit target selection, ambiguous-target handling, authorization checks, and cross-channel regression coverage together.

## Reproduction Assessment

Yes, at source level: reset command tails are not parsed as agent targets, and native command targets are route-derived. I did not run a live multi-agent Discord or Telegram replay.

## Solution Assessment

Unclear until maintainers choose the contract; explicit targeting is the right direction, but a one-channel patch would be too narrow without shared target and authorization semantics.
