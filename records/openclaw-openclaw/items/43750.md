## Summary

Keep open: current main and v2026.6.11 still route native `/new` and `/reset` through route-derived session targets, with no explicit user-selected `@agent` target. The report is source-reproducible and production comments describe real multi-agent workarounds, but the remaining fix needs maintainer product and security direction for target syntax, ambiguous no-target behavior, and cross-agent authorization.

## What This Changes

Request that `/new` and `/reset` support explicit per-agent targeting in shared multi-agent channels and avoid resetting untargeted agents.

## Best Possible Solution

Define one shared destructive-command targeting contract, then implement explicit target selection, ambiguous-target handling, authorization checks, and cross-channel regression coverage together.

## Reproduction Assessment

Yes, at source level: command args are treated as reset tail and native command targets are route-derived. I did not run a live multi-agent Discord or Telegram replay.

## Solution Assessment

Unclear until maintainers choose the contract; explicit targeting is the right direction, but a one-channel patch would be too narrow without shared target and authorization semantics.
