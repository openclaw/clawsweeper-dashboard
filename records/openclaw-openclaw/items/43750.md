## Summary

Keep open: current main and v2026.6.11 still route `/new` and `/reset` through the selected channel/session route, not an explicit user-selected agent target, so the shared-channel session safety problem remains and needs maintainer product/security direction.

## What This Changes

The issue requests explicit agent targeting and safer default behavior for `/new` and `/reset` in shared multi-agent channels.

## Best Possible Solution

Define one cross-channel destructive-command targeting contract, then implement explicit target selection, safe ambiguous-target handling, authorization checks, and regression coverage across shared command/session routing.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What should `/new` and `/reset` do in a multi-agent channel when the user does not specify an agent target, and what explicit target syntax should be supported across text and native slash commands?

Rationale: The code path is clear, but the safe default and authorization model affect session state, command UX, and channel-specific native command registration, so automation should not choose the contract alone.

Likely owner: steipete

Owner reason: Peter has the strongest history signal on the shared native command/session target contract that this decision would change.

Owner confidence: high

Options:

- **Require Explicit Target (recommended):** Require an explicit agent/account target in ambiguous multi-agent rooms and return a chooser or refusal when no target is provided.
- **Choose Active Agent:** Pick an active or highest-context agent for no-target commands, improving convenience but risking surprising resets.
- **Reset Active Participants:** Reset all agents participating in the current thread, preserving group-room semantics but making broad reset behavior intentional.

## Reproduction Assessment

Yes, at source level: reset command tails are not parsed as agent targets, and native command targets are route-derived. I did not run a live multi-agent Discord or Telegram replay, so this is source-reproducible rather than fully reproduced.

## Solution Assessment

Unclear until maintainers choose the contract. Explicit targeting is the right direction, but the best implementation needs shared target and authorization semantics instead of a one-channel patch.
