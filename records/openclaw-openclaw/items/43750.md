## Summary

Keep open: current main and v2026.6.11 still route `/new` and `/reset` through the current route/session target rather than an explicit user-selected agent target, so the shared-channel session-safety problem remains and needs maintainer product/security direction.

## What This Changes

The issue requests explicit agent targeting for `/new` and `/reset` in multi-agent channels, plus safe no-target behavior and channel-gating parity.

## Best Possible Solution

Define one cross-channel destructive-command targeting contract, then implement explicit target selection, safe ambiguous-target handling, authorization checks, and regression coverage for shared native/text command routing.

Options:

- **Require explicit target (recommended):** Require an explicit agent/account target in ambiguous multi-agent rooms and return a chooser or refusal when no target is provided.
- **Choose active agent:** Pick the active or highest-context agent for no-target commands, improving convenience but risking surprising resets.
- **Reset active participants:** Reset all agents participating in the current thread, preserving group-room semantics but making broad reset behavior intentional.

## Reproduction Assessment

Yes, at source level: reset command tails are not parsed as agent targets, and native command targets are route-derived. I did not run a live multi-agent Discord or Telegram replay, so this is source-reproducible rather than fully reproduced.

## Solution Assessment

Unclear until maintainers choose the contract. Explicit targeting is the right direction, but the best implementation needs shared target and authorization semantics instead of a one-channel patch.
