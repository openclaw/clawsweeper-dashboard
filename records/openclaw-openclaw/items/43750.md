## Summary

Keep open: current main has route-based native command target plumbing, but it still does not provide explicit `@agent` or slash-parameter targeting for `/new` and `/reset`, and the ambiguous no-target behavior needs a maintainer product/security decision.

## What This Changes

Requests that `/new` and `/reset` target a specific agent in multi-agent channels instead of ambiguously resetting the wrong shared-channel session.

## Best Possible Solution

Define a maintainer-approved multi-agent reset contract: explicit agent selection for `/new` and `/reset`, fail or prompt on ambiguous no-target commands, and regression coverage for Discord route binding, channel gating, and native command session targets.

Rationale: The code boundary is clear, but the safe behavior changes user-visible command semantics and cross-agent authorization, so automation should not choose the permanent policy alone.

Owner confidence: high

Options:

- **Require explicit target when ambiguous (recommended):** Add an agent mention/slash parameter path and fail or prompt when multiple agents are present without a selected target.
- **Keep route-based default plus optional target:** Preserve current bare-command routing and add explicit target support only for users who opt into it.
- **Defer to broader reset policy work:** Leave this issue open until per-agent or per-binding reset policy is designed with the related session reset requests.
