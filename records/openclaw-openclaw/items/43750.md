## Summary

Keep open: current main and the latest checked release still route `/new` and `/reset` through the resolved channel/session route, with no explicit user-selected agent target for shared multi-agent channels.

## What This Changes

The issue asks for `/new` and `/reset` to target a named agent in multi-agent channels and avoid ambiguous destructive resets.

## Best Possible Solution

Define one shared destructive-command targeting contract, then implement explicit target selection, ambiguous-target prompting or fail-closed behavior, authorization checks, and cross-channel regression coverage.
