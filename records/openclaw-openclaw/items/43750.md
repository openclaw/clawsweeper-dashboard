## Summary

Keep open: current main and the latest release have native-command session target plumbing, but they still do not provide explicit `@agent` or native `agent:` targeting for `/new` and `/reset`, and ambiguous destructive resets remain a maintainer product/security decision.

## What This Changes

The issue requests explicit agent targeting and safe ambiguity handling for `/new` and `/reset` in multi-agent channel contexts.

## Best Possible Solution

Define one explicit target contract for destructive session commands, reuse existing `CommandTargetSessionKey` plumbing, and fail closed or prompt when a multi-agent channel has no unambiguous target.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What should `/new` and `/reset` do when more than one configured agent could handle the channel and the user supplies no explicit target?

Rationale: The code gap is clear, but choosing text `@agent`, native `agent:` parameters, and the no-target fallback affects session-state safety, command authorization, and existing multi-agent channel habits.

Likely owner: steipete

Owner reason: This is a product/security contract on Discord/native-command and reset semantics, and steipete has the strongest relevant history on those policy surfaces.

Owner confidence: high

Options:

- **Require Explicit Target In Multi-Agent Rooms (recommended):** Add text and native-command agent targeting, and make ambiguous destructive commands prompt or no-op instead of resetting a guessed agent.
- **Route First, Target Optional:** Keep current route/binding behavior as the default and add `@agent` or native `agent:` only as an override.
- **Document Channel Isolation Only:** Leave runtime unchanged and document dedicated channels, bindings, or per-account command naming as the supported workaround.

## Reproduction Assessment

Yes, at source level: current main parses `/new` and `/reset` without an agent target field, treats trailing text as command tail input, and native Discord targets only the resolved route or bound session. I did not run a live multi-agent channel reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product contract. The safest direction appears to be explicit agent targeting plus fail-closed or prompt-on-ambiguity behavior, implemented on top of existing native command target plumbing.
