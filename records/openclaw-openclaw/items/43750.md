## Label Justifications

- `impact:session-state`: `/new` and `/reset` mutate the targeted agent session, and the reported ambiguity can reset the wrong context.

- `maturity:stable`: Discord is scored M4 Stable, and the issue affects Discord native command/session routing behavior.

## Summary

Keep open: current main and latest release still route `/new` and `/reset` to the resolved command session without explicit agent targeting, and the ambiguous destructive-command behavior needs a maintainer product/security decision.

## What This Changes

The issue requests explicit `@agent` or native `agent:` targeting for `/new` and `/reset` in multi-agent channels.

## Best Possible Solution

Define one explicit target contract for destructive session commands, reuse existing `CommandTargetSessionKey` plumbing, and prompt or fail closed when a multi-agent channel has no unambiguous target.

Rationale: The implementation gap is clear, but choosing `@agent`, native `agent:` parameters, and ambiguous no-target behavior affects session-state safety, command authorization, and existing shared-channel workflows.

Owner confidence: high

Options:

- **Require explicit target in shared rooms (recommended):** Add text and native-command agent targeting, and make ambiguous destructive commands prompt or no-op instead of resetting a guessed agent.
- **Keep route default plus target override:** Preserve current route/binding behavior when no target is supplied, while adding `@agent` or native `agent:` as an override.
- **Document channel isolation only:** Leave runtime behavior unchanged and document dedicated channels, bindings, or per-account command naming as the supported workaround.

Yes, at source level: current main parses `/new` and `/reset` without an agent target field, treats trailing text as command tail input, and native Discord targets only the resolved route or bound session.

## Solution Assessment

Partly: explicit targeting is the right direction, but the final fix needs maintainer-selected syntax and safe ambiguity behavior before implementation.
