## Summary

Keep open: current main has route/binding-based native command target plumbing, but it still lacks explicit agent targeting for `/new` and `/reset`, and the safe default for ambiguous destructive session commands remains a maintainer product/security decision.

## What This Changes

The issue requests explicit `@agent` or native agent targeting for `/new` and `/reset` in multi-agent channels.

## Best Possible Solution

Define one cross-channel target contract for destructive session commands, reuse existing `CommandTargetSessionKey` plumbing, and prompt or no-op when a multi-agent channel has no unambiguous target.
