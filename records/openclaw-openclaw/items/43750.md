## Summary

Keep open: current main and the latest stable release still route `/new` and `/reset` through generic command input and resolved route/session keys, with no explicit `@agent` or native `agent:` target contract for shared multi-agent rooms.

## What This Changes

Request explicit agent targeting and safer default behavior for `/new` and `/reset` in multi-agent channels.

## Best Possible Solution

Define one explicit target contract for destructive session commands, reuse `CommandTargetSessionKey` plumbing, and prompt or no-op when a multi-agent channel has no unambiguous target.

## Maintainer Decision

Required: true

Kind: product_direction

Question: What should `/new` and `/reset` do in a multi-agent channel when no explicit agent target is supplied?

Rationale: Current code can carry native command target sessions, but choosing `@agent` syntax, native `agent:` parameters, and ambiguous no-target behavior affects session-state safety and command authorization semantics.

Likely owner: steipete

Owner reason: The native command session target helper is the clearest existing seam for this decision.

Owner confidence: high

Options:

- **Require Explicit Target In Multi-Agent Rooms (recommended):** Add text and native-command agent targeting, and make ambiguous destructive commands prompt or no-op instead of resetting a guessed agent.
- **Route First, Target Optional:** Keep current route and binding behavior as the default while adding `@agent` or native `agent:` as an override.
- **Document Channel Isolation Only:** Leave runtime behavior unchanged and document dedicated channels, bindings, or per-account command naming as the supported workaround.

## Reproduction Assessment

Yes, source-level: current main parses `/new` and `/reset` without an agent target field, treats trailing text as command tail input, and native Discord targets only the resolved route or bound session.

## Solution Assessment

Unclear until maintainers choose the product contract; the safest direction is explicit agent targeting plus prompt-or-no-op behavior for ambiguous destructive commands.
