Likely related people: fr-meyer is the proposed implementation author; current-main ownership could not be established from the available PR evidence, so that routing signal is low confidence.

## What This Changes

This PR adds a documented, read-only audit that gathers pull-request reviews, comments, and check runs to return an exact-head READY, BLOCKED, or UNKNOWN convergence result.

## System Context

The proposed audit sits beside repository automation and consumes GitHub pull-request evidence: reviews, comments, reviewer requests, and checks for a head commit. It emits a normalized readiness decision that future ClawSweeper or maintainer workflows could use before acting on a pull request.

## Best Possible Solution

Make requiredness authoritative by resolving the base branch’s protection or ruleset requirements, matching check names and app identities to the head’s checks, and returning UNKNOWN whenever that policy cannot be read; then place the supported pilot in its approved automation owner boundary and demonstrate it on a redacted real PR.
