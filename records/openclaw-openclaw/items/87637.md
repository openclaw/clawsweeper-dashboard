## What This Changes

The issue requests that `openclaw doctor` separately describe memory-core dreaming when embedding memory search is disabled or unavailable, including actionable dreaming status.

## System Context

`openclaw doctor` combines local configuration checks with gateway diagnostic data to help operators understand memory health. Embedding memory search and the memory-core dreaming pipeline are separate paths, but their status is presented together to the CLI user.

## Architecture Diagram

## Best Possible Solution

Define one owner-approved doctor diagnostic contract that keeps embedding memory-search health separate from memory-core dreaming, then expose only the dreaming facts the gateway can reliably supply and cover disabled-search, unavailable-manager, and active-dreaming cases.
