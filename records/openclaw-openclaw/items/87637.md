## What This Changes

Add separate `openclaw doctor` diagnostics for memory-core dreaming so disabled embedding memory search is not presented as the whole memory status.

## System Context

`openclaw doctor` gathers local and gateway health diagnostics, including embedding memory-search readiness. Memory-core dreaming is an independent plugin workflow, so its enabled state and runtime schedule need to remain distinguishable before the CLI renders operator-facing status.

## Best Possible Solution

Define one supported doctor-status contract that preserves the existing embedding-search warning and separately renders memory-core dreaming enablement plus only runtime fields the plugin can authoritatively provide, with focused gateway and CLI regression coverage.
