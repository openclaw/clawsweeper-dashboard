## Summary

Keep this PR open: the reported current-main failure is credible, but the handler-local fix overrides authoritative `replace: true` semantics for every media-bearing empty replacement, and the submitted live trace does not exercise that targeted event shape. ([raw.githubusercontent.com](https://raw.githubusercontent.com/openclaw/openclaw/main/src/gateway/openresponses-http.ts))

## What This Changes

Changes OpenResponses streaming to preserve accumulated assistant text when an empty replacement event includes media metadata, with regression tests for media-bearing and empty-media cases.

## Best Possible Solution

Define media-only addition semantics at the event producer or with an explicit typed event fact, preserve ordinary `replace` behavior in consumers, and cover both additive-media and intentional media-bearing replacement sequences.

## Solution Assessment
