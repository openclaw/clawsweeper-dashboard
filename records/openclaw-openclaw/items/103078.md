## Summary

Keep open: current main and `v2026.6.11` still let the legacy GitHub Copilot OAuth refresh path build a bearer-token endpoint from persisted `enterpriseUrl`, while the newer provider/plugin path has an allowlist. This remains credential-sensitive auth-provider work and needs maintainer security-boundary handling rather than cleanup closure.

## What This Changes

The issue requests hardening legacy GitHub Copilot OAuth refresh so persisted `enterpriseUrl` cannot route a bearer refresh token to an unvalidated domain.

## Best Possible Solution

Apply the existing Copilot host allowlist before legacy refresh constructs any bearer-token endpoint, and pair it with doctor or migration handling plus regression coverage for unsafe persisted `enterpriseUrl` values.

Unclear until maintainers choose the legacy-state security behavior. The maintainable direction is to reuse the existing `normalizeGithubCopilotDomain` allowlist before refresh and keep persisted-state repair in doctor or migration code.
