## Summary

Keep open: current main and latest release still let the legacy GitHub Copilot OAuth refresh path template the bearer-token endpoint from persisted `enterpriseUrl`, while the plugin/config path already uses a `github.com`/`*.ghe.com` allowlist.

## What This Changes

The issue asks OpenClaw to stop legacy GitHub Copilot OAuth refresh from sending a bearer refresh token to an unvalidated persisted `enterpriseUrl` host.

## Best Possible Solution

Use the existing Copilot domain allowlist before constructing any legacy bearer-token refresh endpoint, and add doctor/migration handling plus regression coverage for unsafe persisted `enterpriseUrl` values.

Unclear until maintainers choose the upgrade/security behavior for already-persisted values. The maintainable code direction is to reuse `normalizeGithubCopilotDomain` before refresh and keep legacy-state repair in doctor or migration code.
