## Summary

Keep open: current main and the latest release still allow the legacy GitHub Copilot OAuth refresh helper to build its bearer-token endpoint from persisted `enterpriseUrl`, while the provider plugin already has a safer allowlist path. Because this is credential/security-sensitive and the report is public, it should route to maintainer security-boundary review rather than an automatic fix job.

## What This Changes

The issue asks to harden legacy GitHub Copilot OAuth refresh so persisted enterprise URLs cannot redirect bearer refresh tokens outside `github.com` or allowed `*.ghe.com` tenants.

## Best Possible Solution

Validate the legacy Copilot OAuth `enterpriseUrl` through the existing `normalizeGithubCopilotDomain` allowlist before any token-refresh or fallback URL construction, and add focused regression coverage for migrated legacy OAuth credentials.
