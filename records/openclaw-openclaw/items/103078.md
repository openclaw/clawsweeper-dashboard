## Summary

Keep open: current main and `v2026.6.11` still build the legacy GitHub Copilot OAuth refresh endpoint from persisted `enterpriseUrl` and send a bearer refresh token there, while the provider/plugin path already has an allowlist. This is credential-sensitive auth-provider work, so it should stay open for maintainer security-boundary review rather than cleanup closure or automated repair.

## What This Changes

The issue reports that legacy `github-copilot` OAuth credentials can persist an arbitrary `enterpriseUrl` and the automatic refresh path uses it to build the Copilot token endpoint without the provider allowlist.

## Best Possible Solution

Patch the legacy refresh path to use the existing Copilot domain allowlist before constructing any bearer-token endpoint, and add doctor or migration handling plus regression coverage for migrated legacy OAuth credentials.
