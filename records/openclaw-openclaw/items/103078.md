## Summary

Keep open: current main still routes legacy GitHub Copilot OAuth refresh through an endpoint built from persisted `enterpriseUrl`, while the shipped provider path already has a hostname allowlist. This is credential-sensitive auth-provider work, so cleanup closure or automated repair is not appropriate before maintainer security-boundary review.

## What This Changes

The issue reports that legacy GitHub Copilot OAuth credentials can preserve an unvalidated `enterpriseUrl` and send bearer refresh tokens to that host during automatic refresh.

## Best Possible Solution

Patch the legacy refresh path to apply the existing Copilot domain allowlist before constructing any bearer-token endpoint, and add doctor or migration handling plus regression coverage for migrated legacy OAuth credentials.
