## Summary

Keep open: current main and the latest release still let the legacy GitHub Copilot OAuth refresh path build the bearer-token endpoint from persisted `enterpriseUrl`, while the current provider/plugin path already has a fail-closed allowlist. This is credential-sensitive auth-provider work, so cleanup closure is not appropriate.

## What This Changes

The issue reports that a legacy GitHub Copilot OAuth credential with an unvalidated persisted `enterpriseUrl` can send a bearer refresh token to that host during automatic refresh.

## Best Possible Solution

Patch the legacy refresh path to apply the existing Copilot domain allowlist before constructing any bearer-token endpoint, and add doctor or migration handling plus regression coverage for migrated legacy OAuth credentials.
