## Summary

Keep open: current main has a partial Control UI right-click reply affordance, but it still sends only quoted message text through `chat.send` and lacks the requested structured reply metadata contract into the agent/runtime context; the no-output side also remains tied to open durable final-fallback delivery work.

## What This Changes

The issue requests structured reply-to metadata from Control UI/chat replies to agent sessions and clearer user-facing handling for runs that complete without meaningful assistant output.

## Best Possible Solution

End state should be one maintainer-approved typed reply metadata contract that Control UI `chat.send`, runtime prompt context, and channel reply paths share, with the no-output/fallback display aligned to the durable final fallback delivery contract.

## Reproduction Assessment

Yes. Source inspection shows current main has UI reply preview/Markdown quoting, but `chat.send` and `CurrentInboundPromptContext` still lack a structured reply-to field, so the central metadata gap is reproducible without a live browser run.

## Solution Assessment

Unclear as an implementation until maintainers choose the contract. The best path is not another Control UI-only quote mechanism; it should coordinate the open runtime metadata PR with the durable final-fallback issue and then wire Control UI into that single contract.
