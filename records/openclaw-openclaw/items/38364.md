## Summary

Keep this open: current main has a merged Control UI right-click Reply affordance, but it still sends only Markdown-quoted text and has no structured reply metadata in the `chat.send` protocol or runtime prompt context; the no-output side remains broader fallback-delivery semantics tracked by open related work.

## What This Changes

The issue asks for durable reply-to metadata from Control UI/webchat to reach agent sessions and for empty/no-output completions to be classified more clearly for users.

## Best Possible Solution

Define one typed reply metadata contract from Control UI `chat.send` through gateway protocol and `CurrentInboundPromptContext`, then align no-output terminal presentation with the durable final fallback semantics in #87561.

## Reproduction Assessment

Yes from source for the remaining metadata gap: Control UI only sends Markdown-quoted message text and both the gateway schema and runtime prompt context lack structured reply fields; the no-output behavior was not live-reproduced in this pass but has related source and issue evidence.

## Solution Assessment

No current-main path is the full solution: #92654 solved the UI affordance only, #90745 is an open candidate for runtime reply metadata, and #87561 owns the broader final fallback delivery semantics.
