## Summary

Keep open: current main has a Control UI reply affordance and a hidden text runtime-context carrier, but it still does not expose a structured `replyTo` contract from Control UI/chat.send into agent sessions, and the no-output completion concern is still tied to an open durable final-fallback product decision.

## What This Changes

The issue requests structured reply-to metadata from Control UI/chat surfaces to reach agent sessions and clearer handling when a run completes without a meaningful user-facing assistant reply.

## Best Possible Solution

Split the work along the existing boundaries: land or replace the structured inbound reply-metadata path, and resolve no-output completion through the durable final fallback delivery contract so Control UI reflects the same terminal semantics as other channels.
