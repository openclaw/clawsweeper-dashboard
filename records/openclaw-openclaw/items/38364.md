## Summary

Issue #38364 should stay open because current main has a post-release Control UI reply affordance and related open work, but it still lacks the requested structured reply metadata contract and no-output terminal-state semantics across chat.send, gateway protocol, runtime context, and UI recovery.

## What This Changes

The issue asks OpenClaw to make chat replies and reply-to context durable structured metadata, and to avoid ambiguous successful-looking completion states when no assistant output is produced.

## Best Possible Solution

Keep #38364 as the umbrella product contract until maintainers decide the structured reply metadata shape and align it with #90745 and the final fallback semantics in #87561.

## Reproduction Assessment

Yes from source, but not as a fresh live repro: current main visibly lacks protocol/runtime fields for structured reply metadata and lacks a semantic no-output terminal state, while the issue's production examples explain the user-facing failure mode.

## Solution Assessment

No single current path is sufficient: #92654 solved the UI affordance only, #90745 is an open candidate for runtime reply metadata, and #87561 owns the final fallback semantics, so maintainers still need to choose the durable contract.
