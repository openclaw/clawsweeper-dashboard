## Summary

Keep open: current main has useful runtime-context mitigation, but the Control UI still turns reply intent into Markdown text instead of a typed parent-message contract, and the no-output completion half is still owned by broader final-delivery semantics.

## What This Changes

Request to carry structured reply-to metadata from Control UI/chat surfaces into agent sessions and replace ambiguous no-output completion notices with explicit terminal/fallback states.

## Best Possible Solution

Define one typed Control UI/Gateway inbound reply metadata contract that reaches the agent as runtime context without polluting persisted user text, and route final no-output delivery semantics through https://github.com/openclaw/openclaw/issues/87561.
