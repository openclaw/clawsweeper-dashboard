## Summary

Keep this open: current main has a partial Control UI reply affordance and safer empty-error projection, but it still lacks the requested durable structured reply metadata contract across `chat.send`, runtime context, and agent-session handling; the no-output portion overlaps active fallback-delivery design work rather than being fully settled here.

## What This Changes

The issue requests structured reply-to metadata for Control UI/chat agent sessions and clearer handling of user-visible no-output completion states.

## Best Possible Solution

Keep this as the umbrella issue until maintainers choose a durable reply metadata shape, review or supersede the open runtime-context PR, and align no-output terminal UI with the shared final fallback delivery contract.
