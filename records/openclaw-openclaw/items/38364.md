Keep open: current main partially added a Control UI reply affordance, but it is Markdown quote text only; the structured reply metadata contract and no-output terminal semantics requested here remain unresolved and split across open product-contract work.

## What This Changes

The issue requests durable reply-to metadata from Control UI/chat surfaces into agent sessions plus clearer user-facing handling when a run completes without meaningful assistant output.

## Best Possible Solution

Keep this issue as the Control UI/chat umbrella until maintainers choose one durable reply metadata contract and align the no-output terminal-state UX with https://github.com/openclaw/openclaw/issues/87561, using https://github.com/openclaw/openclaw/pull/90745 as the current reply-runtime candidate rather than opening another narrow fix PR.

## Reproduction Assessment

Yes, source-reproducible rather than live-reproduced: current main lacks reply metadata in chat.send, sends only quoted text from Control UI, and keeps CurrentInboundPromptContext text-only. The no-output side is also source-supported by coarse final/error protocol states and linked production reports, but I did not run a live browser restart/no-output scenario.

## Solution Assessment

No single current path is the best complete solution yet: the merged right-click Reply UI is useful but only sends Markdown text, while https://github.com/openclaw/openclaw/pull/90745 and https://github.com/openclaw/openclaw/issues/87561 cover separate pieces. The maintainable solution is a maintainer-approved protocol/runtime/UI contract with one source of truth for reply identity and terminal no-output state.
