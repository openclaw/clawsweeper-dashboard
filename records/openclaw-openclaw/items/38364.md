## Summary

Keep open: current main has a visible Control UI reply affordance, a runtime-context carrier, and safer empty-error projection, but it still lacks a structured Control UI/Gateway reply-to metadata contract and the no-output completion semantics are still split into broader open delivery work.

## What This Changes

Request structured reply-to metadata from Control UI/chat surfaces into agent sessions and clearer handling for runs that complete without a meaningful assistant reply.

## Best Possible Solution

Define one typed Control UI/Gateway inbound reply metadata contract that reaches the agent as runtime context without polluting persisted user text, and route the no-output final-delivery rules through the durable fallback contract already tracked in related maintainer work.
