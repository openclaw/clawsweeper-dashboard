## Summary

Keep open: current main has partial progress, but the central request is still not complete because Control UI reply intent is serialized as quoted text, the gateway chat.send protocol has no structured reply-target field, and the agent runtime still carries inbound metadata as text rather than a typed reply payload; the no-output half also overlaps an open final-delivery contract issue.

## What This Changes

The issue asks OpenClaw to expose structured reply-to metadata from Control UI/chat surfaces to agent sessions and to make no-output completion states less misleading.

## Best Possible Solution
