## Summary

Keep open: current main has the visible Control UI reply affordance and safer hidden/error projection, but it still lacks a structured Control UI/Gateway reply-to metadata contract and the no-output completion semantics are owned by broader open delivery work.

## What This Changes

The issue requests structured reply-to metadata propagation from Control UI chat into agent sessions and clearer user-facing handling when a run completes without meaningful assistant text.

## Best Possible Solution

Define one typed Control UI/Gateway inbound reply metadata contract that reaches the agent as runtime context without polluting persisted user text, and route the no-output final-delivery rules through https://github.com/openclaw/openclaw/issues/87561.
