## Label Justifications

- `P2`: The issue affects Control UI reply/session context and confusing terminal output state, but it is not a core outage.
- `impact:session-state`: The requested reply target metadata and no-output terminal classification affect what context survives into the agent session and transcript state.

## Summary

Keep open: current main has the right-click Control UI reply affordance, but it still converts the selected target into quoted Markdown instead of exposing structured reply metadata through chat.send and CurrentInboundPromptContext, and the no-output terminal-state work remains tied to open fallback-delivery semantics.

## What This Changes

The issue asks for structured Control UI reply-to metadata to reach agent sessions and for no-output completion states to stop looking like successful empty replies.

## Best Possible Solution

Keep this as the Control UI-facing umbrella until maintainers either land a structured reply metadata contract and explicit no-output terminal-state behavior, or split both remaining pieces into clearly canonical issues/PRs.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction of the reply metadata gap: current main has transient reply state and quoted text, but no structured chat.send or CurrentInboundPromptContext reply payload. The no-output portion is source-backed through related Control UI/fallback work, but not live reproduced here.

## Solution Assessment

Unclear until maintainers choose the durable runtime/session contract. A first-class structured reply field plus explicit Control UI terminal-state rendering is the maintainable direction; Markdown quote injection and generic success notices are not enough.
