## Summary

This issue remains a distinct, source-level Mattermost sequencing concern: the reporter retracted the production incident but retained a plausible warning-before-answer final-gate gap. The open report at https://github.com/openclaw/openclaw/issues/109471 documents the opposite ordering—an answer finalized before a warning deletes the preview—so it should inform a shared test matrix but does not supersede this issue.

## What This Changes

Prevent Mattermost from allowing a non-terminal tool-warning final to suppress a later real assistant final while preserving a lone warning as fallback output.

## Best Possible Solution

Implement a focused Mattermost reply-sequencing guard that does not advance final-reply state for fallback-only non-terminal tool warnings, emits the warning only if no real final arrives, and adds ordered regression coverage for warning→answer and warning-only flows.
