## Summary

Keep this issue open as a distinct, symmetric Mattermost failure mode until the canonical repair explicitly covers both warning→answer and answer→warning ordering. The related open report already documents the same preview/tool-warning lifecycle and should be handled by one shared fix and regression suite rather than separate patches.

## What This Changes

Prevent a non-terminal Mattermost tool-warning final from marking or clearing the final-reply state such that a later successful assistant answer is never delivered.

## Best Possible Solution

Implement one Mattermost-owned warning-buffer path that preserves a real final in either ordering, emits the warning only when no real final settles, and adds focused tests for warning→answer, answer→warning, warning-only, and answer-only turns.
