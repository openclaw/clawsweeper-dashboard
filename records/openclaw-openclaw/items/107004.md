## Summary

This PR remains necessary: current main provides a fresh participant snapshot only during authorized Discord voice turns, while the linked issue asks for silent initial-roster and membership-change events between turns. The implementation follows the Discord plugin ownership boundary, includes focused queue/routing coverage and live Discord proof, and has no concrete correctness finding; it should remain open for explicit maintainer handling because it expands the shared plugin SDK system-event contract and carries the protected `maintainer` label.

## What This Changes

The PR tracks Discord voice membership and sends silent initial-roster and join/leave session events, adding keyed replacement semantics to the shared system-event queue.

## Best Possible Solution

Keep membership tracking in the Discord voice plugin, retain replacement as an additive and documented system-event API only if maintainers accept that shared contract, and land after current-main boundary checks confirm unchanged behavior for existing non-replacement callers and correct session routing across reconnects.
