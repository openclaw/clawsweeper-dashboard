## Summary

Keep open: current main still lacks a cron remaining-budget gate before fallback candidates run, but this PR is not merge-ready because the branch is dirty, its real behavior proof is from an older head, and the new stop hook can still drop the explicit stop error after skip-only attempts.

## What This Changes

The branch adds an internal model-fallback `beforeAttempt` stop hook and threads cron execution deadlines into isolated cron runs so near-timeout fallback attempts can be skipped.

## Best Possible Solution

Land a rebased cron-owned deadline gate that preserves explicit stop errors for skip-only fallback chains and includes current-head proof for both low-budget suppression and normal fallback execution.

## Reproduction Assessment

## Solution Assessment

No, not as currently submitted. The cron-owned pre-attempt budget gate is the right owner boundary, but the branch needs a rebase, current-head proof, and explicit stop-error preservation for skip-only chains before it is the best merge path.
