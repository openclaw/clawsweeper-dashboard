## Label Justifications

- `P1`: A routine non-transient gateway outage can leave a real in-flight ACP turn silently unanswered with no durable failure record.
- `impact:message-loss`: The failed turn has no visible terminal response or interruption message after the disconnect grace expires.
- `impact:session-state`: The ACP session-update stream and replay ledger omit the terminal interruption, leaving the transcript in a misleading dangling state.

## Summary

Current main still has the reported silent terminal path: disconnect reconciliation can reject a pending ACP prompt without emitting or recording a session update, so this issue remains necessary and is distinct from the structured-error-kind work.

## What This Changes

Record and surface an acceptance-aware interruption notice when an ACP prompt is rejected after the gateway disconnect grace expires.

## Best Possible Solution

Settle grace-expired prompts through one idempotent ACP helper that records a clearly labeled interruption update before rejection, with wording derived from `sendAccepted` and focused replay tests for both acceptance states.

## Repair Work Prompt

Fix the silent ACP turn-loss path described by https://github.com/openclaw/openclaw/issues/108587. In the `openclaw acp` translator, when disconnect reconciliation rejects a pending prompt after the grace period, emit and durably record exactly one clearly labeled interruption update before rejecting. Derive resend guidance from the existing `PendingPrompt.sendAccepted` state: only advise resending when the Gateway did not accept the message, and do not imply that an accepted turn is safe to resend. Keep the change inside the ACP translator/session-update owner boundary; do not add config, runtime fallback readers, channel-specific behavior, or parallel transcript storage. Preserve transient reconnect behavior from https://github.com/openclaw/openclaw/pull/59473 and the consolidated state machine from https://github.com/openclaw/openclaw/pull/59574. Add regression coverage for accepted and unaccepted prompts, exactly-once recording, grace expiry, and late reconnect settlement. Do not edit CHANGELOG.md; include user-visible release-note context in the PR body.
