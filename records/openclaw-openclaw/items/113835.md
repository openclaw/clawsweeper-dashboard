## Summary

The PR addresses a reproducible Windows-only clipboard fallback defect with a narrowly scoped implementation and credible real-host before/after evidence. ## What This Changes

The branch makes the final Windows PowerShell clipboard backend read ASCII Base64 from standard input, decode it as UTF-8, and place the resulting text on the clipboard, with a focused regression test for multilingual input.

## System Context

OpenClaw’s infrastructure clipboard helper tries platform-specific command-line backends in order and reports success when one exits cleanly. This change affects the final Windows PowerShell backend, which receives copied dashboard links, tokens, paths, and other UI text after earlier native clipboard tools fail.

  E --> F[UTF-8 text on Windows clipboard]
  D -->|no| G[Successful earlier backend]

## Best Possible Solution

Retain the ordered clipboard-backend design and land the stdin-to-UTF-8 decoding repair once the branch is refreshed against current `main`, so a zero exit code from the PowerShell fallback corresponds to a real copied value.
