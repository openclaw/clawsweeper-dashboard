## Summary

This is useful CI hardening, but the patch does not enforce the claimed two-minute command bound: `--max-time 120` applies to each retry attempt, so the existing five retries can extend each download to roughly twelve minutes plus delays. The unchanged head also lacks controlled-stall proof and currently conflicts with main.

## What This Changes

The PR adds 10-second connection timeouts and 120-second per-attempt transfer limits to both actionlint release downloads in the workflow-sanity job.

## Best Possible Solution

Keep checksum verification and transient retries, but enforce an explicit whole-command wall-clock budget—such as an outer `timeout` with suitably smaller per-attempt limits—then rebase and provide redacted controlled-stall logs demonstrating the final bound.
