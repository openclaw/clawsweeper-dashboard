## What This Changes

Provider failures with HTTP 429 and an explicit overloaded payload should keep the `overloaded` failover reason instead of being forced to `rate_limit`.

## Best Possible Solution

Keep this issue open until maintainers land one canonical classifier fix, then close it together with the older canonical issue and supersede duplicate PRs as appropriate.

Yes, the best fix is a narrow shared classifier precedence/status change with regression coverage. A provider-specific workaround would leave the same generic 429 overload gap for other providers.
