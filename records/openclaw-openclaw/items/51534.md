## Summary

Keep this open: current main supports Discord reply references and deterministic mention rewriting when a mention is already present, and https://github.com/openclaw/openclaw/pull/88527 fixed the adjacent final-reply mention-alias path, but current main still does not auto-inject the original author's mention for guild replies. The remaining work is a new Discord notification/config behavior that needs maintainer product direction and live Discord proof.

## What This Changes

Request an opt-in Discord setting that prepends the original author's `<@id>` mention to guild reply messages when the reply text does not already mention them.

## Best Possible Solution

Decide the Discord notification policy first; if accepted, implement it in the Discord plugin reply delivery path as a narrow opt-in with schema, docs, focused tests, and live guild proof that only the intended reply author is pinged.

## Reproduction Assessment

No high-confidence live reproduction is available. Source inspection does show the requested `autoMentionReply` behavior is absent: replies add `message_reference`, and mention rewriting only handles mentions already present in outbound text.

## Solution Assessment

Unclear pending product direction. Discord-plugin post-processing is the plausible owner boundary, but the config name, default, inheritance scope, and notification safety rules need maintainer approval before this is the best fix.
