## Summary

Keep open: current main and v2026.6.11 still do not implement opt-in Discord reply-author mention injection. The related merged work only fixes replies where the final text already contains a targeted mention, while this request needs a new notification policy and config surface.

## What This Changes

Request to add opt-in Discord behavior that prepends the original reply author's mention to guild reply messages when the model did not include it.

## Best Possible Solution

Confirm the Discord notification policy first; if accepted, implement it inside the Discord plugin as an opt-in config with author-ID-aware prefixing, guild-only scope, mention/broadcast safety checks, docs, focused tests, and live guild proof.

## Reproduction Assessment

Yes, at source level: current main has replyToMode/message_reference and mentionAliases paths, but no autoMentionReply option or original-author prefix step. I did not run a live Discord guild round trip.

## Solution Assessment

Unclear until maintainers decide the notification policy. The requested config is plausible, but the best fix must balance explicit mentions, Discord native reply behavior, broadcast safety, bot-loop risk, and config-surface cost.
