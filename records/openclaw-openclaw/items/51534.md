## Summary

Keep this open: current main and the latest release still do not auto-inject the original Discord reply author's mention. The merged related work in https://github.com/openclaw/openclaw/pull/88527 fixes mention-bearing final replies when a mention or alias is already present, but this issue asks for a distinct opt-in notification behavior that still needs maintainer product direction and live Discord proof.

## What This Changes

The issue asks for an opt-in Discord setting that prepends the original guild message author's `<@id>` mention to replies when the model did not include it.

## Best Possible Solution

Decide the Discord notification policy first; if accepted, implement it inside the Discord plugin reply-delivery path with opt-in scoped config, schema/docs/tests, and live guild proof that only the intended reply author is pinged.

## Reproduction Assessment

No: there is no high-confidence live Discord guild reproduction attached. Source inspection does show the requested behavior is absent: replies add `message_reference`, and existing mention rewriting only handles mentions already present in outbound text.

## Solution Assessment

Unclear pending product direction. Discord-plugin post-processing is the plausible owner boundary, but the config name, default, inheritance scope, and notification safety rules need maintainer approval before this is the best fix.
