## Summary

Keep this open: current main and the latest release still lack original-author auto-mention injection for Discord replies. The related merged work fixes already-present mention text under live preview, but this issue asks for a new opt-in notification policy and config surface that needs maintainer direction.

## What This Changes

The issue requests an opt-in Discord setting that prepends the original guild reply author's explicit mention to the first outbound reply chunk when the agent did not include it.

## Best Possible Solution

Decide the Discord notification policy first; if accepted, implement it inside the Discord plugin reply-delivery path with opt-in scoped config, schema/docs/tests, and live guild proof that only the intended reply author is pinged.

## Reproduction Assessment

No high-confidence live Discord guild reproduction is attached. Source inspection does show the requested behavior is absent: replies add message_reference, and existing mention rewriting only handles mentions already present in outbound text.

## Solution Assessment

Unclear pending product direction. Discord-plugin post-processing is the plausible owner boundary, but the config name, default, inheritance scope, and notification safety rules need maintainer approval before this is the best fix.
