## Summary

The current head is a narrow, plausible fix for the Telegram General-topic variant of the duplicate-conversation bug: it makes persisted last-route metadata reuse the same chat-scoped target already used by live inbound routing, while retaining `threadId` for topic identity. Keep this PR open for the linked bug, but require fresh live Telegram proof on the maintainer-updated head before merge; the PR body currently describes an earlier, different implementation and synthetic test evidence only.

## What This Changes

The PR makes Telegram’s persisted last route use the already-computed inbound target, so the General forum topic’s saved route matches its live routing address while preserving its thread identifier.

## System Context

Telegram converts an inbound forum message into a channel context and separately persists a last route for later session and reply handling. Those two paths must agree on the target form while carrying the topic thread id, or one topic can acquire conflicting conversation identities and duplicate replies.
