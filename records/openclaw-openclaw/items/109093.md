## Summary

Keep this PR open: the plugin-local implementation appears technically sound, but it changes the default behavior of the exported Discord API and the external contributor has supplied only test-harness proof, not real after-fix behavior proof.

## What This Changes

The PR adds an idle timeout and Discord-specific stall error to successful `requestDiscord` response-body reads, plus a synthetic stalled-stream regression test.

## Best Possible Solution

Keep the timeout inside the Discord plugin, but confirm the 30-second public API default and prove it with a real loopback server that sends headers and a partial JSON body, then stalls until `requestDiscord` cancels and returns the expected error.
