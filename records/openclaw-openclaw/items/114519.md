## Label Justifications

- `merge-risk: 🚨 compatibility`: Users whose auto-mode workflows rely on login-shell wrappers will now receive a human-approval prompt.

## Summary

This PR is still necessary: it closes the reported login-shell approval gap across the gateway, node-host, and plugin-harness boundaries by routing startup-capable wrappers to explicit human approval. The patch is internally consistent in the supplied diff and has strong terminal/Testbox proof, but the protected `maintainer` label and security-boundary scope require a human merge decision after the current-base review refresh completes.

## What This Changes

The branch reuses OpenClaw’s existing blocked-shell-wrapper classifier at every exec auto-review entry point so login-shell startup code cannot be implicitly authorized by a model review.

## System Context

Agent commands enter OpenClaw through gateway execution, node-host execution, or the public plugin agent-harness helper. Each path analyzes the command before either requesting model auto-review or creating an explicit human approval request, then dispatches the approved command to an execution host.
