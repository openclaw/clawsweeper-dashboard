## Summary

Keep open. Current main has Kimi K2.6 in the OpenCode Go catalog and captures provider-reported model mismatches as `responseModel`, but the status/runtime model paths still derive the visible active model and context window from requested/session model fields rather than surfacing provider-side rerouting.

## What This Changes

The issue asks OpenClaw to honor `agents.defaults.model.primary=opencode-go/kimi-k2.6` and surface any provider-side routing to `opencode-go/deepseek-v4-pro` in session status/runtime context.

## Best Possible Solution

Keep requested-model selection and fallback semantics unchanged, but add a tested status/runtime diagnostic that shows when the provider-reported response model differs from the configured/requested model.

## Reproduction Assessment

Yes at source level, but not as a live OpenCode Go repro. The source path shows Kimi is requested and a mismatching upstream `chunk.model` is captured as `responseModel`, while the inspected status/runtime paths do not surface that field.

## Solution Assessment

No, current main is not the best end state because it captures provider-reported model identity without making the mismatch visible to the user. The narrow fix is to expose the mismatch as diagnostics/status metadata without silently changing configured model selection.
