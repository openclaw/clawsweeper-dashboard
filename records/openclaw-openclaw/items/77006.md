## Summary

Keep open: current main does not implement an ACPX Codex-home override, and this PR is still a relevant candidate for the open managed Codex ACP auth-home problem. It is not merge-ready because the branch crosses the Codex-home trust boundary, still allows generated API-key auth writes into an explicitly selected external home, and the supplied live proof ended on stale OAuth rather than a successful authenticated Codex ACP result.

## What This Changes

The PR adds an ACPX `codexHome` plugin config key and `OPENCLAW_ACPX_CODEX_HOME` environment override to choose the Codex ACP wrapper home while preserving the isolated default when unset.

## Best Possible Solution

Keep the isolated default and land only a maintainer-approved explicit-home or auth-bridge design that guards external Codex state and includes successful redacted live proof for both the default isolated path and the override path.

## Reproduction Assessment

Yes at source level: current main always gives Codex ACP a generated isolated `CODEX_HOME`, and upstream Codex reads auth, config, plugin, MCP, and log state from that effective home. I did not run live ACPX in this read-only review.

## Solution Assessment

Unclear as the best permanent fix: an explicit-home override is a plausible opt-in mitigation, but the safer end state may be an isolation-preserving auth/setup path and the current patch still mutates the effective Codex home.
