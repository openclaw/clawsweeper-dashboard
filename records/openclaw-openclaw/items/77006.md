## Summary

Keep this PR open as a relevant candidate for the ACPX Codex-home problem, but it is not merge-ready: the opt-in shared Codex home crosses the isolated-home trust boundary, the wrapper can still materialize API-key auth into that explicit home, and the supplied real-run proof did not reach a successful authenticated Codex turn.

## What This Changes

The PR adds an ACPX `codexHome` plugin config key and `OPENCLAW_ACPX_CODEX_HOME` override so Codex ACP can run against a caller-selected Codex home instead of the generated isolated default.

## Best Possible Solution

Keep the isolated default and land only a maintainer-approved explicit-home or auth-bridge design that guards external Codex state and includes redacted live proof for both the default isolated path and the override path.

## Reproduction Assessment

Yes, source inspection shows current main always gives Codex ACP an isolated generated `CODEX_HOME`, and upstream Codex reads config/auth/plugins from that effective home; the PR proof did not show a fully successful after-fix authenticated turn.

## Solution Assessment

Unclear as the best permanent fix: an explicit-home override is a plausible opt-in mitigation, but the safer product direction may be an isolation-preserving auth/setup flow for #73910 and the current patch still mutates external home auth state.
