- `maturity:stable`: The issue affects the M4 Stable gateway-runtime surface, including shared-secret login, trusted-proxy auth, device tokens, and operator permissions.

## Summary

Keep open: current main and v2026.6.11 still model Gateway token auth as one shared operator secret, while this issue asks for a new per-token user identity and session-isolation contract. The Pinchy front-layer workaround and trusted-proxy/device-token paths are useful today, but they do not replace native token-mode per-user identity.

## What This Changes

Add support for multiple Gateway bearer tokens with per-token labels/scopes so multi-user Control UI access can isolate sessions and identify users.

## Best Possible Solution

Keep this as the focused canonical per-user Gateway token identity item until maintainers define one principal model that composes token identity, scoped credentials, trusted-proxy, device pairing, session keys, and author attribution.
