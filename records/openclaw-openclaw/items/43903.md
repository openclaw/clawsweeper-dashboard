## Summary

Keep open: current main and v2026.6.11 still model Gateway token auth as one shared operator secret, while this issue asks for native per-token user identity and session isolation. Trusted-proxy auth and the Pinchy front-layer pattern are useful existing workarounds, but they do not replace token-mode per-user identity in OpenClaw core.

## What This Changes

Request native multi-token Gateway auth with per-token labels/scopes so multiple Control UI/WebChat users can keep isolated sessions while retaining token-mode CLI and device-pairing behavior.

## Best Possible Solution

Define one Gateway principal model that can bind bearer credentials to identity, current operator scopes, optional dispatch restrictions, session routing metadata, docs, and upgrade/doctor behavior.
