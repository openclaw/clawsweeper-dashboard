## Summary

Keep open: current main and v2026.6.11 still expose Gateway token/password auth as one shared operator credential, while this issue requests native per-token user identity and session isolation for shared Control UI/WebChat access. Pinchy is useful existing open-source workaround context, but it does not replace a core Gateway token-mode principal contract.

## What This Changes

Add native Gateway token-mode support for multiple per-user tokens with labels/scopes so shared Control UI/WebChat users can have isolated sessions.

## Best Possible Solution

Define one Gateway principal model that composes per-token user identity, scoped credentials, SecretRefs, rotation/revocation, trusted-proxy/device pairing, session-key derivation, author attribution, docs, and upgrade tests.
