## Summary

Keep open: current main and the latest release still model token/password Gateway auth as one shared operator credential, while this issue asks for native per-token identity and session isolation. The Pinchy/front-layer workaround and trusted-proxy path are useful context, but they do not implement the requested token-mode contract in OpenClaw core.

## What This Changes

Request native support for multiple Gateway bearer tokens with per-token labels/scopes so shared Control UI/WebChat deployments can isolate users and sessions.

## Best Possible Solution

Settle one Gateway principal model first, then implement it across config/schema, auth resolution, WebSocket and HTTP authorization, Control UI/session attribution, tests, and docs, or explicitly choose the trusted-proxy/front-layer pattern as the supported multi-user answer.
