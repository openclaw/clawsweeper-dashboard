## Summary

Keep open: current main still exposes token/password Gateway auth as one shared operator credential, so the requested native per-token user identity and session isolation remains missing; Pinchy and trusted-proxy mode are useful existing paths but do not replace a token-mode principal contract.

## What This Changes

Request native multiple Gateway bearer tokens with per-token labels/scopes so shared Control UI and WebChat users can get isolated sessions and identity metadata.

## Best Possible Solution

Define one Gateway principal model that composes per-token user identity, scoped credentials, SecretRefs, rotation/revocation, trusted-proxy/device pairing, session-key derivation, author attribution, docs, and upgrade tests.
