## Summary

Keep open: current main and the latest stable release still model Gateway token/password auth as one shared operator credential, while this issue asks for native per-token user identity and session isolation. Trusted-proxy, browser-local identity, channel identities, and the linked Pinchy front-layer workaround help today but do not replace the requested core Gateway auth contract.

## What This Changes

Add support for multiple Gateway token credentials with per-token user identity and scopes so shared Control UI/WebChat users can get isolated sessions.

## Best Possible Solution

Keep this open until maintainers choose one Gateway principal model that composes token identity, scopes, trusted-proxy, device pairing, session-key derivation, author attribution, SecretRef, revocation, audit, docs, and tests.
