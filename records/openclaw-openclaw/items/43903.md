## Summary

Keep open: current main and v2026.6.11 still model Gateway token/password auth as one shared operator credential, while this issue asks for a native per-token identity and session-isolation contract. The linked Pinchy front-layer workaround and the related scoped-token and author-attribution issues are useful context, but they do not replace token-mode per-user identity in OpenClaw core.

## What This Changes

Request support for multiple Gateway bearer tokens that map to per-user labels/scopes so Control UI and webchat sessions can be isolated without trusted-proxy auth.

## Best Possible Solution

Keep this as the canonical per-user Gateway token identity item until maintainers define one principal model that composes token identity, scoped credentials, trusted-proxy, device pairing, session keys, and author attribution.

Yes, as a source-level capability check rather than a runtime bug repro: current main and v2026.6.11 support singular shared token/password auth plus identity-bearing trusted-proxy/device-token paths, with no gateway.auth.tokens map/list or token-derived user session identity.

## Solution Assessment

Unclear as proposed. Gateway auth is a plausible owner boundary, but the token object shape, scope semantics, session binding, device/trusted-proxy interaction, and author-attribution model need maintainer security/product direction first.
