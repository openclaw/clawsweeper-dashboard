## Summary

Keep open: current main and the latest release still expose Gateway token/password auth as one shared operator credential, while this issue requests native per-token user identity and session isolation for shared Control UI/WebChat access. The Pinchy front-layer workaround is useful existing open-source context, but it does not replace a core Gateway token-mode principal contract.

## What This Changes

Request support for multiple Gateway bearer tokens with per-token labels/scopes so shared Control UI/WebChat users can get isolated sessions.

## Best Possible Solution

Define one Gateway principal model that composes per-token user identity, scoped credentials, SecretRefs, rotation/revocation, trusted-proxy/device pairing, session-key derivation, author attribution, docs, and upgrade tests.
