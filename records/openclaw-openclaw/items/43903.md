## Summary

Keep open: current main and v2026.6.11 still model Gateway shared-secret auth as one operator credential, while this issue asks for native per-token user identity and session isolation. The trusted-proxy path and the Pinchy front-layer workaround linked in the discussion are useful alternatives today, but they do not replace token-mode per-user identity in OpenClaw core.

## What This Changes

Add native multiple Gateway bearer tokens with per-token user labels/scopes so shared Control UI or webchat users can have isolated sessions without trusted-proxy setup.

## Best Possible Solution

Keep this as the canonical per-user Gateway token identity design item until maintainers define one principal model that composes token identity, scoped credentials, trusted-proxy, device pairing, session keys, and author attribution.
