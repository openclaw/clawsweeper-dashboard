- `maturity:stable`: The issue affects the M4 Stable gateway-runtime surface, including shared-secret login, trusted-proxy auth, device tokens, and operator permissions.

## Summary

Keep open: current main still treats token auth as one shared Gateway operator secret, while this request needs a new per-token identity, scope, and session-isolation contract. The linked Pinchy front-layer workaround is useful production context, but it does not replace native token-mode identity in OpenClaw core.

## What This Changes

The issue requests multiple Gateway bearer tokens with per-token identity/scopes so shared Control UI or WebChat deployments can isolate user sessions.

## Best Possible Solution

Define one Gateway-owned principal model that composes per-token identity, scoped credentials, trusted-proxy identity, device pairing, session-key derivation, author attribution, SecretRefs, revocation, docs, and upgrade tests.
