## Summary

Keep open: current main still models token/password auth as one shared Gateway operator credential, while this issue requests native per-token identity and session isolation for shared Control UI/WebChat use. Pinchy is a useful existing front-layer workaround, but it does not replace a core token-mode principal contract.

## What This Changes

The issue requests multiple `gateway.auth` tokens with per-token labels/scopes so different Control UI/WebChat users can share one Gateway while keeping identity and session history isolated.

## Best Possible Solution

Define one Gateway principal model that composes per-token identity, scoped credentials, SecretRefs, rotation/revocation, trusted-proxy/device pairing, session-key derivation, author attribution, docs, and upgrade tests.
