## Summary

Keep open: current main and latest release still model Gateway token/password auth as one shared operator credential, while this issue asks for a new per-token identity and session-isolation contract that related workarounds and broader scoped-token issues do not replace.

## What This Changes

The issue requests multiple Gateway bearer tokens with per-token identity mapping so Control UI/webchat users can have isolated sessions while keeping token-mode access.

## Best Possible Solution

Keep this focused design item open until maintainers choose one Gateway principal model that composes token identity, scoped credentials, trusted-proxy, device pairing, session keys, and author attribution.

## Reproduction Assessment

Yes, as a source-level capability check rather than a runtime bug repro. Current main and v2026.6.11 support singular shared token/password auth plus identity-bearing trusted-proxy paths, with no gateway.auth.tokens map/list or token-derived user session identity.

## Solution Assessment

Unclear as proposed. Gateway auth is a plausible owner boundary, but the token object shape, scope semantics, session binding, device/trusted-proxy interaction, and author-attribution model need maintainer security/product direction first.
