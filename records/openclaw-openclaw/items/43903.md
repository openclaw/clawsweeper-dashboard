## Summary

Keep open: current main still implements Gateway token/password auth as one shared operator credential, while this issue requests native per-token identity and session isolation for shared Control UI/WebChat use. The linked Pinchy front layer is a useful existing workaround, but it does not replace a core token-mode identity contract.

## What This Changes

Request native support for multiple Gateway bearer tokens with per-token labels/scopes so shared Control UI/WebChat users can get isolated sessions without trusted-proxy.

## Best Possible Solution

Define one Gateway principal model that composes per-token identity, scoped credentials, SecretRefs, rotation/revocation, trusted-proxy/device pairing, session-key derivation, author attribution, docs, and upgrade tests.
