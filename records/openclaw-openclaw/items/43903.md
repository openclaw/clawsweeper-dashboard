## Summary

Keep open: current main still models gateway token/password auth as a single shared operator credential, while this request needs a new native per-token identity, scope, and session-isolation contract.

## What This Changes

Request native support for multiple gateway bearer tokens with per-token identity and scopes so shared Control UI/WebChat deployments can isolate user sessions.

## Best Possible Solution

Define one Gateway principal model that composes per-token identity, scoped credentials, trusted-proxy identity, device pairing, session keys, author attribution, SecretRefs, revocation, docs, and upgrade tests.

Unclear as proposed. Gateway auth is a plausible owner boundary, but the token object shape, scope semantics, session binding, device/trusted-proxy interaction, and author-attribution model need maintainer security/product direction first.
