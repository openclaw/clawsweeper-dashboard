## Summary

Current main still has a single shared Gateway bearer-token model, so the requested multi-user token identity/isolation primitive is not implemented and should remain open as a maintainer-owned auth design item.

## What This Changes

Request native support for multiple Gateway tokens so multi-user Control UI sessions can distinguish users and isolate session access.

## Best Possible Solution

Keep this as a Gateway auth design item and converge it with scoped-token and per-message-author proposals before defining the canonical config, identity propagation, migrations, docs, and security tests.

Options:

- **Design native scoped tokens (recommended):** Define `gateway.auth.tokens[]` or an equivalent canonical credential model that carries user identity/scopes through Gateway sessions and aligns with #92367 and #68353 before implementation.
- **Delegate to proxy/front layer:** Document shared-token mode as single-operator only and direct multi-user deployments to trusted-proxy, separate Gateways, or front-layer tools such as Pinchy.
- **Split attribution from authorization:** Handle chat author labeling separately from bearer-token isolation so UI attribution can advance without claiming token-level authorization semantics.

## Solution Assessment
