## Summary

Keep open: current main and v2026.6.11 still model Gateway token/password auth as one shared operator credential, while this issue asks for a new native per-token identity and session-isolation contract. The Pinchy front-layer workaround and trusted-proxy/device-token paths are useful today, but they do not replace token-mode per-user identity in OpenClaw core.

## What This Changes

Support multiple Gateway auth tokens with per-token labels/scopes so Control UI and webchat users can get isolated sessions in token mode.

## Best Possible Solution

Keep this as the canonical per-user Gateway token identity design item until maintainers define one principal model that composes token identity, scoped credentials, trusted-proxy, device pairing, session keys, and author attribution.

Unclear as proposed. Gateway auth is a plausible owner boundary, but the token object shape, scope semantics, session binding, device/trusted-proxy interaction, and author-attribution model need maintainer security/product direction first.
