## Summary

Keep open: current main still models gateway token/password auth as a single shared operator credential and fixed Control UI client identity, so native per-token identity and session isolation remain unresolved security/product work.

## What This Changes

Request native multiple gateway bearer tokens with per-token labels and scopes so shared Control UI access can map users to isolated sessions while preserving token-mode CLI/device behavior.

## Best Possible Solution

Design a Gateway-owned scoped-token identity primitive that preserves today’s single-token behavior by default and explicitly defines how resolved token identity flows into Control UI sessions, HTTP owner semantics, device pairing, docs, and migrations.
