## Summary

Keep open: current main still treats Gateway token/password auth as a single shared operator credential, while this issue asks for a native per-token identity and session-isolation contract. Trusted-proxy, device-token pairing, browser-local Control UI identity, and the posted front-layer workaround are useful adjacent paths, but none implement token-mode per-user gateway principals.

## What This Changes

Request support for multiple Gateway tokens with per-token user identity, scopes, and isolated sessions for shared Control UI/WebChat access.

## Best Possible Solution

Keep #43903 open as the canonical token-mode per-user principal request until maintainers define one Gateway-owned identity model that composes token identity, scoped credentials, trusted-proxy, device pairing, session routing, author attribution, rotation/revocation, SecretRefs, docs, and tests.
