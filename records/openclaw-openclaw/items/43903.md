## Summary

Keep open: current main and v2026.6.11 still model gateway token auth as one shared operator credential, while this request needs a new per-token identity, scope, and session-isolation contract. The Pinchy front-layer workaround is useful and already linked in discussion, but it does not replace native token-mode identity in OpenClaw core.

## What This Changes

Request support for multiple gateway tokens with per-token labels/scopes so shared Control UI/WebChat deployments can isolate users and sessions without trusted-proxy setup.

## Best Possible Solution

Define one Gateway principal model that composes per-token identity, scoped credentials, trusted-proxy identity, device pairing, session-key derivation, author attribution, SecretRefs, revocation, docs, and upgrade tests.
