## Summary

The issue should stay open because current main and the latest checked release still expose only singular shared-secret gateway credentials, while the requested per-user token/session identity model is a real but security-sensitive product design rather than an autonomous bug fix.

## What This Changes

The issue requests native gateway support for multiple per-user tokens that carry identity and session-isolation metadata for shared Control UI or webchat use.

## Best Possible Solution

Define a gateway-owned principal model for token-mode identity, scopes, and session mapping that preserves singular-token compatibility and includes SecretRef, rotation/revocation, audit, Control UI routing, docs, and upgrade tests.
