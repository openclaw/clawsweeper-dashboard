## Summary

Current main and the latest checked release still expose a single shared Gateway token/password model, so native per-token user identity, session isolation, revocation, and audit remain unresolved. The Pinchy workaround and adjacent scoped-token/chat-author issues are useful, but they do not replace a maintainer-owned Gateway principal design.

## What This Changes

Request native support for multiple Gateway tokens with per-token user identity and isolation for shared multi-user Control UI and Gateway sessions.

## Best Possible Solution

Design one Gateway principal model that composes per-token identity/scopes, SecretRef storage, device pairing and trusted-proxy auth, session-key attribution, revocation, audit logging, docs, and upgrade tests.

## Reproduction Assessment

Yes, as a source-level capability check: current main has no gateway.auth.tokens schema, strict config rejects unknown auth keys, and token auth returns no principal or scope metadata.

## Solution Assessment

Unclear: native Gateway identity is a plausible owner boundary, but the exact token, scope, UI, session, and attribution shape needs maintainer product and security review before a fix PR.
