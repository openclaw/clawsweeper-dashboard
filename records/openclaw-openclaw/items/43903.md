- `maturity:stable`: The issue affects the M4 Stable Gateway runtime surface, including shared-secret login, device auth/pairing, trusted-proxy auth, and operator permissions.

## Summary

Keep open: current main and v2026.6.11 still expose Gateway token/password auth as a single shared operator credential, while this issue asks for native per-token user identity and session isolation. Trusted-proxy auth and the Pinchy front-layer pattern are useful existing options, but they do not replace token-mode per-user identity in OpenClaw core.

## What This Changes

Add a native multi-token Gateway auth mode or token registry that maps bearer tokens to user labels/scopes for isolated Control UI/WebChat sessions.

## Best Possible Solution

Define one Gateway principal model that covers per-user token labels, scoped credentials, SecretRefs, revocation, Control UI session binding, and author attribution before implementation.
