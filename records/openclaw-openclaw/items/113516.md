## Summary

Keep this PR open, but do not merge it as written: it marks a supervisor-managed session finished before the process tree has actually exited, so process state and output retention can become incorrect during the kill grace period.

## What This Changes

This PR changes the agent process tool so both `kill` and `remove` request supervisor cancellation and then invoke process-tree termination for supervisor-managed background sessions.

## System Context

Agent `exec` starts a supervised child process and records a pollable session in the in-memory process registry. The `process` tool requests cancellation, while the supervisor’s wait path observes the real exit and finalizes the session for polling, output, and notifications.

## Architecture Diagram

flowchart LR
  A[Agent exec request] --> B[Process supervisor starts child]
  B --> C[Running process session]
  D[Process kill or remove action] --> E[Cancellation and tree signal]
  E --> B
  B --> F[Actual child-process exit]
  F --> G[Session finalization]
  G --> H[Poll output and completion state]

## Best Possible Solution

Keep the session’s terminal transition under the supervisor’s real-exit path, and make any tree-wide termination capability part of that lifecycle so process state is finalized only after the child has actually exited.
