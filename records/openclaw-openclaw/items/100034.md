## Summary

Keep open: the optimization targets the right transcript hot path and includes useful proof, but the sampled-state completeness check can drop older active session state when rotating long compacted transcripts, so this should not merge as-is.

## What This Changes

The PR adds a bounded head-and-tail transcript reader for file-backed post-compaction successor rotation, falls back to the full reader when sampled state looks incomplete, and adds a long-transcript regression test.

## Best Possible Solution

Make bounded successor rotation prove or carry forward all active pre-compaction state needed by the successor, and fall back to the full reader whenever that proof is missing.

## Reproduction Assessment

Yes, source-reproducible: construct a long transcript with model_change/thinking_level_change/session_info near the session start and compaction plus firstKeptEntryId inside the tail; the PR's sampled state can pass completeness while omitting those state entries. I did not run tests because this review is read-only.

## Solution Assessment

No, not yet: a bounded reader is the right direction, but the proposed completeness check is too narrow. The safer fix is to preserve or prove all successor-visible state before skipping the full parse.
