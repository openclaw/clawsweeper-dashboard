## Summary

Keep open: the optimization targets the right file-backed rotation hot path and has useful terminal proof, but the current completeness check can accept a sampled tail that omits state rows the successor transcript contract still needs to preserve.

## What This Changes

The PR adds a bounded header-and-tail transcript reader for file-backed post-compaction successor rotation and a long-transcript regression test for avoiding full JSONL rereads.

## Best Possible Solution

Keep the bounded reader, but use it only when the sample proves every successor-preserved state/metadata row is present; otherwise fall back to the full reader and cover that case with a long-file regression.

## Reproduction Assessment

Yes at source level: a long transcript can place model/thinking/session/custom state before the 512 KiB tail while still keeping the first-kept entry and compaction boundary inside the tail, causing the new completeness check to use an incomplete state sample.

## Solution Assessment

No: the PR is in the right layer, but the sampled-state success condition is too narrow; the best fix is a stricter completeness gate plus fallback to the existing full reader when preserved state cannot be proven.
