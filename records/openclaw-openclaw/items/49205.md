## Summary

Keep open. Current main and the latest release still persist Control UI `chat.send` turns through OpenClaw transcript/session paths and live WebChat broadcasts, but there is no current gateway path that mirrors those turns into Open WebUI's own visible-history store.

## What This Changes

The issue asks for Control UI-originated turns in an Open WebUI-backed chat to appear in Open WebUI's visible chat history, not only in OpenClaw transcript/model context.

## Best Possible Solution

Define a maintainer-approved, opt-in Open WebUI visible-history sync and backfill contract, then implement it with focused gateway coverage and Docker Open WebUI proof, or explicitly document that this co-editing path is unsupported.

## Reproduction Assessment

Yes, at source level: current `chat.send` persists and broadcasts through OpenClaw session/transcript paths, and targeted source search found no current gateway path that writes Open WebUI visible-history rows for Control UI turns. I did not run the live Open WebUI plus Control UI scenario in this read-only pass.

## Solution Assessment

Unclear as proposed. Direct DB mirroring is plausible, but the best maintainable fix needs maintainer agreement on external Open WebUI schema ownership, operator opt-in/configuration, schema-version handling, and historical backfill behavior.
