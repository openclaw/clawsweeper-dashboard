## Summary

Keep open. Current main and v2026.6.11 still persist Control UI `chat.send` turns through OpenClaw transcript/session paths, and I found no supported path that mirrors those turns into Open WebUI's own visible-history store; the linked PRs cover adjacent session identity/header issues rather than this visual-history sync.

## What This Changes

Ensure Control UI messages sent into an Open WebUI-backed chat also appear as normal Open WebUI visible chat-history messages.

## Best Possible Solution

Define a maintainer-approved, opt-in Open WebUI visible-history sync and backfill contract, then implement it with focused Gateway coverage and Docker Open WebUI proof, or explicitly document that this co-editing path is unsupported.

## Reproduction Assessment

Yes, at source level: current `chat.send` persists and broadcasts through OpenClaw session/transcript paths, and targeted source search found no current Gateway path that writes Open WebUI visible-history rows for Control UI turns.
