## Summary

Keep open. Current main and v2026.6.11 still route Control UI `chat.send` turns through OpenClaw session/transcript persistence without a supported Open WebUI visible-history mirror, and the related open PRs cover adjacent session identity/header issues rather than this `chat.chat`/`chat_message` sync problem.

## What This Changes

The issue requests that Control UI-originated turns in an Open WebUI-backed chat be mirrored into Open WebUI visible chat history as normal message bubbles.

## Best Possible Solution

Define a maintainer-approved, opt-in Open WebUI visible-history sync and backfill contract, then implement it with focused gateway coverage and Docker Open WebUI proof, or explicitly document that this co-editing path is unsupported.

## Reproduction Assessment

Yes at source level: current `chat.send` persists through OpenClaw transcript/session paths, and targeted source search found no gateway path that writes Open WebUI visible-history rows for Control UI turns. I did not run the live Open WebUI plus Control UI scenario in this read-only pass.

## Solution Assessment

Unclear as proposed. Direct DB mirroring is plausible, but the best maintainable fix needs maintainer agreement on external Open WebUI schema ownership, operator opt-in/configuration, schema-version handling, and historical backfill behavior.
