## Summary

Keep open. Current main and the latest release still lack a supported path that mirrors Control UI-originated turns into Open WebUI's visible-history store; the remaining bug is real, but the fix needs maintainer/product review because it would touch an external persisted SQLite data model and possibly historical backfill behavior.

## What This Changes

The issue asks for Control UI messages sent into an Open WebUI-backed chat to appear in Open WebUI visible chat history as normal user/assistant bubbles, not only in OpenClaw transcript/model context.

## Best Possible Solution

Define a maintainer-approved, opt-in Open WebUI visible-history sync contract, then implement new-turn mirroring with focused gateway coverage and Docker Open WebUI proof, or explicitly document that Control UI co-editing of Open WebUI visible history is unsupported.

## Reproduction Assessment

Yes, at source level: current chat.send persists and broadcasts through OpenClaw session/transcript paths, and targeted searches found no Open WebUI DB or visible-history mirror path. I did not run the live Open WebUI plus Control UI scenario in this read-only review.

## Solution Assessment

Unclear as proposed: direct DB mirroring is plausible, but the best maintainable fix needs maintainer agreement on external Open WebUI schema ownership, operator opt-in/configuration, schema-version handling, and historical backfill behavior.
