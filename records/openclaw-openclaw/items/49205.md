## Summary

Keep open: current main and the latest release still route Control UI `chat.send` turns through OpenClaw transcript and Gateway broadcast paths, but there is no current Open WebUI visible-history mirror into its `chat.chat` JSON or `chat_message` rows. The remaining work needs maintainer direction because the likely fix crosses a third-party persistence/schema boundary and needs live Open WebUI proof.

## What This Changes

The issue reports that Control UI messages in an Open WebUI-backed chat can update OpenClaw transcript/model context without appearing in Open WebUI’s visible chat history.

## Best Possible Solution

Define a maintainer-approved, opt-in Open WebUI visible-history sync boundary, preferably behind a stable adapter/plugin seam with schema/version handling, fresh-turn live proof, and a separate historical-backfill decision.
