## Summary

Keep open: current main still persists and broadcasts Control UI chat turns through OpenClaw's Gateway/session transcript path, but I found no runtime path that mirrors those turns into Open WebUI's own visible history store; the related open PRs cover adjacent session identity problems rather than this visual-history sync.

## What This Changes

The issue asks OpenClaw to make Control UI turns in an Open WebUI-backed chat appear in Open WebUI's visible chat history, not only in OpenClaw transcript/model context.

## Best Possible Solution

Define a maintainer-approved Open WebUI visible-history sync boundary, then add focused Gateway coverage and Docker/Open WebUI proof, or explicitly document that Control UI co-editing of Open WebUI visible history is unsupported.
