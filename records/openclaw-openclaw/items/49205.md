## Label Justifications

- `impact:session-state`: The reported failure is a drift between OpenClaw transcript/model context and another chat surface's visible session history.

## Summary

Keep open. Current main still persists Control UI `chat.send` turns through OpenClaw session/transcript storage and broadcasts Gateway chat events, but I found no current source path that mirrors those turns into Open WebUI's own visible history store; the related open PRs cover adjacent session identity problems rather than this visual-history sync.

## What This Changes

The issue asks for Control UI turns in an Open WebUI-backed chat to appear in Open WebUI's visible chat history, not only in OpenClaw transcript/model context.

## Best Possible Solution

Define a maintainer-approved Open WebUI visible-history sync boundary, then add focused Gateway coverage and Docker/Open WebUI proof, or explicitly document that Control UI co-editing of Open WebUI visible history is unsupported.
