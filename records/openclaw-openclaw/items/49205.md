## Summary

Keep open: current main still routes Control UI `chat.send` turns through OpenClaw transcript persistence and Gateway broadcast paths, and I did not find a current Open WebUI visible-history mirror into `webui.db`, `chat.chat`, or `chat_message`. The remaining work needs maintainer direction because the likely fix crosses third-party Open WebUI persistence/schema ownership and needs live proof.

## What This Changes

The issue asks for external Control UI turns in an Open WebUI-backed chat to appear in Open WebUI's visible chat history after they reach OpenClaw transcript/model context.

## Best Possible Solution

Define a maintainer-approved, opt-in Open WebUI visible-history sync boundary, preferably through a stable API/adapter or plugin seam with schema/version handling, fresh-turn tests, live Docker/OpenWebUI proof, and a separate decision for historical backfill.
