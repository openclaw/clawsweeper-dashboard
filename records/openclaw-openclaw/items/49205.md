## Summary

Keep open. Current main and the latest release still persist Control UI `chat.send` turns through OpenClaw transcript/session paths and Gateway broadcasts, but I found no current source path that mirrors those turns into Open WebUI's visible-history store; related open PRs cover adjacent session identity issues rather than this visual-history sync.

## What This Changes

The issue requests that Control UI turns sent into an Open WebUI-backed chat also appear in Open WebUI's visible chat history, not only in OpenClaw transcript/model context.

## Best Possible Solution

Define a supported, operator-controlled Open WebUI visible-history sync boundary with schema/API version handling and live Docker/Open WebUI proof, or explicitly document that Control UI co-editing of Open WebUI visible history is unsupported.
