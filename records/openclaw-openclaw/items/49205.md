## Summary

Keep open. Current main still routes Control UI `chat.send` turns through OpenClaw transcript/session persistence and live Gateway broadcast, but no reviewed source path mirrors those external turns into Open WebUI's own visible-history store; the related open PRs cover adjacent session identity/header issues rather than this visible-history sync.

## What This Changes

The issue requests that Control UI turns written into an Open WebUI-backed chat also appear as normal visible message bubbles in Open WebUI history.

## Best Possible Solution

Define a maintainer-approved Open WebUI visible-history sync boundary, then implement focused gateway coverage and Docker/Open WebUI proof, or explicitly document that Control UI co-editing of Open WebUI visible history is unsupported.

## Reproduction Assessment

Yes, at source level: current `chat.send` persists and broadcasts through OpenClaw session/transcript paths, and targeted source search found no gateway path that writes Open WebUI visible-history rows for Control UI turns. I did not run a live Open WebUI plus Control UI scenario in this read-only pass.

## Solution Assessment

Unclear as proposed. Direct DB mirroring is plausible, but the best maintainable fix needs maintainer agreement on external Open WebUI schema ownership, operator opt-in/configuration, schema-version handling, and historical backfill behavior.
