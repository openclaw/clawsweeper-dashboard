## Summary

Keep open: current main still writes Control UI turns through OpenClaw's transcript and live Gateway broadcast paths, but there is no implementation that mirrors those external turns into Open WebUI's own visible-history store. The report is specific and still useful, but the fix shape needs maintainer direction because it crosses into third-party Open WebUI persistence and likely operator configuration.

## What This Changes

The issue asks for Control UI turns sent into an Open WebUI-backed chat to appear in Open WebUI's visible chat history as normal message bubbles.

## Best Possible Solution

Maintainers should choose an owner-approved Open WebUI sync design: preferably a supported Open WebUI API/plugin boundary, or an explicit opt-in mirror with schema/version guards, operator configuration, doctor/backfill guidance, and live Open WebUI proof.

Kind: product_direction

Question: Should OpenClaw core own mirroring Control UI turns into Open WebUI's visible-history store, and if so through which supported boundary?

Rationale: The user-visible bug is plausible, but the straightforward implementation writes to a third-party database and likely adds configuration or operator assumptions that ClawSweeper should not choose automatically.

Likely owner: steipete

Owner confidence: high

Options:

- **Sponsor a bounded sync design (recommended):** Define an opt-in Open WebUI integration path with version/schema checks, safe configuration, live proof, and a separate decision on historical backfill.
- **Keep this outside core:** Document that Open WebUI's visible chat history is owned by Open WebUI and that Control UI turns are only guaranteed in OpenClaw transcript/context.
- **Move to plugin/API work first:** Require a plugin or supported API seam before any Open WebUI-specific persistence bridge lands in core.
