## Summary

Keep open. Current main and v2026.6.11 still route Control UI `chat.send` turns through OpenClaw transcript/session and live-delivery paths only; there is no supported mirror into Open WebUI's visible-history database, and the related open PRs cover adjacent session identity/header issues rather than this visible-history sync.

## What This Changes

Control UI turns in an Open WebUI-backed chat should appear in Open WebUI visible chat history when they already reach shared OpenClaw transcript and model context.

## Best Possible Solution

Define a maintainer-approved, opt-in Open WebUI visible-history sync and repair contract, or explicitly document that Control UI co-editing of Open WebUI visible history is unsupported.

## Reproduction Assessment

Yes at source level: current `chat.send` persists and broadcasts through OpenClaw session/transcript paths, and targeted source search found no current gateway path that writes Open WebUI visible-history rows for Control UI turns. I did not run the live Open WebUI plus Control UI scenario in this read-only pass.

## Solution Assessment

Unclear as proposed. Direct DB mirroring is plausible, but the best maintainable fix needs maintainer agreement on external Open WebUI schema ownership, operator opt-in/configuration, schema-version handling, and historical backfill behavior.
