## Summary

Keep open. Current main and the latest release still route Control UI `chat.send` turns through OpenClaw transcript/live-delivery paths only, with no supported mirror into Open WebUI's visible-history store; the related open PRs address adjacent session identity/header issues rather than this visual-history sync.

## What This Changes

The issue asks OpenClaw to make Control UI-originated turns in an Open WebUI-backed chat also appear in Open WebUI's visible chat history.

## Best Possible Solution

Define a maintainer-approved, opt-in Open WebUI visible-history sync and backfill contract, or explicitly document that Control UI co-editing of Open WebUI visible history is unsupported.

## Reproduction Assessment

Yes at source level: current `chat.send` persists and broadcasts through OpenClaw session/transcript paths, and targeted source search found no current gateway path that writes Open WebUI visible-history rows for Control UI turns. I did not run the live Open WebUI plus Control UI scenario in this read-only pass.

## Solution Assessment

Unclear as proposed. Direct DB mirroring is plausible, but the best maintainable fix needs maintainer agreement on external Open WebUI schema ownership, operator opt-in/configuration, schema-version handling, and historical backfill behavior.
