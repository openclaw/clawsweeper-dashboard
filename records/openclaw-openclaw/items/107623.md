## Summary

The patch appears correct and well-proven, but merge should wait for an owner-level confirmation that decimal integer strings remain the intended compatibility subset and that fractional string durations are not accepted by the actual computer-action execution path.

## What This Changes

The PR replaces broad JavaScript number coercion in Codex computer timeout budgeting with type-aware duration parsing and adds boundary tests for malformed strings, non-finite values, negative values, and fractional numeric durations.

## Best Possible Solution

Define one explicit computer-duration grammar at the owner boundary and keep execution plus watchdog budgeting aligned; if the action schema/runtime accepts numbers only, merge this parser and tests, otherwise preserve the canonical accepted string forms in both paths.
