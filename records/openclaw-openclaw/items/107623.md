## Summary

This PR remains necessary because current main still broadly coerces computer durations with JavaScript `Number(...)`. The implementation and proof look sound, but merge should pause until the Codex/computer-tool owner confirms whether decimal strings are intentionally supported or all string durations should be rejected to match the canonical tool schema.

## What This Changes

The PR narrows Codex computer-tool deadline parsing to reject hexadecimal, exponent, fractional-string, and non-finite durations while preserving finite fractional numeric durations, and adds focused boundary tests.

## Best Possible Solution

Define one canonical computer-duration grammar at the computer-tool owner boundary, reuse that contract for both execution validation and Codex watchdog budgeting, and retain focused tests proving numeric fractions plus every supported or rejected string form.
