## Summary

The patch appears correct and well-proven, but this PR should remain open for a maintainer to confirm the compatibility boundary: callers that previously relied on JavaScript-style string coercion will now receive the shorter baseline watchdog deadline.

## What This Changes

The PR type-discriminates Codex computer wait durations, preserving finite fractional numbers while rejecting hexadecimal, exponent, fractional-string, and non-numeric forms, with expanded boundary tests.

## Best Possible Solution

Make finite JSON numbers the canonical seconds representation, retain plain decimal integer strings only as a narrow compatibility path, and merge this parser once that input-grammar boundary is explicitly accepted.
