## Summary

This PR appears technically sound and well-proven, but the timeout grammar is compatibility-sensitive and still needs a Codex-area owner to confirm that watchdog budgeting matches the actual computer-tool schema and executor parsing before merge.

## What This Changes

The PR replaces permissive `Number(...)` coercion for Codex computer wait durations with finite-number handling and strict decimal-string parsing, plus focused boundary tests.

## Best Possible Solution

Define one canonical computer-duration normalization contract at the computer tool’s schema/executor boundary and have watchdog budgeting consume the same normalized value, with tests proving valid fractional numbers and malformed inputs cannot diverge between execution time and deadline time.
