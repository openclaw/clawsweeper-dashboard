## Summary

## What This Changes

Request that Control UI config and hardening recommendation sections offer a before/after diff plus explicit one-click apply/dismiss flow instead of directing users to edit JSON manually.

## Best Possible Solution

Define a reusable, allowlisted Control UI recommendation-action model over the existing config RPCs with exact before/after diff, explicit accept/dismiss, confirmation, redaction, restart/audit handling, and security-sensitive copy.

## Reproduction Assessment

Yes, by source inspection for the current behavior rather than as a bug repro: Overview and login-gate still render manual allowInsecureAuth guidance, while the Config tab diff/apply path only applies user-staged editor drafts.

## Solution Assessment

Unclear until maintainers choose the product and security boundary. The maintainable direction is a generic allowlisted recommendation-action flow over existing config APIs, not a hardcoded one-off allowInsecureAuth button.
