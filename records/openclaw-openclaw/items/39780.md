## Summary

Keep open: current main and v2026.6.11 still present insecure-context Control UI recovery as manual config text, while the existing Config diff and Apply controls are scoped to user-staged editor drafts. The remaining work is useful, but it needs product/security direction because the browser UI would persist auth and hardening settings.

## What This Changes

Request that Control UI recommendation cards apply approved config changes through an accepted before/after diff flow instead of telling users to edit openclaw.json manually.

## Best Possible Solution

Define a reusable, allowlisted Control UI recommendation-action model over existing config.patch/config.apply semantics, with exact before/after diff, explicit accept/dismiss, redaction, restart/audit feedback, and stricter policy for auth/security downgrade paths.
