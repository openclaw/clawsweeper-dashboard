## Summary

Keep open: current main and the latest stable release still present Control UI hardening guidance as manual config text, while the existing diff/apply path only covers user-staged Config editor changes. Related upgrade-scanner, QuickStart insecure-auth, and broad Control UI UX items overlap but do not implement this recommendation accept/diff/apply/dismiss flow.

## What This Changes

Add a Control UI flow that lets vetted config and security recommendations show a before/after diff, then accept, dismiss, and apply through existing config APIs instead of directing users to edit config files manually.

## Best Possible Solution

Define a reusable, allowlisted Control UI recommendation-action model that previews validated config patches through the existing config RPC path, requires explicit diff acceptance, records dismissals, and preserves redaction, restart, audit, and concurrency safeguards.
