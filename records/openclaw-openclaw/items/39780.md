## Summary

Keep open: current main still gives manual Control UI auth/origin recovery instructions, while existing diff and config.patch plumbing is scoped to user-staged Config editor changes rather than recommendation accept/dismiss actions; implementation needs product/security direction before the UI applies auth-related config changes for users.

## What This Changes

Request for Control UI upgrade and hardening suggestions to show before/after diffs with accept/dismiss and one-click config application instead of instructing users to edit config files manually.

## Best Possible Solution

Add a policy-approved Control UI recommendation-action framework that reuses config.patch, shows exact before/after diffs, requires explicit accept/dismiss, records an audit note, and treats auth/security paths as allowlisted or higher-confirmation actions.
