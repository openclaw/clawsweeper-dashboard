## Summary

Keep open: current main and the latest release still present the insecure Control UI recovery path as manual config guidance, while the existing diff/apply controls are scoped to user-staged Config editor changes. The remaining work is useful, but it needs maintainer product/security direction before implementation because it would let the UI apply auth/security config changes on the user's behalf.

## What This Changes

The issue requests Control UI recommendation cards that can apply selected security/config hardening changes through a before/after diff and explicit user acceptance instead of telling users to edit config JSON manually.

## Best Possible Solution

Define an allowlisted Control UI recommendation-action model that reuses config.patch, shows a precise before/after diff, requires explicit acceptance for security/auth changes, records an audit note, and keeps manual docs as fallback.
