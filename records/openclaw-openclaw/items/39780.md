## Summary

Keep open: current main still renders the cited Control UI recovery as manual config guidance, and the existing diff/apply flow is scoped to user-staged Config editor changes. The remaining work is useful but needs product/security direction before browser-originated recommendations can mutate auth-related config.

## What This Changes

Request a Control UI recommendation flow that previews config changes, lets the user accept or dismiss them, and applies accepted changes automatically instead of telling users to edit `openclaw.json` manually.

## Best Possible Solution

Define a reusable allowlisted Control UI recommendation-action model that previews validated config patches, requires explicit diff acceptance, records dismissal/confirmation state, and preserves redaction, restart, audit, and concurrency safeguards.
