## Summary

Keep open: current main and v2026.6.11 still expose Control UI auth/hardening guidance as manual config instructions, while the existing config diff and Apply controls are scoped to user-edited config drafts. Related work covers QuickStart defaults, agent-side protected config approval, and broader upgrade scanning, but none implements this Control UI recommendation apply/diff/accept/dismiss flow.

## What This Changes

The issue requests Control UI recommendation cards that apply safe config changes through an explicit before/after diff, accept/dismiss controls, and confirmation instead of instructing users to edit config files manually.

## Best Possible Solution

Define a reusable allowlisted Control UI recommendation-action model over the existing config RPCs with exact before/after diff, explicit accept/dismiss, confirmation, redaction, restart/audit handling, and security-sensitive copy.

- **Split By Recommendation Class:** Use separate policies for hardening, compatibility, and recovery recommendations so secure-by-default changes can be one-click while downgrade paths require stronger consent.
