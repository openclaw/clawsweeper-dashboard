## Summary

Keep open: current main and v2026.6.11 still show the cited Control UI insecure-context recovery as manual config guidance, while the existing before/after diff and Apply flow only covers user-staged Config editor changes. The issue is still useful but needs product/security direction before browser-originated recommendations can mutate auth-related config.

## What This Changes

Request the Control UI to turn config upgrade and hardening recommendations into allowlisted apply actions with a before/after diff, accept/dismiss controls, and confirmation instead of manual file-edit instructions.

## Best Possible Solution

Define a reusable allowlisted Control UI recommendation-action model that previews validated config patches, requires explicit diff acceptance, records dismissal/confirmation state, and preserves redaction, restart, audit, and concurrency safeguards.
