## Summary

Keep open: current main and the latest stable release still present the cited Control UI recovery as manual auth/config guidance, while the existing before/after diff and apply path is limited to user-staged Config editor changes. The remaining work is useful but needs product/security direction before browser-originated recommendations can mutate auth-related config.

## What This Changes

Request a Control UI recommendation workflow that shows config before/after diffs and lets users accept or dismiss upgrade, recovery, or hardening suggestions instead of manually editing config.

## Best Possible Solution

Define a reusable allowlisted Control UI recommendation-action model that previews validated config patches, requires explicit diff acceptance, records dismissal/confirmation state, and preserves redaction, restart, audit, and concurrency safeguards.
