## Summary

Keep open: current main and v2026.6.11 still render the cited insecure-context recovery as manual config guidance, while the existing diff/apply flow is limited to user-staged Config editor changes. The remaining feature needs security/product policy before browser-originated recommendations can mutate auth-related config.

## What This Changes

Requests a Control UI recommendation-action flow that previews config diffs and applies accepted hardening or upgrade config patches instead of telling users to edit openclaw.json manually.

## Best Possible Solution

Define a reusable allowlisted Control UI recommendation-action model that previews validated config patches, requires explicit diff acceptance, records dismissal/confirmation state, and preserves redaction, restart, audit, and concurrency safeguards.
