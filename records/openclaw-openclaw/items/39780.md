## Summary

Keep open: current main still renders the insecure-context Control UI recovery path as manual config guidance, while the existing config diff/apply UI is only for user-staged editor changes. Related upgrade-scanner and QuickStart insecure-auth work overlap, but neither implements this recommendation accept/diff/apply/dismiss flow.

## What This Changes

Request a Control UI flow that turns config hardening and upgrade suggestions into validated before/after diff prompts with accept, dismiss, and automatic config patch application.

## Best Possible Solution

Define a reusable, allowlisted recommendation-action model that previews validated config patches through the existing config RPC path, requires explicit diff acceptance, records dismissals, and preserves redaction, restart, audit, and concurrency safeguards.
