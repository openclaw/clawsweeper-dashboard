## Summary

Keep open: current main and the latest release still render Control UI config hardening/auth guidance as manual instructions, while the existing diff and Apply controls are only for user-staged Config editor changes. The request is useful but needs product/security direction before implementation because browser recommendation cards would mutate security-sensitive auth config.

## What This Changes

Request a Control UI flow where config upgrade or hardening recommendations can show a before/after diff, accept or dismiss user confirmation, apply via config APIs, and show confirmation instead of telling users to edit config files manually.

## Best Possible Solution

Define a reusable, allowlisted Control UI recommendation-action model over existing config.patch/config.apply semantics, with exact before/after diff, explicit accept/dismiss, redaction, restart/audit feedback, and stricter policy for auth or security downgrade paths.

- **Split By Recommendation Class:** Use separate policies for hardening, compatibility, and recovery recommendations so safe-by-default changes can be one-click while downgrade paths require stronger consent.
