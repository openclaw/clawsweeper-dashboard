## Summary

Keep open: current main and v2026.6.11 still present insecure-context and hardening guidance as manual instructions, while the existing before/after diff and Apply controls are scoped to user-edited Config drafts rather than recommendation cards. Related items cover QuickStart defaults, startup warnings, and broader upgrade scanning, but none implements this Control UI-specific apply/diff/accept/dismiss flow.

## What This Changes

The issue requests Control UI recommendation cards that show before/after diffs and can apply, dismiss, and confirm safe config hardening changes through existing config APIs instead of directing users to edit JSON manually.

## Best Possible Solution

Define a reusable, allowlisted Control UI recommendation-action model over the existing config RPCs with exact before/after diff, explicit accept/dismiss, confirmation, redaction, restart/audit handling, and security-sensitive copy.
