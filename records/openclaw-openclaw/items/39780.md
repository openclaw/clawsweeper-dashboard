## Summary

Keep open: current main still presents the insecure-context/auth-hardening guidance as manual config text, while the existing diff and Apply controls are scoped to user-edited Config drafts rather than recommendation cards. The remaining work is useful but needs maintainer product/security direction before implementation.

## What This Changes

Request a Control UI recommendation flow that can show a before/after config diff, accept or dismiss the change, and apply approved hardening or upgrade suggestions through existing config APIs instead of asking users to edit JSON manually.

## Best Possible Solution

Define a reusable, allowlisted Control UI recommendation-action model over existing config.patch/config.apply semantics, with exact before/after diff, explicit accept/dismiss, redaction, restart/audit feedback, and stricter policy for auth/security downgrade paths.
