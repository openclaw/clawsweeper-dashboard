## Summary

Keep open: current main still presents the insecure-context/config-hardening path as manual config guidance, and the existing Config diff/apply machinery is scoped to user-staged editor changes rather than recommendation cards. Related issues and the open QuickStart PR overlap, but none implement this Control UI recommendation apply/diff flow.

## What This Changes

The issue requests Control UI recommendation cards that can apply config changes through an accepted before/after diff instead of instructing users to edit `openclaw.json` manually.

## Best Possible Solution

Define a reusable allowlisted Control UI recommendation-action model over the existing config write APIs, with exact diff, explicit accept/dismiss, redaction, restart/audit feedback, and stricter policy for auth/security downgrade paths.

Rationale: The requested flow would persist auth and hardening config from browser-visible UI, so automation should not choose which security-sensitive settings are safe to mutate or downgrade automatically.

Likely owner: steipete

Owner confidence: high

Options:

- **Allowlisted Recommendation Actions (recommended):** Create a generic allowlisted action model that reuses config.patch/config.apply validation and shows exact diff, confirmation, dismissal, restart/audit, and redaction behavior for approved recommendations.
- **Keep Risky Auth Changes Manual:** Leave auth/security downgrade and recovery suggestions as docs/manual guidance while allowing only low-risk non-auth recommendations to become one-click actions.
- **Split By Recommendation Class:** Use separate policies for hardening, compatibility, and recovery recommendations so safe-by-default changes can be one-click while downgrade paths require stronger consent.

## Solution Assessment
