## Summary

Keep open: current main and v2026.6.11 still present the Control UI insecure-auth guidance as manual copy, while the Config tab diff/apply path only works after a user stages an edit. Related work covers setup defaults and broader upgrade scanning, but none implements this UI-specific recommendation action flow.

## What This Changes

The issue requests Control UI recommendation cards with an Apply Fix button, before/after config diff, accept/dismiss, and confirmation instead of manual JSON edit instructions.

## Best Possible Solution

Define a reusable, allowlisted Control UI recommendation-action model backed by existing config RPCs, with exact before/after diff, explicit accept/dismiss, confirmation, and stronger security copy for auth or hardening changes.

## Reproduction Assessment

Yes for the reported current behavior, though this is not a bug repro: source inspection shows current main still renders manual insecure-auth guidance and only offers diff/apply after a user stages Config tab edits.

## Solution Assessment

Unclear until maintainers choose the product and security boundary. The best shape appears to be a generic allowlisted recommendation-action flow over existing config APIs, not a hardcoded allowInsecureAuth button.
