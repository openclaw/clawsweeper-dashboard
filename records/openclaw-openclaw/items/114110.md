## Summary

The proposed guard matches the documented snapshot distinction and is supported by filesystem-backed before/after evidence showing that a full reset preserves the default workspace when the config read fails. No discrete correctness or security defect is evident in the two-file patch; keep this PR open for the normal current-main refresh and merge gates rather than closing it as cleanup.

## What This Changes

This PR changes onboarding’s full-reset safety check to use the config snapshot’s read-error signal, preventing an unreadable config from causing the default workspace to be moved to Trash, and adds regression coverage for both unreadable and readable-without-workspace cases.

## System Context

The onboarding command reads a configuration snapshot to resolve the workspace that a full reset may remove. If the config cannot be read, the command must refuse an implicit destructive reset; otherwise it may use the normal default-workspace fallback.
