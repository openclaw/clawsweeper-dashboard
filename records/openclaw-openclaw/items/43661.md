## Summary

Keep open: current main has some guardrails around compaction timeouts and unsafe outbound replay, but it does not yet solve the reported family end to end. The active compaction PR only covers partial-progress timeout recovery and is currently conflicting, while the duplicate Telegram send/idempotency side is still tracked by separate open reports and still needs maintainer direction plus live Telegram proof.

## What This Changes

The issue asks OpenClaw to handle compaction timeouts so a large Telegram session recovers or fails once without wedging the lane, duplicating replies, or requiring manual service/session reset.

## Best Possible Solution

Land a maintainer-approved recovery design that combines compaction timeout progress preservation with at-most-once outbound delivery semantics, then close this only after live Telegram proof shows no wedged lane and no duplicate visible reply.
