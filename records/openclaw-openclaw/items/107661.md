## Summary

Keep open for a focused security-boundary decision. Current main contradicts the broad report: sandbox defaults are resolved independently of an `agents.list` entry, `agents.defaults.tools` is not a valid documented/configured policy surface, bindings remap or reject unknown configured agents, and normal explicit-agent selection validates the ID. A narrower gap remains because parsed session identities can retain an unconfigured agent ID; the reachable turn ingresses and resulting effective tool policy need proof before closing.

**Likely related people:** `@steipete` has high-confidence recent history across sandbox and agent-scope behavior; `@vincentkoc` has medium-confidence history around per-agent default resolution.

## What This Changes

Determine whether every reachable turn for an unconfigured agent identity must be rejected or receive an explicit containment baseline before tools are constructed.

## Best Possible Solution

Reject unconfigured agent identities before tool construction at every supported turn ingress unless maintainers explicitly support ephemeral identities; if they do, document that contract and test the global sandbox and global `tools` policy baseline rather than adding the currently invalid `agents.defaults.tools` surface.
