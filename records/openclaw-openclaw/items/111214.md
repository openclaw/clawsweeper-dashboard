The PR moves Telegram, WhatsApp, Feishu, QQBot, ZaloUser, and Nostr durable ingress handling onto a shared `createChannelIngressMonitor` abstraction and updates associated tests and SDK API baseline hashes.

## Best Possible Solution

Keep the shared monitor, but preserve each channel’s prior admission-time retention semantics—either retain lightweight enqueue-time pruning or make the shared monitor enforce the relevant cap synchronously at admission—then add a real redacted runtime proof for at least the affected durable ingress paths.
