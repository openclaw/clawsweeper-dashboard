## Summary

Current main and the latest release already render `openclaw logs` timestamps in local time by default, keep `--local-time` as the compatibility spelling, and provide `--utc` for the old UTC display.

## What This Changes

The issue requests that `openclaw logs` display the log entry local-time field by default instead of UTC timestamps.

## Best Possible Solution

Keep the shipped local-time default with `--utc` as the explicit opt-out, and avoid adding another timezone config surface for this CLI path.

Required: false

## Reproduction Assessment

No for current main: source inspection shows `openclaw logs` now defaults to local-time formatting and the regression test covers a non-UTC timezone path. The original v2026.3.13 behavior is obsolete in the current release line.

## Solution Assessment

Yes: using the existing parsed `time` field and shared timestamp formatter, with `--utc` as an explicit opt-out, is narrower than adding a new timezone config option.
