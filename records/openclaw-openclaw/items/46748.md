## Summary

Current main and the v2026.6.11 release already implement the reported `openclaw logs` local-time behavior, including parser preference for the log `time` field, local rendering by default, `--utc` opt-in, tests, and docs.

## What This Changes

The issue requests that `openclaw logs` display timestamps in the user's local timezone instead of UTC by default.

## Best Possible Solution

Keep the shipped local-time default with `--utc` as the explicit UTC opt-in; any remaining Docker console or journal timestamp concern should be filed as a separate focused report if still reproducible.

## Solution Assessment

Yes. The shipped fix is the narrow maintainable solution: prefer the log `time` field, render local time by default, preserve `--local-time`, and provide `--utc` for operators that need UTC output.
