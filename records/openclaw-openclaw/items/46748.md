## Summary

Current main and the latest release already implement the requested behavior: `openclaw logs` renders top-level `time` in local time by default, keeps `--utc` as the opt-out, and the behavior is covered by docs and tests.

## What This Changes

The issue requests that `openclaw logs` display local-time timestamps instead of UTC timestamps when log records include a local `time` field.

## Best Possible Solution

Keep the shipped `openclaw logs` local-time default with `--utc` opt-out; handle separate Control UI timezone preferences in the existing Control UI-specific thread.
