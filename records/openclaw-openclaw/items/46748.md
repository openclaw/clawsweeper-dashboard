## Summary

Current main and the shipped v2026.6.11 release already render `openclaw logs` timestamps in local time by default, keep `--utc` as the opt-out, and prefer the parsed log `time` field before UTC metadata.

## What This Changes

The issue asks for `openclaw logs` to display timestamps in the user's local timezone instead of UTC by default.

## Best Possible Solution

Keep the shipped local-time default with `--utc` for operators or scripts that need UTC; file a separate focused issue only if service-console or journal timestamps still misbehave outside the `openclaw logs` path.

Yes. The shipped fix is the narrow maintainable solution: parse the log `time` field when present, render local time by default, and keep UTC available through `--utc` without adding new config.
