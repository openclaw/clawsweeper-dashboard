## Summary

Current main and the shipped v2026.6.11 release already implement local-time `openclaw logs` rendering, preserve `--local-time`, add `--utc` for UTC output, and prefer the log `time` field before `_meta.date`.

## What This Changes

The issue asks for `openclaw logs` timestamps to display local time rather than UTC by default.

## Best Possible Solution

Keep the shipped local-time default with `--utc` as the explicit UTC opt-in; any remaining Docker, journal, or console-only timezone mismatch should be filed as a new focused report against a current release.

## Maintainer Decision

## Reproduction Assessment

Yes for the historical bug: the report and related pre-fix discussions identify the CLI using UTC-style timestamps while local `time` data existed. Current main no longer has that failing source path because parser, formatter, tests, and docs now encode local time by default.

## Solution Assessment

Yes. The shipped solution is the narrow maintainable fix for this issue: prefer the log `time` field, render local time by default, keep `--local-time` accepted, and provide `--utc` for operators that need UTC output.
