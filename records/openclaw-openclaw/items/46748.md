## Summary

Current main and the shipped v2026.6.11 release already implement the central request: `openclaw logs` renders local timestamps by default, keeps `--local-time` accepted, and provides `--utc` for UTC output.

## What This Changes

The issue requests that `openclaw logs` display log timestamps in the system local timezone instead of UTC by default.

## Best Possible Solution

Keep the shipped local-time default with `--utc` as the explicit opt-in; console or journal timestamp behavior should be tracked separately if it still reproduces on the current release.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes for the historical bug: the report and prior related reviews identify a source path where `openclaw logs` rendered UTC by default. Current main no longer has that failing path because parser, formatter, tests, and docs encode local time by default.

## Solution Assessment

Yes. The shipped fix is the narrow maintainable solution: prefer the log `time` field, render local time by default, preserve `--local-time`, and provide `--utc` for operators that need UTC.
