## Summary

Current main and the shipped v2026.6.11 release already implement the requested behavior: `openclaw logs` renders text timestamps in local time by default, parses the top-level `time` field before `_meta.date`, and keeps UTC available through `--utc`.

## What This Changes

The issue asks for `openclaw logs` to display local-time timestamps instead of UTC by default.

## Best Possible Solution

Keep the shipped local-time default with `--utc` as the UTC opt-out; any remaining service-console or container timezone concern should be filed as a separate focused report with current-version output.

## Solution Assessment
