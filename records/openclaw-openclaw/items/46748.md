## Summary

Current main and the shipped v2026.6.11 release already implement the reported `openclaw logs` local-time behavior: the CLI parses the log `time` field before `_meta.date`, renders local time by default, and keeps UTC as an explicit `--utc` opt-in.

## What This Changes

The issue requests that `openclaw logs` display timestamps in the user's local timezone by default instead of UTC.

## Best Possible Solution

Keep the shipped local-time default with `--utc` opt-out; any future concern about service-console or journal timestamp prefixes should be filed as a separate focused issue if still reproducible.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes for the historical bug: `v2026.3.13-1` defaulted logs timestamp formatting to UTC unless `--local-time` or `TZ` was used, while current source and tests show local time by default. I did not run the CLI because this cleanup review was read-only.

## Solution Assessment

Yes. The merged fix is the narrow maintainable path: parse the log `time` field when present, render local time by default, and keep UTC available through `--utc` without adding new config.
