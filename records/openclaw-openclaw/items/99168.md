- `P1`: The report describes a broken agent/tool-result workflow where later tool outputs become untrustworthy within a live channel session.

## Summary

Current main already covers the reported large-tool-output poisoning path: oversized and aggregate tool-result truncation now preserves fresh trailing tool results, and regression tests assert later short outputs remain non-empty.

## What This Changes

The issue asks OpenClaw to prevent one oversized or binary-like truncated tool result from causing later tool results in the same session to display as `(no output)`.

## Best Possible Solution

Keep the current main truncation/projection behavior and let the next release carry it; broader repeated-empty-output release regressions should stay in their own canonical reports.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source/regression-test level: the committed tests model saturated prior tool-result history followed by fresh short output, although I did not rerun the live Discord/Linux path.

## Solution Assessment

Is this the best way to solve the issue? Yes: the fix belongs in core tool-result truncation/projection so prior oversized output is bounded while later fresh tool-result text remains visible, without a channel-specific workaround.
