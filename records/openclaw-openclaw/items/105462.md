## Summary

Keep open for product clarification: current main has single-attempt SSH bootstrap and tears down a newly provisioned worker after the first failure, but the request mixes the cloud-worker lifecycle with the separate SSH sandbox configuration surface. The resilience gap is plausible and not implemented, while the correct ownership boundary and need for operator-facing tuning remain undecided.

## What This Changes

Add bounded retries with exponential backoff for transient SSH connection failures when preparing remote worker environments.

## Best Possible Solution

Define initial SSH readiness in the cloud-worker contract, then implement abortable, capped retries only for classified transient bootstrap connection failures while preserving pinned host keys and deterministic lease teardown after exhaustion; avoid new public settings unless real deployments demonstrate a tuning requirement.
