## Summary

The stable-key and runtime-fingerprint design appears coherent, but this protected CI PR should remain open until a post-purge writer-to-warm-consumer run proves the central behavior and maintainers accept or eliminate the two-writer freshness race.

## What This Changes

This PR replaces per-PR and per-manifest Blacksmith dependency disks with stable per-Node-version snapshots, validates freshness through a runtime fingerprint, and assigns protected writer jobs while other CI jobs consume without publishing.

## Best Possible Solution

Purge the exhausted v2 disks, capture an exact-head successful writer followed by a warm consumer that skips installation, and serialize or explicitly document acceptance of last-writer freshness for the shared key.
