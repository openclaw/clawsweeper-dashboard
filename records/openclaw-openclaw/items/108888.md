## Summary

This is a current, well-supported bug in the official iOS onboarding path: the app can receive only a node credential, then disables reconnect and reports a false persistence failure even though its operator credential was never issued. The issue should remain open while maintainers choose a repair that preserves explicit role authorization.

## What This Changes

Make iOS local-discovery pairing produce a usable node-plus-operator authorization state, or provide accurate in-app recovery when the gateway grants only the node role.

## Best Possible Solution

Have the iOS client request both required roles through one visible owner approval, and turn a later setup-code scan against a node-only record into an explicit operator role-upgrade request; preserve the role ceiling while adding an in-app Fix/Re-pair flow and accurate role-mismatch diagnostics.

## Maintainer Decision

Question: Should an iOS device obtain its required operator role through an explicit dual-role or role-upgrade approval, or may successful setup-code redemption extend the device’s approved roles automatically?

Rationale: The repair changes how a stronger bootstrap credential interacts with the durable owner-approved role boundary, so automation should not choose whether role expansion is implicit or explicitly approved.

Likely owner: Peter Steinberger

Owner confidence: medium

Options:

- **Explicit dual-role approval (recommended):** Make iOS request node and bounded operator roles together, and create a visible operator upgrade request when an existing node-only record is encountered.
- **Bootstrap role extension:** Allow successful setup-code redemption to add roles authorized by its bootstrap profile to the existing device without a second owner approval.
- **Diagnostics-only mitigation:** Keep authorization unchanged but replace the persistence error with accurate role-mismatch recovery instructions and an in-app re-pair action.

## Reproduction Assessment

Yes. The report gives a complete v2026.7.1 real-device sequence, and current main retains the exact node-plus-operator gate, misleading error path, and approved-role ceiling needed to reproduce it.

## Solution Assessment

No single proposed direction is sufficient by itself. The safest maintainable fix combines explicit dual-role or role-upgrade approval with truthful iOS diagnostics and in-product recovery, rather than silently weakening the approved-role boundary.
