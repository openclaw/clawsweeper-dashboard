## What This Changes

This PR adds `contents: read` to both primary and fallback GitHub App token requests in the Labeler workflow so label-routing configuration can be read during automated issue and pull-request labeling.

## System Context

The Labeler GitHub Actions workflow handles issue and pull-request events by minting an installation token, reading repository label-routing configuration, and applying labels through GitHub APIs. It has a fallback GitHub App token path for primary-token failures, so both token permission sets affect whether automated labeling can recover successfully.
