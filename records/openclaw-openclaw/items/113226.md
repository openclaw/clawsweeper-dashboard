## What This Changes

The PR adds explicit `contents: read` permissions to GitHub App installation tokens in the auto-response and labeler workflows so Workflow Sanity can audit their declared scopes.

## System Context

GitHub Actions automation mints short-lived GitHub App tokens for repository label and response jobs. The workflow audit examines those declared token scopes, while the tokens then authorize issue or pull-request automation against GitHub APIs.

## Best Possible Solution

Keep explicit `contents: read` only for the labeler token requests that load repository configuration; remove it from both auto-response token requests and rerun the workflow audit plus responder validation.
