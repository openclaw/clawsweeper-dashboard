## What This Changes

The PR adds explicit `contents: read` permissions to both primary and fallback GitHub App tokens used by the Labeler workflow so it can read repository routing configuration while applying labels.

## System Context

The Labeler GitHub Actions workflow creates an installation token, reads repository-maintained label and routing configuration, then applies labels through the GitHub API. Its fallback token is used only when the primary GitHub App token cannot be created, so both token scopes must be valid for the workflow’s recovery path.

## Best Possible Solution

Keep the primary and fallback tokens scoped identically only after a workflow owner confirms the fallback App installation grants `contents: read` and provides a redacted controlled failure-path transcript showing the fallback token reads routing configuration and completes labeling.
