## What This Changes

Adds `contents: read` to the primary and fallback GitHub App token requests in the labeler workflow so its configuration file can be read while labeling issues and pull requests.

## System Context

The labeler workflow receives GitHub issue and pull-request events, mints a token from a primary GitHub App or a fallback App, and then uses that token to read label routing configuration and apply labels. The proposed permission requests affect the failure-recovery token path used when the primary App cannot mint a token.
