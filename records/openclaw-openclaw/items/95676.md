## Summary

This PR has a focused implementation and supplied exact-head runtime proof, but it deliberately changes the default failure policy for ordinary assistant timeouts. Keep it open for a maintainer decision on whether one extra same-profile timeout window is preferable to the current immediate auth-profile rotation or model fallback.

## What This Changes

The PR retries an ordinary assistant-stage timeout once on the same model and auth profile before normal profile rotation or model fallback, and removes empty aborted assistant leaves before replay repair.

## System Context

The embedded agent runner sends a user turn to a selected model and auth profile, then routes failures through retry, profile-rotation, and model-fallback decisions. It also maintains the session transcript that becomes the next model context and user-visible conversation.

## Architecture Diagram

flowchart LR
  A[User prompt] --> B[Embedded agent runner]
  B --> C[Selected model and auth profile]
  C --> D{Assistant failure}
  D -->|First ordinary timeout| E[Retry same model and profile]
  D -->|Other or repeated failure| F[Profile rotation or model fallback]
  E --> G[Repair aborted transcript leaf]
  F --> G
  G --> H[Persist session and response]

## Best Possible Solution

Make the timeout-policy choice explicit: if maintainers want transient ordinary timeouts to receive one bounded retry, merge this focused implementation with its transcript safeguard; otherwise retain the current immediate failover policy and carry only any independently needed replay-safety repair in a narrower change.
