## Summary

The functional fix appears correct and current main still has the reported synchronous callback-ordering bug, but this external PR lacks after-fix real SDK behavior proof and should remain open until a redacted live retry run is provided.

## What This Changes

The PR stores each SDK gateway connection attempt before startup and uses attempt-local callback ownership so a synchronous connection error can be retried.

## Best Possible Solution

Land the attempt-local promise ownership fix after adding a redacted live SDK script or terminal transcript showing the same transport instance reject an insecure connection attempt and successfully retry a valid connection.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source inspection: an insecure remote `ws://` URL makes `GatewayClient.start()` synchronously invoke `onConnectError`, and current main then caches the rejected promise after the callback returns. The PR's focused mock test reproduces that ordering, though no real runtime reproduction was supplied.

## Solution Assessment

Yes. Storing the attempt before startup and clearing state only when callbacks own that attempt is the narrowest maintainable fix, preserving close and stale-callback ownership without adding configuration or compatibility paths.
