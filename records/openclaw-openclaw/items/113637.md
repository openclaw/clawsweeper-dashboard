## Summary

Keep this PR open. Its Doctor migration can change an existing multi-agent installation with a shared `agents.defaults.heartbeat` block from running heartbeats for every agent to running them only for the former default agent; that contradicts the stated behavior-neutral upgrade goal. Likely related people: steipete is the available routing candidate from the proposed agent-ownership work, though current-main ownership provenance was not available in the supplied context (low confidence).

## What This Changes

Adds explicit configurable owners for ambient heartbeat, system-agent/Custodian, and Talk work, and makes `openclaw doctor --fix` persist legacy multi-agent default routing into those targets and channel-wide bindings.

## System Context

Agent routing assigns ambient OpenClaw work to an agent when no request or session already supplies one. Doctor upgrades multi-agent configuration by writing explicit ownership settings that runtime routing, heartbeat scheduling, system-agent inference, and Talk session creation then consume.

## Architecture Diagram

  Config --> Talk[Talk sessions]
  Config --> Channels[Channel-wide bindings]
  Heartbeat --> Runs[Agent runs]
  System --> Runs

## Best Possible Solution

Restrict default-role materialization to truly default-routed heartbeat cases, preserving all-agent enrollment for existing shared `agents.defaults.heartbeat` configurations; add fresh-install and upgrade coverage for both fan-out and explicit single-owner behavior.
