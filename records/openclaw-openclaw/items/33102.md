## Label Justifications

- `P2`: The issue is a normal-priority TUI delivery ergonomics/config improvement with a clear workaround and limited blast radius.
- `impact:message-loss`: The request is about replies not being delivered unless the user remembers the TUI `--deliver` launch flag.

## Summary

Keep open: current main and the latest release still require the `--deliver` flag at TUI launch time and do not expose a config default for it. The related stuck-spinner failure was fixed separately, while this remaining request is a product/config-surface decision rather than an already-implemented bug fix.

## What This Changes

Request a persistent OpenClaw config default for `openclaw tui --deliver` so users do not need to pass the flag on every TUI invocation.

## Best Possible Solution

If maintainers approve the direction, add one schema-backed TUI delivery default with docs and focused TUI/CLI tests, while keeping explicit `--deliver` behavior as the per-invocation override.
