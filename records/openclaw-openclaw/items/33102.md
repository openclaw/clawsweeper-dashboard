## Summary

Keep open: current main and the latest release still do not provide a persistent TUI delivery default, and the requested fix would add a public config/default surface that needs maintainer product direction. The adjacent stuck-spinner failure has already been fixed and closed separately, so the remaining work is the `--deliver` default contract itself.

## What This Changes

The issue requests a config setting, such as `tui.deliver`, that lets users set the default for `openclaw tui --deliver` instead of passing the flag on every launch.

## Best Possible Solution

Make a maintainer-owned decision on whether TUI delivery should be configurable, then either add one canonical typed config key with docs and tests or explicitly keep delivery launch-only.
