## Summary

Keep open. Current main still has only a CLI-flag-driven TUI delivery default and no `tui.deliver` config, while the separate stuck-spinner failure from delivery-off runs has already been fixed and closed elsewhere.

## What This Changes

Request support for a persistent TUI delivery default so users can avoid passing `openclaw tui --deliver` on every invocation.

## Best Possible Solution

Choose the canonical delivery-default model first; if maintainers approve config, implement a tri-state `tui.deliver` path with `--deliver`/`--no-deliver` precedence, schema/help/docs, and focused CLI/TUI tests.
