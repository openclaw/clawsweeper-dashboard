## Summary

Keep open: current main and the latest release still use a flag-only TUI delivery default and do not expose a persistent `tui.deliver` config key. The adjacent stuck-spinner/abort work was handled separately, while this issue remains the canonical product/config decision.

## What This Changes

Add a persistent OpenClaw config option that controls the default value of `openclaw tui --deliver`.

## Best Possible Solution

Make a maintainer decision on TUI delivery policy, then land one focused PR that adds the canonical config key and override semantics with schema, types, help, docs, and tests, or explicitly keep delivery flag-only.

## Reproduction Assessment

Yes, at source level: current main registers `--deliver` with default `false`, passes only the parsed flag into `runTui`, and exposes no config key for that default. I did not run a live TUI session in this read-only cleanup review.

## Solution Assessment

Unclear: a config default is a plausible small solution, but the key shape, default policy, and `--deliver` or `--no-deliver` override semantics need maintainer agreement before implementation.
