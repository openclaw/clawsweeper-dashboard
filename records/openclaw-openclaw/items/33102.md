## Summary

Keep open: current main and latest release still expose `openclaw tui --deliver` as a false-by-default CLI-only flag, and the canonical config schema still has no `tui.deliver` key. The adjacent stuck-spinner issue was closed as implemented, but that review explicitly left this config/default ergonomics issue as the remaining canonical follow-up.

## What This Changes

The issue asks for a persistent OpenClaw config default for the TUI `--deliver` flag so users do not need to pass it on each invocation.

## Best Possible Solution

Decide the intended TUI delivery contract, then either add a canonical tri-state `--[no-]deliver` plus schema/help/docs/tests or document that provider delivery should stay explicit per invocation.

## Reproduction Assessment

Yes. Source inspection shows the current CLI defaults delivery off and the current config schema has no `tui.deliver` key; I did not run a live TUI session because this review is read-only.

## Solution Assessment

Unclear. A `tui.deliver` config key is plausible, but the best fix needs maintainer direction because this adds config surface and may overlap with runtime settings or a broader TUI delivery-default decision.
