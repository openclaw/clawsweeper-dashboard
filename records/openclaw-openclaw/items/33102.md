## Summary

Keep open: current main and the latest release still lack a persistent TUI delivery default, and the remaining request is a config/default product decision rather than an already-fixed bug. The stuck-spinner failure discussed later was handled separately by https://github.com/openclaw/openclaw/pull/77199 and https://github.com/openclaw/openclaw/issues/66991.

## What This Changes

The issue requests a persistent OpenClaw config default for the TUI `--deliver` flag so users do not need to pass it on every `openclaw tui` invocation.

## Best Possible Solution

Have a maintainer choose one canonical persistent TUI delivery-default contract; if approved, implement it through the current config type, strict schema, help/docs, CLI precedence, and focused TUI tests while preserving explicit flag overrides.
