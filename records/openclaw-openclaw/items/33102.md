## Summary

Keep open: current main and the latest release still lack a persistent TUI delivery default, and the remaining request is a config/default product decision rather than an already-fixed bug. The stuck-spinner failure reported in the discussion was handled separately by https://github.com/openclaw/openclaw/pull/77199 and https://github.com/openclaw/openclaw/issues/66991.

## What This Changes

The issue asks for a configurable default for `openclaw tui --deliver` so users do not need to pass the flag on every TUI invocation.

## Best Possible Solution

Have a maintainer choose one persistent TUI delivery-default contract; if approved, implement it through the canonical config type, schema, help/docs, CLI precedence, and focused tests while preserving explicit flag overrides.
