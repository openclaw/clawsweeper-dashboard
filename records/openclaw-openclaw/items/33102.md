## Summary

Keep open: current main and the latest release still default TUI delivery off and expose no persistent config key for that default. The stuck-spinner lifecycle bug was fixed separately, so the remaining work is a bounded but product-sensitive config/default decision.

## What This Changes

The issue requests a persistent config default for `openclaw tui --deliver` so users do not need to pass the flag on every invocation.

## Best Possible Solution

Make a maintainer decision on TUI delivery policy, then land one focused PR that adds the canonical config key, CLI override behavior, schema/type/help/docs, and regression coverage, or explicitly keep delivery flag-only.
