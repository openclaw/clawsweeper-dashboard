## Summary

Keep open: current main and the latest release still default TUI delivery off and do not expose a `tui.deliver` config default. The merged related work fixed an adjacent stuck-spinner/run-lifecycle failure, but the requested config/default policy remains a maintainer product decision.

## What This Changes

The issue requests a config-backed default for the TUI `--deliver` behavior so users do not need to pass the flag on every launch.

## Best Possible Solution

Maintainers should choose the TUI delivery policy first; if accepted, add one canonical config-backed default wired through CLI launch, TUI runtime, schema/help/docs, and focused tests while preserving explicit flag override behavior.

## Reproduction Assessment

Yes. Source inspection shows current main and `v2026.6.11` still default `--deliver` to `false`, pass that value into TUI sends, and lack any `tui.deliver` schema field; I did not run a live TUI session.

## Solution Assessment

Unclear. A config default is a plausible fix, but OpenClaw's config-surface bar means maintainers should first decide whether the best product shape is config, an in-TUI persistent preference, or keeping explicit `--deliver`.
