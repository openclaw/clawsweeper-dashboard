- `impact:message-loss`: When users expect provider delivery, omitting `--deliver` can leave assistant replies stored but not delivered to the expected channel.

## Summary

Keep open: current main and the latest release still only support `--deliver` as a launch flag defaulting to false, with no persistent TUI delivery default in config. The adjacent stuck-spinner failure from the discussion was handled separately by https://github.com/openclaw/openclaw/pull/77199, but the remaining request is a config/default product decision.

## What This Changes

Request to add a persistent OpenClaw config default for the TUI `--deliver` flag so users do not have to pass the flag every run.

## Best Possible Solution

If maintainers approve the product direction, add one canonical TUI delivery default in the current config schema, help metadata, docs, and focused TUI/CLI tests while preserving explicit flag override semantics.
