## Summary

Keep open: current main and the latest release still lack a persistent config default for TUI delivery. The related stuck-spinner failure was fixed separately, but this remains a product/config-surface decision.

## What This Changes

The issue asks for a configurable default for `openclaw tui --deliver` so users do not need to pass the flag on every TUI launch.

## Best Possible Solution

Decide the product direction first; if accepted, add a narrow canonical TUI delivery default with schema/types/docs and tests proving CLI flags still override config.

Options:

- **Approve narrow config default (recommended):** Add a canonical `tui.deliver`-style opt-in default read by the TUI CLI, with schema/docs/tests and explicit flag precedence.
- **Keep launch-only delivery:** Leave `--deliver` as the only persistent mechanism and improve docs or first-run guidance instead of adding config surface.
- **Design a session/UI preference:** Treat delivery as a TUI/session preference rather than an `openclaw.json` key, which needs broader UX design first.
