## Summary

Keep open: current main and the latest release still default TUI delivery off and expose no persistent config key for that default. The adjacent stuck-spinner/abort path was fixed separately, so the remaining work is a bounded but product-sensitive config/default decision.

## What This Changes

The issue requests a persistent config default for the TUI `--deliver` flag so users do not need to pass `openclaw tui --deliver` each time.

## Best Possible Solution

Maintainers should decide the canonical TUI delivery preference contract, then implement one schema/help/docs/tested path that preserves explicit flag precedence and avoids legacy alias keys.

## Solution Assessment

Unclear until maintainer product direction is confirmed. A small implementation is plausible, but the best fix depends on choosing the canonical config shape and whether persistent delivery should live in config, session state, or only runtime UI state.
