## Label Justifications

- `P2`: The request affects a real TUI delivery workflow with a documented workaround, so it is normal-priority user-facing ergonomics rather than an emergency blocker.
- `impact:message-loss`: Without `--deliver`, users expecting visible/channel delivery can miss assistant replies unless they know to opt in on every launch.
- `impact:ux-friction`: The supported workaround requires remembering `--deliver` or maintaining aliases instead of setting a persistent preference.

## Summary

Keep open: current main and v2026.6.11 still keep TUI delivery as a launch-flag-only behavior; the related stuck-spinner failure was fixed separately, but a persistent delivery default remains a config/product decision.

## What This Changes

Request to let users configure a default for `openclaw tui --deliver` so TUI launches can deliver replies without passing the flag every time.

## Best Possible Solution

Have a maintainer decide whether TUI delivery deserves a persistent config default; if approved, add one canonical launch-time key with schema/help/docs/tests and explicit CLI override behavior, otherwise keep delivery launch-only and document the supported workaround.
