## Summary

Keep open: current main and the latest release still default TUI delivery off and expose no persistent config key for that default. The adjacent stuck-spinner failure was fixed separately, so the remaining work is a bounded but product-sensitive config/default decision.

## What This Changes

Requested support for a persistent OpenClaw config default for the TUI `--deliver` flag so users do not have to pass it on every invocation.

## Best Possible Solution

Make a maintainer decision on TUI delivery policy, then land one focused PR that adds the canonical config key and override semantics with schema, type, help, docs, and test coverage, or explicitly keep delivery flag-only.

## Reproduction Assessment

Yes, at source level: current main registers `--deliver` with default `false`, passes only the parsed flag into `runTui`, and exposes no TUI delivery default in the config schema/type. I did not run a live TUI session in this read-only cleanup review.

## Solution Assessment

Unclear: a config default is a plausible small solution, but the key shape, default policy, and `--deliver`/`--no-deliver` override semantics need maintainer agreement before implementation.
