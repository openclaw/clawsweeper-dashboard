## Label Justifications

- `P2`: This is a normal-priority TUI behavior/config improvement with a clear workaround and limited blast radius.
- `impact:message-loss`: With delivery off by default, a TUI turn can complete and persist a reply without visibly delivering it to the user unless `--deliver` is passed.
- `impact:ux-friction`: Users can proceed by passing `--deliver` or using aliases, but the repeated flag/default mismatch creates avoidable TUI confusion.

## Summary

Keep open: current `main` and latest release still default TUI delivery off and expose no `tui.deliver` config key, while related merged work only fixed the adjacent stuck-spinner/abort lifecycle bug. The remaining request is valid but product-sensitive because it adds or changes config/default behavior.

## What This Changes

The issue asks for a configurable default for `openclaw tui --deliver` so users do not have to pass the flag every time.

## Best Possible Solution

A maintainer should choose the delivery-default policy first; if config is accepted, add a canonical `tui` delivery preference through config types, zod schema, help/labels, docs, and focused TUI CLI tests while preserving explicit CLI override semantics.
