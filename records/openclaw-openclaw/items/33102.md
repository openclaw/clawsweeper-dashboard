## Summary

Keep open: current main and `v2026.6.11` still only support launch-time `--deliver` with a false default, and the config schema/docs still lack a persistent `tui.deliver` default. The stuck-spinner path from the discussion was fixed separately by https://github.com/openclaw/openclaw/pull/77199 and https://github.com/openclaw/openclaw/issues/66991, leaving this as a config/default product decision.

## What This Changes

Add a persistent OpenClaw config default for `openclaw tui --deliver` so users do not have to pass the launch flag every time.

## Best Possible Solution

Have a maintainer choose one persistent TUI delivery-default contract; if approved, implement it through the canonical config type, strict schema, help/docs, CLI precedence, and focused tests while preserving explicit flag overrides.
