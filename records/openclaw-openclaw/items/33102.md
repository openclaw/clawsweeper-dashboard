## Summary

Keep open: current main and the latest release still default TUI delivery off and expose no persistent config key for that default. The adjacent stuck-spinner/abort work was handled separately, so the remaining work is a bounded but product-sensitive config/default decision.

## What This Changes

Request to add a persistent config default for `openclaw tui --deliver` so users do not need to pass the flag on every run.

## Best Possible Solution

Make a maintainer decision on TUI delivery policy, then land one focused PR that adds the canonical config key with schema/type/help/docs/tests and explicit CLI override semantics, or document flag-only behavior as intentional.
