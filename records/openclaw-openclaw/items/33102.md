## Summary

Keep open: current main and the latest release still expose TUI delivery only as a default-off launch flag, and the requested persistent default would add a new config/default surface that needs maintainer product direction.

## What This Changes

The issue requests a persistent configuration default for `openclaw tui --deliver` so users do not need to pass the flag every run.

## Best Possible Solution

Decide the canonical product contract first; if accepted, add a small `tui` delivery default surface with schema/help/docs/tests while preserving explicit CLI override behavior.
