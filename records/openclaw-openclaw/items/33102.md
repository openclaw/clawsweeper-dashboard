## Summary

Keep open: current main and the latest release still keep TUI delivery as an explicit `--deliver` launch flag, and no persistent `tui.deliver` config default exists. The adjacent stuck-spinner/abort path was fixed separately, but this requested config/default behavior remains a product/config-surface decision.

## What This Changes

The issue requests a configurable default for `openclaw tui --deliver` so users can enable reply delivery without passing the flag every time.

## Best Possible Solution

If maintainers accept the new preference, add one canonical `tui.deliver` boolean with schema/types/docs and focused TUI CLI tests that preserve explicit flag precedence; otherwise keep the explicit flag-only contract documented.
