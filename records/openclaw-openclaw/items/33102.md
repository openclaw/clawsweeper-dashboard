## Label Justifications

- `P2`: This is a normal-priority TUI config/default improvement with a clear workaround, not an emergency or urgent live regression.
- `impact:message-loss`: The requested default controls whether assistant replies are delivered through configured channels, and the report describes replies being stored instead of visibly delivered without the flag.
- `impact:ux-friction`: Users currently need to remember `--deliver` or maintain aliases because there is no persistent TUI default.

## Summary

Keep open: current main and the latest release still have `--deliver` as an explicit false-by-default TUI flag and no persistent config default. The related stuck-spinner/no-active-run bug was fixed separately, but this request remains a product/config decision.

## What This Changes

Request a persistent OpenClaw config default for TUI `--deliver` so users do not have to pass the flag on every launch.

## Best Possible Solution

Maintainers should choose one TUI-owned default policy, then implement a single canonical config/schema/docs/test path that preserves explicit CLI override behavior and avoids reviving the closed default-flip churn.

- **Keep explicit flag only:** Decline new config/default behavior, keep `--deliver` and shell aliases as the supported path, and close this issue with rationale.

## Solution Assessment

Unclear until a maintainer chooses the product direction. A narrow config default would satisfy the issue, but a default flip or keeping the explicit flag are also policy-level choices because config/default surfaces are compatibility-sensitive.
