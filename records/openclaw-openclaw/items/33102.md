- `impact:message-loss`: Users can send TUI turns where assistant replies are stored but not visibly delivered unless delivery is opted in for that invocation.

## Summary

Keep open: current main and the latest release still default TUI delivery off and expose no persistent config key for that default. The related stuck-spinner and abort fixes are adjacent work, not a replacement for the requested config/default decision.

## What This Changes

Request to let `openclaw tui` read a persistent config default for the `--deliver` flag so users do not need to pass it every run.

## Best Possible Solution

Make a maintainer decision on the canonical TUI delivery-default contract, then land one focused config/schema/docs/test change or explicitly document flag-only behavior.

## Reproduction Assessment

Yes. Source inspection on current main shows `--deliver` defaults to `false`, `runTui` derives delivery only from the parsed option, and the config schema/type expose no persistent delivery default.

## Solution Assessment

Unclear. A config default is a plausible small solution, but the canonical key, default policy, and `--deliver` versus future `--no-deliver` override semantics need maintainer agreement first.
