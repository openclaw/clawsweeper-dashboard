## Label Justifications

- `P2`: This is a normal-priority TUI/config improvement with a clear workaround, not an emergency or current release-blocking regression.
- `impact:message-loss`: Without a persistent delivery default, users expecting provider delivery can silently run TUI turns with delivery disabled unless they remember the flag each launch.
- `impact:ux-friction`: The current launch-only flag forces repeated manual flags or aliases and has already confused users about why replies are not delivered where expected.

## Summary

Keep open: current main and the latest release still lack any supported config key for a TUI delivery default, while the adjacent stuck-spinner failure was fixed separately by https://github.com/openclaw/openclaw/pull/77199. The remaining request is a real but compatibility-sensitive config/product decision, not a narrow automatic bug fix.

## What This Changes

The issue asks for a persistent OpenClaw config default for `openclaw tui --deliver` so users do not have to pass the flag on every TUI launch.

## Best Possible Solution

If maintainers accept the product direction, add one canonical documented TUI delivery default with schema/help/docs/tests and clear flag precedence; otherwise keep delivery launch-only and make the docs/status copy unambiguous.
