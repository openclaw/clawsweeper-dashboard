## Summary

Keep open: current main and the latest release still default `openclaw tui --deliver` off and expose no `tui.deliver` config key. The related stuck-spinner bug was handled separately, but the persistent delivery default remains a config-surface product decision.

## What This Changes

Request to let users configure a default for `openclaw tui --deliver` instead of passing the flag every launch.

## Best Possible Solution

Decide the product shape for a persistent TUI delivery preference; if approved, implement it through canonical config/schema/help/docs plus CLI precedence tests while preserving `--deliver` as an explicit override.

## Reproduction Assessment

Yes for the current limitation: source shows the CLI flag defaults false, `runTui` falls back to false, and the config schema has no `tui.deliver` key. I did not run an interactive TUI session because the missing config path is source-proven.

## Solution Assessment

Unclear until maintainers choose the product direction. A `tui.deliver` config key is plausible, but the config-surface bar means it should be compared against a persisted TUI/session preference before implementation.
