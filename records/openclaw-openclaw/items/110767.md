## Summary

The current head appears to be a scoped, correct hardening patch: it pins validation and reads to one descriptor, caps reads to the validated size, and uses POSIX nonblocking open to reject FIFOs. It has credible real CLI and FIFO evidence plus green focused and repository checks; the remaining action is ordinary maintainer acceptance after refreshing the merge against current `main`.

## What This Changes

The PR replaces path-based model-run image reads with descriptor-bound bounded reads to retain the 100 MiB per-file and 500 MiB aggregate limits while rejecting POSIX FIFOs without blocking.

## Best Possible Solution

Land the descriptor-bound helper after a current-base refresh, preserving the explicit POSIX-only nonblocking guarantee and the existing size-budget behavior.
