## Summary

Keep this PR open for a Windows acquisition-path correction or explicit maintainer decision. The descriptor-bound POSIX path is a meaningful improvement, but the final branch still opens Windows paths normally before proving they are regular files, which can introduce a CLI hang for named-pipe input. Likely related people: penggaolai is the most direct recent contributor to the final acquisition-path commits (low confidence).

## What This Changes

The PR replaces path-based model-run image reads with descriptor-bound bounded reads to enforce 100 MiB per-file and 500 MiB aggregate limits while using POSIX nonblocking opens to reject FIFO inputs.

## Best Possible Solution

Keep descriptor-bound bounded reads, but add a Windows-safe acquisition strategy that preserves nonblocking/reject-before-read behavior for non-regular paths, then show a redacted Windows terminal proof for normal files and named-pipe rejection.
