## Summary

This PR should remain open, but it is not ready to merge: its descriptor `stat()` closes the path-substitution race, yet `FileHandle.readFile()` can still consume unbounded bytes if the already-open file grows after the size check. The PR body provides only automated-test output, so it also still needs redacted after-fix CLI evidence after the bounded-read repair.

## What This Changes

The branch replaces path-based model-run image reads with descriptor-based validation and introduces 100 MiB per-file plus 500 MiB aggregate image budgets.

## Best Possible Solution

Consume each opened descriptor through a bounded read that cannot allocate beyond the reserved per-file and remaining aggregate budgets, add a growth-during-read regression test, then attach redacted real CLI output for accepted, per-file-rejected, and aggregate-rejected inputs.
