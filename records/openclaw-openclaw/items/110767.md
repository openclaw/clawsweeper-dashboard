## Summary

Keep this PR open: descriptor-bound `stat()` removes path substitution, but the subsequent `FileHandle.readFile()` still consumes to EOF and can exceed both validated byte budgets if the same opened regular file grows after `stat()`. The contributor’s redacted live CLI outputs are useful real behavior proof for ordinary acceptance and rejection paths, but they do not establish the race-sensitive allocation bound claimed by this patch.

**Likely related people**

## What This Changes

The PR adds descriptor-bound model-run image reads with 100 MiB per-file and 500 MiB aggregate budgets in `src/cli/capability-cli/model.ts`.

## Best Possible Solution

Read exactly the validated descriptor size with a bounded `FileHandle.read()` loop, return only the bytes actually read, and add regression coverage for a file that grows after descriptor validation while preserving sequential aggregate accounting.

## Reproduction Assessment

Yes from source: open a regular file below the limit, append data to that same inode after `handle.stat()`, then let `handle.readFile()` consume to EOF. The helper charges only the earlier `stat.size`, so its caps do not bound the actual bytes read.

## Solution Assessment

No. Descriptor binding is the right ownership boundary for eliminating path substitution, but `FileHandle.readFile()` is not the narrowest safe consumption primitive because it has no maximum length; an exact-length descriptor read is required.
