## Summary

The PR still leaves the file read unbounded after its descriptor-bound size check: the same opened file can grow after `handle.stat()` and `handle.readFile()` will consume the new EOF. The earlier P1 concern therefore remains unresolved, and the automated test transcript is not real CLI behavior proof.

## What This Changes

The PR changes model-run image loading to use file-handle `stat()` and `readFile()` calls, adding 100 MiB per-file and 500 MiB aggregate admission checks.

## Best Possible Solution

Read the opened descriptor through a length-bounded loop that rejects once bytes exceed the smaller of the per-file limit and remaining aggregate budget, then add focused race/growth coverage and redacted real CLI evidence for acceptance plus both rejection boundaries.

## Solution Assessment

No. Descriptor-bound metadata removes pathname replacement, but the current unbounded read does not enforce the budget during consumption; a bounded descriptor-read loop is the narrow maintainable fix.
