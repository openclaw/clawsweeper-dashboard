## Summary

The descriptor change removes pathname substitution between open and stat, but it still reads the entire descriptor without a read-time ceiling. A writer holding the same inode can enlarge the file after `handle.stat()`, so this PR does not actually preserve the claimed per-file or aggregate memory bounds.

## What This Changes

The branch replaces path-based model-run image reads with descriptor-bound reads and adds a 100 MiB per-file plus 500 MiB aggregate pre-read budget.

## Best Possible Solution

Keep descriptor-bound identity validation, then read each descriptor through a bounded loop that refuses bytes beyond the remaining per-file and aggregate allowance; add regression coverage for growth after validation and redacted real CLI proof for normal, per-file-limit, and aggregate-limit cases.

Yes, from source: open a regular file below the stat-time limit, grow the same inode after `handle.stat()`, and the subsequent unbounded `handle.readFile()` can consume the added bytes. A focused regression test can orchestrate the growth at the descriptor-read boundary.

## Solution Assessment

No. Descriptor-bound stat fixes pathname replacement, but the correct resource-bound solution must also cap bytes while reading from that descriptor rather than trusting a pre-read size snapshot.
