## Summary

Keep this PR open: the descriptor-bound POSIX path is a meaningful hardening improvement with credible terminal proof, but the Windows fallback still opens paths with ordinary read mode and can leave the CLI blocking on a pipe-like path before descriptor validation.

## What This Changes

The PR replaces path-based model-run image reads with descriptor-bound reads, adds per-file and aggregate byte limits, and uses nonblocking opens on non-Windows platforms.

## Best Possible Solution

Preserve descriptor-bound bounded reads, but make acquisition safely reject or avoid blocking on non-regular Windows paths as well, then prove the relevant Windows behavior and refresh the branch against current `main`.
