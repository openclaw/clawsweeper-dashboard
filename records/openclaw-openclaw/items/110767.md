## Summary

The descriptor change removes the pathname replacement window, but it still does not enforce either byte budget while consuming the opened descriptor: `FileHandle.readFile()` can read bytes appended after `handle.stat()`. The earlier P1 therefore remains unresolved, and the PR body still supplies only test output rather than after-fix real CLI proof.

## What This Changes

The PR replaces path-based model-run image reads with descriptor-bound file-handle reads and introduces 100 MiB per-file plus 500 MiB aggregate admission budgets.

## Best Possible Solution

Read each descriptor into a bounded buffer or chunked loop that rejects immediately once the per-file or remaining aggregate allowance is crossed, then provide a redacted real CLI transcript for successful, per-file-limit, and aggregate-limit cases.

## Solution Assessment

No. Descriptor binding is the right ownership boundary for replacement races, but a bounded read loop or bounded buffer is required to make the per-file and aggregate budgets true consumption limits.
