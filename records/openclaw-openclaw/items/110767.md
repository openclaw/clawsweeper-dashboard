## Summary

Keep open: descriptor binding removes pathname substitution, but the patch still performs an unbounded read after its size check, so a file that grows while open can exceed both advertised budgets and allocate beyond the intended limit.

## What This Changes

The PR replaces path-based model-run image reads with descriptor-bound `open`/`stat`/`readFile` handling and adds per-file and aggregate size budgets.

## Best Possible Solution

Keep descriptor-bound opening and replace `handle.readFile()` with a bounded descriptor-read loop that reads at most the validated allocation, returning only bytes actually read; add regression coverage for post-stat growth and aggregate accounting.

## Reproduction Assessment

Yes, from source: open a regular file below the limit, grow it after `handle.stat()` and before or during `handle.readFile()`, and the helper can read beyond the stat-derived per-file and aggregate budgets.

## Solution Assessment

No. Descriptor-bound validation fixes path replacement, but it is not sufficient for a memory budget unless the descriptor read itself is capped to the validated byte count.
