## Summary

Keep this PR open: the latest patch still leaves a check-to-open race in which a regular file can be replaced with a FIFO after `stat()` succeeds, causing `fs.open()` to block on POSIX. The contributor’s live CLI evidence covers ordinary accepted and oversized regular files, but not the availability case introduced by this race. Likely related people: current-main ownership of this helper could not be established from the available read-only evidence (low confidence).

## What This Changes

The PR replaces path-based model-run image reads with descriptor-bound, size-limited reads intended to retain the 100 MiB per-file and 500 MiB aggregate budgets while closing a TOCTOU gap.

## Best Possible Solution

Use a descriptor-first mechanism that cannot block on a substituted special file, verify regular-file status on that descriptor, keep the bounded descriptor read, and prove both the regular-file budget paths and the replacement/FIFO path.

## Reproduction Assessment

Yes from source: replace a regular input file with a FIFO after the pre-open `stat()` and before `fs.open()`; on POSIX the open can wait for a writer. The supplied live proof does not exercise that race.

## Solution Assessment

No. Descriptor-bound size checks are the right direction, but a path-based pre-check cannot guarantee that the subsequently opened object is non-blocking; the non-blocking property must hold at descriptor acquisition and then be verified on the descriptor.
