## Summary

Keep open: the guarded-fetch direction is worthwhile and proof-backed, but the current head still treats every non-default MiniMax base URL as implicit authorization for private and metadata-network access. That trust-boundary choice can weaken SSRF semantics, while removing it unconditionally could break existing local endpoints, so maintainer direction is required before merge.

## What This Changes

Routes MiniMax VLM requests through SSRF-guarded fetch, derives an endpoint policy, releases guarded-fetch resources, and updates affected tests.

## Best Possible Solution

Use guarded fetch for MiniMax VLM while requiring an explicit trusted-private-endpoint contract for private origins and continuing to block metadata and link-local destinations unless separately authorized.
