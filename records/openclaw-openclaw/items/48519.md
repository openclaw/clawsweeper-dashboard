## Summary

Keep open: current main still has message-scoped input provenance, external-content wrapper text, transcript hooks, and coarse memory source buckets, but not the requested provenance chain through tool results, durable writes, stored state, and future read-time policy.

## What This Changes

The issue requests provenance metadata that survives from input/tool results into persistent state and later session reads for memory, files, preferences, and scheduled tasks.

## Best Possible Solution

Define a maintainer-approved provenance contract across tool outputs, durable write/read hooks, memory schema/search, and plugin policy APIs, then implement it with security review, migration guidance, docs, and focused compatibility tests.
