## Summary

Keep open: current main still has message-scoped provenance, external-content wrapping, and transcript write hooks, but not a durable provenance chain through tool results, persistent writes, and future read-time policy. The PitStop comment reinforces that real multi-agent workflows want immutable state-mutation provenance, so this remains a security-sensitive plugin/API and persisted-state design issue rather than cleanup.

## What This Changes

The issue requests durable provenance metadata that follows untrusted or inter-session data through tool results, persistent state writes, and future reads across session boundaries.

## Best Possible Solution

Define a minimal durable provenance contract first: tool-result provenance, persistence-write metadata, legacy unknown-state handling, plugin visibility rules, and read-time policy hooks.
