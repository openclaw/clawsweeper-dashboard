## Summary

Keep open: current main has message-level provenance, external-content wrapping, and transcript hooks, but not the requested durable provenance chain through tool results, persistent writes, and later read-time policy. Related issues remain open and overlap the design, but none fully replaces this specific persistent-state provenance proposal.

## What This Changes

Request durable provenance tracking for agent-written persistent state so future sessions can distinguish trusted user input from inter-session or untrusted tool-derived content.

## Best Possible Solution

Define a host-authored persistent provenance contract spanning tool results, durable write/read hooks, memory/search schemas, and plugin policy APIs, then land it with maintainer security review and compatibility tests.
