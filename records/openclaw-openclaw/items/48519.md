## Summary

Keep open: current main and the latest release still have message-scoped provenance, external-content wrapping, transcript hooks, and memory source buckets, but not a durable provenance chain through tool results, persistent writes, and read-time policy. This remains a security-sensitive Plugin SDK and persisted-state design item, not conservative cleanup.

## What This Changes

Request to persist provenance metadata from tool results through durable state writes and future reads so stored memory, files, preferences, and scheduled tasks can be evaluated by origin.

## Best Possible Solution

Define a minimal durable provenance contract spanning tool-result provenance, persistence-write metadata, migration and unknown-state policy, plugin visibility, and read-time policy hooks, coordinated with https://github.com/openclaw/openclaw/issues/48503, https://github.com/openclaw/openclaw/issues/48509, and https://github.com/openclaw/openclaw/issues/42647.
