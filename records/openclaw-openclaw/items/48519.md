## Summary

Keep open: current main and v2026.6.11 still provide message-scoped provenance, external-content wrapping, transcript persistence hooks, and limited memory source metadata, but not a durable provenance chain through tool results, persistent writes, and read-time policy. This remains a security-sensitive Plugin SDK and persisted-state design item; the linked external projects are useful prior art but not native implementation.

## What This Changes

Request durable provenance metadata across tool results, persistent writes, and future reads of stored state.

## Best Possible Solution

Design a minimal durable provenance contract spanning tool-result origin, pre-persistence write metadata, persisted schema or unknown legacy state, plugin visibility, and read-time policy, using linked external projects as prior art rather than treating them as shipped behavior.
