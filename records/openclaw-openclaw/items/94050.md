## Summary

Keep open: the central failed-exec loop fix is still needed, but this head is not merge-ready because the new failed hash relies on stable exec failure fields that are absent on sibling exec result paths. ## What This Changes

The PR changes exec loop-result hashing so completed output remains in the progress fingerprint while failed output is stripped and replaced with status, exitCode, timedOut, failureKind, and exitSignal, with regression tests.

## Best Possible Solution

Keep the failed-exec output strip only after every real exec result producer either supplies stable failure discriminators or preserves output as a fallback when those fields are absent, then add wrapped exec coverage and fresh real terminal proof.
