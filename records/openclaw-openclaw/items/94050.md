## Summary

Current main still hashes volatile output for every completed or failed exec outcome, so the reported runaway-loop bug remains. The branch is technically well-proven and has no concrete correctness defect, but it intentionally treats all changing output from a nonzero command as no progress; an agent-runtime owner should explicitly accept that availability tradeoff before merge.

## What This Changes

The PR fingerprints nonzero exec outcomes using structured failure identity instead of output text, propagates stable failure details through foreground exec producers, and adds runtime-path tests and documentation.

## Best Possible Solution

Use one owner-approved exec outcome policy across foreground, node-host, and gateway producers: retain the branch’s structured failure identity if changing nonzero output is intentionally classified as no progress, refresh it onto current main, and prove both runaway-loop blocking and a representative progress-sensitive nonzero case.
