## Label Justifications

## Summary

Current main still validates configured-agent existence only when `agentId` is used directly; a supplied `sessionKey` proceeds through generic key resolution and can reach run dispatch without the same registry check. Keep this issue open as a concrete core routing bug. ([github.com](https://github.com/openclaw/openclaw/blob/main/src/agents/tools/sessions-send-tool.ts))

**Likely related people:** @steipete (high confidence; extensive session-tool history), @Takhoffman (medium confidence; prior `sessions_send` correctness work), and @scotthuang (medium confidence; A2A send-flow fixes).

## What This Changes

Reject `sessions_send` targets whose explicit agent-scoped session key names an unconfigured agent before creating or running that session.

## Best Possible Solution

Validate the fully resolved target before any session creation or run dispatch: reject malformed agent-shaped keys, require the embedded agent ID to exist in `listAgentIds(cfg)`, preserve valid non-main lanes for configured agents, and add regression coverage proving no Gateway `agent` call occurs for unknown targets.
