## Summary

Current main still lacks a typed, manifest-authorized Plugin SDK contract for canonical AI-safety events: services only receive an explicitly internal diagnostics handle, while the public agent-event API is generic and plugin-namespaced. The issue remains necessary, and the linked open implementation should stay paired with it until maintainers settle the prerequisite schema and external-plugin trust model.

## What This Changes

Define a typed, manifest-declared, runtime-validated Plugin SDK path for plugins to emit AI safety and quality events.

## Best Possible Solution

Approve the core schema and trust semantics first, then expose one generic manifest-first Plugin SDK seam that validates events, preserves immutable emitter provenance, enforces bounded privacy fields, logs rejections safely, and ships with contract tests plus plugin-author docs; use a fixture or explicitly sponsored reference plugin rather than coupling the core contract to one detector implementation.
