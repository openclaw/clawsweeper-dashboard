## Summary

Keep open: current main now has first-party `extension` support again, but it still lacks the requested generic browser backend registration seam for third-party MCP/custom drivers.

## What This Changes

The issue requests a stable browser backend registration/plugin interface so third-party MCP/custom drivers can be selected and bound without core forks.

## Best Possible Solution

Define a maintainer-approved, versioned browser backend registry that lets plugins declare driver ids and routes config, schema, CLI/control APIs, runtime dispatch, docs, security review, and contract tests through that registry.

## Maintainer Decision

Required: true

Question: Should OpenClaw expose a generic browser backend Plugin SDK/registry seam for third-party drivers, and if so what trust, config, and runtime contract should it enforce?

Rationale: The requested seam would become public API for browser-control authority and profile configuration, so automation cannot safely choose the permanent driver contract, credential boundary, or upgrade policy.

Likely owner: vincentkoc

Owner confidence: high

Options:

- **Design Generic SDK Registry (recommended):** Add a versioned backend contract, registry-owned driver ids, config/schema/client/runtime routing, docs, and security tests before accepting third-party adapters.
- **Limit To First-Party Drivers:** Keep solving Browserbase, extension relay, and My Browser needs as built-in or bundled-plugin drivers without exposing a general third-party contract yet.
- **Defer Until Narrow PRs Settle:** Keep this issue open while narrower browser work clarifies the minimum safe registration API.

## Reproduction Assessment

Yes, at source level. Current main keeps browser driver config, schema, profile creation, runtime resolution, and Plugin SDK surfaces closed to built-in driver ids, so arbitrary adapters are rejected before backend dispatch.

## Solution Assessment

Yes for keeping this open as a design issue. The narrow maintainable solution is a versioned registry/contract with security review, not an autonomous enum-widening patch.
