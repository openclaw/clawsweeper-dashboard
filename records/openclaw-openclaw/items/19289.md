## Summary

Keep open: current main restored a built-in Chrome extension driver, but still does not provide a third-party browser backend registration seam through config, profile creation, runtime dispatch, or the Plugin SDK. The related Browserbase, My Browser, extension relay, and sandbox-backend threads are narrower demand signals rather than replacements for this API-design issue.

## What This Changes

The issue requests a stable browser backend plugin interface so third-party MCP or custom adapter drivers can register without OpenClaw core changes.

## Best Possible Solution

Design a maintainer-approved, versioned browser backend/adapter extension point that registers driver ids through core and the Plugin SDK, updates config/schema/CLI/control routing, and adds docs plus security and contract tests.
