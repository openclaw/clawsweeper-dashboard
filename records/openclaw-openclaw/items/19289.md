## Summary

Keep open: current main restored a built-in extension driver, but it still lacks the requested third-party browser backend registration seam for MCP/custom adapters.

## What This Changes

The issue requests a pluggable browser backend interface so third-party drivers can register without modifying OpenClaw core.

## Best Possible Solution

Design a maintainer-approved, versioned browser backend registry that registers driver ids through core and the Plugin SDK, updates config/schema/CLI/control/runtime dispatch, and includes docs plus security and contract tests.

## Maintainer Decision

Question: Should OpenClaw add a generic browser backend Plugin SDK/registry seam for third-party drivers, or keep browser backends limited to narrow first-party profile drivers for now?

Rationale: The request changes public Plugin SDK/config semantics and the browser-control security boundary, so automation cannot safely choose the permanent contract by widening driver enums.

Options:

- **Design generic SDK registry (recommended):** Add a versioned backend contract, registry-owned driver ids, config/schema/client/runtime routing, docs, and security tests before accepting third-party adapters.
- **Limit to first-party drivers:** Continue solving Browserbase, My Browser, relay, and sandbox needs as individual built-in or bundled-plugin drivers without exposing a generic third-party contract yet.
- **Defer until narrower work settles:** Keep this issue open while related browser-backend demand clarifies the minimum safe registration API.

## Reproduction Assessment

Yes, at source level: current main keeps driver ids and runtime routing closed to built-in browser backends. No live runtime setup is needed because arbitrary driver names are rejected before backend dispatch.

## Solution Assessment

Yes for the review outcome: keeping this as a maintainer API-design issue is the narrowest maintainable path. The implementation should be a versioned registry/contract with security review, not an autonomous enum-widening patch.
