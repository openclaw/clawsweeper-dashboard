## Summary

This PR addresses a real direct-turn silent-reply failure, but it still has the prior P1 delivery regression: a visible routed media-only block does not count as visible, so the new core fallback can add an erroneous text message after media. The branch also has no inspectable after-fix channel proof and carries the protected `maintainer` label, so it needs human review rather than cleanup closure.

## What This Changes

The branch makes the core auto-reply dispatcher send a standard fallback text when a direct visible channel turn finishes without a detected reply, while preserving existing silent-reply and send-policy exceptions.

## System Context

The auto-reply dispatcher converts agent output into final messages or blocks for the originating channel. Its finalization step decides whether a user-visible response already occurred and, with this patch, may synthesize a text fallback when it believes the turn ended silently.

## Best Possible Solution

Before merge, make the fallback gate recognize successfully routed media blocks as visible delivery, or introduce a single settled visible-delivery fact shared by block and final routing; then prove the empty-completion path and media-only control case on a real channel.
