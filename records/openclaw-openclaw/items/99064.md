## Summary

The response-lifecycle defect from the previous review is fixed on the latest head, and the shared helper preserves existing callers by default. The PR still needs a Copilot feature-owner decision because its universal 16 MiB size cap and 30-second total-read timeout create new compatibility boundaries that are not defined by the pinned SDK’s provider- and model-specific request contract.

## What This Changes

The PR bounds Copilot BYOK proxy request bodies at 16 MiB with a 30-second read timeout, adds deterministic 413 handling for declared and streamed overflow, and extends the shared request reader with caller-controlled error teardown.

## Best Possible Solution

Keep one shared bounded-reader path with the existing default intact, but calibrate the Copilot-specific size and timeout policy against representative text, tool, binary, and multimodal SDK requests; prefer progress-aware timeout semantics if actively uploading requests should remain valid, and add exact-head overflow and timeout proof.
