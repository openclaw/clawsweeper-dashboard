## Summary

Keep open: this is a focused and useful Control UI bug-fix PR, but the current patch can still miss queued approval handoffs where the modal label and description do not change, and the proof remains jsdom/Vitest-only rather than a real browser Control UI flow.

## What This Changes

The PR changes the shared Control UI modal dialog to reopen a closed native dialog on Lit updates and adds two modal regression tests.

## Best Possible Solution

Land one Control UI fix that reopens or remounts the modal when the active approval changes even if modal attributes stay the same, with a same-label/same-description regression test and redacted browser-visible proof.

## Reproduction Assessment

Yes at source level: current main can keep the same approval modal element mounted while its old opened latch prevents reopening a closed native dialog after the queue advances. I did not run a browser reproduction in this read-only review.

## Solution Assessment

No, not yet: the modal primitive is the right owner, but the current updated() hook only covers property-driven updates and can miss slot-only queue shifts. A slotchange/active-id remount path plus matching regression coverage would be the safer fix.
