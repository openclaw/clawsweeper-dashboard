## Summary

Keep open: current main and v2026.6.11 still lack the requested standalone Telegram placeholder message lifecycle and config, while related typing, reaction, presence, and broader acknowledgement-text work only partially overlaps.

## What This Changes

The issue requests an opt-in Telegram processing indicator that sends a visible placeholder while work is running, deletes it on reply, and edits or replaces it on failure.

## Best Possible Solution

Choose the intended Telegram responsiveness UX, then land either a default-off Telegram plugin placeholder lifecycle with schema/docs/tests and live proof, or explicitly route users to the chosen presence/status-reaction or broader acknowledgement-text alternative.
