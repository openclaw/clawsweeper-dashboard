## Summary

Keep open: current main and v2026.6.11 still lack the requested standalone Telegram processing-placeholder config and send/delete/edit lifecycle. Existing typing cues, ack reactions, status reactions, and the open Telegram presence PR overlap the responsiveness problem but do not implement the requested placeholder message, so this remains a maintainer product/config decision.

## What This Changes

Request to add a Telegram processing indicator that sends a visible placeholder while a turn is running, then deletes it on reply or edits it on failure.

## Best Possible Solution

Choose the intended Telegram responsiveness UX, then either land a default-off Telegram plugin placeholder lifecycle with schema, docs, tests, and live Telegram proof, or explicitly route users to the chosen presence/status-reaction or broader acknowledgement-text alternative.
