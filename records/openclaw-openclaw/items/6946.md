## Summary

Keep open: current main and latest release still lack the requested Telegram standalone processing-placeholder message config and send/delete/edit lifecycle. Existing typing, ack reactions, status reactions, and the open Telegram presence PR overlap the responsiveness problem but do not implement this exact placeholder-message behavior, so this remains a maintainer product/config decision.

## What This Changes

The issue requests an opt-in Telegram processing indicator that sends a visible placeholder while work is running, deletes it on successful reply, and edits or replaces it on failure.

## Best Possible Solution

Choose the intended Telegram responsiveness UX, then land a default-off Telegram plugin implementation or explicitly route users to the chosen broader acknowledgement/presence alternative.
