## Summary

Keep open: current main and v2026.6.11 still lack the requested standalone Telegram processing-placeholder message config and send/delete/edit lifecycle. Existing typing cues, ack reactions, status reactions, and the open Telegram presence PR overlap the responsiveness problem, but none implements the requested visible placeholder message, so this remains a maintainer product/config decision.

## What This Changes

Add an opt-in Telegram processing indicator that sends a visible placeholder message while a request is running, then deletes it on reply or edits/replaces it on failure.

## Best Possible Solution

Choose the intended Telegram responsiveness UX, then either land an opt-in plugin-owned placeholder lifecycle with schema/docs/tests and Telegram proof, or explicitly route users to the chosen reaction/typing or broader ack-text alternative.
