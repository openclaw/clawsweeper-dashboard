## Summary

Keep open: current main and v2026.6.11 still lack the requested standalone Telegram placeholder-message config and send/delete/edit lifecycle. Existing typing cues, ack reactions, and status reactions are adjacent but do not implement the visible processing message the issue asks for, and the live overlapping PR remains open, conflicting, and only partially overlapping.

## What This Changes

Add an opt-in Telegram processing indicator message that is sent while a request is being processed, deleted on successful reply, and edited or replaced on failure.

## Best Possible Solution

Choose the intended Telegram responsiveness UX, then land either a default-off Telegram plugin placeholder lifecycle with schema/docs/tests and live proof, or explicitly route users to the chosen presence/status-reaction or broader acknowledgement-text alternative.
