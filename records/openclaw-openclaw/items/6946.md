## Summary

Keep open: current main and v2026.6.11 still lack the requested Telegram placeholder-message config and send/delete/edit lifecycle. Existing typing indicators, ack reactions, status reactions, and the open Telegram presence PR overlap the responsiveness problem but do not implement this exact visible placeholder message, so this remains a maintainer product/config decision.

## What This Changes

Request to add an opt-in Telegram processing indicator message that is sent while an inbound request is running, deleted after a successful reply, and edited or replaced on failure.

## Best Possible Solution

Choose the intended Telegram responsiveness UX, then either land a default-off plugin-owned placeholder lifecycle with schema/docs/tests and live Telegram proof, or explicitly route users to the chosen presence/status-reaction or broader acknowledgement-text alternative.
