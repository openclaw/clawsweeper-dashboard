## Summary

Keep open: current main and the latest release still lack the requested standalone Telegram processing-placeholder message config and send/delete/edit lifecycle. Existing typing, ack reactions, status reactions, and the open Telegram presence PR overlap the UX problem, but they do not replace the requested placeholder behavior and still leave a maintainer product/config decision.

## What This Changes

Request adds an opt-in Telegram processing message that appears while an inbound message is being handled, deletes on successful reply, and edits or replaces on failure.

## Best Possible Solution

Choose one opt-in Telegram-visible feedback contract, then implement it in the Telegram plugin with strict schema/help/docs, authorized dispatch wiring, stored placeholder cleanup, success deletion, failure edit-or-replace behavior, focused tests, and real Telegram proof.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 expose typing, ack reactions, status reactions, streaming progress, and generic fallback replies, but no supported immediate processing-placeholder config or stored send/delete/edit lifecycle.

## Solution Assessment

Unclear until maintainers choose the product shape. A Telegram-owned opt-in placeholder is plausible for this exact request, but it should be reconciled with https://github.com/openclaw/openclaw/pull/80690 and https://github.com/openclaw/openclaw/issues/8285 before adding another config surface.
