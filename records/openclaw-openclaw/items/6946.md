## Summary

Keep open: current main and the latest release still lack the requested standalone Telegram placeholder-message lifecycle, while the open presence PR only partially overlaps through typing and reactions. The remaining choice is product direction rather than missing implementation evidence.

## What This Changes

Add an opt-in Telegram processing placeholder that appears while a turn runs and is deleted or changed when the turn completes or fails.

## Best Possible Solution

Standardize one Telegram-owned, opt-in presence contract, then implement the standalone send/delete/edit lifecycle only if maintainers choose it over or alongside the typing and status-reaction model.
