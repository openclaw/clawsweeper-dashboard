## Summary

Keep open: current main and latest release v2026.6.11 still lack the requested standalone Telegram placeholder-message config and send/delete/edit lifecycle. Existing typing cues, ack reactions, status reactions, and the open presence PR at https://github.com/openclaw/openclaw/pull/80690 overlap the responsiveness problem but do not implement the visible processing message requested here.

## What This Changes

Add an opt-in Telegram processing indicator that posts a visible placeholder while a turn runs, deletes it on reply, and edits it on failure.

## Best Possible Solution

Choose the intended bundled Telegram UX, then land an opt-in Telegram plugin change with strict config/schema/help/docs/tests that sends and tracks a standalone placeholder only after an inbound message is accepted, deletes it after successful final delivery, and edits or replaces it on failure without disturbing existing reaction/status behavior.
