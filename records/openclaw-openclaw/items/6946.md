## Summary

Keep open: current main and v2026.6.11 still lack the requested Telegram standalone processing-placeholder message config and send/delete/edit lifecycle. The existing typing, ack-reaction, status-reaction, and draft/streaming paths overlap but do not implement the visible placeholder message requested here.

## What This Changes

Request an opt-in Telegram processing indicator that sends a visible placeholder while a message is processed, deletes it after a successful reply, and edits or replaces it on failure.

## Best Possible Solution

Choose one opt-in Telegram-visible feedback contract, then implement it in the Telegram plugin with strict schema/help/docs, authorized dispatch wiring, stored placeholder cleanup, success deletion, failure edit-or-replace behavior, focused tests, and real Telegram proof.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 expose typing, ack reactions, status reactions, and generic fallback replies, but no supported immediate processing-placeholder config or stored send/delete/edit lifecycle.

## Solution Assessment

Unclear until maintainers choose the product shape. A Telegram-owned opt-in placeholder is plausible for this exact request, but it should be reconciled with https://github.com/openclaw/openclaw/pull/80690 and https://github.com/openclaw/openclaw/issues/8285 before adding another config surface.
