## Summary

Keep open: current main and v2026.6.11 still lack the requested Telegram standalone processing-placeholder message config and send/delete/edit lifecycle. Existing typing cues, ack reactions, status reactions, and the open Telegram presence PR overlap, but they do not implement this exact visible placeholder-message behavior.

## What This Changes

The issue requests an opt-in Telegram processing indicator message that is sent while a request is being handled, then deleted or changed when the final reply or failure occurs.

## Best Possible Solution

Choose the intended Telegram-visible feedback UX, then land one opt-in Telegram-owned implementation with strict schema/help/docs, authorized placeholder dispatch, stored message-id cleanup, success deletion, failure edit-or-replace behavior, focused tests, and real Telegram proof.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 expose typing, ack reactions, status reactions, and progress-related delivery behavior, but no supported immediate processing-placeholder config or stored send/delete/edit lifecycle.

## Solution Assessment

Unclear until maintainers choose the product shape. A Telegram-owned opt-in placeholder is plausible for this exact request, but it should be reconciled with the open presence PR and the broader acknowledgement-text issue before adding config surface.
