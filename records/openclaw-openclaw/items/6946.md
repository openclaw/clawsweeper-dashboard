## Summary

Keep open: current main and the latest release still lack the requested standalone Telegram processing-placeholder message config and send/delete/edit lifecycle. Existing typing cues, ack/status reactions, draft/progress behavior, and the open Telegram presence PR overlap but do not replace this exact placeholder-message request.

## What This Changes

Request to add an opt-in Telegram processing indicator that sends a visible placeholder while a turn runs, deletes it after a successful reply, and edits or replaces it on failure.

## Best Possible Solution

Choose the intended Telegram-visible feedback UX, then land one default-off Telegram-owned or shared-hook implementation with strict schema/help/docs, authorized placeholder dispatch, stored message-id cleanup, success deletion, failure edit-or-replace behavior, focused tests, and real Telegram proof.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 expose typing, ack reactions, status reactions, and progress-related delivery behavior, but no supported immediate processing-placeholder config or stored send/delete/edit lifecycle.

## Solution Assessment

Unclear until maintainers choose the product shape. A Telegram-owned default-off placeholder is plausible for this exact request, but it should be reconciled with the open presence PR and the broader acknowledgement-text issue before adding config surface.
