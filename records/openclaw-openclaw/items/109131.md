## Summary

The timeout-helper direction is sound, but the unchanged PR head still reuses one deadline calculation across multiple sequential Docker commands, so a stalled first command can let later probes exceed the advertised wall-clock deadline. The updated proof is useful but uses PATH-injected Docker and timeout fakes rather than a real Docker setup.

## What This Changes

This PR routes Docker package-install and Compose E2E probes, diagnostics, execution, and cleanup through timeout-aware helpers and replaces fixed-count readiness polling with wall-clock deadlines.

## Best Possible Solution

Keep the shared timeout helper as the single Docker-command boundary, calculate the remaining deadline immediately before every sequential exec, inspect, logs, ps, run, and Compose command, and provide redacted live Docker proof for both package-install and Compose paths.
