## Summary

Keep this PR open. It remains necessary: current main has not absorbed the relay-startup behavior, and the branch now provides focused startup-path tests plus terminal evidence from a real Gateway restart on the final head. The implementation is a narrow fix that shares relay initialization between the existing in-process control service and the eager standalone HTTP-server owner; no concrete correctness or security defect was identified from the supplied final diff and review context.

## What This Changes

This PR starts configured extension-driver browser relays at Gateway boot and also when the existing eager browser-control server path is selected, so paired Chrome extensions can reconnect after a restart without a manual browser request.

## System Context

The bundled browser plugin starts either an in-process browser-control service or a standalone loopback HTTP control server during Gateway startup. Both owners need to initialize configured extension relays so a paired Chrome extension can reconnect before a CLI command or agent browser request lazily activates browser control.
