## Summary

The reported regression is valid and this branch fixes the immediate unknown-command crash, but the guard uses runtime capability detection instead of OpenClaw’s explicit plugin registration lifecycle, so the patch can silently reduce other partial or invalid host loads to CLI-only registration. The competing PR targets the lifecycle contract more directly but is not yet proof-positive, so neither PR should be closed as superseded.

**Likely related people**
- `steipete` — high confidence; introduced and recently refactored the central Codex registration and binding-store paths.
- `kevinslin` — medium confidence; recent contributor to adjacent Codex plugin lifecycle and app/plugin registration behavior.

## What This Changes

The PR makes Codex register only CLI metadata when `runtime.state.openSyncKeyedStore` is unavailable and adds regression coverage for an empty runtime object.

## Best Possible Solution

Register static Codex CLI descriptors first, branch on `api.registrationMode` for metadata-only loading, preserve the intended full and tool-discovery contracts, and attach redacted terminal output proving the unknown-command, Codex-help, and normal full-registration paths.

Yes at source level: OpenClaw 2026.7.1 invokes the Codex entry in `cli-metadata` mode with an empty runtime shell, and current main dereferences `runtime.state` before metadata registration. ## Solution Assessment

No. Guarding the missing method fixes the reported symptom, but checking the explicit `registrationMode` is the narrower and maintainable solution because it preserves the documented distinction between metadata, discovery, tool-discovery, and full loads.
