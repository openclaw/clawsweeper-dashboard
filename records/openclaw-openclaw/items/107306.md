## Summary

The CLI regression fix is proven, but the PR still returns before all Codex provider and tool registration in `tool-discovery`, which OpenClaw defines as a capability-bearing lifecycle. The new lazy state-store thunk makes a narrower lifecycle split feasible.

## What This Changes

The PR registers Codex CLI metadata before runtime wiring, returns before runtime registrations in every non-full mode, and defers binding-store acquisition until the first binding operation.

## Best Possible Solution

Keep CLI metadata and setup loads state-free, but split `tool-discovery` so Codex providers and tools register with the lazy binding store while harnesses, hooks, commands, and other full-runtime surfaces remain full-only.
