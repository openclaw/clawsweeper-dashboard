## Summary

Keep this PR open for revision. Reusing the abort-aware delay is directionally correct, but abort currently ends only the reply-poll loop: the resolver still returns a normal partial turn, and the comment handler can continue into session recording and agent reply dispatch after the account has stopped. ([formatika.de](https://www.formatika.de/index.jsp?content=source&detail=products%2FSources%2Fformale+Sprachen%2FJAVA%2Fopenclaw%2Fextensions%2Ffeishu%2Fsrc%2Fmonitor.comment.ts))

## What This Changes

Threads the Feishu account AbortSignal into Drive-comment reply polling, replaces the fixed delay with an abort-aware wait, and adds focused regression coverage.

## Best Possible Solution

Make account abort a terminal outcome for the active Drive-comment event before authorization, session recording, or reply dispatch, preserve the intended dedupe/replay semantics, and prove the full production path with a real timer and process-level or live-tenant restart transcript.
