## What This Changes

The PR replaces the tools-manager GitHub latest-release success-path `response.json()` call with `readProviderJsonResponse` so release-tag JSON is read under the shared 16 MiB cap.

## Best Possible Solution

Land the narrow bounded-read change after ordinary maintainer approval and check completion, keeping the shared helper as the canonical JSON response-size guard.

## Reproduction Assessment

## Solution Assessment

Yes. The PR changes the exact success response read to the existing bounded JSON helper; using `readResponseWithLimit` directly would be lower-level and would duplicate JSON parse and error-label behavior already owned by the helper.
