## Summary

Keep open: current main and v2026.6.11 still expose the backend `exec.approval.list` RPC but not the requested `openclaw approvals pending` CLI, CLI tests, or public CLI docs. Related implementation PRs are open or closed unmerged, so there is no landed user-facing CLI surface to close against.

## What This Changes

Request adds an `openclaw approvals pending` CLI command with human-readable and JSON output for pending exec approval requests.

## Best Possible Solution

Land one coordinated approvals CLI implementation that reuses `exec.approval.list`, preserves existing visibility and authorization semantics, adds table plus `--json` output and focused CLI/docs tests, and scopes `--watch` or resolve actions only after maintainer confirmation.

## Reproduction Assessment

Yes. Source inspection shows current main has `exec.approval.list`, but `registerExecApprovalsCli` only registers policy `get`, `set`, and `allowlist` commands, with no pending-list CLI path.

## Solution Assessment

Unclear until maintainers settle the approval authority contract. The narrowest maintainable direction is a CLI table/JSON wrapper over the existing `exec.approval.list` RPC, not a second gateway method or a parallel approval store.
