## What This Changes

The issue requests an `openclaw approvals pending` CLI command with human-readable, JSON, and optional watch output for currently pending exec approval requests.

## Best Possible Solution

Land one coordinated approvals CLI implementation backed by the existing `exec.approval.list` method, with table and `--json` output, focused CLI/docs tests, live redacted gateway proof, and a maintainer-approved authority model before adding watch or resolve behavior.

## Reproduction Assessment

Yes. Source inspection on current main shows the backend `exec.approval.list` RPC exists, but the approvals CLI only registers policy `get`, `set`, and `allowlist` commands and the docs omit a runtime pending-list command.

## Solution Assessment

Unclear until maintainers settle the authority contract. The narrow maintainable direction is a CLI wrapper over existing `exec.approval.list`, not a second Gateway method, with watch/resolve scoped separately unless explicitly approved.
