## Summary

Keep open: current main and v2026.6.11 still expose only approvals `get`, `set`, and `allowlist`, while the backend pending-approval list RPC exists. The open overlapping PRs are conflicting, protected, or proof/security blocked, so they are not a merged resolution.

## What This Changes

Add an `openclaw approvals pending` CLI command with table/JSON output, and optionally watch output, to show currently pending exec approval requests and command details.

## Best Possible Solution

Land a narrow approvals CLI implementation that reuses `exec.approval.list`, preserves approval-runtime visibility rules, renders sanitized table and JSON output, adds focused CLI/docs coverage, and scopes `--watch` separately unless maintainers explicitly include it.

## Reproduction Assessment

## Solution Assessment

Yes for the narrow direction, but it is not implemented on main. The maintainable fix is a CLI wrapper over the existing visibility-filtered RPC with sanitized output, docs/tests, and live proof rather than a new protocol method.
