## Summary

Keep open: current main and the latest release still expose the backend `exec.approval.list` RPC but do not expose the requested `openclaw approvals pending` CLI, docs, or CLI tests, and the active overlapping PR still needs maintainer/security review rather than letting this issue close.

## What This Changes

Add an `openclaw approvals pending` CLI command to list currently pending exec approval requests with command details, JSON output, and possibly watch mode.

## Best Possible Solution

OpenClaw should expose a narrow sanitized pending/list CLI backed by the existing `exec.approval.list` RPC and the correct approval-runtime authority path, with focused tests/docs; `--watch` can remain a follow-up unless explicitly scoped in.

## Reproduction Assessment

Yes. Source inspection of current main shows `openclaw approvals` only registers `get`, `set`, and `allowlist`, while the backend `exec.approval.list` RPC already exists.

## Solution Assessment

Yes for the narrow direction, but it is not implemented on main. The best implementation is a CLI wrapper over the existing RPC with the correct approval-runtime authority, sanitized output, tests, docs, and live proof rather than a new protocol method.
