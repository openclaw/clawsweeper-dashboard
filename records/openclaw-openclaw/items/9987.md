## Summary

Keep open: current main and v2026.6.11 still expose the backend pending approval list RPC, but they do not provide the requested `openclaw approvals pending` CLI or docs surface. The open PRs that overlap this issue are conflicting or broader and still need maintainer/security-boundary review, so this issue remains the canonical tracker.

## What This Changes

Add an `openclaw approvals pending` CLI command that lists pending exec approval requests with command details, table output, `--json`, and possibly `--watch`.

## Best Possible Solution

Land a narrow CLI implementation that reuses `exec.approval.list`, uses the established operator approval authority path, renders sanitized table and JSON output, adds focused CLI/docs coverage, and defers `--watch` unless maintainers explicitly include it.

## Reproduction Assessment

Yes, at source level. Current main registers `approvals get`, `set`, and `allowlist`, while the backend `exec.approval.list` RPC already exists and the requested CLI wrapper is absent.

## Solution Assessment

Yes for the narrow direction, but it is not implemented on main. The maintainable path is to wrap the existing RPC with the correct approval authority, sanitized output, tests, docs, and live proof rather than adding a second protocol method.
