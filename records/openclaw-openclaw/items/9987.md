## Summary

Keep open: current main and v2026.6.11 still have the backend pending exec approval list RPC, but they do not expose the requested `openclaw approvals pending` CLI/docs surface, and the open candidate PRs are not merged or ready to make this obsolete.

## What This Changes

Request to add a CLI command like `openclaw approvals pending` with command details, JSON output, and optional watch behavior for currently pending exec approval requests.

## Best Possible Solution

Land a narrow CLI implementation that reuses `exec.approval.list`, preserves the existing approval-runtime visibility contract, renders sanitized table and JSON output, adds focused CLI/docs coverage, and defers `--watch` unless maintainers scope it in.

## Reproduction Assessment

Yes, at source level. Current main registers only `openclaw approvals get`, `set`, and `allowlist`, while the backend `exec.approval.list` RPC already exists.

## Solution Assessment

Yes for the narrow one-shot CLI direction, but not as a broad unresolved watch/resolve surface. The maintainable first step is a CLI wrapper over the existing RPC with approval-runtime authority, sanitized output, tests, docs, and live proof.
