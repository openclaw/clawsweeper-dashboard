## Summary

Keep open: current main and v2026.6.11 still expose the backend `exec.approval.list` RPC but do not expose the requested `openclaw approvals pending` CLI/docs surface, and the relevant open PRs are not merged or safe canonical replacements yet.

## What This Changes

The issue requests a user-facing `openclaw approvals pending` CLI command, with table and JSON output, to list currently pending exec approval requests and their commands.

## Best Possible Solution

Land a narrow CLI implementation that reuses `exec.approval.list`, preserves the established approval-runtime visibility boundary, renders sanitized table and JSON output, adds focused CLI/docs coverage, and defers `--watch` unless maintainers explicitly scope it in.

## Reproduction Assessment

Yes, at source level. Current main registers `approvals get`, `set`, and `allowlist`, while the backend `exec.approval.list` RPC and tests already exist.

## Solution Assessment

Yes for the narrow direction, but it is not implemented on main. The maintainable path is a CLI wrapper over the existing visibility-filtered RPC with sanitized output, tests, docs, and live proof rather than a new protocol method.
