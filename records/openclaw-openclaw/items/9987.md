## Summary

Keep open: current main and the latest release still have the backend `exec.approval.list` RPC, but they do not expose the requested `openclaw approvals pending` CLI/docs/test surface. Open related PRs target the area, but they are unmerged and still need authority-path/security review rather than making this issue obsolete.

## What This Changes

Add a CLI command such as `openclaw approvals pending` to list pending exec approval requests with command details and scriptable output.

## Best Possible Solution

Land a narrow approvals CLI implementation that reuses `exec.approval.list`, preserves approval visibility rules, renders sanitized table and JSON output, adds focused CLI/docs coverage, and treats `--watch` as follow-up unless maintainers explicitly include it.

## Reproduction Assessment

Yes. Source inspection of current main shows `openclaw approvals` only registers `get`, `set`, and `allowlist`, while the backend `exec.approval.list` RPC already exists.

## Solution Assessment

Yes for the narrow direction, but it is not implemented on main. The maintainable path is a CLI wrapper over the existing visibility-filtered RPC with sanitized output, tests, docs, and an explicit maintainer decision on any watch/resolve authority behavior.
