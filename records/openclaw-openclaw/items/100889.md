## Summary

Keep open for maintainer review: current main still has the unbounded browser-control HTTP success read, and this PR fixes the owner transport boundary with focused regression coverage. The remaining question is whether maintainers accept the 32 MiB success-response contract before merge.

## What This Changes

The PR replaces the browser-control HTTP success-path `res.json()` read with a 32 MiB `readResponseWithLimit` cap and adds loopback regression coverage for oversized and normal successful JSON responses.

## Best Possible Solution

Land the bounded success-reader fix if maintainers accept 32 MiB as the browser-control HTTP success JSON contract, keeping the cap at the transport boundary and preserving normal small-response behavior.
