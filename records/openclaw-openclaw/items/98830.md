## Summary

Keep open: the security-audit idea is useful, but the patch currently inspects resolved config, so existing `${VAR}` indirection can be warned on after substitution; the PR also needs actual redacted CLI output before merge.

## What This Changes

Adds a warn-level security audit check and tests for token-shaped plaintext values in `config.env.vars` and direct string entries under `config.env`.

## Best Possible Solution

Base the detector on authored config or a raw audit snapshot so env-var indirection stays clean, add a regression through config/CLI resolution, and attach redacted real CLI output before merge.

## Reproduction Assessment

Yes, by source inspection. The CLI and config loader resolve `${VAR}` before the new collector inspects `cfg`, so an env-reference config can be treated like plaintext when the environment value starts with `sk-`, `xoxb-`, `xapp-`, `ghp_`, or `AKIA`.

## Solution Assessment

No. The warning belongs in the security-audit path, but the implementation should distinguish authored plaintext config from resolved runtime values and cover that through a CLI/config-resolution regression.
