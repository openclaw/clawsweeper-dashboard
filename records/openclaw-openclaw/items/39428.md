## Summary

Keep open: current main and the latest release still route unmatched Discord account traffic to the default agent, and the remaining fix is a security-sensitive routing contract decision rather than an already-implemented cleanup.

## What This Changes

The issue requests Discord inbound routing to map a non-default accountId to a same-named configured agent when no explicit binding matches, instead of falling back to the default agent.

## Best Possible Solution

Maintainers should choose one explicit Discord multi-account contract: approve a guarded same-name fallback with configured-agent validation, diagnostics, docs, regression tests, and live Discord proof, or keep explicit bindings as the contract and add doctor/status warnings for risky missing bindings.
