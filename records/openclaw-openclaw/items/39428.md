## Summary

Keep open: current main and the latest release still route unmatched Discord account traffic through explicit binding tiers and then the default agent, with no guarded same-name accountId-to-agent fallback. The source gap is clear, but changing fallback behavior is security- and compatibility-sensitive and needs maintainer direction.

## What This Changes

The issue requests Discord inbound routing to map a Discord account id to a same-named configured agent when no explicit binding matches.

## Best Possible Solution

Maintainers should choose and document one contract: guarded Discord same-name account fallback with tests and live proof, or explicit bindings plus doctor/status warnings for risky unbound accounts.
