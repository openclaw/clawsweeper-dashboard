## Summary

Keep open: current main and v2026.6.11 still resolve Discord account traffic through explicit binding tiers and then the default agent, while the linked same-name fallback PRs are unmerged and one open fork PR is still dirty.

## What This Changes

The issue requests Discord inbound routing to map a non-default accountId to a configured agent with the same ID when no explicit binding matches.

## Best Possible Solution

Maintainers should choose one explicit Discord routing contract: land a guarded same-name fallback with configured-agent validation, distinct diagnostics, docs, regression tests, and real Discord proof, or keep explicit bindings as the contract and add doctor/status guidance for risky missing bindings.
