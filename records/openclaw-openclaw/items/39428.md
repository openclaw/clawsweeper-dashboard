Keep open: current main and the latest release still route unmatched Discord account IDs through explicit binding tiers and then the default agent, while the open fork PR that targets this issue is conflicting and lacks real Discord proof. ## What This Changes

Route inbound Discord messages for non-default accounts to a same-named agent when no explicit binding matches, instead of falling back to the default agent.

## Best Possible Solution

Maintainers should choose one explicit contract: approve a guarded Discord-only same-name fallback with agent-list validation, distinct matchedBy diagnostics, docs, regression tests, and live Discord proof, or keep explicit bindings as the contract and add doctor/status guidance for risky missing bindings.
