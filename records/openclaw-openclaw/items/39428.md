## Summary

Keep open: current main and v2026.6.11 still route Discord account traffic through explicit binding tiers and then the configured default agent when no binding matches. The source-level problem is clear, but adding implicit same-name account-to-agent routing changes permission-sensitive fallback semantics and needs maintainer direction.

## What This Changes

Request implicit Discord accountId-to-agent routing when a Discord account name matches an agent ID instead of falling back to the default agent.

## Best Possible Solution

Maintainers should choose one routing contract: approve a guarded Discord same-name fallback with configured-agent validation, distinct diagnostics, docs, regression tests, and live Discord proof, or keep explicit bindings as the contract and add doctor/status warnings for risky missing bindings.
