## Summary

Keep open: current main and the latest release still route unmatched Discord account traffic through explicit binding tiers and then the configured default agent. The source path is clear, but adding an implicit same-name account-to-agent fallback changes security-, session-, provider-, and compatibility-sensitive routing semantics, so it needs maintainer direction before a fix is safe.

## What This Changes

Request Discord inbound routing to choose a same-named agent for a named account when no explicit binding matches instead of falling back to the default agent.

## Best Possible Solution

Maintainers should choose one routing contract: approve a guarded Discord-only same-name fallback with configured-agent validation, distinct diagnostics, docs, regression tests, and live Discord proof, or keep explicit bindings as the contract and add doctor/status guidance for risky missing bindings.
