## Summary

Keep open: current main and v2026.6.11 still route unmatched Discord account traffic through explicit binding tiers and then the default agent, with no same-name accountId-to-agent fallback. The gap is source-reproducible, but changing fallback behavior is a security-sensitive routing contract decision and an open linked fork PR is conflicting rather than merge-ready.

## What This Changes

The issue requests Discord inbound routing to prefer an agent whose id matches the Discord account name before falling back to the default agent.

## Best Possible Solution

Maintainers should choose and document one Discord multi-account routing contract, then add resolver and Discord-route tests plus live Discord proof for the chosen behavior.
