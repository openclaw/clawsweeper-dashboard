## Summary

Keep open: current main and v2026.6.11 still route unmatched Discord account traffic through explicit binding tiers and then to the default agent, while the linked fork PR is unmerged, conflicting, and only a candidate for this security-sensitive routing-contract change.

## What This Changes

The issue requests Discord inbound routing to select an agent whose ID matches the Discord account name before falling back to the default agent.

## Best Possible Solution

Maintainers should choose one explicit Discord routing contract: a guarded same-name fallback with configured-agent validation, distinct diagnostics, docs, regression tests, and live Discord proof, or an explicit-binding-only path with doctor/status warnings for risky missing bindings.
