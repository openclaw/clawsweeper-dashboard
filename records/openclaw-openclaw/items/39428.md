## Summary

Keep open: current main still falls back to the configured default agent when no explicit Discord account binding matches, and changing that fallback is a security-sensitive routing contract decision rather than a cleanup close.

## What This Changes

Request automatic Discord routing from a non-default account name to a same-named configured agent when no explicit binding is present.

## Best Possible Solution

Define one Discord multi-account routing contract: either implement a guarded non-default accountId-to-configured-agent fallback with diagnostics, docs, tests, and live proof, or keep explicit bindings as the supported contract and add doctor/status guidance for risky missing bindings.
