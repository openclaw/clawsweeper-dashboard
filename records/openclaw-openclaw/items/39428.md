## Summary

Keep open: current main and the latest release still route unmatched Discord account traffic through explicit binding tiers and then to the default agent, while the requested same-name account-to-agent fallback remains a security-sensitive routing contract decision rather than an implemented fix.

## What This Changes

The issue requests Discord inbound routing to choose a configured agent whose ID matches the Discord account ID before falling back to the default agent.

## Best Possible Solution

Maintainers should choose one explicit contract: approve a guarded Discord-only same-name fallback after explicit binding tiers with agent-list validation, distinct diagnostics, docs, regression tests, and live Discord proof, or keep explicit bindings as the contract and add doctor/status guidance for risky missing bindings.
