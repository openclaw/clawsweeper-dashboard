## Summary

Keep open: current main and v2026.6.11 still route unmatched Discord account traffic through explicit binding tiers and then the configured default agent. The source reproduction is clear, but adding implicit same-name account-to-agent fallback changes security- and compatibility-sensitive routing semantics and needs maintainer direction before a replacement fix is safe.

## What This Changes

The issue requests Discord inbound routing to select a same-named agent from the accountId when explicit bindings do not match.

## Best Possible Solution

Maintainers should choose one routing contract: approve a guarded Discord-only same-name fallback with configured-agent validation, distinct diagnostics, docs, regression tests, and live Discord proof, or keep explicit bindings as the contract and add doctor/status guidance for risky missing bindings.
