## Summary

Keep open: current main and v2026.6.11 still route unmatched Discord account traffic through explicit binding tiers and then the default agent, with no guarded same-name account-to-agent fallback. The issue remains useful, but the fix changes security- and compatibility-sensitive routing semantics and an open fork PR is conflicting rather than landed proof.

## What This Changes

Route Discord inbound messages from a non-default account to a same-named configured agent when no explicit binding matches.

## Best Possible Solution

Maintainers should choose one contract: approve a guarded Discord-only same-name fallback with configured-agent validation, distinct diagnostics, docs, regression tests, and live Discord proof, or keep explicit bindings as the contract and add doctor/status guidance for risky missing bindings.
