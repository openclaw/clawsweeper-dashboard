Keep open: current main and the latest release still route unmatched Discord account traffic through the explicit binding tiers and then to the default agent, while an open fork PR targets this issue but is conflicting and unproven.

## What This Changes

## Best Possible Solution

Maintainers should choose one explicit contract: approve a guarded Discord-only same-name fallback with configured-agent validation, distinct diagnostics, docs, tests, and live Discord proof, or keep explicit bindings as the contract and add doctor/status guidance for risky missing bindings.
