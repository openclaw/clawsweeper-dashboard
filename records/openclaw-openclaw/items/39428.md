## Summary

Keep open: current main and the latest release still route unmatched Discord account traffic to the default agent, while the requested same-name fallback remains a security-sensitive routing contract decision with no merged safe fix.

## What This Changes

Discord inbound routing should use a Discord account name that matches an agent ID instead of falling through to the default agent when no explicit binding exists.

## Best Possible Solution

Maintainers should choose one Discord routing contract: approve a guarded same-name fallback with agent-list validation, distinct diagnostics, docs, regression tests, and live Discord proof, or keep explicit bindings as the contract and add doctor/status guidance for risky missing bindings.
