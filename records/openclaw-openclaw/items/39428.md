## Summary

Keep open: current main and v2026.6.11 still require explicit route bindings before falling back to the default agent, while the same-name Discord account fallback remains a security-sensitive routing policy decision with an open but conflicting/unproven fork PR.

## What This Changes

Route Discord inbound messages from a named account to an agent with the same id when no explicit binding matches.

## Best Possible Solution

Choose a maintainer-approved secure routing contract for unmatched named Discord accounts, then implement it with focused resolver tests, Discord docs, and upgrade/security proof.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should unmatched non-default Discord account ids implicitly route to same-named configured agents, fail closed, or remain explicit-binding-only with stronger setup/doctor diagnostics?

Rationale: The current documented contract uses explicit bindings, but the reported default fallback can cross agent permission boundaries; changing it is both compatibility-sensitive and security-sensitive.

Likely owner: steipete

Owner reason: The decision spans routing policy and security-sensitive fallback behavior, and steipete has the strongest central routing history in the sampled commits.

Owner confidence: medium

Options:

- **Guarded same-name fallback (recommended):** Route non-default Discord accounts to an existing same-named agent only after explicit binding tiers miss, keeping the `default` account on the existing default-agent path and adding tests/docs.
- **Explicit bindings plus diagnostics:** Keep runtime routing unchanged but add setup/doctor warnings or repairs so named Discord accounts without bindings are visible before they route to default.
- **Fail closed for unmatched named accounts:** Reject or drop unmatched named Discord account traffic until an explicit binding exists, maximizing safety at the cost of upgrade compatibility.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: with no matching binding, `resolveAgentRoute` checks explicit binding tiers and then returns the default agent. I did not run a live Discord gateway scenario in this read-only review.

## Solution Assessment

Unclear pending maintainer direction: the proposed same-name fallback directly addresses the report, but explicit-binding diagnostics or fail-closed unmatched accounts may be safer compatibility/security choices.
