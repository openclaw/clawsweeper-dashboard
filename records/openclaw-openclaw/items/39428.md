## Summary

Keep open: current main and v2026.6.11 still route unmatched Discord account traffic through explicit binding tiers and then to the default agent, while the remaining fix is a security-sensitive routing-contract decision rather than an already-implemented behavior.

## What This Changes

The issue asks OpenClaw to route Discord messages from a named account to a same-named configured agent when no explicit binding matches.

## Best Possible Solution

Maintainers should choose one explicit contract: approve a guarded Discord-only same-name fallback with agent-list validation, distinct diagnostics, docs, regression tests, and live Discord proof, or keep explicit bindings as the contract and add doctor/status guidance for risky missing bindings.
