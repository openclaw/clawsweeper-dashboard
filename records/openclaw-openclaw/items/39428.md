## Summary

Keep open: current main still resolves unmatched Discord account traffic through explicit binding tiers and then the configured default agent. The requested same-name Discord account-to-agent fallback remains unresolved and needs maintainer direction because it changes a permission-sensitive routing contract.

## What This Changes

The issue requests Discord account IDs that match agent IDs to route inbound messages to those agents instead of falling back to the default agent when no explicit binding matches.

## Best Possible Solution

A maintained solution should either implement a guarded Discord-only same-name fallback with configured-agent validation, distinct diagnostics, docs, regression tests, and live Discord proof, or keep explicit bindings as the contract and add doctor/status guidance for risky missing bindings.
