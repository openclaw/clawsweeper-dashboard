## Summary

Keep open: current main and v2026.6.11 still route unmatched Discord account traffic through explicit binding tiers and then the configured default agent. The requested same-name Discord account-to-agent fallback remains unresolved and is permission-sensitive enough to need maintainer direction.

## What This Changes

The issue requests Discord to route an inbound accountId to a same-named agent when explicit bindings do not match instead of falling back to the default agent.

## Best Possible Solution

A maintained solution should either implement a guarded Discord-only same-name fallback with configured-agent validation, distinct diagnostics, docs, regression tests, and live Discord proof, or keep explicit bindings as the contract and add doctor/status guidance for risky missing bindings.
