## Summary

Keep open: current main and v2026.6.11 still route unmatched Discord account traffic to the default agent, while the requested same-name fallback is a security-sensitive routing contract change that needs maintainer direction.

## What This Changes

The issue requests Discord inbound routing to map a non-default accountId to a same-named configured agent when no explicit binding matches.

## Best Possible Solution

Maintainers should choose one explicit Discord routing contract: approve a guarded non-default same-name fallback with diagnostics, docs, tests, and live Discord proof, or keep explicit bindings as the contract and add doctor/status guidance for risky missing bindings.
