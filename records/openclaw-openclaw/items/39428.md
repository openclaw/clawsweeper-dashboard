## Summary

Keep open: current main and the latest release still use explicit routing bindings followed by default-agent fallback, with no guarded Discord same-name account-to-agent fallback. The source gap is clear, but changing fallback routing is permission-, session-, and compatibility-sensitive, and the linked PR attempts are not merged or safe canonical fixes.

## What This Changes

The issue requests that Discord inbound messages route to an agent whose ID matches the Discord account name before falling back to the default agent.

## Best Possible Solution

Maintainers should choose one contract: approve a guarded Discord-only same-name fallback with configured-agent validation, distinct diagnostics, docs, regression tests, and live Discord proof, or keep explicit bindings as the contract and add doctor/status guidance for risky missing bindings.
