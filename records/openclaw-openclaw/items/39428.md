## Summary

Keep open: current main and the latest release still route Discord account traffic through explicit binding tiers and then the configured default agent. The requested same-name Discord account-to-agent fallback remains unresolved and needs maintainer product/security direction because it changes a permission-sensitive routing contract.

## What This Changes

Request same-name Discord account IDs to route inbound messages to matching agent IDs instead of falling back to the default agent when no explicit binding matches.

## Best Possible Solution

Keep this issue as the canonical tracker and land a maintainer-approved Discord routing fix that preserves default-account behavior, rejects phantom agents, uses distinct diagnostics, updates docs/tests, and includes redacted live Discord proof.
