## Summary

Keep open: current main and v2026.6.11 still route unmatched Discord account traffic through explicit binding tiers and then the default agent, with no guarded same-name account-to-agent fallback. The source gap is clear, but changing this fallback is security- and compatibility-sensitive and the linked fork PR is conflicting and not merge-ready.

## What This Changes

Request Discord multi-account inbound routing to select a same-named configured agent when no explicit binding matches, instead of falling back to the default agent.

## Best Possible Solution

Maintainers should choose one routing contract: implement a guarded Discord-only same-name fallback with validation, diagnostics, docs, regression tests, and live proof, or keep explicit bindings as the contract and add doctor/status guidance for risky missing bindings.
