## Summary

Keep open: current main and v2026.6.11 still route Discord account traffic through explicit binding tiers and then the default agent when no binding matches. The source-level gap is clear, but adding implicit same-name account-to-agent routing changes permission-sensitive fallback semantics and needs maintainer direction before another fix PR is queued.

## What This Changes

The issue requests Discord inbound routing to map a Discord account name to a matching agent ID instead of falling back to the default agent when no explicit binding matches.

## Best Possible Solution

Maintainers should choose one explicit contract: approve a guarded Discord-only same-name fallback with configured-agent validation, distinct diagnostics, docs, regression tests, and live Discord proof, or keep explicit bindings as the contract and add doctor/status guidance for risky missing bindings.
