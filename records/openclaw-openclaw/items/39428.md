## Summary

Keep open: current main and v2026.6.11 still route Discord account IDs only through explicit binding tiers and then the default agent, while the requested same-name account fallback remains a security-sensitive routing decision with an open fork PR candidate that is conflicting and unproven.

## What This Changes

The issue requests Discord inbound routing to map a non-default Discord account ID to a same-named agent when no explicit binding matches.

## Best Possible Solution

Maintainers should decide whether explicit bindings remain the contract or land a guarded Discord-only fallback with a configured-agent guard, distinct diagnostics, docs, regression tests, and redacted real Discord proof.

## Reproduction Assessment

Yes, at source level. Discord passes accountId into resolveAgentRoute, and the resolver falls through to the configured default agent after explicit binding tiers when no binding matches.

## Solution Assessment

Unclear. A guarded Discord-only accountId-to-agent fallback is plausible, but current docs support explicit bindings and repository policy treats fallback behavior as a product/security decision.
