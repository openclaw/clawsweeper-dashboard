## Summary

Keep open: current main and v2026.6.11 still fall through to the default agent after explicit Discord binding tiers miss, and the remaining same-name fallback is a permission-sensitive routing contract decision rather than conservative cleanup.

## What This Changes

The issue requests Discord inbound routing to select a same-named agent when the Discord account ID matches an agent ID and no explicit binding is configured.

## Best Possible Solution

Maintainers should choose one explicit contract: approve a guarded Discord-only same-name fallback with configured-agent validation, distinct diagnostics, docs, tests, and live Discord proof, or keep explicit bindings as the contract and add doctor/status guidance for risky missing bindings.
