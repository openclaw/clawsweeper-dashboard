## Summary

Keep open: current main and v2026.6.11 still route unmatched Discord account traffic through explicit binding tiers and then the default agent, while the remaining fix requires a security-sensitive routing contract decision.

## What This Changes

The issue requests implicit Discord routing from a non-default accountId to a same-named configured agent when no explicit binding matches.

## Best Possible Solution

Maintainers should choose one explicit contract: approve a guarded Discord-only same-name fallback with configured-agent validation, distinct diagnostics, docs, regression tests, and live Discord proof, or keep explicit bindings as the contract and add doctor/status guidance for risky missing bindings.
