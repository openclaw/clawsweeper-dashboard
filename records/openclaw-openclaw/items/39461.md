## Summary

Keep open: current main and the latest release still ignore `QQBOT_DATA_DIR`, diagnostics still recommend it, and the open linked PR is an implementation candidate rather than a merged fix.

## What This Changes

QQBot should honor `QQBOT_DATA_DIR` for its data directory instead of always reporting and creating the OS-home `~/.openclaw/qqbot` path.

## Best Possible Solution

Resolve the QQBot data-root contract in the linked PR: either support a validated `QQBOT_DATA_DIR` override with docs/tests/proof, or replace the diagnostic with the supported `OPENCLAW_HOME` or SQLite-state guidance.
