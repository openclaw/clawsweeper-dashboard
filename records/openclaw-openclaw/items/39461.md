## Summary

Keep open: current main and the latest release still ignore `QQBOT_DATA_DIR` while QQBot diagnostics recommend it, and https://github.com/openclaw/openclaw/pull/78253 is an open candidate fix rather than a merged implementation.

## What This Changes

The issue asks QQBot to honor `QQBOT_DATA_DIR` for its data directory so Windows diagnostics stop reporting the home-based path after the env var is set.

## Best Possible Solution

Resolve the contract in the linked PR: either implement a validated `QQBOT_DATA_DIR` override with docs, tests, and real diagnostic proof, or intentionally replace the diagnostic with the supported storage guidance.
