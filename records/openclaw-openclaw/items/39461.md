## Summary

Keep open: current main and the latest release still ignore `QQBOT_DATA_DIR`, and the linked open PR is an implementation candidate rather than a merged fix.

## What This Changes

The issue reports that QQBot diagnostics recommend `QQBOT_DATA_DIR`, but the plugin still resolves its data directory from the OS home path on Windows setups with problematic home paths.

## Best Possible Solution

Resolve the contract in the linked PR: either safely implement and document a validated `QQBOT_DATA_DIR` override in the QQBot plugin, or deliberately replace the diagnostic with the supported `OPENCLAW_HOME` or SQLite-state guidance.
