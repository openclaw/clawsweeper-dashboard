## Summary

Keep open: current main and `v2026.6.11` still ignore `QQBOT_DATA_DIR`, and the open linked PR is an unmerged candidate rather than an implemented fix.

## What This Changes

The issue asks QQBot to honor `QQBOT_DATA_DIR` so Windows users can move QQBot data off a non-ASCII or spaced home-directory path.

## Best Possible Solution

Resolve the contract in the linked PR: either safely implement and document a validated `QQBOT_DATA_DIR` override in the QQBot plugin, or deliberately replace the diagnostic with supported `OPENCLAW_HOME` or SQLite-state guidance.
