## Summary

Keep open: current main and the latest release still ignore `QQBOT_DATA_DIR`, and an open closing PR already owns the candidate implementation, so this issue should not be closed until that PR lands or maintainers choose to retire the diagnostic hint.

## What This Changes

The issue asks QQBot to use `QQBOT_DATA_DIR` for its data directory instead of always reporting and creating `~/.openclaw/qqbot`.

## Best Possible Solution

Decide the supported QQBot data-root contract, then either land a validated `QQBOT_DATA_DIR` implementation with docs and real diagnostic proof or replace the diagnostic guidance with supported `OPENCLAW_HOME` or SQLite-state instructions.
