## Summary

Keep open: the latest head moved in the right direction, but `hasAnyClassificationData` is computed only from cron/dreaming classification sets, so a session store containing ordinary non-cron rows still looks like “no store data” and the first-turn `[cron:]` fallback can still wipe content.

## What This Changes

The PR narrows `buildSessionEntry` cron text fallback to first-message, no-session-store-data archive cases and adds regression tests for mid-transcript, explicit non-cron, and metadata-less cron archive behavior.

## Best Possible Solution

Land one canonical memory-host-sdk fix that derives “unknown” from raw session-store/corpus availability, trusts explicit non-cron provenance, preserves metadata-less cron opacity, and proves all three archive cases.

## Reproduction Assessment

Yes. Source inspection of PR head shows the new ordinary session-store test uses only a non-cron row, while `hasAnyClassificationData` still returns false because it checks only cron/dreaming sets, so the first-turn text fallback remains enabled.

## Solution Assessment

No. The fix location is right, but the current implementation does not actually distinguish “store exists and says non-cron” from “no store data,” so the state model needs a small repair before this is the best fix.
