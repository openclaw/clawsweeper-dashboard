## Summary

This PR remains necessary for the linked localized-ENOENT bug, but the unchanged current head retains two prior P1 blockers: a predictable persistent temporary file in a sandbox command and an overbroad parent-error match that can misclassify non-ENOENT failures. The Docker transcript is useful evidence, but it does not exercise current-head `SandboxFsBridge.stat()` under a localized environment or cover the adversarial operand and temporary-file cases.

## What This Changes

Changes sandbox filesystem stat handling to emit and consume an exit-code-2 `ENOENT` sentinel under `LC_ALL=C`, with focused mocked error-path tests.

## Best Possible Solution

Capture the parent `stat` diagnostic without a filesystem temporary, require an ENOENT diagnostic suffix rather than an anywhere-match, preserve same-shell `cd` anchoring, and prove the real bridge path in a localized non-root container with missing, permission-denied, crafted-operand, and cleanup cases.
