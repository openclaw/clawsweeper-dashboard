## Summary

Keep this PR open: it addresses a valid sandbox bug and resolves the earlier review blockers, but the current shell classifier can still mistake user-controlled filename text for the ENOENT diagnostic, converting a different `stat` failure into `null`.

## What This Changes

Pins sandbox `stat` execution to the C locale, maps recognized file-not-found diagnostics to an exit-code-2 sentinel, handles that sentinel in the filesystem bridge, and adds regression coverage.

## Best Possible Solution

Keep the C locale and single `stat` call, but recognize only the terminal ENOENT diagnostic rather than any occurrence of the phrase, with regression coverage for an adversarial basename containing that text during a non-ENOENT failure.
