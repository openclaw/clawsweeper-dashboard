## Summary

Keep open: the locale bug is valid, but this patch replaces it with broader failure masking because `stat` exit status 1 does not uniquely mean “file not found.”

**Likely related people**
- `@steipete` — high confidence; primary recent contributor across the sandbox filesystem bridge history.

## What This Changes

Changes `SandboxFsBridge.stat()` to classify exit code 1 as a missing file and adds mocked tests for localized stderr and a synthetic exit-code-2 error.

## Best Possible Solution

Have the shell plan emit a dedicated sentinel status only after verifying the target is absent, while preserving every other `stat` failure and adding real GNU or BusyBox container proof for localized ENOENT and permission-denied cases.

- **[P1] Preserve non-ENOENT failures that also exit with status 1:** `src/agents/sandbox/fs-bridge.ts:211`
  - body: GNU coreutils `stat` returns the same `EXIT_FAILURE`—normally 1—for any failed operand, and BusyBox follows the same pattern.
