## Label Justifications

- `P1`: The current head changes a security-sensitive sandbox stat path and can silently misclassify real filesystem failures while writing through a predictable temporary pathname.
- `merge-risk: 🚨 compatibility`: Existing callers that receive exceptions for permission or filesystem failures could instead receive `null` after a false ENOENT classification.
- `merge-risk: 🚨 security-boundary`: The new sandbox command writes stderr to a predictable shared `/tmp` pathname that a same-user process can pre-create or redirect.

## Summary

The linked bug remains real on current main, but this PR still introduces two P1 defects in the sandbox shell plan and its Docker transcript exercises copied shell text rather than current-head `SandboxFsBridge.stat()`.

## What This Changes

Changes sandbox filesystem stat handling to emit and consume an exit-code-2 `ENOENT` sentinel under `LC_ALL=C`, adds a parent pre-check, and adds mocked error-path tests.

## Best Possible Solution

Capture the parent `stat` diagnostic without a filesystem temporary, use the same suffix-only ENOENT classification as the target path, add generated-plan regressions for crafted operands and non-ENOENT parent failures, and show a redacted current-head bridge run in a localized container.
