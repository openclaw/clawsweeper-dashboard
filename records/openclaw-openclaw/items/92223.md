## Summary

The stack-safe parser changes are focused and appear correct, but this PR also deletes a targeted class of persisted failed Control UI sends during upgrade. Keep it open until a maintainer accepts that state-migration boundary and the rebased current head has real browser/Gateway proof for both successful large-attachment delivery and selective queue cleanup.

## What This Changes

The PR replaces full-payload data-URL regex parsing in Gateway and Control UI attachment paths with bounded parsing, removes identifiable legacy stack-overflow queue failures, and adds regression coverage.

## Best Possible Solution

Keep the bounded Gateway and Control UI parsers, but merge the queue cleanup only after current-head browser proof demonstrates a large attachment completes without `RangeError` and an upgrade reload removes only the intended legacy failure while preserving a newly marked retryable failure.
