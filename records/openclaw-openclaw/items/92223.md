- `P1`: The PR targets a production-observed attachment workflow failure where large Control UI/gateway sends can hit `RangeError` and block message delivery.
- `merge-risk: 🚨 compatibility`: Existing agent PDF config keys would begin affecting inbound extraction limits, changing upgrade behavior for configured users.

## Summary

Keep open: the PR is still useful because current main only partially covers the large-attachment problem, but the branch needs repair before merge because one new pasted-data-URL path rebuilds a multi-megabyte base64 string with repeated concatenation, which can recreate the V8 stack/flattening failure this PR is meant to remove.

## What This Changes

The PR changes gateway and Control UI attachment parsing, inbound media extraction limits, stale failed composer queue cleanup, tests, and config documentation for stack-safe large PDF/file handling.

## Best Possible Solution

Land a rebased version that uses one chunked or otherwise flat-string stack-safe parser shape across gateway and the current Control UI chat paths, keeps bounded inbound extraction/config docs aligned, and proves the large PDF/file flow in a real browser plus gateway log.
