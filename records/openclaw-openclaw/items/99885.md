## Summary

Keep open: current main and the latest stable release still stage git plugin clones under the process temp directory before publishing into the managed git root, so the reported cross-device `EXDEV` failure remains. The issue now has an open, mergeable, proof-sufficient linked fix candidate, so it should stay open until that PR lands or is rejected.

## What This Changes

The issue reports that git-backed plugin installation fails with `EXDEV` when the temp staging directory and OpenClaw managed git plugin directory are on different filesystems, such as Docker bind-mounted state directories.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99896 if maintainers accept the same-filesystem staging approach; otherwise keep the repair on the git plugin installer publish path and preserve install policy, npm install, rollback, cleanup, and security-event semantics.

## Reproduction Assessment

Yes. Current main stages git plugin clones under `os.tmpdir()` and then publishes the staged repo into the managed git root through `replaceDirectoryAtomic`, which source-proves the `EXDEV` path when those roots are on different filesystems.

## Solution Assessment

Yes. The best current path is the open same-filesystem staging PR, because it keeps the existing replacement primitive and avoids adding a new user-facing setting or relying on the `TMPDIR` workaround.
