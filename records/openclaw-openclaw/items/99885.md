## Summary

## What This Changes

The issue reports `openclaw plugins install git:<repo>` failing with `EXDEV` when the temporary clone and the managed OpenClaw git plugin directory are on different filesystems, especially in Docker bind-mounted homes.

## Best Possible Solution

Make managed git plugin repository publishing cross-device safe while preserving install-policy scanning, npm dependency install, rollback, security event, and cleanup semantics.

## Reproduction Assessment

Yes from source, with high confidence: current main stages git clones under `os.tmpdir()` and then asks `replaceDirectoryAtomic` to rename that staged directory into the managed git plugin directory. I did not run a live Docker bind-mount repro during this read-only pass.

## Solution Assessment

Yes: a narrow installer repair is the best path. Use a same-filesystem staging/publish flow or the existing fs-safe copy-fallback move primitive rather than adding a new user-facing config or relying on the `TMPDIR` workaround.
