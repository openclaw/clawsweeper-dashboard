## Summary

Keep open: current main and the latest release still stage git plugin clones under the process temp directory and publish them through the rename-based managed-repo replacement path, so the reported split-filesystem Docker failure is still present. The open proof-sufficient PR at https://github.com/openclaw/openclaw/pull/99896 is the right fix candidate, but the issue should remain open until that PR or an equivalent fix merges.

## What This Changes

Fix git-backed plugin installs so Docker or bind-mounted setups with `/tmp` and OpenClaw state on different filesystems do not fail with `EXDEV` during managed repository publish.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/99896 or an equivalent narrow installer fix, then close this issue after the fix reaches main.

## Reproduction Assessment

Yes. Current main stages git plugin clones under `os.tmpdir()` and then publishes the staged repository through a rename-based managed-repo replacement path, which source-proves the `EXDEV` failure when those directories are on different filesystems.

## Solution Assessment

Yes. The best fix is the open same-filesystem staging PR or an equivalent narrow installer repair that preserves install policy, dependency install, publish, rollback, cleanup, and security event semantics.
