## Summary

Keep open: current main and the latest release still stage git plugin clones under the process temp directory and publish them through a rename-based directory replacement path, so the reported split-filesystem Docker failure remains valid. The open proof-sufficient fix PR is the right implementation candidate, but this issue should stay open until that PR merges.

## What This Changes

The issue requests making `openclaw plugins install git:<repo>` work when `/tmp` and the managed OpenClaw git plugin directory are on different filesystems, as in Docker bind-mounted state directories.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99896, or close it only if maintainers choose a different fix; this issue should close after a cross-device-safe git plugin install path reaches main.

## Reproduction Assessment

Yes from source, with high confidence: current main stages git plugin clones under `os.tmpdir()` and publishes them through a rename-based directory replacement path. I did not run a live Docker bind-mount repro during this read-only pass.

## Solution Assessment

Yes: a narrow installer repair is the best path, and the open same-filesystem staging PR is currently the best candidate because it avoids adding a new user-facing config or relying on `TMPDIR`.
