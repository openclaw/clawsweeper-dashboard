## Summary

Keep open: the current head is not merge-ready because it advertises full generic CLI `assemble-before-prompt` support while projecting only part of the assemble result, running assembly before CLI bootstrap, and lacking real behavior proof.

## What This Changes

The PR adds `assemble-before-prompt` to generic CLI context-engine host capabilities, calls `assembleHarnessContextEngine()` during CLI run preparation, prepends returned `systemPromptAddition`, and updates compatibility tests.

## Best Possible Solution

Either keep generic CLI rejecting full `assemble-before-prompt`, or implement full post-bootstrap CLI assembly projection into the actual CLI prompt/input path with focused tests and redacted live proof.

## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Do not advertise full assemble support without projection:** `src/context-engine/host-compat.ts:18`
  - body: Adding this default capability makes engines that require `assemble-before-prompt` run on generic CLI, but the new path only writes `systemPromptAddition` into `context.systemPrompt`. Returned `messages`, `promptAuthority`, and `contextProjection` are never projected, and resumed backends using `systemPromptWhen: "first"` or `"never"` can still drop even that prompt addition, so required current-turn context can silently be absent.
  - confidence: 0.91
- **[P2] Run CLI assembly after context-engine bootstrap:** `src/agents/cli-runner/prepare.ts:1081`
  - body: This assemble call runs during prepare, while generic CLI bootstraps the context engine later in `runPreparedCliAgent` and then loads context-engine snapshot history. Engines whose bootstrap or maintenance rewrites session state can assemble from pre-bootstrap bounded hook history, unlike the embedded and Codex paths that bootstrap before assembly.
  - confidence: 0.86
