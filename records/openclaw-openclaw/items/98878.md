## What This Changes

## Best Possible Solution

Apply the seconds fallback consistently to both Codex dynamic-tool timeout readers, add focused tests for the main and side-question paths, then land one canonical PR for https://github.com/openclaw/openclaw/issues/98864.

## Reproduction Assessment

## Solution Assessment

No: the proposed shape is the right local fix for one path, but it should also update the side-question dynamic-tool timeout reader that shares the same protocol and timeout invariant.
