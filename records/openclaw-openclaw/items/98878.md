## Best Possible Solution

Land one canonical fix that uses shared seconds conversion with watchdog grace for `timeoutSeconds`, keeps `timeoutMs` as an exact override, covers main and side-question paths, and includes redacted real Codex dynamic-tool proof.

## Reproduction Assessment

Yes, at source level: current main reads only `timeoutMs` in both Codex dynamic-tool timeout readers, while `sessions_send` exposes `timeoutSeconds` and Codex forwards tool arguments as raw JSON. I did not run a live Codex timeout turn in this read-only review.

## Solution Assessment

No: the PR touches the right owner area, but the exact seconds-form watchdog can preempt `sessions_send` before it returns its structured timeout result. The safer fix is shared seconds conversion plus grace/headroom for `timeoutSeconds`, with `timeoutMs` preserving exact override behavior.
