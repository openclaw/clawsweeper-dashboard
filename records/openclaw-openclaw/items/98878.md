## Summary

Keep open: the branch now patches both Codex dynamic-tool timeout readers, but it arms the outer watchdog at the exact `timeoutSeconds` budget that `sessions_send` uses internally, so it can replace the tool's structured timeout result with a generic hard-timeout response. Real behavior proof is still build/test-only.

## What This Changes

The PR adds `timeoutSeconds` fallback handling to the main and side-question Codex dynamic-tool timeout readers and adds main resolver regression tests.

## Best Possible Solution

Land one canonical fix that converts seconds with the shared timer helper, adds headroom for `timeoutSeconds` watchdogs while keeping `timeoutMs` exact, covers both main and side-question paths, and includes real behavior proof.

## Reproduction Assessment

Yes, source-level: current main's dynamic and side-question readers inspect only `timeoutMs`, while `sessions_send` exposes `timeoutSeconds` and Codex forwards dynamic tool arguments as raw JSON. I did not run a live Codex timeout turn in this read-only review.

## Solution Assessment

No: this is the right owner area, but setting the outer watchdog to the exact seconds budget can preempt `sessions_send` before it returns its structured timeout result. The safer fix is shared seconds conversion plus grace/headroom for `timeoutSeconds`, with `timeoutMs` preserving exact override behavior.
