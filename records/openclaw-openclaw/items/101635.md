## Summary

Keep open: the PR now has direct terminal proof for the wrapped edit shape, but the patch introduces a narrow correctness regression by letting an `item` metadata field override canonical `oldText`/`newText` edit fields.

## What This Changes

The PR updates the edit tool argument preparer to unwrap XML-RPC-style `{ item: { oldText, newText } }` entries and adds a regression test for that wrapped shape.

## Best Possible Solution

Keep prepare-time normalization, but only unwrap true XML-RPC wrapper entries or entries without direct edit fields, and add regression coverage proving direct `oldText`/`newText` still win when extra `item` metadata is present.
