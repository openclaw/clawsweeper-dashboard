## Summary

Keep open: current main and the latest release still select an explicit camera `deviceId` before considering `facing`, and no related issue or PR currently fixes iPhone Continuity Camera front/back lens selection.

## What This Changes

The issue asks for `openclaw nodes camera snap --device-id <iPhone Continuity Camera> --facing front` to capture from the iPhone front camera instead of always capturing from the rear camera.

## Best Possible Solution

Live-test current main with a paired iPhone Continuity Camera, then either implement a supported Continuity lens-selection path or document/diagnose that explicit Continuity Camera device IDs select only the OS-exposed camera.
