## Summary

Keep open: current main and the latest release still make an explicit camera `deviceId` win before front/back selection, and the requested Continuity Camera behavior needs live macOS+iPhone proof plus a maintainer decision on selector precedence.

## What This Changes

The issue reports that `openclaw nodes camera snap --facing front` does not select the front camera for an iPhone Continuity Camera device and captures from the rear camera like `--facing back`.

## Best Possible Solution

Live-test a signed current macOS companion with a paired iPhone, then either implement supported Continuity front/back lens selection without weakening exact `deviceId` targeting or document/surface the platform limitation clearly.

## Maintainer Decision

Required: true

Question: Should macOS camera capture treat `--facing front|back` as a secondary lens selector when an explicit iPhone Continuity Camera `--device-id` is also supplied?

Rationale: Current source treats `deviceId` as an exact camera selector before any facing lookup, but the requested behavior would make `facing` affect a selected external device; that precedence contract needs maintainer intent plus live AVFoundation proof.

Likely owner: steipete

Owner reason: Peter is tied to the current macOS camera picker and prior device-id support history that created the selector-precedence question.

Owner confidence: medium

Options:

- **Preserve exact device targeting (recommended):** Keep `deviceId` as the highest-precedence selector and add a clear limitation or diagnostic if Continuity Camera exposes only one selectable external camera.
- **Add Continuity lens selection:** If live proof shows AVFoundation exposes a reliable front/back selector for the same iPhone, add a narrow macOS implementation and coverage for that behavior.
- **Let facing override device id:** Allow `facing` to replace or ignore an explicit `deviceId`, accepting compatibility risk for multi-camera users who expect exact device targeting.

## Reproduction Assessment

No high-confidence live reproduction was performed in this review. Source inspection shows the reported selector ambiguity is plausible because `deviceId` is matched before requested front/back position, but current macOS plus iPhone hardware proof is still needed.

## Solution Assessment

Unclear. A direct precedence swap is not clearly the best fix because `deviceId` is currently an exact selector; the maintainable solution depends on AVFoundation Continuity Camera behavior and maintainer intent.
