## Summary

Keep open: current main and the latest release still preserve the reported `deviceId` versus `facing` ambiguity, and the safe outcome needs live Continuity Camera proof plus a maintainer decision on selector precedence.

## What This Changes

The issue reports that iPhone Continuity Camera captures from the rear camera for both `--facing front` and `--facing back` when an explicit Continuity Camera device ID is used.

## Best Possible Solution

Live-test the current macOS companion with a paired iPhone Continuity Camera, then either implement a supported front/back selection path or make the CLI/docs clearly state that explicit Continuity Camera device IDs select only the OS-exposed camera.

- **Let facing override device id:** Change selector precedence so `facing` can replace an explicit device id, accepting compatibility risk for existing multi-camera users.
