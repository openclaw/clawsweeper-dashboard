## Summary

Keep open: current main and the latest release still pass the requested `deviceId` through before using `facing`, so the Continuity Camera report remains plausible and is not covered by an implemented fix or duplicate.

## What This Changes

The issue reports that iPhone Continuity Camera ignores `--facing front` and captures from the rear camera for both front and back requests.

## Best Possible Solution

Live-test the current macOS companion with a paired iPhone Continuity Camera, then either implement supported front/back lens selection or document and diagnose that explicit Continuity Camera device ids select only the OS-exposed camera.
