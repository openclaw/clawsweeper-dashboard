## Summary

Keep open: current main and the latest release still preserve exact `deviceId` camera selection before `facing`, so the Continuity Camera report remains plausible and needs live macOS+iPhone proof plus a selector-precedence decision.

## What This Changes

The issue reports that `openclaw nodes camera snap --device-id ... --facing front` on macOS iPhone Continuity Camera captures the rear camera, the same as `--facing back`.

## Best Possible Solution

Live-test the current macOS companion with a paired iPhone Continuity Camera, then either implement a supported front/back lens selection path or document and diagnose that explicit Continuity Camera device IDs select only the OS-exposed camera.
