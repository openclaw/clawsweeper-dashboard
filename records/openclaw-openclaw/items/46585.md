## Summary

Keep open: current main and the latest release still select an exact macOS camera `deviceId` before using `facing`, so the Continuity Camera report remains plausible and needs live macOS+iPhone proof plus a selector-precedence decision.

## What This Changes

The issue reports that `openclaw nodes camera snap --device-id <iPhone Continuity Camera> --facing front` captures from the rear camera, same as `--facing back`.

## Best Possible Solution

Live-test current macOS with a paired iPhone Continuity Camera, then either implement a supported front/back selection path or document and diagnose that explicit Continuity Camera device ids select only the OS-exposed camera.
