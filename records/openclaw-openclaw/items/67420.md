## Summary

Keep open. The requested control is useful and tied to an open canonical issue, but this patch is not merge-ready because explicit opt-outs can be reintroduced by default/primary workspace fallback and the PR has no real behavior proof.

## What This Changes

The PR adds `agents.list[].dreaming.enabled` as a per-agent memory dreaming opt-out, with config type/schema/generated schema updates, docs, and one resolver test.

## Best Possible Solution

Land a refreshed PR or successor that makes explicit disabled-agent opt-outs survive default and primary-workspace fallback, keeps schema/type/generated schema/docs aligned, and includes real behavior proof plus focused mixed, all-disabled, and disabled-primary tests.

## Reproduction Assessment

Yes for the patch defect by source inspection: if the PR filters every configured agent out, current resolver fallback code still adds the default agent and the runtime caller can add the primary workspace. The original OOM report remains source-reproducible rather than live-reproduced here.

## Solution Assessment

No. A per-agent opt-out is a plausible mitigation, but the best fix must track explicit opt-outs through fallback selection and use fallback only when no configured agents exist, not when all configured agents opted out.
