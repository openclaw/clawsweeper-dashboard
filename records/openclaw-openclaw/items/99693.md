## Label Justifications

- `P2`: The issue is a normal-priority Telegram reliability bug limited to long chunked outbound replies and partial send failures.
- `impact:message-loss`: A rejected middle Telegram chunk can prevent later chunks of the same outbound reply from being delivered.

## Summary

Keep open: current main still aborts Telegram chunk delivery when a later chunk rejects outside the existing narrow fallback cases, and current tests explicitly assert that behavior. The issue is valid, but the fix needs a maintainer decision on which chunk errors are recoverable versus fatal.

## What This Changes

The issue asks for Telegram text and rich-text chunk sends to recover per chunk, preserve later chunks, and surface incomplete delivery instead of silently losing the tail.

## Best Possible Solution

Define Telegram-owned recoverable chunk-send failures and implement bounded per-chunk recovery plus incomplete-delivery visibility across the durable and streaming send funnels while leaving fatal routing/auth/topic errors loud.

## Reproduction Assessment

Yes, from source. Current main has a focused test where chunk 2 rejects, sendMessageTelegram rejects, and only chunk 1 is reported delivered; I did not run a live Telegram Bot API repro.

## Solution Assessment

Unclear as requested. Continuing after every Telegram error is too broad; the best fix is a narrow recoverable-error policy with explicit incomplete-delivery visibility.
