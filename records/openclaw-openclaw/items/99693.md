## Label Justifications

- `P2`: This is a normal-priority Telegram delivery reliability bug limited to long chunked outbound replies.
- `impact:message-loss`: A rejected middle Telegram chunk can prevent the remaining chunks of an outbound reply from being delivered.

## Summary

Keep open: current main still has Telegram chunk loops where an unhandled per-chunk send rejection exits before later chunks are attempted. The report is valid, but the safest fix needs maintainer policy on which Telegram errors are recoverable instead of blindly continuing after every failure.

## What This Changes

The issue asks for Telegram chunked sends to handle per-chunk failures so one rejected chunk does not silently drop the remaining reply tail.

## Best Possible Solution

Add Telegram-owned per-chunk recovery for classified recoverable validation/send failures, including plain-text retry or explicit incomplete-delivery signaling, while preserving loud fatal failures and parity between durable and streaming funnels.

## Reproduction Assessment

Yes from source: current main's durable text loop and streaming helper await each chunk without a per-chunk recovery boundary, while the rich loop throws non-classified errors from inside the loop. I did not run a live Telegram Bot API repro in this read-only review.

## Solution Assessment

Unclear as proposed: continuing after every Telegram error is not the best fix because it can mask fatal topic, auth, routing, or transport failures. The maintainable solution is a narrow recoverable-error policy inside the Telegram send funnel.
