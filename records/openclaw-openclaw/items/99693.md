## Label Justifications

- `P2`: This is a normal-priority Telegram delivery reliability bug limited to long chunked outbound replies.
- `impact:message-loss`: A rejected middle Telegram chunk can prevent the remaining chunks of an outbound reply from being delivered.

## Summary

Keep open: current main still aborts Telegram chunk delivery after unclassified per-chunk send errors. Existing code now handles some HTML/rich validation fallback paths, but the requested recoverable-error contract still needs a maintainer decision before changing partial-delivery semantics.

## What This Changes

Reported Telegram chunked outbound sends abort remaining chunks when a middle chunk send rejects, causing silent tail loss in long replies.

## Best Possible Solution

Add Telegram-owned per-chunk recovery only for classified recoverable validation/formatting failures, retry plain text where safe, keep fatal routing/auth/topic errors loud, and surface partial delivery clearly.

## Reproduction Assessment

Yes, source-level: the durable text loop directly awaits each chunk, the rich loop rethrows unclassified errors, and the shared streaming helper awaits sendChunk without a per-chunk recovery path. I did not run a live Telegram API repro in this read-only review.

## Solution Assessment

No, not as a blanket catch-and-continue. The best fix is a classified recoverable-error policy shared by the durable and streaming Telegram send funnels, with fatal errors still propagated.
