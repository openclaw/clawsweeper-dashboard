## Label Justifications

- `P2`: This is a bounded Telegram delivery reliability bug affecting long chunked replies, not a core outage or security issue.
- `impact:message-loss`: A failed middle Telegram chunk can prevent later outbound reply chunks from being delivered to the user.

## Summary

Keep open: current main still lacks a general per-chunk recovery contract for Telegram outbound chunks, and the latest release has the same aborting loop shape. The report is actionable, but the fix should wait for a maintainer decision on which Telegram chunk failures are recoverable versus fatal.

## What This Changes

The issue asks for Telegram chunk send loops to log or recover individual chunk failures so later chunks are not silently dropped.

## Best Possible Solution

Add a Telegram-owned recoverable chunk-failure policy shared by durable send and streaming reply paths: retry known parse/rich validation failures as plain text, log/count dropped chunks, surface incomplete delivery when needed, and keep fatal routing/auth/topic errors loud.

## Reproduction Assessment

Yes from source: current main has chunk loops that still exit on unhandled per-chunk send failures, and a focused mocked send test could reproduce the tail loss. I did not run a live Telegram Bot API repro in this read-only review.

## Solution Assessment

No for the broad proposed catch-and-continue shape; it would risk hiding fatal Telegram failures. The best fix is a classified recoverable-error policy in the Telegram send funnel with parity across durable and streaming delivery.
