- `impact:security`: The request is meant to reduce scheduled cron output falling back to unintended chat targets and exposing sensitive content.
- `impact:message-loss`: Without a stable default target, cron output can route to the wrong destination or fail when the implicit `last` route is stale or unsuitable.

## Summary

Keep open. Current main and the latest release still do not expose `cron.defaults.delivery` or an equivalent configurable primary cron delivery target; the related open PRs only change hard-coded fallback behavior, not the requested global channel/target default.

## What This Changes

Request adding a `cron.defaults.delivery` config option that supplies default cron announce delivery settings when a job omits explicit delivery.

## Best Possible Solution

Keep this focused tracker open and implement a maintainer-approved cron delivery default across config types/schema, service normalization, CLI/UI, docs, and regression tests, with explicit per-job delivery precedence and safe recipient validation.

- **Design `cron.defaults.delivery` (recommended):** Add the requested default with strict schema, explicit per-job precedence, recipient/account/thread validation, CLI/UI visibility, docs, and regression tests.

- **Fold into broader output routing:** Make this a subdecision of the broader cron output-target contract tracked at https://github.com/openclaw/openclaw/issues/49078 before implementing any default recipient field.
