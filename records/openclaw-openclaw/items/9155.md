## Summary

Keep open. Current main and latest release v2026.6.11 still lack `cron.defaults.delivery` or an equivalent configurable primary cron delivery target default; the related open PRs only change hard-coded fallback behavior and do not satisfy the requested config surface.

## What This Changes

Add a `cron.defaults.delivery` config option so cron jobs can inherit a default delivery mode, channel, and target unless a job overrides it.

## Best Possible Solution

Keep this focused tracker open and implement a maintainer-approved cron delivery default across config types/schema, gateway/service normalization, CLI/UI, docs, and regression tests with explicit per-job delivery taking precedence.
