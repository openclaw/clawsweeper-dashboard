## Summary

Keep open. Current main still lacks `cron.defaults.delivery` or an equivalent primary cron delivery recipient default; the issue remains the focused tracker for a useful but privacy-sensitive config/product decision.

## What This Changes

The issue requests a global `cron.defaults.delivery` config object that supplies a default cron announce channel and target when individual jobs omit delivery routing.

## Best Possible Solution

Keep this as the focused tracker and define a maintainer-approved `cron.defaults.delivery` contract that keeps per-job delivery highest priority, separates failure-notification defaults, validates recipient/account/thread data, and updates schema, docs, CLI/UI surfaces, and regression tests together.
