## Summary

Keep open: current main and v2026.6.11 still lack `cron.defaults.delivery` or an equivalent primary cron delivery target default, and the related open PRs address hard-coded fallback/no-channel behavior rather than this configurable channel/target policy.

## What This Changes

The issue requests a `cron.defaults.delivery` config path that applies a default cron delivery mode, channel, recipient, and related target fields when individual jobs omit delivery.

## Best Possible Solution

Keep this issue as the focused product tracker, then implement a maintainer-approved `cron.defaults.delivery` across config schema, runtime/service precedence, CLI/UI, docs, and regression tests.

Not applicable as a failing-bug reproduction; this is a feature/config request. The source-level gap is high confidence because current main and v2026.6.11 expose no `cron.defaults.delivery` path and still use explicit delivery or implicit announce/last behavior.
