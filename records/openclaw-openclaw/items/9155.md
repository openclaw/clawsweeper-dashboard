## Summary

Keep open. Current main and v2026.6.11 still lack `cron.defaults.delivery` or an equivalent primary cron delivery target default; this remains a focused product/security decision rather than cleanup-close material.

## What This Changes

The issue requests a new `cron.defaults.delivery` configuration path for a global default cron delivery mode, channel, and target when job-level delivery is omitted.

## Best Possible Solution

Keep this as the focused tracker and define a maintainer-approved `cron.defaults.delivery` contract that keeps explicit per-job delivery first, separates failure-notification defaults, validates recipients, and updates config schema, docs, CLI/UI surfaces, and regression tests together.
