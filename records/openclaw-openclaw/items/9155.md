## Summary

Keep open. Current main and the latest release still lack `cron.defaults.delivery` or an equivalent configurable primary cron delivery default; related PRs address announce/none/no-channel behavior, not this security-sensitive config surface.

## What This Changes

Request adding `cron.defaults.delivery` so cron jobs can inherit a default delivery mode, channel, and target before falling back to current `last` behavior.

## Best Possible Solution

Keep this as the focused product/security tracker for configurable primary cron delivery defaults, then implement one canonical config surface with explicit precedence, schema/docs/CLI/UI support, and regression tests after maintainer policy review.

## Reproduction Assessment

Yes. Source inspection verifies the missing capability: current main and v2026.6.11 have no `cron.defaults.delivery` type/schema entry, and delivery creation/planning only use per-job delivery or built-in announce/last fallback behavior.

## Solution Assessment

Unclear until maintainers confirm the product policy. If accepted, the best solution is a canonical config/default implementation with job-level precedence, docs, CLI/UI support, and tests rather than a hard-coded default change in one caller.
