## Summary

Keep open. Current main and the latest release still lack a primary cron delivery default; the only global cron delivery-like config is failure-notification-specific, and the requested global recipient default needs maintainer product/security policy before implementation.

## What This Changes

The issue requests a new `cron.defaults.delivery` config option so cron jobs can inherit a default delivery mode, channel, target, account, or thread when per-job delivery is omitted.

## Best Possible Solution

Keep this focused tracker open and implement a maintainer-approved cron delivery default across config types/schema, service and runtime normalization, CLI/UI/docs, and regression tests, with explicit per-job delivery taking precedence and failure-notification defaults kept separate.
