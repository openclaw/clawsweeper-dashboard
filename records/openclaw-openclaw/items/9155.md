## Summary

## What This Changes

The issue requests a new `cron.defaults.delivery` configuration path so cron announce delivery can use a stable default channel and recipient when a job omits explicit delivery routing.

## Best Possible Solution

Keep this as the canonical delivery-default issue; maintainers should choose a security-reviewed cron delivery default policy, then implement it across config types/schema, cron creation and runtime resolution, CLI/Control UI/docs, and precedence tests for job-level delivery before any global default.
