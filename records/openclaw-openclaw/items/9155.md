## Summary

Keep open. Current main and v2026.6.11 still lack `cron.defaults.delivery` or an equivalent primary cron delivery target default, and the open related PRs only change hard-coded fallback policy rather than adding the requested configurable channel/target default.

## What This Changes

Add a `cron.defaults.delivery` config option so cron jobs can inherit a default delivery mode, channel, and target when per-job delivery is omitted.

## Best Possible Solution

Keep this focused tracker open and implement a maintainer-approved `cron.defaults.delivery` path across config types/schema, cron create/normalize/plan behavior, CLI/UI/docs, and precedence tests with explicit per-job delivery winning first.
