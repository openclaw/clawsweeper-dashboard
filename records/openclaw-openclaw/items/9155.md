## Summary

Keep open. Current main and v2026.6.11 still lack `cron.defaults.delivery` or an equivalent configurable primary cron delivery target default, and the related open PRs only change hard-coded cron delivery fallback behavior.

## What This Changes

Request adds `cron.defaults.delivery` so cron jobs can inherit a configured default delivery mode, channel, and target instead of repeating per-job delivery fields or falling back to `last`.

## Best Possible Solution

Keep this focused tracker open and implement a maintainer-approved cron delivery default across config types/schema, service normalization, CLI/UI, docs, and regression tests, with explicit per-job delivery taking precedence.
