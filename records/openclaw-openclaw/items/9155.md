## Summary

Keep open. Current main and the latest shipped release still lack a primary cron delivery-target default, and this remains the focused tracker for a product and recipient-security decision rather than conservative cleanup.

## What This Changes

Add a global cron delivery default whose channel and target apply when a job omits delivery settings, while preserving explicit per-job precedence.

## Best Possible Solution

If approved, add a narrowly scoped, validated cron delivery policy with explicit per-job values first, a configured default second, and a deliberately chosen safe fallback last, covering CLI, Control UI, docs, schema/help generation, and recipient-safety tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw permit isolated cron jobs to inherit a global unattended-message recipient, and exactly which job types and creation surfaces should use that default?

Rationale: The code shape is bounded, but recipient inheritance changes the privacy boundary for scheduled outbound messages and conflicts with an open proposal to make omitted delivery silent.

Likely owner: steipete

Owner reason: This person has the strongest recent merged ownership across cron delivery defaults, config, persistence, editing, and documentation.

Owner confidence: high

Options:

- **Add scoped delivery default (recommended):** Support a validated default only for eligible isolated jobs that omit delivery, with explicit job settings always winning and recipient-safety tests.
- **Require explicit recipients:** Reject global recipient inheritance and improve CLI and Control UI affordances for selecting or copying a destination per job.
- **Unify with output routing:** Defer the narrow setting and resolve it as part of the broader deterministic output-routing design tracked at https://github.com/openclaw/openclaw/issues/49078.

## Reproduction Assessment

Not applicable as a new configuration capability rather than a broken established contract. Current-main source nevertheless confirms with high confidence that no equivalent global primary delivery default exists.

## Solution Assessment

Unclear pending maintainer policy. The proposed precedence is maintainable, but the safest permanent design must define eligible job types, agent/account scope, validation, and how an omitted delivery interacts with silent-mode proposals.
