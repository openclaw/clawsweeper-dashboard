## Summary

Keep open. Current main and v2026.6.11 still do not expose `cron.defaults.delivery` or an equivalent primary cron delivery target default; the related open PRs only adjust hard-coded cron delivery fallback behavior and do not add the requested configurable channel/target default.

## What This Changes

Add a `cron.defaults.delivery` config path so cron jobs can inherit a default delivery mode, channel, and target when per-job delivery is omitted.

## Best Possible Solution

Keep this focused tracker open and implement a maintainer-approved cron delivery default across config types/schema, service normalization, CLI/UI, docs, and regression tests with explicit per-job delivery taking precedence.
