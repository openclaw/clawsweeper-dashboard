- `impact:security`: The request is meant to reduce scheduled cron output falling back to unintended chat targets and exposing sensitive content.

## Summary

Keep open. Current main and v2026.6.11 still lack `cron.defaults.delivery` or an equivalent primary cron delivery target default, and the request remains a focused product/security decision rather than cleanup-close material.

## What This Changes

Add a `cron.defaults.delivery` config path that supplies a default primary delivery mode, channel, and target for cron jobs when per-job delivery is omitted.

## Best Possible Solution

Keep this as the focused tracker and define a maintainer-approved `cron.defaults.delivery` contract that keeps explicit per-job delivery first, separates failure-notification defaults, validates recipients, and updates config schema, CLI/UI surfaces, docs, and regression tests together.
