## Summary

Keep open. Current main and the latest release still lack `cron.defaults.delivery` or an equivalent primary cron delivery target default, and the requested fix is a privacy-sensitive config/default-routing product decision rather than cleanup-close material.

## What This Changes

Add `cron.defaults.delivery` so cron jobs can inherit a configured default delivery mode, channel, and target when job-level delivery is omitted.

## Best Possible Solution

Keep this as the focused tracker and define a maintainer-approved `cron.defaults.delivery` contract with explicit per-job precedence, strict recipient validation, account/thread handling, separation from `cron.failureDestination`, docs, CLI/UI support, and regression tests.
