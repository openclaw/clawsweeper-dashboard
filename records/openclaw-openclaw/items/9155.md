## Summary

Current main and the latest release still lack a configured primary recipient for cron announcements, and adjacent open PRs change delivery mode or session-target handling rather than solving this request. Keep this focused tracker open for a maintainer product and recipient-security decision.

## What This Changes

Add a global cron delivery default that supplies the channel and recipient when a job does not define its own delivery target.

## Best Possible Solution

Define one cron-scoped, account-aware delivery default with explicit job overrides, strict validation, clear omitted-mode behavior, and regression coverage proving that failure notifications and CLI-only defaults remain separate.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should unattended cron jobs inherit a configured announcement recipient, and how should that interact with omitted delivery mode and multi-account channel configuration?

Rationale: This changes a security-sensitive default for autonomous message delivery and introduces new core configuration, so code inspection cannot determine the intended recipient and fail-safe policy.

Likely owner: steipete

Owner reason: The current initial-delivery policy and most subsequent cron config evolution trace to this contributor, who also supplied prior product-triage context on the issue.

Owner confidence: high

Options:

- **Add cron-scoped defaults (recommended):** Add cron.defaults.delivery with job-level precedence, explicit account selection, validation, and a documented rule for omitted mode.
- **Extend channel defaultTo:** Make the existing account delivery target apply to cron as well, accepting a broader cross-surface configuration contract.
- **Require per-job targets:** Keep cron delivery fail-closed or silent unless each announcing job explicitly names its recipient.

## Reproduction Assessment

Yes, at source level: current main has no primary cron recipient-default field and the create-time resolver stores only announce mode when delivery is omitted. No live message was sent because the configuration gap is directly established by the strict schema, resolver, tests, and docs.

## Solution Assessment

Unclear pending product direction. A cron-scoped default is narrower than broadening channel defaultTo, but maintainers must first choose whether omitted jobs announce, remain silent, or require explicit delivery and how multi-account targets are selected.
