## Summary

Keep open. Current main and v2026.6.11 still lack `cron.defaults.delivery` or an equivalent primary cron delivery target default, and the related open PRs only change hard-coded delivery fallback behavior rather than adding a configurable channel/target default.

## What This Changes

Request adding a `cron.defaults.delivery` configuration default so cron jobs can inherit a default delivery mode, channel, and target instead of repeating per-job delivery fields or falling back to the current last-target behavior.

## Best Possible Solution

Keep this focused tracker open and implement a maintainer-approved cron delivery default across config types/schema, service normalization, CLI and Control UI creation flows, docs, and regression tests with explicit per-job delivery taking precedence.
