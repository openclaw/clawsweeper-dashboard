## Summary

Keep open. Current main and v2026.6.11 still lack `cron.defaults.delivery` or an equivalent configurable primary cron delivery target default; related open PRs only change hard-coded delivery fallback behavior, not this config surface.

## What This Changes

The issue requests a `cron.defaults.delivery` config default so cron announce jobs can inherit a channel and target without repeating per-job delivery settings.

## Best Possible Solution

Keep this focused tracker open and implement a maintainer-approved primary cron delivery default across config types/schema, cron creation and delivery resolution, CLI/UI/docs, and precedence tests where explicit per-job delivery wins.
