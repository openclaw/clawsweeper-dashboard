## Label Justifications

- `P2`: This is a normal-priority cron configuration feature with concrete privacy and routing impact but no current core outage by itself.
- `impact:security`: The request is meant to reduce scheduled cron output falling back to unintended chat targets and exposing sensitive content.

## Summary

Keep open. Current main and v2026.6.11 still lack a config-level primary cron delivery default; `cron.failureDestination` is only for failure notifications, and the related open PRs change hard-coded fallback behavior rather than adding the requested configurable channel/target default.

## What This Changes

Add a `cron.defaults.delivery` config option to set a default cron delivery mode, channel, and target when cron jobs omit explicit delivery.

## Best Possible Solution

Keep this focused tracker open and implement a maintainer-approved cron delivery default across config types/schema, service and runtime normalization, CLI/UI/docs, and regression tests with explicit per-job delivery taking precedence.
