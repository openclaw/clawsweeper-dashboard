## Summary

Keep this issue open: current `main` still exposes raw-transcript pagination semantics and no public conversation-visible projection, while the nearby Control UI pagination report addresses fetching older rows rather than making `limit` count readable conversation messages. ([github.com](https://github.com/openclaw/openclaw/blob/main/src/gateway/server-methods/chat.ts))

## What This Changes

Add an opt-in `chat.history` projection whose limit counts display-visible user and assistant messages instead of raw transcript records.

## Best Possible Solution

Add an additive typed projection such as `projection: "conversation"` that preserves today's default, applies after canonical display projection, scans until it collects the requested visible tail, retains raw-sequence pagination cursors, and treats text-only content stripping and full visible totals as separate explicit choices.

## Reproduction Assessment

Yes at source level: construct a transcript page dominated by tool records and request a small `chat.history` limit; current pagination counts transcript records and exposes no visible-conversation projection. A live deployment reproduction was reported, but this review did not rerun it.

## Solution Assessment

Not yet: server-side projection is the correct ownership boundary, but the proposed boolean bundles filtering, limit counting, content stripping, totals, and pagination decisions that should be separated into a stable additive protocol contract.
