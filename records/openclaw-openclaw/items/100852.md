## Summary

Keep open: this is a useful fix attempt for the runaway heartbeat-spend bug, but the patch is not merge-ready because the new idle gate can suppress existing event-backed and due-work heartbeat deliveries, and the hardcoded default policy still needs maintainer approval.

## What This Changes

The PR adds a hardcoded 7-day idle gate and per-agent consecutive-idle skip counter to `runHeartbeatOnce`, plus heartbeat idle-gate unit tests and test seeding fields.

## Best Possible Solution

Narrow the safety guard to plain scheduled heartbeat polling with no pending events, due tasks, or due commitments, then have a maintainer explicitly approve the default idle policy and its relationship to the broader configurable idle-timeout tracker.
