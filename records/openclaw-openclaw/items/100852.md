## Label Justifications

- `merge-risk: 🚨 compatibility`: The hard-coded idle skip changes existing heartbeat execution semantics for upgraded users with no opt-in or migration boundary.
- `merge-risk: 🚨 message-delivery`: The unconditional skip can prevent due commitments and system-event heartbeat notifications from being delivered for idle sessions.

## Summary

Keep open: the heartbeat spend-safety guard is still useful, but this patch is not merge-ready because the new idle gate applies to non-interval heartbeat paths and can suppress due commitments or system-event wakes before they are delivered.

## What This Changes

The PR adds a hard-coded seven-day heartbeat idle skip plus per-agent consecutive idle-skip backoff in `runHeartbeatOnce`, with test fixture updates and new idle-gate tests.

## Best Possible Solution

Keep the spend guard idea, but scope it to ordinary scheduled interval heartbeats, exempt event/cron/hook/manual and commitment-only runs, and have a maintainer accept the seven-day default versus the configurable policy in https://github.com/openclaw/openclaw/issues/14051.
