## Summary

Keep open: the useful idle-spend guard is still blocked by the same P1 issue from the prior review. The new gate runs before event and commitment prompt resolution, so an idle session can skip due commitments and event-backed wake work that current code intentionally keeps active.

## What This Changes

This PR adds a seven-day idle skip and per-agent consecutive idle backoff to `runHeartbeatOnce`, plus heartbeat test fixture fields and a new idle-gate test file.

## Best Possible Solution

Keep the spend guard idea, but scope it to ordinary scheduled interval heartbeats, preserve event/manual/commitment wakes, and have maintainers decide whether the fixed seven-day default is acceptable before merge.
