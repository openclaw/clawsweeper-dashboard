## Label Justifications

- `P2`: Sidebar mutation failures are a reproducible existing-workflow bug with meaningful but limited Control UI blast radius.
- `impact:ux-friction`: Users receive no actionable feedback when destructive or organizational sidebar actions fail and may repeatedly retry them.

## Summary

This is a valid current-main Control UI bug: sidebar session mutations catch capability failures without rendering the capability error, so failed destructive and organizational actions can appear successful. The protected `maintainer` label prevents automated cleanup, and the adjacent collapsed-state corruption remains separately tracked.

## What This Changes

Surface actionable failures for sidebar session mutations, including errors returned by batch deletion.

## Best Possible Solution

Give the sidebar its own visible, dismissible mutation-error state, propagate both rejected promises and non-empty batch result errors into it, and keep group collapsed-state cleanup strictly on successful mutations.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source-reproduction confidence: mount `openclaw-app-sidebar`, select two sessions, return `{ deleted: [], errors: ["delete failed"] }` from `sessions.deleteMany`, and verify the error is absent. The issue also identifies equivalent rejection paths for single-session mutations.

## Solution Assessment

Yes. Rendering one sidebar-owned mutation error and routing all sidebar mutation outcomes through it is narrower and more maintainable than relying on the dedicated Sessions page to display errors for actions initiated elsewhere.
