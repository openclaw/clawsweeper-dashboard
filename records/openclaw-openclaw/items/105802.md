## Summary

Keep this PR open: the SQLite ownership direction matches the repository’s database-first contract, but the current head can migrate a legacy unscoped allowlist into routing-only account `*`, stranding previously approved senders after upgrade. ## What This Changes

Moves channel pairing requests and approved-sender allowlists from credential-directory JSON files into the shared SQLite state database, adding startup and doctor migration for legacy files.

## Best Possible Solution

Keep SQLite as the single runtime owner, ignore wildcard or empty binding account IDs when resolving migration targets, add a regression covering a channel-wide `accountId: "*"` binding, and provide redacted live fresh-install plus legacy-upgrade proof before owner approval.
