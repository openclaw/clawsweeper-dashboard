## Summary

The PR addresses the linked bug, but its null guard also fires when no normalized channel exists, changing the existing generic fallback outside the explicit plugin-rejection case; real behavior evidence is test-only.

## What This Changes

The PR makes inbound claim hook mapping omit `conversationId` when a channel plugin’s inbound conversation resolver returns `null`, and adds focused regression coverage.

## Best Possible Solution

Distinguish “no channel or resolver result” from an explicit plugin `null` decision—preferably through the canonical conversation-resolution helper, or minimally by using `undefined` for the no-channel branch—and cover explicit `null`, absent resolver, and absent channel cases.
