## Summary

Keep open: current main and v2026.6.11 still drop explicit Feishu `replyTo` on ordinary message-tool `send` before text/card/media sends reach the lower Feishu reply helpers. The overlapping Feishu anchor PR is still open, so it is a candidate repair path rather than proof that this issue is fixed.

## What This Changes

Issue reports intermittent missing Feishu quoted-reply display when the agent uses the message tool `replyTo` parameter after upgrading to OpenClaw 2026.3.23-2.

## Best Possible Solution

Fix the Feishu plugin action layer so ordinary `send` maps explicit `replyTo`/`reply_to` targets through text, card, and media sends while preserving the distinct `thread-reply` and topic auto-thread behavior.

## Reproduction Assessment

Yes, at source level: current main's Feishu ordinary `send` action ignores explicit `replyTo`, while lower Feishu helpers can send an API reply when given `replyToMessageId`. I did not run a live Feishu WebSocket reproduction in this read-only review.

## Solution Assessment

Yes for keeping it open: the narrow repair belongs in the Feishu plugin action layer, with tests for text, card, and media send paths. The existing open PR may be the landing path only after its remaining review/author state is resolved.
