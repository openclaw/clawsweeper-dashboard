## Summary

Keep open: current main and the latest release still ignore explicit Feishu `replyTo` on ordinary message-tool `send`, and the overlapping Feishu anchor PR is still open and conflicting rather than a landed fix.

## What This Changes

The issue reports intermittent missing Feishu quoted-reply rendering when an agent uses the message tool's `replyTo` parameter after upgrading to OpenClaw 2026.3.23-2.

## Best Possible Solution

Repair the Feishu plugin action layer so ordinary `send` maps explicit `replyTo` through text, card, and media sends while preserving topic-thread, normal-group, and P2P routing invariants.

## Reproduction Assessment

Yes, at source level: current main exposes message-tool `replyTo`, but the Feishu ordinary `send` action ignores that explicit target before invoking text/card/media sends. I did not run a credentialed live Feishu tenant reproduction.

## Solution Assessment

Yes for keeping this open, but not as a new independent automation branch yet. The narrow fix belongs in the Feishu plugin action mapping and should be coordinated with the open Feishu anchor PR or a credited replacement.
