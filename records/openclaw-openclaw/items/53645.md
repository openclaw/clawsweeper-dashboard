## Summary

Keep open: current main and the latest release still drop explicit Feishu `replyTo` on the ordinary message-tool `send` action before the lower Feishu sender sees it. The open Feishu anchor PR overlaps the issue, but it is still open, conflicting, and waiting on author repair, so it is not a landed fix or safe duplicate target.

## What This Changes

The issue requests stable Feishu quoted replies when the message tool uses `replyTo`, after intermittent failures on OpenClaw 2026.3.23-2.

## Best Possible Solution

Fix the Feishu plugin action layer so ordinary `send` maps explicit `replyTo`/`reply_to` into text, card, and media delivery while preserving `thread-reply`, topic-thread, normal-group, and P2P routing invariants.

## Reproduction Assessment

Yes, at source level: the message tool accepts `replyTo`, but current Feishu ordinary `send` ignores that explicit target before invoking text/card/media sends. I did not run a credentialed live Feishu tenant reproduction.

## Solution Assessment

Yes for keeping this open: the narrow maintainable fix belongs in the Feishu plugin action mapping because the lower outbound adapter already knows how to carry reply targets. The landing path should be coordinated with the open Feishu anchor PR or a credited replacement.
