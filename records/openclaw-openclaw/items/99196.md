## Summary

Keep open: the latest head fixes the earlier full-discovery leak, but the new config-only helper still bypasses the existing bundled-load-path alias guard, making the installed-index path inconsistent with normal discovery for known redundant bundled `plugins.load.paths` entries.

## What This Changes

The PR adds config-only `plugins.load.paths` discovery to installed-index manifest registry reconstruction and tests mixed index/load-path and scoped lookup behavior.

## Best Possible Solution

Share or factor the existing configured load-path scan so the installed-index fallback adds missing workspace plugins while preserving bundled-path alias filtering and scoped candidate behavior.

## Reproduction Assessment

Yes, at source level: current main passes only persisted-index candidates into `loadPluginManifestRegistry`, and that callee skips normal load-path discovery when candidates are supplied. I did not run the live managed npm install plus gateway restart path in this read-only review.

## Solution Assessment

No: the owner boundary is right and the previous full-discovery issue is fixed, but the new helper is still too narrow because it bypasses normal discovery's bundled-load-path alias filtering. The safer fix is to factor the configured-path scanner with that guard included.
