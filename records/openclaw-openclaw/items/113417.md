## Summary

This PR addresses a real outbound-routing bug and includes credible exact-head live Slack evidence that an invalid explicit account no longer triggers a fallback mutation. The remaining blocker is a maintainer-owned compatibility decision: upgraded callers that supplied an invalid account will now receive an error instead of silently using another configured account; the protected `maintainer` label means this should stay open for explicit human review rather than cleanup closure.

## What This Changes

The branch centralizes validation of caller-supplied channel account IDs across CLI, agent tools, Gateway actions, broadcasts, and Feishu tools so malformed, disabled, unknown, conflicting, or mismatched explicit accounts fail instead of borrowing a fallback account.

## System Context

OpenClaw’s outbound-message paths accept requests from the CLI, agent tools, and Gateway, resolve a channel and account, scope any required secrets, and dispatch through channel plugins. This PR changes the explicit-account boundary before delivery, including broadcast planning and Gateway idempotency keys.
