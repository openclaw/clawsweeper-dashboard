## Summary

Keep this PR open for maintainer review. The patch has no concrete correctness finding in the supplied review evidence and includes strong live Slack and Feishu validation, but it deliberately changes upgraded callers from fallback delivery to a visible error when they explicitly provide an invalid or disabled account; the protected `maintainer` label requires an explicit product-contract decision before merge.

## What This Changes

This PR validates explicitly supplied channel account IDs across CLI, agent message tools, Feishu tools, and Gateway send paths so invalid, disabled, unknown, conflicting, or channel-mismatched selections fail instead of falling back to another configured account, while retry idempotency remains bound to the first validated route.

## System Context

Outbound messages enter through the CLI, agent tool, conversation delivery, or Gateway APIs and are resolved to a channel account before secrets and provider operations are accessed. The validated route then controls message delivery and Gateway idempotency so retries cannot switch to a different account after defaults or plugin configuration change.
