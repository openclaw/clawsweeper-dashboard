## Summary

Keep open: current main and the latest release still lack a TUI plain-text accessibility mode, the linked implementation PR is closed unmerged, and adjacent accessibility issues cover different UI/workflow problems rather than this terminal glyph-output request.

## What This Changes

The issue requests a config-backed plain-text TUI mode that replaces emoji and Unicode glyphs with ASCII output for screen-reader users.

## Best Possible Solution

Land a maintainer-approved core TUI plain-text mode that updates config types/schema/help/docs, threads the setting through TUI rendering and pi-tui wrapper seams, and provides ASCII alternatives with focused config and TUI rendering proof.

## Reproduction Assessment

Yes. Source-level reproduction is high confidence: current main and v2026.6.11 have no accepted plain-text TUI config key, strict schemas reject unknown UI/TUI keys, and TUI/tool-display paths still render emoji and Unicode glyphs unconditionally.

## Solution Assessment

Unclear until maintainers choose the public config contract. A core TUI setting is the right boundary, but a tool-display-only patch would be too narrow because selectors, settings, separators, status/waiting text, and dependency-backed controls also need coverage.
