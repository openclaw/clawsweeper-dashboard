Keep open: the reported screen-reader friction remains a distinct TUI accessibility request, while the only directly related implementation attempt was closed unmerged. ## What This Changes

Add an accessibility mode for the TUI that suppresses decorative emoji and Unicode symbols in favor of screen-reader-friendlier plain-text presentation.

## Best Possible Solution

Adopt one documented, default-off TUI accessibility presentation contract only after maintainers choose its activation surface and canonical ASCII output; thread that resolved preference from startup through OpenClaw-owned renderers, document any remaining pi-tui limitation, and cover both default and enabled rendering.
