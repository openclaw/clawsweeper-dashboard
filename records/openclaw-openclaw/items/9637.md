## Summary

Keep open: current main and v2026.6.11 still lack a plain-text TUI presentation mode, the directly linked implementation closed unmerged after deprioritization, and maintainers must choose the durable activation and dependency API contract.

## What This Changes

Add a TUI accessibility mode that replaces product-owned emoji and decorative Unicode symbols with screen-reader-friendly ASCII alternatives.

## Best Possible Solution

Add one terminal-specific accessibility presentation profile under `tui`, resolve it once at startup, map all product-owned decorative symbols to stable ASCII alternatives, use pi-tui loader-frame options, and add or upstream a narrow configurable selection-prefix seam while preserving user content.
