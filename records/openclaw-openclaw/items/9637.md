## What This Changes

The issue requests a TUI accessibility option to disable or replace emoji and Unicode glyphs for screen-reader and plain-text terminal users.

## Best Possible Solution

Land a maintainer-approved core TUI plain-text mode that updates config types/schema/help/docs, loads the flag once at TUI startup, threads it through rendering components, and covers tool summaries, selectors, settings, status/waiting text, and dependency-backed select-list seams.

## Reproduction Assessment

Yes. Source-level reproduction is high confidence: current main has no accepted plain-text accessibility config key, strict config schemas reject unknown UI/TUI keys, and TUI/tool-display paths still render emoji and Unicode glyphs unconditionally.

## Solution Assessment

Unclear until maintainers choose the public config contract. A core TUI setting is the right boundary, but the implementation should cover all visible TUI glyph surfaces rather than only tool-display emojis.
