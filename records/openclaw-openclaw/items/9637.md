## Summary

Current main’s strict `ui` schema still has no plain-text or accessibility mode, the prior implementation at https://github.com/openclaw/openclaw/pull/9685 closed unmerged, and two screen-reader users describe the remaining usability problem. The issue remains necessary, but maintainers must choose the durable activation contract and canonical ASCII presentation before implementation.

## What This Changes

Add a core TUI accessibility mode that replaces emoji and decorative Unicode output with screen-reader-friendly plain-text alternatives.

## Best Possible Solution

Implement one coherent core TUI presentation mode, activated through a maintainer-approved persistent preference or equivalent explicit control, loaded once at TUI startup and applied to every tool, status, selector, separator, spinner, and dependency-wrapper glyph with documented ASCII semantics and focused config/rendering tests.

Options:

- **Use an explicit runtime control:** Provide a TUI startup flag or in-product setting instead of permanent config, while preserving the same whole-surface ASCII contract.
- **Decline the mode:** Keep current presentation and document terminal or screen-reader workarounds, accepting that the reported TUI accessibility friction remains.

## Solution Assessment
