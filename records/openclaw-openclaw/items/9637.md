## Summary

Current main still emits decorative emoji and Unicode throughout the TUI with no accessible presentation mode, and the only exact implementation PR was closed unmerged after deprioritization. Keep this issue open for a maintainer product decision because the need is corroborated, but the public setting, default, scope, and ASCII vocabulary require ownership before implementation.

## What This Changes

Add a TUI accessibility mode that replaces decorative emoji and Unicode symbols with screen-reader-friendly text or ASCII alternatives.

## Best Possible Solution

Implement one typed accessible TUI presentation profile selected once at startup, covering tool summaries, statuses, loaders, selectors, separators, and pi-tui theme or wrapper seams; document stable ASCII alternatives and validate them with a real NVDA, VoiceOver, or Orca session.
