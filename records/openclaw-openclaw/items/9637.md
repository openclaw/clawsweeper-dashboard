## Summary

Keep open. This is a corroborated accessibility feature request for the terminal UI, and the directly related implementation attempt was closed unmerged. A maintainer must choose the durable configuration and plain-text presentation contract before a safe implementation can proceed.

## What This Changes

Add a terminal-UI accessibility option that replaces decorative emoji and Unicode symbols with screen-reader-friendly plain-text alternatives.

## System Context

OpenClaw’s terminal UI renders agent activity, tool summaries, selectors, and status information from configuration and runtime events. Those rendered strings then reach terminal users and screen readers, including symbols supplied by OpenClaw and by the pi-tui control layer.

## Architecture Diagram

flowchart LR
  Config[UI configuration] --> Startup[TUI startup]
  Startup --> Render[Chat, tools, and status rendering]
  Render --> Controls[Selector and theme controls]
  Controls --> Output[Terminal and screen-reader output]

## Best Possible Solution

Define one documented TUI accessibility contract, then implement it at TUI startup and thread it through OpenClaw-owned tool, status, chat, selector, and theme rendering with focused rendering and config-validation coverage; separately decide whether pi-tui needs an upstream capability or a supported local seam.
