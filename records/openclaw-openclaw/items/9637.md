## What This Changes

The issue requests a TUI accessibility configuration option that renders terminal UI output without emoji and Unicode glyphs for screen reader users.

## Best Possible Solution

Add a documented core TUI plain-text accessibility mode in the canonical config/schema/help/docs, load it once at TUI startup, thread it through TUI rendering, and replace tool emoji plus decorative Unicode with chosen ASCII alternatives under that mode.

## Reproduction Assessment

Yes. Source inspection is enough to reproduce the missing capability: current main rejects the proposed config shape and the relevant TUI/tool-display paths still hard-code emoji and Unicode glyphs.

## Solution Assessment

Unclear until maintainers choose the config key, default, and ASCII replacement policy. A core TUI config mode looks like the right owner boundary; existing channel responsePrefix support is not an equivalent solution for terminal rendering.
