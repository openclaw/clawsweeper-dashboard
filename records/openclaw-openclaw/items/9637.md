## Summary

Keep open: current main still has no supported plain-text/accessibility presentation mode for the terminal UI, and the only directly related implementation attempt was closed unmerged. The screen-reader impact is corroborated by a second user, but maintainers need to select the durable TUI activation and replacement-vocabulary contract before implementation.

## What This Changes

The issue requests a configurable terminal-UI accessibility mode that suppresses decorative emoji and Unicode symbols in favor of screen-reader-friendlier plain text.

## Best Possible Solution

Adopt one documented core TUI accessibility mode, preferably under the existing `tui` configuration namespace, with a defined ASCII vocabulary and centralized presentation helpers; cover all owned TUI render paths and use a supported pi-tui theme/wrapper seam for framework glyphs.
