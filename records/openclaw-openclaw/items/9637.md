## Summary

Keep open: current main and the latest release still lack a TUI plain-text accessibility mode, the prior implementation PR was closed unmerged, and related accessibility issues cover adjacent UI problems rather than replacing this request.

## What This Changes

Request a documented TUI accessibility/plain-text config mode that replaces emoji and Unicode glyphs with screen-reader-friendly ASCII output.

## Best Possible Solution

Add a core TUI accessibility/plain-text mode with documented config/schema/help labels, load it once at TUI startup, thread it through tool cards, selectors, waiting/status text, and dependency wrapper seams, then cover it with focused config and TUI rendering tests.

## Reproduction Assessment

Yes, source inspection provides a high-confidence reproduction path: the config schema has no plain-text key and TUI/tool-display renderers still emit emoji and Unicode glyphs unconditionally. I did not run a live screen-reader session.

## Solution Assessment

Yes, the maintainable solution belongs in core TUI/config rather than ClawHub because the affected glyphs are produced by core TUI and tool-display paths. The exact key name, default, and ASCII mapping need maintainer approval before implementation.
