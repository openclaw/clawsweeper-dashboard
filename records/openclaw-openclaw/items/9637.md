## Summary

Keep this issue open: current main still has no supported TUI plain-text/accessibility preference, while the TUI theme still emits a literal Unicode cursor. The earlier implementation attempt is closed unmerged, and a second screen-reader user corroborates the impact. Likely related people: steipete (high), vignesh07 (medium), and vincentkoc (medium).

## What This Changes

Add an opt-in terminal UI presentation mode that replaces decorative emoji and Unicode glyphs with deliberate ASCII or text alternatives for screen-reader users.

## System Context

OpenClaw loads user configuration when starting its terminal UI, then passes themes and formatted tool/chat content into TUI components and the pi-tui rendering library. Those rendered strings become the terminal output consumed by users and assistive technology.

## Architecture Diagram

flowchart LR
  A[OpenClaw configuration] --> B[TUI startup]
  B --> C[Tool and chat formatting]
  B --> D[Theme and selector rendering]
  C --> E[Terminal output]
  D --> E
  E --> F[Screen reader user]

## Best Possible Solution

Define one opt-in TUI text-presentation contract, apply it at TUI startup to every OpenClaw-owned decorative symbol, use supported pi-tui theming or an upstream change for dependency-owned selectors, and document plus test the resulting ASCII vocabulary.
