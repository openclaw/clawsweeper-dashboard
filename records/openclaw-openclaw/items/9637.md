## Summary

Keep open: current main and the latest release still lack a TUI plain-text accessibility mode, while TUI/tool rendering continues to emit emoji, arrows, box-drawing separators, and ellipses without a config-controlled ASCII branch. The issue is actionable core TUI/config work, but the public key, default, and replacement semantics need maintainer product direction.

## What This Changes

The issue requests a TUI accessibility option that replaces emoji and Unicode UI glyphs with screen-reader-friendlier plain-text or ASCII output.

## Best Possible Solution

Add an optional core TUI plain-text accessibility mode across config types, strict schema, generated labels/help, public TUI/config docs, TUI startup loading, tool display, selector/theme rendering, and focused rendering/config tests while preserving current rich glyph output by default unless maintainers choose otherwise.
