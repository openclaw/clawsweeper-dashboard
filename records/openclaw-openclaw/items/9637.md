## Summary

Keep open: current main and the latest stable release still lack a TUI plain-text accessibility mode, while the prior exact implementation PR is closed unmerged and the remaining work needs a maintainer choice on config shape and replacement semantics.

## What This Changes

The issue requests a TUI accessibility option that suppresses emoji and Unicode glyphs in favor of plain ASCII output for screen-reader users.

## Best Possible Solution

Add an opt-in core TUI plain-text accessibility mode across config types, strict schema, generated labels/help, public docs, TUI startup loading, tool cards, selectors/theme rendering, and focused rendering/config tests while preserving rich glyph output by default unless maintainers choose otherwise.
