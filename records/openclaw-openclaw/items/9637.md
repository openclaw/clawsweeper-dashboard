## Summary

Keep open: current main and the latest release still lack a TUI plain-text accessibility mode, the exact linked implementation PR is closed unmerged, and related accessibility issues cover different Control UI or session-navigation problems rather than this terminal glyph-output request.

## What This Changes

The issue requests a TUI accessibility configuration option that disables emoji and Unicode glyph output for screen-reader-friendly plain text rendering.

## Best Possible Solution

Add a core TUI plain-text accessibility mode across config types, zod validation, generated help/labels/schema, public docs, TUI startup config loading, tool display, selector/theme rendering, and focused schema plus TUI rendering tests, keeping rich glyph output as the default unless maintainers choose otherwise.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 lack the proposed config key and still render tool emoji, a box-drawing separator, and a Unicode selector cursor without a plain-text branch; no live screen-reader run was performed.

## Solution Assessment

Unclear until maintainers choose the public config shape and replacement semantics. A core TUI plain-text mode is a plausible owner-boundary fix, but it adds durable config behavior and should not be automated without product direction.
