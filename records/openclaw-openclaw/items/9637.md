Request to add a core TUI accessibility/plain-text config option that suppresses emoji and Unicode glyphs for screen-reader-friendly terminal output.

## Best Possible Solution

Land a maintainer-approved core TUI plain-text mode that updates config types/schema/help/docs, threads the setting through TUI startup and rendering components, covers selectors/status/settings/tool summaries, and adds focused config plus TUI rendering proof.

## Reproduction Assessment

Yes. Source-level reproduction is high confidence: current main has no accepted TUI plain-text config key, strict config schemas reject unknown UI/TUI keys, and TUI/tool-display paths still render emoji and Unicode glyphs unconditionally.

## Solution Assessment

Unclear until maintainers choose the public config contract. A core TUI mode is the right boundary, but a tool-display-only patch would be too narrow because selectors, settings, separators, status/waiting text, and dependency-backed controls also need coverage.
