## Summary

Current main still lacks a screen-reader-friendly TUI presentation mode, and the only direct implementation PR closed unmerged after deprioritization. The request remains valid core accessibility work, but maintainers must define the durable activation contract and full cross-dependency ASCII semantics before implementation.

## What This Changes

Add a TUI accessibility mode that replaces emoji and decorative Unicode symbols with screen-reader-friendly ASCII output.

## Best Possible Solution

Define one startup-resolved TUI presentation policy, add or upstream pi-tui seams where necessary so every decorative interface glyph has an ASCII equivalent, document the contract, and validate the complete experience using a real screen reader.
