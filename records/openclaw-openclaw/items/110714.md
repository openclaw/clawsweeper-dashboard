## Summary

Keep this PR open: it addresses a credible CLI memory-safety concern, but the pathname `statSync` followed by `readFile` does not actually guarantee a bounded read if the file is replaced or grows between those operations. The new unconditional 10 MiB rejection also changes behavior for existing large `oc-path` inputs and needs explicit compatibility acceptance plus real after-fix CLI proof.

## What This Changes

The PR adds a 10 MiB regular-file check before the `oc-path` CLI parses a file and before `path set` reads the prior file for diff output.

## Best Possible Solution

Use a descriptor-based, allocation-bounded reader that validates and reads the same opened file, add focused boundary/race-oriented coverage, and land the 10 MiB policy only after maintainers accept its compatibility impact.
