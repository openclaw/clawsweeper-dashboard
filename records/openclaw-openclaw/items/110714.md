## Summary

This is a focused, plausible OOM-prevention fix with current-head live CLI output showing both normal resolution and oversized-file rejection. The remaining merge question is compatibility: the new 16 MiB cap now applies to every oc-path input format and to `set --diff`, while the demonstrated pre-existing boundary is JSONC-specific.

## What This Changes

The PR replaces unbounded oc-path file reads in AST loading and `set --diff` with a descriptor-bound, chunked 16 MiB reader and updates the oversized-input diagnostic test.

## Best Possible Solution

Keep the descriptor-bound reader, but confirm that a universal 16 MiB cap is the intended oc-path contract; if not, preserve the JSONC diagnostic boundary while defining format-appropriate limits and coverage for each affected read path.
