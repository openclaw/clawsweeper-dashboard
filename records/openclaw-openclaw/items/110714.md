## Summary

This PR still needs a mechanical repair: its pathname `statSync` check can be bypassed if the file is replaced or grows before the later asynchronous `readFile`, so the claimed memory bound is not guaranteed. It also needs direct redacted CLI proof after the repair; the contributor’s supplied evidence is test/CI output only.

## What This Changes

The PR adds a 10 MiB regular-file check before `oc-path` parses a file and before `path set` reads prior content for a diff.

## Best Possible Solution

Use a single opened-file bounded-read primitive that limits bytes while reading, choose and document an intentional compatibility policy for files above the limit, add focused regression coverage, and attach a redacted live CLI transcript for oversized rejection plus a normal successful command.
