## Summary

Keep open: current main and the latest release still render URL-bearing tool output as escaped/plain text in the Control UI and native WebChat paths, and both linked implementation PRs are closed unmerged rather than canonical fixes.

## What This Changes

Request clickable http(s) URLs inside Control UI and native WebChat tool output cards instead of plain text.

## Best Possible Solution

Implement an escape-first http(s)-only URL renderer across all Control UI tool-output paths, then either add equivalent native WebChat Link/AttributedString rendering or explicitly split native scope.

## Reproduction Assessment

Yes, at source level: current main renders URL-bearing Control UI tool output through Lit text bindings and native WebChat through plain SwiftUI Text/String formatting. I did not run browser or app proof because this read-only review can prove the missing link renderer from source.

## Solution Assessment

Unclear until maintainers decide the native WebChat scope. The Control UI fix shape is clear, but the maintainable solution should preserve raw formatting, escape text first, and only emit safe http/https anchors.
