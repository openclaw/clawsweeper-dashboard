## Summary

This feature is still necessary: current main and the latest release continue to render URL-bearing tool results as plain text, while both linked implementation attempts were closed unmerged. The implementation is bounded, but maintainers should decide whether native WebChat parity belongs in the same acceptance scope.

## What This Changes

Render HTTP(S) URLs in Control UI and optionally native WebChat tool-output cards as safe clickable links.

## Best Possible Solution

Reuse or extract the existing maintained URL-parsing policy to produce escaped Lit nodes while preserving JSON and whitespace across every Control UI tool-result presentation, prove it with focused browser tests, and either add equivalent native `AttributedString` handling or track native parity separately according to the maintainer decision.
