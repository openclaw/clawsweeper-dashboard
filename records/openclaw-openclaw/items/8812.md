## Summary

Keep open: current main and the latest release still render URL-bearing tool output as plain text in Control UI and native WebChat, while both linked implementation PRs are closed unmerged prior art. The remaining blocker is a maintainer scope decision, not evidence that the request is obsolete.

## What This Changes

The issue requests clickable URL rendering for URL strings inside Control UI tool output cards and native WebChat tool result cards.

## Best Possible Solution

Implement an escape-first URL-aware renderer across Control UI tool-output paths, then either add equivalent native WebChat link rendering or explicitly split that scope.

## Reproduction Assessment

Yes, at source level: current main renders URL-bearing Control UI tool output through Lit text bindings and native WebChat through plain SwiftUI Text/String formatting. I did not run browser or app proof because this read-only review can prove the missing link renderer from source.

## Solution Assessment

Unclear as a product decision: the Control UI fix shape is clear, but maintainers should decide whether native WebChat remains in scope before another implementation. A safe solution should preserve raw formatting, escape text first, and reuse existing markdown/link-safety rules where practical.
