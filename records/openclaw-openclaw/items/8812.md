## Summary

Keep open: current main and latest release still render URL-bearing tool output as plain escaped text in Control UI and plain SwiftUI text in native WebChat; the two linked implementation PRs are closed unmerged prior art rather than shipped fixes.

## What This Changes

Request to render URL strings inside Control UI and native WebChat tool output as clickable links while preserving safe JSON/plain-text display.

## Best Possible Solution

Implement a safe URL-aware renderer for Control UI tool-output display paths, then either add equivalent native WebChat link rendering or explicitly split that scope into a follow-up.

## Reproduction Assessment

Yes. Source inspection shows URL-bearing tool output reaches Lit text bindings in Control UI and SwiftUI Text via plain strings in native WebChat, so it renders as text instead of clickable anchors/links in current main.

## Solution Assessment

Unclear as a product-scope decision. The Control UI fix shape is clear: use a shared safe renderer that escapes arbitrary tool text before creating http/https anchors and covers every tool-card display path; native WebChat should either get equivalent link rendering or be split explicitly.
