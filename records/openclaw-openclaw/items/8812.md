## Summary

Keep open: current main and the latest release still render URL-bearing tool output as plain text in Control UI and native WebChat, while both linked implementation PRs are closed unmerged prior art rather than shipped fixes.

## What This Changes

The issue requests clickable URL rendering inside Control UI and native WebChat tool-output cards.

## Best Possible Solution

Ship an escape-first http/https URL renderer across all Control UI tool-output surfaces, then either add equivalent native WebChat link rendering or explicitly split that scope into a follow-up.

## Reproduction Assessment

Yes, at source level: current main renders URL-bearing Control UI tool output through Lit text bindings and native WebChat through plain SwiftUI Text/String formatting. I did not run browser or app proof because this read-only review can prove the missing link renderer from source.

## Solution Assessment

Unclear as a product decision: the Control UI implementation boundary is clear, but maintainers should decide whether native WebChat remains in scope before queueing another fix. The implementation should reuse existing markdown/linkify/sanitization concepts where practical without routing raw tool output through unsafe HTML.
