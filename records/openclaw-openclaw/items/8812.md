## Summary

Keep open: current main and the latest release still render URL-bearing tool output as plain text in the Control UI tool-card paths and native WebChat, while the two linked implementation attempts are closed unmerged prior art.

## What This Changes

Request auto-linkifying URL strings in Control UI and possible native WebChat tool output cards so users can open them directly.

## Best Possible Solution

Define the scope, then implement safe URL-aware rendering across every selected tool-output surface with http/https-only links, escaping, punctuation handling, and focused UI/native tests.

## Reproduction Assessment

Yes, at source level. Current main renders URL-bearing Control UI tool output through Lit text bindings/pre code and native WebChat through plain SwiftUI Text, so the non-clickable behavior is clear without running a live UI.

## Solution Assessment

Unclear pending product scope. The Control UI fix shape is clear, but native WebChat should either get equivalent Link or AttributedString handling or be split into a separate scoped issue.
