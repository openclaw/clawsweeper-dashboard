- `P3`: This is a low-risk UI ergonomics feature with limited blast radius, not an urgent runtime regression.

## Summary

Keep open: current main and the latest release still render URL-bearing tool output as escaped/plain text in Control UI and native WebChat, while the two linked implementation PRs are closed unmerged and only useful as prior art.

## What This Changes

Request URL strings in Control UI and native WebChat tool-output cards render as clickable links instead of plain text.

## Best Possible Solution

Implement an escape-first URL-aware renderer across all Control UI tool-output paths, then either add equivalent native WebChat link rendering or explicitly split the native scope.

## Reproduction Assessment

Yes, at source level: current main renders URL-bearing Control UI tool output through Lit text bindings and native WebChat through plain SwiftUI Text/String formatting. I did not run browser or app proof because this read-only review can prove the missing link renderer from source.

## Solution Assessment

Unclear as a product decision: the Control UI fix shape is clear, but maintainers should decide whether native WebChat remains in scope before another implementation. A safe renderer should preserve raw formatting, escape text first, and only produce safe http/https anchors.
