## Label Justifications

- `P3`: Clickable tool-result URLs are a bounded quality-of-life feature with limited blast radius and no blocked core workflow.
- `impact:ux-friction`: Users currently need to copy and paste URL strings from tool results instead of opening them directly.

## Summary

This feature remains necessary: the latest supplied current-main review and v2026.6.11 evidence show URL-bearing tool results still render as plain text, and both linked implementation attempts closed unmerged. The Control UI work is bounded, but maintainers must decide whether native WebChat parity belongs in the same deliverable.

## What This Changes

Render HTTP(S) URLs in Control UI tool-output cards as safe clickable links, with native WebChat parity if included in scope.

## Best Possible Solution

Implement one escaped, HTTP(S)-only URL renderer across every Control UI tool-output variant with focused browser tests, then handle SwiftUI parity separately unless maintainers explicitly require both platforms together.
