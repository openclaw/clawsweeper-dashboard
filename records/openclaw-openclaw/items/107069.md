## Summary

Keep this issue open: current main still exposes a content-only `before_agent_run` event even though provenance exists elsewhere in the run pipeline, so plugins cannot enforce origin-aware pre-model policy. The report remains useful despite one cited producer path having gained provenance since the reporter’s earlier SHA.

## What This Changes

Expose authoritative input provenance to `before_agent_run` and ensure each run producer classifies and carries its trigger origin through the runner pipeline.

## Best Possible Solution

Define producer-owned provenance once when each run is created, carry that prepared fact unchanged through every runner, expose it as an additive optional hook field, and add table-driven producer coverage plus live dispatch-family proof without inferring origin from prompt text.
