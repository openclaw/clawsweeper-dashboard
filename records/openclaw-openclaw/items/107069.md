## Summary

Keep this issue open: current main still gives `before_agent_run` a content-only event, while authoritative provenance is missing from the hook contract and remains unstamped on multiple internal producer paths. The central defect is source-reproducible, but the permanent producer taxonomy and security semantics need owner approval before implementation. citeturn525758view0turn841081view0turn938174view0

## What This Changes

Expose authoritative input provenance to the `before_agent_run` plugin hook and stamp it consistently when external, inter-session, and internal runs originate.

## Best Possible Solution

Add an optional, host-authored `InputProvenance` field to the public hook event, stamp each run once at its producer boundary, preserve the existing fail-closed decision/error contract, and verify all producer families through focused tests plus live dispatch proof.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should `before_agent_run` expose host-authoritative `InputProvenance`, with explicit contractual classifications for every internal producer while retaining the gate's current fail-closed handler semantics?

Rationale: Plugins may use this value for pre-model authorization and cost controls, so producer classification, absence semantics, and handler-failure behavior form a security boundary that should not be inferred by an automated repair.

Likely owner: mbelinky

Owner reason: The existing provenance taxonomy and primary stamping pattern originate from their merged feature work.

Owner confidence: high

Options:

- **Expose authoritative provenance (recommended):** Add optional typed provenance, define every producer classification, preserve fail-closed hook errors, and require complete producer tests and live proof.
- **Expose advisory provenance only:** Add the field but document it as incomplete or non-authoritative, which limits its usefulness for enforceable plugin policy.
- **Keep the content-only gate:** Decline the API change and document that origin-based gating must occur outside `before_agent_run`.

## Reproduction Assessment

Yes at source level: the public event type lacks provenance, and tracing current producer call sites identifies internal paths without equivalent stamping. A live multi-producer run is still needed as implementation proof, not to establish the contract gap.

## Solution Assessment

No, not exactly as proposed: exposing and stamping provenance is the narrowest maintainable fix, but making a throwing gate plugin fail open conflicts with the existing deliberate fail-closed hook contract and requires a separate security decision.
