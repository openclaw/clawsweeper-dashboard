## Summary

Keep this issue open: current main still omits authoritative trigger provenance from `before_agent_run`, while internal producer paths do not consistently stamp the existing provenance type. The reporter’s follow-up removed an outdated producer claim and clarified fail-open semantics, strengthening the actionable report; implementation should wait for an explicit security-boundary decision about which producers may authoritatively assign each origin class.

**Likely related people**
- `tyler6204` — high confidence; the repository routes agents, subagents, and cron ownership to this area.
- `jhps` — medium confidence; introduced provenance-adjacent inbound session metadata.
- `Kaspre` and `Takhoffman` — medium confidence; recent contributors around the plugin-hook implementation and explicitly routed into this discussion.

## What This Changes

Expose authoritative input provenance to `before_agent_run` and stamp currently unclassified internal run producers so plugins can distinguish external, inter-session, and internal triggers.

## Best Possible Solution

Define a centralized producer-authority matrix, stamp normalized provenance where each run is born, carry it through the canonical run parameters, and expose it as an optional additive hook field with producer-family tests plus live traces for user, inter-session, cron, subagent, and compaction runs.

- **Approve authoritative optional provenance (recommended):** Define per-producer authority and expose normalized `inputProvenance?: InputProvenance`, preserving `undefined` for genuinely unknown origins.

- **Keep the gate content-only:** Decline origin-based gating and explicitly document that `before_agent_run` does not provide an authoritative trigger identity.

## Reproduction Assessment

Yes for the central defect: current source shows that the hook event lacks provenance while several internal producer paths do not stamp it. A live multi-producer trace is still needed to prove the exhaustive producer inventory and final fix.

## Solution Assessment

The proposed direction is sound but incomplete if implemented as scattered producer edits. The best fix centralizes producer authority and propagation, exposes an additive optional field, and proves every dispatch family without changing existing plugin block semantics.
