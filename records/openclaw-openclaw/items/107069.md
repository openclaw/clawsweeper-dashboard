## Summary

Keep this issue open: current main still exposes a content-only `before_agent_run` event, so plugins cannot distinguish external-user, inter-session, and internal-system triggers at the pre-model gate. The report’s producer inventory needs refreshing because `src/gateway/server-methods/agent.ts` now handles provenance, but cron, subagent-spawn, and compaction paths still show no equivalent stamping; implementation should wait for explicit approval of the public plugin security contract.

## What This Changes

Expose authoritative run-origin provenance to `before_agent_run` and stamp internal run producers that currently omit it.

## Best Possible Solution

Define one normalized, host-authored provenance field in the canonical agent-run parameters, stamp it where every run is born, carry it unchanged through embedded, CLI, and harness runners into `before_agent_run`, and validate the complete producer matrix with focused tests plus live dispatch-family proof.

## Reproduction Assessment

Yes for the central contract gap: current-main source proves that `before_agent_run` cannot contain provenance because its event type and construction surface do not expose it. ## Solution Assessment

The suggested direction is broadly correct, but adding an optional hook field alone is not the best fix. Provenance should be stamped at each authoritative producer boundary, normalized once, carried through canonical run parameters, and tested across every runner family.
