## Label Justifications

- `P1`: Scheduled heartbeat workflows can silently do no requested work for real users while reporting successful completion state.
- `impact:message-loss`: The assembled due-task instructions are suppressed before the model request, so the intended heartbeat message content is effectively lost.
- `impact:session-state`: `heartbeatTaskState` advances for task prompts the model never received, leaving persisted scheduling state inconsistent with actual execution.

## Summary

Keep open: current main still deterministically replaces the assembled heartbeat task body with the transcript-only placeholder on the no-hook embedded-runner path, then records due tasks as completed after the resulting normal reply path.

## What This Changes

Fix scheduled heartbeat task prompts being omitted from the model request while their last-run timestamps still advance.

## Best Possible Solution

Keep the transcript placeholder for durable history, but always derive the model-facing user text from the effective assembled prompt; add focused helper coverage for heartbeat no-hook and hook-present cases plus one cheap runner integration proving due-task text reaches model submission.
