## Summary

Keep open: this is a focused, still-needed bug-fix PR because current main still uses a prototype-chain `in` check while the branch switches the merge guard to an own-property check and adds regression coverage.

## What This Changes

The branch replaces the markdown-core frontmatter merge `in` check with `Object.hasOwn` and adds a regression test for prototype-named null frontmatter keys.

## Best Possible Solution

Land the narrow own-property guard with the added regression test after ordinary maintainer review and CI/proof checks stay green.

## Reproduction Assessment

Yes. Source inspection shows YAML nulls are skipped, the line parser can still capture `toString: null`, and `key in merged` treats inherited Object prototype names as present; the PR body also includes before/after terminal output.

## Solution Assessment

Yes. The changed condition is the merge point that misclassifies inherited prototype keys, and `Object.hasOwn(merged, key)` fixes that without adding a new parser path.
