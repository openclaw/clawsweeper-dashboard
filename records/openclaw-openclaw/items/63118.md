## Summary

Keep open: current main and the latest release have useful session primitives, but they still do not provide the requested first-class `openclaw sessions stop|kill|pause|resume` lifecycle surface, full UI controls, or resource-limit policy.

## What This Changes

Request first-class session lifecycle commands, Web Console controls, and resource limits for stopping, pausing, resuming, cleaning up, and inspecting OpenClaw sessions.

## Best Possible Solution

Define a secure lifecycle contract that maps existing abort/delete/steer/kill primitives into additive CLI, UI, and API controls with clear admin scopes, hard-kill semantics, and resource policy.

Unclear: the requested direction is aligned, but the proposed all-in-one feature set is too broad to implement safely without product and security scoping. The better path is a maintainer-defined lifecycle contract split into narrow command/UI/API slices.
