## Summary

This issue should stay open: current main has partial session primitives, including `sessions.abort`, `sessions.delete`, `sessions.cleanup`, `sessions.compact`, chat/Web UI stop for active runs, and an admin-only subagent kill HTTP path, but it still does not provide the requested public stop/kill/pause/resume/resource-management lifecycle contract across Gateway, CLI, and UI.

## What This Changes

The issue requests public session lifecycle controls such as stop, kill, pause, resume, cleanup filters, resource limits, and Web Console controls.

## Best Possible Solution

Define one additive, authorization-aware lifecycle contract for Gateway first, then expose consistent CLI and UI controls while routing child-process hard-kill, topic UI, resume/fork, and diagnostics through their narrower linked tracks.
