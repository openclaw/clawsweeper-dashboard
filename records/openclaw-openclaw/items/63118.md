## Summary

Keep open. Current main has useful session primitives, including Gateway abort/delete/reset/cleanup/compact, CLI list/cleanup/tail/export/compact, Control UI archive/delete/checkpoint controls, and an admin HTTP subagent kill route, but it still does not expose the requested public stop, kill, pause, resume, and resource-management lifecycle contract across Gateway RPC, CLI, and Control UI. That contract crosses authorization, child-process ownership, persisted session state, UI semantics, and resource policy, so it needs maintainer product/security direction rather than an automated cleanup close.

## What This Changes

The issue requests first-class session management commands and UI controls for stopping, killing, pausing, resuming, and limiting active sessions.

## Best Possible Solution

Define an additive, authorization-aware lifecycle contract and keep this issue as the umbrella while routing narrower process-kill, topic UI, resume/fork, and diagnostics work to their focused items.
