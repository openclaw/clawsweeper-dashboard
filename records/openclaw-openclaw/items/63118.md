## Summary

This issue should stay open because current main has partial session utilities but still lacks the requested first-class lifecycle contract across CLI, Gateway API, and Control UI. Existing `sessions.abort`, `sessions.delete`, cleanup/compact commands, Workboard stop, and the fixed delete re-registration edge address slices, while hard-kill, pause/resume, general UI controls, and quota/resource policy remain product and security design work.

## What This Changes

Request a complete user-facing session management surface with CLI/UI controls for listing, stopping, killing, pausing, resuming, cleanup, and resource-limit enforcement.

## Best Possible Solution

Define a first-class session lifecycle contract that reuses existing abort/delete/cleanup/compact behavior where safe, adds only the missing Gateway/CLI/UI surfaces, and keeps hard-kill/process/resource-limit policy behind explicit security-reviewed semantics.
