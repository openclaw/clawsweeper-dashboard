## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Rebind the cache when the remote gateway changes:** `apps/macos/Sources/OpenClaw/WebChatSwiftUI.swift:257-263`
  - body: This still builds the cache/outbox once from the current config and keeps that actor for the life of the chat controller. Remote URL, target, or transport edits only rewrite config while `GatewayEndpointStore.requireConfig()` refreshes the effective endpoint for later requests, so an existing chat window can pre-paint old gateway rows and write new gateway history under the previous gateway ID. Recreate/rebind the cache when the effective remote identity changes, or make cache scoping follow the endpoint used for each request.
  - confidence: 0.9
- **[P2] Align macOS outbox wiring with the offline contract:** `apps/macos/Sources/OpenClaw/WebChatSwiftUI.swift:263`
  - body: Passing `store` as `outbox` enables `OpenClawChatViewModel.performSend` to persist text typed while disconnected and auto-send it on reconnect. The macOS docs added by this PR still describe read-only offline browsing with sending disabled until the Gateway returns, so either wire only `transcriptCache` here or add product-approved docs, tests, and proof for intentional queued macOS sends.
  - confidence: 0.86
