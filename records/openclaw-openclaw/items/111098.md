## Label Justifications

- `merge-risk: 🚨 security-boundary`: The new DNS helper is used as an SSRF authorization boundary but does not control or verify the address used by the subsequent network connection.

## Summary

Keep this PR open: the revision restores the earlier local-DNS denial behavior, but its new resolver precheck is not tied to the address that the subsequent pricing request actually connects to. The central security problem remains unresolved, so this PR is not safe to merge as a DNS-rebinding defense.

## What This Changes

The PR adds a DNS-resolving host guard to the optional model-pricing refresh so endpoints that resolve to private or loopback addresses are skipped.

## System Context

Configured model providers can supply base URLs, and the Gateway optionally fetches remote model-pricing metadata for them. This PR changes the security decision made before that background fetch and therefore affects whether the Gateway may initiate an outbound connection.

## Architecture Diagram

flowchart TD

  B --> C[Hostname safety decision]
  C --> D[Remote pricing request]
  D --> E[Cached model pricing]
  C --> F[DNS resolution results]

## Best Possible Solution

Move this decision to a Gateway-owned outbound-fetch boundary that validates the address selected for the actual connection (or otherwise pins and verifies that connection), then add regressions for DNS rebinding and system resolver overrides alongside the pricing-refresh path.
