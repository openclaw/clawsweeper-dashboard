## Summary

This is a plausible P1 prompt-integrity bug: if the active user body is absent while tool calls continue, the agent can act on stale context. The reported artifacts are not available here and current `main` could not be inspected in this read-only environment, so the report should remain open for a maintainer or reporter-supplied trace rather than being closed as the related prompt-header confusion report.

## What This Changes

Investigate and prevent intermittent omission of the current Telegram user-message body from model prompts during long tool-use loops.

## System Context

Inbound channel messages are assembled into an ordinary user message plus an internal runtime-context carrier before each model request. The embedded agent runner then repeatedly submits that prompt while tool calls and tool results extend the same turn.

## Architecture Diagram

flowchart LR
  A[Telegram inbound message] --> B[Session message storage]

  C --> E[Current user body]

  F --> G[Tool-use loop]

## Best Possible Solution

Capture a redacted failing submitted-prompt/request trace, then add a narrow prompt-integrity invariant at the established assembly boundary so a missing active user body fails visibly instead of allowing the loop to continue; add a regression test for long tool-result histories without introducing a new configuration surface.
