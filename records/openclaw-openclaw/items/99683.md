## Summary

Keep open: this is a maintainer-labeled cleanup request, and current main still carries duplicate promise-tail queue implementations alongside the existing SDK primitive. The request is aligned with the repo’s lean-code direction, but it should remain maintainer-owned because the safe migration set spans core and bundled plugin callers with exclusions for specialized scheduling behavior.

## What This Changes

Consolidate duplicate exact-contract per-key promise-tail queues onto the existing `openclaw/plugin-sdk/keyed-async-queue` primitive while leaving specialized scheduling local.

## Best Possible Solution

Land a focused maintainer-sponsored refactor that migrates only exact FIFO-per-key promise-tail copies to `enqueueKeyedTask`, keeps specialized queues local, adds focused caller coverage, and shows net production LOC reduction.

## Reproduction Assessment

Not applicable as a user-facing bug reproduction. Source inspection on current main confirms both the canonical keyed queue primitive and remaining duplicate local promise-tail queue patterns.

## Solution Assessment

Yes, the requested direction is the maintainable shape: reuse the existing SDK primitive only for exact-contract callers and keep timeout, cancellation, drain, and owner-specific scheduling behavior local.
