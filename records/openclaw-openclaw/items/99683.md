## What This Changes

The issue requests consolidating duplicate exact-contract keyed async promise-tail queues onto the existing `enqueueKeyedTask`/`KeyedAsyncQueue` primitive.

## Best Possible Solution

Land a focused maintainer-sponsored refactor that migrates only exact FIFO per-key queues to `enqueueKeyedTask`, preserves specialized queues, and proves no behavior change with targeted caller tests and numstat.

## Reproduction Assessment

Yes for the maintenance concern: current main has the canonical keyed queue primitive and still has local promise-tail queues in Slack, config mutation, cron run logs, and other paths. This is not a runtime bug report with a user-facing reproduction path.

## Solution Assessment

Yes, with the issue's stated boundary: the existing primitive is the narrowest shared helper for FIFO per-key serialization, unrelated-key parallelism, rejection recovery, and final-tail cleanup. Specialized queues should remain local unless their contract exactly matches.
