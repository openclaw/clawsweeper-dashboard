## Summary

Keep open: current main and v2026.6.11 still emit only text content from ACP tool results, and this PR is a focused mapper-level fix. It is not merge-ready because proof is mock-only and the ACP docs still describe tool streaming as text content only.

## What This Changes

The PR adds ACP image content block extraction to `extractToolCallContent()` and regression tests for text, image, mixed, malformed, empty, and string fallback inputs.

## Best Possible Solution

Merge a mapper-level image-content fix only after `docs/cli/acp.md` reflects image tool-call content and a redacted real ACP bridge/client run shows an image block rendering; keep broader Feishu and Control UI media issues separate.

## Reproduction Assessment

Yes at source level: current main and v2026.6.11 route ACP tool updates through `extractToolCallContent()`, which only emits text blocks. I did not run a live ACP client reproduction in this read-only review.

## Solution Assessment

Yes for the code layer: the event mapper is the shared ACP tool-result conversion boundary and the pinned ACP SDK supports image content in tool-call content. It is not the complete merge solution until docs and real ACP bridge/client proof are added.
