## Summary

Keep open: current main and the latest release still drop ACP tool-result image blocks, and this PR is a focused mapper-level fix. It is not merge-ready until the ACP docs and real ACP bridge/client proof are added.

## What This Changes

The PR updates the ACP event mapper and tests so tool result `content[]` blocks with valid image `data` and `mimeType` are emitted as ACP `ToolCallContent`.

## Best Possible Solution

Forward ACP tool-result image blocks at the mapper boundary, update ACP docs to mention image content, and require real ACP bridge/client proof before merge.

## Reproduction Assessment

Yes at source level: current main routes ACP tool update/result payloads through `extractToolCallContent()`, and that function only emits text blocks from `content[]`. I did not run a live ACP client reproduction in this read-only review.

## Solution Assessment

Yes for the code layer: the event mapper is the shared ACP tool-result conversion boundary and the pinned ACP SDK supports image content in tool-call content. It is not the complete merge solution until docs and real ACP bridge/client proof are added.
