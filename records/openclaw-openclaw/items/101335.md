## Label Justifications

- `P2`: This is a normal Telegram queue semantics bug with limited blast radius and no confirmed outage, data loss, or security impact.
- `impact:session-state`: Same-lane Telegram messages cannot enter the active-run queue state while a reply is active, so documented collect behavior diverges from runtime session handling.
- `impact:ux-friction`: Users who configure Telegram `collect` get surprising separate turns for same-chat bursts instead of the documented coalesced follow-up.

## Summary

Keep open: current main still serializes same-lane Telegram spooled updates through a full `bot.handleUpdate` before later updates reach the reply dispatcher, while the queue docs say `collect` coalesces mid-run messages; no implemented fix or direct duplicate was found.

## What This Changes

The issue requests restoring Telegram `collect` queue semantics so same-chat bursts received during an active turn coalesce into one follow-up turn under isolated ingress.

## Best Possible Solution

Define and implement a Telegram ingress-to-followup admission path for busy same-lane updates, with crash/replay tests and live Telegram proof, or explicitly document `collect` as unsupported for same-chat Telegram bursts.
