## Label Justifications

- `P2`: This is a normal-priority Telegram queue bug with limited blast radius: messages still process, but the documented collect behavior does not work for same-chat bursts.
- `impact:session-state`: The issue is about active-run and follow-up queue state not observing same-chat Telegram messages while a prior turn owns the session.
- `impact:ux-friction`: Users configuring collect for Telegram can receive several separate turns instead of one batched follow-up, creating avoidable channel confusion without a full blocker.

## Summary

Keep open: current main still has the documented collect queue downstream of a Telegram ingress path that admits only one same-chat spooled handler at a time and awaits the full bot handler, so the reported coalescing gap is plausible and not superseded.

## What This Changes

The issue reports that Telegram isolated ingress serializes same-chat updates through a per-lane full-turn handler, preventing `messages.queue` collect from batching bursts during an active reply.

## Best Possible Solution

Design a Telegram isolated-ingress handoff that lets same-lane updates arriving behind an active turn enter the existing follow-up/collect queue without weakening durable-before-ack, retry/tombstone, or per-chat ordering guarantees.

## Reproduction Assessment

Source-reproducible, not live-reproduced: current main’s isolated ingress path uses a chat/topic lane key, holds one active spooled handler per lane, and awaits the full Telegram bot handler before the next same-lane update can enter dispatcher queue handling.
