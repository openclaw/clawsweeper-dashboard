- `impact:ux-friction`: Users can continue messaging, but configured Telegram collect mode produces surprising separate replies for same-chat bursts.

## Summary

Keep open: current main still serializes same-lane Telegram spooled updates through a full update handler before later same-chat messages can reach core queue admission, so the documented `collect` behavior remains unproven for this Telegram path and needs maintainer design rather than cleanup closure.

## What This Changes

The issue reports that Telegram same-chat isolated ingress serialization prevents burst messages from reaching `messages.queue.collect` while a reply is active, so they become separate turns instead of one coalesced follow-up.

## Best Possible Solution

Define a maintainer-approved Telegram ingress-to-follow-up admission contract that lets compatible same-chat bursts satisfy collect semantics without weakening durable spool, replay, lane ordering, or control-lane behavior.
