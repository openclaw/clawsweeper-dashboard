## Summary

Keep open: current main still has the reported Telegram boundary where same-lane spooled updates are held behind the active handler until after the turn settles, while collect/follow-up queue admission only engages for messages that reach the reply policy during an active run. This is a real source-level issue, but the fix changes Telegram ordering/replay semantics, so it should get maintainer design review before automation tries to patch it.

## What This Changes

The issue reports that Telegram isolated ingress serializes same-chat updates in a way that prevents collect-mode follow-up batching from coalescing bursts during an active turn.

## Best Possible Solution

Keep this open for a design-reviewed Telegram ingress fix that preserves durable spool ordering while allowing collect-mode same-chat bursts to enter the active follow-up queue, with replay/restart coverage and Telegram-path proof.
