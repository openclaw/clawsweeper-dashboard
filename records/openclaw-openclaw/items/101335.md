## Label Justifications

- `P2`: This is a normal Telegram queue semantics bug with limited blast radius and no confirmed outage, data loss, or security impact.
- `impact:session-state`: Same-lane Telegram messages cannot enter active-run queue state while a reply is active, so configured collect behavior diverges from runtime session handling.
- `impact:ux-friction`: Users who configure Telegram collect get surprising separate turns for same-chat bursts instead of the documented coalesced follow-up.

## Summary

Keep open: current main and the latest release still serialize same-lane Telegram spooled updates through a full update handler before later messages can reach active-run queue admission, so Telegram `collect` remains ineffective for same-chat bursts; no merged fix or exact canonical replacement was found.

## What This Changes

The issue requests that Telegram same-chat bursts arriving during an active reply can coalesce through `messages.queue.byChannel.telegram: "collect"` instead of being processed as separate turns.

## Best Possible Solution

Define Telegram busy-lane semantics explicitly: either bridge busy same-lane spooled updates into the active followup/collect admission path with replay and live Telegram proof, or document Telegram same-chat `collect` as unsupported until the broader scheduler design changes.
