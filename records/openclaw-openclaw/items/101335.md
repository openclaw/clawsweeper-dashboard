## Label Justifications

- `P2`: This is a normal Telegram queue semantics bug with limited blast radius and no confirmed outage, data loss, or security impact.
- `impact:session-state`: Same-lane Telegram updates cannot reach the active-run queue state while a reply is active, so runtime session handling diverges from documented collect behavior.
- `impact:ux-friction`: Users configuring Telegram `collect` get surprising separate turns for same-chat bursts instead of the documented coalesced follow-up.

## Summary

Keep open: current main still blocks later same-lane Telegram spooled updates before they reach the reply dispatcher, so documented `collect` behavior cannot coalesce ordinary same-chat bursts. The related merged PRs are adjacent to Telegram lane ordering and follow-up queues, but none implements the remaining ingress-to-collect bridge.

## What This Changes

The issue asks for Telegram same-chat isolated-ingress bursts to reach active-run `collect`/follow-up batching instead of being serialized as separate idle turns.

## Best Possible Solution

Define a Telegram ingress-to-follow-up admission contract for busy same-lane updates, or explicitly document Telegram same-chat `collect` as unsupported if maintainers choose to preserve strict per-lane serialization.
