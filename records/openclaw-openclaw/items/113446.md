## What This Changes

Prevent embedded session fencing from throwing `EmbeddedAttemptSessionTakeoverError` when an unchanged session file on SMB/CIFS/NFS reports unstable inode or timestamp metadata.

## System Context

Embedded agent runs release a session write lock while model work is in progress, then re-check the session transcript before writing results. The fence is meant to reject real concurrent transcript changes, but a metadata-only mismatch can instead terminate the user-visible completion on network-mounted state storage.

## Architecture Diagram

  B --> C[Release session write lock]

  E --> F[Reacquire session lock]
  F --> G[Compare session file]

  G -->|metadata-only drift| I[Continue completion]

## Best Possible Solution

Retain strict rejection for changed session content, but make the fence classify metadata-only drift as benign using the existing bounded snapshot/digest mechanism, with focused regressions for timestamp/inode flaps and real concurrent writes.

- **Add an explicit compatibility mode:** Keep strict behavior as default while offering a documented, tested content-based mode for network-mounted state.
