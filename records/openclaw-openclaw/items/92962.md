## Summary

The underlying Feishu collect-mode bug remains on current main, but this PR is not merge-ready because its bypass can process later same-chat messages ahead of already queued messages and its verification is limited to source-harness tests.

## What This Changes

Adds Feishu sequential-queue running-state introspection so ordinary same-chat follow-ups can bypass an active handler, while retaining serialized control and `/btw` lanes and adding regression tests.

## Best Possible Solution

Make the queue admission decision pending-aware—ordinary work may bypass only when a same-key task is running and no older same-key task is waiting—then integrate that invariant into current main with a three-arrival ordering regression and redacted live Feishu collect/steer proof.
