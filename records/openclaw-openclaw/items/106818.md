## Summary

The feature is useful and the native riscv64 runtime evidence is credible, but the proposed release path has a post-verification manifest-integrity blocker and overpromises best-effort image availability in the docs.

## What This Changes

Adds a dedicated riscv64 Dockerfile, a non-blocking QEMU release build that can append riscv64 to standard image manifests, and RISC-V Docker documentation.

## Best Possible Solution

Publish an experimental versioned `-riscv64` image first with checksum-pinned Node updates, Dockerfile parity checks, and registry proof; add riscv64 to standard tags only after the final manifest, including that child, has an approved provenance and verification path.
