## Summary

The report identifies a credible cross-runtime auth-state inconsistency on the current stable release, while current OpenAI documentation intentionally keeps subscription profiles blocked until the advertised reset time; the issue should remain open for an explicit cooldown-policy and owner-boundary decision rather than being closed as already implemented.

## What This Changes

Make recovered OpenAI OAuth profiles eligible again before a stale subscription-limit cooldown expires, using successful same-profile requests or a bounded health probe.

## Best Possible Solution

Centralize auth-profile outcome bookkeeping so a verified success from the same profile and quota-bearing OpenAI route clears stale subscription-limit state; otherwise use one bounded post-backoff probe, with regression coverage for interactive fallback and direct internal completion paths plus an operator-visible reset action instead of SQLite edits.
