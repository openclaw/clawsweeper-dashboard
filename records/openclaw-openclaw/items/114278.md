## Summary

Keep this PR open for normal review. The visible patch is a focused recovery change for a severe gateway availability failure, but its supplied evidence proves injected-error cache eviction rather than after-fix recovery from a real corrupted-and-repaired SQLite file; it also intentionally leaves read-only state paths unable to trigger recovery.

## What This Changes

The PR evicts the cached shared SQLite state-database handle after `SQLITE_CORRUPT` or `SQLITE_NOTADB` during a state write, allowing the next open to revalidate a repaired database without restarting the gateway.

## System Context

OpenClaw’s shared state SQLite database is used by gateway subsystems such as channel delivery, approvals, and control requests. State write transactions reuse a cached database handle; this change classifies corruption errors and removes that cached handle so a later request can reopen and validate the file.
