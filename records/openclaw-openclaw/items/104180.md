## Summary

This protected security-sensitive feature PR remains necessary, but it is not merge-ready: it changes existing gateways from manual to automatic node enrollment when the new setting is absent, and its SSH subprocess does not bind the effective destination against OpenSSH `HostName` overrides. The linked issue should remain open with this PR as its candidate fix while maintainers decide the rollout policy and the contributor supplies real SSH proof.

## What This Changes

Adds default-on SSH device-key verification for automatic node pairing approval, a read-only node identity CLI, non-interactive first-surface approval plumbing, configuration/docs, and regression tests.

## Best Possible Solution

Preserve manual pairing when the setting is absent, bind the SSH client's effective destination to the observed peer address while retaining only intentionally supported key and proxy configuration, add redirect regression coverage, and demonstrate real matched and mismatched gateway-to-node runs before merge.
