## Summary

Keep this PR open: the patch correctly prevents a current-main fleet CLI token from passing validation and then failing later under Podman, while preserving the portable positive decimal/scientific forms accepted by both supported runtimes. The fleet surface is experimental and absent from the latest release, so this does not narrow a shipped OpenClaw contract.

## What This Changes

The PR changes `fleet create --cpus` to use strict finite-number parsing and adds a regression case rejecting `0x10`.

## Best Possible Solution

Use one positive decimal/scientific CPU grammar at the fleet CLI boundary, preserving fractional values and rejecting syntax that is not portable across Docker and Podman.
