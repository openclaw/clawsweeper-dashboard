## Summary

Keep open: current main and the latest release still intentionally warn on version-manager Node daemon paths, and there is still no supported exact runtime pin or warning-acknowledgement contract. The ASDF/fnm comments confirm this is broader than NVM, with the open runtime-path PR remaining only an unmerged candidate.

## What This Changes

The issue asks for a durable way to use or acknowledge version-manager Node paths for generated gateway services so doctor does not repeatedly warn about intentionally used NVM/ASDF/fnm paths.

## Best Possible Solution

Support one explicit policy: either land a validated runtime-pin or acknowledgement path with live supervisor proof, or document that a supported system Node install is the only supported way to clear the warning.

- **Add Acknowledgement Only:** Allow users to acknowledge intentional version-manager usage while keeping the audit visible, but only if maintainers accept the reduced warning pressure.
