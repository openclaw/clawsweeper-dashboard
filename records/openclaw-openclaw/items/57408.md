## Best Possible Solution

Maintainers should decide the workspace dotenv trust boundary; if the exception is acceptable, land a narrow test-backed fix that keeps `OPENCLAW_STATE_DIR` and other runtime-control keys blocked and updates the public docs.

Yes. Source inspection shows CLI startup loads workspace `.env` through `loadWorkspaceDotEnvFile`, and current tests assert `OPENCLAW_CONFIG_PATH` remains undefined after that path.

## Solution Assessment

Unclear. Allowing the key would restore the reported workflow, but current source, tests, docs, and security policy treat workspace runtime controls as a fail-closed boundary, so the best fix needs maintainer/security direction.
