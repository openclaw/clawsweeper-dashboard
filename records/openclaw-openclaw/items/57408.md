## Summary

Keep this issue open: current main and the latest release still block `OPENCLAW_CONFIG_PATH` from workspace `.env`, and the remaining change needs maintainer/security direction rather than cleanup closure.

## What This Changes

The issue asks OpenClaw to load project-local `.env` during CLI bootstrap so `OPENCLAW_CONFIG_PATH` selects the intended project config instead of falling back to `~/.openclaw/openclaw.json`.

## Best Possible Solution

Maintainers should choose the workspace dotenv trust boundary; if the exception is acceptable, land a narrow test-backed fix that allows `OPENCLAW_CONFIG_PATH` only, keeps `OPENCLAW_STATE_DIR` and other runtime-control keys blocked, and updates the docs.

## Reproduction Assessment

Yes. Source inspection shows CLI startup loads workspace `.env` through `loadWorkspaceDotEnvFile`, and current tests assert `OPENCLAW_CONFIG_PATH` remains undefined after that path.

## Solution Assessment

Unclear. Allowing the key would restore the reported workflow, but current source, tests, docs, and policy treat workspace runtime controls as a security boundary, so the best fix needs maintainer/security direction.
