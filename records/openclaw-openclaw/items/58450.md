The issue asks OpenClaw to prevent final agent replies from promising a later follow-up unless the same turn actually started a background or delivery mechanism.

## Best Possible Solution

Define a core reply-finalization invariant for unbacked future commitments, then implement it with focused tests for generic follow-up promises, reminder text, cron coverage, session spawn, queued follow-up, and commitments interaction.
