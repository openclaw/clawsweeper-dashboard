## Summary

Keep open: current main still has only a narrow append-only reminder guard and opt-in post-reply commitments; it does not enforce the broader invariant that a final reply promising later follow-up must be backed by cron, session spawn, queued follow-up, or another delivery mechanism.

## What This Changes

The issue requests a runtime guard against final agent replies that promise a later follow-up without starting any real follow-up mechanism.

## Best Possible Solution

Define a maintainer-approved core reply-finalization invariant for unbacked future commitments, then implement focused coverage for generic follow-up promises, reminders, cron, session spawn, queued follow-up, and commitments interaction.

## Reproduction Assessment

No live high-confidence reproduction was run. Source and tests show current main still delivers narrow unbacked reminder promises with an appended note and has no broad same-turn follow-up gate.

## Solution Assessment

No; the current reminder note and opt-in commitments are useful mitigations, but the best fix still needs maintainer direction on whether to rewrite, block, annotate, or schedule broader promise-style replies.
