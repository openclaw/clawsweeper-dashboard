## Summary

Keep this PR open for revision: the proposed accounting threshold does not enforce a memory-hard limit for producer-sized chunks, and the supplied loopback output does not demonstrate the changed production authentication path or a real Urbit login.

## What This Changes

Bounds successful Tlon/Urbit authentication response draining with a 64 KiB accounting threshold and adds stream, cancellation, cookie, and fallback tests.

## Best Possible Solution

First establish whether draining is actually required for Urbit cookie extraction, then either cancel immediately after headers or enforce the limit at a transport/BYOB boundary with a time bound, focused oversized-single-chunk coverage, and an after-fix authentication run.
