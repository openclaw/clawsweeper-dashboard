## Summary

Keep open: the PR is a strong candidate fix for the inline API-key billing cooldown bug, but the prior runtime availability blocker remains. The patch added store-aware inline cooldown checks, while model-list and tool visibility paths still call the runtime availability helper without the loaded auth store, so a cooled inline provider can still be advertised as available.

## What This Changes

The PR records provider-scoped cooldown state for inline `models.providers.<id>.apiKey` credentials, gates their reuse after auth or billing failures, preserves stored-profile fallback, and updates related auth tests plus plugin-SDK surface budgets.

## Best Possible Solution

Thread the relevant auth store through every runtime availability call that can report inline provider auth availability, then land the provider-level cooldown behavior only after maintainers accept the persisted namespace and fail-closed semantics.
