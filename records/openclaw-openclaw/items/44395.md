## Summary

Keep open: current main and v2026.6.11 still use fixed token/overlap memory chunks with no heading-aware strategy, while the entity/concept/synthesis portion is broader product direction and partially overlaps prior ClawHub-scoped Memory Wiki discussions.

## What This Changes

The issue requests Markdown heading-aware memory chunking and a broader entity/graph-memory extraction direction to improve memory search precision.

## Best Possible Solution

Keep this issue as the canonical memory-search quality tracker, split heading-aware chunking from entity/graph-memory work, and have maintainers choose the memory-core API/default plus reindex contract before implementation.

## Reproduction Assessment

Yes by source inspection. Indexing a Markdown memory file with several short headed sections under the current token/overlap chunker can place unrelated sections in one embedding chunk until the size budget flushes.

## Solution Assessment

Unclear. Heading-aware chunking is a plausible narrow slice, but the best solution still needs maintainer decisions on default behavior, index invalidation, and separation from the larger entity-extraction design.
