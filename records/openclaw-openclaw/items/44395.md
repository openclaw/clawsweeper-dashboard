## Summary

Keep open: current main and v2026.6.11 still use fixed token/overlap memory chunking, with no heading-aware strategy or merged automatic entity-extraction path; related implementation PRs are closed unmerged, so this remains the canonical product/design tracker.

## What This Changes

The issue requests heading-aware memory chunking and later entity extraction or graph-memory support to improve memory search precision.

## Best Possible Solution

Keep this as the canonical product tracker, split heading-aware chunking from entity/graph-memory work, and have maintainers choose the memory-core API/default plus index identity contract before implementation.

## Reproduction Assessment

Yes by source inspection: markdown with several short headed sections accumulates into one chunk until the token-derived budget is exceeded because current chunking ignores headings; no live index run was performed in this read-only review.

## Solution Assessment

Unclear: heading-aware chunking is a plausible narrow improvement, but the best solution needs maintainer decisions on default versus opt-in behavior, index invalidation, and separation from the larger entity-extraction design.
