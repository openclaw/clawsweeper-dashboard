## Summary

Keep open: current main and the latest release still use token/overlap-only memory chunks with no heading-aware strategy, while entity/concept/synthesis extraction remains a broader product-boundary decision rather than implemented behavior.

## What This Changes

The issue requests heading-aware memory chunking for markdown memory files plus broader entity extraction, graph-style recall, and consolidation improvements.

## Best Possible Solution

Keep this as the canonical tracker, split heading-aware chunking from entity/graph-memory design, and have maintainers choose the memory-core API/default plus index identity contract before implementation.

- **Make Heading-Aware Default:** Adopt heading boundaries as canonical markdown memory behavior, accepting that existing headed files will reindex and retrieve differently.
- **Defer To Memory MVP:** Keep this open but wait for memory write/entity pipeline decisions so chunking, extraction, and wiki synthesis land as one coordinated design.

## Reproduction Assessment

Yes by source inspection. Indexing a markdown memory file with several short headed sections under the current token/overlap chunker can place unrelated sections in one embedding chunk until the size budget flushes.

## Solution Assessment

Unclear as an implementation path. Heading-aware chunking is a plausible narrow slice, but the best solution still needs maintainer decisions on default behavior, index invalidation, and separation from the larger entity-extraction design.
