## Summary

Keep open: current main and the latest release still use fixed token/overlap chunking for builtin memory indexing, with no heading-aware strategy, while the entity/concept/synthesis portion remains a broader memory product boundary decision.

## What This Changes

The issue requests heading-aware markdown chunking for memory search, with broader follow-up for entity extraction and graph-style memory retrieval.

## Best Possible Solution

Split the work into a focused maintainer-approved heading-aware builtin chunking design with index-identity handling, and track entity extraction through the Memory MVP or Memory Wiki/plugin boundary instead of bundling both into one broad change.
