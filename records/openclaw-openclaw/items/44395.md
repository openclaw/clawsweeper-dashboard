## Summary

Keep open: current main and v2026.6.11 still use fixed token/overlap memory chunks with no heading-aware strategy, and the entity/concept/synthesis path remains a broader memory-wiki/MVP design question rather than an implemented feature.

## What This Changes

Request heading-aware Markdown chunk boundaries for memory search and broader entity extraction/graph-memory support to improve durable memory recall precision.

## Best Possible Solution

Keep this as the canonical tracker, split heading-aware chunking from entity/graph-memory design, and have maintainers choose the memory-core API/default plus index identity contract before implementation.

## Reproduction Assessment

Yes by source inspection. Indexing a Markdown memory file with several short headed sections under the current token/overlap chunker can place unrelated sections in one embedding chunk until the size budget flushes.

## Solution Assessment

Unclear. Heading-aware chunking is a plausible narrow slice, but the best solution still needs maintainer decisions on default behavior, index invalidation, and separation from the larger entity-extraction design.
