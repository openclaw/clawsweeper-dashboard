## Summary

Keep open: current main and v2026.6.11 still use fixed token/overlap memory chunks, the config and index identity lack a heading-aware strategy, and the entity/concept/synthesis portion remains a broader memory product/API decision.

## What This Changes

Requests heading-aware memory chunking plus broader entity extraction so memory search keeps distinct Markdown sections separate and can recall structured people, concepts, and wiki knowledge.

## Best Possible Solution

Keep this issue as the canonical tracker, split heading-aware chunking from entity/graph-memory design, and choose a memory-core chunking API/default plus index identity contract before implementation.
