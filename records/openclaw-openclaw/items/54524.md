## What This Changes

The issue asks OpenClaw to document that enabling both the bundled session-memory hook and raw session transcript memory search can duplicate the same conversation in memory search results.

## Best Possible Solution

Add a docs-only warning in both the memory config reference and the session-memory hook docs; leave runtime dedupe and configurable hook output to separate product work such as https://github.com/openclaw/openclaw/issues/51386 and https://github.com/openclaw/openclaw/issues/60034.

## Reproduction Assessment

Yes, at source level: current main allows memory and sessions sources together, the hook writes generated Markdown under workspace memory, and memory-core can index both sources separately. I did not run a live memory search because this is a read-only review and the requested fix is documentation guidance.

## Solution Assessment

Yes for the scoped docs/design request: adding warnings to both affected docs pages is the narrowest maintainable fix. Runtime provenance-aware dedupe or hook output configuration would be broader follow-up work.
