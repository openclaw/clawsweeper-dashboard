## Summary

Keep open: the PR still targets a real Mattermost pending-history gap, but it cannot merge as-is because it changes a denied-sender context boundary, is written against an older ingress flow, and lacks focused regression coverage.

## What This Changes

The branch changes the Mattermost monitor so group allowlist denials set a history-only flag, skip command blocking, record pending history, and return without a response.

## Best Possible Solution

Land a current-main Mattermost port only after maintainers choose the trigger-only versus context-filtered allowlist semantics, with tests covering denied-sender history, no reply, and no command execution.

## Reproduction Assessment

Yes. Source inspection on current main shows Mattermost returns on `group_policy_not_allowlisted` before pending-history recording, while later mention/onchar drops do record history.

## Solution Assessment

No as submitted. The useful behavior needs a current-main port plus maintainer approval of whether denied Mattermost senders may enter prompt context by default or only through context visibility.
