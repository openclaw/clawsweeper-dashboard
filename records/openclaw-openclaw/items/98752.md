## Summary

Keep open. This maintainer-authored protected PR still has a blocking upgrade-compatibility issue: the Android camera capability missing-key default changes from enabled to disabled, so existing installs that never wrote `camera.enabled` can silently lose advertised camera tools after upgrade or re-onboarding.

## What This Changes

This PR reworks Android first-run gateway onboarding around setup-code/QR pairing, inline scanning, manual fallback, node approval progress, persisted gateway session state, and related bootstrap docs/tests.

## Best Possible Solution

Preserve existing users' effective camera-tool setting across upgrade/re-onboarding, keep any fresh-install privacy default explicit and tested, refresh the branch, and validate the Android onboarding path on an emulator or device.

## Reproduction Assessment

Yes for the review finding: source inspection shows the PR changes the absent `camera.enabled` default from true to false and initializes the onboarding camera capability off. I did not run a live Android upgrade repro in this read-only review.

## Solution Assessment

No, not as currently written. The safer path separates a fresh-install privacy choice from upgrade and re-onboarding behavior so current users do not silently lose advertised camera tools.
