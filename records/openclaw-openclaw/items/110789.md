## Label Justifications

- `P1`: The report describes a current Windows gateway restart cycle that can accumulate child processes until the gateway repeatedly crashes.
- `impact:crash-loop`: The observable reported impact is recurring gateway termination and watchdog restart after orphaned child processes exhaust memory.

## Summary

This issue remains necessary: current `main` still starts Windows cleanup with `taskkill /T` without `/F`, then schedules the forceful fallback three seconds later. The reported restart window can therefore bypass escalation when the owning process exits first; however, forcing every termination immediately would contradict the helper’s documented graceful-shutdown contract and needs Windows runtime proof before choosing that policy.

## What This Changes

The issue requests reliable Windows process-tree cleanup for npx-launched MCP servers and sub-agents so gateway restarts cannot leave child processes accumulating.

## Best Possible Solution

Keep graceful termination as the default, but make Windows escalation reliable for owned child trees during shutdown/restart; validate it with real npx-based MCP and sub-agent processes on Windows before selecting any immediate-force exception.
