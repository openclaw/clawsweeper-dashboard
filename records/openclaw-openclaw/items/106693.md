## Summary

This remains a valid downstream bug: the reporter corrected the initial diagnosis, reproduced the failure through a symlinked skill-bank directory, and linked an open dependency fix. Current main documents supported opt-in writes through trusted symlinked skill targets, so the issue should remain open until that fs-safe fix is released, consumed by OpenClaw, and verified through Skill Workshop apply.

## What This Changes

Fix Skill Workshop apply so updates succeed when an explicitly allowed workspace skill directory is a symlink resolving to a directory inside the trusted root.

## Best Possible Solution

Land and release the narrow fs-safe change that accepts directory symlinks only when their resolved targets remain inside the guarded root, then update OpenClaw and add an apply regression covering an existing skill reached through the explicitly enabled skill-bank symlink policy.
