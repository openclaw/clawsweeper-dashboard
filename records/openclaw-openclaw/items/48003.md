## Summary

Keep open: current main has partial fixes for explicit `/steer` paths and active non-streaming steer admission, but ordinary same-session visible messages can still be held behind channel/session admission lanes before queue policy can inject them into the active run. The open candidate remains https://github.com/openclaw/openclaw/pull/89238, and the remaining safety semantics need maintainer review rather than auto-closing this issue.

## What This Changes

The issue reports that `messages.queue.mode: "steer"` queues mid-turn messages until the active main-session turn completes instead of injecting them at runtime boundaries.

## Best Possible Solution

Refresh and review the admission-layer fix in https://github.com/openclaw/openclaw/pull/89238 or an equivalent maintainer-approved patch that lets ordinary same-session messages in steer mode reach queue policy without violating thread/session ownership, with real Discord, Telegram, and WebChat proof.
