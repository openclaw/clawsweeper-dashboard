## Summary

Keep open: current main has partial fixes for active non-streaming steering and explicit Telegram/Web UI `/steer`, but ordinary same-session visible messages can still wait behind the active reply/channel lane before queue policy can steer them. The open candidate remains https://github.com/openclaw/openclaw/pull/89238, which needs maintainer-approved refresh before it can close this issue.

## What This Changes

The issue reports that `messages.queue.mode: "steer"` messages sent during an active main session run are queued until the turn ends instead of being injected into the running turn at tool/model boundaries.

## Best Possible Solution

Refresh or replace the admission-layer fix so ordinary same-session messages reach active queue policy while preserving route/thread safety, terminal-session recovery, and explicit fallback semantics.
