## Summary

Keep open: current main has partial fixes for active non-streaming steering and explicit Telegram/Web UI `/steer`, but ordinary same-session visible messages can still wait behind channel/reply admission before active-run queue policy can steer them. The remaining work is owned by the open candidate pull request at https://github.com/openclaw/openclaw/pull/89238, which needs maintainer-approved refresh rather than a new cleanup close.

## What This Changes

The issue reports that `messages.queue.mode: "steer"` messages sent during an active main-session turn are queued until completion instead of being injected into the active run at runtime boundaries.

## Best Possible Solution

Refresh or replace the admission-layer fix so ordinary same-session messages reach active queue policy while preserving route/thread safety, terminal-session recovery, and explicit accepted-queue fallback semantics.
