## Summary

Keep open. Current main has the important runtime-admission fix from the merged partial work, but source and discussion still show a remaining same-session admission/ordinary Telegram text path where messages can wait behind an active run before queue-mode steering can act.

## What This Changes

The issue reports that `messages.queue.mode: "steer"` and related steering commands can arrive after the active turn finishes instead of being injected into the running main session at tool/model boundaries.

## Best Possible Solution

Keep this issue as the canonical tracker until maintainers land or replace the remaining post-context same-session admission and ordinary Telegram steer-mode ingress fix, then close obsolete partial PRs against that result.

## Reproduction Assessment

Yes, at source level: ordinary Telegram text remains serialized by chat/topic before final session and queue-mode context exists, and current admission tests keep non-Slack Telegram turns behind active reply operations. I did not run a live transport replay in this read-only review.

## Solution Assessment

No, current main is only a partial solution. The best fix is a post-context, active-session-aware admission/ingress path that lets eligible same-session steer messages reach queue policy without a blind pre-context bypass.
