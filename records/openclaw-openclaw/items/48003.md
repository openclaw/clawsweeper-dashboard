## Summary

Keep open: current main has important partial fixes for active non-streaming steering and explicit Telegram/Web UI `/steer`, but ordinary same-session visible messages can still wait behind an active reply operation before queue policy can steer them. Open PR https://github.com/openclaw/openclaw/pull/89238 is the current candidate for that remaining admission-layer work, but it is not merge-ready.

## What This Changes

The issue reports that `messages.queue.mode: "steer"` messages are serialized behind active main-session turns instead of reaching the active run at tool/model boundaries.

## Best Possible Solution

Refresh or replace the admission-layer fix so ordinary same-session messages reach active queue policy while preserving route/thread safety, terminal-session recovery, and explicit fallback semantics.
