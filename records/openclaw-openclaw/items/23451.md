## Summary

Keep open: current main and the latest release still provide lower-level exec/plugin approval primitives, but not the requested configurable response-level confirmation gate that can inspect same-response assistant text before the first risky tool executes.

## What This Changes

The issue requests a configurable tool confirmation gate that can pause risky tool calls for user approval before execution.

## Best Possible Solution

Define a maintainer-approved core confirmation policy with deterministic risk semantics, backward-compatible config/schema/docs, and regression coverage around execution ordering plus existing approval primitives.

## Reproduction Assessment

Yes, at source level: current main lacks `tools.confirmation` config/schema support, the pre-tool event lacks same-response assistant text, and unblocked tools execute after the lower-level hook path.

## Solution Assessment

Unclear until maintainers choose the security model; a core response-level gate is likely the right layer for same-response risky tool calls, but the exact policy must not duplicate or bypass existing approval seams.
