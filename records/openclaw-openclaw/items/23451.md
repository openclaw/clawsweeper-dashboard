## Summary

Keep open: current main still has exec and plugin approval primitives, but not the requested built-in, configurable response-level confirmation gate that can inspect same-response assistant text before the first risky tool executes.

## What This Changes

The issue requests a configurable runtime gate that can pause risky tool calls for human confirmation before execution when the model emits text and tool calls in the same response.

## Best Possible Solution

Keep this open for a maintainer-approved core design that adds a backward-compatible response-level confirmation gate while preserving exec approvals and plugin `before_tool_call.requireApproval` as lower-level primitives.
