## Summary

Keep open: current main and v2026.6.11 still have lower-level exec/plugin approval primitives, but not the requested configurable response-level confirmation gate that can hold risky same-response tool calls before they execute.

## What This Changes

Request a configurable tool-level confirmation gate that can pause risky model-proposed tool calls before execution, especially when assistant text asks for confirmation in the same response.

## Best Possible Solution

Design a disabled-by-default core confirmation policy that composes with plugin and exec approvals, uses deterministic risk/current-turn authorization where possible, flushes assistant text before holding tools, and documents deny/timeout/transcript/channel behavior with regression coverage.

- **Restrict To Existing Plugin Seam:** Keep core behavior unchanged and require operators to implement contextual approval through before_tool_call.requireApproval or trusted tool policies, accepting that no built-in same-response confirmation gate exists.

## Solution Assessment

Unclear until maintainers settle the policy: a runtime gate between parsed tool calls and execution is the right layer, but the proposed natural-language auto tier needs security/product design. A safer solution should lean on deterministic risk and current-turn authorization signals while preserving existing plugin and exec approval seams.
