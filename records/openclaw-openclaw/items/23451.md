## Summary

Keep open: current main still lacks a built-in configurable response-level tool confirmation gate, and the closest PR attempt was closed unmerged as an unmergeable branch rather than landing the feature.

## What This Changes

This issue requests a configurable tool confirmation gate that can pause risky model-emitted tool calls before execution and wait for explicit human approval.

## Best Possible Solution

Design a core confirmation policy that composes with existing approval primitives, uses deterministic risk and current-turn authorization signals, flushes visible assistant text before holding tools, and documents approve, deny, timeout, transcript, and channel behavior with regression coverage.

- **Fold into broader policy work:** Wait for related action-level deny, response-gate, MCP consent, and HITL interrupt designs to converge before adding a new config surface.

## Reproduction Assessment

Yes, at source level: current main has no tools.confirmation type/schema and the tool execution path proceeds after existing lower-level hooks when they do not block. I did not run a destructive live scenario.

## Solution Assessment

Unclear until maintainers choose the policy; a runtime gate between parsed tool calls and execution is the right layer, but the proposed text-pattern auto tier should be constrained or replaced with deterministic risk/current-turn authorization signals.
