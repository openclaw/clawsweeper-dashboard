## Summary

Keep open: current main and v2026.6.11 still have lower-level exec/plugin approval primitives, but not the requested configurable response-level confirmation gate before the first risky tool executes.

## What This Changes

Request adds a configurable `tools.confirmation` gate that can hold risky tool calls for user approval based on tool risk and same-response assistant text.

## Best Possible Solution

Keep this open for a maintainer-designed core confirmation policy with deterministic risk semantics, schema/docs coverage, and regression tests around tool execution ordering and existing approval primitives.

## Reproduction Assessment

Yes, at source level: current main lacks `tools.confirmation` config/schema support, the pre-tool event lacks same-response assistant text, and unblocked tools execute after the lower-level hook path.

## Solution Assessment

Unclear until maintainers choose the security model; a core gate is likely the right layer for same-response risky tool calls, but the policy must not duplicate or bypass existing approval seams.
