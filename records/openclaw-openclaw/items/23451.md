## Summary

Keep open: current main still has lower-level exec and plugin approval primitives, but not the requested configurable response-level confirmation gate before risky same-response tool calls execute.

## What This Changes

Request a configurable tool confirmation policy that can pause risky tool calls, flush assistant text, and wait for explicit user approval before execution.

## Best Possible Solution

Design a core tool-execution confirmation policy that composes with plugin approvals, uses deterministic risk and current-turn authorization signals where possible, flushes assistant text before holding tools, and documents deny/timeout/transcript/channel behavior with schema and regression coverage.

## Reproduction Assessment

Yes, at source level: current main has no tools.confirmation type/schema and the agent loop proceeds from a tool-use assistant message into tool execution without a built-in response-level confirmation gate. I did not run a destructive live scenario because the missing feature is clear from source inspection.

## Solution Assessment

Unclear: a runtime gate between parsed tool calls and execution is the right layer, but the proposed natural-language auto tier needs product/security design. A safer solution should lean on deterministic risk and current-turn authorization signals while preserving the existing plugin approval seam.
