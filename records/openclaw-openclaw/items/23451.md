## Summary

Keep open: current main and the latest release still have exec/plugin approval primitives, but not the requested configurable response-level confirmation gate before the first risky tool call; the earlier implementation PR was closed unmerged as an unmergeable branch.

## What This Changes

Request a configurable confirmation gate that can hold risky tool calls before execution when assistant text and tool calls arrive in the same model response.

## Best Possible Solution

Keep this as a core product/security design item and define a default-off confirmation policy that composes with exec/plugin approvals, uses deterministic risk and current-turn authorization signals, flushes visible text before holds, and records approve/deny/timeout outcomes cleanly.
