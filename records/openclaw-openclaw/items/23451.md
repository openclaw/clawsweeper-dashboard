## Label Justifications

## Summary

Keep open: current main and latest release still have lower-level plugin/exec approval primitives, but not the requested configurable, response-aware tool confirmation gate before side-effecting tools execute.

## What This Changes

The issue requests a configurable tool-level confirmation gate that can pause risky tool execution for human approval before execution.

## Best Possible Solution

Define a maintainer-approved core/tool-execution confirmation contract with typed config, deterministic action/risk classification, same-response assistant text handling, approval/deny/timeout semantics, and regression coverage that preserves existing plugin and exec approval paths.

## Reproduction Assessment

Yes at source level: current main lacks the requested typed confirmation config and response-level execution hold, while existing hooks only block or approve individual tool calls through lower-level policies. I did not run a destructive live channel repro.

## Solution Assessment

Unclear until maintainers choose the security/product model; the best direction is a core confirmation contract that composes with plugin approvals rather than a prompt-only instruction or a one-off exec guard.

## Risks / Open Questions
