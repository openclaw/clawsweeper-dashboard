## Summary

Keep open: current main and the latest release still lack the requested built-in, configurable response-level tool confirmation gate; existing plugin and exec approvals are adjacent lower-level primitives, and the closest PR attempt was closed unmerged as an unmergeable branch.

## What This Changes

Add a configurable core tool confirmation gate that can pause risky tool execution and wait for explicit human approval before the first tool call runs.

## Best Possible Solution

Design a maintainer-approved core confirmation policy that composes with existing approval primitives, uses deterministic risk/current-turn authorization signals, flushes visible assistant text before holding tools, and documents approve, deny, timeout, transcript, and channel behavior with regression coverage.
