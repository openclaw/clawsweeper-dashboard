## Summary

Keep open: current main still has lower-level exec/plugin approval primitives, but not the requested configurable response-level confirmation gate before same-response risky tool calls execute.

## What This Changes

Request a configurable tool confirmation gate that pauses risky tool execution for human approval based on tool risk and same-response assistant text.

## Best Possible Solution

Design a core tool-execution confirmation policy that composes with plugin approvals, uses deterministic risk and current-turn authorization signals, flushes assistant text before holding tools, and documents deny/timeout/transcript/channel behavior with schema and regression coverage.

Rationale: Source inspection proves the missing gate, but the permanent policy defines a new authorization boundary and config contract that automation cannot choose safely.

Likely owner: steipete

Owner confidence: medium

Options:

- **Design core gate (recommended):** Approve a maintainer-led core design with disabled-by-default config, deterministic risk/current-turn authorization rules, explicit approve/deny/timeout behavior, and regression coverage around existing plugin approvals.
- **Keep plugin-only:** Keep core behavior unchanged and require operators to implement contextual approvals through before_tool_call.requireApproval or trusted tool policies, accepting that no built-in same-response confirmation gate exists.
- **Defer into broader policy work:** Wait for related action-level deny, response-gate, and HITL interrupt designs to settle into one authorization model before adding a new config surface.

## Reproduction Assessment

Yes, at source level: current main has no tools.confirmation type/schema and tool wrappers proceed from existing lower-level hooks into execution when not blocked; no destructive live scenario was run.

## Solution Assessment

Unclear until maintainers choose the policy; a runtime gate between parsed tool calls and execution is the right layer, but text-pattern auto-confirm should be constrained or replaced by deterministic risk/current-turn authorization signals.
