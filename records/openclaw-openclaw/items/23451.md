## Summary

Keep open: current main still has lower-level exec and plugin approval primitives, but no built-in configurable response-level confirmation gate that can pause risky same-response tool calls before execution.

## What This Changes

Request a configurable runtime gate that classifies tool-call risk and pauses selected tool calls for explicit user approval before execution.

## Best Possible Solution

Design a core confirmation policy that composes with existing approvals, uses deterministic risk and current-turn authorization signals, flushes visible assistant text before holding tools, and documents approve, deny, timeout, transcript, and channel behavior.

Question: Should OpenClaw add a built-in response-level tool confirmation gate, and which deterministic risk/current-turn authorization rules should decide allow, require-confirm, deny, and timeout behavior?

Rationale: Source inspection proves the requested gate is missing, but the permanent policy defines a new authorization boundary and config contract that automation cannot choose safely.

Likely owner: steipete

Owner confidence: medium

Options:

- **Design core gate (recommended):** Approve a maintainer-led core design with disabled-by-default config, deterministic risk/current-turn authorization rules, explicit approve/deny/timeout behavior, and regression coverage around existing plugin approvals.
- **Keep plugin-only:** Leave core behavior unchanged and require operators to implement contextual approvals through before_tool_call.requireApproval or trusted tool policies, accepting that no built-in same-response confirmation gate exists.
- **Fold into broader policy work:** Wait for related action-level deny, response-gate, and HITL interrupt designs to settle into one authorization model before adding a new config surface.

## Reproduction Assessment

Yes, at source level: current main has no tools.confirmation type/schema and the tool execution path proceeds after existing lower-level hooks when they do not block. I did not run a destructive live scenario for this read-only review.

## Solution Assessment

Unclear until maintainers choose the policy. A runtime gate between parsed tool calls and execution is the right layer, but the proposed text-pattern auto tier should be constrained or replaced by deterministic risk/current-turn authorization signals.
