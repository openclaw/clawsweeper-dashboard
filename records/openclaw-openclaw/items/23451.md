## Summary

Keep this open: current main has lower-level exec/plugin approval primitives, but it still lacks the requested built-in, configurable, assistant-text-aware tool confirmation gate before first tool execution.

## What This Changes

Request a configurable core tool confirmation gate that can pause risky tool calls before execution when the model emits confirmation-looking text and tool calls in the same response.

## Best Possible Solution

Design a maintainer-approved core tool-execution gate or generic policy seam that composes with plugin before_tool_call.requireApproval, adds documented config/schema/help only if needed, and includes upgrade-safe regression coverage.

## Reproduction Assessment

Yes from source inspection, not from a live run: current strict config schemas do not accept tools.confirmation, and current pre-tool execution only gates lower-level policies and plugin approvals. Same-response assistant text is captured on a separate LLM-output event rather than passed into the pre-tool decision surface.

## Solution Assessment

Unclear as proposed: the safety need is real, but the best implementation should be a maintainer-designed core policy seam with deterministic authorization semantics rather than only an assistant-text question heuristic.
