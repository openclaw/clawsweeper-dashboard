## Summary

Keep open: current main and v2026.6.11 still have lower-level exec/plugin approval primitives, but not the requested configurable response-level confirmation gate before same-response risky tool calls execute.

## What This Changes

Request to add a configurable risk-based confirmation gate that can pause tool execution before execution when the assistant response asks for user confirmation.

## Best Possible Solution

Design a core tool-execution confirmation policy that composes with plugin approvals, uses deterministic risk and current-turn authorization signals where possible, flushes assistant text before holding tools, and documents deny/timeout/transcript/channel behavior with schema and regression coverage.

Rationale: Source inspection proves the missing gate, but the permanent policy defines a new authorization boundary and config contract that automation cannot choose safely.

Likely owner: steipete

Owner confidence: high

Options:

- **Design core gate (recommended):** Approve a maintainer-led core design with disabled-by-default config, deterministic risk/current-turn authorization rules, explicit approve/deny/timeout behavior, and regression coverage around existing plugin approvals.
- **Keep plugin-only:** Keep core behavior unchanged and require operators to implement contextual approvals through before_tool_call.requireApproval or trusted tool policies, accepting that no built-in same-response confirmation gate exists.
- **Defer into broader policy work:** Wait for related action-level deny, response-gate, and HITL interrupt designs to settle into one authorization model before adding a new config surface.

## Reproduction Assessment

Yes, at source level: current main has no tools.confirmation type/schema and the agent loop proceeds from a tool-use assistant message into tool execution without a built-in response-level confirmation gate. I did not run a destructive live scenario because the missing feature is clear from source inspection.

## Solution Assessment

Unclear until maintainers choose the policy. A runtime gate between parsed tool calls and execution is the right layer, but the proposed text-pattern auto tier should be constrained or replaced by deterministic risk and current-turn authorization signals.
