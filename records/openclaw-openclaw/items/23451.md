## Summary

Keep open: current main has lower-level plugin approvals and host exec approvals, but it still lacks the requested built-in configurable confirmation gate that can hold same-response tool execution before the user can answer.

## What This Changes

The issue requests a configurable tool-level confirmation gate that pauses risky tool calls before execution and resumes only after explicit user approval or timeout handling.

## Best Possible Solution

Design a backward-compatible core confirmation policy that uses deterministic tool/action risk and current-turn authorization, flushes visible assistant text before holding execution, and defines approve/deny/timeout plus skipped-tool transcript semantics while preserving existing approval primitives.

## Reproduction Assessment

Yes, source-reproducible: current main has no tools.confirmation config/schema surface and the pre-tool execution path only blocks or plugin-requests approval when existing policies return that result.

## Solution Assessment

Yes for the problem direction, but the best fix is a maintainer-designed core execution policy rather than simply parsing assistant text for questions.
