## Summary

Keep open: current main still has exec and plugin approval primitives, but it does not implement the requested configurable, response-level confirmation gate that can inspect same-response assistant text before the first risky tool executes.

## What This Changes

The issue requests a configurable runtime confirmation gate that pauses risky tool calls for human approval after model output but before execution.

## Best Possible Solution

Keep this open for a maintainer-designed core confirmation policy with deterministic risk semantics, schema/docs coverage, and regression tests around tool execution ordering and existing approval primitives.

## Reproduction Assessment

Yes. Source inspection shows current main lacks `tools.confirmation` config/schema support, the pre-tool event lacks same-response assistant text, and unblocked tools execute after the lower-level hook path.

## Solution Assessment

Unclear until maintainers choose the security model. A core gate is likely the right layer for same-response risky tool calls, but the policy must not duplicate or bypass existing approval seams.
