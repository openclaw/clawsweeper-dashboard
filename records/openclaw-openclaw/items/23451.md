## Summary

Keep open: current main and the latest release still have lower-level plugin/exec approval primitives, but not the requested configurable response-level confirmation gate that can hold same-response risky tool calls before execution.

## What This Changes

The issue requests a configurable tool confirmation gate that classifies tool-call risk and waits for human approval before executing risky same-response tool calls.

## Best Possible Solution

Design a maintainer-approved core confirmation policy that composes with plugin approvals, uses deterministic risk/current-turn authorization signals, flushes assistant text before holding tools, and documents approve/deny/timeout/transcript/channel behavior with schema and regression coverage.

Options:

- **Design core gate (recommended):** Approve a core design with disabled-by-default config, deterministic risk/current-turn authorization rules, explicit approve/deny/timeout behavior, and tests proving existing plugin approvals still compose correctly.
- **Keep plugin-only:** Keep core behavior unchanged and require operators to implement contextual approvals through before_tool_call.requireApproval or trusted tool policies, accepting that no built-in same-response confirmation gate exists.
- **Defer into broader policy work:** Wait for the related action-level deny, pre-response gate, and HITL interrupt designs to settle into one authorization model before adding a new config surface.

## Reproduction Assessment

Yes, at source level: current main has no tools.confirmation type/schema and the agent loop proceeds from a tool-use assistant message into tool execution without a built-in response-level confirmation gate. I did not run a destructive live scenario because the missing feature is clear from source inspection.

## Solution Assessment

Unclear until maintainers choose the policy. A runtime gate between parsed tool calls and execution is the right layer, but the proposed natural-language auto tier should be constrained or replaced by deterministic risk and current-turn authorization signals.
