## Summary

Keep open: current main has adjacent exec/plugin approval primitives, but it does not implement the requested configurable, response-aware tool confirmation gate before risky tool execution.

## What This Changes

Request a core tool-level confirmation policy that can pause risky tool calls, show same-response assistant text first, and require explicit user confirmation before execution.

## Best Possible Solution

Design a documented core confirmation policy that composes with existing exec and plugin approvals, uses deterministic risk and current-turn authorization semantics, flushes visible assistant text before holding execution, and has explicit allow/deny/timeout transcript behavior with focused tests and docs.

## Reproduction Assessment

Yes, source-reproducible: current schemas reject the proposed confirmation surface and the before-tool-call path lacks a response-aware core gate, though no live runtime repro was run for this read-only review.

## Solution Assessment

Partly: a confirmation gate is a strong direction, but the proposed natural-language auto heuristic should be replaced with deterministic risk classification and explicit current-turn authorization semantics.
