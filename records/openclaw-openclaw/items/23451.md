## Summary

Keep open: current main still has exec approvals and plugin `before_tool_call.requireApproval`, but not the requested built-in, configurable confirmation gate that can inspect same-response assistant text before the first tool executes.

## What This Changes

Request a configurable tool-level confirmation gate that can pause risky tool calls for human approval before execution.

## Best Possible Solution

Design a core, backward-compatible confirmation policy that composes with plugin and exec approvals, adds schema/help/docs, and proves approve/deny/timeout/transcript behavior across risky tool classes before enabling it.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction of the design gap: current pre-tool policy sees tool facts but not same-response assistant text, and the adapter executes unless existing lower-level policies block or request approval.

## Solution Assessment

Unclear: the desired end state is sound, but the exact natural-language `auto` heuristic needs maintainer product/security design; deterministic risk facts and explicit current-turn authorization may be safer than parsing confirmation wording alone.
