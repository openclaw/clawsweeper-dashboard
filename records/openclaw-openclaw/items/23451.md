## Summary

Keep open: current main still has lower-level plugin and exec approval primitives, but not the requested configurable response-level tool confirmation gate that can inspect same-response assistant text before the first risky tool executes.

## What This Changes

The issue requests a configurable tool confirmation gate that can pause risky tool calls before execution until a human approves them.

## Best Possible Solution

Design a core confirmation policy with deterministic risk semantics, schema/docs coverage, text-flush-before-hold behavior, approve/deny/timeout handling, and regression tests that preserve existing approval seams.

## Reproduction Assessment

Yes, at source level: current main has no `tools.confirmation` config/schema, the pre-tool path lacks same-response assistant text, and unblocked tools execute after the lower-level hook path.

## Solution Assessment

Unclear until maintainers choose the security model; a core response-level gate is likely the right layer, but it must avoid duplicating or bypassing existing approval primitives.
