## Summary

Keep open: current main has exec and plugin approval primitives, but still no core `tools.confirmation` config, deterministic risk-tier policy, or assistant-text-aware hold before the first same-response tool call executes. A closed unmerged PR attempted this exact feature, and related open issues cover narrower overlaps, so this issue remains the canonical product/security design item.

## What This Changes

Request a configurable core tool confirmation gate that can pause same-response tool execution for human approval based on tool risk and assistant text.

## Best Possible Solution

Design a backward-compatible core confirmation policy that composes with exec and plugin approvals, classifies tool/action risk deterministically, can see same-response assistant text before first execution, flushes visible text before holding tools, and records approve/deny/timeout outcomes safely.

## Reproduction Assessment

Yes, from source inspection: current main lacks `tools.confirmation`, the strict schemas do not accept it, and the pre-tool hook path does not receive same-response assistant text. I did not run a live model reproduction during this read-only review.

## Solution Assessment

Unclear as an implementation shape: a core gate is the right owner for the same-response text/tool-call mismatch, but the risk tiers, auto heuristic, default state, and approval UX need maintainer security/product decisions before a fix PR.
