## Label Justifications

- `P1`: The issue describes risky side-effecting tool execution before a user can decline in agent/channel workflows.
- `impact:data-loss`: The requested gate is meant to prevent unintended destructive or modifying tool calls such as file, config, or delete operations.

## Summary

Keep open: current main and v2026.6.11 still have lower-level plugin and trusted-policy approvals, but no configurable tool confirmation gate that can inspect same-response assistant text before the first risky tool executes.

## What This Changes

Request a configurable tool-level confirmation gate that can pause risky tool calls for human approval before execution.

## Best Possible Solution

Keep this as the canonical maintainer design item for a core confirmation policy that composes with existing plugin approvals, action-deny work, and HITL interrupt primitives.

## Reproduction Assessment

Yes, source-reproducible: current main lacks `tools.confirmation`, strict schemas reject it, before-tool events do not carry assistant text, and unblocked tools execute after the lower-level hook.

## Solution Assessment

Unclear until maintainers choose the security model; a core execution gate is likely the right layer, but exact risk tiers, timeout, and intent semantics must not duplicate or bypass plugin approvals.
