## Label Justifications

## Summary

Keep open: current main still lacks a built-in, configurable response-level tool confirmation gate. Existing exec approvals and plugin `before_tool_call.requireApproval` are useful adjacent primitives, but they do not provide the requested core risk-tier classifier or assistant-text-aware hold before the first tool executes.

## What This Changes

Request a configurable tool confirmation gate that can pause high-risk tool execution for explicit human approval, especially when assistant text asks for confirmation in the same model response.

## Best Possible Solution

Design a core-owned, backward-compatible confirmation policy that composes with plugin `before_tool_call.requireApproval`, exec approvals, and channel approval UX, with explicit denial/timeout transcript semantics and upgrade-safe config defaults.
