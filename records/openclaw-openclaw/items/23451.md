## Summary

Keep open: current main and v2026.6.11 still only have lower-level plugin/exec approval primitives; the requested configurable response-level gate that can inspect same-response assistant text before risky first tool execution remains a product/security design item.

## What This Changes

Add a configurable tool-level confirmation gate that can pause risky tool execution for human approval based on risk tier and same-response assistant text.

## Best Possible Solution

A maintainer-designed core confirmation policy with deterministic risk classification, schema/help docs, text flush before hold, explicit approve/deny/timeout behavior, skipped-tool transcript semantics, and regression tests that preserve existing approval primitives.

## Reproduction Assessment

Yes, at source level: current main lacks tools.confirmation config/schema support, the pre-tool event lacks same-response assistant text, and unblocked tools execute after the lower-level hook path.

## Solution Assessment

Unclear until maintainers choose the security model; a core gate is likely the right layer for same-response risky tool calls, but the permanent design must not duplicate or bypass existing approval seams.
