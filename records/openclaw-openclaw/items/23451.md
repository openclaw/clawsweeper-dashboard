## Summary

Current main still lacks the requested response-level confirmation gate: existing allow/deny and plugin approval hooks operate at individual tool-call time and do not inspect the assistant's same-turn text plus tool calls before execution. Keep this open as the canonical product/security design item for built-in tool confirmation rather than closing it to existing plugin approvals or the closed unmerged implementation attempt.

## What This Changes

Request a configurable tool confirmation policy that can detect risky tool calls in an assistant response and require explicit user approval before execution.

## Best Possible Solution

Define a core, default-compatible response-level confirmation seam with deterministic allow/confirm/deny/timeout behavior, auditability, and tests proving it composes with existing plugin approvals and trusted tool policies.
