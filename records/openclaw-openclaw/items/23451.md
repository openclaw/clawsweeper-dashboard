## Summary

Keep open: current main still has lower-level exec and plugin approval primitives, but it does not implement the requested configurable response-level confirmation gate before first tool execution.

## What This Changes

Request a configurable tool confirmation gate that can pause risky tool calls for human approval when the assistant emits confirmation-like text and tool calls in the same response.

## Best Possible Solution

Design a core confirmation policy that composes with existing approval primitives, uses deterministic risk and current-turn authorization signals, flushes visible assistant text before holding tools, and documents approve, deny, timeout, transcript, and channel behavior with regression coverage.

Rationale: Source inspection proves the missing gate, but the permanent behavior changes the core authorization boundary, config contract, execution ordering, transcript semantics, and channel UX, which automation cannot choose safely.

Likely owner: steipete

Owner confidence: medium

Options:

- **Design the core gate (recommended):** Approve a maintainer-led core design with disabled-by-default config, deterministic risk/current-turn authorization rules, explicit approve/deny/timeout handling, and regression coverage around existing plugin approvals.
- **Keep plugin-only approvals:** Leave core behavior unchanged and require operators or plugins to enforce contextual approval through before_tool_call.requireApproval or trusted tool policies.
- **Fold into broader policy work:** Wait for related action-level deny, response-gate, MCP consent, and HITL interrupt designs to converge before adding a new config surface.

## Reproduction Assessment

Yes, at source level: current main has no tools.confirmation type/schema and the tool execution path proceeds after existing lower-level hooks when they do not block. I did not run a destructive live scenario.

## Solution Assessment

Unclear until maintainers choose the policy; a runtime gate between parsed tool calls and execution is the right layer, but the proposed text-pattern auto tier should be constrained or replaced with deterministic risk/current-turn authorization signals.
