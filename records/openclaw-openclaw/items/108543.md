## Summary

Keep this PR open for maintainer review. The database-first architecture matches repository policy and the supplied tests cover many migration edge cases, with no concrete line-level correctness defect established; however, this is a compatibility-sensitive stored-state migration that makes existing APNs registrations unavailable until an explicit Doctor repair runs, and the PR provides test evidence rather than after-fix proof from a real upgrade setup.

## What This Changes

Moves APNs registration reads and writes from a JSON sidecar into shared SQLite, adding Doctor-only legacy import, deletion tombstones, schema updates, and migration coverage.

## Best Possible Solution

Keep one canonical SQLite runtime authority and Doctor-owned migration, but land only after a real v2026.7.1-style upgrade demonstrates visible detection, successful `doctor --fix`, preserved direct and relay registrations, non-resurrection of a deleted registration, source cleanup, and successful post-migration APNs delivery; the user-facing recovery path should clearly direct operators to Doctor before push silently stops.
