- `impact:session-state`: The issue is about concurrent local runs crossing session keys and pressuring shared agent/app-server run state.

## Summary

Keep open: current main still queues embedded local non-BTW runs only within the same run scope, while the Codex app-server client can be shared across runs, so the reported cross-session concurrency gap remains real enough for a narrow fix.

## What This Changes

Serialize non-BTW embedded local agent runs globally across session keys when they share one embedded app-server, while preserving BTW behavior.

## Best Possible Solution

Move the embedded local non-BTW queue selection to a shared-backend/global run fence, keep stop/abort scoped, and add focused tests for cross-session queueing plus BTW concurrency.

## Reproduction Assessment

Yes at source level, but not from a live run: current main filters queued local runs by the same session scope, so different session keys can bypass serialization. No live app-server repro was run because this was a read-only review.

## Solution Assessment

Yes: a narrow embedded-backend queue predicate change is the best first fix. It should avoid new config surface, leave Gateway behavior alone, and preserve the existing BTW side-result path.
