## Summary

Keep this open: current main still serializes local embedded TUI runs only within the same session/global run scope, while Codex embedded attempts can share one leased app-server client across session keys, so the different-session concurrency hole remains plausible from source.

## What This Changes

The issue requests global serialization for non-BTW embedded local agent runs that share one Codex app-server backend, instead of queueing only by session key.

## Best Possible Solution

Implement a focused queueing fix that serializes ordinary local embedded runs sharing the same Codex app-server backend while preserving `/btw`, `/stop`, and selected-agent isolation where the backend key differs.

## Reproduction Assessment

Yes by source, but not by live execution: starting one unresolved non-BTW local send for one session key and then another non-BTW local send for a different session key bypasses the current queue because `isSameRunScope` requires the same session key.

## Solution Assessment

The requested direction is appropriate, but the best fix should key serialization to shared embedded app-server/backend ownership rather than blindly making every local session global.

## Repair Work Prompt

Fix local embedded TUI run serialization for shared Codex app-server clients. Current `src/tui/embedded-backend.ts` only queues non-BTW sends when `isSameRunScope` matches, so two non-BTW local runs with different session keys can call into the same leased Codex app-server client concurrently. Change the queue decision so non-BTW local runs that would share one embedded backend/app-server serialize globally; preserve `/btw` side-question behavior, `/stop` behavior, and selected-agent isolation when agent/auth/start options imply distinct app-server clients. Keep wait diagnostics via `waitForQueuedLocalRun`. Add focused regression coverage in `src/tui/embedded-backend.test.ts` for two different session keys queueing behind one active non-BTW run and for `/btw` still bypassing the serialization path. Inspect Codex shared-client keying only if needed; do not add config, env surface, or changelog.
