## Summary

Keep open: current main and v2026.6.11 define Chat Completions `tool_calls` for caller-supplied HTTP tools, not every internal OpenClaw tool. Exposing internal tool telemetry remains a core API/security product decision, and the report still lacks a concrete qwen request/response showing a regression from the documented contract.

## What This Changes

The issue asks OpenClaw to return internal agent tool-call information from `/v1/chat/completions` when a client uses a base URL, API key, and model name to talk to an agent.

## Best Possible Solution

Keep the default Chat Completions contract limited to caller-supplied tools; if maintainers want internal-tool visibility, design an explicit redacted opt-in diagnostic or trace surface with docs and tests.
