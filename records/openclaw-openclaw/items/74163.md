## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P1] Neutralize closing syntax before PR-body edits:** `scripts/generate-microsoft-tracker.mjs:426`
  - body: The new `--update-pr-body` mode writes the generated tracker straight into a PR body. Because generated rows include live issue/PR titles and references, any title containing `fixes`, `closes`, or `resolves` plus an issue reference can be reinterpreted by GitHub as closing syntax when this command runs. Escape or neutralize those keywords before calling `gh pr edit`, or remove the mutating mode.
  - confidence: 0.88
- **[P2] Honor live priority labels before keyword escalation:** `scripts/generate-microsoft-tracker.mjs:151-153`
  - body: `priorityFor()` ignores explicit `P0`/`P1`/`P2`/`P3` labels and derives priority from keywords instead, so the generated tracker already demotes a visible `P0` item and promotes visible `P2` items into P0/P1 rows. Parse the live priority label first, then only fall back to keyword heuristics when no priority label exists.
  - confidence: 0.93
- **[P2] Add a check mode for the generated tracker:** `scripts/generate-microsoft-tracker.mjs:422`
  - body: The PR commits generated markdown and adds the generator, but the script only writes output and there is no `--check` or package-script verification path. That leaves reviewers and CI unable to confirm that `MICROSOFT_TRACKER.md` matches the generator without mutating the checkout, contrary to the scripts generated-output guidance.
  - confidence: 0.87
- **[P3] Emit valid Markdown table separators:** `scripts/generate-microsoft-tracker.mjs:362`
  - body: The generator emits table separator rows with a single `-` for the `#` column in issue, PR, and appendix tables. GitHub-flavored Markdown requires at least three hyphens per separator cell, so rerunning this generator can produce tables that render inconsistently.
  - confidence: 0.86
- **[P3] Fix the generated tracker update instruction:** `scripts/generate-microsoft-tracker.mjs:280`
  - body: The generated tracker still tells maintainers to mark rows resolved by editing `this PR body`, even though the PR also commits `MICROSOFT_TRACKER.md` as a repository file. Make the instruction match the chosen workflow so maintainers do not update the wrong surface.
  - confidence: 0.91
- **[P3] Remove the normal PR changelog entry:** `CHANGELOG.md:9`
  - body: Root policy makes `CHANGELOG.md` release-owned for OpenClaw; normal PRs should carry release-note context in the PR body or commit message instead. Drop this changelog edit and leave release generation to the release workflow.
  - confidence: 0.9
