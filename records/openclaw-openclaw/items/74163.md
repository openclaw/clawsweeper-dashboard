Full review comments:

- **[P1] Neutralize copied closing keywords before body updates:** `scripts/generate-microsoft-tracker.mjs:240`
  - body: `prRow()` copies PR titles unchanged, and `--update-pr-body` writes the generated Markdown directly into a PR description. The current generated tracker already contains `(fixes #93288)`; GitHub documents `fixes` as a PR-description closing keyword for default-branch PRs, so this can close unrelated work unless copied titles are escaped or rendered inert. ([docs.github.com](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/linking-a-pull-request-to-an-issue?utm_source=openai))
  - confidence: 0.93
- **[P1] Honor live priority labels before keyword escalation:** `scripts/generate-microsoft-tracker.mjs:151-181`
  - body: `priorityFor()` recomputes P0/P1/P2 from title text and labels instead of first preserving the live `P*` label. The generated tracker already shows this drift by displaying a live P1 item as tracker P0, which misroutes the maintainer queue this tracker is meant to manage.
  - confidence: 0.9
- **[P2] Require token boundaries for Windows matching:** `scripts/generate-microsoft-tracker.mjs:140`
  - body: The category matcher uses `title.includes(term)`, so `windows` also matches strings such as `WindowServer`; the generated tracker currently places a macOS WindowServer issue under Windows. Use token-aware matching or explicit platform exclusions before this becomes a maintained queue source.
  - confidence: 0.86
- **[P2] Add a check mode for the generated tracker:** `scripts/generate-microsoft-tracker.mjs:422`
  - body: The script writes `MICROSOFT_TRACKER.md`, but there is no `--check` mode or package script to verify the committed artifact matches the generator. That leaves the root tracker free to drift after manual edits or PR-body refreshes.
  - confidence: 0.88
- **[P3] Remove the release-owned changelog entry:** `CHANGELOG.md:9`
  - body: Normal PRs should not edit `CHANGELOG.md`; release generation owns it in this repository. Keep the release-note context in the PR body or squash message instead of adding an unreleased changelog line here.
  - confidence: 0.87
- **[P3] Emit valid Markdown table separators from the generator:** `scripts/generate-microsoft-tracker.mjs:362`
  - body: The generator emits `| --------- | -------- | - | ... |` separator rows for the `#` column, while GitHub-flavored Markdown table separators need at least three hyphens. The committed file appears manually widened, but rerunning the generator will reintroduce the invalid separator cells.
  - confidence: 0.82
