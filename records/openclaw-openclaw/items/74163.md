Full review comments:

- **[P1] Neutralize closing keywords before PR-body updates:** `scripts/generate-microsoft-tracker.mjs:426`
  - body: `--update-pr-body` copies the generated tracker into a GitHub PR body verbatim, and the latest output already contains listed titles like `fix #92054` and `Fixes #84600`. If this tracker PR later merges with those strings in its body, GitHub can treat them as closing references for unrelated issues, so the generator needs to escape or rewrite closing keywords before body updates.
  - confidence: 0.9
- **[P2] Honor live priority labels before keyword escalation:** `scripts/generate-microsoft-tracker.mjs:151-153`
  - body: `priorityFor` looks for severity keywords in the title/labels but never first reads exact live `P0`/`P1`/`P2`/`P3` labels, so labels such as `clawsweeper:needs-security-review` can escalate a currently P3/P2 item to P0 while exact triage labels are ignored. The tracker is meant to route maintainer attention, so it should preserve live priority labels before applying fallback heuristics.
  - confidence: 0.86
- **[P2] Add a check mode for the generated tracker:** `scripts/generate-microsoft-tracker.mjs:422`
  - body: This script writes `MICROSOFT_TRACKER.md`, but there is no check-only mode or package/check integration to prove the committed file matches current generator output. That leaves a generated maintainer artifact free to drift from the source of truth, contrary to the scripts guide for generated outputs.
  - confidence: 0.84
- **[P3] Emit valid Markdown separator cells from the generator:** `scripts/generate-microsoft-tracker.mjs:362`
  - body: The generator emits single-hyphen separator cells for the `#` column, which is not a valid GFM table separator cell. The checked-in file may be formatter-adjusted, but rerunning the generator or using `--update-pr-body` can still produce broken table rendering until the generator emits `---` cells itself.
  - confidence: 0.78
- **[P3] Remove the release-owned changelog entry:** `CHANGELOG.md:9`
  - body: Root policy says normal PRs should not edit `CHANGELOG.md`; release automation derives entries from merged PRs and direct commits. This tracker/admin PR should carry release-note context in the PR body or commit message instead of adding a release-owned changelog line.
  - confidence: 0.8
