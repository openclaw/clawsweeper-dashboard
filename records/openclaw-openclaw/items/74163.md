Full review comments:

- **[P1] Neutralize closing keywords before PR-body updates:** `scripts/generate-microsoft-tracker.mjs:426`
  - body: The `--update-pr-body` path writes generated live issue/PR rows directly into a PR body. Because those rows include bare issue references and arbitrary titles, the script needs to neutralize references/closing-keyword text or avoid body mutation so it does not create unintended GitHub cross-reference or closure side effects.
  - confidence: 0.91
- **[P2] Honor live priority labels before keyword escalation:** `scripts/generate-microsoft-tracker.mjs:151-153`
  - body: `priorityFor` derives priority from title and label keywords before respecting existing P-labels, so a currently labeled item can be escalated by incidental words like security/auth in labels or titles. Use the live P-label as the source of truth before keyword fallback to avoid misleading the tracker.
  - confidence: 0.9
- **[P2] Add a check mode for the generated tracker:** `scripts/generate-microsoft-tracker.mjs:421-426`
  - body: The script always writes `MICROSOFT_TRACKER.md` and optionally edits a PR body, but it has no `--check` mode for CI or reviewers to verify that committed tracker output matches the generator. Add a non-mutating check path so future refreshes can be validated without rewriting files or GitHub state.
  - confidence: 0.84
- **[P3] Emit valid Markdown table separators:** `scripts/generate-microsoft-tracker.mjs:362`
  - body: The generator uses a single `-` separator cell for the number column in generated tables. GitHub-flavored Markdown requires at least `---`, so generated PR bodies and future output can render as plain text tables instead of Markdown tables.
  - confidence: 0.86
- **[P3] Fix the generated tracker update instruction:** `scripts/generate-microsoft-tracker.mjs:280`
  - body: The generator still tells maintainers to mark items resolved by editing the PR body, but the PR also commits `MICROSOFT_TRACKER.md` as a repository file. Generate instructions that match the intended source of truth so maintainers do not update the wrong place.
  - confidence: 0.88
- **[P3] Remove the normal-PR changelog entry:** `CHANGELOG.md:9`
  - body: This branch adds a `CHANGELOG.md` entry, but repository policy keeps that file release-owned for generated release notes. Put the release-note context in the PR body or commit message instead and leave `CHANGELOG.md` to release generation.
  - confidence: 0.9
