## Summary

Keep this open for maintainer review: current main and the latest release still hydrate visible Telegram reply-chain media without a self-authored reply-target guard, and current tests explicitly expect bot-authored reply media to hydrate when visibility allows it.

## What This Changes

The issue asks Telegram reply-media resolution to skip bot-authored photos so the agent does not receive its own generated media as inbound user attachment context.

## Best Possible Solution

Make the Telegram reply-chain media contract explicit, then either land a current-main guard with bot-authored and user-authored reply-media tests or close this as intended behavior with the current test contract cited.
