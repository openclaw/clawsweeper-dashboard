## Summary

Keep this open: current main and the latest release still allow visible Telegram reply-chain media from bot-authored messages to be hydrated, and current tests intentionally assert that behavior, so this is not fixed or safely stale. The linked external closing PR is dirty and targets removed older resolver names, so it is not a safe canonical landing path by itself.

## What This Changes

The issue asks Telegram reply media resolution to skip media from bot-authored reply targets so the agent does not receive its own generated media as inbound user attachment.

## Best Possible Solution

Make the Telegram reply-chain media contract explicit; if bot-authored media should be skipped, land a current-main guard in `resolveReplyMediaForChain` with bot-authored and user-authored coverage plus redacted Telegram proof, otherwise close this as intended behavior with the current test contract cited.

## Reproduction Assessment

Yes, at source level. Current main can hydrate media from bot-authored reply-chain nodes when visibility allows it, and current tests explicitly exercise the bot-authored generated-photo path; I did not run tests because this was a read-only cleanup review.

## Solution Assessment

Unclear. A self-authored guard is a plausible narrow fix, but current Telegram tests expect the opposite behavior for visible reply-chain media, so maintainers need to choose the contract before automation should implement it.
