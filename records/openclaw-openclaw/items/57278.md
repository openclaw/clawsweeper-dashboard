## Summary

Keep this open: current main and the latest release still hydrate reply-chain media with no bot-authored guard, while current tests intentionally expect bot-authored reply media to hydrate when visibility allows it. The open closing PR is conflicting and targets old resolver files, so this needs a maintainer contract decision before another fix PR is safe.

## What This Changes

Prevent Telegram reply-chain media hydration from treating bot-authored replied-to photos as inbound user attachments.

## Best Possible Solution

Make the Telegram reply-chain media contract explicit, then either land a current-main self-authored media-skip guard with bot/user regression coverage or close this as intended behavior with the current test contract cited.

## Reproduction Assessment

Yes, at source level. Current main can hydrate media from a bot-authored reply-chain node when visibility allows it, and the focused Telegram test explicitly expects that path.

## Solution Assessment

Unclear. A self-authored guard is a plausible narrow fix, but it would reverse the current test contract, so maintainers need to decide whether bot-authored reply media should be preserved as context or skipped.
