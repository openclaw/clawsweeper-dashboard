## Summary

Keep open: current main and v2026.6.11 have targeted wake, hook, delivery-context, and dedupe building blocks, but not the requested first-class async route registry with lifecycle, event matching, ambiguity handling, privacy policy, and safe action policy.

## What This Changes

Request to add a first-class async route registry that matches later external events to originating topic sessions, posts summaries, wakes the saved sessionKey, dedupes events, and enforces privacy/safety policy.

## Best Possible Solution

Define a narrow plugin/API-friendly async route contract that composes existing hooks, targeted wake, delivery context, persistent dedupe, and approval policy, and add core only for missing generic seams.

## Maintainer Decision

Required: true

Kind: product_direction

Rationale: The request is a cross-cutting product/API/storage/privacy/safety decision rather than a narrow bug repair, and repository vision favors lean core plus plugin/API seams for optional capability.

Likely owner: steipete

Owner reason: The decision spans product scope, plugin boundaries, storage, and recent wake/dedupe history where steipete has relevant adjacent commits and issue discussion.

Owner confidence: medium

Options:

- **Design plugin/API seam first (recommended):** Specify the generic route contract and missing SDK hooks while keeping source watchers and service-specific matchers plugin-owned unless core storage or delivery gaps are proven.
- **Build a core Gateway registry:** Core would own route persistence, matching, ambiguity handling, privacy policy, dedupe, delivery, and migration behavior for a first-party framework feature.
- **Defer to workspace plugins:** Keep the current low-level primitives only and ask users to build route ledgers in plugins or local automation until stronger demand narrows the core need.
