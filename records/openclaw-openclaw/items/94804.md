## Summary

Keep open: current main has targeted wake, hooks, Task Flow, commitments, and ephemeral system-event primitives, but it still lacks the requested first-class async route registry with lifecycle, matching, ambiguity handling, visible delivery, dedupe, privacy, and approval policy.

## What This Changes

The issue requests a framework-level async callback routing layer that maps later external events back to originating topic sessions and wakes or notifies them safely.

## Best Possible Solution

Define a narrow plugin/Gateway async-route contract that composes existing hooks, targeted wake, delivery context, dedupe, Task Flow, and approval policy before deciding whether any core-owned registry is warranted.

- **Keep it workspace/plugin-owned:** Close or defer the core feature and document how to assemble the workflow from hooks, Task Flow, targeted wake, and plugin code.
