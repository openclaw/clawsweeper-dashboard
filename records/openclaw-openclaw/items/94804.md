## Summary

Keep open: current main and v2026.6.11 have targeted wake/sessionKey, cron remapping, hook, delivery, and dedupe building blocks, but not the requested first-class async route registry with lifecycle, external-event matching, ambiguity handling, privacy policy, and safe action policy.

## What This Changes

The issue requests a first-class async result routing layer that maps later external events back to the originating topic session, posts a visible summary, wakes that session, and records dedupe/safety state.

## Best Possible Solution

Define a narrow plugin/API-friendly async route contract that composes existing hooks, task delivery, targeted wake, persistent dedupe, and approval policy before deciding whether any core-owned registry is warranted.

## Maintainer Decision

Question: Should OpenClaw add a first-class async route registry in core, expose only the missing plugin/API seams, or leave this as workspace/plugin-owned composition over existing hooks and targeted wake?

Rationale: The current code has the lower-level primitives, but the requested registry would define new product policy, storage, privacy, and safety semantics across gateway, sessions, channels, and plugins.

Likely owner: steipete

Owner reason: The decision spans core architecture, gateway wake/session routing, and plugin boundaries, and steipete appears in recent routing merge history for the adjacent wake work.

Owner confidence: medium

Options:

- **Plugin/API contract first (recommended):** Design the smallest shared API and plugin seams needed for route registration, matching, dedupe, summaries, wake, and approval-gated actions before adding a core registry.
- **Core Gateway registry:** Accept a larger core feature that owns SQLite-backed route lifecycle, matching, ambiguity handling, policy, and visible delivery semantics.
- **Workspace/plugin-owned only:** Decline core work for now and document how to compose hooks, task delivery, persistent dedupe, and targeted wake in a plugin or local workflow.
