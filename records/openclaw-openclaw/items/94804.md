## Summary

Keep open: current main has targeted wake/session-key primitives, hook mappings, Task Flow waiting state, and plugin runtime helpers, but not the requested first-class async route registry with external-event matching, dedupe, privacy/safety policy, visible topic delivery, and session wake. The remaining work is a product/API/storage boundary decision, not conservative cleanup.

## What This Changes

The issue requests a first-class framework layer for matching later external events to originating topic sessions, delivering a visible summary, deduping events, and waking the saved session safely.

## Best Possible Solution

Decide the boundary first: keep service-specific watchers and matchers plugin-owned, then add only the minimal core/plugin contract needed for durable route state, safe visible delivery, dedupe, ambiguity handling, and targeted wake if existing hooks, Task Flow, and plugin runtime APIs cannot express it cleanly.

## Reproduction Assessment

Not applicable: this is a feature request, not a report of broken documented behavior. Source inspection confirms current main has lower-level wake, hook, and Task Flow primitives but no first-class async route registry to reproduce against.

## Solution Assessment

Unclear: the proposed local single-gateway v1 is plausible, but it is not yet proven to be the best core shape. The best next step is maintainer design review over whether this belongs in core, a plugin API extension, or a ClawHub plugin using existing primitives.
