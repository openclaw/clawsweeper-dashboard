## Summary

Keep open: current main and v2026.6.11 have targeted wake, heartbeat, webhook, Gmail, and delivery-context building blocks, but not the requested first-class async route registry with lifecycle, matching, dedupe, privacy, ambiguity, and safe-action policy.

## What This Changes

Request to add a first-class async route layer that matches later external events to an originating topic session, posts summaries, dedupes events, and wakes the saved session with safety policy.

## Best Possible Solution

Define a narrow async route contract first, preferably plugin/API-backed with a local single-gateway registry, explicit privacy/safety policy, and clear separation from existing wake, hook, heartbeat, and cron primitives.
