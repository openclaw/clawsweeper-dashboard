## Summary

Keep open: current main has targeted wake, hook/cron ingress, system-event dedupe, and delivery-context building blocks, but not the requested first-class async route registry with external-event matching, route lifecycle, ambiguity handling, privacy policy, and safe action policy.

## What This Changes

Request to add a first-class async result routing layer that maps later external events back to originating topic sessions for summary delivery and session wake.

## Best Possible Solution

Define a narrow plugin/API-friendly async callback route contract that composes existing hooks, targeted wake, delivery context, dedupe, and approval policy before deciding whether any core-owned registry is warranted.

## Reproduction Assessment

Not applicable: this is a feature request, not a reported broken current contract. Source inspection confirms the lower-level wake, hook, delivery-context, and dedupe pieces exist while the requested async route registry and policy layer are not present.

## Solution Assessment

Unclear as an implementation direction. A core route registry may be useful, but VISION.md and AGENTS.md both push toward a lean core and plugin/API seams, so maintainers should choose the boundary before implementation.
