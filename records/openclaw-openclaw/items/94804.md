## Summary

Keep open: current main and the latest release have targeted wake, cron, hooks, delivery-context, and idempotency building blocks, but not the requested first-class async route registry with route lifecycle, cross-source event matching, ambiguity handling, dedupe state, privacy policy, and approval-gated action policy.

## What This Changes

The issue requests a first-class async route registry that can match later external events back to the originating topic/session, post visible summaries, wake the saved session, dedupe events, and enforce privacy and safety policy.

## Best Possible Solution

Define a narrow plugin/API-friendly async route contract that composes existing hooks, targeted wake, delivery context, dedupe, commitments, and approval policy before deciding whether any core-owned registry is warranted.
