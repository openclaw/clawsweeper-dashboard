## Summary

Keep open: current main has targeted wake, cron, hook, delivery-context, and dedupe building blocks, but not the requested first-class async route registry with external-event matching, lifecycle, ambiguity handling, privacy, and action policy.

## What This Changes

Request adding a first-class async result routing layer that maps later external events back to the originating topic session with visible summary delivery, targeted wake, dedupe, privacy policy, and approval-gated actions.

## Best Possible Solution

Define a plugin/API-first async route contract that composes existing hooks, targeted wake, delivery context, persistent dedupe, and approval policy; add core-owned storage or registry only if current plugin seams cannot express the workflow safely.
