## Summary

Keep this PR open: the prior P1 remains. The new delivery guard suppresses ordinary one-line payloads from their wording alone, so it can drop a valid user-facing cron message rather than only the unwanted internal narration; the supplied Telegram proof demonstrates the intended case but not that safety boundary.

## What This Changes

The PR adds prompt guidance and a direct-delivery filter intended to block compact cron replies that narrate a prior send or ask instead of containing the message to deliver.

## Best Possible Solution

Keep the prompt improvement, but either carry a structured “do not auto-deliver” outcome from the agent/delivery plan or omit the runtime text filter; any retained suppression must preserve legitimate one-line matching messages with focused regressions.
