## Summary

Current main already fixes the reported release behavior: agent-side web_search now stays on runtime provider discovery for configured search providers, while v2026.6.11 still had the manifest-owner gate that could hide SearXNG from the agent path even when CLI provider resolution worked.

## What This Changes

The issue reports that OpenClaw 2026.6.11 can run SearXNG through the CLI web-search path but the agent-injected web_search tool reports that search is disabled or has no provider.

## Best Possible Solution

Keep the current main runtime-first agent web_search behavior and let the next release carry it to users affected on v2026.6.11.

## Reproduction Assessment

Yes at source level: v2026.6.11 still had the manifest-owner gate that could turn off runtime provider discovery for search, while current main removes that path for search. I did not run a live SearXNG Gateway repro in this read-only review.

## Solution Assessment

Yes. The current main fix is the narrow owner-boundary solution: agent web_search stays runtime-first, and runWebSearch remains responsible for provider scoping and availability checks.
