## Summary

Keep open. Current main mitigates the old fast status wording, but it still does not implement a live gateway memory-runtime health signal for this report, and an open fork PR explicitly closes this issue but is still unmerged and conflicting.

## What This Changes

The issue asks `openclaw status --deep` to stop reporting a live, working memory plugin as unavailable and to reflect actual gateway memory runtime health.

## Best Possible Solution

Define and land one status contract: memory status should either query live gateway runtime health or use an explicitly passive plugin status API, with regression coverage for third-party memory plugins before this issue closes.

## Reproduction Assessment

Yes at source level, but not with a fresh live plugin run: current main still lacks a live gateway memory-runtime health signal and retains local memory-manager status paths for memory-reporting modes. The exact old `unavailable` wording has been mitigated in fast status, so live validation is still useful.

## Solution Assessment

Unclear. The linked PR's provider fallback is a plausible narrow fix, but the best long-term repair needs maintainer agreement on whether status should use live gateway truth or a passive plugin status contract.
