## Summary

Keep open. Current main and v2026.6.11 soften the old human status wording to `not checked`, but they still do not expose separate live memory-runtime health: gateway memory readiness is still derived from embedding state, and memory-reporting paths still probe a local `purpose: "status"` manager. The discussion confirms the same false-negative class across Mem0, Honcho, and memory-qdrant, and an open conflicting fork PR still references this issue with closing syntax.

## What This Changes

The issue reports that `openclaw status --deep` can report an active memory plugin as unavailable even when the live gateway plugin and direct memory operations are working.

## Best Possible Solution

Land or replace a maintainer-approved status contract that separates memory runtime health from embedding readiness, while coordinating CLI-local status side-effect work through https://github.com/openclaw/openclaw/issues/62599.
