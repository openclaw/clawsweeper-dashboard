## Summary

Keep open. Current main no longer uses the old human `unavailable` wording for skipped memory inspection, but it still does not provide a live gateway memory runtime-health signal for `openclaw status --deep`, and an open conflicting fork PR still uses closing syntax for this issue.

## What This Changes

The issue reports that `openclaw status --deep` can mark a working live memory plugin as unavailable because diagnostics use embedding or local probe state instead of live plugin runtime health.

## Best Possible Solution

Define and land one gateway memory status contract that separates live runtime health from embedding readiness, covers human and JSON status, and coordinates CLI-local probing side effects through https://github.com/openclaw/openclaw/issues/62599.
