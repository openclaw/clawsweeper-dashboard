## Summary

Keep open. Current main and the latest release still do not fully solve the reported live-gateway memory status mismatch: deep human/JSON status does not wire a live runtime-health fallback, `doctor.memory.status` still reports embedding readiness rather than a separate runtime-ready signal, and a broader open issue plus a conflicting fork PR still cover the remaining work.

## What This Changes

The issue asks `openclaw status --deep` and doctor memory reporting to stop marking working live gateway memory plugins unavailable when runtime memory operations succeed.

## Best Possible Solution

Define one memory status contract: plain status stays passive, while opt-in memory-reporting status either queries live gateway runtime health consistently or uses a documented passive plugin status API with tests for third-party memory plugins.
