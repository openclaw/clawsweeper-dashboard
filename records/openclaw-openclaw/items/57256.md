## Summary

Keep open. Current main and the latest release avoid the original fast-status `unavailable` wording by showing skipped memory inspection as `not checked`, but memory-reporting status paths still materialize and probe the selected memory plugin locally instead of proving live Gateway runtime health, and an open fork PR still uses closing syntax for this issue.

## What This Changes

The issue asks for `openclaw status --deep` and related diagnostics to report memory as healthy when a live memory plugin is working, instead of marking the plugin unavailable from a mismatched status/doctor probe path.

## Best Possible Solution

Memory status should be read-only, prefer live Gateway runtime health when available, separate runtime health from embedding readiness, and avoid local plugin startup side effects in status/doctor paths.
