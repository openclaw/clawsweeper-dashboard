## Summary

Keep open. Current main partially reduces the misleading output by rendering skipped memory inspection as `not checked`, but the status/doctor contract still lacks a live memory-runtime health signal separate from embedding readiness, and an open conflicting fork PR still uses closing syntax for this issue.

## What This Changes

The issue asks `openclaw status` and `doctor.memory.status` to stop reporting working live memory plugins as unavailable and to reflect live Gateway plugin health.

## Best Possible Solution

Land or close/replace the linked fork PR with a maintainer-approved Gateway memory status contract that separates runtime health from embedding readiness and coordinates the local status side-effect boundary with https://github.com/openclaw/openclaw/issues/62599.

## Reproduction Assessment

No, not as a high-confidence live current-main Mem0/Honcho reproduction. Source inspection still shows the remaining contract gap: readiness is derived from embedding state and the doctor payload lacks a separate runtime-health field.

## Solution Assessment

Unclear. Current main is a partial mitigation for the misleading word, but the durable solution needs a maintainer-approved runtime-health versus embedding-readiness contract or an explicit decision that `not checked` is sufficient.
