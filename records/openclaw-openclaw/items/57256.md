## Summary

Keep open. Current main softened the old false `unavailable` wording to `not checked` for normal/deep status, but it still does not implement the requested live-gateway memory-runtime health signal for working external memory plugins, and an open conflicting fork PR still uses closing syntax for this issue.

## What This Changes

Make `openclaw status --deep` report an enabled external memory plugin as healthy when the live gateway is using that plugin successfully, instead of showing it as unavailable.

## Best Possible Solution

Settle one canonical status contract: memory status should stay read-only, prefer live gateway runtime health when available, separate runtime health from embedding readiness, avoid local plugin startup side effects, and align docs/tests with that contract.
