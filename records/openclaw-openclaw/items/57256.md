## Summary

Keep open. Current main has softened the skipped status output to `not checked`, but the remaining requested contract, reporting live gateway memory-runtime health for working external memory plugins, is still unresolved and an open conflicting fork PR uses closing syntax for this issue.

## What This Changes

The issue reports that `openclaw status --deep` can mark a working external memory plugin as unavailable even though the live gateway runtime and direct memory operations are healthy.

## Best Possible Solution

Define one canonical memory-status contract: status should stay read-only, prefer live gateway runtime health when available, distinguish healthy runtime from embedding readiness, and avoid local plugin startup side effects.
