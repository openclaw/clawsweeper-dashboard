## Summary

Keep open. Current main no longer shows the old fast/deep overview wording as `unavailable`, but the remaining memory-reporting paths still use CLI-local plugin runtime/status probing rather than proving live Gateway memory-runtime health, and https://github.com/BingqingLyu/openclaw/pull/1954 is still an open closing PR for this issue.

## What This Changes

The issue asks `openclaw status --deep` and related doctor/status probes to stop reporting an active memory plugin as unavailable when the live Gateway plugin is registered and memory operations work.

## Best Possible Solution

Settle one canonical memory status contract: status should be read-only, prefer live Gateway runtime health when available, distinguish runtime health from embedding readiness, and avoid local plugin startup side effects before closing this issue or the linked fork PR.
