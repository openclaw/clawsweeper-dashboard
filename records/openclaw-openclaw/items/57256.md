## Summary

Keep open. Current main and the latest release no longer support the old fast-status `unavailable` wording as a complete close: `--deep` still does not prove live memory-runtime health, memory-reporting paths still materialize/probe a local plugin manager, and the remaining scope overlaps the open broader status/plugin-runtime issue plus an open fork PR that still uses closing syntax for this issue.

## What This Changes

The issue requests that `openclaw status --deep` and related doctor/status probes report working live memory-slot plugins as healthy instead of unavailable when the gateway is successfully using them.

## Best Possible Solution

Define a maintainer-approved status contract where plain status stays read-only and memory-reporting status either queries live gateway runtime health or uses an explicit passive plugin status API, then resolve the open fork PR and the broader related issue consistently.
