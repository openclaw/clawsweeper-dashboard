## Summary

Keep open. Current main mitigates the old fast/deep text path by showing memory as not checked when skipped, but the live gateway memory-status contract still derives readiness from embedding state and lacks a separate runtime-health signal; an open conflicting fork PR also still uses closing syntax for this issue.

## What This Changes

The issue reports that `openclaw status --deep` can mark an active memory plugin unavailable even when the live gateway is using that plugin successfully.

## Best Possible Solution

Land or replace a maintainer-approved gateway memory-status contract that separates live runtime health from embedding readiness and coordinates the local status side-effect boundary with https://github.com/openclaw/openclaw/issues/62599.

## Reproduction Assessment

No high-confidence live current-main reproduction was established. Source inspection still shows the remaining contract gap: gateway memory readiness is derived from embedding status and the doctor payload has no separate live runtime-health field.

## Solution Assessment

Unclear. Current main is a partial mitigation for the old wording, but the maintainable fix needs maintainer agreement on gateway-backed runtime health versus local passive plugin status.
