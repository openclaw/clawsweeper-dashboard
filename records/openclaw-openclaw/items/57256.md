## Summary

Keep open. Current main has partially mitigated the old false-negative wording by rendering skipped memory inspection as `not checked`, but it has not clearly resolved the reported live-gateway runtime-health semantics for external memory plugins, and an open linked fork PR still uses closing syntax for this issue.

## What This Changes

The issue asks for `openclaw status --deep` to stop reporting a working memory-slot plugin as unavailable when the live gateway runtime and memory operations are healthy.

## Best Possible Solution

Status should have one maintainer-approved memory health contract: either expose live memory-slot runtime health separately from embedding readiness, or document that status is intentionally inconclusive and leave deep runtime checks to explicit memory diagnostics.
