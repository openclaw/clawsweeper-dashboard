## Summary

Keep open. Current main and the latest release no longer use the old fast-status `unavailable` wording, but `openclaw status --deep` still does not surface live gateway memory runtime health, and memory-reporting paths still fall back to local plugin runtime probing rather than a settled live-gateway status contract.

## What This Changes

The issue reports that `openclaw status --deep` can mark a working live memory plugin unavailable even when gateway logs and direct memory operations prove the plugin is healthy.

## Best Possible Solution

Define one status contract where `openclaw status --deep` either reports live gateway memory runtime health or explicitly says memory health is not checked, while `--all` or memory-specific commands use a passive plugin status API that cannot perform heavyweight local startup.
