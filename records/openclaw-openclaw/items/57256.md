## Summary

Keep open. Current main only softens the old human status wording to `not checked`; it still lacks a separate live memory-runtime health signal, still derives gateway memory readiness from embedding readiness, and the issue is paired with an open conflicting fork PR that uses closing syntax.

## What This Changes

The issue reports that `openclaw status --deep` marks a working live gateway memory plugin as unavailable.

## Best Possible Solution

Define and land or replace a maintainer-approved status/doctor memory contract that reports live gateway memory runtime health separately from embedding readiness and coordinates local plugin side-effect handling with https://github.com/openclaw/openclaw/issues/62599.
