## Summary

Keep open. Current main and the latest release soften the old false `unavailable` wording to `not checked`, but `status --deep` still does not surface live gateway memory-runtime health for working external memory plugins, and there is still an open fork PR using closing syntax for this issue.

## What This Changes

The issue asks for `openclaw status --deep` to stop reporting a working external memory plugin as unavailable when the live gateway runtime is using that plugin successfully.

## Best Possible Solution

Settle one canonical status contract: memory status should stay read-only, prefer live gateway runtime health when available, distinguish runtime health from embedding readiness, and avoid local plugin startup side effects; then review, replace, or close the stale fork PR.
