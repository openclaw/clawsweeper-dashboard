## Summary

Keep open: current main and the latest release still gate the Teams Graph media fetch in a way that can miss inbound channel/group attachments, and two open linked PRs already own candidate fixes that still need maintainer reconciliation.

## What This Changes

The issue asks OpenClaw to recognize and download inbound Microsoft Teams channel/group message attachments that are only retrievable by querying Microsoft Graph.

## Best Possible Solution

Land one reviewed msteams plugin fix that uses correct Graph identifiers for channel roots and replies, handles group/chat HTML payloads without attachment ids, preserves the mention-only protection by default or with an explicit opt-in, and includes focused regression tests plus redacted live Teams proof.

Options:

- **Default-off opt-in fallback (recommended):** Adopt the config-gated shape so existing installs keep the mention-only protection unless operators explicitly opt into extra Graph message reads.
- **Automatic non-personal fallback:** Relax the gate for all non-personal HTML activities with no media so attachments work without new config, accepting extra Graph reads and possible mention-only noise.
- **Combine the fix candidates:** Ask one branch to cover both the channel aadGroupId/reply URL fixes and the group-chat fallback gate so the compatibility story lands once.
