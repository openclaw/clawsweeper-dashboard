## What This Changes

The issue reports that Microsoft Teams inbound channel and group-chat file attachments are not reaching the agent even after Microsoft Graph permissions are configured.

## Best Possible Solution

Land one reviewed Microsoft Teams plugin fix that uses correct Graph identifiers, handles top-level channel messages, thread replies, and group chats, and preserves the mention-only protection by default or behind an explicit opt-in.

Question: Should Microsoft Teams non-personal Graph media fallback run automatically when no media is extracted, or stay default-off behind a new `channels.msteams.graphMediaFallback` option?

Rationale: The current gate avoids the known mention-only false-positive behavior, but Teams can omit attachment ids for real uploaded files; the default affects Graph call volume, permissions expectations, diagnostics, and message-delivery behavior for existing deployments.

Likely owner: sudie-codes

Owner reason: They introduced the current fallback gate whose default behavior now needs to be preserved or intentionally changed.

Owner confidence: medium

Options:

- **Default-off opt-in fallback (recommended):** Adopt the config-gated fallback so existing installs keep current mention-only protection unless operators explicitly enable extra Graph message reads.
- **Automatic non-personal fallback:** Relax the gate for all non-personal HTML activities with no media so attachments work without new config, accepting extra Graph reads and possible mention-only noise.
- **Combine linked fixes:** Ask one branch to cover both the channel AAD group id/reply URL fixes and the group-chat fallback gate so the compatibility story lands once.

## Reproduction Assessment

Yes. Source inspection shows current main still skips the Graph fallback unless delivered HTML contains extracted attachment ids, and issue comments provide live Teams evidence that real uploaded files can arrive without those ids.

## Solution Assessment

Unclear as a final product choice. The default-off fallback looks safest for upgrades, but the channel AAD group id/reply URL fixes and group-chat gate fix should be reconciled in the Microsoft Teams plugin before the issue closes.
