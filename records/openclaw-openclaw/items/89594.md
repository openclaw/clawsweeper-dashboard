## What This Changes

Issue reports that Microsoft Teams channel/group inbound attachments are not available to OpenClaw agents even after Graph permissions are configured.

## Best Possible Solution

Land a single plugin-owned Teams media fix that preserves the prior mention-only protection, uses the correct Graph URL shape for channel replies, and makes any extra Graph lookup behavior an explicit documented operator choice.

Question: Should Microsoft Teams Graph media fallback be default-off and config-gated for group/channel messages, or should OpenClaw attempt it by default whenever non-personal Teams messages have HTML but no resolved media?

Rationale: Current main intentionally avoids Graph calls without extracted attachment IDs to prevent mention-only noise, but the issue and linked live evidence show Teams can strip those IDs from real file uploads; this is a product/compatibility tradeoff, not just a mechanical code fix.

Likely owner: steipete

Owner reason: steipete has the broadest recent msteams ownership signal and is the best available owner for the config/default tradeoff.

Owner confidence: high

Options:

- **Config-gated opt-in (recommended):** Land a default-off Graph media fallback setting so existing deployments keep current behavior unless operators accept the extra Graph lookup cost and permissions.
- **Default Graph fallback:** Attempt Graph fetches by default for non-personal Teams messages that have HTML but no resolved media, accepting extra Graph calls to reduce setup friction.
- **Keep current gate:** Leave the behavior unchanged and document that some Teams channel/group file uploads are unreadable when Bot Framework strips attachment IDs.
