## Summary

Keep open: current main and v2026.6.11 still contain the inbound-media Graph fallback gate and channel Graph URL gaps, while the linked implementation PRs are open candidates rather than merged fixes.

## What This Changes

OpenClaw should recognize and process attachments sent by users in Microsoft Teams channel or group-chat messages.

## Best Possible Solution

Land one reviewed msteams plugin fix that uses correct Graph identifiers, handles top-level messages, thread replies, and group chats, preserves the mention-only protection by default or with explicit opt-in, and includes focused tests plus redacted live Teams proof.

Options:

- **Default-off opt-in fallback (recommended):** Keep existing deployments unchanged and let operators enable extra Graph message reads for group-chat/channel attachment recovery after documenting the required permissions and cost.
- **Automatic non-personal fallback:** Relax the gate for all non-personal HTML activities with no resolved media so attachments work without new config, accepting extra Graph reads and possible mention-only diagnostics.
- **Combine the active fixes:** Ask the linked branches to converge so channel aadGroupId/reply URL fixes and the group-chat fallback policy land with one compatibility story.

## Reproduction Assessment

Yes, source reproduction is high-confidence: current main still skips Graph fallback unless delivered HTML contains extracted attachment IDs, and the issue comments provide live Teams evidence that real uploaded files can arrive without those IDs. I did not replay a live Microsoft Teams tenant in this read-only review.

Unclear as a final product choice: the default-off graphMediaFallback path looks safest for upgrades, but the channel aadGroupId/reply URL fixes and group-chat gate fix need one reconciled implementation. The best fix stays in the msteams plugin rather than core.
