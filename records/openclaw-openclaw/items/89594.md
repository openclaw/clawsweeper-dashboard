## What This Changes

Fix Microsoft Teams inbound file attachments so channel and group-chat messages can reach the agent through the correct Graph lookup without regressing mention-only HTML handling.

## Best Possible Solution

Land one reviewed msteams plugin fix that uses correct Graph identifiers, covers top-level channel messages, thread replies, and group chats, and preserves the mention-only protection by default or behind an explicit opt-in.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Microsoft Teams non-personal Graph media fallback run automatically when no media is extracted, or stay default-off behind a channels.msteams.graphMediaFallback option?

Rationale: The current gate avoids noisy Graph lookups for mention-only messages, but the report and comments show real uploaded files can also arrive without extracted attachment ids; the default changes Graph call volume, permission expectations, diagnostics, and message-delivery behavior for existing Teams deployments.

Likely owner: steipete

Owner reason: They have the strongest recent history across the msteams attachment/channel delivery path and the remaining choice is a compatibility-sensitive product default.

Owner confidence: high

Options:

- **Default-off opt-in fallback (recommended):** Adopt the config-gated shape so existing installs keep the current mention-only protection unless operators explicitly opt into extra Graph message reads.
- **Automatic non-personal fallback:** Relax the gate for all non-personal HTML activities with no media so attachments work without new config, accepting extra Graph reads and possible mention-only noise.
- **Combine the fix candidates:** Ask one branch to cover both the channel aadGroupId/reply URL fixes and the group-chat fallback gate so the compatibility story lands once.

## Reproduction Assessment

Yes. Source inspection shows current main still skips Graph fallback unless delivered HTML contains extracted attachment ids, and the issue comments provide live Teams evidence that real uploaded files can arrive without those ids.

## Solution Assessment

Unclear as a final product choice. The fix should stay in the msteams plugin, but maintainers still need to reconcile the channel aadGroupId/reply URL repair with the group-chat fallback default and the older mention-only protection.
