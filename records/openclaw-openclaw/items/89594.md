## Summary

Keep open: current main and v2026.6.11 still contain the Microsoft Teams inbound attachment failure, and the linked implementation PRs are still open rather than merged. The issue should stay canonical until maintainers reconcile the channel Graph URL fixes, the group-chat fallback gate, and the mention-only false-positive protection.

## What This Changes

The issue reports that inbound Microsoft Teams channel/group messages with file attachments do not produce agent-visible media even after Graph permissions are granted.

## Best Possible Solution

Land one reviewed msteams plugin fix that corrects channel Graph URL construction, handles top-level messages, thread replies, and group-chat HTML payloads, preserves mention-only protection by default or explicit opt-in, and includes focused tests plus redacted live Teams proof.

Question: Should Microsoft Teams non-personal Graph media fallback run automatically when no media is extracted, or stay default-off behind a channels.msteams.graphMediaFallback-style option while the channel URL fixes land?

Owner confidence: high

Options:

- **Default-off opt-in fallback (recommended):** Adopt a config-gated fallback so existing installs keep the mention-only protection unless operators explicitly opt into extra Graph message reads.
- **Automatic non-personal fallback:** Relax the gate for all non-personal HTML activities with no media so attachments work without new config, accepting extra Graph reads and possible mention-only noise.
- **Combine the fix candidates:** Ask one branch to cover channel aadGroupId/reply URL fixes and group-chat fallback gating so the compatibility story lands once.

## Reproduction Assessment

Yes. Source reproduction is high-confidence: current main and v2026.6.11 still skip Graph fallback unless delivered HTML contains extracted attachment IDs, and the issue comments provide live Teams evidence that real uploaded files can arrive without those IDs.

## Solution Assessment

Unclear as a final product choice. The default-off graphMediaFallback shape is the safest upgrade path, but the channel aadGroupId/reply URL fixes and group-chat gate fix need one reconciled msteams-plugin implementation before this issue can close.
