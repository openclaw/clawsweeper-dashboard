## Summary

This PR targets a real LINE receipt bug, but it remains incorrect for reachable multi-message pushes because it retains only the first provider ID and repeats it across all receipt parts. Real behavior proof is also still limited to mocks.

## What This Changes

The PR captures LINE’s push response but uses only its first returned message ID for the singular result and all receipt metadata.

## Best Possible Solution

Preserve every ordered ID returned by LINE, use the first only for the legacy singular `messageId`, and assign each receipt part its corresponding provider ID.

## Solution Assessment

No, not as written. Selecting only the first of several returned IDs does not satisfy the existing multi-part receipt contract; the complete ordered ID list should be mapped through the receipt.
