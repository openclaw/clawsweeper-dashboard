## Summary

The PR fixes a real LINE receipt defect and now has convincing exact-head live proof, but the shared plugin SDK helper should not expose per-result kinds as a separate positional array because that public shape permits silent ID/kind misalignment.

## What This Changes

The PR captures every ordered LINE push and reply response ID, assigns each ID its outbound message kind, and extends the shared receipt normalizer with per-result kind input plus focused tests.

## Best Possible Solution

Keep the unified, proven LINE push/reply result path, but carry each optional kind on its corresponding flat receipt input result so invalid ID/kind alignment is not representable; nested receipts should remain authoritative and unchanged.
