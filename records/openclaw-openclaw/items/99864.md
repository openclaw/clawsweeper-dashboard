## Summary

Keep open: current main still has the source-reproducible compaction overcount, but this branch is not merge-ready because its fallback drops cached prompt context when `totalTokens` is unavailable, and real session proof is still missing.

## What This Changes

The PR changes `calculateContextTokens` to prefer positive `totalTokens`, fall back to `input + output`, and adds compaction regression tests for cached usage overcount.

## Best Possible Solution

Make compaction consume a trusted latest real context or last-call prompt-token snapshot instead of turn-aggregated cache buckets, with coverage for both aggregate overcount and cached missing-total undercount.

## Reproduction Assessment

Yes at source level: current main’s fallback sums cache buckets when `totalTokens` is zero, matching the linked issue’s exact inflated estimate path. I did not run a live Anthropic/container reproduction in this read-only review.

## Solution Assessment

No: the proposed fallback avoids the aggregate overcount by dropping all cache buckets, but trusted cached prompt snapshots use those buckets as context tokens. The safer fix is to feed compaction a latest-call or prompt-token snapshot rather than using a turn aggregate.
