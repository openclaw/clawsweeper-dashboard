## Summary

Keep open: the PR targets a real linked compaction bug, but the proposed fallback fixes the aggregate cache overcount by dropping cached prompt tokens entirely when `totalTokens` is missing, which can delay needed compaction for trusted cached usage snapshots.

## What This Changes

The branch changes the agent-core compaction estimator so positive provider `totalTokens` is preferred and zero/missing totals fall back to `input + output`, with regression tests for the reported cached-usage overcount.

## Best Possible Solution

Feed compaction a trusted latest context snapshot, such as positive `totalTokens`, `promptTokens`, or latest-call usage, and only reject cache buckets when the source is known to be turn-aggregated.

## Reproduction Assessment

Yes at source level: current main’s fallback sums cache buckets when `totalTokens` is zero, matching the linked issue’s exact inflated estimate path. The PR’s own helper-level output also shows the new 15,116-token fallback for that input.

## Solution Assessment

No: the proposed fix avoids the aggregate overcount by dropping all cache buckets, but current usage helpers treat cache buckets as part of prompt/context tokens for trusted snapshots. The safer fix is to pass a trusted latest-call or prompt-token snapshot into compaction and avoid using turn aggregates as context snapshots.
