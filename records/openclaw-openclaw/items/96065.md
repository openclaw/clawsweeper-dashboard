## Summary

Keep open: the PR is aimed at a real secret-handling bug and has a useful macOS LaunchAgent preservation direction, but the current patch is not merge-ready because it removes config SecretRef values from the systemd inline environment without preserving runtime delivery through the generated EnvironmentFile.

## What This Changes

The PR changes gateway install planning so env-backed config SecretRefs are included in `OPENCLAW_SERVICE_MANAGED_ENV_KEYS`, updates LaunchAgent render policy for config SecretRef env values, and adjusts daemon install tests.

## Best Possible Solution

Use the existing `environmentValueSources: "file"` contract for systemd config SecretRef secrets while preserving LaunchAgent env-file delivery, then prove both staged systemd output and macOS LaunchAgent restart/update behavior.

Yes at source level. The current code and PR diff show the install-plan/rendering path that decides whether config SecretRef env values stay inline, become managed metadata, or reach systemd's EnvironmentFile; I did not run a live systemd or launchd install in this read-only review.

## Solution Assessment

No. The PR is a plausible macOS LaunchAgent preservation step, but it is not the best fix for the systemd security bug because it uses `OPENCLAW_SERVICE_MANAGED_ENV_KEYS` as a deletion mechanism without preserving file-backed runtime delivery.
