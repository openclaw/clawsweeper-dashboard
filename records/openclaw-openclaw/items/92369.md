## Summary

Keep open: current evidence still does not establish a supported model-facing fan-out/fan-in contract for isolated cron turns, while the remaining choice is whether OpenClaw should add narrow core lifecycle support or explicitly document the dispatcher-only boundary. The recent workaround comment is useful for fire-and-forget jobs, but it does not let the cron parent wait, aggregate, and deliver one combined result.

## What This Changes

Request a reliable way for an isolated cron session to spawn parallel subagents, wait for their completion, aggregate their outputs, and deliver a final result.

## Best Possible Solution

Document isolated cron as a dispatcher-only path unless maintainers explicitly sponsor a narrow, durable completion-and-aggregation contract owned by the cron/session runtime, with clear timeout, delivery, and persistence semantics.
