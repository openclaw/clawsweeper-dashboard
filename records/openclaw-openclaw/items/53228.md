## Summary

Keep open: current main and the latest release still lack the requested shell-facing `openclaw notify <message>` command, a typed admin-scoped Gateway notification event/RPC, and a Control UI handler for visible connected-session notifications. The related Web Push, notification-tab, and sessions_broadcast work is adjacent, but it does not supersede this issue’s CLI/admin-to-UI surface.

## What This Changes

The issue requests a top-level `openclaw notify <message>` command or equivalent that pushes a visible notification bubble to connected Control UI sessions without an agent turn.

## Best Possible Solution

Define one intentional notification contract: an admin-scoped Gateway RPC/event, broadcast guard, validated payload, CLI entry point, Control UI renderer, tests/docs, and explicit coordination with https://github.com/openclaw/openclaw/issues/20237 for broader UI notification behavior.
