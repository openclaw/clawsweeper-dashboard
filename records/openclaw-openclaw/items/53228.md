## Summary

Keep open: current main and v2026.6.11 still lack the requested root `openclaw notify` command, typed Gateway notification RPC/event, and connected-Control-UI notification handler; Web Push, the Notifications settings tab, and `sessions_broadcast` are adjacent but do not supersede this shell/admin UI broadcast request.

## What This Changes

The issue requests an `openclaw notify <message>` command or equivalent admin-scoped path that pushes visible notifications to connected Control UI sessions without an agent turn.

## Best Possible Solution

Define one intentional core notification contract: an admin-scoped Gateway RPC/event, explicit broadcast guard, validated payload, Control UI renderer, CLI entry point, docs, and tests that distinguish it from `system event`, `chat.inject`, Web Push, and node notifications.
