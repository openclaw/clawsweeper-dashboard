## Summary

Keep open: current main and v2026.6.11 still lack a shell-facing admin notification command, a typed Gateway notification RPC/event, and a connected-Control-UI in-app notification handler. Existing Web Push, admin HTTP RPC, node notify, and session-broadcast work are adjacent but do not satisfy the requested no-agent-turn UI notification path.

## What This Changes

Requested addition of `openclaw notify <message>` or equivalent to push visible admin-scoped notifications from shell tools to connected Control UI sessions without an agent turn.

## Best Possible Solution

Define one product/security-approved notification contract spanning the root CLI, Gateway method/event, broadcast guard, payload and rate limits, Control UI renderer, docs, and focused tests, coordinated with https://github.com/openclaw/openclaw/issues/20237.
