## Summary

Keep open. Current main still lacks the requested shell-facing `openclaw notify <message>` command, typed admin-scoped Gateway notification RPC/event, and connected-Control-UI handler for visible in-app notifications; existing Web Push, system-event, and session-broadcast work are adjacent but not substitutes.

## What This Changes

The issue requests a new shell-facing `openclaw notify <message>` path that sends visible notifications to connected Control UI sessions through an admin-scoped broadcast without creating an agent turn.

## Best Possible Solution

Define one intentional core notification contract only if maintainers accept the boundary: an additive CLI entry point, typed admin-scoped Gateway RPC/event, explicit broadcast guard, Control UI rendering, focused tests, and docs distinguishing it from Web Push, `chat.inject`, `system event`, and agent session fan-out.

## Solution Assessment

Unclear until maintainer product/API/security review. A direct `openclaw notify` command is plausible, but the maintainable solution must settle auth scope, payload shape, targeting, rate limits, delivery semantics, and coordination with the broader WebUI notification tracker.
