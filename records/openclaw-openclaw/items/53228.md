## Summary

The issue is still necessary: current main has adjacent Web Push subscription/test support and an agent-facing system-event path, but no shell-facing admin notification command or typed Gateway/UI notification surface for connected Control UI clients.

## What This Changes

Request an `openclaw notify <message>` style command that can send a visible notification bubble to connected web/Control UI clients.

## Best Possible Solution

Define one narrow admin notification contract that reuses the Gateway permission model and Control UI notification renderer, then document how it composes with broader WebUI notification work.
