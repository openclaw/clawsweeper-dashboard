## Summary

Keep open: current main and the latest stable release still lack the requested shell-facing `openclaw notify` command, typed admin Gateway notification event/RPC, and Control UI handler for visible connected-session notifications. Existing Web Push, `chat.inject`, `system event`, `tasks notify`, and `nodes notify` paths are adjacent but do not solve this request.

## What This Changes

The issue requests an `openclaw notify <message>` or equivalent admin-scoped CLI path that pushes visible notifications to connected Control UI sessions without an agent turn.

## Best Possible Solution

Define one intentional notification contract before implementation: an admin-scoped Gateway RPC/event, broadcast guard, payload validation, abuse controls, CLI entry point, Control UI renderer, tests, and docs that distinguish it from `system event`, `chat.inject`, `nodes notify`, and Web Push.
