## Summary

Keep open. Current main and the latest release still have only adjacent Web Push, system-event, node-local notification, and task notification-policy paths; the requested shell-facing admin notification command, typed Gateway notification event/RPC, and Control UI visible notification handler are still missing and need maintainer product/security/API direction.

## What This Changes

The issue requests an `openclaw notify <message>` or equivalent shell-facing command that uses an admin-scoped broadcast path to show visible notifications in connected Control UI sessions without creating an agent turn.

## Best Possible Solution

Define one intentional notification contract only if maintainers accept the core API boundary: additive CLI entry point, typed admin-scoped Gateway RPC/event, explicit broadcast guard, Control UI rendering, focused tests, and docs distinguishing it from Web Push, `chat.inject`, and `system event`.
