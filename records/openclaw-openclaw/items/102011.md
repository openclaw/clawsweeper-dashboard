## Summary

Keep open: current main and the latest shipped Lobster plugin still let injected optional flow fields steer ordinary documented `run`/`resume` calls into managed TaskFlow parsing instead of the embedded runner path.

## What This Changes

The issue requests that the `@openclaw/lobster` tool treat schema-injected default or empty flow fields as absent for ordinary `run` and `resume` calls.

## Best Possible Solution

Fix the Lobster plugin parser so managed TaskFlow mode is selected only from intentional managed fields, while blank/default `flowStateJson` and `flowExpectedRevision: 0` without `flowId` stay on the ordinary embedded-runner path.

## Repair Work Prompt

Fix the `@openclaw/lobster` tool parser so ordinary documented `run` and `resume` calls are not routed into managed TaskFlow mode when the tool-call payload contains schema-injected defaults or empty values. Keep the fix inside `extensions/lobster`; do not change core TaskFlow APIs or add config. Add regression coverage for ordinary `run` with injected `flowExpectedRevision: 0` and empty or `{}` `flowStateJson`, ordinary `resume` with `token`/`approvalId` plus injected `flowExpectedRevision: 0` and no `flowId`, and managed run/resume still working when intentional managed fields are provided. Preserve existing validation for real invalid managed calls. No changelog edit is required.
