## Summary

Keep this PR open for maintainer review. The proposed config-first local credential policy addresses the reported client/server split, has focused parity and live CLI evidence, and does not introduce a concrete functional or security defect; however, it intentionally changes the documented precedence contract for existing configured-local deployments and carries the protected `maintainer` label.

## What This Changes

The branch makes configured `gateway.auth.token` and `gateway.auth.password`, including active SecretRefs, take precedence over ambient Gateway credential variables for implicit configured-local clients while preserving explicit URL and node-host behaviors.

## System Context

Gateway CLI calls, probes, pairing, the TUI, and internal self-clients resolve credentials before contacting the Gateway. This change aligns their implicit local credential choice with the Gateway server’s configured authentication so calls can complete instead of failing at the auth handshake.
