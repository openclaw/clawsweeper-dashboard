## Label Justifications

- `merge-risk: 🚨 compatibility`: The PR intentionally changes precedence for existing configured-local deployments that relied on ambient credentials overriding `gateway.auth.*`.

## Summary

Keep this PR open for explicit maintainer review rather than cleanup: it consistently makes configured local Gateway credentials authoritative, and the supplied live CLI proof plus focused coverage support the fix, but the intentional upgrade change for deployments relying on ambient credential overrides still needs a maintainer-owned compatibility decision.

## What This Changes

The PR changes implicit configured-local Gateway clients so configured `gateway.auth.token` and `gateway.auth.password` take precedence over ambient Gateway credential variables, while retaining environment-first behavior for explicit URL and node-host targets.

## System Context

Gateway clients used by CLI commands, status/probe paths, pairing, and the TUI derive credentials from configuration and environment variables before connecting to the local Gateway. The Gateway server authorizes those calls using its active `gateway.auth.*` configuration, so the client and server must resolve the same effective credential.
