## What This Changes

The issue requests closing the gateway lock file handle and removing the partial lock file when payload writing fails after `fs.open(lockPath, "wx")` succeeds.

## Best Possible Solution

Land the narrow gateway-lock cleanup via https://github.com/openclaw/openclaw/pull/98848 or an equivalent fix, with proof or regression coverage for the open-success/write-failure cleanup path.

## Reproduction Assessment

Yes for source-level reproduction: make `fs.open(lockPath, "wx")` succeed and make the returned `FileHandle.writeFile` reject. Current main has no cleanup path for that opened handle before the existing `GatewayLockError` path.

## Solution Assessment

Yes, the narrow fix belongs in `acquireGatewayLock` because callers only receive a release closure after the payload write succeeds. The linked PR's approach is the right shape, but it still needs proof or focused regression coverage before merge.
