Keep open. Current main and v2026.6.11 still write short-term promotions to `MEMORY.md`; the merged compaction and contamination fixes reduce damage on that path but do not add configurable destinations, routing rules, or destination indexing semantics.

Request to make memory-core short-term promotion destinations configurable instead of always appending promoted memories to `MEMORY.md`.

## Best Possible Solution

Define one memory-core promotion routing contract with canonical lanes, safe optional path templates, destination indexing, lifecycle metadata coordination with https://github.com/openclaw/openclaw/issues/87660, and aligned schema, docs, and regression tests.

## Reproduction Assessment

Yes. Source inspection on current main and v2026.6.11 shows deep promotions still write to `workspaceDir/MEMORY.md`, and the memory-core schema has no destination or routing config.

## Solution Assessment

Unclear. A configurable target addresses the immediate report, but the June discussion makes the best solution a maintainer product decision around canonical lanes, routing rules, metadata, lifecycle, and indexing semantics.
