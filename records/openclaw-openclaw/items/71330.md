## Summary

Keep open. Current main and v2026.6.11 still hardcode deep short-term promotions to `MEMORY.md`; merged compaction mitigates growth but does not provide configurable destinations, alternate-file search semantics, or the lifecycle routing raised in discussion.

## What This Changes

Request configurable memory-core promotion destinations instead of always appending short-term promotion blocks to `MEMORY.md`.

## Best Possible Solution

Define a maintainer-approved memory-core promotion routing contract with safe default lanes, optional validated customization, date-token rules, docs/schema alignment, focused tests, and `memory_search` coverage for every supported destination.

## Solution Assessment

Unclear. A configurable target addresses the immediate report, but the best permanent fix likely needs maintainer choices about canonical lanes, routing rules, lifecycle metadata, path safety, and indexing semantics.
