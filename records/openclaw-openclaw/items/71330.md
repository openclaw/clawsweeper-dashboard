## Summary

Keep open. Current main and the latest release still route short-term memory promotions to `MEMORY.md`; merged compaction and contamination fixes reduce growth and bad content, but they do not provide configurable or structured promotion destinations.

## What This Changes

The issue requests a configurable destination for memory-core promotion writes instead of always appending promoted memories to `MEMORY.md`.

## Best Possible Solution

Define a constrained memory-core promotion routing model with a canonical default layout, safe path/template validation, search indexing guarantees, docs, and migration/doctor behavior if existing installs need repair.

## Reproduction Assessment

Yes at source level: current main still computes the promotion output path as `workspaceDir/MEMORY.md`, and the scheduled and CLI apply callers do not pass a destination option. I did not run a live promotion cycle because this review is read-only.

## Solution Assessment

Partly. A configurable target file is a plausible ingredient, but the best maintainable fix should be a constrained routing and lifecycle design rather than pure free-form customization.
