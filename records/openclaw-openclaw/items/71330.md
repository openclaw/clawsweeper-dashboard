## Summary

Keep open. Current main and v2026.6.11 still route deep short-term promotions to `MEMORY.md`; the merged compaction and contamination fixes mitigate growth and junk data but do not add configurable destinations, search/indexing semantics, or the lifecycle routing decisions raised in discussion.

## What This Changes

Requested configurable routing for memory-core short-term promotion writes so promoted memories can target a file other than `MEMORY.md`.

## Best Possible Solution

Maintainers should define one memory-core promotion routing contract, likely canonical lanes plus safe optional customization, then align schema, path validation, date templates, lifecycle metadata, docs, and `memory_search` coverage for every supported destination.

## Reproduction Assessment

Yes from source inspection: current main still writes promotion output to the fixed `workspaceDir/MEMORY.md` path, and the memory-core manifest has no destination config. I did not run a live promotion cycle because this read-only review can prove the missing routing surface from source and docs.

## Solution Assessment

Unclear. A configurable target would address the immediate report, but the best permanent fix should be a maintainer-approved routing and lifecycle contract rather than a raw free-form path knob.
