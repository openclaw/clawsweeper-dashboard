Keep open. Current main still writes memory-core deep promotions to root `MEMORY.md`; merged compaction and snippet-cap work reduce growth but do not add configurable destinations, routing rules, or the lifecycle semantics raised in the later discussion.

## What This Changes

The issue requests configurable routing for memory-core short-term promotion writes so promoted memory can target files other than root `MEMORY.md`.

## Best Possible Solution

Define one memory-core promotion routing contract, likely a canonical lane layout with optional safe customization, then implement path validation, date tokens, docs/schema alignment, and `memory_search` coverage for every supported destination.

## Reproduction Assessment

Yes. Source inspection on current main shows deep promotions still write to `workspaceDir/MEMORY.md`, and the memory-core schema has no destination or routing config.

## Solution Assessment

Unclear. A configurable target would address the immediate report, but the June discussion makes the best solution a maintainer product decision around canonical lanes, routing rules, lifecycle metadata, and indexing semantics rather than a raw free-form path knob.
