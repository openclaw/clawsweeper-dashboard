## Summary

Keep open. Current main and the latest release still write short-term promotions to `MEMORY.md`; merged compaction and snippet-cap work reduces growth, but does not add destination routing, alternate-file indexing semantics, or the lifecycle choices raised in the follow-up discussion.

## What This Changes

Request to add a configurable memory-core destination for promoted short-term memories instead of always appending them to `MEMORY.md`.

## Best Possible Solution

Define one memory-core promotion routing contract with safe workspace-relative destinations, approved date tokens or canonical lanes, deterministic indexing coverage, docs/schema/tests, and coordination with lifecycle curation before adding public config.

## Reproduction Assessment

Yes. Source inspection on current main and `v2026.6.11` shows deep promotions still write to `workspaceDir/MEMORY.md`, while the memory-core config/schema/docs expose no destination routing option.

## Solution Assessment

Unclear. A configurable target addresses the immediate report, but the best maintainable solution likely needs canonical lanes, safe path validation, indexing semantics, lifecycle metadata, and archive/dedup policy rather than an unrestricted path knob.
