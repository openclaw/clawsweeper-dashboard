## Summary

Keep open. Current main and v2026.6.11 still write short-term promotions to `MEMORY.md`; recent compaction and contamination fixes reduce growth and bad input, but they do not add configurable promotion destinations or settle the later lifecycle/routing product questions.

## What This Changes

Request to add memory-core configuration for routing promoted short-term memories to a target file other than the hardcoded `MEMORY.md`, including dated paths and search compatibility.

## Best Possible Solution

Define one memory-core promotion routing contract, likely canonical lanes with optional safe customization, then implement path validation, date tokens, docs/schema alignment, and `memory_search` coverage for every supported destination.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 still resolve the promotion output as `workspaceDir/MEMORY.md`, and the memory-core schema has no target or routing config.

## Solution Assessment

Unclear. A configurable target addresses the immediate report, but the later discussion makes the best solution a maintainer product decision around canonical lanes, routing rules, lifecycle metadata, indexing semantics, and safe path handling.
