## Summary

Keep open. Current main and v2026.6.11 still route memory-core deep promotions to `MEMORY.md`; the merged compaction and contamination fixes reduce growth and leakage but do not add configurable promotion destinations, destination indexing rules, or the lifecycle/routing decisions raised in discussion.

## What This Changes

The issue requests a memory-core configuration surface for choosing where short-term promotion output is written, including date-templated paths and searchable alternate files.

## Best Possible Solution

Define a maintainer-approved memory-core promotion routing contract, likely canonical lanes with safe optional customization, then implement validated target resolution, date-token handling, docs/schema alignment, and memory search coverage for every supported destination.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 still write deep short-term promotions to `workspaceDir/MEMORY.md`, and the memory-core schema/docs expose no promotion destination setting.

## Solution Assessment

Unclear. A configurable target addresses the immediate report, but the best durable solution likely needs maintainer choices around canonical lanes, routing rules, lifecycle metadata, safe path templates, and indexing semantics rather than an unconstrained path knob.
