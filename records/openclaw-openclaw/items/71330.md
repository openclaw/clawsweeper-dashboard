Keep open. Current main and v2026.6.11 still route memory-core short-term promotions to `MEMORY.md`; the merged compaction work limits growth but does not add configurable destinations, routing semantics, or the lifecycle policy raised in the later discussion.

## Best Possible Solution

Define a memory-core promotion routing contract with canonical lanes plus safe optional customization, then align schema, docs, path validation, date-token handling, indexing, and lifecycle metadata.
