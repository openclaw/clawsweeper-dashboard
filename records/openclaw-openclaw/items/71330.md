Keep open. Current main and the latest release still write deep short-term promotions to `MEMORY.md`; the merged compaction work reduces growth but does not add configurable routing, alternate-file indexing semantics, or the lifecycle choices called out in the later discussion.

## What This Changes

The issue requests a memory-core configuration option to route promoted short-term memories to a configurable file instead of always appending to `MEMORY.md`.

## Best Possible Solution

Maintainers should define one memory-core promotion routing contract, likely a canonical lane layout with optional safe customization, then implement path validation, date tokens, docs/schema alignment, and `memory_search` coverage for every supported destination.

## Reproduction Assessment

Yes. Source inspection on current main and `v2026.6.11` shows deep promotions still write to `workspaceDir/MEMORY.md`, and the memory-core schema has no destination or routing config.

## Solution Assessment

Unclear. A configurable target would address the immediate report, but the June discussion makes the best solution a maintainer product decision around canonical lanes, routing rules, lifecycle metadata, and indexing semantics rather than a raw free-form path knob.
