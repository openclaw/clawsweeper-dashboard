## Summary

Keep open. Current main and latest release still write deep short-term promotions to `MEMORY.md`; merged compaction and contamination fixes reduce growth and pollution, but they do not add configurable promotion destinations, destination indexing semantics, or the lifecycle routing choices raised in the later discussion.

## What This Changes

The issue requests configurable routing for memory-core short-term promotion output instead of always writing promoted memories into `MEMORY.md`.

## Best Possible Solution

Define one memory-core promotion routing contract, likely a canonical lane layout with safe optional customization, then implement destination validation, date templates, docs/schema alignment, and `memory_search` coverage for every supported destination.

## Reproduction Assessment

Yes. Source inspection on current main and `v2026.6.11` shows deep promotions still write to `workspaceDir/MEMORY.md`, and the memory-core schema has no destination or routing config.

## Solution Assessment

Unclear. A configurable target solves the immediate report, but the maintainable fix needs a product decision about canonical lanes, safe path templating, lifecycle metadata, dedup, and indexing semantics rather than a raw free-form path alone.
