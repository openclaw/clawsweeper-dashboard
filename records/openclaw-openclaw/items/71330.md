## Summary

Keep open. Current main and the latest release still write memory-core deep promotions to `MEMORY.md`; merged compaction and contamination fixes reduce damage but do not add configurable destinations, safe routing rules, or the lifecycle semantics raised in the discussion.

## What This Changes

Request configurable memory-core promotion destinations so automated short-term promotions can write outside root `MEMORY.md`.

## Best Possible Solution

Define one memory-core promotion routing contract, likely a canonical lane layout with optional safe customization, then implement path validation, date tokens, docs/schema alignment, and `memory_search` coverage for every supported destination.

## Reproduction Assessment

Yes. Source inspection on current main and `v2026.6.11` shows deep promotions still write to `workspaceDir/MEMORY.md`, and the memory-core schema has no destination or routing config.

## Solution Assessment

Unclear. A configurable target addresses the immediate report, but the better maintainable solution likely needs maintainer-approved canonical lanes, safe customization, routing metadata, lifecycle controls, and indexing semantics rather than a raw free-form path knob.
