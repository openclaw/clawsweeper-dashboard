Keep open: current main and the latest release still provide avatar display, identity update plumbing, and a browser-local Quick Settings override, but they do not provide the requested persistent Agents-tab avatar upload path. The remaining work adds an admin image upload and workspace-write boundary, so it needs maintainer product and security direction before a repair PR.

## What This Changes

Request a Control UI Agents-tab picker that stores a selected avatar image in the agent workspace, updates `IDENTITY.md`, and serves it through the avatar route.

## Best Possible Solution

Implement persistent per-agent avatar upload only after maintainers approve the boundary: strict operator-admin authorization, bounded image validation, safe workspace-relative storage, `IDENTITY.md` update, avatar route refresh, and focused Control UI/Gateway tests.
