## Summary

Keep open: current main and the latest release still allow transcript header creation to fall back to ambient `process.cwd()` when no explicit cwd is supplied, and the linked closing PR remains open and conflicting rather than merged.

## What This Changes

The issue reports that mirrored session transcript headers can record the wrong workspace because header creation can read ambient `process.cwd()` instead of the target agent workspace.

## Best Possible Solution

Land, rebase, or replace https://github.com/openclaw/openclaw/pull/50454 with a current-main patch that passes the explicit target workspace into transcript header creation while keeping broader `process.chdir()` cleanup separate.

## Reproduction Assessment

Yes. By source inspection, create a stored session entry without `spawnedCwd`, run `appendAssistantMessageToSessionTranscript()` while ambient cwd differs from the target workspace, and header creation can reach `process.cwd()`.

## Solution Assessment

Yes. Passing an explicit target workspace into header creation is the narrow maintainable fix for this path; removing all process-global cwd usage is broader follow-up work.
