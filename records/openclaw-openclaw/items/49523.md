## Summary

Keep open: current main and the latest release still allow mirrored transcript header creation to fall back to ambient `process.cwd()` when the session entry lacks an explicit `spawnedCwd`, and the linked closing PR is still open rather than merged.

## What This Changes

The issue reports that transcript mirror header creation records `cwd` from ambient `process.cwd()` instead of the target agent workspace, allowing cross-agent workspace contamination.

## Best Possible Solution

Rebase, review, and land or replace https://github.com/openclaw/openclaw/pull/50454 with a current-main fix that passes explicit target workspace cwd into transcript header creation while keeping broader `process.cwd()` cleanup separate.

## Reproduction Assessment

Yes. By source inspection, create a stored session entry without `spawnedCwd`, run `appendAssistantMessageToSessionTranscript()` while ambient cwd differs from the target workspace, and header creation reaches `process.cwd()`.

## Solution Assessment

Yes. Passing an explicit target workspace into header creation is the narrow maintainable fix for this path; removing all process-global cwd usage is broader follow-up work.
