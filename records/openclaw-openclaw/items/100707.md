## Summary

The issue is still necessary: current main and the latest release still make `patch.payload.fallbacks` a non-null array in the cron agent tool schema even though the Gateway types and service merge path already support null clears. An open linked PR exists, but it has not merged and its current diff targets config-schema tests rather than the cron tool schema path.

## What This Changes

The issue asks for `cron update` tool-schema validation to accept `payload.model: null` and `payload.fallbacks: null` so existing cron jobs can clear per-job overrides and inherit defaults.

## Best Possible Solution

Land a narrow cron-tool-schema fix that makes patch-only `payload.model` and `payload.fallbacks` nullable, with regression coverage proving the model-facing tool schema and runtime `Value.Check` accept the clear-to-inherit patch.
