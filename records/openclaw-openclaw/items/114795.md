## What This Changes

Make authenticated ClickClack discussion iframes render with the surrounding Control UI theme from first paint and update live when the host theme changes.

## System Context

Control UI stores browser-local appearance preferences and sends resolved theme tokens to embedded content. ClickClack discussion sidebars are cross-origin iframes, so the host must safely convey initial appearance and later theme changes without mutating ClickClack’s standalone account preference.

## Architecture Diagram

flowchart LR
  A[Control UI appearance] --> B[Resolved theme tokens]
  B --> C[Discussion embed URL]
  B --> D[Theme update message]
  C --> E[ClickClack iframe first paint]
  D --> F[Origin and parent validation]
  F --> G[Live iframe theme update]
  E --> H[Themed discussion sidebar]
  G --> H

## Best Possible Solution

Land a coordinated OpenClaw and ClickClack embed contract that passes only the resolved host appearance needed for first paint, validates the expected parent origin and window for live token updates, avoids iframe reloads, and never persists host appearance into the standalone ClickClack account.
