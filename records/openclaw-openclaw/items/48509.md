## Summary

Keep open: current main still has generic plugin hook dispatch plus adjacent tool-call, message, transcript, session, and cron/polling hook surfaces, but I did not find a dedicated pre-write Plugin SDK hook for durable persistence writes across memory, file, cron, config, or preference state. This remains a coherent public Plugin SDK and security-boundary design request rather than cleanup material.

## What This Changes

The issue requests a new `before_persistence_write` Plugin SDK hook that can observe or block durable state writes such as memory, files, cron jobs, config, and preferences before they cross session boundaries.

## Best Possible Solution

Design one canonical Plugin SDK persistence-write event with explicit owner boundaries, dispatch ordering, blocking semantics, and regression coverage for representative memory/file/cron/config or preference write paths before exposing it as public API.
