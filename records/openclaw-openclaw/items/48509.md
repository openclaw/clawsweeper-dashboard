## Best Possible Solution

Settle one minimal public durable-write policy contract with redacted payloads, explicit block/mutate/failure semantics, docs, and representative writer coverage.

Options:

- **Design a dedicated durable-write hook (recommended):** Add a narrow additive hook with redacted targets, explicit block or mutation rules, bounded failure policy, docs, and coverage across representative writer paths.
- **Fold durable context into existing hooks:** Extend `before_tool_call` and provenance APIs instead of adding a hook family, reducing hook count but requiring broader taxonomy work first.
- **Defer to persistent provenance design:** Keep this as a dependency of the broader provenance and read-time trust model before implementing a write-only seam.
