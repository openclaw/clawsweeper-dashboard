## Summary

Keep open: current main and the latest release still expose only generic tool, transcript/message, session, and cron lifecycle hook surfaces; there is no dedicated pre-write durable-state hook, and the remaining work is a public Plugin SDK plus security-boundary design decision.

## What This Changes

Request to add a plugin `before_persistence_write` hook before durable state changes such as memory, file, cron, config, and preference writes.

## Best Possible Solution

Define one additive, documented durable-write contract with minimized/redacted payloads, explicit block-versus-mutate and timeout/failure semantics, and focused coverage across representative memory, file, cron, config, and preference write paths.

## Reproduction Assessment

Yes, at source level: current hook names, event payloads, runner dispatch, docs, and latest-release code lack `before_persistence_write` or an equivalent durable-write hook.

## Solution Assessment

Unclear pending maintainer design: a dedicated hook is plausible, but maintainers still need to choose taxonomy, block versus mutation semantics, redaction, failure policy, and relation to provenance/read hooks.
