## Summary

Keep open: current main and the latest release still expose adjacent tool, transcript-message, session, and cron hooks, but not the requested durable-state pre-write hook for memory, file, cron, config, or preference writes. The request is coherent and vision-aligned, but it needs maintainer/security design review before implementation because it would define a public Plugin SDK security boundary over persisted state.

## What This Changes

The issue requests a new Plugin SDK hook that fires before durable persistence writes such as memory, file, cron, config, and preference changes.

## Best Possible Solution

Adopt one additive durable-write Plugin SDK contract only after design review, with minimal redacted payloads, explicit block or mutation semantics, deterministic ordering, bounded failure behavior, docs, and coverage across representative memory, file, cron, config, and preference writer paths.
