## Summary

Keep open: current main and the latest release still expose adjacent tool, message, transcript, session, and cron hooks, but no dedicated pre-write durable-state hook for memory, file, cron, config, or preference writes. This remains a coherent Plugin SDK/security design item, and related cleanup now treats this issue as the canonical durable persistence hook thread.

## What This Changes

Add an additive Plugin SDK `before_persistence_write` hook before durable state writes such as memory, files, cron jobs, config, and preferences.

## Best Possible Solution

Define one additive durable-write Plugin SDK contract with minimal redacted payloads, block/mutate semantics, ordering after before_tool_call, and bounded failure behavior before adding writer coverage.

## Reproduction Assessment

Yes, at source level: current hook names, event types, runner dispatch, docs, representative durable write paths, and v2026.6.11 lack before_persistence_write or an equivalent durable-write hook.

## Solution Assessment

Unclear pending maintainer design: a dedicated hook is plausible, but maintainers still need to choose taxonomy, block versus mutate semantics, redaction, failure policy, and relation to provenance/read hooks.
