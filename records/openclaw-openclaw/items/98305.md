## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P2] Advance reply fanout for normalized subchunks:** `extensions/feishu/src/outbound.ts:358`
  - body: `sendTextMediaPayload` resolves reply fanout once for each adapter send because implicit replies may be single-use. This new inner loop can turn that one adapter send into several Feishu sends after newline expansion, but every subchunk reuses the same `replyToMessageId`, so expanded chunks can repeatedly target the same reply instead of consuming fanout per platform send. Pass a fresh or intentionally omitted reply target for later subchunks, or move the final chunking before the SDK fanout boundary.
  - confidence: 0.84
- **[P2] Avoid re-normalizing already normalized chunks:** `extensions/feishu/src/send.ts:573`
  - body: Late discovery: this was already visible at the previous reviewed head because `send.ts` did not change in the latest follow-up. The outbound/reply paths normalize the full text before measuring chunks, but every chunk still goes through this payload builder and gets normalized again; if a chunk boundary lands inside a fenced code block, the later chunk starts without the opening fence and code newlines can be expanded as paragraphs, potentially corrupting code formatting or growing past the measured limit. Carry an `alreadyNormalized` state or make normalization single-pass before the final post payload is built.
  - late: true
  - confidence: 0.78
