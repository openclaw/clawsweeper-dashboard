## Summary

Keep open: current main and v2026.6.11 still ignore routing fields for mapped wake hooks, and the open linked PR is the unmerged fix candidate.

## What This Changes

Wake-mode hook mappings should honor configured agentId/sessionKey instead of silently queuing all wake events into main.

## Best Possible Solution

Review, rebase/prove, and land the linked targeted-wake PR or a narrow equivalent that threads wake mapping routing through existing hook session/agent policy.

## Maintainer Decision

## Reproduction Assessment

Yes from source inspection: mapped wake actions carry only text/mode into dispatchWakeHook, and that dispatcher always resolves the main session. I did not run a live gateway repro because this review is read-only.

## Solution Assessment

Yes, the best fix is to make the existing mapping fields work by threading wake routing through the same hook session/agent policy path used by agent hooks. Removing the fields or adding a separate routing mechanism would be less maintainable.
