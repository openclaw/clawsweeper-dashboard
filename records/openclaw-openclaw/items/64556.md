## Summary

Keep open: current main and v2026.6.11 still drop mapped wake hook `agentId`/`sessionKey` before dispatch, and the linked fixing PR remains open and conflicting rather than merged.

## What This Changes

The issue asks for `hooks.mappings[]` with `action: "wake"` to honor configured `agentId` and `sessionKey` instead of silently routing every wake to the default main session.

## Best Possible Solution

Rebase, prove, document, and land https://github.com/openclaw/openclaw/pull/70268, or replace it with a narrow equivalent that threads mapped wake routing through the existing hook agent/session policy helpers.

Yes. Source inspection on current main shows mapped wake actions pass only `text` and `mode` to a dispatcher that always enqueues to the main session; I did not run a live gateway repro in this read-only review.

## Solution Assessment

Yes. Threading mapped wake routing through the existing hook session/agent policy path is the narrow maintainable fix; removing accepted config fields or adding a separate routing mechanism would be less consistent.
