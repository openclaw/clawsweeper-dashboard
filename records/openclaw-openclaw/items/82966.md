## Summary

Keep open: the PR is still paired with the active canonical bug report, but its global change to a helper whose contract is “fresh tokens only” is unsafe; current main already uses a separate stale-display path for the Control UI. The branch needs a rebase, a narrow presentation-only design if `/context` should expose approximate totals, and patched-run proof before it can be reconsidered.

## What This Changes

The branch makes `resolveFreshSessionTotalTokens` return preserved stale totals, then adds selected freshness guards so status, context reporting, Gateway rows, memory flush, and session forks handle those totals differently.

## Best Possible Solution

Keep `resolveFreshSessionTotalTokens` fresh-only and, if maintainers want `/context` to expose stale estimates, add an explicit presentation value plus freshness state that renders as approximate while retaining fresh-only decision gates.
