Keep open: current main and v2026.6.11 still do not expose the requested model-facing Browser Network/interception action. Existing code has passive request listing and bounded response-body capture below the tool surface, but active request interception remains a security-sensitive product/API design decision.

## What This Changes

The issue requests model-facing browser-tool access to CDP Network capabilities for request interception and captured request inspection.

## Best Possible Solution

Design this inside the browser plugin as a network inspection/interception capability with explicit security, redaction, permission, and profile-support rules before exposing it to agents.

## Reproduction Assessment

Yes. Source inspection of the current browser tool schema and dispatcher shows the proposed model-facing Network action shape is not exposed on current main, while lower routes only cover passive request listing and bounded response-body capture.

## Solution Assessment

No, not as the raw proposed `browser act kind=network` shape yet. The best fix should reuse existing browser-plugin request/response infrastructure but add a maintainer-designed security boundary before exposing it to agents.
