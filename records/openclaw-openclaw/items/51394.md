## Summary

Keep open: current main and v2026.6.11 still lack a model-facing browser action for CDP Network request capture or interception. Existing code exposes lower-level passive request listing and bounded response-body capture, but the requested security-sensitive tool/API surface still needs maintainer product and security design.

## What This Changes

Request to expose CDP Network-domain request capture and interception through the browser tool so agents can inspect SPA network traffic beyond fetch monkey-patching.

## Best Possible Solution

Design this as a browser-plugin network inspection capability with an explicit sensitive-data policy, profile capability matrix, permission/redaction rules, model-safe output wrapping, and reuse of the existing /requests and /response/body paths where they fit.

## Reproduction Assessment

Yes. Source inspection reproduces the gap: the model-facing browser tool schema and act-kind union do not expose network, requests, responsebody, or intercept actions, while lower control routes only expose passive request listing and bounded response-body capture.

## Solution Assessment

No, not as proposed yet. A raw browser act kind=network surface should wait for a maintainer-designed security boundary and profile capability matrix rather than directly exposing CDP Network interception to agents.
