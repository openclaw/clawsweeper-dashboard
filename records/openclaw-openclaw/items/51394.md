## Summary

Keep open: current main and v2026.6.11 still lack a model-facing browser action for CDP Network request interception, while existing browser control and CLI paths only expose passive request listing and bounded response-body capture. This remains a new security-sensitive browser capability that needs maintainer product and security design before implementation.

## What This Changes

The issue requests a browser automation API that exposes CDP Network-domain capabilities for request interception, request listing, and SPA endpoint discovery.

## Best Possible Solution

Design this as a browser-plugin network inspection capability with explicit sensitive-data policy, profile capability matrix, permission/redaction rules, model-facing output wrapping, and reuse of the existing /requests and /response/body paths where they fit.

## Reproduction Assessment

Yes. Source inspection reproduces the gap on current main and v2026.6.11: the browser tool schema and dispatcher do not expose network/intercept actions, while lower passive routes exist.

## Solution Assessment

No, not as proposed yet. A raw browser network action should wait for a maintainer-designed security boundary and profile capability matrix rather than directly exposing CDP Network interception to agents.
