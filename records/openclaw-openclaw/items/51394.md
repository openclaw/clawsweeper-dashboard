## Summary

Keep open: current main and latest release still do not expose a model-facing browser Network/CDP interception action. The browser control layer has passive request listing and bounded response-body helpers, but promoting that to model-facing inspection/interception remains a security-sensitive product decision.

## What This Changes

The issue requests a model-facing browser Network/CDP API for capturing, listing, and intercepting browser requests during automation.

## Best Possible Solution

Define this inside the browser plugin as an explicit network diagnostics capability, starting with redacted passive request listing and bounded response-body access, and gate any active interception or mutation behind maintainer-approved security policy and profile support.
