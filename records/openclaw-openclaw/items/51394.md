## Summary

Keep open: current main and v2026.6.11 still lack a model-facing browser Network/CDP interception action. Existing lower-level `/requests`, `responsebody`, and related closed Chrome-relay issues cover passive request inspection or obsolete relay paths, not the full agent-tool request/intercept capability requested here.

## What This Changes

The issue requests model-facing browser-tool access to CDP Network capabilities for request capture and interception during browser automation.

## Best Possible Solution

Design this as a browser-plugin network-inspection capability with explicit sensitive-data policy, redaction, permissions, profile support matrix, and wrapped model-facing output, reusing `/requests` and `/response/body` only where they fit safely.

## Reproduction Assessment

Yes for the requested capability gap, by source inspection rather than a runtime bug repro. Current main and v2026.6.11 lack the model-facing network/intercept browser action while lower control routes expose only passive request listing and bounded response-body capture.

## Solution Assessment

No, not as the proposed raw `browser act kind=network` shape yet. The safer path is a maintainer-designed browser plugin/tool contract with explicit redaction, permissions, profile support, and security review before exposing traffic data to models.
