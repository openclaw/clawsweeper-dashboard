Design this in the browser plugin as an explicit network inspection/interception capability with redaction, permission gates, profile capability limits, safe output wrapping, docs, and tests that reuse existing /requests and /response/body paths where appropriate.

## Risks / Open Questions

- A model-facing interception surface can expose cookies, authorization headers, tokens, private API endpoints, request bodies, and response bodies unless redaction, permissions, profile restrictions, and output wrapping are designed first.
- Active request interception or mutation is stronger than the existing passive request list and bounded response-body route, so it changes the browser tool security boundary.
- Managed, raw/remote CDP, sandbox, node-hosted, and existing-session profiles may need different support levels; a single action shape could overexpose data or fail inconsistently.
