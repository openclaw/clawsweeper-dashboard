## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.91

Full review comments:

- **[P2] Do not protect the resolved sandbox cwd itself:** `src/agents/bash-tools.exec.ts:1797`
  - body: Adding `containerWorkdir` to the protected roots means a sandbox exec whose resolved cwd is the repo can reject ordinary pathless `rg` in that repo. Keep sandbox roots protected, but do not mark the resolved current cwd itself as protected.
  - confidence: 0.9
- **[P2] Parse BSD find roots before predicates:** `src/infra/exec-control-command-guard.ts:1640`
  - body: `find -E ~/.codex/sessions -regex ...` is valid on macOS/BSD, but this scanner stops at `-E` and falls back to `.`. From a safe repo cwd that lets the protected-root search bypass the guard.
  - confidence: 0.9
- **[P2] Use the pre-assignment env for shell path expansion:** `src/infra/exec-control-command-guard.ts:1407`
  - body: For `HOME=/tmp rg token ~/.codex`, the shell expands `~` before applying the temporary assignment to the command environment. Resolving with `assignmentAdjusted.env` can move the search under `/tmp` and allow the original protected-home search.
  - confidence: 0.88
- **[P2] Substitute wrapper positional args before scanning:** `src/infra/exec-control-command-guard.ts:725`
  - body: For `bash -lc 'rg token "$@"' sh ~/.codex/sessions`, the protected path is supplied through `$@`. Analyzing the literal payload separately misses the static protected-root `rg`.
  - confidence: 0.88
- **[P2] Split heredoc bodies into shell statements:** `src/infra/exec-control-command-guard.ts:1057`
  - body: A heredoc script with `cd ~/.codex/sessions` followed by `rg token` is parsed as one argv starting with `cd`, so the later search is never inspected. Split and process the heredoc body like shell statements.
  - confidence: 0.88
- **[P2] Keep function cwd changes conditional:** `src/infra/exec-control-command-guard.ts:1463`
  - body: A function call behind short-circuit, pipeline, or background execution may not update the real shell cwd. Applying `functionWorkdir` unconditionally can make a later protected-root pathless `rg` look safe.
  - confidence: 0.9
- **[P2] Handle bare cd inside shell functions:** `src/infra/exec-control-command-guard.ts:952`
  - body: A shell function can move to home with a bare `cd`, but this regex only recognizes `cd` or `pushd` with an argument. That can leave the analyzer in a safe cwd while the real shell moved to a protected home directory.
  - confidence: 0.87
- **[P2] Track cwd inside command substitutions:** `src/infra/exec-control-command-guard.ts:318`
  - body: Commands inside `$()` run in their own shell, so `echo $(cd ~/.codex/sessions; rg token)` should analyze the inner `rg` from the updated protected cwd. The current tracking only covers top-level and wrapper-payload contexts.
  - confidence: 0.84
- **[P2] Inspect invoked shell function bodies for searches:** `src/infra/exec-control-command-guard.ts:1401`
  - body: The guard skips function definitions and does not replay the body when the function is invoked. A static `f(){ rg token ~/.codex/sessions; }; f` therefore runs a protected-root search that the guard never sees.
  - confidence: 0.9
- **[P2] Treat unresolved simple variables as dynamic paths:** `src/infra/exec-control-command-guard.ts:1728`
  - body: If a loop assigns a protected path to a shell-local variable and later runs `rg token "$d"`, unresolved `$d` is resolved under the safe cwd instead of failing closed as a dynamic shell-expanded search path.
  - confidence: 0.86
- **[P2] Split nested payloads on control operators:** `src/infra/exec-control-command-guard.ts:893`
  - body: Static nested payloads from `eval`, `xargs sh -c`, or `find -exec sh -c` are split only on semicolons and newlines. A payload using `&&` can hide the later protected-root `rg`.
  - confidence: 0.88
- **[P2] Inspect here-string shell stdin payloads:** `src/infra/exec-control-command-guard.ts:1054`
  - body: A shell invoked with `<<< 'rg token ~/.codex/sessions'` reads that inline text as its script, but the collector only recognizes heredoc forms, so this static protected-root search can run unguarded.
  - confidence: 0.86
