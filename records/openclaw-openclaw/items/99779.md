## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P2] Consume ripgrep's short replace operand:** `src/infra/exec-control-command-guard.ts:153-197`
  - body: `RG_OPTION_ARGS_WITH_VALUES` includes `--replace` but not its `-r` alias. For `rg -r repl token` from a protected home directory, ripgrep consumes `repl` as the replacement and searches `.` for pattern `token`, while this parser treats `token` as a narrowed path and allows the broad protected-root search.
  - confidence: 0.93
- **[P2] Parse clustered ripgrep short options:** `src/infra/exec-control-command-guard.ts:1689-1694`
  - body: `collectNonOptionArgs` only consumes a value for a short option when the token length is exactly two. Ripgrep accepts clusters such as `-nE utf-8`, so `rg -nE utf-8 token` from a protected cwd consumes `utf-8` as the encoding and searches `.`, but the guard treats `token` as a path and lets it through.
  - confidence: 0.91
- **[P2] Expand braced variables before suffixes:** `src/infra/exec-control-command-guard.ts:1937-1939`
  - body: `expandShellVariables` only substitutes variables followed by a slash or end of string. A resolved env value like `SESSION_ROOT=$HOME/.codex/sessions` used as `${SESSION_ROOT}_backup` remains a literal safe-cwd path to the guard, even though the shell expands it into a protected `.codex` child.
  - confidence: 0.9
- **[P2] Substitute xargs replacement placeholders:** `src/infra/exec-control-command-guard.ts:1236-1239`
  - body: For `xargs -I{}`, replacement happens inside the initial command args, not only by appending a final dynamic path. This path appends a sentinel but leaves `{}` in shell wrapper positionals, so `sh -c 'rg token "$1"' sh {}` can be analyzed as a safe literal search while xargs supplies the protected root at runtime.
  - confidence: 0.88
- **[P2] Split static shell payload pipelines:** `src/infra/exec-control-command-guard.ts:988-1000`
  - body: Static payload splitting still ignores a top-level single `|`. A payload like `eval 'cat /dev/null | rg token ~/.codex/sessions'` is analyzed as one `cat` argv, so the protected-root `rg` command after the pipe is never inspected.
  - confidence: 0.9
- **[P2] Fail closed on alias-expanded payloads:** `src/infra/exec-control-command-guard.ts:1552-1561`
  - body: Static shell payload analysis never accounts for alias definitions and invocations. With alias expansion enabled, `alias r="rg token ~/.codex/sessions"; r` executes the hidden protected-root search, but the guard only sees the literal alias setup and `r` token.
  - confidence: 0.84
- **[P2] Track popd after pushd directory changes:** `src/infra/exec-control-command-guard.ts:408-424`
  - body: The resolver models `pushd` as a cwd change but does not model `popd`. In a shell starting from a protected cwd, `pushd /tmp; popd; rg token` searches the protected cwd again, while the guard continues analyzing the later pathless `rg` from `/tmp`.
  - confidence: 0.87
- **[P2] Fail closed on variable-backed eval payloads:** `src/infra/exec-control-command-guard.ts:930-934`
  - body: `eval` combines its arguments and executes the result, but this branch only joins the literal argv. A command like `cmd='rg token ~/.codex/sessions'; eval "$cmd"` is parsed as the harmless command `$cmd`, so the broad protected-root search is never rejected.
  - confidence: 0.86
