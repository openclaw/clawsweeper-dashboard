## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P2] Include env state in payload de-dupe:** `src/infra/exec-control-command-guard.ts:267`
  - body: `commandPayloadKey` ignores `payload.env`, so two identical argv payloads after different shell-local assignments collapse into one analysis result. A command can first search a safe `$SESSION_ROOT`, then reassign it to `$HOME/.codex/sessions` and repeat the same `rg`, causing the protected second search to be skipped by de-dupe.
  - confidence: 0.88
- **[P2] Discard prepared workdirs on blocked searches:** `src/agents/bash-tools.exec.ts:1804`
  - body: The broad-search rejection can throw after `discardPreparedSandboxWorkdir` is set but before the `try`/`catch` that invokes it starts. For SSH backend workdir validation, that can leave `refreshedSkillsForNextExecWorkdir` stale and make the next exec skip refreshing materialized skills.
  - confidence: 0.9
- **[P2] Treat unresolved cd targets as unknown cwd:** `src/infra/exec-control-command-guard.ts:407`
  - body: When `resolveCdWorkdir` cannot realpath an expanded destination such as `~root`, later pathless searches keep the previous safe cwd even though the real shell may have changed into another home directory. Unresolved `cd` destinations should fail closed to an unknown/protected cwd instead of preserving the old one.
  - confidence: 0.83
- **[P2] Skip env operands before applying -C:** `src/infra/exec-control-command-guard.ts:431`
  - body: `resolveEnvChdirWorkdir` stops at any non-option token, so `env -u FOO -C "$HOME" rg token` treats `FOO` as the command and never honors the later `-C`. GNU `env -u/--unset` consumes an operand, so this can analyze a pathless search from the old cwd while the real command runs from HOME.
  - confidence: 0.86
- **[P2] Track command and builtin cd wrappers:** `src/infra/exec-control-command-guard.ts:355`
  - body: The cwd tracker only recognizes direct `cd`/`pushd`, but shells also change cwd for `command cd` and `builtin cd`. A static sequence such as `command cd; rg token` can therefore run from HOME while the guard still analyzes the later search from the previous safe directory.
  - confidence: 0.82
- **[P2] Keep conditional cd conditional in script payloads:** `src/infra/exec-control-command-guard.ts:1056`
  - body: In collected script payloads from `eval`, heredocs, and here-strings, `splitTopLevelShellStatements` splits on `&&`/`||`, but this loop then applies any `cd` it sees unconditionally. `false && cd /tmp; rg token` from HOME can be analyzed from `/tmp` even though the shell remains in HOME.
  - confidence: 0.87
- **[P2] Preserve offsets after trimming shell source:** `src/infra/exec-control-command-guard.ts:1417`
  - body: `explainShellCommand(rawCommand.trim())` returns spans for the trimmed source, but the later checks use those spans against `rawCommand`. Leading whitespace can shift conditional/operator detection, letting a skipped `cd` update the tracked cwd and allowing the following pathless search.
  - confidence: 0.84
