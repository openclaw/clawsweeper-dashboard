## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P2] Consume ripgrep's short replace operand:** `src/infra/exec-control-command-guard.ts:189`
  - body: `rg -r repl token` consumes `repl` as the replacement and searches `.` for pattern `token`, but the value-option table only includes `--replace`. From a protected cwd this treats `token` as a narrowed path and lets the broad search run.
  - confidence: 0.9
- **[P2] Parse clustered ripgrep short options:** `src/infra/exec-control-command-guard.ts:1689-1693`
  - body: The non-option parser only consumes a value for exact two-character short options. Ripgrep accepts clusters such as `-nE utf-8`, so this can leave the encoding and pattern as positional args and miss the pathless protected-root search.
  - confidence: 0.88
- **[P2] Expand braced variables before path suffixes:** `src/infra/exec-control-command-guard.ts:1937-1939`
  - body: Shell variables can expand into protected paths even when followed by a suffix, such as `${SESSION_ROOT}_backup`. This regex only substitutes variables before slash or end-of-string, so the guard can resolve the operand under the safe cwd instead of the protected env path.
  - confidence: 0.86
- **[P2] Substitute xargs replacement placeholders:** `src/infra/exec-control-command-guard.ts:1236-1246`
  - body: With `xargs -I{}`, replacement happens inside the initial command arguments, including shell wrapper positional args. Appending only a dynamic sentinel leaves `{}` literal in the nested wrapper analysis, so a protected path supplied by xargs can be missed.
  - confidence: 0.86
- **[P2] Split static shell payload pipelines:** `src/infra/exec-control-command-guard.ts:988-991`
  - body: Static shell payloads can run protected searches after a pipe, but this splitter only separates semicolons, newlines, and `&&`/`||`. A payload like `cat /dev/null | rg token ~/.codex/sessions` is analyzed as `cat` and the `rg` command is skipped.
  - confidence: 0.87
- **[P2] Fail closed on alias-expanded payloads:** `src/infra/exec-control-command-guard.ts:1541-1542`
  - body: When alias expansion is enabled, a later alias invocation can expand to a protected-root search. The analyzer replays shell functions but not aliases, so static alias payloads can hide the actual `rg` command from the guard.
  - confidence: 0.8
- **[P2] Track popd directory-stack changes:** `src/infra/exec-control-command-guard.ts:355-358`
  - body: A bare `popd` changes to the new top directory by default. Because the guard models `pushd` as a cwd change but ignores `popd`, `pushd /tmp; popd; rg token` from a protected cwd can be analyzed from `/tmp` while the real shell searches the protected cwd.
  - confidence: 0.84
- **[P2] Fail closed on dynamic eval payloads:** `src/infra/exec-control-command-guard.ts:930-933`
  - body: `eval` executes the command formed from its arguments. A variable-backed payload such as `cmd='rg token ~/.codex/sessions'; eval "$cmd"` is parsed as a harmless `$cmd` command here, so dynamic eval can bypass the protected-root search guard.
  - confidence: 0.84
- **[P2] Follow npm exec command payloads:** `src/infra/exec-control-command-guard.ts:1269-1270`
  - body: `npm exec -c '<cmd>'` executes the supplied command string, but the static wrapper resolver only unwraps a few process wrappers and leaves package-runner payloads as `npm`. Protected-root searches hidden behind that supported runner form are not inspected.
  - confidence: 0.82
