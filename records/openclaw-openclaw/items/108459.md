- `P0`: A routine Control UI update left a non-technical user without a working gateway for about 40 minutes and recovery required manual service and migration intervention.
- `impact:crash-loop`: The gateway repeatedly failed startup readiness while the LaunchAgent remained active and the runtime stayed stopped.

## Summary

Keep this issue open: current main has migration-convergence fixes for two reported conflict classes, but `update.run` still starts a managed handoff without an observable single-flight guard, so the central concurrent-update failure remains actionable.

## What This Changes

Prevent concurrent managed updates and legacy-state migration conflicts from leaving the macOS gateway stopped after an update.

## Best Possible Solution

Make managed update initiation atomic at the gateway/handoff owner boundary, have duplicate requests join or receive the existing update status, retain convergent migration behavior, and prove that success and failure both restore the previously managed gateway without manual recovery.
