## Summary

Keep this PR open, but do not merge its current implementation: it bypasses the existing incomplete-turn safety decision before choosing the new auth text, so an auth reason can force a terminal warning in outcomes the established helper intentionally suppresses or qualifies. The requested auth guidance is useful, and the narrow repair is to preserve the current terminal-state and delivery-safety gates before adding the more specific message.

## What This Changes

This PR replaces the generic incomplete-turn warning with provider/model-specific authentication advice when terminal resolution receives an `auth` or `auth_permanent` assistant-profile failure reason.

## System Context

The embedded-agent runner converts an assistant attempt's terminal state into user-visible channel text. Terminal resolution receives the selected provider, model, failure reason, delivery state, and attempt outcome, then uses incomplete-turn safeguards to decide whether a warning is safe to send.
