## Summary

Keep open: current main still has before_tool_call blocking/approval, subagent spawning, sandbox requirements, and completion metadata, but not a plugin-returned quarantine directive with constrained execution and standardized trust/provenance metadata. This remains a Plugin SDK/runtime security-boundary design item rather than conservative cleanup.

## What This Changes

The issue requests a Plugin SDK/runtime API that lets plugins request isolated quarantined execution for untrusted tool work and receive results with trust/provenance metadata.

## Best Possible Solution

Design an additive Plugin SDK/runtime isolation contract that reuses sessions_spawn, sandbox, tool-policy, session, and provenance primitives with explicit enforceable guarantees before exposing it to plugins.
