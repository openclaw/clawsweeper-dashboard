## Summary

Keep open: current main and v2026.6.11 still expose before_tool_call blocking, approval, and param rewriting plus subagent sandbox primitives, but not a plugin-returned isolation directive with constrained execution and provenance/trust metadata. This remains a public Plugin SDK/runtime security-boundary design item rather than conservative cleanup.

## What This Changes

Request an additive plugin hook or before_tool_call result that can ask the runtime to run untrusted work in an isolated, constrained session and return provenance/trust metadata.

## Best Possible Solution

Design an additive Plugin SDK/runtime isolation contract that reuses sessions_spawn, sandbox, tool-policy, session, and provenance primitives with explicit enforceable guarantees before exposing it to plugins.

## Reproduction Assessment

Not applicable: this is a feature/API design proposal rather than a broken existing behavior report. Source inspection gives high confidence that the requested hook result shape and trust metadata contract are absent on current main and v2026.6.11.

## Solution Assessment

Unclear as an implementation path: the direction fits OpenClaw's security and plugin-extension goals, but maintainers still need to choose the API shape, enforcement model, and trust metadata contract. The safest path is to reuse existing sessions_spawn, sandbox, tool-policy, and provenance primitives rather than adding a parallel isolation stack.
