## Summary

Keep open: current main and the latest release still only let `before_tool_call` rewrite, block, or request approval, while `sessions_spawn` has adjacent isolated/sandboxed child-run primitives but no plugin-returned quarantine directive or standardized trust metadata.

## What This Changes

Request a Plugin SDK/runtime capability for plugins to ask that untrusted work run in an isolated constrained session and return provenance/trust metadata.

## Best Possible Solution

Design an additive Plugin SDK/runtime isolation contract that reuses `sessions_spawn`, sandbox, tool-policy, session, and provenance primitives with explicit enforceable guarantees before exposing it to plugins.

## Maintainer Decision

Question: Should OpenClaw expose plugin-requestable quarantined execution as a public Plugin SDK/runtime contract, and what concrete isolation and trust-metadata guarantees should it make?

Rationale: The missing behavior is real, but the permanent API shape would define a security boundary and public Plugin SDK expectations that automation should not choose.

Likely owner: steipete

Owner confidence: high

Options:

- **Keep As Design Item (recommended):** Keep this issue open until maintainers define isolation semantics, trust metadata, prerequisite hook context, failure behavior, and compatibility expectations.
- **Narrow To Existing Primitives:** Defer the hook directive and document current `sessions_spawn` sandbox patterns as the supported workaround for trusted operators.
- **Close As Out Of Scope:** Reject plugin-requestable trust-boundary execution if maintainers decide strong isolation must stay at separate gateway or OS-host boundaries.

## Reproduction Assessment

Not applicable: this is a feature/API design proposal rather than a broken existing behavior report. Source inspection gives high confidence that the requested quarantine directive and trust metadata contract are absent on current main and `v2026.6.11`.

## Solution Assessment

Unclear as an implementation path: the direction fits OpenClaw's security and plugin-extension goals, but maintainers still need to choose the API shape, enforcement model, and trust metadata contract. The safest path is to reuse existing `sessions_spawn`, sandbox, tool-policy, and provenance primitives rather than adding a parallel isolation stack.
