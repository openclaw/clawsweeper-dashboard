## Summary

Keep open: current main and v2026.6.11 still expose before_tool_call blocking, approval, and parameter rewrite plus subagent sandbox primitives, but not a plugin-returned quarantined execution directive with constrained capabilities and trust/provenance metadata. This is a security-sensitive Plugin SDK/runtime design item, not conservative cleanup.

## What This Changes

Request an additive Plugin SDK/runtime capability for plugins to ask OpenClaw to run selected operations in an isolated, constrained session and return provenance-tagged trust metadata.

## Best Possible Solution

Design an additive Plugin SDK/runtime trust-boundary contract that reuses existing sessions_spawn, sandbox, tool-policy, audit, and provenance primitives with explicit enforceable guarantees before exposing it to plugins.

Rationale: The missing capability is real, but it defines a security boundary and public plugin contract; automation cannot safely choose the enforcement semantics, result metadata shape, or prerequisite hook dependencies.

Options:

- **Keep As Design Item (recommended):** Keep this open until maintainers define isolation semantics, prerequisite hook context, trust metadata, compatibility expectations, and validation requirements.
- **Document Current Primitives Only:** Document sessions_spawn with sandbox=require, per-agent tool policy, audit, and separate gateway/OS boundaries as the supported workaround without adding a hook directive yet.
- **Reject Hook-Level Quarantine:** Close the direction if maintainers decide strong isolation must remain an operator-managed gateway, OS-user, host, or sandbox deployment boundary only.

## Reproduction Assessment

No for a runtime bug, because this is a feature/API design proposal rather than broken existing behavior. Source and docs inspection give high confidence that the requested isolation directive and trust metadata contract are absent from current main and v2026.6.11.

## Solution Assessment

Unclear as an implementation path: the direction fits OpenClaw's security and plugin-extension goals, but maintainers still need to choose the API shape, enforcement model, and trust metadata contract. The safer direction is to compose existing sessions_spawn, sandbox, tool-policy, audit, and provenance primitives rather than create a parallel isolation stack.
