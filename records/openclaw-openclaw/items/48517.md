## Summary

Keep open: current main and v2026.6.11 still expose blocking/approval/param-rewrite hooks and sessions_spawn sandbox guardrails, but not a plugin-returned isolation directive with constrained execution and provenance/trust metadata. This remains a Plugin SDK/runtime security-boundary design item, not conservative cleanup.

## What This Changes

The issue requests a public Plugin SDK/runtime capability for plugins to request isolated, constrained session execution and receive trust/provenance metadata for the result.

## Best Possible Solution

Design an additive Plugin SDK/runtime isolation contract that reuses sessions_spawn, sandbox, tool-policy, session, and provenance primitives with explicit enforceable guarantees before exposing it to plugins.
