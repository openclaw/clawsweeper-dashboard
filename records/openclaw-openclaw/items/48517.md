## Summary

Keep open: current main and v2026.6.11 have adjacent before_tool_call controls, subagent sandbox/context modes, and security guidance, but not a plugin-returned quarantined execution directive with constrained runtime execution and structured trust/provenance metadata.

## What This Changes

The issue requests a Plugin SDK/runtime API that lets a plugin ask OpenClaw to run selected work in an isolated, constrained session and return trust/provenance metadata.

## Best Possible Solution

Keep this as a maintainer-owned security design item until the Plugin SDK contract names the isolation guarantee, enforcement owner, constrained tool model, and standardized result provenance shape.

- A hook-level quarantine directive could overstate OpenClaw's isolation guarantees unless sandbox scope, allowed-tool enforcement, timeout/token limits, failure handling, and trust metadata semantics are specified together.
- Native plugins execute as trusted gateway code today, so the design must distinguish trusted plugin policy code from untrusted data being processed in an isolated child run.
