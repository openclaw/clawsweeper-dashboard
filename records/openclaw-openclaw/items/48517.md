## Summary

Keep open: current main and the latest release still have adjacent before_tool_call, sessions_spawn, sandbox, and plugin-trust primitives, but not a plugin-returned quarantined execution directive with constrained capabilities and standardized trust/provenance metadata. This remains a security-sensitive Plugin SDK/runtime design item rather than a cleanup-close candidate.

## What This Changes

The issue requests a Plugin SDK/runtime mechanism for hooks to request quarantined isolated execution with constrained capabilities and provenance or trust metadata.

## Best Possible Solution

Design an additive Plugin SDK/runtime isolation contract that composes existing sessions_spawn, sandbox, tool-policy, session, and provenance primitives with explicit enforceable guarantees before exposing it to plugins.

- **Reject Plugin-Requested Quarantine:** Close the direction if maintainers decide strong isolation must remain at separate gateway, OS user, host, or operator-managed sandbox boundaries only.
