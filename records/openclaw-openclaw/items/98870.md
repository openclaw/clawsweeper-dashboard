## Summary

Keep open: current main and the latest release still fetch only the first Teams Graph replies page, the linked repair PRs are closed unmerged, and no open related item currently owns the remaining fix.

## What This Changes

The issue asks OpenClaw to paginate Microsoft Teams channel thread replies so long threads include the newest relevant replies in agent context instead of only the first 50 oldest replies.

## Best Possible Solution

Implement a bounded `fetchThreadReplies` pagination fix that reuses `fetchAllGraphPages`, selects the newest requested replies in chronological context order, and adds focused regression coverage without changing config or channel policy.

## Reproduction Assessment

Yes, from source inspection: current main clamps the Teams replies request to `$top=50`, performs one Graph call, and ignores `@odata.nextLink` before the monitor handler injects replies into agent context. I did not run a live Teams tenant in this read-only review.

## Solution Assessment

Yes: the narrow maintainable fix belongs in the Teams `fetchThreadReplies` helper, reusing the existing Graph pagination helper and keeping best-effort degradation. No new config option or product policy is needed.
