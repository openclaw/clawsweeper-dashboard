## Label Justifications

- `P2`: The issue affects Microsoft Teams thread context quality for long threads but has limited channel-specific blast radius.
- `impact:session-state`: The agent can receive stale Teams thread context when only the oldest reply page is injected.

## Summary

Keep open: current main and the latest release still fetch only one Teams Graph replies page, and every linked fix PR is closed unmerged, so this issue remains the canonical tracker for the long-thread context bug.

## What This Changes

The issue reports that Microsoft Teams channel thread context fetches only the first 50 oldest Graph replies and omits newer replies in long channel threads.

## Best Possible Solution

Keep this issue open as the canonical Teams pagination bug until a maintainer lands the helper-level fix with focused tests and either redacted live over-50-reply Teams proof or explicit acceptance of the bounded Graph fanout risk.

## Reproduction Assessment

Yes. Source-level reproduction is high confidence: current main fetches one `$top=50` replies page, ignores `@odata.nextLink`, and the monitor handler injects that result into thread context; I did not run a live Microsoft Teams tenant in this read-only review.

## Solution Assessment

Yes for fix shape, but not yet for merge readiness. The narrow maintainable fix belongs in `fetchThreadReplies` using the existing `fetchAllGraphPages` helper, while live tenant proof or explicit maintainer risk acceptance should settle the page-fanout concern.
