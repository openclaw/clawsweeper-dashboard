## Label Justifications

- `P2`: This is a normal-priority Teams plugin bug with limited blast radius, where long channel threads can receive stale agent context but the core runtime is not unusable.
- `impact:message-loss`: Newer Teams thread replies can be omitted from the message context passed to the agent.
- `impact:session-state`: The agent can reason over stale Teams thread state when only the oldest first page of replies is included.

## Summary

Keep open: current main and the latest release still fetch only one Teams Graph reply page, and an open linked fix PR now owns the implementation path, so this issue should remain open until that PR lands or is replaced.

## What This Changes

The issue requests Teams channel thread context to follow Microsoft Graph reply pagination so newer replies are not omitted after the first 50 oldest replies.

## Best Possible Solution

Review, repair, or replace the linked Teams PR with a narrow fix that reuses the existing Graph pagination helper, keeps a bounded newest-reply window in chronological order, and adds regression coverage for over-50 reply threads.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: a Teams channel thread with more than 50 replies reaches `fetchThreadReplies`, which currently returns only the first Graph reply page; I did not run a live Teams tenant reproduction in this read-only review.

## Solution Assessment

Yes. The narrow maintainable solution is to fix the Teams plugin helper to follow bounded `@odata.nextLink` pagination and return the newest limited reply window without adding config or core policy.
