## Summary

Keep open: current main and the latest release still fetch only the first Teams replies page, and https://github.com/openclaw/openclaw/pull/100155 is an open closing fix candidate that has not merged.

## What This Changes

Fix Microsoft Teams channel thread context so Graph reply pagination follows `@odata.nextLink` and keeps the newest replies when a thread exceeds 50 replies.

## Best Possible Solution

Keep this issue as the canonical tracker and land a refreshed bounded helper-level pagination fix through https://github.com/openclaw/openclaw/pull/100155 or a narrow replacement once proof or maintainer risk acceptance is available.

## Reproduction Assessment

Yes. Source inspection shows current main still performs one `$top=50` replies request and ignores `@odata.nextLink` before the monitor handler injects thread context; I did not run a live Teams tenant in this read-only review.

## Solution Assessment

Yes. The narrowest maintainable fix is in `fetchThreadReplies`, reusing `fetchAllGraphPages` and preserving best-effort handler degradation; the open PR path still needs merge readiness rather than a separate issue close.
