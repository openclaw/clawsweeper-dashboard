## Label Justifications

- `P1`: The report describes a broken channel workflow where provider failover cleanup can block subsequent user messages after a visible reply has already been sent.
- `impact:message-loss`: Follow-up Telegram messages can be delayed or effectively suppressed behind a session lane that remains occupied after visible reply delivery.
- `impact:session-state`: The failure mode is session-lane admission state diverging from user-visible reply completion.
- `impact:auth-provider`: The trigger is provider overload/auth-profile fallback behavior keeping the run and lane occupied.

## Summary

Keep open: current main still admits same-session work behind an active reply operation and releases the command-lane slot only when the wrapped run settles, while the proposed delivery-based handoff needs maintainer-owned session ordering and transcript-safety decisions.

## What This Changes

The issue requests releasing or handing off the same-session lane after a Telegram-visible reply is delivered during provider failover, instead of holding later inbound messages until failover cleanup or timeout settlement completes.

## Best Possible Solution

Define a maintainer-approved delivery-gated handoff for same-session turns that only admits follow-ups after durable visible delivery and transcript/order guards, then validate it with focused source coverage and live Telegram failover proof.
