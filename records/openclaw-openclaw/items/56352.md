## Summary

Keep open: current main still appears to keep the same-session command lane occupied until the embedded run task settles or stuck-session recovery releases it, while Telegram visible-delivery tracking only records reply-path delivery and does not release that lane.

## What This Changes

The issue reports that a same-session Telegram lane stays occupied after a reply is visibly delivered during provider failover, delaying later inbound messages.

## Best Possible Solution

Define a maintainer-approved visible-delivery handoff for same-session lanes that preserves transcript, ordering, final-delivery, and failover cleanup invariants, then prove it with source tests and live Telegram/provider-failover evidence.

## Reproduction Assessment

Yes at source level, not live: current main still holds the embedded session command lane until the wrapped task settles, while Telegram delivery only marks local reply-path state.

## Solution Assessment

Unclear: releasing on visible delivery is directionally plausible, but the exact handoff needs maintainer judgment to avoid racing transcript durability, final delivery, and failover cleanup.
