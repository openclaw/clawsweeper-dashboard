## Summary

Keep open: current main still ties same-session lane admission to the full embedded/failover task settling, while visible reply delivery is only reply-path state and does not release the command-queue session lane for later Telegram messages.

## What This Changes

Issue #56352 reports that Telegram follow-up messages can stay blocked behind an occupied failover lane after a reply has already been emitted.

## Best Possible Solution

Define a maintainer-approved visible-delivery handoff that admits later same-session visible turns only after explicit transcript, ordering, cleanup, and timeout-recovery invariants are durable, then prove it with focused tests and live Telegram failover evidence.
