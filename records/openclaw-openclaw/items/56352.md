## Summary

Keep open: current main still ties same-session lane admission and active-run lifetime to the full embedded/failover task, while observed Telegram delivery and status reactions do not prove the session lane is released for follow-up messages.

## What This Changes

The issue asks OpenClaw to release a same-session lane once a Telegram reply has been emitted during provider failover, instead of blocking later inbound messages until failover or timeout cleanup completes.

## Best Possible Solution

Define a maintainer-approved visible-delivery handoff that admits later same-session turns while preserving transcript ordering, failover cleanup, and timeout recovery invariants, then prove it with focused source tests and a live Telegram failover scenario.
