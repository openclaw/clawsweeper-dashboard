## Summary

This PR still addresses a real gap on current main: the Responses payload path does not yet reuse the existing provider-native reasoning-effort mapping used by the sibling OpenAI-compatible path. The implementation is narrow and appears correct, but its supplied terminal proof exercises a fixture model rather than a live Responses-compatible provider, so real provider evidence is still needed before merge.

Likely related people: `steipete` is the assigned follow-up owner and is also connected to recent OpenAI reasoning-effort work; confidence is medium.

## What This Changes

The PR maps OpenAI Responses reasoning-effort payloads through each compatible provider’s declared native effort map and adds regression coverage for explicit, summary-only, and default-off requests.

## System Context

OpenClaw’s model runtime converts a canonical thinking level into an OpenAI Responses request before sending it to a selected provider. Provider compatibility metadata can translate those canonical levels into provider-native payload values, which lets compatible endpoints accept requests without changing user-facing thinking controls.
