## Summary

Keep this PR open for a narrow API-shape correction before merge. The provider rejection is real and the live Groq proof is useful, but the patch exposes a second Responses reasoning-mapping configuration surface even though the current model contract already assigns provider-native thinking values to `thinkingLevelMap`; that creates competing precedence and upgrade behavior for the same setting.

## What This Changes

The branch makes OpenAI Responses requests resolve provider-native reasoning effort values, omits OpenAI-only encrypted reasoning fields for compatible endpoints, and adds regression coverage for custom reasoning values and Azure replay behavior.

## System Context

OpenClaw’s AI transport turns a selected model plus agent reasoning settings into an OpenAI Responses request. The shared Responses parameter builder determines the provider-native reasoning payload and whether encrypted reasoning content is requested for later tool/reasoning continuation.

## Architecture Diagram

flowchart LR
  A[Selected model] --> B[Thinking level settings]
  B --> C[Responses parameter builder]
  A --> C
  C --> D[Reasoning effort resolver]
  D --> E[Responses request payload]
  E --> F[OpenAI or compatible endpoint]
  F --> G[Replay-capable session continuation]

## Best Possible Solution

Keep `thinkingLevelMap` as the sole persisted model mapping, make the shared resolver treat its native values as valid Responses payload values, and gate encrypted replay through a named capability contract with coverage for both unsupported-compatible and replay-capable endpoints.
