## Summary

Keep this PR open, but do not merge it as written. It correctly fixes Groq-style provider-native effort mapping and now includes credible redacted live Groq proof, yet its new provider-id check removes encrypted reasoning replay data from Azure Responses and any other non-`openai` provider that still supports that OpenAI Responses feature; that can break later reasoning/tool turns for existing users.

## What This Changes

The PR maps OpenAI Responses reasoning-effort payloads through each provider’s declared native compatibility map and suppresses OpenAI-only reasoning fields for non-OpenAI providers.

## System Context

OpenClaw’s Responses adapter builds the request payload used by OpenAI-compatible and Azure-hosted reasoning models. Provider compatibility metadata maps OpenClaw thinking levels to endpoint-native values, while encrypted reasoning content is returned and replayed on later model calls.

## Architecture Diagram

flowchart LR

  F --> G[Later tool or follow-up turn]

## Best Possible Solution

Keep native-effort mapping in the shared Responses builder, but preserve encrypted reasoning for Azure and any endpoint explicitly known to support replay; use a capability or API-family condition rather than treating every non-`openai` provider as incompatible.
