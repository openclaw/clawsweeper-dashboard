## Summary

Keep this PR open for normal maintainer review: it now shares the provider-native reasoning-effort mapping used by Chat Completions and restores Azure encrypted-reasoning replay after the previous P1 review finding. The contributor supplied redacted live Groq output for both mapped and default-off requests, while the branch adds focused Azure payload coverage.

## What This Changes

The PR maps OpenAI Responses reasoning settings through each model’s provider compatibility map and omits OpenAI-only reasoning fields for compatible endpoints while retaining encrypted replay fields for OpenAI and Azure Responses.

## System Context

OpenClaw’s AI provider layer turns model compatibility metadata and per-run reasoning options into Responses API request payloads. Those payloads go to OpenAI-compatible endpoints and, for replay-capable routes, preserve encrypted reasoning material for later tool or reasoning turns.

## Architecture Diagram

## Best Possible Solution

Keep one shared compatibility-map path for Responses and retain encrypted reasoning only for endpoints with a verified replay contract, adding a focused continuation test whenever another replay-capable provider is introduced.
