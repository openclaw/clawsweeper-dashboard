## Summary

Keep this PR open: the live Groq proof and Azure replay regression coverage demonstrate the intended bug fix, but the branch still adds a second public provider-native reasoning-map contract and gives it precedence over the existing canonical model mapping. That would allow equivalent model definitions to produce different Responses payloads, so it needs a narrow repair before merge.

## What This Changes

The PR makes OpenAI Responses payloads translate canonical reasoning levels to provider-native values, avoids OpenAI-only reasoning fields for compatible endpoints, and adds regression coverage for provider mapping and Azure replay.

## System Context

OpenClaw's AI provider layer converts an agent's canonical reasoning level into each model's request payload. Responses adapters then send that payload to OpenAI-compatible endpoints and, for replay-capable routes, preserve encrypted reasoning material across tool continuations.

## Best Possible Solution

Keep `Model.thinkingLevelMap` as the sole provider-native reasoning mapping contract, route Responses through the centralized resolver using that map, and retain the targeted OpenAI/Azure replay behavior with regression coverage.
