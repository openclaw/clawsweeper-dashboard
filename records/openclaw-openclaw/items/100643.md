## Summary

Close: current main and released OpenClaw already implement the requested Discord gateway liveness behavior. The Discord gateway sends heartbeat payloads, reconnects on missed heartbeat ACKs, restarts startup-open sockets that never reach READY, and the older same-symptom silent-drop report was already closed with the same implementation evidence.

## What This Changes

The issue requests a Discord WebSocket heartbeat watchdog that reconnects when ping/pong traffic stops without a TCP FIN.

## Best Possible Solution

Keep the existing Discord gateway heartbeat and READY liveness implementation; future current-version reports should include redacted gateway logs showing the specific close/error path, and `WS_ERR_TOO_MANY_BUFFERED_PARTS` or close code 1008 evidence should stay with https://github.com/openclaw/openclaw/issues/88330.
