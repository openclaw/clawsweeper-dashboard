## Summary

Keep open: multiple reports on the current release, including July 24–25, 2026 reports on v2026.7.1, still show Active Memory timing out or delaying direct and helper runs. The central reliability problem remains unresolved, while the likely remedies span a narrow eligibility fix and a broader embedded-recall architecture decision.

## What This Changes

Fix Active Memory recall so its embedded pre-prompt work cannot stall Codex-backed user runs, native hooks, gateway delivery, or internal helper sessions.

## System Context

Active Memory is a plugin hook that runs before OpenClaw builds an agent prompt. It starts recall work using the selected provider and context engine, then injects a memory summary into the parent agent run before the gateway can deliver the response.

## Architecture Diagram

flowchart TD
  A[User message or internal helper] --> B[Active Memory eligibility]
  B --> C[Pre-prompt recall hook]
  C --> D[Embedded provider and context runtime]
  D --> E[Memory summary or bounded skip]
  E --> F[Parent agent run]
  F --> G[Gateway response delivery]

## Best Possible Solution

First land a focused eligibility guard with regression coverage so internal helper sessions cannot trigger direct-chat recall, then choose and prove a bounded recall architecture that cannot hold the parent prompt or gateway delivery path hostage.
