## Summary

Keep this PR open for a maintainer product and security-direction decision. It is a documentation-only architecture proposal, not an implementation, and it currently presents an unsupported Iroh transport, CLI command, and mobile flow as though they were OpenClaw behavior; current main instead documents authenticated Gateway WebSocket access over SSH, LAN/Tailnet, or Tailscale.

## What This Changes

This PR adds a German-language proposal document describing a possible Iroh peer-to-peer transport and ticket-based mobile connection flow for the OpenClaw Gateway.

## System Context

OpenClaw clients and nodes connect to a single Gateway that owns sessions, credentials, channels, and state. Remote access currently reaches that Gateway through its authenticated WebSocket using SSH forwarding, trusted LAN/Tailnet access, or Tailscale; the proposal would add a new transport beneath those clients.
