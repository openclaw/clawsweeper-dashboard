## What This Changes

The issue requests a default-off option to synthesize opening `<think>` delimiters for local reasoning models before reasoning parsing, transcript formatting, and delivery.

## Best Possible Solution

If sponsored, add one documented default-off config contract, resolve precedence before embedded-agent runs, pass it through runner/subscriber params, and synthesize the tag exactly once with a native-tag guard before current parsing.

## Reproduction Assessment

Yes for a source-level missing-feature check: current main has no config/schema, runner/subscriber, or message-parser path for force-prepending `<think>`. This is not a failing bug reproduction because the issue asks for a new option.

## Solution Assessment

Unclear. A default-off config option is plausible, but OpenClaw's config-surface bar is high and existing provider params plus reasoning visibility controls are not equivalent, so maintainers should decide whether core config, provider/model metadata, or prompting owns this behavior.
