## Summary

Keep this PR open for repair: the transaction-authoritative delta and prior routing defect are fixed, and the supplied CLI proof is credible, but the process-local parity shortcut can remain stale after another Gateway or CLI manager changes the shared index, allowing later syncs to skip healing checks and mark inconsistent derived search state clean.

## What This Changes

The PR changes session-memory indexing to preserve unchanged chunk rows while transactionally deleting stale rows and inserting only newly changed chunks.

## Best Possible Solution

Remove the unversioned parity shortcut or bind each cached result to an authoritative database revision, then add a two-manager regression proving that derived-row drift after a cached clean write is detected and healed before the source record becomes clean.
