## Summary

This PR addresses a real startup-availability concern, but it does not yet enforce the claimed five-second bound: `spawnSync` uses `SIGTERM` by default and can keep blocking if the child handles that signal. The supplied macOS output only proves normal probes work, not the timeout path, so the patch needs one narrow repair and matching real behavior proof before merge.

## What This Changes

The branch adds five-second timeouts to the macOS `sysctl` and `sw_vers` self-presence probes and adds a Darwin-mocked regression test for the passed options.

## Best Possible Solution

Use a termination strategy that actually bounds the synchronous probes, preserve the best-effort fallback values, and show a redacted macOS timeout-path run in addition to the focused regression coverage.
