## Summary

Keep this PR open: the prior import-order finding is addressed and the added macOS live output confirms normal probes still work, but `spawnSync({ timeout })` alone does not guarantee the claimed startup bound when the child handles the default `SIGTERM`; the changed failure mode also lacks a real timeout-path demonstration.

## What This Changes

The PR adds five-second `spawnSync` timeouts to the macOS `sysctl` and `sw_vers` self-presence probes and dynamically imports the module after a Darwin platform mock for regression coverage.

## Best Possible Solution

Keep self-presence startup from depending on an indefinitely synchronous child: move the probes off the blocking startup path where feasible, or use and test a termination strategy that cannot be ignored by a normal child, then attach redacted macOS evidence of the timeout path.
