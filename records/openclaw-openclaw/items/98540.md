## Summary

Keep open: current main still has the composer/activity state split, and the linked open pull request is the right closing candidate. The report is corroborated by two user comments describing the same confusing idle composer state during active tool execution.

## What This Changes

The issue requests that WebChat’s composer show an in-progress indicator and Stop button whenever the Activity panel shows tools actively running.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/98544, or an equivalent narrow patch, so composer status and Stop controls consume the active tool-execution signal before this issue closes.

## Reproduction Assessment

Yes. Current main is source-reproducible: composer progress and Stop are derived from hasAbortableSessionRun, while running tool activity is tracked separately in activityEntries; I did not run a live browser reproduction.

## Solution Assessment

Yes for the direction. Bridging the existing session-scoped activity stream into the existing composer abortability path is the narrow maintainable fix; this issue should close only after the linked PR or an equivalent patch merges.
