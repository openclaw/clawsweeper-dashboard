## Summary

Keep open: current main still has a source-proven Web UI state split where the Activity panel can know tools are running while the composer’s in-progress and Stop UI only follows chat/session run state. The linked pull request is open and explicitly closes this issue, so the issue should remain open until that PR or an equivalent fix lands.

## What This Changes

The issue reports that the Web UI composer appears idle, with no in-progress indicator or Stop button, while agent tool execution is still active.

## Best Possible Solution

Land or replace https://github.com/openclaw/openclaw/pull/98544 with a narrow UI fix that makes the composer and Activity panel consume the same active tool-execution signal for run status and Stop controls.

## Reproduction Assessment

Yes. Current main is source-reproducible because composer status and Stop controls depend on hasAbortableSessionRun, while running tool activity is tracked separately in activityEntries and not consumed there.

## Solution Assessment

Yes at the issue level. The maintainable solution is a narrow bridge from the existing activity/tool execution signal into the existing composer abortability path, and the open linked PR is the current candidate for that fix.
