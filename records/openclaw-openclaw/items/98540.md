## What This Changes

The issue asks for the Control UI composer to show in-progress state and Stop controls whenever the selected agent session has running tool execution shown in Activity.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/98544 or an equivalent narrow UI fix that makes composer status and Stop controls consume the same active tool-execution signal as Activity.

## Reproduction Assessment

Yes at source level: current main keeps running tool activity in activityEntries while composer status and Stop are driven by chatRunId/session rows only. The reporter screenshot also shows Activity running while the composer appears idle.

## Solution Assessment

Yes, the best solution shape is a narrow UI bridge from the existing tool activity state into the composer abort/status path. The linked pull request appears to target that boundary, but it should be reviewed and proven before this issue closes.
