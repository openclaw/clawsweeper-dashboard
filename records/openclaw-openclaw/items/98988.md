## Summary

Keep open. The shared archive API is the right direction, but this PR is not merge-ready because the archive byte cap is enforced only after the full release asset is downloaded, and the external PR provides mocked/unit proof rather than real fd/rg extraction proof.

## What This Changes

The PR replaces tool-manager archive extraction with the shared safe archive extraction API and updates the corresponding tests.

## Best Possible Solution

Use the shared `extractArchive` path, add a matching byte cap while streaming the release-asset download, and require redacted real behavior proof for fd/rg archive extraction before merge.

## Reproduction Assessment

Yes, source inspection is enough to reproduce the reported class: current main downloads archives and extracts them with unbounded `tar`/`unzip` subprocesses. I did not run a live decompression-bomb payload, but the unbounded path is clear in `src/agents/utils/tools-manager.ts`.

## Solution Assessment

No, not as written. Reusing `extractArchive` is the best extraction boundary, but the complete security fix should also bound the archive download stream before writing past the same compressed-size cap.
