Full review comments:

- **[P1] Remove the unrelated workspace artifacts:** `openclaw-workspace-state.json:1-4`
  - body: This branch adds `HEARTBEAT.md`, `SOUL.md`, `TOOLS.md`, `openclaw-workspace-state.json`, and `xiugaiyijian.md` at repo root, but those files are workspace/bootstrap state or copied review output rather than launcher code. Shipping them would pollute the repository with unrelated agent instructions and prior bot-review text, so the PR needs to drop them before it can be reviewed as a focused launcher change.
  - confidence: 0.95
- **[P2] Delegate readiness instead of hard-coding Gateway health:** `launcher/src/main.rs:103-104`
  - body: `is_gateway_running()` only checks `http://127.0.0.1:18789/health`, so users with a configured Gateway port, profile-specific config, TLS, or a remote URL will see the launcher misreport the service and try to start the wrong default path. The existing `dashboard` and `tui` commands already resolve readiness from config, so the wrapper should call those commands directly or use the same configured readiness path.
  - confidence: 0.9
- **[P2] Add or remove the documented build command:** `launcher/README.md:18-20`
  - body: The README tells users to run `pnpm launcher:build`, but the PR head does not add that script to `package.json` or otherwise wire the launcher into the root build/package surface. As written, the documented build path fails for reviewers and users.
  - confidence: 0.92
- **[P2] Use cross-platform CLI discovery:** `launcher/src/main.rs:19-20`
  - body: The launcher claims Windows support, but the first lookup path shells out to `which`, and the README says npm-global `openclaw` is enough even when `pnpm` is absent. A Windows `.exe` launched outside the source tree can fail to find the CLI despite a normal npm installation, so discovery needs to support the platform-specific bin/shim path or narrow the documented platform claim.
  - confidence: 0.82
- **[P3] Resolve the displayed version through the chosen CLI path:** `launcher/src/main.rs:263-265`
  - body: The screenshot shows `OpenClaw: unknown`, and the source always runs `node <cli_path> --version` even when the resolved CLI path is a bin shim or executable. Reuse the same `.mjs` vs binary command selection used for actual delegation so the menu reports the installed OpenClaw version reliably.
  - confidence: 0.86
