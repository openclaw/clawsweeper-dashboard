Full review comments:

- **[P1] Remove unrelated root artifacts:** `openclaw-workspace-state.json:1-4`
  - body: This branch adds `HEARTBEAT.md`, `SOUL.md`, `TOOLS.md`, `openclaw-workspace-state.json`, and `xiugaiyijian.md` at repo root, but those are workspace/template state or copied review output rather than launcher code. Shipping them would pollute the repository with unrelated agent notes and prior bot-review text, so the PR needs to drop them before it can be reviewed as a focused launcher change.
  - confidence: 0.96
- **[P2] Delegate readiness to existing CLI:** `launcher/src/main.rs:103-104`
  - body: `is_gateway_running()` only checks `http://127.0.0.1:18789/health`, so users with a configured Gateway port, TLS, bind mode, remote URL, or SecretRef-backed auth can see the launcher misreport service state or start the wrong default path. The existing dashboard/TUI commands already resolve configured readiness, so the wrapper should delegate to those paths instead of adding its own probe.
  - confidence: 0.9
- **[P2] Forward known-command arguments:** `launcher/src/main.rs:280-292`
  - body: The known `tui`, `dashboard`, and `update` branches rebuild fixed argv lists and drop user-supplied flags, so `openclaw-launcher tui --url ...`, `dashboard --no-open`, or `update --dry-run` will not reach the CLI even though the README promises pass-through.
  - confidence: 0.88
- **[P2] Wire or remove the build command:** `launcher/README.md:18-20`
  - body: The README tells users to run `pnpm launcher:build`, but the PR head does not add that script to `package.json` or wire the launcher into the package file list. As written, the documented build path fails for reviewers and users.
  - confidence: 0.93
- **[P2] Use cross-platform CLI discovery:** `launcher/src/main.rs:19-20`
  - body: The launcher claims a `.exe` build path and says an npm-installed `openclaw` CLI is enough, but the first lookup shells out to POSIX `which` and never tries the Windows `where` path or the executable name directly. A Windows launcher outside the source tree can fail to find a normal npm-installed CLI, so discovery needs to support the documented platform or the docs should narrow the claim.
  - confidence: 0.82
- **[P3] Resolve version through selected CLI:** `launcher/src/main.rs:264-265`
  - body: The contributor screenshot shows `OpenClaw: unknown`, and the source always runs `node <cli_path> --version` even when the resolved CLI path is a bin shim or executable. Reuse the same `.mjs` versus binary command selection used for actual delegation so the menu reports the installed OpenClaw version reliably.
  - confidence: 0.86
