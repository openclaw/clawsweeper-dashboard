## Summary

## What This Changes

## Best Possible Solution

If maintainers want a core launcher, make it a narrow tested wrapper that forwards exact CLI args, removes workspace artifacts, uses an approved build path, and keeps setup/security decisions visible.

## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Forward delegated command arguments:** `launcher/src/main.rs:286-292`
  - body: For recognized commands the launcher discards every argument after the subcommand. That means `openclaw-launcher update --dry-run` runs plain `openclaw update`, `dashboard --no-open` opens the browser, and `tui --local` is lost; a thin wrapper must preserve the tail argv for the canonical CLI.
  - confidence: 0.95
- **[P1] Remove the workspace artifacts from the repo root:** `SOUL.md:1`
  - body: This PR commits agent workspace/bootstrap files and a copied ClawSweeper review transcript at the source root. Those are generated/user-context artifacts, not launcher source, and they can affect future agent context for anyone working from the checkout.
  - confidence: 0.92
- **[P2] Wire the documented launcher build command:** `launcher/README.md:19`
  - body: The README tells users to run `pnpm launcher:build`, but the PR head package.json does not define that script. As written, the documented build path fails before Cargo is even invoked.
  - confidence: 0.93
- **[P2] Use a platform-aware CLI lookup:** `launcher/src/main.rs:19-33`
  - body: The launcher first probes PATH with `which`, which is not the Windows lookup command, and the fallback treats `pnpm bin openclaw` output as an executable path. A Windows user with a normal global `openclaw` install can hit the 'not found' path even though the CLI is installed.
  - confidence: 0.82
