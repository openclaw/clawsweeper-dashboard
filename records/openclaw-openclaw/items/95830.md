## Summary

Keep open: this is a useful candidate for the canonical Telegram poll-answer bug, but the current patch is not merge-ready because it swallows registry read failures on inbound vote handling and still lacks live Telegram proof for the current head.

## What This Changes

Adds a Telegram keyed-state poll registry, records non-anonymous poll origins from `sendPollTelegram`, handles `poll_answer` updates into Telegram sessions, and adds focused Telegram routing/registry tests.

## Best Possible Solution

Propagate registry read errors from inbound `poll_answer` handling so spooled replay can retry, keep true missing poll IDs as safe no-ops, then add redacted live Telegram proof for direct and topic sessions before landing one canonical PR.

Yes. Source inspection shows current main can send public Telegram polls and request poll-answer-capable updates but has no `poll_answer` handler, and the PR's new lookup-failure path is directly reproducible from source and tests.

## Solution Assessment

No, not yet. Recording poll origins at the central send boundary and resolving votes through Telegram conversation routing is the right shape, but inbound registry read failures must stay retryable and live Telegram proof is still required.
