## Summary

Keep open. The central Telegram poll-answer gap remains owned by the open canonical issue, but this unchanged PR head still has the previously raised P1 delivery-loss defect: a keyed-store lookup failure is swallowed rather than retried; it also lacks current-head live Telegram behavior proof.

## What This Changes

The branch adds a bounded Telegram keyed-state poll-origin registry, records public poll origins during send, and routes later `poll_answer` updates into the originating direct, group, or forum-topic session.

## Best Possible Solution

Preserve the keyed-state approach, rethrow poll-registry read failures so Telegram retries instead of losing a vote, add a regression for that retry behavior, then capture redacted current-head Telegram Desktop proof for direct and forum-topic routing.
