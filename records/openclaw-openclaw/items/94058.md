## Summary

Keep open: current main still contains the source-level path that can let a delivery error result overwrite a successful isolated cron execution, and two open closing PRs already own the fix path.

## What This Changes

The issue requests that scheduled isolated cron agent turns preserve successful agent execution status and record post-run delivery/finalization failure separately.

## Best Possible Solution

Review and land or replace the clean linked fix path, preserving execution status as ok for successful isolated sessions while recording delivery failure in deliveryStatus, deliveryError, and diagnostics.

## Reproduction Assessment

Yes at source level: a non-fatal isolated payload plus dispatchCronDelivery returning an error result still flows through resultWithDeliveryMeta on current main. The exact natural scheduled Gateway/Feishu run has not been live-reproduced here.

## Solution Assessment

Yes, separating execution outcome from delivery outcome is the maintainable fix shape already reflected in the cron types; maintainers still need to accept the observable status/backoff semantics before landing.
