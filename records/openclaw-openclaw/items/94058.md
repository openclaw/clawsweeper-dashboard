## Summary

Keep open: current main and v2026.6.11 still have the source-level path where an error-shaped delivery/finalization result can become the parent isolated cron run status, and the direct fix candidates are still open rather than merged.

## What This Changes

The issue reports that scheduled isolated cron `agentTurn` runs can persist the parent run as `error`/`not-delivered` even when the isolated session ended successfully with a final assistant message.

## Best Possible Solution

Review and land a maintainer-approved cron finalization fix that preserves successful isolated execution separately from delivery/finalization failure while keeping delivery-target refusals and diagnostics explicit.

## Reproduction Assessment

We have a source-level reproduction path, but not a high-confidence live reproduction of the original WSL2/systemd/Feishu scheduled run. Current main can return an error-shaped delivery/finalization result after successful isolated payload resolution, and the scheduler persists that returned status.

## Solution Assessment

Unclear as final product policy. The finalizer is the right boundary for a narrow fix, but maintainers still need to choose the `ok` plus delivery-fields contract versus the broader warning-status contract.
