## Summary

Keep open: current main and the latest release still have the cron finalizer path that can persist a delivery-shaped error as the outer isolated cron run status after a nonfatal agent result, and the direct fix path is still an open pull request rather than merged.

## What This Changes

The issue asks OpenClaw to preserve successful isolated scheduled `agentTurn` execution separately from post-session finalization or delivery failure.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/95419 or a maintainer-approved replacement that keeps isolated execution success separate from delivery failure, then close this issue after the fix reaches main.

## Reproduction Assessment

Yes, source-reproducible: current main can return an error-shaped delivery result after successful isolated payload resolution, and the scheduler persists that returned status as the parent cron result. I did not live-run the original WSL2/systemd/Feishu scheduled scenario.

## Solution Assessment

Unclear as a final product decision. The finalizer and cron outcome boundary are the right narrow code layer, but maintainers still need to choose the `ok` plus `not-delivered` contract or route this through the broader warning-status work.
