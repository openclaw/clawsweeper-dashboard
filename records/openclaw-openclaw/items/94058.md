## Summary

## What This Changes

The issue asks cron to preserve a successful isolated `agentTurn` execution outcome when post-run delivery or finalization fails, instead of recording the parent run as a generic error.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/95419 or a maintainer-approved replacement, while leaving the broader warning-status product contract tracked by https://github.com/openclaw/openclaw/issues/49190.

Options:

- **Accept narrow status split (recommended):** Land the narrow fix so successful isolated execution remains `ok` and delivery failure is reported through `deliveryStatus`, `deliveryError`, and diagnostics.
- **Defer to warning status:** Keep this issue open behind the broader warning-status work if maintainers want a new public partial-success run state instead of reusing `ok`.
- **Keep current error semantics:** Treat delivery failure as primary cron failure and document that status-only consumers should expect `error` for undelivered scheduled output.

Yes at source level: current main can return an error-shaped delivery result through the isolated finalizer after a nonfatal payload, and the scheduler persists that returned status. I did not live-run the original WSL2/systemd/Feishu scheduled scenario.
