## What This Changes

## Best Possible Solution

Land the same-filesystem staging fix through normal maintainer gates, then let the linked canonical issue close after merge.

## Reproduction Assessment

Yes, from source with high confidence. Current main stages git plugin clones under os.tmpdir() and then publishes through a rename-only directory replacement path, which fails with EXDEV when the temp and managed git roots are on different filesystems.

## Solution Assessment

Yes. Staging non-dry-run clones beside the managed repo is the narrowest maintainable fix because it preserves the existing atomic replacement primitive, install policy flow, npm install step, and dry-run isolation instead of adding a broader copy fallback.
