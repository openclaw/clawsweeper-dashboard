## What This Changes

The PR lets git plugin installs create non-dry-run clone temp workspaces beside the managed git repository target and adds regression coverage for same-filesystem staging plus dry-run isolation.

## Best Possible Solution

Land the same-filesystem git clone staging fix through normal maintainer gates, then close the linked canonical issue after merge.

## Reproduction Assessment

Yes, from source with high confidence. Current main stages git plugin clones under os.tmpdir() and then asks replaceDirectoryAtomic to rename that staged repo into the managed git directory, which fails with EXDEV across filesystems.

## Solution Assessment

Yes. Staging non-dry-run clones beside the managed repo target is the narrowest maintainable fix because it preserves the existing atomic replacement primitive and avoids adding a broader copy fallback or user-facing config workaround.
