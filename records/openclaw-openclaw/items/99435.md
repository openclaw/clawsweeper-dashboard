## Summary

Keep open: the PR targets the wrong harness path for the reported embedded-runner bug. The active embedded session path still uses `Agent.runWithLifecycle()`, which catches loop errors into assistant failure messages, so the mid-turn precheck signal can still be persisted instead of reaching the attempt runner.

## What This Changes

The PR adds a symbol-based agent-harness control-flow marker, marks `MidTurnPrecheckSignal`, and rethrows marked errors from `CoreAgentHarness.executeTurn()`.

## Best Possible Solution

Apply the control-flow handling at the active `Agent` lifecycle boundary or a shared loop boundary used by embedded sessions, then add focused regression coverage proving no synthetic assistant error is persisted and attach redacted after-fix runtime proof.
