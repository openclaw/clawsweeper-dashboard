## Summary

Keep this PR open for a narrow compatibility correction: the bounded-read approach and supplied runtime proof are useful, but applying the same 64 KiB limit to the documented `caPath` CA-bundle input can make existing Gateway TLS configurations fail at startup.

## What This Changes

The PR replaces unbounded Gateway TLS certificate, key, and CA file reads with a 64 KiB descriptor-based bounded reader and adds symlink and oversize coverage.

## Best Possible Solution

Retain bounded reads, but use a separately justified bounded limit for `caPath` that preserves documented CA-bundle/custom-chain deployments, with regression coverage for a valid bundle above 64 KiB and an oversized rejection case.
