## Summary

Keep open: current main and the latest release still lack the terminal-field JSONL precedence this PR adds. The patch looks correct and well scoped, but it intentionally changes CLI JSONL fallback reply-selection semantics, so a maintainer should accept that compatibility/message-delivery contract before merge.

## What This Changes

The PR updates full-buffer and streaming CLI JSONL parsing to prefer `task_complete.last_agent_message` and `phase:"final_answer"` over commentary or generic item text, with parser regression tests.

## Best Possible Solution

Land this parser fix after maintainers accept terminal-field precedence and structured commentary-only empty output, while keeping the broader channel-leak policy tracked separately on https://github.com/openclaw/openclaw/issues/25592.

## Reproduction Assessment

Yes. The linked report supplies a concrete JSONL shape, and current main source still ignores `task_complete.last_agent_message` and `phase:"final_answer"` while falling back to generic `item.text` or raw JSONL.

## Solution Assessment

Yes for the narrow parser bug, with a compatibility caveat. The shared CLI JSONL parser is the right boundary because both streamed and completed CLI runner paths consume it before final text is delivered.
