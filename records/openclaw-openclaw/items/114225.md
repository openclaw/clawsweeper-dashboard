## Summary

Keep this PR open. Its intended fallback follows the repository policy for trusted-source work, but the current classifier treats a generic `context deadline exceeded` as proof that the remote command never started; that can rerun a post-dispatch or indeterminate Linux gate locally and incorrectly turn its outcome green. The submitted tests are useful regression coverage, but they do not yet show a real delegated `check:changed` fallback run.

## What This Changes

This PR changes the changed-check wrapper so trusted-source checks fall back to local execution when Blacksmith delegation appears to have failed before starting the remote command.

## System Context

`check:changed` classifies modified paths and runs the relevant verification lanes. For heavier trusted-source lanes it delegates to Blacksmith Testbox; this patch interprets the wrapper result and may instead run the same checks locally.

## Best Possible Solution

Make local fallback depend on an explicit wrapper result that proves lease acquisition or dispatch never occurred, add a post-dispatch-timeout regression case, and capture a redacted real `check:changed` fallback run that shows the local-result notice.
