## Summary

Current main and v2026.6.11 still create credential-bearing bundled MCP temp directories whose only reclaim path is an in-process callback, so gateway death can strand them. This issue is paired with the open fix at https://github.com/openclaw/openclaw/pull/105643 and should remain open until that PR or another validated fix merges.

Likely related people
- @steipete — high confidence; introduced and repeatedly maintained the bundled MCP CLI path.
- @obviyus — high confidence; recent contributor to adjacent CLI live-session and retry lifecycle behavior.
- @vincentkoc — medium confidence; maintained adjacent agent RPC, cleanup, and gateway startup paths.

## What This Changes

Reclaim bundled MCP temporary configurations after their owning gateway dies without deleting configurations still used by surviving CLI subprocesses or concurrent gateways.

## Best Possible Solution

Land a lifecycle-owned reclamation path that removes only configurations proven orphaned, fails closed when liveness cannot be established, and has real gateway-restart proof covering an orphaned run, child-only termination, a surviving persistent child, and concurrent gateways.
