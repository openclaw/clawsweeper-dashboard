## Summary

Keep open, but do not queue a fix yet: the cache concern is plausible, while current plugin lifecycle guidance treats loader metadata as process-lifetime and requires a restart after plugin changes; the report does not yet demonstrate unbounded cache-key growth or retained plugin instances on current main.

## What This Changes

Investigate and prevent plugin module-loader cache entries from retaining obsolete plugin runtime objects after lifecycle changes.

## Best Possible Solution

Add a focused lifecycle regression that repeatedly exercises the supported plugin reload/update boundary, records cache cardinality and collectible objects, and only then add explicit bounded invalidation at the loader owner boundary if growth is proven.
