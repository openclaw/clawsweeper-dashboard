## Summary

Keep this issue open: current `main` still appears to apply log-oriented URL-query redaction before agent messages enter durable transcript storage, and the linked pull request is an active implementation candidate rather than a merged resolution. Because preserving opaque capability values changes a transcript security boundary, maintainers should explicitly confirm the narrow persistence policy before landing it.

## What This Changes

Preserve ordinary URL query values in persisted agent transcripts so later turns can reuse capability-bearing links, while retaining redaction for independently recognized secrets and all log/display surfaces.

## System Context

The Gateway persists agent messages and tool calls into JSONL session transcripts, then uses those transcripts to rebuild context for later turns. A transcript-specific redaction step currently transforms content before storage, whereas logging and tool-display redaction protect diagnostic output.

## Architecture Diagram

flowchart LR
  A[User or tool URL] --> B[Agent message or tool arguments]
  B --> C[Transcript redaction]
  C --> D[Session JSONL storage]
  D --> E[Later context replay]
  B --> F[Logging and tool display]
  F --> G[Redacted diagnostics]

## Best Possible Solution

Adopt one explicit transcript-storage policy that preserves replayable ordinary URL query values but still redacts recognized secrets across plain messages and structured tool arguments, with regression coverage separating transcript persistence from log/display output.
