## Summary

This is a fresh, well-scoped report of an approval-resolution integrity failure: Telegram receives a usable prompt, but another paired surface appears to resolve the canonical request as denied before the authorized Telegram operator can act. The open durable-approvals proposal is related design work, not a demonstrated fix for this immediate device-resolution path, so this issue remains necessary.

## What This Changes

Investigate and prevent a paired macOS device from automatically denying a pending Telegram exec approval before the configured approval timeout or an explicit authorized decision.

## Best Possible Solution

Trace the gateway approval request through paired macOS client delivery and resolution, then ensure only an explicit authorized reviewer action or the configured timeout can produce the terminal denial; add a regression test covering concurrent Telegram and paired-device visibility.
