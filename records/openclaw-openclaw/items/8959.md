## Summary

Keep open: current main and v2026.6.11 still only expose a single-select message presentation/message-tool contract; adjacent Discord components, Telegram managed callbacks or polls, Slack selected-options parsing, the merged hook PR, and the closed dialog PR do not provide the requested portable one-callback batch-select surface.

## What This Changes

Add a portable message-tool multi-select/select-menu capability so agents can present batch-selection options and receive all selected values in one callback across channels.

## Best Possible Solution

Design one additive portable batch-selection contract in message presentation/message tool, export and document it through the plugin SDK, and implement channel-specific rendering plus callback aggregation with fallback text semantics.

## Reproduction Assessment

Not applicable: this is a new-capability request, not broken established behavior. Source and docs on current main and v2026.6.11 verify that the requested portable batch-select contract is absent.

## Solution Assessment

Unclear on the exact API shape, but the best owner boundary is the shared message presentation/message tool contract. Channel-specific components, polls, modals, or pre-agent hooks are useful prior art but are too narrow to solve the cross-platform request.
