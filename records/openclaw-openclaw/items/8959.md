## Summary

Keep open: current main and v2026.6.11 still expose only a single-select shared message-presentation contract; adjacent Telegram managed multiselect callbacks, Slack multi-select payload parsing, the before_agent_reply hook, and the closed dialog-tool PR do not provide the requested portable message-tool batch-select API.

## What This Changes

The issue requests a cross-platform message-tool multi-select component that lets users choose multiple options visually and submit them to the agent in one callback/turn.

## Best Possible Solution

Design one additive portable batch-select presentation/message-tool contract with typed selected-value aggregation, SDK/docs updates, channel limits, fallback text, and channel adapter/callback coverage across Slack, Discord, Telegram, and plain fallback paths.

## Reproduction Assessment

Not applicable: this is a new-capability request, not a broken established behavior. Source, docs, release, and related-item inspection give high confidence that the requested portable batch-select contract is absent.

## Solution Assessment

Unclear on the exact API shape, but the best owner boundary is the shared message presentation/message tool plus plugin SDK contract. A channel-only renderer, hook-only workaround, or the closed dialog branch would not solve the cross-platform one-callback behavior.
