## Summary

Current main and v2026.6.11 still expose only scalar portable message-presentation selects. Native channel capabilities and the closed dialog proposal do not supply the requested cross-platform, one-submit selected-values contract, so the feature remains necessary but requires a maintainer API and product decision.

## What This Changes

Add a portable message-tool multi-select interaction that submits several selected values in one callback across supported channels.

## Best Possible Solution

Define an additive typed batch-selection presentation block with normalized `values[]` callback semantics, capability-aware channel rendering, a documented text fallback, public SDK exports, and focused contract tests; stage the initial channel matrix rather than promising unsupported native parity.

- **Defer structured collection:** Leave the scalar presentation surface unchanged until a broader forms or dialog product direction is sponsored.

## Reproduction Assessment

Yes, at source level: the current shared block schema, message-tool schema, public SDK, documentation, and Slack renderer expose scalar selection only. This is capability-gap verification rather than reproduction of broken existing behavior.

## Solution Assessment

Unclear until maintainers choose the public callback and initial channel-support contract. A shared additive presentation primitive is more maintainable than independent provider-specific message-tool parameters, but full parity should not be promised where a channel lacks equivalent native behavior.
