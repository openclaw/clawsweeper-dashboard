## Summary

Current main still lacks the requested batched cross-channel selection contract. The canonical presentation API, tool schema, documentation, and native channel renderers remain scalar; nearby Slack parsing, polls, CLI prompts, and the closed dialog proposal do not provide one portable array-valued callback. Keep this open for an explicit product/API decision rather than queueing a channel-only patch.

## What This Changes

Add a cross-platform multi-select component to the message tool so users can choose several options and submit them in one callback.

## Best Possible Solution

Extend the canonical `MessagePresentation` model with one additive typed multi-select block and structured array result, then align the message-tool schema, SDK export, docs, channel renderers, inbound normalization, and deterministic text fallback without adding a parallel top-level `selectMenu` parameter.
