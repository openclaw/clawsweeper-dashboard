- `impact:ux-friction`: Current workarounds either incur repeated model latency and cost or lose the requested visual batch-selection experience.

## Summary

Current main and v2026.6.11 still lack the requested portable batch-selection contract; native channel components and the merged pre-agent hook are useful adjacent infrastructure, but maintainers must decide whether array-valued multi-select belongs in the public message presentation API.

## What This Changes

Add a cross-platform multi-select message presentation control that submits all selected values in one callback and avoids a model turn for each toggle.

## Best Possible Solution

Extend the existing typed presentation seam with one additive batch-select block and structured selected-values result, keep rendering and transport encoding channel-owned, document explicit capability limits and text fallback, and use plugin hooks only for workflow state around the control.
