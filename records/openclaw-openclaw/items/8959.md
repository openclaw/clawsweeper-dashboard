## Summary

Keep open: current main and the latest release still lack the requested portable message-tool batch-select contract. Existing Slack, Discord, Telegram, poll, wizard, and plugin-hook primitives are useful adjacent pieces, but none provides one shared message presentation API with min/max multi-select semantics and one selected-values callback across channels.

## What This Changes

The issue requests a cross-platform multi-select capability in the message tool so agents can collect multiple selected values in one user interaction.

## Best Possible Solution

Design one additive portable batch-selection contract in message presentation/message tool, export and document it through the plugin SDK, and implement channel-specific rendering plus callback aggregation with fallback text semantics.

## Reproduction Assessment

Not applicable: this is a new-capability request, not a broken established behavior. Source, docs, release-tag, and related-item inspection give high confidence that the requested portable batch-select contract is absent.

## Solution Assessment

Partly yes: the shared message presentation/message tool boundary is the right owner surface for a cross-platform component. The exact API shape is still unclear and should not be implemented as a channel-only renderer, poll workaround, or closed dialog-branch resurrection without maintainer direction.
