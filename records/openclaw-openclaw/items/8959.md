## Summary

Keep open: current main has portable buttons and single-select presentation plus adjacent poll, hook, and modal primitives, but it still does not provide the requested cross-platform message-tool multi-select block with min/max selection and one selected-values callback. The closed dialog PR is useful prior art but was not merged, and the open Slack modal issue is channel-specific rather than a replacement for this portable contract.

## What This Changes

The issue requests a portable message-tool multi-select component that lets users select multiple options visually and submit them as one callback/agent turn.

## Best Possible Solution

Design one additive portable batch-selection contract in message presentation/message tool, export and document it through the plugin SDK and https://docs.openclaw.ai/plugins/message-presentation, then implement channel-specific rendering plus callback aggregation and fallback semantics.

## Reproduction Assessment

Not applicable: this is a new-capability request, not a broken established behavior. Source, docs, related-item, and current-main inspection give high confidence that the requested portable batch-select contract is absent.

## Solution Assessment

Unclear on the exact API shape, but the best owner boundary is the shared message presentation/message tool contract rather than a channel-only renderer, poll-only workaround, or closed dialog branch.
