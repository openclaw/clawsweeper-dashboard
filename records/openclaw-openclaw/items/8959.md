## Summary

Current main and v2026.6.11 still expose only scalar portable selects. Discord has provider-native multi-value controls, but the requested shared one-submit selected-values contract remains missing and needs an explicit product/API decision. ([docs.openclaw.ai](https://docs.openclaw.ai/plugins/message-presentation?utm_source=openai))

## What This Changes

Add a portable message-tool multi-select UI that batches multiple choices into one callback across supported channels with a usable fallback.

## Best Possible Solution

Extend the canonical MessagePresentation select model additively with explicit multiple-selection cardinality and one structured aggregate-submit callback, render it natively where supported, provide deterministic text degradation elsewhere, and ship SDK docs plus channel and compatibility coverage.

## Solution Assessment
