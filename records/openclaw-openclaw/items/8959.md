## What This Changes

Add a portable message-tool multi-select component that collects several visually selected values and submits them in one callback and agent turn.

## Best Possible Solution

Define an additive typed multi-select presentation action in the shared SDK with ordered selected-value arrays, explicit min/max rules, capability-aware text fallback, docs, and compatibility tests; phase native Discord and Slack renderers first, then add Telegram only after an explicit Mini App or alternative transport decision.

## Risks / Open Questions

- A public multi-select addition must define additive naming, min/max validation, ordered array payloads, stable option identity, and callback encoding without changing existing scalar-select behavior.
- Discord, Slack, Telegram, WhatsApp, and text fallbacks have materially different interaction capabilities, so claiming portable parity without a precise capability and degradation contract could create inconsistent workflows.
- Using Telegram Mini Apps would introduce hosting, identity, authorization, lifecycle, and security decisions beyond ordinary message rendering; it should not be assumed as the default Telegram implementation.
