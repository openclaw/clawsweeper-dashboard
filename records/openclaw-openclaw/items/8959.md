## Summary

Current main still exposes only scalar portable selects; native or adjacent multiselect capabilities do not provide the requested shared one-callback contract. This remains a valid but large public-API feature that needs maintainer product direction before implementation.

## What This Changes

Add a cross-platform message-tool multi-select that returns all selected values in one interaction and agent turn.

## Best Possible Solution

Define one additive typed batch-select presentation block with a structured selected-values result and explicit submit semantics, then add native channel rendering where supported and a documented numbered-text fallback elsewhere.
