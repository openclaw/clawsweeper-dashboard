## Summary

Keep open: current main and v2026.6.11 still expose only a portable single-select message presentation/message-tool contract, while related dialog, Slack modal, Telegram decision-packet, poll, and native component paths do not implement the requested cross-platform multi-select selected-values callback contract.

## What This Changes

Request support for a cross-platform multi-select message component so agents can collect several selected values in one user interaction instead of one agent turn per click.

## Best Possible Solution

Design an additive portable batch-selection presentation/message-tool contract with typed selected-value aggregation, explicit limits and fallback semantics, SDK/docs updates, and channel adapter coverage for Slack, Discord, Telegram, and non-native fallbacks.

## Solution Assessment

Unclear on exact API shape, but the best owner boundary is the shared message presentation/message tool contract rather than a Slack-only modal API, Telegram-only decision-card flow, Discord-only component primitive, existing poll action, or the closed dialog branch.
