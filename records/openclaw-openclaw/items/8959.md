## Summary

Keep open for a maintainer product decision. Current public message-presentation documentation still describes a scalar select control, while the requested one-submit batch selection needs an additive shared callback contract and coordinated channel behavior; the closed dialog PR does not implement or supersede that work.

## What This Changes

Add a portable message-tool control that lets users visually select multiple options and submit the whole selection to the agent in one interaction.

## System Context

The message tool turns an agent response into portable presentation blocks that channel plugins render for users. Channel callbacks then return interaction data to the agent, so a multi-select feature must define one shared selection payload before Discord, Slack, Telegram, and fallback renderers can implement it consistently.

## Architecture Diagram

flowchart LR
  A[Agent message tool] --> B[Shared message presentation]
  B --> C[Plugin SDK contract]
  C --> D[Channel renderers]
  D --> E[User batch selection]
  E --> F[Structured callback to agent]

## Best Possible Solution

Approve an additive shared multi-selection presentation contract with typed selected-values callbacks, explicit limits and fallback semantics, then implement only the channel adapters that can honor that contract and document their capability matrix.
