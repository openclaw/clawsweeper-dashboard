## Label Justifications

- `P1`: The PR fixes a user-visible Control UI failure to stop a selected active channel session and affects cancellation of real channel work.
- `merge-risk: 🚨 compatibility`: The new optional Gateway API field and Control UI default behavior introduce a durable cancellation contract that existing clients must continue to omit safely.
- `merge-risk: 🚨 session-state`: The patch changes how an active session transitions when an abort also removes its queued follow-up and lane work.
- `merge-risk: 🚨 message-delivery`: Discarding queued channel-session work intentionally prevents its future model requests and outbound messages, so the exact policy must be confirmed.

## Summary

Keep this PR open for maintainer review: the reported selected-session stop gap has strong exact-head proof and the patch appears mechanically coherent, but it intentionally establishes a new public queue-discard policy for Control UI stops that needs explicit owner confirmation before merge.

## What This Changes

The PR routes Control UI stops without a browser-local run ID through `sessions.abort` for the selected non-global session and adds opt-in `clearQueued` cleanup for that session’s follow-up and lane queues.

## Best Possible Solution

Confirm that a user-directed stop of a selected non-global channel session should cancel both its active run and its queued successors, then rebase onto current `main` and land with the existing protocol, SDK-compatibility, authorization, and UI coverage intact.
