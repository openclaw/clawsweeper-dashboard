## Summary

This PR has credible proof for the selected-session stop flow and no discrete patch defect established in this review, but it introduces a public `clearQueued` cancellation contract that intentionally discards queued session work. A Gateway/session owner should explicitly approve that user-visible queue-clearing policy and refresh the branch against current `main` before merge.

## What This Changes

The branch makes Control UI stop selected channel-backed sessions through `sessions.abort`, adds opt-in `clearQueued` protocol cleanup for non-global key-only aborts, and updates active-run lifecycle projections and tests.

## Best Possible Solution

Keep the two-path stop design only if the Gateway/session owner explicitly confirms that a Control UI stop of a selected non-global channel session should also discard that session’s queued successors; then rebase and re-run focused isolation, queue, protocol, and upgrade-compatibility checks.
