- `P1`: The PR repairs a broken Control UI stop workflow for active channel sessions, where queued work may otherwise restart after the visible run stops.

## Summary

This remains a useful bug-fix PR, and the supplied exact-head QA output now demonstrates the selected-session stop and queue-isolation behavior. It should stay open for maintainer review because it introduces a public Gateway cancellation semantic (`clearQueued`) whose permanent queue-discard policy needs explicit acceptance before merge.

## What This Changes

The PR routes Control UI stops without a browser-local run ID through `sessions.abort` for the selected non-global session and adds opt-in `clearQueued` cancellation cleanup.

## Best Possible Solution

Keep run-ID cancellation unchanged, accept `clearQueued` only as the explicit selected non-global session-stop policy, and land it with the documented compatibility boundary and focused isolation coverage intact.
