## Label Justifications

- `P1`: The PR changes how active channel-session work is stopped from the primary Control UI, including whether queued work may continue.
- `merge-risk: 🚨 compatibility`: An optional public `sessions.abort.clearQueued` parameter introduces a new cancellation contract that external callers may adopt.
- `merge-risk: 🚨 session-state`: The new behavior clears follow-up and lane queues associated with the selected persisted session.
- `merge-risk: 🚨 message-delivery`: Discarding queued successor work can intentionally suppress future model execution and outbound channel messages for that session.

## Summary

Keep this PR open for maintainer review. The prior key-only compatibility concern appears addressed by preserving the default `sessions.abort` payload, but the latest real runtime proof is for `75616c9`, not the current `0fbbb939` head after three subsequent force-pushes; the new opt-in queue-discard semantics also need explicit acceptance as a public Gateway protocol contract.

## What This Changes

The PR routes Control UI `/stop` without a browser-local run ID through `sessions.abort` for the selected non-global channel session and adds optional `clearQueued` cleanup for that session’s queued work.

## Best Possible Solution

Keep the existing `chat.abort` behavior for browser-owned and global runs, accept the narrowly documented opt-in `clearQueued` session contract only if maintainers want selected channel stops to discard queued successors, then rebase and capture the same real Gateway/Control UI isolation scenario on the exact merge head.
