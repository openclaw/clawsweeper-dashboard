## Summary

Keep open. Current main retains Azure deployment support for backend realtime bridges, but Control UI Talk still uses a browser WebRTC path or a Gateway relay that requires OpenAI Platform credentials; it does not provide the requested Azure Foundry server-side relay, Azure-specific configuration, diagnostics, or live proof. The member’s June 9, 2026 Azure check also confirms this is an intentional feature request awaiting feasible Azure capacity and design review.

## What This Changes

Add first-class Azure Foundry/Azure OpenAI GPT Realtime support for Talk through a server-side Gateway relay so Azure credentials never reach browser clients.

## System Context

Talk connects a browser or mobile client to a realtime voice provider through either direct WebRTC or a Gateway relay. The OpenAI plugin supplies realtime transport and credentials; the Gateway turns that into live audio, transcripts, tool calls, and agent handoff.

## Architecture Diagram

flowchart LR
  A[Talk browser or mobile client] --> B[Gateway Talk session]
  B --> C{Selected transport}
  C -->|Direct WebRTC| D[OpenAI client-secret route]
  C -->|Gateway relay| E[Server-side realtime bridge]
  E --> F[Realtime provider endpoint]
  F --> G[Audio, transcript, tool events]
  G --> B
  B --> A

## Best Possible Solution

Extend the existing bundled OpenAI realtime transport with an explicitly server-only Azure Foundry relay mode, supporting a narrowly defined initial credential contract, Azure GA endpoint/deployment validation, Azure-specific errors, focused regression coverage, docs, and a redacted live Azure smoke before release.
