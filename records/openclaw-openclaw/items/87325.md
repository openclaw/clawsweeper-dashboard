## Summary

Keep open: current main still has only partial Azure deployment bridge plumbing, and the requested first-class Azure Foundry GPT Realtime Talk path needs provider/auth/security design plus live Azure proof before cleanup can close it.

## What This Changes

Request first-class Azure Foundry/Azure OpenAI GPT Realtime Talk through Gateway Relay so Azure credentials stay server-side and Talk uses Azure deployments instead of direct OpenAI Platform browser credentials.

## Best Possible Solution

Implement the Azure Foundry Realtime path in the OpenAI provider plus Talk Gateway relay with server-side API-key and Entra handling, GA endpoint selection, Azure-specific diagnostics, focused tests, docs, and live Azure proof.
