## Summary

Keep open: current main and the latest release still leave the Discord channel-info resolver cache without a size bound, while this PR is focused, proof-backed, and has no blocking review findings.

## What This Changes

The PR adds a 1000-entry FIFO cap to the Discord channel-info resolver cache, exports the cap through the local monitor test barrel, and adds a unit test for oldest-entry eviction.

## Best Possible Solution

Land the focused Discord resolver cache cap after routine maintainer checks, keeping the behavior internal to the Discord plugin and avoiding a new config surface.

Yes. Current main shows the resolver cache stores distinct channel IDs without a size bound, and the PR body includes terminal proof that filling 1001 IDs evicts the oldest entry after the fix.

## Solution Assessment

Yes. Bounding the existing resolver cache at its write helper is the narrow maintainable fix; replacing this resolver cache with a larger lower-level entity-cache refactor is not necessary for this specific memory-bound bug.
