## Label Justifications

- `P0`: The changed early return can create an approval authorization bypass for arbitrary users admitted by open QQBot direct-message policy.
- `merge-risk: 🚨 security-boundary`: The PR changes who may resolve sensitive approval callbacks by replacing explicit actor authorization with an unconditional direct-chat allowance.

## Summary

The prior blocker remains: the new direct-chat early return treats every QQBot C2C sender as an authorized approver, but current QQBot policy allows open or wildcard C2C access by arbitrary users and deliberately keeps fallback approval buttons behind an explicit non-wildcard authorization boundary. The linked bug is real, but this branch replaces a denial bug with a security-boundary bypass and still lacks after-fix runtime proof.

## What This Changes

The PR makes implicit QQBot approval callbacks in direct C2C conversations bypass command authorization and adds unit cases for absent and wildcard DM allowlists.

## Best Possible Solution

Keep the existing fail-closed callback gate and authorize direct approvals through a concrete trusted identity—preferably the approval request's bound intended recipient if that identity is carried end-to-end, otherwise documented explicit approver or owner configuration—with tests and redacted runtime proof for both allowed and denied C2C actors.
