## Summary

Keep this PR open but do not merge the current head: it removes an intentional approval-authorization boundary for every direct QQBot callback, while QQBot open-DM policy permits users beyond the bot owner. The prior P1 finding remains unresolved on the unchanged head, and after-fix runtime proof is still absent.

## What This Changes

The branch makes fallback approval callbacks in QQBot direct C2C conversations bypass command authorization and adds unit cases for absent and wildcard DM allowlists.

## Best Possible Solution

Keep the explicit authorization gate; if direct requesters should approve their own operations, bind each approval end to end to its originating sender and conversation, reject every other C2C sender, and prove both paths in a real QQBot-style runtime flow.
