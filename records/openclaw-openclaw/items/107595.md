## Summary

Keep open: the patch removes the authorization check for every direct QQBot approval callback, but a C2C sender is not necessarily the bot owner and open-DM configuration intentionally admits arbitrary senders, reopening the approval boundary tightened by https://github.com/openclaw/openclaw/pull/87154.

## What This Changes

The PR unconditionally permits implicit approval-button callbacks in direct QQBot conversations and adds unit cases for absent and wildcard DM allowlists.

## Best Possible Solution

Authorize direct approval callbacks against a stable trusted approver identity—configured approvers, effective explicit command authorization, or a maintainer-approved paired owner—while preserving denial for other open-DM senders and covering both outcomes with runtime proof.
