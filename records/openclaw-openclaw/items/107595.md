## Summary

Keep open for revision: the reported approval timeout is source-reproducible, but current behavior is an intentional, documented security boundary and this patch would allow untrusted direct-message users to approve privileged fallback requests.

## What This Changes

The PR makes QQBot direct C2C fallback approval buttons bypass command authorization while retaining the existing authorization gate for group conversations, with tests for absent and wildcard DM allowlists.

## Best Possible Solution

Keep explicit approver or command-owner authorization for C2C fallback buttons, provide an actionable denial message or setup recovery pointing users to `channels.qqbot.execApprovals.approvers`, and prove both authorized-owner success and unauthorized-open-DM rejection in a real QQ flow.

## Reproduction Assessment

Yes at source level: an unconfigured fallback click from a C2C sender without explicit authorization reaches the current command gate and is denied, matching the reporter's timeout. That denial is also the documented security behavior rather than proof that all direct senders should be authorized.

## Solution Assessment

No. An unconditional C2C bypass is not the narrowest safe fix because open or wildcard DM policy does not establish owner identity; the supported solution is an explicit approver or existing owner-authorization path with clearer recovery guidance.
