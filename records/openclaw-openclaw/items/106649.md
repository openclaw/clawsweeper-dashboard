## Summary

Keep this issue open: current main performs a redundant registry lookup on every plugin HTTP request after the lazy handler has loaded, and no related item or current implementation owns the focused optimization. The proposed boolean cache is unsafe because registries may be re-pinned, but switching to a loaded-handler fast path can remove the wrapper lookup while preserving dynamic routing. 

## What This Changes

Avoid repeatedly checking the plugin HTTP route registry after the lazy request handler has initialized.

## Best Possible Solution

Keep dynamic registry resolution inside `handlePluginHttpRequest`, but make the runtime wrapper call the loaded handler directly after first initialization and add a regression test proving imports initialize once while later requests avoid the redundant wrapper lookup.

## Solution Assessment

The issue is valid, but permanently caching an `httpRoutes` boolean is not the best fix because registries may be re-pinned. A loaded-handler fast path is the narrowest maintainable solution because it removes only the redundant wrapper lookup.
