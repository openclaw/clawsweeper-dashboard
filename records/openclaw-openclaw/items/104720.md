## Label Justifications

- `P1`: A routine beta update can deterministically disable durable semantic recall for Gemini-backed agents, while provider quotas can make rebuilding impractical.
- `impact:session-state`: The provider-key mismatch makes existing persistent memory indexes unavailable to agent retrieval despite unchanged embedding semantics.

## Summary

The report is valid and still necessary: current main hashes Gemini’s generated versioned client-identification header into durable memory identity, so a version-only change can pause an otherwise compatible index. No open fix PR or duplicate owns the repair.

## What This Changes

Prevent Gemini’s versioned `x-goog-api-client` identification header from invalidating otherwise compatible durable-memory indexes.

## Best Possible Solution

Continue sending Google’s required attribution header, exclude only framework-generated `x-goog-api-client` from Gemini’s durable identity, and add a persisted-index upgrade regression test while preserving semantic endpoint, model, dimensions, and user-controlled headers.
