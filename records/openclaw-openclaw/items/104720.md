## Summary

Keep this issue open: current main still hashes Gemini’s generated versioned client-attribution header into durable-memory identity, so an OpenClaw version-only change can pause an otherwise compatible index. The latest stable release predates the attribution change, no duplicate or open fix PR owns the repair, and the remaining fix is narrow and queueable.

## What This Changes

Exclude Gemini’s versioned client-identification header from durable-memory compatibility identity when embedding-semantic settings are unchanged.

## Best Possible Solution

Filter only the generated Gemini attribution header from persisted memory identity, preserve outbound attribution and semantic custom-header sensitivity, and add an upgrade regression test proving an existing index remains valid across client-version changes.
