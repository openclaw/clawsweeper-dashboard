## Summary

Keep open: the PR is a useful security-hardening direction, but the current patch still leaves existing plaintext SQLite auth rows unencrypted, treats unreadable encrypted rows as malformed/plain data, and lacks real raw-database proof for the new key path.

## What This Changes

The PR adds an auth-profile crypto helper and routes SQLite `auth_profile_store` reads/writes through an AES-256-GCM envelope when `OPENCLAW_AUTH_PROFILE_SECRET_KEY` is set.

## Best Possible Solution

Rework this into a migration-safe encrypted-store design that deliberately rewrites existing plaintext rows, fails closed on unreadable encrypted rows, documents key custody/recovery/rotation, and proves the raw SQLite upgrade behavior.
