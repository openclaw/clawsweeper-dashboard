## Summary

The reported Feishu fallback bug is valid, and the PR’s `onSkip` change is directionally correct. However, the unconditional delivery-time reset is order-sensitive and can erase a later intentional-silence signal when an earlier queued delivery executes afterward, so the patch should not merge as-is. After-fix evidence is also mock-only rather than a live Feishu DM run.

Likely related people: @vincentkoc (high confidence, repeated Feishu dispatcher work), @Takhoffman (medium confidence, recurring Feishu fix merger and adjacent owner), and @steipete (medium confidence, shared reply-pipeline refactors).

## What This Changes

Records silent block skips in the Feishu reply dispatcher, clears the silence marker on subsequent deliveries, and adds regression coverage for fallback suppression and later failed deliveries.

## Best Possible Solution

Make silent-reply bookkeeping follow dispatcher enqueue order—preserving a later silent skip against earlier queued work while clearing it only for a genuinely later visible delivery attempt—then add inverse-order regression coverage and provide a redacted live Feishu DM transcript or logs.
