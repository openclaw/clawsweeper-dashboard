## Summary

This PR remains necessary and the single-node direction is promising, but it is not merge-ready: current head blocks automatic CLI installation during fresh remote onboarding and would bypass current main’s expanded Mac approval-policy response. The protected maintainer-labeled change also needs inspectable signed-app proof after those defects are fixed.

## What This Changes

The PR makes the macOS app launch the TypeScript node-host as a private worker, combines its CLI capabilities with native Mac commands under one Gateway node identity, and updates onboarding, protocol bridging, documentation, and tests.

## Best Possible Solution

Keep the app as the sole Gateway node and the TypeScript runtime as the canonical CLI-owned command implementation, but add explicit Mac adapters for approval responses, make remote CLI installation automatic without starting a local Gateway, rebase onto current main, and prove fresh local, fresh remote, upgrade, reconnect, approval, worker-owned command, and native TCC command paths in a signed app.
