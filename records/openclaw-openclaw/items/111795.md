## Summary

Keep this PR open, but it is not merge-ready: the new recovery marker is not persisted by the default SQLite-backed Workboard store, so the next dispatch reload can still reapply the dependency or schedule hold. The linked issue remains the canonical bug report while this PR is its candidate fix.

## What This Changes

The branch adds a scoped `statusHoldOverride` metadata field intended to keep `force: true` Workboard promotions dispatchable until the card reaches a terminal state.

## Best Possible Solution

Serialize and deserialize the scoped override in the SQLite Workboard metadata path, then add a durable-store regression proving a forced card remains dispatchable across the reload that dispatch performs and loses the override only on terminal exit.
