## Summary

Keep open: current main and v2026.6.11 still have the generic durable outbound queue and sibling reconnect drains, but Discord does not drain its pending outbound deliveries after gateway reconnect, and the only exact candidate fix is closed unmerged.

## What This Changes

The issue asks for Discord outbound deliveries that fail during gateway WebSocket reconnects to be queued and drained after reconnect, using the existing delivery queue behavior seen in other channel plugins.

## Best Possible Solution

Wire Discord gateway READY-after-reconnect into the existing drainPendingDeliveries queue path for the affected account, with focused lifecycle/retry tests and no new config surface unless maintainers explicitly ask for an opt-out.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Not as a live run in this review, but yes at source level: enqueue a failed Discord outbound delivery, transition the gateway from disconnected to READY, and current main has no Discord reconnect drain call to replay it.

## Solution Assessment

Is this the best way to solve the issue? Yes: reusing the existing delivery queue drain from the Discord lifecycle is narrower and more maintainable than adding a separate Discord queue or a new config option.
