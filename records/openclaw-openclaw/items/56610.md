## Repair Work Prompt

Fix Discord outbound message loss during gateway WebSocket reconnect windows. Current main writes outbound delivery intents before platform send and exposes drainPendingDeliveries, but runDiscordGatewayLifecycle never drains pending Discord entries after reconnect and Discord delivery retry has no gateway-disconnected retry path. Implement a narrow Discord plugin fix using openclaw/plugin-sdk/delivery-queue-runtime; key the drain by the resolved Discord account id, select only Discord entries for that account, and avoid adding channels.discord.delivery.queue or any new config surface. If broadening retry when the gateway is disconnected, use the resolved account.accountId for gateway registry lookup and add omitted-default-account coverage. Use https://github.com/openclaw/openclaw/pull/94320 only as context, not as an already-correct patch; preserve inbound reconnect/dedupe behavior and avoid touching unrelated delivery architecture. Include focused unit coverage plus redacted live Discord reconnect proof when feasible.
