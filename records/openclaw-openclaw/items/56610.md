## Summary

Keep this open: current main still has durable Discord send/write-ahead queue support, but it does not drain Discord pending deliveries on gateway reconnect and the only linked repair PR is closed unmerged.

## Best Possible Solution

Implement a Discord-owned reconnect drain that reuses the shared drainPendingDeliveries helper, filters by resolved account id, adds focused lifecycle/retry coverage, and avoids adding a new config surface unless maintainers explicitly request one.
