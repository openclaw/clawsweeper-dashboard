## Summary

Keep open. The report identifies a credible agent-runtime/configuration failure path: compaction target selection can retain the session model while the embedded compaction runner cannot resolve that model, and the existing reason classifier has no unknown-model category. This needs an owner decision on the compatible fallback and startup/Doctor behavior rather than a blanket change that treats every unknown compaction failure as recoverable.

Likely related people: Tak Hoffman (high-confidence precheck-route author) and Peter Steinberger (high-confidence merger of that route).

## What This Changes

The issue requests safer handling of an unavailable compaction model so a CLI-bound model configuration does not turn a long-session compaction attempt into an opaque failed turn.

## System Context

OpenClaw's built-in agent runtime estimates prompt size before sending a turn and invokes compaction when the transcript is too large. Compaction resolves an effective provider/model target and returns a classified result to the run loop, which either retries the prompt or surfaces an unrecoverable overflow failure.

## Architecture Diagram

flowchart LR
  A[Agent model and config] --> B[Effective compaction target]
  B --> C[Embedded or harness compaction]
  C --> D[Failure reason classification]
  D --> E[Overflow recovery decision]
  E --> F[Retry current turn]
  E --> G[User-visible failure]

## Best Possible Solution

Define a supported effective compaction target for non-embedded harness models, detect an unavailable target before long-session recovery, and return a targeted configuration/Doctor diagnosis; retain terminal overflow handling when no safe transcript-reduction path exists.

## Maintainer Decision

Required: true

Kind: product_direction

Question: For a session model owned by a non-embedded harness and no explicit compaction model, should OpenClaw select a supported embedded target automatically, require a configured compaction target with startup/Doctor diagnostics, or delegate compaction to that harness?

Rationale: The current fallback to the session model is an established tested behavior, while changing it affects model routing, startup diagnostics, and existing configurations; source inspection cannot establish the intended compatibility contract alone.

Likely owner: Peter Steinberger

Owner reason: He merged the precheck recovery path whose compatibility and user-visible failure semantics need to be defined.

Owner confidence: high

Options:

- **Require and diagnose a compatible target (recommended):** Keep the current fallback contract only where it is executable, otherwise fail early with a precise startup/Doctor repair path for `agents.defaults.compaction.model`.
- **Choose an embedded default automatically:** Select a known embedded-capable default when the session model belongs to a non-embedded harness, accepting a new implicit model-routing policy.
- **Add harness-owned compaction:** Have each applicable agent harness provide compaction so its session model never crosses into the embedded runtime.

## Reproduction Assessment

No high-confidence independently executed current-main reproduction was established in this read-only review. The source path is nevertheless reproducible in principle: use a non-embedded harness model with no explicit compaction target, grow the session to the precheck threshold, and observe target resolution plus the classified failure.

## Solution Assessment

Unclear. An explicit unavailable-target reason and early diagnosis are safer than making every unknown compaction result non-fatal, but maintainers must choose the long-term fallback/harness contract before implementation.
