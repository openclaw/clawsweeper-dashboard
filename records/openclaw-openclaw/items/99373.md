## Label Justifications

- `P1`: The report describes a production ambient-group workflow where reset can permanently hide channel messages from the agent context.
- `impact:message-loss`: A stale watermark can cause prompt-window filtering to suppress group messages that are no longer present in the active transcript.
- `impact:session-state`: The problem is session metadata drift: a chat-scoped watermark can outlive the transcript/sessionId it describes.

## Summary

Keep open: this is protected by the `maintainer` label, and current `main` still lacks the requested session-bound watermark validation for ambient transcript watermarks.

## What This Changes

The issue asks OpenClaw to invalidate ambient transcript watermarks when the sessionId changes so archived transcript rows are not filtered out of future prompt windows.

## Best Possible Solution

Stamp ambient watermarks with the current sessionId on write, ignore missing or mismatched sessionId watermarks on read, add reset/daily/delete coverage, and split the double-reset diagnosis if it proves distinct.

## Reproduction Assessment

Yes at source level, not as an executed live repro: current code stores and reads watermarks without sessionId, while prompt filtering treats that watermark as proof that older rows are transcript-owned. I did not execute a Telegram reset scenario in this read-only review.

## Solution Assessment

Yes, the proposed sessionId-bound watermark is the narrowest durable fix because it makes the state self-invalidating across reset/delete flows instead of relying on every reset path to remember cleanup. The double-reset observation should be diagnosed separately if it remains after the primary guard lands.
