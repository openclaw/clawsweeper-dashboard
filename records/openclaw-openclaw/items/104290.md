The PR adds a 10-second per-attempt timeout to Discord directory and allowlist API lookups and keeps cancellation active through response-body consumption.

## Best Possible Solution

Keep timeout ownership in the shared Discord request helper and opt only directory and allowlist lookup callers into the bounded per-attempt policy, covering both header wait and body consumption without adding user configuration or parallel request paths.
