## Summary

Keep this PR open: it addresses a real unbounded watcher-cache bug, but the patch is not merge-ready because eviction still happens after the replacement watcher allocation attempt and the proof does not show the real >32-template-path behavior.

## What This Changes

The PR adds a 32-entry cap to the usage-bar template file cache and closes the oldest cached watcher before storing a new template entry.

## Best Possible Solution

Evict and close the oldest cached watcher before opening the replacement watcher, then add focused eviction coverage and redacted real-run proof for more than 32 template files.

## Reproduction Assessment

Yes by source inspection, though I did not run a live repro here: current main caches one entry and watcher per distinct valid template path with no size bound. A focused check would load more than 32 valid template paths and assert eviction plus watcher closure before replacement watcher creation.

## Solution Assessment

No. The cache is the right fix boundary, but the current patch should free the oldest watcher before calling fs.watch for the replacement and should add regression coverage for that ordering.
