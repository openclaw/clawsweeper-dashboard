## Summary

Keep open: the PR targets a real source-visible resource leak, but the patch still evicts only after attempting to allocate the next watcher, and the contributor proof does not show the >32-template runtime path.

## What This Changes

Adds a 32-entry cap to the usage-bar template file cache and closes the oldest cached watcher before inserting the new entry.

## Best Possible Solution

Evict and close the oldest cache entry before opening the replacement watcher, add focused eviction coverage, and attach redacted terminal or live output that exercises more than 32 template files.

## Reproduction Assessment

Yes by source inspection, not by a live run here: current main keeps one cache entry and watcher per distinct valid template path with no size bound. A focused check would load more than 32 valid template paths and assert eviction plus watcher closure.

## Solution Assessment

No. The cache is the right fix boundary, but the implementation should free the oldest watcher before calling fs.watch for the replacement and should include regression coverage for that ordering.
