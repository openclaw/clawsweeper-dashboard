## Summary

Keep open: the PR targets a real source-reproducible watcher/cache leak, but the current patch still has cache-insertion ordering bugs and the screenshot proof does not demonstrate the changed >32-template eviction path.

## What This Changes

The PR adds a 32-entry cap to the usage-bar template file cache and closes the oldest cached watcher before storing a new entry.

## Best Possible Solution

Bound the usage-template cache at the insertion boundary by evicting an old watcher before opening a watcher for a new key, avoid evicting on overwrites, and prove it with focused tests plus contributor real-run evidence.

## Reproduction Assessment

Yes. Source inspection shows current main stores distinct valid template paths in a module-level Map and opens fs.watch watchers without a size cap; I did not run a live 33-path watcher repro in this read-only review.

## Solution Assessment

No. The cache boundary is the right place to solve this, but the PR needs to evict before watcher allocation, avoid eviction on same-key overwrites, and add focused coverage and real behavior proof.

## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P2] Evict before opening the replacement watcher:** `src/auto-reply/usage-bar/template.ts:149-156`
  - body: The new block runs after `watch(path, ...)` has already tried to allocate the replacement watcher. With a full cache and watcher/file-descriptor pressure, allocation can fail before this frees an old watcher, leaving the new template cached without live refresh even though evicting first could have preserved it.
  - confidence: 0.86
- **[P2] Only evict when adding a new cache entry:** `src/auto-reply/usage-bar/template.ts:149`
  - body: `cacheTemplateFile` is also used for paths already cached without a watcher after an earlier miss or invalid file. In that overwrite case `fileCache.set(path, entry)` does not grow the Map, but this condition can still delete an unrelated oldest entry and close its live watcher.
  - confidence: 0.82
