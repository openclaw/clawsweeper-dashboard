## Summary

Keep open: current main still treats configured provider and request headers as literal strings, while the remaining decision is whether OpenClaw should support generic runtime header placeholders or prefer narrower typed provider-affinity contracts.

## What This Changes

Requested dynamic interpolation for custom provider request headers so session, agent, or run identifiers can be sent to LLM providers such as Fireworks or LiteLLM.

## Best Possible Solution

Keep this as the canonical generic provider-header templating request until maintainers choose a narrow documented placeholder resolver or an explicit typed affinity/run-context header contract with security and precedence boundaries.

## Reproduction Assessment

Yes. Source inspection on current main shows configured provider and request header values are sanitized and merged as literal strings with no session, agent, or run placeholder resolver.

## Solution Assessment

Unclear. Generic templating covers the Fireworks and Langfuse/LiteLLM examples, but maintainers still need to choose whether the durable contract should be generic templates, typed affinity flags, or a narrower run-context header surface.
