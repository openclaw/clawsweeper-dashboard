## Summary

Keep open: current main still treats configured provider headers as literal strings, and the open related PRs cover narrower Fireworks/ZAI affinity or static per-agent header paths rather than the generic session/agent/run header templating requested here.

## What This Changes

The issue requests dynamic interpolation for provider request headers so session, agent, or run identifiers can be sent to custom LLM providers such as Fireworks.ai and LiteLLM-backed Langfuse tracing.

## Best Possible Solution

Keep this as the canonical generic provider-header templating request until maintainers choose a narrow documented resolver, allowed placeholders, identifier-egress policy, and interaction with the open typed/static header PRs.

## Reproduction Assessment

Yes. Source inspection on current main shows configured provider and request header values are sanitized and merged as literal strings with no session, agent, or run placeholder resolver.

## Solution Assessment

Unclear. Generic templating covers the reported Fireworks and Langfuse/LiteLLM use cases, but maintainers still need to choose whether the durable contract should be generic templates, typed affinity flags, or a narrower runtime header map.
