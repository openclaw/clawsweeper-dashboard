## Summary

Keep open: current main and the latest release still treat configured provider/request headers as literal strings, while related open PRs cover narrower affinity or scoped-header directions rather than the generic session/agent/run header interpolation requested here.

## What This Changes

Request dynamic interpolation for configured model-provider headers so values like `{{session.key}}`, `{{agent.id}}`, and `{{run.id}}` can be sent per request to providers or proxies.

## Best Possible Solution

Keep this as the canonical generic provider-header templating request until maintainers choose a narrow documented placeholder resolver or a typed provider affinity/run-context contract that preserves SecretRef and header precedence boundaries.

## Reproduction Assessment

Yes. Source inspection on current main and v2026.6.10 shows configured provider and request header values are sanitized and merged as literal strings with no session, agent, or run placeholder resolver.

## Solution Assessment

Unclear. Generic templating covers the Fireworks and Langfuse/LiteLLM use cases, but maintainers still need to choose whether the durable contract should be generic header templates, typed affinity flags, or a narrower run-context header map.
