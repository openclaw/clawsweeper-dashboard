## Summary

Keep open: current main and the latest release still treat configured provider headers as literal strings, while the open related PRs cover narrower provider-specific affinity or static override paths rather than generic session/agent/run header interpolation.

## What This Changes

The issue requests dynamic variable interpolation in custom LLM provider headers, such as resolving `{{session.key}}`, `{{agent.id}}`, and `{{run.id}}` before outbound provider requests.

## Best Possible Solution

Keep this as the canonical generic provider-header templating request until maintainers choose a narrow documented resolver, allowed placeholders, identifier-egress policy, and interaction with the open typed/static header PRs.

## Reproduction Assessment

Yes. Source inspection on current main and `v2026.6.11` shows configured provider and request header values are sanitized and merged as literal strings with no session, agent, or run placeholder resolver.

## Solution Assessment

Unclear. Generic templating covers the Fireworks and Langfuse/LiteLLM use cases, but maintainers still need to choose whether the durable contract should be generic header templates, typed affinity flags, or a narrower run-context header map.
