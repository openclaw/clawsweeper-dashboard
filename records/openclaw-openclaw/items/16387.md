## Summary

Keep open. Current main and v2026.6.11 still treat configured provider headers as literal strings, and the open related PRs cover narrower affinity/schema/static-header paths rather than this issue's generic session/agent/run placeholder contract.

## What This Changes

Request support for runtime placeholder interpolation in configured LLM provider headers so custom providers can send session-, agent-, or run-scoped header values.

## Best Possible Solution

Define one narrow, documented provider-request metadata contract that preserves static headers, SecretRef/auth handling, retries, and attribution headers while expanding only approved runtime placeholders.
