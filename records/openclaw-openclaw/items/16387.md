- `P2`: The request has real provider cost, cache-affinity, and observability impact, but it is a bounded provider-header feature rather than an outage or data-loss incident.
- `impact:security`: The requested placeholders could send stable OpenClaw session, agent, or run identifiers to third-party provider or proxy endpoints.

## Summary

Keep open: current main and the latest release still treat configured provider headers as literal strings, and the related open PRs cover narrower typed/static header paths rather than the generic session/agent/run header interpolation requested here.

## What This Changes

Support runtime placeholders in configured model-provider headers so provider requests can include session-, agent-, or run-specific values for cache affinity and tracing.

## Best Possible Solution

Keep this as the canonical generic provider-header templating request until maintainers choose a narrow documented resolver, allowed placeholders, identifier-egress policy, and interaction with the open typed/static header PRs.

## Reproduction Assessment

Yes. Source inspection on current main and v2026.6.11 shows configured provider and request header values are sanitized and merged as literal strings with no session, agent, or run placeholder resolver.

## Solution Assessment

Unclear. Generic header templating would solve the reported Fireworks and Langfuse/LiteLLM use cases, but maintainers still need to choose whether the durable contract is generic templates, typed affinity flags, or scoped run-context headers.
