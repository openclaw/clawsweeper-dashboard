## Summary

Keep open: current main and v2026.6.11 still treat configured provider headers as literal strings, and the related open PRs only cover narrower or partial header-affinity/config surfaces rather than the requested generic dynamic header templating.

## What This Changes

The issue requests runtime interpolation for configured model-provider headers so placeholders such as {{session.key}}, {{agent.id}}, and {{run.id}} can produce per-session or per-run provider request headers.

## Best Possible Solution

Keep this issue as the canonical generic provider-header templating request until maintainers approve a narrow documented placeholder contract or deliberately split it into typed affinity and run-context APIs.

## Reproduction Assessment

Yes for the source-level gap: current main and v2026.6.11 sanitize and merge provider/request header strings literally, with no runtime placeholder resolver for session, agent, or run values.

## Solution Assessment

Unclear. Generic templating would solve the reported Fireworks and LiteLLM/Langfuse cases, but maintainers still need to choose the durable contract and security boundary before implementation.
