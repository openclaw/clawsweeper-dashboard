## Summary

Keep open: current main and v2026.6.11 still treat configured provider/request header values as literal strings, while the related open PRs only cover narrower provider-specific or scoped static-header behavior rather than the requested generic runtime templating contract.

## What This Changes

The issue requests dynamic interpolation for configured LLM provider headers so session, agent, or run values can be sent to providers such as Fireworks and LiteLLM.

## Best Possible Solution

Keep this as the canonical generic provider-header templating request until maintainers choose a documented placeholder contract or explicitly split the work into narrower typed affinity/run-context features.

## Reproduction Assessment

Yes. Source inspection on current main and v2026.6.11 shows provider and request header values are sanitized and merged as literal strings with no session, agent, or run placeholder resolver.

## Solution Assessment

Unclear. Generic header templating solves the reported Fireworks and LiteLLM/Langfuse cases, but maintainers still need to choose whether the durable contract is templates, typed affinity flags, or a run-context header map.
