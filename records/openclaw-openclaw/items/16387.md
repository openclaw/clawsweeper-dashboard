- `impact:security`: The requested feature would intentionally send runtime identity values through outbound third-party HTTP headers.

## Summary

Keep open. Current main and v2026.6.11 still treat configured provider headers as literal strings, and the open related PRs cover narrower compat-schema, provider-specific affinity, or scoped static-header paths rather than this issue's generic runtime placeholder contract.

## What This Changes

Add runtime placeholder interpolation in custom model-provider headers so values like {{session.key}}, {{agent.id}}, and {{run.id}} can be sent per request.

## Best Possible Solution

Define one narrow, documented provider-request metadata contract that preserves static headers, SecretRef/auth handling, retries, attribution headers, and provider-owned stream hooks while expanding only approved runtime placeholders.
