## Summary

Keep open. Current main and the latest release still treat configured provider headers as literal strings, while the related open PRs only cover narrower static-header, schema, or provider-specific affinity paths rather than this issue's generic session/agent/run placeholder contract.

## What This Changes

The issue requests dynamic runtime interpolation for custom-provider headers so values like session, agent, or run identifiers can be sent per LLM request.

## Best Possible Solution

Define one narrow, documented provider-request metadata contract that preserves static headers, SecretRef/auth handling, retries, and attribution headers while expanding only approved runtime placeholders.
