## Summary

Keep open: current main and v2026.6.11 still lack dynamic interpolation for configured provider/request headers, and the related open PRs cover narrower or overlapping header-affinity directions rather than replacing this canonical request.

## What This Changes

Request dynamic placeholders in custom LLM provider headers, such as session, agent, or run identifiers, so provider/proxy headers can vary per OpenClaw session or turn.

## Best Possible Solution

Keep this as the canonical generic provider-header templating tracker until maintainers choose a documented placeholder contract or explicitly split it into narrower typed affinity/run-context features.

## Reproduction Assessment

Yes. Source inspection on current main and v2026.6.11 shows provider and request header values are sanitized and merged as literal strings with no session, agent, or run placeholder resolver.

## Solution Assessment

Unclear. Generic header templating solves the Fireworks and LiteLLM/Langfuse examples, but maintainers still need to choose whether templates, typed affinity flags, or a run-context header map are the durable contract.
