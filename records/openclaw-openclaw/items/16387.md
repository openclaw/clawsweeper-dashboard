## Summary

Keep open: current main and v2026.6.11 still treat configured provider/request headers as literal strings, while open related PRs cover narrower affinity or scoped-header directions rather than the generic session/agent/run header interpolation requested here.

## What This Changes

Request dynamic interpolation in custom LLM provider header config so values like `{{session.key}}`, `{{agent.id}}`, and `{{run.id}}` can be sent per request for provider cache affinity and tracing.

## Best Possible Solution

Keep this issue as the canonical generic provider-header templating request until maintainers choose a narrow documented placeholder resolver or explicitly prefer typed provider-specific affinity/run-context contracts.

## Reproduction Assessment

Yes. Source inspection on current main and v2026.6.11 shows configured provider and request header values are sanitized and merged as literal strings with no session, agent, or run placeholder resolver.

## Solution Assessment

Unclear. Generic templating covers the Fireworks and Langfuse/LiteLLM use cases, but maintainers still need to choose whether the durable contract should be generic header templates, typed affinity flags, or a narrower run-context header map.
