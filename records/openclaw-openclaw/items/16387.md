## Summary

Keep open: current main and v2026.6.11 still treat configured provider headers as literal strings, while related open PRs cover narrower Fireworks/OpenAI-compatible affinity, OpenRouter session forwarding, or static scoped header surfaces rather than generic session/agent/run header templating.

## What This Changes

The issue requests dynamic interpolation in custom LLM provider headers so values such as session, agent, or run identifiers can be sent at model-request time.

## Best Possible Solution

Keep this as the canonical generic provider-header templating request until maintainers choose a narrow documented resolver, allowed placeholders, identifier-egress policy, and interaction with the open typed/static header PRs.

## Reproduction Assessment

Yes. Source inspection on current main and v2026.6.11 shows configured provider and request header values are sanitized and merged as literal strings with no session, agent, or run placeholder resolver.

## Solution Assessment

Unclear. Generic templating covers the reported Fireworks and Langfuse/LiteLLM use cases, but maintainers still need to choose whether the durable contract should be generic header templates, typed affinity flags, provider-owned wrappers, or a narrower run-context header map.
