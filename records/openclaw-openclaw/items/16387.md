## Summary

Keep open: current main still lacks dynamic provider-header templating, and the related open PRs cover narrower Fireworks, ZAI, per-agent/per-cron, or run-context header directions rather than replacing this canonical product/security decision.

## What This Changes

The issue requests dynamic interpolation in provider header config so LLM requests can include runtime values such as session, agent, or run identifiers.

## Best Possible Solution

Keep this issue as the canonical generic provider-header templating request until maintainers choose a documented placeholder contract or explicitly split the work into narrower typed affinity and run-context header features.

Unclear. Generic header templating would solve the reported Fireworks and LiteLLM/Langfuse cases, but maintainers still need to choose whether the durable contract is templates, typed affinity flags, or a run-context header map.
