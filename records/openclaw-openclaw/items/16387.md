## Summary

Keep open: current main still treats configured provider headers as literal values, while the requested runtime header templating remains a security- and product-sensitive feature with overlapping but non-canonical open PRs.

## What This Changes

Request to support runtime interpolation of session, agent, and run variables in custom provider header config for per-session provider affinity or tracing headers.

## Best Possible Solution

Choose one secure, documented request-identity mechanism, then land a single maintained path with an explicit placeholder allowlist, tests, and docs while preserving static headers and SecretRef behavior.

## Reproduction Assessment

Yes for source-level confirmation: current main copies configured header strings literally and docs still describe static headers, so a `{{session.key}}` value would not be resolved. I did not run a live provider call because this read-only review already has a direct source path for the missing capability.

## Solution Assessment

Unclear as an implementation direction: dynamic header templating is plausible, but the best fix may instead be a provider-owned transport turn-state hook or a narrower compat flag for specific providers. Maintainers should decide the security and product shape before a new fix PR is queued.
