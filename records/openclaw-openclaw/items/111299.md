## Summary

Likely related people: cxbAsDev (recent stream-error coverage), vincentkoc (recent SSH sandbox work), and steipete (earlier SSH sandbox implementation history).

## What This Changes

This PR adds a no-progress watchdog while a local directory is archived into an SSH sandbox, then applies a 60-second SSH-exit grace after the local archive producer closes, with regression coverage for stalled processes.

## System Context

SSH sandbox setup streams a local workspace through `tar` into an SSH client and waits for both child processes to finish before an agent can use the remote sandbox. The new timers alter when that setup path aborts and therefore affect remote sandbox availability for slow or stalled hosts.

## Best Possible Solution

Keep the no-progress protection while `tar` is producing, but make any deadline after producer completion an explicitly owner-defined sandbox-operation policy with compatibility proof for slow remote extraction rather than an unconditional 60-second default.
