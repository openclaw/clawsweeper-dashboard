## Summary

Current main still leaves the bundled memory-lancedb plugin on vector-only retrieval, and no viable open or merged PR owns the missing hybrid behavior. The request is valid, but official ranking defaults, index lifecycle, fusion, and fallback policy require maintainer direction before implementation.

## What This Changes

Add BM25/full-text retrieval and vector fusion to the bundled memory-lancedb plugin so exact identifiers and semantic matches can both be recalled.

## Best Possible Solution

Keep the implementation inside `extensions/memory-lancedb`: choose an explicit default policy, create and verify an FTS index on `text`, pass normalized query text through every retrieval caller, fuse independently normalized vector and keyword results, preserve a visible vector-only recovery path, and prove fresh-table plus existing-table behavior.
