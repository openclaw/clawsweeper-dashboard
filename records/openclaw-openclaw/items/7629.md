## Summary

Keep open: current main and v2026.6.11 still leave the official memory-lancedb plugin on vector-only retrieval, while the exact prior implementation PR is closed unmerged and the open reranker PR excludes LanceDB.

## What This Changes

Add BM25 plus vector hybrid retrieval to the memory-lancedb plugin, including FTS indexing, hybrid config, query-text propagation, and search-quality parity with the default memory engine.

## Best Possible Solution

Implement a memory-lancedb-owned hybrid mode with explicit config/defaults, FTS index lifecycle handling, query-text propagation, vector-only fallback behavior, docs, and focused regression tests.

Yes, at source level: current memory-lancedb initializes a plain LanceDB table, accepts only embedding vectors in search, and rejects any hybrid config key. I did not run a live LanceDB recall because the missing code path is directly visible in current main and the latest release tag.

## Solution Assessment

Unclear until maintainers choose the product direction; the narrowest maintainable implementation would stay in extensions/memory-lancedb and preserve a clear vector-only fallback. A broad cross-core memory rewrite or default-on ranking change would be riskier than a plugin-owned, tested hybrid mode.
