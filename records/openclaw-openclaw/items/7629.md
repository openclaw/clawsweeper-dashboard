## What This Changes

Request to add BM25/full-text plus vector hybrid retrieval to `memory-lancedb`, including FTS indexing, config weights, and hybrid search/reranking.

## Best Possible Solution

Keep this as the canonical memory-lancedb parity enhancement, then implement it in the plugin after maintainers decide the hybrid default, FTS index lifecycle, scoring contract, and vector-only fallback behavior.

## Reproduction Assessment

Yes at source level: configure `memory-lancedb` and use `memory_recall`, `memory_forget`, `ltm search`, or auto-recall for an exact keyword; current main embeds the query and calls LanceDB `vectorSearch` without FTS/BM25 participation. This is a missing feature/parity gap rather than a broken existing contract.

## Solution Assessment

Unclear as proposed: the plugin owner boundary is right, but maintainers still need to choose defaults, index lifecycle, scoring, and fallback policy. The pinned LanceDB JavaScript API suggests a JS-specific FTS/vector/reranker design rather than copying the Python-style hybrid call from the issue body.
