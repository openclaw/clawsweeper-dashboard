Keep open: current main and v2026.6.11 still leave memory-lancedb on vector-only retrieval, and the only exact implementation PR is closed unmerged while adjacent memory-core/reranker work does not cover LanceDB parity.

## What This Changes

Request to add BM25 plus vector hybrid retrieval to the memory-lancedb plugin, including FTS indexing, hybrid config, and query-text search behavior.

## Best Possible Solution

If maintainers choose official parity, implement hybrid retrieval inside memory-lancedb with explicit config/defaults, FTS index lifecycle, query propagation, vector fallback, docs, and regression tests; otherwise document vector-only behavior and route advanced retrieval to external plugins.
