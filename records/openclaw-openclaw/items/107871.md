## Label Justifications

- `P1`: The reported race can remove every tool from an OAuth MCP server for an entire active agent session, and the proposed patch does not reliably restore that workflow.
- `merge-risk: 🚨 availability`: The changed connection path can still leave the server unavailable while delaying retirement and obscuring the actionable first connection error.

## Summary

Keep this PR open for revision: the reported session-wide MCP tool loss is credible, but the proposed retry reuses SDK lifecycle objects that cannot be connected a second time after the first attempt binds them, so it does not reliably fix the failure.

## What This Changes

The PR wraps session-bind MCP connections in three attempts with 300/600 ms backoff, skips retries for selected authentication errors, and adds unit tests for the retry classifier and attempt limit.

## Best Possible Solution

Make each retry a fresh MCP connection lifecycle—constructing a new client and transport through the existing owner boundary—preserve the original terminal error, and retire the server only after bounded fresh attempts or a confirmed permanent authorization outcome.
