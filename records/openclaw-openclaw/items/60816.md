## Summary

Keep this open: current main and the latest release still lack a distinct already-at-target noop result for identical edit followers, and the linked closing PR is still open, conflicting, and aimed at legacy edit-wrapper files rather than the active session edit tool.

## What This Changes

The issue requests edit-tool semantics where concurrent identical edits report normal success for the writer, noop for already-at-target followers, and errors for true mismatches or write failures.

## Best Possible Solution

Land a repaired active-runtime implementation that adds substring-safe already-at-target noop classification in src/agents/sessions/tools/edit.ts with focused coverage for single replace, edits[], true mismatch, and write-failure paths.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level. Same-file edit calls serialize through withFileMutationQueue; an identical follower can then read already-updated content, fail oldText matching, and hit the current mismatch-hint error path instead of a distinct noop.

## Solution Assessment

Yes for the requested semantics, but not via the linked PR as submitted. The maintainable fix belongs in the active session edit tool with substring-safe target-state classification and regression coverage.
