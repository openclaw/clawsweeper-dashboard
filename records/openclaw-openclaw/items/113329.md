## Summary

Close as implemented: OpenClaw already supports ordered image-generation fallbacks and, by default, adds other authenticated image providers after explicit candidates. It also records failed image-provider attempts before a later provider succeeds, so the single-provider 429 dead-end described here is no longer the current behavior.

## What This Changes

Add configured-provider visibility and explicit cross-provider fallback for image generation when a provider is rate-limited.

## System Context

The shared media-generation runtime receives an image request plus configured model preferences, builds an ordered candidate list from explicit and authenticated providers, and sends each candidate to its owning provider plugin until one succeeds or all attempts fail. Its result is returned through the agent and channel flow, including the attempted-provider context when failures are surfaced.

## Architecture Diagram

flowchart LR
  A[Agent or image_generate request] --> B[Image generation model settings]
  B --> C[Ordered candidate list]
  D[Authenticated provider inventory] --> C
  C --> E[Provider-specific image request]
  E --> F{Generation succeeds?}
  F -- Yes --> G[Image result to agent and channel]
  F -- No --> H[Failure attempt recorded]
  H --> C

## Best Possible Solution

Keep the existing automatic authenticated-provider fallback as the default, and direct users who need deterministic routing to an explicit `imageGenerationModel.fallbacks` list or to disabling automatic provider fallback.

Not applicable as an open defect: current main already has an explicit fallback list and default authenticated cross-provider fallback for image generation. ## Solution Assessment

Yes. The existing shared media-generation candidate resolver is better than a new image-only fallback system because it provides explicit ordering, automatic authenticated-provider discovery, and a supported opt-out for deterministic behavior.
