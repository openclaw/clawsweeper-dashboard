## Summary

Keep open. Current main has partial mobile queue primitives, but it still does not provide the requested durable iOS/Android phone outbox for arbitrary text and voice intents with persistence, idempotent replay, captured-time metadata, and privacy controls.

## What This Changes

Add a durable offline command queue for iOS/Android mobile app intents that captures text or voice while disconnected and syncs them to the Gateway when connectivity returns.

## Best Possible Solution

Define a staged mobile outbox contract first, then implement encrypted durable storage and idempotent reconnect replay for text and voice before adding broader queue-management UI.

## Solution Assessment

No, not as a single full SQLite, background-sync, and edit/reorder implementation. The best path is a staged payload, persistence, privacy, and replay contract that builds on existing iOS Watch and Android voice queue patterns.

## Risks / Open Questions

- Durable mobile storage would hold sensitive commands and possibly audio/location context, so encryption, retention, deletion, redacted diagnostics, and size limits need security design before implementation.
- At-least-once reconnect replay needs client-generated ids, captured-time metadata, Gateway acknowledgements, and dedupe behavior before mobile apps can safely flush delayed commands.
- Mobile OS background limits mean the product promise must distinguish foreground reconnect, best-effort background sync, and review-before-send behavior.
- A full cross-platform outbox, queue-management UI, protocol metadata, and background-sync implementation is too broad for a single automated fix PR without maintainer product decisions.
