## Summary

Keep open. Current main and the latest release still only have scoped mobile queue pieces, while the requested durable iOS/Android command outbox with persisted replay, idempotency, voice/text support, and privacy controls remains unimplemented; the open Android outbox PR is only a partial candidate path.

## What This Changes

Add a durable offline command queue for the iOS and Android node apps so text or voice intents captured while disconnected can persist locally and replay to the Gateway on reconnect.

## Best Possible Solution

Define a staged mobile outbox contract first, then land platform-specific durable text and voice replay with encrypted or OS-protected storage, idempotent Gateway acknowledgements, captured-time metadata, and visible queue review/delete controls.

Options:

- **Stage text outbox with explicit privacy contract (recommended):** Start with a narrow text-only mobile outbox, require idempotent Gateway acks, captured-time metadata, bounded OS-protected storage, delete controls, and real device proof before expanding to voice and queue management.
- **Design full cross-platform command outbox first:** Pause implementation until maintainers approve one iOS/Android contract covering text, voice/audio, edit/reorder UI, retention, Wi-Fi/background behavior, and diagnostics.
- **Defer beyond read-only mobile cache work:** Keep only offline transcript cache work in flight for now and revisit command replay after the security and mobile UX roadmap is clearer.

## Solution Assessment

No, implementing the full SQLite, background-sync, edit/reorder, notification, text, and voice proposal in one sweep is not the best path. The maintainable solution is a staged outbox contract that builds on the existing Android voice and iOS Watch queue patterns while settling privacy, idempotency, and replay semantics first.
