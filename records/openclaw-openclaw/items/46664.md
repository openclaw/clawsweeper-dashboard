## Summary

Keep open. Current main and the latest release still only have scoped queue primitives: iOS Watch chat has a persisted Watch-specific queue, Android voice has an in-memory FIFO, and iOS phone voice still errors when the Gateway is disconnected, so the requested durable cross-platform mobile command outbox remains unimplemented.

## What This Changes

Request to add a durable offline command queue for the iOS/Android node apps, including local storage, reconnect sync, status feedback, voice/text support, queue management, and replay semantics.

## Best Possible Solution

Define a staged mobile outbox contract first, then implement encrypted durable storage and idempotent reconnect replay for text and voice before expanding queue-management UI.

Not applicable: this is a feature request, not a broken existing behavior report. Source inspection gives high-confidence proof that the remaining gap is missing durable, general mobile outbox behavior rather than a reproducible regression.

## Solution Assessment

No for implementing the full SQLite, background-sync, edit/reorder, and notification proposal in one sweep. The maintainable path is a staged payload, persistence, privacy, and replay contract that builds on existing iOS Watch and Android voice queue patterns.
