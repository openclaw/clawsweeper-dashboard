## Summary

Keep open: this is a useful partial fix for the linked process-lifecycle bug, but the submitted patch is not merge-ready because its reconciliation check can cancel legitimate session-key-owned exec runs, it is currently conflicting with main, and it lacks after-fix real behavior proof.

## What This Changes

The PR adds process-supervisor orphan reconciliation, calls it from exec and process-tool paths, exports the new supervisor types, and adds focused unit coverage.

## Best Possible Solution

Rebase onto current main and implement reconciliation against a canonical owner identity that handles both session slugs and sessionKey-owned runs, with regression tests and redacted real behavior proof for owned-run preservation and orphan cleanup.

## Reproduction Assessment

Yes, at source level: the PR passes hasSession into reconciliation while supervisor records can store sessionKey as sessionId and the bash registry is keyed by session.id. I did not run a live exec/session-loss reproduction in this read-only review.

## Solution Assessment

No. In-process reconciliation is a plausible mitigation, but this implementation compares the wrong identifier namespace and is stale against current main; the safer fix is an owner-key-aware reconciliation contract with live proof.
