## Label Justifications

- `P1`: A regression in process ownership cleanup could terminate legitimate background exec work in active sessions.
- `merge-risk: 🚨 compatibility`: Existing exec runs that rely on session-key-backed ownership can start behaving differently when reconciliation runs.
- `merge-risk: 🚨 session-state`: The patch compares supervisor run ownership to the bash-session registry using mismatched identifiers, which can misclassify live run state as orphaned.
- `merge-risk: 🚨 availability`: Misclassified live runs are cancelled, which can interrupt long-running background jobs or agent helper processes.

## Summary

Keep open: the PR is a focused candidate for the linked orphan-process bug, but its new reconciliation compares supervisor ownership against the bash registry with mismatched identifiers and can cancel valid session-key-backed exec runs.

## What This Changes

The PR adds a `reconcileOrphans` process-supervisor API, calls it from exec/process tools, and adds tests for cancelling active supervisor runs whose owning bash session is gone.

## Best Possible Solution

Keep the in-process orphan cleanup direction, but make reconciliation use a single ownership contract across supervisor records and bash sessions, then prove both owned-run preservation and orphan cancellation in a realistic process run.

If a future caller passes one of those values, reconciliation will force-kill the run while recording a non-cancellation reason, so the API should only allow forced-cancellation reasons.
