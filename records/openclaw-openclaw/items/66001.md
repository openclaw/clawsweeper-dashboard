## Summary

Keep open: this PR targets a real process/session lifecycle bug, but the submitted patch is not merge-ready because the new reconciliation can false-cancel sessionKey-owned exec runs, the branch is conflicting, and after-fix real behavior proof is missing.

## What This Changes

The PR adds a process-supervisor orphan-reconciliation API, invokes it from bash exec and process-tool paths, and adds focused tests for cancelling missing-session runs while preserving tracked runs.

## Best Possible Solution

Repair the ownership predicate so orphan reconciliation uses the same canonical key as supervised exec runs, rebase onto current main, add real runtime proof, and keep the broader durable startup policy tracked unless maintainers explicitly accept this as only a partial mitigation.

## Reproduction Assessment

Yes, at source level. PR-head `runExecProcess` can supervise a run under `opts.sessionKey?.trim() || sessionId`, while the new `hasSession` predicate only checks the generated bash session map, so the next reconciliation can cancel a still-tracked run.

## Solution Assessment

No as submitted. In-process orphan reconciliation is a plausible mitigation, but the implementation must first use a session-key-aware ownership contract and the linked issue needs an explicit partial-fix or durable-policy decision.
