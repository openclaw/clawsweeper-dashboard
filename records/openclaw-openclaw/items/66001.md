## Summary

Keep open: this is a plausible partial fix for the open process-orphan issue, but as submitted it can cancel valid `sessionKey`-owned background exec runs because reconciliation checks the wrong ownership identity, and it still lacks real behavior proof.

## What This Changes

The PR adds `ProcessSupervisor.reconcileOrphans`, calls it from bash exec/process tooling, exposes registry tracking, and adds focused supervisor/process-tool tests.

## Best Possible Solution

Repair or replace the PR so reconciliation uses one canonical ownership identity, preserves `sessionKey`-owned runs in tests, and includes redacted real process proof while the canonical issue continues to track durable startup reaping policy.

Yes, from source inspection: current main stores the bash registry entry under the generated process session id, while supervisor records may store `opts.sessionKey`; the PR checks only the registry key and therefore returns false for live `sessionKey`-owned runs. No as submitted. The narrow in-process cleanup can be a useful mitigation, but the implementation must reconcile against a canonical ownership identity and prove it preserves `sessionKey`-owned runs before it is the best fix.
