## Summary

Keep open: current main and latest release v2026.6.11 still omit `agents.list[].identity.name` from the Google Chat typing fallback, and the markdown complaint is not fully resolved because Google Chat supports only a small text-message Markdown subset while the plugin still sends reply chunks directly without a Google Chat-specific conversion policy.

## What This Changes

The issue asks for Google Chat replies to stop showing unsupported raw Markdown syntax and for typing indicators to use the configured agent identity name instead of falling back to OpenClaw.

## Best Possible Solution

Keep this open until a Google Chat-owned fix adds `identity.name` to the typing fallback and applies a maintainer-approved text rendering policy that converts or normalizes OpenClaw Markdown to Google Chat text syntax, with focused tests and live Google Chat proof.

## Reproduction Assessment

Yes, source-level: current main and v2026.6.11 still omit `agent.identity.name` from the typing fallback and send Google Chat text chunks without a channel-specific Markdown conversion step. I did not run a live Google Chat workspace in this read-only review.

## Solution Assessment

Unclear as a complete fix: adding `agent.identity.name` to the existing fallback is the narrow typing fix, but a blanket Markdown strip is not clearly best because Google Chat supports a subset of Markdown. Maintainers should choose conversion, selective normalization, or metadata adjustment before implementation.
