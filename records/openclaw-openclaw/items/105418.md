## What This Changes

Updates the cron session reaper throttle timestamp when persistence sweeping fails.

## Best Possible Solution

Keep the existing five-minute per-store timestamp as the single retry boundary, update it after a failed sweep attempt, and add a deterministic error-then-immediate-retry regression test.
