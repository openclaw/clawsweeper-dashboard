## Summary

This PR remains necessary because current main still computes the native-card reply target from trimmed input but derives thread mode from the raw whitespace value. The exact-head patch removes that split decision across card, media, text, and delivery paths, adds focused regression coverage, and has convincing live Feishu proof with no actionable correctness or security finding.

## What This Changes

The PR centralizes Feishu reply-target and thread-mode normalization across native-card, media, text, and delivery sends, with regression coverage for whitespace reply and thread IDs.

## Best Possible Solution

Land one canonical Feishu reply-mode decision that trims both candidate identifiers and is reused unchanged by every part of a payload, retaining the submitted regression and live-proof coverage.
