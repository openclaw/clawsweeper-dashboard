## Summary

Keep open: current main already exposes some attribution in status and usage projections, but it does not provide the requested stable JSON contract for cron job id/name, channel target kind, and consistent per-row attribution across official status/usage surfaces.

## What This Changes

Request stable optional usage/status JSON fields for agent, session kind, cron job identity, channel, model, and runtime attribution so external dashboards can avoid joining OpenClaw internals.

## Best Possible Solution

Define a narrow additive JSON contract that reuses the current status and usage projections, adds optional cron/session/delivery labels with privacy-safe channel target handling, and coordinates human-readable display work with #51184.
