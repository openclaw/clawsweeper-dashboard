## Summary

Keep open: current main and the latest release already expose partial attribution in status and usage paths, but they do not provide the requested stable cron job identity, session-kind, and channel target-kind JSON contract. This should remain a maintainer-reviewed feature request because it expands public status/usage schema and has privacy-sensitive channel attribution choices.

## What This Changes

The issue requests richer official status/usage JSON attribution fields for agent, session kind, cron job identity, channel target kind, model, and runtime.

## Best Possible Solution

Define one privacy-aware status/usage attribution schema, reuse existing key, agentId, kind, channel, chatType, origin, model, and runtime fields where they are canonical, and add only the missing stable cron/session/channel labels with focused gateway, status JSON, docs, and tests.
