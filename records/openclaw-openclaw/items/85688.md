## Summary

Keep open: current main and v2026.6.11 still expose only partial session attribution, while the requested stable cron/channel/status JSON contract remains a product and privacy decision rather than a completed implementation.

## What This Changes

Request stable optional usage/status JSON fields for agent, session kind, cron job identity, channel attribution, model, and runtime so dashboards do not join local OpenClaw internals.

## Best Possible Solution

Define one documented, privacy-safe per-session usage attribution contract, likely on sessions.usage or a clearly named status export, and keep raw channel target ids omitted, hashed, or behind an explicit operator-controlled flag.
