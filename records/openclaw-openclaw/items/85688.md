## Summary

Keep open: current main and the latest release only partially cover the requested attribution, while cron job identity, channel target-kind semantics, and privacy-safe public field names remain a product/API contract decision.

## What This Changes

The issue requests stable agent, session-kind, cron-job, channel, model, and runtime attribution fields in official usage/status JSON exports.

## Best Possible Solution

Define one additive, privacy-safe attribution contract for status and sessions-usage rows that reuses existing session-store origin and cron metadata, omits or gates private target ids, and keeps narrower display-only or event-stream work in their canonical issues.

Rationale: Current main already exposes some attribution but not the requested cron identity or target-kind contract, and adding those fields creates durable public JSON/API semantics that automation should not choose alone.

Options:

- **Approve a narrow additive JSON contract (recommended):** Add optional status/usage row fields for cron job id/name and channel/target kind while keeping raw private target ids omitted or behind an explicit opt-in.

- **Fold into broader telemetry design:** Track this with broader usage/event-stream observability so status JSON, sessions.usage, and WebSocket attribution use one shared contract.
