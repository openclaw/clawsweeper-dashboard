## Summary

Keep open: current main exposes some agent/channel metadata in `sessions.usage` and status JSON, but it does not provide the requested stable cron job, session-kind, channel-target-kind, and runtime attribution contract. This remains a useful feature request that needs maintainer product/API direction because it expands official JSON surfaces and has privacy tradeoffs.

## What This Changes

Request to add stable optional per-session attribution fields to usage/status JSON for agent, session kind, cron job, channel, model, and runtime.

## Best Possible Solution

Define a narrow additive attribution contract for the official usage/status JSON surfaces, reuse existing session/routing/cron metadata, document which identifiers are omitted or redacted, and keep the narrower CLI/TUI friendly-label work in the related issue.
