## Summary

Keep open: current main only partially covers the requested attribution fields, while cron job identity and channel-target classification remain absent from the official JSON contracts. This is additive status/usage API product work, not a cleanup-close candidate.

## What This Changes

The issue requests stable optional agent, session kind, cron job, channel, model, and runtime attribution fields in status and usage JSON outputs.

## Best Possible Solution

Define a narrow additive JSON schema for status and sessions.usage rows, reuse existing session/cron/channel metadata, keep raw target identifiers private by default, and coordinate only the human-readable CLI/TUI label part with https://github.com/openclaw/openclaw/issues/51184.
