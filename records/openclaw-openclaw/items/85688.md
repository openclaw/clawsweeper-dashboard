## Summary

Keep open: current main already exposes some usage attribution such as `agentId`, `channel`, `chatType`, `label`, model, and provider on `sessions.usage`, but it does not provide the requested stable cron identity, session-kind, channel-target, or status JSON attribution contract, and no related issue fully supersedes that broader request.

## What This Changes

The issue requests official usage/status JSON attribution fields for agent, session kind, cron job identity, channel, model, and runtime so dashboards do not need to join local OpenClaw stores.

## Best Possible Solution

Define a narrow, privacy-safe extension to the existing usage/status JSON rows that reuses session and cron metadata already owned by core, with optional fields and tests for cron, direct chat, and channel sessions.
