## Summary

Keep open: current main and v2026.6.11 already expose some session usage labels, agent ids, channels, status kinds, models, and status runtimes, but they do not provide the requested stable JSON attribution contract for cron job id/name, channel target kind/privacy, and runtime on usage rows.

## What This Changes

The issue requests additive official status/usage JSON attribution fields for agent, session kind, cron job identity, channel, model, and runtime so external dashboards do not join internal stores.

## Best Possible Solution

Define an additive, privacy-preserving attribution schema for status and sessions.usage JSON, project it from canonical session and cron metadata, document it, and keep raw channel target ids out unless maintainers approve an explicit opt-in.
