## Summary

Keep open: current main only partially satisfies the request. `sessions.usage` already exposes agent/channel/model-adjacent fields, but the requested stable session kind, cron job identity, channel target kind, and runtime attribution are still missing, and adding them to official JSON surfaces needs a product/privacy decision.

## What This Changes

The issue requests stable optional attribution fields in official usage/status JSON so dashboards can group usage by agent, session kind, cron job, channel, model, and runtime without joining local stores.

## Best Possible Solution

Define an additive, privacy-safe attribution contract, likely extending `sessions.usage` first and then deciding whether `status --usage --json` should include or point to that per-session data.
