## Review Findings

Overall confidence: 0.9

Full review comments:

- **[P2] Centralize pane message subscriptions:** `ui/src/pages/chat/chat-pane.ts:170`
  - body: Each pane tracks selected-session subscriptions in its own state, but the Gateway registry is per WebSocket connection. If two panes show the same session and one pane switches away, this call can unsubscribe that session for the sibling pane that still needs live `session.message` updates; move ownership to the page level or ref-count it across panes.
  - confidence: 0.94
- **[P2] Scope session lists per pane:** `ui/src/pages/chat/chat-pane.ts:519`
  - body: Every pane copies the singleton `context.sessions.state.result`, while `refreshCurrentChatSessionList` scopes refreshes to the pane's current agent. The last refreshed pane therefore controls all pane header selectors, so a pane on another agent can lose its available sessions until that agent refreshes again.
  - confidence: 0.91
- **[P2] Consume route drafts only once:** `ui/src/pages/chat/chat-page.ts:198`
  - body: The route draft is passed to whichever pane is active, so focusing a different split pane changes its `draft` prop and `ChatPane.willUpdate` copies the same prefill into that pane's composer. Bind the draft to the pane active at the route change or consume it after the first application.
  - confidence: 0.88
