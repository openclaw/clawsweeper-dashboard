## Summary

Keep open: current main and v2026.6.11 still provide immediate model setting, manual fallback management, auth/profile probes, OpenRouter scan support, and runtime failover, but not the requested staged test-promote-rollback model migration workflow.

## What This Changes

The issue requests a staged `openclaw models` workflow for testing a new model before promotion, preserving the old primary as fallback, and rolling back if the new primary breaks.

## Best Possible Solution

Design one coherent `openclaw models` migration workflow that stages arbitrary candidates, verifies provider/auth/sub-agent/tool-use readiness before promotion, preserves the old primary as fallback, persists rollback state in the canonical store, and documents/tests config transitions alongside related probe work.
