## Summary

Keep open: current main and v2026.6.11 still lack a staged model migration workflow, while the issue and prior maintainer review point to product design still needed before implementation.

## What This Changes

Request a safer model-switching workflow that can stage a candidate model, verify it, promote it to primary, preserve the old primary as fallback, and roll back if needed.

## Best Possible Solution

Design one coherent `openclaw models` migration workflow that stages arbitrary candidate models, verifies them before promotion, preserves the old primary as fallback, persists rollback state in the canonical store, and documents/tests the config transitions.

## Reproduction Assessment

Yes, at source level: current main exposes immediate model setting, manual fallback management, auth-profile probes, OpenRouter scan/probe support, and runtime failover, but no staged migrate/test/promote/rollback workflow. I did not run live provider calls because the missing command and persistence behavior are visible in source and docs.

## Solution Assessment

Unclear until maintainers choose the product contract. A staged workflow is plausible and aligned with safer setup, but it should be reconciled with fallback-chain testing and all-configured-model probing before implementation is queued.
