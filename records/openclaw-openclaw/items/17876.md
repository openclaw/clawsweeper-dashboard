## Summary

Current main and v2026.6.11 still lack the requested stage-verify-promote-rollback workflow. The issue remains distinct from narrower model-probe requests, and the discussion explicitly leaves the command, verification, fallback-order, and rollback contracts for maintainer product design.

## What This Changes

Requests a staged model migration workflow that verifies a candidate before promotion, preserves the previous primary as fallback, and supports rollback.

## Best Possible Solution

Build the workflow on one canonical configured-model probe, require explicit promotion after clearly reported checks, deterministically retain the previous primary as fallback, and use a deliberately owned config transaction or backup mechanism for rollback.
