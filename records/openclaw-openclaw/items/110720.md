## Summary

Keep this active maintainer PR open. The branch removes a deliberate fallback that can change channel-specific explicit-target parsing when a plugin is not already loaded; the supplied unit test confirms the new generic fallback but does not establish that all delivery callers have an active registry first.

## What This Changes

The PR stops `resolveExplicitDeliveryTargetCompat` from source-loading unloaded channel plugins and updates the Signal tool-result harness to isolate session storage, close agent databases, and adopt turns before mocked replies.

## Best Possible Solution

Keep the no-lazy-load boundary, but add or present routing-level proof that explicit targets for an unloaded channel either reach the same destination semantics through the normal activation path or are intentionally unsupported with a documented migration boundary.
