## Summary

Keep this PR open for repair. The staged-result design addresses the linked cloud-worker data-loss path, but the branch still turns an additive SQLite column into a rollback-incompatible schema-version bump and can convert a plain workspace into an unusable empty Git repository. The provided evidence is focused test and check output, not an after-fix real cloud-worker recovery run.

## What This Changes

The branch stages cloud-worker workspace results as durable local Git refs before reconciliation, records the ref on pending-result state, and reuses or deletes it during recovery and abandonment.

## Best Possible Solution

Keep staging durable results outside user workspaces or preserve plain-workspace classification, retain state schema version 4 while lazily ensuring the nullable column, then attach redacted live proof of a divergence followed by worker loss or Gateway restart and successful local recovery.

## Solution Assessment

No. Durable staging is a plausible and useful recovery boundary, but it must not alter user workspace classification or create an unnecessary state-schema downgrade barrier; an external staging repository or equivalent owner-managed Git store is safer.
