## Summary

Keep this PR open: its durable-result approach addresses the cloud-worker loss path, but the proposed additive SQLite column unnecessarily advances the state schema from v4 to v5, which can block rollback to the prior release; the PR also still lacks contributor-owned real behavior proof of recovery after a worker or Gateway failure.

## What This Changes

## Best Possible Solution

Keep the state schema version at v4 while adding `staged_result_ref` through the additive migration path, then attach redacted live evidence that a completed result survives worker loss or Gateway restart and is retried locally.
