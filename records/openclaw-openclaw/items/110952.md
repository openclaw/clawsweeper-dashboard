## Summary

Keep this PR open: its core durability approach addresses a real P1 cloud-worker data-loss path, but the proposed additive SQLite column unnecessarily advances the global state schema to v5, causing older supported builds to reject the database after rollback. The PR also needs after-fix runtime proof of the worker-loss recovery path before merge.

## What This Changes

The branch stages completed cloud-worker workspace results as durable local Git refs, records each ref on the pending-result fence, and reuses the staged tree during recovery after a worker environment disappears.

## Best Possible Solution

Keep the global state schema at v4, retain `staged_result_ref` through the idempotent additive-column path, remove the release-owned changelog edit, and attach redacted live evidence showing a reconciled result survives worker loss and is later applied locally.
