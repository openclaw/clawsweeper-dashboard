## Summary

Keep open: current main and the latest release still run preflight compaction and memoryFlush in the foreground reply/session-lane path, so the reported Telegram unresponsiveness is mitigated by diagnostics but not implemented away.

## What This Changes

The issue asks OpenClaw to prevent memory compaction and memoryFlush from blocking inbound same-session messages for minutes.

## Best Possible Solution

Land a maintainer-approved bounded or preemptible maintenance-lane design for compaction and memoryFlush that preserves session ordering while allowing foreground channel messages to be acknowledged or processed promptly.

- **Preserve blocking behavior:** Treat compaction as intentionally foreground and defer or close the nonblocking message-handling request as out of scope.
