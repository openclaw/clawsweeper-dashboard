## Label Justifications

- `P1`: The report describes a real Telegram workflow becoming unresponsive for minutes while user messages queue behind compaction work.
- `impact:session-state`: The affected behavior is session memoryFlush/compaction scheduling, transcript state, and per-session lane serialization.

- `impact:crash-loop`: The incident required a manual gateway restart to recover from an availability hang.

## Summary

Keep open: current main and v2026.6.11 still run preflight compaction and memoryFlush inside the active reply/session scheduling path. The default compaction timeout is now 180s instead of the reported 600s, but the central request for an isolated or preemptible compaction path remains unresolved.

## What This Changes

The issue asks for memory compaction and memoryFlush work to stop blocking foreground Telegram message processing for minutes.

## Best Possible Solution

Land a maintainer-approved bounded or preemptible maintenance-lane design for memoryFlush and compaction that preserves session ordering while allowing foreground channel messages to be acknowledged or processed promptly.
