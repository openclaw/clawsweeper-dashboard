## Summary

Keep open: current main has shorter compaction timeouts and recovery mitigations, but source still shows preflight compaction and memoryFlush occupying the foreground reply/session lane instead of an isolated or preemptible maintenance lane.

## What This Changes

The issue reports that memory compaction can occupy the interactive processing lane long enough to leave Telegram messages queued and the bot unresponsive.

## Best Possible Solution

Move compaction and memory-flush maintenance out of the foreground message lane, or adopt a maintainer-approved preemptible/isolated compaction lane with explicit timeout and recovery semantics for queued user messages.
