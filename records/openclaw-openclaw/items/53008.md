## Summary

Keep open: current main and the latest stable release still let preflight compaction and memoryFlush occupy the foreground reply/session scheduling path, so the reported Telegram unresponsiveness is only partially mitigated by shorter timeouts.

## What This Changes

The issue asks OpenClaw to prevent memory compaction and memoryFlush work from blocking interactive Telegram message processing for minutes.

## Best Possible Solution

Land a maintainer-approved bounded or preemptible maintenance-lane design for memoryFlush and compaction that preserves session ordering while allowing foreground messages to proceed promptly.
