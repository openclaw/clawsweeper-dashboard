## Summary

Keep open: current main and the latest stable release reduce the compaction timeout but still run preflight compaction and memoryFlush inside the foreground reply/session lane, so the blocked-message behavior remains unresolved.

## What This Changes

The issue asks for memory compaction and memoryFlush to stop blocking foreground Telegram replies for minutes and to recover or acknowledge queued messages safely.

## Best Possible Solution

Define a maintainer-approved compaction and memoryFlush scheduling contract that preserves transcript ordering while admitting or visibly acknowledging foreground messages before the maintenance timeout elapses.
