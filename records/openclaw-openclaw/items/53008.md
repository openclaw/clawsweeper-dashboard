- `impact:session-state`: The affected behavior is session memoryFlush/compaction scheduling, transcript state, and per-session lane serialization.

## Summary

Keep open: current main still runs preflight compaction and memoryFlush in the foreground reply path and serializes embedded same-session work, so the newer timeout and diagnostic recovery mitigations do not solve the reported Telegram lane starvation.

## What This Changes

The issue asks OpenClaw to keep inbound Telegram messages responsive when session compaction or memoryFlush runs for a long time.

## Best Possible Solution

Move compaction and memory-flush maintenance out of the foreground message lane, or add a maintainer-approved preemptible/isolated compaction lane with explicit timeout and recovery semantics for queued user messages.
