## Summary

Keep open: current main has reduced the worst compaction timeout from the originally reported 10 minutes, but foreground replies still await preflight compaction and memory flush on the same serialized session/main-lane paths, so the central unresponsive-session failure mode is not implemented away.

## What This Changes

The issue requests that memory compaction and related memory maintenance stop blocking the main Telegram/session processing lane and provide an automatic recovery path instead of requiring a Gateway restart.

## Best Possible Solution

Design a maintainer-approved scheduler/state change that makes compaction and memory flush bounded or preemptible without corrupting transcript rotation, session identity, cancellation, channel delivery, or queued-turn ordering.
