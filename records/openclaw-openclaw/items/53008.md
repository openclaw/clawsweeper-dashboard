Keep open: current main and the latest release still mitigate duration and recovery, but preflight compaction and memoryFlush remain in the in-band session/global lane path that can delay foreground channel work. ## What This Changes

The issue asks OpenClaw to prevent session memory compaction and memoryFlush work from blocking inbound Telegram message processing for minutes.

## Best Possible Solution

Land a maintainer-approved bounded or preemptible compaction/memoryFlush maintenance-lane design that preserves one-writer session safety while letting foreground channel messages receive prompt acknowledgement or processing.
