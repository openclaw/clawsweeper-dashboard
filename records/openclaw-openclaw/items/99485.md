## Summary

Keep open: this is a useful fallback-path fix, but it is not merge-ready because adapter-backed/native approval renderers still bypass these fallback builders, so session identity can remain missing in real channel approval prompts.

## What This Changes

The PR adds Session lines to exec/plugin approval fallback text and mirrors plugin agentId/sessionKey into pending reply channelData, with focused tests.

## Best Possible Solution

Extend session identity through the shared approval view model, reply helpers, and adapter-backed native renderers so fallback text and real channel-native prompts stay consistent.

## Reproduction Assessment

Yes, source-level: current forwarding and native approval runtimes can render through adapter/view-model paths that do not include session identity. I did not run a live channel, but the bypass is directly visible in the current source.

## Solution Assessment

No. The fallback builder change is a good partial fix, but the best fix needs to carry the same session identity through the shared view model and native renderer helpers used by real channel adapters.
