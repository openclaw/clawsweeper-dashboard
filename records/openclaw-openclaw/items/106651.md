## Summary

Keep open, but the reported failure mechanism is incorrect: current main clears the heartbeat immediately when the count reaches zero and the interval callback uses an OR condition. A narrower concern remains plausible—duplicate end events during overlapping runs could undercount active work—but the issue provides no concrete caller path or current-main reproduction showing that duplicate events occur.

## What This Changes

Ensure duplicate channel run lifecycle events cannot desynchronize active-run status or heartbeat activity.

## Best Possible Solution

First establish a focused overlapping-run reproduction through the real channel lifecycle caller; if duplicate completion is possible, make each start return or register an idempotent completion token and retain count-derived public status rather than adding an unowned run-ID Set inside the state machine.
