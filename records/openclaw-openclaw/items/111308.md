## Summary

This PR’s stated pre-banner SSH hang is already bounded by the generated OpenSSH `ConnectTimeout 5` configuration, whose documented scope includes the initial protocol handshake and key exchange. The proposed execa timeout instead imposes a new 60-second ceiling on the entire remote command lifetime, so it can fail legitimate slow sandbox setup or cleanup without proving it fixes the reported condition.

## What This Changes

The branch adds a 60-second default process timeout and an optional `timeoutMs` override to SSH sandbox commands, plus a regression test using a non-exiting executable.

## System Context

The SSH sandbox backend provisions and manages remote agent workspaces by starting local OpenSSH commands for validation, filesystem work, and cleanup. Its command results feed back into sandbox setup and agent execution, so a process deadline changes both stalled-host recovery and the maximum allowed duration of healthy remote operations.

## Best Possible Solution

Remove the global 60-second deadline unless an actual OpenSSH path is shown to escape the existing handshake timeout; if a distinct operation needs a total budget, place that budget at the owning caller with a documented duration and focused upgrade-safe proof.
