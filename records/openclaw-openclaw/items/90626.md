## What This Changes

This PR changes isolated cron CLI creation and runtime delivery planning so omitted delivery mode resolves to `none` instead of `announce`.

## System Context

Cron jobs are created through CLI, service, and declarative paths, then their delivery plan decides whether completed agent output is announced to a channel or retained silently. That plan feeds the isolated-agent delivery dispatcher and determines both user-visible output and whether unresolved delivery affects cron run status.

## Architecture Diagram

  B --> C[Shared default-delivery policy]
  C --> D[Runtime delivery plan]
  D --> E[Resolve channel and recipient]
  E --> F[Dispatch output or record silent result]
  F --> G[Cron run status and delivery log]

## Best Possible Solution

Keep the shared current-main default policy as the single owner, then separately repair only the unresolved implicit no-channel path if maintainers still want successful silent cron runs without weakening explicit delivery.
