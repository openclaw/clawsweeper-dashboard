## Summary

Keep open: current main still violates the FileInfo basename contract for Windows backslash paths, and this PR fixes the shared metadata helper with focused regression coverage and sufficient real Windows runtime proof. I found no blocking correctness or security findings.

## What This Changes

The PR changes `NodeExecutionEnv` file metadata to derive `FileInfo.name` with Windows-aware basename splitting and adds a regression test for Windows-style paths.

## Best Possible Solution

Land the focused shared-helper fix after normal maintainer approval and exact merge-queue checks, keeping POSIX backslash filename behavior unchanged.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: current main still derives `FileInfo.name` by trimming and splitting only POSIX separators, so a Windows path can retain parent directories despite the basename contract. I did not run a before-fix Windows runtime repro in this read-only review.

## Solution Assessment

Yes; `fileInfoFromStats()` is the right boundary because both `fileInfo()` and `listDir()` share it. Patching only `fileInfo()` would leave directory listing metadata inconsistent.
