## Summary

Keep open: this PR addresses a real recovery gap, but the web_fetch spill path now writes a host temp file and advertises that host path to the model without checking whether the active session's read tool can access it, which breaks sandboxed recovery and creates a security-boundary concern.

## What This Changes

The branch preserves spill-file metadata through aggregate tool-result elision, adds web_fetch spilling to private temp files with full-output footers, and updates focused tests.

## Best Possible Solution

Keep the recovery contract, but make web_fetch spill pointers capability-aware: only advertise a path the active read tool can actually read, or degrade without a footer in sandboxed/no-read contexts, with focused sandbox coverage.

## Reproduction Assessment

Yes, for the blocking review issue: source inspection shows web_fetch writes a host tmpdir spill and advertises it in tool text, while sandboxed agents use a sandbox-rooted read tool. I did not run a live sandboxed web_fetch scenario in this read-only review.

## Solution Assessment

No. The aggregate-elision reuse of the existing footer contract is plausible, but the web_fetch spill path is not the best fix until it is gated by the active read capability or writes to a sandbox-readable location.
