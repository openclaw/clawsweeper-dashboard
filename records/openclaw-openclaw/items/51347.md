## Label Justifications

- `P2`: This is a source-reproducible Feishu outbound media bug with security-sensitive policy choices and workarounds, but it is not a core runtime outage.
- `impact:security`: The requested root configuration affects which host filesystem paths Feishu outbound media is allowed to read and upload.
- `impact:message-loss`: Feishu can report a successful send while the requested media attachment was not delivered and only fallback text was sent.

## Summary

Keep open: current main improves local media root handling through shared filesystem policy, but this issue still has a real remaining Feishu delivery-status problem because media upload exceptions are converted into fallback text delivery that the caller formats as a normal success. The Feishu-specific root config request also remains a security/product decision rather than a safe cleanup close.

## What This Changes

The issue requests Feishu CLI media sends honor local-media root configuration or clearly fail/partial-report when media upload is rejected.

## Best Possible Solution

Define one shared outbound local-media access contract, then make Feishu media upload failures surface as an explicit failure or typed partial success that the CLI and session records can show accurately.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should Feishu media upload allowlist failures use the shared filesystem/media root policy only, add a Feishu-specific mediaLocalRoots config surface, or keep text fallback as normal success?

Rationale: This cannot be safely resolved by cleanup automation because it changes host-file upload permissions and user-visible delivery status semantics.

Likely owner: steipete

Owner reason: The decision spans the shared outbound media access policy that steipete recently centralized and the Feishu-specific adapter behavior.

Owner confidence: high

Options:

- **Use shared media policy and explicit failure status (recommended):** Keep host path permission under the shared filesystem/media access policy and change Feishu allowlist/upload failures to hard-fail or return typed partial success instead of ordinary success.
- **Add Feishu-specific mediaLocalRoots:** Add a documented Feishu config key with schema/tests and an explicit security review for the host-path expansion it grants.
- **Document fallback as intended:** Keep fallback text delivery as a successful send only if maintainers explicitly accept that Feishu media upload failure means link fallback delivery, not attachment delivery.

## Reproduction Assessment

Yes, at source level: current main still catches Feishu media upload failures into fallback text delivery and the CLI formats returned direct results as successful sends. I did not run a live Feishu tenant send in this read-only review.

## Solution Assessment

Unclear; a Feishu-only config key is not obviously the best fix because local media roots are a host-file security boundary. The safer direction is a shared media access contract plus explicit Feishu failure or partial-success reporting.
