## Label Justifications

- `P2`: This is a normal-priority Feishu outbound media correctness and security-policy bug with workarounds, not a core runtime outage.
- `impact:security`: The requested behavior affects which local filesystem roots Feishu outbound media may read and upload.
- `impact:message-loss`: A media attachment can fail to upload while the CLI still reports a successful Feishu send for fallback text.

## Summary

Keep open: current main still lacks a supported Feishu `mediaLocalRoots` config surface, and Feishu outbound still converts media-upload exceptions into fallback text delivery that the CLI formats as a normal success. The overlapping root-policy work and closed Feishu PRs do not fully cover the Feishu fallback-success behavior.

## What This Changes

The issue reports that Feishu CLI media sends ignore configured media roots and can report success when media upload fails.

## Best Possible Solution

Define a shared, security-reviewed outbound local-media root contract, then update Feishu schema/docs/tests and return explicit media failure or partial-success status instead of a normal sent result.

- **Feishu-specific config surface:** Add and document `channels.feishu.mediaLocalRoots` with security-reviewed schema, tests, and migration expectations.
- **Keep fallback and document staging:** Treat fallback link delivery as expected behavior and document managed staging directories instead of adding a new root config.

## Solution Assessment

Unclear. A Feishu-only config key is not obviously the best fix because local file roots are a shared security boundary; the maintainable fix should settle shared root policy and Feishu failure semantics together.
