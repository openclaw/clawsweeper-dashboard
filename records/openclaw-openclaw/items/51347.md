## Summary

Keep open: current main and v2026.6.11 still lack a Feishu `mediaLocalRoots` config contract, and Feishu still converts media upload errors into a fallback text result that the CLI can format as success. The remaining fix is security- and product-sensitive because it either widens host-local file read roots or changes existing fallback delivery semantics.

## What This Changes

Request Feishu CLI media sends honor configured local media roots and report media upload failures without a misleading success message.

## Best Possible Solution

Make one maintainer-approved local-media policy decision for Feishu, then align schema, docs, tests, and delivery reporting so media allowlist failures are visibly non-successful or explicitly partial-success.

## Reproduction Assessment

Yes at source level: Feishu's strict config schema lacks `mediaLocalRoots`, its media path only consumes roots passed by outbound context, and upload errors still return fallback delivery results; no live Feishu send was run.

## Solution Assessment

Unclear: directly adding a Feishu-only config key may not be the best fix because current source-derived root expansion already handles some trusted local sends, while the remaining behavior needs a shared security decision and explicit fallback semantics.
