## Label Justifications

- `P2`: This is a normal-priority Feishu outbound media bug with source-level proof and workarounds, but it is not a core-runtime outage.
- `impact:security`: The requested config behavior affects which host filesystem roots Feishu outbound media is allowed to read and upload.
- `impact:message-loss`: Feishu can report a successful send while the intended media attachment was not delivered and only fallback text was sent.

## Summary

Keep open: current main still lacks a supported Feishu `mediaLocalRoots` config surface and Feishu outbound still converts media-upload exceptions into a fallback text delivery that looks successful to the caller. The related Feishu PRs were closed unmerged, while https://github.com/openclaw/openclaw/issues/47002 and https://github.com/openclaw/openclaw/pull/52951 only cover overlapping root-policy direction, not the Feishu fallback-success behavior.

## What This Changes

The issue asks Feishu CLI media sends to honor configured local media roots or clearly fail/document the unsupported path, and to stop reporting normal success when media upload fails.

## Best Possible Solution

Define one security-reviewed outbound local-media root contract, then update Feishu schema/docs/tests and make allowlist upload failures surface as explicit failure or explicit partial success instead of a normal send success.

## Reproduction Assessment

Yes, at source level: current main still rejects the requested Feishu config key and still catches media upload failures into fallback text delivery. I did not run a live Feishu tenant send in this read-only review.

## Solution Assessment

Unclear; adding a Feishu-only config key is not obviously the best fix because it changes host-file read security and could conflict with broader root-policy work. The best maintainable fix should settle the shared root contract and Feishu failure semantics together.
