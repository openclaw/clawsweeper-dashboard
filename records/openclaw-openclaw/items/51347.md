## Summary

Keep this issue open: current main and the latest release still leave Feishu without a supported `channels.feishu.mediaLocalRoots` config surface, and Feishu outbound still converts media upload failures into success-shaped fallback text delivery. The related fix PRs were closed unmerged, while the broader filesystem-roots PR is still open/conflicting and is not a safe canonical replacement.

## What This Changes

The issue reports Feishu CLI media sends ignoring a requested local-root configuration and reporting success after media upload failure.

## Best Possible Solution

Define one security-reviewed outbound local-media root contract, then update Feishu schema/docs/tests only if that contract supports it and make allowlist upload failures surface as explicit failure or explicit partial success.

## Reproduction Assessment

Yes. Source inspection shows the Feishu schema still lacks the requested config key, while the Feishu outbound media path still catches upload errors and returns fallback delivery as success-shaped output.

## Solution Assessment

Unclear. A Feishu-only config key is not clearly the best fix until maintainers choose the generic local-media root policy and the desired fail, partial-fail, or explicit-fallback semantics.
