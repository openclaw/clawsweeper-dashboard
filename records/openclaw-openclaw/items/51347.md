## Summary

Keep open: current main and latest release still lack a supported Feishu local-media roots config surface, and Feishu media upload failures still fall back to a text send that the CLI formats as normal success. Related PRs are closed unmerged or only partially overlap, so this issue remains the canonical Feishu-specific tracker.

## What This Changes

The issue requests that Feishu CLI media sends honor a supported local-media root policy or clearly reject unsupported local media, and stop reporting normal success when upload fails.

## Best Possible Solution

Define the safe outbound local-media root contract, then update Feishu schema/docs/tests and make allowlist upload failures surface as explicit failure or explicit partial success.

## Reproduction Assessment

Yes, at source level: current main still rejects the requested Feishu config key and still catches media upload failures into fallback text delivery. I did not run a live Feishu tenant send in this read-only review.

## Solution Assessment

Unclear; a Feishu-only config key is not obviously the best long-term fix because host-file read roots are a shared security policy. The best solution should settle the shared root contract and Feishu failure semantics together.
