## Summary

This issue should stay open: current main and the latest release still omit a supported Feishu `mediaLocalRoots` config surface, and Feishu media upload failures are still converted into successful fallback text sends that the CLI formats as success. The related Feishu PRs were closed unmerged, while the open Telegram/local-media reports only partially overlap this Feishu behavior.

## What This Changes

The issue reports that Feishu CLI media sends ignore `channels.feishu.mediaLocalRoots` and can still report success when local media upload fails.

## Best Possible Solution

Define one security-reviewed outbound local-media root contract, update Feishu schema/docs/tests, and make allowlist upload failures surface as explicit failure or explicit partial success instead of normal attachment success.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: current Feishu config still rejects the requested local-root key, and Feishu upload errors are converted into successful fallback text sends; no live Feishu tenant send was run in this read-only review.

## Solution Assessment

Unclear. The best fix is not only adding a schema key; it needs maintainer policy on the local-file read boundary and whether local allowlist failures should hard-fail or become explicit partial success.
