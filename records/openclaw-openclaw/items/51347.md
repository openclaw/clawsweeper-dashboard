## Summary

Issue #51347 should stay open because current main still rejects the Feishu `mediaLocalRoots` configuration surface and still converts media-upload failures into fallback link sends that look successful upstream; the related PRs were closed unmerged and the overlapping Telegram issue does not cover Feishu's fallback-success behavior.

## What This Changes

The issue requests Feishu outbound media to honor configured local media roots and stop reporting normal success when a local media upload fails.

## Best Possible Solution

Define one security-reviewed outbound local-media root contract, then update Feishu schema/docs/tests and make allowlist upload failures surface as explicit failure or explicit partial success instead of a normal attachment-success result.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: current Feishu config still rejects the requested local-root key, while Feishu outbound catches media upload failures and returns fallback delivery as success-shaped output.

## Solution Assessment

Unclear without maintainer decision; the best fix is not just adding a schema key, because it also changes the local-file security boundary and whether Feishu should fail, partially fail, or explicitly report fallback on attachment upload failure.
