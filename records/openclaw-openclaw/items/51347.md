## Summary

Keep open: current main and the latest release still do not accept `channels.feishu.mediaLocalRoots`, and Feishu still catches media upload failures and returns a success-shaped fallback text send that the CLI formats as normal success.

## What This Changes

The issue asks Feishu CLI media sends to honor a configured local media root or clearly reject unsupported local paths, and to stop reporting normal success when media upload fails.

## Best Possible Solution

Define one security-reviewed outbound local-media root contract, then update Feishu schema/docs/tests and make allowlist upload failures surface as explicit failure or explicit partial success instead of a normal attachment-success result.

## Reproduction Assessment

Yes at source level. Current main still omits the requested Feishu config key, computes roots from existing media policy instead, and catches Feishu media upload errors into success-shaped fallback sends; no live Feishu tenant send was run.

## Solution Assessment

Unclear until maintainers choose the root-policy and failure-semantics contract. A narrow schema-only fix would be risky because it widens local filesystem reads without resolving whether allowlist failures should fail hard or report explicit partial success.
