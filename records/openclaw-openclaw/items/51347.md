## Summary

Keep open: current main and latest stable release still reject the reported Feishu `mediaLocalRoots` config shape, and Feishu media upload errors still become a success-shaped fallback text send. Main now has a shared `tools.fs`-based local-media policy, so the remaining work needs maintainer security/product direction rather than a narrow automatic patch.

## What This Changes

The issue asks OpenClaw to honor configurable Feishu local-media roots and avoid reporting success when a Feishu media upload fails.

## Best Possible Solution

Define a security-reviewed outbound local-media root policy, then make Feishu delivery results distinguish attachment failure from fallback text delivery without widening host file access by default.

## Reproduction Assessment

Yes at source level: the strict Feishu config schema still lacks `mediaLocalRoots`, and Feishu `sendMedia` still catches media upload errors and returns a fallback text delivery that the CLI formats as success; no live Feishu send was run.

## Solution Assessment

No clear best fix is selected yet: adding `channels.feishu.mediaLocalRoots` directly would create a channel-local file-read config competing with the documented shared `tools.fs` policy, while fail-fast versus partial-success reporting needs maintainer direction.
