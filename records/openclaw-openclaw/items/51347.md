## Summary

Keep open: current main still does not accept `channels.feishu.mediaLocalRoots`, and Feishu still catches media upload failures into fallback text that the caller sees as a delivered Feishu message. The direct fix PR at https://github.com/openclaw/openclaw/pull/51374 was closed unmerged, while the open filesystem-roots PR at https://github.com/openclaw/openclaw/pull/52951 only covers the local-root policy slice and does not settle Feishu fallback-success semantics.

## What This Changes

The issue asks Feishu CLI media sends to honor or clearly reject `channels.feishu.mediaLocalRoots` and to stop reporting a successful send when media upload fails.

## Best Possible Solution

Adopt one security-reviewed outbound local-media root contract, preferably shared with filesystem policy, then align Feishu schema/docs/tests and make allowlist upload failures surface as explicit failure or explicit partial success.

- **Add Feishu-Specific Roots:** Accept a new `channels.feishu.mediaLocalRoots` surface with security review, docs, schema coverage, and upgrade guidance.
- **Document Fallback As Intentional:** Leave fallback text delivery as success and document that failed Feishu uploads may still send link-like fallback text.

## Reproduction Assessment

Yes, at source level: current main still rejects the reported Feishu config key and still catches Feishu media upload failures into fallback text delivery. I did not run a live Feishu tenant send in this read-only review.

## Solution Assessment

Unclear: adding a Feishu-only root key is plausible but may not be the best fix because it creates a host-file security surface beside the shared media policy. The maintainable fix should settle the shared root contract and Feishu failure semantics together.
