## Summary

Keep open: current main still has the Feishu media failure success path, and the remaining config-root behavior is security/product-sensitive rather than a cleanup-close candidate.

## What This Changes

The issue reports that Feishu CLI media sends ignore `channels.feishu.mediaLocalRoots` and can print a successful send after media upload fails.

## Best Possible Solution

Use one security-reviewed media access contract and make Feishu local media upload failures either fail fast or report partial delivery clearly, so the CLI never presents an attachment failure as full success.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should Feishu support a channel-level `mediaLocalRoots` config key, or should local media sends rely only on the existing generic media access policy and managed staging roots?

Rationale: The remaining fix crosses a host file-read boundary and changes Feishu delivery-status semantics, so automation should not choose the permanent security/product contract alone.

Likely owner: vincentkoc

Owner reason: Recent Feishu media/tool-send work plus adjacent security/config history makes this the best available owner for the boundary decision.

Owner confidence: medium

Options:

- **Keep generic media policy and fail fast on local allowlist failures (recommended):** Do not add `channels.feishu.mediaLocalRoots`; make local allowlist upload failures terminal or partial with clear CLI output and keep current managed/source-scoped roots as the supported path.
- **Add a documented Feishu config root surface:** Accept `channels.feishu.mediaLocalRoots` only with schema/docs/doctor/security tests that define upgrade and local-file-read behavior.
- **Document unsupported config and preserve fallback:** Keep the fallback behavior but document that Feishu CLI sends require managed staging roots or generic source-scoped media access, accepting the current partial-delivery semantics.

## Reproduction Assessment

Yes, source-reproducible: current Feishu outbound catches `sendMediaFeishu` failures, sends fallback text, and returns that result; the CLI formatter then prints a success line for returned send results. I did not perform a live Feishu API send in this read-only review.

## Solution Assessment

Unclear as proposed: adding Feishu-specific config roots is not obviously the best fix because current main already has a generic source-scoped media access policy. The safer end state is a maintainer-approved media-root contract plus clear fail-fast or partial-success reporting for media upload failures.
