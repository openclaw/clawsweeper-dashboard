## Summary

Keep open: current main and the latest release still lack a Feishu `mediaLocalRoots` config contract, and Feishu media upload errors still fall back to success-shaped text delivery. The remaining work is real, but it needs maintainer security/product direction before widening local file-read roots or changing Feishu fallback semantics.

## What This Changes

The issue reports that Feishu CLI media sends ignore configured local media roots and can report success after attachment upload failure.

## Best Possible Solution

Define a security-reviewed outbound local-media root contract, then update Feishu/CLI to report media upload failure as either a real failure or explicit partial success with schema, docs, and tests aligned.

## Reproduction Assessment

Yes, source-level: current main has a strict Feishu schema without `mediaLocalRoots`, and the Feishu media adapter still catches upload errors into fallback text send. I did not run a live Feishu credential send in this read-only review.

## Solution Assessment

No, not as an automatic Feishu-only patch. The maintainable fix needs a shared, security-reviewed local-root policy plus explicit Feishu media failure semantics rather than silently adding a parallel channel config path.
