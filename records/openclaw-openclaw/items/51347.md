## Summary

Keep open: current main and v2026.6.11 still omit a Feishu `mediaLocalRoots` config surface and still convert Feishu media upload failures into fallback text delivery that the CLI formats as a normal success.

## What This Changes

Feishu CLI media sends should honor a supported local-media root policy or fail visibly when media upload is denied instead of reporting a normal send success.

## Best Possible Solution

Define one security-reviewed outbound local-media root contract, then update Feishu schema/docs/tests and make allowlist upload failures surface as explicit failure or explicit partial success instead of a normal send success.

- **Fail closed with guidance only:** Do not add Feishu-specific roots; instead make local allowlist violations fail clearly and document the managed staging directories.
- **Add Feishu-specific roots:** Allow `channels.feishu.mediaLocalRoots` directly, but require explicit security docs and tests for host file read/upload boundaries.

## Reproduction Assessment

Yes, at source level: current main still rejects the requested Feishu config key and still catches media upload errors into fallback text delivery. I did not run a live Feishu tenant send in this read-only review.

## Solution Assessment

Unclear; a Feishu-only config key is not clearly the best fix because it would create a host-file access surface beside broader root-policy work. The safest path is a shared root contract plus explicit non-success reporting for denied media.
