- `P2`: This is a normal-priority Feishu outbound media reliability bug with source-level proof and workarounds, but it is not a core-runtime outage.
- `impact:security`: The requested config behavior affects which host filesystem roots Feishu outbound media is allowed to read and upload.
- `impact:message-loss`: Feishu can report a successful send while the intended media attachment was not delivered and only fallback text was sent.

## Summary

Keep open: current main still lacks a supported Feishu `mediaLocalRoots` config surface and Feishu outbound still converts media upload exceptions into fallback text delivery that the CLI formats as a successful send. The linked Feishu fix PRs were closed unmerged, and the broader filesystem-root PR is still an open partial overlap rather than an implemented fix.

## What This Changes

The issue requests Feishu CLI media sends to honor configured local media roots or clearly fail/document the allowed staging paths, and to stop reporting normal success when media upload fails.

## Best Possible Solution

Define one security-reviewed outbound local-media root contract, then update Feishu schema/docs/tests and make allowlist upload failures surface as explicit failure or explicit partial success instead of a normal send success.
