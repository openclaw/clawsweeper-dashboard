## Label Justifications

- `P2`: The issue is source-reproducible and affects Feishu media delivery correctness, but it is channel-scoped and has a managed-media-directory workaround.
- `impact:security`: The requested config behavior controls which host filesystem paths Feishu outbound media is allowed to read and upload.
- `impact:message-loss`: A Feishu attachment can fail to upload while the send path returns a successful fallback text result.

## Summary

Keep open: current main and the latest release still lack a supported Feishu `mediaLocalRoots` config surface, and Feishu outbound still turns media-upload failure into fallback text delivery that can look successful to the caller.

## What This Changes

The issue asks for Feishu CLI media sends to honor configured media roots or document the managed-root policy, and to stop reporting full success when media upload fails.

## Best Possible Solution

Define one security-reviewed outbound local-media root contract, then update Feishu schema/docs/tests and make media upload failures surface as explicit failure or explicit partial success instead of a normal send success.
