- `P2`: This is a source-reproducible Feishu outbound media bug with workarounds and limited blast radius, not a core runtime outage.
- `impact:security`: The requested behavior affects which host filesystem roots Feishu outbound media can read and upload.
- `impact:message-loss`: Feishu can report a successful send while the intended media attachment was not delivered.

## Summary

Keep open: current main still lacks a supported Feishu `mediaLocalRoots` config surface, and Feishu outbound still turns media-upload exceptions into fallback text delivery that the CLI formats as normal success. The related Feishu PRs either landed only adjacent internal plumbing or closed unmerged, while broader filesystem-root work does not yet settle the Feishu failure semantics.

## What This Changes

The issue asks OpenClaw to make Feishu CLI media sends honor configured local-media roots or clearly fail/document unsupported paths, and to stop reporting normal success when media upload fails.

## Best Possible Solution

Define one security-reviewed outbound local-media root contract, then update Feishu schema/docs/tests and make allowlist upload failures surface as explicit failure or explicit partial success instead of normal success.

## Reproduction Assessment

Yes, at source level: current main still rejects the reported Feishu config key and still converts media upload failure into fallback text delivery. I did not run a live Feishu tenant send in this read-only review.

## Solution Assessment

Unclear; a Feishu-only config key may be too narrow because host local-media roots are a shared security boundary. The best solution should settle shared root policy and Feishu failure semantics together.
