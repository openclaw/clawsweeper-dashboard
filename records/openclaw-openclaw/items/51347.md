## Summary

Keep open: current main still lacks a supported Feishu `mediaLocalRoots` config surface and still converts Feishu media-upload errors into successful fallback text delivery, so the reported user problem remains present in both current main and the latest release.

## What This Changes

The issue reports that Feishu `openclaw message send --media` ignores `channels.feishu.mediaLocalRoots` and can report success when the media attachment was not delivered.

## Best Possible Solution

Define one security-reviewed outbound local-media root contract, update Feishu schema/docs/tests if that contract supports configuration, and make upload or allowlist failures surface as explicit failure or partial success rather than ordinary send success.

Rationale: The code fix is straightforward only after maintainers choose the host-file read boundary and user-visible delivery semantics for fallback text versus media failure.

Owner confidence: medium

Options:

- **Shared root contract plus explicit failure state (recommended):** Add or bless a shared outbound local-media root policy, wire Feishu to it, and return hard failure or partial-success status for allowlist/upload failures.

- **Preserve fallback success intentionally:** Document Feishu fallback text as expected behavior and close only the unsupported config-key part after a maintainer decision.
