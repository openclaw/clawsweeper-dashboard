## Summary

Keep this PR open: the bounded reader is a plausible hardening direction, but the unchanged 256 KiB ceiling still creates an upgrade-visible startup failure for existing managed-proxy CA bundles without evidence that the cap is compatible, and the PR still lacks real managed-proxy runtime proof.

## What This Changes

The PR routes async and sync managed-proxy CA loading through `readSecretFileSync` with a 256 KiB maximum and adds normal-path and boundary filesystem tests.

## Best Possible Solution

Retain the shared bounded-reader approach, but have the managed-proxy owner approve a demonstrated CA-bundle limit and add redacted real HTTPS managed-proxy proof for both a normal bundle and an over-limit rejection before merge.
