- **[P2] Return a typed blob record from the stub:** `src/proxy-capture/store.sqlite.test.ts:360-364`
  - body: The new stub returns `{ blobId, sha256, byteLength }`, but `persistEventPayload` requires `persistPayload` to return `CaptureBlobRecord | SharedCaptureBlobRecord` with fields such as `sizeBytes` and `encoding`, so the test type gate fails at every new call site.
  - confidence: 0.96
- **[P2] Keep preview truncation byte-bounded:** `src/proxy-capture/store.sqlite.ts:935`
  - body: `buffer.toString("utf8")` decodes the entire captured payload, and `truncateUtf8Prefix` then turns that whole string back into a Buffer before trimming to 8192 bytes. The old path only decoded the preview prefix; for large request, response, or WebSocket payloads this makes preview generation proportional to full body size and can reintroduce capture-side memory and CPU pressure.
  - confidence: 0.9
- **[P2] Cover the standalone proxy preview path:** `src/proxy-capture/store.sqlite.test.ts:368-371`
  - body: The new regression tests exercise only `persistEventPayload`, but `openclaw proxy start/run` records request and response previews through `finishBodyPreviewCapture` in `src/proxy-capture/proxy-server.ts`, which still decodes an arbitrary 8192-byte prefix with `Buffer.concat(...).toString("utf8")`. A real standalone proxy capture can still store a trailing U+FFFD, so the sibling path needs the same boundary-safe fix and proof.
  - confidence: 0.9
