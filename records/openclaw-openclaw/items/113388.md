## Summary

Keep this issue open for explicit security and product-direction review. It requests a new trusted enforcement boundary—not merely the existing coarse ACP permission modes—and its proposed semantics require an ownership decision between OpenClaw’s ACPX extension and the ACP runtime before implementation can safely begin.

## What This Changes

Add a host-owned restrictive policy ceiling for embedded ACP sessions that can narrow remote-chat agent operations without allowing session or provider settings to broaden access.

## System Context

OpenClaw’s ACPX extension creates embedded Agent Client Protocol sessions from gateway/chat configuration and passes them to an external ACP runtime. The requested ceiling would sit between host-controlled session setup and tool execution, determining which workspace operations the runtime may authorize.

## Architecture Diagram

flowchart LR
  A[Gateway chat or binding] --> B[ACPX session setup]
  C[Trusted host policy] --> D[Effective restrictive ceiling]
  B --> D
  D --> E[ACP runtime or adapter]
  E --> F[Tool permission decision]
  F --> G[Workspace operation]
  F --> H[Denied protected operation]

## Best Possible Solution

Agree on a provider-neutral restrictive-policy contract and trusted enforcement seam first, then implement an opt-in host-only configuration with fail-closed containment semantics, opaque session-policy revisioning, and end-to-end coverage for upgrades and persistent-session reuse.
