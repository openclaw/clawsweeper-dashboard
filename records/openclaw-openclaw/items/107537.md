## Summary

The reported arbitrary-directory traversal is not supported by the inspected diagnostics contract: current documentation and the exporter implementation describe a fixed, sanitized set of config, log, status, health, and stability inputs rather than recursively archiving a workspace directory. However, the issue carries the protected `security` label, and the remaining question—whether any configured config, log, or stability input can be replaced by an attacker-controlled symlink—needs explicit security-owner review before closure.

## What This Changes

Harden the diagnostics support exporter against following attacker-controlled symlinks to files outside its intended input boundaries.

## Best Possible Solution

Have a security owner define the exporter’s trusted-input model and run a focused test that replaces each authorized config, log, and stability input with an external-file symlink; if any untrusted mutation path is valid, reject symlinks or open-and-verify the canonical file before reading, with regression tests for both direct and swap-race cases.
