## Summary

Keep this PR open for maintainer review: the implementation is a coherent fix for the duplicate-manager restart-loop report, but it intentionally changes macOS lifecycle policy to fail closed when system-domain ownership cannot be verified, including with `--force`.

## What This Changes

The branch detects same-label system LaunchDaemons before user LaunchAgent install, staging, restart, or recovery and carries conflicts through daemon recovery, update, and doctor flows.

## Best Possible Solution

Adopt one explicit macOS ownership policy, retain the shared typed guard and recovery messages if fail-closed is accepted, then rebase and validate the exact merge head across install, restart, update, and Doctor paths.
