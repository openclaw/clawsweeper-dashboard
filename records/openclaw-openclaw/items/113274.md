## Summary

Keep this feature request open. The supplied history shows an internal conversation-capability foundation landed, but it deliberately omitted a public session configuration contract; that does not establish that persistent session-scoped skill filtering is already available or that this proposed API is the chosen product direction.

## What This Changes

Add a persistent Gateway session setting that can narrow the skills available to one chat session across Control UI, WebSocket, and SSE/OpenAI-compatible chat paths.

## System Context

Gateway chat clients resolve a session and then enter the agent runtime, where skills are selected for the prompt and related runtime paths. This request would add a persistent session-level narrowing policy between existing agent/channel skill filters and those downstream skill consumers.

## Architecture Diagram

flowchart LR
  A[Control UI, WebSocket, SSE clients] --> B[Gateway session API]
  B --> C[Persistent session settings]
  C --> D[Scoped capability resolution]
  D --> E[Skill eligibility and catalog]
  E --> F[Agent prompt and runtime]
  D --> G[Session diagnostics]

## Best Possible Solution

Design one explicit, authenticated session capability contract that can only narrow the already-resolved skill set, persists canonical state safely, invalidates derived skill state, and has focused proof across every Gateway chat entry point before exposing it publicly.
