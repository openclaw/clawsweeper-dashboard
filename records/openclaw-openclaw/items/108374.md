## Summary

Keep open. The merged startup-migration convergence fix addresses the gateway-readiness loop on current main, but this fresh report adds a distinct, high-impact failure: recovery activity allegedly removed an unrelated plugin’s allowlist, configuration, and credential subtree, with status remaining stale after functional recovery. Current evidence does not establish which mutation path caused that loss, so the remaining problem is neither fully implemented nor safely duplicate-closeable.

## What This Changes

Prevent plugin metadata conflicts from blocking upgrades, preserve unrelated plugin configuration and credentials during repair or reinstall, and make plugin status converge after recovery.

## Best Possible Solution

Keep the merged migration-convergence behavior, then make plugin repair transactional and target-scoped: re-read authoritative config before commit, reject conflicting concurrent writes, preserve every unrelated plugin subtree and secret, reconcile the canonical install index and registry idempotently, and expose a Doctor or Control UI Fix action that previews and verifies the repair without requiring manual config editing.
