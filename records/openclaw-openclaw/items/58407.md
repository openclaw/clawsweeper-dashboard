## Summary

Keep open: current main and v2026.6.11 still carry Discord thread parent metadata, thread-starter context, parent transcript inheritance, and manual `listPins`, but they do not automatically fetch or inject parent-channel pinned messages into Discord thread session context. The request is source-reproducible and useful, but it needs maintainer policy for default behavior, context-visibility filtering, and config shape before implementation.

## What This Changes

Request automatic inheritance of a Discord parent channel's pinned messages into sessions started inside that channel's threads.

## Best Possible Solution

Choose the Discord parent-pin inheritance policy first, then implement it inside the Discord plugin using existing pin-read, read-authorization, and context-visibility primitives with focused tests and docs for the selected default or opt-in behavior.

## Reproduction Assessment

Yes, at source level: current main carries Discord thread parent IDs and explicit `listPins`, but the thread inbound-context path only injects quote/thread-starter/group metadata and never fetches parent-channel pins. I did not run a live Discord gateway repro in this read-only review.

## Solution Assessment

Unclear until maintainers choose the product policy. Automatic injection is plausible, but the narrow maintainable solution depends on default behavior, opt-in configuration, and supplemental-context filtering decisions.
