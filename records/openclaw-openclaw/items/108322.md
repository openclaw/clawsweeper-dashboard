- `P2`: This is a bounded correctness bug in an optional Voice Call diagnostic CLI path, with silent output corruption possible but limited user blast radius.

## Summary

The cursor correction addresses skipped bytes, but the patch still decodes and emits each short read independently, so a read ending inside a JSONL record or UTF-8 character can produce split or corrupted output. The PR should stay open for a narrow follow-up on the same branch.

## What This Changes

Updates the Voice Call custom-file tailer to advance its cursor by the actual bytes read and adds regression coverage for a newline-aligned short read.

## Best Possible Solution

Make custom-file following a streaming JSONL reader that preserves undecoded bytes and incomplete records between polls, emitting only complete newline-terminated records while retaining the byte-accurate cursor.

Yes, at source level: current main advances to the observed file size regardless of `bytesRead`, and the supplied production-entrypoint proof exercises that short-read shape. The remaining mid-record failure follows from forcing the same read boundary before a newline.

## Solution Assessment

No. Advancing by `bytesRead` is necessary, but the maintainable fix must also preserve incomplete UTF-8 and JSONL record data across polling iterations.
