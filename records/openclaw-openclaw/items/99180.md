## What This Changes

The PR adds Gateway MCP loopback validation that rejects present non-object `tools/call.params.arguments` values and extends `mcp-http` tests for invalid, omitted, and object-shaped arguments.

## Best Possible Solution

Land this boundary validation if maintainers accept the SDK-aligned malformed-client break; otherwise require a concrete deprecation or compatibility plan for known supported clients before merging.

## Reproduction Assessment

Yes. Current main and `v2026.6.11` cast `methodParams?.arguments ?? {}` directly, while the PR body shows a raw `POST /mcp` with string arguments now returns `-32602` before hook or executor calls.

## Solution Assessment

Yes. Validating only present top-level `arguments` in `handleMcpJsonRpc` is narrower than changing stdio SDK handling or per-tool schemas, and the tests preserve omitted and object-shaped behavior.
