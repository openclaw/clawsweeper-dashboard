## What This Changes

Adds Gateway HTTP MCP loopback validation that rejects present non-object `tools/call.params.arguments` values and tests invalid, omitted, and object argument cases.

## Best Possible Solution

Merge the narrow validation after maintainers explicitly accept enforcing the SDK-aligned object-argument contract at the Gateway HTTP loopback boundary.

## Reproduction Assessment

## Solution Assessment

Yes. Validating the raw HTTP loopback boundary before hooks and execution is the narrowest maintainable fix; broader per-tool schema validation or stdio changes would be outside this bug.
