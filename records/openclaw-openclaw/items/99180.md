## Summary

## What This Changes

The PR rejects present non-object Gateway MCP loopback `tools/call.params.arguments` with JSON-RPC `-32602` and adds tests for invalid, omitted, and object-shaped arguments.

## Best Possible Solution

Land this boundary validation after maintainer acceptance of the malformed-client compatibility tightening, keeping omitted and object-shaped arguments unchanged and avoiding broader per-tool schema validation in this PR.

## Reproduction Assessment

Yes by source inspection. Current main and v2026.6.11 cast `methodParams?.arguments ?? {}` directly, while the PR body and Real behavior proof show a raw loopback request with string arguments now returns `-32602` before hook/executor side effects.

## Solution Assessment

Yes. The raw HTTP loopback path is the surface bypassing SDK request validation, and validating present `arguments` before hooks/execution is narrower than changing stdio handling or per-tool schemas.
