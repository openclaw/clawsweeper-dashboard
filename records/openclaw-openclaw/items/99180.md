## Summary

## What This Changes

The PR adds a Gateway MCP loopback guard that rejects present non-object `tools/call.params.arguments` with JSON-RPC `-32602` and adds raw HTTP regression coverage for rejected, omitted, and object argument shapes.

## Best Possible Solution

Merge the handler-local guard after maintainer acceptance of the invalid-client behavior change, or document and test a legacy tolerance exception if that compatibility is required.

## Reproduction Assessment

Yes. Source inspection shows current main and `v2026.6.11` cast raw `tools/call.params.arguments` into a record, and the PR body plus added tests demonstrate the raw HTTP path that should reject non-object values before hook/tool side effects.

## Solution Assessment

Yes. The handler-local guard is the narrowest maintainable fix because the raw HTTP loopback path bypasses the SDK request schema while the sibling stdio MCP path already uses `CallToolRequestSchema`; full per-tool schema validation would be broader than the reported boundary bug.
