## Summary

Keep open: current usage summaries and `model.usage` diagnostics provide adjacent observability, but no merged work establishes the requested durable per-call ledger, event identity, job/run attribution, backfill, or canonical ledger-first readers. Recent maintainer discussion explicitly preserves that distinction, while current plugin hooks make the correct core-versus-plugin boundary a product decision.

## What This Changes

Request a native per-call usage ledger with provider/model, session/run/source attribution, token and cost fields, and efficient aggregation for cost tracking.

## Best Possible Solution

Choose one canonical boundary: standardize a privacy-minimized usage-event plugin contract and route accounting products through ClawHub, or—only if offline local accounting is foundational—store deduplicated usage events in the appropriate SQLite state database with retention, backfill, and shared CLI/UI readers.
