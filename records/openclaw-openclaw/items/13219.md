## Summary

Keep open: current main has transcript-backed usage summaries, a durable cache for those transcript scans, and run-level `model.usage` diagnostics, but it still does not implement the requested native per-call usage ledger with stable event IDs, source/run/job attribution, idempotent writes, backfill, and ledger-first readers.

## What This Changes

Request native per-model and per-call usage logging with session/source attribution so users can track cost, model mix, and automated-job spend without parsing session transcripts manually.

## Best Possible Solution

Define one privacy-safe canonical usage-ledger contract at the normalized model-call accounting seam, store it in the appropriate SQLite-backed state owner, and make usage.cost, CLI/UI summaries, diagnostics/plugin views, and backfill read from that contract without duplicating pricing policy.

## Reproduction Assessment

Yes, at source level: current main exposes transcript-backed summaries and model.usage diagnostics, but no durable per-call ledger with event IDs, source/run/job attribution, backfill, or ledger-first readers.

## Solution Assessment

Unclear as requested: the native accounting goal is valid, but the proposed JSONL log should be reconciled with the repo's SQLite-state policy and with plugin/provider-scoped usage APIs before implementation.
