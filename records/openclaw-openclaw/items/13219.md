## Summary

Keep open: current main has transcript-backed cost summaries, durable transcript aggregate cache, `model.usage` diagnostics, and UI cost analysis, but not the requested canonical per-call usage ledger with durable event IDs, source/run/job attribution, backfill, and ledger-first readers.

## What This Changes

The issue requests native per-model/per-call usage logging for cost tracking and model-mix optimization without requiring users to parse session JSONL transcripts manually.

## Best Possible Solution

Define one canonical completed-model-call usage ledger, likely SQLite-backed under current storage policy, written at the normalized usage/cost seam with safe metadata only, durable event IDs, source/run/job attribution, backfill, and readers for CLI, UI, gateway, and plugin summaries.
