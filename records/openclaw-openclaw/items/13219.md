## Summary

Keep open: current main and v2026.6.11 still provide transcript/cache-backed usage summaries and `model.usage` diagnostics, but not the requested durable per-call usage ledger with event IDs, source/run/job attribution, idempotency, backfill, and ledger-first readers. The remaining work needs maintainer product and storage-boundary design.

## What This Changes

Request native per-model/per-call usage logging for cost tracking, model-mix analysis, budget monitoring, and cron/session attribution.

## Best Possible Solution

Define one canonical completed-model-call usage ledger at the normalized usage/cost seam, likely in the shared state DB with additive readers, durable idempotency keys, source/run/job attribution, no prompt or completion content, backfill from transcripts, and transcript fallback only for older data.

Options:

- **Design DB-backed core ledger (recommended):** Record completed model-call usage in a canonical state-store ledger with event IDs, source/run/job attribution, no content fields, transcript backfill, and ledger-first usage readers.
- **Expose plugin observer first:** Prioritize a narrow provider/plugin model-usage feed and leave native summaries transcript-backed until the storage contract is settled.
- **Defer native ledger:** Keep current transcript summaries, diagnostics, and external tools such as burn0 or a ClawHub plugin as the supported path for now.

## Solution Assessment
