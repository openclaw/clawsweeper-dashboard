## Summary

Keep open: current main still has transcript/cache-backed cost summaries and `model.usage` diagnostics, but not the requested durable per-call usage ledger with event IDs, source/run/job attribution, idempotency, backfill, or ledger-first readers.

## What This Changes

Request native durable per-call/per-model usage logging for cost tracking, model-mix analysis, and cron/session attribution.

## Best Possible Solution

Define one core completed-model-call usage ledger contract, likely SQLite-backed, written at the normalized usage/cost seam with safe metadata only, durable event IDs, source/run/job attribution, backfill, and readers for CLI, UI, and plugin summaries.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw make a core durable completed-call usage ledger the canonical accounting source, or should spend accounting stay on plugin/diagnostic seams for now?

Rationale: The user need is source-reproducible, but the durable accounting boundary affects core storage policy, privacy, gateway/API contracts, plugin capability design, and future UI/CLI readers, so automation should not choose it unilaterally.

Likely owner: steipete

Owner reason: He has the strongest history on current usage-cost summaries, the usage docs, and the prior ledger-scope review.

Owner confidence: high

Options:

- **Design the core ledger first (recommended):** Create a maintainer-owned first phase for a canonical SQLite-backed ledger plus transcript backfill and ledger-first readers, then let plugins consume that stable seam.
- **Expose a plugin seam first:** Prioritize provider-scoped or observer-gated model-usage plugin delivery and leave durable spend ledgers to ClawHub plugins until native accounting requirements are clearer.
- **Defer native accounting:** Keep existing transcript summaries and diagnostics only, and revisit after adjacent usage, auth-profile, and plugin API issues settle.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 can be inspected to show transcript/cache-derived usage summaries and `model.usage` diagnostics exist, but no durable per-call ledger type, writer, idempotency key, backfill, or ledger-first reader exists.

## Solution Assessment

No current implementation fully solves the issue. The maintainable path is a single canonical completed-call accounting contract, not a transcript-only cache, diagnostics-only hook, or standalone plugin ledger that can diverge from OpenClaw summaries.
