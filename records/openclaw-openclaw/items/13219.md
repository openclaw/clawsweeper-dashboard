## Summary

Keep open: current main and v2026.6.11 still provide transcript/cache-derived usage summaries, per-session model/provider buckets, provider quota status, and diagnostic events, but not the requested durable per-call usage ledger with stable event IDs, source/run/job attribution, idempotent writes, backfill, and ledger-first readers.

## What This Changes

The issue requests native per-model usage logging with a dedicated per-call usage ledger for cost tracking and model-mix optimization.

## Best Possible Solution

Define one canonical, privacy-safe completed-model-call usage ledger with stable event IDs, source/run/job/session attribution, backfill, and ledger-first readers, following the repo storage policy unless maintainers explicitly designate a file ledger as a product artifact.

## Reproduction Assessment

Yes, at source level. Current main exposes transcript-derived summaries and live diagnostic events, but no durable per-call ledger with stable IDs, source/run/job attribution, backfill, and ledger-first readers.

## Solution Assessment

Unclear until maintainers choose the storage, privacy, API, and plugin boundary. A native ledger is the maintainable direction, but it should not create a second accounting source beside diagnostics, transcript caches, and plugin exports.
