## Summary

Keep open: current main and the latest release still provide transcript-backed summaries, a derived usage-cost cache, and live `model.usage` diagnostics, but not the requested durable per-call usage ledger with stable IDs, source/run/job attribution, backfill, and ledger-first readers. The linked CLI and plugin/diagnostics PRs are adjacent seams, not replacements for the native accounting design.

## What This Changes

Request native per-model usage logging so users can track model mix, tokens, cost, and background-job consumption without parsing session transcripts manually.

## Best Possible Solution

Define one canonical, privacy-safe completed-model-call usage ledger or equivalent core accounting contract, then derive `usage.cost`, `sessions.usage`, CLI/UI summaries, backfill, and plugin/export views from that source while preserving transcript scans for older data.

## Reproduction Assessment

Yes, at source level. Current main has transcript-derived summaries, a usage-cost cache, and live diagnostic/plugin event proposals, but no durable per-call ledger with stable IDs, source/run/job attribution, backfill, and ledger-first readers.

## Solution Assessment

Unclear. A native ledger is plausible and probably the right end state, but maintainers still need to choose the storage/API/privacy/source-of-truth boundary; transcript cache or diagnostics alone are not the best durable billing record.
