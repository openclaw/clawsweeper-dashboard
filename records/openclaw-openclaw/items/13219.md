## Summary

Keep open: current main and v2026.6.11 have transcript/cache-backed usage summaries, session usage views, provider quota/status surfaces, and `model.usage` diagnostics, but still do not implement the requested native durable per-call usage ledger with stable event IDs, source/run/job attribution, idempotent writes, backfill, and ledger-first readers.

## What This Changes

Request native per-model/per-call usage logging so users can track cost, model mix, automated-job spend, and routing behavior without parsing every session transcript manually.

## Best Possible Solution

Define a single core completed-model-call usage ledger contract, likely SQLite-backed, written at the normalized usage/cost seam with safe metadata only, durable event IDs/idempotency, source/run/job attribution, backfill, and readers for CLI/UI/plugin summaries.

Rationale: The evidence shows the user problem is real but the right boundary affects core storage policy, privacy, gateway/API contracts, plugin capability design, and future UI/CLI readers, so automation should not choose it unilaterally.

Options:

- **Design the core ledger first (recommended):** Create a maintainer-owned first phase for a canonical SQLite-backed ledger plus transcript backfill and ledger-first readers, then let plugins consume that stable seam.
- **Expose a plugin seam first:** Prioritize the provider-scoped model-usage plugin feed and leave durable spend ledgers to ClawHub plugins until native accounting requirements are clearer.
- **Defer native accounting:** Keep existing transcript summaries and diagnostics only, and revisit this after adjacent usage, auth-profile, and plugin API issues settle.

## Reproduction Assessment

Yes, at source level. Current main and the latest release can be inspected to show transcript/cache-derived usage summaries and `model.usage` diagnostics exist, but no durable per-call ledger type, writer, idempotency key, backfill, or ledger-first reader exists.

## Solution Assessment

No current implementation fully solves the issue. The maintainable path is a single canonical completed-call accounting contract, not a transcript-only cache, diagnostics-only hook, or standalone plugin ledger that can diverge from OpenClaw summaries.
