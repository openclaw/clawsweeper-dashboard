## Summary

Keep open: current main and the latest release still provide transcript-backed usage summaries, a durable derived cache, and live diagnostic usage events, but not the requested native per-call usage ledger with stable event IDs, source/job/run attribution, idempotent writes, backfill, and ledger-first readers. Existing external tools and adjacent PRs are useful context, but they do not replace the core accounting/product decision.

## What This Changes

The issue requests native per-model/per-call usage logging for cost tracking, model-mix analysis, and cron/session attribution.

## Best Possible Solution

Define one canonical privacy-safe completed-model-call accounting contract, preferably SQLite-backed under the shared or agent state store, then derive usage.cost, sessions.usage, CLI/UI summaries, backfill, and plugin/export views from that source.

## Reproduction Assessment

Yes, at source level. Current main has transcript-derived summaries, a derived usage-cost cache, and live diagnostic events, but no durable per-call ledger with stable IDs, source/run/job attribution, backfill, or ledger-first readers.

## Solution Assessment

Unclear. A native accounting ledger is plausible, but maintainers need to choose storage, API/plugin boundaries, privacy, and source-of-truth semantics before implementation; the literal JSONL log proposal should be reconciled with the repo's SQLite-first state policy.
