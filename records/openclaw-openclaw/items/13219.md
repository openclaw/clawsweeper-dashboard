## Summary

Keep open: current main has transcript-backed cost summaries, a derived usage cache, provider quota/status surfaces, and live `model.usage` diagnostics, but it still lacks the requested durable native per-call usage ledger with stable IDs, source/run/job attribution, backfill, and ledger-first readers. burn0 and the ClawHub tokenomics/plugin work are useful adjacent options, but they do not replace the missing core/API design.

## What This Changes

Request a native per-model completed-call usage log or ledger for cost tracking, model-mix optimization, and cron/session attribution.

## Best Possible Solution

Define one privacy-safe completed-model-call accounting contract, likely backed by canonical storage rather than ad hoc JSONL state, with stable IDs, provider/model, agent/session/run/source/job attribution, tokens, cache, cost, status, and latency; then derive `/usage cost`, CLI/UI summaries, backfill, and plugin/export views from it.

## Reproduction Assessment

Yes, at source level. Current main can be checked by inspecting the transcript-backed summary path and live `model.usage` diagnostics, neither of which provides a durable per-call ledger with stable IDs, source/run/job attribution, backfill, and ledger-first readers.

## Solution Assessment

Unclear. A native usage ledger is a plausible solution, but maintainers need to choose the durable storage, privacy, API, and plugin/export boundary before implementation.
