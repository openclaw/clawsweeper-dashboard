## Summary

Keep open: current main has transcript-backed cost/session summaries, gateway usage APIs, cron/model diagnostic events, and adjacent plugin proposals, but it still does not provide the requested durable native per-call usage ledger with stable event IDs, source/run/job attribution, backfill, and ledger-first readers.

## What This Changes

Request native per-model, per-call usage logging for cost tracking and model-mix optimization across sessions, cron, heartbeat, and other agent sources.

## Best Possible Solution

Define a maintainer-approved usage accounting seam: a typed, content-free, idempotent UsageLedgerEntry stored in the canonical SQLite state path or exposed through a stable plugin feed, written at the normalized model-call usage/cost point, with transcript backfill and ledger-first usage.cost/session readers.

## Reproduction Assessment

Yes, at source level: current main can be checked by reading the usage.cost/session usage paths, which still derive summaries from transcripts and diagnostics rather than a durable per-call ledger. I did not run a live gateway scenario because the missing behavior is clear from the current source and docs.

## Solution Assessment

No current implementation is the full solution: transcript scanning, model.usage diagnostics, and plugin proposals are useful adjacent pieces but do not satisfy durable idempotent ledger storage and ledger-first readers. The best fix needs maintainer direction on core storage versus plugin API boundaries before implementation.
