## Summary

Keep open: current main and the latest release still provide transcript/cache-backed usage summaries plus live diagnostic usage events, but they do not implement the requested durable per-call usage ledger with stable IDs, source/run/job attribution, backfill, or ledger-first readers. Related plugin/diagnostics PRs and external tools are useful adjacent work, not a replacement for the native accounting source-of-truth decision.

## What This Changes

Request native per-model and per-call usage logging for cost tracking, model-mix analysis, cron/subagent attribution, and future budget reporting.

## Best Possible Solution

Define a canonical completed-model-call usage ledger at the normalized usage/cost seam, store only accounting metadata in an approved durable store, and make CLI/UI/plugin reports consume that source with transcript backfill for older sessions.

## Reproduction Assessment

Yes, at source level. Current main has transcript-backed summaries and live model.usage diagnostics, but no durable per-call ledger types, writer, backfill, source/run/job attribution, or ledger-first readers.

## Solution Assessment

No current implementation fully solves this issue. The best path is a single native completed-call accounting contract first, with reports and plugin surfaces derived from that contract instead of more transcript-only or diagnostics-only summaries.
