## Summary

Keep open: current main and the latest release provide transcript-backed usage/cost summaries, per-session model aggregates, provider quota/status surfaces, and live `model.usage` diagnostics, but they still do not implement the requested durable per-call usage ledger with stable event IDs, run/source/job attribution, idempotent writes, backfill, or ledger-first readers. Existing external tools and adjacent open PRs are useful complements, not replacements for the native accounting design.

## What This Changes

Request native per-model usage logging so users can track costs, model mix, sessions, and automated-job consumption without manually parsing session transcripts.

## Best Possible Solution

Define a core completed-model-call usage ledger written at the normalized usage/cost seam, with durable idempotent event IDs, provider/model plus agent/session/run/source/job attribution, token/cache/cost/status/latency metadata, no prompt/completion content, ledger-first readers, and an explicit backfill path from older transcripts.

## Reproduction Assessment

Yes, at source level. Current main can be inspected to show transcript-backed usage summaries, live `model.usage` diagnostics, and provider/model aggregates, but no durable per-call usage ledger with event IDs, source/run/job attribution, backfill, or ledger-first readers.

## Solution Assessment

No current implementation fully solves the issue. The best path is a single core ledger/accounting contract rather than a CLI-only transcript parser, diagnostics-only hook, or provider-plugin-only feed.
