## Summary

Keep open: current main has transcript-backed cost/session summaries, a derived usage-cost cache, and live `model.usage` diagnostics, but it still lacks the requested native durable per-call usage ledger with stable event IDs, source/run/job attribution, backfill, and ledger-first readers. External tools and plugin proposals are useful adjacent workarounds, but they do not replace the core accounting design.

## What This Changes

Request native per-model usage logging for cost tracking with per-call model, token, cost, source, and session attribution.

## Best Possible Solution

Add a core typed completed-model-call usage ledger at the normalized usage/cost seam, stored through the canonical SQLite state layer, with durable event IDs, provider/model, agent/session/run/source/job attribution, token/cache/cost/status/latency metadata, no prompt or completion content, a backfill/import path for old transcripts, and ledger-first `usage.cost`/CLI/UI readers with transcript compatibility only in migration/backfill code.

## Reproduction Assessment

Yes. At source level, current main has transcript-backed summaries, a transcript-derived cache, and live diagnostics, but no native append-only per-call usage ledger with idempotent event records and source/run/job attribution.

## Solution Assessment

No current implementation fully solves it. The maintainable path is a single canonical completed-call ledger feeding summaries and plugin/API consumers, not a transcript parser, docs-only diagnostic event list, or one-off plugin ledger as the source of truth.
