## Summary

Keep open: current main has transcript-backed cost/session summaries, per-session usage views, and live `model.usage` diagnostics, but it still lacks the requested durable per-call usage ledger with stable event IDs, source/run/job/auth attribution, idempotent writes, backfill, and ledger-first readers. Adjacent CLI, diagnostics, plugin, and provider-scoped proposals are useful but do not replace the core accounting design.

## What This Changes

Request durable per-model/token/cost usage logging with enough attribution to analyze model spend across sessions, agents, cron/heartbeat work, and provider/auth paths.

## Best Possible Solution

Define one canonical SQLite-backed, privacy-safe `UsageLedgerEntry` at the normalized model-call usage/cost seam with stable event IDs/idempotency, provider/model/agent/session/run/source/job/auth attribution, token/cache/cost/status/latency metadata, no prompt/completion content, transcript backfill, and ledger-first `usage.cost`, session, UI, and CLI readers.

## Reproduction Assessment

Yes from source: main exposes transcript-derived summaries and live `model.usage` diagnostics, but no durable per-call ledger with stable ids, idempotency, backfill, and source/job/auth attribution.

## Solution Assessment

Unclear as a complete implementation path: a native ledger is the right class of solution, but maintainers still need to decide storage schema, reader migration, privacy/access policy, and how adjacent plugin/diagnostic proposals fit.
