## Summary

Keep open: current main has transcript/cache-derived usage summaries, per-session views, provider quota status, and `model.usage` diagnostics, but it still does not implement the requested durable native per-call usage ledger with stable event IDs, source/run/job attribution, idempotent writes, backfill, and ledger-first readers.

## What This Changes

Request native per-model and per-call usage logging for cost tracking, model-mix analysis, and session/source attribution.

## Best Possible Solution

Define one canonical, privacy-safe completed-model-call usage ledger with stable event IDs, source/run/job/session attribution, backfill, and ledger-first readers, following the repo storage policy unless maintainers explicitly designate JSONL as an export artifact.

## Reproduction Assessment

Yes. Source inspection reproduces the gap: current main exposes transcript-derived summaries and live diagnostic events, but no durable per-call ledger with stable IDs, source/run/job attribution, backfill, and ledger-first readers.

## Solution Assessment

Unclear until maintainers choose the storage, privacy, API, and plugin boundary. A native ledger is the maintainable direction, but it should not create a second accounting source beside diagnostics, transcript caches, and plugin exports.
