## Summary

Keep open: current main has transcript-backed cost/session summaries, per-session usage log views, and live `model.usage` diagnostics, but it still lacks the requested durable per-call usage ledger with stable event IDs, source/run/job attribution, idempotent writes, backfill, and ledger-first readers. The related CLI, diagnostics, and plugin proposals are useful adjacent work, not replacements for the core accounting design.

## What This Changes

Request native per-model usage logging so users can track cost, model mix, cron/subagent attribution, and budget signals without parsing session transcripts manually.

## Best Possible Solution

Define one canonical, privacy-safe completed-model-call usage ledger with stable event IDs and attribution, then derive `usage.cost`, `sessions.usage`, CLI/UI summaries, backfill, and optional plugin/export views from that source.

## Reproduction Assessment

Yes. Source inspection shows current main has transcript-derived summaries and live diagnostic events, but no durable per-call ledger with stable IDs, source/run/job attribution, backfill, and ledger-first readers.

## Solution Assessment

Unclear. A native ledger is the plausible maintainable direction, but maintainers need to choose the storage/API/privacy boundary before an implementation should proceed.
