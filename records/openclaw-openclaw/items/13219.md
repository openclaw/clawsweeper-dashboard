## Summary

Keep open: current main has transcript-derived usage summaries, a cache-backed gateway/API surface, and live `model.usage` diagnostics, but it still lacks the requested durable per-call usage ledger with stable event IDs, source/run/job attribution, idempotent writes, backfill, and ledger-first readers. The linked CLI, plugin, diagnostics, burn0, and ClawMetry workarounds are useful adjacent paths, not replacements for a native accounting design.

## What This Changes

Request native per-model and per-call usage logging for cost tracking, model-mix optimization, and cron/session attribution.

## Best Possible Solution

Design one privacy-safe SQLite-backed completed-model-call usage ledger with stable event IDs, provider/model, agent/session/run/source/job attribution, token/cache/cost/status/latency metadata, no prompt or completion content, transcript backfill, and ledger-first CLI/UI/gateway readers.

## Reproduction Assessment

Yes, at source level: current main exposes transcript-backed summaries, caches, and diagnostics, but no canonical per-call ledger type, writer, backfill, or ledger-first reader exists.

## Solution Assessment

Unclear as an implementation shape: a native ledger is the right product direction to evaluate, but maintainers still need to decide the storage, privacy, API, and migration boundaries; external tools and plugins are only workarounds.
