## Summary

Keep open: current main has transcript-backed cost summaries, a durable derived usage-cost cache, session usage views, and live `model.usage` diagnostics, but it still lacks the requested native completed-call usage ledger with stable IDs, source/run/job attribution, backfill, and ledger-first readers. Adjacent plugin/docs PRs and external tools help, but they do not replace the core accounting source requested here.

## What This Changes

Request native per-model and per-call usage logging so users can track costs, model mix, cron/session attribution, and budget impact without manually parsing session transcripts.

## Best Possible Solution

Define one privacy-safe completed-model-call usage ledger in the appropriate core state store, then derive `usage.cost`, session/CLI/UI summaries, backfill, and optional plugin/export views from that canonical source.

## Reproduction Assessment

Yes. Source inspection shows current main derives summaries from session transcripts and emits live diagnostics, but has no durable per-call ledger with stable IDs, source/run/job attribution, backfill, and ledger-first readers.

## Solution Assessment

Unclear. The accounting need is valid, but the example JSONL log is not clearly the best permanent shape under current storage policy; maintainers should choose the canonical ledger, export, and plugin boundaries first.
