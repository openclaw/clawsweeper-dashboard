## Summary

Keep open: current main still has transcript-backed usage summaries, a derived usage-cost cache, and live `model.usage` diagnostics, but not the requested durable per-call usage ledger with stable IDs, source/run/job attribution, backfill, and ledger-first readers. Related diagnostics, docs, plugin, burn0, ClawMetry, and tokenomics work are useful adjacent paths, not replacements for the native accounting design.

## What This Changes

Request a native per-model/per-call usage ledger or log for cost tracking, model-mix analysis, budget monitoring, and cron/session attribution.

## Best Possible Solution

Define one canonical, privacy-safe completed-model-call usage ledger in the appropriate SQLite-backed store, then derive usage.cost, sessions.usage, CLI/UI summaries, backfill, and approved plugin/export views from that source.

## Reproduction Assessment

Yes for source-level review. Current main has transcript-derived summaries and live diagnostic events, but no durable per-call ledger with stable event IDs, source/run/job attribution, backfill, and ledger-first readers.

## Solution Assessment

Unclear pending maintainer direction. A native ledger is plausible and useful, but the best implementation should follow the repository storage/privacy policy and product decision rather than adding an ad hoc JSONL runtime state file.
