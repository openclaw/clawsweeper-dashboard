## Summary

Keep open: current main and the latest release have transcript-backed cost/session summaries, per-session log views, live `model.usage` diagnostics, and adjacent plugin proposals, but they still do not provide the requested durable per-call usage ledger with stable event ids, source/run/job attribution, idempotent writes, backfill, and ledger-first readers.

## What This Changes

The issue requests native per-model usage logging for cost tracking and model-mix optimization without parsing all session transcript JSONL files manually.

## Best Possible Solution

Define one canonical, privacy-safe completed-model-call usage ledger with stable event ids, source/run/job/session attribution, backfill, and ledger-first readers; follow the repo storage policy unless maintainers explicitly define JSONL as an export artifact.

## Reproduction Assessment

Yes, at source level. Current main exposes transcript-derived summaries and live diagnostic events, but no durable per-call ledger with stable ids, source/run/job attribution, backfill, and ledger-first readers.

## Solution Assessment

Unclear until maintainers choose the storage/API/privacy boundary. A native ledger is the maintainable direction, but it should avoid creating competing accounting sources beside diagnostics, transcript caches, and plugin exports.
