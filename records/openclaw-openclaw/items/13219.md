## Summary

Keep open: current main still has transcript-backed summaries and live `model.usage` diagnostics, but no native durable per-call usage ledger with stable IDs, source/run/job attribution, backfill, or ledger-first readers. The linked CLI/plugin efforts are useful adjacent work, not replacements for the native accounting design.

## What This Changes

The issue requests native per-model usage logging so users can track costs, model mix, cron/subagent spend, and budget behavior without parsing every session transcript.

## Best Possible Solution

Define a core completed-model-call usage ledger at the normalized usage/cost seam, store only accounting metadata, and let CLI/UI/plugin reports consume that canonical source with transcript backfill for older sessions.

## Reproduction Assessment

Yes, at source level: current main has transcript-backed summaries and `model.usage` diagnostics, but no durable per-call ledger types, writer, backfill, or ledger-first readers. I did not run a live user scenario because the missing capability is visible from the current source and docs.

## Solution Assessment

No current implementation fully solves this issue. The best fix is a canonical core usage-ledger contract first, then reports and plugin surfaces derived from that contract rather than more transcript-only or diagnostics-only summaries.
