## Summary

Keep open: current main has transcript/cache-derived usage summaries, per-session views, provider quota status, and `model.usage` diagnostics, but it still does not implement the requested durable native per-call usage ledger with stable event IDs, source/run/job attribution, idempotent writes, backfill, and ledger-first readers.

## What This Changes

Request native durable per-model/per-call usage logging for cost tracking and model-mix optimization instead of requiring users to parse session JSONL files manually.

## Best Possible Solution

Define one canonical, privacy-safe completed-model-call usage ledger, likely SQLite-backed unless explicitly designated as an export log, then write it at the normalized model-call usage/cost seam and make CLI/UI/gateway summaries plus backfill read from it before transcript fallback.

## Reproduction Assessment

Yes. Source inspection reproduces the gap: current main exposes transcript-derived summaries and diagnostic events, but no durable per-call usage ledger with stable IDs, source/run/job attribution, backfill, and ledger-first readers.

## Solution Assessment

Unclear until maintainers choose the storage, privacy, API, and plugin boundary. A native ledger is the maintainable direction, but it should be one canonical accounting source rather than a duplicate beside diagnostics, transcript caches, and plugin exports.
