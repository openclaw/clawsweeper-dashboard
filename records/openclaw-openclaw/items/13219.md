## Summary

Keep open: current main and v2026.6.11 still provide transcript/cache-backed usage summaries and `model.usage` diagnostics, but not the requested durable per-call usage ledger with event IDs, source/run/job attribution, idempotent writes, backfill, and ledger-first readers.

## What This Changes

The issue requests a native per-model/per-call usage log for cost tracking, model-mix analysis, cron/subagent attribution, and budget monitoring.

## Best Possible Solution

Define one canonical completed-model-call usage ledger, likely in the shared state DB, with durable idempotency keys, source/run/job attribution, no prompt or completion content, transcript backfill, and ledger-first usage readers.
