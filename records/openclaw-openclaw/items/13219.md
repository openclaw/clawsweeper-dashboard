## Summary

Keep open: current main still provides transcript-backed usage summaries, a derived usage-cost cache, live `model.usage` diagnostics, and adjacent plugin/API proposals, but it does not provide the requested durable per-call usage ledger with stable IDs, source/run/job attribution, backfill, and ledger-first readers. The remaining work is a product/storage/API boundary decision, not conservative cleanup.

## What This Changes

The issue requests native per-model/per-call usage logging so users can track cost, model mix, and background job consumption without parsing session transcript JSONL files.

## Best Possible Solution

Define one canonical, privacy-safe completed-model-call accounting contract, preferably SQLite-backed unless explicitly approved as a product artifact, then derive `usage.cost`, `sessions.usage`, CLI/UI summaries, backfill, and plugin/export views from that source.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes, at source level: current main has transcript-derived summaries, a derived usage-cost cache, and live diagnostic events, but no durable per-call ledger with stable IDs, source/run/job attribution, backfill, and ledger-first readers.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainers choose the permanent storage/API boundary; a native ledger is plausible, but the maintainable solution must reconcile core accounting, plugin seams, privacy, and SQLite-vs-artifact storage before implementation.
