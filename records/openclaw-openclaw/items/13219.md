## Summary

Keep open: current main has transcript-backed cost/session summaries, a derived usage-cost cache, and live `model.usage` diagnostics, but still lacks the requested durable per-call usage ledger with stable event IDs, source/run/job attribution, idempotent writes, backfill, and ledger-first readers.

## What This Changes

The issue requests native per-model usage logging with per-call token, cache, cost, session, and source attribution for cost tracking.

## Best Possible Solution

Define a canonical, privacy-safe completed-model-call usage ledger at the normalized usage/cost seam, preferably SQLite-backed with optional export, then make `usage.cost`, CLI/UI summaries, and backfill read from that ledger with transcript compatibility for old data.

## Reproduction Assessment

Yes, at source level: current main exposes transcript-derived summaries and live diagnostic events, but no durable per-call ledger with stable IDs, source/run/job attribution, backfill, and ledger-first readers.

## Solution Assessment

No current implementation fully solves it. The maintainable path is a single canonical completed-call ledger rather than treating diagnostics, transcript caches, or plugin exports as competing accounting sources.
