## Summary

Keep this open: current main has transcript-backed cost/session summaries, per-session usage log views, live model.usage diagnostics, and adjacent plugin/API proposals, but it still lacks the requested durable per-call usage ledger with stable event ids, source/run/job attribution, idempotent writes, backfill, and ledger-first readers.

## What This Changes

The issue requests native per-model LLM usage logging for cost tracking, model-mix analysis, cron/session attribution, and future budget monitoring.

## Best Possible Solution

Define one canonical, privacy-safe completed-model-call usage ledger with stable event ids, source/run/job/session attribution, backfill, and ledger-first readers; follow the repo storage policy with SQLite-backed state unless maintainers explicitly approve JSONL as a named export/artifact.

## Reproduction Assessment

Yes. Source inspection reproduces the gap: current main exposes transcript-derived summaries and live diagnostic events, but no durable per-call ledger with stable ids, source/run/job attribution, backfill, and ledger-first readers.

## Solution Assessment

Unclear until maintainers choose the storage/API/privacy boundary. A native ledger is the maintainable direction, but the implementation should avoid creating a second accounting source beside diagnostics, transcript caches, and plugin exports.
