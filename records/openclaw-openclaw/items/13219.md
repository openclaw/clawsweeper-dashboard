## Summary

Keep open: current main and the latest release still provide transcript-backed usage summaries plus run-level `model.usage` diagnostics, but not the requested durable per-call usage ledger with stable ids, source/run/job attribution, backfill, and ledger-first readers. Related plugin and docs work is useful adjacent work, not a replacement for the native accounting design.

## What This Changes

Request native per-model usage logging so users can track cost, model mix, cron/subagent spend, and routing decisions without parsing every session transcript.

## Best Possible Solution

Define a core completed-model-call usage ledger at the normalized usage/cost seam, store only accounting metadata, and make CLI/UI/plugin reports consume that canonical source with transcript backfill for older sessions.

## Reproduction Assessment

Yes. Source inspection shows current main has transcript-backed summaries and `model.usage` diagnostics, but no durable per-call ledger types, writer, backfill, or ledger-first readers; a live scenario was not needed to prove the missing capability.

## Solution Assessment

No current implementation fully solves this issue. The maintainable path is a canonical core usage-ledger contract first, then reports and plugin surfaces derived from that contract rather than more transcript-only or diagnostics-only summaries.
