## Summary

Keep open: current main has transcript-backed cost/session summaries, per-session transcript log views, live model.usage diagnostics, and observability plugins, but it still lacks the requested durable per-call usage ledger with stable usage event ids, source/run/job attribution, idempotent writes, backfill, and ledger-first readers.

## What This Changes

Requested native per-model usage logging for cost tracking through a dedicated per-call usage ledger with model, session/source attribution, token/cache, and cost fields.

## Best Possible Solution

Define one canonical, privacy-safe completed-model-call usage ledger with stable event ids, source/run/job/session attribution, backfill, and ledger-first readers; follow the repo storage policy with SQLite-backed state unless maintainers explicitly define JSONL as an export artifact.

## Reproduction Assessment

Yes. Source inspection reproduces the gap: current main exposes transcript-derived summaries and live diagnostic events, but no durable per-call ledger with stable ids, source/run/job attribution, backfill, and ledger-first readers.

## Solution Assessment

Unclear until maintainers choose the storage/API/privacy boundary. A native ledger is the maintainable direction, but the implementation should avoid creating a second accounting source beside diagnostics, transcript caches, and plugin exports.
