  - body: `renderGatewayServiceCleanupHints()` now returns `[]` when called without a service list, but `status.print.ts` still calls it with no arguments after reporting `extraServices`.   - body: Filtering out every `svc.legacy` before rendering hints drops the only manual cleanup guidance when legacy cleanup is skipped by policy, declined, fails, or is system-scoped. In those paths doctor still reports the legacy service but no longer gives the user a command to remove it.
  - confidence: 0.88
- **[P2] Honor service scope in cleanup commands:** `src/daemon/inspect.ts:38-46`
  - body: The new helper receives `svc.scope` but always emits `launchctl bootout gui/$UID/...` and `systemctl --user ...`. For `doctor --deep` findings from `/Library/LaunchDaemons` or system systemd directories, those commands target the wrong service manager and leave the detected system service installed.
  - confidence: 0.9
- **[P2] Keep lenient SecretRef handling out of strict helpers:** `src/config/types.secrets.ts:143-150`
  - body: This strict helper is exported through the plugin SDK, but the PR makes it read a process-wide doctor env flag and warn instead of throwing for unresolved `exec` refs. During doctor, any strict caller in the same process can silently receive `undefined`; use a doctor-only inspect path instead of weakening the shared strict contract.
  - confidence: 0.82
