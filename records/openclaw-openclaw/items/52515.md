## Summary

Keep open: the linked bug is still real, but this PR is conflicting and the current patch is not safe to merge because it drops status cleanup hints, loses legacy-service manual guidance, emits wrong-scope system cleanup commands, and broadens strict SecretRef behavior through a process env flag.

## What This Changes

The PR changes doctor gateway cleanup hints to render from detected extra services, wraps doctor execution in an env flag that downgrades unresolved exec SecretRefs to warnings, and updates generated plugin SDK API baselines.

## Best Possible Solution

Rework this against current main so doctor and status render cleanup hints from actual detected service metadata, honor user vs system scope, preserve manual guidance for skipped legacy cleanup, and use the existing explicit SecretRef inspect path while strict plugin SDK helpers stay strict.

## Reproduction Assessment

Yes, for the review findings by source inspection: the PR helper returns no hints for no-argument callers, doctor filters legacy services before manual hints, and cleanup rendering ignores `svc.scope`. I did not run a live macOS launchd doctor repro in this read-only review.

## Solution Assessment

No. The cleanup-hint direction is plausible, but this patch is too narrow for status and legacy/system-scope paths, and the SecretRef fix is broader than the current main inspect-mode API requires.
