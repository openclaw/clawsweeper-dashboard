## Summary

Current main still appears to normalize ElevenLabs endpoint overrides as strings and lets malformed values fail later in URL construction, so this remains a valid, bounded provider-owned bug rather than cleanup material.

## What This Changes

Validate malformed ElevenLabs base URL configuration at the provider boundary and return a clear, secret-safe configuration error.

## Best Possible Solution

Validate the URL once in the ElevenLabs shared normalizer, accept only provider-supported HTTP schemes with a fixed secret-safe error, preserve custom path and port behavior, and let realtime deliberately map HTTP(S) to WS(S), with regression coverage for every ElevenLabs surface consuming the helper.
