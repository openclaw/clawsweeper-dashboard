## Summary

Keep open: the PR targets a real Code Mode diagnostic gap, but the current patch would also classify an internal headless wall-clock worker deadline as `aborted` instead of `timeout`, and the external PR only includes focused test output rather than real behavior proof.

## What This Changes

The PR adds an `aborted` Code Mode failure code for worker cancellation and updates the headless abort regression test to expect that code and message.

## Best Possible Solution

Preserve `aborted` only for caller-driven cancellation, keep `timeout` for `CodeModeHeadlessTimeoutError` and worker/runtime deadlines, and add focused coverage for both cases before merge.

## Reproduction Assessment

Yes from source inspection: a headless worker-leg wall-clock timeout uses the same abort signal passed into `runCodeModeWorker`, and this patch resolves that abort path as `aborted`. A focused repro would run headless `while (true) {}` with the wall-clock deadline expiring before the worker's own timeout margin.

## Solution Assessment

No; the patch is a plausible fix for direct caller aborts, but it is too broad because it does not distinguish caller cancellation from the headless wall-clock timeout reason. The best fix is to branch on the abort reason or pass separate timeout/caller-cancel semantics into the worker wrapper.
