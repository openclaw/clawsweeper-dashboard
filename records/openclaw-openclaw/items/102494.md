## Summary

Keep this PR open: the useful abort-vs-timeout goal is still not implemented on current main, but the current patch still turns headless worker-leg wall-clock timeouts into `aborted` and only includes test output as proof.

## What This Changes

The branch adds an `aborted` Code Mode failure code, returns it from `runCodeModeWorker()` signal aborts, updates the headless abort test, and extends the cron trigger failure-code union.

## Best Possible Solution

Preserve `aborted` only for caller-driven cancellation, keep `CodeModeHeadlessTimeoutError` and worker/runtime deadlines as `timeout`, and add focused coverage plus redacted real abort/timeout proof.

## Solution Assessment

No; the patch is plausible for direct caller aborts, but it is too broad because it does not distinguish caller cancellation from the headless wall-clock timeout reason.
