## Summary

Keep open: the PR correctly targets a real current-main gap in one-shot and fallback embedded runs, but it introduces a merge-blocking CLI stdout compatibility issue for existing diagnostics configurations that use stdout log export.

## What This Changes

This PR starts and flushes the diagnostics-otel plugin service around embedded one-shot `openclaw agent --local` and gateway-to-embedded fallback runs, with docs and focused tests.

## Best Possible Solution

Export one-shot traces, metrics, and OTLP logs while preserving normal CLI stdout; stdout JSONL diagnostics should be rerouted, disabled for this process, or explicitly made opt-in for one-shot runs before merge.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes from source: configure diagnostics-otel with `logsExporter: "stdout"` or `"both"`, run `openclaw agent --local` without JSON mode, and the exporter writes JSONL to `process.stdout` while the command also returns its normal stdout reply. I did not run a live collector in this read-only review.

## Solution Assessment

Mostly yes: the scoped non-activating plugin-service load is the right owner boundary and avoids starting Prometheus in short-lived CLI runs. It is not the best mergeable fix until stdout diagnostics cannot corrupt normal CLI output.
