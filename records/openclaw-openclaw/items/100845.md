## Summary

Keep open for an explicit owner decision before merge. The patch is coherent and the supplied live and focused-test evidence supports the reported local-run telemetry gap, but it establishes a new CLI-process plugin-service lifecycle and also includes a separate local-build environment change; the protected member-authored PR should not be auto-closed or auto-merged without confirming that boundary.

## What This Changes

The PR starts and flushes the `diagnostics-otel` plugin service around local and gateway-fallback embedded agent CLI runs, documents that lifecycle, and removes inherited `npm_execpath` from local build child processes.

## Best Possible Solution

Confirm that enabled OTel is intended to have a scoped, OTel-only lifecycle for embedded CLI turns, then land that bounded lifecycle with its failure isolation and focused tests; split the unrelated `npm_execpath` cleanup unless its coupling to this change is documented and accepted.
