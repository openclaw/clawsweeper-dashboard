## Summary

Keep open: current main and v2026.6.11 still select the default, explicit, or session-derived agent before account-route inference, so an outbound-first WhatsApp `message send` can still mirror into the wrong agent session or miss the routed non-default agent transcript.

## What This Changes

The issue asks for outbound `openclaw message send` and similar channel sends through routed WhatsApp accounts to create or resume the correct non-default agent session and persist the first outbound turn.

## Best Possible Solution

Add a maintainer-approved shared outbound agent/session resolver for CLI, Gateway send, and message-tool paths that preserves explicit agent/session precedence and then applies account/peer route bindings under the chosen automatic or opt-in semantics.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should outbound `openclaw message send` infer the routed agent from channel/account/peer bindings automatically when no agent or session is explicit, or require an explicit opt-in flag or command before mirroring into an agent session?

Rationale: Both behaviors are plausible product contracts: automatic inference matches inbound routing and the reported workflow, while an explicit opt-in avoids changing the meaning of existing channel-only outbound sends.

Likely owner: gumadeiras

Owner reason: The decision centers on the outbound session routing/plugin boundary that this history most directly touched.

Owner confidence: medium

Options:

- **Infer routed agent when unambiguous (recommended):** Use account/peer route bindings for outbound sends only after preserving explicit agent and session precedence, and add shared tests across CLI and message-tool/Gateway paths.
- **Require explicit opt-in:** Add a flag or dedicated command for session-aware outbound starts so existing `message send` remains channel-only unless the operator asks to mirror into a session.
- **Keep outbound sends channel-only:** Document the current behavior and require users to start the routed agent session separately before or after sending the opener.

## Reproduction Assessment

Yes, at source level: current main selects the default or explicit/session agent before outbound account routing and mirrors only for that selected agent. I did not run a live WhatsApp send in this read-only review.

## Solution Assessment

Unclear until maintainers choose automatic inference versus explicit opt-in semantics. The narrow maintainable solution is a shared outbound resolver rather than a WhatsApp-only special case.
