## Summary

Keep open. Current main and v2026.6.11 still use Baileys multi-file authentication; the prior replacement PR closed unmerged with correctness concerns, and this MEMBER-authored sensitive-state migration requires maintainer approval of the permanent SQLite, security, and upgrade contract.

## What This Changes

Replace Baileys multi-file WhatsApp authentication state with a production database-backed store and a safe migration path for existing paired sessions.

## Best Possible Solution

Define one plugin-owned transactional SQLite authentication store, migrate and verify every shipped Baileys credential and signal-key category before switching, retain a restricted rollback backup until success, then remove legacy files and all steady-state file fallbacks.
