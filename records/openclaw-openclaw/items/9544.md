## Summary

Keep open. Current main and latest release v2026.6.11 still use Baileys multi-file auth state for the bundled WhatsApp plugin, and this MEMBER-authored, security-sensitive storage/migration request needs maintainer design rather than conservative cleanup.

## What This Changes

The issue requests replacing Baileys multi-file WhatsApp auth state with a production database-backed auth store for credentials and signal keys.

## Best Possible Solution

Keep this open for a maintainer-approved WhatsApp plugin auth-store redesign that replaces Baileys multi-file persistence with canonical database-backed storage, includes a safe migration or doctor path, preserves status/logout/setup behavior, updates docs, and proves fresh install, upgrade, corruption recovery, and key persistence.

## Reproduction Assessment

Yes, at source level: current main still calls Baileys useMultiFileAuthState and keeps signal keys in the Baileys multi-file auth store. No live corruption or IO-growth reproduction was run in this read-only review.

## Solution Assessment

Unclear until maintainers choose the permanent storage and migration contract. Moving away from Baileys multi-file auth is directionally supported by current source, upstream guidance, and OpenClaw's database-first policy, but the exact store design is security-sensitive product work.
