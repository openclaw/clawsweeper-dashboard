## Summary

Keep open. Current main and the latest release still use Baileys `useMultiFileAuthState` for the bundled WhatsApp plugin, and this MEMBER-authored issue is security/session-state-sensitive with a real migration and product-design boundary.

## What This Changes

Replace the bundled WhatsApp plugin's Baileys multi-file JSON auth persistence with a production-grade database-backed auth store and safe migration path.

## Best Possible Solution

Keep this open for a maintainer-owned WhatsApp plugin auth-store redesign that replaces Baileys multi-file persistence, migrates existing auth directories through the plugin/doctor boundary, preserves status/logout/setup behavior, updates docs, and proves fresh install, upgrade, corruption recovery, and key persistence.

## Reproduction Assessment

Yes. Current main and `v2026.6.11` can be source-verified because the WhatsApp socket still calls Baileys `useMultiFileAuthState(authDir)` and keeps signal keys in that store.

## Solution Assessment

Unclear. Moving away from Baileys multi-file auth is supported by current source and upstream guidance, but the custom SQL/SQLite shape should be decided against OpenClaw's plugin-owned migration, doctor, and security requirements.
