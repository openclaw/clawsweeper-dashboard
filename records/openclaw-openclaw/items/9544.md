Keep open. Current main and the latest release still use Baileys `useMultiFileAuthState` for the WhatsApp plugin, the only related consolidated-store PR is closed unmerged, and this MEMBER-authored credential/session-state migration remains product- and security-sensitive maintainer work.

## What This Changes

The issue asks to replace the bundled WhatsApp plugin’s Baileys multi-file JSON auth state with a production database-backed auth store for signal keys and credentials.

## Best Possible Solution

Keep this issue open until the WhatsApp plugin has a maintainer-approved database-backed auth store, safe migration/doctor coverage for existing multi-file sessions, public docs, and fresh-install plus upgrade/corruption/key-persistence tests.

## Reproduction Assessment

Yes. Source inspection of current main and `v2026.6.11` shows the WhatsApp socket still calls `useMultiFileAuthState(authDir)`, so the requested replacement is reproducibly absent without a live WhatsApp account.

## Solution Assessment

Unclear as an exact implementation plan. A database-backed auth store aligns with OpenClaw's SQLite/storage direction and upstream Baileys guidance, but maintainers still need to choose the schema, migration, backup, and failure semantics.
