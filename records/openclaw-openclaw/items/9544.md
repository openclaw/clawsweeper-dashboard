## Summary

Keep open for explicit maintainer handling. This MEMBER-authored, security-sensitive WhatsApp session-storage migration is not eligible for automated cleanup, and the supplied prior review found that the bundled plugin still relied on Baileys multi-file authentication state while the only related replacement PR was closed unmerged.

## What This Changes

Replace Baileys’ multi-file WhatsApp authentication persistence with a production-grade consolidated store that preserves existing WhatsApp sessions safely.

## System Context

The bundled WhatsApp plugin loads Baileys credentials and Signal protocol keys when a WhatsApp account starts, then uses them to connect and deliver channel messages. Its persistence layer affects login continuity, reconnect behavior, logout, recovery, and upgrades of existing linked accounts.

## Architecture Diagram

flowchart LR

  B --> C[Baileys auth state]
  C --> D[Credentials and Signal keys]
  D --> E[Socket connection]
  E --> F[WhatsApp message delivery]
  G[Upgrade or recovery] --> C

## Best Possible Solution

Have the WhatsApp owners choose and document one canonical durable auth-store design, then implement a security-reviewed migration from existing Baileys files with fresh-install, upgrade, corruption-recovery, logout, and reconnect proof.
