## Summary

Keep open. Current main and the latest release still use Baileys `useMultiFileAuthState` for the WhatsApp plugin, the only consolidated-store implementation found is closed unmerged, and this member-authored credential/session-state migration needs maintainer product and security direction before it can be treated as cleanup.

## What This Changes

Request to replace the bundled WhatsApp plugin's Baileys multi-file JSON auth state with a production database-backed and cached auth store for credentials and signal keys.

## Best Possible Solution

Land a maintainer-approved WhatsApp auth-store migration that replaces Baileys multi-file key persistence, safely migrates existing `authDir` data, preserves status/logout/login behavior, updates docs, and tests fresh install, upgrade, corruption recovery, and key persistence.

## Reproduction Assessment

Yes. Source inspection of current main and `v2026.6.11` shows the WhatsApp socket still calls `useMultiFileAuthState(authDir)`, so the requested storage replacement is reproducibly absent without a live WhatsApp account.

## Solution Assessment

Unclear as an implementation plan. A database-backed auth store aligns with OpenClaw storage direction and upstream Baileys guidance, but maintainers still need to choose schema, migration, backup, and failure semantics.
