## Summary

Keep open. Current main and the latest release still use Baileys multi-file authentication, while the only related implementation PR closed unmerged; the requested production auth-store migration remains necessary but needs maintainer approval of its security and upgrade boundary.

## What This Changes

Replace Baileys multi-file authentication with a production database-backed auth store for the bundled WhatsApp plugin.

## Best Possible Solution

Adopt a single WhatsApp-owned SQLite schema in the shared state database, migrate and verify every legacy credential and Signal key through `openclaw doctor --fix`, update all login/status/logout/setup paths to use that canonical store, and delete legacy files only after successful verification without retaining runtime fallback.
