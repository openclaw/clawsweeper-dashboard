## Summary

Keep open. Current main and the latest release still use Baileys `useMultiFileAuthState` for the bundled WhatsApp plugin, and this member-authored storage/security migration needs maintainer direction rather than conservative cleanup.

## What This Changes

The issue requests replacing Baileys multi-file WhatsApp auth persistence with a production database-backed auth store for credentials and signal keys.

## Best Possible Solution

Approve a WhatsApp plugin auth-store redesign that uses OpenClaw's database-first state approach, safely migrates existing Baileys files, preserves status/logout/setup behavior, updates docs, and proves fresh install, upgrade, corruption recovery, and key persistence.

## Reproduction Assessment

Yes, at source level: current main still calls Baileys `useMultiFileAuthState` and keeps signal keys in the Baileys multi-file auth store. No live corruption or IO-growth reproduction was run in this read-only review.

## Solution Assessment

Unclear until maintainers choose the permanent storage and migration contract. Moving away from Baileys multi-file auth is directionally supported by current source, upstream guidance, and repository storage policy, but the exact store design is security-sensitive product work.
