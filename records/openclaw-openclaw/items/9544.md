## Summary

Keep open. Current main and v2026.6.11 still use Baileys useMultiFileAuthState for the WhatsApp plugin, the related consolidated-store PR is closed unmerged, and this MEMBER-authored credential/session-state migration needs maintainer product and security direction.

## What This Changes

The issue requests replacing Baileys multi-file WhatsApp auth state with a production database-backed auth store for credential and signal-key persistence.

## Best Possible Solution

Land a maintainer-approved WhatsApp-plugin auth store, preferably SQLite-backed per OpenClaw storage policy, with safe doctor migration from existing authDir files, credential-permission/backup handling, docs, and fresh-install plus upgrade/corruption tests.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 still import and call useMultiFileAuthState(authDir), so the requested replacement is reproducibly absent without a live WhatsApp account.

## Solution Assessment

Unclear as an implementation plan. A database-backed auth store aligns with upstream Baileys guidance and OpenClaw's database-first direction, but maintainers still need to choose the schema, migration, backup, and failure semantics.
