## What This Changes

The issue requests replacing Baileys multi-file WhatsApp auth persistence with a production SQL-backed auth state and cached signal-key store.

## Best Possible Solution

Keep this open for a maintainer-owned WhatsApp plugin auth-store redesign that replaces Baileys multi-file persistence, migrates existing auth directories through the plugin/doctor boundary, preserves status/logout/setup behavior, updates docs, and proves fresh install, upgrade, corruption recovery, and key persistence.

## Solution Assessment

Unclear. Moving away from Baileys multi-file auth is supported by current source and upstream guidance, but the exact custom SQL/Postgres shape should be decided against OpenClaw's SQLite, plugin-owned migration, doctor, and security requirements.
