## Summary

Keep open. The latest repository review in the discussion confirms that the bundled WhatsApp plugin still uses Baileys multi-file authentication, while the only related implementation PR closed unmerged; MEMBER authorship and the active product/security review signals require explicit maintainer handling.

## What This Changes

Replace Baileys multi-file WhatsApp credential and Signal-key persistence with a production database-backed authentication store and cache.

## Best Possible Solution

Use one plugin-owned SQLite/Kysely schema for account-scoped credentials and Signal keys, migrate and verify legacy files through the plugin doctor flow, and make runtime consume only the canonical database without dual-write or file fallback.

- **Require Re-pairing:** Use the database only for new pairings and require existing users to re-pair, explicitly accepting upgrade disruption instead of migrating keys.
