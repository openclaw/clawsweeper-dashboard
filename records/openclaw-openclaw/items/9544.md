## Summary

Keep open. Current main and v2026.6.11 still route WhatsApp through Baileys `useMultiFileAuthState`, and this MEMBER-authored, security-sensitive auth-store migration is not eligible for conservative cleanup closure.

## What This Changes

The issue requests replacing the bundled WhatsApp plugin's Baileys multi-file auth state with a production database-backed auth store for credentials and signal keys.

## Best Possible Solution

Replace the bundled WhatsApp plugin's Baileys multi-file auth persistence with a plugin-owned database auth store, add a safe doctor-backed migration for existing credentials and signal keys, preserve status/logout/account behavior, update docs, and prove fresh install plus upgrade recovery.

## Reproduction Assessment

Yes, at source level: current main still calls Baileys `useMultiFileAuthState` in `createWaSocket` and still treats the WhatsApp auth directory as Baileys multi-file state. No live corruption or IO-growth reproduction was run in this read-only review.

## Solution Assessment

Yes for the end direction, but not as an autonomous fix: replacing the helper with a database-backed store is the maintainable target, while the exact schema, migration, and security contract need maintainer approval. The closed single-file prior attempt is not sufficient to close this issue.
