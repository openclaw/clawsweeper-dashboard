## Summary

Keep open. Current main and v2026.6.11 still use Baileys multi-file authentication, upstream discourages that helper for production, and no viable replacement PR exists; because this MEMBER-authored issue changes sensitive shipped session state, maintainers must approve the database and migration boundary before implementation.

## What This Changes

Replace Baileys multi-file WhatsApp authentication state with a production database-backed credential and Signal-key store.

## Best Possible Solution

Adopt a dedicated plugin-owned SQLite adapter for the complete Baileys authentication contract, with transactional migration, verification before cutover, secure backup and permissions, explicit external-`authDir` handling, and no steady-state legacy fallback.

Rationale: Upstream and repository policy support moving away from multi-file auth, but changing shipped credentials and cryptographic state requires explicit ownership and upgrade-safety decisions that automation cannot choose.

Owner confidence: high

Options:

- **Dedicated Plugin SQLite (recommended):** Create a dedicated WhatsApp auth database with typed serialization, atomic batches, explicit backup, and verified one-way migration.
- **Extend Shared Plugin State:** Use the shared plugin-state store only after proving its size, binary serialization, transaction, backup, and lifecycle contracts meet Baileys requirements.
- **Retain Hardened Files:** Keep multi-file auth and continue targeted atomicity and performance hardening if maintainers do not want to own the database migration now.

Yes at the source level: current main directly uses the upstream multi-file helper that upstream discourages for production. This review did not run a live corruption, CPU, or I/O benchmark, so the reported operational symptoms remain unmeasured.

## Solution Assessment

No, not exactly as proposed: SQL is the right direction, but a generic key/value/JID table is incomplete without typed serialization, atomic batches, database lifecycle ownership, secure migration, and upgrade proof.
