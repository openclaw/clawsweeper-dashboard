## Summary

The requested production auth-store replacement remains necessary: current main and v2026.6.11 retain Baileys multi-file persistence, while the only implementation attempt closed unmerged with correctness gaps. Because this MEMBER-authored item changes sensitive persisted session state, maintainers must approve the permanent SQLite schema, migration, rollback, and legacy-file cleanup contract before implementation.

## What This Changes

Replace the bundled WhatsApp plugin’s Baileys multi-file authentication state with a production database-backed credential and Signal-key store.

## Best Possible Solution

Use one WhatsApp-owned Kysely schema in the shared state database unless measured schema, volume, or lifecycle requirements justify a dedicated SQLite database; migrate all credentials and Signal keys transactionally, verify a live reopen before removing backed-up legacy files, update status/logout/doctor/docs to the canonical store, and eliminate steady-state file fallback.
