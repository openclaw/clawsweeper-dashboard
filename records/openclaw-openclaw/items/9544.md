## Summary

Keep open. Current main and the latest release still use Baileys `useMultiFileAuthState` for WhatsApp, the prior consolidated-store PR was closed unmerged, and this MEMBER-authored credential/session-state migration needs maintainer product and security direction rather than cleanup closure.

## What This Changes

The issue asks to replace WhatsApp/Baileys multi-file JSON auth state with a production database-backed auth store for credentials and signal keys.

## Best Possible Solution

Keep this issue open until the WhatsApp plugin has a maintainer-approved production auth store, safe migration from existing Baileys files, doctor/recovery behavior, docs updates, and focused tests for fresh install, migration, corruption recovery, and key persistence.

## Reproduction Assessment

Yes for source verification of the implementation gap: current main and `v2026.6.11` still call `useMultiFileAuthState(authDir)` in WhatsApp socket setup. I did not run a live WhatsApp account to reproduce corruption or I/O load.

## Solution Assessment

No implemented solution is present yet. A database-backed or otherwise production-grade auth store is a plausible end state, but storage choice, migration, doctor, and security contracts need maintainer approval before coding.
