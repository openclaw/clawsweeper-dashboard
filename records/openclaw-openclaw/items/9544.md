## Summary

Keep open. Current main and v2026.6.11 still use Baileys multi-file auth for WhatsApp signal keys, the only consolidated-store PR is closed unmerged, and this MEMBER-authored credential/session-state migration needs maintainer product and security direction rather than cleanup closure.

## What This Changes

The issue requests replacing WhatsApp's Baileys multi-file auth state with a production database-backed auth store and cached signal-key layer.

## Best Possible Solution

Keep this open until the WhatsApp plugin has a maintainer-approved database-backed auth store, safe doctor migration from Baileys files, no steady-state runtime fallback to legacy files, updated docs, and focused fresh-install/migration/corruption/key-persistence tests.

## Reproduction Assessment

Yes, source-level. Current main and v2026.6.11 still import and call `useMultiFileAuthState(authDir)` and keep Baileys multi-file key persistence, so the requested replacement is reproducibly absent without a live WhatsApp account.

## Solution Assessment

No, current main is not the best end state for this issue. The existing hardening only protects `creds.json`; the maintainable fix needs a plugin-owned database-backed auth store plus explicit migration and security review.
