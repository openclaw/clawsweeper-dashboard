## Summary

Keep open: current main and the latest release still use Baileys `useMultiFileAuthState` for WhatsApp auth, and the only consolidated-store implementation PR was closed unmerged after review concerns. This is MEMBER-authored, security-sensitive credential/session storage work that needs maintainer product and security direction rather than cleanup closure.

## What This Changes

Replace the bundled WhatsApp plugin's Baileys multi-file auth state with a database-backed auth store for credentials and signal keys.

## Best Possible Solution

Keep this open until the WhatsApp plugin has a maintainer-approved database-backed auth store, safe doctor/migration coverage for existing multi-file sessions, public docs, and fresh-install plus upgrade/corruption/key-persistence tests.

## Reproduction Assessment

Yes. Source inspection of current main and `v2026.6.11` shows the WhatsApp socket still calls `useMultiFileAuthState(authDir)`, so the requested replacement is reproducibly absent without a live WhatsApp account.

## Solution Assessment

Unclear as an implementation plan. A database-backed auth store aligns with OpenClaw's SQLite/storage direction and upstream Baileys guidance, but maintainers still need to choose the schema, migration, backup, and failure semantics.
