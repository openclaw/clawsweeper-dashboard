## Summary

Keep open. Current main and v2026.6.11 still use Baileys `useMultiFileAuthState` for the WhatsApp plugin, the direct consolidated-store PR is closed unmerged, and this MEMBER-authored credential/session-state migration needs maintainer product and security direction rather than cleanup closure.

## What This Changes

Request replacing WhatsApp's Baileys `useMultiFileAuthState` with a production database-backed or consolidated auth store for credentials and signal keys.

## Best Possible Solution

Implement a WhatsApp plugin-owned canonical SQLite-backed auth store with safe migration from Baileys multi-file auth, doctor/backup coverage, docs, and fresh-install plus upgrade/corruption proof.

## Reproduction Assessment

Yes for source-level reproduction. Current main and v2026.6.11 still call `useMultiFileAuthState(authDir)`, so the requested replacement is reproducibly absent without a live WhatsApp account.

## Solution Assessment

Unclear as an exact implementation plan. A database-backed auth store matches upstream Baileys guidance and OpenClaw's SQLite/storage direction, but maintainers still need to choose the schema, migration owner, backup behavior, and failure semantics.
