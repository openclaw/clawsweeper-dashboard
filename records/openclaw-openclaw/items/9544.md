## Summary

Keep open. Current main and the latest inspected release still use Baileys `useMultiFileAuthState` for the bundled WhatsApp plugin, the related replacement PR was closed unmerged, and the item is member-authored plus product/security-sensitive enough to require maintainer direction rather than cleanup closure.

## What This Changes

The issue requests replacing the bundled WhatsApp Baileys multi-file auth state with a production database-backed auth store for credentials and signal keys.

## Best Possible Solution

Design and land a WhatsApp plugin-owned SQLite-compatible auth-state store that migrates existing Baileys files safely, preserves status/logout/login behavior, updates public docs, and includes focused migration, fresh-install, corruption-recovery, and key-persistence proof.

## Reproduction Assessment

## Solution Assessment

Unclear. Replacing the auth store is likely the durable direction, but the exact schema, migration owner, SQLite/shared-state boundary, and compatibility behavior need maintainer design before implementation.
