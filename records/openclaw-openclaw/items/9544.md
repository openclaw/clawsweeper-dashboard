## Summary

Keep open. Current main and v2026.6.11 still use Baileys multi-file authentication, while this MEMBER-authored sensitive-state migration requires maintainer approval of its permanent database, security, and upgrade boundary.

## What This Changes

Replace Baileys multi-file WhatsApp authentication state with a production database-backed store and safe migration path.

## Best Possible Solution

Implement one plugin-owned Kysely/SQLite source of truth, migrate every shipped `authDir` through a verified doctor transaction, preserve rollback until validation succeeds, then remove steady-state legacy file reads and prove fresh pairing, upgrade, restart, logout, and corruption recovery.

Rationale: The implementation gap and upstream production warning are clear, but the permanent owner of sensitive credentials, transaction model, backup retention, and upgrade guarantees require explicit maintainer intent.

Owner confidence: high

Options:

- **Shared Plugin SQLite (recommended):** Use plugin-owned tables or KV in the shared state database, migrate each configured auth directory through doctor in one verified transaction, and remove legacy runtime reads afterward.
- **Dedicated WhatsApp SQLite:** Use a dedicated database only if measured Signal-key volume, locking, backup, or account-lifecycle requirements cannot safely fit the shared state database.
- **Retain Hardened Files:** Continue file-backed persistence with narrower durability and security hardening while explicitly accepting Baileys' production limitation.

## Reproduction Assessment

Yes at source level. Current main and v2026.6.11 directly use Baileys multi-file authentication, and upstream explicitly recommends database storage for production use.

## Solution Assessment

No, the generic SQL key/value proposal is not yet the best complete solution. The implementation should use OpenClaw's SQLite/Kysely ownership model and explicitly cover all accounts, `authDir` compatibility, atomic import, verification, permissions, rollback, cleanup, and upgrade behavior.
