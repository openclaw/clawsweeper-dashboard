## Summary

Keep open. Current main and the latest release still use Baileys `useMultiFileAuthState` for WhatsApp, while the only consolidated-store PR was closed unmerged after review concerns; because this is a MEMBER-authored credential/session/security storage change, it needs maintainer product and security direction rather than cleanup closure.

## What This Changes

The issue asks OpenClaw to replace WhatsApp’s Baileys multi-file auth state with a production-grade consolidated or database-backed auth store.

## Best Possible Solution

Keep this open until the WhatsApp plugin has a maintainer-approved auth-store replacement, safe doctor/migration coverage for existing multi-file sessions, public docs, and fresh-install plus upgrade/corruption/key-persistence tests.

## Reproduction Assessment

Yes. Current-main source inspection shows `createWaSocket` still calls `useMultiFileAuthState(authDir)` and stores credentials in the existing auth directory, so the requested replacement is reproducibly absent without a live WhatsApp account.

## Solution Assessment

Unclear as a final implementation. A database-backed store fits OpenClaw's SQLite/storage direction and Baileys guidance, but maintainers still need to choose schema, migration, backup, and failure semantics.
