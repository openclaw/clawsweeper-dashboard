## Summary

Keep open. The recent review record found the bundled WhatsApp runtime still uses Baileys multi-file auth state, while the only related replacement PR was closed unmerged; this MEMBER-authored, security-sensitive persistence migration requires an explicit maintainer design decision rather than automated cleanup.

## What This Changes

The issue requests replacing Baileys’ multi-file authentication state with a production-grade database-backed store for WhatsApp credentials and Signal keys.

## Best Possible Solution

Design a WhatsApp-plugin-owned SQLite auth store with one doctor-owned migration from Baileys files, explicit session-recovery semantics, and focused fresh-install and upgrade proof before replacing the current runtime path.
