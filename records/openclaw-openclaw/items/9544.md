## Summary

Keep open. Current main and v2026.6.11 still use Baileys `useMultiFileAuthState` for WhatsApp auth, the related consolidated-store PR closed unmerged, and this MEMBER-authored credential/session-state migration needs maintainer product and security direction.

## What This Changes

The issue requests replacing the WhatsApp plugin's Baileys multi-file JSON auth-state storage with a production database-backed auth store and signal-key cache.

## Best Possible Solution

Keep this issue open until the WhatsApp plugin has a maintainer-approved database-backed auth store, safe migration or doctor coverage, updated docs, and fresh-install plus upgrade/corruption tests.

## Reproduction Assessment

Yes. Source inspection of current main and v2026.6.11 shows the WhatsApp socket still calls `useMultiFileAuthState(authDir)`, so the requested replacement is reproducibly absent without a live WhatsApp account.

## Solution Assessment

Unclear as a final implementation plan. A database-backed auth store aligns with OpenClaw storage direction and upstream Baileys guidance, but maintainers still need to choose the schema, migration, backup, and failure semantics.
