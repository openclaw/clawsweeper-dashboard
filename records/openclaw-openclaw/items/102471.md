## Label Justifications

- `impact:auth-provider`: The issue is specifically about OpenAI OAuth access-token expiry, WHAM credential probing, provider cooldowns, and re-auth guidance.
- `impact:ux-friction`: Users can see OpenAI as down for half a day or receive unnecessary re-login guidance even though the refresh token should recover the profile.

## Summary

Keep open: current main still lets the WHAM failure probe use a locally expired OpenAI OAuth access token and turn a 401 into a 12-hour cooldown, and the protected `maintainer` label makes this a human-routed auth issue rather than cleanup-close material.

## What This Changes

The issue asks OpenClaw to skip the WHAM cooldown probe when the stored OpenAI OAuth access token is already locally expired, while keeping the long 401 cooldown for locally valid tokens that WHAM rejects.

## Best Possible Solution

Add a narrow expiry-aware guard before WHAM probing: skip the probe for locally expired or refresh-margin-expiring OAuth access tokens and use normal transient cooldown, while preserving the long cooldown for WHAM 401 responses from locally valid tokens.
