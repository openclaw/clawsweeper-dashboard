## Summary

Keep open: current main and the latest release still allow a transient OpenAI OAuth failure to probe WHAM with an already locally expired access token and convert the resulting 401 into a 12-hour cooldown. The protected maintainer label and secops-owned auth files mean this should stay human-routed rather than become a cleanup close or unattended repair job.

## What This Changes

The issue asks OpenClaw to skip WHAM usage probes for locally expired refreshable OpenAI OAuth access tokens so routine expiry does not create a false 12-hour `wham_token_expired` cooldown.

## Best Possible Solution

Skip the WHAM probe when the stored OpenAI OAuth access token is already locally expired or invalid, preserve the 12-hour WHAM 401 cooldown for locally valid tokens, and add a regression test for the expired-access-token case.
