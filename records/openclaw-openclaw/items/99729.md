## Label Justifications

- `P1`: The issue describes active production CLI-backed session invalidations and queued-turn history loss in real group-agent workflows.
- `impact:session-state`: The reported failure mode invalidates or drops resumed CLI session bindings and can run queued turns without prior conversation history.

## Summary

Keep open: current main and v2026.6.11 still use the single hard-invalidation path for prompt-content hash drift, the linked mention-state PR only covers one narrower axis, and the protected `maintainer` label requires explicit maintainer handling.

## What This Changes

The issue requests a structural CLI session reuse contract that soft-resumes through prompt-content drift while hard-invalidating only mechanical auth, cwd, or MCP changes.

## Best Possible Solution

Maintain this as a maintainer-owned design item: decide the soft-resume policy, then implement one closed reuse result shape across `cli-session`, CLI preparation, binding persistence, and focused regression tests while sequencing narrower PRs like https://github.com/openclaw/openclaw/pull/99722.

Unclear until maintainers choose the product contract. The proposed two-class split is a plausible structural fix, but it deliberately changes when stale system prompt content is tolerated within a CLI session.
