## Summary

Keep open: the PR targets a real OpenAI embedding-batch memory-safety gap, but the patch replaces an unbounded whole-file read with a 16 MiB whole-file cap that can reject valid large batch outputs.

## What This Changes

The PR changes OpenAI embedding batch file-content downloads to use the shared bounded provider text reader and adds a loopback oversized-output regression test.

## Best Possible Solution

Use streaming JSONL parsing or an OpenAI batch-output-specific bounded reader that preserves valid large total outputs while rejecting oversized records or hostile streams.

## Reproduction Assessment

Yes. Current main uses raw `res.text()` for OpenAI `/files/{id}/content`, and the PR test demonstrates oversized streams are rejected after the patch; I did not run a live OpenAI-compatible provider path in this read-only review.

## Solution Assessment

No. The fix location is plausible, but the whole-output 16 MiB cap is not the best shape for embedding batch files; streaming JSONL or an output-specific bound preserves valid large jobs.
