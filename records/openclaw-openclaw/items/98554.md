## Summary

Keep open: the force-push fixes the earlier whole-file-cap regression and now has adequate loopback terminal proof, but the new streaming output reader still has no total record/custom-id budget, so a hostile endpoint can avoid the per-line cap with endless small JSONL records.

## What This Changes

The PR changes OpenAI embedding batch file-content reads to stream successful JSONL output records with a per-line cap and adds large-output plus oversized-line regression coverage.

## Best Possible Solution

Keep the streaming JSONL approach, but enforce the known batch output contract by cancelling or throwing once all requested custom IDs are accounted for or the record count exceeds the group size.

## Reproduction Assessment

Yes, at source/proof level: current main uses raw `res.text()` for `/files/{id}/content`, and the PR proof exercises the production batch path with a loopback provider. I did not run a fresh live command in this read-only review.

## Solution Assessment

No. Streaming JSONL with a per-line cap is the right direction, but the best fix also bounds the number of output records against the known batch group/custom IDs and cancels early on overflow.
