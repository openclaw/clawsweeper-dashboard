## What This Changes

The PR starts the Gmail `gog` watcher in its own Unix process group and routes shutdown through OpenClaw’s shared process-tree terminator so credential-helper descendants are stopped too.

## System Context

The Gmail hook registers and starts a long-running `gog gmail watch serve` subprocess when Gmail hooks are configured. Gateway shutdown or watcher replacement must stop that process and any helper descendants without signalling the parent OpenClaw process.

## Architecture Diagram

flowchart LR
  A[Gmail hook configuration] --> B[Start gog watcher]
  B --> C[Dedicated Unix process group]
  C --> D[Gateway or watcher shutdown]
  D --> E[Shared process-tree terminator]
  E --> F[Gog process exits]
  E --> G[Credential helpers exit]

## Best Possible Solution

Keep the Gmail watcher on the shared process-tree shutdown path, then land a rebased head after the updated merge result preserves the focused tests and the demonstrated descendant-cleanup behavior.
