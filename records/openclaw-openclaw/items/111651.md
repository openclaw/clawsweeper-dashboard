## Summary

The patch appears to close a real authorization gap while preserving fresh keyed creation and idempotent re-sends, but its intentional fail-closed upgrade behavior for existing write-scoped clients needs the protected gateway/security maintainer decision before merge.

## What This Changes

The branch keeps `sessions.create` method authorization at write scope but blocks a write-scoped caller from changing an existing keyed session’s resolved model or thinking selection unless it also has `operator.admin`.

## Best Possible Solution

Adopt the narrow persisted-state-aware admin gate if gateway owners confirm that reconfiguring an adopted keyed session is an admin-only operation, while retaining write access for fresh keyed creation and idempotent re-sends.
