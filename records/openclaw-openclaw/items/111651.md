## Summary

Keep this PR open: it closes the intended privilege gap, but the parameter-only scope rule also rejects documented write-scoped creation of fresh explicitly keyed sessions with an initial model or thinking level. The `maintainer` label and the compatibility/security-boundary tradeoff need an explicit decision before landing.

## What This Changes

The branch changes `sessions.create` authorization so requests with an explicit `key` plus `model` or `thinkingLevel` require `operator.admin`.

## Best Possible Solution

Authorize model or thinking changes at the resolved existing-session adoption boundary, while retaining `operator.write` for fresh explicitly keyed session creation; add focused coverage for both paths.
