## Summary

Keep this PR open. Current `main` still authorizes `sessions.create` at write scope except for `cwd`/`execNode`, so it does not yet prevent a write-scoped caller from reconfiguring an adopted keyed session; the branch remains relevant. The patch appears to preserve fresh-key creation and idempotent existing selections while moving the state-dependent authorization decision into the session service, but it needs redacted real Gateway proof and explicit owner approval because it deliberately changes an established operator-scope compatibility boundary.

## What This Changes

The branch adds a runtime admin-scope gate for keyed `sessions.create` requests that would change an already-existing session’s resolved model or thinking level, with focused authorization and session-service tests.

## Best Possible Solution

Land a state-aware authorization check only after a Gateway owner confirms that reconfiguring an adopted keyed session is an admin-only operation and the PR includes redacted live proof for the write-denied, write-idempotent, fresh-key, and admin-success paths.
