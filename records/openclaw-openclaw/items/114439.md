## What This Changes

The PR makes session navigation select the owning agent before switching the Gateway session, and propagates agent ownership for global observer state through the Gateway, Control UI, Android, and Apple clients.

## System Context

Session selection starts in Control UI or native navigation, then changes the selected agent and Gateway session. The Gateway publishes session observer updates back to clients, where global-session data must remain associated with the selected agent rather than a shared `global` key alone.

## Architecture Diagram

flowchart LR
  Navigation[Client session navigation] --> Selection[Select owning agent]
  Selection --> Gateway[Switch Gateway session]
  Gateway --> Observer[Publish observer digest]
  Observer --> Scope[Apply agent ownership]
  Scope --> Clients[Web and native clients]
  Clients --> UI[Aligned picker, chat, and status]

## Best Possible Solution

Land one canonical, ordered agent-before-session transition only after current-head platform checks pass and a redacted live multi-agent Gateway/client run proves selection, reconnect, and global observer ownership remain aligned through an actual reconnect.
