## Summary

Keep this PR open for QQBot-owner review. The socket-level limit is a valid way to reduce the `ws` 100 MiB inbound-message default, and the contributor supplied credible live loopback proof, but the unconfigured 1 MiB fail-closed ceiling can disconnect a real QQBot gateway and suppress a valid event without evidence that 1 MiB is a supported maximum. Likely related people: hugenshen (medium confidence), based on the merged QQBot gateway-factory work in the same files.

## What This Changes

This PR gives QQBot’s gateway WebSocket client a fixed 1 MiB inbound-message limit and extends direct and proxy-path constructor assertions to require that option.

## System Context

The QQBot plugin creates a long-lived WebSocket client for gateway events, then hands received events to its connection lifecycle and channel processing. This PR inserts a maximum inbound-message decision at socket construction, before QQBot consumes those events.
