## Summary

Keep this PR open for a maintainer security-boundary decision. The focused patch and supplied loopback proof support the 16 MiB behavior, but merging intentionally changes QQBot handling of oversized gateway events from the `ws` 100 MiB default to a disconnecting rejection path; that compatibility and delivery tradeoff needs an owner to accept explicitly.

## What This Changes

The PR caps inbound QQBot gateway WebSocket messages at 16 MiB and extends constructor-option assertions for direct and proxied gateway connections.

## System Context

The QQBot plugin opens a gateway WebSocket to receive events, then hands those events to its gateway connection for parsing and dispatch. This change constrains the transport frame size before JSON parsing, affecting whether unusually large gateway events are delivered or the connection closes.
