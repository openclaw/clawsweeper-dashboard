## Summary

Keep this PR open for maintainer review: constructor-level bounding is technically sound and well proven, but the permanent 1 MiB fail-closed threshold lacks an official QQBot maximum-size contract and can reject previously accepted gateway events.

Likely related people: `vincentkoc` for recent QQBot gateway lifecycle review, `xialonglee` for the shared WebSocket factory, and `steipete` as that factory change’s merger.

## What This Changes

The branch exports a 1 MiB QQBot gateway payload constant and options interface, passes the cap to the shared WebSocket factory, and updates four direct/proxy constructor tests.

## Best Possible Solution

Keep the single factory-level `maxPayload` enforcement and use a QQBot-owner-approved bounded value with documented legitimate-event headroom.
