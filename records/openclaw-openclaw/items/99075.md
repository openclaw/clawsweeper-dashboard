## Summary

This PR is still necessary: current main’s QQBot gateway factory has the merged 30-second handshake timeout but not a payload bound. The patch is mechanically correct and has credible loopback transport proof, but lowering the active `ws` receive ceiling from its 100 MiB default to 16 MiB deliberately disconnects QQBot sessions on larger legitimate gateway events; a QQBot owner should explicitly accept that compatibility and delivery trade-off before merge.

## What This Changes

The PR sets QQBot gateway WebSocket inbound messages to a fixed 16 MiB limit and adds constructor-option assertions for direct and proxied connections.

## System Context

QQBot’s gateway client creates the long-lived WebSocket that receives QQ platform events. The WebSocket library enforces its receive-size limit before QQBot parses an event and passes it into the channel connection lifecycle.
