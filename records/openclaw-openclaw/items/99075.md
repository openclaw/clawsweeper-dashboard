## Summary

The patch remains technically sound and well-proven, but the permanent 1 MiB limit is a compatibility and delivery boundary not established by current QQBot docs or code contracts. A QQBot owner should explicitly accept or raise that threshold before merge.

## What This Changes

The PR exports a 1 MiB QQBot gateway payload cap, applies it to direct and proxied WebSocket construction, and updates four constructor-path tests.

## Best Possible Solution

Keep the shared-factory `maxPayload` design, but merge only with a QQBot-owner-approved threshold backed by protocol or representative production-size evidence and the existing below/above-cap loopback proof.
