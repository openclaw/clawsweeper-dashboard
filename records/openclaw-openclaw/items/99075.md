## Summary

Keep open for a QQBot owner decision: the patch is mechanically sound and well-proven, but neither the official gateway documentation nor live QQBot evidence establishes that 1 MiB is a safe permanent receive limit for every legitimate event.

## What This Changes

The PR adds a 1 MiB inbound message limit to the QQBot gateway WebSocket factory and verifies that option across direct and proxied construction paths.

## Best Possible Solution

Keep the limit in the channel-owned WebSocket factory, but use a compatibility-oriented cap such as 16 MiB unless official limits or representative live QQBot captures justify 1 MiB; retain boundary tests and the oversized-frame loopback proof.
