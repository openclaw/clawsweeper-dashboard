## Summary

Keep open for QQBot owner review: the transport hardening is focused, well-proven, and has no concrete implementation defect, but the official gateway contract does not define a maximum event size, so maintainers must confirm that rejecting all inbound events above 1 MiB is the intended compatibility and delivery policy.

## What This Changes

The PR adds a 1 MiB inbound payload cap to the QQBot gateway WebSocket factory and updates constructor-option tests for direct and proxy paths.

## Best Possible Solution

Keep a fixed, non-configurable cap in the QQBot-owned WebSocket factory, but have the QQBot owner explicitly approve 1 MiB or select a documented larger bound, then retain direct/proxy constructor coverage and loopback proof for accepted and rejected frames.
