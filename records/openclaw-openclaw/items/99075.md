## Summary

The transport hardening is useful and well-proven, but neither the official QQ gateway documentation nor repository precedent establishes 1 MiB as a safe production ceiling. A QQBot owner should choose the channel-specific threshold before the dirty branch is reconciled with current main.

## What This Changes

The PR adds a fixed 1 MiB inbound message limit to QQBot gateway WebSocket construction and updates direct and proxied constructor-option tests.

## Best Possible Solution

Keep a fixed plugin-local bound, but use a QQBot-owner-approved ceiling with compatibility margin—prefer the established 16 MiB gateway bound unless production captures or an official contract prove 1 MiB safe—then rebase so `maxPayload` and `handshakeTimeout` coexist with focused constructor and loopback coverage.
