## Summary

The change is technically sound and still needed on current main, but the fixed 1 MiB ceiling is an owner-level transport policy choice because no QQ gateway maximum is established and exceeding it closes the connection and drops that event.

## What This Changes

The PR configures QQBot gateway WebSocket clients with a 1 MiB inbound message limit and updates direct and proxied constructor-option tests.

## Best Possible Solution

Keep the native `ws.maxPayload` bound in the QQBot-owned factory, but land it only after a QQBot owner explicitly accepts and documents the 1 MiB ceiling—or adjusts it to a better-supported value—while preserving the current direct and proxy-path coverage.
