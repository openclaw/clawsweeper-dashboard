## Summary

Keep open for a QQBot owner decision: the transport mechanism and loopback proof are sound, but the chosen ceiling is an intentional compatibility and delivery boundary that is not established by the upstream QQ contract.

## What This Changes

The PR adds a fixed 1 MiB inbound WebSocket message limit to QQBot gateway connections and updates direct and proxied constructor-option tests.

## Best Possible Solution

Ship one documented plugin-local ceiling approved by a QQBot owner; absent stronger production evidence for 1 MiB, use 16 MiB as the compatibility-safer hardening bound while preserving the existing 30-second handshake timeout and direct/proxy coverage.
