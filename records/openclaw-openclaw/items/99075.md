## Summary

This PR remains useful and focused: it fixes an unbounded QQBot gateway WebSocket receive window, with no line-level correctness finding. It should stay open for maintainer acceptance of the 1 MiB fail-closed cap because that value can reject QQBot frames that previous releases accepted.

## What This Changes

The PR adds a 1 MiB `maxPayload` option to the QQBot gateway WebSocket client and updates its constructor tests to assert the bounded option with and without proxy agents.

## Best Possible Solution

Land the plugin-local `maxPayload` guard after maintainers accept the QQBot-specific cap, or adjust the constant and tests to the maintainer-approved headroom before merge.
