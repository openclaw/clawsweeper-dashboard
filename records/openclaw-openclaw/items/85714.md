## Summary

Keep open: current main still treats a substantive `message_tool_only` final without a `message(action=send)` call as private, logs a warning, and produces no source-channel outbound. The open closing PR https://github.com/openclaw/openclaw/pull/88992 directly owns the recovery proposal, and the July 3 live repro comment shows the same failure class is still current.

## What This Changes

The issue requests fallback delivery or an explicit non-silent outcome when a Codex-backed agent completes with final assistant text but never calls the configured message delivery tool.

## Best Possible Solution

Resolve the open recovery PR as the canonical implementation decision, preserving the default private `message_tool_only` contract unless maintainers explicitly approve the opt-in recovery behavior.

## Reproduction Assessment

Yes. Current main has a high-confidence source reproduction: the qa-lab scenario forces a direct `message_tool_only` final without a message-tool call, then asserts no outbound and a private-final warning.

## Solution Assessment

Unclear for the final product choice. Warning-only behavior is not enough for the reported user-visible silence, while the linked recovery PR is a plausible fix that still needs maintainer approval for the privacy/config tradeoff.
