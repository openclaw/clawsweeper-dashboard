## Summary

Current main still has the reported lifecycle gap: failed registration rolls back several plugin-global side effects and restores registry state without cleaning the plugin's live session-scheduler records. The issue is recent, specific, source-reproducible, and suitable for one focused core fix.

## What This Changes

Ensure failed plugin registration immediately cleans up plugin-owned external scheduler jobs instead of only restoring registry metadata.

## Best Possible Solution

Call the existing owner-scoped session-scheduler cleanup from the registration transaction's global-side-effect rollback boundary, then add regression coverage proving one callback invocation, live-record removal, and registry restoration after a registration exception.
