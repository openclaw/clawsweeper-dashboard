## Summary

Keep open: current main still treats trajectory rows as point-in-time events and diagnostics-otel still exports at least `openclaw.context.assembled` with a zero duration, so the reported duration gap is not implemented on main or the latest release. The remaining work needs a maintainer decision because changing trajectory events into measured spans changes the exported diagnostic contract and only partially overlaps the open OTel latency PR.

## What This Changes

The issue asks for trajectory and telemetry records such as `context.compiled`, `prompt.submitted`, `tool.call`, `tool.result`, and session lifecycle events to carry measured non-zero durations instead of only point timestamps.

## Best Possible Solution

Define a bounded trajectory timing contract, add real measured durations only for operations with lifecycle boundaries, document any rows that intentionally remain point events, and coordinate the OTel context/reply timing subset with the existing latency-decomposition work.
