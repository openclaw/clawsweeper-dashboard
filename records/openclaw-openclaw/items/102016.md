## Summary

Keep open: current main and the latest release still export trajectory rows as single-timestamp events, so the reported missing duration data remains unresolved and needs maintainer direction on event-versus-span semantics.

## What This Changes

The issue requests duration instrumentation for trajectory-exported events such as context assembly, prompt submission, tool calls/results, and session startup.

## Best Possible Solution

Define a versioned trajectory timing contract, add measured duration data only for lifecycle operations, and document which rows intentionally remain point-in-time events.

Question: Should trajectory JSONL gain measured duration/start-end fields, and which reported event types should become lifecycle spans versus remain point events?

Rationale: Changing trajectory rows from timestamped events into duration-bearing spans affects an exported diagnostic schema, support tooling, docs, and transcript-derived tool event semantics.

Likely owner: Peter Steinberger

Owner confidence: medium

Options:

- **Add a trajectory timing contract (recommended):** Keep this issue open and require a focused design/fix that adds measured duration fields for real lifecycle operations with docs and regression coverage.
- **Keep trajectory event-only:** Leave trajectory JSONL as a point-event timeline and update docs to direct latency analysis to OTel diagnostics instead.
- **Split by event family:** Track runtime lifecycle timing separately from transcript-derived tool call/result reconstruction so each family can use the right schema.

## Reproduction Assessment

Yes. Source inspection shows current main and `v2026.6.11` trajectory rows have one `ts` field and no duration/start/end fields, including the reported context, prompt, session, and transcript tool event paths.

## Solution Assessment

Unclear until maintainers choose the schema direction. Adding measured durations is the right end state for real lifecycle operations, but forcing synthetic durations onto point events would be the wrong model.
