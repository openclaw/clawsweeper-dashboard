## Summary

Keep open: current main and v2026.6.11 still expose trajectory rows as single-timestamp events, and current OTel context assembly is still emitted as a zero-duration span. The report remains valid, but a fix needs a maintainer decision on trajectory event-versus-span semantics before changing exported diagnostic schema.

## What This Changes

The issue requests duration/start-end instrumentation for trajectory and telemetry event types that currently appear as zero-duration point spans/events.

## Best Possible Solution

Define an additive timing contract for trajectory and OTel: measured durations for real lifecycle operations, explicit event-only rows where appropriate, and focused docs/tests/proof for the exported schema.

Question: Should trajectory JSONL rows gain a duration/start-end span contract, and which reported event types should become measured lifecycle spans versus remain point-in-time events?

Rationale: The current exported schema is event-based, so fixing this by adding durations changes a diagnostic data contract and requires maintainer intent before implementation.

Likely owner: scoootscooob

Owner confidence: medium

Options:

- **Add additive timing fields (recommended):** Define `durationMs` or start/end fields for real lifecycle operations and update trajectory export, OTel mapping, docs, and tests around that contract.
- **Keep trajectory event-only:** Leave trajectory JSONL as point events, route measured latency work through OTel diagnostics, and clarify the trajectory docs so zero-duration point rows are expected.
- **Split by event family:** Track runtime lifecycle spans separately from transcript-derived tool call/result reconstruction so each event family gets the right schema.

## Reproduction Assessment

Yes, source-reproducible: current main writes trajectory runtime/transcript rows with one timestamp and no duration/start/end fields, and diagnostics-otel still emits `openclaw.context.assembled` with duration 0. I did not run a live trace in this read-only review.

## Solution Assessment

Unclear until maintainers choose the telemetry contract. Adding measured durations for lifecycle operations is the maintainable direction, but forcing synthetic durations onto true point events would be the wrong model.
