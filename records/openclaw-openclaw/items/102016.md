## Summary

Keep open: current main and the latest release still model trajectory rows as timestamped point events, so the reported lack of duration data remains real. The fix should wait for a maintainer decision on trajectory event-versus-span semantics because the requested behavior changes the exported diagnostic schema and overlaps only partly with the existing OTel latency work.

## What This Changes

The issue requests duration instrumentation for trajectory span/event types such as context compilation, prompt submission, tool calls, tool results, and session startup.

## Best Possible Solution

Define a bounded trajectory timing contract, then add measured duration data only for operations with a real lifecycle while documenting any event-only rows that intentionally remain point-in-time.

## Solution Assessment
