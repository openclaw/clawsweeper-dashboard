## Summary

Keep open: current main and the latest release still model trajectory rows as timestamped events, and current OTel still exports at least `openclaw.context.assembled` as a zero-duration span. A fix needs maintainer direction because the issue crosses trajectory event schema, OTel span semantics, and which event types should stay point-in-time.

## What This Changes

The issue asks OpenClaw to stop exporting zero-duration trajectory spans by recording real start and end timing for non-model telemetry events.

## Best Possible Solution

Define a bounded timing contract for trajectory and OTel lifecycle operations, add real duration or start/end fields only where an operation has a measurable lifecycle, and document any intentionally point-in-time events.

- **Split runtime and transcript events:** Track runtime lifecycle spans separately from transcript-derived tool events so each surface can use the right schema without overloading this issue.

## Reproduction Assessment

Yes, source-reproducible: current main has trajectory rows with one timestamp and no duration fields, and OTel records `openclaw.context.assembled` with duration 0. I did not run a live trajectory export in this read-only review.

## Solution Assessment

Unclear until maintainers choose the telemetry contract. Measured durations are the right end state for lifecycle operations, but forcing all event rows to have synthetic nonzero durations would be a weaker model.
