## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.92

Full review comments:

- **[P1] Reuse the existing Notes block boundary for salvage:** `extensions/memory-wiki/src/source-sync-state.ts:265`
  - body: The new extractor starts at the first `openclaw:human:start` anywhere in the page. Imported source content can contain those marker comments, and existing `preserveHumanNotesBlock` intentionally searches after the source Content fence with tests covering that case. With this patch, pruning such a page salvages generated source payload together with the real note, so the recovery file is corrupted instead of containing only the human Notes block.
  - confidence: 0.93
- **[P1] Stop deletion when required salvage writes fail:** `extensions/memory-wiki/src/source-sync-state.ts:300`
  - body: The `catch` covers `readFile`, extraction, `mkdir`, and `writeFile`. If a page has human Notes but `.salvage` cannot be created or written, the error is swallowed and the page is removed anyway, so the fix can still destroy the only copy. Missing/unreadable pages can proceed, but once Notes are found a failed salvage needs to abort or leave the page/state intact.
  - confidence: 0.91
