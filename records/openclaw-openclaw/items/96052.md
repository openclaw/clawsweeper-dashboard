## Summary

Keep this PR open for maintainer review: it is the active, well-proven fix candidate for the filename/date-token memory_search bug, but it changes persisted derived SQLite FTS payload semantics and ranking inputs, so cleanup-close is not appropriate.

## What This Changes

The PR prefixes memory FTS text with the memory path, strips that prefix from returned snippets/scoring, adds FTS text-format metadata/self-heal/backfill behavior, and adds filename-token regression tests.

## Best Possible Solution

Land this PR as the canonical repair if maintainers accept path-prefixed FTS payloads; otherwise replace it with a separate path-index strategy before merge.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 store paths as UNINDEXED FTS metadata and write only chunk body text into the indexed FTS column, matching the linked filename/date-token miss.

## Solution Assessment

Yes, if maintainers accept the stored-format and ranking tradeoff. The PR stays inside memory-core, uses the existing FTS table, keeps snippets body-only, and covers backfill/search self-heal; the main alternative is a heavier separate path-index design.
