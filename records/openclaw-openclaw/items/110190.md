Keep this issue open: current main deliberately moves the remaining structured runtime-context carriers to the absolute request tail after the active user turn, so the reported ordering is still present. The source documents a prompt-cache invariant, but the report raises a credible competing model-quality and delivery-cost concern that needs a targeted provider evaluation before changing the default.

## What This Changes

The issue requests changing the structured runtime-context carrier placement so it no longer follows the active user message, along with neutral wording for its header.

## Best Possible Solution

Compare tail and pre-user placement in a focused multi-turn provider test that records cache reuse, completion quality, reasoning output, and channel delivery; if tail placement is harmful, change the single canonical default and add regression coverage rather than introducing a new user setting.
