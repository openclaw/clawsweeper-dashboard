## What This Changes

This PR preserves an absent controller on restored historical managed task flows, rather than assigning the synthetic `core/legacy-restored` identifier during doctor import or SQLite restore.

## System Context

Task flows are persisted in OpenClaw's shared SQLite state database, restored into the in-memory task-flow registry, then exposed through task-flow CLI commands and lifecycle operations. The changed code covers two legacy-state entry paths and the registry update path that writes restored flows back to SQLite.

## Best Possible Solution

Accept SQL NULL and an absent `controllerId` as the sole representation of genuinely unknown historical provenance, retain controller validation for newly created flows and explicit controller changes, and land only after maintainer acceptance plus visible after-fix runtime proof against current main.
