## Summary

This PR should not merge as written: current ACP code deliberately separates ordinary run-state cleanup from cancellation, and the proposed behavior would emit an abort signal during successful prompt completion without demonstrating any real asynchronous work that currently survives cleanup. Exact-head CI is green, but the contributor evidence is test-only and does not establish the claimed resource leak.

## What This Changes

The PR makes `clearActiveRun` abort its stored controller before clearing run state and adds a regression test asserting the signal is aborted.

## Best Possible Solution

Keep `clearActiveRun` as non-cancelling state cleanup and terminate any demonstrated surviving asynchronous work from the cancellation or teardown owner that actually started it.
