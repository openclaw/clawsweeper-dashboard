## Summary

Keep open: current main still implements the skill readiness/debugging piece as `openclaw skills check`, but the two remaining operator surfaces are still missing from source: status does not carry manifest-registry diagnostics, and the non-tool skill prompt rewrite path has no operator-visible signal.

## What This Changes

The issue requests three developer/operator diagnostics improvements: a skill validation CLI command, plugin registry diagnostics in status output, and a warning when skill commands rewrite prompts.

## Best Possible Solution

Preserve `openclaw skills check`, then either split or implement the remaining two quick wins with sanitized manifest-registry diagnostics in status text/JSON/all and a maintainer-approved signal for non-tool skill prompt rewrites.

## Reproduction Assessment

Yes, at source level. Current main exposes `openclaw skills check`, while status has no manifest-registry diagnostics field and the skill prompt-expansion branch rewrites successful `/skill:<name>` commands without an operator-visible signal.

## Solution Assessment

Partly. The skills check portion is already solved, status diagnostics have a clear status scan/result/rendering home, and the prompt-rewrite warning should wait for a maintainer decision on the least noisy operator-visible surface.
