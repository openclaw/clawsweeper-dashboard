## Summary

## What This Changes

The issue requests three developer/operator quick wins: a skill validation CLI, plugin registry diagnostics in status output, and a warning when skill command handling rewrites a prompt.

## Best Possible Solution

Preserve `openclaw skills check`, then add manifest-registry diagnostics to status text/JSON/all surfaces and an operator-visible warning or diagnostic for non-tool skill prompt rewrites, with focused tests and docs updates.

## Reproduction Assessment

Yes, at source level. Current main shows `openclaw skills check` exists, while status only carries plugin compatibility fields and the non-tool skill invocation branch rewrites the prompt without an operator-visible warning.

## Solution Assessment

Partly. `openclaw skills check` is already the right current solution for skill readiness, and status should reuse existing manifest registry diagnostics, but the prompt-rewrite warning surface still needs maintainer product judgment.
