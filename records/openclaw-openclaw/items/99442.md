## Summary

Keep open: the marker-body change and added regression tests are useful, but this PR is not merge-ready because it leaves structured `turn/completed` interrupted status outside abort classification and provides only Vitest output as proof.

## What This Changes

The PR changes Codex app-server abort-marker detection to match non-empty `<turn_aborted>` structural markers instead of exact guidance prose and adds focused unit coverage for canonical, reworded, developer-role, malformed, empty, and prompt-echo cases.

## Best Possible Solution

Classify `turn/completed` status `interrupted` as aborted, keep marker-shape matching only as the replay fallback, and require regression coverage plus redacted real app-server proof before merge.

## Reproduction Assessment

Yes, at source level: current main strict-matches copied Codex guidance prose while upstream Codex 0.142.4 keeps that prose crate-private and emits structured interrupted turn status. I did not run a live app-server interruption in this read-only review.

## Solution Assessment

No. Marker-shape matching is a good replay fallback, but by itself it is not the best complete fix for the linked bug because structured `turn/completed` interrupted status still produces `aborted: false` in current coverage.
