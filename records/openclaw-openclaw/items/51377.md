## Summary

Keep open: current main still rejects Excel/generic binary `input_file` MIME types in the OpenResponses path and only extracts accepted files into prompt context, while the reporter comments correctly identify the missing workspace/persistence receipt as the remaining product and security decision.

## What This Changes

Support Excel spreadsheets and generic binary uploads as first-class Gateway/OpenResponses `input_file` attachments with explicit persistence, metadata, limits, and documentation.

## Best Possible Solution

Define a maintainer-approved Gateway/OpenResponses binary `input_file` receipt contract that stages allowed payloads as sanitized artifacts with metadata and explicit unsupported errors, while keeping read-tool parsing and provider-native forwarding in their separate linked tracks.
