## Summary

Keep open: current main and v2026.6.11 still only default OpenResponses `input_file` to text/CSV/JSON/PDF extraction and do not provide durable Excel or generic binary workspace receipts; merged attachment work only partially covers `chat.send`.

## What This Changes

Request support for Excel and generic binary uploads through Gateway/OpenResponses with MIME limits, explicit errors, workspace persistence metadata, and documentation.

## Best Possible Solution

Define a maintainer-approved Gateway binary upload contract that stages allowed `input_file` payloads as named workspace artifacts with metadata and explicit unsupported errors, while leaving richer parsing and provider-native forwarding to focused follow-ups.

## Reproduction Assessment

Yes. Source inspection shows `.xlsx` is outside the default `input_file` MIME allowlist, and the allowed non-PDF path decodes content into prompt text instead of persisting a binary workspace artifact.

## Solution Assessment

No, a simple allowlist addition is not the best solution. The maintainable fix needs a Gateway media receipt/staging contract with explicit security policy before Excel and generic binary inputs are enabled.
