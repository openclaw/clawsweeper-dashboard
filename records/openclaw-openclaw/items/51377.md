## Summary

Keep open: current main still excludes Excel from the default `/v1/responses` `input_file` path and decodes allowed files into prompt context rather than staging generic binary workspace artifacts with stable receipts.

## What This Changes

Request support for Excel and generic binary payloads as first-class gateway/API `input_file` uploads with allowlists, size limits, persistence receipts, and documentation.

## Best Possible Solution

Define a maintainer-approved Gateway/OpenResponses binary `input_file` receipt contract that stages allowed binary payloads as sanitized workspace artifacts with metadata and explicit unsupported errors, while keeping read-tool parsing and provider-native forwarding in their narrower linked tracks.
