## Summary

Keep open: current main partially covers `chat.send` non-image offload and `.xlsx` MIME recovery, but `/v1/responses` `input_file` still defaults to text/JSON/PDF extraction and does not provide durable Excel or generic binary workspace receipts.

## What This Changes

The issue requests first-class Excel and generic binary upload support for Gateway/OpenResponses `input_file`, including MIME allowlists, size limits, workspace artifact receipts, and docs.

## Best Possible Solution

Define a maintainer-approved Gateway binary `input_file` contract that stages allowed binary payloads as sanitized workspace artifacts with metadata and explicit unsupported errors, while keeping read-tool parsing and provider-native forwarding in their narrower linked tracks.
