## Summary

Keep open: current main still supports `/v1/responses` `input_file` as text/JSON/PDF extraction, while Excel and generic binary workspace receipts remain a real public Gateway feature and security-design gap.

## What This Changes

Request support for Excel and generic binary uploads through Gateway/OpenResponses `input_file`, including allowlists, limits, persistence metadata, tool access, and documentation.

## Best Possible Solution

Define a maintainer-approved Gateway binary `input_file` contract that stages allowed binary payloads as sanitized workspace artifacts with metadata and explicit unsupported errors, while keeping read-tool parsing and provider-native forwarding in their narrower linked tracks.

## Reproduction Assessment

Yes. Source inspection shows Excel and generic binary MIME types are outside the default `input_file` allowlist, and allowed non-PDF files are decoded into prompt text rather than persisted as binary workspace artifacts.

## Solution Assessment

No as a simple allowlist change. The maintainable fix is a Gateway-level binary upload and workspace receipt contract with security policy, not raw text decoding for more MIME types.
