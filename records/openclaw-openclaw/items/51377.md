## Summary

Keep open: current main partially covers non-image `chat.send` attachments and file-only `/v1/responses` turns, but OpenResponses `input_file` still defaults to text/CSV/JSON/PDF extraction and does not provide durable Excel or generic binary workspace receipts.

## What This Changes

The issue requests first-class Excel and generic binary upload support for Gateway/OpenResponses `input_file`, including persistence, metadata, limits, and documented tool/skill behavior.

## Best Possible Solution

Define a maintainer-approved Gateway/OpenResponses contract that stages allowed binary `input_file` payloads as workspace artifacts with metadata and explicit unsupported errors, leaving spreadsheet preview and provider-native forwarding to separate plugin/provider work.

## Reproduction Assessment

Yes. Source inspection shows `.xlsx`/`.xls` and generic binary MIME types are outside the default `input_file` allowlist, and allowed non-PDF files are decoded into prompt text rather than persisted as binary workspace artifacts.

## Solution Assessment

No. The requested direction is valid, but an allowlist-only change is not the best fix; the maintainable solution is a Gateway-level binary artifact/receipt contract with explicit security policy.
