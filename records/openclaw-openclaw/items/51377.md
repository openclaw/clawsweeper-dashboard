## Label Justifications

- `P2`: This is a normal-priority cross-surface feature gap that blocks spreadsheet/binary workflows but needs design rather than emergency repair.
- `impact:data-loss`: Unsupported uploaded files can fail to become durable, agent-visible workspace artifacts, so operational attachment data may be dropped or not applied to the workflow.
- `impact:security`: Allowing arbitrary binary and Excel uploads affects untrusted file storage, URL fetching, extraction, transcript redaction, and tool/provider exposure boundaries.
- `maturity:stable`: The affected Gateway runtime HTTP/RPC surface is scored M4 Stable in `qa/maturity-scores.yaml`.

## Summary

Keep open: current main partially solves non-image `chat.send` uploads, including `.xlsx` MIME recovery, but `/v1/responses` `input_file` still defaults to text/JSON/PDF extraction and does not provide durable Excel or generic binary workspace receipts.

## What This Changes

Request support for Excel and generic binary uploads in Gateway/OpenResponses `input_file`, including durable workspace persistence, MIME/size policy, security rules, and docs.

## Best Possible Solution

Define a durable binary upload contract for Gateway/OpenResponses first: explicit MIME and size allowlists, workspace receipt metadata, retention/redaction rules, and skill/tool access, while keeping provider-native forwarding on the broader related tracker and parsing in the shared document-extractor path.
