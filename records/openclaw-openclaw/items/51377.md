## Summary

Keep open: current main still has partial coverage only; `chat.send` can offload non-image attachments, but OpenResponses `input_file` still defaults to text/JSON/PDF extraction and does not provide durable Excel or generic binary workspace receipts.

## What This Changes

Request support for Excel spreadsheets and generic binary uploads as first-class Gateway/OpenResponses `input_file` attachments with MIME policy, size limits, workspace access, and docs.

## Best Possible Solution

Define a maintainer-approved Gateway media contract that stages allowed binary `input_file` payloads as named workspace artifacts with metadata and explicit unsupported errors, while leaving richer parsing and provider-native forwarding to separate plugin/provider follow-ups.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: `.xlsx` and generic binary `input_file` MIME types are outside the default allowlist, and allowed non-PDF files are decoded into prompt text rather than persisted as binary workspace artifacts.

## Solution Assessment

No. An allowlist-only change is not the best fix because OOXML and generic binaries need a receipt/staging contract with security policy, not raw text decoding.
