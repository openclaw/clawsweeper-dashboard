## Summary

Keep open: current main only partially addresses non-image chat attachments; `/v1/responses` `input_file` still lacks the requested Excel/generic binary workspace receipt contract.

## What This Changes

Request support for Excel `.xlsx`/`.xls` and generic binary uploads through Gateway/OpenResponses `input_file`, with MIME policy, size limits, workspace persistence metadata, clear errors, and docs.

## Best Possible Solution

Define a maintainer-approved Gateway binary `input_file` contract that stages allowed binary payloads as sanitized workspace or media artifacts with metadata/receipts and explicit unsupported errors, while keeping read-tool parsing and provider-native forwarding in their narrower linked tracks.
