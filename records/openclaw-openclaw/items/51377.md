## Summary

Keep open: current main and v2026.6.11 still exclude Excel/generic binaries from the default OpenResponses input_file path and do not provide a persisted binary receipt for tools.

## What This Changes

The issue requests first-class Excel and generic binary upload handling through the Gateway input_file path, including MIME policy, persistence metadata, limits, errors, and docs.

## Best Possible Solution

Define a maintainer-approved Gateway/OpenResponses binary input_file receipt contract that stages allowed binary payloads as sanitized artifacts with metadata and explicit unsupported errors, while keeping read-tool parsing and provider-native forwarding in their narrower linked tracks.
