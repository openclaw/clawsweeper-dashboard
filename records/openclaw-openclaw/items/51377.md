## Summary

Keep open: current main partially solves non-image `chat.send` attachments, including `.xlsx` MIME recovery, but `/v1/responses` `input_file` still defaults to text/JSON/PDF extraction and does not provide durable Excel or generic binary workspace receipts.

## What This Changes

The issue requests first-class Excel and generic binary upload support for gateway/input_file, including durable workspace persistence, metadata receipts, explicit allowlists, limits, and documentation.

## Best Possible Solution

Define a maintainer-approved Gateway binary `input_file` contract that stages allowed binary payloads as sanitized workspace artifacts with metadata and explicit unsupported errors, while keeping read-tool parsing and provider-native forwarding in their narrower linked tracks.

## Reproduction Assessment

Yes. Source inspection shows `.xlsx` is outside the default `input_file` MIME allowlist, and allowed non-PDF files are decoded into prompt text rather than persisted as binary workspace artifacts.

## Solution Assessment

No as a simple allowlist change. The maintainable fix is a Gateway-level binary upload and workspace receipt contract with security policy, not raw text decoding for more MIME types.
