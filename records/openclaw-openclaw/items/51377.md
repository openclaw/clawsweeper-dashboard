## Summary

Keep open: current main partially handles non-image `chat.send` uploads, including OOXML MIME recovery, but OpenResponses `input_file` still defaults to text/JSON/PDF extraction and does not provide durable Excel or generic binary workspace receipts.

## What This Changes

Request support for Excel and generic binary uploads through Gateway/OpenResponses `input_file`, with allowlists, limits, workspace persistence metadata, explicit unsupported errors, and docs.

## Best Possible Solution

Define a maintainer-approved Gateway binary `input_file` contract that stages allowed binary payloads as sanitized workspace artifacts with metadata and explicit unsupported errors, while leaving read-tool parsing and provider-native forwarding to their narrower linked tracks.

## Reproduction Assessment

Yes, at source level. Current main keeps `.xlsx` outside the default `input_file` MIME allowlist, and accepted files are decoded into prompt context rather than persisted as binary workspace artifacts.

## Solution Assessment

No as a simple allowlist change. The maintainable solution is a Gateway-level binary upload and workspace receipt contract with security policy, not raw text decoding for more MIME types.
