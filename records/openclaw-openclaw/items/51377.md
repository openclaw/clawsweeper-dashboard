## Summary

Keep open: current main and v2026.6.11 partly cover `chat.send` non-image/XLSX offload and file-only Responses turns, but the requested first-class Excel/generic binary `input_file` path still lacks a durable workspace receipt and remains a security/product contract decision.

## What This Changes

Request support for Excel and generic binary uploads through Gateway/OpenResponses `input_file`, with allowlists, size limits, workspace persistence/receipts, and documentation.

## Best Possible Solution

Define one Gateway attachment contract that stores non-text binary uploads as managed media or workspace artifacts with stable metadata receipts, explicit limits, redaction rules, and docs; keep provider-native forwarding and document parsing as separate follow-ups.

## Reproduction Assessment

Yes, source-level reproduction is high confidence: current `input_file` defaults exclude Excel/generic binary, and unsupported MIME values are rejected before any durable workspace receipt is produced. I did not run a live request because this cleanup review is read-only.

## Solution Assessment

No current implementation is only partial. The best fix is not a simple MIME allowlist expansion; it needs a maintainer-approved binary artifact contract with limits, receipts, redaction, and tests.
