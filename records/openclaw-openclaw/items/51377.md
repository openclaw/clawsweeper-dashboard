## Summary

Keep open: current main and the latest release still limit OpenResponses `input_file` to text/JSON/PDF extraction and do not provide durable Excel or generic binary workspace receipts, even though `chat.send` now partially covers non-image attachment offload.

## What This Changes

Request support for Excel and generic binary `input_file` uploads by allowlisting MIME types, persisting files with metadata or receipts, exposing them to tools and skills, and documenting security limits.

## Best Possible Solution

Define a Gateway/OpenResponses binary `input_file` contract that stages allowed files as sanitized workspace artifacts with metadata and clear unsupported errors, while leaving read-tool parsing and provider-native forwarding to the narrower linked tracks.

## Reproduction Assessment

Yes. Source inspection shows `.xlsx` is outside the default `input_file` MIME allowlist, and allowed non-PDF files are decoded into prompt text rather than persisted as binary workspace artifacts.

## Solution Assessment

No as a simple allowlist change. The maintainable fix is a Gateway-level binary upload and workspace receipt contract with explicit security policy, not raw text decoding for more MIME types.
