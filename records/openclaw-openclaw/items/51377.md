## Summary

Keep open: current main partially addresses non-image `chat.send` uploads, including `.xlsx` MIME recovery, but `/v1/responses` `input_file` still defaults to text/JSON/PDF extraction and does not provide durable Excel or generic binary workspace receipts.

## What This Changes

Request support for Excel spreadsheets and generic binary uploads as first-class Gateway/OpenResponses `input_file` attachments with strict limits, persistence, metadata, and documentation.

## Best Possible Solution

Keep this as the Gateway/OpenResponses binary-upload contract item: preserve the existing `chat.send` offload path, then design `input_file` Excel/binary persistence with explicit MIME/size policy, receipts, workspace access, redaction rules, docs, and upgrade-safe tests.

## Reproduction Assessment

Yes. Source inspection shows `chat.send` now offloads non-image files, but `/v1/responses` `input_file` still defaults to text/JSON/PDF MIME extraction and rejects Excel/generic binary before creating a workspace receipt.

## Solution Assessment

Unclear. The requested capability is valid, but the best implementation needs maintainer design for persistence versus extraction versus provider-native forwarding, plus explicit security and configuration policy.
