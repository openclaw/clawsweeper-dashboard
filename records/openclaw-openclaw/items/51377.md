## Summary

Keep open: current main still does not provide the requested Gateway/OpenResponses binary `input_file` receipt contract for Excel or arbitrary allowlisted binaries; merged work only partially overlaps through `chat.send` media offload and file-only `/v1/responses` extraction.

## What This Changes

Request to support Excel and generic binary uploads through Gateway/OpenResponses `input_file` with explicit allowlists, durable workspace receipts, security limits, and documentation.

## Best Possible Solution

Define a maintainer-approved Gateway binary `input_file` receipt contract that stages allowed binary payloads as sanitized workspace artifacts with metadata and explicit unsupported errors, while keeping provider-native forwarding and read-tool parsing in their narrower related tracks.
