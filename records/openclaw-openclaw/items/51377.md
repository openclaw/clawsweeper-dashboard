## Summary

Keep open: current main and v2026.6.11 still only partially address non-image attachments. `chat.send` can stage non-image files, and file-only OpenResponses turns now run, but OpenResponses `input_file` still excludes Excel/generic binary defaults and converts allowed non-PDF files into ephemeral prompt text rather than durable workspace artifacts.

## What This Changes

Support Excel spreadsheets and generic binary uploads through Gateway/OpenResponses `input_file` with durable workspace access, clear limits, security rules, and documentation.

## Best Possible Solution

Define a maintainer-approved Gateway `input_file` artifact contract: allowed binary payloads should be staged as named workspace artifacts with sanitized metadata/receipts and explicit unsupported errors, while richer parsing and provider-native forwarding stay as separate follow-ups.

## Reproduction Assessment

Yes. Source inspection shows `.xlsx` and generic binary `input_file` payloads are outside the default allowlist, and allowed non-PDF files are decoded into ephemeral prompt context rather than persisted as workspace artifacts.

## Solution Assessment

No. Adding Excel MIME strings alone is not the best solution because the central missing behavior is a safe binary artifact and receipt contract, not just text/PDF extraction widening.
