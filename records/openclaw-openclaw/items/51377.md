## Summary

Keep open: current main has partial non-image `chat.send` staging, but `/v1/responses` `input_file` still defaults to text/JSON/PDF extraction and does not provide Excel or generic binary workspace receipts.

## What This Changes

Request to support Excel and generic binary `input_file` uploads with MIME limits, durable workspace metadata, clear unsupported errors, and documentation.

## Best Possible Solution

Define a maintainer-approved Gateway binary `input_file` contract that stages allowed binary payloads as sanitized workspace artifacts with metadata and explicit unsupported errors, while leaving read-tool parsing and provider-native forwarding in their narrower linked tracks.

## Reproduction Assessment

Yes. Source inspection shows `.xlsx` and generic binary MIME types are outside the default `input_file` allowlist, while allowed non-PDF files are decoded into prompt text instead of persisted as binary workspace artifacts.

## Solution Assessment

No as a simple allowlist patch. The maintainable fix is a Gateway-level binary upload and workspace receipt contract with security policy, not raw text decoding for more MIME types.
