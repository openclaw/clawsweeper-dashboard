## Summary

Keep open: current main has partial attachment improvements, but OpenResponses `input_file` still defaults to text/JSON/PDF extraction and does not provide durable Excel or generic binary workspace receipts.

## What This Changes

The issue requests first-class Excel and generic binary upload handling in Gateway/OpenResponses `input_file` paths, with durable workspace receipts, MIME limits, security rules, and documentation.

## Best Possible Solution

Define a maintainer-approved Gateway file artifact contract for allowed binary `input_file` payloads, then stage them as tool-readable workspace/media artifacts with metadata and explicit unsupported errors.

## Reproduction Assessment

Yes. Source inspection shows `.xlsx` and generic binary `input_file` payloads are outside the default file allowlist, while accepted non-PDF files are decoded into prompt text rather than materialized as workspace artifacts.

## Solution Assessment

No. An allowlist-only change is not the best fix; the maintainable solution needs a Gateway-level binary artifact contract with security policy, metadata, and tool-access behavior.
