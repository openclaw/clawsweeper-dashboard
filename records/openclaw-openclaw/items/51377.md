## Summary

Keep open: current main has partial attachment fixes for `chat.send` and file-only `/v1/responses`, but `input_file` still defaults to text/JSON/PDF extraction and does not provide durable Excel or generic binary workspace receipts.

## What This Changes

Request support for Excel and generic binary uploads through the Gateway/OpenResponses `input_file` path with MIME/size policy, workspace access, and documentation.

## Best Possible Solution

Define one explicit Gateway file contract that either persists allowed Excel/generic binaries as workspace-readable receipts or rejects them with clear errors, with allowlists, size limits, redaction behavior, docs, and separate tracking for extraction/provider-native forwarding.

## Reproduction Assessment

Yes from source inspection: `input_file` defaults still exclude Excel and generic binary MIME types, then reject unsupported MIME before any workspace receipt is produced. I did not run a live request because this review is read-only, but the current-main path is clear.

## Solution Assessment

No final solution is selected yet: simply adding `.xlsx` to the allowlist would not solve generic binary persistence, metadata receipts, or redaction/security policy. The maintainable path is a narrow Gateway file contract plus docs and focused tests, with extraction/provider-native work kept as adjacent follow-ups.
