## Summary

Keep open: current main still treats `/v1/responses` `input_file` as a text/PDF extraction path, while the requested Excel and generic-binary workspace receipt contract remains a product and security design decision.

## What This Changes

The issue requests first-class Excel and generic binary uploads for Gateway/OpenResponses `input_file`, including MIME policy, size limits, durable workspace materialization, metadata, and docs.

## Best Possible Solution

Define a maintainer-approved Gateway binary `input_file` receipt contract that stages allowlisted binary payloads as sanitized workspace artifacts with metadata and explicit unsupported errors, while leaving read-tool parsing and provider-native forwarding to their narrower related tracks.
