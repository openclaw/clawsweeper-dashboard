## Summary

Keep open: current main partially handles non-image `chat.send` staging and file-only OpenResponses turns, but `input_file` still defaults to text/JSON/PDF extraction and does not provide durable Excel or generic-binary workspace receipts.

## What This Changes

Request support for Excel and generic binary attachments as first-class Gateway/OpenResponses `input_file` uploads with safe allowlists, size limits, durable workspace receipts, and docs.

## Best Possible Solution

Keep this as the canonical Gateway/OpenResponses binary-upload contract, reuse the existing `chat.send` media-store/staging path where appropriate, and leave provider-native forwarding and document parsing to the narrower related items or plugin surfaces.

## Reproduction Assessment

Yes, by source inspection: the default OpenResponses `input_file` MIME list excludes `.xlsx`, `.xls`, and generic binary MIME types, and the extractor rejects MIME values outside that list. I did not run a live request because this review is read-only.

## Solution Assessment

Unclear until maintainers choose the public contract: adding Excel MIME values alone is not the best fix because unsupported binary formats would still lack a durable receipt/path model. The better shape is a security-reviewed workspace receipt/staging contract, with tabular preview or provider-native forwarding handled separately.
