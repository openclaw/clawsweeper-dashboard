## Summary

Keep open: current main and v2026.6.11 still exclude Excel/generic binaries from the default OpenResponses `input_file` path and do not provide a persisted binary receipt for tools, while related issues cover adjacent but different document/file behavior.

## What This Changes

Request support for Excel `.xlsx`/`.xls` and allowlisted generic binary `input_file` uploads in Gateway/OpenResponses, with workspace persistence, metadata receipts, security limits, and docs.

## Best Possible Solution

Define a maintainer-approved Gateway/OpenResponses binary `input_file` receipt contract that stages allowed binary payloads as sanitized artifacts with metadata and explicit unsupported errors, while keeping read-tool parsing and provider-native forwarding in their narrower linked tracks.
