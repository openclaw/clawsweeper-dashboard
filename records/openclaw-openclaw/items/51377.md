## Summary

Keep open: current main and the latest release still default OpenResponses `input_file` to text/JSON/PDF extraction, while merged `chat.send` and file-only fixes are partial and do not provide durable Excel or generic binary workspace receipts.

## What This Changes

Request support for Excel spreadsheets and generic binary `input_file` uploads through Gateway with MIME policy, workspace persistence/metadata, explicit unsupported errors, and docs.

## Best Possible Solution

Define a maintainer-approved Gateway binary attachment contract that stages allowed `input_file` bytes as workspace artifacts with sanitized metadata and explicit unsupported errors, while leaving richer parsing and provider-native forwarding to follow-up plugin/provider work.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: `.xlsx` and generic binary MIME types are outside the default `input_file` allowlist, and allowed non-PDF files are decoded into prompt text rather than persisted as binary workspace artifacts.

## Solution Assessment

No, an allowlist-only change would not be the best fix. The maintainable solution is a Gateway-level binary artifact contract with security policy, workspace metadata, and clear unsupported behavior.
