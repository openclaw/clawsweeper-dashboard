## What This Changes

The PR adds an optional bounded `clientContext` field to gateway and SDK agent-run requests, stores it by `runId`, and forwards it as private data to trusted diagnostic listeners on session-state and message-queued events.

## Best Possible Solution

Represent attribution as a bounded, explicitly caller-asserted run correlation envelope and attach it directly to canonical trusted run/model-call diagnostic data with the authoritative OpenClaw `runId`; then prove concurrent same-session exporter joins, cleanup, public exclusion, SDK/protocol compatibility, and regenerated Swift output after rebasing.

Options:

- **Adopt a run-native asserted envelope (recommended):** Allow bounded caller metadata, explicitly label it caller-asserted, and carry it with the authoritative run ID on canonical trusted run/model-call events.

- **Reject caller attribution in core:** Keep trusted diagnostics derived only from OpenClaw-owned state and require external orchestrators to correlate through an out-of-repository integration layer.
