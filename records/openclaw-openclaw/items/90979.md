## Summary

Keep this PR open for maintainer review: current main still falls back to raw MCP-config comparison when a stored strict resume hash has no current counterpart, and the proposed shared-helper guard is a sound narrow fix; accepting its intentional reset of affected persisted CLI sessions remains a maintainer compatibility choice.

## What This Changes

The branch makes CLI session reuse invalidate a binding with `mcpResumeHash` when the current run cannot provide that hash, and adds a focused regression test.

## Best Possible Solution

Rebase onto current main, retain the shared-helper guard and regression coverage, then land only if maintainers accept strict MCP-topology proof as the rule for reusing existing persisted CLI sessions.
