- `maturity:stable`: The affected Discord feature is scored M4 Stable, including conversation routing and delivery behavior.

## Summary

Current main still loses the Discord preview ID before a failed cleanup DELETE, preventing a later retry and leaving stale preview content beside the final reply; no open or merged repair PR currently owns this narrow regression.

## What This Changes

Retain a Discord partial-stream preview message ID after transient cleanup deletion failure so a later cleanup call can retry it.

## Best Possible Solution

Keep `takeMessageIdAfterStop` for callers that intentionally consume ownership, but make `clearFinalizableDraftMessage` stop and read the ID, delete it, and clear ownership only after successful deletion, with retry coverage for the shared lifecycle and affected channel adapters.
