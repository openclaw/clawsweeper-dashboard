## Summary

Keep open: this is a focused cron failure-routing bug fix, but it is not merge-ready because the new mode inference still misses provider-prefixed chat targets and the PR currently has only test-output proof.

## What This Changes

The PR changes cron failure-destination resolution so a job-level failure destination with an explicit channel but no mode resolves to announce despite a global webhook default, and adds resolver regression tests.

## Best Possible Solution

Broaden the resolver rule so any no-mode job failure destination that is announce-shaped, including provider-prefixed targets, resolves as announce while bare URL-only overrides continue to inherit webhook mode.

## Reproduction Assessment

Yes. Source inspection shows current main can resolve a job-level chat failure target over a global webhook default into webhook mode, after which the dispatcher rejects the non-HTTP target and skips the alert.

## Solution Assessment

No. The resolver is the right layer, but the current condition only handles an explicit channel field and misses provider-prefixed announce targets that the same delivery resolver and validator already support.
