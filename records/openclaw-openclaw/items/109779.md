## Summary

Current main does not expose provider presentation names or ordering, and the adjacent model-picker issue does not cover this distinct behavior. Keep this feature request open for a product decision about whether presentation metadata belongs in persistent provider config or a UI/catalog layer.

Likely related people: BunsDev for recent Control UI work and vincentkoc for adjacent model catalog/routing work; both are medium-confidence routing candidates.

## What This Changes

Add optional provider display labels and explicit provider ordering for the Control UI model picker while preserving stable provider IDs.

## Best Possible Solution

Define one canonical provider-presentation metadata contract, preserve stable provider IDs, specify deterministic fallback labels and ordering, and consume that metadata consistently across applicable model-picker surfaces.
