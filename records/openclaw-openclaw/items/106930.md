## Summary

Keep this PR open for maintainer review and merge: the linked report establishes a real premature-compaction bug, the implementation follows the intended live-provider-versus-static-fallback boundary, and no actionable correctness or security defect was found.

## What This Changes

The PR changes context-window cache loading so provider-discovered limits take precedence over bundled static metadata while retaining conservative static fallback values for undiscovered models.

## Best Possible Solution

Use verified provider discovery as authoritative for present account-specific limits, apply bundled metadata only to missing cache keys, and preserve explicit operator configuration as the final override.

Yes at source level: discovered and bundled rows currently share minimum-taking cache semantics, allowing a lower bundled row to cap a verified provider value; the linked issue supplies a matching live released-build reproduction.

## Solution Assessment

Yes. Separating verified discovery from static fallback is narrower and safer than provider-specific exceptions or a new configuration surface, while retaining conservative minimum behavior within each source.
