## Summary

Keep this PR open for maintainer review. The consent-gated, one-retry repair flow is a focused response to a real invalid-config startup gap, but it changes startup behavior that can rewrite configuration; the prior JSON-stdout and `--allow-unconfigured` concerns must be verified against the current force-pushed head before merge.

## What This Changes

The branch adds a typed invalid-config recovery flow that offers `openclaw doctor --fix` in interactive CLI and Gateway startup paths, then retries once after consent while headless commands print the repair command only.

## Best Possible Solution

Keep one shared recovery helper, but ensure suppressed-stdout commands remain non-interactive or use stderr-only prompting, and ensure `--allow-unconfigured` bypasses the pre-action recovery offer without writing configuration.
