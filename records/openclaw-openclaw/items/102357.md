Full review comments:

- **[P1] Clear stale streamed text before closing rewrite fallback:** `extensions/msteams/src/reply-stream-controller.ts:192-195`
  - body: When a non-whitespace rewrite is detected, this sets `streamFailed` so `preparePayload()` returns the full rewritten block, but also sets `streamFinalizationPending`, so `finalize()` calls the SDK's `close()`. In `@microsoft/teams.apps` 2.0.13, `close()` publishes the text already accumulated by prior `emit()` calls; the user can therefore receive the stale prefix as one finalized message and the rewritten full reply as another. Clear or retire the SDK text before close, or keep non-whitespace rewrites out of this patch, and test the buffered final content rather than only asserting that `close()` ran.
