## Summary

Keep open: current main still reads successful ClawRouter usage responses with unbounded `response.json()`, while this PR is a focused owner-boundary hardening with sufficient terminal proof. It is not implemented on main or duplicated by another open PR; maintainers only need to accept the intentional 1 MiB compatibility cap before merge.

## What This Changes

The PR caps successful ClawRouter `/v1/usage` response reads at 1 MiB via `readResponseWithLimit` and adds an oversized-response regression test.

## Best Possible Solution

Land the bounded ClawRouter usage read after maintainers accept the 1 MiB quota-response cap, keeping the parsing fix in the ClawRouter plugin and the body limit in the shared response-limit helper.

## Reproduction Assessment

Yes, from source and submitted proof. Current main uses `response.json()` on successful ClawRouter usage responses, and the PR body's local HTTP proof exercises production `fetchClawRouterUsage` with real `fetch` for both oversized and normal responses.

## Solution Assessment

Yes. The ClawRouter plugin owns this usage snapshot boundary, and using the existing shared bounded reader before JSON parsing is the narrow maintainable fix; a broader provider JSON refactor is optional, not required for this PR.
