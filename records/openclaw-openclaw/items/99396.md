## Label Justifications

- `P1`: The PR targets a broken real agent fan-out workflow where top-level sessions can park indefinitely until a user sends another message.
- `merge-risk: 🚨 message-delivery`: The changed wake can be the final delivery event for a fan-out, and the delete-mode path can currently deliver that wake without the child findings.
- `merge-risk: 🚨 session-state`: The PR changes when parked requester sessions resume after child runs settle, and an incomplete wake can leave the parent with stale or insufficient aggregation state.

## Summary

Keep open: the runtime-level fix is aimed at the right agent/session boundary and has strong central real-run proof, but the latest delete-cleanup repair still snapshots retired rows after successful delete-mode cleanup has cleared child result text, so a delete-mode fan-out can wake the requester without the findings it needs to aggregate.

## What This Changes

This PR adds a top-level requester-settle wake in the subagent announce/lifecycle flow, plus registry query support and regression tests for fan-out drain, retries, and retired delete-cleanup rows.

## Best Possible Solution

Preserve an immutable child completion summary before delete cleanup clears result/payload, feed that snapshot into the settle ledger/wake, and keep the existing drain gating, idempotency, and retry semantics.

Yes at source level: current main lacks a top-level requester drain wake while the linked issue and PR body provide real incident timelines. The remaining delete-cleanup defect is also source-reproducible from lifecycle clearing before the newly scheduled wake snapshots the row.

## Solution Assessment

No, not yet: the runtime wake is the right layer, but the delete-cleanup repair is not the best implementation while it ledgers mutable records after result cleanup. A pre-clear immutable summary is the narrower maintainable fix.
