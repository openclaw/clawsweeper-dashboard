## Summary

Keep open. Current main and the latest release still do not expose promptMode on sessions_spawn, while trusted lower-level agent run paths already accept promptMode; making that model-callable needs maintainer product and safety direction.

## What This Changes

The issue requests adding an optional promptMode parameter to sessions_spawn so child sub-agents can be spawned with full, minimal, or none prompt construction.

## Best Possible Solution

If maintainers approve the public contract, add a validated optional promptMode enum to sessions_spawn with the current default preserved, native/ACP semantics documented, and focused tests for schema, forwarding, task visibility, attachments, and tool-policy behavior; otherwise document promptMode as trusted-runtime-only.
