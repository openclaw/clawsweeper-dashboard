## Summary

Keep open. Current main and the latest release still do not expose `promptMode` on `sessions_spawn`, while lower-level agent runs and prompt rendering already support it; exposing `promptMode="none"` to a model-callable spawn tool needs maintainer product and safety direction.

## What This Changes

The issue requests an optional `promptMode` parameter on `sessions_spawn` so callers can spawn deterministic blank sub-agents with `full`, `minimal`, or `none` prompt construction.

## Best Possible Solution

If maintainers approve the contract, add a validated optional `promptMode` enum to native `sessions_spawn` with the current default preserved, document native/ACP safety semantics, and cover schema, forwarding, task, attachment, and tool-policy behavior; otherwise document `promptMode` as trusted-runtime-only.

Options:

- **Keep promptMode trusted-only:** Leave `promptMode` off `sessions_spawn` and document that blank/raw runs require trusted lower-level runtime callers or a future maintainer-owned surface.
- **Design a semantic blank-worker mode:** Add a higher-level isolated-worker option instead of exposing the raw prompt enum, trading a larger design step for a narrower public safety contract.

## Reproduction Assessment

Yes for source-level verification: current `sessions_spawn` has no `promptMode` schema field, parser read, or forwarding path, while lower-level agent runs and prompt rendering already support `promptMode`. This is an API feature gap rather than a strict failing-bug reproduction.

## Solution Assessment

Unclear until maintainers approve the public prompt-mode contract. Reusing the existing enum is the narrowest technical path if `sessions_spawn` should expose this control; a semantic blank-worker mode is safer if maintainers do not want raw prompt construction details in the model-callable API.
