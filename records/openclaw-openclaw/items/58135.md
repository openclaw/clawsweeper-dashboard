## Summary

Keep open. Current main and the latest release still do not expose or forward `promptMode` through the model-callable `sessions_spawn` path, while lower-level trusted agent runs already support it; the remaining question is product approval for exposing that prompt/safety control as spawn API surface.

## What This Changes

Request to add an optional `promptMode: "full" | "minimal" | "none"` parameter to `sessions_spawn` for deterministic blank native sub-agents.

## Best Possible Solution

If maintainers approve the API, add a validated optional promptMode enum to native `sessions_spawn`, preserve the current minimal default, forward it into the child agent run, document safety/context semantics, and cover schema plus forwarding behavior in focused tests.

## Reproduction Assessment

Yes for source-level verification of the missing feature: current `sessions_spawn` does not expose or forward `promptMode`, while lower-level agent runs and prompt rendering already support it. This is not a strict bug reproduction because the issue requests new public API surface.

## Solution Assessment

Unclear until maintainers approve the public prompt-mode contract. Exposing the existing enum is the narrow technical path if `sessions_spawn` should own this control; otherwise prompt mode should remain runtime-owned and documented as not model-callable.
