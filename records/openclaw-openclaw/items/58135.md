## Summary

Keep open. Current main still supports `promptMode` only on trusted lower-level agent runs, not on the model-callable `sessions_spawn` schema or native subagent spawn handoff, so the requested deterministic blank sub-agent API remains unimplemented and needs maintainer product review.

## What This Changes

The issue requests an optional `promptMode` parameter on `sessions_spawn` so spawned sub-agents can run with `full`, `minimal`, or `none` prompt construction.

## Best Possible Solution

If maintainers approve the API, add a validated optional promptMode enum to `sessions_spawn`, preserve the current minimal default, forward it into the child agent run, document the safety/context semantics, and cover schema plus forwarding behavior in focused tests.

## Reproduction Assessment

Yes, source-level verification is high confidence: current main does not expose or forward `promptMode` through `sessions_spawn`, while lower-level agent runs and system-prompt rendering already support it. This is not a strict bug reproduction because the issue requests new public API surface.

## Solution Assessment

Unclear until maintainers approve the public prompt-mode contract. Exposing the existing enum is the narrow technical path if `sessions_spawn` should own this control; otherwise prompt mode should remain runtime-owned and documented as not model-callable.
