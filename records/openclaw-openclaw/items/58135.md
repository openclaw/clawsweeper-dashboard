## Summary

Keep open. Current main still lacks any `promptMode` parameter on the model-callable `sessions_spawn` schema or native subagent handoff, while lower-level prompt rendering already supports `full`, `minimal`, and `none`; the remaining question is product/safety API direction, not implementation discovery.

## What This Changes

Expose an optional `promptMode` control on `sessions_spawn` so spawned sub-agents can run with blank, deterministic prompt context.

## Best Possible Solution

Maintainers should define a safe public spawn isolation profile; if approved, implement schema, type, forwarding, docs, and focused tests while preserving the current minimal default and explicit task/safety semantics.

Rationale: The missing surface is clear in source, but `promptMode: "none"` currently bypasses important runtime prompt sections, so automation cannot decide the permanent public safety/API contract.

Options:

- **Approve safer isolation API (recommended):** Expose a narrow public isolation parameter or constrained prompt profile that suppresses inherited context while preserving required task delivery and safety semantics.
- **Expose raw promptMode:** Add `promptMode?: "full" | "minimal" | "none"` directly to `sessions_spawn`, accepting that model-callable tools can request the internal prompt renderer mode.
- **Keep promptMode internal:** Document that blank deterministic agents require a lower-level/runtime-owned path and do not add prompt-mode control to the spawn tool.

## Reproduction Assessment

Yes, source inspection is enough to verify the missing feature: current `sessions_spawn` does not expose or forward `promptMode`, while the embedded runner and system-prompt renderer already support prompt modes. This is not a strict bug reproduction because it requests new public API surface.

## Solution Assessment

Unclear until maintainers decide the public contract. Directly forwarding the existing enum is technically small, but a safer isolation profile may be the better product shape because raw `none` suppresses important runtime prompt sections.
