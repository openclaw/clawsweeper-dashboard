## Summary

Keep open. Current main and the latest release still do not expose promptMode on sessions_spawn, while lower-level trusted agent runs already support it; exposing that control to a model-callable child-spawn API needs maintainer product and safety direction.

## What This Changes

The issue requests an optional promptMode parameter on sessions_spawn so callers can request deterministic blank sub-agent runs.

## Best Possible Solution

If maintainers approve the public contract, add a validated optional promptMode enum to sessions_spawn with the current minimal default, forward it into the child agent run, document native/ACP safety semantics, and cover schema plus forwarding behavior in focused tests; otherwise document promptMode as trusted-runtime-only.
