## Summary

Keep open. Current main and the latest release still expose `promptMode` only on lower-level trusted agent runs, not on the model-callable `sessions_spawn` schema or native subagent handoff, so the requested deterministic blank sub-agent API remains unimplemented and needs maintainer product review.

## What This Changes

Request to add an optional `promptMode` parameter to `sessions_spawn` so callers can spawn deterministic blank native sub-agents with `promptMode: "none"`.

## Best Possible Solution

If maintainers approve the API, add a validated native-subagent `promptMode` enum to `sessions_spawn`, preserve the current default, define or reject ACP behavior explicitly, forward it into the child agent call, document prompt/safety semantics, and cover schema plus forwarding behavior in focused tests.

## Reproduction Assessment

Yes for source-level verification: current main exposes `promptMode` in lower-level agent runs and system-prompt rendering, but not in the model-callable `sessions_spawn` schema or native subagent handoff. This is a feature/API gap rather than a broken existing contract.

## Solution Assessment

Unclear until maintainers approve the public prompt-mode contract. Exposing the existing enum is the narrow technical path if this belongs in `sessions_spawn`; otherwise the safer path is to keep prompt mode runtime-owned or provide a plugin/SDK seam that can express blank-worker runs without broad model-callable prompt control.
