## Summary

Keep open. Current main and latest release v2026.6.11 still expose `promptMode` on lower-level agent runs but not on the model-callable `sessions_spawn` schema or native subagent handoff, so the requested deterministic blank subagent API remains unimplemented and needs maintainer product review.

## What This Changes

Expose an optional `promptMode` parameter on `sessions_spawn` so native subagent spawns can request `full`, `minimal`, or `none` prompt assembly while preserving the current default.

## Best Possible Solution

If maintainers approve the API, add a validated optional `promptMode` enum to `sessions_spawn`, preserve the current minimal default, forward it into the child run, document the safety/context semantics, and cover schema plus forwarding behavior in focused tests.

## Reproduction Assessment

Yes for source-level verification: current main and v2026.6.11 do not expose or forward `promptMode` through `sessions_spawn`, while lower-level agent runs and system-prompt rendering already support it. This is not a strict bug reproduction because the issue requests new public API surface.

## Solution Assessment

Unclear until maintainers approve the model-callable prompt-mode contract. Exposing the existing enum is the narrow technical path if `sessions_spawn` should own this control; otherwise prompt mode should remain trusted lower-level runtime surface and the current context modes should be documented as the supported boundary.
