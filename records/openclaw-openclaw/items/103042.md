## Summary

Keep this PR open: it targets a real security-sensitive Azure CLI shell issue, but the submitted Windows fix is not mergeable because it resolves `az` to a `.cmd` wrapper and then passes that wrapper directly to `execFile`/`spawn`, which breaks the Windows execution path.

## What This Changes

The PR removes Windows `shell: true` from Microsoft Foundry Azure CLI invocations and adds a cached resolver that uses `where az` on Windows.

## Best Possible Solution

Rework the Windows Azure CLI launcher to use a proven shell-free executable or entrypoint resolution path, or a maintainer-approved shell strategy with strict argument handling, then add focused tests plus redacted Windows Azure CLI proof.
