## Summary

Keep this PR open: the new prompt tells dispatched workers to use `workboard_read`, but that optional tool is not included in the dispatch-time worker allowlist, so a default worker cannot follow the instruction. Likely related people: `chatgpt-codex-connector[bot]` previously identified this effective-tool-surface mismatch (high confidence); Workboard code ownership could not be established from the available read-only inspection.

## What This Changes

The PR changes Workboard worker instructions and docs so a dispatched worker re-reads its own card with `workboard_read` instead of loading every card with `workboard_list`.

## System Context

Workboard dispatch claims ready cards, builds each worker's bounded context, and starts an isolated subagent session with a restricted tool surface. The worker prompt guides that session's next reads, while the dispatch allowlist determines which Workboard tools it can actually call.

## Architecture Diagram

flowchart LR
  A[Ready Workboard card] --> B[Dispatcher claims card]
  B --> C[Build bounded card context]
  C --> D[Restricted worker tool surface]
  D --> E[Worker prompt]
  E --> F[Card-scoped refresh]
  F --> G[Heartbeat, complete, or block card]

## Best Possible Solution

Make the dispatched worker's card-scoped refresh capability real: grant `workboard_read` only through the existing constrained dispatch path after confirming its card/claim authorization, add an effective-tool-surface regression test, then retain the prompt and docs guidance.
