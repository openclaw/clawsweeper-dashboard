## Summary

Keep open. Current main and latest release still provide adjacent pre-tool, finalization-revision, and outbound-message hooks, but not the requested fail-closed responseGate with mandatory-tool accounting, typed validators, two-phase planning, fallback semantics, and audit records; the linked plugin projects are useful complementary context rather than a core fix.

## What This Changes

Request to add a core pre-response enforcement layer that blocks final output until mandatory tool calls and configured validators run and pass.

## Best Possible Solution

Keep this as the canonical response-gate design item: add a versioned core/plugin API for mandatory tool-call accounting, typed response validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, while leaving domain policy packs to plugins or ClawHub.

## Reproduction Assessment

Yes, at source level: current main exposes adjacent pre-tool, finalization-revision, and outbound hooks, but no configured responseGate or mandatory-tool validator contract. I did not run a live canary, so this is source-reproducible rather than executed end-to-end.

## Solution Assessment

No, the current implementation is not a complete solution for this request. The best path is a maintainer-approved core/plugin API design, not a plugin-only policy pack or a narrow fail-closed tweak to one hook.
