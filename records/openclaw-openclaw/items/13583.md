## Summary

Keep open. Current main has adjacent pre-tool blocking, route-specific OpenAI tool_choice rejection, final-answer revision, reply-payload, and outbound message cancellation hooks, but it still lacks the requested fail-closed response gate with mandatory tool-call accounting, typed validators, two-phase planning, bounded fallback, and audit records.

## What This Changes

The issue requests a hard pre-response enforcement layer that blocks final answers until mandatory tool calls and policy validators pass.

## Best Possible Solution

Keep this as the canonical response-gate design item: add a versioned core/plugin API for mandatory tool-call accounting, typed response validators, fail-closed final-response gating, bounded retry/fallback, and audit records, with domain-specific policy packs shipped as plugins or ClawHub packages.

## Reproduction Assessment

Yes, at source level: current main exposes adjacent pre-tool, finalization, tool_choice, and outbound delivery controls, but no responseGate or mandatory-tool validator contract that can mechanically block final delivery until checks pass.

## Solution Assessment

No implementation path is selected yet; the best fix is maintainer-reviewed core/plugin API design rather than extending a soft final-answer revision hook or adding one-off core policy.
