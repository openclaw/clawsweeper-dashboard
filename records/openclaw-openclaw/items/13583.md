## Summary

Keep open. Current main and the latest release still provide adjacent pre-tool blocking, before-finalize revision, native hook relay, and outbound message cancellation, but not the requested fail-closed response gate with mandatory tool-call accounting, typed validators, two-phase planning, retry/fallback semantics, and audit records.

## What This Changes

The issue requests a core/plugin pre-response enforcement layer that can block final output until required tool calls and policy validators have run and passed.

## Best Possible Solution

Keep this as the canonical response-gate policy-as-code design item and design a versioned core/plugin API for mandatory tool-call accounting, typed validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, with domain-specific policies implemented as plugins or ClawHub packages.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 expose adjacent revision, tool-policy, delivery-hook, and native relay mechanisms, but not a fail-closed responseGate with validator and mandatory-tool accounting.

## Solution Assessment

Unclear pending maintainer design. A versioned core/plugin response-gate API appears to be the right boundary, but maintainers need to settle validator trust, fail-closed defaults, retries, audit metadata, and plugin/domain policy ownership before implementation.
