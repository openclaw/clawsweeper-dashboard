## Summary

Keep open. Current main still has adjacent pre-tool blocking, before-finalize revision, reply dispatch, outbound message cancellation, and Codex hook analogues, but it does not implement the requested fail-closed response gate with mandatory-tool accounting, typed validators, two-phase planning, retry/fallback semantics, and audit records.

## What This Changes

Request to add fail-closed pre-response enforcement hooks and validators so final answers or public actions cannot proceed until mandatory tools and policy checks pass.

## Best Possible Solution

Keep this as the canonical response-gate design item: a versioned core/plugin API for mandatory-tool accounting, typed validators, fail-closed final-response/action gating, bounded retry/fallback, and audit records, with domain policy packs living as plugins or ClawHub packages.

## Reproduction Assessment

Yes, at source level: current main lacks a responseGate/two-phase/validator surface, and the closest before_agent_finalize hook fails open on absence or errors instead of blocking final delivery.

## Solution Assessment

Keeping this open for maintainer product/security/API design is the best current path; a safe fix should define a durable core/plugin seam rather than layering policy claims onto message cancellation or pre-tool hooks.
