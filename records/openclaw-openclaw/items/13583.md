## Summary

Keep open. Current main has adjacent pre-tool blocking, outbound cancellation, and a before-finalize revision hook, but it still does not implement the requested fail-closed response gate with mandatory tool-call accounting, typed validators, two-phase planning, retry/fallback semantics, and audit records.

## What This Changes

Request for a core/plugin pre-response enforcement layer that mechanically blocks final output until mandatory tool calls and validators pass.

## Best Possible Solution

Keep this as the canonical response-gate design item and define a versioned core/plugin API for mandatory tool-call accounting, typed response validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, with domain policy packs implemented as plugins or ClawHub packages.

## Reproduction Assessment

Yes. Source inspection reproduces the remaining gap: current main has pre-tool blocking and a before-finalize revision hook, but no fail-closed responseGate contract with mandatory tool-call accounting and validators.

## Solution Assessment

No. The requested direction is plausible, but the best solution needs a maintainer-approved core/plugin API and security design rather than a one-off hook or narrow channel patch.
