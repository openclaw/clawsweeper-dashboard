## Summary

Keep open. Current main and the latest release still provide adjacent pre-tool blocking, final-answer revision, and outbound cancellation hooks, but they do not provide the requested fail-closed response gate with mandatory-tool accounting, typed validators, two-phase planning, fallback semantics, and audit records.

## What This Changes

The issue requests a core pre-response enforcement layer that prevents final output until configured validators and mandatory tool calls have completed successfully.

## Best Possible Solution

Keep this as the canonical response-gate design item and define a versioned core/plugin API for mandatory-tool accounting, typed validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, with domain policy packs living in plugins or ClawHub packages.

## Reproduction Assessment

Yes, at source level. Current main lacks responseGate-style symbols, before_agent_finalize is fail-open revision behavior, and the latest release has the same adjacent-only finalization contract.

## Solution Assessment

Yes for keeping the issue open, but not for queueing a one-shot implementation. The maintainable path is a maintainer-approved versioned response-gate contract that composes with existing pre-tool, message-sending, approval, and plugin APIs.
