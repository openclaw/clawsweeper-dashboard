## Summary

Keep open. Current main and v2026.6.11 still provide adjacent pre-tool blocking, before-finalize revision, reply-dispatch, and outbound cancellation hooks, but not the requested fail-closed response gate with mandatory-tool accounting, typed validators, two-phase planning, retry/fallback semantics, and audit records.

## What This Changes

The issue requests a pre-response enforcement layer that mechanically gates final output on required tool calls and validator results.

## Best Possible Solution

Keep this as the canonical response-gate policy-as-code design item: add a versioned core/plugin API for mandatory-tool accounting, typed validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, with domain-specific policy packs living in plugins or ClawHub packages.

## Reproduction Assessment

Yes. Source inspection shows current main lacks responseGate-style config/API symbols, and the closest hooks either fail open at finalization or only block individual tool execution.

## Solution Assessment

Yes for keeping this open, but not as a narrow automated patch. Existing pre-tool and outbound hooks are useful primitives; the best implementation needs maintainer product/security design for a versioned response-gate contract and audit semantics.
