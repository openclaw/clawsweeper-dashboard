## Summary

Keep open: current main still has adjacent pre-tool blocking, before-finalize revision, message-sending cancellation, and Codex Stop relay support, but not the requested fail-closed responseGate with mandatory tool-call accounting, typed validators, two-phase planning, bounded fallback/retry semantics, and audit records.

## What This Changes

The issue requests a core pre-response enforcement layer that can prevent final answer delivery until mandatory tool calls and validators have passed.

## Best Possible Solution

Keep this as the canonical response-gate policy-as-code design item: add a versioned core/plugin API for mandatory tool-call accounting, typed response validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, with domain policy packs implemented as plugins or ClawHub packages.

## Reproduction Assessment

Yes, as a source-level feature gap. Current main has no responseGate/config/API surface, and the closest before_agent_finalize path is revision-oriented and fail-open rather than a mandatory-tool validator gate.

## Solution Assessment

Unclear pending maintainer design. A core/plugin response-gate seam is the right boundary, but maintainers still need to decide the versioned API, defaults, fail-closed behavior, retry/refusal semantics, audit record shape, and how domain policies stay out of core.
