## Summary

Keep open. Current main has adjacent pre-tool blocking, scoped HTTP `tool_choice` enforcement, and a before-finalize revision hook, but it still lacks the requested fail-closed response gate with mandatory-tool accounting, typed validators, two-phase planning, retry/fallback semantics, and audit records.

## What This Changes

Request to add a fail-closed pre-response enforcement layer that blocks final answers until mandatory tool-call and validator policies have passed.

## Best Possible Solution

Define a versioned core/plugin response-gate API for mandatory tool-call accounting, typed validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, while leaving domain policy packs as plugins or ClawHub packages.

## Reproduction Assessment

Yes, at source level: current main has scoped HTTP `tool_choice`, pre-tool policy, and before-finalize revision hooks, but no general fail-closed `responseGate` contract with mandatory-tool accounting and validators. I did not run a live model scenario because the remaining gap is a broad API/product feature rather than a deterministic single-path bug.

## Solution Assessment

Yes, keeping this open for maintainer design is the best current path. An autonomous patch would have to choose security-sensitive plugin/API semantics, fail-closed behavior, config shape, and audit contracts without maintainer approval.
