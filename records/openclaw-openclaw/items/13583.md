## Summary

Keep open. Current main still has adjacent HTTP client-tool `tool_choice`, pre-tool blocking, finalization revision, and outbound cancellation, but not the requested fail-closed response gate with mandatory-tool accounting, typed validators, two-phase planning, bounded fallback, and audit records; linked plugin work is complementary rather than a core replacement.

## What This Changes

The issue requests a pre-response enforcement layer that blocks final output until mandatory tool calls and configured validators have passed.

## Best Possible Solution

Design a versioned core/plugin response-gate API for mandatory tool-call accounting, typed validators, fail-closed final-response gating, bounded retry/fallback, and audit records, with domain policy packs kept in plugins or ClawHub.

## Reproduction Assessment

Yes for a source-level feature gap: current main lacks the requested responseGate/mandatory-tool ledger/validator contract, and the closest finalization hook fails open on absent or failed hooks.

## Solution Assessment

The product direction is plausible, but the best fix needs maintainer security/API design; a one-off hook patch would be too narrow and could create an unreliable enforcement boundary.
