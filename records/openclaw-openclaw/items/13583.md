## Summary

This issue remains necessary: current main exposes adjacent pre-tool authorization and a bounded `before_agent_finalize` revision hook, but the requested fail-closed final-delivery gate, mandatory-tool ledger, typed validator contract, and deterministic fallback/audit semantics are still not established. The July 19 plugin spike usefully confirms the hook can improve compliance on one Gateway path without turning it into a permanent delivery veto, so this needs maintainer product and security design review rather than a one-shot fix PR.

## What This Changes

Request a fail-closed, pre-response policy gate that requires configured tools and validators to pass before an agent can deliver a final response.

## Best Possible Solution

Define and approve a minimal versioned core/plugin final-delivery policy contract: a trusted run-scoped completed-tool ledger, typed allow/refuse/HITL decision, bounded retry and explicit fail-closed fallback, structured audit events, and cross-harness delivery tests; keep domain-specific policy packs in plugins or ClawHub.
