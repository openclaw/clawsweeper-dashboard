## Summary

Keep open. Current main and the latest release still have adjacent pre-tool blocking, before-finalize revision, reply-dispatch, and outbound cancellation hooks, but they do not implement a fail-closed response gate with mandatory-tool accounting, typed validators, two-phase planning, retry/fallback semantics, and audit records.

## What This Changes

Requests a fail-closed pre-response enforcement layer that prevents final output until mandatory tool calls and policy validators run and pass.

## Best Possible Solution

Keep this as the canonical response-gate policy-as-code design item: define a versioned core/plugin API for mandatory-tool accounting, typed validators, fail-closed final-response gating, bounded retry/fallback behavior, user approval envelopes, and audit records, with domain policies implemented as plugins or ClawHub packages.

## Reproduction Assessment

Yes, as a source-level feature gap: current main has adjacent hooks and HTTP tool_choice enforcement, but no responseGate-style mandatory-tool validator contract or fail-closed final-response gate. I did not run a live agent scenario in this read-only cleanup pass.

## Solution Assessment

Unclear until maintainers choose the product/security contract. A versioned core/plugin response-gate seam is the right end state, but the exact validator trust model, fallback behavior, audit format, and plugin boundary need design review first.
