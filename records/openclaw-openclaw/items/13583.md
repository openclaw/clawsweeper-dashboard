## Summary

Keep open. Current main and v2026.6.11 still provide adjacent pre-tool blocking, final-answer revision, and outbound message cancellation hooks, but not the requested fail-closed response gate with mandatory-tool accounting, typed validators, two-phase planning, fallback semantics, and audit records.

## What This Changes

The issue requests a fail-closed pre-response enforcement layer that blocks final output until mandatory tool calls and policy validators run and pass.

## Best Possible Solution

Keep this open as the canonical response-gate policy-as-code design item, with domain policy packs in plugins and a versioned core/plugin API for mandatory-tool accounting, typed validators, fail-closed final-response gating, bounded fallback, and audit records.

## Reproduction Assessment

Yes at source level. Current main lacks responseGate symbols and has only adjacent hooks: before_agent_finalize is fail-open revision, before_tool_call is pre-execution gating, and message_sending is outbound cancellation.

## Solution Assessment

Unclear pending maintainer design. The issue identifies the right missing boundary, but the best implementation needs a product/security decision on validator authority, audit semantics, fallback behavior, retries, and plugin API shape.
