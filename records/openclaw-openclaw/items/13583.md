## Summary

Keep open. Current main has adjacent pre-tool blocking, before-finalize revision, outbound cancellation, and HTTP client-tool `tool_choice` enforcement, but it still lacks the requested general fail-closed pre-response gate with mandatory-tool accounting, typed validators, two-phase planning, fallback/retry semantics, and audit records.

## What This Changes

The issue requests a hard pre-response enforcement layer that can block final answers until mandatory tool calls, validators, retry/fallback policy, and audit checks pass.

## Best Possible Solution

Keep this as the canonical response-gate design item: define a versioned core/plugin API for mandatory-tool ledgers, typed response validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, with domain policy packs shipped as plugins or ClawHub packages.

## Reproduction Assessment

Yes, at source level. Current main has no `responseGate` contract, the closest finalize hook fails open to `continue`, and the only hard required-tool behavior is scoped to HTTP client tools.

## Solution Assessment

Unclear until maintainer design review. A core/plugin response-gate seam is the right end state, but the exact validator API, fail-closed defaults, audit shape, and plugin policy boundary need product and security decisions first.
