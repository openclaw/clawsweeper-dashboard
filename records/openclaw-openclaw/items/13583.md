## Summary

Keep open. Current main and latest release still provide adjacent pre-tool blocking, final-answer revision, native hook relay, and outbound cancellation hooks, but not the requested fail-closed pre-response gate with mandatory-tool accounting, typed validators, two-phase planning, bounded fallback, and audit records.

## What This Changes

The issue requests a core/plugin enforcement layer that can block final output until mandatory tool calls and configured validators have run and passed.

## Best Possible Solution

Keep this as the canonical response-gate design item and define a versioned core/plugin API for mandatory-tool ledgers, typed validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, with domain policy packs living as plugins or ClawHub packages.

## Reproduction Assessment

Yes, at source level: current main has pre-tool fail-closed hooks and a fail-open finalization revision hook, but no responseGate or mandatory-validator enforcement path. The live comments add deployment evidence, but I did not run a live end-to-end reproduction.

## Solution Assessment

Yes on the product boundary, but not as a one-shot patch: the maintainable path is a reviewed core/plugin API plus policy-pack ownership, not another prompt rule or a plugin-only workaround.
