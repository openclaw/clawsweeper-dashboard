## Summary

Keep open. Current main has adjacent pre-tool blocking, finalization revision, native Stop-hook continuation, outbound hooks, and narrow HTTP client-tool enforcement, but it still lacks the requested fail-closed responseGate with mandatory-tool accounting, typed validators, two-phase planning, fallback/retry semantics, and audit records.

## What This Changes

The issue requests a hard pre-response enforcement layer that blocks final answers until required tool calls, validators, retries/fallback behavior, and audit records have completed.

## Best Possible Solution

Keep this open as the canonical response-gate policy-as-code design item, with domain policies implemented as plugins once core exposes a versioned hard-gate API.

## Reproduction Assessment

Yes. Source inspection shows the current finalization hook can revise answers but continues when absent or failed and lacks mandatory-tool ledgers, typed validators, fail-closed fallback, and audit records; I did not run an end-to-end failing scenario.

## Solution Assessment

Unclear as an implementation shape. The two-phase validator direction is plausible, but the best fix needs maintainer security/product design across core/plugin API, response delivery, native harnesses, and audit semantics before implementation.
