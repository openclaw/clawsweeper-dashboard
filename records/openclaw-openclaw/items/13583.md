## Summary

Keep open. Current main has adjacent pre-tool blocking, before-finalize revision, outbound cancellation hooks, and narrow HTTP `tool_choice` enforcement, but it still does not provide the requested fail-closed `responseGate` with mandatory-tool accounting, typed validators, two-phase planning, retry/fallback semantics, and audit records. The linked APort, vainplex governance, and claude-rule-enforcer comments are useful existing-solution signals for plugin-owned policy packs, but they also reinforce that the missing final-response gate is a core/plugin runtime seam rather than a completed core behavior.

## What This Changes

The issue requests a fail-closed pre-response enforcement layer for mandatory tool calls, validator checks, bounded retry/fallback behavior, and auditability.

## Best Possible Solution

Keep this as the canonical core/plugin API design item: add a versioned response-gate contract for mandatory-tool accounting, typed validators, fail-closed final-response/action gating, bounded retry/fallback behavior, and audit records, with domain policy packs delivered as plugins or ClawHub packages.

## Reproduction Assessment

Yes. Source inspection on current main shows no `responseGate`/two-phase/validator surface, and the closest `before_agent_finalize` hook fails open on absence/errors rather than blocking final response delivery.

## Solution Assessment

Yes, keeping this open for maintainer product/security/API design is the best current path. A one-off core implementation would be too broad; the maintainable direction is a versioned core/plugin seam plus plugin-owned domain policies.
