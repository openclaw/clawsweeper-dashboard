## Summary

Keep open: current main and v2026.6.11 still have adjacent pre-tool, final-answer revision, reply-dispatch, and outbound cancellation hooks, but not the requested fail-closed response gate with mandatory tool-call accounting, typed validators, two-phase planning, fallback/retry semantics, and audit records.

## What This Changes

The issue requests a configurable pre-response enforcement layer that can block final output until required tools and policy validators have run and passed.

## Best Possible Solution

Keep this as the canonical response-gate policy-as-code design item and define a versioned core/plugin API for mandatory tool-call accounting, typed validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, with domain policies shipped as plugins or ClawHub packages.
