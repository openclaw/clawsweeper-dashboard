## Summary

Keep open. Current main still has adjacent pre-tool blocking, before-finalize revision, outbound cancellation, and narrow HTTP tool_choice enforcement, but not the requested fail-closed responseGate with mandatory-tool accounting, typed validators, two-phase planning, retry/fallback semantics, and audit records.

## What This Changes

The issue requests a fail-closed pre-response enforcement layer that can require validators and mandatory tool calls before final answer delivery.

## Best Possible Solution

Keep this open as the canonical response-gate policy-as-code design item: define a versioned core/plugin API for mandatory-tool accounting, typed response validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, with domain-specific policy packs implemented as plugins or ClawHub packages.

## Reproduction Assessment

Yes, at source level: current main has adjacent hooks and visible-reply modes, but no responseGate contract that mechanically requires validators and mandatory tools before final output. I did not run a live agent canary for the quant or public-action scenarios.

## Solution Assessment

No, not as a one-shot implementation. The maintainable solution needs maintainer product/security design for a versioned core/plugin response-gate API rather than a narrow before_agent_finalize, message_sending, or prompt-only patch.
