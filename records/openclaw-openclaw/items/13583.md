## Summary

Keep open. Current main and v2026.6.11 still have adjacent pre-tool, before-finalize, and outbound-message hooks, but not the requested fail-closed response gate with mandatory tool-call accounting, typed validators, two-phase planning, retry/fallback semantics, and audit records.

## What This Changes

Request to add a pre-response enforcement layer that blocks final output until configured mandatory tool calls and validators have passed.

## Best Possible Solution

Keep this as the canonical response-gate design item: define a versioned core/plugin API for mandatory tool-call ledgers, typed response validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, while leaving domain-specific policy packs to plugins or ClawHub.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 lack responseGate/mandatory-tool symbols, and the closest hooks are fail-open revision, pre-tool execution, or outbound-send hooks rather than a hard pre-response gate.

## Solution Assessment

Unclear until maintainers choose the security model. A core/plugin runtime seam is the right layer, but the exact two-phase protocol, config shape, fail-closed defaults, plugin trust, and audit behavior need product/security review first.
