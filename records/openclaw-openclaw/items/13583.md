## Summary

Keep open: current main and v2026.6.11 still provide adjacent pre-tool, final-answer revision, and outbound-cancel hooks, but not the requested fail-closed response gate with mandatory tool-call accounting, typed validators, two-phase planning, fallback semantics, and audit records.

## What This Changes

The issue requests a responseGate-style two-phase enforcement layer that blocks final output until required tools and validators have passed.

## Best Possible Solution

Keep this as the canonical response-gate policy-as-code design item: approve a versioned core/plugin API for mandatory tool-call accounting, typed response validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, while leaving domain-specific policy packs to plugins or ClawHub packages.
