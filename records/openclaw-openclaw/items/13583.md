## Summary

Keep open. Current main still has adjacent pre-tool blocking, before-finalize revision, outbound message cancellation, and narrow HTTP client-tool `tool_choice` enforcement, but it does not implement the requested fail-closed response gate with mandatory internal tool accounting, typed validators, two-phase planning, bounded retry/fallback behavior, or audit records.

## What This Changes

The issue requests a hard pre-response enforcement layer that blocks final output until configured validators and required tool calls pass.

## Best Possible Solution

Keep this as the canonical response-gate design item: add a versioned core/plugin seam for mandatory tool ledgers, typed validators, fail-closed final-response gating, bounded retry/fallback, and audit records, with domain policies shipped as plugins.

## Reproduction Assessment

Yes, at source level: current main exposes adjacent pre-tool, before-finalize, outbound, and HTTP client-tool mechanisms, but no responseGate/validator ledger that can enforce required internal tools before final output.

## Solution Assessment

The current adjacent hooks are not the best complete solution; the maintainable path is a designed core/plugin response-gate contract plus plugin-owned policy packs, not prompt rules or a one-off config shim.
