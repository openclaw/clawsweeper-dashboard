## Summary

Keep open: current main and v2026.6.11 still have adjacent pre-tool blocking, final-answer revision, and outbound message hooks, but no fail-closed response gate with mandatory tool accounting, typed validators, two-phase planning, bounded fallback, or audit records.

## What This Changes

The issue requests hard pre-response enforcement hooks so final output can be blocked until mandatory tools and policy validators pass.

## Best Possible Solution

Keep this as the canonical response-gate policy-as-code design item, with a versioned core/plugin API for mandatory-tool accounting, typed validators, fail-closed final-response gating, bounded retry/fallback, and audit records while domain policies live in plugins or ClawHub.

## Reproduction Assessment

Yes at source level: current main and v2026.6.11 expose only adjacent revision, tool-policy, delivery-hook, and message-cancellation mechanisms, not a fail-closed responseGate with validator and mandatory-tool accounting.

## Solution Assessment

Unclear pending maintainer design; the likely right direction is a versioned response-gate core/plugin seam that composes with existing tool approvals, outbound delivery hooks, message-tool-only behavior, retries, fallbacks, and audit records.
