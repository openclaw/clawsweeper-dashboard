## Summary

Keep open. Current main and the latest release still have adjacent pre-tool blocking, final-answer revision, reply dispatch, and outbound cancellation hooks, but they do not provide the requested fail-closed response gate with mandatory tool-call accounting, typed validators, two-phase planning, bounded fallback semantics, and audit records.

## What This Changes

The issue requests a hard pre-response enforcement layer that blocks final output until mandatory tool calls and configured validators have passed.

## Best Possible Solution

Keep this as the canonical core response-gate design item: add a versioned core/plugin API for mandatory tool-call accounting, typed response validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, with domain-specific policy packs living as plugins or ClawHub packages.

## Reproduction Assessment

Yes. Source inspection shows current main has pre-tool fail-closed policy and before-finalize revision hooks, but no hard responseGate, mandatory-tool ledger, typed validators, or two-phase response protocol; I did not run a live canary.

## Solution Assessment

Yes for keeping this open, not for queuing an automated fix. The narrow maintainable path is a reviewed core/plugin API design with plugin-owned policy packs, rather than a one-off runtime patch.
