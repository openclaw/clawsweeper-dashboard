## Summary

Keep open. Current main and v2026.6.11 still have adjacent pre-tool, final-answer revision, reply-dispatch, and outbound-cancel hooks, but not the requested fail-closed response gate with mandatory-tool accounting, typed validators, two-phase planning, retry/fallback semantics, and audit records.

## What This Changes

The issue requests a pre-response enforcement layer that blocks final output until mandatory tool calls and validator checks have run and passed.

## Best Possible Solution

Define a versioned core/plugin response-gate API for mandatory tool-call accounting, typed validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, with domain-specific policy packs kept in plugins or ClawHub packages.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 expose pre-tool blocking, final-answer revision, reply-dispatch, and message-cancel hooks, but no responseGate/mandatory-tool ledger or validator-controlled final-response protocol.

## Solution Assessment

Unclear pending maintainer design. A hard response gate belongs near the core/plugin runtime seam, but maintainers need to choose the API, trust model, fail-closed defaults, retry/fallback behavior, and audit semantics before a patch can be called the best fix.
