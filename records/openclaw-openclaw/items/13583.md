## Summary

Keep open: current main still has adjacent pre-tool, finalization-revision, message-tool-only, and outbound message hooks, but not the requested fail-closed response gate with mandatory-tool accounting, typed validators, two-phase planning, retry/fallback semantics, and audit records.

## What This Changes

The issue requests a core pre-response enforcement layer that blocks final answers until mandatory tools and policy validators have run and passed.

## Best Possible Solution

Keep this as the canonical response-gate policy-as-code design item: add a versioned core/plugin API for mandatory-tool accounting, typed response validators, fail-closed or HITL final-response gating, bounded retry/fallback behavior, and audit records, while leaving domain policy packs to plugins or ClawHub packages.
