## Summary

Keep open. Current main and v2026.6.11 still have adjacent pre-tool, final-answer revision, HTTP `tool_choice`, and outbound-send hooks, but they do not provide the requested fail-closed pre-response gate with mandatory-tool accounting, typed validators, two-phase planning, fallback/retry semantics, and audit records.

## What This Changes

Request a pre-response enforcement layer that mechanically blocks final output until required tools and policy validators have passed.

## Best Possible Solution

Keep this as the canonical response-gate design item: add a versioned core/plugin API for mandatory-tool ledgers, typed response validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, while leaving domain policy packs to plugins or ClawHub.

## Reproduction Assessment

Yes, for the feature gap: source inspection shows current main lacks a fail-closed responseGate contract and only has adjacent revision, pre-tool, HTTP tool_choice, and outbound-send mechanisms. The live comments add real-world policy-bypass examples, but no local runtime repro was run in this read-only cleanup pass.

## Solution Assessment

Unclear pending maintainer design. A core/plugin response-gate seam is the right layer, but maintainers still need to choose fail-closed defaults, trusted plugin authority, user approval behavior, retry/fallback semantics, and audit shape before implementation.
