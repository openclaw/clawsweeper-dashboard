## Summary

Keep open. Current main has useful adjacent enforcement seams, but it still lacks the requested general fail-closed pre-response gate with mandatory-tool accounting, typed validators, two-phase planning, fallback/retry semantics, and audit records.

## What This Changes

The issue requests a hard pre-response enforcement layer that blocks final output until configured mandatory tool calls and validator checks have passed.

## Best Possible Solution

Keep this as the canonical response-gate policy-as-code design item, with domain policy packs living in plugins or ClawHub packages once a versioned core/plugin API exists for mandatory-tool accounting, typed validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records.

## Reproduction Assessment

Not applicable as a narrow bug repro, but source inspection gives high-confidence proof of the gap: current hooks can revise, cancel, or block adjacent paths, but there is no general responseGate ledger/validator/fail-closed final-delivery contract.

## Solution Assessment

Yes, keeping this open for maintainer product/security design is the best path; a one-off patch would likely create a brittle security API without settled semantics for plugins, audit records, config, and upgrades.
