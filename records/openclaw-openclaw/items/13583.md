## Summary

Keep open. Current main and the latest release still provide adjacent pre-tool blocking, final-answer revision, outbound send cancellation, and prompt/private-reply modes, but they do not implement the requested fail-closed pre-response gate with mandatory tool-call accounting, typed validators, two-phase planning, bounded fallback semantics, and audit records.

## What This Changes

The issue requests a core/plugin enforcement mechanism that blocks final responses until mandatory tool and policy validators have run and passed.

## Best Possible Solution

Define a versioned core/plugin response-gate API with mandatory tool-call accounting, typed validators, bounded retry/fallback behavior, final-delivery blocking, and audit records, while keeping domain policy packs in plugins or ClawHub.

## Reproduction Assessment

Yes, source inspection is enough to reproduce the gap: current main exposes revision and pre-tool hooks but no fail-closed required-tool validator gate before final response delivery.

## Solution Assessment

The requested direction is plausible, but the final API, config, fallback, audit, and trust semantics need maintainer product/security design before implementation.
