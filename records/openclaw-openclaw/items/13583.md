## Summary

Keep open. Current main and v2026.6.11 still have adjacent pre-tool blocking, final-answer revision, and outbound-message cancellation hooks, but not the requested fail-closed responseGate with mandatory-tool accounting, typed validators, two-phase planning, fallback semantics, and audit records; the linked APort Guardrails, vainplex/openclaw-governance, and claude-rule-enforcer comments are useful adjacent plugin/pre-tool context rather than a core fix.

## What This Changes

The issue requests a pre-response enforcement layer that blocks final output until mandatory tool calls and configured validators have run and passed.

## Best Possible Solution

Keep this open as the canonical response-gate design item: add a versioned core/plugin API for mandatory-tool accounting, typed validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, with domain-specific policy packs living as plugins or ClawHub packages.

## Reproduction Assessment

Yes, at source level: current main exposes before_tool_call blocking, message_sending cancellation, and before_agent_finalize revision, but no responseGate or mandatory-tool validator protocol. I did not run a live failing agent scenario because the absence is clear from the current code and docs.

## Solution Assessment

Unclear until maintainers choose the contract. The right layer appears to be a versioned core/plugin response-gate seam, not a one-off domain policy in core or another prompt/config-only rule.
