## Summary

Keep open: current main still has adjacent pre-tool, before-finalize, and outbound-send hooks, but no fail-closed pre-response gate that accounts for required tool calls, typed validators, two-phase planning, fallback behavior, and audit records.

## What This Changes

The issue requests a hard pre-response enforcement layer that blocks final answers until required tools and policy validators have run and passed.

## Best Possible Solution

Define a versioned core/plugin response-gate API for mandatory-tool accounting, typed validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, with domain-specific policy packs kept in plugins or ClawHub packages.

## Reproduction Assessment

Yes, at source level. Current main lacks the proposed responseGate config/API and the closest before_agent_finalize path is a fail-open revision hook, not a mandatory-tool/validator gate.

## Solution Assessment

Unclear until maintainers choose the product and security semantics. A core/plugin runtime seam is the right layer, but the exact fail-closed behavior, validator authority, and plugin API shape need design review first.
