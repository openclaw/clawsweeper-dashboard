## Summary

Keep open. Current main has adjacent pre-tool fail-closed hooks, a before-finalize revision hook, outbound cancellation hooks, and narrow HTTP `tool_choice` enforcement, but it still lacks the requested fail-closed `responseGate` with mandatory-tool accounting, typed validators, two-phase planning, retry/fallback semantics, and audit records.

## What This Changes

The issue requests a pre-response enforcement layer that blocks final output until mandatory tool calls and configured validators have passed.

## Best Possible Solution

Keep this as the canonical response-gate design item and define a versioned core/plugin API for mandatory tool-call accounting, typed response validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, with domain policy packs implemented as plugins or ClawHub packages.

## Reproduction Assessment

Yes, at source level. Current main exposes only adjacent revision, pre-tool, pre-send, and HTTP client-tool enforcement paths, and none implements a general fail-closed responseGate contract with validators and mandatory-tool accounting.

## Solution Assessment

Unclear pending maintainer design. The maintainable path is a versioned core/plugin seam plus external policy packs; the proposed two-phase shape is plausible but needs product and security decisions before implementation.
