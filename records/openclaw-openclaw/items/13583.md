## Summary

Keep open: current main and v2026.6.11 still lack the requested fail-closed response gate with mandatory tool-call accounting, typed validators, two-phase planning, bounded retry/fallback behavior, and audit records. Existing `tool_choice` enforcement is limited to OpenAI-compatible HTTP client tools, and current plugin hooks remain adjacent revision/tool/delivery seams rather than a general responseGate policy boundary.

## What This Changes

Add a fail-closed pre-response enforcement layer that blocks final output until mandatory tool calls and validators run, with configuration, retry/fallback, and audit semantics.

## Best Possible Solution

Keep this open as the canonical response-gate design item and define a versioned core/plugin API for mandatory tool ledgers, typed response validators, fail-closed finalization, bounded retry/fallback behavior, and audit records, with domain policy packs living in plugins or ClawHub packages.
