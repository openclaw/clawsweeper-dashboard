## Summary

Keep open. Current main and v2026.6.11 still have adjacent pre-tool blocking, final-answer revision, and outbound cancellation hooks, but not the requested fail-closed response gate with mandatory-tool accounting, typed validators, two-phase planning, fallback semantics, or audit records.

## What This Changes

The issue requests a fail-closed pre-response enforcement layer that blocks final output until mandatory tool calls and validators have run and passed.

## Best Possible Solution

Keep this as the canonical response-gate policy-as-code design item, with a versioned core/plugin API for mandatory-tool accounting, typed response validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records; domain policies should live in plugins or ClawHub packages.

## Reproduction Assessment

Yes, for the source-level feature gap. Current main and v2026.6.11 expose adjacent hook seams, but they do not define responseGate config, mandatory-tool accounting, validator results, fail-closed final delivery, or audit records.

## Solution Assessment

Unclear until maintainers choose the API boundary. Plugin-owned policy packs are the right place for domain rules, but the missing fail-closed response-delivery seam is core/plugin infrastructure and needs product/security design first.
