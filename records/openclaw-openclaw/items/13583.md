## Summary

Keep open: current main and the latest release still have adjacent pre-tool policy, before-finalize revision, reply payload, and message cancellation hooks, but not the requested fail-closed response gate with mandatory-tool accounting, typed validators, two-phase planning, fallback behavior, and audit records. The linked APort, vainplex governance, and claude-rule-enforcer comments are useful existing-solution signals for plugin-owned policy packs, while also confirming the remaining core/plugin runtime gap.

## What This Changes

Requests a configurable pre-response enforcement layer that blocks final output until required tool calls and validators pass, with two-phase planning, retry/fallback behavior, and audit records.

## Best Possible Solution

Keep this as the canonical response-gate design item: approve a versioned core/plugin API for mandatory-tool ledgers, typed response validators, fail-closed final-response gating, bounded retries/fallbacks, and audit records, with domain policy packs implemented as plugins or ClawHub packages.

## Reproduction Assessment

Yes, at source level. Current main lacks the requested responseGate/config/API surface, and the closest before-finalize hook fails open rather than enforcing mandatory validators before response delivery.

## Solution Assessment

Unclear until maintainers choose the product and security contract. A response-gate core/plugin seam is the plausible right layer, but two-phase planning, fail-closed fallback, audit, plugin trust, and policy-pack ownership need design approval first.
