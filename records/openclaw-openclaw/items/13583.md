## Summary

Keep open. Current main has adjacent pre-tool blocking, final-answer revision, reply-dispatch, and outbound cancellation hooks, but it still lacks a fail-closed pre-response gate with mandatory tool-call accounting, typed validators, two-phase planning, fallback semantics, and audit records.

## What This Changes

Requested core support for fail-closed pre-response enforcement hooks that can require tool calls, run typed validators, and block final output until policy checks pass.

## Best Possible Solution

Keep this as the canonical response-gate design item and define a versioned core/plugin API for mandatory tool-call accounting, typed response validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, with domain-specific policies shipped as plugins or ClawHub packages.

## Reproduction Assessment

Yes for the source-level feature gap: current main has adjacent hooks and policy paths, but no responseGate config/API, mandatory-tool ledger, typed validator contract, or fail-closed final-response gate. No live runtime repro was needed to show the requested capability remains missing.

## Solution Assessment

Unclear until maintainers decide the product and security contract. A core/plugin response-gate seam is the right layer for the missing guarantee, but the exact API, config surface, plugin trust model, fallback behavior, and audit semantics need design review first.
