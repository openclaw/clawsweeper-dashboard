## Summary

Keep open: current main and the latest stable release still have adjacent pre-tool, final-answer revision, reply-dispatch, and outbound cancellation hooks, but not the requested fail-closed response gate with mandatory tool-call accounting, typed validators, two-phase planning, retry/fallback semantics, and audit records.

## What This Changes

The issue requests a configurable pre-response enforcement layer that blocks final output until mandatory tools and policy validators have run and passed.

## Best Possible Solution

Keep this as the canonical response-gate design item and define a versioned core/plugin API for mandatory tool ledgers, typed validators, fail-closed final-response gating, bounded retry/fallback, and audit records, with domain policy packs living in plugins or ClawHub.

Rationale: Current hooks cannot provide this guarantee, and choosing fail-closed delivery, validator authority, retries, fallbacks, audit records, and config shape is a product/security policy decision.

Likely owner: steipete

Owner reason: The open choice spans security defaults, plugin/API design, config compatibility, and final-response delivery semantics.

Owner confidence: medium

Options:

- **Design a versioned response gate (recommended):** Create a core/plugin contract for mandatory tool ledgers, typed validators, trusted plugin authority, bounded retries, deterministic fallback, and audit records while keeping domain policy packs outside core.
- **Extend current finalize hooks:** Evolve before_agent_finalize and delivery hooks into a stronger gate, accepting the risk of overloading advisory fail-open hooks with security semantics.
- **Keep policy plugins advisory:** Document current hooks as best-effort filtering and tool blocking only, and defer hard response enforcement until a future security boundary is approved.
