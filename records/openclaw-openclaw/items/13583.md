## Summary

Keep open. Current main has adjacent hooks and a narrow HTTP client-tool `tool_choice` contract, but it still lacks the requested fail-closed pre-response gate with mandatory tool-call accounting, typed validators, two-phase planning, fallback/retry semantics, and audit records.

## What This Changes

The issue requests a configurable pre-response enforcement layer that blocks final output until required tools and validators have run and passed.

## Best Possible Solution

Keep this as the canonical response-gate design item and define a versioned core/plugin API for mandatory tool-call accounting, typed validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, with domain policy packs living as plugins or ClawHub packages.

## Reproduction Assessment

Yes at source level. Current main exposes pre-tool blocking and a best-effort final-answer revision hook, but the inspected code has no fail-closed responseGate contract, mandatory-tool ledger, typed validators, or audit/fallback payload.

## Solution Assessment

Unclear until maintainers choose the product/security contract. The right direction is a versioned core/plugin response-gate seam plus plugin-owned policy packs, not a narrow patch to the current fail-open finalize hook.
