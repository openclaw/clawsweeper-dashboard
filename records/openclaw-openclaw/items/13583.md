## Summary

Keep open: current main and v2026.6.11 still provide adjacent pre-tool, finalization, and outbound-cancel hooks, but not a fail-closed response gate that blocks final output until mandatory tool calls and validators pass. The discussion usefully points to external/plugin implementations for adjacent policy enforcement while preserving the missing core/plugin runtime seam.

## What This Changes

The issue requests a pre-response enforcement layer with mandatory tool-call accounting, typed validators, two-phase planning, fail-closed fallback behavior, per-agent/per-skill configuration, and audit records before final output delivery.

## Best Possible Solution

Keep this as the canonical core/plugin API design item for hard response gates, with domain-specific validators and policy packs implemented as plugins or ClawHub packages once the versioned runtime seam is approved.
