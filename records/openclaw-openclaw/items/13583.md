## Summary

Keep open: current main still has adjacent pre-tool blocking, final-answer revision, reply-dispatch, and message-cancel hooks, but not the requested fail-closed response gate with mandatory tool-call accounting, typed validators, two-phase planning, bounded fallback behavior, or audit proof. The discussion usefully identifies external/plugin work for adjacent enforcement while preserving the missing core/plugin runtime seam.

## What This Changes

Request a pre-response enforcement layer that blocks final output until required tool calls and policy validators have run and passed.

## Best Possible Solution

Keep this as the canonical response-gate design item and define a versioned core/plugin API for mandatory tool-call accounting, typed validators, fail-closed final-response gating, bounded retry/fallback behavior, and audit records, while leaving domain-specific policy packs to plugins or ClawHub packages.
