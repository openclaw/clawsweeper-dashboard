## Summary

This draft addresses a real duplicate-execution edge case, but it changes the established recovery default from a fresh embedded fallback to a fail-closed CLI error. The linked canonical issue explicitly asks for maintainer product direction on that tradeoff, and the PR has focused test evidence but no inspectable after-fix live Gateway recovery proof yet.

## What This Changes

The PR adds Gateway-run recovery and cache-only idempotent replay after an uncertain CLI disconnect, making a fresh embedded rerun opt-in through `--rerun-on-ambiguous`.

## Best Possible Solution

After an owner confirms the fail-closed default, retain recovery at the Gateway run-owner boundary, document the changed CLI contract, and add a controlled live Gateway disconnect proof showing that recovery returns the original terminal result without admitting a second run.
