## Summary

Keep this issue open: current main still recursively evaluates nested availability expressions without cycle or depth protection, so the central hardening request is not implemented. The report overstates the demonstrated gateway and security impact because its quoted helper is outdated and it does not establish how a cyclic object reaches the planner, but the underlying evaluator failure is concrete enough for a focused P2 repair.

Make tool availability expression evaluation fail safely on cyclic or excessively nested descriptor trees instead of exhausting the JavaScript stack.

## Best Possible Solution

Validate availability trees at the shared descriptor-ingestion boundary and retain a defensive cycle/depth guard in evaluation, converting malformed expressions into unsupported-signal diagnostics while preserving all valid allOf, anyOf, and leaf semantics.
