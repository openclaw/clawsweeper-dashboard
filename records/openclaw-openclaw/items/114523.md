## Summary

This PR is still necessary: current main does not contain its Mattermost server-thread recovery path, and it remains the active candidate for the open restart/session-clear context-loss report. The design is bounded and the submitted live logs directly demonstrate restored context after both a gateway restart and a session reset, but the added awaited network operation and session-marker lifecycle warrant normal owner review before merge.

## What This Changes

The PR adds bounded Mattermost server-thread backfill before a cold threaded inbound turn builds agent context, with per-session markers, retry limits, concurrent-request sharing, and focused regression coverage.

## System Context

Mattermost receives an inbound post, derives a thread-specific history key, and builds a local history window into the agent prompt. When a restart or session reset leaves that window empty, this change retrieves the authoritative Mattermost thread and seeds the window before the agent turn is composed.
