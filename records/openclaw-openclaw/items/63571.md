## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Classify fallback failures before retrying:** `src/web-search/runtime.ts:405-410`
  - body: In explicit fallback mode, this catch path retries every thrown error when `allowFallback` is true. That can send auth, permission, bad-request, unsupported-filter, or deterministic provider-specific failures to later providers, while the canonical feature request only calls for recoverable runtime failures to retry. Add a failure classifier and tests that stop on terminal/auth/validation errors before sending the query elsewhere.
  - confidence: 0.87
- **[P2] Report unresolved fallback provider ids:** `src/web-search/runtime.ts:352-364`
  - body: Configured fallback ids are looked up in the loaded candidate set and missing entries are filtered out, so a typoed fallback looks configured while never running. Surface unresolved fallback ids through config validation, diagnostics, or the final fallback error instead of silently ignoring them.
  - confidence: 0.84
- **[P2] Document the fallback contract:** `src/config/types.tools.ts:490-491`
  - body: This adds the public `tools.web.search.fallbacks` config field without updating the web-search docs to define ordering, retryable versus terminal errors, unknown-provider handling, and privacy/cost implications. Config docs should land with the new field so operators can use it safely.
  - confidence: 0.82
