## Summary

Keep open: current main and v2026.6.11 still document and execute the 1Password `op read` exec-provider shape without disabling the 1Password CLI cache, while startup SecretRef failures still fail closed and can be retried by launchd.

## What This Changes

The issue reports that 1Password `op read` exec secret providers spawn cache-daemon processes on macOS Tahoe and hang unless `--cache=false` or equivalent cache disabling is used.

## Best Possible Solution

Document `--cache=false` or `OP_CACHE=false` in the 1Password SecretRef docs using the existing exec `args`/`env` surface, then separately decide whether generic runtime or plugin API behavior is needed.

## Reproduction Assessment

Partly: source inspection reproduces the current cache-enabled `op read` docs/runtime shape and startup fail-fast behavior, and the 1Password CLI cache contract matches the workaround. No live macOS Tahoe plus 1Password CLI run was performed.

## Solution Assessment

Unclear for runtime behavior: documenting `--cache=false` or `OP_CACHE=false` is the narrowest maintainable fix using existing config, while core auto-detection of `op` would be provider-specific policy that needs maintainer/security approval.
