## Summary

Keep open: current main and v2026.6.11 still document and execute the 1Password `op read` exec-provider shape without disabling the 1Password CLI cache, so the exact macOS LaunchAgent cache-daemon failure remains unresolved and still needs maintainer/security direction.

## What This Changes

The issue reports that 1Password `op read` exec SecretRef providers can spawn cache-daemon processes and hang on macOS Tahoe unless `--cache=false` or `OP_CACHE=false` is used.

## Best Possible Solution

Document `--cache=false` or `OP_CACHE=false` in the 1Password SecretRef docs using the existing exec `args`/`env` surface, then separately decide whether any generic runtime or plugin API behavior is needed.

## Reproduction Assessment

No live high-confidence reproduction was established: this environment cannot exercise macOS Tahoe TCC plus 1Password CLI daemon behavior. Source inspection does confirm current main and v2026.6.11 still use the cache-enabled docs/runtime shape that matches the report.

## Solution Assessment

Unclear for runtime auto-injection: documenting `--cache=false` or `OP_CACHE=false` is the narrowest maintainable fix using existing config, while core provider-specific behavior needs maintainer/security approval.
