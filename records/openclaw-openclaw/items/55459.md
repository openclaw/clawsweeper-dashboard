## Summary

Keep open: current main and v2026.6.11 still document and execute the 1Password `op read` exec-provider shape without disabling the 1Password CLI cache, and the exact macOS/TCC cache-daemon workaround is not owned by the broader restart-loop tracker.

## What This Changes

The issue requests a fix or documentation for 1Password CLI exec SecretRef providers on macOS LaunchAgent installs so `op` runs with cache disabled and avoids daemon-spawn hangs.

## Best Possible Solution

Document `--cache=false` or `OP_CACHE=false` in the 1Password SecretRef docs using the existing exec `args`/`env` surface, then separately decide whether any generic runtime or plugin API behavior is needed.

## Reproduction Assessment

Unclear as a live repro; yes at source level. Current main still documents and executes the cache-enabled `op read` shape, and the 1Password CLI cache contract matches the reported workaround, but no macOS Tahoe LaunchAgent run was performed.

## Solution Assessment

Unclear for runtime behavior. A docs change using existing `args` or `env` is the narrowest maintainable path, while core auto-detection of `op` is provider-specific policy that needs maintainer/security approval.
