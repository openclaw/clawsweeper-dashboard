## Summary

Keep open: current main and v2026.6.11 still document and execute the 1Password `op read` exec-provider shape without disabling the 1Password CLI cache. The existing exec `args`/`env` surface can express the workaround, but any automatic `op` detection or cache override in core needs maintainer/security direction.

## What This Changes

The issue asks OpenClaw to prevent or document 1Password CLI cache-daemon hangs for exec SecretRef providers on macOS Tahoe LaunchAgent setups.

## Best Possible Solution

Document `--cache=false` or `OP_CACHE=false` in the 1Password SecretRef docs using the existing exec provider surface, then separately decide whether any provider-specific runtime behavior belongs in core or a plugin integration.

## Reproduction Assessment

Partly: source inspection proves current main still uses the documented cache-enabled `op read` shape and fail-fast startup path. I have not live-reproduced macOS Tahoe plus 1Password CLI daemon behavior.

## Solution Assessment

Unclear for runtime behavior: documentation through existing `args` or `env` is the narrowest maintainable fix, while auto-detecting `op` or injecting `OP_CACHE=false` in core needs maintainer/security direction.
