## Summary

Keep open: current main and v2026.6.11 still document and execute the 1Password `op read` exec-provider shape without disabling the 1Password CLI cache, and the open related issues do not own this exact macOS/TCC cache-daemon workaround.

## What This Changes

The issue requests a fix or docs guidance for 1Password `op` exec SecretRef providers that spawn cache daemons and hang on macOS Tahoe unless cache is disabled.

## Best Possible Solution

Document `--cache=false` or `OP_CACHE=false` in the 1Password SecretRef docs using the existing exec `args`/`env` surface, then separately decide whether any generic runtime or plugin API behavior is needed.

## Reproduction Assessment

Partly: source and docs show the cache-enabled 1Password exec-provider shape, and official 1Password docs confirm the default cache behavior and disablement knob. No live macOS Tahoe plus 1Password CLI run was performed.

## Solution Assessment

Unclear for runtime behavior: documenting `--cache=false` or `OP_CACHE=false` is the narrowest maintainable fix using existing config, while core auto-detection of `op` would be provider-specific policy that needs maintainer/security approval.
