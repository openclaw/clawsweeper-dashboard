## Summary

Keep open: current main and v2026.6.11 still document and execute the 1Password `op read` exec-provider shape without disabling the 1Password CLI cache, so the exact macOS LaunchAgent cache-daemon hang is not implemented or superseded.

## What This Changes

This issue asks OpenClaw to prevent or document 1Password CLI cache daemon hangs when `op read` is used as an exec SecretRef provider under macOS LaunchAgent.

## Best Possible Solution

Document `--cache=false` or `OP_CACHE=false` in the 1Password SecretRef docs using the existing exec `args`/`env` surface, then only add runtime behavior if maintainers explicitly approve provider-specific credential policy.
