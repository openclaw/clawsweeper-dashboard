## Summary

Keep open: current main and v2026.6.11 still document and execute the 1Password `op read` exec-provider shape without disabling the 1Password CLI cache, so the exact macOS/TCC cache-daemon workaround remains unresolved.

## What This Changes

The issue asks OpenClaw to prevent or document 1Password `op` exec-provider cache daemon hangs on macOS Tahoe, especially by using `--cache=false` or `OP_CACHE=false`.

## Best Possible Solution

Document `--cache=false` or `OP_CACHE=false` in the 1Password SecretRef docs using the existing exec `args` or `env` surface, then separately decide whether any generic runtime or plugin API behavior is needed.

## Reproduction Assessment

Partly: source inspection confirms the current docs/runtime path still runs `op read` without cache disablement, but no live macOS Tahoe plus 1Password CLI reproduction was performed.

## Solution Assessment

Unclear for runtime behavior: documenting `--cache=false` or `OP_CACHE=false` is the narrowest maintainable fix using existing config, while core auto-detection of `op` would be provider-specific policy that needs maintainer/security approval.
