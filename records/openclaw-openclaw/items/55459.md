## Summary

Keep open: current main and v2026.6.11 still document and execute the 1Password `op read` exec-provider shape without disabling the 1Password CLI cache, while the exact cache-daemon/TCC workaround is not owned by the broader restart-loop tracker.

## What This Changes

The issue reports that 1Password `op` used as an exec SecretRef provider can spawn cache daemon processes and hang under macOS LaunchAgent/TCC conditions unless `--cache=false` or `OP_CACHE=false` is used.

## Best Possible Solution

Add clear 1Password SecretRef docs for `--cache=false` or `OP_CACHE=false` using the existing exec `args`/`env` surface, and only change runtime/plugin behavior after an explicit maintainer security decision.

## Reproduction Assessment

No live high-confidence macOS Tahoe reproduction was run. Source inspection verifies the current docs/runtime still use cache-enabled `op read`, and official 1Password docs confirm the cache daemon is default-enabled on UNIX-like systems unless disabled.

## Solution Assessment

Unclear for runtime behavior: documenting `--cache=false` or `OP_CACHE=false` is the narrowest maintainable fix using existing config, while core auto-detection or a new argument surface is a product/security decision.
