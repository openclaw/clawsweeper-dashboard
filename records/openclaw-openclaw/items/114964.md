## Summary

Keep this issue open. The report identifies a narrow, deterministic Doctor migration failure: an alias-less legacy provider key can be copied into a stricter canonical allowlist and prevent the entire repair run from being written. The supplied trace is strong, but current `main` at `9dbfeb7e61a66bf63b62b5ca2db81cbf2550ff12` could not be independently read in this restricted review environment, so an implemented-on-main close is not justified.

## What This Changes

Doctor should migrate legacy `agents.defaults.models` entries without copying alias-less bare provider keys into `agents.defaults.modelPolicy.allow`, where they are invalid.

## System Context

Doctor restores or reads OpenClaw configuration, applies legacy-shape migrations, and then writes the canonical config after validation. This migration feeds the default agent model policy, which determines the model references that runtime routing may use.
