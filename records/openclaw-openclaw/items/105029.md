## Summary

The PR correctly fixes gateway-requested session deletion, agent deletion, and alias canonicalization, but it does not cover production code that deletes session entries directly through the shared lifecycle helper. The credential can therefore remain valid until TTL after some successful deletions, so the patch needs one focused follow-up before merge.

## What This Changes

The PR canonicalizes attach grants to resolved logical session keys and revokes matching grants after gateway session or agent deletion.

## Best Possible Solution

Route post-commit grant revocation through a gateway/runtime-owned session-deletion seam shared by RPC deletion and background cleanup, or explicitly revoke after every production deletion caller, with coverage proving unrelated grants and reset/archive behavior remain unchanged.
