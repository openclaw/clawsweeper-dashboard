## Summary

This PR remains useful and has strong Windows runtime proof, but the current head still permits its four-second adapter fallback to report completion while an indefinitely pending `taskkill` prevents the direct-root kill. The previously reported P1 blocker therefore remains unresolved.

Likely related people: @IWhatsskill introduced the cancellation lifecycle, @steipete contributed to and merged that work, and @vincentkoc recently carried the affected files through a source-layout refactor.

## What This Changes

The PR makes Windows deadline cancellations request an immediate tree-aware hard kill, exposes `taskkill` completion, and delays forced stream settlement until that completion while preserving normal output draining.

## Best Possible Solution

Keep tree traversal ahead of direct-root termination, but give taskkill completion an owner-level deadline and guarantee the direct-root kill before the adapter wait can report completion, with a no-error/no-close regression.
