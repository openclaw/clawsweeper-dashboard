## Summary

The revised head fixes the earlier ordinary-output truncation concern, but one blocking lifecycle race remains: the adapter can report completion before Windows has confirmed termination of the full descendant process tree.

## What This Changes

The PR makes Windows overall and no-output deadlines request immediate tree-aware hard kill, then adds a hard-kill-only 250 ms fallback for child stream settlement.

## Best Possible Solution

Keep immediate hard kill for Windows deadlines and hard-kill-only stream settlement, but have the process-tree owner expose completion so the adapter resolves only after taskkill finishes or a clearly bounded fallback expires.
