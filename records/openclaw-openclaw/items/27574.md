## Summary

Keep open: current main and the latest release still lack a Dashboard or Control UI browser preview route, sidebar entry, page module, or live preview consumer. The related browser handoff issue and plugin UI entry-point PR are useful overlaps, and the FSB comment is helpful design context, but none replaces the requested secured live browser preview surface.

## What This Changes

Add a live Dashboard browser preview panel showing the managed browser's current view, URL/title, console errors, and optional user control for remote troubleshooting.

## Best Possible Solution

Design a secured, admin-scoped, read-only-first browser preview surface that reuses browser.request/browser-control primitives, gates write actions explicitly, and defines redaction, retention, and plugin-vs-core ownership before implementation.

- **Wait for plugin UI entry points:** Defer the browser panel until the generic plugin UI entry-point contract lands, then implement the browser surface as plugin-owned UI under that contract.
- **Defer the feature:** Keep the current CLI/RPC screenshot workflow and pause live preview until remote-browser visibility becomes a prioritized product area.
