## Summary

Keep open: current main and v2026.6.11 still expose browser-control primitives but no live Browser Preview Panel in the Dashboard/Control UI, and the related open items only cover narrower login handoff, generic plugin UI entry points, or chat/canvas visualization.

## What This Changes

Request to add a live Dashboard browser preview panel showing the managed browser view, URL/title, console errors, and optional manual controls for remote/VPS users.

## Best Possible Solution

Design an admin-scoped, read-only-first browser preview surface that reuses browser.request/browser-control primitives, gates write actions explicitly, and coordinates with the browser handoff and plugin UI entry-point work.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 have no Control UI browser route, tab, or live preview renderer while browser-control primitives exist. This is a missing feature rather than a runtime bug needing live reproduction.

## Solution Assessment

Unclear as proposed: a live panel is useful, but the best implementation needs maintainer decisions on admin scope, read-only defaults, write-action gates, redaction/retention, and hardcoded core UI versus a plugin contribution surface.
