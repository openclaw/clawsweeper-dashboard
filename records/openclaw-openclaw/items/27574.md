## Summary

Keep open: current main and v2026.6.11 still lack the requested live browser preview panel in the Control UI; related work is open and narrower or infrastructure-only, so this remains a product/security design item.

## What This Changes

The issue requests a Dashboard/Control UI panel that lets remote users watch the managed browser live, see URL/title and console errors, and optionally interact with the page.

## Best Possible Solution

Design and ship a secured, admin-scoped, read-only-first browser preview surface that reuses browser.request/browser-control primitives, gates write actions explicitly, and coordinates with the browser handoff and plugin UI entry-point work.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 have browser-control primitives but no Control UI browser route, tab, render branch, or live preview consumer. This is a missing feature rather than a runtime bug needing live reproduction.

## Solution Assessment

Unclear as proposed: a live panel is useful, but the best implementation needs maintainer decisions on admin scope, read-only defaults, write-action gates, redaction, retention, and hardcoded core UI versus plugin contribution surface.
