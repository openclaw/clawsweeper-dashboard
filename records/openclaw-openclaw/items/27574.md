## Summary

Keep open: current main and the latest release still have browser-control primitives, but no live Browser Preview Panel in the Dashboard/Control UI; the related open items cover narrower browser handoff or generic plugin UI entry points rather than replacing this tracker.

## What This Changes

Request a live Dashboard/Control UI browser preview panel for remote users that shows browser screenshots, URL/title, console errors, and possibly gated interactions.

## Best Possible Solution

Design an admin-scoped, read-only-first browser preview surface that reuses browser.request/browser-control primitives, gates write actions explicitly, and coordinates with the browser handoff and plugin UI entry-point work.

Yes, source-level: current main and v2026.6.11 have no Control UI browser route, tab, or live preview renderer while browser-control primitives exist. This is a missing feature rather than a runtime bug needing live reproduction.

## Solution Assessment

Unclear as proposed: a live panel is useful, but the best implementation needs maintainer decisions on admin scope, read-only defaults, write-action gates, redaction/retention, and hardcoded core UI versus a plugin contribution surface.
