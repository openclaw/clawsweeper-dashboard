## Summary

Keep open: current main has browser-control RPC/CLI primitives and generic plugin-tab plumbing, but it still has no browser-specific live Dashboard/Control UI preview panel. The FSB reference and the modular-dashboard/widget work are useful design context, but they only partially overlap the requested browser preview and do not replace the needed security/ownership decision.

## What This Changes

The issue requests a live Dashboard/Control UI panel that shows the managed browser view, URL/title, console errors, and optional manual interaction for remote browser troubleshooting.

## Best Possible Solution

Design a secured, admin-scoped, read-only-first browser preview surface that reuses browser.request/browser-control primitives, adds explicit gates for write actions, and coordinates with the browser handoff and plugin-tab/dashboard tracks.
