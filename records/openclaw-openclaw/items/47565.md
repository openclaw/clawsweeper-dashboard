## Summary

Keep open. Current main and the latest release still hardcode the relevant Control UI CSP and Permissions-Policy behavior; same-origin microphone and a few built-in CSP origins are fixed, but the requested configurable browser security-header surface remains missing and needs maintainer security/product direction.

## What This Changes

Requests configurable Control UI CSP and Permissions-Policy headers so custom Control UI roots can allow browser permissions and local connection origins without patching installed files.

## Best Possible Solution

Keep hardened defaults and, if maintainers approve the direction, add a narrow typed Control UI header policy with directive validation, docs, audit visibility, and focused HTTP/header tests; prefer same-origin plugin/gateway routes for local APIs where they fit.
