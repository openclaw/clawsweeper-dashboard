## Summary

Keep open. Current main partially covers the microphone example by allowing same-origin microphone access, but it still hardcodes the Control UI CSP, frame policy, and Permissions-Policy, so the requested configurable security-header policy remains a real security-sensitive product/config decision.

## What This Changes

Request configurable Control UI Permissions-Policy and CSP settings so custom `gateway.controlUi.root` builds can allow trusted browser permissions and local connection origins without patching installed bundles.

## Best Possible Solution

Add a maintainer-approved, narrow, typed Control UI header-policy config with hardened defaults, strict directive/source validation, generated schema metadata, public docs, and focused CSP/Permissions-Policy HTTP tests; document same-origin plugin routes as the safer answer where they fit.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at source level: current main hardcodes the relevant response headers and the strict config schema has no accepted fields for the requested policy overrides.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainers choose the security contract; a narrow typed policy surface or same-origin plugin route guidance is safer than broad raw header overrides.
