## Summary

Keep open. Current main and the latest release still only provide fixed Control UI security headers: same-origin microphone is now allowed and a few CSP origins are hardcoded, but the requested configurable CSP and Permissions-Policy surface is still absent and remains a security-sensitive product/config decision.

## What This Changes

The issue asks for configurable Control UI Permissions-Policy and CSP headers so custom Control UI deployments can permit microphone access and local cross-origin fetches without patching built files.

## Best Possible Solution

Keep hardened defaults; if maintainers approve this direction, add a typed, directive-limited Control UI header policy with strict validation, generated schema/help/docs, and focused tests, or document the supported plugin/proxy alternative.
