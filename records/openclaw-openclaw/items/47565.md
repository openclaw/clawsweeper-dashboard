## Summary

Keep open. Current main and v2026.6.11 partially address the reported pain with same-origin microphone access and fixed CSP allowlist entries, but there is still no supported configurable Control UI CSP or Permissions-Policy surface; the remaining work needs maintainer security/product direction.

## What This Changes

The issue requests configurable Control UI Permissions-Policy and CSP settings so custom Control UI roots can allow microphone access and local API connections without patching installed dist files.

## Best Possible Solution

Keep hardened defaults and, if maintainers approve the direction, add a narrow typed Control UI header policy with directive validation, docs, schema/help updates, audit guidance, and focused HTTP/header tests.

Owner confidence: high

Options:

- **Approve Narrow Typed Policy (recommended):** Add directive-limited config under gateway.controlUi with strict validation and tests while preserving hardened defaults.
- **Prefer Same-Origin Extension Route:** Decline general header overrides and steer local API integrations toward plugin or Gateway routes that avoid weakening browser policy.
- **Keep Fixed Allowlists:** Reject configurability for now and continue adding narrowly justified built-in allowlist entries only for core-owned Control UI features.

## Reproduction Assessment

Yes, at source level: current main hardcodes the relevant headers and the strict config schema lacks the requested policy fields. This is a reproducible missing feature/config surface rather than a broken existing-behavior bug.

## Solution Assessment

Unclear until maintainers choose the security contract. A raw header override is not the best shape; a narrow directive-limited policy or same-origin plugin/Gateway route guidance is safer.
