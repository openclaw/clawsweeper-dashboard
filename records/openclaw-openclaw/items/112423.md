## Summary

Keep this issue open. It has a detailed, repeated built-Gateway reproduction of an archive-materialization stall, and the directly linked open PR is an explicitly bounded first-phase repair rather than a completed resolution of memory pressure and final synchronous reclamation. Likely related people: jalehman is the recent archive-lifecycle contributor; HermanZeng authored the active implementation candidate.

## What This Changes

Prevent large SQLite session-transcript archival during cleanup from monopolizing the Gateway event loop while retaining the existing durable archive-before-delete behavior.

## System Context

SQLite session lifecycle cleanup archives transcript generations before deleting their database rows. The archive path runs during Gateway session deletion, reset, orphan cleanup, and eviction, so long CPU or filesystem work delays other Gateway RPC and liveness activity.
