Likely related people: jalehman is a high-confidence recent contributor to the archive lifecycle path; HermanZeng is the linked implementation candidate author.

## What This Changes

Prevent large SQLite transcript archival during session cleanup from materializing, compressing, publishing, and verifying archives on the gateway event loop.

## System Context

SQLite session maintenance archives a transcript before it deletes associated session rows, preserving durability if cleanup fails. That archive work currently sits on a gateway-owned path, so synchronous transcript processing can delay liveness and other gateway events.

## Architecture Diagram

flowchart LR
  A[Session cleanup request] --> B[SQLite lifecycle planner]
  B --> C[Transcript archive materialization]
  C --> D[Compress and durably publish archive]
  D --> E[Revalidate transcript snapshot]
  E --> F[Delete session and transcript rows]
  C --> G[Gateway event loop]
  G --> H[Liveness and client events]
