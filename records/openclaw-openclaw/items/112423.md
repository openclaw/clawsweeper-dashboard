## What This Changes

Prevent large SQLite session-transcript archives from blocking gateway event-loop work during cleanup while preserving archive-before-delete durability.

## System Context

SQLite session cleanup archives a transcript before deleting its session rows. The gateway invokes this lifecycle path, so synchronous transcript materialization, compression, and durable file publication can delay unrelated gateway requests before the final SQLite cleanup transaction runs.

## Architecture Diagram

  C --> D[Durable archive publication]
  D --> E[Snapshot revalidation]
  E --> F[SQLite row reclamation]
  C --> G[Gateway event loop]
  B --> G

Review and land the bounded Worker-based archive-materialization repair in https://github.com/openclaw/openclaw/pull/112424 if its durability and upgrade behavior are accepted, then use this issue to track measured memory-bounding and final-reclamation follow-up work.
