## Summary

Keep this issue open: current main still builds the active user prompt with inbound metadata and strips that metadata only after the same turn becomes historical, while https://github.com/openclaw/openclaw/pull/100272 is the open linked implementation candidate rather than a merged fix.

## What This Changes

The issue asks OpenClaw to make active user-turn inbound metadata byte-stable with historical replay so provider prompt-cache prefixes do not mutate on every turn.

## Best Possible Solution

Review and either land or reject https://github.com/openclaw/openclaw/pull/100272; if that PR is rejected, the replacement should still keep user turns byte-stable without dropping current-turn sender/reply context.
