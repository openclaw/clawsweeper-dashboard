## What This Changes

The issue asks for subagent session completion to trigger session-memory output in the subagent workspace.

## Best Possible Solution

Define one canonical completed-child-session lifecycle contract, then wire session-memory through that path with focused tests for transcript lookup, workspace resolution, and duplicate-write prevention.

## Reproduction Assessment

Yes, at source level: the bundled session-memory handler and manifest accept only command:new and command:reset, while subagent completion uses a separate plugin lifecycle hook path. I did not run a live filesystem reproduction in this read-only review.

## Solution Assessment

Unclear as a product/API direction: directly handling subagent_ended in session-memory is plausible, but the maintainable fix should settle the session/subagent lifecycle contract first.
