## Summary

Keep open: current main and the latest release still register and run bundled session-memory only for command:new/reset, while completed subagents emit separate typed plugin lifecycle events, so the remaining work needs a maintainer lifecycle-contract decision.

## What This Changes

The issue requests that session-memory save memory files for completed subagent sessions, not only manual /new or /reset resets.

## Best Possible Solution

Define one canonical completed-child-session lifecycle contract, then wire session-memory through that path with focused tests for transcript lookup, workspace resolution, and duplicate-write prevention.

## Reproduction Assessment

Yes, at source level: session-memory accepts only command:new and command:reset, while completed subagents emit subagent_ended through the plugin lifecycle path. I did not run a live filesystem reproduction in this read-only review.

## Solution Assessment

Unclear. Directly special-casing subagent_ended in session-memory is plausible, but the maintainable fix should first settle the session/subagent lifecycle contract instead of adding a parallel one-off completion path.
