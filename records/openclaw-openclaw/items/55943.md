## Summary

Keep open. Current main and v2026.6.11 still scope bundled session-memory to command resets, while completed subagents emit a separate lifecycle hook, so this remains the canonical tracker for a maintainer lifecycle-contract decision.

## What This Changes

The issue asks for completed subagent sessions to trigger session-memory persistence into the subagent workspace memory files.

## Best Possible Solution

Define one canonical completed-child-session lifecycle contract, then wire session-memory through that path with tests for transcript lookup, workspace resolution, and duplicate-write prevention.

Question: Which lifecycle contract should bundled session-memory use for completed subagent sessions: direct subagent_ended handling, a generic internal session-end hook, or typed plugin session_end?

Rationale: Current main exposes multiple adjacent lifecycle surfaces, and a one-off handler branch could create duplicate or incompatible session-memory behavior without a maintainer-owned contract.

Likely owner: vincentkoc

Owner reason: This is primarily a hooks/plugin lifecycle contract decision, and recent session-memory plus related hook review history points here most strongly.

Owner confidence: medium

Options:

- **Use a generic session-end contract (recommended):** Make completed subagent sessions produce the same durable session-end semantics used by other session finalization paths, then have session-memory consume that contract.
- **Handle subagent_ended in session-memory:** Add a narrow bundled-hook path for subagent completion, accepting that session-memory owns subagent transcript and workspace resolution details directly.
- **Defer bundled behavior:** Leave session-memory scoped to command resets and direct users to external plugins for subagent completion memory until the broader plugin lifecycle design lands.

Yes at source level: the handler rejects non-command events and subagents emit subagent_ended, so the requested path has no current trigger. I did not run a live subagent session in this read-only review.
