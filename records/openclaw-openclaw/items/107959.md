## Summary

Keep this PR open for a narrow repair: bounding a malformed cursor loop is useful, but the current implementation silently treats a still-paginated Slack collection as complete after 50 pages, which can regress legitimate large workspaces.

## What This Changes

The PR hard-caps the shared Slack user/channel cursor collector at 50 pages and adds unit tests for normal pagination and the cap.

## Best Possible Solution

Preserve complete traversal for advancing Slack cursors, detect repeated or non-advancing cursors promptly, and make any retained emergency page-budget exhaustion an explicit error rather than returning partial data as complete.
