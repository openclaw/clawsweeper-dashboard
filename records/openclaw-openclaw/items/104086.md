- `P2`: This is a focused Windows shell-discovery bug with a limited platform-specific blast radius and a bounded repair.
- `merge-risk: 🚨 compatibility`: The shared resolver can newly select batch-file shells that existing child and PTY execution modes handle differently.

## Summary

Keep this PR open for a narrow repair: resolving `pwsh.exe` addresses a real Windows discovery gap, but returning `.cmd` or `.bat` creates inconsistent behavior because child execution wraps batch commands while PTY execution directly spawns the selected shell. Real Windows after-fix proof is also still required before merge.

## What This Changes

The PR extends Windows PATH shell discovery to probe `.exe`, `.cmd`, and `.bat` variants and adds Windows-specific regression tests.

## Best Possible Solution

Resolve `pwsh.exe` narrowly for automatic PowerShell discovery; retain `.cmd` or `.bat` support only if child and PTY execution are first unified behind the same trusted Windows batch-command invocation contract.
