## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Persist routes on the thread session entry:** `extensions/mattermost/src/mattermost/monitor.ts:1393`
  - body: Once this block runs for non-DM Mattermost turns, it still writes through `route.mainSessionKey` instead of the active thread `sessionKey`. A cron for thread A can then fall back to a shared route entry last updated by thread B and post into the wrong thread.
  - confidence: 0.88
- **[P1] Avoid redirecting main-session deliveries into public threads:** `extensions/mattermost/src/mattermost/monitor.ts:1383-1399`
  - body: Broadening this write updates the shared main-session route for channel/thread traffic, not only the thread-scoped session that needs recovery. Later main-session heartbeat or wake deliveries can inherit that public Mattermost thread as the last route, changing existing delivery behavior.
  - confidence: 0.82
- **[P2] Do not claim heartbeat routing is fixed here:** `extensions/mattermost/src/mattermost/monitor.ts:1384-1386`
  - body: The added comment frames heartbeat wakeups as fixed by saving `threadId`, but heartbeat target resolution intentionally drops session-derived thread IDs unless an explicit turn source supplies one. This patch is at most a partial cron route-persistence prerequisite.
  - confidence: 0.9
