## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Persist routes on the thread session entry:** `extensions/mattermost/src/mattermost/monitor.ts:1380-1386`
  - body: Removing the guard writes the Mattermost route through the resolved last-route key instead of proving the active thread session entry is updated. Multiple threads can overwrite the same shared route and make a later cron wake inherit another thread's `threadId`.
  - confidence: 0.88
- **[P1] Avoid redirecting main-session deliveries into threads:** `extensions/mattermost/src/mattermost/monitor.ts:1380-1386`
  - body: Broadening this write changes shared Mattermost route state for channel/thread traffic, not only the thread-scoped session that needs recovery. A later main-session delivery can reuse that public thread route and post somewhere the user did not target.
  - confidence: 0.82
- **[P2] Do not claim heartbeat routing is fixed here:** `extensions/mattermost/src/mattermost/monitor.ts:1381-1384`
  - body: The added comment frames heartbeat wakeups as fixed by saving `threadId`, but heartbeat-mode target resolution intentionally drops session-derived thread IDs unless the turn source supplies one. This patch is at most a partial cron route-persistence prerequisite.
  - confidence: 0.9
