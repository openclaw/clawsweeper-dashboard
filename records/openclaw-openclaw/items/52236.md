## What This Changes

The PR removes the Mattermost `kind === "direct"` guard around last-route persistence and stores `effectiveReplyToId` as `deliveryContext.threadId`.

  - body: The new non-direct path still writes `deliveryContext.threadId` to `route.mainSessionKey`, while the active inbound context can be a thread-scoped session key.   - confidence: 0.88
- **[P1] Keep main-session deliveries from inheriting public threads:** `extensions/mattermost/src/mattermost/monitor.ts:1393-1398`
  - body: Persisting every Mattermost thread's `effectiveReplyToId` onto the shared main session changes fallback delivery for later main-session cron or heartbeat runs. A later untargeted run can reuse the last public thread instead of the user's prior main route, which is a user-visible message-routing regression.
  - confidence: 0.84

This PR is at most a cron-route prerequisite unless the heartbeat path is changed too.
  - confidence: 0.9
