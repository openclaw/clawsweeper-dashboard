Full review comments:

- **[P1] Persist routes on the thread session entry:** `extensions/mattermost/src/mattermost/monitor.ts:1391-1399`
  - body: Once this block runs for non-DM Mattermost turns, it still writes to `route.mainSessionKey` rather than the active thread session. Cron delivery looks up the targeted thread session before falling back to main, so different threads can inherit whichever `threadId` was most recently written to the shared entry and reply in the wrong thread.
  - confidence: 0.88
- **[P1] Avoid redirecting main-session deliveries into public threads:** `extensions/mattermost/src/mattermost/monitor.ts:1391-1399`
  - body: Broadening this write updates shared route context for channel/thread traffic, not only the thread-scoped session that needs cron recovery. Later main-session heartbeat or wake deliveries can reuse that public Mattermost thread as the last route, changing existing delivery behavior for users whose main session previously resolved elsewhere.
  - confidence: 0.82
- **[P2] Do not claim heartbeat routing is fixed here:** `extensions/mattermost/src/mattermost/monitor.ts:1383-1386`
  - body: The new comment frames heartbeat wakeups as fixed by saving `threadId`, but heartbeat-mode target resolution intentionally drops session-derived thread IDs unless an explicit turn source supplies one. This patch is at most a partial cron route-persistence prerequisite unless the heartbeat path is changed too.
  - confidence: 0.9
