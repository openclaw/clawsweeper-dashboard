  - body: This new all-session route update still writes through `route.mainSessionKey`, so a thread-scoped Mattermost inbound turn can update shared main-session delivery context instead of the active thread session. Later cron or heartbeat delivery can then read stale or unrelated thread state.
  - confidence: 0.88
- **[P1] Avoid redirecting main-session deliveries into public threads:** `extensions/mattermost/src/mattermost/monitor.ts:1394-1399`
  - body: Adding `threadId: effectiveReplyToId` to the shared persisted route means non-thread main-session deliveries can inherit a public channel thread as the last route. That changes existing delivery behavior for users whose main session previously resolved elsewhere.
  - confidence: 0.82
- **[P2] Do not claim heartbeat routing is fixed here:** `extensions/mattermost/src/mattermost/monitor.ts:1384-1386`
  - body: The added comment says cron and heartbeat wakeups are fixed by saving `threadId`, but current heartbeat resolution intentionally ignores inherited session thread ids unless the turn source explicitly supplies one. This patch is at most a partial cron route-persistence prerequisite.
