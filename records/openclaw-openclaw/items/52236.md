## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Persist routes on the thread session entry:** `extensions/mattermost/src/mattermost/monitor.ts:1380-1386`
  - body: Once this block runs for non-DM Mattermost turns, it still writes through the shared last-route session key instead of the active thread `sessionKey`. A cron for thread A can then inherit thread B's most recent stored `threadId` from that shared entry and post into the wrong thread.
  - confidence: 0.88
- **[P1] Avoid redirecting main-session deliveries into public threads:** `extensions/mattermost/src/mattermost/monitor.ts:1380-1386`
  - body: Broadening this write updates shared route context for channel/thread traffic, not only the thread-scoped session that needs recovery. Later main-session heartbeat or wake deliveries can reuse that public Mattermost thread as the last route, changing existing delivery behavior.
  - confidence: 0.82
- **[P2] Do not claim heartbeat routing is fixed here:** `extensions/mattermost/src/mattermost/monitor.ts:1381-1384`
  - body: The added comment frames heartbeat wakeups as fixed by saving `threadId`, but heartbeat-mode target resolution intentionally guards against inherited session thread IDs unless the turn source supplies one. This is at most a partial route-persistence prerequisite.
  - confidence: 0.9
