Full review comments:

- **[P1] Persist routes on the thread session entry:** `extensions/mattermost/src/mattermost/monitor.ts:1393`
  - body: Once non-direct turns enter this block, the write still targets `route.mainSessionKey` rather than the active thread `sessionKey`. Multiple Mattermost threads can therefore share one stored `threadId`, and later cron delivery for one thread can inherit another thread's route.
  - confidence: 0.88
- **[P1] Avoid redirecting main-session deliveries into public threads:** `extensions/mattermost/src/mattermost/monitor.ts:1391-1399`
  - body: Broadening this last-route write updates shared main-session route context for channel traffic, not only the thread-scoped session that needs recovery. A later main-session heartbeat or wake can then reuse the public Mattermost thread as the last route.
  - confidence: 0.82
- **[P2] Do not claim heartbeat routing is fixed here:** `extensions/mattermost/src/mattermost/monitor.ts:1384-1386`
  - body: The added comment frames heartbeat wakeups as fixed by saving `threadId`, but heartbeat-mode target resolution intentionally drops session-derived thread IDs unless an explicit turn source supplies one. This is at most a partial cron prerequisite.
  - confidence: 0.9
