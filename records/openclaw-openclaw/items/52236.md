## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Persist routes on the thread session entry:** `extensions/mattermost/src/mattermost/monitor.ts:1380-1386`
  - body: Once this block runs for non-DM Mattermost turns, it still writes through the last-route session key derived from the base route rather than the active thread session. Cron delivery can check the targeted thread session before shared fallbacks, so multiple Mattermost threads can inherit the wrong stored `threadId` and post to the wrong thread.
  - confidence: 0.88
- **[P1] Keep main-session deliveries from inheriting public threads:** `extensions/mattermost/src/mattermost/monitor.ts:1380-1386`
  - body: Removing the guard updates shared route context for channel/thread traffic, not only the thread-scoped session that needs cron recovery. Later main-session heartbeat or wake deliveries can then reuse a public Mattermost thread as the last route, changing delivery behavior for existing users.
  - confidence: 0.82
- **[P2] Do not claim heartbeat routing is fixed here:** `extensions/mattermost/src/mattermost/monitor.ts:1381-1384`
  - body: The added comment frames heartbeat wakeups as fixed by saving `threadId`, but heartbeat-mode target resolution intentionally drops session-derived thread IDs unless the turn source supplies one. This patch is at most a partial cron route-persistence prerequisite unless the heartbeat path changes too.
  - confidence: 0.9
