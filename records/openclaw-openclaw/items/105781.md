## Summary

Keep open for normal maintainer merge review: the patch addresses a source-reproducible persistence race without a discrete correctness or security finding, and the submitted Chromium/relay proof plus focused coverage support the changed behavior. The remaining concern is the intentional compatibility shift for Control UI users who previously received immediate persistence from Import.

## What This Changes

The PR makes Control UI Nostr profile imports cancellable drafts, prevents stale responses from replacing newer form state, and retains explicit server-side auto-merge for other callers.

## Best Possible Solution

Land the draft-only Control UI workflow while retaining explicit autoMerge support for non-UI callers and keeping Save & Publish as the sole visible persistence action.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. On current main, delay a Control UI import requested with autoMerge enabled, cancel the profile form, then release the response; the endpoint can still persist the merge after the form closes.

## Solution Assessment

Yes. Opting only the Control UI into the endpoint's existing draft mode, preserving explicit auto-merge callers, and rejecting aborted or stale responses is narrower and safer than adding compensating writes or server-side rollback behavior.
