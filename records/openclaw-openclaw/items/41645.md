## Summary

Keep open: current main and the latest release still expose usage by session, agent, provider, model, channel, and date, but not by a stable per-user accounting subject with authorized per-user views. This is a real feature request, but it needs maintainer product and security-boundary decisions before implementation.

## What This Changes

Request per-user token usage accounting with input/output/total tokens, day/week/month windows, and visibility through `/usage` or the Dashboard.

## Best Possible Solution

Define one core accounting-subject and viewer-authorization contract first, then extend usage RPCs, Dashboard, and any `/usage` view from that contract; quota enforcement should build on the same model later.
