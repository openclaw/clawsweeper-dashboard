## Summary

Keep open: current main has session, agent, channel, provider, model, and date usage reporting, but it still lacks a canonical per-user accounting subject and an authorized per-user usage view. This remains a feature plus security/product decision, not an implemented cleanup item.

## What This Changes

The issue requests per-user token accounting with input/output/total tokens, day/week/month aggregation, and visibility through `/usage` or the Dashboard.

## Best Possible Solution

Define a stable usage principal, retention/export semantics, and authorization boundary first, then extend the existing session/gateway usage pipeline and Dashboard or command surfaces without logging raw personal identifiers by default.

## Risks / Open Questions

- A per-user usage view could expose sensitive billing, model, channel, or session metadata unless the accounting subject and viewer authorization rules are designed first.

- A one-off log-only implementation would create another accounting source of truth beside the existing session and gateway usage summaries.
