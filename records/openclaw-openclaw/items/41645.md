## Summary

Keep open: current main has session, agent, channel, model, provider, date-range, `/usage`, and Dashboard usage surfaces, but it still lacks first-class per-user token accounting or quota/billing boundaries. This remains a product and security design item rather than a narrow bug fix.

## What This Changes

The issue requests per-user input/output/total token accounting with day/week/month reporting visible through `/usage` or the Dashboard for multi-user billing and quota management.

## Best Possible Solution

Define a privacy-safe usage-accounting contract for stable authorized user identity, SQLite-backed aggregates, retention/redaction, `/usage` and Dashboard behavior; if that boundary is not wanted in core, keep per-user billing in a plugin or external observability layer.
