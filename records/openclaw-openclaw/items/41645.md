## Summary

Keep open: current main and the latest release still expose usage by session, agent, provider, model, channel, and date, but not by a stable per-user accounting subject with authorized per-user views. This is a valid feature request, but implementation needs maintainer product and security-boundary decisions first.

## What This Changes

Request per-user input/output/total token accounting with daily, weekly, and monthly views in `/usage` or the Dashboard.

## Best Possible Solution

Define one core accounting-subject and viewer-authorization contract first, then extend usage RPCs, Dashboard, and any `/usage` view from that contract; quota enforcement should build on the same model later.
