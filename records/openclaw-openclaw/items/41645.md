## Summary

Keep open: current main and v2026.6.11 still expose session, agent, channel, model, provider, and date-range usage views, but not first-class user-bucketed token accounting. The remaining work is an identity, storage, authorization, Dashboard, and quota/billing product decision rather than conservative cleanup.

## What This Changes

The issue requests per-user token usage accounting with input/output/total token totals, day/week/month aggregation, and visibility through `/usage` or Dashboard.

## Best Possible Solution

Define a canonical user/principal attribution and authorization model first, then extend usage storage, Gateway RPC, Dashboard, and `/usage` surfaces to expose per-user totals without treating session keys as auth.
