## Summary

Keep open: current main and v2026.6.11 still expose usage by session, provider, model, agent, channel, and date, but not by a stable per-user accounting subject with authorized per-user views. This remains a useful feature request that needs product and security-boundary decisions before implementation.

## What This Changes

The issue requests per-user token usage accounting with input/output/total token totals, day/week/month windows, and `/usage` or Dashboard visibility.

## Best Possible Solution

Define one core accounting-subject and viewer-authorization contract first, then extend usage RPCs, Dashboard, and any `/usage` view from that contract; quota or budget enforcement should build on the same model later.
