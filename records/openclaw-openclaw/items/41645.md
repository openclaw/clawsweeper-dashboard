## Summary

Keep open: current main has session/provider/agent/channel/day usage reporting, provider quota snapshots, and `/usage` footers, but it does not implement the requested per-user token accounting or user-scoped day/week/month reports. This is useful, but it needs a maintainer product and security decision before implementation because it would persist identifiable usage and billing data.

## What This Changes

Request per-user token usage accounting with input/output/total tokens, day/week/month summaries, and `/usage` or Dashboard visibility.

## Best Possible Solution

Keep this open for a maintainer-sponsored design that either defines a privacy-reviewed SQLite-backed usage ledger and Dashboard/API reports, or adds the plugin/API hooks needed for an external accounting plugin.
