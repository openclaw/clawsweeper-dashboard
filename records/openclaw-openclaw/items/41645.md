## Summary

Keep open: current main has session, agent, channel, model, provider, date-range, and Dashboard usage surfaces, but no stable per-user token accounting or quota/billing boundary. The remaining work is a new security-sensitive product surface, not conservative cleanup.

## What This Changes

Request per-user input/output/total token accounting with day/week/month reporting through `/usage` or the Dashboard.

## Best Possible Solution

Define a privacy-safe usage-accounting contract for stable authorized user identity, SQLite-backed aggregates, `/usage` and Dashboard views, and retention/redaction rules; if that boundary is not wanted in core, keep per-user billing in a plugin or external observability layer.
