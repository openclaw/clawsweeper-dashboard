## Summary

Current main has token and cost usage reporting by session, model, provider, agent, and channel, but not by user; billing/quota-oriented user accounting needs a product and security boundary decision before implementation.

## What This Changes

Request per-user input/output/total token accounting with daily, weekly, and monthly aggregation visible through `/usage` or the Control UI dashboard.

## Best Possible Solution

Define the supported identity/accounting boundary first, then extend the existing session usage pipeline and dashboard only if maintainers choose core support for user-linked billing or quota reporting.
