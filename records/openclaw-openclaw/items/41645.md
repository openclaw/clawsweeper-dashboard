## Summary

Keep open: current main has session, agent, channel, provider, model, and date usage reporting, but it still lacks a canonical per-user accounting subject and viewer authorization model. This remains a real feature/product-security decision rather than an implemented or stale issue.

## What This Changes

The issue requests per-user input/output/total token usage statistics, date-range reporting, and visibility through `/usage` or the Dashboard for billing and quota management.

## Best Possible Solution

Define a core accounting-subject contract and permission model first, then expose that subject consistently through the usage RPCs, Dashboard, and any `/usage` surfaces; optional alerts or exports can build on the same contract later.
