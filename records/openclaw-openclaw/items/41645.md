## Summary

Keep open: current main has session, agent, channel, model, provider, date-range, and dashboard usage surfaces, but no per-user token accounting or quota/billing boundary; adding that needs product and security design before implementation.

## What This Changes

Add per-user input/output/total token usage statistics by day/week/month and expose them through `/usage` or the Dashboard.

## Best Possible Solution

Define a privacy-safe core usage-accounting contract for stable authorized user identity, SQLite-backed aggregates, `/usage` and Dashboard views, and documented retention/redaction; if that boundary is not wanted in core, keep per-user billing in a plugin or external observability layer.
