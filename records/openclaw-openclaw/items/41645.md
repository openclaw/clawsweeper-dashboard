## Summary

Keep open: current main and v2026.6.11 have session, agent, channel, model, provider, token-type, and date-range usage surfaces, but not first-class user-bucketed token accounting. The remaining work is a product and security design decision rather than conservative cleanup.

## What This Changes

Request per-user input/output/total token accounting with daily, weekly, and monthly views in `/usage` or Dashboard.

## Best Possible Solution

Define a canonical identity-attribution, authorization, retention, and redaction model first, then extend usage storage, Gateway RPC, Dashboard, and `/usage` surfaces to expose per-user totals against that principal.
