## Summary

Keep open: current main and v2026.6.11 still expose usage by session, provider, model, agent, channel, and date, but not by a stable per-user accounting subject with authorized per-user views. The request remains useful, but it needs product and security-boundary decisions before implementation.

## What This Changes

Requested per-user input/output/total token usage statistics with daily, weekly, and monthly views available through `/usage` or the Dashboard.

## Best Possible Solution

Define one core accounting-subject and viewer-authorization contract first, then extend usage RPCs, Dashboard, and any `/usage` surface from that contract; quota or budget enforcement should build on the same model later.
