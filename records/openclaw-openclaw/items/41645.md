## Summary

Keep open: current main still reports usage by session, agent, channel, model, provider, and date range, but does not provide first-class user-bucketed token accounting. The remaining work is a product and security design question around identity attribution, authorization, retention, and multi-user Gateway behavior, not a conservative cleanup close.

## What This Changes

Request per-user input, output, and total token usage accounting with daily, weekly, and monthly views in `/usage` or the Dashboard.

## Best Possible Solution

Define a canonical user/principal attribution model first, then extend usage storage, Gateway RPC, Dashboard, and `/usage` to expose authorized per-user totals.
