## Summary

Keep open: current main and v2026.6.11 still provide session, agent, channel, provider, model, and date usage reporting, but not a canonical per-user accounting dimension or authorized per-user usage view. This remains a feature with product and security-boundary decisions before implementation.

## What This Changes

The issue requests token usage reporting grouped by user, with input/output/total tokens, daily/weekly/monthly windows, and access through `/usage` or the Dashboard.

## Best Possible Solution

Define one core accounting-subject and viewer-authorization contract first, then expose that subject consistently through usage RPCs, Dashboard, and any `/usage` views; quota or budget enforcement should build on the same contract later.
