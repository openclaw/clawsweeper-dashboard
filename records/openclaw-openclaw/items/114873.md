## Label Justifications

## Summary

Current main already accepts JSON/JSON5 values for `openclaw config set`; a valid array literal is parsed as an array, while malformed JSON5 falls back to a raw string unless `--strict-json` is used. The reported command contains doubled quotes inside the array value, so it is not the supported array literal.

## What This Changes

The issue requests that `openclaw config set` parse JSON array input into array-valued configuration fields instead of storing it as a string.

## System Context

The configuration CLI turns a path and terminal value into a validated `openclaw.json` update. It accepts structured JSON/JSON5 values or plain strings, then writes only values that pass the configuration schema.

## Best Possible Solution

Keep the existing JSON/JSON5 parsing contract and use a valid JSON array, preferably with `--strict-json`, so malformed shell input fails immediately instead of becoming a raw string.
