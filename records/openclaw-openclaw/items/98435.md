## Summary

Keep open: current main still has the same credible recovery gap where restart recovery can count a resumed main session without proving that the Claude CLI-side MCP loopback client reloaded the new gateway loopback endpoint. ## What This Changes

The issue reports that a recovered Claude CLI main session keeps transcript state after a gateway restart but loses usable OpenClaw MCP tool transport until manual `/mcp` reconnect.

## Best Possible Solution

Preserve Claude CLI conversation reuse while adding an explicit bundle-MCP reconnect/reload signal or downgrading recovery status until post-restart MCP tool readiness is proven.

## Reproduction Assessment

Yes at source/field-report level, but not with a live destructive replay. Current source can report recovered sessions from restart recovery while the CLI MCP bridge and stable resume hash are handled in a separate path that does not prove the external client reloaded the new loopback endpoint.

## Solution Assessment

Unclear: the suggested supervisor/reconnect approach is plausible, but maintainers need to choose the boundary that preserves Claude CLI memory without accepting stale MCP transport state or unsafe tool replay.
