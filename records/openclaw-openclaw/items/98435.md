## Label Justifications

- `P1`: The reported behavior can strand active or recovered Claude CLI sessions without their MCP tools until a human or a later process spawn restores the endpoint.
- `impact:session-state`: Gateway restart recovery can restore session content while leaving the session’s associated MCP capability stale or unavailable.

## Summary

Keep open: a live, source-backed candidate fix is still open at https://github.com/openclaw/openclaw/pull/110251 and explicitly targets the shared-loopback teardown that can leave CLI sessions tool-less. Its narrow repair does not yet settle whether restart recovery must verify MCP reachability before reporting a session as recovered.

## What This Changes

Repair Claude CLI sessions that retain an MCP configuration for a loopback endpoint after that endpoint is torn down or recreated, so MCP tools do not remain unavailable while the gateway and session otherwise appear healthy.

## System Context

The Claude CLI runner writes a per-run MCP configuration pointing at the gateway’s local loopback MCP server. Gateway lifecycle and run cleanup then affect whether that shared endpoint remains reachable by live or recovered CLI sessions, while restart recovery reports the session outcome to users.

## Architecture Diagram

flowchart LR
  A[Gateway and CLI run] --> B[Prepare MCP configuration]
  B --> C[Shared loopback MCP server]
  C --> D[Claude CLI tool calls]
  E[Run cleanup or gateway restart] --> C
  E --> F[Session recovery]
  F --> G[Recovery status]
  C --> D

## Best Possible Solution

Land the scoped lifecycle repair in https://github.com/openclaw/openclaw/pull/110251 after exact-head validation, then define whether restart recovery must verify MCP reachability or visibly report partial recovery when capability has not been restored.
