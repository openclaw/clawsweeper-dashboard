## What This Changes

The issue asks OpenClaw to stop intermittent Slack duplicate posts from cron `--announce` jobs and avoid false cron failure notices when the recipient already received the final report.

## Best Possible Solution

Use the existing generic durable-final reconciliation contract for strict single-payload cron announces when the target channel supports it, and preserve delivery status/failure-alert semantics with regression coverage for the Slack ambiguous-send path.
