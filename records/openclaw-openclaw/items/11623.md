## Summary

Current main still does not provide persistent per-agent macOS bubbles, and no other viable issue or PR owns that deliverable. This remains a product decision because it introduces a new native interaction model spanning window behavior, canonical activity state, persistence, and chat routing.

## What This Changes

Add native macOS floating bubbles for running agents, with agent names, persistent placement, follow or anchor behavior, and selected-agent chat access.

## Best Possible Solution

If approved, implement bubbles as a macOS projection of canonical session-keyed activity, persist only app-owned UI placement, and route chat through the existing WebChat session model rather than introducing a parallel JSON state source.
