## Summary

Keep this issue open for a maintainer product decision. The supplied current-code review evidence shows adjacent macOS HUD and chat surfaces, not the requested per-agent floating-overlay model with persisted placement and selected-agent chat routing; no canonical implementation PR is linked.

## What This Changes

Add a native macOS experience that presents each running agent as a draggable floating bubble with quick chat access and optional follow/anchor behavior.

## System Context

The macOS client consumes agent activity and session-selection state to present native status and chat UI. This request would add a new always-on-top interaction layer that turns per-agent activity into independently positioned desktop controls and routes a selected bubble into chat.

## Architecture Diagram

flowchart LR

  B --> C[Per-agent bubble controller]
  C --> D[Persisted positions and interaction mode]
  C --> E[Native always-on-top overlays]
  E --> F[Selected-agent chat launch]
  F --> G[WebChat session routing]

## Best Possible Solution

Decide whether per-agent desktop overlays belong in the native macOS product; if so, design a single native state, persistence, accessibility, and selected-agent routing contract before implementation.
