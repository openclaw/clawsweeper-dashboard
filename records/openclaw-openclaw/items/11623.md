## Summary

Current main still lacks per-agent floating macOS bubbles, and no merged or open canonical replacement owns that interaction. The request aligns with companion-app priorities but needs an explicit product decision because it introduces persistent windowing, accessibility behavior, position state, and agent/session routing.

## What This Changes

Add one native floating macOS bubble per running agent with status/name display, drag and anchor or mouse-follow behavior, persisted placement, and click-to-chat routing.

## Best Possible Solution

Specify a first-party native macOS design that derives bubble identity and activity from canonical gateway/session contracts, stores placement through the app's canonical persistent-state owner rather than a JSON sidecar, provides accessible drag/anchor controls and reduced-motion behavior, and routes chat using the selected agent's canonical session identity.
