## Summary

Keep open: current main has adjacent macOS HoverHUD, WebChat, Canvas, session-menu, and activity surfaces, but not configurable always-on-top per-agent bubbles with persisted placement, drag/anchor or mouse-follow behavior, and click-to-selected-agent chat routing.

## What This Changes

The issue requests native macOS floating per-agent bubbles that show each running agent, persist positions, support drag/follow/anchor interactions, and open chat for the selected agent.

## Best Possible Solution

Define a maintainer-approved macOS bubble/window coordinator or native UI plugin API that derives state from canonical agent/session activity, persists placement through an approved state owner, and routes chat to the selected agent/session.

## Reproduction Assessment

Not applicable as a bug: this is a new macOS capability request, not a failing existing behavior. Source inspection and targeted searches give high confidence that the requested floating-bubble surface is absent on current main.

## Solution Assessment

Unclear until maintainers choose the product direction. Native SwiftUI/AppKit is plausible, but persistence, click-through/accessibility behavior, running-agent state, and chat routing need a maintainer-designed contract rather than an autonomous patch.
