## Summary

Keep open: current main still lacks configurable per-agent floating macOS bubbles. The adjacent HoverHUD, WebChat, Canvas, and activity surfaces are menu-bar anchored or single-session and do not cover persisted bubble placement, mouse-follow or anchor behavior, or click-to-selected-agent chat routing.

## What This Changes

Request to add native macOS floating per-agent bubbles that show running agents, support drag/anchor or mouse-follow behavior, persist placement, and open chat to the selected agent.

## Best Possible Solution

Define a maintainer-approved macOS bubble/window coordinator, or a native UI plugin API, that derives state from canonical agent/session activity, persists placement through an approved owner, supports accessible click-through and drag behavior, and routes chat to the selected agent/session.

## Reproduction Assessment

Not applicable as a bug: this is a new macOS capability request, not a failing existing behavior. Source inspection and targeted searches give high confidence that the requested floating-bubble surface is absent on current main.

## Solution Assessment

Unclear until maintainers choose the product direction. Native SwiftUI/AppKit is plausible, but persistence ownership, click-through/accessibility behavior, running-agent state, and chat routing need a maintainer-designed contract rather than an autonomous patch.
