## Summary

Keep open: current main and the latest release still have adjacent macOS menu-bar, HoverHUD, WebChat, Canvas, and activity surfaces, but not configurable per-agent floating desktop bubbles with persisted placement, drag/anchor or mouse-follow behavior, and click-to-selected-agent chat routing.

## What This Changes

Request a native macOS floating bubble UI that shows each running agent, persists placement, supports drag/anchor/mouse-follow behavior, and opens chat for the selected agent.

## Best Possible Solution

Define a maintainer-approved macOS bubble/window coordinator, or a native UI plugin API, that derives state from canonical agent/session activity, persists placement through an approved state owner, and routes chat to the selected agent/session.

## Reproduction Assessment

Not applicable as a bug: this is a new macOS capability request, not a failing existing behavior. Source inspection and targeted searches give high confidence that the requested floating-bubble surface is absent on current main.

## Solution Assessment

Unclear until maintainers choose the product direction. Native SwiftUI/AppKit is plausible, but persistence, click-through/accessibility behavior, running-agent state, and chat routing need a maintainer-designed contract rather than an autonomous patch.
