## Summary

The requested floating per-agent macOS interaction remains absent on current main, and no related issue or PR has become a canonical implementation. This should stay open for an explicit product decision because it adds a persistent native window model and agent-routing UX rather than repairing established behavior.

## What This Changes

Add configurable always-on-top macOS bubbles for running agents, with names, positioning, mouse-follow or anchoring, and direct per-agent chat access.

## Best Possible Solution

If maintainers want this interaction in core, build an optional native macOS bubble controller from canonical gateway agent/session activity, persist only user placement and preferences through the app’s canonical state owner, and reuse explicit WebChat session routing; otherwise define a supported native UI/window extension seam before moving it outside core.
