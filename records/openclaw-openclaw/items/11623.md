## Summary

Keep open: the requested per-agent floating macOS overlay remains a distinct product capability, not an established bug or a completed implementation. Current adjacent macOS chat surfaces support a single anchored chat panel and session targeting, but do not establish persisted multi-bubble placement, drag/follow controls, or an adopted overlay ownership boundary. Likely related people: steipete is the strongest routing candidate from recent macOS UI history; Nachx639 and ImLukeF are adjacent native chat-routing contributors.

## What This Changes

Add native macOS floating bubbles for running agents, with per-agent naming and placement controls plus click-through routing into that agent’s chat session.

## System Context

The macOS app converts gateway and agent-session activity into native status and chat surfaces. This request would add a new always-on-top overlay layer that consumes agent activity, persists per-agent presentation state, and launches chat for the selected agent.

## Architecture Diagram

  C --> D[Per-agent floating bubbles]

  F --> G[Native chat session routing]

## Best Possible Solution

A macOS owner should either adopt a native overlay design with explicit agent-state, persistence, accessibility, and selected-session routing contracts, or first define a supported native overlay extension seam so the feature can ship outside the core app.
