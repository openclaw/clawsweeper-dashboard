## Summary

Keep open: current main still has adjacent macOS HoverHUD, WebChat, Canvas, Talk, menu, and session/activity surfaces, but it does not implement configurable per-agent floating desktop bubbles with persisted placement, mouse-follow or anchor behavior, and click-to-selected-agent chat routing.

## What This Changes

The issue requests native macOS floating per-agent desktop bubbles with click-to-chat, drag/anchor or mouse-follow behavior, and persisted placement.

## Best Possible Solution

Define a maintainer-approved macOS bubble/window coordinator, or a native UI plugin API, that derives state from canonical agent/session activity, persists placement through an approved state owner, supports accessible click-through and drag behavior, and routes chat to the selected agent/session.

## Reproduction Assessment

Not applicable as a bug: this is a new macOS capability request, not a failing existing behavior. Source inspection and targeted searches give high confidence that the requested floating-bubble surface is absent on current main.

## Solution Assessment

Unclear until maintainers choose the product direction. Native SwiftUI/AppKit is plausible, but persistence, click-through/accessibility behavior, running-agent state, and chat routing need a maintainer-designed contract rather than an autonomous patch.
