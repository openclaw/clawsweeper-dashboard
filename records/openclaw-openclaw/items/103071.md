## Summary

Keep open for normal PR review: current main leaves fal generated-image asset downloads without a request timeout, and this patch applies the same 30s guarded HTTP bound used by fal video downloads. I found no blocking correctness or security issue, but the new hard timeout is a small compatibility tradeoff for very slow downloads.

## What This Changes

The PR adds a 30s `fetchWithSsrFGuard` timeout to fal generated-image asset downloads and updates the fal image-generation test helper to expect it.

## Best Possible Solution

Land the narrow fal image-download timeout after exact-head checks, keeping SSRF policy and media byte caps unchanged; if maintainers want longer slow-network behavior, make that an explicit provider/media timeout decision rather than leaving downloads unbounded.
