## Summary

This PR supplies a focused, source-aligned fix for a real `web_fetch` cache-identity bug. The exact User-Agent used for the request was absent from the current cache key, while the PR scopes cache reuse by a SHA-256 fingerprint and includes direct regression and live-run evidence; keep it open for ordinary exact-head CI and merge review.

## What This Changes

Adds the effective `tools.web.fetch.userAgent` fingerprint to the `web_fetch` cache key and tests that two configured User-Agents do not share a cached response.

## Best Possible Solution

Merge the narrow cache-key fix after rebasing onto current `main` and completing the required checks, retaining the regression test as the contract for configuration-dependent response caching.

Yes. Current main has a clear two-call path: fetch one URL with a positive cache TTL and User-Agent A, then repeat it with User-Agent B; the pre-patch cache key omits the header and returns A's cached result.

## Solution Assessment
