## Summary

The PR remains necessary: current main deterministically misclassifies scoped pnpm and Bun package roots containing `npm-shrinkwrap.json`, while the exact two-file patch fixes that ownership lookup without introducing a competing path or compatibility surface. The implementation, focused tests, and redacted Windows pnpm output support a clean functional verdict; remaining failed or pending checks should be attributed on the exact head before merge rather than treated as a code finding.

## What This Changes

The PR resolves scoped `node_modules/@scope/name` ownership for pnpm and Bun, recognizes pnpm global-layout markers, follows linked package roots for metadata, and adds focused regression coverage.

## Best Possible Solution

Keep the single detector path, derive scoped and unscoped direct `node_modules` ownership consistently, require concrete pnpm or Bun layout evidence before overriding npm shrinkwrap, and merge the exact reviewed head once required checks are green or proven unrelated.

## Reproduction Assessment

Yes. On current main, a scoped package under `node_modules/@scope/name` cannot satisfy the immediate-parent ownership checks, so a shipped `npm-shrinkwrap.json` deterministically yields npm even in pnpm or Bun layouts.

## Solution Assessment

Yes. Sharing a direct `node_modules` root resolver across pnpm and Bun is the narrowest fix, and the additional pnpm marker and linked-root handling address the demonstrated global layout without adding config or a parallel detector.
