## Summary

This member-authored PR remains necessary and is technically sound: current main does not contain the lifecycle hardening, the implementation follows the database-first ownership model, and no discrete correctness or security defect was found. It should remain open for explicit owner acceptance of the compatibility-sensitive fail-closed plugin SQLite backup behavior and normal exact-head landing gates.

## What This Changes

The PR adds serialized SQLite schema mutations, stale-transcript rewrite protection, busy-checkpoint reporting, incremental-vacuum defaults and indexes, compact state snapshots with strict verification, and an offline shared-state doctor compaction command.

## Best Possible Solution

Keep one canonical database-first lifecycle: serialize schema ownership, reject stale destructive rewrites, use bounded runtime vacuuming, reserve full compaction for explicit offline doctor maintenance, and require compact verifiable state snapshots without a raw-page privacy fallback; merge after the owner explicitly accepts that plugin backup compatibility tradeoff.
