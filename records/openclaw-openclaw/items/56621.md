## Summary

Keep open: current main and the latest release still expose `openclaw pairing list` as pending-only plus `pairing approve`; the lower-level store helpers and in-chat `/allowlist` surface only partially cover the requested terminal admin workflow.

## What This Changes

Request to add terminal commands for listing approved paired senders, revoking a paired sender, and showing merged config plus pairing-store allowlists in channel status.

## Best Possible Solution

Define one account-scoped admin pairing/contact management surface that coordinates terminal CLI behavior with `/allowlist`, channel status, and the broader contact inventory, with explicit redaction and authorization semantics.

## Reproduction Assessment

Yes, at source level. Current `registerPairingCli` exposes pending-list and approve commands, while approved-list and revoke remain unregistered.

## Solution Assessment

Unclear until maintainers choose the product and security boundary. The proposed commands are plausible, but the best shape should avoid a second partial permission-management surface beside `/allowlist` and the broader inventory issue.
