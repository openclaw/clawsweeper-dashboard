## Summary

Keep open: current main and v2026.6.11 still lack terminal commands to list approved pairings or revoke a paired sender, while the existing store helpers and in-chat `/allowlist` only partially cover the requested admin workflow. This remains a security-sensitive product decision because it exposes and mutates sender authorization state.

## What This Changes

Request CLI/admin support to list approved channel pairings, revoke a paired sender, and show merged config plus pairing-store allowlists in channel status.

## Best Possible Solution

Define one account-scoped admin pairing/contact management surface that coordinates terminal CLI behavior with `/allowlist`, channel status, and https://github.com/openclaw/openclaw/issues/48620, with explicit redaction, authorization, and metadata semantics.

## Reproduction Assessment

Yes, at source level. Current `openclaw pairing list` lists pending requests and `pairing approve` writes approved senders, while no terminal command lists or revokes approved pairings.

## Solution Assessment

Unclear until maintainers choose the product and security boundary. The proposed commands are plausible, but the best shape should avoid a second partial permission-management surface beside `/allowlist` and the broader contact inventory issue.
