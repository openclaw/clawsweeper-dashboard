## Summary

This PR addresses a currently open, reproducible gateway-responsiveness bug and is neither obsolete nor superseded. Its worker-based extraction preserves the archive-before-delete design, but it changes the persistence-sensitive session cleanup path and should receive a refreshed three-way review and focused lifecycle proof before merge.

## What This Changes

The branch moves whole-buffer SQLite transcript archive creation into a Worker so session deletion, reset, cleanup, and eviction do not block unrelated Gateway event-loop work during large archive reads, compression, publication, and verification.

## System Context

SQLite-backed session lifecycle operations archive transcript generations before reclaiming session and transcript rows. The Gateway invokes these lifecycle paths during deletion, reset, cleanup, and retention work; the proposed Worker performs the expensive read and archive publication while the parent revalidates the snapshot before final deletion.

## Architecture Diagram

flowchart LR
  A[Gateway session lifecycle request] --> B[Build delete and archive plan]
  B --> C[Archive Worker reads SQLite snapshot]
  C --> D[Durable transcript archive publication]
  D --> E[Parent revalidates live session state]
  E --> F[Delete transcript and session rows]
  E --> G[Keep lifecycle state on mismatch or failure]

## Best Possible Solution

Land a refreshed Worker-based archive path only after focused proof confirms that packaged Gateway cleanup remains responsive while snapshot mismatches or archive failures preserve all SQLite lifecycle state; keep streaming extraction and chunked row reclamation as separately measured follow-up work under https://github.com/openclaw/openclaw/issues/112423.
