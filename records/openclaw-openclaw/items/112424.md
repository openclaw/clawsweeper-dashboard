## What This Changes

Moves whole-buffer SQLite transcript archive creation into a dedicated worker thread, then revalidates the planned session snapshot before deleting archived lifecycle rows so large cleanup jobs do not monopolize the gateway event loop.

## System Context

SQLite session lifecycle cleanup must durably archive a transcript before reclaiming its transcript, search-index, and related lifecycle rows. The gateway plans deletion, the worker reads the exact physical SQLite database and publishes the archive, and the parent performs the authoritative final-state check before deletion.

  D --> E[Durable transcript archive]
  E --> F[Final parent snapshot fence]
  F --> G[Lifecycle and transcript reclamation]
