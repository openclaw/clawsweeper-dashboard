## Summary

This PR remains necessary: the linked session-cleanup bug is still open, and the Worker-based archive path is not merged into current main. The branch has strong supplied live Gateway/CLI evidence and no discrete correctness defect found in this review cycle, but it changes the archive-before-delete lifecycle boundary and should receive owner review after the current-head packaging and cross-platform checks complete.

## What This Changes

Moves whole-buffer SQLite transcript archive materialization into a dedicated Worker, then revalidates the planned session snapshot before the parent process deletes lifecycle rows.

## System Context

SQLite-backed session deletion, reset, cleanup, and eviction must archive a transcript before reclaiming its rows. This PR shifts the expensive archive read, serialization, compression, publication, and readback off the Gateway event loop while the parent retains the final SQLite deletion decision.

## Architecture Diagram

  B --> C[Read-only archive Worker]
  C --> D[Durable transcript archive]
  D --> E[Parent revalidates live state]
  E --> F[SQLite and FTS row reclamation]
  F --> G[Gateway remains available for other work]

## Best Possible Solution

Land the Worker implementation only after the current-head build, Windows, and SQLite session-flip lanes confirm that the built sidecar loads correctly and that archive publication still precedes every successful deletion; retain the linked issue for streaming and shorter final reclamation work.
