## Summary

Keep open: current main and the latest release define session lifecycle plus reset/compact controls, but cache-ttl pruning remains tool-result-only and there is still no explicit prune-context/session-boundary API for the requested behavior.

## What This Changes

Requested explicit session-boundary documentation, wall-clock TTL context pruning, and user-triggered session prune/reset controls.

## Best Possible Solution

Maintainers should choose one core contract: either document that TTL only governs tool-result prompt-cache pruning and point users to reset/compact controls, or design an authorized session-prune API plus retention/summarization semantics with tests.

## Reproduction Assessment

Yes for the source-level gap: current main only prunes tool-result messages during context assembly and exposes reset/compact RPCs, not a prune-context API or conversation-history TTL expiry. I did not run a live timed session because this cleanup review is read-only and the code/docs contract is clear.

## Solution Assessment

Unclear: the proposed endpoints are plausible, but the best fix depends on a maintainer decision about whether TTL should prune normal history or remain a prompt-cache/tool-result optimization. A docs-only clarification may be the right outcome if maintainers do not want conversation-history expiry.
