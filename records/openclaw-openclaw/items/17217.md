## Summary

Keep open: current main and v2026.6.11 cover session lifecycle, reset, and compaction controls, but `cache-ttl` pruning is still request-time, context-size-gated, and tool-result-only, with no explicit prune-context API or approved conversation-history TTL semantics.

## What This Changes

The issue requests explicit session boundaries, TTL-based context pruning during long sessions, and user/API controls for pruning or resetting session state.

## Best Possible Solution

Keep this open for maintainer design: either confirm the current tool-result-only TTL semantics and document the supported reset/compact controls, or design an admin-scoped session/context pruning API with protocol, gateway, runtime, docs, and regression coverage.
