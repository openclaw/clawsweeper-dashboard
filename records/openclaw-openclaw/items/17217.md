## Summary

Keep open: current main and the latest release define session reset and compaction controls, but cache-TTL pruning remains request-time, threshold-gated, and tool-result-only, with no explicit prune-context session API or maintainer-approved conversation-history TTL semantics.

## What This Changes

Requested explicit session boundary documentation, immediate TTL-based context pruning, manual mid-session pruning, and reset/session-control APIs for long-running sessions.

## Best Possible Solution

Define one canonical session/context contract that separates tool-result pruning, conversation compaction, manual reset, TTL or rolling retention, authorization, persistence, recovery, and docs before adding transport endpoints.
