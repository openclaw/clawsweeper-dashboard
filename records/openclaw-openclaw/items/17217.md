## Summary

Keep open: current main documents session lifecycle and exposes reset/compact controls, but `contextPruning` remains request-time, in-memory, and tool-result-only, with no manual prune-context API or TTL expiry for normal conversation history. The related open issues cover narrower slices, so none safely replaces this broader session-boundary, retention, and security decision.

## What This Changes

The issue requests explicit session lifecycle semantics, immediate TTL-based pruning of old context, and manual/API controls to prune or reset sessions without restarting OpenClaw.

## Best Possible Solution

Define one canonical session/context contract that separates tool-result pruning, conversation compaction, manual reset, TTL or rolling retention, and authorized API controls, then update code, docs, and tests consistently.

## Reproduction Assessment

Yes, at source level: current main has reset and compaction controls, but no prune-context method and no wall-clock TTL expiry for normal conversation history. Cache-TTL pruning is request-time, in-memory, and tool-result-only by source and docs.

## Solution Assessment

No, not as ad hoc POST endpoints yet. The maintainable path is a maintainer-approved typed session/context contract with authorization, persistence, summarization, recovery, and docs before transport adapters are added.
