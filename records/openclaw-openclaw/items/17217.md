## Summary

Keep open: current main defines session lifecycle and reset/compact controls, but the central request remains unresolved because cache-TTL pruning is still request-time, in-memory, and tool-result-only, with no explicit prune-context API or conversation-history TTL contract.

## What This Changes

The issue requests explicit session boundaries, wall-clock TTL pruning for conversation context, and manual/API controls to prune or reset session context.

## Best Possible Solution

Define one canonical session/context contract that separates reset, compaction, tool-result pruning, conversation-history retention, manual pruning, and authorized API controls, then update implementation and docs consistently.

## Reproduction Assessment

Yes, at source level. Current main has reset and compaction controls, but no prune-context method and no wall-clock conversation-history TTL expiry; cache-TTL pruning is tool-result-only by source and docs.

## Solution Assessment

No, not as standalone POST endpoints yet. The maintainable path is a maintainer-approved typed session/context contract with authorization, persistence, summarization, recovery, and docs before transport adapters are added.
