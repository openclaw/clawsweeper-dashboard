## Summary

Keep open: current main and the latest release still define reset and compaction controls, but cache-TTL pruning remains request-time, threshold-gated, and tool-result-only, with no explicit prune-context API or maintainer-approved conversation-history TTL semantics.

## What This Changes

The issue asks OpenClaw to define session boundaries, make TTL pruning affect active-session context, and add explicit controls for pruning or resetting a session.

## Best Possible Solution

Define one canonical session/context contract that separates tool-result pruning, conversation compaction, manual reset, TTL or rolling retention, authorization, persistence, recovery, and docs before adding transport endpoints.
