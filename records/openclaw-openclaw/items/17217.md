## Summary

Keep open: current main and v2026.6.11 still define session lifecycle plus reset/compact controls, but cache-TTL pruning remains request-time, in-memory, and tool-result-only, with no explicit prune-context API or conversation-history TTL contract.

## What This Changes

The issue requests explicit session-boundary docs, wall-clock TTL pruning during active sessions, and manual prune/reset controls.

## Best Possible Solution

Define one canonical session/context contract that separates tool-result pruning, conversation compaction, manual reset, TTL or rolling retention, and authorized API controls, then align code, docs, and tests consistently.

## Reproduction Assessment

Yes, at source level. Current main has reset and compaction controls, but no prune-context method and no wall-clock conversation-history TTL expiry; cache-TTL pruning is tool-result-only by source and docs.

## Solution Assessment

No, not as standalone POST endpoints yet. The maintainable path is a maintainer-approved typed session/context contract with authorization, persistence, summarization, recovery, and docs before transport adapters are added.
