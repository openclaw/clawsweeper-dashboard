## Summary

Keep open: current main and v2026.6.11 still cover session lifecycle and reset/compact controls only partially, while wall-clock conversation-history TTL, explicit prune-context API semantics, and the broader session-boundary contract remain unresolved product/security work.

## What This Changes

The issue asks OpenClaw to define session boundaries, make TTL pruning expire context during active sessions, and expose manual session/context reset or prune controls.

## Best Possible Solution

Define one canonical session/context contract that separates tool-result pruning, conversation compaction, manual reset, TTL or rolling retention, and authorized API controls, then update code and docs consistently.

## Reproduction Assessment

Yes, at source level: current main has reset and compaction controls, but no prune-context method and no wall-clock conversation-history TTL expiry; cache-TTL pruning is tool-result-only by source and docs.

## Solution Assessment

No, not as standalone POST endpoints yet. The maintainable path is a maintainer-approved typed session/context contract with authorization, persistence, summarization, recovery, and docs before adding transport-specific controls.
