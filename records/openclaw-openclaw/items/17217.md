## Summary

Keep open: current main and v2026.6.11 define session reset/compaction controls, but cache-TTL pruning is still request-time, threshold-gated, and tool-result-only, with no explicit prune-context API or maintainer-approved conversation-history TTL semantics.

## What This Changes

Request to define session boundaries, make TTL pruning affect aged context during active sessions, and add manual prune/reset controls.

## Best Possible Solution

Define one canonical session/context contract that separates tool-result pruning, conversation compaction, manual reset, TTL or rolling retention, authorization, persistence, recovery, and docs before adding transport endpoints.
