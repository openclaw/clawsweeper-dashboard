## Summary

Keep open: current main defines session reset and compaction controls, but cache-TTL pruning is still in-memory, threshold-gated, tool-result-only, and the broader conversation-history TTL/prune-context API remains a product and security decision.

## What This Changes

The issue requests explicit session boundary documentation plus TTL-based conversation pruning, manual prune/reset controls, and API endpoints for session/context management.

## Best Possible Solution

Define one canonical session/context contract that separates tool-result pruning, conversation compaction, manual reset, TTL or rolling retention, authorization, persistence, recovery, and docs before adding transport endpoints or changing TTL semantics.
