## Summary

Keep open: current main still defines cache-TTL pruning as request-time, in-memory, and tool-result-only; reset and compact controls exist, but the requested conversation-history TTL behavior and explicit prune-context/session-boundary API remain product work.

## What This Changes

Requested explicit session-boundary documentation, immediate TTL-based context pruning, and manual controls for pruning or resetting session context without restarting OpenClaw.

## Best Possible Solution

Define one canonical session/context retention contract that separates tool-result pruning, conversation compaction, manual reset, TTL or rolling retention, and authorized API controls, then update code and docs consistently.

## Reproduction Assessment

Yes, at source level: current main has reset and compaction controls, but no prune-context method and no wall-clock conversation-history TTL expiry; cache-TTL pruning is tool-result-only by source and docs.

## Solution Assessment

No, not as standalone POST endpoints yet; the maintainable path is a maintainer-approved typed session/context contract with authorization, persistence, summarization, recovery, and docs before adding transport adapters.
