## Summary

Keep open: current main and the latest release still document reset and compaction controls, but cache-TTL pruning remains request-time, threshold-gated, and tool-result-only, with no explicit prune-context API or approved conversation-history TTL semantics.

## What This Changes

The issue requests explicit session boundary documentation plus TTL-based mid-session context pruning/reset controls, including proposed session prune and reset HTTP endpoints.

## Best Possible Solution

Define one canonical session/context contract that separates tool-result pruning, conversation compaction, manual reset, TTL or rolling retention, authorization, persistence, recovery, and docs before adding transport endpoints.
