## Summary

Keep open: current main defines session lifecycle plus reset and compaction controls, but `contextPruning.ttl` still means in-memory, threshold-gated, tool-result-only pruning; changing it to expire normal conversation history or adding a prune-context API remains a product and security decision.

## What This Changes

The issue requests explicit session-boundary docs plus immediate TTL-based context pruning and manual prune/reset controls for long-running sessions.

## Best Possible Solution

Define one canonical session/context retention contract that separates tool-result pruning, conversation compaction, manual reset, TTL or rolling retention, authorization, persistence, recovery, and docs before adding transport endpoints or changing TTL semantics.
