## Summary

Keep open: current main documents session lifecycle and provides reset/compact controls, but TTL pruning is still request-time, cache-TTL-gated, and tool-result-only; there is no authorized prune-context or conversation-history TTL API for the broader request.

## What This Changes

The issue requests explicit session boundary semantics, immediate TTL-based context pruning, manual prune/reset controls, and session lifecycle documentation.

## Best Possible Solution

Define one canonical session/context contract that separates tool-result pruning, conversation compaction, manual reset, TTL or rolling retention, and authorized API controls, then update code, docs, and tests consistently.
