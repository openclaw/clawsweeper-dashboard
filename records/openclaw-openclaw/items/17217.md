## Summary

Keep open: current main documents session lifecycle and exposes reset/compact controls, but it still does not provide immediate TTL pruning for normal conversation history or a manual prune-context API. The related open issues cover narrower slices, so none safely replaces this broader session-boundary and retention-policy decision.

## What This Changes

The issue requests explicit session-boundary documentation, immediate TTL-based context pruning, and user/API controls to prune or reset sessions without restarting OpenClaw.

## Best Possible Solution

Define one canonical session/context contract that separates tool-result pruning, conversation compaction, manual reset, TTL or rolling retention, and authorized API controls, then update code, docs, and tests consistently.

## Reproduction Assessment

Yes, at source level: current main has reset and compaction controls, but no prune-context method and no wall-clock conversation-history TTL expiry. Cache-TTL pruning is request-time and tool-result-only by source and docs.

## Solution Assessment

No, not as standalone POST endpoints yet; the maintainable path is a maintainer-approved typed session/context contract with authorization, persistence, summarization, recovery, and docs before transport adapters are added.
