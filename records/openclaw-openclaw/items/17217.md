## Summary

Keep open: current main documents session lifecycle and has reset/compact controls, but it still lacks immediate TTL-based conversation-history pruning, summarization, or a prune-context API; the remaining work is a product and security-sensitive session-retention decision.

## What This Changes

The issue requests explicit session boundary docs, immediate TTL pruning during long sessions, and manual prune/reset controls without restarting OpenClaw.

## Best Possible Solution

Define one canonical session/context contract that separates tool-result pruning, conversation compaction, manual reset, TTL or rolling retention, and authorized API controls, then update implementation, docs, and tests consistently.

## Reproduction Assessment

Yes, at source level: current main has reset and compaction controls, but no prune-context method and no wall-clock conversation-history TTL expiry; cache-TTL pruning is tool-result-only by source and docs.

## Solution Assessment

No, not as standalone POST endpoints yet; the maintainable path is a maintainer-approved typed session/context contract with authorization, persistence, summarization, recovery, and docs before transport adapters are added.
