## Summary

Keep open: current main and v2026.6.11 still have the reported source-level regression, with no open PR found that targets this exact heartbeat CLI-binding persistence path.

## What This Changes

The issue reports that heartbeat CLI runs preserve displayed model state but also skip persisting `cliSessionBinding` and `clearCliSessionBinding`, causing stale Claude CLI context after heartbeat turns.

## Best Possible Solution

Separate model-display preservation from CLI binding persistence so heartbeat and runtime-model-preserving runs keep user-facing model fields while still applying valid CLI binding writes and clears.

## Reproduction Assessment

Yes at source level: heartbeat CLI metadata reaches `persistSessionUsageUpdate`, but the current branch returns before applying binding writes or clears. I did not execute a live Claude CLI heartbeat reproduction in this read-only review.

## Solution Assessment

Yes: the narrow maintainable fix is to keep model-display preservation while applying CLI binding updates unless the explicitly internal `preserveUserFacingSessionModelState` path is active.
