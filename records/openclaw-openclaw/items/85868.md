## Summary

Keep open: current main and v2026.6.11 still expose WhatsApp login as QR-only, and the existing 515 handling is a bounded one-shot login socket replacement, while the active phone-code PRs overlap this symptom but are open, conflicting, and not yet live-proven for restart-free recovery.

## What This Changes

The issue reports a WhatsApp phone-code relink sequence where the phone accepts the code but remains on Logging in until restarting the gateway lets 515 recovery finish credential persistence and mark the web session connected.

## Best Possible Solution

Land or rework the active WhatsApp phone-code login path so QR remains the default, partial credentials are cleaned up safely, and live device proof shows whether 515 recovery completes without an operator gateway restart; otherwise document the restart workaround explicitly.
