## Summary

This PR remains useful and correctly addresses the reported circular and BigInt serialization failures, including the previous review’s fallible `String()` fallback. It should stay open because the submitted runtime transcript exercises only the helper, not a provider lifecycle that emits the terminal error event and closes the stream, and the broader competing implementation is not yet a proven safe replacement.

## What This Changes

The PR adds a shared non-throwing JSON formatter for unknown provider stream failures and adopts it in Anthropic, Google, Mistral, and OpenAI Completions paths.

## Best Possible Solution

Use one package-internal unknown-error formatting boundary across the affected provider catch paths, preserve provider-specific messages and metadata, and prove through at least one actual provider lifecycle that a circular rejection emits an error event and closes the stream.

## Reproduction Assessment

Yes at source level: current main passes arbitrary non-Error failures to bare `JSON.stringify`, and a circular value deterministically throws before the terminal stream operations. The PR body does not establish a full current-main provider lifecycle reproduction.

## Solution Assessment

The shared guarded formatter is a correct narrow fix for the filed circular and BigInt cases, but a single total unknown-error formatter that also owns classification and provider-specific inspection is the more maintainable final boundary.
