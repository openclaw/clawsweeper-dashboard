## Summary

Keep open. Current `main` reproduces the missing contract: cached `chat.send` results carry a cache marker only into logging, while the strict response frame and official TypeScript client expose no replay state. The open draft https://github.com/openclaw/openclaw/pull/103705 is the active candidate fix, and prior maintainer feedback supports this narrowed direction while leaving the exact generic protocol shape for review.

**Likely related people**
- @steipete — high confidence from recent `chat.send` and protocol work plus the earlier protocol-boundary decision.
- @RomneyDa and @vincentkoc — medium confidence from recent Gateway client contract and lifecycle work.

## What This Changes

Add a capability-negotiated replay marker for cached `chat.send` responses and surface it on TypeScript Gateway request errors.

## Best Possible Solution

The Gateway should expose one closed JSON replay signal only to opted-in clients, keep responder diagnostics entirely log-only, preserve byte-compatible legacy frames, and provide a real official-client retry flow that stops after a replayed retryable error.
