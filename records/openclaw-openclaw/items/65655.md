## Summary

Keep open: current main and v2026.6.11 still derive and register HTTP Mattermost slash callbacks when `commands.callbackUrl` is omitted, while this PR adds the remaining HTTPS fail-closed gate. The patch looks targeted, but it still needs redacted real Mattermost proof and maintainer/security acceptance for the intentional HTTP-callback deployment break before merge.

## What This Changes

The PR rejects non-HTTPS Mattermost native slash callback URLs before registration and updates the Mattermost docs and monitor tests for derived and explicit HTTP callbacks.

## Best Possible Solution

Land this or a replacement Mattermost plugin transport gate after maintainers accept the fail-closed upgrade behavior, the contributor adds redacted real setup proof, and the PR body matches the narrowed scope.

## Reproduction Assessment

## Solution Assessment

Yes if maintainers accept the breaking hardening: the guard belongs in the Mattermost registration path before token-bearing callbacks are registered over cleartext. If preserving HTTP deployments wins, the safer alternative is a maintainer-approved staged or opt-in strict mode.
