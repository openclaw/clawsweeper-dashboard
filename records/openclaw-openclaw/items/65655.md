## Label Justifications

- `P1`: This is an active Mattermost slash-command security boundary fix for token-bearing callback transport, with a linked open bug and source-level reproduction.
- `merge-risk: 🚨 compatibility`: Existing setups that rely on derived or explicit HTTP Mattermost slash callback URLs will stop registering native slash commands after merge.
- `merge-risk: 🚨 security-boundary`: The PR changes the fail-closed policy for Mattermost slash-command callbacks, which carry reusable command tokens and gate command execution.

## Summary

Keep open: current main and v2026.6.11 still allow Mattermost native slash registration to proceed with derived `http://` callbacks, and this PR is the narrow live fix candidate. It is not merge-ready yet because it intentionally breaks HTTP callback deployments, lacks real Mattermost proof, and its body still describes older token-binding scope that current main already handles.

## What This Changes

The branch updates Mattermost docs/tests and `monitor-slash.ts` so native slash command registration returns before registering when the resolved callback URL is not HTTPS.

## Best Possible Solution

Land this or a maintainer replacement only after the PR body matches the narrowed transport scope, redacted live Mattermost proof is added, and maintainers accept the HTTPS-only callback policy.

## Reproduction Assessment

Yes, from source. Current main and v2026.6.11 derive `http://` callback URLs when `callbackUrl` is omitted and pass them into registration without an HTTPS gate; I did not run a live Mattermost network capture.

## Solution Assessment

Yes for code shape, not yet for merge readiness. A plugin-local pre-registration HTTPS guard is the narrow owner-boundary fix, but the fail-closed upgrade impact and real behavior proof still need maintainer review.
