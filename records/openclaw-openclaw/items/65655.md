## Summary

Keep open: current main and v2026.6.11 still derive and register non-HTTPS Mattermost slash callback URLs when `commands.callbackUrl` is omitted, while this PR still uniquely covers the remaining transport gate; it needs real Mattermost proof and maintainer/security acceptance before merge.

## What This Changes

The branch adds a Mattermost native slash-command startup guard that rejects non-HTTPS callback URLs before registration, plus docs and monitor tests for derived and explicit HTTP callbacks.

## Best Possible Solution

Land this or a replacement Mattermost plugin transport gate after maintainers accept the fail-closed upgrade behavior, the contributor adds redacted real setup proof, and the PR body matches the narrowed scope.

## Reproduction Assessment

Yes, source-level. Current main derives an `http://` Mattermost slash callback when `commands.callbackUrl` is omitted and proceeds toward registration without an HTTPS gate; I did not run a live Mattermost network capture.

## Solution Assessment

Yes if maintainers accept the breaking hardening: the guard belongs in the Mattermost registration path before token-bearing callbacks are registered over cleartext. If preserving HTTP deployments wins, the safer alternative is a maintainer-approved staged or opt-in strict mode.
