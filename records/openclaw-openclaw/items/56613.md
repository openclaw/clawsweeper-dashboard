## Summary

Keep open: current main implements the per-agent TTS half through `agents.list[].tts`, but Android Voice/Talk still lacks target selection and Talk requests still route through `mainSessionKey`. The open Android Chat selector PR only partially overlaps and is currently conflicting.

## What This Changes

Request Talk/Voice mode on companion apps to select the target agent/session and support distinct per-agent TTS voice identities.

## Best Possible Solution

Add a maintainer-approved Talk/Voice target selector that reuses existing gateway agent/session state, preserves the selected target across refresh/reconnect, and keeps voice identity on `agents.list[].tts`.

## Reproduction Assessment

Yes, source-level: current Android `VoiceScreen` starts Talk without collecting agent/session choices, and `TalkModeManager` sends Talk and chat requests through `mainSessionKey`. I did not run live device proof in this read-only review.

## Solution Assessment

Unclear until maintainers choose the UX and platform scope. The maintainable direction is a focused Talk/Voice selector using existing gateway-agent/session data, with TTS voice identity staying on `agents.list[].tts` rather than adding `talk.voiceId`.
