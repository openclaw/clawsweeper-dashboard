## Summary

Keep open: current main and the latest release cover the per-agent TTS voice half through `agents.list[].tts`, but the Android Voice/Talk path still starts Talk without an agent/session picker and routes through the default `mainSessionKey`; the open Android Chat selector PR only partially overlaps because it does not implement Voice/Talk routing.

## What This Changes

Request agent/session switching for Talk/Voice mode and per-agent TTS voice identity across Android and companion-app voice surfaces.

## Best Possible Solution

Keep this as the canonical Talk/Voice session-selection tracker, add a maintainer-approved selector using existing gateway agent/session state, and keep voice identity on the canonical `agents.list[].tts` path.
