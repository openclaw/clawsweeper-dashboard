## Summary

Keep open: current main implements the per-agent TTS half through `agents.list[].tts`, but the Android Talk/Voice path still starts without an agent/session choice and routes realtime/chat requests through `mainSessionKey`. The related Android Chat selector PR is open, conflicting, and explicitly Chat-scoped, so it is not a canonical fix for the remaining Talk/Voice request.

## What This Changes

The issue requests Talk/Voice agent/session switching across companion-app voice surfaces and distinct per-agent TTS voices for multi-agent setups.

## Best Possible Solution

Keep this as the canonical Talk/Voice session-selection issue, add a focused selector that reuses existing gateway agent/session state, and keep voice identity on `agents.list[].tts` instead of adding a new `talk.voiceId` config shape.
