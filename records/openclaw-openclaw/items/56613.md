## Summary

Keep open: current main has shipped canonical per-agent TTS overrides through `agents.list[].tts`, but the remaining Android Voice/Talk path still has no user-facing agent or session picker and continues routing Talk through the runtime default session key. ## What This Changes

The issue asks for Android Talk/Voice to let users choose which configured agent or session receives voice input, with each selected agent using its own voice identity.

## Best Possible Solution

Keep this as the canonical Talk/Voice agent/session-selection request, implement the selector using existing gateway agent/session state and canonical `agents.list[].tts`, and avoid adding `talk.voiceId`.
