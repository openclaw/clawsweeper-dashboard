## Summary

Keep open: current main implements the per-agent TTS half through `agents.list[].tts`, but Talk/Voice still lacks a user-facing agent/session selector and the Android, iOS, and macOS Talk paths still route through main/default session keys. The open Android Chat selector work only partially overlaps because it targets Chat, not the Talk/Voice surface.

## What This Changes

Request agent/session selection in Talk/Voice mode plus per-agent TTS voice identity for multi-agent companion-app voice conversations.

## Best Possible Solution

Keep this as the canonical Talk/Voice session-selection work, implement a maintainer-approved selector using existing gateway agent/session data, and keep voice identity on `agents.list[].tts`.
