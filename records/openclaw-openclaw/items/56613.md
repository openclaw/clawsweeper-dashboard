## Summary

Keep open: current main and the latest release implement the per-agent TTS voice half through `agents.list[].tts`, but Android Voice/Talk still has no agent/session picker and Talk requests still route through the resolved main session key. The related Android Chat selector PR only partially overlaps because it targets Chat, not the Voice/Talk surface.

## What This Changes

Request to let Talk/Voice choose the active agent/session and use distinct per-agent TTS voices in multi-agent native voice conversations.

## Best Possible Solution

Keep this as the canonical Talk/Voice target-selection request, implement a Talk/Voice selector using existing gateway agent/session state, and keep voice identity on canonical `agents.list[].tts`.
