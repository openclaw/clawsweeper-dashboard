## Summary

Keep open: current main has the per-agent TTS half through `agents.list[].tts`, but Android Voice/Talk still lacks a target selector and Talk requests continue to route through `mainSessionKey`. The open Android Chat selector PR only partially overlaps and is not a Voice/Talk fix.

## What This Changes

Request to let Talk/Voice users choose the target agent/session and give different agents distinct TTS voices.

## Best Possible Solution

Add a focused Talk/Voice target selector using existing gateway agent/session state, keep voice identity on `agents.list[].tts`, and avoid adding a parallel `talk.voiceId` config shape.
