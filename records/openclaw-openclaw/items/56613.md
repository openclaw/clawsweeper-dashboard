## Summary

Keep open: current main and the latest release already have the per-agent TTS half via `agents.list[].tts`, but Android Voice/Talk still has no user-visible agent/session picker and routes Talk through the current main session key. The open Android Chat selector PR only partially overlaps because it targets Chat, not the Voice/Talk surface.

## What This Changes

Request to let Talk/Voice choose an agent/session and let different configured agents use distinct TTS voices.

## Best Possible Solution

Keep this as the canonical Talk/Voice session-selection issue, add a selector using existing gateway agent/session state, preserve explicit selected Talk target state across refresh/reconnect, and keep voice identity on `agents.list[].tts`.
