## Summary

Keep open: current main implements the per-agent TTS half through `agents.list[].tts`, but the active Android Voice/Talk path still starts Talk without an agent/session selector and routes through `mainSessionKey`. The related Android Chat selector PR and newer voice-surface work are partial overlaps, not replacements for this Talk/Voice routing request.

## What This Changes

Request Talk/Voice mode to select the target agent/session and support per-agent TTS voice identity instead of sharing one global voice.

## Best Possible Solution

Add a Talk/Voice agent/session selector that reuses existing gateway agent/session state, while keeping voice identity on the canonical `agents.list[].tts` config path.
