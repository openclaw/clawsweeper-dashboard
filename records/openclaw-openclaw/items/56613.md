## Summary

Keep open: the per-agent TTS half is implemented and shipped through `agents.list[].tts`, but current Android Voice/Talk still exposes only Mic, Speaker, and Talk controls and routes Talk turns through `mainSessionKey`; the open Android Chat selector PR only partially overlaps and does not touch Voice/Talk routing.

## What This Changes

Request Android and companion-app Talk/Voice agent/session selection plus per-agent TTS voice identity for multi-agent voice conversations.

## Best Possible Solution

Keep `agents.list[].tts` as the canonical voice-identity surface, then add a companion-app Voice/Talk selector that routes Mic, Talk relay/session create, chat.send, and event filtering through the selected canonical agent/session key with Android regression coverage and a clear parity plan for iOS/macOS.

Options:

- **Add Voice-owned selector (recommended):** Expose an explicit Voice/Talk agent or session picker and route Talk/Mic turns through that selection without relying on hidden Chat state.
- **Mirror Chat selection:** Make Voice follow the active Chat session, which is smaller UI work but creates cross-tab coupling users may not understand.
- **Defer shared routing:** Keep this open until maintainers design one active-agent/session model for Chat, Voice, and companion-app parity.
