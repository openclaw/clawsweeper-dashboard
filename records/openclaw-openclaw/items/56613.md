## Summary

Keep open: current main implements the per-agent TTS half through `agents.list[].tts`, but the Android Talk/Voice surface still has no agent/session selector and Talk still creates/sends turns with the resolved default `mainSessionKey`. The open Android Chat selector PR only partially overlaps and does not cover Talk/Voice routing.

## What This Changes

Request Talk/Voice mode agent/session selection plus per-agent TTS voice identity for multi-agent voice conversations on companion apps.

## Best Possible Solution

Keep this issue as the canonical Talk/Voice session-selection request, reuse existing gateway agent/session state for the selector, and keep voice identity on the already-canonical `agents.list[].tts` config path.

## Reproduction Assessment

Yes for a source-level path: current Android VoiceScreen starts Talk without collecting agent/session choices, and TalkModeManager sends realtime and chat requests through `mainSessionKey`. I did not run live device proof in this read-only review.

## Solution Assessment

Unclear until maintainers choose the UX and platform scope. The maintainable direction is a focused Talk/Voice selector using existing gateway-agent/session data, with TTS voice identity staying on `agents.list[].tts` rather than adding a new `talk.voiceId` shape.
