## Summary

Keep open: current main implements the per-agent TTS voice half through `agents.list[].tts`, but Android Voice/Talk still has no agent/session selector and Talk routing still uses the resolved default `mainSessionKey`. The open Android Chat selector PR only partially overlaps and does not implement Voice/Talk routing.

## What This Changes

Request selectable agent/session targeting in Talk/Voice mode plus distinct per-agent TTS voices for multi-agent setups.

## Best Possible Solution

Keep this issue as the canonical Talk/Voice session-selection tracker, reuse existing gateway agent/session state for the selector, and keep voice identity on the already-canonical `agents.list[].tts` config path.
