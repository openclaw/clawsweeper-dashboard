## Summary

Keep open: current main implements the per-agent TTS half through `agents.list[].tts`, but the active Android Voice/Talk path still starts Talk without an agent/session selector and Talk still routes through the runtime main session key.

## What This Changes

Request to let Talk/Voice mode target a selected agent/session and let agents use distinct TTS voices.

## Best Possible Solution

Keep this as the canonical Talk/Voice target-selection item, reuse existing gateway agent/session data for the selector, and keep voice identity on `agents.list[].tts` instead of adding `talk.voiceId`.

## Reproduction Assessment

Yes for a source-level path: current main's active Android Voice screen starts Talk without collecting agent/session choices, and `TalkModeManager` sends Talk and chat requests through `mainSessionKey`. I did not run live device proof in this read-only review.

## Solution Assessment

Unclear until maintainers choose the UX and platform scope. The maintainable direction is a focused Talk/Voice selector using existing gateway-agent/session data, with TTS voice identity staying on `agents.list[].tts` rather than adding a new `talk.voiceId` shape.
