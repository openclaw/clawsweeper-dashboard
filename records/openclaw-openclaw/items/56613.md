## Summary

Keep open: current main and v2026.6.11 cover the per-agent TTS half through `agents.list[].tts`, but Android Voice/Talk still has no agent/session selector and Talk routing still uses the resolved `mainSessionKey`. The related Android Chat selector PR is open, conflicting, and does not touch the Voice/Talk surface.

## What This Changes

Request agent/session selection for Talk/Voice surfaces plus per-agent voice identity so multi-agent users can talk to non-default agents with distinct TTS voices.

## Best Possible Solution

Keep voice identity on the canonical `agents.list[].tts` path and add a focused Talk/Voice selector that reuses existing gateway agent/session state, likely Android-first unless maintainers choose a shared companion-app UX.
