## Summary

Keep open: current main still exposes one scalar `plugins.slots.memory` owner, and the linked role-slot implementation is still open, unmerged, and currently dirty. The issue is still necessary as a product/API decision for public memory role slots, not a cleanup close.

## What This Changes

This issue requests purpose-specific memory role slots so multiple memory providers can coexist instead of competing for one global memory slot.

## Best Possible Solution

Decide the durable memory role-slot contract and upgrade path, then review and either land a rebased implementation such as https://github.com/openclaw/openclaw/pull/88504 or explicitly narrow/reject that direction.
