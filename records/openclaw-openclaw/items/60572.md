## Summary

Keep open: current main and the latest release still model memory as one exclusive scalar slot, and the open linked PR is the canonical implementation candidate. The discussion adds concrete deployment evidence for Honcho, Mem0, ByteRover, Hindsight, and dreaming coexistence, but accepting memory role slots is a public config/plugin API decision.

## What This Changes

Request to replace the single `plugins.slots.memory` selector with purpose-specific, per-agent memory role slots so recall, compaction, capture, dreaming, and user-model providers can coexist.

## Best Possible Solution

Use https://github.com/openclaw/openclaw/pull/88504 as the canonical implementation review path, decide the memory role taxonomy and upgrade behavior there, and close this issue after that PR merges or maintainers explicitly reject the direction.
