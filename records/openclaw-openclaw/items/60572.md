## Summary

Keep open: current `main` and the latest release still expose one exclusive scalar memory slot, and the linked implementation candidate is open and conflicting rather than merged. The remaining question is a product/API decision about whether OpenClaw should move from one memory owner toward role-specific memory slots.

## What This Changes

The issue requests replacing the single `plugins.slots.memory` owner with purpose-specific global and per-agent memory role slots such as recall, compaction, capture, dreaming, and user modeling.

## Best Possible Solution

Keep this issue open as the canonical product/API discussion, and either land a maintainer-approved version of `https://github.com/openclaw/openclaw/pull/88504` with migration and upgrade proof or explicitly choose a narrower single-memory-owner direction.
