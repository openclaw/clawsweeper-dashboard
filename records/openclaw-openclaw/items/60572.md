## Summary

Keep open: current main and the latest release still expose one scalar memory slot, and the open linked implementation candidate has not merged. The report is useful product/API evidence, but the remaining decision is whether OpenClaw should adopt role-based memory slots as a public plugin/config contract.

## What This Changes

Request purpose-specific memory role slots so recall, compaction, capture, dreaming, and user-model providers can run side by side instead of competing for one `plugins.slots.memory` owner.

## Best Possible Solution

Review https://github.com/openclaw/openclaw/pull/88504 as the canonical implementation path, then land, narrow, or close it with an explicit memory-slot API decision and doctor/upgrade story.
