## Summary

Keep open: current main and latest release still expose a single exclusive scalar memory slot, and the issue is already paired with an open, unmerged implementation candidate. This is a public memory/plugin API direction decision, not conservative cleanup that can close today.

## What This Changes

The issue requests purpose-specific memory plugin slots so recall, compaction, capture, dreaming, and user-modeling providers can coexist instead of competing for one `plugins.slots.memory` owner.

## Best Possible Solution

Decide the memory role-slot API around `https://github.com/openclaw/openclaw/pull/88504`, including legacy scalar migration, doctor repair behavior, per-agent override semantics, and plugin SDK documentation, then close this issue after the direction lands or is explicitly rejected.
