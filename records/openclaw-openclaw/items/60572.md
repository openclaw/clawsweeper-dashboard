## Summary

Keep open: current main and v2026.6.11 still expose one exclusive scalar memory slot, while the linked implementation candidate remains open and unmerged. The remaining decision is whether OpenClaw should accept purpose-specific memory role slots as durable public config/plugin API.

## What This Changes

The issue requests replacing the single `plugins.slots.memory` selector with purpose-specific, optionally per-agent memory role slots for recall, compaction, capture, and user modeling.

## Best Possible Solution

Use https://github.com/openclaw/openclaw/pull/88504 as the canonical implementation review path, decide the memory role taxonomy and upgrade behavior there, and close this issue after that PR merges or maintainers explicitly reject the direction.
