## Label Justifications

- `P1`: Frequent Codex tool-heavy turns can complete side effects but fail to deliver the final response, breaking the active agent workflow until another inbound message arrives.
- `impact:message-loss`: The expected closing assistant response is not delivered after completed tool calls.

## Summary

This is a credible current runtime gap: replay protection correctly blocks rerunning side-effecting tools, but the Codex-specific recovery path does not cover clean turns ending after completed tool calls without a final assistant response. The item is still necessary and distinct from app-server stalls where `turn/completed` never arrives. Likely related people: `jalehman` for incomplete-turn continuation, `joshavant` for Codex app-server liveness, and `funmerlin` for adjacent completion-stall handling. ([github.com](https://github.com/openclaw/openclaw/pull/66167))

## What This Changes

Safely continue Codex app-server turns that end after completed tool calls without a final assistant response, without replaying their side effects.

## Best Possible Solution

Implement a Codex-plugin-owned, one-attempt continuation on the same persisted thread with tools disabled or otherwise provably unavailable, gated on fully paired completed tool results and no visible final response; handle the zero-tool empty-turn defect separately unless testing proves a shared cause.
