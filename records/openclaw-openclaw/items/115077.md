## What This Changes

The PR forwards Telegram’s existing `linkPreview` setting into draft streaming so streamed sends, edits, HTML retries, and rich-message fallbacks suppress preview cards when users disable them.

## System Context

Telegram replies pass from the message dispatcher into a draft-stream controller, which sends and edits one visible reply while an agent streams text. The configured link-preview policy must survive every send/edit/fallback path so a draft finalized in place has the same presentation policy as ordinary delivery.

## Best Possible Solution

Keep the existing `linkPreview` preference owned by the draft stream, remove the release-owned changelog edit, and add a redacted live Telegram proof showing a streamed URL reply remains preview-free through finalization.
