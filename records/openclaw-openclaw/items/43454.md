## Summary

Keep open: current main and the latest tagged release still do not expose the requested workspace/internal lifecycle events, while the existing plugin hook surface covers only adjacent or partial lifecycle seams. The remaining work is a product and security-boundary decision about event family, payload, ordering, and whether threshold behavior belongs in workspace hooks or typed plugin hooks.

## What This Changes

Requests workspace/internal lifecycle hook events for subagent completion, agent turn completion, and tool-call threshold triggers.

## Best Possible Solution

Define a minimal documented lifecycle contract that separates observation-only workspace events from richer typed plugin control hooks, then add source, docs, and tests for the approved event set and payloads.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw expose subagent completion, turn completion, and tool-call threshold boundaries through HOOK.md workspace/internal hooks, typed plugin hooks only, or a split surface with different payload and authority levels?

Rationale: The source gap is clear, but the API choice affects trusted local code execution, session-state exposure, hook ordering, possible threshold config, and the boundary between operator automation and plugin middleware.

Likely owner: steipete

Owner reason: steipete introduced the internal hooks system and is the most direct routing candidate for a product/security boundary decision about workspace hook authority.

Owner confidence: high

Options:

- **Split Observation From Control (recommended):** Expose only minimal observation-oriented workspace events first, while keeping result mutation, threshold policy, and richer payloads in typed plugin hooks.
- **Typed Plugin Hooks Only:** Avoid new HOOK.md lifecycle events and extend the plugin API for lifecycle or receipt use cases that need stronger contracts.
- **Full Workspace Surface:** Add subagent, turn-complete, and threshold workspace events after maintainers define payload, ordering, redaction, and config semantics.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 do not expose subagent, turn-complete, or threshold events through the internal workspace hook family, while existing subagent_ended is typed-plugin-only.

## Solution Assessment

Unclear until maintainers choose the API boundary. The minimal subagent completion bridge is plausible, but the full request needs documented payload, permission, ordering, and threshold-config semantics before it is the best fix.
