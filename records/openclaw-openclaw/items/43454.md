## Summary

Keep open: current main and v2026.6.11 still lack the requested workspace/internal `subagent:ended`, turn-complete, and tool-call-threshold hook surface. Adjacent typed plugin hooks cover some lifecycle and tool-control use cases, but the requested HOOK.md workspace hook workflow remains a product and security-boundary decision.

## What This Changes

Request workspace/internal lifecycle hooks for subagent completion, turn completion, and tool-call thresholds so automation can react to agent lifecycle events.

## Best Possible Solution

Define a maintainer-approved split: expose only safe observation events to workspace/internal hooks, keep mutation and sensitive lifecycle control in typed plugin hooks, and document/test payload, ordering, and security semantics.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw expose subagent completion, turn completion, and tool-call threshold data through workspace/internal hooks, or keep these lifecycle seams plugin-only except for a narrow observation event?

Rationale: The missing surface is source-proven, but payload minimization, hook authority, event ordering, and threshold configuration are public API and security-boundary choices that automation should not choose.

Likely owner: vincentkoc

Owner reason: The unresolved choice sits on hook contract, plugin API, and lifecycle/security boundaries where current history points most strongly to this owner.

Owner confidence: high

Options:

- **Observation-Only Workspace Events (recommended):** Add narrow workspace/internal lifecycle events with minimized metadata while leaving mutation, mid-turn control, and sensitive tool/session access in typed plugin hooks.
- **Keep Lifecycle Plugin-Only:** Treat existing `agent_end`, `before_tool_call`, `after_tool_call`, and `subagent_ended` plugin hooks as the supported lifecycle surface and decline workspace hook expansion for this data.
- **Design Unified Lifecycle Contract First:** Pause implementation until maintainers define one lifecycle model covering internal hooks, typed plugin hooks, payloads, thresholds, permissions, and ordering.

## Solution Assessment

Unclear as proposed. A narrow observation-only `subagent:ended` internal hook may be viable, but turn-complete and threshold behavior need a maintainer-approved API/security split because plugin hooks already cover some lifecycle and tool-control use cases.
