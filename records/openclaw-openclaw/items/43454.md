## Summary

Keep open: current main and the latest release still expose adjacent typed plugin hooks such as `subagent_ended` and `agent_end`, but not the requested internal/workspace `subagent:ended`, turn-complete, or tool-call-threshold hook surface. The overlapping PRs are open/conflicting or closed unmerged, so this remains a maintainer API/security design item rather than a cleanup close.

## What This Changes

The issue requests gateway/workspace lifecycle hook events for subagent completion, agent turn completion, and tool-call thresholds so hooks can react deterministically to agent lifecycle boundaries.

## Best Possible Solution

Settle one lifecycle-hook contract for internal/workspace hooks and typed plugin hooks, including event names, payloads, ordering, timeout behavior, security boundaries, docs, and focused tests.

## Reproduction Assessment

Yes for the source-level gap: current main can be checked by inspecting the internal hook event union, the subagent completion emitter, and the published hook docs. No runtime repro is needed because this is a missing API surface, not a regression in an existing hook contract.

## Solution Assessment

Unclear as proposed: exposing `subagent:ended` to workspace hooks is plausible, but turn-complete and tool-call-threshold events need maintainer decisions on naming, payloads, ordering, security, and whether threshold behavior belongs in hook config.
