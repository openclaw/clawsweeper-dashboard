## What This Changes

The issue requests new gateway/agent lifecycle hook events for workspace automation around subagent completion, agent turn completion, and tool-call thresholds.

## Best Possible Solution

Define a minimal documented lifecycle contract that separates observation-only workspace events from richer typed plugin runtime-control hooks, then implement the approved event set with payload, redaction, ordering, docs, and regression tests.

Rationale: The source gap is clear, but the permanent API affects trusted local code execution, session-state exposure, hook ordering, threshold configuration, and the boundary between workspace automation and plugin middleware.

Likely owner: steipete

Owner confidence: medium

Options:

- **Split Observation From Control (recommended):** Expose minimal observation-oriented workspace events first, while keeping richer result, mutation, threshold, and policy behavior in typed plugin hooks.
- **Use Typed Plugin Hooks Only:** Avoid new HOOK.md lifecycle events and extend the typed plugin API for lifecycle and receipt use cases that need stronger contracts.
- **Add Full Workspace Surface:** Add subagent, turn-complete, and threshold workspace events after defining payload, ordering, redaction, and config semantics.

Yes, at source level. Current main and `v2026.6.11` do not expose the requested `subagent`, turn-complete, or tool-call-threshold events through the internal workspace hook family.

## Solution Assessment

Unclear until maintainers choose the API boundary. The minimal subagent completion bridge is plausible, but the full request needs a documented payload, permission, ordering, and threshold-config contract before implementation is the best fix.
