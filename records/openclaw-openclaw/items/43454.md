## Summary

Keep open: current main and v2026.6.11 still expose adjacent typed plugin hooks such as `subagent_ended`, `agent_end`, `before_tool_call`, and `after_tool_call`, but not the requested workspace/internal `subagent:ended`, turn-complete, or tool-call-threshold hook surface. The remaining work is a lifecycle-hook API design item with security, payload, ordering, and config implications, and the open related PRs are partial or not merged.

## What This Changes

Requested gateway lifecycle hooks for workspace/internal hook consumers, including subagent completion, turn completion, and tool-call threshold events.

## Best Possible Solution

Define one maintainer-approved lifecycle-hook contract for internal/workspace hooks and typed plugin hooks, with explicit event names, payloads, ordering, timeout behavior, security boundaries, docs, and focused tests.

Question: Which lifecycle hook contract should OpenClaw expose for subagent completion, turn completion, and tool-call thresholds: extend workspace/internal hooks, typed plugin hooks, or split those surfaces by sensitivity?

Rationale: The request crosses API naming, payload data exposure, ordering, mid-turn execution, hook config, and plugin/workspace security boundaries, and current open PRs only cover parts of that decision.

Likely owner: steipete

Owner reason: The strongest current history signal for internal hooks and published hook docs points to steipete, while plugin/subagent contributors should be included in the design review.

Owner confidence: medium

Options:

- **Design one combined contract (recommended):** Define the event names, payloads, and security rules once, then land a focused implementation with docs and tests across internal/workspace and typed plugin surfaces as appropriate.
- **Keep runtime control in plugin hooks:** Expose sensitive or mid-turn lifecycle behavior only through typed plugin hooks and keep workspace/internal hooks for coarse operator automation.
- **Stage observation before thresholds:** Land only observation-style completion events first, then decide threshold/mid-turn behavior separately after payload and injection semantics are settled.
