- `impact:session-state`: The motivating use cases are memory, learning loops, subagent completion processing, and turn-level state handling.

## Summary

Keep open: current main and v2026.6.11 still expose adjacent plugin-level `subagent_ended` and `agent_end` hooks, but not the requested internal/workspace `subagent:ended`, turn-complete, or tool-call-threshold lifecycle hook surface. Related PRs are open/conflicting or closed unmerged, so this remains a maintainer product/security API design item rather than a cleanup close.

## What This Changes

The issue requests new Gateway/workspace lifecycle hook events for subagent completion, turn completion, and tool-call thresholds so external learning or memory loops can react without polling or prompt-only rules.

## Best Possible Solution

Maintainers should settle one lifecycle-hook contract that covers workspace/internal hooks and typed plugin hooks, with explicit event names, payloads, ordering, timeout/security behavior, docs, and regression tests, then land or close the related partial PRs against that design.

## Reproduction Assessment

Yes for the source-level gap: current main can be checked by inspecting `InternalHookEventType`, the subagent completion emitter, and internal hook docs. No runtime repro is needed because this is a missing API surface rather than a broken existing contract.

## Solution Assessment

Unclear as proposed: exposing `subagent:ended` is plausible, but turn-complete and tool-call-threshold hooks need maintainer decisions on naming, payloads, ordering, security, and whether threshold config belongs in hook entries. The safer path is a designed lifecycle contract, not a one-off plumbing patch.
