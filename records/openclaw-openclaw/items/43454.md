## Summary

Keep open: current main and v2026.6.11 still lack the requested workspace/internal `subagent:ended`, turn-complete, and tool-call-threshold hook surface. Adjacent typed plugin hooks cover some lifecycle/control use cases, but they do not satisfy the requested HOOK.md workspace hook workflow, and the remaining work is a product/security-boundary decision.

## What This Changes

The issue requests workspace/internal lifecycle hooks for subagent completion, agent turn completion, and tool-call thresholds.

## Best Possible Solution

Define a maintainer-approved split: expose only safe observation events to workspace/internal hooks, keep mutating or sensitive lifecycle control in typed plugin hooks, and document/test the chosen payload, ordering, and security contract.

Question: Should OpenClaw expose subagent completion, turn completion, and tool-call threshold data through workspace/internal hooks, or keep those lifecycle seams plugin-only except for a narrow observation event?

Rationale: The missing surface is source-proven, but payload minimization, hook authority, ordering, and threshold configuration are public API and security-boundary choices that automation should not choose.

Likely owner: vincentkoc

Owner confidence: medium

Options:

- **Observation-Only Internal Events (recommended):** Add narrow workspace/internal lifecycle events with minimized metadata while leaving mutation, mid-turn control, and sensitive tool/session access in typed plugin hooks.
- **Keep Lifecycle Plugin-Only:** Treat existing `agent_end`, `before_tool_call`, `after_tool_call`, and `subagent_ended` plugin hooks as the supported lifecycle surface and decline workspace hook expansion for this data.
- **Design Unified Lifecycle Contract First:** Pause implementation until maintainers define one lifecycle model covering internal hooks, typed plugin hooks, payloads, thresholds, permissions, and ordering.
