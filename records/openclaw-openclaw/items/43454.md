## Summary

Keep open: current main and the latest release still lack the requested workspace/internal lifecycle hook surface for subagent completion, turn completion, and tool-call thresholds. Existing typed plugin hooks cover adjacent `subagent_ended`, `agent_end`, and tool-call observation/control, and open PRs cover only narrower ACP turn pieces, so the remaining work is a maintainer API and security-boundary decision rather than a cleanup close.

## What This Changes

Expose workspace/internal lifecycle hooks for subagent completion, agent turn completion, and tool-call threshold events.

## Best Possible Solution

Define one maintainer-approved lifecycle-hook contract with explicit internal-vs-plugin ownership, event names, payload redaction, ordering, timeout/failure behavior, docs, and focused tests before implementation.

Question: Which lifecycle hook contract should OpenClaw expose for subagent completion, turn completion, and tool-call thresholds: workspace/internal hooks, typed plugin hooks, or a split contract by sensitivity?

Rationale: The source gap is clear, but the decision affects public API naming, hook authority, raw result/session exposure, mid-turn execution, and new configuration semantics, so automation should not lock in the product or security boundary.

Likely owner: steipete

Owner reason: `steipete` has the strongest combined signal from hook docs/source history and current product/API direction for core-vs-plugin extension boundaries.

Owner confidence: high

Options:

- **Design One Split-Surface Contract (recommended):** Define the internal/workspace observation events and typed plugin runtime-control events together, with payload and security rules before implementation.
- **Observation-Only First:** Land only coarse non-mutating completion and turn observation events now, then decide mid-turn thresholds and mutation separately.
- **Typed Plugin Hooks Only:** Keep sensitive lifecycle data and mid-turn behavior out of workspace hooks and expose them only through the plugin SDK with explicit trust gates.

## Reproduction Assessment

Yes. The source-level gap is reproducible by inspecting the internal hook event union, the internal hook docs, and `emitSubagentEndedHookOnce`, which currently emits only the typed plugin `subagent_ended` hook.

## Solution Assessment

Unclear as proposed. Exposing `subagent:ended` is plausible, but the full request needs a maintainer-approved contract for event names, payloads, data exposure, ordering, threshold config, and whether each event belongs to workspace hooks or typed plugin hooks.
