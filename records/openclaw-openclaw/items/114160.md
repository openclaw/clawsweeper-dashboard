## What This Changes

This PR coalesces concurrent identical `sessions.catalog.list` reads by request-owned session snapshot, replays host progress to each connection, keeps mutating Workboard dispatches independent, and adds one-shot exit handling for fast CLI help output.

## System Context

Gateway clients request session catalogs from providers and receive incremental host-progress events over their own connection. The changed path builds a request snapshot, decides whether an identical provider read is already in flight, then returns catalog hosts and per-connection progress without sharing mutating Workboard dispatch results.

## Best Possible Solution

Keep the catalog-read coalescing fix narrowly scoped, add redacted after-fix Gateway evidence showing one provider read with correct progress delivery to concurrent callers, and split the CLI one-shot exit behavior into a dedicated PR unless it is required by this exact Gateway fix.
