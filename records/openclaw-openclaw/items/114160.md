## Summary

Keep this PR open for revision. The coalescing approach is directionally appropriate, but a request that joins after the provider has emitted an early host misses that host’s progressive event, so the claimed per-connection progress fan-out is incomplete; the supplied validation only covers simultaneous subscribers. It also needs real Gateway-runtime proof rather than mocked test output alone.

Likely related people: the history lookup could not run in this read-only sandbox, so the relevant gateway and Workboard owners remain unresolved (low confidence).

## What This Changes

This PR coalesces identical in-flight session-catalog and Workboard dispatch Gateway RPCs to reduce duplicate work while retaining each caller’s final response.

## System Context

The Gateway serves session-catalog requests and forwards Workboard card-dispatch requests from connected clients to providers and plugin runtime services. This PR inserts shared in-flight request coordination before those provider and dispatch operations, then returns RPC responses and progressive catalog events to each connection.

## Best Possible Solution

Retain one shared provider call, record each emitted catalog host, replay the recorded hosts to every later subscriber with that subscriber’s progress identifier, and add a focused late-join regression test plus redacted live Gateway proof.
