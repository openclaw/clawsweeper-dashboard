## Summary

The prior review’s two blockers remain visible at the current head; the PR also needs redacted after-fix Gateway behavior proof, not only mocked tests and pre-fix telemetry.

## What This Changes

The PR adds in-flight request coalescing for Gateway session-catalog listing and Workboard card dispatch calls to reduce repeated work during concurrent requests.

## System Context

Gateway RPC handlers receive requests from individual client connections and call catalog providers or the Workboard plugin. Catalog listing is a read that streams per-host progress, while Workboard dispatch starts work and therefore has per-command side effects.

## Architecture Diagram

flowchart LR
  Clients[Gateway clients] --> CatalogRequest[Session catalog list request]
  Clients --> DispatchRequest[Workboard dispatch request]
  CatalogRequest --> CatalogCoalescer[Catalog in-flight coalescing]
  CatalogCoalescer --> Provider[Catalog provider]
  Provider --> Progress[Per-connection progress events]
  DispatchRequest --> DispatchHandler[Workboard dispatch handler]
  DispatchHandler --> CardStarts[Start ready workboard cards]

## Best Possible Solution

Keep read-only catalog coalescing, but retain and replay emitted host progress to late joiners; remove parameter-only coalescing for mutating Workboard dispatches unless an explicit idempotency contract is designed and approved.
