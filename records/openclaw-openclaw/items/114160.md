## What This Changes

This PR coalesces concurrent matching Gateway session-catalog requests and Workboard card-dispatch calls to reduce duplicated provider and subagent work.

## System Context

Gateway RPC handlers accept requests from multiple connected clients, then call session-catalog providers or the bundled Workboard plugin. The changed layer decides whether callers share work and is responsible for returning each caller's response and progress notifications correctly.

## Architecture Diagram

flowchart LR

  C --> D[Session catalog provider]
  C --> E[Workboard dispatch pass]
  D --> F[Per-client progress events]
  D --> G[Catalog responses]
  E --> H[Subagent starts and results]

## Best Possible Solution

Keep session-catalog deduplication only if it records and replays each emitted host to newly joined callers, and remove the parameter-only Workboard dispatch deduplication unless a separately approved idempotency identity makes repeated commands explicitly equivalent.
