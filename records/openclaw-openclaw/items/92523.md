## Summary

Keep this issue open: current main and v2026.6.11 still leave `waiting` TaskFlows non-terminal with audit-only stale detection, and the direct fix PR closed unmerged because blanket wait expiry would be compatibility-sensitive without a TaskFlow deadline/orphan contract.

## What This Changes

The issue asks OpenClaw core to recover TaskFlows that remain in `waiting` forever so they do not permanently block heartbeat dispatch through `requests-in-flight`.

## Best Possible Solution

Define explicit controller-owned wait abandonment or deadline semantics, then wire recovery into the gateway/runtime owner that actually holds busy state and prove legitimate long waits are preserved.
