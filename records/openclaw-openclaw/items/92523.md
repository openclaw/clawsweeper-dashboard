## Summary

Keep this issue open: current main still leaves managed TaskFlows in `waiting` as non-terminal durable state, while the only direct fix PR is closed unmerged because blanket timeout semantics were unsafe. The report is credible, but the exact `flow_runs` to heartbeat `requests-in-flight` owner still needs maintainer-led diagnosis before a safe repair can be scoped.

## What This Changes

The issue requests recovery for orphaned TaskFlows stuck in `waiting` so they do not permanently block heartbeat dispatch through `requests-in-flight`.

## Best Possible Solution

Define explicit controller-owned wait abandonment or orphan predicates, then wire recovery into the gateway/runtime owner that actually holds `requests-in-flight`, with proof that legitimate durable waits are preserved.
