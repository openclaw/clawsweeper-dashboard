## Summary

Keep open: current main and v2026.6.11 still leave `waiting` TaskFlows durable and audit-only, while the direct fix attempt closed unmerged because blanket timeout semantics were not safe enough.

## What This Changes

The issue requests recovery for orphaned `waiting` TaskFlows so stale `flow_runs` rows cannot keep heartbeat work stuck on `requests-in-flight`.

## Best Possible Solution

Define explicit controller-owned wait deadline or abandonment semantics, then add gateway/runtime recovery proof that releases the actual busy owner without terminating valid durable waits.
