## Summary

Keep this issue open: current main and v2026.6.11 still leave old `waiting` TaskFlows non-terminal with audit-only stale detection, while the direct fix candidate was closed unmerged because blanket expiry would change plugin-visible wait semantics without live gateway proof.

## What This Changes

The issue reports that TaskFlow rows left in `waiting` status can keep a session counted as busy and cause future heartbeat wake attempts to skip as `requests-in-flight`.

## Best Possible Solution

Define a maintainer-approved TaskFlow abandonment or recovery contract, then implement the chosen core repair path with proof that truly orphaned waits stop blocking heartbeat dispatch while legitimate external waits remain safe.

- **Controller-declared deadlines:** Extend managed TaskFlow metadata so plugin controllers declare timeout/abandonment policy and core only expires flows with that contract.
