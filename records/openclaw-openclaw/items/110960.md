## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Authenticate widget tickets before reading the board store:** `src/gateway/board-http.ts:65`
  - body: `handleBoardHttpRequest` loads the widget document before it checks `bt`. Because this public route is outside the normal WebSocket/operator-auth flow and board reads can synchronously open/query an agent DB, malformed requests can consume database work without possessing a valid ticket. Parse and verify the ticket first, then read the document only after authentication succeeds.
  - confidence: 0.96
- **[P1] Bind grants to the reviewed widget revision:** `src/gateway/server-methods/board.ts:128`
  - body: The grant operation identifies only the session and widget name. If the agent replaces that widget after the operator reviews it but before the grant executes, the decision applies to the replacement revision and capability declaration. Carry the reviewed revision or digest and reject the grant atomically when it no longer matches.
  - confidence: 0.94
- **[P1] Provide an authorized rendering contract for MCP-app widgets:** `packages/gateway-protocol/src/schema/board.ts:35-47`
  - body: The public snapshot can report `contentKind: "mcp-app"`, but it exposes neither the persisted descriptor nor a usable authorized view URL; the board HTTP path only serves HTML documents. Such widgets cannot be rendered by a client, so either define a safely authorized MCP-app reconstruction contract or reject this unsupported kind for the initial landing.
  - confidence: 0.9
