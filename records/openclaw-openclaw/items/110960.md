Full review comments:

- **[P1] Authenticate tickets before reading the board store:** `src/gateway/board-http.ts:62-65`
  - body: Reject missing or invalid tickets before `readWidgetHtml` performs registry and SQLite work. As written, unauthenticated requests can synchronously probe registered agent boards on the gateway path, which makes the ticket endpoint an availability amplifier.
  - confidence: 0.95
- **[P1] Bind grants to the reviewed widget revision:** `src/gateway/server-methods/board.ts:125-132`
  - body: Include the reviewed widget revision or digest in `board.widget.grant` and reject stale decisions. A same-name widget can be replaced after review, so the current name-only grant can approve bytes and declared capabilities the operator never saw.
  - confidence: 0.94
- **[P1] Provide a renderable MCP-app widget contract:** `packages/gateway-protocol/src/schema/board.ts:36-49`
  - body: Do not expose `contentKind: "mcp-app"` until clients receive an authorized descriptor or renderable view. The HTTP server only serves HTML documents, while snapshots do not expose a usable MCP-app reconstruction handle.
  - confidence: 0.93
- **[P1] Expose widget creation through the dashboard tool:** `src/agents/tools/dashboard-tool.ts:21-32`
  - body: Add a `widget_put`-equivalent action or route dashboard composition through the existing widget tool. The new agent-facing dashboard tool only rearranges or removes widgets, so an agent with an empty board cannot create the widgets this feature promises it can compose.
  - confidence: 0.94
- **[P1] Publish the board-schema marker only after commit:** `src/boards/sqlite-board-store.ts:47-62`
  - body: Do not retain the `WeakSet` marker when the surrounding write transaction rolls back. Otherwise a failed first mutation on a v13 database without the additive tables can leave this process believing the tables exist, causing later operations to fail until restart.
  - confidence: 0.9
- **[P2] Enforce the documented widget-count limit:** `src/boards/board-store.ts:171-189`
  - body: Reject a new widget once the board reaches its documented maximum. Neither the protocol nor either store bounds distinct widget insertion, allowing oversized persisted snapshots and layouts beyond the supported dashboard contract.
  - confidence: 0.9
