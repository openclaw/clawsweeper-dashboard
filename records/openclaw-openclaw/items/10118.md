## Summary

Keep open: current main partially covers multiline TUI input through pi-tui defaults, but the remaining user-facing docs, /help coverage, and configurable send/newline keybinding decision are still unresolved.

## What This Changes

The issue asks OpenClaw TUI to keep Enter as send while supporting Shift+Enter for newline, with optional configurable send/newline keybindings and help/docs coverage.

## Best Possible Solution

Document the current pi-tui multiline and fallback behavior in TUI docs and /help, then let maintainers decide whether a TUI keybinding config or CLI bridge belongs in OpenClaw.

## Reproduction Assessment

Yes. Source inspection shows partial default newline support in the locked pi-tui package while OpenClaw docs, /help, CLI options, and config schema still omit the requested user-facing and configurable behavior.

## Solution Assessment

No, the current implementation is only a partial solution. Delegating to pi-tui covers default newline insertion where terminal sequences are recognized, but the best fix still needs docs/help coverage and a maintainer decision on configurable keybindings.
