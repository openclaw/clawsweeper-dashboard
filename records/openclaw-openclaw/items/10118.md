## Summary

Keep open: current main and the latest release already get inline Shift+Enter newline handling from pi-tui, but OpenClaw still does not document that behavior in TUI docs or /help and has no approved config/CLI bridge for configurable send/newline keybindings.

## What This Changes

Request multiline composition in `openclaw tui` with Enter preserved for send, Shift+Enter or equivalent newline insertion, optional configurable send shortcut, and docs/help updates.

## Best Possible Solution

Document the current Shift+Enter/Ctrl+J and backslash-enter fallback behavior in the TUI docs and /help, then add a configurable send/newline bridge only if maintainers approve the public keybinding contract.
