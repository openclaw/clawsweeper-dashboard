## Summary

Keep open: current main and v2026.6.11 cover the default Shift+Enter newline path through pi-tui, but OpenClaw still does not document that shortcut in TUI docs or /help and has no maintainer-approved configurable send/newline keybinding surface.

## What This Changes

Request TUI multiline composition where Enter sends, Shift+Enter inserts a newline, and optional configurable send/newline keybindings plus docs/help are added.

## Best Possible Solution

Document the current pi-tui multiline behavior, terminal limitations, and fallback in TUI docs and /help, then let maintainers decide whether OpenClaw should expose a default-preserving keybinding preference.

## Reproduction Assessment

Yes, source-level. Current main shows pi-tui handles default Shift+Enter newlines, while OpenClaw still lacks docs/help coverage and any TUI send/newline keybinding preference in options or CLI wiring.

## Solution Assessment

No final fix is present yet. Delegating editor input to pi-tui is the right default path, but closing would skip the remaining docs/help work and the maintainer decision on configurable keybindings.
