## Summary

Keep open: current main has dependency-backed Shift+Enter newline support, but OpenClaw still does not document multiline composition in TUI docs or `/help`, and configurable send/newline keybindings remain a maintainer product/config decision.

## What This Changes

The issue requests TUI multiline composition with Enter sending by default, Shift+Enter inserting newlines, optional configurable keybindings, and help/docs coverage.

## Best Possible Solution

Keep the dependency-backed Enter-to-send and newline behavior, document Shift+Enter/Ctrl+J/backslash-Enter fallback in TUI help and docs, and only add a keybinding preference after maintainers choose the public config shape.
