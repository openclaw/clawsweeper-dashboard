## Summary

Keep open: current main and the latest release have dependency-backed TUI newline insertion, but OpenClaw still does not document it in TUI docs or /help and has no supported TUI config/CLI bridge for configurable send/newline keybindings.

## What This Changes

The issue requests TUI multiline composition with Shift+Enter while keeping Enter as send, plus docs/help coverage and an optional configurable send/newline keybinding.

## Best Possible Solution

Document the existing TUI newline behavior and fallbacks in docs and /help, then add a public TUI keybinding preference only if maintainers explicitly accept that config/API surface.
