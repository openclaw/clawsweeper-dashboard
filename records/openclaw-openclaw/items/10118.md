## Summary

Keep this issue open but narrow it: current main inherits multiline composition from `pi-tui`, while OpenClaw still omits the shortcut and terminal limitations from TUI help/docs and has no OpenClaw-owned configurable send/newline preference. The related implementation PR is closed unmerged, and the other open composer requests cover distinct external-editor, modal-composer, or Vim workflows rather than owning this remaining TUI decision.

## What This Changes

Document and optionally configure TUI multiline composition while preserving Enter-to-send and supporting Shift+Enter for newline.

## Best Possible Solution

Keep the inherited Enter-to-send plus Shift+Enter/Ctrl+J newline behavior, document its terminal requirements and backslash-Enter fallback in TUI docs and `/help`, and add an OpenClaw-owned preference only if maintainers explicitly want a stable cross-version keybinding contract.
