## Summary

Keep open: current main has dependency-backed TUI newline insertion, but OpenClaw still does not document multiline composition in the TUI guide or /help, and configurable TUI send/newline keybindings remain a maintainer product/config decision.

## What This Changes

The issue requests TUI multiline composition with Enter continuing to send by default and Shift+Enter or a configurable keybinding inserting newlines.

## Best Possible Solution

Keep the pi-tui default newline behavior, document the current multiline shortcut and terminal fallback behavior in TUI docs and /help, and add configurable TUI send keys only after maintainers choose the public config shape.
