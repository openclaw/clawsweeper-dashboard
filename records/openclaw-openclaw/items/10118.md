## Summary

Keep open: current main has dependency-backed TUI newline insertion, but OpenClaw still does not document it in the TUI guide or /help, and a configurable TUI send/newline keybinding remains an explicit product/config decision.

## What This Changes

Request TUI multiline composition with Enter-to-send preserved, Shift+Enter or equivalent newline insertion, optional configurable send behavior, and TUI docs/help coverage.

## Best Possible Solution

Keep pi-tui newline handling as the current default, document Shift+Enter, Ctrl+J, terminal limitations, and backslash-Enter fallback in TUI docs and /help, and add configurable TUI send keys only after maintainers choose the public config/API shape.
