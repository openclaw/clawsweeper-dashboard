## Summary

Keep open: current main partially satisfies the default multiline path through the pinned pi-tui editor, but OpenClaw still lacks user-facing TUI docs, `/help` shortcut coverage, and a maintainer-approved configurable send/newline keybinding surface.

## What This Changes

The issue requests TUI multiline composition via Shift+Enter while keeping Enter as send, with optional configurable send/newline bindings and help/docs coverage.

## Best Possible Solution

Document the current pi-tui multiline behavior and fallback in TUI docs and `/help`, then let maintainers decide whether a TUI keybinding config or CLI bridge belongs in OpenClaw.

## Reproduction Assessment

Yes. Current-main source shows the remaining gap: no OpenClaw-owned send/newline keybinding preference, slash help is command-only, and public TUI docs still list only Enter-to-send while dependency source provides only partial default behavior.

## Solution Assessment

No, current main is not the complete solution. Delegating to pi-tui covers the default Shift+Enter path where terminals support it, but the maintainable finish is docs/help coverage plus an explicit maintainer decision before adding configuration.
