## Summary

Keep open: current main and the latest release partially support multiline TUI input through the pinned pi-tui editor, but OpenClaw still lacks TUI docs, `/help` shortcut coverage, and a maintainer-approved configurable send/newline keybinding surface.

## What This Changes

Request support for composing multiline TUI messages with Enter remaining send by default, Shift+Enter inserting a newline, and optional configurable send/newline keybindings plus help/docs coverage.

## Best Possible Solution

Document current TUI multiline composition behavior and terminal fallback in docs and `/help`, then add default-preserving keybinding preferences only if maintainers approve that public config or CLI surface.

## Reproduction Assessment

Yes. Source inspection shows the remaining gap: `/help` and docs omit multiline composition, and current TUI options/config expose no send/newline keybinding preference; the default Shift+Enter path is dependency-backed rather than an OpenClaw-visible contract.

## Solution Assessment

No, current main is not complete enough to close. Delegating default editing to pi-tui is a reasonable base, but the maintainable end state still needs docs/help coverage and a maintainer decision before adding keybinding config.
