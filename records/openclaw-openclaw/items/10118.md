## Summary

Keep this issue open for a maintainer scope decision. Current main still delegates ordinary editor keys to `pi-tui`, so multiline input may work through that dependency, but OpenClaw’s current TUI guide documents only Enter-to-send and does not define or expose a supported configurable send/newline preference. Likely related people: steipete is the strongest routing candidate (medium confidence) from the TUI wrapper, submission, docs, and earlier issue review history.

## What This Changes

Support reliable multiline composition in `openclaw tui` while keeping Enter-to-send by default, with optional configurable send-key behavior and documented shortcuts.

## System Context

The terminal UI accepts keyboard input through an OpenClaw editor wrapper, then sends submitted text to the Gateway or embedded local runtime. The wrapper handles OpenClaw-specific shortcuts and delegates ordinary editing keys to the bundled `pi-tui` editor.

## Best Possible Solution

Document the current multiline behavior and terminal limitations in the TUI guide and shortcut help first; add a configurable keybinding only after a maintainer explicitly selects a stable TUI configuration contract and its upgrade behavior.
