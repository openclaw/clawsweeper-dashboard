## Summary

Keep open: current main partially covers inline multiline TUI composition through the pinned pi-tui editor, but OpenClaw still does not document the newline shortcut in TUI docs or /help and still has no approved configurable send/newline keybinding surface.

## What This Changes

The issue requests TUI multiline message composition where Enter remains send and Shift+Enter, or a configurable keybinding, inserts a newline.

## Best Possible Solution

Document the current pi-tui multiline shortcuts and fallback behavior in TUI docs and /help, then add a narrow TUI send/newline keybinding bridge only if maintainers approve that public surface.
