## Summary

Keep open: current main and the latest release partially cover default Shift+Enter/newline handling through the pinned pi-tui editor, but OpenClaw still lacks TUI docs, /help shortcut coverage, and a maintainer-approved configurable send/newline keybinding surface.

## What This Changes

Request support for multiline TUI composition with Enter sending by default, Shift+Enter inserting a newline, optional configurable send/newline keybindings, and help/docs coverage.

## Best Possible Solution

Document the current pi-tui multiline behavior and terminal fallback in TUI docs and /help, then add default-preserving keybinding preferences only after maintainers approve the public config or CLI surface.

## Reproduction Assessment

Yes. Source inspection shows the missing remaining behavior: /help and docs omit multiline composition, and current TUI config/options expose no send/newline keybinding preference; the default Shift+Enter path is dependency-backed rather than an OpenClaw-visible setting.

## Solution Assessment

No, current main is not complete enough to close. Delegating to pi-tui is a good default behavior, but the maintainable end state still needs docs/help coverage and a maintainer decision before adding config.
