## Summary

Keep open: current main and v2026.6.11 already have dependency-backed Shift+Enter newline behavior, but the TUI still lacks docs, /help shortcut coverage, and an approved configurable send/newline keybinding surface.

## What This Changes

The issue requests TUI multiline composition with Enter kept as send by default, Shift+Enter inserting a newline, and optional configurable send/newline keybindings with help/docs coverage.

## Best Possible Solution

Document the current pi-tui multiline behavior and terminal fallbacks in the TUI docs and /help, then add a default-preserving TUI keybinding preference only if maintainers approve the public settings surface.

## Reproduction Assessment

Yes, source-level. Current main delegates newline insertion to pi-tui, but OpenClaw docs and /help omit the shortcut and the TUI exposes no configurable send/newline preference.

## Solution Assessment

No final fix is present yet. Delegating default editing to pi-tui is the right baseline, but the maintainable completion still needs docs/help coverage and maintainer approval before adding config or CLI surface.
