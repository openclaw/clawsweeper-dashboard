## Summary

Keep open: current main partially satisfies the default newline request through pi-tui, but OpenClaw still does not document multiline composition in TUI docs or /help and still has no approved configurable send/newline keybinding surface.

## What This Changes

Request multiline composition in `openclaw tui` with Shift+Enter inserting a newline while Enter continues to send, plus optional configurable keybindings and help/docs coverage.

## Best Possible Solution

Document the current pi-tui multiline shortcuts and fallback behavior in TUI docs and /help, then add a narrow TUI send/newline keybinding bridge only if maintainers approve that public surface.
