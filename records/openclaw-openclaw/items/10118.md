## Summary

Keep open: current main already gets newline insertion from pi-tui, but OpenClaw still does not document the TUI newline shortcuts in docs or /help, and a configurable TUI send/newline keybinding remains a product/config decision.

## What This Changes

The issue requests TUI multiline composition where Enter sends by default and Shift+Enter or a configurable keybinding inserts newlines.

## Best Possible Solution

Keep the existing pi-tui newline handling, document Shift+Enter, Ctrl+J, terminal limitations, and the backslash-enter fallback in TUI docs and /help, and add configurable TUI send keys only after maintainers choose the public config/API shape.
