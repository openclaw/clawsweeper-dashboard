## Summary

Keep open: current main and v2026.6.11 partially satisfy inline multiline input through the pinned `pi-tui` editor, but OpenClaw still does not document the TUI newline keybinding in docs or `/help`, and there is no maintainer-approved TUI config/CLI bridge for configurable send/newline preferences.

## What This Changes

The issue requests TUI multiline composition with Enter kept as send and Shift+Enter or configurable keybindings for newline insertion.

## Best Possible Solution

Keep this issue open and narrow it to documenting current multiline composition plus terminal fallback behavior, then have maintainers decide whether OpenClaw should expose a TUI keybinding preference that bridges into `pi-tui`.

## Reproduction Assessment

Yes, source-level. Current main shows partial default Shift+Enter support through `pi-tui`, but the OpenClaw docs, `/help`, CLI options, and TUI config types still lack the requested discoverability and configurable keybinding surface.

## Solution Assessment

Unclear until maintainers settle the product scope. The maintainable path is docs/help for the existing dependency behavior first, with any configurable keybinding added only after an explicit config/CLI boundary decision.
