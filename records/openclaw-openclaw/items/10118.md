## Summary

Keep open: current main has dependency-backed newline insertion and preserves multiline payloads, but OpenClaw still does not document newline composition in TUI docs or `/help`, and configurable send/newline keybindings remain a product/config decision. The related implementation PR is closed and unmerged, while adjacent WebChat and external-editor items only partially overlap this TUI request.

## What This Changes

The issue requests multiline composition in `openclaw tui`, with Enter continuing to send and Shift+Enter or a configurable keybinding inserting newlines.

## Best Possible Solution

Keep the pi-tui-backed Enter-to-send/newline behavior, document Shift+Enter/Ctrl+J/backslash-Enter fallback in TUI docs and `/help`, and add configurable keybindings only after maintainers choose the public config shape.
