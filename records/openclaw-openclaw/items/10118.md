## Summary

Keep open: current main has dependency-backed Shift+Enter/Ctrl+J newline insertion, but OpenClaw still does not expose or document the TUI keybinding behavior in `/help` or TUI docs, and configurable TUI send/newline bindings remain a product/config decision.

## What This Changes

The issue requests TUI multiline composition with Enter kept as send, Shift+Enter inserting a newline, optional configurable send/newline bindings, and help/docs coverage.

## Best Possible Solution

Document the existing pi-tui newline keys and fallbacks in TUI docs and `/help`, then add configurable send/newline bindings only after maintainers choose the public TUI config or CLI contract.
