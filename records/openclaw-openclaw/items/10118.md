## Summary

Keep open: current main and the latest release only partially satisfy the request through the inherited pi-tui editor defaults; OpenClaw still does not document multiline TUI composition in docs or /help and has no maintainer-approved configurable send/newline keybinding surface.

## What This Changes

The issue asks for `openclaw tui` to keep Enter as send while supporting Shift+Enter, or a configurable keybinding, for composing multiline messages.

## Best Possible Solution

Document the current pi-tui multiline behavior and terminal fallback in TUI docs and /help, then let maintainers decide whether a TUI keybinding config or CLI bridge belongs in OpenClaw.

## Reproduction Assessment

Yes. Current-main source and the inspected pi-tui package show partial default newline support, while OpenClaw source shows no keybinding preference and no docs/help coverage for multiline composition.

## Solution Assessment

No. The current dependency default is only a partial solution; the maintainable path is documentation/help for existing behavior plus a maintainer decision before adding a public keybinding configuration surface.
