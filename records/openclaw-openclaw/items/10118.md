## Summary

Keep open: current main and the latest release partially satisfy multiline TUI input through the pinned pi-tui editor, but OpenClaw still does not document newline composition in TUI docs or `/help`, and no configurable send/newline binding surface exists.

## What This Changes

The issue requests TUI multiline composition where Enter remains send and Shift+Enter or a configurable binding inserts a newline.

## Best Possible Solution

Document the existing Shift+Enter and fallback behavior in the public TUI guide and `/help`, then add a config or CLI bridge into pi-tui keybindings only after maintainers approve the preference boundary.

## Reproduction Assessment

Yes for the remaining gap: source inspection shows Shift+Enter is dependency-backed, while current main and v2026.6.11 still omit TUI docs, `/help` shortcut coverage, and any configurable send/newline option.

## Solution Assessment

No final fix is present. The maintainable path is to document the shipped behavior first and let maintainers decide whether OpenClaw should expose a user-facing keybinding preference.
