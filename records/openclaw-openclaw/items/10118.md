## Summary

Keep open: current main and the latest release already inherit default multiline composition from pi-tui, but this issue also asks for user-visible TUI docs/help coverage and optional configurable send/newline behavior, which remain unresolved and need maintainer product judgment.

## What This Changes

This issue requests TUI multiline composition with Enter kept as send, Shift+Enter as newline, optional configurable send/newline keybindings, and docs/help hints.

## Best Possible Solution

Document the current pi-tui Shift+Enter, Ctrl+J, and backslash-enter multiline behavior in TUI docs and /help, keep Enter-to-send as the default, and have maintainers decide whether OpenClaw should expose a TUI keybinding config or CLI bridge.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 show dependency-backed default multiline support, while OpenClaw source still has no TUI keybinding preference and no docs/help coverage for multiline composition.

## Solution Assessment

No, the current implementation is only a partial solution. Delegating to pi-tui covers default newline behavior where terminal sequences are recognized, but the requested docs/help and optional configurable send/newline behavior remain open product work.
