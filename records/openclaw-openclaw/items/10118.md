## Summary

Keep open: current main has dependency-backed Shift+Enter newline insertion and multiline submit preservation, but OpenClaw still does not document newline composition in TUI docs or `/help`, and standalone TUI does not expose a supported send/newline keybinding preference.

## What This Changes

The issue requests TUI multiline composition where Enter remains the default send key and Shift+Enter or configurable keybindings insert newlines.

## Best Possible Solution

Document the current pi-tui multiline shortcuts and terminal-dependent fallbacks in TUI docs and `/help`, then make a maintainer decision on whether to wire a supported TUI keybinding preference into the standalone TUI.
