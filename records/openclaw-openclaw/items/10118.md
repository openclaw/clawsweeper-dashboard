## Summary

Keep open: current main and the latest release have dependency-backed newline insertion, but OpenClaw still omits TUI docs/help for newline composition and fallback behavior, and it has no supported configurable send/newline keybinding surface.

## What This Changes

The issue requests TUI multiline message composition with Enter preserved as send, Shift+Enter inserting a newline, optional configurable send/newline keybindings, and visible help/docs.

## Best Possible Solution

Document the current Shift+Enter/Ctrl+J/backslash-Enter behavior in TUI docs and /help, then add a supported TUI keybinding preference only if maintainers choose that public config surface.
