## Summary

Keep open: current main already gets inline newline insertion from the pinned pi-tui editor, but OpenClaw still does not document the TUI newline shortcuts in docs or `/help`, and configurable TUI send/newline keybindings remain a product/config decision.

## What This Changes

The issue requests TUI multiline composition where Enter keeps sending by default and Shift+Enter inserts a newline, with optional configurable send/newline keybindings and user-facing help/docs.

## Best Possible Solution

Document the existing TUI multiline keys and fallbacks now, then make a maintainer decision on whether a TUI keybinding preference should exist and where it should live.
