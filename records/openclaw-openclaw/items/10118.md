## Summary

Keep open: current main and the latest release already have dependency-backed default Shift+Enter newline composition, but the TUI docs, slash-command help, and any configurable send/newline keybinding surface still do not cover the requested behavior.

## What This Changes

Request TUI multiline composition where Enter sends, Shift+Enter inserts a newline, and optionally a configurable send/newline keybinding with docs and help hints.

## Best Possible Solution

Keep the dependency-backed default behavior, document the actual TUI newline shortcuts and fallbacks in docs and /help, and only add a TUI send-key preference after a maintainer chooses the config/API shape.

## Reproduction Assessment

Source-reproducible rather than live-reproduced: current source and dependency inspection show default multiline composition exists, while docs, /help, and config/CLI keybinding support are still absent.

## Solution Assessment

No, closing this as implemented would be too broad; relying on pi-tui is the right default implementation layer, but the remaining docs/help and configurable-keybinding decision still need OpenClaw ownership.
