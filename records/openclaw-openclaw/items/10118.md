## Summary

Keep open: current main and v2026.6.11 inherit default Shift+Enter newline support from pi-tui, but OpenClaw still lacks TUI docs, /help shortcut coverage, and any maintainer-approved configurable TUI send/newline keybinding surface.

## What This Changes

Request TUI multiline composition with Enter remaining send, Shift+Enter inserting a newline, optional configurable send key behavior, and docs/help hints.

## Best Possible Solution

Document the current pi-tui multiline behavior, terminal limitations, and fallback in TUI docs and /help, then let maintainers decide whether a TUI keybinding config or CLI bridge belongs in OpenClaw.

## Reproduction Assessment

Yes. Current-main source and the pi-tui 0.80.3 package show partial default newline support, while OpenClaw source shows no configurable keybinding preference and no docs/help coverage for multiline composition.

## Solution Assessment

No final fix is present yet. Delegating to pi-tui is a good baseline, but the maintainable completion is docs/help coverage plus a maintainer decision before adding any public keybinding configuration surface.
