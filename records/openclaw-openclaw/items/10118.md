## Summary

Keep open: current main has dependency-backed TUI newline composition, but OpenClaw still does not document the keys in TUI docs or /help and does not expose the requested configurable send/newline keybinding surface.

## What This Changes

The issue asks for TUI multiline composition where Enter still sends, Shift+Enter inserts a newline, and docs/help optionally describe or configure that keybinding.

## Best Possible Solution

Keep the dependency-backed Enter-to-send default, document Shift+Enter/Ctrl+J and fallback behavior in TUI docs and /help, and only add a TUI keybinding preference after maintainers choose the public config/API shape.
