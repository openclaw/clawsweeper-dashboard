## Summary

Keep open: current main and the latest release already have dependency-backed TUI newline insertion, but OpenClaw still does not document the newline/fallback behavior in TUI docs or /help and has no supported CLI/config bridge for configurable send/newline keybindings.

## What This Changes

The issue requests TUI multiline composition with Enter still sending, Shift+Enter inserting a newline, optional configurable send/newline keybindings, and docs/help coverage.

## Best Possible Solution

Document current Shift+Enter/Ctrl+J/backslash-Enter behavior in TUI docs and /help, then add a supported TUI keybinding preference only if maintainers approve that public surface.
