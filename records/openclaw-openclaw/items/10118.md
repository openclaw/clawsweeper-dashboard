## Summary

Keep open: current main has dependency-backed TUI newline insertion, but OpenClaw still lacks TUI docs/help coverage for the newline keys and has no maintainer-approved configurable send/newline keybinding surface.

## What This Changes

The issue requests TUI multiline message composition where Enter sends by default and Shift+Enter inserts a newline, with optional configurable send/newline keybinding behavior and docs/help coverage.

## Best Possible Solution

Document the existing pi-tui newline keys and fallback in the TUI guide and /help, then add configurable TUI keybindings only if maintainers approve the new config or CLI contract.
