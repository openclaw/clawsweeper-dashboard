## Summary

Keep open: current main has dependency-backed inline newline insertion, but OpenClaw still lacks TUI docs/help coverage for the shortcut and the configurable send/newline keybinding choice remains a product/config decision.

## What This Changes

The issue requests TUI multiline composition with Enter still sending by default, Shift+Enter inserting a newline, optional configurable send behavior, and help/docs coverage.

## Best Possible Solution

Document the existing Shift+Enter/Ctrl+J newline behavior and fallbacks in the TUI guide and /help, then add configurable TUI send/newline keybindings only after maintainers approve the config/API shape.
