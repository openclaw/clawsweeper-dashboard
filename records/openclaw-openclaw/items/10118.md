## Summary

Keep open: current main already gets Shift+Enter/Ctrl+J newline insertion from the pinned pi-tui editor, but OpenClaw still omits that behavior from the TUI docs and /help, and a configurable send/newline keybinding bridge remains a product/config decision.

## What This Changes

Request Shift+Enter newline composition in `openclaw tui` while keeping Enter as send, with optional configurable keybinding and help/docs coverage.

## Best Possible Solution

Document the existing pi-tui multiline bindings in public TUI docs and `/help`, then add a default-preserving bridge to pi-tui keybindings only if maintainers explicitly want configurable send/newline preferences.
