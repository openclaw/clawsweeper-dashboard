## Best Possible Solution

Document the current pi-tui newline behavior and terminal fallback in TUI docs and /help, then add default-preserving keybinding preferences only if maintainers approve the public config or CLI surface.

## Reproduction Assessment

Yes. Source inspection shows the remaining missing behavior: TUI docs and /help omit newline composition, and current TUI config/options expose no send/newline keybinding preference.

## Solution Assessment

No, current main is only a partial solution. Delegating default Shift+Enter handling to pi-tui is the right low-level path, but closing would skip the visible docs/help work and the maintainer decision on configurable keybindings.
