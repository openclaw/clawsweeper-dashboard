## Summary

Keep open: current main has dependency-backed Shift+Enter/Ctrl+J newline handling, but OpenClaw still does not document the TUI newline behavior in docs or /help and has no approved public keybinding/config bridge for send/newline preferences.

## What This Changes

The issue requests TUI multiline composition where Enter sends, Shift+Enter inserts a newline, and optional keybinding/config/help documentation covers the behavior.

## Best Possible Solution

Document the current pi-tui-backed Shift+Enter/Ctrl+J/backslash fallback in TUI docs and /help, then add a configurable send/newline keybinding bridge only if maintainers approve that public config surface.
