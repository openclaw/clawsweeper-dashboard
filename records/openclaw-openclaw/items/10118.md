## Summary

Keep open: current main already gets Shift+Enter newline insertion from the pinned pi-tui editor, but OpenClaw still does not expose the behavior in TUI docs or in-product help, and configurable TUI send/newline keybindings remain a product decision.

## What This Changes

The issue requests multiline TUI composition with Enter sending by default, Shift+Enter inserting a newline, optional configurable send/newline keybindings, and docs/help visibility.

## Best Possible Solution

Document the existing pi-tui newline keys and fallbacks in the TUI guide and /help, then add configurable TUI keybindings only if maintainers approve that public config or CLI contract.
