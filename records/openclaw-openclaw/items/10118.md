## Summary

Keep this issue open for a maintainer scope decision. The central multiline capability is already supplied by the TUI’s `pi-tui` editor path, but the requested user-facing discovery remains incomplete and the discussion adds an unresolved question of whether OpenClaw should own a persistent configurable send/newline preference rather than duplicate upstream key handling.

## What This Changes

Request that `openclaw tui` preserve Enter-to-send while enabling multiline composition with Shift+Enter or an approved configurable shortcut, and expose the behavior in help and TUI documentation.

## Best Possible Solution

Document the existing multiline shortcut and terminal-dependent fallback in the TUI guide and in-product help, then add a persistent keybinding preference only if a maintainer explicitly sponsors that OpenClaw-owned contract.
