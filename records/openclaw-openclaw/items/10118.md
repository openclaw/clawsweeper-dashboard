## Summary

Keep open: current main has dependency-backed inline newline input, but OpenClaw still does not document the TUI newline shortcuts in docs or `/help`, and configurable send/newline behavior remains a product/config-surface decision.

## What This Changes

The issue requests TUI multiline composition with Enter kept as send, Shift+Enter or an equivalent newline shortcut, optional configurable send behavior, and docs/help coverage.

## Best Possible Solution

Document the current pi-tui Shift+Enter, Ctrl+J, and backslash-enter behavior in TUI docs and `/help`, then add a narrow configurable keybinding bridge only if maintainers approve that public surface.
