## Summary

Keep this issue open for a maintainer scope decision. Current `openclaw tui` delegates editor input to `pi-tui`, whose Editor already supports terminal-dependent modified-Enter newlines, but the current TUI guide still documents only Enter-to-send and no OpenClaw-owned configurable send/newline preference exists.

## What This Changes

Support and document multiline composition in `openclaw tui` while retaining Enter-to-send, optionally with a configurable send shortcut.

## Best Possible Solution

Document the inherited Pi editor shortcuts and terminal limitations in the TUI guide and in-product help; add a configurable OpenClaw keybinding preference only if maintainers explicitly want to own that public contract.

Options:

- **Document existing behavior (recommended):** Add TUI help and docs for Pi's modified-Enter newline shortcuts, their terminal-dependent nature, and the available fallback; do not add a new config surface.
- **Own a keybinding preference:** Design a canonical TUI configuration contract that wires a selected send/newline mapping into the editor, with documented defaults and focused compatibility tests.
- **Defer the preference:** Keep the current inherited behavior and defer both expanded documentation and configuration until TUI input ergonomics are planned as a broader product slice.
