## Summary

Keep open: current main and the latest release partially cover default multiline input through the pinned `pi-tui` editor, but OpenClaw still lacks TUI docs, `/help` shortcut coverage, and a maintainer-approved configurable send/newline keybinding surface.

## What This Changes

The issue requests TUI multiline composition with Enter kept as send, Shift+Enter inserting a newline, optional configurable send/newline keybindings, and help/docs coverage.

## Best Possible Solution

Document the current `pi-tui` multiline behavior and terminal fallback in TUI docs and `/help`, then let maintainers decide whether a TUI keybinding config bridge belongs in OpenClaw.

## Reproduction Assessment

Yes. Current-main source shows no OpenClaw keybinding preference in `TuiOptions`, `/help` is slash-command-only, and docs still list only Enter-to-send; the default Shift+Enter path is source-proven through the pinned `pi-tui` dependency rather than by an interactive terminal run.

## Solution Assessment

No, this is not solved well enough to close. Delegating editor input to `pi-tui` covers part of the default newline behavior, but the best maintainable solution still needs docs/help coverage and an explicit maintainer decision before adding config.
