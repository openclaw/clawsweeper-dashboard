## Summary

Keep open: current main already inherits dependency-backed TUI multiline insertion, but the requested user-facing TUI shortcut behavior is only partly satisfied because OpenClaw still lacks TUI docs/help coverage and any supported configurable send/newline keybinding contract.

## What This Changes

The issue requests TUI multiline composition with Shift+Enter for newline while keeping Enter as send, with discussion extending the need to configurable send/newline behavior.

## Best Possible Solution

Keep the dependency-backed newline behavior, document the supported terminal-dependent newline shortcuts and fallback in the TUI guide and /help, and add configurable TUI send keys only after maintainers choose the public keybinding contract.
