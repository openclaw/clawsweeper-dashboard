## Summary

Keep open: current main and the latest release partially cover default multiline input through pi-tui, but OpenClaw still lacks TUI docs, /help shortcut coverage, and a maintainer-approved configurable send/newline keybinding surface.

## What This Changes

The issue requests TUI multiline composition where Enter sends and Shift+Enter, or a configurable keybinding, inserts a newline.

## Best Possible Solution

Document the current pi-tui multiline behavior and terminal fallback in TUI docs and /help, then let maintainers decide whether a TUI keybinding config bridge belongs in OpenClaw.

## Reproduction Assessment

Yes. Current-main source and the exact locked pi-tui package show partial default newline support, while OpenClaw source shows no keybinding preference and no docs/help coverage for multiline composition.

## Solution Assessment

No, the current behavior is only a partial solution. Delegating to pi-tui covers default Shift+Enter/newline behavior where terminal sequences are recognized, but the issue still asks for user-visible docs/help and optional configurable send/newline behavior.
