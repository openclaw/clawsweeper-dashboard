## What This Changes

The PR changes Android Voice-tab microphone capture to treat negative `AudioRecord.read` return values as fatal transcription failures and refreshes native i18n source line numbers.

## Best Possible Solution

Land the narrow Voice-tab negative-read failure path after redacted hardware or runtime proof is added, and track TalkModeManager’s identical capture-loop behavior separately if maintainers want full realtime-talk coverage.

## Reproduction Assessment

Yes, source-reproducible: current main directly loops on `read <= 0` after `AndroidAudioInputSession.read`, and Android documents negative `AudioRecord.read` error codes such as `ERROR_DEAD_OBJECT`. I did not run the Bluetooth or USB hot-unplug hardware path.

## Solution Assessment

Yes for the Voice-tab transcription path: treating `read < 0` as fatal while preserving `read == 0` as transient is the narrowest maintainable fix and reuses existing `failTranscription` cleanup. It is not a complete sibling-surface fix because TalkModeManager still needs a separate decision or follow-up.
