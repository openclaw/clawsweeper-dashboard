## Summary

Keep this PR open for revision. Current main already suppresses recovered exec warnings after a completed message-tool source reply, but this patch broadens recovery proof to any visible message-tool delivery; that can hide a genuine later exec failure after a progress or partial message. The PR also needs redacted after-fix Slack or terminal evidence showing the distinct path that current main does not cover.

## What This Changes

This PR counts visible messaging-tool output as a user-facing reply so recovered exec failures do not emit a trailing channel warning.

## System Context

Embedded agent runs collect tool errors and outbound-delivery state, then build final channel payloads at turn completion. The warning policy decides whether to append an exec-failure notice after the agent's visible output has been delivered.

## Best Possible Solution

Keep recovery suppression tied to a terminal, successful user-facing completion signal; if generic messaging-tool sends must qualify, define that lifecycle contract explicitly and add tests proving progress-only sends still preserve genuine later exec-failure notices.
