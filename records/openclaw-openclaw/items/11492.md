## Summary

Keep open: current main and v2026.6.11 still do not expose Slack `channel-info` or `channel-list` as agent-facing message actions, and the only open implementation candidate is a broad conflicting PR with human-review/security/proof blockers.

## What This Changes

The issue requests Slack message-tool actions that let agents resolve Slack channel IDs to channel metadata and list available Slack conversations.

## Best Possible Solution

Land or split a focused Slack plugin change that exposes both `channel-info` and `channel-list` through discovery, dispatch, runtime helpers, public exports, docs, and tests while preserving Slack read-target authorization and token boundaries.

## Reproduction Assessment

Yes, at source level: current main's Slack discovery, dispatch, runtime, docs, and tests omit `channel-info` and `channel-list`, while Discord exposes the sibling actions behind `channelInfo`. I did not run a live Slack workspace because the requested actions are absent before any Slack API call can happen.

## Solution Assessment

Yes on owner boundary, but not yet on merge path. The narrow implementation belongs in `extensions/slack`; maintainers should repair, split, or close the broad open Slack parity PR before queueing duplicate automated work.
