## Summary

Keep open: current main and the latest release still omit the requested Slack `channel-info` and `channel-list` message actions, and the open Slack parity candidate is broad, dirty, human-review gated, and not a safe superseding fix yet.

## What This Changes

The issue requests Slack `channel-info` and `channel-list` message actions so agents can resolve Slack channel IDs and discover workspace channels similarly to Discord.

## Best Possible Solution

Land a focused Slack plugin change, or repair and narrow the open Slack parity PR, so both `channel-info` and `channel-list` are opt-in, authorized consistently with Slack read policy, tested, documented, and proven in a real Slack workspace.

## Reproduction Assessment

Yes, source-reproducible: current Slack discovery, dispatch, runtime exports, tests, docs, and the latest release omit `channel-info` and `channel-list`. This is a feature gap rather than a failing existing behavior repro.

## Solution Assessment

Yes for keeping it open: the maintainable solution belongs in `extensions/slack` with action discovery, dispatch, runtime helpers, tests, docs, and Slack read-authorization review.
