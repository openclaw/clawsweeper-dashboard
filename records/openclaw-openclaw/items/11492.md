## Summary

Current `main` still does not expose Slack `channel-info` or `channel-list` as Slack message actions, and the only open related implementation is a broad, unmerged Slack parity PR with human-review/security/proof blockers, so this issue remains necessary.

## What This Changes

Request to expose Slack `channel-info` and `channel-list` message actions so agents can resolve Slack channel IDs to readable channel metadata.

## Best Possible Solution

Land or split a focused Slack plugin change that exposes both requested actions through discovery, dispatch, runtime helpers, public exports, docs, and tests while preserving Slack read-target authorization and token boundaries.

## Reproduction Assessment

Yes, at source level: current main’s Slack action discovery omits `channel-info` and `channel-list`, and the dispatcher/runtime have no branches or helpers for those actions.

## Solution Assessment

Yes on owner boundary, but not yet on merge path: the implementation belongs in `extensions/slack`, while the broad related PR needs security/proof/mergeability decisions or a focused split before it is the best landing vehicle.
