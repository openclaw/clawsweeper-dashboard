## Summary

Keep open: current main and v2026.6.11 still omit Slack `channel-info` and `channel-list` from agent-facing message actions, while the only open implementation path is a broad protected PR with human-review and security/product blockers.

## What This Changes

Request to add Slack `channel-info` and `channel-list` message actions so agents can resolve Slack channel IDs to human-readable channel metadata and lists.

## Best Possible Solution

Land or split a focused Slack plugin change that exposes both requested actions through discovery, dispatch, runtime helpers, public exports, docs, and tests while preserving Slack authorization and token boundaries.

## Reproduction Assessment

Yes, at source level. Current main's Slack discovery omits `channel-info` and `channel-list`, and the Slack dispatcher would reject those actions as unsupported.

## Solution Assessment

Yes on owner boundary, but not as a duplicate automated fix right now. The implementation belongs in `extensions/slack`, and maintainers should repair or split the broad related PR before landing it.
