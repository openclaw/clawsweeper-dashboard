## Summary

Keep open: current main and v2026.6.11 still omit Slack `channel-info` and `channel-list` as agent-facing message actions, while the only open related implementation path is a broad Slack parity PR with human-review, security, compatibility, and proof blockers.

## What This Changes

The issue requests Slack `channel-info` and `channel-list` message actions so agents can resolve Slack channel IDs and list available conversations.

## Best Possible Solution

Land or split a focused Slack plugin change that exposes both requested actions through discovery, dispatch, runtime helpers, public exports, docs, and tests while preserving Slack read-target authorization and token boundaries.

## Reproduction Assessment

Yes, at source level: current main's Slack discovery omits `channel-info` and `channel-list`, and the dispatcher/runtime have no branches or helpers for those actions. No live Slack workspace run was needed to prove absence.
