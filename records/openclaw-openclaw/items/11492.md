## Summary

Current main still does not expose Slack `channel-info` or `channel-list` as agent-facing message actions, so this remains a valid open feature request. The related broad Slack parity PR is only a candidate and is currently unmerged with human-review/security blockers, so it should not be treated as implemented.

## What This Changes

The issue requests Slack agent message actions for `channel-info` and `channel-list` so agents can resolve Slack channel IDs to names and metadata.

## Best Possible Solution

Land or split a reviewed Slack-plugin implementation that exposes both requested actions through discovery, dispatch, runtime helpers, public exports, docs, and focused tests without broadening unrelated Slack scope.

## Reproduction Assessment

Yes. Source inspection on current main shows Slack discovery, dispatch, runtime helpers, public exports, docs, and tests omit `channel-info` and `channel-list` even though the shared message-action list supports those names.

## Solution Assessment

Yes in direction, but not as a close. The best implementation belongs inside `extensions/slack` using the existing plugin action patterns, with maintainer review for the new action surface and any config gating choice.
