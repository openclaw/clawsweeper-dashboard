## Summary

Keep open: current main and the latest release still do not expose Slack `channel-info` or `channel-list` as agent-facing message actions, and the only live same-repo implementation path is a broad conflicting PR that is human-review blocked.

## What This Changes

The issue requests Slack `channel-info` and `channel-list` message actions so agents can resolve Slack channel IDs to human-readable names, topics, purposes, and workspace channel lists.

## Best Possible Solution

Land or split a focused Slack plugin change that exposes both requested actions through discovery, dispatch, runtime helpers, public exports, docs, and tests while preserving Slack read-target authorization and token boundaries.

## Reproduction Assessment

Yes, at source level. Current main's Slack discovery omits `channel-info` and `channel-list`, and the dispatcher/runtime have no branches or helpers for those actions.

## Solution Assessment

Yes on owner boundary, but not yet on merge path. The implementation belongs in `extensions/slack`; maintainers should either repair/split the broad related PR or land a narrower focused change.
