## Summary

Current main and the latest release still omit both requested Slack actions, and every related implementation path is closed, partial, overly broad, or conflicting. The request is technically coherent and belongs in the Slack plugin, but it should remain open for maintainer direction because agent-visible workspace metadata discovery introduces credential, scope, authorization, and configuration-policy choices.

## What This Changes

Add agent-facing Slack `channel-info` and `channel-list` message actions for channel metadata lookup and token-visible conversation discovery.

## Best Possible Solution

Define one focused Slack-plugin contract for both actions: explicit bot/user credential selection, documented scope and visibility limits, full cursor pagination, narrow returned metadata, intentional action gating, authorization checks where applicable, focused registry/dispatch/runtime tests, Slack docs, and redacted live-workspace proof.
