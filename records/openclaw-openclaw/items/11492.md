## Summary

Keep this issue open. Current public message-action documentation still identifies `channel info` and `channel list` as Discord-only, while Slack is documented for `emoji list`; the requested agent-facing Slack discovery actions are therefore not established on current main. The existing name-directory lookup helps resolve a name for a target but does not give an agent a channel-ID-to-metadata or workspace-list action. An open implementation candidate also omits `channel-info`, so it cannot close the full request. Likely related people: steipete (medium confidence), gumadeiras and vincentkoc (medium confidence).

## What This Changes

Add Slack `channel-info` and `channel-list` message actions so agents can turn Slack channel IDs into readable metadata and discover conversations they may access.

## System Context

The message tool exposes portable actions to agents, then routes each action to the owning channel plugin. For Slack, the plugin discovers allowed actions, dispatches them to runtime helpers, calls Slack APIs with the configured credential, and returns structured results to the agent.

## Architecture Diagram

flowchart LR
  A[Agent message request] --> B[Message action catalog]
  B --> C[Slack plugin action dispatcher]
  C --> D[Slack runtime helper]
  D --> E[Slack conversations API]
  E --> F[Channel metadata or channel list]
  F --> G[Agent response]

## Best Possible Solution

Keep the feature in the bundled Slack plugin and, if approved, add both actions through the existing action catalog, dispatcher, runtime helper, docs, and focused tests; prefer the existing `channelInfo` gate unless maintainers explicitly need a separately documented discovery policy.
