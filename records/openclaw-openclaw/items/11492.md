## Summary

Keep open: current main and the latest release still do not expose Slack `channel-info` or `channel-list` as agent-facing message actions, and the only live candidate is an unmerged broad Slack parity PR that is conflicting and human-review blocked.

## What This Changes

The issue requests Slack agent message actions for channel metadata and channel listing so agents can resolve Slack channel IDs to human-readable channel information.

## Best Possible Solution

Land or split a focused Slack plugin change that exposes both requested actions through discovery, dispatch, runtime helpers, public exports, docs, and tests while preserving Slack read-target authorization and token boundaries.

## Reproduction Assessment

Yes, at source level: current main omits Slack `channel-info` and `channel-list` from discovery and dispatch, so either action would be rejected as unsupported. No live Slack workspace run was needed to prove the missing action surface.

## Solution Assessment

Yes on owner boundary, but not yet on merge path. The implementation belongs in `extensions/slack`; maintainers should choose between repairing or splitting the broad open PR and landing a narrower Slack channel-info/list change.
