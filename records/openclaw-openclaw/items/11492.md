## Summary

Keep open: current main and the latest release still do not expose Slack `channel-info` or `channel-list` as agent-facing message actions, and the active same-repo candidate at https://github.com/openclaw/openclaw/pull/79818 is broad, conflicting, and human-review blocked.

## What This Changes

The issue requests Slack `channel-info` and `channel-list` message actions so agents can resolve Slack channel IDs to names and metadata.

## Best Possible Solution

Land or split a focused Slack plugin change that exposes both requested actions through discovery, dispatch, runtime helpers, public exports, docs, and tests while preserving Slack read authorization and token boundaries.

## Reproduction Assessment

Yes. Source inspection on current main shows Slack discovery omits `channel-info` and `channel-list`, and the Slack dispatcher falls through to the unsupported-action error for those names.

## Solution Assessment

Yes on owner boundary, but not yet on merge path. The implementation belongs in `extensions/slack`; maintainers should repair or split the broad related PR, or land a narrower focused change.
