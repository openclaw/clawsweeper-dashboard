## Summary

Keep open: current main and the latest release still omit Slack `channel-info` and `channel-list` from agent-facing message actions, and the only open implementation path is a broad protected PR that is blocked on human review, mergeability, proof, and security concerns.

## What This Changes

Issue requests Slack agent message actions for `channel-info` and `channel-list` so agents can resolve Slack channel IDs to human-readable channel metadata and names.

## Best Possible Solution

Land or split a focused Slack plugin change that exposes both requested actions through discovery, dispatch, runtime helpers, public exports, docs, and tests while preserving Slack authorization and token boundaries.

## Reproduction Assessment

Yes, at source level. Current main's Slack discovery omits `channel-info` and `channel-list`, and the dispatcher would reject those actions as unsupported; no live Slack workspace repro is needed to establish that the feature is missing.

## Solution Assessment
