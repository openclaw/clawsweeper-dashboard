## Summary

Keep open: current main and v2026.6.11 still omit Slack `channel-info` and `channel-list` as agent-facing message actions. The open candidate at https://github.com/openclaw/openclaw/pull/79818 appears to cover the surface, but it is unmerged and human-review blocked.

## What This Changes

Request to add Slack `channel-info` and `channel-list` message actions so agents can resolve Slack channel IDs to human-readable names and metadata.

## Best Possible Solution

Land or split a focused Slack plugin change that exposes both requested actions through discovery, dispatch, runtime helpers, public exports, docs, and tests while preserving Slack read-target authorization and token boundaries.

## Reproduction Assessment

Yes, at source level: current main's Slack discovery omits `channel-info` and `channel-list`, and the dispatcher/runtime have no branches or helpers for those actions. I did not run a live Slack workspace because the absence is visible in source and docs.

## Solution Assessment

Yes on owner boundary, but not yet on merge path. The feature belongs in `extensions/slack`, while https://github.com/openclaw/openclaw/pull/79818 should be repaired, split, or closed before duplicate automation is queued.
