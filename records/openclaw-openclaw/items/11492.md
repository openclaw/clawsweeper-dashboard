## Summary

Keep open: current main and the latest release still do not expose Slack `channel-info` or `channel-list` as agent-facing message actions, and the live same-repo implementation path is a broad human-review PR rather than merged code.

## What This Changes

The issue requests Slack `channel-info` and `channel-list` message actions so agents can resolve Slack channel IDs to human-readable channel metadata.

## Best Possible Solution

Land a focused Slack plugin change, or a reviewed split from https://github.com/openclaw/openclaw/pull/79818, that exposes both `channel-info` and `channel-list` through Slack discovery, dispatch, runtime helpers, docs, and focused tests without broad unrelated Slack action surface changes.

## Solution Assessment

Yes for the owner boundary: this belongs in the Slack plugin action discovery, dispatch, runtime, docs, and tests. The currently open broad parity PR may need maintainer splitting or narrowing before it is the best merge vehicle.
