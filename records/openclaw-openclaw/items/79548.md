## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Use route projection for bound fallback replies:** `src/auto-reply/reply/bind-aware-dispatch.ts:97-105`
  - body: The fallback resolves a binding but sends `binding.conversation.conversationId` directly as `to`, omitting the parent-conversation/thread projection used by current route helpers. Telegram forum bindings can store a topic id plus parent chat id, so this can target the topic id as the chat or drop the reply instead of delivering to the original topic.
  - confidence: 0.92
- **[P2] Prevent bind-routed blocks from replaying at finalization:** `src/auto-reply/reply/dispatch-acp-delivery.ts:492-496`
  - body: After a prior dispatcher block/final failure triggers the fallback, successful bind-routed visible blocks are still accounted as direct visible deliveries and settled against dispatcher failedCounts. That leaves `finalizeAcpTurnOutput` free to send the accumulated visible text again as a final fallback.
  - confidence: 0.86
- **[P2] Update fallback imports for current main:** `src/auto-reply/reply/bind-aware-dispatch.ts:25-28`
  - body: The new fallback imports normalization helpers from `../../shared/string-coerce.js`, but current main removed that module in favor of `@openclaw/normalization-core/string-coerce`. The branch needs a rebase/import update before it can build against main.
  - confidence: 0.9
