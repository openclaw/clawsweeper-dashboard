Full review comments:

- **[P1] Use route projection for bound fallback replies:** `src/auto-reply/reply/bind-aware-dispatch.ts:97-104`
  - body: The fallback resolves a binding but sends `conversationId` directly as `to`, omitting parent conversation and thread projection. Telegram topic bindings can store a topic id plus parent chat id, so this can target the topic id as the chat or drop/misroute the reply instead of delivering to the original topic.
  - confidence: 0.94
- **[P1] Prevent fallback-delivered blocks from replaying:** `src/auto-reply/reply/dispatch-acp-delivery.ts:492-496`
  - body: After a prior dispatcher block/final failure, later bind-routed visible blocks still get counted as queued direct deliveries, so `settleVisibleText()` can mark visible delivery failed from dispatcher counts and `finalizeAcpTurnOutput()` sends the accumulated text again as a final block.
  - confidence: 0.88
- **[P1] Update the fallback imports for current main:** `src/auto-reply/reply/bind-aware-dispatch.ts:24-28`
  - body: The new fallback imports normalization helpers from `../../shared/string-coerce.js`, but current main uses `@openclaw/normalization-core/string-coerce` and has no `src/shared/string-coerce.ts`. Rebase and update the import path before this can build.
  - confidence: 0.94
