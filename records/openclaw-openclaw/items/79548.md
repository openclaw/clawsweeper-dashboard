Full review comments:

- **[P1] Use route projection for bound fallback replies:** `src/auto-reply/reply/bind-aware-dispatch.ts:97-105`
  - body: The fallback resolves a binding but sends the raw binding conversation id as `to`, bypassing the parent-conversation/thread projection used by current route helpers. Telegram forum bindings can require a parent chat plus topic thread, so this can target the topic id as the chat or drop the reply instead of delivering to the original topic.
  - confidence: 0.92
- **[P2] Prevent bind-routed blocks from replaying at finalization:** `src/auto-reply/reply/dispatch-acp-delivery.ts:492-496`
  - body: After a prior dispatcher block/final failure triggers the fallback, successful bind-routed visible blocks are still accounted as direct visible deliveries and settled against dispatcher failedCounts. That leaves finalization free to send the accumulated visible text again as a final fallback.
  - confidence: 0.86
