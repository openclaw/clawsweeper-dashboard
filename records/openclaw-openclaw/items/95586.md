Options:

- **Keep Runtime Config Env (recommended):** Keep config `env` as a runtime config source, add a Linux systemd/Kimi proof or regression test for the current path, and adjust status/docs only if that proof finds a remaining mismatch.
- **Materialize Service Env:** Render supported config/env secrets into the systemd EnvironmentFile or a SecretRef-backed service source, accepting the new credential-persistence contract with explicit tests and docs.
- **Prefer Durable Auth Stores:** Document daemon-provider keys as `.env` or per-agent auth-profile inputs and make `models status` warn when a config-only source may not represent a running managed service.
