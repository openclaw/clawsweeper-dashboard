## What This Changes

The issue reports that a systemd-managed Gateway can fail Kimi Coding auth and fall back to Ollama even though `openclaw models status --agent` reports `KIMI_API_KEY` as available from config/env.

## Best Possible Solution

Define and test one managed-Gateway credential contract so service env markers, config snapshot env application, `models status --agent`, Kimi docs, and auth-profile or SecretRef guidance all describe the same runtime source of truth.
