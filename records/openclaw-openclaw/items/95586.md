## What This Changes

The issue asks OpenClaw to make Kimi Coding API-key auth behave consistently for systemd-managed Gateway turns when `KIMI_API_KEY` is configured through `openclaw.json` env settings.

## Best Possible Solution

Define one managed-Gateway credential contract, then align service-env rendering, Gateway startup/runtime auth, `models status --agent`, Kimi docs, and focused upgrade tests around that contract.
