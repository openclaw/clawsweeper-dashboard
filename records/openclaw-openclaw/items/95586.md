## Summary

Close: current main now applies selected `openclaw.json` config env into the Gateway process before `startGatewayServer`, so a systemd-managed `openclaw gateway run` process can resolve `env.KIMI_API_KEY` through the same runtime auth path that `models status` reports. ## What This Changes

The issue reports Kimi Coding API keys from config env being visible to CLI status but unavailable to real systemd-managed Gateway turns, causing auth-class model fallback.

## Best Possible Solution

Keep the current centralized Gateway CLI startup env application and close this issue as fixed on main; any broader `.env` precedence work should stay on the separate env-management issue.
