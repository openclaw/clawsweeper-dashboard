## Summary

Keep this issue open. Current main supports a target agent workspace and static per-agent skill visibility, but it does not expose the requested per-run native child workspace or workspace-only skill-discovery policy; the same author has paired the request with an open draft implementation PR at https://github.com/openclaw/openclaw/pull/111462.

## What This Changes

Add a native-only `sessions_spawn` workspace selection that restricts a child to a validated descendant workspace and its workspace-local skills across later turns.

## Best Possible Solution

Keep ordinary subagents on the existing target-agent workspace path, and only add a native-only dynamic workspace mode if it validates a canonical descendant, persists server-owned lineage, explicitly limits skill discovery rather than host authorization, and documents the required sandbox/tool policy for stronger isolation.
