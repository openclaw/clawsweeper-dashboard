## Summary

Keep open for normal PR review/merge: current main and the latest release still route a no-handler empty compaction preparation into core `compact()`, while this patch adds a narrow skip in `runCompactionWork` and preserves the `session_before_compact` safeguard path. I found no blocking correctness finding.

## What This Changes

The PR changes agent-session compaction so an empty keep-all preparation is skipped when no `session_before_compact` handler is registered, and adds a focused regression test for the default and handler paths.

## Best Possible Solution

Land the focused session-boundary guard if maintainers agree that a keep-all preparation with no before-compaction consumer is not a real compaction and should not append a session entry.

## Reproduction Assessment

Yes. Source inspection and the PR regression show a small keep-all session can produce an empty preparation, after which current main calls `compact()` and appends a compaction entry instead of skipping.

## Solution Assessment

Yes. The session boundary is the right layer because it can distinguish whether a `session_before_compact` handler will consume the empty preparation; returning `undefined` from `prepareCompaction` or guarding inside the core compactor would be too broad for the safeguard path.
