## Summary

Keep this issue open. It describes a concrete availability problem in the git-update lifecycle, but the immutable-release-root approach spans updater ownership, service metadata, rollback, garbage collection, and platform supervisors; the `maintainer` label requires explicit maintainer direction before implementation.

## What This Changes

Add immutable, fully built release roots with an atomic managed-service switch for git-based updates, reducing gateway downtime from the build duration to a restart window.

## System Context

Git-based updates currently prepare and mutate an OpenClaw installation before restarting its managed gateway service. The proposed release-root lifecycle would build and validate a complete new runtime tree, switch the service to it briefly, and retain the prior tree for rollback.

## Architecture Diagram

  E --> F[Atomic service-root switch]
  F --> G[Gateway restart]
  G --> H[Previous-root rollback and cleanup]

## Best Possible Solution

Sponsor a phased, owner-reviewed release-root design that builds and validates a self-contained runtime tree before a short service handoff, with explicit rollback, retention, recovery, and cross-platform supervisor proof.
