## Summary

The core fix is well-supported, but the new oversized-input path exits with status 1 even though OC Path’s documented CLI contract classifies parse failures as status 2. This narrow script-visible defect should be corrected before merge.

## What This Changes

The PR measures JSONC input limits in UTF-8 bytes before parsing and propagates the existing oversized-input diagnostic through OC Path commands that load JSON or JSONC files.

## Best Possible Solution

Keep the UTF-8 byte measurement and typed diagnostic, but classify oversized JSONC as a parse error with exit code 2 across file-loading verbs and lock that behavior into CLI tests and refreshed terminal proof.
