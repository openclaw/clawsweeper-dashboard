## What This Changes

The PR measures JSONC input limits in UTF-8 bytes before parsing and converts oversized-input diagnostics into OC Path CLI parse errors for resolve, set, and find operations.

## Best Possible Solution

Keep the single parser-level UTF-8 byte-cap check and shared CLI diagnostic path, then refresh the real CLI transcript and required checks against `5731ac5` before ordinary maintainer merge.

## Reproduction Assessment

Yes from source and prior A/B evidence: a JSONC string containing enough three-byte UTF-8 characters to exceed 16 MiB while remaining below 16 MiB JavaScript code units reaches the old length check and bypasses the intended cap. The supplied prior proof reports that this regression test fails on base and passes with the earlier fix head.

## Solution Assessment

Yes, provisionally: placing the byte check before both the blank-input shortcut and `parseTree` fixes the shared allocation boundary, while reusing the existing typed diagnostic through the CLI's normal parse-error path avoids a second limit or parallel error contract.
