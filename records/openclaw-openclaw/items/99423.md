## Summary

Keep open. The alias-aware completion approach is useful, but the patch is incomplete because it can make completion advertise `exec-approvals` even though current lazy root routing does not load that alias, and the PR proof is unit-test output only.

## What This Changes

The branch adds helpers to emit Commander aliases in zsh, bash, fish, and PowerShell completion generation and extends completion tests with synthetic aliases.

## Best Possible Solution

Land a candidate that keeps completion output aligned with runtime-routable command spellings, either by adding tested `exec-approvals` lazy-route metadata or by filtering aliases that are not accepted at the root entry point.

## Reproduction Assessment

Yes from source. Current main omits aliases from generated completions, and this patch's global alias expansion also exposes the `exec-approvals` alias without matching lazy-route metadata.

## Solution Assessment

No. Alias-aware generation is the right layer, but the fix is incomplete unless completion output is constrained to routable spellings or the missing `exec-approvals` route is added with tests.
