## Summary

Keep open: current `origin/main` and `v2026.6.11` still model Discord message actions behind one coarse `actions.messages` boolean, so the requested least-privilege send/read/edit/delete split remains unimplemented and needs maintainer product/security direction.

## What This Changes

The issue requests a granular Discord message-action gate so send/read/edit/delete can be enabled independently instead of sharing `channels.discord.actions.messages`.

## Best Possible Solution

Choose one maintainer-approved least-privilege Discord message-gate contract, then update config/schema metadata, discovery, runtime enforcement, docs, and focused tests consistently while preserving the current boolean shorthand.
