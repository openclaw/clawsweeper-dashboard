## Summary

Keep open: current main and v2026.6.11 still model Discord message actions with one `actions.messages` boolean for send, read, edit, upload, and delete, so the requested least-privilege gate split remains missing and needs maintainer product/security direction.

## What This Changes

The issue requests splitting Discord message action gating so send, read, edit, and delete can be controlled independently instead of by one `actions.messages` boolean.

## Best Possible Solution

Choose one canonical backward-compatible Discord message gate model, then update config types, strict schema, generated metadata, discovery, runtime checks, docs, and focused tests together while preserving the existing boolean shorthand.

## Reproduction Assessment

Yes. Source inspection on current main and v2026.6.11 shows one Discord `messages` boolean in config, schema, generated metadata, discovery, and runtime, so the requested granular gates are absent.

## Solution Assessment

Unclear. Granular gates fit the least-privilege goal, but maintainers still need to choose the public config shape, inheritance behavior, and composition with existing message-action allowlists.
