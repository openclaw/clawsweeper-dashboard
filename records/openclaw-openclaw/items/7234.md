## Summary

Keep open. Current main and v2026.6.11 still expose one coarse Discord `messages` permission for send, fetch/read, edit, and delete; the least-privilege capability remains missing, and no related issue or viable PR owns the same contract.

## What This Changes

Add granular Discord message action permissions so send, read, edit, and delete can be enabled independently.

## Best Possible Solution

Adopt one canonical backward-compatible Discord message-permission resolver, preserve the existing boolean as a group shorthand, allow explicit send/read/edit/delete overrides, and use the resolved permissions consistently in schema metadata, discovery, runtime enforcement, documentation, and focused tests.

Rationale: This is a shipped, security-sensitive configuration contract; maintainers must choose its stable shape, default inheritance, and upgrade behavior before implementation can safely proceed.

Options:

- **Boolean-or-object group (recommended):** Keep the shipped boolean as the group default and allow optional send, read, edit, and delete overrides beneath `messages`.
- **Separate top-level gates:** Add independent message-action booleans and explicitly define how they override or supersede the existing `messages` group.
- **Keep coarse gate:** Retain the current grouped authorization and document that deployments cannot independently prohibit destructive message actions.

## Reproduction Assessment

Yes—source inspection provides a high-confidence reproduction: setting `channels.discord.actions.messages` false disables the grouped message operations, while current types and validation offer no independent send, read, edit, or delete controls. A live Discord run is not necessary to establish that the configuration capability is absent.

## Solution Assessment

Not yet—the proposed nested object is plausible, but maintainers must first choose the permanent public schema and inheritance semantics. The safest implementation is a shared permission resolver that preserves the shipped boolean shorthand and prevents discovery/runtime authorization drift.
