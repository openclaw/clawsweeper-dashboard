## Summary

Keep open: current main and the latest release still model Discord message send/read/edit/delete behind one `actions.messages` boolean, so the requested least-privilege split remains missing and needs maintainer product/security direction.

## What This Changes

The issue requests a granular Discord message-action gate so operators can independently allow send, read, edit, and delete instead of using one `channels.discord.actions.messages` boolean.

## Best Possible Solution

Choose one canonical backward-compatible Discord message gate model, then update config types, strict schema, generated metadata, discovery, runtime checks, docs, and focused tests while preserving the existing boolean shorthand.

## Reproduction Assessment

Yes. Source inspection on current main and `v2026.6.11` shows one Discord `messages` boolean in config, schema, discovery, and runtime, so the proposed object-shaped gate is not accepted.

## Solution Assessment

Unclear. Granular gates fit least-privilege goals, but maintainers still need to choose the public config shape, inheritance behavior, and composition with existing message-action controls.
