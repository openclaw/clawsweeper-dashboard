## Summary

Keep open: current main and latest release still model Discord `actions.messages` as one coarse boolean, and the existing generic message-action allowlist is not the same as a Discord account/channel-level least-privilege gate. The remaining work is a public Discord config and security-boundary decision.

## What This Changes

The issue requests splitting Discord `actions.messages` so send, read, edit, and delete can be enabled independently while preserving the boolean shorthand.

## Best Possible Solution

Choose one least-privilege Discord message-gate contract, then update config types, schema metadata, discovery, runtime enforcement, docs, and focused tests while preserving existing boolean behavior.
