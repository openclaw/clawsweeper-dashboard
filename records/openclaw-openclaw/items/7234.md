## Summary

Keep open. Current main and v2026.7.1 still expose one Discord `messages` action group covering read, send, edit, and delete, so deployments cannot enforce the requested least-privilege boundary; the exact compatibility and precedence contract needs Discord-owner approval before implementation.

## What This Changes

Add separate Discord send, read, edit, and delete action gates while preserving the shipped aggregate `actions.messages` configuration behavior.

## Best Possible Solution

Keep the Discord-owned shipped boolean valid, add one canonical granular object form, normalize it once into effective send/read/edit/delete capabilities, and use those same prepared capabilities across discovery and execution with aligned schema metadata, docs, compatibility tests, and fresh-config tests.
