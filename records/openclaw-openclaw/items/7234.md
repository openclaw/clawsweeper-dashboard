## Summary

Keep open: current main and the latest release still model Discord message actions as one coarse `actions.messages` boolean, so the requested send/read/edit/delete split remains missing. The generic message-action allowlist is a real workaround, but it does not resolve the Discord-specific public config and destructive-action security contract.

## What This Changes

Requests granular Discord message action gates so operators can disable destructive edit/delete behavior while keeping send/read available.

## Best Possible Solution

Adopt one maintainer-approved Discord message-gate contract that preserves the existing boolean shorthand, makes destructive edit/delete control explicit, and documents how it relates to the generic message-action allowlist.
