## Summary

Keep open. Current main partially resolved the report by leaving Discord send available when `actions.messages` is false, but read, fetch, edit, and delete remain coupled behind one boolean in both current main and v2026.6.11. The prior review correctly identified a remaining least-privilege gap, and no duplicate or active PR owns it; maintainers still need to choose the permanent permission and compatibility contract.

## What This Changes

Add independent Discord message permissions so destructive edit and delete operations can be disabled without removing read or send capability.

## Best Possible Solution

Keep send outside the gate, then approve and implement a Discord-plugin-owned `messages` boolean-or-object contract with optional read, edit, and delete overrides, using one shared resolver across schema metadata, account inheritance, discovery, runtime enforcement, docs, and focused fresh-install and upgrade tests.

- **Separate top-level gates:** Add independent read, edit, and delete action keys with an explicit doctor migration or deprecation path for the released `messages` key.
- **Keep remaining coarse gate:** Retain one shared permission for fetch, read, edit, and delete and document selective denial as unsupported.

## Reproduction Assessment

Yes, from source inspection. Current main and v2026.6.11 define `actions.messages` as one strict boolean; send is now independent, but fetch, read, edit, and delete still enforce that shared key, so the requested remaining configuration cannot be expressed.

## Solution Assessment

Yes in direction, but the original proposal should be narrowed because send is already correctly outside the gate. A backward-compatible boolean-or-object resolver for read, edit, and delete is the narrowest maintainable solution, pending maintainer approval of defaults and upgrade semantics.
