## Summary

Keep open. Current main still exposes `channels.discord.actions.messages` as one boolean and groups read, edit, and delete behind it, so the requested least-privilege control remains missing; send discovery has since been separated, but the central destructive-action boundary still requires a compatibility and security decision.

## What This Changes

Add independent Discord permission gates for reading, sending, editing, and deleting messages instead of controlling them through one `actions.messages` boolean.

## Best Possible Solution

Adopt one Discord-owned canonical permission resolver with explicit send, read, edit, and delete decisions, migrate the shipped boolean shape through `openclaw doctor --fix` or use a deliberately additive override contract, and apply the same resolved permissions to schema discovery, execution, docs, metadata, and focused tests.
