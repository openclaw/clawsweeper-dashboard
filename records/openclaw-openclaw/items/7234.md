## Summary

Keep open for a maintainer decision: the requested least-privilege Discord permission model remains a feature and compatibility contract choice, not a narrow bug fix. The supplied prior source review found one `messages` gate across discovery and runtime, while the linked event-action PR addresses a separate Discord capability rather than this permission split.

## What This Changes

Add independently configurable Discord message permissions so sending, reading, editing, and deleting can be allowed or denied separately instead of sharing one `actions.messages` toggle.

## System Context

OpenClaw's Discord plugin advertises message-tool actions from channel configuration, then checks those permissions again before sending requests to Discord. The proposed change would alter the configuration contract that controls which Discord message operations an agent can discover and execute.

## Best Possible Solution

Adopt one documented backward-compatible Discord permission contract that preserves the existing boolean behavior, defines defaults for each operation, and enforces the same resolved permission consistently in discovery and runtime.
