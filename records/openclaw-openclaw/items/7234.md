## Summary

Current main and v2026.6.11 still expose one Discord `messages` boolean for send, read, edit, and delete, with `send` advertised even when runtime will reject it. No canonical duplicate or fixing PR owns this permission split, and the prior review also kept it open; maintainers still need to choose the stable authorization and migration contract.

## What This Changes

Add independently configurable Discord message send, read, edit, and delete action gates instead of one coarse `actions.messages` boolean.

## Best Possible Solution

Adopt one canonical Discord message-permission shape, enforce it consistently in discovery and runtime, and use the Discord doctor contract to migrate shipped `actions.messages` booleans without changing their effective permissions.

Owner confidence: high

Options:

- **Granular permissions with migration (recommended):** Add explicit send, read, edit, and delete permissions and doctor-migrate each old boolean to equivalent all-enabled or all-disabled values.
- **Keep send outside optional actions:** Leave normal outbound send available and independently gate read, edit, delete, and related optional message operations.
- **Retain the coarse gate:** Preserve one message permission and only make send discovery and runtime behavior consistent.

## Reproduction Assessment

Yes. Current-main source and v2026.6.11 deterministically show one boolean gate for send, read, edit, and delete, including the send discovery/runtime contradiction.

## Solution Assessment

Yes in direction, but not exactly as proposed: granular permissions solve the least-privilege problem, while one canonical config plus `openclaw doctor --fix` migration is safer than indefinitely accepting boolean and object runtime shapes.
