## Summary

Keep open. Current main and the latest release still expose Discord message permissions through one coarse `actions.messages` gate, so the requested least-privilege control remains missing and needs an owner-approved compatibility design before implementation.

## What This Changes

Request separate Discord permission controls for sending, reading, editing, and deleting messages while retaining compatibility with the existing `channels.discord.actions.messages` boolean.

## Best Possible Solution

Add a Discord-plugin-owned granular message-permission contract only after maintainers choose its public shape and compatibility semantics; preserve existing boolean behavior, enforce each operation consistently in discovery and runtime, and cover enabled/disabled upgrade cases with focused tests and docs.

- **Keep the coarse gate:** Decline the additional configuration surface and document that disabling message actions intentionally disables all message operations.
