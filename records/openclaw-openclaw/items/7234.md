## Summary

Keep open. Current main and v2026.7.1 retain one coarse Discord message-action permission, so the requested least-privilege separation remains missing and needs Discord ownership approval before implementation.

## What This Changes

Add granular Discord permissions so send, read, edit, and delete message actions can be enabled independently.

## Best Possible Solution

Adopt owner-approved per-action overrides that inherit predictably from the shipped boolean shorthand, use one canonical resolver for discovery and execution, and document least-privilege defaults and upgrade behavior.

Options:

- **Add inherited per-action overrides (recommended):** Keep the existing boolean as the group default and allow explicit send/read/edit/delete overrides whose values take precedence, with fetch mapped to read and all enforcement using one resolver.
- **Create a generic action policy:** Introduce a channel-independent allow/deny action policy and migrate Discord message gates onto it, accepting a broader API and implementation scope.
- **Retain the coarse gate:** Keep the current boolean-only model and document that deployments must use Discord-side permissions or tool policy for finer restrictions.

## Reproduction Assessment

Yes, at source level: current main exposes only a boolean config/schema and jointly advertises read, edit, and delete through that gate. A live Discord run is unnecessary to establish that the granular configuration capability is absent.

## Solution Assessment

Unclear until the Discord owner selects the public permission and precedence contract. The proposed nested overrides are a strong narrow option, but they must share one resolver across schema, discovery, execution, metadata, docs, and tests.
