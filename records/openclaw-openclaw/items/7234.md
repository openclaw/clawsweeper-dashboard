## Summary

Keep open: current main and the latest release still use one coarse Discord `actions.messages` boolean for send/read/edit/delete behavior, while the requested granular Discord public config/security contract remains undecided and unimplemented.

## What This Changes

Request to split Discord `channels.discord.actions.messages` into separate read, send, edit, and delete controls while preserving the existing boolean shorthand.

## Best Possible Solution

Adopt one maintainer-approved Discord message-gate contract that preserves the existing boolean shorthand, keeps destructive edit/delete control explicit, and documents the generic message-action allowlist as an interim or complementary control.
