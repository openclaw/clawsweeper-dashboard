## Summary

Keep open: current main and the latest release still expose Discord message action control as one coarse `actions.messages` boolean, while the requested channel/account-level send/read/edit/delete split remains missing. The existing generic message-action allowlist is a useful workaround, but it does not settle the Discord-specific public config and security contract.

## What This Changes

Request a granular Discord message action gate so operators can disable destructive edit/delete actions while keeping send/read behavior available.

## Best Possible Solution

Adopt one maintainer-approved Discord message-gate contract that preserves the existing boolean shorthand, keeps destructive edit/delete control explicit, and documents the generic message-action allowlist as an interim or complementary control.
