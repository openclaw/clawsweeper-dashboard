## Summary

Keep open: current main and v2026.6.11 have mature operator scopes plus layered global, agent, group, and sender tool policies, but they still do not expose the requested scope-keyed `toolsByScope` config or feed gateway operator scopes into the agent tool-policy resolver. The remaining work is a security/product decision about the durable authorization boundary, not conservative cleanup.

## What This Changes

The issue requests a new per-session/scope-aware tool-policy layer that bridges gateway operator scopes with agent tool availability.

## Best Possible Solution

Maintainers should decide the durable authorization model first, then either add a typed, documented scope-aware tool-policy layer or route this need to sender/group policy, session envelopes, or the broader tenant RBAC design.
