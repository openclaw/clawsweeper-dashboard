## Summary

Keep open: current main has mature gateway operator scopes plus global, per-agent, provider, group, and sender tool-policy layers, but it still does not bridge the caller's operator scopes into runtime tool-policy resolution or expose a `toolsByScope`-style config surface. The related open items are useful adjacent design tracks, not a merged or single canonical replacement for this focused RFC.

## What This Changes

The issue requests per-session tool-policy overrides that connect gateway operator scopes or sender identity to agent runtime tool access.

## Best Possible Solution

Keep this issue as the focused RFC until maintainers decide whether scope-aware tool policy belongs in core, is absorbed into tenant RBAC, or should be expressed through session envelopes and sender/group policy instead.

## Reproduction Assessment

Not applicable: this is an RFC for a new authorization/config capability, not a report of broken current behavior. Source inspection confirms the requested bridge is absent on current main rather than failing at runtime.

## Solution Assessment

Unclear: `toolsByScope` is a plausible slice, but the best solution depends on maintainer decisions about the operator-scope trust model, config precedence, and whether session envelopes or tenant RBAC should own the boundary.
