## Summary

Keep open: current main and the latest release still lack a scope-keyed bridge from Gateway operator scopes into agent tool-policy resolution. Adjacent sender, group, conversation-profile, and session-envelope work helps the same area but does not replace this RFC, so the remaining question is maintainer security/product direction.

## What This Changes

The issue requests session-level tool filtering that connects Gateway operator scopes to agent tool-policy resolution through a new scope-aware policy contract.

## Best Possible Solution

Keep this as the focused design anchor until maintainers choose a typed scope-aware tool-policy contract or explicitly route the need to sender policies, session envelopes, conversation identity, or tenant RBAC.
