## Summary

Keep open: current main and v2026.6.11 have layered agent, group, sender, and gateway HTTP tool policies, but they still do not provide the requested operator-scope-to-agent-tool-policy bridge. The remaining work is a security/product decision about the durable authorization boundary, not a narrow cleanup close.

## What This Changes

The issue requests a scope-aware per-session tool-policy layer that connects gateway operator scopes to agent tool access.

## Best Possible Solution

Maintainers should first define the authorization boundary and policy precedence, then implement a typed documented scope-aware resolver or explicitly route this need to session envelopes or tenant RBAC.
