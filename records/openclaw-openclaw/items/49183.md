## Summary

Keep open: current main and v2026.6.11 still have Gateway operator scopes and layered agent tool policies, but no `toolsByScope` config or operator-scope layer in runtime tool-policy resolution. Related sender-policy, session-envelope, tenant-RBAC, and org-deployment items are useful adjacent work, but they do not settle this focused product/security decision.

## What This Changes

The issue requests a per-session tool-policy model that bridges Gateway operator scopes into agent tool access, likely through a new scope-keyed config surface.

## Best Possible Solution

Keep this as the focused operator-scope/tool-policy RFC until maintainers decide the durable authorization model, then implement either a documented scope-aware policy layer or route the need through session envelopes, sender/group policies, or tenant RBAC.
