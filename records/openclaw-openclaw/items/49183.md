Keep open: current main and the latest stable release still lack a scope-keyed bridge from Gateway operator scopes into agent tool filtering, and the remaining work is a maintainer security/product decision rather than a narrow repair.

## What This Changes

The issue requests session-level tool policies that bridge Gateway operator scopes into agent tool-policy filtering through `toolsByScope` or an equivalent contract.

## Best Possible Solution

Approve a typed scope-aware tool-policy contract only after maintainers settle the threat model, config location, precedence with sender/group/agent policy, and documented upgrade behavior.

Options:

- **Decline scope-based RBAC:** Document operator scopes as control-plane only and direct stronger multi-user isolation to separate Gateways or the broader tenant RBAC design.
