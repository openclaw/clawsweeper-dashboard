## Summary

Keep open: current main has sender, group, provider, sandbox, and owner/admin tool-policy primitives, but it still has no scope-keyed `toolsByScope` config or gateway-operator-scope input to normal agent tool-policy resolution. This remains a product/security boundary decision, not conservative cleanup.

## What This Changes

Request to add per-session tool policies that bridge Gateway operator scopes into agent tool access, likely through a new `toolsByScope` or equivalent config contract.

## Best Possible Solution

Maintainers should decide the durable authorization model first, then either add a typed scope-aware tool-policy layer or route the need to sender policy, session envelopes, binding policy, conversation identity, or broader tenant RBAC.
