## Summary

Keep open: current main and v2026.6.11 still have agent, group, sender, provider, sandbox, and gateway operator-scope primitives, but they do not expose the requested scope-keyed `toolsByScope` config or pass gateway operator scopes into the normal agent tool-policy resolver. The remaining work is a security/product decision about the durable authorization boundary, not a stale cleanup close.

## What This Changes

Request to add per-session tool-policy filtering that bridges gateway operator scopes with agent tool access for multi-user deployments.

## Best Possible Solution

Maintainers should decide the durable authorization model first, then either add a typed, documented scope-aware tool-policy layer or route this need to sender policy, session envelopes, authenticated-node policy, or the broader tenant RBAC design.

- **Decline scope-based RBAC:** Document operator scopes as control-plane only and direct multi-user isolation to separate Gateways or a broader tenant RBAC design.
