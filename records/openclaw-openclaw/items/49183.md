## Summary

Keep open: current main still lacks a scope-keyed bridge from Gateway operator scopes into agent tool filtering, and overlapping session, binding, and tenant-RBAC work does not replace this focused security/product decision.

## What This Changes

The issue requests session-level tool filtering keyed by Gateway operator scopes, such as `toolsByScope`, so different connected operators can have different tool access in the same agent/session context.

## Best Possible Solution

Approve or reject a typed scope-aware tool-policy contract, including config location, precedence with sender/group/session/binding policy, enforcement layer, docs, and upgrade behavior.
