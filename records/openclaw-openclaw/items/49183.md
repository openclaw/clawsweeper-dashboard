## Summary

Keep open: current main and v2026.6.11 have mature gateway operator scopes plus layered agent, group, and sender tool policies, but they still do not expose the requested scope-keyed `toolsByScope` config or feed gateway operator scopes into the normal agent tool-policy resolver. The open related work covers useful slices, but the remaining question is still a security/product decision about the durable authorization model.

## What This Changes

The issue requests a per-session tool-policy/RBAC layer that bridges gateway operator scopes into agent tool access, likely through a new scope-keyed config surface.

## Best Possible Solution

Maintainers should decide the durable authorization model first, then either add a typed, documented scope-aware tool-policy layer or route this need to sender/group policy, session envelopes, or the broader tenant RBAC design.

## Reproduction Assessment

Not applicable. This is an RFC for a new authorization/config capability; source and release inspection show the requested scope-to-tool-policy bridge is absent rather than a broken existing path.

## Solution Assessment

Unclear. `toolsByScope` is a plausible slice, but maintainers should choose between scope-aware tool policy, sender/group policy, session envelopes, and tenant RBAC before implementation.
