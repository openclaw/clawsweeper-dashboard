## Summary

Keep open: current main and the latest release have sender/group tool-policy primitives and the scoped conversation profile foundation, but they still do not connect gateway operator scopes to runtime tool policy. The remaining decision is security/product direction around trust boundaries, config shape, and policy precedence.

## What This Changes

Requested session-level tool filtering that connects gateway operator scopes to agent tool-policy resolution for multi-user deployments.

## Best Possible Solution

Maintainers should choose the durable authorization model, then either add a typed scope-aware policy layer with docs/tests/upgrade behavior or explicitly route this need to sender policies, session envelopes, or tenant-RBAC work.

- **Design Scope-Aware Tool Policy (recommended):** Keep this issue open and approve a narrow design for scope-to-tool-policy precedence, enforcement layer, docs, and upgrade tests before implementation.

- **Decline Scope Bridge For Now:** Document separate gateways, trusted proxy identity, sender policies, and per-agent profiles as the supported isolation path without adding `toolsByScope`.
