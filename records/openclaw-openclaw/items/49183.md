## Summary

Keep open: current main and v2026.6.11 have sender/group/session policy primitives, but they still do not provide the requested operator-scope-to-agent-tool-policy bridge. The remaining work is a security/product decision about whether scopes should become tool RBAC input, where that contract belongs, and how it composes with session envelopes and tenant RBAC.

## What This Changes

Request session-level tool policy overrides that connect Gateway operator scopes or sender identity to agent tool availability in multi-user deployments.

## Best Possible Solution

Keep this as the focused design anchor until maintainers choose a typed scope-aware tool-policy contract or explicitly route the need to sender policies, session envelopes, conversation identity, or tenant RBAC.
