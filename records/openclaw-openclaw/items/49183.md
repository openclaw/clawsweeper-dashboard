## Summary

Keep open: current main still has Gateway operator scopes and sender/group/agent tool-policy layers, but it does not expose a scope-keyed tool policy or pass the caller's full operator-scope set into agent tool resolution. The remaining work is a security/product decision about the durable authorization boundary, not a stale or already-implemented request.

## What This Changes

The issue requests a new per-session tool-policy capability that bridges Gateway operator scopes into agent tool-access decisions, potentially via `toolsByScope`.

## Best Possible Solution

Keep this as the focused design anchor until maintainers approve a typed scope-aware tool-policy contract or explicitly route the need to sender policies, session envelopes, conversation identity, or tenant RBAC.
