## Summary

Keep open: current main and v2026.6.11 have gateway operator scopes, agent/provider/sender/group tool-policy layers, and scoped conversation foundations, but they still do not expose a scope-keyed `toolsByScope` policy or pass the caller's full operator-scope set into agent tool-policy resolution. The remaining work is a maintainer security/product decision about the durable authorization boundary.

## What This Changes

The issue requests a new per-session tool-policy capability that bridges gateway operator scopes or sender identity into agent tool access.

## Best Possible Solution

Keep this as the focused design anchor until maintainers either approve a typed scope-aware tool-policy contract or explicitly route the need to sender policies, session envelopes, conversation identity, or tenant RBAC.
