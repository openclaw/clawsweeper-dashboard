## Summary

Keep open: current main and the latest release still expose selected SKILL.md files through a model-facing skills catalog and rely on the model to read and follow them, while the requested trusted/untrusted instruction boundary, role locking, per-skill memory/tool authority, and behavioral monitoring remain unresolved security work.

## What This Changes

The issue requests instruction isolation and permission boundaries for SKILL.md content loaded into agent context.

## Best Possible Solution

Adopt a maintainer-approved trusted/untrusted skill precedence model, add narrow per-skill authority metadata, enforce it in prompt assembly and runtime policy, and cover malicious SKILL.md cases with focused tests and docs.
