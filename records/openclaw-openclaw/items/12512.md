## Summary

Keep open: current main and the latest release still expose eligible skills through a model-facing catalog that tells the model to read and follow SKILL.md, while the requested instruction isolation, role locking, per-skill memory/tool authority, and behavioral monitoring remain unresolved security-boundary work.

## What This Changes

The issue requests enforced isolation and capability boundaries for SKILL.md instructions so skill content cannot override agent role, memory, or tool policy.

## Best Possible Solution

Adopt a maintainer-approved trusted/untrusted skill precedence model, expose narrow per-skill capability metadata, enforce it in prompt assembly and runtime policy, and cover malicious SKILL.md cases with focused tests and docs.
