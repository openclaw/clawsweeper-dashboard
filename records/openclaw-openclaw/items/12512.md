## Summary

Keep open: current main and v2026.6.11 still expose SKILL.md as model-followed skill instructions, while the requested role isolation, per-skill memory/tool authority, and runtime monitoring remain unresolved security-boundary work that needs maintainer design.

## What This Changes

The issue requests an instruction-isolation and permission boundary for SKILL.md content so skills cannot override agent role, memory, or tool authority.

## Best Possible Solution

Define a maintainer-approved trusted/untrusted precedence model for skills, add typed per-skill authority metadata for role, memory, and tool influence, enforce it through prompt assembly and runtime/tool policy, and cover malicious SKILL.md cases with focused tests and docs.
