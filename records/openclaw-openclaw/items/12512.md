## Summary

Keep open: current main and v2026.6.11 still rely on a model-facing SKILL.md read-and-follow path, while role locking, instruction isolation, per-skill memory/tool authority, and runtime monitoring remain unresolved security/product design work.

## What This Changes

The issue requests a core instruction-isolation architecture for SKILL.md content, including role locking, behavioral monitoring, and per-skill capability boundaries.

## Best Possible Solution

Define one maintainer-approved skill trust and capability contract, then enforce it consistently through prompt selection, SKILL.md loading, tool execution, memory access, sandbox policy, regression tests, and docs.
