## Summary

Keep open: current main and the latest release still expose skills through a model-facing available-skills catalog that tells the model to read and follow SKILL.md, while role locking, instruction isolation, per-skill memory/tool authority, and runtime monitoring remain unresolved security/product design work.

## What This Changes

The issue requests instruction isolation, role locking, and per-skill capability boundaries for model-visible SKILL.md content.

## Best Possible Solution

Define one maintainer-approved skill trust and capability contract, then enforce it consistently through prompt selection, SKILL.md loading, tool execution, memory access, sandbox policy, regression tests, and docs.
