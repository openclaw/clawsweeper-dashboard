## Summary

Keep open: current main and shipped v2026.6.11 still expose skills through a model-facing SKILL.md read-and-follow path, while the requested instruction isolation, role locking, per-skill memory/tool authority, and runtime monitoring remain unresolved security design work.

## What This Changes

Request to add an instruction-isolation and permission boundary for SKILL.md content so skill instructions cannot override agent role, memory, or tool authority.

## Best Possible Solution

Define one maintainer-approved skill trust and capability contract, then enforce it consistently through prompt selection, SKILL.md loading, tool execution, memory access, sandbox policy, regression tests, and docs.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 instruct the model to read and follow selected SKILL.md files while the skill policy surface only exposes invocation and prompt-visibility controls. I did not run a live malicious-skill exploit.

## Solution Assessment

Unclear as a final implementation path: the requested direction addresses a real hardening gap, but maintainers still need to define the trusted/untrusted skill contract, compatibility defaults, and enforcement scope.
