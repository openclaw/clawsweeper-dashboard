Keep open: current main still uses a model-facing skills catalog and tells the model to read and follow selected SKILL.md files, while the requested instruction isolation, role locking, per-skill memory/tool authority, and behavior monitoring remain unresolved security-boundary work.

The issue requests a core security architecture that isolates SKILL.md instructions from trusted agent context and adds role, memory, tool, and monitoring boundaries for skills.

Adopt a maintainer-approved trusted/untrusted skill precedence model, expose narrow per-skill authority metadata, enforce it in prompt assembly and runtime policy, and cover malicious SKILL.md cases with focused tests and docs.
