## Summary

Keep open: current main and the latest release still expose eligible SKILL.md files through a model-facing skills catalog and visibility policy, but they do not implement the requested trusted/untrusted instruction boundary, role locking, per-skill memory/tool capability enforcement, or runtime monitoring.

## What This Changes

The issue requests core security hardening that isolates model-visible SKILL.md instructions from trusted agent/system context and adds role, memory, tool, and monitoring boundaries.

## Best Possible Solution

Define a maintainer-approved trusted/untrusted precedence model for skills, add typed per-skill authority metadata for role, memory, and tool influence, enforce it through prompt assembly and runtime/tool policy, and cover malicious SKILL.md cases with focused tests and docs.
