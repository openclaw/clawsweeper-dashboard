## Summary

Keep open: current main and v2026.6.11 still expose eligible skills through a model-facing catalog that tells the model to read and follow SKILL.md, while instruction isolation, role locking, per-skill memory/tool authority, and behavioral monitoring remain unresolved security-boundary work.

## What This Changes

Requests a core instruction-isolation architecture for SKILL.md content, including role locking, per-skill authority metadata, and runtime monitoring for prompt-injection behavior.

## Best Possible Solution

Adopt a maintainer-approved trusted/untrusted skill precedence model, expose narrow per-skill authority metadata, enforce it in prompt assembly and runtime policy, and cover malicious SKILL.md cases with focused tests and docs.
