## Summary

Keep open: current main and v2026.6.11 still use a model-facing SKILL.md read-and-follow path, while the requested instruction isolation, role locking, per-skill memory/tool authority, and behavioral monitoring remain unresolved security/product design work.

## What This Changes

The issue requests isolation and enforcement boundaries for SKILL.md instructions so untrusted skill content cannot override agent role, memory, or tool policy.

## Best Possible Solution

Define one maintainer-approved skill trust and capability contract, then enforce it consistently through prompt selection, SKILL.md loading, tool execution, memory access, sandbox policy, regression tests, and docs.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 instruct the model to read and follow selected SKILL.md files while skill policy only exposes invocation and prompt-visibility controls; I did not run a live malicious-skill exploit.

## Solution Assessment

Unclear as a final implementation path. The requested direction addresses a real security-hardening gap, but maintainers still need to define the trusted/untrusted skill contract, compatibility defaults, and enforcement scope before implementation.
