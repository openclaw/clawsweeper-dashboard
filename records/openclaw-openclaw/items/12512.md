## Summary

Keep open: current main and the latest release still expose eligible skills through a model-facing catalog and read-and-follow prompt guidance, while the requested instruction isolation, role locking, per-skill memory/tool authority, and runtime monitoring remain unresolved security-boundary work.

## What This Changes

The issue requests a core security architecture that separates trusted system instructions from SKILL.md content and adds role, memory, tool, and monitoring boundaries for skills.

## Best Possible Solution

Adopt a maintainer-approved trusted/untrusted skill precedence model, expose narrow per-skill authority metadata, enforce it in prompt assembly and runtime policy, and cover malicious SKILL.md cases with focused tests and docs.
