## Summary

Keep open: current main still exposes selected SKILL.md files through a model-facing skills catalog and lacks the requested instruction precedence, role locking, per-skill memory/tool authority, and behavioral monitoring boundary.

## What This Changes

The issue requests core security hardening that isolates SKILL.md instructions from trusted agent context and adds capability/role/memory/tool enforcement for skills.

## Best Possible Solution

Adopt a maintainer-approved trusted/untrusted skill precedence model, expose narrow per-skill authority metadata, enforce it in prompt assembly and runtime policy, and cover malicious SKILL.md cases with focused tests and docs.
