Keep open. Current main still carries split-turn prefix messages through compaction without an obvious duplicate-boundary guard, and the issue describes a plausible session-state/memory bloat bug that is not covered by the adjacent closed split-turn fixes.

## What This Changes

The issue asks OpenClaw to stop split-turn compaction from repeatedly aggregating the same `turnPrefixMessages` during rapid tool-call completion bursts.

## Best Possible Solution

Add a focused regression for repeated split-turn compaction in one tool-heavy turn, then make the core preparation/safeguard path include each prefix segment once before post-compaction memory indexing sees it.
