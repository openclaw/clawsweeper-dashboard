Full review comments:

- **[P1] Preserve queued reservations during stale-session cleanup:** `src/auto-reply/reply/dispatch-from-config.ts:1392-1395`
  - body: This force-clear also applies when the active operation is still `queued`. Current dispatch reserves a queued operation before session init, and `get-reply-run.ts` intentionally updates that queued reservation when stale init rotates the sessionId; `session.ts` also documents that queued pre-dispatch reservations still let the current turn roll over. In a reset race, a second visible turn can now see the first turn's queued old-session reservation and clear it before it rebinds, which removes the registry owner for a valid in-flight turn and can drop or duplicate visible delivery. Please skip queued operations here or move the cleanup to a reset-scoped path that preserves queued reservations.
  - confidence: 0.87
