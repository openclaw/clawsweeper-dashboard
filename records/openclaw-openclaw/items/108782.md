## Summary

Keep open for maintainer review: the scope-only split is coherent and well-proven, but the PR still introduces a new model-facing memory partition contract and performs a persistent schema migration during normal runtime initialization, contrary to the repository’s doctor-owned migration boundary.

## What This Changes

The PR adds optional scoped partitions to the LanceDB memory plugin, including scoped recall, deletion, deduplication and CLI search, a persisted `scope` column, documentation, and regression tests.

## Best Possible Solution

Define one typed scope contract across store, recall, capture and forget—preferably derived or validated from active runtime context—then add a plugin doctor migration that creates and verifies the column while preserving global rows and proving fresh-install, upgrade, and automatic-recall behavior.
