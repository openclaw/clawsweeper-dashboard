Keep open: current main and latest stable still send the selected Bedrock runtime model id as the AWS request identity, while the reported `params.modelId` ARN remains ordinary configured params and the supported Bedrock profile/ARN contract is still a maintainer decision.

## What This Changes

The issue asks OpenClaw to support AWS Bedrock Haiku 4.5 inference-profile identities for cron/model execution, either through `params.modelId`, full ARN model refs, or an alias/profile resolver.

## Best Possible Solution

Define one canonical Bedrock identity contract, document it, then add focused runtime/discovery/cron tests plus a live Bedrock proof for the maintainer-approved Haiku 4.5 profile shape.
