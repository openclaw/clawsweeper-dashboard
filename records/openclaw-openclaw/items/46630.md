## Summary

Keep open: current main has slash-command autocomplete, command discovery, and plugin Control UI tabs, but it still lacks a user-defined shortcut/prompt sidebar with click-to-insert browsing. The remaining question is product/API ownership, because adding `webchat.shortcuts` or a `shortcuts.json` would create a new config surface that may duplicate existing command and plugin metadata.

## What This Changes

Requested a webchat sidebar for user-defined shortcut keywords with click-to-insert prompts and hover descriptions.

## Best Possible Solution

Expose shortcut discovery through one canonical command/prompt metadata surface in Control UI, preferably reusing `commands.list` and plugin descriptors unless maintainers explicitly approve a first-party shortcut config.
