## Summary

Keep open: this is a focused, still-relevant Windows CLI restart bug fix, but the proposed unmanaged Windows fallback can kill the active raw gateway before a Scheduled Task/startup handoff is proven, and the supplied live proof covers the managed service path rather than the changed unmanaged path.

## What This Changes

The branch adds a Windows SIGUSR1 guard in gateway process signaling and routes unmanaged Windows gateway restart through `triggerOpenClawRestart()`, with focused unit tests.

## Best Possible Solution

Keep the SIGUSR1 Windows guard, but preflight a valid managed handoff and protect the active raw listener PID before cleanup, then require real unmanaged Windows proof before merge.

## Reproduction Assessment

Yes, at source level: on the PR head, win32 plus service-not-loaded plus one verified gateway PID enters the new branch and calls `triggerOpenClawRestart()`, whose cleanup can terminate verified listeners without protecting that PID. I did not run a live Windows unmanaged gateway in this read-only review.

## Solution Assessment

No as written: the Scheduled Task handoff is the right direction only after a managed target is proven and the active raw PID is protected. A narrower fix should fail before cleanup when no task or startup target exists, or use a handoff helper that cannot clean up the active unmanaged process.
