## Summary

Keep this PR open for landing: current main still decodes the complete supplied string before Ed25519 validation, the new throw is safely absorbed by production callers, and valid key and signature inputs are far below the proposed ceiling. Existing 64 KiB pre-auth request limits mean this is defense in depth rather than a fix for unlimited gateway allocation, but it remains correct and maintainable hardening.

## What This Changes

The PR adds a 4,096-character input bound to the shared Ed25519 base64url decoder and focused tests for valid and oversized input.

## Best Possible Solution

Land the shared early-rejection guard with focused regression coverage, preserving valid Ed25519 behavior while retaining broader gateway payload limits as the outer defense.
