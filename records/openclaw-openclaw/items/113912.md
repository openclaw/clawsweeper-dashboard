## Summary

Keep open: the report identifies a plausible heartbeat-ack regression where a provider reasoning block prevents an otherwise OK-only heartbeat from being suppressed. The documented contract says OK acknowledgements are dropped by default, so the current behavior needs a focused source and provider-payload verification rather than closure.

## What This Changes

Recognize an otherwise text-only `HEARTBEAT_OK` heartbeat acknowledgement when the provider includes a preceding thinking block.

## System Context

Heartbeat runs receive provider assistant content and decide whether the result is a silent acknowledgement or a user-visible alert. The acknowledgement filter feeds channel delivery, including Telegram, so a false non-OK classification produces chat noise.

## Architecture Diagram

flowchart LR
  A[Heartbeat schedule] --> B[Provider assistant response]
  B --> C[Content blocks]
  C --> D[Heartbeat acknowledgement filter]
  D -->|OK-only| E[Suppress acknowledgement]
  D -->|Alert or substantive content| F[Channel delivery]
  F --> G[Telegram chat]

## Best Possible Solution

Make heartbeat acknowledgement detection ignore non-user-visible reasoning/thinking blocks while retaining the existing fail-open behavior for tool, media, and other substantive content, with regression coverage for both paths.
