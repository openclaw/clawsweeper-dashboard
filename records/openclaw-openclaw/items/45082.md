## Summary

Current main has fixed the proactive Mattermost message-tool thread inheritance path, but the broader issue still has a source-reproducible cron/heartbeat wake gap for non-direct Mattermost thread sessions, so the canonical issue should stay open until that route-persistence path is repaired or explicitly rejected.

## What This Changes

Mattermost proactive sends and wake-triggered replies from thread-scoped sessions should inherit the active thread context instead of posting at the channel root or wrong target.

## Best Possible Solution

Keep the issue open until a narrow Mattermost route-persistence fix stores or reconstructs the correct non-direct thread delivery context on the right session entry and proves cron/heartbeat wakes post back to the originating thread without stale-thread reuse.
