## Summary

Keep this PR open for maintainer review. The latest branch narrows the current-room compatibility repair and supplies real provider evidence, but it intentionally changes the shared contract between core and independently released external channel plugins; that contract needs an owner decision before merge.

## What This Changes

The branch carries OpenClaw’s trusted active-conversation target through shared message-action dispatch so an older external Nextcloud Talk plugin can resolve an equivalent current-room alias for delegated reactions.

## System Context

Model-selected message actions pass from the outbound runner into shared channel dispatch, where OpenClaw checks conversation-read authorization before routing to either a channel plugin or the Gateway. External channel plugins then resolve the target and perform the provider action, so this compatibility layer affects plugin upgrades as well as message-action security boundaries.

## Architecture Diagram

flowchart LR
  Model[Model-selected action] --> Runner[Outbound message runner]
  Runner --> Dispatch[Shared channel dispatch]
  Dispatch --> Guard[Exact-current authorization]
  Guard --> Context[Trusted current target]
  Context --> Plugin[External channel plugin]
  Dispatch --> Gateway[Gateway-owned execution]
  Plugin --> Provider[Nextcloud Talk reaction]
  Gateway --> Provider

## Best Possible Solution

Retain one narrow, documented shared compatibility path only if core owners approve canonical-current target forwarding for independently released external plugins; otherwise move alias support into the Nextcloud Talk plugin or add a more explicit plugin SDK contract with upgrade tests.
