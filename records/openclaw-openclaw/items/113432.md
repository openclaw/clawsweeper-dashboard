## Summary

Keep this PR open for maintainer review. It remains the active, proof-positive candidate fix for the linked external-plugin compatibility regression, but it deliberately establishes a shared core-to-external-plugin canonical-target contract that needs explicit maintainer acceptance before merge.

## What This Changes

This PR changes shared message-action dispatch so a delegated external channel action can preserve an authorized canonical current-room target while allowing older Nextcloud Talk plugin releases to accept equivalent room aliases.

## System Context

The message tool sends model- or operator-requested channel actions through a shared runner that applies conversation and cross-provider policy before dispatching to a channel plugin. External plugins then resolve the target and perform the provider operation, such as adding a reaction to the active Nextcloud Talk room.

## Architecture Diagram

flowchart LR

  B --> C[Conversation and egress policy]
  C --> D[Trusted active conversation]
  D --> E[External plugin target resolution]
  E --> F[Nextcloud Talk room reaction]

## Best Possible Solution

Adopt the narrow host-authorized canonical-target handoff only if maintainers want it to be the supported external-plugin contract; otherwise place equivalent-alias normalization in the Nextcloud Talk plugin and keep shared core dispatch unchanged.
