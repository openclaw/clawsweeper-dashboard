## Summary

Keep open: the PR addresses the central corrupt-JSON crash path, but current head still lets corrupt duplicate pending/claimed rows throw from enqueue and adds an unbounded full-queue reconciliation step on claim/recovery hot paths.

## What This Changes

The PR changes the SQLite channel ingress queue to use tagged JSON parsing, skip or tombstone corrupt payload rows, omit corrupt metadata, and adds queue plus adjacent gateway test updates.

## Best Possible Solution

Keep the parser guard in the queue owner module, but tombstone corrupt duplicate rows during enqueue and make corrupt-row reconciliation bounded to rows already considered by claim and recovery operations.
