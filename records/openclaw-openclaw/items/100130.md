## Summary

Keep open: this is a plausible fix for a real restart-continuation symptom, but the patch removes the deliberate session-id rebound guard added by the merged stale-continuation fix and would allow an old queued internal continuation to dispatch into a different session key binding.

## What This Changes

The PR narrows restart continuation fallback from any `expectedSessionId` mismatch to only a missing session entry, and updates the gateway sentinel tests to expect dispatch after a session id changes.

## Best Possible Solution

Preserve the existing rebound-session protection while adding a narrow, source-proven discriminator for genuine same-session reload rotation, then update tests and real behavior proof for both paths.

## Reproduction Assessment

Yes for the review finding: current main, the merged fix provenance, and the PR diff show that a mismatched non-missing session entry would now dispatch instead of falling back. I did not run a live restart scenario in this read-only review.

## Solution Assessment

No. Narrowing the guard to only missing entries is not the best fix because it conflates real same-session reload rotation with a session-key rebound; the safer fix needs to preserve the rebound guard and separately prove the reported rotation case.
