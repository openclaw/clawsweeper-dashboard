## Summary

This remains a credible channel-runtime bug: the report gives a specific hot-reload sequence where Telegram turns retain obsolete agent tool policy while a fresh CLI runtime reads the corrected configuration. The related hot-reload registry report overlaps in failure shape but does not yet establish one shared root cause, so this issue should remain independently actionable pending current-main source and live reproduction confirmation.

## What This Changes

Fix or safely reclassify hot reloads of `agents.list[].tools` so Telegram polling ingress workers cannot continue serving turns with an outdated per-agent tool policy.

## Best Possible Solution

Make one owner-controlled reload contract authoritative: either rebuild/replace every channel worker’s resolved agent runtime snapshot before accepting its next turn, or classify the affected `agents.list[].tools` changes as restart-required with clear operator-visible status and focused regression coverage for both Telegram and fresh embedded/CLI runtimes.
