## Summary

Keep open: current main and v2026.6.11 have partial ClawHub verification and install provenance, but they still do not enforce trusted SKILL.md signatures or define unsigned-skill capability policy at runtime; related PR #96008 is only a narrow installed-file hash verification slice.

## What This Changes

Request code signing, integrity verification, and unsigned/degraded-mode policy for SKILL.md skill content.

## Best Possible Solution

Keep #12507 open as the canonical native skill integrity/signature tracker and extend ClawHub trust metadata into runtime enforcement after maintainers settle trust roots, revocation, unsigned compatibility, and operator override behavior.

## Reproduction Assessment

Yes, source-level: current main loads SKILL.md into Skill records and runtime snapshots without comparing a trusted signature, persisted digest, revocation state, or unsigned capability tier.

## Solution Assessment

Unclear as a one-shot implementation: the direction is valid, but maintainers still need to choose trust roots, signature authority, revocation behavior, compatibility defaults, and operator overrides before code is safe to land.
