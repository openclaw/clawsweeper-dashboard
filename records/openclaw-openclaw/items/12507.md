## Summary

Keep open: current main has useful ClawHub verification, artifact, provenance, and installed SKILL.md hash metadata, but OpenClaw still does not bind runtime-loaded SKILL.md content to a trusted signature/digest gate or define unsigned-skill capability policy.

## What This Changes

Request to add cryptographic integrity/signature verification for SKILL.md skills and restrict or degrade unsigned skills.

## Best Possible Solution

Define one canonical native skill trust model that binds ClawHub or publisher signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned or revoked capability policy with migration.
