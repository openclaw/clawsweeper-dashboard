## Summary

Keep open: current main and v2026.6.11 still have ClawHub install provenance and a manual `openclaw skills verify` surface, but runtime skill loading does not enforce trusted SKILL.md signatures, persisted digest checks, revocation state, or unsigned capability policy.

## What This Changes

The issue requests cryptographic integrity and signature verification for SKILL.md skills, plus policy for unsigned or untrusted skills across ClawHub distribution and runtime loading.

## Best Possible Solution

Define one maintainer-approved native skill trust model covering ClawHub publisher/signature metadata, persisted artifact/SKILL.md integrity, runtime load enforcement, revocation, status surfaces, and unsigned capability behavior.

## Reproduction Assessment

Yes at source level. Current main and v2026.6.11 read SKILL.md into skill records and runtime snapshots without comparing a trusted signature, persisted digest, revocation state, or unsigned capability tier.

## Solution Assessment

No as a one-shot hash or Ed25519 patch. The maintainable solution needs maintainer-approved trust roots, revocation behavior, compatibility defaults, ClawHub metadata, and operator override policy before runtime enforcement lands.
