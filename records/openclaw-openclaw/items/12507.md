## Summary

Keep open: current main and v2026.6.11 include useful ClawHub verification, provenance, trust-card, and local SKILL.md hash groundwork, but OpenClaw still does not bind runtime-loaded SKILL.md content to a trusted signature/digest gate or define unsigned-skill capability policy.

## What This Changes

Request to add cryptographic verification/signing for SKILL.md skills and restrict unsigned skills through a defined trust policy.

## Best Possible Solution

Define one canonical native skill trust model that binds ClawHub or publisher signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned/revoked capability policy with migration.
