## Summary

Keep open: current main and the latest release have advisory ClawHub verification/trust surfaces and persisted install provenance, but they still do not enforce a trusted SKILL.md signature or digest before runtime loading or define unsigned-skill capability policy.

## What This Changes

The issue requests cryptographic signing and integrity verification for SKILL.md skills, including unsigned-skill restrictions and ClawHub signing infrastructure.

## Best Possible Solution

Define one canonical native skill trust model that binds publisher or ClawHub signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned or revoked capability policy with migration.
