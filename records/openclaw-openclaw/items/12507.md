## Summary

Keep open: current main and v2026.6.11 still load local SKILL.md bytes into runtime skill records and prompt snapshots without a trusted signature/digest gate, while the shipped ClawHub provenance work remains install/status metadata rather than runtime enforcement.

## What This Changes

Request cryptographic SKILL.md integrity/signature verification, ClawHub signing metadata, and degraded capability policy for unsigned skills.

## Best Possible Solution

Keep this as the canonical native skill signature work and define trust roots, revocation, persisted provenance, runtime load enforcement, status surfaces, and unsigned capability policy before implementation.

## Reproduction Assessment

Yes, source-reproducible: current main and v2026.6.11 read SKILL.md into Skill records and runtime snapshots without comparing a trusted signature, persisted digest, revocation state, or unsigned capability tier.

## Solution Assessment

No as a one-shot Ed25519 or hash patch. The maintainable solution needs maintainer-approved trust roots, revocation, compatibility defaults, ClawHub metadata, and operator override behavior before runtime enforcement lands.
