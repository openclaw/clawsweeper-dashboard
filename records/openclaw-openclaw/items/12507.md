## Summary

Keep open: current main has meaningful ClawHub provenance and hash groundwork, but it still does not enforce trusted SKILL.md signatures or digests before runtime loading, and the unsigned-skill policy remains a security/product decision.

## What This Changes

The issue requests cryptographic signature or digest verification for skills so OpenClaw can reject or restrict tampered or unsigned skill instructions.

## Best Possible Solution

Define a canonical signed-skill trust model first, then wire install, audit, status, runtime loading, and capability enforcement to the same persisted provenance with documented compatibility behavior.
