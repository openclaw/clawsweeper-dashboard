## Summary

Keep open: current main and latest release still load SKILL.md bytes into skill records and runtime snapshots without a trusted signature/digest enforcement gate or unsigned-skill capability policy; recent ClawHub provenance work is useful groundwork, but it is still audit metadata rather than the requested runtime trust boundary.

## What This Changes

The issue requests cryptographic integrity and signature verification for distributed SKILL.md skill content, including unsigned-skill restrictions and ClawHub signing infrastructure.

## Best Possible Solution

Keep this as the canonical native skill integrity/signature design item and define one trust model covering ClawHub metadata, persisted provenance, runtime load enforcement, status surfaces, revocation, and unsigned capability policy.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 read SKILL.md into Skill records and runtime snapshots without comparing a trusted signature, persisted digest, revocation state, or unsigned capability tier.

## Solution Assessment

No as a one-shot hash or Ed25519 patch. The maintainable solution needs maintainer-approved trust roots, revocation, compatibility defaults, ClawHub metadata, and operator override behavior before runtime enforcement lands.
