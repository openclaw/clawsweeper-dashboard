## Summary

Keep open: current main and v2026.6.11 have ClawHub trust/provenance surfaces, but SKILL.md content still reaches runtime skill snapshots without trusted signature, digest, revocation, or unsigned-skill capability enforcement.

## What This Changes

The issue requests cryptographic integrity/signature verification and unsigned-skill policy for SKILL.md skills across ClawHub distribution and runtime loading.

## Best Possible Solution

Define a maintainer-approved native skill trust contract that carries ClawHub signature/provenance metadata through install, persisted lock/origin state, runtime snapshot/load enforcement, CLI/UI status, unsigned/revoked policy, migration, and docs.

## Reproduction Assessment

Yes. Source inspection shows current main reads SKILL.md into Skill records and runtime snapshots without comparing a trusted signature, persisted digest, revocation state, or unsigned capability tier.

## Solution Assessment

No, not as a one-shot Ed25519 or hash patch. The maintainable path needs maintainer-approved trust roots, revocation, compatibility defaults, operator override behavior, and runtime enforcement semantics before code lands.
