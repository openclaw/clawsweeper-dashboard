## Summary

Keep open. Current main has ClawHub verification/status surfaces and persisted install provenance, but the runtime still loads SKILL.md without enforcing trusted signatures, digest matches, revocation state, or unsigned-skill capability policy.

## What This Changes

Request to add cryptographic integrity and signature verification for SKILL.md skills, including unsigned-skill restrictions and ClawHub signing support.

## Best Possible Solution

Keep this as the canonical native skill signature/integrity tracker and design one ClawHub-backed trust contract with runtime enforcement, revocation, unsigned compatibility, and operator override semantics.

## Reproduction Assessment

Yes, as a source-level feature gap. Current main reads SKILL.md into Skill records and runtime snapshots without comparing a trusted signature, persisted digest, revocation state, or unsigned capability tier.

## Solution Assessment

Unclear as a final implementation path. Signature verification is the right problem area, but maintainers still need to choose trust roots, revocation, compatibility defaults, and operator override behavior.
