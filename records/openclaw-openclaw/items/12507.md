## Summary

Keep open: current main and the latest release include useful ClawHub verification and local provenance metadata, but OpenClaw still does not bind runtime-loaded SKILL.md content to a trusted signature/digest gate or define unsigned-skill capability policy.

## What This Changes

Request signed or otherwise integrity-verified SKILL.md loading with degraded or restricted behavior for unsigned skills.

## Best Possible Solution

Define one canonical native skill trust model that binds publisher or ClawHub signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned or revoked capability policy with migration.
