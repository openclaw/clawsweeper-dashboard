## Summary

Keep open: current main still lacks runtime-enforced SKILL.md signature or trusted-digest verification. The merged ClawHub provenance work is useful groundwork, but the loader still accepts local skill bytes into runtime snapshots without binding them to signed publisher or registry metadata.

## What This Changes

The issue requests cryptographic integrity/signature verification for SKILL.md skills, plus restricted behavior for unsigned skills and ClawHub signing support.

## Best Possible Solution

Define one native skill trust model that binds ClawHub or publisher signatures to the exact runtime-loaded SKILL.md or full skill contents, persists expected provenance, exposes status, and specifies unsigned or revoked capability policy.
