## Summary

Keep open: current main and v2026.6.11 persist ClawHub provenance and expose advisory verification, but they still do not bind runtime-loaded SKILL.md bytes to trusted signatures or digests before prompt use or capability policy.

## What This Changes

Request cryptographic integrity/signature verification for SKILL.md skills, with restricted behavior for unsigned or unverified skills.

## Best Possible Solution

Define one native skill trust model that binds trusted signatures or digests to the exact runtime-loaded SKILL.md contents, persists expected provenance, exposes status, and specifies unsigned or revoked capability policy.
