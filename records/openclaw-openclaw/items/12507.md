## Summary

Keep open. Current main and v2026.6.11 have ClawHub verification/provenance surfaces, but SKILL.md is still loaded into runtime skill records without mandatory trusted signature/digest validation or an unsigned-skill capability policy.

## What This Changes

The issue requests cryptographic integrity/signature verification for distributed skills, with unsigned-skill capability restrictions and ClawHub signing metadata.

## Best Possible Solution

Keep native skill integrity as a canonical security/product item and design one ClawHub-backed trust contract with runtime enforcement, revocation, unsigned compatibility, and operator override semantics.

## Reproduction Assessment

Yes, as a source-level feature gap: current main and v2026.6.11 read SKILL.md into Skill records and snapshots without checking trusted signature, persisted digest, revocation, or unsigned capability tier.

## Solution Assessment

Unclear as a final implementation path: signature verification is the right problem area, but maintainers still need to choose trust roots, revocation, compatibility defaults, and operator override behavior before implementation.
