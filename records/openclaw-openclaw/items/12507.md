## Summary

Keep open: current main has useful ClawHub provenance and verification surfaces, but SKILL.md still reaches runtime skill snapshots without trusted signature/digest enforcement or an unsigned-skill capability policy.

## What This Changes

The issue requests cryptographic integrity and signature verification for SKILL.md skills, including runtime enforcement and degraded capability handling for unsigned skills.

## Best Possible Solution

Keep this as the canonical native skill-signature work and extend trusted ClawHub metadata through install/update, persisted lock/origin state, runtime load/snapshot enforcement, status surfaces, and documented unsigned/revocation policy after maintainer security design.

## Reproduction Assessment

Yes. Source inspection shows current main reads SKILL.md into Skill records and prompt snapshots without comparing a trusted signature, persisted digest, revocation state, or unsigned capability tier.

## Solution Assessment

No for a narrow automated hash-only patch. The maintainable solution needs maintainer-approved trust roots, signature/envelope format, revocation behavior, compatibility defaults, and operator override semantics before runtime enforcement lands.
