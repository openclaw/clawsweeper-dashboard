## Summary

Keep open: current main has ClawHub skill trust-card, verdict, and provenance surfaces, but it still does not bind the SKILL.md bytes loaded into runtime skill snapshots to a trusted signature/digest policy or define unsigned capability behavior. This remains the canonical security/product tracker for native skill signing and runtime enforcement.

## What This Changes

Add trusted code-signature and content-integrity verification for SKILL.md skills, including unsigned/degraded capability policy across ClawHub installs and runtime loading.

## Best Possible Solution

Define one canonical native skill trust model that binds publisher or ClawHub signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned or revoked capability policy with migration.
