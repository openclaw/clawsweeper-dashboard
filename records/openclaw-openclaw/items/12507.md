## Summary

Keep open: current main and the latest release still do not enforce a trusted SKILL.md signature or digest before runtime loading, and the remaining work is a security/product trust-model decision rather than cleanup.

## What This Changes

The issue requests cryptographic integrity verification and signing for SKILL.md/native skills, with policy for unsigned skills and capability restrictions.

## Best Possible Solution

Define one canonical native skill trust model that binds publisher or ClawHub signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned or revoked capability policy with migration.
