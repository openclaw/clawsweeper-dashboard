## Summary

Keep open: current main has advisory ClawHub verification and persisted local provenance for installed skills, plus an open narrow hash-verification PR, but it still lacks runtime-enforced trusted SKILL.md signatures or digests and an unsigned-skill capability policy.

## What This Changes

The issue requests cryptographic signature and integrity verification for SKILL.md skill content, including policy for unsigned skills.

## Best Possible Solution

Define one canonical native skill trust model that binds publisher or ClawHub signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned or revoked capability policy with migration.
