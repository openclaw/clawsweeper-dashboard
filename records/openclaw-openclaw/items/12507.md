## Summary

Keep open: current main has useful ClawHub trust/provenance groundwork, but it still does not enforce trusted SKILL.md signatures or digests at runtime, and unsigned-skill capability policy remains a security/product decision.

## What This Changes

The issue requests cryptographic integrity and signature verification for skills before they are loaded or granted capabilities.

## Best Possible Solution

Define one canonical native skill trust model that binds ClawHub or publisher signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned/revoked capability policy with migration.
