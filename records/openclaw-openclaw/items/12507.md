## Summary

Keep open: current main has advisory ClawHub verification and provenance metadata, but runtime SKILL.md loading still does not enforce signed or digest-bound contents or define unsigned capability policy.

## What This Changes

Request to add cryptographic signing and integrity verification for SKILL.md skills, with restricted behavior for unsigned skills.

## Best Possible Solution

Define one canonical native skill trust model that binds publisher or ClawHub signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned or revoked capability policy with migration.
