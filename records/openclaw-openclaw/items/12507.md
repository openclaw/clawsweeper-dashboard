## Summary

Keep open: current main and v2026.6.11 have advisory ClawHub verification/provenance, but no runtime trusted signature gate or unsigned capability policy for SKILL.md loading.

## What This Changes

The issue requests cryptographic integrity/signature verification for distributed `SKILL.md` skills, with policy differences for signed versus unsigned skills.

## Best Possible Solution

Keep this as the canonical SKILL.md trust-boundary issue and design a staged model that binds ClawHub verification metadata, persisted expected integrity, loader-time signature checks, unsigned capability policy, migration, docs, and tests.
