## Summary

Keep open: current main has ClawHub provenance and verification-envelope groundwork, but it still does not enforce trusted SKILL.md signatures/digests at runtime or define unsigned-skill capability policy. The closed SIE proposal was consolidated into this issue, while related open security/profile work overlaps without superseding it.

## What This Changes

Request native SKILL.md integrity/signature verification, ClawHub signing support, and degraded capability behavior for unsigned skills.

## Best Possible Solution

Define one canonical signed-skill trust model that binds trusted ClawHub or publisher signatures to exact loaded contents, persists and reverifies expected state, exposes status, and specifies unsigned/revoked capability policy with migration.
