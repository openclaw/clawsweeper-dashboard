## Summary

Keep open: current main and v2026.6.11 have ClawHub trust/verification surfaces and persisted install provenance, but they still do not enforce trusted SKILL.md signatures or unsigned-skill capability policy at runtime.

## What This Changes

The issue requests cryptographic integrity/signature verification for SKILL.md skills, plus degraded or restricted behavior for unsigned skills.

## Best Possible Solution

Keep this as the canonical native skill integrity/signature tracker and extend current ClawHub trust/provenance metadata into runtime enforcement after maintainers settle trust roots, revocation, unsigned compatibility, and operator override behavior.

## Reproduction Assessment

Yes, as a source-level feature gap: current main reads SKILL.md into Skill records and runtime snapshots without comparing a trusted signature, persisted digest, revocation state, or unsigned capability tier.

## Solution Assessment

No, not as a one-shot Ed25519/degraded-mode patch without design; the maintainable path is to extend current ClawHub verification and provenance into runtime enforcement after maintainers choose trust roots, revocation, compatibility, and operator override behavior.
