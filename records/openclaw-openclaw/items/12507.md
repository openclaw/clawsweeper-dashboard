## Summary

Keep open: current main has useful ClawHub skill provenance and advisory verification surfaces, but it still does not bind loaded SKILL.md bytes or skill capability access to a trusted signature/digest policy. This remains the canonical security/product tracker for native skill signing and runtime enforcement.

## What This Changes

Request cryptographic integrity/signature verification for SKILL.md skills, plus restricted or degraded behavior for unsigned skills.

## Best Possible Solution

Define one canonical native skill trust model that binds publisher or ClawHub signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned or revoked capability policy with migration.
