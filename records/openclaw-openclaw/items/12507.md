## Summary

Keep open. Current main and v2026.6.11 record ClawHub skill provenance and expose verify/status paths, but runtime skill loading still does not enforce trusted SKILL.md signatures or digests, nor an unsigned-skill capability policy; the discussion keeps this as the canonical security/product design item.

## What This Changes

The issue requests cryptographic signing and integrity verification for SKILL.md skills, loader enforcement, and degraded restrictions for unsigned skills.

## Best Possible Solution

Keep this as the canonical native skill signature/integrity tracker and design one ClawHub-backed trust contract with runtime enforcement, revocation, unsigned compatibility, and operator override semantics.

## Reproduction Assessment

Yes, as a source-level feature gap. Current main and v2026.6.11 read SKILL.md into Skill records and runtime snapshots without comparing a trusted signature, persisted digest, revocation state, or unsigned capability tier.

## Solution Assessment

Unclear as a final implementation path. Signature verification is the right problem area, but maintainers still need to choose trust roots, revocation, compatibility defaults, profile/config shape, and operator override behavior before implementation.
