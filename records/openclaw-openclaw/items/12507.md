## Summary

Keep open: current main has ClawHub skill verification, trust-card, lock, and UI verdict surfaces, but SKILL.md content still loads into runtime snapshots without a required trusted signature/digest gate or decided unsigned-skill capability policy.

## What This Changes

The issue requests cryptographic verification/signing for SKILL.md skills, plus degraded or restricted behavior for unsigned skills.

## Best Possible Solution

Define one canonical signed-skill trust model that binds ClawHub or publisher verification to exact loaded contents, persists and reverifies expected state, exposes status, and specifies unsigned or revoked capability policy with migration.
