## Summary

Keep open: current main and v2026.6.11 have useful ClawHub verification, trust-card, provenance, and local SKILL.md hash groundwork, but runtime-loaded SKILL.md content is still not bound to a trusted signature/digest gate and unsigned-skill capability policy remains undecided.

## What This Changes

The issue requests cryptographic integrity and signature verification for SKILL.md skill packages, plus restricted behavior for unsigned skills.

## Best Possible Solution

Define one canonical native skill trust model that binds ClawHub or publisher signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned/revoked capability policy with migration.
