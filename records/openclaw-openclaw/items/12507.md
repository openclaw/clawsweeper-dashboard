## Summary

Keep open: current main and the latest release still provide ClawHub verification/provenance surfaces, but not trusted SKILL.md signature enforcement, runtime tamper gating, or an unsigned-skill capability policy.

## What This Changes

Request native cryptographic content/signature verification for SKILL.md skills, ClawHub signing metadata, and restricted handling for unsigned skills.

## Best Possible Solution

Keep this as the canonical native skill trust issue and define trust roots, revocation, unsigned compatibility, and capability policy before extending current ClawHub provenance into runtime enforcement.

## Reproduction Assessment

Yes, source-reproducible: current main and v2026.6.11 load SKILL.md into skill snapshots without trusted signature or unsigned-policy enforcement.

## Solution Assessment

A narrow hash-only or one-off Ed25519 patch is not the best fix; the best path is a maintainer-approved trust model that composes ClawHub metadata, local/plugin skill roots, runtime loading, and compatibility policy.
