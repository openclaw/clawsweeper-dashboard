## Summary

Keep open: current main has ClawHub skill trust checks, verification output, and installed artifact/skill-file metadata, but it still does not enforce trusted SKILL.md signatures or capability policy at runtime. The related SIE proposal was closed as a duplicate of this issue, so this remains the canonical native skill signature and integrity design item.

## What This Changes

The issue requests cryptographic integrity/signature verification for SKILL.md skills, including ClawHub signing metadata, loader verification, and restricted behavior for unsigned skills.

## Best Possible Solution

Keep this as the canonical native skill trust-boundary issue and design a staged signature/integrity model that binds ClawHub metadata, persisted expected digests/signatures, loader-time verification, unsigned-skill policy, and upgrade migration before broad enforcement.
