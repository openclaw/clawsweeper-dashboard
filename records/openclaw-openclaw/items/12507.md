## Summary

Keep open. Current main and v2026.6.11 have ClawHub trust-envelope and install-provenance surfaces, but runtime skill loading still consumes SKILL.md without enforcing a trusted signature/digest decision or unsigned-skill capability policy.

## What This Changes

Request to add trusted SKILL.md content signing/integrity verification for native skills, plus degraded capability behavior for unsigned skills and ClawHub signing infrastructure.

## Best Possible Solution

Keep this open as the canonical native skill signature/integrity tracker and define one ClawHub-backed trust contract with runtime enforcement, revocation, unsigned compatibility, and operator override semantics.

## Reproduction Assessment

Yes, as a source-level feature gap. Current main and v2026.6.11 read SKILL.md into Skill records and runtime snapshots without comparing a trusted signature, persisted digest, revocation state, or unsigned capability tier.

## Solution Assessment

Unclear as a final implementation path. Signature verification is the right problem area, but maintainers still need to choose trust roots, revocation, compatibility defaults, profile/config shape, and operator override behavior before implementation.
