## Summary

Keep open: current main and v2026.6.11 have advisory ClawHub verification and provenance surfaces, but the runtime still loads SKILL.md without a signed or digest-bound trust gate, unsigned capability tier, or revocation policy. This remains a security/product design issue rather than conservative cleanup.

## What This Changes

The issue requests cryptographic integrity and signature verification for SKILL.md skills, including loader verification and degraded capability behavior for unsigned skills.

## Best Possible Solution

Define one canonical native skill trust model that binds publisher or ClawHub signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned or revoked capability policy with migration.
