## Summary

Keep open: current main and v2026.6.11 have partial ClawHub provenance and advisory verification, but skills still enter runtime snapshots without trusted SKILL.md signature/digest enforcement, revocation state, or unsigned capability policy.

## What This Changes

The issue requests cryptographic integrity and signature verification for SKILL.md skills, including ClawHub signing metadata and reduced capabilities for unsigned skills.

## Best Possible Solution

Define a maintainer-approved native skill trust model that binds ClawHub signed metadata or trusted digests to installed SKILL.md bytes and runtime snapshots, with explicit unsigned/revoked policy, migration, and operator override behavior.

## Reproduction Assessment

Yes, source-level. Current main loads SKILL.md into Skill records and runtime snapshots without comparing a trusted signature, persisted digest, revocation state, or unsigned capability tier.

## Solution Assessment

Unclear as a one-shot implementation. The direction is valid, but maintainers still need to choose trust roots, signature authority, revocation behavior, compatibility defaults, and operator overrides before code is safe to land.
