## Summary

Keep open: current main and the latest checked release have ClawHub verification/provenance metadata, but runtime skill loading still trusts `SKILL.md` content without a signed digest, revocation, or unsigned-skill policy gate, so the core security request remains unresolved.

## What This Changes

The issue requests cryptographic verification and signatures for skills before their `SKILL.md` instructions are trusted by OpenClaw runtime.

## Best Possible Solution

Define one maintainer-approved skill trust model that connects ClawHub publisher/signature metadata, archive/install verification, persisted origin/lock state, runtime `SKILL.md` revalidation, status surfaces, revocation, and unsigned-skill capability policy.

## Reproduction Assessment

Yes, source-level: current main and `v2026.6.11` load `SKILL.md` into skill records and prompt snapshots without enforcing a trusted signature, digest, revocation status, or unsigned-skill tier.

## Solution Assessment

No for a one-shot hash or Ed25519 patch; the best fix needs maintainer decisions on trust roots, ClawHub publisher metadata, revocation, runtime enforcement, and unsigned-skill compatibility.
