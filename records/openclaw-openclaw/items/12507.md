## Summary

Keep open: current main has ClawHub verification, install provenance, and an open narrow local-drift PR, but it still does not enforce a trusted SKILL.md signature or digest before runtime loading and does not define unsigned-skill capability policy.

## What This Changes

The issue requests cryptographic verification and signing for SKILL.md skills, with unsigned skills restricted or degraded according to a maintainer-approved trust policy.

## Best Possible Solution

Define one canonical native skill trust model that binds publisher or ClawHub signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned or revoked capability policy with migration.
