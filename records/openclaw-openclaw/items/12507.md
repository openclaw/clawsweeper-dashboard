## Summary

Keep open: current main has useful ClawHub verification and local provenance groundwork, but it still does not enforce trusted SKILL.md signatures or persisted digests before skill text reaches runtime prompt/capability decisions.

## What This Changes

Request to add cryptographic integrity/signature verification for SKILL.md skills and define restricted behavior for unsigned or unverified skills.

## Best Possible Solution

Define one native skill trust model that binds ClawHub or publisher signatures to the exact runtime-loaded SKILL.md contents, persists expected provenance, exposes status, and specifies unsigned or revoked capability policy.
