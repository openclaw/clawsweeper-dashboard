## Summary

Keep open: current main and the latest release have useful ClawHub skill provenance and verification metadata, but they still do not enforce trusted SKILL.md signatures or define unsigned-skill capability policy at runtime.

## What This Changes

The issue requests cryptographic integrity/signature verification for SKILL.md skills, with trusted ClawHub metadata and restricted behavior for unsigned skills.

## Best Possible Solution

Define one canonical native skill trust model that binds publisher or ClawHub signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned or revoked capability policy with migration.
