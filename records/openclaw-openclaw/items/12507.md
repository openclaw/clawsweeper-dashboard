## Summary

Keep open: current main records some ClawHub skill verification, provenance, and hash metadata, but it still does not enforce trusted SKILL.md signatures or unsigned-skill capability policy at runtime. This remains the canonical security/product decision for native skill trust.

## What This Changes

The issue requests cryptographic integrity/signature verification for SKILL.md skills, plus policy for unsigned skills and ClawHub signing infrastructure.

## Best Possible Solution

Keep this as the canonical native skill trust-boundary issue and settle a staged design that binds ClawHub verification, persisted expected integrity, loader-time signature checks, unsigned policy, and migration before enforcement.

- **Adopt Staged Runtime Trust Model (recommended):** Define a versioned digest/signature contract, persist trusted metadata at install/update, then add loader-time warn/strict enforcement and unsigned capability restrictions with migration guidance.

- **Split The Design First:** Track issuer/signature format, ClawHub metadata, loader checks, capability policy, and migration as separate owner-reviewed design tasks before code work.
