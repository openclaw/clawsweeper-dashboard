## Summary

Keep open: current main and v2026.6.11 have advisory ClawHub verification and local provenance metadata, but they still do not enforce a trusted SKILL.md signature/digest gate at runtime or define unsigned-skill capability policy.

## What This Changes

The issue requests cryptographic integrity/signature verification for SKILL.md skills, with policy for unsigned skills and capability restrictions.

## Best Possible Solution

Define one canonical native skill trust model that binds publisher or ClawHub signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned or revoked capability policy with migration.
