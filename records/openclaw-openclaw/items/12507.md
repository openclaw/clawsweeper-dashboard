## Summary

Keep open: current main and v2026.6.11 still do not enforce trusted SKILL.md signatures or capability tiers at runtime. Recent ClawHub provenance work is useful groundwork, but it stores audit metadata rather than binding runtime-loaded skill bytes to a trusted digest/signature policy.

## What This Changes

The issue requests cryptographic integrity and signature verification for SKILL.md-based skills, including trusted metadata, runtime enforcement, and unsigned-skill capability policy.

## Best Possible Solution

Keep this as the canonical native skill integrity/signature design item and define one trust model covering ClawHub metadata, persisted provenance, runtime load enforcement, status surfaces, revocation, and unsigned capability policy.

## Reproduction Assessment

Yes. Source inspection traces SKILL.md from install metadata through loader and snapshot creation, and both current main and v2026.6.11 lack a trusted signature/digest enforcement gate or unsigned-skill capability tier.

## Solution Assessment

No as a one-shot hash or Ed25519 patch. The maintainable solution needs maintainer-approved trust roots, revocation, compatibility defaults, ClawHub metadata, and operator override behavior before runtime enforcement lands.
