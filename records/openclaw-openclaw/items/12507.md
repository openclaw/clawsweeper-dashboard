## Summary

Keep open: current main and v2026.6.11 still do not enforce signed or trusted-digest verification before SKILL.md content enters the skill/runtime prompt path; merged provenance work and the open hash-verify PR are useful partial slices but do not settle the native skill trust boundary.

## What This Changes

Requests cryptographic integrity and signature verification for SKILL.md skills, plus restricted behavior for unsigned or untrusted skills.

## Best Possible Solution

Define one native skill trust model that binds ClawHub or publisher signatures to the exact runtime-loaded SKILL.md contents, persists expected provenance, exposes verification status, and specifies unsigned or revoked capability policy.
