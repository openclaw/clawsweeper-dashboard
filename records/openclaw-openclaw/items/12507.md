## Summary

Keep open: current main and v2026.6.11 have ClawHub verification/provenance metadata, but they still do not enforce a trusted SKILL.md signature or digest before runtime loading or define unsigned-skill capability policy.

## What This Changes

The issue requests cryptographic verification/signing for SKILL.md skills, with runtime verification and restricted behavior for unsigned skills.

## Best Possible Solution

Define one canonical native skill trust model that binds publisher or ClawHub signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned or revoked capability policy with migration.
