Keep open: current main has advisory ClawHub verification, provenance, and hash metadata, but runtime skill loading still lacks trusted SKILL.md signature enforcement and unsigned-skill capability policy. This remains the canonical product/security decision for native skill trust.

## What This Changes

The issue requests signed and integrity-verified SKILL.md loading, ClawHub signing metadata, and restricted degraded behavior for unsigned skills.

## Best Possible Solution

Keep this as the canonical native skill trust-boundary issue and settle a staged design that binds ClawHub trusted metadata, persisted expected digest/signature state, loader-time checks, unsigned policy, and migration before enforcement.
