## Summary

Keep open: current main has partial ClawHub skill verification, install provenance, and user-facing verify commands, but it still does not enforce trusted SKILL.md signatures or define unsigned-skill runtime policy before prompt loading. The issue remains valid canonical security/product work rather than conservative cleanup-closeable.

## What This Changes

The issue requests cryptographic integrity and signature verification for SKILL.md-based skills, including trusted metadata, runtime verification, and restrictions for unsigned skills.

## Best Possible Solution

Keep this open as the canonical native skill integrity/signature tracker and extend ClawHub trust metadata into runtime enforcement after maintainers settle trust roots, revocation, unsigned compatibility, and operator override behavior.

## Reproduction Assessment

Yes, as a source-level feature gap: current main reads SKILL.md into Skill records and prompt snapshots without checking a trusted signature, revocation state, or unsigned capability tier.

## Solution Assessment

No, not as a one-shot hash-only patch. The maintainable path is to bind ClawHub trust metadata and persisted provenance to runtime-loaded bytes with maintainer-approved policy for unsigned, invalid, revoked, and locally modified skills.
