## Summary

Keep open: current main has ClawHub skill verification and local provenance metadata, but the central request remains unresolved because SKILL.md bytes still enter runtime skill snapshots without trusted signature/digest enforcement or an unsigned-skill capability policy.

## What This Changes

Request native integrity/signature verification for skills, including trusted signing metadata, runtime checks before loading SKILL.md, and restricted behavior for unsigned skills.

## Best Possible Solution

Keep this as the canonical native skill signature work and extend ClawHub trust metadata into install, persisted provenance, runtime snapshot/load enforcement, CLI/UI status, and documented unsigned/revocation policy after maintainer security decisions.

## Reproduction Assessment

Yes. Source inspection shows current main and v2026.6.11 read SKILL.md into Skill records and runtime snapshots without comparing a trusted signature, persisted digest, revocation state, or unsigned capability tier.

## Solution Assessment

No, not as a one-shot Ed25519 patch. The maintainable path needs maintainer-approved trust roots, revocation, compatibility defaults, operator overrides, and capability-policy behavior before runtime enforcement lands.
