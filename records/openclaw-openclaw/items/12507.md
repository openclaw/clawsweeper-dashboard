## Summary

Keep open: current main has ClawHub trust checks and persisted local provenance for installed skills, but it still does not enforce a trusted SKILL.md signature or digest before runtime loading or define unsigned-skill capability policy.

## What This Changes

The issue requests cryptographic integrity/signature verification for SKILL.md skills, plus policy for unsigned skills and ClawHub signing infrastructure.

## Best Possible Solution

Define one canonical native skill trust model that binds publisher or ClawHub signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned or revoked capability policy with migration.
