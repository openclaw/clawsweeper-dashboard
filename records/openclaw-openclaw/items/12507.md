## Summary

Keep open: current main and the latest release have useful ClawHub verification and local provenance metadata, but they still do not enforce trusted SKILL.md signatures or digests at runtime, and unsigned/revoked/degraded capability policy remains a security/product decision.

## What This Changes

The issue requests cryptographic integrity/signature verification for SKILL.md skills, including loader enforcement and degraded capability handling for unsigned skills.

## Best Possible Solution

Keep this as the canonical native skill signature work and define trust roots, revocation, persisted provenance, runtime load enforcement, status surfaces, and unsigned capability policy before implementation.

## Reproduction Assessment

Yes. Current main and v2026.6.11 read SKILL.md into Skill records and runtime snapshots without comparing a trusted signature, persisted digest, revocation state, or unsigned capability tier.

## Solution Assessment

Unclear as a final implementation. A one-shot Ed25519 or hash patch is too narrow; maintainers first need to choose trust roots, revocation, compatibility defaults, ClawHub metadata, and operator override behavior.
