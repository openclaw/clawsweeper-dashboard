## Summary

Keep open: current main and v2026.6.11 have ClawHub verification, provenance, and trust-card surfaces, but runtime-loaded SKILL.md content is still not bound to a trusted signature or digest policy and unsigned-skill capability behavior remains undecided.

## What This Changes

The issue requests cryptographic integrity verification and signing for SKILL.md skills, including runtime verification and restricted behavior for unsigned skills.

## Best Possible Solution

Define one canonical signed-skill trust model that binds ClawHub or publisher verification to exact loaded contents, persists and reverifies expected state, exposes status, and specifies unsigned or revoked capability policy with migration.
