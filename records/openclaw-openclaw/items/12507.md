## Summary

Keep open: current main has useful ClawHub verification and provenance groundwork, but it still does not bind runtime-loaded SKILL.md content to a trusted signature or digest policy, and unsigned-skill capability behavior remains a security/product decision.

## What This Changes

The issue requests cryptographic signature and integrity verification for SKILL.md skills before trusted runtime use.

## Best Possible Solution

Define one canonical native skill trust model that binds ClawHub or publisher signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned/revoked capability policy with migration.
