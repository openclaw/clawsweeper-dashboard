## Summary

Keep open: current main and the latest tagged release have useful ClawHub verification, scan, and provenance surfaces, but they still do not enforce trusted SKILL.md signatures or define runtime policy for unsigned skills.

## What This Changes

The issue requests cryptographic verification for SKILL.md content plus restricted capability behavior for unsigned or untrusted skills.

## Best Possible Solution

Keep this as the canonical native SKILL.md trust-boundary issue and define a staged design that ties ClawHub verification, persisted expected integrity, loader-time signature checks, unsigned policy, and migration together before enforcement.

Owner confidence: high

Options:

- **Adopt staged runtime trust model (recommended):** Define a versioned digest/signature contract, persist trusted metadata at install/update, then add loader-time warn/strict enforcement and unsigned capability restrictions with migration guidance.
- **Keep verification advisory:** Keep ClawHub verify output and install provenance as user-visible trust signals without runtime blocking until maintainers approve a stronger enforcement API.
- **Split design first:** Track issuer/signature format, ClawHub metadata, loader checks, capability policy, and migration as separate owner-reviewed design tasks before implementation.
