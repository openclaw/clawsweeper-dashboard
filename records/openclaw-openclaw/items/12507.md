## Summary

Keep open: current main and v2026.6.11 have ClawHub skill provenance and verification snapshots, but they still do not enforce trusted SKILL.md signatures or unsigned-skill capability policy at runtime.

## What This Changes

Request to add cryptographic integrity and signature verification for SKILL.md skills, including ClawHub signing metadata, loader checks, and restricted behavior for unsigned skills.

## Best Possible Solution

Define a staged skill trust contract that binds ClawHub signature/digest metadata to persisted install state and runtime loading, with explicit unsigned-skill compatibility and capability policy before enforcement.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: What native skill trust model should OpenClaw adopt for SKILL.md integrity: advisory ClawHub verification, runtime signature enforcement, or staged enforcement tied to capability policy?

Rationale: The remaining work defines a security boundary for third-party instructions and can change compatibility for existing skills, so automation cannot choose trust roots, issuer/revocation semantics, or unsigned default behavior safely.

Likely owner: steipete

Owner reason: steipete has the strongest combined signal from prior product-security reviews and adjacent skill trust discussion.

Owner confidence: high

Options:

- **Adopt staged runtime trust model (recommended):** Define a versioned signature/digest contract first, persist trusted metadata at install/update, then add loader-time warn/strict enforcement and capability restrictions with migration guidance.
- **Keep verification advisory:** Treat ClawHub verify output and install trust checks as user-visible advisory signals until maintainers identify a concrete runtime enforcement API.
- **Split before implementation:** Track issuer/signature format, ClawHub metadata, runtime loader checks, capability policy, and migration as separate owner-reviewed issues before code work.

## Reproduction Assessment

Yes for the feature gap: current main loads SKILL.md skills without trusted signature enforcement or unsigned capability state. This is not a broken existing behavior repro; it is a verified missing security capability.

## Solution Assessment

Unclear until maintainers choose the security contract. A hash-only or ClawHub-only patch is not the best solution because the durable fix needs trusted metadata, runtime verification, unsigned compatibility policy, and migration semantics.
