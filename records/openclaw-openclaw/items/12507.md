## Summary

Keep open: current main has ClawHub verification, install provenance, and local hash metadata, but it still does not enforce trusted SKILL.md signatures or define runtime policy for unsigned skills.

## What This Changes

The issue requests signed integrity verification for SKILL.md skills, including trusted publisher/signature metadata, runtime checks, and degraded behavior for unsigned skills.

## Best Possible Solution

Keep this as the canonical native SKILL.md trust-boundary issue and define a staged design that binds ClawHub verification, persisted expected integrity, loader-time signature checks, unsigned policy, and migration before enforcement.

Options:

- **Adopt staged runtime trust model (recommended):** Define a versioned digest/signature contract, persist trusted metadata at install/update, then add loader-time warn/strict enforcement and unsigned capability restrictions with migration guidance.

- **Split design first:** Track issuer/signature format, ClawHub metadata, loader checks, capability policy, and migration as separate owner-reviewed design tasks before code work.
