## Summary

Keep open: current main has ClawHub skill verification, provenance, and installed artifact hashes, but loaded SKILL.md content is still not bound to trusted signatures and unsigned capability policy remains undecided.

## What This Changes

Requested signed and integrity-verified SKILL.md loading for skills, including trusted metadata, runtime verification, and restricted unsigned-skill behavior.

## Best Possible Solution

Define one canonical signed-skill trust model that binds ClawHub or publisher signatures to exact loaded skill contents, persists and reverifies state, exposes status, and specifies unsigned or revoked capability policy with migration.
