## Summary

Keep open: current main has advisory ClawHub verification, install provenance, and local hash metadata, but it still does not bind loaded SKILL.md bytes or skill capability access to a trusted signature or digest policy. ## What This Changes

The issue requests cryptographic integrity and signature verification for SKILL.md skills, including runtime verification and restricted behavior for unsigned skills.

## Best Possible Solution

Define one canonical native skill trust model that binds publisher or ClawHub signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned or revoked capability policy with migration.
