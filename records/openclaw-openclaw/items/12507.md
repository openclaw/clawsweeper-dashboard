## Summary

Keep open: current main and v2026.6.11 still lack runtime-enforced SKILL.md signature or trusted-digest verification; the merged ClawHub provenance work is useful groundwork but does not restrict unsigned or tampered skills before prompt/runtime use.

## What This Changes

The issue requests cryptographic signing and integrity verification for SKILL.md skills, including policy differences for signed, unsigned, and verified-publisher skills.

## Best Possible Solution

Define one native skill trust model that binds ClawHub or publisher signatures to the exact runtime-loaded SKILL.md contents, persists expected provenance, exposes status, and specifies unsigned or revoked capability policy.
