## Summary

Keep open. Current main has ClawHub skill verification metadata, install provenance, and advisory docs, but SKILL.md bytes are still loaded into runtime skill snapshots without trusted digest/signature enforcement or an unsigned-skill capability policy, so the central security request remains unresolved.

## What This Changes

Request native SKILL.md integrity/signature verification, ClawHub signing infrastructure, and restricted behavior for unsigned or unverified skills.

## Best Possible Solution

Keep this as the canonical native skill signature/integrity tracker and design one ClawHub-backed trust contract with runtime enforcement, revocation, unsigned compatibility, and operator override semantics.

## Reproduction Assessment

Yes. Current main and v2026.6.11 read SKILL.md into Skill records and runtime snapshots without verifying trusted signatures, persisted digests, revocation state, or unsigned capability tiers.

## Solution Assessment

Unclear as a final implementation path. Signature verification is the right problem area, but maintainers still need to choose trust roots, revocation, compatibility defaults, config/profile shape, and operator override behavior.
