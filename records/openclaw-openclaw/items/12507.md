## Summary

Keep open. Current main and v2026.6.11 still provide advisory ClawHub trust/verification surfaces and install provenance, but runtime skill loading does not verify trusted SKILL.md signatures or digests and no unsigned-skill capability policy is enforced.

## What This Changes

Requests cryptographic integrity/signature verification for SKILL.md skills, ClawHub signing metadata, and restricted behavior for unsigned skills.

## Best Possible Solution

Keep this open as the canonical native skill signature/integrity tracker and design one ClawHub-backed trust contract with runtime enforcement, revocation, unsigned compatibility, and operator override semantics.

## Reproduction Assessment

Yes, as a source-level feature gap. Current main and v2026.6.11 read SKILL.md into Skill records and runtime snapshots without comparing a trusted signature, persisted digest, revocation state, or unsigned capability tier.

## Solution Assessment

Unclear as a final implementation path: signature verification is the right problem area, but maintainers still need to choose trust roots, revocation, compatibility defaults, and operator override behavior before implementation.
