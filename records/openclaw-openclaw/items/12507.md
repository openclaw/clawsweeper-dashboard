## Summary

Keep open: current main and the latest release have ClawHub trust/provenance surfaces, but SKILL.md content still reaches runtime snapshots without trusted signature or digest enforcement and without unsigned-skill capability policy.

## What This Changes

Add integrity/signature verification for SKILL.md skills and restrict unsigned or untrusted skills according to a security policy.

## Best Possible Solution

Keep this as the canonical native skill signature work and extend ClawHub trust metadata into install, persisted provenance, runtime snapshot/load enforcement, CLI/UI status, and documented unsigned/revocation policy after maintainer security decisions.

## Reproduction Assessment

Yes, source-reproducible: current main reads SKILL.md into Skill records and runtime snapshots without comparing a trusted signature, persisted digest, revocation state, or unsigned capability tier.

## Solution Assessment

No, not as a one-shot Ed25519 patch. The maintainable path needs maintainer-approved trust roots, revocation, compatibility defaults, and operator override behavior before runtime enforcement lands.
