## Summary

Keep open: current main and the latest release have ClawHub skill verification, provenance, and advisory signature metadata, but runtime SKILL.md loading still has no trusted signature gate or unsigned-skill capability policy.

## What This Changes

The issue requests cryptographic verification and signing for SKILL.md skill content, including unsigned-skill restrictions tied to security profiles.

## Best Possible Solution

Keep this as the canonical native skill trust-boundary issue and define a staged contract that binds ClawHub verification, persisted expected integrity, loader-time signature checks, unsigned policy, and migration before enforcement.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: What native SKILL.md trust model should OpenClaw adopt: advisory ClawHub verification only, runtime signature enforcement, or staged enforcement that ties ClawHub verification to loader and capability policy?

Rationale: The remaining work defines trust roots, issuer/signature semantics, revocation, unsigned defaults, and upgrade behavior for third-party instructions, which automation cannot choose safely.

Likely owner: steipete

Owner reason: The strongest available routing signal is prior review ownership plus merged history across ClawHub install, skills docs, and security hardening.

Owner confidence: high

Options:

- **Adopt staged runtime trust model (recommended):** Define a versioned digest/signature contract, persist trusted metadata at install/update, then add loader-time warn/strict enforcement and unsigned capability restrictions with migration guidance.
- **Keep verification advisory:** Keep ClawHub verify output and install provenance as user-visible trust signals without runtime blocking until maintainers define stronger enforcement.
- **Split the design first:** Track issuer/signature format, ClawHub metadata, loader checks, capability policy, and migration as separate owner-reviewed design tasks before code work.

## Reproduction Assessment

Yes for the feature gap: source inspection shows current main records ClawHub verification/provenance metadata but the loader still returns SKILL.md skills without a trusted signature or unsigned-policy state. This is not a broken existing behavior repro; it is a verified missing security capability.

## Solution Assessment

Unclear until maintainers choose the security contract. A hash-only or trust-card-only patch is not the best solution because the durable fix needs trusted metadata, runtime verification, unsigned compatibility policy, and migration semantics.
