## Summary

Keep open: current main and v2026.6.11 have ClawHub trust/provenance surfaces, but they still do not enforce trusted SKILL.md signatures or capability restrictions before skills enter runtime prompts. Related external packages and earlier PRs are useful inputs, but this remains canonical core security/product work.

## What This Changes

The issue requests cryptographic integrity/signature verification for distributed SKILL.md skills, plus restricted behavior for unsigned or unverified skills.

## Best Possible Solution

Keep this as the canonical signed-skill trust model issue: define trusted ClawHub/publisher metadata, persist expected integrity, reverify before runtime use, expose status, and specify unsigned capability policy.
