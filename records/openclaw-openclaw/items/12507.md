## Summary

Keep open: current main and v2026.6.11 still lack a runtime-enforced SKILL.md signature or trusted-digest boundary; the newer ClawHub provenance work is useful audit groundwork, but it does not restrict unsigned or tampered skills before prompt/runtime use.

## What This Changes

Request cryptographic integrity and signature verification for SKILL.md skills, including signed-skill trust metadata and restricted behavior for unsigned skills.

## Best Possible Solution

Define one native skill trust model that binds ClawHub or publisher signatures to the exact runtime-loaded SKILL.md contents, persists expected provenance, exposes status, and specifies unsigned/revoked capability policy.

## Solution Assessment

Unclear as a final implementation path. The security direction is aligned, but a narrow hash-only or one-shot loader patch is not the best fix without maintainer-approved trust roots, revocation, compatibility defaults, and ClawHub metadata binding.
