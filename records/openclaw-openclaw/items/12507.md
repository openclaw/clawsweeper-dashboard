## Summary

Keep open: current main and the latest release have useful ClawHub verification and local provenance metadata, but OpenClaw still does not enforce a trusted SKILL.md signature or digest gate before runtime loading or define the unsigned-skill capability policy.

## What This Changes

The issue requests cryptographic integrity/signature verification for SKILL.md-based skills, including trusted metadata, runtime verification, and unsigned-skill capability policy.

## Best Possible Solution

Define one canonical native skill trust model that binds publisher or ClawHub signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned or revoked capability policy with migration.
