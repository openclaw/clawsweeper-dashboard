## Summary

Keep open. Current main and v2026.6.11 have ClawHub skill verification, provenance metadata, and an advisory verify command, but runtime still loads SKILL.md without enforcing a trusted signature, digest, revocation state, or unsigned-skill capability policy; related items are partial or broader rather than superseding this tracker.

## What This Changes

The issue requests cryptographic integrity/signature verification for SKILL.md skills, trusted publisher metadata, and restricted behavior for unsigned or unverifiable skills.

## Best Possible Solution

Keep this as the canonical native skill signature/integrity tracker and design one ClawHub-backed trust contract with runtime enforcement, revocation, unsigned compatibility, and operator override semantics.

## Reproduction Assessment

Yes, as a source-level feature gap: current main and v2026.6.11 read SKILL.md into Skill records and runtime snapshots without comparing a trusted signature, persisted digest, revocation state, or unsigned capability tier.

## Solution Assessment

Unclear as a final implementation path: signature verification is the right problem area, but maintainers still need to choose trust roots, revocation, compatibility defaults, config/profile shape, and operator override behavior before implementation.
