## Summary

Keep open: current main and v2026.6.11 have ClawHub verification/trust-card groundwork, but runtime-loaded SKILL.md content is still not bound to a trusted signature or digest policy, and unsigned/degraded capability behavior remains a security/product decision.

## What This Changes

Request a signed integrity and verification model for SKILL.md/native skill packages, including loader verification and restricted behavior for unsigned skills.

## Best Possible Solution

Define one canonical native skill trust model that binds ClawHub or publisher signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned/revoked capability policy with migration.
