## Summary

Keep open: current main and the latest release still lack trusted SKILL.md signature or digest enforcement at runtime, while the newer ClawHub provenance work only records local install evidence and advisory verification metadata.

## What This Changes

The issue requests cryptographic integrity and signature verification for skills, with unsigned skills restricted or degraded before they are loaded into agent context or granted capabilities.

## Best Possible Solution

Define one canonical native skill trust model that binds ClawHub or publisher signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned/revoked capability policy with migration.
