## Summary

Keep open: current main and v2026.6.11 have useful ClawHub verification/provenance metadata, but OpenClaw still does not enforce a trusted SKILL.md signature or digest gate before runtime loading or define unsigned-skill capability policy.

## What This Changes

The issue requests code signing, content integrity verification, and degraded capability handling for SKILL.md-based skills.

## Best Possible Solution

Define one canonical native skill trust model that binds publisher or ClawHub signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned or revoked capability policy with migration.
