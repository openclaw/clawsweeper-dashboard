## Summary

Keep open: current main and v2026.6.11 have ClawHub trust/verification metadata and advisory checks, but SKILL.md runtime loading still does not require a trusted signature, trusted digest match, revocation check, or unsigned-skill capability policy. This remains canonical security/product work rather than conservative cleanup-closeable.

## What This Changes

The issue requests cryptographic integrity/signature verification for SKILL.md skills, ClawHub signing metadata, and restricted behavior for unsigned skills.

## Best Possible Solution

Keep this issue open as the canonical native skill integrity/signature tracker and extend ClawHub trust metadata into runtime enforcement after maintainers settle trust roots, revocation, unsigned compatibility, and operator override behavior.

## Reproduction Assessment

Yes, as a source-level feature gap. Current main and v2026.6.11 read SKILL.md into skill records and runtime snapshots without comparing a trusted signature, persisted digest, revocation state, or unsigned capability tier.

## Solution Assessment

Unclear as a final implementation path. Signing is the right trust boundary, but the maintainable solution needs maintainer decisions on trust roots, revocation, unsigned compatibility, operator overrides, and how ClawHub verification feeds runtime enforcement.
