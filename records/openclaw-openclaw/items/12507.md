## Summary

Keep open: current main and v2026.6.11 provide ClawHub advisory verification/provenance, but they still do not enforce native SKILL.md signatures or define unsigned-skill capability policy at runtime; related items confirm this remains the canonical tracker.

## What This Changes

Request native integrity/signature verification for SKILL.md skills, with signed-skill trust metadata and restricted behavior for unsigned skills.

## Best Possible Solution

Keep this as the canonical native SKILL.md trust-boundary issue and define a staged design that binds ClawHub verification metadata, persisted expected integrity, loader-time signature checks, unsigned policy, and migration before enforcement.

Options:

- **Adopt staged runtime trust model (recommended):** Define a versioned digest/signature contract, persist trusted metadata at install/update, then add loader-time warn/strict enforcement and unsigned capability restrictions with migration guidance.
- **Keep verification advisory:** Keep ClawHub verify output and install provenance as user-visible trust signals without runtime blocking until maintainers define a stronger enforcement API.
- **Split design first:** Track issuer/signature format, ClawHub metadata, loader checks, capability policy, and migration as separate owner-reviewed design tasks before implementation.

## Solution Assessment

Unclear until maintainers choose the security contract. A hash-only patch is not the best solution because the durable fix needs trusted metadata, runtime verification, unsigned compatibility policy, and migration semantics.
