## Summary

Keep open: current main has useful ClawHub verification, local artifact hashes, and provenance metadata, but it still does not enforce trusted SKILL.md signatures or define unsigned-skill capability policy at runtime.

## What This Changes

The issue requests cryptographic integrity/signature verification for SKILL.md skills, including trusted metadata, runtime verification, and unsigned-skill capability policy.

## Best Possible Solution

Keep this as the canonical native skill trust-boundary issue and define a staged design binding ClawHub signature metadata, install/update persistence, loader-time rechecks, visible status, unsigned capability policy, and migration before enforcement.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: What native SKILL.md trust model should OpenClaw adopt for third-party skills: advisory verification only, runtime signature enforcement, or staged enforcement tied to capability policy?

Rationale: This decides the permanent trust root, signature envelope, revocation behavior, unsigned defaults, and upgrade compatibility for third-party instructions loaded into agent context.

Likely owner: steipete

Owner reason: steipete has the strongest visible history and review signal across native ClawHub install, dangerous-skill hardening, and the current security/product discussion.

Owner confidence: high

Options:

- **Adopt staged runtime trust model (recommended):** Define a versioned digest/signature contract, persist trusted metadata at install/update, then add loader-time warn/strict enforcement and unsigned capability restrictions with migration guidance.
- **Keep verification advisory:** Keep ClawHub verify output and install provenance as user-visible trust signals without runtime blocking until maintainers define a stronger enforcement API.
- **Split design first:** Track issuer/signature format, ClawHub metadata, loader checks, capability policy, and migration as separate owner-reviewed design tasks before code work.

## Reproduction Assessment

Yes for the feature gap: source inspection shows current main records some ClawHub provenance metadata but still loads SKILL.md without trusted signature or unsigned-policy state. This is not a broken existing behavior repro; it is a verified missing security capability.

## Solution Assessment

Unclear until maintainers choose the security contract. A hash-only patch is not the best solution because the durable fix needs trusted metadata, runtime verification, unsigned compatibility policy, and migration semantics.
