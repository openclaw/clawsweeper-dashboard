## Summary

Keep open: current main has ClawHub skill verification, install provenance, artifact hashes, and SKILL.md hashes, but runtime skill loading still does not enforce trusted SKILL.md signatures, revocation state, or an unsigned-skill capability policy. This remains valid security/product work rather than conservative cleanup-closeable.

## What This Changes

The issue requests cryptographic integrity/signature verification for SKILL.md skills, with runtime enforcement and degraded capability behavior for unsigned skills.

## Best Possible Solution

Keep this as the canonical native skill integrity/signature tracker and design a maintainer-approved trust model that connects ClawHub signatures/provenance to runtime loading, revocation, unsigned compatibility, operator overrides, and capability restrictions.

## Reproduction Assessment

Yes. This is source-reproducible as a feature/security gap: current main reads SKILL.md into Skill records and runtime snapshots without comparing a trusted signature, revocation state, or unsigned capability tier.

## Solution Assessment

No as a one-shot Ed25519/degraded-mode patch without design. The maintainable path is to extend current ClawHub verification and provenance into runtime enforcement after maintainers choose trust roots, revocation, compatibility, and operator override behavior.
