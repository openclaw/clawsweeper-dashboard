## Summary

Keep open: current main and v2026.6.11 have ClawHub verification/provenance metadata, but SKILL.md loading still is not bound to a trusted signature or digest policy, and unsigned-skill capability behavior remains a security/product decision.

## What This Changes

The issue requests signed or integrity-verified SKILL.md skill loading with restricted capability behavior for unsigned skills.

## Best Possible Solution

Define one canonical native skill trust model that binds ClawHub or publisher signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned/revoked capability policy with migration.
