## Summary

Keep open: current main has ClawHub provenance and verification groundwork, but it still does not require trusted SKILL.md signatures or digests before runtime loading, and unsigned-skill capability policy remains an unresolved security/product decision.

## What This Changes

Request cryptographic integrity/signature verification for SKILL.md skills, plus degraded capability behavior for unsigned skills.

## Best Possible Solution

Define one canonical native skill trust model that binds ClawHub or publisher signatures to exact loaded skill contents, persists and reverifies expected state, exposes status, and specifies unsigned/revoked capability policy with migration.
