## Summary

Keep this issue open for explicit maintainer handling. The report gives a concrete, current-source race involving cross-conversation draft delivery, and the `maintainer` label prevents automated cleanup even before considering a fix.

## What This Changes

Fix the Control UI catalog-continuation race so an outdated continuation cannot adopt a session, send its draft, change sending state, or show an error after the user switches chats or Gateway connections.

## System Context

The Control UI starts an external catalog continuation through the Gateway, then adopts the returned session and submits the composer draft. That asynchronous result must remain bound to the original connection, selected conversation, catalog generation, and send operation so it cannot affect whichever chat is active later.

## Architecture Diagram

flowchart LR
  A[User opens catalog conversation] --> B[Control UI draft and send]
  B --> C[Gateway catalog continuation]
  C --> D[Continuation result arrives]
  D --> E{Original UI ownership still valid?}
  E -->|Yes| F[Adopt session and send draft]
  E -->|No| G[Ignore stale result]
  F --> H[Active chat state]
  G --> H

## Best Possible Solution

Add a single ownership check around the catalog-continuation completion path, preserving the existing scoped-send behavior and covering stale success and failure after chat switching, reconnecting, and Gateway-client replacement.
