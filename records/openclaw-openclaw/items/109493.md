## Summary

Keep open: the retry direction is sound, but the changed `execFileSync` call does not establish a hard one-second deadline because Node waits for the child process to exit after sending the timeout signal; the supplied runtime harness uses a killable fake `ps`, so it does not prove recovery from the indefinite probe stall this PR targets. ([nodejs.org](https://nodejs.org/api/child_process.html?utm_source=openai))

Likely related people: @obviyus (medium confidence, adjacent stalled-work recovery) and @zhangguiping-xydt (medium confidence, prior merged Gateway probe/recovery work).

## What This Changes

Adds a one-second timeout and `ETIMEDOUT` retry loop to the detached worker-workspace expiry watchdog, with regression coverage using a stalling `ps` fixture.

## Best Possible Solution

Use a non-blocking identity probe whose watchdog regains control at the deadline while preserving nonce and PID-start-time checks, then demonstrate lease release on an actual worker host with a stalled probe.
