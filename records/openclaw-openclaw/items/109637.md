## Summary

## What This Changes

The PR sends inbound Feishu DM replies through the real conversation `chat_id` while retaining sender-scoped identity, routing state, and synthetic-event fallback behavior.

## Best Possible Solution

Preserve the separation between sender-scoped identity/session routing and conversation-scoped reply delivery, then merge only after a rebased head has a redacted live Feishu DM run confirming successful delivery and unchanged synthetic-event behavior.
