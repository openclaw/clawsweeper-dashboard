## Summary

Keep open: current main still runs a model-backed exec reviewer completion on each matching reviewer invocation, and no duplicate or fixing PR owns the repeated paid-completion problem. The issue is source-reproducible, but the repair changes exec approval cache semantics, so it needs maintainer review rather than auto-close or auto-repair.

## What This Changes

The issue reports that byte-identical model-backed exec auto-review requests re-bill fresh completions instead of reusing a deterministic verdict within a run.

## Best Possible Solution

Add a bounded, non-persistent exact-input memo at the approved owner boundary, with tests proving repeated identical requests reuse one completion while preserving allow-once semantics and host/session-sensitive keys.

- **Keep fresh review semantics:** Accept repeated model completions to preserve one-request-one-review behavior until stronger security or billing evidence is available.

Yes after maintainer cache-scope approval: the narrow fix is a shared exact-input reviewer memo rather than per-host caches or durable approval reuse, with an explicit decision for helper callers that create reviewers per request.
