## Summary

Keep open: current main still sends each byte-identical ask-requiring exec through a fresh model-backed reviewer completion, and no merged or open same-repo item appears to own the repeated-billing fix.

## What This Changes

The issue requests per-run reuse of deterministic model-backed exec reviewer verdicts for byte-identical exec approval requests.

## Best Possible Solution

Approve and implement a bounded, non-persistent exact-input memo at the shared reviewer boundary, with focused tests for repeated identical requests and host/session-sensitive key differences.

Rationale: The redundant billing path is source-proven, but caching a model reviewer result changes when a later exec request bypasses a fresh approval-boundary review.

Likely owner: vincentkoc

Owner confidence: high

Options:

- **Approve full-input per-reviewer memo (recommended):** Cache parsed reviewer decisions only inside a reviewer instance, keyed by the full reviewed input or prompt, and never persist or convert them to durable approval.
- **Memoize allow-once only:** Cache only low-risk allow-once results while leaving ask, error, and timeout decisions uncached for a narrower behavior change.
- **Keep fresh review semantics:** Accept the repeated model cost to preserve one-request-one-review semantics until stronger security or billing evidence changes the tradeoff.

## Reproduction Assessment

Yes, as source-reproducible: current main reaches model preparation and completion on every createModelExecAutoReviewer invocation, and node/gateway hosts call that reviewer for each approval miss. I did not run a live provider billing loop, so this is not marked locally reproduced.

## Solution Assessment

Yes after maintainer cache-scope approval: a shared exact-input reviewer memo is narrower than per-host caches or durable approval reuse. The remaining open point is whether helper paths that construct a reviewer per call should be in scope.
