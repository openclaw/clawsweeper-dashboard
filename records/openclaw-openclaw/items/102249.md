## Summary

Keep open: current main and the latest release still run a fresh model-backed exec reviewer completion for each matching reviewer invocation, and the two linked fixes are open candidate PRs rather than merged implementations.

## What This Changes

The issue reports that byte-identical repeated model-backed exec auto-review requests are billed as fresh completions instead of reusing a deterministic per-run verdict.

## Best Possible Solution

Land one reviewed linked fix that adds a bounded exact-input per-run memo in `createModelExecAutoReviewer`, preserving single-use approval semantics and documenting any intentionally out-of-scope helper paths.

Options:

- **Approve exact-input per-run memo (recommended):** Cache only within the shared reviewer instance using the full reviewed input or prompt, keep the cache bounded, and preserve allow-once host semantics.
- **Narrow cached outcomes:** Cache only parsed low-risk allow-once decisions while keeping ask, timeout, and error outcomes fresh for a smaller approval-boundary change.
- **Keep fresh review semantics:** Reject memoization for now and accept repeated reviewer cost to preserve one model review per exec request.

## Solution Assessment

Yes, conditionally. The shared reviewer is the narrowest maintainable fix boundary for the node and gateway paths, but maintainers still need to approve the approval-cache semantics before a linked PR lands.
