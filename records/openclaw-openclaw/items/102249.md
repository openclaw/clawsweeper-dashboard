## Summary

Keep open: current main still invokes the model-backed exec reviewer completion on each matching approval miss, no fixing PR or duplicate appears to own the repeated-billing problem, and cache scope needs maintainer approval because it changes exec approval semantics.

## What This Changes

The issue requests memoizing byte-identical model-backed exec auto-reviewer decisions within a run so repeated approval misses do not trigger repeated paid reviewer completions.

## Best Possible Solution

Add a bounded, non-persistent exact-input memo at the approved reviewer boundary, with tests proving repeated identical requests reuse one completion while host/session/input changes still get fresh review.

Rationale: The source bug is clear, but exec review caching changes when OpenClaw asks the model again before allowing an approval miss, so cache lifetime and key scope need explicit approval-boundary intent.

Owner confidence: high

Options:

- **Approve full-input per-run memo (recommended):** Cache parsed reviewer decisions only inside the shared reviewer instance, keyed by the full reviewed input or prompt, without persisting or converting them to durable approvals.
- **Memoize allow-once only:** Cache only low-risk allow-once results and keep ask, timeout, and error decisions uncached for a narrower behavior change with smaller savings.
- **Keep fresh review semantics:** Accept the repeated model cost to preserve one-request-one-review semantics until stronger security or live billing evidence is available.

## Reproduction Assessment

Yes, as source-reproducible: current createModelExecAutoReviewer reaches model preparation and completion inside each returned reviewer invocation, and both exec hosts call that reviewer per approval miss. I did not run a live provider billing loop.

## Solution Assessment

Unclear until maintainer cache-scope approval: a shared exact-input reviewer memo is the narrowest maintainable fix for the main exec tool, but the approval-boundary semantics and plugin helper scope need an explicit decision.
