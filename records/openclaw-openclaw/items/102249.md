## What This Changes

The issue requests per-run reuse of deterministic model-backed exec auto-reviewer verdicts for byte-identical repeated exec requests to avoid duplicate paid completions.

## Best Possible Solution

Land one reviewed bounded exact-input memo in the shared reviewer, with maintainer-approved cache semantics and regression coverage for node and gateway paths.

Question: Should OpenClaw reuse model-backed exec reviewer decisions for byte-identical repeated requests, and is a bounded per-reviewer exact-input allow-once-only cache the accepted approval boundary?

Rationale: Exec auto-review sits on the process approval boundary, so reusing a prior model verdict changes the one-request-one-review behavior even though the reported duplicate billing bug is real.

Likely owner: jesse-merhi

Owner reason: This handle carried much of the normalized exec auto-mode and approval-boundary work in the feature history.

Owner confidence: high

Options:

- **Approve bounded allow-once memo (recommended):** Cache only parsed low-risk allow-once decisions inside one reviewer instance, keyed by the full reviewed input, after real configured-run proof is available.
- **Cache broader deterministic outcomes:** Permit ask/error/timeout outcomes to be memoized too for more savings, accepting a broader behavior change in the reviewer path.
- **Keep fresh review semantics:** Reject memoization for now and accept repeated model cost so every exec request gets a fresh reviewer call.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: repeated identical calls into the same model-backed reviewer reach a fresh completion call on current main. I did not run a live paid provider billing loop in this read-only review.

## Solution Assessment

Yes, conditionally: the shared reviewer is the right layer for node and gateway because both hosts already pass through that contract. The cache lifetime, key shape, cached outcome set, and helper-path scope still need maintainer approval.
