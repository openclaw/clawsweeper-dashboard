## Summary

Keep open: current main and the latest release still run the model-backed exec reviewer completion on each reviewer invocation, and no same-repo duplicate or fixing PR appears to own the repeated-billing problem. The fix is narrow, but cache lifetime and key shape change an exec approval boundary, so maintainer intent is needed before repair automation.

## What This Changes

The issue asks OpenClaw to reuse deterministic model-backed exec reviewer verdicts for byte-identical repeated exec approval requests within the same run.

## Best Possible Solution

Add a bounded, non-persistent exact-input memo at the shared model reviewer boundary after maintainer approval, with regression coverage proving repeated identical node and gateway requests reuse one completion while preserving allow-once approval semantics.

Options:

- **Approve full-input per-run memo (recommended):** Cache parsed reviewer decisions only inside the shared reviewer instance, keyed by the full reviewed input or rendered prompt, and never persist or convert them to durable approvals.
- **Memoize allow-once only:** Cache only low-risk allow-once decisions and keep ask, error, and timeout outcomes fresh for a narrower behavior change with less savings.
- **Keep fresh review semantics:** Accept repeated model cost to preserve one-request-one-review semantics until stronger security or billing evidence justifies a cache.

Yes after maintainer cache-scope approval: the narrowest maintainable fix is an exact-input memo in the shared model reviewer, not durable approval reuse or separate per-host caches.
