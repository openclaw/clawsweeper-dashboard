## Summary

Keep open: current `origin/main` and the latest release still call the model-backed exec reviewer completion on each reviewer invocation, while the two linked fix PRs are open and not yet merged/proven.

## What This Changes

The issue requests a bounded per-run/per-reviewer memo so byte-identical model-backed exec auto-review requests reuse the deterministic verdict instead of re-billing fresh completions.

## Best Possible Solution

Review and land one linked fix that uses a bounded, non-persistent memo in `createModelExecAutoReviewer` keyed by the full reviewed input or prompt, with regression coverage and real behavior proof, then close this issue after merge.

Question: Should OpenClaw reuse model-backed exec reviewer decisions for byte-identical requests within one reviewer instance, and what cache key/outcome scope is acceptable for the exec approval boundary?

Rationale: The source-level cost bug is real, but the fix deliberately changes one-request-one-review semantics for process execution approvals, so the cache contract needs maintainer intent before closing or auto-repairing.

Likely owner: steipete

Owner reason: This person authored the merged normalized exec auto mode feature and is the strongest current routing signal for the approval-boundary cache decision.

Owner confidence: medium

Options:

- **Approve full-input per-run memo (recommended):** Cache reviewer decisions only inside one reviewer instance and key the cache by the exact serialized reviewed input or prompt, without converting results into durable approval state.
- **Narrow cached outcomes:** Cache only parsed low-risk allow-once results, or key by an even stricter prompt hash, if maintainers want a smaller security-boundary change.
- **Keep fresh-review semantics:** Reject memoization for now and accept repeated reviewer cost to preserve a fresh model review for every exec approval miss.

## Reproduction Assessment

Yes, source-reproducible: current `createModelExecAutoReviewer` reaches model preparation and completion on each reviewer invocation, and both node and gateway hosts call it for each approval miss. I did not run a live provider billing loop, so this is not marked locally reproduced.

## Solution Assessment

Yes, conditionally: the shared reviewer is the right layer for the node/gateway cases, but the fix should memoize the full reviewed input or prompt and preserve single-use approval semantics. Landing one of the linked PRs after maintainer cache-scope approval is better than opening another competing fix.
