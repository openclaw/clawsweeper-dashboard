## Summary

Keep open: current main still runs the model-backed exec reviewer completion on every matching call, and no duplicate issue or fixing PR appears to own the repeated-billing problem.

## What This Changes

The issue requests per-run reuse of deterministic model-backed exec auto-review verdicts for byte-identical exec requests.

## Best Possible Solution

Add a bounded exact-input memo inside createModelExecAutoReviewer after confirming cache semantics, with regression coverage proving repeated identical requests reuse one completion without creating durable or session approval.

Options:

- **Approve exact-input per-run memo (recommended):** Cache parsed reviewer decisions only inside createModelExecAutoReviewer, keyed by the full reviewed input/prompt, and never persist or upgrade them to durable/session approval.
- **Cache allow-once only:** Memoize only low-risk allow-once results and keep ask/error/timeout decisions uncached, trading fewer savings for a narrower approval change.
- **Keep fresh review per request:** Accept repeated reviewer billing to preserve the current one-request-one-review semantics until stronger live billing or security proof exists.

## Reproduction Assessment

Yes from source inspection and the reporter's stubbed model-boundary proof: invoking the same createModelExecAutoReviewer instance twice with identical input reaches the completion call twice because there is no verdict memo. I did not run a live provider billing loop, so this is source-reproducible rather than locally reproduced.

## Solution Assessment

Yes, the best fix shape is a shared per-instance exact-input memo in createModelExecAutoReviewer, not per-host caches or durable approvals. The implementation should preserve allow-once semantics and include regression tests that count model completions.
