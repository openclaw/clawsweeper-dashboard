## Summary

Keep open: current main still sends each matching model-backed exec review request through a fresh completion, and no same-repo duplicate or fixing PR owns the repeated-billing problem.

## What This Changes

The issue requests per-run reuse of byte-identical model-backed exec auto-reviewer verdicts so repeated identical approval misses do not pay for duplicate reviewer completions.

## Best Possible Solution

Add an owner-approved, non-persistent exact-input memo at the shared reviewer boundary, with regression tests proving repeated identical node and gateway requests reuse one completion while changed host, cwd, envKeys, analysis, or agent context still triggers a fresh review.

Options:

- **Approve full-input per-run memo (recommended):** Cache parsed reviewer decisions only inside the shared reviewer instance, keyed by the full reviewed input or prompt, without persisting or converting them to durable approval.
- **Memoize allow-once only:** Cache only low-risk allow-once results and keep ask, error, and timeout decisions uncached for a narrower but less complete cost fix.
- **Keep fresh review semantics:** Accept repeated reviewer completions for identical commands until stronger security or live billing evidence justifies approval-result reuse.

Unclear until maintainer cache-scope approval: the narrowest maintainable repair appears to be a shared exact-input reviewer memo rather than per-host caches or durable approval reuse. The open decision is which input fields and helper surfaces must participate in the memo boundary.
