## Summary

Keep open: current main still has no verdict memo in the model-backed exec auto-reviewer, so repeated byte-identical approval misses can still trigger repeated reviewer completions.

## What This Changes

The issue requests a non-persistent exact-input memo for model-backed exec auto-reviewer decisions so identical repeated exec requests do not re-bill fresh completions.

## Best Possible Solution

Add a bounded, non-persistent exact-input memo at the approved reviewer boundary, with tests proving repeated identical requests reuse one completion while preserving allow-once semantics and host/session-sensitive keys.

Options:

- **Approve full-input per-run memo (recommended):** Cache parsed reviewer decisions only inside the shared reviewer instance, keyed by the full reviewed input or generated prompt, and never persist or convert them to durable approval.
- **Memoize allow-once only:** Cache only low-risk allow-once results and keep ask, error, and timeout decisions uncached for a narrower behavior change with fewer savings.
- **Keep fresh review semantics:** Accept the repeated model cost to preserve one-request-one-review semantics until stronger security or live billing evidence is available.

## Reproduction Assessment

Yes as source-reproducible: current createModelExecAutoReviewer reaches model preparation and completion on each invocation, and node/gateway hosts call it for each approval miss. I did not run a live provider billing loop, so this is not marked locally reproduced.

## Solution Assessment

Yes after maintainer cache-scope approval: the narrowest maintainable fix is a shared exact-input reviewer memo rather than per-host durable approval reuse. The remaining question is the approved cache lifetime and whether per-call helper paths are in scope.
