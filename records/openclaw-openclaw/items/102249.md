## Summary

Keep open: current main still runs the model-backed exec reviewer completion for each matching approval miss, and search did not find a merged or open fixing PR that owns the repeated-billing problem.

## What This Changes

The issue asks OpenClaw to reuse deterministic model-backed exec auto-reviewer verdicts for byte-identical exec requests within a run instead of billing a fresh reviewer completion each time.

## Best Possible Solution

Add a bounded, non-persistent exact-input memo at the shared reviewer boundary, with tests proving repeated identical requests reuse one completion while preserving allow-once semantics and host/session-sensitive keys.

- **Approve full-input per-run memo (recommended):** Cache parsed reviewer decisions only inside the shared reviewer instance, keyed by the complete reviewed input or prompt, and never persist or convert them to durable approval.
- **Memoize allow-once only:** Cache only low-risk allow-once results while leaving ask, error, and timeout decisions uncached for a narrower behavior change with fewer savings.
- **Keep fresh review semantics:** Accept the repeated model cost to preserve one-request-one-review semantics until stronger security or live billing evidence is available.
