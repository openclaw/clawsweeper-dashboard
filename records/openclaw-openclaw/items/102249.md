## Summary

Keep open: current main and the latest release still call the model-backed exec reviewer completion on each matching approval miss, and no duplicate issue or merged fix owns the repeated-billing problem.

## What This Changes

The issue requests per-run memoization for byte-identical model-backed exec auto-reviewer decisions so repeated identical exec approvals do not trigger repeated paid completions.

## Best Possible Solution

Add a bounded, non-persistent exact-input memo at the approved exec-review owner boundary, with regression tests proving identical requests reuse one completion while preserving allow-once semantics and host/session-sensitive keys.

Options:

- **Approve full-input per-run memo (recommended):** Cache parsed reviewer decisions only inside the shared reviewer instance, keyed by the full reviewed input or prompt, and never persist or convert them to durable approval.
- **Memoize allow-once only:** Cache only low-risk allow-once results and keep ask, error, and timeout decisions uncached for a narrower behavior change with fewer savings.
- **Keep fresh review semantics:** Accept repeated reviewer completion cost to preserve one-request-one-review semantics until maintainers want a broader approval-cache policy.

Yes, source-reproducible: current createModelExecAutoReviewer reaches model preparation and completion on each invocation, and node/gateway hosts call it for each approval miss. I did not run a live provider billing loop.

## Solution Assessment

Yes after maintainer cache-scope approval: the narrowest maintainable fix is a shared exact-input reviewer memo rather than per-host durable approvals. The remaining decision is whether Codex app-server helper calls should be covered by caller reuse or left out of scope.
