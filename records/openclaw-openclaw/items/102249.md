## Summary

Keep open: current main and the latest release still call the model-backed exec reviewer completion on each matching approval miss, and no duplicate issue or fixing PR appears to own the repeated-billing problem.

## What This Changes

The issue requests per-run memoization for byte-identical model-backed exec auto-reviewer decisions so repeated identical exec approval misses do not trigger repeated paid reviewer completions.

## Best Possible Solution

Add a bounded, non-persistent exact-input memo at the approved owner boundary, with tests proving repeated identical requests reuse one completion while preserving allow-once semantics and host/session-sensitive keys.

Question: May OpenClaw reuse model-backed exec reviewer decisions for byte-identical requests, and must that cache live only inside one reviewer/run with the full reviewed input as its key?

Rationale: The defect is source-reproducible, but caching an exec approval reviewer result changes when a later request bypasses a fresh model review, so cache lifetime and key shape need explicit approval-boundary intent.

Owner confidence: high

Options:

- **Approve full-input per-run memo (recommended):** Cache parsed reviewer decisions only inside the shared reviewer instance, keyed by the full reviewed input or prompt, and never persist or convert them to durable/session approval.
- **Memoize allow-once only:** Cache only low-risk allow-once results while keeping ask, error, and timeout decisions uncached for a narrower behavior change with fewer savings.
- **Keep fresh review semantics:** Accept the repeated model cost to preserve one-request-one-review semantics until stronger security or live billing evidence is available.

## Reproduction Assessment

Yes, source-reproducible: current createModelExecAutoReviewer reaches model preparation and completion on each invocation, and node/gateway hosts call it for each approval miss. I did not run a live provider billing loop, so this is not marked locally reproduced.

## Solution Assessment

Yes, after maintainer cache-scope approval: the narrowest maintainable fix is a shared exact-input reviewer memo rather than per-host caches or durable approval reuse. The implementation should explicitly decide whether helper paths that create a reviewer per call are in or out of scope.
