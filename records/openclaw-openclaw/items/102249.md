## Summary

Keep open: current main still calls the model-backed exec reviewer completion for each matching approval miss, and no duplicate issue or fixing PR appears to own the repeated-billing problem.

## What This Changes

The issue asks OpenClaw to reuse deterministic model-backed exec auto-reviewer verdicts for byte-identical repeated exec approval requests within the same run.

## Best Possible Solution

Add a bounded, non-persistent exact-input memo at the approved owner boundary, with tests proving repeated identical requests reuse one completion while preserving allow-once semantics and host/session-sensitive keys.

Options:

- **Approve full-input per-run memo (recommended):** Cache parsed reviewer decisions only inside the shared reviewer instance, keyed by the full reviewed input or prompt, and never persist or convert them to durable/session approval.
- **Memoize allow-once only:** Cache only low-risk allow-once results and keep ask, error, and timeout decisions uncached for a narrower behavior change with fewer savings.
- **Keep fresh review semantics:** Accept the repeated model cost to preserve one-request-one-review semantics until stronger security or live billing evidence is available.

## Reproduction Assessment

Yes as source-reproducible: current createModelExecAutoReviewer reaches model preparation and completion on each invocation, and node/gateway hosts call it for each approval miss. I did not run a live provider billing loop, so this is not marked locally reproduced.

## Solution Assessment

Yes after maintainer cache-scope approval: the narrowest maintainable fix is a shared exact-input reviewer memo rather than per-host caches or durable approval reuse. The implementation should also decide whether plugin/Codex helper paths need reviewer reuse or are intentionally out of scope.
