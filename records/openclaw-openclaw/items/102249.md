## Summary

Keep open: current main and the latest release still call the model-backed exec reviewer on each identical approval miss, and two open PRs now use closing syntax for the same bug. The issue should stay open until maintainers choose and land a safe fix.

## What This Changes

Request to avoid re-billing model-backed exec auto-review completions for byte-identical exec approval requests by memoizing deterministic per-run verdicts.

## Best Possible Solution

Review and land one bounded exact-input reviewer memo at the shared exec reviewer boundary, with approval-boundary owner signoff and proof that identical node/gateway requests reuse one completion without broadening allow-once semantics.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should OpenClaw reuse model-backed exec reviewer decisions for byte-identical requests within one reviewer/run, and what exact cache key, lifetime, and outcome set are acceptable on the exec approval boundary?

Rationale: The source bug is clear, but the fix changes one-request-one-model-review semantics on a command execution approval path, which is a security-boundary policy choice rather than a purely mechanical optimization.

Likely owner: vincentkoc

Owner reason: Recent exec approval and security allowlist history makes this the strongest available owner signal for the approval-boundary decision.

Owner confidence: medium

Options:

- **Approve bounded exact-input memo (recommended):** Allow a small per-reviewer-instance cache keyed by the full reviewed input or prompt, with tests for key separation, eviction, and unchanged allow-once handling.
- **Cache only low-risk allows:** Permit memoization only for parsed low-risk allow-once verdicts and keep ask, timeout, error, and unavailable-model outcomes uncached.
- **Keep fresh review semantics:** Reject reviewer-result caching for now and accept repeated reviewer completions until a different cost-control design is chosen.

## Reproduction Assessment

Yes, source-reproducible. Current main prepares and calls the model completion inside createModelExecAutoReviewer for every invocation, and both node and gateway hosts call that reviewer on approval misses; I did not run a live provider billing loop.

## Solution Assessment

Yes, conditionally. The shared reviewer is the narrowest maintainable layer for node/gateway, but the final fix needs maintainer approval of cache semantics and should avoid an unbounded or under-keyed approval-boundary cache.
