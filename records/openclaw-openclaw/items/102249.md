## Summary

Keep open: current main still creates a model completion on every model-backed exec reviewer invocation, and live search found no duplicate issue or fixing PR that owns the repeated-billing problem.

## What This Changes

The issue requests reusing deterministic model-backed exec reviewer verdicts for byte-identical repeated exec requests within a run to avoid redundant paid completions.

## Best Possible Solution

Add a bounded, non-persistent exact-input memo at the shared reviewer boundary, with regression tests proving identical requests reuse one completion while host, cwd, envKeys, agent, and reason remain part of the key.

Options:

- **Approve full-input per-run memo (recommended):** Cache parsed reviewer decisions only inside the shared reviewer instance, keyed by the full reviewed input or prompt, without persisting or converting them to durable approvals.
- **Memoize allow-once only:** Cache only low-risk allow-once results and keep ask, error, and timeout decisions uncached for a narrower behavior change with less cost reduction.
- **Keep fresh review semantics:** Accept repeated model cost to preserve one-request-one-review semantics until maintainers have stronger security or live billing evidence.

## Reproduction Assessment

Yes as source-reproducible: current createModelExecAutoReviewer reaches model preparation and completion on each invocation, and node/gateway hosts call it for each approval miss. I did not run a live provider billing loop in this read-only review.

## Solution Assessment

Unclear until maintainers approve cache scope: if approved, the narrowest maintainable fix is a shared exact-input reviewer memo rather than durable approval reuse or separate per-host caches.
