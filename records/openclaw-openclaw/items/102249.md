## Summary

Keep open: current main still sends each model-backed exec auto-reviewer invocation through a fresh completion, and two open linked PRs now own candidate fixes, so this issue should remain the canonical tracker until one lands or maintainers reject the cache direction.

## What This Changes

The issue asks OpenClaw to reuse deterministic model-backed exec auto-review verdicts for byte-identical repeated exec requests within a run so repeated commands do not trigger repeated paid reviewer completions.

## Best Possible Solution

Keep this issue as the canonical tracker and land one linked PR with a bounded, non-persistent exact-input reviewer memo, regression coverage for node/gateway reuse, real behavior proof, and maintainer-approved cache semantics.

Options:

- **Approve exact-input per-run memo (recommended):** Cache reviewer decisions only inside the shared reviewer instance, keyed by the full reviewed input or prompt, and keep allow-once consumption single-use at the host boundary.
- **Narrow cached outcomes:** Cache only low-risk allow-once decisions and keep ask, timeout, and error outcomes uncached for a smaller approval-boundary change.
- **Keep fresh review semantics:** Reject memoization and accept repeated reviewer cost to preserve a fresh model review for every exec request.
