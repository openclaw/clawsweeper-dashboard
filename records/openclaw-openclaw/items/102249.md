## Summary

Keep open: current main still invokes the model-backed exec reviewer for each approval miss without a verdict memo, and https://github.com/openclaw/openclaw/pull/102362 is an open closing PR rather than merged proof.

## What This Changes

This issue requests per-run memoization of deterministic model-backed exec auto-review decisions so byte-identical repeated exec requests do not trigger duplicate paid reviewer completions.

## Best Possible Solution

Land https://github.com/openclaw/openclaw/pull/102362 or an equivalent bounded per-reviewer-instance exact-input memo, with regression coverage that preserves one-shot approval semantics and host/session-sensitive keys.

Options:

- **Approve exact-input per-instance memo (recommended):** Cache parsed reviewer decisions only inside the shared reviewer instance, keyed by the complete reviewed input, without persisting or converting them into durable approvals.
- **Memoize only low-risk allows:** Cache only low-risk allow-once results and keep ask, error, and timeout decisions uncached for a narrower behavior change with fewer savings.
- **Keep fresh-review semantics:** Accept repeated model cost for now to preserve one-request-one-review semantics until maintainers want a cache boundary.

## Solution Assessment

Yes after maintainer cache-scope approval: the shared reviewer is the narrowest maintainable fix boundary for the node and gateway hosts. Per-host caches or durable approval reuse would be broader and easier to drift.
