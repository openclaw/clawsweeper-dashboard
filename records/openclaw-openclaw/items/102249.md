## Summary

Keep open: current main still performs a fresh model-backed exec reviewer completion on each approval-miss invocation, and no merged fix or canonical duplicate owns the repeated-completion cost issue.

## What This Changes

The issue requests a per-run exact-input memo for model-backed exec auto-reviewer decisions so repeated identical exec approval misses do not trigger repeated paid completions.

## Best Possible Solution

Add a bounded, non-persistent exact-input memo at the shared reviewer boundary after cache-scope approval, with tests proving repeated identical node/gateway requests reuse one completion while preserving allow-once semantics.

Options:

- **Approve full-input per-run memo (recommended):** Cache parsed reviewer decisions only inside the shared reviewer instance, keyed by the full reviewed input or prompt, and never persist or convert them to durable approval.
- **Cache allow-once only:** Memoize only low-risk allow-once results and keep ask, error, and timeout results uncached for a narrower approval-boundary change.
- **Keep fresh review semantics:** Accept repeated reviewer completion cost to preserve one-request-one-review behavior until stronger live billing or security evidence changes the tradeoff.

## Solution Assessment

Yes after maintainer cache-scope approval: a shared exact-input reviewer memo is the narrowest maintainable fix for node/gateway hosts. The remaining product question is whether plugin SDK helper paths must also reuse a reviewer instance.
