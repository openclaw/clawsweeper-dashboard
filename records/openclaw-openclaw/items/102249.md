## Summary

Keep open: current main and the latest release still invoke the model-backed exec reviewer completion per approval miss, with no exact-input verdict memo or duplicate fixing item found.

## What This Changes

The issue asks OpenClaw to avoid rebilling model-backed exec auto-review completions for byte-identical repeated exec approval requests within the same run.

## Best Possible Solution

Add a bounded, non-persistent exact-input memo at the approved shared reviewer boundary, with regression coverage proving repeated identical requests reuse one completion while preserving allow-once approval semantics.

## Maintainer Decision

Required: true

Question: May OpenClaw reuse model-backed exec reviewer decisions for byte-identical requests, and should that cache live only inside one reviewer/run keyed by the full reviewed input or prompt?

Rationale: The source-reproducible cost issue is real, but caching an exec approval reviewer result changes when a later request bypasses a fresh model review, so the approval-boundary lifetime and key need maintainer intent before implementation.

Likely owner: vincentkoc

Owner reason: Current blame and the original auto-mode PR metadata make this the strongest available route for the exec auto-reviewer boundary decision.

Owner confidence: high

Options:

- **Approve full-input per-run memo (recommended):** Cache parsed reviewer decisions only inside the shared reviewer instance, keyed by the full reviewed input or prompt, and never persist or convert them to durable/session approval.
- **Memoize allow-once only:** Cache only low-risk allow-once results and keep ask, error, and timeout decisions uncached for a narrower behavior change with fewer savings.
- **Keep fresh-review semantics:** Accept repeated model cost to preserve one-request-one-review semantics until stronger security or live billing evidence is available.

## Reproduction Assessment

Yes as source-reproducible: current createModelExecAutoReviewer reaches model preparation and completion on each invocation, and node/gateway hosts call it for each approval miss. I did not run a live provider billing loop, so this is not marked locally reproduced.

## Solution Assessment

Unclear until maintainer cache-scope approval: the narrow maintainable fix appears to be a shared exact-input reviewer memo, not per-host caches or durable approval reuse. The remaining decision is the approved approval-boundary semantics.
