Rationale: The current behavior is source-reproducible and wasteful, but caching a model-backed exec approval reviewer result changes one-request-one-review semantics on a security-sensitive path.

Likely owner: joshavant

Owner confidence: high

Options:

- **Approve bounded exact-input memo (recommended):** Cache only within one reviewer/run using the full reviewed input or prompt as the key, with a small bound, key-separation coverage, and no durable approval reuse.
- **Narrow to low-risk allows only:** Memoize only parsed low-risk `allow-once` outcomes and keep ask, error, and timeout results uncached for a smaller approval-boundary change.
- **Keep fresh review semantics:** Reject reviewer-result caching for now and accept repeated model cost until a different cost-control design is approved.

## Solution Assessment

Yes, conditionally. The shared reviewer is the right node/gateway layer for a narrow fix, but the final PR should use a bounded exact-input memo and settle plugin/Codex helper scope before merge.
