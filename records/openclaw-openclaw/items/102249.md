## Summary

Keep open: current main still sends every matching model-backed exec auto-review request through a fresh completion, and no same-repository duplicate or fixing PR owns the repeated-billing problem.

## What This Changes

The issue requests per-run memoization of deterministic model-backed exec reviewer decisions for byte-identical exec requests.

## Best Possible Solution

Add a bounded, non-persistent exact-input memo at the approved exec-reviewer boundary, with tests proving repeated identical requests reuse one completion while preserving allow-once semantics and host/session-sensitive keys.

## Maintainer Decision

Required: true

Kind: product_direction

Question: May OpenClaw reuse model-backed exec reviewer decisions for byte-identical requests, and must that cache live only inside one reviewer/run with the full reviewed input as its key?

Rationale: The bug is narrow and source-backed, but caching an exec approval reviewer result changes when a later request bypasses a fresh model review, so cache lifetime and key shape need explicit approval-boundary intent.

Likely owner: steipete

Owner reason: This is an exec approval-boundary decision, and history shows the strongest repeated ownership signal for that area.

Owner confidence: high

Options:

- **Approve full-input per-run memo (recommended):** Cache parsed reviewer decisions only inside the shared reviewer instance, keyed by the full reviewed input or prompt, and never persist or convert them to durable approval.
- **Memoize allow-once only:** Cache only low-risk allow-once results and keep ask, error, and timeout decisions uncached for a narrower behavior change with fewer savings.
- **Keep fresh review semantics:** Accept the repeated model cost to preserve one-request-one-review semantics until stronger security or live billing evidence is available.

## Reproduction Assessment

Yes, source-reproducible: current `createModelExecAutoReviewer` reaches model preparation and completion on each invocation, and node/gateway hosts call it for each approval miss. I did not run a live provider billing loop in this read-only review.

## Solution Assessment

Yes after maintainer cache-scope approval: the narrowest maintainable fix is a shared exact-input reviewer memo rather than per-host caches or durable approval reuse. The implementation should also decide whether plugin harness helper paths need reviewer reuse or are intentionally out of scope.
