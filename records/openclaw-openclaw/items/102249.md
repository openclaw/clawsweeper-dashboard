## Summary

Keep open: current main still runs a fresh model-backed exec reviewer completion for each matching approval miss, and no merged fix or canonical duplicate appears to own the repeated-billing problem.

## What This Changes

The issue requests a per-run exact-input memo for deterministic model-backed exec auto-reviewer decisions so byte-identical repeated exec requests do not rebill a new reviewer completion.

## Best Possible Solution

Add a bounded, non-persistent exact-input memo at the approved owner boundary, with tests proving repeated identical requests reuse one completion while preserving allow-once semantics and host/session-sensitive keys.

Options:

- **Approve full-input per-run memo (recommended):** Cache parsed reviewer decisions only inside the shared reviewer instance, keyed by the full reviewed input or prompt, and do not persist or convert them to durable approvals.
- **Memoize allow-once only:** Cache only low-risk allow-once results and keep ask, error, and timeout decisions uncached for a narrower behavior change with smaller savings.
- **Keep fresh review semantics:** Accept repeated model cost to preserve one-request-one-review behavior until stronger security or live billing evidence justifies changing the approval boundary.

## Reproduction Assessment

Yes, as source-reproducible: current createModelExecAutoReviewer reaches model preparation and completion on each invocation, and node/gateway hosts call it for each approval miss. I did not run a live provider billing loop, so this is not marked reproduced.

## Solution Assessment

Yes after maintainer cache-scope approval: the narrowest maintainable fix is a shared exact-input reviewer memo rather than per-host caches or durable approval reuse. The remaining decision is whether the plugin harness helper should also be reworked to reuse reviewer instances.
