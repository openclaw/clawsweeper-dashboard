## Summary

Keep this PR open: the supplied head diff still converts every `GatewayLockError` into a skippable condition, so genuine coordinator or filesystem lock-acquisition failures can be reported as ordinary Gateway contention instead of remaining fatal.

## What This Changes

The PR makes `openclaw doctor --fix` persist independent configuration repairs when session SQLite import cannot obtain the Gateway-owned maintenance lock, while skipping that session step with guidance.

## Best Possible Solution

Restrict the skippable error to verified Gateway-lock timeout/contention and retain fatal propagation for all other lock-acquisition failures, with regression coverage for both paths.

No. Persisting independent configuration repairs is the right boundary, but the proposed typed error must represent only expected lock contention rather than every `GatewayLockError`.
