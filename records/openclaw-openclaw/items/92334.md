## Summary

Keep open. The reported remote-node exec failure remains relevant, but this patch repeats the prior security blocker: it lets a persisted socket bearer token bypass the existing store/hardening path and explicitly accepts a `0644` token-bearing file. The July 18 v2026.7.1 macOS report confirms a current exec-denial problem, but its stated tokenless socket does not prove this PR’s specific root cause or the proposed bypass safe.

## What This Changes

The PR removes the socket-token condition from the `security=full` and `ask=off` approvals fast path, then changes the store test to expect no token read and no permission hardening.

## Best Possible Solution

Preserve hardening for any persisted socket credential and repair the node-specific policy-write or host-capability path so hosts that cannot serve approval sockets do not acquire or depend on a socket token in the first place.
