## Summary

Keep open: current main already addresses the aggregate tool-result elision and compaction-pressure parts, but it still silently disables `maxActiveTranscriptBytes` when `truncateAfterCompaction` is not enabled and there is no Doctor finding for that misconfiguration.

## What This Changes

The issue asks for clearer model-visible tool-result pruning markers, config/Doctor warnings for inactive `maxActiveTranscriptBytes`, and compaction behavior when aggregate tool-result budget pressure appears.

## Best Possible Solution

Keep the current aggregate-pressure behavior on main and add a narrow diagnostic that warns in Doctor and config/startup diagnostics when `maxActiveTranscriptBytes` is positive but `truncateAfterCompaction` is not true.
