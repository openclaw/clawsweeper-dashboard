## Summary

Keep open: current main has partial hardening for aborted assistant payloads and merged outbound recovery work, but the reported aborted heartbeat raw tool-output flood is still not conclusively fixed or owned by a merged canonical PR.

## What This Changes

The issue reports that an aborted Telegram heartbeat run delivered raw multi-thousand-line tool output in many channel messages, bypassing the heartbeat `ackMaxChars` contract and wedging outbound recovery after a 429.

## Best Possible Solution

Fix the heartbeat/embedded-run delivery boundary so aborted heartbeat runs cannot flush deferred partial or tool-output payloads to the channel, then handle any broader per-chat flood guard as a separate explicit delivery policy if maintainers want it.

## Reproduction Assessment

No, not as a high-confidence end-to-end live reproduction from this checkout. The reporter's logs plus current source make the abort/deferred-output and outbound-chunking path source-reproducible, but the exact Telegram flood still needs the trajectory or a targeted regression harness.

## Solution Assessment

Unclear as a complete fix shape. The narrowest first fix appears to be suppressing or summarizing aborted heartbeat terminal payloads at the heartbeat/embedded-run boundary, while a generic per-chat flood guard needs separate maintainer policy.
