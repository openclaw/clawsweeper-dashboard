## Summary

Keep open: current main still has a credible source path where heartbeat ack filtering only normalizes selected reply text, while embedded/Codex abort and tool-progress payloads can still reach durable channel delivery and Telegram chunking. I found no merged fix or canonical duplicate for the raw aborted-heartbeat tool-output flood.

## What This Changes

The issue asks OpenClaw to prevent aborted heartbeat runs from flushing raw partial/tool output past `ackMaxChars` and flooding Telegram/outbound delivery.

## Best Possible Solution

Keep this issue open and fix the heartbeat/embedded-run delivery boundary so aborted heartbeat runs cannot flush raw partial or tool-output payloads to channel delivery; treat any generic per-chat flood guard as a separate explicit policy decision.

## Reproduction Assessment

No, not as a full end-to-end Telegram reproduction from this checkout. The reporter's detailed logs plus current source make the failure class source-reproducible, but the exact 91-message flood still needs attached trajectory/gateway logs or a targeted regression harness.

## Solution Assessment

Unclear as a complete fix. The best first fix is likely to suppress or summarize aborted heartbeat terminal/tool-output payloads before durable channel delivery, then consider a separate maintainer-approved per-chat flood guard.
