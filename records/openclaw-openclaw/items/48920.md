## Summary

Keep open: the original `isolatedSession` example is now supported in the latest release, but the underlying live-docs-versus-installed-release problem still exists as a docs/release policy gap and has sibling reports.

## What This Changes

The issue reports that live OpenClaw docs can advertise configuration keys or limits that are not accepted by the latest released CLI, causing users to copy unsupported config and break startup.

## Best Possible Solution

Adopt a maintainer-approved docs/release compatibility path: version-gate or label latest-only docs, add schema/release drift checks, or make installed docs the default source for version-specific guidance.

## Reproduction Assessment

Yes, at source/history level: v2026.3.13-1 rejected `isolatedSession`, while the live docs later advertised it. The exact checked keys now match v2026.6.11, but the main-to-live-docs publish path still makes release drift source-reproducible as a class.

## Solution Assessment

No single schema or docs typo is the best full fix. The durable fix needs a maintainer choice between latest-only warnings, versioned docs, installed docs retrieval, and/or CI checks against the latest release schema.
