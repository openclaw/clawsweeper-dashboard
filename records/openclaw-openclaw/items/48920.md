## Summary

Keep open: the original `isolatedSession` release mismatch is now shipped, but the source-level docs-versus-release failure class is still present because current main adds documented `utilityModel` config while the latest release `v2026.6.11` does not accept that key and the docs sync workflow is still main-driven rather than release-gated.

## What This Changes

The issue reports that live OpenClaw docs can describe configuration that is not supported by the latest released package, causing documented config to fail strict validation for installed users.

## Best Possible Solution

Define and enforce a public docs compatibility policy: either publish release-matched docs by default, clearly badge latest-only content with version availability, or add generated schema checks so main-sourced config docs cannot guide stable users into unsupported keys.

## Reproduction Assessment

Yes, at source level: current main documents and accepts `utilityModel`, while `v2026.6.11` strict schema lacks that key and the docs publish workflow is main-driven. I did not prove the public page has already picked up this newest main-only docs change.

## Solution Assessment

No, a one-off rollback for `utilityModel` or the older heartbeat examples is not the best durable fix. The maintainable solution is a maintainer-chosen docs/release compatibility policy with enforcement or clear version labeling.
