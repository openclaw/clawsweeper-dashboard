## Summary

Keep open: the originally cited `isolatedSession` mismatch and later spot-checks now match the latest stable release, but current `main` still publishes live docs from `main` without a release-matching or version-labeling policy, so the recurring docs-versus-installed-release failure class is not resolved.

## What This Changes

The issue reports that live OpenClaw docs documented heartbeat config before the latest installed release accepted the key, causing strict config validation to stop the user's Telegram workflow.

## Best Possible Solution

Define the public docs compatibility policy, then implement release-pinned or clearly version-labeled docs plus a generated config-docs check or version-aware diagnostic so stable-release users are not guided into unsupported config.

## Reproduction Assessment

Yes, at source-mechanism level: the workflow publishes docs from `main` on docs changes with no release gate, so main-only docs can reach stable users. The exact `isolatedSession` failure no longer reproduces against `v2026.6.11` because that key is now shipped.

## Solution Assessment

Unclear until maintainers choose the docs policy. A one-off rollback for whichever config example is ahead today is not the best durable fix; release-pinned docs, version labels, generated compatibility checks, or version-aware validation errors need a product decision.
