## Summary

Keep open: current main still advertises a config key accepted only on main while the latest stable release rejects it under the strict config schema, so the live-docs-versus-release failure remains valid and needs maintainer policy direction.

## What This Changes

The issue asks for live OpenClaw docs to stay aligned with released versions or clearly mark version availability so documented config keys do not break released installs.

## Best Possible Solution

Define and enforce a public docs compatibility policy, then add version-aware docs/config validation or a Doctor/Fix recovery path so users are not left manually editing config after following official docs.
