## Summary

Keep open: the original `isolatedSession` and earlier `toolResultMaxChars` examples have shipped, but the recurring live-docs-versus-stable-release problem still reproduces because the public configuration reference now documents `wizard.securityAcknowledgedAt` while the latest stable release schema does not accept that strict `wizard` key.

## What This Changes

The issue asks for live docs to stay aligned with stable releases, or to show version availability, so users do not copy unreleased config into released OpenClaw builds.

## Best Possible Solution

Define the public docs compatibility policy, then implement release-pinned or version-labeled docs plus generated config-doc checks or version-aware diagnostics so stable-release users are not guided into unsupported config.

## Reproduction Assessment

Yes, at source level. The public docs/current main document `wizard.securityAcknowledgedAt`, while the latest stable tag's strict `wizard` schema does not accept that key.

## Solution Assessment

Unclear as an implementation path. A one-off rollback for the current example is not the best durable fix; maintainers need to choose and implement a public docs versioning, release-gating, or version-labeling policy.
