## Summary

Keep open: the report conflicts with the documented steer-queue delivery guarantee, and current main still contains a distinct Control UI pending-send queue whose state can disagree with Gateway queue depth. The closely related open report does not yet prove the same root cause because it triggers while idle rather than during an active turn.

## What This Changes

Fix webchat so a message submitted during an active turn is delivered after steering or is visibly reconciled as failed instead of remaining indefinitely in “Queued (1)”.

## Best Possible Solution

Make the chat.send acknowledgement and terminal Gateway lifecycle authoritative for each local queue item, preserving retryable content but converting rejected, dropped, or missing runs into an explicit retry/failure state; cover both active-turn steer and idle sends with focused UI/Gateway regression tests.
