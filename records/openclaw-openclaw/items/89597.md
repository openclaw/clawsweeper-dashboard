## Summary

Keep this PR open: the latest head still imports QQBot credential backups from HOME/USERPROFILE into the active stateDir migration path, the branch is currently conflicting, and the protected maintainer label plus credential-boundary impact need explicit human handling.

## What This Changes

The PR removes QQBot runtime JSON/JSONL cache imports, adds doctor/setup migration for QQBot credential backup JSON files into SQLite plugin KV, and wires startup preflight/docs/tests for that migration.

## Best Possible Solution

Keep the runtime SQLite-only cleanup direction, but restrict QQBot credential-backup migration and preflight detection to the active stateDir unless maintainers explicitly approve and document cross-root recovery.

## Reproduction Assessment

Yes. Source inspection on the latest PR head shows HOME/USERPROFILE QQBot backup roots feeding plugin-state imports that core executes under the active stateDir, and QQBot startup then restores imported credentials into config.

## Solution Assessment

No. Moving legacy imports out of runtime is the right ownership direction, but automatic HOME-to-active-state import is broader than the documented gateway isolation contract; active-state-only migration is the safer fix.
