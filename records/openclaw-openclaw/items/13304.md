## Label Justifications

- `P2`: This is a normal-priority multi-agent routing improvement with real workflow impact but no urgent shipped regression.
- `impact:message-loss`: Without content-based routing, shared-chat messages can be handled by the default or statically bound agent instead of the intended specialist agent.
- `impact:session-state`: Routing content to the wrong agent can attach conversation context to the wrong agent/session in multi-agent setups.

## Summary

Keep open: current main and the latest release still lack binding-level content matching and `stripMatch`, while the open pre-routing hook work is only an adjacent product/API path rather than a merged replacement.

## What This Changes

The issue requests an optional `bindings[].match.content` matcher with regex or prefix support and `stripMatch` so shared-channel messages can route directly to specialist agents by message text.

## Best Possible Solution

Choose one maintainer-approved routing surface: either a validated binding content matcher with deterministic precedence/cache/body-rewrite semantics, or a documented plugin hook path that explicitly replaces this config request.

## Reproduction Assessment

Yes, by source inspection. Adding `match.content` is rejected by the strict binding schema, and the resolver has no message text input or stripped-body output.

## Solution Assessment

Unclear until maintainers choose the API shape. A binding matcher is plausible, but the adjacent pre-routing plugin-hook design may be the better long-term owner for content-driven routing.
