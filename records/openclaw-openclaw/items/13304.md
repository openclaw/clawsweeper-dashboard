## Label Justifications

- `P2`: This is a normal-priority routing enhancement with concrete multi-agent workflow impact but no urgent shipped regression.
- `impact:message-loss`: Without content-based routing, shared-chat messages can be handled by the default or statically bound agent instead of the intended specialist agent.
- `impact:session-state`: Routing content to the wrong agent can attach conversation context to the wrong agent/session in multi-agent setups.

## Summary

Keep open: current main and the latest release still only support static binding selectors, and the open pre-routing hook work is partial overlap rather than a merged replacement for declarative `bindings[].match.content` plus `stripMatch`.

## What This Changes

Request adding content-pattern matching and optional prefix stripping to agent route bindings so shared-chat messages can route directly to specialist agents.

## Best Possible Solution

Define one maintainer-approved routing surface: either a validated binding content matcher with deterministic precedence, cache, and body-rewrite semantics, or a documented plugin-hook path that explicitly replaces this config request.

## Reproduction Assessment

Yes. Source inspection is sufficient: current main rejects `match.content` through the strict binding schema, and `resolveAgentRoute` has no message text input or stripped-body output.

## Solution Assessment

Unclear. A binding matcher is plausible, but maintainers first need to choose whether declarative config or the adjacent pre-routing plugin hook should own content-driven routing.
