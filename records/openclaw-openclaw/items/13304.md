## Label Justifications

- `P2`: This is a normal-priority routing/config feature with real multi-agent workflow impact but no established broken existing behavior contract.
- `impact:session-state`: Content-driven routing could determine which agent workspace and session store receives a shared-chat message.
- `impact:message-loss`: Without content-sensitive routing, messages in shared chats can be misrouted to the default or statically bound agent instead of the intended specialist.

## Summary

Keep open: current main and the latest release still only support static binding selectors, and the requested `match.content` plus `stripMatch` behavior remains a new routing/config API that needs maintainer direction.

## What This Changes

Request to add declarative binding matchers that route inbound messages by text prefix or regex and optionally strip the matched text before dispatching to the selected agent.

## Best Possible Solution

Define one maintainer-approved routing surface: either a validated binding content matcher with deterministic precedence, cache, safety, docs, and body-rewrite semantics, or a documented plugin hook path that explicitly supersedes this config request.

- **Approve Binding Matcher:** Add validated `match.content` config with explicit precedence, safe matching rules, cache behavior, docs, generated schema updates, and `stripMatch` semantics.
- **Supersede With Plugin Hook:** Close or narrow this issue only after a reviewed pre-routing hook lands and documentation explains how it replaces binding-level content routing.

## Reproduction Assessment

Yes, source-level: current main rejects `match.content` via the strict binding schema, `resolveAgentRoute` has no message-text input or stripped-body output, and representative callers pass only static route metadata. This is a missing feature/API surface rather than a broken existing behavior contract.

## Solution Assessment

Unclear until maintainers choose the API shape. A declarative binding matcher fits the reported workflow, but the adjacent pre-routing plugin-hook design may be the cleaner long-term owner for content-driven routing.
