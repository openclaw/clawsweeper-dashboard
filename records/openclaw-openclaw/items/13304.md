## Label Justifications

- `P2`: This is a normal-priority routing/config feature with real multi-agent workflow impact but no urgent shipped regression.
- `impact:message-loss`: Without content-based routing, shared-chat messages can be handled by the default or statically bound agent instead of the intended specialist agent.
- `impact:session-state`: Routing content to the wrong agent can attach conversation context to the wrong agent/session in multi-agent setups.

## Summary

Keep open: current main and the latest release still lack binding-level content matching and `stripMatch`, and the open pre-routing hook work is only a partial overlap rather than a merged replacement for the requested declarative binding API.

## What This Changes

The issue requests declarative binding matchers that can route inbound messages by text pattern or prefix and optionally strip the matched text before agent dispatch.

## Best Possible Solution

Define one maintainer-approved routing surface: either a validated binding content matcher with deterministic precedence, cache, safety, and body-rewrite semantics, or a documented plugin hook path that explicitly replaces this config request.

## Reproduction Assessment

Yes, from source inspection: current main rejects match.content through the strict binding schema, and resolveAgentRoute has no message text input or stripped-body output. This is a missing feature/API surface rather than a failing existing behavior contract.

## Solution Assessment

Unclear until maintainers choose the API shape. A declarative binding matcher is plausible, but the adjacent pre-routing plugin-hook design may be the better long-term owner for content-driven routing.
