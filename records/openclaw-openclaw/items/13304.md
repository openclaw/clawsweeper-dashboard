## Label Justifications

- `P2`: This is a normal-priority routing/config feature with real multi-agent workflow impact but no urgent shipped regression.
- `impact:message-loss`: Without content-sensitive routing, shared-chat messages can be handled by the default or statically bound agent instead of the intended specialist agent.
- `impact:session-state`: Routing content to the wrong agent can attach conversation context to the wrong agent or session in multi-agent setups.

## Summary

Keep open: current main and v2026.6.11 still only support static binding selectors, while this request needs a new content-aware binding/config contract and body rewrite semantics. The related pre-routing hook work overlaps, but it does not implement the declarative `bindings.match.content` API or `stripMatch` behavior requested here.

## What This Changes

The issue requests a `bindings.match.content` matcher for regex or prefix-based agent routing, with optional stripping of the matched prefix before dispatch.

## Best Possible Solution

Define one maintainer-approved routing surface: either a validated binding content matcher with deterministic precedence, cache, safety, docs, and body-rewrite semantics, or a documented plugin hook path that explicitly supersedes this config request.
