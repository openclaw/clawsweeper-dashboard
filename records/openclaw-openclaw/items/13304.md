## Label Justifications

- `P2`: This is a normal-priority routing improvement with real multi-agent workflow impact but no urgent shipped regression.
- `impact:message-loss`: Messages in a shared chat can currently be handled by the default or statically bound agent instead of the intended specialist agent.
- `impact:session-state`: Routing content to the wrong agent can attach conversation context to the wrong agent/session in multi-agent setups.

## Summary

Keep open: current main and the latest release still support only static binding selectors, so the requested `bindings[].match.content` and `stripMatch` behavior remain missing and need maintainer API direction.

## What This Changes

The issue requests declarative binding rules that route inbound messages to agents by message content patterns and optionally strip the matched prefix before the agent sees the text.

## Best Possible Solution

Choose one routing surface first: either a validated binding content matcher with deterministic precedence, cache, safety, and body-rewrite semantics, or a documented plugin hook path that explicitly replaces the config request.

## Reproduction Assessment

Yes, source inspection gives a high-confidence current-main reproduction: `match.content` is rejected by the strict binding schema, and the resolver has no message text input or stripped-body output.

## Solution Assessment

Unclear until maintainers choose the API shape. A binding matcher is plausible, but the adjacent pre-routing plugin-hook design may be the better long-term owner for content-driven routing.
