## Label Justifications

- `P2`: This is a normal-priority routing/config feature with real multi-agent workflow impact but no urgent shipped regression.
- `impact:session-state`: Content routed to the wrong specialist can attach conversation context to the wrong agent or session in multi-agent setups.
- `impact:message-loss`: Without content-sensitive routing, shared-chat messages can be handled by the default or statically bound agent instead of the intended specialist agent.

## Summary

Keep open: current main and the latest release still lack binding-level content matching, message-text-aware route resolution, and `stripMatch`; adjacent pre-routing hook work overlaps but does not replace this declarative binding API request.

## What This Changes

The issue requests a `bindings[].match.content` matcher with pattern/prefix matching and optional matched-prefix stripping so inbound messages can route to specialist agents by message text.

## Best Possible Solution

Define one maintainer-approved routing surface: either a validated binding content matcher with deterministic precedence, cache, safety, and body-rewrite semantics, or a documented plugin hook path that explicitly supersedes this config request.

Yes, source-level: current main rejects `match.content` through strict binding schema, `resolveAgentRoute` has no message-text input or stripped-body output, and representative channel callers pass only static metadata. Unclear until maintainers choose the API shape. A declarative binding matcher fits the reported workflow, but the adjacent pre-routing plugin-hook design may be the better long-term owner for content-driven routing.
