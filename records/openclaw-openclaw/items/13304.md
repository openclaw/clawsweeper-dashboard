## Label Justifications

- `P2`: This is a normal-priority multi-agent routing improvement with real workflow impact but no urgent shipped regression.
- `impact:message-loss`: Without content-based routing, shared-chat messages can be handled by the default or statically bound agent instead of the intended specialist agent.
- `impact:session-state`: Routing content to the wrong agent can attach conversation context to the wrong agent or session in multi-agent setups.

## Summary

Keep open: current main and the latest release still lack binding-level message content matching and stripMatch, and the open pre-routing hook work is adjacent rather than a merged replacement for the requested declarative binding contract.

## What This Changes

The issue requests optional bindings[].match.content rules for regex/prefix-based agent routing, plus optional stripping of the matched prefix before the agent sees the message.

## Best Possible Solution

Maintainers should choose one routing surface: a validated binding content matcher with explicit cache and body-rewrite semantics, or a documented plugin hook path that deliberately replaces this config request.

## Reproduction Assessment

Yes, by source inspection. The proposed match.content shape is absent from the binding type and rejected by the strict schema, and the resolver has no message text input or stripped-body output.

## Solution Assessment

Unclear until maintainers choose the API shape. A binding matcher is plausible, but the adjacent pre-routing plugin-hook design may be the cleaner long-term owner for content-driven routing.
