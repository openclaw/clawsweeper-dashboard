## Label Justifications

- `P2`: This is a normal-priority routing feature with real multi-agent workflow impact but no urgent shipped regression.
- `impact:message-loss`: Without content-based routing, shared-chat messages can be handled by the default or statically bound agent instead of the intended specialist agent.
- `impact:session-state`: Routing content to the wrong agent can attach conversation context to the wrong agent/session in multi-agent setups.

## Summary

Keep open: current main still lacks binding-level content matching and `stripMatch`, and the open pre-routing hook work is only partial overlap rather than a merged replacement for the requested declarative binding API.

## What This Changes

The issue requests a new `bindings[].match.content` pattern matcher with optional `stripMatch` so inbound messages in shared chats can route to different agents by message text.

## Best Possible Solution

Define one maintainer-approved routing surface: either a validated binding content matcher with deterministic precedence, cache, safety, and body-rewrite semantics, or a documented plugin hook path that explicitly replaces this config request.

## Reproduction Assessment

Yes, from source inspection: current main rejects `match.content` through the strict binding schema, and `resolveAgentRoute` has no message text input or stripped-body output. I did not run a live channel reproduction because this is a missing feature/API surface rather than a broken existing contract.

## Solution Assessment

Unclear until maintainers choose the API shape. A declarative binding matcher is plausible, but the adjacent pre-routing plugin-hook design may be the better long-term owner for content-driven routing.

## Risks / Open Questions

- The requested matcher needs maintainer decisions on precedence against static bindings, mention behavior, focus/thread bindings, and plugin-owned pre-routing hooks.

- Content-sensitive routing conflicts with the current static route cache unless the cache key includes normalized content, content rules bypass caching, or cache behavior is split by matcher type.
