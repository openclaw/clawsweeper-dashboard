## Summary

Keep open: current main still lacks binding-level content matching and body-stripping, and the adjacent pre-routing hook work is open and partial rather than a replacement for the declarative binding request.

## What This Changes

Request to add optional content/pattern matchers, including stripMatch, to bindings so message text can select agent routes.

## Best Possible Solution

Define one maintainer-approved routing surface: either a validated binding content matcher with deterministic precedence/cache/body-rewrite semantics, or a documented plugin hook path that explicitly replaces this config request.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence current-main reproduction: adding match.content is rejected by the strict schema, and the route resolver has no message text input or stripped-body output.

## Solution Assessment

Unclear until maintainers choose the API shape. A binding matcher is plausible, but the adjacent pre-routing plugin hook may be the better owner-boundary solution for content-driven routing.
