## Label Justifications

- `P2`: This is a normal-priority routing enhancement with real multi-agent workflow impact but no urgent shipped regression.
- `impact:message-loss`: Without content-sensitive routing, shared-chat messages can be handled by the default or statically bound agent instead of the intended specialist agent.
- `impact:session-state`: Routing content to the wrong agent can attach conversation context to the wrong agent/session in multi-agent setups.

## Summary

Keep open: current main and the latest release still lack binding-level content matching and `stripMatch`, and the open pre-routing hook work only partially overlaps rather than replacing the requested declarative binding API.

## What This Changes

Request adding an optional content matcher to `bindings[].match` so message prefixes or regexes can route a shared chat to different agents and optionally strip the matched prefix before agent delivery.

## Best Possible Solution

Define one maintainer-approved routing surface: either a validated binding content matcher with deterministic precedence/cache/body-rewrite semantics, or a documented plugin hook path that explicitly supersedes this config request.

## Reproduction Assessment

Yes for the source-level capability gap: current main rejects `match.content` through the strict binding schema and `resolveAgentRoute` has no message text input or stripped-body output. This is a feature request rather than a failing existing contract bug.

## Solution Assessment

Unclear until maintainers choose the API shape. A binding matcher is plausible, but the adjacent pre-routing plugin-hook design may be the better long-term owner for content-driven routing.
