## Label Justifications

- `P2`: This is a normal-priority routing/config feature with real multi-agent workflow impact but no urgent shipped regression.
- `impact:message-loss`: Without content-based routing, a shared-chat message can be handled by the default or statically bound agent instead of the intended specialist agent.
- `impact:session-state`: Wrong-agent routing can attach conversation context and session history to the wrong agent in multi-agent setups.

## Summary

Keep open: current main and v2026.6.11 still only support static binding selectors, and the open pre-routing hook work is a partial overlap rather than a merged replacement for declarative binding content matching and stripMatch semantics.

## What This Changes

Request adds an optional binding-level content matcher, including regex or prefix matching and optional matched-prefix stripping, so group messages can route directly to different agents by text.

## Best Possible Solution

Define one maintainer-approved routing surface: a validated binding content matcher with deterministic precedence, cache safety, regex limits, and body-rewrite semantics, or a documented plugin hook path that explicitly replaces this config request.

## Reproduction Assessment

Yes, at source level: current main rejects match.content through the strict binding schema and resolveAgentRoute has no message text input or stripped-body output. This is a missing feature/API surface, not a broken existing behavior contract.

## Solution Assessment

Unclear until maintainers choose the API shape. A declarative binding matcher is plausible, but the adjacent pre-routing plugin-hook design may be the better long-term owner for content-driven routing.
