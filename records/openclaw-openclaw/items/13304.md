## Label Justifications

- `P2`: This is a normal-priority multi-agent routing feature with real workflow impact but no urgent shipped regression.
- `impact:message-loss`: Messages in shared chats can be routed to the default or statically bound agent instead of the intended specialist agent.
- `impact:session-state`: Content sent to the wrong agent can attach context to the wrong agent/session in multi-agent setups.

## Summary

Keep open: current main still lacks declarative binding-level content matching and `stripMatch`, and the related pre-routing hook work is only partial overlap rather than a merged replacement for the requested config/API behavior.

## What This Changes

The issue requests `bindings[].match.content` prefix or regex matching so inbound messages can route to different agents by message text, optionally stripping the matched prefix before delivery.

## Best Possible Solution

Define one maintainer-approved routing surface: either a validated binding content matcher with deterministic precedence, cache, safety, and body-rewrite semantics, or a documented plugin hook path that explicitly replaces this config request.

## Reproduction Assessment

Yes. Current main rejects `match.content` through the strict binding schema, and `resolveAgentRoute` has no message text input, content tier, content-aware cache key, or stripped-body output.

## Solution Assessment

Unclear until maintainers choose the API shape. A declarative binding matcher is plausible, but the adjacent pre-routing plugin-hook design may be the better long-term owner for content-driven routing.
