## Label Justifications

- `P2`: This is a normal-priority multi-agent routing enhancement with real workflow impact but no urgent shipped regression.
- `impact:message-loss`: Without content-based routing, shared-chat messages can be handled by the default or statically bound agent instead of the intended specialist agent.
- `impact:session-state`: Routing content to the wrong agent can attach conversation context to the wrong agent/session in multi-agent setups.

## Summary

Keep open: current main still lacks declarative binding-level content matching and `stripMatch`, while the open pre-routing hook work only partially overlaps and has not replaced the requested config surface.

## What This Changes

Request to let `bindings[].match` route inbound messages by message content patterns and optionally strip the matched prefix before the agent sees the body.

## Best Possible Solution

Define one maintainer-approved routing surface: a validated binding content matcher with deterministic precedence, cache, safety, and body-rewrite semantics, or a documented plugin hook path that explicitly replaces this config request.

## Reproduction Assessment

Yes, from source inspection: current main rejects match.content through the strict binding schema, and resolveAgentRoute has no message text input or stripped-body output. This is a missing feature/API surface rather than a failing existing behavior contract.

## Solution Assessment

Unclear until maintainers choose the API shape. A declarative binding matcher is plausible, but the adjacent pre-routing plugin-hook design may be the better long-term owner for content-driven routing.
