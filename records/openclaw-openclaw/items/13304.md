## Label Justifications

- `P2`: This is a normal-priority routing enhancement with clear user value but it is not an urgent shipped regression or setup blocker.
- `impact:message-loss`: Without content-based routing, messages intended for a specialist agent can be handled by the default/middleman agent instead of the intended responder.
- `impact:session-state`: The request changes which agent/session receives inbound messages based on user text, directly affecting session ownership and context continuity.

## Summary

Keep open: current main and the latest release still only support static binding selectors, and the related pre-routing hook work is open but does not implement declarative `bindings[].match.content` plus `stripMatch` semantics.

## What This Changes

Request content-based binding matchers so inbound messages can route to different agents by regex or prefix instead of only channel/account/peer metadata.

## Best Possible Solution

Define a first-class, validated content-routing contract only after maintainers choose the boundary: if it belongs in bindings, specify precedence, cache behavior, text normalization, body rewriting, docs, and cross-channel tests; if it belongs in plugins, make the pre-routing hook the supported extension path.

Rationale: Both paths are plausible, but the choice changes public config shape, routing precedence, cache semantics, plugin boundaries, and channel delivery behavior; automation cannot safely choose that product/API boundary.

Options:

- **Adopt Core Content Bindings (recommended):** Add a validated binding matcher with explicit regex/prefix safety, deterministic precedence, route-cache treatment, body-rewrite semantics, docs, and representative channel tests.
- **Use Plugin Hook Instead:** Keep core bindings static and treat content classification as plugin-owned once a bounded pre-routing hook is approved and documented.
- **Defer The Feature:** Keep the middleman-agent workaround for now and revisit after the broader pre-routing hook and Discord routing decisions settle.

## Reproduction Assessment

Yes. Source inspection is enough for this feature gap: current config validation rejects `match.content`, and the route resolver/caches do not carry message text or return a stripped body.

## Solution Assessment

Unclear until maintainers choose the boundary. A declarative binding matcher is a coherent solution for the reported workflow, but a bounded pre-routing plugin hook may better fit the core-lean/plugin-first architecture.
