## Label Justifications

- `P2`: This is a normal-priority routing/config feature with real multi-agent workflow impact but no urgent shipped regression.
- `impact:message-loss`: Without content-sensitive routing, shared-chat messages can be handled by the default or statically bound agent instead of the intended specialist agent.
- `impact:session-state`: Routing content to the wrong agent can attach conversation context to the wrong agent or session in multi-agent setups.

## Summary

Keep open: current main and v2026.6.11 still lack binding-level content matching, message-text-aware route resolution, and `stripMatch`; related hook and Discord mention-routing work overlaps but does not replace this declarative binding API request.

## What This Changes

The issue requests an optional `bindings[].match.content` matcher with regex/prefix matching and optional matched-prefix stripping for routing group messages to different agents by message text.

## Best Possible Solution

Define one maintainer-approved content-routing surface: either a validated binding content matcher with deterministic precedence, cache, safety, docs, and body-rewrite semantics, or a documented plugin hook path that explicitly supersedes this config request.

- **Supersede With Plugin Hook:** Narrow or close this issue only after a reviewed pre-routing hook lands and documentation explains how plugins replace binding-level content routing.

## Reproduction Assessment

Yes, source-level: current main rejects `match.content` through strict binding schema, `resolveAgentRoute` has no message-text input or stripped-body output, and representative channel callers pass only static metadata. This is a missing feature/API surface rather than a broken existing behavior contract.

## Solution Assessment

Unclear until maintainers choose the API shape. A declarative binding matcher fits the reported workflow, but the adjacent pre-routing plugin-hook design may be the better long-term owner for content-driven routing.
