## Label Justifications

- `P2`: This is a normal-priority routing/config feature with real multi-agent workflow impact but no urgent shipped regression.
- `impact:session-state`: Content-insensitive static routing can attach a shared-chat turn to the wrong agent or session in multi-agent setups.
- `impact:message-loss`: Messages intended for a specialist agent can be handled by the default or statically bound agent instead.

## Summary

Keep open: current main and the latest release still only support static binding selectors, while related hook work overlaps but does not implement declarative `bindings[].match.content` routing or `stripMatch` semantics.

## What This Changes

The issue requests content-pattern matching in route bindings so inbound messages can route to different agents and optionally strip the matched prefix before dispatch.

## Best Possible Solution

Define one maintainer-approved content-routing surface: either validated binding content matchers with deterministic precedence, cache, safety, docs, and body-rewrite semantics, or a documented plugin hook path that explicitly supersedes this config request.

Yes, source-level: current main rejects `match.content` through strict binding schema, `resolveAgentRoute` has no message-text input or stripped-body output, and representative channel callers pass only static metadata. ## Solution Assessment

Unclear until maintainers choose the API shape. A declarative binding matcher fits the reported workflow, but the adjacent pre-routing plugin-hook design may be the better long-term owner for content-driven routing.
