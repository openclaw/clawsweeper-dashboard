## Label Justifications

- `P2`: This is a normal-priority routing feature with real multi-agent workflow impact but it needs product/API direction before implementation.
- `impact:message-loss`: Without content-based routing, shared-chat messages can be handled by the default or statically bound agent instead of the intended specialist agent.
- `impact:session-state`: Routing content to the wrong agent can attach conversation context to the wrong agent/session in multi-agent setups.

## Summary

Keep open: current main still lacks binding-level content matching and `stripMatch`, and the open pre-routing hook work is only partial overlap rather than a merged replacement for the requested declarative binding API.

## What This Changes

Request to add optional message-content pattern matching and optional matched-prefix stripping to agent route bindings.

## Best Possible Solution

Define one maintainer-approved routing surface: either a validated binding content matcher with deterministic precedence/cache/body-rewrite semantics, or a documented plugin hook path that explicitly replaces this config request.

## Reproduction Assessment

Yes, from source inspection: current main rejects `match.content` through the strict binding schema, and `resolveAgentRoute` has no message text input or stripped-body output.

## Solution Assessment

Unclear until maintainers choose the API shape. A binding matcher is plausible, but the adjacent pre-routing plugin-hook design may be the better long-term owner for content-driven routing.
