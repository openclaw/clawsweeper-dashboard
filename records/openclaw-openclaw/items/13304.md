## Label Justifications

- `P2`: This is a normal-priority routing feature with real multi-agent workflow impact but no urgent shipped regression.
- `impact:message-loss`: Shared-chat messages can be handled by the default or statically bound agent instead of the intended specialist agent.
- `impact:session-state`: Content sent to the wrong agent can attach conversation context to the wrong agent or session in multi-agent setups.

## Summary

Keep open: current main and the latest release still only support static binding selectors, while the open pre-routing hook work is partial overlap rather than a merged replacement for declarative binding content matching and `stripMatch`.

## What This Changes

The issue requests optional `bindings[].match.content` pattern or prefix matching, with optional matched-prefix stripping before the message reaches the selected agent.

## Best Possible Solution

Define one maintainer-approved routing surface: either a validated binding content matcher with deterministic precedence, cache, safety, and body-rewrite semantics, or a documented plugin hook path that explicitly replaces this config request.

## Reproduction Assessment

Yes, from source inspection: current main rejects `match.content` through the strict binding schema and `resolveAgentRoute` has no message text input or stripped-body output. A live channel repro is not needed to prove this missing feature/API surface.

## Solution Assessment

Unclear until maintainers choose the API shape. A declarative binding matcher is plausible, but a pre-routing plugin hook may be the better long-term owner if maintainers prefer plugin-defined content routing over new core config.
