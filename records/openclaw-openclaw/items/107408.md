## Label Justifications

- `P1`: A running Gateway can lose provider or CLI-backend registrations mid-session, breaking real agent workflows until restart.
- `impact:auth-provider`: The failure removes provider and CLI-backend ownership from the active plugin registry, causing configured model/runtime routes to become unavailable.

## Summary

Keep open: the report describes a credible shipped plugin-registry regression, and the linked open pull request is the canonical candidate fix; the issue should remain open until that PR is reviewed and merged or an equivalent fix lands.

## What This Changes

Prevent scoped agent-harness plugin activation from replacing the global active registry and dropping unrelated plugins’ registered CLI backends, providers, and capabilities.

## Best Possible Solution

Land a generic registry-lifecycle fix that preserves unrelated valid active plugin surfaces during scoped harness activation, respects restrictive allowlists and disablement, and includes both real-loader eviction coverage and focused cache/allowlist regression tests.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: activate a plugin that registers a CLI backend, then force a genuine cache-miss scoped load for a different agent harness and resolve the first backend again. A live run against the exact current-main SHA would raise confidence from source-reproducible to reproduced.

## Solution Assessment

Unclear pending PR review: preserving allowed active plugin IDs is a bounded plausible fix, but maintainers should compare it with a non-activating call-scoped registry because that alternative avoids mutating global state entirely.
