## What This Changes

The PR changes Discord progress streaming to defer text-only progress block replies while a progress draft may appear, flush them before final replies when the draft stays empty, and make shared progress suppression depend on a visible progress draft.

## Best Possible Solution

Land the focused Discord/channel fix after redacted real Discord proof shows the fallback progress block arrives before the final reply and no duplicate block appears once a progress draft becomes visible.

## Reproduction Assessment

Yes, source-reproducible: current main and v2026.6.11 suppress progress-mode standalone tool progress before proving a Discord progress draft is visible, and current Discord delivery drops text-only block replies while a draft stream exists. I did not run a live Discord/Codex reproduction in this read-only review.

## Solution Assessment

Yes for code shape: delaying suppression until a draft is visible and flushing empty-draft fallback blocks is narrower than globally unsuppressing tool messages and preserves visible-draft ownership. It is not proof-sufficient without live Discord ordering evidence.
