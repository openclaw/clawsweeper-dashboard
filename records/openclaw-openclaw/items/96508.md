## Summary

Keep open for maintainer security/product acceptance: the patch appears to fix the linked SecretRef dashboard recovery gap and has sufficient live/browser proof, but it intentionally creates an opt-in clipboard path for a full gateway bearer token.

## What This Changes

The PR adds `openclaw dashboard --copy-token`, wires it through CLI registration, adds regression tests, and updates dashboard docs so resolved gateway tokens can be copied while opening a clean Control UI URL.

## Best Possible Solution

Land the opt-in copy-token path only after explicit maintainer acceptance of clipboard bearer recovery; otherwise keep the canonical issue focused on session or exchange-token dashboard auth.

## Reproduction Assessment

Yes. Source inspection shows SecretRef-managed tokens keep `openclaw dashboard` on a clean URL and `config get` returns the redacted SecretRef object, leaving a user without sessionStorage no plaintext recovery path.

## Solution Assessment

Acceptable interim fix if maintainers approve the auth boundary; it is narrower than session/exchange-token auth but keeps normal SecretRef URL behavior unchanged and avoids stdout, log, and browser URL leaks.
