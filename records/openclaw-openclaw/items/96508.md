## Summary

Keep open for maintainer review: the patch is focused, fixes the earlier clipboard-overwrite problem from the prior attempt, has sufficient live proof, and I found no line-level correctness finding. ## What This Changes

The PR adds `openclaw dashboard --copy-token`, wires it through the maintenance CLI, updates dashboard docs, and adds regression coverage for resolved-token clipboard and clean-URL behavior.

## Best Possible Solution

Land the opt-in copy-token path only if maintainers accept clipboard bearer recovery as an interim Control UI auth design; otherwise keep the canonical issue focused on session or exchange-token dashboard authentication.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: with a SecretRef-managed `gateway.auth.token`, current `openclaw dashboard` uses a clean URL and `openclaw config get gateway.auth.token` returns the SecretRef object while the Control UI still needs a token after browser session state is lost.

## Solution Assessment

Unclear until maintainers accept the security boundary. This is a narrow interim fix with focused tests and real behavior proof, but session or exchange-token auth remains the cleaner long-term design if plaintext clipboard recovery is rejected.
