## Summary

Keep open for maintainer review: the patch appears technically correct and the PR body supplies after-fix live proof, but merging it intentionally creates an opt-in clipboard recovery path for a full gateway bearer token across the existing SecretRef non-exposure boundary.

## What This Changes

The branch adds `openclaw dashboard --copy-token`, wires it through the maintenance CLI, updates dashboard docs, and adds regression tests for copying resolved gateway tokens while opening clean Control UI URLs.

## Best Possible Solution

Land the opt-in copy-token path only if maintainers accept clipboard bearer recovery; otherwise solve the canonical issue with a session or exchange-token dashboard auth flow.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: with a SecretRef-managed `gateway.auth.token`, current `openclaw dashboard` uses a clean URL and `config get` returns the redacted config value while Control UI still needs a token after browser session state is lost.

## Solution Assessment

Unclear until maintainers accept the security boundary. This is a narrow interim fix with focused tests and real behavior proof, but session or exchange-token auth remains the cleaner long-term design if plaintext clipboard recovery is rejected.
