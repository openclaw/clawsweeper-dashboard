## Summary

Keep this PR open: the bounded read is a useful hardening change, but the final branch turns each cap overflow into a uniquely named persisted archive with no retention bound. That leaves a repeated malformed-input path able to consume disk indefinitely, so the archive retention contract needs a maintainer decision and a bounded implementation before merge.

## What This Changes

The branch replaces unbounded cron quarantine-sidecar reads with an 8 MiB bounded reader, then archives and restarts an oversized sidecar during writes, with cron store and service regression coverage.

## Best Possible Solution

Keep the 8 MiB bounded reader, but select and implement a bounded archive-retention policy that preserves the intended diagnostic/recovery value without allowing unbounded disk growth, then prove the chosen recovery path against a real final-head cron store.
