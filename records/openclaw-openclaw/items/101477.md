A single quarantine record larger than the cap can remain pending forever, causing later full cron saves and doctor repair to stop before committing canonical SQLite state.

## What This Changes

The PR replaces an unbounded cron quarantine sidecar read with an 8 MiB bounded reader, rejects serialized sidecar writes over 8 MiB, and adds focused oversized read/write tests.

## Best Possible Solution

Keep the bounded reader, but fit quarantine diagnostics into a deterministic byte budget by trimming, summarizing, or omitting oversized records so pending state clears and canonical SQLite persistence always remains available.
