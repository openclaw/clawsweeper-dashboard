## Summary

Keep this PR open, but do not merge it as written: its archive-on-overflow path retains every recovery sidecar indefinitely, so repeated malformed cron input can still exhaust disk space. The bounded read is useful, but archive retention is a product and operations contract that needs maintainer direction before landing.

## What This Changes

The PR replaces the cron quarantine sidecar’s unbounded read with an 8 MiB bounded read, caps new sidecar writes, and rotates a full sidecar into uniquely named archive files so cron persistence can continue.

## Best Possible Solution

Keep the bounded read and write protections, but land archive rotation only with an explicitly approved recovery-data lifecycle—such as a documented operator cleanup/doctor flow or a tested retention policy—and remove unrelated release-checklist churn from the branch.
