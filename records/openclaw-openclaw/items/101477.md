## Summary

Keep this PR open because current main still has the unbounded read, so the fix remains necessary. The latest head addresses the prior cron-persistence blocker, but it is not merge-ready because rollover archives can accumulate without bound and the newly added recovery path lacks direct real-environment proof.

## What This Changes

The branch caps cron quarantine sidecar reads and writes at 8 MiB, rotates an existing sidecar when appending would exceed the cap, and adds store- and service-level regression coverage.

## Best Possible Solution

Keep the bounded reader, but make quarantine rollover lifecycle-owned and storage-bounded—prefer canonical SQLite retention or, at minimum, a fixed replaceable backup with an explicit byte/count limit—then demonstrate a real cron persistence run through the overflow path.
