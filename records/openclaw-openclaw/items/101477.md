## Summary

Keep open: current main makes quarantine-write failures non-blocking, so the earlier P1 persistence-outage concern no longer survives, but the branch still permanently stalls quarantine retention whenever the 8 MiB ceiling is reached. A bounded retention or recovery path is needed before merge.

## What This Changes

The PR caps cron quarantine sidecar reads and serialized writes at 8 MiB and adds oversized-file regression tests.

## Best Possible Solution

Keep the bounded reader, but add bounded retention or archival rotation so reaching the ceiling cannot disable future quarantine writes or sanitization, then cover that behavior through the cron service persistence path.
