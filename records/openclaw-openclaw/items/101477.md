## Summary

The bounded-read and overflow-recovery work is useful and has credible live filesystem proof, but the branch still silently deletes older recovery archives under a new hard-coded retention policy without an approved recovery-data contract. Keep this PR open for an owner decision rather than merging or auto-repairing it.

## What This Changes

The PR caps cron quarantine sidecar reads and writes at 8 MiB, archives sidecars on overflow so cron writes continue, and retains only five uniquely named recovery archives by pruning the oldest files.

## Best Possible Solution

Keep the 8 MiB bounded-read and write-continuation design, but land archive pruning only after an owner explicitly defines whether quarantine archives are disposable recovery artifacts, the intended retention window/count, and the operator-visible recovery path.
