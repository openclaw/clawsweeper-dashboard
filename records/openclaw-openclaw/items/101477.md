## Summary

Keep open: the earlier cron-persistence blocker is addressed, but the new rollover path can accumulate unlimited near-8 MiB archive files and eventually exhaust the state volume; the latest recovery behavior also lacks live, non-test proof.

## What This Changes

The PR caps cron quarantine sidecar reads at 8 MiB and adds archive-and-rotate recovery with store- and service-level regression tests.

## Best Possible Solution

Keep the 8 MiB bounded reader, but make rollover lifecycle-bounded—prefer one replaceable recovery archive or an explicit retained-count/byte limit, with repeated-rollover coverage and a redacted live run proving both archive creation and continued SQLite persistence.
