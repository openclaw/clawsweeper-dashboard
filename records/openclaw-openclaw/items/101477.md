## Summary

The earlier stale-path concern is resolved: this branch now patches the live quarantine reader on current main. However, the added write rejection can turn the ancillary quarantine sidecar into a permanent blocker for canonical cron persistence, so the PR still needs a bounded recovery policy before merge.

## What This Changes

Adds an 8 MiB limit to cron quarantine sidecar reads and writes, with focused oversized-file regression tests.

## Best Possible Solution

Keep the bounded reader, but make an oversized or unreadable quarantine sidecar recoverable by archiving or rotating it and starting a bounded replacement, while preserving canonical SQLite cron writes; add a service-level test proving cron mutations still persist after the sidecar reaches the limit.

## Solution Assessment

No. Bounding the read is the right primitive, but permanently rejecting sidecar growth is not the safest fix because the quarantine artifact can then block the canonical SQLite store; bounded archive or rotation recovery is narrower and operationally safer.
