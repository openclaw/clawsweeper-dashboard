## Summary

Keep open: the prior P1 availability finding remains on the exact live head. The hard sidecar write limit can leave quarantine entries pending, causing later cron persistence and doctor repair to fail repeatedly until manual cleanup.

## What This Changes

This PR caps cron quarantine sidecar reads at 8 MiB, rejects serialized quarantine writes above the same limit, and adds oversized read/write regression tests.

## Best Possible Solution

Keep the shared 8 MiB bounded reader, but deterministically retain, summarize, truncate, or omit quarantine diagnostics within that byte budget so generated sidecar growth never blocks active cron persistence or doctor repair.
