## Summary

This PR has a valid bounded-read objective and recent contributor evidence, but the proposed overflow recovery creates indefinitely retained archive sidecars; that lifecycle remains an unresolved maintainer product and storage decision, so the branch should not merge as-is.

## What This Changes

The branch caps cron quarantine sidecar reads and writes at 8 MiB, then archives an overflowing sidecar and starts a fresh one so cron persistence can continue.

## Best Possible Solution

Keep the bounded reader, but have the cron/storage owner define a durable recovery policy: surface oversized sidecars through Doctor and provide an explicit, verified operator cleanup or migration path before adding persistent archive rotation.
