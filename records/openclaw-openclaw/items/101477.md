## Summary

The read bound addresses a real memory-exhaustion problem, but the current write guard preserves the prior blocking defect: once the quarantine payload exceeds 8 MiB, cron persistence returns before writing the primary durable store. The PR needs a bounded retention or canonical-storage policy rather than a hard sidecar failure.

## What This Changes

The PR caps cron quarantine sidecar reads and serialized writes at 8 MiB and adds focused oversized-file regression tests.

## Best Possible Solution

Keep the bounded regular-file read, then either retain a deterministic bounded subset of quarantine diagnostics or move them into the canonical SQLite state store so overflow never blocks primary cron persistence.
