## Summary

Keep this PR open: current main still performs an unbounded quarantine-sidecar read, so the central hardening remains necessary, but the fixed-name archive recovery path overwrites previously quarantined persistent records after a later overflow and needs a maintainer-approved retention contract before merge.

## What This Changes

Bounds cron quarantine-sidecar reads and writes at 8 MiB, then archives and restarts an over-cap sidecar while adding cron store and service regression coverage.

## Best Possible Solution

Keep the 8 MiB bounded read, but define and implement a non-destructive retention path for quarantined persistent records—preferably a canonical SQLite/doctor-owned path—before allowing automatic sidecar rotation.
