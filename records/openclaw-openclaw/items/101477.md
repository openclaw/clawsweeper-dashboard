## Summary

This PR should remain open because the unchanged hard write rejection can prevent cron mutations from reaching durable SQLite storage once accumulated quarantine history exceeds the cap; the supplied runtime proof covers bounded reads but not this persistence failure.

## What This Changes

The PR bounds cron quarantine sidecar reads at 8 MiB, rejects serialized sidecar writes above the same cap, and adds focused tests for both limits.

## Best Possible Solution

Keep the bounded regular-file read, but serialize a deterministic retained subset below the byte cap so quarantine history cannot block canonical cron persistence; prove both sidecar reload and a real mutation at the boundary.
