## Summary

This PR remains necessary because current `main` still reads cron quarantine sidecars without a byte limit. The patch is correct and well-proven, but it tightens a shipped persisted-state contract: incompatible sidecars will now fail closed, and quarantine failure blocks subsequent cron sanitization and persistence until the file is repaired.

## What This Changes

The PR replaces unbounded cron quarantine sidecar reads with an 8 MiB regular-file reader, applies the same cap before writes, and adds oversized load/save regression tests.

## Best Possible Solution

Keep the shared bounded read/write invariant, but merge only after the cron persistence owner accepts the fail-closed upgrade contract and confirms the existing warning and documentation give operators an actionable repair or reset path.
