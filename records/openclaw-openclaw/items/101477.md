## Summary

Keep this PR open for a cron persistence owner decision: the bounded read/write and overflow recovery are useful and have credible runtime proof, but silently deleting older recovery archives establishes a new data-retention contract without owner approval.

## What This Changes

The branch caps cron quarantine sidecar reads and writes at 8 MiB, archives an overflowed sidecar so cron writes can continue, and deletes oldest archives beyond a five-file limit.

## Best Possible Solution

Define an explicit, owner-approved bounded recovery-artifact policy—such as a documented retention limit with an operator-visible cleanup/recovery path—then retain the bounded read/write and archive-recovery implementation only if it follows that contract.
