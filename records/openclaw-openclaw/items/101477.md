## Summary

The defensive read limit remains useful on current main, but the prior P1 durability finding is unresolved on the latest head: accumulated quarantine history above the limit makes the sidecar flush fail before the canonical SQLite cron save, and the submitted proof demonstrates only the read path.

## What This Changes

The PR caps cron quarantine sidecar reads and serialized writes at 8 MiB and adds regression tests asserting rejection of oversized sidecars.

## Best Possible Solution

Keep the bounded regular-file read, but serialize quarantine history using deterministic byte-bounded retention so the sidecar remains loadable without making canonical cron persistence depend on unbounded historical growth.

## Solution Assessment

No. Bounded regular-file reads are appropriate, but hard-rejecting accumulated quarantine history is not the safest fix because it can block canonical persistence; deterministic retention satisfies the memory bound without creating that failure mode.
