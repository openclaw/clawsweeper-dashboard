## Summary

Keep this PR open for maintainer review. The latest head resolves the prior unsafe auto-deletion concern by removing pruning, but it now leaves recovery archives without a bounded retention or explicit cleanup contract; the PR body’s live proof still describes the removed pruning behavior and is not proof for the current head.

## What This Changes

The PR caps cron quarantine-sidecar reads and writes at 8 MiB, archives a saturated sidecar so cron persistence can continue, and adds cron-store and service-level regression coverage.

## Best Possible Solution

Keep the 8 MiB read/write bound and archive-before-continue recovery, but have a maintainer select and document a recovery-archive lifecycle—prefer an explicit Doctor inspection and cleanup flow over silent runtime deletion—then add current-head proof for that selected contract.
