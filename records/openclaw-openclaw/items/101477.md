## Summary

This PR addresses a live unbounded cron-quarantine read, but it is not safe to merge as written: every overflow creates another retained recovery file with no lifecycle, and the branch also removes the public declaration for an unrelated release-checklist helper.

## What This Changes

The branch caps cron quarantine-sidecar reads and writes at 8 MiB, rotates a saturated sidecar into a timestamped archive, and adds cron store and service regression coverage.

## Best Possible Solution

Keep the focused 8-MiB read/write protection, restore the unrelated declaration, and land archive rotation only with a maintainer-approved bounded operator lifecycle—preferably Doctor-visible inspection and explicit cleanup rather than silent deletion.
