## Summary

The bounded read is useful, but the latest head still hard-rejects an oversized accumulated quarantine payload before the service saves the canonical cron store, so this PR can turn diagnostic-history growth into repeated cron mutation failures. The prior P1 finding remains unresolved, and the posted terminal proof covers only the successful read bound rather than mutation durability at the retention limit.

## What This Changes

The PR caps cron quarantine sidecar reads and serialized writes at 8 MiB and adds tests asserting oversized sidecars are rejected.

## Best Possible Solution

Keep the bounded regular-file read, but serialize quarantine history with deterministic byte-bounded retention—preferably retaining the newest useful records—so the sidecar remains loadable without making canonical cron persistence depend on unlimited historical growth.
