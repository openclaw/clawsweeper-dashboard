## Summary

Keep this PR open: the bounded read and write cap are useful, but overflow recovery currently retains every 8 MiB archive indefinitely, so repeated bad inputs can still exhaust disk and halt cron persistence; the submitted proof is also test-only rather than a direct after-fix runtime transcript.

## What This Changes

The branch replaces the cron quarantine sidecar’s unbounded read with an 8 MiB bounded read, caps writes, and rotates an overflowing sidecar into timestamped recovery archives.

## Best Possible Solution

Keep the bounded reader, then make archive lifecycle explicit: surface retained quarantine archives through Doctor and provide a deliberate, documented operator cleanup action, or obtain maintainer approval for a tested retention policy.
