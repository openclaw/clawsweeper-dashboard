## Summary

This PR remains necessary because current main still uses a broad credential detector that can diverge from the provider runtime contract. The latest branch is technically sound, well-proven, and has no actionable correctness finding, but it needs explicit maintainer acceptance of the new audit-time external plugin execution boundary before merge.

## What This Changes

The PR makes web-search credential auditing honor plugin policy and provider-specific configured values, environment variables, auth profiles, keyless contracts, and fallback hooks, while adding guarded loading of external plugin light artifacts.

## Best Possible Solution

Keep the policy-filtered, provider-owned credential implementation if plugin or security ownership approves audit-time root-confined light-artifact execution; otherwise expose configured credential semantics through a metadata-only manifest or Plugin SDK contract so the audit remains non-executing.
