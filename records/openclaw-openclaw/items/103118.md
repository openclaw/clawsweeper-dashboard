## Summary

The previous external-provider finding is fixed, but the current head still narrows the public plugin credential contract: selected external providers are recognized only through hard-coded `apiKey` or `baseUrl` fields, while runtime supports arbitrary configured credential fields through `getConfiguredCredentialValue`. This is a merge-blocking compatibility and security-audit false-negative risk.

## What This Changes

The PR replaces broad web-search credential detection with policy-filtered, provider-aware checks for common config values, environment variables, auth profiles, keyless providers, and configured fallbacks.

## Best Possible Solution

Evaluate the selected provider through its light public configured-value contract, including arbitrary fields, while preserving plugin policy, origin boundaries, and cold control-plane loading.
