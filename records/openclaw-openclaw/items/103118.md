## Summary

The final head fixes the previously reported provider-scoping gaps, but it reconstructs plugin policy differently from the existing bundled-provider compatibility resolver. With deprecated `plugins.bundledDiscovery: "compat"`, runtime intentionally admits bundled providers outside `plugins.allow`, while this audit filters them out and can under-report web-search exposure.

## What This Changes

The PR rewrites web-search credential presence auditing to apply selected-provider scoping, plugin policy, SecretRef semantics, keyless-provider contracts, and provider-specific manifest environment credentials, with expanded regression coverage.

## Best Possible Solution

Build credential-audit eligibility from the same compatibility-resolved bundled provider candidates used by public-artifact/runtime resolution, then apply the PR’s provider-specific credential checks and add an audit/runtime parity regression for `plugins.bundledDiscovery: "compat"`.
