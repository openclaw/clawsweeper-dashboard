## Summary

The policy-scoping correction is useful, but the unchanged head still narrows a shipped public plugin credential contract: runtime accepts provider-defined configured fields through `getConfiguredCredentialValue`, while the audit recognizes only `apiKey` and `baseUrl`. A runtime-usable external provider can therefore be audit-negative, so the focused contract-parity repair from the prior review remains necessary.

## What This Changes

The PR replaces broad web-search credential detection with policy-filtered, provider-aware checks for config values, environment variables, auth profiles, keyless providers, external providers, and configured fallbacks, plus expanded regression tests.

## Best Possible Solution

Evaluate policy-eligible selected providers through the light public `getConfiguredCredentialValue` contract—or expose one shared light credential-eligibility helper used by runtime and audit—while preserving origin filtering, lazy loading, SecretRef semantics, auth profiles, keyless rules, and configured fallbacks.
