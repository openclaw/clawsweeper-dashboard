## Summary

The latest commit fixes the prior Gemini-versus-Vertex finding and the PR has strong real audit proof, but one merge-blocking false positive remains: an explicit unknown provider with a top-level API key is reported as usable even though the canonical runtime refuses that provider without fallback.

## What This Changes

The PR rewrites web-search credential-presence auditing to apply selected-provider scope, plugin enable/allow/deny policy, SecretRef resolution, keyless-provider contracts, and provider-specific environment variables, with expanded regression coverage.

## Best Possible Solution

Require an explicit provider id to resolve to an active, policy-allowed provider contract before any top-level or nested credential counts, and keep the audit as a light projection of canonical provider credential facts.
