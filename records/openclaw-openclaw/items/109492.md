## Summary

Keep this PR open for a narrow repair: the reported unbounded retention is valid and the supplied proof is convincing, but the current patch can evict a second, unrelated retained run when a terminal event arrives for an already-evicted run.

## What This Changes

The PR caps the TUI stream assembler at 200 tracked runs, refreshes active runs in insertion order, and adds focused eviction coverage.

## Best Possible Solution

Retain the 200-entry LRU cap, but let finalization of an absent run use untracked temporary state so it cannot evict another retained stream, with regression coverage for that late-terminal sequence.

## Solution Assessment

No, not yet. Capping state in the assembler is the correct owner boundary, but pruning should occur only when tracking new streaming state rather than while constructing temporary state for a late final.
