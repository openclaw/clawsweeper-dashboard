## Summary

Keep open: current main and the latest release still do not provide one admin-facing inventory for approved WhatsApp contacts with merged DM/group permission state and last-active data. Existing pairing, directory, channel-status, and in-chat `/allowlist` surfaces cover pieces, so this remains a product/security design item rather than conservative cleanup.

## What This Changes

Request a new admin-facing CLI/contact inventory for WhatsApp paired contacts showing sender IDs, DM and group permission state, and last activity without manually editing `openclaw.json`.

## Best Possible Solution

Define one account-scoped admin inventory and management surface that coordinates pairing-store approvals, configured DM/group allowlists, directory identity lookup, and activity data with explicit redaction and privacy semantics.

## Reproduction Assessment

Yes, at source level. Current `pairing list`, `directory peers list`, `channels status`, and `/allowlist` do not expose one approved WhatsApp contact inventory with merged permission state and per-contact last-active data.

## Solution Assessment

Unclear until maintainers choose the product and security semantics. A CLI inventory is plausible, but it should be account-scoped and coordinated with https://github.com/openclaw/openclaw/issues/56621 and `/allowlist` rather than adding a second partial permission surface.
