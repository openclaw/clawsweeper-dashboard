## Summary

Keep open: current main and v2026.6.11 still do not provide one terminal/admin inventory for approved WhatsApp contacts with merged DM/group permission state and last-active data. Existing `pairing list`, `channels status`, `directory peers list`, and in-chat `/allowlist` cover pieces, but the requested security-sensitive admin surface still needs maintainer product decisions.

## What This Changes

Request an admin-facing way to list and manage approved WhatsApp contacts with sender ID, DM/group policy, and last-active data without editing `openclaw.json`.

## Best Possible Solution

Define one account-scoped admin inventory and permission-management surface that coordinates approved-pairing state, configured allowlists, group policy, directory lookup, and redacted activity metadata.

## Reproduction Assessment

Yes. Source inspection shows current `pairing list`, `channels status`, `directory peers list`, and `/allowlist` do not expose one approved WhatsApp contact inventory with merged permission state and last-active data.

## Solution Assessment

Unclear until maintainers choose the product and security semantics. A CLI/admin inventory is plausible, but it should avoid creating a second partial permission-management surface beside `/allowlist` and https://github.com/openclaw/openclaw/issues/56621.
