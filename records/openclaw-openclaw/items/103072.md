## Summary

Keep this PR open, but it is not merge-ready: the current head still routes stop/cancel behind the same FIFO held by a one-shot PTT capture, and the external PR still lacks real iOS simulator/device behavior proof.

## What This Changes

The PR wraps iOS Talk invokes in a cancellation-aware FIFO, adds task-cancellation cleanup for one-shot push-to-talk, and refreshes native i18n source-line inventory.

## Best Possible Solution

Keep one canonical iOS PTT ownership path, but narrow the serialization so queued starts/one-shots are cancellation-aware while stop/cancel can interrupt an active capture; add focused regression coverage plus redacted simulator/device proof.

## Solution Assessment

No. The safer fix is to serialize capture preparation and stale queued starts/one-shots while keeping stop/cancel as interrupt paths, matching the Android sibling invariant instead of holding one FIFO across the full capture.
