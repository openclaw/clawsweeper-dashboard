## Label Justifications

- `P1`: Both supported managed-browser upload workflows deterministically invoke ordinary site handlers twice and can repeat user-visible processing.
- `impact:other`: Duplicate upload events can cause repeated file processing, submissions, network requests, or UI state transitions.

## Summary

Current `main` still has the deterministic duplicate-event behavior, Playwright 1.61.1 confirms the extra dispatches are redundant, and no separate fix PR or canonical issue currently owns the repair.

## What This Changes

Remove duplicate manual `input` and `change` dispatches from the direct-input and armed file-chooser browser upload flows.

## Best Possible Solution

Make Playwright the sole upload event owner by deleting both redispatch blocks and add browser-level regression coverage proving exactly one trusted `input` and one trusted `change` event for each upload mode.
