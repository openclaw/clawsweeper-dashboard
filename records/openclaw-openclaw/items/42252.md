## Summary

Keep open: current main has separate gateway health, service drift, daemon runtime, and Telegram polling diagnostics, but it still lacks the requested single consolidated doctor verdict and ordered recovery path for mixed LaunchAgent/runtime states.

## What This Changes

The issue requests clearer doctor/gateway diagnostics for mixed LaunchAgent, runtime, service-drift, and duplicate-poller states.

## Best Possible Solution

Define a doctor-owned diagnosis model that combines RPC reachability, service loaded/runtime PID, service config drift, port or duplicate-service clues, and channel conflict warnings into one final verdict with ordered next steps.
