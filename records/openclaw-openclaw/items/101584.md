## Summary

Keep open: the linked bug is real and the PR is focused, but the patch is incomplete because real wake-now cron runs can fall through the queued heartbeat dispatcher, which still rejects main when explicit heartbeat agents omit it.

## What This Changes

The PR bypasses per-agent heartbeat enable and interval gates in `runHeartbeatOnce` for `source: "cron"` and adds a cron service test around main wake success.

## Best Possible Solution

Carry the cron wake exception through both direct and queued heartbeat paths, preserve the global disable gate, and add a real-path regression for explicit heartbeat agents where main has no heartbeat block.
