## Summary

Keep open. Current main still lacks a generic action-aware tool policy: the config contract and matcher operate on whole tool names, while `message` and `gateway` still dispatch individual actions only after the tool has passed policy admission.

## What This Changes

Request action-level tool allow/deny so operators can block side-effecting actions such as `message` sends while preserving read-only actions on the same tool.

## Best Possible Solution

Keep this as the canonical core tracker and design a typed, documented action-aware policy contract enforced before multiplexed actions execute, with explicit precedence and trusted-context semantics for `message` and `gateway`.
