## Summary

Keep open. Current main and the latest release still lack a generic action-aware `tools.allow`/`tools.deny` contract; the existing `tools.message.actions.allow` path is message-specific and does not cover gateway sub-actions or approved-send bypass semantics.

## What This Changes

Request a generic action-aware tool policy so operators can deny specific message or gateway actions while keeping safer read-only actions available.

## Best Possible Solution

Define one typed, documented action-aware tool-policy contract, enforce it before multiplexed actions execute, and cover both `message` and `gateway` read/write splits with security-focused tests.
