## Summary

Keep open. Current main has a message-specific `tools.message.actions.allow` mitigation, but the requested generic action-level `tools.allow`/`tools.deny` contract is still missing for entries like `message:send` and `gateway:config.patch`, and the trusted approved-send bypass semantics remain a maintainer security decision.

## What This Changes

The issue requests action-level tool policy so operators can block side-effecting actions such as message sends while preserving read/search/react actions.

## Best Possible Solution

Keep this as the canonical core tracker for a maintainer-approved, typed action-aware tool-policy contract enforced before multiplexed actions execute, with documented precedence and trusted-context tests for `message` and `gateway`.
