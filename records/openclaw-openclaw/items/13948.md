## Summary

Keep open. Current main and the latest release still expose whole-tool policy only, so action-aware deny remains missing and needs maintainer security/product design before implementation.

## What This Changes

The issue requests action-level tool deny policy so multiplexed tools such as `message` and `gateway` can block write actions while keeping read actions available.

## Best Possible Solution

Keep this as the canonical core tracker and design a typed action-aware tool-policy contract with explicit grammar, wildcard behavior, precedence, trusted-context semantics, docs, and regression coverage for `message` and `gateway`.
