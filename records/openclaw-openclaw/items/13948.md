## Summary

Keep open. Current main has a message-specific `tools.message.actions.allow` allowlist, but the generic tool policy remains whole-tool only and still cannot express `message:send` or `gateway:config.patch` deny semantics across multiplexed tools.

## What This Changes

Request generic action-level tool policy so operators can deny actions like `message:send` or `gateway:config.patch` while preserving other actions on the same tool.

## Best Possible Solution

Keep this as the canonical core tracker and design a typed action-aware policy contract enforced before multiplexed actions execute, with documented precedence, deny semantics, wildcard behavior, and trusted approval/bypass rules for message and gateway.
