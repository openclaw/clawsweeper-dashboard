## Summary

Keep open. Current main now has a message-specific `tools.message.actions.allow` mitigation, but the requested generic action-level tool policy is still missing for `tools.allow`/`tools.deny`, gateway actions, and trusted approved-send bypass semantics.

## What This Changes

The issue requests action-level tool allow/deny so operators can block side-effecting actions like `message:send` while preserving read-only actions.

## Best Possible Solution

Keep this as the canonical core tracker for a maintainer-approved, typed action-aware tool-policy contract enforced before multiplexed actions execute, with documented precedence and trusted-context tests for `message` and `gateway`.
