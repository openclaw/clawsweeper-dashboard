## Summary

Keep open. Current main and the latest release still lack a generic action-aware `tools.allow`/`tools.deny` contract; `tools.message.actions.allow` is a useful message-only partial path, but gateway action splits and trusted approval-bypass semantics remain unresolved.

## What This Changes

Request a generic action-level tool policy so operators can deny `message:send` or `gateway:config.patch` while preserving read and diagnostic actions.

## Best Possible Solution

Define a maintainer-approved typed action-aware tool-policy contract with documented grammar, wildcard behavior, precedence, and pre-execution enforcement for multiplexed tools.

## Reproduction Assessment

Yes. Source inspection shows generic policy is matched by whole tool name before action arguments are read, so `message:send` and `gateway:config.patch` cannot be expressed through `tools.deny` today.

## Solution Assessment

Unclear until maintainers choose the security model. The right direction is generic action-aware policy, but the exact grammar, precedence, and trusted-bypass semantics need product/security approval before implementation.
