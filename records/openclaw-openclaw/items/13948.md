## Summary

Keep open. Current main and the latest release have a message-specific `tools.message.actions.allow` mitigation, but the requested generic action-aware `tools.allow`/`tools.deny` policy, gateway action coverage, and approved-send bypass semantics are still missing.

## What This Changes

Request a generic action-level tool policy so operators can deny side-effecting actions such as `message:send` while keeping read-only actions available.

## Best Possible Solution

Keep this as the canonical core tracker for a maintainer-approved action-aware tool-policy contract, enforced before multiplexed actions execute and covered for `message` and `gateway` read/write splits.
