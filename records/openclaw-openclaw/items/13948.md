## Summary

Keep open. Current main and v2026.6.11 still lack the requested generic action-aware `tools.allow`/`tools.deny` contract; the shipped `tools.message.actions.allow` path is a message-specific allowlist and does not cover gateway actions or trusted approved-send semantics.

## What This Changes

Request action-level tool policy so operators can deny side-effecting actions like `message:send` while preserving read-only actions on the same multiplexed tool.

## Best Possible Solution

Keep this as the canonical core tracker for a maintainer-approved action-aware tool-policy contract, enforced before multiplexed actions execute and covered for `message` and `gateway` read/write splits.
