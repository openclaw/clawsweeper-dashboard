## Summary

Keep open. Current main and v2026.6.11 still lack generic action-level `tools.allow`/`tools.deny`; the newer `tools.message.actions.allow` surface is only a message-specific allowlist and does not cover gateway actions or trusted approved-send semantics.

## What This Changes

Request action-level allow/deny for multiplexed tools such as `message` and `gateway`, including a privileged approved-send path.

## Best Possible Solution

Define a maintainer-approved typed action-aware tool-policy contract with documented grammar, precedence, wildcard behavior, trusted-context rules, and enforcement before multiplexed `message` and `gateway` actions execute.

## Solution Assessment

Unclear until maintainers choose the security model. The maintainable direction is a generic action-aware policy contract and enforcement boundary, not another one-off message or gateway shim.
