## Summary

Keep open: this PR remains the active, focused candidate fix for a real QQBot outbound-delivery regression, but the resolver-selection and reconnect-drain semantics are compatibility-sensitive enough that a maintainer should explicitly accept them before merge.

## What This Changes

The PR adds operation-aware outbound delivery resolution for text and poll sends, routes direct delivery and gateway poll through it, and drains QQBot pending deliveries from reconnect callbacks.

## Best Possible Solution

Merge the focused bug fix after a maintainer accepts the compatibility-sensitive resolver selection and QQBot reconnect replay semantics and required checks are green.

Yes at source level: current main still uses capability-blind outbound resolution in send, poll, and direct-delivery paths, and the linked issue provides live QQBot reconnect logs. I did not run a fresh live QQBot 4009 timeout in this read-only review.

## Solution Assessment

Yes, this appears to be the best fix shape pending maintainer acceptance: splitting send delivery resolution from shared action/read resolution keeps non-send callers intact while aligning send, direct delivery, and gateway poll paths. The safer alternative would be to narrow the resolver change further only if maintainers reject the compatibility tradeoff.
