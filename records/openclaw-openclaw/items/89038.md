## Summary

Keep open for owner review: the patch is coherent, live-proven, and has no discrete correctness finding, but it changes both shared plugin-selection semantics and QQBot reconnect retry timing, which require an explicit maintainer merge-risk decision.

## What This Changes

The PR adds operation-aware outbound plugin resolution for text and poll delivery, aligns direct delivery with that resolver, and drains matching QQBot queued deliveries after READY or RESUMED.

## Best Possible Solution

Use one capability-aware resolver as the canonical text and poll delivery path, and retain QQBot reconnect replay only with an owner-approved, narrowly justified rule for which proven-pre-send failures may bypass normal queue backoff.
