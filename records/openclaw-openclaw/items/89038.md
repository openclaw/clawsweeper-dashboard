## What This Changes

This PR adds operation-aware outbound delivery resolution for text and poll sends, routes direct/gateway delivery through it, and drains matching QQBot pending deliveries on ready/resumed reconnect callbacks.

## Best Possible Solution

Land this PR or a maintainer-approved equivalent after owner acceptance of the selector and reconnect-drain semantics, then close the linked user report with merge provenance.

## Solution Assessment

Is this the best way to solve the issue? Yes, likely: the PR keeps the shared resolver for action/read callers while adding a delivery-only selector for send paths, which is safer than globally gating the existing resolver.
