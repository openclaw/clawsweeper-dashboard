Question: Should enabled tool titles be restricted to a utility model on the session's provider, or may an explicitly configured cross-provider utility model receive raw tool arguments?

Rationale: The canonical utility-model contract intentionally permits explicit cross-provider models, while this PR promises that commands and arbitrary plugin/MCP arguments never reach a provider the session was not already using; automation cannot choose that privacy and product boundary.

Likely owner: steipete

Owner confidence: high

Options:

- **Require same-provider titles (recommended):** Skip title generation when an explicit utility model resolves to another provider, preserving the documented no-new-egress guarantee.
- **Allow configured cross-provider egress:** Honor explicit cross-provider utility models but clearly disclose in config help and docs that enabling titles sends tool arguments to that configured provider.
- **Keep deterministic rendering:** Decline the provider-backed title surface and retain current main's deterministic tool rows.

## Reproduction Assessment

Yes for the two remaining review defects: current source and tests establish the cross-provider contract mismatch, and the title queue has no callback registration or broadcast for every affected pane. The requested opt-in capability itself is a feature, not a bug reproduction.

## Solution Assessment

No in its current form. Default-off gating is a reasonable safety shape, but the implementation contradicts its provider-privacy promise and does not reliably deliver arriving titles to all rendered panes.
