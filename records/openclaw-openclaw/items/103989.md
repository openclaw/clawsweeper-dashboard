## Summary

The current head still has four concrete correctness and safety blockers: the documented same-provider boundary is not enforced, session provider overrides can inherit the wrong auth profile, cached titles outlive gateway changes, and identical shared calls still drop a pane repaint waiter. The opt-in design is safer than the removed always-on version, but this protected feature PR also needs explicit product approval and current-head live proof before merge.

## What This Changes

Adds a default-off `gateway.controlUi.toolTitles` option, a `chat.toolTitles` gateway RPC with utility-model generation and per-agent SQLite caching, and Control UI rendering of generated purpose titles for complex tool calls, with protocol, docs, generated Swift models, and tests.

## Best Possible Solution

Keep deterministic rendering as the default, then enforce or explicitly redefine the provider-egress contract, normalize utility-model profiles to the session credential context, scope browser title state and waiters to the active gateway, and prove both disabled and enabled behavior on the repaired current head.
