## Summary

Keep open: this PR is a focused, viable candidate fix for the open Discord default-account SecretRef restart-loop issue, and current main still has the collector/runtime mismatch. I found no blocking code findings, but merge remains maintainer-owned because it intentionally makes top-level Discord tokens active as the implicit default account when named accounts exist.

## What This Changes

The PR adds Discord-owned implicit default-account SecretRef collection and a file-backed runtime snapshot regression test for default plus named Discord accounts.

## Best Possible Solution

Land the Discord-owned collector fix once maintainers accept that top-level Discord tokens remain active as the implicit default account and required checks stay green.

## Reproduction Assessment

Yes. Source inspection shows current main can skip materializing channels.discord.token when explicit named accounts all provide their own token, while Discord still lists a configured top-level token as an implicit default account and fails closed if that token remains an unmaterialized SecretRef.

## Solution Assessment

Yes. The Discord-owned secret contract is the right layer because shared helper behavior remains generic and a sibling Feishu fix uses the same channel-owned pattern; a runtime token fallback would create a second credential source of truth.
