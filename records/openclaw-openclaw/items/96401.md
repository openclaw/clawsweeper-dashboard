## Summary

Keep open for maintainer review: the patch appears correct and proof-backed, but it intentionally changes Discord multi-account SecretRef activation and needs maintainer acceptance of that compatibility risk before merge.

## What This Changes

The PR adds Discord-only implicit default-account handling to Discord SecretRef collection and a file-backed runtime snapshot regression test for default plus named accounts.

## Best Possible Solution

Land the Discord-owned SecretRef collector fix after maintainer acceptance of the compatibility change and normal merge gates; keep the linked issue open until the PR merges.

## Reproduction Assessment

Yes. Current main can skip materializing channels.discord.token when explicit named accounts all provide tokens, while Discord still lists a configured top-level token as an implicit default account and startup throws if that SecretRef remains configured_unavailable.

## Solution Assessment

Yes. The PR fixes the Discord-owned SecretRef collection boundary to match Discord account listing, matching the Feishu precedent and avoiding a shared helper semantic change or runtime token fallback.
