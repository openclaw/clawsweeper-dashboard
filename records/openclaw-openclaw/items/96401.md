## Summary

Keep open: current main still has the Discord implicit-default SecretRef materialization gap, and this PR is the live candidate fix for https://github.com/openclaw/openclaw/issues/92985. ## What This Changes

The PR changes Discord SecretRef collection so a top-level Discord token remains active as the implicit default account when named Discord accounts are configured, and adds a file-backed runtime snapshot regression test.

## Best Possible Solution

Land the Discord-owned SecretRef collector fix after maintainer acceptance of the compatibility semantics and normal merge gates.

## Reproduction Assessment

Yes. Source inspection shows current main can skip materializing channels.discord.token when explicit named accounts all provide token values, while Discord still lists that top-level token as an implicit default account and fails closed if it remains an unmaterialized SecretRef.

## Solution Assessment

Yes. The PR fixes the Discord-owned SecretRef collection boundary to match Discord account listing, and that is narrower than changing the shared helper contract or adding a runtime token fallback.
