## Summary

Keep open for maintainer review: current main still skips top-level Discord SecretRef materialization in the named-account shape, while this PR aligns the Discord secret contract with existing implicit-default account listing and has no blocking code findings; the remaining issue is the intentional compatibility risk.

## What This Changes

The PR adds Discord-only implicit default-account SecretRef collection and a file-backed regression test so a top-level Discord token is materialized when named accounts are configured.

## Best Possible Solution

Land the Discord-owned SecretRef collector fix after maintainers accept the compatibility change and normal merge gates pass.

## Solution Assessment

Yes. The PR fixes the Discord-owned secret contract, matching account listing and a Feishu precedent, without changing the shared helper public signature or adding runtime token fallbacks.
