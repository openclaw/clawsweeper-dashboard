## Summary

Keep open for maintainer review: this is a focused, source-backed candidate fix for the linked P1 Discord SecretRef regression, and I found no blocking code or security finding. The remaining issue is compatibility review because the PR intentionally keeps a top-level Discord token active as the implicit default account when named accounts exist.

## What This Changes

The PR adds Discord-owned implicit default-account handling to SecretRef runtime collection and a file-backed regression test for default plus named Discord accounts.

## Best Possible Solution

Land this Discord-owned collector fix after maintainers accept the implicit-default compatibility change and normal merge gates pass.

## Reproduction Assessment

Yes. Source inspection shows current main can skip materializing channels.discord.token when explicit named accounts all provide tokens, while Discord still treats a configured top-level token as an implicit default account and fails closed if that token remains an unmaterialized SecretRef.

## Solution Assessment

Yes. The PR fixes the Discord-owned SecretRef collection boundary, matches existing runtime account-listing semantics, and avoids both a shared helper API change and a runtime token fallback.
