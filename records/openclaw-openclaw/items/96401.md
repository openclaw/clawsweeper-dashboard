## Label Justifications

- `P1`: The PR targets a linked P1 Discord regression where adding a named account can take the existing default account offline.
- `merge-risk: 🚨 compatibility`: The diff makes a configured top-level Discord token active as an implicit default account when named accounts exist, which can expose stale SecretRefs during upgrade.

## Summary

Keep open: the patch appears correct and still necessary because current main and v2026.6.11 still skip the implicit default Discord token SecretRef once named accounts are present; the remaining decision is maintainer acceptance of the compatibility-sensitive Discord active-surface change.

## What This Changes

The PR adds Discord-owned SecretRef collection for an implicit default account when a top-level Discord token coexists with named accounts, plus a file-backed runtime snapshot regression test.

## Best Possible Solution

Land the Discord-owned collector fix after maintainers accept the compatibility behavior, because it aligns SecretRef materialization with the existing Discord account-listing contract.

## Reproduction Assessment

Yes. Source inspection shows current main can skip materializing channels.discord.token when explicit named accounts provide their own tokens, while Discord still lists the configured top-level token as an implicit default account and fails startup if it remains configured_unavailable.

## Solution Assessment

Yes. The PR fixes the Discord-owned SecretRef collection boundary to match Discord account listing, avoiding both a shared helper API change and a runtime token fallback.
