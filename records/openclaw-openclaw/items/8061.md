## Summary

Keep open: current main and v2026.6.11 still only enforce a global subagent concurrency cap, while the requested per-target-agent cap needs maintainer-approved config and scheduler semantics.

## What This Changes

The issue requests an optional per-agent subagent concurrency limit so a fragile target such as a local TTS agent can serialize runs while other subagents remain parallel.

## Best Possible Solution

Add a maintainer-approved per-target subagent cap, likely agents.list[].subagents.maxConcurrent, validate it in schema/types/help/docs, and enforce it for both native and ACP spawns alongside the existing global cap.
