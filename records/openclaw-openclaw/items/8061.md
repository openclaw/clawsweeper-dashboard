## Summary

Keep open: current main and v2026.6.11 still provide only a shared subagent concurrency cap plus a requester-session child cap; neither limits concurrent runs by target agent, and no merged or viable canonical replacement owns that distinct requirement.

## What This Changes

Add a configurable concurrency limit keyed by the target agent used for subagent execution.

## Best Possible Solution

Add one validated `agents.list[].subagents.maxConcurrent` policy and enforce it through a shared target-agent reservation mechanism used by native and ACP spawns, while retaining the global safety pool and requester-session child cap.
