## Summary

Keep open: current `main` and v2026.6.11 still only provide a global subagent concurrency cap and fixed `subagent` lane, while this request asks for a target-agent-specific cap with confirmed user demand.

## What This Changes

The issue requests a per-target-agent subagent concurrency cap in `agents.list` so one fragile/local subagent can be serialized without globally limiting all spawned subagents.

## Best Possible Solution

Add a maintainer-approved per-target subagent cap, likely under `agents.list[].subagents`, and enforce it alongside the global cap for both native and ACP spawns with schema, docs, and focused regression tests.

## Reproduction Assessment

Yes, at source level: current main has a strict per-agent schema with no target cap, one global subagent concurrency resolver, and fixed native/ACP dispatch to the `subagent` lane. I did not run a live TTS/local-model workload because the requested config surface does not exist.

## Solution Assessment

Unclear as originally proposed: the capability is well-scoped, but the public key should likely fit the existing `agents.list[].subagents.*` namespace and must compose with adjacent lane and scheduler controls.
