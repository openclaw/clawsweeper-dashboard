Keep open: current main and v2026.6.11 still expose only shared subagent concurrency controls, while this issue requests the distinct ability to serialize one resource-heavy target agent without restricting unrelated targets. A prior owner-side review also kept the request open, and no merged or viable related item owns this exact behavior.

## What This Changes

Add a configurable concurrency cap for runs targeting a specific subagent while allowing other target agents to remain parallel.

## Best Possible Solution

Add `agents.list[].subagents.maxConcurrent` as a target-agent keyed admission limit inside the existing global subagent cap, with one documented composition rule and focused native and ACP spawn coverage.
