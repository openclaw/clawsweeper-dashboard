## Summary

Keep open: current main still provides only one global subagent concurrency limit, while this request needs an additional limit keyed by the selected target agent; the related lane proposals overlap but do not establish that automatic per-target behavior. ([github.com](https://github.com/openclaw/openclaw/blob/main/src/config/agent-limits.ts))

## What This Changes

Add a per-agent subagent concurrency limit so a resource-heavy target agent can be serialized without throttling unrelated subagent targets.

## Best Possible Solution

Approve a narrow additive `agents.list[].subagents.maxConcurrent` policy, enforce it as a second target-keyed gate alongside the global subagent cap, and add schema/help/docs plus native and ACP regression coverage.
