## Summary

Keep open: current `main` and v2026.6.11 still provide only the global subagent concurrency cap, while the requested per-target-agent cap requires maintainer-approved config and scheduler semantics.

## What This Changes

The issue requests an optional per-agent subagent concurrency limit so one target agent, such as a local TTS agent, can serialize subagent runs without restricting all other subagents.

## Best Possible Solution

Add a maintainer-approved per-target subagent cap, likely under `agents.list[].subagents.maxConcurrent`, validate it in schema/types/help/docs, and enforce it for both native and ACP spawns alongside the existing global cap.

- **Fold into broader scheduler design:** Defer implementation until maintainers settle caller-selected subagent lanes and foreground per-agent lanes as one scheduler API.
- **Decline new config surface:** Keep only the global subagent cap and document local-model serialization workarounds, accepting that target-specific throttling remains unavailable.
