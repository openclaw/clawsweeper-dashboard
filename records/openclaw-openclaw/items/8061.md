## Summary

Keep open: current main and v2026.6.11 still expose only a shared subagent concurrency budget, while this issue asks for the distinct ability to serialize one resource-heavy target agent without throttling unrelated targets. The need is concrete and corroborated, but the public configuration owner and hierarchical scheduling semantics require maintainer approval before implementation.

## What This Changes

Add a per-target-agent concurrency limit so selected agents can serialize spawned runs while other subagents continue using the shared concurrency pool.

## Best Possible Solution

Add agents.list[].subagents.maxConcurrent as an optional target-agent budget that composes with the existing global subagent cap, with one shared admission abstraction used by native and ACP spawns plus focused serialization and parallelism coverage.

## Reproduction Assessment

## Solution Assessment
