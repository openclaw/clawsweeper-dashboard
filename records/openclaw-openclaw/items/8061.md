## Summary

Keep open: current main and v2026.6.11 still only expose a global subagent concurrency cap, while this issue asks for a target-agent-specific cap with concrete local-model demand and another user confirmation.

## What This Changes

Request to add an optional per-agent subagent concurrency limit so a target agent such as a local TTS worker can be serialized while other subagents remain parallel.

## Best Possible Solution

Add one maintainer-approved per-target-agent subagent cap, likely under agents.list[].subagents, and enforce it alongside the global cap for native and ACP sessions_spawn with schema, docs, and focused tests.

## Reproduction Assessment

Yes, at source level: current main has no typed or validated per-target subagent cap and routes native plus ACP spawns through one fixed subagent lane. I did not run a live TTS/local-model workload because the requested config surface does not exist.

## Solution Assessment

Unclear as originally proposed: the capability is well scoped, but the public key should likely fit the existing agents.list[].subagents.* namespace and must compose with related lane and scheduler controls.
