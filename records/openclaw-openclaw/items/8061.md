## Summary

Keep open: current main and the latest release still only provide a global subagent concurrency cap, while the requested per-target-agent cap is missing and needs maintainer-approved config and scheduler semantics.

## What This Changes

Request to add an optional per-agent subagent concurrency limit so a fragile target agent can be serialized while other subagents continue running in parallel.

## Best Possible Solution

Add a maintainer-approved per-target subagent cap, likely `agents.list[].subagents.maxConcurrent`, validate it in schema/types/help/docs, and enforce it for both native and ACP spawns alongside the existing global cap.
