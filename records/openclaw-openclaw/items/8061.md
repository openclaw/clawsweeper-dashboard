## Summary

Keep open: current main and v2026.6.11 still provide only shared subagent concurrency controls, while this request addresses the distinct need to serialize one resource-heavy target agent without restricting unrelated targets. The request remains concrete, has corroborating user feedback, and is not replaced by any merged or viable related item; implementation should wait for maintainer approval of the public configuration and scheduling contract.

## What This Changes

Add a per-target-agent subagent concurrency cap so resource-heavy agents can serialize independently of unrelated subagents.

## Best Possible Solution

Adopt one canonical hierarchical admission model: retain the global subagent safety cap, add a validated target-agent override under the existing per-agent `subagents` namespace, and enforce the effective minimum across native and ACP spawn paths with focused concurrency tests and documentation.
