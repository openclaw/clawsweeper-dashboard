## Summary

Keep open: current main still exposes only a shared subagent concurrency budget, while this issue requests the distinct ability to serialize one resource-heavy target agent without throttling unrelated targets. The use case is concrete and corroborated, but the public config shape and hierarchical admission semantics require maintainer approval.

## What This Changes

Add an optional per-agent configuration limit so subagent spawns targeting one agent can be capped independently of other target agents.

## Best Possible Solution

After maintainer approval, add `agents.list[].subagents.maxConcurrent` as a positive target-agent admission cap, require both the global and target-specific slots before starting a spawn, and test that one capped target serializes while unrelated targets retain parallelism.

## Solution Assessment
