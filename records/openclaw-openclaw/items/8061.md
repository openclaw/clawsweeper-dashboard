## Summary

Keep open: current main and v2026.6.11 still only provide a global subagent concurrency cap, while per-target-agent caps need maintainer-approved config and scheduler semantics.

## What This Changes

Request to add a per-agent subagent concurrency limit, such as an optional maxConcurrent field on agents.list entries, so one constrained target agent can serialize without limiting all subagents.

## Best Possible Solution

Add a maintainer-approved per-target subagent cap, likely agents.list[].subagents.maxConcurrent, validate it in schema/types/help/docs, and enforce it for both native and ACP spawns alongside the existing global cap.
