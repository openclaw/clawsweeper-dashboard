## Summary

Keep open: current main and v2026.6.11 still expose only a global subagent concurrency cap, while this issue asks for a target-agent-specific limit with confirmed user demand and unresolved public config semantics.

## What This Changes

The issue requests a per-target-agent subagent concurrency limit so one local or constrained subagent can serialize runs without limiting all other subagents.

## Best Possible Solution

Add one maintainer-approved, validated per-target-agent subagent cap, likely under agents.list[].subagents, and enforce it alongside the global cap for native and ACP spawns with docs and focused tests.

## Reproduction Assessment

Yes. Source inspection reproduces the missing capability: current main and v2026.6.11 have a strict per-agent schema with no target cap, one global subagent resolver, and one fixed subagent lane.

## Solution Assessment

Unclear as originally proposed. The capability is well-scoped, but the public key should likely fit the existing agents.list[].subagents.* namespace and must compose with related lane and scheduler controls.
