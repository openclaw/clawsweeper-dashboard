## Summary

Keep open: current main and v2026.6.11 still expose only a global subagent concurrency cap, while this request needs a maintainer-approved target-agent cap and public scheduler/config semantics.

## What This Changes

Request to let a configured target agent, such as a local TTS subagent, set its own subagent concurrency cap while other subagents remain parallel.

## Best Possible Solution

Add a maintainer-approved per-target subagent cap, likely agents.list[].subagents.maxConcurrent, validate it in schema/types/help/docs, and enforce it for both native and ACP spawns alongside the existing global cap.
