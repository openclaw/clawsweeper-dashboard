## Summary

Keep open: current main and v2026.6.11 still only expose a global subagent concurrency cap, while the requested per-target-agent cap remains missing and needs maintainer-approved config and scheduler semantics.

## What This Changes

Request adding a per-target-agent subagent concurrency cap in `agents.list` so one constrained subagent can serialize while other subagents remain parallel.

## Best Possible Solution

Add a maintainer-approved per-target subagent cap, likely `agents.list[].subagents.maxConcurrent`, validate it in schema/types/help/docs, and enforce it for both native and ACP spawns alongside the existing global cap.
