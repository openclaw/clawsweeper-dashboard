## Summary

Keep open: current main and v2026.6.11 still provide only the global subagent concurrency cap, while this request needs a maintainer-approved per-target-agent cap and scheduler/config contract.

## What This Changes

Add an optional per-agent subagent concurrency limit so one target agent, such as a local TTS agent, can serialize its own spawned runs without constraining other subagents.

## Best Possible Solution

Add a maintainer-approved per-target subagent cap, likely agents.list[].subagents.maxConcurrent, validate it in schema/types/help/docs, and enforce it for both native and ACP spawns alongside the existing global cap.
