## Summary

Keep open: current main still exposes one shared subagent concurrency budget, while this issue requests the distinct ability to serialize work targeting one resource-heavy agent without throttling unrelated targets. Related concurrency reports address caller-selected lanes, inbound agent lanes, parent caps, or lifetime totals rather than this per-target limit. citeturn7view0turn7view1turn18view0

## What This Changes

Add an optional per-agent subagent concurrency limit under `agents.list[]` so selected target agents can serialize while other targets remain parallel.

## Best Possible Solution

After product approval, add a validated `agents.list[].subagents.maxConcurrent` target-agent cap that composes with the existing global safety budget, applies consistently to native and ACP spawn paths, and includes schema/help/docs plus focused serialization and cross-target parallelism tests.
