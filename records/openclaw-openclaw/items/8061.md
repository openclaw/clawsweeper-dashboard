## Summary

Keep open: current main still only has a global `agents.defaults.subagents.maxConcurrent` cap and fixed `subagent` lane, while this issue asks for a target-agent-specific cap with confirmed user demand.

## What This Changes

The issue requests an optional per-agent subagent concurrency cap so one target agent can be serialized without limiting all other subagents.

## Best Possible Solution

Add one validated per-target-agent subagent cap that composes with the existing global `subagent` safety valve and applies consistently to native and ACP spawns.

## Reproduction Assessment

Yes, at source level: current main has a strict per-agent schema with no target cap, one global subagent resolver, and fixed native/ACP dispatch to the `subagent` lane. I did not run a live TTS/local-model workload.

## Solution Assessment

Unclear as originally proposed: the capability is useful, but the public key likely belongs under the existing `agents.list[].subagents.*` namespace and needs maintainer product approval.
