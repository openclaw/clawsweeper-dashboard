## Summary

Keep open: current main and v2026.6.11 still expose only a process-wide subagent concurrency cap, while this issue asks for a target-agent-specific cap with confirmed user demand and no merged canonical fix.

## What This Changes

The issue requests a per-agent subagent concurrency limit so a constrained target agent, such as a local TTS agent, can be serialized without limiting all subagent work globally.

## Best Possible Solution

Add one validated per-target-agent subagent cap, likely under `agents.list[].subagents`, and enforce it alongside the global cap for native and ACP spawns with docs and focused concurrency tests.

## Reproduction Assessment

Yes, at source level: current main has a strict per-agent schema with no target cap, one global subagent resolver, and a fixed `subagent` lane. I did not run a live TTS/local-model workload because the requested config surface does not exist.

## Solution Assessment

Unclear as originally proposed: the capability is well-scoped, but the public key should likely fit the existing `agents.list[].subagents.*` namespace and must compose with related lane and scheduler controls.
