## Summary

Keep open: current main and the latest release still only support a global subagent concurrency cap, while this issue asks for a target-agent-specific cap with confirmed user demand.

## What This Changes

Request a per-configured-agent subagent concurrency limit so constrained targets such as a local TTS agent can serialize while other subagents remain parallel.

## Best Possible Solution

Add a maintainer-approved per-target subagent cap, likely under agents.list[].subagents, with schema/types/docs and native plus ACP enforcement alongside the existing global cap.

## Reproduction Assessment

Yes, at source level: current main has a strict per-agent schema with no target cap, a global-only subagent concurrency resolver, and fixed native/ACP dispatch to the subagent lane. I did not run a live TTS/local-model workload because the requested config surface does not exist.

Unclear as originally proposed: the capability is well-scoped, but the public key should likely fit the existing agents.list[].subagents.* namespace and must compose with adjacent scheduler controls.
