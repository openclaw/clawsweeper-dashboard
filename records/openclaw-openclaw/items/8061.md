## What This Changes

Add an optional per-agent subagent concurrency limit so a selected destination agent can run serially while other subagents continue to use the existing global pool concurrently.

## System Context

OpenClaw routes `sessions_spawn` work through subagent scheduling and command-queue lanes. Configuration supplies the global subagent cap today; the requested behavior would add a destination-agent-specific constraint before work reaches the shared queue.

## Architecture Diagram

flowchart LR
  A[Agent requests subagent work] --> B[Spawn routing]
  B --> C[Destination agent configuration]
  C --> D[Per-agent limit decision]
  D --> E[Global subagent lane]
  E --> F[Command queue]
  F --> G[Subagent run]

## Best Possible Solution

Define one validated per-destination-agent subagent policy under the existing per-agent `subagents` namespace, retain the global cap as an upper bound, document the effective-limit rule, and add focused native and ACP scheduling tests.
