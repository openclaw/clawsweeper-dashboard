## Summary

Current main and v2026.6.11 still lack concurrency control keyed by the spawned target agent, and no merged or viable canonical replacement owns that distinct requirement. The issue should remain open for maintainer approval of the public configuration shape and limit-composition semantics.

## What This Changes

Add a configurable concurrency limit for subagent runs grouped by the spawned target agent without restricting unrelated targets.

## Best Possible Solution

Add `agents.list[].subagents.maxConcurrent` and enforce a shared target-agent admission limit for native and ACP spawns while retaining the global lane and requester-session child cap.
