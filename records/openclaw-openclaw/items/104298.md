## Summary

Keep open for maintainer direction: current main has no hook-visible blocked-skill signal, but it also has no unified denied-invocation lifecycle matching the proposal. Skills are filtered before prompt and command exposure, so the requested event’s meaning and boundary must be defined before implementation.

## What This Changes

The issue requests a hook-visible structured event when an agent’s skill is excluded by allowlist, agent filter, or requirements checks.

## Best Possible Solution

Add an observation-only typed plugin hook for concrete named skill-resolution attempts, with a closed reason union and existing agent/session correlation, while keeping status discovery and snapshot construction side-effect free.
