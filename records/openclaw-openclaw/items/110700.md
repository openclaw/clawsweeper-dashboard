## Summary

Keep this PR open, but do not merge it as written: recognizing `memory_recall` makes Codex omit root `MEMORY.md` from bootstrap context even though the LanceDB tool searches its own vector store rather than that workspace file. The focused tests prove the bypass, not that the bypass preserves access to the file’s contents.

## What This Changes

The PR adds `memory_recall` to Codex workspace-memory tool recognition and adds focused tests asserting that a recall-only tool routes root `MEMORY.md` away from bounded bootstrap injection.

## Best Possible Solution

Keep root `MEMORY.md` injected unless the active memory implementation explicitly declares and proves that its recall interface indexes and can retrieve that workspace file; add an end-to-end assertion that the selected path still exposes the file’s content to a Codex turn.
