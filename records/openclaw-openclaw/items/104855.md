## Summary

This is a valid Feishu multi-agent notification problem, but the proposed raw-text validator is not implementation-ready: current main deliberately generates native mentions only from structured recipient data and preserves model-authored mention-like text literally, while an overlapping bot-to-bot PR is broad, conflicting, and not a safe canonical landing path. The issue should remain open for a Feishu owner to choose the permanent mention-intent contract.

## What This Changes

Requests configurable pre-send validation of Feishu group messages so malformed mention markup is blocked or warned before delivery.

## Best Possible Solution

Define one plugin-owned Feishu outbound mention capability with explicit recipient IDs and native `at` serialization, then add diagnostics only if they validate that typed intent rather than guessing from prose.
