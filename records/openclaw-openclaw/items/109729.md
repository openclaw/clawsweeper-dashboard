## Summary

The prior direct-reflection finding is addressed, but the replacement still attaches the native URL parser error, whose `input` property can retain the credential-bearing URL and leak through cause inspection or serialization.

## What This Changes

The PR converts malformed URL parser failures in the public plugin-SDK SSRF helper into a stable `Invalid URL` error and adds malformed-input and credential-reflection tests.

## Best Possible Solution

Throw a stable `Error("Invalid URL")` without the native parser error, or attach only a deliberately sanitized cause, and test the complete error graph for credential absence while leaving valid SSRF policy behavior unchanged.
