## Summary

This PR remains useful and has convincing real MCP cancellation proof, but the latest head still passes the long-lived run signal directly into every SDK request without detaching it after settlement; the prior lifecycle blocker therefore remains and can accumulate abort listeners across successful calls.

## What This Changes

The PR forwards agent-run abort signals through bundled MCP tool, resource, and prompt requests and excludes caller cancellations from server-failure backoff.

## Best Possible Solution

Use one shared request-scoped signal-forwarding helper that removes the parent abort listener in a finally block, apply it consistently to all five MCP request paths, and prove both cancellation delivery and zero listener accumulation after successful or failed settlement.
