Full review comments:

- **[P1] Require quote-author whenever adding a Signal quote timestamp:** `extensions/signal/src/send.ts:267-270`
  - body: `resolveSignalQuoteMetadata` can return a quote timestamp with no author for direct messages, and this branch then sends `quote-timestamp` without `quote-author`. signal-cli's JSON-RPC send path uses the same send command namespace, which throws when a quote timestamp lacks an author, so DM quote replies can fail instead of sending or falling back.
  - confidence: 0.9
- **[P2] Map quote metadata through Signal container sends:** `extensions/signal/src/send.ts:267-274`
  - body: This adds quote params before calling `signalRpcRequest`, but the container backend's `send` translation still forwards only message, styles, attachments, and timeout to `/v2/send`. Users configured for Signal REST container mode will get normal unquoted sends even though the PR claims native quote support.
  - confidence: 0.86
- **[P1] Keep null reply suppression out of the public SDK contract:** `src/plugin-sdk/reply-payload.ts:44-45`
  - body: Widening `OutboundReplyPayload.replyToId` to `string | null` makes null a new plugin-facing control signal across all normalized reply payload senders. That SDK/API direction needs explicit maintainer approval, docs, and compatibility tests; otherwise plugins and hooks get a second reply-target source of truth for a Signal-specific need.
  - confidence: 0.82
