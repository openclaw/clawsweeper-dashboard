## Summary

This is a well-supported QQBot regression report: released behavior converts remote URLs into bytes and uses the two-request media flow, while the reporter’s same-conversation control preserved image quality with QQ’s direct public-URL send. No merged fix or current-main evidence resolves the quality problem, so the issue remains necessary; implementation should pause only for the security and QQ API semantics decision.

## What This Changes

Restore quality-preserving delivery for tall or large QQBot images sent from eligible public remote URLs without weakening the existing URL-security boundary.

## Best Possible Solution

In the QQBot plugin, preserve the byte-upload path for local data but route validated public HTTP(S) image URLs through QQ’s native URL upload with srv_send_msg=true, return without the follow-up msg_type=7 request, and prove SSRF rejection, quota semantics, non-duplication, and tall-image fidelity with focused tests plus a live C2C comparison.

- **Keep indirect uploads:** Retain the current two-step path and pursue a different Tencent-supported lossless upload mechanism before changing URL forwarding.
