## What This Changes

Ensure repo-native PR preparation creates and reuses complete linked worktrees rather than inheriting a canonical checkout’s sparse paths.

## System Context

The `scripts/pr` workflow creates a linked worktree for reviewing and preparing a pull request, then runs mandatory build, check, and test gates there. A sparse inherited worktree can omit tracked files that build tooling imports, preventing otherwise valid PRs from reaching hosted validation.

## Architecture Diagram

  C[Review init command] --> D[PR linked worktree]
  B --> D
  D --> E[Prepare build and checks]
  E --> F[Hosted validation or merge readiness]
  D --> G[Tracked build inputs]
  G --> E

## Best Possible Solution

Make script-owned PR worktrees explicitly complete before prepare gates run, including reuse paths, and add a focused shell regression test that starts from an intentionally sparse canonical checkout and verifies required tracked files are present.
