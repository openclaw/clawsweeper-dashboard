## Summary

Keep this issue open: current main and v2026.6.11 still have memory-lancedb autoCapture sanitization for transport metadata and host-authored external-content wrappers, but there is no requested `captureFilter` option and no default capture-time rejection for `EXTERNAL_UNTRUSTED_CONTENT`-wrapped content. The remaining work is a security-sensitive product decision about whether this should be a host-owned default boundary or a new operator config surface.

## What This Changes

The issue requests source-based filtering for memory-lancedb `autoCapture`, especially excluding `EXTERNAL_UNTRUSTED_CONTENT`-wrapped external content from automatic memory storage.

## Best Possible Solution

Define the host-owned autoCapture trust boundary first: memory-lancedb should reject host-wrapped external content before trigger matching by default, or add `captureFilter` only if maintainers intentionally want operator-selectable filtering with tests and docs.

## Reproduction Assessment

Yes, at source level: current main has host-authored `EXTERNAL_UNTRUSTED_CONTENT` wrappers and memory-lancedb autoCapture still gates on sanitized user text plus trigger regexes without rejecting that wrapper boundary. I did not run a live exploit; the missing captureFilter/default rejection is directly visible in source and release inspection.

## Solution Assessment

Unclear as proposed: source-based autoCapture exclusion is the right mitigation area, but a user-configured `captureFilter` may be weaker and noisier than a host-owned default rejection of external-content wrappers. Maintainers should choose the security policy and config shape before implementation.
