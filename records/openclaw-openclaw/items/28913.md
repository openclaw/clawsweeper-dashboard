## Summary

Keep this issue open: current main and v2026.6.11 still lack a memory-lancedb captureFilter or default rejection of OpenClaw external-content wrappers, and the remaining action is a maintainer security/product decision rather than a cleanup-closeable item.

## What This Changes

The issue requests source-based filtering for memory-lancedb autoCapture so wrapped external content is not persisted as long-term memory.

## Best Possible Solution

Define the host-owned autoCapture trust boundary first; prefer default rejection of OpenClaw-authored external-content wrappers before trigger matching, with docs and regression tests, unless maintainers explicitly approve a captureFilter config surface.
