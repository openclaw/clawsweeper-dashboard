## Summary

Keep this issue open: current main and v2026.6.11 still lack a memory-lancedb source-wrapper gate or captureFilter option, and the remaining choice is a security/product boundary rather than conservative cleanup.

## What This Changes

The issue requests a memory-lancedb autoCapture filter that skips content wrapped in external untrusted-content markers before trigger-based memory storage.

## Best Possible Solution

Define the host-owned autoCapture trust boundary first; prefer default rejection of OpenClaw-authored external-content wrappers before trigger matching, with docs and regression tests, unless maintainers explicitly approve a captureFilter config surface.
