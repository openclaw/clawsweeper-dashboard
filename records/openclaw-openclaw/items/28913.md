## Summary

Keep open: current main and v2026.6.11 still lack a memory-lancedb captureFilter or default source-wrapper gate, and the related open issues are broader memory/provenance architecture trackers rather than replacements for this narrow autoCapture boundary.

## What This Changes

The issue requests source/tag-aware filtering for memory-lancedb autoCapture so wrapped untrusted external content is not persisted as long-term memory.

## Best Possible Solution

Define the host-owned autoCapture trust boundary first; prefer default rejection of OpenClaw external-content wrappers before trigger matching, with focused tests/docs, unless maintainers explicitly choose an opt-in captureFilter config surface.
