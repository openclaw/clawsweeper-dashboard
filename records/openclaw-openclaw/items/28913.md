## Summary

Keep this open: current main and v2026.6.11 still lack the requested `captureFilter` option or a default `EXTERNAL_UNTRUSTED_CONTENT` exclusion before memory-lancedb auto-capture trigger matching. The remaining work is security-sensitive product design because maintainers need to choose between a host-owned default trust boundary and a new operator config surface.

## What This Changes

Requested source-based filtering for memory-lancedb autoCapture so content wrapped as untrusted external input is not persisted as long-term memory.

## Best Possible Solution

Define the host-owned autoCapture trust boundary first: memory-lancedb should reject wrapped external content before trigger matching by default, or add explicit config only if maintainers intentionally want operator-selectable filtering with docs and tests.

## Reproduction Assessment

Yes, at source level: current main has host-authored external-content wrappers and memory-lancedb autoCapture still runs `shouldCapture` on sanitized user text without rejecting those wrappers or a `captureFilter` policy. I did not run a live exploit, but the missing boundary is visible in source and tests/docs do not define the requested behavior.

## Solution Assessment

Unclear as proposed: source-based filtering before trigger matching is the right mitigation area, but a user-configured `captureFilter` may be weaker and noisier than a host-owned default rejection of external-content wrappers. Maintainers should decide the security policy and config shape before implementation.
