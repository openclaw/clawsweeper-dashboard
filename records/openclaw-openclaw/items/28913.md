## Summary

Keep this issue open: current main still lacks a memory-lancedb source-wrapper gate or the requested captureFilter option, and the remaining choice is a security/product boundary rather than conservative cleanup.

## What This Changes

The issue requests source-aware filtering for memory auto-capture so externally wrapped untrusted content is not persisted as user memory.

## Best Possible Solution

Define the memory auto-capture trust boundary first; prefer default rejection of OpenClaw external-content wrappers before trigger matching unless maintainers explicitly choose a config knob.
