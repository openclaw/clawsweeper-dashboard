## Summary

Keep open: current main and v2026.6.11 still expose memory-lancedb auto-capture triggers and external-content wrappers, but no source-aware capture filter or durable source policy, and the security/config shape needs maintainer review rather than an autonomous cleanup close.

## What This Changes

Request to add source-based filtering for memory-lancedb autoCapture so wrapped untrusted external content is not stored as long-term memory.

## Best Possible Solution

Define a maintainer-approved source/provenance gate for memory-lancedb auto-capture, preferably host-authored rather than agent-controlled, with config/docs/tests only after the security and product boundary is settled.

## Reproduction Assessment

Yes, at source level: current main has external-content wrappers and memory-lancedb auto-capture triggers, but the capture path has no source-wrapper/provenance gate before storing triggered text. I did not run a live exploit because the missing behavior is visible in config, manifest, and auto-capture source.

## Solution Assessment

Unclear as proposed: a narrow captureFilter could reduce one ingress risk, but wrapper-name config is a string-boundary policy and may not cover derived untrusted content. The best fix needs maintainer security/product agreement on a host-authored source/provenance gate or alignment with the broader memory trust model.
