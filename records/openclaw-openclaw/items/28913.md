## Summary

Keep this issue open: current main and v2026.6.11 still lack a memory-lancedb capture filter or default external-wrapper rejection before autoCapture trigger matching, and the remaining choice is a security/product/config decision rather than conservative cleanup.

## What This Changes

The issue requests source-based filtering for memory-lancedb autoCapture so external-content-wrapped text is excluded from long-term memory persistence.

## Best Possible Solution

Settle the memory-layer security boundary first, then implement either default external-wrapper rejection or a narrowly documented plugin-local policy with aligned config schema, manifest metadata, docs, and regression coverage.

- **Add opt-in captureFilter config:** Implement the reporter's captureFilter shape while preserving current default behavior, trading compatibility for weaker safe defaults.
- **Defer to provenance design:** Keep this as part of the broader memory trust/provenance work and leave disable-autoCapture or explicit memory_store as the supported workaround for now.

## Reproduction Assessment

Yes, from source inspection: external-content wrappers are produced by current tool paths, while memory-lancedb autoCapture only sanitizes envelope metadata before running trigger regexes and has no captureFilter or wrapper-source gate. I did not run a live exploit because the source path is sufficient for this feature/security gap.

## Solution Assessment

Unclear until maintainers choose the security boundary. The requested opt-in captureFilter is plausible, but a default rejection of canonical external wrappers may better match OpenClaw's security-and-safe-defaults direction if compatibility impact is acceptable.
