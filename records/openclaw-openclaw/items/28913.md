## Summary

Keep this issue open: current main and v2026.6.11 still have host-authored external-content wrappers and memory-lancedb autoCapture, but no captureFilter option and no default rejection of EXTERNAL_UNTRUSTED_CONTENT-wrapped text before memory trigger matching. The remaining work is a security-sensitive product decision about whether this should be a host-owned default boundary or an operator config surface.

## What This Changes

The issue requests source-aware filtering for memory-lancedb autoCapture so externally wrapped untrusted content is not persisted as long-term memory.

## Best Possible Solution

Define the host-owned autoCapture trust boundary first: memory-lancedb should refuse host-wrapped external content before trigger matching by default, or add an explicit config only if maintainers intentionally want operator-selectable filtering with tests and docs.

## Reproduction Assessment

Yes, at source level: current main has host-authored EXTERNAL_UNTRUSTED_CONTENT wrappers and autoCapture still sanitizes, runs shouldCapture, and stores matching user text without rejecting that wrapper boundary. I did not run a live exploit.

## Solution Assessment

Unclear as proposed: source-based exclusion is the right mitigation area, but a user-configured captureFilter may be weaker and noisier than default host-owned rejection of external-content wrappers. Maintainers should decide the security policy and config shape before implementation.
