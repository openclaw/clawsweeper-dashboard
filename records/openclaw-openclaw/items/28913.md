## Summary

Keep this issue open: current main and v2026.6.11 still have external-content wrappers and memory-lancedb auto-capture sanitization for some inbound metadata, but they do not provide the requested captureFilter option or a default skip for EXTERNAL_UNTRUSTED_CONTENT-wrapped content. The remaining work is security-sensitive product design because it adds or changes memory capture policy and likely config surface.

## What This Changes

The issue requests source-based filtering for memory-lancedb autoCapture so wrapped untrusted external content is not stored as long-term memory.

## Best Possible Solution

Define the host-owned autoCapture trust boundary first: memory-lancedb should refuse host-wrapped external content before trigger matching by default, or add an explicit config only if maintainers intentionally want operator-selectable filtering with tests and docs.

## Reproduction Assessment

Yes, at source level: current main has host-authored EXTERNAL_UNTRUSTED_CONTENT wrappers and autoCapture still runs shouldCapture on sanitized user text without rejecting that wrapper name. I did not run a live exploit, but the trigger/filter path is directly visible in source.

## Solution Assessment

Unclear as proposed: a source-based autoCapture exclusion is the right mitigation area, but a user-configured captureFilter may be weaker and noisier than a host-owned default rejection of external-content wrappers. Maintainers should decide the security policy and config shape before implementation.
