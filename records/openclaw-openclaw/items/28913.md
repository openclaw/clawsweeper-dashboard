## Summary

Keep this issue open: current main and v2026.6.11 still lack a memory-lancedb wrapper/provenance gate or captureFilter option, and the remaining choice is a security/product boundary rather than conservative cleanup.

## What This Changes

Request adding source-based filtering for memory-lancedb autoCapture so wrapped untrusted external content is skipped before trigger-based memory storage.

## Best Possible Solution

Define the host-owned autoCapture trust boundary first; prefer rejecting OpenClaw external-content wrappers before trigger matching, with focused memory-lancedb tests and docs, unless maintainers explicitly choose an opt-in captureFilter config surface.
