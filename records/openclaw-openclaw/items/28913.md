## Summary

Keep open: current main and v2026.6.11 still lack `captureFilter` or an external-wrapper exclusion in `memory-lancedb` auto-capture, while source shows eligible user text can still pass regex capture and be stored. The requested mitigation is security-relevant, but the exact fix needs maintainer product/security choice because it adds memory config surface and overlaps broader provenance/trust work.

## What This Changes

Add a source-aware `memory-lancedb` auto-capture filter that skips externally wrapped untrusted content before storing memories.

## Best Possible Solution

Choose a host-authored source-aware auto-capture policy for `memory-lancedb`, preferably default-skipping OpenClaw external-content wrappers or aligning with the durable provenance/trust design, then add config, manifest, docs, and tests only if maintainers explicitly want an operator knob.

## Reproduction Assessment

Yes, at source level: current main has no `captureFilter` key, and the auto-capture path stores sanitized user text when `shouldCapture` sees trigger words such as `always`. I did not run a live agent workflow in this read-only review.

## Solution Assessment

Unclear. A source-aware capture guard is the right boundary, but the proposed `captureFilter.excludeWrapped` config may be less maintainable than a secure default or a host-authored provenance policy shared with the broader memory trust work.
