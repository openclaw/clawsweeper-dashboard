## Summary

Keep this issue open: current main and v2026.6.11 still run memory-lancedb autoCapture through sanitize-then-trigger matching with no captureFilter and no default external-wrapper rejection. The source-level gap is clear, but the remaining choice is a maintainer security/product decision about host-owned default rejection versus a new operator config surface.

## What This Changes

Request adding source-based autoCapture filtering, proposed as a captureFilter option that excludes EXTERNAL_UNTRUSTED_CONTENT-wrapped turns from LanceDB memory capture.

## Best Possible Solution

Define the host-owned autoCapture trust boundary first; prefer default rejection of host-authored external-content wrappers before trigger matching, with docs and regression tests, unless maintainers intentionally approve a narrow captureFilter config.
