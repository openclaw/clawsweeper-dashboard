## Summary

Keep open: current main and latest release still have memory-lancedb autoCapture regex triggers without a host-side external-content wrapper filter, and the related trust/provenance issues are broader overlap rather than replacements for this narrow autoCapture gap.

## What This Changes

Request adds source-aware filtering for memory-lancedb autoCapture, proposed as `captureFilter.excludeWrapped`, so wrapped `EXTERNAL_UNTRUSTED_CONTENT` is not stored as long-term memory.

## Best Possible Solution

Define the maintainer-approved policy first, then make memory-lancedb autoCapture reject or strip host-wrapped external content at the plugin boundary with aligned config schema, manifest/docs, and regression coverage; only add `captureFilter` if maintainers explicitly want an operator knob.

## Reproduction Assessment

Yes, at source level: a short wrapped external-content block containing a normal trigger word such as `always` reaches sanitizeForMemoryCapture and then shouldCapture, and current main has no captureFilter or external-wrapper rejection. I did not run a live memory write because this review is read-only.

## Solution Assessment

Unclear as proposed: `captureFilter.excludeWrapped` is plausible, but the safer product shape may be default host-side rejection of wrapped external content with an explicit maintainer-approved opt-in only if needed. A narrow config-only patch should wait for security/product direction.
