- `impact:security`: The issue targets prompt-injection persistence from untrusted external content crossing into long-term memory.

## Summary

Keep open: current main and v2026.6.11 still do not provide `captureFilter` or an equivalent `EXTERNAL_UNTRUSTED_CONTENT` guard in memory-lancedb autoCapture. The related memory-trust issues are broader product/security design tracks and do not supersede this narrower capture-time mitigation.

## What This Changes

Request to add source or wrapper-based filtering to memory-lancedb autoCapture so externally wrapped untrusted content is not stored as long-term memory.

## Best Possible Solution

Adopt a host-owned capture policy that skips or strips externally wrapped untrusted content before autoCapture trigger matching, with tests and docs, and add a config knob only if maintainers explicitly want an operator override.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 show external-content wrappers exist, while memory-lancedb autoCapture has no `captureFilter` or `EXTERNAL_UNTRUSTED_CONTENT` skip before trigger matching. This is a feature/security gap rather than a command-level failing test reproduction.

## Solution Assessment

Unclear as proposed: wrapper-aware filtering is the right security direction, but an opt-in `captureFilter` config is not proven to be the best shape under OpenClaw's high config-surface bar. A default host-owned external-content/provenance guard would likely be safer unless maintainers explicitly want an override.
