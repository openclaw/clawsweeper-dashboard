## Summary

Keep open: current main and v2026.6.11 still do not provide source-based `autoCapture` filtering for wrapped external content, and the request remains a security-sensitive product/config decision rather than a cleanup close.

## What This Changes

Request a `memory.captureFilter.excludeWrapped` option so `memory-lancedb` auto-capture can skip text inside `EXTERNAL_UNTRUSTED_CONTENT` wrappers.

## Best Possible Solution

Define a maintainer-approved source/provenance-aware auto-capture gate, then implement it with plugin config/schema/manifest/docs/tests only if that narrow opt-in filter is the chosen security contract.

## Reproduction Assessment

Yes, at source level: current main lacks `captureFilter`, and the auto-capture hook reaches trigger-based `shouldCapture` without a wrapper/source-provenance gate. I did not run a live exploit; the missing behavior is visible in config, runtime, docs, tests, and the latest release tag.

## Solution Assessment

Unclear as proposed: a `captureFilter.excludeWrapped` knob is a plausible narrow mitigation, but maintainers should first decide whether model-visible wrapper names or host-authored provenance should be the trust source. A durable design should avoid making forgeable prompt text the security boundary.
