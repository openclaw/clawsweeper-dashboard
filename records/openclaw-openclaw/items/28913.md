## Summary

Keep this open: current main still has source-level evidence that memory-lancedb autoCapture gates on sanitized user text and trigger regexes without a source-aware exclusion for external-content wrappers, while the proposed new config/default behavior needs maintainer security/product review.

## What This Changes

The issue requests a memory-lancedb autoCapture source filter so EXTERNAL_UNTRUSTED_CONTENT-wrapped turns are not stored as long-term memories.

## Best Possible Solution

Define a maintainer-approved memory-layer source/trust policy that prevents wrapped external content from being auto-captured, then implement it in memory-lancedb with focused regression tests and docs while keeping it aligned with the broader memory provenance design.

## Reproduction Assessment

Yes, at source level: current main shows memory-lancedb autoCapture sanitizes user text and applies shouldCapture triggers without any source-wrapper filter, while external-content wrapping is implemented in a separate security module. I did not run a live exploit because the requested policy surface is absent from source.

## Solution Assessment

Unclear: source-aware capture filtering is the right problem boundary, but the proposed opt-in captureFilter may not be the best final API. Maintainers should choose between default external-wrapper exclusion, a narrowly approved config knob, or a broader host-authored provenance/trust contract.
