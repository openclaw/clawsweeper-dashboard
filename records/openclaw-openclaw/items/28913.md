## Summary

Keep this issue open: current main and v2026.6.11 still have memory-lancedb auto-capture trigger matching without `captureFilter` and without default rejection of `EXTERNAL_UNTRUSTED_CONTENT` before memory storage.

## What This Changes

Requested source-aware filtering for memory-lancedb auto-capture so wrapped untrusted external content is not stored as long-term memory.

## Best Possible Solution

Define the host-owned auto-capture trust boundary first, then either reject host-wrapped external content before trigger matching by default or add a documented operator-selectable filter with focused tests.

## Reproduction Assessment

Yes, at source level: current main has host-authored `EXTERNAL_UNTRUSTED_CONTENT` wrappers and memory-lancedb still sanitizes, runs `shouldCapture`, and stores matching user text without rejecting that wrapper boundary. I did not run a live exploit because the missing option and missing policy branch are visible in source.

## Solution Assessment

Unclear as proposed: source-based exclusion is the right mitigation area, but a user-configured `captureFilter` may be weaker than default host-owned rejection of external-content wrappers. Maintainers should decide the security policy and config shape before implementation.
