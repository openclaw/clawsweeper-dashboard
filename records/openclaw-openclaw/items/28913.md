## Summary

Keep this issue open: current main still has a clear memory-lancedb autoCapture gap for OpenClaw external-content wrappers, and the remaining action is a maintainer security/product decision rather than conservative cleanup.

## What This Changes

The issue requests source-based filtering for memory-lancedb autoCapture so content wrapped as untrusted external input is not persisted as long-term memory by keyword-triggered capture.

## Best Possible Solution

Define the host-owned autoCapture trust boundary first; prefer default rejection of OpenClaw-authored external-content wrappers before trigger matching unless maintainers explicitly choose a documented captureFilter config surface.
