## Summary

Keep this issue open: current main and v2026.6.11 still lack a `memory-lancedb` `captureFilter` or default rejection of OpenClaw external-content wrappers before auto-capture stores memories, and the remaining work is a maintainer security/product decision.

## What This Changes

Add source-based filtering to `memory-lancedb` auto-capture so content inside OpenClaw external-content wrappers is not persisted as LanceDB memory.

## Best Possible Solution

Define the host-owned auto-capture trust boundary first; prefer default rejection of OpenClaw-authored external-content wrappers before trigger matching, with docs and regression tests, unless maintainers explicitly approve a `captureFilter` config surface.

Owner confidence: high

Options:

- **Reject Wrappers By Default (recommended):** Treat `EXTERNAL_UNTRUSTED_CONTENT` as a host-owned capture boundary before trigger matching and add regression coverage for wrapped web, browser, and tool content.
- **Add `captureFilter` Config:** Introduce a documented `excludeWrapped` option with schema, manifest metadata, docs, and upgrade-safe default tests.
- **Defer To Provenance Design:** Leave this narrow filter open until the broader memory trust/provenance model defines the canonical source-authority contract.

## Reproduction Assessment

Yes, at source level. Current main wraps external content, but `memory-lancedb` auto-capture still sanitizes user text, runs `shouldCapture`, and stores matching text without a wrapper/provenance gate; I did not run a live exploit.

## Solution Assessment

Unclear as proposed. Source-based filtering is the right mitigation area, but maintainers should decide whether the best fix is default host-owned wrapper rejection or a new `captureFilter` config surface.
