## Summary

Keep this open: current main and v2026.6.11 still lack a source-aware autoCapture filter, and the remaining work is security-sensitive enough to need maintainer product review rather than an automatic narrow patch.

## What This Changes

The issue requests source-based filtering for memory-lancedb autoCapture so text wrapped as EXTERNAL_UNTRUSTED_CONTENT is not stored as long-term memory.

## Best Possible Solution

Choose a host-authored memory trust policy, then implement source-aware capture filtering or provenance-aware capture in memory-lancedb with matching schema, manifest, docs, and regression coverage.

## Reproduction Assessment

Yes, at source level: current main shows autoCapture sanitizes user text and runs shouldCapture without any EXTERNAL_UNTRUSTED_CONTENT source/wrapper exclusion, while the strict config schema has no captureFilter option. I did not run a live agent flow because the missing behavior is directly visible in the source path.

## Solution Assessment

Unclear as proposed: the requested filter is aimed at the right capture boundary, but an opt-in config alone may be too narrow for a security boundary. A better final design should come from maintainer security review and decide default behavior plus provenance/trust interaction with the broader memory trust work.
