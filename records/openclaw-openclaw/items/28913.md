- `impact:session-state`: Automatically captured untrusted text can become durable memory that influences later sessions after the original external context is gone.

## Summary

Keep open: current main and v2026.6.11 still have trigger-based `memory-lancedb` auto-capture without `captureFilter` or a host-authored source/provenance gate. The broader trust/provenance threads are useful context, but they do not close this narrower capture-time memory-poisoning gap.

## What This Changes

Add source/provenance-based filtering for `memory-lancedb` auto-capture so wrapped untrusted external content is not saved as long-term memory.

## Best Possible Solution

Define a host-authored provenance/trust fact for memory auto-capture and make untrusted external content ineligible by secure default, with any override explicit and security-reviewed.

## Reproduction Assessment

Yes, at source level: current main extracts user-role text, sanitizes it, runs `shouldCapture`, and stores trigger-matching content without a source/provenance gate. I did not run a live poisoning scenario because this read-only review is blocked on security/product policy rather than a failing command path.

## Solution Assessment

No, not exactly as proposed: excluding untrusted auto-capture is the right goal, but a wrapper-name config is weaker than a typed host-authored provenance/trust signal with a secure default chosen by maintainers.
