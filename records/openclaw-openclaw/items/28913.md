## Summary

Keep this open: current main and v2026.6.11 still do not implement the requested `captureFilter`/raw external-wrapper exclusion for memory-lancedb auto-capture. Broader memory trust/provenance issues overlap, but they do not safely supersede this narrower capture-time mitigation.

## What This Changes

Request adding a source-aware `captureFilter` option so memory-lancedb `autoCapture` can skip `EXTERNAL_UNTRUSTED_CONTENT`-wrapped external content before trigger matching.

## Best Possible Solution

Have maintainers choose a source-owned memory capture policy, then implement it in memory-lancedb with manifest/docs/tests and align it with the broader trust/provenance work.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 lack `captureFilter`/`excludeWrapped`, while the auto-capture path still sanitizes text and runs trigger-based `shouldCapture` without source provenance. I did not run a live exploit because the requested architecture/config surface is absent in source.

## Solution Assessment

Unclear as an implementation plan: a capture filter is plausible, but maintainers need to decide whether this should be an opt-in config, a default-safe external-wrapper skip, or part of the broader durable provenance/trust policy. The safest direction is host-owned source policy rather than agent-controlled trust labels.
