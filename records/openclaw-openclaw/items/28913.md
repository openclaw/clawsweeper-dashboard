- `impact:security`: The issue targets indirect prompt-injection and memory-poisoning risk from untrusted external content entering durable memory.
- `impact:session-state`: The requested behavior changes what autoCapture stores as long-term memory and therefore what can resurface in future sessions.

## Summary

Keep this issue open: current main and v2026.6.11 still lack source/tag-aware exclusion for memory-lancedb autoCapture, and the related trust/provenance issues are broader design tracks rather than a merged fix for this narrow capture-time gap.

## What This Changes

Add source/tag-aware filtering to memory-lancedb autoCapture so wrapped external content is not automatically persisted as LanceDB memory.

## Best Possible Solution

Implement a host-authored source/provenance gate for memory-lancedb autoCapture, with config, docs, and regression tests after maintainers decide whether wrapped external content is skipped by default or controlled by explicit policy.

## Reproduction Assessment

Yes, at source level: current memory-lancedb autoCapture sanitizes user text, runs shouldCapture trigger logic, and stores matching text without a source/provenance or EXTERNAL_UNTRUSTED_CONTENT exclusion. I did not run a live LanceDB exploit because the missing gate is clear from source and release inspection.

## Solution Assessment

Unclear as a final implementation: the captureFilter proposal is a plausible narrow mitigation, but the best fix should likely use host-authored provenance or a default wrapped-external-content skip rather than only user-provided tag names.
