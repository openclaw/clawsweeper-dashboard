## Summary

Keep open: current main and v2026.6.11 still lack source-wrapper rejection or a captureFilter option for memory-lancedb autoCapture, and the remaining choice is a security/product boundary decision rather than conservative cleanup.

## What This Changes

Requests source-aware filtering for memory-lancedb autoCapture so OpenClaw external-content wrapper blocks are not persisted as LanceDB memories.

## Best Possible Solution

Define a host-owned autoCapture trust boundary first; prefer rejecting OpenClaw-authored external-content wrappers before trigger matching unless maintainers explicitly choose a documented captureFilter config surface.

Options:

- **Reject wrappers by default (recommended):** Treat EXTERNAL_UNTRUSTED_CONTENT as a host-owned capture boundary before trigger matching and add regression coverage for wrapped web, browser, and tool content.
- **Add captureFilter config:** Introduce a documented excludeWrapped option with schema, manifest, docs, and upgrade-safe default tests.
- **Defer to provenance design:** Keep this narrow filter open until the broader memory trust/provenance model defines the canonical source-authority contract.

## Reproduction Assessment

Yes, at source level. Current main wraps external content, but memory-lancedb autoCapture still sanitizes user text, runs shouldCapture, and stores matching text without a wrapper/provenance gate; I did not run a live exploit.

## Solution Assessment

Unclear as proposed. Source-based filtering is the right mitigation area, but maintainers should decide whether the best fix is default host-owned wrapper rejection or a new captureFilter config surface.
