## Summary

Keep this issue open: current main and v2026.6.11 still lack a memory-lancedb captureFilter or default rejection of OpenClaw external-content wrappers, and the remaining action is a maintainer security/product decision rather than cleanup-closeable work.

## What This Changes

Request source/wrapper-based filtering for memory-lancedb autoCapture so content inside EXTERNAL_UNTRUSTED_CONTENT-style wrappers is not stored as durable memory.

## Best Possible Solution

Define the host-owned autoCapture trust boundary first; prefer default rejection of OpenClaw-authored external-content wrappers before trigger matching, with docs and regression tests, unless maintainers explicitly approve a captureFilter config surface.

- **Defer to provenance architecture:** Leave this narrow filter open until the broader memory trust/provenance model defines the canonical source-authority contract.

## Solution Assessment

Unclear as proposed. Source-based filtering is the right mitigation area, but maintainers should decide whether the best fix is default host-owned wrapper rejection or a new captureFilter config surface.
