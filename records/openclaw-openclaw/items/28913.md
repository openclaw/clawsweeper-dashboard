## Summary

Keep open: current main and v2026.6.11 still lack a memory-lancedb `captureFilter` or default `EXTERNAL_UNTRUSTED_CONTENT` autoCapture gate, and the remaining choice is a maintainer security/product decision rather than cleanup.

## What This Changes

The issue requests source-based memory auto-capture filtering so wrapped external or untrusted content is not stored as long-term memory.

## Best Possible Solution

Define the host-owned autoCapture trust boundary first; prefer rejecting OpenClaw external-content wrappers before trigger matching by default unless maintainers explicitly choose an opt-in `captureFilter` surface.
