## Summary

Keep this issue open: current main and v2026.6.11 still lack the requested `captureFilter` option or a host-owned default skip for `EXTERNAL_UNTRUSTED_CONTENT` content before memory-lancedb autoCapture trigger matching. The related open issues cover broader provenance and prompt-injection architecture, so this remains the narrow tracker for autoCapture filtering.

## What This Changes

Request source-based autoCapture filtering so content wrapped as `EXTERNAL_UNTRUSTED_CONTENT` is not stored as long-term memory.

## Best Possible Solution

Define a host-owned autoCapture trust boundary: skip host-wrapped external content before trigger matching by default, and add operator config only if maintainers intentionally want that policy to be selectable with tests and docs.

## Reproduction Assessment

Yes, at source level: current main has external-content wrappers and memory-lancedb autoCapture still sanitizes, trigger-checks, embeds, and stores text without a `captureFilter` or default wrapper skip. I did not run a live exploit because the relevant path is directly visible in source.

## Solution Assessment

Unclear as proposed: source-based autoCapture exclusion is the right mitigation area, but a user-configured `captureFilter` may be weaker than a host-owned default rejection of external-content wrappers. Maintainers should decide the policy and config shape before implementation.
