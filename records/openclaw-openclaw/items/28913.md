## Summary

Keep this issue open: current main and v2026.6.11 still lack a memory-lancedb captureFilter or a default autoCapture rejection path for OpenClaw external-content wrappers, and the remaining choice is a security/product boundary decision rather than conservative cleanup.

## What This Changes

The issue requests source-based filtering for memory-lancedb autoCapture so wrapped untrusted external content is skipped before preference-trigger matching.

## Best Possible Solution

Define the host-owned autoCapture trust boundary first; prefer default rejection of OpenClaw-authored external-content wrappers before trigger matching, with docs and regression tests, unless maintainers explicitly approve a captureFilter config surface.
