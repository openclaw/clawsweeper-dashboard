- `impact:security`: The report concerns untrusted external content crossing into persistent memory without a capture-time trust boundary.
- `impact:session-state`: The affected data is long-term memory that can influence future sessions after the original context is gone.

## Summary

Keep open: current main still lacks a capture-time source/provenance gate for `memory-lancedb` auto-capture, even though related metadata-sludge filtering has improved. The remaining question is security/product shape, not whether the requested boundary exists today.

## What This Changes

Add source-based filtering to memory auto-capture so configured untrusted wrapper tags are excluded from persistent memory writes.

## Best Possible Solution

Define a plugin-owned capture-time trust/provenance policy for `memory-lancedb`, preferably rejecting wrapped external content by default before auto-capture, with an explicit maintainer-approved config shape only if an override is needed.

## Reproduction Assessment

Yes, source-level. Current `memory-lancedb` auto-capture stores sanitized trigger-matching text and has no `captureFilter` or `EXTERNAL_UNTRUSTED_CONTENT` exclusion path; I did not run a live LanceDB capture.

## Solution Assessment

Unclear as proposed. The requested `captureFilter.excludeWrapped` is plausible, but the best fix may be a default source/provenance gate rather than user-maintained wrapper-name config.
