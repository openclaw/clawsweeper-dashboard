## Summary

Keep this issue open: current main and v2026.6.11 still run memory-lancedb autoCapture through sanitize-then-trigger matching with no captureFilter and no default rejection for OpenClaw external-content wrappers. The remaining choice is a maintainer security/product decision about host-owned default rejection versus a new operator config surface.

## What This Changes

Request to add source-based filtering for memory-lancedb autoCapture, proposed as `memory.captureFilter.excludeWrapped`, so wrapped external content is skipped before trigger matching.

## Best Possible Solution

Define the host-owned autoCapture trust boundary first; prefer default rejection of OpenClaw external-content wrappers before trigger matching, with docs and regression tests, unless maintainers intentionally approve a narrow `captureFilter` config.

Options:

- **Reject wrappers by default (recommended):** Treat `EXTERNAL_UNTRUSTED_CONTENT` as a host-owned capture boundary before trigger matching and add regression coverage for wrapped web/browser/tool content.
- **Add captureFilter config:** Introduce a documented operator-controlled `excludeWrapped` option, with schema, manifest, docs, and upgrade-safe default tests.
- **Fold into provenance design:** Defer this narrow filter until the broader memory trust/provenance model defines the canonical source-authority contract.

## Solution Assessment

Unclear as proposed. Source-based filtering is the right mitigation area, but maintainers should decide whether the best fix is default host-owned wrapper rejection or a new `captureFilter` config surface.
