## Summary

Keep open: current main and v2026.6.11 still lack a source-aware autoCapture gate, and the remaining work is a real memory-security design item rather than stale cleanup.

## What This Changes

The issue requests a configurable source-aware filter for memory autoCapture so wrapped untrusted external content is not persisted as long-term memory.

## Best Possible Solution

Define a maintainer-approved memory source/provenance gate that blocks wrapped untrusted content from durable auto-capture by default or by an explicit approved policy, aligned with the broader memory trust trackers.

## Reproduction Assessment

Yes at source level: current main has external content wrappers and an auto-capture hook, but the hook only sanitizes envelope metadata before trigger matching and storage. I did not run a live LanceDB capture scenario in this read-only review.

## Solution Assessment

No as a final implementation plan: the captureFilter sketch is plausible, but the best fix needs maintainer security/product direction on whether this belongs as a narrow LanceDB option or as host-authored provenance/default policy.
