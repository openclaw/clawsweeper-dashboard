## Summary

Keep this open: current main and v2026.6.11 still lack a memory-lancedb captureFilter or source-wrapper gate, and the overlapping open items are broader architecture trackers rather than replacements for this narrow autoCapture security boundary.

## What This Changes

The issue requests an opt-in memory-lancedb autoCapture filter that skips storage when user-turn text contains wrapped untrusted external content.

## Best Possible Solution

Define the host-owned autoCapture trust boundary first; prefer default rejection of OpenClaw-authored external-content wrappers before trigger matching, with focused docs and regression tests, unless maintainers explicitly approve an opt-in captureFilter config surface.
