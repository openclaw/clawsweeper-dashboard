## Summary

Keep open: the latest-release reproduction and current-main source/test report consistently show gateway-restart interruptions being recorded as cron errors, which pollutes health state even when no agent turn failed. The remaining choice is the durable cron outcome contract; likely related people are markoub and giodl73-repo (low-confidence routing candidates from adjacent restart-recovery work and current-main analysis).

## What This Changes

Make gateway-restart-interrupted cron runs distinguishable from real agent failures so they do not inflate the cron error count or false health alarms.

## System Context

The cron service persists each job’s running and terminal state so startup recovery can account for work interrupted by a gateway restart. That recovered outcome feeds cron health counters, delivery status, notifications, and task-ledger reconciliation.

## Architecture Diagram

flowchart LR
  A[Scheduled cron job] --> B[Persisted running state]
  B --> C[Gateway restart]
  C --> D[Startup recovery]
  D --> E[Terminal cron outcome]
  E --> F[Health counters]
  E --> G[Delivery and notifications]
  E --> H[Task ledger]

## Best Possible Solution

Choose one canonical restart-interruption outcome in the cron recovery layer—preferably reuse the existing `skipped` outcome with the diagnostic reason retained—then ensure it leaves error counters unchanged, records delivery as not requested, and is covered for recurring and one-shot recovery.

Rationale: Both choices change durable cron semantics consumed by health reporting, delivery, retry/backoff, and operator tooling; source evidence establishes the bug but cannot select the permanent status contract.

Likely owner: markoub

Owner reason: Their active adjacent restart-recovery work is the closest identified code-path context, though current-main history ownership still needs confirmation.

Owner confidence: low

Options:

- **Reuse `skipped` for restart interruptions (recommended):** Keep the diagnostic reason but avoid a new public status, leave error and skipped counters unchanged, and suppress failure delivery for recovered interrupted runs.
- **Add `interrupted` as a terminal status:** Expose the distinction explicitly, but define and document its compatibility, retry, health, delivery, and API behavior before implementation.

## Solution Assessment
