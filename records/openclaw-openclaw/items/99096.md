## Summary

## What This Changes

The issue requests that bare leading HTTP 429 provider errors without Retry-After or rate-limit wording use the existing bounded same-model short-window retry after long-window quota filters run.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99097, or close that PR only if maintainers choose a different source-level fix for the same gate; close this issue after the fix reaches main.

## Reproduction Assessment

Yes, at source level. Passing `429 Provider returned error` through the current rate-limit failover path skips same-model retry because the gate sees no short-window wording or Retry-After; I did not run a live provider repro in this read-only review.

## Solution Assessment

Yes. Reusing the existing leading-status parser inside the current short-window gate, after long-window filters, is the narrow source-level fix and avoids adding new config or retry policy.
