## Summary

Keep open: current main and the latest stable release still exclude bare leading-429 provider errors from the existing same-model rate-limit retry, and the linked open PR is the active fix candidate.

## What This Changes

The issue asks OpenClaw to retry transient provider errors like `429 Provider returned error` through the existing same-model rate-limit retry ladder instead of surfacing them immediately.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/99097, or an equivalent source-level fix that treats non-long-window leading 429s as eligible for the existing bounded same-model retry.

## Reproduction Assessment

Yes. Source inspection shows current main classifies leading HTTP 429s as rate limits but rejects `429 Provider returned error` from same-model retry because it has no short-window wording or Retry-After; I did not run a live provider repro.

## Solution Assessment

Yes. Reusing the existing leading-status parser inside the current short-window gate, after long-window filters, is the narrowest maintainable fix and avoids adding config or new fallback policy.
