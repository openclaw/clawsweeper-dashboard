## Summary

Keep open: current main and v2026.6.11 still reject the reported bare leading-429 shape from the existing same-model rate-limit retry gate, and the linked open PR is the active fix candidate.

## What This Changes

The issue asks OpenClaw to route transient status-prefixed 429 provider errors without rate-limit wording through the existing same-model rate-limit retry ladder.

## Best Possible Solution

Review and land the focused linked PR, or close that PR only if maintainers choose a different source-level fix for the same gate.

## Reproduction Assessment

Yes, at source level. Current main classifies the error as rate_limit but rejects `429 Provider returned error` from same-model retry because it lacks short-window wording and Retry-After; I did not run a live provider repro.

## Solution Assessment

Yes. Reusing the existing leading-status parser inside the current short-window gate, after long-window filters, is the narrow maintainable repair and avoids adding config or new fallback policy.
