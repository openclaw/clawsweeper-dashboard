## Summary

Keep open: current main and the latest release still exclude the reported bare status-prefixed 429 shape from the existing same-model rate-limit retry, and an open linked PR now owns the narrow fix path.

## What This Changes

The issue asks OpenClaw to retry bare status-prefixed provider 429 throttles through the existing same-model rate-limit retry ladder instead of surfacing them immediately.

## Best Possible Solution

Review and land the focused linked PR, or close that PR only if maintainers choose a different source-level fix for the same gate.

## Reproduction Assessment

Yes. Source inspection shows the current gate rejects `429 Provider returned error` because it lacks short-window wording and Retry-After, and the issue body provides matching live log evidence; I did not run a live provider repro.

## Solution Assessment

Yes. Reusing the existing leading-status parser inside the current short-window gate, after long-window filters, is the narrowest maintainable fix and avoids adding new config or fallback policy.
