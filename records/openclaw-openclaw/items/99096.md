## Summary

Keep open: current main still excludes the reported bare leading-status 429 shape from the embedded-agent same-model rate-limit retry gate, and the linked open PR is the active fix candidate.

## What This Changes

The issue asks OpenClaw to treat transient provider errors like `429 Provider returned error` as eligible for the existing embedded-agent same-model short-window rate-limit retry after long-window quota and billing cases are filtered.

## Best Possible Solution

Review and land the linked focused PR, or close that PR only if maintainers choose an equivalent source-level fix for the same retry gate.

## Reproduction Assessment

Yes. Source inspection shows `429 Provider returned error` reaches the rate-limit path but returns null from `resolveShortWindowRateLimitRetry` because it lacks Retry-After and short-window wording; I did not run a live provider repro in this read-only review.

## Solution Assessment

Yes. Reusing the existing leading-status parser inside the current short-window retry gate, after long-window filters, is the narrowest maintainable fix and avoids new config or a broader retry policy.
