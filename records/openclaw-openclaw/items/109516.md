Full review comments:

- **[P1] Use a process boundary that can actually time out:** `src/infra/sqlite-wal.ts:176-179`
  - body: Node's synchronous child-process API still waits for the child to exit after sending the timeout signal. A `mount` process blocked in an uninterruptible filesystem call can therefore keep startup hung past ten seconds, so this does not establish the bound claimed by the PR. Run the probe asynchronously or in an isolated helper that startup can abandon after the deadline.
  - confidence: 0.94
- **[P1] Fail safe when the mount probe times out:** `src/infra/sqlite-wal.ts:177-178`
  - body: The new timeout throws into the existing catch and returns no mount entries. For this WAL safety detector, that makes a slow or uncertain remote filesystem look local and can enable WAL on NFS or SMB. Preserve an unknown result and conservatively disable WAL when the probe times out or fails.
  - confidence: 0.88
