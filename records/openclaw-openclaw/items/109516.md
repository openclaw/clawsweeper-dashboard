## Summary

Keep open. The new head does not resolve either prior P1 blocker: Node’s synchronous API still waits for complete child exit after sending the timeout signal, and a timeout is still converted into an empty mount list that can permit WAL. Real behavior proof is also still missing.

## What This Changes

The PR adds a 10-second SIGKILL timeout to the synchronous `mount` fallback used during SQLite WAL filesystem safety detection.

## Best Possible Solution

Replace the synchronous fallback with a probe the caller can stop waiting for, represent detection as local/network/unknown, make unknown select rollback journaling, and cover both the bounded timeout and safe journal-mode outcome with regression and redacted real-process proof.
