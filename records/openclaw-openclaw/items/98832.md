## Summary

Keep open. The PR fixes the right production path, but the proposed mapper still uses `containerWorkdir` without normalizing trailing slashes, while OpenShell accepts and preserves a valid `remoteWorkspaceDir` such as `/sandbox/`; that leaves ordinary `/sandbox/output/...` media paths unmapped for those configs.

## What This Changes

The PR threads sandbox `containerWorkdir` through send and reply media normalization so OpenShell `/sandbox` media paths can map to the host sandbox root.

## Best Possible Solution

Normalize the container workdir once before media prefix checks, add trailing-slash regression coverage, preserve the `/workspace` default and `/sandboxer` rejection, then land one canonical fix for the linked OpenShell bug.

## Reproduction Assessment

Yes. Current source hard-codes `/workspace` media mapping while OpenShell exposes `/sandbox` as its configured workdir; the remaining PR defect is also source-reproducible from the preserved `/sandbox/` config value and unnormalized prefix check.

## Solution Assessment

No, not as written. Threading `containerWorkdir` is the right fix shape, but the branch should normalize trailing slashes before prefix checks so all valid OpenShell workdir spellings are handled.
