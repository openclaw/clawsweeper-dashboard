## Summary

The patch is coherent, well-proven security hardening with no concrete code defect, but it intentionally removes timeout-granted execution from an accepted plugin API and therefore needs explicit human acceptance of the compatibility and authorization-boundary cutover; the stacked parent’s unrelated failing gates must also be resolved before merge.

## What This Changes

The PR makes plugin tool gates fail closed for invalid or unresolved approvals, binds waiter verdicts to approval IDs, consumes one-shot node-policy authority before release, and tightens file-transfer approval parsing.

## Best Possible Solution

Keep one exact fail-closed invariant across all plugin gate release points, retain the legacy field only for a documented deprecation window, and merge after the stacked base is green.
