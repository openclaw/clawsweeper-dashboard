## Summary

Keep open: current main and the latest release still expose memory lifecycle/event-log surfaces, but not the requested all-write memory mutation audit with cause, actor/session context, and tamper-evidence. The Pinchy, world-model-mcp, Memory Audit PR, and broader provenance issues are useful prior art or adjacent design work rather than a merged core implementation of this issue.

## What This Changes

The issue requests an append-only audit log for agent memory-file changes, including what changed, when, why or trigger, session/user context, and tamper-detection value.

## Best Possible Solution

Define a memory plugin or SDK-owned mutation audit contract for MEMORY.md and memory/*.md writes with operation, content summary or hash, cause, session/run/user context, privacy rules, tamper-evidence, and public docs before implementation.
