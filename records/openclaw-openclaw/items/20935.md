## Summary

Keep open: current main still has lifecycle-oriented memory host events and append-only memory-flush guardrails, but not the requested all-write mutation audit for MEMORY.md and memory/*.md with cause, session/user context, and tamper-evidence semantics. The Pinchy, memory-wiki, world-model-mcp, and open Memory Audit PR context are useful prior art or adjacent work, but they do not close the OpenClaw memory-file audit gap.

## What This Changes

The issue requests an append-only audit log for all agent memory-file mutations, including what changed, when, why, and session/user context.

## Best Possible Solution

Design a first-class memory mutation audit layer at the memory plugin/SDK boundary, covering MEMORY.md and memory/*.md writes with operation, content summary or hash, cause, session/run/user context, privacy rules, tamper-evidence, and public docs.

## Reproduction Assessment

Yes, source inspection reproduces the gap: current memory events cover recall, promotion, and dreaming, while memory flush and other memory-file writes do not emit a mutation audit record with cause/session/user/integrity context.

## Solution Assessment

Unclear as proposed: an append-only log is the right direction, but a colocated JSONL-only log would not settle tamper evidence or privacy, so the best path is maintainer-led memory/security design before a fix PR.
