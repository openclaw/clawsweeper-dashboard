## Summary

Keep open: current main still lacks the requested all-write memory mutation audit for `MEMORY.md` and `memory/*.md`; existing memory events and the Gateway audit ledger cover narrower lifecycle/tool metadata only.

## What This Changes

The issue requests an append-only audit log for agent memory changes with what/when/why, session/user context, and tamper-evidence support.

## Best Possible Solution

Design a first-class memory mutation audit layer around all canonical memory write paths, preferably tied to the existing SQLite audit/state model or another explicit tamper-evident store, with documented privacy and integrity semantics.
