## Summary

Keep open: current main and the latest release still expose lifecycle memory events and append-only flush guardrails, not the requested all-write memory mutation audit with cause, session/user context, and tamper-evidence semantics. The Pinchy and world-model-mcp comments are useful prior art, and the open Memory Audit PR overlaps, but none of them currently audit OpenClaw's own MEMORY.md and memory/*.md write surfaces in core.

## What This Changes

The issue requests an append-only audit log for all agent memory changes, including what changed, when, why, session/user context, and tamper-detection support.

## Best Possible Solution

Design a maintainer-approved memory mutation audit layer around every durable memory write or injection surface, with canonical storage, cause propagation, privacy/redaction/retention rules, and explicit tamper-evidence verification documented for operators.

## Reproduction Assessment

Yes, at source level: current main exposes lifecycle memory events and append-only flush guardrails, but no all-write memory mutation audit with cause/session/user context or tamper-evidence semantics. No user-level bug reproduction is required because this is a new audit capability request.

## Solution Assessment

Unclear as an implementation plan: the direction fits OpenClaw's security goals, but maintainers still need to choose the audit storage, privacy, cause propagation, and tamper-evidence contract before code should be queued.
