## Summary

Keep open: current main and v2026.6.11 still expose lifecycle-oriented memory events and memory-flush guardrails, not an all-write memory mutation audit with cause, session/user context, and tamper-evidence semantics. The Pinchy and world-model-mcp comments are useful prior art, and the open Memory Audit PR is adjacent, but none of them currently audits OpenClaw's own `MEMORY.md` and `memory/*.md` mutations.

## What This Changes

Request an append-only audit log for all agent memory file changes, including what changed, when, why, session/user context, and tamper-detection support.

## Best Possible Solution

Keep this as a maintainer-led memory/security design item, then implement one canonical mutation-audit contract around the memory write surfaces with explicit provenance, privacy, and tamper-evidence semantics.

## Reproduction Assessment

Yes at source level: current main has lifecycle memory events and append-only flush guardrails, but the write paths do not record all `MEMORY.md` or `memory/*.md` mutations with cause/session/user/tamper context. This is a missing feature rather than a runnable failure case.

## Solution Assessment

Unclear until maintainers decide the security model; the current event journal is not the best full solution because it is plain lifecycle JSONL inside the memory tree and lacks true mutation provenance. A safer path is a first-class audit contract owned by the memory write boundary with explicit storage and tamper-evidence decisions.
