## Summary

Keep this issue open: it reports a current regression in repeated channel restart recovery, and the `maintainer` label requires explicit maintainer handling. The prior merged restart-recovery work is relevant provenance, but it does not establish that the reported second-restart failure is already fixed on current main.

## What This Changes

The issue requests that restart recovery distinguish globally registered hooks that cannot run for recovered user turns, so the default memory hook does not block repeated channel recovery.

## Best Possible Solution

Define a narrow host-owned hook eligibility contract for recovery, keep unknown hooks conservatively blocking, and add a regression scenario that proves three sequential restarts resume once and deliver exactly one final audit with the bundled memory plugin active.
