## Label Justifications

- `impact:session-state`: The failure marks an interrupted session failed during restart recovery rather than resuming its established task state.
- `impact:message-loss`: The reported behavior replaces automatic final delivery with a resend notice and can require users to repeat work.

## Summary

Keep this issue open: it reports a concrete current regression in replay-safe channel recovery, and resolving it needs an explicit maintainer decision on a host-enforced plugin-hook scope rather than a plugin-local exception. The protected `maintainer` label also requires human handling.

## What This Changes

The issue requests that repeated Gateway restart recovery continue when the default `memory-core` plugin has a globally registered `before_agent_reply` hook that is inactive for recovered user turns.

## Best Possible Solution

Add a narrow host-enforced hook activation/scope contract, apply it to the default memory hook only when the host can prove the recovered turn is outside that scope, and cover both three-restart recovery and a genuinely applicable claiming-hook denial case.

## Maintainer Decision

Required: true

Question: Should OpenClaw add a typed, host-enforced trigger/activation scope to plugin hook registrations so restart recovery can safely ignore hooks guaranteed not to run for recovered user turns?

Rationale: The fix changes the plugin hook contract and restart-safety boundary; source inspection supports the need for a host-owned distinction but cannot choose the permanent public API shape.

Likely owner: steipete

Owner reason: The relevant merged restart-recovery and multi-restart QA work links this contributor directly to the affected behavior and validation scenario.

Owner confidence: high

Options:

- **Add host-enforced hook scope (recommended):** Introduce a typed registration contract that the host validates before restart recovery skips an otherwise globally registered hook.
- **Keep universal hook blocking:** Preserve the current fail-closed behavior and accept resend recovery whenever any `before_agent_reply` hook is registered.
- **Redesign the memory hook seam:** Move the default memory behavior to a narrower existing lifecycle hook if it can preserve heartbeat and cron semantics without expanding the claiming-hook API.

No, not independently in this review. The issue provides a precise live three-restart QA scenario with two observed failures, and current hook dispatch supports the reported boundary, but the live provider scenario was not rerun here.

## Solution Assessment

Unclear pending maintainer direction. A host-enforced scope is safer than a plugin-local bypass, but the permanent plugin-hook contract and whether an existing narrower lifecycle hook suffices need an explicit decision.
