## What This Changes

Add live Anthropic Models API discovery and capability-derived request contracts so newly released Claude models can be catalogued and shaped without waiting for a model-specific source update.

## System Context

The Anthropic provider plugin contributes model metadata to OpenClaw’s provider catalog, while shared Anthropic contracts use model identity and capabilities to prepare API requests. Catalog output affects model selection and limits; request contracts affect the payload sent to Anthropic and therefore whether a configured model can run successfully.

## Best Possible Solution

Adopt a provider-owned live catalog that preserves bundled rows as the offline and pricing baseline, then add a narrow shared capability contract only for API facts that are stable and proven; hide or explicitly mark models whose required request semantics are not covered.

Options:

- **Gate uncontracted models (recommended):** Keep live discovery limited to rows whose required request semantics are covered, so the catalog never advertises a model likely to fail at runtime.
- **Use capability-derived best effort:** Expose new models when published capabilities cover the generic contract, accepting that undocumented provider quirks may still require follow-up fixes.
- **Expose as preview:** Show incomplete rows with an explicit degraded or preview state so advanced users can opt in while preserving a visible warning.
