## Summary

Keep this PR open: the Android lifecycle fix is source-plausible and targets a real TalkMode background capture gap, but it is not merge-ready because after-fix Android proof is missing and the added KDoc currently trips the native i18n inventory check.

## What This Changes

The PR changes Android `NodeRuntime.setForeground(false)` so app backgrounding stops any active voice capture mode through `setVoiceCaptureMode(Off)` instead of only stopping `ManualMic`.

## Best Possible Solution

Keep the narrow NodeRuntime lifecycle fix, remove the new nonessential KDoc or sync native i18n inventory, then land only after redacted Android device/emulator proof confirms active TalkMode backgrounding releases microphone capture and maintainers accept the foreground-only policy.

## Reproduction Assessment

## Solution Assessment

Yes, source-wise: stopping through `setVoiceCaptureMode(Off)` at the NodeRuntime foreground boundary reuses the existing TalkMode and foreground-service cleanup path while preserving `setVoiceScreenActive`'s ManualMic-only behavior. The branch still needs the KDoc/i18n drift fixed and real Android proof before merge.
