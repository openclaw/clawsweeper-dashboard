## Summary

Keep open: current main and v2026.6.11 still compare Codex abort-marker bodies to private Codex guidance prose, while the pinned Codex protocol exposes structured `turn/completed` status data. The protected `maintainer` label also rules out conservative cleanup closure.

## What This Changes

The issue asks OpenClaw to stop recognizing Codex interrupted turns by exact prose matching and instead classify terminal turn state from `turn/completed` `Turn.status` and `Turn.error`.

## Best Possible Solution

Use `turn/completed` `Turn.status` and `Turn.error` as the abort/failure source of truth, and keep only a marker-shape fallback for any proven replay-history gap with focused regression coverage.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes at the source level: send a current-turn `rawResponseItem/completed` `<turn_aborted>` marker whose body differs from the copied guidance, and current main will not classify it as an abort marker; no live end-to-end run was exercised.

## Solution Assessment

Is this the best way to solve the issue? Yes: deriving terminal state from the structured Codex `turn/completed` payload is narrower and more stable than depending on crate-private prose, with a marker-only fallback only if replayed history proves it necessary.
