## Summary

Keep open: current main and the latest release still byte-match Codex abort-marker guidance prose, while the pinned Codex source shows that prose is crate-private and the app-server protocol exposes structured turn status. The protected `maintainer` label and open fix candidates mean this should stay with maintainer review rather than conservative cleanup closure.

## What This Changes

This issue asks OpenClaw to stop recognizing Codex turn aborts by exact private guidance prose and use structured `turn/completed` status/error, with any replay fallback keyed to marker shape rather than marker body text.

## Best Possible Solution

Use `turn/completed` `Turn.status` and `Turn.error` as the abort/failure source of truth, and keep only a marker-shape replay fallback if real history replay still needs it.

## Reproduction Assessment

Yes, at source level: current main still performs strict equality against copied Codex guidance prose in the Codex app-server notification path, and the pinned Codex source exposes that prose as crate-private. No live Codex interruption was exercised in this read-only review.

## Solution Assessment

Yes: deriving abort/failure classification from structured `turn/completed` status/error is narrower and more stable than depending on private Codex wording, with a marker-shape fallback only if replayed history proves it necessary.
