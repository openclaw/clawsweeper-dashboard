## Summary

Keep open: current `main` and the latest release still classify Codex abort markers by strict prose matching, but the `maintainer` label and the prior merged interrupted-turn behavior split mean this needs maintainer-owned repair direction rather than cleanup closure.

## What This Changes

The issue requests replacing Codex app-server abort detection based on private `<turn_aborted>` guidance prose with structured `turn/completed` `Turn.status` and `Turn.error` handling.

## Best Possible Solution

Replace private guidance-body matching with structural protocol handling while preserving the explicit-cancel versus visible-answer-eligible interrupted-turn split, with focused regression tests for reworded markers, interrupted status, failed errors, and explicit cancellation.

## Reproduction Assessment

Yes from source inspection: current `main` strictly compares the marker body against two private upstream prose strings, so an upstream wording change can be reproduced with a focused notification-helper or run-attempt test. I did not run tests in this read-only review.

## Solution Assessment

Mostly yes, but not if interpreted as mapping every `interrupted` turn to `aborted`. The maintainable fix should use structural `turn/completed` data and keep the prior explicit-cancellation split intact.
