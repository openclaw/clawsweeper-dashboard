## Summary

Keep open: current main still has the reported source path, and the linked draft pull request is only a candidate fix until it is reviewed and merged.

## What This Changes

Fix direct-session transcript compaction so an inherited OpenAI OAuth profile on `openai/openai-responses` can fall through to the configured API-key backup while explicit user profile selection remains strict.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/98816 or an equivalent narrow fix that makes inherited compaction auth fallback opt-in while preserving strict explicit profile behavior.

## Reproduction Assessment

Yes at source level, but not from a live run in this review. With an inherited OpenAI OAuth `authProfileId`, current compaction calls `getApiKeyForModel` as an explicit profile and hits the OpenAI Responses API-key assertion before the normal `auth.order.openai` fallback loop can skip to the API-key profile.

## Solution Assessment

Yes, the requested direction is the right boundary: make incompatible-profile fallback an opt-in compaction behavior and keep default explicit profile resolution strict. The linked draft PR needs normal review and proof before it can become the fix.
