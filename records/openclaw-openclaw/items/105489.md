## Summary

The controller-side indexed query is useful, but the requester change adds synchronous SQLite work to a caller that previously filtered the already-restored in-memory registry, then still scans that entire registry. The claimed requester speedup therefore does not establish an improvement for the actual caller, so the PR needs revision before merge.

## What This Changes

The PR adds requester- and controller-scoped SQLite loaders and snapshot helpers, updates three subagent-registry read callers, and adds SQLite store tests.

## Best Possible Solution

Keep the controller query optimization, but leave requester listing unchanged unless it gains lifecycle-owned requester and resolved-controller indexes; then validate persisted/in-memory precedence and benchmark the actual public callers.
