## Label Justifications

- `P2`: The PR is a valuable bounded performance repair, but its new cache has a normal-priority long-running availability defect that should block merge.
- `merge-risk: 🚨 availability`: Merging the unbounded per-controller cache could cause gradual Gateway memory growth under many distinct controller lookups.

## Summary

The indexed-query direction is well-supported and prior correctness concerns were addressed, but the new per-controller cache is unbounded: expired entries remain resident unless that exact key is queried again or a registry write happens. This creates a long-running Gateway memory-growth risk that should be fixed before merge.

## What This Changes

The PR replaces controller-scoped full-registry reads with indexed SQLite queries plus a short-lived per-controller cache and adds correctness and benchmark coverage.

## Best Possible Solution

Keep the scoped indexed query, but make its per-controller cache explicitly bounded with max-entry eviction and opportunistic expired-entry pruning, then add a unique-key churn regression test while preserving the demonstrated warm-query speedup.
