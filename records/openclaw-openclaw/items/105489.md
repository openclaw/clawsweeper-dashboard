## Summary

Keep this PR open for a focused repair. The latest head fixes the prior requester-path regression and the controller-scoped SQL direction is sound, but the patch bypasses the existing 500 ms shared snapshot cache on every controller lookup while benchmarking only cold-cache behavior; repeated and recursive controller reads could therefore perform more synchronous SQLite work than current main.

## What This Changes

The PR keeps requester listing on its existing in-memory path, replaces controller full-registry hydration with scoped SQLite queries plus an in-memory overlay, and adds store, equivalence, and cold-cache benchmark tests.

## Best Possible Solution

Retain the controller-only indexed query, add repeated warm-window and recursive multi-controller benchmarks, and introduce a bounded controller-key cache tied to registry persistence and test-reset invalidation if either workload regresses.
