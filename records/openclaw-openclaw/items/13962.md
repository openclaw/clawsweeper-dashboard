## Label Justifications

- `P2`: This is a meaningful but opt-in group-chat improvement with bounded blast radius and no demonstrated regression in an existing contract.
- `impact:session-state`: The request changes which prior group messages enter a mentioned turn's context and how that pending context is bounded.
- `impact:security`: Running models over unmentioned group traffic expands the existing mention-gating trust and privacy boundary.
- `impact:auth-provider`: The feature would select different model providers for messages in the same group and must compose with existing provider and model overrides.

## Summary

Keep open for maintainer direction: current main still buffers mention-gated group history and supports chat-scoped model overrides, but does not provide mention-state model selection or a deliberate background-processing trust contract. The recent maintainer-side review reached the same conclusion, and the overlapping open proposals do not safely supersede this narrower request.

## What This Changes

Add per-group model routing based on mention state and a configurable number of preceding group messages for mentioned turns.

## Best Possible Solution

Define one secure, channel-agnostic activation contract that carries mention state and bounded pending context into routing, then let channel plugins expose opt-in per-group policy without processing unmentioned traffic by default.

Question: Should mention-state group processing become a first-class shared routing contract, or should core expose a trusted pre-gating plugin hook and leave background-model behavior to an optional plugin?

Rationale: The choice changes the security boundary for unmentioned messages, public configuration surface, provider precedence, and ownership split between core routing and channel plugins; source inspection cannot determine the intended product policy.

Owner confidence: high

Options:

- **Add shared activation contract (recommended):** Introduce a generic mention-state and bounded-context routing contract, with background processing disabled by default and consistent precedence across channel plugins.
- **Expose trusted plugin hook:** Add a read-only or policy-limited pre-gating hook so an optional plugin can implement background classification without channel-specific core configuration.
- **Ship context buffering only:** Add per-group bounded mention context while deferring all background-model processing and its larger trust-boundary decision.
