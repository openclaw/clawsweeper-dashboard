## Label Justifications

- `P2`: This is a meaningful group-chat/provider-routing enhancement with privacy and context implications, but it is not a current regression or blocked core workflow.
- `impact:session-state`: The feature would change which unmentioned group messages enter the agent context window and how much prior group context is attached to a mentioned turn.
- `impact:security`: Processing unmentioned shared-room traffic through a background model creates a privacy and provider-exposure boundary that needs explicit design.
- `impact:auth-provider`: The requested behavior changes provider/model selection based on mention state and must compose with existing auth/provider and model override paths.

## Summary

Keep open: current main and v2026.6.11 still provide buffered group context and channel-scoped model overrides, but not mention-state-aware model routing or a per-group mention-context config surface.

## What This Changes

Requests per-group controls that route mentioned and unmentioned group messages to different models and include a configurable prior-message context window when the bot is mentioned.

## Best Possible Solution

Define a default-off mention-state routing and context policy, preferably as a generic channel/plugin contract unless maintainers explicitly choose a WhatsApp-only surface, then update config schema, docs, and tests for provider precedence, privacy boundaries, skipped-message buffering, and per-group limits.
