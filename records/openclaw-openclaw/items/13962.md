- `impact:session-state`: The request changes how skipped group messages are retained and how much prior group context enters a mentioned turn.

- `impact:auth-provider`: The requested mention/background model controls directly affect provider/model selection and auth-profile behavior.

## Summary

Keep open: current main still lacks per-mention/background model routing and per-group mention context sizing. The existing WhatsApp path buffers skipped mention-gated messages as later context, but skipped unmentioned messages return before model dispatch, and the current model override surface is conversation/session keyed rather than mention-state keyed.

## What This Changes

Request per-group mention-aware model routing plus configurable context sizing for mention-gated group chats.

## Best Possible Solution

Design this as an explicit mention-state-aware group routing contract with security-reviewed defaults, per-group context limits, config/schema/docs updates, and tests for skipped-history buffering, mentioned-message routing, background-model behavior, and model precedence.

## Reproduction Assessment

Yes for a source-level gap: current WhatsApp gating returns before processing unmentioned group messages, and current schema lacks the requested controls. No live group-chat reproduction was run in this read-only review.

## Solution Assessment

No as a ready-to-implement direct config shape: the capability is useful, but adding per-group config is compatibility and security sensitive and needs a maintainer-approved routing precedence contract first.
