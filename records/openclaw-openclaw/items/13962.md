## Summary

Keep open: current main and v2026.6.11 still only provide channel/group/session model overrides plus pending WhatsApp group-history context, not mention-state-aware model routing or per-group mention-context sizing. The remaining work is useful but needs maintainer product and security design because it would expose unmentioned shared-room traffic to a background model and add new public config semantics.

## What This Changes

Request per-group routing that uses different models for mentioned versus unmentioned group messages, plus a configurable context window for mention-gated group replies.

## Best Possible Solution

Define a deliberate mention-state routing and context policy, preferably as a generic channel/plugin contract unless maintainers choose a WhatsApp-only surface, then update config schema/docs and tests around provider precedence, context visibility, skipped-message buffering, and per-group limits.
