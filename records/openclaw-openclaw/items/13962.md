## Label Justifications

- `P2`: This is a meaningful group-chat/provider-routing enhancement with privacy and session-state implications, but it is not a current regression or release-blocking path.
- `impact:session-state`: The feature would change which unmentioned group messages enter the agent's context window and session history.
- `impact:security`: Processing unmentioned shared-room traffic through a configurable background model creates a privacy and provider-exposure boundary.
- `impact:auth-provider`: The request changes provider/model routing based on mention state and must compose with existing model override and auth/provider selection paths.

## Summary

Keep open: current main and v2026.6.11 still provide channel/group/session model overrides and buffered WhatsApp group history, but not mention-state-aware model routing or a per-group mention context window.

## What This Changes

Request per-group controls that route mentioned group messages to one model, unmentioned/background group messages to another, and include a configurable number of previous group messages when a mention arrives.

## Best Possible Solution

Define a default-off mention-state routing and context policy, preferably through a shared channel/plugin contract, then implement WhatsApp config/schema/docs/tests around provider precedence, context visibility, skipped-message buffering, and per-group limits.
