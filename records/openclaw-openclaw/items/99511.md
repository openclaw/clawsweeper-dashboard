## Summary

Keep open: current main and the latest release still store the full pricing fingerprint on each usage-cost cache entry, and the linked fixing PRs are open rather than merged. This issue should remain the canonical report until one candidate fix lands.

## What This Changes

The issue requests deduplicating the usage-cost cache pricing fingerprint by storing it once per cache object instead of once per cached file entry.

## Best Possible Solution

Land one focused cache-format fix that moves the fingerprint to cache-level metadata, rebuilds old v4 cache files safely, and preserves pricing-change invalidation plus checkpoint freshness.

## Reproduction Assessment

Yes from source inspection: current main still stores `pricingFingerprint` on each usage-cost cache entry and checks freshness against that per-entry field. I did not run a live large-cache replay in this read-only review.

## Solution Assessment

Yes: moving the value to cache-level metadata with a cache-version rebuild is the narrow maintainable fix for this exact duplication. Broader cache eviction, tombstone retention, and size-cap work should stay in separate issues.
