## Summary

Keep open: current main and v2026.6.11 still persist the full `pricingFingerprint` on every usage-cost cache file entry, so the reported cache-size and parse/write overhead remains. The fix is narrow enough for one focused repair PR.

## What This Changes

Compact the per-agent usage-cost cache so the pricing fingerprint is stored once or otherwise deduplicated instead of repeated on every cached transcript entry.

## Best Possible Solution

Move the pricing fingerprint to cache-level metadata, or an equivalently compact schema, with a cache version bump and focused regression tests; leave tombstone retention and size-cap policy to the related cache-bloat work.

## Reproduction Assessment

Yes at source level: current main stores `pricingFingerprint` on every `UsageCostCacheFileEntry` and both freshness paths compare that per-entry field. I did not run a large-cache replay in this read-only review.

## Solution Assessment

Yes for a narrow repair: store the fingerprint once at the cache-object level or use an equivalent compact fingerprint while preserving pricing-change invalidation. Do not bundle unrelated tombstone eviction or cache-cap policy into this fix.
