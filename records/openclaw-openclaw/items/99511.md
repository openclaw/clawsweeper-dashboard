## Summary

Keep open: current main and v2026.6.11 still store `pricingFingerprint` on every usage-cost cache entry, and several open closing PRs now own candidate fixes that should be reviewed before this issue closes.

## What This Changes

The issue requests compacting `.usage-cost-cache.json` by storing the shared pricing fingerprint once per cache object or as a short token instead of duplicating it on every entry.

## Best Possible Solution

Review and land exactly one candidate PR that stores global pricing metadata once while preserving freshness semantics, then close this issue and leave broader cache eviction/size-cap work to its separate reports.

## Reproduction Assessment

Yes, at source level: current main defines `pricingFingerprint` on every cache file entry and writes it for each scanned transcript entry. I did not run a large-cache replay in this read-only review.

## Solution Assessment

Yes for the narrow issue: a versioned cache rebuild with one cache-level fingerprint is the smallest maintainable repair. The selected PR still needs maintainer review because the durable generated cache schema changes.
