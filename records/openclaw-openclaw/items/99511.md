## Summary

Keep open: current main and the latest release still store `pricingFingerprint` on every usage-cost cache file entry, and the four linked closing PRs are still open implementation candidates rather than merged fixes.

## What This Changes

The issue requests compacting the usage-cost cache so the identical pricing fingerprint is stored once per cache object, or as a short per-entry token, instead of duplicated on every file entry.

## Best Possible Solution

Keep this issue as the canonical report until maintainers land one compact-cache-schema PR, then close it from the merged fix and avoid opening more duplicate repair PRs.

## Reproduction Assessment

Yes, at source level: current main stores `pricingFingerprint` on every `UsageCostCacheFileEntry` and writes it for each scanned transcript entry. I did not run a live large-cache replay in this read-only review.

## Solution Assessment

Yes for the narrow defect: moving the fingerprint to cache-level metadata with a versioned rebuild is the smallest maintainable shape, provided the linked PR preserves existing freshness and append-only behavior.
