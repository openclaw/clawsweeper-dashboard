## Summary

Keep open: current main and the latest release still store the full pricing fingerprint on every usage-cost cache file entry, and no exact implementation PR now owns this narrow compaction work.

## What This Changes

The issue asks to stop duplicating the same usage-cost `pricingFingerprint` string on every `.usage-cost-cache.json` file entry.

## Best Possible Solution

Compact the versioned usage-cost cache schema so the pricing fingerprint is stored once per cache object or as a short stable token, while preserving existing freshness semantics.

## Reproduction Assessment

Yes, at source level: current main stores `pricingFingerprint` on every `UsageCostCacheFileEntry` and writes it for each scanned transcript entry. I did not run a large-cache replay in this read-only review.

## Solution Assessment

Yes for the narrow bloat: a versioned cache rebuild plus top-level fingerprint or compact per-entry token is the smallest maintainable repair, provided tests cover old-cache rebuild and freshness invalidation.
