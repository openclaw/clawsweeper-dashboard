## Summary

Keep open: current main and v2026.6.11 still serialize `pricingFingerprint` inside every usage-cost cache file entry, and the linked implementation PRs are still open rather than merged.

## What This Changes

The issue asks to deduplicate the per-agent usage-cost cache by storing the identical pricing fingerprint once instead of on every cached file entry.

## Best Possible Solution

Land one narrow cache-shape fix that stores the fingerprint once at cache level, bumps the cache version, preserves checkpointed refresh behavior, and covers v4 rebuild plus pricing-change invalidation.

## Reproduction Assessment

Yes. Source inspection on current main shows each scanned cache entry is built with `pricingFingerprint` and the cache writer serializes the whole cache object, so duplicate fingerprints are source-reproducible without running a write-producing test.

## Solution Assessment

Yes. Moving the fingerprint to cache-level metadata with a version bump is the narrow maintainable fix, provided the landed PR preserves pricing invalidation and checkpoint reload behavior.
