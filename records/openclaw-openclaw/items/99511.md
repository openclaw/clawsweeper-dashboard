## Summary

Keep open: current main and the latest release still persist the full usage-cost pricing fingerprint on each cache entry, and several open fixing PRs now reference this issue, so the issue should remain canonical until one implementation lands.

## What This Changes

The issue requests compacting the usage-cost cache so an identical pricing fingerprint is stored once per cache file instead of repeated on every entry.

## Best Possible Solution

Review and land one focused cache-schema PR that stores the pricing fingerprint once at the cache level, bumps the cache version, and proves freshness invalidation plus append-only reuse still work.

## Reproduction Assessment

Yes, at source level: current main defines `pricingFingerprint` on every usage-cost cache entry and `scanUsageFileForCache` writes it for each scanned transcript. I did not run a large-cache replay in this read-only review.

## Solution Assessment

Yes for the narrow defect: moving the fingerprint to cache-level metadata with a versioned rebuild is the smallest maintainable fix. The best next step is to review and land one of the open implementation PRs rather than create another competing branch.
