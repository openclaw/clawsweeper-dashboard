## Summary

Keep this issue open: current main still routes active embedded-run transcript writes through synchronous JSON serialization and file append/write calls, while the diagnostic heartbeat still samples liveness in the same event loop. The report remains source-backed but needs current-main live measurement before an owner-guided persistence refactor is queued.

## What This Changes

The issue asks OpenClaw to remove or offload synchronous active transcript persistence so large tool-result payloads cannot delay diagnostic liveness sampling and trigger false stuck-session recovery.

## Best Possible Solution

Measure current-main large tool-result runs under diagnostic heartbeat, then move active embedded-run transcript persistence off synchronous SessionManager writes while preserving write locks, cache publication, redaction, compaction, repair, and tool-result caps.
