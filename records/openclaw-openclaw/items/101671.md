## Summary

Keep this issue open: current main has mitigations for oversized live tool results and async append helpers, but the embedded-run `SessionManager` path still persists transcript messages with synchronous serialization and file writes under the active run path, so the central liveness-risk cleanup is not fully implemented.

## What This Changes

The issue asks OpenClaw to stop synchronous transcript persistence from scaling with large tool-result payloads and delaying the diagnostic liveness heartbeat.

## Best Possible Solution

Measure current-main large tool-result runs under diagnostic heartbeat, then remove or offload synchronous `SessionManager` persistence from active embedded-run transcript writes while preserving write locks, cache publication, redaction, and tool-result caps.

No high-confidence current-main reproduction was run. Source inspection shows the synchronous `SessionManager` write path is still reachable, but the default live tool-result cap means the 20 MiB repro needs fresh measurement on current main.

## Solution Assessment

Unclear as an immediate repair. The likely end state is to move active transcript persistence off synchronous `SessionManager` writes, but the broad synchronous API and existing caps make this an owner-guided performance refactor rather than a narrow automatic bug fix.
