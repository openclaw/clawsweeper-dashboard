## Summary

Keep open: current main still has synchronous SessionManager JSONL persistence on the hot transcript path, but current tool-result caps mean the exact large-`cat` repro needs fresh measurement before this becomes a safe automated refactor.

## What This Changes

The issue requests making transcript persistence nonblocking enough that large tool-result/session payloads cannot delay diagnostic liveness sampling and trigger false stuck-session recovery.

## Best Possible Solution

Measure the current guarded large-tool-result path with diagnostics enabled, then move only the proven hot persistence path to a queued async design that preserves transcript lock/cache invariants and recovery semantics.
