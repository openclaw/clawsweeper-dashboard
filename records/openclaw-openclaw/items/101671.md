## Summary

Keep this issue open: current main still routes active embedded-run transcript writes through synchronous `SessionManager` serialization and append I/O, while the diagnostic heartbeat still samples the same event loop and can request stuck-session recovery. The exact large-payload abort still needs current-main live proof because current tool-result caps reduce the original 20 MiB repro shape.

## What This Changes

The issue requests moving or bounding synchronous transcript persistence so large tool-result payloads cannot block liveness sampling and trigger false embedded-run aborts.

## Best Possible Solution

Measure current-main large tool-result runs under the diagnostic heartbeat, then move active embedded-run transcript persistence off synchronous `SessionManager` writes while preserving cache, lock, repair, redaction, and truncation invariants.
