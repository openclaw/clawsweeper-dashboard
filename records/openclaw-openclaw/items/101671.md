## Summary

Keep this issue open: current main still routes the embedded-run SessionManager hot path through synchronous JSONL serialization and file writes, so the central event-loop/liveness risk is not implemented away; existing tool-result caps and warm transcript caches mitigate adjacent costs but do not remove this synchronous persistence path.

## What This Changes

The issue asks to redesign synchronous SessionManager transcript persistence so large tool-result payloads cannot block gateway liveness sampling and trigger stale-session abort recovery.

## Best Possible Solution

Preserve the current transcript graph and lock semantics while moving hot append/rewrite persistence off the event loop or chunking it, then prove with a large-tool-output live run that liveness samples no longer spike into stale-session recovery.
