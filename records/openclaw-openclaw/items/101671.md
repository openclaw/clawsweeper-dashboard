## Summary

Keep this issue open: current main still routes active embedded-run transcript persistence through synchronous `SessionManager` serialization and append/full-write paths, while existing tool-result caps and async append helpers only partially mitigate the reported liveness risk.

## What This Changes

The issue asks OpenClaw to remove or offload synchronous transcript persistence work that scales with tool-result payload size and can delay diagnostic liveness sampling.

## Best Possible Solution

Measure current-main large tool-result runs under diagnostic heartbeat, then move active embedded-run transcript persistence off synchronous `SessionManager` writes while preserving locks, cache publication, redaction, caps, and compaction semantics.
