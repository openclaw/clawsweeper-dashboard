## Summary

The linked bug remains real, but this branch is not merge-safe: it replaces current main’s explicit anti-spoofing rule with text-only cross-message suppression, so a user-authored heartbeat lookalike can remove a legitimate assistant answer from the dream corpus. The same P1 finding remains from both prior review cycles, the branch is behind a rewrite of this loop, and the PR still has only synthetic test output rather than after-fix proof from a real dreaming run.

## What This Changes

Changes dreaming session-corpus ingestion to drop the assistant message immediately following a filtered heartbeat poll and adds focused regression coverage.

## Best Possible Solution

Preserve the current anti-spoofing invariant by carrying an authenticated generated-heartbeat fact from the runtime or session record into corpus ingestion, then drop only that turn’s paired assistant response and prove both genuine-heartbeat and user-lookalike cases on refreshed current main.
