## Summary

Keep this PR open: the authenticated forward filter is promising, but it does not establish how existing persisted Dreaming corpus state converges after a normal upgrade, and the production report does not expose whether state was reset before the claimed improvement.

## What This Changes

The PR marks persisted heartbeat user turns with typed provenance and excludes the paired assistant acknowledgement from memory session-corpus construction.

## Best Possible Solution

Keep authenticated provenance for future heartbeat turns, then have the persisted-state owner explicitly choose and test either bounded forward-only convergence through Dreaming retention or a one-time Dreaming-only corpus/state rebaseline that does not infer provenance from user text.
