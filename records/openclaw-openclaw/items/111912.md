## Summary

The branch closes the BytePlus and Runway portion of the provider-result SSRF gap with an always-guarded download path while retaining the existing explicit private-network opt-in; the latest force-push still needs exact-head compatibility confirmation against the current shared provider HTTP contract before merge.

## What This Changes

The PR adds a guarded provider-download helper, routes BytePlus and Runway generated-video artifact downloads through it, and forwards each provider’s existing request-policy settings to that final download step.

## System Context

OpenClaw’s video-generation provider plugins submit jobs and poll provider status before fetching an artifact URL returned in provider JSON. Those bytes become the agent’s generated-video attachment, so the final URL fetch must apply the same network policy as the earlier provider requests.

## Architecture Diagram

flowchart LR
  A[Agent video request] --> B[BytePlus or Runway plugin]
  B --> C[Submit and poll provider job]
  C --> D[Provider result URL]
  D --> E[Guarded download policy]
  E --> F[Video bytes]
  F --> G[Agent media attachment]

## Best Possible Solution

Land one canonical always-guarded generated-artifact download path for these providers after rebasing and verifying the exact head proves both default private-address blocking and the existing explicit private-network opt-in without changing body timeout, retry, or release behavior.
