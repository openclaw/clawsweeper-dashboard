## Summary

This is a focused, plausible repair for the BytePlus and Runway portions of the generated-video SSRF report, with controlled before/after proof that the shared guarded path blocks loopback targets. It should remain open for maintainer review because it adds a public `provider-http` SDK export and changes the default download behavior for private result endpoints.

## What This Changes

The branch adds `fetchGuardedProviderDownloadResponse`, exports it through the provider HTTP SDK barrel, and uses it for BytePlus and Runway generated-video downloads with focused SSRF and routing tests.

## Best Possible Solution

Keep one generic guarded download helper at the public provider HTTP seam, preserve the existing explicit private-network opt-in, and add provider-entrypoint evidence that an intentional private result URL still succeeds when that opt-in is configured.
