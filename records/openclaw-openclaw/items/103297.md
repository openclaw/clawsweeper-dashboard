## Summary

This PR addresses a real sandbox exec-server crash path, but the current stderr handler still permits a command to continue and later finalize successfully after its stderr output channel has failed; the prior blocker therefore remains unresolved, and the supplied terminal proof does not exercise the changed OpenClaw path.

## What This Changes

Adds stdout and stderr stream-error handlers to Codex sandbox child-process execution plus regression tests for error handling and close-path finalization.

## Best Possible Solution

Treat errors from either command-output stream as a managed execution failure, terminate the child, retain the existing close handler as the sole finalization owner, and demonstrate the resulting failed terminal status through the actual sandbox exec-server path.

## Solution Assessment

No. Adding explicit listeners is the correct boundary, but stderr belongs to the executed command's output contract here and must fail the managed execution rather than be treated like diagnostic-only app-server tracing.
