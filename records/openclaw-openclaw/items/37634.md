## Summary

Keep open: current main and the latest release still make the isolated `workspaceAccess: "none"` sandbox workspace read-only, while user reports and a maintainer comment on a narrower PR keep this issue as the canonical sandbox contract fix.

## What This Changes

The issue asks OpenClaw to keep the real agent workspace unmounted for `workspaceAccess: "none"` while making the per-session sandbox `/workspace` writable.

## Best Possible Solution

Implement the canonical contract: `none` keeps the real agent workspace unmounted, makes only the sandbox-owned `/workspace` writable, preserves protected read-only roots, and proves Docker/browser plus local and remote bridge behavior.
