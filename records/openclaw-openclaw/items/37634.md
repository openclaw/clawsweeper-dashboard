## Summary

Keep open: current `main` and the latest release still make the isolated `workspaceAccess: "none"` workspace read-only, while the latest maintainer discussion keeps this issue as the canonical sandbox contract fix rather than closing it as implemented or duplicate.

## What This Changes

The issue requests that `workspaceAccess: "none"` keep the real agent workspace unmounted while making the isolated sandbox `/workspace` writable.

## Best Possible Solution

Clarify the sandbox contract, then implement isolated-writable `none` consistently across Docker/browser mounts, local and remote filesystem bridges, tool exposure, docs, and regression proof while keeping protected skill paths read-only.
