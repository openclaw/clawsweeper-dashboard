## Summary

Keep open: current main and the latest release still make the isolated `workspaceAccess: "none"` sandbox workspace read-only, and the latest maintainer discussion keeps this issue as the canonical fix path for the isolated-writable contract.

## What This Changes

The issue requests that `workspaceAccess: "none"` keep the real agent workspace unmounted while making the isolated sandbox `/workspace` writable.

## Best Possible Solution

Implement the confirmed isolated-writable `workspaceAccess: "none"` contract across Docker/browser mounts, local and remote filesystem bridges, tool exposure, docs, and regression tests, with live proof that `ro` and protected skill paths remain read-only.
