## Summary

Keep open: current `main` and the latest release still make `workspaceAccess: "none"` use an isolated sandbox workspace but treat that `/workspace` as read-only through Docker/browser mounts plus local and remote filesystem bridges. A maintainer has since confirmed the strict tool-gate workaround is not the right permanent fix and that this issue remains the canonical sandbox contract fix, so this is not conservative cleanup-close material.

## What This Changes

The issue asks for `workspaceAccess: "none"` to hide the real agent workspace while keeping the per-session isolated sandbox `/workspace` writable.

## Best Possible Solution

Implement the maintainer-confirmed contract across all sandbox backends: `none` keeps the real agent workspace unmounted, makes only the sandbox-owned `/workspace` writable, preserves protected skill/read-only bind boundaries, updates docs/tests, and includes live sandbox proof.
