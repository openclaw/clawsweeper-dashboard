## Label Justifications

- `P1`: The reported regression breaks write-heavy sandboxed skills and file operations for users who enabled isolated sandboxing.
- `impact:security`: The issue is about the sandbox filesystem boundary between an unmounted real workspace and an isolated writable sandbox workspace.
- `impact:session-state`: The affected `/workspace` is the per-scope sandbox workspace under `~/.openclaw/sandboxes`, where session-local files, skill materialization, and outputs live.

## Summary

Keep open: current main and v2026.6.11 still make the isolated `workspaceAccess: "none"` sandbox workspace read-only, and the maintainer discussion now identifies this issue as the canonical fix path rather than a cleanup close.

## What This Changes

The issue requests that `workspaceAccess: "none"` keep the real agent workspace unmounted while making the isolated sandbox `/workspace` writable.

## Best Possible Solution

Implement isolated-writable `none` consistently across Docker/browser mounts, local and remote filesystem bridges, tool exposure, docs, and regression tests while preserving host workspace isolation and read-only skill protection.
