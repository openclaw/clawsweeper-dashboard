- `P1`: The report is a source-reproducible sandbox regression that blocks write-heavy skills and workspace operations for users relying on isolated sandboxing.
- `impact:security`: The issue changes the sandbox write boundary between an unmounted real workspace and an isolated writable sandbox workspace.

## Summary

Keep open: current `main` and the latest release still make the isolated `workspaceAccess: "none"` sandbox workspace read-only in Docker/browser mounts and both filesystem bridges, and a maintainer closed the strict write-tool workaround while keeping this issue as the canonical sandbox contract fix.

## What This Changes

The issue requests that `workspaceAccess: "none"` keep the real agent workspace unmounted while making the isolated sandbox `/workspace` writable.

## Best Possible Solution

Clarify and implement the sandbox contract so `none` grants writes only to the isolated sandbox-owned workspace while keeping the real agent workspace unmounted, protected skill paths read-only, and Docker/browser/local/remote behavior plus docs/tests aligned.
