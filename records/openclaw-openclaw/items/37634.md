## Label Justifications

- `P1`: The source-reproducible sandbox regression breaks write-heavy skills and workspace operations for users relying on isolated sandboxing.
- `impact:security`: The issue changes the sandbox filesystem write boundary between an unmounted real workspace and an isolated writable sandbox workspace.
- `impact:session-state`: The affected path is the per-session or per-agent sandbox workspace that carries isolated session files, outputs, and materialized skills.

## Summary

Keep open: current main and the latest release still make the isolated `workspaceAccess: "none"` sandbox workspace read-only, and a maintainer explicitly rejected the strict write-tool-hiding workaround while keeping this issue as the canonical sandbox contract fix.

## What This Changes

The issue requests that `workspaceAccess: "none"` keep the real agent workspace unmounted while making the isolated sandbox `/workspace` writable.

## Best Possible Solution

Settle the sandbox contract, then implement isolated-writable `none` consistently across Docker/browser mounts, local and remote filesystem bridges, write-tool exposure, docs, and regression proof while preserving real-workspace isolation and read-only skill protection.
