## Summary

Keep open. Current `main` and the latest release still make the isolated `workspaceAccess: "none"` workspace read-only at the mount and bridge layers, and a July 6 maintainer comment on the related strict-tool-gate PR explicitly kept this issue as the canonical product/security fix instead of closing it.

## What This Changes

The issue requests that `workspaceAccess: "none"` hide the real agent workspace while keeping the per-session sandbox `/workspace` writable.

## Best Possible Solution

Approve and implement one coordinated sandbox policy: `none` keeps the real agent workspace unmounted, makes only the sandbox-owned `/workspace` writable, preserves read-only skill overlays and path guards, and proves Docker plus remote backend behavior with focused tests and live sandbox proof.
