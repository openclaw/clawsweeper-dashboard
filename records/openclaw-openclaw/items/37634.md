## Summary

Keep open: current `main` and latest release still make the isolated `workspaceAccess: "none"` sandbox workspace read-only, and recent maintainer discussion keeps this issue as the canonical sandbox contract fix rather than accepting the strict write-tool-hiding workaround.

## What This Changes

The issue requests that `workspaceAccess: "none"` keep the real agent workspace unmounted while making the isolated sandbox `/workspace` writable.

## Best Possible Solution

Implement the maintainer-backed contract as one coordinated sandbox change: `none` uses a writable isolated `/workspace`, `ro` remains read-only, and local/remote bridges, tool exposure, protected skill mounts, docs, tests, and live sandbox proof all agree.
