## Summary

Keep open: current main and v2026.6.11 still keep the isolated `workspaceAccess: "none"` sandbox workspace read-only, while the issue discussion and related maintainer comments identify this as the canonical sandbox write-boundary decision rather than cleanup-close material.

The issue requests that `workspaceAccess: "none"` keep the real agent workspace unmounted while allowing writes inside the isolated sandbox `/workspace`.
