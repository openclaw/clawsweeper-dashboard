## Label Justifications

- `P1`: The report is a source-reproducible sandbox regression that blocks write-heavy skills and workspace operations for users relying on isolated sandboxing.
- `impact:security`: The issue changes sandbox write semantics and the boundary between an unmounted real workspace and an isolated writable sandbox workspace.
- `impact:session-state`: The affected path is the per-session or per-agent sandbox workspace that carries isolated session files and materialized skills.

## Summary

Keep open: current `main` and `v2026.6.11` still treat the isolated `workspaceAccess: "none"` sandbox workspace as read-only in the Docker mount, local filesystem bridge, and remote filesystem bridge. A maintainer later closed https://github.com/openclaw/openclaw/pull/73385 because strict write-tool hiding would cement the regression, and explicitly kept this issue as the canonical sandbox contract fix.

## What This Changes

The issue asks OpenClaw to keep `workspaceAccess: "none"` isolated from the real agent workspace while making the per-session sandbox `/workspace` writable.

## Best Possible Solution

Clarify the sandbox contract, then either document `none` as intentionally read-only or implement isolated-writable `none` consistently across Docker/browser mounts, local and remote filesystem bridges, write-tool exposure, docs, and regression proof while preserving read-only skill protection.
