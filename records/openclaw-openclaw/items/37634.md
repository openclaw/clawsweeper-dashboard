## Summary

Keep open. Current `main` and the latest release still make `workspaceAccess: "none"` behave read-only at the Docker mount and filesystem-bridge write gates, while maintainer discussion keeps this issue as the canonical place to restore isolated-but-writable sandbox workspace semantics.

## What This Changes

The issue requests that `workspaceAccess: "none"` keep the real agent workspace unmounted while making the isolated sandbox `/workspace` writable.

## Best Possible Solution

Land a maintainer/secops-reviewed fix that treats `none` as isolated-but-writable across Docker mounts, local and remote filesystem bridge metadata, write gates, tool exposure, docs, and regression tests, while keeping the real agent workspace unmounted and skill protections intact.
