## Summary

Keep open: current main and the latest release still make the isolated `workspaceAccess: "none"` workspace read-only, and recent maintainer discussion keeps this as the canonical sandbox write-boundary decision.

## What This Changes

The issue asks for `workspaceAccess: "none"` to keep the host agent workspace hidden while making the per-session sandbox `/workspace` writable.

## Best Possible Solution

Implement the canonical contract: `none` keeps the real agent workspace unmounted, makes only the sandbox-owned `/workspace` writable, preserves protected read-only roots and explicit read-only binds, and proves Docker/browser plus remote/OpenShell behavior.
