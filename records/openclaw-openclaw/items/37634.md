## Summary

Keep open: current main and v2026.6.11 still keep the isolated `workspaceAccess: "none"` workspace read-only, while related duplicate reports and a later maintainer comment point back to this issue as the canonical sandbox fix. This is not cleanup-closeable because the remaining change is a security-sensitive sandbox write-boundary decision.

## What This Changes

The issue requests that `workspaceAccess: "none"` keep the real agent workspace unmounted while making the isolated sandbox `/workspace` writable.

## Best Possible Solution

Implement one explicit sandbox contract: `workspaceAccess: "none"` keeps the host agent workspace unmounted but makes only the isolated sandbox `/workspace` writable, with local/remote bridges, tool exposure, protected skill mounts, docs, tests, and live sandbox proof aligned.
