## Summary

Keep open: current main and the latest release still keep the isolated `workspaceAccess: "none"` sandbox workspace read-only, and maintainer discussion identifies this as the canonical sandbox write-boundary decision rather than a cleanup close.

## What This Changes

## Best Possible Solution

Implement the canonical contract: `none` keeps the real agent workspace unmounted, makes only the sandbox-owned `/workspace` writable, preserves protected read-only roots, and proves Docker/browser plus remote/OpenShell behavior.
