## Summary

Keep open: current main and the latest release still mount the isolated `workspaceAccess: "none"` `/workspace` read-only, while the exact fix PRs for this behavior are closed unmerged and no merged replacement owns it.

## What This Changes

The issue requests that `workspaceAccess: "none"` hide the main agent workspace while leaving the isolated sandbox `/workspace` writable.

## Best Possible Solution

`workspaceAccess: "none"` should get an explicit maintainer security decision: either make only the isolated sandbox `/workspace` writable while keeping the agent workspace hidden, or keep `none` as a no-write profile and align tool availability/docs with that contract.
