## Summary

This remains a valid Telegram-channel feature request: current OpenClaw supports native ephemeral drafts for DM tool-progress status, but the reviewed documentation does not expose Bot API 10.2 rich-draft Thinking blocks for a generic no-content activity state. The overlapping native-draft work narrows the implementation, but maintainers should first choose whether this richer Telegram-only UX belongs in the existing streaming/rich-message policy.

## What This Changes

Add an opt-in Telegram rich-message draft using Bot API 10.2’s generic native Thinking block while an agent runs, then persist the completed reply normally.

## Best Possible Solution

If sponsored, extend the Telegram channel’s existing streaming/rich-message lifecycle with a DM-only generic Thinking draft that uses the established final-delivery fallback, refreshes before expiry, never carries reasoning or tool arguments, and reuses existing streaming and rich-message controls rather than adding a parallel preference unless maintainers require one.
