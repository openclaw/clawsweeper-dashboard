## Best Possible Solution

Full review comments:

- **[P1] Bound state writes from the sandbox bridge:** `ui/src/lib/workspace/bridge.ts:303`
  - body: A widget with `state:persist` can post valid `workspace:setState` messages in a tight loop, and this branch forwards every one to a synchronous `BEGIN IMMEDIATE` SQLite write plus a gateway broadcast. Because approved widget code remains untrusted, add a per-widget in-flight and rolling rate limit with recovery tests before exposing this write primitive.
  - confidence: 0.94
- **[P2] Deliver state-change events to mounted widgets:** `extensions/workspaces/src/gateway.ts:809`
  - body: The setter emits `plugin.workspaces.widget-state.changed`, but no Control UI path subscribes to that event, so a widget open in another browser never learns that its version changed and cannot refetch. Subscribe at the workspace host and notify only the matching mounted widget, with a two-client regression test.
  - confidence: 0.96
