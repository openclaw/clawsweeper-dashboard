## Summary

Keep open. Current main has the two necessary building blocks—Telegram’s DM-only Dashboard Mini App and Gateway-owned Talk sessions that can write finalized transcript items into a normal agent session—but not a trusted, short-lived bridge from an inbound Telegram conversation to that Talk session. This is a new security- and session-identity-sensitive product capability, so it needs a maintainer decision on the reusable handoff contract before implementation.

## What This Changes

Add a secure Telegram DM entry point that launches realtime Talk bound to the originating OpenClaw conversation and stores finalized Talk transcripts in that same session.

## System Context

Telegram receives a DM command and already has a restricted Mini App launch path, while Talk is a Gateway-owned realtime voice subsystem that can attach to a normal agent session. The missing layer is a constrained handoff that derives the target from trusted Telegram ingress, authorizes the browser client without exposing durable credentials, and then returns final speech turns to the original session.

## Architecture Diagram

flowchart LR
  A[Telegram DM command] --> B[Telegram channel routing]
  B --> C[Trusted session identity]
  C --> D[Short-lived handoff ticket]
  D --> E[Telegram Mini App]
  E --> F[Gateway Talk session]
  F --> G[Finalized transcript]
  G --> H[Original agent session]

## Best Possible Solution

Define a narrow Gateway-owned handoff ticket contract that binds one authenticated channel conversation to one allowed Talk transport and transcript destination, then implement Telegram DM launch and Mini App validation in the Telegram extension; keep group/topic launch explicitly unavailable until its identity and UX path are proved safe.
