## Summary

This PR fixes the shared freshness helper, but it leaves the same provider-owned-session lookup in the direct auto-reply/get-reply session path unchanged. That remaining path can still rotate a `claude-cli` session after the implicit daily boundary when `providerOverride` is `anthropic`, so the linked bug is not fully resolved.

## What This Changes

The PR makes provider-owned CLI session detection fall back from a catalog provider override to the backend model provider, preserving CLI conversations across the implicit daily reset.

## System Context

Session entries persist both the user-selected catalog provider and the backend provider that owns a CLI conversation. The shared freshness path and the direct auto-reply session path each decide whether the implicit daily reset may rotate the session ID, which affects later gateway and chat transcript reuse.

## Architecture Diagram

flowchart LR
  A[Model selection] --> B[Persisted session entry]
  B --> C[Catalog override and backend provider]
  C --> D[Shared freshness lookup]
  C --> E[Auto-reply session lookup]
  D --> F[Implicit daily reset decision]
  E --> F
  F --> G[Session ID and transcript reuse]

## Best Possible Solution

Route both reset decision surfaces through one provider-owned-session predicate that checks the override key first and the backend provider key second, then add regression coverage for the direct auto-reply path.
