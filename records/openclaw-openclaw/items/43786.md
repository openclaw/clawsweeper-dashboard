## Summary

Keep open: current main and the latest release still reject explicit no-auth on reachable Gateway binds, and changing that boundary needs maintainer security/product approval rather than cleanup closure.

## What This Changes

The issue requests allowing `gateway.auth.mode: "none"` for trusted internal non-loopback deployments such as Docker or Kubernetes behind external ingress/auth.

## Best Possible Solution

Keep the fail-closed token/password/trusted-proxy requirement unless maintainers explicitly approve a named private-ingress no-auth policy with startup warnings, audit coverage, docs, and regression tests.
