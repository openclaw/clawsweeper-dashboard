## Summary

Keep open: current main and v2026.6.11 still reject explicit no-auth Gateway mode on non-loopback binds, and allowing it would be a deliberate Gateway security/product decision rather than conservative cleanup.

## What This Changes

The issue requests a trusted-internal deployment mode where `gateway.auth.mode: "none"` can be used without adding a trusted-proxy/nginx workaround.

## Best Possible Solution

Keep the fail-closed token/password/trusted-proxy requirement unless maintainers explicitly approve a named private-ingress no-auth policy with warnings, audit coverage, docs, and regression tests.
