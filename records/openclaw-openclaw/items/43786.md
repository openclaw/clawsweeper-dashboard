## Summary

Keep open: current main and v2026.6.11 still reject explicit no-auth Gateway startup on non-loopback/container binds, and allowing that mode needs maintainer security/product approval.

## What This Changes

The issue requests a supported `gateway.auth.mode: "none"` mode for trusted internal deployments so OpenClaw can run behind external infrastructure without trusted-proxy header validation.

## Best Possible Solution

Keep the current fail-closed startup guard unless maintainers explicitly design and approve a named private-ingress no-auth policy with audit warnings, docs, and focused CLI/runtime coverage.
