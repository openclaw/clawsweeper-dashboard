## Summary

Keep open: current main still rejects explicit no-auth Gateway mode on non-loopback/container binds, and relaxing that boundary needs maintainer security/product approval rather than cleanup closure.

## What This Changes

Request to allow `gateway.auth.mode: "none"` for trusted internal or non-loopback Gateway deployments without requiring trusted-proxy headers or shared-secret auth.

## Best Possible Solution

Preserve the current fail-closed token/password/trusted-proxy requirement unless maintainers explicitly approve a named private-ingress no-auth policy with config or CLI acknowledgement, warnings, audit coverage, docs, and regression tests.
