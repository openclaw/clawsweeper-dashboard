## Summary

Keep open: current main and v2026.6.11 still reject explicit no-auth Gateway startup on non-loopback/container binds, and changing that reachable auth boundary needs maintainer security/product approval. The existing trusted-proxy path is the supported alternative, while the direct same-behavior PR was closed unmerged after concrete security concerns.

## What This Changes

Request to allow explicit Gateway `auth.mode="none"` for trusted internal or non-loopback deployments without requiring trusted-proxy headers or an extra proxy layer.

## Best Possible Solution

Keep the current fail-closed boundary unless maintainers explicitly sponsor a named private-ingress no-auth opt-in with warnings, audit coverage, docs, and regression tests.

- **Relax `auth.mode=none` directly:** Allow explicit none mode to satisfy non-loopback startup without a second interlock, accepting the highest exposure risk and relying on external infrastructure.
