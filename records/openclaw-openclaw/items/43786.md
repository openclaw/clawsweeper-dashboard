## Summary

Keep open: current main and v2026.6.11 still reject explicit no-auth Gateway startup on non-loopback/container binds, and relaxing that boundary needs maintainer security and product approval.

## What This Changes

Request support for running Gateway with `gateway.auth.mode="none"` in trusted internal non-loopback/container deployments without adding a trusted-proxy layer.

## Best Possible Solution

Maintainers should either keep the token/password/trusted-proxy requirement or explicitly design a named dangerous private-ingress no-auth opt-in with startup guards, security audit behavior, docs, and regression coverage.

## Reproduction Assessment

Yes for the current limitation by source inspection: explicit `auth.mode="none"` succeeds at the auth layer but current main rejects it for non-loopback startup, including `bind: "lan"` and container auto-bind paths.

## Solution Assessment

No for the exact proposed shape. `auth mode = none without any validations` is not the safest maintainable solution; if accepted, it should be a deliberate private-ingress policy with warnings, audit behavior, docs, and coverage.
