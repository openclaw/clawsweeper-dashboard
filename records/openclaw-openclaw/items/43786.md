## Summary

Keep open: current main and v2026.6.11 still reject no-auth Gateway mode on non-loopback binds, and the direct implementation attempt was closed unmerged after security concerns; this remains a maintainer security/product decision rather than cleanup.

## What This Changes

Request to allow `gateway.auth.mode: "none"` for trusted internal or non-loopback deployments without the current token/password/trusted-proxy startup validation.

## Best Possible Solution

Keep the fail-closed token/password/trusted-proxy boundary by default; if maintainers sponsor private-ingress no-auth, implement it as a named high-risk policy with explicit acknowledgement, warnings, audit coverage, docs, and focused runtime/CLI tests.
