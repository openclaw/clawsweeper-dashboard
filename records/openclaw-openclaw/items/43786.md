## Summary

Keep open: current main still intentionally rejects explicit no-auth Gateway mode on non-loopback binds, and relaxing that boundary is a security/product decision rather than conservative cleanup.

## What This Changes

Request support for `gateway.auth.mode: "none"` in trusted internal or private-ingress deployments without requiring the current trusted-proxy validation path.

## Best Possible Solution

Keep the current fail-closed default; if maintainers sponsor private-ingress no-auth, add a named explicit high-risk policy with warnings, audit coverage, docs, and regression tests.
