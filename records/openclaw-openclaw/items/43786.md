## Summary

Keep open: current main and v2026.6.11 still reject no-auth non-loopback Gateway startup, and accepting the requested trust model needs explicit security/product approval.

## What This Changes

The issue requests support for running the Gateway on trusted internal networks with `gateway.auth.mode="none"` and no extra proxy-auth validation.

## Best Possible Solution

Keep the fail-closed token/password/trusted-proxy requirement unless maintainers explicitly approve a named dangerous private-ingress no-auth policy with startup guards, audit warnings, docs, and regression coverage.
