## Summary

Keep open: current main still rejects explicit no-auth Gateway mode on non-loopback binds, and changing that boundary needs maintainer security/product approval rather than cleanup closure.

## What This Changes

Requests allowing `gateway.auth.mode: "none"` for trusted internal or private-ingress deployments without requiring trusted-proxy headers.

## Best Possible Solution

Keep the fail-closed token/password/trusted-proxy requirement unless maintainers explicitly approve a named private-ingress no-auth policy with warnings, audit coverage, docs, and regression tests.
