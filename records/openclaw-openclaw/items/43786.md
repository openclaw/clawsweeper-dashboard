## Summary

Keep open: current main and v2026.6.11 still reject `gateway.auth.mode: "none"` on non-loopback Gateway binds, and allowing that reachable no-auth shape is a security/product decision rather than conservative cleanup.

## What This Changes

Request to allow trusted internal deployments to run the Gateway with `gateway.auth.mode: "none"` instead of token/password or trusted-proxy auth.

## Best Possible Solution

Keep the current fail-closed token/password/trusted-proxy requirement unless maintainers explicitly sponsor a named dangerous private-ingress no-auth policy with startup guards, audit warnings, docs, and regression coverage.
