## Summary

Keep open: the PR targets a real transcript-provenance bug, but it still submits the runtime-only placeholder through the normal string prompt path and adds literal filters that can hide real user-authored matching text. The PR also lacks after-fix real behavior proof from a runtime-only maintenance or compaction flow.

## What This Changes

The PR exports the runtime-event placeholder constant, injects hidden runtime-context messages for runtime-only attempts, and filters the placeholder from internal/user-facing text sanitizers with tests.

## Best Possible Solution

Carry runtime-only provenance or suppression before transcript persistence and through display/export/memory consumers, while preserving real user-typed marker text.

Yes, at source level: current main creates the runtime-only placeholder, submits it as a string prompt, emits it as a role:user message, and persists user messages unless explicit suppression is active. I did not run a live WebGUI/TUI compaction flow in this read-only review.
