## Summary

Keep this PR open for explicit maintainer security review. The proposed final-parameter confirmation boundary is aligned with the previously identified gap, but the `maintainer` label and security-sensitive execution ordering require a human to confirm the exact authorization semantics before landing.

## What This Changes

The PR changes Talk voice approvals so a one-shot confirmation is consumed only after policies, hooks, aliases, and tool finalization establish the exact parameters that will execute.

## System Context

Talk sends voice-originated tool calls through the agent pre-execution pipeline, where trusted policy and ordinary hooks can alter a tool call before it runs. The final confirmation gate protects the transition from the resolved executable action to the actual tool invocation.

## Architecture Diagram

  D --> E[Final confirmation consume]
  E --> F[Tool execution or denial]

## Best Possible Solution

Land one canonical final-parameter confirmation contract that rejects rewritten voice actions until the user confirms their exact executable shape, with regression coverage for every execution route and a redacted real Talk validation transcript.
