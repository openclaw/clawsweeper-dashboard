## Summary

Keep open: current main's Gemini projection still removes only `null` from a type array and returns an array when multiple values remain, while the Gemini tool path consumes that projection directly. The existing regression coverage exercises only nullable unions, so this report identifies a narrow untested provider-compatibility gap.

## What This Changes

The issue requests that Gemini-specific tool-schema cleanup collapse multi-type arrays to a scalar compatible type and add focused regression coverage.

## Best Possible Solution

Update the Gemini-only projection to choose one usable non-null scalar type (or omit `type` when none is usable), preserve adjacent schema metadata, and add direct plus nested regression cases without changing generic JSON Schema handling.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes in source: passing a tool property with `type: ['string', 'number']` through the current Gemini cleaner leaves an array-valued `type`; the direct Gemini parameter projection then uses that cleaned schema. A live provider request was not needed to establish the deterministic projection defect.

## Solution Assessment

Yes. Keeping the reduction at the Gemini-only projection boundary and extending the existing cleaner tests is narrower and safer than changing generic JSON Schema semantics or adding configuration.
