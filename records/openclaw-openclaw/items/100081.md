## Summary

Keep open: the latest head still has the prior hot-mode terminal revocation blocker, so a terminal disable can skip the new policy reconciliation path and leave host PTYs active.

## What This Changes

The PR changes the embedded Control UI terminal to explicit opt-in, carries selected agent IDs into new terminal sessions, adds a terminal launch-policy owner, updates reload/CSP/UI plumbing, and expands docs/tests.

## Best Possible Solution

Keep the explicit opt-in and active-agent launch policy, but make restrictive terminal revocations reach the terminal policy/session owner before any hot-mode restart-only skip, with focused regression coverage and accepted upgrade semantics.

## Solution Assessment

No. The centralized terminal launch-policy owner is the right shape, but the current PR is not the best mergeable fix until restrictive terminal changes are reconciled before the hot-mode skip.
