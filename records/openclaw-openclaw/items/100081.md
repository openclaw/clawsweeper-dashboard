## Summary

Keep open: this protected maintainer-labeled PR addresses the earlier active-agent and sandbox-session blockers from https://github.com/openclaw/openclaw/pull/99918, but it still has one blocking security-boundary gap where hot-mode restart-only config changes skip terminal policy reconciliation.

## What This Changes

The PR makes the embedded Control UI terminal explicit opt-in, threads active agent IDs into terminal opens, centralizes terminal launch policy, reconciles disallowed PTYs on config changes, and updates gateway/UI/docs/tests.

## Best Possible Solution

Keep the explicit opt-in and active-agent launch policy, but make restrictive terminal revocations reach the launch policy before any hot-mode restart-only skip, with focused regression coverage.

## Reproduction Assessment

Yes, source-reproducible: with gateway.reload.mode=hot and gateway.terminal.enabled initially true, changing gateway.terminal.enabled to false produces a restart-required plan that returns before onConfigChange runs. That means the terminal policy is not prepared and existing/pending PTYs are not closed.

## Solution Assessment

No. The centralized launch-policy owner is the right shape, but the best mergeable fix must also handle restrictive terminal revocations before the hot-mode ignored-restart return path.
