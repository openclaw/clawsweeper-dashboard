## Maintainer Decision

Required: true

Kind: product_direction

Question: After a bounded reattach and replay attempt cannot prove the original accepted run’s terminal outcome, should `openclaw agent` preserve the isolated embedded rerun by default, fail closed unless users opt in to rerun, or split that policy by delivery mode?

Rationale: This determines a public CLI compatibility contract: automatic rerun favors result availability but risks duplicate side effects, while fail-closed recovery favors single execution but can withhold a result. Source-level correctness cannot select that tradeoff safely.

Likely owner: steipete

Owner reason: The issue’s latest discussion directly requests this person’s decision on the compatibility default.

Owner confidence: medium

Options:

- **Preserve fallback by default (recommended):** After bounded reattach/replay fails, retain the isolated fresh-session embedded fallback so existing CLI users still receive a result, while keeping the recovery-first path.
- **Fail closed by default:** Return an ambiguous-outcome error unless the user explicitly opts in to a rerun that may duplicate side effects.
- **Split by mode:** Use recovery-first fail-closed behavior for `--deliver` and preserve isolated fallback for interactive stdout runs.
