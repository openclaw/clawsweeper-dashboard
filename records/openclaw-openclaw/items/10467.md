## Summary

Keep this issue open: current main still has one global sub-agent lane and scalar concurrency limit, but safely adding lane selection requires a maintainer decision on trusted lane identities, configuration precedence, and an aggregate resource budget.

## What This Changes

Add caller-selectable queue lanes to `sessions_spawn` with compatible per-lane concurrency controls while retaining the existing `subagent` lane as the default.

## Best Possible Solution

Define validated, operator-declared sub-agent lane profiles with an unchanged default profile, explicit precedence and reload semantics, and a mandatory aggregate sub-agent cap before threading profile selection through native and ACP spawn paths.
