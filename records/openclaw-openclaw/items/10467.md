## Summary

Keep open: current main and v2026.6.11 still expose `sessions_spawn` without a caller-selected lane, while native and ACP child runs remain pinned to the single `subagent` queue lane. The gap is source-reproducible, but the requested fix changes model-facing tool and config scheduler semantics that need maintainer product/API direction.

## What This Changes

Request an optional `sessions_spawn.lane` parameter plus per-lane subagent concurrency configuration while preserving the default `subagent` lane.

## Best Possible Solution

Define a maintainer-approved, additive `sessions_spawn.lane` contract that validates lane names, keeps omitted lanes on `subagent`, forwards the resolved lane through native and ACP spawn paths, applies bounded per-lane caps, and updates schema, docs, and regression tests.

## Reproduction Assessment

Yes, at source level: current main has no `sessions_spawn.lane` schema field and hard-codes both native and ACP dispatch to `subagent`. I did not run a live multi-lane workload because the requested input surface does not exist.

## Solution Assessment

Unclear until maintainers choose the public tool/config contract. The maintainable direction appears to be an additive, default-preserving lane parameter plus bounded per-lane caps that compose with adjacent subagent concurrency and queue-visibility work.
