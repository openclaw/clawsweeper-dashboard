## Summary

Keep open: current `main` and v2026.6.11 still expose `sessions_spawn` without a caller-selected lane, and both native and ACP child dispatch remain pinned to the single `subagent` lane. The gap is source-reproducible, but the fix adds model-visible tool and config scheduler semantics that need maintainer product/API direction.

## What This Changes

The issue requests an optional `sessions_spawn.lane` input plus per-lane subagent concurrency configuration so independent spawned sub-agent workloads do not all share one fixed `subagent` queue lane.

## Best Possible Solution

Add a maintainer-approved, default-preserving `sessions_spawn.lane` contract that validates lane names, keeps omitted lanes on `subagent`, forwards the resolved lane through native and ACP spawn paths, applies bounded per-lane caps, and updates schema, docs, and regression tests.

## Reproduction Assessment

Yes. At source level, current `main` exposes no `sessions_spawn.lane` schema field and hard-codes both native and ACP dispatch to `subagent`; I did not run a live multi-lane workload because the requested input surface does not exist.

## Solution Assessment

Unclear until maintainers choose the public tool/config contract. The likely maintainable direction is an additive, default-preserving lane parameter plus bounded per-lane caps that compose with adjacent subagent concurrency and queue-visibility work.
