## Summary

Keep open: current main and the latest release still expose `sessions_spawn` without a caller-selected lane, while both native and ACP child dispatch remain fixed to the single `subagent` lane. The request is valid, but it adds model-visible tool and config semantics that need maintainer product/API direction before an automated fix lane should pick it up.

## What This Changes

Request adding an optional `sessions_spawn.lane` parameter plus per-lane subagent concurrency configuration.

## Best Possible Solution

Add a maintainer-approved, default-preserving subagent lane contract that validates lane names, keeps omitted lanes on `subagent`, forwards the resolved lane through native and ACP spawn paths, applies bounded per-lane caps, and updates schema, docs, and regression tests.

## Reproduction Assessment

Yes, as a source-level feature gap: current main exposes no `sessions_spawn.lane` schema field and hard-codes native and ACP dispatch to `subagent`. I did not run a live multi-lane workload because the requested input surface does not exist.

## Solution Assessment

Unclear until maintainers choose the product/API contract. The likely direction is an additive, default-preserving lane parameter plus bounded per-lane caps, but it must compose with adjacent subagent concurrency and queue-visibility proposals.
