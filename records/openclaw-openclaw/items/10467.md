## Summary

Keep this issue open: both v2026.6.11 and current main still use one fixed sub-agent queue lane and scalar concurrency cap, no related item replaces the selectable-lane requirement, and the remaining public scheduling contract needs maintainer direction.

## What This Changes

Add selectable, independently capped execution lanes for sub-agents spawned through `sessions_spawn`.

## Best Possible Solution

Define administrator-declared lane identities with compatible defaults and deterministic composition of global, lane, and per-target caps, then forward the resolved lane through both native and ACP spawn paths with focused docs and tests.

Owner confidence: high

Options:

- **Declared lanes with composed caps (recommended):** Configure bounded lane IDs, retain `subagent` as the default, and enforce every applicable global, lane, and target capacity constraint.
- **Target-agent partitions only:** Derive isolation from the child agent identity and avoid adding a public lane parameter.
- **Dynamic free-form lanes:** Allow callers to create validated lane names at spawn time and manage their capacity dynamically.

## Reproduction Assessment

Yes. Current main, v2026.6.11, configuration code, and regression tests directly establish one fixed sub-agent lane and one scalar concurrency cap.

## Solution Assessment

Not fully. Selectable isolation remains a valid need, but administrator-declared lanes with composed limits are safer and more maintainable than unrestricted caller-created lanes.
