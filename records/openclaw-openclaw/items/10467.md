## Summary

Keep open: current main and the latest release still expose `sessions_spawn` without a caller-selected lane, and both native and ACP subagent dispatch remain pinned to the single `subagent` queue lane. The request is valid but needs maintainer product/API direction because it adds model-visible tool semantics and new config scheduler behavior.

## What This Changes

Add optional `sessions_spawn.lane` support with independent subagent queue lanes and per-lane concurrency configuration while preserving the default `subagent` lane.

## Best Possible Solution

Add a maintainer-approved, default-preserving `sessions_spawn.lane` contract that validates lane names, keeps omitted lanes on `subagent`, forwards the resolved lane through native and ACP paths, applies bounded per-lane caps, and updates schema, docs, and regression tests.

## Reproduction Assessment

Yes, at source level. Current main exposes no `sessions_spawn.lane` schema field and hard-codes both native and ACP dispatch to the `subagent` lane, so a live multi-lane workload cannot be exercised through the requested input surface.

## Solution Assessment

Unclear until maintainers choose the product/API contract. The likely best direction is an additive, default-preserving lane parameter plus bounded per-lane caps, but it must compose with adjacent subagent concurrency and queue-visibility proposals.
