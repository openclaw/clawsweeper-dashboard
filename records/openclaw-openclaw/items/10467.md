## Summary

Keep open: current main and v2026.6.11 still expose only one fixed subagent queue lane, while this request adds public model-facing tool input plus config scheduler semantics that need maintainer direction before implementation.

## What This Changes

The issue requests an optional `sessions_spawn.lane` parameter with default `subagent` behavior and per-lane subagent concurrency configuration.

## Best Possible Solution

Define a maintainer-approved, additive `sessions_spawn.lane` contract that defaults to `subagent`, validates bounded lane names, forwards the resolved lane through native and ACP spawn paths, preserves the current scalar default, and adds compatible per-lane caps with docs and regression tests.
