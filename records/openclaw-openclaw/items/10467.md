## Summary

Keep open: current main and v2026.6.11 still expose `sessions_spawn` without a caller-selected lane, and both native and ACP child dispatch remain fixed to the single `subagent` queue lane. The request is valid, but it adds model-visible tool and config scheduler semantics that need maintainer product/API direction before implementation.

## What This Changes

The issue requests an optional `sessions_spawn` lane parameter plus per-lane subagent concurrency configuration so independent subagent workloads do not all share the single `subagent` queue lane.

## Best Possible Solution

Add a maintainer-approved, default-preserving subagent lane contract that validates lane names, keeps omitted lanes on `subagent`, forwards the resolved lane through native and ACP spawn paths, applies bounded per-lane caps, and updates schema, docs, and regression tests.

## Reproduction Assessment

Yes. Current main exposes no `sessions_spawn.lane` schema field and hard-codes both native and ACP dispatch to the `subagent` lane; I did not run a live multi-lane workload because the requested input surface does not exist.

## Solution Assessment

Unclear until maintainers choose the product/API contract. The likely best direction is an additive, default-preserving lane parameter plus bounded per-lane caps, but it must compose with adjacent subagent concurrency and queue-visibility proposals.
