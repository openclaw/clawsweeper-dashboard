## Summary

Keep open: current main and v2026.6.11 still lack caller-selected subagent queue lanes, and the remaining work is a model-facing tool/config scheduler contract that needs maintainer approval rather than conservative cleanup.

## What This Changes

The issue requests an optional `sessions_spawn.lane` parameter plus per-lane `maxConcurrent` configuration so independent sub-agent workloads can use separate queue lanes.

## Best Possible Solution

Define a maintainer-approved, additive `sessions_spawn.lane` contract that defaults to `subagent`, validates bounded lane names, forwards the resolved lane through native and ACP spawn paths, preserves the current scalar default, and adds compatible per-lane caps with docs and regression tests.
