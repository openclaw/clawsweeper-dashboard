## Summary

Current main and the latest release still expose one fixed global sub-agent lane, so the requested isolation remains necessary. Keep this feature open for a maintainer choice on the bounded scheduling contract rather than queueing an arbitrary-lane implementation.

## What This Changes

Add caller-selectable sub-agent queue lanes with compatible per-lane concurrency configuration.

## Best Possible Solution

Define configured, validated sub-agent lane classes under one aggregate sub-agent resource ceiling, keep existing spawns on `subagent` by default, and forward only declared lane identifiers through native and ACP paths.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should `sessions_spawn` select only configured bounded lane classes under a global sub-agent ceiling, or should isolation derive from agent identity or queue priority without a new lane parameter?

Rationale: The missing capability is clear, but the permanent tool and config contract determines resource isolation, starvation, lane cardinality, and operator control; prior arbitrary-lane attempts show these are product decisions rather than a mechanical patch.

Likely owner: steipete

Owner reason: The feature and concurrency history most strongly routes through the original `sessions_spawn` and agent-limit work.

Owner confidence: high

Options:

- **Bounded configured classes (recommended):** Allow `sessions_spawn` to choose only declared lane classes, each capped beneath a preserved aggregate sub-agent limit.
- **Identity-derived isolation:** Assign lanes from parent or target agent configuration and keep arbitrary lane selection out of the model-facing tool.
- **Priority-only scheduling:** Keep one sub-agent lane and add priorities, visibility, or per-parent limits instead of independent pools.

## Reproduction Assessment

Yes at the source level: current main has no lane input in `sessions_spawn`, both native and ACP dispatch use the fixed sub-agent lane, and only one scalar sub-agent concurrency limit is applied. This is a reproducible missing capability rather than a violation of an existing documented contract.

## Solution Assessment

No, not as arbitrary lane strings with independent caps; bounded configured lane classes with an aggregate ceiling are a safer maintainable direction. A maintainer must confirm that contract before implementation.
