## Summary

Keep open: current main and v2026.6.11 still expose `sessions_spawn` without a caller-selected lane, while native and ACP child dispatch remain fixed to the single `subagent` queue lane. The source gap is clear, but the requested fix creates model-visible tool and config scheduler semantics that need maintainer product/API direction before automation picks an implementation shape.

## What This Changes

The issue requests an optional `lane` parameter for `sessions_spawn` plus per-lane subagent concurrency configuration.

## Best Possible Solution

Define a maintainer-approved, default-preserving subagent lane contract that validates lane names, keeps omitted lanes on `subagent`, forwards the resolved lane through native and ACP spawn paths, applies bounded per-lane caps, and updates schema, docs, and regression tests together.

## Reproduction Assessment

Yes. Source inspection proves the current schema exposes no `sessions_spawn.lane` field and both native and ACP dispatch hard-code `subagent`; I did not run a live multi-lane workload because the requested input surface does not exist.

## Solution Assessment

Unclear until maintainers choose the public API and config contract. The likely maintainable direction is additive and default-preserving, but arbitrary lane names and per-lane caps need explicit guardrails.
