## Summary

Keep open: current main and v2026.6.11 still expose `sessions_spawn` through one fixed global `subagent` queue lane, while this request adds public model-facing lane selection plus per-lane config semantics that need maintainer direction before implementation.

## What This Changes

The issue requests an optional `sessions_spawn.lane` parameter with independent per-lane sub-agent concurrency configuration.

## Best Possible Solution

Approve a narrow additive design that validates optional lane names, defaults to `subagent`, forwards the resolved lane through native and ACP spawns, applies compatible per-lane subagent concurrency config, and updates docs plus regression tests.

Unclear until maintainer direction is set: the proposed additive lane parameter is plausible and fits the existing command queue, but the public lane naming and per-lane config contract should be decided before a fix PR.
