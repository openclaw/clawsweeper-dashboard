## Summary

Keep open: current main and the latest release still expose one fixed subagent queue lane, while the requested lane parameter and per-lane subagent concurrency config remain missing and need maintainer product direction.

## What This Changes

Request adding an optional `sessions_spawn.lane` parameter plus compatible per-lane subagent concurrency configuration so independent subagent workloads can use separate queue lanes.

## Best Possible Solution

Define a maintainer-approved additive lane contract that defaults to `subagent`, validates bounded lane names, preserves the current scalar default, and applies native/ACP dispatch plus docs and regression tests consistently.
