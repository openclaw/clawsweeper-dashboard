## Summary

Keep open: current main and v2026.6.11 still expose `sessions_spawn` without a caller-selected lane, and both native plus ACP child dispatch remain pinned to the single `subagent` lane with one scalar concurrency cap.

## What This Changes

The issue requests an optional `sessions_spawn.lane` parameter plus per-lane `maxConcurrent` config so independent sub-agent workloads can use separate queue lanes.

## Best Possible Solution

Design a maintainer-approved, default-preserving subagent lane contract that keeps existing callers on `subagent`, validates custom lanes, forwards the selected lane through native and ACP spawns, and documents/tests compatible per-lane caps.

## Reproduction Assessment

Yes, as a source-level feature gap: current main exposes no `sessions_spawn.lane` schema field and hard-codes native plus ACP dispatch to `subagent`. I did not run a live multi-lane workload because the requested input surface does not exist.

## Solution Assessment

Unclear until maintainers choose the public API and config contract. The likely best shape is an additive lane parameter with default-preserving fallback and bounded per-lane caps, not a separate orchestration layer.
