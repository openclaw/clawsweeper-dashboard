## Summary

Keep open: current main and v2026.6.11 still expose `sessions_spawn` without a caller-selected lane, while native and ACP child dispatch remain fixed to the single `subagent` lane. The request is valid, but it adds model-visible tool and config scheduler semantics that need maintainer API direction before implementation.

## What This Changes

Add optional caller-selected lanes to `sessions_spawn`, with per-lane subagent concurrency configuration and `subagent` as the default fallback.

## Best Possible Solution

Add a maintainer-approved, default-preserving subagent lane contract that validates lane names, keeps omitted lanes on `subagent`, forwards the resolved lane through native and ACP spawn paths, applies bounded per-lane caps, and updates schema, docs, and regression tests.

## Reproduction Assessment

Yes, as a source-level feature gap: current main exposes no `sessions_spawn.lane` schema field and hard-codes native and ACP dispatch to `subagent`. I did not run a live multi-lane workload because the requested input surface does not exist.

## Solution Assessment

Unclear until maintainers choose the public tool and config contract. The likely maintainable direction is an additive, default-preserving lane parameter plus bounded per-lane caps that compose with adjacent subagent concurrency and queue-visibility work.
