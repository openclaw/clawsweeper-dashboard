## Summary

Keep this PR open for the requested human review. The per-monitor cache ownership is a narrow, plausible fix for stale Tlon summaries after a monitor restart, but the posted before/after run replaces the Tlon scry boundary with a fixture and does not yet demonstrate an actual restarted Tlon account.

## What This Changes

Scopes Tlon channel-history caching to each running monitor and adds tests that a new monitor fetches fresh history instead of reusing another monitor's cached messages.

## System Context

The Tlon monitor receives channel events and keeps recent messages available for summary requests. This change moves that transient history from module lifetime to monitor lifetime before the summary path reads it.
