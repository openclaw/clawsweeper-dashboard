## Summary

Keep open: current main and v2026.6.11 still have no agent-scoped plugin configuration surface, and the requested behavior is a real multi-agent isolation feature that needs maintainer product and security design rather than cleanup closure.

## What This Changes

The issue requests per-agent plugin configuration overrides so different agents in one gateway can use different plugin settings, credentials, and plugin-owned state.

## Best Possible Solution

Define a maintainer-approved agent-scoped plugin config contract with precedence, SecretRef/redaction, schema validation, lifecycle/restart behavior, doctor/upgrade semantics, docs, and two-agent regression coverage.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 reject agents.list[].plugins through the strict agent schema and resolve plugin config only from global plugins.entries[id].config. I did not run a write-path config repro because source inspection establishes the missing surface.

## Solution Assessment

Unclear. The requested deep-merge model is plausible, but the best fix needs maintainer decisions on precedence, SecretRef/redaction, validation, plugin lifecycle, restart behavior, and whether generic per-agent config or plugin-specific scoping owns each use case.
