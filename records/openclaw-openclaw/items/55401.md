## Summary

Keep open: current main and v2026.6.11 still have no agent-level plugin config surface, and this remains a security-sensitive product/API contract rather than conservative cleanup.

## What This Changes

Issue requests per-agent plugin configuration overrides so multi-agent installs can give the same plugin different config, credentials, and isolation per agent.

## Best Possible Solution

Define a maintainer-approved agent-scoped plugin config contract with precedence, SecretRef/redaction rules, schema validation, lifecycle semantics, docs, and focused two-agent regression coverage.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 both reject agent-level plugin config by schema shape and resolve plugin config only from global `plugins.entries[id].config`.

## Solution Assessment

Unclear. A deep-merge override is plausible, but the best fix needs maintainer decisions on precedence, SecretRef behavior, plugin lifecycle, validation, and whether generic or plugin-specific scoping owns each use case.
