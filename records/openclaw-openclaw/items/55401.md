## Summary

Keep open: current main and v2026.6.11 still have no agent-scoped plugin config surface, while the issue discussion shows real multi-agent credential and state isolation needs that require maintainer product and security design.

## What This Changes

The issue requests per-agent plugin configuration overrides so different agents on one gateway can use different settings, credentials, or accounts for the same plugin.

## Best Possible Solution

Define a maintainer-approved agent-scoped plugin config contract with precedence, SecretRef/redaction, schema validation, lifecycle/restart behavior, doctor/upgrade semantics, docs, and two-agent regression coverage.

## Reproduction Assessment

Yes, at source level: current main rejects agents.list[].plugins through the strict agent schema and resolves plugin config only from global plugins.entries[id].config. I did not run a write-path config repro because the source contract is enough to verify the missing surface.

## Solution Assessment

Unclear. The requested deep-merge model is plausible, but the best fix needs maintainer decisions on precedence, SecretRef/redaction, validation, plugin lifecycle, restart behavior, and whether generic per-agent config or plugin-specific scoping owns each use case.
