## Summary

Keep open: current main and v2026.6.11 still have no agent-scoped plugin config surface, and the discussion shows real multi-agent credential/state isolation needs that require maintainer product and security design before implementation.

## What This Changes

The issue requests per-agent plugin configuration overrides so agents on one gateway can use different plugin settings, credentials, and capability surfaces.

## Best Possible Solution

Define a maintainer-approved agent-scoped plugin config contract with precedence, SecretRef/redaction, schema validation, lifecycle/restart, doctor/upgrade, docs, and two-agent regression coverage.

## Reproduction Assessment

Yes, at source level: current main and v2026.6.11 reject agents.list[].plugins through the strict agent schema and resolve plugin config only from global plugins.entries[id].config. I did not run a write-path config repro because the source contract is enough to verify the missing surface.

## Solution Assessment

Unclear. The requested deep-merge model is plausible, but the best fix needs maintainer decisions on precedence, SecretRef/redaction, validation, plugin lifecycle, restart behavior, and whether generic per-agent config or plugin-specific scoping owns each use case.
