Keep open: current main and the latest release still allow the reported Feishu/Lark announce cron shape with an omitted `delivery.to` to pass create-time validation, while runtime delivery still has the missing-target failure path. ## What This Changes

The issue asks for create-time rejection of Feishu announce cron jobs that omit `delivery.to`, because such jobs can be stored and later fail delivery at runtime.

## Best Possible Solution

Land or adopt one focused gateway/service validation fix for Feishu/Lark announce delivery without a target, with CLI/UI feedback mirroring that boundary; track legacy audit and clearer diagnostic wording separately if maintainers want that UX follow-up.

## Reproduction Assessment

## Solution Assessment

Yes. The requested gateway/service create and update validation is the narrowest maintainable fix because it prevents invalid stored jobs from every creation path; CLI/UI validation should mirror that boundary rather than replace it.
