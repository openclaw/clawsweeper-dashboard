## Summary

Keep open: current main and latest release still accept Feishu/Lark announce cron delivery without `delivery.to`, and runtime can still fail with the missing-target error shown by the operator evidence. The bug is real, but two open fork PR candidates already reference this issue, so maintainers should choose the landing path before another fix lane starts.

## What This Changes

Cron should reject Feishu/Lark announce jobs at create time when no explicit or resolvable delivery target is available.

## Best Possible Solution

Land one focused gateway/service validation fix for Feishu/Lark announce delivery without an explicit or deterministically resolved target, mirror the message in CLI/UI feedback, and track legacy audit or diagnostic wording separately.
