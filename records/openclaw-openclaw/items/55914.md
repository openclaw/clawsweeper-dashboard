## Summary

Keep open: current main has QR/setup-code mobile pairing and a bounded bootstrap handoff, but it still does not implement the requested cloud-backed `openclaw invite` short-code register/resolve flow or the proposed `cloud.enabled` / `cloud.apiUrl` Gateway config. The remaining question is a product/security decision shared with the broader Cloud Relay discussion, not a narrow cleanup close.

## What This Changes

Add an `openclaw invite` command that generates short shareable cloud invite codes for mobile Gateway discovery and pairing.

## Best Possible Solution

Decide the cloud invite and Cloud Relay trust/config model together, then either implement a narrow approved discovery path or document the current QR/setup-code path as the supported no-camera fallback.
