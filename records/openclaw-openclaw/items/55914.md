## Summary

Keep open: current main and v2026.6.11 provide QR/setup-code mobile pairing and a Control UI setup-code RPC, but they still do not provide the requested cloud-backed `openclaw invite` short-code register/resolve flow or the proposed `cloud.enabled` / `cloud.apiUrl` Gateway config.

## What This Changes

The issue requests a new `openclaw invite` command that registers short mobile pairing codes with a configurable cloud backend so users can pair without scanning a QR or entering a long Gateway URL.

## Best Possible Solution

Settle the shared mobile cloud discovery and relay trust model first, then either keep the current local setup-code path as the supported no-camera alternative or implement a narrow approved invite-code resolver with explicit backend, config, security, and migration rules.
