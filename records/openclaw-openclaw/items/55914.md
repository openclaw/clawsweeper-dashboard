## Summary

Keep open: current main and the latest release still lack the requested `openclaw invite` cloud short-code register/resolve flow and the proposed `cloud.enabled` / `cloud.apiUrl` Gateway config. The related one-step setup-code work is local/reachable-Gateway onboarding, while the remaining invite-code request needs a maintainer product and security decision shared with Cloud Relay.

## What This Changes

Add an `openclaw invite` command that creates a short mobile pairing code, registers it with a configurable cloud backend, and lets mobile clients resolve it into a Gateway connection before normal device approval.

## Best Possible Solution

Define a maintainer-approved mobile cloud discovery trust/config model with the Cloud Relay direction, then either implement a narrow invite-code path or explicitly keep QR/setup-code plus reachable Gateway setup as the supported path.
