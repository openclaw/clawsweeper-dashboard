## Summary

Keep open: current main and the latest release have QR/setup-code mobile pairing, but they still do not implement the requested cloud-backed `openclaw invite` register/resolve flow or `cloud.enabled` / `cloud.apiUrl` Gateway config. This remains a product and security decision that partially overlaps Cloud Relay and newer gateway-local setup-code work.

## What This Changes

The issue requests an `openclaw invite` command that creates short cloud-backed pairing codes for mobile Gateway discovery.

## Best Possible Solution

Settle the shared invite-code and Cloud Relay trust/config model, then either keep documenting the current setup-code path as the supported no-camera alternative or implement a narrow approved cloud discovery path with explicit security and upgrade rules.
