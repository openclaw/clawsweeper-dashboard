## Summary

Keep open: current main and the latest release have QR/setup-code mobile pairing, but they still do not implement the requested cloud-backed `openclaw invite` register/resolve flow or the proposed `cloud.enabled` / `cloud.apiUrl` Gateway config. The related Cloud Relay and one-step setup-code items overlap, but neither fully owns this invite-code discovery decision.

## What This Changes

Request an `openclaw invite` CLI command that registers short, expiring mobile pairing codes with a configurable cloud backend for remote or no-camera pairing.

## Best Possible Solution

Decide the cloud invite and Cloud Relay trust/config model together, then either implement a narrow approved discovery path or document the current QR/setup-code path as the supported no-camera fallback.
