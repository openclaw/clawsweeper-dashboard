## Summary

This remains a focused iOS Talk bug: the supplied current-main evidence shows the native send path explicitly supplies `thinking: "low"`, while the related merged macOS repair established inheritance for the analogous voice paths. The open adaptive-fallback PR addresses a different sentinel value and does not remove this concrete iOS override.

## What This Changes

Stop native iOS Talk from forcing `thinking: "low"` on `chat.send` requests so it inherits the effective gateway/session/model thinking policy by default.

## Best Possible Solution

Make the default iOS Talk request omit `thinking`, add a native regression that proves the serialized/default request has no override, and retain a separate explicit value only when an iOS UI control genuinely selects one.
