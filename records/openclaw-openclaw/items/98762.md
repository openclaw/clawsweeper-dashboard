## Summary

Keep open: current main still has a plausible local TUI shutdown path where `requestExit()` stops the embedded backend and aborts active local runs, while the exact macOS trigger that fires during long turns is not yet live-proven.

## What This Changes

The issue reports that `openclaw chat` can exit during long-running embedded Codex turns and log `codex app-server client closed before turn completed` before the assistant produces a final response.

## Best Possible Solution

Keep this issue open for a maintainer-owned local TUI lifecycle fix: first identify and log the exact `requestExit()` trigger, then preserve active embedded turns or classify intentional interruptions according to that trigger.

## Reproduction Assessment

Source-reproducible, but not live reproduced: current `main` has a clear `requestExit()` -> `client.stop()` -> active embedded run abort path, and the Codex harness maps a pre-`turn/completed` client close to the reported error. The missing part is a live macOS/local TUI run proving which shutdown trigger fires without explicit user exit.

## Solution Assessment

Unclear until the trigger is known: request-exit cause diagnostics are the safest first step, then the fix should either avoid stopping active embedded turns for false terminal-loss events or classify genuine exits as intentional interruption. A blanket retry or blanket suppression would be too broad for side-effecting engineering tasks.
