## Label Justifications

- `P2`: Automatic language detection deterministically displays the wrong existing Control UI locale for Traditional Chinese users, but the saved language picker provides a recovery path.

## Summary

This remains a focused Control UI localization bug: the documented automatic locale selection supports `zh-TW`, while the report identifies explicit Traditional-Chinese script and region tags resolving to `zh-CN`. No merged fix or current-main implementation provenance is present in the supplied context, so it should stay open for a narrow resolver-and-regression-test repair.

## What This Changes

Correct automatic Control UI locale resolution so Traditional Chinese browser tags select the `zh-TW` translation bundle rather than `zh-CN`.

## System Context

The Control UI chooses an initial translation bundle from browser language preferences, then lazy-loads the selected locale and stores any later user choice in browser storage. The locale resolver therefore determines which translated interface users see before the settings language picker can override it.

  Traditional --> Loader[Lazy-load locale bundle]
  Simplified --> Loader
  Loader --> UI[Localized Control UI]

## Best Possible Solution

Normalize BCP-47 language tags case-insensitively in the Control UI resolver, map explicit `Hant` and `TW`/`HK`/`MO` regional forms to `zh-TW`, retain the existing Simplified-Chinese path, and add regression coverage without editing generated translation bundles.
