- **[P1] Reject UNC roots before spawning cmd.exe:** `src/infra/windows-encoding.ts:70-78`
  - body: `pathWin32.isAbsolute()` accepts UNC paths, and the later basename/dirname checks allow values like `\\server\share\Windows`, causing codepage detection to execute `\\server\share\Windows\System32\cmd.exe` from a tainted environment. Reuse current main's hardened Windows install-root helper or require a local drive root here.
  - confidence: 0.91
- **[P1] Reuse local-root validation in the SDK decoder:** `packages/memory-host-sdk/src/host/windows-output-decoder.ts:143-151`
  - body: The new SDK decoder repeats the same SystemRoot-to-cmd.exe resolution and accepts UNC roots before spawning `chcp`. Please share or mirror the local-drive validation used by current main so the SDK path does not create a separate executable trust boundary.
  - confidence: 0.9
- **[P2] Inject the Windows decoder for the QMD test:** `packages/memory-host-sdk/src/host/qmd-process.test.ts:153-161`
  - body: This test calls `runCliCommand` without a platform or decoder override, but `decodeWindowsOutputBuffer` returns early on Linux/macOS because `process.platform !== "win32"`; the mocked `chcp` result is never used. Add a decoder factory/platform override seam or pass explicit platform/encoding into the path under test.
