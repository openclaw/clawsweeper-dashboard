## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.89

Full review comments:

- **[P1] Reject UNC roots before spawning cmd.exe:** `src/infra/windows-encoding.ts:70-78`
  - body: `pathWin32.isAbsolute()` accepts UNC paths, and the later basename/dirname checks allow a value like `\\server\share\Windows`; this would make codepage detection execute `\\server\share\Windows\System32\cmd.exe` from a tainted environment. Current main already routes this through the hardened `getWindowsCmdExePath`/`normalizeWindowsInstallRoot` path, so keep that helper or require a local drive root here.
  - confidence: 0.91
- **[P1] Reuse local-root validation in the SDK decoder:** `packages/memory-host-sdk/src/host/windows-output-decoder.ts:143-151`
  - body: The new SDK decoder repeats the same SystemRoot-to-cmd.exe resolution and accepts UNC roots before spawning `chcp`. Please share or mirror the local-drive validation used by current main's Windows install-root helpers so the SDK path does not create a separate executable trust boundary.
  - confidence: 0.9
- **[P2] Inject the Windows decoder for the QMD test:** `packages/memory-host-sdk/src/host/qmd-process.test.ts:140-161`
  - body: This test mocks `spawnSync`, but `decodeWindowsOutputBuffer` returns early on Linux/macOS because `process.platform !== "win32"`, so the mocked codepage is never used and the GBK bytes are decoded as UTF-8. Add a decoder factory/platform override seam like the TUI test uses, or pass explicit platform/encoding into the path under test.
  - confidence: 0.88
