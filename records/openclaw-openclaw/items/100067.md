## Label Justifications

- `P1`: The report describes a latest-stable upgrade regression that can leave provider auth empty and break real agent fallback workflows.
- `impact:auth-provider`: The central failure is OAuth/token provider profiles being stranded outside the canonical SQLite auth store.
- `impact:message-loss`: The reported downstream effect is failed agent turns when every configured fallback provider becomes unavailable after auth migration.
- `impact:ux-friction`: Recovery currently depends on operators recognizing a legacy JSON-versus-SQLite auth-store mismatch and running technical repair steps.
- `maturity:stable`: The issue maps to the M4 Stable `cli-install-update-onboard-doctor` feature because it concerns update, doctor, and auth setup reliability.

## Summary

Keep open: current main and the latest checked release still keep normal runtime auth loads SQLite-only, with legacy `auth-profiles.json` import routed through doctor repair rather than startup/update recovery. The overlapping open PR covers part of the import idea, but it is still a compatibility/security-boundary decision and does not cover the fallback-chain diagnostic request.

## What This Changes

The issue asks OpenClaw to stop 2026.6.x upgrades from stranding legacy JSON auth profiles outside SQLite and to warn when configured fallback chains become unusable.

## Best Possible Solution

Keep steady-state runtime reads SQLite-only, but add a maintainer-approved update/startup detection or one-shot migration path for stranded legacy auth JSON and surface unusable configured model fallback chains before turns fail.

## Reproduction Assessment

Yes at source level: current main leaves a canonical `auth-profiles.json` unread when the per-agent SQLite auth store is empty, and the checked startup/runtime paths do not run the JSON-to-SQLite import. I did not run a live release-to-release upgrade in this read-only pass.

## Solution Assessment

Unclear as an implementation choice: the issue is real, but the best fix needs maintainer direction on automatic startup migration versus loud startup/update warning plus doctor repair. A steady-state runtime JSON fallback remains the wrong default layer under the repository policy unless explicitly approved.
