## Summary

Keep open: current main and v2026.6.11 still keep normal runtime auth loads SQLite-only and route legacy `auth-profiles.json` import through doctor repair, while this report still needs maintainer direction on startup/update recovery or loud warnings plus dead fallback diagnostics.

## What This Changes

The issue asks OpenClaw to recover or loudly warn about stranded legacy JSON auth profiles after the 2026.6.x SQLite auth-store migration and to warn when configured fallback chains resolve to no usable model.

## Best Possible Solution

Keep steady-state runtime on SQLite, then add a maintainer-approved doctor/update/startup recovery path that detects stranded canonical auth JSON and reports unusable configured fallback providers before users discover silent failover loss.

## Reproduction Assessment

Yes at source level, but not with a live upgrade run. If canonical `auth-profiles.json` remains beside an empty per-agent SQLite store, current runtime does not read that JSON and current docs route import through `openclaw doctor --fix`.

## Solution Assessment

Unclear as a product choice: the failure is real, but the best fix needs maintainer direction on automatic startup/update migration versus a loud warning plus doctor repair. A steady-state runtime JSON fallback is not the best layer under current repository policy.
