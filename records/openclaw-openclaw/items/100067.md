## Summary

Current main still keeps runtime auth SQLite-only and ignores legacy `auth-profiles.json`; doctor can import that JSON, but startup/update does not loudly surface stranded profile names, and fallback-chain validation remains incomplete. Open related PRs cover partial or adjacent auth-migration repairs, but none are merged and sufficient to close this canonical issue.

## What This Changes

The issue reports that upgrading from JSON auth profiles to SQLite can leave OAuth/token provider credentials stranded and silently break configured model fallback chains.

## Best Possible Solution

Keep runtime SQLite-only, then add a maintainer-approved doctor/update/startup-visible detection or one-shot migration path for stranded canonical auth JSON, plus a startup/status diagnostic for configured fallback chains whose providers cannot resolve usable auth.

## Reproduction Assessment

Yes, at source level: current main's runtime auth load path reads SQLite and skips legacy `auth-profiles.json`, and the existing regression test locks that behavior. I did not run a live release-to-release Docker upgrade in this read-only review.

## Solution Assessment

Unclear as a product decision: the bug is real, but the best fix needs maintainer agreement on automatic migration versus loud startup/update diagnostics with doctor repair. A steady-state runtime JSON fallback conflicts with current repository policy and tests.
