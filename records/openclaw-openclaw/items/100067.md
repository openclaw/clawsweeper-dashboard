## Summary

Keep open: current main and the latest v2026.6.11 release still keep runtime auth-profile reads on SQLite only, while the JSON-to-SQLite import is a doctor repair path and the remaining startup/update diagnostic plus fallback-chain warning work is not fully implemented or safely superseded.

## What This Changes

The issue reports that upgrading from 2026.5.x to 2026.6.11 can leave existing JSON auth profiles outside the SQLite store, causing provider auth loss and silent model-fallback failure.

## Best Possible Solution

Keep runtime SQLite-only, but add a maintainer-approved update/startup detection or one-shot migration path for stranded canonical auth JSON profiles, then surface dead configured model fallback chains through startup/status diagnostics.

## Reproduction Assessment

Yes, at source level. Current main and v2026.6.11 do not read canonical auth-profiles.json during runtime auth-store loads, while doctor has the only JSON-to-SQLite import path; I did not run a live release-to-release upgrade.

## Solution Assessment

Unclear as an implementation choice. The bug is real, but maintainers need to choose the best boundary between automatic startup/update migration, loud warning plus doctor repair, and fallback-chain diagnostics; a steady-state runtime JSON fallback conflicts with current policy unless explicitly approved.
