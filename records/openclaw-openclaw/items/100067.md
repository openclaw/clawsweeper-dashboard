## Summary

Keep open: current main and v2026.6.11 still keep normal runtime auth reads on the per-agent SQLite store and explicitly do not read legacy `auth-profiles.json`; the existing doctor repair and overlapping open PRs do not fully settle the startup/update warning and fallback-chain diagnostic behavior.

## What This Changes

The issue asks OpenClaw to recover or loudly warn about legacy JSON auth profiles stranded by the 2026.6.x SQLite auth-store migration, and to diagnose dead configured fallback chains at startup.

## Best Possible Solution

Keep runtime auth SQLite-only, but add a maintainer-approved doctor/update/startup-visible detection or one-shot migration path for stranded canonical auth JSON, plus an operator warning when configured primary and fallback model refs resolve to providers with no usable auth.

## Reproduction Assessment

Yes, at source level. A legacy `auth-profiles.json` beside an empty per-agent SQLite store is ignored by current runtime loads, while the import path is wired through doctor repair rather than normal startup/update.

## Solution Assessment

Unclear as a final implementation choice. The problem is real, but maintainers need to choose between automatic startup/update migration, loud warning plus doctor repair, or a narrow hybrid; a steady-state runtime JSON fallback is not the best fit for current repository policy.
