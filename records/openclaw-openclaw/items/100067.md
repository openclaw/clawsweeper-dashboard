## Summary

Keep open: current main still uses SQLite as the runtime auth-profile store, keeps legacy `auth-profiles.json` import in doctor repair, and has an explicit runtime test that legacy JSON is not read. The open overlapping PR addresses part of the report but is not a safe canonical close target because its current approach changes the runtime credential-migration boundary.

## What This Changes

The issue asks OpenClaw to migrate or loudly warn about stranded JSON auth profiles after the SQLite auth-store migration, and to surface dead configured model fallback chains.

## Best Possible Solution

Keep runtime SQLite-only, but add a maintainer-approved doctor/update/startup-visible migration or warning path for stranded canonical auth JSON, plus a clear diagnostic when configured fallbacks resolve to no usable provider auth.

## Reproduction Assessment

Yes at source level: current main intentionally does not read `auth-profiles.json` at runtime, while doctor is the only inspected JSON-to-SQLite import path. I did not perform a live release-to-release upgrade in this read-only review.

## Solution Assessment

Unclear as an implementation choice: the recovery need is real, but the best fix needs maintainer direction on startup/update migration versus loud warning plus doctor repair. A steady-state runtime JSON fallback remains the wrong layer under current policy unless maintainers explicitly approve it.
