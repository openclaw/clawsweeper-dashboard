## Label Justifications

- `impact:auth-provider`: The affected state is provider OAuth/token auth profile migration into the new SQLite auth store.
- `impact:session-state`: The failure strands persisted per-agent auth state across an upgrade rather than preserving the user's existing agent setup.

## Summary

Keep this open. Current main has a doctor-owned path for importing legacy JSON auth profiles into SQLite and intentionally keeps runtime auth reads SQLite-only, but the reported upgrade/status failure remains actionable: stranded legacy profiles are not clearly surfaced in the startup/status path described here, and startup validation for fully dead fallback chains is still a distinct gap.

## What This Changes

The issue asks OpenClaw to migrate or loudly warn about legacy JSON auth profiles stranded by the SQLite auth-store migration, and to validate configured fallback chains when provider models disappear.

## Best Possible Solution

Add a doctor/startup/status health check that detects legacy auth JSON next to empty or missing per-agent SQLite auth rows, names affected profiles/providers, points to `openclaw doctor --fix`, and separately adds a focused model-fallback config health warning for fully unresolved configured fallback chains.

## Reproduction Assessment

Yes at source level for the auth-store half: current tests and docs show runtime no longer reads legacy `auth-profiles.json` and doctor is the intended import path. I did not establish a live 2026.5.28-to-2026.6.11 Docker upgrade repro or a real fallback-chain failure transcript.

## Solution Assessment

Unclear as written. Runtime JSON fallback is not the best fit because OpenClaw policy makes doctor/migration the owner for legacy state, but a loud startup/status warning plus a fallback-chain health check is a maintainable repair direction.
