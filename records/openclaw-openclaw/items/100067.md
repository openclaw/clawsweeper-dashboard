## Summary

Keep open: current main still uses SQLite as the only runtime auth store and the canonical JSON-to-SQLite import path is wired through doctor repair, while the inspected startup/update health paths do not migrate or loudly warn about stranded canonical `auth-profiles.json` files. Prior merged fixes cover migration verification and config-only default-agent imports, but they do not fully cover this report's first-run/update diagnostic and dead-fallback-chain warning request.

## What This Changes

The issue reports that upgrading from JSON auth profiles to SQLite leaves existing OAuth/token profiles unmigrated, causing provider auth and fallback model resolution to fail silently.

## Best Possible Solution

Keep runtime SQLite-only, but add a doctor/update/startup-visible detection path or safe pre-runtime migration for stranded canonical auth JSON profiles, and surface when configured primary/fallback model providers have no usable auth after migration.

## Reproduction Assessment

Yes at source level, but not with a live upgrade run. If canonical `auth-profiles.json` remains beside an empty per-agent SQLite store, current runtime does not read the JSON, and the inspected startup/update health paths do not run the canonical JSON-to-SQLite import.

## Solution Assessment

Unclear as an implementation choice: the issue is real, but the best fix needs maintainer direction on automatic startup migration versus a loud startup/update warning plus doctor repair. A steady-state runtime JSON fallback would be the wrong layer under the repository policy.
