## Summary

Keep open: current main still does not migrate canonical legacy `auth-profiles.json` during normal runtime auth loading, and the only built-in import path remains doctor repair. The linked lazy-import PR overlaps the auth-stranding half of the report, but it is still open and has unresolved runtime-boundary concerns, and it does not cover the fallback-chain startup diagnostic request.

## What This Changes

The issue reports that upgrading from JSON auth profiles to the SQLite auth store leaves existing provider credentials unread and causes configured model fallbacks to fail silently.

## Best Possible Solution

Keep runtime reads on canonical SQLite, but add maintainer-approved upgrade recovery or diagnostics that make stranded auth profiles and dead fallback chains visible before users lose failover.

## Reproduction Assessment

Yes at source level: current main's runtime auth-store load path does not import canonical `auth-profiles.json` when SQLite is empty, while the JSON-to-SQLite import path is wired through doctor repair. I did not run a live release-to-release Docker upgrade in this read-only review.

## Solution Assessment

Unclear as an implementation choice: the issue is valid, but the best fix needs maintainer direction on automatic startup migration versus a loud startup/update warning plus doctor repair. A steady-state runtime JSON fallback remains questionable under the repository policy.
