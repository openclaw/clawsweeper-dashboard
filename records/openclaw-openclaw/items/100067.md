## Summary

Keep open: current main still keeps runtime auth SQLite-only and does not read legacy `auth-profiles.json`, while the inspected doctor path is the migration owner and the startup/status paths still do not clearly migrate or warn about stranded canonical JSON auth profiles before provider fallbacks fail.

## What This Changes

The issue asks OpenClaw to migrate or loudly warn about stranded legacy JSON auth profiles after the SQLite auth-store upgrade, and to detect dead fallback chains caused by missing provider auth.

## Best Possible Solution

Keep steady-state runtime auth SQLite-only, but add a maintainer-approved doctor/update/startup-visible recovery path for stranded canonical auth JSON and surface when configured fallback providers are unusable because auth did not migrate.

## Reproduction Assessment

Yes, at source level: current main still ignores canonical `auth-profiles.json` during normal runtime auth loads when the SQLite store is empty. I did not run the full release-to-release Docker upgrade path in this read-only review.

## Solution Assessment

Unclear as an implementation choice: the issue is valid, but maintainers need to choose between a doctor/update/startup migration boundary and a loud warning plus guided repair. A steady-state runtime JSON fallback remains the riskier layer under current repository policy.
