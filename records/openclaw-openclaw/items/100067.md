## Summary

Keep open: current main still has SQLite as the only normal runtime auth store, while the canonical JSON-to-SQLite import is doctor-owned and not a first-run/update startup migration or loud stranded-auth warning. The open runtime-import PR #93352 overlaps the first ask but is unmerged and blocked on the runtime migration boundary, so it is not a safe close target.

## What This Changes

The issue requests upgrade recovery or warning for legacy JSON auth profiles stranded outside SQLite, plus startup visibility when configured fallback chains have no usable authenticated provider.

## Best Possible Solution

Keep steady runtime SQLite-only, then add a maintainer-approved startup/update diagnostic or safe migration boundary for stranded legacy auth JSON and surface fully dead configured fallback chains.

## Reproduction Assessment

Yes. Source inspection shows a stranded per-agent auth-profiles.json beside an absent or empty SQLite auth store is not read by the current runtime loader, while doctor is the only canonical JSON-to-SQLite import path checked here.

## Solution Assessment

Unclear as an implementation choice. The reported failure is real, but the best fix needs maintainer direction on startup/update migration versus loud warning plus doctor repair; a silent steady-state runtime JSON fallback would conflict with repository policy unless explicitly approved.
