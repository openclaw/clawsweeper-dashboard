## Summary

Keep open: current main and latest release still lack the requested opt-in coalescing or final-only delivery policy for tool-interleaved assistant text. The related open Discord PR targets ordering under streaming-off delivery, not the one-message coalescing behavior requested here.

## What This Changes

The issue requests an OpenClaw config-driven mode that merges text blocks interleaved with tool calls into one outbound channel message.

## Best Possible Solution

Keep this as the canonical reply-pipeline delivery-policy issue, choose opt-in coalescing or final-only semantics, then implement it across final payload assembly and block-streamed tool boundaries with schema, docs, and regression coverage.

## Reproduction Assessment

Yes, at source level. Current main still flushes block replies before tool execution, preserves assistant block boundaries, and has no requested turn-level coalescing or final-only config; I did not run live Telegram or BlueBubbles proof in this read-only review.

## Solution Assessment

Unclear until maintainers choose the delivery contract. A hold/defer or final-only mode is plausible, but it should be opt-in and must cover both final payload assembly and streamed tool-boundary flushing without breaking existing message-boundary semantics.
