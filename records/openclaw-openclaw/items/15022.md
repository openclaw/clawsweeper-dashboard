## Summary

Keep open: current main still lacks a shared opt-in coalescing or final-only delivery policy for tool-interleaved assistant text, and the related open Discord work addresses ordering rather than the one-message coalescing request.

## What This Changes

Request an opt-in setting or delivery policy that merges text blocks from one agent turn into one outbound channel message instead of multiple chat bubbles.

## Best Possible Solution

Choose an opt-in core reply delivery policy, then implement it across final payload assembly and block-streamed tool-boundary flushing with config schema, docs, and regression tests for text -> tool -> text turns.

## Reproduction Assessment

Yes, at source level. Current main still flushes block replies before tool execution, prevents generic coalescing across logical assistant blocks, and has no requested turn-level coalescing/final-only config; I did not run a live Telegram or BlueBubbles reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the delivery contract. A hold/defer or final-only mode is plausible, but it should be opt-in and must cover both final payload assembly and streamed tool-boundary flushing without breaking existing message-boundary semantics.
