## Summary

Keep open. Current main and v2026.6.11 still lack the requested opt-in coalescing or final-only delivery policy; existing coalescing only merges streamed chunks, tool-start still flushes block replies, and the pipeline intentionally preserves logical assistant block boundaries.

## What This Changes

Request an opt-in mode that merges tool-interleaved assistant text blocks from one agent turn into one outbound channel message instead of rapid-fire Telegram/iMessage bubbles.

## Best Possible Solution

Keep this as the canonical reply-pipeline delivery-policy issue, then implement an opt-in coalescing or final-only mode covering final payload assembly and block-streamed tool boundaries with schema, docs, and regression coverage.

## Reproduction Assessment

Yes, at source level. Current main still flushes block replies before tool execution and intentionally avoids coalescing logical assistant blocks; I did not run a live Telegram or BlueBubbles reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the delivery contract. A hold/defer or final-only mode is plausible, but it should be opt-in and must cover final payload assembly plus block-streamed tool boundaries without breaking existing message-boundary semantics.
