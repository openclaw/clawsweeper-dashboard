## Summary

Keep open. Current main partially improves final-payload collapse, but it still lacks the requested opt-in coalescing or final-only delivery policy; the block-streamed path still flushes at tool boundaries and current coalescer coverage intentionally preserves separate logical assistant blocks.

## What This Changes

Request an opt-in agent or channel delivery mode that coalesces text blocks interleaved with tool calls into one outbound message instead of many chat notifications.

## Best Possible Solution

Keep this as the canonical reply-pipeline delivery-policy issue, then implement an opt-in coalescing or final-only mode with schema, docs, and regression coverage after maintainers choose the semantics.

## Reproduction Assessment

Yes, at source level. Current main still flushes block replies before tool execution and intentionally avoids coalescing logical assistant blocks; I did not run a live Telegram or BlueBubbles reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the delivery contract. A hold/defer or final-only mode is plausible, but it should be opt-in and must cover final payload assembly plus block-streamed tool boundaries without breaking existing message-boundary semantics.
