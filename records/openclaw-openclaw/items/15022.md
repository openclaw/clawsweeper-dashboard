## Summary

Keep open: current main still lacks the requested opt-in coalescing or final-only delivery policy for tool-interleaved assistant text, and the related open Discord work targets ordering rather than one-message coalescing.

## What This Changes

The issue requests an opt-in mode to merge text blocks from one tool-interleaved agent turn into a single outbound channel message.

## Best Possible Solution

Keep this as the canonical reply-pipeline delivery-policy issue, choose opt-in coalescing or final-only semantics, then implement it across final payload assembly and block-streamed tool boundaries with schema, docs, and regression coverage.

## Reproduction Assessment

Yes, at source level. Current main still flushes block replies before tool execution, avoids cross-assistant-block coalescing, and has no requested turn-level coalescing/final-only config; I did not run a live Telegram or BlueBubbles reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the delivery contract. A hold/defer or final-only mode is plausible, but it should be opt-in and must cover both final payload assembly and streamed tool-boundary flushing without breaking existing message-boundary semantics.
