## Summary

Keep open: current main and the latest release still lack the requested opt-in coalescing or final-only policy for tool-interleaved assistant text, and the open related Discord PR targets message ordering rather than one-message coalescing.

## What This Changes

Request an opt-in delivery mode that merges or finalizes tool-interleaved assistant text blocks into one outbound channel message instead of many short messages.

## Best Possible Solution

Keep this as the canonical reply-pipeline delivery-policy issue, choose opt-in coalescing or final-only semantics, then implement it across final payload assembly and streamed tool boundaries with schema, docs, and regression coverage.

## Reproduction Assessment

Yes, at source level. Current main has no requested coalescing/final-only config, final payloads can still preserve multiple assistant text payloads, and block-streamed tool boundaries still flush rather than hold; I did not run a live Telegram or BlueBubbles reproduction in this read-only review.

## Solution Assessment

Unclear until maintainers choose the delivery contract. A hold/defer or final-only mode is plausible, but it should be opt-in and must cover both final payload assembly and streamed tool-boundary flushing without breaking existing message-boundary semantics.
