## Summary

Keep open for central security review. Current main intentionally evicts older exact-value redaction entries, active SecretRef-derived credentials use the same process-global registry, and existing tests confirm that an evicted value is no longer masked; no canonical duplicate or active fix PR was found.

## What This Changes

Prevent still-active system and provider credentials from losing exact-value log redaction when the bounded registry experiences sustained churn.

## Best Possible Solution

Introduce lifecycle-owned registration handles that pin every raw and transformed form while a credential is active, remove them on rotation or owner teardown, preserve explicit memory and matcher bounds, and add pressure tests covering logs, proxy capture, and support exports.

Question: Should exact-value redaction guarantee retention for every still-active credential, and which runtime owner must deregister its raw and transformed forms when validity ends?

Rationale: Current recency-based eviction conflicts with credential validity; selecting retention ownership, teardown behavior, and safe resource bounds requires explicit security-owner intent.

Likely owner: steipete

Owner confidence: high

Options:

- **Owner-scoped retention (recommended):** Return registration handles or scopes that pin active credential forms and remove them when the SecretRef snapshot, provider auth state, worker, or process-lifetime owner ends or rotates.
- **Protected permanent tier:** Create a separately bounded non-evictable class for explicitly identified process-lifetime credentials while transient registrations remain evictable.
- **Keep best-effort semantics:** Retain current eviction and explicitly accept that exact-value masking can stop before credential expiry.

## Reproduction Assessment

Yes at source level: current main and its tests deterministically show the oldest exact value becoming unmasked after registry pressure, while active SecretRef and provider credentials use that pool. This read-only review did not generate a live plaintext diagnostic artifact.

## Solution Assessment

No. The proposed permanent-registration API identifies the right invariant but is underspecified; lifecycle-scoped pinning with explicit deregistration is a narrower bounded design.
