## Label Justifications

- `P0`: The report describes a gateway startup crash-loop after following OpenClaw's own model recovery guidance.
- `impact:crash-loop`: Applying the suggested config made the gateway fail validation and crash-loop at startup.
- `impact:auth-provider`: The underlying path is OpenAI/Codex auth, provider routing, and model choice after provider catalog/auth state changed.
- `impact:ux-release-blocker`: A user following in-product/runtime guidance can end up unable to boot the gateway without manual config recovery.
- `maturity:stable`: The crash-loop affects stable gateway startup/lifecycle and CLI doctor/recovery surfaces scored M4 in `qa/maturity-scores.yaml`.

## Summary

Current main already fixes the central user problem: runtime-bound OpenAI/Codex model failures no longer tell operators to add a `models.providers[]` row, so the bad guidance that led to the rejected config and gateway crash-loop is obsolete on main. The fix is not in the latest release tag I checked, so this is current-main-only cleanup rather than shipped-release cleanup.

## What This Changes

The issue reports an OpenAI/Codex provider model error that suggests a `models.providers.openai-codex.models[]` config edit which v2026.6.11 then rejects during gateway startup.

## Best Possible Solution

Keep the current-main runtime-bound hint and model-unavailable classifier, and let the next release carry that recovery behavior to v2026.6.11 users.

## Reproduction Assessment

Yes for the shipped release path by source inspection: `v2026.6.11` still contains the old `models.providers[]` registration hint, while current main has the corrected runtime-bound hint. I did not run a live Docker/OAuth reproduction because the source and tag comparison are sufficient for this cleanup decision.

## Solution Assessment

Yes: the merged main fix is the narrow maintainable solution for this issue because it changes the operator hint at the model-resolution boundary and keeps custom-provider registration guidance for non-runtime providers. Auth-migration discoverability remains separately tracked in https://github.com/openclaw/openclaw/issues/95136.
