## Summary

Keep open: current main still has the reported contradictory source path, and the open candidate PR is not merged and has already been reviewed as missing the exact legacy `openai-codex` reproduction path.

## What This Changes

The issue asks OpenClaw to stop telling operators to add a provider-model config overlay when a bundled or legacy auth-gated provider model is missing and that overlay would be rejected at startup.

## Best Possible Solution

Update the model-not-found hint path to route legacy `openai-codex` and bundled auth-gated misses to doctor/auth guidance while preserving the custom-provider config hint.

## Reproduction Assessment

Yes, at source level: current main still emits the generic provider-registration hint for configured model entries without `agentRuntime`, while current validation rejects `models.providers.openai-codex` without `baseUrl`. I did not run a live Docker crash-loop reproduction.

## Solution Assessment

Yes for the issue direction: fix the misleading runtime guidance and keep `openai-codex` as legacy migration input. The current open PR is only a partial implementation until it covers the reported legacy path.
