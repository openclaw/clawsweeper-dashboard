## Summary

Keep open: current main still has a source-level path where the model resolver can prescribe a `models.providers["openai-codex"]` registration while config validation rejects that legacy provider overlay, and the related OpenAI/Codex migration issues do not directly own this exact diagnostic contradiction.

## What This Changes

The issue asks OpenClaw to fix misleading provider model-registration guidance so missing OpenAI/Codex auth or legacy `openai-codex` routes do not lead operators into a config edit that fails gateway startup validation.

## Best Possible Solution

Keep `openai-codex` as legacy migration input, leave the validator fail-closed for unsupported overlays, and change the unknown-model diagnostic to point users toward canonical `openai` auth/status/doctor recovery instead of adding `models.providers.openai-codex`.

## Reproduction Assessment

Yes at source level: current main still emits the registration hint when `agents.defaults.models` contains the requested ref, while the config schema still rejects the reported `models.providers.openai-codex` overlay without `baseUrl`. I did not run the full Docker gateway reproduction in this read-only review.

## Solution Assessment
