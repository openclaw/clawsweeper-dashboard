Keep open: current main and the latest release still have the contradictory recovery path, and an open linked PR now appears to be the candidate fix but has not merged yet. The issue should remain the canonical tracker until that PR lands or maintainers choose a different fix.

## What This Changes

The issue asks OpenClaw to stop telling operators to add a `models.providers[...]` model entry for a legacy/bundled auth-gated provider when that same config shape is rejected at startup.

## Best Possible Solution

Land one focused fix that keeps `openai-codex` legacy-only, changes the unknown-model hint for legacy/bundled auth-gated misses to point at `openclaw doctor --fix`, `openclaw models status`, and OpenAI auth, then close this issue after the fix merges.

## Reproduction Assessment

Yes, at source level: current main still emits the generic `models.providers[...]` registration hint for unresolved configured model entries without `agentRuntime`, and current validation rejects `models.providers.openai-codex` without `baseUrl`. I did not run the live Docker crash-loop path.

## Solution Assessment

Yes, the best narrow fix is to change the misleading runtime guidance and keep `openai-codex` as legacy migration input, not to make `openai-codex` a new live provider overlay.
