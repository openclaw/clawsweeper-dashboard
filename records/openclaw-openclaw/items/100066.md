## Summary

Keep open: current main and the latest release still contain the contradictory path where an unresolved configured `openai-codex` model can get the generic `models.providers[...]` registration hint, while the validator rejects that same legacy provider overlay without `baseUrl`. The linked fix PR https://github.com/openclaw/openclaw/pull/100104 is a viable candidate but is still open, so this issue remains necessary until that PR or an equivalent fix lands.

## What This Changes

The issue asks OpenClaw to stop giving provider-model registration guidance that can lead operators to an invalid legacy `openai-codex` config and gateway startup crash-loop when the real recovery path is provider auth/status repair.

## Best Possible Solution

Review and land https://github.com/openclaw/openclaw/pull/100104 or an equivalent focused fix that routes legacy `openai-codex` missing-model errors to doctor/models-status/auth guidance while preserving the custom-provider config hint.

## Reproduction Assessment

Yes at source level: current main and `v2026.6.11` still emit the generic provider-registration hint for unresolved configured model entries, and current validation rejects `models.providers.openai-codex` without `baseUrl`. I did not run the Docker crash-loop path live.

## Solution Assessment

Yes for the direction: the narrow maintainable fix is to change the misleading runtime guidance and point legacy/auth-gated `openai-codex` misses to doctor/models status/auth recovery, not to reintroduce `openai-codex` as a live provider overlay. The linked PR is a candidate but has not merged yet.
