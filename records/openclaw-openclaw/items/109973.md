## Summary

Keep this PR open. Current `main` still sends the initial ACP snapshot before returning both lifecycle results, so the central fix remains necessary; however, the deferred callbacks can outlive a session that was closed immediately after the result, and the PR still lacks real affected-client proof.

## What This Changes

The PR defers initial ACP session snapshot and available-command notifications until after `newSession` and `resumeSession` return their JSON-RPC results, adding lifecycle and NDJSON ordering tests.

## Best Possible Solution

Keep result-before-notification ordering, but route deferred initial notifications through lifecycle-owned cancellation or an active-session identity guard, then prove new and resumed sessions with a real ACP client and clear the relevant check failure.
