## Summary

Keep this PR open, but do not merge yet: the intended response-ordering fix is useful and its test coverage is substantial, while the new close guard still permits a stale callback when the same ACP session ID is closed and resumed before the timer fires. It also still needs an after-fix ACP client/process proof rather than only in-process test output.

## What This Changes

The branch defers initial ACP snapshot and available-command notifications from `newSession` and `resumeSession`, adds a close-before-timer guard, and adds lifecycle and NDJSON ordering tests.

## Best Possible Solution

Capture the session instance or a lifecycle generation when scheduling each callback, verify that the currently stored session is that exact instance before emitting, add a close-then-resume-same-ID regression test, and provide a redacted real ACP client/process transcript showing result-before-notification ordering.

Yes, from source: call `newSession` or `resumeSession`, close that session, resume the same session ID before the queued timer runs, then flush timers. The callback's presence-only check accepts the replacement session and can emit the previous lifecycle snapshot.
