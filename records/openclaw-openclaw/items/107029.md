## Summary

Keep this issue open for a narrower maintainer design decision: current main already has durable TTL-backed plugin state plus agent-local cache tables, but whether external plugins should receive an agent-scoped SDK facade remains unresolved.

## What This Changes

Add an agent-scoped, TTL-capable Plugin SDK cache API backed by the per-agent SQLite database and document that inter-turn plugin state must not rely on process memory.

## Best Possible Solution

Extend the existing plugin-state contract with an explicit agent-scoped namespace or store only if concrete plugin audits prove it cannot express the required lifecycle; avoid introducing a parallel cache API and table.
