## Summary

Current main has a restart-safe, TTL-capable SQLite keyed store, but it is plugin-scoped and restricted to bundled or trusted official plugins. This issue requests a distinct public contract that associates state with an agent and exposes it to external plugins, so it should remain open for SDK and security-direction review rather than adding a parallel cache API without a concrete consumer.

**Likely related people**
- @amknight — high confidence: introduced the existing SQLite plugin state store and contributed related restart-safe plugin state work.
- @vincentkoc — medium confidence: recent contributor across plugin SDK, externalization, installation trust, and compatibility boundaries.

## What This Changes

Add an external-plugin cache facade backed by per-agent SQLite tables with TTL-based transient state retention.

## Best Possible Solution

Extend the existing keyed-store contract only after a concrete plugin use case establishes that agent scoping is required; preserve one canonical API and specify principal binding, trust entitlement, quotas, TTL and eviction, cleanup, agent deletion, and cross-agent sharing before selecting shared or per-agent SQLite ownership.

- **Keep external ownership:** Require ordinary external plugins to own their persistence and reserve host SQLite stores for bundled or trusted official plugins.
