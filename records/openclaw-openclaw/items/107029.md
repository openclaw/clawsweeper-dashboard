## Summary

Keep this issue open for a focused maintainer API decision. Current main provides durable shared plugin state with TTL and persistent session-extension state, but neither clearly establishes a general agent-scoped cache contract for external plugins; the report also provides no affected-plugin reproduction proving those existing surfaces are insufficient.

## What This Changes

Add a Plugin SDK cache facade backed by agent-scoped SQLite and discourage in-memory inter-turn plugin state.

## Best Possible Solution

Establish one documented plugin-state decision tree: use shared plugin-state TTL rows for plugin-owned cache, session extensions for session-bound workflow state, and add an agent-scoped SDK contract only if a concrete plugin demonstrates lifecycle requirements those surfaces cannot satisfy.
