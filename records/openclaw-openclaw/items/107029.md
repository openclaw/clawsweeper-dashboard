Keep this issue open for a focused maintainer API decision. Current main already exposes durable plugin-owned SQLite state and agent-database helpers, but it does not establish that external plugins should receive a shared agent-scoped cache facade; the report also lacks a concrete affected-plugin reproduction proving that the existing state surface is insufficient.

## What This Changes

The issue requests a TTL-aware Plugin SDK cache facade backed by per-agent SQLite storage, plus documentation prohibiting in-memory inter-turn state.

## Best Possible Solution

Define one documented plugin-state contract that selects the correct owner and scope: either extend the existing plugin-state runtime with explicit optional agent scoping and TTL semantics, or document it as the canonical plugin-owned store; keep physical agent-database tables private behind that contract and include isolation, cleanup, quota, upgrade, and lifecycle tests.
