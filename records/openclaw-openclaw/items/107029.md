## Summary

Keep this issue open for a maintainer security-boundary decision. Current main already offers restart-safe, TTL-capable SQLite keyed storage for trusted plugins, but a public agent-scoped cache is a distinct SDK and isolation contract; the report does not identify a concrete affected plugin or failing current-main workflow. ([github.com](https://github.com/openclaw/openclaw/blob/main/docs/plugins/sdk-runtime.md))

## What This Changes

Add a Plugin SDK cache facade backed by agent-scoped SQLite and document SQLite as the required store for inter-turn plugin state.

## Best Possible Solution

First inventory concrete plugin use cases; if agent ownership is genuinely required, extend the existing `api.runtime.state` contract with an explicit host-validated agent-scoped store, retaining plugin isolation, quotas, TTLs, backup behavior, and deletion tests rather than adding a parallel `context.cache` facade.

- **Expose a general cache:** Add the proposed generic cache facade for external plugins, accepting a broader public API and security surface.
