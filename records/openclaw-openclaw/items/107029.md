## Summary

Keep this issue open for a maintainer product and security-boundary decision. Current main already provides durable, TTL-capable SQLite keyed storage for trusted plugins, but installed third-party plugins cannot use it and the existing surface is plugin-scoped rather than explicitly agent-scoped. Likely related people: steipete for recent plugin-state SQLite migrations and vincentkoc for shared state-migration work, both with medium confidence.

## What This Changes

Add an agent-scoped, SQLite-backed Plugin SDK cache API for transient plugin state that should survive Gateway and agent restarts.

## Best Possible Solution

Extend the existing keyed-store contract rather than add a parallel cache facade: define explicit plugin-global and agent-scoped store modes, capability-based access for installed plugins, namespace and quota enforcement, lifecycle cleanup semantics, and focused SDK/security/upgrade documentation and tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should installed third-party plugins receive durable SQLite keyed storage, and if so should the existing keyed-store API gain an explicit agent-scoped mode rather than introducing a separate `context.cache` contract?

Rationale: The current restriction to bundled and trusted official plugins is an intentional capability boundary, while choosing shared plugin KV versus per-agent storage determines data isolation, quotas, lifecycle cleanup, and the permanent public SDK contract.

Likely owner: steipete

Owner reason: Recent merged plugin-state SQLite migrations make this the strongest available routing signal for the storage ownership and migration side of the decision.

Owner confidence: medium

Options:

- **Extend Existing Store Safely (recommended):** Add an explicit agent-scoped mode to `api.runtime.state.openKeyedStore` with declared capabilities, quotas, isolation, and lifecycle tests before allowing installed plugins to use it.
- **Keep Trusted-Only Storage:** Retain the current trusted-plugin restriction and require ordinary external plugins to own their persistence outside the privileged runtime storage facade.
- **Add Separate Cache API:** Introduce `context.cache` as a distinct agent-context surface, accepting the maintenance and conceptual cost of overlapping keyed-storage contracts.
