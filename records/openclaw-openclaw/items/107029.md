## Summary

Keep this issue open for a maintainer storage-boundary decision. Current main already provides durable, namespaced SQLite plugin state with TTL support, but the proposed agent-scoped cache would add a parallel, compatibility- and security-sensitive Plugin SDK contract. Likely related people: @100yenadmin for recent session-oriented Plugin SDK work and @vincentkoc for recent plugin lifecycle work, both with medium confidence.

## What This Changes

Requests a Plugin SDK cache facade backed by agent-local SQLite, plus documentation prohibiting in-memory Maps for inter-turn plugin state.

## Best Possible Solution

Keep one canonical SQLite plugin-state facade with TTL and explicit namespace keys; document agent/session keying and migration guidance, and add agent-local storage only if maintainers first define a restricted capability, lifecycle, quota, and isolation contract.
