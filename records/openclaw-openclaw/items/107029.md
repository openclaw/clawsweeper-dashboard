## Summary

Keep this issue open for maintainer product and security-boundary review. Current main already offers durable SQLite-backed plugin-global keyed storage, but agent-scoped storage would be a distinct public SDK contract with unresolved identity, authorization, isolation, quota, and migration semantics.

## What This Changes

Add a Plugin SDK cache facade backed by agent-scoped SQLite tables for transient plugin state that must survive process restarts.

## Best Possible Solution

Define one canonical SDK storage abstraction with runtime-bound plugin and agent identity, explicit cache-versus-persistent semantics, TTL and quota enforcement, and isolation tests before selecting the backing schema or migration path.

- **Add a separate cache facade:** Introduce `context.cache` as a distinct API with independently specified retention, eviction, authorization, and migration behavior.

- A public agent-scoped store could expose or corrupt another agent's state unless agent identity and plugin authorization are bound and checked by the runtime rather than accepted as arbitrary caller input.
