## Summary

Keep open: current main has cost reporting and a shipped plugin-level run block hook, but it still lacks native per-agent spend-budget config, durable budget admission/reservation state, receipts, and status/doctor enforcement.

## What This Changes

The issue requests optional per-agent daily/monthly cost budgets enforced before gateway model dispatch, with block/warn/pause behavior and operator-visible budget status.

## Best Possible Solution

Use this issue as the canonical design tracker for opt-in pre-dispatch budget admission backed by durable accounting/reservations and operator-visible status/doctor UX, or explicitly choose a plugin/API-only boundary.

Owner confidence: medium

Options:

- **Native core admission layer (recommended):** Add opt-in per-agent budgets as a core pre-dispatch path with durable SQLite accounting, reservations/refunds, receipts, and status/doctor surfaces.
- **Plugin/API-first boundary:** Extend the plugin/admission contract enough for external budget systems to enforce before dispatch while core stays limited to generic hooks and observability.
- **External controls only:** Document provider account limits, LiteLLM-style virtual keys, and external proxies as the supported spend-control path and decline native enforcement for now.
