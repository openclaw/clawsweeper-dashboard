## Summary

Keep open: current main and v2026.6.11 still expose cost reporting and plugin-level pre-run blocking, but not native per-agent budget config, durable reservations, pre-dispatch model-call admission, budget receipts, or status/doctor enforcement UX.

## What This Changes

Request optional per-agent daily/monthly cost budgets enforced before gateway model dispatch.

## Best Possible Solution

Use #42475 as the canonical design tracker for an opt-in core budget admission layer with durable SQLite accounting/reservations/receipts and status/doctor UX, or explicitly choose a plugin/API-only boundary.

Options:

- **Native core admission layer (recommended):** Add opt-in per-agent budgets as a core pre-dispatch admission path with durable SQLite accounting, reservations/refunds, receipts, and status/doctor surfaces while allowing plugins to observe or contribute policy.
- **Plugin/API-first boundary:** Extend the plugin/admission contract enough for external budget systems to enforce before dispatch and keep OpenClaw core limited to generic hooks and observability.
- **External/provider controls only:** Defer native enforcement and document provider accounts, balances, and external proxies as the supported budget-control path.

## Reproduction Assessment

Yes at source level: current schemas lack budget fields and the provider/usage paths report costs after the fact; the existing before_agent_run hook can block plugin-owned runs but is not a native budget ledger or admission policy.

## Solution Assessment

Unclear until maintainers choose the boundary; a one-off schema knob over transcript summaries would not be the best fix because concurrency, fallback, reservations, estimates, and receipts need one canonical policy.
