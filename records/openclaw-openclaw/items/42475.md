## Summary

Keep open: current main and v2026.6.11 still provide usage/cost reporting, provider budget display, reactive cooldowns, and a plugin pre-run block hook, but not native per-agent spend-budget config, durable reservations/ledger, gateway model-call admission, receipts, or status/doctor budget UX.

## What This Changes

Request optional per-agent daily/monthly spend budgets enforced before gateway model dispatch, with block/warn/pause behavior and operator status/doctor visibility.

## Best Possible Solution

Use this issue as the canonical design tracker for an opt-in budget admission layer before model dispatch, backed by durable accounting/reservations and operator-visible status/doctor UX, or explicitly choose a plugin/API-only boundary.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should OpenClaw implement native core per-agent spend-budget enforcement, expose only a budget-capable plugin/admission API, or leave spend limits to external/provider-account controls?

Rationale: The remaining work changes config/default surface, provider dispatch policy, persistent accounting state, and operator UX, so automation cannot safely choose the permanent product boundary.

Likely owner: steipete

Owner reason: steipete has the strongest observed connection to current schema/gateway lines and adjacent core runtime guardrail design, though implementation history is shared.

Owner confidence: medium

Options:

- **Native core admission layer (recommended):** Add opt-in per-agent budgets as a core pre-dispatch admission path with durable SQLite accounting, reservations/refunds, receipts, and status/doctor surfaces, while allowing plugins to observe or contribute policy.
- **Plugin/API-first boundary:** Extend the plugin/admission contract enough for external budget systems to enforce before dispatch and keep OpenClaw core limited to generic hooks and observability.
- **External/provider controls only:** Close or defer native enforcement and document provider accounts, balances, LiteLLM, ClawRouter, and external proxies as the supported budget-control path.

## Reproduction Assessment

Yes at source level: current main has cost reporting and plugin blocking, but no native per-agent budget schema, durable budget state, reservation, or model-call admission gate.

## Solution Assessment

Unclear until maintainers choose the boundary; the best fix should be a canonical core admission/accounting design or a deliberate plugin API, not a one-off schema knob over transcript summaries.
