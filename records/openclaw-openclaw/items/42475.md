## Summary

Keep open: current main and v2026.6.11 still provide usage/cost reporting, reactive provider cooldown/failover handling, and a plugin-level block hook, but not native per-agent spend-budget config, durable budget reservations, pre-dispatch cost admission, receipts, or operator UX.

## What This Changes

The issue requests optional per-agent daily/monthly cost budgets enforced by the gateway before model calls are dispatched.

## Best Possible Solution

Use #42475 as the canonical design tracker for an opt-in budget admission layer before model dispatch, backed by durable accounting/reservations and operator-visible status/doctor UX, or explicitly choose a plugin/API-only boundary.

Owner confidence: medium

Options:

- **Native core admission layer (recommended):** Add opt-in per-agent budgets as a core pre-dispatch admission path with durable SQLite accounting, reservations/refunds, receipts, and status/doctor surfaces, while allowing plugins to observe or contribute policy.
- **Plugin/API-first boundary:** Extend the plugin/admission contract enough for external budget systems to enforce before dispatch, and keep OpenClaw core limited to generic hooks and observability.
- **External/provider controls only:** Close or defer native enforcement and document provider accounts, balances, and external proxies as the supported budget-control path.

Yes at source level: current main has cost reporting and plugin blocking, but no native per-agent budget schema, durable budget state, reservation, or model-call admission gate.

## Solution Assessment

Unclear until maintainers choose the boundary; the best fix should be a canonical core admission/accounting design or a deliberate plugin API, not a one-off schema knob over transcript summaries.
