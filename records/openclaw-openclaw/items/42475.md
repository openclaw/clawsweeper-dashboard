## Summary

Keep open: current main still has reporting and a plugin block primitive, but it does not provide native per-agent spend-budget config, durable pre-dispatch reservations, reset-window semantics, budget receipts, or status/doctor enforcement UX.

## What This Changes

Request optional daily/monthly per-agent cost budgets enforced before gateway model dispatch, with block/warn/pause behavior and operator-visible status.

## Best Possible Solution

Keep this as the canonical design tracker until maintainers choose native core admission or a budget-capable plugin/API boundary, then implement durable SQLite accounting, reservations/refunds, receipts, and operator UX together.

Rationale: The remaining work sets new config, provider dispatch policy, persistent accounting state, fallback behavior, and operator-facing status/doctor UX, so automation cannot safely choose the permanent product boundary.

Options:

- **Native Gateway Admission (recommended):** Add opt-in per-agent budgets in core with durable reservations/refunds, budget receipts, reset windows, status/doctor surfaces, and plugin observability hooks.
- **Plugin/API Boundary First:** Extend the plugin/admission contract enough for budget systems to refuse model dispatch before spend while core stays limited to generic hooks and reporting.
- **External Controls Only:** Document provider quotas, separate accounts, local proxies, and external budget systems as the supported path without adding core budget config.

Yes, at source level. Current schemas and reporting paths show no native per-agent budget config or pre-dispatch spend admission gate, while existing usage cost code aggregates transcript usage after calls complete.

## Solution Assessment

Unclear until maintainers choose the ownership boundary. A schema-only budget knob over transcript summaries would be insufficient because reservations, refunds, unknown pricing, fallback behavior, and receipts need one canonical design.
