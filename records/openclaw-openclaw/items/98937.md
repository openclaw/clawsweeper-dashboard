## Summary

Keep open: the PR uses the right public bounded-reader helper, but as submitted an over-cap 409 ownership conflict throws before returning the cancellation result and the existing outer catch then allows the Slack send.

## What This Changes

The branch replaces thread-ownership's 409 `resp.json()` read with `readProviderJsonResponse` and adjusts the adjacent 409 unit-test response headers.

## Best Possible Solution

Keep the public SDK bounded-reader direction, but make HTTP 409 cancellation status-authoritative with best-effort owner parsing and land one canonical thread-ownership fix.

## Reproduction Assessment

Yes, source-level. Current main reaches an unbounded 409 `resp.json()` before cancellation, and the PR head reads capped JSON before returning cancel, so an over-cap 409 throws into the existing fail-open catch.

## Solution Assessment

No as submitted. The helper and import boundary are right, but the best fix is to cancel on the 409 status regardless of owner-body parse success and use the body only for best-effort logging.
