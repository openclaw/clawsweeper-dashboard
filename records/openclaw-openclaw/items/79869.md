## Summary

Keep open: the linked bug is still real on current main and the latest release, but this PR is not merge-ready because it overrides explicit `target: "none"`, can strand deferred zero-interval exec wakes, lacks real behavior proof, and is currently merge-conflicting.

## What This Changes

The PR changes `src/infra/heartbeat-runner.ts` and two heartbeat-runner tests so targeted `exec-event` wakes can run when `heartbeat.every` resolves to `0m`.

## Best Possible Solution

Refresh or replace the branch with a narrow fix that runs targeted zero-interval exec completions while preserving explicit delivery suppression, owning fallback cooldown retries, and proving the real gateway behavior.

## Reproduction Assessment

Yes at source level: current main and `v2026.6.11` resolve `heartbeat.every: "0m"` to no interval and skip `runHeartbeatOnce`, while background exec completion still enqueues an `exec-event` wake. I did not run a live gateway scenario in this read-only review.

## Solution Assessment

No. The heartbeat runner boundary is plausible, but this implementation should preserve outbound delivery authorization separately from exec completion visibility and give fallback cooldown deferrals retry ownership.
