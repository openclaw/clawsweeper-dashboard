## Summary

Keep open: the timeout wrapper improves the parent-token probe, but when that timeout wins it still returns a fork decision and current fork callers then read the parent transcript, so the availability/session-state bug is not fixed yet.

## What This Changes

The branch adds a fresh-token fast path, a 1s timeout around parent-fork token counting, and regression tests for fresh, timed-out, and oversized parent-fork decisions.

## Best Possible Solution

Make unresolved parent sizing choose a bounded non-fork path, or bound the subsequent transcript-copy read too, while preserving the fresh-token fast path and oversized-parent behavior.

## Reproduction Assessment

I did not run a live slow-filesystem reproduction in this read-only review.

## Solution Assessment

No: bounding the token probe is the right direction, but timeout-to-fork does not yet bound or avoid the later transcript read and can bypass the oversized-parent policy. The safer fix is to avoid fork on unresolved sizing or bound the transcript-copy path as well.
