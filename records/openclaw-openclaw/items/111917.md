## Summary

Keep this PR open: clearing a timeout is a useful parity fix, but the agent-facing patch schema still accepts a null timeout for `script` payloads that the gateway update contract does not accept. It also needs after-fix real behavior proof before merge.

## What This Changes

Adds `openclaw cron edit <job> --clear-timeout-seconds` and carries a nullable timeout marker through cron update validation, normalization, merging, tool schemas, tests, prompt snapshots, and CLI documentation.

## Best Possible Solution

Restrict nullable timeout clearing to `agentTurn` and `command` update payload variants, add regression coverage for rejecting a script clear, then attach redacted terminal proof showing an existing job’s timeout is removed without recreating the job.
