## Summary

Keep this PR open. Its clear-marker design is coherent for agent-turn and command jobs, and it fixes the earlier create-versus-patch schema issue, but the tool-facing update schema still accepts `timeoutSeconds: null` for script payloads even though the supported Gateway patch variants only permit that clear for agent-turn and command payloads. The contributor also still needs redacted after-fix CLI or runtime proof; reported tests and CI are supplemental, not real behavior proof.

## What This Changes

Adds `openclaw cron edit <job> --clear-timeout-seconds` and patch-only nullable timeout handling so existing agent-turn or command cron jobs can remove a stored timeout override without being recreated.

## System Context

Cron edits begin in the CLI or agent cron tool, pass through Gateway request validation, then normalize and merge into a persisted cron payload. Removing a timeout override changes whether the subsequent cron run uses a per-job timeout or the normal runtime timeout precedence.

## Architecture Diagram

flowchart LR

  B --> C[Payload patch validation]
  C --> D[Payload normalization]
  D --> E[Payload merge]
  E --> F[Persisted cron job]
  F --> G[Normal timeout precedence]

## Best Possible Solution

Keep nullable timeout clears limited to agent-turn and command update payloads at every boundary, explicitly reject script-job clears before the Gateway call, and add redacted live CLI or runtime proof that a stored timeout is removed without altering the rest of the payload.
