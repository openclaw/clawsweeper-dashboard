## Summary

This PR is still necessary, but it is not ready to merge: its tool-facing update schema accepts `timeoutSeconds: null` for script cron payloads even though the gateway update contract supports timeout clears only for agent-turn and command payloads. It also still has only test/CI evidence, not after-fix runtime proof.

## What This Changes

Adds `openclaw cron edit <job> --clear-timeout-seconds` and nullable update-patch handling so existing agent-turn and command cron jobs can remove a stored payload timeout override.

## System Context

Cron editing reads an existing scheduled job, builds a payload patch, and sends it through the gateway validator to the cron service. The resulting stored job payload controls the timeout used when the scheduler later runs an agent turn or command.

## Architecture Diagram

flowchart LR
  A[CLI or agent cron edit request] --> B[Read existing cron job]
  B --> C[Build payload update patch]
  C --> D[Gateway validates patch]
  D --> E[Cron service merges payload]
  E --> F[Stored cron job]
  F --> G[Scheduled agent or command run]

## Best Possible Solution

Restrict nullable timeout clears at the tool boundary to existing agent-turn and command jobs, retain numeric-only script timeout updates, add a script regression test, then provide redacted live CLI or runtime evidence that a stored timeout is removed without recreating the job.
