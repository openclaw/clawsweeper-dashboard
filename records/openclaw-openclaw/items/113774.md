## Summary

Current main documentation describes the inverse of the reported beta behavior: plugin install metadata belongs in managed state, and legacy `plugins.installs` config is read without rewriting `openclaw.json`. That strongly suggests the reported beta regression has been addressed, but this read-only review could not establish the fixing commit and release/main-only provenance required for an implemented-on-main close. ## What This Changes

Fix the beta regression where Gateway boot writes `plugins.installs` into user configuration even though that key fails config validation and can block a later restart.

## System Context

Gateway and plugin lifecycle commands consume OpenClaw configuration plus managed plugin state. Plugin install records should live in the managed plugin index, while config validation and later Gateway restarts consume only supported user configuration.
