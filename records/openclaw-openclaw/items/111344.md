## Summary

This remains a concrete core plugin-loading bug: the documented SDK helper creates a default entry object with `register`, while the reporter supplied a minimal package that startup validation rejects despite runtime inspection recognizing its channel capability. Current-main evidence does not establish that the validator has been aligned with that entry contract.

## What This Changes

Make gateway startup validation accept the `defineChannelPluginEntry` default entry shape so channel plugins with `activation.onStartup: true` load consistently.

## Best Possible Solution

Use one shared entry-module normalization path for startup validation and runtime loading, then add a regression fixture that starts an external channel plugin built with `defineChannelPluginEntry` and `activation.onStartup: true`.
