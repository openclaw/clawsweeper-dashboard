## Summary

This is a valid narrow stale-tab fix, but the new asynchronous check weakens the existing send-page double-click guard: two rapid clicks can both pass the initial guard, await the tab lookup, and then send the page twice. Keep the PR open for that mechanical repair and real browser evidence of the stale-tab behavior.

## What This Changes

The PR adds a click-time active-tab check to the browser-extension popup so share, send-page, and Copilot actions refresh and abort instead of acting on a tab that changed since the popup rendered.

## System Context

The Chrome extension popup renders controls using the tab active at refresh time, then sends commands to the extension runtime when the user clicks a control. The new guard verifies that the active tab still matches the rendered control state before dispatching share, page-send, or Copilot actions.

  E -->|different tab| G[Refresh popup and abort]

## Best Possible Solution

Preserve the click-time tab-identity guard, then re-check or claim the send-page in-flight state after the asynchronous lookup so only one handler can dispatch; add a focused regression test and a redacted real browser demonstration of stale-tab refresh-and-abort behavior.
