## Label Justifications

- `P0`: The supported upgrade path can leave an existing user without a working managed Gateway, with recovery requiring nvm, package-manager, systemd, and manual state-file operations.
- `impact:ux-release-blocker`: Restoring service after the reported upgrade requires terminal commands and internal knowledge of Node roots, global packages, service bindings, and plugin state files.
- `impact:crash-loop`: The reported plugin migration conflict prevents the Gateway from completing startup and reporting ready.

## Summary

Keep open: current main addresses install-root drift, Node compatibility preflight, service rebinding, restart verification, and partial-update repair, but it does not provide the requested guided Node-runtime migration, and the reported plugin-index conflict still leaves an upgrade path blocked.

## What This Changes

Improve upgrades across Node.js requirement changes by guiding or automating runtime migration, rebinding the managed Gateway, verifying install consistency, and recovering conflicting legacy plugin metadata.

## Best Possible Solution

Provide a guided updater-to-installer handoff that preserves the working runtime until a compatible Node and OpenClaw package are staged, repairs plugin metadata transactionally, rebinds the managed service, and verifies CLI, Gateway, plugins, and readiness without manual file moves.
