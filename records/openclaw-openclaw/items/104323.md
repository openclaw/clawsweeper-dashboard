- `impact:session-state`: Incomplete canonical history makes replay, compaction, memory extraction, and session reconstruction unreliable.

## Summary

Current main has centralized pre-run user-turn persistence, but the report reproduces on a later beta and the recorder still exposes best-effort error handling; the primary JSONL integrity problem is not proven fixed. The trajectory sidecar is intentionally a bounded diagnostic window, so its truncation is expected, but this report adds useful gap-detection and authority-contract evidence beyond the older persistence issue.

## What This Changes

Ensure accepted user turns are never silently absent from canonical session history and make bounded trajectory truncation detectable to downstream consumers.

## Best Possible Solution

Make persistence of every accepted user turn a required canonical-state transition before fallible model execution across CLI, ACP, embedded, channel, queue, cron, and topic paths; fail explicitly or durably retry when that commit cannot complete, add successful/failing/write-failure and rotation regressions, and keep trajectory bounded with an explicit truncation boundary or coverage marker rather than treating it as authoritative.
