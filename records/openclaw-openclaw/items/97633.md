## Summary

Keep open: the PR targets a real ACP Discord thread-delivery gap, but the new ACP guard is not position-aware and can still trust stale stored thread metadata for an ordinary agent-scoped session whose agent id is `acp`; external real behavior proof is also still mock-only.

## What This Changes

The PR adds a `deliveryThreadId` fallback to routed reply thread resolution, wires it from ACP session `deliveryContext.threadId` in the dispatch and prepared-reply paths, and adds focused unit tests.

## Best Possible Solution

Use the existing structural `isAcpSessionKey` classifier at both stored-thread call sites, add a regression for a non-ACP `agent:acp:*` session with stale `deliveryContext.threadId`, and then prove the Discord/ACP thread reply path in a real setup.
