## Summary

Keep open: this PR targets a real Mattermost thread-root send gap that current main does not fully eliminate at the low-level send sink, but the submitted patch is not merge-ready because lookup failures can silently unthread replies and no real Mattermost proof is present.

## What This Changes

The PR adds a Mattermost pre-send post lookup that maps a `replyToId` child post to its thread root before creating the outbound post, plus mocked send tests for child, root, cross-channel, and lookup-failure cases.

## Best Possible Solution

Keep the low-level Mattermost send-sink fix path, but make lookup failures preserve or explicitly fail the requested thread target, then rebase and prove the behavior against a real Mattermost thread before merge.

## Reproduction Assessment

Yes at source level: current `sendMessageMattermost` passes `opts.replyToId` straight to Mattermost `root_id`, while Mattermost rejects child posts as roots. I did not run a live Mattermost reproduction in this read-only review.

## Solution Assessment

No as submitted. Resolving child post IDs at the Mattermost send sink is a plausible owner boundary, but lookup failure should not silently discard the requested thread target.
