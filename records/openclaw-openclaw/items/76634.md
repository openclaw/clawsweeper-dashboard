Keep open: the send-sink bug is still real on current main and the latest release, but this branch is not merge-ready because lookup failures can silently turn intended thread replies into top-level Mattermost posts and the PR still lacks live Mattermost proof.

## What This Changes

The PR adds a Mattermost `/posts/{replyToId}` lookup and mocked send tests so child reply IDs resolve to thread roots before creating the outgoing post.

## Best Possible Solution

Land a current-main send-sink repair that resolves child post IDs to the real Mattermost root, preserves or visibly fails intended threading on lookup failure, stays aligned with merged message-tool threading, and includes redacted live Mattermost proof.

## Reproduction Assessment

Yes at source level: current main and `v2026.6.11` still pass raw `opts.replyToId` into Mattermost `root_id`, and Mattermost rejects child posts as roots. I did not establish a live Mattermost reproduction in this read-only review.

## Solution Assessment

No as submitted: resolving at the send sink is a plausible repair boundary, but silently dropping `root_id` on lookup failure is not the safest message-delivery behavior. The safer path is to preserve or visibly fail intended threading and prove it in a real Mattermost workspace.
