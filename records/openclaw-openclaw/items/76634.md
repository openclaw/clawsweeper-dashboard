## Summary

Keep open: the PR is a focused Mattermost delivery fix with useful remaining send-sink behavior that current main and the merged message-tool threading PR do not fully replace, but it is not merge-ready because lookup failures can silently move valid threaded replies to the channel top level, real Mattermost proof is missing, and GitHub reports the branch as conflicting.

## What This Changes

The PR changes Mattermost outbound sends to fetch `replyToId` posts, use their `root_id` as the thread root, drop cross-channel references, and add send-path tests for those cases.

## Best Possible Solution

Refresh the branch on current `main`, keep the successful child-to-root and cross-channel behavior, preserve threaded delivery on lookup failures unless the lookup proves the reference is unsafe, and add redacted real Mattermost proof before merge.

## Reproduction Assessment

Yes at source level: current `sendMessageMattermost` passes `opts.replyToId` straight to Mattermost `root_id`, and the PR's tests demonstrate child post IDs can reach that sink. I did not run a live Mattermost reproduction in this read-only review.

## Solution Assessment

No as submitted: resolving child post IDs at the send sink is a plausible repair, but the catch-all fallback should not silently discard a previously valid thread root on lookup failure.
