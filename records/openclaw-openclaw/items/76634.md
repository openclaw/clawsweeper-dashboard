## Summary

Keep this PR open: it targets a real Mattermost send-sink threading gap that current main does not fully cover, but the branch is not merge-ready because it can silently post intended thread replies at the channel root on lookup failure, lacks real Mattermost proof, and is currently conflicting.

## What This Changes

The PR changes Mattermost low-level sends to fetch a `replyToId` post and use its thread root as `root_id`, with mocked tests for child, root, cross-channel, and lookup-failure cases.

## Best Possible Solution

Land a current-main send-sink repair that resolves child Mattermost post IDs to the real thread root, preserves or visibly fails intended threading on lookup failure, and includes redacted live Mattermost proof.

## Reproduction Assessment

Yes at source level: current `main` still passes raw `opts.replyToId` into Mattermost `root_id`, and the PR's mocked tests exercise child-post root resolution. I did not run a live Mattermost workspace reproduction in this read-only review.

## Solution Assessment

No as submitted: resolving at the send sink is a plausible repair boundary, but silently dropping `root_id` on lookup failure is not the safest message-delivery behavior. The safer path is to preserve or visibly fail intended threading and prove it in a real Mattermost workspace.
