## Summary

Keep this PR open, but it is not merge-ready: the runtime/gateway direction is well-proven, while two Control UI lifecycle paths still treat the new `paused` state as inactive or idle and the persisted session-row contract still needs maintainer acceptance.

## What This Changes

This PR adds `sessions_yield` paused-state propagation for top-level sessions across native and Codex run lifecycle events, persisted session rows, restart recovery, session broadcasts, and Control UI session display.

## Best Possible Solution

Finish the paused-active invariant across Control UI session consumers, keep the runtime/gateway yield metadata path, and merge only after maintainers accept the new persisted session-row contract and its relationship to broader deferred lifecycle work.

## Reproduction Assessment

Yes for the remaining review findings: source inspection shows paused rows are intentionally active under `isSessionRunActive`, while Workboard lifecycle sync and current-chat clearing still use stale checks that classify paused rows as idle/inactive. The original runtime bug is also source-visible on current main, and the PR body supplies live before/after logs for the paused persistence path.

## Solution Assessment

No, not yet: the runtime/gateway projection is the right layer for the main-session yield marker, but the PR is incomplete until all UI lifecycle consumers share the same nonterminal `paused` invariant. The safer final shape is a single active-state helper used by sessions, Workboard lifecycle sync, and status rendering, plus maintainer acceptance of the new persisted contract.

That makes a yielded paused main session look `interrupted` while its continuation is still pending, so the clearing path should use `isSessionRunActive(nextRow)` or preserve active state for `paused`, with a focused sessions-controller test.
